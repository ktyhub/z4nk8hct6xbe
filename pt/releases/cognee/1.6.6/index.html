cognee v1.6.6

v1.6.6 — Resolução e estabilidade de conflitos

Data de lançamento: 29/10/2026 Alterações: v1.6.6rc1 → v1.6.6

Solicitações pull: #6266, #6337, #6339, #6340

Resumo

Esta versão se concentra em tornar o tratamento de conflitos mais confiável e fácil de gerenciar, além de algumas correções de estabilidade, vetores e layout de dados. Você encontrará um novo API durável para resolução de conflitos, retirada mais segura de escolhas conflitantes, caminhos de cache/exclusão mais rápidos e seguros e melhorias no tratamento de vetores que economizam trabalho de reincorporação.

Destaques

  • Novo API durável para resolução de conflitos de fatos, para que você possa resolver divergências de dados de maneira confiável a partir do API.
  • A revisão de conflitos é habilitada por padrão e muitas correções garantem que as 'escolhas' (decisões do usuário sobre fatos conflitantes) sejam retiradas corretamente em edições, exclusões e reconstruções.
  • Copie vetores armazenados entre armazenamentos de vetores sem reincorporá-los para economizar tempo e custos ao mover/replicar embeddings.
  • Exclusão e armazenamento em cache mais seguros: as exclusões de lista/contexto Redis agora são atômicas ou no local, e erros de permissão/KMS são exibidos para que as falhas não sejam ignoradas silenciosamente.

Novos recursos

  • Resolução durável de conflitos de fatos API — Um novo endpoint API que permite resolver divergências entre fatos conflitantes de maneira durável (persistente). O que faz: registra e aplica as resoluções escolhidas para que o sistema utilize consistentemente o fato resolvido. Por que é importante: resolve inconsistências de dados de maneira confiável entre sessões e componentes, reduzindo respostas incorretas ou comportamento surpreendente de dados obsoletos/conflitantes.
  • Fluxo de trabalho padrão de revisão de conflitos — O sistema agora analisa conflitos por padrão (anteriormente opcional). O que faz: quando o sistema detecta fatos conflitantes (diferentes fontes ou versões da mesma informação), ele os apresenta para revisão automaticamente. Por que é importante: torna a detecção de conflitos acionável imediatamente, para que menos conflitos escapem e as pesquisas/agentes retornem resultados mais limpos.
  • Copiar vetores armazenados entre armazenamentos sem reincorporá-los — Agora você pode mover ou copiar embeddings de vetores de um armazenamento de vetores para outro sem executar novamente o modelo de incorporação. O que faz: executa uma cópia direta dos embeddings armazenados. Por que é importante: acelera a migração e a replicação e reduz a computação e os custos porque os modelos não são chamados novamente.
  • Melhorias na representação de células DLT e de células datadas — Cada coluna DLT (uma coluna usada em tabelas de controle de alterações) agora é tratada como um nó de valor por padrão, e as células datadas são representadas uma vez como um valor de carimbo de data/hora. O que faz: faz com que a plataforma trate as colunas de controle de alterações como valores concretos e evita a duplicação de células de data. Por que é importante: corrige problemas sutis de correção e duplicação ao ler linhas e chaves do conjunto de dados, melhorando a precisão das leituras e do processamento downstream.

Melhorias

  • Remoção mais segura de escolhas (decisões do usuário sobre fatos conflitantes) — As escolhas são retiradas nos momentos corretos: em edições de blocos, exclusões de conectores, operações de esquecimento de conjuntos de dados e quando as reconstruções as perderiam. Isso reduz decisões obsoletas que persistem após alterações de dados.
  • Fail-fast em invalidação e chaves malformadas — A edição falhará se a invalidação do estado relacionado falhar; dicas malformadas para chaves DLT agora geram um erro em vez de ignorá-las silenciosamente. Isso evita inconsistências silenciosas de dados.
  • Preservar o contexto de recuperação ao resolver conflitos — O contexto de recuperação usado para buscar evidências de apoio agora é preservado durante a resolução de conflitos, para que as respostas permaneçam fundamentadas no mesmo contexto.
  • Mesclar e validar tags antes de escrever vetores — As tags agora são mescladas e validadas antes de upserts de vetores, evitando metadados quebrados ou incompletos em registros de vetores.
  • Concluir a implementação do carimbo multisessão — Os carimbos de sessão (usados ​​para rastrear ações entre sessões) agora são implementados de forma consistente em todos os componentes para melhorar o tratamento e a correção da sessão.
  • Faça classify() aceitar visualização de texto simples de objetos selados — Útil quando você precisa classificar o conteúdo de objetos criptografados/selados após eles serem abertos para processamento.

Desempenho

  • Redução da contenção de recuperação ao retirar fatos de conflito excluídos — reduz as condições de corrida e melhora a capacidade de resposta quando muitas decisões estão sendo retiradas de uma só vez.
  • Exclusões de lista Redis no local e exclusões de contexto atômico — as exclusões de cache agora são mais eficientes e consistentes, reduzindo a latência e os estados de exclusão parcial.
  • Leitura direta das colunas-chave de uma linha — a pesquisa direta de colunas-chave reduz a sobrecarga ao ler linhas, melhorando o desempenho de leitura para conjuntos de dados baseados em tabelas.

Segurança

  • Transparência de erros do KMS — Os erros do Key Management System (KMS) agora aparecem desembrulhados para que o código de chamada possa ver e lidar corretamente com problemas de criptografia/chave em vez de ocultá-los.
  • Verificações de permissão de exclusão na limpeza: as operações de limpeza agora verificam as permissões de exclusão, reduzindo o risco de remoção não autorizada de dados.

Correções de bugs

  • Falha na edição quando a invalidação falha — As edições agora param e relatam erros se a invalidação relacionada não puder ser executada, evitando estado inconsistente.
  • Descontinuar escolhas apenas em edições de blocos e em atualização (não cognificar) — Garante que as escolhas sejam descontinuadas no estágio correto do ciclo de vida para evitar descontinuações prematuras ou perdidas.
  • Aposentar escolhas perdidas por reconstruções ou quando seus fatos desaparecerem — Evita que escolhas obsoletas permaneçam após o fato subjacente ter sido removido ou substituído.
  • Retire as escolhas do usuário ao esquecer e ao excluir o conector — Garante que as decisões do usuário sejam limpas quando você esquecer um conjunto de dados ou remover um conector.
  • Ignorar escolhas declaradas no prelúdio — Evita considerar acidentalmente escolhas declaradas (estáticas) durante o pré-processamento do conflito.
  • Citar trechos ativos somente ao resolver conflitos — Usa apenas trechos atualmente ativos (não excluídos) como evidência de apoio, evitando o uso de dados excluídos durante a resolução.
  • Corrigir caminhos de exclusão somente de memória — aborda caminhos que anteriormente se comportavam de maneira diferente ao operar exclusivamente na memória versus armazenamento persistente.
  • Faça com que o contexto Redis exclua entradas atômicas e exclua as entradas da lista no local - corrige condições de corrida e exclusões parciais no cache.
  • Falha em dicas de chave DLT malformadas e aumento em chaves de tabela DLT ilegíveis no modo BROAD - Evita pulos silenciosos e revela entradas de tabela/chave incorretas.
  • Mesclar tags e validar antes de upserts de vetores brutos — Evita gravar metadados de vetores inválidos que podem quebrar as ferramentas downstream.
  • Deixe classify() obter visualização de texto simples de objetos selados — Corrigido o comportamento de classificação para objetos selados que são abertos para análise.
  • Várias atualizações de testes, CI e documentos para manter os exemplos executáveis ​​e garantir a estabilidade nas versões e ambientes do Python.

Mudanças Técnicas

  • Refatorar: vincule sessões a uma operação como uma lista única em todos os lugares — manipulação de sessão interna simplificada para reduzir bugs e tornar as operações de sessão consistentes.
  • Refatorar (deps): simplificar os pinos onnxruntime e a manutenção de dependências relacionadas.
  • Refatorar (telemetria): simplificar os limites de telemetria para um comportamento de instrumentação mais claro.
  • Atualizações de CI e ferramentas: cobertura expandida de fluxo de trabalho e ajustes em scripts de busca de modelo sem chave, manipulação de cache S3 em CI e melhorias no conjunto de testes.

  • bloqueio de arquivo: >=3.12.0,<4.0.0 → >=3.12.0 -onnxruntime: >=1.24.1 → >=1.17
  • pydantico: >=2.10.5 → >=2.13

cognee v1.6.6

v1.6.6 — Conflict resolution & stability

Release Date: 2026-10-29 Changes: v1.6.6rc1 → v1.6.6

Pull Requests: #6266, #6337, #6339, #6340

Summary

This release focuses on making conflict handling more reliable and easier to manage, plus a handful of stability, vector, and data-layout fixes. You’ll find a new durable conflict-resolution API, safer retirement of conflicting choices, faster and safer cache/deletion paths, and improvements to vector handling that save re-embedding work.

Highlights

  • New durable API for fact conflict resolution so you can resolve data disagreements reliably from the API.
  • Conflict review is enabled by default and many fixes ensure 'choices' (user decisions about conflicting facts) are retired correctly on edits, deletes, and rebuilds.
  • Copy stored vectors between vector stores without re-embedding to save time and cost when moving/replicating embeddings.
  • Safer deletion and caching: Redis list/context deletions are now atomic or in-place, and permission/KMS errors are surfaced so failures won’t be silently ignored.

New Features

  • Durable fact conflict resolution API — A new API endpoint that lets you resolve disagreements between conflicting facts in a durable (persistent) way. What it does: records and applies chosen resolutions so the system consistently uses the resolved fact. Why it matters: resolves data inconsistencies reliably across sessions and components, reducing incorrect answers or surprising behavior from stale/conflicting data.
  • Default conflict review workflow — The system now reviews conflicts by default (previously optional). What it does: when the system detects conflicting facts (different sources or versions of the same information), it surfaces them for review automatically. Why it matters: makes conflict detection actionable out of the box, so fewer conflicts slip through and searches/agents return cleaner results.
  • Copy stored vectors between stores without re-embedding — You can now move or copy vector embeddings from one vector store to another without re-running the embedding model. What it does: performs a direct copy of stored embeddings. Why it matters: speeds up migration and replication, and reduces compute and cost because models aren’t re-called.
  • DLT column and dated-cell representation improvements — Every DLT column (a column used in change-tracking tables) is now treated as a value node by default, and dated cells are represented once as a Timestamp value. What it does: makes the platform treat change-tracking columns as concrete values and avoids duplicating date cells. Why it matters: fixes subtle correctness and duplication issues when reading dataset rows and keys, improving accuracy of reads and downstream processing.

Improvements

  • Safer retirement of choices (user decisions about conflicting facts) — Choices are retired at the correct times: on chunk edits, connector deletes, dataset forget operations, and when rebuilds would otherwise lose them. This reduces stale decisions lingering after data changes.
  • Fail-fast on invalidation and malformed keys — Editing will fail if invalidation of related state fails; malformed hints for DLT keys now raise an error instead of silently skipping them. This prevents silent data inconsistencies.
  • Preserve retrieval context when resolving conflicts — The retrieval context used to fetch supporting evidence is now preserved while resolving conflicts so answers remain grounded in the same context.
  • Merge and validate tags before writing vectors — Tags are now merged and validated before vector upserts, avoiding broken or incomplete metadata on vector records.
  • Finish multi-session stamp rollout — Session stamps (used to track actions across sessions) are now rolled out consistently across components for improved session handling and correctness.
  • Make classify() accept plaintext view of sealed objects — Useful when you need to classify contents of encrypted/sealed objects after they are opened for processing.

Performance

  • Reduced retrieval contention when retiring deleted conflict facts — lowers race conditions and improves responsiveness when many decisions are being retired at once.
  • Redis list deletions in-place and atomic context deletes — cache deletions are now more efficient and consistent, reducing latency and partial-deletion states.
  • Direct reading of a row's key columns — looking up key columns directly reduces overhead when reading rows, improving read performance for table-backed datasets.

Security

  • KMS error transparency — Key Management System (KMS) errors are now surfaced unwrapped so calling code can see and correctly handle encryption/key issues instead of having them hidden.
  • Deletion permission checks in cleanup — cleanup operations now verify delete permissions, reducing risk of unauthorized data removal.

Bug Fixes

  • Fail the edit when invalidation fails — Edits now stop and report errors if related invalidation cannot be performed, avoiding inconsistent state.
  • Retire choices only on chunk edits and in update (not cognify) — Ensures choices are retired at the right lifecycle stage to avoid premature or missed retirements.
  • Retire choices lost by rebuilds or when their fact is gone — Prevents stale choices from sticking around after the underlying fact was removed or replaced.
  • Retire user choices on forget and on connector deletes — Ensures user decisions are cleaned up when you forget a dataset or remove a connector.
  • Skip stated choices in the prelude — Avoids accidentally considering stated (static) choices during conflict pre-processing.
  • Cite live chunks only when resolving conflicts — Uses only currently live (non-deleted) chunks as supporting evidence, preventing use of deleted data during resolution.
  • Fix memory-only deletion paths — Addresses paths that previously behaved differently when operating purely in memory vs persistent storage.
  • Make Redis context deletes atomic and delete list entries in-place — Fixes race conditions and partial deletions in the cache.
  • Fail on malformed DLT key hints and raise on unreadable DLT table keys in BROAD mode — Prevents silent skips and surfaces bad table/key inputs.
  • Merge tags and validate before raw vector upserts — Avoids writing invalid vector metadata that could break downstream tooling.
  • Let classify() take plaintext view of sealed objects — Fixed classification behavior for sealed objects that are opened for analysis.
  • Several test, CI, and docs updates to keep examples runnable and ensure stability across Python versions and environments.

Technical Changes

  • Refactor: bind sessions to an operation as a single list everywhere — internal session handling simplified to reduce bugs and make session-operations consistent.
  • Refactor (deps): simplify onnxruntime pins and related dependency housekeeping.
  • Refactor (telemetry): simplify telemetry limits for clearer instrumentation behavior.
  • CI and tooling updates: expanded workflow coverage and adjustments to keyless model fetch scripts, S3 cache handling in CI, and test-suite improvements.

Dependency Updates

Updated:

  • fastembed: <=0.8.0 → >=0.9.1,<0.10
  • filelock: >=3.12.0,<4.0.0 → >=3.12.0
  • onnxruntime: >=1.24.1 → >=1.17
  • pydantic: >=2.10.5 → >=2.13

Removed:

  • diskcache >=5.6.3
