Novidades

  • DeepSeek-V4.1 no GB300 obtém até 1,5x mais taxa de transferência de pré-preenchimento sob carga e cerca de 28% menor latência do primeiro token em prompts de 32K a 64K (#44403, #45059, #45107).
  • Modo de baixa latência SGLang: os plug-ins opcionais NVIDIA megakernel e AMD monokernel executam a decodificação DeepSeek-V4.1-Flash como kernels persistentes fundidos, para decodificação de usuário único até 44% mais rápida no GB300 e 75% no MI350X (#44945, #45450, #44353, #44621).
  • Modelos MoE como DeepSeek-V4.1-Flash, GLM-5.3-Flash e gpt-oss alcançam o primeiro token 30% a 58% mais cedo em prompts de 8K no H200 (#43363).
  • Paged Experts (opt-in) executa modelos MoE maiores que a memória da GPU em uma única GPU de consumidor, até 30x mais rápido que o descarregamento da CPU (#42557, #45787).
  • SGLang agora é executado no Google TPU7x por meio de SGLang-TorchTPU, um plugin nativo do PyTorch para TPU.
  • Agora você pode servir adaptadores LoRA em modelos MoE quantizados (FP8 e NVFP4) com um novo mecanismo LoRA opcional (#45892).
  • Modelos MLA estilo DeepSeek que executam paralelismo de contexto de decodificação agora podem manter seu cache de prefixo no armazenamento L3 baseado em arquivo HiCache (#41187).

Mudanças recentes e notas de atualização

  • O bate-papo do DeepSeek-V4 e V4.1 agora segue a receita do deepseek. Prompts, saídas e os endpoints nativos /separate_reasoning e /parse_function_call passam pelo codificador oficial do DeepSeek, e o próprio encoding_dsv4.py / encoding_dsv41.py do SGLang desapareceu. Clients pode notar: os argumentos de chamada de ferramenta transmitidos chegam em pedaços (o primeiro pedaço carrega arguments: ""), então concatene-os como o OpenAI SDK faz; os IDs de chamada de ferramenta usam o formato oficial call_00_...; O esforço de raciocínio V4 segue o perfil oficial do DeepSeek e a substituição dsv4_reasoning_effort_profile é removida; um reasoning_effort numérico em V4 retorna 400; As mensagens developer são renderizadas como mensagens do sistema; /parse_function_call também retorna chamadas para ferramentas fora de tools com tool_index -1; solicitações que combinam tools com continue_final_message retornam 400. A análise de saída passa pela receita deepseek quando o raciocínio DeepSeek ou o analisador de chamada de ferramenta é definido; sgl-router e sglang-server mantêm seus analisadores Rust por enquanto: #45315, #45907, #46219
  • A reprodução limitada SWA do decodificador DeepSeek-V4.1 está ativada por padrão para configurações CUDA suportadas, incluindo ambas as funções PD. Não é numericamente idêntico ao pré-preenchimento completo. Passe --no-enable-decoder-swa-bounded-replay para manter o pré-preenchimento completo, por exemplo, para implementações de RL cujos logprobs devem corresponder ao treinador: #44403, #45035
  • O padrão do DeepSeek-V4.1 é MegaAttention em PD. No SM100/SM103, ambas as funções PD agora resolvem flashmla_mega e o handshake PD verifica o layout KV, portanto, o pré-preenchimento e a decodificação devem executar o mesmo back-end de atenção (#45075). Atualize o pré-preenchimento e a decodificação juntos, pois uma decodificação mais antiga não pode ler o novo campo de handshake; passe --dsv4-attn-backend flashmla em ambas as funções para manter o FlashMLA. Servidores agregados mantêm FlashMLA quando a atenção é paralela ao tensor entre as classificações: #46263
  • O back-end de atenção do tokenspeed_mla foi removido. tokenspeed_mla ainda inicia como um alias obsoleto para cutedsl_mla com um aviso. Para trocar, passe --attention-backend cutedsl_mla --kv-cache-dtype fp8_e4m3, mais --speculative-attention-mode decode com decodificação especulativa: #44803
  • --speculative-skip-dp-mlp-sync foi removido. Os comandos de inicialização que passam por ele agora falham com um erro de argumento não reconhecido; solte a bandeira: #45043
  • O nome de quantização de difusão kitchen_int8 foi removido. Use convrot_int8, obsoleto em favor dele desde v0.5.22: #45706
  • SGLANG_ENABLE_UNIFIED_RADIX_TREE agora é ignorado sem aviso. Já não teve efeito porque a árvore raiz unificada é o padrão; retire-o dos scripts de inicialização: #45090
  • Os pontos de verificação .pt em formato tar legado não são mais carregados. O inseguro substituto de pickle weights_only=False foi removido; converta esses pontos de verificação em tensores de segurança ou formato zip .pt offline: #42760
  • Os pontos de extremidade HTTP de difusão são validados com mais rigor. Os valores de URL para upscaling_model_path e frame_interpolation_model_path retornam 400, um response_format não compatível é rejeitado antes da geração e um upload para nuvem com falha retorna 502 em vez de 400: #43585
  • A primeira inicialização de um servidor FlashInfer CUTLASS MoE leva mais tempo. O autotune de inicialização agora também cobre tamanhos de pré-preenchimento, portanto, um servidor sem resultados de ajuste salvos leva mais tempo para ficar pronto (no DeepSeek-V4.1-Flash em 8x H200, o autotune vai de cerca de 41 s a 177 s). Inicializações posteriores reutilizam os resultados salvos e --disable-flashinfer-autotune pula o ajuste: #43363
  • As respostas do PNG de difusão são maiores. A saída do PNG agora tem como padrão o nível 0 do zlib: os mesmos pixels, cerca de 3x os bytes, várias vezes mais rápido para codificar. Defina output_compression com um valor diferente de 75 para escolher um nível: #45987
  • sgl-router movido para o diretório sgl-router/ de nível superior. Builds e scripts que apontam para experimental/sgl-router/ devem atualizar o caminho (#45414); --max-in-flight agora é --max-inflight-requests, e o nome antigo ainda funciona como apelido: #44950

  • DeepSeek-V4.1 on GB300 gets up to 1.5x more prefill throughput under load and about 28% lower first-token latency on 32K to 64K prompts (#44403, #45059, #45107).
  • SGLang low-latency mode: the opt-in NVIDIA megakernel and AMD monokernel plugins run DeepSeek-V4.1-Flash decode as fused persistent kernels, for up to 44% faster single-user decode on GB300 and 75% on MI350X (#44945, #45450, #44353, #44621).

  • Paged Experts (opt-in) runs MoE models larger than GPU memory on a single consumer GPU, up to 30x faster than CPU offload (#42557, #45787).
  • SGLang now runs on Google TPU7x through SGLang-TorchTPU, a PyTorch-native plugin for TPU.
  • You can now serve LoRA adapters on quantized MoE models (FP8 and NVFP4) with a new opt-in LoRA engine (#45892).
  • DeepSeek-style MLA models running decode context parallelism can now keep their prefix cache in HiCache file-based L3 storage (#41187).

Breaking Changes & Upgrade Notes

  • DeepSeek-V4 and V4.1 chat now follows deepseek-recipe. Prompts, outputs and the native /separate_reasoning and /parse_function_call endpoints go through DeepSeek's official encoder, and SGLang's own encoding_dsv4.py / encoding_dsv41.py are gone. Clients may notice: streamed tool-call arguments arrive in pieces (the first chunk carries arguments: ""), so concatenate them as the OpenAI SDK does; tool-call ids use the official call_00_... format; V4 reasoning effort follows DeepSeek's official profile and the dsv4_reasoning_effort_profile override is removed; a numeric reasoning_effort on V4 returns 400; developer messages render as system messages; /parse_function_call also returns calls to tools outside tools with tool_index -1; requests that combine tools with continue_final_message return 400. Output parsing goes through deepseek-recipe when the DeepSeek reasoning or tool-call parser is set; sgl-router and sglang-server keep their Rust parsers for now: #45315, #45907, #46219
  • DeepSeek-V4.1 decoder SWA bounded replay is on by default for supported CUDA configurations, including both PD roles. It is not numerically identical to full prefill. Pass --no-enable-decoder-swa-bounded-replay to keep full prefill, for example for RL rollouts whose logprobs must match the trainer: #44403, #45035
  • DeepSeek-V4.1 defaults to MegaAttention under PD. On SM100 / SM103 both PD roles now resolve flashmla_mega and the PD handshake checks the KV layout, so prefill and decode must run the same attention backend (#45075). Upgrade prefill and decode together, since an older decode cannot read the new handshake field; pass --dsv4-attn-backend flashmla on both roles to keep FlashMLA. Aggregated servers keep FlashMLA when attention is tensor-parallel across ranks: #46263
  • The tokenspeed_mla attention backend is removed. tokenspeed_mla still starts as a deprecated alias for cutedsl_mla with a warning. To switch, pass --attention-backend cutedsl_mla --kv-cache-dtype fp8_e4m3, plus --speculative-attention-mode decode with speculative decoding: #44803
  • --speculative-skip-dp-mlp-sync is removed. Launch commands that pass it now fail with an unrecognized-argument error; drop the flag: #45043
  • The kitchen_int8 diffusion quantization name is removed. Use convrot_int8, deprecated in favor of it since v0.5.22: #45706
  • SGLANG_ENABLE_UNIFIED_RADIX_TREE is now ignored without a warning. It already had no effect because the unified radix tree is the default; drop it from launch scripts: #45090
  • Legacy tar-format .pt checkpoints no longer load. The unsafe weights_only=False pickle fallback is removed; convert such checkpoints to safetensors or zip-format .pt offline: #42760
  • Diffusion HTTP endpoints validate more strictly. URL values for upscaling_model_path and frame_interpolation_model_path return 400, an unsupported response_format is rejected before generation, and a failed cloud upload returns 502 instead of 400: #43585
  • The first startup of a FlashInfer CUTLASS MoE server takes longer. Startup autotune now also covers prefill sizes, so a server with no saved tuning results takes longer to become ready (on DeepSeek-V4.1-Flash on 8x H200, autotune goes from about 41 s to 177 s). Later startups reuse the saved results, and --disable-flashinfer-autotune skips tuning: #43363
  • Diffusion PNG responses are larger. PNG output now defaults to zlib level 0: the same pixels, about 3x the bytes, several times faster to encode. Set output_compression to a value other than 75 to pick a level: #45987
  • sgl-router moved to the top-level sgl-router/ directory. Builds and scripts that point at experimental/sgl-router/ must update the path (#45414); --max-in-flight is now --max-inflight-requests, and the old name still works as an alias: #44950
