AutoGPT autogpt-platform-beta-v0.11.2

Highlights

  • Plan-first trial reshapes onboarding and conversion (#16308) — starter tasks and experts now sit behind the paywall, the old "hire" step is gone, and the team is auto-hired when a trial starts, with Home opening on a ranked, expert-owned task list. This is more than a UI shuffle: it moves the value demonstration ahead of commitment, so developers wiring onboarding or analytics should expect a different event sequence and re-check any flow that depended on a manual hire step. Watch for trial-to-paid metrics shifting because the first-run experience is now ledger-driven rather than user-driven.

  • Hard limits land on sandboxes and nested runs (#16461, #16690) — E2B sandbox concurrency is now capped per deployment and per account, and sub-workflow nesting is bounded with nested runs counting against the caller's worker share. For anyone running fan-out or recursive agent workflows, this is the change most likely to bite in production: workloads that previously scaled by spawning more sandboxes or deeper chains will now queue or be throttled. Treat this as a capacity-planning exercise and look for new 429-style pressure in high-concurrency tenants.

  • Account lifecycle gets a real deletion path (#15459, #15487, #16745) — users can self-delete with an optional exit question, accounts are hard-erased after a 14-day window via a new erase-account CLI/job (keeping only a ban record), and erasure now cascades to the account's chats (SECRT-2854). This closes a likely GDPR/data-retention gap, but the 14-day grace plus retained ban record means "deleted" is not instant or absolute — worth documenting clearly for compliance-sensitive adopters and for anyone building on top of account state.

  • OAuth stops failing quietly (#15081, #16685, #15454, #16269) — refresh failures are now recorded with named missing scopes and dead tokens are no longer replayed, client-secret verification moves off the event loop, HubSpot blocks gain native OAuth, and Microsoft 365 becomes a movable onboarding step. The operational payoff is fewer silent auth breakdowns and better diagnostics; the performance payoff is that verification no longer blocks the loop under load. If you integrate HubSpot or Microsoft, expect updated consent scopes and onboarding ordering.

  • Execution semantics tightened for correctness (#16684, #16672, #16703, #16691) — an expert run with any failed step now reports failed instead of completed, bash_exec kills the entire process tree on timeout, oversized LLM requests fail immediately with a clear message instead of hanging, and block media files are cleaned up after AutoPilot runs. These are the kind of fixes that change what your monitoring sees: status webhooks may flip from success to failure for partially-failed runs, which is correct but may reveal latent errors previously masked as green.

  • Model and integration surface expands (#16700, #16699, #16650, #16713) — two new model backends (Meta Muse Ember, Claude Fable 5.2) are added, Wix joins the MCP catalog, and platform SDK keys (Firecrawl, DataForSEO, Tavily, etc.) are now treated uniformly as system credentials. The credential reclassification is the subtle one: key scope and credential-store behavior may change for those integrations, so verify your secret wiring rather than assuming old key paths still apply.

No breaking API changes in this release.
