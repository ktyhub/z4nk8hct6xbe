hyperframes v0.9.80

HyperFrames v0.9.80

Released on 2026-11-22.

Dropping a clip onto main-track clips can now insert it there. Studio previews match the export more closely, and a drive that stops answering no longer stalls a project.

Features

  • Studio: Dropping a clip onto main-track clips can insert it there (08bd7fc12, #8397).

Fixes

  • Engine: An asset download fails once when the egress proxy drops its tunnel (da1476e48, #8417).
  • Studio: An insert on drop never lets linked partners overlap or start before 0 (8929d1164, #8416).
  • Studio: A refused delete no longer brings back another delete still saving (c1f4a193a, #8413).
  • Engine: A capture proxy request whose name will not resolve is reported as failed (75c83d877, #8409).
  • Studio: A sealed undo of a GSAP-animated layer's style shows in place (c3a673990, #8320).
  • Media Use: A project manifest's provider claim never writes a sound credit (ec1839e4a, #8410).
  • Studio Server: A file the drive never answers no longer holds a project's first history copy (267ffc46c, #8187).
  • Studio: Fx badges in a sealed preview show the clip's look, crop and duck (8a69ea039, #8411).
  • Studio: A paused untagged video shows the colours the export renders (71907274a, #8405).
  • CLI: Show copy file names in check progress lines as visible text (4a5a5eb27, #8407).
  • Studio: A delete and its ripple shift save as one edit (7ec38388b, #8404).
  • Studio: The poster rendered for the next open no longer delays a clip's picture (da46c89e2, #8400).
  • Studio Server: A file the drive never answers no longer holds a project's first copy (71dc6f2fe, #8403).
  • CLI: The compile cache lives only in the private HyperFrames cache folder (8127bb885, #8401).

Internal

  • Engine: The frame-tag checks get the time a real encode needs (2b4706f19, #8415).
  • Studio Server: The Windows workflow fails when the link tests cannot run (b008e37b4, #8395).
