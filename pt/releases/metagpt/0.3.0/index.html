MetaGPT v0.3.0

Highlights

  • Executable code workflows — open-interpreter is now available for writing and running code (#315, #350, #402), moving agents beyond code suggestions into execution. Review its permissions and isolate untrusted workloads before enabling this capability.
  • Flexible Mermaid rendering — Diagram conversion supports node.js/mmdc (the default), Playwright, Pyppeteer, and Ink (#309), alongside Windows conversion fixes (#345). Choose a backend that matches your CI environment and verify its browser/runtime dependencies.
  • Expanded storage and model integrations — LanceDB adds a document-store option (#192), iFLYTEK Spark is supported as an underlying LLM (#409), and Azure gains an engine mode (#280). These broaden deployment choices, but confirm the configuration required for each integration before switching.
  • Migration-sensitive agent APIs — Role reactions are reworked into three modes (#479), and message-finding functions are renamed while Message gains an attribute (#354). Custom roles and workflows should be updated and retested if they rely on the previous reaction behavior or lookup names.
  • Better PyPI and Windows support — PROJECT_ROOT now supports installed-package usage (#480), with fixes for installation/event-loop handling (#338), Windows command detection (#292), and Windows event-loop policy (#355, #362). This reduces package-layout and startup failures, though code depending on the old project-root behavior may need adjustment.
  • More structured and moderated outputs — PRD, API-design, and project-management actions now elicit JSON responses (#298), while OpenAI Moderation is integrated (#324, #399). Update downstream parsers to handle structured payloads and account for moderation behavior in agent workflows.
