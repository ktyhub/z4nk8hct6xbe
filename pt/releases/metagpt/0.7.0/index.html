#MetaGPT v0.7.0

Destaques do lançamento

  • Configuração mais fácil e flexível: Configuração simplificada, afastando-se de uma CONFIG global para usar instâncias de configuração para um controle mais granular. Os casos de uso típicos envolvem a atribuição de diferentes LLMs a diferentes funções. Confira aqui para uso detalhado.
  • Contexto introduzido: O contexto é composto por configuração, repositório, espaço de trabalho, etc. Cada função pode possuir seu próprio contexto, permitindo um gerenciamento de contexto mais flexível.
  • Adicionado comando metagpt --init-config: um processo de configuração mais amigável para usuários do pacote pypi.
  • Reestruturação de repositórios: responsabilidades consolidadas de FileRepo e GitRepo para simplificar código e lógica.
  • Assinatura de tags: Alterado o conceito de assinatura de tags para melhor legibilidade e usabilidade.
  • Remoção de funções serializar/desserializar explícitas: Removidas essas funções de Role, usei mixin para melhor clareza.
  • Suporte para inicialização de ActionNode de pydantic.BaseModel: uma maneira fácil e estruturada de definir ActionNode.
  • Reestruturação da ação WritePRD: código simplificado, maior eficácia e lógica de bugs corrigida.
  • Reestruturação do ambiente (experimental): Env re-abstraído para acomodar vários ambientes de forma mais eficaz; Usa mark_as_readable mark_as_writable para decorar APIs para observar e agir uniformemente no ambiente por meio de observação e etapa.
  • Multimodalidade adotada: Adicionado um agente de visão baseado em GPT-4V, confira o exemplo aqui!
  • Desenvolvimento incremental aprimorado: Maior taxa de sucesso de desenvolvimento incremental em comparação com a versão anterior.
  • CodeInterpreter introduzido: um agente geral que resolve problemas por meio de codificação. O agente utiliza planos e ferramentas, capazes de resolver uma ampla gama de problemas, incluindo visualização de dados, modelagem de aprendizado de máquina, raciocínio matemático, scraping da web, imitação de páginas da web, etc. Estamos adicionando exemplos [aqui] (https://docs.deepwisdom.ai/main/en/guide/use_cases/agent/code_interpreter/ci_intro.html)!

O que mudou

Alterações incompatíveis com versões anteriores

  • IMPORTANTE: Removemos config.yam, key.yaml e mudamos para um config2.yaml mínimo. Verifique o método de configuração mais recente aqui
  • Removemos Role._init_actions e adicionamos Role.set_actions, que permite configurar ações a qualquer momento além da inicialização. Especificamente para a inicialização do Role, os usuários também devem usar o self.set_actions(...) agora

MetaGPT v0.7.0

Highlights

  • Breaking changes & migration — Two items require immediate action: config.yaml/key.yaml are gone, replaced by a minimal config2.yaml, so existing installations must regenerate their config (the new metagpt --init-config command is the intended path); and Role._init_actions has been removed in favor of Role.set_actions, which can be called at any time, not just during initialization — custom Roles must switch their init-time setup to self.set_actions(...) or their actions will never register.

  • Per-Role config and Context — The global CONFIG singleton gives way to Config instances, and a new Context bundles config, repo, and workspace so each Role can carry its own. This is the architectural core of #852: you can finally assign different LLMs to different Roles and isolate their state instead of sharing one global setting. Expect refactoring work for any code that imported CONFIG directly, but the payoff is genuine multi-agent heterogeneity.

  • New agent capabilities — A CodeInterpreter agent (planning + tool use across data viz, ML modeling, math, scraping, page imitation) and a GPT-4V-based vision agent (see examples/dalle_gpt4v_agent.py) ship in #852, while incremental development reportedly sees a higher success rate. These push MetaGPT beyond its "software company" persona into general task execution and multimodal input — worth evaluating if your use case was previously out of scope.

  • Reworked internals and extension points — Env is re-abstracted (experimental) with mark_as_readable/mark_as_writable decorators unifying observe/step; FileRepo and GitRepo responsibilities are consolidated; subscriptions become tags; Role's explicit serialize/deserialize are replaced by a mixin; ActionNode can now be initialized from a pydantic.BaseModel; and WritePRD was simplified and corrected. If you subclassed Role, Env, or built custom repo/serialization logic, audit those surfaces — the contracts changed even where behavior looks similar.

  • Stability and tooling — A large testing push (#673, #678, #685, #688, #689, #690, #694, #696, #698, #702, #703, #707, #709, #710, #711, #713, #715, #718, #727, #729, #863, #867) plus targeted fixes: is_human at Role init (#715), BaseLLM system prompt (#732), JSON decode failures on LLM output (#799), prompt routing (#785), and several qa_engineer defects (#765, #775). Class-view generation from source (#676) is also new. Net effect: fewer sharp edges around LLM parsing and QA, though the Zhipu API changes (#770, #861) may affect users of that provider.

Release Highlights

  • Easier and more flexible configuration: Simplified config setup, moving away from a global CONFIG to use Config instances for more granular control. Typical use cases involve assigning different LLMs to different Roles. Please check out here for detailed usage.
  • Introduced Context: Context is made up of config, repo, workspace, etc. Each Role can possess its own context, allowing more flexible context management.
  • Added metagpt --init-config command: A more friendly setup process for pypi package users.
  • Repo restructuring: Consolidated FileRepo and GitRepo responsibilities to simplify code and logic.
  • Subscription to tags: Changed the concept of subscription to tags for improved readability and usability.
  • Removal of explicit serialize/deserialize functions: Removed these functions from Role, used mixin instead for better clarity.
  • Supported initializing ActionNode from pydantic.BaseModel: An easy and structured way to define ActionNode.
  • WritePRD Action restructuring: Simplified code, enhanced effectiveness, and fixed buggy logic.
  • Env restructuring (experimental): Re-abstracted Env to accommodate various environments more effectively; Uses mark_as_readable mark_as_writable to decorate APIs to uniformly observe and act on the environment through observe and step.
  • Embraced Multi-modality: Added a vision agent based on GPT-4V, check out the example here!
  • Improved Incremental development: Higher success rate of incremental development compared to previous version.
  • Introduced CodeInterpreter: A general agent who solves problems through coding. The agent leverages on plans and tools, capable of tackling a wide range of problems, including data visualization, machine learning modeling, math reasoning, web scraping, webpage imitating, etc. We are adding examples here!

What's Changed

Backwards Incompatible Changes

  • IMPORTANT: We removed config.yam, key.yaml and switched to a minimal config2.yaml. Please check the latest setup method here
  • We removed Role._init_actions and added Role.set_actions, which allows actions setup at any time besides initialization. For Role initialization specifically, users should also use self.set_actions(...) now
