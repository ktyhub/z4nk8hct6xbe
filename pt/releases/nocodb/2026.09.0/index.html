NocoDB em conectores Claude

O NocoDB agora está disponível no Claude Connectors, portanto, uma base pode ser conectada ao Claude a partir do diretório de conectores, em vez de adicionar a URL do MCP manualmente. Uma vez conectado, Claude pode usar todas as ferramentas MCP permitidas pela função do usuário conectado, que neste lançamento é um conjunto de 149 cobrindo todo o espaço de trabalho. <img width="1280" height="1102" alt="claude-connectors" src="https://github.com/user-attachments/assets/9a241a7f-c90d-4bde-b3c4-665914eeb13d" />

1200% mais ferramentas MCP

O servidor MCP passou de 11 ferramentas para 149, cobrindo todo o espaço de trabalho, não apenas os registros. Claude, ChatGPT, Cursor ou qualquer MCP client agora podem construir no NocoDB: levantar uma mesa, conectar um fluxo de trabalho a um webhook, montar uma página de interface ou bloquear permissões, tudo em uma conversa. As ferramentas abrangem tabelas, campos, visualizações, filtros, classificações, fluxos de trabalho, interfaces, painéis, widgets, scripts, documentos, webhooks, comentários, permissões, segurança em nível de registro, coloração de linhas, pastas, membros e importação e exportação de CSV. Cada um envolve o mesmo serviço que seu REST API, portanto, validação, permissões e auditoria são idênticas e cada chamada respeita a função do chamador: visualizadores leem, editores escrevem, criadores alteram o esquema. <img width="1008" height="868" alt="mcp-tools" src="https://github.com/user-attachments/assets/d61251cb-7e12-491e-9ca2-fb353087bc21" /> Saiba mais sobre o MCP → 149 é apenas o começo. Já estamos construindo o próximo conjunto, e é aquele que muda o software empresarial para sempre.

Melhorias

  • Botões nas páginas da interface - Os botões agora podem ser colocados em cabeçalhos de páginas de tabelas, barras de ferramentas de revisão de registros, cabeçalhos de grupos de painéis e grupos de campos dentro de uma planilha de registro. Os botões no nível da página executam uma automação sem registro e Ir para a página da interface pode abrir uma página em qualquer interface da base. Saiba mais
  • Arrastar e soltar na Visualização de Lista - Os registros na Visualização de Lista podem ser arrastados pela hierarquia: solte um sobre outro para aninhá-lo ou em um pai diferente para movê-lo para lá. Os sub-registros viajam com seus pais e os links subjacentes são atualizados para você. Saiba mais
  • Crie um campo de registro vinculado inline - Quando os níveis de visualização de lista ou registros aninhados precisarem de um link que ainda não existe, click Crie um campo de registro vinculado para criá-lo no local, tanto na visualização base quanto no construtor de interface. Saiba mais
  • Ajudantes de data em expressões de fluxo de trabalho - $now() retorna a hora atual e $dateAdd(date, amount, unit) a compensa, por exemplo, $dateAdd($now(), 3, 'days').
  • Kanban mais rápido - O quadro Kanban otimizado, anteriormente uma prévia do recurso, agora é o padrão em todos os lugares, incluindo a Community Edition. As pilhas são carregadas progressivamente conforme você rola.
  • Downloads de tabelas grandes no Excel - As exportações do Excel são transmitidas, portanto, tabelas muito grandes são baixadas de maneira confiável e produzem arquivos menores.
  • Progresso da tarefa em documentos longos - A contagem de tarefas de um documento de lista de verificação segue você até o cabeçalho quando o título sai da visualização.

O que foi corrigido

  • Pesquisas aninhadas - Uma pesquisa de uma pesquisa mostra todos os valores na grade e é resolvida corretamente em links muitos para um, em MySQL, SQL Server e Oracle.
  • Acumulações condicionais com usuário atual - Os campos de rollup, pesquisa e link cujas condições usam Usuário atual são calculados para cada usuário em vez de servidos a partir de um cache compartilhado.
  • Confiabilidade da sincronização - Uma sincronização de tabela agora sempre é concluída em vez de permanecer no estado de sincronização, e a edição de uma sincronização de aplicativo é salva sem erros.
  • Nós de registro de fluxo de trabalho - Testar um nó Criar registro ou Atualizar registro relata qualquer chave de campo que não corresponda à tabela de destino, em vez de gravar um registro em branco.
  • Folhas de registro de interface - As edições feitas ao percorrer os registros aparecem na grade imediatamente, as ações de vincular e desvincular oferecem Desfazer e um registro criado dentro de um grupo permanece nesse grupo.
  • Navegação pelo teclado na interface - Com uma planilha de registro aberta, as teclas de seta se movem pela grade e a planilha segue, e Alt+Esquerda e Alt+Direita alternam entre os registros.
  • Construtor de interface - Adicionar uma classificação mantém o menu suspenso aberto, agrupar uma visualização vinculada incorporada deixa a página no lugar e uma interface iniciada reflete as alterações publicadas em outra guia.
  • Listas de verificação de documentos - A marcação de uma tarefa é refletida para cada colaborador em tempo real, e um novo subitem desmarcado em uma tarefa concluída é renderizado sem tachado.
  • Permissões de integração - A tentativa de editar uma integração criada por outra pessoa mostra uma mensagem clara em vez de desconectar você.
  • MCP - A classificação de registros funciona na Community Edition, os tokens sem uma função base recebem uma resposta clara de acesso negado e a autorização OAuth é concluída a partir de clients, como a plataforma OpenAI.
  • Fontes externas - Uma página enorme de resultados explica como reduzir os campos ou o tamanho da página em vez de relatar a fonte como inacessível.
  • Pastas - O botão + em uma fonte de dados externa agora oferece Pasta ao lado de Tabela, e uma pasta criada a partir do menu Mover para de um item ocupa a posição do item na barra lateral em vez de no final da lista.

  • O modo comunidade mantém os recursos gratuitos visíveis - Com Mostrar apenas recursos da edição comunitária ativado, os fluxos de trabalho, as interfaces e as pastas permanecem disponíveis, e os subrecursos bloqueados pelo plano ficam ocultos em vez de serem mostrados como controles inativos.

Alteração planejada para o formato de data e hora API

<Callout type="info">Essa mudança foi anunciada pela primeira vez no 2026.08.2 e ainda está planejada para um próximo lançamento. Não faz parte do 2026.09.0. Estamos mantendo o aviso aqui para que as integrações possam ser preparadas.</Callout> Nas implantações PostgreSQL e SQLite, os valores de data e hora retornados pelo NocoDB passarão da precisão de segundos para milissegundos: | Hoje | Próximo lançamento | | --- | --- | | 2026-07-25 12:34:56+00:00 | 2026-07-25 12:34:56.000+00:00 |

  • Escopo: respostas REST API, cargas úteis de webhook e exportações de arquivos/CSV. Os valores são formatados na leitura, portanto os registros existentes também são retornados no novo formato. Nenhuma migração ou preenchimento de dados é necessário.
  • O que verificar: Os consumidores que analisam datas e horas com um formato estrito ou fixo podem precisar aceitar o componente de milissegundos. Analisadores tolerantes como Day.js e a maioria dos analisadores ISO 8601 não são afetados.
  • Filtros: Os filtros de intervalo e a classificação não são afetados. Os filtros exatos de igualdade de data e hora são comparados com precisão de segundo, portanto, eles podem não corresponder a valores que transportam milissegundos diferentes de zero. A filtragem com reconhecimento de milissegundos está planejada como uma continuação.
  • Não afetado: As conexões MySQL, SQL Server e Oracle mantêm a segunda precisão, as datas e horas renderizadas pela fórmula permanecem com a segunda precisão e a exibição da data e hora no aplicativo permanece inalterada.

Para mais detalhes sobre os recursos introduzidos no 2026.08.2, consulte 2026.08.2 changelog.

1200% More MCP Tools

The MCP server has gone from 11 tools to 149, covering the whole workspace, not just records. Claude, ChatGPT, Cursor, or any MCP client can now build in NocoDB: stand up a table, wire a workflow to a webhook, assemble an interface page, or lock down permissions, all in one conversation.

Tools span tables, fields, views, filters, sorts, workflows, interfaces, dashboards, widgets, scripts, documents, webhooks, comments, permissions, Record-Level Security, row coloring, folders, members, and CSV import and export. Each wraps the same service as its REST API, so validation, permissions, and audit are identical, and every call respects the caller's role: viewers read, editors write, creators change schema.

Improvements

  • Buttons across interface pages - Buttons can now be placed on table page headers, record review toolbars, dashboard group headers, and field groups inside a record sheet. Page-level buttons run an automation without a record, and Go to interface page can open a page in any interface in the base. Learn more
  • Drag and drop in List View - Records in List View can be dragged across the hierarchy: drop one onto another to nest it, or onto a different parent to move it there. Sub-records travel with their parent, and the underlying links are updated for you. Learn more
  • Create a linked record field inline - When List View levels or nested records need a link that does not exist yet, click Create a linked record field to create it on the spot, in both the base view and the interface builder. Learn more
  • Date helpers in workflow expressions - $now() returns the current time and $dateAdd(date, amount, unit) offsets it, for example $dateAdd($now(), 3, 'days').
  • Faster Kanban - The optimized Kanban board, previously a feature preview, is now the default everywhere, including the Community Edition. Stacks load progressively as you scroll.
  • Excel downloads of large tables - Excel exports are streamed, so very large tables download reliably and produce smaller files.
  • Task progress in long documents - The task count of a checklist document follows you into the header once the title scrolls out of view.

What's Fixed

  • Nested lookups - A lookup of a lookup shows every value in the grid and resolves correctly over many-to-one links, on MySQL, SQL Server, and Oracle.
  • Conditional rollups with Current User - Rollup, lookup, and link fields whose conditions use Current User are computed for each user rather than served from a shared cache.
  • Sync reliability - A table sync now always completes rather than staying in the syncing state, and editing an app sync saves without error.
  • Workflow record nodes - Testing a Create record or Update record node reports any field key that does not match the target table, instead of writing a blank record.
  • Interface record sheets - Edits made while stepping through records appear in the grid immediately, link and unlink actions offer Undo, and a record created inside a group stays in that group.
  • Interface keyboard navigation - With a record sheet open, arrow keys move through the grid and the sheet follows, and Alt+Left and Alt+Right step between records.
  • Interface builder - Adding a sort keeps the dropdown open, grouping an embedded linked view leaves the page behind it in place, and a launched interface reflects changes published from another tab.
  • Document checklists - Ticking a task is reflected for every collaborator in realtime, and a new unchecked sub-item under a completed task renders without strikethrough.
  • Integration permissions - Attempting to edit an integration created by someone else shows a clear message instead of signing you out.
  • MCP - Sorting records works in the Community Edition, tokens without a base role receive a clear access denied response, and OAuth authorization completes from clients such as OpenAI's platform.
  • External sources - An oversized page of results explains how to reduce fields or page size instead of reporting the source as unreachable.
  • Folders - The + button on an external data source now offers Folder alongside Table, and a folder created from an item's Move to menu takes the item's position in the sidebar instead of the end of the list.

Self-Hosting Notes

  • Community mode keeps Free features visible - With Show only community edition features on, Workflows, Interfaces, and folders stay available, and plan-locked sub-features are hidden rather than shown as dead controls.
  • Security hardening - Disabled or expired API tokens are rejected in the Community Edition, hidden fields stay hidden behind row color rules on shared views, comments are scoped to their base, and table visibility is enforced on every route.
  • Clearer PostgreSQL permission errors - A schema change attempted without table ownership names the affected table in full, including quoted names with spaces or mixed case.
  • Paid field types on unlicensed deployments - Field types not included in the Community Edition (UUID, AutoNumber, Color, unique constraints, and lookup limits) are now rejected by the API as well as the UI.

Planned Breaking Change to API Datetime Format

<Callout type="info">This change was first announced in 2026.08.2 and is still planned for an upcoming release. It is not part of 2026.09.0. We are keeping the notice here so integrations can be prepared.</Callout>

On PostgreSQL and SQLite deployments, datetime values returned by NocoDB will move from second to millisecond precision:

| Today | Upcoming release | | --- | --- | | 2026-07-25 12:34:56+00:00 | 2026-07-25 12:34:56.000+00:00 |

  • Scope: REST API responses, webhook payloads, and CSV/file exports. Values are formatted on read, so existing records are returned in the new format too. No data migration or backfill is required.
  • What to check: Consumers that parse datetimes with a strict or fixed format may need to accept the millisecond component. Tolerant parsers such as Day.js and most ISO 8601 parsers are unaffected.
  • Filters: Range filters and sorting are unaffected. Exact datetime equality filters compare at second precision, so they may not match values carrying non-zero milliseconds. Millisecond-aware filtering is planned as a follow-up.
  • Not affected: MySQL, SQL Server, and Oracle connections keep second precision, formula-rendered datetimes stay at second precision, and the datetime display in the app is unchanged.

For more details on the features introduced in 2026.08.2, see the 2026.08.2 changelog.
