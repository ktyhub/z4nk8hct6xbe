Interfaces

Interfaces permitem que você crie aplicativos personalizados e fáceis de usar com base nos seus dados básicos. Em vez de dar a todos acesso à base completa com todas as suas tabelas, visualizações e opções de configuração, você cria páginas focadas que apresentam exatamente os dados e ações que cada público precisa: uma fila de revisão para aprovadores, um painel para liderança, um formulário para equipes de campo ou uma ferramenta interna completa que combina todos eles. Sua base continua sendo a única fonte da verdade; o que muda é a forma como cada grupo vivencia isso. As interfaces (beta) estão disponíveis no NocoDB Cloud (plano Plus e superior) e em implantações auto-hospedadas licenciadas (plano Business e superior). <img largura="1440" altura="900" alt="interfaces" src="https://github.com/user-attachments/assets/b31ba6d3-6255-435f-bb30-add5b2684be8" /> Saiba mais sobre Interfaces →

Melhorias e correções

  • Condições dinâmicas na segurança em nível de registro. Uma política agora pode fazer referência a quem está visualizando os dados, como o usuário atual, seu e-mail ou suas equipes, portanto, uma única política como "O responsável é o usuário atual" abrange todo o espaço de trabalho. As políticas também podem filtrar campos do sistema, como Criado por e Última modificação por. Disponível no NocoDB Cloud (plano Scale e superior) e nos planos Scale e Enterprise auto-hospedados. Saiba mais →
  • Nova função de fórmula WEEKNUM. WEEKNUM(date, [startDayOfWeek]) retorna a semana do ano em que a data cai, correspondendo à forma como as planilhas a calculam. As semanas começam no domingo por padrão e um segundo argumento opcional escolhe um primeiro dia da semana diferente. Saiba mais →
  • Selecione um intervalo de linhas com Shift+click. Segure Shift enquanto cli marca a caixa de seleção de uma linha na grade para selecionar cada linha entre ela e a última linha que você clickou, da mesma forma que as planilhas funcionam.
  • As atualizações de link v3 permanecem com escopo definido para os registros solicitados. A atualização de um campo de link por meio dos registros v3 API não remove mais esses registros vinculados de outras linhas.
  • Excluir opções de seleção por título no API v3. O endpoint de exclusão de opções de campo agora aceita títulos de opções em vez de ids e ignora títulos que não existem. Atualize as integrações v3 existentes de acordo.
  • Mudança de comportamento no API v1: as atualizações do usuário não alteram mais o acesso ao espaço de trabalho. PATCH /api/v1/users/{userId} não altera mais o acesso padrão ao espaço de trabalho. Para conceder acesso a uma base específica, utilize POST /api/v3/meta/bases/{baseId}/members com { email, base_role }. Para permitir a criação de base e acesso em todo o espaço de trabalho, use POST /api/v3/meta/workspaces/{workspaceId}/members com { email, workspace_role }.
  • As visualizações agrupadas permanecem inalteradas durante a edição. As grades agrupadas por um link, usuário, JSON ou campo de anexo não ficam mais em branco e são recarregadas a cada edição de célula.
  • Não há mais linhas duplicadas durante a rolagem. Quando um registro sai de uma grade filtrada ou classificada, uma busca em andamento pode renderizá-lo uma segunda vez mais abaixo na visualização.
  • Duplicar um registro não move mais registros vinculados. Copiar cada link literalmente pode desanexar silenciosamente registros vinculados de um para um do original. Esses links agora são ignorados na cópia, com um aviso listando os campos que não foram transferidos.
  • Visualizações mais rápidas com códigos QR. As células de código QR não geram mais códigos em tamanho real para cada linha, o que poderia congelar visualizações com muitos registros.
  • Confiabilidade de instantâneos. Os instantâneos agora funcionam em bases com permissões restritas e em espaços de trabalho que atingiram seu limite de base.
  • Correções de texto inteligente. Uma falha no carregamento inicial não permite mais que o salvamento automático limpe o conteúdo da célula, o Backspace funciona novamente no editor expandido e as tabelas mostram barras persistentes para adicionar linhas e colunas.
  • Os campos de rollup validam seu destino. A criação de um rollup sobre um campo que não pode ser agregado, como um campo Link, Pesquisa ou Botão, é rejeitada com um erro claro em vez de interromper todas as leituras da tabela.
  • Scripts do lado do servidor criam registros com dados. createRecordsAsync em scripts executados por fluxos de trabalho e automações não cria mais registros em branco.
  • O visualizador de imagens funciona em formulários. Abrir um anexo de imagem de um formulário não gera mais erros.
  • As visualizações de lista são carregadas em fontes de dados externas no NocoDB Cloud.
  • As importações do Postgres mantêm o incremento automático sincronizado. Após importar ou migrar uma base para o Postgres, a criação do primeiro registro não falha mais com um erro de chave duplicada.
  • O esquema SQLite muda com índices. A exclusão ou modificação de um campo indexado em um banco de dados SQLite conectado não falha mais.
  • Feedback do sandbox. A criação de um sandbox agora é confirmada com uma mensagem em vez de alterná-lo silenciosamente, e a criação de um documento, que um sandbox não suporta, é desabilitada com uma explicação em vez de falhar no click.
  • Controles de visibilidade de campo mais organizados. O painel de campos nos detalhes da tabela agora usa um botão de alternância para mostrar ou ocultar campos na visualização atual.
  • Diversas correções de estabilidade. Right-clicking espaço vazio em um quadro Kanban não mostra mais as ações de outro cartão, e várias falhas em células selecionadas e na grade da tela foram corrigidas.

Segurança

  • Manuseio de entrada. Validação mais forte de expressões de filtro, destinos de redirecionamento, configurações de conexão e parâmetros OAuth em toda a plataforma.
  • Controles de acesso a dados. Links de compartilhamento público, exportações e dados aninhados agora respeitam consistentemente filtros de visualização e campos ocultos, e as condições de segurança em nível de registro são aplicadas uniformemente em dados, em tempo real e caminhos em cache.
  • Autenticação e sessões. Rotação de token de sessão reforçada e fluxos de autorização OAuth, e login por meio de provedores de identidade agora respeitam o status de verificação de e-mail do provedor.
  • Proteção de incorporação. As páginas NocoDB agora enviam cabeçalhos de proteção de quadros, portanto, apenas links de compartilhamento público podem ser incorporados em outros sites.
  • Atualizações de dependências. As dependências foram atualizadas em relação aos avisos publicados recentemente.

Auto-hospedagem

  • Altere seu plano de licença você mesmo. Cada licença em Conta → Licenças auto-hospedadas em nocodb.com recebe uma página de detalhes com seu plano, período de cobrança, contagem de editores, data de renovação e faturas, além de um fluxo de mudança de plano. As atualizações são aplicadas imediatamente com faturamento proporcional; os downgrades entram em vigor no final do período de faturamento atual e podem ser revertidos até então. Saiba mais →
  • Ocultar recursos pagos em instâncias não licenciadas. Uma nova preferência Mostrar apenas recursos da edição da comunidade em Conta → Perfil oculta emblemas de recursos pagos, solicitações de atualização e controles que levam apenas a uma tela de atualização, de modo que uma instância executada sem licença mostra exatamente o que ela realmente pode fazer. A opção aparece apenas em instâncias auto-hospedadas não licenciadas.
  • Novas opções de configuração. Três variáveis ​​NC_AI_* ajustam os orçamentos de token do assistente de IA: NC_AI_TURN_TOKEN_BUDGET, NC_AI_INRUN_MICROCOMPACT_MIN_TOKENS e NC_AI_TOOL_OUTPUT_SPILL_MAX_ENTRIES. Saiba mais →

Interfaces

Interfaces let you build custom, easy-to-use apps on top of your base data. Instead of giving everyone access to the full base with all its tables, views, and configuration options, you design focused pages that surface exactly the data and actions each audience needs: a review queue for approvers, a dashboard for leadership, a form for field teams, or a full internal tool that combines all of them. Your base remains the single source of truth; what changes is how each group experiences it. Interfaces (beta) are available on NocoDB Cloud (Plus plan and above) and licensed self-hosted deployments (Business plan and above).

Improvements & Fixes

  • Dynamic conditions in Record-Level Security. A policy can now reference whoever is viewing the data, such as the current user, their email, or their teams, so a single policy like "Assignee is the current user" covers the whole workspace. Policies can also filter on system fields such as Created by and Last modified by. Available on NocoDB Cloud (Scale plan and above) and self-hosted Scale and Enterprise plans. Learn more →
  • New WEEKNUM formula function. WEEKNUM(date, [startDayOfWeek]) returns the week of the year a date falls in, matching how spreadsheets calculate it. Weeks start on Sunday by default, and an optional second argument picks a different first day of the week. Learn more →
  • Select a range of rows with Shift+click. Hold Shift while clicking a row's checkbox in the grid to select every row between it and the last row you clicked, the same way spreadsheets work.
  • v3 link updates stay scoped to the requested records. Updating a link field through the v3 records API no longer removes those linked records from other rows.
  • Delete select options by title in API v3. The field options delete endpoint now accepts option titles instead of ids and ignores titles that do not exist. Update existing v3 integrations accordingly.
  • Behaviour change in API v1: user updates no longer change workspace access. PATCH /api/v1/users/{userId} no longer changes default workspace access. To grant access to a specific base, use POST /api/v3/meta/bases/{baseId}/members with { email, base_role }. To allow base creation and workspace-wide access, use POST /api/v3/meta/workspaces/{workspaceId}/members with { email, workspace_role }.
  • Grouped views stay put while editing. Grids grouped by a link, user, JSON, or attachment field no longer blank out and reload on every cell edit.
  • No more duplicate rows while scrolling. When a record dropped out of a filtered or sorted grid, an in-flight fetch could render it a second time further down the view.
  • Duplicating a record no longer moves linked records. Copying every link verbatim could silently detach has-many and one-to-one linked records from the original. These links are now skipped on the copy, with a notice listing the fields that were not carried over.
  • Faster views with QR codes. QR code cells no longer generate full-size codes for every row, which could freeze views with many records.
  • Snapshot reliability. Snapshots now work on bases with restricted permissions and in workspaces that have reached their base limit.
  • Smart Text fixes. A failed initial load no longer lets autosave clear the cell's content, Backspace works again in the expanded editor, and tables show persistent bars for adding rows and columns.
  • Rollup fields validate their target. Creating a rollup over a field that cannot be aggregated, such as a Link, Lookup, or Button field, is rejected with a clear error instead of breaking every read of the table.
  • Server-side scripts create records with data. createRecordsAsync in scripts run by workflows and automations no longer creates blank records.
  • Image viewer works in forms. Opening an image attachment from a form no longer throws an error.
  • List views load on external data sources on NocoDB Cloud.
  • Postgres imports keep auto-increment in sync. After importing or migrating a base into Postgres, creating the first record no longer fails with a duplicate-key error.
  • SQLite schema changes with indexes. Deleting or modifying an indexed field on a connected SQLite database no longer fails.
  • Sandbox feedback. Creating a sandbox now confirms with a message instead of silently switching you over, and creating a document, which a sandbox does not support, is disabled with an explanation rather than failing on click.
  • Tidier field visibility controls. The fields panel in table details now uses an eye toggle to show or hide fields in the current view.
  • Assorted stability fixes. Right-clicking empty space on a Kanban board no longer shows another card's actions, and several crashes in select cells and the canvas grid were fixed.

Security

  • Input handling. Stronger validation of filter expressions, redirect targets, connection configurations, and OAuth parameters across the platform.
  • Data access controls. Public share links, exports, and nested data now consistently honour view filters and hidden fields, and record-level security conditions are applied uniformly across data, realtime, and cached paths.
  • Authentication and sessions. Hardened session token rotation and OAuth authorization flows, and sign-in via identity providers now honours the provider's email verification status.
  • Embedding protection. NocoDB pages now send frame-protection headers, so only public share links can be embedded in other sites.
  • Dependency updates. Dependencies were updated against recently published advisories.

Self-Hosting

  • Change your license plan yourself. Each license under Account → Self-hosted licenses on nocodb.com gets a detail page with its plan, billing period, editor count, renewal date, and invoices, plus a Change plan flow. Upgrades apply immediately with prorated billing; downgrades take effect at the end of the current billing period and can be reverted until then. Learn more →
  • Hide paid features on unlicensed instances. A new Show only community edition features preference under Account → Profile hides paid feature badges, upgrade prompts, and controls that only lead to an upgrade screen, so an instance running without a license shows just what it can actually do. The option appears only on unlicensed self-hosted instances.
  • New configuration options. Three NC_AI_* variables tune the AI assistant's token budgets: NC_AI_TURN_TOKEN_BUDGET, NC_AI_INRUN_MICROCOMPACT_MIN_TOKENS, and NC_AI_TOOL_OUTPUT_SPILL_MAX_ENTRIES. Learn more →
