TencentDB-Agente-Memória v1.0.0

[1.0.0] - 11/06/2026

Versão oficial lançada: Evoluiu do plug-in exclusivo OpenClaw para serviço de memória universal para todos os Agentes. Serviço independente de gateway completo + v2 HTTP API + TypeScript / Python SDK oficial, qualquer estrutura de agente pode acessar memória multicamada completa e recursos de compactação de contexto.

⚠️ Mudanças importantes

  • Divisão da arquitetura cliente/servidor: o mecanismo de memória é dividido do plug-in integrado OpenClaw em um processo de serviço de gateway independente, e os métodos de implantação e acesso mudam.
  • Alteração na estrutura de configuração: A estrutura de configuração do plug-in é nivelada e reconstruída, e o campo gateway original é migrado para o aninhamento server.
  • Alteração do modo de entrada do plug-in: Suporta dois modos de acesso: local (executando localmente dentro do processo, padrão) e client (conectando a um Memory Gateway externo).

🚀 Serviço de gateway independente (v2 API)

A capacidade de memória não está mais vinculada ao host OpenClaw e é executada como um serviço independente. Ele fornece leitura e gravação de memória e gerenciamento de pipeline para qualquer Agente por meio de HTTP v2 API:

  • V2 completo API: 14 rotas padrão cobrindo todas as operações, como CRUD de memória, atualizações atômicas, indexação de cena, consulta de status de pipeline, etc.
  • Consulta de status do pipeline (/v2/pipeline/status): Obtenha o status de execução e o progresso de cada estágio de L1/L2/L3 em tempo real.
  • Gerenciamento do ciclo de vida de instâncias (/v2/instance/destroy): suporte a sistemas externos para criar/destruir ativamente instâncias de memória.
  • Autenticação de portador opcional + lista de permissões CORS: Proteja a segurança do API exposto ao mundo externo.
  • Solicitar verificação do corpo: aplique um limite superior de 1 MiB para evitar solicitações anormais.

🚀 SDK Oficial

  • TypeScript SDK 1.0.0 (@tencentdb-agent-memory/memory-sdk-ts): Tipo seguro, cobrindo todos os v2 API, pronto para uso com instalação npm.
  • Python SDK (tencentdb-agent-memory-sdk-python): instalação pip wheel, modo duplo síncrono/assíncrono, cobrindo todos os API v2.

🚀 Adaptação da estrutura do Agente Universal

  • Adaptação do plug-in OpenClaw: suporta dois modos de acesso: local (executando localmente no processo, padrão) e client (conectando ao Memory Gateway externo). O modo local mantém a experiência original.
  • Adaptação do agente Hermes: adaptador memory_tencentdb_v2, suporta cenário multilocatário da estrutura Hermes.
  • Acesso Universal: Qualquer Agente que possa enviar solicitações HTTP (LangChain, AutoGPT, estrutura autodesenvolvida, etc.) pode acessar através de SDK ou API simples.

🚀 Observabilidade

  • **OpenTelemetry full-link Trace **: suporta relatórios de protocolo OTLP e pode ser conectado a back-ends como Jaeger / Grafana Tempo.
  • Integração Langfuse: encaminha apenas intervalos relacionados ao LLM, adequados para avaliar a qualidade de recuperação de memória.
  • Indicadores de avaliação de pipeline: taxa de extração L1, distribuição de decisão de desduplicação, consumo de tokens em cada estágio, atraso de recall, etc.

🚀 Servidor de descarregamento V2

  • Executor assíncrono L1 / L1.5 / L2: pipeline de processamento de offload independente, com suporte para simultaneidade de sessão em grande escala.
  • Processador de compactação L3: tokenização Mermaid + controle de orçamento de contexto, compactação de contexto inteligente.
  • Injeção MMD: Suporta processo de descarregamento de injeção de dados multimodal.
  • Roteamento /v2/offload/* integrado ao gateway: entrada Offload API unificada.

📦 Método de implantação

| Método | Descrição | |------|------| | Recipiente Docker | docker pull agentmemory/hermes-memory:1.0.0 | | Execute o código-fonte diretamente | node --import tsx/esm src/gateway/server.ts | | Plug-in OpenClaw | Instalado via install-openclaw-plugin-v2.sh | | Plug-in Hermes | Plug-in memory_tencentdb_v2 Python integrado |

⬆️ Instruções de atualização de 0.x

v1.0.0 e 0.x são duas linhas de versão mantidas em paralelo:

  • 0.x (ramificação main): plug-in integrado OpenClaw, adequado para cenários independentes leves
  • 1.x (ramificação feat/server): serviço de memória independente, adequado para implantação multiagente/multiestrutura/baseada em serviço

Os mecanismos de memória central dos dois são os mesmos (camadas L0 → L3 + recuperação híbrida BM25/vetor + memória simbólica de curto prazo Mermaid) e os formatos de dados são compatíveis.

🐛 Correção (v1.0.0-beta.2 → v1.0.0)

  • O plug-in Hermes install_hermes_tdai_gateway.sh foi aprimorado: suporta troca automática de usuário root, migração automática de caminhos antigos, detecção idempotente para pular instalações repetidas
  • Otimização da configuração do gateway: porta padrão 8420, gravação síncrona de duas variáveis de ambiente /etc/profile.d/ e ~/.hermes/.env
  • Preenchimento de documento SDK: TypeScript / Python SDK README e exemplo de acesso
  • Ajuste de configuração do plugin OpenClaw.json: remova o campo obsoleto e adapte-se à versão mais recente do OpenClaw

TencentDB-Agent-Memory v1.0.0

Highlights

  • Gateway + v2 API remove the OpenClaw dependency — Memory now runs as a standalone service exposing 14 routes for CRUD, atomic updates, scenario indexing, pipeline status, and instance lifecycle. Any HTTP-capable agent can integrate; Bearer authentication, CORS allowlists, and a 1 MiB request limit support safer external deployment.
  • Breaking deployment and configuration changes require an explicit migration path — The embedded plugin becomes a client/server architecture: rename the flat gateway configuration to nested server, then choose local mode (default, in-process) or client mode (external Gateway). Existing 0.x installations can remain on main; the service-oriented 1.x line lives on feat/server, with a compatible memory engine and data format.
  • Official SDKs cover the complete API — TypeScript (@tencentdb-agent-memory/memory-sdk-ts) provides typed access, while the Python package (tencentdb-agent-memory-sdk-python) supports both synchronous and asynchronous workflows. This avoids hand-maintaining HTTP clients when integrating LangChain, AutoGPT, Hermes, or custom frameworks.
  • Offload processing is redesigned for concurrency and context control — Asynchronous L1/L1.5/L2 executors handle large session volumes, while L3 combines Mermaid symbolization with context-budget enforcement for compression. Multimodal data can enter the pipeline through /v2/offload/*, making memory infrastructure usable beyond text-only conversations.
  • Production observability is built in — OpenTelemetry traces export over OTLP to backends such as Jaeger or Grafana Tempo; Langfuse receives only LLM-related spans for extraction-quality evaluation. Pipeline metrics—including L1 extraction rate, deduplication decisions, token usage, and recall latency—help diagnose memory behavior rather than treating it as a black box.

[1.0.0] - 2026-06-11

正式版发布：从 OpenClaw 专属插件演进为面向所有 Agent 的通用记忆服务。完整的 Gateway 独立服务 + v2 HTTP API + 官方 TypeScript / Python SDK，任何 Agent 框架均可接入完整的多层记忆与上下文压缩能力。

⚠️ Breaking Changes

  • 客户端/服务端架构拆分：记忆引擎从 OpenClaw 嵌入式插件拆分为独立 Gateway 服务进程，部署方式与接入方式发生变化。
  • 配置结构变更：插件配置结构扁平化重构，原 gateway 字段迁移为 server 嵌套。
  • 插件入口模式变更：支持 local（进程内本地运行，默认）和 client（连接外部 Memory Gateway）两种接入模式。

🚀 独立 Gateway 服务（v2 API）

记忆能力不再绑定 OpenClaw 宿主，以独立服务形式运行，通过 v2 HTTP API 为任意 Agent 提供记忆读写与管线管理：

  • 完整 v2 API：14 条标准路由覆盖记忆 CRUD、原子更新、场景索引、管线状态查询等全部操作。
  • 管线状态查询（/v2/pipeline/status）：实时获取 L1/L2/L3 各阶段运行状态与进度。
  • 实例生命周期管理（/v2/instance/destroy）：支持外部系统主动创建/销毁记忆实例。
  • 可选 Bearer 鉴权 + CORS 白名单：保护对外暴露的 API 安全。
  • 请求体校验：强制 1 MiB 上限，防止异常请求。

🚀 官方 SDK

  • TypeScript SDK 1.0.0（@tencentdb-agent-memory/memory-sdk-ts）：类型安全，覆盖全部 v2 API，npm 安装即用。
  • Python SDK（tencentdb-agent-memory-sdk-python）：pip wheel 安装，同步/异步双模式，覆盖全部 v2 API。

🚀 通用 Agent 框架适配

  • OpenClaw 插件适配：支持 local（进程内本地运行，默认）和 client（连接外部 Memory Gateway）两种接入模式。local 模式保持原有体验。
  • Hermes Agent 适配：memory_tencentdb_v2 adapter，支持 Hermes 框架多租户场景。
  • 通用接入：任何能发 HTTP 请求的 Agent（LangChain、AutoGPT、自研框架等）均可通过 SDK 或裸 API 接入。

🚀 可观测性

  • OpenTelemetry 全链路 Trace：支持 OTLP 协议上报，可对接 Jaeger / Grafana Tempo 等后端。
  • Langfuse 集成：仅转发 LLM 相关 span，适合评估记忆提取质量。
  • 管线评测指标：L1 提取率、去重决策分布、各阶段 token 消耗、recall 延迟等。

🚀 Offload Server V2

  • L1 / L1.5 / L2 异步执行器：独立的 Offload 处理管线，支持大规模会话并发。
  • L3 压缩处理器：Mermaid 符号化 + 上下文预算控制，智能上下文压缩。
  • MMD 注入：支持多模态数据注入 Offload 流程。
  • Gateway 集成 /v2/offload/* 路由：统一 Offload API 入口。

📦 部署方式

| 方式 | 说明 | |------|------| | Docker 容器 | docker pull agentmemory/hermes-memory:1.0.0 | | 源码直接运行 | node --import tsx/esm src/gateway/server.ts | | OpenClaw 插件 | 通过 install-openclaw-plugin-v2.sh 安装 | | Hermes 插件 | 内置 memory_tencentdb_v2 Python 插件 |

⬆️ 从 0.x 升级说明

v1.0.0 与 0.x 是并行维护的两条版本线：

  • 0.x（main 分支）：OpenClaw 嵌入式插件，适合轻量单机场景
  • 1.x（feat/server 分支）：独立 Memory 服务，适合多 Agent / 多框架 / 服务化部署

两者核心记忆引擎相同（L0→L3 分层 + BM25/向量混合检索 + Mermaid 符号化短期记忆），数据格式兼容。

🐛 修复（v1.0.0-beta.2 → v1.0.0）

  • Hermes 插件 install_hermes_tdai_gateway.sh 完善：支持 root 自动切换用户、旧路径自动迁移、幂等检测以跳过重复安装
  • Gateway 配置优化：默认端口 8420，同步写入 /etc/profile.d/ 和 ~/.hermes/.env 两份环境变量
  • SDK 文档补全：TypeScript / Python SDK README 与接入示例
  • OpenClaw plugin.json 配置调整：移除 deprecated 字段，适配 OpenClaw 最新版本

📖 文档

  • SDK 接入指南（TypeScript / Python 示例）。
  • Gateway 独立部署文档。
  • OpenClaw / Hermes 插件安装说明。
  • Docker 部署与配置参考。
