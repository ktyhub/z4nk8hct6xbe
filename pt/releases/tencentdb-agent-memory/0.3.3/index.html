TencentDB-Agente-Memória v0.3.3

[0.3.3] - 08/05/2026

🚀 Novos recursos

  • Compressão de memória de curto prazo (descarregamento de contexto): módulo de descarregamento adicionado para suportar compactação de contexto e descarregamento de memória em cenários de diálogo longo
  • Reconstrução da arquitetura: Núcleo + adaptação multi-framework: Refatorado na camada central independente do host TdaiCore + modo adaptador, desacoplando as dependências da estrutura OpenClaw; nova interface abstrata HostAdapter / LLMRunner
  • Adaptação Hermes Gateway: Adicionado adaptador Hermes Gateway (memory_tencentdb Hermes Plugin) para suportar operação independente por meio da estrutura Hermes; Descoberta automática de configuração zero do gateway
  • Patch automático de descarregamento: aplique automaticamente o patch after_tool_call quando o descarregamento for iniciado e desative automaticamente o descarregamento quando o patch falhar.
  • Filtro de captura L0: exclui blocos de contexto MMD injetados por descarregamento para evitar o armazenamento equivocado de produtos intermediários de compactação como memória
  • Otimização de injeção de recall (amigável ao cache): o recall L1 é movido de appendSystemContext para prependContext para evitar quebra de cache de prompt causada por alterações nas palavras de prompt do sistema em cada rodada
  • Tempo limite de incorporação de cenário: Adicionado embedding.recallTimeoutMs / embedding.captureTimeoutMs, o tempo limite de recall é rebaixado automaticamente para pesquisa pura por palavra-chave
  • Autocorreção do gateway: O plug-in Hermes adiciona um mecanismo watchdog + teste lento para recuperar automaticamente quando o gateway está anormal.
  • Ferramenta de gerenciamento de operação e manutenção: Adicionada ferramenta de gerenciamento de linha de comando memory-tencentdb-ctl, com suporte para dois modos de operação: autônomo e hermes
  • Compatível com a política de permissão de gancho OpenClaw v2026.4.23+: Adicionado ensurePluginHookPolicy() para detectar e concluir automaticamente a configuração do allowConversationAccess
  • Suporte Docker: Adicionada imagem Docker integrada ao Hermes + Memória, uma linha de comandos para iniciar o Agente Hermes com capacidade de memória

✨ Melhorias

  • O diretório de dados e o diretório de instalação são unificados em ~/.memory-tencentdb/
  • Introduzir a variável de ambiente $HERMES_HOME e remover o caminho ~/.hermes codificado
  • CleanContextRunner substitui a palavra padrão do prompt do sistema por systemPromptOverride, economizando aproximadamente 4.500 tokens de entrada para cada chamada L1/L2/L3
  • O prompt L2/L3 é dividido em systemPrompt + userPrompt, com divisão de funções mais clara
  • Ajuste de parâmetro padrão do pipeline: l1IdleTimeoutSeconds 60 → 600s, l2MinIntervalSeconds 300 → 900s, l2MaxIntervalSeconds 1800 → 3600s
  • Os scripts de operação e manutenção permanecem no tarball, mas não são mais registrados como comandos bin, reduzindo a poluição do comando global.
  • log de ciclo de vida de inicialização/destruição rebaixado para nível de depuração
  • Adicionada configuração de compilação tsdown para gerar dist/index.mjs para atender à nova versão de verificação de instalação do OpenClaw
  • A instrução activation.onStartup garante que o plugin seja carregado quando o gateway for iniciado
  • Declare contracts.tools para registrar o nome da ferramenta e atender aos requisitos do contrato de registro da ferramenta

🐛 Correção

  • Corrigir o problema de condição de corrida em chamadas simultâneas de ensureSchedulerStarted
  • Corrigido erro /session/end ao destruir o agendador global (alterado para escopo session_key)
  • Corrigido o problema de não esperar que a tarefa de disparar e esquecer em segundo plano fosse concluída ao fechar a loja
  • Corrigido o problema de disable_offload não excluir a configuração slots.contextEngine corretamente
  • Lógica de detecção de ocupação de slot corrigida: rejeitar somente quando a exceção ok=false, API não for mais considerada erroneamente como um conflito
  • Corrigido o problema em que a compactação agressiva/de emergência travava quando a mensagem do usuário estava no início da fila
  • Corrigido o problema de travamento da compactação de mensagens após um grande número de offloads
  • Corrigida contenção de simultaneidade pullProfilesToLocal causando erro ENOTEMPTY
  • Corrigida a quebra do link de dados originalUserMessageCount, fazendo com que o gravador L0 não conseguisse localizar mensagens contaminadas do usuário
  • Corrigir definição de tipo RecallResult ausente no campo prependContext
  • Corrigido o problema que fazia com que o script fosse encerrado quando ((VAR++)) no ambiente set -e tinha VAR=0
  • Corrigido o problema em que Hermes não encerrava o processo filho do Gateway ao sair
  • Lógica de decisão de versão de política de gancho reforçada, versões não padrão serão ignoradas para evitar erros de escrita de configurações

♻️ Refatoração

  • Lógica unificada de detecção de patch: sempre delegue ao script de patch e determine o resultado pelo código de saída
  • TdaiCore fornece API unificado: handleBeforeRecall() / handleTurnCommitted() / searchMemories()
  • Propriedade do diretório de dados transferida do plugin para gerenciamento da camada Gateway

TencentDB-Agent-Memory v0.3.3

Highlights

  • Long-context offload — New Offload support compresses and unloads context during long conversations. It automatically applies an after_tool_call patch and disables itself if patching fails; L0 capture also filters injected MMD blocks so compressed intermediates do not pollute stored memory.
  • Framework-neutral architecture and Hermes support — TdaiCore now separates memory logic from OpenClaw through HostAdapter and LLMRunner, exposing unified recall, turn-commit, and search APIs. The new memory_tencentdb Hermes plugin adds zero-config Gateway discovery, watchdog/lazy-probe recovery, and a bundled Docker deployment. OpenClaw packaging now includes dist/index.mjs, startup activation, tool contracts, and automatic allowConversationAccess hook-policy setup.
  • Lower token costs and more stable prompt caching — Moving L1 recall from appendSystemContext to prependContext keeps the system prefix stable across turns, avoiding prompt-cache invalidation. systemPromptOverride plus split system/user prompts saves roughly 4,500 input tokens per L1/L2/L3 call. Separate recall/capture timeouts also let recall fall back to keyword search when embeddings time out.
  • Deployment migration and slower consolidation defaults — Data now lives under ~/.memory-tencentdb/; existing installations should migrate their data directory and set $HERMES_HOME instead of relying on ~/.hermes. Operational scripts are no longer registered as global binaries—use memory-tencentdb-ctl for standalone or Hermes management. Pipeline defaults now allow substantially longer idle/consolidation intervals, so tune them if your workload requires faster L2/L3 processing.
  • Multi-session and shutdown reliability — Fixes scope scheduler destruction by session_key, serialize scheduler startup, await background tasks during store shutdown, and clean up Hermes Gateway child processes. Additional race and compression-stall fixes make long-running, concurrent sessions safer, though existing custom lifecycle integrations should be retested.
  • Breaking changes — None announced.

[0.3.3] - 2026-05-08

🚀 新功能

  • 短期记忆压缩（Context Offload）：新增 Offload 模块，支持长对话场景下的上下文压缩与记忆卸载
  • 架构重构：Core + 多框架适配：重构为 TdaiCore 宿主无关核心层 + 适配器模式，解耦 OpenClaw 框架依赖；新增 HostAdapter / LLMRunner 抽象接口
  • Hermes Gateway 适配：新增 Hermes Gateway 适配器（memory_tencentdb Hermes Plugin），支持通过 Hermes 框架独立运行；Gateway 零配置自动发现
  • Offload 自动 patch：Offload 启动时自动应用 after_tool_call patch，patch 失败时自动禁用 offload
  • L0 捕获过滤：排除 offload 注入的 MMD 上下文块，避免将压缩中间产物误存为记忆
  • Recall 注入优化（Cache 友好）：L1 召回从 appendSystemContext 移到 prependContext，避免每轮系统提示词变化导致 prompt cache bust
  • 分场景 Embedding 超时：新增 embedding.recallTimeoutMs / embedding.captureTimeoutMs，recall 超时自动降级为纯关键词搜索
  • Gateway 自愈：Hermes 插件新增 watchdog + lazy probe 机制，Gateway 异常时自动恢复
  • 运维管理工具：新增 memory-tencentdb-ctl 命令行管理工具，支持 standalone 与 hermes 两种运行模式
  • 兼容 OpenClaw v2026.4.23+ hook 权限策略：新增 ensurePluginHookPolicy() 自动检测并补全 allowConversationAccess 配置
  • Docker 支持：新增 Hermes + Memory 一体化 Docker 镜像，一行命令启动带记忆能力的 Hermes Agent

✨ 改进

  • 数据目录与安装目录统一整合至 ~/.memory-tencentdb/
  • 引入 $HERMES_HOME 环境变量，移除硬编码 ~/.hermes 路径
  • CleanContextRunner 通过 systemPromptOverride 替换默认系统提示词，每次 L1/L2/L3 调用节省 ~4500 input tokens
  • L2 / L3 prompt 拆分为 systemPrompt + userPrompt，角色划分更清晰
  • Pipeline 默认参数调整：l1IdleTimeoutSeconds 60→600s，l2MinIntervalSeconds 300→900s，l2MaxIntervalSeconds 1800→3600s
  • 运维脚本保留在 tarball 中但不再注册为 bin 命令，减少全局命令污染
  • init/destroy 生命周期日志降级为 debug 级别
  • 新增 tsdown 构建配置生成 dist/index.mjs，满足新版 OpenClaw 安装校验
  • 声明 activation.onStartup 确保 gateway 启动时加载插件
  • 声明 contracts.tools 注册工具名，满足 tool registration contract 要求

🐛 修复

  • 修复 ensureSchedulerStarted 并发调用下的竞态问题
  • 修复 /session/end 错误销毁全局 scheduler（改为按 session_key 作用域）
  • 修复关闭 store 时未等待后台 fire-and-forget 任务完成的问题
  • 修复 disable_offload 未正确删除 slots.contextEngine 配置的问题
  • 修复 slot 占用检测逻辑：仅在 ok=false 时拒绝，API 异常不再误判为冲突
  • 修复 aggressive/emergency 压缩在用户消息位于队首时卡死的问题
  • 修复消息被大量 offload 后压缩停滞的问题
  • 修复 pullProfilesToLocal 并发竞争导致 ENOTEMPTY 错误
  • 修复 originalUserMessageCount 数据链路断裂导致 L0 recorder 无法定位被污染的 user message
  • 修复 RecallResult 类型定义缺少 prependContext 字段
  • 修复 set -e 环境下 ((VAR++)) 在 VAR=0 时导致脚本退出的问题
  • 修复 Hermes 退出时未终止 Gateway 子进程的问题
  • 加固 hook-policy 版本决策逻辑，非标准版本一律跳过，避免误写配置

♻️ 重构

  • 统一 patch 检测逻辑：始终委托给 patch 脚本并通过退出码判定结果
  • TdaiCore 提供统一 API：handleBeforeRecall() / handleTurnCommitted() / searchMemories()
  • 数据目录所有权从插件移至 Gateway 层管理
