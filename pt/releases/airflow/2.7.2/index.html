airflow 2.7.2

Highlights

  • Timezone-correct datetime handling — Serialization now accepts zoneinfo.ZoneInfo and generic UTC objects (#34683, #34804), and deserialization is made deterministic (#34492). If you run non-UTC timezones or round-trip datetimes through XCom/the DB, this removes a class of subtle bugs where the same value serialized differently depending on the tzinfo implementation — relevant to scheduling accuracy and to anyone comparing serialized state across runs.

  • Smoother upgrade path from older databases — airflow db migrate no longer crashes with AttributeError: 'Select' object has no attribute 'count' (#34348), and the minimum SQLAlchemy version was raised to match ORM features the codebase now uses (#34293). Watch the dependency constraint before upgrading: a SQLAlchemy version below the new floor can still break migrations independently of this fix.

  • REST API behavior shifts — Patching a task instance no longer forces a dry run (#34568), and param validation is now consistent between DAG validation and triggering (#34248). API clients that relied on the implicit dry-run default or on looser validation at trigger time should re-check their automation. The config endpoint also now masks sensitive values (#34712), so scripts scraping that endpoint may see redacted fields where they previously saw plaintext.

  • Scheduler ignores manual runs when planning — New DagRuns are planned without using manually triggered runs as the baseline (#34027). This is a genuine behavioral change: manually triggering or clearing a DAG no longer shifts the scheduler's next-run calculation. Workflows that used manual runs to "catch up" or nudge cadence will behave differently after upgrading.

  • Permission and audit hardening — Several RBAC gaps are closed: DAG warning endpoint (#34355), task-instance access in the batch endpoint (#34315), clearing a TI from the UI (#34123), and access_control={} handling (#34114), plus missing audit logs for Flask add/edit/delete actions (#34090). Admins with custom roles that leaned on the previously broad access should re-verify those roles against the tightened checks.

  • Triggerer and operator changes to watch — dag test now fails when a task defers but no triggerer is running (#34619), surfacing misconfigurations that previously passed silently. PythonVirtualEnvOperator deprecates numeric Python version arguments (#34359), and the docs now flag the future removal of MsSQL as a DB backend (#34375) — worth planning around if either applies to your deployment.

No breaking changes in this release.
