airflow 3.0.1

Highlights

  • Upgrade and dependency layout — The 3.0 upgrade now clears stale dag_code and serialized_dag records (#49563), while import failures mark DAG models stale and associate bundles (#49769), reducing inconsistent metadata during migration. Core also drops gitpython and moves non-core dependencies plus SQS queue support to the meta-package/providers (#49537, #49846, #50057); custom slim installations should declare those dependencies explicitly.

  • Dynamic mapping reliability — Fixes enforce max_active_tis_per_dag for mapped tasks (#49708), support mapped TaskGroup map indexes and extra links (#49996, #50238), and render map_index_template after completion (#49809). Existing mapped DAGs should not need rewrites, but concurrency limits and task-detail behavior are now more consistent.

  • Unified backfill workflow — Backfill and Trigger DAG Run are merged into one form experience (#49490), including dag_run_conf support (#49763). Dry runs now use the creation form’s timezone (#49911), and date-interval validation is stricter (#50116); operators should verify that automated submissions use timezone-aware timestamps.

  • API contract updates — DagRun responses now include bundle_version (#49726), generated clients benefit from an adjusted Execution API OpenAPI schema (#49700), and the default execution-server URL is resolved relative to the API base URL (#49747, #49782). Refresh client models and avoid assuming an absolute execution-server URL.

  • Login and security hardening — Fixes prevent secure-cookie redirect loops (#49721), preserve base_url during logout (#49545), constrain unsafe login redirects in SimpleAuthManager (#49697, #49866), and mask newly set variable values (#43123). Proxy deployments should retest login/logout flows, and the no-auth-header SimpleAllAdminMiddleware (#49599) should remain restricted to trusted internal traffic.

  • Breaking changes — None are explicitly listed in this patch release.
