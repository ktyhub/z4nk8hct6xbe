airflow 2.9.2

Highlights

  • Database connection reliability — AirflowSecurityManagerV2 no longer leaves sessions idle in transaction, reducing connection-pool exhaustion and lock pressure (#39935). Migration fixes also correct Alembic constraint naming and restore existing_nullable handling during downgrades, making schema rollbacks safer (#39032, #39374).
  • Scheduler and retry behavior — The mini scheduler now uses SKIP LOCKED instead of NOWAIT, avoiding contention-related skips when another worker holds a row lock (#39745). Task logs are also fetched when an attempt is retrying without remote logs, preventing gaps during failure diagnosis (#39496).
  • Security and permissions — Custom security-manager actions now work correctly in has_access (#39421), while removing the FAB DAG-run creation option closes a path that bypassed expected workflow controls (#39881). Instance-state buttons also remain disabled for users without permission (#38732).
  • Webserver and API behavior — Bad DAG-trigger parameters now produce a controlled validation response instead of HTTP 500 (#39409). Static-file caching is restored, while dynamically generated responses explicitly use Cache-Control: no-store; reverse proxies should respect the latter to avoid serving stale security-sensitive content (#39345, #39550).
  • Airflow 2.9 compatibility — Dataset URI validation now warns rather than errors in 2.9, reducing upgrade disruption, though strict checks still re-raise exceptions where enabled (#39670, #39719). Deployments should treat these warnings as actionable before moving to stricter validation.
  • Breaking changes — None reported.

No significant changes.

  • Fix example_branch_operator failing in python 3.12 (#39783)

  • Refactor SafeDogStatsdLogger to use get_validator to enable pattern matching (#39370)
