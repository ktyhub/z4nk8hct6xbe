airflow 3.1.7

Highlights

  • Authentication and authorization — JWT generation now handles unset issuer/audience configuration (#61331), while permission fixes cover event logs, DAG query filtering, import-error APIs, and UI endpoints (#60958, #60959, #60884, #60988). Logout now invalidates refresh tokens (#60881), so authentication tests should verify that logged-out tokens cannot be reused.

  • Scheduler and DAG lifecycle correctness — Deserialization failures now hit a scheduler guardrail instead of disrupting processing (#61210). Asset scheduling for stale DAGs and versioned-bundle callbacks are repaired (#60022, #61106, #61230), and path-only DAG changes no longer create unnecessary version churn (#60799). Manual runs on scheduled DAGs also receive unique run IDs (#60468).

  • Operator and worker behavior — TriggerDagRunOperator with wait_for_completion=False no longer defers unexpectedly (#60052), avoiding stuck deferrable executions. Workers now reschedule tasks after DAG-load failures instead of exiting (#59604, #60926), and the triggerer survives non-serializable events rather than crashing (#60981).

  • Large-deployment efficiency — The DAG processor avoids loading all TaskInstances during DAG-version writes (#60962) and applies gc.freeze() (#60845), reducing memory pressure. Queue changes cut redundant processing (#60124, #60003), while XComModel.clear() now uses bulk deletion instead of loading records (#60955), making cleanup substantially cheaper on large metadata databases.

  • API and UI compatibility — The API now enforces its maximum page size (#61073); pagination clients should expect bounded responses rather than arbitrarily large pages. The React Router upgrade (#60456) warrants regression testing for custom UI plugins. Grid virtualization (#60285) and faster large-log scrolling (#60875) also improve responsiveness for heavy DAG views.

  • Compatibility — No breaking changes are listed.
