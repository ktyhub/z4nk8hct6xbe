airflow helm-chart/1.22.0

Highlights

  • Helm baseline raised to 3.19.0 (#66970) — This is the real upgrade gate: any CI job, GitOps controller, or laptop still on Helm 3.18 or older will fail to render the chart outright. Pin your helm binary and reconcile tooling before bumping the chart version — don't discover this mid-deploy.

  • Default Airflow image moves to 3.2.2 (#67681) — Unpinned installs silently jump from 3.2.1 to 3.2.2, so treat this as a patch-level Airflow rollout: smoke-test DAG parsing and provider compatibility even though you didn't "change" any config. Pin defaultAirflowTag explicitly if you need to stage the bump.

  • enableServiceLinks becomes configurable, default flips in 2.0 (#67447) — Kubernetes injects a <SVC>_SERVICE_HOST/_PORT env var for every service in the namespace, polluting task pods and risking collisions with your own variables. You can opt out now, and 2.0 will default to false. Audit any code reading those generated env vars and move to DNS-based lookups, or set enableServiceLinks: true to buy time.

  • Opt-in OTel service (#64902) — A first-class OpenTelemetry service can now be deployed alongside Airflow, giving you a supported traces/metrics path instead of a hand-rolled sidecar. Pair it with the api-server config checksum fix (#66468), which finally rolls the deployment when config changes — previously a config-only edit could leave stale pods running.

  • RBAC and ServiceAccount plumbing tightened (#66598, #66730, #66208, #66095, #66626) — A cluster of fixes corrects Kubernetes-worker ServiceAccount values, adds the missing worker binding/condition, extends launcher RBAC for executor class paths, and renders tpl in ServiceAccount annotations; the cleanup cron also gains serviceAccountTokenVolume (#67446) for IRSA/workload-identity token projection. On locked-down clusters or with custom executor classes, these are the changes most likely to unblock you — and worth diffing against your own overrides.

  • Network and scheduling fixes for day-2 ops (#65754, #67538, #67471, #67762, #65881) — Task-log access now works under NetworkPolicies on both Airflow 2 and 3, triggerer KEDA database-connection rendering is corrected, Celery liveness probes resolve hostnames properly, executor aliases get the right chart labels, and cleanup/database lifecycle hooks actually apply. If you've been carrying workarounds for any of these, retest and remove them; see the expanded Airflow 3 migration guide (#66118) for upgrade sequencing.

Significant Changes

Minimum Helm version was updated to 3.19.0 (#66970)

Default Airflow image is updated to 3.2.2 (#67681)

The default Airflow image that is used with the Chart is now 3.2.2, previously it was 3.2.1.

Added support for configuring enableServiceLinks (#67447)

The default will become false in Chart 2.0. If you rely on these environment variables, explicitly set enableServiceLinks: true, or migrate your code to use DNS-based service lookups.

New Features

  • Add optional OTel service to the Airflow Helm Chart (#64902)
  • Add serviceAccountTokenVolume to cleanup cron (#67446)
  • Add requirePersistence option to worker logGroomerSidecar (#65884)

Improvements

  • Add checksum for api-server config in API server deployment (#66468)

Bug Fixes

  • Fix Helm chart executor label to support executor aliases (#67762)
  • Fix triggerer KEDA database connection rendering (#67538)
  • Fix Celery worker liveness probe hostname lookup (#67471)
  • Fix Go template error comparing slice to nil using eq (#64032)
  • Fix Kubernetes worker service account values (#66598)
  • Add binding for workers.kubernetes and condition workers ServiceAccount (#66730)
  • Fix launcher RBAC for executor class paths (#66208)
  • Fix task log access with NetworkPolicies for Airflow 2 and 3 (#65754)
  • Add missing tpl rendering for ServiceAccount annotations (#66095)
  • Fix go-template if statements for log groomer retention values (#66012)
  • Fix database cleanup lifecycle hooks (#65881)
  • Fix cleanup pod lifecycle hooks not being applied (#65764)
  • Fix deprecation warning (#66238)

Doc only changes

  • Expand Helm Chart upgrade tasks in the Airflow 3 migration guide (#66118)

Misc

  • Change job/pod role bindings rendering and refactor related tests (#66626)
  • Standardize on Dag capitalization in chart wording (#66114)
