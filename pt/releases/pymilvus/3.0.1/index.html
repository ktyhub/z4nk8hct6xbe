#pymilvus v3.0.1

PyMilvus v3.0.1 Release Notes

PyMilvus 3.0.1 é a versão Python SDK recomendada para Milvus 3.0.

Compatibilidade: PyMilvus 3.0.1 requer Python 3.9 ou posterior. Python 3.8 não é mais compatível.

O que mudou

Novos APIs e capacidades

  • Adicione manipulação de DataType.TEXT na validação de esquema, decodificação de resultados e caminhos BulkWriter (#3473).
  • Adicione get_replicate_info() a MilvusClient e AsyncMilvusClient (#3516).
  • Adicionar suporte dump_messages() sincronizado e assíncrono para fluxos de trabalho de salvamento de dados (#3575).
  • Adicione descrições de funções e usuários, incluindo alter_role() e saída de descrição de funções de describe_role() (#3608).
  • Adicione agregação de pesquisa e encaminhe corretamente group_by_fields (#3647).
  • Adicione FunctionChain APIs, encaminhe cada estágio especificado durante a pesquisa e adicione o auxiliar de expressão XGBoost (#3652, #3662, #3685).

Evolução do esquema e campos de função

  • Adicione alter_collection_schema() e suporte à adição dinâmica de campos struct (#3504, #3569).
  • Roteie mutações do esquema de coleção por meio de AlterCollectionSchema, retenha um substituto AddCollectionField herdado apenas para servidores que retornam UNIMPLEMENTED e mantenha o comportamento RPC da função drop compatível (#3572, #3706).
  • Suporte a mapeamentos de campos externos e substituto de campo adicional para coleções externas (#3584, #3728).
  • Adicione drop_function_field(), suporte a campos de função MinHash e exija parâmetros de índice vinculados ao adicionar um campo de função (#3600, #3630, #3672).
  • Mantenha os metadados de chave primária, chave de partição e chave de cluster sincronizados quando os campos são adicionados (#3667).

Iteradores, resultados de pesquisa e manipulação de tipos

  • Mover implementações de consulta, Search Iterator V1 e Search Iterator V2 para a camada client enquanto preserva a compatibilidade do ORM e alinha os avisos de descontinuação do ORM (#3707, #3709, #3714, #3718).
  • Preservar a filtragem externa ao criar iteradores de pesquisa (#3730).
  • Adicione dados de campo compartilhados e decodificadores de valor aninhado, remova o extrator de linha V1 morto e evite a decodificação quadrática de resultados escalares anuláveis (#3552, #3555, #3562, #3605, #3713, #3725).
  • Consolide metadados de tipo lógico em caminhos de pesquisa, inserção, matriz, linha e vetor para remover comportamento inconsistente específico do tipo (#3474, #3481, #3499, #3539, #3548, #3550, #3557, #3613).
  • Aceita entradas flutuantes para vetores FP16 e BF16 (#3546).

Recuperação de conexão e tratamento de erros

  • Faça canais de troca sincronizados e assíncronos reconectados atomicamente, proteja RPCs ativos e cubra a recuperação de canais retirados (#3565, #3567, #3583).
  • Preservar os tempos limite de conexão configurados durante a recuperação (#3615).
  • Mapeie apenas falhas de RPC de configuração de conexão para CONNECT_FAILED e exponha a classificação de erros por meio de MilvusException (#3590, #3618).

Correções de estrutura, array e BulkWriter

  • Preservar vetores anuláveis ​​na saída CSV BulkWriter, oferecer suporte a campos de vetor de estrutura e ignorar cargas úteis para linhas de estrutura nula e subcampos de vetor de estrutura nula (#3485, #3508, #3588, #3637).
  • Resolver pesquisa de vetor binário dentro de matrizes de estrutura, preservar campos de matriz de estrutura reconstruídos a partir de dicionários de esquema e oferecer suporte a atualizações parciais para campos de matriz de estrutura (#3520, #3657, #3674).
  • Materialize os resultados da consulta de array como listas Python padrão (#3655).
  • Melhore os uploads de volume com opções mais seguras por upload, menor simultaneidade padrão, progresso em nível de byte e estado de upload simultâneo de solicitação local (#3627).
  • Preservar prefixos de upload remoto no Windows (#3665).

Validação e correções de correção

  • Rejeitar valores target_size de compactação superdimensionados ou não positivos (#3496, #3644).
  • Rejeite booleanos como valores ou índices de vetores esparsos e melhore os erros de validação (#3626, #3663).
  • Rejeite listas de vetores binários vazias com um erro de parâmetro em vez de vazar um IndexError (#3698).
  • Permitir valores nulos em uma coluna DataFrame de chave primária auto_id durante a inserção (#3678).
  • Descompacte corretamente os resultados do esquema assíncrono antes da otimização da coleção (#3683).

Ferramentas de compatibilidade, construção e teste

  • Suporte para queda Python 3.8; PyMilvus agora requer Python 3.9 ou posterior (#3700).
  • Migrar fluxos de trabalho de desenvolvimento e CI para uv, usar a resolução de versão apoiada pelo Hatchling e manter a semântica de versão RC do branch de lançamento pretendida (#3529, #3534, #3634).
  • Isole as dependências de geração de protobuf e fixe o proto Milvus 3.0 final, regenerando as ligações Python (#3692, #3731).
  • Classificar suítes de testes mantidas e atualizar exemplos assíncronos, struct-field e BulkWriter (#3595, #3599, #3640). Changelog completo: https://github.com/milvus-io/pymilvus/compare/v3.0.0...v3.0.1

pymilvus v3.0.1

PyMilvus v3.0.1 Release Notes

PyMilvus 3.0.1 is the recommended Python SDK release for Milvus 3.0.

Compatibility: PyMilvus 3.0.1 requires Python 3.9 or later. Python 3.8 is no longer supported.

What's Changed

New APIs and capabilities

  • Add DataType.TEXT handling across schema validation, result decoding, and BulkWriter paths (#3473).
  • Add get_replicate_info() to MilvusClient and AsyncMilvusClient (#3516).
  • Add sync and async dump_messages() support for data-salvage workflows (#3575).
  • Add role and user descriptions, including alter_role() and role-description output from describe_role() (#3608).
  • Add search aggregation and correctly forward group_by_fields (#3647).
  • Add FunctionChain APIs, forward every specified stage during search, and add the XGBoost expression helper (#3652, #3662, #3685).

Schema evolution and function fields

  • Add alter_collection_schema() and support dynamically adding struct fields (#3504, #3569).
  • Route collection-schema mutations through AlterCollectionSchema, retain a legacy AddCollectionField fallback only for servers returning UNIMPLEMENTED, and keep drop-function RPC behavior compatible (#3572, #3706).
  • Support external field mappings and add-field fallback for external collections (#3584, #3728).
  • Add drop_function_field(), support MinHash function fields, and require bound index parameters when adding a function field (#3600, #3630, #3672).
  • Keep primary-key, partition-key, and clustering-key metadata synchronized when fields are added (#3667).

Iterators, search results, and type handling

  • Move query, Search Iterator V1, and Search Iterator V2 implementations to the client layer while preserving ORM compatibility and aligning ORM deprecation warnings (#3707, #3709, #3714, #3718).
  • Preserve external filtering when creating search iterators (#3730).
  • Add shared field-data and nested-value decoders, remove the dead V1 row extractor, and avoid quadratic nullable-scalar result decoding (#3552, #3555, #3562, #3605, #3713, #3725).
  • Consolidate logical type metadata across search, insert, array, row, and vector paths to remove inconsistent type-specific behavior (#3474, #3481, #3499, #3539, #3548, #3550, #3557, #3613).
  • Accept float inputs for FP16 and BF16 vectors (#3546).

Connection recovery and error handling

  • Make sync and async reconnect swap channels atomically, protect active RPCs, and cover retired-channel reclamation (#3565, #3567, #3583).
  • Preserve configured connection timeouts during recovery (#3615).
  • Map only connection-setup RPC failures to CONNECT_FAILED and expose error classification through MilvusException (#3590, #3618).

Struct, array, and BulkWriter fixes

  • Preserve nullable vectors in CSV BulkWriter output, support struct-vector fields, and skip payloads for null struct rows and null struct-vector subfields (#3485, #3508, #3588, #3637).
  • Resolve binary-vector search inside struct arrays, preserve struct-array fields reconstructed from schema dictionaries, and support partial updates for struct-array fields (#3520, #3657, #3674).
  • Materialize array query results as standard Python lists (#3655).
  • Improve Volume uploads with safer per-upload options, lower default concurrency, byte-level progress, and request-local concurrent-upload state (#3627).
  • Preserve remote upload prefixes on Windows (#3665).

Validation and correctness fixes

  • Reject oversized or non-positive compaction target_size values (#3496, #3644).
  • Reject booleans as sparse-vector values or indices and improve validation errors (#3626, #3663).
  • Reject empty binary-vector lists with a parameter error instead of leaking an IndexError (#3698).
  • Allow null values in an auto_id primary-key DataFrame column during insert (#3678).
  • Correctly unpack async schema results before collection optimization (#3683).

Compatibility, build, and test tooling

  • Drop Python 3.8 support; PyMilvus now requires Python 3.9 or later (#3700).
  • Migrate development and CI workflows to uv, use Hatchling-backed version resolution, and retain the intended release-branch RC version semantics (#3529, #3534, #3634).
  • Isolate protobuf-generation dependencies and pin the final Milvus 3.0 proto, regenerating the Python bindings (#3692, #3731).
  • Classify maintained test suites and update async, struct-field, and BulkWriter examples (#3595, #3599, #3640).

Full Changelog: https://github.com/milvus-io/pymilvus/compare/v3.0.0...v3.0.1
