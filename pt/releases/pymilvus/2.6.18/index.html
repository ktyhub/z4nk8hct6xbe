pymilvus v2.6.18

PyMilvus 2.6.18 targets the Milvus 2.6 series and requires Python 3.8 or later.

What's Changed

Features and enhancements

  • Add row-level security (RLS) policy and principal-tag management to MilvusClient and AsyncMilvusClient. Supported read and write operations accept rls_principal for server-side enforcement. These APIs require a deployment with RLS support. #3853
  • Add configurable Volume upload policies, with paginated listings and bounded concurrency for large batches. VolumeFileManager.upload_file_to_volume() now skips an existing object by default when its key and byte size match. Set upload_policy=UploadPolicy.OVERWRITE to replace matching objects. #3805
  • Accept custom HTTP headers in bulk_import(), get_import_progress(), and list_import_jobs(). The SDK also exports IDEMPOTENCY_KEY_HEADER for use with servers that support idempotent bulk imports. #3808

Performance and bug fixes

  • Restore linear-time decoding of nullable scalar output fields such as VARCHAR in search results. #3724
  • Implement the async RPC handlers for AsyncMilvusClient.flush_all(), get_compaction_plans(), and update_replicate_configuration(). #3891
  • Preserve existing application log handlers when importing PyMilvus and scope BulkWriter logging to the pymilvus.bulk_writer logger tree. #3847 · #3849
  • Return None in QueryIterator.get_cursor().str_pk before the first page when the primary key is VARCHAR. #3860
  • Raise ParamError for empty binary-vector lists in batch writes and reject out-of-range ports during connection validation. #3697 · #3833

Documentation, tests, and CI

  • Standardize non-ORM docstrings on Google style. #3748
  • Expand unit test coverage, consolidate overlapping tests, and ensure Windows CI reports failures from either the unit or Lite integration suite. #3879 · #3832
