Correções de segurança

v2.5.0 corrige oito vulnerabilidades em três servidores. Atualize mcp-server-git para 2026.11.18, @modelcontextprotocol/server-filesystem a 2.4.0 e @modelcontextprotocol/server-everything a 2.3.1. | Pacote | Afetado | Corrigido em | | --- | --- | --- | | mcp-server-git | através de 2026.11.11 | 2026.11.18 | | @modelcontextprotocol/server-filesystem | todas as versões anteriores a 2.4.0 e versões de data 2025.1.14 a 2026.8.31 | 2.4.0 | | @modelcontextprotocol/server-everything | através de 2.3.0 | 2.3.1 |

mcp-server-git 2026.11.18

  • Uma mesclagem não inicia mais a manutenção automática do Git. Um git_merge bem-sucedido, com avanço rápido incluído, terminou em git maintenance run --auto, cuja coleta de lixo executa os comandos com os nomes gc.recentObjectsHook do próprio repositório, com os privilégios do servidor. maintenance.auto agora é false e gc.auto é 0 para cada comando Git que o servidor executa (GHSA-h2g3-rwxm-xfm3)
  • O Git nunca busca um objeto ausente sozinho. A configuração de um repositório pode declarar um promissor remoto e nomear o programa que o Git executa para buscá-lo (remote.<name>.uploadpack, core.sshCommand), que uma ferramenta somente leitura iniciava quando precisava de um objeto que não estava no disco. A busca lenta está desativada (GIT_NO_LAZY_FETCH=1) e um Git antigo demais para honrar que recusa um repositório que declara um promissor remoto (GHSA-87qg-cmw8-jc5m)
  • Os drivers são lidos novamente depois que uma ferramenta grava a árvore de trabalho. A configuração de um repositório pode incluir um arquivo criado por uma mesclagem ou checkout, portanto, um filtro ou driver de mesclagem pode aparecer após o servidor esvaziar aqueles que encontrou e ser executado durante o git merge --abort que segue um conflito. git_checkout, git_merge e aqueles que abortam agora leem os drivers novamente antes de qualquer outro comando do Git ser executado. A verificação de confinamento --repository ainda não foi repetida após tal gravação (#5599) (GHSA-9vjp-x34c-xg6v)
  • Um filtro ou driver de mesclagem com um nome vazio também é esvaziado. O Git aceita [filter ""], selecionado por filter= em .gitattributes, e a lista de drivers de um repositório do servidor o perdeu, então seu comando foi executado (GHSA-pm7p-vphh-2cg7)
  • Entradas de índice que apontam para fora da árvore de trabalho são recusadas. Com --repository, um .git/index criado nomeando um caminho como ../outside/secret fez com que git_diff_unstaged e git_diff retornassem o conteúdo desse arquivo e git_status relatasse se ele existe. O índice agora é verificado desde o início antes que qualquer ferramenta o leia, e o cache não rastreado, que pode nomear um diretório fora da árvore de trabalho, é desativado (GHSA-r2q8-f657-4r56)
  • A configuração própria de um submódulo não executa mais programas. Com diff.submodule=diff na configuração do repositório, git_diff executou um diff aninhado dentro de cada submódulo alterado sob os próprios drivers diff.external e textconv do submódulo, e git_checkout e git_add executaram Git dentro de um submódulo sob sua própria configuração também. diff.submodule agora é short, os drivers definidos por um submódulo com check-out são substituídos e um Git anterior a 2.33, que não passaria as substituições para um submódulo, é recusado para um repositório que tem um com check-out (GHSA-8wv7-r664-7594)

@modelcontextprotocol/server-filesystem 2.4.0

  • As listagens de diretório permanecem com o diretório que foi verificado (Linux e macOS). list_directory, list_directory_with_sizes, directory_tree e search_files agora listam um diretório no local após verificá-lo, portanto, um diretório trocado por um link simbólico entre a verificação e a listagem não pode mais retornar os nomes de entradas fora dos diretórios permitidos. No Windows, uma listagem ainda não está ancorada (#5600) (GHSA-rq2p-q7c4-6g27)

@modelcontextprotocol/server-everything 2.3.1

  • gzip-file-as-resource trata um endereço NAT64 como o endereço IPv4 que ele carrega. O protetor de endereço privado da ferramenta lê endereços em 64:ff9b::/96 como públicos, portanto, em uma rede com um gateway NAT64, uma URL pode alcançar um endereço IPv4 privado através de um. O endereço IPv4 incorporado agora está verificado (GHSA-38j4-j742-j7r3)

Atualizando de uma versão npm com versão de data

Os servidores TypeScript passaram de versões de data (2025.x, 2026.x) para versões semânticas em 1.0.0. Os gerenciadores de pacotes classificam o 2.4.0 abaixo de todas as versões 2025.xe 2026.x, portanto, não o oferecerão como uma atualização. Se você estiver em uma versão atualizada do @modelcontextprotocol/server-filesystem, instale 2.4.0 explicitamente: npm install @modelcontextprotocol/server-filesystem@2.4.0.

servers v2.5.0

Security fixes

v2.5.0 fixes eight vulnerabilities in three servers. Upgrade mcp-server-git to 2026.11.18, @modelcontextprotocol/server-filesystem to 2.4.0 and @modelcontextprotocol/server-everything to 2.3.1.

| Package | Affected | Fixed in | | --- | --- | --- | | mcp-server-git | through 2026.11.11 | 2026.11.18 | | @modelcontextprotocol/server-filesystem | all versions before 2.4.0, and date versions 2025.1.14 through 2026.8.31 | 2.4.0 | | @modelcontextprotocol/server-everything | through 2.3.0 | 2.3.1 |

mcp-server-git 2026.11.18

  • A merge no longer starts Git's automatic maintenance. A successful git_merge, a fast-forward included, ended in git maintenance run --auto, whose garbage collection runs the commands a repository's own gc.recentObjectsHook names, with the server's privileges. maintenance.auto is now false and gc.auto is 0 for every Git command the server runs (GHSA-h2g3-rwxm-xfm3)
  • Git never fetches a missing object by itself. A repository's configuration could declare a promisor remote and name the program Git runs to fetch from it (remote.<name>.uploadpack, core.sshCommand), which a read-only tool then started when it needed an object that was not on disk. Lazy fetching is turned off (GIT_NO_LAZY_FETCH=1), and a Git too old to honor that refuses a repository that declares a promisor remote (GHSA-87qg-cmw8-jc5m)
  • Drivers are read again after a tool writes the working tree. A repository's configuration can include a file that a merge or checkout creates, so a filter or merge driver could appear after the server had emptied the ones it found, and run during the git merge --abort that follows a conflict. git_checkout, git_merge and that abort now read the drivers again before any other Git command runs. The --repository confinement check is not yet repeated after such a write (#5599) (GHSA-9vjp-x34c-xg6v)
  • A filter or merge driver with an empty name is emptied too. Git accepts [filter ""], selected by filter= in .gitattributes, and the server's list of a repository's drivers missed it, so its command ran (GHSA-pm7p-vphh-2cg7)
  • Index entries that point outside the working tree are refused. With --repository, a crafted .git/index naming a path such as ../outside/secret made git_diff_unstaged and git_diff return that file's content, and git_status report whether it exists. The index is now checked from its top before any tool reads it, and the untracked cache, which can name a directory outside the working tree, is turned off (GHSA-r2q8-f657-4r56)
  • A submodule's own configuration no longer runs programs. With diff.submodule=diff in the repository's configuration, git_diff ran a nested diff inside each changed submodule under the submodule's own diff.external and textconv drivers, and git_checkout and git_add ran Git inside a submodule under its own configuration too. diff.submodule is now short, the drivers a checked-out submodule defines are overridden, and a Git older than 2.33, which would not pass the overrides into a submodule, is refused for a repository that has one checked out (GHSA-8wv7-r664-7594)

@modelcontextprotocol/server-filesystem 2.4.0

  • Directory listings stay with the directory that was checked (Linux and macOS). list_directory, list_directory_with_sizes, directory_tree and search_files now list a directory in place after checking it, so a directory swapped for a symlink between the check and the listing can no longer return the names of entries outside the allowed directories. On Windows a listing is not yet anchored (#5600) (GHSA-rq2p-q7c4-6g27)

@modelcontextprotocol/server-everything 2.3.1

  • gzip-file-as-resource treats a NAT64 address as the IPv4 address it carries. The tool's private-address guard read addresses in 64:ff9b::/96 as public, so on a network with a NAT64 gateway a URL could reach a private IPv4 address through one. The embedded IPv4 address is now checked (GHSA-38j4-j742-j7r3)

Upgrading from a date-versioned npm release

The TypeScript servers moved from date versions (2025.x, 2026.x) to semantic versions in 1.0.0. Package managers rank 2.4.0 below every 2025.x and 2026.x version, so they won't offer it as an upgrade. If you are on a date version of @modelcontextprotocol/server-filesystem, install 2.4.0 explicitly: npm install @modelcontextprotocol/server-filesystem@2.4.0.
