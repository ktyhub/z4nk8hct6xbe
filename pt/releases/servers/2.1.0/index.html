servidores v2.1.0

Correções de segurança

v2.1.0 corrige oito vulnerabilidades em três servidores. Atualizar @modelcontextprotocol/server-filesystem e @modelcontextprotocol/server-everything para 2.0.1 e mcp-server-fetch para 2026.10.24. | Pacote | Afetado | Corrigido em | | --- | --- | --- | | @modelcontextprotocol/server-filesystem | 1.0.0 até 2.0.0 e versões de data até 2026.8.31 | 2.0.1 | | @modelcontextprotocol/server-everything | 1.0.0 a 2.0.0 e versões de data 2025.9.24 a 2026.8.31 | 2.0.1 | | mcp-server-fetch | através de 2026.10.19 | 2026.10.24 |

@modelcontextprotocol/server-filesystem 2.0.1

  • As escritas ficam dentro do diretório que foi verificado (Linux e macOS). Um diretório pai trocado por um link simbólico entre a verificação de acesso e a gravação não pode mais redirecionar write_file, edit_file, create_directory ou o destino move_file fora dos diretórios permitidos. No Windows isso foi corrigido apenas parcialmente; o comunicado diz o que ainda está exposto e como configurar em torno disso (GHSA-53mr-w429-c597)
  • Os caminhos são verificados exatamente como são usados. A verificação de acesso não remove mais aspas finais ou espaços em branco que a operação de arquivo mantém, portanto, um diretório irmão nomeado após um diretório permitido com esse sufixo não é mais acessível (GHSA-7rgq-gccq-qphx)
  • Um link simbólico escrito em letras maiúsculas diferentes não passa mais na verificação de link simbólico para um novo caminho em um volume que não diferencia maiúsculas de minúsculas, como o padrão do macOS. Esta foi uma regressão em 2026.8.31 (GHSA-4gxg-m5jx-9j57)
  • list_directory_with_sizes verifica cada entrada antes de ler seu tamanho, então um link simbólico dentro de um diretório permitido não revela mais o tamanho e o tempo de modificação de um arquivo fora dele (GHSA-hhwq-wxfx-cj7g)

@modelcontextprotocol/server-everything 2.0.1

  • Os transportes HTTP e SSE recusam solicitações de outras origens da web. Eles agora verificam o cabeçalho Origin e não enviam mais Access-Control-Allow-Origin: *, portanto, uma página da web que o usuário visita não pode mais chamar as ferramentas do servidor (como get-env) ou ler seus resultados (GHSA-mvf5-2qqv-rg3c)

mcp-server-fetch 2026.10.24

  • A verificação de endereço e a conexão usam o mesmo nome de host. Para um nome de host internacionalizado (IDNA), o servidor costumava verificar uma forma do nome e conectar-se a outra, que poderia alcançar um endereço interno (GHSA-v38p-wf49-hx2j)
  • Endereços NAT64 são julgados pelo endereço IPv4 que eles carregam. Um endereço em 64:ff9b::/96 que envolve um endereço IPv4 privado, de loopback ou de link local agora é recusado, como um endereço mapeado para IPv4 já era (GHSA-66qx-2266-pmj6)
  • robots.txt é verificado novamente após cada redirecionamento, não apenas para o primeiro URL solicitado (GHSA-3jqg-r5pp-rmp2)

Atualizando de uma versão npm com versão de data

Os servidores TypeScript passaram de versões de data (2025.x, 2026.x) para versões semânticas em 1.0.0. Os gerenciadores de pacotes classificam o 2.0.1 abaixo de todas as versões 2025.xe 2026.x, portanto, não o oferecerão como uma atualização. Se você estiver em uma versão datada, instale 2.0.1 explicitamente, por exemplo npm install @modelcontextprotocol/server-filesystem@2.0.1.

servers v2.1.0

Security fixes

v2.1.0 fixes eight vulnerabilities in three servers. Upgrade @modelcontextprotocol/server-filesystem and @modelcontextprotocol/server-everything to 2.0.1, and mcp-server-fetch to 2026.10.24.

| Package | Affected | Fixed in | | --- | --- | --- | | @modelcontextprotocol/server-filesystem | 1.0.0 through 2.0.0, and date versions through 2026.8.31 | 2.0.1 | | @modelcontextprotocol/server-everything | 1.0.0 through 2.0.0, and date versions 2025.9.24 through 2026.8.31 | 2.0.1 | | mcp-server-fetch | through 2026.10.19 | 2026.10.24 |

@modelcontextprotocol/server-filesystem 2.0.1

  • Writes stay inside the directory that was checked (Linux and macOS). A parent directory swapped for a symlink between the access check and the write can no longer redirect write_file, edit_file, create_directory or the move_file destination outside the allowed directories. On Windows this is only partly fixed; the advisory says what is still exposed and how to configure around it (GHSA-53mr-w429-c597)
  • Paths are checked exactly as they are used. The access check no longer strips a trailing quote or whitespace that the file operation keeps, so a sibling directory named after an allowed one with that suffix is no longer reachable (GHSA-7rgq-gccq-qphx)
  • A symlink spelled in a different letter case no longer passes the symlink check for a new path on a case-insensitive volume, such as macOS's default. This was a regression in 2026.8.31 (GHSA-4gxg-m5jx-9j57)
  • list_directory_with_sizes checks each entry before reading its size, so a symlink inside an allowed directory no longer reveals the size and modification time of a file outside it (GHSA-hhwq-wxfx-cj7g)

@modelcontextprotocol/server-everything 2.0.1

  • The HTTP and SSE transports refuse requests from other web origins. They now check the Origin header and no longer send Access-Control-Allow-Origin: *, so a web page the user visits can no longer call the server's tools (such as get-env) or read their results (GHSA-mvf5-2qqv-rg3c)

mcp-server-fetch 2026.10.24

  • The address check and the connection use the same host name. For an internationalized (IDNA) host name, the server used to check one form of the name and connect to another, which could reach an internal address (GHSA-v38p-wf49-hx2j)
  • NAT64 addresses are judged by the IPv4 address they carry. An address in 64:ff9b::/96 that wraps a private, loopback or link-local IPv4 address is now refused, as an IPv4-mapped one already was (GHSA-66qx-2266-pmj6)
  • robots.txt is checked again after every redirect, not only for the URL first requested (GHSA-3jqg-r5pp-rmp2)

Upgrading from a date-versioned npm release

The TypeScript servers moved from date versions (2025.x, 2026.x) to semantic versions in 1.0.0. Package managers rank 2.0.1 below every 2025.x and 2026.x version, so they won't offer it as an upgrade. If you are on a date version, install 2.0.1 explicitly, for example npm install @modelcontextprotocol/server-filesystem@2.0.1.
