servidores v2.4.0

Correções de segurança

v2.4.0 corrige seis vulnerabilidades em três servidores. Atualize @modelcontextprotocol/server-filesystem para 2.3.0, e mcp-server-git e mcp-server-fetch para 2026.11.11. | Pacote | Afetado | Corrigido em | | --- | --- | --- | | @modelcontextprotocol/server-filesystem | todas as versões anteriores a 2.3.0 e versões de data 2025.1.14 a 2026.8.31 | 2.3.0 | | mcp-server-git | através de 2026.11.4 | 2026.11.11 | | mcp-server-fetch | através de 2026.11.4 | 2026.11.11 |

@modelcontextprotocol/server-filesystem 2.3.0

  • As leituras ficam com o arquivo que foi verificado (Linux e macOS). As ferramentas de leitura e recursos de arquivo agora abrem um arquivo relativo ao diretório que foi verificado, como as gravações já faziam, portanto, um diretório trocado por um link simbólico entre a verificação de acesso e a leitura não pode mais retornar um arquivo de fora dos diretórios permitidos. Um FIFO, soquete ou dispositivo é recusado em vez de lido. No Windows isso estreita a corrida sem fechá-la, como para gravações (#5260) (GHSA-p9cv-8g75-4xcg)
  • move_file move apenas a fonte verificada. Uma movimentação dentro de um dispositivo primeiro retira a fonte de seu próprio diretório verificado com um novo nome, de modo que um diretório de origem trocado por um link simbólico não pode mais trazer um arquivo externo para os diretórios permitidos, onde se tornaria legível (GHSA-7m4x-rv66-mxhh)

mcp-server-git 2026.11.11

  • A própria configuração Git de um repositório não pode mais fazer o servidor executar um programa. Uma chamada somente leitura como git_status em um repositório untrusted usado para executar um comando nomeado em seu .git/config (core.fsmonitor, diff.external, ganchos, filtros e drivers de mesclagem, assinatura) com os privilégios do servidor. Cada comando Git agora substitui essas configurações, e um Git anterior a 2.31, que ignoraria as substituições, é recusado (GHSA-6hqx-gqrx-c5r2)
  • O confinamento de --repository cobre armazenamentos de objetos alternativos, árvores de trabalho vinculadas e links no diretório Git. Um repositório dentro do permitido pode ler os objetos de outro repositório por meio de objects/info/alternates ou passar o diretório Git de uma árvore de trabalho vinculada como o repositório permitido. Ambos são recusados, assim como um link simbólico em um diretório Git que leva para fora do repositório permitido. No Windows, uma junção de diretório ainda não é coberta (#5520) (GHSA-q74p-4wrc-q7w6)

mcp-server-fetch 2026.11.11

  • Os endereços locais do site IPv6 são privados. O protetor de endereço privado lê fec0::/10 como público. Agora é recusado, assim como qualquer endereço IPv6 fora do unicast global (2000::/3) que não carregue um endereço IPv4 (GHSA-3rxj-6jhw-qfv7)
  • robots.txt é comparado com o caminho que o site irá resolver, bem como o caminho conforme escrito, então //private ou /x/../private não podem mais passar de Disallow: /private (GHSA-f9hh-cmx9-2f23)

Atualizando de uma versão npm com versão de data

Os servidores TypeScript passaram de versões de data (2025.x, 2026.x) para versões semânticas em 1.0.0. Os gerenciadores de pacotes classificam o 2.3.0 abaixo de todas as versões 2025.xe 2026.x, portanto, não o oferecerão como uma atualização. Se você estiver em uma versão atualizada do @modelcontextprotocol/server-filesystem, instale 2.3.0 explicitamente: npm install @modelcontextprotocol/server-filesystem@2.3.0.

servers v2.4.0

Security fixes

v2.4.0 fixes six vulnerabilities in three servers. Upgrade @modelcontextprotocol/server-filesystem to 2.3.0, and mcp-server-git and mcp-server-fetch to 2026.11.11.

| Package | Affected | Fixed in | | --- | --- | --- | | @modelcontextprotocol/server-filesystem | all versions before 2.3.0, and date versions 2025.1.14 through 2026.8.31 | 2.3.0 | | mcp-server-git | through 2026.11.4 | 2026.11.11 | | mcp-server-fetch | through 2026.11.4 | 2026.11.11 |

@modelcontextprotocol/server-filesystem 2.3.0

  • Reads stay with the file that was checked (Linux and macOS). The read tools and file resources now open a file relative to the directory that was checked, as writes already did, so a directory swapped for a symlink between the access check and the read can no longer return a file from outside the allowed directories. A FIFO, socket or device is refused rather than read. On Windows this narrows the race without closing it, as for writes (#5260) (GHSA-p9cv-8g75-4xcg)
  • move_file moves only the source it checked. A move within one device first takes the source out of its own checked directory under a fresh name, so a source directory swapped for a symlink can no longer bring an outside file into the allowed directories, where it would become readable (GHSA-7m4x-rv66-mxhh)

mcp-server-git 2026.11.11

  • A repository's own Git configuration can no longer make the server run a program. A read-only call such as git_status on an untrusted repository used to run a command named in its .git/config (core.fsmonitor, diff.external, hooks, filter and merge drivers, signing) with the server's privileges. Every Git command now overrides those settings, and a Git older than 2.31, which would ignore the overrides, is refused (GHSA-6hqx-gqrx-c5r2)
  • --repository confinement covers alternate object stores, linked worktrees and links in the Git directory. A repository inside the allowed one could read another repository's objects through objects/info/alternates, or pass a linked worktree's Git directory off as the allowed repository's. Both are refused, as is a symlink in a Git directory that leads outside the allowed repository. On Windows a directory junction is not yet covered (#5520) (GHSA-q74p-4wrc-q7w6)

mcp-server-fetch 2026.11.11

  • IPv6 site-local addresses are private. The private-address guard read fec0::/10 as public. It is now refused, and so is any IPv6 address outside global unicast (2000::/3) that does not carry an IPv4 address (GHSA-3rxj-6jhw-qfv7)
  • robots.txt is matched against the path the site will resolve, as well as the path as written, so //private or /x/../private can no longer get past Disallow: /private (GHSA-f9hh-cmx9-2f23)

Upgrading from a date-versioned npm release

The TypeScript servers moved from date versions (2025.x, 2026.x) to semantic versions in 1.0.0. Package managers rank 2.3.0 below every 2025.x and 2026.x version, so they won't offer it as an upgrade. If you are on a date version of @modelcontextprotocol/server-filesystem, install 2.3.0 explicitly: npm install @modelcontextprotocol/server-filesystem@2.3.0.
