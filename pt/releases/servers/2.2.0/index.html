servidores v2.2.0

Segurança: tempo de execução Node.js e atualizações de certificado CA (outubro de 2026)

Em 20 de outubro de 2026, a eMudhra divulgou que as chaves privadas de oito de seus certificados de CA intermediários poderiam ser recuperadas dos certificados públicos. Em 21 de outubro, Node.js enviou [lançamentos de segurança] (https://nodejs.org/en/blog/vulnerability/october-2026-security-releases) que atualizam seus certificados CA agrupados para o comprometimento e corrigem vários CVEs de tempo de execução de alta gravidade não relacionados. Em 23 de outubro, certifi 2026.10.23 de Python removeu as raízes eMudhra emSign Root CA - C1 e emSign ECC Root CA - C3. Como estão esses servidores

  • Os servidores TypeScript dependem do tempo de execução Node.js para verificações de certificados. Eles não enviam certificados CA próprios. Somente server-everything faz solicitações HTTPS de saída (gzip-file-as-resource), e o Node.js em que ele é executado as verifica. server-filesystem, server-memory e server-sequential-thinking não fazem conexões de rede.
  • mcp-server-fetch verifica HTTPS em relação ao pacote certifi, por meio de httpx. A instalação a partir do PyPI (uvx mcp-server-fetch, pip install mcp-server-fetch) resolve o certifi, 2026.10.23 atual ou posterior. O arquivo fetch Docker do repositório é instalado a partir de seu arquivo de bloqueio, que esta versão move para certifi 2026.10.23 (#5341).
  • mcp-server-git e mcp-server-time não fazem conexões de rede. Se você executar um servidor TypeScript a partir do npm (npx ou uma instalação global) Ele roda no seu Node.js, que não podemos atualizar para você. Execute Node.js 24.22.1 ou 26.12.1, ou posterior e verifique com node --version. O campo engines dos pacotes aceita qualquer Node.js 24, então o npm não irá avisá-lo sobre um tempo de execução mais antigo e sem patch. Se você executar o mcp-server-fetch a partir de um ambiente existente Um ambiente criado antes de 23 de outubro mantém seu antigo certifi. Atualize-o com uvx --refresh mcp-server-fetch ou pip install -U certifi.

servers v2.2.0

Security: Node.js runtime and CA certificate updates (October 2026)

On October 20, 2026, eMudhra disclosed that the private keys for eight of its intermediate CA certificates could be recovered from the public certificates. On October 21, Node.js shipped security releases that update its bundled CA certificates for the compromise and fix several unrelated high-severity runtime CVEs. On October 23, Python's certifi 2026.10.23 removed the eMudhra roots emSign Root CA - C1 and emSign ECC Root CA - C3.

How these servers stand

  • The TypeScript servers rely on the Node.js runtime for certificate checks. They ship no CA certificates of their own. Only server-everything makes outbound HTTPS requests (gzip-file-as-resource), and the Node.js it runs on verifies them. server-filesystem, server-memory and server-sequential-thinking make no network connections.
  • mcp-server-fetch verifies HTTPS against the certifi bundle, through httpx. Installing from PyPI (uvx mcp-server-fetch, pip install mcp-server-fetch) resolves the current certifi, 2026.10.23 or later. The repository's fetch Dockerfile installs from its lockfile, which this release moves to certifi 2026.10.23 (#5341).
  • mcp-server-git and mcp-server-time make no network connections.

If you run a TypeScript server from npm (npx or a global install)

It runs on your Node.js, which we can't update for you. Please run Node.js 24.22.1 or 26.12.1, or later, and check with node --version. The packages' engines field accepts any Node.js 24, so npm won't warn you about an older, unpatched runtime.

If you run mcp-server-fetch from an existing environment

An environment created before October 23 keeps its older certifi. Refresh it with uvx --refresh mcp-server-fetch, or pip install -U certifi.
