#papelclip v2026.1106.0

Papelclip v2026.1106.0

Lançado: 2026-11-06

Paperclip v2026.1106.0 carrega 515 commits, promovidos de 2026.1023.0-beta.0. A manchete é que o Paperclip Runner agora é o padrão para novos agentes: os novos agentes Claude, Codex, OpenCode e Pi iniciam no Runner nativo em hosts macOS e Linux qualificados, os agentes existentes recebem uma ação de "Atualizar runner" de um click e o GitHub Copilot se junta como um equipamento nativo. Em torno disso: repositórios de projetos que se tornam automaticamente fontes de habilidades, prevenção de injeção de prompt apoiada por modelo, observabilidade do agente para Braintrust ou qualquer endpoint OTLP, uma conexão unificada do Google Workspace, edições em massa na lista de agentes, espaços de trabalho que compactam e expiram com pontos de restauração criptografados e Grok Bot e Muse como provedores experimentais de Runner. Por baixo, o relatório de reinicializações do servidor fica pronto mais cedo, a imagem Docker inicializa a partir de um pacote pré-compilado, as páginas de tarefas carregam mais rápido e mais serviços em segundo plano param de pesquisar o banco de dados.

Mudanças significativas

  • O experimento Pipelines foi removido. Quadros de pipeline, configurações de palco, automação de casos, filas de revisão, os comandos pipelines CLI, a permissão pipelines:write, a configuração enablePipelines e o campo linkedCases nos detalhes da tarefa desapareceram; Os casos e as rotinas permanecem. As tabelas e registros de pipeline existentes são preservados intactos e um valor enablePipelines armazenado é ignorado. (#16834)
  • As falhas de execução não atingem mais o Sentry por padrão. Um DSN de back-end sozinho não relata mais falhas de execução do agente. Configure PAPERCLIP_SENTRY_RUN_FAILURES=unexpected para manter a política filtrada anterior ou all para relatar cada execução com falha ou tempo limite esgotado; o padrão é off. (#16300)
  • A lista de histórico de execução é limitada. GET /api/companies/{companyId}/heartbeat-runs retorna 200 linhas por padrão e no máximo 1.000; clients que dependiam de uma matriz ilimitada devem passar um limit explícito. (#16286)
  • paperclipai agent instructions-file:delete requer --yes como os outros comandos destrutivos CLI; os scripts que o chamam devem adicionar o sinalizador. (#11504)

Destaques

  • O Paperclip Runner é o padrão — Novos agentes Claude no Apple Silicon, Intel macOS e Linux x64 (#15993, #15997), novos agentes Codex no Apple Silicon, Intel macOS, Linux x64 e Linux ARM64 (#15683) e novos agentes OpenCode e Pi no macOS e Linux x64 (#17120, #17142) agora iniciam no Runner nativo em vez do adaptador legado, através da integração, API e CLI, contratações, integrações, plug-ins e importações; O Linux precisa de GNU libc 2.39 ou posterior, uma substituição de "executor legado" reside em Avançado e os agentes existentes mantêm seu executor atual. Os agentes Claude e Codex existentes em alvos qualificados mostram uma ação Upgrade runner que os converte em um click, mantendo modelo, conta e instruções e listando quaisquer configurações que não puderam ser convertidas (#17122). Os agentes Claude Runner começam com suas principais ferramentas de tarefas pré-carregadas, medidas cerca de 20% mais rápidas em tarefas simples (#16885), carregam o nível de esforço escolhido por meio de currículos (#15994) e iniciam no Linux ARM64 (#16372).
  • Copiloto GitHub como chicote nativo — Conecte o Copiloto GitHub por meio de aplicativos/conexões AI com um token GitHub salvo; a lista de modelos do agente é descoberta na conta autenticada e o Copilot (CLI 1.0.88) é executado no Paperclip Runner com as mesmas instruções, permissão e limites de conclusão que os outros provedores nativos, incluindo o manifesto do provedor Linux necessário para sandboxes Daytona (#15705, #15701, #15706).
  • Repositórios de projetos tornam-se fontes de habilidades — Os repositórios GitHub anexados a um novo projeto são importados como fontes de habilidades automaticamente: Paperclip importa suas habilidades, verifica novamente a ramificação configurada a cada cinco minutos com a conexão GitHub da pessoa configurada e instala novas habilidades, a menos que seja excluído; os projetos existentes recebem uma ação "adotar repositórios" em Habilidades → Fontes, as atualizações automáticas podem ser pausadas, as habilidades derivadas do projeto herdam o acesso ao projeto e cada execução fixa as versões da habilidade com as quais começou (#16066). As importações mantêm todo o instantâneo do repositório no commit verificado para que as habilidades que dependem de scripts compartilhados ou habilidades irmãs funcionem após a entrega, listem cada habilidade com sua pasta e ignorem arquivos não suportados ou grandes com um aviso em vez de falharem (#15731, #16308). As fontes ganham um seletor de ramificação que carrega as ramificações do repositório, marca o padrão e valida a referência antes de salvar (#16288); uma fonte cuja ramificação rastreada desapareceu mostra uma ação de reparo de ramificação (#16256); cada fonte salva é listada uma vez com erros de atualização agrupados (#16310); e desconectar uma fonte realmente a remove, com uma opção de manter ou excluir para as habilidades importadas (#16150).
  • Prevenção de injeção de prompt baseada em modelo — Configurações → Conexões permite que um gerenciador de conexões escolha uma conexão e modelo OpenRouter compartilhado (padrão openai/gpt-oss-safeguard-20b) para classificar os resultados da ferramenta antes que cheguem a um agente, substituindo o veredicto de regex e permitindo código benigno que apenas parece um ataque; os custos aparecem em Custos e uma ação "Verificações do modelo de teste" verifica duas amostras fixas. Desligado até ser configurado. (#16976)
  • Observabilidade do agente para seu próprio back-end — Configurações da empresa → Geral → A observabilidade do agente envia logs e rastreamentos nativos do Codex e Claude Code para Braintrust (EUA) ou um endpoint HTTP OTLP personalizado, com credenciais mantidas em segredos da empresa e uma ação de teste; desativado por padrão (#16874). Braintrust também se junta ao catálogo de aplicativos com login nos EUA e na UE ou métodos de chave API (#17141).
  • Uma conexão unificada do Google Workspace — Uma entrada do Google Workspace substitui as configurações separadas de serviço do Google: escolha Gmail, Drive (Documentos, Planilhas, Apresentações) e Agenda, cada um opcionalmente somente leitura, e o consentimento e o acesso à ferramenta estão vinculados a essa seleção; As conexões existentes do Google continuam funcionando (#15545). O Gmail ganha um recurso de arquivamento opcional (#16331).
  • Espaços de trabalho que se limpam — Uma hora após o término de uma árvore de tarefas, o terminal-workspace reaper remove diretórios regeneráveis, como node_modules, dist e target que o próprio .gitignore do repositório ignora, mantendo a ramificação e todas as alterações de origem; o tempo de espera do arquivo cai de 7 dias para 1 (#16304). A expiração do cache Git opcional remove árvores de trabalho concluídas de propriedade do Paperclip e clones de base privados 24 horas após a conclusão da árvore de tarefas e os restaura no commit exato quando uma tarefa é reaberta (#16457, #16691); com pontos de restauração ativados, árvores de trabalho fechadas que ainda contêm confirmações não enviadas ou arquivos não confirmados são salvas primeiro em um ponto de restauração criptografado e restauradas exatamente quando o trabalho é retomado, problemas abertos ociosos são estacionados da mesma maneira após sete dias, verificações de vários repositórios aninhados obtêm seus próprios pontos de restauração e uma tarefa cujo ponto de restauração expirou reabre em um novo espaço de trabalho com uma nota em vez de falhar (#17248, #17271, #17257, #17269). Versões de habilidades materializadas não utilizadas são removidas a cada hora e reconstruídas sob demanda (#16433), e os backups de failover do lado do host de sessões de sandbox remota expiram uma semana após o encerramento dos problemas (#16866).
  • Tarefas com espaço de trabalho próprio — Uma tarefa que precisa de arquivos, mas não possui fonte configurada agora obtém um diretório estável de empresa/tarefa em vez de herdar a pasta inicial do agente, os agentes podem inspecionar, selecionar e solicitar repositórios para seu espaço de trabalho por meio de novas ferramentas de execução, e as conexões de bate-papo podem definir padrões de projeto e espaço de trabalho (#15749); uma nova tarefa obtém seu próprio clone quando o checkout padrão do projeto contém uma árvore de trabalho que o agente não pode ler (#16095), com uma nova tentativa de um click em um checkout limpo quando a configuração é bloqueada dessa forma (#16909).
  • Edições em massa na lista de agentes — Selecione linhas e filtre por chicote para alterar a conexão de IA, o modelo padrão ou ambos para vários agentes ao mesmo tempo, com uma visualização e nova tentativa para atualizações com falha; o seletor de status da lista é removido e os agentes pausados ​​mostram um emblema em vez de esmaecerem (#17215). A visão geral do agente mostra quem criou um agente em empresas com mais de uma pessoa (#16055).
  • Grok Bot e Muse, ambos experimentais — O Grok Bot permite que você convide um Grok Bot existente como um agente que recebe atribuições por meio de uma rotina de webhook e trabalha por meio de uma conexão MCP agente-OAuth dedicada, com configuração guiada, códigos de emparelhamento, progresso, perguntas, documentos e arquivos fluindo de volta para a tarefa e controles de parada e recuperação; os gastos do provedor não são relatados (#16219, #16338, #16274, #16305). O Muse emparelha um Meta Muse pessoal por meio de um receptor somente wake e OAuth apoiado pelo Vault com um tíquete de uso único de dez minutos, com prontidão, expiração de credencial e controles de desconexão na caixa de diálogo de convite (#16444, #16447, #16448, #16450).
  • Fale com um agente com Speko — Uma entrada Speko no catálogo de aplicativos conecta uma persona Speko a um agente existente para que você possa falar com ele por voz do navegador ou telefone a partir de uma tarefa, com transcrições, controles de chamada, configurações de linha de entrada, retornos de chamada telefônica e entradas de chamada em Atividade; mostrado enquanto a configuração experimental Conectores de bate-papo está ativada (#15728).
  • Slack bots, refinados — As configurações de conexão do Slack são simplificadas em torno de "Configuração aberta do Slack" e uma linha "Enviar mensagem de teste", com "Use seu próprio aplicativo" em Avançado (#15679); mensagens diretas simples sempre iniciam ou continuam funcionando mesmo quando Exigir menção está ativado para threads de canal (#16151); e a reação dos olhos aparece assim que uma menção é aceita, inclusive em mensagens diretas (#16491, #16494).
  • Um bot de revisão GitHub mais robusto — O bot mantém um comentário principal de PR atualizado entre pushes, ignora mensagens endereçadas a outros bots e marca o trabalho interrompido com precisão (#16901); comentários resumidos são encabeçados com o nome de exibição do bot para que vários bots em um PR sejam distinguíveis (#16212); a publicação tenta novamente por meio de GitHub 503/429 com espera limitada e sobrevive às reinicializações sem comentários ou verificações duplicadas (#16284, #16883); As ferramentas de bot GitHub obtêm o máximo de 60 segundos do gateway para que submit_review não expire mais (#16275); e as configurações mostram um aviso "Reconectar GitHub" com reconectar o aplicativo salvo como a primeira opção (#16856).
  • Mais aplicativos no catálogo — Daytona, com credenciais de chave API pessoais ou compartilhadas e 274 ações geradas para sandboxes, snapshots, volumes, arquivos, Git e comandos (#16483); Unikraft Cloud, com ações geradas a partir de suas especificações OpenAPI e um metro padrão por conexão (#17139); e idem (#16472). Uma placa de provedor com diversas conexões as recolhe atrás de uma linha "N conexões" (#16097).
  • Comentários do agente na auditoria — As reclamações e sugestões que os agentes registram sobre suas ferramentas agora têm um local: a auditoria ganha uma guia Comentário com filtros de tipo e agente, pesquisa de texto, paginação e links compartilháveis ​​(#16884), legíveis por todas as funções humanas por meio de uma nova permissão commentary:view (#16903).

Correções

  • Espaços de trabalho e sandboxes — Um sandbox remoto cuja execução falhou antes da exportação, cuja locação foi limpa com trabalho não exportado ou cuja tarefa foi cancelada antes da reconstrução é mantida com seus arquivos atrás de uma decisão de reparo explícita em vez de ser excluída pela limpeza (#16397, #16583, #16700); uma tarefa cuja sandbox foi destruída antes da exportação oferece uma ação "Continuar a partir de fontes salvas" somente no quadro (#16690); os arquivos deixados na sandbox de uma execução interrompida são recuperados automaticamente e os acompanhamentos salvos são entregues uma vez (#16906); uma exportação de espaço de trabalho em tempo de desligamento mantém sua propriedade através do dreno do finalizador (#16843); um copy-back longo não perde mais seu bloqueio no tempo limite de transação ociosa do PostgreSQL (#16340, #16956); retomar uma sandbox reutilizável interrompida respeita o tempo limite de inicialização do ambiente em vez de 60 segundos fixos (#16802); uma única verificação de integridade expirada não substitui mais um Runner remoto (#16835); é executado em repositórios com milhares de espaços de trabalho históricos que não ficam mais "preparados" por horas (#16372, #16334, #16342, #16963); um checkout compartilhado não fica mais bloqueado por um leitor cuja identidade desapareceu (#16928) e um espaço de trabalho bloqueado pela árvore de trabalho restrita de outra tarefa recebe um aviso de configuração claro em vez de um 403 opaco (#16545, #16895); uma tarefa filha que herda um espaço de trabalho compartilhado ocupado aguarda em vez de falhar com um erro de segredos enganoso (#16371); e criar uma tarefa com o seletor de isolamento oculto não falha mais na configuração (#16220).
  • Execuções, recuperação e nova tentativa — Tarefas mantidas atrás de um espaço de trabalho retido ou retenção de execução com falha obtêm uma nova tentativa confiável em nível de tarefa que preserva arquivos, estabelece resultados aceitos ou inicia um espaço de trabalho independente (#16965, #17053, #16894, #16104); Parar impede a continuação automática até que você retome (#17105, #14180); uma reinicialização do servidor não impede mais execuções nativas em retenções permanentes, repete conclusões salvas ou substitui paradas de operador definidas nesse meio tempo (#16349, #16962, #16403, #15824); execuções legadas interrompidas ou perdidas no arrendamento antes do envio são repetidas em vez de liquidadas como com falha (#16355, #16358), uma conclusão lenta não falha mais em um controlador ativo (#16622), e consultas lentas não relacionadas não custam mais execuções legadas de seu arrendamento (#17032); um comentário normal em uma tarefa em andamento não cancela mais sua nova tentativa de execução (#16855) e interromper uma execução na fila antes de começar mantém seu acompanhamento salvo em vez de executá-la de qualquer maneira (#16357); mensagens para agentes pausados ​​ou para um agente que não seja o proprietário da tarefa são entregues uma vez em vez de falharem ou serem adiadas para sempre (#16679, #16673); um agente travado marcado como "em execução" é reparado após um período de carência de cinco minutos (#16791); uma execução de Claude (ACP) com uma chamada de ferramenta paralisada falha após 30 minutos em vez de atingir o tempo limite de quatro horas, e as chamadas MCP obtêm um tempo limite de 15 minutos (#16671, #16360); uma exaustão de giro máximo não é mais classificada erroneamente como um modelo ausente (#13885); e uma resposta de "modelo em capacidade" do Codex é tentada novamente como transitória (#16407).
  • IU de bate-papo e tarefas — Dispensar uma solicitação acima do compositor limpa o selo, sobrevive à recarga e não bloqueia mais Nova tentativa (#17218); uma mensagem para um agente Runner não troca mais brevemente seu avatar por uma linha genérica "Trabalhando" (#16989); um acompanhamento consumido sai da fila pendente (#16317); a resposta final de uma tarefa da árvore de trabalho não é mais substituída pelo aviso de "espaço de trabalho pronto" (#16400); um arquivo anexado antes da primeira mensagem do Agent Chat sobreviver à criação da tarefa (#16896); brindes de tarefas em uma empresa multiusuário aparecem apenas para pessoas envolvidas na tarefa (#16153); carregar uma lista de tarefas não adiciona mais tarefas concluídas não relacionadas à sua caixa de entrada (#16063); as respostas são padronizadas para o agente mais recente que atribuiu a tarefa a você (#15594); as abas do painel lateral mantêm uma largura constante (#17068, #14949); Os editores de Markdown não mostram mais alterações não salvas no carregamento (#13915); e uma tarefa do Slack que resulta em uma continuação agendada retorna seu resultado ao thread original (#17045).
  • Custos e orçamentos — Um orçamento em seu limite de aviso é renderizado como um aviso em vez de um banner falso "AGENT HARD STOP" (#16201), e as verificações de orçamento não são mais escalonadas com o número de agentes ociosos não relacionados na empresa (#17046).
  • Conexões e MCP — Uma chamada remota de MCP com falha não torna mais todas as ferramentas irmãs nessa conexão indisponíveis (#16890); um provedor 403 em uma operação de chat não desativa mais toda a conexão Slack, GitHub ou Discord (#16847, #16138); As ferramentas de canal GitHub e Slack permanecem disponíveis em execuções posteriores da mesma tarefa (#16806); várias respostas do tópico de revisão do GitHub recebem, cada uma, sua própria execução de acompanhamento (#17054) e descritores de ferramentas idênticos são listados uma vez (#16281); uma grande atualização do catálogo MCP não lista mais uma ferramenta duas vezes ou trava com um retorno de chamada OAuth (#16602); resultados de ferramentas atribuídos com mais de 500 KB retornam uma referência limitada e uma ferramenta read_tool_result em vez de suspensa (#16980); comandos legados do shell do Codex podem ver segredos de serviço atribuídos explicitamente (#17216); o executor nativo call_api segue as próprias permissões da rota sem uma lista de bloqueios extra (#16040); e agentes em sandbox podem ler histórico de execução, anexos, arquivos de habilidades e registros de recuperação e enviar o token de ponte como X-API-Key (#16575, #16892, #12785).
  • Adaptadores e CLI — Uma execução ilimitada de Claude não falha mais em sua sonda CLI após um segundo (#15329); execuções remotas simultâneas de Claude de um agente não interrompem mais a preparação de habilidades um do outro (#17061); uma tarefa isolada de Claude com ferramentas MCP atribuídas é iniciada (#17149); um sandbox cujo Claude CLI pré-instalado é mais antigo do que o modelo selecionado precisa, obtém a versão necessária instalada de forma privada durante a configuração, em vez de falhar na verificação de versão (#17259); uma instalação do servidor Claude (ACP) não falha mais porque a ponte ACP estava faltando no pacote do servidor (#15912); um turno do Runner OpenCode sobrevive a eventos SSE superdimensionados (#16401) e usa as credenciais GitHub gerenciadas da execução em comandos shell (#16488); Hermes chama de volta na URL API configurada do adaptador (#9425); Os logs de execução do pi_local são cerca de 150× menores (#10249); paperclipai install e update funcionam com npm 12 e Nó 26 (#14000); paperclipai service install não escreve mais um serviço que trava em loop em um shim gerenciado ausente (#13985); e o login do navegador CLI respeita os cabeçalhos Retry-After com limite de taxa (#16482).
  • Servidor e Docker — A inicialização não falha mais em bancos de dados SQL_ASCII legados (#16958) ou trava em um publicBaseUrl sem esquema (#13727); um servidor atrás de um proxy reverso com pesquisas de PTR lentas não para mais de responder por minutos após a atualização (#16333, #16335); uma conexão em pool descartada não falha mais nas verificações de permissão, na prontidão do espaço de trabalho ou no reaper (#16857, #16859); Docker inicializa com muitos arquivos no volume de dados ou um USER_UID/USER_GID não padrão não percorre mais todo o volume (#15992, #16475); ambos enviaram arquivos do Compose para frente PAPERCLIP_TOOL_ACTION_SIGNING_SECRET (#15202); uma parada que dura mais que a sincronização retorna um 409 repetível em vez de 500 (#16032); edições simultâneas de títulos de tarefas não são mais 500 (#13898); um ID de comentário malformado não bloqueia mais os despertares na fila de uma tarefa (#13912); watchdog wakes entrega as instruções do operador (#13771); o limite de tarefa filho conta apenas filhos abertos (#11542); um agente de pulsação simples pode comentar as tarefas novamente (#12621); uma transferência humana de uma execução herdada não é mais cancelada por uma restauração lenta (#16082); e as exportações de feedback mantêm os identificadores públicos legíveis enquanto ainda mascaram tokens reais (#16168).

Melhorias

  • Os casos experimentais mantêm uma tarefa principal nas transferências de agentes com um registro de transferência durável, ferramentas nativas create_case, read_case, update_case e handoff_case, páginas de caso somente leitura e prompts de fluxo de trabalho nomeados reutilizáveis que um caso adota no início ou na transferência (#16959, #17114).
  • Uma verificação do ciclo de vida do agente com falha nomeia a etapa com falha e uma ação corretiva (#16418), e a integração cria o registro do agente assim que você envia seu nome, portanto, a configuração e as novas tentativas mantêm uma identidade (#17005).
  • Os plug-ins podem assinar eventos confirmados do ciclo de vida do projeto e do agente com repetição em vez de pesquisa (#16203); receber alterações de configuração, instrução, habilidade, conexão, ferramenta e concessão do agente por meio de ganchos de tempo de execução duráveis ​​(#16499, #16501, #16603, #16604, #16605); armazenar segredos de instância de propriedade do agente e do projeto no armazenamento secreto criptografado (#16191, #17034); possuir armazenamento de projeto e espaços de trabalho de tarefas, atuar como o provedor de espaço de trabalho padrão e executar tarefas nativas do Runner em ambientes de propriedade do plug-in verificados pelo teste de ambiente do agente (#17001, #17247, #16978, #17029, #17252, #15406); e declarar rotas WebSocket autenticadas e visualizações de detalhes do agente (#17111).
  • Mais trabalho em segundo plano aguarda gravações confirmadas e prazos conhecidos em vez de pesquisar o banco de dados: manutenção de telegrama (#16094), limpeza do espaço de trabalho do terminal (#16282), limpeza de login (#17106), recuperação de controle de execução (#17094), assinaturas de eventos MCP (#17036) e sincronização de fonte de habilidade (#17008); rotinas e monitores de tarefas são acionados no prazo salvo, em vez de aguardar a próxima varredura (#16514).

Paperclip v2026.1106.0

Released: 2026-11-06

Paperclip v2026.1106.0 carries 515 commits, promoted from 2026.1023.0-beta.0. The headline is that the Paperclip Runner is now the default for new agents: new Claude, Codex, OpenCode, and Pi agents start on the native Runner on qualified macOS and Linux hosts, existing agents get a one-click "Upgrade runner" action, and GitHub Copilot joins as a native harness. Around that: project repositories that automatically become skill sources, model-backed prompt injection prevention, agent observability to Braintrust or any OTLP endpoint, a unified Google Workspace connection, bulk edits on the Agents roster, workspaces that compact and expire themselves with encrypted restore points, and Grok Bot and Muse as experimental Runner providers. Underneath, server restarts report ready sooner, the Docker image boots from a precompiled bundle, task pages load faster, and more background services stop polling the database.

Breaking Changes

  • The Pipelines experiment is removed. Pipeline boards, stage settings, case automation, review queues, the pipelines CLI commands, the pipelines:write permission, the enablePipelines setting, and the linkedCases field on task detail are gone; Cases and Routines remain. Existing pipeline tables and records are preserved untouched and a stored enablePipelines value is ignored. (#16834)
  • Run failures no longer reach Sentry by default. A backend DSN alone no longer reports agent run failures. Set PAPERCLIP_SENTRY_RUN_FAILURES=unexpected to keep the previous filtered policy or all to report every failed or timed-out run; the default is off. (#16300)
  • The run history list is bounded. GET /api/companies/{companyId}/heartbeat-runs returns 200 rows by default and at most 1,000; clients that relied on an unbounded array must pass an explicit limit. (#16286)
  • paperclipai agent instructions-file:delete requires --yes like the other destructive CLI commands; scripts that call it must add the flag. (#11504)

Highlights

  • The Paperclip Runner is the default — New Claude agents on Apple Silicon, Intel macOS, and Linux x64 (#15993, #15997), new Codex agents on Apple Silicon, Intel macOS, Linux x64, and Linux ARM64 (#15683), and new OpenCode and Pi agents on macOS and Linux x64 (#17120, #17142) now start on the native Runner instead of the legacy adapter, across onboarding, the API and CLI, hires, built-ins, plugins, and imports; Linux needs GNU libc 2.39 or later, a "Legacy runner" override lives under Advanced, and existing agents keep their current runner. Existing Claude and Codex agents on qualified targets show an Upgrade runner action that converts them in one click, keeping model, account, and instructions and listing any settings that could not be converted (#17122). Claude Runner agents start with their core task tools preloaded, measured about 20% faster on simple tasks (#16885), carry the chosen effort level through resumes (#15994), and start on Linux ARM64 (#16372).
  • GitHub Copilot as a native harness — Connect GitHub Copilot through Apps / AI Connections with a saved GitHub token; the agent's model list is discovered from the authenticated account, and Copilot (CLI 1.0.88) runs through the Paperclip Runner with the same instruction, permission, and completion boundaries as the other native providers, including the Linux provider manifest needed for Daytona sandboxes (#15705, #15701, #15706).
  • Project repositories become skill sources — GitHub repositories attached to a new project are imported as skill sources automatically: Paperclip imports their skills, re-checks the configured branch every five minutes with the setup person's GitHub connection, and installs new skills unless excluded; existing projects get an "adopt repositories" action in Skills → Sources, automatic updates can be paused, project-derived skills inherit project access, and each run pins the skill versions it started with (#16066). Imports keep the whole repository snapshot at the scanned commit so skills that depend on shared scripts or sibling skills work after delivery, list every skill with its folder, and skip unsupported or oversized files with a warning instead of failing (#15731, #16308). Sources gain a branch picker that loads the repository's branches, marks the default, and validates the ref before saving (#16288); a source whose tracked branch disappeared shows a branch repair action (#16256); each saved source is listed once with grouped refresh errors (#16310); and disconnecting a source really removes it, with a keep-or-delete choice for the imported skills (#16150).
  • Model-backed prompt injection prevention — Settings → Connections lets a connection manager pick a shared OpenRouter connection and model (default openai/gpt-oss-safeguard-20b) to classify tool results before they reach an agent, replacing the regex verdict and allowing benign code that merely looks like an attack; costs appear in Costs, and a "Test model checks" action verifies two fixed samples. Off until configured. (#16976)
  • Agent observability to your own backend — Company Settings → General → Agent observability sends native Codex and Claude Code logs and traces to Braintrust (US) or a custom OTLP HTTP endpoint, with credentials held in company secrets and a test action; off by default (#16874). Braintrust also joins the Apps catalog with US and EU sign-in or API-key methods (#17141).
  • A unified Google Workspace connection — One Google Workspace entry replaces the separate Google service setups: pick Gmail, Drive (Docs, Sheets, Slides), and Calendar, each optionally read-only, and consent and tool access are bound to that selection; existing Google connections keep working (#15545). Gmail gains an opt-in archive capability (#16331).
  • Workspaces that clean up after themselves — One hour after a task tree finishes, the terminal-workspace reaper removes regenerable directories such as node_modules, dist, and target that the repository's own .gitignore ignores, keeping the branch and all source changes; the archive cooldown drops from 7 days to 1 (#16304). Opt-in Git cache expiration removes finished Paperclip-owned worktrees and private base clones 24 hours after the task tree is done and restores them at the exact commit when a task reopens (#16457, #16691); with restore points on, closed worktrees that still hold unpushed commits or uncommitted files are saved to an encrypted restore point first and restored exactly when work resumes, idle open issues are parked the same way after seven days, nested multi-repository checkouts get their own restore points, and a task whose restore point has expired reopens on a fresh workspace with a note instead of failing (#17248, #17271, #17257, #17269). Unused materialized skill versions are removed hourly and rebuilt on demand (#16433), and host-side failover backups of remote-sandbox sessions expire a week after their issues close (#16866).
  • Tasks with their own workspace — A task that needs files but has no configured source now gets a stable company/task directory instead of inheriting the agent's home folder, agents can inspect, select, and request repositories for their workspace through new runner tools, and chat connections can set project and workspace defaults (#15749); a fresh task gets its own clone when the project's default checkout contains a worktree the agent cannot read (#16095), with a one-click Retry on a clean checkout when setup is blocked that way (#16909).
  • Bulk edits on the Agents roster — Select rows and filter by harness to change the AI connection, the default model, or both for many agents at once, with a preview and retry for failed updates; the roster's status selector is removed and paused agents show a badge instead of dimming (#17215). The agent Overview shows who created an agent in companies with more than one person (#16055).
  • Grok Bot and Muse, both experimental — Grok Bot lets you invite an existing Grok Bot as an agent that receives assignments through a webhook routine and works through a dedicated agent-OAuth MCP connection, with guided setup, pairing codes, progress, questions, documents, and files flowing back into the task, and Stop and recovery controls; provider spending is not reported (#16219, #16338, #16274, #16305). Muse pairs a personal Meta Muse through a wake-only receiver and Vault-backed OAuth with a ten-minute single-use ticket, with readiness, credential expiry, and disconnect controls in the invite dialog (#16444, #16447, #16448, #16450).
  • Talk to an agent with Speko — A Speko entry in the Apps catalog connects a Speko persona to an existing agent so you can talk to it by browser voice or phone from a task, with transcripts, call controls, inbound-line settings, phone callbacks, and call entries in Activity; shown while the Chat connectors experimental setting is on (#15728).
  • Slack bots, refined — Slack connection Settings are simplified around "Open Slack configuration" and a "Send test message" row, with "Use your own app" under Advanced (#15679); plain direct messages always start or continue work even when Require at-mention is on for channel threads (#16151); and the eyes reaction appears as soon as a mention is accepted, including in direct messages (#16491, #16494).
  • A sturdier GitHub review bot — The bot keeps one main PR comment updated across pushes, ignores messages addressed to other bots, and marks stopped work accurately (#16901); summary comments are headed with the bot's display name so several bots on one PR are distinguishable (#16212); publication retries through GitHub 503/429 with bounded backoff and survives restarts without duplicate comments or checks (#16284, #16883); GitHub bot tools get the gateway's 60-second maximum so submit_review no longer times out (#16275); and settings show a "Reconnect GitHub" notice with reconnect-the-saved-App as the first option (#16856).
  • More apps in the catalog — Daytona, with personal or shared API-key credentials and 274 generated actions for sandboxes, snapshots, volumes, files, Git, and commands (#16483); Unikraft Cloud, with actions generated from its OpenAPI specs and a per-connection default metro (#17139); and Ditto (#16472). A provider card with several connections collapses them behind an "N connections" row (#16097).
  • Agent commentary in Audit — The complaints and suggestions agents file about their tooling now have a home: Audit gains a Commentary tab with agent and type filters, text search, paging, and shareable links (#16884), readable by every human role through a new commentary:view permission (#16903).

  • Experimental Cases keep one primary task across agent handoffs with a durable handoff ledger, native create_case, read_case, update_case, and handoff_case tools, read-only case pages, and reusable named workflow prompts a case adopts at kickoff or on handoff (#16959, #17114).
  • A failed agent-lifecycle verification names the failed step and a corrective action (#16418), and onboarding creates the agent record as soon as you submit its name, so setup and retries keep one identity (#17005).
  • Plugins can subscribe to committed project and agent lifecycle events with replay instead of polling (#16203); receive agent configuration, instruction, skill, connection, tool, and grant changes through durable runtime hooks (#16499, #16501, #16603, #16604, #16605); store agent- and project-owned instance secrets in the encrypted secret store (#16191, #17034); own project storage and task workspaces, act as the default workspace provider, and run native Runner tasks in plugin-owned environments verified by the agent environment test (#17001, #17247, #16978, #17029, #17252, #15406); and declare authenticated WebSocket routes and agent detail views (#17111).
  • More background work waits for committed writes and known deadlines instead of polling the database: Telegram maintenance (#16094), terminal workspace cleanup (#16282), login cleanup (#17106), execution-control recovery (#17094), MCP event subscriptions (#17036), and skill-source sync (#17008); routines and task monitors fire at their saved deadline instead of waiting for the next scan (#16514).
  • Faster starts everywhere: the server reports ready sooner after a restart because housekeeping runs after readiness and settled finalizations are skipped (#16329, #16485, #16328); the Docker image boots from a precompiled runtime bundle, cutting code-load time from up to 24 seconds to under 4 (#16672); task pages load lazily, defer hidden rendering, and refresh the recent-tasks sidebar through one bounded request (#16849, #16878, #16851, #16862); and agent launches overlap GitHub, skill, tool, and sandbox preparation, reuse a per-company Git object cache and verified sandbox image files, and make far fewer database and Daytona calls (#16620, #16608, #16585, #16487, #16687, #16493, #16683, #16536, #16521, #16527, #16561, #16468, #16480, #16552, #16484, #16473, #16425, #16424, #16461, #16498, #16576, #16569, #16414, #17026).
  • Tasks, project lists, inbox discovery, and Blocked hide agent- and system-created tasks by default behind a "show agent-created tasks" filter saved per company (#16157), and Inbox "Mine" excludes channel, routine, and agent-created tasks unless you commented, were assigned, or have an open request (#16356); failure notices show only the latest error with its retry action (#16982); and an expired connection request card says what is still not connected (#14067).
  • An experimental Artifacts V1 presentation shows paper stacks and tiles on the Artifacts page, compact rows in the panel, and grouped rows in the thread (#17228); you can upload files directly in the Artifacts panel by icon or drag-and-drop without sending a message (#15964); the offline recovery page matches the app (#16904); the "Run with provider trace" header button is replaced by the agent's Debugging configuration (#17211); and an app's Access tab shows linked users' photos (#15577).
  • Adding a repository skill to an agent no longer stalls on a full library read (#16899), and invalid arguments to assigned tools, call_api, and set_task_monitor return schema locations and repair guidance (#16905, #16889, #16868, #16961).
  • paperclip_runner agents can set homeMode: "preconfigured" to run native Codex or ACPX Claude with the execution account's existing login, skills, and MCP configuration (#16486); the Runner reports refreshed OAuth credentials without token values crossing the protocol (#16463) and can register verified session-local stdio MCP servers on Unix (#16526); the task PATCH API accepts expectedStatusVersion for backlog-to-todo promotion (#16893); and an anonymous GET /api/liveness reports process liveness without touching the database (#16101).
  • Failure reports record why an OpenCode turn fails when its server stops (#16863); Sentry reports for run failures link to the task and run pages, skip classified provider quota limits, and report a native retry only when the retry ends (#16803, #16029, #16865); due task monitors held by recovery record why in the task activity (#16891); and, when an OTLP endpoint is configured, traces gain spans for controller preparation, execution configuration, workspace and connector preparation, and finalization (#16178, #16236, #16419, #16428, #16454, #16515).

Upgrade Guide

  • Migrations 0334–0374 run on upgrade. Additive schema: 0334, 0341, and 0342 repository skill snapshots, project_skill_sources, and import budgets; 0335 chat_slack_manager_grants and its link from Slack registrations; 0336–0338 execution workspace repository tables; 0339 and 0370 agent-, plugin-, and project-owned company_secrets; 0344 and 0346 Grok Bot tables; 0349–0353 Muse tables; 0357 company_observability; 0362 prompt injection prevention tables; 0363–0368 and 0371 case handoff and workflow tables; 0372–0374 execution_workspace_restore_points; 0373 interaction dismissal columns. Constraint rewrites: 0340 allows delete as a lifecycle-event action; 0361 allows github as an AI default provider. Triggers: 0347, 0348, and 0354–0356 install runtime-invalidation triggers on agents, skills, connections, grants, memberships, and secrets; 0358 bumps issues.status_version on assignee change; 0372 expires restore points when issues close. Row updates: 0343 backfills agents.created_by_user_id from the activity log; 0347 seeds one agent_runtime event per active agent; 0359 grants commentary:view to every active human membership; 0363 backfills case_access_sources. Indexes: 0360 adds a partial index for retained-workspace recovery; 0345 and 0369 are built CONCURRENTLY outside a transaction and are safe to rerun if interrupted. Expect 0343, 0345, and 0369 to take longer on instances with large run histories, and the check-constraint rewrites in 0339, 0362, and 0370 to scan company_secrets, budget_reservations, and cost_events.
  • New agents default to the Paperclip Runner (#15993, #15997, #15683, #17120, #17142): on qualified hosts (Apple Silicon, Intel macOS, Linux x64 with glibc 2.39+, and Linux ARM64 for Codex), new Claude, Codex, OpenCode, and Pi agents are created on the native Runner regardless of the enableNativeRunner setting. Existing agents are unchanged; choose "Legacy runner" under Advanced to opt a new agent out, or use Upgrade runner on an existing agent's configuration to convert it (#17122).
  • New environment variables, none required. Workspace cleanup: PAPERCLIP_WORKSPACE_COMPACTION_ENABLED (on unless exactly false) and PAPERCLIP_WORKSPACE_COMPACTION_DELAY_HOURS (default 1) control removal of regenerable files from finished task worktrees, and PAPERCLIP_WORKSPACE_REAPER_COOLDOWN_DAYS now defaults to 1 instead of 7 (#16304); PAPERCLIP_GIT_CACHE_EXPIRATION_ENABLED and PAPERCLIP_GIT_BASE_EXPIRATION_ENABLED (default false) with PAPERCLIP_GIT_CACHE_EXPIRATION_DRY_RUN (default true) opt into expiring finished worktrees and base clones (#16457); PAPERCLIP_GIT_RESTORE_POINTS_ENABLED (default false) with PAPERCLIP_GIT_RESTORE_POINT_TERMINAL_DELAY_DAYS (default 3), PAPERCLIP_GIT_RESTORE_POINT_IDLE_DAYS (default 7, 0 disables), and PAPERCLIP_GIT_RESTORE_POINT_RETENTION_DAYS (default 90) govern encrypted restore points (#17248, #17271, #17241); PAPERCLIP_SKILL_VERSION_RETENTION_ENABLED (default true) with _DRY_RUN (false), _KEEP (0), and _GRACE_MINUTES (60) prunes unused materialized skill versions (#16433); PAPERCLIP_NATIVE_HARNESS_BACKUP_EXPIRATION_ENABLED (default true) with _DAYS (7) and _DRY_RUN (false) expires remote-session failover backups, so reopening an issue closed longer than that window starts a fresh provider session (#16866). Reporting: PAPERCLIP_SENTRY_RUN_FAILURES (off, unexpected, or all; default off) (#16300). Claude agents also honor an existing ANTHROPIC_BASE_URL and ANTHROPIC_CUSTOM_HEADERS (#16850).
  • New experimental settings, all off by default: Grok Bot (enableGrokBot), which requires Assistant connections (MCP), the Paperclip Runner, authenticated sign-in, and an HTTPS PAPERCLIP_PUBLIC_URL (#16219); Muse — Personal agent (enableMuse), which requires the Runner and public HTTPS (#16450); Artifacts V1 (enableArtifactsV1) (#17228). Speko voice appears under the existing Chat connectors setting (#15728) and workflows under Cases (#17114). enablePipelines is removed (#16834). Settings → Connections is now always visible and no longer depends on Experimental fast responses (#16976).
  • commentary:view for every human role (#16903): migration 0359 and startup seeding grant the new permission to every active human membership, including viewers, so anyone in the company can open Audit → Commentary. Deleting that grant from a member is temporary: startup seeding re-adds every role-default grant for each active human member on the next server start, and this release has no durable way to withhold it. Source-task privacy still filters what each person sees in commentary.
  • Sentry operators (#16300): set PAPERCLIP_SENTRY_RUN_FAILURES=unexpected to keep receiving run-failure events; they are off by default even with SENTRY_DSN_BACKEND configured.
  • API clients: the run history list is capped at 1,000 rows (default 200) (#16286); the linkedCases field and all Pipeline routes are gone (#16834); a PATCH that replaces executionPolicy and sets done during a live review cycle returns 422 unexecuted_review_stage (#13178); and anything parsing GitHub review summary headings must accept bot names (#16212).
  • Custom Docker images (#16672): the shipped image now starts with node server/dist-runtime/index.mjs; images that invoked server/dist/index.js through tsx should switch to the runtime bundle.
  • Default views change: agent- and system-created tasks are hidden from task lists until you enable "show agent-created tasks" (#16157), and Inbox "Mine" no longer includes automation you did not take part in (#16356).
  • Google Workspace (#15545): new Google Workspace requests depend on the Paperclip-hosted OAuth broker update, and older brokers reject them; existing per-service Google connections keep working.
  • Harness pins are unchanged from v2026.1023.0: Codex 0.160.0, Claude Agent SDK 0.3.286 (Claude Code 2.1.286), and OpenCode 1.18.34. GitHub Copilot ships at CLI 1.0.88 (#15701).
  • No other configuration or API changes require action.
