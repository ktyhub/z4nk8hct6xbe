ktransformadores v0.6.3

KTransformers: Suporte MiniMax-M3 e GLM-5.2 Dia 0

Temos o prazer de anunciar o suporte Day0 para dois novos modelos grandes de MoE: MiniMax-M3 e GLM-5.2 em KTransformers + SGLang (sglang-kt). Ambos os modelos estão agora disponíveis para inferência heterogênea CPU-GPU via kt-kernel. Esta atualização também fornece KT LoRA de ponta a ponta servindo para Qwen3.5 MoE.

🚀 Destaques principais

  • Suporte MiniMax-M3 Day0: Suporte completo de inferência para a arquitetura MoE esparsa de especialistas com 128 rotas do MiniMax (MiniMaxAI/MiniMax-M3-MXFP8). Funciona em uma única GPU de 96 GB ou pode ser dimensionado para 8×GPU com descarregamento especializado de CPU kt-kernel.
  • Suporte GLM-5.2 Day0: suporte completo de inferência para GLM-5.2 da Zhipu AI (zai-org/GLM-5.2, zai-org/GLM-5.2-FP8), com precisão FP8 e BF16, back-end de atenção da NSA e atualizações dinâmicas de especialistas via kt-kernel.
  • Serviço KT LoRA: fluxo de trabalho de atendimento Qwen3.5 MoE KT LoRA de ponta a ponta — treine com KT SFT, converta uma vez, atenda por meio de SGLang com um único caminho de adaptador mesclado.

📌 KT LoRA servindo para Qwen3,5 MoE

Um novo fluxo de trabalho completo de ajuste fino para veiculação para Qwen3.5 MoE com LoRA, especialista em KT:

  • Pipeline do adaptador unificado: saída bruta KT SFT → convert_kt_to_sglang_adapter.py → diretório do adaptador mesclado → serviço SGLang --lora-paths.
  • **LoRA especialista + não especialista **: o servidor divide automaticamente os pesos LoRA de especialistas e não especialistas internamente; os usuários atendem a um único caminho de adaptador mesclado.
  • Melhorias no kernel SFT: kernels AMX SFT MoE refatorados, atualizações de base AVX2 MoE e auxiliares SFT MoE paralelos a tensor.
  • Documentos: Ajuste fino e loop de inferência KT-FT (EN) | 中文

📌GLM-5.2

GLM-5.2 é o mais recente modelo MoE da Zhipu AI com NSA (Native Sparse Attention). KTransformers oferece suporte com:

  • Precisão FP8 e BF16: zai-org/GLM-5.2-FP8 e zai-org/GLM-5.2 são suportados.
  • Backend de atenção NSA: atenção esparsa nativa com indexador skip_topk para camadas DSA.
  • Atualizações dinâmicas de especialistas: --kt-enable-dynamic-expert-update com estratégia de posicionamento uniforme.
  • Chamada e raciocínio de ferramenta: analisador de chamada de ferramenta glm47 e analisador de raciocínio glm45. 👉 Tutorial completo

📌MiniMax-M3

MiniMax-M3 é um modelo MoE esparso de 128 especialistas enviado nativamente em MXFP8 (escala fp8 e4m3 + uint8 ue8m0 1×32). KTransformers suporta M3 ponta a ponta com:

  • KT-Kernel híbrido: descarregamento especializado de CPU com cópia de bytes MXFP8 e visualização FP8 de sombra de GPU; validado em 8×H20 e H20 único.
  • MXFP8: caminho de inferência direto do MXFP8 em GPUs Hopper via back-end Triton MoE.
  • Chamada de ferramenta: analisador de chamada de função minimax-m3 (XML nativo <minimax:tool_call> → array OpenAI tool_calls).
  • Modo de pensamento: Controle em nível de solicitação via chat_template_kwargs.thinking_mode — enabled / disabled / adaptive. 👉 Tutorial completo

📥 Instalação

# Option A: One-click install (from ktransformers root)
git clone https://github.com/kvcache-ai/ktransformers.git
cd ktransformers
git submodule update --init --recursive
cd kt-kernel && ./install.sh
cd .. && ./install.sh

# Option B: pip install
pip install sglang-kt
pip install kt-kernel

Requer CUDA 12.0+; CUDA 12.8+ recomendado para implantações FP8/MXFP8.

ktransformers v0.6.3

KTransformers: MiniMax-M3 & GLM-5.2 Day0 Support

We're excited to announce Day0 support for two new large MoE models: MiniMax-M3 and GLM-5.2 in KTransformers + SGLang (sglang-kt). Both models are now available for CPU-GPU heterogeneous inference via kt-kernel. This update also ships end-to-end KT LoRA serving for Qwen3.5 MoE.

🚀 Core Highlights

  • MiniMax-M3 Day0 Support: Full inference support for MiniMax's 128-routed-expert sparse MoE architecture (MiniMaxAI/MiniMax-M3-MXFP8). Runs on a single 96 GB GPU or scales to 8×GPU with kt-kernel CPU expert offload.
  • GLM-5.2 Day0 Support: Full inference support for Zhipu AI's GLM-5.2 (zai-org/GLM-5.2, zai-org/GLM-5.2-FP8), with FP8 and BF16 precision, NSA attention backend, and dynamic expert updates via kt-kernel.
  • KT LoRA Serving: End-to-end Qwen3.5 MoE KT LoRA serving workflow — train with KT SFT, convert once, serve through SGLang with a single merged adapter path.

📌 KT LoRA Serving for Qwen3.5 MoE

A new end-to-end fine-tuning-to-serving workflow for Qwen3.5 MoE with KT expert LoRA:

  • Unified adapter pipeline: KT SFT raw output → convert_kt_to_sglang_adapter.py → merged adapter directory → SGLang --lora-paths serving.
  • Expert + non-expert LoRA: the server auto-splits expert and non-expert LoRA weights internally; users serve a single merged adapter path.
  • SFT kernel improvements: refactored AMX SFT MoE kernels, AVX2 MoE base updates, and tensor-parallel MoE SFT helpers.
  • Docs: KT-FT Fine-Tuning and Inference Loop (EN) | 中文

📌 GLM-5.2

GLM-5.2 is Zhipu AI's latest MoE model with NSA (Native Sparse Attention). KTransformers supports it with:

  • FP8 and BF16 precision: Both zai-org/GLM-5.2-FP8 and zai-org/GLM-5.2 are supported.
  • NSA attention backend: Native sparse attention with skip_topk-gated indexer for DSA layers.
  • Dynamic expert updates: --kt-enable-dynamic-expert-update with uniform placement strategy.
  • Tool calling & reasoning: glm47 tool-call parser and glm45 reasoning parser.

👉 Full Tutorial

📌 MiniMax-M3

MiniMax-M3 is a 128-expert sparse MoE model shipped natively in MXFP8 (fp8 e4m3 + uint8 ue8m0 1×32 scale). KTransformers supports M3 end-to-end with:

  • KT-Kernel hybrid: CPU expert offload with MXFP8 byte-copy and GPU shadow FP8 view; validated on 8×H20 and single H20.
  • MXFP8: Direct MXFP8 inference path on Hopper GPUs via Triton MoE backend.
  • Tool calling: minimax-m3 function-call parser (native <minimax:tool_call> XML → OpenAI tool_calls array).
  • Thinking mode: Request-level control via chat_template_kwargs.thinking_mode — enabled / disabled / adaptive.
