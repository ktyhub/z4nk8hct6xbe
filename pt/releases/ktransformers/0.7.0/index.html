ktransformadores v0.7.0

KTransformers v0.7.0: Suporte para ajuste fino completo e CPU AMD (AVX512) para ajuste fino!

KTransformers v0.7.0 traz compatibilidade de hardware mais ampla e novos recursos de ajuste fino para grandes modelos MoE. Esta versão se concentra em cinco melhorias principais.

Destaques

1. Suporte AVX512 completo para ajuste fino de LoRA

O ajuste fino do KTransformers LoRA agora oferece suporte total a CPUs AVX512 x86 compatíveis sem a necessidade de AMX. O tempo de execução seleciona automaticamente a implementação de CPU apropriada, permitindo que o treinamento especializado do MoE seja executado em uma variedade mais ampla de servidores com grande memória.

kt_config:
  kt_backend: auto

auto é a configuração recomendada para plataformas AMX e AVX512. Alteração relacionada: #2141

2. Suporte nativo FP8 LoRA

KTransformers agora suporta ajuste fino FP8 LoRA nativo para DeepSeek-V3.1. Os pesos e balanças especialistas roteados E4M3 originais em blocos são carregados diretamente do ponto de verificação, evitando a necessidade de materializar uma cópia completa do BF16 antes do treinamento. Na configuração testada do DeepSeek-V3.1, os requisitos de memória do host diminuíram de aproximadamente 1.4 TB com expansão BF16 para cerca de 800 GB. Alteração relacionada: #2141

3. Suporte de ajuste fino Qwen VLM MoE

KTransformers agora oferece suporte ao ajuste fino de LoRA para modelos Qwen3-VL MoE por meio do LLaMA-Factory. A integração lida com as camadas de modelo de linguagem aninhadas do Qwen3-VL, layout de peso especializado fundido e incorporação de patch de visão, permitindo que dados multimodais concluam passagens distribuídas para frente e para trás, atualizações do otimizador e salvamento de pontos de verificação. O caminho de compatibilidade tem como escopo os tipos de modelo Qwen VLM compatíveis e não altera o caminho de treinamento somente texto existente. Alteração relacionada: #2156

4. Implementação rápida do DeepSeek V4 Docker

Esta versão adiciona e expande o guia de implantação DeepSeek V4 Flash Docker. Os usuários podem iniciar um ambiente DeepSeek V4 por meio de um fluxo de trabalho Docker padronizado sem configurar manualmente a pilha completa de compilação e tempo de execução.

5. Reutilização de ativação da CPU

Os usuários avançados agora podem reter as ativações especializadas da CPU durante a recomputação do ponto de verificação de ativação, reduzindo a computação repetida da CPU e melhorando o rendimento do treinamento. Habilite-o no treinamento YAML quando houver memória suficiente no host:

kt_cpu_activation: retain

Deixar esta opção não definida preserva o comportamento de recomputação padrão. A reutilização de ativação troca memória adicional da CPU por recomputação reduzida. Alteração relacionada: #2141

Validação de lançamento

A regressão de lançamento cobriu:

  • Qwen3.5-397B-A17B BF16 LoRA em duas GPUs
  • DeepSeek-V3.1 FP8 LoRA nativo em quatro GPUs
  • Qwen3-VL-30B-A3B-Instrua BF16 LoRA com FSDP2, incluindo pré-processamento multimodal e salvamento de pontos de verificação
  • Perda finita de treinamento
  • Atualizações de parâmetros LoRA diferentes de zero
  • Execução distribuída de FSDP2
  • Carregamento FP8, teste TP, ponto de verificação e testes de ciclo de vida do adaptador

Instalação

pip install "ktransformers[sft]==0.7.0"

Pacotes de integração SFT correspondentes: -transformers-kt==5.6.0.post2 -accelerate-kt==1.14.0.post2

ktransformers v0.7.0

KTransformers v0.7.0: Support Full Fine-Tuning and AMD CPU (AVX512) for Fine-Tuning!

KTransformers v0.7.0 brings broader hardware compatibility and new fine-tuning capabilities for large MoE models. This release focuses on five major improvements.

Highlights

1. Full AVX512 Support for LoRA Fine-Tuning

KTransformers LoRA fine-tuning now fully supports compatible AVX512 x86 CPUs without requiring AMX.

The runtime automatically selects the appropriate CPU implementation, allowing MoE expert training to run on a broader range of large-memory servers.

kt_config:
  kt_backend: auto

auto is the recommended setting for both AMX and AVX512 platforms.

Related change: #2141

2. Native FP8 LoRA Support

KTransformers now supports native FP8 LoRA fine-tuning for DeepSeek-V3.1.

The original block-wise E4M3 routed-expert weights and scales are loaded directly from the checkpoint, avoiding the need to materialize a complete BF16 copy before training.

In the tested DeepSeek-V3.1 configuration, host-memory requirements decreased from approximately 1.4 TB with BF16 expansion to about 800 GB.

Related change: #2141

3. Qwen VLM MoE Fine-Tuning Support

KTransformers now supports LoRA fine-tuning for Qwen3-VL MoE models through LLaMA-Factory.

The integration handles Qwen3-VL's nested language-model layers, fused expert weight layout, and vision patch embedding, enabling multimodal data to complete distributed forward and backward passes, optimizer updates, and checkpoint saving.

The compatibility path is scoped to supported Qwen VLM model types and does not change the existing text-only training path.

Related change: #2156

4. DeepSeek V4 Docker Quick Deployment

This release adds and expands the DeepSeek V4 Flash Docker deployment guide.

Users can start a DeepSeek V4 environment through a standardized Docker workflow without manually configuring the full build and runtime stack.

5. CPU Activation Reuse

Advanced users can now retain CPU expert activations during activation checkpoint recomputation, reducing repeated CPU computation and improving training throughput.

Enable it in the training YAML when sufficient host memory is available:

kt_cpu_activation: retain

Leaving this option unset preserves the default recomputation behavior. Activation Reuse trades additional CPU memory for reduced recomputation.

Related change: #2141

Release Validation

The release regression covered:

  • Qwen3.5-397B-A17B BF16 LoRA on two GPUs
  • DeepSeek-V3.1 native FP8 LoRA on four GPUs
  • Qwen3-VL-30B-A3B-Instruct BF16 LoRA with FSDP2, including multimodal preprocessing and checkpoint saving
  • Finite training loss
  • Non-zero LoRA parameter updates
  • Distributed FSDP2 execution
  • FP8 loading, TP staging, checkpoint, and adapter lifecycle tests

Installation

pip install "ktransformers[sft]==0.7.0"

Matching SFT integration packages:

  • transformers-kt==5.6.0.post2
  • accelerate-kt==1.14.0.post2
