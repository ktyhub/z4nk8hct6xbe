ktransformadores v0.6.4

KTransformers v0.6.4: parâmetros completos de alto desempenho de ponta a ponta e ajuste fino de LoRA

KTransformers v0.6.4 é uma grande atualização para o caminho de ajuste fino KT para modelos MoE grandes e esparsos. Esta versão estende o KT SFT de Ajuste fino de parâmetros completos para LoRA, ao mesmo tempo que melhora o rendimento de treinamento heterogêneo CPU-GPU BF16 e a eficiência de memória na RAM do host e VRAM da GPU.

🚀 Destaques principais

  • Parâmetro completo de ponta a ponta e LoRA SFT: treine grandes modelos MoE esparsos com configurações Full Fine-Tuning, LoRA ou híbrida por meio do fluxo de trabalho familiar LLaMA-Factory.
  • Alto rendimento de treinamento: em execuções de treinamento reais de ponta a ponta, e não em benchmarks de kernel isolados, os KTransformers atingiram aproximadamente 400 tokens/s com Full-FT e 600 tokens/s com LoRA em Qwen3-30B-A3B usando 2× CPUs AMD EPYC 9355 e 2× GPUs RTX 5090. Uma configuração LoRA separada usando um RTX 4090 e uma CPU habilitada para AMX sustentou mais de 700 tokens/s. Os pontos de verificação resultantes também mostraram ganhos claros na validação de ajuste fino de ponta a ponta. DeepSeek V4 em GPUs Ampere: substitutos de atenção BF16 e um caminho FP8 MoE Marlin expandem o suporte do DeepSeek V4 Flash para GPUs sem Tensor Cores FP8 nativos. Compatibilidade e aceleração RAWINT4: compatibilidade de peso compactado mais ampla, carregamento especializado AVX-VNNI-256 e um caminho de pré-preenchimento Kimi K2 mais rápido.
  • Backend experimental Intel iGPU: novo suporte de inferência GPTQ INT4 MoE baseado em SYCL para GPUs integradas Intel.

📌 Parâmetro completo, LoRA e SFT híbrido

Esta versão completa o fluxo de trabalho de treinamento heterogêneo KT CPU-GPU para grandes modelos MoE esparsos:

  • Ajuste fino completo atualiza os pesos especializados da CPU gerenciados pelo KT junto com os parâmetros treináveis regulares do modelo.
  • LoRA cobre camadas lineares regulares, roteadores e portões, e especialistas em MoE fundidos.
  • Treinamento híbrido permite que os parâmetros Full-FT e LoRA sejam treinados juntos.
  • Treinamento confiável de várias etapas oferece suporte ao acúmulo de gradiente, verificação de ativação, execução distribuída, atualizações do otimizador e criação de perfil. O novo caminho de treinamento visa principalmente o treinamento especializado em CPU BF16 KT. 👉 Implementação principal: ktransformers PR #2094

📌 GPUs DeepSeek V4 e Ampere

A integração sglang-kt incluída adiciona suporte mais amplo ao DeepSeek V4 Flash e FP8 MoE em GPUs Ampere:

  • Cache KV BF16 e fallbacks de atenção para GPUs sem Tensor Cores FP8 nativos.
  • Suporte FP8 MoE Marlin para GPU Experts, GPU Prefill e atualizações dinâmicas de especialistas.
  • Correções de estabilidade para agendamento de entrada longa, inicialização AMXINT4/8 e desquantização de escala FP16 FE8M0. Mudanças relacionadas:
  • Inferência de Flash DeepSeek V4 em GPUs Ampere
  • [Corrigir o dimensionamento do pool de tokens SWA V4] (https://github.com/kvcache-ai/sglang/pull/60)
  • Corrigir manipulação de parâmetros AMXINT4/8 SwiGLU
  • FP8 MoE Marlin para GPU Expert e GPU Prefill
  • [Desquantização da escala FP16 FE8M0 Marlin] (https://github.com/kvcache-ai/sglang/pull/63)

📌 Compatibilidade RAWINT4 e aceleração de pré-preenchimento

KTransformers v0.6.4 melhora o caminho RAWINT4 CPU Expert com:

  • Suporte para pontos de verificação de tensores compactados que armazenam pesos INT4 compactados em int32.
  • Carregamento RAWINT4 por especialista em sistemas AVX-VNNI-256.
  • Um caminho de multiplicação de matriz bloqueado para um pré-preenchimento mais rápido do Kimi K2 RAWINT4, enquanto mantém o caminho de decodificação existente para sequências curtas. Mudanças relacionadas:
  • [Normalizar pesos RAWINT4 compactados] (https://github.com/kvcache-ai/ktransformers/pull/2075)
  • [AVX-VNNI-256 carregamento RAWINT4 por especialista] (https://github.com/kvcache-ai/ktransformers/pull/2092)
  • [Envio de tapete pré-preenchido K2 RAWINT4] (https://github.com/kvcache-ai/ktransformers/pull/2080)

📌 Back-end experimental Intel iGPU SYCL

Esta versão apresenta um back-end SYCL experimental para inferência GPTQ INT4 MoE em GPUs integradas Intel. A compatibilidade e o desempenho dependem da GPU Intel, do driver, do conjunto de ferramentas SYCL e da configuração do modelo. 👉 Intel iGPU SYCL GPTQ INT4 MoE backend

🔐 Segurança

O agendador balance_serve agora vincula seu endpoint ZMQ ROUTER ao 127.0.0.1 em vez de todas as interfaces de rede, reduzindo a exposição à desserialização remota não autenticada.

  • Correção de segurança PR #2091 -GHSA-83vp-v6wg-x93x

ktransformers v0.6.4

KTransformers v0.6.4: High-Performance End-to-End Full-Parameter and LoRA Fine-Tuning

KTransformers v0.6.4 is a major upgrade to the KT fine-tuning path for large sparse MoE models. This release extends KT SFT from end-to-end Full-Parameter Fine-Tuning to LoRA, while improving BF16 CPU-GPU heterogeneous training throughput and memory efficiency across host RAM and GPU VRAM.

🚀 Core Highlights

  • End-to-end Full-Parameter and LoRA SFT: train large sparse MoE models with Full Fine-Tuning, LoRA, or Hybrid configurations through the familiar LLaMA-Factory workflow.
  • High training throughput: in real end-to-end training runs—not isolated kernel benchmarks—KTransformers reached approximately 400 tokens/s with Full-FT and 600 tokens/s with LoRA on Qwen3-30B-A3B using 2× AMD EPYC 9355 CPUs and 2× RTX 5090 GPUs. A separate LoRA setup using one RTX 4090 and an AMX-enabled CPU sustained more than 700 tokens/s. The resulting checkpoints also showed clear gains in end-to-end fine-tuning validation.
  • DeepSeek V4 on Ampere GPUs: BF16 attention fallbacks and an FP8 MoE Marlin path expand DeepSeek V4 Flash support to GPUs without native FP8 Tensor Cores.
  • RAWINT4 compatibility and acceleration: broader packed-weight compatibility, AVX-VNNI-256 expert loading, and a faster Kimi K2 prefill path.
  • Experimental Intel iGPU backend: new SYCL-based GPTQ INT4 MoE inference support for Intel integrated GPUs.

📌 Full-Parameter, LoRA, and Hybrid SFT

This release completes the KT CPU-GPU heterogeneous training workflow for large sparse MoE models:

  • Full Fine-Tuning updates KT-managed CPU expert weights together with the model's regular trainable parameters.
  • LoRA covers regular linear layers, routers and gates, and fused MoE experts.
  • Hybrid training allows Full-FT and LoRA parameters to be trained together.
  • Reliable multi-step training supports gradient accumulation, activation checkpointing, distributed execution, optimizer updates, and profiling.

The new training path primarily targets BF16 KT CPU expert training.

👉 Main implementation: ktransformers PR #2094

📌 DeepSeek V4 and Ampere GPUs

The bundled sglang-kt integration adds broader DeepSeek V4 Flash and FP8 MoE support on Ampere GPUs:

  • BF16 KV-cache and attention fallbacks for GPUs without native FP8 Tensor Cores.
  • FP8 MoE Marlin support for GPU Experts, GPU Prefill, and dynamic expert updates.
  • Stability fixes for long-input scheduling, AMXINT4/8 startup, and FP16 FE8M0 scale dequantization.

Related changes:

  • DeepSeek V4 Flash inference on Ampere GPUs
  • Fix V4 SWA token-pool sizing
  • Fix AMXINT4/8 SwiGLU parameter handling
  • FP8 MoE Marlin for GPU Expert and GPU Prefill
  • FP16 FE8M0 Marlin scale dequantization

📌 RAWINT4 Compatibility and Prefill Acceleration

KTransformers v0.6.4 improves the RAWINT4 CPU Expert path with:

  • Support for compressed-tensors checkpoints that store packed INT4 weights in int32.
  • Per-expert RAWINT4 loading on AVX-VNNI-256 systems.
  • A blocked matrix-multiplication path for faster Kimi K2 RAWINT4 prefill, while keeping the existing decode path for short sequences.

Related changes:

  • Normalize compressed RAWINT4 weights
  • AVX-VNNI-256 per-expert RAWINT4 loading
  • K2 RAWINT4 prefill mat-mat dispatch

📌 Experimental Intel iGPU SYCL Backend

This release introduces an experimental SYCL backend for GPTQ INT4 MoE inference on Intel integrated GPUs. Compatibility and performance depend on the Intel GPU, driver, SYCL toolchain, and model configuration.

👉 Intel iGPU SYCL GPTQ INT4 MoE backend

🔐 Security

The balance_serve scheduler now binds its ZMQ ROUTER endpoint to 127.0.0.1 instead of all network interfaces, reducing exposure to unauthenticated remote pickle deserialization.

  • Security fix PR #2091
  • GHSA-83vp-v6wg-x93x

📦 Installation

pip install "ktransformers[sft]"

KT SFT continues to use the LLaMA-Factory training entry and YAML workflow.
