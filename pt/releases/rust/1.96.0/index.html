#rust 1.96.0 <a id="1.96.0-Language"></a>

Idioma

  • Permitir passar a metavariável expr para cfg
  • [Sempre coagir, nunca digita expressões de tupla] (https://github.com/rust-lang/rust/pull/147834)
  • Evite orientação incorreta de inferência de argumentos de função em casos raros
  • [Suporta registros vetoriais s390x em montagem inline] (https://github.com/rust-lang/rust/pull/154184)
  • Permitir usar constantes do tipo ManuallyDrop como padrões (corrigindo uma regressão introduzida em 1.94.0) <a id="1.96.0-Compiler"></a>

Compilador

  • Ativar recurso de relaxamento de link para destinos LoongArch Linux
  • Atualizar linha de base riscv64gc-unknown-fuchsia para RVA22 + vetor <a id="1.96.0-Libraries"></a>

Bibliotecas

  • Suporte para iteração em intervalos de números inteiros NonZero
  • refatorar definição 'válida para leitura/gravação': excluir nulo; adicione isso como uma exceção em métodos individuais
  • Corrigir pesquisa de host atrasada SGX via ToSocketAddr <a id="1.96.0-Stabilized-APIs"></a>

APIs estabilizados

  • assert_matches!
  • debug_assert_matches!
  • From<T> for AssertUnwindSafe<T>
  • From<T> for LazyCell<T, F>
  • From<T> for LazyLock<T, F>
  • core::range::RangeToInclusive
  • core::range::RangeToInclusiveIter
  • core::range::RangeFrom -core::range::RangeFromIter -core::range::Range -core::range::RangeIter <a id="1.96.0-Cargo"></a>

Carga

  • Permitir que uma dependência especifique um repositório git e um registro alternativo. Assim como acontece com crates.io, o repositório git será usado localmente, mas a versão do registro será usada quando publicada.
  • Adicionado suporte target.'cfg(..)'.rustdocflags na configuração.
  • Corrigido CVE-2026-5222 e CVE-2026-5223. <a id="1.96-Rustdoc"></a>

Rustdoc

  • As notas de descontinuação agora são renderizadas como qualquer outra documentação. Anteriormente, eles usavam a propriedade css white-space: pre-wrap; e retiravam quaisquer elementos <p> do HTML renderizado, no entanto, isso causava problemas e comportamento não intuitivo. O novo comportamento deve ser mais previsível, no entanto, algumas notas de descontinuação de múltiplas linhas agora serão renderizadas como linhas únicas. Se isso for indesejável, você pode usar o método markdown padrão para forçar uma quebra de linha, que consiste em dois espaços seguidos por uma nova linha ("\n").
  • Não emita fiapos rustdoc missing_doc_code_examples em itens impl
  • Métodos separados e funções associadas na barra lateral <a id="1.96.0-Compatibility-Notes"></a>

Notas de compatibilidade

  • [Corrigir layout de enums #[repr(Int)] em alguns casos extremos envolvendo campos de tipos de tamanho zero desabitados] (https://github.com/rust-lang/rust/pull/146989)
  • Evitar coerção de redução de tamanho em Pin<Foo> onde Foo não implementa Deref. Algumas dessas coerções eram permitidas anteriormente, mas produzem um tipo sem público útil API.
  • rustc: Pare de passar --allow-undefined em alvos wasm
  • [Gate o atributo #![reexport_test_harness_main] acidentalmente estabilizado] (https://github.com/rust-lang/rust/pull/152210)
  • Erro em return-position-impl-trait-in-traits cujos tipos são muito privados
  • Relate o lint uninhabited_static nas dependências e torne-o negado por padrão
  • As compilações distribuídas agora contêm informações de depuração não divididas para windows-gnu Isso parece melhorar a qualidade dos backtraces. Esta alteração não tem efeito nos padrões de saída de rustc/cargo nesses alvos.
  • [Verifique se os argumentos genéricos const estão digitados corretamente em mais posições] (https://github.com/rust-lang/rust/pull/152931)
  • Remover -Csoft-float
  • A importação de estruturas com ::{self [as name]}, por exemplo, struct S {}; use S::{self as Other};, agora não é mais permitida porque as importações de {self} requerem um módulo pai.
  • Para atributos export_name, link_name e link_section, se múltiplos do mesmo atributo estiverem presentes, o primeiro agora terá precedência.
  • Atualize o LLVM externo mínimo para 21
  • Em alvos avr, o tipo double de C é de 32 bits por padrão, então altere c_double para f32 em alvos avr para corresponder. Esta é uma mudança significativa, mas necessária para fazer com que c_double corresponda ao dobro de C.
  • BTreeMap::append() foi otimizado, o que agora pode causar pânico para tipos com impls Ord incorretos <a id="1.96.0-Internal-Changes"></a>

Mudanças Internas

Essas alterações não afetam nenhuma interface pública do Rust, mas representam melhorias significativas no desempenho ou na parte interna do rustc e ferramentas relacionadas.

  • Alvos JSON: os alvos softfloat aarch64 agora precisam ter rustc_abi definido como "softfloat"
  • especificações de destino: verificações mais rigorosas dos valores LLVM ABI e correlação com cfg(target_abi)

Original em inglês / English original

rust 1.96.0

<a id="1.96.0-Language"></a>

Language

  • Allow passing expr metavariable to cfg
  • Always coerce never types in tuple expressions
  • Avoid incorrect inference guidance of function arguments in rare cases
  • Support s390x vector registers in inline assembly
  • Allow using constants of type ManuallyDrop as patterns (fixing a regression introduced in 1.94.0)

<a id="1.96.0-Compiler"></a>

Compiler

  • Enable link relaxation feature for LoongArch Linux targets
  • Update riscv64gc-unknown-fuchsia baseline to RVA22 + vector

<a id="1.96.0-Libraries"></a>

Libraries

  • Support iterating over ranges of NonZero integers
  • refactor 'valid for read/write' definition: exclude null; add that as an exception on individual methods instead
  • Fix SGX delayed host lookup via ToSocketAddr

<a id="1.96.0-Stabilized-APIs"></a>

Stabilized APIs

  • assert_matches!
  • debug_assert_matches!
  • From<T> for AssertUnwindSafe<T>
  • From<T> for LazyCell<T, F>
  • From<T> for LazyLock<T, F>
  • core::range::RangeToInclusive
  • core::range::RangeToInclusiveIter
  • core::range::RangeFrom
  • core::range::RangeFromIter
  • core::range::Range
  • core::range::RangeIter

<a id="1.96.0-Cargo"></a>

Cargo

  • Allow a dependency to specify both a git repository and an alternate registry. Just like with crates.io, the git repository will be used locally, but the registry version will be used when published.
  • Added target.'cfg(..)'.rustdocflags support in configuration.
  • Fixed CVE-2026-5222 and CVE-2026-5223.

<a id="1.96-Rustdoc"></a>

Rustdoc

  • Deprecation notes are now rendered like any other documentation. Previously they used the css white-space: pre-wrap; property and stripped any <p> elements from the rendered html, however this caused issues and unintuitive behavior. The new behavior should be more predictable, however some multi-line deprecation notes will now be rendered as as single lines. If this is undesirable, you can use the standard markdown method of forcing a linebreak, which is two spaces followed by a newline ("\n").
  • Don't emit rustdoc missing_doc_code_examples lint on impl items
  • Separate methods and associated functions in sidebar

<a id="1.96.0-Compatibility-Notes"></a>

Compatibility Notes

  • Fix layout of #[repr(Int)] enums in some edge cases involving fields of uninhabited zero-sized types
  • Prevent unsize-coercing into Pin<Foo> where Foo doesn't implement Deref. Some such coercions were previously allowed, but produce a type with no useful public API.
  • rustc: Stop passing --allow-undefined on wasm targets
  • Gate the accidentally stabilized #![reexport_test_harness_main] attribute
  • Error on return-position-impl-trait-in-traits whose types are too private
  • Report the uninhabited_static lint in dependencies and make it deny-by-default
  • Distributed builds now contain non-split debuginfo for windows-gnu This appears to improve the quality of backtraces. This change has no effect on the defaults for the output of rustc/cargo on these targets.
  • Check const generic arguments are correctly typed in more positions
  • Remove -Csoft-float
  • Importing structs with ::{self [as name]}, e.g., struct S {}; use S::{self as Other};, is now no longer permitted because {self} imports require a module parent.
  • For export_name, link_name, and link_section attributes, if multiple of the same attribute is present, the first one now takes precedence.
  • Update the minimum external LLVM to 21
  • On avr targets, C's double type is 32-bit by default, so change c_double to f32 on avr targets to match. This is a breaking change, but necessary to make c_double match C's double.
  • BTreeMap::append() was optimized, which may now cause panics for types with incorrect Ord impls

<a id="1.96.0-Internal-Changes"></a>

Internal Changes

These changes do not affect any public interfaces of Rust, but they represent significant improvements to the performance or internals of rustc and related tools.

  • JSON targets: aarch64 softfloat targets now have to have rustc_abi set to "softfloat"
  • target specs: stricter checks for LLVM ABI values, and correlate that with cfg(target_abi)
