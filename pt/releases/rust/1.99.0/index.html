Idioma

  • [Adicionar lint raw_borrows_via_references permitido por padrão que verifica referências que se deterioram imediatamente em empréstimos brutos] (https://github.com/rust-lang/rust/pull/138230)
  • [Estenda o lint unconditional_panic para chamadas de função que entram em pânico quando o tamanho dos pedaços/janelas é zero] (https://github.com/rust-lang/rust/pull/153563)

  • Estabilizar a capacidade de usar funções #[unsafe(naked)] para definir funções C-variádicas (#![feature(c_variadic_naked_functions)]).
  • Os métodos de traço agora são resolvidos em um tipo nunca ajustado (produzindo um FCW)

  • Conserte o fiapo overflowing_literals com negação repetida. Por exemplo, agora não será mais lint no --128_i8, que já é detectado pelo arithmetic_overflow.
  • Adicionar símbolos POSIX aos lints invalid_runtime_symbol_definitions e suspicious_runtime_symbol_definitions
  • Lint atributos #[path] não utilizados em módulos inline
  • Ativar lint unreachable_cfg_select_predicates como parte do grupo de lint unused
  • [Estabilize a passagem de números inteiros de 128 bits por meio de registros vetoriais com asm! em x86] (https://github.com/rust-lang/rust/pull/159525)
  • Documente explicitamente que algumas alocações podem aumentar no local (mas nenhuma pode diminuir)
  • Agora garantimos que o conteúdo de um UnsafeCell pode ser acessado sem passar pelo get
    • O fiapo invalid_reference_casting foi ajustado de acordo
  • Conta para recursos de destino habilitados globalmente em global_asm!
  • Avisar se um atributo doc inválido for usado em uma invocação de macro <a id="1.99.0-Compiler"></a>

  • Ativar static_position_independent_executables em todos os alvos GNU
  • Ao fornecer uma sugestão sobre um método ausente, rustc agora prefere um nome exatamente correspondente de um atributo de alias de documento em vez de uma pesquisa de similaridade de outros nomes de métodos. Se seus novos usuários às vezes esperam um método com um nome diferente, adicionar um alias de documento agora os ajudará a encontrá-lo por meio de sugestões do rustc, além de ajudá-los a encontrá-lo por meio da pesquisa de documentos rust: Ao sugerir nomes de métodos, prefira aliases de documentos exatos em vez de nomes semelhantes <a id="1.99.0-Platform-Support"></a>

Suporte à plataforma

  • Promover riscv64-unknown-linux-musl para Nível 2 com ferramentas de host Consulte a [página de suporte da plataforma] do Rust (https://doc.rust-lang.org/rustc/platform-support.html) para obter mais informações sobre o suporte de plataforma em camadas do Rust. <a id="1.99.0-Libraries"></a>

Bibliotecas

  • A iteração em RangeInclusive (faixas a..=b) agora é [melhor otimizada em algumas circunstâncias] (https://github.com/rust-lang/rust/pull/155114). Como efeito colateral disso, o comportamento dos valores RangeInclusive que já foram esgotados (como um iterador) mudou. Por exemplo, os valores de retorno de start() e end() nesses intervalos podem retornar valores diferentes e o uso de tais intervalos como índices de fatia pode ter um comportamento diferente. Não era garantido que esses comportamentos fossem estáveis, portanto, essas alterações são consideradas como não sendo alterações significativas.

  • [Atualize transmute_copy para usar um pânico sem desenrolar] (https://github.com/rust-lang/rust/pull/155989)

Carga

  • Adicione um novo perfil integrado debug. Esta é uma preparação para a transição do perfil dev da depuração para fornecer um padrão mais sensato para iterações de desenvolvimento mais rápidas. Atualmente não há diferença entre os perfis dev e debug. documentos #17214
  • Os membros do espaço de trabalho na edição 2024 ou posterior agora podem substituir o campo default-features de uma dependência de espaço de trabalho herdada. Por exemplo, serde = { workspace = true, default-features = false } agora desativa recursos padrão mesmo quando a definição do espaço de trabalho os habilita. Nas edições anteriores, default-features = false é ignorado com um aviso. (RFC 3945) #17126 Veja também o Cargo completo changelog <a id="1.99.0-Rustdoc"></a>

Notas de compatibilidade

  • Descontinuar totalmente os módulos integrais legados. Por exemplo, std::i32::MAX deve ser acessado via i32::MAX.
  • [Atualize no_mangle_generic_items para erro grave] (https://github.com/rust-lang/rust/pull/154585)
  • O Pin::new_unchecked teve seus invariantes de segurança ligeiramente alterados
  • Não promova referências a estática externa
  • [Certifique-se de que os tipos inferidos de padrões let sejam verificados] (https://github.com/rust-lang/rust/pull/157841)
  • eremita/fs: Retorne unsupported() em vez de from_raw_os_error(22)
  • Corrigido um bug onde #[repr(simd)] era acidentalmente permitido em invocações de macro no Rust estável
  • Abortar const-eval quando houver genéricos no tipo do valor que está sendo produzido
  • Atributos que não se aplicam a nada agora são um erro nos blocos de código nos comentários do documento
  • [Box::leak: diga às pessoas para evitar vazamentos] (https://github.com/rust-lang/rust/pull/160323)
  • PowerPC inline ASM: corrige flutuadores escalares na faixa vetorial errada em little endian
  • Não leve em consideração doc(cfg()) ao filtrar doctests
  • Inferir tempos de vida anônimos nos tipos de consts associados como 'static
  • Macros que se expandem para ponto e vírgula agora produzem um lint de aviso (semicolon_in_expressions_from_non_local_macros) mesmo quando a macro vem de outra caixa. Anteriormente, esses avisos apareciam apenas para macros da mesma caixa, para evitar a exibição de avisos que não podiam ser corrigidos localmente; no entanto, isso mascarou problemas, pois os testes de integração da caixa que fornece a macro são compilados como uma caixa separada, de modo que os testes geralmente não revelam esse problema. Se você encontrar um lint como este, certifique-se de reportá-lo à caixa que fornece a macro para que eles possam corrigi-lo; não o silencie apenas em sua própria caixa.
    • semicolon_in_expressions_from_macros: Lint também em macros não locais
    • [Dividir semicolon_in_expressions_from_macros não local em um lint separado] (https://github.com/rust-lang/rust/pull/159700)
  • No Cargo, a compilação incremental agora está desabilitada por padrão ao executar no CI. CI é detectado por meio da variável de ambiente CI. #17220
  • A referência Rust não recomenda mais o uso de um único padrão para corresponder uma união ao lado de outro valor, como em uma união etiquetada escrita manualmente. Isso ocorreu porque se descobriu que tal código, em algumas circunstâncias, resultaria na leitura do conteúdo da união pelo compilador antes de verificar se o restante do escrutinado corresponde ao restante do padrão. Isso pode causar um comportamento indefinido no código semelhante ao recomendado anteriormente pela referência. <a id="1.99.0-Internal-Changes"></a>

Original em inglês / English original

rust 1.99.0

<a id="1.99.0-Language"></a>

Language

  • Add allow-by-default raw_borrows_via_references lint that checks for references that decay immediately into raw borrows
  • Extend unconditional_panic lint to function calls that panic when the chunks/windows size is zero
  • Stabilize C-variadic function definitions
  • Stabilize the ability to use #[unsafe(naked)] functions to define C-variadic functions (#![feature(c_variadic_naked_functions)]).
  • Trait methods are now resolved on an adjusted never type (producing a FCW)
  • Coerce from inference variables to trait objects if the inference variable is related via subtyping to a type that is known to be Sized
  • Stabilize #[my_macro] mod foo;. This allows outlined modules (mod foo;) anywhere in the body of a custom attribute or derive macro.
  • Fix the overflowing_literals lint with repeated negation. For instance, it will now no longer lint on --128_i8, which is already detected by the arithmetic_overflow lint.
  • Add POSIX symbols to the invalid_runtime_symbol_definitions and suspicious_runtime_symbol_definitions lints
  • Lint unused #[path] attributes on inline modules
  • Enable unreachable_cfg_select_predicates lint as part of unused lint group
  • Stabilize passing 128-bit integers via vector registers with asm! on x86
  • Explicitly document that some allocations are allowed to grow in-place (but none are allowed to shrink)
  • We now guarantee that the contents of an UnsafeCell can be accessed without going through get
    • The invalid_reference_casting lint was adjusted accordingly
  • Account for globally enabled target features in global_asm!
  • Warn if an invalid doc attribute is used on a macro invocation

<a id="1.99.0-Compiler"></a>

Compiler

  • Convert -Ctarget-cpu into a target-modifier for AVR, AMDGCN and NVPTX
  • Enable static_position_independent_executables on all gnu targets
  • When providing a suggestion about a missing method, rustc now prefers an exactly matching name from a doc alias attribute over a similarity search from other method names. If your new users sometimes expect a method under a different name, adding a doc alias will now help them find it via rustc suggestions, in addition to helping them find it via rustdoc search: When suggesting method names, prefer exact doc aliases over similar names

<a id="1.99.0-Platform-Support"></a>

Platform Support

  • Promote riscv64-unknown-linux-musl to Tier 2 with host tools

Refer to Rust's platform support page for more information on Rust's tiered platform support.

<a id="1.99.0-Libraries"></a>

Libraries

  • Iteration on RangeInclusive (a..=b ranges) is now optimized better in some circumstances. As a side effect of this, the behavior of RangeInclusive values that has already been exhausted (as an iterator) has changed. For example, the return values of start() and end() on such ranges may return different values, and using such ranges as slice indexes may have different behavior. These behaviors were not guaranteed to be stable, so these changes are considered to not be breaking changes.
  • Relax transmute_copy to accept ?Sized types
  • Update transmute_copy to use a non-unwinding panic
  • Don't escape U+FF9E and U+FF9F in escape_debug_ext
  • Re-export core::fmt::NumBuffer in alloc (and std)

<a id="1.99.0-Stabilized-APIs"></a>

Stabilized APIs

  • IntoIterator for Box<[T; N]>
  • IntoIterator for &Box<[T; N]>
  • IntoIterator for &mut Box<[T; N]>
  • VecDeque::retain_back
  • core::ffi::VaList
  • Box::into_non_null
  • Box::from_non_null
  • Vec::into_parts
  • Vec::from_parts
  • core::mem::size_of_val_raw
  • core::mem::align_of_val_raw
  • core::alloc::Layout::for_value_raw
  • String::from_utf8_lossy_owned
  • string::FromUtf8Error::into_utf8_lossy
  • FusedIterator for StepBy<I>
  • std::fs::set_times
  • std::fs::set_times_nofollow
  • <LocalKey<Cell<T>>>::update

<a id="1.99.0-Cargo"></a>

Cargo

  • Add a new built-in profile debug. This is a preparation for transitioning the dev profile away from debugging to give a saner default for faster development iterations. Currently there is no difference between dev and debug profiles. docs #17214
  • Workspace members on edition 2024 or later can now override an inherited workspace dependency's default-features field. For example, serde = { workspace = true, default-features = false } now turns off default features even when the workspace definition enables them. On earlier editions, default-features = false is ignored with a warning. (RFC 3945) #17126

See also the full Cargo changelog

<a id="1.99.0-Rustdoc"></a>

Rustdoc

  • Add new unused_footnote_definition rustdoc lint
  • Smarter filtering of trait impls yields performance improvements of 20% on average and up to 40% on some real-world crates. (1, 2, 3, 4, 5)

<a id="1.99.0-Compatibility-Notes"></a>

Compatibility Notes

  • Fully deprecate the legacy integral modules. For example, std::i32::MAX should be accessed via i32::MAX instead.
  • Upgrade no_mangle_generic_items into hard error
  • The Pin::new_unchecked has had its safety invariants changed slightly
  • Do not promote references to extern statics
  • Ensure that the inferred types of let patterns typecheck
  • hermit/fs: Return unsupported() instead of from_raw_os_error(22)
  • Fixed a bug where #[repr(simd)] was accidentally allowed on macro invocations on stable Rust
  • Abort const-eval when there are generics in the type of the value being produced
  • Attributes not applying to anything are now an error in code blocks in doc comments
  • Box::leak: tell people to avoid unleaking
  • PowerPC inline ASM: Fix scalar floats being in the wrong vector lane on little endian
  • Do not take doc(cfg()) into account when filtering doctests
  • Infer anonymous lifetimes in the types of associated consts as 'static
  • Macros that expand to a semicolon now produce a warning lint (semicolon_in_expressions_from_non_local_macros) even when the macro comes from another crate. Previously, such warnings only appeared for macros from the same crate, to avoid showing warnings that can't be fixed locally; however, this masked problems, as integration tests from the crate providing the macro get compiled as a separate crate, so tests often wouldn't reveal this issue. If you encounter a lint like this, please make sure to report it to the crate providing the macro so they can fix it; don't just silence it in your own crate.
    • semicolon_in_expressions_from_macros: Lint on non-local macros too
    • Split non-local semicolon_in_expressions_from_macros into a separate lint
  • In Cargo, incremental compilation is now disabled by default when running in CI. CI is detected via the CI environment variable. #17220
  • The Rust Reference no longer recommends using a single pattern to match a union alongside another value, such as in a manually-written tagged union. This was because it was found that such code would, in some circumstances, result in the compiler reading the contents of the union before checking if the rest of the scrutinee matches the rest of the pattern. This can cause undefined behavior in code similar to what the reference previously recommended.

<a id="1.99.0-Internal-Changes"></a>

Internal Changes

These changes do not affect any public interfaces of Rust, but they represent significant improvements to the performance or internals of rustc and related tools.

  • Update to LLVM 23
