#rust 1.92.0 <a id="1.92.0-Language"></a>

Idioma

  • Representação e validade do documento MaybeUninit
  • Permitir &raw [mut | const] para campo de união em código seguro
  • Prefira limites de itens de tipos associados em vez de limites de localização para características automáticas e Sized
  • Não materialize X em [X; 0] quando X estiver desdimensionando uma const
  • Suporte para combinação de #[track_caller] e #[no_mangle] (requer cada declaração especificando também #[track_caller])
  • [Faça nunca digitar lints never_type_fallback_flowing_into_unsafe e dependency_on_unit_never_type_fallback negar por padrão] (https://github.com/rust-lang/rust/pull/146167)
  • Permitir a especificação de vários limites para o mesmo item associado, exceto em objetos de características
  • [Fortalecer ligeiramente o tratamento de regiões de classificação mais alta em coerência] (https://github.com/rust-lang/rust/pull/146725)
  • O lint unused_must_use não avisa mais em Result<(), Uninhabited> (por exemplo, Result<(), !>) ou ControlFlow<Uninhabited, ()>. Isso evita ter que verificar se há um erro que nunca pode acontecer. <a id="1.92.0-Compiler"></a>

Compilador

  • Fazer link mips64el-unknown-linux-muslabi64 dinamicamente
  • Remova o código atual para incorporar argumentos de linha de comando no PDB As informações de linha de comando normalmente não são necessárias para ferramentas de depuração, e o código removido estava causando problemas para compilações incrementais, mesmo em destinos que não usam informações de depuração do PDB. <a id="1.92.0-Libraries"></a>

Bibliotecas

  • Especialize-se em Iterator::eq{_by} para iteradores TrustedLen
  • Simplifique Extend para tuplas
  • Adicionados detalhes ao Debug para EncodeWide.
  • iter::Repeat::last e count agora entrarão em pânico, em vez de fazer um loop infinito. <a id="1.92.0-Stabilized-APIs"></a>

  • Rc::new_zeroed_slice
  • Arc::new_zeroed -Arc::new_zeroed_slice -btree_map::Entry::insert_entry -btree_map::VacantEntry::insert_entry

Carga

  • Adicionado um novo capítulo ao livro Cargo, "Otimizando o desempenho da construção". <a id="1.92.0-Rustdoc"></a>

Rustdoc

  • Se um item de característica aparecer na pesquisa rustdoc, oculte os itens impl correspondentes. Anteriormente, uma pesquisa por "último" mostraria tanto Iterator::last quanto métodos impl como std::vec::IntoIter::last. Agora esses métodos impl ficarão ocultos, liberando espaço para métodos inerentes como BTreeSet::last.
  • Relaxar regras para identificadores na pesquisa. Anteriormente só era possível pesquisar identificadores válidos no código rust, agora as pesquisas só precisam ser válidas como parte de um identificador. Por exemplo, agora você pode realizar uma pesquisa que começa com um dígito. <a id="1.92.0-Compatibility-Notes"></a>

Notas de compatibilidade

  • Corrigir backtraces com -C panic=abort no Linux gerando tabelas de desenrolamento por padrão. Construa com -C force-unwind-tables=no para continuar omitindo tabelas de desenrolamento.

rust 1.92.0

<a id="1.92.0-Language"></a>

Language

  • Document MaybeUninit representation and validity
  • Allow &raw [mut | const] for union field in safe code
  • Prefer item bounds of associated types over where-bounds for auto-traits and Sized
  • Do not materialize X in [X; 0] when X is unsizing a const
  • Support combining #[track_caller] and #[no_mangle] (requires every declaration specifying #[track_caller] as well)
  • Make never type lints never_type_fallback_flowing_into_unsafe and dependency_on_unit_never_type_fallback deny-by-default
  • Allow specifying multiple bounds for same associated item, except in trait objects
  • Slightly strengthen higher-ranked region handling in coherence
  • The unused_must_use lint no longer warns on Result<(), Uninhabited> (for instance, Result<(), !>), or ControlFlow<Uninhabited, ()>. This avoids having to check for an error that can never happen.

<a id="1.92.0-Compiler"></a>

Compiler

  • Make mips64el-unknown-linux-muslabi64 link dynamically
  • Remove current code for embedding command-line args in PDB Command-line information is typically not needed by debugging tools, and the removed code was causing problems for incremental builds even on targets that don't use PDB debuginfo.

<a id="1.92.0-Libraries"></a>

Libraries

  • Specialize Iterator::eq{_by} for TrustedLen iterators
  • Simplify Extend for tuples
  • Added details to Debug for EncodeWide.
  • iter::Repeat::last and count will now panic, rather than looping infinitely.

<a id="1.92.0-Stabilized-APIs"></a>

Stabilized APIs

  • NonZero<u{N}>::div_ceil
  • Location::file_as_c_str
  • RwLockWriteGuard::downgrade
  • Box::new_zeroed
  • Box::new_zeroed_slice
  • Rc::new_zeroed
  • Rc::new_zeroed_slice
  • Arc::new_zeroed
  • Arc::new_zeroed_slice
  • btree_map::Entry::insert_entry
  • btree_map::VacantEntry::insert_entry
  • impl Extend<proc_macro::Group> for proc_macro::TokenStream
  • impl Extend<proc_macro::Literal> for proc_macro::TokenStream
  • impl Extend<proc_macro::Punct> for proc_macro::TokenStream
  • impl Extend<proc_macro::Ident> for proc_macro::TokenStream

These previously stable APIs are now stable in const contexts:

  • <[_]>::rotate_left
  • <[_]>::rotate_right

<a id="1.92.0-Cargo"></a>

Cargo

  • Added a new chapter to the Cargo book, "Optimizing Build Performance".

<a id="1.92.0-Rustdoc"></a>

Rustdoc

  • If a trait item appears in rustdoc search, hide the corresponding impl items. Previously a search for "last" would show both Iterator::last as well as impl methods like std::vec::IntoIter::last. Now these impl methods will be hidden, freeing up space for inherent methods like BTreeSet::last.
  • Relax rules for identifiers in search. Previously you could only search for identifiers that were valid in rust code, now searches only need to be valid as part of an identifier. For example, you can now perform a search that starts with a digit.

<a id="1.92.0-Compatibility-Notes"></a>

Compatibility Notes

  • Fix backtraces with -C panic=abort on Linux by generating unwind tables by default. Build with -C force-unwind-tables=no to keep omitting unwind tables.
<!-- end list -->
  • As part of the larger effort refactoring compiler built-in attributes and their diagnostics, the future-compatibility lint invalid_macro_export_arguments is upgraded to deny-by-default and will be reported in dependencies too.
  • Update the minimum external LLVM to 20
  • Prevent downstream impl DerefMut for Pin<LocalType>
  • Don't apply temporary lifetime extension rules to the arguments of non-extended pin! and formatting macros
