#terraforma v1.16.0

1.16.0 (26 de agosto de 2026)

NOVOS RECURSOS:

  • O Terraform agora armazena dados privados planejados para provedores, permitindo que o estado específico do provedor seja preservado durante o planejamento e a aplicação. (#37986)
  • terraform_data: O novo bloco store pode conter valores efêmeros e sensíveis em todo o plano e aplicação. (#38298)
  • Os provedores agora podem usar blocos aninhados como valores computados (#38305)
  • importação: blocos import dentro de módulos agora são suportados. (#38352)
  • Terraform agora está disponível como um binário pré-construído para Linux s390x (zLinux). (#38384)
  • Os gatilhos de ação de recursos agora podem usar os modos on_failure de halt, taint ou continue. (#38722) MELHORIAS:
  • state show: O comando state show agora pode produzir saída legível por máquina quando fornecido com o sinalizador -json (#23940)
  • espaço de trabalho: O comando workspace list agora pode produzir saída legível por máquina quando fornecido com o sinalizador -json (#38397)
  • teste: o Terraform agora informa quais recursos foram deixados para trás quando skip_cleanup foi configurado. (#38449)
  • pilhas: As configurações de ação agora têm acesso a um símbolo caller contendo o valor do objeto do recurso de chamada. (#38668)
  • As ações agora podem usar eventos before_destroy e after_destroy. (#38668)
  • nuvem: o Terraform agora exibe um resumo dos resultados da avaliação de políticas para plan e apply executados em relação ao HCP Terraform. (#38715)
  • política: o Terraform agora resolve credenciais de plug-in de política da nuvem configurada ou back-end remoto durante init, plan e apply, em vez de exigir que o plug-in leia as próprias credenciais. (#38716)
  • gráfico: O comando terraform graph agora pode gerar gráficos no formato Mermaid usando o sinalizador -format=mermaid. (#38719)
  • As saídas do módulo filho com atributos aninhados obsoletos e não referenciados não retornam mais avisos de descontinuação. (#38778)
  • Os blocos de recursos lifecycle agora suportam destroy = false para evitar que um recurso seja destruído. (#38784)
  • A função contains() agora pode testar valores null. (#38792)
  • console: O comando terraform console agora aceita um sinalizador -scope=<module address> opcional, que pode ser usado para avaliar expressões dentro do escopo de um módulo ou de uma instância de módulo específica. (#31861)
  • -invoke agora pode ser combinado com -target para especificar a instância do recurso de chamada quando vários recursos acionam a mesma ação. (#38845)
  • O comando terraform stacks agora infere automaticamente o nome do host de destino do arquivo de credenciais locais (credentials.tfrc.json) quando nem TF_STACKS_HOSTNAME nem TF_CLOUD_HOSTNAME estão definidos (#38896) CORREÇÕES DE ERROS:
  • Os blocos import agora respeitam corretamente os nomes locais dos provedores. (#38338)
  • terraform apply não entra mais em pânico quando o plano contém uma alteração não operacional para um recurso deposto que possui blocos lifecycle.precondition ou lifecycle.postcondition. (#38586)
  • espaço de trabalho: o Terraform agora gera um erro se um nome de espaço de trabalho inválido for selecionado devido a alterações fora de banda. (#38594)
  • teste: o Terraform agora gera um aviso quando um arquivo referenciado pelo sinalizador -filter não existe. (#38603)
  • init: o Terraform não remove mais bloqueios do arquivo de bloqueio de dependência para provedores configurados como dev_override. (#38634)
  • init: O Terraform agora avisa quando provedores não gerenciados estão em uso e podem afetar a instalação do provedor. (#38656)
  • As ações agora são invocadas com relação a todas as dependências de recursos. (#38668)
  • O Terraform agora retorna o erro correto quando um alvo import existe no estado, mas não tem configuração correspondente. (#38782)
  • A função merge() não entra mais em pânico quando objetos null são passados. (#38792)
  • Permitir sublinhados em namespaces de endereço de origem do provedor, para que endereços de provedores de registro privados não sejam mais rejeitados como inválidos (#38894)
  • teste: valores efêmeros opcionais não precisam ser definidos no momento do plano (#38974) NOTAS:
  • init: Erros devido a flags -upgrade e -lockfile=readonly incompatíveis agora são gerados mais cedo no processo de inicialização. (#38561) NOTAS DE ATUALIZAÇÃO:
  • bastion_host_key agora é aplicado corretamente pelos provisionadores. Revise as configurações do provisionador para verificar se a chave configurada está correta antes de atualizar. (#38318)

terraform v1.16.0

1.16.0 (August 26, 2026)

NEW FEATURES:

  • Terraform now stores planned private data for providers, allowing provider-specific state to be preserved across plan and apply. (#37986)

  • terraform_data: The new store block can hold ephemeral and sensitive values across plan and apply. (#38298)

  • Providers can now use nested blocks as computed values (#38305)

  • import: import blocks inside modules are now supported. (#38352)

  • Terraform is now available as a pre-built binary for Linux s390x (zLinux). (#38384)

  • Resource action triggers can now use on_failure modes of halt, taint, or continue. (#38722)

ENHANCEMENTS:

  • state show: The state show command can now produce machine-readable output when supplied with the -json flag (#23940)

  • workspace: The workspace list command can now produce machine-readable output when supplied with the -json flag (#38397)

  • test: Terraform now reports which resources were left behind when skip_cleanup is set. (#38449)

  • stacks: Action configurations now have access to a caller symbol containing the object value of the calling resource. (#38668)

  • Actions can now use before_destroy and after_destroy events. (#38668)

  • cloud: Terraform now displays a summary of policy evaluation outcomes for plan and apply runs against HCP Terraform. (#38715)

  • policy: Terraform now resolves policy plugin credentials from the configured cloud or remote backend during init, plan, and apply, rather than requiring the plugin to read credentials itself. (#38716)

  • graph: The terraform graph command can now output graphs in Mermaid format using the -format=mermaid flag. (#38719)

  • Child module outputs with unreferenced deprecated nested attributes no longer return deprecation warnings. (#38778)

  • Resource lifecycle blocks now support destroy = false to prevent a resource from being destroyed. (#38784)

  • The contains() function can now test for null values. (#38792)

  • console: The terraform console command now accepts an optional -scope=<module address> flag, which can be used to evaluate expressions within the scope of a module or a specific module instance. (#31861)

  • -invoke can now be combined with -target to specify the calling resource instance when multiple resources trigger the same action. (#38845)

  • The terraform stacks command now automatically infers the target hostname from the local credentials file (credentials.tfrc.json) when neither TF_STACKS_HOSTNAME nor TF_CLOUD_HOSTNAME is set (#38896)

BUG FIXES:

  • import blocks now correctly respect provider local names. (#38338)

  • terraform apply no longer panics when the plan contains a no-op change for a deposed resource that has lifecycle.precondition or lifecycle.postcondition blocks. (#38586)

  • workspace: Terraform now raises an error if an invalid workspace name becomes selected due to out-of-band changes. (#38594)

  • test: Terraform now raises a warning when a file referenced via the -filter flag does not exist. (#38603)

  • init: Terraform no longer removes locks from the dependency lock file for providers configured as dev_override. (#38634)

  • init: Terraform now warns when unmanaged providers are in use and may impact provider installation. (#38656)

  • Actions are now invoked with respect to all resource dependencies. (#38668)

  • Terraform now returns the correct error when an import target exists in state but has no corresponding configuration. (#38782)

  • The merge() function no longer panics when passed null objects. (#38792)

  • Allow underscores in provider source address namespaces, so private registry provider addresses are no longer rejected as invalid (#38894)

  • test: Optional ephemeral values do not have to be set at plan time (#38974)

NOTES:

  • init: Errors due to incompatible -upgrade and -lockfile=readonly flags are now raised earlier in the init process. (#38561)

UPGRADE NOTES:

  • bastion_host_key is now correctly applied by provisioners. Review your provisioner configurations to verify the configured key is correct before upgrading. (#38318)
