#vllm v0.27.0

#vLLM v0.27.0 Release Notes

Destaques

Esta versão apresenta 561 commits de 242 colaboradores (64 novos)!

  • Suporte Kimi K3 com pilha completa chegando em uma versão: arquivos de modelo principal e kernels (#50089, #50000), frontends Python (#50093) e Rust (#50104), kernels AttnRes (#50090), suporte DeepGEMM (#50458), pontos de verificação quantizados de tensores compactados (#50500), fusão DSpark AR (#50242) e uma opção para fragmentar o especialista compartilhado em vez de replicá-lo (#50656).
  • Mais novos modelos: modelos Qwen3.5 denso somente de texto e MoE (#50210) com remoção de token de vídeo EVS (#48912), K-EXAONE-2.0-750B-A37B (#50524), VaultGemma por meio do back-end de modelagem de Transformers (#49803) e jina-embeddings-v5-text-nano (#50688).
  • Atualização do PyTorch 2.13.0 junto com torchvision 0.28.0 e Triton 3.7.1 (#48155) — esta é uma mudança de ambiente inovadora; XPU (#48677) e CPU (#50412) seguiram para incendiar o 2.13 também.
  • A integração do FlashAttention 4 se aprofunda no SM100: suporte ao cache FP8 KV (nº 42569) e suporte ao headdim-256 (nº 42669), apoiado por uma nova infraestrutura de aquecimento JIT (nº 47451) e aquecimento do kernel Triton de propriedade do executor (nº 49903) que removem paralisações de compilação na primeira solicitação.
  • Impulso de desempenho do DeepSeek-V4: paralelismo de sequência (#46789), ~2x melhoria do kernel ignorando inicializações c128 vazias (#48957), 3.4% E2E TTFT de pular topk/roteador desnecessário (#49486), 3.9% E2E TTFT de reutilização de espaço de trabalho (#49236), kernel 1.88x de remoção de um kernel completo redundante (#50298), largura topk adaptável (1.0% E2E, #50004), memória GPU de 448 MiB salva no buffer PP (#50312), um cache KV indexador MXFP4 compacto (#48993) e remoção de preenchimento esparso-MLA q-head no FlashInfer >= 0.6.14 (#48047).
  • Model Runner V2 se expande para cargas de trabalho não generativas: atenção somente do codificador (#49331), pooling de sequências para incorporação/classificação (#48791), classificação de token do codificador (#50293) e incorporação de token (#50574), pooling BGE-M3 (#50661), multimodal na CPU (#50073), um especulador MTP multicamadas (#48892), e PCP agora seleciona MRV2 (#50034).
  • Serviço resiliente em grande escala: uma estrutura de tolerância a falhas (simplificada) para implantações de balanceador de carga externo DP+EP (#44428) e preparação assíncrona para escalabilidade EP elástica (#47288).
  • Desagregação para modelos híbridos: NIXL P/D para modelos híbridos MLA+SSM (nº 49762), tamanhos de bloco P/D heterogêneos para modelos híbridos (nº 49612) e roteamento de leitura de pré-preenchimento/decodificação heterogêneo MoRIIO TP<->DP (nº 46116).
  • O front-end Rust desenvolve um plano de controle gRPC: relatórios de integridade com reconhecimento de mecanismo (#48992), controle de aborto (#49255), descoberta de servidor e modelo (#49491), descoberta de fonte de evento KV (#50033), além de vllm-bench integrado ao vllm CLI (#48930).
  • Ativação antecipada de hardware de próxima geração: alvo sm_107 para NVIDIA Rubin (#49387) com caminhos totalmente reduzidos NVLink em SM107 (#49647) e arquitetura ROCm gfx1250 habilitada (#46516).

Suporte ao modelo

  • Kimi K3: novo modelo (#50000) com arquivos de modelo e kernels (#50089), frontend Python (#50093), frontend Rust (#50104), kernels AttnRes (#50090), suporte DeepGEMM (#50458), DSpark AR fusion (#50242) e fragmentação opcional de especialista compartilhado (#50656).
  • Novos modelos: Qwen3.5 somente texto denso e MoE (#50210), K-EXAONE-2.0-750B-A37B (#50524), VaultGemma via backend Transformers (#49803), jina-embeddings-v5-text-nano com backbone do codificador EuroBERT (#50688).
  • Inkling: pesos NVFP4 do compressor llm (#49258) e tensores comprimidos dinâmicos FP8 (#48876).
  • Multimodal: remoção de token de vídeo VidCom2 (#47750), EVS para Qwen3.5 (#48912), gráfico ViT CUDA para Gemma-4 (#46837), remapeamento Cosmos3 FP8 ModelOpt/Diffusers (#48952), verificação de decodificação especulativa MSA MiniMax-M3 (#50032) e processador de vídeo padrão (#50305), Otimização DeepSeek-OCR-2 TTFT (#49531), duração máxima de áudio mais longa para MOSS-TD (#49403).
  • Modelos de difusão: amostragem top_k e top_p para DiffusionGemma (#45429).
  • Back-end de modelagem de transformadores: suporte a modelo de áudio (#39330), rastreador fx aprimorado (#49957), adição residual fundida + passagem de compilação RMSNorm (#48757) e correções para preenchimento MLA + roteamento topk agrupado (#49982), MQA com TP (#49987) e Qwen3-VL M-RoPE (#49292).

Núcleo do motor

  • Aquecimento: nova infraestrutura de aquecimento JIT (#47451), kernels Triton de propriedade do executor aquecidos antes da primeira solicitação (#49903) e aquecimento adequado do renderizador (#50408).
  • Atenção: cache FlashAttention 4 SM100 FP8 KV (#42569) e headdim-256 (#42669); replicação de consulta para decodificação MLA sob DCP para DeepSeek-V2/R1 e Kimi-K2.5 (#45964); MHA mascarado para pré-preenchimentos de MLA esparsos (#48770); pular pontuação esparsa do indexador para pré-preenchimentos curtos e densos (#48407); Gancho de epílogo FlexAttention (#45841) e explosão de compilação de máscara de bloco do codificador evitada (#50339); back-ends de atenção permanecem elegíveis para veiculação somente de texto de modelos LM de prefixo (#48796); contagem de contexto de atenção de mesclagem como argumento de tempo de execução (#48739); suporte a gráfico CUDA do codificador multicaminho unificado (#49934); ganchos de extensão de cache do codificador (#48218).
  • Modelo Runner V2: atenção somente do codificador (#49331), pooling de sequências para incorporação e classificação (#48791), classificação de token do codificador (#50293), incorporação de token do codificador (#50574), pooling BGE-M3 (#50661), multimodal na CPU (#50073), especulador MTP multicamadas (#48892), PCP seleciona MRV2 (#50034), metadados de atenção sempre criados no momento da captura (#49364), perfil de cache do codificador (#47985), materialização de logits FP32 não operacionais ignorados (#47711), amostrador de rejeição fragmentado para evitar OOM (#48630), menos sincronizações de GPU<->CPU no Mamba híbrido (#49736).
  • Descarregamento de KV: camada secundária P2P genérica com pesquisa/exibição de pares (#48021), filtragem de camada por solicitação com TierFilter/TierMatcher (#48123), eventos KV autodescritivos com TieringOffloadingSpec (#48679), políticas de despejo conectáveis via CachePolicyFactory (#49114), MLA KV replicado desduplicado na CPU compartilhada região (#48906), layout MLA de cópia única para CPUOffloadingSpec (#50301), CPUOffloadingSpec movido para SharedOffloadRegion (#50094), identidade secundária compacta independente de TP (#49858), armazenamento/carga C em lote para descarregamento do sistema de arquivos (#49152), descarregamento parcial confiável para prompts de subbloco (#49502), mapeamentos de páginas KV canônicos por camada para descarregamento independente de paralelismo (#48408).
  • Mamba/híbrido: cache ReplaySSM para decodificação padrão Mamba2 mais rápida (#48018), migração de estado DS-conv em modo de alinhamento fundido com num_accepted_tokens > 1 (#49291), seleção de algoritmo FlashInfer Mamba SSU (#50157), falha /wake_up corrigida em modelos híbridos (#41602).
  • Decodificação de especificação: cabeça DSpark Markov replicada em classificações TP (#49731), sample_from_anchor carregado a partir da configuração de especuladores (#48639), string de parada de conclusão mais antiga selecionada (#49391).
  • Resultados estruturados: gramática avançada através dos limites do raciocínio com decodificação específica (#44993).
  • Desempenho de pré-processamento: desrenderização do trabalho da CPU transferido para o pool de threads do renderizador (#49396), pré-processamento de prompt bruto fora do loop de eventos em AsyncLLM (#49608), pré-processamento multimodal isolado em seu próprio executor (#49524), MM incorpora carregamento adiado do loop de eventos (#49477), pré-processamento paralelo em uma solicitação de pooling online (#49153), vídeos com hash por bytes de origem (#49607), modo de imagem original preservado em ImageIO (#49159).
  • RL: marcação de versão de peso para implementações de RL (#49040), IPC de envio de instrutor com estado (#48981), configuração de vLLM definida durante a recarga de peso (#45989), saída de repetição do roteador do kernel MoE monolítico FlashInfer (#44214).
  • Memória e robustez: contabilidade de fragmentação CuMem sleep-L1 (#49208), limites de memória cgroup respeitados em todas as plataformas (#49966), falha rápida quando /dev/shm é muito pequeno (#48879), decapagem de tensor de cópia zero em shm_broadcast (#48442), divisão de hash LRU ignorada em free_blocks quando o cache de prefixo está desativado (#48017), caminho derivado de localização vars excluídos dos fatores de cache torch.compile (#47573), CustomOp.forward_native compilado para ReLU ^ 2 (#50244), configuração HF usada para tokenizers HF (#49907), RMSNorm invariável em lote por meio de tamanho de bloco fixado (#48391).

Hardware e desempenho

  • DeepSeek-V4: paralelismo de sequência (#46789), ~2x kernel ignorando inicializações c128 vazias (#48957), 3.4% E2E TTFT ignorando topk/roteador na decodificação (#49486), 3.9% E2E TTFT reutilização de espaço de trabalho (#49236), kernel 1.88x removendo um kernel completo redundante (#50298), largura topk adaptável 1.0% E2E (#50004), 448 MiB de memória GPU salva (#50312), cache KV do indexador MXFP4 compacto (#48993), preenchimento esparso-MLA q-head removido para FlashInfer >= 0.6.14 (#48047).
  • Kernels: suporte não contíguo RMSNorm com melhoria de kernel 1.2 – 3.1x (#49750), correção de regressão MoE reduce_scatter restaurando 5% da taxa de transferência E2E (#48763), roteamento topk sem polarização não agrupado despachado para o caminho fundido (#49618), roteador LL BF16 GEMM ajustado (#48774) com aquecimento ignorado para não-MoE modelos (#49659), caminho do descritor de tensor Triton para MoE fundido via VLLM_TRITON_USE_TD (#42436), preenchimento cudagraph/DP ignorado em topk (#48979), acesso HBM coalescido no kernel de pré-processamento Marlin INT4-FP8 AWQ (#47268).
  • NVIDIA de última geração: sm_107 para Rubin (#49387), caminhos totalmente reduzidos NVLink no SM107 (#49647), detecção de arco CUDA corrigida produzindo compilações sem kernel no SM121 (#49904).
  • ROCm: arquitetura gfx1250 habilitada (#46516), atenção do codificador AITER FP8 ViT (#49937), especialista compartilhado fundido para pontos de verificação Quark DeepSeek-V4 (#48044), correções de inferência de ponto de verificação Quark GLM-5.2 (#48886), lançamentos de FillFunctor por decodificação DSv3.2 eliminados no hot loop MLA esparso (#44527), projeções FP8 de atenção pré-embaralhadas B para DSv4 (#46720), TML Inkling habilitado (#48841), configuração selective_state_update float16 ajustada para MI325X (#50006), MRoPE estilo GPT-J fixo e otimizado (#49906), correção de precisão de redução rápida no modo cudagraph (#46913), upcast fp32 em cache de escalas de peso estáticas e8m0 (#47773), DMA em lote para cargas de cache KV da CPU (#49843), correção de precisão de escalabilidade EP elástica (#47206).
  • XPU: QK Norm + RoPE fusion pass (#49394), FP8 o_proj com fp8_bmm e transposição de escala de tempo de carregamento (#48334), DeepSeek-V4 fuse_index_q caminho do kernel SYCL (#45991), carregamentos de operandos TD para MoE GEMM em lote (#46340), kernels RMSNorm unificados com vllm_c (#46981).
  • CPU: Kernel MoE fundido INT8 para CPUs Arm (#48637), otimização de inferência s390x com oneDNN INT8 GEMM (#50219), caminho de conversão GDN otimizado para decodificação especulativa (#48577), granito-4 habilitado (#47641), FAST_EXP para Power (#49571), kernels de CPU atualizados para a versão mais recente (#50387), correções de compilação do macOS (#49021, #50915).

Servido e distribuído em grande escala

  • Estrutura de tolerância a falhas (simplificada) para implantações de LB externo DP+EP (#44428).
  • Elastic EP: preparação assíncrona (#47288) e correção de transferência de peso não contígua (#50641).
  • Desagregação P/D: NIXL P/D para modelos híbridos MLA+SSM (#49762), tamanhos de bloco P/D heterogêneos NIXL para modelos híbridos (#49612), TP heterogêneo MoRIIO<->Roteamento de leitura de pré-preenchimento/decodificação DP (#46116), desativação de pesquisa opcional na decodificação PD (#50498), IDs de token de pré-preenchimento reutilizados no caminho de bate-papo de decodificação (#48145), destokenização streaming derender (#47301), NixlPush pula uma etapa extra de handshake em D->P (#49345).
  • Correções: corrida de preempção P/D (#50297), prazos de locação KV rebaseados no relógio do trabalhador (#50326), NIXL híbrido MLA+mamba TP heterogêneo (#49297), balanceamento de carga LB interno (#49204).
  • Mooncake: prepare_value vetorizado no caminho de carga KV (#48531), acessos externos completos re-derivados em limites armazenados (#49481).
  • Conectores de cache do codificador: has_pending_push_work (#49582).
  • Comunicadores: ganchos de ciclo de vida de ponto de verificação de processo, começando com FlashInfer (#46877).

Quantização

  • Novos recursos: integração FP4 Qutlass para tensores compactados (#43229), CuTeDSL MoE para ReLU2 NVFP4 (#49580), suporte linear MXFP8 em INC (#47514), AutoRound W4A16 MoE e MXFP4 linear/MoE em XPU (#47124), modo quant KV para TurboQuant (#50533), emulação ModelOpt FP8 em SM80 (#50019), --linear-backend homenageado pelo ModelOpt W4A16 (#50273).
  • Pontos de verificação: suporte a tensores compactados para DeepSeek-V4 (#41276) e Kimi-K3 (#50500); find_matched_target prioriza correspondências de nomes fundidos (#49483).
  • Refatorador MoE: FusedMoE renomeado para FusedMoEFactory (#44941), MoeWNA16 migrou para o esquema oracle MK (#44120), Quark w8a8-int8 (#46765) e backends MXFP4 aiter/emulation (#49348, #48949) movidos para abstrações de kernel, métodos CT WNA16 Marlin/MoE mesclado (#44570), cobertura Quark W4A8 (INT4-FP8) MoE CI (#48050).

API e interface

  • Frontend Rust: plano de controle gRPC com relatórios de integridade do motor (#48992), RPC de controle de aborto (#49255), descoberta de servidor e modelo (#49491) e descoberta de fonte de evento KV (#50033); vllm-bench integrado em vllm-rs e vllm CLI (#48930) com delegação Rust opcional para vllm bench serve (#50081); fatiamento de tensor multimodal de cópia zero (#48781), tensores multimodais em quadros auxiliares (#49341), --limit-mm-per-prompt (#49604), codificação de tokenizador de texto comum (#49992).
  • APIs: Suporte Cohere chat v2 API (#47189), cache_salt nas mensagens antrópicas API (#49498), chamada de ferramenta estrita e decodificação restrita para GPT-OSS Harmony (#45560), analisador Mistral baseado em mecanismo unificado para raciocínio e chamadas de ferramenta (#48947), stream_interval exposto como um parâmetro de amostragem por solicitação (#49754), parâmetros de amostragem adicionais para a tradução API (#45839), diarized_json para MOSS-Transcribe-Diarize (#48543), carimbos de data e hora cumulativos de pedaços de fala para texto (#41131).
  • Multimodal: seleção de algoritmo hash mm via CLI (#49686), simultaneidade de decodificador PyNvVideoCodec configurável (#49753), parâmetros RFC 2397 aceitos em URLs de dados base64 (#48973).
  • UX e validação: tratamento de erros de solicitação padronizado com uma hierarquia VLLMError (#49665), ruído de log de inicialização reduzido (#50590), substituições de tempo de execução aninhadas incompatíveis rejeitadas (#49247), validação de inicialização paralela de dados aprimorada (#49124), validação de topologia DCP (#49777), 400 em vez de 500 para logprobs não numéricos (#49144), texto simples do Inkling preservado nos analisadores Python e Rust (#50403).
  • Benchmarks: solicitações de sondagem em vllm bench serve (#49611).

vllm v0.27.0

vLLM v0.27.0 Release Notes

Highlights

This release features 561 commits from 242 contributors (64 new)!

  • Kimi K3 support with a full stack landing in one release: core model files and kernels (#50089, #50000), Python (#50093) and Rust (#50104) frontends, AttnRes kernels (#50090), DeepGEMM support (#50458), compressed-tensors quantized checkpoints (#50500), DSpark AR fusion (#50242), and an option to shard the shared expert instead of replicating it (#50656).
  • More new models: Qwen3.5 text-only dense and MoE models (#50210) with EVS video token pruning (#48912), K-EXAONE-2.0-750B-A37B (#50524), VaultGemma via the Transformers modeling backend (#49803), and jina-embeddings-v5-text-nano (#50688).
  • PyTorch 2.13.0 upgrade along with torchvision 0.28.0 and Triton 3.7.1 (#48155) — this is a breaking environment change; XPU (#48677) and CPU (#50412) followed to torch 2.13 as well.
  • FlashAttention 4 integration deepens on SM100: FP8 KV cache support (#42569) and headdim-256 support (#42669), backed by a new JIT warmup infrastructure (#47451) and runner-owned Triton kernel warmup (#49903) that remove first-request compilation stalls.
  • DeepSeek-V4 performance push: sequence parallelism (#46789), ~2x kernel improvement by skipping empty c128 launches (#48957), 3.4% E2E TTFT from skipping unneeded topk/router (#49486), 3.9% E2E TTFT from workspace reuse (#49236), 1.88x kernel from removing a redundant full kernel (#50298), adaptive topk width (1.0% E2E, #50004), 448 MiB GPU memory saved in the PP buffer (#50312), a compact MXFP4 indexer KV cache (#48993), and removal of sparse-MLA q-head padding on FlashInfer >= 0.6.14 (#48047).
  • Model Runner V2 expands to non-generative workloads: encoder-only attention (#49331), sequence pooling for embedding/classification (#48791), encoder token classification (#50293) and token embedding (#50574), BGE-M3 pooling (#50661), multimodal on CPU (#50073), a multi-layer MTP speculator (#48892), and PCP now selects MRV2 (#50034).
  • Resilient large-scale serving: a (simplified) fault tolerance framework for DP+EP external load-balancer deployments (#44428) and async preparation for elastic EP scaling (#47288).
  • Disaggregation for hybrid models: NIXL P/D for hybrid MLA+SSM models (#49762), heterogeneous P/D block sizes for hybrid models (#49612), and MoRIIO heterogeneous TP<->DP prefill/decode read routing (#46116).
  • Rust frontend grows a gRPC control plane: engine-aware health reporting (#48992), abort control (#49255), server and model discovery (#49491), KV event source discovery (#50033), plus vllm-bench integrated into the vllm CLI (#48930).
  • Early next-gen hardware enablement: sm_107 target for NVIDIA Rubin (#49387) with NVLink all-reduce paths on SM107 (#49647), and ROCm gfx1250 architecture enabled (#46516).

Model Support

  • Kimi K3: new model (#50000) with model files and kernels (#50089), Python frontend (#50093), Rust frontend (#50104), AttnRes kernels (#50090), DeepGEMM support (#50458), DSpark AR fusion (#50242), and optional shared-expert sharding (#50656).
  • New models: Qwen3.5 text-only dense and MoE (#50210), K-EXAONE-2.0-750B-A37B (#50524), VaultGemma via Transformers backend (#49803), jina-embeddings-v5-text-nano with EuroBERT encoder backbone (#50688).
  • Inkling: llm-compressor NVFP4 weights (#49258) and compressed-tensors dynamic FP8 (#48876).
  • Multimodal: VidCom2 video token pruning (#47750), EVS for Qwen3.5 (#48912), ViT CUDA graph for Gemma-4 (#46837), Cosmos3 FP8 ModelOpt/Diffusers remapping (#48952), MiniMax-M3 MSA speculative decode verification (#50032) and default video processor (#50305), DeepSeek-OCR-2 TTFT optimization (#49531), longer max audio duration for MOSS-TD (#49403).
  • Diffusion models: top_k and top_p sampling for DiffusionGemma (#45429).
  • Transformers modeling backend: audio model support (#39330), improved fx tracer (#49957), fused residual-add + RMSNorm compilation pass (#48757), and fixes for MLA padding + grouped topk routing (#49982), MQA with TP (#49987), and Qwen3-VL M-RoPE (#49292).

Engine Core

  • Warmup: new JIT warmup infrastructure (#47451), runner-owned Triton kernels warmed before the first request (#49903), and proper renderer warmup (#50408).
  • Attention: FlashAttention 4 SM100 FP8 KV cache (#42569) and headdim-256 (#42669); query replication for MLA decode under DCP for DeepSeek-V2/R1 and Kimi-K2.5 (#45964); masked MHA for sparse MLA prefills (#48770); skip sparse indexer scoring for short dense prefills (#48407); FlexAttention epilogue hook (#45841) and encoder block-mask compile explosion avoided (#50339); attention backends stay eligible for text-only serving of prefix-LM models (#48796); merge-attention context count as a runtime argument (#48739); unified multi-path encoder CUDA graph support (#49934); encoder cache extension hooks (#48218).
  • Model Runner V2: encoder-only attention (#49331), sequence pooling for embedding and classification (#48791), encoder token classification (#50293), encoder token embedding (#50574), BGE-M3 pooling (#50661), multimodal on CPU (#50073), multi-layer MTP speculator (#48892), PCP selects MRV2 (#50034), attention metadata always built at capture time (#49364), encoder cache profiling (#47985), skipped no-op FP32 logits materialization (#47711), chunked rejection sampler to avoid OOM (#48630), fewer GPU<->CPU syncs in hybrid Mamba (#49736).
  • KV offloading: generic P2P secondary tier with peer lookup/serving (#48021), per-request tier filtering with TierFilter/TierMatcher (#48123), self-describing KV events with TieringOffloadingSpec (#48679), pluggable eviction policies via CachePolicyFactory (#49114), deduplicated replicated MLA KV in the shared CPU region (#48906), single-copy MLA layout for CPUOffloadingSpec (#50301), CPUOffloadingSpec moved onto SharedOffloadRegion (#50094), TP-independent compact secondary identity (#49858), batched C store/load for filesystem offload (#49152), reliable partial-tail offload for sub-block prompts (#49502), per-layer canonical KV page mappings for parallelism-agnostic offload (#48408).
  • Mamba/hybrid: ReplaySSM caching for faster Mamba2 standard decode (#48018), fused align-mode DS-conv state migration with num_accepted_tokens > 1 (#49291), FlashInfer Mamba SSU algorithm selection (#50157), fixed /wake_up crash on hybrid models (#41602).
  • Spec decode: DSpark Markov head replicated across TP ranks (#49731), sample_from_anchor loaded from speculators config (#48639), earliest-completing stop string selected (#49391).
  • Structured outputs: grammar advanced across the reasoning boundary with spec decode (#44993).
  • Preprocessing performance: derender CPU work offloaded to the renderer thread pool (#49396), raw-prompt preprocessing off the event loop in AsyncLLM (#49608), multimodal preprocessing isolated on its own executor (#49524), MM embeds loading deferred off the event loop (#49477), parallel preprocessing within a request for online pooling (#49153), videos hashed by source bytes (#49607), original image mode preserved in ImageIO (#49159).
  • RL: weight version tagging for RL rollouts (#49040), stateful trainer-send IPC (#48981), vLLM config set during weight reload (#45989), router replay output from the FlashInfer monolithic MoE kernel (#44214).
  • Memory & robustness: CuMem slept-L1 fragmentation accounting (#49208), cgroup memory limits respected on all platforms (#49966), fail fast when /dev/shm is too small (#48879), zero-copy tensor pickling in shm_broadcast (#48442), LRU hash-split skipped in free_blocks when prefix caching is off (#48017), location-derived path vars excluded from torch.compile cache factors (#47573), CustomOp.forward_native compiled for ReLU^2 (#50244), HF config used for HF tokenizers (#49907), batch-invariant RMSNorm via pinned block size (#48391).

Hardware & Performance

  • DeepSeek-V4: sequence parallelism (#46789), ~2x kernel skipping empty c128 launches (#48957), 3.4% E2E TTFT skipping topk/router in decode (#49486), 3.9% E2E TTFT workspace reuse (#49236), 1.88x kernel removing a redundant full kernel (#50298), adaptive topk width 1.0% E2E (#50004), 448 MiB GPU memory saved (#50312), compact MXFP4 indexer KV cache (#48993), sparse-MLA q-head padding removed for FlashInfer >= 0.6.14 (#48047).
  • Kernels: RMSNorm uncontiguous support with 1.2–3.1x kernel improvement (#49750), MoE reduce_scatter regression fix restoring 5% E2E throughput (#48763), non-grouped bias-less topk routing dispatched to the fused path (#49618), tuned LL BF16 router GEMM (#48774) with warmup skipped for non-MoE models (#49659), Triton tensor-descriptor path for fused MoE via VLLM_TRITON_USE_TD (#42436), cudagraph/DP padding skipped in topk (#48979), coalesced HBM access in the Marlin INT4-FP8 AWQ preprocess kernel (#47268).
  • NVIDIA next-gen: sm_107 for Rubin (#49387), NVLink all-reduce paths on SM107 (#49647), fixed CUDA arch detection producing kernel-less builds on SM121 (#49904).
  • ROCm: gfx1250 architecture enabled (#46516), AITER FP8 ViT encoder attention (#49937), fused shared expert for Quark DeepSeek-V4 checkpoints (#48044), Quark GLM-5.2 checkpoint inference fixes (#48886), DSv3.2 per-decode FillFunctor launches eliminated in the sparse-MLA hot loop (#44527), B-preshuffled attention FP8 projections for DSv4 (#46720), TML Inkling enabled (#48841), tuned selective_state_update float16 config for MI325X (#50006), GPT-J-style MRoPE fixed and optimized (#49906), quickreduce accuracy fix in cudagraph mode (#46913), cached fp32 upcast of static e8m0 weight scales (#47773), batch DMA for CPU KV cache loads (#49843), elastic EP scaling accuracy fix (#47206).
  • XPU: QK Norm + RoPE fusion pass (#49394), FP8 o_proj with fp8_bmm and load-time scale transpose (#48334), DeepSeek-V4 fuse_index_q SYCL kernel path (#45991), TD operand loads for batched MoE GEMM (#46340), RMSNorm kernels unified with vllm_c (#46981).
  • CPU: INT8 fused MoE kernel for Arm CPUs (#48637), s390x inference optimization with oneDNN INT8 GEMM (#50219), GDN conv path optimized for speculative decoding (#48577), granite-4 enabled (#47641), FAST_EXP for Power (#49571), CPU kernels bumped to the latest version (#50387), macOS build fixes (#49021, #50915).

Large Scale Serving & Distributed

  • Fault tolerance framework (simplified) for DP+EP external LB deployments (#44428).
  • Elastic EP: async preparation (#47288) and non-contiguous weight transfer fix (#50641).
  • P/D disaggregation: NIXL P/D for hybrid MLA+SSM models (#49762), NIXL heterogeneous P/D block sizes for hybrid models (#49612), MoRIIO heterogeneous TP<->DP prefill/decode read routing (#46116), optional lookup disable on PD decode (#50498), prefill token ids reused on the decode chat path (#48145), detokenization streaming derender (#47301), NixlPush skips an extra handshake step in D->P (#49345).
  • Fixes: P/D preemption race (#50297), KV lease deadlines rebased onto the worker clock (#50326), NIXL hybrid MLA+mamba heterogeneous TP (#49297), internal LB load-balancing (#49204).
  • Mooncake: vectorized prepare_value on the KV load path (#48531), full external hits re-derived on stored boundaries (#49481).
  • Encoder-cache connectors: has_pending_push_work (#49582).
  • Communicators: process-checkpoint lifecycle hooks, starting with FlashInfer (#46877).

Quantization

  • New capabilities: FP4 Qutlass integration for compressed-tensors (#43229), CuTeDSL MoE for ReLU2 NVFP4 (#49580), MXFP8 linear support in INC (#47514), AutoRound W4A16 MoE and MXFP4 linear/MoE on XPU (#47124), KV quant mode for TurboQuant (#50533), ModelOpt FP8 emulation on SM80 (#50019), --linear-backend honored for ModelOpt W4A16 (#50273).
  • Checkpoints: compressed-tensors support for DeepSeek-V4 (#41276) and Kimi-K3 (#50500); find_matched_target prioritizes fused-name matches (#49483).
  • MoE refactor: FusedMoE renamed to FusedMoEFactory (#44941), MoeWNA16 migrated to the MK oracle scheme (#44120), Quark w8a8-int8 (#46765) and MXFP4 aiter/emulation backends (#49348, #48949) moved to kernel abstractions, CT WNA16 Marlin/MoE methods merged (#44570), Quark W4A8 (INT4-FP8) MoE CI coverage (#48050).

API & Frontend

  • Rust frontend: gRPC control plane with engine-aware health reporting (#48992), abort control RPC (#49255), server and model discovery (#49491), and KV event source discovery (#50033); vllm-bench integrated into vllm-rs and the vllm CLI (#48930) with opt-in Rust delegation for vllm bench serve (#50081); zero-copy multimodal tensor slicing (#48781), multimodal tensors in auxiliary frames (#49341), --limit-mm-per-prompt (#49604), ordinary-text tokenizer encoding (#49992).
  • APIs: Cohere chat v2 API support (#47189), cache_salt in the Anthropic Messages API (#49498), strict tool calling and constrained decoding for GPT-OSS Harmony (#45560), unified engine-based Mistral parser for reasoning and tool calls (#48947), stream_interval exposed as a per-request sampling param (#49754), additional sampling parameters for the translation API (#45839), diarized_json for MOSS-Transcribe-Diarize (#48543), cumulative speech-to-text chunk timestamps (#41131).
  • Multimodal: mm hash algorithm selection via CLI (#49686), configurable PyNvVideoCodec decoder concurrency (#49753), RFC 2397 parameters accepted in base64 data URLs (#48973).
  • UX & validation: standardized request error handling with a VLLMError hierarchy (#49665), reduced startup log noise (#50590), incompatible nested runtime overrides rejected (#49247), improved data-parallel launch validation (#49124), DCP topology validation (#49777), 400 instead of 500 for non-numeric logprobs (#49144), bare Inkling text preserved in Python and Rust parsers (#50403).
  • Benchmarks: probe requests in vllm bench serve (#49611).

Dependencies

  • PyTorch 2.13.0, torchvision 0.28.0, Triton 3.7.1 (#48155); torch 2.13 for XPU (#48677) and CPU (#50412).
  • Transformers 5.14.1 (#49223), FlashInfer 0.6.15 (#48914) then 0.6.16.post3 (#50892), AITER 0.1.16.post5 (#48683) then 0.1.19 (#49361), NCCL 2.30.7 enabling DeepEPv2 in the vllm/vllm-openai image (#45321), tpu-inference v0.25.0 (#49431) then v0.26.0 (#50522), Helion 1.4.0 (#50307), NIXL and UCX upgraded on ROCm (#49251).
  • Build: vllm-flash-attn bumped to a C++20-compatible commit for torch-nightly (#49326), ABI-stable FA2 build pin (#50474).

Deprecations & Removals

  • Models removed: Plamo2 (#49729), Ouro (#49786).
  • Removed the no-longer-supported max_num_partial_prefills and max_long_partial_prefills arguments (#49244).
