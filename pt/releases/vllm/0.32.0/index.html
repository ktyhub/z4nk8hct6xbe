#v0.32.0

Destaques

Esta versão apresenta 814 commits de 363 colaboradores (121 novos)!

  • Decisões estruturadas e analisadores genéricos: o novo endpoint POST /v1/systemone responde a perguntas choice, noul e score em um estado estruturado (#59299), é servido por padrão (#60677, #60696) e também é executado em Cloudflare/clef-omni (#61064), LiquidAI/d1-3B (#60676) e DiffusionGemma (#60466). A nova ferramenta e analisador de raciocínio hf (--tool-call-parser hf, --reasoning-parser hf) lê o response_template do ponto de verificação, portanto, os modelos que o enviam não precisam de analisador específico do modelo (#58604, #58602), tanto nos frontends Python quanto no Rust (#59005).
  • Cache KV de baixa precisão em todos os lugares: O cache KV NVFP4 agora é executado em SM8x e SM12x (#46963), SM90 (#60620) e com decodificação XQA em SM12x (#60452), e no MiniMax-M3 atenção escassa em SM100 (#59300); O padrão GLM-5.x é um cache KV FP8 no SM100, reduzindo pela metade a memória KV por classificação com 2.3-5.5% mais rendimento a um custo TTFT de 7-11% no benchmark do PR (#60140, #60281); fp8_ds_mla no SM90 oferece ao GLM-5.3-Flash até 31% mais rendimento de saída (#59246); ROCm ganha o cache ultraquant_4bit KV de 4 bits com cerca de 2x a densidade de FP8 (#57057).
  • Model Runner V2: um especulador GPU n-gram com rascunhos de comprimento variável (#40704), Elastic EP (#53934), paralelismo de pipeline com paralelismo de contexto pré-preenchido para modelos MLA (#59139), um modo stock torch.compile (#59079) e MRV2 agora é o padrão no ROCm com as exceções MRV1 específicas do modelo removidas (#56360).
  • Inicialização e serviço mais rápidos: vllm download-kernels instala os kernels pré-compilados do FlashInfer (#58765); vllm preload --preload-autotune mantém a tabela de ajuste automático FlashInfer aquecida durante as reinicializações (#60085); uma arena de tensores de memória compartilhada transmite grandes tensores multimodais para trabalhadores com uma cópia (#51207); tokenizadores e processadores são carregados a partir do snapshot local (#60825); e com --api-server-count acima de 1, cada conexão vai para o trabalhador API menos carregado, para 43-85% mais req/s em solicitações curtas (Qwen3-0.6B, 32 tokens de entrada/1 saída) no benchmark do PR (#60723).
  • Suporte ao modelo: novos embeddings omnimodais EmbeddingGemma 2 (#60254), MiniCPM-V 4.7 (#58674) e Nemotron 3.5 ASR (#59827); entrada de vídeo no backend de modelagem do Transformers (#57441); Conversões de índice MLA esparsas GLM-5.3 reutilizadas entre camadas (3.5-3.9x naquele kernel, #59464) e decodificação de rascunho de várias etapas fundidas (13.3% na simultaneidade 1, #57443); Cache de residência HiSparse por solicitação para até 58% mais rendimento no GLM-5.3-NVFP4 no B200 com contextos longos e totalmente residentes em GPU em alta simultaneidade (#60083).
  • Segurança: correções para GHSA-4hhp-h66f-j5j7 (esgotamento de recursos do modelo de bate-papo, #50300), GHSA-q97c-p368-75c4 (tokenizer max_token_id, #59491) e GHSA-frvg-qw88-hww9 (esgotamento de soquete P2P ZMQ, #51504); O CORS não permite mais todas as origens por padrão (#61009); imagens untrusted são limitadas a formatos raster (#60022); identificadores de cache multimodal de memória compartilhada são assinados (#59357); e esquemas JSON aninhados com mais de 64 níveis são rejeitados (#60036).
  • Alterações importantes: Python 3.10 descartado (#60402); origens CORS padrão restritas (#61009); transformers>=5.16.1,<5.20.0 e tokenizers>=0.23.2 (#57387, #59796); Paralelismo de sequência torch.compile e passagens AsyncTP removidas (#60517); atenção em cascata removida (#61126); mamba_cache_mode="all" removido (#58997); max_tokens não está mais reservado na janela de contexto (#57035); Eventos de fluxo de raciocínio de respostas API renomeados (#59652).

Segurança

  • GHSA-4hhp-h66f-j5j7: os modelos de bate-papo são validados estaticamente e renderizados sob um tempo limite (VLLM_CHAT_TEMPLATE_RENDER_TIMEOUT), o chat_template fornecido pelo usuário nas respostas chat_template_kwargs é rejeitado e a execução do modelo de frontend caps Rust (#50300).
  • GHSA-q97c-p368-75c4: tokenizer max_token_id corrigido off-by-one (#59491).
  • GHSA-frvg-qw88-hww9: As sessões de pares P2P ZMQ são limitadas por VLLM_P2P_MAX_PEERS (padrão 128), VLLM_P2P_HANDSHAKE_TIMEOUT_S (padrão 30) e VLLM_P2P_IDLE_TIMEOUT_S (padrão 300), portanto, endereços de pares exclusivos não podem mais esgotar os soquetes ZMQ (#51504).
  • As configurações padrão do CORS não permitem mais todas as origens nos frontends Python e Rust; configure --allowed-origins para permitir origens do navegador (#61009).
  • Imagens Untrusted são abertas com uma lista de permissões de formato raster (ALLOWED_IMAGE_FORMATS), negando EPS/PostScript e WMF (#60022); os identificadores de cache multimodal de memória compartilhada são assinados por HMAC e os identificadores forjados são rejeitados (#59357).
  • Esquemas JSON de saída estruturada aninhados em mais de 64 níveis retornam 400 (#60036); solicitações /v1/embeddings em pedaços mantêm cache_salt (#47696); O áudio Phi-4 MM não contém mais matrizes de atenção multi-GiB (#60614); Os tensores de pixel de soma zero DeepSeek-OCR não matam mais o EngineCore (#59417).
  • Problemas de dependência de segurança: aiohttp>=3.14.3, pillow>=12.3.0, criptografia, urllib3, pyjwt e outros (#59249, #59315, #59427).

  • NIXL 1.5.0 (#56907), CuTe DSL 4.8.0 APIs em escala de bloco (#59480), humming-kernels==0.1.17 com suporte Rubin inicial (#61556, #61858), InstantTensor 0.2.2 (#61167) e flashinfer-jit-cache excluídos da roda install_requires (#60052).
  • ROCm: AITER 0.1.24.post1 (#59794) e MoRI v1.2.3.post1 (#56073). XPU: biblioteca de arredondamento automático 0.16.0 (#60976). TPU: inferência tpu v0.31.0 (#60190).

Construir

  • Python 3.11-3.14 compatível (#60402); rodas macOS construídas com ABI estável (#60312); As compilações de origem CUDA exigem GCC 13 e, caso contrário, falham antecipadamente (#60259); As imagens Docker compilam o bytecode Python em tempo de construção para uma inicialização mais rápida do contêiner (#55422); VLLM_USE_PRECOMPILED encontra uma roda publicada compatível nos últimos 20 commits (#58871); o DeepGEMM vendido usa TORCH_LIBRARY (abi3, #48962).

Quebrando alterações e depreciações

  • Python 3.10 não é mais compatível; o mínimo é Python 3.11 (#60402).
  • Origens padrão do CORS alteradas de * para nenhuma; defina --allowed-origins para o navegador clients (#61009).
  • transformers>=5.16.1,<5.20.0 e tokenizers>=0.23.2 são necessários (#57387, #59796).
  • O paralelismo da sequência torch.compile e as passagens AsyncTP foram removidos, junto com PassConfig.enable_sp, fuse_gemm_comms e sp_min_token_num; o paralelismo de sequência em nível de modelo não é afetado (#60517).
  • A atenção em cascata foi removida; --disable-cascade-attn ainda analisa, mas apenas avisa e será removido em v0.33.0 (#61126).
  • mamba_cache_mode="all" foi removido; --mamba-cache-mode all agora falha na validação (#58997).
  • APIs anteriormente obsoletos foram removidos: wait_for_inflight_requests (use mode="wait"), AsyncLLM.pause_generation(), IOProcessor.output_to_response, vllm.scripts.main() e vllm bench throughput --dataset (#60923). O conjunto de dados de benchmark sonnet foi removido conforme programado (#60129). O suporte do tensor foi removido do LoRA (#60024) e a ponte PyO3 vllm._rust_tool_parser foi removida (#59744).
  • Mudanças no API: max_tokens é tratado como um limite superior na saída em vez de reservado na janela de contexto (#57035); O streaming de respostas API usa response.content_part.added/done com part.type="reasoning_text" em vez de response.reasoning_part.added/done (#59652); SamplingParams.prompt_logprob_token_ids é por linha (#56984); Os logprobs /inference/v1/generate usam IDs de token inteiro (#58181); as respostas sleep API são padronizadas e os níveis inválidos retornam 400 (#52864); return_mm_kwargs foi descontinuado em favor de mm_payload (#61427).
  • Marca d'água: quando o motor possui marca d'água configurada, um campo de solicitação omitido significa habilitado e apenas false desativa; combinações não suportadas avisam e retrocedem (#56801).
  • Frontend Rust: qwen3_xml agora analisa Qwen3-Coder XML (alias de qwen3_coder); use o novo qwen3_json para o formato JSON (#60136).
  • Novos padrões: arena de tensor de memória compartilhada ativada (#51207); Cache GLM-5.x FP8 KV no SM100 com --kv-cache-dtype auto (#60140, #60281); VLLM_DEEPEP_V2_ALLOW_HYBRID_MODE=1 (#57991); Humming preferiu Marlin no SM90 (#56997); sparse_mla_prefill_workspace_factor 2 acima de 256K max_model_len (#61023); MRV2 no ROCm com exceções MRV1 específicas do modelo removidas (#56360); VLLM_ROCM_AITER_MLA_DCP_VERIFY=auto (#59965); dtype=auto escolhe bfloat16 no PowerPC (#58528); Os pontos de verificação MXFP4 W4A4 voltam para W4A16 com um aviso quando não existe nenhum kernel W4A4 (#60079).
  • Validação mais rigorosa: --prefix-match-unit (#58021), max_num_scheduled_tokens=0 (#60714), HiSparse com cudagraph_mode=FULL (#59688) incompatível e --device-ids negativo (#49053) são rejeitados na inicialização.

Highlights

This release features 814 commits from 363 contributors (121 new)!

  • Structured decisions and generic parsers: the new POST /v1/systemone endpoint answers choice, noul and score questions over a structured state (#59299), is served by default (#60677, #60696), and also runs on Cloudflare/clef-omni (#61064), LiquidAI/d1-3B (#60676) and DiffusionGemma (#60466). The new hf tool and reasoning parser (--tool-call-parser hf, --reasoning-parser hf) reads the checkpoint's response_template, so models that ship it need no model-specific parser (#58604, #58602), in both the Python and Rust frontends (#59005).
  • Low-precision KV cache everywhere: NVFP4 KV cache now runs on SM8x and SM12x (#46963), SM90 (#60620) and with XQA decode on SM12x (#60452), and on MiniMax-M3 sparse attention on SM100 (#59300); GLM-5.x defaults to an FP8 KV cache on SM100, halving KV memory per rank with 2.3-5.5% more throughput at a 7-11% TTFT cost in the PR's benchmark (#60140, #60281); fp8_ds_mla on SM90 gives GLM-5.3-Flash up to 31% more output throughput (#59246); ROCm gains the 4-bit ultraquant_4bit KV cache with about 2x the density of FP8 (#57057).
  • Model Runner V2: a GPU n-gram speculator with variable-length drafts (#40704), Elastic EP (#53934), pipeline parallelism with prefill context parallelism for MLA models (#59139), a stock torch.compile mode (#59079), and MRV2 is now the default on ROCm with the model-specific MRV1 exceptions removed (#56360).
  • Faster startup and serving: vllm download-kernels installs FlashInfer's precompiled kernels (#58765); vllm preload --preload-autotune keeps the FlashInfer autotune table warm across restarts (#60085); a shared-memory tensor arena broadcasts large multimodal tensors to workers with one copy (#51207); tokenizers and processors load from the local snapshot (#60825); and with --api-server-count above 1 each connection goes to the least-loaded API worker, for 43-85% more req/s on short requests (Qwen3-0.6B, 32 input / 1 output tokens) in the PR's benchmark (#60723).
  • Model support: new EmbeddingGemma 2 omni-modal embeddings (#60254), MiniCPM-V 4.7 (#58674) and Nemotron 3.5 ASR (#59827); video input in the Transformers modeling backend (#57441); GLM-5.3 sparse MLA index conversions reused across layers (3.5-3.9x on that kernel, #59464) and fused multi-step draft decode (13.3% at concurrency 1, #57443); HiSparse per-request residency caching for up to 58% more throughput on GLM-5.3-NVFP4 on B200 with long, fully GPU-resident contexts at high concurrency (#60083).
  • Security: fixes for GHSA-4hhp-h66f-j5j7 (chat template resource exhaustion, #50300), GHSA-q97c-p368-75c4 (tokenizer max_token_id, #59491) and GHSA-frvg-qw88-hww9 (P2P ZMQ socket exhaustion, #51504); CORS no longer allows every origin by default (#61009); untrusted images are limited to raster formats (#60022); shared-memory multimodal cache handles are signed (#59357); and JSON schemas nested deeper than 64 levels are rejected (#60036).
  • Breaking changes: Python 3.10 dropped (#60402); default CORS origins restricted (#61009); transformers>=5.16.1,<5.20.0 and tokenizers>=0.23.2 (#57387, #59796); torch.compile sequence parallelism and AsyncTP passes removed (#60517); cascade attention removed (#61126); mamba_cache_mode="all" removed (#58997); max_tokens no longer reserved from the context window (#57035); Responses API reasoning stream events renamed (#59652).

  • GHSA-4hhp-h66f-j5j7: chat templates are validated statically and rendered under a timeout (VLLM_CHAT_TEMPLATE_RENDER_TIMEOUT), user-supplied chat_template in Responses chat_template_kwargs is rejected, and the Rust frontend caps template execution (#50300).

  • Default CORS settings no longer allow every origin in the Python and Rust frontends; set --allowed-origins to permit browser origins (#61009).
  • Untrusted images are opened with a raster-format allowlist (ALLOWED_IMAGE_FORMATS), denying EPS/PostScript and WMF (#60022); shared-memory multimodal cache handles are HMAC-signed and forged handles rejected (#59357).

Breaking Changes & Deprecations

  • Python 3.10 is no longer supported; the minimum is Python 3.11 (#60402).
  • Default CORS origins changed from * to none; set --allowed-origins for browser clients (#61009).
  • transformers>=5.16.1,<5.20.0 and tokenizers>=0.23.2 are required (#57387, #59796).
  • The torch.compile sequence parallelism and AsyncTP passes were removed, along with PassConfig.enable_sp, fuse_gemm_comms and sp_min_token_num; model-level sequence parallelism is unaffected (#60517).
  • Cascade attention was removed; --disable-cascade-attn still parses but only warns and will be removed in v0.33.0 (#61126).
  • mamba_cache_mode="all" was removed; --mamba-cache-mode all now fails validation (#58997).
  • Previously deprecated APIs were removed: wait_for_inflight_requests (use mode="wait"), AsyncLLM.pause_generation(), IOProcessor.output_to_response, vllm.scripts.main() and vllm bench throughput --dataset (#60923). The sonnet benchmark dataset was removed as scheduled (#60129). Tensorizer support was removed from LoRA (#60024), and the PyO3 vllm._rust_tool_parser bridge was removed (#59744).
  • API changes: max_tokens is treated as an upper bound on output rather than reserved from the context window (#57035); Responses API streaming uses response.content_part.added/done with part.type="reasoning_text" instead of response.reasoning_part.added/done (#59652); SamplingParams.prompt_logprob_token_ids is per row (#56984); /inference/v1/generate logprobs use integer token IDs (#58181); sleep API responses are standardized and invalid levels return 400 (#52864); return_mm_kwargs is deprecated in favor of mm_payload (#61427).
  • Watermarking: when the engine has watermarking configured, an omitted request field means enabled and only false opts out; unsupported combinations warn and fall back (#56801).
  • Rust frontend: qwen3_xml now parses Qwen3-Coder XML (alias of qwen3_coder); use the new qwen3_json for the JSON format (#60136).
  • New defaults: shared-memory tensor arena on (#51207); GLM-5.x FP8 KV cache on SM100 with --kv-cache-dtype auto (#60140, #60281); VLLM_DEEPEP_V2_ALLOW_HYBRID_MODE=1 (#57991); Humming preferred over Marlin on SM90 (#56997); sparse_mla_prefill_workspace_factor 2 above 256K max_model_len (#61023); MRV2 on ROCm with model-specific MRV1 exceptions removed (#56360); VLLM_ROCM_AITER_MLA_DCP_VERIFY=auto (#59965); dtype=auto picks bfloat16 on PowerPC (#58528); MXFP4 W4A4 checkpoints fall back to W4A16 with a warning when no W4A4 kernel exists (#60079).
  • Stricter validation: incompatible --prefix-match-unit (#58021), max_num_scheduled_tokens=0 (#60714), HiSparse with cudagraph_mode=FULL (#59688), and negative --device-ids (#49053) are rejected at startup.
