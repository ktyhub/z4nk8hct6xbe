Vibe-Trading v0.1.10

🌍 v0.1.10 — Camada de dados global + roll-up desde 0.1.9

v0.1.10 é um lançamento roll-up. A manchete é Camada de dados global: o registro de dados de mercado cresce de 10 para 18 fontes e ganha 18 ferramentas de dados somente leitura que vão além do OHLCV até os fundamentos e o fluxo, todos expostos no MCP. Em torno dele vem tudo acumulado desde 0.1.9 - 10 conectores SDK do corretor, a pilha completa Alpha Zoo alpha compare, uma revisão da confiabilidade do provedor, Pesquisa Autopilot Fase 1, um cache de dados local opcional e uma onda de reforço de segurança orientada pela comunidade. Esta versão está disponível nas versões PyPI, ClawHub e GitHub.

pip install -U vibe-trading-ai
# or
uv tool install --reinstall vibe-trading-ai

Destaques

🌍 Camada de dados global — 18 fontes + 18 ferramentas de dados somente leitura

O registro do carregador cresce de 10 para 18 fontes de dados de mercado:

  • Grátis, sem chave — tushare, okx, yfinance, akshare, baostock, tencent, mootdx, ccxt, futu, local, além de quatro novas adições diretas ao API: Eastmoney, Sina, Stooq e um HTTP direto Yahoo client.
  • Provedores opcionais dos EUA com acesso por chave — Finnhub, Alpha Vantage, Tiingo, FMP; chaves ausentes são ignoradas na cadeia de fallback, nunca a trave. As cadeias de fallback são reordenadas por risco de banimento de IP (lead endpoints públicos leves e tolerantes à aceleração; trilhas REST controladas por chave) atrás de uma porta HTTP acelerada compartilhada (backtest/loaders/_http.py) com intervalos de taxa por host, jitter e reutilização de sessão. Na parte superior 18 ferramentas de dados somente leitura - fluxo de fundos, conselho dragão-tigre, fluxo norte (Stock-Connect), negociação de margem, negociações em bloco, contagem de acionistas, vencimento de bloqueio, associação ao setor, relatórios de pesquisa, notícias, arquivos SEC (EDGAR + XBRL), demonstrações financeiras, cadeias de opções, participações institucionais, triagem de mercado completo, pesquisa de símbolos, macro FRED e pesquisa de ações A em linguagem natural iwencai - em A-share / EUA / HK, todos expostos no MCP. Três clients compartilhados (eastmoney/yahoo/sec_edgar) apoiam os carregadores e ferramentas, e um índice data-routing consolidado mais habilidades eastmoney/sec-edgar por fonte documentam a camada.

💱 10 conectores do corretor SDK — leitura + papel, ao vivo com mandato controlado

A negociação é o conector primeiro: escolha um perfil e papel/ao vivo é um atributo do conector. Este lançamento traz a lista para 10 corretores — IBKR (TWS/Gateway somente leitura local) · Robinhood (Agentic MCP, OAuth) · Tiger · Longbridge · Alpaca · OKX · Binance · Futu · Dhan · Shoonya (Índia NSE/BSE + F&O). Os conectores Direct-SDK compartilham um transporte broker_sdk e cada um lê + colocação de pedidos em contas em papel; a colocação ao vivo passa por um único portão de autonomia limitada com falha fechada (sdk_order_gate.py: mandato + interruptor de interrupção + auditoria). Corretores sem sem discriminador de papel/ao vivo (Longbridge, Dhan, Shoonya) são estruturalmente limitados a papel + somente leitura — seus place_order / cancel_order recusam fortemente qualquer configuração que não seja de papel na primeira linha. As ferramentas de colocação de pedidos ficam fora do MCP (somente agente + CLI).

📊 Comparação alfa entre ferramenta CLI / REST / Web / agente

vibe-trading alpha compare classifica qualquer conjunto de fatores Alpha Zoo por IC / IR em seu universo, compartilhando um núcleo compare_runner.compare_alphas atrás do CLI, uma rota REST POST /alpha/compare com progresso transmitido por SSE, a visualização Alpha Zoo Web UI Compare e uma ferramenta de agente alpha_compare somente leitura. Um filtro de subconjunto run_bench(only=…) avalia apenas os fatores comparados em vez de todo o zoológico.

🔌 Revisão da confiabilidade do provedor

Uma camada de capacidade do provedor controla a captura/reprodução de raciocínio, assinaturas de pensamento Gemini, agente de usuário Kimi e corpos de raciocínio OpenRouter por provedor. vibe-trading provider doctor imprime um instantâneo de diagnóstico redigido. Falhas de streaming agora geram um ProviderStreamError explícito e redigido (transportando status_code + .retryable) com uma nova tentativa para transientes e falha rápida em 4xx; um reasoning_delta SSE limitado aciona um indicador de atividade "Raciocínio…" na interface da Web. Além disso: um adaptador DeepSeek nativo opcional (VIBE_TRADING_DEEPSEEK_ADAPTER), hard-timeouts de ferramenta somente leitura (VIBE_TRADING_TOOL_TIMEOUT_SECONDS) e tratamento de temperatura por provedor (Kimi-k2 forçado para 1.0, MiniMax fixado> 0).

🔬 Piloto Automático de Pesquisa Fase 1

run_research_autopilot transforma um hypothesis_id em uma meta de pesquisa (tese como objetivo, critérios de aceitação relevantes para backtest, dicas para a próxima etapa) e generate_backtest_config escreve automaticamente um backtest config.json a partir do universo da hipótese e das fontes de dados - para que o agente vá direto da ideia → signal_engine.py → execução.

🗃️ Cache de dados local opcional + carregador local

VIBE_TRADING_DATA_CACHE=1 armazena em cache barras resolvidas para ~/.vibe-trading/cache (home do usuário, nunca o repositório); um guarda de desatualização nunca armazena em cache um intervalo que termina hoje, e os quadros armazenados em cache são idênticos em bytes às buscas ao vivo. Um novo carregador local lê OHLCV diretamente de seus próprios arquivos CSV / Parquet / DuckDB via ~/.vibe-trading/data-bridge/config.yaml, com suporte normal à cadeia de fallback.

🛡️ Onda de segurança e proteção

Um passe de fortalecimento orientado pela comunidade: autenticação de gravação de configurações API (nº 245), ativação da ferramenta shell do agente (nº 243), rejeição de religação de host de loopback (nº 242), autenticação explícita de desligamento local (nº 241) e contenção de identificador para ids de proposta de mandato (nº 256), tipos de memória persistente (nº 257) e ids de execução de enxame MCP (nº 258). Além de parada responsiva no meio do fluxo + reconexão SSE ao retornar a uma sessão em execução (#229), fallback web_search multimotor (#231) e viagem de ida e volta Gemini thoughtSignature por meio de chamadas de ferramenta compatíveis com OpenAI (#176, #184).

🪪 Os relatórios de versão agora são consistentes

--version, o REST API (/docs + /api), o handshake do servidor MCP e o rodapé da UI da Web derivam de uma fonte - o REST API mudou para um 5.0.0 codificado errado. A embalagem agora também vem com scripts de exemplo de habilidades na roda, e a imagem Docker instala as bibliotecas nativas do weasyprint para que os relatórios em PDF sejam renderizados.

Vibe-Trading v0.1.10

🌍 v0.1.10 — Global data layer + roll-up since 0.1.9

v0.1.10 is a roll-up release. The headline is the Global data layer: the market-data registry grows from 10 to 18 sources and gains 18 read-only data tools that reach past OHLCV into fundamentals and flow, all exposed over MCP. Around it ships everything accumulated since 0.1.9 — 10 broker SDK connectors, the Alpha Zoo alpha compare full stack, a provider-reliability overhaul, Research Autopilot Phase 1, an opt-in local data cache, and a community-driven security-hardening wave.

This release is available on PyPI, ClawHub, and GitHub Releases.

pip install -U vibe-trading-ai
# or
uv tool install --reinstall vibe-trading-ai

Highlights

🌍 Global data layer — 18 sources + 18 read-only data tools

The loader registry grows from 10 to 18 market-data sources:

  • Free, no key — tushare, okx, yfinance, akshare, baostock, tencent, mootdx, ccxt, futu, local, plus four new direct-API additions: Eastmoney, Sina, Stooq, and a direct-HTTP Yahoo client.
  • Optional key-gated US providers — Finnhub, Alpha Vantage, Tiingo, FMP; absent keys are skipped in the fallback chain, never crash it.

Fallback chains are re-ordered by IP-ban risk (lightweight, throttle-tolerant public endpoints lead; key-gated REST trails) behind a shared throttled HTTP gate (backtest/loaders/_http.py) with per-host rate buckets, jitter, and session reuse. On top sit 18 read-only data tools — fund flow, dragon-tiger board, northbound (Stock-Connect) flow, margin trading, block trades, shareholder count, lockup expiry, sector membership, research reports, news, SEC filings (EDGAR + XBRL), financial statements, options chains, institutional holdings, full-market screening, symbol search, FRED macro, and iwencai natural-language A-share search — across A-share / US / HK, all exposed over MCP. Three shared clients (eastmoney / yahoo / sec_edgar) back the loaders and tools, and a consolidated data-routing index plus per-source eastmoney / sec-edgar skills document the layer.

💱 10 broker SDK connectors — read + paper, mandate-gated live

Trading is connector-first: pick a profile, and paper/live is an attribute of the connector. This release brings the roster to 10 brokers — IBKR (local read-only TWS/Gateway) · Robinhood (Agentic MCP, OAuth) · Tiger · Longbridge · Alpaca · OKX · Binance · Futu · Dhan · Shoonya (India NSE/BSE + F&O). Direct-SDK connectors share a broker_sdk transport and each does read + paper-account order placement; live placement passes a single fail-closed bounded-autonomy gate (sdk_order_gate.py: mandate + kill switch + audit). Brokers with no runtime paper/live discriminator (Longbridge, Dhan, Shoonya) are structurally capped at paper + read-only — their place_order / cancel_order hard-refuse any non-paper config at the first line. Order-placing tools stay off MCP (agent + CLI only).

📊 Alpha compare across CLI / REST / Web / agent tool

vibe-trading alpha compare ranks any set of Alpha Zoo factors by IC / IR on your universe, sharing one compare_runner.compare_alphas core behind the CLI, a POST /alpha/compare REST route with SSE-streamed progress, the Alpha Zoo Web UI Compare view, and a read-only alpha_compare agent tool. A run_bench(only=…) subset filter benches only the compared factors instead of the whole zoo.

🔌 Provider-reliability overhaul

A provider capability layer gates reasoning capture/replay, Gemini thought signatures, Kimi user-agent, and OpenRouter reasoning bodies per provider. vibe-trading provider doctor prints a redacted diagnostic snapshot. Streaming failures now raise an explicit, redacted ProviderStreamError (carrying status_code + .retryable) with one retry for transients and fail-fast on 4xx; a throttled reasoning_delta SSE drives a "Reasoning…" liveness indicator in the Web UI. Also: an optional native DeepSeek adapter (VIBE_TRADING_DEEPSEEK_ADAPTER), read-only tool hard-timeouts (VIBE_TRADING_TOOL_TIMEOUT_SECONDS), and per-provider temperature handling (Kimi-k2 forced to 1.0, MiniMax clamped > 0).

🔬 Research Autopilot Phase 1

run_research_autopilot turns a hypothesis_id into a research goal (thesis as objective, backtest-relevant acceptance criteria, next-step hints), and generate_backtest_config auto-writes a backtest config.json from the hypothesis's universe and data sources — so the agent goes straight from idea → signal_engine.py → run.

🗃️ Opt-in local data cache + local loader

VIBE_TRADING_DATA_CACHE=1 caches settled bars to ~/.vibe-trading/cache (user home, never the repo); a staleness guard never caches a range ending today, and cached frames are byte-identical to live fetches. A new local loader reads OHLCV straight from your own CSV / Parquet / DuckDB files via ~/.vibe-trading/data-bridge/config.yaml, with normal fallback-chain support.

🛡️ Security & hardening wave

A community-driven hardening pass: API settings-write auth (#245), agent shell-tool opt-in (#243), loopback-host rebinding rejection (#242), explicit local-shutdown auth (#241), and identifier containment for mandate proposal-ids (#256), persistent-memory types (#257), and MCP swarm run-ids (#258). Plus responsive Stop mid-stream + SSE reconnect on returning to a running session (#229), multi-engine web_search fallback (#231), and Gemini thoughtSignature round-trip through OpenAI-compat tool calls (#176, #184).

🪪 Version reporting is now consistent

--version, the REST API (/docs + /api), the MCP server handshake, and the Web UI footer all derive from one source — the REST API had drifted to a wrong hardcoded 5.0.0. Packaging also now ships skill example scripts in the wheel, and the Docker image installs weasyprint's native libs so PDF reports render.
