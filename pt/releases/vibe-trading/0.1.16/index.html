Vibe-Trading v0.1.16

Acumula 492 commits/116 pull requests mesclados desde 0.1.15, de 16 contribuidores. O tema deste ciclo é um número que pode mostrar de onde veio. O o portão de aterramento da resposta final parou de adivinhar o que é um número a partir das palavras em torno dele: o modelo declara o papel de cada figura - observado, derivado, proposto, citado ou contado - o portão verifica essa declaração em relação ao evidência da ferramenta da sessão, e um número que falha é cortado da resposta em vez de toda a resposta ser recusada. A própria saída de um backtest (seu Sortino, volume de negócios, pesos e valores p de Monte Carlo, não apenas o seu Sharpe) agora fundamenta o relatório escrito sobre isso, os cartões de execução citam uma métrica apenas onde o CSV salvo concorda e a matriz do corretor gerada indica o perfil de cada perfil permissões como declarações em vez de verificação em tempo de execução. Pesquisa as execuções pararam de perder o que buscaram: a compactação segue o real do modelo janela de contexto em vez de uma estimativa fixa de 40K que começou a limpar a ferramenta resultados da terceira etapa. A varredura de dados perdidos atingiu mais 59 alfas: 15 fatores de contagem qlib158, 20 que preencheram uma entrada ausente com uma constante e 24 portas de comparação. Argentina (BYMA), bares semanais e mensais, Bahasa Canais Indonésia, Gildata, OpenCode, Email e WebSocket e quatro corretores conectores (KIS, Upbit, Toss Securities, Scalable Capital) pousam ao lado.

A anualização é 52/12; uma barra perpétua semanal liquida 21 períodos de financiamento. 1M é correspondido antes de qualquer dobra de caixa, que é lida como um minuto em validação estrita 100x e em atribuição (98.280 barras por ano).   • E-mail e WebSocket juntam-se à configuração guiada do canal Web UI (#1544, após #1519, obrigado @shadowinlife). Ambos os canais obtêm metadados de campo escritos à mão – rótulos localizados, segredos mascarados — além de testes de conexão e acesso rápido por canal aplicar. O teste do email investiga o login IMAP real, a seleção da caixa de correio e o login SMTP sem nunca enviar uma mensagem; WebSocket é um canal de servidor sem controle remoto credenciais, portanto, seu teste valida o material do certificado/chave TLS e vincula todos endereço resolvido localmente - um endereço mantido pelo servidor já em execução lê como o estado esperado, não um fracasso. Salvar uma configuração do WebSocket troca a quente o servidor: clients conectados (incluindo o bate-papo da Web UI) desconectam-se brevemente e reconectar. O sinalizador secreto de uma dica de campo escrita à mão agora é oficial para as chaves que ele cobre - o regex à prova de falhas ainda mascara todas as chaves não sugeridas - então não-segredos em forma de token, como websocket_requires_token, permanecem visíveis e editável em vez de ser mascarado, e um salvamento de formulário não pode mais virar silenciosamente o requisito de token armazenado. As rotas de configuração da web agora constroem o WebSocket adaptador com os serviços de gateway necessários; anteriormente cada salvamento do WebSocket ou teste falhou na validação. O loop de pesquisa do email também ignora a configuração obsoleta excluir/mover pós-ações assim que uma parada ou troca a quente começar, enquanto o o lote já obtido ainda é entregue. Tanto a sonda quanto o loop de pesquisa agora envie um RFC 2971 IMAP ID após o login: caixas de correio NetEase (163/126/yeah.net) aceite o login, mas rejeite o primeiro SELECT com Unsafe Faça login até que o client se identifique, então sem isso o canal Email não conseguia ler as caixas de correio chinesas mais comuns. A identificação é estática e não carrega dados ou segredos do usuário, e os servidores que ignoram ID são não afetado; verificado de ponta a ponta em uma conta ativa do 163.com.

  • **O portão de aterramento da resposta final não adivinha mais qual é o número do palavras ao seu redor. ** Apenas a FORMA de um número é inferida - um ponto decimal, um o sinal de porcentagem, um marco monetário ou uma célula de tabela fazem dele uma medida; datas (incluindo "09-14" sem ano), anos, códigos de segurança, ordinais iniciais de linha e o código em uma cerca marcada com linguagem é estrutura; um número inteiro simples é verificado apenas como o preço de um instrumento cotado na casa dos milhares - então uma frase fica o mesmo veredicto em todas as línguas. Qualquer outro é declarado em um bloco figures protegido no final da resposta, uma linha por figura — value | role | note | ref — e verificado por função: observed deve aparecem na chamada ou ferramenta referenciada (ref pode nomear qualquer um), filtrado para o próprio símbolo da figura, com uma figura marcada com moeda comparada apenas com valores denominados em dinheiro e um percentual apenas contra valores não relacionados a preços; derived precisa de uma fórmula avaliável cujos operandos adicionados ou subtraídos sejam todos observado, combinando a figura com a precisão e o sinal com que foi escrita; proposed é um preço dentro da faixa observada do seu próprio símbolo ou uma derivação; cited deve nomear sua fonte na própria linha da figura, pois o bloco é despojado antes que alguém leia a resposta; count cobre contagens, pesos, limites e probabilidades, enquanto um número marcado em moeda, ou um dentro a faixa de preço do seu instrumento que nenhuma derivação usa como fator é verificada conforme observado quando declarado count. Corrigido

Longas pesquisas param de perder o que buscaram

As duas execuções de um usuário no provedor Codex (GPT-6 Sol) falharam como "0 etapas · no_progress": um backtest de paridade de risco após 1m03s e uma comparação de A-share e empresas de jogos de Hong Kong após 4m50s. Foram dois fracassos diferentes.

  • A compactação de contexto segue a janela de contexto real do modelo — compactação disparado com uma estimativa fixa de 40.000 tokens (caracteres/4 das mensagens, sem contar as definições de ferramentas), enquanto o prompt do sistema por si só é sobre 12.500 deles. A partir da terceira etapa, todos os resultados da ferramenta foram apagados, exceto o últimos três, então uma comparação entre uma dúzia de empresas recuperou o mesmo arquivamentos até a parada sem progresso: reproduzido em v0.1.15 com DeepSeek V4 Pro, registros de sete emissores de ações A obtidos quatro a cinco vezes cada, param em iteração 16; com um orçamento maior, as buscas passaram de 54 para 0. O janela agora vem do VIBE_TRADING_CONTEXT_WINDOW, caso contrário, um limite aprendido do próprio erro de comprimento de contexto do provedor durante a execução, caso contrário src/providers/context_windows.json (272K para o Codex GPT-6 / GPT-5.6 modelos, 1M para DeepSeek V4, cada entrada nomeando sua fonte), caso contrário 128K, e VIBE_TRADING_CONTEXT_MAX_TOKENS (200K) limita o custo de um prompt. Uso é lido dos tokens de entrada relatados pelo provedor. As três camadas disparam contra 80/90/100% do que o prompt do sistema e os esquemas de ferramentas deixam e limpam os resultados mais antigos primeiro, apenas até a linha. Um erro de comprimento de contexto é compactado e tentado novamente em vez de falhar na execução. TOKEN_THRESHOLD é obsoleto e ignorado com um aviso; remova-o do .env.
  • read_file diz onde o agente pode ler e lista um diretório — o Falha de 1m03s: no mesmo prompt, uma execução ao vivo do DeepSeek V4 procurou a fonte do mecanismo de backtest (../../agent/src/backtest, o checkout caminho absoluto, skills/../backtest/engine.py) e todas as tentativas obtiveram o mesmo "Arquivo não encontrado ou caminho escapa do espaço de trabalho". Cada grafia era uma nova chamada e nenhuma observação, então oito rodadas esgotaram o orçamento sem progresso em 93 segundos, antes de qualquer backtest ser executado. A recusa agora nomeia o caso (outside_readable_roots ou not_found), as raízes legíveis (a execução diretório e skills/) e onde estão documentados os contratos do motor (load_skill); um diretório dentro dessas raízes retorna suas entradas. O o limite em si permanece inalterado.
  • Uma execução com falha ou cancelada mantém suas etapas — apenas uma execução concluída é salva sua trilha de ferramentas, então o histórico da Web mostrou "0 etapas" exatamente para as execuções alguém iria querer inspecionar.
  • Uma parada sem progresso indica quais chamadas não produziram nada e por quê — cada uma chamada com falha ou repetida é listada com seu motivo e contagem ("read_file falhou (… não encontrado) ×3"), em vez de uma mensagem sobre resumos anteriores e caminhos de artefato escritos para uma falha diferente.
  • get_market_data falha quando nenhum símbolo solicitado retorna dados — um envelope contendo apenas _unresolved foi um sucesso, então uma corrida cujas fontes todos consideraram isso um progresso. Agora é error_code: nenhum_dados_de_mercado; um resultado parcial ainda é um sucesso, e o aterramento ainda registra todos os símbolos como indisponíveis.
  • Codex (entrada no ChatGPT) mantém o prompt do sistema, seu raciocínio e sua call ids — uma mensagem do sistema que o loop adiciona no meio da execução (uma dica de nova tentativa, uma lembrete de gravação do arquivo) substituiu todo o prompt do sistema de 49.000 caracteres para cada solicitação posterior; agora é enviado como uma mensagem do desenvolvedor, como o O Codex CLI sim. Os itens de raciocínio são transportados de um turno para outro da mesma forma que o O Codex CLI os reproduz e se ressente sem eles se o back-end recusar; chamadas de ferramenta mantêm os IDs dos itens emitidos pelo back-end em vez de fabricados fc_0; a chave do prompt-cache é estável para a sessão em vez de mudar em cada solicitação. O modelo Codex padrão é gpt-6-sol: gpt-5.4 é recusado para contas ChatGPT.

Um relatório de backtest é verificado em relação ao backtest

Um relatório de paridade de risco versus peso igual terminou na recusa enlatada em 12 dos 15 corridas repetidas. Repetindo todos os 26 rascunhos armazenados através do portão (880 de 882 rejeições registradas reproduzidas) mostrou que quatro em cada cinco valores recusados foram valores que o próprio backtest havia escrito.

  • O resultado do próprio backtest fundamenta o relatório sobre ele — apenas métricas cujos nomes o portão conhecia (Sharpe, retorno, rebaixamento, volatilidade, taxa de vitória) eram provas. Cada escalar do cartão de execução, a linha de métricas, o risco Raio-X, a validação de Monte Carlo e o resumo do reequilíbrio agora são (listas como os 1.000 Sharpes simulados não são descidos, e um arquivo diferente as métricas devem corresponder ao manifesto SHA-256 da placa de execução). Uma tabela por barra conta apenas para as linhas mostradas por read_file, embora ainda seja byte para byte o que o mecanismo escreveu; um arquivo que o modelo escreveu nunca é uma evidência. Um a figura pode nomear a execução de onde veio - rp, rp/artifacts/metrics.csv, risk_parity target_positions.csv, rp::sortino — e um valor de um backtest não fundamenta um valor declarado de outro. Repetido: value_mismatch 196 → 1, not_in_referenced_call 167 → 7. No mesmo executa um valor real declarado com sua execução passa 97% do tempo e o o mesmo valor movido de 2 a 10% passa para 0.7%; o caminho não declarado foi deliberadamente não ampliado (toda a linha de métricas teria ultrapassado 16% do inventado valores).
  • A aritmética de uma comparação é lida como está escrita — uma fórmula colada seus rótulos ("等权 Sortino 1.2115 − 风险平价 1.1329") ou seguido por um entre colchetes era "não aritmético"; um operando escrito como uma porcentagem foi lido como um número inteiro, então "13.28% - 12.98%" ancorado em nada e "0.666 × (1 − 3%)" calculou o valor errado; uma soma de pesos quadrados (HHI) não pôde ser escrito; o operando negativo de uma fórmula (um rebaixamento) nunca poderia ancorar; e um campo duas corridas ambos mantêm ancorados nenhum dos dois. Todos agora avaliam (apenas um quadrado ou cubo literal é aceito como poder), e os que ainda falham são a própria aritmética do modelo. Um valor declarado pode ser uma fração (1/3) ou um múltiplo (5.5x).
  • **Um relatório que ainda falha após uma análise concluída ser liberada com o corte de números falhados ** - nomear um símbolo transformava qualquer solicitação em uma resposta do mercado, e uma resposta de mercado sem preço mirabolante nunca foi divulgada cortada. Um a análise concluída agora é; uma questão de preços sem preços nem uma análise ainda obtém a recusa, e a recusa após uma análise não já diz que o rascunho citava preços.
  • Um rascunho que termina nas tags de chamada de ferramenta de fechamento do DeepSeek foi capturado — </｜｜DSML｜｜invoke> ultrapassou o padrão de abertura de tags e alcançou o portão como linhas de declaração ilegíveis.
  • Uma correção indica o que deu errado com um valor declarado pelo modelo — 0.3897 e 38.97% permanecem duas asserções, assim como −1.51pp e uma fórmula que calcula +1.51, mas o modelo agora é informado qual valor declarou (também quando tem sinal oposto) e que sua fórmula segue no sentido contrário rodada, em vez de "não declarado" ou "sua própria nota é avaliada como 1.51%". Em um ao vivo após a correção das evidências, oito diferenças ainda foram cortadas porque o segundo rascunho reescreveu os números em vez das fórmulas. O a correção também pede apenas a resposta corrigida, no nome do usuário idioma: esse rascunho começava com "A rejeição foi porque…", em Inglês para um usuário escrevendo em chinês, e a frase foi divulgada.

O portão de aterramento

  • Uma figura de risco final nomeia seu próprio campo quando uma sessão contém mais de um (#1425, depois de #1444, obrigado @he-yufeng). Uma referência com escopo de chamada ou ferramenta (ref x1) agrupou todos os campos de risco final que a chamada retornou e um campo de risco final não declarado por cento agrupou todos os valores de risco final na sessão, de modo que um ES 95% poderia cotar o valor do VaR 95% e aprovado. A regra é lida nas evidências, nunca prosa: tail_risk_identity() tira (medida, confiança) do nome do campo uma ferramenta foi retornada, então var_95 e es_95 são duas identidades enquanto cvar_99 e es_99 são um. Quando um escopo contém dois ou mais e o valor da figura corresponde a um deles, é recusado com tail_risk_needs_field_ref, cujo a correção nomeia todas as identidades que a sessão contém; uma figura correspondente a não o valor do risco final mantém sua antiga razão, então um número fabricado ainda é um incompatibilidade em vez de uma referência ausente. Custo aceito, declarado na edição: um VaR não declarado de 95% ao lado de um VaR de 99% está correto hoje e agora custa um rodada de correção. O prompt do sistema declara a regra para que um relatório de risco declare o árbitro em sua primeira tentativa.
  • As figuras de risco de cauda mantêm sua identidade sob um campo ref (#1444, obrigado @he-yufeng). Um ref declarado pode nomear um campo de evidência pelo seu caminho completo (data.tail_risk.var_95) ou parte final (var_95), ou campo de uma chamada (q1::historical_var); um VaR 99% cotando o valor de 95%, ou ES cotando o VaR, é rejeitado sob tal ref. Um campo com duas chamadas retornadas com valores diferentes é ambíguo e a correção nomeia as referências para escolher. Uma reivindicação com escopo uma chamada inteira ou não declarada ainda é comparada com cada valor de risco final que ela posso ver (#1425 permanece aberto).
  • A porta de aterramento lê vírgulas decimais (#1517, obrigado @zeus229): 17,93 % e 1.410,00 CNY aterrado em relação aos resultados da ferramenta, dois números não espaçados, como 1400,1777 ficam com dois números, e um algarismo escrito deve corresponder à sua evidência dentro de meia unidade de seu último dígito escrito (um 30.20% truncado para 30.2052% agora é enviado de volta para correção). Uma regex de forma adicionada (14 → 15).
  • Uma resposta redigida mantém seus números de linha e rótulos (#1471). Quando o O portão de aterramento divulgou um rascunho com seus números não verificados cortados, um ranking tabela voltou com (omitted※) no lugar de 1, 2, 3, do 12m em seu cabeçalhos e de "3 nomes" na prosa. Cada número inteiro em uma célula da tabela era um medição, então a coluna de classificação foi cortada; e os dígitos de cada figura cortada foram em seguida, varrido do resto da página, incluindo um único dígito. Forma três regras, sem lista de palavras: uma coluna cujas células numeradas são 1, 2, 3… na linha order é o índice da tabela; um número inteiro simples em uma célula que também contém um palavra (12m mean return, Mean beta (9 reported)) é lida como seria em uma frase, enquanto uma célula que contém apenas um número, qualquer decimal, porcentagem ou valor da moeda, e cada célula sob uma coluna OHLC permanece nas medidas; e a varredura nunca digita um único dígito. Um preço inteiro de um instrumento citado na casa dos milhares ainda é verificado dentro de uma célula escrita.
  • Um resultado de VaR real fundamenta o VaR retornado (#1464). quantlib_call registra um resultado escalar sob o nome da função. Para historical_var e parametric_var esse nome se reduz a var, que a porta de aterramento aceita apenas como um nome de campo inteiro, então o resultado não registrou nenhuma evidência e um valor correto a resposta citando foi rejeitada. Ambos os nomes são agora pseudônimos de risco de cauda. Variações como residual_var permanecem não mapeadas.
  • Inteiros simples em prosa não são declarações de preço. Um número de lista ("输出原则 4"), o comprimento ou contagem da janela era verificado como um preço cotado e poderia ser cortado de uma resposta divulgada.
  • Um rebaixamento em relação a passes altos observados onde quer que os pontos finais estejam escrito. "较 5 月高点 1.053 元已回撤约 37%" foi rejeitado quando seus terminais ficaram em outra linha; uma declaração derived não depende do layout.
  • Os valores dos indicadores denominados em preço são comprovativos, mediante registro. Médias móveis, bandas de Bollinger e níveis semelhantes retornados por technical_indicators são registrados por ferramenta como evidência de preço observado; RSI, MACD e outras licenças não relacionadas a preço não são, e nada é decidido a partir de um palavras do nome do campo.
  • Uma data sem ano é uma data e "24,6M" é 24.6 milhões. Duas execuções reais que se seguiram ao contrato ainda foram divulgados redigidos: "2026-09-11 / 09-14" em uma célula de tabela enviada como "2026-09-11 /（略※）-（略※）", e "24,6 milhões → lotes de 22,6 milhões" como "(omitido※)M → (omitido※)M". Um MM-DD preenchido com zeros, ou um aberto por uma data completa na mesma célula ou linha, é estrutura (um não preenchido "| 11-12 |" ainda está marcado, pois pode ser uma faixa de preço). K/M / B / 千 / 万 / 亿 colado a uma escala de números sua comparação com as evidências, nunca sua forma, e um corte tira a marca da figura. Repetido em resultados da ferramenta de ambas as execuções, cada segundo rascunho agora passa conforme escrito.
  • As contagens de metadados não são métricas, e o resultado do risco final de uma ferramenta pode fundamentar um VaR (#1420, #1426). return_observations, n_returns, return_window, vol_lookback, max_drawdown_duration, aligned_days e seus *_window / Famílias *_lookback / *_obs / n_* / *_count / *_days / *_duration não fundamenta mais uma porcentagem (“年化收益 81%” de 81 observações); var, As folhas var_95, var_99, cvar, es e expected_shortfall apresentam risco de cauda evidência, de forma que um VaR correto não seja mais recusado. A métrica de um campo vem de a cabeça de seu nome, então sharpe_sample_size e drawdown_threshold são não é mais um índice de Sharpe ou um rebaixamento.
  • Uma correção nomeia as impressões do próprio instrumento da figura (#1433). O Os valores "observados mais próximos" vêm desse símbolo (e de sua coluna da tabela ou ref), não de todos os campos de todos os símbolos na execução.
  • Um número é lido da forma como o chat o renderiza (#1418). Largura zero caracteres, um ponto decimal de largura total ou árabe, um espaço sem quebra antes de "%", o sinal de menos U+2212, um escape de barra invertida ("0\.888"), uma entidade HTML e um O código ISO colado aos dígitos ("CNY0,888") não divide mais o preço em inteiros não verificados; uma vírgula decimal ("0,666 CNY", "12,5%") é um decimal enquanto um agrupamento válido ("-1,250.00") permanece agrupado e uma resposta que grava um a vírgula decimal marcada também indica "2.237" e "−5.132%" ao lado como decimais. As barreiras seguem o CommonMark, e uma barreira de código não terminada não isenta mais o resto da resposta.
  • Um ano não é uma proteção de preço. "$2.050", "1999 元" e 2031 sob um fechamento coluna são verificadas; é verificado um preço colocado em uma coluna de data ou código; um data compacta, uma data pontilhada e uma hora são estruturadas. 円 e 원 são moeda marcas e "52pp" / "5200bp" são medidas.
  • Uma declaração não pode realocar ou lavar uma figura. Uma figura a sentença escreve sobre um instrumento e não pode ser declarado encerrado por outro; um o resultado marcado em moeda não pode ser derivado de um RSI ou de um volume; count, derived e proposed não podem ficar em uma coluna de preço.
  • Uma resposta geral sem evidência de ferramenta é cortada, não recusada. Uma pergunta sobre nenhum instrumento ("印花税怎么收") cujos números o portão não pode verificar é divulgado com esses números omitidos e uma nota de rodapé, em vez de uma recusa sobre preços que nunca mencionou; uma resposta de mercado que não observou preço ainda cai para trás. Um bloco de figuras malformado não força mais o substituto ou: o bloco é descartado e o rascunho é verificado conforme escrito.
  • O substituto da sintaxe da chamada da ferramenta chega ao chat uma vez. Quando um modelo atende a iteração de texto forçado com marcação de chamada de ferramenta em uma execução cuja saída é armazenada em buffer, a mensagem de substituição foi transmitida por sua própria ramificação e novamente como a resposta divulgada, então o chat e o CLI mostraram duas vezes.
  • Nenhum número não verificado chega ao chat antes do portão ser executado. Um número sem buffer resposta (nenhum instrumento questionado, nenhuma evidência de ferramenta ainda) transmitiu seu primeiro rascunho ao vivo, números incluídos, e uma rejeição o substituiu; o fluxo agora para no primeiro número em forma de medição, e um rascunho rejeitado é mostrado o prefixo é apagado com stream_reset.
  • Um plano de negociação em uma cerca de código simples é verificado. Somente uma cerca marcada com um a linguagem contém código; uma cerca não etiquetada é lida como prosa.
  • É verificado um preço inteiro de um instrumento cotado em milhares ("600519.SH 最新收盘 1520"), dentro de metade a duas vezes o intervalo observado; um janelas como "200 日均线" permanecem desmarcadas.
  • Um preço declarado count é verificado. Um número dentro do seu instrumento a faixa de preço observada pode ser count somente quando uma derivação declarada a utiliza como um fator.
  • Uma nota de rodapé de redação que o próprio modelo escreveu é removida antes do real cortes, portanto, uma resposta divulgada nunca traz duas notas de rodapé contraditórias ou um marcador para um corte que não aconteceu.
  • Um valor sobre um segundo instrumento é verificado em relação ao valor desse instrumento evidência (#1584, obrigado @zeus229) — resolução do símbolo viu apenas registros comparáveis a preços, portanto, uma linha nomeando um instrumento que a sessão realizou apenas os fundamentos para pegaram o símbolo principal da resposta e falharam como not_in_referenced_call. Qualquer evidência observada com um símbolo explícito agora resolve isso; O 47a036d6 avalia as métricas de análise da mesma forma, portanto, uma métrica de um uma chamada sobre outro símbolo, ou vários, não pode fundamentá-lo.
  • Uma referência de campo pode conter | e uma correção para listas de campos ambíguas as referências exatas a serem usadas (#1586, obrigado @zeus229) — o analisador figures dividir em cada |, encurtando tal ref; uma declaração tem quatro colunas agora, o último ocupando o resto da linha. Quando várias chamadas retornaram um campo, a correção lista cada call_id::field válido (apenas o da figura próprio símbolo desde 47a036d6), e uma referência tool_name::field é recusada como field_ref_needs_call_id com essa lista.
  • Os números inteiros agrupados por pontos de uma resposta com vírgula decimal são lidos como milhares (#1588, obrigado @zeus229) — AR$5.165; volumen 502.408 foi lido como dois decimais e falhou como figure_undeclared. Depois que um documento escreve um decimal vírgula, agora incluindo um 0, com dois ou mais dígitos, 5.165 é 5165 e é ainda verificado; sem essa evidência permanece 5.165. O PR é mais amplo 1% banda de arredondamento não foi mantida (47a036d6): em 0.5% deve-se escrever 0.82467 0,825, não 0,82.
  • Os números do technical_indicators mantêm a data informada pela ferramenta (#1590, obrigado @zeus229) — a ferramenta data seu instantâneo como latest_date, um a ingestão de evidências principais não foi lida, então latest_close, os indicadores e as métricas de volume chegaram ao grounding_evidence.json com timestamp: null. Ele é herdado agora, abaixo dos campos de data da própria linha e acima de as_of; uma carga útil sem data permanece sem data.

  • Uma divisão OOS de bancada estrita precisa de duas observações IC de cada lado (#1559, obrigado @Shizoqua). Uma divisão fora dos preços carregados é recusada.   • A tail-risk figure names its own field once a session holds more than one (#1425, after #1444, thanks @he-yufeng).   • A redacted answer keeps its row numbers and its labels (#1471). Two real runs that followed the contract were still released redacted: "2026-09-11 / 09-14" in a table cell shipped as "2026-09-11 /（略※）-（略※）", and "24.6M → 22.6M lots" as "(omitted※)M → (omitted※)M". Backtest runner and engines

  • Backtests align calendars at any timestamp resolution (#1560, thanks @Shizoqua). The engine merged symbol calendars and placed prices through raw nanosecond integers, but a local duckdb source serves microseconds. Such a run was dated 1970-01-21, and beside a nanosecond source one symbol's closes came back empty. The rebalance mask had the same unit mismatch.

  • Mean-variance style optimizers size a short by its own expected return (#1548, thanks @Shizoqua). The optimizers scored every position as if it were held long, so the strongest shorts (most negative drift) looked worst and got the least capital. BaseOptimizer.optimize now negates a short's column before building the context, so mu is the position's expected return AND cov is the position covariance D Σ D: a long and a short of two +0.92 correlated names hedge instead of reading as correlated (the old objective put the whole book on the long, the new one splits it 0.514 / -0.486).   • One cash-starved open is one rejection, not twenty-six (#1470).   • A text column in metrics.csv no longer drops a run's metrics from the reply (#1579, thanks @Shizoqua) — the session service converted the whole row at once and swallowed the error, so a run with an explicit benchmark, whose benchmark_ticker is text, lost every metric without a log line. Each field is converted on its own now, and only the unconvertible one is skipped.

Alpha Zoo

  • 24 alphas emitted a value computed from a missing bar (#1463, #1523, #1534, #1452, thanks @Shizoqua). A comparison over an operand that is NaN because its window holds the gap is False, and the #1463 sweep, which nudged the bar by a tick, could not see that. A second oracle compares the gapped run with the gap-free one. Comparison gates and np.fmin/np.fmax now mask on their inputs' reach (factors.base.observed_over) rather than on their operands' NaN, so a correlation undefined on complete data keeps its old verdict; the six fmax/fmin alphas converted on 2026-09-18 had lost up to 87% of their post-warmup values in a 5-symbol universe that way and are restored. On gap-free data no finite value changed.

  • Twenty alphas no longer fill a missing input with a constant (#1463). A halt left a comparison reading 0 or False, a .where(cond, 0) reading a flat day, or an np.fmax returning the other side, and the value then fed every rolling window that reached back to the gap. Those cells are NaN now. On gap-free data every finite value is bit-identical to before. A perturbation sweep over all 462 alphas counts 35 still carrying a missing bar forward, down from 55, and every one of them is accounted for: 28 are recursive statistics (the GTJA SMA(A, n, m) smoothers and one running product), which by the policy set on #1463 skip a missing observation and continue from their last state — the operator layer's header now states that exception, and a test pins it; 3 declare their own partial window; 4 are the sweep's own rank-tie artifact. Nothing rewarms a smoother after a gap, and the registry's look-back mask was measured and rejected: it hid 4,270 legitimate cells to remove 41% of the fabricated ones.

  • Asset growth is year over year on the daily panel (#1564, thanks @Shizoqua). Derived fundamentals run on a panel densified to the price calendar, where a one-row lag compared yesterday with today: 0% on ordinary days and a one-day spike at each filing. The lag is now 365 days, as-of.

  • A factor's IC ratio is unset for a negative baseline (#1549, thanks @Shizoqua). Dividing two negative IC means gives a positive ratio, so a rolling IC that got further below zero reported as improvement. The signal itself took the worst of the available metrics and was not fooled; the published number was.

  • qlib158 CNTP / CNTN / CNTD stop counting a missing close as a flat day (#1459, thanks @cgycorey) — the 15 factors (three families × 5 / 10 / 20 / 30 / 60 windows) turn close > prev close into 0/1 and average it, and a NaN comparison reads False. The registry mask from #1377 blanks the gap bar itself, but every later window that still held the gap counted the halt as a day that neither rose nor fell, so cntd read closer to zero than the observed days say. The comparison is NaN now wherever either close is missing: a gap blanks window + 1 rows and the value returns, equal to the gap-free run, once it scrolls out. The same rule moves the first value from row window - 1 to row window, matching each factor's min_warmup_bars, because the first bar has no prior close. On sparse panels this can trip the registry's >95% NaN guard; each factor's notes states from what missing-bar fraction.

  • qlib158 WVMA takes the absolute return in its numerator, as upstream does (#1594, thanks @Shizoqua) — wvma5 … wvma60 computed ts_std(ret·v) / ts_mean(|ret|·v), a signed numerator over an absolute denominator, where qlib's formula takes Abs on both. Every value of the five factors changes. The finishing commit (a5d47c20) points the attribution header at the upstream file that actually defines WVMA (qlib/contrib/data/loader.py, MIT) instead of handler.py, and pins the formula against an independent scalar oracle, a gap and all-zero volume.

  • GTJA alphas 103, 133 and 177 score a fresh extreme high, not low (#1604, thanks @Shizoqua) — HIGHDAY / LOWDAY count bars since the extreme, but the port put the 0-based window index, counted from the oldest bar, in their place. Alpha 103 read a low set today as 5 and a low 19 bars old as 100: the recency signal was inverted. The PR restored the direction one bar off (95 and 0). The finishing commit (0244ecea) counts days since the extreme with today as 0, so alphas 103 and 177 run from 5 to 100 over a 20-bar window, and takes the most recent bar on a tie. It also corrects gtja191/LICENSE.md to cite the Guotai Junan report of 2017-06-15 by Li Chen and Liu Fubing, where the zoo had named a 2014 report.

  • A custom zoo root no longer replaces the bundled alpha of the same name (#1468, fixes #1465, thanks @cgycorey) — Registry(zoo_root=...) loaded custom alpha files into sys.modules under the bundled module's own name. Once a custom root had computed its own qlib158/cntp5.py, a default Registry() in the same process computed the custom code too. The import cache is keyed by module path and zoo root now; module names and relative imports inside a custom root are unchanged. No shipped caller passes zoo_root; it is the path tests and plugins use.

Quant Library and analysis tools

  • A strict-bench OOS split needs two IC observations on each side (#1559, thanks @Shizoqua). A split outside the loaded prices is refused. An alpha whose IC series leaves fewer than two observations on either side is skipped, with the counts in the reason. The IC series ends one forward-return horizon before the prices, so a split one bar from the end used to publish verdicts measured on nothing.

  • Quant inputs are checked before they are used (#1555-#1558, thanks @Shizoqua). HRP aligns a supplied correlation matrix, and the covariance's own rows, to the covariance's column labels; swapping two rows used to move the weights with no error. Purged cross-validation refuses an unordered or duplicated timestamp index, and a label that ends before it starts. Impact models and every fixed-income entry point refuse NaN and infinities instead of returning NaN prices, durations and curves.

  • Shadow-account overtrading uses the whole trading window (#1563, thanks @Shizoqua). A long hold that closed before later short trades no longer shrinks the span.

  • Event-study z-statistics no longer over-reject (#1466). A CAR's standard error summed each day's variance, ignoring that every day is forecast with the same estimated parameters, so the days' abnormal returns are correlated. On null data, the standardised CAR's variance was 1.11 with a 120-day estimation window and 1.41–1.46 with a 30-day one. It is now 1.02 and 1.07, which is only the t correction for an estimated residual variance. Patell and BMP inherit the fix; market_adjusted was already right.

  • Shadow account: an other-market rule no longer matches every symbol (#1538, thanks @Shizoqua), and overtrading PnL no longer double-counts trades already explained (#1475).

  • Quantlib: comps refuses negative bridge magnitudes like the DCF bridge (#1535, thanks @Shizoqua); accrued interest is exact on coupon dates under 30/360 and rejects an unknown day count there too (#1509); Kyle's lambda fits an intercept (#1477).

  • ML strategy: a single-class training window is skipped and the previous model keeps predicting (#1522, thanks @Shizoqua). Memory: two entries with one title and different types keep separate index rows, and forget names the type when ambiguous (#1525). Swarm run and task files use unique temp names (#1536).

  • Patell z uses each normal-return model's own degrees of freedom (#1449, thanks @Shizoqua) — the df / (df - 2) correction in event_study assumed the market model's two estimated parameters for every event, so market_adjusted (none estimated) and mean_adjusted (one) over-stated the variance and reported a slightly smaller |z|, and a larger p-value, than their own fits support. The market model is unchanged. The finishing commit (844b13b9) has estimate_market_model read its residual degrees of freedom from the same table, so the two cannot drift apart.

  • Microstructure estimators refuse NaN and infinite inputs (#1451, thanks @Shizoqua) — a non-finite price came back from roll_effective_spread as a 0.0 spread, kyles_lambda returned nan, and vpin produced a series from NaN or negative volumes. All three raise now, and vpin also refuses a non-finite bucket_size. amihud_illiquidity drops an infinite row the way it already dropped a NaN one; before, an infinite return made the ratio infinite and an infinite volume counted as a zero-illiquidity day. The accept side is pinned too (c6010208): constant prices are a zero spread, all-zero order flow a zero lambda, and zero-volume bars leave VPIN unchanged.

  • Copula pseudo-observations give ties one rank and leave NaN missing (#1453, thanks @Shizoqua) — the double argsort ranked tied values by position ([1, 1, 3] became 0.25 / 0.5 / 0.75) and sorted a NaN last, handing it the column's top rank and counting it in the normaliser. pseudo_observations uses average ranks now, keeps a NaN as NaN with each column normalised by its own count of observations, and refuses infinite values.

  • spread_term_structure keeps tenor 5 and 5.0 in one column (#1507, thanks @Shizoqua) — the column name was built from the raw key, so issuers quoting the same tenor as an int and as a float were split across 5Y_spread_bp and 5.0Y_spread_bp, each NaN for the other group. The reference-curve lookup already treated the two as one tenor.

  • Purged cross-validation refuses a timestamp label index it cannot map (#1556, thanks @Shizoqua) — label end times passed as a Series are turned into positions with searchsorted, which assumes a sorted index. An unordered or duplicated index mapped label ends to the wrong rows with no error, so the purge protected the wrong rows; it raises now. The finishing commit (250ef746) closes the neighbouring gap: a timestamp label ending before its own start was clipped up to it (ends at positions [1, 0, 3, 3] came back as [1, 1, 3, 3]) and now raises, as the positional form already did. A NaT end stays allowed and purges through the last observation.

  • Market-impact models refuse infinite inputs (#1557, thanks @Shizoqua) — NaN was already refused, but positive infinity passed every positivity check: an infinite ADV priced a linear_impact or sqrt_impact order at zero impact, and an infinite price, traded volume or bps returned an infinite buy fill. Price, volume, ADV, bps, impact coefficient, volatility and eta must all be finite now.

  • The correlation-analysis cointegration examples call the Quant Library (#1404, thanks @Shizoqua) — the skill's Engle-Granger example carried its own statsmodels fit and raised KeyError on an unnamed Series, because it looked the hedge ratio up by the series' name. The PR named the regressor; the finishing commit (bd29a187) replaced the local fit with find_hedge_ratio, cointegration_test and adf_test from src.quantlib.timeseries, and the half-life example with compute_half_life. The example now inherits their refusal to pair two legs on different indices positionally, keeps its result keys and adds half_life.

  • portfolio_risk_xray works on windows longer than 250 bars (#1462, closes #1461, thanks @he-yufeng) — the tool fetched prices under the shared 250-row cap. Above it fetch_market_data returns a sampled envelope rather than the bar list the tool parses, so a window of 251 bars or more failed with "no close prices returned for any requested symbol", which is about anything over a year of daily bars. It requests every row now (max_rows=0, as technical_indicators does); volatility, VaR/ES and drawdown need consecutive bars regardless.

  • benford_check reads the leading digit from the number as written (#1591, thanks @Shizoqua) — financial_rigor's Benford check took the digit from 10 ** frac(log10(v)), which lands just under an integer for some exact round values, so 5000 counted as a leading 4. Among the integers 1 to 100,000, twelve were misread (8, 30, 40, 50, 80, 500, 600, 900, 5000, 6000, 9000, 50000). The PR rounded before truncating, which would have read 4999.9999999 as a 5; the finishing commit (d0ef98a6) takes the first significant digit of a Decimal built from the supplied value instead, with no float round-trip. Zero, NaN and infinite values are still skipped.

  • The sentiment scorer reads "low" as bearish only (#1448, thanks @Shizoqua, thanks @Shizoqua) — "low" was in both the bullish and the bearish word lists, so it cancelled itself and shares tumbled to a new low today scored neutral. It was the only word in both; a test now keeps the lists disjoint.

  • Head-and-shoulders detection checks shoulder symmetry on negative series (#1456, thanks @Shizoqua) — the pattern tool divided the shoulder gap by the signed shoulder average. On a series below zero the ratio went negative and always passed the 5% test, so clearly asymmetric shoulders were flagged as a pattern. It divides by the absolute average now, as double_top_bottom already did.

Live trading, brokers and the strategy store

  • Robinhood live trading reads and trades the account the mandate names (#1442). The runner, the pre-trade gate and the commit-time ceiling fetch called Robinhood with no account_number, and read replies one level too shallow (data.positions where Robinhood nests data.data.positions). So every reconciliation aborted, and the gate refused every order because it could not read positions. The tests stayed green only because their fake replies had a shape Robinhood never sends. A Robinhood mandate is now bound at commit to one account from get_accounts: listed, not deactivated, and open to agentic trading. The Web confirm dialog and the CLI both ask for it, and never take it from the agent-written proposal. Every runner and gate call sends that account, and an order naming another account is refused. Held positions, which Robinhood reports without a price, are priced the way a quantity order already was, and one that cannot be priced fails the exposure check closed. Existing Robinhood mandates must be committed again with an account.

  • SDM decay metrics treat NaN and infinite bench results as missing (#1447, thanks @0xouzm) — three stored sharpe=inf rows read as healthy, so a non-dry sdm_decay_scan moved a strategy in monitoring back to active, and -inf read as critical. SQLite keeps infinities as written, so the persistent store was affected too. compute_decay_metrics now drops non-finite values, independently for IC and Sharpe, before the three-observation minimum.

  • A mandate narrowed to zero exposure is stored as zero (#1593, thanks @Shizoqua, thanks @Shizoqua) — narrowing max_total_exposure_usd or account_funding_usd to 0 at commit is legal, but the cap mapping used x or default, so the saved mandate got the order cap back as its exposure limit: the commit widened what the user had just narrowed. An explicit zero now persists, and an order checked against that mandate breaches max_total_exposure_usd.

  • A malformed Robinhood buying_power is a shape error, not an unknown (#1526, thanks @lorenzozanee) — a non-null buying_power that was not an object (a bare number, string or list) was read as unknown and passed; it now raises, so the portfolio source errors instead of carrying the reply. An omitted or null value stays unknown and zero stays valid. As merged the PR also refused an omitted buying_power; 46892136 restored that case to unknown, which is what the PR description specified.

  • Interval and event triggers carry market=None again (#1599, thanks @woshi77777stars, thanks @woshi77777stars) — Trigger.market was both a dataclass field and a classmethod factory, so every non-market trigger carried the bound method as its market, and dataclasses.asdict() + json.dumps() raised on it. due_now() was unaffected. The factory is bound after the class body (d0ef98a6 keeps subclass binding intact), and a repo-wide static test fails on any dataclass or NamedTuple field shadowed this way.

  • With an MT5 profile selected, search_symbol resolves the broker's own symbols (#1597, closes #1589, thanks @lorenzozanee) — it returned no MT5 candidate for an explicit symbol such as XAUUSD, so the identity gate blocked trading_quote, trading_history and get_market_data. Search now reads the configured terminal's catalog by terminal_path with no login credentials. After 47a036d6 every query is answered from that terminal while MT5 is selected, a web-search hit is never substituted, and an ambiguous alias is refused.

  • Backtests attach to the running MT5 terminal without seeing its credentials (#1598, thanks @he-yufeng) — the sandbox's ephemeral HOME had no mt5.json, so the loader attached bare and a forex backtest could fall through to akshare while get_market_data used MT5 in-process. The sandbox now gets only terminal_path and timeout (validated by 47a036d6), never login, password or server, and a bare attach warns that the SDK may pick another installation logged into another account.

  • Dhan paper orders reject fractional share quantities (#1595, thanks @Shizoqua, thanks @Shizoqua) — 0.5 passed the positive check and truncated to 0, returning a successful simulated fill for zero shares, and 1.5 silently became 1. Only whole numbers of at least one share are accepted; a5d47c20 parses with Decimal, so 1.00000000000000001 is refused too, and NaN, infinity or text return an error instead of raising.

Swarm workers

  • A swarm worker can load only the skills its spec lists (#1414, thanks @shadowinlife, thanks @shadowinlife) — SwarmAgentSpec.skills was read only to filter the prompt, so load_skill loaded any skill a worker named. The worker's load_skill now refuses a skill outside the list and names the ones allowed. An empty list stays unrestricted, as the prompt filter treats it; the main agent is unchanged.

  • A swarm tool that declares run_dir gets the directory the model named, confined to the agent's workspace (#1430, thanks @cgycorey) — the worker overwrote every call's run_dir with the workspace, so backtest, exposed to 19 preset agents, never saw the directory it was given. A relative path now resolves under the workspace, an absolute one inside it is kept, and one outside is refused with an error naming the workspace. Tools that do not declare run_dir still get the workspace.

  • Every swarm worker that writes its summary also writes its message log (#1439, thanks @cgycorey) — messages.json is the only record of the arguments the model asked a tool for, and the completed, token-limit, content-filter and incomplete exits wrote summary.md without it, so the most common outcome left no log. Both files now go through one writer. A failed LLM call still writes neither.

Agent loop, providers and goals

  • An explicit provider header survives an ambient twin (#1573, #1568, thanks @zeus229). When OPENAI_CUSTOM_HEADERS names a header the provider also sets (a user-agent beside the Kimi / NVIDIA / OpenCode User-Agent), openai 3.19.2's case-insensitive merge dropped the provider's value. That turned CI red for every PR on 2026-09-24. The first fix proposed would have sent both headers under openai 2.53, the version the lock file and the Docker image install. Every ambient spelling is now omitted and the explicit value re-set after the omits, which holds under both.

  • Read-only results lost to context compaction are restored, not refetched (#1488, thanks @zeus229). A successful read-only call whose payload compaction removed is replayed from the run's own cache, at most six times a run; past the cap it runs again, as it did before, instead of being refused with "use the previous result" for a payload the model cannot see. The cap is checked per restore, and any successful write empties the cache, so a regenerated file is read afresh. read_url opts in; no_cache=true always fetches.

  • OpenAI's gpt-5.6 models run with their reasoning on the agent's default configuration (#1473). /v1/chat/completions refuses function tools for gpt-5.6-terra and gpt-5.6-luna unless reasoning_effort is none, including when no effort is configured and the model applies its own default, so a plain LANGCHAIN_PROVIDER=openai setup failed on its first tool call with Function tools with reasoning_effort are not supported. The adapter now treats that refusal the way it treats a rejected temperature or stream_options: the request is retried on /v1/responses, where the effort travels as reasoning.effort, and the model is remembered for the rest of the process so later calls go there first. Nothing changes for a model whose chat endpoint accepts tools, and LANGCHAIN_USE_RESPONSES_API=true still selects the route up front and skips the one failed request.

  • A research goal that is an order is still refused (#1562, thanks @Shizoqua). The execution filter no longer rejects research that mentions shares or coins ("should the fund sell its GOOGL shares"). It refuses an objective that opens with buy or sell, puts a quantity right after the verb, or writes 买入 / 卖出 with a quantity and a unit. The first version of the change had made "Buy 100 shares of NVDA" an accepted goal.

  • Research goals refuse an order that puts "now" or "immediately" before the verb (#1605, thanks @Shizoqua) — the execution filter matched only the verb-then-cue order, so Immediately buy TSLA, Now sell GOOGL and Please immediately short TSLA were accepted as research objectives. The mirrored rule requires the cue to sit directly before the verb, with only separators and an optional please between them. The first version allowed up to 40 characters there and also refused Now research whether to buy AAPL; the finishing commit (0244ecea) keeps that and similar research phrasings accepted. The check runs on a goal's objective, on each of its criteria and on an objective update.

  • The tail a full compaction keeps counts a thinking model's reasoning (#1582, thanks @Shizoqua) — the layer-3 tail is sized to a 20K-token budget, but the sizing read content and tool-call arguments and skipped reasoning_content, so on reasoning-heavy turns the kept tail could run far past its budget and compaction freed less than intended. The reasoning text is counted now, as the loop's token estimate already counted it.

  • technical_indicators results are restored after compaction instead of fetched again (#1601, thanks @zeus229) — the tool is read-only but repeatable, and a repeatable tool is replayed from the run's memory only if it opts in; it did not, so an identical request after compaction re-ran the market-data fetch. It opts in now, like web_reader, within the loop's existing replay budget.

  • Token counts and Polymarket CLOB token ids are no longer redacted as credentials (#1606, thanks @Shizoqua) — the token credential marker is a substring match, so token_budget, token_usage, total_input_tokens, total_output_tokens and clob_token_id read [redacted] in traces, event previews and the live audit ledger. Since 0244ecea each is released only in its expected shape (a non-negative integer, a map of counts, a decimal uint256 id); any other value under those names stays redacted.

  • A remote MCP tool with a malformed properties schema still gets a valid one (#1607, thanks @Shizoqua) — normalize_mcp_tool_schema dropped a non-object properties such as a string or a list and then skipped the {} fallback, so the tool reached the model as an object schema with no properties key at all. It gets {} now, unless the top level composes anyOf / oneOf / allOf.

  • The Copilot credential fallback re-reads the token after 60 seconds (#1619, closes #1617, thanks @lorenzozanee) — when neither COPILOT_GITHUB_TOKEN nor OPENAI_API_KEY is set, get_llm_credentials falls back to GH_TOKEN / GITHUB_TOKEN or gh auth token, and it cached that answer for the life of the process. The cache now expires after 60 seconds. Its consumer is provider diagnostics: Copilot requests go through the SDK client, which resolves credentials each time it is created.

Channels, memory and configuration

  • The Email channel verifies TLS certificates by default (#1544, thanks @shadowinlife). The implicit-SSL paths (IMAP4_SSL / SMTP_SSL) in both the connection probe and the polling/send adapter used Python's default unverified context (CERT_NONE, no hostname check), so the mailbox password travelled to a server whose certificate was never checked — an active network attacker between the operator and their mail provider could harvest it. All four call sites now build their context through a shared email_tls_context() that verifies the certificate and hostname against the system CA bundle, matching the STARTTLS path, which already did. A new verify_tls field (default true, surfaced in the guided Email setup in all nine locales) is the documented opt-out for self-signed or internal-CA servers. Upgrade note: a mail server with such a certificate connected before this change and now fails the TLS handshake until verify_tls is set to false for it.

  • Plain IMAP no longer sends the mailbox password in clear text (after #1544). With imap_use_ssl off, the Email channel and its connection test logged in over an unencrypted connection, and the guided setup put that switch one click away. A new imap_use_tls (on by default, the IMAP twin of smtp_use_tls) upgrades the connection with STARTTLS before LOGIN; a server that offers no STARTTLS is reported as a network failure before the password is sent. verify_tls now governs STARTTLS on IMAP and SMTP as well as implicit SSL, so a self-signed server can opt out on any path. Upgrade note: an imap_use_ssl: false setup against a server without STARTTLS stops connecting until imap_use_tls is set to false for it, which sends the password in plain text again.

  • Settings-write routes reject cross-site browser requests (#1544, thanks @shadowinlife). require_settings_write_auth did not apply the cross-site guard that its siblings require_auth and require_event_stream_auth enforce on unsafe methods, so a malicious web page could attempt a CSRF write against any settings route — including the new POST /channels/email/test, which merges stored credentials with a caller-supplied patch and could be steered to send the stored mailbox password to an attacker-chosen host. The guard now runs first on every settings-write route; same-origin Web UI calls and non-browser clients (CLI/curl, no Origin) are unaffected.

  • Channel adapters log through stdlib again: {} placeholders, napcat's 17 sites and loguru-only .opt() calls lost their messages (signal's _safe_handle raised instead of swallowing) (#1533, #1531, thanks @shadowinlife). Slack DMs from unapproved senders get a pairing code (#1524, thanks @Shizoqua); Discord no longer pings @everyone or roles (#1537); duplicate-reply suppression covers integer message ids and is bounded (#1476); the WebSocket channel starts again (from #1521).

  • Two memories sharing a title keep separate index rows and links (#1545, thanks @Shizoqua). Under VT_MEMORY_HIERARCHY an entry lives at {memory_type}/{slug}.md, so two entries with one title had the same path.name: the second add() overwrote the first's MEMORY.md row, and the semantic-link block beside it excluded the other entry as "self" and wrote an ambiguous target. Both key on the path relative to the memory dir now; a sidecar written earlier, with a bare filename or an absolute path, is still read.

  • /agent.json, /agent.yaml and /agent.yml are gitignored at the runtime root; the Feishu QR login already wrote channel credentials there.

  • Signal channel: stripping the bot's mention no longer removes the wrong character after an emoji (#1478, thanks @Shizoqua) — Signal reports a mention's start and length in UTF-16 code units, and the channel sliced the Python string with them directly. Each character outside the Basic Multilingual Plane (most emoji) before the mention shifted the slice by one, so the mention placeholder stayed in the text handed to the agent and the neighbouring character was cut instead. Offsets are converted to string indices before a mention is stripped or tested as a leading mention.

  • A file received over DingTalk is saved inside its download directory whatever it is named (#1506, thanks @Shizoqua) — the adapter joined the inbound fileName to the per-sender download path unsanitized, so a name with ../ segments, or an absolute path (which replaces the whole path when joined), could write outside it. The name goes through safe_filename now, as the other adapters already sanitize a remote file name.

  • A channel that fails to load logs which one and why (#1580, thanks @Shizoqua, thanks @Shizoqua) — two channel-registry log calls had two %s placeholders and one argument, so an external plugin that failed to import, or a built-in channel skipped for a missing SDK (at debug level), printed --- Logging error --- instead of its name and the exception.

  • The README says which process owns Telegram polling (#1583, closes #1553, thanks @lorenzozanee) — Telegram allows one getUpdates poller per bot token. vibe-trading serve owns the channel runtime, and channels start asks the running server (VIBE_TRADING_API_URL, default http://127.0.0.1:8000) to start it rather than polling itself, so the conflict to avoid is a second server process with the same token enabled.

  • Memory garbage collection no longer compresses an entry it just archived (#1450, thanks @Shizoqua) — the compression pass reused the entry list read before archiving, so an entry just moved to archive/ was compressed from a path that no longer existed and logged a failure. 451c554a skips by whether the file still exists, not by id: ids are six hex characters two files can share, and an archive step that failed leaves its file to be compressed.

  • An unparseable optional numeric setting falls back to its default instead of failing config load (#1592, thanks @Shizoqua) — the coercion that drops a bad int / float env value skipped int | None fields, so ANTHROPIC_MAX_TOKENS=not_a_number raised while building EnvConfig. Optional fields get the same fallback now; a parseable value outside the field's bounds (ANTHROPIC_MAX_TOKENS=0) is still rejected.

Web UI and locales

  • Leaving a chat cancels its pending history scrolls — a scroll scheduled while a conversation's history loaded could still fire after leaving it, and a history load still in flight could schedule another.

  • A welcome-screen quick action stays highlighted after you click it (#1500, thanks @shadowinlife) — the first chip was styled as selected by its position, whatever had been clicked, so the chip you chose never lit up. The highlight now follows the click and moves with the next one, and each chip reports aria-pressed.

  • Broker SDK diagnostics no longer name Longbridge for every broker (#1436, thanks @tingkk) — the shared sdk_missing and network_unreachable messages on the Runtime page and in the chat connector status said Longbridge whichever broker raised them, so an unreachable Futu OpenD gateway sent the user to check Longbridge. They now name the affected broker's SDK, service or local gateway, in every locale.
