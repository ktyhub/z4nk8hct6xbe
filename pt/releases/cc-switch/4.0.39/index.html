Chave CC v4.0.39

Esta versão é principalmente para reparos. Um botão de cópia foi adicionado à caixa de entrada API Key; Backup pode definir o limite superior do tamanho total e, quando ultrapassar o limite, será excluído do mais antigo; quando Claude Code usa GPT-6.2 Sol / Astra por meio do Codex OAuth, a taxa de acertos do cache solicitada pelo sistema é bastante melhorada. Além disso, os provedores nativos de Claude Code e Claude Desktop foram corrigidos e precisam esperar até 600 segundos antes do failover; uma longa resposta de streaming faz com que a memória ocupada pelo uso e pela coleta de logs continue crescendo; uma caixa de confirmação ainda aparece depois que a configuração de mesclagem do link de importação com um clique falha; quando apenas a versão desktop do Codex está instalada, a página do plug-in exibe "Codex não instalado"; a página do plug-in cria uma pasta de configuração vazia para aplicativos desinstalados; O Flash DeepSeek V4.1 do OpenCode Go está faltando max Pensando em engrenagens; problemas como camadas pop-up e menus suspensos piscando quando clicados rapidamente. Adicionar

API A caixa de entrada da chave pode ser copiada com um clique

Há um botão de cópia (#9232) próximo à caixa de entrada da chave API no formulário do fornecedor. O que é copiado é a chave com os espaços iniciais e finais removidos. O sucesso ou o fracasso serão solicitados. Não é exibido quando a caixa de entrada está vazia ou não pode ser editada.

Tamanho máximo total do backup

Um novo "Tamanho total máximo de backup" foi adicionado às configurações de backup (#9011, relacionado a #6706). O padrão é “Sem limite” e nenhum backup será excluído após a atualização.

  • Após definir o limite superior, quando a pasta de backup ultrapassar esse tamanho, ela será excluída a partir do backup mais antigo.
  • O backup mais recente e o backup usado para recuperação são sempre mantidos, portanto, quando um único backup for maior que o limite superior, a pasta ainda poderá exceder o limite superior.
  • O limite superior entra em vigor no próximo backup ou manutenção diária. A manutenção diária também limpa arquivos temporários deixados por falhas de backup com mais de 24 horas.

Mudança

  • Claude Code tem maior taxa de acerto de cache ao usar GPT-6.2 Sol / Astra via Codex OAuth (#9848, consulte #9847): O prompt do sistema é alterado para ser colocado na primeira mensagem do desenvolvedor, e o backend do ChatGPT irá armazená-lo em cache junto com a conversa. A taxa real de acerto do segundo turno é de cerca de 98%. Outros modelos e roteamento com chave API permanecem inalterados.
  • Filtro de privacidade mais rápido (#9826): resultados de filtragem inalterados.

Correção

  • Quando o provedor nativo de Claude Code e Claude Desktop está travado e não consegue imprimir palavras, o failover levará até 600 segundos (#9754): esse tipo de solicitação de streaming usa o tempo limite de solicitações que não são de streaming e agora usa o tempo limite da primeira palavra (padrão 60 segundos) como outras solicitações de streaming.
  • Respostas de streaming longas ou intermináveis ​​fazem com que o uso e o uso de memória para a coleta de logs continuem a crescer (#9846, consulte #9843): O buffer agora tem até 64 MiB e pode continuar a analisar o conteúdo subsequente após encontrar eventos extremamente grandes.
  • Depois que a configuração de mesclagem do link de importação com um clique falha, a caixa de confirmação ainda aparece (#9844, consulte #9841): Agora apenas um erro é solicitado e a caixa de confirmação não é mais exibida.
  • Quando apenas a versão Desktop do Codex está instalada, a página do plug-in exibe "Codex não está instalado" (consulte #9850): Por exemplo, apenas a versão Desktop do Codex (MSIX) está instalada no Windows. Agora, quando o codex instalado separadamente não puder ser encontrado, a página do plug-in e outros locais que usam a linha de comando do Codex usarão aquele que vem com a versão desktop. A instalação, atualização e desinstalação da página "Aplicativo" ainda se aplicam apenas ao Codex CLI instalado separadamente.
  • A página do plug-in cria pastas de configuração vazias para aplicativos desinstalados (veja #9852): Ao abrir a página do plug-in, pastas vazias como ~/.codex e ~/.grok também serão criadas para aplicativos que não estão instalados como Codex, Grok Build, OpenClaw, Pi ou MiniMax Code. Agora você pode construí-lo depois de encontrar a ferramenta de linha de comando. Se não estiver instalado, ainda mostrará "Não instalado".
  • O DeepSeek V4.1 Flash do OpenCode Go não possui o equipamento de pensamento max (consulte #9853): Por padrão, a lista de modelos do OpenCode Go agora indica low, high e max. OpenCode não retorna mais ao low / medium / high universal.
  • A camada pop-up e o menu suspenso piscam quando clicados rapidamente (#9176, consulte #9175): Clicar novamente durante a animação de abertura ou fechamento não mudará duas vezes seguidas.

cc-switch v4.0.39

CC Switch v4.0.39

本版本以修复为主。API Key 输入框加了复制按钮；备份可以设置总大小上限，超过时从最旧的开始删；Claude Code 经 Codex OAuth 使用 GPT-6.2 Sol / Astra 时，系统提示的缓存命中率大幅提高。

另外修复了 Claude Code 和 Claude Desktop 的原生供应商卡住不出字时，要等最长 600 秒才故障转移；很长的流式响应让用量和日志收集占用的内存一直增长；一键导入链接合并配置失败后仍弹出确认框；只装了 Codex 桌面版时，插件页显示「未安装 Codex」；插件页给没装的应用建了空配置文件夹；OpenCode Go 的 DeepSeek V4.1 Flash 缺少 max 思考档位；快速点击时弹出层和下拉菜单闪烁等问题。

新增

API Key 输入框可以一键复制

供应商表单的 API Key 输入框旁边多了复制按钮（#9232），复制的是去掉首尾空格后的 Key，成功或失败都会提示。输入框为空或不可编辑时不显示。

备份总大小上限

备份设置里新增「备份总大小上限」（#9011，相关 #6706），默认「不限制」，升级后不会删任何备份。

  • 设置上限后，备份文件夹超过这个大小时，会从最旧的备份开始删除。
  • 最新的一份备份和恢复正在使用的备份始终保留，所以单份备份比上限还大时，文件夹仍可能超过上限。
  • 上限在下次备份或每日维护时生效。每日维护还会清理备份中途崩溃留下、超过 24 小时的临时文件。

变更

  • Claude Code 经 Codex OAuth 使用 GPT-6.2 Sol / Astra 时缓存命中率更高（#9848，见 #9847）：系统提示改放在第一条 developer 消息里，ChatGPT 后端会把它和对话一起缓存。实测从第二轮起命中率约 98%。其他模型和用 API Key 的路由不变。
  • 隐私过滤器更快（#9826）：过滤结果不变。

修复

  • Claude Code 和 Claude Desktop 的原生供应商卡住不出字时，最长要等 600 秒才故障转移（#9754）：这类流式请求用的是非流式请求的超时，现在和其他流式请求一样用首字超时（默认 60 秒）。
  • 很长或一直不结束的流式响应，让用量和日志收集占用的内存一直增长（#9846，见 #9843）：缓冲现在最多 64 MiB，遇到超大的事件后也能继续解析后面的内容。
  • 一键导入链接合并配置失败后，仍弹出确认框（#9844，见 #9841）：现在只提示错误，不再弹确认框。
  • 只装了 Codex 桌面版时，插件页显示「未安装 Codex」（见 #9850）：比如 Windows 上只装了 Codex 桌面版（MSIX）。现在找不到单独安装的 codex 时，插件页等用到 Codex 命令行的地方会改用桌面版自带的那份。「应用」页的安装、升级和卸载仍只管单独安装的 Codex CLI。
  • 插件页给没装的应用建了空配置文件夹（见 #9852）：打开插件页时，没装 Codex、Grok Build、OpenClaw、Pi 或 MiniMax Code 也会建出 ~/.codex、~/.grok 等空文件夹。现在找到命令行工具后才建，没装的照常显示「未安装」。
  • OpenCode Go 的 DeepSeek V4.1 Flash 缺少 max 思考档位（见 #9853）：预设现在按 OpenCode Go 的模型列表写明 low、high、max 三档，OpenCode 不再退回通用的 low / medium / high。
  • 快速点击时，弹出层和下拉菜单闪烁（#9176，见 #9175）：在打开或关闭的动画过程中再点一下，不会再连着切换两次。

致谢

感谢 @H15teve（GPT-6.2 缓存命中）、@minimote（复制 API Key）、@zayokami（备份总大小上限）、@vastStage（流式请求超时）、@HaiYangBG1（流式响应内存、一键导入失败提示、测试隔离）、@YUZHEthefool（隐私过滤器提速）、@Delta1035（弹出层闪烁）、@allenxu09（评审修改）、@SaladDay（代码整理）的贡献。

感谢 @IndexEeve、@Thanatos-Z、@beiqixingnang、@muchenkezhan 报告问题和提供复现信息。

完整的技术细节请见 CHANGELOG。
