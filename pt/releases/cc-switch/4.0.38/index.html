Chave CC v4.0.38

Esta versão é principalmente para reparos. Links de importação com um clique agora podem importar provedores WorkBuddy; As contas Antigravidade também podem ser trocadas no Centro de Autorização no Linux; A lista de sessões do Antigravity não é mais misturada com sessões vazias e subsessões internas, e o leitor da sessão pode ver pensamentos, chamadas de ferramentas e resultados. Além disso, foi corrigido que todos os fornecedores terceirizados desaparecem após o arquivo de configuração do DeepSeek Harness ser passado por certas ferramentas YAML; ao abrir o CC Switch no Finder, a página "Aplicativo" marca a instalação normal do npm como "incapaz de executar"; quando o armazém de habilidades não é GitHub / GitLab / Gitea, ele apenas solicita "0 habilidades" sem relatar um erro; o nível de pensamento selecionado pelo Codex para o modelo às vezes não entra em vigor; Codex Existem vários erros de conversão de formato no roteamento; o uso é contabilizado duas vezes; "Nenhuma sessão contém esta palavra" é exibido quando a procura de texto da sessão falha; a interface principal torna-se uma barra branca ou é coberta pela barra de menu do macOS; o link no Linux AppImage não responde, etc. Inglês → | Versão japonesa →

Adicionar

WorkBuddy suporta importação de links com um clique

Os links de fornecedores ccswitch:// agora podem ser importados para fornecedores WorkBuddy (#9768) e os cartões resultantes serão os mesmos adicionados manualmente na página WorkBuddy.

  • O link deverá possuir modelo; apiFormat suporta apenas openai_chat.
  • Quando o ID do modelo já estiver ocupado por outro cartão, a importação será rejeitada e não sobrará meio cartão.

Mudar conta Antigravity no Linux

No Linux, você também pode gerenciar o login e a troca de conta do agy na central de autorização. O cartão oficial exibe o limite da conta vinculada (#9774, relacionado #9245).

  • As credenciais de login são armazenadas nas chaves do sistema (Serviço Secreto). Quando o chaveiro estiver bloqueado, as verificações de antecedentes de status e saldo de crédito serão ignoradas e o desbloqueio será solicitado ao trocar ativamente de número.
  • Para cartões com conta vinculada no Linux, a caixa de diálogo "Abrir Terminal" agora tem "Usar agy para fazer login desta vez": Quando não houver nenhuma conta vinculada à máquina ou o chaveiro estiver indisponível, você pode abrir o terminal com o login atual primeiro, e a vinculação do cartão permanece inalterada.

Mudança

  • Lista de sessões antigravidade e leitor de sessões (#9266, consulte #9265): Basta procurar /usage no terminal para sair de sessões vazias deixadas para trás (exibidas como Jan 1), registros residuais que foram excluídos ou sincronizados de outros dispositivos, subagentes /boost e perguntas de bypass /btw não aparecem mais na lista e seu uso é contado como habitual. Conversas sem título usam uma prévia ou a primeira pergunta como título. O leitor de sessão pode ver pensamentos, texto, chamadas de ferramentas (incluindo MCP, navegador, etc.) e resultados de ferramentas (incluindo códigos de saída de comando, status de interrupção) e alterações de arquivo mostram o número de linhas adicionadas e excluídas. Após a atualização, o índice do corpo da sessão será reconstruído automaticamente.
  • Pesquisa de sessão e estatísticas de uso são mais rápidas (#9823, #9825): O índice de pesquisa não é mais reconstruído para cada ID e caminho de sessão ao alternar aplicativos na página de sessão, e o uso de memória é muito menor; a consulta de estatísticas de uso pode usar o índice do banco de dados, a primeira palavra é lida apenas uma vez e o preço é carregado apenas uma vez para cada consulta.
  • Remova o "Google" redundante do nome do pacote da conta Google na Central de Autorização (#9834): "Google AI Pro" para contas Antigravity e Gemini CLI agora é exibido como "AI Pro".

Correção

  • Todos os fornecedores terceirizados no DeepSeek Harness desapareceram repentinamente (consulte #9785): Depois que cordis.patch.yml for salvo por certas ferramentas YAML, o off no equipamento de pensamento se tornará false. CC Switch usado para salvá-lo como está e gravá-lo sempre que for sincronizado. DeepSeek Harness invalidou toda a configuração do fornecedor devido a esta chave ilegal. Agora será corrigido ao ler e escrever (false volta para off e a engrenagem desconhecida é removida).
  • Ao abrir o CC Switch no Finder, a página "Aplicativo" marca a instalação do npm normalmente funcionando como "incapaz de executar" (Veja #9810): O nó não pode ser encontrado no PATH usado para instalação. As ferramentas de linha de comando instaladas usando npm --prefix, volta, pnpm, bun, etc. serão consideradas inoperantes e a interface também recomendará a reinstalação ou desinstalação. A detecção agora inclui o PATH do shell de login, o mesmo que quando o CC Switch executa outras ferramentas de linha de comando. O Windows não é afetado.
  • Ao adicionar um armazém de habilidades em um site não suportado (como cnb.cool), apenas "0 habilidades" serão solicitadas sem erro (consulte #9812): Este tipo de site retornará uma página da web para qualquer endereço, e a página da web baixada anteriormente será tratada como um pacote compactado e não haverá aviso se falhar. Agora aparecerá a mensagem "O pacote baixado não é compactado: este site pode não ser o armazém GitHub / GitLab / Gitea e ainda não é compatível."
  • O nível de pensamento selecionado manualmente (como max, ultra) para o modelo no Codex às vezes não entra em vigor (#9017, consulte #8952): Quando o nome do modelo corresponde ao modelo oficial do Codex, o diretório do modelo gerado usa o nível de pensamento oficial. Agora pressione Escrever selecionado no cartão.
  • Quando o Codex é convertido para o formato Chat via roteamento, ferramentas com nomes semelhantes colidirão (#9554, consulte #9551): Quando o nome da ferramenta ou namespace contém __, a ferramenta pode ter sido perdida no passado ou a chamada pode ter sido enviada para a ferramenta errada. Cada ferramenta agora tem um nome exclusivo e as chamadas podem ser mapeadas com precisão.
  • Conversas usando modelos de terceiros por meio de roteamento Codex não podem continuar após a mudança para o modelo oficial (#9756, consulte #9054): O ID da mensagem convertida começa com resp_, e a interface oficial exige que comece com msg_. No modo de conexão direta, invalid_id_prefix será reportado. O ID recém-gerado muda para começar com msg_; as conversas antigas que foram salvas permanecem inalteradas.
  • Quando Codex é conectado a Claude no AWS Bedrock por meio do roteador, cada solicitação reporta 400 (#8659, consulte #6118): A definição da ferramenta contém um campo strict específico do OpenAI extra, que Bedrock não aceita. Este campo não é mais encaminhado.
  • Cálculo duplo de dosagem:
    • Quando o nome do modelo possui um prefixo de gateway (como antigravity/gemini-3.8-flash-high), a mesma solicitação é contada uma vez no registro de roteamento e no log de sessão do Codex (#9249). Agora remova o prefixo e compare novamente.
    • Após a atualização do antigo arquivo de sessão do Gemini, o uso arquivado foi importado novamente; o número de tokens na sessão mudou, mas não foi atualizado (#9527, consulte #9523).
  • As gravações de cache para Codex nas estatísticas de uso mostram N/A (#8191): Os valores reais agora são mostrados, apenas Gemini e Grok Build ainda mostram N/A (eles não relatam gravações de cache). O log de solicitação também não conta mais as gravações do cache do Codex como nova entrada.
  • A velocidade de saída do Antigravity é mostrada como uma estimativa, que é baixa (#9788, consulte #9787): O próprio Antigravity registra o tempo da primeira palavra e a duração da saída de streaming, que não foram usados ​​​​antes. A velocidade é estimada com base no tempo total gasto (incluindo a espera antes da primeira palavra). Agora conta a duração real da saída como para solicitações roteadas.
  • Quando ocorre um erro na pesquisa de texto da conversa, "Nenhuma conversa contém esta palavra" é exibido (#9512, consulte #9511): Agora será exibido "A pesquisa de texto falhou e só pode ser pesquisada por título, diretório e primeira e última mensagens." Você pode clicar em "Tentar novamente" e a conversa será incluída novamente no índice ao tentar novamente.
  • Dois problemas de limite com sessões OpenCode (#7982): Sessões que foram migradas para o novo formato e depois continuadas no OpenCode 1.x usadas para exibir o conteúdo antigo; quando a migração para o novo formato foi interrompida no meio do caminho, as sessões inacabadas não ficaram mais ocultas.
  • O comando de sessão de restauração do Oh My Pi reportará um erro quando colado no PowerShell no Windows (#9153, consulte #9152): O método de escrita do PowerShell agora é gerado no Windows, e o macOS e o Linux permanecem inalterados.
  • Nada acontece ao clicar em um link ou abrir uma pasta em um AppImage do Linux (#9113, consulte #9112): A versão antiga do xdg-open que vem com o AppImage não faz nada no KDE Plasma 6. Agora use o próprio xdg-open do sistema. deb/rpm, macOS e Windows não são afetados.
  • No macOS, feche a interface principal de tela inteira da bandeja e ela será coberta pela barra de menu e pelo Dock quando você abri-la novamente (#9770, consulte #9769): Agora você sairá da tela inteira antes de fechar a bandeja e restaurará a tela inteira ao abri-la novamente na bandeja, Dock, etc.
  • A interface principal é apenas uma barra branca após a abertura (#9504, consulte #9496): O tamanho da janela lembrado é anormalmente pequeno e é restaurado para o tamanho padrão quando aberto.
  • Ao editar um fornecedor, feche o editor que ainda está sendo salvo e abra-o novamente, e o botão "Salvar" continuará girando (#9593, veja #9592).
  • A migração de login da versão antiga do Copilot desistirá ao encontrar o tempo limite da rede e tentará novamente após reiniciar (#9549, consulte #9544): Agora, depois que a rede for restaurada, a migração continuará na próxima vez que o Copilot for usado sem reiniciar; ele só desistirá se o token expirar (401/403) ou sair.
  • O endereço da estação de transferência foi confundido com o fabricante oficial (#9648): Quando um nome de domínio oficial aparece no caminho ou nos parâmetros do endereço, ou o nome de domínio parece semelhante (como api.x.ai.example.com), ele era anteriormente considerado como esse fabricante: xAI tratará disso especificamente, e o saldo e o limite do pacote também serão verificados de acordo com o modelo oficial dessa empresa. Agora observe apenas os nomes de domínio reais.
  • Durante operações como importação de configuração e download de sincronização em nuvem, alguns fornecedores no aplicativo cumulativo não foram gravados no arquivo de configuração, mas o prompt foi bem-sucedido (#9747): Os fornecedores que não foram gravados serão agora listados.
  • Depois de mover o local de armazenamento de habilidades, alguns aplicativos não conseguiram vincular novamente, mas relataram sucesso (#9748): Agora será listado no prompt.

cc-switch v4.0.38

Highlights

  • WorkBuddy providers via shareable links — ccswitch:// links can now create WorkBuddy provider cards (#9768), extending the one-click import flow that previously excluded this provider. The constraints matter when distributing configs to a team: the link must include a model, apiFormat is limited to openai_chat, and a model ID already claimed by another card causes the whole import to be rejected rather than leaving a half-created card. Plan model IDs ahead of time if you're generating links programmatically.

  • Linux Antigravity account management — Authorization Center now handles agy login/account switching on Linux, with quota shown on the official card (#9774, #9245). Credentials live in the system Secret Service keyring, so headless or locked-keyring environments will silently skip background status/quota refresh and only prompt for unlock on an explicit switch — worth knowing before scripting this on CI boxes. The new "use current agy login for this session" option in the terminal dialog is a useful escape hatch that keeps the card's binding untouched.

  • Antigravity session cleanup and a one-time index rebuild — The session list now filters out empty /usage exits (Jan 1 entries), deleted or cross-device leftovers, /boost subagents, and /btw side questions, while their usage still counts; untitled sessions fall back to preview text or the first prompt (#9266). The reader surfaces thinking blocks, tool calls (including MCP/browser), tool results with exit codes and interruption state, and file diffs with add/delete line counts. Expect a one-time body-index rebuild after upgrading — searches may be incomplete until it finishes, and long-lived sessions will look noticeably different in the list.

  • Codex routing correctness — Four format fixes unblock previously broken routed workflows: manually selected thinking levels like max/ultra are no longer overwritten by official-model defaults (#9017); uniquely generated tool names prevent __-containing names from colliding or misrouting calls (#9554); converted message IDs now use the required msg_ prefix instead of resp_, fixing invalid_id_prefix when switching a routed conversation to an official model (#9756); and the OpenAI-only strict field is stripped from tool definitions for AWS Bedrock Claude, eliminating per-request 400s (#8659). Note that the ID fix is forward-only — already-stored conversations keep their old IDs.

  • Usage numbers you can trust — Gateway prefixes such as antigravity/ are stripped before deduplication so a single request isn't counted in both the route log and Codex session log (#9249); updated legacy Gemini session files no longer re-import archived usage and now refresh changed token counts (#9527); Codex cache-write reports real values instead of N/A and is no longer double-counted as new input (#8191). Session search and usage queries also got faster and lighter — no per-session index rebuild when switching apps, indexed queries, single-pass first-token reads, and pricing loaded once per query (#9823, #9825). Recomputed historical figures may shift once these fixes are applied.

  • Self-healing config and honest failure reporting — The DeepSeek Harness .yml fix is the subtle one: after certain YAML editors turn off into false, CC Switch used to write the invalid key back on every sync until Harness rejected the entire vendor block; it now normalizes false→off and drops unknown tiers on both read and write (#9785). npm/volta/pnpm/bun installs are no longer falsely flagged as "cannot run" when CC Switch is launched from Finder, because detection now uses the login-shell PATH (#9810); proxy URLs are matched by real hostname instead of substrings like api.x.ai.example.com (#9648); and partial failures during config import/cloud sync or skill relocation are now listed instead of reporting success (#9747, #9748). Search errors are surfaced as failures with a retry action rather than a misleading "no sessions contain this term" (#9512).

No breaking changes in this release.

新增

WorkBuddy 支持一键导入链接

ccswitch:// 供应商链接现在可以导入 WorkBuddy 供应商（#9768），生成的卡片和在 WorkBuddy 页手动添加的一样。

  • 链接必须带模型；apiFormat 只支持 openai_chat。
  • 模型 ID 已被别的卡片占用时，导入会被拒绝，不会留下半截卡片。

Linux 上切换 Antigravity 账号

Linux 上也能在授权中心管理 agy 的登录、切换账号，官方卡片上显示所绑定账号的额度（#9774，相关 #9245）。

  • 登录凭据存在系统的钥匙串（Secret Service）里。钥匙串锁着时，后台查状态和额度会跳过，主动切号时会请求解锁。
  • Linux 上绑了账号的卡片，「打开终端」对话框里多了「本次使用 agy 当前登录」：本机没有绑定的账号或钥匙串不可用时，可以先用当前登录打开终端，卡片的绑定保留不变。

变更

  • Antigravity 会话列表和会话阅读器（#9266，见 #9265）：在终端里只查一下 /usage 就退出留下的空会话（显示为 Jan 1）、已删除或从别的设备同步来的残留记录、/boost 子代理和 /btw 旁路提问不再出现在列表里，它们的用量照常统计。没有标题的会话用预览或第一句提问当标题。会话阅读器能看到思考、正文、工具调用（含 MCP、浏览器等）和工具结果（含命令退出码、中断状态），文件改动显示增删行数。升级后会话正文索引会自动重建一次。
  • 会话搜索和用量统计更快（#9823、#9825）：会话页切换应用时不再为每个会话 ID 和路径重建搜索索引，内存占用也小得多；用量统计的查询能用上数据库索引，首字时间只读一遍，价格每次查询只加载一次。
  • 授权中心里 Google 账号的套餐名去掉多余的「Google」（#9834）：Antigravity 和 Gemini CLI 账号的「Google AI Pro」现在显示为「AI Pro」。

修复

  • DeepSeek Harness 里所有第三方供应商突然消失（见 #9785）：cordis.patch.yml 经过某些 YAML 工具保存后，思考档位里的 off 会变成 false。CC Switch 以前会原样存下来、每次同步都写回去，DeepSeek Harness 因为这一个非法键把整段供应商配置都判为无效。现在读写时都会改正（false 改回 off，不认识的档位去掉）。
  • 从访达打开 CC Switch 时，「应用」页把能正常用的 npm 安装标成「无法运行」（见 #9810）：检测安装时用的 PATH 里找不到 node，用 npm --prefix、volta、pnpm、bun 等方式装的命令行工具就会被判成无法运行，界面还会建议重装或卸载。现在检测时带上登录 shell 的 PATH，和 CC Switch 运行其他命令行工具时一样。Windows 不受影响。
  • 添加不支持的站点（如 cnb.cool）上的技能仓库时，只提示「0 个技能」而不报错（见 #9812）：这类站点对任何地址都返回一个网页，以前下载到的网页被当成压缩包，失败了也没有提示。现在会提示「下载到的不是压缩包：这个站点可能不是 GitHub / GitLab / Gitea 仓库，暂不支持」。
  • Codex 给模型手动选的思考等级（如 max、ultra）有时没生效（#9017，见 #8952）：模型名和 Codex 官方模型对得上时，生成的模型目录用的是官方的思考等级。现在按卡片里选的写入。
  • Codex 经路由转成 Chat 格式时，名字相近的工具会撞名（#9554，见 #9551）：工具名或命名空间里自带 __ 时，以前可能丢掉工具，或者把调用发给错的工具。现在每个工具都有唯一的名字，调用能准确对回去。
  • Codex 经路由用过第三方模型的对话，切到官方模型后无法继续（#9756，见 #9054）：转换出来的消息 ID 以 resp_ 开头，官方接口要求以 msg_ 开头，直连模式下会报 invalid_id_prefix。新生成的 ID 改为 msg_ 开头；已经存下的旧对话不变。
  • Codex 经路由连 AWS Bedrock 上的 Claude 时，每个请求都报 400（#8659，见 #6118）：工具定义里多带了 OpenAI 专用的 strict 字段，Bedrock 不接受。现在不再转发这个字段。
  • 用量重复计算：
    • 模型名带网关前缀（如 antigravity/gemini-3.8-flash-high）时，同一个请求在路由记录和 Codex 会话日志里各算一次（#9249）。现在去掉前缀再比对。
    • Gemini 旧会话文件更新后，已经归档的用量又被导入一次；会话里的 token 数变了却没有更新（#9527，见 #9523）。
  • 用量统计里 Codex 的缓存写入显示 N/A（#8191）：现在显示实际数值，只有 Gemini 和 Grok Build 仍显示 N/A（它们不上报缓存写入）。请求日志也不再把 Codex 的缓存写入算进新输入。
  • Antigravity 的输出速度显示为估算值，偏低（#9788，见 #9787）：Antigravity 自己记录了首字时间和流式输出时长，以前没用上，速度按总耗时（含首字前的等待）估算。现在和经路由的请求一样按实际输出时长计算。
  • 会话正文搜索出错时，显示「没有会话包含这个词」（#9512，见 #9511）：现在会提示「正文搜索失败，暂时只能按标题、目录和首末消息查找」，可以点「重试」，重试时会把会话重新收录进索引。
  • OpenCode 会话的两个边界问题（#7982）：迁移到新格式后又在 OpenCode 1.x 里继续的会话，以前显示的是旧内容；新格式迁移中途中断时，没迁完的会话不再被隐藏。
  • Oh My Pi 的恢复会话命令在 Windows 上粘贴到 PowerShell 会报错（#9153，见 #9152）：Windows 上现在生成 PowerShell 写法，macOS 和 Linux 不变。
  • Linux AppImage 里点链接在浏览器中打开、或打开文件夹，没有任何反应（#9113，见 #9112）：AppImage 自带的旧版 xdg-open 在 KDE Plasma 6 下什么都不做。现在改用系统自己的 xdg-open。deb / rpm、macOS 和 Windows 不受影响。
  • macOS 上把全屏的主界面关到托盘，再打开时被菜单栏和 Dock 遮住（#9770，见 #9769）：现在关到托盘前先退出全屏，从托盘、Dock 等再打开时恢复全屏。
  • 主界面打开后只是一条白条（#9504，见 #9496）：记住的窗口尺寸异常小时，打开时恢复成默认大小。
  • 编辑供应商时，关掉还在保存的编辑器再打开，「保存」按钮一直转圈（#9593，见 #9592）。
  • Copilot 旧版登录迁移遇到网络超时就放弃，要重启才会再试（#9549，见 #9544）：现在网络恢复后，下次用到 Copilot 时会继续迁移，不用重启；只有令牌失效（401 / 403）或退出登录才放弃。
  • 中转站地址被误认成官方厂商（#9648）：地址的路径或参数里出现官方域名，或者域名长得像（如 api.x.ai.example.com）时，以前会被当成那家厂商：xAI 走专门的处理，余额和套餐额度也按那家的官方模板查。现在只看真正的域名。
  • 导入配置、云同步下载等操作中，累加式应用有供应商没写进配置文件，却提示成功（#9747）：现在会列出写入失败的供应商。
  • 移动技能存储位置后，有应用没能重新链接，却提示成功（#9748）：现在会在提示里列出来。
