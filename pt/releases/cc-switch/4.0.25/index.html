Chave CC v4.0.25

Esta versão adiciona uma verificação de conectividade à página MCP, que pode verificar com um clique se todos os servidores MCP habilitados podem ser conectados; quando o Codex usa a conta oficial por meio de roteamento local, a solicitação oficial pode ser suspensa automaticamente antes que a cota esteja quase esgotada e modelos de terceiros ainda estejam disponíveis. Além disso, a taxa de câmbio na página de uso pode ser obtida automaticamente e o formulário do fornecedor Codex pode definir o limite de simultaneidade do subagente. Quando Claude Code e Claude Desktop são roteados ou agregados, o menu de modelos indicará de qual fornecedor cada modelo vem e qual modelo ele realmente é. As sessões do Kimi Code também podem ser excluídas no gerenciamento de sessões. Ele também corrigiu problemas como "terminal aberto" misturando configurações de roteamento e agregação, fornecedores como OpenCode Go no modo de roteamento solicitando a Claude Code para fazer login novamente, erros sendo relatados toda vez após enviar um arquivo para um modelo de texto simples, fornecedor conteúdo do formulário no Windows piscando para frente e para trás, o painel da bandeja não sendo aberto na inicialização e o uso sendo contado duas vezes quando o Codex usa o mapeamento de modelo. Adicionar

Verificação de conectividade MCP

Antigamente, após a configuração do servidor MCP, só se sabia se ele poderia ser conectado quando era utilizado na ferramenta de programação (#4498). Agora existe um botão “Verificar conectividade” no topo da página do MCP, que irá verificar todos os servidores habilitados; existe também uma “Conexão de Teste” no menu de cada linha, e somente esta será verificada.

  • Não será marcado automaticamente ao abrir a página, e será exibido "desmarcado" caso não tenha sido marcado; após alterar a configuração de conexão de um determinado servidor, seus resultados serão zerados.
  • O método de verificação consiste em completar um handshake MCP com o servidor, e todos os três métodos de conexão, comando local (stdio), HTTP e versão antiga SSE, são suportados. Aguarde até 30 segundos por servidor e todo o aplicativo poderá verificar até 3 simultaneamente.
  • Após a verificação do servidor iniciado pelo comando local, ele terminará junto com o processo filho iniciado e nenhum processo em segundo plano será deixado. Comandos como npx e uvx também podem ser encontrados no macOS e Linux quando o CC Switch não é iniciado a partir do terminal.

Proteção de cota oficial do Codex

Quando o Codex usa a conta oficial do ChatGPT, ele entrará no modo de reserva quando a cota de cinco horas ou semanal for esgotada. Agora você pode suspender solicitações oficiais quando a cota estiver quase esgotada, saindo da cota, e modelos de terceiros ainda podem ser usados ​​normalmente. Ative a "Proteção de cota oficial" em "Configurações → Configuração do aplicativo → Aprimoramento do aplicativo Codex", você pode definir limites de uso de cinco horas e semanais (padrão 95% e 98%) e suspender novas solicitações oficiais quando um deles for atingido.

  • Só entra em vigor para solicitações oficiais do Codex roteadas localmente por meio do CC Switch e está desativado por padrão.
  • A taxa de utilização lê diretamente as informações de cota incluídas na resposta oficial. Solicitações múltiplas não serão enviadas durante o uso normal; ele será consultado separadamente somente depois de começar a ser usado ou ficar inativo por cerca de 5 minutos.
  • Se a cota não for encontrada (problemas de rede, expiração de login, etc.), o sistema será liberado normalmente e não haverá bloqueio incorreto. As solicitações suspensas retornarão erros diretamente e não serão transferidas para outros provedores na fila de failover.

Obtenha automaticamente a taxa de câmbio na página de uso

A área "Exibição" em "Configurações de uso" na página de uso possui uma "Fonte de taxa de câmbio". Você pode escolher "Preenchimento Manual" (padrão) ou "Obtenção Automática". Somente quando a recuperação automática for selecionada a rede será conectada. A taxa de câmbio será atualizada automaticamente se ultrapassar 12 horas. Se a recuperação falhar, a última taxa de câmbio continuará a ser usada. A taxa de câmbio obtida automaticamente e a preenchida manualmente são salvas separadamente. Quando você voltar para o preenchimento manual, o valor preenchido ainda estará lá. As taxas ainda são registradas em dólares americanos e só são convertidas quando mostradas.

Limite de simultaneidade de subagentes do Codex

Há um "Limite de simultaneidade de subagentes" no "Modelo de subagentes" no formulário de fornecedor do Codex, que define o número máximo de subagentes que podem ser abertos simultaneamente em uma sessão do Codex (#9055). Esta é a configuração global do Codex. [agents] max_threads inscrito em config.toml permanecerá inalterado na troca de fornecedor, podendo também ser alterado no cartão oficial; se deixado em branco, o valor padrão do Codex será usado.

O menu Modelo indica o fornecedor e o modelo real

Código Claude No modo roteamento, cada arquivo do menu /model lia apenas "Modelo Sonnet Personalizado", sendo impossível saber qual modelo correspondia a qual fornecedor. Agora será escrito como "Fornecedor · Modelo Atual · Janela" (a janela só é exibida quando o cursor está 1M para cima), e o mesmo vale para modelos em modo de agregação. Se o próprio fornecedor tiver escrito a descrição do modelo, aquela escrita por você prevalecerá. Claude Desktop Nos modos de roteamento e agregação, a descrição abaixo do modelo utilizado para aplicar a cópia oficial conforme Opus e Sonnet no nome, e o modelo de agregação exibia sempre a mesma frase. Agora também altere para "Fornecedor·Modelo Real·Janela".

Excluir sessão do Kimi Code

As sessões do Kimi Code podem ser excluídas diretamente no gerenciamento de sessões. No passado, eles só podiam ser excluídos no Kimi Code. O método de exclusão é o mesmo do próprio Kimi Code, e o histórico do subagente será excluído junto. Preço: Adicionado GPT-6.1 Terra à lista de preços integrada.

Mudança

  • O roteamento local não aceita mais solicitações de páginas da web. A rota local substituirá a solicitação pelas credenciais de provedor salvas e depois a encaminhará. Portanto, se a página da Web puder enviar a solicitação para a rota local, ela poderá esgotar sua cota. As solicitações com uma tag de origem do navegador serão rejeitadas e o acesso a esta máquina por meio de um nome de domínio comum não será mais aceito. As solicitações enviadas pelas ferramentas de programação não são afetadas.
  • A barra de ferramentas da página "Descobrir" de Habilidades está alinhada com a página "Instalado" (#9125): A posição e a largura da caixa de pesquisa são consistentes, o botão de atualização é alterado para o botão de texto "Atualizar Warehouse", a origem, o filtro de warehouse e "Ver apenas desinstalados" são movidos para o cabeçalho e "Instalar em" é colocado no lado direito do cabeçalho. Falta uma linha, mas a funcionalidade permanece a mesma.
  • Quando o terminal preferido no Windows for o PowerShell, se o PowerShell 7 estiver instalado, use-o para abrir (#8992, #3271). Caso contrário, use o Windows PowerShell que acompanha o sistema. Isso vale para “abrir o terminal” do cartão do fornecedor e instalar e atualizar aplicativos.
  • Padrão: O plano pré-pago e de token da Qianwen AI Platform e QwenCloud são alterados para o novo nome de domínio MaaS, e o plano de codificação permanece inalterado.

Correção

  • No modo de roteamento ou agregação, o "Terminal Aberto" da placa Claude Code mistura configurações de roteamento e agregação. O Código Claude no terminal trará ao mesmo tempo as credenciais do placeholder da rota e a Chave deste cartão. O arquivo de modelo que não corresponder a este cartão usará o nome do modelo na agregação e o endereço enviado para este cartão não será usado; modelos de outros fornecedores também aparecerão no menu /model. Agora apenas as configurações próprias desta placa são usadas no terminal, e suas outras configurações globais são mantidas como de costume.
  • No modo de roteamento, fornecedores como OpenCode Go que usam ANTHROPIC_API_KEY para armazenar chaves solicitarão ao Claude Code para confirmar a chave personalizada. Se você selecionar "Não" por padrão, você não estará logado (#8111, #8104). Agora no modo de roteamento, as credenciais do espaço reservado são sempre escritas em ANTHROPIC_AUTH_TOKEN e as solicitações enviadas ao upstream permanecem inalteradas.
  • Após enviar um arquivo ou áudio para o modelo de texto simples, 400 serão reportados em cada rodada subsequente (#6274, #6151). Agora, ao enviar para um modelo de texto simples via roteamento, os arquivos e áudio da conversa serão substituídos por uma descrição em texto; o relatório de erros chinês do GLM também pode ser reconhecido. O processamento de imagens permanece inalterado.
  • Nomes e outros conteúdos no formulário do fornecedor no Windows piscam para frente e para trás (#6420, #6349). Este é o preenchimento automático do WebView2 sobrepondo o conteúdo do formulário, agora desativado na janela principal.
  • O painel da bandeja não pode ser aberto e não pode ser retirado da bandeja por um período de tempo após a inicialização (#9154). O uso da sessão importada ocupará o banco de dados na inicialização e o painel da bandeja deverá aguardar os dados. Agora o painel aparecerá primeiro, “Abrir janela principal” e “Sair” estarão disponíveis imediatamente e a lista será então carregada.
  • Quando o Codex usa mapeamento de modelo via roteamento, o uso da mesma solicitação é contado duas vezes (#7643, #5526). O que é registrado no log da sessão é o nome do modelo usado pelo Codex, e o que é registrado no roteamento é o nome do modelo mapeado, que não pode ser correspondido durante a desduplicação. Agora os dois lados podem se enfrentar.
  • A cota utilizada pelo subagente no exemplo oficial do Pi não está incluída nas estatísticas (#8386, #8340). Agora será registrado separadamente de acordo com o fornecedor e modelo de cada subagente. Após a atualização, a sessão Pi anterior será relida e reconstituída.
  • Ao importar o MCP do Pi, os servidores não suportados pelo Pi também foram importados e ativados, e todas as sincronizações subsequentes falharam (#7888). Servidores com métodos de conexão SSE, nomes não compatíveis e servidores cujos nomes são diferentes apenas de - e _ serão agora ignorados e solicitados; o arquivo de configuração MCP do Pi não será mais criado quando o Pi não estiver instalado.
  • Quando apenas o agente está configurado no terminal ou CC Switch e nenhum agente do sistema está configurado, a sincronização de preços de models.dev continua falhando (#8739, #6696). Agora ele é baixado pelo CC Switch em segundo plano, e o agente que você configurou será usado; o mesmo vale para importar preços de modelos e preencher automaticamente os parâmetros do modelo no formulário.
  • Quando Claude Code se conecta ao xAI através de um roteador, a solicitação de busca forçada de rede é rejeitada pelo xAI e reporta 422 (#8664).
  • MiniMax M3.1 Flash Thinking Gears em Pi (#8540): As duas predefinições oficiais do MiniMax removem "Desligado" e "Mínimo" que não são aceitos por este modelo, e as engrenagens restantes são enviadas normalmente.

cc-switch v4.0.25

Highlights

  • MCP connectivity checks — The MCP page gains a "check connectivity" button that handshakes every enabled server (stdio, HTTP, and legacy SSE), with a 30s per-server timeout and a cap of three concurrent checks; each row also gets a "test connection" for a single server. This matters because previously you only found out a server was dead when a coding tool actually tried to use it (#4498). Watch out: results are lazy, not live — nothing is checked on page open, and editing a server's connection config resets its status, so a green result is a point-in-time signal.

  • Codex official quota protection — Opt-in under Settings → App Config → Codex App Enhancements: once 5-hour or weekly usage on an official ChatGPT account crosses a threshold (95%/98% by default), new official requests are paused while third-party models keep working. It applies only to official requests through CC Switch's local router, reads quota data already in responses (no extra calls in steady state), and fails open if quota can't be read. Important behavioral caveat: paused requests return an error outright rather than falling through to your failover queue — plan for a hard stop, not a graceful handoff.

  • Breaking: local router rejects web-origin requests — Requests carrying a browser origin marker, and access to the local router via a normal domain pointing at localhost, are now refused; coding-tool traffic is unaffected. This closes a hole where any web page could spend your stored provider credentials (reported responsibly by @yukitakasama). If you had a custom web UI or dashboard calling the local router, that integration will break and needs to move to a non-browser client.

  • Model menus show provider and actual model — Claude Code's /model menu in route mode, and Claude Desktop in route/aggregate mode, now label entries as "provider · actual model · window" (window only when 1M is in play), replacing the generic "Custom Sonnet model" and name-based Opus/Sonnet guesses. Custom descriptions you set on a provider take precedence. This is a genuine debugging win for tracing which upstream a request hit — especially paired with the auth fix below.

  • Usage accounting fixes — Two long-standing billing bugs are resolved: Codex requests using model mapping were double-counted because session logs and router logs disagreed on the model name (#7643, #5526), and Pi official-example subagent usage was omitted entirely (#8386, #8340). On upgrade, past Pi sessions are re-read to backfill missing usage. Also in route mode, placeholder credentials now go into ANTHROPIC_AUTH_TOKEN instead of ANTHROPIC_API_KEY, fixing Claude Code prompting for a custom key and ending up logged out after choosing "no" (#8111, #8104) — upstream requests are unchanged.

  • Subagent concurrency and exchange rates — Codex provider forms gain a "subagent concurrency limit" that writes [agents] max_threads into config.toml; it's a global setting that survives provider switches (also editable on the official card), and blank means the Codex default (#9055). The usage page can now auto-fetch exchange rates (12h refresh, falls back to the last known rate, stored separately from manual entries), and Kimi Code sessions can finally be deleted from session management, including subagent history.

新增

MCP 连通性检查

以前 MCP 服务器配好以后，只有在编程工具里用到时才知道能不能连上（#4498）。

现在 MCP 页面顶部多了「检查连通性」按钮，会检查所有已启用的服务器；每一行的菜单里也有「测试连接」，只检查这一个。

  • 打开页面时不会自动检查，没检查过的显示「未检查」；改了某个服务器的连接配置后，它的结果会重置。
  • 检查方式是和服务器完成一次 MCP 握手，本地命令（stdio）、HTTP 和旧版 SSE 三种连接方式都支持。每个服务器最多等 30 秒，整个应用同时最多检查 3 个。
  • 本地命令启动的服务器检查完会连同它启动的子进程一起结束，不会留下后台进程。macOS 和 Linux 上不从终端启动 CC Switch 时，也能找到 npx、uvx 这类命令。

Codex 官方额度保护

Codex 用官方 ChatGPT 账号时，五小时或每周额度用完会进入 Reserve 模式。现在可以在额度快用完时先暂停官方请求，留着额度，第三方模型照常可用。

在「设置 → 应用配置 → Codex 应用增强」里打开「官方额度保护」，可以设置五小时和每周使用率的阈值（默认 95% 和 98%），任一达到就暂停新的官方请求。

  • 只对经过 CC Switch 本地路由的 Codex 官方请求生效，默认关闭。
  • 使用率直接读官方响应里自带的额度信息，正常使用时不会多发请求；刚开始用或空闲约 5 分钟后，才会先单独查询一次。
  • 查不到额度（网络问题、登录过期等）时照常放行，不会误挡。被暂停的请求会直接返回错误，不会转到故障转移队列里的其他供应商。

用量页汇率自动获取

用量页「用量设置」里的「显示」区多了「汇率来源」，可以选「手动填写」（默认）或「自动获取」。选了自动获取才会联网，汇率超过 12 小时会自动更新，获取失败时继续用上次的汇率。自动获取的汇率和手动填的分开保存，切回手动填写时你自己填的值还在。费用仍按美元记录，只在显示时换算。

Codex 子代理并发上限

Codex 供应商表单的「子代理模型」下面多了「子代理并发上限」，设置一个 Codex 会话里最多同时开多少个子代理（#9055）。这是 Codex 的全局设置，写进 config.toml 的 [agents] max_threads，切换供应商时保持不变，官方卡片上也能改；留空就用 Codex 的默认值。

模型菜单写明供应商和实际模型

Claude Code 在路由模式下，/model 菜单里每一档以前只写「Custom Sonnet model」，看不出对应哪家供应商的哪个模型。现在会写成「供应商 · 实际模型 · 窗口」（窗口只在上游标了 1M 时显示），聚合模式下的模型也一样。供应商里自己写过模型说明的，以你写的为准。

Claude Desktop 在路由和聚合模式下，模型下面的说明以前按名字里的 Opus、Sonnet 套用官方文案，聚合模型一律显示同一句。现在也改成「供应商 · 实际模型 · 窗口」。

删除 Kimi Code 会话

会话管理里可以直接删除 Kimi Code 会话了，以前只能去 Kimi Code 里删。删除方式和 Kimi Code 自己的一样，子代理的历史会一起删掉。

定价： 内置价格表新增 GPT-6.1 Terra。

变更

  • 本地路由不再接受网页发来的请求。本地路由会把请求换成你保存的供应商凭据再转发，所以网页如果能把请求发到本地路由，就能用掉你的额度。现在带浏览器来源标记的请求会被拒绝，通过普通域名指向本机的访问也不再接受。编程工具发的请求不受影响。
  • Skills「发现」页的工具栏和「已安装」页对齐（#9125）：搜索框位置和宽度一致，刷新按钮改为「刷新仓库」文字按钮，来源、仓库筛选和「只看未安装」挪进表头，「安装到」放在表头右侧。少了一行，功能不变。
  • Windows 上首选终端是 PowerShell 时，装了 PowerShell 7 就用它打开（#8992、#3271），没装才用系统自带的 Windows PowerShell。供应商卡片的「打开终端」和应用的安装、升级都是这样。
  • 预设： 千问 AI 平台和 QwenCloud 的按量付费、Token Plan 改用新的 MaaS 域名，Coding Plan 不变。

修复

  • 在路由或聚合模式下，Claude Code 卡片的「打开终端」混入了路由和聚合的设置。终端里的 Claude Code 会同时带上路由的占位凭据和这张卡片的 Key，这张卡片没配的模型档位会用上聚合里的模型名，发到这张卡片的地址上用不了；/model 菜单里也会出现其他供应商的模型。现在终端里只用这张卡片自己的设置，你的其他全局设置照常保留。
  • 路由模式下，OpenCode Go 等用 ANTHROPIC_API_KEY 存 Key 的供应商会让 Claude Code 要求确认自定义 Key，默认选「否」后就是未登录（#8111、#8104）。现在路由模式下占位凭据一律写进 ANTHROPIC_AUTH_TOKEN，发给上游的请求不变。
  • 给纯文本模型发过一个文件或音频后，之后每一轮都报 400（#6274、#6151）。现在经路由发给纯文本模型时，对话里的文件和音频会换成一段文字说明；智谱 GLM 的中文报错也能认出来。图片的处理不变。
  • Windows 上供应商表单里的名称等内容来回闪（#6420、#6349）。这是 WebView2 的自动填充在覆盖表单内容，现在已对主窗口关掉。
  • 启动后的一段时间里托盘面板打不开，也没法从托盘退出（#9154）。启动时导入会话用量会占着数据库，托盘面板要等数据。现在面板会先弹出，「打开主窗口」和「退出」马上能用，列表随后加载。
  • Codex 经路由用了模型映射时，同一个请求的用量被算两遍（#7643、#5526）。会话日志里记的是 Codex 用的模型名，路由记的是映射后的模型名，去重时对不上。现在两边能对上了。
  • Pi 官方示例的子代理用的额度没有统计进来（#8386、#8340）。现在会按每个子代理的供应商和模型分别记录，升级后会把以前的 Pi 会话重新读一遍补上。
  • 从 Pi 导入 MCP 时，Pi 不支持的服务器也被导入并启用，之后每次同步都失败（#7888）。SSE 连接方式、名字不合规、名字只差 - 和 _ 的服务器现在会跳过并提示；没装 Pi 时也不会再创建 Pi 的 MCP 配置文件。
  • 只在终端或 CC Switch 里设了代理、没设系统代理时，models.dev 价格同步一直失败（#8739、#6696）。现在改由 CC Switch 后台下载，会走你设的代理；导入模型价格和表单自动填模型参数也一样。
  • Claude Code 经路由连 xAI 时，强制联网搜索的请求被 xAI 拒绝，报 422（#8664）。
  • Pi 里的 MiniMax M3.1 Flash 思考档位（#8540）：两个 MiniMax 官方预设去掉了这个模型不接受的「关闭」和「最小」，其余档位照常发送。
