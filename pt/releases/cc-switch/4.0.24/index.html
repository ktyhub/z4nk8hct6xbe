Chave CC v4.0.24

Esta versão adiciona a opção "Abrir o navegador automaticamente ao fazer login" na central de autorização. Depois de desligá-lo, você só poderá copiar o link de login para fazer login em sua conta, podendo abri-lo no navegador de sua preferência. Isso é adequado para usuários que usam um ambiente de navegador independente para cada conta. Além disso, problemas como o nível máximo de pensamento sendo reduzido para xhigh ao usar GPT 6.1 Sol/Terra via Claude Code e Claude Desktop, os fornecedores terceirizados não sendo exibidos após a seleção de um modelo que suporta entrada de PDF no DeepSeek Harness, o CC Switch no WSL saindo após a inicialização, o nível de pensamento não sendo enviado após o provedor de bate-papo do Codex reabrir o "Support Thinking Level", etc. Notas de versão do v4.0. Adicionar

Você só pode copiar o link ao fazer login na sua conta

Antigamente, ao fazer login em uma conta na central de autorização, a página de login sempre era aberta usando o navegador padrão do sistema. Se você usar ferramentas como AdsPower para abrir um ambiente de navegador separado para cada conta, o login cairá no navegador errado. Agora há uma opção "Abrir o navegador automaticamente ao fazer login" na parte superior do centro de autorização. Os logins das contas Claude, ChatGPT, Copilot, xAI, Antigravity, Kimi e DeepSeek são todos controlados por ele, incluindo logins iniciados no formulário de adição de fornecedor. Depois de desligar:

  • Clique em Login para copiar o link de login para a área de transferência, abra-o no navegador que deseja usar, faça login e concorde com a autorização, o CC Switch será atualizado automaticamente.
  • Logins que exigem a inserção de um código de verificação não copiarão mais automaticamente o código de verificação para evitar a exclusão do link na área de transferência.
  • Ao aguardar para fazer login, você pode clicar em "Copiar link de login" para copiá-lo novamente. O botão para abrir a página de login não será exibido. No Windows, o Claude Code abrirá o navegador sozinho e o CC Switch só exibirá o link de login quando o switch estiver desligado. A opção está ativada por padrão e só é gravada neste computador e não é sincronizada com a nuvem. Padrão: A6API usa o novo nome de domínio a6api.vip.

Correção

  • Quando Claude Code e Claude Desktop estão conectados ao upstream do formato OpenAI e o modelo é gpt-6.1-sol ou gpt-6.1-terra, o equipamento de pensamento máximo é reduzido para xhigh e emitido (#9122). Agora no GPT 5.6 e versões posteriores, os modelos sem sufixos ou com sufixos sol, terra, luna e astra retêm o máximo; outros sufixos como pro, codex, mini, etc. ainda são emitidos como xhigh.
  • DeepSeek Harness Depois de selecionar um modelo que suporta entrada de PDF na lista de modelos extraídos, todos os fornecedores terceirizados não são exibidos (#9116). O tipo de entrada de modelo do DeepSeek Harness reconhece apenas texto e imagens. Escrever um PDF invalidará toda esta configuração. Agora é só escrever textos e imagens.
  • CC Switch on WSL sai diretamente após iniciar, e o ícone da bandeja "Permissão negada" é relatado (#9021, #9020). O ícone da bandeja do Linux foi alterado para ser colocado no diretório de cache do aplicativo.
  • Depois que o provedor de bate-papo do Codex fechar e abrir o "Support Thinking Level", o nível de pensamento selecionado não será mais enviado para o upstream (#8998, #8954). Upstreams como o GitHub Copilot, portanto, não recebem nenhum equipamento de pensamento. Os fornecedores que foram salvos antes voltarão ao normal sem reedição.
  • O cartão "DeepSeek Official Login" do DeepSeek Harness diz "Login com conta Claude" (#9058). Agora é “Fazer login com conta DeepSeek”.

cc-switch v4.0.24

Highlights

  • Browser-independent account login — The new local “automatically open browser on login” switch controls Claude, ChatGPT, Copilot, xAI, Antigravity, Kimi, and DeepSeek sign-in, including supplier-add flows. Disable it to copy an authorization URL and complete login in a separate browser environment; CAPTCHA codes are no longer auto-copied, preventing them from overwriting that URL. On Windows, Claude Code likewise emits a link instead of launching a browser. The setting is per-device and does not sync.
  • Preserved max reasoning for routed GPT models — #9122 fixes Claude Code and Claude Desktop downgrading max to xhigh when using gpt-6.1-sol or gpt-6.1-terra through OpenAI-format routers. GPT 5.6 and later now retain max without a suffix or with sol, terra, luna, or astra; pro, codex, mini, and other suffixes still map to xhigh.
  • DeepSeek Harness provider visibility restored — #9116 addresses a configuration failure triggered by selecting a PDF-capable model. Because Harness accepts only text and image inputs, CC Switch now writes only those capabilities; PDF input is intentionally omitted so one incompatible model no longer hides every third-party supplier.
  • Codex Chat reasoning settings repaired — #8998, following #8954, fixes reasoning levels disappearing after “support thinking levels” is disabled and re-enabled. Previously saved suppliers recover automatically—no re-editing or re-saving is required—and upstreams such as GitHub Copilot receive the selected level again.
  • WSL startup fixed — #9021 moves the Linux tray icon into the application cache directory, resolving the startup-time “Permission denied” failure reported in #9020. WSL users can launch CC Switch without applying a separate tray-icon permission workaround.
  • A6API preset endpoint updated — The built-in A6API preset now uses a6api.vip. Users who copied the previous endpoint into custom supplier configurations, allowlists, or proxies should check those references separately; changing the preset does not rewrite manually configured values.

No breaking changes.

CC Switch v4.0.24

本版本在授权中心加了「登录时自动打开浏览器」开关，关掉后登录账号只复制登录链接，由你自己选浏览器打开，适合每个账号用独立浏览器环境的用户。另外修复了 Claude Code、Claude Desktop 经路由用 GPT 6.1 Sol / Terra 时 max 思考档位被降成 xhigh、DeepSeek Harness 选了支持 PDF 输入的模型后第三方供应商全部不显示、WSL 上 CC Switch 启动就退出、Codex 的 Chat 供应商重开「支持思考等级」后思考档位发不出去等问题。4.0 完整的更新内容请见 v4.0 发布说明。

新增

登录账号时可以只复制链接

以前在授权中心登录账号，一律用系统默认浏览器打开登录页。用 AdsPower 这类工具给每个账号单独开浏览器环境的话，登录会落到错误的浏览器里。

现在授权中心顶部多了「登录时自动打开浏览器」开关，Claude、ChatGPT、Copilot、xAI、Antigravity、Kimi、DeepSeek 账号登录都受它控制，包括在添加供应商表单里发起的登录。关掉后：

  • 点登录只把登录链接复制到剪贴板，在你要用的浏览器里打开、登录并同意授权，CC Switch 会自动更新。
  • 需要输入验证码的登录不再自动复制验证码，免得把剪贴板里的链接顶掉。
  • 等待登录时可以点「复制登录链接」再复制一次，打开登录页的按钮不显示。

Windows 上 Claude Code 会自己打开浏览器，开关关掉时 CC Switch 会让它只输出登录链接。

开关默认打开，只记在这台电脑上，不随云同步。

预设： A6API 改用新域名 a6api.vip。

修复

  • Claude Code、Claude Desktop 经路由连 OpenAI 格式的上游、模型是 gpt-6.1-sol 或 gpt-6.1-terra 时，max 思考档位被降成 xhigh 发出（#9122）。现在 GPT 5.6 及以后的版本，不带后缀或带 sol、terra、luna、astra 后缀的模型都保留 max；pro、codex、mini 等其他后缀仍按 xhigh 发。
  • DeepSeek Harness 从拉取到的模型列表里选了支持 PDF 输入的模型后，第三方供应商全部不显示（#9116）。DeepSeek Harness 的模型输入类型只认文字和图片，写进去一个 PDF 就会让这一条配置整体失效。现在只写文字和图片。
  • WSL 上 CC Switch 启动后直接退出，报托盘图标「Permission denied」（#9021、#9020）。Linux 的托盘图标改为放在应用的缓存目录。
  • Codex 的 Chat 供应商关掉再打开「支持思考等级」后，选的思考档位不再发给上游（#8998、#8954）。GitHub Copilot 等上游因此收不到任何思考档位。以前保存过的供应商不用重新编辑，也会恢复正常。
  • DeepSeek Harness 的「DeepSeek 官方登录」卡片写着「用 Claude 账号登录」（#9058）。现在是「用 DeepSeek 账号登录」。

致谢

感谢 @gddg（WSL 托盘）、@guishiw（Codex 思考等级）、@iSanae233（DeepSeek 登录文案）的贡献。

感谢 @Xinyu-Li-1997、@clickwzy、@mhsbz、@ggbdpq 报告问题、提供复现信息和修复思路。

完整的技术细节请见 CHANGELOG。
