chave cc v4.0.36

Chave CC v4.0.36

Esta versão adiciona uma página de plug-in, que permite instalar, ativar, atualizar e desinstalar plug-ins para Claude Code, Codex, Grok Build, MiniMax Code, OpenClaw e Pi no CC Switch e gerenciar o mercado de plug-ins para Claude Code, Codex e Grok Build. Os armazéns de habilidades agora podem ler armazéns privados com tokens de acesso; os fornecedores roteados localmente podem definir multiplicadores de taxas; e os capítulos de desktop do Claude Code podem ser vistos no gerenciamento de sessões. Além disso, corrigimos problemas como o bloqueio da aprovação automática depois que o Codex abre a proteção de cota oficial; modelos oficiais recém-lançados no modo de agregação Codex demoram muito para aparecer; o uso de sessões 1.x não é mais contado após o upgrade do OpenCode para 2.x; a data personalizada na página de uso muda para 1905 assim que o ano é inserido; vários modelos de antigravidade são exibidos como sem preço e outros problemas. Os níveis de inferência com o mesmo preço nas estatísticas de uso agora são mesclados em uma linha. Inglês → | Versão japonesa →

Adicionar

Página do plug-in

Adicione "plug-ins" à barra lateral e gerencie plug-ins através da linha de comando de cada aplicativo (para requisitos, consulte #791, #9220):

  • Suporta Claude Code, Codex, Grok Build, MiniMax Code, OpenClaw, Pi e lista apenas aplicativos não ocultos.
  • Você pode ativar, desativar, atualizar (o Código MiniMax não pode ser atualizado) e desinstalar em "Instalado"; pesquise e instale em "Discover"; Claude Code, Codex e Grok Build também podem adicionar, atualizar e remover o mercado de plug-ins no "Mercado". O endereço pode ser owner/repo de GitHub, endereço Git ou pasta local. Plugins para Pi vêm do pacote Pi no npm.
  • Antes da instalação, Grok Build, OpenClaw e Pi confirmarão se os plug-ins são executados com suas permissões e instalarão apenas aqueles de fontes confiáveis. Para plug-ins no Claude Code que requerem consentimento no terminal, o CC Switch não concordará com você e solicitará que você execute o comando de instalação correspondente no terminal; aplicativos que exigem login primeiro também solicitarão comandos de login.
  • Codex desativa o plug-in e altera apenas o enabled do plug-in em config.toml, deixando o restante do conteúdo e comentários inalterados.
  • Pode levar vários minutos para baixar um grande armazém de mercado. Você pode fechar a caixa de diálogo primeiro e será avisado quando ela for concluída.

O armazém de habilidades oferece suporte a armazéns privados

No "Armazém de habilidades de gerenciamento", você pode definir tokens de acesso por site. Armazéns privados em GitHub, GitLab e Gitea/Forgejo podem navegar, instalar e verificar atualizações (para requisitos, consulte #9666).

  • Os tokens são salvos por site (como github.com, gitlab.example.com), armazenados no armazenamento de credenciais do sistema (macOS keychain, Windows Credential Manager, outros sistemas são arquivos legíveis apenas pela máquina local) e não são sincronizados com a nuvem. Somente permissão somente leitura é necessária.
  • Quando o download falhar, será distinguido se o token não está definido ou se o token foi rejeitado (inválido, expirado ou não autorizado para ler este armazém).

Taxa de despesas do fornecedor

Quando as transferências são faturadas com base em descontos, os custos nas estatísticas de utilização podem ser estimados com base em múltiplos (#9656). Um novo "multiplicador de custo do fornecedor" foi adicionado aos formulários não oficiais de fornecedores de Claude Code, Codex, Gemini CLI e Grok Build: os preços de referência de todos os modelos desta empresa são multiplicados por ele, 0.5 é metade do preço e deixar em branco é 1 vez.

  • Só tem efeito para solicitações roteadas localmente e definidas após configuração; o uso importado de registros de sessão durante a conexão direta ainda é contado como 1x.

Exibir capítulos da versão desktop do Claude Code no gerenciamento de sessões

Os capítulos atribuídos aos diálogos por modelos na versão desktop do Claude Code eram exibidos anteriormente como chamadas comuns de ferramentas MCP (consulte #9728, #9729 para obter os requisitos). Agora é exibido como uma linha de capítulos, que pode ser vista mesmo quando a linha do tempo está fechada; os capítulos serão listados no diretório de conversas e saltarão quando clicados; os capítulos podem ser encontrados por pesquisa e os capítulos se tornarão títulos ao exportar para Markdown.

Mudança

  • Estatísticas de uso mesclam engrenagens de inferência com o mesmo preço (#8845, consulte #9065): Diferentes forças de inferência do mesmo modelo, se os quatro preços de entrada, saída, leitura de cache e gravação de cache forem iguais ao modelo básico, e o modelo básico tiver preços precisos, eles serão mesclados na linha do modelo básico. Filtragem, resumo diário e tempo da primeira palavra são todos calculados de acordo com a fusão, e o nome do modelo original ainda é exibido no log de solicitação.

Correção

  • Depois que o Codex ativou a "Proteção de cota oficial", a aprovação automática foi bloqueada quando o limite foi atingido (#9733, consulte #9732): OpenAI tornou o modelo de aprovação automática codex-auto-review do Codex gratuito e não incluído na cota do pacote. Agora a proteção de cotas permite isso diretamente, e outros modelos oficiais estão suspensos como de costume.
  • No modo de agregação Codex, os modelos oficiais recém-lançados (como GPT-6.2) demoram muito para aparecer: No modo de agregação, o Codex lê apenas o diretório do modelo escrito pelo CC Switch. O cache da lista oficial de modelos foi reduzido de 6 horas para 1 hora; a versão do Codex ao obter a lista também se referirá ao CLI que acompanha a versão desktop e à versão gravada pelo próprio Codex. Depois que a versão desktop for atualizada automaticamente, ela não receberá mais uma lista mais curta baseada na versão antiga.
  • Após a atualização do OpenCode para 2.x, as sessões criadas ou continuadas em 1.x não serão contadas em uso (#8363, consulte #8361): Quando os conjuntos de dados antigo e novo coexistem, ambos os conjuntos agora são lidos e a mesma mensagem é contada apenas uma vez. Os bancos de dados verificados anteriormente continuam a partir da última verificação e não reabastecem os registros anteriores.
  • Ao inserir manualmente o ano na data personalizada na página de uso, ele se torna 1905 (veja #9699): Agora a data completa entrará em vigor e não será substituída durante o processo de entrada.
  • Vários modelos Antigravity mostram "sem preço" nas estatísticas de uso: a versão em camadas do Gemini Flash (como gemini-3.8-flash-tiered para subagente de navegador integrado) é cobrada pelo preço base do Flash (#9600); A versão escalonada do Hydrogen é cobrada pelo preço base (#9706, consulte #9705); a etapa de execução ao usar o Orchestrator é retornada ao Gemini 4 Hydrogen (#9686, consulte #9685), a etapa de planejamento é retornada ao Gemini 4 Neon e seu preço é adicionado (#8845); A versão Thinking de Claude (como Claude Opus 4.6 (Thinking)) é cobrada de acordo com o modelo básico correspondente. Os registros sem preço existentes serão automaticamente compensados.
  • A lista de modelos no modo de roteamento Claude Desktop é deixada em branco e o nome do modelo Claude padrão é usado em vez do modelo do fornecedor (consulte #9735): O modo de roteamento é originalmente assim, e o prompt do formulário agora está claramente escrito: deixá-lo em branco na conexão direta lerá automaticamente /v1/models. Para utilizar o modelo do fornecedor no modo roteirização, preencha a lista de modelos.
  • O MCP no cordis.patch.yml de nível inicial do DeepSeek Harness não pode ser visto no CC Switch e não há explicação (consulte #9714): O CC Switch apenas lê e grava arquivos de cada perfil. A caixa de diálogo de importação do MCP agora indica que os arquivos de nível inicial não são lidos nem gravados e que o MCP contido neles deve ser gerenciado lá.

cc-switch v4.0.36

Highlights

  • Plugins move into the sidebar — A new Plugins page manages Claude Code, Codex, Grok Build, MiniMax Code, OpenClaw, and Pi by driving each app's own CLI rather than reimplementing plugin logic (#791, #9220). For adopters: install/update/uninstall plus marketplace add/refresh/remove for the first three; Pi installs come from npm; MiniMax Code cannot be updated. It is deliberately not hands-off — Grok/OpenClaw/Pi prompt before install because plugins run with your privileges, Claude Code plugins needing terminal consent are handed back to you, and login-required apps surface the login command. Two details worth knowing: disabling a Codex plugin only flips its enabled flag in config.toml and leaves all other content and comments intact (safe for config management), and large marketplace clones can take minutes, with a notification on completion.

  • Private skill repos unblocked via per-site tokens — Skill repositories now accept access tokens to browse, install, and check updates on private GitHub, GitLab, and Gitea/Forgejo repos (#9666). Tokens are scoped per host (github.com, gitlab.example.com), need only read access, and live in the OS credential store (Keychain, Windows Credential Manager, or a local user-readable file elsewhere) — critically, they do not cloud-sync, so each machine must be configured separately. Download failures now distinguish "no token set" from "token rejected" (invalid/expired/no access), turning an opaque 404 into an actionable error.

  • Cost reporting: multiplier in, tier granularity out — Non-official provider forms for Claude Code, Codex, Gemini CLI, and Grok Build gain a "provider cost multiplier" (#9656): 0.5 halves reference prices, blank means 1×, useful when a reseller bills at a discount. Scope matters — it applies only to requests routed through the local proxy after you set it; imported/direct sessions still count at 1×, so historical spend is not retroactively discounted. Separately, reasoning tiers sharing all four prices (input/output/cache read/cache write) with an exactly-priced base model now collapse into that base row (#8845, #9065); filters, daily totals, and first-token timings use the merged data while request logs keep the original model name — fewer rows, not lost detail. Antigravity pricing gaps also close (Flash/Hydrogen tiered, Orchestrator execution→Hydrogen and planning→Neon with a new price, Claude Thinking→base) with existing unpriced records recalculated (#9600, #9706, #9685, #8845) — so past spend figures may rise.

  • Usage fixes for mixed or upgraded installs — OpenCode 2.x users with leftover 1.x sessions now count usage from both databases with per-message dedup (#8363, #8361); note that previously scanned DBs resume from the last scan and older messages are not backfilled. With Codex "official quota protection" on, the now-free codex-auto-review model bypasses the pause (#9733, #9732) while other official models still pause. In Codex aggregation mode the official-model cache drops from 6h to 1h and version detection now consults the bundled/desktop CLI, so newly released models (e.g. GPT-6.2) stop lagging behind auto-updates.

  • Claude Code Desktop chapters become first-class — Model-generated chapter markers, previously rendered as generic MCP tool calls, now appear as chapter rows (#9728, #9729): visible even with the timeline collapsed, listed in the session directory with click-to-jump, searchable, and exported as Markdown headings. A small but real quality-of-life win for navigating long Desktop sessions.

  • Breaking changes — None; no migration steps required.

CC Switch v4.0.36

本版本新增插件页面，可以在 CC Switch 里安装、启用、更新、卸载 Claude Code、Codex、Grok Build、MiniMax Code、OpenClaw、Pi 的插件，并管理 Claude Code、Codex、Grok Build 的插件市场。技能仓库现在可以用访问令牌读取私有仓库；经本地路由的供应商可以设置费用倍率；会话管理里能看到 Claude Code 桌面版的章节。

另外修复了 Codex 开了官方额度保护后自动审批也被拦下；Codex 聚合模式下新发布的官方模型要很久才出现；OpenCode 升级到 2.x 后 1.x 会话的用量不再统计；用量页自定义日期一输入年份就变成 1905；Antigravity 多个模型显示未定价等问题。用量统计里价格相同的推理档位现在合并成一行。

新增

插件页面

侧栏新增「插件」，通过各应用自己的命令行管理插件（需求见 #791，#9220）：

  • 支持 Claude Code、Codex、Grok Build、MiniMax Code、OpenClaw、Pi，只列出没有隐藏的应用。
  • 「已安装」里可以启用、停用、更新（MiniMax Code 不能更新）、卸载；「发现」里搜索并安装；Claude Code、Codex、Grok Build 还可以在「市场」里添加、刷新、移除插件市场，地址可以是 GitHub 的 owner/repo、Git 地址或本地文件夹。Pi 的插件来自 npm 上的 Pi 包。
  • Grok Build、OpenClaw、Pi 安装前会先确认：插件以你的权限运行，只装来源可信的。Claude Code 里要在终端同意的插件，CC Switch 不替你同意，会提示到终端运行对应的安装命令；需要先登录的应用也会提示登录命令。
  • Codex 停用插件只改 config.toml 里这个插件的 enabled，其余内容和注释不动。
  • 大的市场仓库下载可能要几分钟，可以先关掉对话框，完成后会提示。

技能仓库支持私有仓库

「管理技能仓库」里可以按站点设置访问令牌，GitHub、GitLab、Gitea / Forgejo 上的私有仓库都能浏览、安装和检查更新（需求见 #9666）。

  • 令牌按站点保存（如 github.com、gitlab.example.com），存在系统的凭据存储里（macOS 钥匙串、Windows 凭据管理器，其他系统是本机仅自己可读的文件），不随云同步。只需要只读权限。
  • 下载失败时会区分是没设令牌，还是令牌被拒（无效、过期或无权读取这个仓库）。

供应商费用倍率

中转按折扣计费时，用量统计里的花费可以按倍率估算（#9656）。Claude Code、Codex、Gemini CLI、Grok Build 的非官方供应商表单里新增「供应商费用倍率」：这家所有模型的参考价都乘以它，0.5 即半价，留空为 1 倍。

  • 只对经本地路由、并且设置之后的请求生效；直连时从会话记录导入的用量仍按 1 倍统计。

会话管理里显示 Claude Code 桌面版的章节

Claude Code 桌面版里模型给对话打的章节，以前显示成普通的 MCP 工具调用（需求见 #9728，#9729）。现在显示成章节行，收起时间线也能看到；对话目录里会列出章节，点击即跳转；查找能搜到章节，导出 Markdown 时章节变成标题。

变更

  • 用量统计合并价格相同的推理档位（#8845，见 #9065）：同一个模型的不同推理强度，如果输入、输出、缓存读、缓存写四种价格都和基础模型相同，并且基础模型有精确价格，就合并到基础模型那一行。筛选、每日汇总和首字时间都按合并后统计，请求日志里仍显示原始模型名。

修复

  • Codex 开了「官方额度保护」后，达到阈值时自动审批也被拦下（#9733，见 #9732）：OpenAI 已经让 Codex 的自动审批模型 codex-auto-review 免费、不计入套餐额度，现在额度保护对它直接放行，其他官方模型照常暂停。
  • Codex 聚合模式下，新发布的官方模型（如 GPT-6.2）要很久才出现：聚合模式下 Codex 只读 CC Switch 写的模型目录。官方模型列表的缓存从 6 小时缩短到 1 小时；获取列表时报的 Codex 版本也会参考桌面版自带的 CLI 和 Codex 自己记录的版本，桌面版自动更新后不会再按旧版本拿到少一截的列表。
  • OpenCode 升级到 2.x 后，之后在 1.x 里新建或继续的会话不计入用量（#8363，见 #8361）：新旧两套数据并存时现在两套都读，同一条消息只算一次。以前扫描过的数据库从上次扫描处继续，不回补更早的记录。
  • 用量页自定义日期手动输入年份时，一输入就变成 1905（见 #9699）：现在输入完整的日期才生效，输入过程中不会被改写。
  • Antigravity 多个模型在用量统计里显示「未定价」：Gemini Flash 的 tiered 版本（如内置浏览器子代理用的 gemini-3.8-flash-tiered）按 Flash 基础价计费（#9600）；Hydrogen 的 tiered 版本按基础价计费（#9706，见 #9705）；用 Orchestrator 时的执行步归到 Gemini 4 Hydrogen（#9686，见 #9685），规划步归到 Gemini 4 Neon 并新增它的价格（#8845）；Claude 的 Thinking 版本（如 Claude Opus 4.6 (Thinking)）按对应的基础模型计费。已有的未定价记录会自动补算。
  • Claude Desktop 路由模式下模型列表留空，用的是默认的 Claude 模型名而不是供应商的模型（见 #9735）：路由模式本来如此，表单提示现在写清楚了：直连时留空会自动读取 /v1/models，路由模式下要用供应商的模型请填写模型列表。
  • DeepSeek Harness 的 home 级 cordis.patch.yml 里的 MCP 在 CC Switch 里看不到，也没有说明（见 #9714）：CC Switch 只读写各 profile 的文件，MCP 导入对话框现在写明 home 级文件既不读也不写，其中的 MCP 请在那里管理。
