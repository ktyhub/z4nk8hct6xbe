Chave CC v4.0.31

Esta versão adiciona um novo aplicativo gerenciado Tencent WorkBuddy: o modelo personalizado é gravado na configuração do próprio modelo do WorkBuddy e pode ser selecionado diretamente no WorkBuddy; também pode ser alternado entre várias contas WorkBuddy. Antes de mudar, você pode ver o pacote, pontos restantes e prazo de validade de cada conta. A interface foi recentemente adicionada em Alemão, e o README também está disponível em todos os oito idiomas da interface. Além disso, quando o Claude Code estiver conectado à retransmissão do formato OpenAI Responses via roteamento, a sessão será relatada como 400 em cada rodada depois que a mesma retransmissão for atribuída a diferentes recursos do Azure e não puder ser continuada; quando conectado ao upstream do formato Gemini Native via roteamento, a chamada da ferramenta paralela será relatada como 400 e a taxa de acertos do cache é muito baixa; o prompt de foco da bandeja do macOS sempre fica pendurado na tela; o uso de conversas antigas continuadas pelo Codex nunca é importado. Adicionar

WorkBuddy

Tencent WorkBuddy se torna um novo aplicativo gerenciado (#8757, para requisitos consulte #4802, #5802, #7419, #7076). Assim como o OpenCode, vários fornecedores são válidos ao mesmo tempo:

  • Modelo Personalizado: Após clicar em "Adicionar", o modelo do fornecedor é gravado no próprio models.json do WorkBuddy, e é exibido como "Nome: ID do Modelo" na seleção do modelo do WorkBuddy. Quando o nome for deixado em branco, use "Etiqueta do Fabricante". Os modelos que você adicionou no WorkBuddy são mantidos como estão. Os modelos personalizados do WorkBuddy suportam apenas o formato OpenAI Chat Completions.
    • Para os modelos predefinidos, você pode selecionar a intensidade do pensamento na seleção do modelo do WorkBuddy (como baixo/alto/máximo para Kimi K3.1 Pro).
    • Atualmente, o WorkBuddy não suporta o mesmo ID de modelo aparecendo duas vezes. Ao selecionar um preset, serão ignorados os modelos que foram utilizados por outras placas e qual delas é a placa. IDs de modelo duplicados preenchidos manualmente serão marcados e não poderão ser salvos.
  • Conta Oficial: As contas logadas no WorkBuddy serão automaticamente incluídas na “Central de Autorização”, que exibe o apelido, pacote, pontos restantes e prazo de validade dos pontos (expira em três dias). Existem duas entradas para trocar de conta: adicionar o cartão "Login oficial do WorkBuddy" vinculado a esta conta ou clicar em "Mudar WorkBuddy para esta conta" no menu desta conta na central de autorização.
    • Certifique-se de sair completamente do WorkBuddy (incluindo a barra de menu/bandeja) antes de alternar, caso contrário, o login atual será gravado de volta.
    • "Fazer login em outra conta" apenas interrompe o WorkBuddy na página de login localmente e não desconecta a conta atual no servidor. As contas incluídas ainda podem ser trocadas.
    • Pacotes e pontos só podem ser verificados quando o WorkBuddy estiver em execução e a conta estiver logada. Uma vez verificados, eles serão armazenados em cache e exibidos.
  • **MCP, habilidades, palavras de prompt **: sincronizado com o mcp.json do WorkBuddy, catálogo de habilidades e palavra de prompt global CODEBUDDY.md. As entradas MCP gerenciadas pelo conector WorkBuddy não serão alteradas.
  • Gerenciamento de sessão e estatísticas de uso: lista sessões do WorkBuddy, importa uso de logs de sessão. A sessão não pode ser retomada no terminal.

Interface em alemão, README em oito idiomas

  • Alemão: O idioma do sistema é selecionado automaticamente na primeira inicialização, e o menu da bandeja e o painel de atalhos também foram traduzidos. Os espaços reservados para o filtro de privacidade estão temporariamente em inglês na interface alemã, assim como em coreano e russo.
  • README foi adicionado às versões em chinês tradicional, coreano, turco e russo, correspondendo aos oito idiomas da interface.

Outros

  • Há "Ressincronizar agora" diretamente no menu "⋯" no canto superior direito da página Habilidades (#9417): Não há necessidade de ir em "Armazenamento e sincronização" para encontrá-lo.
  • Ao agrupar "por projeto" no gerenciamento de conversas, as conversas que não pertencem a nenhum projeto na versão desktop do Codex são agrupadas em um grupo "Codex Chat" (#9415): Cada conversa não pertence mais a um grupo.
  • Adicionada filtragem de código de status para logs de solicitação: 403, 404, 502, 503, 504, 520, 529 (#9425).

Mudança

  • O filtro de privacidade é alterado para a última etapa antes do envio da solicitação (#9460): Anteriormente, a solicitação era filtrada ao entrar pela primeira vez na rota. O conteúdo adicionado à solicitação posteriormente, como novas tentativas de failover, resumos compactados gerados pelo próprio CC Switch, etc., não será processado. Agora toda vez que for enviado para o upstream, será filtrado para fornecer uma cobertura mais completa; o texto descritivo da ferramenta não será processado. O teste também é mais rápido e os resultados são consistentes com os anteriores.
  • A importação de uso do Codex é mais rápida (#9400): Menos análise repetida e alocação de memória ao ler logs de sessão do Codex.

Correção

  • Claude Code/Claude Desktop relata ocasionalmente 400 "O item solicitado foi criado em um recurso diferente do Azure OpenAI" ao transferir o formato OpenAI Responses por meio do roteador e, em seguida, relata um erro sempre na mesma sessão (#9424). A transferência distribui a mesma sessão para diferentes recursos do Azure OpenAI, e o histórico da sessão contém os registros de pensamento gerados por outro recurso; um invalid_encrypted_content semelhante será reportado caso o fornecedor seja trocado durante a sessão. Agora, quando o upstream se recusar dessa forma, ele removerá esses registros de pensamentos e tentará novamente automaticamente, e a sessão poderá continuar. Solicitações normais não são afetadas.
  • Quando o Claude Code é conectado ao upstream do formato Gemini Native via roteamento, a chamada da ferramenta paralela reportará 400 "número de partes de resposta de função" (#9453): Os resultados da ferramenta espalhados em várias mensagens agora serão mesclados antes de serem enviados.
  • Quando Claude Code se conecta ao upstream do formato Gemini Native via roteamento, a taxa de acerto do cache de sessão longa é de apenas cerca de 20% (#9450): Claude Code adicionará um prompt de token restante em cada rodada. Anteriormente foi movido para a frente de toda a história, resultando em um início diferente de cada rodada. Agora permanecendo na posição original, o histórico anterior permanece inalterado a cada rodada e o cache pode ser atingido.
  • Quando Claude Code se conecta ao upstream do formato Gemini Native por meio de roteamento, o uso de registros de solicitação de streaming é baixo e as leituras de cache geralmente são registradas como 0 (#9464).
  • O prompt de foco "CC Switch" do ícone da bandeja no macOS sempre fica pendurado na tela e só pode sair do aplicativo (#9445, #9329, #9446): Este prompt não é mais exibido no macOS, e os pontos no ícone e no painel de atalho ainda irão lembrá-lo quando algo der errado.
  • Quando outros aplicativos no macOS estão em tela cheia, clicar no ícone da barra de menu não abre o painel de atalhos (#9331).
  • No modo de roteamento Claude Code, o CLAUDE_CODE_SUBAGENT_MODEL_FORCE definido no fornecedor não pode ser gravado em settings.json (#9451, #9455): Agora ele é gravado com o fornecedor como outras configurações específicas do fornecedor, e suas próprias configurações globais não serão apagadas pela troca.
  • Codex Depois de continuar uma conversa antiga que foi encerrada, o uso recém-gerado não foi importado (#9420).
  • Quando o Codex está diretamente conectado a um fornecedor terceirizado, a desativação de "Manter login oficial durante a troca sem aquisição" não terá efeito imediato. Você tem que voltar para o cartão oficial e depois voltar (#9367): Agora, após alterar as configurações, a configuração do fornecedor atual será substituída.
  • Para o modelo GPT com o mesmo nome do oficial no fornecedor terceirizado Codex, o nome de exibição exibido na seleção do modelo não é o nome de exibição que você definiu (#9380).
  • Depois de desinstalar o Claude Desktop no macOS, a página "Aplicativos" ainda o lista como instalado (#9383): Agora apenas o Claude.app é reconhecido e os diretórios de dados restantes não são mais contados.
  • O botão copiar é solicitado com sucesso no Linux KDE Wayland, mas a área de transferência está vazia ou ainda possui conteúdo antigo (#9384).
  • **Na lista suspensa de contas do cartão Copilot CLI oficial, a opção de não vincular uma conta diz "Usar conta padrão", mas na verdade usa o próprio login GitHub do Copilot CLI ** (#9408): Agora diz "Seguir o próprio login do Copilot CLI".
  • Modelos DeepSeek Harness adicionados manualmente não podem definir opções de compatibilidade (#9330): O editor de compatibilidade agora também é exibido e esse caractere pode ser desativado para interfaces como o modo de compatibilidade Bailian que não aceita o caractere developer.
  • Ao ativar o Skill, ele avisa que a criação do link simbólico falhou e o motivo específico não pode ser visto (#9439): O relatório de erros agora contém o código de erro fornecido pelo sistema (como os error 5 no Windows), tornando mais fácil determinar se é um problema de permissão ou outros motivos.
  • Em "Aplicativos" e "Configurações" na parte inferior da barra lateral, o texto é cortado nas interfaces em alemão, turco e russo.

Instruções de atualização

Versão do banco de dados atualizada de 25 para 26, adicionando switches WorkBuddy para MCP e Skills. O backup do banco de dados será feito automaticamente antes da atualização; se você reverter para a versão antiga após a atualização, a versão antiga avisará que a versão do banco de dados é muito nova e não pode ser aberta.

cc-switch v4.0.31

Highlights

  • WorkBuddy integration — Tencent WorkBuddy is now a managed app with multiple simultaneously active providers (#8757). Custom models are written to its models.json, while MCP, Skills, prompts, sessions, and usage data can be synchronized. Only OpenAI Chat Completions is supported for custom models, and duplicate model IDs are rejected.
  • WorkBuddy account switching — The authorization center displays account plans, remaining credits, and expiration dates. Fully quit WorkBuddy—including its tray—before switching, or it may overwrite the new login; quota data is refreshed only while WorkBuddy is running and signed in.
  • Recovery for broken Azure-backed sessions — When an OpenAI Responses relay routes conversation history to a different Azure resource, CC Switch now removes incompatible reasoning records and retries once (#9424). This can recover sessions stuck on repeated 400s, including after a mid-conversation provider change.
  • Better Gemini Native routing and caching — Tool results split across messages are now combined, avoiding parallel-tool-call 400 errors (#9453). Per-turn token notices stay in place instead of being moved to the start of history, preserving cache prefixes and improving long-conversation cache hits (#9450).
  • Privacy filtering covers late-added content — Filtering now runs immediately before every upstream request, including failover retries and CC Switch-generated summaries (#9460). Tool descriptions remain unfiltered, so sensitive information embedded there is not covered.
  • Database upgrade prevents downgrade — The schema moves from version 25 to 26 for WorkBuddy MCP/Skills toggles. Backups are automatic, but older versions cannot open the upgraded database; keep the backup if rollback may be needed.

CC Switch v4.0.31

本版本新增受管应用腾讯 WorkBuddy：自定义模型写进 WorkBuddy 自己的模型配置，在 WorkBuddy 里直接就能选；还能在多个 WorkBuddy 账号之间切换，切换前先看到每个号的套餐、剩余积分和到期时间。界面新增德语，README 也有了全部八种界面语言的版本。

另外修复了 Claude Code 经路由连 OpenAI Responses 格式的中转时，会话被同一个中转分到不同 Azure 资源后每一轮都报 400、再也继续不了；经路由连 Gemini Native 格式上游时，并行工具调用报 400、缓存命中率很低；macOS 托盘悬停提示一直挂在屏幕上；Codex 续接的旧对话用量从不导入等问题。

新增

WorkBuddy

腾讯 WorkBuddy 成为新的受管应用（#8757，需求见 #4802、#5802、#7419、#7076）。和 OpenCode 一样是多个供应商同时生效：

  • 自定义模型：点「添加」后，供应商的模型写进 WorkBuddy 自己的 models.json，在 WorkBuddy 的模型选择里显示为「名称:模型 ID」，名称留空时用「厂商标签」。WorkBuddy 里自己添加的模型原样保留。WorkBuddy 的自定义模型只支持 OpenAI Chat Completions 格式。
    • 预设里的模型在 WorkBuddy 的模型选择里可以选思考强度（例如 Kimi K3.1 Pro 的 low / high / max）。
    • WorkBuddy 暂时不支持同一个模型 ID 出现两次。选预设时会跳过已被别的卡片用掉的模型并说明是哪张卡；手动填了重复的模型 ID 会标出来，不能保存。
  • 官方账号：在 WorkBuddy 里登录过的账号会自动收录到「授权中心」，显示昵称、套餐、剩余积分和积分到期时间（三天内到期标橙）。切换账号有两个入口：添加绑定了这个账号的「WorkBuddy 官方登录」卡片，或者在授权中心这个账号的菜单里点「切换 WorkBuddy 到这个账号」。
    • 切换前要先完全退出 WorkBuddy（包括菜单栏 / 托盘），否则它会把当前登录写回去。
    • 「登录另一个账号」只在本机让 WorkBuddy 停在登录页，不会在服务端登出当前账号，已收录的账号仍然可以切回去。
    • 套餐和积分要在 WorkBuddy 正在运行、并且登录着这个账号时才能查到，查到后会缓存显示。
  • MCP、Skills、提示词：同步到 WorkBuddy 的 mcp.json、Skills 目录和全局提示词 CODEBUDDY.md。WorkBuddy 连接器管理的 MCP 条目不会被改动。
  • 会话管理和用量统计：列出 WorkBuddy 会话，从会话日志导入用量。会话不能在终端里恢复。

德语界面，README 八种语言

  • 德语：首次启动按系统语言自动选择，托盘菜单和快捷面板也已翻译。隐私过滤器的占位符在德语界面下和韩语、俄语一样暂用英文。
  • README 新增繁体中文、韩语、土耳其语和俄语版本，和界面的八种语言一一对应。

其他

  • Skills 页面右上角的「⋯」菜单里直接有「立即重新同步」（#9417）：不用再进「存储与同步」里找。
  • 会话管理「按项目」分组时，Codex 桌面版不属于任何项目的对话归到一组「Codex 聊天」（#9415）：不再每个对话各占一组。
  • 请求日志的状态码筛选新增 403、404、502、503、504、520、529（#9425）。

变更

  • 隐私过滤器改在请求发出前的最后一步过滤（#9460）：以前在请求刚进入路由时过滤，故障转移重试、CC Switch 自己生成的压缩摘要等后来加进请求的内容不会被处理。现在每一次发往上游前都会过滤，覆盖更全；工具的说明文字不处理。检测也更快，结果和以前一致。
  • Codex 用量导入更快（#9400）：读取 Codex 会话日志时少做重复的解析和内存分配。

修复

  • Claude Code / Claude Desktop 经路由连 OpenAI Responses 格式的中转时，偶尔报 400「The requested item was created under a different Azure OpenAI resource」，之后同一会话每一轮都报错（#9424）。中转把同一个会话分到了不同的 Azure OpenAI 资源，会话历史里带着另一个资源生成的思考记录；会话中途换供应商也会报类似的 invalid_encrypted_content。现在上游这样拒绝时，会去掉这些思考记录后自动重试一次，会话可以继续。正常的请求不受影响。
  • Claude Code 经路由连 Gemini Native 格式上游时，并行工具调用后报 400「number of function response parts」（#9453）：分散在几条消息里的工具结果现在会合并到一起再发出。
  • Claude Code 经路由连 Gemini Native 格式上游时，长会话缓存命中率只有两成左右（#9450）：Claude Code 每一轮都会追加一条剩余 Token 提示，以前被挪到整段历史的最前面，导致每一轮的开头都不一样。现在留在原来的位置，前面的历史每一轮保持不变，可以命中缓存。
  • Claude Code 经路由连 Gemini Native 格式上游时，流式请求记录的用量偏少，缓存读取常常记成 0（#9464）。
  • macOS 上托盘图标的「CC Switch」悬停提示一直挂在屏幕上，只能退出应用（#9445、#9329、#9446）：macOS 上不再显示这个提示，出问题时图标上的圆点和快捷面板照常提醒。
  • macOS 上其他应用全屏时，点菜单栏图标弹不出快捷面板（#9331）。
  • Claude Code 路由模式下，供应商里设置的 CLAUDE_CODE_SUBAGENT_MODEL_FORCE 写不进 settings.json（#9451、#9455）：现在和供应商的其他专属设置一样随供应商写入，你自己在全局设置的值也不会被切换清掉。
  • Codex 续接已结束的旧对话后，新产生的用量一直没有导入（#9420）。
  • Codex 直连第三方供应商时，关掉「非接管切换时保留官方登录」不会立即生效，要切回官方卡再切回来（#9367）：现在改完设置就会重写当前供应商的配置。
  • Codex 第三方供应商里与官方同名的 GPT 模型，模型选择里显示的不是你设置的显示名（#9380）。
  • macOS 上卸载 Claude Desktop 后，「应用」页仍把它列为已安装（#9383）：现在只认 Claude.app，残留的数据目录不再算。
  • Linux KDE Wayland 上复制按钮提示成功，但剪贴板是空的或还是旧内容（#9384）。
  • Copilot CLI 官方卡的账号下拉里，不绑定账号的选项写着「使用默认账号」，实际用的是 Copilot CLI 自己的 GitHub 登录（#9408）：现在写成「跟随 Copilot CLI 自己的登录」。
  • DeepSeek Harness 手动添加的模型没法设置兼容选项（#9330）：现在也显示兼容性编辑器，可以为百炼兼容模式这类不接受 developer 角色的接口关掉这个角色。
  • 启用 Skill 时提示符号链接创建失败，看不出具体原因（#9439）：报错里现在带上系统给出的错误码（例如 Windows 的 os error 5），方便判断是权限问题还是别的原因。
  • 侧栏底部的「应用」和「设置」，德语、土耳其语、俄语界面下文字被截断。

升级说明

数据库版本从 25 升到 26，为 MCP 和 Skills 增加 WorkBuddy 的开关。升级前会自动备份数据库；升级后再退回旧版本，旧版本会提示数据库版本过新，打不开。
