chave cc v4.0.33

Chave CC v4.0.33

Esta versão corrige o problema de que após voltar para Claude oficial de um provedor terceirizado, a sessão Claude Code já aberta ainda envia a solicitação ao provedor anterior, e a sessão precisa ser reiniciada para recuperação. Ollama Cloud foi adicionado à consulta de cota de pacote; Troca de conta antigravidade na central de autorização agora também oferece suporte ao Windows. Além disso, o fornecedor Claude Code/Claude Desktop corrigiu o relatório “API Key é inválido ou não tem permissão” ao obter a lista de modelos ao selecionar o formato Gemini Native; alguns provedores de serviços são bloqueados pela Cloudflare na obtenção da lista de modelos; alguns pedidos do Antigravity Orchestrator ainda não têm preço; A sincronização WebDAV está completamente indisponível em alguns NAS; A falha de upload do WebDAV/S3 exibe apenas "Falha na construção da solicitação"; consultar problemas de xAI, como ser solicitado a fazer login novamente ao encontrar instabilidades na rede ao solicitar cotas; deixar de atualizar uma habilidade no meio do caminho e excluir a habilidade original, etc. Inglês → | Versão japonesa →

Adicionar

Cota do pacote Ollama Cloud

O fornecedor com o endereço ollama.com agora pode consultar a cota do Token Plan (para requisitos, consulte #9382): o pacote atual exibe a proporção restante da cota e o tempo de reinicialização no pacote atual, e a versão antiga do pacote exibe a proporção restante de 5 horas e duas janelas por semana. A cota adquirida separadamente não é exibida; contas pré-pagas não possuem cotas de pacote e os motivos serão explicados. Ollama (localhost:11434) rodando nativamente não tem plano e não será reconhecido.

  • Para fornecedores Ollama Cloud recém-adicionados ou importação com um clique, a consulta de cota é habilitada por padrão; para fornecedores existentes, clique em "Configurar consulta de uso" no cartão e o modelo Token Plan será selecionado automaticamente. Abra "Ativar consulta de uso" e salve-o.

Alternar conta Antigravity no Windows

A troca de conta Antigravity na central de autorização costumava oferecer suporte apenas ao macOS, mas agora também pode ser usada no Windows: após a troca, agy lê a nova conta. O cartão oficial Antigravity pode vincular a conta e verificar o limite da conta vinculada. Ele também perguntará para qual conta irá mudar antes de abrir o terminal. Linux ainda não é compatível.

Correção

  • **Após voltar para Claude oficial de um provedor terceirizado, a sessão aberta do Claude Code ainda envia a solicitação para o provedor anterior e precisa ser reiniciada para retomar ** (#9247, consulte #7808, #3057): O Claude Code em execução lerá apenas variáveis de ambiente settings.json que são adicionadas e alteradas na sessão, e as excluídas permanecem na sessão. Agora, ao alternar, primeiro escreva o endereço, as credenciais e o mapeamento do modelo a serem excluídos como valores nulos. A próxima solicitação da sessão aberta não usará mais a anterior e a excluirá do arquivo após cerca de 10 segundos. O modelo principal (ANTHROPIC_MODEL) definido quando a sessão for iniciada não será alterado: se foi definido no modelo anterior, selecione Padrão no menu do modelo após voltar ou abra uma nova sessão.
  • Quando o fornecedor do Claude Code / Claude Desktop seleciona o formato Gemini Native, "Obter Lista de Modelos" sempre informa "A chave API é inválida ou não tem permissão": Agora passe a chave da forma exigida pelo Google. A solicitação real que está sendo roteada já é normal, apenas a obtenção da lista de modelos é afetada. Além disso, para Pi, Oh My Pi e Kimi Code, se você escolher o fornecedor da interface do Google, poderá obter uma lista de modelos que antes listava apenas até 50 modelos, mas agora você pode listá-los todos.
  • Ao obter a lista de modelos, alguns provedores de serviços por trás da Cloudflare a rejeitaram diretamente e foram relatados erroneamente como "A chave API é inválida ou não tem permissão" (#7429, consulte #7427): A solicitação agora carrega o User-Agent por padrão; se o User-Agent estiver definido no cabeçalho do fornecedor ou da solicitação, a configuração prevalecerá.
  • Quando o Antigravity seleciona o Orchestrator, algumas solicitações ainda aparecem sem preço (#9542, consulte #9493): As etapas mostradas como "Gemini 4 Hydrogen (Orchestrator)" são cobradas de acordo com o preço do Gemini 4 Hydrogen, e o histórico nos últimos 30 dias também compensará a taxa. O preço personalizado ainda tem prioridade.
  • A sincronização WebDAV está completamente indisponível em alguns NAS e todas as conexões de teste, uploads e downloads falham (#5623, consulte #5621): Esses NAS ainda retornam 400 para "Criar diretório" quando a pasta compartilhada já existe. No passado, ele abortaria diretamente, mas agora verificará novamente se o diretório existe.
  • Quando o upload do WebDAV/S3 é desconectado pelo servidor, apenas "Falha na construção da solicitação" é exibido (consulte #9559): Agora está claro se a solicitação não foi construída ou falha quando enviada, e o motivo específico é anexado para facilitar a determinação se é um problema de rede, TLS ou servidor. Os parâmetros de senha e assinatura no endereço não aparecerão no relatório de erros.
  • A sincronização automática do S3 ainda pode ser carregada novamente após ser desativada (#9528): uploads automáticos enfileirados enquanto outra sincronização está em andamento agora relerão as configurações antes de iniciar e não serão mais carregados se a sincronização automática ou a sincronização do S3 for desativada durante o período. WebDAV é exatamente isso.
  • Ao consultar o saldo da conta xAI, se você encontrar jitter de rede ou erro de serviço xAI, será solicitado que você faça login novamente (#9526, consulte #9522): Este prompt só ocorrerá se o login for realmente inválido. Erros temporários serão relatados normalmente e o último saldo encontrado será retido. Tente novamente na próxima vez.
  • Depois que uma conta xAI não padrão expirou, a conta padrão selecionada na central de autorização foi substituída por outra conta (#9548, consulte #9543).
  • Se a cópia falhar no meio da atualização de uma Skill, a Skill original será excluída, mas ainda será mostrada como instalada na lista (veja #9521): Agora a nova versão será substituída somente após ser completamente copiada, e a versão original será mantida se falhar.
  • Quando o Codex é convertido para o formato Chat via roteamento, required: null na definição da ferramenta é rejeitado pelo upstream estrito (#7023, consulte #7019).
  • Quando o caminho para o arquivo de configuração do shell no macOS/Linux contém dois pontos, "conflito de variável de ambiente do sistema detectado" falhará ao excluir ou restaurar variáveis (#7170, consulte #7169).
  • Os padrões Pi de PIPELLM, AICodeWith e E-FlowCode são exibidos como o nome do modelo antigo na seleção do modelo (#9514): Por exemplo, Claude Opus 5.5 é exibido como claude-opus-5, e a solicitação real é o novo modelo. As predefinições DeepSeek Harness, Copilot CLI, Oh My Pi, MiniMax Code e Kimi Code geradas usando essas predefinições são modificadas juntas; os fornecedores já adicionados mantêm seus nomes originais salvos.
  • Fornecedores com endereços no formato api.commandcode.ai/providers são usados ​​como cota de consulta de pacote de código de comando (#9518).

Agradecimentos

Obrigado a @funkpopo (alteração de sessões abertas após voltar para Claude oficial e gerenciamento centralizado de listas de idiomas), @ziyangxiami (preços do Hydrogen Orchestrator), @SailingLoong (User-Agent para obter lista de modelos), @stofancy (NAS compatível com WebDAV), @HaiYangBG1 (duas correções para conta xAI, mantendo a versão original quando a atualização do Skill falha), @GalaxyKW (definição de ferramenta de codex) required), @cuishuang (dois pontos no caminho da variável de ambiente), @SaladDay (nome do modelo padrão Pi, identificação de endereço de código de comando, sincronização automática S3 e fusão de código de sincronização WebDAV e S3, gerenciamento centralizado de listas de idiomas, comparação constante de front-end e back-end, etc. organização interna). Obrigado a @Lawgk, @eDramas, @xinluke, @JImmyHui2017, @liuxixiang11, @WindowsXP-PLUS por relatar problemas e fornecer informações de reprodução. Detalhes técnicos completos estão disponíveis em CHANGELOG.

cc-switch v4.0.33

CC Switch v4.0.33

本版本修复了从第三方供应商切回 Claude 官方后，已经开着的 Claude Code 会话仍把请求发给上一家、要重开会话才恢复的问题。套餐额度查询新增 Ollama Cloud；授权中心的 Antigravity 账号切换现在也支持 Windows。

另外修复了 Claude Code / Claude Desktop 的供应商选 Gemini Native 格式时获取模型列表总报「API Key 无效或无权限」；部分服务商获取模型列表被 Cloudflare 拦下；Antigravity Orchestrator 仍有部分请求显示未定价；WebDAV 同步在一些 NAS 上完全用不了；WebDAV / S3 上传失败只显示「请求构造失败」；查询 xAI 额度时遇到网络抖动就被要求重新登录；更新 Skill 中途失败把原来的 Skill 删掉等问题。

新增

Ollama Cloud 套餐额度

地址是 ollama.com 的供应商现在可以查询 Token Plan 额度（需求见 #9382）：现行套餐显示本期套餐内额度的剩余比例和重置时间，旧版套餐显示 5 小时和每周两个窗口的剩余比例。单独购买的额度不显示；按量付费的账号没有套餐额度，会说明原因。本机运行的 Ollama（localhost:11434）没有套餐，不会被识别。

  • 新添加或一键导入的 Ollama Cloud 供应商默认开启额度查询；已有的供应商在卡片上点「配置用量查询」，Token Plan 模板会自动选好，打开「启用用量查询」后保存即可。

Windows 上切换 Antigravity 账号

授权中心的 Antigravity 账号切换以前只支持 macOS，现在 Windows 也能用：切换后 agy 读到的是新账号，Antigravity 官方卡可以绑定账号、查看所绑账号的额度，打开终端前也会提示将切换到哪个账号。Linux 暂不支持。

修复

  • 从第三方供应商切回 Claude 官方后，已经开着的 Claude Code 会话仍把请求发给上一家，要重开会话才恢复（#9247，见 #7808、#3057）：运行中的 Claude Code 只会读入 settings.json 里新增和改动的环境变量，被删掉的仍留在会话里。现在切换时先把要删的地址、凭据和模型映射写成空值，开着的会话下一条请求就不再用上一家，约 10 秒后再从文件里删掉。会话启动时就定下的主模型（ANTHROPIC_MODEL）不会跟着变：如果上一家设了它，切回后在模型菜单里选一次 Default，或者新开会话。
  • Claude Code / Claude Desktop 的供应商选 Gemini Native 格式时，「获取模型列表」总是报「API Key 无效或无权限」：现在按 Google 要求的方式传 Key。经路由的实际请求本来就正常，只有获取模型列表受影响。另外，Pi、Oh My Pi、Kimi Code 选 Google 接口的供应商，获取模型列表以前最多只列出 50 个，现在能列全。
  • 获取模型列表时，部分放在 Cloudflare 后面的服务商直接拒绝，被误报为「API Key 无效或无权限」（#7429，见 #7427）：请求现在默认带上 User-Agent；供应商或请求头里设了 User-Agent 的，仍以设置的为准。
  • Antigravity 选 Orchestrator 时，仍有部分请求显示未定价（#9542，见 #9493）：显示为「Gemini 4 Hydrogen (Orchestrator)」的步骤按 Gemini 4 Hydrogen 的价格计价，近 30 天内的历史也会补上费用。自定义价格仍然优先。
  • WebDAV 同步在部分 NAS 上完全用不了，测试连接、上传、下载都失败（#5623，见 #5621）：这些 NAS 在共享文件夹已存在时仍对「建目录」回 400，以前会直接中止，现在会再查一次目录是否存在。
  • WebDAV / S3 上传被服务器中途断开时，只显示「请求构造失败」（见 #9559）：现在分清是请求没构造出来还是发送时失败，并附上具体原因，方便判断是网络、TLS 还是服务器的问题。地址里的密码和签名参数不会出现在报错里。
  • S3 自动同步在关掉之后仍可能再上传一次（#9528）：另一次同步进行中时排队的自动上传，现在开始前会重新读取设置，期间关掉了自动同步或 S3 同步就不再上传。WebDAV 本来就是这样。
  • 查询 xAI 账号额度时，遇到网络抖动或 xAI 服务出错就提示需要重新登录（#9526，见 #9522）：只有登录真的失效才这样提示，临时错误照常报错并保留上次查到的额度，下次查询再试。
  • 一个非默认的 xAI 账号过期后，授权中心里选好的默认账号被换成了别的账号（#9548，见 #9543）。
  • 更新 Skill 时如果复制到一半失败，原来的 Skill 被删掉，列表里却仍显示已安装（见 #9521）：现在新版本完整复制好之后才替换，失败时保留原来的版本。
  • Codex 经路由转成 Chat 格式时，工具定义里的 required: null 被要求严格的上游拒绝（#7023，见 #7019）。
  • macOS / Linux 上 shell 配置文件的路径里带冒号时，「检测到系统环境变量冲突」删除或恢复变量会失败（#7170，见 #7169）。
  • PIPELLM、AICodeWith、E-FlowCode 的 Pi 预设在模型选择里显示成旧模型名（#9514）：比如 Claude Opus 5.5 显示成 claude-opus-5，实际请求的是新模型。用这几个预设生成的 DeepSeek Harness、Copilot CLI、Oh My Pi、MiniMax Code、Kimi Code 预设一起修正；已经添加的供应商保留原来保存的名字。
  • 地址形如 api.commandcode.ai/providers 的供应商被当成 Command Code 套餐查询额度（#9518）。

致谢

感谢 @funkpopo（切回 Claude 官方后开着的会话跟着切换，以及语言列表集中管理）、@ziyangxiami（Hydrogen Orchestrator 计价）、@SailingLoong（获取模型列表的 User-Agent）、@stofancy（WebDAV 兼容 NAS）、@HaiYangBG1（xAI 账号的两处修复、Skill 更新失败时保留原版本）、@GalaxyKW（Codex 工具定义的 required）、@cuishuang（环境变量路径里的冒号）、@SaladDay（Pi 预设模型名、Command Code 地址识别、S3 自动同步，以及 WebDAV 与 S3 同步代码合并、语言列表集中管理、前后端常量比对等内部整理）的贡献。

感谢 @Lawgk、@eDramas、@xinluke、@JImmyHui2017、@liuxixiang11、@WindowsXP-PLUS 报告问题和提供复现信息。

完整的技术细节请见 CHANGELOG。
