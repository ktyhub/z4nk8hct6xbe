Chave CC v4.0.35

Esta versão permite que cartões Codex usando contas ChatGPT em Claude Code / Claude Desktop usem GPT-6.2. O alvo completo do Codex /goal pode ser visto no gerenciamento de sessão, e o ID da solicitação nos detalhes da solicitação pode ser copiado com um clique. Além disso, o modo automático do Claude Code é totalmente bloqueado em modelos que não conseguem desligar o pensamento; o modo de agregação Codex e o "Terminal Aberto" informam que o Responses-Lite requer reasoning.context; a primeira solicitação após o Codex compactar o contexto é rejeitada; a página de uso fica travada quando a data personalizada é selecionada para um ano muito antigo; e a cópia gerenciada do Skill não poderá ser desinstalada se não estiver mais lá. Inglês → | Versão japonesa →

Adicionar

Exibir o alvo completo do Codex /goal no gerenciamento de sessão

Quando o alvo excede 700 bytes, o conteúdo do alvo não é escrito no contexto injetado pelo Codex, e o alvo não pode ser visto no gerenciamento de sessão (veja #9647). Agora o objetivo completo é lido no registro da sessão e exibido como um "status do objetivo" de uma etapa, que é expandido para revelar o conteúdo completo; registros duplicados com objetivo e status inalterados não são mais exibidos.

Você pode copiar o ID completo da solicitação nos detalhes da solicitação.

Valores muito longos nos detalhes da solicitação serão truncados por reticências. IDs de solicitação longos, como resp_... do Codex, não podem ser copiados completamente para correspondência de log (consulte #9681). Agora existe um botão de cópia após o ID da solicitação.

Adicionado preço do GPT-6.2 Sol / Astra

O preço é calculado de acordo com o arquivo padrão oficial (dentro de 272K); o arquivo de contexto longo, Batch/Fast e outros arquivos não são diferenciados como GPT-6.

Correção

  • O cartão Codex usando uma conta ChatGPT em Claude Code / Claude Desktop não pode obter GPT-6.2, e ainda relata "não suportado ao usar Codex com uma conta ChatGPT" após preenchê-lo manualmente (#9678, consulte #9670): OpenAI determina quais modelos fornecer de acordo com a versão do cliente Codex, CC Switch A versão relatada é muito antiga. Agora solicite de acordo com o Codex 0.169.0, nenhum ID de modelo é codificado.
  • O modo automático do Claude Code é totalmente rejeitado para Bash, MCP e outras chamadas de ferramentas em modelos que não podem desligar o pensamento (veja #8887, #9671): A solicitação de julgamento no modo automático requer desligar o pensamento. Modelos como MiniMax-M3.1-Flash reportam diretamente 400, e Claude Code considera que o serviço de julgamento não está disponível. Agora ao passar pelo roteamento (Claude Code e Claude Desktop), o upstream do formato Anthropic irá reportar um erro como esse e retirar o campo que fecha o pensamento, e tentar novamente na mesma empresa. As solicitações originalmente aceitas pelo upstream são enviadas como estão, sem afetar o cache.
  • Codex relatou "Responses-Lite requer que reasoning.context seja all_turns" no modo de agregação, e a conexão direta e o roteamento da mesma empresa são normais (consulte #9665): Quando o cartão não grava o diretório do modelo, o modo de agregação usa as mesmas configurações oficiais do GPT-6 que a conexão direta. O mesmo erro que ocorria ao “abrir o terminal” do cartão também foi corrigido.
  • Quando o Codex é convertido para o formato Chat por meio de roteamento, a primeira solicitação após a compactação do contexto é rejeitada pelo gateway com requisitos estritos como "o conteúdo da mensagem não pode estar vazio" (consulte #9660): Mensagens do usuário contendo apenas imagens se tornarão mensagens vazias durante a compactação. Agora, ao converter para o formato Chat, as mensagens do usuário com conteúdo vazio são removidas e as demais mensagens permanecem inalteradas.
  • Quando o ponto inicial da data personalizada na página de uso é selecionado para um ano muito antigo, como 1905, o cliente congela (consulte #9691): Agora você só pode selecionar datas do primeiro registro de uso até hoje. As datas fora do intervalo não podem ser selecionadas e as datas inseridas manualmente serão colocadas de volta no intervalo.
  • Não é possível desinstalar quando a cópia gerenciada de uma habilidade não está mais disponível (#9669, consulte #9668).

Agradecimentos especiais aos seguintes colaboradores: Seu PR descobriu e corrigiu um problema real, mas o mesmo problema foi posteriormente corrigido na linha principal e o PR foi fechado. @xunapro (#4262, o primeiro PR do mesmo tipo propôs que a seleção do provedor de serviços S3 não foi lembrada, e Alibaba Cloud OSS/Tencent Cloud COS relatou 403 devido ao endereço do caminho), @mercutiojohn (#8547, identificou três razões pelas quais o fornecedor Gemini CLI não conseguiu obter a lista de modelos). Obrigado a @chencyan364, @DemosHume, @LAN-SHH, @mouse8867, @leafsnow, @zhuqiang1248, @ramonmi, @zx2121651, @VICCC-0x90 por levantar requisitos, relatar problemas e fornecer informações de reprodução. cc-switch v4.0.35

Highlights

  • GPT-6.2 on ChatGPT-backed Codex cards — Claude Code and Claude Desktop now report Codex client version 0.169.0 instead of pinning model IDs, fixing the “not supported” rejection and letting OpenAI’s negotiation determine availability (#9678). Pricing covers only the standard ≤272K tier; long-context, Batch, and Fast tiers are not yet differentiated.
  • Auto mode tolerates mandatory reasoning — When an Anthropic-format upstream rejects the request to disable thinking—such as MiniMax-M3.1-Flash—the router removes that field and retries once with the same provider. Accepted requests remain untouched, preserving cache behavior, while Bash/MCP tool calls no longer fail across the session.
  • Codex routing handles aggregation and compaction — Cards without a model catalog now use the official GPT-6 settings employed by direct connections, satisfying Responses-Lite’s reasoning.context = all_turns requirement in aggregation and “Open Terminal” flows (#9665). Chat-format conversion also removes empty user messages produced by image-only compaction, preventing the first post-compaction request from being rejected (#9660).
  • Session and request diagnostics are no longer truncated — Full /goal text is recovered from session records even when Codex omits goals over 700 bytes from injected context; unchanged goal/status duplicates are collapsed. Long request IDs such as resp_... now have a copy button for reliable log correlation (#9647, #9681).
  • Guardrails for stale state — Missing managed Skill copies no longer block uninstall (#9669), while custom usage dates are limited to the range from the first recorded usage through today. Out-of-range manual input is clamped, eliminating the freeze caused by extremely early years (#9691).
  • Breaking changes — None.

CC Switch v4.0.35

本版本让 Claude Code / Claude Desktop 里用 ChatGPT 账号的 Codex 卡片能用上 GPT-6.2，会话管理里可以看到 Codex /goal 的完整目标，请求详情里的请求 ID 可以一键复制。

另外修复了 Claude Code 的 auto 模式在关不掉思考的模型上被整体拦下；Codex 聚合模式和「打开终端」报 Responses-Lite 需要 reasoning.context；Codex 压缩上下文后第一条请求被拒；用量页自定义日期选到很早的年份时卡死；Skill 的托管副本不在了就卸载不掉等问题。

新增

会话管理里显示 Codex /goal 的完整目标

目标超过 700 字节时，Codex 注入的上下文里不写目标内容，会话管理里也就看不到目标（见 #9647）。现在从会话记录里读出完整目标，显示成一步「目标 · 状态」，展开即是完整内容；目标和状态都没变的重复记录不再显示。

请求详情里可以复制完整的请求 ID

请求详情里过长的值会被省略号截断，像 Codex 的 resp_... 这类长请求 ID 没法完整复制去对日志（见 #9681）。现在请求 ID 后面多了一个复制按钮。

新增 GPT-6.2 Sol / Astra 的价格

按官方标准档（272K 以内）的价格计费；长上下文档、Batch / Fast 等档位和 GPT-6 一样暂不区分。

修复

  • Claude Code / Claude Desktop 里用 ChatGPT 账号的 Codex 卡片获取不到 GPT-6.2，手动填了也报「not supported when using Codex with a ChatGPT account」（#9678，见 #9670）：OpenAI 按 Codex 客户端版本决定给哪些模型，CC Switch 报的版本太旧。现在按 Codex 0.169.0 请求，没有写死任何模型 ID。
  • Claude Code 的 auto 模式在关不掉思考的模型上，Bash、MCP 等工具调用全部被拒（见 #8887、#9671）：auto 模式的判断请求要求关闭思考，MiniMax-M3.1-Flash 这类模型直接报 400，Claude Code 就认为判断服务不可用。现在经路由时（Claude Code 和 Claude Desktop），Anthropic 格式的上游这样报错会去掉关闭思考的字段，在同一家重试一次。上游本来接受的请求原样发送，不影响缓存。
  • Codex 聚合模式下报「Responses-Lite requires reasoning.context to be all_turns」，同一家直连和路由都正常（见 #9665）：卡片没写模型目录时，聚合模式改用和直连一样的 GPT-6 官方设置。从卡片「打开终端」时出现的同一个报错也一并修好。
  • Codex 经路由转成 Chat 格式时，压缩上下文后第一条请求被要求严格的网关以「message content cannot be empty」拒绝（见 #9660）：压缩时只含图片的用户消息会变成空消息，现在转成 Chat 格式时去掉内容为空的用户消息，其他消息不变。
  • 用量页自定义日期的起点选到 1905 年这类很早的年份时，客户端卡死（见 #9691）：现在只能选从第一条用量记录到今天之间的日期，范围外的日期不可选，手动输入的也会被拉回范围内。
  • Skill 的托管副本已经不在时卸载不掉（#9669，见 #9668）。

致谢

感谢 @imfuxiao（Codex 卡片支持 GPT-6.2）、@Maharramoff（卸载托管副本已不在的 Skill）、@SaladDay（拆分本地路由的转发代码、数据库访问改用应用类型）的贡献。

特别感谢以下贡献者：你们的 PR 发现并修复了真实的问题，只是同样的问题后来在主线上另行修好，PR 因此关闭。@xunapro（#4262，同类 PR 里最早提出 S3 服务商选择没被记住、阿里云 OSS / 腾讯云 COS 因路径式地址报 403）、@mercutiojohn（#8547，找准了 Gemini CLI 供应商获取模型列表失败的三个原因）。

感谢 @chencyan364、@DemosHume、@LAN-SHH、@mouse8867、@leafsnow、@zhuqiang1248、@ramonmi、@zx2121651、@VICCC-0x90 提出需求、报告问题和提供复现信息。
