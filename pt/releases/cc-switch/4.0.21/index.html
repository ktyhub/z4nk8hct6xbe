Chave CC v4.0.21

Esta versão adiciona a alternância entre várias contas de assinatura oficiais do Claude Code: adicione várias contas Claude na central de autorização, escolha uma para cada cartão oficial e, seja qual for o cartão para o qual você mudar, o Claude Code usará esse número; se quiser usar vários números ao mesmo tempo, "abrir o terminal" do cartão, esse terminal usará sempre o número do cartão. Faça login e siga o processo oficial do Claude Code. O token só ficará no Código Claude na sua máquina local. O CC Switch não fará upload, atualização ou logout. Os cartões vinculados às contas e à central de autorização exibirão o pacote e o saldo restante de cada conta. Além disso, o "Terminal Aberto" foi movido para o cartão, e a lista de modelos do Codex pode ser arrastada e classificada, o que será mantido após reiniciar no modo leve. Corrigido o problema de expiração de login incorreta após a conta ChatGPT gerenciada ser reiniciada, a solicitação do Codex é enviada para outro endereço durante o roteamento, há timeout / autoApprove extras na configuração MCP do Codex, OpenCode e Grok Build não estão instalados corretamente no npm 12, o tempo de uso do Kimi Code está errado e há &, *, ! no models.yml do Oh My Pi. Adicionar

Alternar entre várias contas de assinatura oficial do Claude

Quando você tem mais de uma assinatura Claude (como Max pessoal e equipe da empresa ou várias contas Pro), você só pode criar /logout e depois /login no Claude Code ou criar você mesmo um diretório de configuração para cada conta. Agora é possível gerenciar múltiplas contas no CC Switch (#1928). Para uso gráfico e comparação de conformidade item por item, consulte Use CC Switch para alternar várias assinaturas oficiais do Claude e problemas de conformidade. **Segurança e Conformidade. ** A conta de assinatura é gerenciada pela ferramenta. O mais importante é que o token seja seguro e não viole os termos da Antrópico. Esta função é implementada de acordo com a documentação oficial do Claude Code. O token está sempre apenas no seu Código Claude local:

  • **Faça login e siga o processo oficial. ** Ao adicionar uma conta, você está executando o claude auth login --claudeai que vem com o Claude Code. A senha e autorização são preenchidas na página oficial do claude.ai. CC Switch não possui login próprio Claude, nem cliente OAuth próprio. A [página jurídica e de conformidade] (https://code.claude.com/docs/en/legal-and-compliance#authentication-and-credential-use) da Anthropic exige que o login em uma conta Claude seja concluído por meio do próprio processo da Anthropic e não restringe explicitamente os usuários de fazer login no Claude Code não modificado com suas próprias assinaturas.
  • **Múltiplas contas usam o método oficialmente recomendado. ** Cada conta possui um diretório de configuração independente, diferenciado por CLAUDE_CONFIG_DIR. O método é o mesmo da seção "Login com múltiplas contas" no Código Claude [Documento de Certificação] (https://code.claude.com/docs/en/authentication#log-in-with-multiple-accounts). CC Switch apenas cria o diretório e abre o terminal para você.
  • **O token não sai da máquina. ** O token existe apenas no próprio local do Claude Code (chaveiro para macOS, .credentials.json para Linux e Windows), e não é carregado, sincronizado com a nuvem ou gravado no banco de dados CC Switch. O próprio CC Switch lembra apenas informações da conta, como e-mail, organização, pacote e tempo de expiração do login, mas não lembra tokens.
  • **Não envia solicitações para você. ** CC Switch não possui servidor e não requer token de assinatura para chamar o modelo; as solicitações de diálogo são enviadas diretamente para a Anthropic a partir do Claude Code local não modificado, e o uso é cobrado em sua própria conta. Ao verificar o limite, verifique diretamente a interface de limite oficial da Anthropic nesta máquina, que contém os mesmos dados do /usage do próprio Claude Code.
  • **Sem atualização, sem logout, sem alteração do Código Claude. ** Os tokens são sempre atualizados pelo próprio Claude Code. Excluir uma conta excluirá apenas o diretório criado para ela pelo CC Switch (junto com a entrada desse diretório nas chaves do macOS) e não permitirá que a conta efetue logout em qualquer lugar. CC Switch não modifica os arquivos de programa de Claude Code.
  • **Basta controlar sua própria conta. ** Não faz rotação automática de contas de acordo com cotas, nem oferece a função de compartilhar assinaturas com outras pessoas. O cartão e o número serão movidos e registrados entre os locais de armazenamento do Código Claude local (apenas no formato próprio do Código Claude). A documentação oficial não menciona especificamente esse uso. Caso queira utilizar apenas o método especificado no documento, guarde o cartão “Login com Código Claude”, sendo que as demais contas só poderão ser utilizadas a partir do cartão “Terminal Aberto”. Como usar:
  • **Adicionar conta. ** Clique em “Adicionar Conta” no grupo Claude da Central de Autorização. O navegador abrirá a página de autorização oficial de claude.ai, e a conta aparecerá automaticamente na lista após o login. Se o navegador não puder retornar à máquina após a autorização, você pode colar o endereço na barra de endereço ou o código na página de volta. Os diretórios de cada conta não interferem entre si e sincronizarão suas configurações em ~/.claude, MCP e CLAUDE.md (exceto credenciais de login e configurações relacionadas a roteamento).
  • **Escolha uma conta para o cartão oficial. ** O menu suspenso "Método de login" do cartão oficial de Claude é o mesmo do cartão oficial do Codex: a parte superior é a conta logada e a parte inferior é "Adicionar ou gerenciar conta Claude" (vá para a central de autorização) e "Fazer login com código Claude". Basta criar um cartão para uma conta.
  • **Corte o cartão e o número será cortado. ** Ao mudar para o cartão oficial da conta selecionada, o CC Switch coloca o login desta conta na posição onde Claude Code o lê por padrão, e a conta original é colocada de volta em seu próprio diretório. claude no terminal, plug-in IDE e script usarão esse número, e o Código Claude que já está em execução também será alterado imediatamente sem reiniciar. Ao mudar para o cartão oficial da conta selecionada, o login atual será coletado primeiro, caso ainda não esteja na central de autorização. Claude Code mantém seu próprio bloqueio ao trocar; se o CC Switch sair acidentalmente durante a troca, ele será automaticamente concluído ou retirado na próxima vez que for trocado ou iniciado. Os cartões que escolherem “Login com Claude Code” não serão logados, e quem não adicionar uma conta não será afetado.
  • **Vários números são usados ​​ao mesmo tempo. ** “Terminal Aberto” no cartão com a conta selecionada. Este terminal é fixado com o número do cartão. Trocar de cartão posteriormente não afetará isso.
  • **Pacote e cota. ** A legenda do cartão mostra o número da conta e pacote (como Max 20x), e um prompt é exibido quando o login precisa ser atualizado; o limite restante desta conta é exibido por padrão na parte inferior do cartão, e cada conta na central de autorização também possui a mesma coluna de limite. Quando o token de uma conta não utilizada expirar, o CC Switch executará o claude -p /usage do próprio Claude Code em seu diretório uma vez (até uma vez a cada 10 minutos para cada conta). O Claude Code atualizará o login e consultará a cota sozinho, e o CC Switch apenas lerá os resultados. /usage não chama o modelo e não consome o crédito do diálogo. Cartões oficiais sem conta selecionada também exibirão o pacote conectado no momento. Alguns pontos a serem observados:
  • O Controle Remoto que você está utilizando será desconectado após a alteração do número; a primeira mensagem após a alteração do número precisa reconstruir o cache de prompt, que será mais lento e consumirá mais crédito.
  • Quando o diretório de configuração do Claude é sobrescrito nas configurações (incluindo apontar para WSL), Cheka não mudará de login e a interface solicitará o uso de "Terminal Aberto".

Correção

  • Após reiniciar a conta ChatGPT gerenciada, aparece "Login expirou" e não pode ser alterado. Ele se recupera depois de um tempo (#8901). No passado, qualquer HTTP 403 encontrado ao atualizar o login era considerado uma falha de login e os erros de rede também eram exibidos como expirados. Agora, como o Codex CLI, apenas erros 401 ou erros de invalidação de token claro são considerados expirados; problemas temporários de rede serão repetidos normalmente e a cota manterá o último resultado. Após a troca da bandeja, o saldo que não foi consultado na interface principal também será consultado novamente.
  • Quando o Codex era roteado localmente, a solicitação era enviada para outros endereços (#8849, #8848). Quando houver múltiplas tabelas de fornecedores em config.toml, ou houver uma linha de endereços antigos comentada acima, o primeiro base_url do texto foi previamente buscado, e a Chave do fornecedor selecionado será enviada para outro lugar. Agora pressione model_provider para obter o endereço da tabela selecionada.
  • O uso da compactação remota do Codex às vezes é perdido (#8879).
  • Existem timeout e autoApprove extras na configuração MCP do Codex, a versão desktop do Codex relatou configurações desconhecidas e --strict-config recusou-se a carregar (#8843). Esses dois campos pertencem a outros clientes. Eles foram gravados no config.toml como eram antes. Se forem excluídos manualmente, serão gravados de volta na próxima vez que forem sincronizados. Agora removido ao gravar no Codex, outros aplicativos não serão afetados.
  • Quando o Codex está conectado a vários recursos do Azure por meio de retransmissão, uma mensagem 400 "criado sob um recurso Azure OpenAI diferente" é relatada no meio da sessão e não pode ser continuada (#8877). Agora tente novamente após receber este erro, removendo o ID da entrada do histórico. Solicitações normais não são afetadas.
  • ClinePass é um upstream que retorna resultados de Chat Completions em data. Solicitações sem streaming relatam 422 "Sem opções de resposta" (#5658).
  • No npm 12, o OpenCode instalado na página "Aplicativo" reporta "Incompatível com a versão do Windows que você está executando" no Windows, e o Grok Build ainda está executando a versão antiga após a atualização (#8863). O npm 12 não executa o script de instalação por padrão e esses dois pacotes dependem dele para colocar programas reais. Seus scripts de instalação agora são permitidos durante a instalação e atualização.
  • Hermes no Windows é exibido como duas instalações na página "Aplicativos" (#8839). hermes.cmd deixado no mesmo diretório não é mais contado como uma instalação.
  • Uso do Kimi Code, o tempo de solicitação para uma rodada inteira de diálogo é o mesmo e, quando calculado por hora, é comprimido na última hora (#8899). Agora registre o tempo em que cada solicitação é concluída. Os registros importados serão corrigidos na próxima vez que o arquivo da sessão for alterado.
  • Quando o models.yml do Oh My Pi contém name: Search & Fetch, que contém valores como &, * e !, o fornecedor informa "Este YAML usa um formato ou sintaxe que não pode ser editado com segurança pelo CC Switch" (#8897).
  • Quando ~/.gemini/.env é escrito como export GEMINI_API_KEY=..., não há chave após a importação e ela será excluída do arquivo ao voltar para o fornecedor padrão (#8862, #8861).
  • **Ao mudar de um projeto com palavras de prompt habilitadas para um projeto sem palavras de prompt, as palavras de prompt originais não são desativadas. **
  • Quando a barra lateral da página de estatísticas de uso é expandida ou recolhida, a borda direita do gráfico de tendências salta (#8548).

cc-switch v4.0.21

Highlights

  • Multiple official Claude accounts, switchable per card — CC Switch can now manage several Claude.ai subscriptions (personal Max vs. company Team, multiple Pro seats) and swap which one claude uses (#1928). Accounts are added through the official claude auth login --claudeai flow, each in its own CLAUDE_CONFIG_DIR — the same pattern Claude Code's own docs recommend — with settings, MCP config and CLAUDE.md seeded from ~/.claude but credentials and routing left alone. Switching a card moves that account's login into Claude Code's default credential store (macOS Keychain / .credentials.json) under Claude Code's own lock, with automatic completion or rollback on the next launch if the app dies mid-swap; running sessions follow immediately, no restart needed. Tokens never reach CC Switch's database or any server — it stores only email, org and plan metadata, never refreshes or logs out accounts, and deletion only removes the directories it created. For genuinely parallel use, launch a terminal from the card: that shell is pinned to the card's account and unaffected by later switches. Watch-outs: Remote Control sessions disconnect on account change, the first message after a switch rebuilds the prompt cache (slower, extra usage), and if you've overridden the Claude config directory — including pointing it at WSL — card switching deliberately won't move credentials; use "Open Terminal" instead.

  • Codex routing and auth correctness — With multiple provider tables in config.toml, or a commented-out old address above the active one, CC Switch previously grabbed the first base_url in the text and paired it with the selected provider's key — sending both to the wrong host. The address is now resolved from the table named by model_provider (#8849, #8848). Related fixes: Azure relay sessions hit by 400 "created under a different Azure OpenAI resource" now retry once with the prior entry IDs stripped (#8877), remote-compaction usage is no longer lost (#8879), and managed ChatGPT accounts no longer show a false "login expired" and lock out switching on any 403 — only 401 or an explicit token-invalid error counts, matching Codex CLI, with transient failures retried and the last quota result kept (#8901). If you somehow depended on that commented-out URL being used, that behavior is gone.

  • Generated config stays valid under strict validation — CC Switch stops writing timeout and autoApprove into Codex's MCP config (#8843): those fields belong to other clients and triggered "unknown setting" errors in Codex Desktop and outright load failures under --strict-config, with manual deletion undone on the next sync; other applications' configs are unaffected. SSE selection now warns up front (#8882) — Codex accepts only stdio and HTTP and will try to talk HTTP to an SSE-only server, while Pi and Antigravity reject it on save. Editing robustness also improved: ~/.gemini/.env entries written as export GEMINI_API_KEY=... import correctly and no longer get deleted when switching back to the default provider (#8862, #8861), and Oh My Pi models.yml values containing &, *, or ! (e.g. name: Search & Fetch) no longer block saving with "unsupported YAML format" (#8897).

  • Installs and usage metering — npm 12 stopped running install scripts by default, which made the OpenCode install on Windows report "incompatible with your Windows version" and left Grok Build running the old binary after an upgrade; install and upgrade now explicitly allow those packages' scripts (#8863). A leftover hermes.cmd no longer registers as a second Windows installation (#8839), and ClinePass-style upstreams that wrap Chat Completions payloads in data no longer produce 422 "No choices in response" on non-streaming calls (#5658). Kimi Code usage is now timestamped per request completion instead of stamping a whole conversation identically and bunching it into the last hour (#8899); already-imported records correct themselves on the next session-file change.

  • Model and card workflow polish — The Codex provider form's model list is drag-reorderable with mouse or keyboard, and that order is literally the /model menu order — drag a model to the top to make it the default, replacing the delete-and-re-add workaround (#8870). "Open Terminal" moved from the ⋯ menu to an icon next to "Edit," with an "(environment isolated)" tooltip on cards pinned to an account or custom endpoint; lightweight mode now survives restarts, though a cold ccswitch:// launch still opens the main window so import dialogs can render. Presets were refreshed too: DeepSeek standardized on Flash, Kimi gained K3.1 Pro / Pro HighSpeed with low/high/max reasoning (#8867), and ClinePass (#8885) and TeamoRouter Claude (#8266) were added.

  • Breaking changes — None.

CC Switch v4.0.21

本版本为 Claude Code 增加了多个官方订阅账号的切换：在授权中心添加几个 Claude 账号，每张官方卡选一个，切到哪张卡，Claude Code 就用哪个号；想几个号同时用，从卡片上「打开终端」，那个终端固定用卡片上的号。登录走 Claude Code 官方的流程，令牌只留在本机的 Claude Code 里，CC Switch 不上传、不刷新、不登出。绑了账号的卡片和授权中心都会显示每个号的套餐和剩余额度。另外，「打开终端」挪到了卡片上，Codex 的模型列表可以拖动排序，轻量模式重启后保持。修复了托管 ChatGPT 账号重启后误报登录过期、Codex 经路由时请求发到了别的地址、Codex 的 MCP 配置里多出 timeout / autoApprove、npm 12 下 OpenCode 和 Grok Build 装不好、Kimi Code 用量的时间不对、Oh My Pi 的 models.yml 里有 &、*、! 时无法编辑等问题。4.0 完整的更新内容请见 v4.0 发布说明。

新增

在多个 Claude 官方订阅账号之间切换

手上有不止一个 Claude 订阅（比如个人 Max 和公司 Team，或者多个 Pro 账号）时，以前只能在 Claude Code 里 /logout 再 /login，或者自己给每个号建配置目录。现在可以在 CC Switch 里管理多个号（#1928）。

图文用法和逐条的合规对照见 使用 CC Switch 切换多个 Claude 官方订阅以及合规问题。

安全与合规。 订阅账号交给工具管理，最要紧的是令牌安全、不违反 Anthropic 的条款。这个功能按 Claude Code 官方文档的做法实现，令牌始终只在你本机的 Claude Code 里：

  • 登录走官方流程。 添加账号时运行的是 Claude Code 自带的 claude auth login --claudeai，密码和授权都在 claude.ai 的官方页面完成。CC Switch 没有自己的 Claude 登录，也没有自己的 OAuth 客户端。Anthropic 的法律与合规页要求 Claude 账号的登录必须通过 Anthropic 自己的流程完成，并且明确不限制用户用自己的订阅登录未经修改的 Claude Code。
  • 多账号用的是官方推荐的方法。 每个号一个独立的配置目录，用 CLAUDE_CONFIG_DIR 区分，和 Claude Code 认证文档里「Log in with multiple accounts」一节的方法一样，CC Switch 只是替你建好目录、打开终端。
  • 令牌不离开本机。 令牌只存在 Claude Code 自己的位置（macOS 的钥匙串，Linux、Windows 的 .credentials.json），不上传，不随云同步，也不写进 CC Switch 的数据库。CC Switch 自己只记邮箱、组织、套餐这类账号资料和登录过期时间，不记令牌。
  • 不替你发请求。 CC Switch 没有服务器，不用订阅令牌调用模型；对话请求都由本机未经修改的 Claude Code 直接发给 Anthropic，用量计在你自己的账号上。查额度时在本机直接查 Anthropic 官方的额度接口，和 Claude Code 自己的 /usage 查的是同一份数据。
  • 不刷新、不登出、不改 Claude Code。 令牌一律由 Claude Code 自己刷新。删除账号只删 CC Switch 为它建的目录（macOS 上连同这个目录在钥匙串里的条目），不会让这个号在任何地方退出登录。CC Switch 不修改 Claude Code 的程序文件。
  • 只管你自己的账号。 不按额度自动轮换账号，也不提供把订阅共享给别人的功能。

切卡即切号会在本机 Claude Code 的存储位置之间移动登录（只按 Claude Code 自己的格式），官方文档没有专门讲到这种用法。只想用文档写明的方式的话，卡片保持「跟随 Claude Code 登录」，其他号只从卡片「打开终端」使用。

怎么用：

  • 添加账号。 在授权中心的 Claude 组点「添加账号」。浏览器会打开 claude.ai 的官方授权页，登录后账号自动出现在列表里。浏览器授权后回不到本机时，可以把地址栏里的地址或页面上的代码粘贴回来。每个号的目录互不干扰，会同步你在 ~/.claude 里的设置、MCP 和 CLAUDE.md（登录凭据和路由相关的设置除外）。
  • 给官方卡选账号。 Claude 官方卡的「登录方式」下拉和 Codex 官方卡一样：上面是已登录的账号，下面是「添加或管理 Claude 账号」（跳到授权中心）和「跟随 Claude Code 登录」。一个号建一张卡就行。
  • 切卡即切号。 切到选了账号的官方卡时，CC Switch 把这个号的登录放进 Claude Code 默认读取的位置，原来那个号放回它自己的目录。终端、IDE 插件、脚本里的 claude 都改用这个号，已经在运行的 Claude Code 也会立即跟着换，不用重启。切到选了账号的官方卡时，现在的登录如果还不在授权中心会先收进来。切换时持有 Claude Code 自己的锁；切换中途 CC Switch 意外退出的话，下次切换或启动时会自动补完或撤回。选「跟随 Claude Code 登录」的卡不碰登录，不添加账号的人不受影响。
  • 几个号同时用。 在选了账号的卡上「打开终端」，这个终端固定用卡片上的号，之后切换卡片不影响它。
  • 套餐和额度。 卡片副标题显示账号和套餐（如 Max 20x），登录需要更新时带一个提示；卡片底部默认显示这个号的剩余额度，授权中心里每个号也有一样的额度列。不在用的号令牌过期时，CC Switch 在它的目录里运行一次 Claude Code 自带的 claude -p /usage（每个号最多 10 分钟一次），由 Claude Code 自己刷新登录、查询额度，CC Switch 只读结果。/usage 不调用模型，不消耗对话额度。没选账号的官方卡也会显示当前登录的套餐。

几点注意：

  • 切号后正在用的 Remote Control 会断开；换号后第一条消息要重建提示缓存，会慢一点、多用一点额度。
  • 在设置里覆盖了 Claude 配置目录（包括指向 WSL）时，切卡不会切换登录，界面会提示改用「打开终端」。

Codex 的模型列表可以拖动排序

Codex 供应商表单里的模型列表，每行开头有拖动手柄，可以用鼠标或键盘调整顺序（#8870）。这个顺序就是 Codex 里 /model 菜单的顺序。第一行代表默认模型时，拖到第一行的模型成为新的默认模型。以前要删掉再加回来才能挪位置。

改进

「打开终端」挪到卡片上。 以前在 ⋯ 菜单里，现在是「编辑」左边的一个图标按钮。悬停提示是「以此供应商打开终端」，终端固定用这张卡时（填了自己的地址和 Key 的卡、选了 Claude 账号的官方卡）会写「（环境隔离）」。

授权中心每组的「添加账号」按钮固定在标题右边。 以前没有账号时按钮会挪到空白提示里，几组卡片的按钮高低不一。ChatGPT 的登录方式改成按钮旁边的一个小下拉。标题里的「删除全部账号」菜单去掉了，账号在各自那一行的菜单里删除。各个账号的额度条现在对齐，长度一致。

轻量模式重启后保持。 在轻量模式下退出 CC Switch，下次启动仍是轻量模式，不再弹出主界面。从 ccswitch:// 链接冷启动时照常打开主界面，好显示导入对话框。

Hermes 卡片显示「默认」，「设为默认」移到 ⋯ 菜单里。 Hermes 把添加的供应商都写进 config.yaml，当前那家只是默认值，和 OpenClaw、OpenCode、Kimi Code 一样。以前的电源图标「启用」按钮看起来像开关。

卡片变成「使用中」时，用量一栏不再左右挪动。

MCP 选了 SSE 时提示哪些应用不支持（#8882）。Codex 只支持 stdio 和 HTTP，会把 SSE 地址当作 HTTP 连接，服务端只支持 SSE 时连不上；Pi 和 Antigravity 保存时会报错。现在「写入到」下面会提前提示。

Claude Desktop 的上游地址填 githubcopilot.com 时，上游格式显示为「由路由按模型自动选择」（#8838），和选 GitHub Copilot 供应商时一样。

OpenCode 的 OMO、OMO Slim 卡片不再显示「检测连通」（#8842）。它们只是代理和模型的对应关系，没有地址可测，以前点了会报错。

土耳其语翻译补全（#8836）。

预设： DeepSeek 一律改用 Flash 模型；Kimi 官方预设加入 K3.1 Pro 和 K3.1 Pro HighSpeed，可以选 low / high / max 思考程度（#8867）；OpenClaw 的 MiniMax M3.1 Flash 可以选 max；新增 ClinePass（#8885）、TeamoRouter Claude（#8266）；Claude Desktop 的 OpenCode Go 改用官方文档的地址，额度也能查了（#8720、#8779）。

修复

  • 托管 ChatGPT 账号重启后显示「登录已过期」、不能切换，过一会儿又自己好了（#8901）。以前刷新登录时遇到任何 HTTP 403 都当成登录失效，网络错误也显示成过期。现在和 Codex CLI 一样，只有 401 或明确的令牌失效错误才算过期；一时的网络问题照常重试，额度保留上一次的结果。托盘切换后，主界面里查询失败的额度也会重新查询。
  • Codex 经本地路由时，请求发到了别的地址（#8849、#8848）。config.toml 里有多个供应商表、或上面有一行注释掉的旧地址时，以前取的是文本里第一个 base_url，会带着选中供应商的 Key 发到别处。现在按 model_provider 选中的那张表取地址。
  • Codex 远程压缩的用量有时漏记（#8879）。
  • Codex 的 MCP 配置里多出 timeout、autoApprove，Codex 桌面版报未知设置，--strict-config 拒绝加载（#8843）。这两个字段是别的客户端的，以前原样写进了 config.toml，手动删掉下次同步又会写回来。现在写给 Codex 时去掉，其他应用不受影响。
  • Codex 经中转连到多个 Azure 资源时，会话中途报 400「created under a different Azure OpenAI resource」，无法继续（#8877）。现在收到这个错误后重试一次，去掉历史记录的条目 ID。正常的请求不受影响。
  • ClinePass 这类把 Chat Completions 结果包在 data 里返回的上游，非流式请求报 422「No choices in response」（#5658）。
  • npm 12 下，「应用」页装的 OpenCode 在 Windows 上报「与你运行的 Windows 版本不兼容」，Grok Build 升级后仍在跑旧版本（#8863）。npm 12 默认不运行安装脚本，这两个包要靠它放置真正的程序。现在安装和升级时允许它们的安装脚本。
  • Windows 上 Hermes 在「应用」页显示成两处安装（#8839）。同一目录里遗留的 hermes.cmd 不再算一处安装。
  • Kimi Code 的用量，一整轮对话的请求时间都一样，按小时统计时挤在最后一小时（#8899）。现在按每次请求完成的时间记。已导入的记录在会话文件下次变化时会更正。
  • Oh My Pi 的 models.yml 里有 name: Search & Fetch 这类含 &、*、! 的值时，保存供应商时报「此 YAML 使用了 CC Switch 无法安全编辑的格式或语法」（#8897）。
  • ~/.gemini/.env 里写成 export GEMINI_API_KEY=... 时，导入后没有 Key，切回默认供应商还会把它从文件里删掉（#8862、#8861）。
  • 从启用了提示词的项目切到没有提示词的项目，原来的提示词没有停用。
  • 用量统计页展开或收起侧栏时，趋势图右边缘跳动（#8548）。
