Chave CC v4.0.29

Esta versão adiciona um novo aplicativo gerenciado GitHub Copilot CLI: Fornecedores com sua própria chave escreverão seu próprio providers.json no Copilot. Utilize /model em copilot para selecioná-lo junto com o modelo oficial sem passar pelo CC Switch. Os idiomas coreano e russo foram adicionados à interface. Os sete idiomas foram mantidos simultaneamente e o inglês não é mais exibido nos locais faltantes. Além disso, a versão desktop do Codex no Windows relatou um erro ao executar o Codex no WSL ao usar um provedor terceirizado; Novas conversas do Codex relataram 400 ao conectar-se ao upstream de respostas nativas de terceiros via roteamento; quando o Codex se conectou ao formato Anthropic upstream via roteamento, as respostas longas foram truncadas pelo limite superior de saída de 8192; O oficial do Codex travou no modo de roteamento e não conseguiu obter a lista de modelos da própria conta. Adicionar

GitHub Copiloto CLI

GitHub Copilot CLI (copilot) torna-se um novo aplicativo gerenciado (#8753, consulte #5768 para obter os requisitos). Existem dois tipos de cartões de fornecedor:

  • Login Oficial: Faça login com o Copilot CLI em seu próprio GitHub sem gravar nenhum arquivo. "Terminal Aberto" inicia copilot com o modelo e força de inferência no cartão; quando o cartão estiver vinculado à conta GitHub da central de autorização, use esta conta para iniciar. O limite do Copilot da conta é exibido no cartão.
  • Fornecedores com Chave Própria: Clique em “Adicionar” e escreva providers.json ($COPILOT_HOME/providers.json) próprio do Copilot. Posteriormente, se você iniciar o copilot em qualquer lugar da máquina, poderá selecionar “Logotipo/Modelo do Cartão” no /model junto com o modelo oficial, e a solicitação será enviada diretamente ao fornecedor sem roteamento pelo CC Switch. GitHub pode ser usado sem fazer login.
    • O CC Switch altera apenas suas próprias entradas, deixando outras entradas no arquivo (o próprio Copilot também gravará esse arquivo) e a ordem inalterada. O providers.json Copilot não poderá iniciar se for escrito incorretamente, portanto, todo o arquivo será verificado de acordo com as regras do Copilot antes de escrever. Por exemplo, a saída máxima do modelo não pode ocupar toda a janela de contexto.
    • A casa onde o modelo padrão atual do Copilot está localizado está marcada como padrão e não pode ser removida ou excluída. Para alterar, primeiro use /model no copilot para substituí-lo por outro modelo.
    • O botão do terminal no cartão só pode ser usado após adicioná-lo. Ao iniciar, selecione diretamente o primeiro modelo desta placa.
    • Os padrões herdam os padrões do fornecedor do Pi. Também suporta:
  • MCP, Skills, Prompt Words: Sincronizado com o mcp-config.json do Copilot, diretório de Skills e arquivos de comando.
  • Gerenciamento de sessões: lista as sessões do Copilot, que podem ser retomadas no terminal.
  • Estatísticas de uso: importe o uso do log de sessão do Copilot; fornecedores com Chave própria serão cobrados de acordo com o cartão selecionado na sessão.
  • Link de importação com um clique: você pode importar fornecedores do Copilot, reconhecer a escrita providers.json, oferecer suporte a bearerToken e reter todos os IDs de modelo no link.

Interfaces coreano e russo, sete idiomas são mantidos simultaneamente

  • Coreano (#8794, consulte #2704 para requisitos) e Russo (#7788, consulte #6010 para requisitos): seleção automática por idioma do sistema na primeira inicialização, menu da bandeja e painel de atalho também foram traduzidos. A moeda para estatísticas de uso foi adicionada ao Won Coreano (KRW), que suporta aquisição automática de taxas de câmbio.
  • Turco, coreano e russo não são mais "traduções comunitárias e o inglês é exibido onde falta": cada frase na interface está disponível em sete idiomas: chinês simplificado, chinês tradicional, inglês, japonês, 한국어, Türkçe e Русский. Posteriormente, os direitos autorais novos e modificados também serão alterados nos sete idiomas.
  • O resumo da atualização que aparece após a atualização está disponível apenas em chinês simplificado, chinês tradicional, inglês e japonês, e outros idiomas são exibidos em inglês.

Mudança

  • Copilot explica o motivo pelo qual a lista de modelos obtida está vazia (#5500): Contas Copilot Free podem obter modelos, mas nenhum deles pode ser usado no seletor de modelos. Anteriormente, apenas informava que nenhum modelo foi encontrado. Agora será avisado que esta conta pode não ter o Copilot Pro ativado; os formulários Claude Code e Claude Desktop também solicitarão que gpt-4.1 ou gpt-4o possam ser preenchidos manualmente. Quando a conta possui modelos, mas nenhum deles suporta o formato upstream atualmente selecionado, o formulário do Codex explicará isso separadamente.

Correção

  • Quando a versão desktop do Codex no Windows executa o Codex em WSL, um provedor terceirizado relata "Esse arquivo ou diretório não existe (erro de sistema operacional 2)" na inicialização (#9375). A partir do v4.0.27, o CC Switch grava o arquivo do diretório do modelo como um caminho absoluto do Windows no config.toml. O Codex no WSL não consegue ler esse caminho e os três modos de conexão direta, roteamento e agregação são afetados. Agora no Windows, a versão desktop do Codex permitiu a mudança de gravação apenas do nome do arquivo ao executar o Codex no WSL, que será corrigido automaticamente na próxima vez que for gravado.
  • Nova rota de conversação do Codex para conectar respostas nativas de terceiros upstream Times 400 (#9328, relacionado #7074, #9379). A nova versão desktop do Codex trará resultados da ferramenta de contexto de página sem call_id em novas conversas, assim como os recibos para automação e envio de tarefas cruzadas, e upstreams com validação rigorosa rejeitarão toda a solicitação. No passado, ele era reescrito apenas para xAI, mas agora todas as respostas nativas não oficiais do upstream são reescritas em uma mensagem do usuário e o conteúdo é preservado. Assinaturas oficiais e resultados de ferramentas com call_id não são afetados.
  • Quando o Codex é conectado ao upstream do formato Antrópico através do roteador, a resposta longa é truncada e "Resposta incompleta retornada, motivo: max_output_tokens" é relatado. O mesmo se aplica à nova tentativa. As solicitações do Codex sem limite de saída eram emitidas anteriormente como 8192, e pensando que também conta, as chamadas de ferramentas que gravam um arquivo inteiro de uma vez serão esgotadas. O padrão agora é 32.000. Quando o limite de saída upstream for menor, ele reportará 400. Você pode preencher o valor que ele suporta nos "tokens de saída máxima" do fornecedor.
  • O cartão oficial do Codex não pode obter a lista de modelos da própria conta no modo de roteamento: o Codex só pode usar sua própria lista, que não possui modelos específicos da conta; após abrir o Daybreak na versão desktop do Codex, todos os modelos oficiais ficam cinza. Agora, quando o roteador estiver usando o cartão oficial e "Suspender o uso do login oficial" não estiver ativado, o roteador entregará a lista oficial de modelos ao Codex como está. Provedores terceirizados não encaminham.
  • Quando Claude Code se conecta ao modelo DeepSeek no Mistral via roteamento, cada rodada após a ferramenta ser chamada reporta 422 (#9385, #9388).
  • O cartão Claude Code só pode ser utilizado através de roteamento. Após clicar em "Abrir Terminal", Claude Code solicita "Não logado" para cada frase e a solicitação não é enviada. As credenciais para cartões como GitHub Copilot, Codex OAuth e xAI OAuth são fornecidas por roteamento. Cartões em formatos não antrópicos devem ser convertidos para formato por roteamento, e o terminal se conecta diretamente ao endereço do cartão e não pode ser utilizado. Agora o botão “Abrir Terminal” deste tipo de placa está esmaecido e indica que é necessário ativar o roteamento e executar o cliente diretamente no terminal. Este tipo de cartão na página do Codex também foi alterado de um botão oculto para também esmaecido.
  • O limite exibido no cartão oficial do Claude pode ser o de outra conta: Após a alteração do login padrão desta máquina para outra conta, o cartão que está sendo utilizado irá ler o limite da conta de login padrão. Agora será confirmado que o login padrão pertence a esta conta.
  • Cota de antigravidade não corresponde a agy /usage; tanto o Google AI Ultra 5x quanto o 20x exibem apenas "Google AI Ultra" (#9317, #9319).

cc-switch v4.0.29

Highlights

  • GitHub Copilot CLI becomes a managed app (#8753) — Two card types: official cards use Copilot CLI's own GitHub login and write no files; BYOK cards write into Copilot's own $COPILOT_HOME/providers.json (requested in #5768). The key architectural point: BYOK requests go straight from copilot to the provider via /model, bypassing CC Switch routing entirely, and work without a GitHub login. For adopters this is the first app whose config lives in the client rather than the switcher — expect to manage it from copilot itself.
  • BYOK safety rules and Copilot tooling — A malformed providers.json prevents Copilot from starting, so CC Switch validates the whole file before writing, touches only its own entry, and preserves other entries and ordering; the provider holding the current default model can't be removed until you switch away with /model. Presets are inherited from Pi. MCP servers, Skills, prompts, session resume and usage import are wired up, and one-click import links accept bearerToken while preserving model IDs — useful for migrating an existing Copilot setup.
  • Codex routing: 400s on new conversations and truncated long answers — Tool results without call_id (new-chat page context, automation receipts) are now rewritten as a user message for all non-official native Responses upstreams, not just xAI (#9328, #7074, #9379); official subscriptions and call_id-bearing results are untouched. Separately, routed requests to Anthropic-format upstreams now default to 32,000 output tokens instead of 8,192 (thinking counts toward the cap). Watch this: if an upstream's own limit is lower, set the provider's "max output tokens" or you'll trade truncation for a 400.
  • Codex WSL paths and account model lists — Since v4.0.27 CC Switch wrote Windows absolute paths for model directory files into config.toml; Codex under WSL couldn't read them and third-party providers failed with "No such file or directory" across direct, route and aggregate modes (#9375). The fix writes just the filename when WSL execution is enabled and self-corrects on the next write. Routing also now passes the official account's own model list through when the official card is active and "pause official login" is off — previously Daybreak greyed out every official model.
  • Claude Code routing and credential correctness — Fixes a 422 on every turn after a tool call when routing to DeepSeek models on Mistral (#9385, #9388), and stops the official card from showing another account's quota by verifying the default login belongs to that card. Route-only cards (Copilot, Codex OAuth, xAI OAuth, non-Anthropic formats) now grey out "Open terminal" instead of launching a session that reports "Not logged in" — if you used that button for these cards, run the client with routing enabled instead.
  • Seven languages at parity, clearer empty-model hints — Korean (#8794) and Russian (#7788) join the UI; Turkish, Korean and Russian are no longer partial translations with English fallbacks, all seven locales are maintained together, and KRW is added with automatic FX rates. Caveat: the post-upgrade summary still ships only in Simplified/Traditional Chinese, English and Japanese. An empty Copilot model list now explains a likely missing Copilot Pro subscription and suggests gpt-4.1/gpt-4o (#5500) rather than a generic "no models found".
  • No breaking changes.

CC Switch v4.0.29

本版本新增受管应用 GitHub Copilot CLI：自带 Key 的供应商会写进 Copilot 自己的 providers.json，在 copilot 里用 /model 就能和官方模型一起选，不用经过 CC Switch。界面新增韩语和俄语，七种语言从此同步维护，不再有缺的地方显示英文。

另外修复了 Windows 上 Codex 桌面版在 WSL 里运行 Codex 时，用第三方供应商启动就报错；Codex 新对话经路由连第三方原生 Responses 上游报 400；Codex 经路由连 Anthropic 格式上游时，长回答被 8192 的输出上限截断；Codex 官方卡在路由模式下拿不到账号自己的模型列表等问题。

新增

GitHub Copilot CLI

GitHub Copilot CLI（copilot）成为新的受管应用（#8753，需求见 #5768）。供应商卡片分两种：

  • 官方登录：用 Copilot CLI 自己的 GitHub 登录，不写任何文件。「打开终端」以卡片上的模型和推理强度启动 copilot；卡片绑定了授权中心的 GitHub 账号时，用这个账号启动。卡片上显示该账号的 Copilot 额度。
  • 自带 Key 的供应商：点「添加」后写进 Copilot 自己的 providers.json（$COPILOT_HOME/providers.json）。之后在本机任何地方启动 copilot，都能在 /model 里和官方模型并列选到「卡片标识/模型」，请求直接发给供应商，不经过 CC Switch 的路由。不登录 GitHub 也能用。
    • CC Switch 只改这一家自己的条目，文件里的其他条目（Copilot 自己也会写这个文件）和顺序原样保留。providers.json 写坏了 Copilot 会起不来，所以写入前会按 Copilot 的规则把整份文件校验一遍，例如模型的最大输出不能占满整个上下文窗口。
    • Copilot 当前默认模型所在的那一家标为默认，不能移除或删除。要换，先在 copilot 里用 /model 换成别家的模型。
    • 卡片上的终端按钮要添加之后才能用，启动时直接选中这张卡的第一个模型。
    • 预设沿用 Pi 的供应商预设。

此外还支持：

  • MCP、Skills、提示词：同步到 Copilot 的 mcp-config.json、Skills 目录和指令文件。
  • 会话管理：列出 Copilot 会话，可以在终端里恢复。
  • 用量统计：从 Copilot 的会话日志导入用量；自带 Key 的供应商按会话里选中的卡片记账。
  • 一键导入链接：可以导入 Copilot 供应商，认得 providers.json 写法，支持 bearerToken，链接里的模型 ID 全部保留。

韩语、俄语界面，七种语言同步维护

  • 韩语（#8794，需求见 #2704）和俄语（#7788，需求见 #6010）：首次启动按系统语言自动选择，托盘菜单和快捷面板也已翻译。用量统计的币种新增韩元（KRW），支持自动获取汇率。
  • 土耳其语、韩语、俄语不再是「社区翻译、缺的地方显示英文」：界面上的每一句话，中文简体、中文繁体、English、日本語、한국어、Türkçe、Русский 七种语言都有，之后新增和修改文案也会七种语言一起改。
  • 升级后弹出的更新摘要暂时只有中文简体、中文繁体、英文和日文，其他语言显示英文。

变更

  • Copilot 获取模型列表为空时说明原因（#5500）：Copilot Free 账号能拿到模型，但没有一个可以在模型选择器里用，以前只提示没有找到模型。现在会提示这个账号可能没有开通 Copilot Pro；Claude Code 和 Claude Desktop 的表单还会提示可以手动填写 gpt-4.1 或 gpt-4o。账号有模型、但都不支持当前选择的上游格式时，Codex 表单会单独说明。

修复

  • Windows 上 Codex 桌面版在 WSL 里运行 Codex 时，用第三方供应商一启动就报「No such file or directory (os error 2)」（#9375）。v4.0.27 起，CC Switch 在 config.toml 里把模型目录文件写成 Windows 绝对路径，WSL 里的 Codex 读不懂这个路径，直连、路由、聚合三种模式都受影响。现在在 Windows 上、Codex 桌面版开启了在 WSL 中运行 Codex 时，改回只写文件名，下次写入时自动改正。
  • Codex 新对话经路由连第三方原生 Responses 上游时报 400（#9328，相关 #7074、#9379）。新版 Codex 桌面版会在新对话里带上没有 call_id 的页面上下文工具结果，自动化和跨任务派发的回执也是这样，校验严格的上游会拒绝整个请求。以前只对 xAI 改写，现在对所有非官方的原生 Responses 上游都改写成一条用户消息，内容保留。官方订阅和带 call_id 的工具结果不受影响。
  • Codex 经路由连 Anthropic 格式上游时，长回答被截断，报「Incomplete response returned, reason: max_output_tokens」，重试也一样。Codex 请求不带输出上限，以前按 8192 发出，思考也算在内，一次写一整个文件的工具调用就会用完。现在默认改为 32000。上游的输出上限更低时会报 400，可以在供应商的「最大输出 tokens」里填它支持的值。
  • Codex 官方卡在路由模式下拿不到账号自己的模型列表：Codex 只能用它自带的列表，缺少账号专属的模型；Codex 桌面版打开 Daybreak 后，官方模型全部变灰。现在路由正在用官方卡、且没有打开「暂停使用官方登录」时，路由会把官方的模型列表原样交给 Codex。第三方供应商不转发。
  • Claude Code 经路由连 Mistral 上的 DeepSeek 模型时，工具调用之后的每一轮都报 422（#9385、#9388）。
  • 只能经路由使用的 Claude Code 卡片，点「打开终端」后 Claude Code 每句话都提示未登录（「Not logged in」），请求根本没发出去。GitHub Copilot、Codex OAuth、xAI OAuth 这类卡片的凭据由路由提供，非 Anthropic 格式的卡片要靠路由转换格式，终端直连卡片地址用不了。现在这类卡片的「打开终端」按钮变灰，并说明要开启路由后在终端里直接运行客户端。Codex 页面上这类卡片也从隐藏按钮改为同样变灰。
  • Claude 官方卡显示的额度可能是另一个账号的：本机默认登录换成别的账号后，正在用的那张卡会读到默认登录那个账号的额度。现在会先确认默认登录属于这个账号。
  • Antigravity 的额度和 agy /usage 对不上；Google AI Ultra 5x 和 20x 都只显示「Google AI Ultra」（#9317、#9319）。
