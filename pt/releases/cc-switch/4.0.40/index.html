Chave CC v4.0.40

Esta versão permite que o cartão oficial do Grok Build seja vinculado à conta xAI no centro de autorização e pode ser alternado entre várias contas Grok, como os cartões oficiais Claude e Codex. Página de plug-in suporta Antigravidade CLI; Estatísticas de uso adicionou taxa de acerto de cache à lista de fornecedores e modelos; Xiaomi MiMo possui consulta integrada de saldo e limite de plano de token; o cartão da conta na central de autorização segue a ordem e as configurações ocultas do aplicativo da barra lateral. Esta versão também fortalece as verificações de segurança de MCP de importação de link direto, scripts de uso, importação de SQL e endereços de escuta não nativos, e melhora a velocidade do banco de dados, roteamento local, sincronização de uso, pesquisa de sessão e página do aplicativo. Além disso, o uso do agente principal do Kimi Code Desktop não é contabilizado; a velocidade de saída da antigravidade é falsamente alta a partir de 4.0.38; a sessão Antigravidade no Código T3 e o ACP rodando sozinhos não podem ser vistos; a resposta oficial do Mistral API fica vazia após o início do pensamento; As respostas nativas do Kimi sempre reportam 400 depois que a ferramenta de visualização paralela é chamada; Os pontos da conta corporativa do WorkBuddy são exibidos como esgotados; não pode ser visto na bandeja A cota xAI e a conta oficial são exibidas como nomes de domínio de sites; habilidades duplicadas aparecem na “Descoberta” da página Habilidades; a página "Aplicativo" não exibe o status da instalação até que a versão seja verificada. Adicionar

O cartão oficial da Grok está vinculado à conta xAI

A forma oficial Grok do Grok Build adicionou um "método de login" (#9321, feche #8599). Você pode selecionar a conta xAI no centro de autorização, adicionar ou gerenciar a conta xAI ou "fazer login com Grok CLI". O uso é o mesmo dos cartões oficiais de Claude e Codex.

  • Cada conta vinculada é um cartão separado. Com o número da conta no nome, você pode adicionar quantos cartões quiser; aqueles que não estão vinculados a uma conta ainda terão o mesmo cartão fixo.
  • Ao mudar para o cartão com uma conta vinculada a ele, o CC Switch irá primeiro atualizar o login desta conta e, em seguida, gravá-lo em ~/.grok/auth.json do Grok CLI, e outros conteúdos do arquivo não serão alterados. Grok CLI não é gravado quando esta conta já está logada; quando a rede falha temporariamente, ele solicita que você tente novamente mais tarde. Quando a conta é realmente inválida, ele solicita que você vá ao centro de autorização para fazer login novamente.
  • Antes de alterar o número, o número atualmente logado pelo Grok CLI será coletado na central de autorização; ao voltar para o cartão "Login com Grok CLI", ele será restaurado para o número anterior à primeira alteração de número.
  • Ao excluir a conta na central de autorização, se Grok CLI estiver usando CC Switch para fazer login nesta conta, o login original será restaurado. Se a conta original desaparecer, saia.
  • Para cartões vinculados a um número de conta, os limites do cartão, utilização e palete são todos verificados de acordo com esse número. Quando o login do Grok CLI expirar para um cartão sem conta, utilize a conta do mesmo usuário na central de autorização para verificar o limite.

Plug-in antigravidade CLI

A página "Plugins" suporta Antigravidade CLI (#9882, #9885). Assim como outros aplicativos, você pode chamar a linha de comando do próprio agy. Você pode navegar pelos plug-ins oficiais e de mercados parceiros em "Discover" para instalar, ativar, desativar, desinstalar e atualizar.

  • Antes de atualizar, compare o número da versão existente no mercado. Se for a versão mais recente, não a reinstale.
  • Quando o plug-in estiver ocupado por uma sessão do Antigravity ou serviço em segundo plano em execução, você será solicitado a fechá-lo primeiro e tentar novamente.
  • Os plug-ins instalados pelo antigo aplicativo Antigravity são colocados em um diretório com nome numérico. CC Switch não pode atualizá-los. Ele solicitará que você os desinstale e reinstale em “Discover”.

Estatísticas de uso: veja a taxa de acertos do cache por provedor e modelo

As listas de estatísticas de uso "Fornecedor" e "Modelo" adicionam uma coluna "Taxa de acerto" após os Tokens, para que você possa ver qual fornecedor e qual modelo não utilizou o cache. O algoritmo é igual à taxa de acertos no log de solicitação (acessos ao cache ÷ entradas armazenáveis ​​em cache). Os acessos ao cache e as entradas armazenáveis ​​em cache de cada linha somam o total na parte superior; linhas sem entradas armazenáveis ​​em cache exibem "—".

Saldo Xiaomi MiMo e limite do plano de token

O provedor do Xiaomi MiMo incorporou duas consultas oficiais (fechadas #9404), então você não precisa mais depender do script de uso de cookies do console:

  • Token Plan (Chave iniciada por tp-): Apresenta a cota utilizada e total, bem como o horário de término deste período.
  • Saldo (Tecla iniciada por sk-): Apresenta o saldo disponível (descontando a parte congelada). Um saldo de 0 não será considerado uma chave inválida.

O cartão do centro de autorização segue o aplicativo da barra lateral

Os cartões de conta na central de autorização são organizados na ordem dos aplicativos arrastados para a página "Aplicativos". O cartão só ficará oculto se todos os aplicativos que utilizam esta conta estiverem ocultos (as contas Copilot, ChatGPT, xAI também serão utilizadas por fornecedores de aplicativos como Claude Code); o cartão ignorado no formulário do fornecedor sempre será exibido.

Mudança

  • Banco de dados e roteamento local são mais rápidos (#9820, #9821): O banco de dados principal é alternado para o modo WAL, as filas de configuração, roteamento, preços e failover a serem lidas para cada solicitação de roteamento são alteradas para leitura do cache, as operações do banco de dados de roteamento são movidas para um thread separado, não ocupando mais o thread que processa a solicitação; o conteúdo da conversa é copiado menos uma vez ao encaminhar a solicitação e a filtragem de privacidade não é mais repetida para solicitações que não foram reescritas.
  • A sincronização de uso é mais rápida (#9817, #9818): Os logs de sessão de cada aplicação são verificados em paralelo; os scripts de uso são executados em threads separados, não retardando mais outras solicitações.
  • A pesquisa de conteúdo de conversa é mais rápida (#9827, #9896): A pesquisa de uma ou duas palavras não irá mais varrer o texto inteiro; quando a digitação continuar, a última pesquisa inacabada será cancelada. O formato do índice de pesquisa foi alterado e o índice será reconstruído para a primeira pesquisa após a atualização.
  • A página "Aplicativo" abre mais rápido (#9418, #9886, fechar #9884): Primeiramente exibe o grupo "Instalado/Não Instalado" de acordo com o caminho de instalação da máquina, sem esperar pela verificação de versão de cada ferramenta; as versões de cada ferramenta são verificadas ao mesmo tempo e cada ferramenta é exibida uma após a verificação.

Segurança

  • Deep link import MCP (#9831): A caixa de confirmação exibe todos os campos do servidor MCP (incluindo diretório de trabalho, cabeçalhos de solicitação, etc.), e os campos de alto risco são marcados em vermelho. Lerá as variáveis ​​de ambiente locais, executará comandos auxiliares, apontará o diretório de trabalho para o caminho de compartilhamento de rede ou o endereço de configuração não é http/https, recusará diretamente a importação.
  • Usage Script (#9829): As solicitações enviadas pelo script não seguem mais redirecionamentos e não podem ser enviadas para a porta de roteamento do próprio CC Switch. A resposta pode ler até 2 MiB; Chave, endereço e outras variáveis ​​preenchidas no script serão escapadas corretamente. O endereço de consulta de uso no link direto também será verificado. Se for uma intranet ou endereço local, uma caixa de confirmação será exibida.
  • Importação SQL (#9832): Ao importar backup SQL ou instantâneo de sincronização WebDAV/S3, a criação de gatilhos e visualizações não é permitida, o tamanho máximo do arquivo é 512 MiB e a execução é abortada após mais de 30 segundos.
  • Verificação de host para endereços de escuta não locais (#9833): quando o serviço de roteamento escuta 0.0.0.0/::, as solicitações da máquina local também devem passar na verificação de host para evitar a religação de DNS.

Correção

  • O uso do agente principal do Kimi Code Desktop não é contado (#9505, consulte #9498): Kimi Code Desktop 1.3.5 alterou o formato do log da sessão, o uso do agente principal foi ignorado e o modelo do subagente é exibido como unknown. Ambos os formatos agora podem ser lidos sem cálculos duplos; após a atualização, os logs antigos serão verificados novamente para compensar o uso e os modelos perdidos anteriormente.
  • A velocidade de saída da antigravidade é falsamente alta (#9858): A partir de 4.0.38, solicitações que foram consideradas por um longo tempo podem exibir dezenas de milhares de tok/s. O token de saída da Antigravidade contém pensamento oculto, e o tempo da primeira palavra também inclui o tempo de pensamento. Agora é calculado com base no tempo completo.
  • Sessões de antigravidade no Código T3 e ACP autônomo não são visíveis (#9857, consulte #9838): Essas sessões agora aparecerão na lista de sessões e nas estatísticas de uso. Não há comando de recuperação disponível para eles e eles não podem ser excluídos no CC Switch; a descrição adicionada pelo Código T3 fora da pergunta será removida e o título mostrará a pergunta original.
  • A resposta oficial do Mistral API está vazia depois que o pensamento é ativado (Veja #9902): O API oficial do Mistral (incluindo o modelo de terceiros que ele fornece) divide a resposta em pensamentos e fragmentos de texto e os retorna. A rota local não pode ser lida e a resposta está vazia ou não possui processo de pensamento. Ambos os fragmentos agora podem ser lidos sequencialmente; as solicitações para upstream permanecem inalteradas.
  • As respostas nativas de Kimi continuam relatando 400 depois de visualizar a imagem em paralelo (#8825, consulte #7504): Codex Desktop inserirá prompts entre os resultados de chamadas de ferramentas paralelas. Respostas nativas estritas, como o upstream de Kimi, descartarão os resultados que não seguem a chamada e 400 serão relatados em cada rodada após esta sessão. Agora vamos coletar todos os resultados e colocar o prompt de inserção.
  • Os pontos da conta corporativa do WorkBuddy são exibidos como usados (veja #9694): A conta corporativa é alterada para verificar o uso da empresa, mostrando o valor total, usado e tempo de expiração; quantidade ilimitada é exibida como "ilimitado, N usado". Quando o valor não é encontrado, a consulta falha e "esgotado (total 0)" não é mais exibido.
  • A cota xAI não é visível na bandeja (consulte #9899): provedores xAI OAuth no Codex e Claude Code (incluindo membros da agregação Codex) também exibem cotas na bandeja de acordo com a conta xAI vinculada. Quando não vinculado, é utilizada a conta padrão do centro de autorização, que é consistente com a placa de interface principal.
  • A conta oficial na bandeja é exibida como o nome de domínio do site (#9863): O cartão Codex oficial com a conta gerenciada está vinculado, bem como os cartões Codex OAuth, GitHub Copilot e xAI OAuth. O subtítulo da bandeja exibe a conta logada (as notas manuais têm prioridade). O cartão xAI OAuth na interface principal também exibe o número da conta; a bandeja será atualizada após fazer login na central de autorização, mudar a conta padrão, excluir ou sair.
  • Habilidades duplicadas aparecem em "Descobrir" na página Habilidades: Duas habilidades com o mesmo nome no último diretório do mesmo warehouse serão carregadas no mesmo diretório. "Discover" exibia originalmente duas linhas, mas agora apenas a mais próxima do diretório raiz do warehouse é exibida.
  • CLI que vem com OpenCode Desktop é solicitado a usar npm para atualizar (#9099): A fonte de instalação deste CLI é mostrada como OpenCode Desktop, e explica que ele é atualizado com o aplicativo Desktop e não é mais contabilizado em "todas as atualizações"; OpenCode instalado separadamente é atualizado normalmente.
  • Eventos de streaming próximos ao limite superior de 64 MiB são ignorados por engano (#9867): O limite superior do buffer adicionado por 4.0.39 é alterado para ser julgado com base em um único evento. Eventos normais que estejam próximos do limite superior não serão mais descartados junto com o próximo no mesmo bloco.

Instruções de atualização

  • Se o serviço de roteamento monitorar 0.0.0.0/:: e usar um nome de host personalizado (sem terminar com .local, .internal, .localhost) para acessar a rota nesta máquina, você receberá um 403 após a atualização. Você precisa preencher este nome de host no “Endereço de Conexão” da “Rota Local” (este endereço também será escrito na configuração de cada cliente). Outros dispositivos em LAN, WSL e Docker não são afetados.
  • O índice para pesquisa de conteúdo da sessão será reconstruído durante a primeira pesquisa após a atualização. Se houver muitas sessões, a primeira busca será mais lenta.

cc-switch v4.0.40

Highlights

  • Grok Official now supports xAI account switching — #9321 adds account-bound Grok cards that refresh credentials and write only the selected identity to ~/.grok/auth.json, preserving its other contents. Quotas follow the bound account, while deleting an account or returning to “Follow Grok CLI login” restores the previous CLI identity.

  • Antigravity CLI joins the plugin manager — #9882 and #9885 support discovering and managing official and partner-market plugins through agy. Updates skip current versions and require stopping active sessions; plugins installed by older Antigravity versions into numbered directories must be uninstalled and reinstalled because CC Switch cannot update them.

  • Quota diagnostics are more actionable — Supplier and model tables now expose cache-hit rate, making cache-unfriendly workloads visible. Xiaomi MiMo also gains built-in queries for tp- Token Plan usage and sk- balance, including frozen-fund adjustments, removing the need for cookie-scraping usage scripts.

  • Import and routing surfaces are hardened — #9831, #9829, and #9832 reject risky deep-link MCP configurations, restrict usage-script redirects and response size, and block SQL triggers/views with new size and execution-time limits. Migration: if routing listens on 0.0.0.0 or :: and local requests use a custom hostname, expect HTTP 403 until that hostname is added under Local Routing → Connection Address (#9833).

  • Routing, usage collection, and search are faster — WAL, cached request-path configuration, and dedicated database threads reduce routing contention (#9820, #9821); session logs are scanned in parallel, and usage scripts run off the request path. Migration: the search-index format changed, so the first search after upgrading rebuilds the index and may take longer for large histories (#9827).

  • Provider compatibility fixes prevent empty or stuck sessions — Mistral responses now preserve reasoning/body fragment order, and Kimi native Responses groups parallel image-tool results before intervening prompts to prevent subsequent turns from repeatedly returning HTTP 400 (#8825). Antigravity throughput is recalculated against full elapsed time so hidden thinking no longer inflates tok/s, while the 64 MiB streaming fix avoids dropping valid near-limit events (#9867).

CC Switch v4.0.40

本版本让 Grok Build 的官方卡可以绑定授权中心里的 xAI 账号，像 Claude、Codex 官方卡一样在多个 Grok 账号之间切换。插件页支持 Antigravity CLI；用量统计的供应商和模型列表加了缓存命中率；小米 MiMo 内置余额和 Token Plan 额度查询；授权中心的账号卡片跟随侧栏应用的顺序和隐藏设置。

本版本还加固了深链接导入 MCP、用量脚本、SQL 导入和非本机监听地址的安全检查，并提升了数据库、本地路由、用量同步、会话搜索和「应用」页的速度。另外修复了 Kimi Code Desktop 主 agent 的用量没统计；Antigravity 输出速度从 4.0.38 起虚高；T3 Code 和单独运行的 ACP 里的 Antigravity 会话看不到；Mistral 官方 API 开思考后回复为空；Kimi 原生 Responses 在并行看图工具调用后一直报 400；WorkBuddy 企业账号积分显示为已用完；托盘里看不到 xAI 额度、官方账号显示成网站域名；Skills 页的「发现」里出现重复的技能；「应用」页要等版本检查完才显示安装状态等问题。

新增

Grok 官方卡绑定 xAI 账号

Grok Build 的 Grok Official 表单加了「登录方式」（#9321，关闭 #8599），可以选授权中心里的 xAI 账号、添加或管理 xAI 账号，或者「跟随 Grok CLI 登录」，用法和 Claude、Codex 官方卡一样。

  • 每个绑定的账号是一张单独的卡，名字带上账号，可以加任意多张；不绑账号的仍是原来那张固定的卡。
  • 切到绑了账号的卡时，CC Switch 会先刷新这个号的登录，再把它写进 Grok CLI 的 ~/.grok/auth.json，文件里的其他内容不动。Grok CLI 已经登录着这个号时不写；网络暂时失败时提示稍后重试，账号确实失效才提示去授权中心重新登录。
  • 换号前，Grok CLI 当前登录的号会先收进授权中心；切回「跟随 Grok CLI 登录」的卡时，还原成第一次换号前的号。
  • 在授权中心删掉账号时，如果 Grok CLI 正在用的是 CC Switch 替这个号写的登录，会还原原来的登录，原来的号也没了就退出登录。
  • 绑了账号的卡，卡片、用量和托盘的额度都按这个号查。没绑账号的卡在 Grok CLI 的登录过期时，改用授权中心里同一个用户的账号查额度。

Antigravity CLI 插件

「插件」页支持 Antigravity CLI（#9882、#9885），和其他应用一样调用 agy 自己的命令行，可以在「发现」里浏览官方和合作伙伴市场的插件，安装、启用、停用、卸载和更新。

  • 更新前先比对市场上的版本号，已是最新就不重装。
  • 插件被正在运行的 Antigravity 会话或后台服务占用时，提示先关掉再重试。
  • 旧版 Antigravity 应用装的插件放在数字命名的目录里，CC Switch 无法替它更新，会提示卸载后在「发现」里重新安装。

用量统计：按供应商和模型看缓存命中率

用量统计的「供应商」和「模型」列表在 Tokens 后面加了「命中率」一列，能看出是哪家供应商、哪个模型没吃到缓存。算法和请求日志里的命中率一样（缓存命中 ÷ 可缓存输入），各行的缓存命中和可缓存输入加起来与顶部的总数一致；没有可缓存输入的行显示「—」。

小米 MiMo 余额和 Token Plan 额度

小米 MiMo 的供应商内置了两种官方查询（关闭 #9404），不用再靠抓控制台 Cookie 的用量脚本：

  • Token Plan（tp- 开头的 Key）：显示已用和总额度，以及本期结束时间。
  • 余额（sk- 开头的 Key）：显示可用余额（扣除冻结部分），余额为 0 不会被当成 Key 无效。

授权中心卡片跟随侧栏应用

授权中心的账号卡片按「应用」页里拖动的应用顺序排列。只有用到这个账号的应用全都隐藏了，卡片才隐藏（Copilot、ChatGPT、xAI 账号还会被 Claude Code 等应用的供应商用到）；从供应商表单跳过来的那张卡总是显示。

新增预设

新增 StringAI。

变更

  • 数据库与本地路由更快（#9820、#9821）：主数据库改用 WAL 模式，路由每次请求要读的配置、路由、定价和故障转移队列改从缓存读，路由的数据库操作移到单独的线程，不再占住处理请求的线程；转发请求时少复制一次对话内容，没有改写过的请求不再重复跑隐私过滤。
  • 用量同步更快（#9817、#9818）：各应用的会话日志并行扫描；用量脚本在单独的线程里运行，不再拖慢其他请求。
  • 会话内容搜索更快（#9827、#9896）：一两个字的搜索不再扫描全部正文；继续输入时，上一次还没完成的搜索会被取消。搜索索引格式有变，升级后第一次搜索会重建索引。
  • 「应用」页打开更快（#9418、#9886，关闭 #9884）：先按本机的安装路径显示「已安装 / 未安装」分组，不用等每个工具的版本检查；各工具的版本同时检查，查完一个显示一个。

安全

  • 深链接导入 MCP（#9831）：确认框显示 MCP 服务器的全部字段（包括工作目录、请求头等），高危字段标红提示。会读取本机环境变量、执行辅助命令、把工作目录指向网络共享路径，或地址不是 http / https 的配置，直接拒绝导入。
  • 用量脚本（#9829）：脚本发出的请求不再跟随重定向，不能发给 CC Switch 自己的路由端口，响应最多读 2 MiB；填进脚本的 Key、地址等变量会正确转义。深链接里的用量查询地址也会检查，是内网或本机地址时确认框会提示。
  • SQL 导入（#9832）：导入 SQL 备份或 WebDAV / S3 同步快照时，不允许创建触发器和视图，文件最大 512 MiB，执行超过 30 秒即中止。
  • 非本机监听地址的 Host 检查（#9833）：路由服务监听 0.0.0.0 / :: 时，来自本机的请求也要通过防 DNS 重绑定的 Host 检查。

修复

  • Kimi Code Desktop 主 agent 的用量没统计（#9505，见 #9498）：Kimi Code Desktop 1.3.5 换了会话日志格式，主 agent 的用量被跳过，子 agent 的模型显示为 unknown。现在两种格式都能读，不会重复计算；升级后会重新扫描一次旧日志，补上以前漏掉的用量和模型。
  • Antigravity 输出速度虚高（#9858）：4.0.38 起，思考较久的请求能显示几万 tok/s。Antigravity 的输出 token 含隐藏的思考，首字时间也包含思考时长，现在改回按完整耗时计算。
  • T3 Code 和单独运行的 ACP 里的 Antigravity 会话看不到（#9857，见 #9838）：这些会话现在会出现在会话列表和用量统计里。它们没有可用的恢复命令，也不能在 CC Switch 里删除；T3 Code 加在提问外面的说明会去掉，标题显示原本的提问。
  • Mistral 官方 API 开思考后回复为空（见 #9902）：开了思考的 Mistral 官方 API（包括它提供的第三方模型）把回复拆成思考和正文两种片段返回，本地路由读不出来，回复为空或没有思考过程。现在两种片段都能按顺序读出；发给上游的请求不变。
  • Kimi 原生 Responses 在并行看图后一直报 400（#8825，见 #7504）：Codex Desktop 会在并行工具调用的结果之间插入提示，Kimi 这类严格的原生 Responses 上游会丢掉不紧跟调用的结果，这个会话之后每轮都报 400。现在先把这批结果收齐放在一起，再放插入的提示。
  • WorkBuddy 企业账号积分显示为已用完（见 #9694）：企业账号改查企业用量，显示总额度、已用和到期时间；不限量的显示「不限量，已用 N」，查不到额度时报查询失败，不再显示「已用完（共 0）」。
  • 托盘里看不到 xAI 额度（见 #9899）：Codex、Claude Code 里的 xAI OAuth 供应商（包括 Codex 聚合的成员）在托盘里也按绑定的 xAI 账号显示额度，没绑定时用授权中心的默认账号，和主界面卡片一致。
  • 托盘里官方账号显示成网站域名（#9863）：绑了托管账号的 Codex 官方卡，以及 Codex OAuth、GitHub Copilot、xAI OAuth 卡，托盘副标题显示登录的账号（手动备注优先）。主界面的 xAI OAuth 卡片也显示账号；在授权中心登录、切换默认账号、删除或退出登录后托盘会跟着更新。
  • Skills 页的「发现」里出现重复的技能：同一个仓库里末级目录同名的两个技能会装进同一个目录，「发现」里原来显示成两行，现在只显示离仓库根目录最近的那个。
  • OpenCode Desktop 自带的 CLI 被提示用 npm 升级（#9099）：这份 CLI 的安装来源显示为 OpenCode Desktop，并说明它随 Desktop 应用更新，不再计入「全部升级」；单独安装的 OpenCode 照常升级。
  • 快到 64 MiB 上限的流式事件被误跳过（#9867）：4.0.39 加的缓冲上限改成按单条事件判断，接近上限的正常事件不会再和同一块里的下一条一起被丢掉。

升级说明

  • 路由服务监听 0.0.0.0 / ::、又在本机用自定义主机名（不以 .local、.internal、.localhost 结尾）访问路由的，升级后会收到 403，需要在设置「本地路由」的「连接地址」里填上这个主机名（这个地址也会写进各客户端的配置）。局域网、WSL、Docker 里的其他设备不受影响。
  • 会话内容搜索的索引会在升级后第一次搜索时重建，会话多的话第一次会慢一些。
