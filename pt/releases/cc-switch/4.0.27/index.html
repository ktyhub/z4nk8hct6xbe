Chave CC v4.0.27

Esta versão permite que o gerenciamento de sessão pesquise o corpo da mensagem, adicione densidade de interface e configurações de escala de interface, tabelas de preços de modelos podem ser pesquisadas e fornecedores usados ​​​​pelo Grok Build também podem abrir o terminal. A página instalada de Skills foi redesenhada e os ícones dos fornecedores seguirão o tema claro e escuro. Além disso, o arquivo de configuração foi substituído por um arquivo normal ou falhou ao ser gravado quando era um soft link, o fornecedor ficou preso na recuperação do disjuntor até reiniciar após cancelar a solicitação, o modo de plano relatou um erro após o Codex definir permissões personalizadas, a habilidade de execução foi falsamente relatada como tendo uma atualização, o armazém de Skills mostrou 0 Skills, pi.exe de Python foi reconhecido como Pi no Windows, a sincronização de preço do modelo expirou, a janela não pôde ser arrastada ao abrir o caixa de diálogo, o menu do navegador apareceu ao clicar com o botão direito e problemas do Linux, como exibição anormal do painel de atalho. Para obter o conteúdo completo da atualização do 4.0, consulte Notas de versão do v4.0. Inglês → | Versão japonesa →

Adicionar

Pesquise o corpo da mensagem de uma conversa

No passado, a pesquisa na página de gerenciamento de sessões só encontrava o título, o diretório e o ID da sessão. Não foi possível encontrá-lo quando me lembrei do que havia falado, mas não consegui lembrar qual sessão era (#7896, #7420). Agora você pode abrir "Pesquisar texto da mensagem": abra-o no menu "⋯" no canto superior direito da página ou clique no botão diretamente no prompt quando a pesquisa não tiver resultados. Após a abertura, os resultados da pesquisa listarão os fragmentos do corpo do hit e quantas mensagens foram atingidas.

  • Desligado por padrão. Após a abertura, o CC Switch indexará localmente o corpo da mensagem e o progresso será exibido durante a criação. Neste momento, os resultados corporais podem não estar completos.
  • O índice é um arquivo local separado session-index.db, que não participa da sincronização ou backup na nuvem; desligar esta opção irá excluí-la.

Densidade e escala de interface

Dois novos itens foram adicionados em "Configurações → Geral → Aparência" (#9209):

  • Densidade da Interface: “Compacto” é o tamanho original e o valor padrão; "Confortável" é um tamanho de fonte maior e os botões e caixas de entrada são mais altos.
  • Zoom da interface: 90%, 100%, 110%, 125% quatro níveis, você também pode pressionar Ctrl (⌘ no macOS) mais +, - para ajustar, pressione Ctrl/⌘ mais 0 para restaurar. Ambas as configurações são salvas apenas localmente, assim como o tema. O painel de acesso à bandeja permanece compacto em tamanho.

A tabela de preços do modelo pode ser pesquisada

Uma caixa de pesquisa foi adicionada acima da tabela de preços do modelo para filtrar por ID ou nome do modelo (#9205). Pressionar Enter editará o primeiro resultado; quando não houver modelo correspondente, pressionar Enter adicionará um novo preço para o modelo inserido.

Grok Build Terminal aberto

O cartão de fornecedor do Grok Build também possui um botão "Abrir Terminal" (#9234). Grok CLI não pode permitir que apenas um terminal mude de fornecedor, portanto este botão só aparece no fornecedor que está sendo utilizado. O terminal aberto usa diretamente a configuração Grok gerenciada pelo CC Switch; --always-approve será adicionado ao ignorar a confirmação de permissão.

Mudança

  • Habilidades de reformatação de página instaladas (#9210):
    • A coluna do nome é fixada à esquerda e as colunas de cada aplicativo rolam horizontalmente abaixo dela quando a janela é estreita.
    • A filtragem de status e origem é movida para a mesma barra de ferramentas da página “Descobrir”, e as Habilidades não serão bloqueadas após serem selecionadas; as operações em lote retêm atualização, desinstalação e "ativação para"/"desativação" por aplicativo.
    • O link "N Atualizável" do cabeçalho foi removido e o número "Atualizar tudo" na barra de ferramentas já está escrito; clique na marca "Atualizável" em cada linha para atualizar esta habilidade.
    • O menu "..." de cada linha mantém documento aberto, diretório aberto e desinstalação; quando a escrita falha, a mensagem de erro é exibida na posição descrita.
  • Ícone do fornecedor segue tema (#8438): Removido o fundo branco fixo atrás do ícone do cartão. Os ícones escuros de cor única mudam com a cor do texto e podem ser vistos claramente no modo escuro; ícones multicoloridos com traços escuros, ícones de imagem e ícones que você carrega ainda terão um fundo claro no modo escuro.
  • Clicar com o botão direito não abre mais o menu do navegador (#8919, #8921): No passado, clicar com o botão direito na janela principal e no painel da bandeja abriria o próprio menu do navegador (no Windows, era "Voltar", "Recarregar", "Salvar como", "Imprimir", etc.). Não mais; caixas de entrada, editores de código e texto selecionado ainda podem ser clicados com o botão direito, copiados e colados.
  • O log do disjuntor indica qual fornecedor é (#9292): Todos os logs do disjuntor (CB-001 a CB-006) carregam "aplicativo: id do fornecedor"; quando o disjuntor rejeita um fornecedor, ele também grava uma linha FWD-004, indicando o nome do fornecedor, e não mais a ignora silenciosamente. Apenas os logs foram alterados, mas os comportamentos do roteamento e do disjuntor permanecem inalterados.
  • Predefinições: O modelo padrão das predefinições do Mistral AI foi alterado para mistral-large-4 (Mistral Medium 3.5 foi anunciado como obsoleto pela Mistral), e as predefinições do Mistral AI para Claude Code, Codex e Claude Desktop não estão mais ocultas. O pacote Mistral Vibe e o API compartilham a mesma cota. "Obter chave API" foi alterado para abrir a página chave do Vibe CLI, que está disponível gratuitamente, por assinatura e pré-pago; você também pode encontrá-lo pesquisando “Vibe” ao adicionar um fornecedor. Adicionados Genesis (#9269) e TokenPlus (#9296). Os fornecedores que já foram adicionados não são afetados.

Correção

  • Quando o arquivo de configuração for um soft link, a troca de provedores irá substituí-lo por um arquivo normal e um erro será relatado diretamente no Windows (#6764, #9283). Quando você usa a ferramenta dotfiles ou a pasta de sincronização para gerenciar arquivos ~/.claude/settings.json, ~/.codex/config.toml, opencode.json, etc., eles geralmente são links virtuais. No passado, o próprio link seria substituído durante a escrita. No macOS e no Linux, o link se transformou em um arquivo normal e foi desacoplado do arquivo original. No Windows, foi relatado um erro "falha na substituição atômica" (erro OS 1464). Agora o arquivo real apontado pelo link é gravado e o link permanece inalterado.
  • Após o cancelamento da solicitação no meio do caminho, o provedor pode estar em recuperação do disjuntor até ser reiniciado (#7206, #9292). Durante o período de recuperação do disjuntor, o disjuntor passa apenas em uma solicitação de detecção; se o cliente for desconectado antes da conclusão da solicitação, a cota não será devolvida e todas as solicitações subsequentes a este fornecedor serão rejeitadas. Agora, não importa como termine a solicitação, a vaga será devolvida.
  • Depois de definir permissões personalizadas no Codex, use o modo de plano para relatar erros (#7349, #7294). O Codex mais recente exige que model_catalog_json seja um caminho absoluto ao ler permissões personalizadas. No passado, CC Switch escrevia o nome do arquivo e o Codex informava AbsolutePathBuf deserialized without a base path. Agora escreva o caminho absoluto; ainda escreva o nome do arquivo quando o diretório de configuração estiver em WSL.
  • Habilidades que foram executadas uma vez são exibidas como "atualizáveis", e clicar em atualizar cobrirá todo o diretório (#7780, #7772). Os arquivos __pycache__ e .pyc gerados quando o Python é executado são incluídos no conteúdo da Skill. Esses arquivos agora são ignorados durante a verificação de atualizações; registros antigos retirados de versões anteriores serão convertidos automaticamente e não resultarão em falsos positivos.
  • O armazém de habilidades mostra "0 habilidades reconhecidas" (#9273). A filial do armazém adicionada durante a importação é registrada como HEAD, ou quando a filial padrão do armazém é master mas está atribuída a principal, a quantidade é sempre 0. Agora a contagem é baseada nas filiais efetivamente lidas; o warehouse que não consegue ler indicará "falha na leitura" e o motivo. Após importar a Skill e adicionar um novo warehouse, ela será lida novamente na próxima vez que for aberta.
  • O Windows trata pi.exe no pacote Python como Pi (#9267). Existe um pacote pi não relacionado no PyPI que instalará o Scripts\pi.exe e a página do aplicativo o exibirá como "incapaz de executar". Pi só é lançado via npm e agora pi.exe no diretório Python Scripts não é mais reconhecido como Pi.
  • Falha na sincronização do preço do modelo, solicitando apenas error decoding response body (#9262). O download da lista de preços de models.dev expira no meio de uma rede ou proxy lento. O tempo limite agora foi reduzido de 15 para 60 segundos, e o verdadeiro motivo será escrito no status de sincronização quando ela falhar.
  • Ao adicionar o fornecedor DeepSeek Harness, ele apenas solicita Invalid DeepSeek Harness profile YAML, não sei qual arquivo é (#9297). Agora o relatório de erros escreverá o caminho do arquivo de configuração do erro e o erro específico do YAML, tornando mais fácil encontrar o arquivo para reparar.
  • O teste de conectividade determina que a estação de redirecionamento está inacessível (#9253, #5747). Alguns gateways redirecionam entre si entre /v1 e /v1/. Agora estamos testando se eles podem se conectar mesmo que recebam o redirecionamento.
  • A janela não pode ser arrastada ao abrir uma caixa de diálogo (#9140). As janelas agora podem ser arrastadas enquanto uma caixa de diálogo está aberta; os botões minimizar, maximizar e fechar ainda estão disponíveis ao usar botões de janela no aplicativo no Windows e Linux.
  • Exceção de exibição do painel de atalhos do Linux: O painel e a janela reabertos no modo leve são renderizados incorretamente (#9233, #9216) e parte do painel é cortada quando o zoom de exibição é definido (#9287, #8556). Painéis no Linux alterados para fundo opaco.
  • Quando o nome do fornecedor começa com caracteres como emoji ou é precedido por um espaço, o primeiro caractere exibido em um cartão sem ícone fica ilegível ou em branco (#8139).
  • O aviso de risco do link de importação com um clique perde o endereço IPv6 com endereço IPv4 incorporado (#8127). Este tipo de endereço agora é julgado de acordo com o endereço IPv4 que ele realmente aponta, seja na máquina local ou na intranet.

cc-switch v4.0.27

Highlights

  • Full-text session search is opt-in — Search can now match message bodies, not just titles, directories, and IDs (#7896). CC Switch builds a separate local session-index.db; it is excluded from cloud sync and backups, deleted when the feature is disabled, and results may be incomplete during initial indexing—important if you rely on cross-device session history.
  • Configuration writes preserve symlinks — Provider switches now write through to the target of linked files such as ~/.claude/settings.json, ~/.codex/config.toml, and opencode.json instead of replacing the link (#9283). This keeps dotfiles and synced configurations connected and fixes Windows atomic-replacement error 1464; existing links need no migration.
  • Two reliability blockers are fixed — Codex custom-permission configurations now use an absolute model_catalog_json path, resolving plan-mode deserialization failures (#7349); WSL configuration directories intentionally still use a filename. Canceled requests now return circuit-breaker probe slots, preventing providers from remaining stuck in recovery until restart (#9292).
  • Skill updates no longer chase runtime artifacts — Update checks ignore __pycache__ and .pyc, preventing used Python Skills from being falsely marked stale and then overwritten during updates (#7780); old records are converted automatically. Repository discovery now counts the branch actually read and reports failures with reasons instead of showing “0 skills” (#9273).
  • Provider setup gains safer defaults and Grok terminal access — New Mistral AI presets default to mistral-large-4 because Medium 3.5 is deprecated; existing providers are unchanged. Grok Build’s terminal action appears only on the active provider because Grok CLI cannot switch providers per terminal; it uses CC Switch’s managed configuration and adds --always-approve when permission confirmation is skipped (#9234).
  • Breaking changes — None.

CC Switch v4.0.27

本版本让会话管理可以搜索消息正文，新增界面密度和界面缩放设置，模型定价表可以搜索，Grok Build 正在使用的供应商也能打开终端了。Skills 的已安装页重新排了版，供应商图标会跟随深浅色主题。另外修复了配置文件是软链接时被替换成普通文件或写入失败、取消请求后供应商卡在熔断恢复中直到重启、Codex 设置了自定义权限后 plan 模式报错、运行过的 Skill 被误报有更新、Skills 仓库显示 0 个 Skill、Windows 上把 Python 的 pi.exe 认成 Pi、模型价格同步超时、打开对话框时窗口拖不动、右键弹出浏览器菜单，以及 Linux 快捷面板显示异常等问题。4.0 完整的更新内容请见 v4.0 发布说明。

新增

搜索会话的消息正文

以前会话管理页的搜索只能找标题、目录和会话 ID，记得聊过什么、却想不起是哪个会话时找不到（#7896、#7420）。

现在可以打开「搜索消息正文」：在页面右上角的「⋯」菜单里打开，或者搜索没有结果时直接点提示里的按钮。打开后，搜索结果会列出命中的正文片段和命中了几条消息。

  • 默认关闭。打开后 CC Switch 会在本地为消息正文建立索引，建立期间会显示进度，这时正文结果可能还不全。
  • 索引是单独的本地文件 session-index.db，不参与云同步，也不进备份；关闭这个开关会删除它。

界面密度和界面缩放

「设置 → 通用 → 外观」里新增两项（#9209）：

  • 界面密度：「紧凑」就是原来的尺寸，也是默认值；「舒适」的字号大一档，按钮和输入框更高一些。
  • 界面缩放：90%、100%、110%、125% 四档，也可以按 Ctrl（macOS 上是 ⌘）加 +、- 调整，按 Ctrl/⌘ 加 0 复原。

两项设置只保存在本机，和主题一样。托盘快捷面板始终保持紧凑尺寸。

模型定价表可以搜索

模型定价表上方加了搜索框，按模型 ID 或名称筛选（#9205）。按回车会编辑第一个结果；没有匹配的模型时，回车会为输入的模型新增定价。

Grok Build 打开终端

Grok Build 的供应商卡片也有「打开终端」按钮了（#9234）。Grok CLI 不能只让某一个终端换供应商，所以这个按钮只出现在正在使用的供应商上，打开的终端直接用 CC Switch 管理的这份 Grok 配置；选择跳过权限确认时会加上 --always-approve。

变更

  • Skills 已安装页重新排版（#9210）：
    • 名称列固定在左侧，窗口窄时各应用的列在它下面横向滚动。
    • 状态和来源筛选移到和「发现」页一样的工具栏里，选中 Skill 后也不会被挡住；批量操作保留更新、卸载和按应用「启用到」/「停用」。
    • 去掉了页头的「N 个可更新」链接，工具栏的「全部更新」已经写了数量；点每行的「可更新」标记就能更新这个 Skill。
    • 每行的「…」菜单保留打开文档、打开目录和卸载；写入失败时，错误信息显示在描述的位置。
  • 供应商图标跟随主题（#8438）：去掉了卡片图标后面固定的白底。单色的深色图标会跟着文字颜色变化，深色模式下也看得清；带深色笔画的多色图标、图片图标和你上传的图标在深色模式下仍然带浅色底。
  • 右键不再弹出浏览器菜单（#8919、#8921）：以前在主窗口和托盘面板里点右键，会弹出浏览器自带的菜单（Windows 上是「后退」「重新加载」「另存为」「打印」等）。现在不会了；输入框、代码编辑器和选中的文字仍然可以右键复制粘贴。
  • 熔断日志写明是哪家供应商（#9292）：熔断器的日志（CB-001 到 CB-006）都带上了「应用:供应商 id」；熔断器拒绝某家供应商时也会记一行 FWD-004，写明供应商名称，不再悄悄跳过。只改了日志，路由和熔断行为不变。
  • 预设： Mistral AI 预设的默认模型改为 mistral-large-4（Mistral Medium 3.5 已被 Mistral 宣布弃用），Claude Code、Codex 和 Claude Desktop 的 Mistral AI 预设不再隐藏。Mistral Vibe 套餐和 API 共用额度，「获取 API Key」改为打开 Vibe CLI 的密钥页，免费、订阅和按量付费都能用；添加供应商时搜「Vibe」也能找到它。新增 Genesis（#9269）、TokenPlus（#9296）。已添加的供应商不受影响。

修复

  • 配置文件是软链接时，切换供应商会把它替换成普通文件，Windows 上直接报错（#6764、#9283）。用 dotfiles 工具或同步文件夹管理 ~/.claude/settings.json、~/.codex/config.toml、opencode.json 等文件时，它们通常是软链接。以前写入时会把链接本身替换掉，macOS 和 Linux 上链接变成普通文件、和原文件脱钩，Windows 上报错「原子替换失败」（os error 1464）。现在会写到链接指向的真实文件，链接保持不变。
  • 请求中途被取消后，供应商可能一直处在熔断恢复中，直到重启（#7206、#9292）。熔断恢复期间，熔断器只放一个探测请求过去；如果这个请求还没结束客户端就断开了，名额不会还回去，之后发给这家供应商的请求全被拒绝。现在无论请求怎么结束，名额都会还回去。
  • Codex 设置了自定义权限后，用 plan 模式报错（#7349、#7294）。较新的 Codex 读取自定义权限时要求 model_catalog_json 是绝对路径，以前 CC Switch 写的是文件名，Codex 报 AbsolutePathBuf deserialized without a base path。现在写成绝对路径；配置目录在 WSL 里时仍写文件名。
  • 运行过一次的 Skill 被显示为「可更新」，点更新会覆盖整个目录（#7780、#7772）。Python 运行时生成的 __pycache__ 和 .pyc 文件被算进了 Skill 的内容。现在检查更新时忽略这些文件；以前版本记下的旧记录会自动换算，不会因此误报。
  • Skills 仓库显示「识别到 0 个技能」（#9273）。导入时添加的仓库分支记为 HEAD，或者仓库默认分支是 master 却配成了 main 时，数量总是 0。现在按实际读取的分支计数；读取失败的仓库会写明「读取失败」和原因，导入 Skill 新增了仓库后，下次打开会重新读取。
  • Windows 上把 Python 包里的 pi.exe 当成 Pi（#9267）。PyPI 上有一个无关的 pi 包会装出 Scripts\pi.exe，应用页会把它显示为「无法运行」。Pi 只通过 npm 发布，现在 Python Scripts 目录里的 pi.exe 不再被识别为 Pi。
  • 模型价格同步失败，只提示 error decoding response body（#9262）。网络较慢或经代理时，从 models.dev 下载价格表会在读到一半时超时。现在超时时间从 15 秒放宽到 60 秒，失败时同步状态里会写出真正的原因。
  • 添加 DeepSeek Harness 供应商时只提示 Invalid DeepSeek Harness profile YAML，不知道是哪个文件（#9297）。现在报错会写出出错的配置文件路径和 YAML 的具体错误，方便找到文件修复。
  • 连通性测试把会重定向的中转站判为不通（#9253、#5747）。有的网关在 /v1 和 /v1/ 之间互相重定向，现在测试收到重定向就算连得上。
  • 打开对话框时窗口拖不动（#9140）。现在对话框打开时仍然可以拖动窗口；Windows 和 Linux 上使用应用内窗口按钮时，最小化、最大化和关闭按钮也照常可用。
  • Linux 快捷面板显示异常：轻量模式下重新打开的面板和窗口渲染出错（#9233、#9216），设置了显示缩放时面板被裁掉一部分（#9287、#8556）。Linux 上的面板改为不透明背景。
  • 供应商名称以 emoji 等字符开头、或前面带空格时，没有图标的卡片显示的首字是乱码或空白（#8139）。
  • 一键导入链接的风险提示漏判了内嵌 IPv4 地址的 IPv6 地址（#8127）。这类地址现在按它实际指向的 IPv4 地址判断是否为本机或内网。
