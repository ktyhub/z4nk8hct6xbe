Chave CC v4.0.34

Esta versão do repositório de habilidades suporta GitLab, Gitea e Forgejo (incluindo instâncias autoconstruídas e Codeberg), e você não pode mais adicionar repositórios apenas no GitHub. Agora você pode excluir diretamente a sessão do Antigravity CLI no gerenciamento de sessões; após ativar o download automático de atualizações, o download da nova versão começará imediatamente. Além disso, os modelos WorkBuddy adicionados manualmente podem definir a intensidade do pensamento, e a sincronização S3 também pode limpar configurações salvas localmente, como WebDAV. Além disso, o fornecedor “Get Model List” do Gemini CLI informou que a chave é inválida ou obtém uma lista vazia; o modelo GitHub Copilot no Codex é considerado como não suportando imagens; Alibaba Cloud OSS, Tencent Cloud COS e Huawei Cloud OBS não podem usar a sincronização S3; todo o upload da sincronização na nuvem falha quando há links inválidos no diretório Skills; Fable 5.2 é exibido como Fable 5 no modo de roteamento; Copilot A taxa de acertos de cache do modelo Gemini no Copilot é baixa; O Copilot tem problemas como falha na solicitação do modelo 1M Fable. Adicionar

Armazém de habilidades suporta GitLab, Gitea e Forgejo

"Management Skills Warehouse" costumava aceitar apenas o endereço de github.com, mas agora também pode adicionar armazéns públicos em GitLab, Gitea e Forgejo (para requisitos, consulte #1324, #4227), incluindo instâncias autoconstruídas e Codeberg:

  • Preencha owner/name e ainda processe como GitHub; ao preencher o endereço completo de outros sites, o CC Switch perguntará primeiro se o site é Gitea / Forgejo ou GitLab, e depois fará o download da forma correspondente. Portas personalizadas, agrupamento multinível de GitLab e endereços copiados na página Gitea podem ser usados.
  • Navegar por habilidades, instalar, verificar atualizações e links "Abrir Documento" irão para o site onde o repositório está localizado.
  • Apenas são suportados armazéns públicos e o endereço deve ser https. Gitee ainda não oferece suporte (sua interface de download requer um token).
  • O mesmo owner/name só pode ser mantido em um site. Adicionar um armazém com o mesmo nome a outro site substituirá o original.

Excluir sessão Antigravity CLI no gerenciamento de sessão

Anteriormente, as sessões de antigravidade só podiam ser excluídas em qualquer momento. Agora você pode excluir diretamente a sessão do Antigravity CLI no gerenciamento de sessões. Ao excluir, ele limpará o índice e o resumo da sessão, assim como o próprio agy. Ele não aparecerá novamente após reiniciar o agy.

  • A sessão não pode ser excluída enquanto estiver aberta. Feche-o primeiro.
  • As sessões do IDE Antigravity, assim como as sessões apenas com índices e sem registros de sessão, ainda precisam ser excluídas no Antigravity.

Comece a baixar automaticamente a nova versão imediatamente após descobri-la

Depois de ativar "Baixar atualizações automaticamente", era necessário aguardar uma verificação de antecedentes cerca de 1 minuto após a inicialização para iniciar o download. A página “Sobre” mostrava apenas que havia uma nova versão, que parecia que a mudança não estava em vigor. Agora o download começará assim que uma nova versão for encontrada durante a inicialização, e "Baixando a nova versão em segundo plano..." ou "Download concluído" será exibido no prompt da nova versão na página "Sobre". Os ícones, texto e botões da caixa de confirmação de instalação também foram realinhados.

Modelos adicionados manualmente do WorkBuddy podem definir a intensidade do pensamento

O modelo WorkBuddy padrão já foi capaz de selecionar a intensidade de pensamento no menu do modelo WorkBuddy, mas os modelos adicionados ou selecionados manualmente na lista de modelos possuem apenas a opção de pensamento (consulte #9599). Agora, depois de ativar o pensamento, você pode verificar a “intensidade do pensamento” a ser fornecida nos detalhes do modelo e definir “pode desligar o pensamento”; se nenhuma delas estiver marcada, apenas a opção de pensamento ainda será exibida. Os modelos obtidos na lista de modelos também serão preenchidos automaticamente com as resistências disponíveis de acordo com as regras do formulário Pi.

A sincronização S3 pode limpar a configuração local

As configurações de sincronização S3 têm uma nova "Configuração Limpa", que é igual ao WebDAV: exclua a área salva, bucket, chave, endpoint e diretório remoto da máquina local e interrompa a sincronização automática. Os dados carregados no bucket não serão excluídos.

Correção

  • O fornecedor "Obter lista de modelos" do Gemini CLI relata que a chave é inválida ou uma lista vazia é obtida ao usar um gateway compatível (consulte #8546): No passado, quando você pressionava Authorization: Bearer para enviar uma chave do AI Studio, o Google não a reconhecia; agora você o obtém através do método nativo do Gemini. A última versão foi reparada por Claude Code/Claude Desktop que escolheu o fornecedor do formato Gemini Native. Desta vez o reparo foi feito pelo próprio fornecedor da Gemini CLI.
  • Quando o GitHub Copilot é usado no Codex, os modelos que suportam imagens são tratados como apenas suporte a texto (#8027, consulte #7977): Ao obter a lista de modelos, a capacidade de entrada de imagem declarada pelo Copilot será lida. Para fornecedores Copilot que foram adicionados, obtenha novamente a lista de modelos e salve-a, depois saia completamente e reinicie o Codex.
  • Alibaba Cloud OSS, Tencent Cloud COS e Huawei Cloud OBS não podem usar a sincronização S3 e recebem um erro de chave de acesso (consulte #3996): Os novos buckets dessas três empresas rejeitam o antigo endereço baseado em caminho e agora usarão automaticamente o endereço que coloca o bucket no nome de domínio. Outros serviços como MinIO e R2 permanecem inalterados.
  • O provedor de serviços selecionado nas configurações de sincronização S3 não é lembrado após reabrir a página de configurações (#8644).
  • Quando há links inválidos no diretório Skills, todo o upload de sincronização na nuvem falha (consulte #9615): Links simbólicos inválidos ou conexões de diretório que não podem ser abertas no Windows, anteriormente causavam o cancelamento de todo o upload (o Windows relatou os error 5), e o download também falhou ao fazer backup de Skills existentes. Esses links agora são ignorados e um aviso é registrado.
  • Quando o upstream é Fable 5.2 no modo de roteamento, o /model de Claude Code ainda exibe Fable 5 (veja #9608): Fable 5.2 / 5.1 agora é escrito como o ID do modelo da versão correspondente, e Claude Desktop também é corrigido.
  • Quando o GitHub Copilot usa o modelo Gemini, a taxa de acerto do cache para sessões longas é de apenas cerca de 27% (consulte #9613): Claude Code anexa uma mensagem do sistema a cada rodada e o Copilot parece movê-los para o início da solicitação, fazendo com que o início de cada rodada de solicitações mude. Agora apenas para o modelo Gemini no Copilot, as mensagens do sistema no meio da sessão são enviadas como mensagens do usuário em suas posições originais, e o início não muda. Outros fornecedores e modelos não são afetados.
  • Quando o GitHub Copilot utiliza o modelo Fable e verifica 1M, a solicitação reporta 400: O Copilot não possui uma versão 1M do modelo Claude, e agora retornará o modelo normal da mesma versão. Após obter a lista de modelos do Copilot, os modelos que não possuem versão 1M (e o contexto é inferior a 1M) não podem ser verificados para 1M; aqueles que já foram verificados serão listados no prompt. Recomenda-se cancelar porque Claude Code ainda planejará o contexto de acordo com 1M.
  • Após alterar o diretório de configuração do Hermes nas configurações, o fornecedor não foi gravado no novo diretório (#9567).
  • Depois que ocorre um erro interno na detecção de conectividade do MCP ou no login do DeepSeek Harness, o CC Switch deve ser reiniciado antes de poder ser usado novamente (#9572).
  • Se o nome do fornecedor, endereço ou nome do modelo contiver a palavra mistral, será tratado como Mistral. Intensidade de pensamento (#9573): Agora apenas o endereço oficial api.mistral.ai é reconhecido.
  • Adicionado preço máximo do Qwen4 (#9612).

Instruções de atualização

A versão do banco de dados aumentou de 26 para 27, para que o armazém de habilidades registre o site em que está. O backup do banco de dados será feito automaticamente antes da atualização; se você reverter para a versão antiga após a atualização, a versão antiga avisará que a versão do banco de dados é muito nova e não pode ser aberta.

Graças a @SaladDay (configuração clara S3, sincronização de diretório de configuração Hermes, identificação Mistral, recuperação de bloqueio e organização de código de cerca de 45 PRs nesta versão: divisão de arquivos grandes, mesclagem de lógica duplicada, exclusão de código inútil e direitos autorais de interface, conclusão de testes de consistência de front-end e back-end), @paulo-t (armazém de habilidades GitLab), @EdwinDigital (recursos de imagem do modelo Copilot), @Dopetaiga (lembre-se do provedor de serviços S3), @kilingzhang, @xiaoyx1107 (endereço de nuvem doméstica S3), @yreidev (preço máximo do Qwen4). Obrigado a @xzxiaoshan, @mercutiojohn, @axlrose, @LeenixP, @loseheart-dev, @kebe7jun, @hurleychin por relatar problemas e fornecer informações de reprodução. cc-switch v4.0.34

Highlights

  • One-way database migration (v26 → v27) — The only breaking change: the schema now records which host each skill repo lives on. Upgrade auto-backs-up the DB, but rollback is off the table — older builds refuse to open the newer database ("version too new"). If you need an escape hatch, keep that pre-upgrade backup yourself before deploying.
  • Skill repos escape GitHub (#4227) — "Manage skill repos" now accepts GitLab, Gitea and Forgejo, including self-hosted instances and Codeberg. owner/name still means GitHub; a full URL triggers a one-time Gitea/Forgejo-vs-GitLab prompt, and custom ports, GitLab nested groups and URLs copied from Gitea all work — browsing, install, update checks and "open docs" follow the repo's host. Watch the limits: public repos and HTTPS only (no Gitee, whose download API needs a token), and since an owner/name may exist on only one host, adding the same name elsewhere silently replaces the original entry.
  • Copilot fixes demand a manual refresh and restart — Image-capable Copilot models were misdetected as text-only (#8027); existing providers must re-fetch and save the model list, then fully quit and restart Codex. The 1M checkbox is also now honest: Copilot has no 1M Claude variants, so requests fall back to the standard model, models without 1M can no longer be flagged, and any still-checked ones are listed for you to uncheck — Claude Code otherwise keeps planning against a 1M context it won't get.
  • Copilot + Gemini cache-hit rate repaired — Long sessions through GitHub Copilot were hitting ~27% cache because Claude Code appends a system message every turn, which Copilot hoists to the front and thereby changes the prompt prefix each round (#9613). The fix re-sends mid-session system messages in place as user messages, scoped to Gemini models on Copilot only — expect better cache reuse there, no behavior change elsewhere.
  • S3 sync: virtual-hosted addressing and local config clearing — Alibaba OSS, Tencent COS and Huawei OBS buckets reject legacy path-style URLs, so sync now uses bucket-in-domain addressing (#3996); MinIO/R2 are untouched. A new "Clear config" action (like WebDAV) wipes locally stored region, bucket, keys, endpoint and remote dir and stops auto-sync — uploaded data in the bucket is safe, and the chosen provider now survives reopening settings (#8644).
  • Smaller operational fixes worth noting — Gemini CLI providers now fetch models the native way instead of sending an Authorization: Bearer AI Studio key that Google rejects or that yields empty lists via gateways (#8546). Cloud sync skips dead symlinks / broken Windows junctions with a warning instead of aborting the whole upload (#9615). Auto-download now starts the moment an update is detected at launch rather than waiting for the ~1-minute background check. And Mistral thinking-strength handling now keys off the official api.mistral.ai host, so any provider/name/model containing the string "mistral" is no longer misclassified (#9573).

CC Switch v4.0.34

本版本的技能仓库支持 GitLab、Gitea 和 Forgejo（包括自建实例和 Codeberg），不再只能添加 GitHub 上的仓库。会话管理里现在可以直接删除 Antigravity CLI 的会话；开启自动下载更新后，发现新版本会立刻开始下载。另外，WorkBuddy 手动添加的模型可以设置思考强度，S3 同步也可以像 WebDAV 一样清除本机保存的配置。

另外修复了 Gemini CLI 的供应商「获取模型列表」报 Key 无效或拿到空列表；Codex 里的 GitHub Copilot 模型被当成不支持图片；阿里云 OSS、腾讯云 COS、华为云 OBS 用不了 S3 同步；Skills 目录里有失效链接时整个云同步上传失败；路由模式下 Fable 5.2 被显示成 Fable 5；Copilot 上的 Gemini 模型缓存命中率低；Copilot 上勾了 1M 的 Fable 模型请求失败等问题。

新增

技能仓库支持 GitLab、Gitea 和 Forgejo

「管理技能仓库」以前只接受 github.com 的地址，现在也能添加 GitLab、Gitea、Forgejo 上的公开仓库（需求见 #1324、#4227），包括自建实例和 Codeberg：

  • 填 owner/name 仍按 GitHub 处理；填其他站点的完整地址时，CC Switch 会先问一次这个站点是 Gitea / Forgejo 还是 GitLab，再按对应的方式下载。自定义端口、GitLab 的多级分组、Gitea 页面上复制的地址都能用。
  • 浏览技能、安装、检查更新和「打开文档」链接都会去仓库所在的站点。
  • 只支持公开仓库，地址必须是 https。Gitee 暂不支持（它的下载接口需要令牌）。
  • 同一个 owner/name 只能保留在一个站点上，在另一个站点添加同名仓库会替换原来的。

在会话管理里删除 Antigravity CLI 会话

以前 Antigravity 的会话只能在 agy 里删。现在可以在会话管理里直接删除 Antigravity CLI 的会话，删除时会和 agy 自己一样，把它的会话索引和摘要一并清理，重启 agy 后不会再冒出来。

  • 会话正在 agy 里打开时不能删，先在 agy 里关掉它。
  • Antigravity IDE 的会话，以及只有索引、没有会话记录的会话，仍然要在 Antigravity 里删除。

发现新版本后立刻开始自动下载

开启「自动下载更新」后，以前要等启动约 1 分钟后的后台检查才开始下载，「关于」页只显示有新版本，看起来像开关没生效。现在启动时一发现新版本就开始下载，「关于」页的新版本提示下会显示「正在后台下载新版本…」或「已下载完毕」。安装确认框的图标、文字和按钮也重新对齐了。

WorkBuddy 手动添加的模型可以设置思考强度

预设里的 WorkBuddy 模型早就能在 WorkBuddy 的模型菜单里选思考强度，手动添加或从模型列表选的模型却只有思考开关（见 #9599）。现在打开思考后，模型详情里可以勾选要提供的「思考强度」，并设置「可以关闭思考」；都不勾时仍只显示思考开关。从模型列表获取的模型也会按 Pi 表单的规则自动填上可用的强度。

S3 同步可以清除本机配置

S3 同步设置新增「清除配置」，和 WebDAV 一样：从本机删除保存的区域、存储桶、密钥、端点和远程目录，并停止自动同步，存储桶里已经上传的数据不会删除。

修复

  • Gemini CLI 的供应商「获取模型列表」报 Key 无效，或者用兼容网关时拿到空列表（见 #8546）：以前按 Authorization: Bearer 发 AI Studio Key，Google 不认；现在按 Gemini 原生方式获取。上一版修好的是 Claude Code / Claude Desktop 选 Gemini Native 格式的供应商，这次修的是 Gemini CLI 自己的供应商。
  • Codex 里用 GitHub Copilot 时，支持图片的模型被当成只支持文字（#8027，见 #7977）：获取模型列表时会读取 Copilot 声明的图片输入能力。已经添加的 Copilot 供应商，请重新获取模型列表并保存，再完全退出并重启 Codex。
  • 阿里云 OSS、腾讯云 COS、华为云 OBS 用不了 S3 同步，被提示 Access Key 错误（见 #3996）：这三家的新存储桶拒绝旧的路径式地址，现在会自动改用把存储桶放在域名里的地址。MinIO、R2 等其他服务不变。
  • S3 同步设置里选的服务商，重新打开设置页后没记住（#8644）。
  • Skills 目录里有失效的链接时，云同步整个上传失败（见 #9615）：失效的符号链接，或 Windows 上打不开的目录联接，以前会让上传整体中止（Windows 上报 os error 5），下载时也会在备份现有 Skills 这一步失败。现在跳过这类链接并记录警告。
  • 路由模式下上游是 Fable 5.2 时，Claude Code 的 /model 仍显示 Fable 5（见 #9608）：Fable 5.2 / 5.1 现在写成对应版本的模型 ID，Claude Desktop 同样修正。
  • 经 GitHub Copilot 用 Gemini 模型时，长会话的缓存命中率只有约 27%（见 #9613）：Claude Code 每一轮都会追加一条系统消息，Copilot 看起来会把它们都挪到请求开头，导致每轮请求的开头都变了。现在只对 Copilot 上的 Gemini 模型，把会话中途的系统消息按原位置作为用户消息发送，开头不再变化。其他供应商和模型不受影响。
  • 经 GitHub Copilot 用 Fable 模型并勾选 1M 时，请求报 400：Copilot 没有 1M 版本的 Claude 模型，现在会退回同版本的普通模型。获取过 Copilot 模型列表后，没有 1M 版本（上下文也不到 1M）的模型不能再勾 1M；已经勾了的会列在提示里，建议取消，因为 Claude Code 仍会按 1M 规划上下文。
  • 在设置里改了 Hermes 的配置目录后，供应商没有写进新目录（#9567）。
  • MCP 连通性检测或 DeepSeek Harness 登录出过一次内部错误后，要重启 CC Switch 才能再用（#9572）。
  • 供应商名称、地址或模型名里带 mistral 字样，就会被当成 Mistral 处理思考强度（#9573）：现在只认官方地址 api.mistral.ai。
  • 新增 Qwen4 Max 的价格（#9612）。

升级说明

数据库版本从 26 升到 27，为技能仓库记录它所在的站点。升级前会自动备份数据库；升级后再退回旧版本，旧版本会提示数据库版本过新，打不开。
