DeepSpeed v0.19.2

Highlights

  • Multi-backward gradient control (#7992) — New engine.coalesce_grad_reduction() lets ZeRO 1/2/3 defer and combine gradient reductions across several backward() calls into one step. This targets training loops that split an optimizer step over multiple micro-batches or losses, where the default per-backward reduction is both a sync bottleneck and a correctness hazard. Watch out: if you inspect .grad between backward calls, reduction timing now differs.

  • torch.func transforms on ZeRO (#8026) — The engine now supports functorch-style transforms (grad, vmap, functional_call) under ZeRO 0/1/2, unlocking per-sample gradients and functional optimizer patterns previously blocked by ZeRO's hook assumptions. The important caveat: ZeRO-3 is excluded, so stage-3 users can't use this yet.

  • AutoEP and a new accelerator backend (#7938, #8054) — Adds Automatic Expert Parallelism for MoE models (sharding/routing handled for you) plus support for the Biren SUPA accelerator. AutoEP removes significant manual plumbing for large MoE training; validate kernel parity and numerics on non-NVIDIA hardware before committing production runs.

  • Mixed-precision numerics changed (#8066, #8056, #8029) — Casting is now per-policy: fp32 buffers are preserved rather than coerced to the low-precision dtype, gradient flow is consistently fp32, and the FP16 optimizer's flat buffer filters out requires_grad=False params. This is the most likely source of surprising diffs — models relying on fp32 master weights or running-stat buffers may see different values and memory footprints after upgrading.

  • DeepCompile and ZenFlow correctness fixes (#8032, #8036, #8038, #8033, #8042, #7771) — A cluster of real fixes: parameter/grad lifetime handling for ZeRO-1/3 under DeepCompile, grad dtype normalization before ZeRO-3 reduction, corrected all-gather scheduler candidate selection, plus ZenFlow fixes for NVMe parameter offload with the ZeRO-3 selective optimizer and Adam under PyTorch's updated backward flow. If 0.19.1 gave you crashes or silent mis-reductions with these paths, this release is worth the upgrade.

  • Breaking changes — None in this release; 0.19.1's broken PyPI metadata is also corrected here (#8039, #8040), so pip installs work again.
