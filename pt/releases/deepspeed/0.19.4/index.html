DeepSpeed v0.19.4

Highlights

  • ZeRO-3 + AutoTP inference — Tensor parallelism now works with ZeRO-3 inference, including HuggingFace lm_head replacement, tp_plan metadata preservation, and checkpoint consolidation across both TP and DP ranks. This removes a significant composition constraint; recheck previously consolidated checkpoints and validate round trips across your intended parallel topology (#8167, #8146, #8187, #8168).
  • Broader gradient-accumulation support — Managed accumulation adds ZeRO stages 0/1, while unmanaged accumulation adds stages 2/3. Stage 0/1 users gain an explicit managed mode, and ZeRO-2/3 workloads can retain manual accumulation control without custom workarounds (#8184, #8203, #8217).
  • Corrected training schedules — WarmupLR preserves per-group base learning rates, tensor-specific LRs survive scheduler updates—including OneCycle—and OneCycle stair counts now affect the curve. Invalid warmup types and zero-step schedules are also guarded. These fixes can change effective LR trajectories, so revalidate baselines and resumed jobs (#8171, #8202, #8205, #8179, #8151, #8166).
  • MoE correctness and performance — Dispatch fixes silent Tutel + TP corruption, enables Tutel shared MoE with k != 1, adds Triton grouped-GEMM for Ampere/Ada, and improves AutoEP rank splitting and routing. MoE users should benchmark the new expert-GEMM path and rerun correctness checks when changing backend, top-k, expert counts, or token-dropping behavior (#8195, #8174, #8180, #8190, #8155).
  • Safer compilation and runtime diagnostics — DeepCompile state is scoped to graph and engine lifecycles, with a fix for ZeRO-3 gathered-parameter ownership; zero.Init now warns about silent single-rank fallback; blocking AIO bindings release the GIL. Exercise engine rebuild and checkpoint paths, investigate rank-fallback warnings, and expect better overlap for threaded I/O workloads (#8159, #8157, #8089, #8196).
  • Compatibility — No breaking changes are called out in this release.
