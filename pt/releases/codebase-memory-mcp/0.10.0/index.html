códigobase-memória-mcp v0.10.0

⚠️ Use v0.10.1. v0.10.0 enviou uma regressão MCP-client crítica (#1522): o formato de saída padrão das principais ferramentas de descoberta renderizadas como um {} vazio em MCP clients compatíveis com especificações, como Claude Code. Tudo abaixo descreve esta versão com precisão – mas a versão de correção a substitui e é aquela que deve ser instalada.

Um lançamento marcante desde v0.9.0 — o back-end do cbm foi rearquitetado em torno de um daemon de coordenação compartilhado, a saída da ferramenta foi reconstruída em um formato de árvore compacto (~99% menos tokens de saída em resultados grandes), a catraca de memória de longa data do Windows foi corrigida e verificada, e um novo sistema de cobertura torna os pontos cegos do gráfico visíveis — apresentando a 15ª ferramenta do cbm, check_index_coverage, e um esqueleto de código perdido renderizado logo ao lado a galáxia de código na interface do gráfico. Desde o lançamento candidato, o gráfico ganhou uma nova classe de borda CALL_REFERENCE apoiada por evidências, a substituição do alocador dos binários do Linux foi considerada silenciosamente inativa e genuinamente ativada, e todos os problemas de daemon/instalador/Windows relatados no RC foram corrigidos. Adicione três novas superfícies de linguagem contribuídas pela comunidade, resolução de pacote cruzado Swift, uma revisão de extração Nix e um amplo lote de correção orientado pela comunidade em todo o mecanismo de consulta, armazenamento e extratores.

⚠️ Mudanças de comportamento

  • Nova classe de borda: CALL_REFERENCE — e CALLS agora significa exatamente uma coisa. O gráfico agora distingue invocar um chamável de passá-lo como um valor (app.register(pluginFn, opts)). CALLS é reservado exclusivamente para invocações; CALL_REFERENCE é emitido somente quando a evidência determinística do analisador/LSP/registro prova o valor exato que pode ser chamado (extensões exatas de ocorrência, estado de ligação lexical, identidade de símbolo resolvida); ocorrências ambíguas, sombreadas ou de recuperação dinâmica permanecem USAGE. Consultas que presumiam que todo relacionamento que pode ser chamado era uma aresta CALLS deveriam levar em conta o novo rótulo — e ganhar uma precisão que não tinham antes: uma aresta CALL_REFERENCE é uma prova, não uma suposição.

  • Um arquivo por plataforma — a UI está sempre incluída. A divisão ui-*/variante não UI desapareceu: cada plataforma agora envia um único arquivo com a UI gráfica incorporada, e os pacotes npm/PyPI a incluem por padrão (a opção CBM_VARIANT=ui do RC é obsoleta). Menos artefatos, sem downloads de variantes erradas, uma composição para verificar.

Destaques

  • O daemon de coordenação — um marco de backend. Até agora cada sessão cbm era uma ilha: cada servidor MCP, chamada CLI e gancho abriam a loja por conta própria e não sabiam nada sobre seus vizinhos. A partir desta versão, todos eles são coordenados por meio de um daemon por usuário — handshakes de conflito de compilação/versão, controle de admissão de indexação e uma UI gráfica compartilhada. Novo daemon start|stop|status CLI; um daemon quente remove o custo de inicialização por comando - medido comandos CLI 40–58% mais rápidos em um gráfico de 8,5 milhões de nós (~2.6 s salvos por chamada). Reforçado por relatórios de campo RC: cada caminho de rejeição agora responde ao client com um motivo, em vez de deixá-lo esperando. Além dos ganhos imediatos, esta é a base sobre a qual os próximos lançamentos se baseiam: controles centralizados para fluxos de trabalho multiagentes e infraestrutura de relatórios/observabilidade somente local — tudo permanece em sua máquina; nada é enviado para lugar nenhum.
  • Gráficos de chamadas baseados em evidências. A nova classe de borda CALL_REFERENCE (veja mudanças de comportamento) preenche uma lacuna de precisão de longa data: padrões de ordem superior — plug-ins registrados por valor, retornos de chamada, tabelas manipuladoras — são agora relacionamentos gráficos de primeira classe apoiados por evidências determinísticas, enquanto CALLS para de absorver suposições. A saída opcional include_evidence mostra por que existe uma borda: a origem da resolução por trás dela.
  • Saída da ferramenta em formato de árvore — linhas compactas TOON agrupadas por prefixo com paginação exatamente uma vez, relatório de impacto real do detect_changes e detecção de ciclo gráfico. Mediu ~99% menos tokens de saída em comparação com v0.9.0 em resultados de consultas grandes - e as respostas MCP não duplicam mais sua carga útil em structuredContent, praticamente dobrando o orçamento de resposta utilizável.
  • A catraca de memória do Windows foi corrigida (#581) — e a substituição do Linux foi ativada. A substituição do alocador foi compilada silenciosamente no MinGW, de modo que o CRT manteve as páginas liberadas comprometidas e os daemons de longa duração aumentaram a memória por meses. mimalloc agora possui genuinamente as alocações do Windows, os heaps de thread são liberados na saída do thread e uma auditoria de propriedade em voz alta faz com que qualquer regressão futura se anuncie na inicialização. Artefatos verificados no lançamento: uma absorção de consulta pura de 10 minutos que mediu o crescimento de heap confirmado de 53× em compilações v0.9.0-era agora mede 1.06×. A mesma auditoria capturou a imagem espelhada no Linux: os binários Linux enviados nunca realmente rotearam o malloc comum através do mimalloc - a partir desta versão, eles o fazem.
  • Uma instalação, 43 agentes de codificação — o instalador automaticamente (ou condicionalmente, onde os marcadores documentados de um client estão presentes) configura 43 agentes e superfícies client — Claude Code, Codex CLI, Gemini CLI, Cursor, Zed, VS Code, Windsurf, Cline, Aider, Goose, Amp, Copilot CLI, Sourcegraph Cody e mais 30 — com extensões pi e OpenCode agora geradas diretamente do registro da ferramenta. Perfis de ferramentas experimentais (--tool-profile=analysis|scout) expõem superfícies de inspeção restritas para agentes exploradores leves. E não toca mais no que não é seu: os ganchos existentes são preservados mesmo quando uma reescrita de script é recusada.
  • Cobertura honesta — o gráfico perdido — o que não apareceu no gráfico agora é de primeira classe, encabeçado por check_index_coverage — a 15ª ferramenta cbm: sinais de cobertura de análise por arquivo, arquivos deliberadamente ignorados relatados como uma classe de design, cobertura dobrada em index_status com notas sobre get_code_snippet e um gráfico de falhas consultável persistido na loja. Na IU, o código perdido é renderizado como um esqueleto ao lado da galáxia de código — click-to-focus, com uma chamada de relatório de caso extremo.
  • Novas superfícies de linguagem — resolução semântica Perl LSP-tier, suporte InterSystems IRIS ObjectScript e fiação Mojo — todas as três contribuições da comunidade — além de IMPORTAÇÕES rápidas de pacotes cruzados resolvidas por meio de manifestos Package.swift e uma revisão de extração Nix em duas partes (arquivos com raiz de função não descartam mais suas definições; caminhos de atributos modelados com nomes qualificados com escopo definido).
  • Robustez do mecanismo de consulta — coalesce() e funções escalares multi-arg em WHERE, semântica correta do caminho de comprimento de var com um limite de profundidade anunciado, DISTINCT-before-LIMIT, a lista ORDER BY multichave completa homenageada com LIMIT intacto, retornos de propriedade composta/escapada, um prazo de execução de relógio de parede para consultas descontroladas e paginação tools/list para não paginação clients.

O que mudou

Daemon de coordenação e simultaneidade

Esta é a maior mudança de back-end desde o início do projeto: o modelo de execução do cbm passou de processos independentes por sessão para um back-end coordenado por usuário. Sessões simultâneas são coordenadas por meio do daemon (daemon start|stop|status, permanente ou gerenciado por sessão) com IPC autenticado, detecção de conflito de impressão digital/versão/raiz de cache, controle de admissão de trabalho físico para indexação paralela e a UI gráfica servida pelo daemon. Como um daemon por usuário é um limite de segurança, seu IPC foi reforçado de acordo - no Windows, os pipe clients são validados pela identidade do processo em vez de representação, os objetos de namespace privado são carimbados pelo proprietário com o SID do usuário do token e os DACLs são estritamente validados; no POSIX, a identidade do soquete é verificada em relação aos registros fixados no inode. Tudo permanece estritamente local.

Os relatórios de campo RC fortaleceram as costuras: um client cuja imagem binária o daemon rejeita agora obtém uma resposta em vez de um "pendente" indefinido (#1383); uma resposta MCP superdimensionada produz um erro estruturado em vez da morte do processo (#1375); conecta o daemon de superfície a criar conflitos para seu chamador em vez de emitir nada (#1388); e o caminho de admissão que aceita uma compilação incompatível agora nomeia seu grupo em diagnóstico. No macOS, os subprocessos são gerados via posix_spawn em vez de fork+exec.

Preparação para fluxos de trabalho multiagentes nativos da árvore de trabalho. O daemon também é a base para como as configurações multiagentes realmente são executadas hoje: um agente por árvore de trabalho git. Neste momento cada árvore de trabalho deve ser indexada como se fosse um repositório separado. Com a camada de daemon centralizada instalada, os próximos lançamentos irão retrabalhar exatamente isso: as árvores de trabalho se tornarão filhas do gráfico do repositório principal, compartilhando tudo inalterado e indexando apenas o que difere — tornando o padrão agente por árvore de trabalho dramaticamente mais barato em tempo e disco.

Semântica e reindexação de gráficos

O trabalho do CALL_REFERENCE (veja mudanças de comportamento) é executado em toda a pilha: extração, resolução LSP, publicação sequencial e paralela, persistência, contagens de MCP/UI e documentação, com correspondência exata de ocorrência para que um resultado LSP nunca possa promover um uso diferente do mesmo nome e tratamento de falha fechada para sombreamento lexical e ambiguidade. Junto com isso, a reindexação a quente foi movida para um pipeline de mesclagem delta — os dados inalterados são copiados adiante e apenas a fatia alterada é corrigida e trocada atomicamente, substituindo o caminho anterior de reconstrução e reparo. O desempenho de reindexação quente em grande escala ainda é um trabalho em andamento (veja os problemas conhecidos), mas o retrabalho estrutural que esta versão traz é a base sobre a qual as vitórias restantes chegam.

Saída da ferramenta e superfície MCP

Saída compacta TOON em toda a superfície de consulta (~ 10 × menor) e, em seguida, o formato de árvore na parte superior (linhas agrupadas por prefixo, cursores de paginação exatamente uma vez, impacto de mudança real em detect_changes, detecção de ciclo SCC) para uma saída combinada de ~ 99% redução de token vs v0.9.0 em resultados grandes. As respostas do MCP param de duplicar toda a sua carga útil em structuredContent (#1375). O include_evidence opcional expõe a origem da resolução de borda. O detect_changes avalia a detecção de sementes para intervalos de linha alterados. As ferramentas ADR receberam um passe de correção da comunidade: as leituras permanecem sem bloqueio durante a reindexação, as gravações de seção enganosas são rejeitadas e os rótulos de escopo de cobertura são preservados. index_repository resolve um repo_path a partir de um nome de projeto conhecido; um nome de projeto inválido não pode mais enviar o daemon espalhando arquivos .corrupt.<hex> (#1425); As recusas de ativação do CLI são atribuídas à verificação de segurança registrada (#1416); e --help deriva sua lista de ferramentas do registro MCP, portanto, não pode desviar.

Segurança do Windows e da memória

A cadeia # 581: rotear alocações comuns do Windows por meio de mimalloc (--wrap + substituição de CRT estático), liberar heaps de thread de um retorno de chamada de desconexão TLS, descartar um bloco de cache de página SQLite com falha no arm64 e auditar a propriedade do alocador por classe de tamanho em voz alta na inicialização para que "o ajuste é decoração" nunca mais possa acontecer silenciosamente. Novo desde o RC: a mesma filosofia de auditoria detectada que os binários Linux enviados nunca haviam realmente roteado malloc através de mimalloc — a substituição agora está genuinamente ativa (#1360); diagnósticos de memória relatam RSS da verdade do sistema operacional em todas as plataformas; bancos de dados gráficos em caminhos de cache não-ASCII abrem de forma confiável no Windows (cada caminho de manutenção SQLite aberto agora é roteado através da mesma normalização de caminho amplo que a abertura primária - anteriormente o segundo índice em, por exemplo, um cache com nome cirílico falhou); stdio é executado em modo binário no MCP no Windows; processos filhos gerados não atualizam mais as janelas do console (#1427, além de uma correção da comunidade para o caso geral); e a base de código é compilada de forma limpa no MinGW GCC.

O Windows agora vem com um único binário — e as atualizações são executadas em install.ps1

Anteriormente, o Windows enviava dois executáveis: um pequeno inicializador permanente e o binário do produto por trás dele. Agora ele vem um binário, exatamente como Linux e macOS.

O inicializador existia para que o produto pudesse se atualizar: no Windows, um executável em execução não pode substituir sua própria imagem, então um segundo binário residente teve que realizar a troca. Esse pequeno ajudante tropeça de forma confiável na heurística do antivírus, e não poderíamos mantê-lo sem enviar algo que foi sinalizado - então a etapa de atualização saiu do processo em execução e entrou no install.ps1, que é executado enquanto o codebase-memory-mcp não está em execução.

O que muda para você: no Windows, o codebase-memory-mcp update não é mais atualizado. Ele imprime o comando exato a ser executado:

powershell -ExecutionPolicy Bypass -File "<install-dir>\install.ps1"

install.ps1 é idempotente, então executá-lo novamente é a atualização: ele interrompe o daemon, retira o binário em execução, instala o novo e limpa. A instalação por meio de npm ou pip não é afetada — atualize com seu gerenciador de pacotes como antes.

Idiomas e precisão de extração

Resolução semântica Perl da camada LSP; Suporte à linguagem ObjectScript da InterSystems; Fiação Mojo. Novo desde o RC: IMPORTAÇÕES de pacote cruzado Swift resolvidas por meio de manifestos Package.swift; Os arquivos Nix cuja expressão raiz é uma função não descartam mais todas as definições, e os caminhos de atributos Nix são modelados com nomes de folhas e QNs com escopo definido, com ligações em nível de módulo cunhadas como variáveis; os decoradores separados por um comentário permanecem anexados; macros GoogleTest com o mesmo nome em um arquivo obtêm nomes exclusivos em vez de serem recolhidas em um único nó e eliminar bordas de chamada (#1266); URLs literais de modelo JS/TS são nivelados para espaços reservados {} para que o encontro de rota funcione; O manuseio do array Haskell é seguro para alias. Mecanismo de consulta (Cypher)

coalesce() e funções escalares multi-arg em WHERE; semântica de caminho var-length fixada com um grampo de profundidade anunciado; DISTINCT aplicado antes dos limites RETURN; retornos de valor total para propriedades compostas e de escape; um prazo de execução ininterrupto; Paginação padrão tools/list. Novo desde o RC: a lista completa de múltiplas teclas ORDER BY é analisada e aplicada com LIMIT mantido intacto (#1334); OPTIONAL MATCH não pode mais fabricar uma linha "sem correspondência" depois que o orçamento da linha for preenchido; e as colunas de agregação são classificadas por funções agregadas reais.

Loja, artefatos e ciclo de vida

Publicação de cache atômico no gravador SQLite; as exportações de instantâneos tornaram-se consistentes e as importações corruptas foram recusadas; sidecars WAL/SHM de destino removidos antes de instalar um novo banco de dados; SQLITE_CORRUPT surgiu a partir de varreduras de linha; WAL delimitado via journal_size_limit; o observador reindexa repositórios sujos uma vez por estado distinto; a canonização relativa do repo_path não corrompe mais e exclui automaticamente os bancos de dados do projeto. Novidade desde o RC: a publicação da reindexação é atômica de ponta a ponta — preparada em caminhos privados, verificada e colocada em quarentena em caso de falha; Selagem WAL antes da troca de artefatos; e listas de permissões de rótulos roteiam através do conjunto de tipo canônico.

Agentes, clients e instalador

A cobertura de integração do agente abrange 43 superfícies client automáticas/condicionais, cada uma alterada somente quando sua plataforma documentada, marcador ou caminho de configuração existente estiver presente. Novo desde o RC — principalmente direto dos relatórios de campo do RC: o instalador nunca remove os ganchos existentes quando uma reescrita de script é recusada, e --dry-run prevê exatamente esse resultado (#1387); função de agente Codex gerada TOMLs declaram seu transporte; As extensões pi e OpenCode são geradas a partir do registro da ferramenta, portanto, novas ferramentas aparecem nelas automaticamente; raízes de indexação podem ser declaradas a partir do CLI, a descoberta limpa o diretório de cache e a compactação é segura em termos de tamanho em entradas grandes; A instalação/desinstalação/medicação do Windows não falha mais em sessões que eles próprios podem interromper com segurança (#1416). Transportado do lote RC: o caminho de transação de instalação do Windows com segurança reforçada, rejeição de sinalizadores desconhecidos com sugestões de sinalizadores mais próximos, rotulagem --dry-run honesta, pilhas de caminhada de descoberta crescentes, detecção de memória FreeBSD e o resolvedor estrito CBM_MEM_BUDGET_MB.

CI e infraestrutura de teste

Cada local – CI local, PR CI, simulação de pré-lançamento e pipeline de lançamento – executa os mesmos scripts de perna canônicos, com um contrato de paridade de local que transforma qualquer desvio em uma construção vermelha; execução paralela por suíte com porta de perda zero (~2.5× suítes mais rápidas); cobertura ampliada do ThreadSanitizer mais ARM64 Windows UBSan nativo; atestado de lançamento de artefato; pernas de imersão com abertura de liberação. Novo desde o RC: VirusTA varredura total dos artefatos de arquivo exatos é uma etapa final padrão de cada simulação (com o mecanismo de sinalização nomeado, não apenas contado); As execuções de CI local são isoladas por ID de execução; e o pipeline de lançamento em si foi depurado em público - skip_tests não ignora mais a fumaça e a imersão silenciosamente, e os bits executivos do script são fixados por contrato.

Problemas conhecidos

  • Pequeno crescimento de memória somente no Windows sob carga de consulta sustentada (~4.5 KB/consulta; nem o macOS nem o Linux mostram isso). Esta não é a catraca nº 581 – as auditorias de propriedade são aprovadas e o modo de falha 53× desaparece – mas é rastreado por uma investigação de acompanhamento.
  • A reindexação morna em escala muito grande ainda é mais lenta do que v0.9.0-era, mas está melhorando. O pipeline de mesclagem delta enviado nesta versão substitui o caminho de reconstrução e reparo e já reduz substancialmente o tempo de reindexação quente em nossas execuções A/B; fechar a lacuna restante para os números de acertos do cache v0.9.0-era é um trabalho ativo em andamento. A indexação fria é igual ou mais rápida que todas as linhas de base.
  • Jitter de contagem de bordas multithread: as contagens de nós são estáveis ​​em bytes nas execuções; os totais de borda podem variar marginalmente de execução para execução em linguagens com alta resolução (pior caso TypeScript). Rastreado como uma investigação de determinismo aberto.
  • No macOS, uma linha de inicialização mem.allocator.not_owned pode aparecer nos logs — no macOS esta é a configuração projetada (o alocador atende as populações sqlite/tree-sitter vinculadas; o malloc comum permanece com o alocador do sistema) e é inofensivo. No Windows e agora no Linux é o tripwire para a classe #581: se você vê-lo lá, por favor, arquive-o.

Falsos positivos de antivírus — a história completa e uma mudança de política

Esta versão é fornecida com 0 detecções em cada artefato — cada arquivo binário, scripts de instalação e arquivos de avisos, cada um verificado por mais de 60 mecanismos. A tabela de verificação abaixo é gerada a partir dessas varreduras, e cada link VirusTotal nela é durável: você mesmo pode verificar novamente os bytes exatos a qualquer momento.

Devemos a você a história mais longa, porque ela mudou a forma como nosso portão de lançamento funciona – e porque é uma das principais razões pelas quais o trecho do RC até a final levou semanas em vez de dias.

O que aconteceu. Durante o RC e a reta final, algumas compilações acionaram intermitentemente uma heurística de aprendizado de máquina – o mecanismo da Microsoft reportando Trojan:Script/Wacatac.B!ml – enquanto todos os outros mecanismos reportavam limpo. O sufixo !ml marca a pontuação de um modelo estatístico, não uma correspondência de assinatura; o token Script é um depósito genérico nesse esquema de nomenclatura e não diz nada sobre o conteúdo do script. Primeiro, tratamos isso como um compromisso potencial: dissecação completa de uma matriz de lançamento construída a partir de um commit, engenharia reversa dos artefatos sinalizados, análise de entropia em relação a perfis de carga útil compactada. Nada. Os veredictos se dividem em todos os eixos de uma só vez - o eixo de link estático/dinâmico invertido entre arquiteturas, dois binários macOS com estrutura de segmento idêntica divididos limpos/sinalizados e artefatos irmãos de uma construção colocados em diferentes intervalos de variantes. A evidência decisiva: um arquivo idêntico – o mesmo SHA-256 – passou de 0/62 limpo para sinalizado em cerca de uma hora, sem nenhuma alteração de nossa parte. E o experimento que realizamos na outra direção confirmou isso: removemos todos os scripts de shell incorporados do binário e movemos o pacote de UI e os modelos de integração para arquivos verificados separados — a contagem de detecção não caiu, ela simplesmente se moveu entre os artefatos, então revertemos para a composição mais simples de binário único. Parte do veredicto reside no próprio estado do scanner, não em nossos bytes. Nenhuma mudança de código pode garantir a não detecção, porque o classificador não está julgando apenas o código.

Por que a política mudou. As notas do RC diziam que nosso portão era zero detecções, permanentemente, sem tolerância - e estávamos falando sério quando o escrevemos. Mas um portão zero contra um veredicto que gira em bytes idênticos significa que nosso tempo de lançamento é uma função do estado do modelo de nuvem do Defender, não do nosso código: cada incidente custa dias de verificação de bytes em um endpoint ativo do Defender, preenchendo um relatório falso positivo com a Microsoft e aguardando uma revisão do classificador – com o desenvolvimento efetivamente bloqueado por trás disso. Essa não é uma forma sustentável de enviar navios, e fingir que a regra absoluta ainda é válida teria sido uma opção desonesta. Então, nós a substituímos por uma política que podemos realmente manter, documentada e fixada por um teste de contrato em SECURITY.md:

  • Uma versão pode ser enviada com no máximo uma detecção e somente quando o mecanismo for Microsoft e o rótulo terminar em !ml — a classe exata de falso positivo evidenciada descrita acima.
  • Todo o resto ainda bloqueia, fortemente: dois ou mais motores, qualquer etiqueta baseada em assinatura, qualquer outro fornecedor, qualquer veredicto "suspeito".
  • Uma detecção tolerada é publicada, nunca escondida — ela aparece na tabela de verificação abaixo com seu link VirusTotal e um marcador TOLERATED, para que você possa sempre ver exatamente o que foi enviado.

Esta versão não precisava de tolerância - ela faz uma varredura totalmente limpa - mas você deve conhecer a regra sob a qual as versões futuras serão enviadas.

Isso é endêmico, não específico para nós. A mesma família !ml atinge repetidamente binários grandes, não assinados e nativos de código aberto: llama.cpp (nada encontrado na engenharia reversa), próprio gh CLI do GitHub, conjunto de ferramentas Go da própria Microsoft, Anthropic's Código Claude, Códice OpenAI, rust-lang, yt-dlp, Godot, PyInstaller, Tauri. Um engenheiro da Microsoft na equipe Go colocado claramente: "não podemos exatamente consertar algo e resolver todos os falsos positivos do Go." Nós deliberadamente não remodelamos o binário para evitar o classificador - é isso que o malware faz, e o mesmo engenheiro relata que "aumenta o escrutínio em vez de evitá-lo." Preferimos ser escaneáveis ​​e explicar um falso positivo do que ser ilegível e ter uma boa pontuação. O que corrigimos de qualquer maneira. A investigação revelou defeitos reais, corrigidos por seus próprios méritos e agora confirmados pelos portões de lançamento: cada binário Linux que já havíamos enviado solicitava uma pilha executável (uma anotação .note.GNU-stack faltando); uma sonda fork somente para teste foi compilada em compilações de produção; o daemon gerou curl contra o GitHub libera API para verificar se há atualizações - removido, cbm agora não faz nenhuma solicitação de rede por conta própria; extração não utilizada e maquinário de extensão carregável SQLite compilado; fortalecimento de arquivo temporário e varredura de link simbólico; e carimbos de data/hora de construção removidos para bytes reproduzíveis.

A solução duradoura é a assinatura de código, e ela está em andamento: a validação de identidade e o registro na plataforma são burocráticos, e não técnicos, por isso seguem seu próprio cronograma. A assinatura ajudará no Windows; observe que não existe nenhum esquema de assinatura de código que os mecanismos AV respeitem para binários ELF do Linux, portanto, a transparência acima é permanente, não transitória. Se você encontrar algo que contradiga nossa avaliação, queremos saber: abra uma edição com o rótulo av-analysis — uma descoberta concreta muda nossa posição. Até a assinatura dos terrenos, o portão acima, os hashes publicados, o atestado de procedência da construção e a fonte que você sempre pode construir são as âncoras trust para este projeto.

⚠️ Behavior changes

  • New edge class: CALL_REFERENCE — and CALLS now means exactly one thing. The graph now distinguishes invoking a callable from passing it as a value (app.register(pluginFn, opts)). CALLS is reserved exclusively for invocations; CALL_REFERENCE is emitted only when deterministic parser/LSP/registry evidence proves the exact callable value (occurrence-exact spans, lexical binding state, resolved symbol identity); ambiguous, shadowed, or dynamically rebound occurrences remain USAGE. Queries that assumed every callable relationship was a CALLS edge should account for the new label — and gain a precision they didn't have before: a CALL_REFERENCE edge is proof, not a guess.

  • One archive per platform — the UI is always included. The ui-* / non-UI variant split is gone: every platform now ships a single archive with the graph UI embedded, and the npm/PyPI packages include it by default (the CBM_VARIANT=ui opt-in from the RC is obsolete). Fewer artifacts, no wrong-variant downloads, one composition to verify.

Highlights

  • The coordination daemon — a backend milestone. Until now every cbm session was an island: each MCP server, CLI call, and hook opened the store on its own and knew nothing about its neighbors. As of this release, all of them coordinate through a per-user daemon — build/version conflict handshakes, indexing admission control, and a shared graph UI. New daemon start|stop|status CLI; a warm daemon removes per-command startup cost — measured 40–58% faster CLI commands on an 8.5M-node graph (~2.6 s saved per call). Hardened by RC field reports: every rejection path now answers the client with a reason instead of leaving it waiting. Beyond the immediate wins, this is the foundation the next releases build on: centralized controls for multi-agent workflows and local-only reporting/observability infrastructure — everything stays on your machine; nothing is sent anywhere.
  • Evidence-backed call graphs. The new CALL_REFERENCE edge class (see behavior changes) closes a long-standing precision gap: higher-order patterns — plugins registered by value, callbacks, handler tables — are now first-class graph relationships backed by deterministic evidence, while CALLS stops absorbing guesses. Optional include_evidence output shows why an edge exists: the resolution provenance behind it.
  • Tree-format tool output — TOON-compact, prefix-grouped rows with exactly-once pagination, real detect_changes impact reporting, and graph cycle detection. Measured ~99% fewer output tokens vs v0.9.0 on large query results — and MCP responses no longer duplicate their payload in structuredContent, roughly doubling the usable response budget on top.
  • Windows memory ratchet fixed (#581) — and the Linux override switched on. The allocator override silently compiled out under MinGW, so the CRT kept freed pages committed and long-lived daemons ratcheted memory for months. mimalloc now genuinely owns Windows allocations, thread heaps release at thread exit, and an out-loud ownership audit makes any future regression announce itself at startup. Verified on release artifacts: a 10-minute pure-query soak that measured 53× committed-heap growth on v0.9.0-era builds now measures 1.06×. The same audit then caught the mirror image on Linux: shipped Linux binaries had never actually routed ordinary malloc through mimalloc — as of this release they do.
  • One install, 43 coding agents — the installer automatically (or conditionally, where a client's documented markers are present) configures 43 agent and client surfaces — Claude Code, Codex CLI, Gemini CLI, Cursor, Zed, VS Code, Windsurf, Cline, Aider, Goose, Amp, Copilot CLI, Sourcegraph Cody, and 30 more — with pi and OpenCode extensions now generated straight from the tool registry. Experimental tool profiles (--tool-profile=analysis|scout) expose restricted inspection surfaces for lightweight scout agents. And it no longer touches what isn't its own: existing hooks are preserved even when a script rewrite is refused.
  • Honest coverage — the missed graph — what did not make it into the graph is now first-class, headlined by check_index_coverage — the 15th cbm tool: parse-coverage signals per file, deliberately-ignored files reported as a by-design class, coverage folded into index_status with notes on get_code_snippet, and a queryable miss graph persisted in the store. In the UI, the missed code renders as a skeleton beside the code galaxy — click-to-focus, with a report-an-edge-case callout.
  • New language surfaces — Perl LSP-tier semantic resolution, InterSystems IRIS ObjectScript support, and Mojo wiring — all three community-contributed — plus Swift cross-package IMPORTS resolved through Package.swift manifests and a two-part Nix extraction overhaul (function-rooted files no longer drop their definitions; attrpaths modeled with scoped qualified names).
  • Query engine robustness — coalesce() and multi-arg scalar functions in WHERE, correct var-length path semantics with an advertised depth clamp, DISTINCT-before-LIMIT, the full multi-key ORDER BY list honored with LIMIT intact, composite/escaped property returns, a wall-clock execution deadline for runaway queries, and tools/list pagination for non-paginating clients.
  • Store & artifact integrity — a four-report series from one community member exposed torn WAL-mode exports, swallowed SQLITE_CORRUPT, stale WAL replay over fresh DBs, and invalid JSON on async edges; all four are fixed. Reindex publication is now atomic end to end — staged, verified, and quarantined on failure rather than replacing a good database with a broken one.
  • CI, completely wrapped up — local CI, PR CI, dry runs, and releases all execute the same canonical leg scripts, enforced by a venue-parity contract that turns any drift into a red build. Parallel per-suite test execution with a zero-loss gate, release-gating soak legs, per-run isolation, artifact attestation, and VirusTotal scanning of the real archive artifacts as a standard pre-release step.

What's changed

Coordination daemon & concurrency

This is the largest backend change since the project began: cbm's execution model moved from independent per-session processes to a coordinated per-user backend. Concurrent sessions coordinate through the daemon (daemon start|stop|status, permanent or session-managed) with authenticated IPC, build-fingerprint/version/cache-root conflict detection, physical-job admission control for parallel indexing, and the graph UI served from the daemon. Because a per-user daemon is a security boundary, its IPC was hardened accordingly — on Windows, pipe clients are validated by process identity rather than impersonation, private-namespace objects are owner-stamped with the token user's SID, and DACLs are strictly validated; on POSIX, socket identity is checked against inode-pinned records. Everything remains strictly local.

RC field reports then hardened the seams: a client whose binary image the daemon rejects now gets an answer instead of an indefinite "pending" (#1383); an oversized MCP reply produces a structured error instead of process death (#1375); hooks surface daemon build conflicts to their caller instead of emitting nothing (#1388); and the admission path that accepts a mismatched build now names its cohort in diagnostics. On macOS, subprocesses spawn via posix_spawn instead of fork+exec.

Preparation for worktree-native multi-agent workflows. The daemon is also the groundwork for how multi-agent setups actually run today: one agent per git worktree. Right now each worktree has to be indexed as if it were a separate repository. With the centralized daemon layer in place, upcoming releases will rework exactly this: worktrees become children of the main repository's graph, sharing everything unchanged and indexing only what differs — making the agent-per-worktree pattern dramatically cheaper in time and disk.

Graph semantics & reindexing

The CALL_REFERENCE work (see behavior changes) runs through the whole stack: extraction, LSP resolution, sequential and parallel publication, persistence, MCP/UI counts, and documentation, with occurrence-exact matching so an LSP result can never promote a different same-named usage, and fail-closed handling for lexical shadowing and ambiguity. Alongside it, warm re-indexing moved to a delta-merge pipeline — unchanged data is copied forward and only the changed slice is patched and atomically swapped in, replacing the previous rebuild-and-repair path. Warm re-index performance at very large scale is still work in progress (see known issues), but the structural rework this release ships is the foundation the remaining wins land on.

Tool output & MCP surface

TOON compact output across the query surface (~10× smaller) and then the tree format on top (prefix-grouped rows, exactly-once pagination cursors, real change-impact in detect_changes, SCC cycle detection) for a combined ~99% output-token reduction vs v0.9.0 on large results. MCP responses stop duplicating their entire payload in structuredContent (#1375). Optional include_evidence exposes edge resolution provenance. detect_changes scopes seed detection to changed line ranges. ADR tools got a community correctness pass: reads stay nonblocking during reindex, misleading section writes are rejected, and coverage scope labels are preserved. index_repository resolves a repo_path from a known project name; an invalid project name can no longer send the daemon littering .corrupt.<hex> files (#1425); CLI activation refusals are attributed to the recorded safety check (#1416); and --help derives its tool list from the MCP registry, so it can't drift.

Windows & memory safety

The #581 chain: route ordinary Windows allocations through mimalloc (--wrap + static-CRT override), release thread heaps from a TLS detach callback, drop an SQLite page-cache slab that faulted on arm64, and audit allocator ownership per size class out loud at startup so "the tuning is decoration" can never happen silently again. New since the RC: the same audit philosophy caught that shipped Linux binaries had never actually routed malloc through mimalloc — the override is now genuinely active (#1360); memory diagnostics report OS-truth RSS on every platform; graph databases under non-ASCII cache paths open reliably on Windows (every maintenance-path SQLite open now routes through the same wide-path normalization as the primary open — previously the second index into e.g. a Cyrillic-named cache failed); stdio runs in binary mode under MCP on Windows; spawned child processes no longer flash console windows (#1427, plus a community fix for the general case); and the codebase compiles cleanly under MinGW GCC.

Windows now ships a single binary — and updates run from install.ps1

Windows previously shipped two executables: a small permanent launcher plus the product binary behind it. It now ships one binary, exactly like Linux and macOS.

The launcher existed so the product could update itself in place: on Windows a running executable cannot replace its own image, so a second resident binary had to perform the swap. That small helper reliably trips antivirus heuristics, and we could not keep it without shipping something that gets flagged — so the update step moved out of the running process and into install.ps1, which runs while codebase-memory-mcp is not running.

What changes for you: on Windows, codebase-memory-mcp update no longer updates in place. It prints the exact command to run instead:

powershell -ExecutionPolicy Bypass -File "<install-dir>\install.ps1"

install.ps1 is idempotent, so re-running it is the update: it stops the daemon, retires the running binary, installs the new one, and cleans up. Installing through npm or pip is unaffected — update with your package manager as before.

Languages & extraction accuracy

Perl LSP-tier semantic resolution; InterSystems ObjectScript language support; Mojo wiring. New since the RC: Swift cross-package IMPORTS resolved through Package.swift manifests; Nix files whose root expression is a function no longer drop every definition, and Nix attrpaths are modeled with leaf names and scoped QNs, with module-level bindings minted as Variables; decorators separated by a comment stay attached; same-named GoogleTest macros in one file get unique names instead of collapsing into a single node and dropping call edges (#1266); JS/TS template-literal URLs flatten to {} placeholders so route rendezvous works; Haskell array handling is alias-safe. Carried from the RC batch: native fetch() as HTTP_CALLS, CommonJS require() shadow fixes, aliased-import resolution, C/C++ #include-to-header edges and #ifdef-split recovery, PHP trait-recursion OOM fixes, Laravel and JAX-RS route composition, env-access CONFIGURES guards, File-node QN collision fixes, UTF-8-safe docstring truncation, and bounded GLR stack-merge recursion.

Query engine (Cypher)

coalesce() and multi-arg scalar functions in WHERE; var-length path semantics fixed with an advertised depth clamp; DISTINCT applied before RETURN limits; whole-value returns for composite and escaped properties; a wall-clock execution deadline; tools/list default pagination. New since the RC: the full multi-key ORDER BY list is parsed and applied with LIMIT kept intact (#1334); OPTIONAL MATCH can no longer fabricate a "no match" row after the row budget fills; and aggregation columns are classified by actual aggregate functions.

Store, artifacts & lifecycle

Atomic cache publish in the SQLite writer; snapshot exports made consistent and corrupt imports refused; destination WAL/SHM sidecars removed before installing a fresh DB; SQLITE_CORRUPT surfaced from row scans; WAL bounded via journal_size_limit; watcher reindexes dirty repos once per distinct state; relative repo_path canonicalization no longer corrupts and auto-deletes project DBs. New since the RC: reindex publication is atomic end to end — staged under private paths, verified, and quarantined on failure; WAL sealing before artifact swap; and label allowlists route through the canonical type-like set.

Agents, clients & installer

Agent integration coverage spans 43 automatic/conditional client surfaces, each changed only when its documented platform, marker, or existing config path is present. New since the RC — mostly straight from RC field reports: the installer never removes existing hooks when a script rewrite is refused, and --dry-run predicts exactly that outcome (#1387); generated Codex agent role TOMLs declare their transport; pi and OpenCode extensions are generated from the tool registry, so new tools appear in them automatically; indexing roots can be declared from the CLI, discovery prunes the cache directory, and compression is size-safe on huge inputs; Windows install/uninstall/doctor no longer fail on sessions they themselves can stop safely (#1416). Carried from the RC batch: the security-hardened Windows install transaction path, unknown-flag rejection with nearest-flag suggestions, honest --dry-run labeling, growing discovery walk stacks, FreeBSD memory detection, and the CBM_MEM_BUDGET_MB strict resolver.

CI & test infrastructure

Every venue — local CI, PR CI, the pre-release dry run, and the release pipeline — runs the same canonical leg scripts, with a venue-parity contract that turns any drift into a red build; parallel per-suite execution with a zero-loss gate (~2.5× faster suites); widened ThreadSanitizer coverage plus native ARM64 Windows UBSan; release-artifact attestation; release-gating soak legs. New since the RC: VirusTotal scanning of the exact archive artifacts is a standard final step of every dry run (with the flagging engine named, not just counted); local-CI runs are isolated per run id; and the release pipeline itself was debugged in public — skip_tests no longer silently skips smoke and soak, and script exec bits are pinned by contract.

Known issues

  • Small Windows-only memory growth under sustained query load (~4.5 KB/query; neither macOS nor Linux shows it). This is not the #581 ratchet — ownership audits pass and the 53× failure mode is gone — but it is tracked with a follow-up investigation.
  • Warm re-index at very large scale is still slower than v0.9.0-era, but improving. The delta-merge pipeline shipped in this release replaces the rebuild-and-repair path and already cut warm re-index times substantially in our A/B runs; closing the remaining gap to the v0.9.0-era cache-hit numbers is active work in progress. Cold indexing is at or faster than all baselines.
  • Multi-threaded edge-count jitter: node counts are byte-stable across runs; edge totals can vary marginally run-to-run on resolution-heavy languages (worst case TypeScript). Tracked as an open determinism investigation.
  • On macOS a startup line mem.allocator.not_owned may appear in logs — on macOS this is the designed configuration (the allocator serves the bound sqlite/tree-sitter populations; ordinary malloc stays with the system allocator) and is harmless. On Windows and now Linux it is the tripwire for the #581 class: if you see it there, please file it.

Antivirus false positives — the full story, and a policy change

This release ships with 0 detections on every artifact — every binary archive, both install scripts, and the notices files, each scanned by 60+ engines. The verification table below is generated from those scans, and every VirusTotal link in it is durable: you can re-check the exact bytes yourself at any time.

We owe you the longer story, because it changed how our release gate works — and because it is one of the main reasons the stretch from RC to final took weeks rather than days.

What happened. During the RC and final stretch, some builds intermittently tripped one machine-learning heuristic — Microsoft's engine reporting Trojan:Script/Wacatac.B!ml — while every other engine reported clean. The !ml suffix marks a statistical model's score, not a signature match; the Script token is a generic bucket in that naming scheme and says nothing about script content. We treated it as a potential compromise first: full dissection of a release matrix built from one commit, reverse-engineering of the flagged artifacts, entropy analysis against packed-payload profiles. Nothing. The verdicts split across every axis at once — the static/dynamic link axis inverted between architectures, two macOS binaries with identical segment structure split clean/flagged, and sibling artifacts of one build landed in different variant buckets.

The decisive evidence: one identical file — same SHA-256 — went from 0/62 clean to flagged within about an hour, with no change on our side. And the experiment we ran in the other direction confirmed it: we removed every embedded shell script from the binary and moved the UI bundle and integration templates into separate verified files — the detection count did not drop, it simply moved between artifacts, so we reverted to the simpler single-binary composition. Part of the verdict lives in the scanner's own state, not in our bytes. No code change can guarantee non-detection, because the classifier is not judging only the code.

Why the policy changed. The RC notes said our gate was zero detections, permanently, with no tolerance — and we meant it when we wrote it. But a zero gate against a verdict that flips on identical bytes means our release timing is a function of Defender's cloud-model state, not of our code: each incident cost days of verifying bytes against a live Defender endpoint, filing a false-positive report with Microsoft, and waiting for a classifier revision — with development effectively hard-blocked behind it. That is not a sustainable way to ship, and pretending the absolute rule still held would have been the dishonest option. So we replaced it with a policy we can actually keep, documented and pinned by a contract test in SECURITY.md:

  • A release may ship with at most one detection, and only when the engine is Microsoft and the label ends in !ml — the exact, evidenced false-positive class described above.
  • Everything else still blocks, hard: two or more engines, any signature-based label, any other vendor, any "suspicious" verdict.
  • A tolerated detection is published, never hidden — it appears in the verification table below with its VirusTotal link and a TOLERATED marker, so you can always see exactly what shipped.

This release did not need the tolerance — it scans fully clean — but you should know the rule under which future releases ship.

This is endemic, not specific to us. The same !ml family repeatedly hits large, unsigned, native open-source binaries: llama.cpp (nothing found on reverse engineering), GitHub's own gh CLI, Microsoft's own Go toolchain, Anthropic's Claude Code, OpenAI's Codex, rust-lang, yt-dlp, Godot, PyInstaller, Tauri. A Microsoft engineer on the Go team put it plainly: "we can't exactly go fix something and solve all Go false positives." We deliberately do not reshape the binary to dodge the classifier — that is what malware does, and the same engineer reports it "increases scrutiny rather than avoiding it." We would rather be scannable and explain a false positive than be unreadable and score well.

What we fixed anyway. The investigation turned up real defects, corrected on their own merits and now asserted by release gates: every Linux binary we had ever shipped requested an executable stack (a missing .note.GNU-stack annotation); a test-only fork probe was compiled into production builds; the daemon spawned curl against the GitHub releases API to check for updates — removed, cbm now makes no network request of its own accord; unused extraction and SQLite loadable-extension machinery compiled out; temp-file and symlink-scan hardening; and build timestamps removed for reproducible bytes.

The durable fix is code signing, and it is underway — identity validation and platform enrollment are bureaucratic, not technical, so it lands on its own schedule. Signing will help on Windows; note that no code-signing scheme exists that AV engines honour for Linux ELF binaries, so the transparency above is permanent, not transitional. If you find anything that contradicts our assessment, we want to know: open an issue with the av-analysis label — a concrete finding changes our position. Until signing lands, the gate above, published hashes, build provenance attestation, and source you can always build yourself are the trust anchors for this project.
