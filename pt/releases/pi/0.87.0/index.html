pi v0.87.0

Novos recursos

  • Contexto de sessão canônica e limites de extensão — Edite o contexto do modelo sem reescrever o histórico e adicione ganchos de ciclo de vida acionáveis. Consulte ContextEditEntry e eventos de extensão.
  • Extensões de contexto de transcrição completa — Use context_with_system para transformações de mensagens do sistema por solicitação. Consulte context_with_system.
  • Limites de entrada de imagem por modelo — Configure o redimensionamento de imagem seguro em cache por modelo para anexos, read e imagens de resultados de ferramentas. Consulte Limites de entrada de imagem.

Mudanças importantes

  • Removida a opção herdada do agente shouldStopAfterTurn. Use finishTurn e retorne { action: "end" }. finishTurn é executado antes de turn_end, mas aplica a decisão posteriormente e também recebe erros e respostas abortadas; migre predicados de resposta normal retornando undefined para essas saídas difíceis. Veja o @earendil-works/pi-agent-core changelog para um exemplo completo de antes e depois.
  • Adicionado ContextEditEntry à união SessionEntry exportada. Os consumidores TypeScript com chaves de entrada exaustivas devem atender context_edit; use replacement: null para omissão e substituição de conteúdo caso contrário.
  • Tornou SessionManager canônico para o contexto do provedor AgentSession. A atribuição de session.agent.state.messages não substitui mais o histórico de solicitações futuras; restaure com SessionManager.inMemory(cwd, { id }, entries), navegue com session.navigateTree() ou anexe através de session.sessionManager e chame session.refreshContext().
  • TurnEndEvent expandido com campos de limite obrigatórios e adicionado AgentBeforeSettleEvent à união ExtensionEvent exportada. Os consumidores que constroem eventos ou ligam exaustivamente o ExtensionEvent devem lidar com os novos formatos. ExtensionRunner.emit() não aceita mais turn_end; integrações de host despacham limites acionáveis ​​com emitBoundary(baseEvent, buildContext).
  • Execuções diferidas solicitadas aos manipuladores agent_settled até que todos os manipuladores liquidados terminem. Os manipuladores ainda observam ctx.isIdle() === true, mas não veem mais um agent_start reentrante durante o mesmo envio de notificação.

Adicionado

  • Adicionadas edições de contexto de modelo somente para acréscimos. Por exemplo, sessionManager.appendContextEdit(entryId, null) omite uma mensagem do contexto futuro do provedor sem alterar o histórico bruto, o uso ou o histórico da UI.
  • Adicionados limites de extensão turn_end e agent_before_settle acionáveis. Retorne { entries: [...event.entries, draft], continue: true } para persistir as entradas estruturais em ordem e garantir uma próxima solicitação do fornecedor sem alterar a direção ou programação de acompanhamento.
  • Adicionada entrada de compactação sem retenção: sessionManager.appendCompaction(summary, null, tokensBefore) armazena o próprio ID da compactação como seu limite mantido.
  • Adicionado o evento de extensão context_with_system, que é executado após os manipuladores context na transcrição completa, incluindo mensagens do sistema e envia seu resultado literalmente. Consulte context_with_system.
  • Adicionados perfis de redimensionamento de imagem por modelo por meio de inputLimits.images.resize no models.json, aplicados a anexos de arquivos, leituras de imagens e imagens de resultados de ferramentas (#9631).

Corrigido

  • Correção de substituições de edição de contexto de string que produziam conteúdo inválido de mensagem de assistente e resultado de ferramenta em vez de blocos de texto.
  • Foram corrigidos metadados de limites invisíveis ao contexto e edições de substituição, fazendo com que entradas recém-anexadas ou substituídas fossem resumidas antes de sua primeira solicitação do provedor.
  • Foi corrigida a contabilização do contexto editado, descartando o uso válido do assistente capturado após a última edição do contexto e reutilizando esse uso após uma compactação posterior torná-lo obsoleto.
  • Corrigidas novas tentativas de erro selecionadas e recuperação de comprimento/estouro final, mantendo tentativas de modelo abandonadas no contexto futuro do provedor; as omissões de recuperação pós-execução agora persistem sem ocultar o histórico de transcrição bruto ou alterar o agendamento da fila.
  • Corrigidos os manipuladores context que filtram ou fatiam mensagens descartando as declarações de prompt e de ferramenta, que após a compactação orientada por extensão deixavam as solicitações sem ferramentas integradas ou faziam o Codex emitir texto bruto de chamada de ferramenta. Os manipuladores não veem mais as mensagens do sistema; Pi restaura o prompt e o estado da ferramenta após sua execução. Consulte context (#9789, #9822).
  • Corrigido /bug permitindo uploads no modo offline enquanto preserva as exportações zip locais (#9841 por @christianklotz).
  • Corrigido aquecimento de cache de prompt ocioso, reconstruindo caches expirados quando seu temporizador ou uma decisão de extensão é atrasada.
  • Diagnóstico de falhas aprimorado com dicas que identificam extensões carregadas que aparecem no rastreamento de pilha.
  • Correção de arquivos de texto começando com GIF sendo classificados incorretamente como imagens e omitidos na entrada read e CLI @file (#9755).
  • Correção do frontmatter do modelo de prompt malformado sendo ignorado silenciosamente em vez de relatado como um aviso de recurso (#9830 por @christianklotz).
  • Foram corrigidos endpoints herdados e desconhecidos de conclusão de bate-papo compatíveis com OpenAI que recebiam esquemas de ferramentas estritos, a menos que anunciassem suporte explicitamente (#9816).

pi v0.87.0

New Features

  • Canonical session context and extension boundaries — Edit model context without rewriting history and add actionable lifecycle hooks. See ContextEditEntry and extension events.
  • Full-transcript context extensions — Use context_with_system for per-request system-message transformations. See context_with_system.
  • Per-model image input limits — Configure cache-safe image resizing per model for attachments, read, and tool-result images. See Image Input Limits.

Breaking Changes

  • Removed the inherited shouldStopAfterTurn agent option. Use finishTurn and return { action: "end" } instead. finishTurn runs before turn_end but applies the decision afterward, and it also receives error and aborted responses; migrate normal-response predicates by returning undefined for those hard exits. See the @earendil-works/pi-agent-core changelog for a complete before-and-after example.
  • Added ContextEditEntry to the exported SessionEntry union. TypeScript consumers with exhaustive entry switches must handle context_edit; use replacement: null for omission and a content replacement otherwise.
  • Made SessionManager canonical for AgentSession provider context. Assigning session.agent.state.messages no longer replaces future request history; restore with SessionManager.inMemory(cwd, { id }, entries), navigate with session.navigateTree(), or append through session.sessionManager and call session.refreshContext().
  • Expanded TurnEndEvent with required boundary fields and added AgentBeforeSettleEvent to the exported ExtensionEvent union. Consumers constructing events or exhaustively switching on ExtensionEvent must handle the new shapes. ExtensionRunner.emit() no longer accepts turn_end; host integrations dispatch actionable boundaries with emitBoundary(baseEvent, buildContext).
  • Deferred runs requested from agent_settled handlers until all settled handlers finish. Handlers still observe ctx.isIdle() === true, but no longer see a reentrant agent_start during the same notification dispatch.

Added

  • Added append-only model-context edits. For example, sessionManager.appendContextEdit(entryId, null) omits one message from future provider context without changing raw history, usage, or UI history.
  • Added actionable turn_end and agent_before_settle extension boundaries. Return { entries: [...event.entries, draft], continue: true } to persist structural entries in order and ensure one next provider request without changing steering or follow-up scheduling.
  • Added retain-none compaction input: sessionManager.appendCompaction(summary, null, tokensBefore) stores the compaction's own ID as its kept boundary.
  • Added the context_with_system extension event, which runs after context handlers on the full transcript including system messages and sends its result verbatim. See context_with_system.
  • Added per-model image resize profiles through inputLimits.images.resize in models.json, applied to file attachments, image reads, and tool-result images (#9631).

Fixed

  • Fixed string context-edit replacements producing invalid assistant and tool-result message content instead of text blocks.
  • Fixed context-invisible boundary metadata and replacement edits causing newly appended or replaced input to be summarized before its first provider request.
  • Fixed edited-context accounting both discarding valid assistant usage captured after the latest context edit and reusing that usage after a later compaction made it stale.
  • Fixed selected error retries and final length/overflow recovery retaining abandoned model attempts in future provider context; post-run recovery omissions are now persisted without hiding raw transcript history or changing queue scheduling.
  • Fixed context handlers that filter or slice messages dropping the prompt and tool declarations, which after extension-driven compaction left requests without built-in tools or made Codex emit raw tool-call text. Handlers no longer see system messages; Pi restores the prompt and tool state after they run. See context (#9789, #9822).
  • Fixed /bug allowing uploads in offline mode while preserving local zip exports (#9841 by @christianklotz).
  • Fixed idle prompt-cache warming rebuilding expired caches when its timer or an extension decision is delayed.
  • Improved crash diagnostics with hints identifying loaded extensions that appear in the stack trace.
  • Fixed text files beginning with GIF being misclassified as images and omitted from read and CLI @file input (#9755).
  • Fixed malformed prompt template frontmatter being silently ignored instead of reported as a resource warning (#9830 by @christianklotz).
  • Fixed inherited unknown OpenAI-compatible Chat Completions endpoints receiving strict tool schemas unless they explicitly advertise support (#9816).
