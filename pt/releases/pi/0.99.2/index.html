pi v0.99.2

Novos recursos

  • Servidores MCP ficam fora do caminho: servidores com exposição padrão codemode não estão mais listados na descrição codemode e não bloqueiam mais o primeiro prompt. Eles aparecem em uma breve seção de prompt do sistema e os scripts encontram suas ferramentas com searchTools() e describeNamespace(). Consulte Controlar a exposição da ferramenta.
  • Mais opções de autenticação MCP: oauth.clientName para servidores que aceitam apenas OAuth clients conhecidos e "auth": { "provider": "<provider>" } para autenticar servidores HTTP com o token /login de um provedor. Consulte Autenticar com OAuth.
  • Federação de identidade da carga de trabalho antrópica a partir das variáveis ​​de ambiente antrópicas SDK. Consulte Usar uma chave API do ambiente.
  • /reload ativa ferramentas recém-adicionadas à configuração defaultTools. Consulte Ferramentas.

Adicionado

  • Adicionado um campo description para servidores MCP (pi mcp add --description), mostrado com o servidor no prompt do sistema e usado para classificar suas ferramentas na pesquisa de ferramentas, e um auxiliar de modo de código describeNamespace(name) que retorna instruções e nomes de ferramentas de um namespace. describeNamespace() e searchTools() aceitam um namespace como mcp__dev-radius, mcp__dev_radius, dev-radius ou dev_radius.
  • Adicionada uma configuração oauth.clientName para servidores MCP (pi mcp add --oauth-client-name) para alterar o nome client enviado durante o registro OAuth client, ​​para servidores que aceitam apenas clients conhecidos (#10226).
  • Adicionado "auth": { "provider": "<provider>" } para servidores HTTP MCP para enviar o token /login atual de um provedor como token de portador em vez de usar MCP OAuth. O token é lido em cada solicitação, portanto, aplicam-se atualizações do provedor. Permitido apenas no mcp.json global e em extensões, e requer https, exceto em hosts de loopback.
  • Adicionada federação de identidade de carga de trabalho antrópica das variáveis ​​de ambiente ANTHROPIC_FEDERATION_RULE_ID, ANTHROPIC_ORGANIZATION_ID e ANTHROPIC_IDENTITY_TOKEN_FILE (consulte Provedores) (#10177, #10242 por @philfreo).
  • /reload agora permite ferramentas recentemente adicionadas à configuração defaultTools. As ferramentas removidas permanecem ativadas, as ferramentas desligadas durante a sessão permanecem desativadas, a menos que sejam adicionadas recentemente, e --tools, --no-tools e --no-builtin-tools ainda substituem a configuração (#10245).

Alterado

  • Servidores MCP com exposição padrão codemode não aparecem mais na descrição codemode; os scripts os encontram com searchTools(). codemode-deferred agora é um apelido para codemode. Use a exposição direct para ferramentas que o modelo deve ver sem pesquisar (#10212).
  • A descrição do codemode não inclui mais ferramentas adiadas, contagens de ferramentas ou instruções do servidor MCP, portanto não muda mais quando os servidores MCP se conectam ou alteram suas ferramentas. A descrição do tool_search não lista mais os servidores cujas ferramentas ele pode carregar, pelo mesmo motivo. Os servidores são listados em uma seção de prompt do sistema mcp_servers com um resumo de uma linha, atualizado no início de cada prompt; uma seção alterada é anexada à conversa. Os scripts leem as instruções do servidor com describeNamespace() (#10212).
  • O primeiro prompt não espera mais por servidores MCP sem ferramentas direct. Eles se conectam em segundo plano e são esperados quando um script de modo de código os nomeia, um script pesquisa ferramentas ou tool_search é executado (#10212).

Corrigido

  • Corrigidas novas sessões ignorando intermitentemente o modelo padrão salvo ou avisando que nenhum modelo está disponível, quando pertence a um provedor nativo registrado em extensão com uma credencial armazenada (#9962, #10190 por @davidbrai).
  • Corrigido o URL de login do /mcp que não era clickable ao passar pelas linhas, emitindo-o como um hiperlink de terminal com uma linha Cmd/Ctrl+click to open como /login (#10186).
  • Correção do modo de código image() que aceitava dados base64 mal formados ou tipos de imagem não suportados, que persistiam em um bloco de imagem inválido que fazia com que todas as solicitações posteriores do provedor falhassem com HTTP 400 (#10215).
  • Corrigida a falha do modo de código ao iniciar seu script de trabalho a partir do executável independente do Windows (#10204).
  • Corrigida a lentidão do envio de prompt com a duração da sessão, porque a resolução da seleção do modelo da sessão consultava o catálogo de modelos uma vez por mensagem do assistente (#10198).
  • Corrigida a lentidão nas pesquisas de modelo para provedores com um catálogo pi.dev atualizado, porque a fusão de modelos de catálogo remoto demorava um tempo quadrático.
  • Corrigidos os exemplos de extensão built-in-tool-renderer.ts e minimal-mode.ts, removendo os resumos e diretrizes das ferramentas integradas do prompt do sistema (#10072, #10193 por @christianklotz).
  • Correção da detecção de estouro de contexto para erros Prompt exceeds max length do endpoint Z.AI CN (#10208).
  • Corrigidas falhas nas solicitações Antrópicas quando um esquema de ferramenta utiliza palavras-chave Rejeições de uso estrito de ferramenta Antrópica, como minimum/maximum; essas ferramentas agora são enviadas de forma não estrita (#9953).
  • O provedor corrigido tenta disparar imediatamente quando um cabeçalho Retry-After contém uma data não analisável; eles agora usam espera exponencial (#9571).
  • Corrigidos comandos de extensão registrados sem nome de string ou manipulador travando pi ao digitar /; a extensão agora falha ao carregar com um erro (#10054).
  • Corrigidos resultados recolhidos das ferramentas codemode e MCP preenchendo a tela quando a saída é uma linha longa, como JSON minificado. Assim como a saída do bash, a visualização agora está limitada a linhas quebradas em vez de linhas lógicas.
  • Corrigida a listagem de codemode.mode: "only" read, bash, edit e write na lista de ferramentas do prompt do sistema, embora as solicitações declarem apenas codemode (#10192).
  • Corrigidos scripts de modo de código chamando a ferramenta MCP errada quando dois nomes de ferramentas diferem apenas em - e _, como read-file e read_file. Como no Codex, os nomes de ferramentas e namespaces MCP agora substituem - por _ (mcp__my-server__x agora é mcp__my_server__x), todas as ferramentas de colisão de um servidor recebem um sufixo hash e nomes de servidores que diferem apenas em - e _ são rejeitados (#10239).

pi v0.99.2

New Features

  • MCP servers stay out of the way: servers with the default codemode exposure are no longer listed in the codemode description and no longer block the first prompt. They appear in a short system prompt section, and scripts find their tools with searchTools() and describeNamespace(). See Control tool exposure.
  • More MCP authentication options: oauth.clientName for servers that only accept known OAuth clients, and "auth": { "provider": "<provider>" } to authenticate HTTP servers with a provider's /login token. See Authenticate with OAuth.
  • Anthropic workload identity federation from the Anthropic SDK environment variables. See Use an API key from the environment.
  • /reload enables tools newly added to the defaultTools setting. See Tools.

Added

  • Added a description field for MCP servers (pi mcp add --description), shown with the server in the system prompt and used to rank its tools in tool search, and a describeNamespace(name) codemode helper that returns a namespace's instructions and tool names. describeNamespace() and searchTools() accept a namespace as mcp__dev-radius, mcp__dev_radius, dev-radius, or dev_radius.
  • Added an oauth.clientName setting for MCP servers (pi mcp add --oauth-client-name) to change the client name sent during OAuth client registration, for servers that only accept known clients (#10226).
  • Added "auth": { "provider": "<provider>" } for HTTP MCP servers to send a provider's current /login token as the bearer token instead of using MCP OAuth. The token is read on every request, so provider refreshes apply. Only allowed in the global mcp.json and from extensions, and requires https except on loopback hosts.
  • Added Anthropic workload identity federation from the ANTHROPIC_FEDERATION_RULE_ID, ANTHROPIC_ORGANIZATION_ID, and ANTHROPIC_IDENTITY_TOKEN_FILE environment variables (see Providers) (#10177, #10242 by @philfreo).
  • /reload now enables tools newly added to the defaultTools setting. Tools removed from it stay enabled, tools turned off during the session stay off unless newly added, and --tools, --no-tools, and --no-builtin-tools still override the setting (#10245).

Changed

  • MCP servers with the default codemode exposure no longer appear in the codemode description; scripts find them with searchTools(). codemode-deferred is now an alias for codemode. Use direct exposure for tools the model should see without searching (#10212).
  • The codemode description no longer includes deferred tools, tool counts, or MCP server instructions, so it no longer changes when MCP servers connect or change their tools. The tool_search description no longer lists the servers whose tools it can load, for the same reason. Servers are listed instead in an mcp_servers system prompt section with a one-line summary, updated at the start of each prompt; a changed section is appended to the conversation. Scripts read server instructions with describeNamespace() (#10212).
  • The first prompt no longer waits for MCP servers without direct tools. They connect in the background and are waited for when a codemode script names them, a script searches tools, or tool_search runs (#10212).

Fixed

  • Fixed new sessions intermittently ignoring the saved default model, or warning that no models are available, when it belongs to an extension-registered native provider with a stored credential (#9962, #10190 by @davidbrai).
  • Fixed the /mcp sign-in URL not being clickable when it wraps across lines, by emitting it as a terminal hyperlink with a Cmd/Ctrl+click to open line like /login (#10186).
  • Fixed codemode image() accepting malformed base64 data or unsupported image types, which persisted an invalid image block that made every later provider request fail with HTTP 400 (#10215).
  • Fixed codemode failing to start its script worker from the standalone Windows executable (#10204).
  • Fixed prompt submission slowing down with session length, because resolving the session's model selection looked up the model catalog once per assistant message (#10198).
  • Fixed model lookups slowing down for providers with a refreshed pi.dev catalog, because merging remote catalog models took quadratic time.
  • Fixed the built-in-tool-renderer.ts and minimal-mode.ts extension examples removing the built-in tools' summaries and guidelines from the system prompt (#10072, #10193 by @christianklotz).
  • Fixed context overflow detection for Z.AI CN endpoint Prompt exceeds max length errors (#10208).
  • Fixed Anthropic requests failing when a tool schema uses keywords Anthropic strict tool use rejects, such as minimum/maximum; such tools are now sent non-strict (#9953).
  • Fixed provider retries firing immediately when a Retry-After header contains an unparseable date; they now use exponential backoff (#9571).
  • Fixed extension commands registered without a string name or handler crashing pi when typing /; the extension now fails to load with an error instead (#10054).
  • Fixed collapsed codemode and MCP tool results filling the screen when the output is one long line, such as minified JSON. Like bash output, the preview is now limited to wrapped lines instead of logical lines.
  • Fixed codemode.mode: "only" listing read, bash, edit, and write in the system prompt's tool list although requests only declare codemode (#10192).
  • Fixed codemode scripts calling the wrong MCP tool when two tool names differ only in - and _, such as read-file and read_file. Like in Codex, MCP tool and namespace names now replace - with _ (mcp__my-server__x is now mcp__my_server__x), colliding tools of a server all get a hash suffix, and server names that differ only in - and _ are rejected (#10239).
