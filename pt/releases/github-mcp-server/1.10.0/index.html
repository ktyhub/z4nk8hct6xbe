github-mcp-servidor v1.10.0

Destaques

v1.10.0 é uma versão substancial de segurança, confiabilidade e compatibilidade para o servidor GitHub MCP.

Mais seguro por padrão

  • Adicionada exclusão confirmada de repositório com elicitação de formulário e estado protegido de multi-ida e volta (#3076).
  • Credenciais de portador restritas para autoridades GitHub configuradas (#3056).
  • HTTPS aplicado para hosts corporativos GitHub (#3069).
  • Configuração estática inválida do --tools falhou ao fechar (#3050).
  • Bloqueio reforçado, limites de solicitação, isolamento de cache, passagem de URL e limpeza de resposta (#3109, #3112, #3113, #3111, #3108, #3114, #3110).

Melhor compatibilidade com o GitHub Enterprise Server

  • list_issues e search_issues agora são degradados com segurança quando os tipos GraphQL de campo personalizado estão indisponíveis (#3086, #2897).
  • list_issues agora retorna logins de destinatários e matrizes vazias estáveis ​​para problemas não atribuídos (#3064).
  • Falhas de validação expõem detalhes seguros do conjunto de regras quando fornecidos pelo GitHub API (#3081).

Operações de arquivo de repositório mais seguras

  • get_file_contents agora identifica links simbólicos e rotula claramente o conteúdo desreferenciado.
  • Gravações de links simbólicos exigem aceitação explícita de allow_symlink_write: true (#3071).
  • Corrigidos recursos MCP binários sendo codificados em base64 duas vezes (#3098).

Contratos de ferramentas mais confiáveis

  • Modos de entrada add_issue_comment corrigidos (#3085).
  • issue_write.issue_fields[].delete: false agora é um ambiente autônomo válido para clients de esquema estrito (#3077).
  • Ferramentas de parâmetro zero aceitam uma propriedade arguments omitida enquanto rejeitam null explícito e JSON malformado (#3099).
  • Ferramentas de assinatura de notificação anunciam explicitamente comportamento destrutivo (#2936).
  • As negações de solicitação de revisão do copiloto agora retornam orientações acionáveis ​​em vez de um simples 404 (#3119).

Projetos, Ações e eficiência

  • Adicionadas operações de ciclo de vida de visualização do projeto e configuração de campo visível (#2961, #2988).
  • Ações reduzidas e outras cargas de resposta bem-sucedidas (#3047, #3055).
  • Melhor desempenho de higienização e dependências de UI/construção atualizadas (#3120, #3100).

Mudanças de comportamento a serem observadas

  • Nomes estáticos desconhecidos do --tools agora impedem a inicialização.
  • As atualizações de links simbólicos exigem aceitação explícita.
  • As solicitações não podem relaxar o bloqueio imposto pelo servidor.
  • Corpos de solicitação HTTP superdimensionados são rejeitados antecipadamente.
  • add_issue_comment realiza validação de modo mutuamente exclusivo mais rigorosa.
  • A exclusão do repositório requer um MCP client moderno elegível, suporte à elicitação de formulário e os escopos apropriados.

github-mcp-server v1.10.0

Highlights

v1.10.0 is a substantial security, reliability, and compatibility release for the GitHub MCP Server.

Safer by default

  • Added confirmed repository deletion with form elicitation and protected multi-round-trip state (#3076).
  • Restricted bearer credentials to configured GitHub authorities (#3056).
  • Enforced HTTPS for GitHub Enterprise hosts (#3069).
  • Made invalid static --tools configuration fail closed (#3050).
  • Hardened lockdown, request limits, cache isolation, URL traversal, and response sanitization (#3109, #3112, #3113, #3111, #3108, #3114, #3110).

Better GitHub Enterprise Server compatibility

  • list_issues and search_issues now degrade safely when issue custom-field GraphQL types are unavailable (#3086, #2897).
  • list_issues now returns assignee logins and stable empty arrays for unassigned issues (#3064).
  • Validation failures expose safe ruleset details when supplied by the GitHub API (#3081).

Safer repository file operations

  • get_file_contents now identifies symbolic links and clearly labels dereferenced content.
  • Symbolic-link writes require explicit allow_symlink_write: true opt-in (#3071).
  • Fixed binary MCP resources being base64-encoded twice (#3098).

More reliable tool contracts

  • Corrected add_issue_comment input modes (#3085).
  • issue_write.issue_fields[].delete: false is now a valid no-op for strict-schema clients (#3077).
  • Zero-parameter tools accept an omitted arguments property while rejecting explicit null and malformed JSON (#3099).
  • Notification subscription tools explicitly advertise destructive behavior (#2936).
  • Copilot review-request denials now return actionable guidance instead of a bare 404 (#3119).

Projects, Actions, and efficiency

  • Added Project view lifecycle operations and visible-field configuration (#2961, #2988).
  • Reduced Actions and other successful response payloads (#3047, #3055).
  • Improved sanitization performance and refreshed UI/build dependencies (#3120, #3100).

Behavior changes to note

  • Unknown static --tools names now prevent startup.
  • Symbolic-link updates require explicit opt-in.
  • Requests cannot relax server-enforced lockdown.
  • Oversized HTTP request bodies are rejected early.
  • add_issue_comment performs stricter mutually exclusive mode validation.
  • Repository deletion requires an eligible modern MCP client, form elicitation support, and the appropriate scopes.
