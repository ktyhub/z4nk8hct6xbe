accelerate v1.14.0

Highlights

  • FSDP2 training correctness — FSDP2 now casts models to a uniform dtype before sharding, fully shards embeddings and normalization layers, and excludes frozen non-floating Params4bit from wrapping (#3985, #4015, #3987). Mixed-precision training and QLoRA should avoid these known sharding assertions and crashes without manual workarounds.
  • FSDP2 loading and conversion — Full-state loading now uses key-based matching with corrected dtype and Params4bit handling (#3982, #4021, #3981). Auto-wrap respects _no_split_modules, and prepare_model() prevents double-wrapping (#3999, #3977). The to-fsdp2 conversion drops unsupported FSDP1-only keys instead of leaking them into FSDP2 (#4065), so those options are no longer forwarded.
  • Expanded hardware support — Accelerate now supports end-to-end AMD ROCm workflows (#4025), while Neuron pads all-gather and broadcast operations to reduce recompilation (#4000). For XPU, pytorch-triton-xpu is renamed to triton-xpu (#4007); update any explicit dependency references.
  • Quantized offloading — TorchAO offloading is now supported (#3973), int8 offload-hook statistics are restored correctly (#4044), and keep_in_fp32_modules works with tied weights in load_and_quantize_model (#4043). This reduces precision surprises when offloading quantized models with shared parameters.
  • Distributed data edge cases — BatchSamplerShard supports dynamic batch sizes with even_batches (#3969). Fixes also remove unintended padding when processes outnumber samples (#4052) and correct iterable-dataset sharding when shard and process counts match (#3958). Pipelines using workarounds should recheck sample counts and padding assumptions.
  • Breaking changes — None declared upstream.

FSDP2 Improvements

This release brings a large batch of FSDP2 fixes and quality-of-life improvements: correct dtype handling on load, sharding of embeddings/norms, QLoRA crash prevention, and a more robust auto-wrap policy.

  • Fsdp2 fully_shard embedding and norm by @SunMarc in #4015
  • Fix fsdp2 load full state dict dtype mismatch by @SunMarc in #4021
  • Fix region compilation fsdpv2 by @SunMarc in #4022
  • [FSDP2] Cast model to uniform dtype before fully_shard to fix mixed-dtype AssertionError by @roycho96 in #3985
  • [FSDP2] Auto-exclude non-floating frozen Params4bit from fully_shard to prevent QLoRA crash by @roycho96 in #3987
  • fix(FSDP2): auto-wrap policy ignoring _no_split_modules fallback by @JohnGiorgi in #3999
  • fix: use key-based matching in fsdp2_load_full_state_dict by @roycho96 in #3982
  • fix: add missing model_has_params4bit guard to fsdp2_load_full_state_dict call by @roycho96 in #3981
  • Fix to-fsdp2: drop REMOVED / NOT_YET_IMPLEMENTED FSDP1 keys instead of leaking them by @lollinng in #4065
  • Prevent double-wrapping models in prepare_model() by @joshuaswanson in #3977

AMD ROCm support

Accelerate now works end-to-end on AMD ROCm devices. Thanks @Abdennacer-Badaoui!

  • Make accelerate work end-to-end on AMD ROCm by @Abdennacer-Badaoui in #4025

Neuron
