#acelerar v1.16.0

Suporte ao acelerador

O Accelerate agora usa torch.accelerator de forma mais ampla para oferecer suporte a back-ends registrados do PyTorch sem exigir uma ramificação separada específica do dispositivo em toda a biblioteca. As integrações existentes mantêm seus APIs nativos quando necessário para compatibilidade. Isso também inclui melhorias iniciais para uso de TPU de chip único por meio de torch-tpu. O suporte mais amplo à TPU continua em andamento.

  • Simplifique a descoberta de back-end e estenda o suporte ao acelerador personalizado — @SunMarc (#4335, #4547).
  • Correção de pesos vinculados, carregamento de tensores de segurança, relatórios de memória e validação FP16 para uso de torch-tpu de chip único - @tengomucho (#4570).

Melhorias no iniciador

accelerate launch agora sai de forma limpa quando interrompido com Ctrl+C ou SIGTERM, limpando trabalhadores infantis. Os lançamentos distribuídos também lidam com sinais de desligamento do torchrun sem um rastreamento extra do iniciador.

  • Limpe processos filhos em caso de interrupção e melhore o comportamento de --quiet e --debug — @SunMarc (#4573).
  • Revela erros de processo filho em simple_launcher enquanto preserva a saída ao vivo — @albertvillanova (#4305). ##FSDP Várias correções abordam o carregamento eficiente de RAM, incluindo compatibilidade com modelos de carregamento de Transformers no metadispositivo em classificações diferentes de zero. O FSDP1 agora reconecta as referências do otimizador quando a inicialização substitui metaparâmetros, e o FSDP2 distingue corretamente esses parâmetros ao mapeá-los para suas substituições fragmentadas. O FSDP2 também suporta a preparação de um modelo sem otimizador, permitindo fluxos de trabalho como Trainer.evaluate() antes do treinamento.
  • Correção da inicialização de metaparâmetros FSDP e mapeamento do otimizador — @SunMarc (#4576).
  • Corrigido o carregamento eficiente de RAM do FSDP2 de parâmetros e buffers ignorados - @SunMarc (#4568).
  • Corrigido o sharding FSDP2 quando o checkpoint de ativação está habilitado — @SunMarc @Titus-von-Koeller (#4575).
  • Permitir preparar um modelo sem otimizador em FSDP2 — @qgallouedec (#4519). 🚨🚨🚨 ## Requisitos e remoções Accelerate agora requer Python 3.11+ e PyTorch 2.6+. Esta versão também remove várias integrações obsoletas e APIs.
  • Aumente a versão mínima Python para 3.11 e a versão PyTorch para 2.6 - @SunMarc (#4459, #4461).
  • Remova as integrações PiPPy e MS-AMP — @SunMarc (#4462, #4463).
  • Remova o FP8RecipeKwargs obsoleto. Use AORecipeKwargs para TorchAO ou TERecipeKwargs para Transformer Engine - @SunMarc (#4464).

accelerate v1.16.0

Highlights

  • Hard version floor and removed integrations (breaking) — This release drops Python <3.11 and PyTorch <2.6 (#4459, #4461), so pin your environments before upgrading. Two integrations are gone entirely: PiPPy (#4462) and MS-AMP (#4463), meaning any pipeline depending on them must be reworked or stay on v1.15. The deprecated FP8RecipeKwargs is also removed (#4464); migrate to AORecipeKwargs (TorchAO) or TERecipeKwargs (Transformer Engine) or your config will fail to import.
  • Unified accelerator discovery and first single-chip TPU support — By routing backend detection through torch.accelerator (#4335, #4547), custom/registered PyTorch backends no longer require device-specific branches throughout the library — a meaningful simplification if you maintain a non-CUDA integration. Initial torch-tpu support lands with fixes for tied weights, safetensors loading, memory reporting, and FP16 validation (#4570); treat TPU as early-stage (broader support is still in progress), but the native-API compatibility path means existing integrations keep working.
  • FSDP meta-device loading and optimizer-free prep — RAM-efficient loading is substantially repaired: meta parameters on nonzero ranks are now handled for Transformers-style meta-device loading, with FSDP1 reconnecting optimizer references and FSDP2 distinguishing meta params from their sharded replacements (#4576), plus fixes for ignored params/buffers (#4568) and activation checkpointing (#4575). FSDP2 can now prepare a model without an optimizer (#4519), which finally makes patterns like Trainer.evaluate() before training possible; combined with restored FP16 GradScaler state (#4291) and preserved output/loss dtypes (#4403), this is a strong release for memory-constrained fine-tuning.
  • Cleaner launcher shutdown and error reporting — accelerate launch now exits cleanly on Ctrl+C/SIGTERM and reaps child workers rather than orphaning them, and torchrun shutdown no longer emits a spurious launcher traceback (#4573); simple_launcher also surfaces child-process errors while keeping live output (#4305). The practical win is more reliable distributed job control and debuggable failures in CI and on preemptible clusters.
  • Behavioral and correctness fixes worth reviewing — accelerate launch no longer forces torch.compile(dynamic=False) (#4254), so dynamic-shape recompiles you previously suppressed may reappear — watch compile times. A VRAM leak from cached INT8 weights during CPU/disk offload is fixed (#4325), as is balanced_low_0 resolving memory limits by position instead of device ID (#4298) and memory sizing for sub-byte/packed dtypes (#4237). Gradient clipping is now aligned with Transformers (#4266), tensor parallelism can coexist with replicated data parallelism (#4193), and skip_first_batches preserves dataloader options like drop_last and device mesh (#4296) — all of which can subtly change training numerics or performance, so validate against a known-good run after upgrading.

Accelerator support

Accelerate now uses torch.accelerator more broadly to support registered PyTorch backends without requiring a separate device-specific branch throughout the library. Existing integrations retain their native APIs where needed for compatibility.

This also includes initial improvements for single-chip TPU usage through torch-tpu. Broader TPU support remains in progress.

  • Simplify backend discovery and extend custom accelerator support — @SunMarc (#4335, #4547).
  • Fix tied weights, safetensors loading, memory reporting, and FP16 validation for single-chip torch-tpu usage — @tengomucho (#4570).

Launcher improvements

accelerate launch now exits cleanly when interrupted with Ctrl+C or SIGTERM, cleaning up child workers. Distributed launches also handle torchrun shutdown signals without an extra launcher traceback.

  • Clean up child processes on interruption and improve --quiet and --debug behavior — @SunMarc (#4573).
  • Surface child-process errors in simple_launcher while preserving live output — @albertvillanova (#4305).

FSDP

Several fixes address RAM-efficient loading, including compatibility with Transformers loading models onto the meta device on nonzero ranks. FSDP1 now reconnects optimizer references when initialization replaces meta parameters, and FSDP2 correctly distinguishes those parameters when mapping them to their sharded replacements.

FSDP2 also supports preparing a model without an optimizer, allowing workflows such as Trainer.evaluate() before training.

  • Fix FSDP meta-parameter initialization and optimizer mapping — @SunMarc (#4576).
  • Fix FSDP2 RAM-efficient loading of ignored parameters and buffers — @SunMarc (#4568).
  • Fix FSDP2 sharding when activation checkpointing is enabled — @SunMarc @Titus-von-Koeller (#4575).
  • Allow preparing a model without an optimizer under FSDP2 — @qgallouedec (#4519).

🚨🚨🚨 ## Requirements and removals

Accelerate now requires Python 3.11+ and PyTorch 2.6+. This release also removes several deprecated integrations and APIs.

  • Raise the minimum Python version to 3.11 and PyTorch version to 2.6 — @SunMarc (#4459, #4461).
  • Remove the PiPPy and MS-AMP integrations — @SunMarc (#4462, #4463).
  • Remove the deprecated FP8RecipeKwargs. Use AORecipeKwargs for TorchAO or TERecipeKwargs for Transformer Engine — @SunMarc (#4464).
