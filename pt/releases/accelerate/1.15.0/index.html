#acelerar v1.15.0

v1.15.0: memória de ativação FSDP2, melhorias no dtensor

##FSDP2 Um grande lote de FSDP2 funciona nesta versão: duas correções que cortam a memória de ativação em longos comprimentos de sequência, suporte de incorporação vinculada na tocha >= 2.13 e uma rodada de correção de pontos de verificação e correções de escala. O ponto de verificação de ativação envolve cada filho da camada correspondente (self_attn, mlp, as normas) em vez da própria camada, de modo que cada ativação entre filhos permanece salva para trás. Agora envolve a camada. Há também um novo activation_checkpointing_offload somente FSDP2, que move as entradas restantes do ponto de verificação por camada para a memória da CPU fixada. Os gradientes são exatamente aqueles do checkpoint de ativação simples:

# fsdp2.yaml
fsdp_config:
  fsdp_version: 2
  fsdp_auto_wrap_policy: TRANSFORMER_BASED_WRAP
  fsdp_activation_checkpointing: true
  fsdp_activation_checkpointing_offload: true

accelerate launch --config_file fsdp2.yaml train.py
  • Ponto de verificação de ativação FSDP2: envolva a própria camada do transformador correspondente, não cada um de seus filhos por @qgallouedec em #4172
  • Adicionar FSDP2 activation_checkpointing_offload: descarregar entradas de camada com ponto de verificação para memória de CPU fixada por @qgallouedec em #4175
  • Corrigir modelos de incorporação vinculada FSDP2 na tocha >= 2.13: coloque a incorporação de saída no mesmo grupo full_shard de @qgallouedec em #4171
  • Correção de FSDP2/PEFT/FULL_STATE_DICT eliminando todos os fragmentos do adaptador de classificação, exceto classificação 0 por @AmineDiro em #4206
  • FSDP2: torch.save/load por classificação para SHARDED_STATE_DICT para corrigir o tempo limite do ponto de verificação de 2800+ NPU por @gygdh-001 em #4105
  • Corrigida a resolução do caminho do ponto de verificação fragmentado FSDP por @HaomingSong em #4119
  • Gera um erro claro quando o FSDP está habilitado em uma malha sem dimensão de shard por @qgallouedec em #4180

DTensor

Duas correções para modelos fragmentados por DTensor, que você atinge com FSDP2, paralelismo de tensor ou qualquer configuração de paralelismo ND: o gradiente clipping não falha mais na operação foreach quando tensores simples e DTensors são misturados, e prepare_model deixa um modelo já fragmentado onde está:

  • Suporte à norma de graduação Clip para dtensores por @michaelbenayoun em #4219
  • prepare_model: não mova modelos fragmentados do DTensor para o dispositivo por @qgallouedec em #4181

Descarregamento e Quantização

Um modelo inteiro agora pode ser despachado para disco, incluindo pesos amarrados — útil para ferramentas como llm-compressor que compactam modelos grandes em máquinas que não conseguem suportá-los:

  • [Offloading] Suporte para descarregamento completo de disco por @kylesayrs em #4083
  • Corrigida falha de descarregamento de disco em tensores FP8 por @shoemoney em #4151

Rastreadores

Rastreadores personalizados podem ser registrados por nome e então selecionados no log_with= como qualquer outro integrado:

from accelerate import Accelerator
from accelerate.tracking import register_tracker_class

register_tracker_class(MyTracker)  # MyTracker.name == "my_tracker"
accelerator = Accelerator(log_with="my_tracker")

accelerate v1.15.0

Highlights

  • FSDP2 activation memory at long sequences — Activation checkpointing now wraps the matched transformer layer itself instead of wrapping each child (self_attn, mlp, norms), so inter-child activations are no longer retained for backward (#4172). New FSDP2-only fsdp_activation_checkpointing_offload moves the remaining per-layer checkpoint inputs to pinned CPU memory with gradients identical to plain AC (#4175) — enable via fsdp_config.fsdp_activation_checkpointing_offload: true. Watch the trade-off: this buys memory at long context, not speed, since it adds CPU↔GPU transfers.

  • FSDP2 tied embeddings & checkpoint reliability — Tied-embedding models now work on torch ≥ 2.13 by placing the output embedding in the same fully_shard group (#4171). Checkpoint correctness gets several fixes: FULL_STATE_DICT with PEFT no longer discards every rank's adapter shard but rank 0 (#4206), SHARDED_STATE_DICT switches to per-rank torch.save/load to eliminate 2800+ NPU checkpoint timeouts (#4105), sharded path resolution is corrected (#4119), and enabling FSDP on a mesh with no shard dim now raises a clear error (#4180).

  • DTensor-sharded models — Relevant if you use FSDP2, tensor parallelism, or any N-D parallelism: gradient clipping no longer crashes on the foreach op when plain tensors and DTensors are mixed (#4219), and prepare_model now leaves an already-sharded model in place instead of moving it to the device (#4181).

  • Full disk offload & FP8 quantization — An entire model, including tied weights, can now be dispatched to disk (#4083), which is what makes tools like llm-compressor usable on machines that can't hold the model in memory. A companion fix stops disk offload from crashing on FP8 tensors (#4151).

  • Custom trackers and device coverage — register_tracker_class lets you register a tracker by name and select it through log_with= like a built-in (#4060), and MLFLOW_NESTED_RUN can finally be turned off (#4223). On devices: a neuron dynamo backend makes --torch-compile work with the Transformers Trainer (#4097, #4218), MPS is correctly reported in accelerate env and its OOMs handled by find_executable_batch_size (#4158, #4221, #4227). One gotcha: context parallelism is now explicitly refused for models with sliding-window or chunked attention (#4177).

  • Breaking changes — None; this release is additive and bug-fix only.

v1.15.0: FSDP2 activation memory, dtensor improvements

FSDP2

A large batch of FSDP2 work this release: two fixes that cut activation memory at long sequence lengths, tied-embedding support on torch >= 2.13, and a round of checkpointing correctness and scale fixes.

Activation checkpointing was wrapping each child of the matched layer (self_attn, mlp, the norms) instead of the layer itself, so every inter-child activation stayed saved for backward. It now wraps the layer.

There's also a new FSDP2-only activation_checkpointing_offload, which moves the remaining per-layer checkpoint inputs to pinned CPU memory. Gradients are exactly those of plain activation checkpointing:

# fsdp2.yaml
fsdp_config:
  fsdp_version: 2
  fsdp_auto_wrap_policy: TRANSFORMER_BASED_WRAP
  fsdp_activation_checkpointing: true
  fsdp_activation_checkpointing_offload: true

accelerate launch --config_file fsdp2.yaml train.py
  • FSDP2 activation checkpointing: wrap the matched transformer layer itself, not each of its children by @qgallouedec in #4172
  • Add FSDP2 activation_checkpointing_offload: offload checkpointed layer inputs to pinned CPU memory by @qgallouedec in #4175
  • Fix FSDP2 tied-embedding models on torch >= 2.13: put the output embedding in the same fully_shard group by @qgallouedec in #4171
  • Fix FSDP2/PEFT/FULL_STATE_DICT dropping every rank's adapter shard except rank 0 by @AmineDiro in #4206
  • FSDP2: per-rank torch.save/load for SHARDED_STATE_DICT to fix 2800+ NPU checkpoint timeout by @gygdh-001 in #4105
  • Fix FSDP sharded checkpoint path resolution by @HaomingSong in #4119
  • Raise a clear error when FSDP is enabled on a mesh with no shard dimension by @qgallouedec in #4180

DTensor

Two fixes for DTensor-sharded models, which you hit with FSDP2, tensor parallelism, or any N-D parallelism setup: gradient clipping no longer fails on the foreach op when plain tensors and DTensors are mixed, and prepare_model leaves an already-sharded model where it is:

  • Clip grad norm support for dtensors by @michaelbenayoun in #4219
  • prepare_model: don't move DTensor-sharded models to the device by @qgallouedec in #4181

Offloading & Quantization

An entire model can now be dispatched to disk, including tied weights — useful for tools like llm-compressor that compress large models on machines that can't hold them:

  • [Offloading] Support full disk offloading by @kylesayrs in #4083
  • Fix disk offload crash on FP8 tensors by @shoemoney in #4151

Trackers

Custom trackers can be registered by name and then selected from log_with= like any built-in one:

from accelerate import Accelerator
from accelerate.tracking import register_tracker_class

register_tracker_class(MyTracker)  # MyTracker.name == "my_tracker"
accelerator = Accelerator(log_with="my_tracker")
  • Add register_tracker_class to register custom trackers by name by @javierdejesusda in #4060
  • Fix MLFLOW_NESTED_RUN never being able to turn nesting off by @yupengtang in #4223

Neuron gains a torch dynamo backend (so --torch-compile works with the Transformers Trainer) and MPS is now reported and handled properly by accelerate env and find_executable_batch_size.
