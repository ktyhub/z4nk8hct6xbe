#acelerar v1.11.0

Suporte TE MXFP8

Adicionamos suporte para MXFP8 em nossa integração com o TransformerEngine. Para usar isso, você precisa definir use_mxfp8_block_scaling em fp8_config. Consulte a documentação da nvidia [aqui]. (https://docs.nvidia.com/deeplearning/transformer-engine/user-guide/examples/fp8_primer.html#MXFP8-and-block-scaling)

  • Adicionado suporte para receita TE MXFP8 acelerada por @pstjohn em https://github.com/huggingface/accelerate/pull/3688

Treinamento FP16/BF16 para dispositivos MPS

O suporte BF16 e FP16 para dispositivos MPS finalmente chegou. Agora você pode passar no mixed_precision = "fp16" or "bf16" ao treinar em um Mac (fp16 requer tocha 2.8 e bf16 requer tocha 2.6)

  • Adicionado suporte bf16/fp16 para amplificador com dispositivo mps da @SunMarc no https://github.com/huggingface/accelerate/pull/3373

  • talento: permitir política de precisão mista como dtype por @kmehant em https://github.com/huggingface/accelerate/pull/3751

accelerate v1.11.0

Highlights

  • Python 3.10 minimum — Python 3.9 support is dropped following its EOL (#3809), so update CI images, deployment runtimes, and dependency constraints before upgrading. The deprecated FindTiedParametersResult type is also removed (#3786); remove imports or migrate annotations to the supported tied-parameter API.

  • Mixed precision on Apple MPS — MPS training now accepts mixed_precision="fp16" or "bf16" (#3373). FP16 requires PyTorch 2.8+, while BF16 requires 2.6+; verify your Torch build before enabling either. This brings Apple Silicon training configurations closer to CUDA mixed-precision workflows.

  • Transformer Engine MXFP8 — Set use_mxfp8_block_scaling in fp8_config to use the MXFP8 block-scaling recipe (#3688). This changes FP8 quantization and scaling behavior rather than being a drop-in speed tweak, so validate accuracy and throughput against NVIDIA’s hardware and Transformer Engine requirements.

  • FSDPv2 feature parity — FSDPv2 gains ignored_params support (#3731), correctly suppresses gradient synchronization inside no_sync() via set_requires_gradient_sync(False) (#3762), and accepts mixed-precision dtype strings through the CLI or fsdp_config (#3751). This avoids unnecessary gradient all-reduces during accumulation and simplifies configuration, but confirm that string-selected dtypes match your hardware and autocast policy.

  • Distributed reliability and memory — CPU-RAM-efficient loading now covers ND and HSDP parallelism (#3740), while fixes address multi-node CUDA invalid-device-ordinal errors (#3779) and XPU INT64 all_gather failures (#3756). Large sharded workloads should face less host-memory pressure and fewer startup or collective-operation failures.

TE MXFP8 support

We've added support for MXFP8 in our TransformerEngine integration. To use that, you need to set use_mxfp8_block_scaling in fp8_config. See nvidia docs [here]. (https://docs.nvidia.com/deeplearning/transformer-engine/user-guide/examples/fp8_primer.html#MXFP8-and-block-scaling)

  • Add support for TE MXFP8 recipe in accelerate by @pstjohn in https://github.com/huggingface/accelerate/pull/3688

FP16/BF16 Training for MPS devices

BF16 and FP16 support for MPS devices is finally here. You can now pass mixed_precision = "fp16" or "bf16" when training on a mac (fp16 requires torch 2.8 and bf16 requires torch 2.6)

  • Add bf16/fp16 support for amp with mps device by @SunMarc in https://github.com/huggingface/accelerate/pull/3373

FSDP updates

The following PRs add respectively support to ignored_params and no_sync() for FSDPv2:

  • feat: add ignored_params support for fsdp2 by @kmehant in https://github.com/huggingface/accelerate/pull/3731
  • fix: model.set_requires_gradient_sync(False) should be called to turn off gradient synchronization in FSDP2 by @EquationWalker in https://github.com/huggingface/accelerate/pull/3762

Mixed precision can now be passed as a dtype string from accelerate cli flag or fsdp_config in accelerate config file:

  • feat: allow mixed precision policy as dtype by @kmehant in https://github.com/huggingface/accelerate/pull/3751

Nd-parallel updates

  • Context Parallelism docs typos fixed by @sergiopaniego in https://github.com/huggingface/accelerate/pull/3761
