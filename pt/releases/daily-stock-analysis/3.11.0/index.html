daily_stock_análise v3.11.0

Destaques do lançamento

  • 🎨 O ambiente de trabalho da Web concluiu uma rodada de unificação da interface do usuário e atualizações de tema duplo - a página inicial, consulta de estoque, backtesting, páginas de posição e configurações foram ainda mais integradas em tokens de design unificados, superfícies de entrada e expressões de status; um tema completo de cores claras foi adicionado e a alternância de cores claras/escuras com um clique e o salvamento persistente são suportados.
  • 🤖 Os recursos do bot/agente são restaurados na ramificação principal — Comandos como /history, /strategies e /research são restaurados e /ask continua a suportar comparação de múltiplas cadeias e perspectivas de combinação; Os links de pesquisa profunda, monitoramento de eventos e pesquisa agendada são restaurados na linha principal.
  • 🔒 Aprimoramentos de segurança e sincronização de estabilidade de execução - Corrija o risco de desvio de limite atual do X-Forwarded-For, restaure o caminho de instalação oficial do PyPI do LiteLLM, a inicialização do Tushare não depende mais do SDK local e reduza a vulnerabilidade do Docker, empacotamento de desktop e reconstrução do ambiente.
  • 🖥️ Os detalhes de uso diário continuam a ser aprimorados — Corrigidos problemas como preenchimento automático e envio de ações de Hong Kong na página inicial, exibição do tema da tela inicial da página de login, sobreposição de nomes históricos de ações longas e interrupção de todo o envio de notificação quando a análise do Telegram Markdown falha.

Novos recursos

  • 🎨 Novo tema claro e alternância de tema duplo estão online - Um tema claro completo é adicionado ao ambiente de trabalho da Web e suporta alternância com um clique entre os modos claro e escuro na barra lateral; a seleção do tema será mantida e a preferência atual será mantida após a atualização da página. Esta atualização não é um ajuste parcial de cores, mas um conjunto completo de redesenhos de tema claro na hierarquia do cartão, contraste da borda, superfície de entrada, prompts de status e plano de fundo da página.
  • 🤖 Completar os recursos de Agente/Bot ausentes na ramificação principal — #648 / #649 foi reabastecido main: A restauração do bot /history, /strategies, /research, /ask mantém a comparação multi-cadeia e a perspectiva de combinação; a configuração do Deep Research e Event Monitor está novamente visível e editável na página de configurações da Web, agendamento O modo também se reconecta à pesquisa de alarmes de eventos.

Melhorias

  • 🖥️ As páginas principais são unificadas na mesma linguagem visual do ambiente de trabalho — Home / Chat / Backtest / Portfolio / Settings integra ainda tokens de design compartilhados, sistema de entrada input-surface, expressões de estado vazio/de erro e semântica de máscara de gaveta para reduzir a fragmentação visual e desvio de estilo privado local entre as páginas.
  • 💬 Aprimoramento da acessibilidade de interação e feedback para solicitações de ações — A página de solicitações de ações aprimorou a exportação de sessões, envio de notificações, cópia de mensagens, exclusão de histórico e prompts contextuais de acompanhamento; As operações de resposta de IA não dependem mais de passar o mouse e os botões principais podem ser acessados ​​diretamente em dispositivos com tela sensível ao toque e cenários de tela pequena.
  • 📊 As superfícies de página de backtest e posição e as expressões de status continuam a ser padronizadas — Os controles de filtro de página de backtest, status booleano, tabelas de resultados e cartões de resumo são unificados em primitivas de entrada/status compartilhadas; feedback de importação de página de posição, prompts de atualização de taxa de câmbio, status vazio e informações de aviso são consolidados em componentes compartilhados para reduzir a duplicação no nível da página.
  • 🧭 Otimização colaborativa de navegação e shell de página — A troca de tema da barra lateral, marca de canto de preenchimento de perguntas, máscara de gaveta móvel e contrato de rolagem de conteúdo principal são ainda mais unificados, e a experiência de troca de página da página inicial, estoque de perguntas e backtest no desktop e terminais móveis é mais estável.

Teste

  • 🧪 Aprimoramento de governança de interface de usuário e regressão de caminho crítico - Complementa testes de componentes para SidebarNav, ChatPage, BacktestPage e outros componentes e adiciona proteções de governança de interface de usuário para evitar continuamente que elementos interativos reintroduzam atributos nativos de title ou que estilos antigos de input-terminal reflitam. Atualize de forma síncrona a verificação relacionada à gaveta smoke / markdown para cobrir os principais links principais após a atualização do tema.

Correção

  • 🌗 A predefinição de tema padrão para a tela inicial da Web é escura — apps/dsa-web/index.html agora lerá as preferências de tema salvas localmente antes que o React seja montado; se não houver valor salvo, ele irá predefinir imediatamente dark para <html> e sincronizar color-scheme para evitar que o tema claro pisque na página inicial e na página de login primeiro.
  • 🔐 Fecho da camada de tema independente da página de login — A caixa de entrada da página de login, rótulo, botão de alternância e cópia do botão agora usam token visual --login-* independente e não herdam mais a cor de texto do tema claro/escuro global; mesmo que o navegador armazene em cache o tema claro, a página de login ainda mantém um visual escuro estável e um desempenho de entrada de senha ciano, evitando que pontos de senha e direitos autorais se tornem pretos.
  • 🖥️ Correção de entrada do código de ações de Hong Kong na página inicial — A caixa de entrada de análise da página inicial da Web agora pode aceitar corretamente os códigos de ações de Hong Kong e preencher automaticamente os itens de estoque de Hong Kong selecionados, preencher o 00700.HK / HK00700 e outros reconhecimentos de formato e evitar alarmes falsos de "Insira um código de estoque ou nome de estoque válido" ao enviar.
  • 🔒 Correção do valor X-Forwarded-For do limite de corrente de autenticação (CWE-345) (#841 / #842) — get_client_ip() mudou de tomar o valor mais à esquerda de X-Forwarded-For para o valor mais à direita para evitar que invasores contornem a proteção de força bruta forjando o primeiro balde limitador de corrente rotativa; afeta apenas o cenário de implantação do TRUST_X_FORWARDED_FOR=true e do proxy reverso confiável de camada única. O ambiente proxy multinível precisa ser avaliado e configurado de acordo com o documento de implantação.
  • 📦 Restaure a instalação oficial do PyPI do LiteLLM e bloqueie o limite superior de segurança — requirements.txt Reutilize o caminho de instalação oficial do PyPI do pip install litellm e aumente o limite superior de segurança do <1.82.7, mantendo o requisito mínimo histórico do >=1.80.10, para evitar a instalação acidental da versão arriscada do 1.82.7 / 1.82.8 que foi removida; Windows O script de empacotamento de desktop também recorre de forma síncrona ao link pip install -r requirements.txt padrão, reduzindo os custos de manutenção causados ​​por ramificações de download especiais.
  • 📨 A análise de Markdown do Telegram falha e volta para texto simples (correções #850) - src/notification_sender/telegram_sender.py agora removerá automaticamente parse_mode quando o Telegram retornar HTTP 400 e contiver erros de análise de can't parse entities / Markdown e, em seguida, tentará enviar novamente texto simples para evitar *ST e outro conteúdo de texto que causa diretamente a falha de toda a notificação.
  • 🔢 As cotações de mercado em tempo real de ações A retêm avisos de câmbio (correções #852) - DataFetcherManager e TushareFetcher agora manterão avisos explícitos de Xangai-Shenzhen, como SZ000001 / 000001.SZ. A versão antiga do ramo de downgrade do mercado em tempo real Tushare não julga mais Shenzhen 000001 como sh000001 no Shanghai Composite Index.
  • 🎯 Os pontos de compra subótimos do multiagente não copiam mais cegamente os pontos de compra ideais (correções #851) - Quando o resultado do multiagente não possui secondary_buy independente, o painel agora dá prioridade à exibição de N/A em vez de copiar o valor de fallback para ser exatamente o mesmo que ideal_buy, reduzindo a exibição enganosa de pontos de compra duplos.
  • 🧩 A inicialização do Tushare não depende mais do pacote SDK local — TushareFetcher agora usa diretamente o HTTP client integrado para acessar o Tushare Pro e não precisa mais do import tushare para inicializar durante a fase de inicialização; Docker corrigido, empacotamento de desktop ou reconstrução de ambiente após Docker, empacotamento de desktop ou reconstrução de ambiente, relatando No module named 'tushare' antecipadamente devido à falta de problemas de pacote tushare e adicionando testes de regressão correspondentes.
  • ⚙️ O fluxo de trabalho daily_analysis conclui o mapeamento DEEPSEEK_API_KEY — O fluxo de trabalho de análise diária de ações do GitHub agora transmitirá DEEPSEEK_API_KEY de forma correta e transparente para evitar tarefas na nuvem que são configuradas com chaves, mas não podem obter as variáveis ​​de ambiente correspondentes em tempo de execução.
  • 🖥️ Truncamento e exibição flutuante de nomes de ações que são muito longos na lista de histórico (correções #815) - Nomes de ações que são muito longos na lista de histórico agora serão truncados automaticamente de acordo com o tipo de caractere (Inglês 15/Chinês 8/Misto 10 caracteres), o resultado do truncamento será exibido por padrão e o nome completo será exibido ao passar o mouse; resolver o problema de nomes de ações sobrepostos ao texto da etiqueta de status à direita na resolução 1920x1080. Adicionada função da ferramenta stockName.ts e testes correspondentes adicionados.

Documentação

  • 🧾 A entrada de doação README foi atualizada para o código QR Xiaohongshu — A entrada de patrocínio no README e as descrições em chinês e inglês foram atualizadas para o material do código QR Xiaohongshu para manter o mesmo calibre de exibição.

daily_stock_analysis v3.11.0

发布亮点

  • 🎨 Web 工作台完成一轮 UI 统一与双主题升级 — 首页、问股、回测、持仓和设置页进一步收口到统一设计 token、输入表面和状态表达；新增完整浅色主题，并支持浅色 / 深色一键切换与持久化保存。
  • 🤖 Bot / Agent 能力重新补回主分支 — 恢复 /history、/strategies、/research 等命令，/ask 继续支持多股对比与组合视角；Deep Research、事件监控与 schedule 轮询链路重新接回主线能力。
  • 🔒 安全性与运行稳态同步补强 — 修复 X-Forwarded-For 限流绕过风险，恢复 LiteLLM 官方 PyPI 安装路径，Tushare 初始化不再依赖本地 SDK，降低 Docker、桌面打包和环境重建时的脆弱点。
  • 🖥️ 日常使用细节继续打磨 — 修复首页港股自动补全提交、登录页首屏主题闪烁、历史长股票名重叠，以及 Telegram Markdown 解析失败时整条通知发送中断等问题。

新功能

  • 🎨 全新浅色主题与双主题切换上线 — Web 工作台新增完整浅色主题，并支持在侧边栏中一键切换浅色 / 深色模式；主题选择会持久化保存，刷新页面后仍保持当前偏好。此次升级不是局部配色微调，而是对卡片层级、边界对比、输入表面、状态提示和页面背景做了一整套 light theme 重绘。
  • 🤖 补回主分支缺失的 Agent / Bot 能力 — #648 / #649 已重新补回 main：Bot 恢复 /history、/strategies、/research，/ask 保留多股对比与组合视角；Deep Research 与 Event Monitor 的配置重新在 Web 设置页可见并可编辑，schedule 模式也重新接入事件告警轮询。

改进

  • 🖥️ 核心页面统一到同一套工作台视觉语言 — Home / Chat / Backtest / Portfolio / Settings 进一步收口到共享设计 token、input-surface 输入体系、空态/错误态表达和抽屉遮罩语义，减少页面之间的视觉割裂与局部私有样式漂移。
  • 💬 问股交互可达性与反馈增强 — 问股页补强了会话导出、通知发送、消息复制、历史删除与追问上下文提示；AI 回复操作不再过度依赖 hover，触屏设备和小屏场景下也能直接触达关键按钮。
  • 📊 回测与持仓页表面和状态表达继续标准化 — 回测页筛选控件、布尔状态、结果表格与汇总卡片统一到共享输入/状态原语；持仓页的导入反馈、汇率刷新提示、空态与警示信息进一步归口到共享组件，减少页面级重复实现。
  • 🧭 导航与页面壳层协同优化 — 侧边栏主题切换、问股完成角标、移动端抽屉遮罩和主内容滚动契约进一步统一，首页、问股和回测在桌面端与移动端的切页体验更稳定。

测试

  • 🧪 UI 治理与关键路径回归补强 — 补充 SidebarNav、ChatPage、BacktestPage 等组件测试，并新增 UI governance 守卫，持续防止交互元素重新引入原生 title 属性或旧 input-terminal 样式回流。同步更新 smoke / markdown drawer 相关验证，覆盖主题升级后的关键主链路。

修复

  • 🌗 Web 首屏默认主题预设为深色 — apps/dsa-web/index.html 现在会在 React 挂载前读取本地保存的主题偏好；若没有已保存值，则立即给 <html> 预设 dark 并同步 color-scheme，避免首页和登录页首屏先闪出浅色主题。
  • 🔐 登录页独立主题层收口 — 登录页输入框、标签、切换按钮和按钮文案现在使用独立的 --login-* 视觉 token，不再继承全局浅/深主题文字色；即使浏览器缓存了浅色主题，登录页仍保持稳定的深色视觉与青色密码输入表现，避免密码圆点和文案落成黑色。
  • 🖥️ 首页港股代码输入修复 — Web 首页分析输入框现在可正确接受港股代码与自动完成选中的港股项，补齐 00700.HK / HK00700 等格式识别，避免提交时误报“请输入有效的股票代码或股票名称”。
  • 🔒 认证限流 X-Forwarded-For 取值修复（CWE-345）（#841 / #842）— get_client_ip() 从取 X-Forwarded-For 最左值改为最右值，防止攻击者通过伪造首部旋转限流桶绕过暴力破解保护；仅影响 TRUST_X_FORWARDED_FOR=true 且单层可信反向代理的部署场景，多级代理环境需按部署文档评估配置。
  • 📦 恢复 LiteLLM 官方 PyPI 安装并锁定安全上限 — requirements.txt 重新使用 pip install litellm 的官方 PyPI 安装路径，并在保留历史最低要求 >=1.80.10 的同时增加 <1.82.7 的安全上限，避免误装已被移除的 1.82.7 / 1.82.8 风险版本；Windows 桌面打包脚本也同步回退到标准 pip install -r requirements.txt 链路，减少特殊下载分支带来的维护成本。
  • 📨 Telegram Markdown 解析失败回退纯文本（fixes #850）— src/notification_sender/telegram_sender.py 现在会在 Telegram 返回 HTTP 400 且包含 can't parse entities / Markdown 解析错误时，自动去掉 parse_mode 后重试纯文本发送，避免 *ST 等正文内容直接导致整条通知失败。
  • 🔢 A 股同码实时行情保留交易所提示（fixes #852）— DataFetcherManager 与 TushareFetcher 现在会保留 SZ000001 / 000001.SZ 这类显式沪深提示，旧版 Tushare 实时行情降级分支不再把深市 000001 误判成 sh000001 上证指数。
  • 🎯 多 Agent 次优买点不再盲目复制理想买点（fixes #851）— 当多智能体结果缺少独立 secondary_buy 时，仪表盘现在优先展示 N/A 而不是把 fallback 值硬拷贝成与 ideal_buy 完全相同，减少误导性的双买点展示。
  • 🧩 Tushare 初始化不再强依赖本地 SDK 包 — TushareFetcher 现在直接使用内置 HTTP client 访问 Tushare Pro，不再在启动阶段先 import tushare 才能初始化；修复了 Docker、桌面打包或环境重建后因缺少 tushare 包而提前报 No module named 'tushare' 的问题，并补充对应回归测试。
  • ⚙️ daily_analysis 工作流补齐 DEEPSEEK_API_KEY 映射 — GitHub Actions 每日分析工作流现在会正确透传 DEEPSEEK_API_KEY，避免云端任务配置了密钥却在运行时拿不到对应环境变量。
  • 🖥️ 历史列表过长股票名称截断与悬停展示（fixes #815）— 历史列表中过长的股票名称, 现在会按字符类型自动截断（英文15/中文8/混合10字符），默认显示截断结果，悬停时展示完整名称；解决 1920x1080 分辨率下股票名称与右侧状态标签文字重叠的问题。新增 stockName.ts 工具函数并补充对应测试。

文档

  • 🧾 README 捐赠入口更新为小红书二维码 — README 及中英文说明中的赞助入口更新为小红书二维码素材，保持展示口径一致。
