daily_stock_análise v3.9.0

Destaques do lançamento

  • 🤖 Links de modelo e idiomas de relatório são mais flexíveis - O agente agora pode selecionar links de modelo de forma independente por meio do AGENT_LITELLM_MODEL, e análises comuns e relatórios de agente também podem ser gerados em um idioma unificado por meio de REPORT_LANGUAGE=zh|en, reduzindo problemas de mistura como "conteúdo em inglês + shells em chinês" e permitindo que as equipes avaliem o custo, a velocidade e os recursos da análise principal e do agente, respectivamente.
  • 🔎 A experiência de análise da página inicial completou uma rodada de otimização de circuito fechado - O preenchimento automático de A-share foi adicionado à página inicial, suportando recuperação de código, nome chinês, pinyin e alias; ao mesmo tempo, o status do Dashboard é integrado à loja unificada, e a interação entre histórico, relatórios, notícias e gavetas Markdown é mais estável, e as perguntas "Ask AI" também darão prioridade ao contexto atual do relatório.
  • 💬 Os recursos de notificação e recuperação continuam a se expandir - Adicionado canal de notificação de primeira classe do Slack; SearXNG pode descobrir automaticamente instâncias públicas e fazer downgrade delas de acordo com pesquisas controladas quando instâncias autoconstruídas não estão configuradas; depois que o link de notícias urgentes do Tavily for reparado, a filtragem estrita urgente não perderá mais resultados válidos devido a erros.
  • 💼 A ligação entre as posições e a revisão do mercado é mais estável — A análise do mercado de ações A pode opcionalmente acessar o TickFlow para fortalecer o índice e as estatísticas de subida e descida; a escrita do livro de posições é alterada para serialização para reduzir a janela de sobrevenda simultânea; a entrada de atualização da taxa de câmbio e os prompts de status desativados também são mais claros, reduzindo erros de julgamento do usuário.

Novos recursos

  • 🔎 MVP de preenchimento automático de ações da Web - A caixa de entrada de análise da página inicial adiciona preenchimento automático baseado em índice local, compatível com código de ações, nome chinês, pinyin e correspondência de alias; após a seleção do candidato, será enviado o código canônico, e stock_name, original_query, selection_source serão transmitidos de forma transparente para a solicitação de análise, status da tarefa e evento SSE; quando o carregamento do índice falhar, ele retornará automaticamente ao modo de entrada antigo, sem bloquear o processo de envio original. A sincronização é complementada com um carregador de índice estático, scripts de geração de índice e testes de contrato de front-end e back-end. O desenvolvimento é realizado em fases, sendo que a primeira fase apoia apenas ações A.
  • 💬 Canal de notificação de primeira classe do Slack - Adicionado suporte para notificações nativas do Slack, suportando métodos de acesso Bot Token e Incoming Webhook; ao configurar ao mesmo tempo, dê prioridade ao uso do Bot API para garantir que textos e imagens sejam enviados para o mesmo canal; O modo Bot Token suporta upload de imagem (corpo bruto POST, sem usar multipart); adicionado item de configuração SLACK_BOT_TOKEN, SLACK_CHANNEL_ID, SLACK_WEBHOOK_URL, fluxo de trabalho de ações GitHub sincroniza e conclui a entrega de segredos correspondente.
  • 🌍 O idioma de saída do relatório é configurável (Problema #758) - Adicionado REPORT_LANGUAGE=zh|en, padrão zh; a configuração de idioma injetará simultaneamente análise normal e prompt do agente e cobrirá modelos Markdown/Jinja, fallback de notificação, metadados de histórico/API report_language e cópia fixa da página de relatório da Web para evitar a saída mista de "conteúdo em inglês + shell chinês".
  • 🚀 Agente é desacoplado do modelo de análise comum (Edição #692) - Adicionado AGENT_LITELLM_MODEL (deixe em branco para herdar LITELLM_MODEL, nenhum prefixo é normalizado de acordo com openai/<model>); a marca is_primary/is_fallback do link de execução do Agente e /api/v1/agent/models é alterada para ser baseada no link do modelo real do Agente; a configuração do sistema e a verificação do período de inicialização são concluídas AGENT_LITELLM_MODEL Verificado por unknown_model/missing_runtime_source; A página de configurações da Web adiciona a seleção do modelo principal do agente e sincroniza com a configuração de tempo de execução do modo de canal.
  • 🔎 Descoberta automática de instância pública SearXNG e pesquisa controlada (#752) - Adicionado SEARXNG_PUBLIC_INSTANCES_ENABLED. Quando SEARXNG_BASE_URLS não estiver configurado, ele extrairá a lista de instâncias públicas de searx.space por padrão e selecionará instâncias em ordem de pesquisa controlada; se um tempo limite, erro de conexão, HTTP diferente de 200 ou JSON inválido for encontrado na mesma solicitação, ele mudará automaticamente para a próxima instância. Os usuários que configuraram instâncias autoconstruídas mantêm as prioridades e a semântica originais inalteradas; O fluxo de trabalho de ações daily_analysis GitHub também suporta transmissão transparente explícita deste switch e exibe o status atual no log de inicialização.
  • 📈 Aprimoramento da análise de mercado do TickFlow (#632) — Adicionado TICKFLOW_API_KEY opcional; após a configuração, o TickFlow terá prioridade para as principais tendências do índice na revisão do mercado de ações A; se o pacote TickFlow atual suportar a consulta do pool de destino, as estatísticas de aumento e queda do mercado também darão prioridade ao TickFlow. Em caso de falha ou permissões insuficientes, retornará imediatamente ao link AkShare / Tushare / efinance existente; a ordem de recurso da lista de preços do sector permanece inalterada. A camada de acesso também é adaptada ao contrato SDK real: a consulta do índice principal puxa em lotes de acordo com o limite superior de uma única solicitação e converte uniformemente o change_pct / amplitude proporcional retornado pelo TickFlow no calibre percentual interno do projeto.

Melhorias

  • Fatia de estado do painel e fechamento do espaço de trabalho — estado inicial/painel movido para stockPoolStore, seleção de histórico consolidado, carregamento de relatórios, sincronização de tarefas, atualização de pesquisa e manipulação de gaveta de redução em uma única fatia de estado.
  • Padronização do painel do painel — manteve o contrato de layout do painel atual estável enquanto unificava o histórico, o relatório, as notícias e a apresentação de descontos com tokens compartilhados, estados padronizados e rolagem limitada no painel para a lista de histórico.
  • Ponte de acompanhamento do painel para bate-papo — acompanhamentos “Ask AI” roteados por meio da hidratação do contexto do relatório em vez do acoplamento direto de estado entre páginas, enquanto mantém os envios de bate-papo utilizáveis ​​quando o contexto do histórico enriquecido ainda está sendo carregado.
  • 💼 Serialização de gravação simultânea do razão de posição (#742) - A escrita/exclusão de evento de origem de posição agora obterá primeiro o bloqueio de gravação serializado no SQLite, reduzindo a janela para venda simultânea de transações com excesso de reservas a serem gravadas no razão; a interface de gravação de posição direta retorna 409 portfolio_busy durante a competição de bloqueio, e a importação CSV mantém o envio um por um e conta ocupado como failed_count.
  • 💱 Preencher entrada de atualização manual para taxa de câmbio da página de posição (#748) - A página Web /portfolio agora exibirá o botão "Atualizar Taxa de Câmbio" no cartão "Status da Taxa de Câmbio", chamando diretamente a interface POST /api/v1/portfolio/fx/refresh existente; após a atualização, apenas o instantâneo e os dados de risco serão recarregados, e o resultado de "Atualizado/Ainda obsoleto/Falha na atualização" será retornado com um resumo embutido, reduzindo as preocupações do usuário sobre o equívoco fxStale de longa permanência.

  • 🌍 Completar o limite de localização entre a análise de inicialização do REPORT_LANGUAGE e a exibição do histórico - Config continuará a seguir a semântica existente de "variáveis ​​​​de ambiente real primeiro, .env fica no fundo" ao iniciar e emitirá avisos explícitos quando os dois entrarem em conflito, reduzindo erros de julgamento causados ​​​​por fontes pouco claras de REPORT_LANGUAGE; ao mesmo tempo, a resposta de detalhes em inglês do /api/v1/history/{id} será sincronizada com o sentiment_label localizado, histórico Markdown Ele também identificará corretamente o emoji de nível de risco do inglês bias_status para evitar exibições mistas/falso-positivas de chinês e inglês, como 乐观 ou 🚨Safe.
  • 📰 Tavily reparo de mapeamento de tempo de liberação de recuperação de notícias urgente (#782) - Tavily agora usará explicitamente topic="news" em notícias de ações e dimensões de inteligência estritamente sensíveis ao tempo, e é compatível com dois campos de tempo de lançamento published_date / publishedDate; corrigido Tavily retornando claramente resultados, mas todos sendo registrados como drop_unknown no estágio subsequente de filtragem rígida. Perguntas descartadas, enquanto restaura dimensões analíticas, como análise institucional, expectativas de desempenho e análise do setor para pesquisa de fonte ampla, e não são mais compactadas uniformemente no modo de notícias.
  • 💱 Correção semântica para desabilitar a atualização da taxa de câmbio na página de posição (#772) - Quando PORTFOLIO_FX_UPDATE_ENABLED=false, POST /api/v1/portfolio/fx/refresh agora retornará refresh_enabled=false e disabled_reason explícitos, e a página Web /portfolio exibirá claramente "A atualização online da taxa de câmbio foi desativada" e não informará mais falsamente "Não há par de taxas de câmbio que possa ser atualizado na faixa atual".
  • 🤖 Tempo limite do agente e proteção de configuração — AGENT_ORCHESTRATOR_TIMEOUT_S agora também protege o loop ReAct legado de agente único, lotes de ferramentas paralelas param de esperar quando o orçamento restante se esgota e valores numéricos inválidos de .env voltam para padrões seguros com avisos em vez de travar a inicialização.
  • 🌐 Compatibilidade com curinga CORS + credenciais — CORS_ALLOW_ALL=true não combina mais allow_origins=["*"] com solicitações credenciadas, evitando falhas de origem cruzada no navegador em configurações de demonstração/desenvolvimento.
  • 🧭 Configurações do agente indisponíveis ocultas na interface da Web — Os controles Deep Research/Monitor de eventos agora são tratados como metadados somente de compatibilidade na ramificação atual e são removidos da página Configurações para evitar a exposição de alternâncias não funcionais.

daily_stock_analysis v3.9.0

发布亮点

  • 🤖 模型链路与报告语言更灵活 — Agent 现在可以通过 AGENT_LITELLM_MODEL 独立选择模型链路，普通分析与 Agent 报告也可通过 REPORT_LANGUAGE=zh|en 输出统一语言，减少“英文内容 + 中文壳子”这类混排问题，并允许团队分别权衡主分析与 Agent 的成本、速度和能力。
  • 🔎 首页分析体验完成一轮闭环优化 — 首页新增 A 股自动补全，支持代码、中文名、拼音和别名检索；同时 Dashboard 状态收口到统一 store，历史、报告、新闻与 Markdown 抽屉的交互更稳定，“Ask AI” 追问也会优先携带当前报告上下文。
  • 💬 通知与检索能力继续外扩 — 新增 Slack 一等通知渠道；SearXNG 在未配置自建实例时可以自动发现公共实例并按受控轮询降级；Tavily 时效新闻链路修复后，严格时效过滤不再错误丢光有效结果。
  • 💼 持仓与市场复盘链路更稳 — A 股 market review 可选接入 TickFlow 强化指数与涨跌统计；持仓账本写入改为串行化以缩小并发超卖窗口；汇率刷新入口和禁用态提示也更加清晰，减少用户误判。

新功能

  • 🔎 Web 股票自动补全 MVP — 首页分析输入框新增本地索引驱动的自动补全，支持股票代码、中文名、拼音和别名匹配；选中候选后会提交 canonical code，并透传 stock_name、original_query、selection_source 到分析请求、任务状态和 SSE 事件；索引加载失败时自动退回旧输入模式，不阻断原有提交流程。同步补充了静态索引加载器、索引生成脚本和前后端契约测试。分阶段进行开发，第一阶段仅支持 A 股。
  • 💬 Slack 一等通知渠道 — 新增 Slack 原生通知支持，同时支持 Bot Token 和 Incoming Webhook 两种接入方式；同时配置时优先使用 Bot API，确保文本与图片发送到同一频道；Bot Token 模式支持图片上传（raw body POST，不使用 multipart）；新增 SLACK_BOT_TOKEN、SLACK_CHANNEL_ID、SLACK_WEBHOOK_URL 配置项，GitHub Actions 工作流同步补齐对应 Secrets 传递。
  • 🌍 报告输出语言可配置（Issue #758）— 新增 REPORT_LANGUAGE=zh|en，默认 zh；语言设置会同步注入普通分析与 Agent Prompt，并覆盖 Markdown/Jinja 模板、通知 fallback、历史/API report_language 元数据及 Web 报告页固定文案，避免“英文内容 + 中文壳子”的混合输出。
  • 🚀 Agent 与普通分析模型解耦（Issue #692）— 新增 AGENT_LITELLM_MODEL（留空继承 LITELLM_MODEL，无前缀按 openai/<model> 归一）；Agent 执行链路与 /api/v1/agent/models 的 is_primary/is_fallback 标记改为基于 Agent 实际模型链路；系统配置与启动期校验补齐 AGENT_LITELLM_MODEL 的 unknown_model/missing_runtime_source 检查；Web 设置页新增 Agent 主模型选择并与渠道模式运行时配置同步。
  • 🔎 SearXNG 公共实例自动发现与受控轮询（#752）— 新增 SEARXNG_PUBLIC_INSTANCES_ENABLED，在未配置 SEARXNG_BASE_URLS 时默认从 searx.space 拉取公共实例列表，并按受控轮询顺序选择实例；同次请求内遇到超时、连接错误、HTTP 非 200 或无效 JSON 会自动切换到下一个实例。已配置自建实例的用户保持原有优先级与语义不变；daily_analysis GitHub Actions 工作流也已支持显式透传该开关并在启动日志中展示当前状态。
  • 📈 TickFlow market review enhancement (#632) — 新增可选 TICKFLOW_API_KEY；配置后，A 股大盘复盘的主要指数行情优先尝试 TickFlow；若当前 TickFlow 套餐支持标的池查询，市场涨跌统计也会优先尝试 TickFlow。失败或权限不足时立即回退到现有 AkShare / Tushare / efinance 链路；板块涨跌榜回退顺序保持不变。接入层同时适配了真实 SDK 契约：主指数查询按单次请求上限分批拉取，并将 TickFlow 返回的比例型 change_pct / amplitude 统一转换为项目内部的百分比口径。

改进

  • Dashboard state slice and workspace closure — moved Home / Dashboard state into stockPoolStore, consolidated history selection, report loading, task syncing, polling refresh, and markdown drawer handling under a single state slice.
  • Dashboard panel standardization — kept the current dashboard layout contract stable while unifying history, report, news, and markdown presentation with shared tokens, standardized states, and bounded in-panel scrolling for the history list.
  • Dashboard-to-chat follow-up bridge — routed “Ask AI” follow-ups through report-context hydration instead of direct cross-page state coupling, while keeping chat sends usable when enriched history context is still loading.
  • 💼 持仓账本并发写入串行化（#742）— 持仓源事件写入/删除现在会在 SQLite 下先获取串行化写锁，减少并发卖出把超售流水写入账本的窗口；直接持仓写接口在锁竞争时返回 409 portfolio_busy，CSV 导入保持逐条提交并把 busy 计入 failed_count。
  • 💱 持仓页汇率手动刷新入口补齐（#748）— Web /portfolio 页面现在会在“汇率状态”卡片中展示“刷新汇率”按钮，直接调用现有 POST /api/v1/portfolio/fx/refresh 接口；刷新后会仅重载快照与风险数据，并以内联摘要反馈“已更新 / 仍 stale / 刷新失败”的结果，减少用户对 fxStale 长时间停留的误解。

修复

  • 🔎 Web 自动补全 Enter 提交语义修正 — 股票自动补全在搜索命中候选时不再默认高亮第一项；候选列表展开但用户尚未用方向键或鼠标明确选中时，按 Enter 会继续提交原始输入，避免手动输入被第一条候选静默覆盖。
  • 🌍 补齐 REPORT_LANGUAGE 启动解析与历史展示本地化边界 — Config 在启动时继续遵循“真实环境变量优先、.env 兜底”的既有语义，并在两者冲突时输出显式告警，减少 REPORT_LANGUAGE 来源不清带来的误判；同时 /api/v1/history/{id} 英文详情响应会同步本地化 sentiment_label，历史 Markdown 也会正确识别英文 bias_status 的风险等级 emoji，避免出现 乐观 或 🚨Safe 这类中英混排/误报展示。
  • 📰 Tavily 时效新闻检索发布时间映射修复（#782）— Tavily 在股票新闻和严格时效的情报维度中现在会显式使用 topic="news"，并兼容 published_date / publishedDate 两种发布时间字段；修复了 Tavily 明明返回结果却在后续硬过滤阶段被全部记为 drop_unknown 丢弃的问题，同时将机构分析、业绩预期、行业分析等分析型维度恢复为宽源搜索，不再被统一压缩成新闻模式。
  • 💱 持仓页汇率刷新禁用语义修正（#772）— 当 PORTFOLIO_FX_UPDATE_ENABLED=false 时，POST /api/v1/portfolio/fx/refresh 现在会返回显式 refresh_enabled=false 与 disabled_reason，Web /portfolio 页面会明确提示“汇率在线刷新已被禁用”，不再误报“当前范围无可刷新的汇率对”。
  • 🤖 Agent timeout and config hardening — AGENT_ORCHESTRATOR_TIMEOUT_S now also protects the legacy single-agent ReAct loop, parallel tool batches stop waiting once the remaining budget is exhausted, and invalid numeric .env values fall back to safe defaults with warnings instead of crashing startup.
  • 🌐 CORS wildcard + credentials compatibility — CORS_ALLOW_ALL=true no longer combines allow_origins=["*"] with credentialed requests, avoiding browser-side cross-origin failures in demo/development setups.
  • 🧭 Unavailable Agent settings hidden from Web UI — Deep Research / Event Monitor controls are now treated as compatibility-only metadata in the current branch and are removed from the Settings page to avoid exposing non-functional toggles.
