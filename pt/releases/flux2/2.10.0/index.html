#fluxo2 v2.10.0

Destaques

Flux v2.10.0 é um lançamento de recurso. Os usuários são incentivados a atualizar para obter a melhor experiência. Visão geral dos novos recursos:

  • A identidade do objeto está geralmente disponível; o feature gate ObjectLevelWorkloadIdentity foi retirado
  • SPIFFE mTLS para comunicação entre controladores
  • Notificação Event, Alert e Provider APIs promovidos para v1
  • OCIRepository como fonte de gráfico para HelmRelease
  • Descriptografia SOPS para arquivos criptografados com expressões regulares de comentários e --override-manager-before-dry-run (Kustomization)
  • Atualização de imagem em lote com .spec.policyChangeDelay, nova tentativa em push rejeitados e .Changed.Summary (ImageUpdateAutomation)
  • Back-end de armazenamento de artefato Flux habilitado por padrão para tags ImageRepository
  • Artefatos entre namespaces, provisionamento de namespace de locatário e descoberta de padrão de caminho (ArtifactGenerator)
  • Novos provedores de notificação Zoom, incident.io e Mastodon
  • Construído com Kubernetes 1.37 e Go 1.27 ❤️ Muito obrigado a todos os colaboradores do Flux que nos ajudaram com este lançamento!

Compatibilidade com Kubernetes

Esta versão é compatível com as seguintes versões Kubernetes: | Versão Kubernetes | Mínimo exigido | |--------------------|------------------| | v1.35 | >= 1.35.2 | | v1.36 | >= 1.36.1 | | v1.37 | >= 1.37.0 |

[!NOTA] Observe que o projeto Flux oferece suporte apenas para as três versões secundárias mais recentes do Kubernetes. A compatibilidade retroativa com versões mais antigas do Kubernetes e OpenShift é oferecida por fornecedores como ControlPlane que fornece suporte empresarial para Flux.

Compatibilidade com OpenShift

O Flux pode ser instalado no cluster Red Hat OpenShift diretamente do OperatorHub usando Flux Operator. A operadora permite a configuração de bloqueio de multilocação Flux, políticas de rede, armazenamento persistente, sharding, escalonamento vertical e sincronização do estado do cluster a partir de repositórios Git, artefatos OCI e armazenamento compatível com S3.

Procedimento de atualização

⚠️ Alterações importantes nesta versão:

  • A identidade do objeto está sempre habilitada e o Flux RBAC padrão não concede mais o verbo create no recurso serviceaccounts/token. Se a sua instalação depender do RBAC padrão, vincule um ClusterRole com essa permissão ao controlador ServiceAccount antes de atualizar. Consulte fluxcd/flux2#6139 para obter o ClusterRole e ClusterRoleBinding necessários.
  • A notificação Alert e Provider APIs são promovidas para v1. A conversão de um v1beta3 Alert ou Provider em v1 descarta os campos Alert.spec.summary e Provider.spec.interval preteridos, o token JWT estático para o Azure Event Hub e a configuração de TLS ou proxy em Provider.spec.secretRef. Use eventMetadata.summary, proxySecretRef e certSecretRef.
  • O backend de armazenamento de artefatos Flux agora é o padrão para o banco de dados de tags ImageRepository. A troca do portão limpa o banco de dados de tags local, portanto, a primeira reconciliação após a atualização verifica novamente cada ImageRepository. Configure --feature-gates=FluxStorage=false para continuar usando o BadgerDB.
  • Autenticação remota de cluster com .spec.kubeConfig.configMapRef utiliza identidade de objeto; substitua a chave herdada audiences por credential.auth.fluxcd.io/audiences. Siga o Procedimento de atualização do Flux v2.7+ para uma atualização tranquila de versões mais antigas do Flux para v2.10.

flux2 v2.10.0

Highlights

Flux v2.10.0 is a feature release. Users are encouraged to upgrade for the best experience.

Overview of the new features:

  • Object identity is generally available; the ObjectLevelWorkloadIdentity feature gate is retired
  • SPIFFE mTLS for inter-controller communication
  • Notification Event, Alert and Provider APIs promoted to v1
  • OCIRepository as a chart source for HelmRelease
  • SOPS decryption for files encrypted with comment regexes, and --override-manager-before-dry-run (Kustomization)
  • Image update batching with .spec.policyChangeDelay, retry on rejected pushes, and .Changed.Summary (ImageUpdateAutomation)
  • Flux artifact storage backend enabled by default for ImageRepository tags
  • Cross-namespace artifacts, tenant namespace provisioning, and path-pattern discovery (ArtifactGenerator)
  • New Zoom, incident.io and Mastodon notification providers
  • Built with Kubernetes 1.37 and Go 1.27

❤️ Big thanks to all the Flux contributors that helped us with this release!

Kubernetes compatibility

This release is compatible with the following Kubernetes versions:

| Kubernetes version | Minimum required | |--------------------|------------------| | v1.35 | >= 1.35.2 | | v1.36 | >= 1.36.1 | | v1.37 | >= 1.37.0 |

[!NOTE] Note that the Flux project offers support only for the latest three minor versions of Kubernetes. Backwards compatibility with older versions of Kubernetes and OpenShift is offered by vendors such as ControlPlane that provide enterprise support for Flux.

OpenShift compatibility

Flux can be installed on Red Hat OpenShift cluster directly from OperatorHub using Flux Operator. The operator allows the configuration of Flux multi-tenancy lockdown, network policies, persistent storage, sharding, vertical scaling and the synchronization of the cluster state from Git repositories, OCI artifacts, and S3-compatible storage.

Upgrade procedure

⚠️ Breaking changes in this release:

  • Object identity is always enabled and the default Flux RBAC no longer grants the create verb on the serviceaccounts/token resource. If your installation relies on the default RBAC, bind a ClusterRole with this permission to the controller ServiceAccount before upgrading. See fluxcd/flux2#6139 for the required ClusterRole and ClusterRoleBinding.
  • The notification Alert and Provider APIs are promoted to v1. Converting a v1beta3 Alert or Provider to v1 drops the deprecated Alert.spec.summary and Provider.spec.interval fields, the static JWT token for Azure Event Hub, and TLS or proxy configuration in Provider.spec.secretRef. Use eventMetadata.summary, proxySecretRef and certSecretRef instead.
  • The Flux artifact storage backend is now the default for the ImageRepository tag database. Switching the gate wipes the local tag database, so the first reconciliation after the upgrade rescans every ImageRepository. Set --feature-gates=FluxStorage=false to keep using BadgerDB.
  • Remote cluster authentication with .spec.kubeConfig.configMapRef uses object identity; replace the legacy audiences key with credential.auth.fluxcd.io/audiences.

Please follow the Upgrade Procedure for Flux v2.7+ for a smooth upgrade from older versions of Flux to v2.10.
