#LangBot v4.11.7

LangBot é uma plataforma de chatbot e agente de IA de código aberto que oferece suporte a várias plataformas de mensagens instantâneas, grandes modelos de linguagem, bases de conhecimento e plug-ins para ajudá-lo a construir, implantar e gerenciar assistentes de IA. LangBot é um chatbot de IA de código aberto e plataforma de agente que conecta plataformas de mensagens, grandes modelos de linguagem, bases de conhecimento e plug-ins para ajudá-lo a construir, implantar e gerenciar assistentes de IA.

LangBot v4.11.7

A última versão estável da linha 4.11.x. Ele substitui v4.11.6, que foi retirado: v4.11.6 rejeitou contagens de tokens simultâneos em um modelo compartilhado, portanto, as conversas do LocalAgent executadas ao mesmo tempo podem voltar a estimativas aproximadas e falhar. Se você instalou o v4.11.6, atualize para o v4.11.7.

Esta versão é a versão estável final do 4.11.x, substituindo o v4.11.6 retirado. v4.11.6 rejeitará contagens de tokens simultâneos quando várias sessões usarem o mesmo modelo ao mesmo tempo, portanto, o LocalAgent usará estimativas aproximadas e algumas conversas falharão. Os usuários que instalaram o v4.11.6 devem atualizar para o v4.11.7.

Ele não contém novos recursos. Corrige as falhas reportadas pelas instâncias 4.11.x através da telemetria LangBot Space, e atualiza o plugin SDK e os plugins oficiais envolvidos.

Correções/Reparos

  • Contagem simultânea de tokens (regressão v4.11.6): A contagem simultânea no mesmo modelo não é mais rejeitada; somente a contagem que ainda estiver em execução após o tempo limite ou cancelamento impedirá uma nova contagem. As contagens simultâneas de tokens em um modelo não são mais rejeitadas; apenas uma contagem que sobreviveu ao chamador bloqueia novas.
  • Plugins do Windows / Plug-ins do Windows: O plug-in print chinês ou emoji não faz mais com que o plug-in seja desconectado durante a execução e o erro 'gbk' codec can't encode (SDK 0.7.24) não ocorre mais. Um plug-in que imprime texto ou emoji em chinês não desconecta mais o tempo de execução do plug-in no Windows com localidade chinesa.
  • Contagem de tokens do Windows / Contagem de tokens do Windows: O arquivo tokenizer que vem com o pacote de instalação do Windows do LiteLLM é CRLF newline. Se a verificação falhar, ele será baixado novamente do openaipublic. Quando a rede estiver indisponível, a primeira conversa de cada processo ficará travada (30 segundos count_tokens call timed out em telemetria). LangBot agora irá converter esses arquivos em LF e salvá-los em data/tiktoken_cache quando for iniciado, e a contagem ficará completamente offline. Além disso, quando a contagem expira ou falha, o LocalAgent usa estimativas locais para continuar a conversa em vez de falhar durante toda a rodada. As rodas do Windows do LiteLLM enviam arquivos tokenizer CRLF que falham na verificação de hash do tiktoken e acionam um download; LangBot agora mantém uma cópia offline normalizada e uma falha de contagem não falha mais no turno do LocalAgent.
  • Disponibilidade do executor/Disponibilidade do executor: Durante a inicialização ou reconexão, aguarde até que o plug-in instalado conclua a inicialização antes de despachar e não relate mais Agent runner not found: plugin:langbot-team/LocalAgent/default.
  • Tempo de execução do plug-in: durante a reconexão do tempo de execução, a sincronização do espaço de trabalho e o envio de eventos aguardarão a conclusão da reconexão (até 30 segundos) e não falharão mais na janela de desconexão; o tamanho real e as sugestões de processamento serão fornecidos quando o volume do anexo e do fluxo exceder o erro limite (SDK).
  • Base de conhecimento/Base de conhecimento: o back-end da biblioteca de vetores é inicializado em um thread em segundo plano. Anteriormente, em máquinas mais lentas, o primeiro repositório bloqueava o loop de eventos, fazendo com que o plug-in fosse desconectado durante o tempo de execução e falhasse no repositório. O back-end do vetor é criado a partir do loop de eventos; a primeira ingestão em um host lento não interrompe mais a conexão de tempo de execução do plug-in.
  • SQLite/SQLAlchemy: O problema de unknown ON CONFLICT update shape ao gravar pela primeira vez no armazenamento de plug-in para instalações não Docker (pip/uvx) no SQLAlchemy 2.1 foi corrigido e o limite de dependência foi definido como <2.2; o bloqueio de gravação do SQLite é liberado durante a atualização da imagem, reduzindo database is locked.
  • Box sandbox / Box sandbox: comandos excessivamente longos são executados por meio de scripts temporários, corrige Argument list too long e falha na importação de anexos grandes (SDK).
  • Runners: Coze/Dify lida com saídas concluídas e de tipo de fluxo de trabalho e não trata mais essas respostas como respostas vazias; não relata mais um erro quando a configuração de inferência do LocalAgent está vazia. A desserialização de respostas de erro de comando não trava mais (SDK).
  • Interações do Runner/Interação do Runner: em adaptadores mais antigos, como HTTP Bot e OneBot, as interações iniciadas pelo Runner (como o nó de entrada manual do fluxo de trabalho Dify) não relatam mais um erro get_interaction_capabilities e são alteradas para perguntas e respostas de texto. As interações do executor em adaptadores legados (HTTP Bot, OneBot,…) voltam para texto em vez de falhar.
  • Telemetria/Atribuição de Telemetria: execuções canceladas são registradas como canceladas em vez de com falha; os detalhes do erro são retidos quando o roteamento falha; as execuções que já estão no estado final não reportam mais erros de conversão; o campo da plataforma da cadeia de execução não é mais substituído pela fonte da ferramenta (mcp/skill, etc.).
  • Plugins oficiais/Plugins oficiais: EssentialCommands 0.1.12 corrige !func; HelloPlugin 0.1.6 remove a saída de depuração; LocalAgent 0.2.10, CozeAgent 0.2.5 e DifyAgent 0.2.8 foram listados no Marketplace.
  • SDK: langbot-plugin corrigido de 0.7.23 para 0.7.24.

LangBot v4.11.7

Highlights

  • Upgrade now if you're on v4.11.6 — That build was withdrawn: it rejected concurrent token counts on a shared model, so simultaneous LocalAgent sessions silently degraded to rough estimates and could fail mid-turn. v4.11.7 is the final stable 4.11.x release, contains no new features, and was verified with an in-place upgrade of 4.11.6 data — treat it as a drop-in corrective patch, not a feature drop.
  • Concurrent token counting restored — Counts against the same model are no longer rejected simply because another is in flight; only a count that has outlived its caller (timed out or cancelled) now blocks new ones. The release added a stress check of 8–24 simultaneous LocalAgent conversations on one model with no rejections, versus 3–6 rejected counts per 24-conversation round on 4.11.6 — the core regression for anyone running multi-session bots.
  • Windows: offline, encoding-safe token counting — LiteLLM's Windows wheels ship CRLF tokenizer files that fail tiktoken's hash check and trigger a download; with no network, every process's first conversation stalls ~30s (count_tokens call timed out). LangBot now normalizes those files into data/tiktoken_cache at startup for fully offline counting, and a timeout/failure falls back to a local estimate instead of failing the whole turn. Plugin print of Chinese text or emoji also no longer disconnects the runtime with 'gbk' codec can't encode (SDK 0.7.24).
  • Plugin and runner lifecycle hardened — Startup/reconnect now waits for installed plugins to finish initializing before dispatching, eliminating spurious Agent runner not found: plugin:langbot-team/LocalAgent/default errors, and reconnects hold workspace sync and event dispatch for up to 30s rather than failing in the disconnect window. The knowledge-base vector backend is created off the event loop, so first-time ingestion on a slow host no longer blocks the loop and drops the plugin runtime.
  • Non-Docker, sandbox, and legacy-adapter fixes — pip/uvx installs on SQLAlchemy 2.1 hit unknown ON CONFLICT update shape on the first plugin-storage write; the dependency is now capped at <2.2 and the SQLite write lock is released during image refresh to curb database is locked. Box sandbox runs overlong commands via a temp script (fixing Argument list too long and large-attachment imports), and runner interactions such as Dify human-input nodes now fall back to text on HTTP Bot/OneBot instead of throwing get_interaction_capabilities.
  • SDK, plugins, and telemetry housekeeping — langbot-plugin is pinned 0.7.23 → 0.7.24, a prerequisite for the Windows/SDK fixes; EssentialCommands 0.1.12 repairs !func, HelloPlugin 0.1.6 drops debug output, and LocalAgent 0.2.10 / CozeAgent 0.2.5 / DifyAgent 0.2.8 are on the Marketplace. Telemetry now records cancelled executions as cancelled rather than failed, preserves error details on routing failures, and stops tool sources (mcp/skill) from overwriting the platform field.

No breaking changes.

LangBot v4.11.7

The final stable release of the 4.11.x line. It replaces v4.11.6, which has been withdrawn: v4.11.6 rejected concurrent token counts on a shared model, so LocalAgent conversations running at the same time could fall back to rough estimates and fail. If you installed v4.11.6, upgrade to v4.11.7.

本版本是 4.11.x 的最终稳定版，取代已撤回的 v4.11.6。v4.11.6 在多个会话同时使用同一模型时会拒绝并发的 token 计数，LocalAgent 因此改用粗略估算，部分对话会失败。已安装 v4.11.6 的用户请升级到 v4.11.7。

It contains no new features. It fixes the failures reported by 4.11.x instances through LangBot Space telemetry, and updates the plugin SDK and the official plugins involved.

Fixes / 修复

  • Concurrent token counting / 并发 Token 计数（v4.11.6 回归）：同一模型上的并发计数不再被拒绝；只有超时或被取消后仍在运行的计数，才会阻止新的计数。Concurrent token counts on one model are no longer rejected; only a count that outlived its caller blocks new ones.
  • Windows plugins / Windows 插件：插件 print 中文或 emoji 不再导致插件运行时断连，也不再出现 'gbk' codec can't encode 报错（SDK 0.7.24）。A plugin printing Chinese text or emoji no longer disconnects the plugin runtime on Chinese-locale Windows.
  • Windows token counting / Windows Token 计数：LiteLLM 的 Windows 安装包自带的 tokenizer 文件是 CRLF 换行，校验失败后会重新从 openaipublic 下载；网络不通时，每个进程的首次对话都会卡住（遥测里的 30 秒 count_tokens call timed out）。LangBot 现在启动时会把这些文件转成 LF 存到 data/tiktoken_cache，计数完全离线。另外，计数超时或失败时 LocalAgent 改用本地估算继续对话，不再整轮失败。LiteLLM's Windows wheels ship CRLF tokenizer files that fail tiktoken's hash check and trigger a download; LangBot now keeps a normalized offline copy, and a counting failure no longer fails the LocalAgent turn.
  • Runner availability / Runner 可用性：启动或重连期间，等待已安装插件完成初始化后再派发，不再报 Agent runner not found: plugin:langbot-team/LocalAgent/default。
  • Plugin runtime / 插件运行时：运行时重连期间，工作区同步和事件派发会先等待重连完成（最多 30 秒），不再在断连窗口内失败；附件和流的体积超限报错会给出实际大小和处理建议（SDK）。
  • Knowledge base / 知识库：向量库后端在后台线程中初始化。之前在较慢的机器上，首次入库会阻塞事件循环，导致插件运行时断连、入库失败。The vector backend is created off the event loop; the first ingestion on a slow host no longer drops the plugin runtime connection.
  • SQLite / SQLAlchemy：非 Docker 安装（pip / uvx）在 SQLAlchemy 2.1 上首次写入插件存储时报 unknown ON CONFLICT update shape 的问题已修复，依赖上限设为 <2.2；图片刷新期间释放 SQLite 写锁，减少 database is locked。
  • Box sandbox / Box 沙箱：过长的命令改为通过临时脚本执行，修复 Argument list too long 和大附件导入失败（SDK）。
  • Runners：Coze / Dify 处理已完成和 workflow 类型的输出，不再把这类响应当成空响应；LocalAgent 推理配置为空时不再报错。命令错误响应的反序列化不再崩溃（SDK）。
  • Runner interactions / Runner 交互：HTTP Bot、OneBot 等旧版适配器上，Runner 发起的交互（例如 Dify 工作流的人工输入节点）不再报 get_interaction_capabilities 错误，改为文本问答。Runner interactions on legacy adapters (HTTP Bot, OneBot, …) fall back to text instead of failing.
  • Telemetry / 遥测归因：取消的执行记为 cancelled 而不是失败；路由失败时保留错误详情；已经是终态的执行不再报转换错误；执行链的平台字段不再被工具来源（mcp / skill 等）覆盖。
  • Official plugins / 官方插件：EssentialCommands 0.1.12 修复 !func；HelloPlugin 0.1.6 去掉调试输出；LocalAgent 0.2.10、CozeAgent 0.2.5、DifyAgent 0.2.8 已在 Marketplace 上架。
  • SDK：langbot-plugin 由 0.7.23 固定到 0.7.24。

Release verification

  • Required checks (unit tests, fast integration, PostgreSQL contract, SQLAlchemy 2.0 / 2.1 matrix, Box integration, E2E startup, Core smoke, regression tools, lint) passed on the release commit.
  • Before tagging, the release candidate was installed and run through routine operations with both Docker (docker compose --profile box) and uvx (uvx --from <wheel> langbot, dependencies resolved from PyPI: SDK 0.7.24, SQLAlchemy 2.1.8). Each run used a fresh data directory. The checks covered account setup, the WebUI, Marketplace install with permission confirmation, enable and uninstall, models, a LocalAgent pipeline over HTTP Bot with a tool call in the Box sandbox, the !help !cmd !func !plugin !version commands, knowledge-base ingestion and retrieval, and persistence after a restart. The same checks were run with uvx on Windows 11 (code page 936) for the v4.11.6 candidate; v4.11.7 only changes platform-independent counting logic on top of it, including a plugin printing Chinese and emoji, and a first LocalAgent conversation with tokenizer downloads blocked (about 4 s, no network access).
  • Dify 1.18.0 human-input workflows were run end to end through DifyAgent over HTTP Bot.
  • v4.11.7 adds a concurrency check: 8–24 simultaneous LocalAgent conversations on one model, with no token-count rejections (v4.11.6 rejected 3–6 counts per 24-conversation round). An in-place upgrade from v4.11.6 data was also verified.
