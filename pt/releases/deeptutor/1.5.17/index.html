DeepTutor v1.5.17

#Deep Tutor v1.5.17 #DeepTutor v1.5.17 Release Notes Data de lançamento: 2026.08.25 v1.5.16 conectou uma biblioteca MarginNote e colocou uma série de falhas de gateway de lado. Isso muda a quem um Parceiro pertence: ele deixa de ser um recurso de toda a implantação que apenas um administrador pode tocar e se torna algo que cada membro constrói, possui e com o qual mantém suas próprias conversas privadas — um administrador ainda empresta as suas por meio de concessões. Em torno disso existe uma base de conhecimento que rastreia repositórios GitHub, Antigravity CLI em Meus Agentes, um código QR WeChat desenhado no navegador em vez de um arquivo de log e um contêiner que mantém os extras opcionais que você declarou. Os parceiros existentes continuam a trabalhar e migram; a única mudança de comportamento tem como escopo usuários não administradores, que agora podem ver uma página de Parceiros que costumava ser fechada para eles.

Novidades

Os parceiros pertencem às pessoas, não à implantação

Cada rota /api/v1/partners costumava ficar atrás de um portão administrativo geral, para que um membro pudesse falar com um parceiro que um administrador lhe designasse e nada mais. Em vez disso, três direitos agora se aninham: gerenciar (seu criador, mais qualquer administrador) cobre alma, canais, modelos, ativos, ciclo de vida e exclusão; use adiciona qualquer pessoa a quem um administrador tenha atribuído e significa manter uma conversa; ninguém mais pode ver que o parceiro existe - um parceiro sem dono e um parceiro invisível respondem da mesma forma, portanto, os ids não podem ser enumerados. As conversas seguem o humano, não o parceiro. Duas pessoas conversando com o mesmo companheiro nunca veem os tópicos uma da outra, e cada lado lê de volta no aplicativo da web em sua própria conta. As concessões ainda existem e seu formato permanece inalterado, mas agora oferecem apenas parceiros gerenciados pelo administrador: aquele que alguém construiu para si pode ser compartilhado ou não, já que seu SOUL.md geralmente é escrito pessoalmente.

Uma conta de bate-papo pode carregar sua identidade DeepTutor

Um parceiro acessado por QQ ou Telegram costumava conhecer apenas o ID do remetente local do canal, portanto, cada mensagem recebida era anônima - ela chegava ao pool de threads compartilhado e o parceiro respondia fora do espaço de trabalho do administrador, em vez da própria biblioteca do remetente. Peça um código ao seu parceiro no aplicativo web, envie /link <code> para ele a partir da conta de chat que você deseja conectar, e a partir daí esse remetente é você: a conversa é privada para sua conta, legível novamente no navegador, e o parceiro lê seu conhecimento, cadernos e memória da mesma forma que faria em um web turn.

Dois parceiros podem compartilhar um canal

Estado de tempo de execução do canal — tokens de bot, cursores de pesquisa longa, referências de conversa, armazenamentos de dispositivos E2EE — residiam em um diretório por canal, não por parceiro, portanto, dois parceiros configurados no mesmo canal leem as credenciais um do outro e sobrescrevem o cursor um do outro. Apenas um deles poderia estar online. O estado agora reside em data/partners/<id>/channels/<channel>/, e a árvore antiga é copiada na primeira inicialização quando seu proprietário tem certeza — o token salvo corresponde ao token configurado de um parceiro ou apenas um parceiro tem esse canal habilitado. Uma gravata genuína é autenticada novamente uma vez, em vez de receber a conta de outra pessoa.

WeChat pessoal faz login no navegador

A troca de código QR sempre funcionou, mas só foi executada a partir do próprio start() do canal e desenhou o código no stdout do servidor - que em qualquer implantação de contêiner é um log de supervisão que a pessoa que configura o parceiro não pode acessar (#951). A mesma troca agora é executada para o aplicativo web: pressione Scan to connect na página do canal do parceiro, faça a varredura e o token do bot será gravado na configuração do canal no lado do servidor. Uma resposta de status informa se o login foi bem-sucedido, nunca o que produziu. O terminal ainda imprime um código como substituto.

Uma base de conhecimento pode rastrear repositórios GitHub

Registre um repo, branch e glob como uma fonte GitHub e seu Markdown será colocado na KB e ressincronizado sob demanda, para que a documentação que você segue permaneça atualizada sem recarregá-la. Contribuído como #903; os destinos de download estão contidos no diretório raw/ da KB, já que um segmento .. ou um caminho absoluto em uma entrada de árvore teria sido escrito - e, no ramo de remoção, excluído - fora da base.

Antigravidade CLI junta-se aos Meus Agentes

O Google retirou o Gemini CLI em junho e direcionou seus usuários para o Antigravity CLI, então qualquer pessoa em um plano Google AI Pro/Ultra ou Gemini Code Assist ficou com um back-end gemini que não tinha CLI para detectar (#828). agy agora é um backend próprio – conecte-o, consulte-o no meio do caminho, retome suas conversas. O backend Gemini CLI permanece: ele ainda funciona para qualquer pessoa que possua uma chave Gemini API e uma conexão funcional não deve ser interrompida na atualização. ###deeptutor doctor Um comando que responde "este espaço de trabalho está pronto para iniciar uma sessão?" — configurações, provedores, dependências, portas. --online também envia uma pequena solicitação ao provedor do modelo configurado; --format json imprime o mesmo relatório para um script ou agente. Contribuído como #959.

Containers guardam os extras que você declarou

Um contêiner é descartável, então docker exec … pip install ".[partners]" sobrevive exatamente até o próximo compose down (#762). Em vez disso, declare-os na implantação - DEEPTUTOR_EXTRAS: "math-animator,partners" e DEEPTUTOR_APT_PACKAGES para bibliotecas do sistema - e cada contêiner iniciado a partir dele os reaplica. Um contêiner quente paga uma pesquisa de metadados por requisito, o cache pip reside no volume de dados e uma roda ausente deixa esse recurso indisponível em vez de interromper a implantação.

Os embeddings sobrevivem a um provedor com taxa limitada

Reindexar uma grande biblioteca em um provedor de baixo RPM costumava queimar horas e depois morrer em um 429. Três coisas mudaram: um pool de chaves gira em provider × model com resfriamento por chave para que uma chave acelerada não envenene mais a execução; um orçamento de nova tentativa espera Retry-After em vez de se esgotar em uma janela deslizante; e um acelerador em todo o processo serializa o intervalo mais postagem em reindexações simultâneas, que é o que fez uma solicitação bem-sucedida falhar manualmente dentro do aplicativo. Contribuído como #962. ###Janelas A análise do MinerU decodificou sua saída de subprocesso com o padrão da plataforma - GBK em uma instalação zh-CN - e morreu no primeiro byte não ASCII; seu renderizador de PDF multithread corrompeu separadamente o heap. Ambos são fixos, o protetor de renderização tem como escopo apenas o Windows (#844). As gravações atômicas agora tentam novamente um PermissionError transitório de um antivírus ou indexador que contém o destino, e a execução do código funciona em um host Windows (#964).

Sortido

  • O esforço de raciocínio é por conversa. O controle de nível de modelo do v1.5.9 agora pode ser substituído para um único bate-papo (#641, contribuído como #958).
  • A indexação falha limitada em vez de suspensa. Um provedor que aceita uma solicitação de incorporação e nunca a conclui paralisa o futuro do executor para sempre; uma proteção de pulsação agora aumenta após uma janela limitada sem progresso (#946).
  • Os blocos de layout de página do MinerU param de ser indexados como conteúdo. Cabeçalhos, rodapés e números de página são filtrados antes da ingestão; um tipo de bloco não reconhecido é indexado em vez de falhar em toda a execução, portanto, uma versão do MinerU que adiciona um não pode quebrar a indexação (#949).
  • A transcrição de voz aceita o que o Chrome grava. audio/webm;codecs=opus é normalizado uma vez, no limite do fio, em vez de ser rejeitado como um formato desconhecido (#945).
  • Os cartões de teste de domínio não ficam mais abaixo da dobra. O visualizador é montado após a janela de rolagem pós-transmissão ser fechada (#960), e um teste cujas opções repetem um rótulo ou uma resposta é rejeitado no registro, em vez de ser mostrado como um cartão sem resposta (#956).
  • Um caminho de aprendizagem mantém seu nome. Três superfícies o derivaram do primeiro módulo, portanto, reconstruir um mapa renomeou o caminho e os três poderiam discordar; uma função responde agora, e a derivação é o substituto, nunca o registro.
  • Uma ferramenta que altera o que a rodada opera é executada primeiro. Mudar o caminho de maestria no meio da rodada deixou as outras chamadas vinculadas ao estado com o qual a rodada começou; o despachante agora executa ferramentas de religação, religa todo o resto e, em seguida, executa as ferramentas de pausa por último.
  • As respostas locais do LightRAG citam suas fontes (#754), e o pipeline LlamaIndex local não congela mais sua decisão da barra de progresso no momento da importação (#864).
  • O Azure OpenAI aceita o ponto final que o portal lhe entrega. Um URL …/openai/deployments/<name>/chat/completions clássico é reduzido à superfície /openai/v1, pelo que o chat deixa de responder a 404 Resource not found enquanto a sonda de definições passa.
  • Gemini incorpora imagens onde o modelo suporta e recusa contents para aquele que não o faz, em vez de postar peças que o endpoint rejeitará (#814).
  • Uma página pode perguntar se um recurso está instalado. Recursos servidos por plug-in, como a sala de prática Whisper, foram oferecidos por uma instalação padrão que não poderia honrá-los, e a vez voltou Unknown capability (#963).
  • O pacote CLI independente declara o que realmente importa (#954).

DeepTutor v1.5.17

Highlights

  • Partners are now personal, with nested rights — /api/v1/partners loses its blanket admin gate. Rights split into manage (creator or admin: soul, channels, models, assets, lifecycle, deletion) and use (assigned users holding conversations); everyone else gets an indistinguishable "not found" so ids can't be enumerated. Members gain a Partners page, so any UI/API assumptions about locking them out are obsolete. Grants still work but now only offer admin-managed partners — a partner a member built for themselves won't appear in the assignable pool.

  • Conversations follow the human, including from chat — QQ/Telegram senders used to be anonymous channel-local ids landing in a shared admin thread pool. Ask a partner for a code in the web app, send /link <code> from the chat account, and that sender is bound to your identity: private thread, readable back in the browser, with the partner reading your knowledge/notebooks/memory. Two people talking to the same companion no longer see each other's threads.

  • Channel state moves per partner — migrate by copy — tokens, long-poll cursors, conversation refs and E2EE device stores used to live in one directory per channel (data/partners/<channel>/), so two partners on one channel read each other's credentials and only one could be online. State now lives at data/partners/<id>/channels/<channel>/; on first start the old tree is copied when ownership is unambiguous, ambiguous cases re-authenticate once, and the legacy tree is left untouched for manual recovery. Worth a backup if you run multiple partners on one channel.

  • GitHub repos become a KB source, with a traversal guard — register repo/branch/glob and Markdown is pulled and re-synced on demand (#903), so docs you follow stay current without re-uploading. The download path is confined to the KB's raw/ dir: .. segments and absolute paths in tree entries are rejected, closing a write — and on removal, delete — outside the base when ingesting untrusted repos.

  • Antigravity CLI, readiness checks, and persistent container extras — Google retired Gemini CLI in June (#828); agy is a new backend you can connect and consult mid-turn, while the gemini backend stays for API-key holders, so a working upgrade shouldn't break. deeptutor doctor (#959) adds one readiness check for settings/providers/deps/ports with --online and --format json for scripts. Container extras move from ephemeral docker exec … pip install ".[partners]" (lost on compose down, #762) to DEEPTUTOR_EXTRAS / DEEPTUTOR_APT_PACKAGES in Compose; preview with python scripts/install_extras.py --dry-run.

  • Embeddings stop dying on rate-limited providers — a per-key pool with cooldown across provider × model, a Retry-After-aware budget, and a process-wide throttle fix reindexes that previously burned hours then died on 429 (#962); a heartbeat guard bounds a provider that accepts a request and never completes (#946). Windows hosts also get MinerU decoding that no longer assumes UTF-8 plus a Windows-scoped renderer guard (#844) and atomic writes that retry transient PermissionError from AV/indexers (#964).

No breaking changes in this release — existing partners migrate themselves with no re-index or manual steps; the only behavior change is that non-admin users now see a Partners page.

DeepTutor v1.5.17 Release Notes

Release Date: 2026.08.25

v1.5.16 connected a MarginNote library and put a run of gateway failures to rest. This one changes who a Partner belongs to: they stop being a deployment-wide resource only an admin can touch and become something each member builds, owns, and holds their own private conversations with — an admin still lends theirs out through grants. Around that sit a knowledge base that tracks GitHub repositories, Antigravity CLI under My Agents, a WeChat QR code drawn in the browser instead of a log file, and a container that keeps the optional extras you declared. Existing partners keep working and migrate themselves; the one behavior change is scoped to non-admin users, who can now see a Partners page that used to be closed to them.

What's New

Partners belong to people, not to the deployment

Every /api/v1/partners route used to sit behind a blanket admin gate, so a member could talk to a partner an admin had assigned them and nothing else. Three rights now nest instead: manage (its creator, plus any admin) covers soul, channels, models, assets, lifecycle and deletion; use adds anyone an admin assigned it to, and means holding a conversation; anyone else cannot see that the partner exists — an unowned partner and an invisible one answer alike, so ids cannot be enumerated.

Conversations follow the human, not the partner. Two people talking to the same companion never see each other's threads, and each side reads back in the web app under its own account. Grants still exist and are unchanged in shape, but they now only offer admin-managed partners: one someone built for themselves is theirs to share or not, since its SOUL.md is usually written personally.

A chat account can carry your DeepTutor identity

A partner reached over QQ or Telegram used to know only a channel-local sender id, so every inbound message was anonymous — it landed in the shared thread pool, and the partner answered out of the admin workspace rather than the sender's own library. Ask your partner for a code in the web app, send /link <code> to it from the chat account you want connected, and from then on that sender is you: the conversation is private to your account, readable back in the browser, and the partner reads your knowledge, notebooks and memory the way it would in a web turn.

Two partners can share a channel

Channel runtime state — bot tokens, long-poll cursors, conversation references, E2EE device stores — lived in one directory per channel, not per partner, so two partners configured on the same channel read each other's credentials and overwrote each other's cursor. Only one of them could ever be online. State now lives under data/partners/<id>/channels/<channel>/, and the old tree is copied across on first start when its owner is certain — the saved token matches one partner's configured token, or only one partner has that channel enabled at all. A genuine tie re-authenticates once rather than being handed someone else's account.

Personal WeChat signs in from the browser

The QR-code exchange has always worked, but it only ran from the channel's own start() and drew the code on the server's stdout — which on any container deployment is a supervisord log the person configuring the partner cannot reach (#951). The same exchange now runs for the web app: press Scan to connect on the partner's channel page, scan, and the bot token is written into the channel config server-side. A status reply says whether the login succeeded, never what it produced. The terminal still prints a code as a fallback.

A knowledge base can track GitHub repositories

Register a repo, branch and glob as a GitHub source and its Markdown is pulled into the KB and re-synced on demand, so documentation you follow stays current without re-uploading it. Contributed as #903; download destinations are contained inside the KB's raw/ directory, since a .. segment or an absolute path in a tree entry would otherwise have written — and, on the removal branch, deleted — outside the base.

Antigravity CLI joins My Agents

Google retired Gemini CLI in June and pointed its users at Antigravity CLI, so anyone on a Google AI Pro/Ultra or Gemini Code Assist plan was left with a gemini backend that had no CLI to detect (#828). agy is now a backend of its own — connect it, consult it mid-turn, resume its conversations. The Gemini CLI backend stays: it still runs for anyone holding a Gemini API key, and a working connection must not break on upgrade.

deeptutor doctor

One command that answers "is this workspace ready to start a session?" — settings, providers, dependencies, ports. --online also sends a small request to the configured model provider; --format json prints the same report for a script or an agent. Contributed as #959.

Containers keep the extras you declared

A container is disposable, so docker exec … pip install ".[partners]" survives exactly until the next compose down (#762). Declare them on the deployment instead — DEEPTUTOR_EXTRAS: "math-animator,partners", and DEEPTUTOR_APT_PACKAGES for system libraries — and every container started from it re-applies them. A warm container pays one metadata lookup per requirement, the pip cache lives on the data volume, and a missing wheel leaves that one feature unavailable rather than taking the deployment down.

Embeddings survive a rate-limited provider

Reindexing a large library against a low-RPM provider used to burn hours and then die on a 429. Three things changed: a key pool rotates across provider × model with per-key cooldown so one throttled key no longer poisons the run; a retry budget waits out Retry-After instead of exhausting itself on a sliding window; and a process-wide throttle serializes the interval-plus-post across concurrent reindexes, which is what made a request that succeeded by hand fail inside the app. Contributed as #962.

Windows

MinerU parsing decoded its subprocess output with the platform default — GBK on a zh-CN install — and died on the first non-ASCII byte; its multi-threaded PDF renderer separately corrupted the heap. Both are fixed, the render guard scoped to Windows only (#844). Atomic writes now retry a transient PermissionError from an antivirus or indexer holding the target, and code execution works on a Windows host (#964).

Assorted

  • Reasoning effort is per conversation. The model-level control from v1.5.9 can now be overridden for a single chat (#641, contributed as #958).
  • Indexing fails bounded instead of hanging. A provider that accepts an embedding request and never completes it stalled the executor future forever; a heartbeat guard now raises after a bounded window of no progress (#946).
  • MinerU page-layout blocks stop being indexed as content. Headers, footers and page numbers are filtered before ingest; an unrecognized block type is indexed rather than failing the whole run, so a MinerU release that adds one cannot break indexing (#949).
  • Voice transcription accepts what Chrome records. audio/webm;codecs=opus is normalized once, at the wire boundary, instead of being rejected as an unknown format (#945).
  • Mastery quiz cards no longer land below the fold. The viewer mounts after the post-stream scroll window closed (#960), and a quiz whose options repeat a label or an answer is rejected at registration rather than shown as an unanswerable card (#956).
  • A learning path keeps its name. Three surfaces each derived it from the first module, so rebuilding a map renamed the path and the three could disagree; one function answers now, and derivation is the fallback, never the record.
  • A tool that changes what the round operates on runs first. Switching mastery path mid-round left the other calls bound to the state the round started with; the dispatcher now runs rebinding tools, re-binds everything else, then runs pausing tools last.
  • Local LightRAG answers cite their sources (#754), and the local LlamaIndex pipeline no longer freezes its progress-bar decision at import time (#864).
  • Azure OpenAI accepts the endpoint the portal hands you. A classic …/openai/deployments/<name>/chat/completions URL is reduced to the /openai/v1 surface, so chat stops answering 404 Resource not found while the settings probe passes.
  • Gemini embeds images where the model supports it, and refuses contents for one that does not rather than posting parts the endpoint will reject (#814).
  • A page can ask whether a capability is installed. Plugin-served capabilities such as the Whisper practice room were offered by a stock install that could not honour them, and the turn came back Unknown capability (#963).
  • The standalone CLI package declares what it actually imports (#954).

Upgrade Notes

pip install -U deeptutor; Docker users pull ghcr.io/hkuds/deeptutor:latest. No re-index and no manual migration.

  • Non-admin users gain a Partners page. On a multi-user deployment members can now create and manage their own partners, and their conversations with any partner are private to their account. Existing partners have no owner_id and therefore read as admin-managed — exactly what they were — so nothing you have configured changes hands.
  • Channel state moves per partner, by copy. On first start, state under data/partners/<channel>/ is copied to data/partners/<id>/channels/<channel>/ when its owner is unambiguous. The legacy tree is left untouched, so a bad outcome is recoverable by hand; a partner whose ownership was ambiguous simply re-authenticates once.
  • Grants only list admin-managed partners now. A partner a member built for themselves will not appear in the assignable pool.
  • Container extras are opt-in. Nothing changes until you set DEEPTUTOR_EXTRAS in your Compose file. Preview one with python scripts/install_extras.py --dry-run "<name>".
  • Gemini CLI connections keep working. Antigravity is an additional backend, not a replacement.
