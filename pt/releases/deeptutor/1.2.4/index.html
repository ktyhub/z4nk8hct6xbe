#Deep Tutor v1.2.4 #DeepTutor v1.2.4 Release Notes Data de lançamento: 2026.04.25

Destaques

Suporta mais formatos de anexo no bate-papo

O pipeline de anexos de documentos v1.2.3 foi expandido para além dos arquivos do Office. Os anexos de bate-papo agora aceitam os mesmos formatos de texto do roteador de ingestão da Base de conhecimento: Markdown, texto simples, logs, JSON/YAML/TOML, CSV/TSV, LaTeX/BibTeX, HTML/XML/SVG, folhas de estilo, scripts e arquivos de código-fonte comuns (.py, .js, .ts, .tsx, .java, .cpp, .go, .rs, .sql, .sh e mais).

  • Paridade de back-end com roteamento de KB — deeptutor/utils/document_extractor.py importa FileTypeRouter.TEXT_EXTENSIONS, portanto, anexos de bate-papo e uploads de KB compartilham uma fonte de verdade para formatos de texto/código. FileTypeRouter.decode_bytes() centraliza a cadeia de fallback UTF-8 / UTF-8-BOM / GBK / GB18030 / Latin-1 / CP1252.
  • SVG como fonte legível — .svg foi adicionado ao conjunto de extensões de texto RAG e é tratado como um anexo de documento em vez de uma imagem de visão, permitindo que o LLM inspecione a fonte XML enquanto o frontend ainda renderiza uma visualização segura em miniatura.
  • UX de anexo digitado — web/lib/doc-attachments.ts agora expõe OFFICE_EXTS, TEXT_LIKE_EXTS, detecção de SVG, substituto MIME/extensão mais rico e ícones específicos de categoria para código, shell, JSON, configuração, dados, marcação, folhas de estilo, texto simples, documentos do Office e SVG.
  • Cópia do Composer atualizada — a dica de arrastar e soltar agora anuncia "Imagens, documentos do Office, código e texto" em vez da antiga lista somente do Office.

Tour de configuração com um comando

O scripts/start_tour.py evoluiu de um assistente de configuração puro para um caminho de instalação nova em 7 etapas que pode detectar o ambiente local, instalar dependências e, em seguida, orientar a configuração do provedor.

  • Etapa de instalação de dependência — o tour verifica Python, uv, Node.js e npm; instala requisitos de backend, instala DeepTutor em modo editável e executa frontend npm install com saída de terminal ao vivo.
  • Compatibilidade com uv pip (#376) — A instalação da dependência Python agora prefere uv pip quando disponível e vincula --python <current-interpreter> para que os pacotes cheguem ao interpretador que executa o tour em vez de um .venv / $VIRTUAL_ENV não relacionado.
  • Detecção de npm do Windows (#381) — invocações de npm usam npm.cmd no Windows, corrigindo verificações de versão e comandos de instalação em sistemas onde o npm é exposto como um comando shim em vez de um executável.
  • Opções de LLM orientadas por registro de provedor — o assistente agora lê o registro PROVIDERS completo, agrupa provedores por modo, destaca serviços comuns e inclui opções mais recentes, como custom_anthropic, OpenRouter, SiliconFlow, provedores de codificação Volcengine/BytePlus, GitHub Copilot, OpenAI Codex, llama.cpp, OVMS, MiniMax, Mistral, Qianfan, Step Fun e Xiaomi MiMo.
  • Dicas de pesquisa e configuração — Serper está disponível na lista de provedores de pesquisa; A versão Azure/API e os prompts de proxy agora mostram orientações in-line em inglês e chinês.
  • UX de terminal de lista longa — scripts/_cli_kit.py renderiza menus de seleção longos dentro de uma janela de rolagem com indicadores "mais acima/abaixo", evitando linhas de terminal obsoletas quando a lista de provedores excede a altura da tela.

Exportação de Markdown de bate-papo

A página de bate-papo agora tem uma ação Baixar Markdown ao lado de "Salvar no Bloco de Notas" e "Novo Bate-papo". web/lib/chat-export.ts serializa a conversa atual como Markdown com um título, carimbo de data e hora de exportação ISO, títulos de função, rótulos de capacidade e metadados de anexo e, em seguida, baixa-a com um nome de arquivo higienizado com carimbo de data. Isso oferece aos usuários um caminho de exportação local leve para compartilhar, arquivar ou mover uma conversa para notas externas.

UI de gerenciamento da base de conhecimento polonês

A página Conhecimento foi reforçada para um gerenciamento diário mais denso:

  • As zonas de lançamento de criação e upload agora são cartões tracejados mais simples, com resumos concisos da política de upload in-line.
  • Os cartões KB passaram de quatro grandes painéis de estatísticas para linhas compactas mostrando contagem de documentos, prontidão do índice, horário da última atualização, provedor, modelo de incorporação, progresso ao vivo e caminho de armazenamento.
  • As ações padrão/de exclusão foram simplificadas visualmente, reduzindo a altura do cartão e facilitando a digitalização de grandes listas de KB.

Atualização de documentação e localização

A família README foi atualizada para corresponder à nova história de instalação e superfície do provedor:

  • README em polonês — assets/README/README_PL.md adiciona uma tradução completa em polonês do README do projeto (#379).
  • Documentos de configuração — o README principal e os READMEs multilíngues agora descrevem o tour guiado como o caminho recomendado para novos clones: crie um ambiente Python, execute python scripts/start_tour.py e use python scripts/start_web.py para inicialização diária.
  • Documentos do provedor — as tabelas de provedores foram atualizadas para o registro de provedores v1.2.3, incluindo custom_anthropic, endpoints canônicos do MiniMax, provedores de plano de codificação, provedores locais e notas de autenticação esclarecidas para OpenAI Codex/GitHub Copilot.
  • Seções de lançamento/notícias — READMEs multilíngues agora incluem resumos de v1.2.2 e v1.2.3, uma chamada de guia de contribuição e o marco da comunidade de 20 mil estrelas.

UI e correções de tema

  • Popovers com reconhecimento de tema — os menus de capacidade/ferramenta/referência/habilidade do compositor agora usam --popover mais desfoque de fundo em vez de --card, melhorando o contraste no tema Glass e contextos popover escuros.
  • Dicas de esquema de cores nativo — as raízes dos temas claro, escuro, Neve e Vidro declaram o color-scheme correto, melhorando os controles nativos e as superfícies renderizadas pelo navegador.
  • Hidratação de rolagem suave — a rolagem suave global agora está bloqueada por trás do html[data-scroll-behavior="smooth"], com o atributo definido pelo layout raiz para evitar aplicá-lo involuntariamente.
  • Dimensionamento do logotipo da barra lateral — as imagens do logotipo da barra lateral agora fixam classes de largura/altura renderizadas explícitas para evitar pequenas mudanças de layout.

Limpeza

Removido o ponteiro do submódulo nanobot obsoleto e o stub scripts/extract_numbered_items.sh obsoleto do repositório. A base de código v1.2.x agora depende da extração de documentos na árvore e dos caminhos de roteamento RAG em vez do auxiliar legado.

Expansão do conjunto de testes

  • Extração de documentos de back-end — tests/utils/test_document_extractor.py agora cobre texto simples, fonte Python, JSON, CSV, Markdown, entrada UTF-8-BOM, decodificação substituta GBK e extração de fonte SVG.
  • Classificação de anexos de front-end — web/tests/doc-attachments.test.ts agora cobre aceitação de texto/código, roteamento SVG como documento, detecção de nome de arquivo SVG sem distinção entre maiúsculas e minúsculas e as novas categorias de ícones para código, JSON, configuração, shell, dados, marcação, folhas de estilo e SVG.

DeepTutor v1.2.4

DeepTutor v1.2.4 Release Notes

Release Date: 2026.04.25

Highlights

Support More Attachment Formats in Chat

The v1.2.3 document-attachment pipeline has been expanded beyond Office files. Chat attachments now accept the same text-like formats as the Knowledge Base ingestion router: Markdown, plain text, logs, JSON/YAML/TOML, CSV/TSV, LaTeX/BibTeX, HTML/XML/SVG, stylesheets, scripts, and common source-code files (.py, .js, .ts, .tsx, .java, .cpp, .go, .rs, .sql, .sh, and more).

  • Backend parity with KB routing — deeptutor/utils/document_extractor.py imports FileTypeRouter.TEXT_EXTENSIONS, so chat attachments and KB uploads share one source of truth for text/code formats. FileTypeRouter.decode_bytes() centralizes the UTF-8 / UTF-8-BOM / GBK / GB18030 / Latin-1 / CP1252 fallback chain.
  • SVG as readable source — .svg was added to the RAG text extension set and is treated as a document attachment instead of a vision image, letting the LLM inspect the XML source while the frontend still renders a safe thumbnail preview.
  • Typed attachment UX — web/lib/doc-attachments.ts now exposes OFFICE_EXTS, TEXT_LIKE_EXTS, SVG detection, richer MIME/extension fallback, and category-specific icons for code, shell, JSON, config, data, markup, stylesheets, plain text, Office docs, and SVG.
  • Composer copy updated — the drag-and-drop hint now advertises "Images, Office docs, code & text" instead of the older Office-only list.

One-Command Setup Tour

scripts/start_tour.py has evolved from a pure configuration wizard into a 7-step fresh-install path that can detect the local environment, install dependencies, and then guide provider configuration.

  • Dependency installation step — the tour checks Python, uv, Node.js, and npm; installs backend requirements, installs DeepTutor in editable mode, and runs frontend npm install with live terminal output.
  • uv pip compatibility (#376) — Python dependency installation now prefers uv pip when available, and binds --python <current-interpreter> so packages land in the interpreter running the tour instead of an unrelated .venv / $VIRTUAL_ENV.
  • Windows npm detection (#381) — npm invocations use npm.cmd on Windows, fixing version checks and install commands on systems where npm is exposed as a command shim rather than an executable.
  • Provider registry-driven LLM choices — the wizard now reads from the full PROVIDERS registry, groups providers by mode, highlights common services, and includes newer options such as custom_anthropic, OpenRouter, SiliconFlow, Volcengine / BytePlus coding providers, GitHub Copilot, OpenAI Codex, llama.cpp, OVMS, MiniMax, Mistral, Qianfan, Step Fun, and Xiaomi MiMo.
  • Search and config hints — Serper is available in the search-provider list; Azure/API-version and proxy prompts now show inline guidance in both English and Chinese.
  • Long-list terminal UX — scripts/_cli_kit.py renders long select menus inside a scrolling window with "more above/below" indicators, preventing stale terminal rows when the provider list exceeds the screen height.

Chat Markdown Export

The chat page now has a Download Markdown action next to "Save to Notebook" and "New Chat". web/lib/chat-export.ts serializes the current conversation as Markdown with a title, ISO export timestamp, role headings, capability labels, and attachment metadata, then downloads it with a sanitized date-stamped filename. This gives users a lightweight local export path for sharing, archiving, or moving a conversation into external notes.

Knowledge Base Management UI Polish

The Knowledge page was tightened up for denser day-to-day management:

  • Creation and upload drop zones are now simpler dashed cards with concise inline upload-policy summaries.
  • KB cards moved from four large stat panels to compact rows showing document count, index readiness, last-updated time, provider, embedding model, live progress, and storage path.
  • Default/delete actions were simplified visually, reducing card height and making large KB lists easier to scan.

Documentation and Localization Refresh

The README family was updated to match the new install story and provider surface:

  • Polish README — assets/README/README_PL.md adds a complete Polish translation of the project README (#379).
  • Setup docs — the main README and multilingual READMEs now describe the guided tour as the recommended fresh-clone path: create a Python environment, run python scripts/start_tour.py, then use python scripts/start_web.py for daily launch.
  • Provider docs — provider tables were refreshed for the v1.2.3 provider registry, including custom_anthropic, MiniMax's canonical endpoints, coding-plan providers, local providers, and clarified authentication notes for OpenAI Codex / GitHub Copilot.
  • Release/news sections — multilingual READMEs now include v1.2.2 and v1.2.3 summaries, a contributing-guide callout, and the 20k-star community milestone.

UI and Theme Fixes

  • Theme-aware popovers — composer capability/tool/reference/skill menus now use --popover plus backdrop blur instead of --card, improving contrast in the Glass theme and dark popover contexts.
  • Native color-scheme hints — light, dark, Snow, and Glass theme roots declare the correct color-scheme, improving native controls and browser-rendered surfaces.
  • Smooth-scroll hydration — global smooth scrolling is now gated behind html[data-scroll-behavior="smooth"], with the attribute set by the root layout to avoid applying it unintentionally.
  • Sidebar logo sizing — sidebar logo images now pin explicit rendered width/height classes to prevent small layout shifts.

Cleanup

Removed the stale nanobot submodule pointer and the deprecated scripts/extract_numbered_items.sh stub from the repository. The v1.2.x codebase now relies on the in-tree document extraction and RAG routing paths instead of that legacy helper.

Test Suite Expansion

  • Backend document extraction — tests/utils/test_document_extractor.py now covers plain text, Python source, JSON, CSV, Markdown, UTF-8-BOM input, GBK fallback decoding, and SVG source extraction.
  • Frontend attachment classification — web/tests/doc-attachments.test.ts now covers text/code acceptance, SVG-as-document routing, case-insensitive SVG filename detection, and the new icon categories for code, JSON, config, shell, data, markup, stylesheets, and SVG.
