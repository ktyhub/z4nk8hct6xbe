#Deep Tutor v1.4.2 #DeepTutor v1.4.2 Release Notes Data de lançamento: 2026.05.28 v1.4.2 é uma versão de estabilidade e polimento além de v1.4.1. Ele desbloqueia Gemini 2.5+ no Visualize e no agente de chat, corrige um Regressão ContextVar que roteou silenciosamente solicitações autenticadas para o espaço de trabalho do administrador, fortalece o protocolo de bate-papo para modelos de raciocínio com chamada de ferramenta nativa, oferece UX de streaming suave em todos os bate-papos superfície e adiciona suporte para o fornecedor local Lemonade.

Gemini 2.5 + Raciocínio padrão desativado

Gemini 2.5 / 3 é enviado com pensamento habilitado por padrão e grava todo o Orçamento de max_tokens com base no raciocínio, a menos que reasoning_effort: "none" seja enviado no pedido. v1.4.2 centraliza essa lógica em reasoning_params.default_reasoning_effort_for, a única fonte de verdade usada por todos os três caminhos de execução (o OpenAI SDK, o aiohttp substituto e o construtor de raciocínio-kwargs). Visualize, converse, resolva, e o loop agente para de retornar corpos vazios quando configurado contra gemini-2.5-pro/gemini-2.5-flash/gemini-3-*.

Visualize o endurecimento do pipeline

Três modos de falha independentes são corrigidos:

  • Padrões de max_tokens por capacidade — Visualize agora tem seu próprio entrada em agents.yaml (tokens de 16k) propagados de DEFAULT_AGENTS_SETTINGS, então usuários existentes com um obsoleto data/user/settings/agents.yaml pega o limite mais alto automaticamente sem edição manual.
  • SVG / HTML root trim — quando um modelo envolve sua saída com prosa ("Aqui está: <svg>…") ou emite uma cerca de fechamento na mesma linha como tag de fechamento, o agente gerador agora corta para a parte mais externa <svg>…</svg> / <!doctype>…</html> para que o renderizador sempre receba uma raiz limpa.
  • Falha no modo JSON na etapa de revisão → fallback gracioso - grande ou SVGs complexos ocasionalmente tropeçam no modo JSON escaping dentro da revisão passo. Em vez de travar a curva, o Visualize agora registra a falha e envia o rascunho não revisado para que o usuário ainda veja uma renderização resultado.

Solicitações autenticadas chegam ao espaço de trabalho certo (#485)

Em v1.4.1, require_auth era uma dependência de sincronização FastAPI. RápidoAPI despacha dependências de sincronização via anyio.to_thread.run_sync, que executa-os em um thread de trabalho sob uma cópia do contexto da solicitação — então a chamada set_current_user(...) dentro da dependência instalada o usuário no contexto do thread, que foi descartado quando o tópico retornado. O endpoint então leu o padrão não definido e caiu de volta ao espaço de trabalho do administrador, roteando silenciosamente todos os autenticados leituras/gravações do usuário por meio dos dados do administrador local. require_auth e require_admin agora são async def, então eles execute na mesma tarefa assíncrona que o endpoint e o ContextVar é visível em todos os lugares a jusante. HTTP e WebSocket os pontos de entrada agora compartilham um único auxiliar _install_current_user, então o objeto de usuário resolvido a partir de uma carga de token é idêntico em transportes.

Modelos de raciocínio + chamada de ferramenta nativa: protocolo de rótulo corrigido

v1.4.1 tentou ser inteligente com modelos de raciocínio que possuem suporte para chamada de ferramenta - disse-lhes para ignorarem o TOOL/THINK/ Etiquetas FINISH/PAUSE e contam com reasoning_content plus tool_calls sozinho, e dentro de run_labeled_step tratou Prelúdios <think> e qualquer delta de chamada de ferramenta de entrada como implícito resoluções de rótulo. Na prática, ambos os atalhos prejudicam: quando uma ferramenta chamada vazou no fluxo de conteúdo como JSON em vez de um real tool_calls delta, não havia etiqueta para reparar e o loop tratou alegremente o JSON como resposta como um FINISH. Multivoltas raciocínio + fluxos de trabalho de ferramentas queimariam iterações no reparo tenta novamente ou encerra silenciosamente antecipadamente. Em v1.4.2:

  • O prompt do sistema de raciocínio + ferramentas nativas informa ao modelo que o raciocínio é exibido em uma área de rastreamento separada, mas o formal o fluxo de conteúdo ainda deve começar com exatamente um dos FINISH/TOOL/THINK/PAUSE.
  • run_labeled_step não trata mais deltas de chamada de ferramenta como autoritário para resolução de etiqueta, e implicit_think_label é ignorado (mantido para compatibilidade com API). Um rótulo faltando sempre cai para LABEL_UNKNOWN, então o caminho de reparo de protocolo do pipeline de chat pega-o em vez de desviar silenciosamente a curva.
  • Os prelúdios do <think>...</think> em linha são transmitidos ao vivo para o subtraço de raciocínio e retirado do text formal retornado para o loop - para que a área de resposta não vaze mais o provedor bruto marcadores.

Streaming suave em todas as superfícies de bate-papo

A máquina de escrever rAF (useSmoothStreamText) lançada na semana passada para o chat principal agora está conectado através do AssistantResponse, então o painel de bate-papo do livro, guia de acompanhamento do questionário e qualquer outra superfície que renderiza uma mensagem do assistente e obtém a mesma cadência alinhada ao quadro durante o streaming e uma passagem autônoma para mensagens concluídas. Correções complementares:

  • O painel de bate-papo do livro e a guia de acompanhamento do questionário mudaram sua rolagem automática para useLayoutEffect e parou de usar scrollIntoView({behavior: "smooth"}) — a animação suave corre contra o próximo quadro atualização de layout durante fluxos rápidos e produz jitter visível. Eles agora faça um único pino scrollTop = scrollHeight na fase de layout, correspondendo ao que useChatAutoScroll faz no chat principal.
  • O painel de bate-papo do livro marca seu scroller com data-chat-scroll-root, então aplica-se a regra global overflow-anchor: none (o navegador a ancoragem de rolagem integrada combate a fixação manual quando o código é bloqueado refluxo acima do cursor).
  • AssistantResponse agora está memorizado - as bolhas completadas param re-analisando a redução quando um irmão de streaming não relacionado atualiza o pai.

Redesenho da barra lateral

A lista de sessões de bate-papo da barra lateral expandida mudou para sua própria região recolhível Recentes com uma janela de visualização de rolagem independente, então históricos longos não empurram mais a navegação secundária para fora da tela. O "Novo bate-papo" botão desapareceu (click Chat na navegação já inicia um novo sessão) e um link do Documentos para deeptutor.info fica próximo ao link GitHub no rodapé. Cada sessão agora é renderizada com um ícone Lucide amigável e determinístico — brilhos, folha, pena, nuvem, gota, sol, lua, chama, estrela, etc.

  • para que a barra lateral pareça variada à primeira vista, sem embaralhar renderizar novamente. As sessões de corrida adicionam uma animação suave de movimento; os ociosos fique parado.

Fornecedor local de limonada

Nova ligação de provedor lemonade para o tempo de execução AMD Ryzen AI/NPU (URL base padrão http://localhost:13305/api/v1). Detectado automaticamente por porta 13305, nenhuma chave API necessária, listada no host README Docker- seção de gateway e nos documentos de configuração do provedor ao lado Ollama/LM Studio/llama.cpp/vLLM.

Models-Endpoint Probe homenageia DISABLE_SSL_VERIFY

A detecção automática da janela de contexto agora passa aiohttp.TCPConnector(ssl=False) quando DISABLE_SSL_VERIFY está definido, correspondendo ao comportamento do resto da camada HTTP. Local autoassinado servidores de inferência não voltam mais para a janela de contexto padrão só porque a sonda não conseguiu verificar o certificado.

Testes

  • tests/services/config/test_context_window_detection.py — o O probe models-endpoint homenageia DISABLE_SSL_VERIFY e passa em um TCPConnector(ssl=False) para a sessão aiohttp.

DeepTutor v1.4.2

Highlights

  • Auth context finally reaches endpoints (#485) — require_auth and require_admin were sync FastAPI dependencies, so anyio.to_thread.run_sync ran them in a worker thread under a copy of the request context; the set_current_user(...) ContextVar was discarded on thread return, and endpoints fell back to the admin workspace — silently routing every authenticated user's reads/writes through local admin data. Both are now async def (same asyncio task as the endpoint), and HTTP/WebSocket share one _install_current_user helper so the resolved user is identical across transports. Regression pinned in tests/api/test_auth_contextvar.py. Watch out: any other sync FastAPI dependency you've written that sets a ContextVar has this same silent-loss bug.

  • Gemini 2.5+/3 reasoning is default-off, centrally — thinking-on-by-default burned the entire max_tokens budget on reasoning and returned empty bodies across Visualize, Chat, Solve, and the agentic loop. A single source of truth, default_reasoning_effort_for, now emits reasoning_effort: "none" for gemini-2.5-pro / gemini-2.5-flash / gemini-3-*, consumed by all three execution paths (OpenAI SDK, aiohttp fallback, reasoning-kwargs builder). No config change is needed if you already wired a Gemini 2.5+ model — previously empty or truncated outputs just start working.

  • Reasoning + native tool-calling now enforces the label protocol — v1.4.1 let tool-call deltas and <think> preludes implicitly resolve labels, so a tool call that leaked into content as JSON could be treated as FINISH and terminate multi-turn workflows early. The formal stream must now begin with exactly one of FINISH/TOOL/THINK/PAUSE; run_labeled_step treats tool-call deltas as non-authoritative, ignores implicit_think_label (kept for API compatibility), and maps missing labels to LABEL_UNKNOWN so the repair path catches them. Inline <think>…</think> is streamed live to the reasoning sub-trace and stripped from text. This is a behavioral change: downstream consumers relying on implicit label resolution need revisiting.

  • Visualize hardened on three fronts (#490) — a seeded 16k Visualize entry in agents.yaml lets users with a stale config auto-upgrade, though a hand-edited max_tokens still wins (the new default only applies when Visualize isn't mentioned at all); generator output is trimmed to the outermost <svg>/<!doctype>…<html> root so prose-wrapped or fenced markup still renders cleanly; and a JSON-mode escaping crash in the review step now logs and ships the unreviewed draft instead of killing the turn. Note the upgrade nuance if you hand-tuned Visualize's cap. (First contribution from @skinred78.)

  • Streaming and local-provider polish — useSmoothStreamText is now wired through AssistantResponse, so book chat, quiz follow-ups, and every assistant bubble get frame-aligned rAF streaming with a no-op pass-through for completed messages; autoscroll moved to useLayoutEffect with a single scrollTop pin (dropping scrollIntoView({behavior:"smooth"}) jitter), data-chat-scroll-root disables scroll anchoring, and bubbles are memoized to stop re-parsing markdown on sibling updates. Sidebar sessions moved into a collapsible Recents viewport with deterministic Lucide icons; a new lemonade provider targets AMD Ryzen AI/NPU at localhost:13305 (auto-detected, no API key); and the models-endpoint probe honors DISABLE_SSL_VERIFY via TCPConnector(ssl=False) so self-signed local servers keep their detected context window.

  • Breaking changes — None; drop-in from v1.4.1 (pip install -U deeptutor / ghcr.io/hkuds/deeptutor:latest).

DeepTutor v1.4.2 Release Notes

Release Date: 2026.05.28

v1.4.2 is a stability and polish release on top of v1.4.1. It unblocks Gemini 2.5+ across Visualize and the chat agent, fixes a ContextVar regression that silently routed authenticated requests to the admin workspace, hardens the chat protocol for reasoning models with native tool calling, ships smooth-streaming UX across every chat surface, and adds support for the Lemonade local provider.

Gemini 2.5+ Reasoning Default-Off

Gemini 2.5 / 3 ship with thinking enabled by default and burn the entire max_tokens budget on reasoning unless reasoning_effort: "none" is sent on the request. v1.4.2 centralizes that logic in reasoning_params.default_reasoning_effort_for, the single source of truth used by all three execution paths (the OpenAI SDK, the aiohttp fallback, and the reasoning-kwargs builder). Visualize, Chat, Solve, and the agentic loop all stop returning empty bodies when configured against gemini-2.5-pro / gemini-2.5-flash / gemini-3-*.

Visualize Pipeline Hardening

Three independent failure modes are fixed:

  • Per-capability max_tokens defaults — Visualize now has its own entry in agents.yaml (16k tokens) seeded from DEFAULT_AGENTS_SETTINGS, so existing users with a stale data/user/settings/agents.yaml pick up the higher cap automatically without hand-editing.
  • SVG / HTML root trim — when a model wraps its output with prose ("Here you go: <svg>…") or emits a closing fence on the same line as the closing tag, the generator agent now trims to the outermost <svg>…</svg> / <!doctype>…</html> so the renderer always receives a clean root.
  • Review-step JSON-mode crash → graceful fallback — large or complex SVGs occasionally trip JSON-mode escaping inside the review step. Instead of crashing the turn, Visualize now logs the failure and ships the unreviewed draft so the user still sees a rendered result.

Authenticated Requests Land In The Right Workspace (#485)

In v1.4.1, require_auth was a sync FastAPI dependency. FastAPI dispatches sync dependencies via anyio.to_thread.run_sync, which runs them in a worker thread under a copy of the request context — so the set_current_user(...) call inside the dependency installed the user on the thread's context, which was discarded when the thread returned. The endpoint then read the unset default and fell back to the admin workspace, silently routing every authenticated user's reads/writes through the local admin's data.

require_auth and require_admin are now async def, so they execute in the same asyncio task as the endpoint and the ContextVar is visible everywhere downstream. HTTP and WebSocket entry points now share a single _install_current_user helper so the user object resolved from a token payload is identical across transports.

Reasoning Models + Native Tool Calling: Label Protocol Fixed

v1.4.1 tried to be clever with reasoning models that have native tool-calling support — it told them to ignore the TOOL/THINK/ FINISH/PAUSE labels and rely on reasoning_content plus tool_calls alone, and inside run_labeled_step it treated <think> preludes and any incoming tool-call delta as implicit label resolutions. In practice both shortcuts hurt: when a tool call leaked into the content stream as JSON instead of a real tool_calls delta, there was no label to repair against, and the loop happily treated the JSON-as-answer as a FINISH. Multi-turn reasoning + tool workflows would either burn iterations on repair retries or silently terminate early.

In v1.4.2:

  • Reasoning + native-tools system prompt tells the model that reasoning is displayed in a separate trace area, but the formal content stream must still start with exactly one of FINISH/TOOL/THINK/PAUSE.
  • run_labeled_step no longer treats tool-call deltas as authoritative for label resolution, and implicit_think_label is ignored (kept for API compatibility). A missing label always falls to LABEL_UNKNOWN, so the chat pipeline's protocol-repair path catches it instead of silently mis-routing the turn.
  • Inline <think>...</think> preludes are streamed live into the reasoning sub-trace and stripped from the formal text returned to the loop — so the answer area no longer leaks raw provider markers.

Smooth Streaming Across Every Chat Surface

The rAF typewriter (useSmoothStreamText) introduced last week for the main chat is now wired through AssistantResponse, so the book chat panel, quiz follow-up tab, and any other surface that renders an assistant message all get the same frame-aligned cadence during streaming and a no-op pass-through for completed messages.

Companion fixes:

  • Book chat panel and quiz follow-up tab moved their autoscroll to useLayoutEffect and stopped using scrollIntoView({behavior: "smooth"}) — the smooth animation races against the next-frame layout update during fast streams and produces visible jitter. They now do a single scrollTop = scrollHeight pin in layout phase, matching what useChatAutoScroll does on the main chat.
  • Book chat panel marks its scroller with data-chat-scroll-root so the global overflow-anchor: none rule applies (the browser's built-in scroll anchoring fights manual pinning when code blocks reflow above the cursor).
  • AssistantResponse is now memoized — completed bubbles stop re-parsing markdown when an unrelated streaming sibling updates the parent.

Sidebar Redesign

The expanded sidebar's chat-session list moved into its own collapsible Recents region with an independent scroll viewport, so long histories no longer push secondary nav off-screen. The "New chat" button is gone (clicking Chat in the nav already starts a new session), and a Docs link to deeptutor.info sits next to the GitHub link in the footer.

Each session now renders with a deterministic, friendly Lucide icon — sparkles, leaf, feather, cloud, droplet, sun, moon, flame, star, etc. — so the sidebar feels varied at a glance without shuffling on re-render. Running sessions add a gentle wiggle animation; idle ones stay still.

Lemonade Local Provider

New lemonade provider binding for the AMD Ryzen AI / NPU runtime (default base URL http://localhost:13305/api/v1). Auto-detected by port 13305, no API key required, listed in the README Docker host- gateway section and in the provider configuration docs alongside Ollama / LM Studio / llama.cpp / vLLM.

Models-Endpoint Probe Honors DISABLE_SSL_VERIFY

The context-window auto-detection now passes aiohttp.TCPConnector(ssl=False) when DISABLE_SSL_VERIFY is set, matching the behavior of the rest of the HTTP layer. Self-signed local inference servers no longer fall back to the default context window just because the probe couldn't verify their cert.

Tests

  • tests/api/test_auth_contextvar.py — pins the regression from #485: a sync require_auth would lose the ContextVar; the async version preserves it across the dependency boundary.
  • tests/services/llm/test_reasoning_params.py — covers the centralized default_reasoning_effort_for mapping.
  • tests/core/test_labeled_step_think_prelude.py — updated to reflect the new "labels are always required" semantics.
  • tests/agents/chat/test_agentic_parallel_tools.py — verifies the reasoning + native-tools path still resolves multi-tool turns.
  • tests/services/config/test_context_window_detection.py — the models-endpoint probe honors DISABLE_SSL_VERIFY and passes a TCPConnector(ssl=False) to the aiohttp session.

Upgrade Notes

  • Drop-in from v1.4.1: pip install -U deeptutor; Docker users pull ghcr.io/hkuds/deeptutor:latest.
  • If you previously hand-edited data/user/settings/agents.yaml to bump Visualize's max_tokens, that value still wins. The new 16k default only seeds users whose agents.yaml doesn't mention Visualize at all.
  • If you wired a Gemini 2.5+ model and saw empty or truncated outputs, no configuration change is needed — the default-off behavior now applies automatically.
