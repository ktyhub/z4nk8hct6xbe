#Deep Tutor v1.6.4 #DeepTutor v1.6.4 Release Notes Data de lançamento: 2026.09.03 v1.6.4 torna o espaço de trabalho de aprendizagem mais leve no início, mais claro durante a execução de um trabalho longo e mais durável quando você alterna entre as páginas. Books e Mastery Path ganham controles de origem e geração mais precisos, Reading lembra mais de seu lugar e perfis de modelo descrevem explicitamente seu protocolo de conexão e recursos. Os espaços de trabalho existentes migram automaticamente; os autores de extensão que usam módulos LLM privados devem revisar as notas de atualização.

Novidades

Inicialização mais leve e trabalho pesado isolado

Ferramentas e recursos integrados agora são carregados apenas quando usados, enquanto o provedor SDK clients compartilha um pool limitado em vez de crescer sem limites. A análise de documentos e outros trabalhos pesados ​​são executados através de processos de trabalho isolados, portanto, é menos provável que uma falha do analisador ou um pico de memória leve o servidor principal consigo. As implantações podem ajustar a simultaneidade com DEEPTUTOR_ISOLATED_WORKERS.

Livros expõem o real plano de geração

Antes do início da geração, os Livros mostram uma estimativa de capítulo ao vivo e permitem escolher quais tipos de conteúdo gerado pertencem ao resultado. Você pode gerar o livro inteiro ou apenas o primeiro capítulo e, em seguida, seguir os estados honestos de fila, execução, pausa, retomada e interrupção, em vez de adivinhar se o trabalho ainda está ativo.

Mastery Path cobre o material que você selecionou

Uma base de conhecimento local agora pode ser restrita a arquivos individuais ao construir um caminho. Se os tópicos gerados perderem o material selecionado, a revisão de cobertura nomeia a lacuna e permite regenerar com os arquivos necessários ou aceitar a omissão deliberadamente. O Bate-papo comum também pode oferecer um cartão de transferência confirmado por click para retomar um tópico de domínio ou iniciar uma nova sessão de estudo sem navegar por conta própria.

Leitura e conversas mantêm seu lugar

A leitura adiciona marcadores duráveis, restaura texto salvo ou posições de EPUB e fornece feedback mais claro da unidade anterior/próxima, controles de tipografia, um complemento redimensionável e exportação de bloco de notas. As conversas continuam durante a navegação com estado não lido, arquivamento e restauração, captura de notebook e atualizações de títulos preservados de forma mais consistente.

Uma linguagem de atividade em todo o espaço de trabalho

Chat, Livros, Co-Writer e a barra lateral agora compartilham a mesma apresentação de atividades para trabalho na fila, progresso, conclusão, interrupção e falha. O trabalho de longa duração é mais fácil de reconhecer e controlar sem que cada superfície invente um vocabulário de status diferente.

Os endpoints do modelo se descrevem

Os perfis LLM e Task podem usar roteamento automático ou selecionar explicitamente conclusões de bate-papo OpenAI, respostas OpenAI ou mensagens antrópicas. A descoberta de modelo de endpoint anexa IDs de modelo selecionados sem substituir entradas existentes, e substituições por modelo podem marcar chamada de ferramenta, entrada de imagem, saída JSON e controles de raciocínio como Automático, Suportado ou Não suportado.

Notas de atualização

Execute pip install -U deeptutor; Os usuários do Docker puxam o ghcr.io/hkuds/deeptutor:latest. Configurações, livros, sessões e dados de aprendizagem existentes não precisam de migração manual.

  • As configurações existentes do wire_api migram para o api_format; os campos de compatibilidade permanecem legíveis e as ligações antrópicas legadas continuam a ser carregadas.
  • O Markdown da memória legada passa de data/user/workspace/memory para data/memory. Os conflitos de nomes são copiados em vez de substituídos; atualize scripts externos que ainda direcionam o caminho antigo.
  • A dependência do agendador agora está instalada com o aplicativo completo. Nenhuma instalação separada do croniter é necessária.
  • Extensões que importam módulos privados abaixo de deeptutor.services.llm.executors ou módulos de implementação de provedor devem ser movidas para a fábrica pública e superfícies de protocolo. Os shims de nuvem/locais obsoletos permanecem para esta versão.
  • DEEPTUTOR_ISOLATED_WORKERS é opcional e o padrão é 2; diminua-o em hosts muito pequenos ou aumente-o somente após medir a memória do analisador.
  • Os guias em inglês e chinês foram atualizados juntos em deeptutor.info. Changelog completo: https://github.com/HKUDS/DeepTutor/compare/v1.6.3...v1.6.4

DeepTutor v1.6.4

Highlights

  • Isolated heavy work and lazy loading — Built-in tools now load on demand and provider SDK clients share a bounded pool instead of growing without limit, while document parsing moves into separate worker processes tuned via DEEPTUTOR_ISOLATED_WORKERS (default 2). The real win for operators is fault containment: a parser crash or memory spike is far less likely to take the main server down. Watch the sizing, though — lower the pool on small hosts and only raise it after measuring parser memory, since the default may be aggressive on constrained deployments.

  • Books show the real generation plan — Before generation starts you get a live chapter estimate and can pick which generated content types land in the result, run the whole book or just the first chapter, and follow honest queued/running/paused/resumed/interrupted states. This is fundamentally a cost-and-time control: you can pilot a single chapter before committing to a full book, and you no longer have to guess whether a stalled job is still alive.

  • Mastery Path honors your file selection — A local Knowledge Base can be narrowed to individual files, and coverage review now names exactly which selected material the generated topics missed, letting you regenerate with those files required or deliberately accept the omission. Chat can also offer a click-confirmed hand-off card to resume or start a Mastery session rather than auto-navigating — a meaningful workflow guard, since study sessions no longer hijack the UI without consent.

  • Reading and conversations keep their place — Reading adds durable bookmarks, restores saved text/EPUB positions, and gains typography controls, a resizable companion, and notebook export; conversations preserve unread state, archive/restore, notebook capture, and title updates across navigation. A single activity vocabulary now spans Chat, Books, Co-Writer, and the sidebar, which cuts cognitive load on long-running work — but any downstream tooling parsing per-surface status strings will need to map onto the new shared states.

  • Explicit wire protocols and migration chores — LLM/Task profiles can now pin Auto, OpenAI Chat Completions, OpenAI Responses, or Anthropic Messages, with per-model overrides for tool calling, image input, JSON output, and reasoning; discovery appends model IDs instead of replacing them. Budget time for the upgrade path: wire_api becomes api_format (compat fields still readable), legacy memory Markdown moves from data/user/workspace/memory to data/memory (conflicts are backed up, but update external scripts pointing at the old path), croniter is now bundled, and extension authors importing private modules under deeptutor.services.llm.executors or provider implementations must migrate to the public factory/protocol surfaces — deprecated shims remain only for this release.

DeepTutor v1.6.4 Release Notes

Release Date: 2026.09.03

v1.6.4 makes the learning workspace lighter to start, clearer while long work is running, and more durable when you move between pages. Books and Mastery Path gain finer source and generation controls, Reading remembers more of your place, and model profiles describe their wire protocol and capabilities explicitly. Existing workspaces migrate automatically; extension authors using private LLM modules should review the upgrade notes.

What's New

Lighter startup and isolated heavy work

Built-in tools and capabilities now load only when used, while provider SDK clients share a bounded pool instead of growing without limit. Document parsing and other heavy jobs run through isolated worker processes, so a parser crash or memory spike is less likely to take the main server with it. Deployments can tune concurrency with DEEPTUTOR_ISOLATED_WORKERS.

Books expose the real generation plan

Before generation starts, Books show a live chapter estimate and let you choose which generated content types belong in the result. You can generate the whole book or only the first chapter, then follow honest queued, running, paused, resumed, and interrupted states instead of guessing whether work is still alive.

Mastery Path covers the material you selected

A local Knowledge Base can now be narrowed to individual files when building a path. If generated topics miss selected material, the coverage review names the gap and lets you regenerate with those files required or accept the omission deliberately. Ordinary Chat can also offer a click-confirmed hand-off card to resume a Mastery topic or start a new study session without navigating on its own.

Reading and conversations keep their place

Reading adds durable bookmarks, restores saved text or EPUB positions, and provides clearer previous/next-unit feedback, typography controls, a resizable companion, and notebook export. Conversations continue across navigation with unread state, archive and restore, notebook capture, and title updates preserved more consistently.

One activity language across the workspace

Chat, Books, Co-Writer, and the sidebar now share the same activity presentation for queued work, progress, completion, interruption, and failure. Long-running work is easier to recognize and control without each surface inventing a different status vocabulary.

Model endpoints describe themselves

LLM and Task profiles can use Auto routing or explicitly select OpenAI Chat Completions, OpenAI Responses, or Anthropic Messages. Endpoint model discovery appends selected model IDs without replacing existing entries, and per-model overrides can mark tool calling, image input, JSON output, and reasoning controls as Auto, Supported, or Not supported.

Upgrade Notes

Run pip install -U deeptutor; Docker users pull ghcr.io/hkuds/deeptutor:latest. Existing settings, books, sessions, and learning data need no manual migration.

  • Existing wire_api settings migrate to api_format; compatibility fields remain readable, and legacy Anthropic bindings continue to load.
  • Legacy memory Markdown moves from data/user/workspace/memory to data/memory. Name conflicts are backed up rather than overwritten; update external scripts that still target the old path.
  • The scheduler dependency is now installed with the full application. No separate croniter install is required.
  • Extensions importing private modules below deeptutor.services.llm.executors or provider implementation modules must move to the public factory and protocol surfaces. Deprecated cloud/local shims remain for this release.
  • DEEPTUTOR_ISOLATED_WORKERS is optional and defaults to 2; lower it on very small hosts or raise it only after measuring parser memory.
  • The English and Chinese guides have been updated together at deeptutor.info.
