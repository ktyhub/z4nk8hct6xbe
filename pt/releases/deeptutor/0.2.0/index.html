DeepTutor v0.2.0

Highlights

  • Container-first deployment — PR #14 introduces a multi-stage Dockerfile plus separate dev and production docker-compose configs. This is the lowest-friction path to a reproducible deployment: no manual conda/pip bootstrapping on the host, and the multi-stage build keeps the production image lean. If you were scripting your own environment setup, this is worth adopting as the new baseline.
  • Treat this as a security release — PR #20 patches critical RCE and LFI (path-traversal) vulnerabilities, PR #11 applies least-privilege hardening across the app, PR #21 updates dependencies to clear known CVEs, and PR #22 enforces WSS for production WebSockets. If you're running v0.1 anywhere exposed, upgrade promptly. Watch the WebSocket change specifically: any production client still connecting over ws:// will need to move to wss:// or connections will fail.
  • Frontend stack jump to Next.js 16 / React 19 — a major-version upgrade of the framework and UI library, not a routine dependency bump. Expect performance and feature gains, but downstream customizations, custom components, or App Router assumptions should be regression-tested — React 19 and Next.js 16 carry their own breaking changes that aren't enumerated here.
  • More reliable Smart Solver output — PR #18 fixes JSON parsing failures for triple-quoted Python strings, a common shape in LLM-generated responses. This matters because it removes a class of silent parse failures where solver output was technically correct but unreadable by the pipeline — a direct reliability win for anything consuming structured solver results.
  • SolveAgent planning behavior changed — PR #23 forces intent-only planning during code generation. This is a behavioral change, not just a bug fix: generated code should be better aligned with stated intent, but teams relying on previous generation patterns should re-validate prompts and review outputs after upgrading.
  • Smoother local setup and UI polish — PR #2 removes false "Virtual env not detected" warnings under conda, PR #12 fixes DisplayManager attribute initialization when the rich library isn't installed, and PR #10 fixes the knowledge-base modal backdrop and positioning. Small changes, but they remove real onboarding friction and headless/minimal-install crashes.

No explicit breaking changes are called out in this release.

Release v0.2.0

🚀 New Features

Docker Deployment: Added multi-stage Dockerfile and docker-compose configurations for both development and production environments Enhanced WebSocket Security: Improved websocket security with comprehensive documentation

🔧 Improvements

Next.js 16 & React 19: Upgraded frontend framework to the latest versions for better performance and features JSON Parsing: Fixed JSON parsing for triple-quoted Python strings, improving output reliability UI Enhancements: Fixed knowledge base modal backdrop and positioning issues Install Scripts: Improved installation scripts with better conda environment detection and session management SolveAgent: Enhanced code generation by enforcing intent-only planning

🔒 Security

Fixed critical path traversal and injection vulnerabilities Updated dependencies to address security vulnerabilities Hardened application attack surface through least privilege principle Enhanced secure websockets implementation

🐛 Bug Fixes

Fixed DisplayManager attributes initialization before rich availability check Various UI and core stability improvements
