#Deep Tutor v1.5.9 #DeepTutor v1.5.9 Release Notes Data de lançamento: 2026.08.04 Onde v1.5.8 era sobre memória, este é sobre provedores - o endpoint Embedding 2 nativo do Gemini, um controle de esforço de raciocínio por modelo, um gateway Novita AI - e sobre os caminhos que estavam silenciosamente errados abaixo deles: consultas incorporadas como se fossem documentos, none ativando o pensamento, uma falha de capacidade chegando como uma mensagem em branco. Drop-in para a maioria das instalações, mas os usuários do docker-compose.ghcr.yml têm uma migração de dados única para executar antes do próximo up.

Novidades

Gemini Incorporando 2 sobre o API nativo

Um perfil de incorporação Gemini agora tem como padrão o endpoint …/models/<model>:batchEmbedContents nativo do Google com gemini-embedding-2, autenticado com x-goog-api-key, e o endpoint segue o modelo que você escolher – inclusive por meio de um prefixo de gateway. Os perfis gemini-embedding-001 existentes permanecem deliberadamente no caminho compatível com OpenAI: a rota nativa envia um taskType e normaliza L2 o que retorna, portanto, movê-los alteraria seus vetores de documento e invalidaria silenciosamente o índice construído a partir deles. Aponte você mesmo base_url para o URL nativo para ativar qualquer modelo.

As consultas deixam de ser incorporadas como documentos

Os embeddings de recuperação agora cumprem sua função. As tags LlamaIndex consultam search_query e passagens search_document, LightRAG mapeia sua própria dica de contexto da mesma maneira e os adaptadores optam explicitamente (SUPPORTS_INPUT_TYPE) para que um back-end que nunca enviou uma função continue não enviando uma. Somente o Cohere — que exige o campo e já tem como padrão search_document — muda hoje: os vetores do documento permanecem intactos, as consultas finalmente ganham a função correta. Sem reindexação.

Um seletor de esforço de raciocínio por modelo

Cada modelo LLM no catálogo obtém uma profundidade de raciocínio padrão opcional ao lado de sua janela de contexto, oferecida apenas onde o provedor realmente suporta uma e rotulada no próprio vocabulário desse provedor (mínimo/baixo/médio/alto/xalto para famílias no estilo OpenAI, adaptativo onde esse é o único modo ligado, um simples ligado/desligado para o resto). Padrão do provedor (Automático) deixa a escolha para o provedor. Dois bugs antrópicos falharam na fiação: none estava pensando ligado com um orçamento de 4.096 tokens, e um adaptive armazenado enviado para uma família mais velha atraiu 400 em vez do orçamento padrão.

Novita AI e MiniMax na plataforma certa

Novita AI junta-se aos gateways LLM (novita, https://api.novita.ai/openai). O MiniMax executa duas plataformas separadas cujas chaves não são intercambiáveis, e o padrão agora aponta para a global (api.minimax.io) em vez da da China continental; As janelas de contexto minimax-m3 e minimax-m2.7 são registradas e a detecção também lê um campo context_size.

As implantações do Compose mantêm todo o data/

docker-compose.ghcr.yml montou em bind apenas data/user, data/memory e data/knowledge_bases, então data/system (o segredo de assinatura JWT, contas, concessões, tokens Codex por proprietário), data/users, data/partners e data/cli-apps viviam na camada gravável do contêiner e eram descartados em cada recriação. Agora ele monta a árvore inteira, combinando com os outros arquivos do Compose. As implantações de volume nomeado e de compilação de origem nunca foram afetadas.

Login do Codex dentro de um contêiner local

As implantações locais padrão de Docker e Podman colocam o navegador e o servidor em redes de loopback separadas, de modo que o retorno de chamada do OAuth nunca chegou. Agora existe uma sobreposição compose.codex-oauth.yaml temporária (e os comandos docker/podman equivalentes) que publica as portas 1455/1457 apenas enquanto você faz login – com desmontagem, para que essas portas voltem para seus outros Codex clients. Consulte CONTAINERIZATION.md.

Falhas que costumavam chegar como nada

Uma capacidade levantada - ou uma solicitação de uma que não existe - encerrou o stream sem veredicto, e o turno foi persistido como completed com resposta vazia. O erro agora é marcado como terminal e realizado por meio de um evento DONE, então o turno é armazenado como failed com sua mensagem e a UI mostra o que deu errado em vez de uma bolha vazia.

Sortido

  • O idioma da interface que você salvou é respeitado no primeiro carregamento. Ele residia nas configurações ui do backend, que apenas a rota Configurações já lia, então todas as outras páginas começavam em inglês até que você as selecionasse novamente naquele navegador. A escolha local ainda vence.
  • O Visualize não aborta mais quando o modelo de análise inventa um render_type ou visual_genre fora do enum — o valor off-enum é descartado e o campo volta ao seu padrão.
  • Parâmetros de consulta semelhantes a credenciais (key, api_key, token, access_token) são editados em cada terminal que o assistente, o client e as mensagens de erro são impressas.

DeepTutor v1.5.9

Highlights

  • docker-compose.ghcr.yml requires a one-time migration — The configuration now persists all of data/, including data/system, data/users, data/partners, and data/cli-apps. Before the next up -d, run the documented docker cp loop; otherwise empty host directories will shadow existing container state, regenerate the JWT secret, and hide non-admin accounts. Named-volume and source-build deployments are unaffected.
  • Embeddings distinguish queries from documents — Retrieval adapters now explicitly identify query versus passage embeddings (search_query versus search_document). Cohere queries finally use the correct role without changing document vectors or requiring re-indexing. New Gemini profiles default to gemini-embedding-2 on the native :batchEmbedContents endpoint with x-goog-api-key; existing gemini-embedding-001 profiles intentionally remain on the OpenAI-compatible path to protect existing indexes.
  • Reasoning effort is configurable per model — The model catalog exposes provider-specific controls, with Auto preserving provider defaults. Two Anthropic wiring bugs are fixed: none no longer enables thinking with a 4096-token budget, and unsupported stored adaptive values no longer trigger a 400 for older model families.
  • Novita AI arrives; MiniMax defaults move globally — novita is available at https://api.novita.ai/openai. MiniMax now defaults to api.minimax.io; mainland-China deployments must set base_url to https://api.minimaxi.com/v1 or /anthropic and use a China-platform key, since platform keys are not interchangeable. Saved profiles retain their existing URLs.
  • Local containers gain a temporary Codex OAuth bridge — A compose.codex-oauth.yaml overlay publishes ports 1455 and 1457 only during browser sign-in, then removes them so they remain available to other Codex clients. This addresses loopback callbacks that could not reach the containerized server.
  • Streaming capability failures are now terminal and visible — Raised or missing capabilities propagate through a terminal DONE event instead of silently ending the stream. Affected turns are stored as failed with an error message rather than completed with an empty answer, and the UI can surface the failure.

DeepTutor v1.5.9 Release Notes

Release Date: 2026.08.04

Where v1.5.8 was about memory, this one is about providers — Gemini's native Embedding 2 endpoint, a per-model reasoning-effort control, a Novita AI gateway — and about the paths that were quietly wrong underneath them: queries embedded as if they were documents, none turning thinking on, a capability crash arriving as a blank message. Drop-in for most installs, but docker-compose.ghcr.yml users have a one-time data migration to run before their next up.

What's New

Gemini Embedding 2 over the native API

A Gemini embedding profile now defaults to Google's native …/models/<model>:batchEmbedContents endpoint with gemini-embedding-2, authenticated with x-goog-api-key, and the endpoint follows the model you pick — including through a gateway prefix. Existing gemini-embedding-001 profiles deliberately stay on the OpenAI-compatible path: the native route sends a taskType and L2-normalizes what comes back, so moving them would change their document vectors and silently invalidate the index built from them. Point base_url at the native URL yourself to opt any model in.

Queries stop being embedded as documents

Retrieval embeddings now carry their role. LlamaIndex tags queries search_query and passages search_document, LightRAG maps its own context hint the same way, and adapters opt in explicitly (SUPPORTS_INPUT_TYPE) so a backend that never sent a role keeps not sending one. Only Cohere — which requires the field and already defaulted to search_document — changes today: document vectors are untouched, queries finally get the right role. No re-index.

A reasoning-effort selector per model

Each LLM model in the catalog gets an optional default reasoning depth next to its context window, offered only where the provider actually supports one and labelled in that provider's own vocabulary (minimal/low/medium/high/xhigh for OpenAI-style families, adaptive where that is the only on-mode, a plain on/off for the rest). Provider default (Auto) leaves the choice to the provider. Two Anthropic bugs fell out of wiring it up: none was turning thinking on with a 4096-token budget, and a stored adaptive sent to an older family drew a 400 instead of the default budget.

Novita AI, and MiniMax on the right platform

Novita AI joins the LLM gateways (novita, https://api.novita.ai/openai). MiniMax runs two separate platforms whose keys are not interchangeable, and the default now points at the global one (api.minimax.io) instead of the mainland-China one; minimax-m3 and minimax-m2.7 context windows are recorded, and detection also reads a context_size field.

Compose deployments keep all of data/

docker-compose.ghcr.yml bind-mounted only data/user, data/memory and data/knowledge_bases, so data/system (the JWT signing secret, accounts, grants, per-owner Codex tokens), data/users, data/partners and data/cli-apps lived in the container's writable layer and were discarded on every recreate. It now mounts the whole tree, matching the other Compose files. Named-volume and source-build deployments were never affected.

Codex sign-in inside a local container

Default local Docker and Podman deployments put the browser and the server on separate loopback networks, so the OAuth callback never arrived. There is now a temporary compose.codex-oauth.yaml overlay (and the equivalent docker/podman commands) that publishes ports 1455/1457 only while you sign in — with teardown, so those ports go back to your other Codex clients. See CONTAINERIZATION.md.

Failures that used to arrive as nothing

A capability that raised — or a request for one that does not exist — ended the stream without a verdict, and the turn was persisted as completed with an empty answer. The error is now marked terminal and carried through a DONE event, so the turn is stored as failed with its message and the UI shows what went wrong instead of an empty bubble.

Assorted

  • The interface language you saved is honored on first load. It lived in the backend's ui settings, which only the Settings route ever read, so every other page started in English until you re-picked it in that browser. A local choice still wins.
  • Visualize no longer aborts when the analysis model invents a render_type or visual_genre outside the enum — the off-enum value is dropped and the field falls back to its default.
  • Credential-like query parameters (key, api_key, token, access_token) are redacted in every endpoint the wizard, the client, and error messages print.

Upgrade Notes

pip install -U deeptutor; Docker users pull ghcr.io/hkuds/deeptutor:latest. No schema changes, and nothing to re-index.

  • docker-compose.ghcr.yml users: copy your state out before the next up -d. The new whole-tree mount means empty host directories would shadow what is in the container's writable layer, regenerating the auth secret (logging everyone out) and starting with no non-admin accounts. The one docker cp loop is in CONTAINERIZATION.md → One-time migration.
  • MiniMax on the mainland-China platform: the default base URL is now the global endpoint. Set base_url to https://api.minimaxi.com/v1 (or https://api.minimaxi.com/anthropic) and use a China-platform key — keys are issued per platform. Saved profiles keep whatever URL they already have.
  • Gemini embeddings: existing gemini-embedding-001 profiles are left where they are on purpose. New profiles and gemini-embedding-2 use the native endpoint.
