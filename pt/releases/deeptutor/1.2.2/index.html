DeepTutor v1.2.2

#Deep Tutor v1.2.2 #DeepTutor v1.2.2 Release Notes Data de lançamento: 2026.04.22

Destaques

Sistema de habilidades de autoria do usuário

Introduzido um subsistema Skills completo que permite aos usuários criar, editar e ativar arquivos SKILL.md personalizados na interface da web. Cada habilidade reside em data/user/workspace/skills/<name>/SKILL.md com frontmatter YAML (name, description, triggers opcional) e um corpo Markdown que é injetado literalmente no prompt do sistema de bate-papo quando ativo.

  • Backend — SkillService (deeptutor/services/skill/service.py) fornece CRUD + listagem + seleção com validação estrita de nome (^[a-z0-9][a-z0-9-]{0,63}$), análise de frontmatter e isolamento em nível de diretório. REST API montado em /api/v1/skills com GET /list, GET /{name}, POST /create, PUT /{name}, DELETE /{name}.
  • Frontend — uma nova guia Habilidades na página de gerenciamento de conhecimento (web/app/(utility)/knowledge/page.tsx) com editor SKILL.md embutido e um menu seletor de habilidades no compositor de bate-papo. As habilidades podem ser alternadas individualmente ou definidas para o modo auto (envia ["auto"] para o backend). web/lib/skills-api.ts fornece uma camada API do lado client em cache. UnifiedChatContext transporta skills através da carga útil do WebSocket.

Revisão do desempenho de entrada de bate-papo (#351, #360, #362)

Atraso de entrada eliminado em longas conversas por meio de colocation de estado profundo:

  • ComposerInput — extraído do ChatComposer em seu próprio componente memo, de modo que re-renderizações frequentes de pressionamentos de tecla são isoladas do resto do compositor (painéis de recursos, chips de referência, menus de ferramentas). Expõe um ComposerInputHandle imperativo (clear(), getValue()) para evitar a elevação do estado de entrada.
  • SimpleComposerInput — uma variante leve para a página de bate-papo do TutorBot que elimina totalmente a menção @ e a sobrecarga de capacidade, corrigindo o atraso residual relatado após a refatoração inicial.
  • React.memo em painéis de configuração — QuizConfigPanel, MathAnimatorConfigPanel, ResearchConfigPanel e VisualizeConfigPanel agora estão agrupados em React.memo; retornos de chamada pai em ChatPage estabilizados com useCallback.
  • @-mention helpers exportados — shouldOpenAtPopup e stripTrailingAtMention movidos para ComposerInput.tsx como exportações nomeadas para reutilização de componentes cruzados.

Auto-Fallback para rejeição response_format

Proteção estática supports_response_format estendida do v1.2.1 com um caminho de recuperação automática em tempo de execução. Quando um provedor retorna inesperadamente HTTP 400 para response_format={"type":"json_object"} (comum com modelos LM Studio + Gemma/Qwen), ambos os caminhos de execução LLM agora detectam o erro, eliminam o campo e tentam novamente uma vez:

  • caminho aiohttp (cloud_provider.py) — A heurística _looks_like_unsupported_response_format detecta a rejeição em _openai_complete e _openai_stream; na correspondência, a solicitação é repetida sem response_format e o par (ligação, modelo) é armazenado em cache.
  • Caminho OpenAI SDK (executors.py) — _create_with_format_fallback envolve client.chat.completions.create, capturando BadRequestError e aplicando a mesma lógica de nova tentativa + cache.
  • Cache de tempo de execução (capabilities.py) — O registro disable_response_format_at_runtime / is_response_format_disabled_at_runtime descobriu incompatibilidades em um set de nível de módulo para que as chamadas subsequentes ignorem response_format antecipadamente sem pagar o custo de nova tentativa.
  • _answer_now.py — stream_synthesis agora verifica supports_response_format antes de conectar response_format, evitando que o 400 em primeiro lugar tenha fluxos de resposta de caminho rápido.

LAN/correção de acesso remoto (#340)

Quando outra máquina na rede local abre a UI da web, o NEXT_PUBLIC_API_BASE em tempo de construção (normalmente http://localhost:8001) resolveria para o próprio loopback do navegador remoto em vez do servidor. Um novo auxiliar resolveBase() em web/lib/api.ts detecta essa incompatibilidade e troca o nome do host por window.location.hostname em tempo de execução, para que apiUrl() e wsUrl() alcancem o backend correto, independentemente de qual máquina abriu a página.

Emblema da versão da barra lateral e link GitHub

A barra lateral agora exibe a versão atual do build junto com um indicador de status:

  • Rota /api/version — um endpoint ISR Next.js que consulta api.github.com/repos/HKUDS/DeepTutor/releases/latest (revalidação por hora, GITHUB_TOKEN opcional para margem de limite de taxa) e retorna a tag, nome, URL e data de publicação mais recentes.
  • VersionBadge — compara NEXT_PUBLIC_APP_VERSION (injetado em tempo de construção via next.config.js / git describe --tags) com a versão mais recente obtida. Mostra um ponto verde quando atualizado, âmbar quando desatualizado e neutro quando desconhecido. Clicking navega até a página de lançamento.
  • Dockerfile — novo argumento de construção APP_VERSION canalizado para o ambiente Next.js para que implantações baseadas em Docker também obtenham exibição precisa da versão.
  • Ícone GitHub — um link direto para o repositório adicionado aos estados da barra lateral recolhida e expandida.

Suporte para anexo de imagem de solução profunda

DeepSolveCapability agora extrai o primeiro anexo de imagem (URI de dados ou URL) de context.attachments por meio de um novo auxiliar _first_image_url e o passa para os agentes planejador e solucionador. Internamente, PlannerAgent e SolverAgent foram refatorados para usar a classe de dados Attachment por meio do pipeline multimodal unificado do BaseAgent em vez de construir manualmente matrizes de mensagens multimodais - removendo duas funções auxiliares _build_multimodal_messages idênticas. BaseAgent.stream_llm também ganhou lógica para construir mensagens de system_prompt + user_prompt quando attachments são fornecidos sem messages explícito e logs quando as imagens são removidas para modelos sem visão.

Passagem de anexo do pipeline do Agentic Chat

Os métodos _stage_responding e _stage_acting em AgenticChatPipeline agora chamam _prepare_messages_with_attachments após a construção de mensagens, garantindo que as imagens enviadas pelo usuário sejam encaminhadas para o LLM em todas as fases do chat - não apenas na fase inicial de pensamento.

Resiliência TutorBot WebSocket (#354)

Endureceu o endpoint /api/v1/tutorbot/{bot_id}/ws:

  • Início automático — se o bot estiver configurado, mas não estiver em execução quando um WebSocket se conectar, o endpoint agora chama mgr.start_bot() automaticamente em vez de fechar imediatamente com 4004. IDs de bot desconhecidos ainda recebem uma carga útil de erro JSON antes de fechar.
  • _safe_send wrapper — todas as chamadas ws.send_json passam por um auxiliar que captura WebSocketDisconnect/RuntimeError, evitando exceções não tratadas quando o client cai no meio do fluxo.
  • Desconexão elegante — _handle_user_messages pega WebSocketDisconnect em receive_text e quebra de forma limpa.

Página de configurações: Máscara de teclas API (#355)

O campo Chave API na página Configurações agora é renderizado como type="password" por padrão com um botão de alternância Eye / EyeOff. O estado de visibilidade é redefinido ao alternar entre serviços ou perfis.

Revisão da interface da biblioteca de livros

Substituído o espaço reservado mínimo "Selecione um livro" por um componente BookLibrary completo (web/app/(workspace)/book/components/BookLibrary.tsx) com pesquisa, cartões filtrados por status com contagens de capítulos/páginas, ações de criação e exclusão e emblemas de status (Rascunho/Esboço/Compilação/Pronto). BookSidebar foi simplificado para uma visualização de leitor de livro único com um botão Voltar "← Todos os livros", e a página do livro agora mostra condicionalmente a biblioteca ou a barra lateral com base na visualização atual.

Modo de visualização em tela cheia

As visualizações SVG, Mermaid e ChartJS agora têm um botão Maximizar (canto superior direito) que abre o gráfico em uma sobreposição de tela inteira com Escape para fechar. As visualizações de iframe HTML são excluídas porque já fornecem sua própria capacidade de "Abrir em uma nova guia".

Correções de bugs

  • Adaptador de incorporação ConnectError não tentado novamente (#353) — adicionado httpx.ConnectError à tupla de exceção de nova tentativa em OpenAICompatibleEmbeddingAdapter, para que falhas de conexão transitórias durante a incorporação sejam repetidas com espera exponencial em vez de aumentarem imediatamente.
  • Reforço de incorporação RAG None — CustomEmbedding._aget_query_embedding e _aget_text_embedding agora geram um ValueError claro quando o provedor retorna None em vez de travar posteriormente no cálculo de similaridade. O método em lote _aget_text_embeddings agora determina a dimensão de vetor zero de fallback a partir de vetores irmãos ou do dim configurado e aumenta se nenhum estiver disponível (evitando a persistência silenciosa de vetores de comprimento zero).
  • Falha de exclusão de KB no diretório ausente — KnowledgeBaseManager.delete_knowledge_base agora resolve o caminho diretamente via self.base_dir / name e lida com o caso em que a pasta no disco já foi removida, limpando a entrada órfã kb_config.json em vez de aumentar FileNotFoundError.
  • CLI parse_json_object espaços em branco — a função agora remove os espaços em branco iniciais/finais antes da análise, portanto, as novas linhas finais da tubulação do shell não causam mais json.JSONDecodeError.

Expansão do conjunto de testes

  • TutorBot WebSocket — 2 novos testes cobrindo inicialização automática de bots parados, mas configurados e carga útil de erro JSON para IDs de bot desconhecidos (tests/api/test_tutorbot_router.py).
  • Ajudantes CLI — 2 testes para manipulação de espaços em branco parse_json_object e JSON inválido (tests/cli/test_common.py).
  • Parâmetros de rota — 3 testes para o novo utilitário firstParam (web/tests/route-params.test.ts).
  • API resolve base — testes para a lógica de troca de nome de host LAN (web/tests/api-resolve-base.test.ts).

DeepTutor v1.2.2

DeepTutor v1.2.2 Release Notes

Release Date: 2026.04.22

Highlights

User-Authored Skills System

Introduced a full Skills subsystem that lets users create, edit, and activate custom SKILL.md files from the web UI. Each skill lives under data/user/workspace/skills/<name>/SKILL.md with YAML frontmatter (name, description, optional triggers) and a Markdown body that is injected verbatim into the chat system prompt when active.

  • Backend — SkillService (deeptutor/services/skill/service.py) provides CRUD + listing + selection with strict name validation (^[a-z0-9][a-z0-9-]{0,63}$), frontmatter parsing, and directory-level isolation. REST API mounted at /api/v1/skills with GET /list, GET /{name}, POST /create, PUT /{name}, DELETE /{name}.
  • Frontend — a new Skills tab in the Knowledge management page (web/app/(utility)/knowledge/page.tsx) with inline SKILL.md editor, and a skill picker menu in the chat composer. Skills can be toggled individually or set to auto mode (sends ["auto"] to the backend). web/lib/skills-api.ts provides a cached client-side API layer. UnifiedChatContext carries skills through the WebSocket payload.

Chat Input Performance Overhaul (#351, #360, #362)

Eliminated input lag in long conversations through deep state colocation:

  • ComposerInput — extracted from ChatComposer into its own memo'd component so frequent keystroke re-renders are isolated from the rest of the composer (capability panels, reference chips, tool menus). Exposes an imperative ComposerInputHandle (clear(), getValue()) to avoid lifting input state.
  • SimpleComposerInput — a lightweight variant for the TutorBot chat page that strips @-mention and capability overhead entirely, fixing residual lag reported after the initial refactor.
  • React.memo on config panels — QuizConfigPanel, MathAnimatorConfigPanel, ResearchConfigPanel, and VisualizeConfigPanel are now wrapped in React.memo; parent callbacks in ChatPage stabilized with useCallback.
  • @-mention helpers exported — shouldOpenAtPopup and stripTrailingAtMention moved to ComposerInput.tsx as named exports for cross-component reuse.

Auto-Fallback for response_format Rejection

Extended the v1.2.1 static supports_response_format guard with a runtime auto-recovery path. When a provider unexpectedly returns HTTP 400 for response_format={"type":"json_object"} (common with LM Studio + Gemma/Qwen-style models), both LLM execution paths now detect the error, drop the field, and retry once:

  • aiohttp path (cloud_provider.py) — _looks_like_unsupported_response_format heuristic detects the rejection in _openai_complete and _openai_stream; on match, the request is retried without response_format and the (binding, model) pair is cached.
  • OpenAI SDK path (executors.py) — _create_with_format_fallback wraps client.chat.completions.create, catching BadRequestError and applying the same retry + cache logic.
  • Runtime cache (capabilities.py) — disable_response_format_at_runtime / is_response_format_disabled_at_runtime record discovered incompatibilities in a module-level set so subsequent calls skip response_format upfront without paying the retry cost.
  • _answer_now.py — stream_synthesis now checks supports_response_format before attaching response_format, preventing the 400 in the first place for fast-path answer flows.

LAN / Remote Access Fix (#340)

When another machine on the local network opens the web UI, the build-time NEXT_PUBLIC_API_BASE (typically http://localhost:8001) would resolve to the remote browser's own loopback instead of the server. A new resolveBase() helper in web/lib/api.ts detects this mismatch and swaps the hostname for window.location.hostname at runtime, so apiUrl() and wsUrl() reach the correct backend regardless of which machine opened the page.

Sidebar Version Badge & GitHub Link

The sidebar now displays the current build version alongside a status indicator:

  • /api/version route — a Next.js ISR endpoint that queries api.github.com/repos/HKUDS/DeepTutor/releases/latest (hourly revalidation, optional GITHUB_TOKEN for rate-limit headroom) and returns the latest tag, name, URL, and publish date.
  • VersionBadge — compares NEXT_PUBLIC_APP_VERSION (injected at build time via next.config.js / git describe --tags) against the fetched latest release. Shows a green dot when up-to-date, amber when outdated, and neutral when unknown. Clicking navigates to the release page.
  • Dockerfile — new APP_VERSION build arg piped into the Next.js env so Docker-based deployments also get accurate version display.
  • GitHub icon — a direct link to the repository added to both collapsed and expanded sidebar states.

Deep Solve Image Attachment Support

DeepSolveCapability now extracts the first image attachment (data-URI or URL) from context.attachments via a new _first_image_url helper and passes it to the planner and solver agents. Internally, PlannerAgent and SolverAgent were refactored to use the Attachment dataclass through BaseAgent's unified multimodal pipeline instead of manually constructing multimodal message arrays — removing two identical _build_multimodal_messages helper functions. BaseAgent.stream_llm also gained logic to construct messages from system_prompt + user_prompt when attachments are provided without explicit messages, and logs when images are stripped for non-vision models.

Agentic Chat Pipeline Attachment Passthrough

The _stage_responding and _stage_acting methods in AgenticChatPipeline now call _prepare_messages_with_attachments after building messages, ensuring that user-uploaded images are forwarded to the LLM in every chat stage — not just the initial thinking stage.

TutorBot WebSocket Resilience (#354)

Hardened the /api/v1/tutorbot/{bot_id}/ws endpoint:

  • Auto-start — if the bot is configured but not running when a WebSocket connects, the endpoint now calls mgr.start_bot() automatically instead of immediately closing with 4004. Unknown bot IDs still receive a JSON error payload before close.
  • _safe_send wrapper — all ws.send_json calls go through a helper that catches WebSocketDisconnect / RuntimeError, preventing unhandled exceptions when the client drops mid-stream.
  • Graceful disconnect — _handle_user_messages catches WebSocketDisconnect on receive_text and breaks cleanly.

Settings Page: API Key Masking (#355)

The API Key field on the Settings page is now rendered as type="password" by default with an Eye / EyeOff toggle button. The visibility state resets when switching between services or profiles.

Book Library UI Overhaul

Replaced the minimal "Select a book" placeholder with a full BookLibrary component (web/app/(workspace)/book/components/BookLibrary.tsx) featuring search, status-filtered cards with chapter/page counts, creation and deletion actions, and status badges (Draft / Outline / Compiling / Ready). BookSidebar was simplified to a single-book reader view with a "← All books" back button, and the book page now conditionally shows either the library or the sidebar based on the current view.

Visualization Fullscreen Mode

SVG, Mermaid, and ChartJS visualizations now have a Maximize button (top-right) that opens the graphic in a fullscreen overlay with Escape-to-close. HTML iframe visualizations are excluded since they already provide their own "Open in new tab" affordance.

Bug Fixes

  • Embedding adapter ConnectError not retried (#353) — added httpx.ConnectError to the retry exception tuple in OpenAICompatibleEmbeddingAdapter, so transient connection failures during embedding are retried with exponential backoff instead of raising immediately.
  • RAG None-embedding hardening — CustomEmbedding._aget_query_embedding and _aget_text_embedding now raise a clear ValueError when the provider returns None instead of crashing later in similarity computation. The batch method _aget_text_embeddings now determines the fallback zero-vector dimension from sibling vectors or the configured dim, and raises if neither is available (preventing silent persistence of zero-length vectors).
  • KB delete crash on missing directory — KnowledgeBaseManager.delete_knowledge_base now resolves the path directly via self.base_dir / name and handles the case where the on-disk folder was already removed, cleaning up the orphaned kb_config.json entry instead of raising FileNotFoundError.
  • CLI parse_json_object whitespace — the function now strips leading/trailing whitespace before parsing, so trailing newlines from shell piping no longer cause json.JSONDecodeError.

Test Suite Expansion

  • TutorBot WebSocket — 2 new tests covering auto-start of stopped-but-configured bots and JSON error payload for unknown bot IDs (tests/api/test_tutorbot_router.py).
  • CLI helpers — 2 tests for parse_json_object whitespace handling and invalid JSON (tests/cli/test_common.py).
  • Route params — 3 tests for the new firstParam utility (web/tests/route-params.test.ts).
  • API resolve base — tests for the LAN hostname swap logic (web/tests/api-resolve-base.test.ts).
