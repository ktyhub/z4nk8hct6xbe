Raspagem v0.4.13

Uma nova atualização trazendo feed spiders e um servidor MCP mais inteligente 🎉

[!NOTA]

  • Siga-nos no X para dicas e truques diários
  • Esta provavelmente será a última atualização antes das principais atualizações no v0.5

🚀 Coisas novas e mudanças na qualidade de vida

  • Novos modelos de aranha de feed. XMLFeedSpider itera nos nós de qualquer feed XML (RSS, Atom, feeds de produtos, etc.) e CSVFeedSpider itera em linhas CSV como dicionários. Ambos descompactam feeds compactados automaticamente. (Verifique os documentos) 
    from scrapling.spiders import XMLFeedSpiderclass RSSSpider(XMLFeedSpider):    name = "rss"    start_urls = ["https://example.com/feed.xml"]    async def parse_node(self, response, node):        yield {"title": node.findtext("title"), "link": node.findtext("link")}result = RSSSpider().start()
  • Atualizou o servidor MCP para MCP SDK v2 e tornou-o mais inteligente. O servidor agora envia instruções que ensinam seu agente de IA como usar as ferramentas com eficiência; cada ferramenta declara anotações para que clients como Claude Code possam aprovar automaticamente aquelas somente leitura; as descrições das ferramentas são mais enxutas para salvar tokens; e o servidor anuncia sua versão e logotipo para MCP clients. (Verifique os documentos)
  • Adicionado um comando scrapling-mcp que mapeia diretamente para scrapling mcp, portanto, registrar Scrapling com MCP clients e registros que esperam um único comando agora é uma linha única.
  • Versões Playwright/Patchright e navegador não fixadas. O User-Agent do navegador gerado agora sempre corresponde à versão exata do Chromium que suas unidades Playwright/Patchright instaladas, portanto, o Scrapling não fixa mais suas versões e você pode atualizá-las livremente. Execute scrapling install --force após atualizar para atualizar os navegadores.

🐛 Correções de bugs

  • Corrigido o problema de importação do Scrapling que travava com um browserforge ValueError quando o pacote de dados de impressões digitais estava atrasado em relação às versões do navegador. (Corrige #394, #396 e #400)
  • Corrigido o erro de dimensionamento das ferramentas do navegador em massa do MCP em seus pools de páginas, o que fazia com que o bulk_fetch falhasse em lotes de mais de 50 URLs e o bulk_stealthy_fetch buscasse todos os URLs por meio de uma única guia, por @Yigtwxx em #393.

Projeto

  • Nova Política de Contribuição de IA: Contribuições assistidas por IA são bem-vindas, mas devem ser divulgadas no PR ou na edição; envios que parecem resultados de IA não divulgados são rotulados e fechados.

🙏 Agradecimentos especiais à comunidade por todos os testes e feedback contínuos

Scrapling v0.4.13

Highlights

  • Feed spider templates — XMLFeedSpider supports RSS, Atom, and other XML feeds, while CSVFeedSpider yields rows as dictionaries. Both transparently decompress gzip responses, removing common feed-handling boilerplate; XML spiders customize extraction through parse_node.

  • Smarter MCP server — The MCP SDK v2 upgrade adds built-in usage instructions, token-efficient tool descriptions, and annotations that let compatible clients auto-approve read-only tools. Review permission policies accordingly, since these annotations can expand what agents execute without prompting.

  • Simpler MCP registration — The new scrapling-mcp command directly maps to scrapling mcp, making registration with clients and registries that require a single executable straightforward.

  • Browser dependencies unpinned — Playwright, Patchright, and browser versions are no longer pinned, so projects can upgrade them independently. Scrapling now derives its User-Agent from the actual Chromium version in use; run scrapling install --force after upgrading to refresh browser binaries.

  • More reliable bulk fetching and imports — #393 fixes pool sizing that caused bulk_fetch to fail beyond 50 URLs and forced bulk_stealthy_fetch through one tab. Import-time browserforge crashes caused by lagging fingerprint data are also fixed (#394, #396, #400).

  • Breaking changes — None announced for this release.

A new update bringing feed spiders and a smarter MCP server 🎉

[!NOTE]

  • Follow us on X for daily tips and tricks
  • This will most likely be the last update before the major updates in v0.5

🚀 New Stuff and quality of life changes

  • New feed spider templates. XMLFeedSpider iterates over the nodes of any XML feed (RSS, Atom, product feeds, etc.), and CSVFeedSpider iterates over CSV rows as dictionaries. Both decompress gzipped feeds automatically. (Check the docs) 
    from scrapling.spiders import XMLFeedSpiderclass RSSSpider(XMLFeedSpider):    name = "rss"    start_urls = ["https://example.com/feed.xml"]    async def parse_node(self, response, node):        yield {"title": node.findtext("title"), "link": node.findtext("link")}result = RSSSpider().start()
  • Upgraded the MCP server to MCP SDK v2 and made it smarter. The server now ships instructions that teach your AI agent how to use the tools efficiently; every tool declares annotations so clients like Claude Code can auto-approve the read-only ones; tool descriptions are leaner to save tokens; and the server advertises its version and logo to MCP clients. (Check the docs)
  • Added a scrapling-mcp command that maps directly to scrapling mcp, so registering Scrapling with MCP clients and registries that expect a single command is now a one-liner.
  • Unpinned Playwright/Patchright and browser versions. The generated browser User-Agent now always matches the exact Chromium version your installed Playwright/Patchright drives, so Scrapling no longer pins their versions and you can upgrade them freely. Run scrapling install --force after updating to refresh the browsers.

🐛 Bug Fixes

  • Fixed importing Scrapling crashing with a browserforge ValueError when the fingerprints data package lags behind the browser versions. (Fixes #394, #396, and #400)
  • Fixed the MCP bulk browser tools mis-sizing their page pools, which made bulk_fetch fail on batches of more than 50 URLs and bulk_stealthy_fetch fetch all URLs through a single tab, by @Yigtwxx in #393.

Project

  • New AI Contribution Policy: AI-assisted contributions are welcome but must be disclosed in the PR or issue; submissions that look like undisclosed AI output get labeled and closed.

🙏 Special thanks to the community for all the continuous testing and feedback
