Raspagem v0.2

#O que mudou

Novos recursos

  1. Apresentando o recurso Fetchers com 3 novos tipos principais para fazer o Scrapling buscar páginas para você com MUITAS opções!
    • A classe Fetcher para solicitações HTTP básicas
    • A classe StealthyFetcher é um buscador completamente furtivo que usa uma versão furtiva modificada do Firefox.
    • A classe PlayWrightFetcher que permite fazer solicitações baseadas em navegador com Vanilla PlayWright, PlayWright com modo stealth feito por mim, navegadores reais através de CDP e NSTBrowser's docker browserless!
  2. Adicionados os métodos find_all/find completamente novos para encontrar elementos facilmente na página com magia negra!
  3. Adicionados os métodos filter e search à classe Adaptors para operações em massa mais fáceis em grupos de objetos Adaptor.
  4. Adicionados métodos css_first e xpath_first para facilitar o uso.
  5. Adicionado o novo tipo de classe TextHandlers que é usado para operações em massa em objetos TextHandler como a classe Adaptors.
  6. Adicionados métodos generate_full_css_selector e generate_full_xpath_selector.

Bugs eliminados

  1. Agora a versão da classe Adaptors de re_first retorna o primeiro resultado que corresponde a todos os objetos Adaptor internos, em vez da lógica defeituosa de retornar os resultados de re_first de todos os objetos Adaptor.
  2. Agora, se o usuário selecionar um conteúdo do tipo texto a ser retornado dos elementos selecionados (como a função css ::text) com qualquer método como .css ou .xpath. O objeto Adaptor retornará a classe TextHandlers em vez de retornar uma lista de strings como antes. Então agora você pode fazer page.css('something::text').re_first(r'regex_pattern').json() em vez de page.css('something::text')[0].re_first(r'regex_pattern').json()
  3. Agora os argumentos re/re_first de Adaptor/Adaptors são consistentes com os de TextHandler. Então agora você tem argumentos clean_match e case_sensitive.
  4. Agora o argumento auto_match está habilitado por padrão na inicialização do Adaptor mas ainda assim você deve habilitá-lo ao selecionar os elementos se quiser habilitá-lo. (Não é um bug, mas uma decisão de design)
  5. Muitas correções de anotações de tipo aqui e ali para uma melhor experiência de preenchimento automático enquanto você codifica com Scrapling.

Mudanças na qualidade de vida

  1. Renomeamos os métodos css_selector e xpath_selector para generate_css_selector e generate_xpath_selector para maior clareza e para não interromper o preenchimento automático durante a codificação.
  2. Reestruturou a maior parte do código antigo em um subpacote core e outras decisões de design para uma manutenção mais limpa e fácil no futuro.
  3. Reestruturou a pasta de testes em uma estrutura mais limpa e adicionou testes para os novos recursos. Além disso, agora os ambientes tox são armazenados em cache no GitHub para testes automatizados mais rápidos a cada commit.

Scrapling v0.2

Highlights

  • Fetchers unify fetching and parsing — The headline addition is a Fetchers subsystem with three classes: Fetcher for plain HTTP, StealthyFetcher built on a camoufox-modified Firefox for anti-bot evasion, and PlayWrightFetcher covering vanilla Playwright, the author's stealth-mode Playwright, real browsers over CDP, and NSTBrowser's browserless Docker. The practical win is staying inside Scrapling's API end-to-end instead of pairing it with an external HTTP/browser client — but the stealth and browserless paths bring heavy runtime dependencies (Firefox/camoufox, Playwright, Docker), so they're not drop-in replacements for a lightweight requests setup.

  • Breaking: selector helpers renamed — css_selector and xpath_selector are now generate_css_selector and generate_xpath_selector. Calls to the old names will fail at runtime after upgrading. The change is cosmetic (clarity and auto-completion), so the migration is a mechanical find-and-replace with no behavior to revalidate.

  • Breaking: text selections return TextHandlers — Selecting text nodes (e.g. css('...::text')) now yields a TextHandlers object rather than a plain list of strings. Indexing patterns like page.css('x::text')[0].re_first(...) must become chained calls such as page.css('x::text').re_first(...).json(). This is the likeliest source of subtle breakage because only text-type selections are affected — string-oriented code keeps working until it hits a ::text selector.

  • Bulk operations and regex consistency — Adaptors gains filter and search, plus new css_first/xpath_first shortcuts that remove [0] boilerplate; TextHandlers mirrors Adaptors for bulk text work, and generate_full_css_selector/generate_full_xpath_selector produce absolute selectors. Two correctness fixes matter: Adaptors.re_first now returns the first match across all contained Adaptors instead of each object's separate results, and re/re_first accept clean_match and case_sensitive consistently with TextHandler. Watch existing pipelines that relied on the old re_first output — results can legitimately change. auto_match is now enabled at Adaptor init (still needs enabling per selection).

  • Internal restructuring — Most legacy code moved into a core subpackage, the test tree was reorganized, and tox environments are now cached in CI. No public API change is intended, but code reaching into internal module paths may need import updates.

What's changed

New features

  1. Introducing the Fetchers feature with 3 new main types to make Scrapling fetch pages for you with a LOT of options!
    • The Fetcher class for basic HTTP requests
    • The StealthyFetcher class is a completely stealthy fetcher that uses a stealthy modified version of Firefox.
    • The PlayWrightFetcher class that allows doing browser-based requests with Vanilla PlayWright, PlayWright with stealth mode made by me, Real browsers through CDP, and NSTBrowser's docker browserless!
  2. Added the completely new find_all/find methods to find elements easily on the page with dark magic!
  3. Added the methods filter and search to the Adaptors class for easier bulk operations on Adaptor object groups.
  4. Added methods css_first and xpath_first methods for easier usage.
  5. Added the new class type TextHandlers which is used for bulk operations on TextHandler objects like the Adaptors class.
  6. Added generate_full_css_selector and generate_full_xpath_selector methods.

Bugs Squashed

  1. Now the Adaptors class version of re_first returns the first result that matches in all Adaptor objects inside instead of the faulty logic of returning the results of re_first of all Adaptor objects.
  2. Now if the user selects a text-type content to be returned from selected elements (like css ::text function) with any method like .css or .xpath. The Adaptor object will return the TextHandlers class instead of returning a list of strings like before. So now you can do page.css('something::text').re_first(r'regex_pattern').json() instead of page.css('something::text')[0].re_first(r'regex_pattern').json()
  3. Now Adaptor/Adaptors re/re_first arguments are consistent with the TextHandler ones. So now you have clean_match and case_sensitive arguments.
  4. Now the auto_match argument is enabled by default in the initialization of Adaptor but still you have to enable it while selecting elements if you want to enable it. (Not a bug but a design decision)
  5. A lot of type-annotations corrections here and there for better auto-completion experience while you are coding with Scrapling.

Quality of life changes

  1. Renamed both css_selector and xpath_selector methods to generate_css_selector and generate_xpath_selector for clarity and to not interrupt the auto-completion while coding.
  2. Restructured most of the old code into a core subpackage and other design decisions for cleaner and easier maintenance in the future.
  3. Restructured the tests folder into a cleaner structure and added tests for the new features. Also now tox environments are cached on GitHub for faster automated tests with each commit.
