#VoxCPM 2.0.3

VoxCPM v2.0.3

Esta versão se concentra no ajuste fino da usabilidade, estabilidade do tempo de execução, carregamento LoRA mais seguro e inferência de streaming mais rápida.

Destaques

  • Adicionado voxcpm validate para validação do manifesto de treinamento pré-voo JSONL.
  • Adicionado suporte opcional ref_audio no pipeline de dados de ajuste fino.
  • Melhor manipulação de dispositivos em tempo de execução com suporte explícito a --device e comportamento mais seguro do tipo MPS.
  • Decodificação VAE de streaming VoxCPM2 aprimorada, evitando decodificação de sobreposição redundante.
  • Carregamento de ponto de verificação LoRA legado reforçado com weights_only=True.
  • Corrigido o tratamento de incompatibilidade de classificação LoRA em lora_ft_webui.py.

Novos recursos

  • Adicione voxcpm validate --manifest train.jsonl para detectar problemas de dados de treinamento antes do ajuste fino.
    • Valida o formato JSONL, campos text/audio obrigatórios, existência/legibilidade de áudio, taxa de amostragem, estatísticas de duração, estatísticas de comprimento de texto e ref_audio opcional.
  • Adicione suporte opcional ref_audio para manifestos de ajuste fino.
    • A embalagem de treinamento agora suporta [103, ref_audio, 104, text, 101, target_audio, 102].
    • A perda é aplicada somente ao segmento de áudio alvo.
  • Adicione o argumento --device CLI para comandos de inferência de modelo.
    • Suporta auto, cpu, mps, cuda e dispositivos CUDA indexados, como cuda:0.

Desempenho

  • Melhore a decodificação VAE de streaming VoxCPM2 com um StreamingVAEDecoder com estado.
    • A decodificação de streaming agora processa apenas o patch latente mais recente e carrega internamente o estado de convolução causal.
    • Isso remove a decodificação de sobreposição redundante e reduz a sobrecarga de decodificação VAE de streaming.

Correções

  • Corrija o acúmulo de forma dinâmica do gráfico CUDA usando o codificador de recurso não compilado para pré-preenchimento.
  • Corrija a transmissão da máscara de atenção SDPA da CPU usando um formato de máscara transmitível explícito.
  • Corrigida a ordem de validação de texto sem string para aumentar o ValueError pretendido em vez de AttributeError.
  • Correção de vazamentos no descritor de arquivo ao carregar config.json em carregadores de modelo locais.
  • Corrija problemas de qualidade de áudio MPS promovendo dtypes de baixa precisão para float32 no Apple Silicon por padrão.
  • Correção da validação de substituição VOXCPM_MPS_DTYPE para corresponder aos aliases de dtype suportados.
  • Corrija a incompatibilidade de classificação LoRA em lora_ft_webui.py recarregando o modelo quando a classificação do ponto de verificação for diferente.
  • Correção da manipulação de texto de controle do Web Demo, removendo os parênteses antes de construir o prompt do modelo.

Segurança

  • O carregamento legado do LoRA .ckpt / .pth agora usa torch.load(..., weights_only=True).
  • Isso reduz o risco de execução arbitrária da carga útil do pickle, preservando a compatibilidade do ponto de verificação somente do tensor.

Documentação

  • Documentar vLLM-Omni como uma opção de serviço de produção para VoxCPM2.
  • Atualize o uso do Web Demo para python app.py --port 8808.
  • Exemplo de download local de atualização do ModelScope.
  • Esclareça o requisito Python como >=3.10,<3.13.
  • Adicione ComfyUI_RH_VoxCPM à lista do ecossistema.

Testes

  • Adicionada cobertura para validação de manifesto de treinamento, incluindo incompatibilidade de taxa de amostragem, áudio ausente, caminhos relativos, códigos de saída ref_audio e CLI.
  • Adicionados testes de seleção de dispositivos em tempo de execução.
  • Adicionados testes de segurança de pontos de verificação LoRA para pontos de verificação somente de tensor e cargas úteis de picles maliciosas.
  • Adicionados testes CLI para padrões --device e encaminhamento de argumentos.

VoxCPM 2.0.3

VoxCPM v2.0.3

This release focuses on fine-tuning usability, runtime stability, safer LoRA loading, and faster streaming inference.

Highlights

  • Added voxcpm validate for pre-flight JSONL training manifest validation.
  • Added optional ref_audio support in the fine-tuning data pipeline.
  • Improved runtime device handling with explicit --device support and safer MPS dtype behavior.
  • Improved VoxCPM2 streaming VAE decoding by avoiding redundant overlap decoding.
  • Hardened legacy LoRA checkpoint loading with weights_only=True.
  • Fixed LoRA rank mismatch handling in lora_ft_webui.py.

New Features

  • Add voxcpm validate --manifest train.jsonl to catch training data issues before fine-tuning.
    • Validates JSONL format, required text/audio fields, audio existence/readability, sample rate, duration stats, text length stats, and optional ref_audio.
  • Add optional ref_audio support for fine-tuning manifests.
    • Training packing now supports [103, ref_audio, 104, text, 101, target_audio, 102].
    • Loss is applied only to the target audio segment.
  • Add --device CLI argument for model inference commands.
    • Supports auto, cpu, mps, cuda, and indexed CUDA devices such as cuda:0.

Performance

  • Improve VoxCPM2 streaming VAE decode with a stateful StreamingVAEDecoder.
    • Streaming decode now processes only the newest latent patch and carries causal convolution state internally.
    • This removes redundant overlap decoding and reduces streaming VAE decode overhead.

Fixes

  • Fix CUDA Graph dynamic-shape accumulation by using the uncompiled feature encoder for prefill.
  • Fix CPU SDPA attention mask broadcasting by using an explicit broadcastable mask shape.
  • Fix non-string text validation order to raise the intended ValueError instead of AttributeError.
  • Fix file descriptor leaks when loading config.json in local model loaders.
  • Fix MPS audio quality issues by promoting low-precision dtypes to float32 on Apple Silicon by default.
  • Fix VOXCPM_MPS_DTYPE override validation to match supported dtype aliases.
  • Fix LoRA rank mismatch in lora_ft_webui.py by reloading the model when checkpoint rank differs.
  • Fix Web Demo control text handling by stripping parentheses before constructing the model prompt.

Security

  • Legacy LoRA .ckpt / .pth loading now uses torch.load(..., weights_only=True).
  • This reduces the risk of arbitrary pickle payload execution while preserving tensor-only checkpoint compatibility.

Documentation

  • Document vLLM-Omni as a production serving option for VoxCPM2.
  • Update Web Demo usage to python app.py --port 8808.
  • Update ModelScope local download example.
  • Clarify Python requirement as >=3.10,<3.13.
  • Add ComfyUI_RH_VoxCPM to the ecosystem list.

Tests

  • Added coverage for training manifest validation, including sample-rate mismatch, missing audio, relative paths, ref_audio, and CLI exit codes.
  • Added runtime device selection tests.
  • Added LoRA checkpoint safety tests for tensor-only checkpoints and malicious pickle payloads.
  • Added CLI tests for --device defaults and argument forwarding.
