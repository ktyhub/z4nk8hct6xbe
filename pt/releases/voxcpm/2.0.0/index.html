VoxCPM 2.0.0

Highlights

  • VoxCPM2 model and deployment target — Introduces a 2B, tokenizer-free diffusion-autoregressive model with 30-language synthesis and native 48 kHz output. Adopt via openbmb/VoxCPM2, now the CLI default; budget roughly 8 GB VRAM versus 6 GB for 1.5, and do not assume existing 1.5 LoRA adapters are compatible.
  • Voice design and controllable cloning — Natural-language descriptions at the start of text create voices without reference audio; reference_wav_path enables timbre cloning with optional style instructions, while prompt_wav_path plus prompt_text preserves continuation-style cloning. The CLI exposes these through voxcpm design and voxcpm clone; --reference-audio is rejected for VoxCPM1.5 models, and controllable outputs may require retries.
  • CLI migration — The CLI now favors design, clone, and batch subcommands; legacy root arguments still work but emit deprecation warnings. Validation added in #161 rejects invalid ranges and conflicting options before model loading. Scripts using --lora-enable-lm or --lora-enable-dit must switch to --lora-disable-lm or --lora-disable-dit.
  • Audio dependency change — torchcodec is now required (#139), so refresh or rebuild environments rather than upgrading code alone. Because the dependency is unpinned, verify Torch/TorchCodec compatibility and regenerate lockfiles for reproducible deployments.
  • Fine-tuning and data-pipeline fixes — Validation-audio generation now uses CUDA autocast and restores model mode and AudioVAE state in a finally block (#186), reducing dtype and state leakage during SFT/LoRA training; test scripts now pass the correct max_len keyword (#98). Dataset-length calculation uses batch column access (#128), improving initialization most when duration metadata exists; audio decoding remains the fallback.
  • Automation-friendly diagnostics — Debug and model-loading messages move from stdout to stderr (#141), keeping stdout clean for pipelines. Narrower exception handling (#188) prevents unrelated failures from being mislabeled as missing Triton or silently ignored during checkpoint scanning.
