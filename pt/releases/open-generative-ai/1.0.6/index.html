  • O mecanismo de inferência local no Linux/Windows pode ser baixado novamente (#108) — a última versão stable-diffusion.cpp do leejet vem temporariamente apenas para Mac arm64 + Windows CUDA-runtime stub + Linux ROCm, então qualquer pessoa fora desse conjunto restrito acessa Error invoking remote method 'local-ai:download-binary': No binary found for this platform. O downloader agora percorre as últimas 15 versões do leejet até encontrar uma que realmente tenha uma compilação para o sistema operacional/arch atual, e o correspondente do Linux prefere x86_64 simples → vulkan → rocm. Os usuários do macOS Intel recebem um erro mais claro, pois o leejet nunca publicou um binário x86_64 do macOS.
  • Mais #110 (configuração segura para submódulo) e #111 (botão Configurações proeminentes) do v1.0.5.

Open-Generative-AI v1.0.6

Highlights

  • Local inference binaries restored (#108) — A narrow upstream stable-diffusion.cpp release (Mac arm64 + a Windows CUDA-runtime stub + Linux ROCm only) broke the local-engine download on nearly every other platform, surfacing as Error invoking remote method 'local-ai:download-binary': No binary found for this platform. The downloader now walks the last 15 leejet releases until it finds a build for the current OS/arch, with Linux preference order plain x86_64 → vulkan → rocm. If you were pinned to an older app version just to keep local generation alive, you can upgrade — but expect a fallback build rather than the newest upstream one.
  • Platform caveat: macOS Intel is still UI-only — A 1.0.6.dmg (x64) is shipped, but leejet has never published an x86_64 macOS binary, so the local engine still cannot install there; #108 only replaces the cryptic IPC error with an explicit message. Intel users should plan to bring their own inference backend or use remote generation.
  • Source setup made submodule-safe (#110) — Carried forward from v1.0.5: setup no longer assumes git submodules are already initialized, so fresh clones and CI checkouts won't fail mid-install. This matters mainly if you build from source instead of consuming a .dmg/AppImage.
  • Settings surfaced more prominently (#111) — Also from v1.0.5, a prominent Settings button shortens the path to configuring the local engine. Small change, but useful given #108 can now silently fall back to an older binary — you'll want quick access to verify which engine is in use.
  • Packaging gotchas remain — First macOS launch still requires xattr -cr "/Applications/Open Generative AI.app" then right-click → Open to get past Gatekeeper. On Ubuntu 24.04+, the AppImage can silently fail due to unprivileged-user-namespace restrictions; either set kernel.apparmor_restrict_unprivileged_userns=0 or install the .deb, which bundles an AppArmor profile. Bake these into your install docs rather than debugging them per-user.
  • Breaking changes — None in this release.

Fixes

  • Local inference engine on Linux/Windows is downloadable again (#108) — leejet's latest stable-diffusion.cpp release temporarily ships only Mac arm64 + Windows CUDA-runtime stub + Linux ROCm, so anyone outside that narrow set hit Error invoking remote method 'local-ai:download-binary': No binary found for this platform. The downloader now walks the last 15 leejet releases until it finds one that actually has a build for the current OS/arch, and the Linux matcher prefers plain x86_64 → vulkan → rocm. macOS Intel users get a clearer error since leejet has never published an x86_64 macOS binary.
  • Plus #110 (submodule-safe setup) and #111 (prominent Settings button) from v1.0.5.

Downloads

  • macOS Apple Silicon (M1/M2/M3/M4): Open Generative AI-1.0.6-arm64.dmg
  • macOS Intel (x64): Open Generative AI-1.0.6.dmg
  • Linux x86_64 — AppImage: Open Generative AI-1.0.6.AppImage (chmod +x then run)
  • Linux x86_64 — Debian/Ubuntu: open-generative-ai_1.0.6_amd64.deb (sudo apt install ./open-generative-ai_1.0.6_amd64.deb)

First launch on macOS: xattr -cr "/Applications/Open Generative AI.app" then right-click → Open. AppImage on Ubuntu 24.04+: if it silently fails, sudo sysctl -w kernel.apparmor_restrict_unprivileged_userns=0 or install the .deb instead (it ships an AppArmor profile).
