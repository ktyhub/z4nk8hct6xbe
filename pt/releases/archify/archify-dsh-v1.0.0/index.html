Arquivar DSH 1.0.0

@tt-a1i/archify-dsh@1.0.0 traz o fluxo de autoria e entrega do Archify 3.x para a integração da comunidade DeepSeek Harness. Ele inclui Archify 3.0.1, incluindo a correção de instalação de Skill pós-tag de #704, da fonte imutável 7158026e852f3aa6578c741e673b46d7878c92c1. Os números de versão do adaptador e do Archify são independentes. O host suportado é exatamente @deepseek-ai/dsh@0.1.2-rc.1, com o nó ^22.19.0 || >=24.0.0. DSH continua sendo uma prévia do desenvolvedor; o contrato 1.0 do adaptador não promete compatibilidade com outras versões do host. Esta é uma integração da comunidade, não um produto oficial do DeepSeek.

Instalar e atualizar

Atualize o host DSH separadamente para a versão suportada e execute este comando em cada perfil que usa Archify:

dsh plugin --profile web add @tt-a1i/archify-dsh@1.0.0

O mesmo comando atualiza o plugin anterior. Archify 3.x inclui marcas de autoria, esquema de fluxo de trabalho v2, localização do visualizador e reconhecimento de atualização opcional. As entradas existentes do esquema v1 permanecem suportadas; o HTML existente mantém seu visualizador incorporado. Consulte as notas de atualização do Archify 3.0. Esta versão preserva o único provedor Skill do sistema de arquivos archify-plugin. Ele não adiciona ferramentas nativas, dependências de tempo de execução, scripts de ciclo de vida, telemetria, manipulação de credenciais ou atualizações automáticas de plug-ins. O host avalia a expressão de resolução cordis.patch.yml limitada do pacote fora da área restrita do agente. Os arquivos gerados permanecem arquivos comuns do espaço de trabalho, sem chips automáticos de Arquivos Produzidos na Web. O adaptador preparado 0.2.0 nunca foi publicado. O 0.1.0 publicado permanece imutável; 1.0.0 substitui esse candidato.

Highlights

  • First stable adapter, but a decoupled Archify payload — @tt-a1i/archify-dsh@1.0.0 is the first non-preview adapter release, bundling Archify 3.0.1 from immutable source 7158026e, including the post-tag Skill-install fix from #704. Adapter and Archify versions are numbered independently, so the 1.0.0 tag tells you nothing about which Archify build you actually get — pin or inspect the payload if reproducibility matters.

  • Hard host and Node pins, and an upgrade order that matters — Support is exactly @deepseek-ai/dsh@0.1.2-rc.1 on Node ^22.19.0 || >=24.0.0. The 1.0 contract explicitly promises no compatibility with other DSH versions, and DSH itself is still a developer preview. Practically: bump the host first, then the plugin — a host-only upgrade can silently put you outside the supported matrix.

  • Install/upgrade is per-profile, not global — Run dsh plugin --profile web add @tt-a1i/archify-dsh@1.0.0 in every profile that uses Archify; the same command both installs and upgrades the prior plugin. There is no automatic plugin upgrade, so any profile you skip keeps running 0.1.0.

  • Archify 3.x features arrive with a deliberately gentle migration — You get authored brand marks, Workflow schema v2, Viewer localization, and optional update awareness, while schema-v1 inputs still parse and existing HTML keeps its embedded Viewer. Skim the 3.0 upgrade notes before regenerating artifacts, but re-running over old inputs is low-risk.

  • Thin, auditable plugin surface — with one trust caveat — It remains a single archify-plugin filesystem Skill provider: no native tools, runtime dependencies, lifecycle scripts, telemetry, credential handling, or auto-upgrades. Note that the host evaluates the package's bounded cordis.patch.yml resolution expression outside the agent sandbox, so that expression is host-trusted code worth reviewing; generated files stay ordinary workspace files with no Web Produced Files chips.

  • Supply chain you can actually verify — A prepared 0.2.0 candidate was never published; published 0.1.0 stays immutable and 1.0.0 supersedes it. The npm tarball is byte-identical to accepted-main build 594f608 (SHA-256 d009c470…, integrity sha512-ae5L+Sy…). The gate exercised clean install and integrity-pinned 0.1.0 → 1.0.0 upgrade across Linux, macOS, and Windows — 19 stages per OS — covering installed doctor/demo, uninstall, and base-profile preservation, with the source-version smoke on a temp copy to protect pnpm hard links.

No breaking changes.

Archify DSH 1.0.0

@tt-a1i/archify-dsh@1.0.0 brings the Archify 3.x authoring and delivery flow to the DeepSeek Harness community integration. It bundles Archify 3.0.1, including the post-tag Skill installation fix from #704, from immutable source 7158026e852f3aa6578c741e673b46d7878c92c1. Adapter and Archify version numbers are independent.

The supported host is exactly @deepseek-ai/dsh@0.1.2-rc.1, with Node ^22.19.0 || >=24.0.0. DSH remains a developer preview; the adapter's 1.0 contract does not promise compatibility with other host versions. This is a community integration, not an official DeepSeek product.

Install and upgrade

Update the DSH host separately to the supported version, then run this command in each profile that uses Archify:

dsh plugin --profile web add @tt-a1i/archify-dsh@1.0.0

The same command upgrades the previous plugin. Archify 3.x includes authored brand marks, Workflow schema v2, Viewer localization, and optional update awareness. Existing schema-v1 inputs remain supported; existing HTML retains its embedded Viewer. See the Archify 3.0 upgrade notes.

This release preserves the single archify-plugin filesystem Skill provider. It adds no native tools, runtime dependencies, lifecycle scripts, telemetry, credentials handling, or automatic plugin upgrades. The host evaluates the package's bounded cordis.patch.yml resolution expression outside the agent sandbox. Generated files remain ordinary workspace files, without automatic Web Produced Files chips.

The prepared adapter 0.2.0 was never published. Published 0.1.0 remains immutable; 1.0.0 supersedes that candidate.

Release validation

The release gate covers clean installation and integrity-pinned published plugin 0.1.0 → 1.0.0 upgrade in isolated profiles on Linux, macOS, and Windows. It checks installed bytes, single-provider discovery and Skill loading, installed CLI doctor and demo, uninstall, and preservation of the base profile. The full source-version smoke runs on a temporary copy to preserve pnpm store hard links.
