archify v2.16.0

Highlights

  • Viewer goes multilingual — The Viewer UI now localizes itself from meta.locale (#108), and the selected language survives in-app navigation (#159), with a new bilingual authoring cookbook (#78) to support it. This removes hand-translated UI chrome for non-English audiences, but it makes your meta.locale values load-bearing: an unset or malformed locale now directly determines rendered language, so audit metadata before rollout.

  • Reproducible, verifiable artifacts — The canonical ZIP is now byte-reproducible and written atomically (#119, #129), generated SVGs are validated as well-formed XML (#114, #120), and the release job fetches the exact annotated tag object instead of an ambiguous ref (#215). For teams pinning or mirroring archify in CI, this finally gives you trustworthy artifact hashes and an attestable supply chain — expect one-time generated-output diffs as normalization settles.

  • Constraint-driven compiler — #146 adds a constraint-driven compiler to the workflow layer, pushing diagram generation beyond free-form prompting toward declarative constraints. Worth evaluating if you need deterministic, lintable output; treat its output contract as early-stage and watch for changes in the next minor.

  • Renderer and Viewer behavior fixes — Intent Trace now preserves the author's arrow direction (#90), Semantic Radar handles collisions and dragging correctly (#100), and dataflow graphs drop degenerate points so vertical edges retain a real final segment (#203). These are behavioral, not cosmetic — if you added workarounds for reversed arrows, stuck nodes, or clipped vertical edges, remove them and re-verify rendered diagrams on upgrade.

  • Security hardening — Automation now requires owner review (#109), a vulnerability reporting policy was published (#164), and a vulnerable transitive fast-uri version is pinned to a fixed release (#209). Low-effort for adopters, but audit your own lockfile if you vendor or mirror archify's dependency tree, since the override addresses a known CVE.

  • No breaking changes are indicated in this release.
