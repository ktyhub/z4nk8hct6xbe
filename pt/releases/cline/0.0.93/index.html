cline sdk/sdk/v0.0.93

  • Os plug-ins são carregados no processo por meio de um registro por processo, em vez de um subprocesso de nó/bun, de modo que o CLI compilado e seu hub não precisam mais de um tempo de execução no PATH, e os plug-ins podem usar o Bun global no hub construído pelo Bun. CLINE_PLUGIN_MODE=sandbox mantém a sandbox do subprocesso. O registro agrupa importação, configuração, ganchos, ferramentas e comandos com tempos limite e captura de erros, e rastreia o estado de cada plug-in (carregando/pronto/degradado/com falha/desativado) com seu último erro. Um plug-in com falha não descarta mais suas ferramentas silenciosamente: session.create aceita uma política plugins e retorna pluginIssues, falhas posteriores atingem as sessões afetadas como avisos de status, o hub responde plugins.list/plugins.status/plugins.reload e transmite plugin.status_changed, e o daemon marca um plug-in com falha em vez de desligar quando um erro não detectado surge dele. Cada sessão obtém sua própria cópia de cada módulo de plug-in, portanto, os plug-ins que mantêm o estado por sessão no nível do módulo continuam funcionando
  • Desativar o raciocínio agora funciona em todos os provedores, não apenas em uma lista fixa. Os modelos cuja entrada no catálogo não tem opção de desligamento não são enviados e mantêm seu padrão, e os modelos sem capacidade reasoning são ignorados. Gemini e Vertex enviam valores exatos de thinkingBudget apenas para modelos que anunciam um orçamento; Os modelos Gemini apenas de nível obtêm um nível de pensamento (eles rejeitaram thinkingBudget). Uma solicitação nunca carrega a opção de raciocínio portátil e um controle de provedor nativo (effort, thinking, thinkingConfig,…); o nativo vence
  • O modelo padrão do provedor cline é a primeira entrada da lista de modelos recomendados Cline, voltando para anthropic/claude-sonnet-5.5. CLINE_DEFAULT_MODEL_ID passa de Claude Sonnet 5 para Claude Sonnet 5.5, e o padrão do provedor openrouter agora é anthropic/claude-sonnet-5.5 também
  • estimateRequestInputTokens e createTokenEstimator não cobram mais cargas úteis de imagem base64 na taxa de texto. Uma captura de tela de aproximadamente 90 KB contava como aproximadamente 30 mil tokens, portanto, algumas imagens acionaram a compactação automática muito antes de a transcrição estar próxima do orçamento. Cada imagem agora adiciona um ESTIMATED_TOKENS_PER_IMAGE (1600) plano. Nova exportação createImageAwareReplacer em @cline/shared
  • A compactação automática usa a janela de contexto do modelo resolvido. Quando a entrada de catálogo descoberta não tinha limite, mas a substituição do modelo selecionado tinha, a compactação era entregue à entrada de catálogo simples e executada contra o orçamento errado
  • Execuções agendadas: as execuções na fila são reivindicadas corretamente em bun:sqlite, o que vincula os parâmetros nomeados da loja como NULL para que o hub da área de trabalho nunca reivindique uma execução na fila e permaneça pendente sem erros. As execuções cujo turno do agente termina com um erro de provedor (como um ID de modelo retirado) agora são registradas como falhadas com a mensagem de erro, em vez de serem bem-sucedidas silenciosamente, e o relatório de execução mantém o uso e as chamadas de ferramentas. As ocorrências do cron na fila substituídas por uma ocorrência mais recente do mesmo agendamento são canceladas, de modo que um backlog não reproduz mais todos os slots perdidos consecutivamente
  • Arquivos de regras que são links simbólicos agora são carregados de diretórios de configuração em vez de ignorados. As edições no destino de um link são selecionadas na próxima atualização ou nova sessão
  • resolveSkillsConfigSearchPaths escaneia .claude/skills, então habilidades criadas por Claude Code ficam visíveis para Cline
  • A ferramenta de edição anuncia old_text como uma string simples. Quando o esquema permitia nulo, alguns modelos enviavam nulo em vez do texto de substituição. Nulo ainda é aceito em tempo de execução e tratado como omitido
  • Conectores do Composio: sessões conectadas registram as metaferramentas do Composio (pesquisar, gerenciar conexões, aguardar conexões, executar múltiplas), para que o agente possa encontrar ferramentas de conector em kits de ferramentas, entregar ao usuário um Connect Link para um aplicativo que ainda não está conectado e executar o que encontrou. As ferramentas do conector são descobertas por meio de metapesquisa; o estado de conexão da área de trabalho salvo não fornece mais ferramentas de modelo. Os hosts podem fornecer sua própria autenticação através da nova opção connectorsRequest (ConnectorsRequest exportado de @cline/core), que também é encaminhada para sessões agendadas. resolveComposioToolsStatePath foi renomeado para resolveComposioConnectionStatePath
  • Os auxiliares de login na nuvem Cline no @cline/core aceitam um AbortSignal, para que os hosts possam cancelar um login pendente enquanto ele está pesquisando
  • As atualizações de sessões na nuvem atualizam sessões abertas com títulos renomeados na web e mantêm as renomeações feitas localmente enquanto uma atualização está em andamento
  • Atualizado o catálogo de modelos (6.572 → 6.862 modelos). Adiciona os provedores AI/ML API, LowRouter e Prime Inference. models.dev não lista mais v0, então o provedor v0 é fornecido apenas com seu modelo padrão, v0-1.5-md. O URL base do OpenCode Go muda de https://opencode.ai/zen/go/v1 para https://opencode.ai/inference/go/v1. A lista gratuita Cline adiciona a visualização da Etapa 5. Os modelos padrão mudam para 302.AI, CrossModel, Cortecs, DigitalOcean, NEAR AI Cloud e Ofox (Claude Haiku 5.5), DevPass (LLM Gateway), LLM Gateway e Meta (Muse Wonder 1.0), Aixy (GPT-6.1 Sol), CloudFerro Sherlock e Moark (GLM 5.3), Ambient, NanoGPT, Neuralwatt e Novita AI Changelog completo: https://github.com/cline/cline/compare/sdk/sdk/v0.0.92...sdk/sdk/v0.0.93

cline sdk/sdk/v0.0.93

  • Plugins load in-process through one registry per process instead of a node/bun subprocess, so the compiled CLI and its hub no longer need a runtime on PATH, and plugins can use the Bun global under the Bun-built hub. CLINE_PLUGIN_MODE=sandbox keeps the subprocess sandbox. The registry wraps import, setup, hooks, tools and commands with timeouts and error capture, and tracks each plugin's state (loading/ready/degraded/failed/disabled) with its last error. A failing plugin no longer silently drops its tools: session.create accepts a plugins policy and returns pluginIssues, later failures reach affected sessions as status notices, the hub answers plugins.list/plugins.status/plugins.reload and broadcasts plugin.status_changed, and the daemon marks a plugin failed instead of shutting down when an uncaught error comes from it. Each session gets its own copy of every plugin module, so plugins that keep per-session state at module level keep working
  • Turning reasoning off now works on every provider, not just a fixed list. Models whose catalog entry has no off option are sent nothing and keep their default, and models without a reasoning capability are skipped. Gemini and Vertex send exact thinkingBudget values only to models that advertise a budget; level-only Gemini models get a thinking level instead (they rejected thinkingBudget). A request never carries both the portable reasoning option and a native provider control (effort, thinking, thinkingConfig, …); the native one wins
  • The cline provider's default model is the first entry of the Cline recommended-models list, falling back to anthropic/claude-sonnet-5.5. CLINE_DEFAULT_MODEL_ID moves from Claude Sonnet 5 to Claude Sonnet 5.5, and the openrouter provider default is now anthropic/claude-sonnet-5.5 too
  • estimateRequestInputTokens and createTokenEstimator no longer bill base64 image payloads at the text rate. A ~90 KB screenshot counted as ~30k tokens, so a few images triggered auto compaction long before the transcript was near budget. Each image now adds a flat ESTIMATED_TOKENS_PER_IMAGE (1600). New createImageAwareReplacer export in @cline/shared
  • Auto compaction uses the resolved model's context window. When the discovered catalog entry had no limit but the selected-model override did, compaction was handed the bare catalog entry and ran against the wrong budget
  • Scheduled runs: queued runs are claimed correctly under bun:sqlite, which bound the store's named parameters as NULL so the desktop hub never claimed a queued run and it stayed pending with no error. Runs whose agent turn ends with a provider error (such as a retired model id) are now recorded as failed with the error message instead of succeeding silently, and the run report keeps usage and tool calls. Queued cron occurrences superseded by a newer occurrence of the same schedule are cancelled, so a backlog no longer replays every missed slot back to back
  • Rule files that are symlinks are now loaded from config directories instead of skipped. Edits to a link's target are picked up on the next refresh or new session
  • resolveSkillsConfigSearchPaths scans .claude/skills, so skills authored for Claude Code are visible to Cline
  • The editor tool advertises old_text as a plain string. When the schema allowed null, some models sent null instead of the replacement text. Null is still accepted at runtime and treated as omitted
  • Composio connectors: signed-in sessions register Composio's meta tools (search, manage connections, wait for connections, multi-execute), so the agent can find connector tools across toolkits, hand the user a Connect Link for an app that is not connected yet, and run what it found. Connector tools are discovered through meta search; saved desktop connection state no longer supplies model tools. Hosts can supply their own authentication through the new connectorsRequest option (ConnectorsRequest exported from @cline/core), which is also forwarded to scheduled sessions. resolveComposioToolsStatePath is renamed to resolveComposioConnectionStatePath
  • The Cline cloud sign-in helpers in @cline/core accept an AbortSignal, so hosts can cancel a pending sign-in while it is polling
  • Cloud session refreshes update open sessions with titles renamed on the web, and keep renames made locally while a refresh is in flight
  • Refreshed the model catalog (6,572 → 6,862 models). Adds the AI/ML API, LowRouter, and Prime Inference providers. models.dev no longer lists v0, so the v0 provider ships with only its default model, v0-1.5-md. OpenCode Go's base URL moves from https://opencode.ai/zen/go/v1 to https://opencode.ai/inference/go/v1. The Cline free list adds Step 5 Preview. Default models change for 302.AI, CrossModel, Cortecs, DigitalOcean, NEAR AI Cloud, and Ofox (Claude Haiku 5.5), DevPass (LLM Gateway), LLM Gateway, and Meta (Muse Wonder 1.0), Aixy (GPT-6.1 Sol), CloudFerro Sherlock and Moark (GLM 5.3), Ambient, NanoGPT, Neuralwatt, and Novita AI
