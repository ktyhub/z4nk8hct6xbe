agno v3.0.7

#Changelog

Novos recursos

  • Armazenamento de páginas em agno.knowledge.page. O Knowledge publica atomicamente metadados de catálogo, texto e vetores do sistema de arquivos, preserva revisões anteriores quando uma atualização falha e expõe sincronização limitada e configuração assíncrona, sincronização de origem, pesquisa, leitura, lista e grep APIs. Instalado através do novo extra agno[pages]. (#9963)
    • Knowledge(page_search=PageSearchConfig(...)) fornece controles de planejador local de transação digitado. Preferências de digitalização não definidas, custos, contagens de trabalhadores e limites herdam as configurações do PostgreSQL.
  • PublicSurface para atendimento público: atende agentes selecionados, MCP nativo sem estado e fluxos de trabalho de sincronização durável autenticados, com cotas compartilhadas, limites de solicitação e saída, CORS e autenticação de serviço interno. (#9963)
    • Equipes explicitamente selecionadas agora também podem ser atendidas, com suporte a REST e gzip. Compartilham os limites de admissão, execução e saída do Agente; a lista é reduzida e as rotas dos membros permanecem privadas, a menos que sejam selecionadas de forma independente. (#9996)
  • PageFileSystem(knowledge=...): um kit de ferramentas de sistema de arquivos de página somente leitura limitado com execução sincronizada e assíncrona, exposto explicitamente por meio de files.tools(). Os comandos leem páginas preguiçosamente em relação às revisões fixadas, listam metadados com escopo definido e executam grep literal limitado; eles não podem executar um shell ou gravar arquivos. (#9997)
  • Os callables de dependência do agente podem receber run_input e session, junto com os agent e run_context existentes. A resolução é executada antes dos pré-ganchos e reutiliza valores bem-sucedidos nas novas tentativas do modelo. add_dependencies_to_context ainda tem como padrão False. (#9963)
  • AIMLAPI: as solicitações carregam um conjunto de cabeçalho de atribuição fixo somente para análise, inspecionável como agno.models.aimlapi.AIMLAPI_HEADERS e substituível por modelo via default_headers, onde as chaves fornecidas pelo chamador vencem. Os cabeçalhos não carregam dados do usuário e não afetam o roteamento, a seleção do modelo ou o faturamento. O modelo padrão também passa do gpt-4o-mini aposentado para o gpt-5.6-terra. (#9898)

Melhorias

  • Os fluxos de trabalho relatam etapas com falha como StepError para falhas de executor levantadas e saídas com falha explícita, carregando a identidade da etapa atual. Os relatórios de função ainda são preservados como StepOutput, e o conteúdo do agente, da equipe e do fluxo de trabalho aninhado mantém seu fluxo de executor existente. Ambas as impressoras de streaming do console renderizam StepError explicitamente, mostrando a falha original e limpando a saída de progresso obsoleta. (#10001)

Correções de bugs

  • As execuções de fluxo de trabalho com falha são finalizadas antes do evento de streaming do terminal. Um fluxo de trabalho pausado durante um fluxo em segundo plano pode falhar durante uma continuação sem streaming, salvar ERROR no banco de dados e deixar seu fluxo rastreado preso em PAUSED; novas falhas de streaming produziram WorkflowError antes que a execução com falha fosse salva, portanto, um consumidor que fechasse naquele evento poderia perder totalmente a execução. (#10001)
    • As rejeições de proteção de fluxo de trabalho aninhadas não são mais repetidas, o que anteriormente reproduzia efeitos colaterais secundários anteriores. O skip_on_failure explícito é respeitado por meio da política de tentativa final existente e as novas tentativas comuns do executor são preservadas.
  • Meta Llama e AIMLAPI: todas as execuções falharam. As substituições _format_message de ambos os provedores foram derivadas de OpenAIChat, que passa compress_tool_results posicionalmente, então cada chamada gerou TypeError: _format_message() takes 2 positional arguments but 3 were given. (#10031, #9898, correções #9034)
  • Anthropic: argumentos de ferramenta vazios são preservados. Uma chamada de ferramenta Claude com argumento zero é um objeto de entrada vazio, que o adaptador tratou como falso e omitiu function.arguments. A análise de streaming e não streaming agora serializa cada entrada de ferramenta, então a entrada vazia se torna "{}". (#8970, correções #8971)
  • Os wrappers de ferramentas armazenados em cache não fixam mais o quadro do chamador. validate_call armazena o f_locals do chamador no wrapper que ele cria e o Function armazena esses wrappers em cache durante a vida do processo, portanto, em Python 3.13, cada ferramenta em cache manteve o quadro de empacotamento ativo junto com o agente, a sessão e o estado de execução na pilha. O resolvedor de namespace é limpo assim que os validadores são construídos. (#9941, correções #9940)
  • Agente nativo anônimo JSON não vaza mais diagnósticos: uma execução com falha retornou HTTP 200 carregando o status ERROR e diagnóstico de modelo aninhado, e agora é um 503 run_failed seguro, combinando com a proteção contra erros de streaming. Os diagnósticos do operador autenticado não são afetados. (#9963)
  • Correções de veiculação de páginas em novas tentativas de origem, desduplicação de link canônico, vinculação de origem no momento da publicação, verificação de página limitada e ordenação de dependência de continuação do agente. (#9996)

Mudanças significativas

  • Os argumentos do construtor Knowledge são apenas palavras-chave. Chamadas posicionais como Knowledge("docs") devem se tornar Knowledge(name="docs"). content_db agora é a grafia preferida; contents_db continua sendo um alias de leitura/gravação compatível, compartilhando o mesmo campo de classe de dados, portanto, serialização, cópia e dataclasses.replace(..., contents_db=...) permanecem inalterados. Passar ambas as palavras-chave requer o mesmo objeto. (#9963)
  • A pesquisa de página respeita o PgVector HNSW ef_search configurado em vez de forçar silenciosamente 200, portanto, as implantações que dependiam do 200 implícito devem defini-lo explicitamente. Os índices de página construídos a partir de compilações principais provisórias podem carregar um ef_construction=64 implícito e precisar de uma reconstrução gerenciada pelo operador; a configuração relata um erro acionável em vez de reconstruir automaticamente. (#9963)

agno v3.0.7

Changelog

New Features

  • Page storage in agno.knowledge.page. Knowledge atomically publishes catalog metadata, filesystem text and vectors, preserves previous revisions when a refresh fails, and exposes bounded sync and async setup, source synchronization, search, read, list and grep APIs. Installed through the new agno[pages] extra. (#9963)
    • Knowledge(page_search=PageSearchConfig(...)) provides typed, transaction-local planner controls. Unset scan preferences, costs, worker counts and thresholds inherit the PostgreSQL settings.
  • PublicSurface for public serving: serves selected Agents, native stateless MCP and authenticated durable-sync Workflows, with shared quotas, request and output bounds, CORS and internal-service authentication. (#9963)
    • Explicitly selected Teams are now servable too, with REST and gzip support. They share the Agent admission, execution and output limits; the roster is reduced and member routes stay private unless independently selected. (#9996)
  • PageFileSystem(knowledge=...): a bounded read-only page filesystem toolkit with sync and async execution, exposed explicitly through files.tools(). Commands read pages lazily against pinned revisions, list scoped metadata and run bounded literal grep; they cannot execute a shell or write files. (#9997)
  • Agent dependency callables can receive run_input and session, alongside the existing agent and run_context. Resolution runs before pre-hooks and reuses successful values on model retries. add_dependencies_to_context still defaults to False. (#9963)
  • AIMLAPI: requests carry a fixed, analytics-only attribution header set, inspectable as agno.models.aimlapi.AIMLAPI_HEADERS and overridable per model via default_headers, where caller-supplied keys win. The headers carry no user data and do not affect routing, model selection or billing. The default model also moves from the retired gpt-4o-mini to gpt-5.6-terra. (#9898)

Improvements

  • Workflows report failed steps as StepError for both raised executor failures and explicitly failed outputs, carrying the current step's identity. Function reports are still preserved as StepOutput, and Agent, Team and nested Workflow content keeps its existing executor stream. Both console streaming printers render StepError explicitly, showing the original failure and clearing stale progress output. (#10001)

Bug Fixes

  • Failed workflow runs are finalized before their terminal streaming event. A workflow that paused during a background stream could fail during a non-streaming continuation, save ERROR to the database and leave its tracked stream stuck at PAUSED; fresh streaming failures yielded WorkflowError before the failed run was saved, so a consumer closing at that event could lose the run entirely. (#10001)
    • Nested workflow guardrail rejections are no longer retried, which previously replayed earlier child side effects. Explicit skip_on_failure is honored through the existing final-attempt policy and ordinary executor retries are preserved.
  • Meta Llama and AIMLAPI: every run crashed. Both providers' _format_message overrides had drifted from OpenAIChat, which passes compress_tool_results positionally, so each call raised TypeError: _format_message() takes 2 positional arguments but 3 were given. (#10031, #9898, fixes #9034)
  • Anthropic: empty tool arguments are preserved. A zero-argument Claude tool call is an empty input object, which the adapter treated as falsy and omitted function.arguments for. Streaming and non-streaming parsing now serialize every tool input, so empty input becomes "{}". (#8970, fixes #8971)
  • Cached tool wrappers no longer pin the caller's frame. validate_call stores the caller's f_locals on the wrapper it builds and Function caches those wrappers for the life of the process, so on Python 3.13 every cached tool kept the wrapping frame alive along with the Agent, session and run state on the stack. The namespace resolver is cleared once the validators are built. (#9941, fixes #9940)
  • Anonymous native Agent JSON no longer leaks diagnostics: a failed run returned HTTP 200 carrying status ERROR and nested model diagnostics, and is now a safe 503 run_failed, matching the streaming error protection. Authenticated operator diagnostics are unaffected. (#9963)
  • Page serving corrections across source retries, canonical-link deduplication, publication-time source binding, bounded page checkout and Agent continuation dependency ordering. (#9996)

Highlights

  • Pages become a first-class, transaction-safe subsystem — plus a public serving surface — #9963 adds agno.knowledge.page: atomic publication of catalog metadata, filesystem text and vectors that preserves the previous revision when a refresh fails, with bounded sync/async setup, source sync, search, read, list and grep APIs, installed via the new agno[pages] extra. PublicSurface then serves selected Agents, stateless MCP and durable-sync Workflows under shared quotas, request/output bounds, CORS and internal-service auth, and #9996 extends this to explicitly selected Teams (REST + gzip) with a trimmed roster and member routes kept private. This is the release's centerpiece: it turns "docs" into a bounded, reversible serving primitive instead of ad-hoc ingestion — but quotas and limits are shared across every served surface, so capacity-plan before exposing Teams.
  • Migration required: Knowledge is now keyword-only — #9963 breaks positional Knowledge("docs"), which must become Knowledge(name="docs"). content_db is the preferred spelling; contents_db survives as a read/write alias on the same dataclass field, so serialization, copy and dataclasses.replace(..., contents_db=...) are unchanged, but passing both keywords now requires the identical object. Audit all positional Knowledge(...) calls before upgrading; this is the most likely source of immediate breakage.
  • Page search stops hardcoding HNSW ef_search — also in #9963, page search now honors the configured PgVector ef_search instead of silently forcing 200, so anyone who depended on the implicit 200 must set it explicitly or recall/accuracy will shift. Indexes built from interim main builds may carry an implicit ef_construction=64 and need an operator-managed rebuild; setup emits an actionable error rather than rebuilding automatically, making this a deliberate scheduled migration rather than a silent one.
  • Workflow failures become observable — and stop being lost — #10001 reports failed steps as StepError (for both raised executor failures and explicitly failed outputs) carrying step identity, and both console printers render it while clearing stale progress; function results stay StepOutput and Agent/Team/nested content keeps its executor stream, so check any consumer that pattern-matched only on StepOutput. The same PR fixes a real loss path where a run that paused in a background stream then failed during non-streaming continuation saved ERROR while its stream stayed PAUSED, and fresh streaming failures emitted WorkflowError before the run was persisted — a consumer closing on that event could lose the run entirely. Nested guardrail rejections are also no longer retried, preventing replay of earlier child side effects.
  • Three provider crashes fixed — prioritize if you use Llama, AIMLAPI or Anthropic — Meta Llama and AIMLAPI _format_message overrides had drifted from OpenAIChat's positional compress_tool_results, so every run died with TypeError: _format_message() takes 2 positional arguments but 3 were given (#10031, #9898, fixes #9034); Anthropic now serializes zero-argument tool calls as "{}" instead of dropping function.arguments (#8970, fixes #8971). AIMLAPI additionally moves its default off the retired gpt-4o-mini to gpt-5.6-terra and adds analytics-only attribution headers (AIMLAPI_HEADERS, overridable per model via default_headers, caller keys winning) that carry no user data — check model pinning and header allowlists.
  • Less memory retention and fewer diagnostic leaks — #9941 (fixes #9940) clears the namespace resolver after validate_call builds tool wrappers, so cached Function wrappers on Python 3.13 no longer pin the caller's frame along with the Agent, session and run state for the process lifetime; long-lived 3.13 servers should see flatter memory. Separately, #9963 turns anonymous native Agent JSON failures from HTTP 200 with embedded model diagnostics into a safe 503 run_failed, matching the streaming error path while leaving authenticated operator diagnostics intact.

Breaking Changes

  • Knowledge constructor arguments are keyword-only. Positional calls such as Knowledge("docs") must become Knowledge(name="docs"). content_db is now the preferred spelling; contents_db remains a supported read/write alias sharing the same dataclass field, so serialization, copy and dataclasses.replace(..., contents_db=...) are unchanged. Passing both keywords requires the same object. (#9963)
  • Page search honours the configured PgVector HNSW ef_search instead of silently forcing 200, so deployments that relied on the implicit 200 should set it explicitly. Page indexes built from interim main builds can carry an implicit ef_construction=64 and need an operator-managed rebuild; setup reports an actionable error rather than rebuilding automatically. (#9963)
