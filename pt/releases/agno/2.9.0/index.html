agno v2.9.0

#Changelog

Novos recursos

  • StudioRunnerTools: novo kit de ferramentas de despacho com reconhecimento de identidade (agno.tools.studio_runner.StudioRunnerTools) que divide a execução de StudioTools. Qualquer componente (líder de equipe, roteador) pode montá-lo para descobrir e executar agentes/equipes/fluxos de trabalho criados no Studio sem obter a superfície de criação/edição/exclusão do Studio. As ferramentas run_* encadeiam o user_id do chamador na subexecução para que o estado por usuário chegue à pessoa certa.
  • Filtro de nome list_components: foi adicionado um filtro name a list_components.

Correções de bugs

  • A2A: Corrigido o fluxo A2A client que eliminava metadados no nível da tarefa ao quebrar na atualização de status.
  • Fluxo de trabalho (WebSocket): respeite a versão do fluxo de trabalho selecionada no WebSocket.
  • Equipe HITL: Persistir execuções de membros pausadas para que o currículo HITL da equipe sobreviva a uma recarga de sessão.
  • Reidratação: Preserva as instruções do kit de ferramentas sobre reidratação.
  • Anotações de estrutura: anotações de retorno de estrutura de proteção.

Comportamento e mudanças importantes

  • Substituição da ferramenta MCP tool_name bloqueada (Segurança): os pontos de entrada da ferramenta MCP não permitem mais uma substituição tool_name no momento da chamada. Anteriormente, um modelo poderia passar tool_name="delete_repo" para qualquer ferramenta MCP e o servidor executaria essa ferramenta enquanto listas de permissões, requires_confirmation, aprovação HITL e registro eram resolvidos a partir do nome declarado, ignorando qualquer portão de HITL/aprovação. O nome da ferramenta executada agora está fechado em tool.name. Os argumentos tool_name fornecidos pelo modelo são encaminhados como argumentos comuns (não usados ​​para escolher a ferramenta), portanto, as ferramentas que declaram legitimamente um parâmetro tool_name continuam funcionando.
  • O cache de resultados da ferramenta agora usa chaves por usuário (segurança/alteração de comportamento): com cache_results=True, a chave de cache agora inclui uma identidade de contexto de execução estável (user_id, session_id), corrigindo um vazamento de cache entre usuários em que uma ferramenta armazenada em cache que levava run_context (por exemplo, MemoryTools) servia o resultado de um usuário para outro. run_id fica fora da chave, de modo que o armazenamento em cache permanece útil durante as execuções do usuário. Alterações existentes no comportamento do cache — as chaves são compostas de maneira diferente, portanto, os acessos anteriores ao cache não serão alinhados da mesma maneira.
  • A reidratação agora falha ruidosamente (mudança de comportamento): desserialização de um componente persistente com referências não resolvidas usadas para degradar silenciosamente (as ferramentas de um agente se tornaram [], uma equipe perdeu membros, esquemas/conhecimento foram descartados) e depois executado. Referências não resolvidas agora geram ComponentRehydrationError (um AgnoError, status_code=422) em caminhos estritos. A rigidez é uma propriedade do chamador: público from_dict/load padrão strict=False (as viagens de ida e volta continuam funcionando), mas pesquisas do AgentOS e todos os caminhos de despacho (REST POST /runs, continuar, ferramentas de execução MCP, StudioRunner) são padrão strict=True e agora retornam um 422 nomeando a parte não resolvida em vez de executar um componente degradado. Versões de membros fixadas também são homenageadas.

agno v2.9.0

Changelog

New Features

  • StudioRunnerTools: New identity-aware dispatch toolkit (agno.tools.studio_runner.StudioRunnerTools) that splits execution out of StudioTools. Any component (team lead, router) can mount it to discover and run Studio-built agents/teams/workflows without getting the Studio's create/edit/delete surface. run_* tools thread the caller's user_id into the sub-run so per-user state lands on the right person.
  • list_components name filter: Added a name filter to list_components.

Bug Fixes

  • A2A: Fixed the A2A stream client dropping Task-level metadata by breaking on status-update.
  • Workflow (WebSocket): Honor the selected workflow version over WebSocket.
  • Team HITL: Persist paused member runs so team HITL resume survives a session reload.
  • Rehydration: Preserve toolkit instructions on rehydration.
  • Framework annotations: Guard framework return annotations.

Behaviour & Breaking Changes

  • MCP tool tool_name override blocked (Security): MCP tool entrypoints no longer allow a call-time tool_name override. Previously a model could pass tool_name="delete_repo" to any MCP tool and the server would execute that tool while allow-lists, requires_confirmation, HITL approval, and logging all resolved from the declared name — bypassing any HITL/approval gate. The executed tool name is now closed over from tool.name. Model-supplied tool_name args are forwarded as ordinary arguments (not used to pick the tool), so tools that legitimately declare a tool_name parameter keep working.
  • Tool result caching now uses per-user keys (Security / behaviour change): With cache_results=True, the cache key now includes stable run-context identity (user_id, session_id), fixing a cross-user cache leak where a cached tool taking run_context (e.g. MemoryTools) served one user's result to another. run_id stays out of the key so caching remains useful across a user's runs. Existing cache behaviour changes — keys are composed differently, so prior cache hits won't line up the same way.
  • Rehydration now fails loudly (behaviour change): Deserializing a persisted component with unresolvable references used to silently degrade (an agent's tools became [], a team lost members, schemas/knowledge dropped) and then run. Unresolvable references now raise ComponentRehydrationError (an AgnoError, status_code=422) on strict paths. Strictness is a caller property: public from_dict/load default strict=False (round-trips keep working), but AgentOS lookups and every dispatch path (REST POST /runs, continue, MCP run tools, StudioRunner) default strict=True and now return a 422 naming the unresolvable piece instead of running a degraded component. Pinned member versions are also honored.
