agno v3.0.5

#Changelog

Alterações importantes

  • As falhas de incorporação são exibidas, não mascaradas. A ingestão agora relata falhas de incorporação em vez de retornar sucesso. O conteúdo que anteriormente exibia completed agora pode exibir failed ou partial — essas ingestões eram sempre incompletas e eram apenas relatadas como bem-sucedidas. A enum ContentStatus no API (/openapi.json) ganha partial, mudando de ["processing","completed","failed"] para ["processing","completed","partial","failed"]. Nenhuma migração de esquema é necessária (a coluna de status já é varchar).
  • Os incorporadores aumentam EmbeddingError em vez de retornar um vetor vazio em caso de falha. Chamar um banco de dados de vetor search() diretamente agora aumenta onde ele retornou anteriormente []; Knowledge.search() não é afetado e ainda não retorna resultados.
  • As falhas de incorporação do AWS Bedrock aumentam EmbeddingError, não ModelProviderError. Os manipuladores except ModelProviderError existentes em torno da incorporação do Bedrock deixarão de ser detectados. Mude para except EmbeddingError.
  • GET /knowledge/content/{id}/status retorna 404 para conteúdo ausente/não pertencente em vez de 200 com status: "failed".
  • skip_if_exists=True não pula mais o conteúdo gravado como failed ou partial, portanto, o conteúdo incompleto é reincorporado em vez de ser marcado silenciosamente como completo.

Novos recursos

  • partial status do conteúdo: novo ContentStatus.PARTIAL para arquivos em que alguns pedaços foram incorporados e outros não — pesquisáveis, mas incompletos, portanto, nem completed nem failed. (#9814)
  • Repetição de incorporação opcional durante a ingestão (desativado por padrão): ative com Knowledge(max_embedding_retries=3, embedding_retry_backoff=1.0). As falhas de autenticação ignoram ambas as configurações e falham na primeira tentativa (a mesma credencial é sempre rejeitada). Observação: cada nova tentativa incorpora novamente o documento inteiro.
  • GandrTools: novo kit de ferramentas de conversão de texto em fala para o Gandr TTS API.
  • provedor de modelo llmman: novo provedor de modelo.

Melhorias

  • Mensagens de falha de incorporação acionáveis: as mensagens de falha agora nomeiam a contagem de blocos, o incorporador, o motivo e a etapa de recuperação, em vez de "Não foi possível inserir a incorporação".
  • A reingestão não destrói mais partes pesquisáveis: um protetor embed_before_replace incorpora documentos antes de excluir os existentes, portanto, uma reingestão com falha é abortada antes que qualquer coisa seja removida (anteriormente, uma reincorporação com falha poderia deixar um documento com zero partes).
  • MCPTools aceita headers= estático: os cabeçalhos de autenticação no tempo de conexão podem ser transmitidos diretamente no caminho url= para HTTP e SSE transmitíveis, sem construir StreamableHTTPClientParams.

agno v3.0.5

Highlights

  • Embedding failures are now surfaced, not silently swallowed (#9814) — Ingestion stops reporting completed for content whose embeddings actually failed; those records now show failed or the new partial status. Editorially: expect your ingestion dashboards to turn red on day one — this is exposing pre-existing data loss, not causing it. The API's ContentStatus enum grows from ["processing","completed","failed"] to include partial; no schema migration is needed because the status column is already varchar, but any client doing strict enum validation against /openapi.json will need updating.
  • Exception contract changes bite Bedrock and direct vector-DB callers — Embedders now raise EmbeddingError instead of returning [] when you call a vector DB's search() directly (Knowledge.search() still returns empty results, so only raw callers are affected). More dangerously, AWS Bedrock embedding failures now raise EmbeddingError rather than ModelProviderError, so existing except ModelProviderError blocks will silently stop catching — audit and switch those handlers to except EmbeddingError before upgrading, or errors will escape unhandled.
  • Status lookup and skip_if_exists semantics shift — GET /knowledge/content/{id}/status now returns 404 for missing or non-owned content instead of 200 with status: "failed"; clients that parse the body and never check the status code will misread this. Meanwhile skip_if_exists=True no longer treats failed/partial records as done, so incomplete documents get re-embedded instead of being left broken — good for recovery, but watch embedding cost on corpora with historically masked failures.
  • Failure resilience gets two guardrails (both off by default) — Opt into Knowledge(max_embedding_retries=3, embedding_retry_backoff=1.0) for transient embedding errors, but note authentication failures intentionally bypass retries (same credential, same rejection) and every retry re-embeds the whole document, so this is a cost/latency tradeoff, not a free safety net. Separately, the embed_before_replace guard in #9814 embeds new content before deleting old chunks, so a failed re-ingest aborts atomically instead of leaving a document with zero searchable chunks — a real data-loss fix worth verifying if you re-ingest frequently.
  • Smaller surface additions worth noting — MCPTools now accepts static headers= on the url= path for connect-time auth with Streamable HTTP and SSE, removing the need to hand-build StreamableHTTPClientParams (#9444). New Gandr TTS toolkit (#9852) and llmman provider (#9863) expand integrations, and litellm/crawl4ai extras are re-enabled (#9868) — check those extras if you previously worked around their removal.

Changelog

Breaking Changes

  • Embedding failures are surfaced, not masked. Ingestion now reports embedding failures instead of returning success. Content that previously showed completed may now show failed or partial — those ingests were always incomplete, they were only reported as successful. The ContentStatus enum in the API (/openapi.json) gains partial, changing from ["processing","completed","failed"] to ["processing","completed","partial","failed"]. No schema migration is required (the status column is already varchar).
  • Embedders raise EmbeddingError instead of returning an empty vector on failure. Calling a vector DB's search() directly now raises where it previously returned []; Knowledge.search() is unaffected and still returns no results.
  • AWS Bedrock embedding failures raise EmbeddingError, not ModelProviderError. Existing except ModelProviderError handlers around Bedrock embedding will stop catching — switch to except EmbeddingError.
  • GET /knowledge/content/{id}/status returns 404 for missing/non-owned content instead of 200 with status: "failed".
  • skip_if_exists=True no longer skips content recorded as failed or partial, so incomplete content is re-embedded rather than silently marked complete.

New Features

  • partial content status: new ContentStatus.PARTIAL for files where some chunks embedded and others did not — searchable but incomplete, so neither completed nor failed. (#9814)
  • Optional embedding retry during ingestion (off by default): enable with Knowledge(max_embedding_retries=3, embedding_retry_backoff=1.0). Authentication failures ignore both settings and fail on the first attempt (the same credential is rejected every time). Note: each retry re-embeds the whole document.
  • GandrTools: new text-to-speech toolkit for the Gandr TTS API.
  • llmman model provider: new model provider.

Improvements

  • Actionable embedding failure messages: failure messages now name the chunk count, embedder, reason and recovery step, instead of "Could not insert embedding".
  • Re-ingest no longer destroys searchable chunks: an embed_before_replace guard embeds documents before deleting existing ones, so a failing re-ingest aborts before anything is removed (previously a failed re-embed could leave a document with zero chunks).
  • MCPTools accepts static headers=: connect-time auth headers can be passed directly on the url= path for Streamable HTTP and SSE, without constructing StreamableHTTPClientParams.
