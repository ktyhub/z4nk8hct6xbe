agno v3.1.0

Novos recursos

  • Gerenciamento/autorização de usuários (RBAC): um novo pacote agno.os.authz adiciona controle de acesso baseado em funções ao AgentOS — um armazenamento de funções, política de escopo, registro de auditoria, diretório de usuários e um roteador de administrador, com mecanismos de autorização conectáveis (um mecanismo nativo mais um mecanismo fga de granularidade fina). Os escopos e o middleware de autenticação foram estendidos para aplicá-lo.
  • Sistema de arquivos AgentOS: um novo sistema de arquivos agno.fs (DbFileSystem) com rotas /filesystem dedicadas (listar/ler/gerenciar arquivos) apoiados por uma tabela agno_fs.
  • Atualizações de configuração/autenticação do MCP: configuração atualizada do servidor MCP e tratamento de autenticação MCP integrado.
  • AIMLAPITools: novo kit de ferramentas para imagem, vídeo, fala e transcrição por meio do AI/ML API.

⚠️ Mudanças importantes

  • Rechaveamento da tabela do sistema de arquivos (agno_fs): v3.1 codifica a tabela do sistema de arquivos por (namespace, user_id, path), onde user_id é a partição do usuário ("" para a partição compartilhada/sem usuário). Uma tabela criada por uma versão anterior é recusada com SchemaOutdatedError até ser atualizada. A rechave nunca é executada automaticamente. Atualize uma vez, com a aplicação parada, usando o script do seu banco de dados (#10530): Isso afetará você somente se você usar DbFileSystem. A tabela é gerenciada por DbFileSystem (seu próprio esquema, que pode ser construído a partir de um db_url simples), portanto, deliberadamente não faz parte de MigrationManager.
python libs/agno/migrations/migrate_filesystem_postgres.py   # PostgreSQL
python libs/agno/migrations/migrate_filesystem_sqlite.py     # SQLite
  • As ferramentas padrão e de ciclo de vida do MCP agora são opcionais: MCPConfig(tools=[...]) agora publica exatamente as ferramentas que você lista - tanto default_tools quanto lifecycle_tools são padronizados como False. Anteriormente, uma configuração tools=[...] também atendia às ferramentas padrão integradas (e ao ciclo de vida continue_run / cancel_run).

Correções de bugs

  • HITL: continuar uma execução pausada com background + stream não duplica mais a execução pausada em seu próprio histórico.
  • OpenAIResponses: recupera solicitações quando a resposta encadeada (anterior) desaparece.
  • DB: uma exclusão assíncrona que com falha não é mais relatada como uma execução que não estava lá — os dois casos são distintos.
  • Saída estruturada: não trava quando um fragmento JSON fornece um escalar antes de uma lista.
  • Resultados da ferramenta Python: distinguir resultados avaliados de None de variáveis ​​ausentes.
  • Chunking: rejeita uma sobreposição que não seja menor que o tamanho do bloco.
  • Leitores CSV: lidam com finais de registros CR (\r).
  • CsvTools: respeita limites explícitos de zero linhas.
  • Ferramentas de comando do shell/espaço de trabalho: respeitam um zero explícito tail.
  • GeminiTools: armazena bytes de vídeo brutos no artefato generate_video .
  • GithubTools: cria links de ramificação a partir da URL da web do repositório (#10509); get_file_content preserva texto válido não ASCII UTF-8
  • LocalFileSystemTools: lê e grava arquivos locais como UTF-8.
  • PubMed: preserva metadados para resumos curtos.
  • Citações de Claude: preserva títulos de documentos anuláveis.

agno v3.1.0

Highlights

  • AgentOS gains RBAC — The new agno.os.authz package adds role-based access control to AgentOS: a role store, scope policy, audit log, user directory and admin router, with pluggable authorization engines (native and fine-grained fga). Scopes and auth middleware were extended to enforce it. If you're running AgentOS in a multi-user context, this is the release that gives you per-user permissions and an audit trail — plan how you'll map existing identities onto roles before enabling enforcement, since scope checks now actually bite.

  • A managed filesystem for AgentOS — agno.fs introduces DbFileSystem, backed by a new agno_fs table and exposed through dedicated /filesystem routes for listing, reading and managing files. It manages its own schema from a bare db_url, so it is deliberately outside MigrationManager — meaning upgrades are a manual, app-specific concern rather than something the standard migration flow will handle for you.

  • Breaking — filesystem table re-key requires a manual, offline migration — v3.1 keys agno_fs by (namespace, user_id, path), with "" denoting the shared/no-user partition. Tables created by older releases are refused with SchemaOutdatedError and the re-key never runs automatically (#10530). If you use DbFileSystem, stop the application and run the right script once — migrate_filesystem_postgres.py or migrate_filesystem_sqlite.py under libs/agno/migrations/ — before restarting, or your filesystem routes will fail outright.

  • Breaking — MCP default and lifecycle tools are now opt-in — With MCPConfig(tools=[...]) you now get exactly the tools you list: both default_tools and lifecycle_tools default to False (#10285). Previously a tools=[...] config silently also served the built-in defaults plus continue_run / cancel_run. If an agent relied on those built-ins without declaring them, it will lose them on upgrade — set the flags explicitly to restore old behavior.

  • New AIMLAPITools toolkit — Adds image, video, speech and transcription capabilities via the AI/ML API (#10276). This is a new provider option for multimodal workloads; worth evaluating if you want to consolidate generation and transcription behind a single toolkit rather than mixing vendors.

  • Notable fixes for long-running agents — HITL pauses resumed with background + stream no longer duplicate the run in history (#10597); OpenAIResponses recovers when a chained previous response is gone (#10395); failed async deletes are no longer misreported as "run not found" (#10682); and structured output no longer crashes when a JSON fragment yields a scalar before a list (#10654). Collectively these harden multi-turn and streaming flows — check them against any resilience or retry logic you built around the old behavior.

New Features

  • User Management / Authorization (RBAC): a new agno.os.authz package adds role-based access control to AgentOS — a role store, scope policy, audit log, user directory and an admin router, with pluggable authorization engines (a native engine plus a fine-grained fga engine). Scopes and auth middleware were extended to enforce it.
  • AgentOS Filesystem: a new agno.fs filesystem (DbFileSystem) with dedicated /filesystem routes (list/read/manage files) backed by an agno_fs table.
  • MCP config / auth updates: refreshed MCP server config and built-in MCP auth handling.
  • AIMLAPITools: new toolkit for image, video, speech and transcription via the AI/ML API.

⚠️ Breaking Changes

  • Filesystem table re-key (agno_fs): v3.1 keys the filesystem table by (namespace, user_id, path), where user_id is the user partition ("" for the shared/no-user partition). A table created by an earlier release is refused with SchemaOutdatedError until upgraded — the re-key never runs automatically. Upgrade once, with the application stopped, using the script for your database (#10530):

This affects you only if you use DbFileSystem. The table is managed by DbFileSystem (its own schema, buildable from a bare db_url), so it is deliberately not part of MigrationManager.

python libs/agno/migrations/migrate_filesystem_postgres.py   # PostgreSQL
python libs/agno/migrations/migrate_filesystem_sqlite.py     # SQLite
  • MCP default & lifecycle tools are now opt-in: MCPConfig(tools=[...]) now publishes exactly the tools you list — both default_tools and lifecycle_tools default to False. Previously a tools=[...] config also served the built-in default tools (and the lifecycle continue_run / cancel_run).

Bug Fixes

  • HITL: continuing a paused run with background + stream no longer duplicates the paused run in its own history.
  • OpenAIResponses: recover requests when the chained (previous) response is gone.
  • DB: an async delete that failed is no longer reported as a run that wasn't there — the two cases are distinguished.
  • Structured output: don't crash when a JSON fragment provides a scalar before a list.
  • Python tool results: distinguish Nonevalued results from missing variables.
  • Chunking: reject an overlap that is not smaller than the chunk size.
  • CSV readers: handle CR (\r) record endings.
  • CsvTools: honor explicit zero row limits.
  • Shell / workspace command tools: honor an explicit zero tail.
  • GeminiTools: store raw video bytes in the generate_video artifact.
  • GithubTools: build branch links from the repository web URL (#10509); get_file_content preserves valid non-ASCII UTF-8 text
  • LocalFileSystemTools: read and write local files as UTF-8.
  • PubMed: preserve metadata for short abstracts.
  • Claude citations: preserve nullable document titles.
