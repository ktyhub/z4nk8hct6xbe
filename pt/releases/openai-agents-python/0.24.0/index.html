Resumo do escopo

  • O candidato contém main atual e #5335. As alterações além do principal estão limitadas aos metadados de propriedade do lançamento.

Avaliação de risco (ordenada por impacto)

  1. Roteie as execuções salvas afetadas para seu SDK original e código do agente.
    • Risco: 🟢 BAIXO, com precaução de atualização necessária. Alguns pontos de verificação anteriormente legíveis agora falham com segurança, em vez de correrem o risco de propriedade incorreta do agente.
  • Evidência: o escritor avança do esquema 1.18 para 1.21. O leitor rejeita certos gráficos mais antigos com agentes não-raiz de mesmo nome, cuja ordem de identidade salva poderia ter dependido de atributos de gancho, mesmo quando esses atributos permaneceram inalterados. A nova geração de identidade exclui todos os atributos de instância de gancho e mantém o tipo de gancho. Gráficos distinguíveis apenas por esses atributos não podem ser serializados. Outros esquemas históricos suportados permanecem legíveis.
    • Arquivos: src/agents/run_state.py, src/agents/_run_state_agent_identity.py, tests/test_run_state.py.
    • Ação: conclua as tarefas legadas afetadas com o SDK original, definições de agente inalteradas e ordem de gancho usada quando o instantâneo foi gravado. Use nomes de agentes exclusivos antes de iniciar novas execuções duráveis. Não renomeie um gráfico armazenado nem altere seu rótulo de esquema para forçar a migração. SDKs mais antigos não podem ler novos instantâneos 1.21.

  1. Atualize os formatadores de erros de ferramentas personalizadas existentes para uma terceira categoria.

    • Risco: 🟢 BAIXO, com migração explícita para callbacks exaustivos. Um formatador que trata cada não rejeição como uma ferramenta ausente agora pode retornar texto enganoso para uma função travada.
    • Evidência: ToolErrorFormatterArgs.kind adiciona "tool_exception"; o campo opcional error é anexado. O retorno de chamada em toda a execução agora lida com falhas de funções decoradas elegíveis. Manipuladores explícitos por ferramenta, incluindo None explícito ou o manipulador padrão, mantêm a precedência. Falhas, tempos limite, cancelamento e chamadas de programa apoiadas por esquema criadas de fábrica no MCP e Agent.as_tool mantêm seu comportamento separado.
    • Arquivos: src/agents/run_config.py, src/agents/tool.py, src/agents/run_internal/tool_execution.py, tests/test_tool_exception_formatter.py.
    • Ação: manipule "tool_exception" explicitamente ou retorne None para que ele retenha a mensagem padrão. Mantenha os detalhes da exceção fora da saída visível do modelo, a menos que sejam deliberadamente higienizados. Sem formatador personalizado, o comportamento padrão permanece inalterado.

  2. Preservar o trabalho concluído sem prometer repetição automática.

    • Risco: 🟢 BAIXO. A recuperação retém mais trabalhos concluídos, mas os aplicativos ainda devem conciliar os efeitos colaterais externos e o histórico parcialmente comprometido.
    • Evidência: o histórico de aprovações diferidas aguarda o limite do guardrail de saída. Para execuções gerenciadas por client, ​​os pares de chamada/saída aceitos sobrevivem a falhas de irmãos ou de retorno de chamada depois que as proteções de entrada e saída da ferramenta permitem a publicação. As conversas gerenciadas pelo servidor mantêm seu caminho de recuperação separado. As gravações pendentes retêm a identidade da sessão e o estado de compactação. A compactação automática aguarda aprovações pendentes; a substituição autônoma do Redis usa uma transação. As gravações de conversas usam lotes de no máximo 20 itens e podem ser confirmadas parcialmente entre solicitações.
    • Arquivos: src/agents/run_internal/session_persistence.py, src/agents/run_internal/tool_execution.py, src/agents/memory/openai_conversations_session.py, src/agents/memory/openai_responses_compaction_session.py, src/agents/extensions/memory/redis_session.py.
    • Ação: retomar falhas não terminais suportadas com o back-end e ID da sessão original, usando o estado e o histórico retornados em vez de reproduzir ferramentas concluídas. Após um acréscimo parcial de Conversas, inspecione e repare o histórico remoto antes de tentar novamente; não reenvie a lista completa enquanto uma parte anterior permanecer armazenada. Coordenar outros redatores; A substituição atômica do Redis não evita a compactação obsoleta entre os processos. As leituras e pops do cluster Redis permanecem disponíveis, mas o acréscimo, a limpeza e a substituição transacionais exigem um back-end compatível. As falhas de saída do terminal não podem ser reproduzidas.

  3. Mantenha a área restrita, o rastreamento e os limites de exibição pretendidos.

  • Risco: 🟢 BAIXO. Os comandos locais do macOS não podem mais iniciar aplicativos host por meio do Launch Services; execuções desabilitadas emitem menos intervalos dentro de rastreamentos de propriedade do chamador.
    • Evidência: #5335 adiciona negação de serviços de inicialização ao perfil macOS normal/PTY compartilhado. A cobertura nativa verifica a decisão do sistema operacional. A validação de entrada do sandbox retorna erros de ferramenta recuperáveis ​​sem engolir falhas do provedor. Falhas de montagem protegidas produzem novos erros redigidos. Os argumentos de origem e as exceções vinculadas permanecem intactos, mas o rastreamento de origem capturado é desanexado. A desativação do rastreamento abrange ferramentas retomadas e limpeza transmitida, enquanto ferramentas aprovadas retomadas usam o intervalo do agente. O exemplo em tempo real renderiza o conteúdo da ferramenta como texto literal.
    • Arquivos: src/agents/sandbox/sandboxes/unix_local.py, src/agents/sandbox/_mount_security.py, src/agents/run.py, src/agents/tracing/, examples/realtime/app/static/app.js.
    • Ação: mantenha a nota de comportamento do macOS e o crédito do repórter #5335 no comunicado. Não descreva o sandbox local como isolamento completo de host ou rede; use o Docker documentado ou alternativas hospedadas quando necessário. Não é necessário rastreamento ou migração de configuração em tempo real.
  1. Mantenha integrações aditivas e requisitos de dependência explícitos.

As dicas omitidas permanecem omitidas, portanto, aplique você mesmo os padrões do MCP instalados. Os metadados não são serializados na origem da ferramenta. Instale a versão SDK específica do exemplo e mantenha a propriedade separada de client/rastreamento. Atualize os arquivos de bloqueio do aplicativo ao adotar os extras alterados.

Rascunho das principais alterações

Principais mudanças

0.24.0 adiciona formatação de erros de função em toda a execução e anotações de descoberta de MCP e melhora a recuperação, segurança de sandbox e rastreamento. Esta versão secundária inclui alterações de compatibilidade para retornos de chamada de erro personalizados e alguns gráficos de agentes salvos. Revise os dois primeiros destaques antes de atualizar.

Destaques:

  • Atualize formatadores de erro personalizados. RunConfig.tool_error_formatter pode receber kind="tool_exception" e um error opcional. Manuseie o novo tipo ou retorne None para reter a mensagem padrão. Os manipuladores explícitos por ferramenta mantêm a precedência; os padrões não configurados permanecem inalterados.
  • Planeje atualizações em torno de execuções salvas. Novos snapshots RunState usam o esquema 1.21. Conclua os gráficos de agentes de mesmo nome mais antigos afetados em seu SDK original. Mantenha o código do agente e a ordem original dos ganchos inalterados. Use nomes de agentes exclusivos para novas execuções duráveis; renomear um gráfico salvo não é uma migração.
  • Recupere o trabalho concluído de forma mais confiável. O histórico de aprovação diferida, as saídas de ferramentas concluídas, os aliases e o estado de compactação sobrevivem aos caminhos de recuperação suportados. A compactação automática aguarda aprovações. Redis substitui o histórico atomicamente em clients independentes suportados. Os anexos de conversas respeitam o limite de solicitação de 20 itens. Reconcilie gravações parciais antes de tentar novamente.
  • Proteja a execução e exibição locais. Os comandos do sandbox do macOS negam solicitações de serviços de inicialização. As ferramentas sandbox se recuperam de argumentos de modelo inválidos. Erros de montagem protegidos preservam os dados de exceção do chamador enquanto desanexam o traceback capturado. A demonstração em tempo real exibe o conteúdo da ferramenta como texto.
  • Honrar as opções de rastreamento por meio de retomada e limpeza. A desativação do rastreamento por execução se aplica aos rastreamentos do chamador e as ferramentas de retomada aprovadas são anexadas ao período de agente retomado.
  • Use exemplos de integração e metadados mais ricos. As ferramentas MCP expõem o mcp_annotations opcional como dicas de descoberta. Novas receitas do Decisions demonstram classificação, roteamento e revisão de ferramentas com OpenAI >=3.26.0,<4. Eles usam um client separado, não um adaptador de modelo de Agente.
  • Atualizar bloqueios de dependência opcionais. O extra Temporal usa temporalio==1.34.0; o extra Vercel suporta vercel-sandbox>=0.7.0,<0.9. Os mínimos do Core Python e OpenAI SDK permanecem inalterados.

Obrigado a @masasron por relatar o problema de sandbox local do macOS corrigido em #5335.

Notas

  • Esta revisão cobre exatamente o candidato acima, incluindo seus metadados de lançamento. Alterações no principal, no candidato ou em sua linha de base API exigem uma nova verificação e aprovação da versão.

Release readiness review (v0.23.1 -> TARGET 0f44a46474d1f37a6b0ee006251a78bde4179bea)

This is a release readiness report done by $final-release-review skill.

Release intent

  • Review mode: final candidate, Release Please PR #5285.
  • Intended release: minor, 0.24.0.
  • Minimum required release type: minor. Existing tool error formatters receive a new category, and the RunState reader restricts some legacy agent identities.
  • Versioning verdict: compatible with the required minor release.

Release call

🟢 GREEN LIGHT TO SHIP. The prepared 0.24.0 candidate has no unresolved release blocker. Its compatibility changes have supported migration or fallback paths described below.

Scope summary

  • 111 files changed (+15,444/-1,412). Main areas: tool execution and failure recovery, durable RunState and session history, sandbox safety, tracing, examples, dependencies, and release metadata.
  • The candidate contains current main and #5335. Changes beyond main are limited to release-owned metadata.

Risk assessment (ordered by impact)

  1. Route affected saved runs to their original SDK and agent code.

    • Risk: 🟢 LOW, with a required upgrade precaution. Some previously readable checkpoints now fail safely instead of risking incorrect agent ownership.
    • Evidence: the writer advances from schema 1.18 to 1.21. The reader rejects certain older graphs with same-name non-root agents whose saved identity ordering could have depended on hook attributes, even when those attributes remained unchanged. New identity generation excludes all hook instance attributes and retains the hook type. Graphs distinguishable only by those attributes cannot be serialized. Other supported historical schemas remain readable.
    • Files: src/agents/run_state.py, src/agents/_run_state_agent_identity.py, tests/test_run_state.py.
    • Action: finish affected legacy tasks with the original SDK, unchanged agent definitions, and hook ordering used when the snapshot was written. Use unique agent names before starting new durable runs. Do not rename a stored graph or change its schema label to force migration. Older SDKs cannot read new 1.21 snapshots.

  2. Update existing custom tool error formatters for a third category.

    • Risk: 🟢 LOW, with an explicit migration for exhaustive callbacks. A formatter that treats every non-rejection as a missing tool can now return misleading text for a crashed function.
    • Evidence: ToolErrorFormatterArgs.kind adds "tool_exception"; the optional error field is appended. The run-wide callback now handles eligible decorated function failures. Explicit per-tool handlers, including explicit None or the default handler, keep precedence. Factory-created MCP and Agent.as_tool failures, timeouts, cancellation, and schema-backed program calls keep their separate behavior.
    • Files: src/agents/run_config.py, src/agents/tool.py, src/agents/run_internal/tool_execution.py, tests/test_tool_exception_formatter.py.
    • Action: handle "tool_exception" explicitly or return None for it to retain the default message. Keep exception details out of model-visible output unless deliberately sanitized. With no custom formatter, default behavior stays unchanged.

  3. Preserve completed work without promising automatic replay.

    • Risk: 🟢 LOW. Recovery retains more completed work, but applications must still reconcile external side effects and partially committed history.
    • Evidence: deferred approval history waits for the output guardrail boundary. For client-managed runs, accepted call/output pairs survive sibling or callback failures after input and tool-output guardrails permit publication. Server-managed conversations retain their separate recovery path. Pending writes retain session identity and compaction state. Automatic compaction waits for pending approvals; standalone Redis replacement uses a transaction. Conversations writes use batches of at most 20 items and can commit partially across requests.
    • Files: src/agents/run_internal/session_persistence.py, src/agents/run_internal/tool_execution.py, src/agents/memory/openai_conversations_session.py, src/agents/memory/openai_responses_compaction_session.py, src/agents/extensions/memory/redis_session.py.
    • Action: resume supported nonterminal failures with the original session backend and ID, using returned state and history instead of replaying completed tools. After a partial Conversations append, inspect and repair remote history before retrying; do not resend the full list while an earlier part remains stored. Coordinate other writers; Redis atomic replacement does not prevent stale compaction across processes. Redis Cluster reads and pops remain available, but transactional append, clear, and replacement require a supported backend. Terminal output failures do not become replayable.

  4. Retain the intended sandbox, tracing, and display boundaries.

    • Risk: 🟢 LOW. macOS local commands can no longer launch host applications through Launch Services; disabled runs emit fewer spans inside caller-owned traces.
    • Evidence: #5335 adds Launch Services denial to the shared normal/PTY macOS profile. Native coverage checks the operating-system decision. Sandbox input validation returns recoverable tool errors without swallowing provider failures. Protected mount failures produce fresh redacted errors. Source arguments and linked exceptions remain intact, but the caught source traceback is detached. Tracing opt-out covers resumed tools and streamed cleanup, while resumed approved tools use the agent span. The realtime example renders tool content as literal text.
    • Files: src/agents/sandbox/sandboxes/unix_local.py, src/agents/sandbox/_mount_security.py, src/agents/run.py, src/agents/tracing/, examples/realtime/app/static/app.js.
    • Action: retain the macOS behavior note and #5335 reporter credit in the release. Do not describe local sandboxing as complete host or network isolation; use the documented Docker or hosted alternatives where needed. No tracing or realtime configuration migration is required.

  5. Keep additive integrations and dependency requirements explicit.

    • Risk: 🟢 LOW. Consumers opting into metadata, examples, or extras must use their specific contracts.
    • Evidence: converted MCP tools expose copied mcp_annotations metadata; it does not grant approval or become a model tool schema. Decisions examples use a separate OpenAI client with named typed answers and conservative refusal handling. Core Python support remains >=3.10 and the OpenAI dependency remains >=3.0.0,<4. The examples require OpenAI >=3.26.0,<4; the Temporal extra pins 1.34.0 and the Vercel extra accepts >=0.7.0,<0.9.
    • Files: src/agents/mcp/util.py, src/agents/tool.py, examples/decisions/, pyproject.toml, uv.lock.
    • Action: treat MCP annotations as untrusted discovery hints. Non-MCP and unannotated tools return None; reads return copies. Omitted hints stay omitted, so apply the installed MCP defaults yourself. The metadata is not serialized into tool origin. Install the example-specific SDK version and retain separate client/tracing ownership. Refresh application lockfiles when adopting the changed extras.

Key Changes draft

Key Changes

0.24.0 adds run-wide function error formatting and MCP discovery annotations, and improves recovery, sandbox safety, and tracing. This minor release includes compatibility changes for custom error callbacks and some saved agent graphs. Review the first two highlights before upgrading.

Highlights:

  • Update custom error formatters. RunConfig.tool_error_formatter can receive kind="tool_exception" and an optional error. Handle the new kind or return None to retain the default message. Explicit per-tool handlers keep precedence; unconfigured defaults stay unchanged.
  • Plan upgrades around saved runs. New RunState snapshots use schema 1.21. Finish affected older same-name agent graphs on their original SDK. Keep the agent code and original hook ordering unchanged. Use unique agent names for new durable runs; renaming a saved graph is not a migration.
  • Recover completed work more reliably. Deferred approval history, completed tool outputs, aliases, and compaction state survive supported recovery paths. Automatic compaction waits for approvals. Redis replaces history atomically on supported standalone clients. Conversations appends respect the 20-item request limit. Reconcile partial writes before retrying.
  • Harden local execution and display. macOS sandbox commands deny Launch Services requests. Sandbox tools recover from invalid model arguments. Protected mount errors preserve caller exception data while detaching the caught traceback. The realtime demo displays tool content as text.
  • Honor tracing choices through resume and cleanup. Per-run tracing opt-out applies inside caller traces, and approved resumed tools attach to the resumed agent span.
  • Use richer integration examples and metadata. MCP tools expose optional mcp_annotations as discovery hints. New Decisions recipes demonstrate classification, routing, and tool review with OpenAI >=3.26.0,<4. They use a separate client, not an Agents model adapter.
  • Refresh optional dependency locks. The Temporal extra uses temporalio==1.34.0; the Vercel extra supports vercel-sandbox>=0.7.0,<0.9. Core Python and OpenAI SDK minimums are unchanged.

Thanks to @masasron for reporting the macOS local sandbox issue fixed in #5335.
