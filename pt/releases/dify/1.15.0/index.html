O que mudou

Melhorias de UX e UI

  • Aterrissagem/integração redesenhada para uma experiência de primeira execução mais fácil (#37433, #37844, #37800)
  • Navegação mais rápida — paleta "vá para qualquer coisa" aprimorada e entradas de pesquisa com foco automático (#32130, #37175)
  • Exclusões mais seguras — confirmação de um click antes de remover um aplicativo (#37263)
  • Editor de fluxo de trabalho mais limpo com painéis dobráveis (#37276)
  • Notificações mais claras — alertas consistentes que mostram erros longos por completo (#37382, #37581)
  • Mais acessível — dicas de permissão de plugins, menu de contato restaurado, link para pular navegação e aprimoramento de foco do teclado (#37310, #37774, #37644)

Novos recursos

difyctl — acione o Dify na linha de comando (Docs)

  • difyctl é um client de linha de comando para Dify: agora você pode executar aplicativos e fluxos de trabalho diretamente de seu terminal, para que agentes pessoais, scripts e pipelines de CI possam invocar fluxos de trabalho Dify sem abrir a interface da web (#37036)
  • Instale-o em qualquer plataforma (macOS, Linux, Windows) com um único comando e sem token de acesso — os binários são publicados como lançamentos públicos com verificação de soma de verificação (#37036, #37454)
  • Passe variáveis de ambiente com escopo definido para execuções da ferramenta CLI e obtenha mensagens de erro mais claras e consistentes (incluindo manipulação amigável de limite de taxa) tanto no difyctl quanto no /openapi/v1 API (#37324, #37285, #37313, #36896)

Veja CoT em Workflow e Chatflow e CLI

  • Fluxo de bate-papo/fluxo de trabalho agora pode transmitir o raciocínio do modelo em um painel dedicado de "pensamento" ao vivo, mantendo a resposta final limpa e legível. O raciocínio é preservado para que ainda esteja lá após a atualização da página, e o mesmo raciocínio é visível no CLI e nas visualizações de execução do fluxo de trabalho (#37460, #37828)

Formulários Human-in-the-Loop mais ricos

  • Quando um fluxo de trabalho faz uma pausa para solicitar a opinião de uma pessoa, o formulário agora pode incluir seleções suspensas e uploads de arquivos/vários arquivos — não apenas texto livre — para que as pessoas possam responder com opções estruturadas e anexos (#36322)

Suporte para modelos lentos e de longa duração

  • Os fluxos de trabalho agora podem usar modelos de geração que demoram muito para responder (como geração de imagem ou vídeo) por meio de um mecanismo de pesquisa: o nó espera pacientemente pelo resultado final em vez de atingir o tempo limite (#37462)

Conhecimento de planilhas mais avançadas

  • Imagens incorporadas em arquivos Excel agora são extraídas durante a importação de conhecimento, para que o conteúdo da planilha que depende de imagens (diagramas, capturas de tela, gráficos) não seja mais perdido (#37104)

Observabilidade mais profunda

  • Defina seu próprio ID de sessão de rastreamento para Phoenix para que os rastreamentos se alinhem com as sessões do seu aplicativo e siga as etapas de recuperação de documentos em rastreamentos para entender como os resultados RAG foram produzidos (#37056, #37283)

Aperfeiçoamento de autoria de fluxo de trabalho

  • Um nó inicial atualizado torna mais claro como um fluxo de trabalho começa, e um nó de saída mais inteligente oferece mais controle sobre o que um fluxo de trabalho retorna (#37348, #35511)
  • Erros mais amigáveis quando um ID de aplicativo ou espaço de trabalho está malformado, em vez de falhas confusas (#37212)

Instalações de plug-ins mais rápidas em determinadas regiões

  • O daemon do plugin agora detecta automaticamente sua região na inicialização e, onde a conectividade de rede com o PyPI é ruim, escolhe automaticamente um espelho de pacote próximo - portanto, a instalação de plugins é mais rápida e confiável sem qualquer configuração manual. Você ainda pode fixar um espelho específico se preferir (dify-plugin-daemon#750)

Atualizações de segurança

Esta versão corrige um problema de passagem de caminho no encaminhamento do plugin-daemon (cve-2026-41948).

Correções de bugs

  • HTTP de saída reforçado com tempos limite limitados para solicitações Firecrawl, Jina, Watercrawl, Nacos e Marketplace e saída de proxy SSRF padrão reforçada (#37638, #37637, #37515, #37444, #37424, #36332)
  • Corrigidos erros de armazenamento de vetores Lindorm causados pela atualização opensearch-py (#37862) e compatibilidade de credenciais Tongyi (#37942)
  • Cache de credenciais invalidado após atualização do OAuth (#37630)
  • Melhor tratamento de erros de execução de fluxo de trabalho, conversas validadas com entusiasmo para evitar travamentos e prevenção de interrupções herdadas de interromper execuções do GraphEngine (#37919, #37224, #37129)
  • Resolvido DetachedInstanceError por meio de refatoração de gerenciamento de sessão (#37847) e hidratação de estado de implantação estabilizada (#37818)
  • Foi corrigida a validação do comprimento da descrição da variável de conversação para evitar o truncamento do varchar(255) (#33038) e o chinês armazenado como Unicode para que a pesquisa funcione (#37446)
  • Numerosas UI da web e correções de polimento de acessibilidade/anel de foco

Melhorias

  • Gerenciamento de sessão refatorado entre serviços para aceitar db.session explicitamente por meio de injeção de dependência para consistência (#37639, #37832, #37695, #37694 e relacionados)
  • Digitação modernizada (remoção de type: ignore/cast redundantes, conversão de ABCs em Protocol, substituição de cadeias isinstance por match-case)
  • Latência de inicialização de fluxo de trabalho reduzida para Chatflow (#36773) e latência de encerramento de fluxo de trabalho reduzida para que a interrupção de uma execução tenha efeito mais rápido (#37106, #37129)
  • Dependências atualizadas para correções CVE (Bleach, PyJWT, starlette, grupo de armazenamento) (#37860, #37008, #37076, #37861)

Guia de atualização

Migração de tipo de modelo

[!IMPORTANTE]

Migração única de tipo de modelo legado para atualizações auto-hospedadas

Se esta implantação foi atualizada de uma versão Dify anterior a 1.15.0 e esta migração ainda não foi aplicada, execute-a após a atualização.

Esta migração não está incluída no flask db upgrade. Sem ele, os registros do modelo legado podem fazer com que as solicitações API relacionadas ao modelo falhem com erros, impedindo que os modelos afetados sejam carregados ou usados.

Faça backup do banco de dados antes de aplicar a migração. O comando é executado no modo de teste por padrão; revise a saída antes de executá-la novamente com --apply. A migração é idempotente e pode ser executada novamente com segurança.

Docker Compor

Execute a partir do diretório docker.

# Apply after reviewing the dry-run output
docker compose exec -T api flask data-migrate legacy-model-types --apply \
  > legacy-model-types-apply.jsonl

Implantação do código-fonte

Execute a partir da raiz do repositório após concluir flask db upgrade.

# Apply after reviewing the dry-run output
uv run --project api flask data-migrate legacy-model-types --apply \
  > legacy-model-types-apply.jsonl

Depois de aplicar a migração, execute o comando de simulação novamente. Se não reportar atualizações ou exclusões de linha adicionais, reinicie os serviços relevantes e verifique se os modelos existentes podem ser carregados e invocados com sucesso.

[!IMPORTANTE]

  • Esta versão inclui novas migrações de banco de dados. Execute-os como parte da atualização.
  • A atualização automática do plug-in agora está configurada por categoria de plug-in. Depois de executar o flask db upgrade, você também DEVE executar o flask backfill-plugin-auto-upgrade para migrar as configurações de atualização automática dos locatários existentes para o novo modelo com escopo de categoria. Se você pular esta etapa, as configurações de atualização automática do plug-in configuradas anteriormente pelos usuários poderão deixar de ter efeito.
  • Variáveis ​​de ambiente alteradas (19 adicionadas, 2 removidas, 1 modificada). Revise a seção Mudanças nas variáveis ​​​​de ambiente e atualize seu .env de acordo.
  • Docker Arquivos de configuração do Compose alterados. Se você mantiver um docker-compose.yaml personalizado, revise as alterações e reaplique as personalizações locais com cuidado.

New Features

difyctl — drive Dify from the command line (Docs)

  • difyctl is a command-line client for Dify: you can now run apps and workflows straight from your terminal, so personal agents, scripts, and CI pipelines can invoke Dify workflows without opening the web UI (#37036)
  • Install it on any platform (macOS, Linux, Windows) with a single command and no access token — binaries are published as public releases with checksum verification (#37036, #37454)
  • Pass scoped environment variables to CLI tool runs, and get clearer, consistent error messages (including friendly rate-limit handling) across both difyctl and the /openapi/v1 API (#37324, #37285, #37313, #36896)

See CoT in Workflow & Chatflow & CLI

  • Chat Flow / Workflow can now stream the model's reasoning into a dedicated live "thinking" panel while keeping the final answer clean and readable. The reasoning is preserved so it's still there after a page refresh, and the same reasoning is visible in CLI and workflow run previews (#37460, #37828)

Richer Human-in-the-Loop forms

  • When a workflow pauses to ask a person for input, the form can now include dropdown selects and file / multi-file uploads — not just free text — so people can answer with structured choices and attachments (#36322)

Support for slow, long-running models

  • Workflows can now use generation models that take a long time to respond (such as image or video generation) via a polling mechanism: the node patiently waits for the final result instead of timing out (#37462)

Knowledge from richer spreadsheets

  • Images embedded inside Excel files are now extracted during knowledge import, so spreadsheet content that relies on pictures (diagrams, screenshots, charts) is no longer lost (#37104)

Deeper observability

  • Set your own trace session id for Phoenix so traces line up with your application's sessions, and follow document-retrieval steps in traces to understand how RAG results were produced (#37056, #37283)

Workflow authoring polish

  • A refreshed start node makes it clearer how a workflow begins, and a smarter output node gives you more control over what a workflow returns (#37348, #35511)
  • Friendlier errors when an app or workspace ID is malformed, instead of confusing failures (#37212)

Faster plugin installs in certain regions

  • The plugin daemon now auto-detects your region at startup and, where network connectivity to PyPI is poor, automatically picks a nearby package mirror — so installing plugins is faster and more reliable without any manual setup. You can still pin a specific mirror if you prefer (dify-plugin-daemon#750)

Security Updates

This release fixes a path traversal issue in plugin-daemon forwarding (cve-2026-41948).

Bug Fixes

  • Hardened outbound HTTP with bounded timeouts for Firecrawl, Jina, Watercrawl, Nacos, and Marketplace requests, and hardened default SSRF proxy egress (#37638, #37637, #37515, #37444, #37424, #36332)
  • Fixed Lindorm vector store errors caused by the opensearch-py update (#37862) and Tongyi credential compatibility (#37942)
  • Invalidated credential cache after OAuth refresh (#37630)
  • Improved workflow execution error handling, eagerly validated conversations to prevent hanging, and prevented legacy stop from interrupting GraphEngine runs (#37919, #37224, #37129)
  • Resolved DetachedInstanceError via session management refactoring (#37847) and stabilized deployment state hydration (#37818)
  • Fixed conversation variable description length validation to prevent varchar(255) truncation (#33038) and stored Chinese as unicode so search works (#37446)
  • Numerous web UI and accessibility/focus-ring polish fixes

Improvements

  • Refactored session management across services to accept db.session explicitly via dependency injection for consistency (#37639, #37832, #37695, #37694, and related)
  • Modernized typing (removed redundant type: ignore/cast, converted ABCs to Protocol, replaced isinstance chains with match-case)
  • Reduced workflow startup latency for Chatflow (#36773) and lowered workflow termination latency so stopping a run takes effect faster (#37106, #37129)
  • Upgraded dependencies for CVE fixes (Bleach, PyJWT, starlette, storage group) (#37860, #37008, #37076, #37861)

Upgrade Guide

Model Type Migration

[!IMPORTANT]

One-time legacy model type migration for self-hosted upgrades

If this deployment was upgraded from a Dify version earlier than 1.15.0 and this migration has not already been applied, run it after upgrading.

This migration is not included in flask db upgrade. Without it, legacy model records can cause model-related API requests to fail with errors, preventing affected models from being loaded or used.

Back up the database before applying the migration. The command runs in dry-run mode by default; review the output before rerunning it with --apply. The migration is idempotent and can be safely rerun.

Docker Compose

Run from the docker directory.

# Apply after reviewing the dry-run output
docker compose exec -T api flask data-migrate legacy-model-types --apply \
  > legacy-model-types-apply.jsonl

Source Code Deployment

Run from the repository root after completing flask db upgrade.

# Apply after reviewing the dry-run output
uv run --project api flask data-migrate legacy-model-types --apply \
  > legacy-model-types-apply.jsonl

After applying the migration, run the dry-run command again. If it reports no additional row updates or deletions, restart the relevant services and verify that existing models can be loaded and invoked successfully.

[!IMPORTANT]

  • This release includes new database migrations. Run them as part of the upgrade.
  • Plugin auto-upgrade is now configured per plugin category. After running flask db upgrade, you MUST also run flask backfill-plugin-auto-upgrade to migrate existing tenants' auto-upgrade settings into the new category-scoped model. If you skip this step, plugin auto-upgrade settings users previously configured may stop taking effect.
  • Environment variables changed (19 added, 2 removed, 1 modified). Review the Environment Variable Changes section and update your .env accordingly.
  • Docker Compose configuration files changed. If you maintain a customized docker-compose.yaml, review the changes and re-apply local customizations carefully.
