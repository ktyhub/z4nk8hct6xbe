#difícil 1.16.0-rc1

Apresentando o Agente Dify (Experimental): Uma nova experiência de agente no Dify

[!AVISO] Você deve fornecer serviços de Agente Dify ⚠️apenas para usuários trusted e não maliciosos⚠️.

Como muitos de vocês sabem, o paradigma do agente LLM baseado em shell trouxe um grande salto nas capacidades dos agentes e mudou a forma como pensamos sobre os agentes. Enquanto isso, as Skills fornecem uma maneira padronizada de empacotar e distribuir recursos, facilitando a construção de agentes poderosos.

Hoje, estamos lançando experimentalmente o Dify Agent. Como outros agentes líderes, ele é executado em uma sandbox Linux. Esta versão inclui:

  • Um construtor para criar Agentes Dify

    • Você pode construir Agentes Dify por meio da IU: definir um prompt base, fazer upload de habilidades e arquivos e conectar ferramentas e conhecimento do ecossistema Dify.
    • Também fornecemos um agente que ajuda você a construir Agentes Dify. Por meio de conversação, ele pode configurar o ambiente sandbox Linux, instalar os pacotes necessários e criar novas habilidades e arquivos que seu agente Dify pode usar posteriormente.

  • Integração do Dify Workflow para o Dify Agent

    • Você pode usar um Dify Agent existente em um fluxo de trabalho Dify ou criar temporariamente um Dify Agent inline. Ele executará a tarefa definida pelo nó do fluxo de trabalho, gerará a saída necessária e a passará para o próximo nó.

  • Uma nova experiência de aplicativo da web

    • O Dify Agent que você cria pode ser publicado e usado como um aplicativo da web. Embora a experiência do usuário permaneça familiar, agora ela é desenvolvida pelo Dify Agent.

Documentos: https://docs.dify.ai/en/self-host/use-dify/build/new-agent/overview

Limitações

Observe que na versão experimental atual, todos os agentes Dify são executados na mesma sandbox. Isso significa:

  • Em circunstâncias normais, cada Agente Dify configura seu ambiente e executa tarefas em seu próprio espaço de trabalho sem interferir nos outros.
  • Porém, com instruções simples, qualquer Agente Dify pode ler ou interferir nos ambientes e dados de outros Agentes Dify, incluindo dados do usuário.

O isolamento estrito será implementado em uma versão futura. Por enquanto,

[!AVISO] Você deve fornecer serviços de Agente Dify ⚠️apenas para usuários trusted e não maliciosos⚠️.

Da mesma forma, como o Dify Agent ainda não está totalmente pronto, você pode descobrir que alguns recursos não estão disponíveis para o Dify Agent. Por exemplo, a exportação DSL do fluxo de trabalho Dify não está disponível quando o fluxo de trabalho contém nós que fazem referência ao Agente Dify.

Guia de atualização

[!IMPORTANTE]

  • Esta versão inclui novas migrações de banco de dados. Execute-os como parte da atualização.
  • Variáveis ​​de ambiente alteradas. Revise a seção Mudanças nas variáveis ​​de ambiente e atualize seu .env de acordo.
  • Docker Arquivos de configuração do Compose alterados. Se você mantiver um docker-compose.yaml personalizado, revise as alterações e reaplique as personalizações locais com cuidado.

Docker Compor implantações

  1. Faça backup de seus arquivos YAML e env personalizados do docker-compose. 
    cd dockercp docker-compose.yaml docker-compose.yaml.$(date +%s).bakcp .env .env.$(date +%s).bak 2>/dev/null || true
  2. Obtenha o código mais recente para a versão 1.16.0-rc1. 
    git fetch --tagsgit checkout 1.16.0-rc1
  3. Pare os serviços (execute dentro do diretório docker). 
    docker compose down
  4. Faça backup dos dados. 
    tar -cvf volumes-$(date +%s).tgz volumes
  5. Revise quaisquer alterações no arquivo env e aplique novamente as personalizações locais.
  6. Atualizar serviços. 
    docker compose up -d

Implantações de código-fonte

  1. Pare o servidor API, o Worker e o servidor front-end da Web.
  2. Obtenha o código mais recente para a versão 1.16.0-rc1. 
    git fetch --tagsgit checkout 1.16.0-rc1
  3. Atualize as dependências do Python. 
    cd apiuv sync
  4. Execute migrações de banco de dados. 
    uv run flask db upgrade
  5. Reinicie o servidor API, o Worker e o servidor front-end da Web. Para experimentar o novo recurso de agente, você também precisa iniciar o dify-agent e o shellctl. Importante: shellctl não inclui autenticação integrada — por segurança, é altamente recomendável executá-lo dentro de um contêiner.

dify 1.16.0-rc1

Introducing Dify Agent (Experimental): A New Agent Experience in Dify

[!WARNING] You should provide Dify Agent services ⚠️only to trusted, non-malicious users⚠️.

As many of you know, the shell-based LLM agent paradigm has brought a major leap in agent capabilities and changed how we think about agents. Meanwhile, Skills provide a standardized way to package and distribute capabilities, making it easier to build powerful agents.

Today, we are experimentally launching Dify Agent. Like other leading agents, it runs in a Linux sandbox. This release includes:

  • A builder for creating Dify Agents

    • You can build Dify Agents through the UI: set a base prompt, upload Skills and files, and connect tools and knowledge from the Dify ecosystem.
    • We also provide an agent that helps you build Dify Agents. Through conversation, it can configure the Linux sandbox environment, install required packages, and create new Skills and files that your Dify Agent can use later.

  • Dify Workflow integration for Dify Agent

    • You can use an existing Dify Agent in a Dify Workflow, or temporarily create an inline Dify Agent. It will execute the task defined by the workflow node, generate the required output, and pass it to the next node.

  • A new web app experience

    • The Dify Agent you build can be published and used as a web app. While the user experience remains familiar, it is now powered by Dify Agent.

Docs: https://docs.dify.ai/en/self-host/use-dify/build/new-agent/overview

Limitations

Please note that in the current experimental release, all Dify Agents run in the same sandbox. This means:

  • Under normal circumstances, each Dify Agent configures its environment and executes tasks within its own workspace without interfering with others.
  • However, with simple instructions, any Dify Agent can read or interfere with the environments and data of other Dify Agents, including user data.

Strict isolation will be implemented in a future release. For now,

[!WARNING] You should provide Dify Agent services ⚠️only to trusted, non-malicious users⚠️.

Similarly, because Dify Agent is not fully ready yet, you may find that some features are not available for Dify Agent. For example, Dify Workflow DSL export is unavailable when the workflow contains nodes that reference Dify Agent.

Upgrade Guide

[!IMPORTANT]

  • This release includes new database migrations. Run them as part of the upgrade.
  • Environment variables changed. Review the Environment Variable Changes section and update your .env accordingly.
  • Docker Compose configuration files changed. If you maintain a customized docker-compose.yaml, review the changes and re-apply local customizations carefully.

Docker Compose Deployments

  1. Back up your customized docker-compose YAML and env files. 
    cd dockercp docker-compose.yaml docker-compose.yaml.$(date +%s).bakcp .env .env.$(date +%s).bak 2>/dev/null || true
  2. Get the latest code for the 1.16.0-rc1 release. 
    git fetch --tagsgit checkout 1.16.0-rc1
  3. Stop the services (run inside the docker directory). 
    docker compose down
  4. Back up data. 
    tar -cvf volumes-$(date +%s).tgz volumes
  5. Review any env file changes and re-apply local customizations.
  6. Upgrade services. 
    docker compose up -d

Source Code Deployments

  1. Stop the API server, Worker, and Web frontend server.
  2. Get the latest code for the 1.16.0-rc1 release. 
    git fetch --tagsgit checkout 1.16.0-rc1
  3. Update Python dependencies. 
    cd apiuv sync
  4. Run database migrations. 
    uv run flask db upgrade
  5. Restart the API server, Worker, and Web frontend server. To experiment with the new agent feature, you also need to start dify-agent and shellctl. Important: shellctl does not include built‑in authentication — for security, it is strongly recommended to run it inside a container.
