dify 1.20.0

#difícil 1.20.0 Dify 1.20.0 mantém seus rastreamentos fluindo e suas bases de conhecimento mais seguras. Exporte rastreamentos para qualquer coletor OpenTelemetry, mantenha o Langfuse funcionando após a desativação do endpoint de ingestão herdado e verifique se há malware nos arquivos de conhecimento carregados antes de serem indexados. Os fluxos de bate-papo podem mostrar a atividade da ferramenta do agente conforme ela acontece, e os tokens de acesso pessoal permitem que scripts e agentes chamem o Dify OpenAPI em seu nome. O daemon de plug-in incluído foi atualizado para 0.6.15-local. Novos recursos · Alterações de configuração e integração · Migrações de banco de dados · Guia de atualização

Novos recursos

Novo HITL: inclua aprovações nas ferramentas de mensagens da sua equipe

Integre a revisão humana em seus fluxos de trabalho por e-mail e nas ferramentas de mensagens que sua equipe já usa. O novo HITL introduz canais compartilhados, contatos centralizados, modelos de notificação e formulários de aprovação verificados, permitindo que sua equipe configure destinatários uma vez e reutilize-os em nós de entrada humana, e agora está habilitado por padrão (NEXT_PUBLIC_ENABLE_HITL_IM=true). (#44864, #45945)

  • Alcance os aprovadores onde eles trabalham. Configure o e-mail e uma plataforma de mensagens instantâneas (Slack, Feishu/Lark, Microsoft Teams, DingTalk ou WeCom) para entregar solicitações de revisão de fluxo de trabalho por meio dos canais existentes da sua equipe.
  • Gerencie destinatários em Contatos. Sincronize diretórios de mensagens instantâneas e selecione aprovadores em uma lista de contatos compartilhada. Os fluxos de trabalho também podem endereçar o iniciador ou usar destinatários de email únicos e dinâmicos.
  • Aprovar em cartões ou formulários. Os destinatários podem revisar solicitações diretamente em cartões de mensagens instantâneas compatíveis ou abrir formulários independentes, com login Dify ou verificação de e-mail para verificar sua identidade.
  • Personalize notificações com contexto de fluxo de trabalho. Use modelos e variáveis ​​de fluxo de trabalho para incluir contexto essencial em assuntos e órgãos de notificação.
  • Teste e rastreie a entrega. Envie notificações de teste para verificar sua configuração e inspecione os registros de entrega para solucionar problemas de solicitações que não chegaram conforme o esperado.
  • Adote o novo HITL em fluxos de trabalho existentes. Use a migração opcional para atualizar nós legados de entrada humana quando seu fluxo de trabalho estiver pronto. Os requisitos de implantação estão listados em Alterações de configuração e integração.

Exporte traços para qualquer coletor OpenTelemetry

Traga os rastreamentos de execução do Dify para sua pilha de observabilidade existente. O novo provedor OpenTelemetry exporta rastreamentos de aplicativos e agentes para qualquer coletor compatível, permitindo rastrear etapas de fluxo de trabalho, chamadas de modelo e atividades de ferramentas juntos em sua plataforma preferida. Use esses rastreamentos para inspecionar a execução de solicitações e diagnosticar falhas sem exigir uma integração Dify específica do fornecedor. (#45659) O rastreamento do Langfuse agora oferece suporte ao Langfuse v4 e ao atual serviço de ingestão do Langfuse Cloud. As configurações existentes do Langfuse continuam funcionando. (#45606)

[!IMPORTANTE] O Langfuse Cloud retirou seu endpoint de ingestão legado em 16 de novembro de 2026, e o Langfuse v4 auto-hospedado rejeita eventos enviados a ele. Atualize para 1.20.0 para continuar fornecendo rastreamentos para essas implantações.

Verificar uploads de conhecimento em busca de malware

Proteja suas bases de conhecimento verificando se há malware nos arquivos enviados antes de serem extraídos ou indexados. Quando ativado (FILE_SCAN_ENABLED=true), os proprietários e administradores do espaço de trabalho podem configurar scanners uma vez em Integrações → Verificação de segurança de arquivos e, em seguida, definir como cada base de conhecimento os utiliza. Os scanners suportados incluem Cloudmersive, Scanii, OPSWAT MetaDefender Cloud e um Custom Endpoint. (#46090, #46492)

  • Escolha a proteção por base de conhecimento. Selecione um scanner e configure o comportamento de fallback quando a verificação não estiver disponível ou um arquivo não puder ser verificado.
  • Proteja uploads de conhecimento no Dify. A verificação abrange bases de conhecimento clássicas, fontes de arquivos locais do RAG Pipeline e uploads da base de conhecimento do agente.
  • Veja por que os arquivos foram bloqueados. As falhas de verificação aparecem na lista de documentos para revisão.

Observe as ferramentas do agente funcionarem no Chatflow

Quando um Chatflow delega tarefas a um nó do Agente v2 (requer NEXT_PUBLIC_ENABLE_AGENT_V2_IN_CHATFLOW=true), os usuários agora podem ver quais ferramentas ele invoca em tempo real. A atividade da ferramenta aparece junto com a resposta nas visualizações e nos chats publicados, facilitando o acompanhamento do progresso do Agente. Expanda qualquer cartão de ferramenta para inspecionar o que foi solicitado e devolvido. (#46220)

Automatize chamadas OpenAPI com tokens de acesso pessoal

Conceda acesso a scripts, trabalhos de CI e agentes pessoais ao Dify OpenAPI em seu nome sem compartilhar sua sessão do console. Crie um token de acesso pessoal na página Conta e defina-o para espaços de trabalho e recursos específicos. Você pode definir uma data de expiração opcional, atualizar seu escopo à medida que sua automação evolui ou revogá-la quando não for mais necessária. (#45540, #46606)

Escolha fontes de conhecimento GitHub em uma árvore

Navegue e selecione o conteúdo GitHub que deseja adicionar a uma base de conhecimento a partir de uma árvore expansível de repositórios, diretórios, problemas e solicitações pull. Explore a estrutura de origem e escolha as páginas exatas para importar, esteja você criando uma nova base de conhecimento ou adicionando uma fonte a uma já existente. (#45990)

Pesquise e navegue em telas menores

Pesquise conteúdo e restrinja resultados usando escopos selecionáveis em Goto Anything. Em telas menores, a pesquisa e a navegação são abertas em gavetas para preservar espaço para a página atual. (#45675, #45650) Links diretos agora podem abrir fluxos de criação de aplicativos ou modelos em branco do Studio. (#45717)

Descrições e metadados de conhecimento mais flexíveis

  • Descrições mais longas da base de conhecimento. Limites maiores de comprimento de descrição permitem que você forneça mais contexto para cada base de conhecimento. (#45075)
  • Metadados de conhecimento externo. A recuperação de conhecimento externo agora retorna metadados de documentos junto com o conteúdo. (#22496)

Melhorias

** Menor sobrecarga de banco de dados e inicialização. ** As atualizações de execução de nós evitam recarregar linhas armazenadas, as políticas de credenciais são avaliadas uma vez por configuração do provedor, os padrões do modelo usam sessões de curta duração e as chamadas incorporadas não mantêm mais uma sessão de banco de dados aberta. As dependências de recursos da Web também carregam mais lentamente. (#46410, #46441, #45806, #45788, #46145) Falhas de documentos mais claras e layouts mais estáveis. Os documentos de conhecimento agora relatam motivos de falha e estágios de processamento específicos. As caixas de diálogo se adaptam a janelas de visualização estreitas e mantêm ciclos de vida consistentes entre contas, conhecimentos, aplicativos, habilidades e fluxos de trabalho. As páginas de autenticação carregam mais rápido, cabem em telas menores e mantêm o foco do teclado acessível. Os controles segmentados são animados suavemente, preservando layouts compactos e respeitando as preferências de movimento reduzido. (#45128, #46487, #45686, #45668, #45634, #45600, #45640, #45974)

Correções de bugs

  • Pré-visualizações de arquivos e links assinados mais seguros. Pré-visualizações de SVG inline no sandbox e verificação da assinatura original antes de renovar links de arquivos expirados. (#46505)
  • Proteção de acesso mais forte. Edite detalhes de novas tentativas de nó de fluxos públicos, evite a reutilização de retorno de chamada OAuth, imponha permissões de função de membro e exclua o vetor de escopo para o conjunto de dados de destino. (#46517, #46001, #46053, #45586)
  • Atualizações de dependência de segurança. Atualize github.com/klauspost/compress em dify-agent-runtime para o endereço CVE-2026-116591 e atualize Node.js em imagens de tempo de execução para a versão de segurança 24.22.3. (#46544, #46206, #46064)
  • Fluxos de trabalho de bloqueio confiáveis. Libere conexões de banco de dados antes da execução e retorne falhas de preparação imediatamente, evitando o esgotamento do pool de conexões e solicitações suspensas que aguardam até o tempo limite. (#46254)
  • Trabalhadores mais estáveis. Resolva o loop ocupado Redis BRPOP e evite verificações de atualização de plug-in sobrepostas, limitando a simultaneidade em 20 verificações entre trabalhadores. (#45940, #46500)
  • Conclua streams do Chatflow. Feche os streams corretamente após respostas diretas e redefina o orçamento de reconexão quando um stream for retomado. (#45552, #46110)
  • Execução correta do agente. Preserva chamadas paralelas para a mesma ferramenta de plug-in, transmite entradas de aplicativo declaradas para execuções do agente e entrega imagens carregadas para modelos de visão. (#45207, #45425, #45745)
  • Recuperação de conhecimento precisa. Restaure os resultados de palavras-chave/híbridos do Weaviate retornando pontuações BM25 e mantenha a incorporação de vetores alinhados quando um item de lote for descartado. (#45642, #45569)
  • Ferramentas API personalizadas confiáveis. Resolva variáveis de servidor OpenAPI, parâmetros de caminho com codificação percentual e suporte a uniões anuláveis OpenAPI 3.1. (#46504, #45965, #45895)

Proxy reverso e configuração do trabalhador

  • Nova rota API: No modo WEBHOOK, encaminhe /callbacks/human-input/v2/im/ para o serviço API (api:5001 no Docker Compose), preservando o caminho da solicitação, o corpo bruto e os cabeçalhos de assinatura do provedor. O modelo nginx incluído já inclui esta regra; adicione seu equivalente ao nginx personalizado, Ingress ou outras configurações de proxy reverso. Configure o provedor de mensagens instantâneas com o URL de retorno de chamada gerado pelo canal. (#44864)
  • Novas filas do Celery: Inclui human_input_delivery para processamento de retorno de chamada de mensagens instantâneas assíncrono e atualizações de cartão pós-envio, e human_input_contact_sync para sincronização de diretório de contatos de mensagens instantâneas. A lista de trabalhadores Docker padrão inclui ambos. As listas personalizadas CELERY_QUEUES, CELERY_WORKER_QUEUES ou Celery --queues devem fornecer um consumidor ativo para cada fila junto com as assinaturas existentes. (#44864)

Arquivos de ambiente Docker

docker/envs/core-services/shared.env não está mais carregado. Mova as configurações comuns de API, trabalhador e Beat para api-worker.env antes de recriar contêineres. Preserve quaisquer configurações específicas do serviço no arquivo de substituição usado por esse serviço. (#46497) URLs públicos são compartilhados pela Web, API e trabalhadores por meio do novo envs/core-services/urls.defaults e do urls.env opcional: *CONSOLE_API_URL *CONSOLE_WEB_URL *SERVICE_API_URL *APP_API_URL *APP_WEB_URL Defina URLs base acessíveis pelo navegador sem os sufixos /console/api, /api ou /v1. Valores explícitos em urls.env substituem configurações de URL específicas do serviço; root docker/.env substitui ambos. O SERVER_CONSOLE_API_URL interno da Web permanece no web.env. Isso também resolve um problema em que links de ícones gerados apontavam para 127.0.0.1:5001 em novas instalações. (#46497)

Guia de atualização

[!IMPORTANTE] Remova as configurações do shared.env desativado antes de recriar os contêineres. Revise URLs públicos, roteamento de retorno de chamada HITL personalizado e assinaturas de trabalho. As implantações do OpenShell exigem uma atualização de gateway compatível e não restauram mais os Home Snapshots. O daemon de plug-in incluído foi atualizado para 0.6.15-local.

Preparar a implantação

  1. Faça backup de dados e configuração. Faça backup de seu banco de dados, dados de armazenamento de vetores, arquivos carregados, armazenamento de daemon de plug-in, armazenamento de espaço de trabalho do agente, segredos de implantação e arquivos de ambiente. Agende uma janela de manutenção para uma atualização de pilha única.
  2. Atualize os componentes Dify juntos. Use imagens correspondentes de 1.20.0 API, trabalhador, Web, back-end de agente e sandbox local, juntamente com o daemon de plug-in 0.6.15-local. Mantenha SECRET_KEY, qualquer PASSWORD_PEPPER configurado e o token de autenticação de sandbox local inalterados. Os tokens de acesso pessoal dependem do SECRET_KEY; certifique-se de que o mesmo valor seja usado em todas as réplicas API. Se estiver atualizando de uma versão anterior à 1.19.0, siga também o Guia de atualização da 1.19.0.
  3. Migrar shared.env. Se envs/core-services/api-worker.env não existir, renomeie envs/core-services/shared.env para esse caminho. Se ambos existirem, mescle apenas as configurações ausentes e preserve os valores api-worker.env existentes, incluindo atribuições vazias intencionais. Mantenha as configurações específicas do serviço no arquivo de substituição de serviço apropriado. As implantações sem shared.env não requerem migração.
  4. Consolide URLs públicos. Crie envs/core-services/urls.env a partir de urls.defaults somente se ele ainda não existir. Mova os valores de URL público pretendidos para lá e remova atribuições duplicadas de arquivos de serviço individuais. Os valores raiz .env existentes mantêm a precedência. Mantenha o roteamento interno da Web API no web.env.
  5. Aplique alterações de ambiente, rota e fila. Siga Alterações de configuração e integração, incluindo as novas configurações de HITL, rota de retorno de chamada de IM e ambas as filas do Celery.
  6. Deixe a inicialização do armazenamento do plugin ser executada. init_permissions agora também prepara ./volumes/plugin_daemon para o UID 1001 do daemon, e o daemon espera que ele seja concluído. Recrie a implantação com docker compose up -d para que o serviço init seja executado. (#45615)

Implantações OpenShell

Atualize o gateway OpenShell e o SDK juntos para 0.1.3 ou posterior dentro da linha 0.1.x suportada e atualize o Dify API e o Agent Backend juntos. O gateway deve suportar exposição de serviço nativo e passagem de portador, preservando o token de autorização por sandbox derivado de DIFY_AGENT_OPENSHELL_SHELLCTL_AUTH_TOKEN. Mantenha esse segredo mestre idêntico nas réplicas do Agent Backend. (#45862) Crie a imagem de tempo de execução do OpenShell a partir da verificação de lançamento e configure DIFY_AGENT_OPENSHELL_SANDBOX_IMAGE para a referência de imagem exata disponível para os nós de computação do gateway. A imagem deve incluir shellctl e iproute2; uma imagem de tempo de execução em cache mais antiga pode não ter as ferramentas de rede necessárias. Ao atualizar do token shellctl compartilhado anterior em toda a implantação, gere um novo segredo mestre de alta entropia e atualize todas as réplicas de back-end do agente juntas. Drene o trabalho ativo e, em seguida, pare e reinicie os sandboxes existentes para que o shellctl seja reiniciado com a credencial derivada. A readquirição de um sandbox já íntegro não atualiza sua credencial. Os Home Snapshots de volume compartilhado e DIFY_AGENT_OPENSHELL_SHARED_MOUNT_PATH foram removidos. Os sandboxes em execução existentes mantêm seu estado durante os ciclos de parada/reinicialização, enquanto as vinculações recém-criadas iniciam na página inicial padrão da imagem. DIFY_AGENT_OPENSHELL_DRIVER_CONFIG agora é opcional. Revise o guia de implantação do OpenShell, incluindo seus requisitos de imagem de tempo de execução, antes de atualizar. Outros back-ends de sandbox não são afetados.

Docker Compor

Depois que a tag e as imagens 1.20.0 forem publicadas, interrompa a implantação normalmente, mude para a versão, migre os arquivos de configuração local e, em seguida, extraia e inicie os serviços atualizados:

cd dify/docker
docker compose stop -t -1
git fetch --tags
git checkout 1.20.0
# Migrate shared.env, public URLs, and any custom proxy/worker configuration.
docker compose pull
docker compose up -d

Mantenha as migrações de inicialização do API habilitadas (MIGRATION_ENABLED=true) ou aplique a cadeia de migração completa por meio de seu processo de migração gerenciado antes de iniciar novos trabalhadores. Use docker compose up -d após alterar os arquivos de ambiente; uma reinicialização simples não os recarrega.

Implantações de origem

Use Python 3.13, Node.js 24.22.3 ou posterior na linha 24.x e pnpm 12.18.0. Após interromper os serviços e mudar para a versão, execute os seguintes comandos na raiz do repositório:

uv sync --project api --frozen
uv run --directory api flask db upgrade
pnpm install --frozen-lockfile

Reconstrua a Web e reinicie o API, os trabalhadores, o agendador e os serviços do Agente da mesma versão. Atualize as dependências bloqueadas do back-end do agente autônomo se ele for implantado separadamente. Preserve as assinaturas de trabalho existentes e adicione as duas filas HITL quando necessário. dify 1.20.0

Dify 1.20.0 keeps your traces flowing and your knowledge bases safer. Export traces to any OpenTelemetry collector, keep Langfuse working after its legacy ingestion endpoint retirement, and scan uploaded knowledge files for malware before they are indexed. Chatflows can show Agent tool activity as it happens, and personal access tokens let scripts and agents call the Dify OpenAPI on your behalf. The bundled plugin daemon is upgraded to 0.6.15-local.

New Features · Configuration and Integration Changes · Database Migrations · Upgrade Guide

New Features

New HITL: bring approvals into your team's messaging tools

Integrate human review into your workflows via email and the messaging tools your team already uses. New HITL introduces shared channels, centralized contacts, notification templates, and verified approval forms—allowing your team to configure recipients once and reuse them across Human Input nodes, and is now enabled by default (NEXT_PUBLIC_ENABLE_HITL_IM=true). (#44864, #45945)

  • Reach approvers where they work. Configure email and an IM platform—Slack, Feishu/Lark, Microsoft Teams, DingTalk, or WeCom—to deliver workflow review requests through your team's existing channels.
  • Manage recipients in Contacts. Sync IM directories and select approvers from a shared contact list. Workflows can also address the initiator or use one-time and dynamic email recipients.
  • Approve in cards or forms. Recipients can review requests directly in supported IM cards or open standalone forms, with Dify login or email verification to verify their identity.
  • Customize notifications with workflow context. Use templates and workflow variables to include essential context in notification subjects and bodies.
  • Test and track delivery. Send test notifications to verify your setup and inspect delivery records to troubleshoot requests that did not arrive as expected.
  • Adopt New HITL in existing workflows. Use opt-in migration to upgrade legacy Human Input nodes when your workflow is ready.

Deployment requirements are listed under Configuration and Integration Changes.

Export traces to any OpenTelemetry collector

Bring Dify execution traces into your existing observability stack. The new OpenTelemetry provider exports app and Agent traces to any compatible collector, allowing you to track workflow steps, model calls, and tool activity together in your preferred platform. Use these traces to inspect request execution and diagnose failures without requiring a vendor-specific Dify integration. (#45659)

Langfuse tracing now supports Langfuse v4 and the current Langfuse Cloud ingestion service. Existing Langfuse configurations continue to work. (#45606)

[!IMPORTANT] Langfuse Cloud retired its legacy ingestion endpoint on November 16, 2026, and self-hosted Langfuse v4 rejects events sent to it. Upgrade to 1.20.0 to keep delivering traces to those deployments.

Scan knowledge uploads for malware

Protect your knowledge bases by scanning uploaded files for malware before they are extracted or indexed. When enabled (FILE_SCAN_ENABLED=true), workspace owners and admins can configure scanners once under Integrations → File Security Scan, then define how each knowledge base uses them. Supported scanners include Cloudmersive, Scanii, OPSWAT MetaDefender Cloud, and a Custom Endpoint. (#46090, #46492)

  • Choose protection per knowledge base. Select a scanner and configure fallback behavior when scanning is unavailable or a file cannot be scanned.
  • Protect knowledge uploads across Dify. Scanning covers classic knowledge bases, RAG Pipeline local-file sources, and Agent Knowledge Base uploads.
  • See why files were blocked. Scan failures appear in the document list for review.

Watch Agent tools work in Chatflow

When a Chatflow delegates tasks to an Agent v2 node (requires NEXT_PUBLIC_ENABLE_AGENT_V2_IN_CHATFLOW=true), users can now see which tools it invokes in real time. Tool activity appears alongside the response in both previews and published chats, making it easier to follow the Agent's progress. Expand any tool card to inspect what it requested and returned. (#46220)

Automate OpenAPI calls with personal access tokens

Grant scripts, CI jobs, and personal agents access to the Dify OpenAPI on your behalf without sharing your Console session. Create a personal access token from your Account page and scope it to specific workspaces and resources. You can set an optional expiration date, update its scope as your automation evolves, or revoke it when it is no longer needed. (#45540, #46606)

Choose GitHub knowledge sources from a tree

Browse and select the GitHub content you want to add to a knowledge base from an expandable tree of repositories, directories, issues, and pull requests. Explore the source structure and pick the exact pages to import, whether you are creating a new knowledge base or adding a source to an existing one. (#45990)

Search and navigate on smaller screens

Search across content and narrow results using selectable scopes in Goto Anything. On smaller screens, search and navigation open in drawers to preserve space for the current page. (#45675, #45650)

Direct links can now open Studio's blank-app or template creation flows. (#45717)

More flexible knowledge descriptions and metadata

  • Longer knowledge base descriptions. Increased description length limits allow you to provide more context for each knowledge base. (#45075)
  • External knowledge metadata. External knowledge retrieval now returns document metadata alongside content. (#22496)

Improvements

Lower database and startup overhead. Node execution updates avoid reloading stored rows, credential policies are evaluated once per provider configuration, model defaults use short-lived sessions, and embedding calls no longer hold open a database session. Web feature dependencies also load more lazily. (#46410, #46441, #45806, #45788, #46145)

Clearer document failures and steadier layouts. Knowledge documents now report specific failure reasons and processing stages. Dialogs adapt to narrow viewports and maintain consistent lifecycles across accounts, knowledge, apps, Skills, and workflows. Authentication pages load faster, fit smaller screens, and keep keyboard focus accessible. Segmented controls animate smoothly while preserving compact layouts and respecting reduced-motion preferences. (#45128, #46487, #45686, #45668, #45634, #45600, #45640, #45974)

Bug Fixes

  • Safer file previews and signed links. Sandbox inline SVG previews and verify the original signature before renewing expired file links. (#46505)
  • Stronger access protection. Redact node-retry details from public streams, prevent OAuth callback reuse, enforce member-role permissions, and scope vector deletion to the target dataset. (#46517, #46001, #46053, #45586)
  • Security dependency updates. Upgrade github.com/klauspost/compress in dify-agent-runtime to address CVE-2026-116591, and update Node.js in runtime images to security release 24.22.3. (#46544, #46206, #46064)
  • Reliable blocking workflows. Release database connections before execution and return preparation failures immediately, preventing connection-pool exhaustion and hanging requests that wait until timeout. (#46254)
  • More stable workers. Resolve the Redis BRPOP busy loop and prevent overlapping plugin upgrade checks, capping concurrency at 20 checks across workers. (#45940, #46500)
  • Complete Chatflow streams. Properly close streams after direct replies and reset the reconnect budget when a stream resumes. (#45552, #46110)
  • Correct Agent execution. Preserve parallel calls to the same plugin tool, pass declared app inputs to Agent runs, and deliver uploaded images to vision models. (#45207, #45425, #45745)
  • Accurate knowledge retrieval. Restore Weaviate keyword/hybrid results by returning BM25 scores, and keep embedding vectors aligned when a batch item is dropped. (#45642, #45569)
  • Reliable custom API tools. Resolve OpenAPI server variables, percent-encode path parameters, and support OpenAPI 3.1 nullable unions. (#46504, #45965, #45895)

Configuration and Integration Changes

New and changed settings

(#46616) |

For Docker Compose, configure shared backend overrides in envs/core-services/api-worker.env and Web overrides in envs/core-services/web.env. Root docker/.env takes precedence. Apply changes with docker compose up -d; a plain restart does not reload environment files.

The OpenTelemetry provider supports OTLP/HTTP with protobuf; gRPC is not supported. Live Agent tool activity requires streaming output, is unavailable for buffered-output paths, and is not replayed from chat history.

File scanning is disabled by default at the deployment level and must also be enabled per knowledge base. Policies for scanner unavailability and unscannable files both default to blocking the file.

Disabling NEXT_PUBLIC_ENABLE_HITL_IM does not roll back saved data or halt server-side work already in progress.

Reverse proxy and worker configuration

  • New API route: In WEBHOOK mode, forward /callbacks/human-input/v2/im/ to the API service (api:5001 in Docker Compose), preserving the request path, raw body, and provider signature headers. The bundled nginx template already includes this rule; add its equivalent to custom nginx, Ingress, or other reverse proxy configurations. Configure the IM provider with the channel's generated Callback URL. (#44864)
  • New Celery queues: Include human_input_delivery for asynchronous IM callback processing and post-submission card updates, and human_input_contact_sync for IM contact directory synchronization. The default Docker worker list includes both. Custom CELERY_QUEUES, CELERY_WORKER_QUEUES, or Celery --queues lists must provide an active consumer for each queue alongside existing subscriptions. (#44864)

Docker environment files

docker/envs/core-services/shared.env is no longer loaded. Move common API, worker, and Beat settings to api-worker.env before recreating containers. Preserve any service-specific settings in the override file used by that service. (#46497)

Public URLs are shared by Web, API, and workers through the new envs/core-services/urls.defaults and optional urls.env:

  • CONSOLE_API_URL
  • CONSOLE_WEB_URL
  • SERVICE_API_URL
  • APP_API_URL
  • APP_WEB_URL

Set browser-accessible base URLs without /console/api, /api, or /v1 suffixes. Explicit values in urls.env override service-specific URL settings; root docker/.env overrides both. Web's internal SERVER_CONSOLE_API_URL remains in web.env. This also resolves an issue where generated icon links pointed to 127.0.0.1:5001 on fresh installations. (#46497)

Database Migrations

Upgrading from 1.19.0 adds six migration revisions, moving the migration head from 53c10126d551 to f8b6e2c4a901. Apply the complete Alembic chain through the normal migration runner.

| Revision | Change | | --- | --- | | 6b7e2a9c4d10 | Add nullable started_by_sys_user_id to human_input_im_sync_runs and require exactly one initiating identity per row. | | b2e4c6d8a013 | Add personal access tokens and their resource/workspace scope tables. | | 8c2f5d7a1e30 | Add file scanner, scan policy, and scan-result tables. | | 91f4b2d7c8e0 | Add Evaluation configuration, run, and run-item tables. | | c7e4a1b2d9f0 | Add the Evaluation framework column with a default value. | | f8b6e2c4a901 | Merge the Evaluation and main migration branches. |

The Evaluation migrations apply to the Community Edition as well, even though CE does not expose the Evaluation feature. Include these revisions when applying the migration chain; none of the six revisions require a separate manual backfill command. (#45945, #45540, #46090, #46141)

New HITL introduces the necessary database schema and automatically backfills Contact identities for existing accounts with no extra commands required. These migrations are already included in 1.19.0—existing 1.19.0 deployments need no action, while older versions should run the full migration chain. Legacy Human Input nodes are not automatically migrated and remain opt-in.

Upgrade Guide

[!IMPORTANT] Move settings out of the retired shared.env before recreating containers. Review public URLs, custom HITL callback routing, and worker subscriptions. OpenShell deployments require a compatible gateway upgrade and no longer restore Home Snapshots. The bundled plugin daemon is updated to 0.6.15-local.

Prepare the deployment

  1. Back up data and configuration. Back up your database, vector-store data, uploaded files, plugin daemon storage, Agent workspace storage, deployment secrets, and environment files. Schedule a maintenance window for a single-stack upgrade.
  2. Upgrade the Dify components together. Use matching 1.20.0 API, worker, Web, Agent Backend, and Local sandbox images, alongside plugin daemon 0.6.15-local. Keep SECRET_KEY, any configured PASSWORD_PEPPER, and the Local sandbox authentication token unchanged. Personal access tokens depend on SECRET_KEY; ensure the same value is used across all API replicas. If upgrading from a version earlier than 1.19.0, also follow the 1.19.0 upgrade guide.
  3. Migrate shared.env. If envs/core-services/api-worker.env does not exist, rename envs/core-services/shared.env to that path. If both exist, merge only missing settings and preserve existing api-worker.env values, including intentional empty assignments. Retain service-specific settings in the appropriate service override file. Deployments without shared.env require no migration.
  4. Consolidate public URLs. Create envs/core-services/urls.env from urls.defaults only if it does not already exist. Move the intended public URL values there, then remove duplicate assignments from individual service files. Existing root .env values retain precedence. Keep internal Web API routing in web.env.
  5. Apply environment, route, and queue changes. Follow Configuration and Integration Changes, including the New HITL settings, IM callback route, and both Celery queues.
  6. Let plugin storage initialization run. init_permissions now also prepares ./volumes/plugin_daemon for the daemon's UID 1001, and the daemon waits for it to complete. Recreate the deployment with docker compose up -d so the init service runs. (#45615)

OpenShell deployments

Upgrade the OpenShell gateway and SDK together to 0.1.3 or later within the supported 0.1.x line, and upgrade the Dify API and Agent Backend together. The gateway must support native service exposure and bearer passthrough, preserving the per-sandbox authorization token derived from DIFY_AGENT_OPENSHELL_SHELLCTL_AUTH_TOKEN. Keep that master secret identical across Agent Backend replicas. (#45862)

Build the OpenShell runtime image from the release checkout and set DIFY_AGENT_OPENSHELL_SANDBOX_IMAGE to the exact image reference available to the gateway's compute nodes. The image must include both shellctl and iproute2; an older cached runtime image may lack the required networking tools.

When upgrading from the previous shared deployment-wide shellctl token, generate a fresh high-entropy master secret and update all Agent Backend replicas together. Drain active work, then stop and restart existing sandboxes so shellctl restarts with the derived credential. Reacquiring an already healthy sandbox does not refresh its credential.

Shared-volume Home Snapshots and DIFY_AGENT_OPENSHELL_SHARED_MOUNT_PATH are removed. Existing running sandboxes retain their state across stop/restart cycles, whereas newly created Bindings start from the image's default Home. DIFY_AGENT_OPENSHELL_DRIVER_CONFIG is now optional. Review the OpenShell deployment guide, including its runtime-image requirements, before upgrading. Other sandbox backends are unaffected.

Docker Compose

Once the 1.20.0 tag and images are published, stop the deployment gracefully, switch to the release, migrate local configuration files, and then pull and start the updated services:

cd dify/docker
docker compose stop -t -1
git fetch --tags
git checkout 1.20.0
# Migrate shared.env, public URLs, and any custom proxy/worker configuration.
docker compose pull
docker compose up -d

Keep API startup migrations enabled (MIGRATION_ENABLED=true), or apply the full migration chain through your managed migration process before starting new workers. Use docker compose up -d after changing environment files; a plain restart does not reload them.

Source deployments

Use Python 3.13, Node.js 24.22.3 or later in the 24.x line, and pnpm 12.18.0. After stopping the services and switching to the release, run the following commands from the repository root:

uv sync --project api --frozen
uv run --directory api flask db upgrade
pnpm install --frozen-lockfile

Rebuild Web and restart the API, workers, scheduler, and Agent services from the same release. Update the standalone Agent Backend's locked dependencies if deploying it separately. Preserve existing worker subscriptions and add the two HITL queues where needed.
