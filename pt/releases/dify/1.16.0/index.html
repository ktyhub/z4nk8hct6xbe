#difícil 1.16.0

Apresentando o Dify Agent (Beta): uma nova experiência de agente no Dify

[!AVISO] Você deve fornecer serviços de Agente Dify ⚠️apenas para trusted, usuários não maliciosos⚠️.

Como muitos de vocês sabem, o paradigma do agente LLM baseado em shell trouxe um grande salto nas capacidades dos agentes e mudou a forma como pensamos sobre os agentes. Enquanto isso, as Skills fornecem uma maneira padronizada de empacotar e distribuir recursos, facilitando a construção de agentes poderosos.

Hoje estamos lançando o Dify Agent. Como outros agentes líderes, ele é executado em uma sandbox Linux. Esta versão inclui:

  • Um construtor para criar Agentes Dify

    • Você pode construir Agentes Dify por meio da IU: definir um prompt base, fazer upload de habilidades e arquivos e conectar ferramentas e conhecimento do ecossistema Dify.
    • Também fornecemos um agente que ajuda você a construir Agentes Dify. Por meio de conversação, ele pode configurar o ambiente sandbox Linux, instalar os pacotes necessários e criar novas habilidades e arquivos que seu agente Dify pode usar posteriormente.

  • Integração do Dify Workflow para o Dify Agent

    • Você pode usar um Dify Agent existente em um fluxo de trabalho Dify ou criar temporariamente um Dify Agent inline. Ele executará a tarefa definida pelo nó do fluxo de trabalho, gerará a saída necessária e a passará para o próximo nó.

  • Uma nova experiência de aplicativo da web

    • O Dify Agent que você cria pode ser publicado e usado como um aplicativo da web. Embora a experiência do usuário permaneça familiar, agora ela é desenvolvida pelo Dify Agent.

Documentos: https://docs.dify.ai/en/self-host/use-dify/build/new-agent/overview

⚠️ Ação necessária

Aviso de compatibilidade OpenAI GPT-5.6

O plug-in OpenAI anteriormente usava como padrão o Chat Completions API, que foi descontinuado pela OpenAI no início deste ano e tem suporte cada vez mais fraco para séries de modelos mais recentes. A família GPT-5.6 recém-lançada tem muitas restrições incomuns e exclusivas de combinação de parâmetros quando usada com completações de bate-papo, porque o OpenAI agora fornece apenas suporte mínimo de compatibilidade para conclusões de bate-papo com novos modelos. Este não é um problema do sistema Dify.

O tipo API padrão para novas configurações foi alterado de Conclusões de bate-papo para Respostas. No entanto, os usuários que salvaram anteriormente uma chave API personalizada com o padrão antigo (conclusões de bate-papo) manterão essa configuração, o que pode causar erros inesperados que parecem ter origem no Dify.

Se você configurou anteriormente uma chave OpenAI API personalizada, verifique a configuração do tipo API e mude para Respostas se ainda estiver definido para Conclusões de bate-papo, especialmente ao usar GPT-5.6 ou modelos posteriores.

Novos recursos

Aplicativo do agente (Beta aberto)

  • Agent App entra em versão beta aberta e agora está habilitado por padrão para todos os usuários. Ele apresenta uma sandbox integrada para execução de código e comandos shell, um sistema de habilidades que permite aos agentes chamar ferramentas e APIs, uma lista de agentes para gerenciar e reutilizar agentes em um espaço de trabalho e suporte para referenciar novos agentes a partir de nós de agentes de fluxo de trabalho.

Geração de fluxo de trabalho de IA mais inteligente

  • O gerador de fluxo de trabalho ⌘K → /create e /refine AI foi aprimorado de ponta a ponta: o campo de baixo valor "Saída ideal" foi removido, chips de exemplo estáticos foram substituídos por sugestões geradas por IA baseadas no contexto do seu espaço de trabalho e a geração de configuração de nó agora é paralelizada para resultados mais rápidos. Um tempo limite configurável (WORKFLOW_GENERATION_TIMEOUT_MS, padrão 180s) evita que gerações de longa duração sejam interrompidas. Atualização do protocolo MCP
  • O servidor de fluxo de trabalho como MCP agora suporta o protocolo MCP 2025-06-18 com negociação de versão e saída de ferramenta estruturada, enquanto permanece compatível com versões anteriores de clients mais antigos. As conexões MCPClient agora podem injetar cabeçalhos de solicitação HTTP dinâmicos em tempo de execução usando espaços reservados (por exemplo, {{request.headers.X-Custom-Auth}}), permitindo a passagem de autenticação por solicitação.

Personalização de aplicativos da Web

  • Os proprietários de aplicativos agora podem personalizar o texto do espaço reservado de entrada de bate-papo (até 64 caracteres) para aplicativos da web Chatbot, Agente e Chatflow. A UI de personalização foi refinada com nomenclatura mais clara ("Frontend personalizado"/"Branding") e melhor manuseio de rótulos. As descrições dos aplicativos agora são exibidas nas telas de bate-papo e de aplicativos de geração de texto com uma visualização recolhível para evitar empurrar o formulário de entrada para fora da tela.

Confiabilidade e operações do fluxo de trabalho

  • Os arquivos de execução do fluxo de trabalho agora podem ser exportados e as execuções ativas são abortadas corretamente durante o desligamento a quente do Celery para evitar tarefas órfãs. As conexões Redis são mais resilientes com suporte de manutenção de atividade TCP e cobertura expandida de novas tentativas. Os provedores de modelos agora recebem app_id para atribuição de custos do lado do provedor (por exemplo, Bedrock requestMetadata, metadados OpenAI, rótulos Vertex AI). Os fluxos de login OAuth e SSO agora preservam URLs de redirecionamento de forma mais confiável, com uma visualização de erro dedicada para conclusões de SSO com falha.

Guia de atualização

Migração de tipo de modelo

[!IMPORTANTE]

Migração única de tipo de modelo legado para atualizações auto-hospedadas

Se esta implantação foi atualizada de uma versão Dify anterior a 1.15.0 e esta migração ainda não foi aplicada, execute-a após a atualização.

Esta migração não está incluída no flask db upgrade. Sem ele, os registros do modelo legado podem fazer com que as solicitações API relacionadas ao modelo falhem com erros, impedindo que os modelos afetados sejam carregados ou usados.

Faça backup do banco de dados antes de aplicar a migração. O comando é executado no modo de teste por padrão; revise a saída antes de executá-la novamente com --apply. A migração é idempotente e pode ser executada novamente com segurança.

Docker Compor

Execute a partir do diretório docker.

# Apply after reviewing the dry-run output
docker compose exec -T api flask data-migrate legacy-model-types --apply \
  > legacy-model-types-apply.jsonl

Implantação do código-fonte

Execute a partir da raiz do repositório após concluir flask db upgrade.

# Apply after reviewing the dry-run output
uv run --project api flask data-migrate legacy-model-types --apply \
  > legacy-model-types-apply.jsonl

Depois de aplicar a migração, execute o comando de simulação novamente. Se não reportar atualizações ou exclusões de linha adicionais, reinicie os serviços relevantes e verifique se os modelos existentes podem ser carregados e invocados com sucesso.

dify 1.16.0

Introducing Dify Agent (Beta): A New Agent Experience in Dify

[!WARNING] You should provide Dify Agent services ⚠️only to trusted, non-malicious users⚠️.

As many of you know, the shell-based LLM agent paradigm has brought a major leap in agent capabilities and changed how we think about agents. Meanwhile, Skills provide a standardized way to package and distribute capabilities, making it easier to build powerful agents.

Today, we are launching Dify Agent. Like other leading agents, it runs in a Linux sandbox. This release includes:

  • A builder for creating Dify Agents

    • You can build Dify Agents through the UI: set a base prompt, upload Skills and files, and connect tools and knowledge from the Dify ecosystem.
    • We also provide an agent that helps you build Dify Agents. Through conversation, it can configure the Linux sandbox environment, install required packages, and create new Skills and files that your Dify Agent can use later.

  • Dify Workflow integration for Dify Agent

    • You can use an existing Dify Agent in a Dify Workflow, or temporarily create an inline Dify Agent. It will execute the task defined by the workflow node, generate the required output, and pass it to the next node.

  • A new web app experience

    • The Dify Agent you build can be published and used as a web app. While the user experience remains familiar, it is now powered by Dify Agent.

Docs: https://docs.dify.ai/en/self-host/use-dify/build/new-agent/overview

OpenAI GPT-5.6 Compatibility Notice

The OpenAI plugin previously defaulted to using the Chat Completions API, which was deprecated by OpenAI earlier this year and has increasingly poor support for newer model series. The newly released GPT-5.6 family has many unusual and unique parameter combination restrictions when used with Chat Completions, because OpenAI now provides only minimal compatibility support for Chat Completions with new models. This is not a Dify system issue.

The default API type for new configurations has been changed from Chat Completions to Responses. However, users who previously saved a custom API key with the old default (Chat Completions) will retain that setting, which may cause unexpected errors that appear to originate from Dify.

If you have previously configured a custom OpenAI API key, please check your API type setting and switch to Responses if it is still set to Chat Completions, especially when using GPT-5.6 or later models.

New Features

Agent App (Open Beta)

  • Agent App enters open beta and is now enabled by default for all users. It introduces a built-in sandbox for code execution and shell commands, a skill system that lets agents call tools and APIs, an agent roster for managing and reusing agents across a workspace, and support for referencing new agents from workflow agent nodes.

Smarter AI Workflow Generation

  • The ⌘K → /create and /refine AI workflow generator has been enhanced end-to-end: the low-value "Ideal output" field was removed, static example chips replaced with AI-generated suggestions grounded in your workspace context, and node config generation is now parallelized for faster results. A configurable timeout (WORKFLOW_GENERATION_TIMEOUT_MS, default 180s) prevents long-running generations from hanging.

MCP Protocol Upgrade

  • The workflow-as-MCP server now supports MCP protocol 2025-06-18 with version negotiation and structured tool output, while remaining backward compatible with older clients. MCPClient connections can now inject dynamic HTTP request headers at runtime using placeholders (e.g. {{request.headers.X-Custom-Auth}}), enabling per-request authentication passthrough.

Web App Customization

  • App owners can now customize the chat input placeholder text (up to 64 chars) for Chatbot, Agent, and Chatflow web apps. The customization UI has been refined with clearer naming ("Custom Frontend" / "Branding") and better label handling. App descriptions are now displayed on chat and text-generation app screens with a collapsible view to avoid pushing the input form off screen.

Workflow Reliability & Operations

  • Workflow run archives can now be exported, and active runs are properly aborted during Celery warm shutdown to prevent orphaned tasks. Redis connections are more resilient with TCP keepalive support and expanded retry coverage. Model providers now receive app_id for provider-side cost attribution (e.g. Bedrock requestMetadata, OpenAI metadata, Vertex AI labels). OAuth and SSO login flows now preserve redirect URLs more reliably, with a dedicated error view for failed SSO completions.

Upgrade Guide

Model Type Migration

[!IMPORTANT]

One-time legacy model type migration for self-hosted upgrades

If this deployment was upgraded from a Dify version earlier than 1.15.0 and this migration has not already been applied, run it after upgrading.

This migration is not included in flask db upgrade. Without it, legacy model records can cause model-related API requests to fail with errors, preventing affected models from being loaded or used.

Back up the database before applying the migration. The command runs in dry-run mode by default; review the output before rerunning it with --apply. The migration is idempotent and can be safely rerun.

Docker Compose

Run from the docker directory.

# Apply after reviewing the dry-run output
docker compose exec -T api flask data-migrate legacy-model-types --apply \
  > legacy-model-types-apply.jsonl

Source Code Deployment

Run from the repository root after completing flask db upgrade.

# Apply after reviewing the dry-run output
uv run --project api flask data-migrate legacy-model-types --apply \
  > legacy-model-types-apply.jsonl

After applying the migration, run the dry-run command again. If it reports no additional row updates or deletions, restart the relevant services and verify that existing models can be loaded and invoked successfully.

[!IMPORTANT]

  • This release includes 8 new database migrations. Run database migrations as part of the upgrade.
  • 28 new environment variables, 1 removed, and 1 modified. Review the Environment Variable Changes section and update your .env accordingly.
  • Docker Compose configuration changed significantly: two new services (agent_backend, local_sandbox) were added. If you maintain a customized docker-compose.yaml, review the changes and re-apply local customizations carefully.
  • DIFY_AGENT_SERVER_SECRET_KEY ships with a development default. You must replace it in production with a securely generated key: python -c 'import secrets; print(secrets.token_urlsafe(32))'
  • ENABLE_AGENT_V2 has been renamed to NEXT_PUBLIC_ENABLE_AGENT_V2 and now defaults to true. Remove the old variable from your env files.
  • OpenAI GPT-5.6 users: If you have previously configured a custom OpenAI API key, verify your API type is set to Responses (not Chat Completions). See the Known Issues section above.

Docker Compose Deployments

  1. Back up your customized docker-compose YAML and env files.

    cd docker
cp docker-compose.yaml docker-compose.yaml.$(date +%s).bak
cp .env .env.$(date +%s).bak 2>/dev/null || true

  2. Get the latest code from the release branch or tag.

    git fetch --tags
git checkout 1.16.0

  3. Stop the service. Please execute in the docker directory.

    docker compose down

  4. Back up data.

    tar -cvf volumes-$(date +%s).tgz volumes

  5. Review the new environment variables (especially DIFY_AGENT_SERVER_SECRET_KEY) and update your .env file. Re-apply any local customizations.

  6. Upgrade services.

    docker compose up -d

Source Code Deployments

  1. Stop the API server, Worker, and Web frontend Server.

  2. Get the latest code from the release tag.

    git fetch --tags
git checkout 1.16.0

  3. Update Python dependencies.

    cd api
uv sync

  4. Run the migration script.

    uv run flask db upgrade

  5. Configure the new Agent backend service. Refer to the dify-agent section in docker/envs/core-services/dify-agent.env.example for required environment variables.

  6. Restart the API server, Worker, and Web frontend Server.
