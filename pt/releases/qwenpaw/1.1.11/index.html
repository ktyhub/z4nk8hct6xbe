QwenPaw v1.1.11

Highlights

  • Console becomes an extension platform — v1.1.11 is less a feature drop and more a pivot toward pluggability: the Plugin Market with AgentScope Platform integration (#5023), the underlying plugin extension infrastructure (#4997), a tool-cards plugin system (#5046), and a prompt-section registry that lets plugins inject system-prompt blocks at named anchors (#4804). Uninstall hooks and an exposed skill-provider API (#4794) close the lifecycle loop. For adopters this means customization should move from forking core to installing/injecting plugins — but treat the new hook and anchor contracts as unstable surface area to watch in the next minor.

  • Provider onboarding gets cheaper and more faithful — Free Model OAuth (#5049) removes the API-key step entirely for zero-config models, and Xiaomi MiMo Token Plan ships as a built-in provider (#4722). More importantly for anyone using custom sampling params, Extra Body Routing (#4689) funnels non-standard generate_kwargs into extra_body instead of letting them be dropped or rejected — paired with the compaction fix that now respects a model's max_input_length when active_model is unset (#5021) and a ProviderManager fallback for that lookup (#4827). Expect fewer silent param losses and fewer context-window overruns.

  • MCP gets safer and more stable — Per-server tool whitelisting with a frontend toggle (#5002) lets you limit each server's exposed tool set, shrinking both prompt bloat and attack surface — the single most actionable security control in this release. Two long-standing irritants are also fixed: alias-rewritten tool names no longer fail OpenAI-style name regex validation (#4958), and MCP subprocesses no longer accumulate across restarts (#5014), so long-running instances stop leaking child processes.

  • Human-in-the-loop and identity land in channels — Telegram tool approval via inline keyboard (#4737) brings interactive HITL gating to a chat channel — a genuine behavioral change if you relied on fully autonomous tool execution there. Identity handling is tightened across the board: QQ QR-code authorization (#4848), Feishu interactive card extraction (#4879) plus group session sharing (#4821), DingTalk inline image/video cards (#5073), and access control now carrying sender usernames via a unified user-info structure (#4897) while preserving acl_sender_id through native payload merges (#4925). Audit any ACL rules that keyed on the old sender representation.

  • File-preview restriction is the one behavior change to check — File preview is now confined to WORKING_DIR with sensitive files blocked (#4981). Workflows that previewed paths outside the working directory will break silently and need to relocate files; this is the change most likely to surprise existing users. The durability story improves alongside it — non-blocking writes via aiofiles (#4954), atomic session-state writes (#4706), and an awaited broadcast coroutine fix (#5048) reduce the odds of truncated state and fire-and-forget errors.

  • Faster startup and cross-browser reliability — Backend startup is unblocked and parallelized (#5074), so boot and reload times should drop noticeably. Browser automation gains a CDP timeout parameter and profile isolation for cross-browser switching (#4944), and the "dream" job now uses the cron runner's workspace instead of a stale instance directory (#4936) — fix those two if you run scheduled browser-backed tasks. Note the reverted "session list as right-side panel" (#5076): anyone who adopted that layout will see it disappear again.

No breaking changes in this release.
