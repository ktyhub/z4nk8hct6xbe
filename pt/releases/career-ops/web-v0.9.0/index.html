career-ops web-v0.9.0

Highlights

  • Web-triggered runs finally honor your language config (#3253) — Runs launched from the UI now respect language.modes_dir and language.output instead of silently falling back to defaults. If you'd customized output locations or mode directories, behavior that was previously correct only on CLI runs now applies to web runs too — recheck any UI-launched job whose artifacts seemed to land in the wrong place.
  • Exit code becomes the source of truth for run success (#1974) — Nonfatal CLI stderr on a clean exit no longer marks a run as failed, eliminating false failures from tools that log warnings to stderr. The tradeoff: a zero-exit process that reports errors only via stderr will now be treated as successful, so audit any wrapper scripts that relied on stderr text to signal failure.
  • Failure diagnostics get real root causes (#2158) — Job failures now surface a cause-specific hint in place of the generic "check your auth" prompt, which should cut down on chasing the wrong problem. Related observability change: runtime data paths are no longer written into traces, so telemetry gets cleaner and stops leaking local filesystem paths.
  • Follow-up list is filtered to what's actually due (#2157) — The follow-ups surface now shows only items whose due date has arrived, reducing dashboard noise. If you were using that list as a backlog of all upcoming follow-ups, you'll need another view to see not-yet-due items.
  • Navigation and table rendering cleanup (#1931, #3254, #3160, #2821) — The decision-card report link now uses next/link (client-side navigation instead of a full reload), evaluation tables no longer collapse to one word per line, tab-label spacing and report-table word-breaking are fixed, and a global "Back to Top" button lands for long pages. Mostly polish, but the next/link switch is a genuine behavioral/perf change worth noting if you measure navigation timing.
  • Dependency upkeep with lockfile churn — Lockfiles refreshed for a Next update (2ca6c00) and for postcss bumps, including regeneration of the nested web/ lockfile (dba2a2e). No API surface change, but transitive updates warrant a quick build-pipeline smoke test.

No breaking changes in this release.
