career-ops web-v0.14.0

Highlights

  • Template packs gain a declarative contract — #3900 adds atsLint with rules as data in templates/ats-rules.yml, while #3852/#3916 let a pack declare the sections it owns. Together these make upgrades reviewable: both "what this pack manages" and "which ATS rules apply" are now diffable YAML rather than implicit behavior. Migration watch-out: audit each installed pack before upgrading — an undeclared section is now treated as yours and may stop receiving pack updates, and ATS findings can change as packs bring their own rule file.

  • modes_dir becomes a market list — #3798 lets language.modes_dir declare multiple markets. Configs pointing at a single path still make sense, but any script that walks modes on disk now has to handle several roots; CI jobs that build locale packages should iterate the list instead of assuming one directory.

  • Dashboard binds to loopback by default — #3716 changes the web app's default bind address. This is the deployment-facing change to plan for: if you reached the dashboard from another host or a container, it will look like the service is down after the upgrade, so set the host binding explicitly.

  • New surfaces read from core, not web-local state — #2628 adds local scheduled scans, #4576 builds progress and insights views from the core, and #4586 surfaces post-interview silence on Follow-ups. The practical shift is that scans no longer require a cloud scheduler and these views reflect core-side state rather than a browser cache — so results should agree across clients, and anything still cached locally will look stale by comparison.

  • Loading transitions stop discarding your working state — #4338 adds route-aware loading feedback; #4473 and #4495 preserve context and assistant conversations across transitions. Long runs now survive navigation, but the flip side is that context persists between routes — clear or scope the session when switching applications to avoid carrying stale assumptions into a new one.

  • AI paths get explicit cost and completion guarantees — #4746 gates paid assistant fan-out on a cost estimate, #4744 counts cached input in the usage meter, #4638 falls back from a stale cliId on every AI route rather than just Run, and #4107 requires confirmed worker stream completion. Expect reported usage to jump once cached tokens are counted — that's accounting, not new spend — and expect fewer silently truncated results.

No breaking changes are documented in this release.

Features
