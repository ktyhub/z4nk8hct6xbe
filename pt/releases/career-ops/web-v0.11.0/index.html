career-ops web-v0.11.0

Highlights

  • Local API hardening — The dashboard API adds an opt-in Origin allowlist (#3597), reducing exposure of local job data and actions to untrusted websites. Configure trusted origins when enabling it; existing behavior remains unchanged otherwise.
  • Tracker integrity — Addition columns are now resolved by name, preventing score and status values from being written into each other’s columns and corrupting application metrics.
  • Stable posting identity — URL normalization now preserves fragment comparison parameters and hash-route identity, so bookmarked and shared links continue resolving to the same posting rather than being misidentified.
  • Report and document accuracy — Failed fetches no longer become scored reports (#3826), verdict blocks are detected by heading rather than fragile letter markers (#3502), and tailored-document checks use both actual files on disk and application-specific resolution. This avoids misleading scores, readiness states, and cover-letter selection.
  • Agent CLI compatibility — Grok gains a parser, token folding becomes per-CLI (#2689), pretty-printed set-status.mjs success responses parse correctly (#3602), and agent CLIs are fenced at spawn. These changes make mixed-CLI automation more reliable without requiring workflow rewrites.
  • Breaking changes — None.
