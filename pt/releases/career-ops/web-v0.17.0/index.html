career-ops web-v0.17.0

Highlights

  • CV ingestion and edit persistence — The editor now imports PDF and TeX CVs directly (#6238), and preview page counts are derived from rendered content rather than stored metadata (#6180). CV Studio also gained save-state guards: edits persist when you navigate away and surface explicit "saved" indicators (#6179, #6182). For anyone scripting the editor, this is a real behavioral shift — the CV pipeline is now stateful, and anything keying off a stored page-count field must re-derive it from content.

  • Resume authenticity and recruiter-facing deliverables — CV generation now actively rejects stock resume phrasing the candidate did not author (#6178), and the apply flow uploads the tailored CV under a recruiter-facing filename (#6399, #6478). Watch out: content that previously passed validation may now be flagged as boilerplate, and the filename contract for downstream apply tooling changes — integrations matching on the old name will need updating.

  • Evaluation modes and report structure — You can now choose full versus focused job evaluations (#5917) and opt into a years-of-experience filter parsed from the JD (#6153, #6154), while the Machine Summary is written as the last report section (#6157). This makes evaluation granularity and JD-driven filtering configurable, but consumers that parse reports by section position must adjust — Machine Summary is no longer where it used to be.

  • Pipeline state and addressable filters — Pipeline views can be saved with a score floor (#6103), a tailored-resume column was added (#6341, closing #6338), and pipeline/follow-up searches now live in the URL (#6060). Two changes worth flagging: evaluated jobs are dropped from the pending inbox (#5906) — so the inbox can no longer double as a history — and posting dates are preserved when adding to the pipeline (#5690), fixing silent metadata loss on import.

  • Runtime, engines, and Windows/CLI behavior — The engines field now declares the full NODE_ENGINES range (#5993), automatic agent-rules generation in next.config.mjs is disabled (#6150), and npm-installed agent CLIs now run on Windows (#5787). Child processes are launched with process.execPath and windowsHide (#5900, #5902), the Homebrew opt path is pinned so brew upgrade cannot break the scan schedule (#6375), and onboarding only offers the assistant when a CLI is actually runnable (#6432). If you relied on generated agent rules you must supply them yourself; console-free children cut noise but hide diagnostics.

  • Config-file safety and accessibility — Saves are now guarded against stale state: a cadence save from a tab holding an older profile is refused (#6053), profile.yml comments survive profile/cadence writes (#5678), and an unreadable modes/_profile.md is never overwritten with a stub (#5839). Report headers with Windows line endings are parsed correctly (#6052), and a11y fixes land around WCAG AA status text (#6078) and a skip-to-content link (#6063). The config changes matter most if your YAML is source-controlled: hand-edited comments and unreadable files are now protected rather than silently clobbered.

No breaking changes are documented in this release.
