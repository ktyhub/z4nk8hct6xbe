argo-cd v3.6.2

Highlights

  • Faster, safer reconciliation — ApplicationSet refresh now patches only its refresh annotation instead of rewriting the object (#24378, #24647; backport #31029). This reduces unnecessary writes and the risk of overwriting concurrent controller updates.
  • Diff-cache correctness after unknown sync states — The controller now bypasses cached diffs after an Unknown sync status and retains its server-side diff cache when manifest-generate-paths is unchanged (#30893, #30812). Expect more accurate drift detection, with cache-hit performance preserved for unaffected manifests.
  • Lower controller memory pressure — gitops-engine no longer retains a decoded OpenAPI document per cluster and trims excess capacity from cached compressed manifests (#30810, #30779). Large multi-cluster installations should see reduced steady-state memory use without configuration changes.
  • Fix for deny-rule precedence — AppProject negative destination rules (!name / !server) now veto even when a positive rule matches (#30896). Review policies that combine allow and deny patterns; destinations previously admitted may now be rejected.
  • Dependency hardening — regexp2 is upgraded to v2.13.0 to address CVE-2026-77299 (#31039), while Helm moves to v4.3.2 and Go to v1.27.4 (#30986, #30915). Validate any custom Helm-backed integrations as part of the upgrade.
  • Operational and UI fixes — Kustomize with ignoreMissingComponents now includes every existing component (#30909), and UI fixes improve multi-source navigation, pod terminal continuity, grouped-pod visibility, and breadcrumb layout.

No breaking changes.

Quick Start

Non-HA:

kubectl create namespace argocd
kubectl apply -n argocd --server-side --force-conflicts -f https://raw.githubusercontent.com/argoproj/argo-cd/v3.6.2/manifests/install.yaml

HA:

kubectl create namespace argocd
kubectl apply -n argocd --server-side --force-conflicts -f https://raw.githubusercontent.com/argoproj/argo-cd/v3.6.2/manifests/ha/install.yaml

Release Signatures and Provenance

All Argo CD container images are signed by cosign. A Provenance is generated for container images and CLI binaries which meet the SLSA Level 3 specifications. See the documentation on how to verify.
