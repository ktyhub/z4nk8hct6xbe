#tempo v3.1.0 Grafana Tempo 3.1.0 adiciona redação de rastreamento baseada em consulta, aritmética de métricas TraceQL e extrapolação com reconhecimento de amostragem, melhorias de conectividade Kafka e ferramentas experimentais para comparação e remoção de rastreamentos. Também torna vParquet5 o formato padrão para blocos recém-escritos.

Destaques

  • Redação por consulta: Envie trabalhos de redação usando um seletor TraceQL em vez de enumerar IDs de rastreamento, com janelas de tempo opcionais e melhorias na confiabilidade da redação.
  • Métricas TraceQL: combine agregações com aritmética e opte pela extrapolação usando a probabilidade de amostragem registrada em intervalos. O caminho de busca somente span mais rápido agora está habilitado por padrão.
  • Gerador de métricas e gráficos de serviço: Detecte a topologia de serviço sob amostragem intensa com um medidor de informações de conexão opcional, reconheça db.system.name e reduza as métricas de extensão e a sobrecarga de processamento do gráfico de serviço.
  • Remoção de intervalo experimental: Reduza o tamanho da resposta de rastreamento por ID v2, com aceitação em nível de solicitação e padrões configuráveis.
  • Conectividade Kafka: Configure mecanismos SASL adicionais, TLS e TLS mútuo, busca com reconhecimento de rack e compactação de produtor, incluindo gzip para Azure Event Hubs.
  • Diferenças e resumos de rastreamentos experimentais: Compare rastreamentos por meio de API, tempo-cli e MCP, com formatos de patch completo e resumo compacto.
  • vParquet5 por padrão: Grave novos blocos em vParquet5 enquanto continua a ler blocos vParquet4 e vParquet3 existentes, sem migração de dados. O changelog detalhado abaixo inclui as notas RC1 revisadas e backports subsequentes, com referências de relações públicas, créditos de contribuidor, identificadores de segurança e orientações de atualização.

Não envie uma redação em janela enquanto agendadores e trabalhadores executam versões diferentes. Um trabalhador anterior a essa alteração ignora os campos da janela e remove todas as correspondências de consulta em cada bloco fornecido, independentemente do carimbo de data e hora, sem erro e sem maneira de recuperar os dados.

Mudanças significativas

Antes de atualizar

Esta versão inclui alterações significativas na configuração e novos padrões. Revise as entradas detalhadas abaixo, especialmente se você usar cache Redis, gravações vParquet3 ou configurações personalizadas de front-end de consulta.

  • vParquet3: O Tempo se recusa a iniciar quando configurado para gravar blocos vParquet3. Mude storage.trace.block.version para vParquet5 ou vParquet4 antes de atualizar. Os blocos vParquet3 existentes permanecem legíveis, mas não são mais compactados.
  • Redis: O cluster Redis se torna o padrão, o suporte do Sentinel é removido e as chaves de configuração e as configurações de TLS são alteradas. Revise os detalhes da migração antes de atualizar uma instalação usando o cache experimental Redis.
  • Edição em janela: não envie trabalhos de redação em janela enquanto agendadores e trabalhadores executam versões diferentes. Um trabalhador mais velho pode ignorar a janela de tempo e redigir todos os rastreamentos correspondentes em um bloco.
  • Atualizando de um 3.1 RC: Remova a opção obsoleta query_frontend.trace_by_id.span_pruning_enabled. A remoção permanece opcional com span_pruning=true, a menos que um padrão seja configurado; span_pruning_enabled_by_default e a substituição span_pruning_enabled por locatário permanecem disponíveis.
  • Comparação de rastreamento: O comando CLI e a ferramenta MCP agora são denominados traces-diff.
  • Comportamento de consulta: Revise as alterações de fragmentação de rastreamento por ID, validação de consulta de métricas mais rigorosa e o tamanho reduzido do pacote de streaming gRPC padrão.
  • cache: O cache experimental Redis foi completamente reescrito com várias alterações significativas. O suporte do Sentinel foi abandonado em favor do cluster Redis (padrão, opt-out) (#7337) (@oleg-kozlyuk-grafana)
    • Atualize Redis client para github.com/redis/go-redis/v9 e torne o roteamento explícito.
    • Cluster Redis agora é o padrão; opte pelo client de nó único com single_node: true (ou -redis.single-node).
    • As implantações de cluster Redis requerem Redis 7+.

tempo v3.1.0

Grafana Tempo 3.1.0 adds query-based trace redaction, TraceQL metrics arithmetic and sampling-aware extrapolation, Kafka connectivity improvements, and experimental tools for comparing and pruning traces. It also makes vParquet5 the default format for newly written blocks.

Highlights

  • Redaction by query: Submit redaction jobs using a TraceQL selector instead of enumerating trace IDs, with optional time windows and redaction reliability improvements.
  • TraceQL metrics: Combine aggregations with arithmetic and opt into extrapolation using the sampling probability recorded in spans. The faster span-only fetch path is now enabled by default.
  • Metrics-generator and service graphs: Detect service topology under heavy sampling with an opt-in connection-information gauge, recognize db.system.name, and reduce span-metrics and service-graph processing overhead.
  • Experimental span pruning: Reduce trace-by-ID v2 response size, with request-level opt-in and configurable defaults.
  • Kafka connectivity: Configure additional SASL mechanisms, TLS and mutual TLS, rack-aware fetching, and producer compression, including gzip for Azure Event Hubs.
  • Experimental trace diff and summaries: Compare traces through the API, tempo-cli, and MCP, with full-patch and compact-summary formats.
  • vParquet5 by default: Write new blocks in vParquet5 while continuing to read existing vParquet4 and vParquet3 blocks, without a data migration.

Breaking Changes

Before upgrading

This release includes breaking configuration changes and new defaults. Review the detailed entries below, especially if you use Redis caching, vParquet3 writes, or custom query-frontend settings.

  • vParquet3: Tempo refuses to start when configured to write vParquet3 blocks. Change storage.trace.block.version to vParquet5 or vParquet4 before upgrading. Existing vParquet3 blocks remain readable but are no longer compacted.

  • Redis: Redis Cluster becomes the default, Sentinel support is removed, and configuration keys and TLS settings change. Review the migration details before upgrading an installation using the experimental Redis cache.

  • Windowed redaction: Do not submit windowed redaction jobs while schedulers and workers run different versions. An older worker can ignore the time window and redact every matching trace in a block.

  • Upgrading from a 3.1 RC: Remove the obsolete query_frontend.trace_by_id.span_pruning_enabled option. Pruning remains opt-in with span_pruning=true unless a default is configured; span_pruning_enabled_by_default and the per-tenant span_pruning_enabled override remain available.

  • Trace comparison: The CLI command and MCP tool are now named traces-diff.

  • Query behavior: Review Trace-by-ID sharding changes, stricter metrics-query validation, and the reduced default gRPC streaming packet size.

  • cache: Experimental Redis cache has been completely rewritten with multiple breaking changes. Sentinel support has been dropped in favor of Redis Cluster (default, opt-out) (#7337) (@oleg-kozlyuk-grafana)

    • Upgrade Redis client to github.com/redis/go-redis/v9 and make routing explicit.
    • Redis Cluster is now the default; opt into the single-node client with single_node: true (or -redis.single-node).
    • Redis Cluster deployments require Redis 7+.
    • Redis Sentinel support is removed: the master_name, sentinel_username, sentinel_password YAML keys and their -redis.master-name, -redis.sentinel-username, -redis.sentinel-password flags are gone. YAML keys idle_timeout and max_connection_age are renamed to conn_max_idle_time and conn_max_lifetime.
    • The minimal tls_enabled/tls_insecure_skip_verify pair is replaced with the dskit-style TLS block (tls_cert_path, tls_key_path, tls_ca_path, tls_server_name, tls_insecure_skip_verify, tls_cipher_suites, tls_min_version); invalid TLS settings now fail closed instead of silently downgrading to cleartext.
    • Adds Redis Cluster routing options (route_by_latency, route_randomly, read_only, max_redirects, min_idle_conns) and a configurable max_item_size cap. Cross-slot MGet/Del fan out across shards in parallel; MSet uses Pipeline instead of TxPipeline so cross-slot writes no longer fail with CROSSSLOT.
    • RedisCache.Store is now recorded in tempo_rediscache_request_duration_seconds, matching the memcached client.

  • operations: Stop publishing mutable Docker image tags to immutable GAR repositories and pin examples to Tempo 3.0.0. (#7369) (@javiermolinar)

  • query-frontend: Remove the cluster-wide query_frontend.trace_by_id.span_pruning_enabled configuration option; span pruning is always available for trace-by-ID v2 requests. (#7912, #8010) (@ie-pham) Pruning remains opt-in per request with span_pruning=true unless a default is configured. The experimental span_pruning_enabled_by_default option and per-tenant span_pruning_enabled override remain available; an explicit request value takes precedence. Users upgrading from an earlier 3.1 RC should remove the obsolete cluster-wide option.

  • query-frontend: new job sharding approach for trace lookups, using a new config option blocks_per_shard which replaces query_shards. (#7105) (@mdisibio)

  • storage: Enforce the vParquet3 deprecation. Tempo now refuses to start with storage.trace.block.version set to vParquet3, and the compactor no longer compacts existing vParquet3 blocks together. (#7858) (@mdisibio) Existing vParquet3 blocks remain readable and are left as-is. Set the block version to vParquet4 or later.

  • traceql: Reject metrics query requests with identical start and end timestamps. (#7602) (@mdisibio)
