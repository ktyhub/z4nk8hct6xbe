raio ray-2.60.0

Destaques

  • Leituras de embaralhamento de dados Ray e Parquet: Nesta versão do Ray, embaralhamento v2 é a estratégia de embaralhamento padrão para junções e agregações (#66260). As leituras do Parquet agora dimensionam as tarefas de leitura a partir dos metadados do grupo de linhas no rodapé de cada arquivo, em vez de estimar o tamanho do arquivo, portanto, as tarefas de leitura são compactadas com um orçamento de bytes preciso (#65596, #65806, #65821).
  • Atualizações contínuas do Ray Serve: adicionamos max_surge_percent, que inicia réplicas de substituição antes de interromper as antigas para que uma atualização contínua não reduza a capacidade de serviço (#66267). Uma atualização contínua cujas novas réplicas continuam falhando agora para em DEPLOY_FAILED e deixa as réplicas antigas restantes roteáveis, em vez de substituir todas as réplicas íntegras (#66252, #66290).
  • Segurança: Ray Data agora rejeita colunas de objetos em conserva em todos os leitores que desserializam dados Arrow de entrada externa, fechando um caminho de execução remota de código nos leitores LeRobot, Databricks, Iceberg, Hugging Face, ClickHouse, BigQuery e Delta Sharing (#66042, #65769). Imagens de raio e construções de roda pinam certifi 2026.10.19 e pip 26.2.2 após o comprometimento do eMudhra CA, e aiohttp muda para 3.14.4 para CVE-2026-111064 e CVE-2026-111066 (#67295, #67298, #67301, #67304, #67305, #67350).

Ray servir

🎉 Novos recursos

  • Métricas de escalonamento automático colunar. Os roteadores agora enviam relatórios de métricas de identificador como matrizes numéricas planas em vez de objetos Python em conserva por padrão, e o controlador os mescla em uma passagem vetorizada, reduzindo o custo do loop do controlador em 2,8x–13,5x em 64–4.096 réplicas por identificador; defina RAY_SERVE_COLUMNAR_AUTOSCALING_METRICS=0 para reverter (#64281, #66104, #66105, #66070, #66240). O esquema de integridade do controlador também informa quanto de cada loop de controle vai para a ingestão de métricas (#66106).
  • Surge atualizações contínuas. A nova opção de implantação do max_surge_percent inicia novas réplicas antes de interromper as antigas, mantendo a capacidade no destino durante uma atualização contínua; o padrão 0 mantém o comportamento existente de parar e iniciar (#66267).
  • Compactação de nós para agendamento de pacotes. Com RAY_SERVE_USE_PACK_SCHEDULING_STRATEGY=1, uma vez que todas as implantações estão estáveis, o controlador migra as réplicas de um nó parcialmente usado para que o escalonador automático possa liberá-lo, iniciando as substituições antes de interromper os originais para que a capacidade nunca diminua; ajuste-o com RAY_SERVE_NODE_COMPACTION_DELAY_S e configurações relacionadas (#66108).
  • Reflexão do servidor gRPC. Ferramentas como grpcurl, grpcui e Postman agora podem descobrir e chamar serviços Serve gRPC por meio do proxy gRPC sem arquivos proto locais; a reflexão está ativada por padrão e pode ser desativada com gRPCOptions(enable_reflection=False) ou --grpc-disable-reflection (#65854).
  • Multiplexação de modelo para entrada direta e RoundRobinRouter. As implantações de entrada direta aceitam IDs de modelo multiplexados em HTTP e gRPC (#65678), e RoundRobinRouter prefere réplicas que já hospedam o modelo solicitado (#65679).
  • Políticas de escalonamento automático personalizadas chegam à versão beta. O recurso sai do experimental (#66058) e um novo alfa PrometheusQueryMixin permite que as políticas sejam dimensionadas nas métricas Prometheus, mantendo os resultados da consulta PromQL atualizados em um thread em segundo plano, para que as leituras nunca sejam bloqueadas em chamadas de rede (#65884).

💫 Melhorias

  • Os métodos de sincronização são executados em um pool de threads por padrão. O bloqueio de E/S síncrona em métodos de implantação de sincronização não paralisa mais o loop de eventos da réplica; implantações cujo estado compartilhado não é thread-safe podem restaurar o comportamento antigo com RAY_SERVE_RUN_SYNC_IN_THREADPOOL=0 (#66436).
  • _to_object_ref() sem bloqueio. DeploymentResponse._to_object_ref() agora retorna assim que a solicitação é atribuída a uma réplica em vez de esperar pelo resultado da réplica (#65243).
  • Atualizações contínuas com falha mais seguras. Quando uma atualização contínua falha, as réplicas antigas sobreviventes continuam servindo o tráfego (#66252) e a atualização para no limite de falha de inicialização e permanece DEPLOY_FAILED (inclusive nas reinicializações do controlador) em vez de substituir todas as réplicas antigas íntegras; desative com RAY_SERVE_STOP_FAILED_ROLLING_UPDATES=0 (#66290).
  • Padrões do HAProxy de produção. As tentativas de conexão agora são limitadas a 5s e o tráfego ativo marca as réplicas inativas sem esperar por uma verificação de integridade, portanto, as novas tentativas alcançam uma réplica íntegra mais cedo (#65729). O buffer de entrada cresce de 256 KiB para 8 MiB, de modo que o roteamento LLM com reconhecimento de corpo vê solicitações completas de um milhão de tokens, com maxconn reduzido de 20.000 para 4.096 para limitar a memória do buffer (#66360).
  • Drenação elegante da réplica do HAProxy. Depois que a janela de cancelamento de registro termina, uma réplica de drenagem de entrada direta por trás do HAProxy fecha seu ouvinte HTTP, de modo que as solicitações atrasadas de trabalhadores do HAProxy obsoletos são recusadas e tentadas novamente em outra réplica em vez de falharem no meio do voo; isso removeu ~40 erros client por evento de interrupção pontual em uma frota de teste (#65698).
  • Drenagem normal na preempção do nó. O controlador agora vê os nós que Ray marcou como drenagem (por exemplo, quando ray start --block recebe SIGTERM), então a lógica existente do Serve migra réplicas e proxies deles em vez de falhar nas solicitações em andamento (#65502).
  • Agregação de métricas somente do controlador. As métricas de escalonamento automático agora são sempre agregadas no controlador, o que é correto entre fontes e para agregação max/min; o sinalizador RAY_SERVE_AGGREGATE_METRICS_AT_CONTROLLER é removido e, como o padrão está desativado, isso altera o comportamento padrão (#65714). O controlador também não reagrega mais solicitações apenas para gravar a linha de log de escalabilidade (#64654).

🔨 Correções

  • root_path compatível com ASGI (quebra). root_path agora segue a especificação ASGI em todos os modos de entrada, corrigindo a entrada direta retornando 404 para cada solicitação (incluindo /-/healthz) e HAProxy removendo o prefixo duas vezes; uvicorn foi atualizado para 0.53 (mínimo 0.26). Solicitações que ainda incluem o prefixo root_path agora retornam 404, então remova-o na sua entrada ou desmarque root_path (#66446).
  • Regressão de importação jinja2. from ray import serve não falha mais em imagens finas sem jinja2 (uma regressão 2.57); jinja2 agora é importado preguiçosamente e declarado no extra serve (#65542).
  • Solicitações encalhadas no roteamento. As tarefas de roteamento agora permanecem ativas até que atribuam a solicitação que possuem; anteriormente, uma saída antecipada poderia deixar as solicitações aguardando para sempre com roteadores de correspondência exata, como KVAwareRouter (#66325).
  • Correções de roteamento multiplexado. O roteamento por meio de um roteador de solicitação de entrada agora tenta novamente em vez de retornar HTTP 503 enquanto os metadados de localização do modelo se propagam (#66170) e réplicas mortas são descartadas do mapa de modelo multiplexado, evitando que um KeyError encalhe solicitações silenciosamente (#66358).
  • Correções de agendamento de gangue. O grupo de posicionamento compartilhado de uma gangue agora é removido somente quando seu último membro para, em vez de matar irmãos que ainda estavam servindo (#66221), e o controlador não trava mais na recuperação quando o estado Ray API está inacessível durante a detecção de vazamento do grupo de posicionamento (#66149).
  • Liberação do nó proxy para escalabilidade até zero. As réplicas do roteador de solicitação de entrada não mantêm mais seu nó proxy ativo depois que as réplicas do aplicativo param, portanto, aplicativos de escalabilidade até zero podem liberar o nó (#65824).
  • Correções de reimplantação e remoção de implantação. Reimplantar uma implantação enquanto sua versão anterior ainda está sendo desmontada não aciona mais rejeições falsas de DeploymentUnavailableError (#66323) e remover uma implantação de um aplicativo com escalonamento automático em nível de aplicativo não gera mais um KeyError que paralisa o loop de controle do aplicativo (#66438).
  • Remoção da substituição de configuração. A remoção de uma opção da configuração de uma implantação agora restaura o valor definido no código em vez de manter a substituição antiga (#66266).
  • Métricas de identificador seguras para a distorção do relógio. A desatualização da métrica do identificador agora é medida a partir do momento em que o controlador recebeu o relatório, portanto, a distorção do relógio entre os nós não descarta mais métricas novas antecipadamente ou mantém os identificadores obsoletos ativos (#66307).
  • Métrica de desligamento do proxy. A métrica de duração do desligamento do proxy agora é registrada para cada proxy interrompido e mede todo o desligamento em vez de uma única iteração do loop de controle (#66151).
  • Manipuladores de métodos registrados grpcio. O proxy gRPC agora roteia serviços registrados por meio do manipulador de métodos registrados mais recente do grpcio, API, que anteriormente ignorava o roteamento de solicitação do Serve (#66502).

Highlights

  • Ray Data shuffle and Parquet reads: In this Ray release, shuffle v2 is the default shuffle strategy for joins, aggregations (#66260). Parquet reads now size read tasks from the row-group metadata in each file's footer instead of estimating from file size, so read tasks are packed to an accurate byte budget (#65596, #65806, #65821).
  • Ray Serve rolling updates: We've added max_surge_percent, which starts replacement replicas before stopping old ones so a rolling update doesn't reduce serving capacity (#66267). A rolling update whose new replicas keep failing now stops at DEPLOY_FAILED and leaves the remaining old replicas routable, instead of replacing every healthy replica (#66252, #66290).
  • Security: Ray Data now rejects pickled-object columns in every reader that deserializes Arrow data from external input, closing a remote code execution path in the LeRobot, Databricks, Iceberg, Hugging Face, ClickHouse, BigQuery, and Delta Sharing readers (#66042, #65769). Ray images and wheel builds pin certifi 2026.10.19 and pip 26.2.2 after the eMudhra CA compromise, and aiohttp moves to 3.14.4 for CVE-2026-111064 and CVE-2026-111066 (#67295, #67298, #67301, #67304, #67305, #67350).

Ray Serve

🎉 New Features

  • Columnar autoscaling metrics. Routers now send handle metric reports as flat numeric arrays instead of pickled Python objects by default, and the controller merges them in one vectorized pass, cutting controller loop cost by 2.8x–13.5x at 64–4,096 replicas per handle; set RAY_SERVE_COLUMNAR_AUTOSCALING_METRICS=0 to revert (#64281, #66104, #66105, #66070, #66240). The controller health schema also reports how much of each control loop goes to ingesting metrics (#66106).
  • Surge rolling updates. The new max_surge_percent deployment option starts new replicas before stopping old ones, keeping capacity at the target during a rolling update; the default of 0 keeps the existing stop-then-start behavior (#66267).
  • Node compaction for pack scheduling. With RAY_SERVE_USE_PACK_SCHEDULING_STRATEGY=1, once all deployments are stable the controller migrates replicas off a partially used node so the autoscaler can release it, starting replacements before stopping the originals so capacity never dips; tune it with RAY_SERVE_NODE_COMPACTION_DELAY_S and related settings (#66108).
  • gRPC server reflection. Tools such as grpcurl, grpcui, and Postman can now discover and call Serve gRPC services through the gRPC proxy without local proto files; reflection is on by default and can be disabled with gRPCOptions(enable_reflection=False) or --grpc-disable-reflection (#65854).
  • Model multiplexing for direct ingress and RoundRobinRouter. Direct-ingress deployments accept multiplexed model IDs over both HTTP and gRPC (#65678), and RoundRobinRouter prefers replicas that already host the requested model (#65679).
  • Custom autoscaling policies reach beta. The feature graduates from experimental (#66058), and a new alpha PrometheusQueryMixin lets policies scale on Prometheus metrics by keeping PromQL query results fresh in a background thread, so reads never block on network calls (#65884).

💫 Enhancements

  • Sync methods run in a thread pool by default. Blocking synchronous I/O in sync deployment methods no longer stalls the replica's event loop; deployments whose shared state isn't thread-safe can restore the old behavior with RAY_SERVE_RUN_SYNC_IN_THREADPOOL=0 (#66436).
  • Non-blocking _to_object_ref(). DeploymentResponse._to_object_ref() now returns as soon as the request is assigned to a replica instead of waiting for the replica's result (#65243).
  • Safer failed rolling updates. When a rolling update fails, surviving old replicas keep serving traffic (#66252), and the update stops at the startup-failure threshold and stays DEPLOY_FAILED (including across controller restarts) instead of replacing every healthy old replica; opt out with RAY_SERVE_STOP_FAILED_ROLLING_UPDATES=0 (#66290).
  • Production HAProxy defaults. Connection attempts are now bounded at 5s and live traffic marks dead replicas down without waiting for a health check, so retries reach a healthy replica sooner (#65729). The ingress buffer grows from 256 KiB to 8 MiB so body-aware LLM routing sees full million-token requests, with maxconn lowered from 20,000 to 4,096 to cap buffer memory (#66360).
  • Graceful HAProxy replica draining. Once the deregistration window ends, a draining direct-ingress replica behind HAProxy closes its HTTP listener, so late requests from stale HAProxy workers are refused and retried on another replica instead of failing mid-flight; this removed ~40 client errors per spot-interruption event in a staging fleet (#65698).
  • Graceful draining on node preemption. The controller now sees nodes that Ray has marked as draining (for example, when ray start --block receives SIGTERM), so Serve's existing logic migrates replicas and proxies off them instead of failing in-flight requests (#65502).
  • Controller-only metrics aggregation. Autoscaling metrics are now always aggregated at the controller, which is correct across sources and for max/min aggregation; the RAY_SERVE_AGGREGATE_METRICS_AT_CONTROLLER flag is removed, and because it defaulted to off this changes the default behavior (#65714). The controller also no longer re-aggregates requests just to write the scaling log line (#64654).

🔨 Fixes

  • ASGI-compliant root_path (breaking). root_path now follows the ASGI spec in every ingress mode, fixing direct ingress returning 404 for every request (including /-/healthz) and HAProxy stripping the prefix twice; uvicorn is upgraded to 0.53 (minimum 0.26). Requests that still include the root_path prefix now return 404, so strip it at your ingress or unset root_path (#66446).
  • jinja2 import regression. from ray import serve no longer fails on slim images without jinja2 (a 2.57 regression); jinja2 is now imported lazily and declared in the serve extra (#65542).
  • Stranded requests in routing. Routing tasks now stay alive until they assign the request they own; previously an early exit could leave requests waiting forever with exact-match routers such as KVAwareRouter (#66325).
  • Multiplexed routing fixes. Routing through an ingress request router now retries instead of returning HTTP 503 while model-location metadata propagates (#66170), and dead replicas are dropped from the multiplexed model map, preventing a KeyError that silently stranded requests (#66358).
  • Gang scheduling fixes. A gang's shared placement group is now removed only when its last member stops, instead of killing siblings that were still serving (#66221), and the controller no longer crashes on recovery when the Ray state API is unreachable during placement group leak detection (#66149).
  • Proxy node release for scale-to-zero. Ingress request-router replicas no longer keep their proxy node alive after the application's replicas stop, so scale-to-zero apps can release the node (#65824).
  • Redeploy and deployment-removal fixes. Redeploying a deployment while its previous version is still being torn down no longer triggers spurious DeploymentUnavailableError rejections (#66323), and removing a deployment from an app with application-level autoscaling no longer raises a KeyError that stalls the application control loop (#66438).
  • Config override removal. Removing an option from a deployment's config now restores the value defined in code instead of keeping the old override (#66266).
  • Clock-skew-safe handle metrics. Handle metric staleness is now measured from when the controller received the report, so clock skew between nodes no longer drops fresh metrics early or keeps stale handles alive (#66307).
  • Proxy shutdown metric. The proxy shutdown duration metric is now recorded for every stopped proxy and measures the whole shutdown rather than a single control-loop iteration (#66151).
  • grpcio registered-method handlers. The gRPC proxy now routes services registered through grpcio's newer registered-method handler API, which previously bypassed Serve's request routing (#66502).

📖 Documentation

  • Standalone Serve CLI page. The serve CLI reference moved to its own page, matching how the other libraries' API references are organized (#65943).
  • metrics_interval_s warning. The autoscaling guide now warns that very low values can overload the controller, and the examples use the defaults (#65972).
  • KubeRay examples on ray.io/v1. The examples, including the Serve fault-tolerance guide, moved from ray.io/v1alpha1, and a RayService example that used the unsupported serveConfig field (and so deployed zero applications) was fixed (#65336).

🏗 Architecture refactoring:

  • Removed async inference queue monitor. This removes the unused QueueMonitorActor, its controller-side metric, and AutoscalingContext.total_pending_async_requests (which was always 0); AsyncInferenceAutoscalingPolicy already polls the broker directly (#66405).
  • Full serve/_private type checking. mypy and pyrefly now scan the whole serve/_private tree instead of a hand-maintained file list, so new modules are covered by default (#65653).
  • Test deflaking. Fixes span routing, metrics, gang scheduling, direct ingress, and deployment tests (#65654, #65725, #65995, #65811, #65836, #66000, #66037, #65664, #65822, #66059, #66101, #66150, #66195, #66317, #66296, #66346, #66071, #66395, #66206, #66455, #66482, #66495, #66492, #67165); the controller benchmark also now reserves per-replica memory so the 8,192-replica checkpoint no longer hits OOM kills (#65847).
