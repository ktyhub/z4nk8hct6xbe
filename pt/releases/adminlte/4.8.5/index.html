AdminLTE v4.8.5

Um patch de manutenção: a construção do AdminLTE a partir da fonte está silenciosa novamente. Nada no dist/ mudou o comportamento - o CSS compilado é idêntico em bytes ao 4.8.4, então esta versão só importa se você mesmo compilar o Sass.

Corrigido

npm run production imprimiu seis avisos de suspensão de uso do Sass.

Sass 1.95.0 descontinuado o ternário if($condition, $if-true, $if-false) em favor do CSS if(). As folhas de paleta usaram-no em três lugares – lte-needs-aa() em colors/_variables.scss e a seleção de cor de texto em colors/_primary.scss duas vezes – e como adminlte-colors.scss e adminlte-colors-v3.scss extraem essas parciais, três locais de chamada produziram seis avisos.

Agora são declarações @if simples. Deliberadamente não a sintaxe if(sass(cond): a; else: b) que Sass sugere: isso exigiria Sass >= 1.95 de todos que compilassem AdminLTE a partir do código-fonte, e nós enviamos o SCSS. @if compila em todas as versões, produz CSS com bytes idênticos e permanece limpo com estilo.

Vale a pena registrar para quem segue esse upstream: o Bootstrap usa o ternário if() 82 vezes no bootstrap/scss e avisa também - mas o css-compile já passa pelo --quiet-deps, então nada disso chega ao seu console. Cada aviso neste relatório era o código do próprio AdminLTE (#6111, relatado por @lfiorini).

Manutenção

  • Dependências de desenvolvimento atualizadas — sass 1.102.0 → 1.103.0, astro 7.2.3 → 7.2.4, @astrojs/mdx 7.0.6 → 7.0.7, happy-dom 20.11.2 → 20.11.6. Todos dentro de suas especialidades atuais.
  • A compilação dos documentos saiu do obsoleto markdown.rehypePlugins do Astro. Astro 7.2.4 descontinua as chaves remarkPlugins / rehypePlugins / remarkRehype de nível superior em favor de um markdown.processor explícito - o que teria colocado um novo aviso no próprio comando deste lançamento. O plugin de tabelas responsivas agora passa por unified() de @astrojs/markdown-remark; mesmo pipeline, todas as 90 páginas construídas com bytes idênticos.
  • nanoid passou para 3.3.18 no lockfile — GHSA-2v37-7h3g-55p8 (alto), transitivo e somente dev. npm audit agora relata zero vulnerabilidades. Nada enviado no dist/ foi afetado.
  • TypeScript permanece em 6.0.3. 7.0.2 está fora, mas typescript-eslint ainda declara peerDependencies.typescript: ">=4.8.4 <6.1.0" e @astrojs/check aceita ^5 || ^6, então o conjunto de ferramentas ainda não pode se mover.

AdminLTE v4.8.5

Highlights

  • Zero runtime delta — source-only housekeeping — dist/ is byte-identical to 4.8.4: same compiled CSS, same JS. CDN/dist/ consumers get a genuine no-op; only teams compiling the shipped SCSS themselves see any change. There is no visual or behavioral fix here — the payoff is a clean npm run production log.

  • Six Sass deprecation warnings gone (#6111) — Sass 1.95.0 deprecated the ternary if($cond, $a, $b), and three AdminLTE call sites (lte-needs-aa() in colors/_variables.scss plus two text-colour picks in colors/_primary.scss) fan out through both adminlte-colors.scss and adminlte-colors-v3.scss to emit six warnings. Rewritten as plain @if, so warning-gated CI stops tripping (reported by @lfiorini).

  • Deliberate choice of @if over Sass's suggested if() — The new if(sass(cond): a; else: b) form would force Sass ≥ 1.95 on everyone compiling AdminLTE's SCSS; @if works on all versions, emits byte-identical CSS, and stays stylelint-clean. That compatibility floor is intentional — if you maintain overrides, this signals AdminLTE won't raise your minimum Sass version.

  • Docs build off deprecated Astro config — Astro 7.2.4 deprecates top-level remarkPlugins/rehypePlugins/remarkRehype in favour of markdown.processor; leaving the responsive-tables plugin on the old key would have injected a fresh warning into the very command being cleaned up. It now goes through unified() from @astrojs/markdown-remark, with all 90 pages byte-identical — relevant only if you fork the docs pipeline.

  • Dev supply chain and toolchain pins — nanoid → 3.3.18 in the lockfile closes GHSA-2v37-7h3g-55p8 (high, transitive/dev-only; nothing in dist/ was ever affected), taking npm audit to zero, while sass 1.103.0, astro 7.2.4, @astrojs/mdx 7.0.7 and happy-dom 20.11.6 stay within majors. TypeScript stays at 6.0.3 because typescript-eslint (>=4.8.4 <6.1.0) and @astrojs/check (^5 || ^6) block 7.0.2 — don't plan a TS 7 move on this release.

No breaking changes.

A housekeeping patch: building AdminLTE from source is quiet again. Nothing in dist/ changed behaviour — the compiled CSS is byte-identical to 4.8.4, so this release matters only if you compile the Sass yourself.

Fixed

npm run production printed six Sass deprecation warnings.

Sass 1.95.0 deprecated the ternary if($condition, $if-true, $if-false) in favour of the CSS if(). The palette sheets used it in three places — lte-needs-aa() in colors/_variables.scss, and the text-colour pick in colors/_primary.scss twice — and since both adminlte-colors.scss and adminlte-colors-v3.scss pull those partials in, three call sites produced six warnings.

They are now plain @if statements. Deliberately not the if(sass(cond): a; else: b) syntax Sass suggests: that would require Sass >= 1.95 of everyone compiling AdminLTE from source, and we ship the SCSS. @if compiles on every version, produces byte-identical CSS, and stays stylelint-clean.

Worth recording for anyone who chases this upstream: Bootstrap uses the ternary if() 82 times across bootstrap/scss and warns too — but css-compile already passes --quiet-deps, so none of that reaches your console. Every warning in this report was AdminLTE's own code (#6111, reported by @lfiorini).

Maintenance

  • Dev dependencies refreshed — sass 1.102.0 → 1.103.0, astro 7.2.3 → 7.2.4, @astrojs/mdx 7.0.6 → 7.0.7, happy-dom 20.11.2 → 20.11.6. All within their current majors.
  • The docs build moved off Astro's deprecated markdown.rehypePlugins. Astro 7.2.4 deprecates the top-level remarkPlugins / rehypePlugins / remarkRehype keys in favour of an explicit markdown.processor — which would have put a fresh warning into the very command this release is about. The responsive-tables plugin now goes through unified() from @astrojs/markdown-remark; same pipeline, all 90 built pages byte-identical.
  • nanoid bumped to 3.3.18 in the lockfile — GHSA-2v37-7h3g-55p8 (high), transitive and dev-only. npm audit now reports zero vulnerabilities. Nothing shipped in dist/ was ever affected.
  • TypeScript stays on 6.0.3. 7.0.2 is out, but typescript-eslint still declares peerDependencies.typescript: ">=4.8.4 <6.1.0" and @astrojs/check accepts ^5 || ^6, so the toolchain still cannot move.

npm install admin-lte@4.8.5
