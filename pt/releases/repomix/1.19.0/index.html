#repomix v1.19.0

Esta versão move o servidor MCP para SDK v2 com progresso e cancelamento ao vivo, torna a saída do --compress muito mais precisa e traz uma grande rodada de correções de bugs de colaboradores iniciantes!

Novidades 🚀

Servidor MCP em SDK v2 e o protocolo 2026-07-28 (#1952, #1954)

O servidor MCP agora é executado no MCP TypeScript SDK v2. Os Clients que suportam o protocolo 2026-07-28 negociam-no automaticamente e os clients existentes funcionam como antes.

  • O servidor sai de forma limpa quando o client fecha o stdin, portanto nenhum processo repomix --mcp é deixado para trás.
  • A instalação extrai cerca de metade dos pacotes (171 a 84), já que a v1 SDK trouxe dependências de transporte HTTP como Express que o servidor somente stdio nunca usou.

Para autores de client: os esquemas de ferramentas agora declaram o esquema JSON 2020-12 (corpos inalterados) e os erros de validação não começam mais com MCP error -32602: .

MCP: Progresso e cancelamento para pacotes de longa duração (#1955, #1958)

pack_codebase, pack_remote_repository e generate_skill agora enviam notifications/progress quando o client passa por um progressToken, então pacotes longos mostram status ativo e clients que redefinem seu tempo limite no progresso não os cortam mais. No modo --sandbox, as mensagens carregam apenas o nome do estágio, nunca um caminho de host.

Cancelar ou desconectar uma chamada agora interrompe o pacote e limpa sua saída parcial.

Melhorias ⚡

Saída --compress mais precisa (#2003)

Os testes de ouro para cada linguagem suportada expuseram um conjunto de bugs, agora corrigidos:

  • O código dos corpos funcionais não vaza mais na saída como se fosse uma declaração.
  • Linhas duplicadas são removidas.
  • Declarações que foram descartadas silenciosamente são mantidas, como C/C++ typedef e #define, campos C# e Java, campos struct Rust, chamadas Ruby attr_* e regras CSS.

Mudanças de saída para C, C++, C#, CSS, Dart, Go, Java, JavaScript/TypeScript, Ruby, Rust, Swift e Vue. Se você confia no --compress em um pipeline, espere uma diferença do v1.18.

Geração de habilidades: melhor detecção de pilha de tecnologia (#1995)

--skill-generate agora lê dependências do Gradle Kotlin DSL (build.gradle.kts) e das formas PEP 621 e Poetry do pyproject.toml.

Aviso quando um caminho de URL remoto é ignorado (#1980, #1984, #433)

Uma URL como https://github.com/owner/repo/tree/main/src/shared compactava todo o repositório e eliminava silenciosamente o caminho. O Repomix agora avisa e sugere um padrão --include:

The path "src/shared" in the remote URL is ignored, and the whole repository will be packed.
To pack only that path, add: --include "src/shared/**"

Correções de bugs 🐛

Ignorar padrões que terminam em curinga agora exclui arquivos (#1963, #1876, #320)

Padrões como **/npm-debug.log* e **/repomix-output.* excluíam apenas o conteúdo do diretório, então arquivos como npm-debug.log.1 e docs/repomix-output.xml entravam na saída. Eles agora estão excluídos. Nada do que antes era excluído é incluído.

.git/info/exclude segue as regras de correspondência do Git (#1871, #1870)

Um padrão sem barras como secret.txt agora corresponde em qualquer profundidade, como no Git, então sub/secret.txt não é mais compactado.

Agradecimentos especiais a @sxh313 por esta contribuição! 🎉

Padrões de ignorar personalizados negados que não são mais invertidos (#1975, #400)

!main.ts em ignore.customPatterns ou --ignore excluiu main.ts em vez de incluí-lo novamente. Os padrões negados agora são ignorados com um aviso até que o suporte adequado chegue (#400).

Dividir arquivos de saída que não são mais empacotados na próxima execução (#1921, #1920)

Com --split-output, arquivos como repomix-output.1.xml de uma execução anterior não são mais obtidos como entrada.

Agradecimentos especiais a @lorenzozanee pela primeira contribuição! 🎉

--remove-comments mantém URLs em CSS, SCSS, Less, Vue e Svelte (#1912, #1965, #1911)

url(http://example.com/logo.png) foi cortado para url(http: porque // foi tratado como um comentário. Cada linguagem agora usa suas próprias regras de comentários, e os arquivos Vue e Svelte são tratados por <script>, <style> e seção de marcação.

Agradecimentos especiais a @plox-sumit pela sua primeira contribuição! 🎉

Nomes de arquivos não ASCII em registros e diferenças do Git (#1940, #1979)

Nomes como 日本語.txt não aparecem mais como "\346\227\245..." em logs e diferenças do git, e output.git.sortByChanges agora classifica esses arquivos corretamente.

Agradecimentos especiais a @ feiiiiii5 pela sua primeira contribuição! 🎉

--token-count-tree 0 mostra a árvore completa (#1941)

Não imprimiu nada antes; agora mostra todos os arquivos.

Agradecimentos especiais a @ feiiiiii5 por esta contribuição! 🎉

Caminhos --stdin aninhados no Windows (#1922)

Caminhos de tubulação como src/(routes)/page[1].ts para repomix --stdin no Windows compactam apenas arquivos de nível raiz. Os caminhos aninhados agora correspondem.

Agradecimentos especiais a @lux-liang pela primeira contribuição! 🎉

Erros fatais visíveis em --quiet e --stdout (#1875, #1874)

Um pacote com falha em --quiet ou --stdout saiu com o código 1 e não imprimiu nada. O erro agora vai para stderr.

Agradecimentos especiais a @sxh313 por esta contribuição! 🎉

Correções do servidor MCP (#1867, #1866, #1865, #1864, #1869, #1868)

  • --mcp --verbose não grava mais diagnósticos em stdout, onde clients os lê como quadros de protocolo. (#1867)
  • O registro de erros não é mais silenciado pelo resto da sessão após uma chamada generate_skill ou pack_remote_repository. (#1865)
  • grep_repomix_output agora formata contexto como grep -C e lida com saídas muito grandes. (#1869)

Agradecimentos especiais a @sxh313 pela sua primeira contribuição! 🎉

Fortalecimento de segurança 🔒

MCP pack_codebase sempre executa a verificação secreta (#1960)

Um repomix.config.json no diretório compactado pode desativar a verificação secreta de pacotes MCP com security.enableSecurityCheck: false. A varredura agora sempre é executada para pacotes MCP; execuções simples do CLI ainda seguem o arquivo de configuração.

Documentação 📚

Os documentos do MCP agora afirmam que sem --sandbox, pack_codebase trusts o repomix.config.* no diretório que ele empacota, assim como executar o CLI lá. Use --sandbox quando seu assistente puder compactar diretórios não rusted, como repositórios clonados de terceiros. (#1961)

Consulte Servidor MCP: Modo Sandbox e Por que um arquivo de configuração é um código.

Como atualizar

npm update -g repomix

Como sempre, se você tiver algum problema ou sugestão, informe-nos sobre os problemas do GitHub ou sobre nossa [comunidade Discord] (https://discord.gg/wNYzTwZFku).

repomix v1.19.0

This release moves the MCP server to SDK v2 with live progress and cancellation, makes --compress output far more accurate, and brings a big round of bug fixes from first-time contributors!

What's New 🚀

MCP Server on SDK v2 and the 2026-07-28 Protocol (#1952, #1954)

The MCP server now runs on the MCP TypeScript SDK v2. Clients that support the 2026-07-28 protocol negotiate it automatically, and existing clients work as before.

  • The server exits cleanly when the client closes stdin, so no repomix --mcp processes are left behind.
  • The install pulls in about half as many packages (171 to 84), since the v1 SDK brought HTTP transport dependencies such as Express that the stdio-only server never used.

For client authors: tool schemas now declare JSON Schema 2020-12 (bodies unchanged), and validation errors no longer start with MCP error -32602: .

MCP: Progress and Cancellation for Long-Running Packs (#1955, #1958)

pack_codebase, pack_remote_repository and generate_skill now send notifications/progress when the client passes a progressToken, so long packs show live status, and clients that reset their timeout on progress no longer cut them off. In --sandbox mode, messages carry only the stage name, never a host path.

Cancelling a call or disconnecting now stops the pack and cleans up its partial output.

Improvements ⚡

More Accurate --compress Output (#2003)

Golden tests for every supported language exposed a set of bugs, now fixed:

  • Code from function bodies no longer leaks into the output as if it were a declaration.
  • Duplicate lines are removed.
  • Declarations that were silently dropped are kept, such as C/C++ typedef and #define, C# and Java fields, Rust struct fields, Ruby attr_* calls and CSS at-rules.

Output changes for C, C++, C#, CSS, Dart, Go, Java, JavaScript/TypeScript, Ruby, Rust, Swift and Vue. If you rely on --compress in a pipeline, expect a diff from v1.18.

Skill Generation: Better Tech-Stack Detection (#1995)

--skill-generate now reads dependencies from Gradle Kotlin DSL (build.gradle.kts) and from the PEP 621 and Poetry forms of pyproject.toml.

Warning When a Remote URL Path Is Ignored (#1980, #1984, #433)

A URL like https://github.com/owner/repo/tree/main/src/shared packed the whole repository and silently dropped the path. Repomix now warns and suggests an --include pattern:

The path "src/shared" in the remote URL is ignored, and the whole repository will be packed.
To pack only that path, add: --include "src/shared/**"

Bug Fixes 🐛

Ignore Patterns Ending in a Wildcard Now Exclude Files (#1963, #1876, #320)

Patterns such as **/npm-debug.log* and **/repomix-output.* only excluded directory contents, so files like npm-debug.log.1 and docs/repomix-output.xml slipped into the output. They are now excluded. Nothing that was excluded before becomes included.

.git/info/exclude Follows Git's Matching Rules (#1871, #1870)

A slash-free pattern such as secret.txt now matches at any depth, as in Git, so sub/secret.txt is no longer packed.

Special thanks to @sxh313 for this contribution! 🎉

Negated Custom Ignore Patterns No Longer Invert (#1975, #400)

!main.ts in ignore.customPatterns or --ignore excluded main.ts instead of re-including it. Negated patterns are now skipped with a warning until proper support lands (#400).

Split Output Files No Longer Packed into the Next Run (#1921, #1920)

With --split-output, files like repomix-output.1.xml from a previous run are no longer picked up as input.

Special thanks to @lorenzozanee for their first contribution! 🎉

--remove-comments Keeps URLs in CSS, SCSS, Less, Vue and Svelte (#1912, #1965, #1911)

url(http://example.com/logo.png) was cut to url(http: because // was treated as a comment. Each language now uses its own comment rules, and Vue and Svelte files are handled per <script>, <style> and markup section.

Special thanks to @plox-sumit for their first contribution! 🎉

Non-ASCII File Names in Git Logs and Diffs (#1940, #1979)

Names like 日本語.txt no longer appear as "\346\227\245..." in git logs and diffs, and output.git.sortByChanges now sorts these files correctly.

Special thanks to @feiiiiii5 for their first contribution! 🎉

--token-count-tree 0 Shows the Full Tree (#1941)

It printed nothing before; it now shows every file.

Special thanks to @feiiiiii5 for this contribution! 🎉

Nested --stdin Paths on Windows (#1922)

Piping paths such as src/(routes)/page[1].ts into repomix --stdin on Windows packed only root-level files. Nested paths now match.

Special thanks to @lux-liang for their first contribution! 🎉

Fatal Errors Visible Under --quiet and --stdout (#1875, #1874)

A failed pack under --quiet or --stdout exited with code 1 and printed nothing. The error now goes to stderr.

Special thanks to @sxh313 for this contribution! 🎉

MCP Server Fixes (#1867, #1866, #1865, #1864, #1869, #1868)

  • --mcp --verbose no longer writes diagnostics to stdout, where clients read them as protocol frames. (#1867)
  • Error logging is no longer silenced for the rest of the session after a generate_skill or pack_remote_repository call. (#1865)
  • grep_repomix_output now formats context like grep -C and handles very large outputs. (#1869)

Special thanks to @sxh313 for their first contribution! 🎉

Security Hardening 🔒

MCP pack_codebase Always Runs the Secret Scan (#1960)

A repomix.config.json in the packed directory could turn off the secret scan for MCP packs with security.enableSecurityCheck: false. The scan now always runs for MCP packs; plain CLI runs still follow the config file.

Documentation 📚

The MCP docs now state that without --sandbox, pack_codebase trusts the repomix.config.* in the directory it packs, just like running the CLI there. Use --sandbox when your assistant may pack untrusted directories, such as cloned third-party repositories. (#1961)

See MCP Server: Sandbox Mode and Why a config file is code.

How to Update

npm update -g repomix

As always, if you have any issues or suggestions, please let us know on GitHub issues or our Discord community.
