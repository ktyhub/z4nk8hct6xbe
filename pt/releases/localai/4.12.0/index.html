LocalAI 4.12.0 foi lançado!

Esta versão redesenha a UI da web e adiciona streaming de respostas de voz, roteamento de decisão nativo e mais controle sobre a memória do modelo e o estado do prompt. Ele também adiciona aumento de imagem, captura de movimento ao vivo, armazenamento Qdrant e histórico de bate-papo autenticado. É também uma preparação para o próximo lançamento, que incluirá suporte a complementos. Nosso plano é mover alguns componentes (por exemplo, Studio, Talk) para complementos separados que podem ser instalados sob demanda do LocalAI.

Destaques:

  • 🖥️ IU da web redesenhada: controles compartilhados, temas claros e escuros, fluxos de trabalho de modelos e estúdio mais claros e manutenção de back-end com escopo de nó.
  • 🎙️ Streaming de voz e modelos de áudio agrupados: alimente fragmentos LLM no Qwen TTS, use streaming de cláusulas explícitas com outros mecanismos e combine funções de análise de áudio por meio de pacotes Parakeet.
  • 🧭 Roteamento de decisão nativo: classifique solicitações com modelos de decisão e use o novo adaptador /v1/decisions para predicados, escolhas e pontuações.
  • 🖼️ Aprimoramento de imagem no Studio: crie uma imagem infantil ampliada sem sair do projeto, com um /v1/images/upscale API dedicado.
  • 🛡️ Privacidade e configuração de ferramentas: filtragem de PII de respostas, rejeição opcional de mídia não inspecionável, perfis de alias e credenciais OAuth2 client para servidores MCP remotos.
  • 🕺 Captura de movimento GEM-X ao vivo: transmita quadros RGB em uma pose limitada baseada em sessão API na CPU ou Vulkan.
  • 🗄️ Lojas Qdrant persistentes: use as lojas existentes API com TLS e credenciais baseadas no ambiente.
  • 💾 Controles de inferência: configure o cache especializado do MoE, leituras de tensor lento e salvamento e restauração de cache de prompt de slot explícito.

🚀 Novos recursos e melhorias importantes

🖥️ Uma UI web compartilhada e operações de modelo mais claras

A UI da web usa um kit CSS/SVG compartilhado, temas em tinta e azul-petróleo, controles consistentes e hubs de construção e operação com reconhecimento de permissão. Os URLs existentes permanecem disponíveis. Modelos expõe detalhes do modelo, variantes, informações de posicionamento e uso do disco. O Studio compartilha um layout de composição, trabalho, resultado e resultados recentes em seus fluxos de trabalho.

A contabilidade de armazenamento por modelo distingue os arquivos compartilhados dos arquivos específicos do modelo. Os totais agregados desduplicam os bytes compartilhados. O tamanho exibido de um modelo não é necessariamente o espaço que a exclusão dele ocupa.

As importações manuais remotas agora são executadas como trabalhos de galeria rastreados. A página de importação e o editor aguardam o sucesso da aquisição e mostram falhas ou cancelamento. As importações de arquivos locais sem downloads mantêm o comportamento síncrono. As importações enfileiradas podem aplicar padrões de inferência recomendados, portanto, defina parâmetros importantes explicitamente ao reproduzir uma configuração.

Os backends suportam a remoção confirmada de uma construção concreta de um nó selecionado. As verificações de proteção e os bloqueios de conflito evitam a remoção durante operações conflitantes. As falhas de atualização retêm o último inventário conhecido em vez de reportar um estado vazio não verificado.

🔗 PR: #12526, #12551, #12587, #12599, #12785. Importações em fila: aquisição em segundo plano e enfileiramento com reconhecimento de resolvedor.

💬 Histórico de bate-papo, controles de raciocínio e informações mais ricas

Os usuários logados podem sincronizar conversas através do /api/conversations. Caches no escopo da conta, intenções de exclusão persistentes e marcas para exclusão evitam que clients obsoletos restaurem conversas excluídas. Isso requer autenticação, WebUI habilitado e permissão chat_history. Sessões anônimas e somente com chave legada mantêm o histórico local do navegador; o histórico antigo do navegador compartilhado não é atribuído automaticamente a uma conta.

Um seletor de esforço controla a solicitação reasoning_effort por chat. Nenhum também oculta rastros de raciocínio retornados para novas respostas. /effort permanece disponível; a ação separada /reasoning é removida. Esta escolha de UI não prova que todo back-end suprime a computação de raciocínio interno.

O ditado do microfone anexa texto editável por meio de um modelo de transcrição instalado. PDFs digitalizados sem camada de texto renderizam suas primeiras dez páginas como anexos de imagem para um modelo com capacidade de visão. O Canvas oferece visualizações HTML com seu próprio CSP em uma sandbox sem allow-same-origin. As visualizações expiram após dez minutos e permanecem na memória do processo. Os recursos HTTPS externos permitidos podem ser carregados, portanto as visualizações não ficam necessariamente off-line. As implantações multifrontend precisam de roteamento que atinja o processo que contém a visualização.

🎙️ Streaming de respostas de voz e análise de áudio integrada

Qwen TTS aceita texto incremental por meio do RPC backend TTSLive opcional. Com o streaming LLM e TTS habilitado, uma expressão nativa pode começar a produzir áudio antes que a resposta completa do LLM chegue. O cancelamento e a contrapressão se propagam pelo caminho ativo; uma expressão com falha não é reproduzida após a confirmação do áudio.

pipeline:
  streaming:
    llm: true
    tts: true

Para mecanismos não nativos, pipeline.streaming.clause_chunking: true permite explicitamente a síntese de cláusulas limitadas. Deixá-lo sem definição preserva a síntese da resposta completa. A entrada Qwen nativa não usa este divisor de cláusula.

A galeria adiciona qwen3-streaming-assistant, vits-streaming-assistant e piper-streaming-assistant. Essas predefinições instalam apenas a configuração do pipeline. Instale seu componente LLM, modelo de transcrição, VAD e modelo TTS separadamente.

Os pacotes Parakeet podem desempenhar várias funções de áudio, incluindo ASR, VAD, diarização, detecção de som e codificador de alto-falante. As funções disponíveis dependem do pacote; eles não implicam uma passagem de inferência fundida. A diarização pode retornar eventos sonoros cronometrados com include_sounds.

Os modelos Parakeet equipados com alto-falantes também podem servir para incorporação e verificação de voz. As impressões digitais do codificador distinguem pesos compatíveis e os armazenamentos de voz separam diferentes dimensões de incorporação. voice_verify_threshold usa distância cosseno, o padrão é 0.5 e aceita valores entre 0 e 2. Este back-end não adiciona suporte anti-spoofing ou análise de voz.

As respostas em tempo real agora aguardam que os commits de áudio anteriores concluam a transcrição. Uma resposta em espera termina com input_not_committed se seu commit pendente não produzir nenhum item de usuário, em vez de iniciar o LLM sem esse turno. interrupt_response: false preserva uma resposta ativa enquanto retém transcrições e eventos sonoros sobrepostos.

🔗 PR: #12770, #12455, #12463, #12479, #12491, #12499, #12544, #12446. Acompanhamentos diretos: RPCs de voz do Parakeet, respostas de commit ordenadas e controle de interrupção.

🎵 Expansão de som estruturado e controles de fala

YuE2 se junta ao caminho de geração de som audio.cpp. As legendas comuns do Studio fornecem seu estilo, a menos que um parâmetro de estilo explícito as substitua. Os pesos YuE2 usam CC-BY-NC-4.0 e são limitados ao uso não comercial.

A Simple Sound pode opcionalmente usar expansion_model para transformar uma breve descrição em campos musicais validados. O comportamento da versão final requer um modelo llama-cpp com use_tokenizer_template: true e suporte de ferramenta nativo. LocalAI requer exatamente uma chamada expand_sound estrita; a prosa JSON e o texto de raciocínio não são argumentos alternativos. A expansão inválida é interrompida antes da geração de áudio.

OmniVoice expõe controles de duração e pós-processamento limitados por meio de parâmetros de fala. A duração é limitada a 30 segundos e quantizada para quadros de geração. Isso não garante uma duração final exata do WAV. O Pocket TTS também aceita uma opção de linguagem de carregamento de modelo, como options: ["language:french"].

🔗 PR: #12617, #12703, #12772, #12783, #12787, #12790, #12637, #12766.

🖼️ Aumento de escala de imagem e controles de geração adicionais

POST /v1/images/upscale fornece upscaling dedicado com verificações explícitas de capacidade do modelo. O Studio grava a saída como uma imagem secundária para que você possa continuar trabalhando no mesmo projeto. O modo ESRGAN nativo suporta agrupamento sem carregar um contexto de difusão. A escala solicitada deve corresponder à escala nativa do modelo; não é uma interpolação em escala arbitrária.

custom_sigmas expõe cronogramas de eliminação de ruído específicos de pontos de verificação. Novos assemblies Qwen Image usam essas programações; os codificadores selecionados transformam essas entradas apenas em texto para imagem. Suas licenças de modelo e codificador ainda se aplicam.

MiniMax-H3 ganha campos aditivos de imagem de referência, vídeo de referência e áudio WAV com verificações de partição e entradas limitadas. Esses campos são somente API nesta versão; React não os expõe. O suporte de origem não estabelece geração ponta a ponta em todos os pontos de verificação ou dispositivos.

🔗 PR: #12620, #12619, #12668.

🧭 Roteamento de decisão nativo e /v1/decisions

Os modelos de decisão podem classificar solicitações diretamente para um roteador, em vez de usar uma resposta geral de chat como protocolo de classificação. O caminho nativo também oferece suporte a decisões de imagem em linha limitadas com formato e projetor compatíveis.

POST /v1/decisions adapta o pipeline existente do SystemOne para predicados, escolhas e pontuações. Ele suporta até 64 perguntas e preserva opções booleanas ou de string digitadas. /v1/systemone permanece disponível.

A entrada de imagem requer um modelo de decisão com capacidade de imagem e dados PNG ou JPEG embutidos. As entradas não suportadas falham em vez de se tornarem silenciosamente decisões apenas em texto. Aplicam-se as permissões de decisões existentes e a contabilidade de uso.

Imagens llama.cpp instaladas mais antigas podem não ter suporte nativo para decisões, mesmo quando o servidor é atual. Erros de back-end obsoletos reconhecidos agora retornam um 501 orientado para atualização e marcam o back-end para atualização. Esta detecção não reconstrói uma imagem por si só.

🔗 PR: #12449, #12603, #12733.

🛡️ Controles de privacidade, perfis de modelo e autenticação MCP remota

O middleware PII agora cobre instruções de respostas recebidas, itens de texto, argumentos de função e saída de ferramenta serializada. pii.block_unscanned_media: true rejeita opcionalmente mídia que os detectores de texto não podem inspecionar. Ele bloqueia em vez de OCR ou transcreve mídia.

pii_detection:
  extend_to_next_word: [ZIPCODE]
  extend_to_previous_word: [LASTNAME]
  protected_terms: [Example Supplier]

A extensão de palavras adjacentes e os arquivos com termos protegidos adicionam controle opcional sobre o mascaramento NER. Os termos protegidos aplicam-se apenas ao NER, não aos detectores de padrões. Eles passam onde quer que o mesmo termo ocorra, portanto, coloque na lista de permissões apenas valores seguros para divulgação. As extensões podem mascarar demais.

Essas alterações não fornecem filtragem completa em todos os caminhos de solicitação. A interceptação do agente e o conteúdo histórico das respostas resolvidas permanecem lacunas. Respostas WebSockets com uma política de detector ativa são recusadas em vez de filtradas; use HTTP POST para essa política.

Os aliases podem transportar profile.system_prompt, configuração MCP e política da ferramenta client enquanto compartilham um modelo de destino carregado. mcp.auto ativa servidores configurados apenas dentro das permissões de instância e usuário. As notas opcionais de evidências numéricas são uma heurística de advertência, não uma verificação factual. Os servidores MCP remotos suportam OAuth2 client_credentials, incluindo segredos apoiados pelo ambiente e atualização automática de token. Os pontos finais de token requerem HTTPS, exceto hosts de loopback explícitos. A rotação de credenciais por meio de variáveis ​​de ambiente requer a reinicialização do processo de propriedade da conexão. A descoberta SSE legada permanece disponível com fallback restrito.

🔗 PR: #12661, #12660, #12708, #12755, #12711, #12304. Adições diretas: credenciais OAuth2, termos protegidos e extensão da palavra anterior.

🕺 Captura de movimento ao vivo GEM-X

O novo backend gemxcpp converte quadros RGB transmitidos em poses humanas por meio de /api/motion/sessions e um WebSocket duplex. Clients pode selecionar saída SOMA-77 ou SMPL-24 e usar tickets de navegador de uso único vinculados à origem.

O API limita a entrada e a contagem de sessões, em vez de acumular uma lista de pendências de captura ilimitada. Os limites incluem uma sessão por modelo, quatro por usuário e dezesseis por frontend. Clients devem seguir os créditos de controle de fluxo.

Esta integração é apenas API e suporta CPU ou Vulkan; O macOS usa CPU, não inferência de metal. Ele não fornece malha corporal, controlador de robô ou reidentificação de pessoa. O estado da sessão é local no frontend. Os pesos GEM-X possuem seus próprios termos de licença de modelo NVIDIA.

🔗 Commits: backend GEM-X e duplex API, limites de sessão por usuário e endurecimento de autenticação de soquete.

🗄️ Lojas de vetores apoiadas por Qdrant

Use backend: qdrant-store através do /stores/* API existente para persistir vetores em Qdrant. A configuração oferece suporte a TLS, autoridades de certificação personalizadas e chaves API com suporte de ambiente. O padrão gRPC do Qdrant é a porta 6334, não a porta REST 6333.

As gravações usam blocos de no máximo 500 pontos com um tempo limite por bloco. Os blocos anteriores podem permanecer gravados se um bloco posterior falhar; um conjunto inteiro não é atômico. COSINE é a métrica padrão. Outras métricas retornam pontuações brutas que não correspondem aos limites existentes baseados em cosseno.

🔗 Confirmações: backend Qdrant, gravações limitadas e compatibilidade TLS.

💾 Controles de memória do modelo e estado de prompt salvo

  • options: ["moe_cache_mib:4096"] define um orçamento de cache de GPU opcional para especialistas em MoE residentes no host. Consome VRAM e depende da carga de trabalho; caches subdimensionados podem se debater.
  • options: ["lazy_mode:on"] permite leituras lentas para tensores marcados a montante. auto mantém regras de seleção upstream; off os carrega na inicialização. Bifurcações sem campo avisam e ignoram a opção.
  • options: ["slot_save_path:/var/lib/localai/slots"] permite salvar/restaurar slot de administrador por meio de /v1/slots/save e /v1/slots/restore. O estado de prompt salvo sobrevive ao descarregamento do modelo. Use configurações compatíveis de modelo, quantização e contexto; arquivos salvos são dados confidenciais.

A persistência de slot é somente POSIX, mantém no máximo 32 salvamentos por modelo e não coordena vários processos que compartilham um diretório. Um slot ocupado aguarda sua solicitação ativa. Esses controles não implicam latência em toda a versão ou melhoria de memória.

🔗 PR: #12729, #12743, #12730.

🔧 Recuperação distribuída e diagnóstico opcional

As implantações PostgreSQL/NATS ganham gerações de carga, concessões, watchdogs de trabalhadores e cancelamento específico de tentativa por meio do POST /api/models/:id/load-cancel. Atualize os front-ends primeiro. O padrão de ressincronização da configuração do modelo é 30 segundos por meio de --model-config-resync-interval. A descoberta de coleção Root PostgreSQL agora usa um registro compartilhado entre frontends. As coleções por usuário estão fora dessa mudança. O descarregamento direcionado libera o modelo nomeado em vez de um back-end de trabalho arbitrário. Estas são alterações de modo distribuído NATS, não recursos de federação libp2p.

A intenção de parada do administrador não se torna durável pela ressincronização de configuração: as políticas de réplica ainda podem reiniciar um modelo interrompido. Não trate a ressincronização como uma política de parada persistente.

O --pprof opcional expõe um perfilador somente de loopback numérico separado. --request-phase-timing registra fases de frontend sem adicionar testes de sistema de arquivos. Os perfis podem conter dados confidenciais e adicionar sobrecarga; não exponha o criador de perfil por meio de entrada pública. Essas medições cobrem o frontend Go, não a inferência da GPU nos trabalhadores.

🔗 PR: #12524, #12558, #12536, #12537, #12610, #12616.

LocalAI v4.12.0

Highlights

  • Native decision routing — LocalAI can now classify with dedicated decision models instead of parsing a general chat reply, exposed as POST /v1/decisions for predicates, choices and typed scores (up to 64 questions, boolean/string choices preserved), with /v1/systemone left intact (#12449, #12603, #12733). This removes a brittle "chat-as-classifier" protocol for router and agent builders. Watch out: inline image decisions require an image-capable decision model with PNG/JPEG data, and stale llama.cpp images return an upgrade-oriented 501 that flags the backend for upgrade but won't rebuild it for you.
  • Streaming voice responses — Qwen TTS accepts incremental text via the new TTSLive backend RPC, so with pipeline.streaming.llm/tts: true audio starts before the full LLM reply arrives; non-native engines need opt-in pipeline.streaming.clause_chunking: true, and the new *-streaming-assistant gallery presets install pipeline config only, not component models (#12770, #12455, #12463, #12499). The payoff is much lower time-to-first-audio for voice agents. Watch out: realtime responses now wait for earlier audio commits (input_not_committed if a pending commit yields no user item), and Parakeet bundles expose speaker embedding/verification via voice_verify_threshold (cosine distance, default 0.5) with no anti-spoofing guarantees.
  • Workload-specific memory and prompt-state controls — moe_cache_mib:<n>, lazy_mode:on|auto|off, and slot_save_path with /v1/slots/save and /v1/slots/restore let you trade VRAM for host-resident MoE experts, defer marked tensor reads, and persist prompt caches across model unloads (#12729, #12743, #12730). Useful for long-lived agents, but these are opt-in tuning knobs, not a blanket speedup: slot persistence is POSIX-only, capped at 32 saves per model, stores sensitive prompt data, and an undersized MoE cache will thrash.
  • PII filtering extends to Responses; remote MCP gets OAuth2 — PII middleware now covers incoming Responses instructions, text items, function arguments and serialized tool output, adding pii.block_unscanned_media, NER protected terms and adjacent-word extension (#12661, #12660, #12708), while remote MCP servers support OAuth2 client_credentials with env-backed secrets and automatic token refresh (#12755, #12711). For compliance-sensitive adopters this is the headline security change, but it is explicitly not end-to-end: agent interception and resolved historical Responses remain gaps, and Responses WebSockets are refused outright when a detector policy is active — use HTTP POST. Token endpoints require HTTPS (except explicit loopback), and rotating credentials via env vars requires restarting the connection-owning process.
  • Account-scoped chat history; /reasoning action removed — Signed-in users get server-side conversation sync through /api/conversations, gated on authentication + WebUI + the chat_history permission; anonymous and legacy-key sessions stay browser-local, and old shared browser history is not migrated into an account (#12663, #12788, #12716). For automation the breaking change to note is that /reasoning is gone — use the unified reasoning_effort picker or the still-available /effort — and Canvas previews now run in a sandboxed CSP with a 10-minute in-memory expiry, so multi-frontend deployments must route to the process holding the preview.
  • Persistent Qdrant stores and new generation APIs — backend: qdrant-store plugs into the existing /stores/* API with TLS, custom CAs and env-backed keys; POST /v1/images/upscale adds native-ESRGAN tiling and records output as a Studio child image (#12620, #12619, #12668); and the gemxcpp backend streams RGB frames into bounded pose sessions over a duplex WebSocket. The operational gotchas matter more than the feature list: Qdrant's gRPC default is 6334 (not REST 6333), writes are non-atomic 500-point chunks, COSINE is the default and other metrics return raw scores that break cosine-based thresholds, upscale scale must match the model's native scale, and GEM-X is API-only (CPU/Vulkan; macOS CPU) with no mesh or controller output.

🎉 LocalAI 4.12.0 Release! 🚀

<h1 align="center"> <br> <img height="300" src="https://raw.githubusercontent.com/mudler/LocalAI/refs/heads/master/core/http/static/logo.png"> <br> <br> </h1>

LocalAI 4.12.0 is out!

This release redesigns the web UI and adds streaming voice responses, native decision routing, and more control over model memory and prompt state. It also adds image upscaling, live motion capture, Qdrant stores, and authenticated chat history. It is also a preparation for the upcoming release which will include addon support. Our plan is to move few components (e.g. Studio, Talk) to separate add-ons that can be installed on-demand from LocalAI.

Highlights:

  • 🖥️ Redesigned web UI: shared controls, light and dark themes, clearer Models and Studio workflows, and node-scoped backend maintenance.
  • 🎙️ Streaming voice and bundled audio models: feed LLM fragments into Qwen TTS, use explicit clause streaming with other engines, and combine audio analysis roles through Parakeet bundles.
  • 🧭 Native decision routing: classify requests with decision models and use the new /v1/decisions adapter for predicates, choices, and scores.
  • 🖼️ Image upscaling in Studio: create an upscaled child image without leaving the project, with a dedicated /v1/images/upscale API.
  • 🛡️ Privacy and tool configuration: Responses PII filtering, opt-in rejection of uninspectable media, alias profiles, and OAuth2 client credentials for remote MCP servers.
  • 🕺 Live GEM-X motion capture: stream RGB frames into a bounded, session-based pose API on CPU or Vulkan.
  • 🗄️ Persistent Qdrant stores: use the existing stores API with TLS and environment-backed credentials.
  • 💾 Inference controls: configure MoE expert caching, lazy tensor reads, and explicit slot prompt-cache save and restore.

🚀 New Features & Major Enhancements

🖥️ A shared web UI and clearer model operations

The web UI uses a shared CSS/SVG kit, ink-and-teal themes, consistent controls, and permission-aware Build and Operate hubs. Existing URLs remain available. Models exposes model details, variants, placement information, and disk usage. Studio shares a compose, job, result, and recent-results layout across its workflows.

Per-model storage accounting distinguishes shared files from model-specific files. Aggregate totals deduplicate shared bytes. A model's displayed size is not necessarily the space deleting it reclaims.

Remote manual imports now run as tracked gallery jobs. The import page and editor wait for acquisition to succeed and show failures or cancellation. Local-file imports without downloads retain synchronous behavior. Queued imports can apply recommended inference defaults, so set important parameters explicitly when reproducing a configuration.

Backends supports confirmed removal of one concrete build from one selected node. Protection checks and conflict locks prevent removal during conflicting operations. Refresh failures retain the last known inventory instead of reporting an unverified empty state.

🔗 PRs: #12526, #12551, #12587, #12599, #12785. Queued imports: background acquisition and resolver-aware queueing.

💬 Chat history, reasoning controls, and richer input

Signed-in users can synchronize conversations through /api/conversations. Account-scoped caches, persistent deletion intents, and tombstones prevent stale clients from restoring deleted conversations. This requires authentication, the WebUI enabled, and the chat_history permission. Anonymous and legacy-key-only sessions keep browser-local history; old shared browser history is not automatically assigned to an account.

One effort picker controls the per-chat reasoning_effort request. None also hides returned reasoning traces for new replies. /effort remains available; the separate /reasoning action is removed. This UI choice does not prove that every backend suppresses internal reasoning computation.

Microphone dictation appends editable text through an installed transcription model. Scanned PDFs without a text layer render their first ten pages as image attachments for a vision-capable model.

Canvas serves HTML previews with their own CSP in a sandbox without allow-same-origin. Previews expire after ten minutes and live in process memory. Allowed external HTTPS resources can load, so previews are not necessarily offline. Multi-frontend deployments need routing that reaches the process holding the preview.

🔗 PRs: #12663, #12788, #12700, #12716, #12756, #12715.

🎙️ Streaming voice responses and bundled audio analysis

Qwen TTS accepts incremental text through the optional TTSLive backend RPC. With LLM and TTS streaming enabled, one native utterance can start producing audio before the complete LLM reply arrives. Cancellation and backpressure propagate through the live path; a failed utterance does not replay after audio commitment.

pipeline:
  streaming:
    llm: true
    tts: true

For non-native engines, pipeline.streaming.clause_chunking: true explicitly enables bounded clause synthesis. Leaving it unset preserves whole-reply synthesis. Native Qwen input does not use this clause splitter.

The gallery adds qwen3-streaming-assistant, vits-streaming-assistant, and piper-streaming-assistant. These presets install pipeline configuration only. Install their component LLM, transcription model, VAD, and TTS model separately.

Parakeet bundles can carry multiple audio roles, including ASR, VAD, diarization, sound detection, and a speaker encoder. Available roles depend on the bundle; they do not imply one fused inference pass. Diarization can return timed sound events with include_sounds.

Speaker-equipped Parakeet models can also serve voice embedding and verification. Encoder fingerprints distinguish compatible weights, and voice stores separate different embedding dimensions. voice_verify_threshold uses cosine distance, defaults to 0.5, and accepts values between 0 and 2. This backend does not add anti-spoofing or voice-analysis support.

Realtime responses now wait for earlier audio commits to finish transcription. A waiting response ends with input_not_committed if its pending commit produces no user item, instead of starting the LLM without that turn. interrupt_response: false preserves an active response while retaining overlapping transcripts and sound events.

🔗 PRs: #12770, #12455, #12463, #12479, #12491, #12499, #12544, #12446. Direct follow-ups: Parakeet voice RPCs, ordered commit responses, and interruption control.

🎵 Structured Sound expansion and speech controls

YuE2 joins the audio.cpp sound-generation path. Ordinary Studio captions supply its style unless an explicit style parameter overrides them. YuE2 weights use CC-BY-NC-4.0 and are limited to non-commercial use.

Simple Sound can optionally use expansion_model to turn a short description into validated music fields. Final release behavior requires a llama-cpp model with use_tokenizer_template: true and native tool support. LocalAI requires exactly one strict expand_sound call; prose JSON and reasoning text are not fallback arguments. Invalid expansion stops before audio generation.

OmniVoice exposes bounded duration and postprocessing controls through speech parameters. Duration is capped at 30 seconds and quantized to generation frames. This does not guarantee an exact final WAV duration. Pocket TTS also accepts a model-load language option, such as options: ["language:french"].

🔗 PRs: #12617, #12703, #12772, #12783, #12787, #12790, #12637, #12766.

🖼️ Image upscaling and additional generation controls

POST /v1/images/upscale provides dedicated upscaling with explicit model capability checks. Studio records the output as a child image so you can continue working within the same project. Native ESRGAN mode supports tiling without loading a diffusion context. Requested scale must match the model's native scale; it is not arbitrary-scale interpolation.

custom_sigmas exposes checkpoint-specific denoising schedules. New Qwen Image assemblies use those schedules; the selected encoders make these entries text-to-image only. Their model and encoder licenses still apply.

MiniMax-H3 gains additive reference-image, reference-video, and WAV-audio fields with partition checks and bounded inputs. These fields are API-only in this release; React does not expose them. Source support does not establish end-to-end generation on every checkpoint or device.

🔗 PRs: #12620, #12619, #12668.

🧭 Native decision routing and /v1/decisions

Decision models can classify requests directly for a router instead of using a general chat response as the classification protocol. The native path also supports bounded inline image decisions with a compatible format and projector.

POST /v1/decisions adapts the existing SystemOne pipeline to predicates, choices, and scores. It supports up to 64 questions and preserves typed boolean or string choices. /v1/systemone remains available.

Image input requires an image-capable decision model and inline PNG or JPEG data. Unsupported inputs fail rather than silently becoming text-only decisions. Existing Decisions permissions and usage accounting apply.

Older installed llama.cpp images may lack native Decisions support even when the server is current. Recognized stale-backend errors now return an upgrade-oriented 501 and mark the backend for upgrade. This detection does not itself rebuild an image.

🔗 PRs: #12449, #12603, #12733.

🛡️ Privacy controls, model profiles, and remote MCP authentication

PII middleware now covers incoming Responses instructions, text items, function arguments, and serialized tool output. pii.block_unscanned_media: true optionally rejects media the text detectors cannot inspect. It blocks rather than OCRs or transcribes media.

pii_detection:
  extend_to_next_word: [ZIPCODE]
  extend_to_previous_word: [LASTNAME]
  protected_terms: [Example Supplier]

Adjacent-word extension and protected-term files add opt-in control over NER masking. Protected terms apply to NER only, not pattern detectors. They pass wherever the same term occurs, so allowlist only values safe to disclose. Extensions can over-mask.

These changes do not provide complete filtering across every request path. Agent interception and resolved historical Responses content remain gaps. Responses WebSockets with an active detector policy are refused rather than filtered; use HTTP POST for that policy.

Aliases can carry profile.system_prompt, MCP configuration, and client-tool policy while sharing one loaded target model. mcp.auto activates configured servers only within instance and user permissions. Optional numerical evidence notes are a warning heuristic, not factual verification.

Remote MCP servers support OAuth2 client_credentials, including environment-backed secrets and automatic token refresh. Token endpoints require HTTPS except explicit loopback hosts. Credential rotation through environment variables requires restarting the connection-owning process. Legacy SSE discovery remains available with constrained fallback.

🔗 PRs: #12661, #12660, #12708, #12755, #12711, #12304. Direct additions: OAuth2 credentials, protected terms, and previous-word extension.

🕺 GEM-X live motion capture

The new gemxcpp backend converts streamed RGB frames into human poses through /api/motion/sessions and a duplex WebSocket. Clients can select SOMA-77 or SMPL-24 output and use single-use, origin-bound browser tickets.

The API bounds ingress and session counts rather than accumulating an unlimited capture backlog. Limits include one session per model, four per user, and sixteen per frontend. Clients must follow flow-control credits.

This integration is API-only and supports CPU or Vulkan; macOS uses CPU, not Metal inference. It does not provide a body mesh, robot controller, or person re-identification. Session state is frontend-local. GEM-X weights carry their own NVIDIA model-license terms.

🔗 Commits: GEM-X backend and duplex API, per-user session bounds, and socket authentication hardening.

🗄️ Qdrant-backed vector stores

Use backend: qdrant-store through the existing /stores/* API to persist vectors in Qdrant. Configuration supports TLS, custom certificate authorities, and environment-backed API keys. Qdrant's gRPC default is port 6334, not REST port 6333.

Writes use chunks of at most 500 points with a timeout per chunk. Earlier chunks can remain written if a later chunk fails; a whole set is not atomic. COSINE is the default metric. Other metrics return raw scores that do not match existing cosine-based thresholds.

🔗 Commits: Qdrant backend, bounded writes, and TLS compatibility.

💾 Model memory controls and saved prompt state

  • options: ["moe_cache_mib:4096"] sets an opt-in GPU cache budget for host-resident MoE experts. It consumes VRAM and is workload-dependent; undersized caches can thrash.
  • options: ["lazy_mode:on"] enables lazy reads for upstream-marked tensors. auto retains upstream selection rules; off loads them at startup. Forks without the field warn and ignore the option.
  • options: ["slot_save_path:/var/lib/localai/slots"] enables admin slot save/restore through /v1/slots/save and /v1/slots/restore. Saved prompt state survives model unloading. Use compatible model, quantization, and context settings; saved files are sensitive data.

Slot persistence is POSIX-only, keeps at most 32 saves per model, and does not coordinate multiple processes sharing a directory. A busy slot waits for its active request. These controls do not imply a release-wide latency or memory improvement.

🔗 PRs: #12729, #12743, #12730.

🔧 Distributed recovery and opt-in diagnostics

PostgreSQL/NATS deployments gain load generations, leases, worker watchdogs, and attempt-specific cancellation through POST /api/models/:id/load-cancel. Upgrade frontends first. Model config resync defaults to 30 seconds through --model-config-resync-interval.

Root PostgreSQL collection discovery now uses a shared registry across frontends. Per-user collections are outside that change. Targeted unloading frees the named model rather than an arbitrary worker backend. These are NATS distributed-mode changes, not libp2p federation features.

Admin stop intent is not made durable by config resync: replica policies can still restart a stopped model. Do not treat resync as a persisted stop policy.

Opt-in --pprof exposes a separate numeric-loopback-only profiler. --request-phase-timing records frontend phases without adding filesystem probes. Profiles can contain sensitive data and add overhead; do not expose the profiler through public ingress. These measurements cover the Go frontend, not GPU inference on workers.

🔗 PRs: #12524, #12558, #12536, #12537, #12610, #12616.

🧰 Smaller features worth knowing about

  • Pause and resume your own API keys, either indefinitely or until a timestamp, without deleting them. #12521.
  • Prefer eligible installed development backends with --prefer-development-backends. Activation requires a frontend restart and separate worker configuration/restarts. #12782.
  • Backend OCI downloads use the configured --download-staging-path. #12280.
  • Tagged releases add a thin Linux x86_64 launcher AppImage. It needs glibc 2.35+ and host graphics libraries; it does not bundle the server, backends, or models. #12647.
  • Silero VAD threshold, silence, and padding settings are configurable through model options. #12430.
