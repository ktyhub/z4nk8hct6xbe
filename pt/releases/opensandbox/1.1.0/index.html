OpenSandbox docker/execd/v1.1.0

Novidades

✨ Recursos

  • execd como sandbox init (OSEP-0018). execd agora pode ser executado como PID 1: ceifador único com uma abstração managedProcess em cada caminho de inicialização, encaminhamento de sinal (TERM/HUP/USR1/USR2/WINCH), propagação de código de saída de propriedade do ponto de entrada e um substituto de subreaper para o caminho do Pool. Opt-in via EXECD_INIT=1 (injetado pelo runtime.execd_run_as_init do servidor para Docker/K8s Batch/Agent/Pool); topologia clássica inalterada e desativada por padrão. (#1474)
  • Piso de reforço pré-exec. O novo auxiliar nativo opensandbox-launcher aplica faixa de env → KEEPCAPS → acabamento do conjunto delimitador → no_new_privs → eliminação de identidade → seccomp → execve; [landlock] adiciona uma lista de permissões de sistema de arquivos (fail-open abaixo de ABI/kernel 5.13, relatado como unsupported). GET /v1/isolated/capabilities ganha um objeto hardening com estado por camada; cada camada degrada a falha aberta. (#1474)
  • variante de observação eBPF. execd-ebpf (CGO + cilium/ebpf) conecta exec/connect/privilege com CO-RE, com escopo para o cgroup sandbox, emitindo uma auditoria rotativa JSONL; precisa de kernel ≥5.10 com BTF. A imagem padrão permanece inalterada. (#1474 #1562)
  • Ganchos de ciclo de vida preStart e periodic (OSEP-0020). CreateSandboxRequest.lifecycle é transportado para a sandbox por meio do ambiente OPEN_SANDBOX_LIFECYCLE interno (Kubernetes; o provedor Docker rejeita solicitações de ciclo de vida). execd inicia HTTP antes de preStart, executa ganchos periodic não sobrepostos através do caminho do processo gerenciado com reconhecimento de reaper e somente libera o processo do usuário após preStart ser bem-sucedido. A configuração persiste em $HOME/.execd/lifecycle.toml, com EXECD_LIFECYCLE_CONFIG como substituição exata; a sincronização de bootstrap e o desligamento pré-inicial são fechados com falha com watchdogs TERM/KILL e os vars de transporte internos são removidos do código do usuário. Modelos API alinhados entre Go/Python/JS/Kotlin/C# SDKs. (#1587 #1588 #1589)

🐛 Correções de bugs

  • Sinais no namespace não vazam mais para /command no modo init. kill -HUP 1 anteriormente matava tudo o que /command estava rodando (signal: hangup); os sinais agora pertencem apenas ao encaminhador init. (#1546)
  • Falha na criação do PTY emitiu um segundo corpo de sucesso. POST /pty agora para imediatamente após a resposta de erro em vez de anexar um corpo de sucesso e um ID de sessão inexistente. (#1603)
  • A validação cwd agora respeita ambientes com escopo de solicitação. Solicitações /command de primeiro/segundo plano podem usar uma variável cwd de seu próprio mapa envs em vez de serem rejeitadas com 400. (#1611)
  • Cargas de trabalho não raiz não puderam ser iniciadas: /bootstrap.sh normalizado para 0755. Uma imagem implantada carregou bootstrap.sh como 0751 root:root, enviando imagens com um usuário padrão não raiz (por exemplo, admin) para CrashLoopBackOff antes da execução dos ganchos. A construção da imagem agora força bits exec em execd/execd-ebpf/opensandbox-supervisor/bootstrap.sh independentemente das permissões de checkout. (#1619#1606)
  • Tempo limite do preStart aumentado de 300s para 10800s (3h). periodic.timeoutSeconds permanece em 300s; Os limites da política do produto agora são aplicados apenas no lado do servidor, com o execd mantendo apenas uma proteção técnica contra transbordamento. (#1637)

📦 Diversos

  • Cobertura OSEP-0018 fechada: caminho do servidor e proteção Kubernetes e2e (isolamento TOML transportado pelo ConfigMap, sem alteração de lógica do servidor), proteção insuficiente PTY, integração bwrap + init-reaper, política [seccomp]/keep_capabilities personalizada, pino de desvio EXECD_INIT↔TOML, reinicialização de K8s, reciclagem contra pods de modo de inicialização, parada iniciada em tempo de execução, e uma fumaça de contêiner vazio execd-ebpf (funciona como validação do kernel-5.10). Redundância de teste e código morto cortado (-359 linhas). (#1554 #1555 #1562 #1574)
  • Permissão automática de endpoint OTLP enviada nos componentes compartilhados (saída honra OTEL_EXPORTER_OTLP_METRICS_ENDPOINT/OTEL_EXPORTER_OTLP_ENDPOINT; loop de leitura do visualizador PTY refatorado ao longo do caminho). (#1504)
  • Guia de gancho do ciclo de vida com diagrama de tempo e exemplos de criação por SDK; SDK cliValidação de timeout do lado ent alinhado com o Servidor. (#1605)

OpenSandbox docker/execd/v1.1.0

What's New

✨ Features

  • execd as sandbox init (OSEP-0018). execd can now run as PID 1: single reaper with a managedProcess abstraction on every launch path, signal forwarding (TERM/HUP/USR1/USR2/WINCH), entrypoint-owned exit-code propagation, and a subreaper fallback for the Pool path. Opt-in via EXECD_INIT=1 (injected by the server's runtime.execd_run_as_init for Docker/K8s Batch/Agent/Pool); classic topology unchanged and default off. (#1474)

  • Pre-exec hardening floor. The new opensandbox-launcher native helper applies env strip → KEEPCAPS → bounding-set trim → no_new_privs → identity drop → seccomp → execve; [landlock] adds a filesystem allowlist (fail-open below ABI/kernel 5.13, reported as unsupported). GET /v1/isolated/capabilities gains a hardening object with per-layer state; every layer degrades fail-open. (#1474)

  • eBPF observation variant. execd-ebpf (CGO + cilium/ebpf) hooks exec/connect/privilege with CO-RE, scoped to the sandbox cgroup, emitting a rotating JSONL audit; needs kernel ≥5.10 with BTF. The default image is unchanged. (#1474 #1562)

  • preStart and periodic lifecycle hooks (OSEP-0020). CreateSandboxRequest.lifecycle is transported to the sandbox via the internal OPEN_SANDBOX_LIFECYCLE env (Kubernetes; the Docker provider rejects lifecycle requests). execd starts HTTP before preStart, runs non-overlapping periodic hooks through the reaper-aware managed-process path, and only releases the user process after preStart succeeds. Config persists at $HOME/.execd/lifecycle.toml, with EXECD_LIFECYCLE_CONFIG as exact override; bootstrap sync and preStart shutdown are fail-closed with TERM/KILL watchdogs, and internal transport vars are stripped from user code. API models aligned across Go/Python/JS/Kotlin/C# SDKs. (#1587 #1588 #1589)

🐛 Bug Fixes

  • In-namespace signals no longer leak into /command in init mode. kill -HUP 1 previously killed whatever /command was running (signal: hangup); signals are now owned by the init forwarder only. (#1546)

  • PTY creation failure emitted a second success body. POST /pty now stops immediately after the error response instead of appending a success body and a nonexistent session id. (#1603)

  • cwd validation now honors request-scoped envs. Foreground/background /command requests can use a cwd variable from their own envs map instead of being rejected with 400. (#1611)

  • Non-root workloads could not start: /bootstrap.sh normalized to 0755. A deployed image carried bootstrap.sh as 0751 root:root, sending images with a non-root default user (e.g. admin) into CrashLoopBackOff before hooks ran. The image build now forces exec bits on execd/execd-ebpf/opensandbox-supervisor/bootstrap.sh regardless of checkout permissions. (#1619 #1606)

  • preStart timeout raised from 300s to 10800s (3h). periodic.timeoutSeconds stays at 300s; product policy bounds are now enforced Server-side only, with execd keeping just a technical overflow guard. (#1637)

📦 Misc

  • OSEP-0018 coverage closed out: server-path and Kubernetes hardening e2e (ConfigMap-carried isolation TOML, no server logic change), PTY-under-hardening, bwrap + init-reaper integration, custom [seccomp]/keep_capabilities policy, EXECD_INIT↔TOML drift pin, K8s Restart recycle against init-mode pods, runtime-initiated stop, and an execd-ebpf bare-container smoke (doubles as kernel-5.10 validation). Test redundancy and dead code trimmed (-359 lines). (#1554 #1555 #1562 #1574)

  • OTLP endpoint auto-allow shipped in the shared components (egress honors OTEL_EXPORTER_OTLP_METRICS_ENDPOINT/OTEL_EXPORTER_OTLP_ENDPOINT; PTY viewer read loop refactored along the way). (#1504)

  • Lifecycle hook guide with timing diagram and per-SDK creation examples; SDK client-side timeout validation aligned with the Server. (#1605)
