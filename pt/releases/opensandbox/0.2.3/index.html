Servidor OpenSandbox/v0.2.3

Novidades

⚠️ Mudanças importantes

  • OPENSANDBOX_EGRESS_SANDBOX_ID agora é injetado pelo servidor e rejeitado no ambiente de solicitação — o servidor define incondicionalmente a variável de atribuição sandbox-id do sidecar de saída nos tempos de execução Docker e Kubernetes e a remove da lista de permissões do ambiente. As solicitações que passam em env agora recebem 400 em vez de um valor falsificável pelo usuário. #1381

✨ Recursos

  • Ganchos de ciclo de vida de sandbox (preStart/periodic), OSEP-0020 — CreateSandboxRequest.lifecycle é aceito, validado (transportes reservados, nomes periódicos duplicados, combinações de alocação de pool) e transportado para cargas de trabalho Kubernetes por meio do ambiente OPEN_SANDBOX_LIFECYCLE reservado para execd executar. Docker rejeita explicitamente solicitações de ciclo de vida; PATCH e outros tipos de gancho estão fora do escopo. É fornecido com modelos Java/Kotlin, Python e TypeScript SDK alinhados. #1588 #1589
  • Limite preStart.timeoutSeconds aumentado de 300s para 3 horas — os limites do servidor e OpenAPI agora permitem até 10800s para ganchos pré-inicialização; o limite periódico permanece em 300s. O limite de política do produto do lado execd é removido, mantendo as alterações de política apenas no servidor. #1637
  • Pausa/retomada QEMU VMState para sandboxes baseados em runc — captura opcional de estado de memória/vCPU/dispositivo convidado por meio de migração QMP; rootfs e VMState compactados são armazenados como imagens OCI separadas codificadas por resumos SHA-256 imutáveis. Suporta pausa, desanexação e restauração autônoma em pool do BatchSandbox, preservando a memória do convidado, o disco gravável, o ID de inicialização e a continuidade do contador. Os snapshots somente Rootfs permanecem compatíveis com versões anteriores. #1584
  • O esgotamento da capacidade do pool agora é identificável pela máquina — o controlador publica uma condição PoolAllocationPending/PoolCapacityExhausted; o servidor aguarda uma janela de aquisição limitada (novo kubernetes.pool_acquisition_timeout_seconds, padrão 30s) e então retorna HTTP 429 com KUBERNETES::POOL_CAPACITY_EXHAUSTED e Retry-After: 5 em vez do tempo limite de prontidão 504 genérico. Controladores mais antigos voltam com segurança ao comportamento existente. #1581
  • Resumo de alocação de pool em respostas de ciclo de vida — getSandbox agora apresenta um bloco Sandbox.allocation opcional (mode: pool, poolRef, state: allocated) para alocações de pool Kubernetes confirmadas, emitido apenas para referências concretas de pool não curinga com evidência de alocação correspondente. Nenhum dado de pod/namespace/IP é exposto. #1481
  • Métricas de solicitação HTTP genéricas via OTLP — um middleware ASGI fino exporta server.http.request.duration (ms) com http_method, http_route correspondente (ou unknown para solicitações não roteadas/com falha de autenticação) e atributos http_status_code, complementando o histograma de duração de criação existente. Caminhos brutos, IDs, chaves e corpos nunca são atributos; não operacional quando [otel] está desabilitado. #1561
  • Diagnóstico estável API com escopos — os diagnósticos agora honram o contrato de descritor público em linha: logs: container|all e events: runtime|lifecycle|all, com 400 DIAGNOSTICS_SCOPE_UNSUPPORTED para escopos desconhecidos e avisos explícitos para escopos de melhor esforço incompletos. As respostas de texto simples no-scope obsoletas ainda funcionam com um cabeçalho Deprecation. #1553
  • base de back-end de frotas de sandbox rápida (OSEP-0007) — um FastPath v2 gRPC client envolve todos os RPCs FastPathService com mapeamento de erro digitado (FastPathNotFound → 404, etc.), e uma camada de mapeamento de criação/status converte o contrato público em semântica de sandbox rápida, rejeitando campos não suportados (volumes, platform, resourceRequests, credentialProxy, snapshotId, etc.) com erros claros. Ainda não conectado como um tempo de execução ativo. #1558 #1559
  • As chaves de assinatura de acesso seguro podem vir de um segredo Kubernetes — o servidor aceita substituições de env OPENSANDBOX_SECURE_ACCESS_KEYS / OPENSANDBOX_SECURE_ACCESS_ACTIVE_KEY (espelhando a substituição da chave API, modo de gateway necessário) e o gráfico Helm adiciona server.gateway.secureAccess.existingSecret (mutuamente exclusivo com texto simples keys, aplicado no tempo de renderização) para que os fluxos de GitOps nunca confirmem material de chave. #1445
  • Tempo de execução Docker sandbox_env / sandbox_binds — os novos campos [docker] aplicam variáveis de ambiente em toda a frota e montagens de vinculação de host a cada contêiner de sandbox (a solicitação env vence sandbox_env; vinculações de configuração precedem vinculações derivadas de solicitação), dando ao tempo de execução Docker o gancho do lado do operador que o modelo de pod K8s possui. #1303
  • Tempo limite de prontidão do sidecar de saída configurável — o novo [egress] timeout_seconds (padrão 30s, valores não positivos rejeitados) permite que as implantações do Docker ajustem quanto tempo o servidor aguarda pelo endpoint de integridade do sidecar. #1522
  • Namespaces de locatário validados na inicialização (OSEP-0014) — o servidor verifica rapidamente se cada namespace de locatário existe e está acessível antes de servir o tráfego, agregando todos os namespaces ausentes/inacessíveis em um único erro fatal em vez de falhar apenas no momento da solicitação. OSEP-0004/0005/0014 marcado como implementado. #1389

🔒 Segurança

  • Solavancos de dependência de correção de CVE — google.golang.org/grpc → v1.82.1 em kubernetes/ingress/execd/egress/internal (xDS RBAC e correções HTTP/2), postcss → 8.5.11 (arquivo arbitrário lido via sourceMappingURL). #1385

🐛 Correções de bugs

  • Pesquisas de endpoint Docker ~108x mais rápidas — a pesquisa de contêiner agora passa pelo nome determinístico sandbox-<id> com validação de rótulo opensandbox.io/id, voltando para a varredura de rótulo somente quando necessário. Referência local: 6,07s → 56ms para resolução de endpoint execd+egress. #1400
  • Cache do Informer expira quando o relógio para — has_synced agora significa "cache atualmente ativo", não "uma lista inicial concluída uma vez"; um relógio parado ou entreaberto (por exemplo, após uma atualização do plano de controle) degrada para leituras diretas do API em vez de servir o status congelado para sempre, o que anteriormente fazia com que todas as criações fossem 504 com POD_READY_TIMEOUT. Limite derivado de botões existentes (resync_period + watch_timeout); nenhuma nova configuração. #1534
  • Vazamento de conexão proxy em respostas abortadas — quando um client downstream se desconectou antes do início do streaming do corpo da resposta, a resposta httpx de back-end nunca foi liberada, esgotando gradualmente o pool compartilhado até httpcore.PoolTimeout. O proxy agora possui a resposta de back-end para todo o ciclo de vida do ASGI, protege o aclose() contra cancelamento e libera em caso de falha na configuração. Teste de estresse: 1000/1000 desconexões limpas. #1488
  • IDs de operação de proxy estáveis e exclusivos — as 20 operações HTTP com proxy emitiram anteriormente 4 IDs de operação duplicados dependentes do processo (16 avisos OpenAPI); cada método agora obtém seu próprio ID determinístico com envio de tempo de execução, autenticação e comportamento 405 idênticos. Os clients gerados devem ser regenerados. #1634
  • A criação automática de PVC não trava mais com um 500 malformado — o patch de referência do proprietário do PVC passou por um caminho _content_type não suportado que levantou ApiTypeError (deixando PVCs sem referências de proprietário) e SandboxErrorCodes.INTERNAL_ERROR foi indefinido, mascarando o erro real. Ambos corrigidos: o patch usa o caminho call_api de fusão estratégica suportado; código de erro definido. #1538 #1447
  • O contêiner de modelo securityContext agora chega aos pods — a fusão profunda anteriormente substituiu os contêineres do modelo no atacado, eliminando silenciosamente o securityContext no nível do contêiner. As chaves de modelo agora complementam (nunca substituem) os valores de tempo de execução, correspondendo à filosofia volumeMounts existente. #1564
  • Os redirecionamentos de back-end relativos à raiz permanecem na rota do proxy — Location: /login de um back-end de sandbox é rebaseado para /v1/sandboxes/{id}/proxy/{port}/login; referências absolutas, de caminho de rede e somente de consulta permanecem intactas. #1516
  • Os endpoints proxy do servidor eliminam o cabeçalho de roteamento de entrada — OpenSandbox-Ingress-To (sem distinção entre maiúsculas e minúsculas) é removido das respostas use_server_proxy=true enquanto o acesso seguro e outros cabeçalhos de endpoint são preservados. #1503
  • Não há cabeçalhos Date/Server duplicados em respostas com proxy — o proxy preserva uma origem Date enquanto suprime o padrão do Uvicorn (e o cabeçalho backend Server), emitindo exatamente um Date. #1471
  • Erro de currículo inválido não vaza mais as partes internas do controlador — a mensagem 409 para uma sandbox em execução (sucesso interno) agora diz "estado em execução" em vez de "fase bem-sucedida"; Status HTTP e código de erro inalterados. #1586
  • Limites de CPU não finitos rejeitados — nan, valores infinitos e estourados são rejeitados antes da conversão do Docker NanoCpus em vez de serem aceitos silenciosamente. #1568
  • Montagens mistas de subPath de PVC somente leitura permitidas — a origem do PVC é definida como somente leitura quando cada montagem da declaração é somente leitura; a rejeição no nível de serviço que bloqueava a criação legítima de PVC com políticas mistas foi removida. #1440
  • Resolução de endpoints de proxy de servidor de sandbox do agente — a resolução de endpoint interno agora delega ao provedor de carga de trabalho e lê endereços de pod de sandbox do agente de status.podIPs em vez da anotação somente BatchSandbox e coloca literais IPv6 entre colchetes antes de anexar a porta. #1424
  • Relatórios de versão corrigidos em todos os lugares — /openapi.json, metadados de pacotes instalados e o gráfico appVersion relataram 0.1.0 obsoleto; o servidor agora lê sua versão dos metadados do pacote em tempo de execução, compila injeta SETUPTOOLS_SCM_PRETEND_VERSION e o script de lançamento atinge Chart.yaml appVersion. #1439

📦 Diversos

  • execd v1.0.22 vem com proteção de modo init OSEP-0018 — execd como sandbox init (PID 1) com piso de proteção pré-exec (faixa de ambiente, conjunto delimitador, no_new_privs, queda de identidade, limites de ambiente, seccomp) e proteção Kubernetes e2e + cobertura PTY/bwrap. #1474 #1555
  • Portão de ciclo de vida de carga de trabalho fechado com falha de sessão isolada — o servidor distribui um portão de ciclo de vida Bubblewrap nativo para /opt/opensandbox para ambos os tempos de execução; as cargas de trabalho permanecem bloqueadas até que o execd as marque como prontas. Somente na primeira fase — a admissão de capacidade e a rede de sessão permanecem desabilitadas. #1388
  • O MITM transparente de saída pode interceptar portas TCP extras — o OPENSANDBOX_EGRESS_MITMPROXY_EXTRA_PORTS experimental anexa portas ao 80/443 sempre ativo com validação de falha fechada (cap multiportas 15); a vinculação de credenciais ainda se aplica apenas a portas canônicas. #1379
  • Bumps automáticos — egress v1.1.5 → v1.1.7 (#1391 #1498 #1600); execd v1.0.22 (#1501).

OpenSandbox server/v0.2.3

Highlights

  • Egress sandbox attribution is now server-owned — remove OPENSANDBOX_EGRESS_SANDBOX_ID from request env; Docker and Kubernetes now inject it themselves, and client-supplied values receive HTTP 400 instead of being accepted as spoofable attribution. #1381
  • Lifecycle hooks are Kubernetes-only in this release — preStart and periodic hooks reach execd through OPEN_SANDBOX_LIFECYCLE, with aligned Java/Kotlin, Python, and TypeScript SDK models. Docker explicitly rejects lifecycle requests, PATCH is unsupported, preStart.timeoutSeconds now allows 10,800 seconds, and periodic hooks remain capped at 300 seconds. #1588 #1589 #1637
  • Pause/resume preserves live QEMU state, not just disk contents — opt-in runc support captures guest memory, vCPU, and device state through QMP, storing rootfs and compressed VMState as separate digest-addressed OCI images. Pooled BatchSandbox pause, detachment, and standalone restoration preserve guest memory, writable disks, boot IDs, and counters; rootfs-only snapshots remain compatible. #1584
  • Kubernetes pool exhaustion now has an actionable backpressure contract — new allocation conditions and kubernetes.pool_acquisition_timeout_seconds (default 30s) replace generic 504s with HTTP 429, KUBERNETES::POOL_CAPACITY_EXHAUSTED, and Retry-After: 5; clients should update capacity-related retry handling. getSandbox also exposes allocation state for concrete pool references without leaking pod, namespace, or IP data. #1581 #1481
  • Regenerate proxy clients and migrate diagnostics callers — the 20 proxied operations now have unique, deterministic OpenAPI operation IDs, so generated clients should be rebuilt despite unchanged runtime dispatch. Diagnostics require explicit logs/events scopes; unsupported scopes return 400, while deprecated unscoped plain-text responses remain available with a Deprecation header. #1634 #1553
  • Secure-access keys can stay out of Git, but startup validation becomes stricter — gateway deployments can source signing keys from a Kubernetes Secret through server.gateway.secureAccess.existingSecret, mutually exclusive with plaintext keys. Ensure configured tenant namespaces exist and are accessible before startup, since missing or inaccessible namespaces now cause a fatal error rather than request-time failures. #1445 #1389

What's New

⚠️ Breaking Changes

  • OPENSANDBOX_EGRESS_SANDBOX_ID is now server-injected and rejected in request env — the server unconditionally sets the egress sidecar's sandbox-id attribution variable in both Docker and Kubernetes runtimes, and removed it from the env allowlist. Requests that pass it in env now get a 400 instead of a user-spoofable value. #1381

✨ Features

  • Sandbox lifecycle hooks (preStart / periodic), OSEP-0020 — CreateSandboxRequest.lifecycle is accepted, validated (reserved transports, duplicate periodic names, pool-allocation combinations), and transported to Kubernetes workloads via the reserved OPEN_SANDBOX_LIFECYCLE env for execd to execute. Docker explicitly rejects lifecycle requests; PATCH and other hook types are out of scope. Ships with aligned Java/Kotlin, Python, and TypeScript SDK models. #1588 #1589

  • preStart.timeoutSeconds limit raised from 300s to 3 hours — server and OpenAPI limits now allow up to 10800s for pre-start hooks; the periodic limit stays at 300s. The execd-side product policy bound is removed, keeping policy changes server-only. #1637

  • QEMU VMState pause/resume for runc-based sandboxes — opt-in capture of guest memory/vCPU/device state via QMP migration; rootfs and compressed VMState are stored as separate OCI images keyed by immutable SHA-256 digests. Supports pooled BatchSandbox pause, detachment, and standalone restoration while preserving guest memory, writable disk, boot ID, and counter continuity. Rootfs-only snapshots remain backward compatible. #1584

  • Pool capacity exhaustion is now machine-identifiable — the controller publishes a PoolAllocationPending/PoolCapacityExhausted condition; the server waits a bounded acquisition window (new kubernetes.pool_acquisition_timeout_seconds, default 30s) and then returns HTTP 429 with KUBERNETES::POOL_CAPACITY_EXHAUSTED and Retry-After: 5 instead of the generic 504 readiness timeout. Older controllers safely fall back to the existing behavior. #1581

  • Pool allocation summary in lifecycle responses — getSandbox now surfaces an optional Sandbox.allocation block (mode: pool, poolRef, state: allocated) for confirmed Kubernetes pool allocations, emitted only for concrete non-wildcard pool references with matching allocation evidence. No pod/namespace/IP data is exposed. #1481

  • Generic HTTP request metrics via OTLP — a thin ASGI middleware exports server.http.request.duration (ms) with http_method, matched http_route (or unknown for unrouted/auth-failed requests), and http_status_code attributes, complementing the existing create-duration histogram. Raw paths, IDs, keys, and bodies are never attributes; no-op when [otel] is disabled. #1561

  • Stable diagnostics API with scopes — diagnostics now honor the public inline descriptor contract: logs: container|all and events: runtime|lifecycle|all, with 400 DIAGNOSTICS_SCOPE_UNSUPPORTED for unknown scopes and explicit warnings for incomplete best-effort scopes. Deprecated no-scope plain-text responses still work with a Deprecation header. #1553

  • fast-sandbox fleets backend groundwork (OSEP-0007) — a FastPath v2 gRPC client wraps all FastPathService RPCs with typed error mapping (FastPathNotFound → 404, etc.), and a create/status mapping layer converts the public contract to fast-sandbox semantics, rejecting unsupported fields (volumes, platform, resourceRequests, credentialProxy, snapshotId, etc.) with clear errors. Not yet wired as an active runtime. #1558 #1559

  • Secure-access signing keys can come from a Kubernetes Secret — the server accepts OPENSANDBOX_SECURE_ACCESS_KEYS / OPENSANDBOX_SECURE_ACCESS_ACTIVE_KEY env overrides (mirroring the API-key override, gateway mode required), and the Helm chart adds server.gateway.secureAccess.existingSecret (mutually exclusive with plaintext keys, enforced at render time) so GitOps flows never commit key material. #1445

  • Docker runtime sandbox_env / sandbox_binds — new [docker] fields apply fleet-wide environment variables and host bind mounts to every sandbox container (request env wins over sandbox_env; config binds precede request-derived binds), giving the Docker runtime the operator-side hook the K8s pod template has. #1303

  • Egress sidecar readiness timeout configurable — new [egress] timeout_seconds (default 30s, non-positive values rejected) lets Docker deployments tune how long the server waits for the sidecar health endpoint. #1522

  • Tenant namespaces validated at startup (OSEP-0014) — the server fail-fast verifies every tenant namespace exists and is accessible before serving traffic, aggregating all missing/inaccessible namespaces into a single fatal error instead of failing only at request time. OSEP-0004/0005/0014 marked implemented. #1389

🔒 Security

  • CVE-remediating dependency bumps — google.golang.org/grpc → v1.82.1 across kubernetes/ingress/execd/egress/internal (xDS RBAC and HTTP/2 fixes), postcss → 8.5.11 (arbitrary file read via sourceMappingURL). #1385

🐛 Bug Fixes

  • Docker endpoint lookups ~108x faster — container lookup now goes through the deterministic sandbox-<id> name with opensandbox.io/id label validation, falling back to the label scan only when needed. Local benchmark: 6.07s → 56ms for execd+egress endpoint resolution. #1400

  • Informer cache expires when the watch stalls — has_synced now means "cache is currently live", not "an initial list finished once"; a stalled or half-open watch (e.g. after a control-plane upgrade) degrades to direct API reads instead of serving frozen status forever, which previously caused every create to 504 with POD_READY_TIMEOUT. Bound derived from existing knobs (resync_period + watch_timeout); no new config. #1534

  • Proxy connection leak on aborted responses — when a downstream client disconnected before response-body streaming started, the backend httpx response was never released, gradually exhausting the shared pool until httpcore.PoolTimeout. The proxy now owns the backend response for the full ASGI lifecycle, shields aclose() from cancellation, and releases on setup failure. Stress test: 1000/1000 disconnects cleaned up. #1488

  • Unique, stable proxy operation IDs — the 20 proxied HTTP operations previously emitted 4 process-dependent duplicate operation IDs (16 OpenAPI warnings); each method now gets its own deterministic ID with identical runtime dispatch, auth, and 405 behavior. Generated clients should be regenerated. #1634

  • PVC auto-create no longer crashes with a malformed 500 — the PVC owner-reference patch went through an unsupported _content_type path that raised ApiTypeError (leaving PVCs without owner refs) and SandboxErrorCodes.INTERNAL_ERROR was undefined, masking the real error. Both fixed: patch uses the supported strategic-merge call_api path; error code defined. #1538 #1447

  • Template container securityContext now reaches pods — the deep-merge previously replaced the template's containers wholesale, silently dropping container-level securityContext. Template keys now supplement (never override) runtime values, matching the existing volumeMounts philosophy. #1564

  • Root-relative backend redirects stay under the proxy route — Location: /login from a sandbox backend is rebased to /v1/sandboxes/{id}/proxy/{port}/login; absolute, network-path, and query-only references are left untouched. #1516

  • Server-proxy endpoints drop the ingress routing header — OpenSandbox-Ingress-To (case-insensitive) is removed from use_server_proxy=true responses while secure-access and other endpoint headers are preserved. #1503

  • No duplicate Date/Server headers on proxied responses — the proxy preserves an origin Date while suppressing Uvicorn's default (and the backend Server header), emitting exactly one Date. #1471

  • Invalid-resume error no longer leaks controller internals — the 409 message for a Running (internally Succeed) sandbox now says "state Running" instead of "phase Succeed"; HTTP status and error code unchanged. #1586

  • Non-finite CPU limits rejected — nan, infinite, and overflowed values are rejected before Docker NanoCpus conversion instead of being silently accepted. #1568

  • Mixed read-only PVC subPath mounts allowed — the PVC source is set read-only only when every mount of the claim is read-only; the service-level rejection that blocked legitimate mixed-policy PVC creation is removed. #1440

  • Agent-sandbox server-proxy endpoints resolve — internal endpoint resolution now delegates to the workload provider and reads agent-sandbox pod addresses from status.podIPs instead of the BatchSandbox-only annotation, and brackets IPv6 literals before appending the port. #1424

  • Version reporting fixed everywhere — /openapi.json, installed package metadata, and the chart appVersion all reported stale 0.1.0; the server now reads its version from package metadata at runtime, builds inject SETUPTOOLS_SCM_PRETEND_VERSION, and the release script bumps Chart.yaml appVersion. #1439

📦 Misc

  • execd v1.0.22 ships OSEP-0018 init-mode hardening — execd as sandbox init (PID 1) with pre-exec hardening floor (env strip, bounding set, no_new_privs, identity drop, ambient caps, seccomp) and Kubernetes hardening e2e + PTY/bwrap coverage. #1474 #1555

  • Isolated-session fail-closed workload lifecycle gate — the server distributes a native Bubblewrap lifecycle gate to /opt/opensandbox for both runtimes; workloads stay blocked until execd marks them ready. First phase only — capability admission and session networking remain disabled. #1388

  • Egress transparent MITM can intercept extra TCP ports — experimental OPENSANDBOX_EGRESS_MITMPROXY_EXTRA_PORTS appends ports to the always-on 80/443 with fail-closed validation (multiport cap 15); credential binding still applies to canonical ports only. #1379

  • Auto-bumps — egress v1.1.5 → v1.1.7 (#1391 #1498 #1600); execd v1.0.22 (#1501).
