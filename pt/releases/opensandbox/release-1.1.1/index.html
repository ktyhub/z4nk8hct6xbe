Versão OpenSandbox-1.1.1

Corte estável da linha de patch 1.1.1: corrige a roda quebrada do servidor 1.1.0 - a filtragem de exclusão VCS do hatchling descartou silenciosamente os stubs FastPath gRPC comprometidos do pacote PyPI, de modo que cada instalação 1.1.0 do opensandbox-server falhou no momento da importação; PyPI é imutável, portanto a correção é enviada nesta linha (#1959). Pacotes SDK/CLI/server são publicados em 1.1.1 (somente imagens enviadas por 1.1.1-rc.1). Todos no 1.1.0 deveriam atualizar. Linha de base para cada seção abaixo: release-1.1.0.

Destaques

  • Corrige a roda do servidor 1.1.0: stubs FastPath agora são enviados no pacote e instalam a importação de forma limpa; Pacotes SDK/CLI/servidor publicados em 1.1.1 (#1959)
  • Operações de sistema de arquivos vinculados à identidade: execd executa o arquivo APIs como um UID/GID Linux explícito, com FilesWithIdentity/files_with_identity em todos os cinco SDKs; sessões isoladas ganham múltiplas montagens de sobreposição independentes (#2070 #2093 #2094 #2095 #2096 #2097 #2032)
  • Proteção do servidor: a criação do instantâneo envia o objeto de tempo de execução antes de persistir, de modo que as leituras iniciais não podem ser mapeadas para Failed, as falhas de back-end com proxy são mapeadas para 502/504 em vez de um 500 genérico e o diagnóstico funciona para sandboxes em pool (#2098 #2077 #2084 #2104)

Servidor

  • Implementar pausa/retomada para o provedor de agente-sandbox fazendo ponte para spec.operatingMode (Running/Suspended) em agents.x-k8s.io/v1beta1, com derivação de estado (Paused/Pausing/Resuming/Terminated) e 409 em transições inválidas; ambos os endpoints retornaram anteriormente "não suportado" (#1975)
  • Isole inquilinos que compartilham um namespace Kubernetes: cria o carimbo opensandbox.io/tenant e lista/obtém/exclui/pausa/retomar/proxy oculta os sandboxes rotulados de outros inquilinos como 404, enquanto os sandboxes legados não rotulados permanecem visíveis até a expiração; também adiciona kubernetes.insecure_skip_tls_verify para incompatibilidades de CA de ServiceAccount (#1973)
  • Corrija a queda silenciosa da intenção de renovação após a reinicialização do servidor no modo multilocatário: o resolvedor agora recorre a uma pesquisa de rótulo em todo o cluster com um disjuntor 403 e avisos estruturados, trusts um namespace observado de entrada da carga útil da intenção quando verificável, e implantações de locatário único nunca resolvem além do namespace configurado (#1819)
  • Adicione [docker] publish_host para publicar portas sandbox em modo bridge em um endereço de host (padrão 0.0.0.0 inalterado) — com 127.0.0.1 ou o gateway bridge Docker, a porta execd sem token não chega mais a interfaces públicas (#1954)
  • Adicionar uma seção de configuração [egress.upstream_proxy] digitada somente para administrador (URL + autorização opcional, validada no carregamento) que injeta o proxy CONNECT upstream encadeado do sidecar em Docker e Kubernetes, com 400s de falha fechada quando o networkPolicy solicitado é incompatível; valores secretos não são mais ecoados em erros de validação de configuração (#1999), além de ca_cert_path (Docker) e ca_secret_name (Kubernetes), portanto, proxies https:// assinados por uma CA privada são trusted sem substituir o armazenamento trust do sistema - o PEM aumenta /etc/ssl/certs no sidecar (#2030)
  • Torne a criação de snapshot livre de corrida para os primeiros leitores em k8s/fsb: POST /sandboxes/{id}/snapshots agora cria o objeto de tempo de execução (SandboxSnapshot CR / fsb submit) antes de persistir a linha Creating e retorna sem enfileirar um trabalhador, então a sincronização em tempo de leitura não pode mais mapear um objeto ainda não criado para Failed - inclusive em outras réplicas HA; recuperação reenvia linhas travadas inline (#2098), corrigindo a janela onde uma pesquisa client logo após a criação inverteu a linha para um Failed permanente (#2077)
  • Mapeie falhas de back-end com proxy para status significativos: tempos limite de leitura/gravação retornam 504 BACKEND_TIMEOUT, redefinições de resposta intermediária e erros de protocolo retornam 502 BACKEND_RESPONSE_FAILED, mantendo 502 BACKEND_CONNECTION_FAILED para falhas de conexão — um sandbox que morre no meio da solicitação não parece mais um bug de servidor (#2084)
  • Encontre pods alocados em pool para diagnóstico de k8s: BatchSandboxes em pool não carregam o rótulo de pod opensandbox.io/id, portanto, cada chamada de logs/eventos/inspeção retornou 404; a pesquisa agora retorna aos pods listados na anotação alloc-status da carga de trabalho (#2104)
  • Remova volumes Docker criados automaticamente quando a criação falhar antes da execução do bloco de provisionamento (extração de imagem, verificações de credenciais/proxy upstream, pré-requisitos do Windows, preparação de OSSFS) — um nome de imagem digitado incorretamente não vaza mais o PVC que acionou (#2103)
  • Relatório de exclusão de BatchSandboxes em pool/modo de tarefa como Stopping/DELETING: metadata.deletionTimestamp agora vence a publicação de status de tempo de execução, portanto, um sandbox cujos pods não ficam prontos durante a finalização não volta mais para Pending/CREATING (#2122)
  • Impedir que PATCHes de metadados Docker ressuscitem chaves excluídas: patch() agora inicia a partir do arquivo de substituição (como get() faz) em vez de mesclar novamente os rótulos do contêiner, então {"env": null} permanece excluído e um arquivo de substituição esvaziado não restaura os rótulos originais (#2065)
  • Aceitar env na criação do modelo e inseri-lo na imagem dourada do fast-sandbox (/etc/sandbox-init.env, herdando o OCI Config.Env da imagem de origem), fechando a lacuna onde SandboxTemplate.spec.envs existia, mas o ciclo de vida API o rejeitou; compatível com todos os SDKs (#1984)
  • A criação do Wake Kubernetes aguarda eventos de observação do informante em vez de uma pesquisa fixa de 1 segundo, reduzindo a latência de criação do pool pré-aquecido de ~ 1 s para dezenas de milissegundos, enquanto mantém o fallback de pesquisa (#1996)
  • Envie os stubs FastPath gRPC comprometidos na roda do servidor à força - incluindo-os após as exclusões do VCS do hatchling e importe a roda construída no fluxo de trabalho de lançamento antes de publicar - esta é a correção de falha no tempo de instalação do 1.1.0 (#1959)
  • Corrigido o instantâneo CR plural do Fast Sandbox (sandboxsnapshots) no Helm RBAC e o tempo de execução do instantâneo fsb, onde sandboxesnapshots poderia falhar na lista/observação com RBAC ausente (#1972)
  • Propague a mensagem de erro FastPath subjacente por meio do mapeamento de capacidade 429 (mantendo o status e Retry-After, adicionando um campo cause) para que falhas de admissão/tempo de execução, como um dispositivo KVM quebrado, não sejam mais mascaradas como exaustão do pool e registre o erro bruto antes do mapeamento (#2001)
  • Esclareça o contrato de renovação: renew-expiration pode encurtar, preservar ou estender a expiração (qualquer meta futura é válida) e max_sandbox_timeout_seconds limita apenas a criação, não a renovação ou a vida útil total - documentação e referências SDK alinhadas, com cobertura de regressão em Docker, Kubernetes e FastSandbox (#2087)
  • Corrija as bordas do Docker: rejeite uma pausa repetida de um sandbox já pausado com o 409 documentado em vez de trazer à tona o "já pausado" do Docker como 500 (#2023) e limpe os caminhos do sistema mascarado/somente leitura do Docker apenas para sandboxes que optam pela extensão de isolamento para que o Bubblewrap aninhado possa montar um procfs privado (#1982)

SDKs

  • Adicione operações de sistema de arquivos vinculadas à identidade de ponta a ponta: execd ganha rotas /v1/filesystem/{uid}/{gid} aditivas apoiadas por um processo de trabalho por solicitação em execução com credenciais explícitas e grupos suplementares derivados de conta (fechado com falha, rotas existentes inalteradas) e cada sandbox SDK as expõe — Python files_with_identity, JavaScript filesWithIdentity, Kotlin filesWithIdentity, C# FilesWithIdentity, Go FilesWithIdentity — para que o Linux verifique as permissões do usuário selecionado durante o acesso real; a seleção de identidade pertence ao back-end trusted, isso impõe permissões do sistema de arquivos e não é um limite de inquilino (#2070 #2093 #2094 #2095 #2096 #2097)
  • Exponha várias montagens de sobreposição independentes por sessão isolada no API e em todos os cinco SDKs: CreateIsolatedSessionRequest.overlays ({path, mode, persist}) com partes superiores tmpfs rastreadas por host ou efêmeras separadas, workspace mantido como açúcar e SessionState ecoando a lista canônica - completando a base interna de #2021 (#2032)
  • Adicionar commands.setEnv para injeção de ambiente de tempo de execução persistente em todos os cinco SDKs de sandbox (Python assíncrono/sincronizado, JavaScript, Kotlin/Java, Go, C#): anexa KEY=VALUE ao arquivo de ambiente de sandbox com serialização exata de tempo de execução, validação de chave local/NUL e uma falha alta quando EXECD_ENVS não está definido (#2013)
  • Limpeza sistemática de auditoria entre idiomas em sandbox, intérprete de código e MCP SDKs: tente novamente o backoff, colapsando para atraso zero e sessão descartada cwd, sessão isolada Python ignorando encoding e orçamentos de prontidão relatando erros obsoletos, JS retoma o compartilhamento e elimina o transporte do sandbox de origem, códigos Kotlin são executados eliminando todos os eventos enquadrados por SSE e nunca configurando exitCode, C# cria falha no novo sandbox 404 e NREs em corpos vazios, e MCP por chamada fecha destruindo o transporte compartilhado em todo o servidor - cada um corrigido com testes de regressão (#2020)
  • Suporte env no modelo criado em todos os cinco SDKs, combinando com o cozimento da imagem dourada do lado do servidor (#1984)
  • Alinhar a conclusão do fluxo de comando em segundo plano entre idiomas: com o atraso de conclusão fixo do execd removido, a coleta de resultados em segundo plano em Go, Kotlin e C# agora retorna na confirmação de inicialização como Python e JavaScript em vez de esperar por EOF e inferir o código de saída 0 — status do comando de consulta para o resultado final; chamadas em primeiro plano ainda são lidas para EOF para servidores mais antigos (#1825) ###Python

  • Autenticar solicitações de intérprete de código no modo proxy de servidor: criação de contexto e execução de streaming agora anexa a chave API como solicitações de arquivo sandbox, corrigindo 401s do mesmo proxy (#2125)

Controlador

  • Adicionar métricas de caminho do alocador OpenTelemetry no medidor opensandbox/controller: programação de alocação de pool, persistência de estado de alocação e histogramas de duração de sincronização de resultado de alocação com atributos de namespace/pool/sucesso, exportados por OTLP (#2014)
  • Prepare a superfície de atribuição de pool para extensão personalizada: a interface Predicate e os métodos predicados em poolassign agora são exportados - o pacote permanece em kubernetes/internal/, portanto, módulos Go externos não podem importá-lo ainda (#2037)
  • Substituição automática de pods BatchSandbox presos em falhas de provisionamento durante a inicialização: pods nunca prontos aguardando em ImagePullBackOff/ErrImagePull são excluídos após um limite para que o agendador possa escapar de um nó quebrado (um disco cheio deixou uma frota de produção com 114 sandboxes travados), com um orçamento de substituição por sandbox, por geração e um aviso PodRecoveryLimitReached; imagens permanentemente quebradas são ignoradas (#1961)
  • Suporte a modelos de URI de imagem de instantâneo personalizados: rootfs de nome --snapshot-image-uri-template / controller.snapshot.imageURITemplate e destinos de estado de VM QEMU com metadados de instantâneo/sandbox/contêiner/namespace e auxiliares date/dateInZone, validados (refs inválidos, alvos duplicados) antes da criação do trabalho; vazio mantém a nomenclatura existente (#2004)
  • Corrija o predicado free-pod admitindo pods apenas em um IP não vazio: o agendador de tarefas vinculou tarefas aos pods Kubernetes marcados como NotReady (ainda iniciando ou reiniciando), a atribuição POST falhou sem nenhuma nova tentativa e um irmão saudável foi ignorado; a prontidão agora é necessária como qualquer outro predicado (#2138)
  • Mantenha o status da última tarefa conhecida quando uma consulta de status falhar durante a liberação: um único /getTasks com tempo limite não marca mais uma tarefa releasing como concluída, o que ignorou Set(nil), ignorou o gancho postStop e deixou o controlador descartar o finalizador de limpeza ou retornar o pod para o pool enquanto a tarefa ainda estava em execução (#2067)
  • Pular despacho de pausa para um BatchSandbox já Paused: renovar um sandbox pausado acelerou sua geração e reativou o handlePause, que precisa de um pod de origem em execução e levou o sandbox para Failed/PauseFailed (#2082)
  • Correção de um impasse do committer de imagem em que a pausa do contêiner QEMU por meio do congelamento do cgroup v2 nunca é concluída (threads do kernel do trabalhador KVM nunca atingem frozen), ignorando o congelamento redundante para o contêiner QEMU já pausado no QMP e confirmando com --pause=false (#1986)

Executado

  • Execute operações comuns do sistema de arquivos sob uma identidade Linux explícita: rotas aditivas /v1/filesystem/{uid}/{gid} geram um processo de trabalho por solicitação com o uid/gid selecionado e grupos suplementares derivados de conta, fechados com falha em plataformas não suportadas; as rotas existentes mantêm sua identidade atual - os acompanhamentos voltados para SDK são enviados na mesma versão (#2070)
  • Expor as sobreposições públicas de sessão isolada API (validação, mesclagem canônica com workspace legado, atribuição de alocador por sobreposição) - detalhes e suporte SDK em SDKs (#2032)
  • Fornece às sessões de sobreposição uma identidade de limpeza durável fora de sua subárvore removível (<upper_root>/.execd-cleanup/<session-id>): a recuperação de inicialização remove apenas os diretórios correspondentes exatos e a exclusão parcial ou os registros perdidos são tentados novamente dentro do processo ou entre reinicializações, em vez de tornar os diretórios superiores órfãos (#2107)
  • Deixe os filhos de um comando em segundo plano concluído continuarem em execução: o contexto pós-Wait cancela não mais SIGKILLs todo o grupo de processos, então um nohup ./server & em segundo plano sobrevive ao seu script - cancelamento e tempos limite ainda matam o grupo (#2074)
  • Eliminar todo o grupo de processos quando a execução de uma sessão bash expirar: apenas o próprio bash foi eliminado, então os filhos (sleep 2; …) mantiveram a execução suspensa além do prazo (#2079)
  • Preservar os bytes \n/\r no texto do evento stdout/stderr /command em primeiro plano, para que os eventos concatenados reconstruam os finais de linha do comando, incluindo linhas em branco e um fragmento final não terminado; o Python SDK orientado para exibição Execution.text e o resumo stderr não inserem mais linhas em branco extras quando CRLF chega em eventos, enquanto logs.stdout/logs.stderr brutos mantêm seu texto original (#2033)
  • Remova o arquivo de script de sessão bash por execução (execd_bash_*.sh), que retinha uma cópia de cada variável de ambiente de sessão - segredos incluídos - legível por qualquer comando posterior como o mesmo usuário (#2076)
  • Prenda a extremidade HTTP Range antes de calcular o comprimento: bytes=0-9223372036854775807 estourou para um comprimento negativo e respondeu 206 com um Content-Range/Content-Length quebrado e sem corpo, em downloads de sessão regular e isolada (#2089)
  • Remova o atraso fixo de um segundo após a conclusão do comando, reduzindo a latência média do evento do terminal para retornar de aproximadamente 1000 ms para menos de milissegundos, mantendo a liberação de saída e a limpeza de pulsação (#1825)
  • Pare de registrar cada pedaço stdout/stderr no nível de informação, que representou 99.8% do volume de log execd em cargas de trabalho com saída pesada (#1906)

Rede

saída

  • Continuar a base de interceptação TLS vinculada a credenciais (OSEP-0023) [EXPERIMENTAL] através da linha: retornos de chamada de sessão de revisão ao vivo fixados por geração mantidos sob o bloqueio de ciclo de vida mitmproxy (#2036), classificação ClientHello sem credencial de ECH/SNI/passagem estática com solicitações de admissão needs_registry (#2046), um registro de admissão de conexão limitado que nega a exaustão em vez de fazer downgrade para passagem opaca (#2062) e sinaliza admissões descobertas por cortes de seletores (#2072), solicitação de admissão fixada em um instantâneo imutável sem fallback de credenciais antigas e cercas permanentes para hosts removidos (#2088), ciclos de vida de tratamento de solicitação limitados com um orçamento global e inspeção paginada (#2091), prazos de desativação monotônicos para conexões descobertas (#2100), publicação conjunta de receptor/registo TLS com semântica de repetição de preparação/confirmação/aborto (#2106) conectado ao IPC de revisão autenticado por meio de um InstallationReceiver interno (#2120), transações de mutação do Vault apoiadas por revisão com reconciliação de tentativa exata e cerca de prontidão (#2124), candidatos de revisão de política efetiva congelados revalidando todas as ligações, incluindo aquelas somente HTTP (#2139), recuperação de revisão protegida e publicação de prontidão com identidade de bootstrap exata e resultados incertos em quarentena (#2151) e cobertura de recuperação IPC entre idiomas contra o endpoint de produção (#2136) — apenas base; o Vault público ainda grava 503 sob o portão e o TLS seletivo permanece desabilitado
  • Estender o proxy CONNECT upstream encadeado: proxies trust https:// assinados por uma CA privada por meio de um pacote OPENSANDBOX_EGRESS_MITMPROXY_UPSTREAM_EXTRA_CA estilo anexo que aumenta o armazenamento trust do sistema para todas as verificações TLS upstream, configuradas a partir do ca_cert_path/ca_secret_name do servidor (#2030); suporte ao proxy encadeado no perfil de sandbox rápido com quedas de endpoint em todo o perfil para que as cargas de trabalho de sandbox não possam alcançar o proxy upstream diretamente, propagação de DNS de infraestrutura resolvida simultaneamente por meio de upstreams dnsproxy e o resolvedor de pod e propagação de tabela nft atômica com elementos de descarte permanentes durante o tempo de inatividade do daemon (#2003)
  • Adicione um proxy CONNECT upstream encadeado opcional ao caminho mitmproxy transparente (OPENSANDBOX_EGRESS_UPSTREAM_PROXY/_AUTH), roteando a saída da sandbox por meio de proxies de encaminhamento corporativos com autoridade CONNECT consistente com SNI/Host, validação de inicialização com falha fechada e nenhuma mudança de comportamento quando não definido (#1816)
  • Reverter o arquivo de política persistente quando uma aplicação NFT falhar, para que uma reinicialização nunca carregue uma política que o chamador foi informado de que havia falhado - potencialmente mais flexível do que aquela que está realmente em execução (#2075)
  • Tolerar barras codificadas por porcentagem aninhadas no protetor de caminho do proxy de credencial: o relaxamento %2f de camada única agora se aplica a qualquer profundidade de decodificação, portanto, os downloads de pip de proxies PyPI internos não falham mais com 403 request path contains ambiguous segments enquanto o Credential Vault está ativo; segmentos de pontos, barras invertidas em todas as profundidades e decodificações não convergentes ainda são rejeitados (#2153)
  • Continuar a base anterior vinculada a credenciais: inicializar sessões de revisão autenticadas no lançamento do sidecar e reiniciar atrás de um portão interno (#1948), preparar candidatos de mutação não publicados do Credential Vault com semântica de confirmação de reconhecimento antes de publicar (#1980), serializar /policy e o Vault escreve atrás de uma barreira de mutação compartilhada (#1991), preparar recargas sempre com regras antes da publicação (#1997), reter a identidade exata da tentativa em resultados de coordenador indeterminados (#2007) e adicionar atualizações de revisão pós-bootstrap com reconciliação de tentativa exata (#2017)

entrada

  • Falha no tempo de renderização do gráfico quando providerType=fast-sandbox está configurado sem um chaveiro de acesso seguro: o gateway passou anteriormente por helm template e depois CrashLoopBackOff'd em FastPath routing requires --secure-access-keys; o guia de implantação agora também documenta o gateway conforme necessário no Kubernetes (os pods sandbox são somente ClusterIP) e instalados antes do servidor (#2047)
  • Suporte à desativação por solicitação de intenções de renovação de acesso por meio de um cabeçalho OpenSandbox-Access-Renew: skip, suprimido antes que o estado do acelerador seja tocado e removido nos caminhos do gateway e do proxy do servidor - para sondagens de integridade e outro tráfego no estilo de pulsação (#1966)

OpenSandbox release-1.1.1

Stable cut of the 1.1.1 patch line: fixes the broken 1.1.0 server wheel — hatchling's VCS-exclude filtering silently dropped the committed FastPath gRPC stubs from the PyPI package, so every 1.1.0 install of opensandbox-server failed at import time; PyPI is immutable, so the fix ships on this line (#1959). SDK/CLI/server packages publish at 1.1.1 (1.1.1-rc.1 shipped images only). Everyone on 1.1.0 should upgrade. Baseline for every section below: release-1.1.0.

Highlights

  • Fixes the 1.1.0 server wheel: FastPath stubs now ship in the package and installs import cleanly; SDK/CLI/server packages publish at 1.1.1 (#1959)
  • Identity-bound filesystem operations: execd executes file APIs as an explicit Linux UID/GID, with FilesWithIdentity/files_with_identity in all five SDKs; isolated sessions gain multiple independent overlay mounts (#2070 #2093 #2094 #2095 #2096 #2097 #2032)
  • Server hardening: snapshot creation submits the runtime object before persisting so early reads can't map to Failed, proxied backend failures map to 502/504 instead of a generic 500, and diagnostics work for pooled sandboxes (#2098 #2077 #2084 #2104)

Server

  • Implement pause/resume for the agent-sandbox provider by bridging to spec.operatingMode (Running/Suspended) on agents.x-k8s.io/v1beta1, with state derivation (Paused/Pausing/Resuming/Terminated) and 409 on invalid transitions; both endpoints previously returned "not supported" (#1975)
  • Isolate tenants that share one Kubernetes namespace: creates stamp opensandbox.io/tenant, and list/get/delete/pause/resume/proxy hide other tenants' labeled sandboxes as 404 while unlabeled legacy sandboxes stay visible until expiry; also adds kubernetes.insecure_skip_tls_verify for ServiceAccount CA mismatches (#1973)
  • Heal the silent renew-intent drop after a server restart in multi-tenant mode: the resolver now falls back to a cluster-wide label lookup with a 403 circuit breaker and structured warnings, trusts an ingress-observed namespace from the intent payload when verifiable, and single-tenant deployments never resolve beyond the configured namespace (#1819)
  • Add [docker] publish_host to publish bridge-mode sandbox ports on one host address (default 0.0.0.0 unchanged) — with 127.0.0.1 or the Docker bridge gateway, the tokenless execd port no longer lands on public interfaces (#1954)
  • Add a typed, admin-only [egress.upstream_proxy] config section (URL + optional authorization, validated at load) that injects the sidecar's chained upstream CONNECT proxy on both Docker and Kubernetes, with fail-closed 400s when the requested networkPolicy is incompatible; secret values are no longer echoed in config-validation errors (#1999), plus ca_cert_path (Docker) and ca_secret_name (Kubernetes) so https:// proxies signed by a private CA are trusted without replacing the system trust store — the PEM augments /etc/ssl/certs in the sidecar (#2030)
  • Make snapshot creation race-free for early readers on k8s/fsb: POST /sandboxes/{id}/snapshots now creates the runtime object (SandboxSnapshot CR / fsb submit) before persisting the Creating row and returns without queueing a worker, so read-time sync can no longer map a not-yet-created object to Failed — including on other HA replicas; recovery resubmits stuck rows inline (#2098), fixing the window where a client polling right after create flipped the row to a permanent Failed (#2077)
  • Map proxied backend failures to meaningful statuses: read/write timeouts return 504 BACKEND_TIMEOUT, mid-response resets and protocol errors return 502 BACKEND_RESPONSE_FAILED, keeping 502 BACKEND_CONNECTION_FAILED for connect failures — a sandbox that dies mid-request no longer looks like a server bug (#2084)
  • Find pool-allocated pods for k8s diagnostics: pooled BatchSandboxes don't carry the opensandbox.io/id pod label, so every logs/events/inspect call returned 404; the lookup now falls back to the pods listed in the workload's alloc-status annotation (#2104)
  • Remove auto-created Docker volumes when create fails before the provisioning block runs (image pull, credential/upstream-proxy checks, Windows prerequisites, OSSFS prep) — a mistyped image name no longer leaks the PVC it triggered (#2103)
  • Report deleting pooled/task-mode BatchSandboxes as Stopping/DELETING: metadata.deletionTimestamp now wins over runtime status publication, so a sandbox whose pods go not-ready during finalization no longer flips back to Pending/CREATING (#2122)
  • Stop Docker metadata PATCHes from resurrecting deleted keys: patch() now starts from the override file (as get() does) instead of re-merging container labels, so {"env": null} stays deleted and an emptied override file doesn't restore the original labels (#2065)
  • Accept env on template create and bake it into the fast-sandbox golden image (/etc/sandbox-init.env, inheriting the source image's OCI Config.Env), closing the gap where SandboxTemplate.spec.envs existed but the lifecycle API rejected it; supported across all SDKs (#1984)
  • Wake Kubernetes creation waits on informer watch events instead of fixed 1-second polling, cutting prewarmed-pool create latency from ~1 s to tens of milliseconds while keeping the polling fallback (#1996)
  • Ship the committed FastPath gRPC stubs in the server wheel by force-including them past hatchling's VCS excludes, and smoke-import the built wheel in the release workflow before publishing — this is the 1.1.0 install-time breakage fix (#1959)
  • Fix the Fast Sandbox snapshot CR plural (sandboxsnapshots) in Helm RBAC and the fsb snapshot runtime, where sandboxesnapshots could fail list/watch with missing RBAC (#1972)
  • Propagate the underlying FastPath error message through the 429 capacity mapping (keeping status and Retry-After, adding a cause field) so admission/runtime failures like a broken KVM device are no longer masked as pool exhaustion, and warn-log the raw error before mapping (#2001)
  • Clarify the renewal contract: renew-expiration may shorten, preserve, or extend expiration (any future target is valid) and max_sandbox_timeout_seconds caps only creation, not renewal or total lifetime — documentation and SDK references aligned, with regression coverage across Docker, Kubernetes, and FastSandbox (#2087)
  • Fix Docker edges: reject a repeated pause of an already-paused sandbox with the documented 409 instead of surfacing Docker's "already paused" as 500 (#2023), and clear Docker masked/read-only system paths only for sandboxes that opt into the isolation extension so nested Bubblewrap can mount a private procfs (#1982)

  • Expose multiple independent overlay mounts per isolated session across the API and all five SDKs: CreateIsolatedSessionRequest.overlays ({path, mode, persist}) with separate host-tracked or ephemeral tmpfs uppers, workspace kept as sugar, and SessionState echoing the canonical list — completing the internal foundation from #2021 (#2032)
  • Add commands.setEnv for persistent runtime env injection in all five sandbox SDKs (Python async/sync, JavaScript, Kotlin/Java, Go, C#): appends KEY=VALUE to the sandbox env file with runtime-exact serialization, local key/NUL validation, and a loud failure when EXECD_ENVS is unset (#2013)
  • Systematic cross-language audit cleanup across sandbox, code-interpreter, and MCP SDKs: Go retry backoff collapsing to zero delay and dropped session cwd, Python isolated-session ignoring encoding and readiness budgets reporting stale errors, JS resume sharing and killing the source sandbox's transport, Kotlin codes runs dropping every SSE-framed event and never setting exitCode, C# create failing on fresh-sandbox 404 and NREs on empty bodies, and MCP per-call closes tearing down the server-wide shared transport — each fixed with regression tests (#2020)

  • Align background command stream completion across languages: with execd's fixed completion delay removed, background result collection in Go, Kotlin, and C# now returns on startup acknowledgement like Python and JavaScript instead of waiting for EOF and inferring exit code 0 — query command status for the eventual outcome; foreground calls still read to EOF for older servers (#1825)

Python

  • Raise on error responses from create_session and delete_session: both passed the parsed model to the error handler (which needs the raw status), so 400/404/500 returned None as success and unknown statuses raised with a bogus status_code=200 — the CLI could print "Deleted session" for a session that never existed (#2066)
  • Expose follow_redirects on ConnectionConfig/ConnectionConfigSync, propagated to all handwritten async/sync httpx clients including SSE clients and generated-client wrappers (#1123)
  • Keep the last real endpoint error when the readiness deadline expires mid-request: the budget no longer records its own SandboxReadyTimeoutException as last_error, so causes like KUBERNETES::POD_IP_NOT_AVAILABLE aren't masked as a plain timeout (#2121)
  • Authenticate Code Interpreter requests in server-proxy mode: context creation and streamed execution now attach the API key like sandbox file requests, fixing 401s from the same proxy (#2125)
  • Serialize SandboxPoolSync.shutdown() teardown: concurrent shutdown (or shutdown racing start()) could close the warmup event loop twice; teardown is now idempotent under a dedicated lock (#2041)
  • Orphan the shared warmup event loop instead of closing it over an in-flight warmup: when the bounded drain wait ends with warmups still running, shutdown leaves the loop alive so the in-flight warmup finishes and cleans up its sandbox, instead of destroying the pending task and skipping cleanup (#2142)

Execd

  • Execute ordinary filesystem operations under an explicit Linux identity: additive /v1/filesystem/{uid}/{gid} routes spawn a per-request worker process with the selected uid/gid and account-derived supplementary groups, fail-closed on unsupported platforms; existing routes keep their current identity — the SDK-facing follow-ups ship in the same release (#2070)
  • Expose the public isolated-session overlays API (validation, canonical merge with legacy workspace, per-overlay allocator assignment) — details and SDK support under SDKs (#2032)

  • Let children of a finished background command keep running: the post-Wait context cancel no longer SIGKILLs the whole process group, so a backgrounded nohup ./server & survives its script — cancellation and timeouts still kill the group (#2074)
  • Kill the whole process group when a bash session run times out: only bash itself was killed, so (sleep 2; …) children kept the run hanging past its deadline (#2079)
  • Preserve \n/\r bytes in foreground /command stdout/stderr event text, so concatenated events reconstruct the command's line endings including blank lines and a trailing unterminated fragment; the Python SDK's display-oriented Execution.text and stderr summary no longer insert extra blank lines when CRLF arrives across events, while raw logs.stdout/logs.stderr keep their original text (#2033)
  • Remove the per-run bash session script file (execd_bash_*.sh), which retained a copy of every session environment variable — secrets included — readable by any later command as the same user (#2076)

Upgrade & Compatibility

  • The 1.1.0 server package on PyPI is broken at import time and cannot be replaced (PyPI is immutable) — upgrade to this line; see #1959
  • Behavior change: the HTTP proxy maps backend read/write timeouts to 504 and mid-response failures to 502 with typed error codes instead of a generic 500; SDK default retry configs differ for the new 504 — the Go SDK's DefaultRetryConfig retries 504 like 502/503, while Python's default retries 502/503 only (#2084)
  • Behavior change: children left behind by a finished background command keep running after it exits, matching the foreground path; cancellation and timeouts still kill the group (#2074)
  • Behavior change: snapshot creation on k8s/fsb submits the runtime object before persisting and recovery resubmits inline; polling clients no longer observe a spurious permanent Failed (#2098)
  • Behavior change: background command result collection in Go, Kotlin, and C# returns on startup acknowledgement and no longer infers exit code 0 — query command status for the eventual outcome (#1825)
  • Behavior change: in multi-tenant mode, another tenant's labeled sandboxes in a shared namespace now resolve as 404; unlabeled legacy sandboxes stay visible until expiry (#1973)
  • Chart: the base chart now creates the shared fastSandbox.namespaces.system namespace by default — set fastSandbox.namespaces.createSystem=false if you manage it externally (#2044); the ingress gateway is required on Kubernetes deployments and must be installed before the server, and fast-sandbox mode requires a secure-access key ring at render time (#2047 #2048)
  • Fast-sandbox operators: restores never boot a kernel and direct boot requires an explicit operator kernelPath pin (#2028); the Firecracker runtime now requires XFS with reflink at startup — use the provided reflink-XFS state-disk helper on nodes that lack it (#2123); the vendored CRD drops the removed boxlite runtime enum (#2145); the integration environment reads RUSTFS_*/RC_IMAGE instead of MINIO_*/MC_IMAGE with no legacy alias (#2009)

  • Kubernetes: supported range v1.21 – v1.34 (charts declare kubeVersion: ">=1.21.1-0")
  • Skew: server ↔ CLI/SDK same line supported; ±1 minor warns

Installation

# Platform (Kubernetes) — render the chart at this tag and apply
git clone https://github.com/opensandbox-group/OpenSandbox
cd OpenSandbox
git checkout release-1.1.1
helm dependency build manifests/charts/opensandbox  # package file:// sub-charts (not committed)
# Before first install, configure the server API key and enable the ingress
# gateway (required on Kubernetes; the bare render disables it, and the server
# refuses to start with an empty api_key) — see the deployment guide:
# https://open-sandbox.ai/deployment/
helm template ./manifests/charts/opensandbox | kubectl apply -f -
# or point your GitOps platform (Argo / Flux) at the repo path + tag

# SDKs
pip install opensandbox==1.1.1            # Python
npm install @alibaba-group/opensandbox@1.1.1   # JavaScript
# Kotlin/JVM: implementation("com.alibaba.opensandbox:sandbox:1.1.1")
dotnet add package Alibaba.OpenSandbox --version 1.1.1
go get github.com/alibaba/OpenSandbox/sdks/sandbox/go@v1.1.1

# Run the server locally
uvx opensandbox-server==1.1.1

Verify what you installed against the BOM: see Release Verification.
