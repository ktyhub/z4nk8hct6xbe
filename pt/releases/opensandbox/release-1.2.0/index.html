Versão OpenSandbox-1.2.0

Corte estável da linha 1.2.0, transportando tudo mesclado desde release-1.1.1 através de dois candidatos a lançamento mais um delta de endurecimento pós-rc. Imagens enviadas com o rcs; Pacotes SDK/CLI/server são publicados em 1.2.0. Todos no 1.1.x deveriam atualizar. Linha de base para cada seção abaixo: release-1.1.1.

Destaques

  • Pausa automática e ativação ao acesso para sandboxes rápidos (OSEP-0024) chegam de ponta a ponta: o ingresso registra a atividade e estaciona solicitações para sandboxes pausadas até que a restauração seja concluída, o servidor executa uma varredura ociosa atrás de um campo de criação lifecycle.idlePolicy opcional e todos os cinco SDKs obtêm o contrato de nova tentativa de ativação - desativado por padrão, apenas aditivo (#2156 #2180 #2192 #2198 #2218)
  • Credential Vault (OSEP-0022) chega de ponta a ponta para sandboxes rápidos: o sidecar de saída mantém o vault com persistência durável por assunto e transferência de pausa/retomada selada, o servidor expõe o vault acessível pelo usuário API com valores de credencial nunca aparecendo em qualquer leitura pública, e o MITM CA é fixado por pool para que uma reinicialização de saída não gire mais a âncora trust em sandboxes ativas - além de escopo de porta regras de saída de ponta a ponta no perfil clássico (#2249 #2252 #2255 #2263 #2251 #2212)
  • Instantâneos rápidos de Sandbox e construções de modelos podem ser publicados e inicializados a partir de registros OCI (ciclo de vida OverlayBD OCI), e uma campanha de confiabilidade remove tempos limite de chamadas inteiras de transferências de arquivos SDK em todos os cinco idiomas, faz com que o execd relate CPU/memória com escopo de sandbox e eliminações de OOM e corrige uma longa lista de correção de backend Docker e problemas de saída de PTY/sessão (#2338 #2165 #2200 #2191)

Servidor

  • Implementar o lado do servidor da pausa automática OSEP-0024 para sandboxes rápidos: o campo de criação lifecycle.idlePolicy (idleTimeoutSeconds 30–86400, onIdle: pause, wakeOnAccess, activeProbe opcional) persiste como uma anotação Sandbox CR reservada; um varredor ocioso enumera sandboxes fsb optadas, verifica a atividade em Redis, faz um bloqueio de pausa por sandbox e emite um FastPath idempotente PauseSandbox; um activeProbe declarado passa pelo gateway de entrada e um sentinela OpenSandbox-Skip-Activity suprime uma observação e é removido nos saltos do gateway e do proxy. A configuração se move sob [automation.idle_pause] e redis.dsn é validado na carga quando o varredor está habilitado (#2192 #2181 #2215)
  • Implementar o Credential Vault API (OSEP-0022, perfil fast-sandbox): POST|GET|PATCH|DELETE /v1/sandboxes/{id}/credential-vault envia revisões completas do vault sobre o relé do manipulador FastPath e trata a resposta do relé como o ack validado por saída síncrona - o CRD nunca transporta material do vault e cada leitura pública é higienizada no lado do servidor; PATCH compõe na memória com expectedRevision como backstop de réplica cruzada, back-ends não-fsb fazem proxy da superfície /credential-vault do sidecar e a rejeição de tempo de criação do fsb credentialProxy é suspensa (#2263)
  • Asse o MITM CA fixado em SandboxTemplates criados pelo servidor (OSEP-0022): a nova configuração [kubernetes] template_mitm_ca_secret (padrão desativado) emite spec.egressMitmCertificate — apenas a entrada do certificado, nunca a chave privada — em cada modelo; o segredo deve existir em cada namespace de modelo (distribuição de runbook de operações), e uma cópia perdida falha na construção de forma observável (#2288)
  • Adicionar lifecycle.renewalPolicy (OSEP-0009): a opção de renovação ao acessar passa da chave opaca extensions["access.renew.extend.seconds"] para uma renewalPolicy.extendSeconds estruturada (300–86400); a chave herdada está obsoleta (suportada em 1.x, removida em 2.0) e o sandbox rápido a rejeita com 400 em vez de aceitar silenciosamente um modo não operacional (#2296)
  • Implementar o endpoint de contexto de diagnóstico (especificação em #2236): GET /v1/sandboxes/{sandboxId}/diagnostics/context retorna o ID do sandbox, o estado do ciclo de vida, o tipo de backend e os identificadores definidos pelo backend para Docker, Kubernetes e Fast Sandbox sem se conectar ao execd — o contexto Kubernetes permanece disponível antes que um pod seja alocado; back-ends de extensão que não a implementam retornam 501 (#2292)
  • Encaminhe o caminho ainda codificado através do proxy sandbox: Starlette vinculou a rota {full_path:path} do caminho decodificado por porcentagem, então um ? decodificado iniciou uma consulta, %2F se tornou um separador e os segmentos %2E%2E foram resolvidos - fechando um escape de prefixo em endpoints mapeados pelo host Docker; o proxy agora pega a cauda ainda codificada do client do caminho bruto (validando a decodificação para o caminho roteado) e lê a consulta da string de consulta bruta, para que os backends recebam alvos de solicitação byte por byte, correspondendo ao gateway de entrada (#2228)
  • Continue bloqueando chamadas Docker fora do loop de eventos: pesquisas de endpoint de proxy, validação de existência de rede e inspeção/criação de volume por PVC foram executadas de forma síncrona dentro de manipuladores assíncronos, de modo que um daemon Docker lento (por exemplo, durante uma grande extração) congelou todas as outras solicitações, incluindo tráfego de proxy; eles agora são executados em threads de trabalho com contexto de locatário preservado e falhas de validação de volume ainda limpam volumes criados automaticamente (#2268 #2366)
  • Parar de relatar rótulos herdados de imagem como estado de sandbox no Docker: as leituras de metadados retornaram para todos os rótulos de contêiner não reservados - incluindo rótulos mesclados da imagem - e os contêineres restaurados herdaram rótulos reservados, como expires-at, portas de host e o token de saída; na pior das hipóteses, uma sandbox TTL restaurada foi excluída porque já expirou após a reinicialização do servidor. As criações agora registram as chaves de metadados da solicitação em um rótulo reservado e leem apenas essas chaves, e os rótulos reservados presentes na imagem, mas não definidos pela sandbox, são apagados antes do início do contêiner (#2363 #2269)
  • Rejeitar instantâneos do gVisor que descartariam gravações silenciosamente: docker commit no padrão --overlay2=root:self do gVisor pode reportar READY enquanto não restaura nenhuma gravação do sandbox; a simulação de instantâneo agora recusa o gVisor, a menos que os argumentos efetivos incluam --overlay2=none e a criação falha quando o diferencial do sistema de arquivos é somente armazenamento de arquivos (#2241)
  • Manter um snapshot fsb cuja resposta de criação foi perdida: um UNAVAILABLE/DEADLINE_EXCEEDED do FastPath após a solicitação ter sido aceita de forma duradoura retornou 500 sem gravar uma linha, deixando o SandboxSnapshot e seus artefatos publicados sem registro; o create now investiga o instantâneo antes de falhar e o relata como enviado quando o FastPath o persistiu (#2361)
  • Corrija as arestas restantes do backend Docker: a expiração do BatchSandbox relata Terminated/SANDBOX_EXPIRED em vez de Running após spec.expireTime (#2238); conflitos simultâneos do ciclo de vida são mapeados para 404/409 em vez de 500 (#2387); patches de metadados simultâneos não chegam mais a 500 ou chaves perdidas (#2267 #2281); createdAt permanece estável durante as leituras e as transições de pausa/retomada são gravadas (#2405); as ações de política de rede são validadas e campos desconhecidos retornam 422 (#2383 #2385); a imagem da sandbox é lida a partir da configuração do contêiner, portanto, uma imagem docker rmi -f não é mais 500s GET /sandboxes (#2353); o modelo lê trust a projeção do banco de dados em vez de sincronizar o CR em cada verificação de criação (#2326); o resfriamento da renovação se aplica a todas as fontes de renovação quando o consumidor Redis está habilitado (#2276 #2279); Os pods BatchSandbox são padronizados como restartPolicy: Never, portanto, uma reinicialização do kubelet não pode mais limpar a camada gravável ao relatar Succeed (#2128); os modos de rede pasta/slirp4netns/none do podman passam (com networkPolicy rejeitado, já que não há ponte para conectar) (#2203); Os carimbos de data/hora Docker com segundos fracionários incomuns não informam mais silenciosamente a hora atual (#2220); e o contêiner de cache execd respeita os perfis de segurança [docker] e secure_runtime (#2254)

SDKs

As alterações de código abaixo acompanham os pacotes 1.2.0.

  • Adicione o contrato OSEP-0024 SDK a todos os cinco idiomas: um campo de criação lifecycle.idlePolicy digitado com validação de falha rápida do lado client, além do contrato de wake-retry - em um 503 carregando o marcador OpenSandbox-Wake: expired de propriedade do gateway (sua presença prova que a solicitação foi estacionada e nunca encaminhada, tornando a nova tentativa de qualquer método segura), o SDK reenvia após Retry-After sob um orçamento limitado (padrão 5 tentativas/60 s, botões por client) e a exaustão gera uma exceção de tempo limite de ativação digitada; o manuseio do 503 simples permanece inalterado (#2198 #2218). O contrato inicialmente contornou os transportes de streaming; a solicitação que inicia um fluxo agora faz novas tentativas em JavaScript, Python e Go - os fluxos estabelecidos nunca são reproduzidos - enquanto o fluxo C#/Kotlin começa atualmente com falha rápida (#2357 #2426)
  • Adicione o contrato Credential Vault client a todos os cinco SDKs (OSEP-0022): sandboxes apoiados por modelo roteiam chamadas de vault através do servidor no mesmo sinal de origem de modelo que a política de rede, enquanto os adaptadores diretos de sidecar permanecem intocados (#2263)
  • Pare de limitar uploads e downloads de arquivos no tempo limite da solicitação (padrão 30 s) em todos os cinco SDKs - o tempo limite de toda a chamada cobriu o envio do corpo e a leitura da resposta, de modo que qualquer transferência grande ou lenta falhou no meio do voo, mesmo quando saudável; as transferências agora são executadas em um client dedicado sem prazo de chamada completa que ainda limita a espera pelos cabeçalhos de resposta, portanto, uma transferência paralisada ainda falha em vez de travar (#2165 #2186 #2196 #2206)
  • Implementar diagnósticos em toda a superfície SDK (com #2292): context é exposto por meio das fachadas de gerenciador e sandbox em todos os cinco idiomas, e JavaScript, Go e C# obtêm logs/eventos públicos APIs correspondentes à superfície Python/JVM existente (#2292)
  • Adicione lifecycle.renewalPolicy a todos os cinco SDKs (OSEP-0009): um campo de criação digitado com validação de falha rápida do lado client (extendSeconds 300–86400), substituindo a chave de extensões opacas (#2296)
  • Suporta regras de saída com escopo de porta em todos os cinco SDKs: NetworkRule.ports (TCP 1–65535, no máximo 256 por regra, target agora opcional) com validação do lado client espelhando o servidor (intervalo, duplicatas, limite, domínio + portas rejeitadas); JavaScript codifica a invariante de destino ou portas como um tipo de união (#2212)
  • Apresentar o execution_complete.exit_code oficial em Go e Kotlin, preferindo-o aos substitutos evalue/inferred-0 anteriores, mantendo-se compatível com servidores mais antigos (#2330); honrar um cabeçalho OPEN-SANDBOX-API-KEY fornecido explicitamente sobre a chave configurada, independentemente da caixa do nome do cabeçalho em JavaScript, C# e Kotlin (#2348 #2372 #2375); suprimir métricas sandbox.create para o aquecimento do pool client criado em Go, Python e JavaScript (#2199)
  • Remover credenciais protegidas em redirecionamentos de origem cruzada em JavaScript, C# e Go: cabeçalhos prefixados em sandbox, tokens de endpoint (X-EXECD-ACCESS-TOKEN, X-API-Key) e cabeçalhos de autenticação configurados são removidos sempre que um redirecionamento altera esquema/host/porta, enquanto saltos de mesma origem e cabeçalhos não relacionados são preservados; uploads de arquivos nunca seguem redirecionamentos em JavaScript e, em navegadores, um redirecionamento opaco falha ao fechar, em vez de correr o risco de reproduzir credenciais (#2178 #2173 #2183)
  • Roteie os cabeçalhos do plano de dados do interpretador de código JavaScript e C# por meio da política compartilhada: as solicitações /code de modo direto não transportam mais o locatário OPEN-SANDBOX-API-KEY para execd, uma chave de conexão configurada explicitamente mantém precedência sobre o apiKey configurado sem entradas duplicadas de variante de caso e as credenciais com escopo de endpoint ainda vencem (#2149) ###Python
  • Tentar novamente o tempo limite de ativação do gateway ao iniciar um fluxo: o SSE clients removeu totalmente o wrapper de nova tentativa, então commands.run, a sessão é executada e codes.run em uma sandbox pausada automaticamente falhou com o marcado 503 sempre que a restauração durou mais que o orçamento do parque do gateway; os transportes de streaming agora realizam uma nova tentativa somente de ativação (sem novas tentativas gerais, sem prazos adicionais), e os documentos não reivindicam mais tentativas de bypass de fluxos (#2357)
  • Normalizar o domínio de conexão: uma barra final ou /v1 em domain / OPEN_SANDBOX_DOMAIN produziu URLs //v1/... que o servidor 404'd — a mesma variável funcionou em todos os outros SDK; Python agora remove ambos (#2347)
  • Reutilize contextos SSL em transportes próprios: os certificados CA foram recarregados em cada chamada, bloqueando o loop de eventos sob simultaneidade assíncrona - a criação medida P50 melhora cerca de 18–28% sob simultaneidade (#2360)
  • Preservar o primeiro evento SSE após uma BOM UTF-8 (incluindo uma divisão entre blocos de rede) (#2226); fechar corpos de resposta de tempo limite de ativação no cancelamento (#2371); fechar respostas de download de arquivo assíncrono interrompido para que uma leitura cancelada ou com falha não ocupe mais a conexão (#2369); manter o código de status quando uma resposta de erro carrega um corpo diferente de JSON — o HTML/404/500 vazio de um proxy apareceu anteriormente como InvalidArgumentException sem status (#2402); levanta o erro estruturado compartilhado de falhas do interpretador de código codes.run em vez de uma exceção criada manualmente que perdeu retry_after (#2364); mantenha os fragmentos de saída do interpretador de código juntos em Execution.text em vez de inserir novas linhas extras (#2408); arredondar o tempo limite do comando abaixo de milissegundos em até 1 ms em vez de enviar 0 (que desativou o tempo limite) (#2419); parar de propagar uma busca de endpoint cancelada para garçons simultâneos (#2277); encaminhar credential_proxy através de pools de sandbox, que o descartaram silenciosamente antes (#2283); parar de relatar substituições de arquivos com falha como bem-sucedidas (#2222); limpar a inicialização cancelada do pool assíncrono em vez de ficar preso no STARTING (#2209); regenerar o ciclo de vida client para eliminar padrões obsoletos codificados (comportamento do fio inalterado) (#2280); MCP: cancelar uma chamada de ferramenta não cancela mais uma conexão compartilhada unida para o mesmo sandbox, que falhou em todas as outras chamadas em espera (#2355) ###JavaScript
  • Preservar eventos de execução com finais de linha CR: os analisadores SSE são divididos apenas em LF, portanto, um fluxo delimitado por CR válido elimina silenciosamente o ID de execução, a saída e o evento de conclusão (#2374)
  • Escopo da invalidação do cache do endpoint em andamento para cada sandbox, de modo que a invalidação do sandbox B não descarte mais o resultado de uma busca pendente para o sandbox A (#2349)
  • Preservar pedaços de bytes reutilizados em uploads de arquivos: um produtor assíncrono que reutiliza uma visualização Uint8Array/Buffer carregou o conteúdo mutado duas vezes em vez de ambos os instantâneos (#2428); manter o cancelamento do chamador ativo após a chegada dos cabeçalhos de resposta - abortar o fluxo SSE intermediário ou o download intermediário que deixou o corpo em execução (#2350)

Vá

  • Pare de tentar novamente gravações não idempotentes por padrão: com a nova tentativa habilitada, 27 sites de chamada POST/PATCH (sandbox/sessão/comando/arquivo/instantâneo/mutações de cofre) podem ser executados duas vezes e ainda retornar sucesso — POST/PATCH não tenta mais repetir códigos de status por padrão, tenta novamente apenas falhas de transporte comprovadamente pré-envio (disque/CONNECT/TLS antes dos bytes de solicitação) e bootstraps SSE ignoram a nova tentativa genérica laço; chamadores que aceitam risco de execução duplicada podem aceitar via RetryConfig.RetryableStatusCodesNonIdempotent (#2342)
  • Tente novamente o tempo limite de ativação do gateway ao iniciar um fluxo SSE: os seis sites de chamada de streaming (execuções de comando/código/sessão, observação de métricas) anteriormente falharam imediatamente com o 503 marcado; o bootstrap agora estaciona dentro do mesmo orçamento Retry-After e retorna o erro de tempo limite de ativação digitado na exaustão - os fluxos estabelecidos nunca são reproduzidos, um 503 vazio ainda não é tentado novamente, mesmo com a opção de status de gravação, e um 503 alcançado por meio de uma cadeia de redirecionamento perde a proveniência do wake, portanto, uma solicitação já executada nunca é reenviada; chamadores que dependem de fail-fast podem passar WakeRetryDisabled() (#2426)
  • Manter terminadores de linha em Execution.Text(): execd já inclui \n/\r no texto do evento e requer concatenação para reconstruir stdout, mas o auxiliar inseriu uma nova linha extra entre eventos finalizados ("a\n" + "b\n" tornou-se "a\n\nb\n"); um separador agora é adicionado somente quando o evento anterior ainda não termina em um terminador (#2381)
  • Retire a chave do locatário API das solicitações de plano de dados de modo direto: uma chave de locatário fornecida por meio de ConnectionConfig.Headers foi entregue ao execd e ao sidecar de saída dentro da sandbox untrusted — completando as correções de exposição de credenciais em todos os cinco SDKs (#2337)
  • Autentique solicitações de plano de dados com proxy com o cabeçalho da chave API em vez de contrabandear a chave do locatário para a sandbox, corrigindo 401s no modo proxy multilocatário (#2274); superfície execution_complete.exit_code (#2330)

Controlador

  • Manter um BatchSandbox até que a limpeza seja concluída: um sandbox excluído pode desaparecer do ciclo de vida API (GET 404) enquanto seu pod de propriedade ainda estiver em execução, permitindo que um sandbox substituto grave o mesmo diretório persistente antes que o antigo gravador seja encerrado; a exclusão agora usa a exclusão em cascata de primeiro plano junto com os finalizadores existentes - as consultas relatam Stopping durante a limpeza gerenciada e 404 chega somente depois que o tempo de execução termina (#2154)
  • Correção do executor de tarefa tratando um arquivo de saída vazio como código de saída 0, que relatou uma tarefa com falha ou interrompida como Succeeded quando o shim foi eliminado no meio da gravação (#2270)

Executado

  • Relatar métricas de CPU/memória com escopo de sandbox e eliminações de OOM: GET /metrics lê o /proc do host dentro do contêiner, de modo que os painéis mostram números de todo o host; o uso agora vem do próprio cgroup do sandbox quando os limites são configurados (visualização do host mantida para convidados ilimitados), e um poller cgroupfs compara o contador de kills OOM do kernel a cada 5 s para exportar execd.system.oom.kills com logs de aviso estruturados - sem recursos necessários (#2200 #2191)
  • Servir o /tmp privado de sessão por meio dos arquivos API: o /tmp do perfil de isolamento estrito era um tmpfs anônimo sem caminho do lado do host, portanto, os caminhos dos arquivos API sob /tmp falharam e os chamadores tiveram que transportar artefatos por meio de comandos shell base64; /tmp agora é um diretório por sessão apoiado por host e montado no namespace - a mesma semântica privada, mas legível e gravável através dos endpoints de arquivos existentes (#2424)
  • Suporte à autenticação PTY WebSocket do navegador: os navegadores não podem definir X-EXECD-ACCESS-TOKEN em um handshake WebSocket nativo, portanto, as conexões de terminal precisavam de um relé BFF; a atualização PTY agora aceita o token execd existente por meio da entrada de credencial do subprotocolo opensandbox-pty (estilo Kubernetes) sem novo emissor de token e precedência de cabeçalho preservada para SDK/CLI clients (#2334)
  • Manter sessões isoladas ativas quando uma execução em primeiro plano é cancelada ou desconectada: o contexto da execução derivado da solicitação HTTP, portanto, uma desconexão ou expiração do timeout_seconds SIGINT'd todo o grupo de processos, incluindo o shell da sessão persistente - a sessão morreu e cada execução posterior 404'd; execuções agora interrompem apenas o comando em execução (com um escalonamento SIGKILL limitado) enquanto a sessão sobrevive, e execuções silenciosas em primeiro plano emitem pings SSE periódicos para que os tempos limite de inatividade do gateway não fechem mais o fluxo (#2351)
  • Preservar os finais de linha de saída da sessão bash: os eventos stdout run_in_session eliminaram os bytes \n/\r, portanto as linhas em branco eram irrecuperáveis e os eventos concatenados não reconstruíam a saída; o texto do evento agora carrega seu final de linha original - os consumidores devem concatenar o texto do evento por execução (#2318)
  • Encerrar uma execução do Jupyter quando seu kernel morrer ou a conexão cair: ambos os casos anteriormente deixavam a solicitação do interpretador de código aberta indefinidamente com pings SSE mantendo-a ativa; eles agora falham na execução (KernelDied / KernelConnectionLost) exatamente uma vez (#2401)
  • Manter a leitura da saída da sessão além de uma linha com mais de 16 MiB: o loop de leitura parou no limite — as sessões bash foram interrompidas até o tempo limite padrão de 24 horas e as sessões isoladas vazaram a saída para a próxima execução; linhas muito longas agora são transmitidas em pedaços (nunca dividindo UTF-8) (#2275)
  • Execute grandes códigos de segundo plano em sessões isoladas: o wrapper passou o código como um único argumento bash -c e o Linux limita um argumento exec a 128 KiB — o código de segundo plano acima falhou apenas com Argument list too long; agora é entregue através de stdin como o caminho de primeiro plano (#2400); teste a capacidade da rede privada para que tempos de execução restritos obtenham um erro estruturado para sessões share_net=false em vez de um EOF opaco (#2333)
  • E as correções menores: relatar exit_code explicitamente na conclusão do comando e erros (#2303 #2316); enviar erros de execução depois que o fluxo foi iniciado como eventos SSE error emoldurados, em vez de um corpo JSON vazio, o Python SDK caiu (#2354); mantenha a saída PTY armazenada em buffer até ser drenada quando o shell sair, para que a última tela de saída não seja mais perdida (#2362); sempre envie o quadro fechado WSCloseTakenOver (4001) no controle do PTY, mesmo no meio da gravação (#2376 #2378); escrever um script de execução isolado enquanto lê sua saída para que uma execução tagarela não possa mais travar nos pipes stdin/stdout (#2399); rejeitar caminhos absolutos fora do escopo na visualização dos arquivos da sessão em vez de tocar silenciosamente no arquivo errado (#2322); servir pontos de montagem binds através dos arquivos de sessão isolados API (#2299); truncar os arquivos de saída do comando antes de desvincular, para que os daemons que mantêm o fd não possam causar crescimento invisível do disco (#2295); omitir métricas inválidas de uso superior e falhar na admissão de cota fechada em caso de erros de verificação (#2257); desduplicar importações JDK MITM CA em armazenamentos trust compartilhados (~6.2 s → ~0.6 s para quatro JDKs) (#2310); sessões PTY padrão para TERM=xterm-256color quando não definidas (#2313); aspas e barras invertidas com codificação percentual em nomes de arquivos Content-Disposition (#2161); e analise o cabeçalho Range antes de definir os cabeçalhos de download para que um intervalo malformado retorne um JSON 416 limpo (#2216)

Os itens do cofre OSEP-0022 dizem respeito à superfície do cofre de credenciais do perfil fast-sandbox; os itens OSEP-0023 permanecem com escopo definido para o tempo de execução de revisão experimental padrão.

  • Adicione o cofre mantido por saída para sandboxes rápidos (OSEP-0022), aterrissando em estágios: a superfície de retransmissão interna /vault/{sandboxUid} com POST somente de criação (409 em duplicado, atômico em réplicas de servidor), revisão completa PUT com expectedRevision e uma pré-condição expectedIncarnation para que um gravador obsoleto nunca possa acessar o sucessor de uma redefinição, valor incluindo GET e DELETE que mantém a política (#2249); persistência durável por assunto — um arquivo por assunto em um volume com escopo de pod (tmpfs opcional), o mesmo protocolo de commit dos arquivos de política, então acked significa durável e aplicado, recarga protegida por encarnação e eliminação ao desvincular (#2252); e a rota do cofre fastlet-proxy substituída foi removida (#2247)
  • Carregar o cofre durante a pausa/retomada (OSEP-0022 "Ciclo de vida do cofre"): VAULT_EXPORT copia o arquivo do cofre no pacote de instantâneo estritamente antes da desmontagem do tempo de execução e sela o assunto (todas as operações do cofre respondem 409 enquanto pausadas; a aplicação continua) e VAULT_IMPORT é a única transferência de encarnação autorizada - uma falha de exportação genuína falha no ponto de verificação de pausa para que a desmontagem nunca seja executada sem um pacote, e um sinal de capacidade vaultTransfer permite uma saída sem persistência do vault, pule a transferência em vez de falhar (#2255 #2290)
  • Fixe a CA MITM de sandbox rápida (OSEP-0022): a CA versionada e fixada em pool é propagada a partir de uma montagem secreta somente leitura no confdir mitmdump, substituindo a geração ao iniciar - uma reinicialização de saída não gira mais a CA e invalida silenciosamente o TLS trust de cada sandbox ativo; uma CA ausente ou incompatível recusa apenas o complemento MITM com mitmCaFingerprint / mitmCaDown exibido em /healthz (#2251)
  • Definir o controle de assunto obsoleto na reutilização de slot: a chave de despacho do fast-sandbox é o IP do slot e os slots são reutilizados, de modo que um SET_BINDING pode reivindicar uma chave ainda mantida por um assunto morto, mas registrado - a saída agora trata isso como autoritativo, destruindo as regras NFT, refcount DNS, redirecionamento MITM e fatia do cofre do sujeito obsoleto antes de registrar o sucessor deny-first (#2250)
  • Alinhe a política de rede fast-sandbox com o padrão de vault: a política gravada torna-se um estado de saída mantida - uma superfície de retransmissão /policy/{sandboxUid} com pré-condições de revisão, arquivos duráveis por assunto, transferência de instantâneo POLICY_EXPORT/POLICY_IMPORT e, após uma reinicialização de saída, o arquivo confirmado substituindo a entrada de ligação de tempo de criação reproduzida (#2309)
  • Suporte a regras de saída com escopo de porta de ponta a ponta (perfil clássico): NetworkRule.ports (TCP 1–65535, ≤256 por regra) torna target opcional — regras somente de porta ou portas combinadas com um IP/CIDR; domínio+ports é rejeitado porque as regras de domínio são avaliadas na camada proxy DNS; uma lista de permissões reachable.ports.cap enviada pela operadora é aplicada como uma negação sempre antes de cada regra de usuário, de modo que mesmo defaultAction: allow não pode abrir uma porta não incluída na lista de permissões, e a rota de sandbox rápida rejeita ports com 400 até que o caminho nft do fastlet possa aplicá-los (fechado com falha, documentado) (#2212)
  • Isentar o alvo de redirecionamento MITM das regras com escopo de porta: com o piso da porta do operador e o MITM transparente ambos ativos, cada fluxo interceptado foi silenciosamente bloqueado - o iptables REDIRECT reescreveu dport 80/443 para o ouvinte local antes da cadeia de filtro ser executada, então a queda do complemento de piso julgou a porta reescrita; a tupla do ouvinte agora é aceita antes de cada regra com escopo de porta, não adicionando nenhuma nova acessibilidade, e uma porta interceptada não incluída na lista de permissões agora falha visivelmente no proxy em vez de passar silenciosamente (#2435)
  • Continuar a base experimental OSEP-0023 [EXPERIMENTAL] além da linha: admissão ao Vault vinculada a credenciais ao vivo com rotação por solicitação (#2176), revisões de política reconhecidas antes da publicação (#2182), admissão HTTP/2 com drenagem limitada (#2201), contenção de falha de tempo de execução em um inesperado Saída MITM (#2172), persistência de arquivo de política de revisão atômica (#2162), classificação de efeito de aplicação nft (#2167), seletores de passagem TLS estáticos com rejeição de inicialização para listas nativas conflitantes (#2229), contadores de admissão TLS (#2265), a base IPC de revisão de assunto somente para instalação (#2284) e transições de assunto convergentes do Fast Sandbox à frente dos consumidores do ciclo de vida v2 (#2294)
  • E os itens menores: envie egress-trace, um visualizador de admissão somente leitura dentro da imagem de saída (estado de política ao vivo, conjuntos NFT, concessões de DNS, veredictos por conexão e um subcomando probe; conteúdos descriptografados nunca são mostrados) (#2230); encaminhar consultas DNS sobre TCP quando o client usou TCP, então grandes respostas truncadas (SPF/DKIM TXT, respostas de muitos registros) finalmente chegam (#2358); preservar as regras DNS do gateway compartilhado quando o último assunto em um gateway de sandbox rápido for lançado, que anteriormente removeu toda a tabela NFT compartilhada (#2427); cortar fsyncs do bootstrap da política de tempo de criação e adicionar instrumentação de latência de criação por estágio - entrega realmente quente medida abaixo de 100 ms de ponta a ponta com política aplicada (#2327)

entrada

  • Implementar rastreamento de atividade OSEP-0024 e wake-on-access: com --activity-enabled, cada solicitação roteada registra um carimbo de data/hora de atividade monotônico para Redis — dispare e esqueça, nunca no caminho ativo; com --wake-enabled, uma solicitação roteada para uma sandbox rápida pausada é estacionada em vez de respondida 503: um ResumeSandbox por réplica por sandbox sob um voo único cercado por ponto de verificação, um estacionamento limitado e repetição de rota obsoleta restrita a métodos idempotentes com corpos reproduzíveis; a resposta wake-timeout carrega o marcador definido pelo OSEP (503 + Retry-After: 1 + OpenSandbox-Wake: expired), retirado de cada resposta upstream para que uma sandbox não possa forjar a proveniência; com ambos os sinalizadores não definidos, o comportamento é idêntico em bytes ao anterior (#2156 #2180)

  • Tornar a exclusão do sandbox confiável: a exclusão agora envia uma exclusão de Fastlet protegida antes de qualquer verificação de ausência de tempo de execução, portanto, uma falha de transporte ou uma resposta de inspeção vazia não é mais tratada como prova de que o sandbox desapareceu (o que poderia deixar o microVM órfão enquanto o CR desaparecia); o Fastlet registra uma marca de exclusão por identidade para que uma criação atrasada não possa reviver uma sandbox excluída. OpenSandbox release-1.2.0

Stable cut of the 1.2.0 line, carrying everything merged since release-1.1.1 through two release candidates plus a post-rc hardening delta. Images shipped with the rcs; SDK/CLI/server packages publish at 1.2.0. Everyone on 1.1.x should upgrade. Baseline for every section below: release-1.1.1.

Highlights

  • Auto-pause and wake-on-access for fast sandboxes (OSEP-0024) lands end to end: the ingress records activity and parks requests to paused sandboxes until the restore completes, the server runs an idle sweeper behind an opt-in lifecycle.idlePolicy create field, and all five SDKs get the wake-retry contract — off by default, additive only (#2156 #2180 #2192 #2198 #2218)
  • Credential Vault (OSEP-0022) lands end to end for fast sandboxes: the egress sidecar holds the vault with durable per-subject persistence and sealed pause/resume transfer, the server exposes the user-reachable vault API with credential values never appearing on any public read, and the MITM CA is pinned per pool so an egress restart no longer rotates the trust anchor under live sandboxes — plus port-scoped egress rules end to end in the classic profile (#2249 #2252 #2255 #2263 #2251 #2212)
  • Fast Sandbox snapshots and template builds can publish to and boot from OCI registries (OverlayBD OCI lifecycle), and a reliability campaign removes whole-call timeouts from SDK file transfers in all five languages, makes execd report sandbox-scoped CPU/memory and OOM kills, and fixes a long list of Docker-backend correctness and PTY/session output issues (#2338 #2165 #2200 #2191)

Server

  • Implement the server side of OSEP-0024 auto-pause for fast sandboxes: the lifecycle.idlePolicy create field (idleTimeoutSeconds 30–86400, onIdle: pause, wakeOnAccess, optional activeProbe) persists as a reserved Sandbox CR annotation; an idle sweeper enumerates opted-in fsb sandboxes, checks activity in Redis, takes a per-sandbox pause lock, and issues an idempotent FastPath PauseSandbox; a declared activeProbe runs through the ingress gateway, and an OpenSandbox-Skip-Activity sentinel suppresses one observation and is stripped on both gateway and proxy hops. Config moves under [automation.idle_pause], and redis.dsn is validated at load when the sweeper is enabled (#2192 #2181 #2215)
  • Implement the Credential Vault API (OSEP-0022, fast-sandbox profile): POST|GET|PATCH|DELETE /v1/sandboxes/{id}/credential-vault pushes complete vault revisions over the FastPath handler relay and treats the relay response as the synchronous egress-validated ack — the CRD never carries vault material and every public read is sanitized server-side; PATCH composes in memory with expectedRevision as the cross-replica backstop, non-fsb backends proxy the sidecar's /credential-vault surface, and the fsb credentialProxy create-time rejection is lifted (#2263)
  • Bake the pinned MITM CA into server-created SandboxTemplates (OSEP-0022): new [kubernetes] template_mitm_ca_secret config (default off) emits spec.egressMitmCertificate — the certificate entry only, never the private key — on every template; the Secret must exist in each template namespace (ops-runbook distribution), and a missed copy fails the build observably (#2288)
  • Add lifecycle.renewalPolicy (OSEP-0009): the renew-on-access opt-in moves from the opaque extensions["access.renew.extend.seconds"] key to a structured renewalPolicy.extendSeconds (300–86400); the legacy key is deprecated (supported throughout 1.x, removed in 2.0), and fast sandbox rejects it with 400 rather than silently accepting a no-op (#2296)

Go

  • Stop retrying non-idempotent writes by default: with retry enabled, 27 POST/PATCH call sites (sandbox/session/command/file/snapshot/vault mutations) could execute twice and still return success — POST/PATCH no longer retry status codes by default, retry only transport failures proven to be pre-send (dial/CONNECT/TLS before request bytes), and SSE bootstraps bypass the generic retry loop; callers who accept duplicate-execution risk can opt in via RetryConfig.RetryableStatusCodesNonIdempotent (#2342)
  • Retry the gateway's wake timeout when starting an SSE stream: the six streaming call sites (command/code/session runs, metrics watch) previously failed immediately with the marked 503; the bootstrap now parks within the same Retry-After budget and returns the typed wake-timeout error on exhaustion — established streams are never replayed, a bare 503 is still not retried even with write-status opt-in, and a 503 reached through a redirect chain loses wake provenance so an already-executed request is never resent; callers relying on fail-fast can pass WakeRetryDisabled() (#2426)

Execd

  • Report sandbox-scoped CPU/memory metrics and OOM kills: GET /metrics read the host's /proc inside the container, so dashboards showed host-wide numbers; usage now comes from the sandbox's own cgroup when limits are configured (host view kept for unlimited guests), and a cgroupfs poller diffs the kernel OOM kill counter every 5 s to export execd.system.oom.kills with structured warn logs — no capabilities required (#2200 #2191)

  • Behavior change: template reads (GET /templates, the create gate) report the database projection with freshness bounded by watch delivery (normally milliseconds) — a create racing a just-finished build can see a brief retryable 404 (#2326)
  • Behavior change: isolated-session files-API paths outside the session's mounts are rejected with an error instead of silently resolving into the workspace (#2322)
  • Behavior change (experimental egress live mode only): nonempty native ignore_hosts/allow_hosts now reject startup — migrate static TLS bypass entries to OPENSANDBOX_EGRESS_MITMPROXY_PASSTHROUGH_HOSTS (#2229)
  • Behavior change: execd upper-directory quota admission fails closed when upper_max_bytes > 0 and a usage scan fails (previously the quota check was silently bypassed) (#2257)
  • Deprecation: the extensions["access.renew.extend.seconds"] create key is deprecated in favor of lifecycle.renewalPolicy.extendSeconds — supported throughout 1.x, removed in 2.0; setting both is accepted only when values match (#2296)
  • Fast Sandbox: OverlayBD templates now require OCI storage, and snapshot spec.templateName is optional with status.manifestRef admitting oci:// — update consumers that assumed the name index or a required templateName (#2338)

Installation

# Platform (Kubernetes) — render the chart at this tag and apply
git clone https://github.com/opensandbox-group/OpenSandbox
cd OpenSandbox
git checkout release-1.2.0
helm dependency build manifests/charts/opensandbox  # package file:// sub-charts (not committed)
# Before first install, configure the server API key and enable the ingress
# gateway (required on Kubernetes; the bare render disables it, and the server
# refuses to start with an empty api_key) — see the deployment guide:
# https://open-sandbox.ai/deployment/
helm template ./manifests/charts/opensandbox | kubectl apply -f -
# or point your GitOps platform (Argo / Flux) at the repo path + tag

# SDKs
pip install opensandbox==1.2.0            # Python
npm install @alibaba-group/opensandbox@1.2.0   # JavaScript
# Kotlin/JVM: implementation("com.alibaba.opensandbox:sandbox:1.2.0")
dotnet add package Alibaba.OpenSandbox --version 1.2.0
go get github.com/alibaba/OpenSandbox/sdks/sandbox/go@v1.2.0

# Run the server locally
uvx opensandbox-server==1.2.0

Verify what you installed against the BOM: see Release Verification.
