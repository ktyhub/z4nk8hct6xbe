Versão OpenSandbox-1.2.0-rc.2

Segundo candidato a lançamento na linha 1.2.0, carregando tudo mesclado desde release-1.2.0-rc.1 - o título é o Credential Vault (OSEP-0022) pousando de ponta a ponta para sandboxes rápidos: um cofre mantido por saída com persistência durável por assunto e transferência de pausa/retomada, o cofre roteado pelo servidor acessível pelo usuário API e um MITM CA fixado em pool. A política de rede segue o mesmo padrão de saída mantida, e NetworkRule ganha regras com escopo de porta no perfil clássico – sandboxes rápidas as rejeitam quando fechadas com falha até que o caminho NFT do fastlet as aplique. As imagens são publicadas agora; Os pacotes SDK/CLI são enviados no nível estável 1.2.0. Por favor, teste e relate problemas.

Destaques

  • Cofre de credenciais (OSEP-0022) chega de ponta a ponta para sandboxes rápidos: o sidecar de saída mantém o cofre com arquivos duráveis por assunto, transferência de instantâneo selada para pausa/retomada e controle de assunto obsoleto na reutilização de slot (#2249 #2252 #2255 #2250); o servidor expõe o POST|GET|PATCH|DELETE /v1/sandboxes/{id}/credential-vault API acessível ao usuário sobre o relé do manipulador FastPath com valores de credencial nunca aparecendo em qualquer leitura pública (#2263), e o MITM CA é fixado por pool para que uma reinicialização de saída não gire mais a âncora trust em sandboxes ativas (#2251)
  • A política de rede espelha o cofre: a política de sandbox rápida registrada torna-se um estado de saída mantida com retransmissão CRUD, persistência durável e pausa/retomada de transferência de instantâneo (#2309), e NetworkRule ganha regras com escopo de porta de ponta a ponta no perfil clássico - especificação, sidecar nftables, validação de servidor e todos os cinco SDKs, enquanto sandboxes rápidos rejeitam ports fechado por falha por enquanto — além de um piso de porta TCP do lado do operador que nenhuma política de usuário pode abrir (#2212)
  • Atualização de ciclo de vida e diagnóstico: lifecycle.renewalPolicy substitui a chave opaca de renovação de extensões (OSEP-0009) (#2296); o contexto de diagnóstico API atinge o servidor, todos os cinco SDKs e o CLI (#2292); correções de execd tornam as falhas de inicialização distinguíveis, preservam a saída da sessão byte por byte e interrompem o crescimento silencioso do disco (#2303 #2318 #2295)

Servidor

  • Implementar o lado do servidor do Credential Vault (OSEP-0022, perfil fast-sandbox): o POST|GET|PATCH|DELETE /v1/sandboxes/{id}/credential-vault API acessível ao usuário envia revisões completas do vault sobre o relé do manipulador FastPath InvokeHandlerAction e trata a resposta do relé como o ack validado por saída síncrona - o CRD nunca carrega material do vault, e cada leitura pública é higienizada no lado do servidor; PATCH compõe na memória (delete → replace → add, cada nome sendo resolvido no máximo uma vez) com expectedRevision como backstop de réplica cruzada, back-ends não-fsb fazem proxy da superfície /credential-vault do sidecar e a rejeição de tempo de criação do fsb credentialProxy é suspensa (#2263)
  • Asse o MITM CA fixado em SandboxTemplates criados pelo servidor (OSEP-0022): a nova configuração [kubernetes] template_mitm_ca_secret / template_mitm_ca_secret_key (padrão desativado) emite spec.egressMitmCertificate — apenas a entrada do certificado, nunca a chave privada — em cada modelo criado pelo servidor; o segredo deve existir em cada namespace de modelo (distribuição de runbook de operações), e uma cópia perdida falha na construção de forma observável (#2288)
  • Adicionar lifecycle.renewalPolicy (OSEP-0009): a opção de renovação ao acessar passa da chave de criação extensions["access.renew.extend.seconds"] opaca para um renewalPolicy.extendSeconds estruturado (300–86400), espelhando o padrão idlePolicy; a chave herdada está obsoleta (suportada em 1.x, removida em 2.0), a configuração de ambas é aceita apenas quando os valores analisados ​​correspondem, o valor é normalizado no rótulo Docker / anotação Kubernetes existente para que os sandboxes de pré-atualização continuem renovando e o sandbox rápido o rejeite com 400 em vez de aceitar silenciosamente um não operacional (#2296)
  • Implementar o endpoint de contexto de diagnóstico (contrato OSEP de rc.1): GET /v1/sandboxes/{sandboxId}/diagnostics/context retorna o ID do sandbox, o estado do ciclo de vida, o tipo de back-end e os identificadores definidos pelo back-end para Docker, Kubernetes e Fast Sandbox sem se conectar ao execd — o contexto Kubernetes permanece disponível antes que um pod seja alocado, e os back-ends de extensão que não o implementam retornam 501 (#2292)
  • Encaminhe o caminho ainda codificado através do proxy sandbox: Starlette vinculou a rota {full_path:path} do caminho decodificado por porcentagem e o proxy colou esse valor de volta na URL upstream, então um ? decodificado iniciou uma consulta, # um fragmento, %2F tornou-se um separador, %25 e escapes não UTF-8 foram reescritos e os segmentos %2E%2E foram resolvidos - o proxy agora pega a cauda ainda codificada do client do caminho bruto (validando sua decodificação para o caminho roteado, com um fallback de recodificação) e lê a consulta da string de consulta bruta; back-ends recebem alvos de solicitação byte por byte, correspondendo ao gateway de entrada, e o escape de prefixo %2E%2E em endpoints mapeados por host Docker é fechado (#2228)
  • Relatar a expiração do BatchSandbox enquanto o pod ainda está em execução: um spec.expireTime anterior ainda era relatado como Running (pod pronto com IP), então o faturamento do relógio continuou crescendo após o tempo limite configurado; expiração agora verifica antes dos estados prontos e retorna Terminated / SANDBOX_EXPIRED com last_transition_at definido para o próprio expireTime (#2238)
  • Rejeitar instantâneos do gVisor que eliminariam gravações silenciosamente: docker commit no padrão --overlay2=root:self do gVisor pode reportar READY enquanto não restaura nenhuma gravação do sandbox (apenas a entrada opaca /.gvisor.filestore.* é visível); a simulação de instantâneo agora resolve o tempo de execução do contêiner e recusa o gVisor, a menos que os argumentos efetivos incluam --overlay2=none e a criação falha ao fechar quando a comparação do sistema de arquivos é somente armazenamento de arquivos (#2241)
  • Aplique perfis de segurança [docker] e secure_runtime ao contêiner de cache execd: ele ignorou apparmor_profile / seccomp_profile / docker_runtime, portanto, em um host cujo perfil seccomp padrão bloqueia a imagem execd, cada POST /sandboxes falhou 503 sem escape de configuração (#2254)
  • Tornar os patches de metadados Docker simultâneos seguros: a leitura-modificação-gravação da loja foi desbloqueada e cada gravação compartilhou um nome temporário, então duas solicitações PATCH /metadata simultâneas para uma sandbox chegaram a 500 (FileNotFoundError ao renomear) ou descartaram silenciosamente a chave do outro; um bloqueio em toda a loja mais nomes temporários por gravação serializam patches (a última gravação vence por chave), uma gravação com falha não deixa mais seu arquivo temporário para trás e o contrato de endpoint agora é documentado por tempo de execução - os patches Kubernetes escrevem de volta todo o rótulo definido como lido, os patches fsb enviam apenas suas próprias chaves protegidas por UID e geração (#2267 #2281)
  • Resolver endpoints de proxy fora do loop de eventos: manipuladores de proxy HTTP/WebSocket chamados de get_endpoint síncrono diretamente - uma chamada de soquete Docker por solicitação de proxy em Docker, uma leitura de apiserver em falhas de cache Kubernetes - bloqueando o loop para todas as outras solicitações e fluxos; um daemon Docker lento (por exemplo, durante uma extração de imagem) foi suficiente para congelar o servidor; a pesquisa agora é executada via asyncio.to_thread com contexto de locatário preservado (#2268)
  • Aplicar o resfriamento de renovação quando o consumidor Redis estiver habilitado: as renovações do proxy ignoraram totalmente o min_interval_seconds (cada solicitação em proxy executou uma renovação de get_sandbox + expiração) e as intenções de fila foram limitadas apenas por réplica de entrada, portanto, N réplicas foram renovadas até N vezes por intervalo; o tempo de espera agora se aplica a todas as fontes de renovação e começa somente após uma renovação bem-sucedida (#2276 #2279)

SDKs

As alterações de código abaixo acompanham a versão estável do 1.2.0 - o rc não envia pacotes SDK.

  • Adicione o contrato Credential Vault client a todos os cinco SDKs (OSEP-0022): sandboxes apoiados por modelo roteiam chamadas de vault através do servidor no mesmo sinal de origem de modelo que a política de rede (OPEN-SANDBOX-ORIGIN: template ou o sinalizador createFromTemplate local), enquanto os adaptadores diretos secundários permanecem intactos; O Sandbox.credential_vault do Python agora retorna o serviço de vault para ambos os perfis, e Go ganha métodos de vault no nível Sandbox ramificando no mesmo sinal (#2263)
  • Adicione lifecycle.renewalPolicy a todos os cinco SDKs (OSEP-0009): um campo de criação digitado com validação de falha rápida do lado client (extendSeconds 300–86400) conectado através dos conversores de criação, substituindo a chave de extensões opacas (#2296)
  • Implementar diagnósticos em toda a superfície SDK (com #2292): context é exposto através das fachadas de gerenciador e sandbox em todos os cinco idiomas, e JavaScript, Go e C# ganham logs/eventos públicos APIs correspondentes à superfície Python/JVM existente (fábricas personalizadas continuam funcionando - o novo serviço de diagnóstico é opcional)
  • Suporta regras de saída com escopo de porta em todos os cinco SDKs (#2212): NetworkRule.ports (TCP 1–65535, no máximo 256 por regra, target agora opcional) com validação do lado client espelhando o servidor (intervalo, duplicatas, limite, domínio + portas rejeitadas, máscara de rede-CIDR + portas rejeitadas); JavaScript codifica o invariante de destino ou portas como um tipo de união, Python normaliza um alvo de fio em branco na leitura ###Python
  • Pare de propagar uma busca de terminal cancelada para garçons: o cache de terminal de busca compartilhada define o CancelledError do chamador de busca no futuro compartilhado, para que garçons simultâneos - por exemplo, Irmãos TaskGroup - criaram CancelledError embora nada os tenha cancelado; os garçons agora resolvem novamente (endpoint em cache, busca em andamento mais recente ou seus próprios), enquanto o chamador cancelado ainda aumenta como antes (#2277)
  • Encaminhar credential_proxy por meio de pools de sandbox: PoolCreationSpec.credential_proxy foi descartado pelos caminhos de criação sincronizada e assíncrona, portanto, os sandboxes de aquecimento e criação direta perderam silenciosamente a configuração de proxy de credencial solicitada; fábricas personalizadas permanecem compatíveis (a palavra-chave é omitida quando não definida) (#2283)
  • Gere novamente o ciclo de vida client para descartar padrões obsoletos codificados (timeout_seconds: 2, wake_on_access: true → UNSET) deixados para trás pela mudança de especificação em #2212; o comportamento da conexão permanece inalterado — o servidor aplica os mesmos padrões (#2280)

Vá

  • Autentique solicitações de plano de dados com proxy com a chave API: o modo proxy enviou a chave API do locatário - uma credencial que pode criar, pausar e excluir cada sandbox do locatário - para a sandbox untrusted como X-EXECD-ACCESS-TOKEN (e como autenticação de saída) enquanto omite o cabeçalho OPEN-SANDBOX-API-KEY que o middleware do servidor lê, então as solicitações de proxy multilocatário falharam 401 e surgiram como tempos limite de prontidão; a chave do locatário agora passa pelo cabeçalho do servidor e nunca é contrabandeada para a sandbox ou sidecar de saída, as chaves proxy fornecidas pelo endpoint e pelo chamador vencem independentemente do case, e o modo direto permanece sem chave (#2274)

Controlador

  • Correção do executor de tarefa tratando um arquivo de saída vazio como código de saída 0: o shim cria o arquivo de saída antes de gravá-lo e Inspect ignorou o erro de análise - um shim eliminado no meio (ou uma falha na gravação, por exemplo, disco cheio) relatou uma tarefa com falha ou interrompida como Succeeded; um arquivo inválido ou vazio agora passa para a verificação pid (Running enquanto está vivo, ProcessCrashed uma vez desaparecido) (#2270)

Executado

  • Preservar os finais de linha de saída da sessão bash: os eventos stdout run_in_session descartaram bytes \n/\r, portanto as linhas em branco eram irrecuperáveis e a concatenação dos eventos de uma execução não reconstruía sua saída; o texto do evento agora carrega seu final de linha original (linhas em branco aparecem como eventos contendo apenas o final), alinhando o fluxo de sessão com o contrato /command de primeiro plano - os consumidores devem concatenar o texto do evento por execução em vez de tratar cada evento como uma linha sem nova linha (#2318)
  • Reportar exit_code sobre erros de comando: um comando que foi executado e saiu diferente de zero e um comando cujo processo nunca foi iniciado (por exemplo, fork/exec: argument list too long) relatou o mesmo evento de erro, então clients lendo o status de saída de evalue poderia relatar uma falha de inicialização como sucesso; o novo opcional error.exit_code está presente apenas quando o processo foi executado e finalizado diferente de zero (-1 na terminação do sinal) (#2303)
  • Servir pontos de montagem binds através dos arquivos de sessão isolados API: o roteador de visualização mesclada registrou apenas montagens de sobreposição, então session.files falhou com ErrPathOutsideOverlays nos mesmos destinos de ligação que session.run poderia ler; cada ligação agora registra uma visualização roteada (dest → source, vinculações somente leitura rejeitam gravações, vinculam visualizações sobreposições de sombra em vínculos de prefixo) (#2299)
  • Truncar arquivos de saída de comando antes de desvincular: filhos bifurcados (daemons) sobrevivem legitimamente aos comandos enquanto mantêm a saída fd, de modo que um arquivo desvinculado continua consumindo o disco como um crescimento (deleted) invisível até que o último detentor saia; cada ponto de exclusão existente agora é truncado para zero primeiro, e a saída em segundo plano só é tocada no momento da exclusão do zelador, para que a janela de retenção permaneça legível (#2295)
  • Omitir métricas inválidas de uso superior em erros de verificação: uma falha na verificação do sistema de arquivos emitiu um execd.isolation.upper.usage_bytes enganoso de 0 enquanto sessões e dados ainda existiam; leituras inválidas agora são omitidas (um superior vazio válido ainda informa 0) e a admissão de cota falha quando upper_max_bytes > 0 e uma varredura falham em vez de ignorar silenciosamente a contabilidade (#2257)
  • Evite importações redundantes de JDK MITM CA: sandboxes com vários JDKs instalados geralmente compartilham um armazenamento trust, mas cada JDK executou novamente a importação de keytool (~6.2 s para quatro JDKs); a inicialização agora é desduplicada pelo caminho de armazenamento trust resolvido com comparação de conteúdo de certificado, reduzindo o estágio para ~0.6 s enquanto ainda substitui certificados girados (#2310)
  • Sessões PTY padrão para TERM=xterm-256color quando o ambiente de usuário resolvido não possui TERM utilizável, então programas interativos ganham cores; um TERM explícito sempre vence (#2313)

Rede

saída

Os itens do cofre OSEP-0022 dizem respeito à superfície do cofre de credenciais do perfil fast-sandbox; os acompanhamentos do OSEP-0023 permanecem com escopo definido para o tempo de execução de revisão experimental padrão.

  • Adicione o cofre de saída para sandboxes rápidos (OSEP-0022), aterrissando em estágios: a superfície de retransmissão interna /vault/{sandboxUid} com POST somente de criação (409 em duplicado, atômico em réplicas de servidor), PUT de revisão completa com expectedRevision e uma pré-condição expectedIncarnation para que um gravador obsoleto nunca possa chegar ao sucessor de uma redefinição, valor incluindo GET e DELETE que mantém a política (#2249); persistência durável por assunto — um arquivo por assunto em um volume com escopo de pod (tmpfs opcional), o mesmo protocolo de commit dos arquivos de política, então acked significa durável e aplicado, recarga protegida por encarnação e eliminação ao desvincular (#2252); e a rota de cofre fastlet-proxy substituída removida com seu cache de push pendente (#2247)
  • Carregar o cofre durante a pausa/retomada (OSEP-0022 "Ciclo de vida do cofre"): VAULT_EXPORT copia o arquivo do cofre no pacote de instantâneos estritamente antes da desmontagem do tempo de execução e sela o assunto (todas as operações do cofre respondem 409 enquanto pausadas; a aplicação continua), e VAULT_IMPORT é a única transferência de encarnação autorizada - o pacote carimba novamente com a cerca restaurada antes de data-plane-ready, validado de acordo com a política atual antes de qualquer efeito durável; uma falha de exportação genuína deixa o assunto sem lacre e falha no ponto de verificação de pausa, de modo que a desmontagem nunca é executada sem um pacote e o cofre local de saída sobrevive para a nova tentativa (#2255); um sinal de capacidade vaultTransfer permite que uma saída sem persistência do cofre ignore totalmente a transferência - o ponto de verificação prossegue sem o cofre (semântica de pré-transferência) em vez de falhar (#2290)
  • Definir o controle de assunto obsoleto na reutilização de slot: a chave de despacho do fast-sandbox é o IP do slot e os slots são reutilizados, para que um SET_BINDING possa reivindicar uma chave ainda mantida por um sujeito morto, mas registrado - a saída agora trata isso como autoritativo, destruindo as regras NFT do sujeito obsoleto, refcount DNS, redirecionamento MITM e fatia de cofre sob o bloqueio de registro antes de registrar o sucessor deny-first; o tráfego nunca é despachado para regras obsoletas, descarregamentos tardios permanecem no-ops protegidos e cada caminho de falha deixa cada sujeito totalmente registrado ou totalmente despejado (#2250)
  • Fixe a CA MITM de sandbox rápida (OSEP-0022 "MITM Trust Anchor"): a CA versionada e fixada no pool é propagada a partir de uma montagem secreta somente leitura no confdir mitmdump (idempotente, fechado com falha em um par não carregável), substituindo a geração na inicialização - uma reinicialização de saída não gira mais a CA e invalida silenciosamente o TLS trust de cada sandbox ativa; uma CA ausente ou incompatível recusa apenas o complemento MITM (aplicação de política não afetada) com mitmCaFingerprint / mitmCaDown aparecendo em /healthz e o status das ações, portanto, um emparelhamento incorreto de segredo de template↔pool é visível rapidamente (#2251)
  • Alinhe a política de rede fast-sandbox com o padrão do vault: a política gravada torna-se um estado de saída mantida - uma superfície de retransmissão /policy/{sandboxUid} com pré-condições de revisão (assunto desconhecido 404, incompatibilidade de encarnação 412, selado 409), arquivos duráveis por assunto usando o mesmo protocolo de commit, transferência de snapshot POLICY_EXPORT/POLICY_IMPORT espelhando o vault e, após uma reinicialização de saída, o arquivo commitado substituindo o entrada de ligação no momento da criação reproduzida (#2309)
  • Suporte a regras de saída com escopo de porta de ponta a ponta (perfil clássico): NetworkRule.ports (TCP 1–65535, ≤256 por regra) torna target opcional — regras somente de porta ou portas combinadas com um IP/CIDR; domínio+ports é rejeitado porque as regras de domínio são avaliadas na camada proxy DNS; a precedência deny-before-allow se mantém em todo o escopo, e um bug de chave de mesclagem PATCH que permite que uma segunda regra somente de porta expulse a primeira foi corrigido; uma lista de permissões reachable.ports.cap enviada pela operadora é aplicada como uma negação sempre antes de cada regra de usuário, de modo que mesmo o defaultAction: allow não pode abrir uma porta que não esteja na lista de permissões; a rota fast-sandbox rejeita ports com 400 até que o caminho fastlet nft possa aplicá-los (fechamento com falha, documentado) (#2212)
  • Adicionar seletores de passagem TLS estáticos ao tempo de execução experimental de revisão ao vivo: OPENSANDBOX_EGRESS_MITMPROXY_PASSTHROUGH_HOSTS é uma matriz de host exata/curinga limitada aplicada em ClientHello com rejeição de sobreposição de 443; ignore_hosts/allow_hosts nativo não vazio existente agora rejeita a inicialização no modo ao vivo — migre entradas de desvio de TLS estáticas para a matriz (modo legado inalterado, nenhum interceptionMode público adicionado) (#2229)
  • Emite contadores de admissão TLS: um evento de melhor esforço por admissão final ClientHello alimenta egress.mitm.tls.connections_total com rótulos mode/decision/reason fechados — mede decisões de admissão, não apertos de mão ou solicitações, e explicitamente não é evidência de segurança (#2265)
  • Adicionar a base IPC de revisão de assunto somente para instalação (OSEP-0023 Fase 4): um canal de soquete Unix v2 autenticado roteia transações de revisão vinculadas ao destino para receptores de instalação independentes e com admissão desabilitada com bytes de solicitação congelados e reconciliação de resposta perdida; nenhum chamador de produção ainda (#2284)
  • Envie egress-trace, um visualizador de admissão somente leitura dentro da imagem de saída: estado da política ao vivo, conjuntos NFT e concessões de DNS com TTLs, conexões de saída reais anotadas com seu veredicto de admissão e um subcomando probe <domain> separando a negação da política da falha do resolvedor; nenhuma mudança de comportamento do sidecar e o conteúdo L7 descriptografado nunca é mostrado deliberadamente (#2230)

Diversos

  • Console: obtenha o terceiro de cinco PRs de console planejados - operações de administração e plataforma, com agregação /api/admin/sandboxes, proxy de detalhes por locatário, pools API (documentados como não isolados por locatário) e lista / pools / visão geral de sandbox global de administrador KPIs na interface da web (#2131); preservar respostas upstream vazias e bem-sucedidas no proxy BFF em vez de falhar na decodificação JSON em 200/201/205 (#2271)
  • CLI: adicione osb terminal <sandbox-id>, anexando o terminal local a um PTY real dentro da sandbox sobre o execd PTY WebSocket - modo bruto com redimensionamento orientado por SIGWINCH, repetição na reconexão, propagação de código de saída remota e suporte para modos de conexão direta e proxy de servidor (TTY interativo, POSIX) (#2313); relatar entradas de duração fora do intervalo como erros de validação Click em vez de OverflowError/ValueError não detectado (#2272)
  • OSEPs: OSEP-0022 revisado — o vault monta a ligação de ação como uma revisão selada AES-256-GCM em um canal de controle, com o CA fixado por pool como a âncora MITM trust (#2174); a solicitação planejada do driver de tempo de execução OpenSandbox é retirada (o driver firecracker é enviado como está; o tempo de negação primeiro substitui o teste healthz de pré-criação) (#2259); A distribuição de namespace MITM CA torna-se um pré-requisito de implantação de runbook de operações em vez de um controlador de sincronização residente (#2282)
  • Exemplos: adicione uma imagem Docker completa para o exemplo DeerFlow agrupando o servidor OpenSandbox (host Docker runtime) e o backend DeerFlow, para início de workshop de um comando sem um conjunto de ferramentas Python local (#2262)
  • Documentos: reflua a prosa de marcação compactada em parágrafos de linha única em 148 arquivos (cerca de 7,4 mil fragmentos recolhidos, renderização inalterada) e codifique a regra de estilo de prosa em AGENTS.md (#2285)
  • Testes/CI: cache de módulos Go para os cinco jobs e2e noturnos do Kubernetes (setup-go ignorou silenciosamente seu cache sem um go.sum raiz, baixando novamente o gráfico completo do módulo todas as noites) (#2306); feche o caminho feliz do cofre de credenciais na fumaça da sandbox rápida - retransmissão CRUD, injeção através do mitm real para cada tipo de autenticação, rotação, durabilidade de reinicialização e eliminação (#2256); despejar todos os logs do contêiner do pod fastlet (incluindo saída) na pausa/retomada, verificação de falha (#2290)
  • lançamento: versão da plataforma para 1.2.0-rc.2 em gráficos e referências de imagem

Atualização e compatibilidade

  • Quebra: o texto do evento stdout da sessão bash agora inclui seus finais de linha originais e linhas em branco aparecem como eventos — os consumidores devem concatenar o texto do evento por execução para recuperar a saída exata em vez de tratar cada evento como uma linha sem nova linha (#2318)
  • Mudança de comportamento: um BatchSandbox após seu spec.expireTime agora reporta Terminated / SANDBOX_EXPIRED em vez de Running, mesmo enquanto o pod ainda está pronto — os chamadores que tratam Running como vivo devem verificar a expiração (#2238)
  • Mudança de comportamento: instantâneos apoiados por Docker de contêineres gVisor sem --overlay2=none são rejeitados com SNAPSHOT::UNSUPPORTED_RUNTIME (409) em vez de publicar uma imagem silenciosamente incompleta (#2241)
  • Mudança de comportamento (somente modo ao vivo de saída experimental): ignore_hosts/allow_hosts nativos não vazios agora rejeitam a inicialização - migre entradas de desvio de TLS estáticas para OPENSANDBOX_EGRESS_MITMPROXY_PASSTHROUGH_HOSTS (#2229)
  • Descontinuação: a chave de criação extensions["access.renew.extend.seconds"] foi descontinuada em favor de lifecycle.renewalPolicy.extendSeconds — suportada em 1.x, removida em 2.0; definir ambos é aceito somente quando os valores correspondem (#2296)
  • Mudança de comportamento: a admissão de cota do diretório superior execd falha quando upper_max_bytes > 0 e uma verificação de uso falham (anteriormente, a verificação de cota era ignorada silenciosamente) (#2257)

OpenSandbox release-1.2.0-rc.2

Second release candidate on the 1.2.0 line, carrying everything merged since release-1.2.0-rc.1 — the headline is the Credential Vault (OSEP-0022) landing end to end for fast sandboxes: an egress-held vault with durable per-subject persistence and pause/resume transfer, the user-reachable server-routed vault API, and a pool-pinned MITM CA. Network policy follows the same egress-held pattern, and NetworkRule gains port-scoped rules in the classic profile — fast sandboxes reject them fail-closed until the fastlet nft path enforces them. Images publish now; SDK/CLI packages ship at the 1.2.0 stable bump. Please test and report issues.

Highlights

  • Credential Vault (OSEP-0022) lands end to end for fast sandboxes: the egress sidecar holds the vault with durable per-subject files, sealed snapshot transfer for pause/resume, and stale-subject takeover on slot reuse (#2249 #2252 #2255 #2250); the server exposes the user-reachable POST|GET|PATCH|DELETE /v1/sandboxes/{id}/credential-vault API over the FastPath handler relay with credential values never appearing on any public read (#2263), and the MITM CA is pinned per pool so an egress restart no longer rotates the trust anchor under live sandboxes (#2251)
  • Network policy mirrors the vault: the recorded fast-sandbox policy becomes egress-held state with relay CRUD, durable persistence, and pause/resume snapshot transfer (#2309), and NetworkRule gains port-scoped rules end to end in the classic profile — spec, sidecar nftables, server validation, and all five SDKs, while fast sandboxes reject ports fail-closed for now — plus an operator-side TCP port floor that no user policy can open (#2212)
  • Lifecycle and diagnostics polish: lifecycle.renewalPolicy replaces the opaque renew extensions key (OSEP-0009) (#2296); the diagnostics context API reaches server, all five SDKs, and the CLI (#2292); execd fixes make start failures distinguishable, preserve session output byte-for-byte, and stop silent disk growth (#2303 #2318 #2295)

Server

  • Implement the server side of the Credential Vault (OSEP-0022, fast-sandbox profile): the user-reachable POST|GET|PATCH|DELETE /v1/sandboxes/{id}/credential-vault API pushes complete vault revisions over the FastPath InvokeHandlerAction handler relay and treats the relay response as the synchronous egress-validated ack — the CRD never carries vault material, and every public read is sanitized server-side; PATCH composes in memory (delete → replace → add, each name resolving at most once) with expectedRevision as the cross-replica backstop, non-fsb backends proxy the sidecar's /credential-vault surface, and the fsb credentialProxy create-time rejection is lifted (#2263)
  • Bake the pinned MITM CA into server-created SandboxTemplates (OSEP-0022): new [kubernetes] template_mitm_ca_secret / template_mitm_ca_secret_key config (default off) emits spec.egressMitmCertificate — the certificate entry only, never the private key — on every server-created template; the Secret must exist in each template namespace (ops-runbook distribution), and a missed copy fails the build observably (#2288)
  • Add lifecycle.renewalPolicy (OSEP-0009): the renew-on-access opt-in moves from the opaque extensions["access.renew.extend.seconds"] create key to a structured renewalPolicy.extendSeconds (300–86400), mirroring the idlePolicy pattern; the legacy key is deprecated (supported throughout 1.x, removed in 2.0), setting both is accepted only when the parsed values match, the value normalizes into the existing Docker label / Kubernetes annotation so pre-upgrade sandboxes keep renewing, and fast sandbox rejects it with 400 rather than silently accepting a no-op (#2296)
  • Implement the diagnostics context endpoint (OSEP contract from rc.1): GET /v1/sandboxes/{sandboxId}/diagnostics/context returns the sandbox ID, lifecycle state, backend type, and backend-defined identifiers for Docker, Kubernetes, and Fast Sandbox without connecting to execd — Kubernetes context stays available before a Pod is allocated, and extension backends that don't implement it return 501 (#2292)
  • Forward the still-encoded path through the sandbox proxy: Starlette bound the {full_path:path} route from the percent-decoded path and the proxy pasted that value back into the upstream URL, so a decoded ? started a query, # a fragment, %2F became a separator, %25 and non-UTF-8 escapes were rewritten, and %2E%2E segments were resolved — the proxy now takes the client's still-encoded tail from the raw path (validating it decodes to the routed path, with a re-encode fallback) and reads the query from the raw query string; backends receive request targets byte-for-byte, matching the ingress gateway, and the %2E%2E prefix-escape on Docker host-mapped endpoints is closed (#2228)
  • Report BatchSandbox expiry while the pod is still Running: a past spec.expireTime was still reported as Running (Ready pod with IP), so wall-clock billing kept growing after the configured timeout; expiry now checks before the ready states and returns Terminated / SANDBOX_EXPIRED with last_transition_at set to the expireTime itself (#2238)
  • Reject gVisor snapshots that would silently drop writes: docker commit under gVisor's default --overlay2=root:self can report READY while restoring none of the sandbox's writes (only the opaque /.gvisor.filestore.* entry is visible); snapshot preflight now resolves the container's runtime and refuses gVisor unless the effective args include --overlay2=none, and create fails closed when the filesystem diff is filestore-only (#2241)
  • Apply [docker] security profiles and secure_runtime to the execd cache container: it ignored apparmor_profile / seccomp_profile / docker_runtime, so on a host whose default seccomp profile blocks the execd image, every POST /sandboxes failed 503 with no configuration escape (#2254)
  • Make concurrent Docker metadata patches safe: the store's read-modify-write was unlocked and every write shared one temporary name, so two concurrent PATCH /metadata requests for a sandbox raced into a 500 (FileNotFoundError on rename) or silently dropped the other's key; a store-wide lock plus per-write temp names serialize patches (last write wins per key), a failed write no longer leaves its temp file behind, and the endpoint contract is now documented per runtime — Kubernetes patches write back the whole label set it read, fsb patches send only their own keys fenced by UID and generation (#2267 #2281)
  • Resolve proxy endpoints off the event loop: HTTP/WebSocket proxy handlers called the synchronous get_endpoint directly — a Docker socket call per proxied request on Docker, an apiserver read on Kubernetes cache misses — blocking the loop for every other request and stream; a slow Docker daemon (e.g. during an image pull) was enough to freeze the server; the lookup now runs via asyncio.to_thread with tenant context preserved (#2268)
  • Apply the renew cooldown when the Redis consumer is enabled: proxy renews skipped min_interval_seconds entirely (every proxied request ran a get_sandbox + expiration renew) and queue intents were only throttled per ingress replica, so N replicas renewed up to N times per interval; the cooldown now applies to every renew source and starts only after a successful renew (#2276 #2279)

SDKs

Code changes below ride the 1.2.0 stable release — rc ships no SDK packages.

  • Add the Credential Vault client contract to all five SDKs (OSEP-0022): template-backed sandboxes route vault calls through the server on the same template-origin signal as network policy (OPEN-SANDBOX-ORIGIN: template or the local createFromTemplate flag), while sidecar-direct adapters stay untouched; Python's Sandbox.credential_vault now returns the vault service for both profiles, and Go gains Sandbox-level vault methods branching on the same signal (#2263)
  • Add lifecycle.renewalPolicy to all five SDKs (OSEP-0009): a typed create field with client-side fail-fast validation (extendSeconds 300–86400) wired through the create converters, replacing the opaque extensions key (#2296)
  • Implement diagnostics across the SDK surface (with #2292): context is exposed through both the manager and sandbox facades in all five languages, and JavaScript, Go, and C# gain public logs/events APIs matching the existing Python/JVM surface (custom factories keep working — the new diagnostics service is optional)
  • Support port-scoped egress rules in all five SDKs (#2212): NetworkRule.ports (TCP 1–65535, at most 256 per rule, target now optional) with client-side validation mirroring the server (range, duplicates, cap, domain+ports rejected, netmask-CIDR+ports rejected); JavaScript encodes the target-or-ports invariant as a union type, Python normalizes a blank wire target on read-back

Python

  • Stop propagating a cancelled endpoint fetch to waiters: the shared-fetch endpoint cache set the fetching caller's CancelledError on the shared future, so concurrent waiters — e.g. TaskGroup siblings — raised CancelledError though nothing cancelled them; waiters now re-resolve (cached endpoint, newer in-flight fetch, or their own), while the cancelled caller still raises as before (#2277)
  • Forward credential_proxy through sandbox pools: PoolCreationSpec.credential_proxy was dropped by both sync and async creation paths, so warmup and direct-create sandboxes silently lost the requested credential-proxy configuration; custom factories stay compatible (the keyword is omitted when unset) (#2283)
  • Regenerate the lifecycle client to drop stale hardcoded defaults (timeout_seconds: 2, wake_on_access: true → UNSET) left behind by the spec change in #2212; wire behavior is unchanged — the server applies the same defaults (#2280)

Go

  • Authenticate proxied data-plane requests with the API key: proxy mode sent the tenant API key — a credential that can create, pause, and delete every sandbox of the tenant — into the untrusted sandbox as X-EXECD-ACCESS-TOKEN (and as egress auth) while omitting the OPEN-SANDBOX-API-KEY header the server middleware reads, so multi-tenant proxy requests failed 401 and surfaced as readiness timeouts; the tenant key now rides the server header and is never smuggled into the sandbox or egress sidecar, endpoint-supplied and caller-supplied proxy keys win regardless of casing, and direct mode stays key-free (#2274)

Controller

  • Fix task-executor treating an empty exit file as exit code 0: the shim creates the exit file before writing it, and Inspect ignored the parse error — a shim killed in between (or a failed write, e.g. full disk) reported a failed or interrupted task as Succeeded; an invalid or empty file now falls through to the pid check (Running while alive, ProcessCrashed once gone) (#2270)

Execd

  • Preserve bash session output line endings: run_in_session stdout events dropped \n/\r bytes, so blank lines were unrecoverable and concatenating a run's events did not reconstruct its output; event text now carries its original line ending (blank lines surface as events containing only the ending), aligning the session stream with the foreground /command contract — consumers should concatenate event text per run instead of treating each event as a newline-free line (#2318)
  • Report exit_code on command errors: a command that ran and exited non-zero and a command whose process never started (e.g. fork/exec: argument list too long) reported the same error event, so clients reading the exit status from evalue could report a start failure as success; the new optional error.exit_code is present only when the process ran and finished non-zero (-1 on signal termination) (#2303)
  • Serve binds mount points through the isolated session files API: the merged-view router only registered overlay mounts, so session.files failed with ErrPathOutsideOverlays on the same bind destinations that session.run could read; each bind now registers a routed view (dest → source, read-only binds reject writes, bind views shadow overlays on prefix ties) (#2299)
  • Truncate command output files before unlink: forked children (daemons) legitimately outlive commands while holding the output fd, so an unlinked file kept consuming disk as invisible (deleted) growth until the last holder exited; every existing deletion point now truncates to zero first, and background output is only touched at janitor deletion time so the retention window stays readable (#2295)
  • Omit invalid upper-usage metrics on scan errors: a failed filesystem scan emitted a misleading execd.isolation.upper.usage_bytes of 0 while sessions and data still existed; invalid readings are now omitted (a valid empty upper still reports 0), and quota admission fails closed when upper_max_bytes > 0 and a scan fails instead of silently bypassing accounting (#2257)
  • Avoid redundant JDK MITM CA imports: sandboxes with several installed JDKs often share one trust store, but each JDK re-ran the keytool import (~6.2 s for four JDKs); initialization is now deduplicated by resolved trust-store path with certificate-content comparison, cutting the stage to ~0.6 s while still replacing rotated certificates (#2310)
  • Default PTY sessions to TERM=xterm-256color when the resolved user environment has no usable TERM, so interactive programs get colors; an explicit TERM always wins (#2313)

Networking

egress

The OSEP-0022 vault items concern the fast-sandbox profile's credential-vault surface; the OSEP-0023 follow-ups remain scoped to the default-off experimental revision runtime.

  • Add the egress-held vault for fast sandboxes (OSEP-0022), landing in stages: the internal /vault/{sandboxUid} relay surface with create-only POST (409 on duplicate, atomic across server replicas), full-revision PUT with expectedRevision and an expectedIncarnation precondition so a stale writer can never land on a reset's successor, value-including GET, and DELETE that keeps the policy (#2249); durable per-subject persistence — one file per subject under a Pod-scoped volume (optional tmpfs), the same commit protocol as policy files so acked means durable and applied, incarnation-fenced reload, and purge on unbind (#2252); and the superseded fastlet-proxy vault route removed with its pending-push cache (#2247)
  • Carry the vault across pause/resume (OSEP-0022 "Vault Lifecycle"): VAULT_EXPORT copies the vault file into the snapshot bundle strictly before runtime teardown and seals the subject (all vault ops answer 409 while paused; enforcement continues), and VAULT_IMPORT is the only authorized incarnation transfer — the bundle re-stamps with the restored fence before data-plane-ready, validated against the current policy before any durable effect; a genuine export failure leaves the subject unsealed and fails the pause checkpoint, so teardown never runs without a bundle and the egress-local vault survives for the retry (#2255); a vaultTransfer capability signal lets an egress without vault persistence skip the transfer entirely — the checkpoint proceeds without the vault (pre-transfer semantics) instead of failing (#2290)
  • Define stale-subject takeover on slot reuse: the fast-sandbox dispatch key is the slot IP and slots are reused, so a SET_BINDING can claim a key still held by a dead-but-registered subject — egress now treats that as authoritative, tearing down the stale subject's nft rules, DNS refcount, MITM redirect, and vault slice under the registry lock before registering the successor deny-first; traffic is never dispatched to stale rules, late unloads stay fence-guarded no-ops, and every failure path leaves each subject either fully registered or fully evicted (#2250)
  • Pin the fast-sandbox MITM CA (OSEP-0022 "MITM Trust Anchor"): the pool-pinned, versioned CA is seeded from a read-only secret mount into the mitmdump confdir (idempotent, fail-closed on an unloadable pair), replacing generate-on-start — an egress restart no longer rotates the CA and silently invalidates every live sandbox's TLS trust; a missing or mismatched CA refuses only the MITM addon (policy enforcement unaffected) with mitmCaFingerprint / mitmCaDown surfaced on /healthz and the actions status, so a template↔pool Secret mispairing is visible at a glance (#2251)
  • Align the fast-sandbox network policy with the vault pattern: the recorded policy becomes egress-held state — a /policy/{sandboxUid} relay surface with revision preconditions (unknown subject 404, incarnation mismatch 412, sealed 409), durable per-subject files using the same commit protocol, POLICY_EXPORT/POLICY_IMPORT snapshot transfer mirroring the vault, and, after an egress restart, the committed file superseding the replayed create-time binding input (#2309)
  • Support port-scoped egress rules end to end (classic profile): NetworkRule.ports (TCP 1–65535, ≤256 per rule) makes target optional — port-only rules, or ports combined with an IP/CIDR; domain+ports is rejected since domain rules evaluate at the DNS proxy layer; deny-before-allow precedence holds across scoping, and a PATCH merge-key bug that let a second port-only rule evict the first is fixed; an operator-shipped reachable.ports.cap whitelist is enforced as an always-deny ahead of every user rule so even defaultAction: allow cannot open a non-whitelisted port; the fast-sandbox route rejects ports with 400 until the fastlet nft path can enforce them (fail-closed, documented) (#2212)
  • Add static TLS passthrough selectors to the experimental live-revision runtime: OPENSANDBOX_EGRESS_MITMPROXY_PASSTHROUGH_HOSTS is a bounded exact/wildcard host array applied at ClientHello with 443-overlap rejection; existing nonempty native ignore_hosts/allow_hosts now reject startup in live mode — migrate static TLS bypass entries to the array (legacy mode unchanged, no public interceptionMode added) (#2229)
  • Emit TLS admission counters: one best-effort event per final ClientHello admission feeds egress.mitm.tls.connections_total with closed mode/decision/reason labels — it measures admission decisions, not handshakes or requests, and is explicitly not security evidence (#2265)
  • Add the installation-only subject revision IPC foundation (OSEP-0023 Phase 4): an authenticated v2 Unix-socket channel routes target-bound revision transactions to independent, admission-disabled installation receivers with frozen request bytes and lost-reply reconciliation; no production caller yet (#2284)
  • Ship egress-trace, a read-only admission viewer inside the egress image: live policy state, nft sets and DNS leases with TTLs, real outbound connections annotated with their admission verdict, and a probe <domain> subcommand separating policy denial from resolver failure; no sidecar behavior change, and decrypted L7 contents are deliberately never shown (#2230)

Misc

  • Console: land the third of five planned console PRs — admin and platform ops, with /api/admin/sandboxes aggregation, per-tenant detail proxying, a pools API (documented as not tenant-isolated), and admin global sandbox list / pools / overview KPIs in the web UI (#2131); preserve empty successful upstream responses in the BFF proxy instead of failing JSON decode on 200/201/205 (#2271)
  • CLI: add osb terminal <sandbox-id>, attaching the local terminal to a real PTY inside the sandbox over the execd PTY WebSocket — raw mode with SIGWINCH-driven resize, replay on reconnect, remote exit code propagation, and support for both direct and server-proxy connection modes (interactive TTY, POSIX) (#2313); report out-of-range duration inputs as Click validation errors instead of uncaught OverflowError/ValueError (#2272)
  • OSEPs: OSEP-0022 revised — the vault rides the action binding as an AES-256-GCM-sealed revision on one control channel, with the per-pool pinned CA as the MITM trust anchor (#2174); the planned OpenSandbox runtime driver ask is withdrawn (the firecracker driver ships as-is; deny-first timing replaces the pre-create healthz probe) (#2259); MITM CA namespace distribution becomes an ops-runbook deployment prerequisite instead of a resident sync controller (#2282)
  • Examples: add an all-in-one Docker image for the DeerFlow example bundling the OpenSandbox server (host Docker runtime) and the DeerFlow backend, for one-command workshop starts without a local Python toolchain (#2262)
  • Docs: reflow hard-wrapped markdown prose into single-line paragraphs across 148 files (~7.4k collapsed fragments, rendering unchanged) and codify the prose style rule in AGENTS.md (#2285)
  • Tests/CI: cache Go modules for the five Kubernetes nightly e2e jobs (setup-go silently skipped its cache without a root go.sum, re-downloading the full module graph nightly) (#2306); close the credential-vault happy path in the fast-sandbox smoke — relay CRUD, injection through the real mitm for every auth type, rotation, restart durability, and purge (#2256); dump every fastlet Pod container's logs (including egress) on pause/resume verify failure (#2290)
  • release: bump platform version to 1.2.0-rc.2 across charts and image references

Upgrade & Compatibility

  • Breaking: bash-session stdout event text now includes its original line endings, and blank lines appear as events — consumers must concatenate event text per run to recover exact output instead of treating each event as a newline-free line (#2318)
  • Behavior change: a BatchSandbox past its spec.expireTime now reports Terminated / SANDBOX_EXPIRED instead of Running, even while the pod is still Ready — callers that treat Running as alive should check expiry (#2238)
  • Behavior change: Docker-backed snapshots of gVisor containers without --overlay2=none are rejected with SNAPSHOT::UNSUPPORTED_RUNTIME (409) instead of publishing a silently incomplete image (#2241)
  • Behavior change (experimental egress live mode only): nonempty native ignore_hosts/allow_hosts now reject startup — migrate static TLS bypass entries to OPENSANDBOX_EGRESS_MITMPROXY_PASSTHROUGH_HOSTS (#2229)
  • Deprecation: the extensions["access.renew.extend.seconds"] create key is deprecated in favor of lifecycle.renewalPolicy.extendSeconds — supported throughout 1.x, removed in 2.0; setting both is accepted only when values match (#2296)
  • Behavior change: execd upper-directory quota admission fails closed when upper_max_bytes > 0 and a usage scan fails (previously the quota check was silently bypassed) (#2257)
