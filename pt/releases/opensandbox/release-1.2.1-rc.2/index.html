Versão OpenSandbox-1.2.1-rc.2

Segundo candidato a lançamento na linha de patch 1.2.1, trazendo tudo mesclado desde release-1.2.1-rc.1 (04/11/2026). O título é OSEP-0026 com excesso de assinaturas com reconhecimento de recursos de ponta a ponta: o servidor registra o formato efetivo da máquina de cada modelo, encaminha-o como limites por sandbox em pools ResourceAware e reproduz os limites registrados em restaurações de instantâneos, validados por uma via de verificação KVM dedicada. A rede Fast Sandbox atinge paridade nas regras de saída com escopo de porta, o tempo de execução experimental de revisão de assunto OSEP-0023 avança das bases da sessão para um portão de prontidão imposto, e o fast-sandbox fixado obtém instantâneos OCI somente rootfs opcionais. Um lote de segurança elimina bugs reais de perda de dados e disponibilidade: campos desconhecidos em objetos de solicitação fechados agora são rejeitados, uma reinicialização do controlador não pode mais despejar pods de sandboxes ativas e o caminho de dados com proxy do servidor entra no modo de manutenção. As imagens são publicadas agora; Os pacotes SDK/CLI são enviados no nível estável 1.2.1.

Destaques

  • O excesso de assinaturas com reconhecimento de recursos (OSEP-0026) chega de ponta a ponta: as formas da máquina de modelo são registradas no tempo de construção, encaminhadas como limites por sandbox quando o pool selecionado relata ResourceAware, o instantâneo restaura a reprodução dos limites registrados da fonte em vez de falhar, e um estágio verify-resourceaware CI afirma a cadeia até os valores do cgroup (#2602 #2623 #2628 #2633 #2637)
  • Paridade e proteção de saída rápida do Sandbox: as regras NetworkRule.ports com escopo de porta agora são aplicadas por assunto (a rejeição 400 foi suspensa) (#2662); As concessões de DNS são renovadas no kernel e sobrevivem à remoção do vizinho (#2652 #2653); o tempo de execução de revisão de assunto experimental OSEP-0023 atinge um portão de prontidão em instantâneos reconhecidos (#2666)
  • Segurança e ciclo de vida: objetos de solicitação fechados rejeitam campos desconhecidos com 422 em vez de ignorá-los silenciosamente (#2576); uma reinicialização do controlador não despeja mais pods alocados para sandboxes ativas (#2398); o caminho de dados do proxy do servidor foi descontinuado no modo de manutenção - roteia o tráfego da sandbox através do gateway de entrada (#2548)

Servidor

  • Sobrescrição com reconhecimento de recursos (OSEP-0026): o formato efetivo da máquina de cada modelo (CPU/memória pós-padrão) é registrado em spec_json.machine no momento da construção e projetado de forma idêntica no CRD (#2623); o modo de modelo cria o encaminhamento como resources.limits por sandbox quando - e somente quando - o pool selecionado relata ResourceAware, com LegacySlot/pools FastPath mais antigos falhando na segurança para omissão de campo e o modo de pool lê em cache TTL (#2628); a criação de snapshot registra os limites por sandbox da origem e as restaura, reproduzindo-os — anteriormente, um sandbox de modelo modelado restaurado em um pool ResourceAware voltava aos padrões do pool e o FastPath rejeitou a restauração completamente (#2633); Os stubs FastPath são regenerados com os campos proto com reconhecimento de recursos como base (#2619); o contrato está definido em OSEP-0026 (#2602)
  • O caminho de dados com proxy do servidor foi descontinuado no modo de manutenção: /sandboxes/{id}/proxy/{port}, o parâmetro use_server_proxy, as opções SDK correspondentes e os sinalizadores CLI/MCP agora carregam marcadores de descontinuação explícitos (cabeçalho de resposta Deprecation: true, avisos de tempo de execução por idioma), apenas com segurança e correções de bugs — as implantações devem expor o tráfego de sandbox através do gateway de entrada (#2548)
  • Campos desconhecidos em objetos de solicitação fechados são rejeitados com o envelope 422 higienizado em vez de serem descartados silenciosamente — readonly: true em um volume não permanece mais gravável silenciosamente e createIfNotExist: false não deixa mais a criação automática de volume habilitada; dez modelos (solicitações de imagem/auth/platform/volume/OSSFS/credential-proxy/snapshot-renew) agora usam extra = "forbid", e a propriedade token de autenticação TypeScript está obsoleta (#2576)
  • O informante Kubernetes rastreia gravações por objeto em vez de invalidar todo o cache: cada criação/patch/exclusão marcava previamente todo o cache da carga de trabalho como não sincronizado até uma relistagem completa (até 60 s), portanto, uma réplica com gravações constantes (renovações são suficientes) atendeu quase todas as leituras do servidor API e terminou em 429s; as leituras agora vão ao ar apenas para o objeto escrito até que o evento WATCH o confirme (#2599)
  • A sonda de atividade de pausa ociosa honra seu contrato de veredicto: ela nunca aumenta e cada falha apenas descarta o candidato atual — uma resposta 200 profundamente aninhada usada para escapar e pular o resto da varredura; as respostas agora devem ser descompactadas, caber em 4 KiB e chegar dentro de timeoutSeconds como um limite de troca inteira (#2596)

SDKs

As alterações de código abaixo acompanham a versão estável do 1.2.1 - o rc não envia pacotes SDK. ###Python

  • Inteiros Content-Range malformados ou fora do intervalo são tratados como metadados desconhecidos (limitados de 64 bits) e as respostas de streaming assíncrono são fechadas quando o mapeamento de metadados de resposta falha em downloads de sessão padrão e isolada — anteriormente, o fluxo subjacente poderia permanecer aberto (#2570)
  • O servidor Python MCP expõe o status do comando em segundo plano e logs incrementais: command_get_status (estado de execução, código de saída) e command_get_logs (conteúdo + cursor opaco), com orientação de pesquisa nas descrições da ferramenta (#2648) ###JavaScript
  • Tempo limite de comando positivo de submilissegundos arredondado para pelo menos 1 ms — Math.round serializou 0.0004 s como timeout: 0, o que desativa o limite de tempo de execução para comandos comuns e seleciona o padrão do servidor em sessões Bash (#2440)

Vá

  • O orçamento de ativação limita as novas tentativas em andamento: após uma ativação marcada 503, novas tentativas obtêm um prazo para o WakeOverallDeadline restante (somente cabeçalhos - fluxos SSE estabelecidos e corpos de download nunca são cortados) (#2572), e espera genérica ou esperas Retry-After que não cabem no orçamento restante são ignoradas para que uma nova tentativa de falha mista não durma mais após o prazo ou oculte o erro comum atrás de um marcador de ativação mais antigo (#2611)
  • Pool hardening: uma aquisição cancelada não consome mais uma entrada ociosa saudável ou aciona uma criação (#2616); o desligamento normal honra o cancelamento do chamador enquanto aguarda a drenagem de aquisições independentes (#2617); manutenção ociosa (redução, reaping quase expirado) continua durante a espera de criação em vez de ser ignorada durante todo o tick (#2565)
  • Uma resposta SSE começando com uma BOM UTF-8 não descarta mais o primeiro quadro de dados ou seu campo de evento/id — um quadro de inicialização de comando pode perder o ID de execução (#2618); um prazo de tempo limite de execução que expira dentro de uma solicitação de status agora retorna SandboxRunningTimeoutError independentemente do tempo, portanto a classificação errors.As é estável (#2668) Os READMEs SDK acompanham a superfície enviada: ciclo de vida idlePolicy + wake-retry, renewalPolicy e regras com escopo de porta documentadas em todos os cinco idiomas (#2590); trocar credenciais e fluxos de criação/pesquisa de modelo fsb documentados para JavaScript, Python, Go (#2597) e Kotlin (#2620); o exemplo de isolamento de rede usa importações reais e classe de regra (#2711)

Controlador

  • A remoção do pool após a reinicialização do controlador não exclui mais pods de sandboxes ativos: o armazenamento de alocação na memória só foi recuperado dentro do Schedule, mas a remoção foi executada primeiro em cada reconciliação do pool — na primeira reconciliação após uma reinicialização, todos os pods rotulados para remoção pareciam ociosos e foram excluídos, incluindo os alocados; a recuperação agora é executada antes de qualquer leitura de armazenamento (#2398)
  • A redução do poolMax agora dimensiona os pods de pool ociosos: anteriormente apenas limitava o crescimento, então os pods ociosos acima do novo limite funcionavam indefinidamente; apenas pods ociosos são excluídos e as exclusões já planejadas contam para o limite (#2470)
  • A expectativa de RV de status de um BatchSandbox excluído é eliminada, corrigindo o crescimento ilimitado do heap líder - a entrada para o último patch de status de cada BatchSandbox já reconciliado permaneceu durante a vida do processo (#2646)
  • O tempo de eleição do líder é configurável: --leader-elect-lease-duration, --leader-elect-renew-deadline e --leader-elect-retry-period (mais valores do gráfico), para que os operadores em planos de controle mais lentos possam impedir que um travamento do servidor API de 10 s force uma reeleição completa; os padrões permanecem inalterados (#2651)
  • Gráfico: o ConfigMap de sinalizadores de recursos do controlador é renderizado no namespace do controlador - ele foi para o namespace da versão do Helm, onde o controlador nunca o leu, então controller.podRecovery.* foi ignorado silenciosamente (#2694)

Executado

  • Os arquivos de sessão isolada API ocultam entradas excluídas por sobreposição: whiteouts de kernel (dispositivos 0/0), diretórios user.overlay.opaque e os próprios marcadores .wh. do API agora ocultam entradas inferiores em estatísticas/leitura/lista/pesquisa - depois de rm f && mkdir d, os f e d/x excluídos ainda eram legíveis com seus conteúdos antigos, e RemoveAll("d") saiu d/x listável até agora (#2469)
  • A cópia ao renomear e chmod é fiel à camada inferior: o modo (incluindo setuid/setgid/sticky) e a propriedade da sessão são preservados, os links simbólicos permanecem como links simbólicos, os diretórios somente inferiores podem ser renomeados e o rm f.txt && mv f.txt g.txt não ressuscita mais o arquivo excluído; chmod recusa links simbólicos em vez de segui-los até um caminho de host (#2638)
  • As corridas MITM CA trust contra reinicializações de saída são fechadas: inicializa apenas trusts uma CA que apareceu após uma ausência observada ou sobreviveu a uma janela de estabilização, e um observador vitalício reinstala o sistema/mesclado/NSS/JDK trust sempre que o conteúdo da CA exportado muda - anteriormente uma reinicialização do sidecar deixava a sandbox com a CA rotacionada em todos os lugares até a reconstrução (#2582)
  • Execuções isoladas em primeiro plano não gravam mais seu script no stdin do shell: o código que lê stdin (read, cat) consumiu o resto do script incluindo o marcador final, corrompendo o código de saída e sequestrando a sessão; o código agora é executado via eval com </dev/null, um erro de sintaxe encerra a execução com status 2 e a sessão sobrevive (#2517)
  • Correções menores: o pedaço de saída final do suporte PTY é liberado antes do quadro exit em vez de acelerá-lo (um filho de fundo segurando o tubo atrasa exit em no máximo 2 s) (#2644); As métricas do cgroup v1 e a observação do OOM respeitam a raiz de montagem do contêiner, portanto, Docker-on-cgroup-v1 relatou CPU/memória do host em vez dos limites do sandbox (#2641); downloads de diretório retornam 400 em vez de um 500/empty-200 dependente do sistema de arquivos, e um cabeçalho Range malformado 416 carrega uma mensagem (#2451); um glob /files/search inválido retorna 400 em vez de 500 (ou 200 em um diretório vazio) (#2687); created_at relata a hora de nascimento do inode via statx, então chmod/rename não o altera mais (#2604); A conclusão do Jupyter é derivada do resultado real do kernel (resposta + inatividade, erros IOPub retidos) em vez de acelerá-lo (#2606)

Rede

saída

  • As regras de saída com escopo de porta são aplicadas por assunto no sandbox rápido: o caminho nft por assunto obtido nas cadeias de permissão/descarte da porta TCP (MITM corresponde à porta original da conexão, não ao ouvinte do proxy), o servidor fsb passa ports e mescla por (target, ports), e a rejeição 400 no tempo de criação é suspensa - a semântica de negação antes de permitir e somente TCP corresponde ao perfil clássico, e domínio + portas permanecem rejeitados em ambos (#2662)
  • PATCH /policy no sidecar clássico não elimina mais regras intocadas: a chave de mesclagem compartilhada permite que um patch não relacionado remova um deny existente e abra tráfego bloqueado (fail-open); regras básicas de escopos ausentes do patch agora são mantidas, correspondendo ao contrato documentado (#2664)
  • As concessões de DNS de sandbox rápida são renovadas no kernel: a adição simples do elemento temporizado é bem-sucedida, mas deixa a expiração do kernel inalterada, portanto, novas conexões com um IP em cache foram descartadas assim que o primeiro tempo limite expirou; a renovação agora usa a sequência adicionar/excluir/re-adicionar (#2652), e reconstruir a tabela NFT compartilhada quando um assunto é removido adiciona novamente as concessões não expiradas dos assuntos restantes em vez de deixar os IPs em cache ociosos bloqueados (#2653)
  • O tempo de execução experimental de revisão de assunto OSEP-0023 avança [EXPERIMENTAL] (atrás de OPENSANDBOX_EGRESS_EXPERIMENTAL_REVISION_RUNTIME, admissão ainda desativada): sessões de assunto somente de instalação com IPC por criança autenticado e novas gerações de controle (#2589), um trabalhador de drenagem de ciclo de vida FIFO registrando SET/REMOVE/rebind/takeover intents (#2609), instantâneos de decisão por assunto instalados após a ligação e após cada mutação do Vault/política (#2634 #2649), e o gancho pronto para plano de dados agora bloqueia um instantâneo reconhecido para a cerca/geração/resumo atual - retornando 503 enquanto a autoridade ou o ACK está faltando (#2666); o contrato de integração de propriedade e revisão está fixado em OSEP-0022/0023 (#2586)
  • O tempo de execução experimental de revisão ao vivo do sidecar rejeita portas de interceptação extras na inicialização e falha ao fechar portas de destino TLS não canônicas (não 443), em vez de deixá-las alcançar o portão de autoridade HTTP posterior (#2587)

entrada

  • As leituras da política Wake reutilizam uma única configuração Kubernetes: servindo rotas regulares e de sandbox rápida com configuração REST analisada duas vezes habilitada para wake, e o segundo registro de sinalizador global entrou em pânico na inicialização com flag redefined: cluster (#2600)

Caixa de areia rápida

  • Pool quente ublk nativo em implantações OCI: OverlayBD agora começa com um pool de 4/8 de dispositivos de 2 GiB (runtime.oci.poolLow/poolHigh/poolSizeGB ajustável em gráfico, poolLow=0 desabilitado), então o modelo cria dispositivos pré-alocados de ocorrência em vez de alocar sob demanda; CI afirma acertos quentes sem erros ou reinicializações do daemon (#2594 fast-sandbox#163)
  • Opte por snapshots OCI somente rootfs (FSEP-0001) no caminho OverlayBD: a captura persiste apenas na camada rootfs gravável sem um despejo de memória e restaura as inicializações em vez de continuar no local — artefatos menores sem janela de teste do tamanho da memória e sem fixação de modelo de CPU, com o manifesto do artefato conduzindo a restauração; uma recuperação RootfsOnly com falha suspende a rota até que a recuperação seja bem-sucedida; capacidade de nível de tempo de execução, a fiação do snapshot API do OpenSandbox vem depois (#2706 fast-sandbox#173 fast-sandbox#167)
  • Proteção do ciclo de vida: os fastlets são isolados do pool de VMs OOM e retêm erros de drenagem, diagnósticos de recursos e identidades de tempo de execução com falha nas fases de preparação (#2626 fast-sandbox#162); a pausa imediata após a criação não acelera mais a projeção de status do controlador - uma pausa interrompida mantém sua intenção e uma retomada simultânea preserva a linhagem do ponto de verificação, portanto, nenhum atraso de liquidação do lado client é necessário (#2626 fast-sandbox#166)
  • Recuperação de instantâneos e reconciliadores: capturas em quarentena são reconciliadas e rotas inseguras retiradas, tempos de execução em quarentena retirados, caminhos vsock isolados, rotas suspensas restauradas e terminais Fastlet Pods são substituídos apenas em pools ativos; redefinir carimbos de data e hora de revisão preservar frações (#2706 fast-sandbox#172 fast-sandbox#170)
  • Gráficos: o controlador fast-sandbox e as cargas de trabalho do tempo de execução do firecracker aceitam podLabels/podAnnotations/nodeSelector/affinity, a malha DART P2P do tempo de execução pode ser desativada (runtime.p2p.enabled=false não renderiza nenhuma porta de serviço/peer headless e o agente extrai diretamente do armazenamento de origem), e o gráfico do controlador ganha controller.extraArgs para sinalizadores binários não modelados (#2566)
  • Integração ResourceAware: um dispositivo ResourceAware SandboxPool com seleção POOL_MODE=resource-aware (#2622), um estágio verify-resourceaware afirmando o encaminhamento de modelo moldado em níveis CR/cgroup/saturação (#2637), e a via de integração PR agora executa a pilha ResourceAware por padrão, enquanto todas as noites mantém a cobertura LegacySlot (#2647)
  • Correção menor: o gráfico de sandbox rápido ignora o segredo da chave de rota de desenvolvimento quando routeKeys.existingSecret está definido - as instalações de produção não renderizam mais a chave privada Ed25519 somente para desenvolvimento publicada (#2695)

Diversos

  • Console: um shell sandbox do navegador faz a ponte entre o xterm e o PTY do execd por meio de um WebSocket do BFF — entradas nas listas de inquilino e administrador, chaves de inquilino e tokens execd permanecem no BFF, uma página aberta é um PTY (#2233); uma conexão execd interrompida após a conexão relatar como um shell perdido em vez de um rastreamento de erro alegando que o shell falhou ao abrir (#2639); Os rótulos da IU são traduzidos para o inglês (#2657)
  • agente de nó: uma fonte vm-console opcional coleta a saída do console convidado do Fast Sandbox — descoberta de VM local do nó a partir de fast-sandbox.json gravado em driver sem relógios CR, fidelidade de bytes brutos por UID de sandbox em alterações de posicionamento e compensações reconhecidas seguras para reinicialização (#2234); o ambiente de integração o implanta e declara a coleta de ponta a ponta (#2676); a orientação de operações cobre alinhamento de caminho, cobertura de nós e regras de descoberta (#2677)
  • CLI: seções de configuração que não são de tabela são rejeitadas com um erro claro em vez de travar todos os comandos (#2551); As células da tabela None são renderizadas como - em vez do texto literal (#2691); um destino de regra de saída vazio é um erro de uso com a dica ACTION=TARGET (#2692)
  • Acompanhamento OSEP-0025: a autenticação do chamador do resolvedor é especificada - um JWT Ed25519 armazenado em cache em cada discagem de resolução TCP, verificado off-line em relação a um JWKS publicado no servidor, fechando a lacuna R4 adiada na camada de aplicativo (#2631)
  • Governança: regras de nomeação e remoção de mantenedores são mais rígidas — aprovação majoritária para mantenedores de componentes, suporte ao proprietário do caminho, LGTMs patrocinadores e um processo de emérito/remoção (#2678); @jianpingpei é nomeado mantenedor do agente do nó (#2679)
  • OSEPs e documentos: OSEP-0024/0026 e seis OSEPs anteriores são marcados como implementados, OSEP-0006 (console do desenvolvedor) é retirado (#2624 #2670 #2671 #2672 #2673); a página de índice OSEP foi removida do site de documentos - oseps/ em GitHub é o índice canônico (#2674)

Atualização e compatibilidade

  • Quebra: campos desconhecidos em objetos de solicitação fechados agora retornam 422 — chaves anteriormente ignoradas (por exemplo readonly em um volume) são rejeitadas; envie cada campo uma vez, alias ou snake_case, mas não ambos; no TypeScript SDK, ImageAuth.token combinado com username/password agora falha — envie apenas username e password (#2576)
  • Descontinuação: o caminho de dados com proxy do servidor (/sandboxes/{id}/proxy/{port}, use_server_proxy, as opções SDK/CLI/MCP) está em modo de manutenção — sem novos recursos, apenas segurança e correções de bugs; expor o tráfego da sandbox por meio do gateway de entrada (#2548)
  • Mudança de comportamento: o código em uma execução isolada em primeiro plano não pode mais ler o stdin da sessão (ele só obtinha o próprio script da execução dessa forma), e um erro de sintaxe agora termina a execução com status 2 enquanto a sessão sobrevive — anteriormente ele matava o shell (#2517)
  • Mudança de comportamento: downloads de um diretório retornam 400 INVALID_REQUEST_BODY em vez de um 500 dependente do sistema de arquivos ou um 200/206 vazio/incompleto; use a rota /directories/list; um intervalo 416 malformado ganha um campo message (#2451)
  • Mudança de comportamento: as respostas da sonda de atividade de pausa ociosa devem ser descompactadas, no máximo 4 KiB, e completadas dentro de timeoutSeconds como um limite de troca inteira - qualquer outra coisa é um veredicto de erro para esse candidato (#2596)
  • Mudança de comportamento: pools cuja contagem de pods ociosos excede um poolMax reduzido agora dimensionam o excesso (apenas pods ociosos são excluídos) (#2470)
  • Fast Sandbox: implantações habilitadas para OCI reservam um pool de dispositivos ublk ocioso por padrão — configure runtime.oci.poolLow=0 para manter o comportamento sob demanda anterior e combine poolSizeGB com a capacidade do modelo criado para tamanhos de disco personalizados (#2594)
  • Fast Sandbox: regras de saída com escopo de porta (NetworkRule.ports) agora são aceitas e aplicadas em rotas de fast-sandbox — anteriormente elas retornavam 400; as regras existentes não são afetadas (#2662)
  • Apenas tempo de execução de revisão ao vivo de saída experimental: portas de interceptação extras são rejeitadas na inicialização - remova OPENSANDBOX_EGRESS_MITMPROXY_EXTRA_PORTS ao ativar esse tempo de execução (#2587)
  • Somente tempo de execução experimental de revisão de sandbox rápido (OPENSANDBOX_EGRESS_EXPERIMENTAL_REVISION_RUNTIME=true): o gancho pronto para plano de dados pode retornar 503 até que o instantâneo do assunto seja reconhecido; cria, aguarde até fastpath_wait_ready_seconds (padrão 30 s) e retorne Pendente/Indisponível (#2666)
  • Imagens: opensandbox/<component>:release-1.2.1-rc.2 (todos os três registros; imagens fsb para sandbox rápido)
  • Pacotes: inalterados — artefatos SDK/CLI publicados na versão estável do 1.2.1
  • Gráficos: renderização a partir desta tag (helm template ./manifests/charts/opensandbox)
  • Kubernetes: faixa suportada v1.21 – v1.34

OpenSandbox release-1.2.1-rc.2

Second release candidate on the 1.2.1 patch line, carrying everything merged since release-1.2.1-rc.1 (2026-11-04). The headline is OSEP-0026 resource-aware oversubscription landing end to end: the server records each template's effective machine shape, forwards it as per-sandbox limits on ResourceAware pools, and replays recorded limits across snapshot restores, validated by a dedicated KVM verify lane. Fast Sandbox networking reaches parity on port-scoped egress rules, the experimental OSEP-0023 subject revision runtime advances from session foundations to an enforced readiness gate, and the pinned fast-sandbox gains opt-in rootfs-only OCI snapshots. A safety batch closes real data-loss and availability bugs: unknown fields in closed request objects are now rejected, a controller restart can no longer evict pods of live sandboxes, and the server-proxied data path enters maintenance mode. Images publish now; SDK/CLI packages ship at the 1.2.1 stable bump.

Highlights

  • Resource-aware oversubscription (OSEP-0026) lands end to end: template machine shapes are recorded at build time, forwarded as per-sandbox limits when the selected pool reports ResourceAware, snapshot restores replay the source's recorded limits instead of failing, and a verify-resourceaware CI stage asserts the chain down to cgroup values (#2602 #2623 #2628 #2633 #2637)
  • Fast Sandbox egress parity and hardening: port-scoped NetworkRule.ports rules are now enforced per subject (the 400 rejection is lifted) (#2662); DNS leases renew in the kernel and survive neighbour removal (#2652 #2653); the experimental OSEP-0023 subject revision runtime reaches a readiness gate on acknowledged snapshots (#2666)
  • Safety and lifecycle: closed request objects reject unknown fields with 422 instead of silently ignoring them (#2576); a controller restart no longer evicts pods allocated to live sandboxes (#2398); the server-proxy data path is deprecated into maintenance mode — route sandbox traffic through the ingress gateway (#2548)

Server

  • Resource-aware oversubscription (OSEP-0026): each template's effective machine shape (post-default CPU/memory) is recorded in spec_json.machine at build time and projected identically into the CRD (#2623); template-mode creates forward it as per-sandbox resources.limits when — and only when — the selected pool reports ResourceAware, with LegacySlot/older FastPath pools failing safe to field-omitted and the pool-mode read TTL-cached (#2628); snapshot creation records the source's per-sandbox limits and restores replay them — previously a shaped template sandbox restored on a ResourceAware pool fell back to pool defaults and FastPath rejected the restore outright (#2633); FastPath stubs are regenerated with the resource-aware proto fields as groundwork (#2619); the contract is defined in OSEP-0026 (#2602)
  • The server-proxied data path is deprecated into maintenance mode: /sandboxes/{id}/proxy/{port}, the use_server_proxy parameter, the matching SDK options, and the CLI/MCP flags now carry explicit deprecation markers (Deprecation: true response header, runtime warnings per language), with security and bug fixes only — deployments should expose sandbox traffic through the ingress gateway (#2548)
  • Unknown fields in closed request objects are rejected with the sanitized 422 envelope instead of being silently discarded — readonly: true on a volume no longer silently stays writable, and createIfNotExist: false no longer leaves automatic volume creation enabled; ten models (image/auth/platform/volume/OSSFS/credential-proxy/snapshot-renew requests) now use extra = "forbid", and the TypeScript auth token property is deprecated (#2576)
  • The Kubernetes informer tracks writes per object instead of invalidating the whole cache: every create/patch/delete previously marked the entire workload cache unsynced until a full relist (up to 60 s), so a replica with steady writes (renewals are enough) served almost every read from the API server and ended in 429s; reads now go live only for the written object until the WATCH event confirms it (#2599)
  • The idle-pause activity probe honors its verdict contract: it never raises and every failure only drops the current candidate — a deeply nested 200 answer used to escape and skip the rest of the sweep; answers must now be uncompressed, fit 4 KiB, and arrive within timeoutSeconds as a whole-exchange bound (#2596)

SDKs

Code changes below ride the 1.2.1 stable release — rc ships no SDK packages.

Python

  • Malformed or out-of-range Content-Range integers are treated as unknown metadata (64-bit bounded), and async streaming responses are closed when response-metadata mapping fails in standard and isolated-session downloads — previously the underlying stream could stay open (#2570)
  • The Python MCP server exposes background command status and incremental logs: command_get_status (running state, exit code) and command_get_logs (content + opaque cursor), with polling guidance in the tool descriptions (#2648)

JavaScript

  • Positive sub-millisecond command timeouts round up to at least 1 ms — Math.round serialized 0.0004 s as timeout: 0, which disables the runtime bound for ordinary commands and selects the server default in Bash sessions (#2440)

Go

  • The wake budget bounds in-flight retries: after a marked wake 503, further attempts get a deadline for the remaining WakeOverallDeadline (headers only — established SSE streams and download bodies are never cut off) (#2572), and generic backoff or Retry-After waits that cannot fit the remaining budget are skipped so a mixed-failure retry no longer sleeps past the deadline or hides the ordinary error behind an older wake marker (#2611)
  • Pool hardening: a cancelled acquire no longer consumes a healthy idle entry or triggers a creation (#2616); graceful shutdown honors caller cancellation while waiting for independent acquires to drain (#2617); idle maintenance (shrink, near-expiry reaping) continues during creation backoff instead of being skipped for the whole tick (#2565)
  • An SSE response starting with a UTF-8 BOM no longer drops the first data frame or its event/id field — a command init frame could lose the execution ID (#2618); a running-timeout deadline expiring inside a status request now returns SandboxRunningTimeoutError regardless of timing, so errors.As classification is stable (#2668)

SDK READMEs catch up with the shipped surface: lifecycle idlePolicy + wake-retry, renewalPolicy, and port-scoped rules documented in all five languages (#2590); exchange credentials and fsb template create/poll flows documented for JavaScript, Python, Go (#2597) and Kotlin (#2620); the network isolation example uses the real imports and rule class (#2711)

Controller

  • Pool eviction after a controller restart no longer deletes pods of live sandboxes: the in-memory allocation store was only recovered inside Schedule, but eviction ran first on every pool reconcile — on the first reconcile after a restart every pod labelled for eviction looked idle and was deleted, including allocated ones; recovery now runs before any store read (#2398)
  • Lowering poolMax now scales idle pool pods in: it previously only capped growth, so idle pods above the new bound ran indefinitely; only idle pods are deleted, and already-planned deletions count toward the bound (#2470)
  • A deleted BatchSandbox's status-RV expectation is dropped, fixing unbounded leader heap growth — the entry for the last status patch of every BatchSandbox ever reconciled stayed for the life of the process (#2646)
  • Leader election timing is configurable: --leader-elect-lease-duration, --leader-elect-renew-deadline, and --leader-elect-retry-period (plus chart values), so operators on slower control planes can stop a 10 s API-server stall from forcing a full re-election; defaults are unchanged (#2651)
  • Chart: the controller feature-flags ConfigMap is rendered into the controller's namespace — it went to the Helm release namespace, where the controller never read it, so controller.podRecovery.* was silently ignored (#2694)

Execd

  • The isolated-session files API hides overlay-deleted entries: kernel whiteouts (0/0 devices), user.overlay.opaque directories, and the API's own .wh. markers now hide lower entries in stat/read/list/search — after rm f && mkdir d the deleted f and d/x were still readable with their old contents, and RemoveAll("d") left d/x listable until now (#2469)
  • Copy-up on rename and chmod is faithful to the lower layer: mode (including setuid/setgid/sticky) and session ownership are preserved, symlinks stay symlinks, lower-only directories can be renamed, and rm f.txt && mv f.txt g.txt no longer resurrects the deleted file; chmod refuses symlinks instead of following them to a host path (#2638)
  • MITM CA trust races against egress restarts are closed: bootstrap only trusts a CA that appeared after an observed absence or survived a stabilization window, and a lifetime watcher reinstalls system/merged/NSS/JDK trust whenever the exported CA content changes — previously a sidecar restart left the sandbox with the rotated-out CA everywhere until rebuild (#2582)
  • Foreground isolated runs no longer write their script to the shell's stdin: code that reads stdin (read, cat) consumed the rest of the script including the end marker, corrupting the exit code and hijacking the session; code now runs via eval with </dev/null, a syntax error ends the run with status 2 and the session survives (#2517)
  • Smaller fixes: the PTY holder's final output chunk is flushed before the exit frame instead of racing it (a background child holding the pipe delays exit by at most 2 s) (#2644); cgroup v1 metrics and OOM watch honor the container's mount root, so Docker-on-cgroup-v1 reported host CPU/memory instead of the sandbox's limits (#2641); directory downloads return 400 instead of a filesystem-dependent 500/empty-200, and a malformed Range header's 416 carries a message (#2451); an invalid /files/search glob returns 400 instead of 500 (or 200 on an empty directory) (#2687); created_at reports the inode birth time via statx, so chmod/rename no longer change it (#2604); Jupyter completion is derived from the kernel's actual outcome (reply + idle, IOPub errors retained) instead of racing it (#2606)

Networking

egress

  • Port-scoped egress rules are enforced per subject in fast sandbox: the per-subject nft path gained TCP port allow/drop chains (MITM matches the connection's original port, not the proxy listener), the fsb server passes ports through and merges by (target, ports), and the create-time 400 rejection is lifted — deny-before-allow and TCP-only semantics match the classic profile, and domain+ports stays rejected in both (#2662)
  • PATCH /policy on the classic sidecar no longer drops untouched rules: the shared merge key let an unrelated patch remove an existing deny and open blocked traffic (fail-open); base rules of scopes absent from the patch are now kept, matching the documented contract (#2664)
  • Fast-sandbox DNS leases renew in the kernel: the plain timed-element add succeeds but leaves the kernel expiry unchanged, so new connections to a cached IP were dropped once the first timeout lapsed; renewal now uses the add/delete/re-add sequence (#2652), and rebuilding the shared nft table when one subject is removed re-adds the remaining subjects' unexpired leases instead of leaving idle cached IPs blocked (#2653)
  • The experimental OSEP-0023 subject revision runtime advances [EXPERIMENTAL] (behind OPENSANDBOX_EGRESS_EXPERIMENTAL_REVISION_RUNTIME, admission still disabled): installation-only subject sessions with authenticated per-child IPC and fresh control generations (#2589), a FIFO lifecycle drain worker recording SET/REMOVE/rebind/takeover intents (#2609), per-subject decision snapshots installed after binding and after every Vault/policy mutation (#2634 #2649), and the data-plane-ready hook now gates on an acknowledged snapshot for the current fence/generation/digest — returning 503 while authority or the ACK is missing (#2666); the ownership and revision integration contract is pinned in OSEP-0022/0023 (#2586)
  • The experimental sidecar live revision runtime rejects extra interception ports at startup and fails closed on non-canonical (non-443) TLS destination ports, instead of letting them reach the later HTTP authority gate (#2587)

ingress

  • Wake policy reads reuse a single Kubernetes config: serving regular and fast-sandbox routes with wake enabled parsed REST config twice, and the second global flag registration panicked at startup with flag redefined: cluster (#2600)

Fast Sandbox

  • Native ublk warm pool on OCI deployments: OverlayBD now starts with a 4/8 pool of 2 GiB devices (chart-tunable runtime.oci.poolLow/poolHigh/poolSizeGB, poolLow=0 disables), so template creates hit pre-allocated devices instead of allocating on demand; CI asserts warm hits with no misses or daemon restarts (#2594 fast-sandbox#163)
  • Opt-in rootfs-only OCI snapshots (FSEP-0001) on the OverlayBD path: capture persists only the writable rootfs layer without a memory dump, and restore boots instead of resuming in place — smaller artifacts with no memory-sized staging window and no CPU-model pinning, with the artifact manifest driving restore; a failed RootfsOnly recovery suspends the route until recovery succeeds; runtime-level capability, the OpenSandbox snapshot API wiring comes later (#2706 fast-sandbox#173 fast-sandbox#167)
  • Lifecycle hardening: Fastlets are isolated from VM-pool OOM and retain drain errors, resource diagnostics, and failed runtime identities across readiness phases (#2626 fast-sandbox#162); immediate pause after create no longer races the controller's status projection — an interrupted pause keeps its intent and a concurrent resume preserves checkpoint lineage, so no client-side settle delay is needed (#2626 fast-sandbox#166)
  • Snapshot and reconciler recovery: quarantined captures are reconciled and unsafe routes withdrawn, exited quarantined runtimes retired, vsock paths isolated, suspended routes restored, and terminal Fastlet Pods are replaced only in active pools; reset revision timestamps preserve fractions (#2706 fast-sandbox#172 fast-sandbox#170)
  • Charts: the fast-sandbox controller and firecracker-runtime workloads accept podLabels/podAnnotations/nodeSelector/affinity, the runtime's DART P2P mesh can be disabled (runtime.p2p.enabled=false renders no headless Service/peer port and the agent pulls directly from the origin store), and the controller chart gains controller.extraArgs for unmodeled binary flags (#2566)
  • ResourceAware integration: a ResourceAware SandboxPool fixture with POOL_MODE=resource-aware selection (#2622), a verify-resourceaware stage asserting shaped-template forwarding at CR/cgroup/saturation levels (#2637), and the PR integration lane now runs the ResourceAware stack by default while nightly keeps LegacySlot coverage (#2647)
  • Smaller fix: the fast-sandbox chart skips the dev route-key Secret when routeKeys.existingSecret is set — production installs no longer render the published development-only Ed25519 private key (#2695)

Misc

  • Console: a browser sandbox shell bridges xterm to execd's PTY over a BFF WebSocket — entries on the tenant and admin lists, tenant keys and execd tokens stay on the BFF, one page open is one PTY (#2233); a dropped execd connection after connect reports as a lost shell instead of an error traceback claiming the shell failed to open (#2639); UI labels are translated to English (#2657)
  • node-agent: an opt-in vm-console source collects Fast Sandbox guest console output — node-local VM discovery from driver-written fast-sandbox.json without CR watches, raw-byte fidelity per sandbox UID across placement changes, and restart-safe acknowledged offsets (#2234); the integration environment deploys it and asserts collection end to end (#2676); ops guidance covers path alignment, node coverage, and discovery rules (#2677)
  • CLI: non-table configuration sections are rejected with a clear error instead of crashing every command (#2551); None table cells render as - instead of the literal text (#2691); an empty egress rule target is a usage error with the ACTION=TARGET hint (#2692)
  • OSEP-0025 follow-up: resolver caller authentication is specified — a cached Ed25519 JWT on every TCP resolve dial, verified offline against a server-published JWKS, closing the deferred R4 gap at the application layer (#2631)
  • Governance: maintainer nomination and removal rules are tightened — majority approval for component maintainers, path-owner support, sponsor LGTMs, and an emeritus/removal process (#2678); @jianpingpei is nominated as node-agent maintainer (#2679)
  • OSEPs and docs: OSEP-0024/0026 and six earlier OSEPs are marked implemented, OSEP-0006 (developer console) is withdrawn (#2624 #2670 #2671 #2672 #2673); the OSEP index page is removed from the docs site — oseps/ on GitHub is the canonical index (#2674)

Upgrade & Compatibility

  • Breaking: unknown fields in closed request objects now return 422 — previously ignored keys (for example readonly on a volume) are rejected; send each field once, alias or snake_case but not both; in the TypeScript SDK, ImageAuth.token combined with username/password now fails — send only username and password (#2576)
  • Deprecation: the server-proxied data path (/sandboxes/{id}/proxy/{port}, use_server_proxy, the SDK/CLI/MCP options) is in maintenance mode — no new features, security and bug fixes only; expose sandbox traffic through the ingress gateway (#2548)
  • Behavior change: code in a foreground isolated run can no longer read the session's stdin (it only ever got the run's own script that way), and a syntax error now ends the run with status 2 while the session survives — previously it killed the shell (#2517)
  • Behavior change: downloads of a directory return 400 INVALID_REQUEST_BODY instead of a filesystem-dependent 500 or an empty/incomplete 200/206; use the /directories/list route; a malformed-range 416 gains a message field (#2451)
  • Behavior change: idle-pause activity probe answers must be uncompressed, at most 4 KiB, and complete within timeoutSeconds as a whole-exchange bound — anything else is an error verdict for that candidate (#2596)
  • Behavior change: pools whose idle pod count exceeds a lowered poolMax now scale the excess in (only idle pods are deleted) (#2470)
  • Fast Sandbox: OCI-enabled deployments reserve an idle ublk device pool by default — set runtime.oci.poolLow=0 to keep the previous on-demand behavior, and match poolSizeGB to the built template capacity for custom disk sizes (#2594)
  • Fast Sandbox: port-scoped egress rules (NetworkRule.ports) are now accepted and enforced on fast-sandbox routes — they previously returned 400; existing rules are unaffected (#2662)
  • Experimental egress live revision runtime only: extra interception ports are rejected at startup — remove OPENSANDBOX_EGRESS_MITMPROXY_EXTRA_PORTS when enabling that runtime (#2587)
  • Experimental fast-sandbox revision runtime only (OPENSANDBOX_EGRESS_EXPERIMENTAL_REVISION_RUNTIME=true): the data-plane-ready hook may return 503 until the subject snapshot is acknowledged; creates then wait up to fastpath_wait_ready_seconds (default 30 s) and return Pending/Unavailable (#2666)
  • Images: opensandbox/<component>:release-1.2.1-rc.2 (all three registries; fsb images for fast-sandbox)
  • Packages: unchanged — SDK/CLI artifacts publish at the 1.2.1 stable release
  • Charts: render from this tag (helm template ./manifests/charts/opensandbox)
  • Kubernetes: supported range v1.21 – v1.34
  • Skew: server ↔ CLI/SDK same line supported; ±1 minor warns
