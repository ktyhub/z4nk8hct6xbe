#homem das cavernas v4.0.0 Caveman 4.0.0 torna npx @caveman-ai/cli a única instalação, adiciona roteamento automático através do Caveman Cloud no proxy local e envia Caveman Blocks como um módulo.

Um comando para instalar

  • npx @caveman-ai/cli abre uma configuração de tela única. Ele encontra seus agentes de codificação e seus logins (cada perfil do Claude Code), mostra o que vai mudar, aplica-se no Enter e se oferece para iniciar o agente. Sem terminal aplica-se apenas com --yes.
  • install.sh e install.ps1 terminam na mesma configuração, fixados no CLI que esta versão envia.
  • caveman on|off alterna módulos de um registro. O índice do módulo (modules.json) está listado no manifesto de soma de verificação assinado da versão binária e o CLI recusa um índice que o manifesto não lista. Um arquivo de bloqueio de módulo registra o que está instalado.
  • Novos comandos: caveman stop, grade de status, caveman doctor offline, caveman providers add|remove|login|local e caveman providers cloud on|off.
  • Uma configuração inicial: ~/.caveman/cloud.json. A configuração mais antiga migra uma vez, sem corridas, e a desativação da telemetria é transferida.
  • O login usa o fluxo do dispositivo compartilhado. Ele recusa nuvens HTTP simples que não sejam esta máquina.

Roteamento automático (conectado ao Caveman Cloud)

  • caveman-auto aparece nos seletores de modelos Claude Code e OpenCode com uma janela de contexto de 1M. O roteamento se aplica apenas ao Auto e inclui logins Claude Pro/Max e logins ChatGPT (Codex, OpenCode).
  • Para cada solicitação roteável, o proxy solicita ao estágio de rota da nuvem um modelo e esforço (contratos route-ask-v1) e escolhe entre os provedores que você configurou. Se a chave for recusada ou um limite de faturamento for atingido, a solicitação passa sem roteamento e caveman status informa o motivo.
  • Os tradutores entre mensagens, conclusões de bate-papo e respostas cobrem todas as nove direções, para que o Claude Code possa ser executado em hosts de respostas, como o plano ChatGPT.
  • Um tempo de execução conectado envia lotes de eventos runtime/v1 para a nuvem e respeita a desativação da telemetria.

Cache

  • O proxy mantém o cache de prompt do Anthropic aquecido enquanto uma sessão é pausada. O tempo de aquecimento vem de tempos de retorno medidos, no máximo dois aquecimentos executados ao mesmo tempo, e caveman stats lista cada aquecimento.
  • Uma sessão permanece em seu modelo durante pausas na nuvem e falhas transitórias, para que uma troca de modelo não reescreva o prefixo armazenado em cache.

Blocos do Homem das Cavernas

  • A versão binária espelha caveman-ai/blocks v0.1.0-rc.4 (fixado pelo resumo de sua lista de checksum). Cada binário do Blocks é republicado sob o mesmo manifesto assinado dos outros binários. As contagens de uso de blocos se enquadram no mesmo aviso de telemetria e exclusão do Caveman.

Catálogo

  • Adiciona Soneto 5.5, Haiku 5.5, GPT-6.1 Sol e GPT-6 Luna.

Versões

  • @caveman-ai/cli vai de 2.1.0 a 4.0.0 para combinar com a versão do produto. Os binários passam de bin-v2.1.0 para bin-v4.0.0.
  • O instalador do npx github:JuliusBrussee/caveman depende do CLI ^4.0.0, então o -- --uninstall roda um CLI que entende o que o 4.0 escreveu.

Lançamentos complementares

  • Binários assinados, índice de módulo e contêiner: bin-v4.0.0
  • npm CLI: @caveman-ai/cli@4.0.0 Mudanças completas: https://github.com/JuliusBrussee/caveman/compare/v3.2.0...v4.0.0 Liberar fumaça: https://github.com/JuliusBrussee/caveman/actions/runs/38431102855

caveman v4.0.0

Highlights

  • One-command install and signed module registry — npx @caveman-ai/cli collapses the old installers into one discovery-driven setup: it finds your coding agents and every Claude Code login, previews the diff, and applies on Enter (--yes required when no TTY); install.sh/install.ps1 now just enter that same flow pinned to this release's CLI. caveman on|off toggles modules from a registry whose modules.json index is checked against the binary's signed checksum manifest (an unlisted index is refused) and tracked in a lockfile, so upgrades are reproducible rather than drifting. New caveman stop, a status grid, an offline caveman doctor, and caveman providers add|remove|login|local|cloud on|off turn previously opaque state into inspectable, controllable state.
  • Auto routing through Caveman Cloud — caveman-auto appears in the Claude Code and OpenCode pickers with a 1M context window and, for signed-in users, routes Auto requests (including Claude Pro/Max and ChatGPT/Codex logins) via Cloud's route-ask-v1 stage, choosing a model and effort from the providers you configured. The important behavior is graceful degradation: a refused key or a hit billing limit sends the request through unrouted and caveman status tells you why, so enabling Auto doesn't turn provider problems into hard failures. Signed-in runtimes send runtime/v1 event batches but honor the telemetry opt-out — worth confirming if you're privacy-sensitive.
  • Nine-direction protocol translation — translators now cover all conversions across Messages, Chat Completions, and Responses, which is what actually makes "run Claude Code on a Responses host such as the ChatGPT plan" work. This is the enabling layer behind the login-based Auto routing above, not a cosmetic picker entry; if you were previously blocked by protocol mismatch, that constraint is gone.
  • Prompt-cache-aware session pinning — the proxy keeps the Anthropic prompt cache warm across paused sessions using measured return times, caps concurrency at two warms, and lists each one in caveman stats. More importantly, a session stays on its model across Cloud pauses and transient failures, so a model switch no longer rewrites the cached prefix — expect fewer cache misses and lower latency/cost on interruption-heavy workflows.
  • Config consolidation and version alignment (migration notes) — all state moves to one home, ~/.caveman/cloud.json, via a one-time, race-free migration that carries the telemetry opt-out over. The CLI jumps 2.1.0 → 4.0.0 (matching the product) and binaries move bin-v2.1.0 → bin-v4.0.0; the npx github:JuliusBrussee/caveman installer now requires CLI ^4.0.0 specifically so -- --uninstall runs a CLI that understands what 4.0 wrote — update any pinned scripts or automation that still assume the 2.1 layout.
  • Caveman Blocks and catalog refresh — the binary release mirrors caveman-ai/blocks v0.1.0-rc.4, pinned by the digest of its checksum list and republished under the same signed manifest as the other binaries, with Blocks usage folded into the same telemetry notice and opt-out. The catalog adds Sonnet 5.5, Haiku 5.5, GPT-6.1 Sol, and GPT-6 Luna, so verify your provider allowlists/effort mappings pick up the new IDs.

No breaking changes.

Caveman 4.0.0 makes npx @caveman-ai/cli the one install, adds Auto routing through Caveman Cloud on top of the local proxy, and ships Caveman Blocks as a module.

One command to install

  • npx @caveman-ai/cli opens a one-screen setup. It finds your coding agents and their logins (every Claude Code profile), shows what it will change, applies on Enter, then offers to start the agent. Without a terminal it applies only with --yes.
  • install.sh and install.ps1 end in the same setup, pinned to the CLI this release ships.
  • caveman on|off switches modules from a registry. The module index (modules.json) is listed in the signed checksum manifest of the binary release, and the CLI refuses an index that manifest does not list. A module lockfile records what is installed.
  • New commands: caveman stop, a status grid, an offline caveman doctor, caveman providers add|remove|login|local and caveman providers cloud on|off.
  • One config home: ~/.caveman/cloud.json. Older config migrates once, without races, and the telemetry opt-out carries over.
  • Sign-in uses the shared device flow. It refuses plain-HTTP Clouds other than this machine.

Auto routing (signed in to Caveman Cloud)

  • caveman-auto shows up in the Claude Code and OpenCode model pickers with a 1M context window. Routing applies only to Auto, and that includes Claude Pro/Max logins and ChatGPT logins (Codex, OpenCode).
  • For each routable request the proxy asks Cloud's route stage for a model and effort (contracts route-ask-v1) and picks from the providers you set up. If the key is refused or a billing limit is hit, the request goes through unrouted and caveman status says why.
  • Translators between Messages, Chat Completions and Responses cover all nine directions, so Claude Code can run on Responses hosts such as the ChatGPT plan.
  • A signed-in runtime sends runtime/v1 event batches to Cloud and respects the telemetry opt-out.

Cache

  • The proxy keeps the Anthropic prompt cache warm while a session is paused. Warm timing comes from measured return times, at most two warms run at once, and caveman stats lists every warm.
  • A session stays on its model across Cloud pauses and transient failures, so a model switch doesn't rewrite the cached prefix.

Caveman Blocks

  • The binary release mirrors caveman-ai/blocks v0.1.0-rc.4 (pinned by the digest of its checksum list). Each Blocks binary is republished under the same signed manifest as the other binaries. Blocks usage counts fall under the same telemetry notice and opt-out as Caveman's.

Catalog

  • Adds Sonnet 5.5, Haiku 5.5, GPT-6.1 Sol and GPT-6 Luna.

Versions

  • @caveman-ai/cli goes from 2.1.0 to 4.0.0 to match the product version. Binaries move from bin-v2.1.0 to bin-v4.0.0.
  • The npx github:JuliusBrussee/caveman installer depends on CLI ^4.0.0, so -- --uninstall runs a CLI that understands what 4.0 wrote.

Companion releases

  • Signed binaries, module index and container: bin-v4.0.0
  • npm CLI: @caveman-ai/cli@4.0.0
