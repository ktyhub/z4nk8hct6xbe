#grafificar v0.9.105

grafificar 0.9.105

  • Correção: watch diretórios ignorados (node_modules, .git, saída de compilação) são removidos da árvore de observação do Linux, portanto, um grande projeto não registra mais dezenas de milhares de relógios inotify desperdiçados e arrisca ENOSPC; o observador recursivo não-Linux permanece inalterado e ainda é acionado a cada mudança real (#5074, #5091, obrigado @Deepjyoti-Sarmah).
  • Correção: cpp uma cadeia de chamada de membro roteada através de campos de classe declarados em outros cabeçalhos (client.actions->Execute(), com valor ., ponteiro bruto -> e receptores unique_ptr/shared_ptr de argumento único) resolve para o membro do tipo de campo em todo o conjunto de inclusão, bloqueado para um tipo e membro exclusivo e fechado com falha caso contrário; um local digitado cuja classe está em outro repositório é estacionado para a mesclagem entre repositórios (# 5098, obrigado @xRedLeader).
  • Correção: markdown um intervalo de código nomeando uma classe de namespace \ maiúscula (\Foo\Bar, App\API) ou uma chamada de método com qualificação de tipo (Type::member()) é mantida como uma menção de símbolo em vez de ser descartada, enquanto um Type::CONST/Type::class sem chamada permanece descartado (#5093, obrigado @Adityakk9031).
  • Correção: ts/js uma chamada através de um barril CommonJS desestruturado require (const { Thing } = require('./barrel') onde o barril reexporta Thing) resolve para a declaração real seguindo as exportações do barril, em vez de eliminar a borda (#5034, #5104, obrigado @qq2514568380).
  • Correção: wiki a varredura órfã dobra slugs com casefold (não lower), então dois nomes de artigos que colidem apenas sob dobragem completa de maiúsculas e minúsculas Unicode (Straße/STRASSE, Σ/ς) mantêm cada um seu próprio arquivo em vez de um ser excluído como órfão; um arquivo escrito nesta execução nunca é varrido (#5087, #5102, obrigado @nothariharan).
  • Correção: construir hiperarestas são mantidas inteiras em um graphify update incremental: elas são lidas no slot de gráfico aninhado que um gravador somente JSON usa e, após uma remoção da fonte excluída, uma hiperedge descarta apenas seus membros removidos (e a si mesmo somente quando nenhum permanece), em vez de perder silenciosamente ou deixar hiperarestas pendentes (#5081, #5103, obrigado @nothariharan).
  • Correção: cache uma entrada de cache semântica degradada (subprodução) não fixa mais o corpus: depois que o protetor de redução vê uma reextração voltar menor que o gráfico armazenado, a entrada é carimbada como partial para que a próxima execução a reenvie em vez de reproduzir o resultado degradado para sempre (#5083, #5101, obrigado @nothariharan).
  • Correção: afetado graphify affected <file> semeia os nós de membros aninhados do arquivo (um método dentro de uma classe) transitivamente, não apenas um salto, então a análise de impacto não sub-relata mais os chamadores que se ligam a um membro aninhado (#5094, obrigado @ Adityakk9031).
  • Correção: árvore build_tree deriva a raiz do diretório comum dos pais do arquivo, portanto, uma árvore de arquivo único ou de diretório único não é mais aninhada automaticamente no próprio arquivo (# 5092, obrigado @ Adityakk9031).
  • Correção: consulta um rótulo cujo nome está atrás de um esquema ou qualificador de namespace (public.sweep_widget_state(), fmt.Println) é correspondido em sua cauda por toda a consulta e classificado acima das camadas por token, portanto, não é mais superado por nós de colisão de token único e eliminado das sementes (#5080, #5095, obrigado @sunhouy).
  • Correção: detectar uma verificação de inatividade incremental faz hash de um arquivo cujo carimbo cai dentro da janela de inclinação do relógio em ambos os lados de seu mtime, portanto, uma reescrita do mesmo tique que não se move mtime ainda é capturada em vez de ser servida obsoleta (#5090, obrigado @sunhouy).
  • Correção: caminho graphify path A B recusa um endpoint cujas palavras não aparecem em nenhum lugar do gráfico (saída não encontrada) em vez de retornar uma rota enganosa construída a partir de tokens vagamente sobrepostos (#5085, obrigado @sunhouy).
  • Correção: csharp uma chamada de método de extensão clássica (x.Foo() onde Foo é declarado static ... Foo(this X x, ...)) se vincula à declaração do método de extensão por meio de uma passagem aditiva que é executada após o despacho nominal, restrita a um namespace visível, um tipo this correspondente e um método aplicável exclusivo; um método de instância com o mesmo nome vence, uma extensão estática sem extensão ou não importada não obtém vantagem e a ambiguidade falha no fechamento (#4828, #4849, obrigado @Deepjyoti-Sarmah).
  • Correção: markdown uma menção de função livre simples e não qualificada em prosa (token, sem () e sem namespace) se liga a uma função de mesmo nome somente quando seu arquivo de definição (ou outro símbolo dele) é citado dentro da cadeia de seção do título, em vez de corresponder a qualquer chamada de mesmo nome no corpus; links de estilo de referência ([text][label]) são resolvidos no site de uso (#4804, #4806, obrigado @madanlalit).
  • Correção: exportar a proteção contra redução to_json não conta mais fontes semânticas que foram substituídas na reextração ou removidas como exclusões como "perdidas", portanto, um graphify update legítimo não é recusado; um psiquiatra genuíno e inexplicável ainda é recusado (#5107, obrigado @khkar).
  • Correção: construir um nó cujo file_type ou confidence chega como um valor estruturado (lista/dict) de uma passagem LLM flutuante não trava mais as verificações de associação de validação/construção: a validação o revela como um erro de esquema e a construção o dobra para concept/INFERRED sem fabricar uma pontuação (#5088, obrigado @sdivyanshu90).
  • Correção: llm um documento divisível abaixo do limite de caracteres cuja saída do modelo trunca é promovido para uma fatia de intervalo completo e dividido ao meio (e repetido) em vez de ser mantido como um resultado parcial truncado; uma unidade não divisível ou de código/binária ainda falha no fechamento (#5072, #5078, obrigado @aadilrizwan).
  • Proeza: llm extra_headers de um provedor compatível com OpenAI personalizado são encaminhados para o client como default_headers, com escopo definido para esse provedor e com qualquer cabeçalho Authorization descartado para que não possa substituir a credencial configurada (#3680, #4783, obrigado @jaimemartinez).
  • Perf: extrair intermediários de gráfico inteiro (o memorando de análise no CLI único, listas de trabalho de construção/cluster/exportação) são liberados assim que são consumidos, reduzindo o pico de memória em um corpus grande; a saída do gráfico é idêntica em bytes (# 5063, obrigado @TPAteeq).
  • Correção: skillgen o prompt do subagente Claw/kiro/pi agora diz ao trabalhador para gravar seu pedaço em CHUNK_PATH, então um pedaço de despacho de disco não é mais retornado inline e perdido na etapa de mesclagem (#5040, obrigado @connhodendatabase).
  • Correção: deps o piso do pypdf foi aumentado para 6.21.4 nos extras pdf e all para obter suas correções de segurança (#5015, obrigado @yotamleo). O esquema de cache AST aumentou para 42; caches quentes executam novamente as extrações afetadas de C++, Markdown e C#.

graphify v0.9.105

graphify 0.9.105

  • Fix: watch ignored directories (node_modules, .git, build output) are pruned from the Linux watch tree, so a large project no longer registers tens of thousands of wasted inotify watches and risks ENOSPC; the non-Linux recursive watcher is unchanged and still fires on every real change (#5074, #5091, thanks @Deepjyoti-Sarmah).

  • Fix: cpp a member-call chain routed through class fields declared in other headers (client.actions->Execute(), with value ., raw-pointer -> and single-arg unique_ptr/shared_ptr receivers) resolves to the field type's member across the include set, gated to a unique type and member and fail-closed otherwise; a typed local whose class is in another repo is parked for the cross-repo merge (#5098, thanks @xRedLeader).

  • Fix: markdown a code span naming an uppercase \-namespace class (\Foo\Bar, App\API) or a type-qualified method call (Type::member()) is kept as a symbol mention instead of being dropped, while a non-call Type::CONST/Type::class stays dropped (#5093, thanks @Adityakk9031).

  • Fix: ts/js a call through a destructured CommonJS barrel require (const { Thing } = require('./barrel') where the barrel re-exports Thing) resolves to the real declaration by following the barrel's exports, instead of dropping the edge (#5034, #5104, thanks @qq2514568380).

  • Fix: wiki the orphan sweep folds slugs with casefold (not lower), so two article names that collide only under full Unicode case-folding (Straße/STRASSE, Σ/ς) each keep their own file instead of one being deleted as an orphan; a file written this run is never swept (#5087, #5102, thanks @nothariharan).

  • Fix: build hyperedges are kept whole across an incremental graphify update: they are read from the nested graph slot a JSON-only writer uses, and after a deleted-source prune a hyperedge drops only its removed members (and itself only when none remain), instead of silently losing or leaving dangling hyperedges (#5081, #5103, thanks @nothariharan).

  • Fix: cache a degraded (under-producing) semantic cache entry no longer pins the corpus: after the shrink guard sees a re-extraction come back smaller than the stored graph, the entry is stamped partial so the next run re-dispatches it instead of replaying the degraded result forever (#5083, #5101, thanks @nothariharan).

  • Fix: affected graphify affected <file> seeds the file's nested member nodes (a method inside a class) transitively, not just one hop, so impact analysis no longer under-reports callers that bind to a nested member (#5094, thanks @Adityakk9031).

  • Fix: tree build_tree derives the common directory root from file parents, so a single-file or single-directory tree is no longer self-nested under the file itself (#5092, thanks @Adityakk9031).

  • Fix: query a label whose name is behind a schema or namespace qualifier (public.sweep_widget_state(), fmt.Println) is matched on its tail by the whole query and ranked above the per-token tiers, so it is no longer out-competed by single-token collision nodes and dropped from the seeds (#5080, #5095, thanks @sunhouy).

  • Fix: detect an incremental staleness check hashes a file whose stamp lands within the clock-skew window on either side of its mtime, so a same-tick rewrite that does not move mtime is still caught instead of being served stale (#5090, thanks @sunhouy).

  • Fix: path graphify path A B refuses an endpoint whose words appear nowhere in the graph (exit not-found) instead of returning a misleading route built from loosely-overlapping tokens (#5085, thanks @sunhouy).

  • Fix: csharp a classic extension-method call (x.Foo() where Foo is declared static ... Foo(this X x, ...)) binds to the extension method's declaration through an additive pass that runs after nominal dispatch, gated to a visible namespace, a matching this type and a unique applicable method; an instance method of the same name wins, a non-extension static or an unimported extension gets no edge, and ambiguity fails closed (#4828, #4849, thanks @Deepjyoti-Sarmah).

  • Fix: markdown a bare, unqualified free-function mention in prose (token, no () and no namespace) binds to a same-named function only when its defining file (or another symbol from it) is cited within the heading's section chain, instead of matching any same-named callable in the corpus; reference-style links ([text][label]) resolve at the use site (#4804, #4806, thanks @madanlalit).

  • Fix: export the to_json shrink guard no longer counts semantic sources that were replaced on re-extract or pruned as deletions as "lost", so a legitimate graphify update is not refused; a genuine unexplained shrink is still refused (#5107, thanks @khkar).

  • Fix: build a node whose file_type or confidence arrives as a structured value (list/dict) from a drifting LLM pass no longer crashes the validate/build membership checks: validation surfaces it as a schema error, and the build folds it to concept/INFERRED without fabricating a score (#5088, thanks @sdivyanshu90).

  • Fix: llm a splittable document below the character cap whose model output truncates is promoted to a full-range slice and bisected (and retried) instead of being kept as a truncated partial result; a non-splittable or code/binary unit still fails closed (#5072, #5078, thanks @aadilrizwan).

  • Feat: llm a custom OpenAI-compatible provider's extra_headers are forwarded to the client as default_headers, scoped to that provider and with any Authorization header dropped so it cannot override the configured credential (#3680, #4783, thanks @jaimemartinez).

  • Perf: extract whole-graph intermediates (the parse memo on the one-shot CLI, build/cluster/export working lists) are freed as soon as they are consumed, cutting peak memory on a large corpus; graph output is byte-identical (#5063, thanks @TPAteeq).

  • Fix: skillgen the claw/kiro/pi subagent prompt now tells the worker to write its chunk to CHUNK_PATH, so a disk-dispatch chunk is no longer returned inline and lost at the merge step (#5040, thanks @connhodendatabase).

  • Fix: deps the pypdf floor is raised to 6.21.4 in the pdf and all extras to pick up its security fixes (#5015, thanks @yotamleo).

The AST cache schema is bumped to 42; warm caches re-run the affected C++, Markdown and C# extractions.
