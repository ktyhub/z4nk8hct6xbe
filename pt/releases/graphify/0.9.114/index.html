#grafificar v0.9.114 Trabalho de desempenho no pipeline de extração/compilação/atualização, além de um lote de correções de extração e compilação. Cada entrada marcada como Perf preserva exatamente a saída do gráfico (byte idêntico); o extrator corrige a saída alterada e compartilha um aumento no esquema de cache AST (veja a nota no final).

  • Perf: ids normalize_id obtém um atalho ASCII, expressões regulares pré-compiladas e um cache LRU, portanto, o caso do identificador comum (ASCII, repetido) ignora o loop de normalização Unicode. ~1,26x no caminho de computação e uma grande vitória em ids repetidos, que são muito recorrentes em um corpus.
  • Perf: cache save_cached constrói a cópia na gravação da carga útil portátil no disco em vez de copy.deepcopy fazer cada resultado por arquivo; Cerca de 20% mais rápido na transformação de gravação em cache, dimensionando com tamanho de gráfico por arquivo. A entrada nunca sofre mutação e os bytes no disco são idênticos.
  • Perf: extract cada arquivo de origem é lido do disco uma vez (o hash da chave e a análise compartilham um buffer) em vez de duas vezes em uma compilação fria, e o tree-sitter Parser é reutilizado por idioma dentro de um trabalhador em vez de reconstruído por arquivo (a leitura do arquivo é aproximadamente reduzida pela metade no caminho do trabalhador).
  • Perf: extract a finalização da resolução de arquivos cruzados constrói seus índices de nó/borda compartilhados em algumas passagens fundidas em vez de ~6 varreduras completas independentes do gráfico; ~15% mais rápido na fase de finalização.
  • Perf: watch a comparação de topologia sem alteração usa um hash de conteúdo independente de ordem calculado em uma passagem em vez de classificar e serializar novamente o gráfico inteiro; ~ 1,4x nessa comparação.
  • Perf: cluster a partição da comunidade é armazenada em cache por um hash de topologia e reutilizada quando o gráfico permanece inalterado (~9x em um acerto de cache do cluster) e a chave determinística de classificação de borda elimina um json.dumps por borda em favor de uma chave de tupla barata (ordenação idêntica).
  • Perf: analisar A centralidade de intermediação do suggest_questions agora executa uma implementação de Brandes de matriz plana em vez da implementação baseada em dict do networkx, com pontuações idênticas bit a bit; ~2,6x mais rápido, crescendo com o tamanho do gráfico (#5303, obrigado @Max17190).
  • Perf: watch cada caminho de origem preservado é rebaseado uma vez por atualização incremental em vez de ser recalculado por nó e borda; a saída da atualização é idêntica em bytes (# 5322, obrigado @ Max17190).
  • Correção: java um campo ou classe anotado com Lombok @Getter obtém o nó getter getX()/isX() sintetizado que javac vê, então obj.getX() resolve para ele; campos booleanos usam isX, @Getter(AccessLevel.NONE) é respeitado, um getter escrito à mão não é duplicado e um @Getter não Lombok é ignorado (# 5148, obrigado @Deepjyoti-Sarmah).
  • Correção: kotlin uma chamada de membro em um receptor com um tipo declarado (parâmetro, propriedade, val x: T ou val x = T()) é vinculada ao método desse tipo em arquivos, em vez do último método com o mesmo nome no arquivo, e as chamadas de interface são enviadas para seus implementadores; um receptor ambíguo ou desconhecido falha ao fechar (#5355, obrigado @xiongjianxu).
  • Correção: sql um corpo de rotina PostgreSQL PL/pgSQL que a gramática analisa apenas por meio de recuperação de ERROR (RETURN QUERY SELECT ... FROM t) tem suas leituras de tabela recuperadas como bordas reads_from em vez de descartadas (#5349, obrigado @Deepjyoti-Sarmah).
  • Correção: build quando uma borda extraída por AST e uma cópia semântica (LLM) da mesma borda amarram, a borda EXTRACTED determinística é mantida, portanto, um documento posterior --update não exclui mais uma borda de código que uma cópia semântica havia sobrescrito (#5334, obrigado @Ildar-gn).
  • Correção: sql um procedimento T-SQL cujo cabeçalho a gramática analisa apenas parcialmente (tree-sitter-sql 0.3.12+ lê incorretamente o nome, absorvendo parâmetros sem parênteses ou um escape ""/]]) produz um único nó de rotina em vez de uma duplicata sob o ID de leitura incorreta; é mantida uma rotina real de compartilhamento da linha da leitura incorreta (#5236, obrigado @Deepjyoti-Sarmah).
  • Correção: vbnet um método declarado depois que uma string literal de múltiplas linhas não é mais descartada: o arquivo é reanalisado com strings de múltiplas linhas achatadas primeiro em um espaço reservado para preservação de linha, para que uma string não terminada em uma linha não engula mais o resto da classe; arquivos de linha única são analisados ​​inalterados (#5320, obrigado @Deepjyoti-Sarmah).
  • Correção: cpp um tipo qualificado para std:: (std::chrono::seconds, std::vector<T>) não é mais reconectado em um símbolo de projeto com o mesmo nome; a referência std obtém seu próprio stub sem fonte que a religação do corpus ignora, enquanto os argumentos do modelo do tipo std ainda são resolvidos para os próprios tipos do projeto (# 5219, obrigado @ deba2k5).
  • Correção: python um import mod simples onde mod fica em um diretório sys.path.insert(...) (um diretório de script sem pacote) agora vincula mod.func() ao nó de função func, corresponde ao arquivo exclusivo nesse caminho e falha no fechamento por ambiguidade ou nome stdlib; uma borda calls não tem mais alias em um nó de arquivo (#5253, obrigado @madhusudanpatnaik).
  • Correção: servir uma consulta que filtra a relação call agora mantém bordas calls de repositório cruzado (escritas como relation=calls, context=cross_repo), que foram descartadas silenciosamente pelo filtro somente de contexto (#5257, obrigado @LHopitalOne).
  • Correção: construir a borda estrutural method/contains de um membro para seu proprietário é mantida sobre uma borda de uso de membro de direção oposta (um método que lê a própria propriedade estática ou constante de sua classe), para que o membro não desapareça mais do passeio do tipo; relações de não uso (herda/implementa) mantêm a regra existente (#2391, obrigado @livingforelvis). O esquema de cache AST aumentou para 50; caches quentes executam novamente as extrações afetadas de Kotlin, Java, SQL, VB.NET, C++ e Python (importação sys.path).

graphify v0.9.114

Performance work on the extract/build/update pipeline, plus a batch of extractor and build fixes. Every entry marked Perf preserves graph output exactly (byte-identical); the extractor fixes change output and share one AST cache schema bump (see the note at the end).

  • Perf: ids normalize_id gets an ASCII fast-path, pre-compiled regexes and an LRU cache, so the common (ASCII, repeated) identifier case skips the Unicode normalization loop. ~1.26x on the compute path and a large win on repeated ids, which recurs heavily across a corpus.
  • Perf: cache save_cached builds the portable on-disk payload copy-on-write instead of copy.deepcopy-ing every per-file result; ~20% faster on the cache-write transform, scaling with per-file graph size. The input is never mutated and the on-disk bytes are identical.
  • Perf: extract each source file is read from disk once (the key hash and the parse share one buffer) instead of twice on a cold build, and the tree-sitter Parser is reused per language within a worker instead of rebuilt per file (file reads roughly halved on the worker path).
  • Perf: extract the cross-file resolution finalize builds its shared node/edge indexes in a few fused passes instead of ~6 independent full scans of the graph; ~15% faster on the finalize stage.
  • Perf: watch the no-change topology comparison uses an order-independent content hash computed in one pass instead of sorting and re-serializing the whole graph; ~1.4x on that compare.
  • Perf: cluster the community partition is cached by a topology hash and reused when the graph is unchanged (~9x on a cluster cache hit), and the deterministic edge-sort key drops a per-edge json.dumps in favour of a cheap tuple key (identical ordering).
  • Perf: analyze suggest_questions' betweenness centrality now runs a flat-array Brandes implementation instead of networkx's dict-based one, with bit-for-bit identical scores; ~2.6x faster, growing with graph size (#5303, thanks @Max17190).
  • Perf: watch each preserved source path is rebased once per incremental update instead of recomputed per node and edge; the update output is byte-identical (#5322, thanks @Max17190).
  • Fix: java a field or class annotated with Lombok @Getter gets the synthesized getX()/isX() getter node javac sees, so obj.getX() resolves to it; boolean fields use isX, @Getter(AccessLevel.NONE) is respected, a hand-written getter is not duplicated, and a non-Lombok @Getter is ignored (#5148, thanks @Deepjyoti-Sarmah).
  • Fix: kotlin a member call on a receiver with a declared type (parameter, property, val x: T, or val x = T()) binds to that type's method across files instead of the last same-named method in the file, and interface calls dispatch to their implementers; an ambiguous or unknown receiver fails closed (#5355, thanks @xiongjianxu).
  • Fix: sql a PostgreSQL PL/pgSQL routine body that the grammar only parses through ERROR recovery (RETURN QUERY SELECT ... FROM t) has its table reads recovered as reads_from edges instead of dropped (#5349, thanks @Deepjyoti-Sarmah).
  • Fix: build when an AST-extracted edge and a semantic (LLM) copy of the same edge tie, the deterministic EXTRACTED edge is kept, so a later docs --update no longer deletes a code edge that a semantic copy had overwritten (#5334, thanks @Ildar-gn).
  • Fix: sql a T-SQL procedure whose header the grammar only partly parses (tree-sitter-sql 0.3.12+ misreads the name, absorbing unparenthesised params or a ""/]] escape) yields a single routine node instead of a duplicate under the misread id; a real routine sharing the misread's line is kept (#5236, thanks @Deepjyoti-Sarmah).
  • Fix: vbnet a method declared after a multi-line string literal is no longer dropped: the file is reparsed with multi-line strings flattened to a line-preserving placeholder first, so an unterminated string on one line no longer swallows the rest of the class; single-line files are parsed unchanged (#5320, thanks @Deepjyoti-Sarmah).
  • Fix: cpp a std::-qualified type (std::chrono::seconds, std::vector<T>) is no longer rewired onto a same-named project symbol; the std reference gets its own sourceless stub the corpus rewire skips, while the std type's template arguments still resolve to the project's own types (#5219, thanks @deba2k5).
  • Fix: python a plain import mod where mod sits on a sys.path.insert(...) directory (a non-package script dir) now binds mod.func() to the func function node, matched to the unique file on that path and failing closed on ambiguity or a stdlib name; a calls edge is no longer aliased onto a file node (#5253, thanks @madhusudanpatnaik).
  • Fix: serve a query that filters on the call relation now keeps cross-repo calls edges (written as relation=calls, context=cross_repo), which were silently dropped by the context-only filter (#5257, thanks @LHopitalOne).
  • Fix: build a member's structural method/contains edge to its owner is kept over an opposite-direction member-usage edge (a method reading its class's own static property or constant), so the member no longer vanishes from the type's walk; non-usage relations (inherits/implements) keep the existing rule (#2391, thanks @livingforelvis).

The AST cache schema is bumped to 50; warm caches re-run the affected Kotlin, Java, SQL, VB.NET, C++ and Python (sys.path import) extractions.
