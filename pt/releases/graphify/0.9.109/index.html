#grafificar v0.9.109

  • Correção: csharp um arquivo de origem não-UTF-8 (Windows-1252/UTF-16) que contém uma diretiva de pré-processador é decodificado antes que a diretiva seja apagada, portanto, um identificador não-ASCII não é mais interrompido e membros posteriores não são mais eliminados (#5194, obrigado @JensD-git).
  • Correção: csharp uma implementação de interface explícita (void IFoo.Bar()) é mantida fora da ligação de sobrecarga e obtém seu próprio nó, portanto, não entra mais em colapso com uma sobrecarga pública de Bar e chama o envio para o membro correto (#5193, obrigado @JensD-git).
  • Correção: ids membros ou funções de um escopo cujos nomes diferem apenas por um _ inicial/final, ou apenas por caso, obtêm ids de nó distintos em vez de um engolir o outro, agora em Kotlin (#5206), Swift (#5204), Dart (#5200) e C++ (incluindo um construtor Foo vs destruidor ~Foo e um sublinhado final name_, #5202); um nome público exclusivo mantém o id simples e os gêmeos são salgados, como já foi feito para Python, C#, Java e PHP (obrigado @rohit-jsfreaky).
  • Correção: llm quando um retorno de chamada por bloco é gerado durante a extração paralela, os blocos restantes na fila são cancelados em vez de continuar a execução, portanto, uma execução com falha é interrompida imediatamente sem desperdício de chamadas de modelo (#5187, obrigado @MaxWang007).
  • Correção: extrair uma falha de AST por arquivo durante uma compilação incremental preserva os últimos registros AST válidos da fonte em vez de excluí-los, marca a execução como incompleta e limpa o hash de manifesto do arquivo para que a próxima execução tente novamente (#5191, obrigado @sdivyanshu90).
  • Correção: llm uma resposta contendo dois ou mais fragmentos de gráfico independentes (ou uma matriz de vários elementos) é rejeitada e tentada novamente em vez de armazenar em cache apenas o primeiro como se estivesse completo; um único objeto, ou uma matriz de elemento único envolvendo um fragmento válido, ainda é aceito (#5192, obrigado @sdivyanshu90).
  • Correção: extrair sob uma raiz de varredura com link simbólico, um arquivo na raiz mantém seu source_file relativo ao repositório em vez de ser reduzido a um nome de base simples (que mesclava arquivos distintos em um e esvaziou o gráfico); apenas o pai é resolvido, portanto, um link simbólico de arquivo que #2832 mantém distinto ainda é (#4624, obrigado @maruf-asterbyte).
  • Correção: extrair um parâmetro variado faz referência ao seu tipo de elemento (xs ...T em Go, T... xs em Java, params T[] em C#, T* em Scala, ...$xs em PHP), em vez de não emitir nenhum tipo edge (#4638, obrigado @madhusudanpatnaik).
  • Correção: dart um typedef herdado que retorna um tipo de função (typedef int Function(int) Make();) é nomeado por seu próprio nome declarado em vez de Function (#4641, obrigado @madhusudanpatnaik).
  • Correção: habilidade um arquivo para o qual um subagente semântico despachou, mas nunca relatou uma entrada de cobertura, é tratado como não lido e reenviado, em vez de ser armazenado em cache e carimbado como completo a partir de nós adivinhados por seu nome; o prompt do subagente agora solicita uma entrada de cobertura (0 = nunca aberta) para cada arquivo (#2225, obrigado @Kalessin-Roke). O esquema de cache AST aumentou para 46; caches quentes executam novamente as extrações afetadas de C#, Kotlin, Swift, Dart, C++, Go, Java, Scala e PHP.

Original em inglês / English original

graphify v0.9.109

  • Fix: csharp a non-UTF-8 source file (Windows-1252/UTF-16) that contains a preprocessor directive is decoded before the directive is blanked, so a non-ASCII identifier is no longer cut short and later members are no longer dropped (#5194, thanks @JensD-git).
  • Fix: csharp an explicit interface implementation (void IFoo.Bar()) is kept out of overload binding and gets its own node, so it no longer collapses with a public Bar overload, and calls dispatch to the correct member (#5193, thanks @JensD-git).
  • Fix: ids members or functions of one scope whose names differ only by a leading/trailing _, or only by case, get distinct node ids instead of one swallowing the other, now in Kotlin (#5206), Swift (#5204), Dart (#5200) and C++ (including a constructor Foo vs destructor ~Foo, and a trailing-underscore name_, #5202); a unique public name keeps the plain id and the twins are salted, as already done for Python, C#, Java and PHP (thanks @rohit-jsfreaky).
  • Fix: llm when a per-chunk callback raises during parallel extraction, the remaining queued chunks are cancelled instead of continuing to run, so a failed run stops promptly without wasted model calls (#5187, thanks @MaxWang007).
  • Fix: extract a per-file AST failure during an incremental build preserves the source's last good AST records instead of deleting them, marks the run incomplete, and clears the file's manifest hash so the next run re-attempts it (#5191, thanks @sdivyanshu90).
  • Fix: llm a response carrying two or more independent graph fragments (or a multi-element array) is rejected and retried instead of caching only the first as if complete; a single object, or a single-element array wrapping one valid fragment, is still accepted (#5192, thanks @sdivyanshu90).
  • Fix: extract under a symlinked scan root, an in-root file keeps its repo-relative source_file instead of collapsing to a bare basename (which merged distinct files into one and emptied the graph); only the parent is resolved, so a file symlink that #2832 keeps distinct still is (#4624, thanks @maruf-asterbyte).
  • Fix: extract a variadic parameter references its element type (xs ...T in Go, T... xs in Java, params T[] in C#, T* in Scala, ...$xs in PHP), instead of emitting no type edge (#4638, thanks @madhusudanpatnaik).
  • Fix: dart a legacy typedef that returns a function type (typedef int Function(int) Make();) is named by its own declared name instead of by Function (#4641, thanks @madhusudanpatnaik).
  • Fix: skill a file a semantic subagent dispatched but never reported a coverage entry for is treated as unread and re-dispatched, instead of being cached and stamped complete from nodes guessed off its name; the subagent prompt now asks for a coverage entry (0 = never opened) for every file (#2225, thanks @Kalessin-Roke). The AST cache schema is bumped to 46; warm caches re-run the affected C#, Kotlin, Swift, Dart, C++, Go, Java, Scala and PHP extractions.
