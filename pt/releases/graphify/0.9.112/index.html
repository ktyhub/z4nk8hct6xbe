graphify v0.9.112

#grafificar v0.9.112

  • Documentos: python o README, suas traduções, CONTRIBUTING, RELEASING, o modelo de relatório de bug e os alvos ruff/pyright agora declaram Python 3.11 como o mínimo, correspondendo ao piso enviado em 0.9.111 (#5238, obrigado @Deepanshu-Mehta; @Max17190 enviou a mesma correção em #5237).
  • Documentos: links o link de configuração Always-on no README e todas as traduções apontam diretamente para docs.graphify.com/open-source/vibe-coding em vez de passar por um redirecionamento do caminho antigo de guias/always-on (#5261, obrigado @SyedFahad7).
  • Correção: java cada método sobrecarregado obtém seu próprio nó codificado por aridade e assinatura apagada, em vez de todas as sobrecargas colapsarem em um nó que descartava membros e roteava chamadas incorretamente; A correspondência de substituição affected agora tem reconhecimento de aridade, portanto, uma divisão run(int) não está vinculada a um supertipo run() por rótulo, e sobrecargas de repositório cruzado e método genérico também são tratadas (# 5251, obrigado @ deba2k5). Sobrecargas de mesma aridade e apenas de tipo distinto ainda se vinculam à primeira declarada (espelhando o precedente C # # 4584); o despacho do tipo argumento literal é um acompanhamento. Construtores sobrecarregados ainda compartilham um nó.
  • Correção: go um tipo de receptor simples (func (s Service) m()) resolve para o tipo de seu próprio pacote em vez de ser comparado com todos os tipos de mesmo nome no corpus, então dois pacotes cada um declarando um Service mantêm suas próprias bordas de chamada de membro em vez de ambos perdê-los para uma fiança de ambiguidade (#5242, obrigado @ayushcodes10).
  • Correção: rust uma importação use crate::... é resolvida dentro de sua própria caixa em vez de vazar através dos limites da caixa para o item de mesmo nome de outra caixa em um espaço de trabalho com várias caixas; uma importação crate:: de caixa única ainda é resolvida como antes (#5240, obrigado @Max17190).
  • Correção: js um membro this.x = function (params) {...} não fabrica mais um indirect_call falso quando um de seus parâmetros obscurece uma função de corpus de mesmo nome usada na posição do argumento; seus próprios parâmetros e nomes capturados do escopo anexo são tratados como ligações locais, enquanto um nome genuinamente não vinculado ainda é resolvido (#5241, obrigado @Max17190).
  • Correção: c uma inclusão de ângulo qualificada por diretório (#include <dir/header.h>) é resolvida para o arquivo local correspondente e os cabeçalhos da biblioteca padrão (<stdio.h>, <functional>) são mantidos fora do índice de alias para que um arquivo de projeto com o mesmo nome não seja curado neles; um cabeçalho local que compartilha um nome qualificado de diretório ainda é resolvido (#5218, obrigado @Yi-111-a).
  • Correção: sql uma tabela nomeada com letras não ASCII que a gramática reduz para um _ vazio não cria mais um nó com um id vazio ou uma borda para um id vazio; em vez disso, a borda falsa é eliminada (# 5250, obrigado @ grbr2010).
  • Correção: dedup uma palavra derivada de prefixo é mantida separada de sua palavra base, de modo que pares de antônimos e prefixos (synchronous/asynchronous, cyclic/acyclic, reload/load) não se dobram mais por meio da mesclagem de rótulo difuso, enquanto inflexões genuínas como handler/handlers ainda se fundem (#5239, obrigado @Deepanshu-Mehta).
  • Correção: construir a tabela de família do protetor de borda entre idiomas não se desvia mais da do extrator: 37 extensões que não tinham entrada de família (portanto, uma colisão coincidente de nomes entre idiomas nunca foi descartada) são reconciliadas e um teste falha no CI se as duas tabelas divergirem novamente (#5247, obrigado @Yi-111-a).
  • Correção: instalar graphify claude install grava sua seção no arquivo que Claude Code realmente lê. Claude Code lê o AGENTS.md de um projeto somente quando não existe CLAUDE.md (CLAUDE.md, .claude/CLAUDE.md, CLAUDE.local.md) no projeto ou em qualquer diretório acima dele, portanto, criar um CLAUDE.md ao lado de um AGENTS.md escondeu silenciosamente esse AGENTS.md do Claude Code. A instalação agora tem como alvo um CLAUDE.md/.claude/CLAUDE.md existente, se presente, caso contrário, um AGENTS.md/.claude/AGENTS.md existente, caso contrário, um novo CLAUDE.md como antes; a desinstalação é simétrica (#5277, obrigado @andrebrait).
  • Correção: instalar graphify install se recusa a sobrescrever uma configuração existente do Kilo que não pode analisar, em vez de substituí-la silenciosamente por um arquivo somente gráfico e perder as configurações do usuário; uma configuração válida ou ausente ainda é mesclada como antes (#5265, obrigado @divya0795).
  • Correção: analisar os ciclos de importação de dois arquivos são listados antes que o limite de enumeração seja preenchido, portanto, em um gráfico com muitos ciclos mais longos, os ciclos mais restritos (dois arquivos mútuos) não são mais descartados; a listagem agora também é determinística entre execuções (#5267, obrigado @divya0795).
  • Correção: extração o protetor net-shrink não está armado para uma fonte que não tem nada para proteger (uma que nunca produziu nenhum nó salvo, por exemplo, um arquivo cuja gramática extra opcional não está instalada), então tal fonte não bloqueia mais uma extração posterior que reduz legitimamente o gráfico; uma fonte que salvou registros ainda arma a guarda (#5245, obrigado @ayushcodes10).
  • Correção: construir dobrar um documento gêmeo Markdown preserva a estrutura do sobrevivente: um nó de título real não é mais confundido com o gêmeo semântico da página e o nó da página (com seu frontmatter e bordas contains) é mantido, enquanto gêmeos semânticos genuínos ainda dobram (#5272, obrigado @sdivyanshu90).
  • Correção: construir aliases de corpus com link simbólico são removidos de forma independente: excluir ou excluir um alias de link simbólico não descarta mais seu alvo ou um alias de irmão que resolve para o mesmo arquivo, porque agora a correspondência de remoção é feita com chaves no caminho do corpus em vez do alvo físico resolvido (#5273, obrigado @sdivyanshu90).
  • Correção: pascal uma unidade que a gramática do tree-sitter não pode analisar de ponta a ponta (por exemplo, uma com uma string SQL literal de escape) é recuperada por meio de uma nova tentativa mascarada que preserva o comprimento de bytes, em vez de não gerar nenhum nó; a nova tentativa é executada somente quando a análise normal apresenta erro e é aceita apenas se for estritamente mais saudável, portanto, as unidades que já foram analisadas permanecem inalteradas (#5264, obrigado @patrykseksymfonia).
  • Correção: pascal uma classe base resolve sua declaração real na unidade em que é declarada, em vez de um stub correspondente à convenção de nome de arquivo, então a borda inherits e as chamadas herdadas através dela são resolvidas entre arquivos (#5280, obrigado @patrykseksymfonia).
  • Correção: pascal uma chamada por meio de uma variável de objeto global (DM.Open, o idioma do módulo de dados Delphi) é resolvida para o membro do tipo da variável: o extrator registra globais em nível de unidade, campos por classe e sombras por rotina, e a resolução vincula a chamada qualificada com falha fechada por meio da cláusula de uso, deixando-a sem solução quando um campo, local ou tipo de matriz global sombreia o nome (# 3101, obrigado @patrikseksymfonia).
  • Façanha: delphi um formulário (.dfm/.lfm) está vinculado à unidade que o implementa: a classe do formulário e cada stub OnClick = Handler obtêm uma borda references INFERIDA para a classe e método real no irmão .pas, emparelhado pelo nome base e uma pesquisa exclusiva de classe/método (#5281, obrigado @patrykseksymfonia). O esquema de cache AST aumentou para 48; caches quentes executam novamente as extrações Go, Java, JS/TS, C/C++, SQL e Pascal afetadas.

Original em inglês / English original

graphify v0.9.112

  • Docs: python the README, its translations, CONTRIBUTING, RELEASING, the bug-report template and the ruff/pyright targets now state Python 3.11 as the minimum, matching the floor that shipped in 0.9.111 (#5238, thanks @Deepanshu-Mehta; @Max17190 sent the same fix in #5237).
  • Docs: links the Always-on setup link in the README and all translations points straight at docs.graphify.com/open-source/vibe-coding instead of going through a redirect from the old guides/always-on path (#5261, thanks @SyedFahad7).
  • Fix: java each overloaded method gets its own node keyed by arity and erased signature, instead of all overloads collapsing into one node that dropped members and misrouted calls; affected override-matching is now arity-aware so a split run(int) is not tied to a supertype run() by label, and cross-repo and generic-method overloads are handled too (#5251, thanks @deba2k5). Same-arity, type-only-distinct overloads still bind to the first declared one (mirroring the C# precedent #4584); literal-argument-type dispatch is a follow-up. Overloaded constructors still share one node.
  • Fix: go a bare receiver type (func (s Service) m()) resolves to its own package's type instead of being matched against every same-named type in the corpus, so two packages each declaring a Service keep their own member-call edges rather than both losing them to an ambiguity bail (#5242, thanks @ayushcodes10).
  • Fix: rust a use crate::... import resolves inside its own crate instead of leaking across crate boundaries to another crate's same-named item in a multi-crate workspace; a single-crate crate:: import still resolves as before (#5240, thanks @Max17190).
  • Fix: js a this.x = function (params) {...} member no longer fabricates a false indirect_call when one of its parameters shadows a same-named corpus function used in argument position; its own params and names captured from the enclosing scope are treated as local bindings, while a genuinely unbound name still resolves (#5241, thanks @Max17190).
  • Fix: c a directory-qualified angle include (#include <dir/header.h>) resolves to the matching local file, and standard-library headers (<stdio.h>, <functional>) are kept off the alias index so a same-named project file is not healed onto them; a local header that shares a directory-qualified name still resolves (#5218, thanks @Yi-111-a).
  • Fix: sql a table named with non-ASCII letters that the grammar collapses to a bare _ no longer mints a node with an empty id or an edge to an empty id; the bogus edge is dropped instead (#5250, thanks @grbr2010).
  • Fix: dedup a prefix-derived word is kept apart from its base word, so antonym and prefixed pairs (synchronous/asynchronous, cyclic/acyclic, reload/load) no longer fold together through the fuzzy label merge, while genuine inflections like handler/handlers still merge (#5239, thanks @Deepanshu-Mehta).
  • Fix: build the cross-language edge guard's family table no longer drifts from the extractor's: 37 extensions that had no family entry (so a coincidental cross-language name collision was never dropped) are reconciled, and a test fails CI if the two tables diverge again (#5247, thanks @Yi-111-a).
  • Fix: install graphify claude install writes its section to the file Claude Code actually reads. Claude Code reads a project's AGENTS.md only when no CLAUDE.md (CLAUDE.md, .claude/CLAUDE.md, CLAUDE.local.md) exists in the project or any directory above it, so creating a CLAUDE.md beside an AGENTS.md silently hid that AGENTS.md from Claude Code. The install now targets an existing CLAUDE.md/.claude/CLAUDE.md if present, else an existing AGENTS.md/.claude/AGENTS.md, else a new CLAUDE.md as before; uninstall is symmetric (#5277, thanks @andrebrait).
  • Fix: install graphify install refuses to overwrite an existing Kilo config it cannot parse, instead of silently replacing it with a graphify-only file and losing the user's settings; a valid or missing config still merges as before (#5265, thanks @divya0795).
  • Fix: analyze two-file import cycles are listed before the enumeration cap fills, so on a graph with many longer cycles the tightest (mutual two-file) cycles are no longer dropped; the listing is also now deterministic across runs (#5267, thanks @divya0795).
  • Fix: extract the net-shrink guard is not armed for a source that has nothing to protect (one that never produced any saved nodes, e.g. a file whose optional grammar extra is not installed), so such a source no longer blocks a later extract that legitimately shrinks the graph; a source that did have saved records still arms the guard (#5245, thanks @ayushcodes10).
  • Fix: build folding a Markdown document twin preserves the survivor's structure: a real heading node is no longer mistaken for the page's semantic twin and the page node (with its frontmatter and contains edges) is kept, while genuine semantic twins still fold (#5272, thanks @sdivyanshu90).
  • Fix: build symlinked corpus aliases are pruned independently: excluding or deleting one symlink alias no longer also drops its target or a sibling alias that resolves to the same file, because prune matching now keys on the corpus path rather than the resolved physical target (#5273, thanks @sdivyanshu90).
  • Fix: pascal a unit the tree-sitter grammar cannot parse end to end (for example one with an escaped SQL string literal) is recovered through a byte-length-preserving masked retry, instead of yielding no nodes; the retry runs only when the normal parse errored and is accepted only if strictly healthier, so units that already parse are unchanged (#5264, thanks @patrykseksymfonia).
  • Fix: pascal a base class resolves to its real declaration in the unit it is declared in, instead of a stub matched by filename convention, so the inherits edge and the inherited calls through it resolve across files (#5280, thanks @patrykseksymfonia).
  • Fix: pascal a call through a global object variable (DM.Open, the Delphi data-module idiom) resolves to the variable's type member: the extractor records unit-level globals, per-class fields and per-routine shadows, and resolution binds the qualified call fail-closed through the uses-clause, leaving it unresolved when a field, local or array-typed global shadows the name (#3101, thanks @patrykseksymfonia).
  • Feat: delphi a form (.dfm/.lfm) is linked to the unit that implements it: the form class and each OnClick = Handler stub get an INFERRED references edge to the real class and method in the sibling .pas, paired by base name and a unique class/method lookup (#5281, thanks @patrykseksymfonia).

The AST cache schema is bumped to 48; warm caches re-run the affected Go, Java, JS/TS, C/C++, SQL and Pascal extractions.
