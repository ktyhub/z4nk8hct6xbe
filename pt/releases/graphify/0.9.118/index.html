#grafificar v0.9.118 Um lote de correções de extração, resolução, veiculação, exportação, clustering e geração de relatórios em quatorze solicitações pull da comunidade. As alterações em Objective-C, C e C# alteram a saída do nó/borda, de modo que o esquema de cache do AST aumenta (51 para 53) e a primeira compilação após a atualização extrai novamente os idiomas afetados; as outras correções não precisam de reconstrução.

  • Correção: csharp um local, parâmetro ou campo chamado partial, required, async, nint, nuint ou with (palavras-chave contextuais) que tree-sitter-c-sharp analisa incorretamente onde uma instrução começa com ele não atrapalha mais o arquivo; ele é reescrito em sua forma @name literal antes da análise (preservação do comprimento de byte), de modo que o tipo envolvente e os membros posteriores sejam mantidos em vez de serem eliminados silenciosamente (# 5043, obrigado @ThatAblaze).
  • Correção: c uma chamada através de um campo de ponteiro de função struct (ops->run(), ops.run()) não fabrica mais uma borda calls para uma função livre de mesmo nome; o nome do campo não é evidência do destino de tempo de execução do ponteiro, portanto a estimativa é descartada. Uma chamada direta simples ainda resolve (#5410, obrigado @sdivyanshu90).
  • Correção: objc um método Objective-C cujo nome se dobra no id de um irmão dentro de um @interface/@implementation/@protocol (um _ inicial/final como em -setup/-_setup, ou uma diferença apenas de maiúsculas e minúsculas) obtém seu próprio id de nó salgado em vez de substituí-lo; a declaração e definição de um método ainda compartilham um único nó (#5390, obrigado @ayushcodes10).
  • Correção: go o tipo de proprietário de um campo struct tem como escopo seu próprio pacote, portanto, um campo de um tipo cujo nome é declarado em dois pacotes é vinculado ao correto e suas chamadas de membro são resolvidas em vez de serem descartadas como ambíguas (#5408, obrigado @azizur100389).
  • Correção: extrair uma importação Svelte que vem através de um barril export * agora resolve para o módulo de definição real, correspondendo ao .ts simples. O resolvedor de arquivos cruzados estava mascarando .vue, mas não .svelte, então as importações do Svelte <script> foram perdidas devido a um erro de análise de modelo; barris encadeados são resolvidos e reexportações ambíguas falham. Execute graphify extract . --force uma vez para reparar um gráfico já armazenado em cache (#5403, obrigado @Max17190).
  • Correção: extração arquivos de áudio e vídeo que são detectados, mas não extraídos (extração sem cabeça não tem etapa de transcrição) agora são relatados no resumo em vez de desaparecerem silenciosamente, correspondendo aos outros avisos de salto; nenhum nó é fabricado para eles (#5076, obrigado @ayushcodes10).
  • Correção: seções A nova tentativa de get_section não reutiliza mais o índice de pesquisa de trigramas do gráfico completo. A nova tentativa foi executada em uma visualização de subgráfico networkx cujo ditado .graph é o mesmo objeto que serve para armazenar o índice em cache, portanto, a nova tentativa pesquisou ids obsoletos e fora da seção e levantou KeyError; a visualização de nova tentativa agora obtém seus próprios metadados de gráfico, o que também remove o risco de corrupção de índice de gráfico compartilhado para chamadores de serviço simultâneos (nº 5385, obrigado @Deepjyoti-Sarmah).
  • Correção: servir o servidor MCP carrega graph.json fora do loop de eventos, de modo que uma grande recarga de gráfico não bloqueia mais solicitações simultâneas; uma solicitação durante uma recarga é atendida no gráfico atual e uma recarga corrompida deixa o gráfico antigo intacto (# 5371, obrigado @Deepjyoti-Sarmah).
  • Correção: atualização um GRAPH_REPORT.md agrupado que é excluído enquanto o gráfico permanece inalterado é regenerado em vez de ser ignorado pelo portão sem alteração; o gráfico em si é deixado com bytes idênticos (restaurado do cache da partição), portanto, não há reconstrução desnecessária (# 5402, obrigado @ Max17190).
  • Correção: os nós de imagem de consulta são rebaixados na pontuação inicial junto com documentos e papéis, de modo que uma imagem rica em legendas não supera mais o código real para uma consulta cujos termos ela repete (nº 445, obrigado @ayushcodes10).
  • Correção: exportar nomes de arquivos de exportação respeitam o NAME_MAX do sistema de arquivos de destino (testado via pathconf, não assumido como 255), então graphify export obsidian/wiki/canvas não aborta mais com ENAMETOOLONG em sistemas de arquivos que relatam um limite inferior, como eCryptfs (143); nomes longos são truncados com um sufixo hash e links internos usam nomes abreviados (#2109, obrigado @Synvoya).
  • Correção: as exportações de gráficos direcionados do wiki agora incluem bordas de entrada, portanto, uma auditoria da comunidade não subestima mais a confiança (uma borda AMBÍGUA de entrada pode ficar invisível enquanto a página lê "EXTRACTED 100%"). Nas páginas do nó divino, as bordas de entrada são marcadas como (incoming), portanto, uma relação como calls não é lida de trás para frente (#5369, obrigado @sdivyanshu90).
  • Correção: config .graphifyrc agora analisa demote_docs / query_demote_docs, para que um projeto possa definir o rebaixamento de documento no rcfile em vez de apenas por meio do sinalizador CLI; um sinalizador explícito ainda o substitui (#5290, obrigado @debojyoti10CC).
  • Desempenho: a contagem de sobreposição de comunidades de cluster durante uma reconstrução é calculada a partir de nós compartilhados em uma passagem, em vez de cruzar cada par de comunidades, transformando uma etapa O (comunidades ao quadrado) em uma etapa linear com resultados idênticos em bytes (#5382, obrigado @Max17190).

graphify v0.9.118

A batch of extractor, resolution, serve, export, clustering and reporting fixes across fourteen community pull requests. The Objective-C, C and C# changes alter node/edge output, so the AST cache schema bumps (51 to 53) and the first build after upgrading re-extracts the affected languages; the other fixes need no rebuild.

  • Fix: csharp a local, parameter or field named partial, required, async, nint, nuint or with (contextual keywords) that tree-sitter-c-sharp mis-parses where a statement starts with it no longer derails the file; it is rewritten to its verbatim @name form before parsing (byte-length preserving), so the enclosing type and the members after it are kept instead of being silently dropped (#5043, thanks @ThatAblaze).
  • Fix: c a call through a struct function-pointer field (ops->run(), ops.run()) no longer fabricates a calls edge to a same-named free function; the field name is no evidence of the pointer's runtime target, so the guess is dropped. A plain direct call still resolves (#5410, thanks @sdivyanshu90).
  • Fix: objc an Objective-C method whose name folds onto a sibling's id within one @interface/@implementation/@protocol (a leading/trailing _ as in -setup/-_setup, or a case-only difference) gets its own salted node id instead of overwriting it; the declaration and definition of one method still share a single node (#5390, thanks @ayushcodes10).
  • Fix: go a struct field's owner type is scoped to its own package, so a field of a type whose name is declared in two packages binds to the right one and its member calls resolve instead of being dropped as ambiguous (#5408, thanks @azizur100389).
  • Fix: extract a Svelte import that comes through an export * barrel now resolves to the real defining module, matching plain .ts. The cross-file resolver was masking .vue but not .svelte, so the Svelte <script> imports were lost to a template parse error; chained barrels resolve and ambiguous re-exports fail closed. Run graphify extract . --force once to repair an already-cached graph (#5403, thanks @Max17190).
  • Fix: extract audio and video files that are detected but not extracted (headless extract has no transcription step) are now reported in the summary instead of silently vanishing, matching the other skip notices; no nodes are fabricated for them (#5076, thanks @ayushcodes10).
  • Fix: sections get_section's retry no longer reuses the full graph's trigram search index. The retry ran against a networkx subgraph view whose .graph dict is the same object serve caches the index on, so the retry searched stale, out-of-section ids and raised KeyError; the retry view now gets its own graph metadata, which also removes a shared-graph index-corruption hazard for concurrent serve callers (#5385, thanks @Deepjyoti-Sarmah).
  • Fix: serve the MCP server loads graph.json off the event loop, so a large graph reload no longer blocks concurrent requests; a request during a reload is served the current graph and a corrupt reload leaves the old graph intact (#5371, thanks @Deepjyoti-Sarmah).
  • Fix: update a clustered GRAPH_REPORT.md that is deleted while the graph is otherwise unchanged is regenerated instead of being skipped by the no-change gate; the graph itself is left byte-identical (restored from the partition cache) so there is no needless rebuild (#5402, thanks @Max17190).
  • Fix: query image nodes are demoted in seed scoring alongside documents and papers, so a caption-rich image no longer out-seeds real code for a query whose terms it happens to repeat (#445, thanks @ayushcodes10).
  • Fix: export export filenames honor the target filesystem's NAME_MAX (probed via pathconf, not assumed to be 255), so graphify export obsidian/wiki/canvas no longer aborts with ENAMETOOLONG on filesystems that report a lower limit such as eCryptfs (143); long names are truncated with a hash suffix and internal links use the shortened names (#2109, thanks @Synvoya).
  • Fix: wiki directed-graph exports now include incoming edges, so a community audit no longer under-reports confidence (an incoming AMBIGUOUS edge could be invisible while the page read "EXTRACTED 100%"). On god-node pages incoming edges are marked (incoming) so a relation like calls is not read backwards (#5369, thanks @sdivyanshu90).
  • Fix: config .graphifyrc now parses demote_docs / query_demote_docs, so a project can set doc demotion in the rcfile instead of only via the CLI flag; an explicit flag still overrides it (#5290, thanks @debojyoti10CC).
  • Perf: cluster community-overlap counting during a rebuild is computed from shared nodes in one pass instead of intersecting every pair of communities, turning an O(communities squared) step into a linear one with byte-identical results (#5382, thanks @Max17190).
