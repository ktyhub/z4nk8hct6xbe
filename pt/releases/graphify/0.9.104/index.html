#grafificar v0.9.104

grafificar 0.9.104

  • Segurança: habilidade o runbook /graphify não substitui mais o caminho de varredura no código Python. Cada bloco de código gerado (detectar, AST e extração semântica, construir, diagnosticar, rotular, manifestar e --update) agora lê a raiz de varredura resolvida do arquivo secundário graphify-out/.graphify_root trusted que a Etapa 1 grava por meio de um heredoc citado, em vez de colar o caminho fornecido pelo agente em uma string literal. Um diretório cujo nome continha uma aspa ou $(...) poderia anteriormente sair do Path('INPUT_PATH') e ser executado como código; agora é lido como dados inertes. Abrange os hosts montados e os monólitos Aider/Devin (#4762, obrigado @danikdanik).
  • Correção: solididade uma chamada em um receptor de um tipo de contrato ou interface (IERC20 token; token.transfer(), IERC20(a).transfer(), token().balanceOf()) é vinculada por nome e aridade por meio da linearização desse tipo à declaração do próprio tipo, em vez de não produzir nenhuma vantagem; fechado para um único contrato/interface visível e fechado com falha em um tipo desconhecido ou ambíguo (#5060, obrigado @rohit-jsfreaky).
  • Correção: solididade uma chamada anexada por uma diretiva using A for T (using SafeCast for uint256; x.toUint48()) vincula-se à biblioteca ou função livre que ela anexa, correspondida pelo tipo do receptor e uma aridade maior que a chamada; fechado com falha quando o tipo de receptor é desconhecido, a biblioteca é ambígua ou duas funções cabem (# 5062, obrigado @ rohit-jsfreaky).
  • Correção: membros solidity, funções livres e tipos em um escopo cujos nomes diferem apenas por um _ inicial ou por caso (_grantRole / grantRole) obtêm ids de nó separados, para que o símbolo _ não desapareça mais em seu gêmeo e suas chamadas caiam no nó direito (# 5027, obrigado @rohit-jsfreaky).
  • Correção: csharp um construtor (instância, estático ou primário) é seu próprio nó pertencente ao seu tipo, com seu corpo e chamadas : base(...)/: this(...) creditadas a ele; new X(...), : base(...) e : this(...) vinculam adicionalmente a sobrecarga com correção de aridade, e duas sobrecargas adequadas ou uma base não resolvida não fornecem vantagem ao construtor (# 5054, obrigado @rohit-jsfreaky).
  • Correção: chamadas csharp dentro de uma propriedade ou acessador de indexador, um corpo de expressão ou um corpo de operador/conversão são creditadas a esse membro em vez de serem perdidas; um indexador se torna um nó this[] e um operador um nó .operator +() (#5056, obrigado @rohit-jsfreaky).
  • Correção: consulta um nó com o mesmo rótulo que é a única correspondência para um termo de consulta é mantido como uma semente em vez de ser eliminado pelo limite por rótulo, de modo que cada termo distinto mantém pelo menos uma semente enquanto a inundação de rótulo genérico permanece limitada (#5027, obrigado @Vaibhav2824).
  • Correção: watch eventos somente leitura são mantidos fora da máscara inotify por meio de um event_filter somente alteração, de modo que uma árvore grande não leva mais o watchdog a um loop de estouro de fila autossustentável; volta com um aviso sobre versões watchdog sem suporte event_filter (#5033, obrigado @Deepjyoti-Sarmah).
  • Correção: cache a ortografia do caminho longo \\?\ é mantida fora da identidade do cache, então o mesmo arquivo acessado por \\?\C:\... e C:\... compartilha uma entrada; também corrige gravações de índice estatístico vazio em compartilhamentos UNC, um aviso falso de "índice estatístico trocado" no Windows e um alias de junção/link simbólico compartilhando erroneamente o resumo de seu alvo (#5035, obrigado @Bortlesboat).
  • Correção: cache as chaves de índice estatístico permanecem relativas à raiz em uma raiz de caminho longo do Windows, portanto, um corpus movido ou clonado mantém o atalho da chave portátil (#5035, obrigado @Vaibhav2824).
  • Correção: testa o fixture unicode TypeScript é escrito como UTF-8 em todas as plataformas, então os deslocamentos de bytes correspondem ao extrator em hosts Windows (cp1252) (#5064, obrigado @ayushcodes10).
  • Correção: testa a simulação da fonte de frescor do gancho é normalizada por meio de os_long_path, portanto, o branch de erro de leitura/obsoleto é realmente exercido no Windows (#5065, obrigado @ayushcodes10).
  • Correção: testes o teste de fila pendente de observação compara objetos Path para que os separadores / e \ sejam comparados iguais no Windows (#5039, obrigado @Yi-111-a).
  • Correção: extrair um ID de nó de espaço reservado de importação Python ambíguo é hash de dados independentes de checkout (nome do módulo, arquivo de origem relativo à raiz de varredura, localização) em vez do caminho absoluto, então o mesmo projeto em um caminho diferente ou um cache movido obtém os mesmos ids (#5045, obrigado @Fardin7798).
  • Correção: yaml um modelo usando tags intrínsecas do CloudFormation (!Ref, !GetAtt, !Sub) não falha mais na análise: um carregador permissivo com escopo reconstrói a forma de cada nó marcado com ! sem avaliá-lo, enquanto as tags !!python/... ainda aumentam e nunca são executadas (#5077, obrigado @ayushcodes10).
  • Correção: assistir uma atualização incremental do --watch reconstrói o corpus completo quando graph.json está faltando, em vez de escrever um gráfico parcial apenas do manifesto (#5020, obrigado @azizur100389).
  • Correção: observar uma alteração em uma entrada de resolução JS/TS (tsconfig.json, jsconfig.json, um arquivo de bloqueio) aciona uma reconstrução completa para que os importadores escolham a nova resolução, em vez de deixar bordas imports_from obsoletas (#5020, obrigado @azizur100389).
  • Correção: ingerir duas capturas graphify add simultâneas para o mesmo URL não se sobrepõem: o arquivo de captura é criado exclusivamente (O_EXCL) e uma colisão tenta novamente um novo nome, com a carga útil buscada uma vez (#5020, obrigado @azizur100389).
  • Correção: refletir uma entrada malformada na sobreposição de aprendizagem é ignorada em vez de travar toda a carga, e uma entrada legada de fonte nula é preservada como uma anotação sem fonte (#5020, obrigado @azizur100389).
  • Correção: global uma entrada de repositório malformada no manifesto global é descartada por conta própria, mantendo os outros repositórios rastreados, e apenas uma raiz não-objeto ou mapa de repositórios é copiada e redefinida (#5020, obrigado @azizur100389).
  • Correção: consulta um gráfico recém-construído em uma subpasta não é mais sinalizado como uma compilação anterior ao # 1504 (o que incomodava um extract --force não operacional): o teste de identificação legado remove o deslocamento do .graphify_root antes de derivar as hastes do arquivo, e um gráfico legado genuíno ainda é capturado (# 5019, obrigado @ neumannpeter1231-lang).
  • Correção: árvore graphify export tree reconhece o alias do nó src (e file/path/filepath) então um gráfico carregando essas chaves renderiza uma árvore preenchida em vez de uma árvore vazia; um gráfico apenas conceitual ainda está vazio (#5030, obrigado @ Adityakk9031).
  • Correção: cli graphify provider add aceita sintaxe igual a --pricing-input=VALUE/--pricing-output=VALUE e rejeita um preço não numérico, não finito ou negativo com um erro limpo em vez de um traceback ou uma estimativa de custo envenenada (#5031, obrigado @Adityakk9031). O esquema de cache AST aumentou para 40; caches quentes executam novamente as extrações afetadas do Solidity e C#. As correções Python e YAML acima não precisam de alterações (os IDs de espaço reservado são resolvidos após o cache por arquivo, e o YAML com falha anterior nunca foi armazenado em cache).

graphify v0.9.104

graphify 0.9.104

  • Security: skill the /graphify runbook no longer substitutes the scan path into Python code. Every generated code block (detect, AST and semantic extraction, build, diagnose, label, manifest, and --update) now reads the resolved scan root from the trusted graphify-out/.graphify_root sidecar that Step 1 writes through a quoted heredoc, instead of pasting the agent-supplied path into a string literal. A directory whose name carried a quote or $(...) could previously break out of Path('INPUT_PATH') and run as code; it is now read as inert data. Covers the assembled hosts and the Aider/Devin monoliths (#4762, thanks @danikdanik).
  • Fix: solidity a call on a receiver of a contract or interface type (IERC20 token; token.transfer(), IERC20(a).transfer(), token().balanceOf()) binds by name and arity through that type's linearization to the type's own declaration, instead of producing no edge; gated to a single visible contract/interface and fail-closed on an unknown or ambiguous type (#5060, thanks @rohit-jsfreaky).
  • Fix: solidity a call attached by a using A for T directive (using SafeCast for uint256; x.toUint48()) binds to the library or free function it attaches, matched by the receiver's type and an arity one greater than the call; fail-closed when the receiver type is unknown, the library is ambiguous, or two functions fit (#5062, thanks @rohit-jsfreaky).
  • Fix: solidity members, free functions and types in one scope whose names differ only by a leading _ or by case (_grantRole / grantRole) get separate node ids, so the _ symbol no longer vanishes into its twin and its calls land on the right node (#5027, thanks @rohit-jsfreaky).
  • Fix: csharp a constructor (instance, static or primary) is its own node owned by its type, with its body and : base(...)/: this(...) calls credited to it; new X(...), : base(...) and : this(...) additively link the arity-correct overload, and two fitting overloads or an unresolved base give no constructor edge (#5054, thanks @rohit-jsfreaky).
  • Fix: csharp calls inside a property or indexer accessor, an expression body, or an operator/conversion body are credited to that member instead of being lost; an indexer becomes a this[] node and an operator a .operator +() node (#5056, thanks @rohit-jsfreaky).
  • Fix: query a same-label node that is the only match for a query term is kept as a seed instead of being dropped by the per-label cap, so every distinct term keeps at least one seed while generic-label flooding stays capped (#5027, thanks @Vaibhav2824).
  • Fix: watch read-only events are kept out of the inotify mask via a change-only event_filter, so a large tree no longer drives watchdog into a self-sustaining queue-overflow loop; falls back with a warning on watchdog versions without event_filter support (#5033, thanks @Deepjyoti-Sarmah).
  • Fix: cache the \\?\ long-path spelling is kept out of cache identity, so the same file reached through \\?\C:\... and C:\... shares one entry; also fixes empty stat-index writes under UNC shares, a spurious "stat index switched" warning on Windows, and a junction/symlink alias wrongly sharing its target's digest (#5035, thanks @Bortlesboat).
  • Fix: cache stat-index keys stay root-relative under a Windows long-path root, so a moved or cloned corpus keeps the portable-key fastpath (#5035, thanks @Vaibhav2824).
  • Fix: tests the TypeScript unicode fixture is written as UTF-8 on every platform, so byte offsets match the extractor on Windows (cp1252) hosts (#5064, thanks @ayushcodes10).
  • Fix: tests the hook-freshness source mock is normalized through os_long_path, so the read-error/stale branch is actually exercised on Windows (#5065, thanks @ayushcodes10).
  • Fix: tests the watch pending-queue test compares Path objects so / and \ separators compare equal on Windows (#5039, thanks @Yi-111-a).
  • Fix: extract an ambiguous Python import's placeholder node id is hashed from checkout-independent data (module name, scan-root-relative source file, location) instead of the absolute path, so the same project at a different path or a moved cache gets the same ids (#5045, thanks @Fardin7798).
  • Fix: yaml a template using CloudFormation intrinsic tags (!Ref, !GetAtt, !Sub) no longer fails to parse: a scoped permissive loader rebuilds each !-tagged node's shape without evaluating it, while !!python/... tags still raise and never execute (#5077, thanks @ayushcodes10).
  • Fix: watch a --watch incremental update rebuilds the full corpus when graph.json is missing, instead of writing a partial graph from the manifest alone (#5020, thanks @azizur100389).
  • Fix: watch a change to a JS/TS resolution input (tsconfig.json, jsconfig.json, a lockfile) triggers a full rebuild so importers pick up the new resolution, instead of leaving stale imports_from edges (#5020, thanks @azizur100389).
  • Fix: ingest two concurrent graphify add captures for the same URL no longer clobber each other: the capture file is created exclusively (O_EXCL) and a collision retries a fresh name, with the payload fetched once (#5020, thanks @azizur100389).
  • Fix: reflect a malformed entry in the learning overlay is skipped instead of crashing the whole load, and a legacy null-source entry is preserved as a source-less annotation (#5020, thanks @azizur100389).
  • Fix: global a malformed repo entry in the global manifest is dropped on its own, keeping the other tracked repos, and only a non-object root or repos map is backed up and reset (#5020, thanks @azizur100389).
  • Fix: query a graph freshly built on a subfolder is no longer flagged as a pre-#1504 build (which nagged a no-op extract --force): the legacy-id probe strips the .graphify_root offset before deriving file stems, and a genuine legacy graph is still caught (#5019, thanks @neumannpeter1231-lang).
  • Fix: tree graphify export tree recognises the src node alias (and file/path/filepath) so a graph carrying those keys renders a populated tree instead of an empty one; a concept-only graph still reports empty (#5030, thanks @Adityakk9031).
  • Fix: cli graphify provider add accepts --pricing-input=VALUE/--pricing-output=VALUE equals-syntax and rejects a non-numeric, non-finite or negative price with a clean error instead of a traceback or a poisoned cost estimate (#5031, thanks @Adityakk9031).

The AST cache schema is bumped to 40; warm caches re-run the affected Solidity and C# extractions. The Python and YAML fixes above need no bump (placeholder ids are resolved after the per-file cache, and previously-failing YAML was never cached).
