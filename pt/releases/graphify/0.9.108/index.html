#grafificar v0.9.108

  • Correção: csharp uma chamada de membro em um receptor digitado por um tipo minúsculo, prefixado por sublinhado ou semelhante a uma palavra-chave (_Pair, pair, um campo ou parâmetro de construtor primário assim digitado) agora é vinculada e uma chamada estática como pair.Create() é resolvida; namespace e receptores desconhecidos ainda falham no fechamento. Chamadas clássicas de método de extensão em receptores bool/char? também são vinculadas (#5174, obrigado @JensD-git).
  • Correção: java uma chamada por meio de um campo estático qualificado por classe (Service.INSTANCE.get() e uma cadeia Service.INSTANCE.other().m()) é resolvida por meio do tipo declarado desse campo; um local ou parâmetro que obscurece o nome da classe mantém essa ligação, e um campo de instância acessado como Type.field não é tratado como estático (#5149, obrigado @MaxWang007).
  • Correção: sql um corpo de rotina preserva junções de vírgula (FROM a, b) para que cada tabela seja lida e mantém um sufixo @dblink como um nó remoto distinto em vez de apontar a borda para uma tabela local com o mesmo nome (#5169, obrigado @mohitdixit02).
  • Correção: sql o alias de uma tabela derivada não analisada (FROM (SELECT ...) q onde a subconsulta falha ao analisar) não é mais mal interpretado como um nó de tabela; uma tabela real após a subconsulta não ser afetada (#5147, obrigado @Yi-111-a).
  • Correção: caminho graphify path prefere uma rota através de arquivos reais em vez de uma que desvia através de um hub de importação sem fonte (um stub de módulo externo ou stdlib) quando ambos são igualmente curtos e confiáveis; quando a única rota é através de um hub, ela ainda é retornada (#5153, obrigado @ayushcodes10).
  • Correção: report GRAPH_REPORT.md mantém o custo do token de extração de cost.json após um graphify update, em vez de redefini-lo para zero no caminho de reconstrução somente AST (#5154, obrigado @kevin9327).
  • Correção: ganchos o deslocamento de pesquisa é suavizado quando o gráfico pode estar obsoleto (alterações pendentes desde a última construção), espelhando o deslocamento de leitura, em vez de sempre dizer ao agente para consultar o gráfico; um arquivo genuinamente não indexado ainda recebe o empurrãozinho (# 5132, obrigado @ayushcodes10).
  • Correção: servir uma recarga de gráfico não para mais cada solicitação MCP: o novo gráfico é construído lateralmente e trocado atomicamente, de modo que solicitações simultâneas continuam sendo atendidas no gráfico atual em vez de bloquear toda a reconstrução, e uma única recarga em andamento é compartilhada em vez de reconstruída por garçom (#5177, obrigado @ayushcodes10).
  • Correção: consulta um filtro --context nomeando uma relação de herança (inherits, implements, extends) agora atinge arestas de herança que não carregam nenhum atributo de contexto, então a caminhada segue uma hierarquia de classes em vez de parar na semente; bordas sem contexto sem herança ainda são filtradas e o cabeçalho informa quando um filtro não corresponde a nenhuma borda (# 5178, obrigado @sunhouy).
  • Correção: sql Oracle [NON]EDITIONABLE PROCEDURE/FUNCTION/TRIGGER DDL é recuperado do nó ERROR em vez de gerar apenas um nó de arquivo; uma tabela ou rotina literalmente chamada editionable, e DDL não rotineiro, como EDITIONABLE VIEW, não são recuperados incorretamente (#5167, obrigado @Yi-111-a). O esquema de cache AST aumentou para 45; caches quentes executam novamente as extrações afetadas de C#, Java e SQL.

graphify v0.9.108

  • Fix: csharp a member call on a receiver typed by a lowercase, underscore-prefixed or keyword-like type (_Pair, pair, a field or primary-constructor parameter so typed) now binds, and a static call like pair.Create() resolves; namespace and unknown receivers still fail closed. Classic extension-method calls on bool/char? receivers also bind (#5174, thanks @JensD-git).
  • Fix: java a call through a class-qualified static field (Service.INSTANCE.get(), and a chain Service.INSTANCE.other().m()) resolves via that field's declared type; a local or parameter that shadows the class name keeps that binding, and an instance field accessed as Type.field is not treated as static (#5149, thanks @MaxWang007).
  • Fix: sql a routine body preserves comma joins (FROM a, b) so every table is read, and keeps a @dblink suffix as a distinct remote node instead of pointing the edge at a local same-named table (#5169, thanks @mohitdixit02).
  • Fix: sql an unparsed derived table's alias (FROM (SELECT ...) q where the subquery fails to parse) is no longer mis-read as a table node; a real table after the subquery is unaffected (#5147, thanks @Yi-111-a).
  • Fix: path graphify path prefers a route through real files over one that detours through a sourceless import hub (an external or stdlib module stub) when both are equally short and confident; when the only route is via a hub it is still returned (#5153, thanks @ayushcodes10).
  • Fix: report GRAPH_REPORT.md keeps the extraction token cost from cost.json after a graphify update, instead of resetting it to zero on the AST-only rebuild path (#5154, thanks @kevin9327).
  • Fix: hooks the search nudge softens when the graph may be stale (pending changes since the last build), mirroring the read nudge, instead of always telling the agent to query the graph; a genuinely unindexed file still gets the plain nudge (#5132, thanks @ayushcodes10).
  • Fix: serve a graph reload no longer stalls every MCP request: the new graph is built off to the side and swapped in atomically, so concurrent requests keep being served the current graph instead of blocking for the whole rebuild, and a single in-flight reload is shared rather than rebuilt per waiter (#5177, thanks @ayushcodes10).
  • Fix: query a --context filter naming a heritage relation (inherits, implements, extends) now reaches heritage edges that carry no context attribute, so the walk follows a class hierarchy instead of stopping at the seed; non-heritage context-less edges are still filtered out, and the header reports when a filter matched no edges (#5178, thanks @sunhouy).
  • Fix: sql Oracle [NON]EDITIONABLE PROCEDURE/FUNCTION/TRIGGER DDL is recovered from the ERROR node instead of yielding only a file node; a table or routine literally named editionable, and non-routine DDL such as EDITIONABLE VIEW, are not mis-recovered (#5167, thanks @Yi-111-a). The AST cache schema is bumped to 45; warm caches re-run the affected C#, Java and SQL extractions.
