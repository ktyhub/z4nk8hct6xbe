#grafificar v0.9.113

  • Alteração: embalagem o mínimo de Python agora é 3.11.5 (era 3.11), e a sopa está fixada em 4.1.1 para cada intérprete. as versões corrigidas do Soupsieve exigem 3.11.5, portanto, aumentar o piso limpa os avisos do Soupsieve abertos (ReDoS e recursão/polinomial-DoS no analisador de seletor CSS, alcançados transitivamente por meio de beautifulsoup4 nos extras opcionais svg/all/pdf). As instalações em Python 3.11.0-3.11.4 continuam resolvendo para 0.9.112; todos no 3.11.5 e superior não são afetados (#5301, obrigado @TPAteeq).
  • Correção: métodos ruby de uma classe ou módulo cujos nomes diferem apenas por um _ inicial/final ou por caso (_read_attribute/read_attribute, _where!/where!), incluindo aqueles em um class << self, obtêm ids de nó distintos em vez de um engolir o outro (#5292, obrigado @rohit-jsfreaky).
  • Correção: funções de campo de tabela lua cujos nomes diferem apenas por um _ inicial/final (M._load/M.load, Runner:_start/Runner:start) obtêm ids de nó distintos; M.f/M:f ainda nomeia um campo (#5294, obrigado @rohit-jsfreaky).
  • Correção: membros scala cujos nomes diferem apenas por um _ inicial, um sufixo setter _= ou caso (_enter/enter, size/size_=, forEach/foreach), inclusive em uma classe e seu objeto complementar, obtenha ids de nó distintos (#5296, obrigado @rohit-jsfreaky).
  • Correção: elixir defs cujos nomes diferem apenas por um _ inicial/final, um sufixo !/? ou maiúsculas e minúsculas (_name/name, get/get!, __schema__/schema) obtêm ids de nó distintos, portanto, uma chamada get! não chega mais a get (#5298, obrigado @rohit-jsfreaky).
  • Correção: rust o argumento de tipo de uma característica prelúdio (Celsius em impl From<Celsius> ou um limite T: Into<Celsius>) é lido como uma referência de argumento genérico em vez de ser confundido com a característica em si, então ele não emite mais uma borda implements/inherits errada (#5332, obrigado @azeemshaik025).
  • Correção: go uma chamada de membro é mantida quando outro pacote no corpus nomeia um tipo de arquivo irmão: o stub sem fonte em colisão é movido para seu próprio id em vez de salgar a declaração real e tornar órfãs suas bordas de método, que haviam descartado a chamada (#5304, obrigado @Yi-111-a).
  • Correção: ruby um método escrito inline após um modificador de acesso (private def validate, private_class_method def self.audit) mantém sua associação à classe envolvente em vez de ser emitido como uma função em nível de arquivo, então as chamadas para ele resolvem o método (#5310, obrigado @Synvoya).
  • Correção: swift uma chamada que é o último operando de uma expressão de operador (base + bonus(), !isEmpty()), que a gramática analisa como o receptor, é extraída em vez de descartada (#5311, obrigado @Synvoya).
  • Correção: kotlin uma chamada sob um operador de prefixo (!isReady(), -compute()) é extraída em vez de descartada, incluindo prefixos empilhados e !obj.ready() (#5312, obrigado @Synvoya).
  • Correção: vbnet um parâmetro com um valor padrão é contado como opcional, independentemente da ordem do modificador (ByVal Optional x As Integer = 0, ByRef Optional ...), portanto, a aridade do método e a resolução de sobrecarga estão corretas (#5320, obrigado @Deepjyoti-Sarmah).
  • Correção: as identidades de inclusão cpp são mantidas quando o cache AST está em outra unidade que não a de origem (um caso de unidade cruzada do Windows em que os.path.relpath foi gerado e cada arquivo obteve uma chave vazia), portanto, a dobragem de declaração/definição ainda funciona; o caminho normal da mesma unidade permanece inalterado (# 5145, obrigado @ Ayushraj06 bits).
  • Correção: llm novas tentativas de geração de rótulos mantêm um limite de saída de 512 tokens, de modo que o passe de recuperação de comunidade única não fique mais faminto abaixo do lote do qual está se recuperando; um GRAPHIFY_MAX_OUTPUT_TOKENS explícito ainda substitui (#2086, obrigado @Synvoya).
  • Correção: ruby um include/prepend/extend de um módulo escrito dentro de um bloco class << self emite sua borda mixes_in, em vez de ser perdida porque apenas instruções diretas do corpo da classe foram verificadas (#5317, obrigado @Synvoya).
  • Correção: python uma classe com uma base parametrizada (class C(Base[T]), class D(Mapping[str, int])) emite a borda inherits para o tipo base e é percorrida para chamadas de métodos herdados, em vez de ser descartada e marcada como opaca; um argumento genérico aninhado, uma base de chamada e mod.Base[T] ainda não são tratados como pais (#5318, obrigado @Synvoya).
  • Correção: tsconfig um tsconfig.json extends e o mapeamento exato de compilerOptions.paths são resolvidos para a configuração/arquivo verificado real que eles nomeiam, em vez de um stub pendente; uma extensão de pacote não corpus, um caminho curinga e uma extensão circular falha ao fechar (# 5223, obrigado @Deepjyoti-Sarmah).
  • Correção: cpp uma declaração de encaminhamento de classe inacessível (que não atinge o caminho de inclusão) não bloqueia mais a dobra da declaração de um membro em sua definição fora de linha; casos genuinamente ambíguos (um modelo ou uma segunda definição) ainda permanecem separados (#5337, obrigado @winesoft-namjin-yun).
  • Correção: extrair uma importação que tem como alvo um cabeçalho envolvido em uma colisão de ID não é mais redirecionada incondicionalmente para a variante do cabeçalho: o redirecionamento é controlado pela família de idiomas do arquivo de importação, portanto, um Python import foo ao lado de um foo.h/foo.py em colisão mantém sua vantagem para foo.py em vez de ser descartado como linguagem cruzada (# 5328, obrigado @sdivyanshu90).
  • Correção: servir uma consulta que é um ID de nó exato é resolvida diretamente para esse nó, em vez de ser superada por um nó diferente que compartilha seu caminho de origem tokenizado (#5343, obrigado @Ayushraj06-bit). O esquema de cache AST aumentou para 49; caches quentes executam novamente as extrações afetadas de Ruby, Lua, Scala, Elixir, Rust, Swift, Kotlin, VB.NET, Python e TypeScript-config.

Original em inglês / English original

graphify v0.9.113

  • Change: packaging the minimum Python is now 3.11.5 (was 3.11), and soupsieve is pinned to 4.1.1 for every interpreter. soupsieve's patched releases require 3.11.5, so raising the floor clears the open soupsieve advisories (ReDoS and recursion/polynomial-DoS in the CSS selector parser, reached transitively through beautifulsoup4 in the optional svg/all/pdf extras). Installs on Python 3.11.0-3.11.4 keep resolving to 0.9.112; everyone on 3.11.5 and up is unaffected (#5301, thanks @TPAteeq).
  • Fix: ruby methods of one class or module whose names differ only by a leading/trailing _ or by case (_read_attribute/read_attribute, _where!/where!), including those in a class << self, get distinct node ids instead of one swallowing the other (#5292, thanks @rohit-jsfreaky).
  • Fix: lua table-field functions whose names differ only by a leading/trailing _ (M._load/M.load, Runner:_start/Runner:start) get distinct node ids; M.f/M:f still name one field (#5294, thanks @rohit-jsfreaky).
  • Fix: scala members whose names differ only by a leading _, a _= setter suffix, or case (_enter/enter, size/size_=, forEach/foreach), including across a class and its companion object, get distinct node ids (#5296, thanks @rohit-jsfreaky).
  • Fix: elixir defs whose names differ only by a leading/trailing _, a !/? suffix, or case (_name/name, get/get!, __schema__/schema) get distinct node ids, so a get! call no longer lands on get (#5298, thanks @rohit-jsfreaky).
  • Fix: rust a prelude trait's type argument (Celsius in impl From<Celsius> or a T: Into<Celsius> bound) is read as a generic-argument reference instead of being mistaken for the trait itself, so it no longer emits a wrong implements/inherits edge (#5332, thanks @azeemshaik025).
  • Fix: go a member call is kept when another package in the corpus names a sibling-file type: the colliding sourceless stub is moved to its own id instead of salting the real declaration and orphaning its method edges, which had dropped the call (#5304, thanks @Yi-111-a).
  • Fix: ruby a method written inline after an access modifier (private def validate, private_class_method def self.audit) keeps its membership of the enclosing class instead of being emitted as a file-level function, so calls to it resolve to the method (#5310, thanks @Synvoya).
  • Fix: swift a call that is the last operand of an operator expression (base + bonus(), !isEmpty()), which the grammar parses as the callee, is extracted instead of dropped (#5311, thanks @Synvoya).
  • Fix: kotlin a call under a prefix operator (!isReady(), -compute()) is extracted instead of dropped, including stacked prefixes and !obj.ready() (#5312, thanks @Synvoya).
  • Fix: vbnet a parameter with a default value is counted as Optional regardless of modifier order (ByVal Optional x As Integer = 0, ByRef Optional ...), so method arity and overload resolution are correct (#5320, thanks @Deepjyoti-Sarmah).
  • Fix: cpp include identities are kept when the AST cache is on another drive than the source (a Windows cross-drive case where os.path.relpath raised and every file got an empty key), so declaration/definition folding still works; the normal same-drive path is unchanged (#5145, thanks @Ayushraj06-bit).
  • Fix: llm label-generation retries keep a 512-token output floor, so the single-community recovery pass is no longer starved below the batch it is recovering from; an explicit GRAPHIFY_MAX_OUTPUT_TOKENS still overrides (#2086, thanks @Synvoya).
  • Fix: ruby an include/prepend/extend of a module written inside a class << self block emits its mixes_in edge, instead of being missed because only direct class-body statements were scanned (#5317, thanks @Synvoya).
  • Fix: python a class with a parameterized base (class C(Base[T]), class D(Mapping[str, int])) emits the inherits edge to the base type and is walked for inherited-method calls, instead of being dropped and marked opaque; a nested generic argument, a call base, and mod.Base[T] are still not treated as parents (#5318, thanks @Synvoya).
  • Fix: tsconfig a tsconfig.json extends and exact compilerOptions.paths mapping resolve to the real scanned config/file they name rather than a dangling stub; a non-corpus package extends, a wildcard path, and a circular extends fail closed (#5223, thanks @Deepjyoti-Sarmah).
  • Fix: cpp an unreachable class forward declaration (one no include path reaches) no longer blocks the fold of a member's declaration into its out-of-line definition; genuinely ambiguous cases (a template or a second definition) still stay separate (#5337, thanks @winesoft-namjin-yun).
  • Fix: extract an import that targets a header involved in an id collision is no longer unconditionally repointed to the header variant: the repoint is gated by the importing file's language family, so a Python import foo beside a colliding foo.h/foo.py keeps its edge to foo.py instead of being dropped as cross-language (#5328, thanks @sdivyanshu90).
  • Fix: serve a query that is an exact node id resolves straight to that node instead of being out-ranked by a different node that shares its tokenized source path (#5343, thanks @Ayushraj06-bit).

The AST cache schema is bumped to 49; warm caches re-run the affected Ruby, Lua, Scala, Elixir, Rust, Swift, Kotlin, VB.NET, Python and TypeScript-config extractions.
