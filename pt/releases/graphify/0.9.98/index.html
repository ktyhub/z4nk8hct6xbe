#grafificar v0.9.98 ##0.9.98 (30/10/2026)

  • Correção: construir quando arestas duplicadas de mesma relação entram em colapso, a origem da cópia perdida (confiança mais fraca) é mantida em uma lista also_seen na aresta sobrevivente em vez de ser descartada, para que a evidência mais fraca não seja perdida silenciosamente; o campo é serializado para graph.json e é idempotente em reconstruções (#4881, #4891, obrigado @SyedFahad7).
  • Correção: csharp um nó de método C# é rotulado com seu tipo proprietário (MyClass.Method) em vez de um Method simples, portanto, métodos com o mesmo nome entre tipos são distinguíveis; os ids e bordas dos nós permanecem inalterados (somente rótulo de exibição) (#4883, #4889, obrigado @SyedFahad7).
  • Talento: path graphify path e a saída do caminho mais curto do MCP relatam a confiança geral do caminho como o salto mais fraco (nível de confiança mais baixo, depois pontuação mais baixa), com uma linha de resumo nomeando esse salto (#4885, #4892, obrigado @SyedFahad7).
  • Correção: caminho um endpoint escrito Type.Member resolve para o nó membro, não para o tipo que o contém, então graphify path "Exporter.Run" "PdfReport.Build" encontra a rota de chamada real; nomes exatos e nomes de arquivos ainda vencem primeiro, e um Type.Member cujo membro não existe falha no fechamento (#4884, #4893, obrigado @SyedFahad7).
  • Correção: extract ids de arquivo e ids por declaração são mantidos distintos, então uma declaração de nível superior cujo nome corresponde ao seu arquivo (por exemplo class Js em a.js) não é mais descartada silenciosamente em uma colisão de id; referências de arquivos cruzados vinculam-se ao id declarado (#4854, #4857, obrigado @Deepjyoti-Sarmah).
  • Correção: dedup quando uma menção de documento de arquivo cruzado e um nó AST colidem em um ID de definição, o nó AST mantém o ID em vez de ser descartado, enquanto o enriquecimento do mesmo arquivo, gêmeos de extensão e casos de definidor único são deixados como estão (#4859, #4872, obrigado @TanmayShah29; abordagem duplicada em #4871 por @ayushcodes10).
  • Correção: build um ciclo de importação de dois arquivos (a imports b, b imports a) é relatado na compilação não direcionada padrão, e o carimbo é limpo corretamente em reconstruções incrementais/de observação para que uma importação descartada não deixe mais um ciclo obsoleto (#4839, #4841, obrigado @Mpasha17; abordagem duplicada em #4852 por @legendteddy).
  • Correção: extrair uma importação JS/TS relativa carregando um sufixo ?query ou #fragment (./mod.js?v=1) resolve para o módulo real em vez de um nó fantasma; As importações do nó #subpath permanecem intactas (#4860, #4876, obrigado @Jitendarmahara; abordagem duplicada em #4869 por @mirzasnowy).
  • Correção: go um receptor vinculado a var x = T{} ou var x = &T{} (um literal composto) é digitado como T, correspondendo ao formato x := T{}, então seu membro chama resolve (#4843, obrigado @ayushcodes10).
  • Correção: verilog um construtor de classe SystemVerilog (function new(...), que não possui tipo de retorno) obtém seu próprio nó, borda method e referências de tipo de parâmetro (#4848, obrigado @ayushcodes10).
  • Correção: powershell using module/using assembly elimina uma extensão de arquivo real (Helpers.psm1 para helpers), mas mantém um nome de módulo pontilhado sem extensão intacta (Az.Accounts) (#4847, obrigado @ayushcodes10).
  • Correção: solididade um conjunto using {a, b} for T de função livre emite bordas uses para cada função nomeada, não apenas o formulário using Lib for T de biblioteca única (#4846, obrigado @ayushcodes10).
  • Correção: commonlisp um defclass cuja superclasse é definida posteriormente no mesmo arquivo se liga a esse nó local em vez de cunhar um stub sem fonte (#4845, obrigado @ayushcodes10).
  • Correção: pascal inherited e inline formam blocos de componentes (.lfm/.dfm) são reconhecidos, então um bloco object posterior mantém seu pai correto em vez de ser re-parentado por uma pilha de aninhamento corrompida (#4844, obrigado @ayushcodes10).
  • Correção: servir quando dois nós se vinculam em uma pesquisa e diferem apenas por caso, aquele escrito exatamente como consultado vence (os outros permanecem acessíveis um nível abaixo) em vez de cada ortografia ser recusada como ambígua (#4870, obrigado @nothariharan).
  • Correção: exportar as chaves de exportação de texto Cypher MERGE no ID do nó estável e definir o rótulo separadamente, portanto, reimportar após uma mudança de rótulo atualiza o nó em vez de criar uma duplicata (#4878, obrigado @oleksii-tumanov).
  • Correção: pdf o cache de texto convertido é inserido no caminho de origem resolvido, portanto, dois PDFs com o mesmo nome relativo em raízes diferentes não envenenam um ao outro em um processo (#4851, obrigado @xunguangzlj-cloud).

graphify v0.9.98

0.9.98 (2026-10-30)

  • Fix: build when duplicate same-relation edges collapse, the losing (weaker-confidence) copy's provenance is kept in an also_seen list on the surviving edge instead of being discarded, so the weaker evidence is not silently lost; the field is serialized to graph.json and is idempotent across rebuilds (#4881, #4891, thanks @SyedFahad7).
  • Fix: csharp a C# method node is labelled with its owning type (MyClass.Method) instead of a bare Method, so same-named methods across types are distinguishable; node ids and edges are unchanged (display label only) (#4883, #4889, thanks @SyedFahad7).
  • Feat: path graphify path and the MCP shortest-path output report the overall path confidence as the weakest hop (lowest confidence tier, then lowest score), with a summary line naming that hop (#4885, #4892, thanks @SyedFahad7).
  • Fix: path an endpoint written Type.Member resolves to the member node, not the containing type, so graphify path "Exporter.Run" "PdfReport.Build" finds the real call route; exact names and file names still win first, and a Type.Member whose member does not exist fails closed (#4884, #4893, thanks @SyedFahad7).
  • Fix: extract file ids and per-declaration ids are kept distinct, so a top-level declaration whose name matches its file (for example class Js in a.js) is no longer silently dropped on an id collision; cross-file references bind to the declared id (#4854, #4857, thanks @Deepjyoti-Sarmah).
  • Fix: dedup when a cross-file document mention and an AST node collide on a defining id, the AST node keeps the id instead of being dropped, while same-file enrichment, extension twins and single-definer cases are left as-is (#4859, #4872, thanks @TanmayShah29; duplicate approach in #4871 by @ayushcodes10).
  • Fix: build a two-file import cycle (a imports b, b imports a) is reported in the default undirected build, and the stamp is cleared correctly on incremental/watch rebuilds so a dropped import no longer leaves a stale cycle (#4839, #4841, thanks @Mpasha17; duplicate approach in #4852 by @legendteddy).
  • Fix: extract a relative JS/TS import carrying a ?query or #fragment suffix (./mod.js?v=1) resolves to the real module instead of a phantom node; Node #subpath imports are left untouched (#4860, #4876, thanks @Jitendarmahara; duplicate approach in #4869 by @mirzasnowy).
  • Fix: go a receiver bound with var x = T{} or var x = &T{} (a composite literal) is typed as T, matching the x := T{} form, so its member calls resolve (#4843, thanks @ayushcodes10).
  • Fix: verilog a SystemVerilog class constructor (function new(...), which has no return type) gets its own node, method edge and parameter-type references (#4848, thanks @ayushcodes10).
  • Fix: powershell using module/using assembly drops a real file extension (Helpers.psm1 to helpers) but keeps a dotted module name with no extension intact (Az.Accounts) (#4847, thanks @ayushcodes10).
  • Fix: solidity a free-function using {a, b} for T set emits uses edges for each named function, not just the single-library using Lib for T form (#4846, thanks @ayushcodes10).
  • Fix: commonlisp a defclass whose superclass is defined later in the same file binds to that local node instead of minting a sourceless stub (#4845, thanks @ayushcodes10).
  • Fix: pascal inherited and inline form component blocks (.lfm/.dfm) are recognised, so a later object block keeps its correct parent instead of being re-parented by a corrupted nesting stack (#4844, thanks @ayushcodes10).
  • Fix: serve when two nodes tie in a lookup and differ only by case, the one spelled exactly as queried wins (the others stay reachable one tier down) instead of every spelling being refused as ambiguous (#4870, thanks @nothariharan).
  • Fix: export the Cypher text export keys MERGE on the stable node id and sets the label separately, so re-importing after a label change updates the node instead of creating a duplicate (#4878, thanks @oleksii-tumanov).
  • Fix: pdf the converted-text cache is keyed on the resolved source path, so two PDFs with the same relative name in different roots do not poison each other within one process (#4851, thanks @xunguangzlj-cloud).
