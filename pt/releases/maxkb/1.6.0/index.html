MaxKB v1.6.0

Highlights

  • OpenAI-compatible chat API — PR #1128 adds standard OpenAI-format conversations, effectively letting MaxKB act as a drop-in endpoint for existing OpenAI SDK clients and tooling. Watch the request path: early adopters hit an error when stream=false, fixed in PR #1289, so exercise both streaming and non-streaming modes before routing production traffic through it.
  • Reranking and multi-path recall — PR #1121 brings rerank models into retrieval, so you can fuse multiple recall lanes and reorder candidates before they reach the LLM — a direct, configuration-level lever on RAG answer quality. Rerankers can now come from Alibaba Cloud Bailian, Xinference, or local models; expect to re-tune your retrieval top-k once a reranker sits in the loop.
  • Voice Q&A and speech providers — PR #1120 enables voice-based Q&A, backed by new ASR/TTS integrations for Doubao, iFlytek Spark, and OpenAI in PR #1102. For hands-free or multilingual entry points this removes a separate speech layer, but it adds provider credentials and per-request audio cost to the deployment.
  • Simple-app configuration changes — PR #1182 restructures simple apps: prompts split into variants with and without knowledge-base citations, question optimization moves into the linked-knowledge-base parameters (with its own prompt), and "multi-turn dialogue" becomes a configurable history-record count. Treat this as a behavioral change: re-open and re-save existing simple apps after upgrading, since prompt and memory semantics shift until you review them. PR #1203 also adds system variables for history chat and conversation ID.
  • Knowledge base ingestion and bulk operations — Excel/CSV uploads arrive in PR #1083 and PDF chapter-aware segmentation in PR #1124, widening what you can index. The operationally significant wins are batch re-vectorization and bulk question-to-segment association (PR #1235): when you swap embedding models, re-vectorize in bulk instead of re-uploading documents.
  • Richer output and controls — ECharts and HTML rendering (PR #1173, #1175) lets apps emit charts and full pages rather than plain markdown, while custom global variables (PR #1146) and function permission/status controls (PR #1189) expand orchestration options. The max output-token ceiling also rises to 100k and becomes user-controlled (PR #1192) — useful for long generations, but set explicit budgets to avoid runaway latency and cost.

No breaking changes in this release.
