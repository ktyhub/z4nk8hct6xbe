MaxKB v1.5.0

Highlights

  • Reusable functions in workflows — PR #1002 introduces a function library and function nodes for advanced applications, allowing shared transformations, validation, and custom logic to run inside workflows instead of being duplicated across prompts or nodes.
  • Broader model control and provider support — Applications can now set temperature and max_tokens (#974), making response behavior and output limits tunable per app. PR #959 adds integrations for Bedrock, Doubao, Tencent Hunyuan, vLLM, and Xinference; the latter two are particularly relevant to self-hosted inference deployments.
  • Security-driven upgrade recommended — PR #950 fixes a Django JSONField SQL-injection vulnerability, CVE-2024-42005. Prioritize this release if your MaxKB instance is network-accessible, even if the new workflow features are not needed.
  • More robust knowledge-base ingestion — Vectorization and PDF segmentation are improved (#1001, #989), PDF uploads are recognized correctly again (#1046), and individual segments no longer fail above 100,000 characters (#1031). The fix for direct-answer mode ensures a similarity of 0.000 is actually persisted; changed chunking may affect retrieval quality, so recheck results on representative documents.
  • Application and administration improvements — App cloning (#992), automatic trimming of leading/trailing spaces in app names (#1008), corrected chat-log exports, and workflow prompt selection/zoom fixes (#1058) reduce operational friction. X-Pack also gains CAS and OIDC authentication (#955), requiring identity-provider configuration when enabled.
  • Breaking changes — None reported.
