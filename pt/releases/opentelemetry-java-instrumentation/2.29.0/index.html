opentelemetry-instrumentação java v2.29.0

Esta versão tem como alvo o OpenTelemetry SDK 1.63.0.

Observe que muitos artefatos têm o sufixo -alpha anexado ao seu número de versão, refletindo que eles continuarão a ter alterações significativas. Consulte VERSIONING.md para obter mais detalhes.

⚠️ Mudanças importantes em APIs não estáveis

  • Alterar o tipo de retorno para JmxTelemetry.start(...) APIs. (#18782)
  • A telemetria experimental do pacote de tempo de execução agora emite valores package.checksum_algorithm=SHA-256 e package.checksum de 64 caracteres em vez de somas de verificação SHA1. (#18846)

🚫 Depreciações

  • Renomeie as chaves de contexto de criação de log comuns para otel.instrumentation.common.logging.trace-id-key, otel.instrumentation.common.logging.span-id-key e otel.instrumentation.common.logging.trace-flags-key, mantendo os nomes de propriedades antigos obsoletos. (#18851)
  • Renomear os sistemas alvo kafka-broker e kafka-connect JMX para experimental-kafka-broker e experimental-kafka-connect; os nomes antigos ainda funcionam por enquanto e registram um aviso. (#18971)

🌟 Nova instrumentação javaagent

  • Adicione instrumentação SOFARPC 5.4 que emite RPC client e spans e métricas de servidor. (#15589)
  • Adicionar instrumentação Javaagent para HBase client 2.0.0 até 2.5.0. (#18253)

📈 Melhorias

  • Adicione suporte opcional para emissão de exceções de solicitação HTTP como sinais de log com otel.semconv.exception.signal.preview=logs. (#16259)
  • Adicionar instrumentação Javaagent opentelemetry-api-1.63 para OpenTelemetry API 1.63 e opentelemetry-api-incubator 1.63. (#18911)
  • Adicione otel.semconv-stability.v3-preview como um substituto para a configuração declarativa de estabilidade semconv v3_preview. (#18936)
  • Atualizar a opção de convenção semântica de banco de dados estável experimental (otel.semconv-stability.opt-in=database) em instrumentações de banco de dados, incluindo nomes de span e atributos db.*. (#18808, #18853, #18920, #18922, #18926, #18930, #18970, #18979, #18980, #18984, #18985, #18986, #18987, #18989, #18990, #18992, #18993, #19004, #19005)
  • Capture texto de consulta e parametrização para instruções em lote do Cassandra. (#18964)
  • Mantenha opentelemetry-api e opentelemetry-instrumentation-annotations habilitados em otel.instrumentation.common.v3-preview mesmo quando default-enabled=false. (#18792)
  • Quando otel.instrumentation.common.v3-preview está habilitado, as instrumentações afetadas emitem atributos de identidade user.* em vez de enduser.*. (#18795)
  • Desative as métricas Kafka client por padrão quando otel.instrumentation.common.v3-preview=true. (#18828)
  • Reconhecer prefixos de URL JDBC do Amazon Aurora DSQL e do AWS wrapper ao analisar metadados de conexão JDBC. (#18831)
  • Definir versões de instrumentação em escopos de medidores emitidos. (#18866)
  • Execute a instrumentação @WithSpan após outras instrumentações para que outros conselhos possam anexar atributos ao intervalo ativo. (#18874)
  • Emite falhas do banco de dados client como logs db.client.operation.exception quando otel.semconv.exception.signal.preview está habilitado. (#18889)
  • Emite exceções RPC como registros de log quando otel.semconv.exception.signal.preview=logs está habilitado. (#18890)
  • Emite exceções de mensagens como registros de log em otel.semconv.exception.signal.preview. (#18891)
  • Emitir registros de log faas.invocation.exception para exceções FaaS quando otel.semconv.exception.signal.preview=logs estiver habilitado. (#18892)
  • Emite logs gen_ai.client.operation.exception para bate-papo OpenAI e falhas de incorporação quando otel.semconv.exception.signal.preview=logs está habilitado. (#18893)
  • Emite falhas de solicitação AWS SDK como registros de log rpc.client.call.exception quando otel.semconv.exception.signal.preview=logs está habilitado. (#18894)
  • A configuração declarativa agora oferece suporte à seleção de convenção semântica por domínio usando configurações semconv.version, semconv.experimental e semconv.dual_emit. (#18908)
  • Quando otel.instrumentation.common.v3-preview estiver ativado, use otel.semconv-stability.preview em vez de otel.semconv-stability.opt-in para aceitar as convenções semânticas não estáveis service.peer e rpc. (#18914)
  • Desative a instrumentação @WithSpan das corrotinas Kotlin por padrão quando otel.instrumentation.common.v3-preview=true. (#18919)
  • Use o caminho com reconhecimento de resumo em SqlQueryAnalyzer.analyze() quando otel.instrumentation.common.v3-preview estiver habilitado. (#18921)
  • Quando otel.instrumentation.common.v3-preview está ativado, os nomes de configuração de sanitização JDBC/db obsoletos são ignorados em favor de db.query_sanitization.enabled. (#18934)
  • Incluir jvm.gc.cause nas métricas de duração do GC quando otel.instrumentation.common.v3-preview estiver habilitado. (#18967)
  • Emitir métricas de duração para operações de transação JDBC COMMIT e ROLLBACK. (#19003)
  • Use uma classe InstrumentationVersion gerada no OkHttp 3.0 em vez de ler as propriedades da versão incorporada, evitando violações de leitura de disco do Android StrictMode. (#19006)
  • Adicionar atributos de extensão de detalhes do thread para configuração declarativa do Spring Starter quando distribution.spring_starter.thread_details_enabled estiver definido. (#19008)

  • Preservar o contexto atual para futuras execuções de comandos Redisson para que as operações assíncronas continuem o rastreamento ativo. (#18701)
  • Impedir que o agente Pulsar crie intervalos de recebimento duplicados para consumidores multitópicos. (#18771)
  • Corrigido um travamento nas solicitações de streaming do Ktor client para que os intervalos terminem imediatamente com o Ktor 3.5.0. (#18781)
  • Corrigido um Bedrock converseStream NullPointerException quando uma chamada de ferramenta possui argumentos vazios. (#18783)
  • Capture o ID da mensagem Pulsar mais cedo para que os intervalos do produtor possam registrá-lo de forma confiável. (#18803)
  • Corrija a instrução SQLite JDBC e a instrumentação de instruções preparadas para que as conexões SQLite produzam intervalos SQL e captura de parâmetros. (#18885)
  • Correção das chaves de configuração declarativas do Logback MDC para que as configurações do otel.instrumentation/development.java.* sejam aplicadas corretamente. (#18924)
  • Correção da limpeza de senha SQL para destinos DDL de maiúsculas e minúsculas, como create table e alter table. (#18927)
  • Os logs emitidos por meio de registradores Log4j assíncronos agora mantêm o OpenTelemetry Context do thread do aplicativo em vez de retornar à recuperação somente de span. (#18937)
  • Evite erros de instrumentação ao carregar redis.clients.jedis.Jedis, BinaryJedis e UnifiedJedis. (#19000)
  • Execute retornos de chamada assíncronos do OpenSearch com o contexto pai da solicitação. (#19027)

opentelemetry-java-instrumentation v2.29.0

This release targets the OpenTelemetry SDK 1.63.0.

Note that many artifacts have the -alpha suffix attached to their version number, reflecting that they will continue to have breaking changes. Please see VERSIONING.md for more details.

⚠️ Breaking changes to non-stable APIs

  • Change the return type for JmxTelemetry.start(...) APIs. (#18782)
  • Experimental runtime package telemetry now emits package.checksum_algorithm=SHA-256 and 64-character package.checksum values instead of SHA1 checksums. (#18846)

🚫 Deprecations

  • Rename the common logging context keys to otel.instrumentation.common.logging.trace-id-key, otel.instrumentation.common.logging.span-id-key, and otel.instrumentation.common.logging.trace-flags-key, while keeping the old property names deprecated. (#18851)
  • Rename the kafka-broker and kafka-connect JMX target systems to experimental-kafka-broker and experimental-kafka-connect; the old names still work for now and log a warning. (#18971)

🌟 New javaagent instrumentation

  • Add SOFARPC 5.4 instrumentation that emits RPC client and server spans and metrics. (#15589)
  • Add Javaagent instrumentation for HBase client 2.0.0 through 2.5.0. (#18253)

📈 Enhancements

  • Add opt-in support for emitting HTTP request exceptions as log signals with otel.semconv.exception.signal.preview=logs. (#16259)
  • Add opentelemetry-api-1.63 Javaagent instrumentation for OpenTelemetry API 1.63 and opentelemetry-api-incubator 1.63. (#18911)
  • Add otel.semconv-stability.v3-preview as a fallback for the declarative v3_preview semconv stability setting. (#18936)
  • Update the experimental stable database semantic-convention opt-in (otel.semconv-stability.opt-in=database) across database instrumentations, including span names and db.* attributes. (#18808, #18853, #18920, #18922, #18926, #18930, #18970, #18979, #18980, #18984, #18985, #18986, #18987, #18989, #18990, #18992, #18993, #19004, #19005)
  • Capture query text and parameterization for Cassandra batch statements. (#18964)
  • Keep opentelemetry-api and opentelemetry-instrumentation-annotations enabled under otel.instrumentation.common.v3-preview even when default-enabled=false. (#18792)
  • When otel.instrumentation.common.v3-preview is enabled, affected instrumentations emit user.* identity attributes instead of enduser.* ones. (#18795)
  • Disable Kafka client metrics by default when otel.instrumentation.common.v3-preview=true. (#18828)
  • Recognize Amazon Aurora DSQL and AWS wrapper JDBC URL prefixes when parsing JDBC connection metadata. (#18831)
  • Set instrumentation versions on emitted Meter scopes. (#18866)
  • Run @WithSpan instrumentation after other instrumentations so other advice can attach attributes to the active span. (#18874)
  • Emit database client failures as db.client.operation.exception logs when otel.semconv.exception.signal.preview is enabled. (#18889)
  • Emit RPC exceptions as log records when otel.semconv.exception.signal.preview=logs is enabled. (#18890)
  • Emit messaging exceptions as log records under otel.semconv.exception.signal.preview. (#18891)
  • Emit faas.invocation.exception log records for FaaS exceptions when otel.semconv.exception.signal.preview=logs is enabled. (#18892)
  • Emit gen_ai.client.operation.exception logs for OpenAI chat and embeddings failures when otel.semconv.exception.signal.preview=logs is enabled. (#18893)
  • Emit AWS SDK request failures as rpc.client.call.exception log records when otel.semconv.exception.signal.preview=logs is enabled. (#18894)
  • Declarative configuration now supports per-domain semantic-convention selection using semconv.version, semconv.experimental, and semconv.dual_emit settings. (#18908)
  • When otel.instrumentation.common.v3-preview is enabled, use otel.semconv-stability.preview instead of otel.semconv-stability.opt-in to opt in to the nonstable service.peer and rpc semantic conventions. (#18914)
  • Disable Kotlin coroutines @WithSpan instrumentation by default when otel.instrumentation.common.v3-preview=true. (#18919)
  • Use the summary-aware path in SqlQueryAnalyzer.analyze() when otel.instrumentation.common.v3-preview is enabled. (#18921)
  • When otel.instrumentation.common.v3-preview is enabled, deprecated JDBC/db sanitization config names are ignored in favor of db.query_sanitization.enabled. (#18934)
  • Include jvm.gc.cause on GC duration metrics when otel.instrumentation.common.v3-preview is enabled. (#18967)
  • Emit duration metrics for JDBC transaction operations COMMIT and ROLLBACK. (#19003)
  • Use a generated InstrumentationVersion class in OkHttp 3.0 instead of reading embedded version properties, avoiding Android StrictMode disk-read violations. (#19006)
  • Add thread details span attributes for declarative Spring starter configuration when distribution.spring_starter.thread_details_enabled is set. (#19008)

🛠️ Bug fixes

  • Preserve the current context for Redisson command execution futures so async operations continue the active trace. (#18701)
  • Stop the Pulsar agent from creating duplicate receive spans for multi-topic consumers. (#18771)
  • Fix a hang in Ktor client streaming requests so spans end promptly with Ktor 3.5.0. (#18781)
  • Fix a Bedrock converseStream NullPointerException when a tool call has empty arguments. (#18783)
  • Capture the Pulsar message ID earlier so producer spans can record it reliably. (#18803)
  • Fix SQLite JDBC statement and prepared-statement instrumentation so SQLite connections produce SQL spans and parameter capture. (#18885)
  • Fix Logback MDC declarative configuration keys so otel.instrumentation/development.java.* settings apply correctly. (#18924)
  • Fix SQL password sanitization for mixed-case DDL targets like create table and alter table. (#18927)
  • Logs emitted through async Log4j loggers now keep the application thread's OpenTelemetry Context instead of falling back to span-only recovery. (#18937)
  • Avoid instrumentation errors when loading redis.clients.jedis.Jedis, BinaryJedis, and UnifiedJedis. (#19000)
  • Run OpenSearch async callbacks with the request's parent context. (#19027)
