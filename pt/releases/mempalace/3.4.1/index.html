#mempalace v3.4.1

v3.4.1 — Suporte a cursor e IDE antigravidade

Agora temos suporte para mais dois editores: um plug-in Cursor com ganchos nativos e suporte para Google Antigravity de primeira classe — ambos trazendo o salvamento automático do MemPalace, a recuperação de início de sessão e a mineração de transcrição literal para o mesmo padrão já fornecido para Claude Code e Codex. Duas correções de confiabilidade completam o ciclo: embeddinggemma não mata mais grandes reintegrações de OOM e os backups migrate / repair param de se acumular até preencherem o disco.

Recursos

  • Plugin Cursor IDE (.cursor-plugin/). Registra automaticamente o servidor mempalace-mcp, cinco comandos de barra (/mempalace-help, /mempalace-init, /mempalace-mine, /mempalace-search, /mempalace-status) e uma habilidade invocável por modelo - sem edição manual do ~/.cursor/mcp.json. Instale a partir de um clone local agora ou do mercado Cursor, uma vez publicado. (#1632)
  • Ganchos IDE do cursor (stop / preCompact / sessionStart). Salvamento automático em segundo plano a cada N turnos do agente, mineração de transcrição síncrona antes da compactação do Cursor e recuperação de memória de início de sessão com escopo para a ala do espaço de trabalho. Instalador de um comando em hooks/cursor/install.sh (--scope user|project, --variant full|minimal, --dry-run, --uninstall) — idempotente e livre de dependências.
  • Suporte IDE Antigravity (Google) de primeira classe. Novo pacote .antigravity-plugin/ e instalador idempotente que registra MemPalace como um plugin Antigravity — servidor MCP, habilidade e dois ganchos de ciclo de vida (mineração em segundo plano no Stop, injeção de memória literal na primeira chamada de modelo). bash 3.2 / compatível com macOS, compartilha o mesmo diretório ~/.mempalace/hook_state/ que os ganchos Claude Code / Codex / Cursor e respeita todos os kill switch existentes. (#1633, #1771)
  • Resolução zero do interpretador de configuração para ganchos. Os ganchos agora resolvem Python a partir do shebang do script do console mempalace-mcp antes de voltar para python3, corrigindo a mineração silenciosa sem operação em layouts uv tool install / pipx onde o sistema python3 não pode importar mempalace.

Correções de bugs

  • embeddinggemma não elimina mais reintegrações em massa de OOM. O incorporador ONNX executou uma única passagem em toda a sua entrada, portanto, um lote em escala de reparo (~ 5.000 documentos) alocou buffers de atenção muito além da RAM disponível e o kernel eliminou o processo silenciosamente. A incorporação agora é executada em sublotes de 32 documentos; os vetores por documento permanecem inalterados. (#1770)
  • Retenção de backup para evitar o uso ilimitado do disco. mempalace migrate e mempalace repair max-seq-id gravaram um backup novo e completo a cada execução e nunca o limparam — um palácio foi encontrado com centenas de GB de backups obsoletos além de algumas centenas de MB de dados ativos. Uma nova configuração max_backups (padrão 10; 0 mantém tudo) agora remove o mais antigo após cada novo backup ser gravado. (#1697) Um grande obrigado a todos que contribuíram neste ciclo — tanto as integrações do IDE quanto várias dessas correções vieram da comunidade, incluindo vários colaboradores iniciantes. Todos estão creditados abaixo.

mempalace v3.4.1

v3.4.1 — Cursor and Antigravity IDE support

We now have support for two more editors: a Cursor plugin with native hooks, and first-class Google Antigravity support — both bringing MemPalace's auto-save, session-start recall, and verbatim transcript mining to the same standard already shipping for Claude Code and Codex. Two reliability fixes round out the cycle: embeddinggemma no longer OOM-kills large re-embeds, and migrate / repair backups stop accumulating until they fill the disk.

Features

  • Cursor IDE plugin (.cursor-plugin/). Auto-registers the mempalace-mcp server, five slash commands (/mempalace-help, /mempalace-init, /mempalace-mine, /mempalace-search, /mempalace-status), and a model-invocable skill — no manual ~/.cursor/mcp.json edit. Install from a local clone now, or the Cursor marketplace once published. (#1632)

  • Cursor IDE hooks (stop / preCompact / sessionStart). Background auto-save every N agent turns, synchronous transcript mining before Cursor compacts, and session-start memory recall scoped to the workspace wing. One-command installer at hooks/cursor/install.sh (--scope user|project, --variant full|minimal, --dry-run, --uninstall) — idempotent and dependency-free.

  • First-class Antigravity (Google) IDE support. New .antigravity-plugin/ package and idempotent installer that registers MemPalace as an Antigravity plugin — MCP server, skill, and two lifecycle hooks (background mining on Stop, verbatim memory injection on the first model call). bash 3.2 / macOS-compatible, shares the same ~/.mempalace/hook_state/ directory as the Claude Code / Codex / Cursor hooks, and honors every existing kill switch. (#1633, #1771)

  • Zero-config interpreter resolution for hooks. The hooks now resolve Python from the mempalace-mcp console-script shebang before falling back to python3, fixing silently-no-op mining under uv tool install / pipx layouts where the system python3 can't import mempalace.

Bug Fixes

  • embeddinggemma no longer OOM-kills bulk re-embeds. The ONNX embedder ran a single pass over its entire input, so a repair-scale batch (~5,000 docs) allocated attention buffers far beyond available RAM and the kernel killed the process silently. Embedding now runs in 32-doc sub-batches; per-document vectors are unchanged. (#1770)

  • Backup retention to prevent unbounded disk usage. mempalace migrate and mempalace repair max-seq-id wrote a fresh, full-size backup every run and never cleaned up — one palace was found with hundreds of GB of stale backups beside a few hundred MB of live data. A new max_backups setting (default 10; 0 keeps all) now prunes the oldest after each new backup is written. (#1697)

A big thank-you to everyone who contributed this cycle — both IDE integrations and several of these fixes came from the community, including a number of first-time contributors. Everyone is credited below.
