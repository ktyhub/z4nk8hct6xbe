#mempalace v3.5.0

v3.5.0 — daemon de gravação local, transporte HTTP opcional e ferramentas de limpeza de palácio

Este ciclo adiciona duas novas maneiras de executar o caminho de gravação do MemPalace e um conjunto de ferramentas para manter um palácio limpo. Um daemon local opcional serializa minas em segundo plano, salvamentos diários e ingestões de gancho por meio de um único processo, em vez de correr para o identificador do palácio, e um transporte HTTP opcional permite que o servidor MCP seja executado atrás de um HTTP client/proxy de longa duração - padrão de loopback, com uma proteção de religação de DNS de host/origem e um token de portador opcional. Três novas ferramentas MCP chegam ao lado: mempalace_checkpoint (agrupar uma sessão inteira em um único salvamento), mempalace_delete_by_source (limpar cirurgicamente a contaminação de benchmark/avaliação extraída - gavetas e suas entradas de índice) e um filtro source_file para pesquisa com escopo. Novos analisadores de transcrição (Continue.dev, Gemini CLI, Pi) e cobertura de mineradores para C#/PHP/Swift/Kotlin/Java ampliam o que você pode minerar, e um lote de correções de desempenho e confiabilidade de grandes palácios completam o lançamento.

Recursos

  • Ative o daemon local para gravações na fila. mempalace daemon serializa todas as gravações do palácio por meio de um processo local para que o trabalho em segundo plano pare de correr pelo controle do palácio. Ativado e somente local. (#1826)
  • Transporte HTTP opcional para o servidor MCP. mempalace-mcp --transport http atende JSON-RPC em POST /mcp (com GET /healthz) para implantações de proxy/de longa duração. stdio permanece o padrão; o caminho HTTP liga 127.0.0.1, fixa Host e rejeita Origin sem loopback (proteção de religação de DNS) e suporta um token de portador MEMPALACE_MCP_HTTP_TOKEN opcional. (#1801, #1806)
  • Ferramenta de salvamento em lote mempalace_checkpoint. Arquiva múltiplas chamadas add_drawer mais uma entrada de diário opcional em uma única viagem de ida e volta do MCP, literalmente, reutilizando o caminho de adição/desdupação idempotente. (#1851)
  • Ferramenta de limpeza em massa mempalace_delete_by_source. Exclusão de correspondência exata e simulação por padrão de cada gaveta e suas entradas de índice de armário/AAAK para um source_file — o recurso quando arquivos de benchmark/eval são explorados em uma ala real. A simulação informa o raio da explosão; o commit grava uma entrada de auditoria WAL. (#1722, #1729)
  • Filtro source_file opcional para mempalace_search. Escopo uma pesquisa para um caminho armazenado exato; passado por todos os caminhos de pesquisa para que nunca perca uma correspondência silenciosamente. (#1815, #1817)
  • Novos analisadores de transcrição — Sessões Continue.dev (nº 731), Gemini CLI / AI Studio (nº 204) e agente Pi JSONL (nº 169).
  • Cobertura mais ampla de linguagem de mineração — C#/.NET, PHP (#1819), Swift/Kotlin (#1368) e detecção de projetos Java, incl. subprojetos sem raiz (#1720).
  • Mina final no plugin Claude SessionEnd para que as últimas trocas sejam capturadas no encerramento da sessão. (#1814, #1820)

Desempenho

  • Visão geral/status e graph_stats respondidos a partir do agregado SQLite — corrige tempos limite de palácios grandes. (#1748, #1379)
  • O Embedder limita os threads intra-op do tempo de execução ONNX para que uma mina em segundo plano não fixe mais todos os núcleos. (#1068)
  • Paginação pushdown SQL para sqlite_exact (#1842) e pgvector (#1840), além de metadados em massa de rolagem única para Qdrant (#1832).

Correções de bugs

  • pgvector tolera bytes de transcrição hostis — um substituto solitário (#1833) ou byte NUL (#1829) não aborta mais a mina inteira.
  • Pontos de recuperação de índice divergente em repair --mode from-sqlite, não uma re-mineração — a re-mineração derrubou silenciosamente gavetas e entradas de diário adicionadas ao MCP. (#1843, #1847, #1849)
  • Rotas de divergência obsoletas do ChromaDB HNSW para o substituto do SQLite em vez de falhar na leitura. (#1816, #1822)
  • O servidor MCP recusa um segundo escritor para o mesmo palácio em vez de competir com o HNSW. (#1818, #1823)
  • Windows hook miner surge com CREATE_NO_WINDOW — sem flash de console. (#1783, #1848)
  • URIs somente leitura SQLite codificados por porcentagem para que caminhos de palácio espaçados/caracteres especiais sejam abertos.

CI

  • test-windows tenta apenas o floco de compactação transitório ChromaDB HNSW (--only-rerun); Linux/macOS mantém zero reexecuções para que regressões reais continuem barulhentas. (#1854) Um grande obrigado a todos que contribuíram neste ciclo — muitos desses recursos e correções vieram da comunidade, incluindo vários colaboradores iniciantes. Todos estão creditados abaixo.

mempalace v3.5.0

v3.5.0 — local write daemon, opt-in HTTP transport, and palace-cleanup tooling

This cycle adds two new ways to run MemPalace's write path and a set of tools for keeping a palace clean. An opt-in local daemon serializes background mines, diary saves, and hook ingests through a single process instead of racing for the palace handle, and an opt-in HTTP transport lets the MCP server run behind a long-lived HTTP client/proxy — loopback-default, with a Host/Origin DNS-rebinding guard and an optional bearer token. Three new MCP tools land alongside: mempalace_checkpoint (batch a whole session into one save), mempalace_delete_by_source (surgically purge mined benchmark/eval contamination — drawers and their index entries), and a source_file filter for scoped search. New transcript parsers (Continue.dev, Gemini CLI, Pi) and miner coverage for C#/PHP/Swift/Kotlin/Java widen what you can mine, and a batch of large-palace performance and reliability fixes round out the release.

Features

  • Opt-in local daemon for queued writes. mempalace daemon serializes all palace writes through one local process so background work stops racing the palace handle. Opt-in and local-only. (#1826)
  • Opt-in HTTP transport for the MCP server. mempalace-mcp --transport http serves JSON-RPC at POST /mcp (with GET /healthz) for proxy/long-lived deployments. stdio remains the default; the HTTP path binds 127.0.0.1, pins Host and rejects non-loopback Origin (DNS-rebinding guard), and supports an optional MEMPALACE_MCP_HTTP_TOKEN bearer token. (#1801, #1806)
  • mempalace_checkpoint batch-save tool. Files multiple add_drawer calls plus an optional diary entry in a single MCP round-trip, verbatim, reusing the idempotent add/dedup path. (#1851)
  • mempalace_delete_by_source bulk-cleanup tool. Exact-match, dry-run-by-default deletion of every drawer and its closet/AAAK index entries for a source_file — the recourse when benchmark/eval files get mined into a real wing. The dry run reports the blast radius; the commit writes a WAL audit entry. (#1722, #1729)
  • Optional source_file filter for mempalace_search. Scope a search to an exact stored path; threaded through every search path so it never silently drops a match. (#1815, #1817)
  • New transcript parsers — Continue.dev sessions (#731), Gemini CLI / AI Studio (#204), and Pi agent JSONL (#169).
  • Wider miner language coverage — C#/.NET, PHP (#1819), Swift/Kotlin (#1368), and Java project detection incl. rootless subprojects (#1720).
  • Final mine on Claude plugin SessionEnd so the last exchanges are captured at session close. (#1814, #1820)

Performance

  • Overview/status and graph_stats answered from the SQLite aggregate — fixes large-palace timeouts. (#1748, #1379)
  • Embedder caps ONNX-runtime intra-op threads so a background mine no longer pins every core. (#1068)
  • SQL-pushdown pagination for sqlite_exact (#1842) and pgvector (#1840), plus single-scroll bulk metadata for Qdrant (#1832).

Bug Fixes

  • pgvector tolerates hostile transcript bytes — a lone surrogate (#1833) or NUL byte (#1829) no longer aborts the whole mine.
  • Diverged-index recovery points at repair --mode from-sqlite, not a re-mine — re-mining silently dropped MCP-added drawers and diary entries. (#1843, #1847, #1849)
  • Stale ChromaDB HNSW divergence routes to the SQLite fallback instead of failing the read. (#1816, #1822)
  • The MCP server refuses a second writer for the same palace rather than racing the HNSW handle. (#1818, #1823)
  • Windows hook miner spawns with CREATE_NO_WINDOW — no console flash. (#1783, #1848)
  • Percent-encoded SQLite read-only URIs so spaced/special-char palace paths open.

CI

  • test-windows retries only the transient ChromaDB HNSW compaction flake (--only-rerun); Linux/macOS keep zero reruns so real regressions stay loud. (#1854)

A big thank-you to everyone who contributed this cycle — many of these features and fixes came from the community, including several first-time contributors. Everyone is credited below.
