Stirling-PDF_0.33.1 Docker hub movido para stirlingtools v3.3.0

Stirling Office Convert (ainda beta) foi atualizado. Agora você também pode escolhê-lo como conversor em muitas outras ferramentas, como Email, HTML, Markdown e e-books para PDF, além de PDF para HTML/Markdown/XML/EPUB/AZW3 e PDF/A. Compare-o com o conversor existente e informe-nos!

Nosso roteiro é ativar o Office Convert por padrão na próxima semana e, se nenhuma alteração for necessária, remover completamente o LibreOffice e outras dependências na semana seguinte. Portanto, agora é o melhor momento para experimentar e relatar (e enviar arquivos de exemplo) quaisquer conversões que não pareçam corretas!

Outras mudanças são:

  • O login automático SSO agora funciona mesmo quando o login com nome de usuário/senha está ativado (os administradores ainda podem acessar o formulário de senha via /login?all)
  • Atualização e suporte para JPDFium e suporte para Windows ARM64. Esta atualização também traz melhor redação, melhorias de mesclagem/divisão e menos memória em arquivos grandes
  • Digitalização móvel mais rápida e precisa, sem mais 9 MB OpenCV incluídos
  • Solicitações mais rápidas com muito menos leituras de banco de dados e novo cache de entidade
  • Logs de inicialização e tempo de execução mais silenciosos
  • Imagem base Spring Boot, Docker e muitas outras atualizações de dependências
  • Traduções atualizadas para todos os idiomas

Também corrigimos alguns bugs, incluindo

  • Converta o envio de uploads de arquivos múltiplos ou mistos para a conversão errada
  • Configurações do e-book redefinindo o formato de saída selecionado
  • "Incluir todos os destinatários" sem controlar CC/BCC em e-mail para PDF
  • Incorporação de fonte PDF/UA, tornando os campos do formulário não mais preenchíveis
  • Assinatura de certificado rejeitando chaves PEM PKCS#8 não criptografadas
  • O visualizador sai da sua página após adicionar um marcador
  • Extração de arquivo oferecida para arquivos não zip

Esta versão também inclui diversas melhorias de segurança e estabilidade, por isso aconselhamos os usuários a atualizarem quando possível! Observação: o antigo e obsoleto back-end de edição de texto PDF API foi removido em favor do novo Editor de Texto. Esperamos adicionar um novo Editor de Texto API em breve!

Stirling-PDF_0.33.1 Docker hub move to stirlingtools v3.3.0

Highlights

  • Office Convert is poised to replace LibreOffice — Stirling Office Convert is bumped to 0.3.3 (#8761) and is now selectable as the converter for Email, HTML, Markdown and ebook-to-PDF, plus PDF-to-HTML/Markdown/XML/EPUB/AZW3 and PDF/A. Maintainers signal it will be on by default next week with LibreOffice and other dependencies removed the week after (#8665). Treat this as a migration window: run your own conversion corpus now and report bad output with sample files, because divergent rendering is the main adoption risk.
  • Breaking: the legacy PDF text-editing API is gone — The deprecated backend text-editing API and Type3 font cache were removed (#8504) in favour of the new Text Editor, but a replacement API is only "hoping" to land soon. Any client integrating against the old endpoint must be reworked; there is no drop-in path yet, so budget for a gap rather than a simple flip.
  • SSO auto-login now coexists with password login — #8486 makes SSO auto-login work even when username/password login is enabled, with the password form still reachable at /login?all. Admins should verify that escape hatch is documented for locked-out users, since the old assumption that password auth implies a visible form no longer holds.
  • JPDFium 1.3.0 and Windows ARM64 land together — The release bundles JPDFium 1.3.0, a 1.1.1 Docker base, better redaction, merge/split improvements and lower memory use on large files, plus Windows ARM64 support (#8781, #8715 for Spring Boot 4.1.2). The security and stability fixes are strong enough that the maintainers explicitly advise upgrading; ARM64 users gain a supported target.
  • Hot paths get a caching and dependency diet — Hibernate second-level caching via Caffeine JCache (#7504), reusing the already-resolved User instead of re-querying per request (#8061), reading auth.users only where consumed (#8063) and cutting repeated reads on authenticated requests (#8066) should cut latency and DB load. Watch cache invalidation around admin/user changes (#8579). Separately, the mobile scanner drops the 9 MB OpenCV bundle for built-in page detection (#8719), trimming the client footprint.
  • Auth and file handling are hardened in ways that change behaviour — Request-size bounds and mobile scanner relay hardening (#8672), atomic single-use invite consumption (#7861), rejection of malformed emails/unknown teams at invite creation (#7864), MFA settings protection and case-insensitive rename checks (#8687), and archive extraction limited to .zip (#8722). Also note guest-account controls are tightened (#8230, #8228) and PKCS#8 PEM keys without encryption are now accepted for signing (#8694) — check any automation relying on the previously permissive rename or extraction behaviour.

Stirling Office Convert (still beta) has been upgraded. You can also now pick it as the converter in lots of other tools such as Email, HTML, Markdown and ebooks to PDF plus PDF to HTML/Markdown/XML/EPUB/AZW3, and PDF/A. Please compare it with the existing converter and let us know!

Our roadmap is to turn Office Convert on by default next week, and then, if no changes are required, fully remove LibreOffice and other dependencies the week after. So now is the best time to try it and report (And send example files) any conversions that don't look correct!

Other changes are:

  • SSO auto-login now works even when username/password login is enabled (admins can still reach the password form via /login?all)
  • JPDFium upgrade and support and Windows ARM64 support, This update also brings better redaction, merge/split improvements and lower memory on big files
  • Faster and more accurate mobile scanning, with no more 9MB OpenCV bundled
  • Faster requests with far fewer database reads and new entity caching
  • Quieter startup and runtime logs
  • Spring Boot, Docker base image and lots of other dependency updates
  • Updated translations for all languages

We also fixed some bugs including

  • Convert sending multiple or mixed file uploads to the wrong conversion
  • Ebook settings resetting the selected output format
  • "Include all recipients" not controlling CC/BCC in email to PDF
  • PDF/UA font embedding making form fields no longer fillable
  • Certificate signing rejecting unencrypted PKCS#8 PEM keys
  • Viewer jumping away from your page after adding a bookmark
  • Archive extraction being offered for non-zip files

This release also includes several security and stability improvements, so we advise users to update when possible! Note: the old, deprecated backend PDF text editing API has been removed in favour of the new Text Editor. We are hoping to add a new Text Editor API soon!
