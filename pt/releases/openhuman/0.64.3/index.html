#openhuman v0.64.3

A atualização de confiabilidade e velocidade

v0.64.0 → v0.64.3 tem como objetivo fazer com que o OpenHuman pareça mais estável sob cargas de trabalho reais - menos loops, melhor recuperação, inicialização mais rápida e superfícies de faturamento/uso mais claras. Envie-o. 🚀

Destaques

Estabilidade do agente e controle de loop 🧭

Os agentes agora permanecem focados na última solicitação do usuário (mesmo após a chegada dos resultados da pesquisa de ferramentas), evitando serem puxados para saudações anteriores e interrompendo loops de ferramentas improdutivos mais cedo com classificação de falhas mais inteligente e exploração limitada. O resultado: menos paralisações, menos chamadas repetidas e resultados mais determinísticos “parciais, mas úteis” quando as ferramentas são bloqueadas. (#6656, #6660, #6661) — Obrigado @senamakel!

Recuperação de bate-papo, resiliência de streaming e correção de sessão quente 🛠️

Esta versão fortalece a experiência de chat: as conclusões da sessão quente agora finalizam adequadamente o progresso e podem, opcionalmente, capturar respostas SSE de inferência completas e bem-sucedidas para depuração; fluxos de modelo concluídos que não retornam resposta obtêm uma nova tentativa limitada; e a recuperação de transcrição/estado do aplicativo é mais robusta após gravações com falha ou interrompidas, preservando o histórico e mantendo estáveis ​​os acompanhamentos na fila. (#6665, #6685, #6686) — Obrigado @senamakel!

Integrações mais rápidas e descoberta de habilidades 🔥

A inicialização do turno e a disponibilidade de ferramentas devem ser mais rápidas graças ao armazenamento em cache e ao aquecimento das integrações do Composio e dos metadados de habilidades entre turnos/sessões (com regras de invalidação claras). Isso também encaminha atualizações do Socket.IO WebSocket por meio do proxy de captura de inferência local para roteamento de eventos mais consistente. (#6684) — Obrigado @senamakel!

Horário, fuso horário e correção de agendamento 🕒

O OpenHuman agora entende frases de horário mais naturais (como “amanhã às 9h”, “desde segunda-feira” e “em 2h30”), e as chamadas do conector Composio incluem o fuso horário IANA do usuário, ajudando os resultados posteriores (como carimbos de data e hora do Gmail) a se alinharem com o que os usuários realmente querem dizer. Os subagentes duráveis ​​também são retomados de forma mais confiável quando os IDs de sessão aparecem em vários campos. (#6670, #6673, #6674) — Obrigado @senamakel e @M3gA-Mind!

Observabilidade e telemetria do desenvolvedor 📡

O rastreamento de produção Langfuse é habilitado a partir do host canônico de produção API (enquanto mantém hosts desconhecidos fechados), e os turnos do agente filho são agrupados de forma limpa sob a linhagem de conversação pai - com metadados de geração mais completos e contabilidade cuidadosa para evitar contagem dupla. (#6677) — Obrigado @senamakel!

UI de faturamento e uso mais clara 💳

As superfícies de uso e cobrança passaram por uma verificação da realidade: “Uso e limites” agora é “Uso” (removendo medidores de orçamento local enganosos), o registro de uso de chamadas do provedor tem uma guia dedicada com melhores filtros e semântica de registro limitada, e o acesso à cobrança é consolidado em Contas com um link de painel hospedado (com /settings/billing preservado como um redirecionamento). Além disso, o chat não culpa mais incorretamente respostas de modelo vazias por créditos insuficientes – a orientação de crédito agora aparece apenas para erros de faturamento explícitos. (#6657, #6679) — Obrigado @senamakel!

Limpeza de ferramentas e plataforma (Windows + componentes retirados) 🧹

Os usuários do Windows devem ver um carregamento mais confiável do módulo TinyMemory graças a uma correção fixa do TinyBus ACL, e a integração retirada do Medulla foi totalmente removida (ao mesmo tempo em que preserva um alias de configuração herdado para que configurações mais antigas sejam carregadas com segurança como local). A superfície da ferramenta do orquestrador também foi reforçada com a remoção de ferramentas de prompt não utilizadas e entradas delegadas. Finalmente, o file_read agora está descompactado para que o orquestrador possa ler as visualizações dos resultados sem abrir todo o pacote de ferramentas de arquivos. (#6680, #6682, #6669, #6666) — Obrigado @senamakel e @M3gA-Mind!

Cobertura de teste e regressões ✅

A nova cobertura de regressão bloqueia o comportamento “saudação → continuação adiada da ferramenta Gmail” de ponta a ponta, ajudando a garantir que o agente mantenha a solicitação ativa e o resultado da ferramenta juntos e não volte ao contexto anterior. (#6659) — Obrigado @senamakel!

Créditos do Colaborador

Muito obrigado a todos que enviaram v0.64.0 → v0.64.3: @senamakel, @M3gA-Mind.

openhuman v0.64.3

The Reliability & Speed Upgrade

v0.64.0 → v0.64.3 is all about making OpenHuman feel steadier under real workloads—fewer loops, better recovery, faster turn startup, and clearer billing/usage surfaces. Ship it. 🚀

Highlights

Agent stability & loop control 🧭

Agents now stay focused on the latest user request (even after tool search results arrive), avoid getting pulled back into earlier greetings, and stop unproductive tool loops sooner with smarter failure classification and bounded exploration. The result: fewer stalls, fewer repeat calls, and more deterministic “partial-but-useful” outcomes when tools are blocked. (#6656, #6660, #6661) — Thank you @senamakel!

Chat recovery, streaming resilience & warm-session correctness 🛠️

This release hardens the chat experience: warm-session completions now properly finalize progress and can optionally capture full successful inference SSE responses for debugging; completed model streams that return no answer get a bounded one-time retry; and transcript/app-state recovery is more robust after failed or torn writes—preserving history and keeping queued follow-ups stable. (#6665, #6685, #6686) — Thank you @senamakel!

Faster integrations & skill discovery 🔥

Turn startup and tool availability should feel snappier thanks to caching and warming of Composio integrations and skill metadata across turns/sessions (with clear invalidation rules). This also forwards Socket.IO WebSocket upgrades through the local inference capture proxy for more consistent event routing. (#6684) — Thank you @senamakel!

Time, time zones & scheduling correctness 🕒

OpenHuman now understands more natural time phrases (like “tomorrow 9am”, “since Monday”, and “in 2h30m”), and Composio connector calls include the user’s IANA time zone—helping downstream results (like Gmail timestamps) line up with what users actually mean. Durable subagents also resume more reliably when session IDs show up in multiple fields. (#6670, #6673, #6674) — Thank you @senamakel and @M3gA-Mind!

Observability & developer telemetry 📡

Production Langfuse tracing is enabled from the canonical production API host (while keeping unknown hosts closed), and child agent turns are grouped cleanly under parent conversation lineage—with more complete generation metadata and careful accounting to avoid double counting. (#6677) — Thank you @senamakel!

Clearer billing & usage UI 💳

Usage and billing surfaces got a reality check: “Usage & Limits” is now “Usage” (removing misleading local budget gauges), provider-call usage logging has a dedicated tab with better filters and bounded record semantics, and billing access is consolidated under Accounts with a hosted dashboard link (with /settings/billing preserved as a redirect). Also, chat no longer incorrectly blames empty model responses on insufficient credits—credit guidance now appears only for explicit billing errors. (#6657, #6679) — Thank you @senamakel!

Tooling & platform cleanup (Windows + retired components) 🧹

Windows users should see more reliable TinyMemory module loading thanks to a pinned TinyBus ACL fix, and the retired Medulla integration has been fully removed (while preserving a legacy config alias so older configs load safely as local). The orchestrator tool surface was also tightened by removing unused prompt tools and delegate entries. Finally, file_read is now unpacked so the orchestrator can read result previews without opening up the whole files tool pack. (#6680, #6682, #6669, #6666) — Thank you @senamakel and @M3gA-Mind!

Test coverage & regressions ✅

New regression coverage locks in the “greeting → deferred Gmail tool continuation” behavior end-to-end, helping ensure the agent keeps the active request and tool result together and doesn’t fall back into earlier context. (#6659) — Thank you @senamakel!

Contributor Credits

Big thanks to everyone who shipped v0.64.0 → v0.64.3: @senamakel, @M3gA-Mind.
