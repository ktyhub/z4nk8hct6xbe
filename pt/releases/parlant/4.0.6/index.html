#parlant v4.0.6

[4.0.6] - 16/11/2026

Adicionado

  • parlant lint liga um projeto de agente Parlant por meio de seu agente de codificação. Isso imprime instruções para o agente de codificação: quais capítulos lint executar, cada um em seu próprio subagente (parlant lint --section SECTION --chapter CHAPTER imprime um regras do capítulo) e como lidar com as descobertas por gravidade. Resultados ALTOS são corrigido imediatamente, no máximo 3 tipos de questões MÉDIAS são propostos por rodada, e BAIXOS apenas com o seu OK. As primeiras seções são Comportamento (observações que combinam diversas situações, sejam elas alternativas ou que devem ser todas espera) e redação e tom de voz (predefinidos respostas em vez de palavras em políticas ou instruções). Toda regra tem um ID, como BHV001, que permanece o mesmo entre as versões.
  • parlant init agora instala um gancho pré-push git (.githooks/pre-push, set através de core.hooksPath) que interrompe um push até que o commit seja lintado, e o scaffolded AGENTS.md diz ao agente de codificação para executar parlant lint antes de cada empurrão. Depois de lintar e confirmar as correções, parlant lint --done records the commit so the push goes through; git push --no-verify pula o gancho. Um clone do projeto ativa o gancho com git config core.hooksPath .githooks. --no-git não instala nenhum gancho.
  • parlant dashboard agent cards AGENT_ID DESTINATION grava todos os arquivos que você site serve para que agentes pessoais de IA encontrem seu agente, em DESTINATION/.well-known: agent-card.json para A2A e poppy.json e poppy-0.4.json para Poppy, o Protocolo de agente pessoal que Meta Muse e Shopify usam. --no-a2a e --no-poppy deixa uma família de fora. Os documentos Poppy precisam do conjunto de sites do agente no Dashboard, já que Poppy identifica uma empresa pelo seu domínio; sem isso o comando escreve o cartão e diz isso. parlant dashboard agent view mostra o POPPY ADDRESS do agente e parlant widget init aponta para o novo comando. parlant dashboard agent card ainda imprime o cartão A2A sozinho para modelos mais antigos instruções.
  • O onPathChanged(path, notifyAgent) do widget de chat informa ao agente qual página o visitante está ligado. É chamado quando o widget é carregado e quando o caminho muda sem recarga; notifyAgent(path, data?) adiciona um evento personalizado ({ type: "page_view", page: path, ...data }, fonte customer_ui) que não inicia uma resposta. Uma nova conversa é recebida antes de qualquer outra coisa, para que o agente possa saber uma pergunta feita em sua página de preços a partir de uma pergunta feita em sua página inicial.

Alterado

  • Com alto esforço do agente, a remoção de regras previamente descobertas agora tem como padrão raciocínio de modelo baixo, classificação de regras de correspondência. Raciocínio explícito de rota de modelo as configurações ainda têm precedência.
  • Quando uma política implica outra, a política implicada é agora julgada com o políticas que o implicam em vista. Isso ajuda quando seu texto depende de deles, como "o complemento" definido por outra política. Ainda corresponde seus próprios méritos, e a vinculação funciona como antes: quando uma política vinculativa partidas, a implicada também é ativada.
  • Convidados e clientes conectados podem adicionar eventos personalizados às suas próprias sessões, com fonte customer_ui, até 4 KB de dados e 30 por minuto. Até agora só o back-end poderia, então um site tinha que retransmitir visualizações de páginas por meio de seu próprio servidor com a chave de administrador. Outras fontes ainda precisam da chave admin; uma permissão personalizada portão que não concede CREATE_CUSTOM_EVENT continua recusando. PARLANT_CUSTOMER_UI_EVENT_MAX_BYTES altera o limite de tamanho (4096 por padrão).
  • Um widget de chat com um avatar de vídeo agora move o vídeo para um círculo ao lado o nome do agente quando a conversa rola e o espaço que ele deixa fecha. Rolar para cima além do topo o traz de volta. O cabeçalho mantém seu altura e desaparece nas mensagens abaixo do círculo. O nome e a legenda desaparece enquanto o vídeo se move e volta ao lado do círculo, o legenda sob o nome. Um avatar de foto agora tem o mesmo tamanho que o avatar encaixado círculo, e seu cabeçalho desaparece também nas mensagens abaixo dele. Rolando para cima no widget não é mais puxado para baixo em uma conversa curta e enviar uma mensagem traz a visão para ela. Nos telefones, o widget mostra apenas o círculo, que é recortado no rosto pela configuração launcher do avatar. Seu projeto mantém a cópia parlant widget init feito. Para pegar isso, execute parlant widget init --force, que substitui essa cópia e quaisquer alterações que você feito para isso.
  • Com Gemini como seu provedor, responde com esforço médio, alto e máximo e ambos verificações de revisão agora são executadas no Gemini 4 Hydrogen em vez do Gemini 3.8 Flash. Médio o esforço mantém baixo raciocínio. Em um agente de site, este corte de respostas de 15 a 30 segundos para 6–8, e o Hydrogen manteve seu raciocínio fora das respostas onde 3.8 Flash em um nível baixo, o raciocínio havia escrito tudo em um. Esforço mínimo e baixo permanece ligado Flash Lite. Uma rota react ou review.* que você mesmo definiu permanece inalterada. Para mantenha o modelo antigo, encaminhe-o explicitamente, por ex. "react": p.ModelConfig("gemini:gemini-3.8-flash", reasoning="low").
  • O padrão do LiteLLM para ambas as verificações de revisão agora é gemini/gemini-4-hydrogen em vez de gemini/gemini-3.8-flash.

Corrigido

  • Uma observação com título, mas sem nota, não aparece mais na lista do agente instruções como uma entrada vazia (seu título seguido por "Detalhes: [Nenhum]", sem sua condição). Uma regra agora chega ao prompt do agente somente quando diz algo: seu conteúdo (uma nota de observação, uma ação política), ou as ferramentas que torna relevantes, caso em que o seu estado é mostrado mesmo quando tem um título. Regras sem conteúdo também ficam de fora da observação de que informa ao agente quais instruções perderam prioridade neste turno. Observações sem uma nota, continue trabalhando para relacionamentos, escopo de resposta automática e correspondência; eles simplesmente não custam tokens imediatos.
  • Os escopos de registro agora são desenrolados após exceções e cancelamento, para registros posteriores na mesma tarefa não retém rótulos de componentes obsoletos.
  • O widget de bate-papo centraliza seu aviso de isenção de responsabilidade e "Powered by Parlant" abaixo da entrada nos telefones.
  • O widget de chat não mostra mais "↓ Novas mensagens" em um chat vazio ou curto que o visitante rolou para cima. A pílula agora aparece apenas quando há algo abaixo para onde pular.
  • O widget de bate-papo não termina mais uma resposta finalizada com um * perdido. Uma resposta com um número ímpar de marcadores * usados para obter um após sua última palavra. Meio digitado negrito e itálico ainda fecham enquanto uma resposta é transmitida. Para pegar isso e o outras correções de widget, execute parlant widget init --force, que substitui seu a cópia do widget do projeto e quaisquer alterações feitas nele.
  • Um nível de raciocínio definido em um modelo Gemini 4 em uma rota esquemática, como "review.*": p.ModelConfig("gemini:gemini-4-hydrogen", reasoning="high"), agora é enviado para Gêmeos. Costumava ser descartado, então o modelo pensou em seu próprio padrão.
  • A relevância da resposta automática agora considera as correspondências de todos os blocos de consulta anteriores selecionando as respostas mais próximas, mantendo a melhor pontuação correspondente de cada resposta.

parlant v4.0.6

[4.0.6] - 2026-11-16

Added

  • parlant lint lints a Parlant agent project through your coding agent. It prints instructions for the coding agent: which lint chapters to run, each in its own subagent (parlant lint --section SECTION --chapter CHAPTER prints a chapter's rules), and how to handle findings by severity. HIGH findings are fixed right away, at most 3 MEDIUM issue types are proposed per round, and LOW ones only with your OK. The first sections are Behavior (observations that combine several situations, whether alternatives or ones that must all hold) and Wording and Tone of Voice (canned responses rather than wording in policies or instructions). Every rule has an ID, such as BHV001, that stays the same across releases.
  • parlant init now installs a git pre-push hook (.githooks/pre-push, set through core.hooksPath) that stops a push until the commit has been linted, and the scaffolded AGENTS.md tells the coding agent to run parlant lint before every push. After linting and committing the fixes, parlant lint --done records the commit so the push goes through; git push --no-verify skips the hook. A clone of the project turns the hook on with git config core.hooksPath .githooks. --no-git installs no hook.
  • parlant dashboard agent cards AGENT_ID DESTINATION writes every file your site serves so personal AI agents find your agent, into DESTINATION/.well-known: agent-card.json for A2A, and poppy.json and poppy-0.4.json for Poppy, the Personal Agent Protocol that Meta Muse and Shopify use. --no-a2a and --no-poppy leave a family out. The Poppy documents need the agent's site set in the Dashboard, since Poppy identifies a business by its domain; without it the command writes the card and says so. parlant dashboard agent view shows the agent's POPPY ADDRESS, and parlant widget init points at the new command. parlant dashboard agent card still prints the A2A card alone for older instructions.
  • The chat widget's onPathChanged(path, notifyAgent) tells the agent which page the visitor is on. It's called when the widget loads and when the path changes without a reload; notifyAgent(path, data?) adds a custom event ({ type: "page_view", page: path, ...data }, source customer_ui) that doesn't start a reply. A new conversation gets it before anything else, so the agent can tell a question asked on your pricing page from one asked on your home page.

Changed

  • At high agent effort, pruning previously discovered rules now defaults to low model reasoning, matching rule ranking. Explicit model-route reasoning settings still take precedence.
  • When one policy entails another, the entailed policy is now judged with the policies that entail it in view. This helps when its wording relies on theirs, such as "the add-on" that another policy defines. It still matches on its own merits, and entailment works as before: when an entailing policy matches, the entailed one is activated too.
  • Guests and signed-in customers may add custom events to their own sessions, with source customer_ui, up to 4 KB of data and 30 a minute. Until now only the backend could, so a site had to relay page views through its own server with the admin key. Other sources still need the admin key; a custom permission gate that doesn't grant CREATE_CUSTOM_EVENT keeps refusing them. PARLANT_CUSTOMER_UI_EVENT_MAX_BYTES changes the size limit (4096 by default).
  • A chat widget with a video avatar now moves the video into a circle beside the agent's name once the conversation scrolls, and the space it leaves closes up. Scrolling up past the top brings it back. The header keeps its height and fades out over the messages below the circle. The name and subtitle fade out while the video moves and back in beside the circle, the subtitle under the name. A photo avatar is now the same size as the docked circle, and its header fades out over the messages below it too. Scrolling up in the widget no longer gets pulled back down in a short conversation, and sending a message brings the view to it. On phones the widget only shows the circle, which is cropped onto the face by the avatar's launcher setting. Your project keeps the copy parlant widget init made. To pick this up, run parlant widget init --force, which replaces that copy and any changes you made to it.
  • With Gemini as your provider, replies at medium, high and max effort and both review checks now run on Gemini 4 Hydrogen instead of Gemini 3.8 Flash. Medium effort keeps low reasoning. On a website agent this cut replies from 15–30 seconds to 6–8, and Hydrogen kept its reasoning out of replies where 3.8 Flash at low reasoning had written it into one. Minimal and low effort stay on Flash-Lite. A react or review.* route you set yourself is unchanged. To keep the old model, route it explicitly, e.g. "react": p.ModelConfig("gemini:gemini-3.8-flash", reasoning="low").
  • LiteLLM's default for both review checks is now gemini/gemini-4-hydrogen instead of gemini/gemini-3.8-flash.

Fixed

  • An observation with a title but no note no longer appears in the agent's instructions as an empty entry (its title followed by "Details: [None]", without its condition). A rule now reaches the agent's prompt only when it says something: its content (an observation's note, a policy's action), or the tools it makes relevant, in which case its condition is shown even when it has a title. Rules without content are also left out of the note that tells the agent which instructions lost priority this turn. Observations without a note keep working for relationships, canned-response scoping and matching; they simply cost no prompt tokens.
  • Logging scopes now unwind after exceptions and cancellation, so later logs in the same task do not retain stale component labels.
  • The chat widget centers its disclaimer and "Powered by Parlant" under the input on phones.
  • The chat widget no longer shows "↓ New messages" in an empty or short chat that the visitor scrolled up in. The pill now appears only when there is something below to jump to.
  • The chat widget no longer ends a finished reply with a stray *. A reply with an odd number of * bullets used to get one after its last word. Half-typed bold and italics still close while a reply streams. To pick up this and the other widget fixes, run parlant widget init --force, which replaces your project's copy of the widget and any changes you made to it.
  • A reasoning level set on a Gemini 4 model in a schematic route, such as "review.*": p.ModelConfig("gemini:gemini-4-hydrogen", reasoning="high"), is now sent to Gemini. It used to be dropped, so the model thought at its own default.
  • Canned-response relevance now considers matches from every query chunk before selecting the closest responses, retaining each response's best matching score.
