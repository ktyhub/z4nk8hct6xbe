#parlant v4.0.5

[4.0.5] - 12/11/2026

Adicionado

  • Gemini 4 Hydrogen funciona através do provedor Gemini, incluindo respostas transmitidas, chamadas de ferramentas, reprodução de conversas salvas e contabilidade de tokens. Selecione-o como gemini:gemini-4-hydrogen; os modelos padrão existentes permanecem inalterados.
  • O widget de chat mostra tabelas Markdown na resposta de um agente como tabelas. Eles usado para mostrar como linhas de tubos. Alinhamento de coluna, Markdown embutido nas células e canos escapados funcionam. Uma tabela transmitida aparece quando seu cabeçalho e divisor as linhas chegam e são preenchidas célula por célula. Uma mesa larga rola lateralmente para dentro a mensagem e os estilos de tabela do próprio site não a alteram. Seu projeto mantém a cópia parlant widget init feita. Para pegar isso, execute parlant widget init --force, que substitui essa cópia e quaisquer alterações que você feito para isso.
  • Os fluxos de eventos (sse=true) agora carregam um id em cada quadro e são retomados a partir de isso. Um client que se reconecta com Last-Event-ID é captado após o quadro que ele última serra, em vez de repetir a sessão desde o início. Streams perguntam a reconectando o navegador para esperar três segundos (retry: 3000) e um modo inativo stream envia um comentário keep-alive a cada 15 segundos, então um proxy não é mais fecha uma conexão silenciosa antes que wait_for_data expire. Quando um pedido carrega min_offset e Last-Event-ID, o último dos dois vence: um reconectar client geralmente ainda tem o min_offset original em seu URL, e honrá-lo repetiria a sessão. O atraso e o keep-alive intervalo pode ser definido com PARLANT_SSE_RETRY_MS e PARLANT_SSE_HEARTBEAT_SECONDS; 0 desativa o keep-alive e 0 para o delay omite a linha retry:.
  • Gemini atende à Decisão Gemini 1 do Google (gemini-decision-1), que responde muitas perguntas de sim/não, escolha e escala sobre uma conversa em uma única pedido. Uma rota {"*": "gemini"} agora a utiliza para classificação de regras no esforços que classificam regras em um lote, como rotas OpenAI e OpenRouter já fazer com seus modelos de decisão. Nomeie-o em uma rota com "matching.rank[capability=decision]": "gemini:gemini-decision-1". Ele usa seu GEMINI_API_KEY existente. Gemini não relata nenhum custo para isso, então adicione um Entrada gemini-decision-1 para server.set_pricing(...) (o Google lista $ 0.10 por milhões de tokens de entrada e nada para saída) para ter seu preço definido.

Alterado

  • Os modelos Gemini contam tokens em seu servidor em vez de perguntar ao Gemini API, que levou cerca de 300 ms por contagem. Uma etapa após uma chamada de ferramenta fez dois desses chamadas consecutivas enquanto escolhe respostas automáticas, portanto, responde após uma chamada de ferramenta agora comece cerca de 0.4 – 0,6s antes. As contagens usam o tokenizer Gemma 3 aberto e estão dentro de um ou dois tokens do Google. O extra gemini agora é instalado sentencepiece. O tokenizer é baixado uma vez de raw.githubusercontent.com, em segundo plano, na primeira contagem. Até que esteja pronto, ou se o seu servidor não consegue acessar GitHub, Parlant conta com o API como antes e registra um aviso dizendo isso.
  • Os agentes não repetem mais o que o cliente acabou de dizer antes respondendo ("Geração de leads para uma startup de logística, então…"). Uma reação agora responde ao que a mensagem significa e quando o cliente está respondendo à pergunta do próprio agente, o agente passa direto para a próxima etapa. A solicitação não não proíbe mais reconhecimentos de ações, como "faz sentido" pelo nome.
  • Os agentes criados por parlant init não aprendem mais a repetir as palavras do visitante de volta. As personalidades calorosas e otimistas agora reagem à mensagem significa, e o anfitrião caloroso vai direto para a próxima etapa quando o visitante é respondendo à sua pergunta. Os projetos existentes mantêm texto próprio; copie o novo redação de um novo parlant init se o seu agente ecoar.

Corrigido

  • Em servidores gerenciados (hospedados no painel), session.metadata.get(), .set() e .delete(), session.update() e server.get_session() falharam com “Sessão não encontrada” para conversas ao vivo, porque procuraram na loja que contém declarações de inicialização em vez daquele que contém sessões. Eles agora use o mesmo armazenamento de sessão do mecanismo e do API, conforme session.labels já fez isso, então um recuperador ou ferramenta que lê ou escreve os metadados da sessão funcionam da mesma forma hospedada e localmente.
  • As verificações de preços não avisam mais sobre modelos padrão do provedor não utilizados quando um rota de modelo mais específica os substitui, como embeddings Gemini em um Servidor antrópico. Modelos ainda acessíveis por outras rotas e modelos efetivamente observados em uso, permanecem incluídos na cobertura de preços.
  • Ferramentas MCP que retornam resultados estruturados, como um modelo pydantic, agora fornecem o agente o resultado como simples JSON. Antes, a chamada era executada, mas o agente estava disse "Erro de chamada de ferramenta", para que pudesse tentar novamente uma chamada que já havia sido atendida efeito ou dizer ao cliente que falhou.
  • Os agentes Gemini sob carga simultânea não fazem mais filas uns atrás dos outros enquanto um cache de prompt está sendo criado. Solicitações de outros caches e solicitações cujos o cache já existe, vá em frente imediatamente; solicitações para o mesmo cache ainda compartilhe uma criação, para que ela seja criada e seu armazenamento seja cobrado uma vez.
  • Servidores com armazenamentos MongoDB iniciam mais rápido à medida que o histórico de sessões e eventos aumenta. Quando a versão gravada de uma loja já corresponde à versão em execução, inicialização não não lê mais todos os documentos através de seu carregador. Quando uma migração é necessário, os documentos são carregados e migrados como antes.

parlant v4.0.5

[4.0.5] - 2026-11-12

Added

  • Gemini 4 Hydrogen works through the Gemini provider, including streamed replies, tool calls, saved conversation replay and token accounting. Select it as gemini:gemini-4-hydrogen; existing default models are unchanged.
  • The chat widget shows Markdown tables in an agent's reply as tables. They used to show as lines of pipes. Column alignment, inline Markdown in cells and escaped pipes work. A streamed table appears once its header and divider rows arrive and fills in cell by cell. A wide table scrolls sideways inside the message, and your site's own table styles don't change it. Your project keeps the copy parlant widget init made. To pick this up, run parlant widget init --force, which replaces that copy and any changes you made to it.
  • Event streams (sse=true) now carry an id on every frame and resume from it. A client that reconnects with Last-Event-ID picks up after the frame it last saw, instead of replaying the session from the beginning. Streams ask a reconnecting browser to wait three seconds (retry: 3000), and an idle stream sends a keep-alive comment every 15 seconds, so a proxy no longer closes a quiet connection before wait_for_data expires. When a request carries both min_offset and Last-Event-ID, the later of the two wins: a reconnecting client usually still has the original min_offset in its URL, and honoring it would replay the session. The delay and the keep-alive interval can be set with PARLANT_SSE_RETRY_MS and PARLANT_SSE_HEARTBEAT_SECONDS; 0 disables the keep-alive, and 0 for the delay omits the retry: line.
  • Gemini serves Google's Gemini Decision 1 (gemini-decision-1), which answers many yes/no, choice and scale questions about one conversation in a single request. A {"*": "gemini"} route now uses it for rule ranking at the efforts that rank rules in one batch, as OpenAI and OpenRouter routes already do with their decision models. Name it on a route with "matching.rank[capability=decision]": "gemini:gemini-decision-1". It uses your existing GEMINI_API_KEY. Gemini reports no cost for it, so add a gemini-decision-1 entry to server.set_pricing(...) (Google lists $0.10 per million input tokens and nothing for output) to have it priced.

Changed

  • Gemini models count tokens on your server instead of asking the Gemini API, which took about 300ms per count. A step after a tool call made two such calls in a row while choosing canned responses, so replies after a tool call now start about 0.4–0.6s sooner. Counts use the open Gemma 3 tokenizer and are within a token or two of Google's. The gemini extra now installs sentencepiece. The tokenizer downloads once from raw.githubusercontent.com, in the background, on the first count. Until it's ready, or if your server can't reach GitHub, Parlant counts with the API as before and logs one warning saying so.
  • Agents no longer repeat what the customer just said back to them before replying ("Lead generation for a logistics startup, so…"). A reaction now responds to what the message means, and when the customer is answering the agent's own question, the agent goes straight to its next step. The prompt no longer bans stock acknowledgments such as "makes sense" by name.
  • Agents created by parlant init no longer learn to repeat the visitor's words back. The warm-host and upbeat personalities now react to what a message means, and the warm host goes straight to its next step when the visitor is answering its question. Existing projects keep their own text; copy the new wording from a fresh parlant init if your agent echoes.

Fixed

  • On managed (Dashboard-hosted) servers, session.metadata.get(), .set() and .delete(), session.update() and server.get_session() failed with "Session not found" for live conversations, because they looked in the store that holds startup declarations instead of the one that holds sessions. They now use the same session store as the engine and the API, as session.labels already did, so a retriever or tool that reads or writes session metadata works the same hosted as it does locally.
  • Pricing checks no longer warn about unused provider-default models when a more specific model route overrides them, such as Gemini embeddings on an Anthropic server. Models still reachable through other routes, and models actually observed in use, remain included in pricing coverage.
  • MCP tools that return structured results, such as a pydantic model, now give the agent the result as plain JSON. Before, the call ran but the agent was told "Tool call error", so it could retry a call that had already taken effect or tell the customer it failed.
  • Gemini agents under concurrent load no longer queue behind each other while a prompt cache is being created. Requests for other caches, and requests whose cache already exists, go ahead at once; requests for the same cache still share one creation, so it is created and its storage charged once.
  • Servers with MongoDB stores start faster as session and event history grows. When a store's recorded version already matches the running one, startup no longer reads every document back through its loader. When a migration is needed, documents are loaded and migrated as before.
