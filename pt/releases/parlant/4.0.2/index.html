#parlant v4.0.2

[4.0.2] - 05/11/2026

Adicionado

  • O widget de chat permite que o agente de IA no navegador do visitante converse com seu agente sobre WebMCP (document.modelContext; no Chrome hoje atrás de uma bandeira). Ligado em cada página em que está, o widget registra uma ferramenta ask_agent descrita com o nome do agente. Uma chamada inicia a conversa do widget se não houver nenhuma ainda assim, como um agente reserva para o cliente (customer_represented_by_an_agent), manda a pergunta pelo chat, então aparece lá com a resposta, abre o chat e responde ao agente do navegador assim que o turno terminar. Acompanhamento as chamadas continuam a mesma conversa. A mensagem carrega metadata.parlant_widget.asked_by = "customer_agent", então o chat e seu as ferramentas podem diferenciar o agente do visitante do visitante. Nada acontece em um navegador sem WebMCP; webmcp={false} desliga. ParlantTransport sendMessage usa um argumento de metadados opcional e ensureSession um opção para a bandeira.
  • Server(session_store=..., customer_store=...) aceita um s3://bucket URL para manter sessões e clientes no Amazon S3. Dê ao Parlant um balde de seu próprio. As credenciais vêm da cadeia de credenciais da AWS; adicione ?region= ou, para armazenamento compatível com S3, ?endpoint=. O armazenamento deve suportar gravações condicionais, que evitam que servidores simultâneos substituam cada um atualizações de outros. Coleções vazias sobrevivem a reinicializações e a uma migração com falha write deixa os dados originais no lugar. Qualquer consulta que não seja uma pesquisa por ID, como listar sessões, lê todos os objetos da coleção, então use MongoDB se você precisar de consultas indexadas em escala.
  • O widget de chat (parlant widget init) tira a foto do agente em uma Suporte avatar: { type: "logo", src }, { type: "photo", src, live? } ou { type: "video", src?, poster?, live?, launcher? }. Um avatar de vídeo reproduz um curto loop silenciado sob o cabeçalho, rola a conversa uma vez ele inicia e mantém o tamanho aberto quando o chat é expandido. No fechado lançador, launcher o corta no rosto. Deixe de fora src para usar o vídeo do próprio widget de um agente. live adiciona o ponto verde no vídeo canto também, vermelho enquanto o servidor não pode ser alcançado. Use um H.264 MP4 salvo com -movflags +faststart; O iPhone Safari trava no WebM.

Alterado

  • As sugestões persistentes do widget de chat se destacam das de abertura: delineado e escrito na cor primária do tema no fundo do chat, em vez do preenchimento cinza.
  • Em telefones e tablets, o widget de bate-papo fecha o teclado na tela uma vez por mensagem é enviada, digitada ou escolhida nas sugestões, então a resposta não está escondido atrás dele.
  • Com o provedor LiteLLM, as rotas de revisão agora são padronizadas para gemini/gemini-3.8-flash em vez de gemini/gemini-3.6-flash, o mesmo modelo que o provedor Gemini já usa para eles.
  • O agente do andaime lead-gen não adivinha mais quando um visitante pergunta sobre o negócio, seus produtos ou seu projeto e seu conhecimento do produto não tem resposta. Diz que é uma ótima pergunta, mas difícil de responder adequadamente no chat, se oferece para conectá-los com a equipe, pede um e-mail ou telefone número e repassa a pergunta com request_team_follow_up. Não relacionado perguntas, as perguntas sobre pedidos e preços dos clientes existentes são tratadas como antes. Para tornar isso possível, o record_lead agora aceita uma liderança com apenas um objetivo e um contato: buying_for e role são opcionais, e um desconhecido não marca nada.
  • parlant dashboard project confirm finaliza um projeto local ou auto-hospedado mesmo quando seu servidor já mantém sessões, como ao tentar o agente. Ele os importa primeiro para o painel, como faz o Sync do painel, e em seguida, conclui a configuração, para que o projeto não fique mais em "Concluir configuração". Uma importação que leva mais de 90 segundos é interrompida com SYNC_IN_PROGRESS; execute confirm novamente para continuar aguardando a mesma importação. Uma importação com falha termina com SYNC_FAILED e seu motivo. -parlant init --dashboard --json e parlant dashboard project create --json para um projeto local ou auto-hospedado agora liste nextSteps, terminando com project confirm. O AGENTS.md com andaime informa aos agentes de codificação para confirmar o projeto assim que seu servidor estiver conectado.
  • Depois de criar um projeto gerenciado cuja verificação de configuração descobriu como executá-lo, parlant dashboard project create agora aponta para parlant dashboard --project ID deploy: a primeira implantação ao vivo completa o configuração. A página de configuração do painel é opcional para revisar as configurações.

Obsoleto

  • Os adereços avatarUrl, avatarStyle e liveIndicator do widget de chat, em favor de avatar. Eles ainda funcionam quando o avatar não está configurado.

Corrigido

  • Gemini Argon pode reproduzir chamadas de ferramentas salvas com seu pensamento original assinado blocos em vez de voltar desnecessariamente ao histórico apenas de resultados.
  • Filtrar sessões por rótulos agora retorna páginas completas e funcionais cursores de continuação, com contagens totais consistentes em qualquer ordem de classificação.
  • A paginação do cursor MongoDB agora preserva os filtros $or em páginas posteriores, portanto as listagens filtradas não incluem mais registros fora do conjunto solicitado.
  • As respostas automáticas agora mantêm vetores de pesquisa separados para seu texto e cada sinal, para que os sinais não colidam mais no índice de relevância. Aplica-se quando as respostas são criadas ou atualizadas; os índices existentes não são reconstruído automaticamente.
  • No iPhone, focar a caixa de mensagem do widget de bate-papo não aumenta mais o zoom da página in, o que empurrou o bate-papo aberto para fora da borda direita da tela. A caixa usa uma fonte de 16px em telas sensíveis ao toque, tamanho abaixo do qual o iOS amplia.
  • As ferramentas locais e MCP agora aceitam argumentos de lista separados por vírgula sem colchetes, preservando vírgulas entre aspas e listas vazias.
  • A mensagem mais recente do widget de bate-papo não passa mais pelas sugestões e caixa de mensagem quando algo ocupa o espaço da transcrição, como o Banner "Conexão interrompida" aparecendo logo após um envio. A transcrição permaneceu preso ao fundo apenas à medida que as mensagens cresciam, e não à medida que sua visualização diminuía.
  • Programações de atualização de variável de contexto inválidas são rejeitadas antes de salvar, portanto, uma atualização de agendamento com falha deixa os dados existentes da variável intactos.
  • Uma mensagem do cliente que chega enquanto o agente ainda está trabalhando no o anterior agora substitui aquela curva, conforme pretendido, mesmo quando o motor estava em no meio da rejeição de uma etapa: uma chamada de ferramenta ou mensagem rejeitada por um gancho de revisão, pelo revisor ou pela moderação. Antes, a rejeição recomeçou a etapa e descartou o cancelamento pendente, então o agente terminou de responder à primeira mensagem e depois respondeu à segunda em um turno separado. Os clientes que enviam duas mensagens em rápida sucessão agora recebem uma resposta que leva ambos em consideração.

Segurança

  • Aumente a versão mínima python-multipart para 0.0.30 para ambos UV e instalações pip, evitando a instalação de versões afetadas por CVE-2026-53539.

[4.0.1] - 02/11/2026

Alterado

  • parlant init --scaffold lead-gen agora cria seu agente com preamble_config=p.PreambleConfiguration.encourage(). Antes de sua primeira ferramenta ligar para o agente diz uma linha curta, como "Deixe-me verificar isso", então o o visitante não fica esperando em silêncio. Sem ele, os preâmbulos não seriam gerenciados: tudo o que o modelo escreveu antes de uma chamada de ferramenta ser concluída.
  • Cada ferramenta nos andaimes lead-gen e retail-store agora possui um narration, como "Verificar quais dias são gratuitos" ou "Acompanhar seu remessa". O chat mostra enquanto a ferramenta é executada, em vez do genérico "Ferramentas de execução".

Corrigido

  • Com o provedor Antrópico, a indexação não falha mais em Claude Opus 4.7 e posterior ou qualquer modelo Claude 5, incluindo as rotas padrão (Sonnet 5.5 e Haiku 5.5). Parlant enviou um temperature, que esses modelos rejeitam com "temperature está obsoleto para este modelo."; agora envia um apenas para Modelos Claude 3 e modelos Claude 4 até 4.6, que ainda aceitam.
  • Um esforço de raciocínio baseado no modelo de Claude Fable agora usa o pensamento adaptativo de um orçamento pensante, que Fable rejeita.
  • Um esforço de raciocínio sobre Claude Opus 4.5 não falha mais. Parlant enviou pensamento adaptativo, que rejeita ("o pensamento adaptativo não é apoiado em este modelo"); agora recebe um orçamento pensado, como fazem Sonnet e Haiku 4.5.

parlant v4.0.2

[4.0.2] - 2026-11-05

Added

  • The chat widget lets the AI agent in a visitor's browser talk to your agent over WebMCP (document.modelContext; in Chrome behind a flag today). On every page it's on, the widget registers an ask_agent tool described with the agent's name. A call starts the widget's conversation if there is none yet, as one an agent holds for the customer (customer_represented_by_an_agent), sends the question through the chat, so it shows there with the reply, opens the chat, and answers the browser agent once the turn has ended. Follow-up calls continue the same conversation. The message carries metadata.parlant_widget.asked_by = "customer_agent", so the chat and your tools can tell the visitor's agent from the visitor. Nothing happens in a browser without WebMCP; webmcp={false} turns it off. ParlantTransport's sendMessage takes an optional metadata argument and ensureSession an option for the flag.
  • Server(session_store=..., customer_store=...) accepts an s3://bucket URL to keep sessions and customers in Amazon S3. Give Parlant a bucket of its own. Credentials come from the AWS credential chain; add ?region= or, for S3-compatible storage, ?endpoint=. The storage must support conditional writes, which keep concurrent servers from overwriting each other's updates. Empty collections survive restarts, and a failed migration write leaves the original data in place. Any query other than a lookup by ID, such as listing sessions, reads every object in the collection, so use MongoDB if you need indexed queries at scale.
  • The chat widget (parlant widget init) takes the agent's picture in one avatar prop: { type: "logo", src }, { type: "photo", src, live? } or { type: "video", src?, poster?, live?, launcher? }. A video avatar plays a short muted loop under the header, scrolls away with the conversation once it starts, and keeps its opened size when the chat is expanded. On the closed launcher, launcher crops it onto the face. Leave out src to use the widget's own video of an agent. live adds the green dot, on the video's corner too, red while the server can't be reached. Use an H.264 MP4 saved with -movflags +faststart; iPhone Safari stalls on WebM.

Changed

  • The chat widget's persistent suggestions stand out from its opening ones: outlined and lettered in the theme's primary color on the chat's background, instead of the grey fill.
  • On phones and tablets, the chat widget closes the on-screen keyboard once a message is sent, whether typed or picked from the suggestions, so the reply isn't hidden behind it.
  • With the LiteLLM provider, review routes now default to gemini/gemini-3.8-flash instead of gemini/gemini-3.6-flash, the same model the Gemini provider already uses for them.
  • The lead-gen scaffold's agent no longer guesses when a visitor asks about the business, its products or their project and its product knowledge has no answer. It says it's a great question but hard to answer properly in the chat, offers to connect them with the team, asks for an email or phone number, and passes the question on with request_team_follow_up. Unrelated questions, existing customers' order questions and prices are handled as before. To make that possible, record_lead now accepts a lead with just a goal and a contact: buying_for and role are optional, and an unknown one scores nothing.
  • parlant dashboard project confirm finishes a local or self-hosted project even when its server already holds sessions, such as from trying the agent. It imports them into the dashboard first, as the dashboard's Sync does, and then completes the setup, so the project no longer stays at "Finish setup". An import that takes longer than about 90 seconds stops with SYNC_IN_PROGRESS; run confirm again to keep waiting for the same import. A failed import stops with SYNC_FAILED and its reason.
  • parlant init --dashboard --json and parlant dashboard project create --json for a local or self-hosted project now list nextSteps, ending with project confirm. The scaffolded AGENTS.md tells coding agents to confirm the project once its server is connected.
  • After creating a managed project whose setup check found how to run it, parlant dashboard project create now points to parlant dashboard --project ID deploy: the first live deploy completes the setup. The dashboard's setup page is optional for reviewing the settings.

Deprecated

  • The chat widget's avatarUrl, avatarStyle and liveIndicator props, in favor of avatar. They still work when avatar isn't set.

Fixed

  • Gemini Argon can replay saved tool calls with their original signed thought blocks instead of unnecessarily falling back to result-only history.
  • Filtering sessions by labels now returns complete pages and working continuation cursors, with consistent total counts in either sort order.
  • MongoDB cursor pagination now preserves $or filters on later pages, so filtered listings no longer include records outside the requested set.
  • Canned responses now retain separate search vectors for their text and every signal, so signals no longer collide in the relevance index. Applies when responses are created or updated; existing indexes are not rebuilt automatically.
  • On iPhone, focusing the chat widget's message box no longer zooms the page in, which pushed the open chat off the right edge of the screen. The box uses a 16px font on touch screens, the size below which iOS zooms.
  • Local and MCP tools now accept comma-separated list arguments without brackets while preserving quoted commas and empty lists.
  • The chat widget's latest message no longer slips under the suggestions and message box when something takes the transcript's space, such as the "Connection interrupted" banner appearing just after a send. The transcript stayed pinned to the bottom only as messages grew, not as its view shrank.
  • Invalid context-variable freshness schedules are rejected before saving, so a failed schedule update leaves the variable's existing data intact.
  • A customer message that arrives while the agent is still working on the previous one now replaces that turn, as intended, even when the engine was in the middle of rejecting a step: a tool call or message turned down by a review hook, by the reviewer, or by moderation. Before, the rejection restarted the step and dropped the pending cancellation, so the agent finished replying to the first message and then answered the second one in a separate turn. Customers who send two messages in quick succession now get one reply that takes both into account.

Security

  • Raise the minimum python-multipart version to 0.0.30 for both uv and pip installations, preventing installation of versions affected by CVE-2026-53539.

[4.0.1] - 2026-11-02

Changed

  • parlant init --scaffold lead-gen now creates its agent with preamble_config=p.PreambleConfiguration.encourage(). Before its first tool call the agent says one short line, such as "Let me check that", so the visitor isn't left waiting in silence. Without it, preambles were unmanaged: whatever the model wrote before a tool call went straight through.
  • Every tool in the lead-gen and retail-store scaffolds now has a narration, such as "Checking which days are free" or "Tracking your shipment". The chat shows it while the tool runs, instead of the generic "Running tools".

Fixed

  • With the Anthropic provider, indexing no longer fails on Claude Opus 4.7 and later or any Claude 5 model, including the default routes (Sonnet 5.5 and Haiku 5.5). Parlant sent a temperature, which those models reject with "temperature is deprecated for this model."; it now sends one only to Claude 3 models and Claude 4 models up to 4.6, which still accept it.
  • A reasoning effort on a Claude Fable model now uses adaptive thinking instead of a thinking budget, which Fable rejects.
  • A reasoning effort on Claude Opus 4.5 no longer fails. Parlant sent it adaptive thinking, which it rejects ("adaptive thinking is not supported on this model"); it now gets a thinking budget, as Sonnet and Haiku 4.5 do.
