Recursos

Use o próprio servidor do vLLM em vez do TRL

trl vllm-serve costumava executar um aplicativo FastAPI personalizado em torno do LLM do vLLM, com sua própria distribuição paralela de dados e uma extensão de trabalho para sincronização de peso. O próprio servidor do vLLM cobre tudo isso. O servidor personalizado desapareceu: trl/scripts/vllm_serve.py cai de 1218 para ~130 linhas e agora traduz seus sinalizadores em vllm serve, imprime o comando equivalente, encaminha qualquer argumento extra e define as três configurações que o TRL precisa (--weight-transfer-config, --logprobs-mode processed_logprobs, --max-logprobs -1). fastapi, uvicorn e pydantic deixam o vllm extra. A sincronização de peso agora usa o mecanismo de transferência de peso NCCL do vLLM – os tensores são anunciados uma vez e transmitidos em uma única transmissão compactada, em vez de uma solicitação HTTP + transmissão por tensor. Os logprobs do professor de destilação vêm do prompt_logprobs. Benchmark (modo de servidor GRPO em H100, Qwen2.5-1.5B / Qwen2.5-VL-3B, mesma semente, mesmos dados): | Configuração | antes | depois | aceleração | | --- | --- | --- | --- | | Texto, TP=1 | 1.08, 0.91 s/passo | 0.63, 0.62 s/passo | 1.59× | | Texto, TP=2 | 0.96, 0.96 s/passo | 0.62, 0.60 s/passo | 1.57× | | VLM,TP=1 | 2.14, 2.13 s/passo | 1.48, 1.48 s/passo | 1.44× | Conclusões de bits idênticos em relação ao servidor antigo (16/16 em 4 prompts × n = 4, logprobs idênticos a 0.0 em 499 tokens). trl vllm-serve ainda aceita os mesmos sinalizadores - agora apenas encaminha para vllm serve. por @qgallouedec em https://github.com/huggingface/trl/pull/6765

Novo AsyncDistillationTrainer experimental (+ MOPD multiprofessor)

Destilação assíncrona de acordo com a política, arquitetada como AsyncGRPOTrainer: um trabalhador de implementação em segundo plano gera as conclusões do próprio aluno e as pontua em relação a um professor atendido por HTTP, de modo que a geração e o treinamento se sobrepõem em vez de se alternarem. O professor nunca é carregado localmente — apenas uma URL do servidor vLLM. Também suporta MOPD (destilação sob política multiprofessor): passe mais de uma entrada em teacher_server_urls e encaminhe cada amostra para um professor por meio de uma coluna teacher_id (por exemplo, um professor de matemática e um professor de código, cada um servido de forma independente).

from trl.experimental.async_distillation import AsyncDistillationConfig, AsyncDistillationTrainer

trainer = AsyncDistillationTrainer(
    model="Qwen/Qwen3-4B",
    args=AsyncDistillationConfig(
        teacher_server_urls=["http://teacher-math:8000", "http://teacher-code:8000"],
        teacher_top_k=16,
    ),
    train_dataset=dataset,  # rows carry a `teacher_id` column for MOPD
)
trainer.train()

por @kashif em https://github.com/huggingface/trl/pull/6705

Exemplos reorganizados em pastas por exemplo

examples/ foi dividido por formato (scripts/ vs notebooks/), que dispersou arquivos relacionados (por exemplo, sft_nemotron_3 existia como um script e um notebook, em pastas diferentes; os notebooks OpenEnv viviam separados dos scripts OpenEnv). Tudo agora é uma pasta por história — o nome indica o método e a tarefa (grpo_wordle, sft_gpt_oss, ppo_tldr), e a pasta contém todos os arquivos que o exemplo precisa (scripts, notebooks, prompts, modelos de chat, código de avaliação). Os scripts de demonstração finos de treinador único foram removidos (eles residem em trl/scripts/ e cada página de documento do treinador tem um snippet executável). Os links antigos examples/scripts/… e examples/notebooks/… GitHub / Colab serão 404 - vale a pena sinalizar em postagens posteriores. por @qgallouedec em https://github.com/huggingface/trl/pull/6820

trl v1.11.0

Features

Use vLLM's own server instead of TRL's

trl vllm-serve used to run a custom FastAPI app around vLLM's LLM, with its own data-parallel fan-out and a worker extension for weight sync. vLLM's own server covers all of that. The custom server is gone: trl/scripts/vllm_serve.py drops from 1218 to ~130 lines and now translates its flags into vllm serve, prints the equivalent command, forwards any extra argument, and sets the three settings TRL needs (--weight-transfer-config, --logprobs-mode processed_logprobs, --max-logprobs -1). fastapi, uvicorn and pydantic leave the vllm extra.

Weight sync now uses vLLM's NCCL weight-transfer engine — tensors are announced once and streamed in a single packed broadcast, instead of one HTTP request + broadcast per tensor. Distillation teacher logprobs come from prompt_logprobs.

Benchmark (GRPO server-mode on H100, Qwen2.5-1.5B / Qwen2.5-VL-3B, same seed, same data):

| Setup | before | after | speedup | | --- | --- | --- | --- | | Text, TP=1 | 1.08, 0.91 s/step | 0.63, 0.62 s/step | 1.59× | | Text, TP=2 | 0.96, 0.96 s/step | 0.62, 0.60 s/step | 1.57× | | VLM, TP=1 | 2.14, 2.13 s/step | 1.48, 1.48 s/step | 1.44× |

Bit-identical completions vs the old server (16/16 over 4 prompts × n=4, logprobs identical to 0.0 over 499 tokens). trl vllm-serve still accepts the same flags — it just forwards to vllm serve now.

by @qgallouedec in https://github.com/huggingface/trl/pull/6765

New experimental AsyncDistillationTrainer (+ multi-teacher MOPD)

Async on-policy distillation, architected like AsyncGRPOTrainer: a background rollout worker generates the student's own completions and scores them against a teacher served over HTTP, so generation and training overlap instead of alternating. The teacher is never loaded locally — just a vLLM server URL.

Also supports MOPD (multi-teacher on-policy distillation): pass more than one entry in teacher_server_urls and route each sample to a teacher via a teacher_id column (e.g. a math teacher and a code teacher, each served independently).

from trl.experimental.async_distillation import AsyncDistillationConfig, AsyncDistillationTrainer

trainer = AsyncDistillationTrainer(
    model="Qwen/Qwen3-4B",
    args=AsyncDistillationConfig(
        teacher_server_urls=["http://teacher-math:8000", "http://teacher-code:8000"],
        teacher_top_k=16,
    ),
    train_dataset=dataset,  # rows carry a `teacher_id` column for MOPD
)
trainer.train()

by @kashif in https://github.com/huggingface/trl/pull/6705

Examples reorganized into per-example folders

examples/ was split by format (scripts/ vs notebooks/), which scattered related files (e.g. sft_nemotron_3 existed as both a script and a notebook, in different folders; OpenEnv notebooks lived apart from OpenEnv scripts). Everything is now one folder per story — the name says the method and the task (grpo_wordle, sft_gpt_oss, ppo_tldr), and the folder holds every file the example needs (scripts, notebooks, prompts, chat templates, eval code). Thin single-trainer demo scripts are removed (they live in trl/scripts/ and each trainer doc page has a runnable snippet). Old examples/scripts/… and examples/notebooks/… GitHub / Colab links will 404 — worth flagging in downstream posts.

by @qgallouedec in https://github.com/huggingface/trl/pull/6820
