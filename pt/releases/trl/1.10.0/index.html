🎓 DistillationTrainer agora é um treinador estável

Após uma refatoração de ~30-PR que remodelou seu contrato de dados, caminho de perda, pilha de geração, superfície de configuração e testes, DistillationTrainer e DistillationConfig passaram de trl.experimental.distillation para o pacote trl de nível superior. Mesma superfície de importação que SFT/DPO/GRPO/KTO. O antigo caminho experimental ainda funciona e emite um FutureWarning (remoção em v2.0.0).

# Before
from trl.experimental.distillation import DistillationConfig, DistillationTrainer

# Now
from trl import DistillationConfig, DistillationTrainer

Também pousa um trl distillation CLI e move os testes para tests/. O arco de refatoração completo: trocou colunas de assinatura para prompt (formato messages obsoleto), fixou a pilha de geração em GRPOs, conectou a perda JSD fragmentada e excluiu o caminho logit completo, limpou o caminho Liger para compartilhar a extração com o caminho fragmentado, adotou o temporização log() / training_step / _save_checkpoint do GRPO, reconstruiu o conjunto de testes para o formato GRPO e muito mais. por @qgallouedec em cerca de 30 PRs (#6479, #6480, #6481, #6482, #6484, #6487, #6497, #6508, #6509, #6510, #6511, #6512, #6513, #6521, #6522, #6523, #6524, #6525, #6526, #6530, #6537, #6604, #6605, #6606, #6607, #6609, #6610, #6611, #6612, #6613, #6614, #6629, #6630, #6632, #6633, #6634, #6639, #6640, #6641, #6642, #6643, #6644, #6645, #6647, #6653).

AsyncGRPO: treinamento de agente proprietário de loop (armazenamento OpenEnv)

Novo caminho experimental de propriedade de loop (caixa preta) para AsyncGRPOTrainer — para treinar agentes externos como opencode que executam seu próprio loop de ferramenta, em vez de TRL conduzir cada curva como no caminho de caixa branca environment_factory. O agente é executado em uma sessão OpenEnv no modo transparent_proxy; um proxy no sandbox captura os IDs de token e logprobs de cada turno. Após a conclusão, o TRL lê o rastreamento, reconstrói as linhas de treinamento por turno e pontua o espaço de trabalho com o verify() da sessão. É fornecido com três ganchos de política fornecidos pelo chamador (rollout_reward_fn, train_turn_fn, agent_turn_fn) para que você possa eliminar chamadas auxiliares da estrutura (gerador de títulos, resumidor de contexto) e reforçar apenas as curvas desejadas. Inclui um examples/scripts/openenv/opencode.py independente (sandbox de subprocesso local + verificador stdin/stdout retido DeepCoder), validado de ponta a ponta em Qwen3-4B. por @AmineDiro em https://github.com/huggingface/trl/pull/6420, mais variante HF-sandbox por @sergiopaniego em https://github.com/huggingface/trl/pull/6565

Exemplo SFT de difusão em bloco DiffusionGemma

Um novo exemplo SFT para google/diffusiongemma-26B-A4B-it implementando a receita de referência: um bloco de resposta por etapa, corrupção aleatória uniforme de token com t ~ U(eps, 1), autocondicionamento de duas passagens, entropia cruzada plana em toda a tela mais uma co-perda autoregressiva no codificador. LoRA visa atenção + lineares MLP densos. Requer transformers >= 5.12.0. Vem com modelos de bate-papo diffusion_gemma.jinja / diffusion_gemma_training.jinja (com marcadores {% generation %}) para que assistant_only_loss=True funcione imediatamente. por @kashif em https://github.com/huggingface/trl/pull/6003

trl v1.10.0

Features

🎓 DistillationTrainer is now a stable trainer

After a ~30-PR refactor that reshaped its data contract, loss path, generation stack, config surface, and tests, DistillationTrainer and DistillationConfig graduate from trl.experimental.distillation to the top-level trl package. Same import surface as SFT / DPO / GRPO / KTO. The old experimental path still works and emits a FutureWarning (removal in v2.0.0).

# Before
from trl.experimental.distillation import DistillationConfig, DistillationTrainer

# Now
from trl import DistillationConfig, DistillationTrainer

Also lands a trl distillation CLI and moves the tests to tests/. The full refactor arc: switched signature columns to prompt (deprecated messages-format), pinned the generation stack to GRPO's, wired the chunked JSD loss and deleted the full-logit path, cleaned the Liger path to share extraction with the chunked path, adopted GRPO's log() / training_step timing / _save_checkpoint, rebuilt the test suite to GRPO shape, and much more.

by @qgallouedec across ~30 PRs (#6479, #6480, #6481, #6482, #6484, #6487, #6497, #6508, #6509, #6510, #6511, #6512, #6513, #6521, #6522, #6523, #6524, #6525, #6526, #6530, #6537, #6604, #6605, #6606, #6607, #6609, #6610, #6611, #6612, #6613, #6614, #6629, #6630, #6632, #6633, #6634, #6639, #6640, #6641, #6642, #6643, #6644, #6645, #6647, #6653).

AsyncGRPO: loop-owning agent training (OpenEnv harness)

New experimental loop-owning (black-box) path for AsyncGRPOTrainer — for training external agents like opencode that run their own tool loop, rather than TRL driving each turn as in the environment_factory white-box path.

The agent runs in an OpenEnv session in transparent_proxy mode; an in-sandbox proxy captures each turn's token ids and logprobs. On completion, TRL reads the trace, rebuilds per-turn training rows, and scores the workspace with the session's verify(). Ships with three caller-supplied policy hooks (rollout_reward_fn, train_turn_fn, agent_turn_fn) so you can drop framework aux calls (title generator, context summarizer) and reinforce only the turns you want.

Includes a self-contained examples/scripts/openenv/opencode.py (local subprocess sandbox + DeepCoder held-out stdin/stdout verifier), validated end-to-end on Qwen3-4B.

by @AmineDiro in https://github.com/huggingface/trl/pull/6420, plus HF-sandbox variant by @sergiopaniego in https://github.com/huggingface/trl/pull/6565

DiffusionGemma block-diffusion SFT example

A new SFT example for google/diffusiongemma-26B-A4B-it implementing the reference recipe: one response block per step, uniform random token corruption with t ~ U(eps, 1), two-pass self-conditioning, flat cross-entropy over the whole canvas plus an autoregressive co-loss on the encoder. LoRA targets attention + dense MLP linears. Requires transformers >= 5.12.0.

Ships with diffusion_gemma.jinja / diffusion_gemma_training.jinja chat templates (with {% generation %} markers) so assistant_only_loss=True works out of the box.
