Existe um [guia](https://huggingface.co/docs/trl/neuron) para acompanhá-lo. O Neuron recompila uma vez por forma de entrada, portanto, uma execução não preenchida para cerca de um minuto em cada novo comprimento de sequência. `pad_to_multiple_of` agora tem como padrão `"auto"`: 128 no Neuron, `None` em outros lugares, então nada muda na GPU. Trainium2, Qwen3-0.6B SFT, 20 passos: **130 s com o padrão contra 260 s sem**. * Adicione um guia para treinamento no AWS Trainium por @qgallouedec em https://github.com/huggingface/trl/pull/7729 * Padrão `pad_to_multiple_of` para `"auto"` por @qgallouedec em https://github.com/huggingface/trl/pull/7724 * Execute o cabeçote LM fundido e os núcleos de destilação em dispositivos sem Triton por @qgallouedec em https://github.com/huggingface/trl/pull/7669 *Relate o dispositivo Neuron em `trl env` e telemetria por @qgallouedec em https://github.com/huggingface/trl/pull/7672 * Suporte qualquer acelerador no descarregamento de ativação por @qgallouedec em https://github.com/huggingface/trl/pull/7670 ### 🌳 Atenção à árvore para AsyncGRPO AsyncGRPO agora empacota cada linha de microlote como uma **árvore de prefixo** em vez de uma sequência simples. As implementações multivoltas e multigerações repetem muitos prefixos: em um prompt compartilhado, esses tokens costumavam ser encaminhados uma vez por linha. A Tree Packing os encaminha uma vez. ```text rollout 0: [ prompt ] [ completion A ] prompt ──┬── completion A ── later turn rollout 1: [ prompt ] [ completion B ] => └── completion B rollout 2: [ prompt ] [ completion A ] [ … ] ``` Cadeias sem bifurcação colapsam em segmentos, e as consultas de cada segmento atendem ao K/V reunido ao longo de seu caminho da raiz ao segmento em uma única chamada FA3 varlen. Sem tensor de máscara: cada camada, exceto atenção, é executada uma vez por token exclusivo e apenas K/V é duplicado ao longo de prefixos compartilhados. trl v1.16.0

Features

🛠️ TRL now trains on AWS Trainium

<img width="1672" height="941" alt="Neon Warehouse_ AWS and Trainium Support" src="https://github.com/user-attachments/assets/dcb6e2a1-0f7c-4635-819b-a1ec6f5e143b" />

The fused LM head from v1.15 is what made Neuron tractable; the remaining gaps are closed here. There is a guide to go with it.

Neuron recompiles once per input shape, so an unpadded run stalls about a minute on every new sequence length. pad_to_multiple_of now defaults to "auto": 128 on Neuron, None elsewhere, so nothing changes on GPU. Trainium2, Qwen3-0.6B SFT, 20 steps: 130 s with the default against 260 s without.

  • Add a guide for training on AWS Trainium by @qgallouedec in https://github.com/huggingface/trl/pull/7729
  • Default pad_to_multiple_of to "auto" by @qgallouedec in https://github.com/huggingface/trl/pull/7724
  • Run the fused LM head and distillation kernels on devices without Triton by @qgallouedec in https://github.com/huggingface/trl/pull/7669
  • Report the Neuron device in trl env and telemetry by @qgallouedec in https://github.com/huggingface/trl/pull/7672
  • Support any accelerator in activation offloading by @qgallouedec in https://github.com/huggingface/trl/pull/7670

🌳 Tree attention for AsyncGRPO

AsyncGRPO now packs every micro-batch row as a prefix tree instead of a flat sequence. Multi-turn and multi-generation rollouts repeat a lot of prefix: on a shared prompt, those tokens used to be forwarded once per row. Tree packing forwards them once.

rollout 0:  [ prompt ] [ completion A ]              prompt ──┬── completion A ── later turn
rollout 1:  [ prompt ] [ completion B ]        =>             └── completion B
rollout 2:  [ prompt ] [ completion A ] [ … ]

Chains without a fork collapse into segments, and each segment's queries attend to the K/V gathered along its root-to-segment path in a single FA3 varlen call. No mask tensor: every layer except attention runs once per unique token, and only K/V is duplicated along shared prefixes.

Qwen3-1.7B, 32K tokens per rollout, forward + backward:

| layout | packing ratio | sequence packing | tree packing | peak GiB | | --- | --- | --- | --- | --- | | shared prompt | 1.00 | 8677 ms | 8737 ms (0.99×) | 35.2 → 35.2 | | shared prompt | 2.29 | 8266 ms | 4341 ms (1.90×) | 35.2 → 18.0 | | shared prompt | 3.37 | 8179 ms | 2755 ms (2.97×) | 35.2 → 13.6 | | nested fork | 1.60 | 8557 ms | 6217 ms (1.38×) | 35.2 → 23.8 | | nested fork | 3.56 | 8172 ms | 2635 ms (3.10×) | 35.2 → 13.5 |

There is no packing option to choose: with nothing shared a tree row is exactly the old sequence packing, at a ~1% cost.

by @AmineDiro in https://github.com/huggingface/trl/pull/7328

Muse Spark Open

Support for meta-models/Muse-Spark-Open-816B-A42B: the tiny-model script, coverage in the VLM tests (SFT, DPO, KTO, chat-template utils, fused LM head), and a LoRA SFT example on 8 nodes of 8×H100 with DistributedConfig(fsdp_size=64, ep_size=8), token dispatch and packing. Measured at 14.2 s/step, 131k tokens/step, 40.2 GB per GPU.

Needs transformers>=5.20.0; the adapter save additionally needs transformers#49500 with peft 0.21.2.

by @qgallouedec in https://github.com/huggingface/trl/pull/7536
