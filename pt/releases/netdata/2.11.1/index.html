#netdata v2.11.1

#Release notes

Netdata v2.11.1 é uma versão de patch para solucionar problemas descobertos desde v2.11.0.

Este é um lançamento de patch maior do que o normal, focado na correção de consultas, estabilidade do mecanismo de banco de dados, robustez da conectividade em nuvem, eficiência de integridade/alerta e desligamento e segurança durante a vida útil do processo, juntamente com uma série de correções de coletor e plataforma, incluindo cobertura mais ampla do SQL Server e melhorias de CPU e disco do Windows.

Mecanismo de consulta

  • Valores exatos de SUM preservados quando um ponto armazenado abrange linhas de resultados ou um limite de nível de armazenamento automático e linhas de base de soma incremental preservadas para que os buckets contendo apenas uma amostra de abertura não produzam mais consultas vazias (#23512, #23505, @ktsaou)
  • Manteve os carimbos de data e hora API independentes da retenção de cada Agente, de modo que a mesma solicitação explícita ou relativa retorne os mesmos carimbos de data e hora de linha entre os Agentes (#23507, @ktsaou)
  • Atribuição de RESET de nível 0 e evidência de anomalia à linha de resultados que realmente contém a amostra de origem e contagens fixas de contribuidores de taxa de anomalia em consultas agrupadas de duas passagens (#23504, #23508, @ktsaou)
  • Aplicado options=absolute a pontos obtidos do nível de entrada durante uma mudança de plano, de modo que um valor negativo não possa mais cruzar uma transição de nível inalterado (#23503, @ktsaou)
  • Correção de um operador lógico no wrapper JSON para que dimensões não consultadas sejam excluídas conforme esperado, a menos que todas as dimensões sejam solicitadas (#23639, @stelfrag)

Mecanismo de banco de dados

  • Corrigido um uso após livre e um fatal em consultas de extensão mescladas, adquirindo referências de cache de página antes de publicar detalhes da página e sincronizando a desmontagem de consultas de extensão mesclada sob o spinlock de extensão (#23475, #23521, @stelfrag)
  • Corrigida uma dupla ausência de métricas MRG obsoletas durante a migração do diário v2 e um vazamento de contador de lote de liberação vazio que poderia deixar o desligamento ou a rotação do arquivo de dados aguardando indefinidamente (#23560, #23699, @stelfrag)
  • Prevenção de relatórios de retenção de níveis negativos e baseados em época: sem truncamento de 32 bits ao formatar durações, tempos de início desconhecidos ou zero tratados como indisponíveis, diários vazios ignorados e retenção extrapolada limitada (#23648, @stelfrag)
  • Cadências de páginas válidas superiores a um dia foram aceitas em vez de tratá-las como inválidas e emitir telemetria de reparo falsa (#23514, @ktsaou)
  • Evitou a criação/liberação de rotatividade do mapa UUID e contenção de bloqueio de gravação de partição durante pesquisas de métricas MRG e incluiu cache completo e identidade de página em mensagens fatais do PGC para tornar diagnosticáveis problemas de cache (#23538, #23522, @stelfrag)
  • Atualizado o SQLite incluído para 3.53.4 (#23511, @stelfrag)
  • Reparadas as cargas de trabalho de teste de estresse -W createdataset e dbengine, que travavam em um alocador de rótulos NULL, carimbavam cada amostra gerada com o relógio de parede em vez do intervalo de tempo solicitado e liberavam duas vezes o estado na desmontagem do host (#23758, @stelfrag)

Conectividade em nuvem (ACLK)

  • Adicionado nome de host TLS e verificação de IP para solicitações ACLK HTTPS, preservando o comportamento de modo inseguro (#23463, @stelfrag)
  • Interrupção do relatório de certificados autoassinados dispensados como falhas de verificação de certificado no modo inseguro, para que erros de E/S ou HTTP posteriores sejam relatados como realmente são (#23732, @stelfrag)
  • Mudou os HTTPS e MQTT clients para tempos limite monotônicos baseados em microssegundos com um watchdog de progresso de E/S e pesquisa pré-CONNACK limitada para um segundo para que um peer silencioso não possa mais atrasar o desligamento em até 60 segundos (#23105, #23733, @stelfrag)
  • Parou de contar PUBACKs MQTT ausentes como confirmações bem-sucedidas, rastreando-os com um contador de tempo limite dedicado que agora é preservado em desconexões sem tocar em um client liberado (#23486, #23734, @stelfrag)
  • Buffers de resposta agrupados preservados e seus metadados para respostas ACLK compactadas e mascaramento WebSocket fixo de cargas que abrangem limites de buffer de anel (#23485, @stelfrag)

Saúde e alertas

  • Corrigido o alerta 10min_cpu_usage do Windows anexado aos gráficos service.*_cpu_utilization e disparando alarmes CRÍTICOS falsos (#23559, @thiagoftsm)
  • Alertas indexados por nome por host, substituindo verificações de alerta de host completo durante a resolução de variáveis de integridade (#23554, @stelfrag)
  • Evitou a reinicialização de protótipos de alerta quando os metadados do gráfico não foram alterados, de modo que novos registros contínuos do gráfico filho não acionem mais reavaliações repetidas de integridade (#23515, @stelfrag)
  • Criação de resumos de alertas gerados somente quando uma notificação é realmente enviada, evitando trabalho por iteração e um potencial impasse de ordem de bloqueio com remoção de gráfico (#23544, @stelfrag)
  • Correção de uma verificação de erro incorreta na preparação de instruções SQL no código do banco de dados de integridade e remoção de dois índices health_log_detail não utilizados para reduzir o armazenamento do banco de dados pai e a manutenção da árvore B (#23545, #23722, @stelfrag)

Metadados, rótulos e internos

  • Destruição de dicionário adiada enquanto os dicionários APIs estão em andamento, tornando set/get/delete e travessia segura contra destruição simultânea durante o desligamento (#23634, @stelfrag)
  • Corrigido um uso após liberação na coleta de lixo do dicionário quando um retorno de chamada de exclusão entrava novamente no coletor e liberava o sucessor em cache no meio da caminhada e parava as coleções de visualização deixando para trás os itens excluídos do mestre (#23819, @stelfrag)
  • Impediu que o ceifador de gráfico obsoleto liberasse um gráfico que outro subsistema ainda faz referência, o que deixou um gráfico não indexado segurando seu bloqueio de destruição e poderia fatal um coletor que ainda estivesse gravando nele (#23761, @stelfrag)
  • Desmontagem adiada da fila do trabalhador de aprendizado de máquina até que todos os coletores tenham parado, de modo que um coletor que sobreviva ao prazo de desligamento não possa mais abortar em um mutex de fila destruído (#23757, @stelfrag)
  • Redefinir e desbloquear o SIGPIPE em filhos gerados, para que uma criança cujos pipes estejam fechados saia em vez de sobreviver no EPIPE - que havia bloqueado centenas de processos powermetrics no macOS - relatou falha na entrega do sinal em vez de descartá-lo silenciosamente e tornou os testes de regressão do servidor spawn determinísticos (#23751, #23815, @stelfrag)
  • Testado o suporte KSM antes de ativar a desduplicação de página em vez de assumi-la, para que os kernels não suportados não relatem mais erros de KSM e limitem a marcação KSM aos pools de páginas do dbengine que podem realmente mesclar (#23822, @stelfrag)
  • Ignorou a higienização e reinternou metadados de gráfico inalterados em registros repetidos de gráfico e aumentou a versão do rótulo apenas em mutações reais do rótulo (#23603, #23513, @stelfrag)
  • Corrigido um problema de limpeza de buffer de texto e uma corrida de dimensionamento de árvore dyncfg durante atualizações de configuração simultâneas (#23657, @stelfrag)
  • Substituído sprintf() por snprintfz() limitado na formatação numérica inicfg e substituído strings de formato de caminho /proc/net/dev dinâmico por literais (#23638, #23450, @stelfrag)
  • Redução da sobrecarga de pulso executando a coleta mallinfo2() em um intervalo configurável e alinhado ao pulso, carimbando-o após a conclusão para que uma chamada lenta não possa monopolizar o ciclo de trabalho e interrompendo os solavancos redundantes da versão dos metadados do gráfico de pulso (#23579, #23736, #23650, @stelfrag)
  • Removida uma sonda de rótulo por gráfico dos gráficos filhos de pulso, contando com a comparação da versão do rótulo do host; em um pai com 808 filhos, a sonda foi responsável por cerca de 23% do segmento de pulso principal e deixou lacunas nos gráficos netdata.* que emite (#23760, @stelfrag)
  • Silenciamos uma descoberta do Coverity e corrigimos comentários obsoletos e diagnósticos de teste de unidade, incluindo a documentação do comportamento do sinalizador de inicialização de integridade enquanto uma criança está desconectada (#23553, #23737, #23541, @stelfrag)

Colecionadores e exportação

  • Corrigida a análise de /proc/interrupts quando o primeiro contador é colado ao ID de interrupção, o que poderia forçar a alteração dos valores do contador em IDs de dimensão e causar crescimento ilimitado de dimensão (#23651, @stelfrag)
  • Coleta de soquete limitada a uma tentativa verificada por namespace de rede, para que falhas auxiliares não acionem mais tentativas repetidas de coleta para cada registro de soquete (#23778, @ktsaou)
  • Interrompeu o coletor UPS go.d incorporando o comando completo em erros de conexão, que registrava a credencial PASSWORD em texto não criptografado; apenas os argumentos USERNAME e PASSWORD são editados, portanto, outros comandos permanecem diagnosticáveis (#23782, @stelfrag)
  • SQL COUNT saturado resulta no coletor ibm.d AS/400 antes de reduzi-los para int, portanto, uma contagem fora do intervalo não pode mais envolver o negativo e alterar silenciosamente os limites de cardinalidade (#23783, @stelfrag)
  • Corrigida a transformação do medidor MikroTik no coletor SNMP go.d e removido átomos desalinhados do mecanismo de gráfico go.d (#23525, #23540, @ilyam8)
  • Pontuação válida preservada em nomes de host de telnet OpenTSDB e prefixos de métrica, enquanto ainda substitui espaços em branco, caracteres de controle e delimitadores que corromperiam registros de telnet (#23749, @stelfrag)
  • Corrigida a mensagem do gráfico desativado charts.d.plugin apontando para charts.d.plugin.conf em vez do charts.d.conf real (#23662, @ilyam8)
  • SQL Server: adicionou um fallback de cache de plano (sys.dm_exec_query_stats) para top-queries quando o Query Store está indisponível ou desabilitado e recorreu à sessão system_health integrada para error-info quando nenhuma sessão dedicada de Eventos Estendidos está configurada (#23748, @thiagoftsm)
  • SQL Server: reforçou as consultas de função entre edições, testando a edição e a versão do mecanismo uma vez por instância e roteando consultas com escopo de servidor versus consultas com escopo de banco de dados adequadamente, para que top-queries, deadlock-info e error-info funcionem no Banco de Dados SQL do Azure e na Instância Gerenciada, bem como no SQL Server local (#23564, @ilyam8)
  • SQL Server: corrigiu o impasse e as consultas de informações de erro no SQL Server 2014 e anteriores, detectando o Query Store por coluna de catálogo em vez da versão do produto e lendo o caminho event_file do catálogo da sessão em vez de assumir que corresponde ao nome da sessão (#23460, @thiagoftsm)
  • SQL Server: excluiu trabalhos desabilitados do SQL Agent da coleção por padrão (defina collect_disabled_jobs: true para mantê-los) e bloqueou os alertas de trabalho no trabalho que está sendo habilitado, de modo que a última execução com falha de um trabalho desabilitado não mantenha mais um alerta gerado (#23645, @ilyam8)
  • Windows: coletamos métricas de CPU do objeto de performance Processor Information, mapeando suas instâncias NumaNode,NumaIndex para CPUs lógicas através da topologia do processador, para que hosts com mais de 64 processadores lógicos sejam reportados corretamente; o objeto Processor legado ainda é usado onde Processor Information não está disponível (#23549, @thiagoftsm)
  • Windows: adicionado exclude space metrics on paths em [plugin:windows:PerflibStorage] para manter volumes lógicos indesejados (como montagens de backup temporárias) fora da coleção de espaço em disco, adicionado um rótulo de volume serial_number e corrigido o rótulo driver_type com erro ortográfico para drive_type (#23660, @thiagoftsm)

Instalação e embalagem

  • Windows: correção da reivindicação quando apenas um token é fornecido e marcação do token de reivindicação e proxy como propriedades MSI ocultas para que não apareçam mais nos logs detalhados do instalador (#23547, @thiagoftsm; #23735, @stelfrag)
  • Restringiu o plugin eBPF para userlands de 64 bits e resolveu o conjunto de ferramentas Go do tipo de máquina userland em vez da arquitetura do kernel (#23446, @stelfrag)
  • macOS: resolveu os IOKit APIs dinamicamente em vez de vinculá-los diretamente, restaurando compilações em macOS SDKs mais antigos (#23421, @stelfrag)

netdata v2.11.1

Release notes

Netdata v2.11.1 is a patch release to address issues discovered since v2.11.0.

This is a larger-than-usual patch release focused on query correctness, database engine stability, Cloud connectivity robustness, health/alert efficiency, and shutdown and process-lifetime safety, along with a number of collector and platform fixes, including broader SQL Server coverage and Windows CPU and disk improvements.

Query engine

  • Preserved exact SUM values when a stored point spans result rows or an automatic storage-tier boundary, and preserved incremental-sum baselines so buckets holding only an opening sample no longer produce empty queries (#23512, #23505, @ktsaou)
  • Kept API timestamps independent of each Agent's retention, so the same explicit or relative request returns the same row timestamps across Agents (#23507, @ktsaou)
  • Attributed tier-0 RESET and anomaly evidence to the result row that actually contains the source sample, and fixed anomaly-rate contributor counts in two-pass group-by queries (#23504, #23508, @ktsaou)
  • Applied options=absolute to points fetched from the incoming tier during a plan switch, so a negative value can no longer cross a tier transition unchanged (#23503, @ktsaou)
  • Fixed a logical operator in the JSON wrapper so unqueried dimensions are excluded as expected unless all dimensions are requested (#23639, @stelfrag)

Database engine

  • Fixed a use-after-free and a fatal in merged extent queries by acquiring page-cache references before publishing page details and synchronizing merged extent query teardown under the extent spinlock (#23475, #23521, @stelfrag)
  • Fixed a double free of stale MRG metrics during journal v2 migration, and an empty flush-batch counter leak that could leave shutdown or datafile rotation waiting indefinitely (#23560, #23699, @stelfrag)
  • Prevented negative and epoch-based tier retention reporting: no 32-bit truncation when formatting durations, unknown or zero start times treated as unavailable, empty journals ignored, and extrapolated retention capped (#23648, @stelfrag)
  • Accepted valid page cadences longer than one day instead of treating them as invalid and emitting false repair telemetry (#23514, @ktsaou)
  • Avoided UUID map create/free churn and partition write-lock contention during MRG metric lookups, and included full cache and page identity in PGC fatal messages to make cache issues diagnosable (#23538, #23522, @stelfrag)
  • Updated the bundled SQLite to 3.53.4 (#23511, @stelfrag)
  • Repaired the -W createdataset and dbengine stress-test workloads, which crashed on a NULL labels allocator, stamped every generated sample with the wall clock instead of the requested time range, and double-freed state at host teardown (#23758, @stelfrag)

Cloud connectivity (ACLK)

  • Added TLS hostname and IP verification for ACLK HTTPS requests, while preserving insecure-mode behavior (#23463, @stelfrag)
  • Stopped reporting waived self-signed certificates as certificate verification failures in insecure mode, so later I/O or HTTP errors are reported for what they are (#23732, @stelfrag)
  • Switched the HTTPS and MQTT clients to monotonic, microsecond-based timeouts with an I/O progress watchdog, and bounded pre-CONNACK polling to one second so a quiet peer can no longer delay shutdown by up to 60 seconds (#23105, #23733, @stelfrag)
  • Stopped counting missing MQTT PUBACKs as successful acknowledgements, tracking them with a dedicated timeout counter that is now preserved across disconnects without touching a freed client (#23486, #23734, @stelfrag)
  • Preserved pooled response buffers and their metadata for compressed ACLK responses, and fixed WebSocket masking of payloads spanning ring-buffer boundaries (#23485, @stelfrag)

Health and alerts

  • Fixed the Windows 10min_cpu_usage alert attaching to service.*_cpu_utilization charts and firing false CRITICAL alarms (#23559, @thiagoftsm)
  • Indexed alerts by name per host, replacing full-host alert scans during health-variable resolution (#23554, @stelfrag)
  • Avoided re-initializing alert prototypes when chart metadata has not changed, so continuous child-chart re-registrations no longer trigger repeated health re-evaluation (#23515, @stelfrag)
  • Built raised-alert summaries only when a notification is actually sent, avoiding per-iteration work and a potential lock-order deadlock with chart removal (#23544, @stelfrag)
  • Fixed an incorrect error check on SQL statement preparation in the health database code, and removed two unused health_log_detail indexes to reduce parent database storage and B-tree maintenance (#23545, #23722, @stelfrag)

Metadata, labels and internals

  • Deferred dictionary destruction while dictionary APIs are in flight, making set/get/delete and traversal safe against concurrent destruction during shutdown (#23634, @stelfrag)
  • Fixed a use-after-free in dictionary garbage collection when a delete callback re-entered the collector and freed the cached successor mid-walk, and stopped view collections leaving master-deleted items behind (#23819, @stelfrag)
  • Stopped the obsolete-chart reaper from freeing a chart another subsystem still references, which left an unindexed chart holding its destroy lock and could fatal a collector still writing to it (#23761, @stelfrag)
  • Deferred machine-learning worker queue teardown until after all collectors have stopped, so a collector that outlives the shutdown deadline can no longer abort on a destroyed queue mutex (#23757, @stelfrag)
  • Reset and unblocked SIGPIPE in spawned children, so a child whose pipes are closed exits instead of surviving on EPIPE — which had stranded hundreds of powermetrics processes on macOS — reported failed signal delivery instead of dropping it silently, and made the spawn-server regression tests deterministic (#23751, #23815, @stelfrag)
  • Probed for KSM support before enabling page deduplication instead of assuming it, so unsupported kernels no longer report KSM errors, and limited KSM marking to the dbengine page pools that can actually merge (#23822, @stelfrag)
  • Skipped sanitizing and re-interning unchanged chart metadata on repeated chart registration, and incremented the label version only on actual label mutations (#23603, #23513, @stelfrag)
  • Fixed a text-buffer cleanup issue and a dyncfg tree sizing race during concurrent configuration updates (#23657, @stelfrag)
  • Replaced sprintf() with bounded snprintfz() in inicfg numeric formatting, and replaced dynamic /proc/net/dev path format strings with literal ones (#23638, #23450, @stelfrag)
  • Reduced pulse overhead by running mallinfo2() collection on a configurable, pulse-aligned interval, stamping it after completion so a slow call cannot monopolize the duty cycle, and stopped redundant pulse chart metadata version bumps (#23579, #23736, #23650, @stelfrag)
  • Removed a per-chart label probe from the pulse child charts, relying on the host label-version compare instead; on a parent with 808 children the probe accounted for about 23% of the main pulse thread and left gaps in the netdata.* charts it emits (#23760, @stelfrag)
  • Silenced a Coverity finding and corrected stale comments and unit-test diagnostics, including documenting health-initialization flag behavior while a child is disconnected (#23553, #23737, #23541, @stelfrag)

Collectors and exporting

  • Fixed /proc/interrupts parsing when the first counter is glued to the interrupt ID, which could push changing counter values into dimension IDs and cause unbounded dimension growth (#23651, @stelfrag)
  • Bounded socket collection to one verified attempt per network namespace, so helper failures no longer trigger repeated collection attempts for every socket record (#23778, @ktsaou)
  • Stopped the go.d UPS collector embedding the full command in connection errors, which logged the PASSWORD credential in clear text; only USERNAME and PASSWORD arguments are redacted, so other commands stay diagnosable (#23782, @stelfrag)
  • Saturated SQL COUNT results in the ibm.d AS/400 collector before narrowing them to int, so an out-of-range count can no longer wrap negative and silently change the cardinality limits (#23783, @stelfrag)
  • Corrected the MikroTik gauge transform in the go.d SNMP collector, and removed unaligned atomics from the go.d chart engine (#23525, #23540, @ilyam8)
  • Preserved valid punctuation in OpenTSDB telnet hostnames and metric prefixes, while still replacing whitespace, control characters, and delimiters that would corrupt telnet records (#23749, @stelfrag)
  • Fixed the charts.d.plugin disabled-chart message pointing to charts.d.plugin.conf instead of the actual charts.d.conf (#23662, @ilyam8)
  • SQL Server: added a plan-cache fallback (sys.dm_exec_query_stats) for top-queries when Query Store is unavailable or disabled, and fell back to the built-in system_health session for error-info when no dedicated Extended Events session is configured (#23748, @thiagoftsm)
  • SQL Server: hardened the function queries across editions, probing engine edition and version once per instance and routing server-scoped versus database-scoped queries accordingly, so top-queries, deadlock-info and error-info work on Azure SQL Database and Managed Instance as well as on-premises SQL Server (#23564, @ilyam8)
  • SQL Server: fixed the deadlock and error-info queries on SQL Server 2014 and older, detecting Query Store by catalog column instead of product version, and reading the event_file path from the session catalog instead of assuming it matches the session name (#23460, @thiagoftsm)
  • SQL Server: excluded disabled SQL Agent jobs from collection by default (set collect_disabled_jobs: true to keep them) and gated the job alerts on the job being enabled, so a disabled job's last failed run no longer keeps an alert raised (#23645, @ilyam8)
  • Windows: collected CPU metrics from the Processor Information performance object, mapping its NumaNode,NumaIndex instances to logical CPUs via the processor topology, so hosts with more than 64 logical processors are reported correctly; the legacy Processor object is still used where Processor Information is unavailable (#23549, @thiagoftsm)
  • Windows: added exclude space metrics on paths under [plugin:windows:PerflibStorage] to keep unwanted logical volumes (such as temporary backup mounts) out of disk space collection, added a volume serial_number label, and corrected the misspelled driver_type label to drive_type (#23660, @thiagoftsm)

Installation and packaging

  • Windows: fixed claiming when only a token is provided, and marked the claim token and proxy as hidden MSI properties so they no longer appear in verbose installer logs (#23547, @thiagoftsm; #23735, @stelfrag)
  • Restricted the eBPF plugin to 64-bit userlands and resolved the Go toolchain from the userland machine type rather than the kernel architecture (#23446, @stelfrag)
  • macOS: resolved the IOKit APIs dynamically instead of linking them directly, restoring builds against older macOS SDKs (#23421, @stelfrag)
