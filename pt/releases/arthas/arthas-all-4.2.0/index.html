#arthas arthas-all-4.2.0

Visão geral da mudança

  • façanha: profiler atualizou o perfil assíncrono integrado para 4.4, removeu a ação obsoleta check, atualizou o valor opcional --cstack para fp|dwarf|vm|vmx|no e corrigiu problemas relacionados a travamento do Zing JVM, consulte #3186 #3199
  • chore: Tempo limite padrão da sessão estendido de 30 minutos para 3 horas, substituindo os padrões as.sh, arthas.properties e Shell Server
  • correção: corrige a falha de mapeamento do ClassLoader do classloader-metaspace causada pela contagem inconsistente de classe oculta/classe de array quando o ID do carregador JFR está faltando e reduz o ruído do log de diagnóstico, consulte #3198
  • correção: corrige o problema de que o fechamento normal pode esperar indefinidamente quando o servidor MCP é interrompido. Feche cada componente e adicione um tempo limite de 5 segundos e continue a limpar o executor da tarefa. Veja #3194
  • correção: Corrige o problema em que a resposta HTTP Streamable do MCP fecha a conexão, mas não envia Connection: close, fazendo com que o cliente reutilize a conexão fechada e o teste de integração falhe ocasionalmente, consulte #3200
  • chore: Remova a opção de download obsoleta do --use-http, repo-mirror continua a suportar URL do repositório aliyun/center/HTTP, o download usa HTTPS por padrão, consulte #3189 -chore: o pipeline de lançamento usa JDK 21 para construir o fatjar do Tunnel Server e requer que a correspondência de ativos de lançamento seja bem-sucedida, consulte #3192
  • documentos: atualize a descrição do Arthas 4.x com suporte para JDK 8+ (incluindo JDK 17/21/25) e adicione a entrada da barra lateral do documento classloader-metaspace, AI/MCP, consulte #3195

arthas arthas-all-4.2.0

Highlights

  • Profiler jumps to async-profiler 4.4 (#3186, #3199) — The bundled async-profiler is upgraded, fixing Zing JVM crashes, but it carries two breaking edits: the deprecated check action is removed and --cstack now accepts only fp|dwarf|vm|vmx|no. Any scripts invoking profiler check or passing older --cstack values (e.g. none) will fail and must be updated before adoption.
  • Download defaults to HTTPS; --use-http removed (#3189) — The deprecated --use-http flag is gone and downloads now default to HTTPS. repo-mirror still supports aliyun/center and arbitrary HTTP repository URLs, so private mirrors keep working, but automation passing --use-http will now error out and needs that flag dropped.
  • Session timeout tripled to 3 hours — The default session timeout goes from 30 minutes to 3 hours across as.sh, arthas.properties, and the Shell Server. Long investigations are far less likely to drop mid-session, but idle attached agents hold resources much longer — factor that into capacity planning.
  • MCP shutdown and connection fixes (#3194, #3200) — Important if you embed the MCP Server: graceful stop now applies a 5-second timeout per component while still draining the task executor, so shutdown can no longer hang indefinitely (#3194); and Streamable HTTP responses now send Connection: close when closing, stopping clients from reusing dead connections and eliminating integration-test flakiness (#3200).
  • classloader-metaspace reliability (#3198) — ClassLoader mapping failures caused by missing JFR loader IDs are fixed by reconciling hidden/array class counts, with diagnostic log noise reduced. Users who saw inconsistent or missing mappings on hidden/array-class-heavy workloads should now get stable output.
  • Build and docs housekeeping (#3192, #3195) — Tunnel Server fatjar is now built on JDK 21 with a hard requirement that release assets match, tightening artifact integrity; docs confirm Arthas 4.x supports JDK 8+ (including 17/21/25) and add sidebar entries for classloader-metaspace and AI/MCP. No action required unless you build Arthas releases yourself.

变更概览

  • feat: profiler 升级内置 async-profiler 到 4.4，移除已废弃的 check action，并将 --cstack 可选值更新为 fp|dwarf|vm|vmx|no，修复 Zing JVM 崩溃相关问题，见 #3186 #3199
  • chore: 默认 session timeout 从 30 分钟延长到 3 小时，覆盖 as.sh、arthas.properties 和 Shell Server 默认值
  • fix: 修复 classloader-metaspace 在 JFR loader id 缺失时对 hidden class / array class 计数不一致导致的 ClassLoader 映射失败，并降低诊断日志噪音，见 #3198
  • fix: 修复 MCP Server stop 时 graceful close 可能无限等待的问题，关闭各组件增加 5 秒超时并继续清理 task executor，见 #3194
  • fix: 修复 MCP Streamable HTTP 响应关闭连接但未发送 Connection: close 导致客户端复用已关闭连接、集成测试偶发失败的问题，见 #3200
  • chore: 移除已废弃的 --use-http 下载选项，repo-mirror 继续支持 aliyun / center / HTTP repository URL，下载默认使用 HTTPS，见 #3189
  • chore: release 流水线使用 JDK 21 构建 Tunnel Server fatjar，并要求 release asset 匹配成功，见 #3192
  • docs: 更新 Arthas 4.x 支持 JDK 8+（含 JDK 17 / 21 / 25）的说明，并补充 classloader-metaspace、AI/MCP 文档侧边栏入口，见 #3195
