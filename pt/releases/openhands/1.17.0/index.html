OpenHands v1.17.0

Highlights

  • Node 24 becomes the floor for Agent Canvas — PR #17009 requires Node 24 for the canvas runtime. This is the upgrade that will actually break people: self-hosters and anyone building the canvas must move their toolchain to Node 24 or builds fail outright. Treat it as the first migration step, not an optional bump.

  • "Canvas Extensions" are now "Apps" — PR #17064 renames the concept across the codebase. The rename is more than cosmetic if you script against or reference "extensions" in configs, docs, or automation manifests — audit those references after upgrading. Two companion fixes matter for anyone installing custom apps: PR #17072 correctly joins the local extension source and path, and PR #17120 finally surfaces the install failure reason instead of a silent error.

  • Automation permissions split into view vs. manage — PR #17105 breaks the old single automation permission into separate view and manage scopes, with a creator escape hatch. This is an access-control behavior change: review existing role assignments, because a user who could previously manage automations may now only be able to view them unless they created them.

  • Security: DOMPurify sanitization bypass patched — PR #17060 fixes a sanitization bypass in DOMPurify. If the canvas renders any untrusted HTML, this is the strongest reason to take the release promptly — it's a defense-in-depth fix you don't want to lag on. Alongside it, PR #16908 adds a --disable-telemetry runtime flag for self-hosted canvas, which matters for privacy-conscious or air-gapped deployments that previously had no clean opt-out.

  • Component defaults bumped across the stack — agent-server to 1.45.0, automation to 1.11.1, and SDK to 1.46.0 (PRs #17238, #17203, #17086, #16970), with the automation SDK version lookup refactored to React Query (#16982). Fresh deployments adopt these automatically, but if you pin component versions explicitly you'll need to advance them manually to avoid version-skew bugs.

  • New capabilities and behavioral changes to watch — local Agent Canvas Planner support (#16178), generic custom automation manifests (#17129), cloud LLM provider connections (#16757), and automation runs that are now task-outcome aware (#16937) expand what you can build. Behaviorally, workspace hooks now auto-load on conversation start (#16971), plugin queries are scoped to the active backend (#16891), and subscription LLM configs preserve their base_url (#16089) — the last two are quiet fixes that can change which backend or endpoint your requests actually hit.
