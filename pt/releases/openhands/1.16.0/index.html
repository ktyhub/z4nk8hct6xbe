OpenHands v1.16.0

Highlights

  • Explicit skill allow-list — Skills are no longer exposed through an all-on catalog; review your skill configuration after upgrading so required capabilities remain enabled. Disabled skills are now forwarded through agent_context, keeping backend enforcement aligned with the UI (#16860, #16812).
  • Canvas Extensions frontend — Extension pages, sidebar controls, and customization are now available in the product UI (#16895). Canvas telemetry is correlated with conversation identity, while baked working_dir values are scoped to the default-local backend to avoid affecting other backend types (#16796, #16759).
  • Provider setup and switching — Settings now support selecting providers and toggling agent LLM switching; API keys are validated before connection setup advances, and provider pickers follow pagination instead of stopping at the default page size (#16772, #16441, #16840, #16758). Default and free-model selections were also corrected (#16922).
  • Self-hosted desktop onboarding — Linux desktop installer CI and Debian packaging are included, bundled npm is restored on Windows, and the VS Code button now renders for local backends (#16656, #16381, #16106). A user-added Local backend with a usable LLM can also bypass onboarding (#16931).
  • Automation observability and load control — Runs expose their live phase, while bounded history fan-out and paused sidebar polling reduce unnecessary backend and UI load for automation-heavy workspaces (#16740, #16867).
  • Upgrade impact — No breaking changes are explicitly flagged; test custom integrations against software-agent-sdk 1.44.0, automation 1.9.0, and extensions 0.19.0 (#16968).
