OpenHands v1.41.0

Highlights

  • ACP capability negotiation — Reasoning-effort choices now come from what the agent reports, reducing client/model mismatches, while focus and remount refresh login status. Custom ACP integrations should verify both behaviors against their agents (#19436, #19729).
  • Proxy and plain-HTTP deployments — UUID generation no longer requires crypto.randomUUID() on non-loopback HTTP origins, and MCP OAuth callbacks now use the browser-facing backend URL. These fixes remove environment-specific failures, though proxies must still expose the correct callback URL (#19732, #19744).
  • Managed-App secret handling — Automatic managed-App enablement reuses profile secret consent, and requested secrets can now be securely replaced. Admins should review consent scope because setup can proceed without repeated approval (#18572, #19062).
  • Browser verification coverage — Verification scenarios now exercise map controls and browser timezone beyond happy paths, making interactive and locale-sensitive regressions easier to catch before release (#19670).
  • Canvas runtime security — The Canvas image advances to Debian snapshot 20261114 for linux-libc-dev security fixes. Rebuild derived images or update pinned snapshots to inherit the patch (#19786).
  • Compatibility — No breaking changes are called out in this release; contributors should refresh dependencies for the ESLint 10 bump (#19507).
