OpenHands cloud-1.39.0

Highlights

  • Default-org onboarding and tenancy model — 1.39.0 reshapes identity for self-hosted (OHE) installs: existing users are auto-migrated into a default org on first auto-add (#14740), the first signed-in user becomes its owner via a new is_default flag (#14752), and unclaimed automation events are routed there on single-org installs (#14745). Admins gain hide_personal_workspaces (#14741) and an explicit OH_DEPLOYMENT_MODE flag to gate the enterprise-cloud CTA (#14794). Watch the invitation flow: links now auto-accept and are copyable and matched by verified email at sign-in (#14786, #14758, #14759), so email-delivery-based invite processes change behavior.

  • ACP model switching and MCP support — Cloud conversations get a switch_acp_model proxy endpoint (#14744) with a model dropdown and credential fields in agent settings (#14733), plus MCP server config for ACP agents (#14613). Two follow-ups are required for the picker to actually render: error bodies are sanitized in the proxy (#14760) and acp_server is surfaced on cloud conversations (#14797). Note the cloud start-path change that reverts bootstrap-prompt resume while enabling acp_isolate_data_dir (#14722).

  • Multi-model discovery, BYOK, and org LLM profiles — OHE now discovers models across proxies with BYOK gating and a catalogue union (#14773), and org-level LLM profiles become editable in settings (#14715). A cluster of frontend fixes stabilizes the profile UX: blank-field defaults (#14782), preserved base URLs (#14776), provider-first API-key rendering (#14787), form hydration (#14789), and auth-field dedupe (#14893). Managed litellm_proxy/ URLs are remapped to openhands/ on settings load (#14766) and keys are reconciled per (user, org) (#14803) — audit stored provider configs after upgrading.

  • SDK/agent-server 1.29.0 and a breaking config cleanup — The release rides SDK bumps to 1.27.0/1.28.0/1.29.0 (#14726, #14753, #14889) and agent-server to 1.29.0, including a Gemini cache fix (#14751). The migration hazard: acp_env was removed in SDK 1.29.0 and its footprint purged (#14921), so any deployment or integration still supplying it must drop it. A clear error now surfaces when a custom sandbox image's agent-server SDK mismatches (#14883).

  • Security hardening sweep — A broad CVE/GHSA patch batch lands: pyjwt 2.13.0 (#14854), tornado 6.5.7 (#14856), aiohttp 3.14.1 (#14871), starlette 1.3.1 (#14874), bleach 6.4.0 (#14945), msgpack 1.2.1 (#14944), jupyter-server 2.20.0 (#14943), pypdf 6.13.3 (#14959), and frontend deps including the postcss XSS fix (#14770) and dompurify (#14956). Beyond version bumps, PluginSpec credentials are redacted during serialization (#14795), API-key Bearer auth is decoupled from Keycloak offline sessions (#14867), and CORS header handling is corrected (#14835) — security-sensitive adopters should prioritize this release.

  • Migration and behavioral watch-outs — Sandbox concurrency is now derived from the runtime /list API instead of the is_paused DB flag (#14834); a SaaS migration handles pause state (#14829) and migration 122 is renumbered to 123 after dropping is_paused (#14840), backed by an integrity check (#14689) — verify your migration chain before upgrading. Conversation-limit enforcement shipped (#14168) and was reverted in the same release (#14877), so don't build against it yet, and secret names are now validated as env-var format (#12980).
