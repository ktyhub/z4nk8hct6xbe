OpenHands v1.35.0

Highlights

  • Server-backed conversation state — Workspace/repository metadata and sidebar pin/archive state now persist as server-side conversation tags (#16666, #18697), while cloud repository selection can be remembered and cleared (#19053). Organization now follows the conversation rather than a single browser session; self-hosters should include these tags in backup and retention handling.
  • Faster, less runtime-dependent chat startup — Conversations open with inline progress before the runtime is ready, and saved Cloud history is compacted, prefetched during navigation, and replayed without probing unavailable runtimes (#19155, #19194, #19195, #19203, #19248). Inactive panels are also deferred (#19153). E2E tests assuming raw tool-event rows should account for grouped hooks, reasoning, and tool calls (#19084).
  • More flexible event-driven automations — A new Events view for webhook sources, per-source event-type lists, and clone-URL storage for Bitbucket Data Center repositories improve multi-source setup (#19034, #19025, #19023). Templates now match instance integrations (#19101), keep_alive is editable (#19125), and saving an Event trigger preserves its destination (#19239).
  • Stronger recovery and attachment delivery — Sending a message resumes paused sandboxes; Cloud attachments reach the runtime workspace and survive navigation; transient failures recover without repeated errors (#19186, #19158, #19159, #19144). Initial Cloud history failures are retried before socket fallback (#19207), and saved terminal output is restored during replay (#19220).
  • Self-hosted launcher behavior — LAN opt-in is honored, startup diagnostics are corrected, an occupied port 3001 triggers a free-port fallback, and ingress/static services restart after exit (#18363, #19230, #19256). Deployment scripts and proxies should use the reported startup URL instead of assuming port 3001.
  • ACP profiles and agent-server compatibility — ACP launches now include enabled catalog skills (#18834), so ACP-hosted agents receive the intended skill set. The agent-server dependency moves to 1.59.0 (#19057); custom backend or ACP integrations should smoke-test skill discovery and session startup after upgrading.

No breaking changes noted.

macOS install note

The app isn't signed with an Apple Developer ID yet, so macOS may call a downloaded build "damaged" — it's Gatekeeper quarantine, not a bad file. After moving the app to Applications, clear the flag once, then open normally:

xattr -dr com.apple.quarantine "/Applications/OpenHands Agent Canvas.app"

Signing + notarization is tracked in OpenHands/OpenHands#16774.
