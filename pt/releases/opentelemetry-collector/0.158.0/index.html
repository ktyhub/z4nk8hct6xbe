Usuário final Changelog

🚀 Novos componentes 🚀

  • processor/queuebatch: Novo queuebatchprocessor para substituir o legado batchprocessor. (#15047, #13582, #12022, #11308, #8272, #6046) A nova implementação é baseada no exporterhelper, usa a mesma configuração do sending_queue.

💡 Melhorias 💡

  • cmd/mdatagen: Adicione aliases de tipo estendido de primeira classe (int64, duração, opaque_string, id, opaque_map, etc.) para esquemas de configuração em metadata.yaml (#15513) Os autores agora podem escrever type: int64, type: duration, type: opaque_string, type: id ou type: opaque_map diretamente como um tipo de propriedade na seção config: de metadata.yaml. Cada alias se expande para a representação correta do esquema JSON e do tipo Go automaticamente. Os usos existentes dos tipos de esquema JSON padrão, format: e x-customType: permanecem suportados sem migração.
  • extension/memory_limiter: Promova a extensão do limitador de memória para estabilidade beta. (#14533)

🧰 Correções de bugs 🧰

  • cmd/mdatagen: Remove a linha extra na documentação.md em torno da descrição (#15664)
  • cmd/mdatagen: Habilita automaticamente métricas v1 quando a métrica legada está habilitada e o feature gate v1 está ativado (#15650) Quando o recurso v1 está habilitado e uma métrica legada está habilitada, o correspondente A métrica v1 agora está habilitada programaticamente para que os usuários não precisem adicionar a métrica v1 para sua configuração.
  • cmd/mdatagen: Corrige aviso de colisão incorreto para métricas versionadas com nomes emitidos diferentes (#15648) A detecção de colisão de mesmo nome (verificações de tipo/atributo) estava sendo usada para métricas versionadas com nomes diferentes. Isso fez com que a métrica herdada fosse desativada, o que estava incorreto e também uma mensagem de aviso estava sendo registrada incorretamente informando que as métricas tinham o mesmo nome quando em na verdade eles tinham nomes diferentes.
  • cmd/mdatagen: Métricas versionadas não lidam com atributos renomeados com o mesmo tipo (#15595) As métricas versionadas precisam suportar a emissão de atributos legados e mais recentes quando o nome da métrica é o mesmo, mas o os nomes dos atributos diferem. Isso não funcionou quando o nome dos atributos mudou, mas o tipo permaneceu o mesmo. Aqui adicionamos suporte a métricas versionadas com atributos renomeados onde esses atributos têm o mesmo tipo.
  • exporter/debug: corrige a formatação de atributos de amostra de perfil para valores não string (#15647) Anteriormente, valores não-string produziam saída malformada, como %!s(int64=42). Os atributos de amostra de perfil agora usam o formato de atributo digitado do exportador de depuração, como Int(42). Isso também mudará as strings de hello-world para Str(hello-world).
  • pkg/config/configtls: Corrige vazamento de goroutine e descritor de arquivo quando client_ca_file_reload está habilitado (#9221) Cada chamada para ServerConfig.LoadTLSConfig com client_ca_file_reload habilitado iniciava um goroutine do observador de arquivos que nunca poderia ser interrompida, pois o recarregador não estava acessível do *tls.Config retornado. O arquivo client CA agora é verificado quanto a alterações enquanto o TLS apertos de mão são servidos, no máximo uma vez por segundo, combinando como reload_interval já recarrega o certificado do servidor. Nenhuma goroutine em segundo plano é iniciada, então nada resta atrás quando um servidor é demolido e recriado.

opentelemetry-collector v0.158.0

Images and binaries here: https://github.com/open-telemetry/opentelemetry-collector-releases/releases/tag/v0.158.0

End User Changelog

🚀 New components 🚀

  • processor/queuebatch: New queuebatchprocessor to replace the legacy batchprocessor. (#15047, #13582, #12022, #11308, #8272, #6046) New implementation is based exporterhelper, uses same configuration as sending_queue.

💡 Enhancements 💡

  • cmd/mdatagen: Add first-class extended type aliases (int64, duration, opaque_string, id, opaque_map, etc.) to config schemas in metadata.yaml (#15513) Authors can now write type: int64, type: duration, type: opaque_string, type: id, or type: opaque_map directly as a property type in the config: section of metadata.yaml. Each alias expands to the correct JSON Schema representation and Go type automatically. Existing uses of standard JSON Schema types, format:, and x-customType: remain supported without migration.

  • extension/memory_limiter: Promote the memory limiter extension to beta stability. (#14533)

🧰 Bug fixes 🧰

  • cmd/mdatagen: Removes the extra line in the documentation.md around description (#15664)

  • cmd/mdatagen: Auto-enable v1 metrics when legacy metric is enabled and v1 feature gate is on (#15650) When the v1 feature gate is enabled and a legacy metric is enabled, the corresponding v1 metric is now programmatically enabled so users don't need to add the v1 metric to their config.

  • cmd/mdatagen: Fix incorrect collision warning for versioned metrics with different emitted names (#15648) Same name collision detection (type/attribute checks) was being used for versioned metrics with different names. This caused the legacy metric to be disabled which was incorrect and also a warning msg was being incorrectly logged that stated the metrics had the same name when in fact they had different names.

  • cmd/mdatagen: Versioned metrics don't handle renamed attributes with same type (#15595) Versioned metrics need to support emitting legacy and latest attributes when the metric name is the same but the attributes names differ. This was not working when the attributes name changed but the type remained the same. Here we add support to versioned metrics with renamed attributes where those attributes have the same type.

  • exporter/debug: Fix profile sample attribute formatting for non-string values (#15647) Previously, non-string values produced malformed output such as %!s(int64=42). Profile sample attributes now use the debug exporter's typed attribute format, such as Int(42). This will also change strings from hello-world to Str(hello-world).

  • pkg/config/configtls: Fix goroutine and file descriptor leak when client_ca_file_reload is enabled (#9221) Every call to ServerConfig.LoadTLSConfig with client_ca_file_reload enabled started a file watcher goroutine that could never be stopped, since the reloader was not reachable from the returned *tls.Config. The client CA file is now checked for changes while TLS handshakes are served, at most once per second, matching how reload_interval already reloads the server certificate. No background goroutine is started, so nothing is left behind when a server is torn down and recreated.
