Usuário final Changelog

🚩 Depreciações 🚩

  • pkg/confighttp: Preterem campos simples de keepalive em client e configuração do servidor em favor da nova seção keepalive. (#14020) Os seguintes campos de configuração client foram descontinuados em favor da seção keepalive:
    • idle_conn_timeout -> keepalive::idle_conn_timeout
    • max_idle_conns -> keepalive::max_idle_conns
    • max_idle_conns_per_host -> keepalive::max_idle_conns_per_host
    • disable_keep_alives: true -> keepalive::enabled: false Os seguintes campos de configuração do servidor foram descontinuados em favor da seção keepalive:
    • idle_timeout -> keepalive::idle_timeout
    • keep_alives_enabled: false -> keepalive::enabled: false Os campos obsoletos definidos na configuração continuam funcionando exatamente como antes e produzem um aviso de descontinuação quando o client ou servidor é criado. Configurando campos obsoletos juntos com a nova seção keepalive é um erro. O código que migra dos campos obsoletos pode usar o novo NewDefaultKeepaliveClientConfig e funções NewDefaultKeepaliveServerConfig para construir uma seção keepalive com o valores padrão.

💡 Melhorias 💡

  • all: Versão Bump go em todos os go.mod para 1.26.0, abandone o suporte em 1.25.0 (#15799)
  • all: Declarar suporte para windows/amd64 nível 1 e windows/arm64 nível 2 (#15786)
  • pkg/confmap: Remove o auxiliar isStringyStructure morto (não utilizado desde (#12793) Este é um caminho de código interno não exportado, sem nenhuma alteração de comportamento voltada para o usuário.
  • pkg/exporterhelper: Armazena em cache o tamanho da solicitação por tipo de dimensionador para que o lote de tamanho de byte não recalcule mais o tamanho do proto serializado de todo o lote acumulado em cada solicitação consumida. (#12636) Com sizer: bytes, a verificação MinSize do batcher chamada BytesSize(), que ignorou o tamanho do cache e percorreu novamente o protobuf do lote inteiro em cada solicitação consumida, acumulando O (n ^ 2) no número de solicitações mescladas. O tamanho agora é armazenado em cache separadamente para as dimensões de bytes e itens e mantido de forma incremental durante a fusão/divisão, portanto a verificação é O(1). Um único o cache não digitado não pôde ser reutilizado com segurança porque o batcher e a fila podem peça diferentes tipos de medidores na mesma solicitação.
  • processor/memory_limiter: relata apenas o status de integridade do componente limitador de memória quando o estado de integridade muda. (#15751)

🧰 Correções de bugs 🧰

  • cmd/mdatagen: permite sublinhados em IDs de portas de recurso para compatibilidade com nomes de componentes com sublinhados (#15592)
  • pkg/pprofile: adicione verificações de limites a FromLocationIndices e switchDictionary (#15697) FromLocationIndices agora retorna um erro em vez de entrar em pânico quando está fora do intervalo ou índice de localização negativo, espelhando FromAttributeIndices. As verificações de índice usadas ao mesclar perfis agora também rejeitam índices negativos. Estes eram anteriormente acessíveis com um índice negativo decodificado de uma carga útil OTLP, que entrou em pânico com o coletor via Profiles.MergeTo.
  • pkg/service: roteia erros internos do OpenTelemetry SDK (por exemplo, exportações de métricas/log/rastreamento com falha) por meio do registrador configurado do coletor em vez do manipulador de erros global padrão do OTel SDK, que sempre é impresso em stderr via log.Print, independentemente da codificação de log configurada. (#12378)

opentelemetry-collector v0.160.0

Images and binaries here: https://github.com/open-telemetry/opentelemetry-collector-releases/releases/tag/v0.160.0

End User Changelog

🚩 Deprecations 🚩

  • pkg/confighttp: Deprecate flat keepalive fields in client and server config in favor of the new keepalive section. (#14020) The following client configuration fields are deprecated in favor of the keepalive section:
    • idle_conn_timeout -> keepalive::idle_conn_timeout
    • max_idle_conns -> keepalive::max_idle_conns
    • max_idle_conns_per_host -> keepalive::max_idle_conns_per_host
    • disable_keep_alives: true -> keepalive::enabled: false The following server configuration fields are deprecated in favor of the keepalive section:
    • idle_timeout -> keepalive::idle_timeout
    • keep_alives_enabled: false -> keepalive::enabled: false Deprecated fields set in the configuration keep working exactly as before and produce a deprecation warning when the client or server is created. Setting deprecated fields together with the new keepalive section is an error. Code migrating off the deprecated fields can use the new NewDefaultKeepaliveClientConfig and NewDefaultKeepaliveServerConfig functions to build a keepalive section with the default values.

💡 Enhancements 💡

  • all: Bump go version in all go.mod to 1.26.0, drop support on 1.25.0 (#15799)

  • all: Declare windows/amd64 tier 1 and windows/arm64 tier 2 support (#15786)

  • pkg/confmap: Remove dead isStringyStructure helper (unused since (#12793) This is an internal, unexported code path with no user-facing behavior change.

  • pkg/exporterhelper: Cache the request size per sizer type so byte-sized batching no longer recomputes the serialized proto size of the whole accumulated batch on every consumed request. (#12636) With sizer: bytes, the batcher's MinSize check called BytesSize(), which ignored the cached size and re-walked the entire batch's protobuf on every consumed request, making accumulation O(n^2) in the number of merged requests. The size is now cached separately for the bytes and items dimensions and maintained incrementally during merge/split, so the check is O(1). A single untyped cache could not be reused safely because the batcher and the queue may ask for different sizer types on the same request.

  • processor/memory_limiter: Only report memory limiter component health status when the health state changes. (#15751)

🧰 Bug fixes 🧰

  • cmd/mdatagen: Allow underscores in feature gate IDs for compatibility with component names with underscores (#15592)

  • pkg/pprofile: add bounds checks to FromLocationIndices and switchDictionary (#15697) FromLocationIndices now returns an error instead of panicking on an out-of-range or negative location index, mirroring FromAttributeIndices. The index checks used when merging profiles now also reject negative indices. These were previously reachable with a negative index decoded from an OTLP payload, which panicked the collector via Profiles.MergeTo.

  • pkg/service: Route OpenTelemetry SDK-internal errors (e.g. failed metric/log/trace exports) through the collector's configured logger instead of the OTel SDK's default global error handler, which always printed to stderr via log.Print regardless of the configured log encoding. (#12378)

API Changelog

🛑 Breaking changes 🛑

  • pkg/service: telemetry.Factory.CreateResource and telemetry.CreateResourceFunc now return (pcommon.Resource, string, error) instead of (pcommon.Resource, error) to expose the resource's schema URL. (#15129) The telemetry.Factory interface is experimental and cannot be implemented externally (it has an unexported method). Callers using telemetry.WithCreateResource must update the function signature to return a third string value for the schema URL.

🚩 Deprecations 🚩

  • pkg/confighttp: Deprecate flat keepalive fields in client and server config in favor of the new keepalive section. (#14020) The following client configuration fields are deprecated in favor of the keepalive section:
    • idle_conn_timeout -> keepalive::idle_conn_timeout
    • max_idle_conns -> keepalive::max_idle_conns
    • max_idle_conns_per_host -> keepalive::max_idle_conns_per_host
    • disable_keep_alives: true -> keepalive::enabled: false The following server configuration fields are deprecated in favor of the keepalive section:
    • idle_timeout -> keepalive::idle_timeout
    • keep_alives_enabled: false -> keepalive::enabled: false Deprecated fields set in the configuration keep working exactly as before and produce a deprecation warning when the client or server is created. Setting deprecated fields together with the new keepalive section is an error. Code migrating off the deprecated fields can use the new NewDefaultKeepaliveClientConfig and NewDefaultKeepaliveServerConfig functions to build a keepalive section with the default values.

💡 Enhancements 💡

  • pkg/component: Add ResourceSchemaURL field to component.TelemetrySettings to expose the collector resource's schema URL to components. (#15129)
  • pkg/exporterhelper: Migrate TimeoutConfig to schema-based configuration generated by mdatagen. (#15505)

🧰 Bug fixes 🧰

  • pkg/pprofile: add bounds checks to FromLocationIndices and switchDictionary (#15697) FromLocationIndices now returns an error instead of panicking on an out-of-range or negative location index, mirroring FromAttributeIndices. The index checks used when merging profiles now also reject negative indices. These were previously reachable with a negative index decoded from an OTLP payload, which panicked the collector via Profiles.MergeTo.
