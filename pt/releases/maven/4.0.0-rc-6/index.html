maven maven-4.0.0-rc-6

Notas

Este novo release candidate do Maven 4 foi lançado para obter feedback dos usuários. O Maven 4 restringiu algumas coisas em comparação ao Maven 3, então certifique-se de executar a ferramenta mvnup antes de tentar seu projeto com o Maven 4.

Problemas corrigidos desde RC-5

Todos os problemas conhecidos relatados nos RC-5 release notes foram corrigidos:

  • Bug de configuração do bean — o estado de acessibilidade do campo foi armazenado em cache globalmente, causando falhas de injeção de configuração do plugin. Corrigido em #11433.
  • Problema de simultaneidade no API v4 — um ConcurrentModificationException foi corrigido em #11429.
  • Embalagem BOM — a conversão POM do consumidor para projetos BOM agora preserva corretamente as versões de dependência. Corrigido em #11464.
  • macOS Gatekeeper — os binários nativos JLine extraídos que acionaram o Gatekeeper foram removidos da distribuição (#11997). A solução alternativa xattr do RC-5 não é mais necessária.

Problemas de compatibilidade conhecidos

A seguir estão problemas de compatibilidade conhecidos ao usar o Maven 4. Executando mvnup antes de construir com O Maven 4 corrigirá muitos problemas comuns de versão do plugin automaticamente. Os problemas abaixo estão aqueles que requerem intervenção manual ou correções upstream.

Validação POM mais rigorosa

O Maven 4 impõe uma validação mais rigorosa que o Maven 3. Os projetos podem precisar corrigir seus POMs:

  • Elementos XML duplicados — <artifactId>, <properties>, etc. duplicados agora são rejeitados (erro Duplicated tag). Corrija o POM de origem.
  • Declarações de dependência duplicadas — o mesmo groupId:artifactId declarado duas vezes agora é rejeitado (must be unique).
  • Expressões não interpoladas — Expressões ${...} em URLs de repositório, IDs de gerenciamento de distribuição e outros campos que o Maven 3 aceitou silenciosamente agora são rejeitados.
  • XML inválido em POMs transitivos — instruções de processamento ilegais ou prefixos de namespace não declarados em POMs transitivos causam erros Non-parseable POM.
  • Propriedades em caminhos <module> — Maven 4 não interpola mais propriedades como ${spark.version} em elementos <module> no momento da leitura do POM.
  • Versões compatíveis com CI — projetos que usam ${revision} sem flatten-maven-plugin podem encontrar erros de versão de dependência ausentes.
  • Solicitação de coleta inválida — dependências transitivas com expressões de versão ${...} não interpoladas são rejeitadas.

Mudanças na resolução de dependências transitivas

O TransitiveDependencyManager do Maven 4 aplica dependencyManagement em todas as profundidades transitivas (o Maven 3 aplicou-o apenas no primeiro nível). Isso é intencional, mas pode alterar as versões resolvidas:

  • As dependências anteriores no caminho de classe podem desaparecer — adicione declarações explícitas. Consulte #12302.
  • As regras de versão maven-enforcer-plugin podem ser acionadas devido ao downgrade de versões transitivas.
  • license-maven-plugin pode relatar novas dependências transitivas que não estão na lista de permissões.
  • A verificação do recurso Karaf pode falhar devido a incompatibilidades de versão do pacote OSGi.

Compatibilidade de plug-ins e extensões

Alguns plugins e extensões requerem versões específicas para Maven 4:

  • Quarkus — versões anteriores a 3.20 usam padrões ServiceLocator/RepositorySystem incompatíveis com DI baseado em Sisu do Maven 4. Atualize para Quarkus 3.20+.
  • Tycho — versões anteriores ao 5.0 usam padrões de injeção Guice/Sisu quebrados pelo Maven 4. Atualize para Tycho 5.0.3+.
  • Extensão Desenvolvecity Maven — falha na inicialização devido a alterações no carregamento de classe SLF4J (ClassNotFoundException: SimpleLogger).
  • pgpverify-maven-plugin — versões anteriores a 1.20 atingiram um ClassCastException com o resolvedor do Maven 4. Consulte resolver#1957.
  • cyclonedx-maven-plugin — falha com Invalid Version Range Request ao usar versões compatíveis com CI ${revision}.
  • maven-site-plugin — A renderização do modelo Velocity pode falhar com versões de plugin de site incompatíveis.
  • maven-shade-plugin — dependency-reduced-pom.xml pode causar erro The parents form a cycle.
  • commons-release-plugin — clean-staging falha no Maven 4.

Mudanças no carregamento de classe

  • Plugins que dependem do layout de classe do Maven 3 podem encontrar erros de "importações estrangeiras" (por exemplo, plug-ins Quarkus, JAXB).
  • O roteamento de repositório baseado em prefixo do Maven 4 pode bloquear artefatos que não correspondem a /.meta/prefixes.txt.

Formatação pós-mvnup

  • spotless-maven-plugin e sortpom-maven-plugin podem relatar violações de formatação após mvnup modificar arquivos POM. Execute novamente o formatador após mvnup.

Outro

  • POMs upstream quebrados — por exemplo, hadoop-project 3.1.0–3.3.0 tem XML inválido (<Xlint:-unchecked/>) causando erros de análise. Eles precisam de correções upstream rastreadas em HADOOP-19923.
  • Ordenação de elementos POM do Enforcer — O construtor de modelos do Maven 4 reordena os elementos POM em uma ordem canônica, o que pode quebrar as regras do aplicador, verificando a ordenação dos elementos.
  • Manuseio do SNAPSHOT — Os artefatos do SNAPSHOT podem ser exibidos como "presentes, mas indisponíveis" no tratamento diferente de metadados do resolvedor do Maven 4.

maven maven-4.0.0-rc-6

Notes

This new release candidate of Maven 4 is released to get feedback from users. Maven 4 has restricted a few things compared to Maven 3, so make sure to run the mvnup tool before trying your project with Maven 4.

Issues fixed since RC-5

All known issues reported in the RC-5 release notes have been fixed:

  • Bean configuration bug — field accessibility state was cached globally, causing plugin configuration injection failures. Fixed in #11433.
  • Concurrency issue in the v4 API — a ConcurrentModificationException was fixed in #11429.
  • BOM packaging — consumer POM conversion for BOM projects now correctly preserves dependency versions. Fixed in #11464.
  • macOS Gatekeeper — the extracted JLine native binaries that triggered Gatekeeper have been removed from the distribution (#11997). The xattr workaround from RC-5 is no longer needed.

Known compatibility issues

The following are known compatibility issues when using Maven 4. Running mvnup before building with Maven 4 will fix many common plugin version issues automatically. The issues below are those that require manual intervention or upstream fixes.

Stricter POM validation

Maven 4 enforces stricter validation than Maven 3. Projects may need to fix their POMs:

  • Duplicate XML elements — duplicate <artifactId>, <properties>, etc. are now rejected (Duplicated tag error). Fix the source POM.
  • Duplicate dependency declarations — same groupId:artifactId declared twice is now rejected (must be unique).
  • Uninterpolated expressions — ${...} expressions in repository URLs, distribution management IDs, and other fields that Maven 3 silently accepted are now rejected.
  • Invalid XML in transitive POMs — illegal processing instructions or undeclared namespace prefixes in transitive POMs cause Non-parseable POM errors.
  • Properties in <module> paths — Maven 4 no longer interpolates properties like ${spark.version} in <module> elements at POM reading time.
  • CI-friendly versions — projects using ${revision} without flatten-maven-plugin may hit missing dependency version errors.
  • Invalid Collect Request — transitive dependencies with uninterpolated ${...} version expressions are rejected.

Transitive dependency resolution changes

Maven 4's TransitiveDependencyManager applies dependencyManagement at all transitive depths (Maven 3 only applied it at the first level). This is intentional but can change resolved versions:

  • Dependencies previously on the classpath may disappear — add explicit declarations. See #12302.
  • maven-enforcer-plugin version rules may trigger due to downgraded transitive versions.
  • license-maven-plugin may report new transitive dependencies not in the allow-list.
  • Karaf feature verification may fail due to OSGi bundle version mismatches.

Plugin and extension compatibility

Some plugins and extensions require specific versions for Maven 4:

  • Quarkus — versions before 3.20 use ServiceLocator/RepositorySystem patterns incompatible with Maven 4's Sisu-based DI. Upgrade to Quarkus 3.20+.
  • Tycho — versions before 5.0 use Guice/Sisu injection patterns broken by Maven 4. Upgrade to Tycho 5.0.3+.
  • Develocity Maven extension — fails to initialize due to SLF4J classloading changes (ClassNotFoundException: SimpleLogger).
  • pgpverify-maven-plugin — versions before 1.20 hit a ClassCastException with Maven 4's resolver. See resolver#1957.
  • cyclonedx-maven-plugin — fails with Invalid Version Range Request when using ${revision} CI-friendly versions.
  • maven-site-plugin — Velocity template rendering may fail with incompatible site plugin versions.
  • maven-shade-plugin — dependency-reduced-pom.xml can cause The parents form a cycle error.
  • commons-release-plugin — clean-staging fails under Maven 4.

Classloading changes

  • Plugins relying on Maven 3's classrealm layout may encounter "foreign imports" errors (e.g., Quarkus, JAXB plugins).
  • Maven 4's prefix-based repository routing may block artifacts not matching /.meta/prefixes.txt.

Post-mvnup formatting

  • spotless-maven-plugin and sortpom-maven-plugin may report formatting violations after mvnup modifies POM files. Re-run the formatter after mvnup.

Other

  • Broken upstream POMs — e.g., hadoop-project 3.1.0–3.3.0 has invalid XML (<Xlint:-unchecked/>) causing parse errors. These need upstream fixes tracked in HADOOP-19923.
  • Enforcer POM element ordering — Maven 4's model builder reorders POM elements into a canonical order, which can break enforcer rules checking element ordering.
  • SNAPSHOT handling — SNAPSHOT artifacts may show as "present, but unavailable" under Maven 4's different resolver metadata handling.
