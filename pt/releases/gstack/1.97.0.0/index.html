gstack v1.97.0.0

#gstack v1.97.0.0 ##gstack v1.97.0.0 Principalmente /ship, o comando do gstack que analisa, testa e abre uma solicitação pull para você: menos rodadas de revisão extras desnecessárias, auditorias que seguem sua preferência de modelo, duas portas de aceitação que mantêm /investigate e /plan-ceo-review em sua etapa principal e uma correção de segurança do navegador.

Novidades

  • Um portão de aceitação para /plan-ceo-review evita que a sessão termine até que a revisão tenha escrito suas conclusões classificadas; ligue-o com ./setup --ceo-review-gate #4047.
  • Uma porta de aceitação para /investigate bloqueia uma correção até que a causa raiz seja anotada, incluindo correções feitas por meio de comandos shell; ligue-o com ./setup --investigate-gate #4045.
  • Se você seguir o canal de atualização estável, correções importantes (segurança, regressões, perda de dados, bloqueadores) agora atingem a estabilidade em um dia, e a estabilidade nunca fica mais de uma semana atrás das alterações testadas no #4083 principal.

Correções

  • Segurança: o navegador incluído no gstack agora usa Playwright 1.65.0 com Chromium 158, que não é mais trusts para as autoridades de certificação eMudhra comprometidas #4087.
  • O log de auditoria de navegação não salva mais o que você digita nas páginas, como senhas enviadas com fill ou type, respostas de caixas de diálogo e valores de cookies ou cabeçalhos. Relatado por @derHaken #4073, #4081.
  • O log de auditoria de navegação e o log de rede não mantêm mais valores ou credenciais de consulta de URL, portanto, os campos de um formulário de login enviado permanecem fora do disco #4082.
  • gstack-brain-sync não chama mais um push rejeitado de erro de autenticação só porque o URL do seu controle remoto contém uma palavra como auth ou 403, então ele tenta novamente o push como deveria #4035.
  • O daemon de navegação não falha mais com "A porta… está em uso?" em uma máquina ocupada; agora ele escolhe sua porta antes de começar a escutar #4035.
  • A verificação secreta do gstack não sinaliza mais código comum como config.prod ou server.local(...) como um nome de host interno vazado, obrigado @nazarli-shabnam #4043.
  • Documentos do navio, cobertura de testes e auditorias de planos agora são executados no modelo que você definiu em suas preferências, em vez de sempre no Sonnet 5.5 #4038, #4042.
  • /ship não solicita mais outra rodada de revisão quando sua própria auditoria de documentos edita arquivos após a revisão, mesmo quando a auditoria é executada duas vezes #4034, #4071.
  • Adicionar padrões review_exclude_paths em sua ramificação principal não força mais solicitações pull abertas através de revisão novamente quando nenhum de seus arquivos corresponde a #4030, #4036, #4041.
  • Cada revisor /ship agora vê a mesma diferença aparada, incluindo um revisor cujas instruções foram reconstruídas por conta própria após uma falha na inicialização #4048.
  • O planejamento da revisão do /ship termina em cerca de 35 segundos em repositórios de resultados muito grandes, em vez de atingir o tempo limite #4040.
  • Solicitações de pull de resultados cheias de prompts de modelo capturados não atingem mais o limite de tamanho de revisão de /ship apenas porque esses prompts mencionam variáveis-chave API #4044.
  • /ship e /review não contam mais a frase final de um revisor, como "Nada disso chega a CRÍTICO". como uma descoberta crítica #4075.
  • Uma solicitação pull empilhada cujo pai foi mesclado por squash não tem mais as próprias alterações do sinalizador /ship main como edições não revisadas #4021.
  • /ship não fica mais travado quando uma linha de documentos com uma reivindicação de dinheiro, segurança ou numérica é adicionada após a conclusão da revisão #4062.
  • /ship não fica mais travado após uma mesclagem de base que altera uma linha revisada e move o código próximo a ela; agora pede uma pequena nova verificação #4054.
  • /ship não solicita mais uma nova revisão quando uma fusão de base apenas ultrapassa uma versão ou número de regras que sua política de navio declara como mecânica #4053.
  • /ship não para mais em um arquivo Godot .uid adicionado após revisão, e sua política de navio agora pode nomear seus próprios arquivos de teste #4063.
  • Uma política de envio cuja versão mínima do gstack é mais recente que a última versão estável agora é recusada nominalmente, em vez de enviar sessões para uma atualização que não pode satisfazê-la #4080.
  • A verificação "testar novamente após sua última edição" do /investigate agora detecta correções escritas através de comandos shell como sed -i ou um heredoc #4078.
  • As portas /investigate e /plan-ceo-review não permitem mais que uma sessão termine sem verificação quando a varredura é executada lentamente #4072.
  • /runaway-stopper não sinaliza mais agentes que fazem check-in a cada quatro minutos enquanto aguardam o CI como fugitivos #4069.
  • O executor Ubicloud por trás de /ubicloud nunca trata um erro API como sucesso e nunca destrói uma VM que outro chamador criou com o mesmo nome #4039, #4046.

Mudanças para mantenedores

  • As etapas de conclusão e aceitação de /ship lidam melhor com as rodadas de correção concedidas pelo proprietário: todas as verificações de correção encadeadas contam, uma rodada concedida atualiza o dinheiro e a segurança é relida por conta própria, as notas governadas pelo proprietário fecham suas descobertas e o resultado nomeia a concessão usada #4050, #4064, #4070, #4077.
  • O registro de releitura de dinheiro e segurança sobrevive a uma mesclagem principal posterior e aceita obtém seu limite de espera de CI da política de envio base (ci_record_timeout_s) #4058, #4065.
  • aceitar verifica uma ramificação sob sua própria política de teste quando essa ramificação apenas adiciona execuções de teste, e um proprietário pode conceder uma exceção para uma execução de teste #4061.
  • As novas chaves de política de envio mechanical_retake e test_code requerem gstack 1.97.0.0 #4079.
  • No Capy, os comandos auxiliares /ship agora registram suas próprias chamadas para que a contagem de chamadas de uma execução seja conhecida #4059.
  • O próprio repositório do gstack agora executa uma verificação de liberação paga em main a cada 8 horas, testa novamente uma solicitação pull mesclada na dica de main antes de mesclá-la quando main for movido e faz com que os arquivos de teste ignorados por CI sejam executados novamente antes da mesclagem #4031, #4029, #4028.
  • A etapa de mesclagem oculta seu próprio ambiente, incluindo o token GitHub, das verificações executadas no Linux #4032.
  • A verificação do arquivo de lançamento aceita uma saída de lançamento que a ferramenta de lançamento do repositório regenera #4033.
  • Uma solicitação pull que edita setup não executa mais todos os casos de avaliação pagos em uma tela estreita #4056.
  • O aviso de shard lento do free-CI agora é responsável por shards divididos em trabalhos paralelos, obrigado @indraoverflow #4085.
  • Reparos de teste: dois arquivos de teste agora passam em um processo e quatro testes instáveis ​​relatam por que falharam #4068, #4074.
  • O inventário de evidências registra os últimos veredictos de roteamento e /investigação de avaliação #4076.
  • gstack agora gera uma edição de carregamento sob demanda de três habilidades (investigar, revisar e planejar revisão) para outro host de agente #4049.
  • Documentos do agente: agentes no Capy comentam e solicitam revisões apenas por meio das ferramentas de RP do Capy, agentes executando /ship sleep até terminar e mantendo seu contexto pequeno, e AGENTS.md lista habilidades apenas por nome #4027, #4055, #4060. gstack v1.97.0.0

gstack v1.97.0.0

Mostly /ship, gstack's command that reviews, tests and opens a pull request for you: fewer needless extra review rounds, audits that follow your model preference, two opt-in gates that hold /investigate and /plan-ceo-review to their key step, and a browser security fix.

What's new

  • An opt-in gate for /plan-ceo-review keeps the session from finishing until the review has written its ranked findings; turn it on with ./setup --ceo-review-gate #4047.
  • An opt-in gate for /investigate blocks a fix until a root cause is written down, including fixes made through shell commands; turn it on with ./setup --investigate-gate #4045.
  • If you follow the stable update channel, important fixes (security, regressions, data loss, blockers) now reach stable within a day, and stable is never more than a week behind tested changes on main #4083.

Fixes

  • Security: gstack's bundled browser now uses Playwright 1.65.0 with Chromium 158, which no longer trusts the compromised eMudhra certificate authorities #4087.
  • The browse audit log no longer saves what you type into pages, such as passwords sent with fill or type, dialog answers, and cookie or header values. Reported by @derHaken #4073, #4081.
  • The browse audit log and network log no longer keep URL query values or credentials, so a submitted login form's fields stay off disk #4082.
  • gstack-brain-sync no longer calls a rejected push an auth error just because your remote's URL contains a word like auth or 403, so it retries the push as it should #4035.
  • The browse daemon no longer fails with "Is port … in use?" on a busy machine; it now picks its port right before it starts listening #4035.
  • gstack's secret scan no longer flags ordinary code such as config.prod or server.local(...) as a leaked internal hostname, thanks @nazarli-shabnam #4043.
  • /ship's docs, test-coverage and plan audits now run on the model you set in your preferences instead of always on Sonnet 5.5 #4038, #4042.
  • /ship no longer asks for another review round when its own docs audit edits files after the review, even when the audit runs twice #4034, #4071.
  • Adding review_exclude_paths patterns on your main branch no longer forces open pull requests through review again when none of their files match #4030, #4036, #4041.
  • Every /ship reviewer now sees the same trimmed diff, including a reviewer whose instructions were rebuilt on their own after a failed start #4048.
  • /ship's review planning finishes in about 35 seconds on very large results repositories instead of timing out #4040.
  • Results pull requests full of captured model prompts no longer hit /ship's review size limit just because those prompts mention API key variables #4044.
  • /ship and /review no longer count a reviewer's closing sentence such as "None of these rises to CRITICAL." as a critical finding #4075.
  • A stacked pull request whose parent was squash-merged no longer has /ship flag main's own changes as unreviewed edits #4021.
  • /ship no longer gets stuck when a docs line with a money, security or numeric claim is added after the review finished #4062.
  • /ship no longer gets stuck after a base merge that both changes a reviewed line and moves code next to it; it now asks for one small re-check #4054.
  • /ship no longer asks for a new review when a base merge only bumps a version or rules number your ship policy declares as mechanical #4053.
  • /ship no longer stops on a Godot .uid file added after review, and your ship policy can now name your own test files #4063.
  • A ship policy whose minimum gstack version is newer than the latest stable release is now refused by name, instead of sending sessions to an upgrade that cannot satisfy it #4080.
  • /investigate's "test again after your last edit" check now notices fixes written through shell commands such as sed -i or a heredoc #4078.
  • The /investigate and /plan-ceo-review gates no longer let a session end unchecked when their scan runs slowly #4072.
  • /runaway-stopper no longer flags agents that check in every four minutes while waiting on CI as runaways #4069.
  • The Ubicloud runner behind /ubicloud never treats an API error as success and never destroys a VM that another caller created under the same name #4039, #4046.

Changes for maintainers

  • /ship's finish and accept steps handle owner-granted fix rounds better: chained fix-checks all count, a granted round refreshes the money and security re-read on its own, owner-ruled notes close their findings, and the result names the grant it used #4050, #4064, #4070, #4077.
  • The money and security re-read record survives a later main merge, and accept takes its CI wait limit from the base ship policy (ci_record_timeout_s) #4058, #4065.
  • accept checks a branch under its own test policy when that branch only adds test runs, and an owner can grant an exception for one test run #4061.
  • The new ship-policy keys mechanical_retake and test_code require gstack 1.97.0.0 #4079.
  • On Capy, /ship helper commands now log their own calls so a run's call count is known #4059.
  • gstack's own repository now runs one paid release check on main every 8 hours, re-tests a pull request merged onto main's tip before merging it when main has moved, and has CI-skipped test files rerun before merge #4031, #4029, #4028.
  • The merge step hides its own environment, including the GitHub token, from the checks it runs on Linux #4032.
  • The release-file check accepts a release output that the repository's release tool regenerates #4033.
  • A pull request that edits setup no longer runs every paid eval case on a narrow screen #4056.
  • The free-CI slow-shard warning now accounts for shards split across parallel jobs, thanks @indraoverflow #4085.
  • Test repairs: two test files now pass in one process, and four flaky tests report why they failed #4068, #4074.
  • The evidence inventory records the latest routing and /investigate eval verdicts #4076.
  • gstack now generates a load-on-demand edition of three skills (investigate, review and plan review) for another agent host #4049.
  • Agent docs: agents on Capy comment and request reviews only through Capy's PR tools, agents running /ship sleep until it finishes and keep their context small, and AGENTS.md lists skills by name only #4027, #4055, #4060.
