#gstack v1.102.0.0 gstack 1.102.0.0 torna o Codex um host de primeira classe: agora ele recebe sugestões de habilidades do gstack, a verificação de comando destrutivo e a retenção da lista de verificação /review. A verificação de comando destrutivo foi reconstruída para perguntar com muito menos frequência e, ao mesmo tempo, causar muito mais danos reais. Verificação de comando destrutivo (/cuidadoso)

  • Ele não pergunta mais sobre a exclusão de arquivos temporários (pastas /tmp, mktemp, caches, saída de compilação) e agora pergunta antes de exclusões fora do seu projeto, descartando trabalho não confirmado, reescritas de histórico, exclusões de ramificações remotas, redefinições de banco de dados e exclusões de nuvem. Uma exclusão recursiva de / ou de sua pasta pessoal, um push forçado para a ramificação padrão e a limpeza de um disco inteiro são bloqueados, independentemente de como são gravados. Em uma repetição de 254.322 comandos de agentes reais, as solicitações inofensivas caíram de 1.40% dos comandos para 0.33%, e os comandos destrutivos capturados aumentaram de 443 para 930 de 948. (#4513)
  • Lê os comandos com mais atenção: git push --repo=origin +main, força-empurra após um cd ou com --all/--mirror, silencioso git clean -q, find -L … -delete e wipefs -a em todas as grafias são capturados; Os testes e greps do git push -nf para texto SQL não solicitam mais. No mesmo replay, isso não detecta menos comandos destrutivos e adiciona 141 solicitações inofensivas (0.39% dos comandos no total); um acompanhamento está trabalhando nisso. (#4525)
  • Os programas do Agente SDK recebem um aviso em vez de uma pergunta, pois o SDK recusa uma pergunta e ninguém responde. Configure GSTACK_SESSION_KIND=interactive para manter a solicitação. (#4513) Códice
  • ./setup --host codex (Codex 0.170+) adiciona ganchos que sugerem a habilidade correta do gstack para um prompt e executa a verificação de comando destrutivo antes de cada comando shell. O Codex não pode perguntar sobre um único comando, então um comando arriscado é bloqueado em sessões interativas e avisado em codex exec. Trust os ganchos quando o Codex pergunta na inicialização. (#4512)
  • /review no Codex é realizada uma vez se tentar terminar sem seu passe ou relatório adversário, como no Claude Code. (#4522) Conta um subagente Sol iniciado com task_name nessa passagem. (#4526)
  • Os ganchos do Codex funcionam quando o caminho da pasta do Codex tem caracteres de shell, a desinstalação mantém seus próprios ganchos trusted, a configuração corresponde ao esquema de gancho do Codex mais de perto e a lista de verificação de /review lê o ; citado e as leituras com falha corretamente. (#4528)
  • Sugestões de habilidades, prompts de seleção e documentos nomeiam habilidades da maneira como o Codex as lista ($review, não $gstack-review). (#4523, #4524)
  • horário comercial, revisão de design de plano e atualização de gstack carregam novamente no Codex, uma habilidade sob codex exec sabe que está autônoma, e os revisores do Codex começam com um contexto limpo. (#4510) Ganchos e roteamento
  • Os ganchos auxiliares estão ativados por padrão, a verificação do comando destrutivo é executada como um gancho e o roteamento de prompt é acionado em longos relatórios de erros. Com as próprias habilidades do gstack, o gancho de roteamento roteia 14 dos 60 relatórios de bugs reais (era 17); os documentos agora correspondem. (#4503, #4505)
  • O gancho de roteamento agora também sugere habilidades que você mesmo instalou e para de enviar relatórios de bugs para /qa. Com habilidades instaladas, ele encaminha 40 dos 60 relatórios de bugs reais. (#4506) /enviar, revisar e CI
  • No Capy, /ship não edita mais ou comenta solicitações pull em sua conta GitHub; ele entrega o texto à ferramenta de relações públicas do próprio Capy. (#4518)
  • Um comando cuja saída foi cortada agora falha em vez de ser julgado por parte de sua saída. Isso fecha uma lacuna onde um push cujo diferencial ultrapassou 64 MiB poderia transportar uma credencial além do gancho pré-push. (#4492, #4502)
  • Uma revisão fracassada do segundo modelo nomeia a causa que a interrompeu, registra um 402 como interrupção do orçamento e nunca exclui seu próprio prompt. (#4515, #4519)
  • Quando uma correção atinge uma verificação de mesclagem, a segunda rodada de revisão agora a analisa em vez de relatar a conclusão. (#4520)
  • A política de envio pode marcar os dados publicados como conteúdo para que /ship possa revisar grandes PRs de dados, e essa pasta não pode ocultar o código-fonte ou os arquivos do agente da revisão. (#4511, #4516)
  • /ship's review funciona quando o checkout que está sendo enviado não é o checkout padrão do projeto. (#4507)
  • A verificação da máquina de estado de /ship aceita as linhas de cabeçalho que seu leitor escreve. (#4504)
  • A verificação de número alterado para de sinalizar testes que compartilham apenas uma palavra como limit. Obrigado @dtoelke. (#4496)
  • PRs que mesclaram uma versão reutilizam sua execução de teste anterior quando a versão apenas regenerou um arquivo declarado. (#4483)
  • Quando Claude Code executa /verify antes de um commit, ele recebe uma verificação rápida em vez do loop de correção completo (#4508), e essa verificação falha perfeitamente em um tempo limite. (#4527)
  • O coletor de avaliações não descarta mais um P0 real escrito como um resumo e para de ler as listas de escopo dos revisores como descobertas. (#4527)
  • gstack-ship-queue ready agora preenche suas fusões de teste contra outros PRs abertos e cujo segundo modelo verificou o registro de decisão, além de seis pequenas correções de ferramentas /navio, incluindo o registro de uma decisão retransmitida por outro agente. (#4529)
  • As execuções de teste cujos trabalhadores iniciam em sua própria sessão não são mais interrompidas como paralisadas. Obrigado @dtoelke. (#4533)
  • O CI de suíte gratuita sobrevive a um espelho lento do Ubuntu, e quatro testes instáveis e verificações de avaliação foram corrigidos. (#4530) Gcérebro
  • A verificação de leitura do /sync-gbrain funciona quando a primeira página tem mais de 64 KB. (#4497)
  • Sincronizar um segundo repositório não faz mais com que o primeiro repositório solicite que você sincronize novamente. Obrigado @SatriaSuriaAriffin. (#4532)

gstack v1.102.0.0

gstack 1.102.0.0 makes Codex a first-class host: it now gets gstack's skill suggestions, the destructive-command check and /review's checklist hold. The destructive-command check was rebuilt to ask far less often while catching far more real damage.

Destructive-command check (/careful)

  • It no longer asks about deleting scratch files (/tmp, mktemp folders, caches, build output), and it now asks before deletes outside your project, throwing away uncommitted work, history rewrites, remote branch deletes, database resets and cloud deletes. A recursive delete of / or your home folder, a force-push to the default branch, and wiping a whole disk are blocked however they're written. On a replay of 254,322 real agent commands, harmless asks fell from 1.40% of commands to 0.33%, and destructive commands caught rose from 443 to 930 of 948. (#4513)
  • It reads commands more carefully: git push --repo=origin +main, force-pushes after a cd or with --all/--mirror, quiet git clean -q, find -L … -delete, and wipefs -a in every spelling are caught; git push -nf dry runs and greps for SQL text no longer ask. On the same replay this catches no fewer destructive commands, and it adds 141 harmless asks (0.39% of commands in total); a follow-up is working on those. (#4525)
  • Agent SDK programs get a warning instead of an ask, because the SDK refuses an ask nobody answers. Set GSTACK_SESSION_KIND=interactive to keep the ask. (#4513)

Codex

  • ./setup --host codex (Codex 0.170+) adds hooks that suggest the right gstack skill for a prompt and run the destructive-command check before every shell command. Codex can't ask about a single command, so a risky one is blocked in interactive sessions and warned about under codex exec. Trust the hooks when Codex asks at startup. (#4512)
  • /review on Codex is held once if it tries to finish without its adversarial pass or report, as on Claude Code. (#4522) It counts a Sol subagent started with task_name as that pass. (#4526)
  • Codex hooks work when your Codex folder's path has shell characters, uninstall keeps your own hooks trusted, setup matches Codex's hook schema more closely, and /review's checklist reads quoted ; and failed reads correctly. (#4528)
  • Skill suggestions, picker prompts and docs name skills the way Codex lists them ($review, not $gstack-review). (#4523, #4524)
  • office-hours, plan-design-review and gstack-upgrade load again on Codex, a skill under codex exec knows it's unattended, and Codex reviewers start with a clean context. (#4510)

Hooks and routing

  • The helper hooks are on by default, the destructive-command check runs as a hook, and prompt routing fires on long bug reports. With gstack's own skills the routing hook routes 14 of 60 real bug reports (was 17); the docs now match. (#4503, #4505)
  • The routing hook now also suggests skills you've installed yourself, and stops sending bug reports to /qa. With installed skills it routes 40 of 60 real bug reports. (#4506)

/ship, review and CI

  • On Capy, /ship no longer edits or comments on pull requests under your GitHub account; it hands the text to Capy's own PR tool. (#4518)
  • A command whose output was cut off now fails instead of being judged on part of its output. This closes a gap where a push whose diff passed 64 MiB could carry a credential past the pre-push hook. (#4492, #4502)
  • A failed second-model review names the cause that stopped it, records a 402 as a budget stop, and never deletes its own prompt. (#4515, #4519)
  • When a fix touches a merge check, the second review round now reviews it instead of reporting done. (#4520)
  • Ship policy can mark published data as content so /ship can review large data PRs, and such a folder can't hide source code or agent files from review. (#4511, #4516)
  • /ship's review works when the checkout being shipped isn't the project's default checkout. (#4507)
  • /ship's state-machine check accepts the header lines its reader writes. (#4504)
  • The changed-number check stops flagging tests that only share a word like limit. Thanks @dtoelke. (#4496)
  • PRs that merged a release reuse their earlier test run when the release only regenerated a declared file. (#4483)
  • When Claude Code runs /verify before a commit, it gets a quick check instead of the full fix loop (#4508), and that check fails cleanly on a timeout. (#4527)
  • The review collector no longer drops a real P0 written as a summary bullet, and stops reading reviewers' scope lists as findings. (#4527)
  • gstack-ship-queue ready now fills in its trial merges against other open PRs and which second model checked the decision record, plus six small /ship tool fixes, including recording a ruling relayed from another agent. (#4529)
  • Test runs whose workers start in their own session are no longer killed as stalled. Thanks @dtoelke. (#4533)
  • Free-suite CI survives a slow Ubuntu mirror, and four flaky tests and eval checks were fixed. (#4530)

GBrain

  • /sync-gbrain's read check works when the first page is over 64 KB. (#4497)
  • Syncing a second repo no longer makes the first repo ask you to sync again. Thanks @SatriaSuriaAriffin. (#4532)
