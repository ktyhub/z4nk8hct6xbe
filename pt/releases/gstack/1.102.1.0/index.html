#gstack v1.102.1.0 gstack 1.102.1.0 fecha uma lacuna onde um segredo escrito após uma barra pode ser impresso sem ocultação, bloqueia o relatório de uso do gstack e o torna mais útil para pessoas que optam por participar, corrige um conjunto de bugs em como o gstack escolhe a habilidade certa para um prompt e faz com que a etapa inicial de uma habilidade gstack seja executada enquanto Claude Code carrega a habilidade, para que ela não possa ser ignorada. Relatórios de uso (telemetria, aceitação)

  • O back-end de relatórios de uso agora aceita dados apenas por meio de seu próprio endpoint verificado: a chave pública no repositório não pode mais ler ou gravar as tabelas, e um usuário Supabase conectado tem tudo negado. As próprias execuções de teste do gstack nunca enviam dados de uso, o tráfego de teste é deixado de fora do gstack-community-dashboard e sua contagem ativa semanal agora conta instalações reais em vez de verificações de atualização. Versões do gstack anteriores a v0.11.16.0 (março de 2026) param de enviar dados de uso, porque gravaram diretamente nas tabelas. (#4537)
  • Se você aceitar, cada execução de habilidade agora também envia nove novos campos, cada um escolhido em uma lista fixa: qual agente de codificação a executou, a família do modelo, se você, o modelo ou outra habilidade a iniciou, por que ela terminou, se suas próprias verificações foram aprovadas, se a seção de roteamento e os ganchos do gstack estão configurados, um ID de sessão aleatório e, para atualizações, a versão de onde você veio e por que uma atualização falhou. É executado a partir do CI e dos próprios rótulos de avaliação do gstack, e uma duração que o gstack não conseguiu medir é enviada vazia em vez de 0. A pergunta de aceitação lista os novos campos, e o modo anônimo agora diz que não envia "nenhum ID de dispositivo; um ID aleatório por sessão do agente que nunca é reutilizado". Nenhum campo contém código, caminhos de arquivo, prompts ou nomes de repositório; cada campo está listado em docs/privacy.md. (#4542) Habilidades e sugestões de habilidades
  • No Claude Code, a etapa inicial de cada habilidade gstack agora é executada enquanto a habilidade é carregada, então o modelo não pode mais ignorá-la (em execuções de teste, os modelos seguiram a etapa inicial de uma habilidade carregada em apenas 45% a 62% das sessões). Se o carregamento falhar, a habilidade diz isso em uma linha e o modelo executa a etapa inicial, como antes. Codex e outros agentes mantêm as instruções antigas. (#4509) O teste pago do gstack que verifica esta etapa inicial agora conta aquela que foi executada durante o carregamento. (#4543)
  • Quando um prompt parece um relatório de bug, o gancho de sugestão de habilidade agora nomeia apenas sua habilidade de correção de bug instalada e nunca sugere/verifica antes dela. Em 60 prompts reais de correção de bugs, ela agora nomeia a habilidade de correção de bugs em todos os 46 relatórios de bugs. (#4539)
  • O gancho de sugestão de habilidade agora ignora palavras dentro de crases e blocos de código, então um comando entre aspas como "Executar gh pr review 123" não aciona mais /revisão, e um sinalizador --fix em um log colado não faz mais um prompt parecer um relatório de bug. Obrigado a @vilano93, que encontrou e consertou primeiro. (#4566)
  • gstack agora informa em uma linha o que está prestes a adicionar antes de instalar um trabalho em segundo plano (gbrain autopilot) ou a extensão do navegador gstack, incluindo como removê-lo. Um novo teste falhará se uma etapa de instalação futura deixar essa linha de fora. (#4538) Segurança e proteção
  • A verificação de comando destrutivo (/careful) fecha mais maneiras em torno de seus blocos de limpeza de disco e push forçado: wipefs -a é bloqueado em todos os alvos e em mais grafias, uma gravação em um disco é bloqueada quando seu caminho é citado ou passa por um link para /dev, e git push -fn --no-dry-run conta como um push forçado real. Nada do que foi bloqueado ou questionado antes é permitido agora. (#4534)
  • /cso agora pode auditar repositórios que contêm links simbólicos. Ele lista cada link e seu alvo no relatório e nunca o segue, onde antes um único link (mesmo CLAUDE.md -> AGENTS.md) interrompeu a auditoria. Obrigado a @nathanshox pelo relatório e pela primeira correção. (#4567)
  • O ocultador secreto do gstack agora também esconde uma senha, chave API ou token escrito como name=value após uma barra (como cfg/api_key=… ou https://host/cb/token=…), onde antes ele os pegava apenas no início de uma linha. O relatório histórico do /cso imprimiu tais valores; ele e todos os outros lugares em que o gstack esconde segredos (revisar material, dados de uso, registros de envio) agora os ocultam. (#4571) /revisão de envio e código
  • Uma execução de CI verde ainda conta para /ship e merge quando GitHub se recusa a armazenar os arquivos da execução porque o armazenamento do repositório está cheio: gstack agora pode ler o mesmo registro do log do trabalho, sob as mesmas verificações. (#4536)
  • /ship agora para e informa o que fazer quando a execução de teste anterior do CI não puder ser reutilizada, em vez de iniciar todo o conjunto de testes em sua máquina. (#4565)
  • Quando o proprietário determina que as descobertas de uma revisão interrompida são aceitáveis como notas abertas, essas decisões agora deixam /ship terminar (#4552), o registro de revisão indica quais descobertas ainda estão aguardando uma decisão (#4553), e as decisões também funcionam quando as descobertas da revisão foram salvas em um arquivo separado (#4568).
  • Uma solicitação pull que adiciona apenas um plano de avaliação e seus arquivos de dados simples (um pré-registro) agora obtém a revisão mais leve de um revisor destinada a redações, e as linhas de dados não contam mais como linhas de código quando o gstack dimensiona uma revisão. (#4544)
  • Run ids nos registros de aprovação de /ship, como 507-7192673, não são mais confundidos com números de telefone e bloqueados, e uma equipe cujo nome começa com "GStack" pode registrar decisões. (#4549) Navegador e testes
  • O auxiliar do navegador não escolhe mais a porta 10080, que o Chrome se recusa a abrir, então cerca de uma inicialização em 39.000 não falha mais ao carregar suas próprias páginas; um teste instável também foi corrigido. (#4554)
  • a avaliação de sincronização de documentação do gstack não falha mais quando /ship repara a linha de resultados de um revisor da maneira permitida. (#4555)
  • Para pessoas que trabalham no gstack: todos os testes que falharam e foram aprovados em sua nova tentativa nas execuções de teste gratuitas do gstack agora são registrados, incluindo execuções iniciadas manualmente em uma ramificação, para que os testes instáveis sejam contados e corrigidos. (#4572)
  • Para pessoas que trabalham no gstack: as execuções de testes em solicitações pull começam uma etapa antes, porque o trabalho que divide os testes agora é executado junto com as verificações anteriores, em vez de depois delas. (#4570)

gstack v1.102.1.0

gstack 1.102.1.0 closes a gap where a secret written after a slash could be printed unhidden, locks down gstack's usage reporting and makes it more useful for people who opt in, fixes a set of bugs in how gstack picks the right skill for a prompt, and makes a gstack skill's start step run as Claude Code loads the skill, so it can't be skipped.

Usage reporting (telemetry, opt-in)

  • The usage-reporting backend now accepts data only through its own checked endpoint: the public key in the repo can no longer read or write the tables, and a signed-in Supabase user is denied everything. gstack's own test runs never send usage data, test traffic is left out of gstack-community-dashboard, and its weekly active count now counts real installs instead of update checks. gstack versions older than v0.11.16.0 (March 2026) stop sending usage data, because they wrote straight to the tables. (#4537)
  • If you opt in, each skill run now also sends nine new fields, each a pick from a fixed list: which coding agent ran it, the model family, whether you, the model or another skill started it, why it ended, whether its own checks passed, whether gstack's routing section and hooks are set up, a random session id, and for upgrades the version you came from and why an upgrade failed. Runs from CI and gstack's own evals label themselves, and a duration gstack couldn't measure is sent empty instead of 0. The opt-in question lists the new fields, and anonymous mode now says it sends "no device ID; a random id per agent session that is never reused". No field carries code, file paths, prompts or repo names; every field is listed in docs/privacy.md. (#4542)

Skills and skill suggestions

  • In Claude Code, each gstack skill's start step now runs while the skill loads, so the model can no longer skip it (in test runs, models had followed a loaded skill's start step in only 45% to 62% of sessions). If loading fails, the skill says so in one line and the model runs the start step itself, as before. Codex and other agents keep the old instructions. (#4509) gstack's paid test that checks this start step now counts one that ran during loading. (#4543)
  • When a prompt reads like a bug report, the skill-suggestion hook now names your installed bug-fix skill alone and never suggests /verify ahead of it. On 60 real bug-fix prompts it now names the bug-fix skill on all 46 bug reports. (#4539)
  • The skill-suggestion hook now ignores words inside backticks and code blocks, so a quoted command such as "Run gh pr review 123" no longer triggers /review, and a --fix flag in a pasted log no longer makes a prompt look like a bug report. Thanks to @vilano93, who found and first fixed it. (#4566)
  • gstack now tells you in one line what it's about to add before it installs a background job (gbrain autopilot) or the gstack browser extension, including how to remove it. A new test fails if a future install step leaves that line out. (#4538)

Safety and security

  • The destructive-command check (/careful) closes more ways around its disk-wipe and force-push blocks: wipefs -a is blocked on every target and in more spellings, a write into a disk is blocked when its path is quoted or goes through a link to /dev, and git push -fn --no-dry-run counts as a real force-push. Nothing that was blocked or asked about before is allowed now. (#4534)
  • /cso can now audit repositories that contain symbolic links. It lists each link and its target in the report and never follows it, where before a single link (even CLAUDE.md -> AGENTS.md) stopped the audit. Thanks to @nathanshox for the report and first fix. (#4567)
  • gstack's secret hider now also hides a password, API key or token written as name=value after a slash (such as cfg/api_key=… or https://host/cb/token=…), where before it caught them only at the start of a line. /cso's history report had printed such values; it and every other place gstack hides secrets (review material, usage data, /ship logs) now hide them. (#4571)

/ship and code review

  • A green CI run still counts toward /ship and merging when GitHub refuses to store the run's files because the repository's storage is full: gstack can now read the same record from the job's log, under the same checks. (#4536)
  • /ship now stops and tells you what to do when CI's earlier test run can't be reused, instead of starting the whole test suite on your machine. (#4565)
  • When the owner rules a stopped review's findings acceptable as open notes, those rulings now let /ship finish (#4552), the review record says which findings are still waiting for a ruling (#4553), and rulings also work when the review's findings were saved in a separate file (#4568).
  • A pull request that adds only an eval's plan and its plain data files (a preregistration) now gets the lighter one-reviewer review meant for write-ups, and rows of data no longer count as lines of code when gstack sizes a review. (#4544)
  • Run ids in /ship's approval records, such as 507-7192673, are no longer mistaken for phone numbers and blocked, and a team whose name starts with "GStack" can record rulings. (#4549)

Browser and tests

  • The browser helper no longer picks port 10080, which Chrome refuses to open, so about one start in 39,000 no longer fails to load its own pages; one flaky test was fixed too. (#4554)
  • gstack's documentation-sync eval no longer fails when /ship repairs a reviewer's result line in the allowed way. (#4555)
  • For people working on gstack: every test that failed and then passed on its retry in gstack's free test runs is now recorded, including runs started by hand on a branch, so flaky tests get counted and fixed. (#4572)
  • For people working on gstack: test runs on pull requests start one step sooner, because the job that splits the tests now runs alongside the earlier checks instead of after them. (#4570)
