gstack v1.101.0.0

#gstack v1.101.0.0 ##gstack v1.101.0.0

Novidades

  • Antes que você seja solicitado a testar a construção de um aplicativo, o novo comando gstack-first-use faz com que um agente de outra família de modelos jogue no mesmo tipo de dispositivo e verifique as cinco primeiras coisas que você fará com ele. (#4465)
  • Antes que um agente faça uma pergunta ao seu proprietário, gstack-owner-answers pode comparar o rascunho com as respostas anteriores do proprietário e sugerir eliminar apenas as linhas que um sim existente já cobre. (#4467)
  • GitHub release notes agora listam todas as alterações em palavras simples, com um link para sua solicitação pull. (#4390)
  • Quando outro agente dirige /ship passo a passo, cada fase agora é executada como um comando, as chamadas são contadas e a execução é interrompida após 100 minutos. (#4451)
  • O passo push do /ship agora sempre termina com uma linha PUSH: que diz se ele empurrou; se um script corresponder às linhas antigas do PUSH:, atualize-o. (#4474)
  • O plano de revisão do /ship agora envia código Swift que solicita permissões de privacidade ou toca saúde, calendário, contatos ou arquivos no dispositivo para o painel de revisão completo. (#4472)
  • gstack-autoplan revise --plan com um arquivo diferente agora diz que a execução segue esse arquivo. (#4470)
  • /office-hours explica por que recomenda um modo, citando suas próprias palavras. (#4450)
  • /office-hours mantém seus 34 vídeos e ensaios do fundador fora do arquivo de habilidades, então a habilidade é cerca de 8.6 KB menor. (#4463)
  • /autoplan autônomo agora executa a revisão do segundo modelo que você ativou e aguarda por ela em vez de encerrar a sessão. (#4459)

Segurança

  • O arquivo, a linha e o motivo de uma descoberta de segurança não aparecem mais na descrição de uma solicitação pull; mostra um ID opaco e os detalhes permanecem no registro de aprovação privado. (#4486)
  • A verificação de segredos agora captura um segredo construído a partir de pequenos pedaços com + ou escrito em um comentário e para de sinalizar três tipos de código comum. (#4457)

Correções

  • /ship com limite de token no Claude Code não para mais em sua primeira transferência: a nova sessão agora recebe seu prompt. Obrigado @exGeni. (#4452)
  • No Claude Code, o prompt da sessão de transferência agora começa com o comando /ship digitado, então a habilidade realmente carrega. (#4487)
  • /ship não para mais para a aprovação do proprietário quando a fusão da base altera apenas o texto do lado da base. (#4458)
  • A prosa de confirmação de um revisor não se torna mais uma conclusão crítica que somente um proprietário pode esclarecer. (#4458)
  • Quando /ship para no seu limite de rodada de revisão e o proprietário permite mais uma rodada, essa rodada agora paga pela correção das descobertas em vez de outra revisão somente leitura. (#4479)
  • /ship no Codex não para mais na auditoria de cobertura de teste: as habilidades do Codex agora iniciam sua auditoria e subagentes revisores com as próprias ferramentas do Codex (ative multi_agent = true em [features] em ~/.codex/config.toml). (#4489)
  • /ship não informa mais nenhum bloqueador quando a revisão do segundo modelo encontrou um e não terminará enquanto o bloqueador estiver aberto. (#4485)
  • Quando /ship publica uma descrição de pull request, a contagem de rodadas de revisão anteriores agora sempre vem do histórico real do PR; uma descrição contendo blocos de histórico extras poderia fazer o gstack contar uma rodada onde havia três. (#4440)
  • gstack-post não sinaliza mais os IDs de execução e commits do próprio /ship como números de telefone, portanto, postar uma descrição de solicitação de pull /ship não precisa mais de confirmação. (#4488)
  • O plano de revisão do /ship agora classifica os arquivos Swift e Xcode por risco, em vez de enviar todas as solicitações pull do iOS para o painel de revisão completo. (#4469)
  • A seleção de teste pré-push do /ship agora encontra os testes de um aplicativo monorepo que importa através de seu próprio alias @/. Obrigado @dtoelke. (#4464)
  • Um teste ou um repositório temporário no diretório temporário não pode mais gravar linhas de aprovação em seu Capy Drive real. (#4466)
  • o roteador do gstack não fornece mais uma regra especial para relatórios de bugs, então o modelo corrige um bug da mesma forma que faria sem o gstack; no Claude Code, um relatório de bug também não carrega mais o roteador. (#4442)
  • Uma execução autônoma de /plano automático no Claude Code não reporta mais sua proteção de fase como desativada enquanto está ligada, e um relatório de fase escrito apenas no raciocínio agora recebe uma negação que nomeia a correção. (#4481)
  • gstack-autoplan revise já não recusa um plano que o primeiro next aceitou. (#4470)
  • Uma revisão de plano de segundo modelo em /autoplan não é mais relatada como indisponível quando realmente é executada. (#4471)
  • /autoplan autônomo agora registra a resposta retransmitida do proprietário à sua pergunta final em vez de recusá-la. (#4484)
  • Duas execuções /autoplan iniciadas no mesmo segundo não compartilham mais um ID de execução. (#4459)
  • Duas execuções gstack-owner-answers add para a mesma resposta não colidem mais. (#4490)
  • skill_prefix=true agora sobrevive a atualizações quando o gbrain é instalado. Obrigado @fliaron. (#4454)
  • Os documentos do OpenClaw não enviam mais você para o ClawHub, que não possui habilidades atuais de gstack; eles apontam para ./setup --host openclaw. Obrigado @exGeni. (#4454)
  • gstack-issue-links não lê mais problemas de outros repositórios como gstack. (#4454)
  • /sync-gbrain não diz mais OK quando as páginas falham na importação ou quando um envio de artefatos falha, e um caminho na fila malformado não interrompe mais a sincronização de artefatos para cada projeto. (#4455)
  • Empacotar um checkout para uma execução do Ubicloud não falha mais quando o git está reescrevendo uma referência ao lado dele. (#4447)
  • Com um provedor de Codex personalizado, a verificação de prontidão do Codex e a revisão do segundo modelo agora escolhem o mesmo modelo: o model do provedor em ~/.codex/config.toml conta apenas quando é o modelo da camada de revisão (gpt-6-astra para a camada de fronteira), e ambos recusam qualquer outro nome pelo mesmo motivo. No provedor OpenAI de ações, a revisão do segundo modelo em /autoplan e /spec agora usa o modelo da camada de revisão em vez do config.toml. (#4491)
  • gstack-artifact validate e ack agora recusam um /autoplan run.json que gstack-autoplan não escreveu, ou cujo diário, resultados de revisão ou ponto de verificação discordam dele. (#4494)

Mudanças para mantenedores

  • Uma execução de CI que passou somente depois que seus trabalhos com falha foram executados novamente agora é marcado como tal sempre que o gstack o reutiliza. (#4473)
  • /ship reutiliza a execução de teste de aprovação do CI ao mesclar a base sem alterar nenhum arquivo e para em vez de iniciar silenciosamente execuções de teste locais de uma hora ou revisar uma comparação vazia. (#4461)
  • Um plano pré-registrado para teste/envio sem seu subagente coordenador separado. (#4456)
  • Esse plano agora permite que casos reversos que conflitam com código posterior sejam resolvidos manualmente. (#4460)
  • CI carrega resultados de testes de suíte gratuita para Trunk com uploader analítico v2.1.8 e analítico-cli 0.17.0. (#4453)
  • Um teste de piso de política não falha mais quando a própria versão do gstack atinge a versão secundária após a chave de política mais recente. (#4495)
  • A avaliação /plan-ceo-review HOLD SCOPE não falha mais em uma revisão porque sua pergunta de acompanhamento não repetiu o nome do modo. (#4447) Comparar v1.100.0.0...v1.101.0.0 · changelog completo

gstack v1.101.0.0

gstack v1.101.0.0

What's new

  • Before you're asked to try an app build, the new gstack-first-use command has an agent from another model family play that build on the same kind of device and check the first five things you'll do with it. (#4465)
  • Before an agent asks its owner a question, gstack-owner-answers can check the draft against the owner's earlier answers and suggest dropping only the lines an existing standing yes already covers. (#4467)
  • GitHub release notes now list every change in plain words, with a link to its pull request. (#4390)
  • When another agent drives /ship step by step, each phase now runs as one command, the calls are counted, and the run stops itself after 100 minutes. (#4451)
  • /ship's push step now always ends with one PUSH: line that says whether it pushed; if a script matched the old PUSH: lines, update it. (#4474)
  • /ship's review plan now sends Swift code that asks for privacy permissions or touches health, calendar, contacts or on-device files to the full review panel. (#4472)
  • gstack-autoplan revise --plan with a different file now says the run follows that file. (#4470)
  • /office-hours explains why it recommends a mode, quoting your own words. (#4450)
  • /office-hours keeps its 34 founder videos and essays out of the skill file, so the skill is about 8.6 KB smaller. (#4463)
  • Unattended /autoplan now runs the second-model review you turned on, and waits for it instead of ending the session. (#4459)

Security

  • A security finding's file, line and reason no longer appear in a pull request description; it shows an opaque id and the details stay in the private approval record. (#4486)
  • The secrets check now catches a secret built from short pieces with + or written in a comment, and stops flagging three kinds of ordinary code. (#4457)

Fixes

  • /ship with a token cap on Claude Code no longer stops at its first handoff: the new session now receives its prompt. Thanks @exGeni. (#4452)
  • On Claude Code, that handoff session's prompt now starts with the typed /ship command, so the skill actually loads. (#4487)
  • /ship no longer stops for an owner's sign-off when merging the base only changed base-side text. (#4458)
  • A reviewer's confirming prose no longer becomes a Critical finding that only an owner can clear. (#4458)
  • When /ship stops at its review-round limit and the owner allows one more round, that round now pays for fixing the findings instead of another read-only review. (#4479)
  • /ship on Codex no longer stops at the test coverage audit: Codex skills now start their audit and reviewer subagents with Codex's own tools (turn on multi_agent = true under [features] in ~/.codex/config.toml). (#4489)
  • /ship no longer reports zero blockers when the second-model review found one, and won't finish while that blocker is open. (#4485)
  • When /ship posts a pull request description, the count of earlier review rounds now always comes from the PR's real history; a description carrying extra history blocks could make gstack count one round where there were three. (#4440)
  • gstack-post no longer flags /ship's own run ids and commit ids as phone numbers, so posting a /ship pull request description no longer needs a confirm. (#4488)
  • /ship's review plan now sorts Swift and Xcode files by risk instead of sending every iOS pull request to the full review panel. (#4469)
  • /ship's pre-push test selection now finds the tests of a monorepo app that imports through its own @/ alias. Thanks @dtoelke. (#4464)
  • A test, or a scratch repository in the temp directory, can no longer write approval rows into your real Capy Drive. (#4466)
  • gstack's router no longer gives bug reports a special rule, so the model fixes a bug the way it would without gstack; on Claude Code, a bug report also no longer loads the router. (#4442)
  • An unattended /autoplan run on Claude Code no longer reports its phase guard as off while it is on, and a phase report written only in reasoning now gets a denial that names the fix. (#4481)
  • gstack-autoplan revise no longer refuses a plan that the first next accepted. (#4470)
  • A second-model plan review in /autoplan is no longer reported as unavailable when it actually ran. (#4471)
  • Unattended /autoplan now records the owner's relayed answer to its final question instead of refusing it. (#4484)
  • Two /autoplan runs started in the same second no longer share a run id. (#4459)
  • Two gstack-owner-answers add runs for the same answer no longer collide. (#4490)
  • skill_prefix=true now survives updates when gbrain is installed. Thanks @fliaron. (#4454)
  • The OpenClaw docs no longer send you to ClawHub, which has no current gstack skills; they point to ./setup --host openclaw. Thanks @exGeni. (#4454)
  • gstack-issue-links no longer reads other repositories' issues as gstack's. (#4454)
  • /sync-gbrain no longer says OK when pages failed to import or an artifacts push failed, and one malformed queued path no longer stops artifacts sync for every project. (#4455)
  • Packing a checkout for a Ubicloud run no longer fails when git is rewriting a ref beside it. (#4447)
  • With a custom Codex provider, the Codex readiness check and the second-model review now pick the same model: the provider's model in ~/.codex/config.toml counts only when it is the review tier's model (gpt-6-astra for the frontier tier), and both refuse any other name with the same reason. On the stock OpenAI provider, the second-model review in /autoplan and /spec now uses the review tier's model instead of config.toml's. (#4491)
  • gstack-artifact validate and ack now refuse an /autoplan run.json that gstack-autoplan didn't write, or whose journal, review outputs or checkpoint disagree with it. (#4494)

Changes for maintainers

  • A CI run that passed only after its failed jobs were re-run is now marked as such wherever gstack reuses it. (#4473)
  • /ship reuses CI's passing test run when merging the base changed no file, and stops instead of quietly starting hour-long local test runs or reviewing an empty diff. (#4461)
  • A preregistered plan for testing /ship without its separate coordinating subagent. (#4456)
  • That plan now lets case reverts that conflict with later code be resolved by hand. (#4460)
  • CI uploads free-suite test results to Trunk with analytics-uploader v2.1.8 and analytics-cli 0.17.0. (#4453)
  • A policy-floor test no longer fails once gstack's own version reaches the minor release after the newest policy key. (#4495)
  • The /plan-ceo-review HOLD SCOPE eval no longer fails a review because its follow-up question didn't repeat the mode name. (#4447)
