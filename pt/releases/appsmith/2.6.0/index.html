appsmith v2.6.0

⚠️ Para usuários EE, antes de atualizar para v2.6.0, conclua a execução do fluxo de trabalho temporal existente no v2.5.1

Appsmith está migrando para um novo mecanismo de fluxo de trabalho. Não se pode confiar que as execuções iniciadas no antigo mecanismo Temporal serão retomadas ou concluídas após a atualização para v2.6.0.

Uma execução é uma execução de um fluxo de trabalho. Isso inclui execuções que esperam que uma pessoa aprove uma solicitação, mesmo quando ela não está processando nada ativamente.

O que fazer antes de atualizar:

  1. Atualize para v2.5.1 primeiro se você estiver em uma versão anterior.
  2. Deixe todas as execuções no Temporal terminarem, incluindo aquelas que aguardam aprovação. Interrompa uma execução apenas se estiver disposto a abandonar o trabalho restante.
  3. Em Configurações de administrador → Instância → Central de administração, revise e confirme o ponto de verificação v2.5.0 · Transição do mecanismo de fluxo de trabalho. Siga o guia de transição do mecanismo de fluxo de trabalho.
  4. Atualize para v2.6.0.

Possível tempo de inatividade: a verificação de atualização pode impedir a inicialização de todo o servidor Appsmith se encontrar solicitações de aprovação pendentes do mecanismo antigo. Conclua as etapas acima antes de atualizar; não confie na verificação de inicialização para encontrar todas as execuções inacabadas.

Se a inicialização for bloqueada por este ponto de verificação, retorne para v2.5.1, termine ou interrompa deliberadamente as execuções afetadas, conclua o ponto de verificação e tente novamente a atualização.

🔐 Correção de segurança Brotli (CVE-2026-111497):

Appsmith v2.6.0 inclui a correção para uma vulnerabilidade no decodificador Node.js Brotli. O processamento de dados compactados por Brotli criados com códigos maliciosos pode corromper a memória e potencialmente causar uma falha no serviço, expor a memória do processo ou permitir a execução remota de código. Os clientes auto-hospedados devem atualizar para v2.6.0 para receber a correção. Consulte o aviso de segurança Node.js para obter detalhes.

⚠️ Notas importantes sobre atualização

  • Os arquivos docker.env customizados devem conter valores literais resolvidos. As expressões do shell interrompem a inicialização com um diagnóstico redigido. Mova as opções JVM de docker.env para Docker Compose ou configuração do ambiente Helm antes de atualizar. Os nomes OTEL_*, incluindo os terminais do exportador de rastreamento documentados, agora são aceitos. Os padrões gerados e os valores de configurações de administrador não precisam de alterações. (#42225, #42422)
  • As consultas Redis devem usar um nome de comando estático. Uma ligação no nome do comando retorna um erro de configuração de consulta. Os valores de ligação permanecem dentro de um único argumento. (#42465)
  • O plugin DynamoDB agora usa AWS SDK para Java 2.55.9. Uma região deve conter apenas letras, dígitos e hifens e ter no máximo 63 caracteres. As respostas podem incluir chaves adicionais; as chaves e os valores existentes permanecem os mesmos. Se o servidor definir AWS_ENDPOINT_URL, AWS_ENDPOINT_URL_DYNAMODB, AWS_USE_FIPS_ENDPOINT ou AWS_USE_DUALSTACK_ENDPOINT, o plugin agora os honrará. (#42346)

🔐 Segurança

  • Dependências agrupadas atualizadas para solucionar vulnerabilidades relatadas. (#42444, #42449, #42466, #42475, #42492)
  • As leituras de página e layout no modo editor agora exigem permissão de edição e retornam o rascunho. O modo de visualização ainda requer permissão de leitura e retorna a página publicada. (#42425)
  • A atualização de um aplicativo ou fonte de dados agora mantém o espaço de trabalho em que foi criado. (#42462)
  • A criação de um espaço de trabalho agora ignora um ID, políticas e grupos de permissão fornecidos pelo client. O servidor os gera. (#42478)
  • As ligações de consulta Redis permanecem dentro de um argumento de comando, portanto, um valor vinculado não pode adicionar argumentos extras. (#42465)

🛠️ Confiabilidade

  • Os aplicativos públicos recebem novamente a chave configurada do Google Maps, portanto, os widgets de mapas funcionam para visualizadores anônimos. (#42440)
  • Salvar credenciais de fonte de dados agora descarta a conexão em cache dessa fonte de dados em cada pod de servidor. (#42430)
  • O fechamento de uma conexão de fonte de dados removida não é mais executado no thread de solicitação compartilhada, portanto, um banco de dados travado não paralisa mais as verificações de integridade. (#42450)
  • As visualizações de página são registradas quando uma página é aberta, não quando o editor carrega o layout DSL. (#42429)
  • Objetos de solicitação aninhados do DynamoDB, incluindo itens de transação e configurações de índice, agora são criados sempre da mesma maneira. (#42346)

✨ Novos recursos e melhorias

  • Filtros SQL estruturados MCP podem testar isNull e notNull. (#42491)
  • Os filtros SQL estruturados do MCP podem agrupar condições com anyOf, que compila para OR e é combinado com os demais filtros. (#42495)
  • SQL estruturado MCP like pode corresponder contém, prefixo, sufixo ou texto exato. Consultas PostgreSQL podem usar ilike. (#42496)

🎨 Melhorias na interface e nos widgets

  • Em Configurações do aplicativo → Navegação, Mostrar logotipo e Mostrar título do aplicativo não mudam mais enquanto um salvamento está em andamento. (#42488)

🔧 Git, implantação e configuração

  • docker.env agora aceita nomes OTEL_*, incluindo os endpoints documentados do exportador de rastreamento OpenTelemetry. Um valor OTEL_* definido externamente ainda substitui o arquivo na reinicialização. (#42422)
  • A telemetria do navegador agora é enviada apenas para construtores. Visitantes anônimos e usuários finais de aplicativos publicados não são mais rastreados no navegador. (#42353)

appsmith v2.6.0

Highlights

  • Workflow engine cutover (EE) — v2.6.0 ships a new workflow engine, and runs started on Temporal in v2.5.x are not guaranteed to resume or finish. Treat this as a staged migration gate, not an in-place jump: land on v2.5.1 first, drain every in-flight run (including ones sitting in approval queues), acknowledge the v2.5.0 · Workflow Engine Transition checkpoint in Admin Settings → Instance → Admin central, then upgrade. The startup check can block the entire server if it detects pending old-engine approvals, and it is explicitly not exhaustive — plan a maintenance window and don't rely on that guardrail to catch everything.

  • Brotli RCE fix (CVE-2026-111497) — self-hosted operators should treat this as a security-mandatory upgrade. Crafted Brotli-compressed input can corrupt memory, crash the service, expose process memory, or enable remote code execution; v2.6.0 pulls in the Node.js decoder fix with no config change required. Combined with the bundled-dependency bumps (#42444, #42449, #42466, #42475, #42492), this is the strongest argument to move quickly if your instance is internet-facing.

  • Stricter docker.env and telemetry config — #42225/#42422 narrow docker.env to resolved literal values; shell expressions now halt startup with a redacted diagnostic, so move JVM options out into Docker Compose or Helm env config before upgrading or you won't boot. The upside: OTEL_* names, including the documented trace exporter endpoints, are now accepted — though an externally set OTEL_* still overrides the file on restart. Generated defaults and Admin Settings values need no changes, so the work is mainly auditing custom env files.

  • Datasource plugin behavior shifts — two changes that query authors will feel. Redis now requires a static command name; binding into the command slot is a hard query-configuration error, while bound values must stay inside a single argument — this closes an argument-injection path (#42465). DynamoDB moves to AWS SDK for Java 2.55.9 (#42346): region strings are validated to letters/digits/hyphens and ≤63 chars, responses may include extra keys, and the plugin now honors AWS_ENDPOINT_URL, AWS_ENDPOINT_URL_DYNAMODB, AWS_USE_FIPS_ENDPOINT, and AWS_USE_DUALSTACK_ENDPOINT set server-side — welcome news for custom endpoints and FIPS/dual-stack setups.

  • Permission and data-ownership hardening — #42425 tightens editor-mode page/layout reads to require edit permission and return the draft, while view mode still requires read and returns the published page; automations using read-only credentials against editor endpoints should expect 403s. #42462 preserves an app's/datasource's original workspace on update, and #42478 ignores client-supplied workspace id, policies, and permission groups on create (the server generates them) — clients that set those fields will see them silently replaced.

  • MCP SQL filters and reliability polish — the structured SQL filter language gains genuine query power: isNull/notNull (#42491), anyOf grouping that compiles to OR and composes with other filters (#42495), and like with contains/prefix/suffix/exact matching plus PostgreSQL ilike (#42496). Operationally, saved datasource credentials now purge cached connections on every pod (#42430) and evicted-connection cleanup moves off the shared request thread so one hung database no longer stalls health checks (#42450); public apps get the configured Maps key back (#42440). Watch that browser telemetry is now builders-only (#42353) — anonymous and end-user activity disappears from browser analytics.

⚠️ For EE users, before upgrading to v2.6.0 finish existing Temporal workflow runs on v2.5.1

Appsmith is moving to a new workflow engine. Runs that started on the old Temporal engine cannot be relied on to resume or finish after upgrading to v2.6.0.

A run is one execution of a workflow. This includes executions waiting for a person to approve a request, even when they are not actively processing anything.

What to do before upgrading:

  1. Upgrade to v2.5.1 first if you are on an earlier version.
  2. Let all runs on Temporal finish, including any waiting for approval. Stop a run only if you are willing to abandon its remaining work.
  3. In Admin Settings → Instance → Admin central, review and acknowledge the v2.5.0 · Workflow Engine Transition checkpoint. Follow the workflow engine transition guide.
  4. Upgrade to v2.6.0.

Possible downtime: the upgrade check can prevent the entire Appsmith server from starting if it finds pending approval requests from the old engine. Complete the steps above before upgrading; do not rely on the startup check to find every unfinished run.

If startup is blocked by this checkpoint, return to v2.5.1, finish or deliberately stop the affected runs, complete the checkpoint, and retry the upgrade.

🔐 Brotli security fix (CVE-2026-111497):

Appsmith v2.6.0 includes the fix for a vulnerability in the Node.js Brotli decoder. Processing maliciously crafted Brotli-compressed data can corrupt memory and potentially cause a service crash, expose process memory, or allow remote code execution. Self-hosted customers should upgrade to v2.6.0 to receive the fix. See the Node.js security advisory for details.

⚠️ Important Upgrade Notes

  • Customized docker.env files must contain resolved literal values. Shell expressions stop startup with a redacted diagnostic. Move JVM options from docker.env to Docker Compose or Helm environment configuration before upgrading. OTEL_* names, including the documented trace exporter endpoints, are now accepted. Generated defaults and Admin Settings values need no changes. (#42225, #42422)
  • Redis queries must use a static command name. A binding in the command name returns a query configuration error. Binding values stay inside a single argument. (#42465)
  • The DynamoDB plugin now uses AWS SDK for Java 2.55.9. A region must contain only letters, digits, and hyphens, and be at most 63 characters. Responses can include additional keys; existing keys and values stay the same. If the server sets AWS_ENDPOINT_URL, AWS_ENDPOINT_URL_DYNAMODB, AWS_USE_FIPS_ENDPOINT, or AWS_USE_DUALSTACK_ENDPOINT, the plugin now honors them. (#42346)

🔐 Security

  • Updated bundled dependencies to address reported vulnerabilities. (#42444, #42449, #42466, #42475, #42492)
  • Editor-mode page and layout reads now require edit permission and return the draft. View mode still requires read permission and returns the published page. (#42425)
  • Updating an application or datasource now keeps the workspace it was created in. (#42462)
  • Creating a workspace now ignores a client-supplied id, policies, and permission groups. The server generates them. (#42478)
  • Redis query bindings stay inside one command argument, so a bound value cannot add extra arguments. (#42465)

🛠️ Reliability

  • Public apps again receive the configured Google Maps key, so Map widgets work for anonymous viewers. (#42440)
  • Saving datasource credentials now drops that datasource's cached connection on every server pod. (#42430)
  • Closing an evicted datasource connection no longer runs on the shared request thread, so one hung database no longer stalls health checks. (#42450)
  • Page views are recorded when a page is opened, not when the editor loads layout DSL. (#42429)
  • Nested DynamoDB request objects, including transaction items and index settings, are now built the same way every time. (#42346)

✨ New Features & Enhancements

  • MCP structured SQL filters can test isNull and notNull. (#42491)
  • MCP structured SQL filters can group conditions with anyOf, which compiles to OR and is combined with the other filters. (#42495)
  • MCP structured SQL like can match contains, prefix, suffix, or exact text. PostgreSQL queries can use ilike. (#42496)

🎨 UI & Widget Improvements

  • In App Settings → Navigation, Show logo and Show application title no longer switch themselves while a save is in progress. (#42488)

🔧 Git, Deployment & Configuration

  • docker.env now accepts OTEL_* names, including the documented OpenTelemetry trace exporter endpoints. An externally set OTEL_* value still overrides the file on restart. (#42422)
  • Browser telemetry is now sent for builders only. Anonymous visitors and end users of published apps are no longer tracked in the browser. (#42353)
