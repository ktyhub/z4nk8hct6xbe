#Agente-Reach v1.4.1

Correção

** Corrigido o problema de falha na instalação do código-fonte. ** Instalações recentes de GitHub (pip install .../archive/main.zip, pipx, uvx) falharão diretamente na construção devido ao empacotamento repetido das rodas:

ValueError: A second file is being added to the wheel archive at the same path:
`agent_reach/guides/setup-exa.md`

A razão é que packages = ["agent_reach"] em pyproject.toml já contém guides/, skill/ e scripts/, e force-include os empacota novamente - a nova versão do hatchling relata diretamente um erro sobre isso. Blocos redundantes de inclusão forçada foram removidos (#329).

Verificado: wheel foi construído de forma limpa (sem entradas duplicadas), SKILL.md/guides/scripts são todos distribuídos normalmente com o pacote e 85 testes são todos verdes.

  • Fechar: #308 #315 #328 #332 #334
  • Obrigado a @nyxst4ck(#329) e @1131096740(#319) por enviar a correção 🙏

Reforço de CI

Adicionado controle de acesso de construção de roda (#340): Cada envio irá realmente construir a roda, verificar se não há entradas duplicadas, confirmar se o arquivo de dados está no pacote e instalá-lo em um ambiente limpo. Anteriormente, o CI executava apenas instalações editáveis ​​(pip install -e .) e nunca conseguia detectar problemas de empacotamento - tais bugs não podiam mais ser liberados estruturalmente.

Método de atualização

Envie esta frase ao seu agente:

帮我更新 Agent Reach:https://raw.githubusercontent.com/Panniantong/agent-reach/main/docs/update.md

ou manualmente:

pip install --upgrade https://github.com/Panniantong/agent-reach/archive/main.zip

Agent-Reach v1.4.1

Highlights

  • Source-install fix (#329) — The release's whole reason for existing: pip install .../archive/main.zip, pipx, and uvx installs were dying at wheel-build time with ValueError: A second file is being added to the wheel archive at the same path: agent_reach/guides/setup-exa.md. Root cause was pyproject.toml declaring packages = ["agent_reach"] (already covering guides/, skill/, scripts/) while a redundant force-include block packed those same files a second time — newer hatchling promotes that duplication to a hard error. Removing the block (#329, with a second fix in #319) unblocks the most common install path for tool-based users; closes #308, #315, #328, #332, #334.

  • Bundled assets still ship — Worth verifying because packaging fixes often silently drop data files: SKILL.md, guides, and scripts are confirmed present in the wheel and all 85 tests pass. No runtime code changed, so this is a low-risk distribution repair rather than a behavior change — upgrading won't break Skill or guide discovery.

  • Wheel-build gate in CI (#340) — The structural fix behind the fix. CI previously only ran pip install -e ., an editable install that never exercises wheel assembly, so duplicate-entry regressions were invisible until adopters hit them. Every commit now builds a real wheel, asserts no duplicate paths, confirms data files are inside the package, and smoke-installs into a clean venv — this class of bug is now blocked pre-release instead of found by users.

  • Upgrade path is self-referential — watch the first install — Pick up the fix by sending your Agent the update URL (docs/update.md on main) or running pip install --upgrade https://github.com/Panniantong/agent-reach/archive/main.zip. The catch: that command targets the very main.zip archive that was broken, and only works now because the fix has landed on main. pipx/uvx users should confirm their tool re-resolves main rather than reusing a cached broken archive.

No breaking changes.

修复

修复了源码安装失败的问题。 近期从 GitHub 安装(pip install .../archive/main.zip、pipx、uvx)会因 wheel 重复打包直接构建失败:

ValueError: A second file is being added to the wheel archive at the same path:
`agent_reach/guides/setup-exa.md`

原因是 pyproject.toml 中 packages = ["agent_reach"] 已经包含了 guides/、skill/、scripts/,而 force-include 又把它们打包了一遍——新版 hatchling 对此直接报错。现已删除冗余的 force-include 块(#329)。

已验证:wheel 构建干净(无重复条目)、SKILL.md / guides / scripts 全部正常随包分发、85 个测试全绿。

  • 关闭:#308 #315 #328 #332 #334
  • 感谢 @nyxst4ck(#329)与 @1131096740(#319)提交修复 🙏

CI 加固

新增 wheel-build 门禁(#340):每次提交都会真实构建 wheel、校验无重复条目、确认数据文件在包内,并在干净 venv 中冒烟安装。此前 CI 只跑 editable 安装(pip install -e .),永远测不到打包问题——这类 bug 从此结构性地无法再发布出去。

升级方式

把这句话发给你的 Agent:

帮我更新 Agent Reach:https://raw.githubusercontent.com/Panniantong/agent-reach/main/docs/update.md

或手动:

pip install --upgrade https://github.com/Panniantong/agent-reach/archive/main.zip
