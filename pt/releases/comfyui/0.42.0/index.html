ComfyUI v0.42.0

Highlights

  • New image & multimodal model support — MOSS-image lands (#17095) with fused Situ sampling (#17099) for faster, lower-memory inference, joined by the Krea 3 Image partner node (#17067) and refreshed FLUX 3 Image display labels (#17075). Embedding models can now also be loaded onto Qwen3.5 (#17159). If you build image workflows, these drop into existing graphs — but expect to re-tune prompts and checkpoints, and note that the partner nodes are the ones most likely to churn between minor releases.

  • Qwen 3.x gets faster and better-structured — Part 2 of the Qwen 3.x performance work (#17007) continues the inference speedups, while #17121 fixes think-block handling in TextGenerate templates. The practical impact is lower latency on Qwen-backed text nodes plus corrected <think>/reasoning output formatting — worth regression-testing any workflow that parses model text, since the "fixed" output shape may differ from what your downstream nodes previously assumed.

  • 3D pipeline refactored — Remeshing has been reworked (#16805), with new support for models that have PDD baked in (#17157) and NAF neighborhood attention now operating per LR cell (#17155); a crash on solid mode with an empty mesh is also fixed (#17140). These are behavior-level, not just cosmetic, changes to the 3D node stack — re-validate generated meshes and attention quality before relying on them in production, especially if you used the old remeshing defaults.

  • Partner-node model removal needs a migration — The Quiver node set drops the retired Arrow 1.x models (#17102). Saved workflows that still reference those checkpoint names will fail to resolve, so audit your graphs and repoint them to current Arrow models. This is the one change here likely to break existing projects rather than merely extend them.

  • Device and platform constraints changed — ARM Linux is now covered by execution and unit tests (#17139), widening validated deployment targets. Conversely, CPU devices no longer support fp8, nvfp4, mxfp8 or int8 (#17170): CPU-only users running quantized checkpoints will hit errors and must move those workloads to GPU or use an unquantized model — check your dtype settings before upgrading if you run on CPU.

  • Stability and dependency housekeeping — Fixes restore the webcam node (#17144) and correct text-generation cleanup/teardown (#17169), so long-running sessions should leak less. comfy-kitchen is bumped to 0.2.39 (#17171), the Comfy quant format gains better docs (#17078), and the frontend package moves to 1.55.18 (#16859). No action needed unless you pinned those dependencies yourself.
