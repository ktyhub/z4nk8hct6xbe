canal canal-1.1.2

Highlights

  • MySQL 8.0 binlog parsing — canal-1.1.2 adds解析 support for MySQL 8.0's binlog format, which diverged enough from 5.7 (different metadata/row-image encoding) that older builds could mis-decode or fail outright against an 8.0 source. For teams planning an 8.0 migration this is the gating feature: you can point canal at 8.0 directly rather than staging binlogs through a 5.7 intermediary. Pair it with #1189, which fixes garbled binlog filename parsing — worth checking if your filename encoding was previously being mangled.

  • Built-in ClientAdapter sinks — canal now ships client adapters that write straight to HBase, relational DBs (MySQL/PostgreSQL/Oracle/SQL Server), and Elasticsearch, so you can get from binlog to a target store without writing your own consumer. The catch is explicit in the release notes: adapters are in rapid iteration and their interfaces change between versions. Pin your canal version and re-read the wiki on upgrade — this is the least stable surface in the release.

  • MQ config migration & auto-scan — MQ send settings moved out of mq.yml into canal.properties, which now supports auto-scan/hot reload. This is a real migration step for Kafka/RocketMQ deployments: existing mq.yml files are no longer the source of truth, so re-apply broker/topic settings in canal.properties and verify reload behavior at deploy time. The dynamism is a win for config management, but static mq.yml edits will silently stop taking effect.

  • Message delivery correctness — #1104 fixes a correctness bug where, after a RocketMQ/Kafka send failed and rolled back, the position was still committed — events could be lost while appearing acknowledged. #1120 changes FlatMessage so columns whose value is null are no longer stripped from the payload. Both are behavioral changes consumers should validate: downstream now sees null-valued columns it previously didn't, and at-least-once behavior is actually upheld after failures.

  • Cloud & schema-tracking hardening — #1169 adds direct delivery to Alibaba Cloud ONS (managed RocketMQ), and #1076 makes RDS OSS binlog downloads more resilient via position-based auto-rollback when the local offset has drifted. TableMeta TSDB also gets two fixes (#1168 daily snapshot failing when filters change, #1100 int display-width mismatches), cutting false schema-drift alarms for schema-management workflows.

功能新增

  1. 支持mysql8.0的binlog解析 【BinlogChange(MySQL8)】
  2. canal提供内置的客户端能力【ClientAdapter】
    • 同步到HBase wiki
    • 同步到Rdb(支持mysql/pg/oracle/sqlserver) wiki
    • 同步到ES wiki
    • 目前adapter为支持更多常见的目标存储，会处于快速迭代中，不同版本之间会有接口调整，请及时关注文档
  3. RocketMQ消息支持直接投递至aliyun ons(RocketMQ云服务) #1169

功能重构

  1. MQ消息发送的配置相关从mq.yml调整至canal.properties，支持了auto scan的能力，请关注最新的配置文档 wiki

小需求&bugfix

  1. 修复mysql binlog文件名解析乱码问题 #1189
  2. 修复修复TableMeta TSDB在每天定时snapshot因filter变化导致失败 #1168
  3. 修复canal docker支持MQ模式启动失败问题 #1087
  4. 修复TableMeta TSDB支持int display width不一致问题 #1100
  5. 修复rocketmq&kafka 发送消息失败时回滚后继续提交的问题 #1104
  6. 修复alter rename 的ddl 类型解析错误的问题 #1103
  7. 修复FlatMessage 中data过滤掉了 value null的column #1120
  8. 优化aliyun rds oss binlog下载的能力，支持基于位点自动回溯 #1076
