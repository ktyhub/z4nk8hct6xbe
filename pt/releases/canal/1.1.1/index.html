canal canal-1.1.1

Highlights

  • MQ fan-out broadens with pk-hash partitioning — RocketMQ becomes a first-class delivery backend (#695) alongside Kafka, and both now support hashing by primary key into multiple partitions (#958). For adopters this is the headline: pk-hash keeps all changes for a given row ordered within a single partition while letting you scale consumers horizontally — but choosing a stable pk is now correctness-critical, since rows without one can land unpredictably and break per-row ordering guarantees.

  • HBase and non-JVM clients close the ecosystem gap — Native HBase sync (#849) plus new community C# (CanalSharp) and Go (canal-go) clients mean binlog consumers are no longer forced onto the Java/ClientAdapter path. Teams running mixed stacks can drop bespoke bridges, but note these two clients are separate upstream repos with their own release cadence — pin versions and validate them against 1.1.1's wire format.

  • proto2 → proto3 (3.6.1) is the upgrade to watch — The protocol bump is the real migration hazard here: serialize/deserialize semantics and generated code differ between proto2 and proto3, so you must regenerate all clients (Java, C#, Go) against the 3.6.1 schema in lockstep. Rolling this out with older proto2-generated clients risks decode failures or silently defaulted fields — treat it as a coordinated, all-at-once cutover, not a rolling one.

  • Java client shades Guava to end classpath wars (#912) — Guava is now packaged inside the client instead of pulled transitively, which resolves version clashes in larger applications. If your build implicitly relied on canal's Guava version being on the classpath, that dependency is no longer exported — audit your dependency tree and declare Guava explicitly where needed.

  • Operational hardening worth upgrading for — A cluster of fixes removes common production failure modes: single-core startup crash (#873), GTID races in parallel parse mode (#881), a thread-leak-driven OOM when MySQL stays unreachable (#968), out-of-bounds parsing for MySQL set and bit(8) values, and Docker --restart failures (#1001). Password encryption in config (#990) and TTL-based cleanup for tablemeta TSDB data (#1047) are quiet but important wins for security posture and long-running metadata growth.

功能新增

  1. 原生支持RocketMQ消息投递 #695 【Canal Kafka QuickStart】
  2. 原生支持hbase的数据同步 #849 ClientAdapter
  3. 新增c#/go多语言客户端的支持
    • canal java客户端: https://github.com/alibaba/canal/wiki/ClientExample
    • canal c#客户端开源项目地址： https://github.com/CanalSharp/CanalSharp
    • canal go客户端开源项目地址： https://github.com/CanalClient/canal-go
  4. MQ消息投递支持按pk hash到多个分区partition(Kafka/RocketMQ均支持) #958

小需求&bugfix

  1. 修复单核环境下的canal启动异常问题 #873
  2. 修复parse并行解析模式gtid的并发问题 #881
  3. java client内聚guava打包,解决和外部系统的版本冲突问题 #912
  4. 升级proto2为proto3(3.6.1),支持更多的跨语言能力
  5. 支持配置中数据库密码加密处理 #990
  6. 并行解析下，数据库一直连不上导致OOM异常(线程数泄漏,出现暴涨) #968
  7. mysql set类型8值情况解析越界bugfix otter#617
  8. 支持otter使用canal的新特性，比如rds ak/sk配置、tsdb配置
  9. 修复docker部署canal-server无法使用 docker-restart命令 #1001
  10. 修复mysql bit(8)类型8值情况解析越界bugfix
  11. tablemeta tsdb数据增加过期清理能力 #1047
