Codewhale v0.9.3

Codewhale é o produto público da Shannon Labs. O codewhale os nomes de comando, pacote npm e release-asset permanecem técnicos em letras minúsculas identificadores. O pacote npm legado deepseek-tui está obsoleto e não recebe mais lançamentos. Usuários provenientes do legado v0.8.x deepseek / Os nomes deepseek-tui deverão migrar com docs/REBRAND.md.

Instalar

Recomendado — npm (um comando, todos os três pontos de entrada)

npm install -g codewhale

O wrapper baixa os codewhale, codew e codewhale-tui correspondentes binários desta versão e os coloca no mesmo diretório.

Docker/GHCR

docker run --rm -it \
  -e DEEPSEEK_API_KEY="$DEEPSEEK_API_KEY" \
  -v codewhale-home:/home/codewhale/.codewhale \
  ghcr.io/hmbown/codewhale:v0.9.3

A imagem envia o despachante codewhale, o calço codew e o tempo de execução codewhale-tui. A tag latest também é atualizada no lançamento.

Carga (Linux / macOS)

cargo install codewhale-cli codewhale-tui --locked

Ambas as caixas são necessárias - codewhale-cli produz o despachante codewhale e o calço codew, enquanto codewhale-tui produz o tempo de execução interativo ao qual o despachante delega. A instalação de apenas uma caixa falhará em tempo de execução com um erro MISSING_COMPANION_BINARY.

O que há em v0.9.3

Este é o candidato de origem Codewhale v0.9.3. Não é um lançamento publicado até que a tag, os pacotes, as somas de verificação e os ativos de lançamento correspondentes existam. DeepSeek V4 Flash agora é uma rota Codewhale de primeira classe, e o agente voltado para superfície da ferramenta foi reduzida às ferramentas de ação canônica que atuais os modelos realmente precisam. Esta versão também fortalece credenciais, autorização, durabilidade, compactação e limites do provedor de arquivos macOS durante a exclusão tempo de execução obsoleto e superfície de dependência.

Adicionado

  • Suporte nativo deepseek-v4-flash sobre as respostas API do DeepSeek, incluindo repetição de item de raciocínio sem estado, eventos terminais SSE semânticos, estruturados chamadas de função e saídas, apply_patch e formato de fio com reconhecimento de modelo seleção. Os Flash IDs atuais exatos usam respostas; futuro direto Os IDs do modelo deepseek-vN-* herdam essa rota de forma conservadora, enquanto os IDs personalizados Endpoints compatíveis com DeepSeek retêm conclusões de bate-papo, a menos que sejam configurados caso contrário.
  • Uma transferência codewhale auth print-api-key somente para tubos explicitamente selecionados fornecedores. Ele compartilha a autoridade de credencial de escopo doméstico da Codewhale, recusa saída do terminal e evita que os marcadores de posição sentinela se tornem ativos credenciais.
  • Aplicação max_tool_calls por turno no portão de admissão do motor, além de um escopo de gravação de arquivo nomeado com uma costura de leitura separada. O tempo de execução agora rejeita chamadas acima do orçamento antes da execução e mantém o limite de gravação do operador explícito (#4415).
  • Catracas de contrato de tempo de execução, estrutura de origem e backlog de persistência que desvio de nome em vez de permitir que grandes superfícies de propriedade cresçam silenciosamente (#3921, #4785).

Alterado

  • Os integrados visíveis ao modelo agora usam os canônicos Bash, File e Run esquemas de ação. apply_patch permanece disponível como único personalizado direto ferramenta de edição suportada pelo DeepSeek Responses. O fluxo de trabalho agrupado de stop-ship, Acessórios de frota, atalhos de shell e testes de motor usam o mesmo código canônico vocabulário.
  • Solicitações canônicas File { action: "write" } agora passam pelo mesmo verificações semânticas de repo-law como o antigo caminho de gravação. Aprovação, Acesso Total, e a execução do fluxo de trabalho não pode ignorar o piso de segurança do repositório escolhendo o esquema canônico.
  • A resolução inicial do Codewhale é compartilhada entre CLI, TUI, estado e segredo lojas. doctor está offline por padrão, distingue a fonte da credencial de disponibilidade e relata um instantâneo de caminho consistente.
  • Gravações de eventos de tempo de execução duráveis são serializadas em processos simultâneos, o bloqueio do histórico aguarda a saída dos trabalhadores assíncronos e o esgotamento da cota do provedor permanece digitado e pode ser tentado novamente por meio de compactação (#4522).
  • A descoberta de habilidades armazena em cache o catálogo mesclado por trás da validação do tempo assistido; grandes blocos de teste de habilidade, mecanismo, subagente, UI e ambiente-oceano agora residem em costuras de teste próprias.
  • Os resumos de raciocínio permanecem no idioma do usuário, água-viva completa as silhuetas são realocadas em torno do texto transcrito e os quadros do oceano em cache incluem sua identidade de paleta (#4807).
  • O contrato de ordem de autorização agora documenta e testa como modos, ganchos, regras de permissão, pisos de segurança, lei de recompra, aprovações e composição de sandbox (PR #4980).

Corrigido

  • As extensões de sandbox do macOS cobrem espaços de trabalho do CloudStorage/File Provider sem ampliando caminhos não relacionados; obrigado @Watcher24 pelo relatório #4085 e reprodução.
  • O estado do shell em primeiro plano é desconectado antes da direção, portanto, um comando interrompido não pode continuar possuindo o compositor (PR #4979).
  • Falhas no nível do aplicativo MCP e envelopes de erro malformados falham ao fechar em vez de parecer uma saída de ferramenta bem-sucedida.
  • As falhas opcionais do PDF são verdadeiras e a classificação do PDF não falha mais entradas suportadas.
  • O conteúdo da pasta entre colchetes é editado a partir de rastreamentos e diagnósticos de credenciais nunca trate sentinelas de espaço reservado como chaves utilizáveis.

Removido

  • Os aliases herdados que podem ser chamados exec_shell, run_shell_command, read_file, write_file, list_dir, grep_files, file_search e a duplicata Registros de trabalho/RLM. A transcrição histórica e a semântica política permanecem legível, mas os novos modelos de curvas recebem apenas a superfície de ação canônica.
  • A cadeia de dependência do analisador de PDF incluída, substituindo-a pela menor limite de extração opcional rastreado por #4382.

Colaboradores

  • Turisla (@greyfreedom) documentado e bloqueou o contrato de ordem de autorização no PR #4980.
  • Nightt (@nightt5879) primeiro plano fixo desprendimento de projéteis antes de dirigir em PR #4979.
  • Watcher24 (@Watcher24) forneceu o macOS Relatório e reprodução do provedor de arquivos para #4085.
  • Fred Leitz (@fleitz) retém o necessário crédito do candidato-fonte pela correção canônica do espaço de trabalho Bash do PR #4673 e edição #4674. Consulte CHANGELOG.md para notas completas e docs/CHANGELOG_ARCHIVE.md para versões mais antigas.

Codewhale v0.9.3

Highlights

  • DeepSeek V4 Flash becomes a first-class route, with a conservative wire-format split — Native deepseek-v4-flash now runs over DeepSeek's Responses API with stateless reasoning-item replay, semantic SSE terminal events, structured function calls/outputs, and apply_patch. The practical wrinkle for adopters: only exact Flash IDs take the Responses path; future direct deepseek-vN-* IDs inherit it conservatively, and custom DeepSeek-compatible endpoints silently stay on Chat Completions unless explicitly reconfigured. If you rely on a custom endpoint, don't assume Flash semantics apply without opting in.

  • Legacy tool aliases are removed — this is the breaking change that will bite existing integrations — New model turns receive only the canonical Bash, File, Run action surface; exec_shell, run_shell_command, read_file, write_file, list_dir, grep_files, file_search, and the duplicate Work/RLM registrations are gone, with apply_patch left as the sole direct custom edit tool. Historical transcripts and stored policies remain readable, so this won't corrupt old sessions — but any custom tool definitions, hooks, or policy rules keyed to the old names must be rewritten or they'll stop resolving on new turns. Budget a migration pass before upgrading if you've customized the tool surface.

  • The repo-law safety floor can no longer be bypassed by schema choice — Canonical File { action: "write" } now goes through the same semantic repo-law checks as the former write path, and the authorization-order contract is documented and locked by tests in PR #4980. This closes a real escape hatch: Approval, Full Access, and workflow execution can't slip a write past the repository safety boundary just by using the canonical schema. Expect previously-permitted writes in permissive modes to start getting gated — that's intentional, not a regression.

  • Per-turn tool budgets are enforced at admission, not after the fact (#4415) — max_tool_calls is now checked at the engine gate, and over-budget calls are rejected before execution; writes are additionally constrained to a named-file scope with a separate read seam. Agents that used to "get away" with long chains of small calls will now see hard rejections rather than throttling, so tune budgets and favor fewer, larger actions. The named-file scope also makes the operator's write boundary explicit, which is worth reviewing if your agent writes outside a single project root.

  • Install and credential paths changed — mind the two-crate contract and offline doctor — Cargo users must install both codewhale-cli and codewhale-tui; pulling only one fails at runtime with MISSING_COMPANION_BINARY. The old deepseek-tui package is deprecated with no further releases, and v0.8.x deepseek/deepseek-tui users must follow docs/REBRAND.md. On the credential side, doctor is now offline by default and separates credential source from availability, and the new codewhale auth print-api-key is pipe-only (refuses terminal output, rejects sentinel placeholders). Scripts that parse doctor output or pipe keys to a TTY will need updating.

  • Durability and fail-closed hardening land across the runtime — Durable event writes are serialized across concurrent processes and blocking history waits move off async workers, with provider quota exhaustion kept typed and retryable through compaction (#4522). On the security side: macOS sandbox extensions now cover CloudStorage/File Provider workspaces without widening unrelated paths (#4085), foreground shell state detaches before steering so an interrupted command can't hold the composer (PR #4979), MCP application-level and malformed-envelope errors fail closed instead of masquerading as successful tool output, and bracketed-paste contents are redacted from traces. Note the bundled PDF parser chain is dropped in favor of a smaller optional extraction boundary (#4382), so PDF handling now depends on that optional path — and the NSIS installer is still unsigned, so expect a SmartScreen prompt on Windows.

Codewhale is the public product from Shannon Labs. The codewhale command, npm package, and release-asset names remain lowercase technical identifiers. The legacy npm package deepseek-tui is deprecated and receives no further releases. Users coming from v0.8.x legacy deepseek / deepseek-tui names should migrate with docs/REBRAND.md.

What's in v0.9.3

This is the Codewhale v0.9.3 source candidate. It is not a published release until the matching tag, packages, checksums, and release assets exist.

DeepSeek V4 Flash is now a first-class Codewhale route, and the agent-facing tool surface has been reduced to the canonical action tools that current models actually need. This release also hardens credential, authorization, durability, compaction, and macOS File Provider boundaries while deleting stale runtime and dependency surface.

Added

  • Native deepseek-v4-flash support over DeepSeek's Responses API, including stateless reasoning-item replay, semantic SSE terminal events, structured function calls and outputs, apply_patch, and model-aware wire-format selection. Exact current Flash IDs use Responses; future direct deepseek-vN-* model IDs inherit that route conservatively, while custom DeepSeek-compatible endpoints retain Chat Completions unless configured otherwise.
  • A pipe-only codewhale auth print-api-key handoff for explicitly selected providers. It shares Codewhale's home-scoped credential authority, refuses terminal output, and prevents sentinel placeholders from becoming live credentials.
  • Per-turn max_tool_calls enforcement at the engine admission gate, plus a named-file write scope with a separate read seam. The runtime now rejects over-budget calls before execution and keeps the operator's write boundary explicit (#4415).
  • Runtime-contract, source-structure, and persistence-backlog ratchets that name drift instead of allowing large ownership surfaces to grow silently (#3921, #4785).

Changed

  • Model-visible built-ins now use the canonical Bash, File, and Run action schemas. apply_patch remains available as the one direct custom edit tool supported by DeepSeek Responses. The bundled stop-ship workflow, Fleet fixtures, shell shortcut, and engine tests use the same canonical vocabulary.
  • Canonical File { action: "write" } requests now pass through the same semantic repo-law checks as the former write path. Approval, Full Access, and workflow execution cannot bypass the repository safety floor by choosing the canonical schema.
  • Codewhale home resolution is shared across the CLI, TUI, state, and secret stores. doctor is offline by default, distinguishes credential source from availability, and reports one consistent path snapshot.
  • Durable runtime event writes are serialized across simultaneous processes, blocking history waits move off async workers, and provider quota exhaustion remains typed and retryable through compaction (#4522).
  • Skill discovery caches the merged catalog behind watched-mtime validation; large skill, engine, subagent, UI, and ambient-ocean test blocks now live in owned test seams.
  • Reasoning summaries stay in the user's language, complete jellyfish silhouettes relocate around transcript text, and cached ocean frames include their palette identity (#4807).
  • The authorization-order contract now documents and tests how modes, hooks, permission rules, safety floors, repo law, approvals, and sandboxing compose (PR #4980).

Fixed

  • macOS sandbox extensions cover CloudStorage/File Provider workspaces without broadening unrelated paths; thanks @Watcher24 for the #4085 report and reproduction.
  • Foreground shell state detaches before steering, so an interrupted command cannot keep owning the composer (PR #4979).
  • MCP application-level failures and malformed error envelopes fail closed instead of looking like successful tool output.
  • Optional PDF failures are truthful and PDF classification no longer misses supported inputs.
  • Bracketed-paste contents are redacted from traces, and credential diagnostics never treat placeholder sentinels as usable keys.

Removed

  • The legacy callable aliases exec_shell, run_shell_command, read_file, write_file, list_dir, grep_files, file_search, and the duplicate Work/RLM registrations. Historical transcript and policy semantics remain readable, but new model turns receive only the canonical action surface.
  • The bundled PDF parser dependency chain, replacing it with the smaller optional extraction boundary tracked by #4382.

Contributors

  • Turisla (@greyfreedom) documented and locked the authorization-order contract in PR #4980.
  • Nightt (@nightt5879) fixed foreground shell detachment before steering in PR #4979.
  • Watcher24 (@Watcher24) provided the macOS File Provider report and reproduction for #4085.
  • Fred Leitz (@fleitz) retains required source-candidate credit for the canonical Bash workspace fix from PR #4673 and issue #4674.
