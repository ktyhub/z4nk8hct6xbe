Codewhale v0.8.63

CodeWhale é o projeto canônico, comando, pacote npm e nome do ativo de liberação. O pacote npm legado deepseek-tui é obsoleto e não recebe mais lançamentos. Usuários vindos de Nomes legados v0.8.x deepseek / deepseek-tui devem migrar com docs/REBRAND.md.

Instalar

Recomendado — npm (um comando, ambos os binários)

npm install -g codewhale

O wrapper baixa ambos os binários desta versão e os coloca no mesmo diretório.

Docker/GHCR

docker run --rm -it \
  -e DEEPSEEK_API_KEY="$DEEPSEEK_API_KEY" \
  -v ~/.deepseek:/home/codewhale/.deepseek \
  ghcr.io/hmbown/codewhale:v0.8.63

A imagem envia o despachante codewhale e o tempo de execução codewhale-tui. A tag latest também é atualizada no lançamento.

Carga (Linux / macOS)

cargo install codewhale-cli codewhale-tui --locked

Ambas as caixas são necessárias — codewhale-cli produz o despachante codewhale e codewhale-tui produz o tempo de execução interativo ao qual o despachante delega. A instalação de apenas um binário falhará em tempo de execução com um erro MISSING_COMPANION_BINARY.

O que há em v0.8.63

Adicionado

  • Proteções de distribuição de subagentes (#3318, #3319). Execuções de fluxo de trabalho com alta distribuição podem agora enfileira e drena mais agentes do que o limite de simultaneidade instantânea padrão, com [subagents] max_admitted disponível para ajustar esse limite população de admissão. Chamadas agent distintas não são mais limitadas pelo proteção de loop por turno antes do lançamento do tempo de execução simultaneidade e provedor a retirada do limite de taxa pode ser aplicada. [subagents] token_budget aplica um compartilhamento teto de token agregado para uma execução raiz agent e seus descendentes.
  • Aplicação de token de subagente por trabalhador (#3321). A token_budget / max_tokens definido em uma chamada agent individual agora limita aquele único trabalhador no meio da execução: uma vez que seus tokens de modelo acumulados excedem o limite, ele para de forma limpa com status budget_exhausted em vez de executar para max_steps. Isto complementa a porta de admissão em nível de escopo (#3319) – o limite por trabalhador termina um trabalhador fugitivo, o limite do escopo limita a distribuição total - sem contagem dupla. Colhido de #3321 por @donglovejava.
  • Configuração de fanout do subagente específico do provedor. [subagents.providers.<provider>] perfis agora substituem enabled, max_concurrent, max_admitted, launch_concurrency, max_depth, orçamento de token, tempo limite de API e pulsação tempo limite para o provedor ativo. Use perfis amplos diretos-API, como [subagents.providers.deepseek] e perfis de assinatura mais restritos, como [subagents.providers.glm]; /config subagents status mostra tanto global e valores resolvidos pelo provedor ativo.
  • Controle e isolamento de subagentes. A única ferramenta agent agora expõe status, espiar e cancelar ações para crianças em execução e aceita worktree: true para criar uma árvore de trabalho/branch git isolada para edição paralela faixas em vez de exigir que os chamadores rolem manualmente um cwd.

Corrigido

  • Correção do modo e do catálogo de ferramentas. As principais ferramentas de ação permanecem detectáveis na pesquisa de catálogo/ferramenta voltada para o modelo e sinalizadores de autoverificação de consistência manipuladores registrados que saem do catálogo anunciado. Em busca de revisão prompts no modo Agente/YOLO explícito agora mantêm o modo e as ferramentas solicitadas, com apenas uma dica de revisão consultiva.
  • Recuperação de orquestração de subagentes. Os agentes filhos agora tentam novamente de forma transitória o cabeçalho do provedor/tempo limite de SSE antes da falha e as execuções pai sintetizam perdidas conclusões filho do estado filho terminal para que a orquestração não possa ficar presa a um evento de conclusão perdido.
  • Chamadas da ferramenta de pensamento DeepSeek. Solicitações de conclusão de bate-papo do DeepSeek agora são omitidas tool_choice explícito sempre que o raciocínio/pensamento estiver habilitado, evitando rejeições de provedores, deixando inalteradas as rotas sem reflexão.
  • Atalhos e atribuição da barra lateral de tarefas. Ctrl-K permanece paleta/emacs-kill, enquanto Ctrl-X tem como escopo o cancelamento do shell em segundo plano da barra lateral de tarefas. Concha empregos lançados por subagentes agora são renderizados com seu proprietário agente-criança no Barra lateral e transcrição de tarefas.
  • Recuperação de referência e economia de contexto. Pesquisa repetida somente leitura blocos de loop agora retornam orientação em vez de falhas fatais de ferramentas, compilação Python falhas que estão faltando setuptools incluem uma dica de instalação/nova tentativa, longa os tempos limite do shell em primeiro plano direcionam os modelos para a execução em segundo plano e As saídas shell/test/web são compactadas anteriormente para rotas de grande contexto.
  • Redação do display de configuração. codew config get/list agora mascara recursivamente chaves semelhantes a token, segredo, senha, credencial e autorização dentro tabelas extras desconhecidas e edita valores de cabeçalho HTTP confidenciais antes imprimindo saída de configuração.
  • Dicas de acompanhamento na fila e teclas de direção forçada. A visualização da entrada pendente agora anuncia Ctrl+S send now sempre que existem acompanhamentos na fila, e Ctrl/Cmd+Enter a direção forçada também aceita o terminal comum Ctrl+J codificação enquanto um turno está em execução.
  • Visibilidade padrão da barra lateral restaurada (#3328). Sessões novas e atualizadas agora use uma barra lateral composta fixada por padrão quando o terminal for largo suficiente, para que Agentes e Tarefas ativas apareçam sem optar por voltar ao modo inativo colapso automático. Arquivos de configurações mais antigos que capturaram o colapso automático do v0.8.62 padrão agora migre para pinned, a menos que /sidebar auto --save registre um aceitação explícita. /sidebar agora informa quando largura ou recolhimento automático suprime a renderização em vez de dizer que a barra lateral está visível. Relatado por @dxfq.
  • Manuseio de ambiente de proxy de execução JavaScript (#3273, #3331). js_execution agora ativa o modo proxy de ambiente do Node quando variáveis de proxy estão presentes, espelha variáveis de proxy em letras minúsculas para o processo filho e preenche HTTP_PROXY / HTTPS_PROXY de ALL_PROXY. Relatado por @lordwedggie e colhido de #3331 por @cyq1017.
  • Proteção de autenticação sem loopback do servidor de aplicativos legado (#3258). Nu codewhale app-server --host 0.0.0.0 agora falha rapidamente, a menos que seja explícito É fornecido --auth-token ou CODEWHALE_APP_SERVER_TOKEN, mantendo gerado apenas loopback de tokens cwapp_* únicos.
  • Migração do caminho de gravação do estado .deepseek legado (#3240). Subdiretórios de estado (sessions, slop_ledger, trophies, catalog) agora são sempre escritos sob ~/.codewhale/, e a primeira gravação de um subdiretório realoca qualquer pré-existente Conteúdo do ~/.deepseek/<sub> no local primário para que a árvore herdada pare crescendo enquanto os dados antigos são preservados. O resolvedor de leitura ainda encontra dados legados para preenchimento até que cada subdiretório migre. Relatado por @Final527; integração fatia marcadora de #3302 por @nightt5879.
  • Validação de subdiretório de estado no Windows (#3240). Proteção de caminho de estado agora rejeita strings de subdiretórios com raiz/prefixadas, como /etc antes de resolver ou migrando diretórios de estado, mantendo o resolvedor de gravação .codewhale dentro sua raiz de estado em todas as plataformas. Os créditos do contribuidor para este lançamento estão na entrada changelog acima - obrigado a todos cujos relatórios, relações públicas, análises e reproduções o moldaram. Consulte CHANGELOG.md para notas completas e docs/CHANGELOG_ARCHIVE.md para versões mais antigas.

Codewhale v0.8.63

Highlights

  • Rebrand and dual-binary install — deepseek-tui is deprecated and no longer published; anyone on legacy v0.8.x deepseek/deepseek-tui names must migrate via docs/REBRAND.md. Every install path now ships two cooperating binaries — the codewhale dispatcher and the codewhale-tui runtime — so Cargo users must install both crates (codewhale-cli + codewhale-tui) or hit MISSING_COMPANION_BINARY at runtime. Watch out for the unsigned NSIS installer on Windows, which will trigger SmartScreen until signing is wired up.

  • Bounded, tunable sub-agent fanout — #3318/#3319 replace the hard instantaneous concurrency cap with a queue-and-drain admission model ([subagents] max_admitted) and stop counting distinct agent calls against the per-turn loop guard, so high-fanout workflows can finally launch instead of being silently throttled. Cost control comes from two deliberately non-overlapping ceilings: a scope-wide [subagents] token_budget for a root run and its descendants (#3319), and a per-worker token_budget/max_tokens that ends a single child cleanly with budget_exhausted rather than grinding to max_steps (#3321).

  • Provider-scoped sub-agent policy and control — [subagents.providers.<provider>] profiles override concurrency, depth, timeouts, and token budgets per provider, so you can run loose settings for direct-API routes like deepseek and tighter caps for subscriptions like glm; /config subagents status now shows both resolved globals and the active-provider values — check this when a fanout behaves differently than expected. The agent tool also gains status/peek/cancel actions and worktree: true, which spins up an isolated branch/worktree for parallel edit lanes instead of making you hand-roll cwd.

  • Auth and config-redaction behavior changes — #3258 makes codewhale app-server --host 0.0.0.0 fail fast unless you pass --auth-token or CODEWHALE_APP_SERVER_TOKEN; generated cwapp_* tokens stay loopback-only, so any non-loopback deployment must now supply explicit auth or it won't start. Separately, codew config get/list recursively masks token/secret/password/credential/authorization keys inside extras tables and redacts sensitive HTTP headers — scripts that scrape config output for those values will now see redacted output.

  • State migration to ~/.codewhale — #3240 moves sessions, slop_ledger, trophies, and catalog writes under ~/.codewhale/ and relocates any pre-existing ~/.deepseek/<sub> data on first write, while reads still backfill from legacy paths; expect a one-time relocation and verify your data landed before deleting the old tree. Windows state-path validation now rejects rooted/prefixed subdir strings, so custom subdir names like /etc will be refused rather than silently resolved.

  • Provider and runtime robustness, plus UI behavior shifts — DeepSeek reasoning routes now omit tool_choice to avoid provider rejections, child agents retry transient header/SSE timeouts and parents synthesize missed completions so orchestration can't hang, and js_execution honors proxy env vars again (mirrors lowercase variants, backfills HTTP_PROXY/HTTPS_PROXY from ALL_PROXY, #3273/#3331). On the UI side, #3328 re-pins the composed sidebar on wide terminals and auto-migrates v0.8.62 auto-collapse settings to pinned, Ctrl-X is now scoped to Tasks-sidebar shell cancellation while Ctrl-K stays kill/palette, and Ctrl/Cmd+Enter force-steering now also accepts the Ctrl+J terminal encoding.

CodeWhale is the canonical project, command, npm package, and release-asset name. The legacy npm package deepseek-tui is deprecated and receives no further releases. Users coming from v0.8.x legacy deepseek / deepseek-tui names should migrate with docs/REBRAND.md.

Recommended — npm (one command, both binaries)

The wrapper downloads both binaries from this Release and places them in the same directory.

  -e DEEPSEEK_API_KEY="$DEEPSEEK_API_KEY" \

The image ships the codewhale dispatcher and codewhale-tui runtime. The latest tag is also updated on release.

Both crates are required — codewhale-cli produces the codewhale dispatcher and codewhale-tui produces the interactive runtime that the dispatcher delegates to. Installing only one binary will fail at runtime with a MISSING_COMPANION_BINARY error.

What's in v0.8.63

Added

  • Sub-agent fanout safeguards (#3318, #3319). High-fanout Workflow runs can now queue and drain more agents than the instantaneous concurrency cap by default, with [subagents] max_admitted available to tune that bounded admission population. Distinct agent calls are no longer capped by the per-turn loop guard before runtime launch concurrency and provider rate-limit backoff can apply. [subagents] token_budget applies a shared aggregate token ceiling to a root agent run and its descendants.
  • Per-worker sub-agent token enforcement (#3321). A token_budget / max_tokens set on an individual agent call now bounds that single worker mid-run: once its accumulated model tokens exceed the cap it stops cleanly with a budget_exhausted status instead of running to max_steps. This complements the scope-level admission gate (#3319) — the per-worker cap stops one runaway worker, the scope cap bounds total fan-out — without double-counting. Harvested from #3321 by @donglovejava.
  • Provider-specific sub-agent fanout config. [subagents.providers.<provider>] profiles now override enabled, max_concurrent, max_admitted, launch_concurrency, max_depth, token budget, API timeout, and heartbeat timeout for the active provider. Use broad direct-API profiles such as [subagents.providers.deepseek] and tighter subscription profiles such as [subagents.providers.glm]; /config subagents status shows both global and active-provider resolved values.
  • Sub-agent control and isolation. The single agent tool now exposes status, peek, and cancel actions for running children, and accepts worktree: true to create an isolated git worktree/branch for parallel edit lanes instead of requiring callers to hand-roll a cwd.

Fixed

  • Mode and tool catalog correctness. Core action tools remain discoverable in the model-facing catalog/tool search, and a consistency self-check flags registered handlers that drift out of the advertised catalog. Review-looking prompts in explicit Agent/YOLO mode now keep the requested mode and tools, with only an advisory review hint.
  • Sub-agent orchestration recovery. Child agents now retry transient provider header/SSE timeouts before failing, and parent runs synthesize missed child completions from terminal child state so orchestration cannot hang on a lost completion event.
  • DeepSeek thinking tool calls. DeepSeek chat-completions requests now omit explicit tool_choice whenever reasoning/thinking is enabled, avoiding provider rejections while leaving no-thinking routes unchanged.
  • Task sidebar shortcuts and attribution. Ctrl-K stays palette/emacs-kill, while Ctrl-X is scoped to Tasks-sidebar background shell cancellation. Shell jobs launched by sub-agents now render with their child-agent owner in the Tasks sidebar and transcript.
  • Benchmark-turn recovery and context economy. Repeated read-only search loop blocks now return guidance instead of fatal tool failures, Python build failures that are missing setuptools include an install/retry hint, long foreground shell timeouts steer models toward background execution, and noisy shell/test/web outputs are compacted earlier for large-context routes.
  • Config display redaction. codew config get/list now recursively masks token-, secret-, password-, credential-, and authorization-like keys inside unknown extras tables and redacts sensitive HTTP header values before printing config output.
  • Queued follow-up hints and force-steer keys. The pending-input preview now advertises Ctrl+S send now whenever queued follow-ups exist, and Ctrl/Cmd+Enter force-steering also accepts the common Ctrl+J terminal encoding while a turn is running.
  • Sidebar default visibility restored (#3328). New and upgraded sessions now use a pinned composed sidebar by default when the terminal is wide enough, so live Agents and Tasks surface without opting back into idle auto-collapse. Older settings files that captured the v0.8.62 auto-collapse default now migrate to pinned unless /sidebar auto --save records an explicit opt-in. /sidebar now reports when width or auto-collapse suppresses rendering instead of saying the sidebar is visible. Reported by @dxfq.
  • JavaScript execution proxy env handling (#3273, #3331). js_execution now enables Node's environment-proxy mode when proxy variables are present, mirrors lowercase proxy variables for the child process, and backfills HTTP_PROXY / HTTPS_PROXY from ALL_PROXY. Reported by @lordwedggie and harvested from #3331 by @cyq1017.
  • Legacy app-server non-loopback auth hardening (#3258). Bare codewhale app-server --host 0.0.0.0 now fails fast unless an explicit --auth-token or CODEWHALE_APP_SERVER_TOKEN is supplied, keeping generated one-time cwapp_* tokens loopback-only.
  • Legacy .deepseek state write-path migration (#3240). State subdirectories (sessions, slop_ledger, trophies, catalog) are now always written under ~/.codewhale/, and the first write of a subdir relocates any pre-existing ~/.deepseek/<sub> contents into the primary location so the legacy tree stops growing while old data is preserved. The read resolver still finds legacy data for backfill until each subdir migrates. Reported by @Final527; onboarding marker slice from #3302 by @nightt5879.
  • State subdir validation on Windows (#3240). State path hardening now rejects rooted/prefixed subdir strings such as /etc before resolving or migrating state directories, keeping the .codewhale write resolver inside its state root across platforms.
