#claude-mem v15.21.0

Claude-mem não desativa mais o modo de código de Claude Code

  • Modo de código começa com claude-mem habilitado (#6278, obrigado @naive000; relatado em #6209 por @nasif-naseef). O Modo de Código (experimental, Claude Code 2.1.323 e posterior) se recusa a iniciar quando o módulo hooks de um plug-in conecta tool.call. o mod de limpeza automática de claude-mem funcionou, então o Modo Código estava desativado para todos com claude-mem ativado, mesmo com a limpeza automática desativada. O mod agora lê os resultados da ferramenta por meio de session.append. A limpeza automática ainda funciona em todas as versões do Claude Code que executam mods (2.1.287 e posteriores).

A limpeza automática continua de onde parou

A limpeza automática ainda estará desativada, a menos que você defina CLAUDE_MEM_AUTO_CLEAR_ENABLED como true. Quando está ligado:

  • Ele continua com um prompt de continuação em vez da palavra simples "continuar" (#6294). Antes de limpar, Claude salva seu estado de trabalho uma última vez, nomeando a lista a partir da qual está trabalhando, a tarefa que acabou de concluir e o objetivo geral. Após /clear, a limpeza automática envia: You are working on "<list>" and recently completed "<task>". Pick back up on our overarching goal "<goal>" from where you left off. Se esse salvamento deixou algum dos três de fora, ele envia "continuar" como antes e registra o motivo.
  • Começa em 40% da janela de contexto em vez de 33% (#6294). Um CLAUDE_MEM_AUTO_CLEAR_PERCENT que você configura em settings.json ou o ambiente ainda ganha.

Novas maneiras de se conectar

  • Hermes Desktop, pesquise e salve no MCP (#6284, obrigado @krishnadobhal; parte de #5940). claude-mem hermes install --mcp-only --project-cwd <absolute-directory> adiciona claude-mem como um servidor MCP para Hermes One e Hermes Desktop sem torná-lo o provedor de memória. Você pesquisa e salva quando solicita; nada é capturado ou injetado por conta própria. claude-mem hermes uninstall remove apenas o que escreveu e restaura config.yaml byte por byte.
  • GitHub Copilot no VS Code (#6286, obrigado @krishnadobhal; parte de #5895). npx claude-mem install --ide copilot-vscode grava a entrada MCP que o agente Copilot do VS Code lê (~/.copilot/mcp-config.json, o mesmo arquivo que o Copilot CLI usa). A entrada agora inclui "tools": ["*"]. Sem ele, o VS Code conectou-se ao claude-mem, mas nunca ofereceu suas ferramentas ao modelo. Ainda não há captura automática.
  • Predefinição ModelGo (#6277, obrigado @lichloe1116-gif da equipe ModelGo). O provedor compatível com OpenAI possui uma predefinição modelgo para https://api.modelgo.ai/v1. Ele não define nenhum modelo padrão, então escolha um que sua chave possa usar.

Também novo

  • Verificações de gravação do estado de trabalho (#6217, obrigado @vieGPT). Você pode fazer com que o work_state_write execute um comando de verificação local antes de gravar nas listas que você escolher, definidas em ~/.claude-mem/work-state-write-guard.json. Uma gravação recusada retorna HTTP 409 e nada é salvo. Sem arquivo, nada muda.
  • CLAUDE_MEM_API_AGENT_EXTRA_BODY (#6225, obrigado @Moep90; #6223). Um objeto JSON adicionado a cada solicitação enviada pelo agente api (a atualização Meu Trabalho e o agente corpus com api). Para um modelo Qwen em vLLM, {"chat_template_kwargs":{"enable_thinking":false}} desativa o raciocínio. Campos como model, messages e max_tokens são descartados com um aviso e nunca são enviados ao gateway cmem.ai.

Atualização do meu trabalho

  • Respostas lentas do seu próprio modelo não falham mais em cerca de 5 minutos (#6224, obrigado @Moep90; #6222). A busca de Bun desistiu de uma conexão que ficou silenciosa por 5 minutos, antes que o limite de solicitação de 10 minutos do agente api fosse aplicado. Agora esse limite é o único.
  • Endpoints que desejam que o max_completion_tokens funcione (#6242). Quando um endpoint recusa max_tokens, o agente api envia a solicitação mais uma vez com max_completion_tokens, em vez de falhar todas as chamadas com HTTP 400.
  • Uma atualização não para mais em uma resposta que foi recusada duas vezes (#6212, obrigado @Moep90). Na primeira tentativa de agrupamento, foco ou revisão, as partes que falham nas verificações são descartadas e o restante é salvo. Antes, o mesmo lote falhava em todas as execuções.
  • A história da construção está escrita em partes (#6279, obrigado @0xABCD01; relatado em #6226 por @Moep90). A etapa da história enviou todas as avaliações alteradas em uma pergunta. Essa questão ultrapassou a janela de contexto do modelo e todas as atualizações posteriores falharam. Agora envia peças que se enquadram no mesmo orçamento de perguntas que as outras etapas utilizam.
  • Conversas longas são agrupadas pelas solicitações mais recentes, não pelas dez primeiras (#6243, obrigado @Afloat16).
  • Os commits feitos com git commit --message ou --message= são reconhecidos (#6236, obrigado @Afloat16).
  • Um commit obtém um link GitHub somente quando a evidência nomeia um repositório (#6237, obrigado @Afloat16).
  • Enquanto My Rules espera por um agente, ele vincula as instruções para configurar uma atualização do API (#6214, obrigado @liuyinchu).

Configuração, importação e exportação

  • A configuração termina quando o histórico de prompts é grande (#6280, obrigado @0xABCD01; #6266; relatado em #6227 por @deserteaglemj). A configuração parou em 99% em "Encontrar seu trabalho recente" quando os prompts recentes ultrapassaram o limite de upload hospedado de 2 MiB e todas as tentativas falharam da mesma maneira. Agora ele conclui a configuração da sua máquina e diz isso. A etapa de consentimento também mostra "Demais para um upload. Desmarque uma ferramenta ou pule a verificação". e desliga o botão de upload até que a seleção caiba.
  • Importação de grandes exportações (#6261, obrigado @Afloat16). Um arquivo acima do limite de solicitação de 5 MiB do trabalhador foi recusado (HTTP 413) antes que qualquer coisa fosse salva. Arquivos grandes agora são enviados em partes, primeiro as sessões, com seu conteúdo completo.
  • As observações importadas são encontradas por desduplicação da mesma forma que as ao vivo, quando CLAUDE_MEM_DEDUP_ENABLED está ativado (#6263, obrigado @Afloat16).
  • claude-mem import --dry-run não para mais em uma configuração de trabalhador ruim, já que uma visualização nunca chama o trabalhador (#6215, obrigado @liuyinchu).
  • Conversas Codex Desktop importadas de outro agente não são mais contadas como prompts digitados no Codex (#6219, obrigado @rigel905; #6218).
  • Exportando para /dev/stdout, /dev/stderr, um link simbólico para qualquer um deles, ou um FIFO grava JSON limpo lá, e as linhas de progresso e avisos vão para o outro fluxo (#6288, de #6258 por @Afloat16).

Correções

  • Windows: Claude Code carrega RULES-AND-TOOLS.md novamente (#6234, obrigado @QuantScorpus). claude-mem escreveu suas linhas de importação @ com barras invertidas. Claude Code os ignora sem dizer uma palavra, e Claude-mem também omite a outra cópia das instruções, de modo que nenhum dos dois chegou ao modelo. As linhas agora usam barras. Uma importação @ mostrada dentro de um exemplo de código protegido não conta mais como a importação real (#6293, de #6241 por @Afloat16).
  • claude-mem start executa o trabalhador instalado (# 6235, obrigado @ZedingZhang; relatado em # 6228 por @ExactDoug), não a cópia para a qual um alias de shell antigo aponta, que pode estar faltando suas dependências.
  • Os backups mantêm o novo instantâneo após o relógio ser atrasado (#6273, obrigado @Afloat16). Antes, a limpeza podia excluir o instantâneo que acabara de ser relatado como salvo.
  • teambrain join ativa a nova conexão de sincronização mesmo quando a etapa de compartilhamento opcional falha (#6275, obrigado @Afloat16).
  • Resumos sem progresso não são armazenados (#6202, obrigado @ShitK). Um resumo apenas com título ou planos futuros costumava ser salvo e anunciado como um sucesso.
  • As mensagens automáticas do Claude Code não dividem mais uma solicitação (#6251, obrigado @Afloat16). As varreduras de orientador e de entrega trataram-nas como novas solicitações e perderam orientações e gravações de arquivos anteriores do mesmo turno.
  • Corpus constrói mais de 250.000 trabalhos de observação (#6271, obrigado @Afloat16). Eles falharam com too many SQL variables.
  • Codex: um plugin desativado com uma tecla TOML pontilhada permanece desativado (#6239, obrigado @Afloat16), por exemplo plugins."claude-mem@claude-mem-local".enabled = false.
  • O frontmatter da habilidade de pesquisa de mem é válido YAML (#6276, obrigado @Afloat16; relatado em #6267 por @orbiutyt).
  • Aider: o instalador edita o arquivo de configuração que o Aider realmente usa (primeiro o diretório de trabalho, depois o git root e depois o home) (#6289, de #6230 por @Afloat16) e mantém os caminhos de arquivo citados intactos nas listas read: (#6290, de #6231 por @Afloat16).
  • Arquivos de contexto Cursor e Grok mantêm o contexto mais recente quando duas atualizações se sobrepõem (#6291, de #6232 por @Afloat16).
  • Servidor auto-hospedado: um trabalho com chave revogada ou violação de escopo é executado uma vez em vez de três vezes (#6252) e claude-mem server jobs retry republica com novas tentativas e espera da fila (#6253), obrigado @HEOJUNFO. O provedor OpenRouter lê no máximo 64 KiB quando verifica uma resposta para um erro de campo de token (#6238, obrigado @Afloat16). Um evento de agente ilegível não interrompe mais todas as leituras dessa tabela (#6199, obrigado @DeryFerd).

Segurança

  • shell-quote 1.11.0 (#6205, obrigado @manippoudel; relatado em #6200 por @lucasbritolubro). A versão 1.9.0 está na faixa CVE-2026-102422 (crítica). Nenhum caminho de código em claude-mem atingiu o código afetado; isso tira tudo do que é enviado.
  • adm-zip 0.6.1 e zod 4.6.7 no tempo de execução do plugin, fora de seus avisos altos (#6220, obrigado @LeviReisJs; relatado em #6211 por @noumanbhatti).
  • A chave Gemini API vai em um cabeçalho, não no URL de solicitação (#6196, obrigado @DeryFerd), então proxies e logs de acesso não a registram.
  • Arquivos temporários recebem um nome aleatório e são criados exclusivamente nos sites de gravação atômica restantes (#6198, #6193, obrigado @DeryFerd), portanto, um link simbólico plantado não pode redirecionar uma gravação de configurações ou arquivos de estado.
  • O /v1/info não autenticado do servidor auto-hospedado mostra apenas o estado (# 6195, obrigado @DeryFerd): sem modo de autenticação, versão do esquema, host Redis ou texto de erro do driver.
  • CI: a verificação da lista de permissões pós-instalação inspeciona todas as dependências diretas do plugin (#6197), e a verificação do ambiente de spawn lê blocos env declarados acima de um spawn e verifica o tempo de execução do plugin (#6194), obrigado @DeryFerd.

Para contribuidores

  • TypeScript 7.0.2 (#6207, obrigado @krishnadobhal; #6188). Os scripts e testes que utilizam o compilador API mantêm TypeScript 6 através de um alias.
  • O import smoke test fecha seus leitores SQLite antes da varredura final (#6216, obrigado @liuyinchu).

claude-mem v15.21.0

claude-mem no longer turns off Claude Code's Code Mode

  • Code Mode starts with claude-mem enabled (#6278, thanks @naive000; reported in #6209 by @nasif-naseef). Code Mode (experimental, Claude Code 2.1.323 and later) refuses to start when a plugin's hooks module hooks tool.call. claude-mem's auto-clear mod did, so Code Mode was off for everyone with claude-mem enabled, even with auto-clear off. The mod now reads tool results through session.append instead. Auto-clear still works on every Claude Code version that runs mods (2.1.287 and later).

Auto-clear picks up where it left off

Auto-clear is still off unless you set CLAUDE_MEM_AUTO_CLEAR_ENABLED to true. When it is on:

  • It resumes with a continuation prompt instead of the bare word "continue" (#6294). Before clearing, Claude saves its work state one last time, naming the list it is working from, the task it just finished and the overall goal. After /clear, auto-clear sends: You are working on "<list>" and recently completed "<task>". Pick back up on our overarching goal "<goal>" from where you left off. If that save left any of the three out, it sends "continue" as before and logs why.
  • It starts at 40% of the context window instead of 33% (#6294). A CLAUDE_MEM_AUTO_CLEAR_PERCENT you set in settings.json or the environment still wins.

New ways to connect

  • Hermes Desktop, search and save over MCP (#6284, thanks @krishnadobhal; part of #5940). claude-mem hermes install --mcp-only --project-cwd <absolute-directory> adds claude-mem as an MCP server for Hermes One and Hermes Desktop without making it the memory provider. You get search and save when you ask for them; nothing is captured or injected on its own. claude-mem hermes uninstall removes only what it wrote and restores config.yaml byte for byte.
  • GitHub Copilot in VS Code (#6286, thanks @krishnadobhal; part of #5895). npx claude-mem install --ide copilot-vscode writes the MCP entry that VS Code's Copilot agent reads (~/.copilot/mcp-config.json, the same file Copilot CLI uses). The entry now includes "tools": ["*"]. Without it, VS Code connected to claude-mem but never offered its tools to the model. No automatic capture yet.
  • ModelGo preset (#6277, thanks @lichloe1116-gif of the ModelGo team). The OpenAI-compatible provider has a modelgo preset for https://api.modelgo.ai/v1. It sets no default model, so pick one your key can use.

Also new

  • Work-state write checks (#6217, thanks @vieGPT). You can make work_state_write run a local check command before it writes to lists you choose, set in ~/.claude-mem/work-state-write-guard.json. A refused write returns HTTP 409 and nothing is saved. With no file, nothing changes.
  • CLAUDE_MEM_API_AGENT_EXTRA_BODY (#6225, thanks @Moep90; #6223). A JSON object added to every request the api agent sends (the My Work refresh and the corpus agent with api). For a Qwen model on vLLM, {"chat_template_kwargs":{"enable_thinking":false}} turns reasoning off. Fields such as model, messages and max_tokens are dropped with a warning, and it is never sent to the cmem.ai gateway.

My Work refresh

  • Slow answers from your own model no longer fail at about 5 minutes (#6224, thanks @Moep90; #6222). Bun's fetch gave up on a connection that had been quiet for 5 minutes, before the api agent's 10-minute request limit applied. Now that limit is the only one.
  • Endpoints that want max_completion_tokens work (#6242). When an endpoint refuses max_tokens, the api agent sends the request once more with max_completion_tokens, instead of failing every call with HTTP 400.
  • A refresh no longer stalls on an answer that was refused twice (#6212, thanks @Moep90). On the one retry for grouping, focus or review, the parts that fail the checks are dropped and the rest is saved. Before, the same batch failed on every run.
  • The build story is written in parts (#6279, thanks @0xABCD01; reported in #6226 by @Moep90). The story step sent every changed review in one question. That question grew past the model's context window, and every refresh after that failed. It now sends parts that fit the same question budget the other steps use.
  • Long conversations are grouped by their latest requests, not their first ten (#6243, thanks @Afloat16).
  • Commits made with git commit --message or --message= are recognized (#6236, thanks @Afloat16).
  • A commit gets a GitHub link only when the evidence names one repository (#6237, thanks @Afloat16).
  • While My Rules waits for an agent, it links the instructions for setting up an API refresh (#6214, thanks @liuyinchu).

Setup, import and export

  • Setup finishes when your prompt history is large (#6280, thanks @0xABCD01; #6266; reported in #6227 by @deserteaglemj). Setup stopped at 99% on "Finding your recent work" when the recent prompts were over the 2 MiB hosted upload limit, and every retry failed the same way. It now finishes setup on your machine and says so. The consent step also shows "Too much for one upload. Untick a tool or skip the scan." and turns off the upload button until the selection fits.
  • Large exports import (#6261, thanks @Afloat16). A file over the worker's 5 MiB request limit was refused (HTTP 413) before anything was saved. Large files are now sent in parts, sessions first, with their full content.
  • Imported observations are found by deduplication the same way live ones are, when CLAUDE_MEM_DEDUP_ENABLED is on (#6263, thanks @Afloat16).
  • claude-mem import --dry-run no longer stops on a bad worker setting, since a preview never calls the worker (#6215, thanks @liuyinchu).
  • Conversations Codex Desktop imported from another agent are no longer counted as prompts typed in Codex (#6219, thanks @rigel905; #6218).
  • Exporting to /dev/stdout, /dev/stderr, a symlink to either, or a FIFO writes clean JSON there, and progress lines and warnings go to the other stream (#6288, from #6258 by @Afloat16).

Fixes

  • Windows: Claude Code loads RULES-AND-TOOLS.md again (#6234, thanks @QuantScorpus). claude-mem wrote its @ import lines with backslashes. Claude Code skips those without a word, and claude-mem then also left out its other copy of the instructions, so neither reached the model. The lines now use forward slashes. An @ import shown inside a fenced code example no longer counts as the real one (#6293, from #6241 by @Afloat16).
  • claude-mem start runs the installed worker (#6235, thanks @ZedingZhang; reported in #6228 by @ExactDoug), not the copy an old shell alias points at, which can be missing its dependencies.
  • Backups keep the new snapshot after the clock is set back (#6273, thanks @Afloat16). Before, cleanup could delete the snapshot it had just reported as saved.
  • teambrain join turns on the new sync connection even when the optional sharing step fails (#6275, thanks @Afloat16).
  • Summaries with no progress in them are not stored (#6202, thanks @ShitK). A summary with only a title or future plans used to be saved and announced as a success.
  • Claude Code's automatic messages no longer split a request (#6251, thanks @Afloat16). The advisor and deliverable scans treated them as new requests and lost earlier advice and file writes from the same turn.
  • Corpus builds over 250,000 observations work (#6271, thanks @Afloat16). They failed with too many SQL variables.
  • Codex: a plugin turned off with a dotted TOML key stays off (#6239, thanks @Afloat16), for example plugins."claude-mem@claude-mem-local".enabled = false.
  • The mem-search skill's frontmatter is valid YAML (#6276, thanks @Afloat16; reported in #6267 by @orbiutyt).
  • Aider: the installer edits the config file Aider actually uses (working directory first, then git root, then home) (#6289, from #6230 by @Afloat16), and keeps quoted file paths intact in read: lists (#6290, from #6231 by @Afloat16).
  • Cursor and Grok context files keep the newer context when two refreshes overlap (#6291, from #6232 by @Afloat16).
  • Self-hosted server: a job with a revoked key or a scope violation runs once instead of three times (#6252), and claude-mem server jobs retry republishes with the queue's retries and backoff (#6253), thanks @HEOJUNFO. The OpenRouter provider reads at most 64 KiB when it checks an answer for a token-field error (#6238, thanks @Afloat16). One unreadable agent event no longer breaks every read of that table (#6199, thanks @DeryFerd).

Security

  • shell-quote 1.11.0 (#6205, thanks @manippoudel; reported in #6200 by @lucasbritolubro). Version 1.9.0 is in the range of CVE-2026-102422 (critical). No code path in claude-mem reached the affected code; this takes it out of what ships.
  • adm-zip 0.6.1 and zod 4.6.7 in the plugin runtime, out of their High advisories (#6220, thanks @LeviReisJs; reported in #6211 by @noumanbhatti).
  • The Gemini API key goes in a header, not the request URL (#6196, thanks @DeryFerd), so proxies and access logs don't record it.
  • Temp files get a random name and are created exclusively at the remaining atomic-write sites (#6198, #6193, thanks @DeryFerd), so a planted symlink can't redirect a write of settings or state files.
  • The self-hosted server's unauthenticated /v1/info shows state only (#6195, thanks @DeryFerd): no auth mode, schema version, Redis host or driver error text.
  • CI: the postinstall allowlist check inspects every direct plugin dependency (#6197), and the spawn environment check reads env blocks declared above a spawn and scans the plugin runtime (#6194), thanks @DeryFerd.

For contributors

  • TypeScript 7.0.2 (#6207, thanks @krishnadobhal; #6188). The scripts and tests that use the compiler API keep TypeScript 6 through an alias.
  • The import smoke test closes its SQLite readers before the final scan (#6216, thanks @liuyinchu).
