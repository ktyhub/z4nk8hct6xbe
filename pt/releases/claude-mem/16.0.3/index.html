#claude-mem v16.0.3

Correção crítica

  • O gancho OMP funciona com o tempo de execução do servidor (#6367, obrigado @flipcyde101, fecha #6366 relatado por @walynde). Quando CLAUDE_MEM_RUNTIME era server ou server-beta, o gancho OMP ainda enviava tudo para o trabalhador local, portanto as sessões OMP eram descartadas. O gancho agora lê CLAUDE_MEM_SERVER_URL, CLAUDE_MEM_SERVER_API_KEY e CLAUDE_MEM_SERVER_PROJECT_ID (ou os nomes CLAUDE_MEM_SERVER_BETA_*; variáveis ​​de ambiente vencem settings.json) e se comunica diretamente com o /v1 API do servidor: início da sessão, eventos de ferramenta e resposta, contexto e fim da sessão. Ele aplica as mesmas regras que o trabalhador aplica antes de salvar qualquer coisa: os blocos <private> são removidos, os projetos excluídos e CLAUDE_MEM_SKIP_TOOLS são respeitados, cada prompt é registrado e o nome do projeto vem do git. Se as configurações do servidor estiverem incompletas, ele retornará ao trabalhador como antes.
  • Usuários do OMP: executem npx claude-mem install --ide omp uma vez para obter essa correção. O gancho do OMP é um arquivo copiado, portanto, uma atualização do plugin por si só não o substitui.

Correções

  • Consultas de conhecimento e solicitações de corpus não podem mais ficar suspensas para sempre (#6368, obrigado @flipcyde101, fechamento #6364 relatado por @soarkit). Um fluxo paralisado do Agente SDK usado para manter a solicitação e seu filho Claude CLI vivos sem fim. Uma consulta de conhecimento ou prime agora para após 10 minutos e uma solicitação de corpus após 15, com um erro 504. O corpus permanece bloqueado até que o tempo limite do trabalho seja realmente interrompido, portanto, ele não pode gravar após uma exclusão ou reconstrução.
  • O aviso "pausado para salvar memórias" desaparece assim que o Codex está salvando (#6374, obrigado @ryrenz, fecha #6372 relatado por @raw34). Depois que você trocou CLAUDE_MEM_PROVIDER para codex após uma pausa na cota de Claude, cada nova sessão ainda informava que a captura estava pausada até que o antigo tempo de espera de Claude acabasse. O aviso agora é recalculado quando o Codex armazena uma memória.
  • server api-key create --scope sem valor é recusado (#6375, obrigado @ryrenz, fecha #6373 relatado por @soarkit). Ele costumava criar uma chave com escopo definido para a string literal true, que cada solicitação rejeitava. Um --scope, --name, --team ou --project simples agora imprime --<flag> requires a value e sai de 1 sem escrever nada, tanto em create quanto em migrate-scopes.
  • O Relatório de custos do agente não trava mais em observações sem modelo (#6376, obrigado @ZedingZhang, fecha #6371 relatado por @Realauster). acr.py rollup levantou um TypeError quando uma janela tinha um modelo ausente e um modelo nomeado e sem preço.
  • A imagem do servidor Docker é construída novamente (#6386, fecha #6379 relatado por @InfoALR). Ele agora usa node:20-trixie, porque o tree-sitter 0.26 precisa de um glibc mais novo do que os navios node:20.
  • A atualização do meu trabalho é executada em OpenCode 2.x (#6361, refs #6339 relatado por @Realauster). OpenCode 2.x rejeita os sinalizadores --pure e --dir, portanto, cada etapa de atualização saiu de 1. A etapa agora verifica opencode --version e usa o isolamento próprio de cada versão. 2.0.0 a 2.2.2 e 3.x são recusados ​​por um motivo, porque não conseguem manter os plugins fora. Em todas as versões o agente de atualização agora tem todas as ferramentas negadas.
  • OMP e Hermes leem uma porta de trabalho salva como um número (#6363, obrigado @chuenchen309). {"CLAUDE_MEM_WORKER_PORT": 45678} em settings.json costumava ser ignorado, então suas solicitações iam para a porta padrão.
  • O instalador do OpenClaw não exclui mais uma pasta que não instalou (#6381, obrigado @DeryFerd). Ele executou o rm -rf em qualquer caminho de instalação nomeado pelo ~/.openclaw/openclaw.json. Agora ele substitui uma pasta somente quando ela está ausente, vazia ou contém o manifesto OpenClaw do próprio claude-mem. Qualquer outra coisa é deixada com um aviso e a pasta de extensões padrão é usada; se isso também for feito por outra coisa, o instalador para.
  • O trabalhador pode parar cada criança de Claude que iniciar (#6385, obrigado @DeryFerd). A compactação de campo e o encerramento do Telegram iniciaram o processo Claude fora da lista de processos do trabalhador, portanto, um trabalhador que saiu com força os deixou em execução. Eles agora estão nessa lista e não ocupam espaço de simultaneidade.
  • Uma impressão travada do CLI não pode aumentar a memória do trabalhador sem limite (#6384, obrigado @DeryFerd). A saída coletada de claude, codex, gemini e opencode é limitada a 128 Mi caracteres, cerca de 2.5 vezes o maior giro real medido. Após o limite, o início e o fim são mantidos, um aviso é registrado e a resposta é recusada em vez de lida como uma resposta parcial. As saídas menores permanecem inalteradas.
  • Um registro de transcrição sem fim não pode aumentar a memória do trabalhador sem limite (#6383, obrigado @DeryFerd). Um registro JSONL acima de 64 MiB (o maior registro real medido foi de 44 MiB) é ignorado, com um aviso que nomeia o arquivo, o deslocamento do registro e seu tamanho. As linhas depois dele são lidas normalmente.
  • O /v1/info não autenticado não mostra mais o texto de erro Redis (#6380, obrigado @DeryFerd). Uma faixa de fila que não pôde ser lida usada para publicar o erro do driver, como um host e uma porta. O motivo agora permanece no log do servidor.

Novo

  • Capacidade de CPU opcional para chroma-mcp (#6369, obrigado @flipcyde101, parcialmente aborda #6365 relatado por @FengJie2004). Defina CLAUDE_MEM_CHROMA_MAX_THREADS como 2 se o chroma-mcp mantiver vários núcleos ocupados. Ele limita os threads do incorporador e, no Linux com taskset, as CPUs chroma-mcp podem usar. Está desativado por padrão (0), porque um limite sempre ativo atrasou o primeiro preenchimento. #6365 permanece aberto.
  • Predefinição AIGROW para o provedor compatível com OpenAI (#6370, obrigado @guglielmo-io).

Serviço de sincronização hospedado

  • Os serviços de sincronização comparam suas credenciais internas do projetor em tempo constante (#6382, obrigado @DeryFerd). Uma comparação simples de strings pode vazar o segredo compartilhado por meio do tempo de resposta. Isso altera o services/sync-api e o services/sync-hub, que não fazem parte do pacote npm: ele chega aos usuários apenas quando esses serviços são implantados, e não por meio desta versão.

Testes

  • Um teste de transcrição instável agora conta os puxões da enquete anexada em vez de acelerar a verificação do arquivo (#6360). changelog completo: https://github.com/thedotmack/claude-mem/compare/v16.0.2...v16.0.3

claude-mem v16.0.3

Critical fix

  • The OMP hook works with the server runtime (#6367, thanks @flipcyde101, closes #6366 reported by @walynde). When CLAUDE_MEM_RUNTIME was server or server-beta, the OMP hook still sent everything to the local worker, so OMP sessions were dropped. The hook now reads CLAUDE_MEM_SERVER_URL, CLAUDE_MEM_SERVER_API_KEY and CLAUDE_MEM_SERVER_PROJECT_ID (or the CLAUDE_MEM_SERVER_BETA_* names; environment variables win over settings.json) and talks to the server's /v1 API directly: session start, tool and reply events, context, and session end. It applies the same rules the worker applies before it saves anything: <private> blocks are stripped, excluded projects and CLAUDE_MEM_SKIP_TOOLS are honored, every prompt is recorded, and the project name comes from git. If the server settings are incomplete, it falls back to the worker as before.
  • OMP users: run npx claude-mem install --ide omp once to get this fix. The OMP hook is a copied file, so a plugin update alone does not replace it.

Fixes

  • Knowledge queries and corpus requests can no longer hang forever (#6368, thanks @flipcyde101, closes #6364 reported by @soarkit). A stalled Agent SDK stream used to keep the request and its Claude CLI child alive with no end. A knowledge query or prime now stops after 10 minutes and a corpus request after 15, with a 504 error. The corpus stays locked until the timed-out work has really stopped, so it cannot write after a delete or rebuild.
  • The "paused saving memories" notice goes away once Codex is saving (#6374, thanks @ryrenz, closes #6372 reported by @raw34). After you switched CLAUDE_MEM_PROVIDER to codex following a Claude quota pause, every new session still said capture was paused until the old Claude cooldown ran out. The notice is now recomputed when Codex stores a memory.
  • server api-key create --scope with no value is refused (#6375, thanks @ryrenz, closes #6373 reported by @soarkit). It used to create a key scoped to the literal string true, which every request then rejected. A bare --scope, --name, --team or --project now prints --<flag> requires a value and exits 1 without writing anything, on both create and migrate-scopes.
  • The Agent Cost Report no longer crashes on observations with no model (#6376, thanks @ZedingZhang, closes #6371 reported by @Realauster). acr.py rollup raised a TypeError when one window had both a missing model and a named, unpriced one.
  • The Docker server image builds again (#6386, closes #6379 reported by @InfoALR). It now uses node:20-trixie, because tree-sitter 0.26 needs a newer glibc than node:20 ships.
  • My Work refresh runs on OpenCode 2.x (#6361, refs #6339 reported by @Realauster). OpenCode 2.x rejects the --pure and --dir flags, so every refresh step exited 1. The step now checks opencode --version and uses each version's own isolation. 2.0.0 to 2.2.2 and 3.x are refused with a reason, because they cannot keep plugins out. On every version the refresh agent now has all tools denied.
  • OMP and Hermes read a worker port saved as a number (#6363, thanks @chuenchen309). {"CLAUDE_MEM_WORKER_PORT": 45678} in settings.json used to be ignored, so their requests went to the default port.
  • The OpenClaw installer no longer deletes a folder it did not install (#6381, thanks @DeryFerd). It ran rm -rf on whatever install path ~/.openclaw/openclaw.json named. It now replaces a folder only when it is missing, empty, or holds claude-mem's own OpenClaw manifest. Anything else is left alone with a warning and the default extensions folder is used; if that is also taken by something else, the installer stops.
  • The worker can stop every Claude child it starts (#6385, thanks @DeryFerd). Field compression and the Telegram wrap-up started their Claude process outside the worker's process list, so a worker that exited hard left them running. They are now on that list, and they do not take a concurrency slot.
  • A CLI stuck printing can't grow the worker's memory without limit (#6384, thanks @DeryFerd). Output collected from claude, codex, gemini and opencode is capped at 128 Mi characters, about 2.5 times the largest real turn measured. Past the cap, the start and end are kept, a warning is logged, and the reply is refused instead of read as a partial answer. Smaller outputs are unchanged.
  • A transcript record with no end can't grow the worker's memory without limit (#6383, thanks @DeryFerd). A JSONL record over 64 MiB (the largest real record measured was 44 MiB) is skipped, with a warning that names the file, the record's offset and its size. The lines after it are read as normal.
  • The unauthenticated /v1/info no longer shows Redis error text (#6380, thanks @DeryFerd). A queue lane that could not be read used to publish the driver's error, such as a host and port. The reason now stays in the server log.

New

  • Opt-in CPU cap for chroma-mcp (#6369, thanks @flipcyde101, partly addresses #6365 reported by @FengJie2004). Set CLAUDE_MEM_CHROMA_MAX_THREADS to 2 if chroma-mcp keeps several cores busy. It caps the embedder's threads and, on Linux with taskset, the CPUs chroma-mcp can use. It is off by default (0), because an always-on cap slowed the first backfill. #6365 stays open.
  • AIGROW preset for the OpenAI-compatible provider (#6370, thanks @guglielmo-io).

Hosted sync service

  • The sync services compare their internal projector credential in constant time (#6382, thanks @DeryFerd). A plain string compare could leak the shared secret through response timing. This changes services/sync-api and services/sync-hub, which are not part of the npm package: it reaches users only once those services are deployed, not through this release.

Tests

  • A flaky transcript test now counts the append poll's pokes instead of racing its file check (#6360).
