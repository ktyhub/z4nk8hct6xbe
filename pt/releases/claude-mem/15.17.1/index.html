#claude-mem v15.17.1

As sessões abertas continuam sendo capturadas após uma atualização

Desde 15.16.0, o trabalhador limpa versões antigas de plugins do cache de plugins do Claude Code cinco minutos após seu início e depois de hora em hora. Uma sessão do Claude Code que já estava aberta quando uma atualização chegou continua sendo executada na pasta da versão mais antiga. Depois que a varredura excluiu aquela pasta, Claude Code recusou-se a executar todos os ganchos claude-mem daquela sessão ("O diretório de plug-ins não existe"), então a sessão parou silenciosamente de salvar prompts, chamadas de ferramentas, observações e resumos.

A varredura agora lê os registros .in_use que Claude Code mantém para cada versão do plugin e mantém uma versão enquanto qualquer sessão carregada dele ainda está em execução. As pastas que não são utilizadas pela sessão em execução ainda serão removidas na próxima varredura, portanto, a limpeza do disco do 15.16.0 permanece. A varredura do trabalhador, npx claude-mem prune (e seu --dry-run) e o instalador seguem a mesma regra (#5971, obrigado @rigel905, correções #5970).

Correções

  • Contexto: uma seleção de projeto explicitamente vazia não mostra nada em vez de observações de cada projeto (#5866, obrigado @Afloat16).
  • Contexto: estimativas de custo de leitura e economia contam os fatos armazenados uma vez, em vez de contar caracteres de escape extras e um [] inventado para linhas sem fatos (#5980, obrigado @Afloat16).
  • Observador: uma resposta transmitida que chega como uma recusa conta como saída gerada, portanto, uma transmissão interrompida não é enviada novamente e cobrada duas vezes (#5843, obrigado @Afloat16).
  • Meu trabalho: o agente API rejeita uma resposta que o provedor cortou com content_filter, em vez de salvar um relatório incompleto (#5878, obrigado @Afloat16).
  • Sincronização: uma página extraída de registros sincronizados espera por outro gravador em vez de falhar imediatamente com "o banco de dados está bloqueado", portanto, uma primeira extração grande não demora mais minutos (#5996).
  • Meu Trabalho: o trabalhador lê o histórico compartilhado de Meu Trabalho uma vez por alteração, em vez de relê-lo inteiro em cada passagem de sincronização (#5986).
  • Visualizador de nuvem: um visualizador de nuvem de inicialização lenta recarrega sua página "inicial" até que o trabalhador responda, e uma guia Meu Trabalho na nuvem oculta fecha seu feed ao vivo até que seja mostrado novamente (#5988, #5953).

Integrações

Novos fluxos de trabalho de memória verificados para estruturas de agentes, cada um com escopo para um projeto: Vercel AI SDK (#5951), LangGraph (#5954), Pydantic AI (#5955), Microsoft Agent Framework (#6017), Haystack (#6018), LlamaIndex (#6019), Google ADK (#6020), CrewAI (#6021), Strands Agents (#6023), Agentes OpenAI SDK (#6024), Agno (#6025), SmolAgents (#6026), AG2 (#6027) e AutoGen (#6028). Obrigado @ Afloat16 por todos eles.

  • Visualizador de nuvem: base para rotear cada conta conectada ao seu próprio aplicativo; o comportamento da produção permanece inalterado (#5952).
  • modelo de véspera: o arquivo de bloqueio do modelo inclui claude-mem 15.17.0, portanto seu botão de implantação é instalado (#5968).

claude-mem v15.17.1

Open sessions keep capturing after an update

Since 15.16.0 the worker clears old plugin versions out of Claude Code's plugin cache five minutes after it starts and then hourly. A Claude Code session that was already open when an update arrived keeps running from the older version folder. Once the sweep deleted that folder, Claude Code refused to run every claude-mem hook for that session ("Plugin directory does not exist"), so the session silently stopped saving prompts, tool calls, observations and summaries.

The sweep now reads the .in_use records Claude Code keeps for each plugin version, and keeps a version while any session loaded from it is still running. Folders no running session uses are still removed on the next sweep, so the disk clean-up from 15.16.0 stays. The worker's sweep, npx claude-mem prune (and its --dry-run) and the installer all follow the same rule (#5971, thanks @rigel905, fixes #5970).

Fixes

  • Context: an explicitly empty project selection shows nothing instead of observations from every project (#5866, thanks @Afloat16).
  • Context: read-cost and savings estimates count stored facts once, instead of counting extra escape characters and an invented [] for rows without facts (#5980, thanks @Afloat16).
  • Observer: a streamed answer that arrives as a refusal counts as generated output, so an interrupted stream is not sent again and charged twice (#5843, thanks @Afloat16).
  • My Work: the API agent rejects an answer the provider cut with content_filter, instead of saving an incomplete report (#5878, thanks @Afloat16).
  • Sync: a pulled page of synced records waits for another writer instead of failing at once with "database is locked", so a large first pull no longer backs off for minutes (#5996).
  • My Work: the worker reads My Work's shared history once per change instead of re-reading all of it on every sync pass (#5986).
  • Cloud viewer: a slow-starting cloud viewer reloads its "starting" page until the worker answers, and a hidden cloud My Work tab closes its live feed until it is shown again (#5988, #5953).

Integrations

New verified memory workflows for agent frameworks, each scoped to one project: Vercel AI SDK (#5951), LangGraph (#5954), Pydantic AI (#5955), Microsoft Agent Framework (#6017), Haystack (#6018), LlamaIndex (#6019), Google ADK (#6020), CrewAI (#6021), Strands Agents (#6023), OpenAI Agents SDK (#6024), Agno (#6025), SmolAgents (#6026), AG2 (#6027) and AutoGen (#6028). Thanks @Afloat16 for all of them.

Also in this release

  • Cloud viewer: groundwork for routing each signed-in account to its own app; production behaviour is unchanged (#5952).
  • eve template: the template's lockfile includes claude-mem 15.17.0, so its deploy button installs (#5968).
