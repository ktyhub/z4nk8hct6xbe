#claude-mem v15.18.0

Agentes Eve obtêm a mesma memória que Claude Code e Codex

claude-mem/eve agora fornece a um agente eve o loop completo de memória claude-mem por meio de sua conta cmem.ai (#6042).

  • Contexto da sessão: cada turno começa com a linha do tempo recente da sua memória. Ele é atualizado a cada turno com um ID de mensagem, portanto, ele se substitui em vez de se acumular.
  • Recuperar cada turno: uma pesquisa antes do turno, como antes.
  • A gravação agora está ativada por padrão. Após cada curva concluída, o provedor envia o prompt, uma observação por chamada de ferramenta e um resumo da curva para cmem.ai como plataforma eve. Chamadas de ferramentas gravadas e resumos saem de sua permissão de observador cmem.ai, a mesma permissão que seus outros clients usam. Passe capture: false para manter o antigo comportamento somente leitura; contexto de sessão, recall, pesquisa e remember continuam funcionando.
    • As regiões <private>…</private> e o texto em forma de segredo são removidos na sua implantação antes que qualquer coisa seja enviada, com as mesmas regras que o plugin Cowork usa.
    • Replays do mesmo turno são descartados por cmem.ai (IDs de chamada de ferramenta com escopo de turno e uma chave de idempotência).
    • Cada solicitação é enviada uma vez. Sem novas tentativas, spool ou fila, portanto, uma interrupção nunca gera gastos posteriores. Uma falha é registrada com quantos eventos foram aceitos.
  • Ferramentas: search, timeline, get_observations (a pesquisa inteligente de três etapas) e remember.
  • versões véspera: testadas nas vésperas 0.84.0 e 1.0.0-rc.9.
  • Modelo: funciona em um Vercel AI Gateway de crédito gratuito (Claude, voltando para openai/gpt-5-mini quando Claude é recusado em créditos gratuitos) ou configura ANTHROPIC_API_KEY para ligar diretamente para Claude e EVE_MODEL para escolher um modelo exato. As execuções agendadas obtêm a memória do proprietário, o e-mail do proprietário deve corresponder exatamente e um exemplo de resumo matinal é enviado desativado.

Documentos: https://docs.claude-mem.ai/eve-integration

As opções de instalação passam para o navegador

Uma instalação padrão agora configura o tempo de execução no terminal e, em seguida, abre a configuração da web local para escolher agentes e integrações, habilidades agrupadas, modelo, preferências de memória nativa, atualizações opcionais de e-mail e telemetria (#5967). Os shells de agente podem passar --setup browser quando uma pessoa está lá, ou --setup defer para deixar as opções para a primeira visita do Meu Trabalho. Instalações explícitas de --provider/--ide e npx claude-mem update se comportam como antes.

Também novo

  • Gemini CLI: captura nativa do ciclo de vida com npx claude-mem gemini install|status|uninstall (#5991, obrigado @Kirat0201, fecha #5949). Documentos: https://docs.claude-mem.ai/gemini-cli/setup
  • Corpus de conhecimento em seu provedor API (opt-in): CLAUDE_MEM_CORPUS_AGENT=api responde query_corpus por meio do OpenRouter selecionado ou provedor compatível com OpenAI em vez do Agente Claude SDK. O padrão permanece inalterado (#5682, obrigado @bulanovk).
  • Agente SDK: um exemplo de memória no escopo do projeto (#5995, obrigado @Kirat0201).

Esclarecimento de privacidade

  • Uploads de histórico de prompts (#5176): a configuração do navegador pergunta antes de enviar o histórico de prompts selecionado para cmem.ai (corrigido em v15.8.3, #5220). Pular esta etapa não envia nenhum histórico de prompts. A habilidade de metas do proprietário pode usar seu agente de codificação existente para analisar o histórico local e salvar por meio do trabalhador local sem um upload de intenção cmem.ai separado. A inferência ainda usa o provedor de modelo desse agente. A atualização não remove os dados enviados anteriormente.

Correções

Obrigado @ Afloat16 por cada correção abaixo, a menos que outro nome seja fornecido.

Pesquisa e memória

  • Palavras Unicode em perguntas longas ainda correspondem às memórias indexadas (#5997); correspondência de títulos canonicamente equivalentes (#5975); barras invertidas literais no histórico do arquivo POSIX são mantidas (#5985, obrigado @Kirat0201); o ponto final semântico somente de observação pagina (#5892).
  • Recall sobrevive a mesclagens repetidas de projetos (#5990), e o Chroma mantém metadados ativos durante uma mesclagem e inicializa grandes projetos sem espalhar IDs de linha (#5881, #5862).
  • O conteúdo de observação estruturada distinta não é mais mesclado (#5979); identidades de sessões manuais em colisão são mantidas separadas (#5868).
  • Notas de memória nativa: os metadados citados são decodificados (#5983), análises Markdown com prefixo BOM (#5976) e o frontmatter precisa de uma linha de fechamento real de nível superior (#5845).
  • As respostas de conhecimento em diversas partes são mantidas inteiras (#6002).

Contexto e servidor

  • As linhas de contexto do servidor obedecem aos filtros de modo (#5993, obrigado @0xABCD01) e mantêm suas plataformas quando as respostas anteriores são selecionadas (#6003); rótulos armazenados em cache são atualizados após o uso da descoberta ser estabelecido (#6006).
  • O servidor mantém o escopo da plataforma para memórias manuais desvinculadas (#5875), identidade de recebimento nativo através de validação de eventos (#5872), plataformas de eventos em feeds de visualizadores (#5846) e captura de recibos de mutação dentro do escopo da chave (#5883).
  • Chaves de recall delegadas precisam de escopo de leitura (#5856); os resultados da geração em voo são eliminados antes de serem retornados (#5858); corpos de resumos recuperados são exibidos no visualizador (#5869).
  • O desligamento para de aceitar HTTP antes de esgotar as conexões (#5853).
  • O observador mantém a identidade da entrega quando a captura está desabilitada (#5867); sync mantém a caixa de saída quando um push interrompido é rejeitado (#5850).

Importar e configurar

  • As importações mantêm o histórico compactado do Codex (#6000), a proveniência da parte de texto do Gemini e as edições do histórico JSONL (#5999, #5865), Unicode na origem imediata (#5989), prompts legados distintos de Claude (#5982) e texto de observação legado (#5854); a atividade de fork do OpenCode copiada é excluída (#6004).
  • Uma importação de histórico é limitada às suas linhas iniciais (#5877); varreduras locais incluem histórico arquivado do Codex (#5888); a cobertura de token deixa de fora o histórico do observador e as estimativas de contexto do Codex (#5847, #5886).
  • As exportações incluem o histórico completo salvo (#5879); ancestrais de diretórios de dados vinculados trabalham para mídia (#5874); A regra do Código Claude importa espaços de escape (#5852).
  • Telemetria divulga compartilhamento padrão na primeira sessão (#5884).

Meu trabalho

  • Os passes de sincronização de trabalho compartilhado são limitados para que um thread travado não possa atrasar as ações do proprietário (#6014, obrigado @LuckVd) e as solicitações do leitor têm um prazo (#5860, obrigado @LuckVd).
  • A proveniência da sessão é republicada após uma publicação de atividade com falha (#6010, obrigado @bulanovk); a publicação de atividade compartilhada com falha é tentada novamente (#5870).
  • As metas do proprietário descartam cotações não verificáveis ​​de um novo salvamento em vez de recusar todo o salvamento (#5992, obrigado @0xABCD01); instantâneos de metas somente com regras são reutilizados (#5987); decisões de foco mais recentes sobrevivem a um desfazer (#5849).
  • Os produtos são atualizados quando os arquivos locais são alterados (#5887), os produtos GitHub são vinculados à saída push SSH (#5998), as opções valiosas do git push são analisadas antes dos alvos (#5885) e os assuntos de commit entre aspas simples são mantidos literalmente (#5896).
  • Os entregáveis ​​mantêm declarações para cópias capturadas anteriormente (#5973).

Integrações

  • OpenCode: o contrato atual da ferramenta integrada V2 é normalizado e o status da ferramenta com falha é mantido (#5857, #5855).
  • OMP: a semântica da ferramenta nativa e a identidade de recebimento de chamada de ferramenta são mantidas e os ganchos são instalados no perfil selecionado (#5871, #5864, #5876).
  • OpenClaw: a configuração JSON5 é aceita e a configuração do host selecionada e os caminhos de estado são usados ​​(#5861, #5844).
  • Windsurf: os comandos do usuário sobrevivem à instalação e a identidade do servidor MCP é mantida para filtragem de recursão (#5882, #5880).
  • Cursor: Argumento MCP e resultado Os envelopes JSON são decodificados (#5848). DSH: o caminho da transcrição gerenciada é atualizado na reinstalação (#5873). Código T3: o estado do plugin TOML é lido antes da remoção (#5851).
  • A leitura inteligente de arquivos inclui declarações de cabeçalho C e C++, construtores de registros Java compactos e TypeScript declare functions (#6015, #6012, #6005); Literais XML mantêm suas tags de fechamento (#5977).

Redação e desempenho

  • Os tokens de acesso Pulumi e os tokens pessoais Doppler foram redigidos (#5984, obrigado @kevin9327).
  • A telemetria agrega estatísticas de eventos na chegada (#5994), longas linhas de transcrição são montadas uma vez na importação (#5981), o uso do token OpenCode é transmitido (#5974) e as pesquisas de repetição de prompt legado no visualizador são limitadas por tempo (#6011).

Documentos

  • Os guias da estrutura do agente foram agrupados e uma configuração que não existe foi removida (#6030).
  • A reivindicação do token é declarada como uma proporção de tamanho por resultado (#5889, obrigado @Zhong-fan, #4138).

claude-mem v15.18.0

eve agents get the same memory as Claude Code and Codex

claude-mem/eve now gives an eve agent the full claude-mem memory loop through your cmem.ai account (#6042).

  • Session context: each turn starts with the recent timeline from your memory. It is refreshed every turn under one message id, so it replaces itself instead of piling up.
  • Recall each turn: one search before the turn, as before.
  • Recording is now on by default. After each completed turn the provider sends the prompt, one observation per tool call, and a turn summary to cmem.ai as platform eve. Recorded tool calls and summaries come out of your cmem.ai observer allowance, the same allowance your other clients use. Pass capture: false to keep the old read-only behaviour; session context, recall, search and remember keep working.
    • <private>…</private> regions and secret-shaped text are removed on your deployment before anything is sent, with the same rules the Cowork plugin uses.
    • Replays of the same turn are dropped by cmem.ai (turn-scoped tool call ids and an idempotency key).
    • Each request is sent once. No retry, spool or queue, so an outage never creates spend later. A failure is logged with how many events were accepted.
  • Tools: search, timeline, get_observations (the three-step Smart search) and remember.
  • eve versions: tested on eve 0.84.0 and 1.0.0-rc.9.
  • Template: works on a free-credit Vercel AI Gateway (Claude, falling back to openai/gpt-5-mini when Claude is refused on free credits), or set ANTHROPIC_API_KEY to call Claude directly and EVE_MODEL to pick an exact model. Scheduled runs get the owner's memory, owner email must match exactly, and a morning-digest example schedule ships turned off.

Docs: https://docs.claude-mem.ai/eve-integration

Install choices move to the browser

A standard install now sets up the runtime in the terminal, then opens the local web setup to choose agents and integrations, bundled skills, model, native-memory preferences, optional email updates and telemetry (#5967). Agent shells can pass --setup browser when a person is there, or --setup defer to leave the choices for the first My Work visit. Explicit --provider / --ide installs and npx claude-mem update behave as before.

Also new

  • Gemini CLI: native lifecycle capture with npx claude-mem gemini install|status|uninstall (#5991, thanks @Kirat0201, closes #5949). Docs: https://docs.claude-mem.ai/gemini-cli/setup
  • Knowledge corpus on your API provider (opt-in): CLAUDE_MEM_CORPUS_AGENT=api answers query_corpus through the selected OpenRouter or OpenAI-compatible provider instead of the Claude Agent SDK. The default is unchanged (#5682, thanks @bulanovk).
  • Agent SDK: a project-scoped memory example (#5995, thanks @Kirat0201).

Privacy clarification

  • Prompt-history uploads (#5176): browser setup asks before sending selected prompt history to cmem.ai (fixed in v15.8.3, #5220). Skip this step sends no prompt history. The owner-goals skill can use your existing coding agent to analyze local history and save through the local worker without a separate cmem.ai intent upload. Inference still uses that agent's model provider. Updating does not remove data previously sent.

Fixes

Thanks @Afloat16 for every fix below unless another name is given.

Search and memory

  • Unicode words in long questions still match indexed memories (#5997); canonically equivalent titles match (#5975); literal backslashes in POSIX file history are kept (#5985, thanks @Kirat0201); the observation-only semantic endpoint paginates (#5892).
  • Recall survives repeated project merges (#5990), and Chroma keeps live metadata during a merge and bootstraps large projects without spreading row ids (#5881, #5862).
  • Distinct structured observation content is no longer merged (#5979); colliding manual session identities are kept apart (#5868).
  • Native memory notes: quoted metadata is decoded (#5983), BOM-prefixed Markdown parses (#5976), and frontmatter needs a real top-level closing line (#5845).
  • Knowledge answers in several parts are kept whole (#6002).

Context and server

  • Server context rows obey mode filters (#5993, thanks @0xABCD01) and keep their platforms when prior replies are selected (#6003); cached labels refresh after discovery usage settles (#6006).
  • The server keeps platform scope for unlinked manual memories (#5875), native receipt identity through event validation (#5872), event platforms in viewer feeds (#5846), and capture mutation receipts within the key's scope (#5883).
  • Delegated recall keys need read scope (#5856); in-flight generation results are purged before returning (#5858); salvaged summary bodies show in the viewer (#5869).
  • Shutdown stops accepting HTTP before draining connections (#5853).
  • The observer keeps delivery identity when capture is disabled (#5867); sync keeps the outbox when a stopped push is rejected (#5850).

Import and setup

  • Imports keep compressed Codex history (#6000), Gemini text-part provenance and JSONL history edits (#5999, #5865), Unicode in prompt provenance (#5989), distinct legacy Claude prompts (#5982) and legacy observation text (#5854); copied OpenCode fork activity is excluded (#6004).
  • A history import is bounded to its starting rows (#5877); local scans include archived Codex history (#5888); token coverage leaves out observer history and Codex context estimates (#5847, #5886).
  • Exports include the full saved history (#5879); linked data-directory ancestors work for media (#5874); Claude Code rule imports escape spaces (#5852).
  • Telemetry discloses default sharing in the first session (#5884).

My Work

  • Shared-work sync passes are bounded so a hung thread cannot stall owner actions (#6014, thanks @LuckVd), and reader requests have a deadline (#5860, thanks @LuckVd).
  • Session provenance is republished after a failed activity publish (#6010, thanks @bulanovk); failed shared-activity publication is retried (#5870).
  • Owner goals drop unverifiable quotes from a fresh save instead of refusing the whole save (#5992, thanks @0xABCD01); rules-only goal snapshots are reused (#5987); newer focus decisions survive an undo (#5849).
  • Products refresh when local files change (#5887), GitHub products link from SSH push output (#5998), valued git push options parse before targets (#5885), and single-quoted commit subjects are kept literally (#5896).
  • Deliverables keep declarations for previously captured copies (#5973).

Integrations

  • OpenCode: the current V2 built-in tool contract is normalized and failed tool status is kept (#5857, #5855).
  • OMP: native tool semantics and tool-call receipt identity are kept, and hooks install into the selected profile (#5871, #5864, #5876).
  • OpenClaw: JSON5 configuration is accepted, and the selected host config and state paths are used (#5861, #5844).
  • Windsurf: user hook commands survive installation and the MCP server identity is kept for recursion filtering (#5882, #5880).
  • Cursor: MCP argument and result JSON envelopes are decoded (#5848). DSH: the managed transcript path refreshes on reinstall (#5873). T3 Code: TOML plugin state is read before removal (#5851).
  • Smart file reading includes C and C++ header declarations, compact Java record constructors and TypeScript declare functions (#6015, #6012, #6005); XML literals keep their closing tags (#5977).

Redaction and performance

  • Pulumi access tokens and Doppler personal tokens are redacted (#5984, thanks @kevin9327).
  • Telemetry aggregates event statistics on arrival (#5994), long transcript lines are assembled once on import (#5981), OpenCode token usage is streamed (#5974), and legacy prompt retry lookups in the viewer are bounded by time (#6011).

Docs

  • Agent framework guides are grouped, and a setting that does not exist was removed (#6030).
  • The token claim is stated as a per-result size ratio (#5889, thanks @Zhong-fan, #4138).
