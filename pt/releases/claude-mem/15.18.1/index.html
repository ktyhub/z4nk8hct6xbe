#claude-mem v15.18.1

Correções críticas

  • O trabalhador não falha mais ao iniciar quando o banco de dados está ocupado na inicialização (#6041). Se o registro de atualização do Meu Trabalho foi deixado como "em execução" por uma reinicialização e o banco de dados foi bloqueado naquele momento, a gravação de reparo foi lançada e desativou toda a inicialização do trabalhador, de modo que a memória permaneceu desligada até a próxima reinicialização. A falha de reparo agora é registrada e a próxima verificação agendada tenta novamente (independentemente de a atualização agendada estar ativada ou não).
  • npx claude-mem update e a atualização automática diária mantêm sua configuração (#6045). Antes disso, uma atualização autônoma redefinia um servidor ou tempo de execução do servidor beta de volta para o trabalhador local, portanto, a captura era movida para fora do servidor. Uma instalação legada sem nenhum provedor salvo também pode ter sua sincronização na nuvem desativada e suas chaves de ambiente antrópico limpas. As atualizações agora reutilizam seu tempo de execução, provedor, modelo e agentes salvos. Eles não reabrem a configuração do navegador nem fazem perguntas de configuração novamente e só pedem uma chave Gemini ou OpenRouter se alguma estiver faltando. npx claude-mem install permanece inalterado.
  • Meus resumos de trabalho param de tentar novamente respostas de modelos inutilizáveis ​​para sempre (#6039, obrigado @mohitdixit02, relatado por @adminwat em #6037). Quando a resposta do modelo falhou na validação, não era JSON ou voltou vazia, a mesma solicitação inalterada era reenviada a cada minuto sem fim. Um relatório mediu 104.869 ligações, e a carga constante deixou um runner local de Ollama faminto. Cada versão de solicitação agora recebe no máximo três tentativas com uma espera crescente e, em seguida, aguarda até que sua entrada ou configurações sejam alteradas. O cartão mostra o motivo real. Obrigado @balabommablock-cpu por testar e encontrar o caso de resposta vazia.

Correções

  • Custo mais baixo do observador por padrão (#6031, obrigado @kartik70, fecha #5023). O orçamento de conversação do observador cai de 400.000 para 100.000 caracteres (cerca de 100 mil para cerca de 26 mil tokens por turno na medição do problema). Instalações que ainda mantêm o antigo padrão fornecido são movidas uma vez; um valor que você mesmo definiu é mantido.
  • Redação: As chaves Heroku API e os tokens Atlassian API agora são removidos antes do armazenamento (#6046, obrigado @kevin9327).
  • TeamBrain: o texto retransmitido não pode mais passar como títulos, cercas ou regras do próprio Claude-mem (~~~, ***, ___, setext ===) (#6048, obrigado @kevin9327).
  • Estado de trabalho: GET /api/work-state/export retorna o histórico completo de uma lista quando ela é muito longa para uma resposta do MCP, e as leituras abreviadas do MCP agora dizem isso e apontam para ela (#6049, obrigado @Jeremy891102, fecha #6043).
  • Meu trabalho (obrigado @Afloat16):
    • Uma solicitação verificada é desmarcada novamente quando uma nova revisão de entrega ou PR publicado altera seu resultado (#5891).
    • O primeiro mapa de metas de um longo histórico de prompts é executado em lotes com pontos de verificação, em vez de uma pergunta enorme que falha e se repete (#6001).
    • A resolução de solicitações originais não verifica mais toda a janela de prompt por conversa (#6022).
  • Leitura inteligente de arquivo: as assinaturas de função terminam no limite do corpo real em todas as linguagens suportadas, portanto, parâmetros desestruturados e objetos padrão permanecem no contorno e são pesquisáveis ​​(#6029, obrigado @Afloat16).
  • Gemini CLI: npx claude-mem gemini install encontra um trabalhador instalado apenas no cache do plugin em vez de reportá-lo como ausente (#6032, obrigado @Kirat0201).
  • Memória: reproduzir uma nota de memória nativa mais antiga usa um índice em vez de verificar o histórico do projeto dentro da transação de gravação (#6016, obrigado @Afloat16).

Novos exemplos e documentos

  • Obsidian: uma exportação unilateral e opcional de memórias selecionadas para um cofre existente, nunca sobrescrevendo suas anotações (#6051, obrigado @Jeremy891102, fecha #5943).
  • Pipecat: um exemplo explícito de pipeline de memória de projeto (#6050, obrigado @Jeremy891102, fecha #5946).
  • elizaOS: um exemplo verificado de memória explícita (#6035, obrigado @Kirat0201, fecha #5914).
  • ContextForge: um fluxo de trabalho de recall privado (#6033, obrigado @Kirat0201, fecha #5935).

claude-mem v15.18.1

Critical fixes

  • The worker no longer fails to start when the database is busy at startup (#6041). If the My Work refresh record was left as "running" by a restart and the database was locked at that moment, the repair write threw and took down the worker's whole startup, so memory stayed off until the next restart. The repair failure is now logged, and the next scheduled check tries again (whether or not scheduled refresh is on).
  • npx claude-mem update and the daily auto-update keep your setup (#6045). Before this, an unattended update reset a server or server-beta runtime back to the local worker, so capture moved off your server. A legacy install with no saved provider could also have its cloud sync turned off and its Anthropic env keys cleared. Updates now reuse your saved runtime, provider, model and agents. They don't reopen the browser setup or ask the setup questions again, and only ask for a Gemini or OpenRouter key if one is missing. npx claude-mem install is unchanged.
  • My Work summaries stop retrying unusable model answers forever (#6039, thanks @mohitdixit02, reported by @adminwat in #6037). When the model's answer failed validation, wasn't JSON or came back empty, the same unchanged request was resent every minute with no end. One report measured 104,869 calls, and the constant load starved a local Ollama runner. Each request version now gets at most 3 tries with a growing wait, then waits until its input or settings change. The card shows the actual reason. Thanks @balabommablock-cpu for testing and finding the empty-answer case.

Fixes

  • Lower observer cost by default (#6031, thanks @kartik70, closes #5023). The observer's conversation budget drops from 400,000 to 100,000 characters (about 100K to about 26K tokens per turn in the issue's measurement). Installs that still hold the old shipped default move once; a value you set yourself is kept.
  • Redaction: Heroku API keys and Atlassian API tokens are now removed before storage (#6046, thanks @kevin9327).
  • TeamBrain: relayed text can no longer pass as claude-mem's own headings, fences or rules (~~~, ***, ___, setext ===) (#6048, thanks @kevin9327).
  • Work state: GET /api/work-state/export returns the complete history of a list when it is too long for an MCP reply, and shortened MCP reads now say so and point to it (#6049, thanks @Jeremy891102, closes #6043).
  • My Work (thanks @Afloat16):
    • A checked request is unchecked again when a new deliverable revision or published PR changes its result (#5891).
    • The first goals map of a long prompt history runs in checkpointed batches instead of one oversized question that fails and repeats (#6001).
    • Resolving original requests no longer rescans the whole prompt window per conversation (#6022).
  • Smart file read: function signatures end at the real body boundary in every supported language, so destructured parameters and default objects stay in the outline and are searchable (#6029, thanks @Afloat16).
  • Gemini CLI: npx claude-mem gemini install finds a worker installed only in the plugin cache instead of reporting it missing (#6032, thanks @Kirat0201).
  • Memory: replaying an older native memory note uses an index instead of scanning project history inside the write transaction (#6016, thanks @Afloat16).

New examples and docs

  • Obsidian: an opt-in, one-way export of selected memories into an existing vault, never overwriting your notes (#6051, thanks @Jeremy891102, closes #5943).
  • Pipecat: an explicit project-memory pipeline example (#6050, thanks @Jeremy891102, closes #5946).
  • elizaOS: a verified explicit-memory example (#6035, thanks @Kirat0201, closes #5914).
  • ContextForge: a private recall workflow (#6033, thanks @Kirat0201, closes #5935).
