#claude-mem v16.0.2

Correção crítica

  • Uma atualização automática não exclui mais a versão do plugin da qual uma sessão do Claude Code em execução foi carregada (#6352, obrigado @0xABCD01, fecha #6349 relatado por @justindrp). A varredura de cache mantém uma pasta de versão enquanto o processo Claude Code registrado em seu arquivo .in_use está ativo. No macOS e no BSD, alguns segundos de diferença entre o horário de início registrado por Claude Code e aquele relatado pelo ps foram lidos como reutilização de PID, então a varredura excluiu a pasta de uma sessão ao vivo e todos os ganchos falharam pelo resto da sessão. Uma incompatibilidade de horário de início não remove mais a pasta enquanto o processo nesse PID ainda é o Código Claude. Um PID que agora pertence a outro programa ainda será removido como antes.
  • Cada remoção de cache agora registra por que e quem. O trabalhador grava uma linha de log por versão removida com seu motivo (órfão ou substituído) e o .in_use registra a rejeição e o porquê (processo encerrado ou incompatibilidade de horário de início), para que qualquer remoção possa ser rastreada apenas a partir do log.

Correções

  • O cartão de início de sessão é sorteado em contas Team e Enterprise (#6353, obrigado @KeithMoc, fecha #6314 relatado por @TimoWestland). Quando um plugin de organização é executado primeiro e os ganchos usuais da placa nunca são acionados, a placa agora solicita a si mesma no gancho session.start e o gancho de contexto responde.
  • Meu trabalho detecta conexões OpenCode 2.x (#6340, obrigado @ZedingZhang, fecha #6339 relatado por @Realauster). A sonda de login lê a saída JSON do OpenCode, portanto, um provedor conectado não é mais relatado como desconectado no OpenCode 2.3.2.
  • A atualização My Work prefere MXC para lançamentos isolados do Codex no Windows (#6348, obrigado @QuantScorpus, refs #5163). A atualização não seleciona mais o sandbox não elevado e falha antes do início do agente.
  • Ambas as sondagens host-observador fornecem a um observador lento o mesmo 1 s (#6359, obrigado @rtmalikian, fecha #6358). A sonda assíncrona usou 400 ms e a sonda de tempo de instalação 1 s, portanto, uma chamou um observador válido de "ocupado" e a outra não.
  • As exclusões da coleção Chroma que perdem a resposta são verificadas antes de uma reconstrução (#6338, obrigado @POWDER-RANGER). O trabalhador lista as coleções uma vez em vez de repetir a exclusão e só reconstrói quando a exclusão é confirmada.
  • chroma-mcp reinicia após uma leitura cancelada quando as gravações em andamento são resolvidas (#6337, obrigado @MaxWang007). A próxima chamada não vai mais para um servidor que não consegue mais ler sua entrada.
  • Erros de trabalho e caminhos desconhecidos respondem em JSON (#6341, obrigado @DeryFerd). O trabalhador agora instala seus manipuladores de erros e 404, portanto, não retorna mais a página de erro HTML do Express com caminhos de arquivos locais no rastreamento de pilha.
  • O posicionamento CLAUDE.md resolve caminhos absolutos antes da verificação do projeto (#6336, obrigado @LeviReisJs). Os caminhos de barra no Windows não são mais descartados e os caminhos que climb saem do projeto com .. são recusados.
  • npx claude-mem doctor lê o endpoint do médico do trabalhador uma vez (#6344, obrigado @DeryFerd), então um trabalhador lento custa um tempo limite em vez de dois.
  • A habilidade do Relatório de custos do agente usa um nome compatível com as especificações (#6356, obrigado @LuckVd, refs #6355), para que os agentes que verificam os nomes das habilidades a carreguem.

Novo

  • Codex como reserva de cota de observador (#6326, obrigado @QuantScorpus). Quando Claude atinge sua cota de guarda, o observador pode usar o Codex local CLI conectado ao ChatGPT e retornar a Claude através do caminho de recuperação existente.
  • Predefinição WorldRouter para o provedor compatível com OpenAI (#6357, obrigado @Opgeek-1).
  • O cartão inicial mostra a marca Claude-Mem na coluna da direita quando o terminal é largo o suficiente (#6333).

Testes, CI e documentos

  • Um teste de religação de DNS fixa a proteção Host do trabalhador à frente do CORS (#6345, obrigado @DeryFerd).
  • A versão do Windows executa o protetor de lista de permissões pós-instalação (#6343, obrigado @DeryFerd).
  • A nuvem Devin precisa de um segredo organizacional para conectar o CMEM Pro (#6335).
  • O exemplo de fixação do Docker diz para construir a partir da raiz do repositório (#6346, obrigado @DeryFerd). changelog completo: https://github.com/thedotmack/claude-mem/compare/v16.0.1...v16.0.2

claude-mem v16.0.2

Critical fix

  • An auto-update no longer deletes the plugin version a running Claude Code session was loaded from (#6352, thanks @0xABCD01, closes #6349 reported by @justindrp). The cache sweep keeps a version folder while the Claude Code process recorded in its .in_use file is alive. On macOS and BSD, a few seconds of difference between the start time Claude Code recorded and the one ps reports was read as PID reuse, so the sweep deleted the folder from under a live session and every hook failed for the rest of that session. A start-time mismatch no longer removes the folder while the process at that PID is still Claude Code. A PID that now belongs to another program is still pruned as before.
  • Every cache prune now logs why and who. The worker writes one log line per removed version with its reason (orphaned or superseded) and the .in_use records it rejected and why (process exited or start-time mismatch), so any removal can be traced from the log alone.

Fixes

  • The session-start card is drawn on Team and Enterprise accounts (#6353, thanks @KeithMoc, closes #6314 reported by @TimoWestland). When an organization plugin runs first and the card's usual hooks never fire, the card now asks for itself from the session.start hook and the context hook answers it.
  • My Work detects OpenCode 2.x connections (#6340, thanks @ZedingZhang, closes #6339 reported by @Realauster). The login probe reads OpenCode's JSON output, so a connected provider is no longer reported as logged out on OpenCode 2.3.2.
  • My Work refresh prefers MXC for isolated Codex launches on Windows (#6348, thanks @QuantScorpus, refs #5163). The refresh no longer picks the unelevated sandbox and fails before the agent starts.
  • Both host-observer probes give a slow observer the same 1 s (#6359, thanks @rtmalikian, closes #6358). The async probe used 400 ms and the install-time probe 1 s, so one called a valid observer "occupied" and the other did not.
  • Chroma collection deletes that lose their reply are checked before a rebuild (#6338, thanks @POWDER-RANGER). The worker lists collections once instead of replaying the delete, and only rebuilds once the delete is confirmed.
  • chroma-mcp restarts after a cancelled read once in-flight writes settle (#6337, thanks @MaxWang007). The next call no longer goes to a server that can no longer read its input.
  • Worker errors and unknown paths answer in JSON (#6341, thanks @DeryFerd). The worker now installs its 404 and error handlers, so it no longer returns Express's HTML error page with local file paths in the stack trace.
  • CLAUDE.md placement resolves absolute paths before the project check (#6336, thanks @LeviReisJs). Forward-slash paths on Windows are no longer dropped, and paths that climb out of the project with .. are refused.
  • npx claude-mem doctor reads the worker's doctor endpoint once (#6344, thanks @DeryFerd), so a slow worker costs one timeout instead of two.
  • The Agent Cost Report skill uses a spec-compliant name (#6356, thanks @LuckVd, refs #6355), so agents that check skill names load it.

New

  • Codex as an observer quota fallback (#6326, thanks @QuantScorpus). When Claude hits its quota guard, the observer can use the local Codex CLI signed in with ChatGPT and return to Claude through the existing recovery path.
  • WorldRouter preset for the OpenAI-compatible provider (#6357, thanks @Opgeek-1).
  • The startup card shows the Claude-Mem mark in a right column when the terminal is wide enough (#6333).

Tests, CI and docs

  • A DNS-rebinding test pins the worker's Host guard ahead of CORS (#6345, thanks @DeryFerd).
  • The Windows build runs the postinstall allowlist guard (#6343, thanks @DeryFerd).
  • Devin cloud needs one org secret to connect CMEM Pro (#6335).
  • The Docker pinning example says to build from the repository root (#6346, thanks @DeryFerd).
