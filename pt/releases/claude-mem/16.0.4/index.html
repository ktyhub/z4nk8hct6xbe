#claude-mem v16.0.4

Correções

  • A pesquisa Chroma funciona novamente enquanto o modelo de incorporação é baixado (#6399, fecha a parte "Porta inválida" de #6365 relatada por @FengJie2004, causa raiz encontrada por @kevincommits). httpx 0.28 interpretou incorretamente uma entrada IPv6 entre colchetes, como [::1] em NO_PROXY e falhou com Invalid port: ':1]', então o chroma-mcp não pôde adicionar documentos e a pesquisa voltou para FTS5. O filho chroma-mcp agora obtém o mesmo host sem colchetes (::1). As entradas com uma porta e todas as outras entradas permanecem inalteradas.
  • A injeção de contexto mantém observações cujos conceitos são uma string simples antiga (#6393, obrigado @jiangjiang248, fecha #6389 relatado por @soarkit). A pesquisa por palavra-chave correspondeu a um conceito legado como 缓存, mas a injeção de contexto eliminou a mesma observação. Ambos agora leem conceitos por meio de uma expressão SQL compartilhada, para que não possam se separar novamente.
  • OpenCode Go responde às etapas de atualização e corpus do Meu Trabalho (#6395, obrigado @HemanRamlal). O agente API agora envia o cabeçalho x-opencode-session que o OpenCode Go requer (um id por execução) e desativa o raciocínio com reasoning_effort: none, que Go honra. Antes, todas as etapas falhavam com 400 MissingSessionID ou esgotavam seu orçamento de resposta enquanto pensava.
  • As entradas expiradas do observador ao vivo são contadas e relatadas (#6394, obrigado @Zhong-fan, fecha #6391 relatado por @abhiroopb). O buffer ao vivo ainda descarta uma entrada que ninguém reivindica em cinco minutos e ainda nunca a reproduz. A linha WARN agora carrega um total em execução e /api/processing-status o retorna como expiredObserverInputs, portanto a perda é visível sem a leitura dos logs.
  • /api/tool-uses recusa um encontro ruim em vez de ignorá-lo (#6387, obrigado @kevincommits). Um dateStart ou dateEnd que não era um número (uma data ISO, um erro de digitação ou o parâmetro fornecido duas vezes) foi eliminado e a listagem retornou linhas de cada data. Agora responde 400 INVALID_DATE. Os valores de época-milissegundos funcionam como antes.
  • /api/dedup/candidates recusa um limite fracionário em vez de responder 500 (#6388, obrigado @REI-330). limit=2.5 falhou com datatype mismatch. Um limite que não é um número inteiro agora responde a 400 limit must be a whole number, e o armazenamento fixa o que está vinculado para que um limite negativo não possa ler todas as linhas.
  • /api/advisor-calls limita seu deslocamento como qualquer outra listagem (#6396, obrigado @DeryFerd). Um enorme offset fez o SQLite varrer e descartar linhas na conexão compartilhada do trabalhador. Ele agora usa o limite de listagem compartilhada e um visualizador que mantém paradas de paginação com offsetCapReached.

Serviço de sincronização hospedado

  • A sincronização API verifica a URL do projetor antes de enviar seu segredo (#6397, obrigado @DeryFerd). INTERNAL_PROJECTOR_URL agora segue as mesmas regras que FORWARD_ORIGIN (https absoluto, http simples apenas para loopback, sem credenciais, consulta ou fragmento) e falha na inicialização. Antes, um erro de digitação ou um endereço http:// enviava o segredo do portador interno em texto não criptografado. Isso altera o services/sync-api, que não faz parte do pacote npm: ele chega aos usuários apenas quando o serviço é implantado.

Interno

  • Um ajudante agora decide se um deslocamento de listagem ultrapassou o limite (#6398, obrigado @DeryFerd). O comportamento permanece inalterado.
  • O 16.0.3 changelog agora diz aos usuários do OMP para executarem o npx claude-mem install --ide omp uma vez para obter a correção do tempo de execução do servidor. changelog completo: https://github.com/thedotmack/claude-mem/compare/v16.0.3...v16.0.4

claude-mem v16.0.4

Fixes

  • Chroma search works again while the embedding model downloads (#6399, closes the "Invalid port" part of #6365 reported by @FengJie2004, root cause found by @kevincommits). httpx 0.28 misread a bracketed IPv6 entry such as [::1] in NO_PROXY and failed with Invalid port: ':1]', so chroma-mcp could not add documents and search fell back to FTS5. The chroma-mcp child now gets the same host without brackets (::1). Entries with a port, and every other entry, are unchanged.
  • Context injection keeps observations whose concepts are an old plain string (#6393, thanks @jiangjiang248, closes #6389 reported by @soarkit). Keyword search matched a legacy concept such as 缓存, but context injection dropped the same observation. Both now read concepts through one shared SQL expression, so they cannot drift apart again.
  • OpenCode Go answers My Work refresh and corpus steps (#6395, thanks @HemanRamlal). The API agent now sends the x-opencode-session header OpenCode Go requires (one id per run), and turns reasoning off with reasoning_effort: none, which Go honors. Before, every step failed with 400 MissingSessionID, or ran out of its answer budget while thinking.
  • Expired live observer inputs are counted and reported (#6394, thanks @Zhong-fan, closes #6391 reported by @abhiroopb). The live buffer still drops an input nobody claims within five minutes, and still never replays it. The WARN line now carries a running total, and /api/processing-status returns it as expiredObserverInputs, so the loss is visible without reading logs.
  • /api/tool-uses refuses a bad date instead of ignoring it (#6387, thanks @kevincommits). A dateStart or dateEnd that was not a number (an ISO date, a typo, or the parameter given twice) was dropped, and the listing returned rows from every date. It now answers 400 INVALID_DATE. Epoch-millisecond values work as before.
  • /api/dedup/candidates refuses a fractional limit instead of answering 500 (#6388, thanks @REI-330). limit=2.5 failed with datatype mismatch. A limit that is not a whole number now answers 400 limit must be a whole number, and the store clamps what it binds so a negative limit cannot read every row.
  • /api/advisor-calls caps its offset like every other listing (#6396, thanks @DeryFerd). A huge offset made SQLite scan and discard rows on the worker's shared connection. It now uses the shared listing cap, and a viewer that keeps paging stops with offsetCapReached.

Hosted sync service

  • The sync API checks the projector URL before sending its secret (#6397, thanks @DeryFerd). INTERNAL_PROJECTOR_URL now follows the same rules as FORWARD_ORIGIN (absolute https, plain http only for loopback, no credentials, query or fragment) and fails at startup. Before, a typo or an http:// address sent the internal bearer secret in cleartext. This changes services/sync-api, which is not part of the npm package: it reaches users only once that service is deployed.

Internal

  • One helper now decides whether a listing offset is past the cap (#6398, thanks @DeryFerd). Behavior is unchanged.
  • The 16.0.3 changelog now tells OMP users to run npx claude-mem install --ide omp once to get the server-runtime fix.

Full changelog: https://github.com/thedotmack/claude-mem/compare/v16.0.3...v16.0.4
