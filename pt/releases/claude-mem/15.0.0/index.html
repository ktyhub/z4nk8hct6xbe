#claude-mem v15.0.0

Pesquisa inteligente de memória por padrão

A recuperação de memória agora é inteligente por padrão: pesquise o índice compacto, inspecione o contexto em torno dos resultados relevantes e, em seguida, busque apenas os detalhes selecionados. O agente raciocina sobre a relevância entre essas três etapas. Instruções locais, de nuvem/Pro e de servidor autônomo descrevem as ferramentas disponíveis nesse tempo de execução. A pesquisa opcional de uma chamada agora é dumb_search. Sua descrição é explícita: "Não raciocina sobre os resultados. Rápido, mas superficial. Use o Smart para uma recuperação confiável". Ele realiza correspondência determinística de títulos e não raciocina sobre relevância.

Migração

  • Use a habilidade mem-search para recuperação inteligente padrão. As ferramentas locais são search → timeline → get_observations; Cloud/Pro começa com memory_search e pode buscar resumos selecionados com get_summaries.
  • Substitua as chamadas para os antigos mem_search guiados/automáticos API e flash_search pelo fluxo de trabalho Inteligente ou escolha explicitamente dumb_search para uma pesquisa superficial. Os modos automático/guiado e os cursores de continuação são removidos.
  • Atualize as conexões MCP existentes para que clients carregue o novo catálogo e descrições de ferramentas.

Correção

  • A linha do tempo da nuvem suporta contexto ancorado em um resultado de pesquisa selecionado.
  • A recuperação do servidor autônomo permanece no escopo de seu projeto de servidor configurado, em vez de ler a memória de um trabalhador local.
  • A saída de detalhes selecionados relata seus limites honestamente e preserva as identidades dos registros selecionados quando um conteúdo longo deve ser encurtado.
  • A pesquisa de memória nativa usa índices somente de observação, e os índices locais mistos retêm prefixos de ID de sessão/prompt para que as leituras de acompanhamento não possam selecionar um tipo de registro diferente com o mesmo número.
  • Os prompts do instalador, a documentação pública, as instruções de integração e as orientações de memória geradas usam a mesma política Smart-first.

Outras mudanças desde v14.0.1

  • Adicionado suporte e instalação de memória do Hermes Agent, incluindo manuseio seguro da configuração YAML existente.
  • Adicionado fallback entre uma chave Anthropic API e a assinatura Claude, com classificação de cota e recuperação de volta ao provedor primário em um limite de mensagem.
  • Manteve as solicitações HTTP do trabalhador responsivas durante leituras de contexto local, limitou amplas pesquisas de fallback de texto completo e removeu paralisações quadráticas de remoção de tags.
  • Correção de memória aprimorada: type="all" pesquisa todas as categorias, observações excluídas removem seus documentos Chroma, saídas inesperadas do Chroma rejeitam solicitações pendentes e renomeações de pontos de verificação do Windows com falha preservam o ponto de verificação anterior.
  • Maior privacidade e tratamento de solicitações: prompts totalmente privados não se tornam mais solicitações de usuários armazenadas; a redação principal lida com travessões finais; resumos de pesquisa internos da Grok não se tornam trabalho do usuário; solicitações de trabalho multilíngues são reconhecidas; e a condensação de campo do OpenRouter evita raciocínios desnecessários.
  • Instalação aprimorada e confiabilidade de tempo de execução em Windows, macOS, Conda, Qoder, Goose, OpenCode, Antigravity, Codex e TeamBrain. As correções incluem auto-recursão do iniciador e manipulação de diretório de trabalho, limpeza de diretório temporário obsoleto, autenticação acionável e erros de tempo de execução ausentes e registro correto de gancho de host.
  • Adicionado contexto opcional entre projetos com CLAUDE_MEM_CONTEXT_PROJECTS=all, ordenação de contexto de pasta corrigida e correspondência glob, entradas de spool de resumo órfãs expiradas e pesquisa de log de diretório de dados efetivo aprimorada e telemetria de autenticação em nuvem. As identidades de validação e entrega são registradas separadamente no recibo de lançamento após a conclusão das compilações finais, implantação e verificações de pacote.

claude-mem v15.0.0

Smart memory search by default

Memory recall now defaults to Smart: search the compact index, inspect context around relevant results, then fetch only the selected details. The agent reasons about relevance between these three steps. Local, cloud/Pro, and standalone-server instructions describe the tools available in that runtime.

The optional one-call lookup is now dumb_search. Its description is explicit: “Doesn’t reason about the results. Fast, but shallow. Use Smart for reliable recall.” It performs deterministic title matching and does not reason about relevance.

Migration

  • Use the mem-search skill for default Smart recall. Local tools are search → timeline → get_observations; Cloud/Pro starts with memory_search and can fetch selected summaries with get_summaries.
  • Replace calls to the old mem_search guided/auto API and flash_search with the Smart workflow, or explicitly choose dumb_search for a shallow lookup. Auto/guided modes and continuation cursors are removed.
  • Refresh existing MCP connections so clients load the new tool catalog and descriptions.

Correctness

  • Cloud timeline supports context anchored to a selected search result.
  • Standalone-server recall stays scoped to its configured server project rather than reading a local worker's memory.
  • Selected-detail output reports its bounds honestly and preserves selected record identities when long content must be shortened.
  • Native memory lookup uses observation-only indexes, and mixed local indexes retain session/prompt ID prefixes so follow-up reads cannot select a different record kind with the same number.
  • Installer prompts, public documentation, integration instructions, and generated memory guidance use the same Smart-first policy.

Other changes since v14.0.1

  • Added Hermes Agent memory support and installation, including safe handling of existing YAML configuration.
  • Added fallback between an Anthropic API key and the Claude subscription, with quota classification and recovery back to the primary provider at a message boundary.
  • Kept worker HTTP requests responsive during local context reads, bounded broad full-text fallback searches, and removed quadratic tag-stripping stalls.
  • Improved memory correctness: type="all" searches every category, deleted observations remove their Chroma documents, unexpected Chroma exits reject pending requests, and failed Windows checkpoint renames preserve the previous checkpoint.
  • Tightened privacy and request handling: fully private prompts no longer become stored user requests; key redaction handles trailing dashes; internal Grok research briefs do not become user work; multilingual work requests are recognized; and OpenRouter field condensation avoids unnecessary reasoning.
  • Improved installation and runtime reliability across Windows, macOS, Conda, Qoder, Goose, OpenCode, Antigravity, Codex, and TeamBrain. Fixes include launcher self-recursion and working-directory handling, stale temporary-directory cleanup, actionable authentication and missing-runtime errors, and correct host hook registration.
  • Added optional cross-project context with CLAUDE_MEM_CONTEXT_PROJECTS=all, corrected folder context ordering and glob matching, expired orphaned summary spool entries, and improved effective-data-directory log lookup and cloud authentication telemetry.

Validation and delivery identities are recorded separately in the release receipt after the final builds, deployment, and package checks complete.
