#nanobot v0.1.5.post2 🐈 nanobot v0.1.5.post2 está aqui 🎉 — 67 PRs mesclados, 12 novos colaboradores. O mundo do agente ficou maior e mais estável. Se v0.1.5.post1 tratava do agente aprendendo a gerenciar a si mesmo, v0.1.5.post2 tratava de alcance e polimento. Windows e Python 3.14 aderiram à matriz suportada. A ferramenta read_file aprendeu a entender DOCX, XLSX e PPTX. O Microsoft Teams chegou como um canal. O API compatível com OpenAI iniciou a transmissão via SSE. E, abaixo de tudo isso, cerca de 50 correções menores em cron, memória, novas tentativas, arquivos de sessão e peculiaridades do provedor continuaram transformando "funciona" em "é sólido". Uma interface de navegador dedicada também começou a tomar forma no repositório – visualização da fonte por enquanto.

Destaques

  • Windows + Python 3.14 — suporte de primeira classe — Uma matriz CI completa cobrindo executores do Windows e Python 3.14 chegou, junto com marcadores de instalação e correções de tempo de execução para as peculiaridades que essas plataformas expõem. Se você estiver executando o nanobot no WSL porque “o Windows não funcionou bem”, você pode parar. (#3194)
  • Documentos do Office, legíveis nativamente — A ferramenta read_file agora extrai texto de DOCX, XLSX e PPTX — tabelas e formas agrupadas incluídas, alças de pasta de trabalho fechadas com segurança. Combinado com o suporte anterior a PDF, o agente pode abrir qualquer formato que seu colega acabou de lhe enviar por e-mail, sem passar por um conversor. (#3336, #3269, #3353)
  • API compatível com OpenAI — streaming SSE — /v1/chat/completions agora emite pedaços SSE quando stream=true, conectando os retornos de chamada on_stream/on_stream_end existentes. Qualquer client construído para o OpenAI API – LangChain, LlamaIndex, seu próprio frontend – obtém deltas ao vivo do nanobot em vez de esperar pela resposta completa. O endpoint também parou de encerrar streams com um marcador de sucesso após uma falha de back-end, portanto, os erros surgem honestamente. (#3222, #3262)
  • Microsoft Teams, pensamento MiniMax, LM Studio, MyTool — Microsoft Teams juntou-se à lista de canais. MiniMax tem um endpoint de pensamento de estilo antrópico dedicado, além de uma correção de mapeamento reasoning_effort → reasoning_split. O LM Studio agora é compatível com chaves API anuláveis ​​para servidores locais que não esperam uma. O novo MyTool permite que o agente examine sua própria configuração de tempo de execução - e oculta campos de configuração aninhados sensíveis na saída check para que a autoinspeção não vaze segredos. (#3197, #3160, #3363, #3186, #3177, #3261)
  • Confiabilidade — a metade nada glamorosa de um lançamento — Os arquivos de sessão agora usam gravações atômicas com reparo de arquivos corrompidos, portanto, um desligamento incorreto não consome mais seu histórico. A recuperação do cursor de memória lida com corrupção de números não inteiros. A compactação automática ignora sessões com tarefas ativas e unifica a injeção de resumo em caminhos de consolidação. Os provedores ganham um disjuntor para o substituto do Responses API e reconhecem os limites de taxa do ZhiPu 1302. O Cron para de vazar o progresso intermediário, seu esquema de ferramenta funciona com OpenAI Codex/Responses e as repetidas pulsações não se espalham mais nos canais do usuário. Os acompanhamentos do subagente persistem no histórico da sessão. Metade deles você nunca notará – e esse é exatamente o ponto. (#3312, #3340, #3081, #3304, #3302, #3356, #3320, #3295, #3229, #3242)
  • Canais — mais silenciosos e nítidos — O Telegram ganhou divisão intermediária para respostas longas e melhor renderização de markdown para saída LLM moderna. O Discord parou de tratar as mensagens de bot para bot como auto-loops e adicionou listas de permissões baseadas em canais. O e-mail desduplica mensagens rejeitadas por SPF/DKIM para impedir spam de log e ignora mensagens de caixa de correio auto-enviadas. WeCom analisa mensagens de entrada mistas corretamente. Cada um individualmente pequeno; juntos, eles significam menos momentos do tipo "por que meu bot fez isso". (#3329, #3355, #3280, #3171, #3325, #3228, #3161)
  • **WebUI - visualização antecipada, apenas fonte ** - Um webui/ dedicado chegou ao repositório com um fluxo de bate-papo WebSocket, alternador de localidade i18n, tipografia inspirada na Apple com suporte CJK e tema de bloco de código em modo escuro ao vivo. O canal WebSocket subjacente também aprendeu a multiplexar vários chat_ids em uma única conexão. Atenção: esta é apenas uma visualização do código-fonte - o WebUI ainda não foi incluído intencionalmente no wheel publicado. Se você quiser experimentá-lo, clone o repositório e execute-o a partir de webui/. Um lançamento empacotado ocorrerá assim que o UX for resolvido. (#3310, #3272, #3314, #3306)

Extração de documentos nativos do Office de @aiguozhi123456. Gravações atômicas de sessão do mesmo autor, capturando um caso real de perda de dados. Ele mantém sua história mesmo quando a energia pisca. E há uma UI tomando forma no webui/ para quem quiser dar uma espiada. Isso é um pós-lançamento fazendo trabalho pós-lançamento – e muito mais.

nanobot v0.1.5.post2

🐈 nanobot v0.1.5.post2 is here 🎉 — 67 PRs merged, 12 new contributors. The agent's world got bigger and steadier.

If v0.1.5.post1 was about the agent learning to manage itself, v0.1.5.post2 is about reach and polish. Windows and Python 3.14 joined the supported matrix. The read_file tool learned to understand DOCX, XLSX, and PPTX. Microsoft Teams arrived as a channel. The OpenAI-compatible API started streaming via SSE. And beneath all of that, ~50 smaller fixes across cron, memory, retry, session files, and provider quirks kept turning "it works" into "it's solid." A dedicated browser UI also started taking shape in the repo — source preview for now.

Highlights

  • Windows + Python 3.14 — first-class support — A full CI matrix covering Windows runners and Python 3.14 landed, along with install markers and runtime fixes for the quirks those platforms expose. If you've been running nanobot on WSL because "Windows didn't quite work," you can stop. (#3194)

  • Office documents, natively readable — The read_file tool now extracts text from DOCX, XLSX, and PPTX — tables and grouped shapes included, workbook handles closed safely. Combined with the earlier PDF support, the agent can open whatever format your colleague just emailed you without bouncing through a converter. (#3336, #3269, #3353)

  • OpenAI-compatible API — SSE streaming — /v1/chat/completions now emits SSE chunks when stream=true, wiring up the existing on_stream / on_stream_end callbacks. Any client built for the OpenAI API — LangChain, LlamaIndex, your own frontend — gets live deltas from nanobot instead of waiting for the whole response. The endpoint also stopped terminating streams with a success marker after a backend failure, so errors surface honestly. (#3222, #3262)

  • Microsoft Teams, MiniMax thinking, LM Studio, MyTool — Microsoft Teams joined the channel roster. MiniMax got a dedicated Anthropic-style thinking endpoint plus a reasoning_effort → reasoning_split mapping fix. LM Studio is now supported via nullable API keys for local servers that don't expect one. The new MyTool lets the agent introspect its own runtime configuration — and hides sensitive nested config fields in check output so self-inspection doesn't leak secrets. (#3197, #3160, #3363, #3186, #3177, #3261)

  • Reliability — the unglamorous half of a release — Session files now use atomic writes with corrupt-file repair, so a bad shutdown no longer eats your history. Memory cursor recovery handles non-integer corruption. Auto-compact skips sessions with active tasks and unifies summary injection across consolidation paths. Providers gain a circuit breaker for Responses API fallback and recognize ZhiPu 1302 rate limits. Cron stops leaking intermediate progress, its tool schema works with OpenAI Codex/Responses, and retry heartbeats no longer spill into user channels. Subagent follow-ups persist in session history. Half of these you'll never notice — which is exactly the point. (#3312, #3340, #3081, #3304, #3302, #3356, #3320, #3295, #3229, #3242)

  • Channels — quieter and sharper — Telegram gained mid-stream splitting for long replies and better markdown rendering for modern LLM output. Discord stopped treating bot-to-bot messages as self-loops and added channel-based allow-lists. Email deduplicates SPF/DKIM-rejected messages to stop log spam and ignores self-sent mailbox messages. WeCom parses mixed inbound messages correctly. Each individually small; together they mean fewer "why did my bot do that" moments. (#3329, #3355, #3280, #3171, #3325, #3228, #3161)

  • WebUI — early preview, source only — A dedicated webui/ has landed in the repo with a WebSocket chat flow, i18n locale switcher, Apple-inspired typography with CJK support, and live dark-mode code-block theming. The underlying WebSocket channel also learned to multiplex multiple chat_ids over a single connection. Heads up: this is source-preview only — the WebUI is intentionally not bundled into the published wheel yet. If you want to try it, clone the repo and run it from webui/. A packaged release will follow once the UX settles. (#3310, #3272, #3314, #3306)

Community

v0.1.5.post2 is what a release looks like when the foundation is done and people start finishing things. A Windows CI matrix from @JiajunBernoulli. Native Office document extraction from @aiguozhi123456. Session atomic writes from the same author, catching a real data-loss edge case. A Telegram mid-stream split that makes long replies actually readable. Twelve new contributors, and a lot of returning ones quietly landing the things that were on everyone's wish list. The agent runs on Windows. It reads your documents. It keeps its history even when the power blinks. And there's a UI taking shape in webui/ for whoever wants to peek. That's a post release doing post-release work — and then some.
