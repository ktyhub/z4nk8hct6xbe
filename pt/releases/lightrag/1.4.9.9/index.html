LightRAG v1.4.9.9

#Release Note V1.4.9.9

Notas importantes

  • Adicionar isolamento de espaço de trabalho para status de pipeline e armazenamento na memória: Várias instâncias LightRAG com espaços de trabalho distintos podem ser criadas simultaneamente, marcando um avanço significativo em direção à alternância perfeita de espaço de trabalho em um único servidor LightRAG.
  • Adicionar isolamento de dados vetoriais de espaço de trabalho por nome de modelo e dimensão para PostgreSQL e Qdrant: Anteriormente, LightRAG usava uma única coleção/tabela para incorporação de modelo e dimensão diferente, o que causava falhas de incompatibilidade de dimensão ou poluição de dados em vários espaços de trabalho.
  • A seleção de dimensão é compatível com OpenAI e Gemini Modelo de incorporação com nova variável de ambiente introduzida: EMBEDDING_SEND_DIM
  • Adicionar ferramentas de migração de cache LLM e limpeza de cache de consulta LLM entre diferentes armazenamentos KV: permitindo que os usuários alternem back-ends de armazenamento sem perder extração em cache e dados de resumo.
  • Extração DOCX aprimorada aprimorada com suporte para conteúdo de tabela **.
  • Extração XLSX aprimorada com manuseio adequado de caracteres tab e newline dentro das células.
  • Corrigir vulnerabilidade crítica de segurança nos componentes do React Server: #2494
  • Adicionar suporte de truncamento automático de texto para funções de incorporação: a função de incorporação OpenAI agora respeita o valor max_token_size em EmbeddingFunc e truncamento automático de texto de entrada para evitar erros API causados por textos que excedem os limites de token do modelo.

What's Breaking (apenas para integração LightRAG Core)

  • Renomear parâmetros da função de chunking: Se você incorporar a função de chunking no LightRAG e passar os parâmetros por nome, serão necessárias atualizações de código correspondentes.

    tokenizer: Tokenizer,
    content: str,
    split_by_character: str | None = None,
    split_by_character_only: bool = False,

@wrap_embedding_func_with_attrs(

)
@retry(
    stop=stop_after_attempt(3),
    wait=wait_exponential(multiplier=1, min=4, max=60),
    retry=(
        retry_if_exception_type(RateLimitError)
        | retry_if_exception_type(APIConnectionError)
        | retry_if_exception_type(APITimeoutError)
    ),
)
async def embedding_func(texts: list[str]) -> np.ndarray:
    client = AzureOpenAI(
        api_key=AZURE_OPENAI_API_KEY,
        api_version=AZURE_EMBEDDING_API_VERSION,
        azure_endpoint=AZURE_OPENAI_ENDPOINT,
    )
    embedding = client.embeddings.create(model=AZURE_EMBEDDING_DEPLOYMENT, input=texts)

    embeddings = [item.embedding for item in embedding.data]
    return np.array(embeddings)

LightRAG v1.4.9.9

Highlights

  • Workspace and model isolation — Pipeline status and in-memory state are now workspace-scoped, while PostgreSQL/Qdrant vector storage isolates data by embedding model and dimension to prevent cross-workspace pollution and dimension-mismatch crashes (#2369, #2391, #2513). Existing stores are migrated automatically; set model_name through wrap_embedding_func_with_attrs to use model-suffixed tables, while functions without it remain on legacy unsuffixed tables.
  • Core integration migrations — Direct LightRAG integrations face breaking changes: chunking_by_token_size parameters were renamed (#2379), so update callers passing arguments by name. Wrap custom embedding functions exactly once with embedding_dim, max_token_size, and model_name metadata; nested wrapping is also fixed (#2522). Custom chunkers can now be asynchronous, avoiding blocking during expensive chunking (#2336).
  • Embedding dimensions and token limits — EMBEDDING_SEND_DIM adds configurable dimensions for OpenAI and Gemini, while dimension validation and automatic OpenAI input truncation prevent invalid vectors and token-limit API failures (#2328, #2329, #2368, #2523). Changing model or dimension selects an isolated vector namespace, so treat it as a migration/re-embedding decision rather than a drop-in setting change.
  • Cache portability and prompt caching — New KV migration and LLM query-cache cleanup tools let you transfer cached extraction and summary data between storage backends and remove stale query hits (#2330, #2335). Run migration before switching backends; restructured entity-extraction prompts also improve OpenAI prompt-cache reuse, reducing repeated extraction costs (#2426).
  • Structured document extraction — DOCX ingestion now includes table content, and XLSX handling preserves tabs/newlines and escapes special characters (#2383, #2386), making structured data available to retrieval. Re-ingest existing documents to benefit, and expect chunk text—and therefore embeddings—to change.
  • Security and startup hardening — React 19.2.1 addresses the React Server Components vulnerability (#2494). The API server can now start without built WebUI assets and initializes configuration lazily (#2418, #2351), while uploads no longer block on dependency installation (#2350), improving headless and container deployments.

Release Note V1.4.9.9

Important Notes

  • Add Workspace Isolation for Pipeline Status and In-memory Storage: Multiple LightRAG instances with distinct workspaces can be created simultaneously, marking a significant advancement toward seamless workspace switching within a single LightRAG server.

  • Add Workspace Vector Data Isolation by Model Name and Dimension for PostgreSQL and Qdrant: Previously, LightRAG used a single collection/table for difference embedding model and dimension, which caused dimension mismatch crashes or data pollution in multi-workspace.

  • Dimension Selection is Supported for OpenAI and Gemini Embedding model with new env var introduced: EMBEDDING_SEND_DIM

  • Add LLM Cache Migration and LLM Query Cache Cleanup Tools Between Different KV Storage: enabling users to switch storage backends without losing cached extraction and summary data.

  • Enhanced Enhanced DOCX Extraction with Table Content Support.

  • Enhanced XLSX extraction with proper handling of tab and newline characters within cells.

  • Fix Critical Security Vulnerability in React Server Components: #2494

  • Add Automatic Text Truncation Support for Embedding Functions: OpenAI embedding function now respect max_token_size value in EmbeddingFunc, and automatic truncate input text to prevent API errors caused by texts exceeding model token limits.

What's Breaking (for LightRAG Core integration only)

  • Rename params of chunking function: If you incorporate the chunking function into LightRAG and pass parameters by name, corresponding code updates are required.
