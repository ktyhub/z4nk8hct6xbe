LightRAG v1.1.6

Highlights

  • Storage backend expansion — Qdrant joins as a first-class backend and MongoGraphStorage can now be enabled straight from config (#738), with MongoDocStatusStorage (#751) and API-side datastore selection (#744) rounding out the set. For adopters this means you can run the graph, vector, and doc-status layers on MongoDB/Qdrant instead of defaulting to the bundled stores — check that your chosen combination is coherently configured, since mixing backends across layers is now possible and easy to get subtly wrong.

  • Namespace key layout changed — storage namespaces now get a prefix (#729) with refined handling (#732). This is the quiet gotcha of the release: namespace prefixes alter how keys are arranged in your backend, so anyone upgrading an existing instance with persisted data should verify their namespace configuration before restart rather than assuming transparent compatibility.

  • Provider plumbing reworked — Ollama was split into its own module (#717) and its .env loading bug fixed (#719), Gemini is now integrated as a client (#750), and LiteLLM proxying works through embedding_binding_host (#771). If you rely on Ollama or proxy-hosted embeddings, re-check your env/config after upgrade — the Ollama fix in particular means previously ignored .env settings will now actually take effect.

  • Deployment and startup changes require action — startup scripts and service files were renamed for clarity (#728), and Docker images no longer bake in .env; it must be mounted as a volume in docker-compose.yml (#759). These are migration steps, not cosmetic: custom systemd units, startup wrappers, or compose files referencing old paths/secrets will break until updated.

  • API server hardening and async behavior — keyword_extraction is now accepted by the LLM function (#720) and error handling was broadly improved (#712, #723), but note that CLI document scanning was moved to a background task (#766). Scripts that assumed synchronous scan completion need to switch to polling/pipeline status instead of relying on an immediate return.

  • Stability and quality-of-life fixes — reasoning-model output can be trimmed (#724), a classic mutable-default-parameter bug is fixed (#722), Neo4j's MAX_CONNECTION_POOL_SIZE is now honored (#764), Postgres uses partial updates for doc status (#741), and the graph viewer gets a web UI plus a macOS file-dialog crash fix (#737, #718). Combined with insert/delete corrections (#754, #769) and pipeline/parallelism work (#734, #739, #768), this reads as a consolidation release — worthwhile for anyone on 1.1.5 who has been hitting edge-case runtime errors.
