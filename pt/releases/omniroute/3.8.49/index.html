OmniRoute v3.8.49

Highlights

  • Multimodal gateway expansion — OmniRoute now routes embeddings, batch/async speech-to-text, TTS, image generation, and video generation—not just chat. Additions include OpenRouter embeddings, Mixedbread, Speechmatics/Gladia/Rev AI, gTTS/EdgeTTS/Fish Audio, and Segmind/Freepik/Novita/DeepInfra. This enables consolidated non-chat workloads, but note that Speechmatics v1 is batch-only and several web-based providers are unofficial or rate-limited (#6994, #6656, #6659, #6660, #6667, #6668, #8164).

  • More controllable context compression — The new omniglyph engine renders prompts, tool documentation, and history as PNG pages, with measured 59–70% end-to-end token reduction, but remains preview-only, off by default, and restricted to Claude Fable 5 through the direct Anthropic route. Model-aware tokenizers, a Responses tool-output engine, per-model/endpoint exclusions, and Headroom’s nested-array codec give operators finer control; validate output quality before enabling image-based compression for agent workflows (#6556, #6661, #6837, #8009, #8010, #8064).

  • Routing and quota observability — Every completion now carries X-OmniRoute-Decision with strategy, provider, and latency; relay fallbacks expose X-Routing-Fallback-Reason; and /api/usage/model-latency-stats provides p50/p95/p99, success rate, TTFT, end-to-end latency, and tokens-per-second. OpenRouter quota tracking also puts credit-exhausted connections into cooldown on 402 instead of immediately reselecting the same key—making routing failures diagnosable without server-log access (#7765, #7262, #7218, #7635, #6842).

  • Changed overload behavior — Request-queue admission control adds opt-in maxQueueDepth (0 remains disabled) and typed RATE_LIMIT_QUEUE_FULL rejections, while the default maximum queue wait drops from 120 seconds to 15 seconds. Expect faster failures under saturation and tune client retry/backoff behavior accordingly. Per-model header timeouts, all-provider session affinity, and prompt-cache affinity also change which connection serves repeated requests (#7649, #7632, #7650, #8008).

  • Deployment changes requiring action — The live-dashboard WebSocket server now auto-starts in-process and defaults to port 20132, previously 20129; update reverse proxies, firewall rules, and dashboards accordingly. Replace OMNIROUTE_DISABLE_LIVE_WS with OMNIROUTE_ENABLE_LIVE_WS—enabled by default—and expect the WS path to follow NEXT_PUBLIC_LIVE_WS_PUBLIC_URL, falling back to /live-ws. Bun’s bundled SQLite runtime is now supported, avoiding a native better-sqlite3 build on Bun deployments (#6072, #7878).

  • Security controls and provider removals — OIDC can now gate dashboard administrator login while preserving password fallback. omniroute auth export --force emits decrypted plaintext credentials, with --out files written as 0600; MITM root-CA trust remains opt-in through MITM_ROOT_CA_ENABLED=true. The defunct glhf, kluster, cablyai, and inclusionai providers are removed, so migrate any dependent connections before upgrading (#6973, #6683, #6684, #6675).
