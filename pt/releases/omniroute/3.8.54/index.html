OmniRoute v3.8.54

Highlights

  • Official ChatGPT sign-in and broader provider coverage — The new chatgpt provider does dynamic registration with PKCE, live model discovery, and inference through the public Responses API with earliest_refresh_at-based refresh; it is deliberately separate from codex and chatgpt-web, routes fail closed to the registration that advertises a model, and its catalog never inherits Cursor auto* aliases (#15201). Alongside it: MiniMax Code (managed gateway + device-code sign-in), Microsoft 365 Copilot work/school auth, GitHub Copilot embeddings, and a native opencode-server executor for opencode serve that speaks only the v1 server API and rejects a 2.x server with a clear error instead of treating it as healthy (#16995). Net effect: fewer hand-rolled OAuth integrations, but check any automation keyed to the old alias behavior before flipping traffic.

  • Smarter combo routing, plus one behavior change to watch — Endpoint-specific combo routes (chat, search/fetch, embeddings, rerank, images, video, music, OCR, audio) land with two new strategies: jev and expiry-first. jev spends one TypeSafe System One choice call to admit a winner plus up to 4 fallbacks (confidence ≥ 0.15), falls open to your own provider order on missing key/timeout/low confidence, and sends the latest user message to TypeSafe — so it is gated behind COMBO_JEV_STRATEGY_ENABLED (default off) (#15279). Watch-out: typesafe is now decisions-only, so a chat request routed to it fails fast with HTTP 400 pointing at POST /v1/systemone instead of silently falling through to the OpenAI-compatible default executor using the TypeSafe key (#14498, #13987); re-point any route that relied on that fallthrough.

  • Key-level budgets, usage telemetry, and self-service APIs — /v1/me/status now returns today/this-week USD, request and token usage, a limits[] entry per per-key limit on its own enforcement window, masked account labels and cache-first accountQuotas, and it accepts x-api-key (#14771). New /v1/me/sessions lists agent sessions with project/client/date/sort filters (#14840), requests are attributed to coding-agent sessions and projects (#14833), and a rolling 5-hour USD budget plus reusable key-policy templates and POST /api/keys/import round out the key story. Note the new per-key anthropicRateLimitHeaders mode (auto/forward/strip): auto preserves legacy forwarding only for keys pinned to a single shared connection, so pooled-account Anthropic identity/quota headers may stop reaching clients (#14862).

  • Agentic pipelines: loop detection and context compaction — Native-protocol pipelines now detect repeated tool rounds with unchanged, call-matched results and consecutive failed rounds, handing control back to the planner without falsely halting on ambiguous parallel rounds (#15420, #19318). Opt-in context compaction applies per-model character budgets to the planner and each executor fallback while preserving instructions and tool boundaries (#15421, #19317). Operationally, STREAM_READINESS_TIMEOUT now names the failure shape, and large bodies to api.anthropic.com are gzip-compressed like Claude Code. Both features are opt-in, so existing pipelines keep their behavior until enabled.

  • Privacy and media controls remain default-off — A reversible PII token vault is available but requires PII_REDACTION_ENABLED; Video Bridge frame drill-down publishes derived JPEG frames only with explicit operator and per-part consent via tenant-bound, bounded opaque handles, keeps raw videos out of retention, and stays off pending real-model evidence (#16074); image normalization before dispatch is also opt-in. Good news for regulated deployments, but none of these are on by default — confirm compliance posture did not change silently.

  • Distribution and upgrade mechanics — Docker images are now also published to cheaperinference/omniroute and GHCR, Electron auto-update is served from cheaper-inference/OmniRoute, migration names are timestamped, and the omni-queue merge queue runs in shadow mode. Derived counts (locales, facts) are refreshed only at release via npm run facts / release:refresh-derived. If you pin images or mirror artifacts, update your references; otherwise this is a runtime no-op.

No breaking changes.
