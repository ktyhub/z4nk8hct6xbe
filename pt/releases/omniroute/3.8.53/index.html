OmniRoute v3.8.53

Highlights

  • Keak UI Kit replaces the old dashboard identity — KEA-7886: the dashboard and standalone pages (login, status, error, legal, docs) now run on a vendored packages/ui-kit pinned to an upstream commit, guarded byte-for-byte by npm run check:ui-kit-snapshot (lime accent, self-hosted Inter / Instrument Serif / IBM Plex Mono). Expect a wholesale visual change; anyone with custom CSS or forked pages should treat this as a migration point, and the snapshot check will fail CI if the vendored kit drifts.

  • Microsoft Entra ID tokens replace static keys on /v1/* — Claude Code (and any client) can authenticate with an Entra token; security groups map onto existing OmniRoute key groups for model allow/deny, while budgets and rate limits stay per-key and unaffected by group membership. A dependency-free scripts/cli/omniroute-sso.mjs sign-in helper ships for Claude Code. Separately, GitHub Copilot connections (#12833) now persist plan / model-selection mode / quota state and route Free / Student accounts to the catalog auto model — verify if you depended on explicit model selection for those accounts.

  • Routing becomes observable and controllable over the API — GET /v1/models/health now reports per-key pause state (#16247) and whether reasoning_effort: none was actually honored (#16253); /v1/models publishes the routable auto and auto/lkgp ids with pool limits (#16224); OTel spans gain omniroute.api_key.id and gen_ai.usage.cost/.currency, with the stream event emitted only once cost lookup lands (#14736). These close long-standing blind spots for multi-account pools and reasoning-tier routing — note, though, that the stream event now waits on cost lookup (null on failure), which can shift its timing.

  • Quota-aware failover goes granular, mostly opt-in — per-API-key ordered preferredConnections (#13102) pin a primary account with quota/cooldown-aware fallback without touching global connection priority. Two guards ship OFF by default: OMNIROUTE_AVALANCHE_PROTECTION_ENABLED=true stops a tokens-per-minute 429 from cascading across a provider's remaining keys and shortens model-lockout cooldown (#15775), and OMNIROUTE_AGENTIC_STALL_FAILOVER=1 fails over a combo member that ends a tool-result turn with finish: stop and no tool call (#13954). Both change when requests fail over and which answer wins, so evaluate before enabling.

  • Three request-path behavior changes to watch — the Bifrost sidecar fast-path (#12953) now handles /v1/chat/completions and /v1/messages directly (API-key policy first, never relaying echoed credential/cookie headers) and falls back to native on 5xx, network errors, or unsupported endpoints; opt-in quota recovery (x-omniroute-quota-recovery: auto, #14982) parks terminal-quota turns encrypted for 24h and exposes them at GET /api/v1/quota-recoveries/{id}; and UNPRICED_USAGE_BUDGET_POLICY (#14608) keeps fail_closed as default but a key blocked only by unpriced usage now gets a 400 naming the unpriced models instead of a misleading quota percentage. Watch for altered latency/failure characteristics on the fast path and the new 400 body shape in clients that parse quota errors.

  • bun:release adds a bun-first packaging path — npm run bun:release (scripts/release/bun-pack.mjs, #12801) packs the already-built dist/ into an npm-compatible tarball via bun pm pack (falling back to npm pack) for bun-based global installs, while the Next.js build and prepublish step stay on Node. Useful if you distribute global installs, but don't expect the build itself to move to bun yet.

No breaking API changes; nearly all new behavior is opt-in flags/env vars defaulting OFF (one known issue: some apiRegionLabel / apiRegionInternational strings stay in English until v3.8.54).
