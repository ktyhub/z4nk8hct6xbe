OmniRoute v3.8.48

Highlights

  • Hotfix: 3.8.48 is the first installable release of the v3.8.47 cycle — The published 3.8.47 package crashed on every boot with ERR_MODULE_NOT_FOUND because dist/head-response-guard.cjs fell out of the npm prepublish allowlist — the third recurrence of this class after tls-options/3.8.41 (#7065, #7040). The fix not only re-adds the file but enforces it via check:pack-artifact plus a closure test over every server-ws.mjs sibling import, so treat that check as the real release gate rather than a formality. Desktop adopters on Windows also need this build: the better-sqlite3 Electron-ABI rebuild now spawns npx.cmd through a shell because Node's CVE-2024-27980 hardening broke shell-less spawn on Windows runners. Pin to 3.8.48; do not deploy 3.8.47.

  • Routing and spend controls become explicit rather than silent — X-OmniRoute-Budget-Fallback: strict (or config.budgetFallback: "strict") makes an over-budget auto/* combo fail fast with HTTP 402 instead of quietly falling back to the cheapest candidate that could still breach the cap (#3470); the default cheapest preserves old behavior, so opt in if you need a hard cap. Alongside it: per-model web-search/web-fetch interception (#6814), config-driven per-provider/model param denylist/allowlist that auto-learns from upstream 400s (#6649/#6625), combo context requirements (#6907), and a providerStrategies override plus combo-level sticky round-robin so targets batch calls the way account fallback already does (#6678). Watch the resolution order — per-combo → global combo sticky → account sticky — when diagnosing surprising target selection.

  • Chaos Mode turns one prompt into a multi-model fan-out — A new opt-in engine dispatches a task to every active provider connection in parallel or chains outputs sequentially for collaborative refinement, configured under Dashboard → Chaos Mode with a new chaosModeEnabled permission gated per API key and disabled by default both globally and per key (#6728). It runs in-process via the established synthetic-Request/route-handler pattern (no network hop or hardcoded port), caps parallelism at 10, and rejects stream requests explicitly. Before enabling, audit key permissions: with the external Bearer-token route POST /api/skills/collect/chaos and the config-cache leak fixed, this is a genuine cost multiplier when switched on.

  • Auth and bulk import converge on enterprise/9router parity — Codex imports now accept 9router's camelCase export (accessToken/refreshToken/idToken/expiresAt plus nested providerSpecificData), normalized onto the existing snake_case keys only when absent so snake_case and mixed exports keep working (#6665). Kiro/Amazon Q gains External IdP refresh for org-issued tokens through the IdP's own tokenEndpoint (SSRF-guarded to an HTTPS known-IdP-host allowlist) (#6363) and long-lived API-key linking with live model discovery (#6587); ClinePass now offers both OAuth and BYOK under the aligned alias cp (#6126). Skill Collector moves from a standalone Python app to GET /api/skills/collect/detect + POST /install, management-auth and loopback-gated because detection spawns a child process per CLI, and the MCP tool now honestly reports action: "planned" (#6294) — any consumer parsing that field must update.

  • Observability, providers, and release ergonomics widen the surface — Langfuse tracing plugin (#6577), OpenVecta inference gateway (#6833), and native xAI /v1/responses routing (#6709) expand where traffic and telemetry can go; icons now resolve local SVGs first through a 5-tier fallback, replacing LobeHub-first (#6317), and zh-TW localization lands for both UI and CLI (#6320). On the contributor side, changelog.d/ fragments end the CHANGELOG merge-storm (#6783) and validate-release-green --full-ci reproduces the whole static CI gate locally (#6583), while the Sonar gate is informational until the org plan supports the tuned threshold. Snapshot tests asserting icon URLs may need updating.

  • Breaking changes — None declared; the behavioral changes above are additive, opt-in, or bug fixes, and defaults preserve existing behavior.
