OmniRoute v3.8.39

✨ Novos recursos

  • feat(oauth): login remoto do Antigravity via ajudante local + colar credenciais — Antigravity (e outros provedores OAuth "nativos/desktop" do Google) usam o consentimento firstparty/nativeapp do Google, que só libera o código de autenticação quando o redirecionamento de loopback (127.0.0.1:<port>) é acessível a partir do navegador aprovador. Em uma instalação VPS remota, esse loopback reside no servidor, portanto, o consentimento fica suspenso para sempre e nunca emite um código - o substituto "colar o URL de retorno de chamada" não tem nada para colar (uma restrição do lado do Google, idêntica no 9router upstream). Um novo auxiliar omniroute login antigravity CLI executa o OAuth na própria máquina do usuário (onde 127.0.0.1 funciona), troca o código e imprime um blob de credencial omniroute-cred-v1.… de linha única; o campo Antigravity Connect → Etapa 2 do painel agora aceita esse blob (junto com URLs de retorno de chamada) e persiste a conexão por meio de uma nova ação paste-credentials (integração do lado do servidor, lista de permissões do provedor, com o provedor incorporado do blob necessário para corresponder à rota). O túnel SSH local-forward está documentado como uma alternativa sem ferramentas. Consulte docs/guides/REMOTE-MODE.md. (#5203)
  • feat(agent-bridge): fallback de instalação de certificado elegante para contêineres / headless — quando a CA raiz MITM não pode ser instalada no armazenamento trust do sistema automaticamente (Docker / headless / sem sudo / armazenamento trust somente leitura), o Agent Bridge não falha mais na inicialização com um genérico "Falha na instalação do certificado". Agora ele inicia no modo ignorar e o painel apresenta um guia de instalação manual específico da plataforma (além de um link de download da CA) para que o operador possa trust o certificado manualmente. Os endpoints trust-cert retornam uma resposta { skippable, manualGuide } estruturada (HTTP 200) para falhas de ambiente em vez de 500; um cancelamento explícito do usuário ainda é relatado de forma distinta. (#4546 — obrigado @phuchptty)
  • feat(compressão): recuperação CCR de intervalo/grep/stats (reDoS-safe, compatibilidade com versões anteriores) — estende a ferramenta omniroute_ccr_retrieve MCP e o endpoint /api/compression/retrieve com parâmetros opcionais range (fatia de byte/linha), grep (correspondência literal ou de padrão limitado segura para ReDoS contra linhas armazenadas) e stats (contagens de bytes/linhas/palavras) para que os agentes extraiam exatamente a fatia ou resumo que precisam em vez de expandir novamente todo o bloco armazenado. Todos os parâmetros são opcionais - nenhum parâmetro retorna o byte completo do bloco idêntico ao comportamento existente; o armazenamento CCR escrito por ionizador/fuzzy/headroom é totalmente compatível. Sexto item do roteiro de compressão. (#5187)
  • feat(compressão): codificador candidato TOON best-of-N + tabela A/B do codificador — adiciona @toon-format/toon como um codificador candidato no mecanismo de compressão de headroom por meio de um esquema best-of-N: tanto GCF quanto TOON são executados por prompt e o resultado mais curto é mantido, em vez de codificadores de hard-swapping (GCF já codifica o bloco headroom e TOON não é uma vitória universal sem perdas). Uma tabela de comparação A/B do codificador (GCF vs TOON vs JSON — bytes e tokens cl100k) agora aparece no estúdio de compressão. Quinto item do roteiro de extração de recursos de compressão (bancada: #5080, porta: #5127, fuzzy/gate: #5143, ionizador: #5148). (#5163)

🔧 Correções de bugs

  • correção (oauth): a atualização antigravidade não anula mais o update_token armazenado em uma resposta upstream vazia — O endpoint do token OAuth do Google usa tokens de atualização não rotativos: uma resposta de atualização normalmente OMITE refresh_token e ocasionalmente o retorna como uma string vazia. O refreshCredentials do executor de Antigravidade usou typeof tokens.refresh_token === "string" ? tokens.refresh_token : credentials.refreshToken e, como typeof "" === "string" é verdadeiro, uma resposta de string vazia substituiu o token bom por "" - anulando-o na primeira atualização. A verificação agora trata um valor não-string ou vazio como ausente e preserva o token armazenado, correspondendo à semântica canônica refreshGoogleToken (tokens.refresh_token || refreshToken). (#3850 — obrigado @3xa228148)
  • correção (api): acesso ao painel LAN/Tailscale — esquema CSP ws:, rota de versão isenta de GET, erros de campo de combinação de superfície — três falhas ao abrir o painel a partir de um host sem loopback: (1) CSP connect-src permitiu o esquema ws: apenas para origens de loopback, bloqueando o ws://<lan-host>:* Live WebSocket do painel de LAN/Tailscale clients; o esquema ws: simples agora é permitido (simétrico com o wss: simples já permitido), mantido declarativo em next.config.mjs sem middleware global (o projeto não possui nenhum por design); (2) GET /api/system/version foi bloqueado por LOCAL_ONLY_API_PREFIXES para todos os métodos, apesar de apenas POST gerar processos filhos (git/npm/pm2) — um novo conjunto LOCAL_ONLY_API_GET_EXEMPTIONS isenta métodos de leitura seguros para este caminho, mantendo POST/PUT/PATCH/DELETE estritamente somente loopback; (3) Os erros de validação do COMBO_002 surgiram apenas na mensagem genérica - firstField/firstMessage agora são extraídos do primeiro problema do Zod e incluídos no corpo da resposta. (#5083 — obrigado @KooshaPari pelo diagnóstico e PR original #5084)
  • **correção (sse): adiar o fechamento de </think> para que nunca vaze antes de tool_calls no streaming de Claude → OpenAI ** - quando um bloco de pensamento de Claude foi seguido por um bloco tool_use, o tradutor emitiu incondicionalmente um pedaço content: "</think>" em content_block_stop, injetando um pedaço de texto assistente espúrio imediatamente antes do delta tool_calls e corrompendo clients compatíveis com OpenAI (por exemplo, codificação Kimi). O marcador de fechamento agora é adiado: ele é liberado no primeiro text_delta que segue o bloco de pensamento (preservando o comportamento #4633 / decolua/9router#454 para Claude Code / Cursor) ou no final do fluxo quando nenhuma tool_calls foi coletada. Os fluxos de uso de ferramentas nunca recebem um text_delta após o bloco de pensamento, portanto, </think> nunca é emitido no conteúdo antes de tool_calls. (#5123)
  • fix(sse): normaliza o conteúdo da mensagem do usuário da matriz no executor do código de comando para evitar upstream 400 - quando um client envia um turno de usuário cujo content é uma matriz de partes de conteúdo (por exemplo, [{type:"text",text:"…"}, …]), a matriz bruta foi encaminhada literalmente para o código de comando upstream, o que requer que messages[N].content para a função user seja uma string simples - resultando em expected string, received array/HTTP 400 no DeepSeek V4-Pro e outros modelos de código de comando. A ramificação do usuário de convertMessages agora chama normalizeContentText() (já usado pelas ramificações de sistema, assistente e ferramenta) para que o conteúdo do usuário multiparte seja unido a uma string antes do envio. Endereços parcialmente (#5166); o sintoma do token de saída 0 em modelos somente de raciocínio é rastreado separadamente.
  • correção (mcp): retorne HTTP 404 (não 400) para um ID de sessão HTTP Streamable desconhecido/expirado — quando uma sessão MCP é encerrada ou fica ociosa e o client reutiliza o cabeçalho Mcp-Session-Id obsoleto, o transporte HTTP Streamable responde com HTTP 400. A especificação MCP (2025-03-26 e 2025-11-25, Session Management) exige HTTP 404 Not Found nesse caso, e clients compatíveis com as especificações apenas reinicializam uma sessão em 404 - portanto, o 400 não era recuperável. O manipulador agora retorna 404 para um ID de sessão presente, mas desconhecido, enquanto um ID de sessão ausente em uma solicitação não inicializada permanece corretamente 400. (#5169 — obrigado @czer323)
  • correção (api): bloquear "Auto (Zero-Config)" nas configurações de segurança agora remove auto/* de /v1/models — o anunciante combinado auto/* integrado (#4164 / #4235) no topo do catálogo de modelos ignorou settings.blockedProviders, portanto, marcar Auto (Zero-Config) em Segurança → Provedores bloqueados não teve efeito e o seletor de modelo continuou listando todos Entrada auto/*. O loop de injeção agora ignora todo o bloco auto/* quando o provedor de sistema auto (seu id e alias são ambos auto) é bloqueado, consistente com a forma como todos os outros provedores são filtrados do catálogo. (#5192 — obrigado @WslzGmzs)
  • **correção (cli): calibra automaticamente o heap do servidor V8 a partir da RAM física em vez de um padrão fixo de 512 MB ** - o servidor foi gerado com um --max-old-space-size=512 codificado (omniroute serve) ou sem nenhum sinalizador de heap (desktop Electron, que então herdou o baixo padrão de ~ 512 MB do tempo de execução), então máquinas ricas em RAM ainda falharam sob carga (FATAL ERROR: Ineffective mark-compacts near heap limit … ~500MB em code=134) com muitos provedores/contas e grandes catálogos de modelos (um relatório: 16 GB de RAM, 65 provedores, aproximadamente 100 contas, aproximadamente 2.600 modelos). Um novo auxiliar calibrateHeapFallbackMb(os.totalmem()) deriva o heap padrão como ~35% da RAM física, fixado em [512, 4096] e conectado a bin/cli/commands/serve.mjs e electron/main.js. Um OMNIROUTE_MEMORY_MB explícito (ou um --max-old-space-size predefinido) ainda vence, portanto o contrato de substituição #2939 permanece inalterado. (#5172, #5160, #5152 — obrigado @manchairwang, @Xyzjesus)
  • **correção (oauth): o login do Antigravity não trava mais - ativação do tipo disparar e esquecer + pós-troca limitada ** - o login do Antigravity OAuth do painel girou indefinidamente porque postExchange aguardou o loop de nova tentativa do onboardUser inline (até 10 × 5 s por tentativa, cada busca sem tempo limite), bloqueando a resposta do /exchange para sempre. Correspondendo ao fluxo da web upstream do roteador 9: onboardUser agora executa disparar e esquecer em uma tarefa em segundo plano; o endpoint /exchange é limitado por um tempo limite máximo de 10 s, portanto sempre retorna; um endpoint de progresso permite que o painel pesquise o estado de conclusão da integração. (#5193)
  • correção (antigravidade): tente novamente contas Antigravity por família de cotas antes de escalar o combo — quando uma conta Antigravity retorna uma cota ou limite de taxa 429 para um modelo Gemini (por exemplo, gemini-3.5-flash-medium), a orquestração do combo pode avançar prematuramente para o próximo modelo combo em vez de tentar outras contas Antigravity elegíveis para a mesma família de cotas. O reconhecimento da família de cotas de antigravidade agora é adicionado ao caminho de fallback para que um 429 em uma conta acione uma nova tentativa limitada do mesmo modelo em outras contas de antigravidade que compartilham esse intervalo de cotas antes que o combo seja degradado para um modelo de nível inferior. (#5180 — obrigado @Ardem2025)
  • correção (tradutor): aceitar o formato de mensagens de Claude no guarda não-stream malformado-200 - quando um Claude client (por exemplo, código Claude) é roteado para um provedor não-Claude, o corpo de resposta não-stream traduzido está no formato de mensagens de Claude (type: "message", content[]) produzido por convertOpenAINonStreamingToClaude. detectMalformedNonStream reconheceu apenas OpenAI choices[].message e respostas API output[], então esta forma caiu para empty_choices → 502. O guarda agora reconhece a forma de mensagens de Claude: texto, uso de ferramenta e blocos de pensamento carregando uma contagem signature como saída válida, enquanto um content: [] genuinamente vazio ainda é sinalizado. (#5156 — obrigado @NomenAK)
  • **correção (sse): resolve blocos <tool> da deepseek-web sem nome por meio da correspondência de esquema de parâmetro ** - quando chat.deepseek.com emite um bloco <tool> sem filho <name>, sem chave name/type do corpo JSON e sem sufixo de tag, cada caminho de resolução de nome em extractCall retornou null e o XML bruto vazou para o client como texto simples. Um substituto conservador baseado em esquema agora compara os nomes dos parâmetros extraídos do bloco com as chaves de esquema de cada ferramenta declarada; se exatamente uma ferramenta corresponder, seu nome será usado. Correspondências zero ou ambíguas (>1) ainda retornam null, portanto nenhuma chamada é atribuída incorretamente. (#5154, #5173)
  • correção (stream): normalizar os motivos de conclusão de segurança do provedor para content_filter — Gemini e Antigravity podem retornar motivos de segurança/terminais proibidos (SAFETY, RECITATION, BLOCKLIST, PROHIBITED_CONTENT) que clients downstream compatíveis com OpenAI não reconhecem. Um auxiliar de normalização de motivo de término compartilhado agora os mapeia para o valor content_filter padrão, aplicado nos caminhos de streaming e de coleta JSON para ambos os provedores. (#5197 — obrigado @rdself)
  • correção (respostas): normalizar respostas não array API input antes do roteamento — as respostas OpenAI API aceitam input como uma string, objeto ou lista, mas o OmniRoute manipula apenas cargas úteis em formato de lista; uma string ou objeto input foi descartado silenciosamente no caminho Respostas → Conclusões de bate-papo. O tradutor agora normaliza input para uma lista antes do envio; o caminho de respostas nativas do Codex também normaliza antes do encaminhamento (evitando 400 Input must be a list upstream); e os caminhos de injeção imediata e extração do desinfetante PII são protegidos contra input com valor de objeto para que as verificações de segurança não sejam interrompidas. (#5204 — obrigado @wilsonicdev)
  • correção (zenmux): normaliza funções do sistema GLM prefixadas pelo fornecedor para modelos Z.AI — ZenMux expõe Z.AI GLM por meio de IDs compatíveis com OpenAI prefixadas pelo fornecedor, como z-ai/glm-5.2. A detecção GLM existente correspondia apenas aos ids glm-*/glm, portanto, zenmux/z-ai/glm-5.2 manteve as mensagens do sistema no lugar; Z.AI rejeita históricos compactados que terminam com uma virada do sistema antes das sequências assistant(tool_calls) → tool.   • correção (xai): adicionar sonda de teste de conexão OAuth + normalizar aliases de esforço de raciocínio xAI — xAI rejeita valores de esforço de raciocínio não suportados (max, xhigh) com HTTP 400 após uma atualização do provedor; o tradutor xAI agora mapeia max e xhigh para high antes de encaminhar. Além disso, as conexões xAI OAuth não tinham configuração de teste de painel, portanto, os testes do provedor retornaram "Provider test not supported"; uma sonda de teste OAuth dedicada agora está conectada para contas xAI com cobertura de regressão para a normalização do esforço.   • **consertar (servir): honrar HOSTNAME de .env em vez de codificar 0.0.0.0 ** - bin/cli/commands/serve.mjs espalhou process.env no ambiente de processo filho, mas imediatamente substituiu HOSTNAME por um "0.0.0.0" literal, descartando silenciosamente qualquer endereço de ligação configurado pelo usuário, embora HOSTNAME esteja documentado em .env.example e docs/reference/ENVIRONMENT.md. dist/server.js já leu process.env.HOSTNAME corretamente; apenas o wrapper CLI o estava substituindo.   • fix(auth): permite fallback sintético sem autenticação para mimocode — conexões mimocode sem credenciais explícitas foram bloqueadas antes de chegar ao executor.   • correção (combo): rejeitar respostas vazias API output: [] como um acionador de failover — um corpo API de respostas sem streaming com object: "response" e output: [] foi aceito como um HTTP 200 válido pelo validador de qualidade de resposta combinada, permitindo que um destino combinado pare em vez de fazer failover para a próxima etapa.   • correção (request-logger): nunca renderize uma porcentagem negativa no crachá de compactação — quando cada token de prompt foi compactado (totalIn = 0, compressed > 0), o comprimido de compactação exibia (-100%) porque o formato do crachá codificou um - inicial antes do valor percentual. OmniRoute v3.8.39

Highlights

  • Remote Antigravity onboarding is now viable on VPS/headless installs — Google's firstparty/nativeapp consent only releases the auth code to a reachable 127.0.0.1 loopback, so the old "paste the callback URL" fallback was useless on a remote server (the same constraint exists upstream in 9router). omniroute login antigravity now runs the flow on your own machine and prints a single-line omniroute-cred-v1.… blob that the dashboard accepts through a new provider-allowlisted paste-credentials action (#5203) — the blob's embedded provider must match the route's provider, so keep those in sync. Two companion fixes make it actually usable: onboarding runs fire-and-forget behind a 10 s /exchange timeout with a progress endpoint instead of hanging forever (#5193), and an empty refresh_token in Google's non-rotating refresh response no longer nulls the stored credential (#3850). An SSH local-forward tunnel remains the zero-tooling alternative (docs/guides/REMOTE-MODE.md).

  • MCP session and cert-install endpoints have new response contracts — A stale Mcp-Session-Id now returns HTTP 404 instead of 400 (#5169), which is spec-mandated (MCP 2025-03-26 / 2025-11-25) and practically important because spec-compliant clients only re-initialize on 404 — if you built retries around the old 400, update them; a genuinely missing session id on a non-initialize request still correctly returns 400. Agent Bridge also stops hard-failing when its MITM CA can't be auto-installed (Docker, headless, no sudo, read-only trust store): it starts in skip mode and the trust-cert endpoints now return HTTP 200 with { skippable, manualGuide } plus a CA download link instead of a 500 (#4546). Parse that new shape and surface the platform-specific manual-trust guide to operators; explicit user cancellation is still reported separately.

  • Compression adds targeted retrieval and a best-of-N encoder with no migration — omniroute_ccr_retrieve and /api/compression/retrieve gain optional range, grep (ReDoS-safe literal or bounded-pattern), and stats parameters, so agents can fetch a byte/line slice or counts instead of re-expanding an entire stored block (#5187). All parameters are optional and the no-parameter response is byte-identical to today's, with existing ionizer/fuzzy/headroom stores fully compatible. Headroom now runs both GCF and TOON per prompt and keeps the shorter result rather than hard-swapping encoders, backed by a GCF/TOON/JSON bytes-and-cl100k-tokens A/B table in the studio (#5163; bench #5080, gate #5127, fuzzy/gate #5143, ionizer #5148) — treat this as content-dependent savings, not a universal win.

  • Streaming and translator edge cases that broke real clients are fixed — In Claude→OpenAI streaming, </think> is now deferred to the first following text_delta (or stream finish), so it never leaks ahead of tool_calls and corrupts OpenAI-compatible consumers such as Kimi Coding, while preserving Claude Code/Cursor behavior (#5123). The non-stream malformed-200 guard recognizes Claude Messages shape, so type: "message" bodies with text, tool_use, or signed-thinking blocks no longer fall through to a spurious 502 (#5156); array-valued user content is normalized to a string before the Command Code upstream (#5166, partial); Responses API input given as a string or object is normalized to a list before routing (#5204); nameless deepseek-web <tool> blocks are resolved by unique parameter-schema match with ambiguous cases still left unresolved (#5154/#5173); and Gemini/Antigravity safety reasons map to standard content_filter (#5197). Downstream code should now expect content_filter rather than provider-specific terminal reasons.

  • The server's default V8 heap is now RAM-aware — The previous hard-coded --max-old-space-size=512 (CLI) and inherited ~512 MB runtime default (Electron) caused code-134 OOM crashes under large catalogs (one report: 16 GB RAM, 65 providers, ~100 accounts, ~2,600 models). calibrateHeapFallbackMb(os.totalmem()) now derives the default as ~35% of physical RAM clamped to [512, 4096] in both bin/cli/commands/serve.mjs and electron/main.js (#5172/#5160/#5152). An explicit OMNIROUTE_MEMORY_MB or a pre-set --max-old-space-size still wins, so pinned setups are unaffected — but if you added an override to work around the old ceiling, you can drop it and let the default scale.

  • Dashboard reachability, catalog filtering, and quota fallback all changed behavior — LAN/Tailscale dashboard access was broken in three ways: bare ws: was blocked by CSP outside loopback, GET /api/system/version was gated by the loopback-only prefix list despite being read-only, and COMBO_002 errors hid field detail. Now ws: is permitted declaratively in next.config.mjs, safe GETs are exempted while mutating methods stay loopback-only, and Zod firstField/firstMessage are returned (#5083). Blocking Auto (Zero-Config) under Security finally removes the auto/* block from /v1/models (#5192), so model pickers will shrink accordingly. Antigravity 429s now retry other accounts in the same quota family before degrading the combo to a lower-tier model (#5180) — expect fewer tier downgrades under quota pressure, at the cost of extra in-band retries.

No breaking changes in this release.

✨ New Features

  • feat(oauth): remote Antigravity login via local helper + paste-credentials — Antigravity (and other Google "native/desktop" OAuth providers) use Google's firstparty/nativeapp consent, which only releases the auth code when the loopback redirect (127.0.0.1:<port>) is reachable from the approving browser. On a remote VPS install that loopback lives on the server, so the consent hangs forever and never emits a code — the "paste the callback URL" fallback has nothing to paste (a Google-side constraint, identical in upstream 9router). A new omniroute login antigravity CLI helper runs the OAuth on the user's own machine (where 127.0.0.1 works), exchanges the code, and prints a single-line omniroute-cred-v1.… credential blob; the dashboard's Antigravity Connect → Step 2 field now accepts that blob (alongside callback URLs) and persists the connection via a new paste-credentials action (server-side onboarding, provider-allowlisted, with the blob's embedded provider required to match the route). The SSH local-forward tunnel is documented as a zero-tooling alternative. See docs/guides/REMOTE-MODE.md. (#5203)
  • feat(agent-bridge): graceful cert-install fallback for containers / headless — when the MITM root CA can't be installed into the system trust store automatically (Docker / headless / no sudo / read-only trust store), the Agent Bridge no longer hard-fails on start with a generic "Certificate install failed". It now starts in skip mode and the dashboard surfaces a platform-specific manual-install guide (plus a CA download link) so the operator can trust the certificate by hand. The trust-cert endpoints return a structured { skippable, manualGuide } response (HTTP 200) for environment failures instead of a 500; an explicit user cancellation is still reported distinctly. (#4546 — thanks @phuchptty)
  • feat(compression): CCR ranged/grep/stats retrieval (ReDoS-safe, backward-compat) — extends the omniroute_ccr_retrieve MCP tool and /api/compression/retrieve endpoint with optional range (byte/line slice), grep (ReDoS-safe literal or bounded-pattern match against stored lines), and stats (byte/line/word counts) parameters so agents pull exactly the slice or summary they need instead of re-expanding the entire stored block. All parameters are optional — no parameters returns the full block byte-identical to the existing behavior; the CCR store written by ionizer/fuzzy/headroom is fully compatible. Sixth item of the compression roadmap. (#5187)
  • feat(compression): TOON best-of-N candidate encoder + encoder A/B table — adds @toon-format/toon as a candidate encoder in the headroom compression engine via a best-of-N scheme: both GCF and TOON run per prompt and the shorter result is kept, rather than hard-swapping encoders (GCF already encodes the headroom block and TOON is not a lossless universal win). An encoder A/B comparison table (GCF vs TOON vs JSON — bytes and cl100k tokens) is now surfaced in the compression studio. Fifth item of the compression feature-extraction roadmap (bench: #5080, gate: #5127, fuzzy/gate: #5143, ionizer: #5148). (#5163)

🔧 Bug Fixes

  • fix(oauth): Antigravity refresh no longer nulls the stored refresh_token on an empty upstream response — Google's OAuth token endpoint uses non-rotating refresh tokens: a refresh response normally OMITS refresh_token and occasionally returns it as an empty string. The Antigravity executor's refreshCredentials used typeof tokens.refresh_token === "string" ? tokens.refresh_token : credentials.refreshToken, and because typeof "" === "string" is true, an empty-string response overwrote the good token with "" — nulling it on first refresh. The check now treats a non-string or empty value as absent and preserves the stored token, matching the canonical refreshGoogleToken (tokens.refresh_token || refreshToken) semantics. (#3850 — thanks @3xa228148)

  • fix(api): LAN/Tailscale dashboard access — ws: CSP scheme, GET-exempt version route, surface combo field errors — three failures when opening the dashboard from a non-loopback host: (1) CSP connect-src allowed the ws: scheme only for loopback origins, blocking the dashboard's ws://<lan-host>:* Live WebSocket from LAN/Tailscale clients; the bare ws: scheme is now permitted (symmetric with the bare wss: already allowed), kept declarative in next.config.mjs with no global middleware (the project has none by design); (2) GET /api/system/version was blocked by LOCAL_ONLY_API_PREFIXES for all methods despite only POST spawning child processes (git/npm/pm2) — a new LOCAL_ONLY_API_GET_EXEMPTIONS set exempts safe read methods for this path while keeping POST/PUT/PATCH/DELETE strictly loopback-only; (3) COMBO_002 validation errors only surfaced the generic message — firstField/firstMessage are now extracted from the first Zod issue and included in the response body. (#5083 — thanks @KooshaPari for the diagnosis and original PR #5084)

  • fix(sse): defer </think> close so it never leaks before tool_calls in Claude→OpenAI streaming — when a Claude thinking block was followed by a tool_use block, the translator unconditionally emitted a content: "</think>" chunk at content_block_stop, injecting a spurious assistant text chunk immediately before the tool_calls delta and corrupting OpenAI-compatible clients (e.g. Kimi Coding). The close marker is now deferred: it is flushed at the first text_delta that follows the thinking block (preserving the #4633 / decolua/9router#454 behavior for Claude Code / Cursor) or at stream finish when no tool_calls were collected. Tool-use streams never get a text_delta after the thinking block, so </think> is never emitted into content before tool_calls. (#5123)

  • fix(sse): normalize array user-message content in the Command Code executor to prevent upstream 400 — when a client sends a user turn whose content is an array of content parts (e.g. [{type:"text",text:"…"}, …]), the raw array was forwarded verbatim to the Command Code upstream, which requires messages[N].content for the user role to be a plain string — resulting in expected string, received array / HTTP 400 on DeepSeek V4-Pro and other Command Code models. The user branch of convertMessages now calls normalizeContentText() (already used by system, assistant, and tool branches) so multi-part user content is joined to a string before dispatch. Partially addresses (#5166); the 0-output-token symptom on reasoning-only models is tracked separately.

  • fix(mcp): return HTTP 404 (not 400) for an unknown/expired Streamable HTTP session id — when an MCP session is terminated or idles out and the client reuses the stale Mcp-Session-Id header, the Streamable HTTP transport replied with HTTP 400. The MCP spec (2025-03-26 and 2025-11-25, Session Management) mandates HTTP 404 Not Found in that case, and spec-compliant clients only re-initialize a session on 404 — so the 400 was non-recoverable. The handler now returns 404 for a present-but-unknown session id, while a missing session id on a non-initialize request correctly stays 400. (#5169 — thanks @czer323)

  • fix(api): blocking "Auto (Zero-Config)" in Security settings now removes auto/* from /v1/models — the built-in auto/* combo advertiser (#4164 / #4235) at the top of the models catalog ignored settings.blockedProviders, so checking Auto (Zero-Config) under Security → Blocked Providers had no effect and the model picker kept listing every auto/* entry. The injection loop now skips the entire auto/* block when the system provider auto (its id and alias are both auto) is blocked, consistent with how every other provider is filtered from the catalog. (#5192 — thanks @WslzGmzs)

  • fix(cli): auto-calibrate the server V8 heap from physical RAM instead of a fixed 512MB default — the server was spawned with a hard-coded --max-old-space-size=512 (omniroute serve) or with no heap flag at all (Electron desktop, which then inherited the runtime's low ~512MB default), so RAM-rich machines still OOM-crashed under load (FATAL ERROR: Ineffective mark-compacts near heap limit … ~500MB at code=134) with many providers/accounts and large model catalogs (one report: 16GB RAM, 65 providers, ~100 accounts, ~2600 models). A new calibrateHeapFallbackMb(os.totalmem()) helper derives the default heap as ~35% of physical RAM, clamped to [512, 4096], and is wired into both bin/cli/commands/serve.mjs and electron/main.js. An explicit OMNIROUTE_MEMORY_MB (or a pre-set --max-old-space-size) still wins, so the #2939 override contract is unchanged. (#5172, #5160, #5152 — thanks @manchairwang, @Xyzjesus)

  • fix(oauth): Antigravity login no longer hangs — fire-and-forget onboarding + bounded post-exchange — the dashboard's Antigravity OAuth login spun indefinitely because postExchange awaited the onboardUser retry loop inline (up to 10 × 5 s per attempt, each fetch with no timeout), blocking the /exchange response forever. Matching the upstream 9router web flow: onboardUser now runs fire-and-forget in a background task; the /exchange endpoint is bounded by a 10 s hard timeout so it always returns; a progress endpoint lets the dashboard poll onboarding completion state. (#5193)

  • fix(antigravity): retry Antigravity accounts by quota family before escalating the combo — when one Antigravity account returns a quota or rate-limit 429 for a Gemini model (e.g. gemini-3.5-flash-medium), combo orchestration could prematurely advance to the next combo model instead of trying other eligible Antigravity accounts for the same quota family. Antigravity quota-family awareness is now added to the fallback path so a 429 on one account triggers a bounded same-model retry across other Antigravity accounts sharing that quota bucket before the combo degrades to a lower-tier model. (#5180 — thanks @Ardem2025)

  • fix(translator): accept Claude Messages shape in the non-stream malformed-200 guard — when a Claude client (e.g. Claude Code) is routed to a non-Claude provider, the translated non-streaming response body is in Claude Messages shape (type: "message", content[]) produced by convertOpenAINonStreamingToClaude. detectMalformedNonStream only recognized OpenAI choices[].message and Responses API output[], so this shape fell through to empty_choices → 502. The guard now recognizes the Claude Messages shape: text, tool_use, and thinking blocks carrying a signature count as valid output, while a genuinely empty content: [] is still flagged. (#5156 — thanks @NomenAK)

  • fix(sse): resolve nameless deepseek-web <tool> blocks via parameter-schema match — when chat.deepseek.com emits a <tool> block with no <name> child, no JSON body name/type key, and no tag suffix, every name-resolution path in extractCall returned null and the raw XML leaked to the client as plain text. A conservative schema-based fallback now compares the block's extracted parameter names against each declared tool's schema keys; if exactly one tool matches, its name is used. Zero or ambiguous (>1) matches still return null so no calls are misattributed. (#5154, #5173)

  • fix(stream): normalize provider safety finish reasons to content_filter — Gemini and Antigravity can return safety/prohibited terminal reasons (SAFETY, RECITATION, BLOCKLIST, PROHIBITED_CONTENT) that OpenAI-compatible downstream clients do not recognize. A shared finish-reason normalization helper now maps these to the standard content_filter value, applied in both the streaming and JSON collection paths for both providers. (#5197 — thanks @rdself)

  • fix(responses): normalize non-array Responses API input before routing — the OpenAI Responses API accepts input as a string, object, or list, but OmniRoute only handled list-shaped payloads; a string or object input was silently dropped on the Responses→Chat Completions path. The translator now normalizes input to a list before dispatch; the Codex-native Responses path also normalizes before forwarding (preventing upstream 400 Input must be a list); and the prompt-injection and PII sanitizer extraction paths are guarded against object-valued input so security checks do not throw. (#5204 — thanks @wilsonicdev)

  • fix(zenmux): normalize vendor-prefixed GLM system roles for Z.AI models — ZenMux exposes Z.AI GLM via vendor-prefixed OpenAI-compatible IDs such as z-ai/glm-5.2. The existing GLM detection only matched bare glm-*/glm ids, so zenmux/z-ai/glm-5.2 kept system messages in place; Z.AI rejects compressed histories ending with a system turn before assistant(tool_calls) → tool sequences. The fix extends GLM detection to cover z-ai/glm-* prefixes and routes them through the existing normalizeSystemRole path. (#5158 — thanks @Thinkscape)

  • fix(xai): add OAuth connection test probe + normalize xAI reasoning effort aliases — xAI rejects unsupported reasoning effort values (max, xhigh) with HTTP 400 after a provider update; the xAI translator now maps max and xhigh to high before forwarding. Additionally, xAI OAuth connections had no dashboard test configuration, so provider tests returned "Provider test not supported"; a dedicated OAuth test probe is now wired for xAI accounts with regression coverage for the effort normalization. (#5157 — thanks @nguyenxvotanminh3)

  • fix(serve): honour HOSTNAME from .env instead of hardcoding 0.0.0.0 — bin/cli/commands/serve.mjs spread process.env into the child-process environment but immediately overwrote HOSTNAME with a literal "0.0.0.0", silently discarding any user-configured bind address even though HOSTNAME is documented in .env.example and docs/reference/ENVIRONMENT.md. dist/server.js already read process.env.HOSTNAME correctly; only the CLI wrapper was overriding it. The fix applies process.env.HOSTNAME || "0.0.0.0" so the env value takes effect. (#5134, #5170 — thanks @anki1kr / @Angelo90810)

  • fix(cli): force NODE_ENV to match dev/start run mode in the custom Next server — when .env.example ships NODE_ENV=production, starting npm run dev via scripts/dev/run-next.mjs forwarded that value to the programmatic next() entry, which — unlike the next CLI — does not normalize it to match the run mode. The resulting production flag caused PostCSS to skip Tailwind's CSS transform, surfacing as Module parse failed: Unexpected character '@' on globals.css. The custom server now explicitly forces NODE_ENV=development for the dev path and NODE_ENV=production for the start path regardless of .env. (#5189 — thanks @backryun)

  • fix(cli): raise dev server Node heap limit to 8 GB to prevent OOM — npm run dev crashed with FATAL ERROR: Ineffective mark-compacts near heap limit — Allocation failed - JavaScript heap out of memory while compiling heavy dashboard routes because node scripts/dev/run-next.mjs ran on V8's ~4 GB default with no --max-old-space-size flag. The dev npm script now passes --max-old-space-size=8192 at invocation time (the only point where this flag can be set for that process). (#5198 — thanks @backryun)

  • fix(cli): re-enable Turbopack as the default npm run dev bundler — PR #4092 forced webpack because an earlier Turbopack 16.2.x panic (internal error: entered unreachable code: there must be a path to a root in turbopack-core/module_graph) blocked the OmniRoute module graph. That panic no longer reproduces on the pinned Next 16.2.9, so OMNIROUTE_USE_TURBOPACK is flipped from 0 to 1 in .env.example, aligning it with docs/reference/ENVIRONMENT.md which had already documented the default as 1. (#5206 — thanks @backryun)

  • fix(auth): allow synthetic no-auth fallback for mimocode — mimocode connections without explicit credentials were blocked before reaching the executor. The auth layer now permits a synthetic no-auth fallback for the mimocode provider so credential-free access patterns work as intended. (#5205 — thanks @KooshaPari)

  • fix(combo): reject empty Responses API output: [] as a fail-over trigger — a non-streaming Responses API body with object: "response" and output: [] was accepted as a valid HTTP 200 by the combo response-quality validator, allowing a combo target to stop rather than fail over to the next leg. The non-stream validator now inspects Responses-API-shaped bodies before the generic output shortcut and rejects an empty output: [] as empty_choices; structural non-empty output (e.g. function_call) remains valid. (#5207 — thanks @KooshaPari)

  • fix(proxy): close cached dispatchers when clearing the proxy cache — cached proxy and direct-retry dispatchers were not closed on cache clear, leaking open connection handles. The cache-clear path now calls close() on all evicted dispatchers; dispatcher cache and lifecycle helpers have been extracted from the oversized proxy-dispatcher module into a dedicated helper for reuse. (#5202 — thanks @KooshaPari)

  • fix(proxy): coalesce concurrent fast-fail health probes per proxy URL — under high concurrency each simultaneous request opened its own TCP health probe for the same proxy URL, creating a thundering-herd burst. Concurrent proxy fast-fail checks are now coalesced so only one TCP probe runs per proxy URL at a time; the completed-result health cache is preserved so subsequent same-URL checks return immediately. (#5109, #5208 — thanks @KooshaPari)

  • fix(pwa): prefer cached navigation before showing the offline page — the service worker was too eager to display /offline on transient navigation failures. It now caches successful navigation responses and consults the cached route or app shell before falling back to /offline; /offline remains the final fallback when no cached navigation or app shell exists. (#5165, #5209 — thanks @KooshaPari)

  • fix(request-logger): never render a negative percentage in the compression badge — when every prompt token was compressed (totalIn = 0, compressed > 0), the compression pill displayed (-100%) because the badge format hard-coded a leading - before the percentage value. The badge now omits the negative sign in this case, correctly representing the saving as a positive ratio. (#5201 — thanks @KooshaPari)

  • fix(dashboard): use amber for home update-step warning icon — the warning-state icon in the home update steps (HomePageClient.tsx) used text-yellow-500 (Tailwind #eab308), which has poor contrast on light backgrounds (~1.9:1, below WCAG AA) and is inconsistent with the amber warning convention used by every sibling element in the same component. Switched to text-amber-500 — a one-line className change with no behavior change. (#5176)

📝 Maintenance

  • test(combo): deterministic context-relay universal-handoff coverage — covers the universal (provider-agnostic) session-handoff path in context-relay (combo.ts:2099–2139), which previously had only a definition-order assertion and a TODO(phase-2). The test drives the real pipeline via session seams (x-session-id → relayOptions.sessionId → maybeGenerateUniversalHandoff) without live infrastructure. (#5168)
  • test(combo): end-to-end quota-share DRR routing-decision coverage (matrix parity) — adds the missing E2E test for the quota-share strategy, driving the real handleChat → chatCore → selectQuotaShareTarget → executor pipeline via in-process seams and asserting which connection is dispatched. The DRR selector already had 29 unit tests; this closes the E2E gap and brings quota-share to parity with the 17-strategy public matrix. (#5179)
  • test(combo): deterministic context-relay codex quota-handoff coverage (closes last gap) — covers the codex-specific handoff block of context-relay (combo.ts:2143–2183), which #5168 left documented-but-untested because it requires a codex connection. All seams (fetchCodexQuota, handoff generation, session relay) are mocked deterministically without live infra. (#5195)
  • test(ci): wire antigravity-quota-family test under test:vitest (fix test-discovery orphan) — open-sse/services/__tests__/antigravity-quota-family.test.ts (introduced by #5180) was not collected by any active runner, causing check:test-discovery to report a new orphan and gate every subsequent PR on the release branch. The file is now added to vitest.mcp.config.ts include and the corresponding orphan-allowlist entry is removed. (#5196)
  • test(security): regression guard — PII redaction stays opt-in (default off) + Hard Rule #20 — adds a test asserting both PII_REDACTION_ENABLED and PII_RESPONSE_SANITIZATION feature-flag defaultValue fields are "false" and that data passes through all three application points (piiMasker, piiSanitizer, streamingPiiTransform) untouched when both flags are off, encoding Hard Rule #20 as a CI-enforced contract and fixing a misleading doc implication that PII masking was on by default. (#5159)
  • docs(i18n): add Traditional Chinese (zh-TW) README + update zh-CN — adds a new Traditional Chinese translation (docs/i18n/zh-TW/README.md) and updates the Simplified Chinese README to the current English baseline; the language index (docs/i18n/README.md) and root README.md badge row are updated accordingly. (#5162 — thanks @lunkerchen)
  • docs(i18n): full sync of zh-TW and zh-CN README to canonical English v3.8.39 — brings both translations to full parity, adding the complete What's New section, compression real-token examples, and all sections updated in the v3.8.38/39 English README. (#5171 — thanks @lunkerchen)
  • docs(combo): sync combo/routing-strategy docs to current state + document test coverage — removes a stale ordinal from the Fusion bullet in README.md; adds a new Testing & Coverage section to docs/routing/AUTO-COMBO.md documenting the deterministic strategy matrix (npm run test:combo:matrix), quota-share DRR E2E coverage, and context-relay handoff tests delivered across the v3.8.39 cycle. (#5185)
