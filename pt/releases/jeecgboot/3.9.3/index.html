#JecgBoot v3.9.3

Registro de atualização

Atualização importante: o backend está totalmente adaptado para Spring Boot 4, o frontend foi finalmente atualizado para Vite 8 e dependências principais como Pinia 3, Vue Router 5, Shiro 3.0, MyBatis-Plus 3.5.16, Nacos 3.2.2, XXL-JOB 3.4.2, etc. AI low code entra no segmento de estágio 2.0, suporta sistemas de geração de linguagem natural, formulários, processos, relatórios e telas grandes, e lança JimuChatBI 1.0 ao mesmo tempo; além disso, também concluiu relatórios de blocos de construção, inicialização de microsserviços Docker, desempenho de inicialização de banco de dados e otimização de carregamento de dependência pesada de front-end e reparou problemas como eco de seleção múltipla, PopupDict, chamada de IA, aprimoramento de JS e vulnerabilidades de SSRF armazenadas, melhorando ainda mais a segurança, estabilidade e experiência de desenvolvimento do sistema.

Arquitetura e atualização de dependências

  • A arquitetura backend foi atualizada para Spring Boot 4 e a adaptação de compatibilidade relevante foi concluída.
  • A ferramenta de construção front-end foi finalmente atualizada para o Vite 8 e o plug-in do tema foi migrado para o local.
  • Atualize Pinia 3, Roteador Vue 5.
  • Atualize o Jeecg Starter para 3.9.4.
  • Atualize Shiro para 3.0.0 e adapte-se à nova versão do shiro-redis.
  • Atualize MyBatis-Plus para dependências básicas como 3.5.16 e Druid.
  • Atualize XXL-JOB para 3.4.2.
  • Atualize o painel Sentinel para 1.8.10.
  • Atualize Nacos para 3.2.2, adicione configuração de porta de gerenciamento.
  • Atualize LangChain4j para 1.17.2.
  • Atualizar dependências como Apache Tika, CommonMark, AutoPoi, Commons IO e MinIO.
  • Remova lodash e use lodash-es uniformemente.
  • Relatórios de blocos de construção e componentes de tela grande atualizados para serem compatíveis com Spring Boot 4 e suportar a nova versão do assistente de IA.

IA e recursos de baixo código

  • Os recursos de IA de baixo código foram atualizados para 2.0, suportando a geração de sistemas, formulários, processos, relatórios e telas grandes em linguagem natural.
  • Lançado JimuChatBI 1.0, fornecendo recursos de questionamento de números inteligentes Chat2BI de código aberto.
  • Fornece AI Flow adaptado para Spring Boot 4.
  • O modelo de IA padrão é ajustado para DeepSeek V4 Pro.
  • Corrigida a anormalidade na chamada de modelo após a pesquisa online do DeepSeek V4 Flash.
  • Corrigido o problema em que as operações comerciais de encaixe de bate-papo da IA ​​não estavam disponíveis.
  • Corrigido o problema em que a página de design do processo de IA não podia ser exibida corretamente.

Correções de funções

  • Corrigido o problema em que os ecos de seleção múltipla da posição do usuário do sistema eram exibidos como 1,2,3 (#9420).
  • Corrigido o problema de o componente PopupDict não ser verificado corretamente ao abri-lo pela segunda vez.
  • Corrigido o problema de execução repetida de função em updateSchema (#9612).
  • Corrigido um problema que causava exceções de página após erros de configuração de código de aprimoramento JS (#9699).
  • Corrigido um erro causado pela configuração padrão do modelo AI quando o Docker é iniciado (#9635).
  • Corrigido o problema de que tinycolor2 não pode ser analisado quando o front end é iniciado (#9698).
  • Corrigido o problema de tela branca e carregamento lento quando o ambiente de desenvolvimento Vite 8 acessa páginas fortemente dependentes, como Tinymce, ECharts, VXE-Table, etc. pela primeira vez (#9782).
  • Elimine o aviso de compatibilidade na inicialização do servidor de desenvolvimento Vite 8.
  • Corrigidos problemas de compatibilidade como Swagger, testes unitários e conflitos de dependência do Redis após a atualização do Spring Boot 4.

Correções de segurança

  • Corrigida a vulnerabilidade SSRF armazenada em WordUtil.addImage (CWE-918).

Implantação e otimização de desempenho

  • Fornece script de início rápido de microsserviço.
  • Otimize o processo de inicialização do microsserviço Docker, o gateway aguarda que o Nacos esteja pronto antes de iniciar.
  • Ajustou a sequência de inicialização do Nacos Console e da Web e melhorou a exposição da porta de gerenciamento.
  • Otimize a configuração Nginx de front-end único e suporte a resolução dinâmica do endereço de back-end por meio do DNS integrado do Docker.
  • Otimize a primeira inicialização do banco de dados, adote o envio em lote e reduza logs inválidos e melhore a velocidade de inicialização.
  • Corrigido o problema em que o gateway e o front-end não conseguem acessar a instância de serviço quando a inicialização demora muito.
  • Otimize a configuração da porta para reduzir o risco de conflitos de porta no ambiente Docker.

JeecgBoot v3.9.3

Highlights

  • Major framework migration — The backend now targets Spring Boot 4, while the frontend moves to Vite 8, Pinia 3, and Vue Router 5. Plan a coordinated dependency and compatibility pass before upgrading, including Spring Boot 4-specific AI Flow, Shiro 3/shiro-redis, Redis, Swagger, and test adjustments.
  • Natural-language low-code 2.0 — AI generation now spans systems, forms, workflows, reports, and dashboards, with JimuChatBI 1.0 adding conversational analytics. The default model changes to DeepSeek V4 Pro; verify existing prompts, model configuration, and business-operation integrations against the new AI flow.
  • Stored SSRF fixed — WordUtil.addImage no longer permits attacker-controlled image requests to reach internal resources (CWE-918). Prioritize this release if your deployment accepts untrusted Word content, and review downstream image-fetching paths.
  • Faster and more reliable container startup — New microservice scripts gate gateway startup on Nacos readiness, reorder Nacos services, reduce database initialization overhead through batch commits, and improve port configuration. Initialization delays should no longer leave gateway/frontend clients unable to discover services.
  • Vite 8 development-experience fixes — Optimizations address first-load white screens and slow loading of TinyMCE, ECharts, and VXE-Table (#9782), alongside startup warnings and tinycolor2 resolution (#9698). Heavy-component pages should load reliably without changing application code.
  • Targeted correctness fixes — Multi-value user-position display (#9420), repeated updateSchema function execution (#9612), broken UI state after invalid JS enhancements (#9699), PopupDict reselection, AI workflow rendering, and Docker’s default AI configuration (#9635) are resolved; regression-test these customizations after upgrading.

升级日志

重要升级：后端全面适配 Spring Boot 4，前端最终升级至 Vite 8，并同步升级 Pinia 3、Vue Router 5、Shiro 3.0、MyBatis-Plus 3.5.16、Nacos 3.2.2、XXL-JOB 3.4.2 等核心依赖；AI 低代码迈入 2.0 阶 段，支持自然语言生成系统、表单、流程、报表和大屏，同时发布 JimuChatBI 1.0；此外，还完成了积木报表、Docker 微服务启动、数据库初始化性能及前端重依赖加载优化，并修复多选回显、PopupDict、AI 调用、JS 增强和存储型 SSRF 漏洞等问题，进一步提升了系统的安全性、稳定性与开发体验。

架构与依赖升级

  • 后端架构升级至 Spring Boot 4，完成相关兼容性适配。
  • 前端构建工具最终升级至 Vite 8，主题插件迁移至本地。
  • 升级 Pinia 3、Vue Router 5。
  • 升级 Jeecg Starter 至 3.9.4。
  • 升级 Shiro 至 3.0.0，并适配新版 shiro-redis。
  • 升级 MyBatis-Plus 至 3.5.16、Druid 等基础依赖。
  • 升级 XXL-JOB 至 3.4.2。
  • 升级 Sentinel Dashboard 至 1.8.10。
  • 升级 Nacos 至 3.2.2，新增管理端口配置。
  • 升级 LangChain4j 至 1.17.2。
  • 升级 Apache Tika、CommonMark、AutoPoi、Commons IO、MinIO 等依赖。
  • 移除 lodash，统一使用 lodash-es。
  • 升级积木报表及大屏组件，兼容 Spring Boot 4，并支持新版 AI 助手。

AI 与低代码能力

  • 低代码 AI 能力升级至 2.0，支持通过自然语言生成系统、表单、流程、报表及大屏。
  • 发布 JimuChatBI 1.0，提供开源对话式 Chat2BI 智能问数能力。
  • 提供适配 Spring Boot 4 的 AI Flow。
  • 默认 AI 模型调整为 DeepSeek V4 Pro。
  • 修复 DeepSeek V4 Flash 联网搜索后的模型调用异常。
  • 修复 AI 聊天对接业务操作不可用的问题。
  • 修复 AI 流程设计页面无法正常显示的问题。

功能修复

  • 修复系统用户职务多选回显为 1,2,3 的问题（#9420）。
  • 修复 PopupDict 组件二次打开时未正确勾选的问题。
  • 修复 updateSchema 中函数重复执行的问题（#9612）。
  • 修复 JS 增强代码配置错误后导致页面异常的问题（#9699）。
  • 修复 Docker 启动时默认AI模型配置导致的报错（#9635）。
  • 修复前端启动时无法解析 tinycolor2 的问题（#9698）。
  • 修复 Vite 8 开发环境首次访问 Tinymce、ECharts、VXE-Table 等重依赖页面时白屏及加载缓慢的问题（#9782）。
  • 消除 Vite 8 开发服务器启动时的兼容性警告。
  • 修复 Spring Boot 4 升级后的 Swagger、单元测试、Redis 依赖冲突等兼容问题。

安全修复

  • 修复 WordUtil.addImage 存储型 SSRF 漏洞（CWE-918）。

部署与性能优化

  • 提供微服务快速启动脚本。
  • 优化 Docker 微服务启动流程，网关等待 Nacos 就绪后再启动。
  • 调整 Nacos Console 与 Web 启动顺序，并完善管理端口暴露。
  • 优化单体前端 Nginx 配置，支持通过 Docker 内置 DNS 动态解析后端地址。
  • 优化数据库首次初始化，采用批量提交并减少无效日志，提高初始化速度。
  • 修复初始化耗时较长时网关及前端无法访问服务实例的问题。
  • 优化端口配置，降低 Docker 环境下的端口冲突风险。
