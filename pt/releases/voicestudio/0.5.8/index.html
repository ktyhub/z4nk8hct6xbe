Destaques

  • OmniVoice GGUF usa GPUs AMD, Intel e NVIDIA por meio de Vulkan no Windows e Linux, e GPUs Intel Arc executam OmniVoice
  • A configuração volta para uma construção de CPU menor quando os downloads do PyTorch falham, e o aplicativo volta para a CPU quando a GPU falha
  • O Windows carrega os modelos, um arquivo por vez, e uma falha no mecanismo nomeia sua causa e oferece reinicialização na CPU
  • a clonagem de voz dots.tts é executada no Windows por meio de audio.cpp, sem configuração do Python
  • Convert pode manter sua entrega e gravar vídeo; A dublagem exporta as legendas primeiro e move as linhas entre os alto-falantes

O OmniVoice agora usa sua GPU AMD, Intel ou NVIDIA, e o VoiceStudio fica muito mais difícil de quebrar. OmniVoice GGUF é executado em qualquer GPU Vulkan no Windows e Linux, dimensiona seu modelo para sua placa e pode permanecer carregado entre solicitações (opt-in, Configurações → Desempenho), e as GPUs Intel Arc também executam OmniVoice. Quando algo dá errado, o aplicativo continua funcionando: a configuração oferece uma construção de CPU muito menor quando o download do PyTorch continua falhando, tenta novamente downloads paralisados ​​e o VoiceStudio passa para a CPU com um aviso quando a GPU falha. No Windows, os modelos carregam um arquivo por vez para evitar uma falha na primeira inicialização, e uma falha no mecanismo nomeia a biblioteca por trás dele e oferece reinicialização na CPU.

Esta versão também traz clonagem de voz dots.tts para Windows sem configuração Python, Convert que mantém sua entrega e grava vídeo, dublagem que exporta legendas primeiro e move linhas entre alto-falantes, um comando de terminal voicestudio, atualizações em segundo plano, uma nova janela do instalador do macOS e centenas de correções para dublagem, configuração, audiolivros e aplicativos de telefone.

A nova janela do instalador do macOS (#4001).

VoiceStudio v0.5.8

Highlights

  • OmniVoice GGUF goes cross-vendor on Vulkan — The GGUF path now runs on any Vulkan GPU on Windows and Linux, covering AMD, Intel and NVIDIA cards plus Intel Arc, with model sizing per card and an opt-in resident runtime (Settings → Performance) that skips the reload before every generation (#3965, #3654). Release installers now bundle omnivoice.cpp's tts-server so resident mode survives outside dev builds, falling back to per-request loading when unavailable (#4005), and a Self-test in Settings → Models names the Vulkan device it actually ran on — the quickest way to verify a driver setup before chasing generation bugs (#3993).
  • Failure paths became fallbacks — Setup offers a much smaller CPU build when the PyTorch download keeps failing (#3846) and retries stalled downloads; a startup GPU probe switches to CPU with a notice if the GPU fails (#3845). On Windows, models load one file at a time to avoid first-launch crashes, and engine crashes now name the offending library and offer Restart on CPU. Crash reports include what was running and free memory (#3844), turning anonymous OOMs into diagnosable ones.
  • Source builds drop Gradio and training from the default install — The migration item for anyone running from source: Gradio and WebDataset are no longer installed by default (~81 MB lighter), and the demo and training paths now require the ui and train extras (#4027). Add those explicitly if your workflow uses them. Expect a one-time in-place package update on first launch when coming from 0.5.7, including the PyTorch 2.10 security update (#3884).
  • dots.tts cloning reaches Windows without Python — Voice cloning runs through the audio.cpp runtime, so Windows users skip the Python setup that previously gated the feature. The runtime moves to v0.9.4, but installed Breeze-TTS-2, dots.tts and Sortformer models keep working without a re-download, and the previous runtime continues serving them until you install the update (#3129).
  • Convert and dubbing preserve more source material — Convert voice can keep the original delivery video, returning picture and background when they can be preserved and converted audio plus an explanation when they can't (#3750). Dubbing now exports subtitles first, moves lines between speakers, and can speak the original transcript in the source language to bypass translation entirely (#3747).
  • CLI and quieter updates — A new voicestudio terminal command exposes voices, speech, transcription, dubbing and models with tab completion, auto-starting the app in the background when needed (#3828). Updates download in the background and install on quit with a title-bar progress pill, Restart/Retry controls and a prompt when work is running (#3928), so long sessions aren't interrupted mid-task.

No breaking changes for existing installs.

OmniVoice now uses your AMD, Intel or NVIDIA GPU, and VoiceStudio gets much harder to break. OmniVoice GGUF runs on any Vulkan GPU on Windows and Linux, sizes its model to your card and can stay loaded between requests (opt-in, Settings → Performance), and Intel Arc GPUs run OmniVoice too. When something goes wrong, the app now keeps going: setup offers a much smaller CPU build when the PyTorch download keeps failing, retries stalled downloads, and VoiceStudio moves to the CPU with a notice when the GPU fails. On Windows, models load one file at a time to avoid a crash on first launch, and an engine crash names the library behind it and offers Restart on CPU.

This release also brings dots.tts voice cloning to Windows with no Python setup, Convert that keeps your delivery and takes video, dubbing that exports subtitles first and moves lines between speakers, a voicestudio terminal command, background updates, a new macOS installer window, and hundreds of fixes to dubbing, setup, audiobooks and the phone apps.

The new macOS installer window (#4001).

Updating from 0.5.7: Take the in-app update offered by 0.5.7, or install over your existing app; voices, projects and settings are kept. On first launch the local runtime updates its packages in place, including the PyTorch 2.10 security update (#3884)

Updating from a 0.5.8 beta: Nothing to do: the Beta channel rolls forward onto 0.5.8 automatically. To stop getting betas, switch to Stable in Settings → Updates → Update channel.

Running from source: The Gradio demo and model training are no longer installed by default; add the ui or train extra if you use them (#4027)
