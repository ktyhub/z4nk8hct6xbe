Esta versão adiciona nada menos que nove novos métodos PEFT e coloca muito trabalho na infraestrutura circundante, por exemplo, adicionando um novo benchmark de geração de imagens para o conjunto de comparação de métodos e melhorando significativamente a estrutura da documentação.

Novos métodos

Olá RA

@hqsiswiliam adicionou "HiRA: Adaptação de alta classificação Hadamard com eficiência de parâmetros para modelos de linguagem grande" ao PEFT (#2668). Em vez de adicionar o produto de baixa classificação BA ao peso base, HiRA multiplica-o elemento a elemento (produto Hadamard) pelo peso base congelado. Como o peso base em si é de classificação completa, a atualização resultante não é mais restrita a uma classificação baixa, enquanto a contagem de parâmetros treináveis ​​permanece a mesma do LoRA.

GLORA

@not-lain contribuiu com GLoRA: "One-for-All: Generalized LoRA for Parameter-Efficient Fine-Tuning" em #3098. É um método PEFT flexível que estende o LoRA com peso configurável, ativação e adaptação de polarização, proporcionando um ajuste fino mais rico sem custo extra de inferência. Use-o quando precisar de flexibilidade por camada ou adaptação mais forte do que o Vanilla LoRA. Ignore-o para camadas não lineares (por exemplo, Conv/Embedding) ou quando o LoRA padrão já for suficiente e a simplicidade for importante.

BEFT

@whubaichuan adicionou "BEFT: Ajuste fino de modelos de linguagem com eficiência de polarização" em #3195. O BEFT baseia-se na observação de que o ajustamento fino dos termos de enviesamento por si só pode ser competitivo em regimes com poucos dados, mas vai mais longe: em vez de treinar todos os enviesamentos, visa a projecção de valor por defeito, uma vez que os autores consideraram que isto é mais eficiente. Isso reduz a contagem dos parâmetros treináveis ​​para aproximadamente 0.01% do total de parâmetros.

MonteCLoRA

@ victor7246 integrou o MonteCLoRA, "Robust and Efficient Fine-tuning of LLMs with Bayesian Reparameterization of Low-Rank Adaptation" em #2943. LoRA é conhecido por ser sensível a hiperparâmetros como taxa de aprendizagem e tamanho do lote. Esta nova variante do LoRA aborda isso tratando os parâmetros de baixo escalão como uma distribuição em vez de uma estimativa pontual, usando a estimativa de Monte Carlo para obter uma estimativa posterior de baixa variância. Isso deve tornar o treinamento visivelmente mais robusto, ao custo de apenas O(rank) parâmetros adicionais.

VeLoRA

@roymiles adicionou VeLoRA: "Treinamento eficiente de memória usando projeções de subtoken de classificação 1" em #3159. Ao contrário da maioria dos métodos PEFT, esta variante LoRA tem como alvo a memória de ativação em vez da contagem de parâmetros: as ativações intermediárias são divididas em subtokens e compactadas com uma projeção fixa de classificação 1 antes de serem armazenadas em cache para a passagem para trás e, em seguida, reconstruídas durante a retropropagação. Conceitualmente, é semelhante ao checkpoint de gradiente, com menor economia de memória, mas rodando mais rápido.

###Uni-LoRA

@KaiyangLi1992 contribuiu com Uni-LoRA: "Um vetor é tudo que você precisa" em #3257. O artigo mostra que variantes LoRA com parâmetros eficientes, como VeRA e VB-LoRA, podem ser descritas como projetando todo o espaço de parâmetros LoRA em um subespaço muito menor, diferindo apenas na escolha da projeção. Uni-LoRA usa uma única projeção global em todo o modelo, em vez de projeções em camadas, o que permite o compartilhamento de parâmetros entre camadas e, portanto, contagens de parâmetros muito baixas.

FRoD

@Bane-Elvin adicionou FRoD, "Ajuste fino eficiente de classificação completa com graus rotacionais para convergência rápida", em #3270. Em vez de adicionar deltas de baixa classificação como LoRA, ele reconstrói pesos selecionados com subespaços rotacionais compartilhados e coeficientes treináveis ​​esparsos. É especialmente útil quando a convergência rápida e um teto de capacidade de classificação completa mais alto são importantes, e seu grande subespaço rotacional esparso também pode ser promissor para a fusão de modelos. As principais compensações são a dispendiosa inicialização da decomposição conjunta e os passes para frente/para trás um pouco mais lentos do que o LoRA, portanto, pode ser menos atraente para um ajuste fino único de tarefa única.

###MiCA

@sr-networks contribuiu com MiCA, "MiCA aprende mais conhecimento que LoRA e ajuste fino completo", em #3260. MiCA é uma variante LoRA que inicializa B a partir do SVD do peso base, pegando os vetores singulares esquerdos pertencentes aos menores valores singulares e, em seguida, treina apenas A. A ideia é que a adaptação destas direções subutilizadas integre novos conhecimentos de forma mais eficaz do que a adaptação do subespaço dominante, com menos interferência nas capacidades existentes.

DEFÉ

@MAXNORM8650 adicionou DEFT, "Ajuste fino eficiente de composição para modelos de texto para imagem", em #3342. Este método PEFT divide uma atualização de peso em duas partes aprendidas de classificação inferior: uma projeção que remove um subespaço do peso congelado e uma atualização de classificação inferior que injeta novo conteúdo em seu lugar. Use DEFT para personalizar um modelo de texto para imagem a partir de algumas imagens, mantendo o seguimento/editabilidade das instruções do modelo básico com o mínimo de esquecimento. É menos adequado se você não precisar preservar os outros recursos do modelo base (um adaptador aditivo simples é mais simples) ou para camadas além de Linear/Conv1D. O método PaRa também é suportado como um caso especial de DEFT.

Melhorias

Seleção automática de alvo LoRA

@oswaldoludwig adicionou KappaTuneSelector em #3106 com base em "O número de condição como um proxy invariável em escala para codificação de informações em unidades neurais". O PR adiciona uma nova função, find_kappa_target_modules, que identifica automaticamente quais módulos são melhores para atingir com base no número de condição das matrizes de peso base. Isso elimina algumas suposições ao escolher target_modules ao configurar LoRA ou outros métodos PEFT.

Suporte mais amplo à quantização

#3117 adiciona suporte genérico de quantização para BOFT, MiSS e VeRA, e #3321 faz o mesmo para SHiRA. Anteriormente, o suporte à quantização tinha que ser implementado por método e por backend; mais métodos agora funcionam com back-ends de quantização comuns prontos para uso. Observe que, como consequência, o VeRA agora usa o back-end de quantização genérico em vez de seu back-end de quantização de bits e bytes anterior. Se você encontrar problemas por causa disso, informe-nos.

Vários adaptadores com target_parameters

target_parameters, que permite direcionar nn.Parameters diretamente (útil para modelos MoE que agrupam especialistas em um único parâmetro), agora suporta adição e carregamento de vários adaptadores (#3350).

AdaLoRA para Conv2d

@Anai-Guo adicionou SVDConv2d em #3196, então AdaLoRA agora pode atingir camadas torch.nn.Conv2d.

Reestruturação da documentação

A documentação do PEFT foi reorganizada em #3300 e #3325, o que deve tornar consideravelmente mais fácil a navegação agora que o PEFT suporta tantos métodos. Cada método PEFT também fornece uma visão geral de seu desempenho nos benchmarks PEFT. Há também uma longa série de melhorias na documentação de muitos contribuidores nesta versão, obrigado a todos que trabalharam nelas.

Mudanças

Descontinuação do AutoGPTQ

Após a mudança para GPT-QModel como backend na versão anterior, o AutoGPTQ agora está formalmente obsoleto (#3190) graças ao @Qubitium.

Highlights

This release adds no less than nine new PEFT methods and puts a lot of work into the surrounding infrastructure, for example adding a new image generation benchmark for the method comparison suite and greatly improving the documentation structure.

New Methods

HiRA

@hqsiswiliam added "HiRA: Parameter-Efficient Hadamard High-Rank Adaptation for Large Language Models" to PEFT (#2668). Instead of adding the low-rank product BA to the base weight, HiRA multiplies it elementwise (Hadamard product) with the frozen base weight. Because the base weight itself is full rank, the resulting update is no longer constrained to be low rank, while the trainable parameter count stays the same as LoRA's.

GLoRA

@not-lain contributed GLoRA: "One-for-All: Generalized LoRA for Parameter-Efficient Fine-Tuning" in #3098. It is a flexible PEFT method that extends LoRA with configurable weight, activation, and bias adaptation, delivering richer fine-tuning with no extra inference cost. Use it when you need per-layer flexibility or stronger adaptation than vanilla LoRA. Skip it for non-Linear layers (e.g. Conv/Embedding) or when standard LoRA is already sufficient and simplicity matters.

BEFT

@whubaichuan added "BEFT: Bias-Efficient Fine-Tuning of Language Models" in #3195. BEFT builds on the observation that fine-tuning bias terms alone can be competitive in low-data regimes, but goes further: rather than training all biases, it targets the value projection by default, as the authors found this to be most efficient. This brings the trainable parameter count down to roughly 0.01% of the total parameters.

MonteCLoRA

@victor7246 integrated MonteCLoRA, "Robust and Efficient Fine-tuning of LLMs with Bayesian Reparameterization of Low-Rank Adaptation" in #2943. LoRA is known to be sensitive to hyperparameters like learning rate and batch size. This new LoRA variant addresses this by treating the low-rank parameters as a distribution rather than a point estimate, using Monte Carlo estimation to obtain a low-variance posterior estimate. This should make training noticeably more robust, at the cost of only O(rank) additional parameters.

VeLoRA

@roymiles added VeLoRA: "Memory Efficient Training using Rank-1 Sub-Token Projections" in #3159. Unlike most PEFT methods, this LoRA variant targets activation memory rather than parameter count: intermediate activations are split into sub-tokens and compressed with a fixed rank-1 projection before being cached for the backward pass, then reconstructed during backpropagation. Conceptually, it is similar to gradient checkpointing, with a lower memory saving but running faster.

Uni-LoRA

@KaiyangLi1992 contributed Uni-LoRA: "One Vector is All You Need" in #3257. The paper shows that parameter-efficient LoRA variants like VeRA and VB-LoRA can all be described as projecting the full LoRA parameter space down to a much smaller subspace, differing only in the choice of projection. Uni-LoRA uses a single global projection across the whole model instead of layer-wise ones, which allows cross-layer parameter sharing and thus very low parameter counts.

FRoD

@Bane-Elvin added FRoD, "Full-Rank Efficient Fine-Tuning with Rotational Degrees for Fast Convergence", in #3270. Instead of adding low-rank deltas like LoRA, it reconstructs selected weights with shared rotational subspaces and sparse trainable coefficients. It is especially useful when fast convergence and a higher full-rank capacity ceiling are important, and its large sparse rotational subspace may also be promising for model merging. The main tradeoffs are the costly joint-decomposition initialization and slightly slower forward/backward passes than LoRA, so it may be less attractive for a one-off single-task fine-tune.

MiCA

@sr-networks contributed MiCA, "MiCA Learns More Knowledge Than LoRA and Full Fine-Tuning", in #3260. MiCA is a LoRA variant that initializes B from the SVD of the base weight, taking the left singular vectors belonging to the smallest singular values, and then trains only A. The idea is that adapting these underused directions integrates new knowledge more effectively than adapting the dominant subspace, with less interference with existing capabilities.

DEFT

@MAXNORM8650 added DEFT, "Decompositional Efficient Fine-Tuning for Text-to-Image Models", in #3342. This PEFT method splits a weight update into two learned low-rank parts: a projection that removes a sub-space of the frozen weight, and a low-rank update that injects new content in its place. Use DEFT for personalizing a text-to-image model from a few images while retaining the base model's instruction-following/editability with minimal forgetting. It is less of a fit if you don't need to preserve the base model's other capabilities (a plain additive adapter is simpler) or for layers beyond Linear/Conv1D. The PaRa method is also supported as a special case of DEFT.

Enhancements

Automatic LoRA target selection

@oswaldoludwig added KappaTuneSelector in #3106 based on "The Condition Number as a Scale-Invariant Proxy for Information Encoding in Neural Units". The PR adds a new function, find_kappa_target_modules, which automatically identifies which modules best to target based on the condition number of the base weight matrices. This removes some of the guesswork from choosing target_modules when configuring LoRA or other PEFT methods.

Broader quantization support

#3117 adds generic quantization support to BOFT, MiSS, and VeRA, and #3321 does the same for SHiRA. Previously, quantization support had to be implemented per method and per backend; more methods now work with the common quantization backends out of the box. Note that as a consequence, VeRA now uses the generic quantization backend instead of its previous bitsandbytes quantization backend. If you encounter issues because of that, please let us know.

Multiple adapters with target_parameters

target_parameters, which allows targeting nn.Parameters directly (useful for MoE models that pack experts into a single parameter), now supports adding and loading multiple adapters (#3350).

AdaLoRA for Conv2d

@Anai-Guo added SVDConv2d in #3196, so AdaLoRA can now target torch.nn.Conv2d layers.

Documentation restructure

The PEFT documentation was reorganized in #3300 and #3325, which should make it considerably easier to navigate now that PEFT supports so many methods. Each PEFT method also provides an overview of how well it fares in the PEFT benchmarks. There is also a long tail of documentation improvements from many contributors this release, thanks to everyone who worked on those.

Changes

AutoGPTQ deprecation

Following the switch to GPT-QModel as the backend in the previous release, AutoGPTQ is now formally deprecated (#3190) thanks to @Qubitium.

Benchmarks

Image generation benchmark

The method comparison suite now has an image generation benchmark (#3082). This complements the existing MetaMathQA benchmark and allows to compare PEFT methods on a completely different task. This gives us a more complete picture of the capabilities of different PEFT methods. To check the results, visit the Gradio Space and on the top left, select the task "image-gen".
