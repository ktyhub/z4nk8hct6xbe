angular v22.0.1

Highlights

  • URL handling and HTTP progress reporting — Query parameters are now inserted before URL fragments, router navigation boundaries use the native URL object, and POST/PATCH requests correctly forward reportUploadProgress and reportDownloadProgress. JSONP requests reject non-HTTP(S) URLs, and an explicitly empty referrer is preserved.

  • Template and binding safety — Link sanitization now covers MathML href/xlink:href attributes and two-way properties; i18n event attributes are disallowed. The compiler-cli also binds switch exhaustiveness-check expressions, improving type narrowing and compile-time validation.

  • SSR and TransferState hardening — SSR hardening covers platform-location origin validation, TransferState restoration against DOM clobbering, and disabling WebMCP server-side. WebMCP tools now require descriptions, and generated form schemas set additionalProperties: false.

  • Prototype-pollution defenses — Form-group control lookups reject prototype-shadowed keys, formatDateTime prevents prototype pollution, and styling utilities correctly handle null-prototype objects. Dynamic control names and date/time inputs deserve regression testing if your application builds them from user data.

  • Stability and lifecycle fixes — Synchronous errors in PendingTasks.run are handled, destroyed views no longer retain a dangling prevConsumer reference (#68681), and form animation listeners are cleaned up on destruction. Transfer-cache keys now use cryptographic SHA-256 rather than non-cryptographic hashing.

  • Server XHR deprecation — XHR support in @angular/platform-server is deprecated; migrate SSR request code to standard fetch APIs.

No breaking changes in this patch release.
