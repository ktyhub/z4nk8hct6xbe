angular v22.2.1

Highlights

  • URL sanitization security hardening — The core sanitizer now blocks dangerous data: and vbscript: URLs (7c634ecec4) while widening the allowlist for non-executable MIME-type data: URLs (9aeef8df6f). Paired with platform-server rejecting protocol-relative paths in resolveUrl (928dcfd258), the router safely falling back when serializing protocol-relative URLs (a6e6097b3d), and absolute redirects from redirect functions being capped (8b6dd5e947), this closes common XSS and open-redirect vectors. Watch out: templates or SSR code that deliberately relied on embedded data: payloads or protocol-relative redirects will now be rejected.
  • Stricter router outlet validation — Duplicate named outlets are now rejected in production builds (3b6796f1ab), and outlets must match a route before child segments are processed (e9bf52aa03). This is the likeliest source of new runtime errors after upgrading: audit route configs for duplicate outlet names that may previously have passed silently.
  • Router memory and resource-timing changes — UrlTree instances are no longer retained in RouterLink (14793bfe4b) and URL-sized objects are not copied into every route snapshot (568d6a83a2), cutting allocation churn on navigation-heavy apps. Separately, blocking resource inputs now initialize synchronously on activation (d23932f2fd) — a behavioral change that affects exactly when activated components observe their input data.
  • Template/compiler correctness — Fixes stop the template pipeline from incorrectly stripping parentheses in expressions (c451a3b98d, bbc556daa9) and add explicit return types to generated functions (0ecaf8e7ab). This changes emitted output, not just type-checking, so recheck any grouping-parenthesis expressions whose generated code may have compiled differently.
  • Debugging and HTTP observability — httpResource now forwards reportProgress as reportDownloadProgress (6dee7fe91c), so progress callbacks actually fire. NG0600 errors now name the signal and component (f5e8edc5a6), afterRenderEffect gains a debugName (21851fc3a3), error-boundary fallbacks render correctly after HMR (88614a5407), NgOptimizedImage passes a srcset binding through when optimization is disabled (ad2f291ba0), and compiler-cli readConfiguration supports extendedConfigCache (fe9ebf5bf5).

No breaking changes were announced in this release.
