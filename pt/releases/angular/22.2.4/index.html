angular v22.2.4

Highlights

  • New ngClass migration — The sole feature in this patch (6c631a5359) adds an ng update migration that rewrites static string and array ngClass bindings to the native class binding. Read it as a directional signal: Angular now wants class for static or statically-composed values and reserves ngClass for dynamic object maps. Run the migration and review its output, but note it deliberately skips dynamic object bindings — those still need manual rewrites if you want to drop the directive entirely.

  • JIT change detection flips for pre-v22 libraries — In JIT mode (dev builds, tests, playgrounds), libraries compiled before v22 now default to Eager change detection (1a7ebad7a5) instead of the previous behavior. This is a dev/JIT-vs-AOT parity change: components consumed from older packages may check far more often and expose timing-sensitive bugs that were masked before. If you're chasing test-only or dev-only rendering differences after upgrading, start here — no opt-out flag is mentioned in this patch.

  • i18n and hydration get production-hardened — A dense cluster of core fixes targets SSR/i18n correctness: the shared ICU case queue is no longer mutated during hydration (570679134b), every attribute translation is scanned for ICUs (b8102ebeb4), integer overflow is guarded (57ae1d1bb6), and bindings inside ICU expressions get clearer warnings (84a398bec2). Two fixes stop collisions with prototype-named keys such as constructor/toString — one in the compiler (bc600a2fc2), one in getTransferState (be85e4eb74). Localized SSR apps benefit from fewer hydration mismatches and less transfer-state corruption; two perf changes also keep i18n assertions and debug-name reads out of production (e79a9199a5, c1b8b0a914).

  • Router's Navigation API integration is stabilized — For apps opted into the browser Navigation API, this patch removes several sharp edges: downloads are no longer intercepted (6ccbb0f6aa), redirects work during traversal navigations (b8383a1987), and guard order is respected when a guard throws a RedirectCommand (2f0e2ac5e7) — directly relevant to auth redirect chains. Also fixed: routerLinkActive clears stale classes (702ba3a2eb), route data is unsubscribed when an outlet deactivates (6c995a5a6d), and several URL-serialization edge cases (d1da1a7c4c, 12b553bc28, ea8cdc4c6b).

  • Forms and resources tighten validation — Signal-based forms now reject unsupported updateOn values in SignalFormControl (122663145b) instead of silently accepting them, so previously loose configs will throw — audit signal form definitions on upgrade. formControlName with no matching control no longer crashes (41b189752e). On the reactivity side, resource() avoids redundant reloads when params are unchanged (fe02c34c3c), which reduces needless refetches in data-driven views.

  • Build toolchain and hybrid-app fixes — compiler-cli now requires @jridgewell/sourcemap-codec ≥ 1.6.0 (4b82200c4e); pinning an older transitive version will break builds until updated. HTTP caching accounts for multiple Cache-Control headers (2251098d52), the language service resolves inputs with restricted access (646e9723db), and upgrade compiles only the template contents of a downgraded component (ecaec13db4) — worth noting for hybrid AngularJS/Angular apps.

No breaking changes in this release.
