bookkeeper release-4.17.4

Highlights

  • Security dependency upgrades — Vert.x moves to 4.5.27 for CVE-2026-6860 (#4792, superseding the earlier 4.5.24 bump), and Thrift moves to 0.23.0 for CVE-2026-43869 (#4791); commons-lang3 is now 3.20.0 (#4725). If you embed or shade BookKeeper, check dependency convergence so older vulnerable versions are not still packaged.
  • Data integrity and Java 8 compatibility — #4701 closes a race where concurrent write and recovery paths could create different LedgerDescriptor instances for one ledger, bypassing the fencing lock and causing entry loss. #4771 publishes ConcurrentLongHashMap key/value arrays atomically to prevent resize-time ArrayIndexOutOfBoundsException; #4778 preserves the 4.17 branch’s Java 8 compatibility after that fix.
  • Read-path optimization rolled back — #4830 reverts #4730 after its non-blocking response handling and maxReadsInProgressLimit=10000 default were found to deadlock Netty event loops under read backlog or slow clients. This release restores the previous blocking response path and maxReadsInProgressLimit=0 default; do not expect the advertised READ_ENTRY_REQUEST p99 improvement, and re-test if you ran a build containing #4730.
  • Client timeout and LAC hardening — #4760 fixes a recycled-operation NPE race in PendingAddOp.maybeTimeout() when addEntryQuorumTimeoutNanos > 0; #4737 makes V3 responses remove pending operations before asynchronous completion can recycle them; and #4713 releases the Netty buffer used by PendingWriteLacOp with explicitLacInterval. Together these reduce sporadic client failures and memory leaks under load.
  • Multi-region failover behavior is opt-in — #4727 adds bookieConnectionErrorQuarantineEnabled, defaulting to false. Enabling it counts TCP/DNS connection failures toward bookie quarantine, helping avoid repeated selection of unreachable bookies, endless ensemble changes, and ZooKeeper metadata growth. Review bookieQuarantineTimeSeconds when enabling it.
  • Replication and diagnostics — #4678 throttles verification reads using inFlightReadEntryNumInLedgerChecker, making 100% verification practical for large ledgers without Too many requests failures. #4692 lets readledger -bookie infer omitted -fe/-le bounds, while #4731 fixes ledger iteration across ZooKeeper’s 10,000-ledger ranges.
  • Compatibility — No breaking changes are declared.

4.17.4

Release 4.17.4 includes multiple bug fixes and few dependency updates.

Apache BookKeeper users are encouraged to upgrade to 4.17.4 if you are using 4.17.x. The technical details of this release are summarized below.

Bugs

  • Revert "Fix read thread blocking in sendResponseAndWait causing READ_ENTRY_REQUEST p99 latency spike (#4730)" PR #4830
  • [Fix] Replace Java record with nested class in ConcurrentLongHashMap (branch-4.17) PR #4778
  • [Fix] ConcurrentLongHashMap throw ArrayIndexOutOfBoundsException PR #4771
  • Fix NPE in PendingAddOp.maybeTimeout() when clientCtx is null after recycling PR #4760
  • Fix race condition NPE in V3 response handling during timeout check PR #4737
  • [FIX] Fix IllegalThreadStateException in ComponentStarter shutdown hook PR #4733
  • Issue 2422: Fix SyncLedgerIterator.hasNext() failing to iterate across ZK ledger ranges PR #4731
  • Fix read thread blocking in sendResponseAndWait causing READ_ENTRY_REQUEST p99 latency spike PR #4730
  • Count the connection failure as the condition of quarantine PR #4727
  • [client] fix writeLac memory leak and thread safety issue PR #4713
  • Fix the stream client python package name PR #4703
  • [fix]Fix entry loss due to incorrect lock of LedgerHandle PR #4701
  • [fix] Ledger Replication worker should throttle on verrification reads PR #4678
  • FlakyTest: BookieAutoRecoveryTest.testEmptyLedgerLosesQuorumEventually PR #4672

Improvements

  • [improve] Update readledger command to read all the entries from a bookie when first entry and last entry ids are not provided PR #4692
  • test: migrate client module api tests to junit 5 PR #4377
  • test: migrate client module bookie tests to junit 5 PR #4359

Dependency updates

  • Upgrade vertx to 4.5.27 to address CVE-2026-6860 PR #4792
  • Upgrade thrift to 0.23.0 to address CVE-2026-43869 PR #4791
  • build(deps): bump org.apache.commons:commons-lang3 from 3.17.0 to 3.20.0 PR #4725
  • build(deps): bump io.vertx:vertx-core from 4.5.11 to 4.5.24 PR #4702
