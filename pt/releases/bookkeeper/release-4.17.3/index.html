##4.17.3

A versão 4.17.3 inclui várias correções de bugs e algumas atualizações de dependências.

Os usuários do Apache BookKeeper são incentivados a atualizar para o 4.17.3 se você estiver usando o 4.17.x. Os detalhes técnicos desta versão estão resumidos abaixo.

Erros

  • [Correção] Falha nas entradas de leitura após vários descomissionamentos PR #4613
  • [correção]BK permanece no estado somente leitura mesmo se o disco estiver vazio PR #4640
  • Traga de volta o antigo nome do método público removido de #4640 PR #4682
  • [corrigir]erro de compilação do arquivo native_io_jni.c para o env jdk11 e windows PR #4665
  • Pare Gc apenas para o disco de preenchimento para DbLedgerStorage PR #4661
  • [Correção]Código de erro errado (-102) ao abrir um livro-razão excluído PR #4657
  • Registre todos os erros no GarbageCollectorThread PR #4649

Melhorias

  • suporte equalsAndHashcode para BookieServerInfo PR #4686
  • Suporta configuração de parâmetros relacionados ao TCP Keepalive no Bookie Client. PR #4683 *adicionar limite de taxa para taxa de leitura zk em gc. PR #4645

Atualizações de dependências

  • Atualize netty para 4.1.130 Final PR #4699
  • [segurança] Substitua net.jpountz.lz4:lz4 por at.yawk.lz4:lz4-java PR #4696
  • Atualize OpenTelemetry para 1.56.0, instrumentação Otel para 2.21.0 e Otel semconv para 1.37.0 PR #4690

bookkeeper release-4.17.3

Highlights

  • Garbage collection resilience — GC could hang indefinitely on a corrupt entry log file (#4544); 4.17.3 confines GC-stopping to genuine disk-full conditions on DbLedgerStorage (#4661), logs every GC thread error (#4649), and rate-limits ZooKeeper reads during GC (#4645). Operationally this means fewer silent stalls that quietly consume disk, but expect much noisier GC logs and potentially slower large compactions due to the ZK throttle.

  • Decommissioning and ledger reads — Entry reads could fail after repeated bookie decommissions (#4613), and opening a deleted ledger returned the misleading error code -102 (#4657). Anyone automating rolling decommissions or ledger lifecycle handling should re-check error-code branching — callers keyed on the old value may now take a different path.

  • Read-only recovery and API compatibility — A bookie could remain stuck in read-only even after its disk was reclaimed (#4640); that fix initially removed a public method, and #4682 restores the old public method name. If you tested an intermediate snapshot, re-verify callers — the published 4.17.3 public API is intact.

  • Build and platform support — The native I/O JNI source failed to compile under JDK 11 on Windows (#4665). This matters mainly to teams building from source on Windows/JDK 11 toolchains rather than consuming published binaries.

  • Client networking and bookie views — Bookie clients can now configure TCP keepalive parameters (#4683), useful for long-lived connections through NAT/load balancers, and BookieServerInfo gained equals/hashCode (#4686), fixing dedup problems in set/map-based bookie views.

  • Dependency updates with migration bite — Netty moves to 4.1.130 (#4699) and OpenTelemetry to 1.56.0 / instrumentation 2.21.0 / semconv 1.37.0 (#4690); a security fix swaps net.jpountz.lz4:lz4 for at.yawk.lz4:lz4-java (#4696), and commons-collections (#4689) plus commons-configuration2/commons-beanutils from top-level deps (#4648) are removed. Consumers relying on these transitively must declare them directly, and the LZ4 package change warrants a classpath/shading check before upgrading.

No intentional breaking changes in this release.

4.17.3

Release 4.17.3 includes multiple bug fixes and few dependency updates.

Apache BookKeeper users are encouraged to upgrade to 4.17.3 if you are using 4.17.x. The technical details of this release are summarized below.

Bugs

  • Fix: Garbage collection stuck on corrupt entry log file PR #4544
  • [fix] Failed read entries after multiple decommissioning PR #4613
  • [fix]BK stays at read_only state even if the disk is empty PR #4640
  • Bring back the old public method name which removed from #4640 PR #4682
  • [fix]compile error of the file native_io_jni.c for the env jdk11 & windows PR #4665
  • Only stop Gc for the fill disk for DbLedgerStorage PR #4661
  • [fix]Wrong error code(-102) when opening a deleted ledger PR #4657
  • Log all the error in the GarbageCollectorThread PR #4649

Improvements

  • support equalsAndHashcode for BookieServerInfo PR #4686
  • Supports configuring TCP Keepalive related parameters in Bookie Client. PR #4683
  • add rate limit for zk read rate in gc. PR #4645

Dependency updates

  • Upgrade netty to 4.1.130 Final PR #4699
  • [security] Replace net.jpountz.lz4:lz4 with at.yawk.lz4:lz4-java PR #4696
  • Upgrade OpenTelemetry to 1.56.0, Otel instrumentation to 2.21.0 and Otel semconv to 1.37.0 PR #4690
  • Exclude commons-collections from dependencies PR #4689
  • Remove commons-configuration2 and commons-beanutils from top level dependencies PR #4648
