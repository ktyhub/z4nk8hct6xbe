WeKnora v0.3.2

Highlights

  • Async re-parse & remote-URL ingestion — #679 adds an async knowledge re-parse API (with examples) and #696 lets you create knowledge directly from remote file URLs. Together they let ingestion pipelines re-index existing documents and pull from HTTP/object-storage sources without round-tripping through local uploads. The async shape is the thing to design around: re-parse no longer behaves as a call-and-return, so you'll need to poll status or wire up completion callbacks.
  • Storage & Doc Processor refactor — #704 is the architectural centerpiece and more than an internal cleanup: storage and document processing were overhauled, so any custom storage layer or doc-processor wiring should be treated as having moved integration points. It lands alongside #705, which adds TagID and IsRecommended fields to vector embeddings — a stored-schema change. Plan a re-embed/reindex rather than assuming existing vectors pick up the new fields automatically.
  • Config migration required: MinerU endpoint removed — #706 removes mineru_api_base_url from ParserEngineConfig and related components. If you pointed MinerU at a self-hosted or custom endpoint through that field, it will be ignored (or fail config validation) after upgrade. This is the release's one genuine breaking change — audit parser configs before rolling out.
  • New backends: Milvus & Volcengine TOS — #699 adds Milvus as a retrieval vector DB and #691 adds Volcengine TOS as an object-storage backend, expanding deployment targets if you were pinned to the existing options. They're additive, not replacements, but each is a fresh integration surface — worth validating in staging, especially stacked on top of the #704 storage refactor.
  • Deployment & API-surface changes — Helm's frontend APP_HOST default flipped to app (#694). If you relied on the old default, verify ingress/frontend can still reach the app after a chart upgrade. #698 fixes Swagger generation and regenerates the docs, so regenerate any generated API clients against the new spec. #695 makes form validation tolerate non-boolean responses — relevant if your auth provider returns truthy strings instead of JSON booleans.
  • Chat UX & reasoning-model polish — #689 fixes handling of "thinking" content in Ollama chat responses, so reasoning-model output no longer leaks into or breaks parsing of streamed replies. On the UI side: batch conversation management (#692, plus #703 to load all sessions in batch mode), Mermaid diagram rendering (#702), and a user-level memory-graph preview (#687) — useful if you expose multi-session chat or knowledge graphs to end users.
