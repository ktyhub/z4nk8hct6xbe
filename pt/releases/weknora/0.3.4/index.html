WeKnora v0.3.4

Highlights

  • Native MCP service — #721 adds a built-in MCP server, so external agents and tooling can query knowledge bases directly instead of through bespoke REST glue. For integrators this is the first thing to evaluate: it turns WeKnora from an app you call into a capability surface agents can discover, and may let you delete homegrown adapter code.
  • Vector backend expansion — Weaviate becomes a supported retrieval backend (#737) and the Milvus retriever gets its long-standing bugs fixed (#722). Two caveats for adopters: migration 000017 shipped with broken PostgreSQL dollar-quoting (#739), so validate both fresh installs and upgrades against your Postgres version before rollout; and choosing between Milvus and Weaviate now changes index/ops footprint, not just a config string.
  • API keys encrypted at rest — #733 introduces AES-256-GCM encryption for stored API keys. This is a security posture improvement, but the operational question is key management: find out where the encryption key lives and how (or whether) existing plaintext keys are re-encrypted on upgrade — plan for key rotation or re-entry if not automatic.
  • Multilingual becomes first-class — Frontend hardcoded Chinese strings are replaced with i18n calls (#724), LLM prompts are made language-neutral (#729), with follow-up fixes for vue-i18n placeholder escaping, computed-ref accessors and missing ru-RU keys (#730) and TDesign locale synchronization (#735). Expect answer language to follow the user rather than defaulting to Chinese — a real behavioral change worth testing, especially given the #730 accessor fix which can surface as subtle runtime errors.
  • IM channels, Slack first — A new IM integration layer (#760) gains Slack support in both WebSocket and webhook modes (#773), plus file handling and knowledge-base integration (#767), a tool-invocation/result-formatting refactor (#771), and docs (#775). This is the path to putting WeKnora inside team chat rather than behind a separate UI; webhook vs WebSocket is a deployment decision (firewalling, callback URLs), so pick deliberately.
  • Chunker hard limit and storage backends — The chunker now enforces a 7500-character ceiling (#758) to stop embedding APIs rejecting oversized payloads: documents that previously produced larger chunks will be split differently, which can change retrieval granularity and is worth a relevance regression check. Alongside that, an S3 storage adapter lands (#736) and MinIO endpoint validation now flags stray http:///https:// prefixes (#763) — relevant if you run object storage, since misconfigured endpoints fail more loudly now.
  • Breaking changes — None documented in this release.
