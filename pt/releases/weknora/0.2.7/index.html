WeKnora v0.2.7

Highlights

  • Tabular analysis — New data_schema and data_analysis tools let agents inspect and run SQL over CSV/XLSX/XLS knowledge using in-memory DuckDB (#494). Enable both on reasoning agents; queries are read-only and temporary tables are session-cleaned. Because files are loaded into memory, use bounded queries, and pre-cache DuckDB’s spatial extension for Excel in air-gapped environments.
  • FAQ priority retrieval — first_priority_tag_ids and second_priority_tag_ids now constrain FAQ search and rank first-tier matches ahead of second-tier matches, preventing lower-priority entries from displacing them through higher raw scores (#503). PostgreSQL deployments require migration 000007_embeddings_tag_id; rebuild existing FAQ embeddings to populate tag_id before using priority filters.
  • Custom chunk separators — Users can define arbitrary chunking separators instead of choosing only presets (#505), allowing chunk boundaries to follow structured documents. The setting affects newly generated chunks, so reprocess existing knowledge and re-evaluate retrieval if you need the new boundaries applied.
  • Provider compatibility — OpenAI requests now omit unsupported chat_template_kwargs, eliminating 400 errors; the parameter is sent only for ProviderGeneric backends such as vLLM (#496). Xiaomi’s provider domain is also corrected (#506), so re-test saved Xiaomi configurations after upgrading.
  • Deployment controls — MAX_FILE_SIZE_MB unifies upload, gRPC, and Nginx limits with a 50 MB default; keep reverse-proxy limits aligned to avoid HTTP 413 responses (#502). Docker builds remove the package-upgrade step and the Dockerfile’s default APK_MIRROR_ARG, so restricted-network builds must pass a mirror explicitly (#498, #499). The Debian-based app image also requires rebuilding custom native extensions against glibc (#494).
  • Breaking changes — None announced.
