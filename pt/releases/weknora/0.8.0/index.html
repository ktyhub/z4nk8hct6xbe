WeKnora v0.8.0

Highlights

  • Skill sandbox and breaking backend changes — Agents can now use workspace-scoped sandbox configs, a tenant skill catalog, per-sandbox installs from ClawHub/SkillHub/git URLs, snapshots, injected skill environment variables, and session-scoped containers (#2651, #2769, #2795, #2833, #2852). The local host-process backend is removed: migrate any sandbox_type=local config to Cube, E2B, or Docker before upgrading—legacy rows are delete-only and execution fails (#2815). Docker is disabled by default; enable WEKNORA_SANDBOX_DOCKER_ENABLED=true or System Settings → Network Security only if you accept host-root-equivalent daemon access (#2936).

  • Authentication and invitation behavior — /auth/oidc/start enables direct 302 OIDC login, and id_token signatures are now verified through JWKS (#2647, #2927); users can also change passwords from their profiles (#2591, #2596). In invite_only mode, invitation links require login before joining a workspace, with optional auto-accept for registered users (#2627, #2633). Enabling WEKNORA_AUTH_COMPLEX_PASSWORD_ENABLED makes mixed case, digits, and special characters mandatory for new registrations, password changes, and resets, without invalidating existing credentials (#2929).

  • In-process document parsing and ingestion hardening — The standard app image now links the anydoc Go engine (#2702, #2721), alongside improved PPT/PPTX, XMind, DOCX-table, merged-cell, and PDF-image handling (#2621, #2713, #2898, #2657, #2775). Anydoc 0.1.9 bounds malicious-PDF parsing costs (#2720). Custom app images must be rebuilt to include the engine, and build_images.sh now uses BuildKit (#2287). Outbound-URL SSRF defenses and Markdown-table parsing were also hardened (#2626, #2770, #2935).

  • Retrieval correctness and performance — Query-understanding failures now fall back to the original query (#2592); MatchCount=0 no longer wipes all hybrid-search results, match counts are normalized, and resource_urls=public is honored (#1156, #2750, #2814). Incremental MMR reduces knowledge-search selection overhead (#2737), while chunk fixes preserve child embeddings, stop dropping repeated contiguous text, exclude deleted images, and sanitize persisted context headers (#2680, #2686, #2730, #2701).

  • Durable agent memory and cost observability — Cross-session long-term memory adds /api/v1/memory/* endpoints and a Go client (#2689, #3009). Per-turn LLM token usage is now reported and attributed (#2772), follow-up and sandbox spans are nested under chat traces (#2904), and stable prompt prefixes plus provider cache markers support better cache reuse (#3002). Teams should review privacy and retention policies for the newly stored memory and token-usage data.

  • Broader model, search, and datasource ecosystem — LiteLLM is now a model provider (#2923), Exa and Metaso add web-search options (#2617, #2625), and GitLab and Tencent IMA connectors expand document ingestion with real per-source sync deletions (#2656, #2662, #2690). A DeepSeek Harness plugin exposes WeKnora retrieval tools to external agents (#2759). Lite-mode deployments also receive missing versioned SQLite migrations (#2749); back up existing Lite databases before upgrading.
