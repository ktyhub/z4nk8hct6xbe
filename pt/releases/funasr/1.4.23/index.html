FunASR 1.4.23

Fonte: efe5504e388613e5298e1f93d5ca9f861700b489/tag v1.4.23.

Correção

Entrega # 3849: inicialize o cursor de quadro válido para o frontend online com lfr_m=lfr_n=1 e evite pedaços VAD offline finais vazios e redundantes para múltiplos de entrada exatos. Entrega #3783: mapa de IDs token_list fornecidos para peças do modelo antes da conversão de texto. Com um vocabulário fornecido, SentencePiece ids2tokens retorna peças list[str]; use tokens2text para texto. Sem um vocabulário fornecido, o comportamento do texto decodificado legado é preservado.

Isso não reivindica qualidade ASR pré-treinada, aceitação do Windows/NPU ou um resultado completo do conjunto de repositórios.

Os funasr-onnx==0.4.9 e funasr-torch==0.1.6 lançados separadamente possuem suas próprias tags, embalagens e verificação. Esta versão do pacote raiz não os republica. PR #3848 não está incluído. Entrada vazia de streaming explícita e caudas não vazias que produzem zero recursos estão fora da aceitação de hardware #3849; esta versão não afirma que todos os caminhos EOS foram corrigidos.

FunASR v1.4.23

Highlights

  • No-LFR online frontend — #3849 initializes the valid-frame cursor for lfr_m=lfr_n=1, fixing default online feature/chunk handling. Streaming empty input and nonempty tails producing zero features remain outside its hardware acceptance, so not every EOS path is covered.
  • ONNX empty-input handling — #3846 removes redundant empty final offline VAD chunks for exact input multiples, while #3847 prevents empty punctuation input from consuming cache. This avoids spurious empty segments and protects stateful processing context.
  • Tokenizer vocabulary semantics — #3783 resolves supplied token_list IDs to model pieces before text conversion. With a supplied vocabulary, SentencePiece ids2tokens() returns list[str]; call tokens2text() when text is required. Pipelines without a supplied vocabulary retain legacy decoded-text behavior.
  • Runtime package separation — funasr==1.4.23 does not republish funasr-onnx==0.4.9 or funasr-torch==0.1.6; adopt the separately released ONNX package from #3850 to obtain its VAD and punctuation fixes. PR #3848 is not included.
  • Verification limits — Acceptance covers CPU/offline fixtures and package integrity, not a full repository suite or pretrained-quality evaluation. Attached llama.cpp binaries reuse unchanged runtime-llamacpp-v0.2.6 assets and were not rebuilt or rerun; no new GPU, Windows, or NPU acceptance is claimed.
  • Compatibility — No breaking changes are declared; update custom vocabulary decoding to use tokens2text() where text is required.

FunASR 1.4.23

Source: efe5504e388613e5298e1f93d5ca9f861700b489 / tag v1.4.23.

Fix

Deliver #3849: initialize the valid-frame cursor for the online frontend with lfr_m=lfr_n=1, and avoid redundant empty final offline VAD chunks for exact input multiples. Deliver #3783: supplied token_list IDs map to model pieces before text conversion. With a supplied vocabulary, SentencePiece ids2tokens returns list[str] pieces; use tokens2text for text. Without a supplied vocabulary, legacy decoded-text behavior is preserved.

This does not claim pretrained ASR quality, Windows/NPU acceptance or a full repository-suite result.

The separately released funasr-onnx==0.4.9 and funasr-torch==0.1.6 have their own tags, packages and verification. This root-package release does not republish them. PR #3848 is not included. Explicit streaming-empty-input and nonempty tails producing zero features are outside the #3849 hardware acceptance; this release does not claim every EOS path is fixed.

Verification Scope

  • New candidate release/README checks: 45 cases, 0 skips. Related docs/package/release checks: 104 cases, 2 explicitly recorded skips; no failures or errors.
  • Actual installed candidate and final wheels: 61 CPU contracts each covering no-LFR feature/chunk handling, analytic VAD finalization and tokenizer vocabulary semantics. Local tiny SentencePiece and controlled acoustic fixtures are not pretrained quality or hardware inference. All 439 package files and 13 entrypoints match the accepted source.
  • Reused 16 direct FP32/BF16 frontend cases, 12 FP32 VAD cases and 12 FP32/BF16 tokenizer/decoder cases from #3849/#3783 after rehashing their sealed raw receipts and binding the exact source to the installed wheel. The earlier frontend run's six failed VAD cases remain recorded; the later corrected VAD run passed all 12. This release performs no new GPU execution and makes no pretrained-quality claim.
  • The local candidate build and candidate/final package checks, tests and installations use private HOME/cache directories and separate network namespaces with verified network-unreachable probes. The final-tag build runs in GitHub Actions under the existing release workflow, not the local network namespace. No newly downloaded pretrained weights are used. The separately reported #3848 test-download incident is not an authorization or validation input for this release.
  • Exact release-head and merged-main CI were accepted from their actual logs, with artifact inventories recorded. The final-tag workflow and the newly downloaded Python wheel/sdist passed byte/metadata/archive/source checks, strict Twine, offline installation, actual import and CLI checks.
  • The 10 unchanged runtime archives reuse complete cache bytes freshly hashed against new asset metadata and the existing runtime source release. They were not rebuilt or re-executed. SHA256SUMS covers all 12 payloads. This is not a new runtime-hardware claim.
  • No full repository-suite, production-environment upgrade, Nano benchmark or adoption/growth claim is made.
