#FastGPT v4.16.1

📦 Guia de atualização

Atualizar variáveis de ambiente do Agent Sandbox e imagem em execução

Ao habilitar o Agent Sandbox, verifique a seguinte configuração em fastgpt-app e fastgpt-pro simultaneamente. 4.16.1 usa o endereço completo da imagem em execução:

# 普通非 root 镜像，默认配置
AGENT_SANDBOX_OPENSANDBOX_IMAGE=registry.cn-hangzhou.aliyuncs.com/fastgpt/fastgpt-agent-sandbox:v0.3.1

Se o sandbox precisar instalar dependências do apt, você deverá mudar para a imagem raiz; se necessário, você pode configurar a fonte da imagem apt:

AGENT_SANDBOX_OPENSANDBOX_IMAGE=registry.cn-hangzhou.aliyuncs.com/fastgpt/fastgpt-agent-sandbox-root:v0.3.1
AGENT_SANDBOX_APT_MIRROR=https://mirrors.tuna.tsinghua.edu.cn/ubuntu

Para obter uma lista completa de fontes de espelho da China continental e fontes de espelho globais, seleção de espelho raiz/não raiz e configuração de fonte de dependência personalizada, consulte Configuração do OpenSandbox.

Ferramenta de migração JSON Formato de armazenamento de esquema

Execute a migração estritamente na seguinte ordem de versão:

  1. Depois de garantir que a versão 4.16.0 do script initHttpToolSchema seja executada, converta os parâmetros da matriz de histórico da ferramenta HTTP manual no esquema JSON padrão.
  2. Após atualizar para 4.16.1, execute initToolJsonSchemaStorage nesta seção.

4.16.1 verificará a aplicação da ferramenta HTTP e sua versão histórica responsável pelo 4.16.0; se os dados ainda contiverem tipos de array antigos, a interface se recusará a executar para evitar que os dados antigos sejam convertidos diretamente em strings. A migração lida apenas com aplicativos de ferramentas MCP/HTTP e suas versões históricas, e não com aplicativos de fluxo de trabalho comuns.

4.16.1 unifica o esquema JSON de ferramentas MCP/HTTP em armazenamento de string. Você pode executar um teste primeiro para verificar as alterações:

curl -X POST 'https://你的域名/api/admin/4161/initToolJsonSchemaStorage' \
  -H 'Content-Type: application/json' \
  -H 'rootkey: 你的ROOT_KEY' \
  -d '{"dryRun":true}'

Após confirmar o total.changedDocumentCount, realize a migração oficial:

curl -X POST 'https://你的域名/api/admin/4161/initToolJsonSchemaStorage' \
  -H 'Content-Type: application/json' \
  -H 'rootkey: 你的ROOT_KEY' \
  -d '{"dryRun":false}'

🚀 Novo conteúdo

  1. Canais de publicação de terceiros, com suporte para arquivos multimodais, transcrição de áudio e citações (se houver)
  2. Apoie a equipe na instalação de plug-ins do sistema (modo de processo, existem certos riscos de segurança, versões futuras suportarão operação isolada sem servidor).
  3. O sandbox oferece suporte a fontes apt personalizadas.

⚙️ Otimização

  1. Nomeação da chave S3, cancele o nome do arquivo original como chave para evitar que seja muito longo.
  2. O esquema MCP/HTTP json usa armazenamento do tipo String para evitar que objetos personalizados entrem em conflito com as regras do mongo.

🐛 Correção

  1. Na configuração da variável global do fluxo de trabalho, o nome do campo é muito longo e transborda.
  2. AgentV2 chama o subfluxo de trabalho e o conteúdo de saída do fluxo dentro do fluxo de trabalho não é desabilitado.
  3. Link de convite da equipe, você pode receber o mesmo convite da equipe repetidamente.
  4. Utilizando registros, o selecionador de data terá mais um dia.

🛠️ Otimização de código

  1. Preencha todos os documentos da interface devapi.
  2. Inicialização simultânea do sistema plug-in e otimização de log.
  3. Corrigido o problema em que erros durante a operação do plug-in eram gerados como erros do sistema.
  4. Corrigido o problema causado pela política --allow-net não ser definida quando a versão do plug-in Node.js é superior à v25.

FastGPT v4.16.1

Highlights

  • Mandatory two-step JSON Schema migration — The highest-risk item in this release: MCP/HTTP tool schemas now store as strings to avoid Mongo rule conflicts with custom objects (PR #7497), and you cannot skip ahead. You must first complete 4.16.0's initHttpToolSchema on manual HTTP tools, then run 4.16.1's initToolJsonSchemaStorage; the endpoint deliberately rejects any HTTP tool data still in the old array form rather than silently stringifying it. Scope is limited to MCP/HTTP tool apps and their history versions — regular workflows are untouched. Always POST with {"dryRun":true} first and inspect total.changedDocumentCount before the real run.

  • Agent Sandbox image/config rewrite — 4.16.1 switches to fully-qualified runtime image addresses, so check AGENT_SANDBOX_OPENSANDBOX_IMAGE in both fastgpt-app and fastgpt-pro, not just one. If your sandbox installs apt packages you must move to the -root:v0.3.1 variant; custom apt mirrors are now supported via AGENT_SANDBOX_APT_MIRROR (PR #7537). Watch out: staying on the non-root image while adding apt steps will fail at runtime.

  • Richer third-party publish channels — Outlink messages now carry multimodal files, audio transcription, and citations (PR #7353), plus published MCP servers now align their auth with API keys (PR #7364). If you build on the outlink/MCP surface, this materially expands what a shared published app can deliver — but verify your auth expectations against the new API-key alignment.

  • Team-installed system plugins, with a security caveat — Teams can now install system plugins directly, with tool-selector filters (PR #7485). These run in process mode, which the maintainers explicitly flag as a security risk; serverless isolation is promised later. Treat team plugin installs as a trust decision, not just a convenience feature.

  • Plugin runtime hardening — Concurrent plugin initialization and error logging are improved, plugin errors no longer bubble up as system errors, and a Node.js > v25 bug caused by a missing --allow-net policy is fixed. If you run newer Node in plugin environments, this is the fix that unblocks you; elsewhere it means cleaner separation between plugin faults and platform faults.

  • Storage/UI behavior changes — S3 object keys are decoupled from original filenames to prevent overlong keys (PR #7547), so anything that assumed the filename was derivable from the key needs revisiting. Also fixed: duplicate team invitation acceptance via a new unique index (PR #7563, requires index creation on upgrade), hidden child-tool stream output in AgentV2 (PR #7550), long-variable-name overflow, and an off-by-one in the usage-record date picker.

No breaking API changes — but the JSON Schema migration is effectively mandatory.

📦 升级指南

更新 Agent Sandbox 环境变量和运行态镜像

启用 Agent Sandbox 时，请在 fastgpt-app 和 fastgpt-pro 中同步检查以下配置。4.16.1 使用完整的运行态镜像地址：

# 普通非 root 镜像，默认配置
AGENT_SANDBOX_OPENSANDBOX_IMAGE=registry.cn-hangzhou.aliyuncs.com/fastgpt/fastgpt-agent-sandbox:v0.3.1

如果沙盒需要安装 apt 依赖，必须切换为 root 镜像；如需要，可配置 apt 镜像源：

AGENT_SANDBOX_OPENSANDBOX_IMAGE=registry.cn-hangzhou.aliyuncs.com/fastgpt/fastgpt-agent-sandbox-root:v0.3.1
AGENT_SANDBOX_APT_MIRROR=https://mirrors.tuna.tsinghua.edu.cn/ubuntu

中国大陆镜像源和全球镜像源的完整镜像列表、root/non-root 镜像选择，以及自定义依赖源配置，请参考 OpenSandbox 配置。

迁移工具 JSON Schema 存储格式

请严格按以下版本顺序执行迁移：

  1. 在确保执行完成 4.16.0 版本的 initHttpToolSchema 脚本，将手动 HTTP 工具的历史数组参数转换为标准 JSON Schema。
  2. 升级到 4.16.1 后，再执行本节的 initToolJsonSchemaStorage。

4.16.1 会检查 4.16.0 负责的 HTTP 工具应用及其历史版本；如果这些数据仍包含旧数组类型，接口会拒绝执行，避免旧数据被直接转换为字符串。迁移只处理 MCP/HTTP 工具应用及其历史版本，不处理普通工作流应用。

4.16.1 将 MCP/HTTP 工具的 JSON Schema 统一为字符串存储。可先执行 dry-run 检查变更情况：

curl -X POST 'https://你的域名/api/admin/4161/initToolJsonSchemaStorage' \
  -H 'Content-Type: application/json' \
  -H 'rootkey: 你的ROOT_KEY' \
  -d '{"dryRun":true}'

确认 total.changedDocumentCount 后执行正式迁移：

curl -X POST 'https://你的域名/api/admin/4161/initToolJsonSchemaStorage' \
  -H 'Content-Type: application/json' \
  -H 'rootkey: 你的ROOT_KEY' \
  -d '{"dryRun":false}'

🚀 新增内容

  1. 第三方发布渠道，支持多模态文件、音频转录、引用（如有）
  2. 支持团队安装系统插件（进程模式，存在一定安全风险，未来版本支持 serverless 隔离运行）。
  3. 沙盒支持自定义 apt 源。

⚙️ 优化

  1. S3 key 命名，取消原文件名作为 key，防止超长。
  2. MCP/HTTP json schema 采用 String 类型存储，防止自定义对象与 mongo 规则冲突。

🐛 修复

  1. 工作流全局变量配置，字段名太长溢出。
  2. AgentV2 调用子工作流，工作流内流输出内容未禁用。
  3. 团队邀请链接，可重复接收同一个团队邀请。
  4. 使用记录，日期选择器会多一天。

🛠️ 代码优化

  1. 补全所有 devapi 接口文档。
  2. 插件系统并发初始化以及日志优化。
  3. 修复插件运行中的错误会抛出为系统错误的问题。
  4. 修复插件在 Node.js 版本高于 v25 时由于 --allow-net 策略未设置导致的问题。
