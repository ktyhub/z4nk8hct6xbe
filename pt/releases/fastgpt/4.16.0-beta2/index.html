#FastGPT v4.16.0-beta2

📦 Guia de atualização

1. Limpe a configuração histórica do modelo do sistema

Esta versão começa a usar Schema estrito ao inicializar e salvar modelos de sistema. Strings numéricas, gradientes de preço em formato de string ou campos ausentes salvos em versões anteriores podem causar falha na verificação inicial. Após a atualização, execute primeiro o teste para visualizar a configuração do modelo que precisa ser processada; a simulação não modificará os dados nem atualizará o cache:

curl -X POST 'https://你的域名/api/admin/dataClean/cleanSystemModelConfigs' \
  -H 'Content-Type: application/json' \
  -H 'rootkey: 你的ROOT_KEY' \
  -d '{"dryRun":true}'

Após confirmar que não há dados no invalidSamples que requeiram processamento manual, realize a limpeza formal:

curl -X POST 'https://你的域名/api/admin/dataClean/cleanSystemModelConfigs' \
  -H 'Content-Type: application/json' \
  -H 'rootkey: 你的ROOT_KEY' \
  -d '{"dryRun":false}'

A limpeza converte strings numéricas legais em números, converte priceTiers como uma string em uma matriz e remove números opcionais ilegais. Números obrigatórios ilegais ou ausentes usam os valores padrão do sistema: maxContext/maxResponse/quoteMaxToken para LLM é 16000/16000/13000, defaultToken/maxToken para incorporação é 500/3000 e o preço é 0. functionCall permanece opcional e o weight ausente na incorporação é substituído por 0.

A execução formal grava dados de maneira uniforme e atualiza imediatamente o cache do modelo do sistema; o cache de tempo de execução é reconstruído mesmo se não houver registros para atualizar. A interface é segura para ser executada novamente; quando for executado novamente, wouldUpdate deverá ser 0. Os registros que não puderem passar pelo esquema completo do modelo atual não serão gravados e todos os detalhes serão retornados em invalidSamples.

🚀 Novo conteúdo

  1. A configuração do sistema da aplicação de workflow é movida para o painel de configuração independente na barra de ferramentas do lado esquerdo da tela, que será aberta automaticamente ao criar uma nova aplicação de workflow.
  2. A declaração de abertura suporta configuração independente de várias perguntas predefinidas e pode ser classificada arrastando e soltando.

⚙️ Otimização

  1. Reconstrua a página do canal de lançamento, exiba-a em grupos por canais nativos e canais de terceiros e exiba a quantidade configurada de cada canal.
  2. A atualização em lote do mercado de ferramentas suporta a exibição de alguns itens com falha, nova tentativa ou desinstalação individualmente e melhora a exibição de versões instaladas e status de atualização.
  3. O limite superior do número de aplicativos rápidos na página do portal é ajustado para 3, e as configurações históricas que excederam o limite superior são compatíveis.
  4. O analisador de PDF usa corte dinâmico de bordas em vez de corte fixo de bordas para evitar o corte do conteúdo real.

🐛 Correção

  1. Corrigido o problema de que os parâmetros dinâmicos da versão antiga da ferramenta HTTP de fluxo de trabalho não restauravam corretamente o método de entrada padrão.
  2. Corrigido o problema de que ao criar uma nova aplicação de fluxo de trabalho, os recursos internacionais não eram pré-carregados, fazendo com que a cópia da configuração inicial ficasse anormal.
  3. Corrigido o problema em que os parâmetros da ferramenta de fluxo de trabalho podiam ser renderizados repetidamente.
  4. Corrigido o problema em que as variáveis ​​de arquivo não podiam fazer upload de arquivos após o lançamento do aplicativo.
  5. Corrigido o problema de que o parâmetro de arquivo da ferramenta de fluxo de trabalho compartilhado não consegue fazer upload de arquivos.
  6. Corrigido um problema em que chaves de objeto S3 e nomes de arquivos contendo caracteres especiais, como espaços, %, #, ? e barras, podiam causar upload, análise, visualização ou download anormais.
  7. Corrigir o problema de que o modelo padrão do sistema não filtra informações confidenciais, de modo a evitar que a resposta da interface de inicialização do sistema retorne a chave do modelo API, endereço de solicitação e configuração interna.

🛠️ Otimização de código

  1. O arquivo de log de auditoria não será mais excluído, mas será transferido para o arquivo frio do S3.
  2. Adicione verificação e limpeza de dados para configuração administrativa.
  3. Cancele o SSR da conta/* página.

FastGPT v4.16.0-beta2

Highlights

  • Mandatory system-model data migration — Model initialization and saves now enforce a strict schema, so legacy numeric strings, serialized priceTiers, and missing required fields can block startup. Run POST /api/admin/dataClean/cleanSystemModelConfigs with {"dryRun":true}, resolve any invalidSamples, then run it with {"dryRun":false}; the operation is idempotent and rebuilds the system-model cache even when no records change. Missing required numbers fall back to documented defaults, including LLM maxContext/maxResponse/quoteMaxToken of 16000/16000/13000, Embedding defaultToken/maxToken of 500/3000, and price 0.

  • Security hardening removes credential exposure — Default models are now sanitized in system-initialization responses, preventing model API keys, request URLs, and internal configuration from leaking through that endpoint. Integrations that previously consumed those fields from initialization data must obtain credentials through an authorized configuration path instead (#7519). S3 key handling also now safely supports spaces and characters such as %, #, ?, and /, while preserving deletion of legacy keys rejected by current validation (#7468, #7509).

  • Workflow configuration and file handling are more reliable — Workflow system settings move to a dedicated left-toolbar panel that opens automatically for new apps (#7454). File uploads are fixed for published apps, shared workflow tools, and node debugging; external variables are consistently exposed as workflow inputs while explicit input modes are preserved (#7472, #7504, #7506, #7510). This removes several environment-specific upload failures and prevents inherited or duplicated tool-parameter rendering from disrupting workflow configuration.

  • Release operations change materially — Tool Marketplace batch updates can now show partial failures and retry or unload individual plugins instead of requiring an all-or-nothing recovery path (#7444). Audit logs are no longer deleted: they are archived to S3, so deployments need archive storage and permissions configured, and retention/recovery procedures should account for cold-stored records. Publish-channel UI now separates native and third-party channels and reports configured counts (#7456).

  • Model execution and deployment compatibility fixes — Responses ending with reasoning-only tool_calls are no longer misclassified as empty, avoiding dropped tool-call output in agent workflows (#7517). Zod contracts are aligned with runtime data, ESM imports and documentation builds receive compatibility fixes, and OpenSandbox adopts Cilium isolation plus filesystem-based stream handling (#7499, #7500, #7514). Operators should review sandbox networking prerequisites, and note that Helm charts and their release workflow have moved to fastgpt-pro (#7463).

Breaking changes: strict model validation requires the documented cleanup; audit logs now archive to S3 instead of being deleted; Helm distribution moves to fastgpt-pro.

📦 升级指南

1. 清洗历史系统模型配置

本版本开始在系统模型初始化及保存时使用严格 Schema。此前版本保存的数字字符串、字符串形式的价格梯度或缺失字段可能导致初始化校验失败。升级后请先执行 dry-run，查看需要处理的模型配置；dry-run 不会修改数据或刷新缓存：

curl -X POST 'https://你的域名/api/admin/dataClean/cleanSystemModelConfigs' \
  -H 'Content-Type: application/json' \
  -H 'rootkey: 你的ROOT_KEY' \
  -d '{"dryRun":true}'

确认 invalidSamples 中没有需要人工处理的数据后，执行正式清洗：

curl -X POST 'https://你的域名/api/admin/dataClean/cleanSystemModelConfigs' \
  -H 'Content-Type: application/json' \
  -H 'rootkey: 你的ROOT_KEY' \
  -d '{"dryRun":false}'

清洗会将合法数字字符串转换为 number、将字符串形式的 priceTiers 转换为数组，并删除非法的可选数字。非法或缺失的必填数字使用系统默认值：LLM 的 maxContext/maxResponse/quoteMaxToken 分别为 16000/16000/13000，Embedding 的 defaultToken/maxToken 分别为 500/3000，价格为 0。functionCall 保持可选，Embedding 缺失的 weight 补为 0。

正式执行会统一写入数据并立即刷新系统模型缓存；即使没有记录需要更新，也会重新构建运行时缓存。接口可安全重复执行；再次 dry-run 时，wouldUpdate 应为 0。无法通过当前完整模型 Schema 的记录不会写入，详情会全部返回在 invalidSamples 中。

🚀 新增内容

  1. 工作流应用的系统配置移至画布左侧工具栏中的独立配置面板，新建工作流应用时会自动打开。
  2. 开场白支持独立配置多个预设问题，并可拖拽排序。

⚙️ 优化

  1. 重构发布渠道页面，按原生渠道和第三方渠道分组展示，并显示各渠道已配置数量。
  2. 工具市场批量更新支持展示部分失败项、单独重试或卸载，并完善已安装版本和更新状态的展示。
  3. 门户页快捷应用数量上限调整为 3 个，并兼容已超出上限的历史配置。
  4. PDF 解析器动态边缘裁剪，而不是固定边缘裁剪，避免裁剪掉真实内容。

🐛 修复

  1. 修复旧版工作流 HTTP 工具的动态参数未正确恢复默认输入方式的问题。
  2. 修复新建工作流应用时，国际化资源未预加载导致初始配置文案异常的问题。
  3. 修复工作流工具参数可能被重复渲染的问题。
  4. 修复应用发布后，文件变量无法上传文件的问题。
  5. 修复共享工作流工具的文件参数无法上传文件的问题。
  6. 修复 S3 对象键和文件名包含空格、%、#、?、斜杠等特殊字符时，可能导致上传、解析、预览或下载异常的问题。
  7. 修复系统默认模型未进行敏感信息过滤的问题，避免系统初始化接口响应返回模型 API Key、请求地址及内部配置。

🛠️ 代码优化

  1. 审计日志归档，不再删除，改成转存到 S3 冷归档。
  2. 增加对 admin 配置的数据校验和清洗。
  3. 取消 account/* 页面 SSR。
