#FastGPT v4.17.3

Guia de atualização

Mudanças de configuração

  • A versão Node.js implantada a partir do código fonte deve atender ^22.23.4 || ^24.22.1 || ^26.12.1. Confirme se o ambiente operacional atende a essa faixa antes de atualizar.
  • DEFAULT_TEAM_BASIC_PERMISSIONS_ENABLED ainda tem como padrão false; quando ativado, o grupo padrão de todos os membros de uma nova equipe não receberá apenas permissão para criar aplicativos, habilidades e bases de conhecimento, mas também a permissão de criação de chave API. As equipes existentes não receberão automaticamente permissões adicionais.
  • O limite superior total de instâncias ativas do sandbox do Agente foi alterado para ser configurado através do AGENT_SANDBOX_MAX, com valor padrão de 100. A cota é compartilhada entre sessões da aplicação e edição de habilidades; o AGENT_SANDBOX_MAX_EDIT_DEBUG original não é mais usado. Adicionado AGENT_SANDBOX_MAX_PER_TEAM para definir o limite superior para uma única equipe. Não há limite por padrão. A configuração de cotas no console de gerenciamento de versão comercial tem precedência sobre variáveis ​​de ambiente.
  • OpenSandbox adiciona AGENT_SANDBOX_CPU_OVERCOMMIT_FACTOR e AGENT_SANDBOX_MEMORY_OVERCOMMIT_FACTOR, o valor padrão é 1 e o valor não deve ser inferior a 1. Só entra em vigor quando Kubernetes está em execução e o servidor OpenSandbox não é inferior a v0.2.1. A reserva de recursos é reduzida, mas o limite superior do recurso permanece inalterado. Afeta apenas sandboxes recém-criadas ou reconstruídas.
  • O console de gerenciamento da versão comercial adicionou "Número máximo simultâneo de recuperações de vetores" (systemEnv.vectorRecallConcurrency), que permite configuração de 0-1000. O valor padrão de 0 significa sem limite. Os números positivos limitam a simultaneidade de recuperação compartilhada de todas as instâncias de serviço e todas as bibliotecas de vetores; a versão de código aberto não permite esse limite e não possui variáveis ​​de ambiente correspondentes.
  • Adicionado AUXILIARY_GENERATION_SHOW_RUN_DETAIL, padrão false, para controlar se serão exibidos os dados de entrada da operação gerados por habilidades, agentes e assistência ao fluxo de trabalho.
  • O endereço padrão do App Market (MARKETPLACE_URL) é atualizado para https://v3.marketplace.fastgpt.cn, e o endereço personalizado configurado explicitamente continua a usar o valor original.

Script de atualização

O sistema primeiro conclui as tarefas de inicialização necessárias e sua cadeia de dependências de pré-requisitos e, em seguida, cada instância do aplicativo recarrega o modelo e inicia o negócio. As três novas tarefas a seguir são executadas automaticamente em segundo plano, com um máximo de três cotas simultâneas no cluster compartilhado. A falha não bloqueará tarefas não dependentes; você pode visualizar os resultados na página de gerenciamento, reparar os dados com falha e tentar novamente.

  • Afiliação de equipe de instância de sandbox de backfill (20261009_backfill_agent_sandbox_team_id): Conclua a afiliação de equipe de instâncias históricas com base em aplicativos de origem ou habilidades para estatísticas de cota de equipe; registros órfãos com fontes excluídas são ignorados e contados.
  • Preencher caminhos ancestrais de diretórios (20261022_backfill_folder_ancestor_ids): recria caminhos de diretórios de aplicativos, ferramentas e bases de conhecimento e limpa campos residuais de recursos que não sejam de pastas. As pastas penduradas diretamente em outros tipos de árvores de diretório são movidas para o diretório raiz desta equipe e as antigas permissões de herança pai são limpas; caminhos ancestrais de árvore cruzada de nível superior são truncados nos limites. Registros de exceção, como pais ausentes, equipes cruzadas ou loops, são retidos como itens com falha e serão repetidos após o reparo.
  • Migrar preço do modelo do sistema para milhões de unidades (20261025_token_prices_per_million): Converta o preço histórico do modelo do sistema e grave-o em pricing, retenha o valor original do campo antigo e pule o modelo que já possui pricing legal; o modelo de equipe não participa da migração.

Instruções de compatibilidade

  • ativação root e senha: remova DEFAULT_ROOT_PSW, a inicialização não substituirá mais a senha root existente. A senha inicial para um novo root é 123456. Você precisa definir uma nova senha ao fazer login pela primeira vez; quando a raiz histórica status não é salva, você precisa usar a senha original para fazer login e concluir a ativação. As alterações diárias de senha são realizadas na página de informações da conta. Quando você esquecer sua senha, use o script de redefinição de senha root e forneça a nova senha explicitamente.
  • Unidade de preço do modelo: LLM usa pricing.tiers, outros modelos usam pricing.unitPrice. Preço unitário do token e escada maxInputTokens O limite superior é alterado para um milhão de tokens, o TTS é alterado para um milhão de caracteres, o STT ainda é a cada 60 segundos e o preço unitário é mantido com duas casas decimais. Após a atualização, confirme se a migração em segundo plano foi bem-sucedida e verifique o preço do modelo do sistema; os modelos de sistema que não foram migrados para pricing são temporariamente tratados como gratuitos e os modelos de equipe são gratuitos.
  • Verificação de orquestração de fluxo de trabalho: Canvas, depuração e geração auxiliar seguem uniformemente [regras de organização] (/guide/build/workflow/rules). Loopbacks seriais puros, conexões de processo entre ferramentas e vários nós de chamada compartilhando a mesma entrada de ferramenta são proibidos, e o refluxo controlado por saídas de condição válidas é permitido. Os subprocessos da ferramenta podem ler o upstream do chamador, mas não podem fazer referência à saída que o próprio chamador não produziu. O fluxo de trabalho antigo mantém as conexões existentes e pode salvar rascunhos. As conexões que não atendem às regras precisam ser corrigidas antes da depuração e publicação.
  • Permissões de gerenciamento da base de conhecimento: Modificar as informações básicas da base de conhecimento, configuração do modelo e seus próprios atributos, como nomes de arquivos, tags, status desativado, etc. requer permissões gerenciáveis ​​(manage); as operações de conteúdo continuam a usar as permissões de edição originais. A modificação de atributos ao mover um arquivo também requer permissões administrativas para o arquivo.
  • Exportação de base de conhecimento: /api/core/dataset/exportAll suporta apenas uma única base de conhecimento e a exportação de diretório precisa ser solicitada por base; quando as permissões em nível de arquivo estão habilitadas, somente os arquivos legíveis pelos membros atuais serão exportados.
  • Tipo de arquivo de conversa: Adicionados document e unknown à categoria de anexo; os antigos parâmetros de entrada e registros históricos do file continuam compatíveis e são classificados por nome de arquivo, link e informações de resposta. O cliente customizado deverá ser compatível com a nova classificação e não utilizar mais apenas o file para julgar documentos.
  • Paging e resposta a erros: A paginação geral tratará pageSize excedendo 500 como 500, e algumas interfaces ainda possuem restrições menores; quando offset e pageNum são transmitidos ao mesmo tempo, offset será usado primeiro, incluindo offset=0, e deslocamentos ilegais não serão revertidos para números de página. A solicitação API identificada como um erro de configuração do usuário retorna HTTP 400 e a parte de acesso precisa tratá-la como uma resposta de falha.

FastGPT v4.17.3

Highlights

  • Runtime and upgrade path — Source deployments now require Node.js ^22.23.4 || ^24.22.1 || ^26.12.1 (images use 24.22.1). DEFAULT_ROOT_PSW is removed: existing root passwords are no longer overwritten, new roots start with 123456 and must set a password on first login, and legacy roots without status must activate with their existing password. Three background migrations backfill sandbox team ownership, folder ancestors and pricing; retry failures before trusting quotas, ACL paths or billing. SeekDB data now survives container restart/recreation (#7942).
  • Billing units change — LLM pricing.tiers and other models’ pricing.unitPrice now express prices per million tokens; tier maxInputTokens is also in millions, TTS is per million characters, and STT remains per 60 seconds, rounded to two decimals. Migration preserves legacy fields and skips valid pricing; team models are excluded. Audit migrated system-model prices—unmigrated system models and team models are treated as free.
  • Workflow/Agent authoring — Pro adds resumable assisted workflow generation, but candidates still require manual application, inspection and debugging before save/publish; it needs edit rights plus assisted-generation and sandbox capabilities. Variables can now supply select options, passwords, tool secrets and HTTP/MCP auth headers. Canvas, debug and assistance share stricter validation: pure serial loops, cross-tool edges and multiple callers sharing one tool entry are rejected, while valid conditional backflow is allowed. Existing invalid drafts remain editable but must be corrected before debug/publish.
  • Permissions and tenant isolation — Team members can configure isolated models/channels with AI Proxy integration (#7895), and owners can bulk-replace invalid model references. Dataset metadata, model and file-attribute changes—including file moves—now require manage; content operations retain edit. App test/debug paths enforce edit rights before node execution and run system tools as the actual member (#7927). Cross-team PG/OpenGauss recall and cross-dataset image access are fixed; folder inheritance is opt-in at creation (#7966).
  • Sandbox capacity controls — Replace AGENT_SANDBOX_MAX_EDIT_DEBUG with AGENT_SANDBOX_MAX (default 100), shared by app sessions and skill editing; AGENT_SANDBOX_MAX_PER_TEAM adds a per-team cap and defaults to unlimited. Kubernetes with OpenSandbox Server ≥ v0.2.1 supports CPU/memory overcommit factors (default and minimum 1), lowering reservations without raising hard limits and affecting only new/rebuilt sandboxes. Pro admin quota settings override environment variables (#7917).
  • API and integration contracts — Pagination caps pageSize at 500 (some endpoints lower), prefers offset over pageNum even for offset=0, and no longer falls back on invalid offsets; recognized user-config errors return HTTP 400. /api/core/dataset/exportAll is single-dataset and respects readable-file ACLs. Chat attachments add document/unknown while retaining legacy file, so clients must stop using file alone to detect documents. Pro streamed/raw responses survive NextAPI (#7971); MCP and external channels now share team QPM limits, with dependency failures failing open.

升级指南

配置变更

  • 源码部署的 Node.js 版本须满足 ^22.23.4 || ^24.22.1 || ^26.12.1，升级前请先确认运行环境符合该范围。
  • DEFAULT_TEAM_BASIC_PERMISSIONS_ENABLED 仍默认 false；启用时，新团队默认全员组除应用、技能和知识库创建权限外，还会获得 API Key 创建权限，已有团队不自动补授。
