#gráfico de código v1.4.1

[1.4.1] - 10/07/2026

Novos recursos

  • O servidor MCP agora percebe quando existe uma versão mais recente do CodeGraph e informa a você - um servidor de longa execução usado para ficar atrás das versões silenciosamente até que algo quebrasse. Na inicialização, ele verifica a versão mais recente em segundo plano (nunca bloqueando, no máximo uma vez por dia, o cache em todos os servidores da máquina) e exibe um aviso de uma linha "atualização disponível - execute codegraph upgrade" no log do servidor, nas instruções que seu agente vê na conexão e no codegraph_status. Nada é atualizado por si só, e estar offline significa simplesmente não ter aviso prévio. Desative com CODEGRAPH_NO_UPDATE_CHECK=1; DO_NOT_TRACK=1 também o desativa. (#1243)

Correções

  • codegraph upgrade em uma instalação npm do Windows na verdade executa o npm novamente - o Node moderno se recusa a iniciar o npm.cmd diretamente, então a atualização falhou com um erro de spawn antes de fazer qualquer coisa. O npm agora é invocado da mesma forma que um terminal o executaria. (#1238)
  • codegraph uninstall agora desinstala o CodeGraph. Ele costumava remover apenas as configurações do agente e deixar todos os binários instalados para trás, então o codegraph ainda funcionava depois - especialmente confuso quando uma instalação global npm e uma instalação autônoma estavam presentes e a remoção de uma ainda deixava a outra respondendo no PATH. A desinstalação agora encontra todas as instalações na máquina (o pacote autônomo, o pacote global npm, o link do inicializador) e remove todas elas, depois de mostrar exatamente o que encontrou e perguntar primeiro (--yes ignora o prompt). As configurações no nível da máquina, como sua escolha de telemetria, são preservadas, uma verificação de origem nunca é tocada e o novo sinalizador --keep-cli restaura o antigo comportamento somente de configurações. (#1071)
  • codegraph_explore não permite mais que palavras comuns em inglês em uma pergunta de linguagem natural controlem a classificação quando elas correspondem ao nome de um símbolo de código. Uma pergunta como "como o fluxo de atualização verifica a versão mais recente" usada para tratar "verificar" como um símbolo que o agente solicitou pelo nome, classifica primeiro o arquivo dessa definição não relacionada e exclui completamente os arquivos sobre os quais a pergunta se refere. Nomes de símbolos escritos com precisão (camelCase, PascalCase, snake_case, nomes qualificados) ainda recebem destaque exatamente como antes, assim como os sacos de símbolos de palavras simples cujas palavras pertencem juntas no mesmo arquivo.
  • Chamadas de método PHP feitas por meio de uma propriedade de classe — $this->dep->method(), o formato de chamada dominante em bases de código de injeção de construtor (Symfony, Laravel) — agora resolvem o método no tipo declarado da propriedade, para que os chamadores e a análise de impacto vejam os sites de chamada de produção em vez de relatar um método pesado de DI como não chamado ou apenas de teste. Parâmetros de construtor promovidos, propriedades digitadas, atribuição de construtor clássico (incluindo assinaturas multilinhas) e injeção de setter digitado, tudo conta; as propriedades do tipo interface são resolvidas para o método de interface e os métodos herdados são resolvidos por meio da hierarquia de tipos. Somente declarações em forma de propriedade são consultadas — uma variável local com o mesmo nome ou parâmetro em outro lugar nunca pode digitar incorretamente a propriedade — e uma propriedade cujo tipo não pode ser recuperado estaticamente permanece desvinculada em vez de adivinhada. Obrigado @w0lan. (#1220)
  • codegraph upgrade agora também atualiza as versões anteriores instaladas em seus agentes - a seção CodeGraph em CLAUDE.md / AGENTS.md / GEMINI.md e a entrada MCP - portanto, a atualização não deixa mais os agentes seguindo as instruções escritas para ferramentas que já foram renomeadas ou removidas. Somente atualização: os agentes que você nunca configurou não são tocados e sua permissão e opções de gancho são preservadas. Também disponível manualmente como codegraph install --refresh e ignorável com CODEGRAPH_NO_INSTALL_REFRESH=1. (#1238)
  • codegraph upgrade em uma instalação npm agora atualiza através do npm novamente em vez de criar silenciosamente uma segunda cópia que nunca vence a corrida PATH - anteriormente codegraph --version continuava reportando a versão antiga para sempre, não importa quantas vezes você atualizasse. (#1238)
  • Após cada atualização, o CodeGraph agora verifica se o comando codegraph que seu terminal resolve realmente serve a versão recém-instalada - confirmando que você não precisa de um novo terminal ou informando exatamente qual instalação obsoleta está ocultando o novo. (#1071)
  • O watchdog de segurança não mata mais um índice íntegro em armazenamento gravemente degradado. Ele costumava julgar a atividade puramente pelo loop de eventos, de modo que uma longa gravação de banco de dados em um disco com problemas parecia idêntica a um processo travado e poderia encerrar um índice válido e em andamento. Durante codegraph index/codegraph init, o watchdog agora também verifica se os arquivos de índice no disco estão avançando antes de agir: o trabalho lento, mas em progresso, é deixado de lado (limitado por um hard cap), enquanto um processo genuinamente interrompido ainda é eliminado exatamente tão rápido quanto antes. (#1231)
  • A sincronização incremental agora capta relacionamentos entre arquivos que só podem ser resolvidos após uma edição — por exemplo, quando um arquivo obtém uma exportação que outro arquivo inalterado já estava importando ou chamando. Anteriormente, a referência no arquivo inalterado nunca era revisitada, portanto, os chamadores, o impacto e os resultados do fluxo omitiam silenciosamente a nova borda (enquanto o status relatava um índice limpo) até uma reindexação completa. Referências que ainda não podem ser resolvidas agora são lembradas e repetidas automaticamente sempre que uma alteração introduz um símbolo que possa satisfazê-las — isso também abrange uma classe que ganha um novo método que outros arquivos já chamam. Obrigado @loadcosmos pelo relatório com reprodução mínima. (#1240)
  • O caso inverso também foi corrigido: quando uma edição remove ou move um símbolo (ou exclui seu arquivo), os chamadores em arquivos inalterados agora resolvem novamente durante a mesma sincronização - religando-se ao novo local do símbolo quando ele foi movido ou esperando para se reconectar automaticamente quando ele voltar - em vez de perder silenciosamente seu relacionamento até uma reindexação completa. (#1240)

codegraph v1.4.1

[1.4.1] - 2026-07-10

New Features

  • The MCP server now notices when a newer CodeGraph release exists and tells you — a long-running server used to drift behind releases silently until something broke. On startup it checks the latest release in the background (never blocking, at most once a day, cached across all servers on the machine) and surfaces a one-line "update available — run codegraph upgrade" notice in the server log, in the instructions your agent sees on connect, and in codegraph_status. Nothing updates by itself, and being offline just means no notice. Opt out with CODEGRAPH_NO_UPDATE_CHECK=1; DO_NOT_TRACK=1 disables it too. (#1243)

Fixes

  • codegraph upgrade on a Windows npm install actually runs npm again — modern Node refuses to launch npm.cmd directly, so the upgrade failed with a spawn error before doing anything. npm is now invoked the way a terminal would run it. (#1238)
  • codegraph uninstall now actually uninstalls CodeGraph. It used to remove only the agent configurations and leave every installed binary behind, so codegraph still ran afterward — especially confusing when both an npm global install and a standalone install were present and removing one still left the other answering on PATH. Uninstall now finds every install on the machine (the standalone bundle, the npm global package, the launcher link) and removes them all, after showing you exactly what it found and asking first (--yes skips the prompt). Machine-level settings like your telemetry choice are preserved, a source checkout is never touched, and the new --keep-cli flag restores the old configs-only behavior. (#1071)
  • codegraph_explore no longer lets ordinary English words in a natural-language question hijack the ranking when they happen to match a code symbol's name. A question like "how does the upgrade flow check the latest version" used to treat "check" as a symbol the agent asked for by name, rank that unrelated definition's file first, and crowd the files the question is actually about out of the answer entirely. Precisely written symbol names (camelCase, PascalCase, snake_case, qualified names) still get top billing exactly as before, as do plain-word symbol bags whose words belong together in the same file.
  • PHP method calls made through a class property — $this->dep->method(), the dominant call shape in constructor-injection codebases (Symfony, Laravel) — now resolve to the method on the property's declared type, so callers and impact analysis see production call sites instead of reporting a DI-heavy method as uncalled or test-only. Promoted constructor parameters, typed properties, classic constructor assignment (including multi-line signatures), and typed setter injection all count; interface-typed properties resolve to the interface method, and inherited methods resolve through the type hierarchy. Only property-shaped declarations are consulted — a same-named local variable or parameter elsewhere can never mistype the property — and a property whose type can't be recovered statically stays unlinked rather than guessed. Thanks @w0lan. (#1220)
  • codegraph upgrade now also refreshes what previous versions installed into your agents — the CodeGraph section in CLAUDE.md / AGENTS.md / GEMINI.md and the MCP entry — so upgrading no longer leaves agents following instructions written for tools that have since been renamed or removed. Refresh-only: agents you never configured are not touched, and your permission and hook choices are preserved. Also available manually as codegraph install --refresh, and skippable with CODEGRAPH_NO_INSTALL_REFRESH=1. (#1238)
  • codegraph upgrade on an npm install now upgrades through npm again instead of quietly creating a second copy that never wins the PATH race — previously codegraph --version kept reporting the old version forever, no matter how many times you upgraded. (#1238)
  • After every upgrade, CodeGraph now checks that the codegraph command your terminal resolves actually serves the freshly installed version — confirming you don't need a new terminal, or telling you exactly which stale install is shadowing the new one. (#1071)
  • The safety watchdog no longer kills a healthy index on severely degraded storage. It used to judge liveness purely by the event loop, so one long database write on a struggling disk looked identical to a hung process and could get a valid, in-progress index terminated. During codegraph index/codegraph init the watchdog now also checks whether the index files on disk are advancing before it acts: slow-but-progressing work is left alone (bounded by a hard cap), while a genuinely hung process is still killed exactly as fast as before. (#1231)
  • Incremental sync now picks up cross-file relationships that only become resolvable after an edit — for example, when a file gains an export that another, unchanged file was already importing or calling. Previously the reference in the unchanged file was never revisited, so callers, impact, and flow results silently omitted the new edge (while status reported a clean index) until a full re-index. References that can't be resolved yet are now remembered and automatically retried whenever a change introduces a symbol that could satisfy them — this also covers a class gaining a new method that other files already call. Thanks @loadcosmos for the report with a minimal reproduction. (#1240)
  • The reverse case is fixed too: when an edit removes or moves a symbol (or deletes its file), callers in unchanged files now re-resolve during the same sync — rebinding to the symbol's new home when it moved, or waiting to reconnect automatically when it comes back — instead of silently losing their relationship until a full re-index. (#1240)
