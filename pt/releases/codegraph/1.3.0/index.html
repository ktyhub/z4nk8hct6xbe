#gráfico de código v1.3.0

[1.3.0] - 07/07/2026

Novos recursos

  • CodeGraph agora indexa Nix (.nix) — flocos, módulos NixOS e home-manager, sobreposições e conjuntos de pacotes se juntam ao gráfico: ligações let e attrset, funções ({ pkgs, ... } simples, desestruturado e curry) e ligações inherit tornam-se símbolos pesquisáveis, com bordas de chamada entre ligações. A fiação em nível de arquivo segue as maneiras como o Nix realmente conecta os arquivos: import ./relative/path.nix (com import ./dir alcançando o default.nix do diretório), listas imports = [ ./hardware.nix ../common ] do módulo NixOS, listas modules = [ ./configuration.nix ] estilo flake e o idioma nixpkgs callPackage ./pkgs/foo { } - então "o que essa configuração realmente atrai" e "o que usa este módulo" são responsáveis ​​​​em configurações reais. Referências dinâmicas (import <nixpkgs>, caminhos variáveis, referências de módulos de entrada em flocos) são deliberadamente deixadas desvinculadas em vez de adivinhadas. Obrigado @TyceHerrman. (#324, #332, #648)
  • A fiação de opções do sistema do módulo NixOS é interligada, então as questões de fluxo cruzam o limite do módulo em vez de escurecer: uma gravação de configuração como launchd.user.agents.myapp = { ... } ou home.file.".gitconfig" = { ... } vincula-se ao módulo que declara essa opção (options.launchd.user.agents = mkOption { ... } - grafias de declaração simples e aninhadas contam, chaves citadas como system.defaults.NSGlobalDomain."com.apple.dock" correspondem à sua declaração exata), o que faz com que "como a ativação deste serviço produz o daemon de lançamento/arquivo de configuração gerado" rastreável de ponta a ponta e "o que define esta opção" respondidos em todos os módulos, incluindo testes. A precisão é deliberadamente conservadora: caminhos ${...} interpolados, opções declaradas em mais de um módulo e namespaces de opções internas do submódulo permanecem desvinculados em vez de adivinhados, e cada salto em ponte é rotulado como fiação heurística do sistema de módulo em vez de mostrado como uma referência simples.
  • CodeGraph agora indexa ArkTS (.ets) — a linguagem dos aplicativos HarmonyOS/OpenHarmony. Tudo o que TypeScript é extraído (classes, interfaces, enums, aliases de tipo, importações/exportações, bordas de chamada), além das próprias construções do ArkTS: estruturas @Component / @ComponentV2 com seus decoradores (@Entry, @State, @Prop, @Link, @Local, @Param,…) capturados e pesquisáveis, build() visualiza árvores vinculadas pai → filho para que "quais páginas renderizam este componente" sejam responsáveis, atributos encadeados conectados às funções @Extend/@Styles que eles invocam, métodos e funções @Builder conectados ao gráfico de chamada e ligações de eventos no estilo .onClick(this.handler) vinculadas a seus métodos manipuladores. Os projetos modulares do HarmonyOS também são resolvidos através dos limites do módulo: um import { CartRepository } from "data" simples segue a dependência do oh-package.json5 file: para o módulo correto - honrando a entrada main declarada de cada módulo, tanto dos consumidores .ets quanto do .ts - enquanto nomes ambíguos em monorepos de vários aplicativos permanecem deliberadamente desvinculados em vez de adivinhados, e bases de código mistas .ets / .ts fazem link cruzado livremente. Validado em aplicativos HarmonyOS reais, incluindo o monorepo de amostras oficiais do OpenHarmony. (#396, #512, #648, #890)
  • Os saltos dinâmicos do ArkUI são interligados para que as questões de fluxo os cruzem em vez de ficarem escuros, cada um rotulado como despacho dinâmico em vez de mostrado como uma chamada simples: métodos que atribuem uma propriedade reativa (@State, @Local,…) vinculam-se ao build() do componente (o salto de re-renderização - controlado por atribuição, portanto, um método que apenas lê o estado não obtém vantagem); emitter.emit(eventId) se vincula ao assinante emitter.on/once correspondente quando ambos os lados compartilham uma chave de evento estaticamente recuperável (pares de IDs numéricos dentro de apenas um arquivo, constantes nomeadas dentro de um módulo, portanto, amostras não relacionadas em um monorepo nunca fazem link cruzado); e router.pushUrl({ url: 'pages/Detail' }) links para a estrutura @Entry da página de destino, com URLs ambíguos deixados sem link em vez de adivinhados.
  • A indexação interrompida ou incompleta agora é visível em vez de silenciosa: uma execução interrompida no meio do índice (travamento, falta de memória, watchdog) deixa um marcador que codegraph status relata como um índice truncado, uma execução concluída que descarta arquivos se reporta como parcial - tanto na saída humana quanto em status --json - e codegraph index imprime um aviso com as contagens exatas quando seu resultado não corresponde ao que a varredura descobriu.
  • CodeGraph agora indexa Terraform e OpenTofu (.tf, .tfvars, .tofu) — recursos, fontes de dados, módulos, variáveis, saídas, provedores e todos os atributos locals tornam-se símbolos (por exemplo, aws_s3_bucket.my_bucket, var.region, module.vpc, local.prefix) e usos como var.region, module.vpc.id, data.aws_caller_identity.current ou aws_s3_bucket.my.arn são conectados em arquivos cruzados, portanto, pesquisas, chamadores e consultas de impacto retornam resultados reais em repositórios de infraestrutura, em vez de nada. As chamadas de módulo são interligadas através do limite do módulo: as entradas de um bloco module vinculam-se às variáveis ​​do módulo filho, module.vpc.vpc_id atinge a definição output "vpc_id" do filho e o caminho source local do bloco vincula-se aos arquivos do módulo - então "o que quebra se eu alterar a variável deste módulo" atinge todos os chamadores em vez de um beco sem saída na declaração (o registro e as fontes git são deliberadamente deixados como limites visíveis em vez de adivinhados). A fiação entre componentes através do módulo cloudposse/atmos remote-state também se conecta: module.vpc.outputs.vpc_cidr em um componente atinge a própria saída do componente vpc quando o nome do componente é declarado estaticamente (um literal ou uma variável com um padrão literal) e exatamente um diretório corresponde - qualquer coisa dinâmica ou ambígua permanece desvinculada. Os provedores com alias são de primeira classe: provider "aws" { alias = "east" } obtém seu próprio símbolo e provider = aws.east em um recurso (ou mapa providers de um módulo) vincula-se a essa configuração, encontrando a árvore do módulo da maneira como o Terraform realmente a herda. Os blocos de migração de estado moved/import/removed e as asserções check fazem referência aos recursos que eles nomeiam, portanto, a trilha de papel de um refatorador faz parte do gráfico. As atribuições .tfvars vinculam-se às variáveis ​​que elas definem, incluindo arquivos var mantidos em um subdiretório. A resolução segue o escopo real por diretório do Terraform, de modo que variáveis ​​com o mesmo nome entre módulos nunca se cruzam e "o que depende de var.project_id" em um repositório de vários módulos nunca se mistura em módulos não relacionados. Obrigado @Javviviii2. (#83, #310, #648)
  • CodeGraph agora indexa CUDA (.cu, .cuh) — kernels, funções de dispositivo/host, estruturas e classes tornam-se símbolos, e a borda da chamada host→kernel sobrevive à sintaxe de inicialização do <<<grid, block>>>, então perguntas como "como essa chamada alcança o kernel da GPU?" rastreie através do limite CPU/GPU em vez de escurecer no local de lançamento. Todos os estilos de inicialização do mundo real se conectam: lançamentos modelados (my_kernel<Traits, 256><<<grid, block>>>(args)), lançamentos por meio de um ponteiro de função local (auto kernel = &my_kernel<...>; ... kernel<<<grid, block>>>(args) - cada alvo atribuído à ramificação vinculado), configurações de inicialização inicializadas por chaves (<<<dim3{1,1,1}, dim3{256,1,1}>>>) e kernels definidos por meio de uma macro de nome no primeiro argumento (estilo DEFINE_FLASH_FORWARD_KERNEL(kernel_name, ...) { ... } de atenção flash), que agora indexam sob seus nomes reais de kernel. CUDA que reside em cabeçalhos .h/.hpp simples - onde fica grande parte do código de dispositivo do mundo real, incluindo cabeçalhos de modelo de inicialização - é reconhecido pelo conteúdo e indexado da mesma maneira. Validado em llm.c, flash-attention e NVIDIA CUTLASS. (#387, #648)
  • Os símbolos C++ definidos dentro dos blocos namespace agora carregam o namespace em seu nome qualificado (flash::compute_attn, C++17 namespace a::b { incluído), e as chamadas qualificadas pelo namespace (ns::fn(...)) resolvem suas definições - anteriormente, essas chamadas nunca eram vinculadas, o que ocultava grande parte do gráfico de chamadas em bases de código C++ com muitos namespaces dos chamadores e da análise de impacto.
  • Chamadas C++ que explicam argumentos de modelo (fn<T, 256>(args)) agora vinculam à função que instanciam, a mesma classe base de modelo de normalização que já tinha.
  • CodeGraph agora indexa Solidity (.sol) — contratos, bibliotecas, interfaces, estruturas, enums, modificadores, eventos, erros e variáveis de estado tornam-se símbolos de primeira classe, com bordas de chamada que seguem emit, revert, protetores modificadores (estilo onlyOwner, incluindo cadeias de construtores de base como constructor() ERC20(...)) e chamadas de biblioteca/método (incluindo using diretivas). As diretivas import são resolvidas para o arquivo importado, portanto, questões de contrato cruzado como "rastrear transferFrom por meio de atualizações de subsídio e saldo" ou "como onlyRole atinge o armazenamento de função?" trabalhe imediatamente em bases de código reais do Solidity (validadas em contratos solmate, solady e OpenZeppelin). Obrigado @naiba. (#374, #648)
  • O envio do comportamento Erlang agora é seguido através do gráfico: uma chamada de estrutura por meio de um módulo variável - as dobras Handler:init/Middleware:execute do cowboy, o Mod:callback(...) do gerenciador de plug-ins - vincula-se às implementações do repositório do comportamento que declara esse retorno de chamada, de modo que os rastreamentos de fluxo e o impacto cruzam o limite de retorno de chamada OTP em vez de parar nele. Os links são controlados com precisão: a aridade do retorno de chamada deve corresponder, exatamente um comportamento pode possuir esse formato de retorno de chamada (uma colisão permanece desvinculada em vez de adivinhada), o implementador deve realmente exportar o retorno de chamada e o fan-out é limitado - um comportamento com centenas de implementadores permanece um limite visivelmente dinâmico. Cada salto em ponte é rotulado como despacho dinâmico com seu site de fiação, nunca mostrado como uma chamada estática simples.
  • CodeGraph agora indexa Erlang (.erl, .hrl) — funções, com cláusulas e aridades de mesmo nome agrupadas como um símbolo abrangendo todas elas, além de registros com seus campos, aliases -type/-opaque, macros -define e assinaturas -spec anexadas a cada função. As chamadas mod:fn(...) entre módulos são resolvidas para a função do módulo de destino, os valores fun name/arity são capturados como referências (portanto, registros de retorno de chamada como lists:foreach(fun submit/1, ...) são vinculados), -include/-include_lib se conectam aos arquivos de cabeçalho que eles extraem, as declarações -behaviour vinculam um módulo de retorno de chamada ao seu comportamento (e apenas a um módulo - uma macro ou função com o mesmo nome em outro lugar do repositório nunca é confundida com uma), e as listas -export (mais -compile(export_all)) acionam o sinalizador público/privado de cada função. Os idiomas indiretos do OTP são seguidos onde o alvo é estático: chamadas spawn/apply/proc_lib/timer/rpc que nomeiam seu alvo como argumentos (Module, Function, Args) produzem bordas de chamada, e gen_server:call/cast se conecta ao handle_call/handle_cast do módulo de destino - seu próprio ao direcionar ?MODULE (incluindo o idioma -define(SERVER, ?MODULE)) e o módulo nomeado quando um nome registrado segue a convenção nomear o servidor após seu módulo do OTP (gen_server:call(other_mod, ...), diretamente ou por meio de uma macro -define(STORE, other_mod)); um nome registrado que não corresponda a nenhum módulo permanece desvinculado. As macros também participam do gráfico: as chamadas do corpo -define pertencem à macro, cada ?MACRO(...) usa links de site na cadeia de chamadas (e as leituras simples do ?CONSTANT são rastreadas como referências), portanto, um caminho de chamada oculto atrás de uma macro - set_password → ?SQL_UPSERT_T → sql_query_t - rastreia de ponta a ponta e "onde esta macro é usada" é responsável. índice de scripts como qualquer módulo (a linha shebang é entendida) e arquivos de recursos do aplicativo OTP (.app.src, .app) juntam-se ao gráfico: {mod, ...} vincula um aplicativo ao seu módulo de retorno de chamada e {applications, [...]} conecta aplicativos irmãos guarda-chuva - resolvendo apenas para módulos, portanto, um nome de aplicativo OTP como ssl nunca é confundido com uma função de mesmo nome. O despacho verdadeiramente dinâmico (Mod:handle(...), envio de mensagens, geração de módulo var) é deliberadamente deixado desvinculado em vez de adivinhado. codegraph_explore também entende a ortografia de símbolos nativos de Erlang em consultas - mod:fn/3 e init/2 encontram os símbolos que nomeiam. (#635, #648)
  • CodeGraph agora indexa Visual Basic .NET (.vb) - classes, módulos, interfaces, estruturas, enums, propriedades, eventos, membros abstratos MustOverride e assinaturas Declare P/Invoke, com bordas de hierarquia Inherits/Implements, bordas de chamada (resolvidas por meio de parênteses ambíguos de chamada versus índice do VB) e Links de instanciação New/As New. Estilos VB do mundo real são analisados de forma limpa: arquivos de designer WinForms, strings interpoladas e multilinhas, literais XML (expressões <%= %> incorporadas incluídas), consultas LINQ de linha única e multilinha, lambdas multilinhas, fiação de eventos Handles/WithEvents, eventos personalizados, literais de data, identificadores de caracteres de tipo clássicos (i%, name$) e idiomas não ingleses Identificadores (Unicode). (#648, #639, #170)
  • CodeGraph agora indexa COBOL (.cbl, .cob, .cpy) — programas, seções e parágrafos com bordas de chamada PERFORM/GO TO, chamadas de programa cruzado CALL, importações de copybook COPY (copybooks independentes incluídos) e registros de DIVISÃO DE DADOS com nomes de condição de 88 níveis, em fonte fixa e gratuita formato. As consultas de impacto funcionam em itens de dados: cada site de gravação MOVE/ADD/COMPUTE/SUBTRACT vincula-se ao campo que ele muda, portanto, "o que toca neste campo do caderno" responde entre os programas. Os fluxos CICS também se conectam: destinos de programa EXEC CICS LINK/XCTL, copybooks EXEC SQL INCLUDE e saltos RETURN TRANSID(...) pseudo-conversacionais são resolvidos para o programa que possui o ID da transação. (#590, #648)
  • CodeGraph agora indexa CFML (.cfc, .cfm, .cfs) — tanto o estilo clássico baseado em tags (<cfcomponent>/<cffunction>) quanto a moderna sintaxe component { ... } de script simples, incluindo extends/implements, blocos <cfscript> incorporados (em qualquer profundidade de aninhamento, inclusive dentro <cfif>/<cfloop>/<cftry>), bordas de chamada e chamadas incorporadas em expressões #hash# dentro de corpos SQL <cfquery>. Arquivos salvos com uma marca de ordem de bytes UTF-8 e tags com valores de atributos sem aspas — ambos comuns em bases de código CFML de longa duração — também são manipulados. Obrigado @ghedwards. (#1118)
  • A herança CFML escrita como um caminho de componente agora está vinculada ao componente correto. extends="coldbox.system.web.Controller" nomeia seu supertipo por caminho pontilhado e extends="../base" por caminho relativo (o estilo FW/1) - ambos anteriormente não produziam nenhuma vantagem de herança, o que em aplicativos CFML estilo estrutura ocultava a maior parte da hierarquia de tipos da análise de impacto e raio de explosão (no próprio núcleo do ColdBox, mais de 90% da herança era invisível). A resolução é deliberadamente conservadora: o layout do diretório de destino deve corroborar o caminho declarado - portanto, um supertipo que reside em uma biblioteca fora do repositório (testbox, mxunit, uma estrutura instalada) permanece corretamente desvinculado em vez de ser adivinhado, e um caminho ambíguo não produz nenhuma borda em vez de um caminho errado. (#1152)
  • Chamadas de método CFML feitas através de uma variável local, argumento digitado ou propriedade de componente agora são resolvidas para o método correto — a mesma inferência de tipo de receptor que outras linguagens orientadas a objetos já tinham. var svc = new UserService(); svc.save(), createObject("component", "path.UserService"), um parâmetro digitado <cfargument> ou cfscript e campos com escopo variables./this. - incluindo o padrão pseudoconstrutor (variables.svc = new UserService() em init()) e propriedades injetadas por WireBox (property name="svc" inject="UserService") - todos agora vinculam a chamada ao método do componente declarado, com métodos herdados de um supertipo resolvido por meio de links de herança acima. Isso faz com que os chamadores, o raio de impacto/raio de explosão e os rastreamentos de fluxo codegraph_explore sigam as chamadas de serviço CFML em vez de descartá-las ou adivinhar entre métodos com o mesmo nome.
  • O gancho de contexto do Claude Code agora reconhece prompts que descrevem o código em palavras simples — em qualquer idioma — comparando as palavras do prompt com os nomes dos símbolos realmente no índice do seu projeto. Perguntar sobre "a máquina de estado de comandos" encontra OrderStateMachine sem nenhuma palavra-chave envolvida. A confiança decide quanto é injetado: questões estruturais e solicitações para nomear um símbolo real ainda recebem todo o contexto antecipadamente; uma correspondência de palavras simples obtém um ponteiro curto para os símbolos correspondentes para que o próprio agente os consulte; todo o resto permanece em silêncio, exatamente como antes.
  • A telemetria de uso anônimo agora conta com que frequência o gancho de contexto injetou contexto, ofereceu uma dica ou permaneceu em silêncio - apenas nomes de contadores fixos; o conteúdo do prompt nunca é armazenado ou enviado. Isso torna a precisão do gancho mensurável em vez de adivinhada. Os contadores registram o que realmente aconteceu, não o que foi tentado: uma pesquisa que errou ou voltou vazia conta como um resultado silencioso distinto, nunca como contexto entregue (#1143, obrigado @inth3shadows).
  • Arquivos de shader de metal (.metal) agora estão indexados. A Metal Shading Language é próxima o suficiente do C++ para que funções de vértice/fragmento/kernel, estruturas, aliases de tipo e as chamadas entre eles cheguem ao gráfico — portanto, pipelines de shader em projetos da plataforma Apple aparecem na análise de impacto e nos rastreamentos de fluxo, em vez de serem ignorados silenciosamente. As anotações de atributos no estilo [[buffer(0)]] do Metal são tratadas para que não possam corromper o que é extraído. Obrigado @FluxKo pelo relatório. (#1121)
  • CodeGraph agora indexa mapas SQL iBatis 2 legados (<sqlMap>), não apenas arquivos MyBatis 3 <mapper>. Os fragmentos <select> / <insert> / <update> / <delete>, <statement> / <procedure> da iBatis e <sql> dentro de um <sqlMap> tornam-se símbolos de instrução pesquisáveis ​​- para mapas com namespace e o estilo de id Map.statement sem namespace - e as referências <include> são resolvidas para o fragmento que eles extraem, então pesquise, chamadores e consultas de impacto retornam resultados em bases de código iBatis que anteriormente não produziam nenhum símbolo de instrução. Obrigado @ESPINS pelo relatório e pela reprodução. (#1182)
  • Agora você pode forçar a fonte primária gitignorada no índice com uma lista include em codegraph.json. O caso que isso resolve: um projeto rastreado por um segundo VCS (SVN, Perforce,…) junto com o Git, onde alguma fonte real está comprometida com esse VCS e deliberadamente listada no .gitignore para que nunca chegue ao Git - o git nunca lista esses arquivos, então o CodeGraph nunca os indexou, e nem o includeIgnored (que apenas revive repositórios git incorporados dentro de um diretório gitignored) nem o exclude (seu oposto) poderia ajudar. Adicione um codegraph.json raiz com, por exemplo, { "include": ["Tools/", "Local/typescript/"] } e CodeGraph descobre esses arquivos diretamente do disco - substituindo .gitignore - e os indexa no índice completo, sync incremental e observação de arquivos, em projetos git e não git. Os padrões são do estilo gitignore e correspondem aos caminhos relativos à raiz do projeto (um diretório, um glob ** recursivo ou um único arquivo). Um exclude explícito ainda vence, e saltos integrados como node_modules, dist e .git nunca são incluídos novamente. Isso complementa o exclude existente (seu oposto - manter arquivos rastreados fora) e includeIgnored (optar in para repositórios incorporados gitignorados).

Correções

  • Indexar um grande monorepo Java ou Kotlin Spring é dramaticamente mais rápido. A fase de resolução de referência – a maior parte de um codegraph index inicial – poderia durar quase uma hora em um grande projeto multimódulo e agora termina em alguns minutos, produzindo o mesmo gráfico. A causa: cada chamada receiver.method() na base de código verificava repetidamente todo o conjunto de chaves de configuração do projeto em busca de uma correspondência - trabalho que só se aplica a ligações Spring @Value / @ConfigurationProperties, nunca a chamadas de método comuns. Como parte da mesma correção, uma chamada de método cujo nome coincide com uma chave de configuração (digamos, uma chamada service.process() junto com uma entrada service.process em application.yml) não está mais vinculada incorretamente a essa chave de configuração - ela agora é resolvida para o método real. Obrigado @bayernjava pelo relatório. (#1180)
  • codegraph init em um repositório pai cujo .gitignore exclui seus repositórios filhos não indexa mais nada silenciosamente e relata sucesso. O layout "super-repo de repositórios filhos gitignored" - um repositório Git de nível superior que .gitignores cada filho service-*/ ou packages/* para que git status permaneça quieto - usado para indexar apenas os poucos arquivos de nível superior do pai e imprimir "Concluído" com 0 nós, mesmo que executar codegraph init dentro de qualquer filho funcionasse bem (CodeGraph respeita .gitignore por padrão, então os filhos excluídos foram ignorados). Agora, quando um índice fica vazio, o CodeGraph detecta os repositórios filhos gitignorados que foram ignorados, nomeia-os e - em um terminal interativo - oferece-se para indexá-los (gravando uma entrada includeIgnored em codegraph.json e reindexando no local); execuções não interativas imprimem o trecho codegraph.json exato a ser adicionado. Projetos que mantêm legitimamente clones de referência gitignorados fora de um índice funcional nunca são incomodados: a oferta só aparece quando o índice estaria vazio. Obrigado @ small-obrigado pelo relatório. (#1156)
  • O leitor mapeador MyBatis é mais robusto em XML do mundo real. Os valores de atributos entre aspas simples (id='getById', XML legal e comum em mapeadores mais antigos) não são mais ignorados, portanto, essas instruções são inseridas no gráfico. Declarações e <include>s que foram comentados com <!-- ... --> não produzem mais símbolos fantasmas. E duas declarações de divisão de fornecedor – o mesmo id com databaseId="oracle" / databaseId="mysql" – escritas em uma única linha não descartam mais silenciosamente um dos pares. Obrigado @ESPINS pelo relatório, pelas reproduções e pelas correções. (#1182)
  • codegraph init e codegraph index não são mais mortos pelo watchdog de segurança na etapa "Resolvendo refs" em grandes bases de código com muitos nomes de métodos (grandes monorepos Java/empresariais foram as principais vítimas, especialmente em máquinas mais lentas). A resolução costumava aparecer apenas a cada 500 referências, portanto, um conjunto denso de referências caras poderia fazer com que o watchdog morresse de fome por tempo suficiente para que ele assumisse que o processo estava travado e matasse um índice perfeitamente saudável. A resolução agora faz pontos de verificação após cada referência, e duas das etapas caras ficaram muito mais baratas: pesquisas repetidas de métodos do mesmo tipo agora são armazenadas em cache e os arquivos de origem não são mais divididos linha por linha para cada chamada sendo resolvida - como resultado, a indexação de tais repositórios é várias vezes mais rápida. Arquivos de linha única gerados ou reduzidos também são ignorados durante a inferência do tipo receptor, em vez de serem verificados por chamada. Obrigado @UchihaYong e @wangmeng-95 pelos relatórios. (#1122)
  • Um índice deixado incompleto por uma execução interrompida agora se recupera na próxima sincronização, em vez de permanecer errado silenciosamente para sempre. Se a indexação morreu no meio da resolução de referências (uma falha, Ctrl-C ou a eliminação do watchdog corrigida acima), os arquivos afetados ainda pareciam indexados, mas suas bordas de chamador/impacto estavam faltando - um raio de explosão muito pequeno agrupado por pacote ou módulo, por exemplo. um método injetado por Spring @Resource relatando 3 de seus 10 arquivos de chamada reais - e como as sincronizações incrementais apenas resolvem novamente os arquivos que foram alterados, o dano foi permanente até uma reindexação completa. Qualquer sincronização (uma alteração de arquivo monitorada ou um codegraph sync vazio) agora detecta as referências restantes e termina de resolvê-las, codegraph status avisa quando um índice está nesse estado em vez de passá-lo como íntegro, e uma rara parada antecipada que poderia abandonar a resolução em repositórios cujos primeiros arquivos fazem referência apenas a bibliotecas externas também foi corrigida. Obrigado @KnifeOfLife pelo relatório e pela observação de correlação de pacotes que o definiu. (#1187)
  • O servidor de segundo plano compartilhado não é mais desligado em uma sessão de editor/agente ao vivo que simplesmente não consulta o CodeGraph há algum tempo. Um temporizador de segurança destinado a colher um servidor abandonado - aquele cujo client desapareceu sem que a conexão fosse fechada - foi reaping qualquer servidor que não viu nenhuma solicitação por 30 minutos, incluindo uma sessão perfeitamente ao vivo que simplesmente não estava perguntando nada ao CodeGraph; que silenciosamente descartou a sessão (e todas as outras sessões compartilhando o mesmo servidor em segundo plano) para um modo de processo mais lento pelo resto de sua vida. Em uma máquina durante um dia, ela disparou 20 vezes em sessões ao vivo e não detectou nenhum fantasma real. O cronômetro agora verifica se os clients conectados ainda estão ativos e só colhe quando nenhum deles está, portanto, uma sessão silenciosa, mas ativa, mantém seu servidor compartilhado enquanto um servidor genuinamente abandonado ainda é limpo. (#1200)
  • O servidor de segundo plano do CodeGraph não deixa mais um processo persistente do Node quando seu editor ou agente interrompe seu inicializador durante a inicialização. Se o aplicativo que iniciou o CodeGraph (Codex, Claude Code ou outro MCP client) foi encerrado na primeira fração de segundo do servidor - uma investigação de configuração, uma solicitação cancelada, um tempo limite de inicialização - enquanto mantinha os canais da conexão abertos, o servidor poderia ser entregue ao sistema antes que seu cão de guarda de detecção de órfãos capturasse um ponto de referência, deixando-o em execução (ocioso, ~ 30 MB) até que o próprio aplicativo de inicialização fosse encerrado; ao longo de um longo dia de lançamentos repetidos, eles se acumularam. O servidor agora registra seu pai o mais cedo possível, e os inicializadores npm e autônomos passam o ID do processo do host real para ele, para que ele possa observar o host diretamente, em vez de apenas o inicializador que já pode ter desaparecido. Como solução final, um servidor que nunca recebe uma única solicitação após iniciar agora se desliga em vez de esperar a saída do host - ajustável com CODEGRAPH_STARTUP_HANDSHAKE_TIMEOUT_MS (0 desabilita). Obrigado @ruslan33321 pelo relatório. (#1185)
  • O gancho de contexto automático do Código Claude agora é acionado para perguntas estruturais feitas em quase trinta idiomas — francês, espanhol, português, alemão, italiano, holandês, polonês, tcheco, romeno, húngaro, grego, sueco, dinamarquês, norueguês, finlandês, russo, ucraniano, turco, indonésio, vietnamita, tailandês, hindi, árabe, farsi, hebraico, japonês, coreano e chinês simplificado e tradicional — em vez de apenas inglês e chinês simplificado. Anteriormente, uma pergunta natural como "comment marche la state machine des commandes?" não injetou nada, a menos que contivesse um nome de símbolo em forma de código, fazendo com que o gancho parecesse quebrado para equipes que não falam inglês. Perguntas em inglês formuladas com formas de palavras derivadas ("explicar a arquitetura…", "quais são as dependências…") agora também são acionadas, e prompts em qualquer outro idioma ainda são acionados quando nomeiam um símbolo do índice. Obrigado @anthonyle-roy-lgtm pelo relatório. (#1126)
  • Chamadas de métodos Lua e Luau com nomes capitalizados (obj:Method() — a convenção padrão do Roblox) agora estão vinculadas ao método correto. Como a sintaxe de chamada de método de Lua parece idêntica a uma anotação de tipo Luau, uma chamada capitalizada como lg:Log() foi mal interpretada como declarando o tipo da variável, portanto, sempre que duas ou mais classes compartilhavam um nome de método (Init, Update, Destroy,…) a chamada era silenciosamente descartada dos chamadores, raio de impacto/explosão e rastreamentos de fluxo. Os nomes dos métodos em letras minúsculas não foram afetados. Obrigado @ inth3shadows pela análise precisa da causa raiz e reprodução. (#1124)
  • Removido o código morto deixado pelo recurso de raciocínio gerenciado descontinuado. Seu fluxo codegraph login foi desconectado antes mesmo de ser lançado em um lançamento, mas o módulo não utilizado ainda foi enviado dentro dos pacotes da plataforma, e uma revisão de segurança sinalizou sua etapa de abertura do navegador Windows (ele roteou o URL de login através de cmd, o que não seria seguro se o fluxo já tivesse sido conectado novamente). O módulo restante e seus testes foram totalmente excluídos. Obrigado @ inth3shadows pelo relatório. (#1114)
  • O gancho de contexto do Claude Code não trata mais palavras comuns em inglês que apenas começam com "call", "trace", "affect" ou "connect" - calo, caligrafia, Connecticut, conectivo, afetuoso, Tracey - como questões estruturais, que costumavam injetar contexto CodeGraph completo em prompts que não tinham nada a ver com a estrutura do código. Formulários genuinamente estruturais (chamadas, chamadores, retornos de chamada, local de chamada, rastreado, rastreamento, afetado, conexões, conectividade, …) ainda são acionados exatamente como antes. Obrigado @ inth3shadows pelo relatório. (#1138)
  • Um comando git travado não pode mais travar o CodeGraph indefinidamente. O git verifica a detecção da árvore de trabalho e a configuração do git-hook, e a etapa npm install -g opcional do instalador, agora atinge o tempo limite e falha normalmente em vez de bloquear para sempre - isso é mais importante para o servidor MCP em segundo plano, onde um git hang ilimitado (sistemas de arquivos de rede, um fsmonitor preso) poderia congelá-lo anteriormente por tempo suficiente para que o cão de guarda de segurança o matasse. Obrigado @ inth3shadows pelo relatório. (#1139)
  • A nova correspondência de palavras simples do gancho de contexto funciona imediatamente em projetos indexados por uma versão mais antiga do CodeGraph. A pesquisa de palavras na qual ela se baseia é construída no momento do índice, portanto, um projeto indexado antes da atualização tinha um projeto vazio e o gancho não encontraria nada silenciosamente até que algo mais acontecesse para atualizar o índice; o gancho agora o preenche no primeiro uso (uma etapa única - normalmente a atualização de inicialização do servidor MCP em segundo plano chega lá primeiro). Obrigado @ inth3shadows pelo relatório. (#1142)
  • Várias correções de precisão na correspondência de palavras simples: um símbolo renomeado (por exemplo, uma rota NestJS após a aplicação do prefixo do módulo) permanece encontrável com seu novo nome (#1141); uma palavra que aparece apenas no seu código como nome de pacote de uma instrução de importação não é mais apresentada como um símbolo correspondente (#1144); palavras no plural não geram mais chaves de pesquisa distorcidas ("serviços" não procuram mais "servic") (#1145); e um nome que corresponda ao singular e ao plural de uma palavra não pode mais extrair uma correspondência genuína de duas palavras (#1146). Obrigado @inth3shadows pelos relatórios.
  • Classes C++ do Unreal Engine fortemente refletidas não são mais eliminadas do índice. A marcação de reflexão que decora os membros — UPROPERTY(...), UFUNCTION(...), UCLASS(...), GENERATED_BODY(), UE_DEPRECATED_*(...), DECLARE_DELEGATE_*(...) — são chamadas de macro sem ponto e vírgula que o tree-sitter não reconhece, então cada uma cai na recuperação de erros; em uma classe grande, os erros se acumulam até que todo o class_specifier entre em colapso e a classe, sua cláusula base e seus membros desapareçam (UCharacterMovementComponent, com ~ 240 dessas macros, desapareceu completamente, quebrando cada subclasse/hierarquia de tipo e consulta de raio de explosão que passou por ele). Essas macros de anotação de início de linha agora são apagadas (preservação de deslocamento) antes da análise para que a classe sobreviva. Obrigado @luoyxy pelo relatório e análise da causa raiz. (#1093 acompanhamento)
  • Membros e métodos do Unreal Engine prefixados por uma macro de exportação/visibilidade não são mais perdidos. A macro *_API não fica apenas no cabeçalho da classe - ela prefixa quase todos os membros exportados de uma grande classe UE (ENGINE_API virtual void Tick(...), static ENGINE_API void AddReferencedObjects(...)); o analisador lia a macro como um token de tipo extra e cada declaração caía na recuperação de erros, portanto, em cabeçalhos como Actor.h e World.h centenas de tipos de retorno se acumulavam como erros órfãos e ainda poderiam levar a classe ao colapso. As macros *_API / *_EXPORT / *_ABI de nível de membro/método (Unreal, Qt/Boost, LLVM) agora são apagadas antes da análise, espelhando a recuperação de cabeçalho de classe existente. (#1093 acompanhamento)
  • Macros de anotação do Unreal Engine que aparecem na linha intermediária - UMETA(DisplayName=...) de um valor de enum, UPARAM(ref) de um parâmetro ou uma tag de descontinuação inserida em um alias using (using FOnNetTick UE_DEPRECATED(5.5, "...") = ...;, que sozinho reduziu UWorld em World.h) - agora também foram removidas. Eles ocupam posições que a recuperação líder de linha estruturalmente não pode alcançar, e um único deles poderia derrubar o enum ou classe circundante. Eles são correspondidos por uma lista de nomes somente Unreal (UMETA, UPARAM, UE_DEPRECATED*), portanto, nenhum código C++ padrão ou de outra biblioteca é afetado. Juntas, essas três correções recuperam a classe principal de todos os grandes cabeçalhos do Unreal Engine testados (Actor, ActorComponent, SkeletalMeshComponent, World, LightComponent, CharacterMovementComponent). (#1093 acompanhamento)
  • Um cabeçalho C++ cujo único sinal C++ é uma classe anotada com macro de exportação não é mais detectado incorretamente como C — que descartou silenciosamente a classe. Um arquivo .h tem como padrão C e só é reclassificado como C++ quando mostra uma construção específica de C++, mas essa verificação não pode ser vista através de uma macro de exportação/visibilidade: class ENGINE_API UFoo : public UObject não corresponde ao padrão macro-cego class Name :, portanto, um cabeçalho enxuto no estilo Unreal-Engine carregando apenas GENERATED_BODY() e nenhum public: / virtual / explícito namespace / template foi analisado como C. O extrator C não emite nós de classe, então a classe - e seu link de herança - desapareceu do gráfico, desfazendo silenciosamente a recuperação da macroclasse adicionada em #1061. A heurística de detecção C++ agora reconhece uma declaração class/struct anotada com macro de exportação (a mesma forma #1061 espaços em branco antes da análise), correspondendo a como class Foo : Bar já foi detectado; o <keyword> <MACRO> <Name> de dois tokens antes de um [:{] nunca ocorre em C válido, portanto, os cabeçalhos C genuínos não são afetados. Obrigado @luoyxy pelo relatório e análise da causa raiz. (#1133)

codegraph v1.3.0

[1.3.0] - 2026-07-07

New Features

  • CodeGraph now indexes Nix (.nix) — flakes, NixOS and home-manager modules, overlays, and package sets join the graph: let and attrset bindings, functions (simple, destructured { pkgs, ... }, and curried), and inherit bindings all become searchable symbols, with call edges between bindings. File-level wiring follows the ways Nix actually connects files: import ./relative/path.nix (with import ./dir reaching the directory's default.nix), NixOS module imports = [ ./hardware.nix ../common ] lists, flake-style modules = [ ./configuration.nix ] lists, and the nixpkgs callPackage ./pkgs/foo { } idiom — so "what does this configuration actually pull in" and "what uses this module" are answerable on real setups. Dynamic references (import <nixpkgs>, variable paths, flake-input module references) are deliberately left unlinked rather than guessed. Thanks @TyceHerrman. (#324, #332, #648)
  • The NixOS module system's option wiring is bridged, so flow questions cross the module boundary instead of going dark at it: a config write like launchd.user.agents.myapp = { ... } or home.file.".gitconfig" = { ... } links to the module that declares that option (options.launchd.user.agents = mkOption { ... } — flat and nested declaration spellings both count, quoted keys like system.defaults.NSGlobalDomain."com.apple.dock" match their exact declaration), which makes "how does enabling this service produce the launchd daemon / generated config file" traceable end-to-end and "what sets this option" answerable across modules, tests included. Precision is deliberately conservative: interpolated ${...} paths, options declared in more than one module, and submodule-internal option namespaces stay unlinked rather than guessed, and every bridged hop is labeled as heuristic module-system wiring rather than shown as a plain reference.
  • CodeGraph now indexes ArkTS (.ets) — the language of HarmonyOS / OpenHarmony apps. Everything TypeScript gets extracted (classes, interfaces, enums, type aliases, imports/exports, call edges), plus ArkTS's own constructs: @Component / @ComponentV2 structs with their decorators (@Entry, @State, @Prop, @Link, @Local, @Param, …) captured and searchable, build() view trees linked parent→child so "which pages render this component" is answerable, chained attributes connected to the @Extend/@Styles functions they invoke, @Builder methods and functions wired into the call graph, and .onClick(this.handler)-style event bindings linked to their handler methods. Modular HarmonyOS projects resolve across module boundaries too: a bare import { CartRepository } from "data" follows the oh-package.json5 file: dependency to the right module — honoring each module's declared main entry, from .ets and .ts consumers alike — while ambiguous names in multi-app monorepos deliberately stay unlinked rather than guessed, and mixed .ets/.ts codebases cross-link freely. Validated on real HarmonyOS apps including the official OpenHarmony samples monorepo. (#396, #512, #648, #890)
  • ArkUI's dynamic hops are bridged so flow questions cross them instead of going dark, each labeled as dynamic dispatch rather than shown as a plain call: methods that assign a reactive property (@State, @Local, …) link to the component's build() (the re-render hop — assignment-gated, so a method that merely reads state gets no edge); emitter.emit(eventId) links to the matching emitter.on/once subscriber when both sides share a statically-recoverable event key (numeric ids pair within one file only, named constants within one module, so unrelated samples in a monorepo never cross-link); and router.pushUrl({ url: 'pages/Detail' }) links to the target page's @Entry struct, with ambiguous urls left unlinked rather than guessed.
  • Interrupted or incomplete indexing is now visible instead of silent: a run killed mid-index (crash, out-of-memory, watchdog) leaves a marker that codegraph status reports as a truncated index, a completed run that dropped files reports itself as partial — both in the human output and in status --json — and codegraph index prints a warning with the exact counts when its result doesn't add up to what the scan discovered.
  • CodeGraph now indexes Terraform and OpenTofu (.tf, .tfvars, .tofu) — resources, data sources, modules, variables, outputs, providers, and every locals attribute become symbols (e.g. aws_s3_bucket.my_bucket, var.region, module.vpc, local.prefix), and uses like var.region, module.vpc.id, data.aws_caller_identity.current, or aws_s3_bucket.my.arn are wired up cross-file, so search, callers, and impact queries return real results on infrastructure repos instead of nothing. Module calls are bridged across the module boundary: a module block's inputs link to the child module's variables, module.vpc.vpc_id reaches the child's output "vpc_id" definition, and the block's local source path links to the module's files — so "what breaks if I change this module's variable" reaches every caller instead of dead-ending at the declaration (registry and git sources are deliberately left as visible boundaries rather than guessed). Cross-component wiring through the cloudposse/atmos remote-state module connects too: module.vpc.outputs.vpc_cidr in one component reaches the vpc component's own output when the component name is statically declared (a literal, or a variable with a literal default) and exactly one directory matches — anything dynamic or ambiguous stays unlinked. Aliased providers are first-class: provider "aws" { alias = "east" } gets its own symbol, and provider = aws.east on a resource (or a module's providers map) links to that configuration, found up the module tree the way Terraform actually inherits it. moved/import/removed state-migration blocks and check assertions reference the resources they name, so a refactor's paper trail is part of the graph. .tfvars assignments link to the variables they set, including var-files kept in a subdirectory. Resolution follows Terraform's real per-directory scoping, so same-named variables across modules never cross-link and "what depends on var.project_id" in a multi-module repo never mixes in unrelated modules. Thanks @Javviviii2. (#83, #310, #648)
  • CodeGraph now indexes CUDA (.cu, .cuh) — kernels, device/host functions, structs, and classes become symbols, and the host→kernel call edge survives the <<<grid, block>>> launch syntax, so questions like "how does this call reach the GPU kernel?" trace across the CPU/GPU boundary instead of going dark at the launch site. Real-world launch styles all connect: templated launches (my_kernel<Traits, 256><<<grid, block>>>(args)), launches through a local function pointer (auto kernel = &my_kernel<...>; ... kernel<<<grid, block>>>(args) — each branch-assigned target linked), brace-initialized launch configs (<<<dim3{1,1,1}, dim3{256,1,1}>>>), and kernels defined through a name-in-first-argument macro (flash-attention's DEFINE_FLASH_FORWARD_KERNEL(kernel_name, ...) { ... } style), which now index under their real kernel names. CUDA that lives in plain .h/.hpp headers — where much real-world device code sits, launch-template headers included — is recognized by content and indexed the same way. Validated on llm.c, flash-attention, and NVIDIA CUTLASS. (#387, #648)
  • C++ symbols defined inside namespace blocks now carry the namespace in their qualified name (flash::compute_attn, C++17 namespace a::b { included), and namespace-qualified calls (ns::fn(...)) resolve to their definitions — previously such calls never linked at all, which hid much of the call graph in namespace-heavy C++ codebases from callers and impact analysis.
  • C++ calls that spell out template arguments (fn<T, 256>(args)) now link to the function they instantiate, the same normalization templated base classes already had.
  • CodeGraph now indexes Solidity (.sol) — contracts, libraries, interfaces, structs, enums, modifiers, events, errors, and state variables become first-class symbols, with call edges that follow emit, revert, modifier guards (onlyOwner-style, including base-constructor chains like constructor() ERC20(...)), and library/method calls (including using directives). import directives resolve to the imported file, so cross-contract questions like "trace transferFrom through allowance and balance updates" or "how does onlyRole reach the role storage?" work out of the box on real Solidity codebases (validated on solmate, solady, and OpenZeppelin Contracts). Thanks @naiba. (#374, #648)
  • Erlang behaviour dispatch is now followed through the graph: a framework call through a variable module — cowboy's Handler:init/Middleware:execute folds, a plugin manager's Mod:callback(...) — links to the repo's implementations of the behaviour that declares that callback, so flow traces and impact cross the OTP callback boundary instead of stopping at it. The links are precision-gated: the callback arity must match, exactly one behaviour may own that callback shape (a collision stays unlinked rather than guessed), the implementer must actually export the callback, and the fan-out is bounded — a behaviour with hundreds of implementers stays a visibly dynamic boundary. Every bridged hop is labeled as dynamic dispatch with its wiring site, never shown as a plain static call.
  • CodeGraph now indexes Erlang (.erl, .hrl) — functions, with clauses and arities of the same name grouped as one symbol spanning all of them, plus records with their fields, -type/-opaque aliases, -define macros, and -spec signatures attached to every function. Cross-module mod:fn(...) calls resolve to the target module's function, fun name/arity values are captured as references (so callback registrations like lists:foreach(fun submit/1, ...) link up), -include/-include_lib connect to the header files they pull in, -behaviour declarations link a callback module to its behaviour (and only ever to a module — a same-named macro or function elsewhere in the repo is never mistaken for one), and -export lists (plus -compile(export_all)) drive each function's public/private flag. OTP's indirection idioms are followed where the target is static: spawn/apply/proc_lib/timer/rpc calls that name their target as (Module, Function, Args) arguments produce call edges, and gen_server:call/cast connects to the target module's handle_call/handle_cast — its own when targeting ?MODULE (including the -define(SERVER, ?MODULE) idiom), and the named module when a registered name follows OTP's name-the-server-after-its-module convention (gen_server:call(other_mod, ...), directly or through a -define(STORE, other_mod) macro); a registered name that matches no module stays unlinked. Macros participate in the graph too: a -define body's calls belong to the macro, each ?MACRO(...) use site links into the call chain (and bare ?CONSTANT reads are tracked as references), so a call path hidden behind a macro — set_password → ?SQL_UPSERT_T → sql_query_t — traces end-to-end and "where is this macro used" is answerable. escripts index like any module (the shebang line is understood), and OTP application resource files (.app.src, .app) join the graph: {mod, ...} links an app to its callback module and {applications, [...]} connects umbrella sibling apps — resolving only ever to modules, so an OTP app name like ssl is never mistaken for a same-named function. Truly dynamic dispatch (Mod:handle(...), message sends, var-module spawns) is deliberately left unlinked rather than guessed. codegraph_explore also understands Erlang-native symbol spelling in queries — mod:fn/3 and init/2 find the symbols they name. (#635, #648)
  • CodeGraph now indexes Visual Basic .NET (.vb) — classes, Modules, interfaces, structures, enums, properties, events, MustOverride abstract members, and Declare P/Invoke signatures, with Inherits/Implements hierarchy edges, call edges (resolved through VB's ambiguous call-vs-index parentheses), and New/As New instantiation links. Real-world VB styles parse cleanly: WinForms designer files, interpolated and multi-line strings, XML literals (embedded <%= %> expressions included), single-line and multi-line LINQ queries, multi-line lambdas, Handles/WithEvents event wiring, Custom Events, date literals, classic type-character identifiers (i%, name$), and non-English (Unicode) identifiers. (#648, #639, #170)
  • CodeGraph now indexes COBOL (.cbl, .cob, .cpy) — programs, sections and paragraphs with PERFORM/GO TO call edges, CALL cross-program calls, COPY copybook imports (standalone copybooks included), and DATA DIVISION records with 88-level condition names, in both fixed and free source format. Impact queries work on data items: every MOVE/ADD/COMPUTE/SUBTRACT write-site links back to the field it changes, so "what touches this copybook field" answers across programs. CICS flows connect too: EXEC CICS LINK/XCTL program targets, EXEC SQL INCLUDE copybooks, and pseudo-conversational RETURN TRANSID(...) hops resolve to the program owning the transaction id. (#590, #648)
  • CodeGraph now indexes CFML (.cfc, .cfm, .cfs) — both the classic tag-based style (<cfcomponent>/<cffunction>) and modern bare-script component { ... } syntax, including extends/implements, embedded <cfscript> blocks (at any nesting depth, including inside <cfif>/<cfloop>/<cftry>), call edges, and calls embedded in #hash# expressions inside <cfquery> SQL bodies. Files saved with a UTF-8 byte-order mark and tags with unquoted attribute values — both common in long-lived CFML codebases — are handled too. Thanks @ghedwards. (#1118)
  • CFML inheritance written as a component path now links to the right component. extends="coldbox.system.web.Controller" names its supertype by dotted path and extends="../base" by relative path (the FW/1 style) — both previously produced no inheritance edge at all, which on framework-style CFML apps hid most of the type hierarchy from impact and blast-radius analysis (on ColdBox's own core, over 90% of inheritance was invisible). Resolution is deliberately conservative: the target's directory layout must corroborate the declared path — so a supertype that lives in an out-of-repo library (testbox, mxunit, an installed framework) correctly stays unlinked rather than being guessed at, and an ambiguous path produces no edge rather than a wrong one. (#1152)
  • CFML method calls made through a local variable, typed argument, or component property now resolve to the right method — the same receiver-type inference the other object-oriented languages already had. var svc = new UserService(); svc.save(), createObject("component", "path.UserService"), a typed <cfargument> or cfscript parameter, and variables./this.-scoped fields — including the pseudoconstructor pattern (variables.svc = new UserService() in init()) and WireBox-injected properties (property name="svc" inject="UserService") — all now link the call to the declared component's method, with methods inherited from a supertype resolved through the inheritance links above. This makes callers, impact/blast-radius, and codegraph_explore flow traces follow CFML service calls instead of dropping them or guessing among same-named methods.
  • The Claude Code context hook now recognizes prompts that describe code in plain words — in any language — by checking the prompt's words against the symbol names actually in your project's index. Asking about "the state machine des commandes" finds OrderStateMachine with no keyword involved. Confidence decides how much gets injected: structural questions and prompts naming a real symbol still get full context up front; a plain-words match gets a short pointer to the matching symbols so the agent queries them itself; everything else stays silent, exactly as before.
  • Anonymous usage telemetry now counts how often the context hook injected context, offered a hint, or stayed silent — fixed counter names only; the prompt's content is never stored or sent. This makes the hook's accuracy measurable instead of guessed. The counters record what actually happened, not what was attempted: a lookup that errors or comes back empty counts as a distinct silent outcome, never as delivered context (#1143, thanks @inth3shadows).
  • Metal shader files (.metal) are now indexed. Metal Shading Language is close enough to C++ that vertex/fragment/kernel functions, structs, type aliases, and the calls between them all land in the graph — so shader pipelines in Apple-platform projects show up in impact analysis and flow traces instead of being silently skipped. Metal's [[buffer(0)]]-style attribute annotations are handled so they can't corrupt what gets extracted. Thanks @FluxKo for the report. (#1121)
  • CodeGraph now indexes legacy iBatis 2 SQL maps (<sqlMap>), not just MyBatis 3 <mapper> files. <select>/<insert>/<update>/<delete>, iBatis's <statement>/<procedure>, and <sql> fragments inside a <sqlMap> become searchable statement symbols — for both namespaced maps and the namespace-less Map.statement id style — and <include> references resolve to the fragment they pull in, so search, callers, and impact queries return results on iBatis codebases that previously produced no statement symbols at all. Thanks @ESPINS for the report and the reproduction. (#1182)
  • You can now force gitignored first-party source into the index with an include list in codegraph.json. The case this solves: a project tracked by a second VCS (SVN, Perforce, …) alongside Git, where some real source is committed to that VCS and deliberately listed in .gitignore so it never lands in Git — git never lists those files, so CodeGraph never indexed them, and neither includeIgnored (which only revives embedded git repositories inside a gitignored directory) nor exclude (its opposite) could help. Add a root codegraph.json with, e.g., { "include": ["Tools/", "Local/typescript/"] } and CodeGraph discovers those files directly off disk — overriding .gitignore — and indexes them on the full index, incremental sync, and file-watching, on both git and non-git projects. Patterns are gitignore-style and matched against project-root-relative paths (a directory, a recursive ** glob, or a single file). An explicit exclude still wins, and built-in skips like node_modules, dist, and .git are never re-included. This complements the existing exclude (its opposite — keep tracked files out) and includeIgnored (opt in to gitignored embedded repos).

Fixes

  • Indexing a large Java or Kotlin Spring monorepo is dramatically faster. The reference-resolution phase — the bulk of a first-time codegraph index — could run for the better part of an hour on a big multi-module project and now finishes in a few minutes, producing the same graph. The cause: every receiver.method() call in the codebase was repeatedly scanning the project's entire set of configuration keys looking for a match — work that only ever applies to Spring @Value / @ConfigurationProperties bindings, never to ordinary method calls. As part of the same fix, a method call whose name coincides with a configuration key (say a service.process() call alongside a service.process entry in application.yml) is no longer mislinked to that config key — it now resolves to the actual method. Thanks @bayernjava for the report. (#1180)
  • codegraph init at a parent repository whose .gitignore excludes its child repositories no longer silently indexes nothing and reports success. The "super-repo of gitignored child repos" layout — a top-level Git repo that .gitignores each service-*/ or packages/* child so git status stays quiet — used to index only the parent's few top-level files and print "Done" with 0 nodes, even though running codegraph init inside any child worked fine (CodeGraph respects .gitignore by default, so the excluded children were skipped). Now, when an index comes up empty, CodeGraph detects the gitignored child repositories that were skipped, names them, and — in an interactive terminal — offers to index them (writing an includeIgnored entry to codegraph.json and re-indexing on the spot); non-interactive runs print the exact codegraph.json snippet to add. Projects that legitimately keep gitignored reference clones out of a working index are never nagged: the offer only appears when the index would otherwise be empty. Thanks @small-thanks for the report. (#1156)
  • The MyBatis mapper reader is sturdier on real-world XML. Single-quoted attribute values (id='getById', legal XML and common in older mappers) are no longer skipped, so those statements make it into the graph. Statements and <include>s that were commented out with <!-- ... --> no longer produce phantom symbols. And two vendor-split statements — the same id with databaseId="oracle" / databaseId="mysql" — written on a single line no longer silently drop one of the pair. Thanks @ESPINS for the report, the reproductions, and the fixes. (#1182)
  • codegraph init and codegraph index no longer get killed by the safety watchdog at the "Resolving refs" step on large method-name-heavy codebases (big Java/enterprise monorepos were the main victims, especially on slower machines). Resolution used to come up for air only every 500 references, so a dense stretch of expensive ones could starve the watchdog long enough for it to assume the process was stuck and kill a perfectly healthy index. Resolution now checkpoints after every reference, and two of the expensive steps got much cheaper: repeated method lookups on the same type are now cached, and source files are no longer re-split line-by-line for every call being resolved — indexing such repos is several times faster as a result. Generated or minified single-line files are also skipped during receiver-type inference instead of being scanned per call. Thanks @UchihaYong and @wangmeng-95 for the reports. (#1122)
  • An index left incomplete by an interrupted run now heals itself on the next sync instead of silently staying wrong forever. If indexing died partway through resolving references (a crash, Ctrl-C, or the watchdog kill fixed above), the affected files still looked indexed but their caller/impact edges were missing — a too-small blast radius clustering by package or module, e.g. a Spring @Resource-injected method reporting 3 of its 10 real caller files — and because incremental syncs only re-resolve files that changed, the damage was permanent until a full re-index. Any sync (a watched file change, or a bare codegraph sync) now detects the leftover references and finishes resolving them, codegraph status warns when an index is in that state instead of passing it off as healthy, and a rare early-stop that could abandon resolution on repos whose first files reference only external libraries is fixed too. Thanks @KnifeOfLife for the report and the package-correlation observation that pinned it down. (#1187)
  • The shared background server no longer shuts down out from under a live editor/agent session that simply hasn't queried CodeGraph in a while. A safety timer meant to reap an abandoned server — one whose client vanished without the connection ever closing — was reaping any server that saw no requests for 30 minutes, including a perfectly live session that just wasn't asking CodeGraph anything; that silently dropped the session (and every other session sharing the same background server) to a slower in-process mode for the rest of its life. On one machine over a day it fired 20 times on live sessions and caught zero real phantoms. The timer now checks whether the connected clients are actually still alive and only reaps when none of them are, so a quiet-but-live session keeps its shared server while a genuinely abandoned one is still cleaned up. (#1200)
  • CodeGraph's background server no longer leaves a lingering Node process behind when your editor or agent kills its launcher during startup. If the app that started CodeGraph (Codex, Claude Code, or another MCP client) was killed within the server's first fraction of a second — a config probe, a cancelled request, a startup timeout — while keeping the connection's pipes open, the server could be handed off to the system before its orphan-detection watchdog had captured a reference point, leaving it running (idle, ~30 MB) until the launching app itself exited; over a long day of repeated launches these accumulated. The server now records its parent at the earliest possible moment, and the npm and standalone launchers pass the real host's process id down to it so it can watch the host directly instead of only the launcher that may already be gone. As a final backstop, a server that never receives a single request after starting now shuts itself down instead of waiting for the host to exit — tunable with CODEGRAPH_STARTUP_HANDSHAKE_TIMEOUT_MS (0 disables). Thanks @ruslan33321 for the report. (#1185)
  • The automatic context hook for Claude Code now fires for structural questions asked in nearly thirty languages — French, Spanish, Portuguese, German, Italian, Dutch, Polish, Czech, Romanian, Hungarian, Greek, Swedish, Danish, Norwegian, Finnish, Russian, Ukrainian, Turkish, Indonesian, Vietnamese, Thai, Hindi, Arabic, Farsi, Hebrew, Japanese, Korean, and both simplified and traditional Chinese — instead of just English and simplified Chinese. Previously a natural question like "comment marche la state machine des commandes ?" injected nothing unless it happened to contain a code-shaped symbol name, making the hook look broken for non-English teams. English questions phrased with derived word forms ("explain the architecture…", "what are the dependencies…") now fire too, and prompts in any other language still fire when they name a symbol from the index. Thanks @anthonyle-roy-lgtm for the report. (#1126)
  • Lua and Luau method calls with capitalized names (obj:Method() — the standard Roblox convention) now link to the right method. Because Lua's method-call syntax looks identical to a Luau type annotation, a capitalized call like lg:Log() was misread as declaring the variable's type, so whenever two or more classes shared a method name (Init, Update, Destroy, …) the call was silently dropped from callers, impact/blast-radius, and flow traces. Lowercase method names were unaffected. Thanks @inth3shadows for the precise root-cause analysis and repro. (#1124)
  • Removed dead code left behind by the discontinued managed-reasoning feature. Its codegraph login flow was unplugged before ever shipping in a release, but the unused module still shipped inside the platform bundles, and a security review flagged its Windows browser-open step (it routed the login URL through cmd, which would have been unsafe had the flow ever been wired back up). The leftover module and its tests are now fully deleted. Thanks @inth3shadows for the report. (#1114)
  • The Claude Code context hook no longer treats ordinary English words that merely start with "call", "trace", "affect", or "connect" — callus, calligraphy, Connecticut, connective, affectionate, Tracey — as structural questions, which used to inject full CodeGraph context into prompts that had nothing to do with code structure. Genuinely structural forms (calls, callers, callbacks, call site, traced, tracing, affected, connections, connectivity, …) still fire exactly as before. Thanks @inth3shadows for the report. (#1138)
  • A stuck git command can no longer hang CodeGraph indefinitely. The git checks behind worktree detection and git-hook setup, and the installer's optional npm install -g step, now time out and fail gracefully instead of blocking forever — this matters most for the background MCP server, where an unbounded git hang (network filesystems, a wedged fsmonitor) could previously freeze it long enough for the safety watchdog to kill it. Thanks @inth3shadows for the report. (#1139)
  • The context hook's new plain-words matching works immediately on projects indexed by an older CodeGraph version. The word lookup it relies on is built at index time, so a project indexed before the upgrade had an empty one, and the hook would silently find nothing until something else happened to refresh the index; the hook now fills it in on first use (a one-time step — normally the background MCP server's startup catch-up gets there first). Thanks @inth3shadows for the report. (#1142)
  • Several accuracy fixes to the plain-words matching: a renamed symbol (for example a NestJS route after its module prefix is applied) stays findable under its new name (#1141); a word that only appears in your code as an import statement's package name is no longer presented as a matched symbol (#1144); plural words no longer generate garbled lookup keys ("services" no longer also looks up "servic") (#1145); and a name matching both the singular and plural of one word can no longer squeeze out a genuine two-word match (#1146). Thanks @inth3shadows for the reports.
  • Heavily-reflected Unreal Engine C++ classes are no longer dropped from the index. Reflection markup that decorates members — UPROPERTY(...), UFUNCTION(...), UCLASS(...), GENERATED_BODY(), UE_DEPRECATED_*(...), DECLARE_DELEGATE_*(...) — are no-semicolon macro calls that tree-sitter doesn't recognize, so each drops into error recovery; in a big class the errors pile up until the whole class_specifier collapses and the class, its base clause, and its members vanish (UCharacterMovementComponent, with ~240 such macros, disappeared entirely, breaking every subclass/type-hierarchy and blast-radius query that went through it). These line-leading annotation macros are now blanked (offset-preserving) before parsing so the class survives. Thanks @luoyxy for the report and root-cause analysis. (#1093 follow-up)
  • Unreal Engine members and methods prefixed by an export/visibility macro are no longer lost. The *_API macro doesn't only sit on the class header — it prefixes almost every exported member of a large UE class (ENGINE_API virtual void Tick(...), static ENGINE_API void AddReferencedObjects(...)); the parser read the macro as an extra type token and each such declaration fell into error recovery, so on headers like Actor.h and World.h hundreds of return types piled up as orphan errors and could still tip the class into collapse. Member/method-level *_API / *_EXPORT / *_ABI macros (Unreal, Qt/Boost, LLVM) are now blanked before parsing, mirroring the existing class-header recovery. (#1093 follow-up)
  • Unreal Engine annotation macros that appear mid-line — an enum value's UMETA(DisplayName=...), a parameter's UPARAM(ref), or a deprecation tag wedged into a using alias (using FOnNetTick UE_DEPRECATED(5.5, "...") = ...;, which alone collapsed UWorld in World.h) — are now stripped too. These sit in positions the line-leading recovery structurally can't reach, and a single one could take down the surrounding enum or class. They are matched by an Unreal-only name list (UMETA, UPARAM, UE_DEPRECATED*) so no standard-C++ or other-library code is affected. Together these three fixes recover the main class of every large Unreal Engine header tested (Actor, ActorComponent, SkeletalMeshComponent, World, LightComponent, CharacterMovementComponent). (#1093 follow-up)
  • A C++ header whose only C++ signal is an export-macro-annotated class is no longer misdetected as C — which had silently dropped the class. A .h file defaults to C and is only reclassified as C++ when it shows a C++-specific construct, but that check couldn't see through an export/visibility macro: class ENGINE_API UFoo : public UObject didn't match the macro-blind class Name : pattern, so a lean Unreal-Engine-style header carrying just GENERATED_BODY() and no explicit public: / virtual / namespace / template was parsed as C. The C extractor emits no class nodes, so the class — and its inheritance link — vanished from the graph, quietly undoing the macro-class recovery added in #1061. The C++ detection heuristic now recognizes an export-macro-annotated class/struct declaration (the same shape #1061 blanks before parsing), matching how class Foo : Bar was already detected; the two-token <keyword> <MACRO> <Name> before a [:{] never occurs in valid C, so genuine C headers are unaffected. Thanks @luoyxy for the report and root-cause analysis. (#1133)
