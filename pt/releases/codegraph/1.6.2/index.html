#gráfico de código v1.6.2

[1.6.2] - 03/10/2026

Destaques

  • Muito menos links errados, em todos os idiomas. Uma chamada, importação ou tipo agora resolve a maneira como sua linguagem abrange nomes — por meio de importações, pacotes, namespaces e a classe em que está escrito — parando de chegar a um símbolo não relacionado que apenas compartilha seu nome. Isso abrange TypeScript e JavaScript, Python, Java, Kotlin, Scala, C#, VB.NET, Swift, Objective-C, Go, Rust, C e C++, PHP, Ruby, Dart, Lua, R e muito mais, e torna os chamadores, o impacto e as respostas codegraph_explore mais dignas de trust.
  • Sobrecargas, super e recursão são resolvidas corretamente. Uma chamada atinge a sobrecarga em que seus argumentos cabem, uma chamada super atinge o método pai e um método que chama outra sobrecarga, ou o método de outro objeto com o mesmo nome, não parece mais que chama a si mesmo.
  • Rotas para mais estruturas. Angular (incluindo bibliotecas Nx), aplicativos de administração Vue Router, rotas aninhadas Rails, add_url_rule do Flask, ASP.NET FastEndpoints, subprojetos Play, rotas de fechamento de Vapor e rotas Expo Router API são encontradas. As rotas NestJS e Laravel são nomeadas pelo caminho que uma solicitação realmente segue, e um teste Spring ou Laravel que chama uma rota por URL conta como cobrindo-o.
  • Mais do seu código no gráfico. Opções Vue Componentes API, constantes enum Java e Kotlin com corpos, JavaScript digitado em fluxo, chamadas infix Kotlin, visualizações e eventos nativos React Native, módulos Expo, CFML baseados em tags e arquivos Delphi .inc estão todos indexados agora.
  • Windows: sem janelas piscando, sem travamentos aleatórios. O servidor em segundo plano não abre mais janelas do console enquanto funciona, travamentos esporádicos de violação de acesso (código de saída 3221225477) durante a indexação ou desligamento são corrigidos e o codegraph upgrade funciona enquanto uma sessão do agente está usando o CodeGraph.
  • Um servidor em segundo plano mais estável. MCP clients mais recentes, como Antigravity, se conectam novamente, Claude Code vê o texto completo de codegraph_status, uma sessão que perdeu o servidor compartilhado se reconecta sozinha e um projeto consultado por meio de projectPath é liberado após 10 minutos ociosos.
  • Indexação concluída. Grandes projetos C e C++ não ficam mais sem memória ao resolver referências, um arquivo COBOL não pode mais paralisar a indexação e codegraph sync mantém cada chamador de um nome definido mais de uma vez.
  • Atualização: reindexe seus projetos após esta versão — a maioria dessas correções são escritas durante a indexação.

Novos recursos

  • Nos projetos Nuxt e Astro, uma página roteada por arquivo agora está vinculada ao componente que seu arquivo define. Um endpoint Astro está vinculado aos manipuladores de verbos HTTP que ele exporta, como export const GET. Antes, uma rota de página como a pages/admin.vue da Nuxt ou a src/pages/about.astro da Astro não estava vinculada a nada, então chamadores, impacto e fluxos paravam na rota.
  • Links do React Router e chamadas navigate(…) escritas por meio de um objeto route-config, como o paths.app.discussion.getHref(id) do bulletproof-react, agora alcançam a rota que abrem. Um <Link> com um atributo de função de seta antes de seu to, como onMouseEnter={() => …}, também é lido.
  • As rotas do roteador de dados do React Router são nomeadas por seu caminho completo: os caminhos children aninhados são unidos aos seus pais, as constantes path: paths.app.root.path são lidas e as rotas lazy: () => import('./routes/x') são vinculadas ao componente do módulo. Um invólucro de proteção como <ProtectedRoute> não substitui mais a página. No bulletproof-react, cada rota agora tem seu caminho e página reais.
  • Rotas Vapor cujo manipulador é um fechamento final, como app.get("hello") { req in … }, rotas WebSocket como app.webSocket("chat") { req, ws in … } e registros routes.on(.POST, "x", use: handler) agora são encontradas, e uma rota de fechamento vincula-se ao que o fechamento chama, da mesma forma que um manipulador in-line Express faz. Antes eram lidas apenas rotas com um manipulador use:, e uma rota de fechamento não estava vinculada a nada, então chamadores, impacto e fluxos paravam nela.
  • Arquivos JavaScript digitados em fluxo (aqueles com @flow em seu comentário de cabeçalho) agora são analisados ​​como TypeScript, portanto, anotações de tipo como render(): React.Node não interrompem mais as classes. Isso afeta principalmente o código React Native: nas próprias bibliotecas do React Native o gráfico ganhou mais de 8.000 links e as classes de componentes mantêm seus métodos. Os arquivos sem o pragma permanecem inalterados. Reindexar após a atualização.
  • Um link feito por um framework ou resolvedor de ponte agora registra qual deles o fez (metadata.framework, como swift-objc-bridge ou react-native-bridge), conforme descreve o README. Antes, apenas eventos sintetizados e canais de visualização eram nomeados.
  • Aplicativos ASP.NET criados com FastEndpoints agora têm suas rotas: o Get(…)/Post(…) de cada classe de endpoint em Configure() se torna uma rota vinculada ao seu próprio HandleAsync/ExecuteAsync, incluindo caminhos mantidos na constante Route de uma classe de solicitação. ardalis/CleanArchitecture passou de nenhuma rota para 24. As rotas API mínimas escritas sem uma barra inicial (app.MapGet("api/todos", …)) agora são denominadas /api/todos.
  • São reconhecidos os projetos de reprodução mantidos em subdiretórios, para que seja lido o conf/routes de cada um. Um repositório sem nenhuma versão do Play em sua raiz, como os exemplos do playframework, passou de nenhuma rota para mais de 130.
  • As rotas Rails agora são lidas com seu aninhamento: namespace e scope adicionam seu caminho e módulo controlador, resources aninhado fica sob o :id de seu pai e os blocos member / collection adicionam suas ações. Uma rota com namespace agora é vinculada ao controlador de seu próprio módulo. Rotas em um mecanismo Rails config/routes.rb também são encontradas: solidus passou de nenhuma rota para mais de 600, e os links de rota para ação do mastodon quase triplicaram.
  • Rotas de flask registradas com add_url_rule(…) agora são encontradas e vinculadas à sua função de visualização ou visualização baseada em classe. Assim são as rotas cadastradas através de um helper próprio do projeto que passa uma lista de caminhos e um view_func=. O flaskbb, que registra todas as visualizações dessa forma, passou de nenhuma rota para mais de 100.
  • Os componentes Vue escritos com as opções API (export default { methods: {…}, computed: {…}, watch: {…}, mounted() {…} }), como todo aplicativo Vue 2, agora têm seus métodos, propriedades computadas, observadores e ganchos de ciclo de vida no gráfico. Cada um tem seus próprios chamadores e chamadas, e o @click="handleLogin" de um modelo se vincula ao método que ele executa. No vue-element-admin são mais de 800 novos links, onde as chamadas de um componente pertenciam ao arquivo inteiro.
  • Eventos React Native cujo nome é mantido em uma constante agora vinculam o código nativo ao JavaScript que os escuta, como o addListener(PrivateTypes.DEVICE_CONNECTIVITY_EVENT, …) da NetInfo ou um Java .emit(PROGRESS_EVENT, …). A constante é lida da maneira como a linguagem a define, a partir do mesmo arquivo, de uma importação ou de sua classe proprietária, portanto, um parâmetro que compartilha o nome de uma constante nunca é confundido com ela.
  • As visualizações React Native declaradas com requireNativeComponent('X'), o antigo estilo Paper que usa mapas nativos de reação e controle segmentado, agora vinculam o JavaScript às suas implementações nativas de iOS e Android, como as especificações do Codegen já faziam, inclusive em arquivos .js simples. Uma tag JSX escrita com um nome diferente de seu componente, como <Autocomplete> para import Autocomplete from './autocomplete.vue', agora é vinculada ao componente que ela renderiza.
  • As rotas do Expo Router API (app/hello+api.ts) agora são endpoints, um por método exportado, como GET /hello, vinculados à função que os trata. Eles costumavam aparecer como uma tela chamada /hello+api. Em um repositório cuja raiz declara Expo Router para um aplicativo de exemplo, um aplicativo Next.js em sua própria pasta, como docs/ do react-native-true-sheet, não obtém mais telas Expo feitas a partir de seus arquivos.
  • As chamadas para um módulo Expo agora alcançam as funções nativas do módulo mesmo quando o JavaScript nomeia o módulo com outro nome, como CameraManager da expo-camera para requireNativeModule('ExpoCamera'). Ambas as implementações iOS e Android estão vinculadas. as chamadas da expo-camera costumavam vincular de volta ao método de mesmo nome que fazia a chamada, então um método parecia ter chamado a si mesmo.
  • Aplicativos angulares divididos em bibliotecas Nx, como angular-spotify, agora têm suas rotas e navegação. Uma rota carregada lentamente escrita async () => (await import('@app/home')).HomeModule é seguida através do index.ts da biblioteca até o módulo que ele reexporta, e um routerLink em uma biblioteca agora atinge uma tela declarada em outra. Caminhos de rota construídos a partir de uma constante de classe (RouterUtil.Configuration.Lyrics, `issue/:${ProjectConst.IssueId}`) or an enum are now read. A redirect in a routes file that only lazy-loads others now counts, and router.navigate(['project', 'issue', id]) without relativeTo são lidos da raiz, como Angular faz. Reindexar projetos Angular após a atualização.
  • Os aplicativos React Router agora mostram navegação escrita como <Redirect to="/login" /> do React Router v5 e por meio de um link estilizado, como HeaderLink = styled(Link) do react-boilerplate usado como <HeaderLink to="/features">. Os aplicativos criados dessa forma tinham rotas, mas não tinham links entre suas telas.
  • As rotas do SvelteKit agora são nomeadas pelo endereço solicitado pelo navegador. Uma pasta (group) como (app) ou (marketing) não faz mais parte do caminho de uma rota, e um parâmetro com matcher, como [id=integer], é apenas :id. Assim, goto('/blocks') e <a href="/blocks"> agora chegam a uma página que mora em src/routes/(app)/blocks/, onde antes não chegavam a nada e as telas do aplicativo não mostravam navegação. Reindexe os projetos do SvelteKit após a atualização.
  • Aplicativos Vue Router criados como vue-element-admin, vue-admin-template ou vben agora têm suas rotas e telas. Rotas declaradas em uma tabela nomeada (export const constantRoutes = [...], const routes: RouteRecordRaw[] = [...]), em arquivos de rotas por módulo ou através de new Router(...) agora são lidas. As rotas filhas são unidas ao caminho do pai e o componente do pai é o layout ao redor delas. Uma visualização carregada lentamente (() => import('@/views/dashboard/index')) está vinculada ao arquivo que nomeia e this.$router.push(...) conta como navegação. As rotas baseadas em arquivo do Nuxt agora vêm apenas de um aplicativo Nuxt, então a pasta pages/ de um aplicativo Vue simples não se transforma mais em telas inventadas, e um aplicativo Nuxt na raiz de seu repositório agora obtém suas rotas. Reindexe projetos Vue após a atualização.
  • As rotas NestJS agora são nomeadas pelo caminho que uma solicitação segue: o prefixo global de app.setGlobalPrefix('api') é aplicado, junto com sua lista exclude, assim como o versionamento de URI de app.enableVersioning(...), com @Version, VERSION_NEUTRAL e o próprio version do controlador levado em consideração. Uma rota que costumava aparecer como GET /user agora é GET /api/v1/user, portanto, a chamada this.http.get('/api/v1/user') ou fetch de um front end se conecta ao método do controlador que a atende. Reindexe projetos NestJS após a atualização.
  • As rotas do Laravel agora são nomeadas pelo caminho que uma solicitação segue: um / inicial é adicionado onde o arquivo de rotas o deixa de fora, os grupos Route::prefix() e Route::group(['prefix' => …]) são aplicados e as rotas em routes/api.php carregam o prefixo /api sob o qual o Laravel as atende, lidas em seu RouteServiceProvider, bootstrap/app.php ou qualquer arquivo que monte um arquivo de rotas. Um front-end fetch('/api/…') agora se conecta à rota Laravel que o atende. Reindexar projetos Laravel após a atualização.
  • Controladores que testes Spring ou Laravel exercitam por URL agora contam como testados. Isso abrange perform(post("/owners/new")) do MockMvc, WebTestClient, ​​TestRestTemplate, RestAssured, $this->postJson('api/me') do Laravel, get('/about') do Pest e ajudantes de solicitação do próprio projeto construídos sobre eles. codegraph_explore agora nomeia o conjunto de testes que atinge tal ponto final, onde antes cada um deles parecia não ter sido testado. Reindexe os projetos Spring e Laravel após a atualização.
  • Em um aplicativo Angular, um método que um modelo chama, como (click)="toggleFavorite()" ou (ngSubmit)="submitForm()", agora está vinculado a seu componente. Esses métodos costumavam não mostrar nenhum chamador, então as perguntas do impacto e dos chamadores paravam neles, e as verificações de código morto podiam listá-los como não utilizados. Reindexar projetos Angular após a atualização.
  • Aplicativos angulares agora possuem rotas e navegação no gráfico. Cada tela em uma matriz Routes é uma rota nomeada por seu caminho completo, incluindo filhos, arquivos loadChildren carregados lentamente e NgModules, caminhos escritos como constantes de rota ou strings $localize e redirecionamentos. Cada rota está vinculada ao seu componente. router.navigate([...]), navigateByUrl, o createUrlTree de um guarda e cada routerLink no modelo de um componente se vinculam à tela que abrem, e os componentes filhos de um modelo (<app-article-list>) são vinculados ao componente que os renderiza. Perguntas como "para onde vai esse botão" e "o que renderiza esse componente" agora têm respostas no codegraph_explore. Reindexar projetos Angular após a atualização.
  • Os arquivos de inclusão Delphi e Free Pascal (.inc) agora são indexados como Pascal. Antes, eles eram lidos como PHP e ficavam vazios. Um arquivo .inc com uma tag <?php ainda é PHP, e um mapeamento codegraph.json para .inc ainda vence. Obrigado @ijbranch pelo relatório. (#2279)
  • No CFML baseado em tags, as chamadas escritas em tags agora são vinculadas: nas expressões <cfset>, <cfif>/<cfelseif>, <cfreturn>, <cfloop condition> e #…#. Antes, apenas os códigos <cfscript> e <cfquery> eram lidos, então os chamadores e o impacto não encontravam quase nada em componentes baseados em tags. Funções agrupadas em tags como <cfprocessingdirective> ou <cfsilent> agora também são indexadas, e um <cfinterface> é indexado como uma interface à qual implements se vincula. Reindexar projetos CFML após a atualização. Obrigado @HarryMuc pelo relatório. (#2091)
  • Constantes enum Java e entradas enum Kotlin com corpo próprio agora têm seus métodos no gráfico. Exemplos são PLUS { int apply(…) { … } } e NewBuffer { override fun pipe() … }. Antes, esses métodos estavam faltando e todas as chamadas dentro deles eram descartadas. O tokenizer HTML e o construtor de árvore do jsoup são escritos dessa maneira, portanto, mais de 2.000 de suas chamadas eram invisíveis. Reindexe para pegar isso.
  • Chamadas infixas do Kotlin, como Users.id eq id1 ou single { … } bind MyApi::class do koin, agora são registradas como chamadas para a função infixa. Antes, eles não tinham nenhum chamador. No Exposed, eq agora mostra mais de mil chamadores. As operações de bits em números (x and 0xff, h shr 8) são deixadas para os próprios operadores do Kotlin, mesmo quando o projeto define uma extensão com o mesmo nome. Reindexar após a atualização.

Correções

####Janelas

  • No Windows, as janelas do terminal não abrem e fecham mais enquanto o CodeGraph é executado em segundo plano. Desde 1.6.1, um servidor MCP em segundo plano exibia uma janela de console (uma janela completa do Terminal do Windows quando esse é o terminal padrão) várias vezes quando era iniciado e novamente sempre que sincronizava novamente um arquivo alterado. Todas as chamadas git do CodeGraph agora são executadas ocultas. Obrigado @Suharaz, @23q3, @A-Van-Gestel, @HarryMuc e @MzaGuille. (#2094, #2096, #2312)
  • No Windows, um projeto aberto com uma letra de unidade ou nome de pasta diferente, como d:\work\app e D:\Work\App, agora se junta ao servidor de segundo plano CodeGraph que já está em execução para ele. Antes, cada ortografia iniciava um servidor próprio que saía de uma vez, então a sessão servia silenciosamente o gráfico por si só, sem observação de arquivos compartilhados ou sincronização automática, e codegraph list mostrava o projeto duas vezes. Obrigado @greatjackzhou. (#2278)
  • No Windows, o codegraph upgrade não interrompe mais a instalação enquanto uma sessão do agente está usando o CodeGraph. Ele costumava parar no meio do caminho e deixar o CodeGraph incapaz de iniciar; agora ele troca os novos arquivos com o CodeGraph em execução e coloca a versão anterior de volta se algo falhar, e a nova execução do instalador do PowerShell funciona da mesma maneira. Se uma atualização anterior já interrompeu sua instalação, execute novamente o irm https://raw.githubusercontent.com/colbymchenry/codegraph/main/install.ps1 | iex para repará-lo. Obrigado @tippmar-nr pelo relatório. (#2185)
  • No Windows, o CodeGraph às vezes não trava mais com o código de saída 3221225477 (uma violação de acesso) em uma máquina ocupada: logo após a análise em codegraph init, codegraph index e sincronizações em segundo plano, ou quando o servidor em segundo plano é desligado. Interromper um de seus threads auxiliares (aqueles que analisam arquivos, resolvem referências, gravam o índice e contam alterações para codegraph_status) enquanto ele ainda estava inicializando ou antes de terminar de limpar sua memória, interrompeu todo o processo. Os threads agora terminam de iniciar e são limpos antes de saírem.

O servidor de segundo plano, sessões e o CLI

  • O gancho de prompt do Claude Code não é mais executado nas mensagens que o Claude Code usa para devolver o relatório de um subagente à sessão principal. Antes, um relatório tão longo poderia manter o gancho ocupado além do tempo limite de 30 segundos do gancho de Claude Code e injetar contexto não relacionado ao que você perguntou. Obrigado @danusha2345 e @tippmar-nr pelo relatório. (#2184)
  • MCP clients mais recentes, como Antigravity 2.5, conectam-se novamente: o servidor agora responde à sonda server/discover imediatamente com "método não encontrado", então eles vão direto para o aperto de mão normal em vez de esperar por uma resposta que pode levar segundos ou nunca chegar. Obrigado @danusha2345 e @samem26 pelo relatório. (#2084)
  • Uma sessão CodeGraph que consultou outro projeto através de projectPath não mantém mais esse projeto bloqueado enquanto estiver em execução: após 10 minutos sem consulta ele libera o projeto, para que a própria sessão do projeto e codegraph index possam assumir novamente (sintonize com CODEGRAPH_PROJECT_IDLE_TIMEOUT_MS, 0 mantém-no aberto). Obrigado @danusha2345 e @bompus pelo relatório. (#2087)
  • Claude Code agora mostra ao modelo o texto completo de codegraph_status e da recusa do índice obsoleto do explore. Ambos os resultados também continham structuredContent, e Claude Code mostra o structuredContent de um resultado no lugar de seu texto, então o modelo viu apenas um objeto JSON atualizado: nenhuma mensagem de recusa, nenhuma orientação de nova tentativa e nenhum relatório de status. Ambos os resultados agora são apenas texto. Obrigado @bompus. (#2088)
  • Quando um agente pergunta ao CodeGraph sobre um repositório git separado aninhado dentro de um projeto indexado, um que o índice do projeto deixa de fora (por exemplo, porque o .gitignore do pai o exclui), ele agora recebe a orientação usual "não está indexado" em vez de respostas do código do projeto pai. Repositórios aninhados que o pai indexa, como submódulos, funcionam como antes. Obrigado @wstczyw pelo relatório. (#2110)
  • Uma sessão de agente que perdeu sua conexão com o servidor de segundo plano compartilhado do CodeGraph ou não conseguiu acessá-lo na inicialização não interrompe mais a execução do servidor pelo restante da sessão. Ele se reconecta sozinho assim que o servidor pode ser iniciado, para que outras sessões no mesmo projeto sejam sincronizadas automaticamente em vez de serem executadas somente leitura. Obrigado @ijbranch pelo relatório. (#2277)
  • codegraph index não desiste mais com "Não foi possível verificar se o daemon CodeGraph ativo parou" enquanto o servidor de segundo plano ainda está concluindo seu desligamento, e codegraph daemon não relata mais tal servidor como um que não pôde parar; ambos agora esperam que ele saia, por cerca de 20 segundos. Uma sessão de agente que está servindo o CodeGraph por si só, porque o servidor em segundo plano estava indisponível, agora também espera que esse trabalho pare antes de sair, em vez de sair no meio, o que pode travar no Windows. Obrigado @bompus. (#2311)
  • A telemetria de uso anônimo agora envia uma contagem diária por ferramenta ou comando, conforme documentado, em vez de uma por processo de codegraph. Antes, a cada inicialização do servidor MCP, o comando CLI e o gancho de prompt enfileiravam sua própria entrada, de modo que uma máquina ocupada carregava milhares de cópias da mesma contagem todos os dias. Se você tiver a telemetria desativada, nada muda.

Indexação e sincronização

  • Um arquivo COBOL cuja última linha termina dentro da área de sequência (colunas 1 a 6), como um período de fechamento recuado apenas quatro espaços, não para mais a indexação por mais de um minuto e depois termina no índice sem símbolos.
  • Editar um arquivo que define o mesmo nome mais de uma vez, como duas classes em que cada uma possui um método execute ou sobrecargas de método, não move mais todos os chamadores de outros arquivos para um deles durante codegraph sync. Uma sincronização interrompida no meio de um arquivo também não perde mais esses chamadores até uma reindexação completa. Obrigado @ijbranch pelo relatório. (#2276)
  • A indexação de um grande projeto C ou C++ não fica mais sem memória no meio da "Resolução de referências". Cabeçalhos cujo protetor de inclusão é escrito como #define X_H 1, como em OpenSceneGraph e osgEarth, ou que estão incluídos em um codegraph de sinalizador de construção não podem ser conhecidos, costumavam ser relidos em cada caminho de inclusão, que cresce exponencialmente com a profundidade da árvore de inclusão. Cada um agora é lido uma vez por estado de inclusão, e um limite rígido interrompe a verificação em qualquer árvore de inclusão que ainda seja muito grande. Obrigado @ danusha2345 e @coolhitmanleon pelo relatório. (#2127)
  • Em uma máquina ocupada, a indexação ou sincronização de um projeto pequeno não inicia mais threads extras em segundo plano para resolver referências que não podem ser usadas. Sob carga pesada, o ritmo mais lento fazia com que um projeto de dez arquivos parecesse grande o suficiente para precisar deles, o que acrescentava segundos à execução e mantinha memória extra.

Em vários idiomas

  • Um tipo que estende outro tipo com o mesmo nome agora é vinculado a esse outro tipo em vez de a si mesmo. Quando a fonte especifica o qualificador, esse qualificador escolhe entre candidatos com o mesmo nome. Antes, o trait BigDecimalInstances extends cats.kernel.instances.BigDecimalInstances dos gatos e cada trait AllOps … with Functor.AllOps[…] apontavam para a característica de declaração, e o JsonConverter<T> : JsonConverter da Newtonsoft.Json se estendia.
  • As convenções de nomes de framework para Django, FastAPI, Flask, ASP.NET, Gin, SwiftUI e Vapor agora escolhem apenas uma classe que a referência pode ver. Exemplos dessas convenções são "um …View é uma visualização", "um …Service é um serviço" e "um nome capitalizado é um modelo". A escolha começa no próprio arquivo da referência e depois em seu pacote, e nunca pega uma classe declarada dentro de alguma função ou aninhada na classe de outro arquivo. Antes, os testes do framework REST do Django vinculavam o MockView e Serializer de cada arquivo a outro arquivo, e os testes do netbox vinculavam TestForm() a um formulário declarado dentro de uma função de teste diferente.
  • Um método que chama um método de mesmo nome no resultado de outra expressão não está mais vinculado a si mesmo em nenhuma linguagem. Exemplos são requestToArmeria(request).execute() de Scala dentro de execute(), self.0.into_route(state) de Rust dentro de into_route() e this@Buffer.write(…) de Kotlin de um objeto interno. Um valor cuja cadeia inicializadora chama um método de mesmo nome, como o val response = basicRequest.get(…).response(…) do sttp, também não está mais vinculado a si mesmo.
  • Um método que transfere sua chamada para outro objeto não está mais vinculado a si mesmo. Em TypeScript e JavaScript, uma chamada através de this.<field> ou window.<x> conta como recursão somente quando o campo é declarado como classe própria do método. Uma estimativa apenas do nome de um destinatário nunca chega ao método de chamada. Antes, toggle() do BookStack fazendo this.container.classList.toggle('open'), listen() fazendo window.$events.listen(…) e FileStorage::delete fazendo $storage->delete($path) apontavam para si mesmos.
  • Uma função ou nome passado como valor agora é resolvido para o que está no escopo onde está escrito. Uma função aninhada dentro de outra função só pode ser acessada de dentro dela. No Python, um parâmetro ou local de mesmo nome é aquele local. Um fixture pytest é um parâmetro de teste apenas em seu próprio módulo ou sob seu conftest.py. Antes, o self._build_auth(auth) do httpx vinculado a um auth um teste define dentro de outra função, e auth_flow(self, request) entregando request vinculado à função request() do pacote.
  • Em Java, C#, Kotlin, Swift, Scala, Dart e VB.NET, uma chamada agora atinge a sobrecarga cujos parâmetros se ajustam aos seus argumentos, e não a sobrecarga de mesmo nome que foi indexada primeiro. Por exemplo, HashCodeBuilder.reflectionHashCode(this) agora atinge a sobrecarga de um argumento com varargs, não uma sobrecarga de três parâmetros. Os chamadores de cada sobrecarga agora são seus.
  • Um método que chama outra sobrecarga de si mesmo agora está vinculado a essa sobrecarga e não a si mesmo. Um exemplo é toInstant(instant) retornando toInstant(instant, Instant.EPOCH). A sobrecarga mais completa agora lista suas sobrecargas de conveniência entre seus chamadores, de modo que seu impacto os inclui. Isso se aplica a Java, C#, Kotlin, Swift, C++, Scala, Dart e VB.NET. A recursão real permanece inalterada.
  • O código de produção não está mais vinculado a um símbolo de mesmo nome dentro de um conjunto de testes, pois os testes não são integrados ao programa. Antes, os tipos Record<string, …> do typeorm atingiam uma entidade de teste chamada Record, e as anotações de amostra @Override do okhttp atingiam a classe Override aninhada de um teste. O código de suporte de teste enviado por um projeto, como uma pasta testing/ ou um módulo *-test, permanece ao seu alcance.
  • Uma chamada de método em uma variável não é mais considerada um método duplo de teste apenas porque o duplo tem o único método com esse nome. Isso cobria classes chamadas Mocked…, Fake…, Stub… ou Dummy…: as chamadas resp.json() do Django-allauth foram todas para seu MockedResponse. Um teste que nomeia o duplo ainda o chama.
  • Uma chamada através de um nome de classe, como THorse.Get(…), MyView.as_view() ou ColorChoices.values(), agora atinge o método de classe que a classe herda. A herança é lida a partir das próprias declarações de classe, em Pascal, Python, Ruby, PHP, TypeScript/JavaScript e na família Java. Antes, essa ligação era resolvida adivinhando o nome. No Horse, THorse.Get('/ping', …) costumava pousar 120 vezes em uma interface de grupo de rotas Get. Reindexar após a atualização.
  • Um método adivinhado a partir do nome de um receptor não chega mais a um manipulador de solicitações para o qual a estrutura da web envia, como post / get de uma visualização Django ou DRF ou update / destroy de um controlador. Ele também não chega mais a um teste duplo que o arquivo de chamada nunca menciona. No Django-allauth, o client.post(…) dos testes costumava pousar em um ClientRegistrationView 425 vezes. No Mealie, o response.json() costumava pousar no _FakeHTTPResponse de teste 424 vezes. No Python, site = Site.objects.create(…) agora transforma site em Site, então site.save() atinge o próprio save do modelo. Reindexar após a atualização.
  • Em C#, Java e Kotlin, uma chamada por meio de um campo, propriedade ou parâmetro agora chega ao método do tipo com o qual foi declarado. Isso inclui um tipo herdado de uma classe base com seu argumento de tipo preenchido, uma declaração genérica ou for-each, um alias C# using e um limite de parâmetro de tipo. Uma chamada não depende mais de uma estimativa do método de mesmo nome de alguma classe de projeto, e um tipo de fora do projeto não fornece nenhum link. No Newtonsoft.Json, _innerWriter.WriteValue(…) dentro de um invólucro de gravador costumava pousar no próprio WriteValue do invólucro e um Write(…) de TextWriter em um gravador de teste. Em commons-lang, o parse(…) de um campo DateFormat costumava pousar no DateParser do projeto 284 vezes.
  • Uma chamada a uma variável declarada com um tipo de fora do projeto (List<String> list, var sb = new StringBuilder(), signer = TimestampSigner()) não pousa mais em um método de tipo de projeto com o mesmo nome. No gson, list.add(…) costumava pousar em um wrapper de lista de projetos; em commons-lang, s.length() e buffer.append(…) em classes de projeto. No Python, um argumento de palavra-chave dentro de uma chamada (prefix=IPNetwork(…)) não é mais considerado para uma atribuição a esse nome.
  • Uma chamada a um tipo de fora do projeto, como Integer.valueOf(…), Arrays.asList(…), Object.assign(…) ou Exception.Create(…) do Delphi, não cai mais no próprio método do projeto com esse nome. Em commons-lang, Integer.valueOf costumava pousar em StringUtils.valueOf mais de 800 vezes. As variáveis ​​exportadas do Go e os parâmetros capitalizados e locais do Pascal não são confundidos com nomes de tipos.
  • Em PHP, CFML, Pascal, COBOL e VB.NET, uma chamada escrita em um caso diferente do que sua definição agora resolve, como formatprice() para FormatPrice ou ToMatchWithCase() do CFML para toMatchWithCase. Essas linguagens ignoram maiúsculas e minúsculas nos nomes, mas essas chamadas costumavam ser descartadas antes da resolução.
  • Em Java, Kotlin, Swift, C#, C e C++, Go, Scala, Ruby, Dart e outras linguagens que diferenciam maiúsculas de minúsculas, um nome não está mais vinculado a um símbolo cujo nome difere apenas em maiúsculas e minúsculas. No jsoup, o @Test do JUnit vinculou todos os testes a um método test; new CookieManager() foi vinculado a um getter cookieManager() e um tipo Method a um method(). PHP, Pascal, CFML, COBOL e VB.NET, cujos nomes realmente ignoram maiúsculas e minúsculas, permanecem inalterados.
  • Uma chamada super em um método de substituição, como super.viewDidLoad(), [super init], base.Handle(), parent::setUp() ou super().dispatch(…), não faz mais com que o método pareça que chama a si mesmo. A chamada vai para a versão pai, portanto, uma substituição deixa de aparecer como recursiva e não é mais listada entre seus próprios chamadores.
  • Um parâmetro de tipo genérico, como A em def zipWith[A, B](…), T em <T> T max(…) ou class Foo<T>, não está mais vinculado a um símbolo de projeto que compartilha seu nome. Em gatos, um implicit def A tinha milhares de dependentes inventados de cada A da biblioteca. O mesmo vale para Rust, Dart, TypeScript, Java, Kotlin, Swift, Go, C# e C++. Uma classe ou outro tipo declarado dentro de uma função só é vinculado dentro dessa função. No Scala, o próprio parâmetro de um def, como f em (f: A => B), não está mais vinculado a um campo de mesmo nome em outro lugar. Um nome simples não alcança mais um tipo aninhado dentro de outro tipo, a menos que o código esteja dentro desse tipo, estenda-o ou importe seus membros; o tipo no escopo é vinculado, como o próprio FlatMap dos gatos no lugar do FlatMap aninhado de Eval. Reindexe projetos nesses idiomas após a atualização.

O manipulador é o último argumento da rota, portanto, um middleware embutido antes de um manipulador nomeado não o substitui mais, e um wrapper como asyncHandler(async function (req, res) {…}) e uma vírgula final funcionam. Antes, uma rota como a POST /login não estava ligada a nada.

Antes, as funções remotas do SvelteKit vinculavam validate(arg) ao validate de seu carregador de configuração em outro pacote, e os exemplos do Express vinculavam logger('dev') ao logger de um exemplo.

Antes, o <Item.Root> do shadcn-svelte era vinculado a um type Item que um componente de exemplo declara para si mesmo, e o isActive do halo importado de seu núcleo de editor vinculado ao valor local de um componente de guia.

Antes, cada parâmetro object do auxiliar lodash era vinculado a um function object() {} declarado dentro de runInContext, e o new Class(…) de zod era vinculado a um Class não relacionado quando Class era o parâmetro da função. Resultados de gancho desestruturados como const { t } = useI18n() ainda estão vinculados à função de onde vêm.

As regras do Vue (macros do compilador, importações automáticas do Nuxt, componentes por nome) agora se aplicam apenas aos scripts do aplicativo.

Uma classe aninhada dentro da classe de outro arquivo nunca é alcançada pelo seu nome simples. Antes, o restante dessa linha era um erro de análise e, em um arquivo com muitos deles, toda a classe ao seu redor poderia ser perdida. C# e VB.NET

  • Os nomes C# agora seguem os escopos da linguagem. Um bloco namespace X { … } qualifica apenas os tipos dentro dele, portanto, um tipo declarado após o bloco, ou no segundo namespace de um arquivo, não é mais arquivado no primeiro. Um namespace escrito dentro de outro é Outer.Inner. Um using vincula-se ao namespace do projeto em vez de outro arquivo using com o mesmo nome. Um global using aplica-se apenas dentro do seu próprio projeto. Um tipo aninhado é acessível pelo nome simples apenas de dentro de seu proprietário ou de um tipo derivado dele, inclusive por meio de outra parte parcial. Antes, o Guard do serilog era arquivado sob JetBrains.Annotations, o Some.InformationEvent() de seus testes ia para o Some dos testes de desempenho e o new Source() do mesmo arquivo do AutoMapper poderia alcançar o Source aninhado de outra classe de teste.

Também contado: um global using para todo o projeto, as entradas <Using> do projeto, os usos implícitos do SDK ou um alias que o nomeie. Antes, os testes async Task da Newtonsoft vinculavam Task a uma classe de teste com esse nome em outro namespace, e os DTOs do AutoMapper vinculavam-se ao BaseEntity de outro namespace.
  • Os membros C# de uma interface agora são públicos e os tipos declarados sem modificador agora são internos, conforme a linguagem define. Uma chamada em um campo digitado pela interface agora atinge o método da interface, onde não encontrava nada. Uma estimativa do nome de um destinatário agora pesa apenas o nome do tipo de proprietário, não seu namespace. Nomes .NET padrão como ToString, Add e Write precisam de um receptor com o nome do proprietário. Em todas as linguagens, uma suposição do código de produção não chega mais a uma simulação ou auxiliar definido em um conjunto de testes. Reindexar após a atualização.
  • Em C#, um nome simples como TestContext, Easing ou Helper() agora é resolvido apenas para um membro da classe em que está escrito, suas classes externas, suas classes base ou um tipo trazido com using static. Isso inclui um global using static e um <Using … Static="true"/> de arquivo de projeto. No eShop, o TestContext das classes de teste costumava pousar na propriedade de outra classe de teste; em Newtonsoft.Json, TypeNameHandling.All agora atinge o enum em vez de uma propriedade com o mesmo nome.
  • No VB.NET, uma chamada através de um receptor como Me.Panel.Controls.Add(…) ou New System.Drawing.Size(…) não chega mais a um membro de classe não relacionado com o mesmo nome. Agora resolve apenas através de Me, MyBase ou MyClass, através da classe ou módulo do próprio membro (Logger.Log(…)), ou através de um tipo de consulta de serviço (GetService(Of Notifier).Notify()). No SCrawler, o código do designer do Windows Forms usado para vincular mais de 700 chamadas Size a um caso de enum aninhado e mais de 500 chamadas Controls.Add a uma classe de coleção.
  • Em C# e VB.NET, um tipo escrito em código, como Type sourceType, List<int>, new TypeMap() ou Dictionary<string, Type>, agora está vinculado ao tipo e não mais a uma propriedade, método ou campo que compartilha seu nome. List<…> usado para vincular a propriedade List de alguma classe de teste, Type a uma propriedade Type de um atributo e um parâmetro do tipo TypeMap a uma propriedade TypeMap em vez da classe TypeMap. Esses membros apareceram com centenas de dependentes inventados. Ler uma propriedade ou passar um método, como Builder.Services ou MapGet("/x", GetItems), ainda vincula como antes. Reindexar projetos C# e VB.NET após a atualização.

  • Uma classe Objective-C que está em conformidade com um protocolo com seu próprio nome agora se vincula a esse protocolo em vez de a si mesma. Antes, cada uma das classes estilo @interface SDDiskCache : NSObject <SDDiskCache> do SDWebImage era implementada sozinha.

Um nome de biblioteca padrão posteriormente em uma cadeia (axis.entries.removeAll(), names.contains(x)) não chega mais ao método de um tipo de projeto, a menos que o receptor ou o rótulo do argumento da chamada aponte para ele. Um global em um playground ou alvo de teste não está mais vinculado ao código principal. Reindexar após a atualização.

Uma mensagem para self ou super atinge apenas a classe do remetente e suas superclasses, incluindo categorias nas visualizações UIKit e AppKit. Uma chamada no estilo C como completionBlock() nunca é considerada um método ou propriedade. Uma mensagem para uma variável local utiliza o tipo declarado da variável (FMResultSet *rs). No SDWebImage, [self class], respondsToSelector: e isKindOfClass: costumavam pousar nas substituições de uma classe de proxy mais de 150 vezes, e no fmdb [rs close] agora atinge o conjunto de resultados.

Apenas o query era mantido, então a chamada vinculada ao query do tipo vinha primeiro; em um aplicativo Vapor, cada tipo de rota tem um, então os chamadores, o impacto e as respostas codegraph_explore apontaram para o código de outro endpoint. Uma chamada em um caminho de tipo que não nomeia nenhum tipo no projeto, como um Plot.Node.footer(…) de SDK, é deixada desvinculada. Reindexe projetos Swift após a atualização.

Cada um costumava obter uma segunda cópia de uma linha, sem chamadores ou chamadas, que aparecia ao lado do tipo real na pesquisa e as respostas do codegraph_explore eram um beco sem saída. Reindexe projetos Swift após a atualização.

Reindexe projetos Swift após a atualização.

Um extension View { … } ou extension Text { … } costumava substituir o tipo do SwiftUI, portanto, cada visualização, cada Text("…") e cada Color.red em um aplicativo vinculado a qualquer arquivo que o estendesse. Esses arquivos lideraram as listas de maior dependência e seu impacto atingiu todo o aplicativo. Reindexe projetos Swift após a atualização.

Reindexar projetos Vapor após a atualização.

Em Rust, Vec::new(), String::from(…) e caminhos de módulos como task::spawn(…) permanecem como bibliotecas padrão. No fmt, 1.728 chamadas fmt::format(…) não eram vinculadas a nada, assim como cerca de 1.400 chamadas py::… no pybind11.

Em Tóquio, .map(…) em um Option costumava pousar em MutexGuard::map; no axum, o get(handler) do roteador no get de um pote de biscoitos; em ripgrep, .clone() em um tipo de erro.
  • Em Rust, um Ok(…), Some(…), Err(…), Result<…>, Option<…>, Vec<…> ou drop(…) simples agora significa a biblioteca padrão, a menos que o arquivo defina ou importe um item de projeto com esse nome. Eles costumavam vincular a qualquer variante ou estrutura de enum com o mesmo nome no projeto: cada Some(x) em ripgrep para a variante Some de um enum, e cada Ok e Result em serde para estruturas declaradas por seus testes de macro-higiene. Uma variante de enum agora é alcançada por um nome simples apenas quando o arquivo uses o faz ou é * de seu enum, e uma variante nunca representa um tipo. Reindexe os projetos Rust após a atualização.

  • No PHP, um nome de classe não qualificado agora é resolvido para a classe do namespace atual ou aquela que um use importa, como o PHP faz. Se a classe importada vier de uma biblioteca, ela não será resolvida no projeto. Antes, as solicitações de formulário de Koel vinculavam extends Request a qualquer classe Request indexada primeiro, e os controladores do BookStack vinculavam Request $request (Laravel, por importação) à própria subclasse Request do BookStack.
  • Uma chamada Dart como ext.endsWith(".avi") ou map.putIfAbsent(…) em um valor cujo tipo não é conhecido agora conta como o próprio método String, List ou Map do Dart. Ele não chega mais a um método de projeto com o mesmo nome. Uma extensão Dart também é correspondida pelo tipo que ela estende, não por seu próprio nome, então o ext.endsWith do getx em uma String parou de atingir extension RxStringExt on Rx<String>.
  • Uma chamada de Lua simples como ipairs(t), error("…") ou setup() do busted agora significa a própria função de Lua, a menos que o arquivo defina uma. Ele não chega mais a um método de tabela com o mesmo nome: as chamadas ipairs do telescópio foram para o ipairs de uma lista vinculada e as chamadas error do kong para seu módulo de resposta. O próprio alias de uma função de um membro da tabela host, como local get_query = kong.request.get_query, agora também é seguido.
  • Chamadas Lua feitas através de um alias local agora alcançam a função que ele nomeia. Isso abrange local splitn = require("kong.tools.string").splitn, um membro do módulo como utils.select_listener e uma função que um módulo exporta com outro nome (return { check = check_phase }). Aliases das próprias funções de Lua, como local type = type ou local fmt = string.format, não aparecem mais como chamadas em seu projeto. No Kong, são mais de 1.000 chamadas que agora atingem sua função real e cerca de 5.000 becos sem saída a menos.
  • No Solidity, uma chamada sem receptor agora atinge uma função do contrato ao seu redor ou de um contrato que ela herda. No OpenZeppelin, _msgSender() em contratos construídos em Context costumava pousar na substituição de ERC2771Context 83 vezes. Em Erlang, uma chamada para a função de outro módulo agora segue o -import(Mod, [f/N]) do arquivo. No cowboy, as chamadas -import(req_SUITE, [do_get/3]) costumavam cair no do_get/3 de outra suíte. Uma chamada simples sem essa importação não está mais vinculada a algum outro módulo. Reindexar após a atualização.
  • Em Lua e Luau, uma chamada através de uma tabela de biblioteca padrão ou host (string, table, io, vim, ngx, assert do busted…) ou um método de string como line:find(…) não chega mais ao único método de projeto com o mesmo nome. As funções que o próprio projeto define nessas tabelas ainda estão vinculadas. No kong, as especificações assert.truthy(…) e assert.falsy(…) costumavam pousar em um auxiliar de condição mais de 1.700 vezes; no telescópio, line:find(…) no find do selecionador.
  • No PHP, uma chamada através de uma variável de tipo nada não chega mais ao método de uma classe não relacionada apenas porque é o único método com esse nome. A variável agora precisa ser nomeada após a classe do método, ou após uma classe que a herda ($page->save() onde Page estende Entity). No guzzle, o $response->getHeaderLine() dos testes costumava pousar em um teste duplo; no symfony/console, $e->getMessage() em uma barra de progresso.
  • No CFML, uma chamada não chega mais ao método de um componente não relacionado apenas porque o nome corresponde. Uma chamada sem receptor dentro de um componente agora atinge apenas os métodos desse componente e os dos componentes que ele estende, portanto, recursos integrados como now() permanecem integrados. Uma chamada em uma variável sem tipo agora precisa que a variável seja nomeada após o componente, então server.keyExists(…) não é mais usado para keyExists de algum componente. No coldbox, o now() costumava pousar em um auxiliar de data mais de 200 vezes, e o fail(…) do TestBox nas especificações agora atinge a classe base de especificações.
  • Em Ruby, uma chamada não chega mais a um método de classe não relacionado apenas porque é o único método com esse nome. Uma chamada em um receptor sem tipo agora precisa que o receptor receba o nome da classe do método, como web_push_request.legacy_encrypt. Uma chamada sem receptor dentro de uma classe agora alcança apenas os métodos daquela classe, os métodos de suas superclasses e os dos módulos que ela inclui, estende ou acrescenta. No rubocop, node.loc em um nó de sintaxe usado para pousar no método loc do projeto mais de 1.200 vezes, e format(…) do Kernel no format do servidor de linguagem. No mastodon, render em controladores costumava pousar em um renderizador inline, e authorize agora atinge a preocupação de autorização.
  • No Dart, uma chamada escrita sem receptor agora alcança apenas um método da classe em que está escrita, de uma classe que estende, mistura ou implementa, ou de uma extensão de um desses tipos, e escolhe o mais próximo. No riverpod, test(…) de package:test nos arquivos de teste usados ​​para pousar no método test de uma classe de contêiner mais de 1.100 vezes, expect(…) de prateleira e getx em expect de classes não relacionadas e emit(…) de bloco em um Cubit na classe base errada. As classes declaradas como class A = B with C; agora são indexadas sob seu nome, com o que elas estendem e combinam. Reindexar após a atualização.
  • No R, uma variável atribuída no topo de um arquivo de teste não está mais vinculada ao pacote ou a outros testes, porque testque executa cada arquivo de teste em seu próprio ambiente. No ggplot2, o c <- ggplot(…) de um teste costumava coletar 2.455 chamadas c(…) do pacote. As variáveis ​​em helper-*.R e setup-*.R, que testam que são carregadas para cada teste, ainda são compartilhadas.
  • Em Lua e Luau, uma variável ou função local não está mais vinculada a outros arquivos, pois só é visível no arquivo que a declara. No kong, o local it = it de um auxiliar de especificação costumava coletar o it(…) de todos os outros arquivos de especificação (mais de 4.000 links), e o local ipairs = ipairs de um módulo pegava o ipairs(…) de todo o projeto. As funções globais ainda estão vinculadas entre arquivos.
  • Chamadas PHP em $this, self, static e parent agora alcançam o método da classe em que foram escritas, uma classe que ela estende ou uma característica que qualquer um deles usa, com classes pai e características encontradas através das importações namespace e use do arquivo. No núcleo Drupal, $this->assertEquals() (PHPUnit's) costumava vincular-se a uma classe comparadora não relacionada 8.832 vezes, $this->assertSession() a uma classe base de teste JavaScript e $this->t() a Views::t. Eles agora alcançam UiHelperTrait e StringTranslationTrait, ou nada quando o método reside em um pacote fora do repositório. Uma chamada dentro de uma característica e uma classe base que chama um método definido por sua subclasse mantêm seus links. Reindexe projetos PHP após a atualização.
  • Uma chamada de função PHP escrita após => em um array, como 'count' => count($items), 'by' => user()->id ou 'label' => trans('…'), agora é lida como uma chamada de função simples. Costumava ser usado para uma chamada de método e vinculado a qualquer classe que tivesse um método com esse nome. No BookStack, isso significava 166 links errados.
  • Uma chamada PHP escrita sem receptor, como redirect($url), view('books.show'), auth() ou basename($path), é uma chamada de função e não está mais vinculada a um método, campo ou classe de mesmo nome em qualquer outro lugar do projeto. Esses links errados apareciam em chamadores, impacto e respostas do codegraph_explore sempre que um auxiliar do Laravel ou PHP embutido compartilhava seu nome com um membro do projeto. Reindexe projetos PHP após a atualização.

codegraph v1.6.2

[1.6.2] - 2026-10-03

Highlights

  • Far fewer wrong links, in every language. A call, import or type now resolves the way its language scopes names — through imports, packages, namespaces and the class it is written in — so it stops landing on an unrelated symbol that only shares its name. This covers TypeScript and JavaScript, Python, Java, Kotlin, Scala, C#, VB.NET, Swift, Objective-C, Go, Rust, C and C++, PHP, Ruby, Dart, Lua, R and more, and makes callers, impact and codegraph_explore answers more trustworthy.
  • Overloads, super and recursion resolve correctly. A call reaches the overload its arguments fit, a super call reaches the parent's method, and a method that calls another overload, or another object's method of the same name, no longer looks like it calls itself.
  • Routes for more frameworks. Angular (including Nx libraries), Vue Router admin apps, Rails nested routes, Flask's add_url_rule, ASP.NET FastEndpoints, Play subprojects, Vapor closure routes and Expo Router API routes are found. NestJS and Laravel routes are named by the path a request actually takes, and a Spring or Laravel test that calls a route by URL counts as covering it.
  • More of your code in the graph. Vue Options API components, Java and Kotlin enum constants with bodies, Flow-typed JavaScript, Kotlin infix calls, React Native native views and events, Expo modules, tag-based CFML and Delphi .inc files are all indexed now.
  • Windows: no flashing windows, no random crashes. The background server no longer pops up console windows while it works, sporadic access-violation crashes (exit code 3221225477) while indexing or shutting down are fixed, and codegraph upgrade works while an agent session is using CodeGraph.
  • A steadier background server. Newer MCP clients such as Antigravity connect again, Claude Code sees the full text of codegraph_status, a session that lost the shared server reconnects by itself, and a project queried through projectPath is released after 10 idle minutes.
  • Indexing that finishes. Large C and C++ projects no longer run out of memory while resolving references, a COBOL file can no longer stall indexing, and codegraph sync keeps every caller of a name that is defined more than once.
  • Upgrading: re-index your projects after this release — most of these fixes are written while indexing.

New Features

  • In Nuxt and Astro projects, a file-routed page is now linked to the component its file defines. An Astro endpoint is linked to the HTTP-verb handlers it exports, like export const GET. Before, a page route like Nuxt's pages/admin.vue or Astro's src/pages/about.astro linked to nothing, so callers, impact and flows stopped at the route.
  • React Router links and navigate(…) calls written through a route-config object, like bulletproof-react's paths.app.discussion.getHref(id), now reach the route they open. A <Link> with an arrow-function attribute before its to, such as onMouseEnter={() => …}, is read too.
  • React Router data-router routes are named by their full path: nested children paths are joined to their parent's, path: paths.app.root.path constants are read, and lazy: () => import('./routes/x') routes link to the module's component. A guard wrapper like <ProtectedRoute> no longer stands in for the page. On bulletproof-react, every route now has its real path and page.
  • Vapor routes whose handler is a trailing closure, like app.get("hello") { req in … }, WebSocket routes like app.webSocket("chat") { req, ws in … }, and routes.on(.POST, "x", use: handler) registrations are now found, and a closure route links to what the closure calls, the way an Express inline handler does. Before, only routes with a use: handler were read, and a closure route linked to nothing, so callers, impact and flows stopped at it.
  • Flow-typed JavaScript files (those with @flow in their header comment) are now parsed like TypeScript, so type annotations like render(): React.Node no longer cut classes short. This mostly affects React Native code: on React Native's own libraries the graph gained over 8,000 links, and component classes keep their methods. Files without the pragma are unchanged. Re-index after upgrading.
  • A link made by a framework or bridge resolver now records which one made it (metadata.framework, such as swift-objc-bridge or react-native-bridge), as the README describes. Before, only synthesized event and view channels were named.
  • ASP.NET apps built with FastEndpoints now have their routes: each endpoint class's Get(…) / Post(…) in Configure() becomes a route linked to its own HandleAsync / ExecuteAsync, including paths kept in a request class's Route constant. ardalis/CleanArchitecture went from no routes to 24. Minimal API routes written without a leading slash (app.MapGet("api/todos", …)) are now named /api/todos.
  • Play projects kept in subdirectories are recognized, so each one's conf/routes is read. A repository with no Play build at its root, like playframework's samples, went from no routes to over 130.
  • Rails routes are now read with their nesting: namespace and scope add their path and controller module, nested resources sit under their parent's :id, and member / collection blocks add their actions. A namespaced route now links to its own module's controller. Routes in a Rails engine's config/routes.rb are found too: solidus went from no routes to over 600, and mastodon's route-to-action links nearly tripled.
  • Flask routes registered with add_url_rule(…) are now found and linked to their view function or class-based view. So are routes registered through a project's own helper that passes a list of paths and a view_func=. flaskbb, which registers every view that way, went from no routes to over 100.
  • Vue components written with the Options API (export default { methods: {…}, computed: {…}, watch: {…}, mounted() {…} }), as every Vue 2 app is, now have their methods, computed properties, watchers and lifecycle hooks in the graph. Each one has its own callers and calls, and a template's @click="handleLogin" links to the method it runs. On vue-element-admin that's over 800 new links, where a component's calls used to belong to the whole file.
  • React Native events whose name is held in a constant now link native code to the JavaScript that listens for them, like NetInfo's addListener(PrivateTypes.DEVICE_CONNECTIVITY_EVENT, …) or a Java .emit(PROGRESS_EVENT, …). The constant is read the way the language scopes it, from the same file, an import or its owning class, so a parameter that happens to share a constant's name is never mistaken for it.
  • React Native views declared with requireNativeComponent('X'), the older Paper style that react-native-maps and segmented-control use, now link from JavaScript to their native iOS and Android implementations, as Codegen specs already did, including in plain .js files. A JSX tag written under a different name than its component, like <Autocomplete> for import Autocomplete from './autocomplete.vue', now links to the component it renders.
  • Expo Router API routes (app/hello+api.ts) are now endpoints, one per exported method, like GET /hello, bound to the function that handles them. They used to show up as a screen named /hello+api. In a repository whose root declares Expo Router for an example app, a Next.js app in its own folder, like react-native-true-sheet's docs/, no longer gets Expo screens made from its files.
  • Calls into an Expo module now reach the module's native functions even when the JavaScript names the module something else, like expo-camera's CameraManager for requireNativeModule('ExpoCamera'). Both the iOS and the Android implementations are linked. expo-camera's calls used to link back to the same-named method making the call, so a method looked like it called itself.
  • Angular apps split across Nx libraries, like angular-spotify, now have their routes and navigation. A lazily loaded route written async () => (await import('@app/home')).HomeModule is followed through the library's index.ts to the module it re-exports, and a routerLink in one library now reaches a screen declared in another. Route paths built from a class constant (RouterUtil.Configuration.Lyrics, `issue/:${ProjectConst.IssueId}`) or an enum are now read. A redirect in a routes file that only lazy-loads others now counts, and router.navigate(['project', 'issue', id]) without relativeTo is read from the root, as Angular does. Re-index Angular projects after upgrading.
  • React Router apps now show navigation written as React Router v5's <Redirect to="/login" /> and through a styled link, like react-boilerplate's HeaderLink = styled(Link) used as <HeaderLink to="/features">. Apps built this way had routes but no links between their screens.
  • SvelteKit routes are now named by the address a browser asks for. A (group) folder like (app) or (marketing) is no longer part of a route's path, and a parameter with a matcher, like [id=integer], is just :id. So goto('/blocks') and <a href="/blocks"> now reach a page that lives in src/routes/(app)/blocks/, where before they reached nothing and the app's screens showed no navigation. Re-index SvelteKit projects after upgrading.
  • Vue Router apps built like vue-element-admin, vue-admin-template or vben now have their routes and screens. Routes declared in a named table (export const constantRoutes = [...], const routes: RouteRecordRaw[] = [...]), in per-module route files, or through new Router(...) are now read. Child routes are joined onto their parent's path, and the parent's component is the layout around them. A lazily loaded view (() => import('@/views/dashboard/index')) is bound to the file it names, and this.$router.push(...) counts as navigation. Nuxt's file-based routes now come only from a Nuxt app, so a plain Vue app's pages/ folder no longer turns into made-up screens, and a Nuxt app at the root of its repository now gets its routes. Re-index Vue projects after upgrading.
  • NestJS routes are now named by the path a request takes: the global prefix from app.setGlobalPrefix('api') is applied, along with its exclude list, and so is URI versioning from app.enableVersioning(...), with @Version, VERSION_NEUTRAL and a controller's own version taken into account. A route that used to appear as GET /user is now GET /api/v1/user, so a front end's this.http.get('/api/v1/user') or fetch call connects to the controller method that serves it. Re-index NestJS projects after upgrading.
  • Laravel routes are now named by the path a request takes: a leading / is added where the routes file leaves it out, Route::prefix() and Route::group(['prefix' => …]) groups are applied, and routes in routes/api.php carry the /api prefix Laravel serves them under, read from your RouteServiceProvider, bootstrap/app.php or any file that mounts a routes file. A front-end fetch('/api/…') now connects to the Laravel route that serves it. Re-index Laravel projects after upgrading.
  • Controllers that Spring or Laravel tests exercise by URL now count as tested. That covers MockMvc's perform(post("/owners/new")), WebTestClient, TestRestTemplate, RestAssured, Laravel's $this->postJson('api/me'), Pest's get('/about'), and a project's own request helpers built on them. codegraph_explore now names the test suite that reaches such an endpoint, where before every one of them looked untested. Re-index Spring and Laravel projects after upgrading.
  • In an Angular app, a method a template calls, like (click)="toggleFavorite()" or (ngSubmit)="submitForm()", is now linked from its component. These methods used to show no callers at all, so impact and callers questions stopped at them, and dead-code checks could list them as unused. Re-index Angular projects after upgrading.
  • Angular apps now have routes and navigation in the graph. Each screen in a Routes array is a route named by its full path, including children, lazily loaded loadChildren files and NgModules, paths written as route constants or $localize strings, and redirects. Each route is linked to its component. router.navigate([...]), navigateByUrl, a guard's createUrlTree and every routerLink in a component's template link to the screen they open, and a template's child components (<app-article-list>) are linked to the component that renders them. Questions like "where does this button go" and "what renders this component" now have answers in codegraph_explore. Re-index Angular projects after upgrading.
  • Delphi and Free Pascal include files (.inc) are now indexed as Pascal. Before, they were read as PHP and came up empty. A .inc file with a <?php tag is still PHP, and a codegraph.json mapping for .inc still wins. Thanks @ijbranch for the report. (#2279)
  • In tag-based CFML, calls written in tags are now linked: in <cfset>, <cfif>/<cfelseif>, <cfreturn>, <cfloop condition> and #…# expressions. Before, only <cfscript> and <cfquery> code was read, so callers and impact found almost nothing in tag-based components. Functions wrapped in tags like <cfprocessingdirective> or <cfsilent> are now indexed too, and a <cfinterface> is indexed as an interface that implements links to. Re-index CFML projects after upgrading. Thanks @HarryMuc for the report. (#2091)
  • Java enum constants and Kotlin enum entries with a body of their own now have their methods in the graph. Examples are PLUS { int apply(…) { … } } and NewBuffer { override fun pipe() … }. Before, those methods were missing and every call inside them was dropped. jsoup's HTML tokenizer and tree builder are written this way, so over 2,000 of their calls were invisible. Re-index to pick this up.
  • Kotlin infix calls, like Users.id eq id1 or koin's single { … } bind MyApi::class, are now recorded as calls to the infix function. Before, they had no callers at all. On Exposed, eq now shows over a thousand callers. Bit operations on numbers (x and 0xff, h shr 8) are left to Kotlin's own operators, even where the project defines a same-named extension. Re-index after upgrading.

Fixes

Windows

  • On Windows, terminal windows no longer flash open and closed while CodeGraph runs in the background. Since 1.6.1, a background MCP server popped up a console window (a full Windows Terminal window when that is the default terminal) several times when it started and again every time it re-synced a changed file. All of CodeGraph's git calls now run hidden. Thanks @Suharaz, @23q3, @A-Van-Gestel, @HarryMuc and @MzaGuille. (#2094, #2096, #2312)
  • On Windows, a project opened with a different drive-letter or folder-name case, like d:\work\app and D:\Work\App, now joins the CodeGraph background server that is already running for it. Before, each spelling started a server of its own that exited at once, so the session quietly served the graph by itself with no shared file watching or auto-sync, and codegraph list showed the project twice. Thanks @greatjackzhou. (#2278)
  • On Windows, codegraph upgrade no longer breaks the install while an agent session is using CodeGraph. It used to stop partway and leave CodeGraph unable to start; it now swaps the new files in with CodeGraph running and puts the previous version back if anything fails, and re-running the PowerShell installer works the same way. If an earlier upgrade already broke your install, re-run irm https://raw.githubusercontent.com/colbymchenry/codegraph/main/install.ps1 | iex to repair it. Thanks @tippmar-nr for the report. (#2185)
  • On Windows, CodeGraph no longer sometimes crashes with exit code 3221225477 (an access violation) on a busy machine: right after parsing in codegraph init, codegraph index and background syncs, or as the background server shuts down. Stopping one of its helper threads (the ones that parse files, resolve references, write the index and count changes for codegraph_status) while it was still starting up, or before it had finished cleaning up its memory, took the whole process down. Threads now finish starting and clean up before they exit.

The background server, sessions and the CLI

  • The Claude Code prompt hook no longer runs on the messages Claude Code uses to hand a subagent's report back to the main session. Before, such a long report could keep the hook busy past Claude Code's 30-second hook timeout and inject context unrelated to what you asked. Thanks @danusha2345, and @tippmar-nr for the report. (#2184)
  • Newer MCP clients such as Antigravity 2.5 connect again: the server now answers their server/discover probe right away with "method not found", so they go straight on to the regular handshake instead of waiting on a reply that could take seconds or never come. Thanks @danusha2345, and @samem26 for the report. (#2084)
  • A CodeGraph session that queried another project through projectPath no longer keeps that project locked for as long as it runs: after 10 minutes without a query it lets the project go, so the project's own session and codegraph index can take over again (tune with CODEGRAPH_PROJECT_IDLE_TIMEOUT_MS, 0 keeps it open). Thanks @danusha2345, and @bompus for the report. (#2087)
  • Claude Code now shows the model the full text of codegraph_status and of explore's stale-index refusal. Both results also carried structuredContent, and Claude Code shows a result's structuredContent in place of its text, so the model saw only a freshness JSON object: no refusal message, no retry guidance and no status report. Both results are now text only. Thanks @bompus. (#2088)
  • When an agent asks CodeGraph about a separate git repository nested inside an indexed project, one the project's index leaves out (for example because the parent's .gitignore excludes it), it now gets the usual "isn't indexed" guidance instead of answers from the parent project's code. Nested repositories the parent does index, such as submodules, work as before. Thanks @wstczyw for the report. (#2110)
  • An agent session that lost its connection to CodeGraph's shared background server, or couldn't reach it at startup, no longer stops that server from running for the rest of the session. It reconnects on its own once the server can start, so other sessions on the same project get auto-sync back instead of running read-only. Thanks @ijbranch for the report. (#2277)
  • codegraph index no longer gives up with "Could not verify that the active CodeGraph daemon has stopped" while the background server is still finishing its shutdown, and codegraph daemon no longer reports such a server as one it could not stop; both now wait for it to exit, for up to about 20 seconds. An agent session that is serving CodeGraph by itself, because the background server was unavailable, now also waits for that work to stop before it exits instead of exiting partway through, which could crash on Windows. Thanks @bompus. (#2311)
  • Anonymous usage telemetry now sends one daily count per tool or command, as documented, instead of one per codegraph process. Before, every MCP server launch, CLI command and prompt hook queued its own entry, so a busy machine uploaded thousands of copies of the same count each day. If you have telemetry turned off, nothing changes.

Indexing and sync

  • A COBOL file whose last line ends inside the sequence area (columns 1-6), such as a closing period indented only four spaces, no longer stalls indexing for over a minute and then ends up in the index with no symbols.
  • Editing a file that defines the same name more than once, like two classes that each have an execute method or a method's overloads, no longer moves every caller from other files onto one of them during codegraph sync. A sync interrupted partway through a file also no longer loses those callers until a full re-index. Thanks @ijbranch for the report. (#2276)
  • Indexing a large C or C++ project no longer runs out of memory partway through "Resolving refs". Headers whose include guard is written as #define X_H 1, as in OpenSceneGraph and osgEarth, or that are included under a build flag codegraph cannot know, used to be re-read on every include path, which grows exponentially with the depth of the include tree. Each is now read once per include state, and a hard limit stops the check on any include tree that is still too large. Thanks @danusha2345, and @coolhitmanleon for the report. (#2127)
  • On a busy machine, indexing or syncing a small project no longer starts extra background threads for resolving references that it can't use. Under heavy load the slower pace made a ten-file project look big enough to need them, which added seconds to the run and held extra memory.

Across languages

  • A type that extends another type of the same name now links to that other type instead of to itself. When the source spells out the qualifier, that qualifier picks between same-named candidates. Before, cats' trait BigDecimalInstances extends cats.kernel.instances.BigDecimalInstances and every trait AllOps … with Functor.AllOps[…] pointed back at the declaring trait, and Newtonsoft.Json's JsonConverter<T> : JsonConverter extended itself.
  • Framework name conventions for Django, FastAPI, Flask, ASP.NET, Gin, SwiftUI and Vapor now only pick a class the reference can see. Examples of these conventions are "a …View is a view", "a …Service is a service" and "a capitalized name is a model". The pick starts from the reference's own file and then its package, and never takes a class declared inside some function or nested in another file's class. Before, Django REST framework's tests linked each file's own MockView and Serializer to another file's, and netbox's tests linked TestForm() to a form declared inside a different test function.
  • A method that calls a same-named method on another expression's result is no longer linked to itself in any language. Examples are Scala's requestToArmeria(request).execute() inside execute(), Rust's self.0.into_route(state) inside into_route(), and Kotlin's this@Buffer.write(…) from an inner object. A value whose initializer chain calls a same-named method, like sttp's val response = basicRequest.get(…).response(…), no longer links to itself either.

On eShop, test classes' TestContext used to land on one other test class's property; on Newtonsoft.Json, TypeNameHandling.All now reaches the enum rather than a same-named property.
  • In VB.NET, a call through a receiver like Me.Panel.Controls.Add(…) or New System.Drawing.Size(…) no longer lands on an unrelated class's member with the same name. It now resolves only through Me, MyBase or MyClass, through the member's own class or module (Logger.Log(…)), or through a service lookup's type (GetService(Of Notifier).Notify()). On SCrawler, the Windows Forms designer code used to link over 700 Size calls to a nested enum's case and over 500 Controls.Add calls to a collection class.
  • In C# and VB.NET, a type written in code, like Type sourceType, List<int>, new TypeMap() or Dictionary<string, Type>, now links to the type and no longer to a property, method or field that shares its name. List<…> used to link to some test class's List property, Type to an attribute's Type property, and a parameter of type TypeMap to a TypeMap property instead of the TypeMap class. Those members showed up with hundreds of made-up dependents. Reading a property or passing a method, like Builder.Services or MapGet("/x", GetItems), still links as before. Re-index C# and VB.NET projects after upgrading.

Swift and Objective-C

  • An Objective-C class that conforms to a protocol of its own name now links to that protocol instead of to itself. Swift's naming conventions for views, models and controllers also no longer apply to Objective-C code. Before, every one of SDWebImage's @interface SDDiskCache : NSObject <SDDiskCache>-style classes implemented itself.
  • In Swift, a call to an overloaded method now reaches the overload whose argument labels it spells, with defaulted parameters optional. Before, only the argument count was compared. Alamofire's self.tableView(tableView, numberOfRowsInSection:) inside another tableView overload linked to itself, and cancel(optionallyProducingResumeData:) linked to cancel(producingResumeData:).
  • A Swift call on a property declared with a type, like Kingfisher's var cache: ImageCache! or self.storage.write(…), now reaches that type's method or one it inherits. It no longer lands on a subclass override in a test, or on another type's method of the same name.
  • A Swift call on a value built on the spot, like JSONDecoder().decode(…) or Realm().create(…), now resolves to that type's method, or to one it inherits. It no longer lands on some other type's method of the same name: Vapor's JSONDecoder().decode calls had gone to a request's private container.
  • In Objective-C, [super init] and other messages to super now reach the superclass's method, never the sending class's own override. This also works where the index lost the @implementation's range. On SDWebImage, NSObject subclasses' [super init] used to land on SDDiskCache's init, and [self class] in tests on a proxy class's class. On AFNetworking, a serializer's [super encodeWithCoder:] now reaches its superclass. Re-index after upgrading.
  • In Swift, a call written with no receiver, or through self. or super., now reaches only a member of the type around it or of what that type inherits or conforms to, and the nearest override wins. A standard-library name later in a chain (axis.entries.removeAll(), names.contains(x)) no longer lands on a project type's method, unless the receiver or the call's argument label points to it. On Charts, min(a, b) and max(a, b) used to land on a range type's min field and a Sequence extension, and super.init(…) on an Objective-C demo's init over 170 times. A global in a playground or a test target is no longer linked from the main code. Re-index after upgrading.
  • In Objective-C, a message now reaches a method only when it could really be sent there. A message to self or super reaches only the sender's class and its superclasses, including categories on UIKit and AppKit views. A C-style call like completionBlock() is never taken for a method or property. A message to a local variable uses the variable's declared type (FMResultSet *rs). On SDWebImage, [self class], respondsToSelector: and isKindOfClass: used to land on a proxy class's overrides over 150 times, and on fmdb [rs close] now reaches the result set.
  • A Swift call through a nested type, like API.PackageController.GetRoute.query(on: db), now links to that type's method. Only query used to be kept, so the call linked to whichever type's query came first; in a Vapor app every route type has one, so callers, impact and codegraph_explore answers pointed at another endpoint's code. The same applies to nested types' initializers (API.PackageController.Model(name:)), to enum cases (Gitlab.Error.requestFailed(status:)), to types declared in an extension API.PackageController { … }, and to The Composable Architecture's Path.State.detail(…). A call on a type path that names no type in the project, such as an SDK's Plot.Node.footer(…), is left unlinked. Re-index Swift projects after upgrading.
  • A SwiftUI view, a @main app, a view controller and a UIView subclass are now indexed once. Each used to get a second, one-line copy with no callers or calls, which showed up next to the real type in search and codegraph_explore answers as a dead end. Re-index Swift projects after upgrading.
  • A Swift class or struct that declares a protocol composition across lines, like typealias Client = AutocompleteService.Client followed by & PostingService.Client on the next line, is now indexed whole. That line used to break the parse of the entire enclosing type, so its methods, initializer and properties went missing, and calls into them landed on same-named methods elsewhere. Re-index Swift projects after upgrading.
  • A Swift reference to a type now links to the type's own declaration, not to a file that extends it. An extension View { … } or extension Text { … } used to stand in for SwiftUI's type, so every view, every Text("…") and every Color.red in an app linked to whichever file happened to extend it. Those files topped the most-depended-on lists and their impact reached the whole app. A bare name like @State, @Test or Result<…> no longer links to some other type's nested State or Result, and a qualified name like Build.Id links to the Id it names. Methods declared in an extension of an SDK type still resolve on the types that conform to it, and a protocol's methods declared in any of its extensions now connect to each conforming type's own implementation. Re-index Swift projects after upgrading.
  • A Vapor route now links to the handler it names. use: SearchController.show used to link to whichever controller's show came first, so routes with a common handler name, like show, index or get, pointed at another endpoint's code in callers, impact and codegraph_explore answers. Nested types like API.PackageController.get and handlers declared in an extension of the controller now resolve too, and use: self.index resolves to the collection's own index. Re-index Vapor projects after upgrading.

C, C++, Go and Rust

  • A call in C code is no longer linked to a C++ class's method, since C has no methods and can't call one. Before, redis's POSIX read(fd, buf, n) calls and hiredis's c->funcs->read(…) function pointer pointed at a Qt adapter's read method.
  • In Go, a name written through an imported package from outside the module, like context.Context, http.ResponseWriter or testify's require.Contains, is no longer linked to a project symbol of that name. Before, fiber's context.Context parameters pointed at a method Stream.Context, its require.Contains(…) assertions at an extractor's Contains, and gin's http.ResponseWriter at its own ResponseWriter interface.
  • In Rust, Self::Error in a signature now resolves to the enclosing impl's or trait's own associated type. A path through a generic parameter, like V::Value, no longer resolves to an unrelated struct of that name. Before, serde's Self::Error signatures pointed at its one struct Error, and axum's Self::Error at axum-core's error type.
  • In Rust projects, a struct, handler or service name no longer resolves to an item declared inside some function body, and a file's own item comes before any other crate's. Before, axum's examples' Uri linked to a struct Uri declared inside a routing test, tokio's runtime Handle linked to tokio-test's, and ripgrep's Glob { … } in globset linked to the CLI flags' Glob.
  • Rust type and function names now follow Rust's scoping. A name from another file counts only when a use brings it in (or a * glob over its module). One imported from outside the project, like use std::task::{Context, Poll} or use futures::Stream, means that outside item. A path names its module: io::Result isn't an unrelated Result alias elsewhere, and std::io::Error is std's. On tokio, over 1,200 io::Result and 600 Context references had been landing on private project types.
  • A C++ call into a macro-opened namespace, like fmt::format("{}", x), now picks the overload its arguments fit. Before, the first overload indexed won: fmt's 1,400 fmt::format calls all reached the text_style overload in color.h. A narrow string literal now fits a narrow format string, a wide L"…" fits the wide overload, and the argument count has to fit too.
  • C++ classes written around macros and preprocessor conditionals now keep their members. These include an access specifier spelled as a macro (JSON_PRIVATE_UNLESS_TESTED:), an attribute macro after a template head or a doc comment, and an #if in the middle of a declaration, such as inside a constructor's initializer list. The first branch of a mid-declaration #if is the one indexed. nlohmann/json's basic_json class used to be lost whole and now has its roughly 390 members. Files with a parse error dropped on redis, curl, pybind11 and leveldb, and no file got worse. Re-index after upgrading.
  • Calls on a library's own types and modules no longer land on a project method that happens to share the name. In Rust, Vec::new(), String::from(…) and module paths like task::spawn(…) stay the standard library's. A later link of a multi-line Rust or Go chain now counts as a chained call, named after the chain's first line. In Go, w.Header().Get(…) is net/http's. In R, a plain call like range(x) is a function, not an object's method. In JavaScript, response.text() / .json() is fetch's. On tokio, task::spawn(…) used to land on TaskTracker::spawn 300 times. On ggplot2, range(…) used to land on a coordinate system's range method. Re-index after upgrading.
  • In C and C++, a qualified name like fmt::format now reaches a declaration inside a namespace the library opens with a macro, like fmt's FMT_BEGIN_NAMESPACE, pybind11's PYBIND11_NAMESPACE_BEGIN(…) or rapidjson's and spdlog's …_NAMESPACE_BEGIN. It also works through a namespace alias like namespace py = pybind11;. On fmt, 1,728 fmt::format(…) calls used to link to nothing, and so did about 1,400 py::… calls on pybind11.
  • In Rust and Go, a call later in a chain, like sym.filename().map(…) or c.Flags().String(…), no longer lands on the project's own method of that name when the name is a standard-library one (unwrap, clone, map, iter, Go's String or Error). A plain call like get(handler) or drop(x) never lands on a method. On tokio, .map(…) on an Option used to land on MutexGuard::map; on axum, the router's get(handler) on a cookie jar's get; on ripgrep, .clone() on an error type.
  • In Rust, a bare Ok(…), Some(…), Err(…), Result<…>, Option<…>, Vec<…> or drop(…) now means the standard library's, unless the file defines or imports a project item of that name. These used to link to any same-named enum variant or struct in the project: every Some(x) in ripgrep to one enum's Some variant, and every Ok and Result in serde to structs its macro-hygiene tests declare. An enum variant is now reached by a bare name only where the file uses it or its enum's *, and a variant never stands for a type. Re-index Rust projects after upgrading.

PHP, Ruby, Dart, Lua, R, Solidity, Erlang and CFML

  • In Laravel apps, a route whose controller is named by string now links to its handler, without needing a Controller suffix and keeping the namespace it's written with: 'Common\Uploads@inline', and Route::resource('companies', 'Common\Companies', [...]) with an options array. Two same-named controllers in different namespaces are told apart by that namespace. Before, akaunting linked 304 of its 313 routes to nothing.
  • In Rails apps, a resources line's only: and except: are now read in every form Rails accepts: %i[new create index], %w(index show), a quoted name, and the older :only => [...]. Before, only a bracketed list was read, so maybe's resources :family_exports, only: %i[new create index] became all seven routes, four of them to actions the controller doesn't have.
  • In PHP, a class written with a namespace in its name now links to that class. After use App\Fields as Field;, new Field\FirstName(), extends Field\Base and Field\FirstName::make() all name App\Fields\FirstName, as do Fields\FirstName written inside namespace App; and a fully qualified \App\Fields\FirstName. Before, none of these had a link, so callers and impact missed every class reached that way. Thanks @drakeo338. (#2256)
  • In Solidity, a call to an overloaded function now reaches the overload whose parameter count it fits, as in the other languages with overloading. Before, OpenZeppelin's _checkRole(role, _msgSender()) inside the one-argument _checkRole(bytes32 role) was linked to itself.
  • In R, a call like c(1, 2) is no longer linked to a data variable that happens to share a base function's name, since R skips non-function bindings when it looks up a call. Before, ggplot2's facet tests bound c <- data_frame(b = 3), and every c(…) call in those files pointed at that data frame. Functions built by a factory, like ggplot2's geom_point <- make_constructor(…), still resolve.
  • A Dart extension on X { … } with no name is no longer mistaken for the type X, and its members are reachable only inside the file that declares it, as in Dart. Before, bloc's linter linked analyzer's Token and Dart's Uri to small extension blocks, and every flutter_test find.text(…) call linked to a text getter on another example's TaskStatus.
  • In PHP, an unqualified class name now resolves to the current namespace's class or the one a use imports, as PHP does. If the imported class comes from a library, it resolves to nothing in the project. Before, koel's form requests linked extends Request to whichever Request class was indexed first, and BookStack's controllers linked Request $request (Laravel's, by import) to BookStack's own Request subclass.
  • A Dart call like ext.endsWith(".avi") or map.putIfAbsent(…) on a value whose type isn't known now counts as Dart's own String, List or Map method. It no longer lands on a project method of the same name. A Dart extension is also matched by the type it extends, not by its own name, so getx's ext.endsWith on a String stopped reaching extension RxStringExt on Rx<String>.
  • A bare Lua call like ipairs(t), error("…") or busted's setup() now means Lua's own function unless the file defines one. It no longer lands on a table method of the same name: telescope's ipairs calls had gone to a linked list's ipairs, and kong's error calls to its response module. A function's own alias of a host table member, like local get_query = kong.request.get_query, is now followed as well.
  • Lua calls made through a local alias now reach the function it names. That covers local splitn = require("kong.tools.string").splitn, a module member such as utils.select_listener, and a function a module exports under another name (return { check = check_phase }). Aliases of Lua's own functions, such as local type = type or local fmt = string.format, no longer show up as calls into your project. On Kong that is over 1,000 calls that now reach their real function, and about 5,000 fewer dead-end edges.
  • In Solidity, a call with no receiver now reaches a function of the contract around it or of one it inherits. On OpenZeppelin, _msgSender() in contracts built on Context used to land on ERC2771Context's override 83 times. In Erlang, a call to another module's function now follows the file's -import(Mod, [f/N]). On cowboy, -import(req_SUITE, [do_get/3]) calls used to land on another suite's do_get/3. A bare call with no such import no longer links to some other module. Re-index after upgrading.
  • In Lua and Luau, a call through a standard or host library table (string, table, io, vim, ngx, busted's assert…) or a string method like line:find(…) no longer lands on the one project method with the same name. Functions the project itself defines on those tables still link. On kong, the specs' assert.truthy(…) and assert.falsy(…) used to land on a condition helper over 1,700 times; on telescope, line:find(…) on the picker's find.
  • In PHP, a call through a variable nothing types no longer lands on an unrelated class's method just because it's the only method with that name. The variable now needs to be named after the method's class, or after a class that inherits it ($page->save() where Page extends Entity). On guzzle, the tests' $response->getHeaderLine() used to land on a test double; on symfony/console, $e->getMessage() on a progress bar.
  • In CFML, a call no longer lands on an unrelated component's method just because the name matches. A call with no receiver inside a component now reaches only that component's methods and those of the components it extends, so built-ins like now() stay built-ins. A call on an untyped variable now needs the variable to be named after the component, so server.keyExists(…) is no longer taken for some component's keyExists. On coldbox, now() used to land on a date helper over 200 times, and TestBox's fail(…) in specs now reaches the spec base class.
  • In Ruby, a call no longer lands on an unrelated class's method just because it's the only method with that name. A call on an untyped receiver now needs the receiver to be named after the method's class, like web_push_request.legacy_encrypt. A call with no receiver inside a class now reaches only that class's methods, its superclasses' methods, and those of the modules it includes, extends or prepends. On rubocop, node.loc on a syntax node used to land on the project's one loc method over 1,200 times, and Kernel's format(…) on the language server's format. On mastodon, render in controllers used to land on an inline renderer, and authorize now reaches the authorization concern.
  • In Dart, a call written without a receiver now reaches only a method of the class it's written in, of a class it extends, mixes in or implements, or of an extension on one of those types, and picks the nearest one. On riverpod, package:test's test(…) in the test files used to land on a container class's test method over 1,100 times, shelf's and getx's expect(…) on unrelated classes' expect, and bloc's emit(…) in a Cubit on the wrong base class. Classes declared as class A = B with C; are now indexed under their name, with what they extend and mix in. Re-index after upgrading.
  • In R, a variable assigned at the top of a test file is no longer linked from the package or from other tests, because testthat runs each test file in its own environment. On ggplot2, a test's c <- ggplot(…) used to collect 2,455 of the package's c(…) calls. Variables in helper-*.R and setup-*.R, which testthat loads for every test, are still shared.
  • In Lua and Luau, a local variable or function is no longer linked from other files, since it's only visible in the file that declares it. On kong, a spec helper's local it = it used to collect every other spec file's it(…) (over 4,000 links), and one module's local ipairs = ipairs took the whole project's ipairs(…). Global functions are still linked across files.
  • PHP calls on $this, self, static and parent now reach the method of the class they're written in, a class it extends, or a trait any of them uses, with parent classes and traits found through the file's namespace and use imports. On Drupal core, $this->assertEquals() (PHPUnit's) used to link to an unrelated comparator class 8,832 times, $this->assertSession() to a JavaScript-test base class, and $this->t() to Views::t. They now reach UiHelperTrait and StringTranslationTrait, or nothing when the method lives in a package outside the repository. A call inside a trait, and a base class calling a method its subclass defines, keep their links. Re-index PHP projects after upgrading.
  • A PHP function call written after => in an array, like 'count' => count($items), 'by' => user()->id or 'label' => trans('…'), is now read as a plain function call. It used to be taken for a method call and linked to whichever class had a method of that name. On BookStack, that meant 166 wrong links.
  • A PHP call written without a receiver, such as redirect($url), view('books.show'), auth() or basename($path), is a function call, and no longer links to a same-named method, field or class elsewhere in the project. These wrong links showed up in callers, impact and codegraph_explore answers wherever a Laravel helper or PHP built-in shared its name with a project member. Re-index PHP projects after upgrading.
