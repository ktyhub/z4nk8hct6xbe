druida druida-0.13.0-incubating

Druid 0.13.0-incubating contém mais de 400 novos recursos, melhorias de desempenho/estabilidade/documentação e correções de bugs de 81 colaboradores. É a primeira versão do Druid no programa Apache Incubator. Os principais novos recursos e melhorias incluem:

  • indexação de lote paralelo nativo
  • compactação automática de segmentos
  • tabelas de esquema do sistema
  • status aprimorado da tarefa de indexação, estatísticas e relatórios de erros
  • Tratamento nulo compatível com SQL
  • cache do corretor em nível de resultado
  • ingestão de RDBMS
  • Suporte ao filtro Bloom
  • formatos de resultados SQL adicionais
  • agregadores adicionais (stringFirst/stringLast, ArrayOfDoublesSketch, HllSketch)
  • suporte para múltiplas especificações de agrupamento na consulta groupBy
  • suporte mútuo TLS
  • Gerenciamento de trabalhadores baseado em HTTP
  • contrapressão do corretor
  • configuração de ajuste de ingestão maxBytesInMemory
  • visões materializadas (extensão da comunidade)
  • analisador para Influx Line Protocol (extensão da comunidade)
  • Emissor OpenTSDB (extensão da comunidade) A lista completa de alterações está aqui: https://github.com/apache/incubator-druid/pulls?q=is%3Apr+is%3Aclosed+milestone%3A0.13.0 A documentação para esta versão está em: http://druid.io/docs/0.13.0-incubating/

Destaques

Indexação em lote paralelo nativo

Apresenta o supervisor index_parallel que gerencia a ingestão paralela em lote de fontes divisíveis sem exigir dependência do Hadoop. Consulte http://druid.io/docs/latest/ingestion/native_tasks.html para obter mais informações. Observação: Esta é a implementação inicial monofásica e tem limitações sobre como espera que os dados de entrada sejam particionados. Notavelmente, ele não possui uma implementação shuffle que será adicionada na próxima iteração deste recurso. Para mais detalhes, consulte a proposta em #5543. Adicionado por @jihoonson em #5492.

Compactação automática de segmento

Anteriormente, compactar pequenos segmentos em segmentos de tamanho ideal para melhorar o desempenho da consulta exigia o envio e a execução de tarefas de compactação ou reindexação. Muitas vezes, esse era um processo manual ou exigia um agendador externo para lidar com o envio periódico de tarefas. Este patch implementa compactação automática de segmentos gerenciada pelo serviço coordenador. Observação: Esta é a implementação inicial e tem limitações de interoperabilidade com tarefas de ingestão em tempo real. Atualmente, as tarefas de indexação exigem a aquisição de um bloqueio na parte da linha do tempo que serão modificadas para evitar inconsistências de operações simultâneas. Essa implementação usa bloqueios de baixa prioridade para garantir que nunca interrompa a ingestão em tempo real, mas isso também significa que a compactação poderá falhar em fazer qualquer progresso se as tarefas em tempo real adquirirem bloqueios continuamente no intervalo de tempo que está sendo compactado. Isso será melhorado na próxima iteração deste recurso com bloqueio mais refinado. Para mais detalhes, consulte a proposta em #4479. Documentação para este recurso: http://druid.io/docs/0.13.0-incubating/design/coordinator.html#compacting-segments Adicionado por @jihoonson em #5102.

Tabelas de esquema do sistema

Adiciona um esquema de sistema à interface SQL que contém tabelas que expõem informações sobre segmentos atendidos e publicados, nós do cluster e informações sobre tarefas de indexação em execução e concluídas. Observação: Esta implementação contém algumas ineficiências de sobrecarga conhecidas que serão abordadas em um patch futuro. Documentação para este recurso: http://druid.io/docs/0.13.0-incubating/querying/sql.html#system-schema Adicionado por @surekhasaharan em #6094.

Status, estatísticas e relatórios de erros aprimorados da tarefa de indexação

Melhora o desempenho e os detalhes dos APIs relacionados à ingestão, que anteriormente eram bastante opacos, dificultando a determinação da causa de exceções de análise, falhas de tarefas e a saída real de uma tarefa concluída. Também adiciona relatórios aprimorados de métricas de ingestão, incluindo estatísticas de rendimento médio móvel. Adicionado por @surekhasaharan e @jon-wei em #5801, #5418 e #5748.

Tratamento nulo compatível com SQL

Melhora o tratamento de valores nulos pelo Druid, tratando-os como valores ausentes em vez de serem equivalentes a strings vazias ou um valor zero. Isso torna o Druid mais compatível com SQL e melhora a integração com ferramentas externas de BI que suportam ODBC/JDBC. Consulte #4349 para proposta. Para ativar esse recurso, você precisará definir a propriedade druid.generic.useDefaultValueForNull=false de todo o sistema. Adicionado por @nishantmonu51 em #5278 e #5958.

Cache do corretor em nível de resultados

Implementa cache em nível de resultado em corretores que podem operar simultaneamente com o cache em nível de segmento tradicional. Consulte #4843 para proposta. Documentação para este recurso: http://druid.io/docs/0.13.0-incubating/configuration/index.html#broker-caching Adicionado por @a2l007 em #5028.

Ingestão de RDBMS

Apresenta um firehose sql que suporta ingestão de dados diretamente de um RDBMS. Adicionado por @a2l007 em #5441.

Suporte ao filtro Bloom

Adiciona suporte para otimizar consultas Druidas aplicando um filtro Bloom gerado por um sistema externo como Apache Hive. No futuro, #6397 suportará a geração de filtros Bloom como resultado de consultas Druid que podem então ser usadas para otimizar consultas futuras. Adicionado por @nishantmonu51 em #6222.

Formatos adicionais de resultados SQL

Adiciona formatos de resultados para JSON e CSV baseados em linha e, adicionalmente, cabeçalhos de resposta X-Druid-Column-Names e X-Druid-Column-Types contendo uma lista de colunas contidas no resultado. Adicionado por @gianm em #6191.

agregadores 'stringLast' e 'stringFirst'

Apresenta dois agregadores complementares, stringLast e stringFirst que operam em colunas de string e retornam o valor com o carimbo de data / hora máximo e mínimo respectivamente. Adicionado por @andresgomezfrr em #5789.

ArrayOfDoublesSketch

Adiciona suporte para esboços Tuple numéricos, que estendem a funcionalidade da contagem de esboços Theta distintos, adicionando matrizes de valores duplos associados a chaves exclusivas. Adicionado por @AlexanderSaydakov em #5148. ###HllSketch Adiciona uma implementação configurável de um agregador de contagem distinto baseado em HllSketch de https://github.com/DataSketches.. A comparação com o HyperLogLogCollector nativo do Druid mostra maior precisão, eficiência e velocidade: https://datasketches.github.io/docs/HLL/HllSketchVsDruidHyperLogLogCollector.html Adicionado por @AlexanderSaydakov em #5712.

Suporte para múltiplas especificações de agrupamento na consulta groupBy

Adiciona suporte para o parâmetro groupBy subtotalsSpec que permite que o Druid seja eficiente ao reutilizar resultados intermediários no nível do corretor ao executar múltiplas consultas que agrupam por subconjuntos do mesmo conjunto de colunas. Consulte a proposta em #5179 para obter mais informações. Adicionado por @himanshug em #5280.

Suporte mútuo a TLS

Adiciona suporte para TLS mútuo (validação de certificado de servidor + validação de certificado client). Veja: https://en.wikipedia.org/wiki/Mutual_authentication Adicionado por @jon-wei em #6076.

Gerenciamento de trabalhadores baseado em HTTP

Adiciona uma implementação de gerenciamento de tarefas de indexação baseada em HTTP para substituir a anterior baseada em ZooKeeper. Parte de um conjunto de melhorias para reduzir e eventualmente eliminar a dependência do Druida do ZooKeeper. Consulte #4996 para proposta. Adicionado por @himanshug em #5104.

Contrapressão do corretor

Permite que o corretor exerça contrapressão nos nós de serviço de dados para evitar que o corretor trave sob pressão de memória quando os resultados chegam mais rápido do que são lidos por clients. Adicionado por @gianm em #6313.

configuração de ajuste de ingestão 'maxBytesInMemory'

Anteriormente, um parâmetro de ajuste importante para indexar o gerenciamento de memória de tarefas era a configuração maxRowsInMemory, que determinava o limite para derramar o conteúdo da memória no disco. Isso era difícil de configurar corretamente, pois o “tamanho” de uma linha variava com base em vários fatores. maxBytesInMemory torna esta configuração baseada em bytes em vez de baseada em linhas. Adicionado por @surekhasaharan em #5583.

Visualizações materializadas

Suporta a criação de visualizações materializadas que podem melhorar o desempenho da consulta em determinadas situações ao custo de armazenamento adicional. Consulte http://druid.io/docs/latest/development/extensions-contrib/materialized-view.html para obter mais informações. Observação: Esta é uma extensão contribuída pela comunidade e não é incluída automaticamente na distribuição Druid. Agradecemos comentários para decidir quando promover isso para uma extensão principal. Para obter mais informações, consulte Extensões da comunidade. Adicionado por @zhangxinyu1 em #5556.

Analisador para protocolo de linha de influxo

Adiciona suporte para ingestão do formato de dados Influx Line Protocol. Para mais informações, consulte: https://docs.influxdata.com/influxdb/v1.6/write_protocols/line_protocol_tutorial/ Observação: Esta é uma extensão contribuída pela comunidade e não é incluída automaticamente na distribuição Druid. Agradecemos comentários para decidir quando promover isso para uma extensão principal. Para obter mais informações, consulte Extensões da comunidade. Adicionado por @njhartwell em #5440.

Emissor OpenTSDB

Adiciona suporte para emissão de métricas Druid para OpenTSDB. Observação: Esta é uma extensão contribuída pela comunidade e não é incluída automaticamente na distribuição Druid. Agradecemos comentários para decidir quando promover isso para uma extensão principal. Para obter mais informações, consulte Extensões da comunidade. Adicionado por @QiuMM em #5380.

Atualizando de 0.12.3 e anteriores

Veja abaixo as alterações entre 0.12.3 e 0.13.0 que você deve conhecer antes de atualizar. Se você estiver atualizando de uma versão anterior ao 0.12.3, consulte release notes das versões intermediárias relevantes para notas adicionais.

A extensão de armazenamento de metadados MySQL não inclui mais o driver JDBC

A extensão de armazenamento de metadados MySQL agora é empacotada junto com a distribuição Druid, mas sem o driver MySQL JDBC necessário (devido a restrições de licenciamento). Para usar esta extensão, o driver precisará ser baixado separadamente e adicionado ao diretório da extensão. Consulte http://druid.io/docs/latest/development/extensions-core/mysql.html para obter mais detalhes.

Configuração da região AWS necessária para extensão S3

Como resultado da mudança do jets3t para o AWS SDK (#5382), os usuários da extensão S3 agora são obrigados a definir explicitamente a região de destino. Isso pode ser feito configurando a propriedade de sistema JVM aws.region ou a variável de ambiente AWS_REGION. Por exemplo, para definir a região como 'us-east-1' por meio das propriedades do sistema:

  • adicione -Daws.region=us-east-1 ao arquivo jvm.config para todos os serviços Druidas
  • adicione -Daws.region=us-east-1 a druid.indexer.runner.javaOpts em middleManager/runtime.properties para que a propriedade seja passada para processos peon (trabalhador)

Alterações nas especificações de ingestão

Como resultado da renomeação do pacote de io.druid para org.apache.druid, as especificações de ingestão que fazem referência às classes por seu nome de classe totalmente qualificado precisarão ser modificadas adequadamente. Por exemplo, se você estiver usando a extensão Parquet com indexação Hadoop, o campo inputFormat do inputSpec precisará mudar de io.druid.data.input.parquet.DruidParquetInputFormat para org.apache.druid.data.input.parquet.DruidParquetInputFormat.

Mudanças nas métricas

Novas métricas

  • task/action/log/time - Milissegundos necessários para registrar uma ação de tarefa no log de auditoria (#5714)
  • task/action/run/time - Milissegundos necessários para executar uma ação de tarefa (#5714)
  • query/node/backpressure - Nanossegundos em que o canal fica ilegível devido à aplicação de contrapressão (#6335) (Observe que isso não está habilitado por padrão e requer uma implementação personalizada de QueryMetrics para emitir)

Novas dimensões

  • taskId e taskType adicionados às métricas relacionadas a tarefas (#5664)

Outro

  • HttpPostEmitterMonitor não emite mais maxTime e minTime se nenhum tempo for registrado (#6418)

Restrições de reversão

Agregadores duplos de 64 bits

Agregadores duplos de 64 bits agora são usados por padrão (veja #5478). O suporte para colunas de ponto flutuante de 64 bits foi lançado no Druid 0.11.0, portanto, se estiver habilitado, versões anteriores a 0.11.0 não serão capazes de ler os segmentos de dados. Para desabilitar e manter o formato antigo, você precisará definir a propriedade druid.indexing.doubleStorage=float de todo o sistema.

Desativando índices de bitmap

0.13.0 adiciona suporte para desabilitar índices de bitmap por coluna, o que pode economizar espaço nos casos em que os índices de bitmap não agregam valor. Isso é feito definindo o campo 'createBitmapIndex' no esquema da dimensão. Os segmentos escritos com esta opção não serão compatíveis com versões anteriores do Druid (#5402).

Mudanças de comportamento

Mudanças no nome do pacote Java

Todos os nomes dos pacotes do Druid mudaram de io.druid para org.apache.druid. Isso afeta o nome da classe principal Java que você deve executar ao iniciar os serviços, que agora é org.apache.druid.cli.Main. Também pode afetar a instalação e configuração de extensões e monitores.

ParseSpec agora é um campo obrigatório nas especificações de ingestão

Não existe mais um ParseSpec padrão (anteriormente DelimitedParseSpec). As especificações de ingestão agora exigem que parseSpec seja especificado. Se você não forneceu anteriormente um parseSpec, você deve usar um com "format": "tsv" para manter o comportamento existente (#6310).

Altere para o número máximo de linhas padrão para retornar em um quadro JDBC

O valor padrão para druid.sql.avatica.maxRowsPerFrame foi reduzido de 100k para 5k para minimizar erros de falta de memória (#5409).

Mudança de comportamento do roteador ao rotear para corretores dedicados a diferentes intervalos de tempo

Como resultado do #5595, os roteadores agora podem selecionar um corretor indesejado em configurações onde existem diferentes níveis de corretores que se destinam a serem dedicados a consultas em diferentes intervalos de tempo. Veja #1362 para discussão.

Ruby TimestampSpec não ignora mais milissegundos

Os carimbos de data e hora analisados usando um TimestampSpec com formato 'ruby' não truncam mais o componente de milissegundos. Se você estava usando este analisador e queria uma granularidade de consulta de SECOND, certifique-se de que ele esteja configurado adequadamente em suas especificações de indexação (#6217).

Pequeno aumento no tamanho dos anúncios de tarefas ZooKeeper

O nome da fonte de dados foi adicionado a TaskAnnouncement, o que resultará em um pequeno aumento por tarefa na quantidade de dados armazenados em ZooKeeper (#5511).

Adição do campo 'nome' aos agregadores filtrados

Agregadores do tipo 'filtrado' agora suportam um campo 'nome'. Anteriormente, o agregador filtrado herdava o nome do agregador que ele empacotava. Se você tiver fornecido o campo 'nome' para o agregador filtrado e para o agregador empacotado, ele preferirá o nome do agregador filtrado. Ele usará o nome do agregador empacotado se o nome do agregador filtrado estiver ausente ou vazio (#6219).

utf8mb4 agora é o conjunto de caracteres de armazenamento de metadados recomendado

Para obter instruções de atualização, use as instruções ALTER DATABASE e ALTER TABLE conforme descrito aqui: https://dev.mysql.com/doc/refman/5.7/en/charset-unicode-conversion.html. Para motivação e referência, consulte #5377 e #5411.

Propriedades de configuração removidas

  • druid.indexer.runner.tlsStartPort foi removido (#6194).
  • druid.indexer.runner.separateIngestionEndpoint foi removido (#6263).

Mudanças na interface para desenvolvedores de extensões

  • A embalagem foi renomeada de io.druid para org.apache.druid. Todas as extensões de terceiros precisarão renomear seu META-INF/io.druid.initialization.DruidModule para org.apache.druid.initialization.DruidModule e atualizar o pacote de sua extensão adequadamente (#6266).
  • A interface DataSegmentPuller foi removida (#5461).
  • Várias funções do java-util foram removidas (#5461).
  • O construtor da classe Metadata mudou (#5613).
  • O perfil Maven 'spark2' foi removido (#5581).

Descontinuações do API

Senhor Supremo

  • O endpoint /druid/indexer/v1/supervisor/{id}/shutdown foi descontinuado em favor de /druid/indexer/v1/supervisor/{id}/terminate (#6272 e #6234).
  • O endpoint /druid/indexer/v1/task/{taskId}/segments foi descontinuado (#6368).
  • O campo status retornado por /druid/indexer/v1/task/ID/status foi descontinuado em favor de statusCode (#6334).
  • Os parâmetros reportParseExceptions e ignoreInvalidRows para configurações de ajuste de ingestão foram descontinuados em favor de logParseExceptions e maxParseExceptions (#5418).

Corretor

  • O endpoint /druid/v2/datasources/{dataSourceName}/dimensions foi descontinuado. Uma consulta de metadados de segmento ou a tabela SQL INFORMATION_SCHEMA deve ser usada (#6361).
  • O endpoint /druid/v2/datasources/{dataSourceName}/metrics foi descontinuado. Uma consulta de metadados de segmento ou a tabela SQL INFORMATION_SCHEMA deve ser usada (#6361).

druid druid-0.13.0-incubating

Druid 0.13.0-incubating contains over 400 new features, performance/stability/documentation improvements, and bug fixes from 81 contributors. It is the first release of Druid in the Apache Incubator program. Major new features and improvements include:

  • native parallel batch indexing
  • automatic segment compaction
  • system schema tables
  • improved indexing task status, statistics, and error reporting
  • SQL-compatible null handling
  • result-level broker caching
  • ingestion from RDBMS
  • Bloom filter support
  • additional SQL result formats
  • additional aggregators (stringFirst/stringLast, ArrayOfDoublesSketch, HllSketch)
  • support for multiple grouping specs in groupBy query
  • mutual TLS support
  • HTTP-based worker management
  • broker backpressure
  • maxBytesInMemory ingestion tuning configuration
  • materialized views (community extension)
  • parser for Influx Line Protocol (community extension)
  • OpenTSDB emitter (community extension)

The full list of changes is here: https://github.com/apache/incubator-druid/pulls?q=is%3Apr+is%3Aclosed+milestone%3A0.13.0

Documentation for this release is at: http://druid.io/docs/0.13.0-incubating/

Highlights

Native parallel batch indexing

Introduces the index_parallel supervisor which manages the parallel batch ingestion of splittable sources without requiring a dependency on Hadoop. See http://druid.io/docs/latest/ingestion/native_tasks.html for more information.

Note: This is the initial single-phase implementation and has limitations on how it expects the input data to be partitioned. Notably, it does not have a shuffle implementation which will be added in the next iteration of this feature. For more details, see the proposal at #5543.

Added by @jihoonson in #5492.

Automatic segment compaction

Previously, compacting small segments into optimally-sized ones to improve query performance required submitting and running compaction or re-indexing tasks. This was often a manual process or required an external scheduler to handle the periodic submission of tasks. This patch implements automatic segment compaction managed by the coordinator service.

Note: This is the initial implementation and has limitations on interoperability with realtime ingestion tasks. Indexing tasks currently require acquisition of a lock on the portion of the timeline they will be modifying to prevent inconsistencies from concurrent operations. This implementation uses low-priority locks to ensure that it never interrupts realtime ingestion, but this also means that compaction may fail to make any progress if the realtime tasks are continually acquiring locks on the time interval being compacted. This will be improved in the next iteration of this feature with finer-grained locking. For more details, see the proposal at #4479.

Documentation for this feature: http://druid.io/docs/0.13.0-incubating/design/coordinator.html#compacting-segments

Added by @jihoonson in #5102.

System schema tables

Adds a system schema to the SQL interface which contains tables exposing information on served and published segments, nodes of the cluster, and information on running and completed indexing tasks.

Note: This implementation contains some known overhead inefficiencies that will be addressed in a future patch.

Documentation for this feature: http://druid.io/docs/0.13.0-incubating/querying/sql.html#system-schema

Added by @surekhasaharan in #6094.

Improved indexing task status, statistics, and error reporting

Improves the performance and detail of the ingestion-related APIs which were previously quite opaque making it difficult to determine the cause of parse exceptions, task failures, and the actual output from a completed task. Also adds improved ingestion metric reporting including moving average throughput statistics.

Added by @surekhasaharan and @jon-wei in #5801, #5418, and #5748.

SQL-compatible null handling

Improves Druid's handling of null values by treating them as missing values instead of being equivalent to empty strings or a zero-value. This makes Druid more SQL compatible and improves integration with external BI tools supporting ODBC/JDBC. See #4349 for proposal.

To enable this feature, you will need to set the system-wide property druid.generic.useDefaultValueForNull=false.

Added by @nishantmonu51 in #5278 and #5958.

Results-level broker caching

Implements result-level caching on brokers which can operate concurrently with the traditional segment-level cache. See #4843 for proposal.

Documentation for this feature: http://druid.io/docs/0.13.0-incubating/configuration/index.html#broker-caching

Added by @a2l007 in #5028.

Ingestion from RDBMS

Introduces a sql firehose which supports data ingestion directly from an RDBMS.

Added by @a2l007 in #5441.

Bloom filter support

Adds support for optimizing Druid queries by applying a Bloom filter generated by an external system such as Apache Hive. In the future, #6397 will support generation of Bloom filters as the result of Druid queries which can then be used to optimize future queries.

Added by @nishantmonu51 in #6222.

Additional SQL result formats

Adds result formats for line-based JSON and CSV and additionally X-Druid-Column-Names and X-Druid-Column-Types response headers containing a list of columns contained in the result.

Added by @gianm in #6191.

'stringLast' and 'stringFirst' aggregators

Introduces two complementary aggregators, stringLast and stringFirst which operate on string columns and return the value with the maximum and minimum timestamp respectively.

Added by @andresgomezfrr in #5789.

ArrayOfDoublesSketch

Adds support for numeric Tuple sketches, which extend the functionality of the count distinct Theta sketches by adding arrays of double values associated with unique keys.

Added by @AlexanderSaydakov in #5148.

HllSketch

Adds a configurable implementation of a count distinct aggregator based on HllSketch from https://github.com/DataSketches. Comparison to Druid's native HyperLogLogCollector shows improved accuracy, efficiency, and speed: https://datasketches.github.io/docs/HLL/HllSketchVsDruidHyperLogLogCollector.html

Added by @AlexanderSaydakov in #5712.

Support for multiple grouping specs in groupBy query

Adds support for the subtotalsSpec groupBy parameter which allows Druid to be efficient by reusing intermediate results at the broker level when running multiple queries that group by subsets of the same set of columns. See proposal in #5179 for more information.

Added by @himanshug in #5280.

Mutual TLS support

Adds support for mutual TLS (server certificate validation + client certificate validation). See: https://en.wikipedia.org/wiki/Mutual_authentication

Added by @jon-wei in #6076.

HTTP based worker management

Adds an HTTP-based indexing task management implementation to replace the previous one based on ZooKeeper. Part of a set of improvements to reduce and eventually eliminate Druid's dependency on ZooKeeper. See #4996 for proposal.

Added by @himanshug in #5104.

Broker backpressure

Allows the broker to exert backpressure on data-serving nodes to prevent the broker from crashing under memory pressure when results are coming in faster than they are being read by clients.

Added by @gianm in #6313.

'maxBytesInMemory' ingestion tuning configuration

Previously, a major tuning parameter for indexing task memory management was the maxRowsInMemory configuration, which determined the threshold for spilling the contents of memory to disk. This was difficult to properly configure since the 'size' of a row varied based on multiple factors. maxBytesInMemory makes this configuration byte-based instead of row-based.

Added by @surekhasaharan in #5583.

Materialized views

Supports the creation of materialized views which can improve query performance in certain situations at the cost of additional storage. See http://druid.io/docs/latest/development/extensions-contrib/materialized-view.html for more information.

Note: This is a community-contributed extension and is not automatically included in the Druid distribution. We welcome feedback for deciding when to promote this to a core extension. For more information, see Community Extensions.

Added by @zhangxinyu1 in #5556.

Parser for Influx Line Protocol

Adds support for ingesting the Influx Line Protocol data format. For more information, see: https://docs.influxdata.com/influxdb/v1.6/write_protocols/line_protocol_tutorial/

Note: This is a community-contributed extension and is not automatically included in the Druid distribution. We welcome feedback for deciding when to promote this to a core extension. For more information, see Community Extensions.

Added by @njhartwell in #5440.

OpenTSDB emitter

Adds support for emitting Druid metrics to OpenTSDB.

Note: This is a community-contributed extension and is not automatically included in the Druid distribution. We welcome feedback for deciding when to promote this to a core extension. For more information, see Community Extensions.

Added by @QiuMM in #5380.

Updating from 0.12.3 and earlier

Please see below for changes between 0.12.3 and 0.13.0 that you should be aware of before upgrading. If you're updating from an earlier version than 0.12.3, please see release notes of the relevant intermediate versions for additional notes.

MySQL metadata storage extension no longer includes JDBC driver

The MySQL metadata storage extension is now packaged together with the Druid distribution but without the required MySQL JDBC driver (due to licensing restrictions). To use this extension, the driver will need to be downloaded separately and added to the extension directory.

See http://druid.io/docs/latest/development/extensions-core/mysql.html for more details.

AWS region configuration required for S3 extension

As a result of switching from jets3t to the AWS SDK (#5382), users of the S3 extension are now required to explicitly set the target region. This can be done by setting the JVM system property aws.region or the environment variable AWS_REGION.

As an example, to set the region to 'us-east-1' through system properties:

  • add -Daws.region=us-east-1 to the jvm.config file for all Druid services
  • add -Daws.region=us-east-1 to druid.indexer.runner.javaOpts in middleManager/runtime.properties so that the property will be passed to peon (worker) processes

Ingestion spec changes

As a result of renaming packaging from io.druid to org.apache.druid, ingestion specs that reference classes by their fully-qualified class name will need to be modified accordingly.

As an example, if you are using the Parquet extension with Hadoop indexing, the inputFormat field of the inputSpec will need to change from io.druid.data.input.parquet.DruidParquetInputFormat to org.apache.druid.data.input.parquet.DruidParquetInputFormat.

Metrics changes

New metrics

  • task/action/log/time - Milliseconds taken to log a task action to the audit log (#5714)
  • task/action/run/time - Milliseconds taken to execute a task action (#5714)
  • query/node/backpressure - Nanoseconds the channel is unreadable due to backpressure being applied (#6335) (Note that this is not enabled by default and requires a custom implementation of QueryMetrics to emit)

New dimensions

  • taskId and taskType added to task-related metrics (#5664)

Other

  • HttpPostEmitterMonitor no longer emits maxTime and minTime if no times were recorded (#6418)

Rollback restrictions

64-bit doubles aggregators

64-bit doubles aggregators are now used by default (see #5478). Support for 64-bit floating point columns was release in Druid 0.11.0, so if this is enabled, versions older than 0.11.0 will not be able to read the data segments.

To disable and keep the old format, you will need to set the system-wide property druid.indexing.doubleStorage=float.

Disabling bitmap indexes

0.13.0 adds support for disabling bitmap indexes on a per-column basis, which can save space in cases where bitmap indexes add no value. This is done by setting the 'createBitmapIndex' field in the dimension schema. Segments written with this option will not be backwards compatible with older versions of Druid (#5402).

Behavior changes

Java package name changes

Druid's package names have all moved from io.druid to org.apache.druid. This affects the name of the Java main class that you should run when starting up services, which is now org.apache.druid.cli.Main. It may also affect installation and configuration of extensions and monitors.

ParseSpec is now a required field in ingestion specs

There is no longer a default ParseSpec (previously the DelimitedParseSpec). Ingestion specs now require parseSpec to be specified. If you previously did not provide a parseSpec, you should use one with "format": "tsv" to maintain the existing behavior (#6310).

Change to default maximum rows to return in one JDBC frame

The default value for druid.sql.avatica.maxRowsPerFrame was reduced from 100k to 5k to minimize out of memory errors (#5409).

Router behavior change when routing to brokers dedicated to different time ranges

As a result of #5595, routers may now select an undesired broker in configurations where there are different tiers of brokers that are intended to be dedicated to queries on different time ranges. See #1362 for discussion.

Ruby TimestampSpec no longer ignores milliseconds

Timestamps parsed using a TimestampSpec with format 'ruby' no longer truncates the millisecond component. If you were using this parser and wanted a query granularity of SECOND, ensure that it is configured appropriately in your indexing specs (#6217).

Small increase in size of ZooKeeper task announcements

The datasource name was added to TaskAnnouncement which will result in a small per task increase in the amount of data stored in ZooKeeper (#5511).

Addition of 'name' field to filtered aggregators

Aggregators of type 'filtered' now support a 'name' field. Previously, the filtered aggregator inherited the name of the aggregator it wrapped. If you have provided the 'name' field for both the filtered aggregator and the wrapped aggregator, it will prefer the name of the filtered aggregator. It will use the name of the wrapped aggregator if the name of the filtered aggregator is missing or empty (#6219).

utf8mb4 is now the recommended metadata storage charset

For upgrade instructions, use the ALTER DATABASE and ALTER TABLE instructions as described here: https://dev.mysql.com/doc/refman/5.7/en/charset-unicode-conversion.html.

For motivation and reference, see #5377 and #5411.

Removed configuration properties

  • druid.indexer.runner.tlsStartPort has been removed (#6194).
  • druid.indexer.runner.separateIngestionEndpoint has been removed (#6263).

Interface changes for extension developers

  • Packaging has been renamed from io.druid to org.apache.druid. All third-party extensions will need to rename their META-INF/io.druid.initialization.DruidModule to org.apache.druid.initialization.DruidModule and update their extension's packaging appropriately (#6266).

  • The DataSegmentPuller interface has been removed (#5461).

  • A number of functions under java-util have been removed (#5461).

  • The constructor of the Metadata class has changed (#5613).

  • The 'spark2' Maven profile has been removed (#5581).

API deprecations

Overlord

  • The /druid/indexer/v1/supervisor/{id}/shutdown endpoint has been deprecated in favor of /druid/indexer/v1/supervisor/{id}/terminate (#6272 and #6234).
  • The /druid/indexer/v1/task/{taskId}/segments endpoint has been deprecated (#6368).
  • The status field returned by /druid/indexer/v1/task/ID/status has been deprecated in favor of statusCode (#6334).
  • The reportParseExceptions and ignoreInvalidRows parameters for ingestion tuning configurations have been deprecated in favor of logParseExceptions and maxParseExceptions (#5418).

Broker

  • The /druid/v2/datasources/{dataSourceName}/dimensions endpoint has been deprecated. A segment metadata query or the INFORMATION_SCHEMA SQL table should be used instead (#6361).
  • The /druid/v2/datasources/{dataSourceName}/metrics endpoint has been deprecated. A segment metadata query or the INFORMATION_SCHEMA SQL table should be used instead (#6361).
