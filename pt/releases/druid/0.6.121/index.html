druida druida-0.6.121

Esta é uma versão pequena, principalmente com atualizações de estabilidade e desempenho.

Atualizando

  • Se estiver atualizando a partir do 0.6.105, nenhuma etapa específica será necessária.
  • Se estiver atualizando de uma versão mais antiga, consulte as notas para Druid 0.6.105

Release Notes

Novos recursos

  • novo agregador de estimativa de cardinalidade: usa hyperUnique (o agregador HyperLogLog otimizado) para estimar a cardinalidade de uma dimensão
  • refizemos completamente os esquemas de ingestão para consolidar a ingestão em lote e em tempo real. Por enquanto, tudo é compatível com versões anteriores e esperamos ter novos exemplos e tutoriais que mostrem como usar o novo esquema. Esperamos que isso simplifique a ingestão.
  • topNs classificados alfanuméricos
  • uma nova consulta de união (no momento, isso só funciona se houver colunas e métricas comumente nomeadas entre suas fontes de dados)
  • permitir a substituição baseada em configuração das propriedades do trabalho do Hadoop para ingestão em lote
  • algoritmo de balanceamento de custos do coordenador multithread para decisões de balanceamento de carga mais rápidas (o número de threads a serem usados é configurável dinamicamente, é 1 por padrão)
  • adicionado um parâmetro de contexto para forçar um algoritmo de otimização topN de 2 passagens (anteriormente isso era feito de uma heurística que raramente era usada)
  • endpoints de coordenador adicionais para retornar mais informações sobre o estado do cluster

Melhorias

  • melhor uso da memória de ingestão em tempo real. Dependendo do número total de segmentos no seu cluster, muito menos memória pode agora ser usada para ingestão em tempo real.
  • ingestão em lote mais rápida quando há vários arquivos de dados brutos individuais. Obrigado @deepujain.
  • mangueiras de incêndio RabbitMQ mais resistentes. Obrigado @tucksaun.
  • O agregador JavaScript agora suporta dimensões com vários valores.
  • topN invertido agora funciona com classificação lexicográfica
  • topN lexicográfico agora suporta funções de extração de dimensão

Correções de bugs

  • diversas correções para o agregador hyperUnique, onde grandes erros nas estimativas poderiam ser relatados em certos casos extremos
  • corrigida uma condição de corrida extrema no coordenador, onde poderia carregar/descartar segmentos incorretamente ao desconectar/reconectar do Zookeeper
  • corrigida uma condição de limite com ingestão em tempo real, onde um coletor defeituoso pode ser criado com eventos atrasados
  • jetty atualizado para 9.1.5 para corrigir um problema de conexão semiaberta que ocorre ocasionalmente (tem sido extremamente difícil para nós reproduzir isso - mas quando isso ocorre, os nós parecem ter seus threads do jetty paralisados enquanto gravam em um canal que já está fechado)
  • corrigido um bug onde os resultados armazenados em cache eram combinados em ordem arbitrária
  • corrigidos bugs adicionais de revestimento
  • Druid agora passa nos testes com Java 8

Documentação

  • nova documentação sobre possíveis hardwares para nós de produção e configuração deles. Procure mais melhorias na configuração em breve.
  • Corrigidos vários links quebrados em documentos. Obrigado @jcollum.

druid druid-0.6.121

This is a small release with mainly stability and performance updates.

Updating

  • If updating from 0.6.105, no particular steps need to be taken.
  • If updating from an older release, see the notes for Druid 0.6.105

Release Notes

New features

  • new cardinality estimation aggregator: uses hyperUnique (the optimized HyperLogLog aggregator) to estimate the cardinality of a dimension
  • we have completely redone the ingestion schemas to consolidate batch and real-time ingestion. Everything is backwards compatible for the time being, and we hope to have new examples and tutorials that show how to use the new schema. It should hopefully simplify ingestion.
  • alphanumeric sorted topNs
  • a new union query (right now this only works if there are commonly named columns and metrics among your datasources)
  • allow config-based overriding of Hadoop job properties for batch ingestion
  • multi-threaded the coordinator cost balancing algorithm for faster load balancing decisions (the number of threads to use is dynamically configurable, it is 1 by default)
  • added a context parameter to force a 2-pass topN optimization algorithm (previously this was done a heuristic that was rarely used)
  • additional coordinator endpoints to return more info about cluster state

Improvements

  • improved real-time ingestion memory usage. Depending on the number of total segments in your cluster, much less memory can now be used for real-time ingestion.
  • faster batch ingestion when there are numerous individual raw data files. Thanks @deepujain.
  • more resilient rabbitMQ firehoses. Thanks @tucksaun.
  • JavaScript aggregator now supports multi-valued dimensions.
  • inverted topN now works with lexicographic sorting
  • lexicographic topN now supports dimension extraction functions

Bug Fixes

  • several fixes for hyperUnique aggregator where large errors in estimates could be reported in certain edge cases
  • fixed an edge case race condition in the coordinator where it could load/drop segments incorrectly when disconnecting/reconnecting from Zookeeper
  • fixed an edge condition with real-time ingestion where a bad sink can be created with delayed events
  • updated jetty to 9.1.5 for a fix of a half-open connection problem that occurs occasionally (it’s been extremely difficult for us to reproduce this -- but when it occurs nodes appear to have their jetty threads stalled while writing to a channel that is already closed)
  • fixed a bug where cached results would get combined in arbitrary order
  • fixed additional casing bugs
  • Druid now passes tests with Java 8

Documentation

  • new documentation about possible hardware for production nodes and configuration for them. Look for more improvements to configuration coming soon.
  • Fixed several broken links in docs. Thanks @jcollum.
