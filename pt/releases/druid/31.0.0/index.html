<a name="31.0.0-important-features-changes-and-deprecations-projections-experimental" href="#31.0.0-important-features-changes-and-deprecations-projections-experimental">#</a> Projeções (experimentais)

Druid 31.0.0 inclui suporte experimental para um novo recurso chamado projeções. As projeções são pré-agregados agrupados de um segmento que são usados ​​automaticamente no momento da consulta para otimizar a execução de quaisquer consultas que se 'ajustem' ao formato da projeção, reduzindo o custo de cálculo e de E/S, reduzindo o número de linhas que precisam ser processadas. As projeções estão contidas em segmentos de uma fonte de dados e aumentam o tamanho do segmento. Mas eles podem compartilhar dados, como dicionários de valores de colunas codificadas por dicionário, com as colunas do segmento base.

Atualmente, as projeções suportam apenas a ingestão baseada em JSON, mas podem ser usadas por consultas que usam o mecanismo de tarefas MSQ ou o novo mecanismo Dart. O desenvolvimento futuro permitirá a criação de projeções como parte da ingestão baseada em SQL.

Temos muitos planos para continuar a melhorar esse recurso nas próximas versões, mas estamos entusiasmados em disponibilizá-lo para que os usuários possam começar a experimentar, já que as projeções podem melhorar drasticamente o desempenho da consulta.

Para obter mais informações, consulte Projeções.

<a name="31.0.0-functional-areas-and-related-changes-querying-dart" href="#31.0.0-functional-areas-and-related-changes-querying-dart">#</a> Dardo

Dart é um mecanismo de consulta com trabalhadores multithread que realiza embaralhamentos na memória para fornecer simultaneidade ajustável e custos de infraestrutura para consultas de baixa latência e alta complexidade.

Para experimentar o Dart, defina druid.msq.dart.enabled como true em suas propriedades de tempo de execução comuns. Em seguida, você pode selecionar Dart como mecanismo de consulta no console da web ou por meio do API /druid/v2/sql/dart, que aceita a mesma carga útil JSON que /druid/v2/sql. O Dart é totalmente compatível com as formas de consulta Druid atuais e o formato de armazenamento do Druid. Isso significa que você pode experimentar o Dart com suas consultas e fontes de dados existentes.

<a name="31.0.0-functional-areas-and-related-changes-querying-projections" href="#31.0.0-functional-areas-and-related-changes-querying-projections">#</a> Projeções

Como recurso experimental, as projeções ainda não estão bem documentadas, mas podem ser definidas para ingestão de streaming e ingestão de lote 'clássica' como parte do dataSchema. Para obter um exemplo de especificação de ingestão, consulte a descrição da solicitação pull para #17214.

O campo groupingColumns na especificação define a ordem em que os dados são classificados na projeção. Em vez de definir explicitamente a granularidade como na tabela base, você a define com uma coluna virtual. Durante a ingestão, a lógica de processamento encontra a coluna virtual de granularidade “melhor” que é uma expressão timestamp_floor e a utiliza como a coluna __time para a projeção. As projeções não precisam ter uma coluna de tempo definida. Nesses casos, eles ainda podem corresponder a consultas que não estão sendo agrupadas no prazo.

Existem novos sinalizadores de contexto de consulta que foram adicionados para auxiliar na experimentação com projeções:

  • useProjection aceita um nome de projeção específico e instrui o mecanismo de consulta que deve usar essa projeção e falhará na consulta se a projeção não corresponder à consulta
  • forceProjections aceita verdadeiro ou falso e instrui o mecanismo de consulta que deve usar uma projeção e falhará na consulta se não conseguir encontrar uma projeção correspondente
  • noProjections aceita verdadeiro ou falso e instrui os mecanismos de consulta a não usarem projeções

<a name="31.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes" href="#31.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes">#</a> Notas de atualização

<a name="31.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-array-ingest-mode-now-defaults-to-array" href="#31.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-array-ingest-mode-now-defaults-to-array">#</a> O modo de ingestão de array agora é padronizado como array

O sinalizador de contexto de ingestão baseado em SQL arrayIngestMode agora tem como padrão array em vez de mvd. Isso significa que os tipos SQL VARCHAR ARRAY não são mais traduzidos e armazenados implicitamente em colunas VARCHAR, mas são armazenados como VARCHAR ARRAY. Essa alteração permite que outros tipos de matriz, como BIGINT ARRAY e DOUBLE ARRAY, sejam inseridos com MSQ em seus respectivos tipos de coluna de matriz, em vez de falharem como acontece no modo mvd.

Para continuar a armazenar sequências de vários valores, modifique quaisquer consultas de inserção/substituição para agrupar os tipos de matriz com o operador ARRAY_TO_MV.

A validação existe para evitar a mistura de colunas VARCHAR e VARCHAR ARRAY na mesma tabela, portanto, qualquer ingestão afetada por essa alteração falhará e fornecerá uma mensagem de erro descritiva em vez de exibir um comportamento inesperado.

A opção arrayIngestMode de none foi removida. Foi introduzido antes da lógica de validação de tabela como um meio para os operadores de cluster forçarem os escritores de consulta a definir explicitamente array ou mvd em seus contextos de consulta, mas fornece pouca utilidade no Druid 31.

Consulte os seguintes tópicos para obter mais informações:

  • Ingerir dimensões de vários valores sobre como ingerir strings de vários valores.

<a name="31.0.0-important-features-changes-and-deprecations-projections-experimental" href="#31.0.0-important-features-changes-and-deprecations-projections-experimental">#</a> Projections (experimental)

Druid 31.0.0 includes experimental support for new feature called projections. Projections are grouped pre-aggregates of a segment that are automatically used at query time to optimize execution for any queries which 'fit' the shape of the projection by reducing both computation and i/o cost by reducing the number of rows which need to be processed. Projections are contained within segments of a datasource and do increase the segment size. But they can share data, such as value dictionaries of dictionary encoded columns, with the columns of the base segment.

Projections currently only support JSON-based ingestion, but they can be used by queries that use the MSQ task engine or the new Dart engine. Future development will allow projections to be created as part of SQL-based ingestion.

We have a lot of plans to continue to improve this feature in the coming releases, but are excited to get it out there so users can begin experimentation since projections can dramatically improve query performance.

For more information, see Projections.

Dart is a query engine with multi-threaded workers that conducts in-memory shuffles to provide tunable concurrency and infrastructure costs for low-latency high complexity queries.

To try out Dart, set druid.msq.dart.enabled to true in your common runtime properties. As an experimental feature, projections are not well documented yet, but can be defined for streaming ingestion and 'classic' batch ingestion as part of the dataSchema. For an example ingestion spec, see the the pull request description for #17214.

The groupingColumns field in the spec defines the order which data is sorted in the projection. Instead of explicitly defining granularity like for the base table, you define it with a virtual column. During ingestion, the processing logic finds the ‘finest’ granularity virtual column that is a timestamp_floor expression and uses it as the __time column for the projection. Projections do not need to have a time column defined. In these cases, they can still match queries that are not grouping on time.

There are new query context flags that have been added to aid in experimentation with projections:

  • useProjection accepts a specific projection name and instructs the query engine that it must use that projection, and will fail the query if the projection does not match the query
  • forceProjections accepts true or false and instructs the query engine that it must use a projection, and will fail the query if it cannot find a matching projection
  • noProjections accpets true or false and instructs the query engines to not use any projections

<a name="31.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-array-ingest-mode-now-defaults-to-array" href="#31.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-array-ingest-mode-now-defaults-to-array">#</a> Array ingest mode now defaults to array

The SQL-based ingestion context flag arrayIngestMode now defaults to array instead of mvd. This means that SQL VARCHAR ARRAY types is no longer implicitly translated and stored in VARCHAR columns, but is instead stored as VARCHAR ARRAY. This change permits other array types such as BIGINT ARRAY and DOUBLE ARRAY to be inserted with MSQ into their respective array column types instead of failing as they do in mvd mode.

To continue to store multi-value strings, modify any insert/replace queries to wrap the array types with the ARRAY_TO_MV operator.

Validation is in place to prevent mixing VARCHAR and VARCHAR ARRAY columns in the same table, so any ingestions affected by this change will fail and provide a descriptive error message instead of exhibiting unexpected behavior.

The arrayIngestMode option of none has been removed. It was introduced prior to the table validation logic as a means for cluster operators to force query writers to explicitly set array or mvd on their query contexts but provides little utility in Druid 31.

See the following topics for more information:

  • Ingest multi-value dimensions for how to ingest multi-value strings.
  • Ingest arrays for ingesting arrays.
