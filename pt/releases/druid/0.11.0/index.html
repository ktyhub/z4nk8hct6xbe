druida druida-0.11.0

Druid 0.11.0 contém mais de cem melhorias de desempenho, melhorias de estabilidade e correções de bugs de quase 40 colaboradores. Esta versão adiciona dois recursos principais de segurança, suporte TLS e pontos de extensão para autenticação e autorização. Os principais novos recursos incluem:

  • Suporte TLS (também conhecido como SSL)
  • Pontos de extensão para autenticação e autorização
  • Suporte de colunas duplas
  • Estratégia de balanceamento de cacheCost
  • suporte à expressão jq no analisador JSON
  • Extensão de cache Redis
  • Melhorias de desempenho do GroupBy
  • Várias melhorias no Druid SQL A lista completa de alterações está aqui: https://github.com/druid-io/druid/pulls?utf8=%E2%9C%93&q=is%3Apr%20is%3Aclosed%20milestone%3A0.11.0 A documentação para esta versão está em: http://druid.io/docs/0.11.0/

Destaques

Suporte TLS

Druid agora suporta TLS, permitindo comunicações criptografadas client e entre nós. Consulte http://druid.io/docs/0.11.0/operations/tls-support.html para obter detalhes sobre configuração e extensões relacionadas. Adicionado por @pjain1 em https://github.com/druid-io/druid/pull/4270.

Pontos de extensão de autenticação/autorização

Pontos de extensão para autenticação e autorização de solicitações foram adicionados ao Druid. Consulte http://druid.io/docs/0.11.0/configuration/auth.html para obter informações sobre configuração e implementação de extensão. A extensão de autenticação Kerberos existente foi atualizada para implementar a nova interface do Authenticator. Consulte a seção "Alterações na configuração Kerberos" em "Atualização de 0.10.1 e versões anteriores" para obter mais informações se você estiver usando a extensão Kerberos. Adicionado por @ jon-wei em https://github.com/druid-io/druid/pull/4271

Suporte para colunas duplas

Druid agora oferece suporte a colunas agregadoras de tipo duplo. Consulte http://druid.io/docs/0.11.0/querying/aggregations.html para obter documentação sobre os novos agregadores Double. Adicionado por @b-slim em https://github.com/druid-io/druid/pull/4491.

estratégia de balanceamento de cacheCost

Os usuários que atualizam para 0.11.0 são incentivados a experimentar a nova estratégia de balanceamento de segmento cachingCost em seus coordenadores. Esta estratégia oferece grandes melhorias de desempenho em relação à estratégia de balanceamento de custos existente e está planejada para se tornar a estratégia padrão na versão seguinte ao 0.11.0. Esta estratégia pode ser selecionada definindo a seguinte propriedade nos coordenadores:

druid.coordinator.balancer.strategy=cachingCost

Adicionado por @dgolitsyn em https://github.com/druid-io/druid/pull/4731

suporte à expressão jq no analisador JSON

O analisador de entrada JSON do Druid agora suporta expressões jq usando jackson-jq, permitindo mais transformações de entrada antes da ingestão. Consulte http://druid.io/docs/0.11.0/ingestion/flatten-json.html para obter mais detalhes. Adicionado por @knoguchi em https://github.com/druid-io/druid/pull/4171.

Extensão de cache Redis

Uma nova implementação de cache usando Redis foi adicionada em uma extensão, adicionada por @QiuMM em https://github.com/druid-io/druid/pull/4615.. Consulte a solicitação pull anterior para obter mais detalhes.

Melhorias de desempenho do GroupBy

Várias novas otimizações de desempenho foram adicionadas à consulta GroupBy por @jihoonson nos seguintes PRs: https://github.com/druid-io/druid/pull/4660 Classificação paralela para ConcurrentGrouper https://github.com/druid-io/druid/pull/4576 Agregação baseada em array para consulta groupBy https://github.com/druid-io/druid/pull/4668 Adicione IntGrouper para evitar boxing/unboxing desnecessário na agregação baseada em array PR #4660 oferece uma melhoria geral ao paralelizar a classificação de resultados parciais, enquanto PR #4576 e #4668 oferecem melhorias significativas ao agrupar em uma única coluna String.

Melhorias SQL

Várias melhorias e recursos foram adicionados ao Druid SQL, por @gianm nos seguintes PRs: https://github.com/druid-io/druid/pull/4750 - Suporte TRIM https://github.com/druid-io/druid/pull/4720 - Arredondamento para contagem distinta https://github.com/druid-io/druid/pull/4561 - Métricas para consultas SQL https://github.com/druid-io/druid/pull/4360 - suporte a expressões SQL

E muito mais!

A lista completa de alterações está aqui: https://github.com/druid-io/druid/pulls?utf8=%E2%9C%93&q=is%3Apr%20is%3Aclosed%20milestone%3A0.11.0

Atualizando do 0.10.1 e versões anteriores

Veja abaixo as alterações entre 0.10.1 e 0.11.0 que você deve conhecer antes de atualizar. Se você estiver atualizando de uma versão anterior ao 0.10.1, consulte release notes das versões intermediárias relevantes para notas adicionais.

Atualizando coordenadores e senhores supremos

O patch a seguir altera a maneira como os redirecionamentos coordenador-> overlord são tratados: https://github.com/druid-io/druid/pull/5037 O algoritmo de eleição do líder supremo mudou em 0.11.0: https://github.com/druid-io/druid/pull/4699. Como resultado dos dois patches acima, é necessário cuidado especial ao atualizar o Coordinator ou Overlord para 0.11.0. Todos os coordenadores e overlords devem ser desligados e atualizados juntos. Por exemplo, para atualizar os coordenadores, você desligaria todos os coordenadores, atualizaria-os para 0.11.0 e depois os iniciaria. Overlords devem ser atualizados de maneira semelhante. Durante o processo de atualização, não deve haver nenhum período de tempo em que um coordenador ou overlord não 0.11.0 esteja executando simultaneamente com um coordenador ou overlord 0.11.0. Observe que pelo menos um overlord deve ser acionado o mais rápido possível após desligá-los, para que os peões, a tranquilidade, etc., continuem a trabalhar após algumas tentativas. Observe também que a propriedade druid.zk.paths.indexer.leaderLatchPath não é mais usada agora.

Mudanças no nome do serviço

Nas versões anteriores do Druid, os caracteres / em nomes de serviços definidos por druid.service seriam substituídos por caracteres : porque esses nomes de serviços eram usados em caminhos Zookeeper. O Druida 0.11.0 não realiza mais essas substituições de caracteres. Exemplo:1 - se a configuração antiga possuía um broker com nome de serviço test/broker: druid.service=test/broker e um roteador foi configurado assumindo que / será substituído por : no nome do serviço do corretor, druid.router.tierToBrokerMap={"hot":"test:broker","_default_tier":"test:broker"} a configuração do roteador deve ser atualizada para remover essa suposição: druid.router.tierToBrokerMap={"hot":"test/broker","_default_tier":"test/broker"} Exemplo:2 - Se a configuração antiga tinha overlord com nome de serviço test/overlord então o valor de druid.coordinator.asOverlord.overlordService ou druid.selectors.indexing.serviceName deveria ser test/overlord e não test:overlord Exemplo:3 - Se a configuração antiga tinha overlord com nome de serviço test:overlord então o valor de druid.coordinator.asOverlord.overlordService ou druid.selectors.indexing.serviceName deveria ser test:overlord e não test/overlord As seguintes configurações relacionadas ao nome do serviço também são afetadas e devem ser atualizadas para corresponder exatamente ao valor da propriedade druid.service em outro nó que está sendo descoberto. druid.coordinator.asOverlord.overlordService druid.selectors.coordinator.serviceName druid.selectors.indexing.serviceName druid.router.defaultBrokerServiceName druid.router.coordinatorServiceName druid.router.tierToBrokerMap Consulte https://github.com/druid-io/druid/issues/4992 para obter mais detalhes.

Mudanças na configuração do Kerberos

O formato de configuração da autenticação Kerberos mudou como resultado das novas interfaces introduzidas pelo #4271. Consulte http://druid.io/docs/0.11.0/development/extensions-core/druid-kerberos.html para as novas propriedades de configuração. Os usuários podem apontar o authorizerName do autenticador Kerberos para uma instância de um autorizador "allowAll" para replicar o comportamento pré-0.11.0 de um cluster usando a autenticação Kerberos sem autorização.

Pesquisas Mudanças no caminho do API

Os caminhos para a configuração de pesquisas API foram alterados devido ao #5058. Os caminhos de configuração que tinham o formato /druid/coordinator/v1/lookups agora têm o formato /druid/coordinator/v1/lookups/config. Consulte http://druid.io/docs/0.11.0/querying/lookups.html para o API atual.

Migrando para colunas duplas

Antes do 0.11.0, os agregadores Double* armazenavam valores de coluna no disco como Float enquanto executavam agregações usando representações Double. PR #4491 permite que os agregadores Double armazenem valores de coluna no disco como Doubles. Devido a preocupações relacionadas a atualizações contínuas e downgrades de versão, esse comportamento é desabilitado por padrão e o Druid continuará a armazenar agregadores duplos no disco como carros flutuantes. Para ativar o armazenamento de coluna dupla, configure a seguinte propriedade nas propriedades de tempo de execução comuns:

druid.indexing.doubleStorage=double

Os usuários não devem definir esta propriedade durante uma atualização contínua inicial para 0.11.0, pois quaisquer nós executando pré-0.11.0 Druid não serão capazes de lidar com colunas duplas criadas durante o período de atualização. Os usuários também precisarão reindexar quaisquer segmentos com colunas duplas se fizerem downgrade de 0.11.0 para uma versão mais antiga. Consulte #4944 e #4605 para obter mais informações.

Verificar alterações na consulta

A consulta Scan foi movida de extensions-contrib para core Druid. Como parte desta migração: https://github.com/druid-io/druid/pull/4751, o tratamento da coluna de tempo pela consulta de varredura foi alterado. A coluna de tempo agora é retornada como "__time" em vez de "timestamp", ela não será mais incluída se você não a solicitar especificamente em suas "colunas" e será retornada como um comprimento em vez de uma string. Os usuários podem reverter o tratamento de tempo da consulta Scan para o comportamento da extensão herdada configurando "legacy" : true em suas consultas ou configurando a propriedade druid.query.scan.legacy = true. O objetivo disso é fornecer um caminho de migração para usuários que anteriormente usavam a extensão contrib.

Alterações na interface de extensão

Suporte a coluna dupla do agregador

A interface Aggregator ganhou um método getDouble(), cujo padrão é converter o resultado de getFloat(). O método getDouble() deve ser reimplementado para quaisquer agregadores customizados que possam suportar duplas. Consulte https://github.com/druid-io/druid/pull/4595 para obter mais detalhes.

Mudança na interface do QueryRunner

A interface do QueryRunner mudou e o antigo método run() foi removido, substituído por um novo método que aceita um objeto QueryPlus. Extensões de consulta personalizadas precisarão implementar a nova interface. Consulte https://github.com/druid-io/druid/pull/4184 e https://github.com/druid-io/druid/pull/4482 para obter mais detalhes.

Mudança na interface do filtro

O método Filter.getBitmapResult() não possui mais uma implementação padrão: https://github.com/druid-io/druid/pull/4481 Extensões de filtro personalizadas precisarão fornecer uma implementação para getBitmapResult() agora.

Outras notas

jvm/gc/métrica de tempo

A métrica jvm/gc/time não é mais emitida, sendo substituída por uma nova métrica denominada jvm/gc/cpu pelos motivos aqui descritos: https://github.com/druid-io/druid/pull/4480

Estratégia de seleção de trabalhador padrão

Observe que a estratégia padrão de seleção de trabalhador mudou de fillCapacity para equalDistribution. Esta mudança foi introduzida no 0.10.1, a versão anterior, mas não foi mencionada nos 0.10.1 release notes, por isso é mencionada novamente aqui.

Criação de segmento V8 removida

O Druid agora sempre criará segmentos V9, a criação de segmentos V8 não é mais suportada e a propriedade buildV9Directly para tarefas de ingestão foi removida. Consulte https://github.com/druid-io/druid/pull/4420 para obter mais detalhes.

LogLevelAdjuster removido

Observe que o LogLevelAjuster foi removido: https://github.com/druid-io/druid/pull/4236 Qualquer usuário que use mbeans para configurar níveis de log deve configurar o log4j2 usando jmx.

druid druid-0.11.0

Druid 0.11.0 contains over a hundred performance improvements, stability improvements, and bug fixes from almost 40 contributors. This release adds two major security features, TLS support and extension points for authentication and authorization.

Major new features include:

  • TLS (a.k.a. SSL) support
  • Extension points for authentication and authorization
  • Double columns support
  • cachingCost Balancer Strategy
  • jq expression support in JSON parser
  • Redis cache extension
  • GroupBy performance improvements
  • Various improvements to Druid SQL

The full list of changes is here: https://github.com/druid-io/druid/pulls?utf8=%E2%9C%93&q=is%3Apr%20is%3Aclosed%20milestone%3A0.11.0

Documentation for this release is at: http://druid.io/docs/0.11.0/

Highlights

TLS support

Druid now supports TLS, enabling encrypted client and inter-node communications. Please see http://druid.io/docs/0.11.0/operations/tls-support.html for details on configuration and related extensions.

Added by @pjain1 in https://github.com/druid-io/druid/pull/4270.

Authentication/authorization extension points

Extension points for authenticating and authorizing requests have been added to Druid. Please see http://druid.io/docs/0.11.0/configuration/auth.html for information on configuration and extension implementation.

The existing Kerberos authentication extension has been updated to implement the new Authenticator interface, please see the "Kerberos configuration changes" section under "Updating from 0.10.1 and earlier" for more information if you are using the Kerberos extension.

Added by @jon-wei in https://github.com/druid-io/druid/pull/4271

Double columns support

Druid now supports Double type aggregator columns. Please see http://druid.io/docs/0.11.0/querying/aggregations.html for documentation on the new Double aggregators.

Added by @b-slim in https://github.com/druid-io/druid/pull/4491.

cachingCost Balancer Strategy

Users upgrading to 0.11.0 are encouraged to try the new cachingCost segment balancing strategy on their coordinators. This strategy offers large performance improvements over the existing cost balancer strategy, and it is planned to become the default strategy in the release following 0.11.0.

This strategy can be selected by setting the following property on coordinators:

druid.coordinator.balancer.strategy=cachingCost

Added by @dgolitsyn in https://github.com/druid-io/druid/pull/4731

jq expression support in JSON parser

Druid's JSON input parser now supports jq expressions using jackson-jq, enabling more input transforms before ingestion. Please see http://druid.io/docs/0.11.0/ingestion/flatten-json.html for more details.

Added by @knoguchi in https://github.com/druid-io/druid/pull/4171.

Redis cache extension

A new cache implementation using Redis has been added in an extension, added by @QiuMM in https://github.com/druid-io/druid/pull/4615. Please refer to the preceding pull request for more details.

GroupBy performance improvements

Several new performance optimizations have been added to the GroupBy query by @jihoonson in the following PRs:

https://github.com/druid-io/druid/pull/4660 Parallel sort for ConcurrentGrouper https://github.com/druid-io/druid/pull/4576 Array-based aggregation for groupBy query https://github.com/druid-io/druid/pull/4668 Add IntGrouper to avoid unnecessary boxing/unboxing in array-based aggregation

PR #4660 offers a general improvement by parallelizing partial result sorting, while PR #4576 and #4668 offer significant improvements when grouping on a single String column.

SQL improvements

Various improvements and features have been added to Druid SQL, by @gianm in the following PRs:

https://github.com/druid-io/druid/pull/4750 - TRIM support https://github.com/druid-io/druid/pull/4720 - Rounding for count distinct https://github.com/druid-io/druid/pull/4561 - Metrics for SQL queries https://github.com/druid-io/druid/pull/4360 - SQL expressions support

And much more!

The full list of changes is here: https://github.com/druid-io/druid/pulls?utf8=%E2%9C%93&q=is%3Apr%20is%3Aclosed%20milestone%3A0.11.0

Updating from 0.10.1 and earlier

Please see below for changes between 0.10.1 and 0.11.0 that you should be aware of before upgrading. If you're updating from an earlier version than 0.10.1, please see release notes of the relevant intermediate versions for additional notes.

Upgrading coordinators and overlords

The following patch changes the way coordinator->overlord redirects are handled: https://github.com/druid-io/druid/pull/5037

The overlord leader election algorithm has changed in 0.11.0: https://github.com/druid-io/druid/pull/4699.

As a result of the two patches above, special care is needed when upgrading Coordinator or Overlord to 0.11.0. All coordinators and overlords must be shut down and upgraded together.

For example, to upgrade Coordinators, you would shutdown all coordinators, upgrade them to 0.11.0 and then start them. Overlords should be upgraded in a similar way.

During the upgrade process, there must not be any time period where a non-0.11.0 coordinator or overlord is running simultaneously with an 0.11.0 coordinator or overlord.

Note that at least one overlord should be brought up as quickly as possible after shutting them all down so that peons, tranquility etc continue to work after some retries.

Also note that the druid.zk.paths.indexer.leaderLatchPath property is no longer used now.

Service name changes

In earlier versions of Druid, / characters in service names defined by druid.service would be replaced by : characters because these service names were used in Zookeeper paths. Druid 0.11.0 no longer performs these character replacements.

Example:1 - if the old configuration had a broker with service name test/broker: druid.service=test/broker

and a Router was configured assuming that / will be replaced with : in the broker service name, druid.router.tierToBrokerMap={"hot":"test:broker","_default_tier":"test:broker"}

the Router configuration should be updated to remove that assumption: druid.router.tierToBrokerMap={"hot":"test/broker","_default_tier":"test/broker"}

Example:2 - If the old configuration had overlord with service Name test/overlord then value of druid.coordinator.asOverlord.overlordService or druid.selectors.indexing.serviceName should be test/overlord and not test:overlord

Example:3 - If the old configuration had overlord with service Name test:overlord then value of druid.coordinator.asOverlord.overlordService or druid.selectors.indexing.serviceName should be test:overlord and not test/overlord

Following service name-related configurations are also affected and should be updated to exactly match the value of druid.service property on other node being discovered.

druid.coordinator.asOverlord.overlordService druid.selectors.coordinator.serviceName druid.selectors.indexing.serviceName druid.router.defaultBrokerServiceName druid.router.coordinatorServiceName druid.router.tierToBrokerMap

Please see https://github.com/druid-io/druid/issues/4992 for more details.

Kerberos configuration changes

The Kerberos authentication configuration format has changed as a result of the new interfaces introduced by #4271. Please refer to http://druid.io/docs/0.11.0/development/extensions-core/druid-kerberos.html for the new configuration properties.

Users can point the Kerberos authenticator's authorizerName to an instance of an "allowAll" authorizer to replicate the pre-0.11.0 behavior of a cluster using Kerberos authentication with no authorization.

Lookups API path changes

The paths for the lookups configuration API have changed due to #5058.

Configuration paths that had the form /druid/coordinator/v1/lookups now have the form /druid/coordinator/v1/lookups/config.

Please see http://druid.io/docs/0.11.0/querying/lookups.html for the current API.

Migrating to Double columns

Prior to 0.11.0, the Double* aggregators would store column values on disk as Float while performing aggregations using Double representations.

PR #4491 allows the Double aggregators to store column values on disk as Doubles. Due to concerns related to rolling updates and version downgrades, this behavior is disabled by default and Druid will continue to store Double aggregators on disk as floats.

To enable Double column storage, set the following property in the common runtime properties:

druid.indexing.doubleStorage=double

Users should not set this property during an initial rolling upgrade to 0.11.0, as any nodes running pre-0.11.0 Druid will not be able to handle Double columns created during the upgrade period. Users will also need to reindex any segments with Double columns if downgrading from 0.11.0 to an older version. Please see #4944 and #4605 for more information.

Scan query changes

The Scan query has been moved from extensions-contrib to core Druid. As part of this migration: https://github.com/druid-io/druid/pull/4751, the scan query's handling of the time column has changed.

The time column is now is returned as "__time" rather than "timestamp", it is no longer included if you do not specifically ask for it in your "columns", and it is returned as a long rather than a string.

Users can revert the Scan query's time handling to the legacy extension behavior by setting "legacy" : true in their queries, or setting the property druid.query.scan.legacy = true. This is meant to provide a migration path for users that were formerly using the contrib extension.

Extension Interface Changes

Aggregator double column support

The Aggregator interface has gained a getDouble() method, which defaults to casting the result of getFloat(). The getDouble() method should be re-implemented for any custom aggregators that can support doubles.

See https://github.com/druid-io/druid/pull/4595 for more details.

QueryRunner interface change

The QueryRunner interface has changed and the old run() method has been removed, replaced by a new method that accepts a QueryPlus object.

Custom query extensions will need to implement the new interface.

Please see https://github.com/druid-io/druid/pull/4184 and https://github.com/druid-io/druid/pull/4482 for more details.

Filter interface change

The Filter.getBitmapResult() method no longer has a default implementation: https://github.com/druid-io/druid/pull/4481

Custom filter extensions will need to provide an implementation for getBitmapResult() now.

Other Notes

jvm/gc/time metric

The jvm/gc/time metric is no longer emitted, replaced by a new metric named jvm/gc/cpu for the reasons described here: https://github.com/druid-io/druid/pull/4480

Default worker select strategy

Please note that the default worker select strategy has changed from fillCapacity to equalDistribution. This change was introduced in 0.10.1, the previous release, but was not mentioned in the 0.10.1 release notes, so it is called out again here.

V8 segment creation removed

Druid will now always build V9 segments, creating V8 segments is no longer supported and the buildV9Directly property for ingestion tasks has been removed.

Please see https://github.com/druid-io/druid/pull/4420 for more details.

LogLevelAdjuster removed

Please note that the LogLevelAdjuster has been removed: https://github.com/druid-io/druid/pull/4236

Any user using mbeans to configure log levels should configure log4j2 using jmx instead.
