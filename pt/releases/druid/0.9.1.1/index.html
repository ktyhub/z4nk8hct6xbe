druida druida-0.9.1.1

Druid 0.9.1.1 contém apenas uma alteração desde Druid 0.9.1, #3204, que corrige um bug no console da web do Coordinator. A lista completa de mudanças para a linha Druid 0.9.1 está aqui: https://github.com/druid-io/druid/issues?q=milestone%3A0.9.1+is%3Aclosed

Atualizando de 0.9.0

Pesquisas de tempo de consulta

A funcionalidade de consulta de tempo de consulta (QTL) foi substancialmente reformulada nesta versão. A maioria dos usuários precisará atualizar suas configurações e consultas. A extensão druid-namespace-lookup agora está obsoleta e será removida em uma versão futura do Druid. Os usuários devem migrar para a nova extensão druid-lookups-cached-global. Ambas as extensões podem ser carregadas simultaneamente para simplificar a migração. Para obter detalhes sobre a migração, consulte Transição para lookups-cached-global na documentação.

Outras notas

Além das alterações de QTL, observe as seguintes alterações:

  • O valor padrão para maxRowsInMemory foi definido como 75.000 para todas as formas de ingestão. Isso está de acordo com os padrões anteriores para tarefas do Hadoop e ingestão baseada no Tranquility. Se você estivesse criando tarefas de índice em tempo real diretamente (sem Tranquility), isso seria menor que o padrão anterior de 500.000.
  • O endpoint REST /druid/coordinator/v1/datasources/{dataSourceName}?kill=true&interval={myISO8601Interval} agora está obsoleto. O novo endpoint REST /druid/coordinator/v1/datasources/{dataSourceName}/intervals/{interval}?kill=true pode ser usado em seu lugar.
  • A propriedade druid.indexer.runner.separateIngestionEndpoint agora está obsoleta. Se você estivesse usando essa funcionalidade para isolar solicitações push de eventos e solicitações de atendimento de consultas para tarefas em tempo real, poderá realizar algo semelhante com druid.indexer.server.maxChatRequests.
  • Para desenvolvedores de extensões Druid, observe que as constantes QueryGranularity (ALL, NONE, etc) foram movidas para io.druid.granularity.QueryGranularities em #2980. A sintaxe da consulta não é afetada.

Atualizações contínuas

O processo padrão de atualização do Druida descrito por http://druid.io/docs/0.9.1.1/operations/rolling-updates.html deve ser seguido para atualizações contínuas.

Supervisor Kafka

Druid 0.9.1 é a primeira versão a incluir o serviço experimental de indexação Kafka, utilizando uma nova tarefa de indexação do tipo Kafka e um supervisor que é executado dentro do Druid overlord. O serviço de indexação Kafka fornece uma garantia de ingestão exatamente uma vez e não tem restrição de eventos que exigem carimbos de data/hora que estejam dentro de um período de janela. Mais detalhes sobre esse recurso estão disponíveis na documentação: http://druid.io/docs/0.9.1.1/development/extensions-core/kafka-ingestion.html. Observação: O serviço de indexação Kafka usa o consumidor Java Kafka que foi introduzido no Kafka 0.9. Como houve alterações de protocolo nesta versão, os consumidores Kafka 0.9 não são compatíveis com corretores mais antigos e você precisará garantir que seus corretores Kafka sejam da versão 0.9 ou superior. Detalhes sobre a atualização para a versão mais recente do Kafka podem ser encontrados aqui: http://kafka.apache.org/documentation.html#upgrade

druid druid-0.9.1.1

Druid 0.9.1.1 contains only one change since Druid 0.9.1, #3204, which addresses a bug with the Coordinator web console. The full list of changes for the Druid 0.9.1 line is here: https://github.com/druid-io/druid/issues?q=milestone%3A0.9.1+is%3Aclosed

Updating from 0.9.0

Query time lookups

Query time lookup (QTL) functionality has been substantially reworked in this release. Most users will need to update their configurations and queries.

The druid-namespace-lookup extension is now deprecated, and will be removed in a future version of Druid. Users should migrate to the new druid-lookups-cached-global extension. Both extensions can be loaded simultaneously to simplify migration. For details about migrating, see Transitioning to lookups-cached-global in the documentation.

Other notes

Aside from the QTL changes, please note the following changes:

  • The default value for maxRowsInMemory has been set to 75,000 across the board for all forms of ingestion. This is in line with previous defaults for Hadoop tasks and Tranquility-based ingestion. If you were creating realtime index tasks directly (without Tranquility) then this is lower than the previous default of 500,000.
  • The /druid/coordinator/v1/datasources/{dataSourceName}?kill=true&interval={myISO8601Interval} REST endpoint is now deprecated. The new /druid/coordinator/v1/datasources/{dataSourceName}/intervals/{interval}?kill=true REST endpoint can be used instead.
  • The druid.indexer.runner.separateIngestionEndpoint property is now deprecated. If you were using this functionality to isolate event-push requests and query serving requests for realtime tasks, you can accomplish something similar with druid.indexer.server.maxChatRequests.
  • For developers of Druid extensions, note that the QueryGranularity constants (ALL, NONE, etc) have been moved to io.druid.granularity.QueryGranularities in #2980. Query syntax is not affected.

Rolling updates

The standard Druid update process described by http://druid.io/docs/0.9.1.1/operations/rolling-updates.html should be followed for rolling updates.

Kafka Supervisor

Druid 0.9.1 is the first version to include the experimental Kafka indexing service, utilizing a new Kafka-type indexing task and a supervisor that runs within the Druid overlord. The Kafka indexing service provides an exactly-once ingestion guarantee and does not have the restriction of events requiring timestamps which fall within a window period. More details about this feature are available in the documentation: http://druid.io/docs/0.9.1.1/development/extensions-core/kafka-ingestion.html.

Note: The Kafka indexing service uses the Java Kafka consumer that was introduced in Kafka 0.9. As there were protocol changes made in this version, Kafka 0.9 consumers are not compatible with older brokers and you will need to ensure that your Kafka brokers are version 0.9 or better. Details on upgrading to the latest version of Kafka can be found here: http://kafka.apache.org/documentation.html#upgrade
