druida druida-0.8.0

Recentemente, introduzimos uma alteração incompatível com versões anteriores no esquema que o Druid usa quando emite métricas. Se você não estiver emitindo métricas Druid para um endpoint http, o procedimento de atualização deverá ser simples.

Atualizando de 0.7.x

  • Se você estiver emitindo métricas Druid para um endpoint http, consulte https://github.com/druid-io/druid/blob/master/docs/content/operations/metrics.md para o novo esquema usado para métricas Druid
  • io.druid.server.metrics.ServerMonitor foi renomeado para io.druid.server.metrics.HistoricalMetricsMonitor. Você precisará atualizar todas as configurações que contenham essa alteração.
  • A correção de uma das chaves de índice do banco de dados requer etapas de migração descritas em https://github.com/druid-io/druid/pull/1322

Atualizando do 0.6.x

  • Consulte o guia de atualização de 0.6.x para 0.7.x: https://github.com/druid-io/druid/releases/tag/druid-0.7.0
  • Após atualizar para 0.7.x, siga as instruções anteriores para atualizar para 0.8.x

Novos recursos

  • Refazer métricas do Druid para usar um esquema de métricas compreensível
  • Suporte à compactação para colunas de vários valores
  • Adicionados agregadores longMax/longMin além dos agregadores min/max [double] anteriores que foram renomeados para doubleMax/doubleMin apropriados
  • Adicionada uma tarefa hadoop_convert_segment para o indexador para permitir a recompactação em lote em grande escala de dados antigos como uma tarefa do indexador.

Melhorias

  • A tarefa de índice agora ignora linhas inválidas (#1264)
  • Filtragem de segmento aprimorada para dataSourceMetadataQuery (#1299)
  • Numerosos testes de unidade adicionais

Correções de bugs

  • Corrigidos avisos obsoletos na indexação em lote do Hadoop (#1275). Obrigado @infynyxx!
  • Correção de groupBys aplicando limitSpecs a históricos em agregações de postagens (#1292). Obrigado @guobingkun!
  • Corrija valores digitados incorretamente em consultas SQL de metadados (#1295). Obrigado @anubhgup!
  • Corrigir problemas de cache do timeBoundary (#1303)
  • Correção do problema do serde ao extrair carimbos de data/hora do cache (#1304)
  • Corrigidos arquivos gzip concatenados com firehose s3 estático (#1311)
  • Corrigir problemas de configuração da tabela de auditoria (#1322)
  • Corrigir serde de mangueira de incêndio IRC (#1331)
  • Corrigir exceções aritméticas no corretor (#1336)
  • Corrigido um erro em que a tarefa Converter segmento deixaria tarefas zumbis se a tarefa falhasse (#1363)
  • Corrigido #1365 para retornar o nome real da métrica complexa na resposta da consulta de metadados do segmento
  • Correção do cache groupBy para funcionar com agregadores renomeados (#1499)

Documentação

  • Numerosas correções de erros de digitação. Obrigado a @textractor, @rasahner e @bobrik.

druid druid-0.8.0

We recently introduced a backwards incompatible change to the schema Druid uses when it emits metrics. If you are not emitting Druid metrics to an http endpoint, the update procedure should be straightforward.

Updating from 0.7.x

  • If you are emitting Druid metrics to an http endpoint, please consult https://github.com/druid-io/druid/blob/master/docs/content/operations/metrics.md for the new schema used for Druid metrics
  • io.druid.server.metrics.ServerMonitor has been renamed to io.druid.server.metrics.HistoricalMetricsMonitor. You will need to update any configs that contain this change.
  • Correction to one of db index keys requires migration steps described in https://github.com/druid-io/druid/pull/1322

Updating from 0.6.x

  • Please see the update guide from 0.6.x to 0.7.x: https://github.com/druid-io/druid/releases/tag/druid-0.7.0
  • After updating to 0.7.x, follow the previous instructions to update to 0.8.x

New Features

  • Redo Druid metrics to use an understandable metrics schema
  • Support compression for multi-value columns
  • Added longMax/longMin aggregators in addition to previous min/max [double] aggregators which have been renamed to appropriate doubleMax/doubleMin
  • Added a hadoop_convert_segment task for the indexer to allow large scale batch re-compression of old data as an indexer task.

Improvements

  • Index task now ignores invalid rows (#1264)
  • Improved segment filtering for dataSourceMetadataQuery (#1299)
  • Numerous additional unit tests

Bug Fixes

  • Fixed deprecated warnings in Hadoop batch indexing (#1275). Thanks @infynyxx!
  • Fix groupBys applying limitSpecs to historicals on post aggregations (#1292). Thanks @guobingkun!
  • Fix incorrectly typed values in metadata sql queries (#1295). THanks @anubhgup!
  • Fix timeBoundary cache serde problems (#1303)
  • Fix serde issue with pulling timestamps from cache (#1304)
  • Fixed concatenated gzip files with static s3 firehose (#1311)
  • Fix audit table config serde problems (#1322)
  • Fix IRC firehose serde (#1331)
  • Fix Arithmetic exceptions on the broker (#1336)
  • Fix an error where the Convert Segment Task would leave zombie tasks if the task failed (#1363)
  • Fixed #1365 to return actual complex metric name in segment metadata query response
  • Fix groupBy caching to work with renamed aggregators (#1499)

Documentation

  • Numerous typo fixes. Thanks to @textractor, @rasahner, & @bobrik.
