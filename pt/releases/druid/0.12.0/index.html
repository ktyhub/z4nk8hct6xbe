druida druida-0.12.0

Druid 0.12.0 contém mais de cem melhorias de desempenho, melhorias de estabilidade e correções de bugs de quase 40 colaboradores. Esta versão adiciona melhorias importantes ao serviço de indexação Kafka. Outros novos recursos importantes incluem:

  • Bloqueio de tarefas priorizadas
  • Melhor gerenciamento automático de segmentos
  • Teste pós-agregadores de estatísticas
  • Agregador de esboço de quantis numéricos
  • Extensão de autenticação básica
  • Melhorias no enfileiramento de solicitações de consulta
  • Análise de suporte em lote
  • Várias melhorias de desempenho
  • Várias melhorias no Druid SQL A lista completa de alterações está aqui: https://github.com/druid-io/druid/pulls?utf8=%E2%9C%93&q=is%3Apr%20is%3Aclosed%20milestone%3A0.12.0 A documentação para esta versão está em: http://druid.io/docs/0.12.0/

Destaques

Kafka indexando handoffs incrementais e particionamento desacoplado

O serviço de indexação Kafka agora oferece suporte a transferências incrementais, bem como à dissociação do número de segmentos criados por uma tarefa de indexação Kafka do número de partições Kafka. Consulte https://github.com/druid-io/druid/pull/4815#issuecomment-346155552 para obter mais informações. Adicionado por @pjain1 em #4815.

Bloqueio de tarefas priorizadas

Druid agora oferece suporte a prioridades para indexação de bloqueios de tarefas. Quando uma tarefa de indexação precisa adquirir um bloqueio em uma fonte de dados + intervalo, as tarefas de prioridade mais alta agora podem antecipar as tarefas de prioridade mais baixa. Consulte http://druid.io/docs/0.12.0-rc1/ingestion/tasks.html#task-priority para obter mais informações. Adicionado por @jihoonson em https://github.com/druid-io/druid/pull/4550.

Gerenciamento automático de segmento aprimorado

Limpeza automática de segmentos pendentes

As tarefas de indexação criam entradas na tabela "pendingSegments" no armazenamento de metadados; antes do 0.12.0, essas entradas temporárias não eram limpas automaticamente, levando a uma possível degradação do desempenho do cluster ao longo do tempo. Druid 0.12.0 permite que o coordenador limpe automaticamente as entradas não utilizadas na tabela de segmentos pendentes. Este recurso é habilitado configurando druid.coordinator.kill.pendingSegments.on=true nas propriedades do coordenador. Adicionado por @jihoonson em #5149.

Tarefa de compactação

Compactar segmentos (mesclar um conjunto de segmentos dentro de um determinado intervalo para criar um conjunto com segmentos maiores, mas com menos segmentos) é um caso de uso comum de ingestão em lote do Druid. Druid 0.12.0 agora suporta uma tarefa de compactação que mescla todos os segmentos dentro de um determinado intervalo em um único segmento. Consulte http://druid.io/docs/0.12.0-rc1/ingestion/tasks.html#compaction-task para obter mais detalhes. Adicionado por @jihoonson em #4985.

Teste pós-agregadores de estatísticas

Novos pós-agregadores de estatísticas de teste de pontuação z e valor p foram adicionados à extensão druid-stats. Consulte http://druid.io/docs/0.12.0-rc1/development/extensions-core/test-stats.html para obter mais detalhes. Adicionado por @chunghochen em #4532.

Agregador de esboço de quantis numéricos

Um agregador de esboço de quantis numéricos foi adicionado à extensão druid-datasketches. Adicionado por @AlexanderSaydakov em #5002.

Extensão de autenticação básica

Druid 0.12.0 inclui uma nova extensão de autenticação/autorização que fornece autenticação HTTP básica e controle de acesso simples baseado em função. Consulte http://druid.io/docs/0.12.0-rc1/development/extensions-core/druid-basic-security.html para obter mais informações. Adicionado por @jon-wei em #5099.

Melhorias na fila de solicitações de consulta

Atualmente, clients pode sobrecarregar um corretor inadvertidamente, enviando muitas solicitações que são enfileiradas em uma fila de pool de trabalhadores Jetty ilimitada. Clients normalmente fecham a conexão após um certo tempo limite do lado client, ​​mas o corretor continuará a processar essas solicitações, dando a impressão de não estar respondendo. Enquanto isso, clients continuaria tentando novamente, continuando a adicionar solicitações a um corretor já sobrecarregado. As propriedades recentemente introduzidas druid.server.http.queueSize e druid.server.http.enableRequestLimit na configuração do corretor e configuração histórica permitem que os usuários configurem a rejeição de solicitações para evitar que clients sobrecarreguem os corretores e históricos com consultas. Adicionado por @himanshug em #4540.

Análise de suporte em lote

Para desenvolvedores de extensões de análise de ingestão personalizadas, agora é possível que InputRowParsers retorne vários InputRows de uma única linha de entrada. Isso pode simplificar os pipelines de ingestão, reduzindo a necessidade de transformações de entrada fora do Druid. Adicionado por @pjain1 em #5081.

Melhorias de desempenho

SegmentWriteOutMedium

Ao criar novos segmentos, o Druid armazena alguns dados pré-processados em buffers temporários. Antes do 0.12.0, esses buffers sempre eram mantidos em arquivos temporários no disco. No 0.12.0, o PR #4762 de @leventov permite que esses buffers temporários sejam armazenados na memória fora do heap, reduzindo assim o número de operações de E/S do disco durante a ingestão. Para ativar o uso de memória fora do heap para esses buffers, a propriedade druid.peon.defaultSegmentWriteOutMediumFactory precisa ser configurada adequadamente. Se estiver usando memória fora do heap para buffers temporários, certifique-se de que -XX:MaxDirectMemorySize seja aumentado para acomodar o maior uso direto de memória. Consulte http://druid.io/docs/0.12.0-rc1/configuration/indexing-service.html#SegmentWriteOutMediumFactory para obter detalhes de configuração.

Mesclagem paralela de resultados GroupBy intermediários

PR #4704 de @jihoonson permite ao usuário configurar vários threads de processamento a serem usados para mesclagem paralela de resultados GroupBy intermediários que foram derramados no disco. Antes do 0.12.0, essa etapa de fusão sempre ocorria em um único thread. Consulte http://druid.io/docs/0.12.0-rc1/configuration/querying/groupbyquery.html#parallel-combine para obter detalhes de configuração.

Outras melhorias de desempenho

  • Otimizações de memória DataSegment: #5094 por @leventov
  • Remover IndexedInts.iterator(): #4811 por @leventov
  • ExpressionSelectors: Adicione seletores otimizados: #5048 por @gianm

Melhorias SQL

Várias melhorias e recursos foram adicionados ao Druid SQL, por @gianm nos seguintes PRs:

  • Melhorar a tradução de expressões de piso de tempo: #5107
  • Adicionar TIMESTAMPADD: #5079
  • Adicionar regra para remover agregações não utilizadas: #5049
  • Suporte a contagem filtrada distinta no estilo CASE: #5047
  • Adicionar formato de resultado "array" e formatos de resultado de documento: #5032
  • Correção do puttingSpec em agregadores complexos: #5024
  • Comportamento aprimorado ao converter strings implicitamente para literais de data/hora: #5023
  • Adicionar balanceadores de conexão do roteador para consultas Avatica: #4983
  • Corrija a simplificação incorreta do filtro: #4945
  • Correção do tratamento de consultas SQL do roteador: #4851

Atualizando de 0.11.0 e versões anteriores

Veja abaixo as alterações entre 0.11.0 e 0.12.0 que você deve conhecer antes de atualizar. Se você estiver atualizando de uma versão anterior ao 0.11.0, consulte release notes das versões intermediárias relevantes para obter notas adicionais.

Restrições de reversão

Observe que após a atualização para 0.12.0 não é mais possível fazer o downgrade para uma versão anterior a 0.11.0, devido às alterações feitas em https://github.com/druid-io/druid/pull/4762. Ainda é possível reverter para a versão 0.11.0.

migração da biblioteca com.metamx.java-util

A biblioteca java-util Metamarkets foi trazida para o Druid. Como resultado, as seguintes referências de pacote foram alteradas: com.metamx.common -> io.druid.java.util.common com.metamx.emitter -> io.druid.java.util.emitter com.metamx.http -> io.druid.java.util.http com.metamx.metrics -> io.druid.java.util.metrics Isso afetará a configuração do druid.monitoring.monitors. As referências às classes de monitoramento no antigo pacote com.metamx.metrics.* precisarão ser atualizadas para referenciar io.druid.java.metrics.*, por exemplo. io.druid.java.util.metrics.JvmMonitor. Se as classes nos pacotes com.metamx mostrados acima forem referenciadas em outras configurações, como log4j2.xml, essas referências também precisarão ser atualizadas. Os desenvolvedores de extensões precisarão atualizar seu código para usar os novos pacotes Druid também.

Extensão de cache de cafeína

A extensão de cache Caffeine foi movida de uma extensão para o núcleo Druid. Além disso, o cache Caffeine é agora a implementação de cache padrão. Remova druid-caffeine-cache se estiver presente na lista de extensões ao atualizar para 0.12.0. Mais informações podem ser encontradas em https://github.com/druid-io/druid/pull/4810.

Mudanças no serviço de indexação Kafka

earlyMessageRejectPeriod

A semântica da configuração do earlyMessageRejectPeriod mudou. O earlyMessageRejectPeriod agora será adicionado ao (task start time + task duration) em vez de apenas ao (task start time) ao determinar os limites da janela de mensagem. Consulte https://github.com/druid-io/druid/pull/4990 para obter mais informações.

Atualização contínua

No 0.12.0, há alterações de protocolo entre o supervisor Kafka e a tarefa de indexação Kafka e também algumas alterações nos formatos de metadados persistidos no disco. Portanto, para suportar a atualização contínua, todos os Gerentes Intermediários precisarão ser atualizados primeiro antes do Overlord. Observe que esta ordem é diferente da ordem padrão de atualização. Observe também que esta ordem só é necessária ao usar o Serviço de Indexação Kafka. Se alguém não estiver usando o Kafka Indexing Service ou puder lidar com o tempo de inatividade do Kafka Supervisor, poderá atualizar em qualquer ordem. Até o momento em que o Overlord for atualizado, todas as tarefas de indexação do Kafka se comportarão da mesma maneira (mesmo se forem atualizadas) como antes, o que significa que não há dissociação e transferências incrementais. Assim que o Overlord for atualizado, as novas tarefas iniciadas pelo Overlord atualizado suportarão os novos recursos. Consulte https://github.com/druid-io/druid/pull/4815 para obter mais informações.

Reverter

Depois que os gerentes superiores e intermediários forem revertidos, um novo conjunto de tarefas deverá ser iniciado, o que funcionará corretamente. No entanto, o conjunto atual de tarefas poderá falhar durante uma reversão. Consulte #4815 para obter mais informações.

Mudanças na interface para desenvolvedores de extensões

O ColumnSelectorFactory API mudou. Os autores da extensão do agregador e quaisquer outros que usem ColumnSelectorFactory precisarão atualizar seu código de acordo. Consulte https://github.com/druid-io/druid/pull/4886 para obter mais detalhes. O método Aggregator.reset() foi removido porque estava obsoleto e não era usado. Consulte https://github.com/druid-io/druid/pull/5177 para obter mais informações. A interface DataSegmentPusher foi alterada e o método push() agora possui um parâmetro replaceExisting adicional. Consulte https://github.com/druid-io/druid/pull/5187 para obter detalhes. A interface Escalator foi alterada: o método createEscalatedJettyClient foi removido. Consulte https://github.com/druid-io/druid/pull/5322 para obter mais detalhes.

druid druid-0.12.0

Druid 0.12.0 contains over a hundred performance improvements, stability improvements, and bug fixes from almost 40 contributors. This release adds major improvements to the Kafka indexing service.

Other major new features include:

  • Prioritized task locking
  • Improved automatic segment management
  • Test stats post-aggregators
  • Numeric quantiles sketch aggregator
  • Basic auth extension
  • Query request queuing improvements
  • Parse batch support
  • Various performance improvements
  • Various improvements to Druid SQL

The full list of changes is here: https://github.com/druid-io/druid/pulls?utf8=%E2%9C%93&q=is%3Apr%20is%3Aclosed%20milestone%3A0.12.0

Documentation for this release is at: http://druid.io/docs/0.12.0/

Highlights

Kafka indexing incremental handoffs and decoupled partitioning

The Kafka indexing service now supports incremental handoffs, as well as decoupling the number of segments created by a Kafka indexing task from the number of Kafka partitions. Please see https://github.com/druid-io/druid/pull/4815#issuecomment-346155552 for more information.

Added by @pjain1 in #4815.

Prioritized task locking

Druid now supports priorities for indexing task locks. When an indexing task needs to acquire a lock on a datasource + interval, higher-priority tasks can now preempt lower-priority tasks. Please see http://druid.io/docs/0.12.0-rc1/ingestion/tasks.html#task-priority for more information.

Added by @jihoonson in https://github.com/druid-io/druid/pull/4550.

Improved automatic segment management

Automatic pending segments cleanup

Indexing tasks create entries in the "pendingSegments" table in the metadata store; prior to 0.12.0, these temporary entries were not automatically cleaned up, leading to possible cluster performance degradation over time. Druid 0.12.0 allows the coordinator to automatically clean up unused entries in the pending segments table. This feature is enabled by setting druid.coordinator.kill.pendingSegments.on=true in coordinator properties.

Added by @jihoonson in #5149.

Compaction task

Compacting segments (merging a set of segments within a given interval to create a set with larger but fewer segments) is a common Druid batch ingestion use case. Druid 0.12.0 now supports a Compaction Task that merges all segments within a given interval into a single segment. Please see http://druid.io/docs/0.12.0-rc1/ingestion/tasks.html#compaction-task for more details.

Added by @jihoonson in #4985.

Test stats post-aggregators

New z-score and p-value test statistics post-aggregators have been added to the druid-stats extension. Please see http://druid.io/docs/0.12.0-rc1/development/extensions-core/test-stats.html for more details.

Added by @chunghochen in #4532.

Numeric quantiles sketch aggregator

A numeric quantiles sketch aggregator has been added to the druid-datasketches extension.

Added by @AlexanderSaydakov in #5002.

Basic auth extension

Druid 0.12.0 includes a new authentication/authorization extension that provides Basic HTTP authentication and simple role-based access control. Please see http://druid.io/docs/0.12.0-rc1/development/extensions-core/druid-basic-security.html for more information.

Added by @jon-wei in #5099.

Query request queuing improvements

Currently clients can overwhelm a broker inadvertently by sending too many requests which get queued in an unbounded Jetty worker pool queue. Clients typically close the connection after a certain client-side timeout but the broker will continue to process these requests, giving the appearance of being unresponsive. Meanwhile, clients would continue to retry, continuing to add requests to an already overloaded broker..

The newly introduced properties druid.server.http.queueSize and druid.server.http.enableRequestLimit in the broker configuration and historical configuration allow users to configure request rejection to prevent clients from overwhelming brokers and historicals with queries.

Added by @himanshug in #4540.

Parse batch support

For developers of custom ingestion parsing extensions, it is now possible for InputRowParsers to return multiple InputRows from a single input row. This can simplify ingestion pipelines by reducing the need for input transformations outside of Druid. Added by @pjain1 in #5081.

Performance improvements

SegmentWriteOutMedium

When creating new segments, Druid stores some pre-processed data in temporary buffers. Prior to 0.12.0, these buffers were always kept in temporary files on disk. In 0.12.0, PR #4762 by @leventov allows these temporary buffers to be stored in off-heap memory, thus reducing the number of disk I/O operations during ingestion. To enable using off-heap memory for these buffers, the druid.peon.defaultSegmentWriteOutMediumFactory property needs to be configured accordingly. If using off-heap memory for the temporary buffers, please ensure that -XX:MaxDirectMemorySize is increased to accommodate the higher direct memory usage.

Please see http://druid.io/docs/0.12.0-rc1/configuration/indexing-service.html#SegmentWriteOutMediumFactory for configuration details.

Parallel merging of intermediate GroupBy results

PR #4704 by @jihoonson allows the user to configure a number of processing threads to be used for parallel merging of intermediate GroupBy results that have been spilled to disk. Prior to 0.12.0, this merging step would always take place within a single thread.

Please see http://druid.io/docs/0.12.0-rc1/configuration/querying/groupbyquery.html#parallel-combine for configuration details.

Other performance improvements

  • DataSegment memory optimizations: #5094 by @leventov
  • Remove IndexedInts.iterator(): #4811 by @leventov
  • ExpressionSelectors: Add optimized selectors: #5048 by @gianm

SQL improvements

Various improvements and features have been added to Druid SQL, by @gianm in the following PRs:

  • Improve translation of time floor expressions: #5107
  • Add TIMESTAMPADD: #5079
  • Add rule to prune unused aggregations: #5049
  • Support CASE-style filtered count distinct: #5047
  • Add "array" result format, and document result formats: #5032
  • Fix havingSpec on complex aggregators: #5024
  • Improved behavior when implicitly casting strings to date/time literals: #5023
  • Add Router connection balancers for Avatica queries: #4983
  • Fix incorrect filter simplification: #4945
  • Fix Router handling of SQL queries: #4851

And much more!

The full list of changes is here: https://github.com/druid-io/druid/pulls?utf8=%E2%9C%93&q=is%3Apr%20is%3Aclosed%20milestone%3A0.12.0

Updating from 0.11.0 and earlier

Please see below for changes between 0.11.0 and 0.12.0 that you should be aware of before upgrading. If you're updating from an earlier version than 0.11.0, please see release notes of the relevant intermediate versions for additional notes.

Rollback restrictions

Please note that after upgrading to 0.12.0, it is no longer possible to downgrade to a version older than 0.11.0, due to changes made in https://github.com/druid-io/druid/pull/4762. It is still possible to roll back to version 0.11.0.

com.metamx.java-util library migration

The Metamarkets java-util library has been brought into Druid. As a result, the following package references have changed:

com.metamx.common -> io.druid.java.util.common com.metamx.emitter -> io.druid.java.util.emitter com.metamx.http -> io.druid.java.util.http com.metamx.metrics -> io.druid.java.util.metrics

This will affect the druid.monitoring.monitors configuration. References to monitor classes under the old com.metamx.metrics.* package will need to be updated to reference io.druid.java.metrics.* instead, e.g. io.druid.java.util.metrics.JvmMonitor.

If classes under the the com.metamx packages shown above are referenced in other configurations such as log4j2.xml, those references will need to be updated as well.

Extension developers will need to update their code to use the new Druid packages as well.

Caffeine cache extension

The Caffeine cache extension has been moved out of an extension, into core Druid. In addition, the Caffeine cache is now the default cache implementation. Please remove druid-caffeine-cache if present from the extension list when upgrading to 0.12.0. More information can be found at https://github.com/druid-io/druid/pull/4810.

Kafka indexing service changes

earlyMessageRejectPeriod

The semantics of the earlyMessageRejectPeriod configuration have changed. The earlyMessageRejectPeriod will now be added to (task start time + task duration) instead of just (task start time) when determining the bounds of the message window. Please see https://github.com/druid-io/druid/pull/4990 for more information.

Rolling upgrade

In 0.12.0, there are protocol changes between the Kafka supervisor and Kafka Indexing task and also some changes to the metadata formats persisted on disk. Therefore, to support rolling upgrade, all the Middle Managers will need to be upgraded first before the Overlord. Note that this ordering is different from the standard order of upgrade, also note that this ordering is only necessary when using the Kafka Indexing Service. If one is not using Kafka Indexing Service or can handle down time for Kafka Supervisor then one can upgrade in any order.

Until the point in time Overlord is upgraded, all the Kafka Indexing Task will behave in same manner (even if they are upgraded) as earlier which means no decoupling and incremental hand-offs. Once, Overlord is upgraded, the new tasks started by the upgraded Overlord will support the new features.

Please see https://github.com/druid-io/druid/pull/4815 for more info.

Roll back

Once both the overlord and middle managers are rolled back, a new set of tasks should be started, which will work properly. However, the current set of tasks may fail during a roll back. Please see #4815 for more info.

Interface Changes for Extension Developers

The ColumnSelectorFactory API has changed. Aggregator extension authors and any others who use ColumnSelectorFactory will need to update their code accordingly. Please see https://github.com/druid-io/druid/pull/4886 for more details.

The Aggregator.reset() method has been removed because it was deprecated and unused. Please see https://github.com/druid-io/druid/pull/5177 for more info.

The DataSegmentPusher interface has changed, and the push() method now has an additional replaceExisting parameter. Please see https://github.com/druid-io/druid/pull/5187 for details.

The Escalator interface has changed: the createEscalatedJettyClient method has been removed. Please see https://github.com/druid-io/druid/pull/5322 for more details.
