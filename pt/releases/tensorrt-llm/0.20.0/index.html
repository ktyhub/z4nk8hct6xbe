TensorRT-LLM v0.20.0

TensorRT-LLM versão 0.20.0

Principais recursos e melhorias

  • Suporte ao modelo
    • Adicionado suporte Qwen3. Consulte a seção “Qwen3” em examples/models/core/qwen/README.md.
    • Adicionado suporte HyperCLOVAX-SEED-Vision no fluxo PyTorch. Consulte examples/models/contrib/hyperclovax/README.md
    • Adicionado Dynasor-CoT em exemplos de andaimes. Consulte examples/scaffolding/contrib/Dynasor/README.md
    • Adicionado suporte Mistral Small 3.1 24B VLM no fluxo de trabalho TRT
    • Adicionado suporte Gemma3-1b-it no fluxo de trabalho PyTorch
    • Adicionado suporte ao modelo Nemotron-H
    • Adicionado suporte Eagle-3 para LLAMA4
  • Fluxo de trabalho PyTorch
    • Adicionado suporte para Lora
    • Adicionado suporte a logits de retorno
    • Adote nova definição de logprob no fluxo PyTorch
    • Estatísticas por solicitação habilitadas com backend PyTorch
    • LogitsProcessor ativado no back-end do PyTorch
  • Referência:
    • Adicione largura do feixe para baixa latência.
    • Corrigir erros trtllm-bench iter_stats e cuda_graph_batch_sizes.
    • Remover benchmark de tempo de execução Python obsoleto
    • Adicionar suporte de benchmark para andaimes
  • Modelos multimodais
    • Adicionado suporte em trtllm-serve
    • Adicionado suporte no trtllm-bench, o suporte é limitado apenas à imagem por enquanto
  • Compatível com DeepSeek-R1 W4A8 no Hopper
  • Adicione o suporte RTX Pro 6000 em GPU única
  • Processador de entrada Llama4 integrado
  • Adicionados kernels FHMA de redução de CGA na Blackwell
  • Contexto fragmentado habilitado para FlashInfer
  • Reutilização de cache KV suportada para MLA
  • Adicionado suporte ao gráfico Piecewise CUDA
  • Suporta vários adaptadores LoRA e TP
  • Adicionado roteador com reconhecimento de cache KV para serviço desagregado
  • Atenção não concentrada para suporte nativo
  • Adicionado kernel group_rms_norm para normalizar múltiplas entradas em um único operador
  • Adicionado roteador inteligente para o módulo MoE
  • Adicionado suporte de tamanho de cabeçote 72 para kernel de pré-processamento QKV
  • Adicionado suporte MNNVL MoE A2A
  • Grandes tabelas de incorporação otimizadas em modelos multimodais
  • Logprobs e prompt_logprobs Top-K suportados em LLMAPI
  • Habilitado agendador de sobreposição no fluxo de trabalho TRT via executor API

Mudanças na infraestrutura

  • A equipe TRT-LLM lança formalmente a imagem docker em NGC.
  • A roda TensorRT-LLM pré-construída no PyPI agora está vinculada ao PyTorch 2.7.0, que usa o CXX11 ABI
  • A versão dependente do TensorRT foi atualizada para 10.10.0
  • A versão CUDA dependente é atualizada para 12.9.0
  • A versão pública dependente do PyTorch foi atualizada para 2.7.0
  • A versão dependente do NVIDIA ModelOpt foi atualizada para 0.29.0
  • A versão dependente do NCCL é mantida em 2.25.1
  • Kernels XQA de código aberto
  • A versão dos conjuntos de dados dependentes foi atualizada para 3.1.0
  • Migrar o back-end do Triton para o repositório TensorRT LLM para o submódulo TensorRT LLM
  • Downgrade da versão do conjunto de ferramentas gcc de 13 para 11

API Mudanças

  • [Alteração significativa]: Habilitar sobreposição de agendamento por padrão
  • Remover GptSession/V1 obsoleto do fluxo de trabalho TRT
  • Definir _AutoDeployLlmArgs como objeto de configuração primário
  • Permitir substituir argumentos CLI pelo arquivo YAML em trtllm-serve
  • Introduziu campo de incorporação multimodal no LlmRequest

  • Correção de bug relacionado à criação de stream CUDA como parâmetro padrão, que será inicializado durante a importação (#3764)
  • Corrigido bug de DP de atenção no modelo Qwen3 MoE (#4141)
  • Corrigido acesso ilegal à memória ao executar LLaMA 4 com CUDA Graph habilitado (#4101)
  • Redefina os estados planejados para evitar vazamento de memória no TrtllmAttentionWrapper (#4227)

TensorRT-LLM v0.20.0

Highlights

  • Scheduling overlap now on by default (breaking) — The most consequential behavioral change: overlap scheduling ships enabled, which alters request scheduling and can shift latency/throughput profiles for existing deployments. The flag was also corrected to enable_overlap_scheduler (#4433), so launch scripts still using the old name will silently lose control of it — audit your configs. In the same vein, the legacy GptSession/V1 TRT path is removed (V1 batching tests dropped in #4703) and _AutoDeployLlmArgs becomes the primary config object, so code built on the old session API or config shape needs migration.
  • Toolchain and dependency jump — This release rebases on PyTorch 2.7.0 (now built with the CXX11 ABI), TensorRT 10.10.0, CUDA 12.9.0, ModelOpt 0.29.0 and datasets 3.1.0, with NCCL held at 2.25.1. The CXX11 ABI switch is the one to watch: out-of-tree C++ extensions and custom plugins must be rebuilt against the new ABI or you'll hit symbol/link mismatches. GCC is downgraded 13→11 and the Triton backend moves into a submodule — both relevant if you build from source. NVIDIA now publishes an official release image on NGC (#4400), the safest route to a consistent stack.
  • Broader model and hardware coverage — Qwen3 (including a fix for missing mrope args in summary tasks, #4432), Nemotron-H, Eagle-3 speculative decoding for Llama4, Mistral Small 3.1 24B VLM, Gemma3-1b-it and HyperCLOVAX-SEED-Vision land, plus DeepSeek-R1 W4A8 on Hopper. RTX Pro 6000 (SM120) gains single-GPU FP8/NVFP4 support for Nemotron Super 49B (#4363, #4548), but multi-GPU on that part remains a known issue — plan single-GPU deployments for now.
  • PyTorch flow approaches parity — The PyTorch backend adds LoRA, return-logits, per-request stats and LogitsProcessor support, and adopts the new logprob definition. That last item is behaviorally significant: logprob values and their contract change, so downstream scoring or cross-backend comparisons should be revalidated rather than assumed identical to the TRT path.
  • New serving and performance levers — Long-context and MoE serving get piecewise CUDA graphs, MLA KV-cache reuse, a KV-cache-aware router for disaggregated serving, chunked context for FlashInfer, a smart MoE router and the overlap scheduler via the TRT executor API. LLM API adds top-K logprobs and prompt_logprobs, and LlmRequest gains a multimodal embedding field — important if you build multimodal serving on trtllm-serve.
  • Stability fixes worth the bump — Several correctness bugs close here: a hang when the context server lacks KV-cache capacity (#3095), illegal memory access with Llama4 under CUDA graphs (#4101), C++ decoder synchronization in PyTorch (#3106) and an attention data-parallel bug on Qwen3 MoE (#4141). If you run disaggregated serving or CUDA-graph-enabled Llama4, these alone justify upgrading.
