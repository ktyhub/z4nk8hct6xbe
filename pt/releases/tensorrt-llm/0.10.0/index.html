TensorRT-LLM v0.10.0

Olá, Temos o prazer de anunciar a versão 0.10.0 do TensorRT-LLM. Tem sido um esforço intenso e esperamos que permita que você implante facilmente inferência baseada em GPU para LLMs de última geração. Queremos que o TensorRT-LLM ajude você a executar esses LLMs muito rapidamente. Esta atualização inclui:

Principais recursos e melhorias

  • O Python API de alto nível
    • Adicionada incorporação paralela, incorporação de compartilhamento e suporte MLP fundido.
    • Habilitado o uso do executor API.
  • Adicionado um recurso de redução de peso com um novo comando trtllm-refit. Para obter mais informações, consulte examples/sample_weight_stripping/README.md.
  • Adicionado um recurso de streaming de peso. Para obter mais informações, consulte docs/source/advanced/weight-streaming.md.
  • Aprimorado o recurso de múltiplos perfis; O argumento --multiple_profiles no comando trtllm-build cria mais perfis de otimização agora para melhor desempenho.
  • Adicionado suporte de quantização FP8 para Mixtral.
  • Adicionado suporte para paralelismo de pipeline para GPT.
  • Kernel applyBiasRopeUpdateKVCache otimizado evitando recálculo.
  • Redução de overheads entre chamadas enqueue de motores TensorRT.
  • Adicionado suporte para cache KV paginado para modelos enc-dec. O apoio está limitado à largura da viga 1.
  • Adicionados kernels W4A(fp)8 CUTLASS para a arquitetura NVIDIA Ada Lovelace.
  • Adicionadas opções de depuração (--visualize_network e --dry_run) ao comando trtllm-build para visualizar a rede TensorRT antes da construção do mecanismo.
  • Integrou os novos kernels NVIDIA Hopper XQA para o modelo LLaMA 2 70B.
  • Melhorou o desempenho do paralelismo de pipeline ao habilitar lotes em andamento.
  • Quantização suportada para modelos Nemotron.
  • Adicionado suporte LoRA para Mixtral e Qwen.
  • Adicionado suporte em lote em voo para modelos ChatGLM.
  • Adicionado suporte ao ModelRunnerCpp para que funcione com o executor API para modelos compatíveis com IFB.
  • Aprimorou o AllReduce personalizado adicionando uma heurística; volte a usar o kernel NCCL nativo quando os requisitos de hardware não forem satisfeitos para obter o melhor desempenho.
  • Otimizado o desempenho do processo de conversão de checkpoint para LLaMA.
  • Referência
    • [BREAKING CHANGE] Movidos os argumentos e a lógica de geração de taxa de solicitação do script de preparação do conjunto de dados para gptManagerBenchmark.
    • Habilitado streaming e suporte à latência Time To the First Token (TTFT) e métricas Inter-Token Latency (ITL) para gptManagerBenchmark.
    • Adicionada a opção --max_attention_window ao gptManagerBenchmark.

Mudanças no API

  • [BREAKING CHANGE] Defina o argumento tokens_per_block padrão do comando trtllm-build como 64 para melhor desempenho.
  • [BREAKING CHANGE] Migração de modelos enc-dec para o fluxo de trabalho unificado.
  • [MUDANÇA DE ÚLTIMA HORA] Renomeado GptModelConfig para ModelConfig.
  • [BREAKING CHANGE] Adicionado modo de decodificação especulativa ao construtor API.
  • [BREAKING CHANGE] Refatorar configurações de agendamento
    • Unificou o SchedulerPolicy com o mesmo nome em batch_scheduler e executor, e renomeou-o para CapacitySchedulerPolicy.
    • Expandiu a estratégia de agendamento de configuração existente de SchedulerPolicy para SchedulerConfig para aumentar a extensibilidade. Este último também introduz uma configuração baseada em blocos chamada ContextChunkingPolicy.
  • [BREAKING CHANGE] O prompt de entrada foi removido da saída de geração nos generate() e generate_async() APIs. Por exemplo, quando solicitado como A B, o resultado da geração original poderia ser <s>A B C D E, onde apenas C D E é a saída real e agora o resultado é C D E.
  • [BREAKING CHANGE] Mudou o padrão add_special_token no backend TensorRT-LLM para True.
  • GptSession e TrtGptModelV1 obsoletos.

Atualizações de modelo

  • Suporte DBRX
  • Suporte Qwen2
  • Suporte CogVLM
  • Suporte porT5
  • Suporte LLaMA 3
  • Apoio ao Ártico (com FP8)
  • Suporte Fuyu
  • Suporte Caqui
  • Implantação de suporte
  • Suporte Phi-3-Mini com corda longa
  • Suporte Neva
  • Suporte Kosmos-2
  • Suporte RecorrenteGemma

Problemas corrigidos

  • Corrigidos alguns comportamentos inesperados na busca de feixe e parada antecipada, para que as saídas sejam mais precisas.
  • Corrigida falha de segmentação com paralelismo de pipeline e gather_all_token_logits. (#1284)
  • Removida a verificação desnecessária no XQA para corrigir travamentos do código Llama 70b Triton. (#1256)
  • Corrigido um problema de ScalarType não suportado para BF16 LoRA. (https://github.com/triton-inference-server/tensorrtllm_backend/issues/403)
  • Eliminado o carregamento e salvamento da tabela de prompts no multimodal. (https://github.com/NVIDIA/TensorRT-LLM/discussions/1436)
  • Corrigido erro ao converter os pesos dos modelos do Qwen 72B INT4-GPTQ. (#1344)
  • Corrigidas paradas antecipadas e falhas em casos de loteamento de Medusa em voo. (#1449)
  • Adicionado suporte para mais versões do NVLink para paralelismo automático. (#1467)
  • Corrigida a falha de afirmação causada pelos valores padrão da configuração de amostragem. (#1447)
  • Correção de uma especificação de requisitos no Windows para nvidia-cudnn-cu12. (#1446)
  • Corrigido erro de cálculo de posição relativa MMHA em gpt_attention_plugin para modelos enc-dec. (#1343)

Mudanças na infraestrutura

  • A imagem base Docker para TensorRT-LLM foi atualizada para nvcr.io/nvidia/pytorch:24.03-py3.
  • A imagem base Docker para backend TensorRT-LLM foi atualizada para nvcr.io/nvidia/tritonserver:24.03-py3.
  • A versão dependente do TensorRT foi atualizada para 10.0.1.
  • A versão CUDA dependente é atualizada para 12.4.0.
  • A versão dependente do PyTorch foi atualizada para 2.2.2. Atualmente, existem dois ramos principais no projeto:
  • O branch rel é o branch estável para o lançamento do TensorRT-LLM. Ele foi submetido a controle de qualidade e testado cuidadosamente.
  • O branch principal é o branch dev. É mais experimental. Estamos atualizando a filial main regularmente com novos recursos, correções de bugs e otimizações de desempenho. A ramificação rel será atualizada com menos frequência e as frequências exatas dependem do seu feedback. Obrigado, A equipe de engenharia do TensorRT-LLM

TensorRT-LLM v0.10.0

Highlights

  • Broader model and quantization support — Adds paths for LLaMA 3, DBRX, Qwen2, CogVLM, Phi-3-Mini with long RoPE, RecurrentGemma, and Arctic with FP8. FP8 Mixtral, Nemotron quantization, Mixtral/Qwen LoRA, and Ada Lovelace W4A(fp)8 CUTLASS kernels expand deployment options. Conversion and kernel fixes for Qwen 72B INT4-GPTQ (#1344) and Code Llama 70B Triton/XQA (#1256) make those paths safer to adopt.

  • Explicit weight lifecycle management — The new trtllm-refit command supports weight stripping, allowing engines to be stored without weights and refit later; weight streaming provides another way to manage weight residency for memory-constrained deployments. Follow the weight-stripping example and streaming documentation to update build and loading workflows rather than assuming existing engine artifacts work unchanged.

  • Executor and scheduler API migration — The Python high-level API and ModelRunnerCpp now support the executor API for IFB-compatible models. Update imports and configuration constructors for GptModelConfig → ModelConfig, SchedulerPolicy → CapacitySchedulerPolicy, and the expanded SchedulerConfig with ContextChunkingPolicy. Builder calls also need the new speculative-decoding mode, while GptSession and TrtGptModelV1 are deprecated.

  • Generation output and token semantics changed — generate() and generate_async() now return only newly generated tokens, not the input prompt. Remove any postprocessing that manually strips or expects a prepended prompt. The TensorRT-LLM backend also defaults add_special_token to True, so explicitly set it to False where existing tokenizer pipelines require the previous behavior.

  • New build defaults and encoder–decoder workflow — Newly built engines default to tokens_per_block=64, changing KV-cache block granularity; set it explicitly when comparing performance or memory against older builds. Encoder–decoder models have moved to the unified workflow, requiring conversion/build/runtime script updates. Their new paged KV-cache support is currently limited to beam width 1.

  • Benchmarking and runtime stack updates — Request-rate arguments moved from the dataset preparation script to gptManagerBenchmark; update harnesses accordingly and use the new streaming TTFT/ITL metrics and --max_attention_window option. Re-pin CI and containers to the 24.03 base images, TensorRT 10.0.1, CUDA 12.4.0, and PyTorch 2.2.2, and rebuild custom plugins against TensorRT 10 before deployment.

Hi,

We are very pleased to announce the 0.10.0 version of TensorRT-LLM. It has been an intense effort, and we hope that it will enable you to easily deploy GPU-based inference for state-of-the-art LLMs. We want TensorRT-LLM to help you run those LLMs very fast.

This update includes:

Key Features and Enhancements

  • The Python high level API
    • Added embedding parallel, embedding sharing, and fused MLP support.
    • Enabled the usage of the executor API.
  • Added a weight-stripping feature with a new trtllm-refit command. For more information, refer to examples/sample_weight_stripping/README.md.
  • Added a weight-streaming feature. For more information, refer to docs/source/advanced/weight-streaming.md.
  • Enhanced the multiple profiles feature; --multiple_profiles argument in trtllm-build command builds more optimization profiles now for better performance.
  • Added FP8 quantization support for Mixtral.
  • Added support for pipeline parallelism for GPT.
  • Optimized applyBiasRopeUpdateKVCache kernel by avoiding re-computation.
  • Reduced overheads between enqueue calls of TensorRT engines.
  • Added support for paged KV cache for enc-dec models. The support is limited to beam width 1.
  • Added W4A(fp)8 CUTLASS kernels for the NVIDIA Ada Lovelace architecture.
  • Added debug options (--visualize_network and --dry_run) to the trtllm-build command to visualize the TensorRT network before engine build.
  • Integrated the new NVIDIA Hopper XQA kernels for LLaMA 2 70B model.
  • Improved the performance of pipeline parallelism when enabling in-flight batching.
  • Supported quantization for Nemotron models.
  • Added LoRA support for Mixtral and Qwen.
  • Added in-flight batching support for ChatGLM models.
  • Added support to ModelRunnerCpp so that it runs with the executor API for IFB-compatible models.
  • Enhanced the custom AllReduce by adding a heuristic; fall back to use native NCCL kernel when hardware requirements are not satisfied to get the best performance.
  • Optimized the performance of checkpoint conversion process for LLaMA.
  • Benchmark
    • [BREAKING CHANGE] Moved the request rate generation arguments and logic from prepare dataset script to gptManagerBenchmark.
    • Enabled streaming and support Time To the First Token (TTFT) latency and Inter-Token Latency (ITL) metrics for gptManagerBenchmark.
    • Added the --max_attention_window option to gptManagerBenchmark.

API Changes

  • [BREAKING CHANGE] Set the default tokens_per_block argument of the trtllm-build command to 64 for better performance.
  • [BREAKING CHANGE] Migrated enc-dec models to the unified workflow.
  • [BREAKING CHANGE] Renamed GptModelConfig to ModelConfig.
  • [BREAKING CHANGE] Added speculative decoding mode to the builder API.
  • [BREAKING CHANGE] Refactor scheduling configurations
    • Unified the SchedulerPolicy with the same name in batch_scheduler and executor, and renamed it to CapacitySchedulerPolicy.
    • Expanded the existing configuration scheduling strategy from SchedulerPolicy to SchedulerConfig to enhance extensibility. The latter also introduces a chunk-based configuration called ContextChunkingPolicy.
  • [BREAKING CHANGE] The input prompt was removed from the generation output in the generate() and generate_async() APIs. For example, when given a prompt as A B, the original generation result could be <s>A B C D E where only C D E is the actual output, and now the result is C D E.
  • [BREAKING CHANGE] Switched default add_special_token in the TensorRT-LLM backend to True.
  • Deprecated GptSession and TrtGptModelV1.

Model Updates

  • Support DBRX
  • Support Qwen2
  • Support CogVLM
  • Support ByT5
  • Support LLaMA 3
  • Support Arctic (w/ FP8)
  • Support Fuyu
  • Support Persimmon
  • Support Deplot
  • Support Phi-3-Mini with long Rope
  • Support Neva
  • Support Kosmos-2
  • Support RecurrentGemma

Fixed Issues

  • Fixed some unexpected behaviors in beam search and early stopping, so that the outputs are more accurate.
  • Fixed segmentation fault with pipeline parallelism and gather_all_token_logits. (#1284)
  • Removed the unnecessary check in XQA to fix code Llama 70b Triton crashes. (#1256)
  • Fixed an unsupported ScalarType issue for BF16 LoRA. (https://github.com/triton-inference-server/tensorrtllm_backend/issues/403)
  • Eliminated the load and save of prompt table in multimodal. (https://github.com/NVIDIA/TensorRT-LLM/discussions/1436)
  • Fixed an error when converting the models weights of Qwen 72B INT4-GPTQ. (#1344)
  • Fixed early stopping and failures on in-flight batching cases of Medusa. (#1449)
  • Added support for more NVLink versions for auto parallelism. (#1467)
  • Fixed the assert failure caused by default values of sampling config. (#1447)
  • Fixed a requirement specification on Windows for nvidia-cudnn-cu12. (#1446)
  • Fixed MMHA relative position calculation error in gpt_attention_plugin for enc-dec models. (#1343)

Infrastructure changes

  • Base Docker image for TensorRT-LLM is updated to nvcr.io/nvidia/pytorch:24.03-py3.
  • Base Docker image for TensorRT-LLM backend is updated to nvcr.io/nvidia/tritonserver:24.03-py3.
  • The dependent TensorRT version is updated to 10.0.1.
  • The dependent CUDA version is updated to 12.4.0.
  • The dependent PyTorch version is updated to 2.2.2.

Currently, there are two key branches in the project:

  • The rel branch is the stable branch for the release of TensorRT-LLM. It has been QA-ed and carefully tested.
  • The main branch is the dev branch. It is more experimental.

We are updating the main branch regularly with new features, bug fixes and performance optimizations. The rel branch will be updated less frequently, and the exact frequencies depend on your feedback.

Thanks, The TensorRT-LLM Engineering Team
