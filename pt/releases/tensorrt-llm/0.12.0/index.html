TensorRT-LLM v0.12.0

Olá, Temos o prazer de anunciar a versão 0.12.0 do TensorRT-LLM. Esta atualização inclui:

Principais recursos e melhorias

  • LoRA compatível para modelos MoE.
  • O ModelWeightsLoader está habilitado para modelos da família LLaMA (experimental), ver docs/source/architecture/model-weights-loader.md.
  • FP8 FMHA compatível para arquitetura NVIDIA Ada Lovelace.
  • Modelos GPT-J, Phi, Phi-3, Qwen, GPT, GLM, Baichuan, Falcon e Gemma suportados para a classe LLM.
  • Suportado FP8 OOTB MoE.
  • Starcoder2 SmoothQuant compatível. (#1886)
  • Decodificação especulativa ReDrafter suportada, consulte a seção “ReDrafter” em docs/source/speculative_decoding.md.
  • Remoção de preenchimento suportada para BERT, graças à contribuição de @Altair-Alpha em #1834.
  • Adicionado suporte de lote em voo para o modelo GLM 10B.
  • Função de ativação gelu_pytorch_tanh suportada, graças à contribuição de @ttim em #1897.
  • Adicionado parâmetro chunk_length ao Whisper, graças à contribuição de @MahmoudAshraf97 em #1909.
  • Adicionado argumento concurrency para gptManagerBenchmark.
  • O executor API suporta solicitações com diferentes larguras de feixe, consulte docs/source/executor.md#sending-requests-with-different-beam-widths.
  • Adicionada a flag --fast_build ao comando trtllm-build (experimental).

Mudanças no API

  • [BREAKING CHANGE] max_output_len é removido do comando trtllm-build, se você deseja limitar o comprimento da sequência no estágio de construção do motor, especifique max_seq_len.
  • [BREAKING CHANGE] O argumento use_custom_all_reduce foi removido de trtllm-build.
  • [BREAKING CHANGE] O argumento multi_block_mode é movido do estágio de construção (trtllm-build e construtor API) para o tempo de execução.
  • [BREAKING CHANGE] O argumento de tempo de construção context_fmha_fp32_acc é movido para tempo de execução para modelos de decodificadores.
  • [BREAKING CHANGE] Os argumentos tp_size, pp_size e cp_size são removidos do comando trtllm-build.
  • O gerenciador de lote C++ API foi descontinuado em favor do C++ executor API e será removido em uma versão futura do TensorRT-LLM.
  • Adicionada uma versão API à biblioteca C++, será gerado um arquivo cpp/include/tensorrt_llm/executor/version.h.

Atualizações de modelo

  • Modelo LLaMA 3.1 compatível.
  • Modelo Mamba-2 compatível.
  • Modelo EXAONE compatível, consulte examples/exaone/README.md.
  • Modelo Qwen 2 compatível.
  • Modelos GLM4 suportados, consulte examples/chatglm/README.md.
  • Adicionado suporte multimodal LLaVa-1.6 (LLaVa-NeXT), consulte a seção “LLaVA, LLaVa-NeXT e VILA” em examples/multimodal/README.md.

Problemas corrigidos

  • Corrigido token de pad errado para os modelos CodeQwen. (#1953)
  • Corrigido erro de digitação em cluster_infos definido em tensorrt_llm/auto_parallel/cluster_info.py, graças à contribuição de @saeyoonoh em #1987.
  • Removidas flags duplicadas no comando em docs/source/reference/troubleshooting.md, obrigado pela contribuição de @hattizai em #1937.
  • Corrigida falha de segmentação na camada de amostragem TopP, graças à contribuição de @akhoroshev em #2039. (#2040)
  • Corrigida a falha ao converter o checkpoint para o modelo Mistral Nemo. (#1985)
  • exclude_modules propagado para quantização apenas de peso, graças à contribuição de @fjosw em #2056.
  • Corrigidos links errados no README, graças à contribuição de @Tayef-Shah em #2028.
  • Corrigidos alguns erros de digitação na documentação, graças à contribuição de @lfz941 em #1939.
  • Corrigida a falha de construção do mecanismo quando deduzido que max_seq_len não é um número inteiro. (#2018)

Mudanças na infraestrutura

  • A imagem base Docker para TensorRT-LLM foi atualizada para nvcr.io/nvidia/pytorch:24.07-py3.
  • A imagem base Docker para o backend TensorRT-LLM foi atualizada para nvcr.io/nvidia/tritonserver:24.07-py3.
  • A versão dependente do TensorRT foi atualizada para 10.3.0.
  • A versão CUDA dependente é atualizada para 12.5.1.
  • A versão dependente do PyTorch foi atualizada para 2.4.0.
    • A versão dependente do ModelOpt é atualizada para v0.15.0.

Problemas conhecidos

  • No Windows, a instalação do TensorRT-LLM pode ser bem-sucedida, mas você pode clicar em OSError: exception: access violation reading 0x0000000000000000 ao importar a biblioteca em Python. Consulte Instalando no Windows para soluções alternativas. Atualmente, existem dois ramos principais no projeto:
  • O branch rel é o branch estável para o lançamento do TensorRT-LLM. Ele foi submetido a controle de qualidade e testado cuidadosamente.
  • O branch principal é o branch dev. É mais experimental. Estamos atualizando o branch main regularmente com novos recursos, correções de bugs e otimizações de desempenho. A ramificação rel será atualizada com menos frequência e as frequências exatas dependem do seu feedback. Obrigado, A equipe de engenharia do TensorRT-LLM

TensorRT-LLM v0.12.0

Highlights

  • Build and runtime configuration migration — trtllm-build no longer accepts max_output_len, use_custom_all_reduce, tp_size, pp_size, or cp_size; use max_seq_len to constrain engine sequence length. multi_block_mode and decoder context_fmha_fp32_acc now belong in runtime configuration, not engine builds. Existing build scripts must be updated accordingly.

  • C++ executor migration — The C++ batch manager API is deprecated in favor of the C++ executor API and will be removed in a future release. Integrations still using the batch manager should migrate now, particularly to benefit from the expanded request-level controls.

  • Expanded model coverage — This release adds LLaMA 3.1, Qwen 2, GLM4, EXAONE, Mamba-2, and LLaVa-1.6/LLaVa-NeXT support, broadening both text and multimodal deployment options. The LLM class additionally supports GPT-J, Phi, Phi-3, Qwen, GPT, GLM, Baichuan, Falcon, and Gemma, reducing the need for model-specific integration code.

  • MoE and FP8 capabilities — LoRA support for MoE models and out-of-the-box FP8 MoE make adapter deployment and quantized expert models more accessible. FP8 FMHA support on Ada Lovelace also extends the hardware options for FP8 attention workloads.

  • More flexible inference and serving — ReDrafter speculative decoding adds another acceleration path, while the Executor API now supports requests with different beam widths, enabling heterogeneous decoding workloads. Whisper’s new chunk_length parameter provides additional control over long-audio processing.

  • Stability fixes and platform refresh — Notable fixes include the TopP sampling segmentation fault (#2040), Mistral Nemo checkpoint conversion (#1985), and non-integer max_seq_len build failures (#2018). The stack now targets TensorRT 10.3.0, CUDA 12.5.1, PyTorch 2.4.0, ModelOpt 0.15.0, and 24.07 containers, so rebuild engines and revalidate custom kernels. Windows imports may still hit an access violation; consult the documented workarounds.

Hi,

We are very pleased to announce the 0.12.0 version of TensorRT-LLM. This update includes:

Key Features and Enhancements

  • Supported LoRA for MoE models.
  • The ModelWeightsLoader is enabled for LLaMA family models (experimental), see docs/source/architecture/model-weights-loader.md.
  • Supported FP8 FMHA for NVIDIA Ada Lovelace Architecture.
  • Supported GPT-J, Phi, Phi-3, Qwen, GPT, GLM, Baichuan, Falcon and Gemma models for the LLM class.
  • Supported FP8 OOTB MoE.
  • Supported Starcoder2 SmoothQuant. (#1886)
  • Supported ReDrafter Speculative Decoding, see “ReDrafter” section in docs/source/speculative_decoding.md.
  • Supported padding removal for BERT, thanks to the contribution from @Altair-Alpha in #1834.
  • Added in-flight batching support for GLM 10B model.
  • Supported gelu_pytorch_tanh activation function, thanks to the contribution from @ttim in #1897.
  • Added chunk_length parameter to Whisper, thanks to the contribution from @MahmoudAshraf97 in #1909.
  • Added concurrency argument for gptManagerBenchmark.
  • Executor API supports requests with different beam widths, see docs/source/executor.md#sending-requests-with-different-beam-widths.
  • Added the flag --fast_build to trtllm-build command (experimental).

API Changes

  • [BREAKING CHANGE] max_output_len is removed from trtllm-build command, if you want to limit sequence length on engine build stage, specify max_seq_len.
  • [BREAKING CHANGE] The use_custom_all_reduce argument is removed from trtllm-build.
  • [BREAKING CHANGE] The multi_block_mode argument is moved from build stage (trtllm-build and builder API) to the runtime.
  • [BREAKING CHANGE] The build time argument context_fmha_fp32_acc is moved to runtime for decoder models.
  • [BREAKING CHANGE] The arguments tp_size, pp_size and cp_size is removed from trtllm-build command.
  • The C++ batch manager API is deprecated in favor of the C++ executor API, and it will be removed in a future release of TensorRT-LLM.
  • Added a version API to the C++ library, a cpp/include/tensorrt_llm/executor/version.h file is going to be generated.

Model Updates

  • Supported LLaMA 3.1 model.
  • Supported Mamba-2 model.
  • Supported EXAONE model, see examples/exaone/README.md.
  • Supported Qwen 2 model.
  • Supported GLM4 models, see examples/chatglm/README.md.
  • Added LLaVa-1.6 (LLaVa-NeXT) multimodal support, see “LLaVA, LLaVa-NeXT and VILA” section in examples/multimodal/README.md.

Fixed Issues

  • Fixed wrong pad token for the CodeQwen models. (#1953)
  • Fixed typo in cluster_infos defined in tensorrt_llm/auto_parallel/cluster_info.py, thanks to the contribution from @saeyoonoh in #1987.
  • Removed duplicated flags in the command at docs/source/reference/troubleshooting.md, thanks for the contribution from @hattizai in #1937.
  • Fixed segmentation fault in TopP sampling layer, thanks to the contribution from @akhoroshev in #2039. (#2040)
  • Fixed the failure when converting the checkpoint for Mistral Nemo model. (#1985)
  • Propagated exclude_modules to weight-only quantization, thanks to the contribution from @fjosw in #2056.
  • Fixed wrong links in README, thanks to the contribution from @Tayef-Shah in #2028.
  • Fixed some typos in the documentation, thanks to the contribution from @lfz941 in #1939.
  • Fixed the engine build failure when deduced max_seq_len is not an integer. (#2018)

Infrastructure Changes

  • Base Docker image for TensorRT-LLM is updated to nvcr.io/nvidia/pytorch:24.07-py3.
  • Base Docker image for TensorRT-LLM Backend is updated to nvcr.io/nvidia/tritonserver:24.07-py3.
  • The dependent TensorRT version is updated to 10.3.0.
  • The dependent CUDA version is updated to 12.5.1.
  • The dependent PyTorch version is updated to 2.4.0.
  • The dependent ModelOpt version is updated to v0.15.0.

Known Issues

  • On Windows, installation of TensorRT-LLM may succeed, but you might hit OSError: exception: access violation reading 0x0000000000000000 when importing the library in Python. See Installing on Windows for workarounds.

Currently, there are two key branches in the project:

  • The rel branch is the stable branch for the release of TensorRT-LLM. It has been QA-ed and carefully tested.
  • The main branch is the dev branch. It is more experimental.

We are updating the main branch regularly with new features, bug fixes and performance optimizations. The rel branch will be updated less frequently, and the exact frequencies depend on your feedback.

Thanks, The TensorRT-LLM Engineering Team
