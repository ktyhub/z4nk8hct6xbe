TensorRT-LLM v0.15.0

Olá, Temos o prazer de anunciar a versão 0.15.0 do TensorRT-LLM. Esta atualização inclui:

Principais recursos e melhorias

  • Adicionado suporte para EAGLE. Consulte examples/eagle/README.md.
  • Adicionado suporte funcional para sistemas GH200.
  • Adicionado suporte AutoQ (precisão mista).
  • Adicionado um comando trtllm-serve para iniciar um servidor baseado em FastAPI.
  • Adicionado suporte FP8 para Nemotron NAS 51B. Consulte examples/nemotron_nas/README.md.
  • Adicionado suporte INT8 para quantização GPTQ.
  • Adicionado suporte nativo TensorRT para INT8 Smooth Quantization.
  • Adicionado suporte de quantização para o modelo Exaone. Consulte examples/exaone/README.md.
  • Medusa habilitada para modelos Qwen2. Consulte a seção “Medusa com Qwen2” em examples/medusa/README.md.
  • Paralelismo de pipeline otimizado com ReduceScatter e AllGather para modelos Mixtral.
  • Adicionado suporte para arquitetura do modelo Qwen2ForSequenceClassification.
  • Adicionado suporte ao plugin Python para simplificar os esforços de desenvolvimento de plugins. Consulte examples/python_plugin/README.md.
  • Adicionado suporte a diferentes dimensões de classificação para módulos LoRA ao usar o formato Hugging Face. Obrigado pela contribuição de @AlessioNetti em #2366.
  • Compartilhamento de incorporação ativado por padrão. Consulte a seção "Incorporando Paralelismo, Compartilhamento de Incorporação e Plug-in de Pesquisa" em docs/source/performance/perf-best-practices.md para obter informações sobre as condições necessárias para incorporar compartilhamento.
  • Adicionado suporte para FP8 por token por canal (ou seja, FP8 por linha) no Ada.
  • Estendido o máximo suportado de beam_width para 256.
  • Adicionado suporte de quantização FP8 e INT8 SmoothQuant para a variante InternVL2-4B (somente modelo LLM). Consulte examples/multimodal/README.md.
  • Adicionado suporte para decodificação especulativa de pesquisa imediata. Consulte examples/prompt_lookup/README.md.
  • Integração da quantização QServe w4a8 por grupo/por canal. Consulte a seção “quantização w4aINT8 (QServe)” em examples/llama/README.md.
  • Adicionado um exemplo C++ para logits rápidos usando o executor API. Consulte a seção “executorExampleFastLogits” em examples/cpp/executor/README.md.
  • [BREAKING CHANGE] O suporte à GPU NVIDIA Volta foi removido nesta e em versões futuras.
  • Adicionadas as seguintes melhorias ao LLM API:
    • [BREAKING CHANGE] Movida a inicialização do tempo de execução da primeira invocação de LLM.generate para LLM.__init__ para melhor desempenho de geração sem aquecimento.
    • Adicionados argumentos n e best_of à classe SamplingParams. Esses argumentos permitem o retorno de múltiplas gerações para uma única solicitação.
    • Adicionados argumentos ignore_eos, detokenize, skip_special_tokens, spaces_between_special_tokens e truncate_prompt_tokens à classe SamplingParams. Esses argumentos permitem mais controle sobre o comportamento do tokenizer.
    • Adicionado suporte para destokenização incremental para melhorar o desempenho de destokenização para geração de streaming.
    • Adicionado o argumento enable_prompt_adapter à classe LLM e o argumento prompt_adapter_request ao método LLM.generate. Esses argumentos permitem o ajuste imediato.
  • Adicionado suporte para um argumento gpt_variant ao arquivo examples/gpt/convert_checkpoint.py. Esse aprimoramento permite a conversão de pontos de verificação com mais variantes de modelo GPT. Obrigado à contribuição de @tonylek em #2352.

Mudanças no API

  • [BREAKING CHANGE] Movida a flag builder_force_num_profiles no comando trtllm-build para a variável de ambiente BUILDER_FORCE_NUM_PROFILES.
  • [BREAKING CHANGE] Modificados os padrões da classe BuildConfig para que fiquem alinhados com o comando trtllm-build.
  • [BREAKING CHANGE] Removidas as ligações Python de GptManager.
  • [BREAKING CHANGE] auto é usado como o valor padrão para a opção --dtype em scripts de quantização e conversão de pontos de verificação.
  • [BREAKING CHANGE] Caminho gptManager API obsoleto em gptManagerBenchmark.
    • [BREAKING CHANGE] Obsoletos os argumentos beam_width e num_return_sequences para a classe SamplingParams no LLM API. Use os argumentos n, best_of e use_beam_search.
    • Argumento --trust_remote_code exposto ao servidor OpenAI API. (#2357)

Atualizações de modelo

  • Adicionado suporte para os modelos Llama 3.2 e Lhama 3.2-Vision. Consulte examples/mllama/README.md para obter mais detalhes sobre o modelo lhama 3.2-Vision.
  • Adicionado suporte para Deepseek-v2. Consulte examples/deepseek_v2/README.md.
  • Adicionado suporte para modelos Cohere Command R. Consulte examples/commandr/README.md.
  • Adicionado suporte para Falcon 2, consulte examples/falcon/README.md, graças à contribuição de @puneeshkhanna em #1926.
  • Adicionado suporte para InternVL2. Consulte examples/multimodal/README.md.
  • Adicionado suporte para os modelos Qwen2-0.5B e Qwen2.5-1.5B. (#2388)
  • Adicionado suporte para Minitron. Consulte examples/nemotron.
  • Adicionada uma variante GPT - Granito (20B e 34B). Consulte a seção “Variante GPT - Granito” em examples/gpt/README.md.
  • Adicionado suporte para o modelo LLaVA-OneVision. Consulte a seção “LLaVA, LLaVa-NeXT, LLaVA-OneVision e VILA” em examples/multimodal/README.md.

Problemas corrigidos

  • Corrigido um erro de fatia na função forward. (#1480)
  • Corrigido um problema que aparecia ao construir o BERT. (#2373)
  • Corrigido um problema em que o modelo não era carregado durante a construção do BERT. (2379)
  • Corrigidos os exemplos de executores quebrados. (#2294)
  • Corrigido o problema em que o kernel moeTopK() não consegue encontrar o especialista correto quando o número de especialistas não é uma potência de dois. Obrigado @dongjiyingdjy por relatar este bug.
  • Corrigida uma falha de asserção em crossKvCacheFraction. (#2419)
  • Corrigido um problema ao usar smoothquant para quantizar o modelo Qwen2. (#2370)
  • Corrigido um erro de digitação no PDL em docs/source/performance/perf-benchmarking.md, obrigado @MARD1NO por apontar isso em #2425.

Mudanças na infraestrutura

  • A imagem base Docker para TensorRT-LLM é atualizada para nvcr.io/nvidia/pytorch:24.10-py3.
  • A imagem base Docker para TensorRT-LLM Backend foi atualizada para nvcr.io/nvidia/tritonserver:24.10-py3.
  • A versão dependente do TensorRT foi atualizada para 10.6.
  • A versão CUDA dependente é atualizada para 12.6.2.
  • A versão dependente do PyTorch foi atualizada para 2.5.1.
  • A versão dependente do ModelOpt é atualizada para 0.19 para plataforma Linux, enquanto 0.17 ainda é usado na plataforma Windows.

Documentação

  • Adicionado um botão de cópia para trechos de código na documentação. (#2288) Estamos atualizando o branch main regularmente com novos recursos, correções de bugs e otimizações de desempenho. A ramificação rel será atualizada com menos frequência e as frequências exatas dependem do seu feedback. Obrigado, A equipe de engenharia do TensorRT-LLM

TensorRT-LLM v0.15.0

Highlights

  • Hardware and stack requirements move forward — Volta GPU support is removed. The stack now targets CUDA 12.6.2, TensorRT 10.6, PyTorch 2.5.1, and updated 24.10 container images; verify driver compatibility and rebuild or refresh custom images before upgrading.

  • Inference serving is now first-class — The new trtllm-serve command launches a FastAPI-based server, and the OpenAI-compatible server exposes --trust_remote_code (#2357). This lowers setup friction, but enabling remote code is appropriate only for trusted model repositories.

  • Sampling and streaming APIs change — Runtime initialization moves from the first LLM.generate() call into LLM.__init__, eliminating first-generation warmup. Replace deprecated beam_width and num_return_sequences with n, best_of, and use_beam_search; new controls for EOS handling, detokenization, special tokens, and prompt truncation provide finer output management. Incremental detokenization improves streaming performance.

  • Speculative decoding gains multiple paths — EAGLE, prompt-lookup decoding, and Medusa for Qwen2 broaden options for reducing generation latency. These are model-dependent capabilities, so confirm checkpoints and supported configurations in the respective example READMEs rather than assuming a drop-in speedup.

  • Quantization and serving topology expand — AutoQ mixed precision, INT8 GPTQ and native TensorRT SmoothQuant, Ada row-wise FP8, and QServe w4a8 support widen deployment choices. Mixtral pipeline parallelism now uses ReduceScatter/AllGather, which may improve throughput, so re-benchmark existing deployments rather than assuming identical performance.

Hi,

We are very pleased to announce the 0.15.0 version of TensorRT-LLM. This update includes:

Key Features and Enhancements

  • Added support for EAGLE. Refer to examples/eagle/README.md.
  • Added functional support for GH200 systems.
  • Added AutoQ (mixed precision) support.
  • Added a trtllm-serve command to start a FastAPI based server.
  • Added FP8 support for Nemotron NAS 51B. Refer to examples/nemotron_nas/README.md.
  • Added INT8 support for GPTQ quantization.
  • Added TensorRT native support for INT8 Smooth Quantization.
  • Added quantization support for Exaone model. Refer to examples/exaone/README.md.
  • Enabled Medusa for Qwen2 models. Refer to “Medusa with Qwen2” section in examples/medusa/README.md.
  • Optimized pipeline parallelism with ReduceScatter and AllGather for Mixtral models.
  • Added support for Qwen2ForSequenceClassification model architecture.
  • Added Python plugin support to simplify plugin development efforts. Refer to examples/python_plugin/README.md.
  • Added different rank dimensions support for LoRA modules when using the Hugging Face format. Thanks for the contribution from @AlessioNetti in #2366.
  • Enabled embedding sharing by default. Refer to "Embedding Parallelism, Embedding Sharing, and Look-Up Plugin" section in docs/source/performance/perf-best-practices.md for information about the required conditions for embedding sharing.
  • Added support for per-token per-channel FP8 (namely row-wise FP8) on Ada.
  • Extended the maximum supported beam_width to 256.
  • Added FP8 and INT8 SmoothQuant quantization support for the InternVL2-4B variant (LLM model only). Refer to examples/multimodal/README.md.
  • Added support for prompt-lookup speculative decoding. Refer to examples/prompt_lookup/README.md.
  • Integrated the QServe w4a8 per-group/per-channel quantization. Refer to “w4aINT8 quantization (QServe)” section in examples/llama/README.md.
  • Added a C++ example for fast logits using the executor API. Refer to “executorExampleFastLogits” section in examples/cpp/executor/README.md.
  • [BREAKING CHANGE] NVIDIA Volta GPU support is removed in this and future releases.
  • Added the following enhancements to the LLM API:
    • [BREAKING CHANGE] Moved the runtime initialization from the first invocation of LLM.generate to LLM.__init__ for better generation performance without warmup.
    • Added n and best_of arguments to the SamplingParams class. These arguments enable returning multiple generations for a single request.
    • Added ignore_eos, detokenize, skip_special_tokens, spaces_between_special_tokens, and truncate_prompt_tokens arguments to the SamplingParams class. These arguments enable more control over the tokenizer behavior.
    • Added support for incremental detokenization to improve the detokenization performance for streaming generation.
    • Added the enable_prompt_adapter argument to the LLM class and the prompt_adapter_request argument for the LLM.generate method. These arguments enable prompt tuning.
  • Added support for a gpt_variant argument to the examples/gpt/convert_checkpoint.py file. This enhancement enables checkpoint conversion with more GPT model variants. Thanks to the contribution from @tonylek in #2352.

API Changes

  • [BREAKING CHANGE] Moved the flag builder_force_num_profiles in trtllm-build command to the BUILDER_FORCE_NUM_PROFILES environment variable.
  • [BREAKING CHANGE] Modified defaults for BuildConfig class so that they are aligned with the trtllm-build command.
  • [BREAKING CHANGE] Removed Python bindings of GptManager.
  • [BREAKING CHANGE] auto is used as the default value for --dtype option in quantize and checkpoints conversion scripts.
  • [BREAKING CHANGE] Deprecated gptManager API path in gptManagerBenchmark.
  • [BREAKING CHANGE] Deprecated the beam_width and num_return_sequences arguments to the SamplingParams class in the LLM API. Use the n, best_of and use_beam_search arguments instead.
  • Exposed --trust_remote_code argument to the OpenAI API server. (#2357)

Model Updates

  • Added support for Llama 3.2 and llama 3.2-Vision model. Refer to examples/mllama/README.md for more details on the llama 3.2-Vision model.
  • Added support for Deepseek-v2. Refer to examples/deepseek_v2/README.md.
  • Added support for Cohere Command R models. Refer to examples/commandr/README.md.
  • Added support for Falcon 2, refer to examples/falcon/README.md, thanks to the contribution from @puneeshkhanna in #1926.
  • Added support for InternVL2. Refer to examples/multimodal/README.md.
  • Added support for Qwen2-0.5B and Qwen2.5-1.5B model. (#2388)
  • Added support for Minitron. Refer to examples/nemotron.
  • Added a GPT Variant - Granite(20B and 34B). Refer to “GPT Variant - Granite” section in examples/gpt/README.md.
  • Added support for LLaVA-OneVision model. Refer to “LLaVA, LLaVa-NeXT, LLaVA-OneVision and VILA” section in examples/multimodal/README.md.

Fixed Issues

  • Fixed a slice error in forward function. (#1480)
  • Fixed an issue that appears when building BERT. (#2373)
  • Fixed an issue that model is not loaded when building BERT. (2379)
  • Fixed the broken executor examples. (#2294)
  • Fixed the issue that the kernel moeTopK() cannot find the correct expert when the number of experts is not a power of two. Thanks @dongjiyingdjy for reporting this bug.
  • Fixed an assertion failure on crossKvCacheFraction. (#2419)
  • Fixed an issue when using smoothquant to quantize Qwen2 model. (#2370)
  • Fixed a PDL typo in docs/source/performance/perf-benchmarking.md, thanks @MARD1NO for pointing it out in #2425.

Infrastructure Changes

  • The base Docker image for TensorRT-LLM is updated to nvcr.io/nvidia/pytorch:24.10-py3.
  • The base Docker image for TensorRT-LLM Backend is updated to nvcr.io/nvidia/tritonserver:24.10-py3.
  • The dependent TensorRT version is updated to 10.6.
  • The dependent CUDA version is updated to 12.6.2.
  • The dependent PyTorch version is updated to 2.5.1.
  • The dependent ModelOpt version is updated to 0.19 for Linux platform, while 0.17 is still used on Windows platform.

Documentation

  • Added a copy button for code snippets in the documentation. (#2288)

We are updating the main branch regularly with new features, bug fixes and performance optimizations. The rel branch will be updated less frequently, and the exact frequencies depend on your feedback.

Thanks, The TensorRT-LLM Engineering Team
