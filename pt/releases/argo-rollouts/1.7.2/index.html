argo-rollouts v1.7.2

Highlights

  • Scale-down fixes and a required RBAC update — Two coupled changes (#3762/#3784, #3675) address replica sets refusing to scale down because of stale annotations and a missing update verb on the controller's ClusterRole for the scaleDown feature (#3672). This is the one real migration step in the release: if you use progressive traffic scaling, upgrading the controller alone is insufficient — re-apply the ClusterRole manifest or scale-down will still be denied.
  • Analysis now honors the rollback window (#3670, fixes #3669) — AnalysisRun reconciliation takes RollbackWindow into account, so a failed analysis no longer triggers a rollback outside the configured window. If you gate rollbacks by time via AnalysisTemplate/AnalysisRun, this changes when a failing canary is actually aborted — verify your window definitions after upgrading.
  • Datadog provider API correctness (#3730) — The last aggregator is now set explicitly only on the Datadog v2 path; v1 queries are left untouched. Teams that saw malformed or rejected metric queries on v1 after earlier aggregator changes should see them resolve, while v2 users get deterministic aggregation semantics.
  • Native sidecar support in the dashboard (#3639, fixes #3366) — Pod status logic now understands Kubernetes restartable init containers (native sidecars, GA in 1.29). On clusters where a service mesh or agent injects sidecars, the dashboard will report correct pod state instead of marking healthy pods as pending/not-ready.
  • Controller fixes for Traefik routing and stable RS selection (#3759 fixing #3615, and #3664) — The controller now resolves the correct resourceName for traefik.io traffic objects and reads stableRS from the rollout context rather than a stale source. If you route canaries through Traefik or depend on accurate stable/canary replica weighting, these eliminate silent misrouting and bad scaling decisions present in earlier patches.
  • Less connection churn from metric polling (#3780) — The HTTP metric provider reuses a single http.Transport across requests instead of building new clients per poll. With many AnalysisRuns at high frequency, this reduces socket/file-descriptor churn and TCP handshake overhead — relevant if you've observed FD pressure or latency spikes in the controller.

No breaking changes in this release.

  • analysis: Take RollbackWindow into account when Reconciling Analysis Runs. Fixes #3669 (#3670)
  • controller: Get the right resourceName for traefik.io.Fixes #3615 (#3759)
  • controller: use the stableRS from the rollout context rather tha… (#3664)
  • dashboard: Update pod status logic to support native sidecars. Fixes #3366 (#3639)
  • metricprovider: reuse http.Transport for http.Client (#3780)
