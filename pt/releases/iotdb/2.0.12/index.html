#iotdb v2.0.12

Recursos e melhorias

Prevenção de injeção de SQL: Refatoração do PreparedStatement do modelo de tabela para evitar injeção de SQL Gerenciamento de cluster: Suporte à implantação de cluster IPv6 REST: REST API suporta a configuração do fuso horário client Sincronização de dados: desempenho de filtragem otimizado para colunas TAG não-primeiras no modelo de tabela Ferramentas de importação/exportação de dados: Estratégia de degradação para arquivos de carga Gerenciamento de banco de dados: SHOW CREATE DATABASE/TOPIC/PIPE Computação - Execução de consulta - Cláusulas SQL: Otimize a mensagem de erro quando uma consulta select * tiver muitas colunas Funções: Adicionada função de análise de tempo-frequência (FFT) Funções: Adicionadas funções de filtragem (HighPass, LowPass) Cache de pontos mais recente: O cache de pontos mais recente suporta ativação/desativação na granularidade de tabela/banco de dados Funções: Funções agregadas de taxa/aumento/iragem/delta integradas para o modelo de tabela Funções: Função de correlação de sequência adicionada (XCorr) Funções: Função integrada com valor de tabela M4 Funções: Função com valor de tabela de correspondência de tendência de série temporal Funções: foi adicionada a função integrada com valor de tabela read_tsfile, que dá suporte à consulta direta de um arquivo tsfile especificado usando SQL Metadados do modelo de árvore: ao criar uma nova série temporal em um dispositivo existente, ignore os atributos alinhados/não alinhados especificados na instrução create e use os atributos alinhados/não alinhados do dispositivo atual em vez de relatar um erro Medição: Otimizou o resultado da validação da Medição durante gravações de cache Exclusão de granularidade do dispositivo: foi corrigido um problema em que, após excluir uma tabela com uma grande quantidade de dados e, em seguida, recriar a tabela e gravar dados, a consulta dessa tabela apresentava alta latência Otimização de memória: Otimização de memória ao copiar a memtable TVList durante consultas Pipe Data Sync: Otimizou o algoritmo de correspondência para ** Metadados do modelo de árvore: Adicionado um sinalizador booleano aos nós do dispositivo indicando se há outros dispositivos abaixo e ajustado a consulta select measurement from xxx.** Cláusulas SQL: Otimização de desempenho para tabela completa order by time + limit no modelo de tabela Cláusulas SQL: Otimização de memória para consultas de tabela completa no modelo de tabela Sincronização de dados do Pipe: Algoritmo de expansão/contração do bloco de memória do Pipe otimizado

Erros

Mesclagem de arquivos on-line: Corrigido um problema em que show disk_usage fazia a mesclagem travar Metadados do modelo de árvore: Corrigido o problema de "banco de dados sem correspondência" Sincronização de dados: Suporte para armazenar o progresso do ponto de verificação de análise do TsFile, para que, na nova tentativa após falha, não haja necessidade de analisar novamente o arquivo inteiro Escrita Básica: Foi corrigido um problema em que, para o mesmo dispositivo alinhado, primeiro escrever uma solicitação com menos colunas e mais linhas e, em seguida, escrever uma solicitação com mais colunas e uma linha gerava um WAL que, ao reiniciar o DataNode, causava uma expansão severa do valor nulo da memtable e, por fim, fazia com que a reinicialização do DataNode travasse Sincronização de TsFile: Ao carregar um tsfile, modifique a lógica de comparação do conjunto de réplicas: ao comparar conjuntos de réplicas, não se preocupe mais com a ordem da lista, compare apenas se os elementos dentro dos conjuntos são exatamente idênticos; alterar a comparação da lista para uma comparação definida Sincronização de dados do Pipe: Foi corrigido um problema em que o Pipe gerava um NPE para pontos de medição nulos ao converter uma gravação de inserção parcial em um tablet Sincronização de dados do Pipe: Corrigido um problema em que o Pipe parava após um tempo limite de análise do tsfile Mesclagem de arquivos on-line: Foi corrigido um problema em que a mesclagem não voltava à cópia quando a criação de links físicos falhava Pipe Data Sync: Adicionados limites de cota de memória independente por Pipe ou agendamento justo Pipe Data Sync: Backoff exponencial implementado e proteção de disjuntor para cenários em que o disco está cheio ou o receptor está indisponível Pipe Data Sync: Adicionados limites globais e por Pipe em TsFiles em voo Pipe Data Sync: Corrigido um problema em que drop pipe não esperava pelo retorno do coletor Ferramentas de importação/exportação de dados: Corrigido um erro ao executar tsfile load enquanto um banco de dados nomeado com um prefixo root. já existia Metadados do modelo de tabela: Otimizou o tratamento de caracteres especiais escapados com crases em visualizações de tabela Sincronização de dados do Pipe: Ao excluir um Pipe, ocorrem processos assíncronos (por exemplo, recuperação); o resultado da execução assíncrona precisa ser comunicado ao usuário Pipe Data Sync: Drop pipe não espera mais pelo retorno do coletor, garantindo a remoção completa do Pipe Sincronização de dados do Pipe: Foi corrigido o atraso na parte do atribuidor ao executar comandos de criação/iniciação/parada/exclusão do Pipe Sincronização de dados do Pipe: Corrigido o problema de registro excessivo, reduzindo a quantidade de registros no lado do receptor do Pipe Pipe Data Sync: Corrigido um problema em que a divisão de um tsfile em 1.3.x para sincronizar dados parciais com 2.x falhava

iotdb v2.0.12

Features & Improvements

SQL Injection Prevention: Refactored the table model's PreparedStatement to prevent SQL injection Cluster Management: Support IPv6 cluster deployment REST: REST API supports setting the client timezone Data Sync: Optimized filtering performance for non-first TAG columns in the table model Data Import/Export Tools: Degradation strategy for Load files Database Management: SHOW CREATE DATABASE/TOPIC/PIPE Computation - Query Execution - SQL Clauses: Optimize the error message when a select * query has too many columns Functions: Added time-frequency analysis function (FFT) Functions: Added filtering functions (HighPass, LowPass) Latest Point Cache: The latest point cache supports being enabled/disabled at table/database granularity Functions: Built-in rate/increase/irate/delta aggregate functions for the table model Functions: Added sequence correlation function (XCorr) Functions: Built-in M4 table-valued function Functions: Time-series trend matching table-valued function Functions: Added the built-in table-valued function read_tsfile, supporting direct querying from a specified tsfile using SQL Tree Model Metadata: When creating a new time series under an existing device, ignore the aligned/unaligned attributes specified in the create statement and use the current device's aligned/unaligned attributes instead of reporting an error Measurement: Optimized the validation result of Measurement during cache writes Device-Granularity Deletion: Fixed an issue where, after deleting a table with a large amount of data and then re-creating the table and writing data, querying that table had high latency Memory Optimization: Memory optimization when copying the memtable TVList during queries Pipe Data Sync: Optimized the matching algorithm for ** Tree Model Metadata: Added a boolean flag to device nodes indicating whether there are other devices below, and tuned the query select measurement from xxx.** SQL Clauses: Performance optimization for full-table order by time + limit in the table model SQL Clauses: Memory optimization for full-table queries in the table model Pipe Data Sync: Optimized the Pipe memory block expansion/contraction algorithm

Bugs

Online File Merge: Fixed an issue where show disk_usage caused the merge to hang Tree Model Metadata: Fixed the "no matched database" issue Data Sync: Support storing TsFile parsing checkpoint progress, so that on retry after failure there is no need to re-parse the entire file Basic Write: Fixed an issue where, for the same aligned device, first writing a request with fewer columns and more rows and then writing a request with more columns and one row generated a WAL that, upon restarting the DataNode, caused severe memtable null-value expansion and ultimately caused the DataNode restart to hang TsFile Sync: When loading a tsfile, modify the replica set comparison logic: when comparing replica sets, no longer care about list order, only compare whether the elements within the sets are exactly identical; change the list comparison to a set comparison Pipe Data Sync: Fixed an issue where Pipe threw an NPE for null measurement points when converting a partial insert write into a tablet Pipe Data Sync: Fixed an issue where Pipe stopped after a tsfile parsing timeout Online File Merge: Fixed an issue where the merge did not fall back to copying when creating hard links failed Pipe Data Sync: Added per-Pipe independent memory quota limits or fair scheduling Pipe Data Sync: Implemented exponential backoff and circuit breaker protection for scenarios where the disk is full or the receiver is unavailable Pipe Data Sync: Added global and per-Pipe limits on in-flight TsFiles Pipe Data Sync: Fixed an issue where drop pipe did not wait for the sink's return Data Import/Export Tools: Fixed an error when executing tsfile load while a database named with a root. prefix already exists Table Model Metadata: Optimized the handling of special characters escaped with backticks in table views Pipe Data Sync: When deleting a Pipe there are asynchronous processes (e.g., recover); the asynchronous execution result needs to be communicated to the user Pipe Data Sync: Drop pipe no longer waits for the sink's return, ensuring complete removal of the Pipe Pipe Data Sync: Fixed the lag in the assigner portion when executing Pipe create/start/stop/delete commands Pipe Data Sync: Fixed the excessive logging issue by reducing the amount of logs on the Pipe receiver side Pipe Data Sync: Fixed an issue where splitting a tsfile in 1.3.x to sync partial data to 2.x failed
