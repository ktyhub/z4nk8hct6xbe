parlant v4.0.6

[4.0.6] - 2026-11-16

Ajouté

  • parlant lint lint un projet d'agent Parlant via votre agent de codage. Il imprime les instructions pour l'agent de codage : quels chapitres de charpie exécuter, chacun dans son propre sous-agent (parlant lint --section SECTION --chapter CHAPTER imprime un règles du chapitre) et comment traiter les résultats par gravité. Les résultats ÉLEVÉS sont résolu immédiatement, au maximum 3 types de problèmes MOYEN sont proposés par tour, et FAIBLES seulement avec votre OK. Les premières sections sont le comportement (observations qui combinent plusieurs situations, qu'elles soient alternatives ou qui doivent toutes tenir) et la formulation et le ton de la voix (en conserve réponses plutôt que de formuler des politiques ou des instructions). Chaque règle a un ID, tel que BHV001, qui reste le même d'une version à l'autre.
  • parlant init installe désormais un hook de pré-push git (.githooks/pre-push, set via core.hooksPath) qui arrête un push jusqu'à ce que le commit soit linté, et l'échafaudage AGENTS.md indique à l'agent de codage d'exécuter parlant lint avant chaque poussée. Après le linting et la validation des correctifs, parlant lint --done records the commit so the push goes through; git push --no-verify saute le crochet. Un clone du projet active le hook avec git config core.hooksPath .githooks. --no-git n'installe aucun crochet.
  • parlant dashboard agent cards AGENT_ID DESTINATION écrit chaque fichier de votre le site sert à ce que les agents IA personnels trouvent votre agent, dans DESTINATION/.well-known : agent-card.json pour A2A, et poppy.json et poppy-0.4.json pour Poppy, le Protocole d'agent personnel utilisé par Meta Muse et Shopify. --no-a2a et --no-poppy laisse une famille de côté. Les documents Poppy nécessitent l'ensemble du site de l'agent dans le Dashboard, puisque Poppy identifie une entreprise par son domaine ; sans cela le la commande écrit la carte et le dit. parlant dashboard agent view affiche le l'ADRESSE POPPY de l'agent et parlant widget init pointe vers la nouvelle commande. parlant dashboard agent card imprime toujours la carte A2A seule pour les plus anciennes instructions.
  • Le onPathChanged(path, notifyAgent) du widget de chat indique à l'agent quelle page le visiteur est allumé. Il est appelé lorsque le widget se charge et lorsque le chemin change sans rechargement ; notifyAgent(path, data?) ajoute un événement personnalisé ({ type: "page_view", page: path, ...data }, source customer_ui) qui ne démarre pas une réponse. Une nouvelle conversation l'obtient avant toute autre chose, afin que l'agent puisse le savoir une question posée sur votre page de tarification parmi celle posée sur votre page d'accueil.

Modifié

  • En cas d'effort élevé de l'agent, l'élagage des règles découvertes précédemment est désormais par défaut raisonnement de modèle faible, classement des règles de correspondance. Raisonnement explicite modèle-itinéraire les paramètres sont toujours prioritaires.
  • Lorsqu'une politique en entraîne une autre, la politique qu'elle implique est désormais jugée avec le les politiques qui l’impliquent en vue. Cela aide lorsque sa formulation repose sur le leur, comme « le module complémentaire » défini par une autre politique. Ça correspond toujours ses propres mérites, et l'implication fonctionne comme avant : lorsqu'une politique impliquant correspond, celui impliqué est également activé.
  • Les invités et les clients connectés peuvent ajouter des événements personnalisés à leurs propres sessions, avec la source customer_ui, jusqu'à 4 Ko de données et 30 par minute. Jusqu'à maintenant seulement le backend le pouvait, donc un site devait relayer les pages vues via son propre serveur avec la clé admin. D'autres sources ont toujours besoin de la clé d'administration ; une autorisation personnalisée la porte qui n'accorde pas CREATE_CUSTOM_EVENT continue de les refuser. PARLANT_CUSTOMER_UI_EVENT_MAX_BYTES modifie la limite de taille (4096 par défaut).
  • Un widget de chat avec un avatar vidéo déplace désormais la vidéo dans un cercle à côté le nom de l'agent une fois la conversation défilée, et l'espace qu'elle laisse se ferme. Faire défiler vers le haut le ramène. L'en-tête conserve son hauteur et disparaît sur les messages situés sous le cercle. Le nom et les sous-titres disparaissent pendant que la vidéo bouge et reviennent à côté du cercle, le sous-titre sous le nom. Un avatar photo a désormais la même taille que l'avatar ancré cercle, et son en-tête disparaît également sur les messages en dessous. Faire défiler vers le haut dans le widget n'est plus redescendu lors d'une courte conversation, et l'envoi d'un message y apporte la vue. Sur les téléphones, le widget affiche uniquement le cercle, qui est recadré sur le visage. par le paramètre launcher de l'avatar. Votre projet conserve la copie parlant widget init fabriqué. Pour récupérer ça, cours parlant widget init --force, qui remplace cette copie et toutes les modifications que vous fait à cela.
  • Avec Gemini comme fournisseur, répond à un effort moyen, élevé et maximum et les deux les contrôles d'examen s'exécutent désormais sur Gemini 4 Hydrogen au lieu de Gemini 3.8 Flash. Moyen l'effort maintient un raisonnement faible. Sur un agent de site Web, cela réduit les réponses de 15 à 30 secondes à 6-8, et Hydrogen a gardé son raisonnement en dehors des réponses où 3.8 Flash au raisonnement bas, je l'avais écrit en un seul. Un effort minimal et faible reste actif Flash Lite. Un itinéraire react ou review.* que vous avez défini reste inchangé. À conserver l'ancien modèle, l'acheminer explicitement, par ex. "react": p.ModelConfig("gemini:gemini-3.8-flash", reasoning="low").
  • La valeur par défaut de LiteLLM pour les deux contrôles de révision est désormais gemini/gemini-4-hydrogen au lieu de gemini/gemini-3.8-flash.

Corrigé

  • Une observation avec un titre mais sans note n'apparaît plus dans la fiche de l'agent instructions sous forme d'entrée vide (son titre suivi de "Détails : [Aucun]", sans son état). Une règle atteint désormais l'invite de l'agent uniquement lorsqu'elle dit quelque chose : son contenu (une note d'observation, une action politique), ou les outils qu'il rend pertinents, auquel cas son état est affiché même lorsque il a un titre. Les règles sans contenu sont également exclues de la note selon laquelle indique à l'agent quelles instructions ont perdu la priorité ce tour-ci. Observations sans note, continuez à travailler sur les relations, la portée des réponses prédéfinies et correspondance ; ils ne coûtent tout simplement aucun jeton d'invite.
  • Les étendues de journalisation se déroulent désormais après les exceptions et les annulations, donc les journaux plus tard dans la même tâche, ne conservez pas les étiquettes de composants obsolètes.
  • Le widget de chat centre sa clause de non-responsabilité et "Powered by Parlant" sous l'entrée sur les téléphones.
  • Le widget de chat n'affiche plus "↓ Nouveaux messages" dans un chat vide ou court que le le visiteur a fait défiler vers le haut. La pilule n'apparaît désormais que lorsqu'il y a quelque chose ci-dessous vers lequel accéder.
  • Le widget de chat ne termine plus une réponse terminée avec un * parasite. Une réponse avec un nombre impair de balles * utilisées pour en obtenir une après son dernier mot. À moitié tapé Les caractères gras et italiques se ferment toujours pendant qu'une réponse est diffusée. Pour récupérer ceci et le d'autres correctifs de widgets, exécutez parlant widget init --force, qui remplace votre la copie du projet du widget et toutes les modifications que vous y avez apportées.
  • Un niveau de raisonnement posé sur un modèle Gemini 4 dans un parcours schématique, tel que "review.*": p.ModelConfig("gemini:gemini-4-hydrogen", reasoning="high"), c'est maintenant envoyé aux Gémeaux. Auparavant, il était abandonné, le modèle pensait donc selon ses propres valeurs par défaut.
  • La pertinence des réponses standardisées prend désormais en compte les correspondances de chaque segment de requête auparavant sélectionner les réponses les plus proches, en conservant le meilleur score de correspondance de chaque réponse.

parlant v4.0.6

[4.0.6] - 2026-11-16

Added

  • parlant lint lints a Parlant agent project through your coding agent. It prints instructions for the coding agent: which lint chapters to run, each in its own subagent (parlant lint --section SECTION --chapter CHAPTER prints a chapter's rules), and how to handle findings by severity. HIGH findings are fixed right away, at most 3 MEDIUM issue types are proposed per round, and LOW ones only with your OK. The first sections are Behavior (observations that combine several situations, whether alternatives or ones that must all hold) and Wording and Tone of Voice (canned responses rather than wording in policies or instructions). Every rule has an ID, such as BHV001, that stays the same across releases.
  • parlant init now installs a git pre-push hook (.githooks/pre-push, set through core.hooksPath) that stops a push until the commit has been linted, and the scaffolded AGENTS.md tells the coding agent to run parlant lint before every push. After linting and committing the fixes, parlant lint --done records the commit so the push goes through; git push --no-verify skips the hook. A clone of the project turns the hook on with git config core.hooksPath .githooks. --no-git installs no hook.
  • parlant dashboard agent cards AGENT_ID DESTINATION writes every file your site serves so personal AI agents find your agent, into DESTINATION/.well-known: agent-card.json for A2A, and poppy.json and poppy-0.4.json for Poppy, the Personal Agent Protocol that Meta Muse and Shopify use. --no-a2a and --no-poppy leave a family out. The Poppy documents need the agent's site set in the Dashboard, since Poppy identifies a business by its domain; without it the command writes the card and says so. parlant dashboard agent view shows the agent's POPPY ADDRESS, and parlant widget init points at the new command. parlant dashboard agent card still prints the A2A card alone for older instructions.
  • The chat widget's onPathChanged(path, notifyAgent) tells the agent which page the visitor is on. It's called when the widget loads and when the path changes without a reload; notifyAgent(path, data?) adds a custom event ({ type: "page_view", page: path, ...data }, source customer_ui) that doesn't start a reply. A new conversation gets it before anything else, so the agent can tell a question asked on your pricing page from one asked on your home page.

Changed

  • At high agent effort, pruning previously discovered rules now defaults to low model reasoning, matching rule ranking. Explicit model-route reasoning settings still take precedence.
  • When one policy entails another, the entailed policy is now judged with the policies that entail it in view. This helps when its wording relies on theirs, such as "the add-on" that another policy defines. It still matches on its own merits, and entailment works as before: when an entailing policy matches, the entailed one is activated too.
  • Guests and signed-in customers may add custom events to their own sessions, with source customer_ui, up to 4 KB of data and 30 a minute. Until now only the backend could, so a site had to relay page views through its own server with the admin key. Other sources still need the admin key; a custom permission gate that doesn't grant CREATE_CUSTOM_EVENT keeps refusing them. PARLANT_CUSTOMER_UI_EVENT_MAX_BYTES changes the size limit (4096 by default).
  • A chat widget with a video avatar now moves the video into a circle beside the agent's name once the conversation scrolls, and the space it leaves closes up. Scrolling up past the top brings it back. The header keeps its height and fades out over the messages below the circle. The name and subtitle fade out while the video moves and back in beside the circle, the subtitle under the name. A photo avatar is now the same size as the docked circle, and its header fades out over the messages below it too. Scrolling up in the widget no longer gets pulled back down in a short conversation, and sending a message brings the view to it. On phones the widget only shows the circle, which is cropped onto the face by the avatar's launcher setting. Your project keeps the copy parlant widget init made. To pick this up, run parlant widget init --force, which replaces that copy and any changes you made to it.
  • With Gemini as your provider, replies at medium, high and max effort and both review checks now run on Gemini 4 Hydrogen instead of Gemini 3.8 Flash. Medium effort keeps low reasoning. On a website agent this cut replies from 15–30 seconds to 6–8, and Hydrogen kept its reasoning out of replies where 3.8 Flash at low reasoning had written it into one. Minimal and low effort stay on Flash-Lite. A react or review.* route you set yourself is unchanged. To keep the old model, route it explicitly, e.g. "react": p.ModelConfig("gemini:gemini-3.8-flash", reasoning="low").
  • LiteLLM's default for both review checks is now gemini/gemini-4-hydrogen instead of gemini/gemini-3.8-flash.

Fixed

  • An observation with a title but no note no longer appears in the agent's instructions as an empty entry (its title followed by "Details: [None]", without its condition). A rule now reaches the agent's prompt only when it says something: its content (an observation's note, a policy's action), or the tools it makes relevant, in which case its condition is shown even when it has a title. Rules without content are also left out of the note that tells the agent which instructions lost priority this turn. Observations without a note keep working for relationships, canned-response scoping and matching; they simply cost no prompt tokens.
  • Logging scopes now unwind after exceptions and cancellation, so later logs in the same task do not retain stale component labels.
  • The chat widget centers its disclaimer and "Powered by Parlant" under the input on phones.
  • The chat widget no longer shows "↓ New messages" in an empty or short chat that the visitor scrolled up in. The pill now appears only when there is something below to jump to.
  • The chat widget no longer ends a finished reply with a stray *. A reply with an odd number of * bullets used to get one after its last word. Half-typed bold and italics still close while a reply streams. To pick up this and the other widget fixes, run parlant widget init --force, which replaces your project's copy of the widget and any changes you made to it.
  • A reasoning level set on a Gemini 4 model in a schematic route, such as "review.*": p.ModelConfig("gemini:gemini-4-hydrogen", reasoning="high"), is now sent to Gemini. It used to be dropped, so the model thought at its own default.
  • Canned-response relevance now considers matches from every query chunk before selecting the closest responses, retaining each response's best matching score.
