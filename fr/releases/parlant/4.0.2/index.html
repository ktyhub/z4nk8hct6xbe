parlant v4.0.2

[4.0.2] - 2026-11-05

Ajouté

  • Le widget de chat permet à l'agent IA dans le navigateur d'un visiteur de parler à votre agent sur WebMCP (document.modelContext ; dans Chrome derrière un drapeau aujourd'hui). Sur à chaque page sur laquelle il se trouve, le widget enregistre un outil ask_agent décrit avec le nom de l'agent. Un appel démarre la conversation du widget s'il n'y en a pas pourtant, comme celui qu'un agent détient pour le client (customer_represented_by_an_agent), envoie la question via le chat, elle s'affiche donc avec la réponse, s'ouvre le chat, et répond à l'agent navigateur une fois le tour terminé. Suivi les appels continuent la même conversation. Le message porte metadata.parlant_widget.asked_by = "customer_agent", donc le chat et votre les outils peuvent distinguer l'agent du visiteur du visiteur. Rien ne se passe dans un navigateur sans WebMCP ; webmcp={false} l'éteint. ParlantTransport sendMessage prend un argument de métadonnées facultatif et ensureSession un option pour le drapeau.
  • Server(session_store=..., customer_store=...) accepte un s3://bucket URL pour conserver les sessions et les clients dans Amazon S3. Donnez à Parlant un seau de le sien. Les informations d'identification proviennent de la chaîne d'informations d'identification AWS ; ajoutez ?region= ou, pour le stockage compatible S3, ?endpoint=. Le stockage doit prendre en charge écritures conditionnelles, qui empêchent les serveurs concurrents d'écraser les uns les autres les mises à jour des autres. Les collections vides survivent aux redémarrages et à l'échec d'une migration write laisse les données originales en place. Toute requête autre qu'une recherche par ID, comme lister les sessions, lit chaque objet de la collection, utilisez donc MongoDB si vous avez besoin de requêtes indexées à grande échelle.
  • Le widget de chat (parlant widget init) prend la photo de l'agent en une seule fois Hélice avatar : { type: "logo", src }, { type: "photo", src, live? } ou { type: "video", src?, poster?, live?, launcher? }. Un avatar vidéo joue un courte boucle assourdie sous l'en-tête, défile une fois avec la conversation il démarre et conserve sa taille ouverte lorsque le chat est développé. Sur le fermé lanceur, launcher le recadre sur le visage. Laissez de côté src pour utiliser le la propre vidéo d'un agent du widget. live ajoute le point vert, sur la vidéo coin aussi, rouge alors que le serveur n'est pas joignable. Utiliser un MP4 H.264 enregistré avec -movflags +faststart ; iPhone Safari se bloque sur WebM.

Modifié

  • Les suggestions persistantes du widget de chat se démarquent de celles d'ouverture : souligné et lettré dans la couleur principale du thème sur l'arrière-plan du chat, au lieu du remplissage gris.
  • Sur les téléphones et les tablettes, le widget de chat ferme le clavier à l'écran une fois par jour. Le message est envoyé, qu'il soit tapé ou sélectionné parmi les suggestions, donc la réponse n'est pas caché derrière.
  • Avec le fournisseur LiteLLM, les itinéraires d'examen sont désormais par défaut gemini/gemini-3.8-flash au lieu de gemini/gemini-3.6-flash, pareil modèle que le fournisseur Gemini utilise déjà pour eux.
  • L'agent de l'échafaudage lead-gen ne devine plus lorsqu'un visiteur demande l'entreprise, ses produits ou son projet et sa connaissance des produits n'ont aucun réponse. Il dit que c'est une excellente question mais qu'il est difficile d'y répondre correctement dans le contexte actuel. discuter, propose de les mettre en contact avec l'équipe, demande un e-mail ou un téléphone numéro et transmet la question avec request_team_follow_up. Sans rapport Les questions, les questions de commande des clients existants et les prix sont traités comme avant. Pour rendre cela possible, record_lead accepte désormais les leads avec juste un un objectif et un contact : buying_for et role sont optionnels, et inconnus ne rapporte rien.
  • parlant dashboard project confirm termine un projet local ou auto-hébergé même lorsque son serveur organise déjà des sessions, par exemple lors de l'essai de l'agent. Il les importe d'abord dans le tableau de bord, comme le fait la synchronisation du tableau de bord, et termine ensuite la configuration, de sorte que le projet ne reste plus à « Terminer la configuration ». Une importation qui prend plus de 90 secondes environ s'arrête avec SYNC_IN_PROGRESS ; exécutez à nouveau confirm pour continuer à attendre la même importation. Un échec d'importation s'arrête avec SYNC_FAILED et sa raison. -parlant init --dashboard --json et parlant dashboard project create --json pour un projet local ou auto-hébergé, indiquez maintenant nextSteps, en terminant par project confirm. Le AGENTS.md échafaudé demande aux agents de codage de confirmer le projet une fois son serveur connecté.
  • Après avoir créé un projet géré dont la vérification de configuration a trouvé comment l'exécuter, parlant dashboard project create pointe maintenant vers parlant dashboard --project ID deploy : le premier déploiement en direct complète le configuration. La page de configuration du tableau de bord est facultative pour vérifier les paramètres.

Obsolète

  • Les accessoires avatarUrl, avatarStyle et liveIndicator du widget de chat, dans faveur de avatar. Ils fonctionnent toujours lorsque avatar n'est pas défini.

Corrigé

  • Gemini Argon peut rejouer les appels d'outils enregistrés avec leur pensée originale signée bloque au lieu de revenir inutilement à l’historique des résultats uniquement.
  • Le filtrage des sessions par étiquettes renvoie désormais des pages complètes et fonctionnelles curseurs de continuation, avec des décomptes totaux cohérents dans les deux ordres de tri.
  • La pagination du curseur MongoDB préserve désormais les filtres $or sur les pages ultérieures, donc les listes filtrées n'incluent plus les enregistrements en dehors de l'ensemble demandé.
  • Les réponses standardisées conservent désormais des vecteurs de recherche distincts pour leur texte et chaque signal, donc les signaux n'entrent plus en collision dans l'indice de pertinence. S'applique lorsque les réponses sont créées ou mises à jour ; les index existants ne sont pas reconstruit automatiquement.
  • Sur iPhone, focaliser la boîte de message du widget de chat ne zoome plus sur la page dans, ce qui a poussé le chat ouvert hors du bord droit de l’écran. La boîte utilise une police de 16 pixels sur les écrans tactiles, taille en dessous de laquelle iOS zoome.
  • Les outils locaux et MCP acceptent désormais les arguments de liste séparés par des virgules sans crochets tout en préservant les virgules entre guillemets et les listes vides.
  • Le dernier message du widget de chat ne glisse plus sous les suggestions et boîte de message lorsque quelque chose prend de l'espace dans la transcription, comme le Bannière "Connexion interrompue" apparaissant juste après un envoi. La transcription est resté épinglé au bas uniquement à mesure que les messages augmentaient, et non à mesure que sa vue diminuait.
  • Les programmes de fraîcheur variables contextuellement invalides sont rejetés avant la sauvegarde, ainsi, un échec de mise à jour du planning laisse les données existantes de la variable intactes.
  • Un message client qui arrive alors que l'agent est encore en train de travailler sur le le précédent remplace désormais ce tour, comme prévu, même lorsque le moteur était en marche. le milieu du rejet d'une étape : un appel d'outil ou un message refusé par un crochet de révision, par le réviseur ou par modération. Avant, le rejet recommençait l'étape et a abandonné l'annulation en attente, l'agent a donc fini de répondre au premier message, puis a répondu au second dans un tour séparé. Les clients qui envoient deux messages à la suite reçoivent désormais une réponse qui prend en compte les deux.

Sécurité

  • Augmenter la version minimale de python-multipart à 0.0.30 pour les deux uv et les installations pip, empêchant l'installation des versions affectées par CVE-2026-53539.

[4.0.1] - 2026-11-02

Modifié

  • parlant init --scaffold lead-gen crée désormais son agent avec preamble_config=p.PreambleConfiguration.encourage(). Avant son premier outil appeler l'agent dit une courte ligne, comme "Laissez-moi vérifier ça", donc le le visiteur n'est pas laissé attendre en silence. Sans cela, les préambules n’étaient pas gérés : tout ce que le modèle a écrit avant qu'un appel d'outil ne soit effectué directement.
  • Chaque outil des échafaudages lead-gen et retail-store dispose désormais d'un narration, comme « Vérifier quels jours sont gratuits » ou « Suivre votre expédition". Le chat l'affiche pendant l'exécution de l'outil, au lieu du générique "Exécuter des outils".

Corrigé

  • Avec le fournisseur Anthropic, l'indexation n'échoue plus sur Claude Opus 4.7 et version ultérieure ou tout modèle Claude 5, y compris les itinéraires par défaut (Sonnet 5.5 et Haïku 5.5). Parlant a envoyé un temperature, que ces modèles rejettent avec "temperature est obsolète pour ce modèle."; il n'en envoie désormais qu'un seul à Modèles Claude 3 et Claude 4 jusqu'au 4.6, qui l'acceptent toujours.
  • Un effort de raisonnement sur un modèle de Claude Fable utilise désormais la pensée adaptative d'un budget réfléchi, ce que Fable rejette.
  • Un effort de raisonnement sur Claude Opus 4.5 n'échoue plus. Parlant l'a envoyé pensée adaptative, qu'il rejette (« la pensée adaptative n'est pas prise en charge sur ce modèle"); il bénéficie désormais d'un budget réfléchi, comme le font Sonnet et Haiku 4.5.

parlant v4.0.2

[4.0.2] - 2026-11-05

Added

  • The chat widget lets the AI agent in a visitor's browser talk to your agent over WebMCP (document.modelContext; in Chrome behind a flag today). On every page it's on, the widget registers an ask_agent tool described with the agent's name. A call starts the widget's conversation if there is none yet, as one an agent holds for the customer (customer_represented_by_an_agent), sends the question through the chat, so it shows there with the reply, opens the chat, and answers the browser agent once the turn has ended. Follow-up calls continue the same conversation. The message carries metadata.parlant_widget.asked_by = "customer_agent", so the chat and your tools can tell the visitor's agent from the visitor. Nothing happens in a browser without WebMCP; webmcp={false} turns it off. ParlantTransport's sendMessage takes an optional metadata argument and ensureSession an option for the flag.
  • Server(session_store=..., customer_store=...) accepts an s3://bucket URL to keep sessions and customers in Amazon S3. Give Parlant a bucket of its own. Credentials come from the AWS credential chain; add ?region= or, for S3-compatible storage, ?endpoint=. The storage must support conditional writes, which keep concurrent servers from overwriting each other's updates. Empty collections survive restarts, and a failed migration write leaves the original data in place. Any query other than a lookup by ID, such as listing sessions, reads every object in the collection, so use MongoDB if you need indexed queries at scale.
  • The chat widget (parlant widget init) takes the agent's picture in one avatar prop: { type: "logo", src }, { type: "photo", src, live? } or { type: "video", src?, poster?, live?, launcher? }. A video avatar plays a short muted loop under the header, scrolls away with the conversation once it starts, and keeps its opened size when the chat is expanded. On the closed launcher, launcher crops it onto the face. Leave out src to use the widget's own video of an agent. live adds the green dot, on the video's corner too, red while the server can't be reached. Use an H.264 MP4 saved with -movflags +faststart; iPhone Safari stalls on WebM.

Changed

  • The chat widget's persistent suggestions stand out from its opening ones: outlined and lettered in the theme's primary color on the chat's background, instead of the grey fill.
  • On phones and tablets, the chat widget closes the on-screen keyboard once a message is sent, whether typed or picked from the suggestions, so the reply isn't hidden behind it.
  • With the LiteLLM provider, review routes now default to gemini/gemini-3.8-flash instead of gemini/gemini-3.6-flash, the same model the Gemini provider already uses for them.
  • The lead-gen scaffold's agent no longer guesses when a visitor asks about the business, its products or their project and its product knowledge has no answer. It says it's a great question but hard to answer properly in the chat, offers to connect them with the team, asks for an email or phone number, and passes the question on with request_team_follow_up. Unrelated questions, existing customers' order questions and prices are handled as before. To make that possible, record_lead now accepts a lead with just a goal and a contact: buying_for and role are optional, and an unknown one scores nothing.
  • parlant dashboard project confirm finishes a local or self-hosted project even when its server already holds sessions, such as from trying the agent. It imports them into the dashboard first, as the dashboard's Sync does, and then completes the setup, so the project no longer stays at "Finish setup". An import that takes longer than about 90 seconds stops with SYNC_IN_PROGRESS; run confirm again to keep waiting for the same import. A failed import stops with SYNC_FAILED and its reason.
  • parlant init --dashboard --json and parlant dashboard project create --json for a local or self-hosted project now list nextSteps, ending with project confirm. The scaffolded AGENTS.md tells coding agents to confirm the project once its server is connected.
  • After creating a managed project whose setup check found how to run it, parlant dashboard project create now points to parlant dashboard --project ID deploy: the first live deploy completes the setup. The dashboard's setup page is optional for reviewing the settings.

Deprecated

  • The chat widget's avatarUrl, avatarStyle and liveIndicator props, in favor of avatar. They still work when avatar isn't set.

Fixed

  • Gemini Argon can replay saved tool calls with their original signed thought blocks instead of unnecessarily falling back to result-only history.
  • Filtering sessions by labels now returns complete pages and working continuation cursors, with consistent total counts in either sort order.
  • MongoDB cursor pagination now preserves $or filters on later pages, so filtered listings no longer include records outside the requested set.
  • Canned responses now retain separate search vectors for their text and every signal, so signals no longer collide in the relevance index. Applies when responses are created or updated; existing indexes are not rebuilt automatically.
  • On iPhone, focusing the chat widget's message box no longer zooms the page in, which pushed the open chat off the right edge of the screen. The box uses a 16px font on touch screens, the size below which iOS zooms.
  • Local and MCP tools now accept comma-separated list arguments without brackets while preserving quoted commas and empty lists.
  • The chat widget's latest message no longer slips under the suggestions and message box when something takes the transcript's space, such as the "Connection interrupted" banner appearing just after a send. The transcript stayed pinned to the bottom only as messages grew, not as its view shrank.
  • Invalid context-variable freshness schedules are rejected before saving, so a failed schedule update leaves the variable's existing data intact.
  • A customer message that arrives while the agent is still working on the previous one now replaces that turn, as intended, even when the engine was in the middle of rejecting a step: a tool call or message turned down by a review hook, by the reviewer, or by moderation. Before, the rejection restarted the step and dropped the pending cancellation, so the agent finished replying to the first message and then answered the second one in a separate turn. Customers who send two messages in quick succession now get one reply that takes both into account.

Security

  • Raise the minimum python-multipart version to 0.0.30 for both uv and pip installations, preventing installation of versions affected by CVE-2026-53539.

[4.0.1] - 2026-11-02

Changed

  • parlant init --scaffold lead-gen now creates its agent with preamble_config=p.PreambleConfiguration.encourage(). Before its first tool call the agent says one short line, such as "Let me check that", so the visitor isn't left waiting in silence. Without it, preambles were unmanaged: whatever the model wrote before a tool call went straight through.
  • Every tool in the lead-gen and retail-store scaffolds now has a narration, such as "Checking which days are free" or "Tracking your shipment". The chat shows it while the tool runs, instead of the generic "Running tools".

Fixed

  • With the Anthropic provider, indexing no longer fails on Claude Opus 4.7 and later or any Claude 5 model, including the default routes (Sonnet 5.5 and Haiku 5.5). Parlant sent a temperature, which those models reject with "temperature is deprecated for this model."; it now sends one only to Claude 3 models and Claude 4 models up to 4.6, which still accept it.
  • A reasoning effort on a Claude Fable model now uses adaptive thinking instead of a thinking budget, which Fable rejects.
  • A reasoning effort on Claude Opus 4.5 no longer fails. Parlant sent it adaptive thinking, which it rejects ("adaptive thinking is not supported on this model"); it now gets a thinking budget, as Sonnet and Haiku 4.5 do.
