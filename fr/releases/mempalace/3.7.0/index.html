mempalace v3.7.0

v3.7.0 — flux de journaux d'agent, colonne vertébrale d'intégrité et intégrations enfichables

Le titre de cette version est coordination du flux de journaux des agents : une couche d'événements locale en premier lieu en ajout uniquement afin que les agents sur différentes machines puissent déléguer le travail, attendre des réponses, échanger des correctifs et accuser réception des transferts via le hub MemPalace — sans qu'un humain ne relaye les messages. Tout le reste dans 3.7.0 renforce les palais de longue durée sous une charge multi-session (propriété d'un seul écrivain, réparation/remine plus sûre, cycle de vie MCP) et étend les options d'intégration/recherche (intégrations compatibles OpenAI, fenêtres de date de recherche) sans modifier la valeur locale par défaut.

Fonctionnalités

  • Coordination du flux de journaux d'agent (RFC 003). Couche d'événements en ajout uniquement pour le travail multi-agent : paquets de tâches durables, transferts d'attente/accusé de réception, artefacts de correctifs et de fichiers et suivi en direct sur le hub HTTP MCP (GET /logstream/stream SSE). Les outils MCP incluent mempalace_event_append / list / wait / ack, la mise/obtention d'artefacts et la soumission de correctifs ; CLI mempalace logstream reflète les verbes de base. Les événements et les artefacts restent locaux, textuellement et séparés du palais des tiroirs (logstream.sqlite3). Les flottes d'agents à cerveau partagé/multi-machines n'ont plus besoin d'un humain pour relayer le statut entre les hôtes. (#2162, phases 1 à 5)
  • Fondation de synchronisation multi-maître Logstream (RFC 004 étape 0). Hooks de réplication Logstream au niveau du domaine afin que les agents coordonnés puissent partager la couche de coordination entre les répliques du palais - l'étape de stockage pour un cerveau partagé répliqué. (#2162, synchronisation des journaux)
  • Intégrations compatibles OpenAI. L'option d'adhésion embedding_model: "openai-compat" communique avec n'importe quel point de terminaison /v1/embeddings (LM Studio, llama.cpp, vLLM, le shim OpenAI d'Ollama ou un serveur auto-hébergé) via stdlib urllib — aucune nouvelle dépendance. Les variables de configuration et d'environnement définissent l'URL, le modèle et la clé ; l'identifiant du modèle fait partie du nom de l'intégrateur, donc un changement de modèle force une réindexation. Le chemin MiniLM/ONNX par défaut est inchangé. (#1671, #1559)
  • Fenêtre de date de recherche. mempalace_search et mempalace search acceptent since / before ([since, before) sur filed_at), partagés avec list_drawers via mempalace.date_window. Les tiroirs non datés sont exclus lorsqu'une reliure est active ; le pool de candidats vectoriels s'élargit sous un filtre et signale une troncature lorsque le pool est plein. (#2000, #463)
  • Fournisseur de mémoire Hermes (noyau). Les fichiers Hermes MemoryProvider intégrés au package passent en direct par file_conversation_exchange() afin que les métadonnées correspondent à l'exploration de convo, avec un travailleur en arrière-plan afin que la boucle d'agent ne se bloque jamais. L'installation/le remplissage/les documents restent un suivi empilé. (#1915, #2215)
  • Adaptateurs source RFC 002 sur le mien. mempalace mine <source> --source <adapter> résout les adaptateurs enregistrés, détient le bail de l'écrivain Palace pour l'ingestion complète et maintient les essais à sec inertes. Les anciens chemins --mode sont inchangés. (#2068, #2062)
  • Hook write-routing via le démon. Les sauvegardes et les mines de hook en arrière-plan peuvent honorer la politique de routage en écriture partagée afin que les configurations multisessions sérialisent les mutations via un propriétaire local. (#2030, #1963)

Performances

  • EmbeddingGemma regroupe les documents par taille avant le sous-lot, supprimant le travail des jetons rembourrés sur de longs balayages sans changer la signification du vecteur. S'applique uniquement au embedding_model: embeddinggemma. (#2104)
  • Les sondes de capacité HNSW sont mises en cache et invalidées par la signature du fichier Palace, de sorte que les chemins d'état/taxonomie répétés ne réanalysent plus les segments natifs à chaque appel. (#2051, #1471)
  • La numérotation des lignes chunk_text est O(N), corrigeant les blocages de plusieurs secondes sur les grandes sources. (#2054, #2055)

Corrections de bugs

  • Le minage fonctionne à nouveau sur le backend Chroma par défaut. L'intégration explicite ne transmet plus les scalaires Chroma np.float32 que normalize_embeddings rejette. (#2187)
  • Les exportations de données ChatGPT sont analysées comme des conversations et non stockées sous forme de tableaux JSON bruts. (#2160)
  • Les backends locaux imposent la propriété d'un seul écrivain pendant toute la durée du processus. Les palais sauvegardés sur des fichiers nécessitent un propriétaire d'écrivain pendant toute la durée de vie du processus ; MCP en lecture seule peut coexister ; les backends distants restent multi-processus. (#2079, #2045)
  • MCP refuse les écritures lorsque la bibliothèque servie dérive (mempalace et chromadb lorsque ce backend est actif) après une mise à niveau sans redémarrage. Désactivez-vous avec MEMPALACE_MCP_ALLOW_STALE_LIBRARY. (#2081, #899)
  • Les valeurs par défaut d'écriture de Chroma HNSW correspondent à chromadb (batch_size=100 / sync_threshold=1000), retirant l'ancienne protection contre les ballonnements 2/2. (#2107, #2106)
  • La réparation et la récupération sont plus sûres en cas de conflit. Verrouillage de la mine avant l'archivage, préservation des collections temporaires en cas d'échec d'un échange, échec bruyant en cas de pagination tronquée ; L'exécution à sec est un véritable aperçu dans les modes hérités et from-sqlite ; les sauvegardes ignorent les sockets/canaux/nœuds de périphérique afin qu'un socket Palace en direct n'abandonne plus la réparation/la migration.   • rebuild_index détient le bail du rédacteur du palais pour le cycle complet d'instantané → reconstruction/échange. (#2195)
  • Les verrous de mines orphelins par source sont récoltés (âge + troupeau non bloquant), limités à une fois toutes les 15 minutes ; les serrures au niveau du palais sont intactes. (#2200)
  • La divergence HNSW est contrôlée en amont avant les sites de crash restants du count() dans les assistants de mine, de déduplication, de migration, de réparation et de palais. (#2093)
  • Le reminage et l'ingestion de conversations ne perdent plus ou ne dupliquent plus les tiroirs. Déduplication du hachage du contenu, portée de purge du balayage, drawer_id aller-retour lors de la recherche ; Claude Code subagents/ ignoré par défaut (--include-subagents pour s'inscrire). (#2050, #2125, #2090, #1330, #1217)
  • Le cycle de vie MCP et démon renforce l'utilisation multi-agents. La lecture seule refuse les mutations de l'hôte config/checkpoint-ack ; stdio se ferme sur EOF ; le démon reporte les tâches refusées par le verrouillage ; La capture de la sortie standard Windows se replie ou échoue si le flux de protocole ne peut pas être restauré. (#2126, #2072, #2029, #2211, #2210)
  • Encodage et renforcement des paramètres régionaux Windows. La broche UTF-8 sur la configuration/dialecte s'ouvre ; la réparation mojibake ne détruit plus la prose portugaise/vietnamienne/turque propre ; réparation-encodage CLI reconfigure stdio ; Symboles non ASCII CLI remplacés pour les consoles GBK. Garde ReDoS candidat entité ; rejeter le chunk_overlap pathologique ; worktree cwd correspond à l'aile du projet ; L'accent mis sur la démarque n'est pas une émotion ; les points d'entrée de service restaurent MEMPALACE_PALACE_PATH ; systemd Restart=always avec des documents de surveillance inactifs ; Clé d'environnement docker-compose.yml valide. mempalace v3.7.0

v3.7.0 — agent logstream, integrity spine, and pluggable embeddings

The headline of this release is agent logstream coordination: an append-only, local-first event layer so agents on different machines can delegate work, wait for replies, exchange patches, and acknowledge handoffs through the MemPalace hub — without a human relaying messages. Everything else in 3.7.0 hardens long-lived palaces under multi-session load (single-writer ownership, safer repair/re-mine, MCP lifecycle) and expands embed/search options (OpenAI-compatible embeddings, search date windows) without changing the local-first default.

Features

  • Agent logstream coordination (RFC 003). Append-only event layer for multi-agent work: durable task packets, wait/ack handoffs, patch and file artifacts, and live tailing over the MCP HTTP hub (GET /logstream/stream SSE). MCP tools include mempalace_event_append / list / wait / ack, artifact put/get, and patch submit; CLI mempalace logstream mirrors the core verbs. Events and artifacts stay local, verbatim, and separate from the drawer palace (logstream.sqlite3). Shared-brain / multi-machine agent fleets no longer need a human to relay status between hosts. (#2162, phases 1–5)

  • Logstream multi-master sync foundation (RFC 004 step 0). Estate-level logstream replication hooks so coordinated agents can share the coordination layer across palace replicas — the storage step for a replicated shared brain. (#2162, logsync)

  • OpenAI-compatible embeddings. Opt-in embedding_model: "openai-compat" talks to any /v1/embeddings endpoint (LM Studio, llama.cpp, vLLM, Ollama's OpenAI shim, or a self-hosted server) over stdlib urllib — no new dependency. Config and env vars set URL, model, and key; the model id is part of the embedder name so a model change forces a reindex. Default MiniLM/ONNX path is unchanged. (#1671, #1559)

  • Search date window. mempalace_search and mempalace search accept since / before ([since, before) on filed_at), shared with list_drawers via mempalace.date_window. Undated drawers are excluded while a bound is active; the vector candidate pool widens under a filter and reports truncation when the pool is full. (#2000, #463)

  • Hermes memory provider (core). In-package Hermes MemoryProvider files live turns through file_conversation_exchange() so metadata matches convo mining, with a background worker so the agent loop never blocks. Install/backfill/docs remain a stacked follow-up. (#1915, #2215)

  • RFC 002 source adapters on mine. mempalace mine <source> --source <adapter> resolves registered adapters, holds the palace writer lease for the full ingest, and keeps dry-runs inert. Legacy --mode paths are unchanged. (#2068, #2062)

  • Hook write-routing through the daemon. Background hook saves and mines can honor the shared write-routing policy so multi-session setups serialize mutations through one local owner. (#2030, #1963)

Performance

  • EmbeddingGemma groups documents by size before sub-batching, cutting padded-token work on long sweeps without changing vector meaning. Applies only to embedding_model: embeddinggemma. (#2104)

  • HNSW capacity probes are cached and invalidated by palace file signature, so repeated status/taxonomy paths no longer re-scan native segments every call. (#2051, #1471)

  • chunk_text line numbering is O(N), fixing multi-second hangs on large sources. (#2054, #2055)

Bug Fixes

  • Mining works again on the default Chroma backend. Explicit-embedding writes no longer hand Chroma np.float32 scalars that normalize_embeddings rejects. (#2187)

  • ChatGPT data exports are parsed as conversations, not stored as raw JSON arrays. (#2160)

  • Local backends enforce process-lifetime single-writer ownership. File-backed palaces require one writer owner for the process lifetime; read-only MCP may coexist; remote backends remain multi-process. (#2079, #2045)

  • MCP refuses writes when the served library drifts (mempalace, and chromadb when that backend is active) after an upgrade without restart. Opt out with MEMPALACE_MCP_ALLOW_STALE_LIBRARY. (#2081, #899)

  • Chroma HNSW write defaults match chromadb (batch_size=100 / sync_threshold=1000), retiring the old 2/2 bloat guard. (#2107, #2106)

  • Repair and recovery are safer under contention. Mine-lock before archive, preserve temp collections on failed swap, fail loud on truncated pagination; dry-run is a true preview in both legacy and from-sqlite modes; backups skip sockets/pipes/device nodes so a live palace socket no longer aborts repair/migrate. (#2109, #2086, #2087, #2133, #2144, #2207, #2212)

  • rebuild_index holds the palace writer lease for the full snapshot→rebuild/swap cycle. (#2195)

  • Orphaned per-source mine locks are reaped (age + nonblocking flock), throttled to once per 15 minutes; palace-level locks are untouched. (#2200)

  • HNSW divergence is preflighted before remaining count() crash sites across mine, dedup, migrate, repair, and palace helpers. (#2093)

  • Re-mine and conversation ingest no longer lose or duplicate drawers. Content-hash dedup, sweeper purge scope, round-trippable drawer_id on search; Claude Code subagents/ skipped by default (--include-subagents to opt in). (#2050, #2125, #2090, #1330, #1217)

  • MCP and daemon lifecycle harden multi-agent use. Read-only refuses config/checkpoint-ack host mutations; stdio exits on EOF; daemon defers lock-refused jobs; Windows stdout capture falls back or fails closed if the protocol stream cannot be restored. (#2126, #2072, #2029, #2211, #2210)

  • Encoding and Windows locale hardening. Pin UTF-8 on config/dialect opens; mojibake repair no longer destroys clean Portuguese/Vietnamese/Turkish prose; repair-encoding CLI reconfigures stdio; non-ASCII CLI symbols replaced for GBK consoles. (#2098, #2208, #2194, #1104, #1034, #2193)

  • Small correctness fixes. Entity-candidate ReDoS guard; reject pathological chunk_overlap; worktree cwd maps to the project wing; markdown emphasis is not emotion; service entrypoints restore MEMPALACE_PALACE_PATH; systemd Restart=always with idle watchdog docs; valid docker-compose.yml environment key. (#2127, #2056, #2206, #2199, #2192, #2203, #2204, #2188)

Documentation

  • Agent logstream concept page, coordination protocol, shared-brain fleet guide, and RFC 003/004. (#2162)
  • Operator write-routing / single-writer recovery notes. (#2079)
  • Remote-server idle watchdog and read-only semantics. (#2126, #2204)
  • README Docker section leads with the published image and real mount/permission pitfalls. (#2196)
  • MX3 public-shim example and CONTRIBUTING Discussions cleanup. (#597, #555)

Internal

  • Docker publish is gated on a real smoke script (Compose parse, mine, MCP handshake). (#2189)
  • Embedding empty-batch / plain-sequence regression tests; HNSW defaults assertions. (#2191, #2159)
