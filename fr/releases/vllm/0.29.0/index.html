Faits saillants

Cette version contient 594 commits de 277 contributeurs (91 nouveaux) !

  • Model Runner V2 est désormais la valeur par défaut pour tous les modèles (#53183), complétant le déploiement qui a commencé avec le regroupement de modèles (#48290). MRV2 a également obtenu le profilage de mémoire graphique CUDA pour le dimensionnement automatique du cache KV (#53306), l'échantillonnage par lots qui réduit la mémoire des logits par étape de 1/TP (#50465), l'intégration d'invites (#42963), la spéculation extract_hidden_states (#49811), l'envoi FULL cudagraph rembourré pour un décodage uniforme sous le décodage spécifié (#53407) et le saut de synchronisation DP avant Pré-remplissage du brouillon EAGLE/MTP (#53694). MRV1 reste utilisé pour quelques modèles ROCm et fonctionnalités que MRV2 ne prend pas encore en charge.
  • Nouveaux modèles : aperçu Hy4, MoE actif 770B/49B de Tencent avec Gated DeepSeek Sparse Attention et MTP natif (#54160) ; Qwen3.8-Flash-Next avec BF16/FP8/NVFP4 et MTP (#53896) ; GraniteSWA et GraniteMoeSWA (#52706) ; NemotronH_Omni_Reasoning_V3 avec MTP (#52929, #53121) ; Points de contrôle Kimi K3 NVFP4 (#53132).
  • Performances Kimi-K3 et DeepSeek V4 : fusion du top-k MXFP4 dans la queue latente du K3 (environ 5 % de latence E2E, #53152), préparation des métadonnées K3 Mamba lors d'un lancement de Triton (accélération du noyau 6.6-7.6x, #52388), GEMM à faible latence Hopper optimisé (#54088) désormais également distribué sur SM100 (#53534) et utilisé pour eh_proj (accélération du noyau 12.9-25.2%, #53942), GEMM-RS étendu à GEMM-AR (#53053), porte MLA fusionnée dans la projection QKV-A (#54015), K3 DCP avec DSpark (#52188) et accès au cache de préfixe partiel DCP (#50493) ; Les experts partagés DeepSeek V4 ont été fusionnés dans MegaMoE (#53040), la largeur adaptative top-k a été réaménagée (#52823), un noyau de serrage SwiGLU natif pour Humming MoE (#53685) et un backend expert FlashInfer moe_ep opt-in (#49636).
  • Décodage spéculatif : statistiques d'acceptation par requête dans les réponses OpenAI API via --per-request-spec-decode-metrics (#48915), vérification adaptative étendue aux logprobs (#52242), SM100 sparse MLA pour GLM-5.2 (#52783) et DeepSeek V4 sur SM90 (#52795), brouillons Qwen3-Omni DSpark (#52560), PLAMo3 EAGLE-3/DFlash (#54239) et DFlash2 chargés à partir du format spéculateurs (#53797).
  • Synchronisation du poids RL : un nouveau backend P2P sharded_rdt dans lequel chaque travailleur extrait uniquement sa tranche TP/EP via NIXL ou Ray Direct Transport (#43375), des mises à jour de poids IPC locales (#52497), des mises à jour de coordonnées de points de contrôle clairsemées via des chargeurs de poids natifs (#50723, #53751) et un chargement expert acheminé pour gpt-oss (#52209).
  • Mise en cache des préfixes Mamba : les points de contrôle de pré-remplissage internes offrent une amélioration TTFT de 9 à 25 % (#52789) ; prefix_cache_retention_interval est désormais un argument CLI par défaut à 0 (#52216), avec une rétention dense automatiquement restaurée pour les modèles hybrides utilisant EAGLE/MTP (#55760, #55861).
  • Nouveaux paramètres par défaut : FlashInfer all-reduce activé par défaut pour les groupes TP CUDA, désactivez-le avec VLLM_ALLREDUCE_USE_FLASHINFER=0 (#52998) ; prefix-cache NONE_HASH est déterministe par défaut, donc les utilisateurs du cache KV distribué n'ont plus besoin d'épingler PYTHONHASHSEED (#51875) ; nouveaux drapeaux de contrôle d'admission --max-num-queued-reqs / --max-num-queued-tokens (#49445).
  • Modifications majeures : dix architectures de modèles obsolètes supprimées (#53608) ; FlexOlmo, Olmo3 et Hunyuan V1/VL ont migré vers le backend de modélisation Transformers (#53615) ; Le backend du décodeur vidéo PyAV a été supprimé (#54231) ; python -m vllm.entrypoints.openai.api_server est obsolète au profit de vllm serve (#52131) ; VLLM_TEST_FORCE_FP8_MARLIN (#52182) et VLLM_ROCM_USE_AITER_FP4_ASM_GEMM (#53141) supprimés.

:avertissement : Dépréciation de Model Runner V1

Maintenant que Model Runner V2 est utilisé par défaut, nous considérons Model Runner V1 comme obsolète et ciblons v0.32 pour sa suppression. Nous n’avons plus l’intention d’accepter d’autres améliorations ou optimisations spécifiques à MRV1.

Certaines [fonctionnalités] (https://github.com/vllm-project/vllm/issues/47172) ne sont pas encore prises en charge dans MRV2, mais nous prévoyons de combler ces lacunes dans les 2-3 prochaines semaines. Ceux-ci incluent le parallélisme de séquence, le chevauchement de deux lots, le parallélisme expert élastique, les processeurs logits personnalisés et certaines méthodes de décodage spéculatif. Pour l'instant, vLLM utilisera toujours MRV1 si l'une de ces fonctionnalités est configurée.

vllm v0.29.0

v0.29.0

Highlights

This release features 594 commits from 277 contributors (91 new)!

  • Model Runner V2 is now the default for all models (#53183), completing the rollout that began with pooling models (#48290). MRV2 also gained CUDA graph memory profiling for KV cache auto-sizing (#53306), batch-sharded sampling that cuts per-step logits memory by 1/TP (#50465), prompt embeds (#42963), extract_hidden_states speculation (#49811), padded FULL cudagraph dispatch for uniform decode under spec decode (#53407), and DP-sync skipping before EAGLE/MTP draft prefill (#53694). MRV1 remains in use for a few ROCm models and features MRV2 does not yet support.
  • New models: Hy4-preview, Tencent's 770B/49B-active MoE with Gated DeepSeek Sparse Attention and native MTP (#54160); Qwen3.8-Flash-Next with BF16/FP8/NVFP4 and MTP (#53896); GraniteSWA and GraniteMoeSWA (#52706); NemotronH_Omni_Reasoning_V3 with MTP (#52929, #53121); Kimi K3 NVFP4 checkpoints (#53132).
  • Kimi-K3 and DeepSeek V4 performance: fused MXFP4 top-k finalization in the K3 latent tail (about 5% E2E latency, #53152), K3 Mamba metadata preparation in one Triton launch (6.6-7.6x kernel speedup, #52388), tuned Hopper low-latency GEMM (#54088) now also dispatched on SM100 (#53534) and used for eh_proj (12.9-25.2% kernel speedup, #53942), GEMM-RS extended to GEMM-AR (#53053), MLA gate merged into the QKV-A projection (#54015), K3 DCP with DSpark (#52188) and DCP partial prefix cache hits (#50493); DeepSeek V4 shared experts fused into MegaMoE (#53040), adaptive top-k width re-landed (#52823), a native SwiGLU clamp kernel for Humming MoE (#53685), and an opt-in FlashInfer moe_ep expert backend (#49636).
  • Speculative decoding: per-request acceptance stats in OpenAI API responses via --per-request-spec-decode-metrics (#48915), adaptive verification extended to logprobs (#52242), SM100 sparse MLA for GLM-5.2 (#52783) and DeepSeek V4 on SM90 (#52795), Qwen3-Omni DSpark drafts (#52560), PLaMo3 EAGLE-3/DFlash (#54239), and DFlash2 loading from speculators format (#53797).
  • RL weight sync: a new sharded_rdt P2P backend where each worker pulls only its TP/EP slice over NIXL or Ray Direct Transport (#43375), rank-local IPC weight updates (#52497), sparse checkpoint-coordinate updates through native weight loaders (#50723, #53751), and routed expert loading for gpt-oss (#52209).
  • Mamba prefix caching: internal prefill checkpoints deliver a 9%-25% TTFT improvement (#52789); prefix_cache_retention_interval is now a CLI argument defaulting to 0 (#52216), with dense retention automatically restored for hybrid models using EAGLE/MTP (#55760, #55861).
  • New defaults: FlashInfer all-reduce enabled by default for TP CUDA groups, opt out with VLLM_ALLREDUCE_USE_FLASHINFER=0 (#52998); prefix-cache NONE_HASH is deterministic by default so distributed KV cache users no longer need to pin PYTHONHASHSEED (#51875); new --max-num-queued-reqs / --max-num-queued-tokens admission-control flags (#49445).
  • Breaking changes: ten deprecated model architectures removed (#53608); FlexOlmo, Olmo3 and Hunyuan V1/VL migrated to the Transformers modeling backend (#53615); PyAV video decoder backend removed (#54231); python -m vllm.entrypoints.openai.api_server deprecated in favor of vllm serve (#52131); VLLM_TEST_FORCE_FP8_MARLIN (#52182) and VLLM_ROCM_USE_AITER_FP4_ASM_GEMM (#53141) removed.

:warning: Model Runner V1 Deprecation

Now that Model Runner V2 is used by default, we are considering Model Runner V1 deprecated and are targeting v0.32 for its removal. We do not intend to accept any more MRV1-specific improvements or optimizations.

Some features are not yet supported in MRV2 but we are planning for these gaps to be closed within the next 2-3 weeks. These include sequence parallelism, dual-batch overlap, elastic expert parallellism, custom logits processors and certain speculative decoding methods. For now, vLLM will still fall back to use MRV1 if any of these features are configured.
