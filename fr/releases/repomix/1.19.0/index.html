#repomix v1.19.0

Cette version déplace le serveur MCP vers SDK v2 avec progression et annulation en direct, rend la sortie --compress beaucoup plus précise et apporte une grande série de corrections de bugs de la part des nouveaux contributeurs !

Quoi de neuf 🚀

Serveur MCP sur SDK v2 et le protocole 2026-07-28 (#1952, #1954)

Le serveur MCP fonctionne désormais sur le MCP TypeScript SDK v2. Les Clients qui prennent en charge le protocole 2026-07-28 le négocient automatiquement et les clients existants fonctionnent comme avant.

  • Le serveur se ferme proprement lorsque le client ferme stdin, donc aucun processus repomix --mcp n'est laissé de côté.
  • L'installation récupère environ la moitié du nombre de packages (171 à 84), puisque la v1 SDK a apporté des dépendances de transport HTTP telles que Express que le serveur uniquement stdio n'a jamais utilisées.

Pour les auteurs de client : les schémas d'outils déclarent désormais le schéma JSON 2020-12 (corps inchangés) et les erreurs de validation ne commencent plus par MCP error -32602: .

MCP : Progression et annulation des packs de longue durée (#1955, #1958)

pack_codebase, pack_remote_repository et generate_skill envoient désormais notifications/progress lorsque le client passe un progressToken, donc les packs longs affichent leur statut en direct, et les clients qui réinitialisent leur délai d'attente en cours de progression ne les coupent plus. En mode --sandbox, les messages portent uniquement le nom de la scène, jamais le chemin de l'hôte.

L'annulation d'un appel ou la déconnexion arrête désormais le pack et nettoie sa sortie partielle.

Améliorations ⚡

Sortie --compress plus précise (#2003)

Les tests Golden pour chaque langue prise en charge ont révélé un ensemble de bugs, désormais corrigés :

  • Le code des corps de fonction ne s'infiltre plus dans la sortie comme s'il s'agissait d'une déclaration.
  • Les lignes en double sont supprimées.
  • Les déclarations qui ont été supprimées silencieusement sont conservées, telles que les champs C/C++ typedef et #define, C# et Java, les champs de structure Rust, les appels Ruby attr_* et les règles at CSS.

Modifications de sortie pour C, C++, C#, CSS, Dart, Go, Java, JavaScript/TypeScript, Ruby, Rust, Swift et Vue. Si vous comptez sur --compress dans un pipeline, attendez-vous à une différence avec v1.18.

Génération de compétences : meilleure détection des piles technologiques (#1995)

--skill-generate lit désormais les dépendances de Gradle Kotlin DSL (build.gradle.kts) et des formes PEP 621 et Poetry de pyproject.toml.

Avertissement lorsqu'un chemin d'URL distant est ignoré (#1980, #1984, #433)

Une URL comme https://github.com/owner/repo/tree/main/src/shared a compressé l'intégralité du référentiel et supprimé silencieusement le chemin. Repomix avertit désormais et suggère un modèle --include :

The path "src/shared" in the remote URL is ignored, and the whole repository will be packed.
To pack only that path, add: --include "src/shared/**"

Corrections de bugs 🐛

Ignorer les modèles se terminant par un caractère générique et exclure désormais les fichiers (#1963, #1876, #320)

Les modèles tels que **/npm-debug.log* et **/repomix-output.* excluaient uniquement le contenu du répertoire, de sorte que des fichiers comme npm-debug.log.1 et docs/repomix-output.xml se glissaient dans la sortie. Ils sont désormais exclus. Rien de ce qui était exclu auparavant ne devient inclus.

.git/info/exclude suit les règles de correspondance de Git (#1871, #1870)

Un modèle sans barre oblique tel que secret.txt correspond désormais à n'importe quelle profondeur, comme dans Git, donc sub/secret.txt n'est plus compressé.

Un merci spécial à @sxh313 pour cette contribution ! 🎉

Les modèles d'ignorance personnalisés annulés ne sont plus inversés (#1975, #400)

!main.ts dans ignore.customPatterns ou --ignore a exclu main.ts au lieu de le réinclure. Les modèles annulés sont désormais ignorés avec un avertissement jusqu'à ce que le support approprié arrive (#400).

Les fichiers de sortie fractionnés ne sont plus intégrés à la prochaine exécution (#1921, #1920)

Avec --split-output, les fichiers comme repomix-output.1.xml d'une exécution précédente ne sont plus récupérés en entrée.

Un merci spécial à @lorenzozanee pour sa première contribution ! 🎉

--remove-comments Conserve les URL en CSS, SCSS, Less, Vue et Svelte (#1912, #1965, #1911)

url(http://example.com/logo.png) a été coupé en url(http: car // a été traité comme un commentaire. Chaque langage utilise désormais ses propres règles de commentaires, et les fichiers Vue et Svelte sont gérés par <script>, <style> et section de balisage.

Un merci spécial à @plox-sumit pour sa première contribution ! 🎉

Noms de fichiers non-ASCII dans les journaux et différences Git (#1940, #1979)

Les noms comme 日本語.txt n'apparaissent plus comme "\346\227\245..." dans les journaux et les différences git, et output.git.sortByChanges trie désormais correctement ces fichiers.

Un merci spécial à @feiiiiii5 pour sa première contribution ! 🎉

--token-count-tree 0 affiche l'arborescence complète (#1941)

Il n’y avait rien imprimé auparavant ; il affiche maintenant tous les fichiers.

Un merci spécial à @feiiiiii5 pour cette contribution ! 🎉

Chemins --stdin imbriqués sous Windows (#1922)

Les chemins de tuyauterie tels que src/(routes)/page[1].ts vers repomix --stdin sous Windows contenaient uniquement des fichiers au niveau racine. Les chemins imbriqués correspondent désormais.

Un merci spécial à @lux-liang pour sa première contribution ! 🎉

Erreurs fatales visibles sous --quiet et --stdout (#1875, #1874)

Un pack en échec sous --quiet ou --stdout est sorti avec le code 1 et n'a rien imprimé. L'erreur va maintenant à stderr.

Un merci spécial à @sxh313 pour cette contribution ! 🎉

Correctifs du serveur MCP (#1867, #1866, #1865, #1864, #1869, #1868)

  • --mcp --verbose n'écrit plus les diagnostics sur la sortie standard, où clients les lit sous forme de trames de protocole. (#1867)
  • La journalisation des erreurs n'est plus silencieuse pour le reste de la session après un appel generate_skill ou pack_remote_repository. (#1865)
  • grep_repomix_output formate désormais le contexte comme grep -C et gère de très grandes sorties. (#1869)

Un merci spécial à @sxh313 pour leur première contribution ! 🎉

Renforcement de la sécurité 🔒

MCP pack_codebase exécute toujours l'analyse secrète (#1960)

Un repomix.config.json dans le répertoire compressé pourrait désactiver l'analyse secrète des packs MCP avec security.enableSecurityCheck: false. L'analyse s'exécute désormais toujours pour les packs MCP ; Les exécutions simples de CLI suivent toujours le fichier de configuration.

##Documentations 📚

La documentation MCP indique maintenant que sans --sandbox, pack_codebase trust place le repomix.config.* dans le répertoire qu'il contient, tout comme y exécuter le CLI. Utilisez --sandbox lorsque votre assistant peut compresser des répertoires non rust, tels que des référentiels tiers clonés. (#1961)

Voir Serveur MCP : Mode Sandbox et Pourquoi un fichier de configuration est du code.

Comment mettre à jour

npm update -g repomix

Comme toujours, si vous avez des problèmes ou des suggestions, veuillez nous en informer sur les problèmes de GitHub ou sur notre [communauté Discord] (https://discord.gg/wNYzTwZFku).

repomix v1.19.0

This release moves the MCP server to SDK v2 with live progress and cancellation, makes --compress output far more accurate, and brings a big round of bug fixes from first-time contributors!

What's New 🚀

MCP Server on SDK v2 and the 2026-07-28 Protocol (#1952, #1954)

The MCP server now runs on the MCP TypeScript SDK v2. Clients that support the 2026-07-28 protocol negotiate it automatically, and existing clients work as before.

  • The server exits cleanly when the client closes stdin, so no repomix --mcp processes are left behind.
  • The install pulls in about half as many packages (171 to 84), since the v1 SDK brought HTTP transport dependencies such as Express that the stdio-only server never used.

For client authors: tool schemas now declare JSON Schema 2020-12 (bodies unchanged), and validation errors no longer start with MCP error -32602: .

MCP: Progress and Cancellation for Long-Running Packs (#1955, #1958)

pack_codebase, pack_remote_repository and generate_skill now send notifications/progress when the client passes a progressToken, so long packs show live status, and clients that reset their timeout on progress no longer cut them off. In --sandbox mode, messages carry only the stage name, never a host path.

Cancelling a call or disconnecting now stops the pack and cleans up its partial output.

Improvements ⚡

More Accurate --compress Output (#2003)

Golden tests for every supported language exposed a set of bugs, now fixed:

  • Code from function bodies no longer leaks into the output as if it were a declaration.
  • Duplicate lines are removed.
  • Declarations that were silently dropped are kept, such as C/C++ typedef and #define, C# and Java fields, Rust struct fields, Ruby attr_* calls and CSS at-rules.

Output changes for C, C++, C#, CSS, Dart, Go, Java, JavaScript/TypeScript, Ruby, Rust, Swift and Vue. If you rely on --compress in a pipeline, expect a diff from v1.18.

Skill Generation: Better Tech-Stack Detection (#1995)

--skill-generate now reads dependencies from Gradle Kotlin DSL (build.gradle.kts) and from the PEP 621 and Poetry forms of pyproject.toml.

Warning When a Remote URL Path Is Ignored (#1980, #1984, #433)

A URL like https://github.com/owner/repo/tree/main/src/shared packed the whole repository and silently dropped the path. Repomix now warns and suggests an --include pattern:

The path "src/shared" in the remote URL is ignored, and the whole repository will be packed.
To pack only that path, add: --include "src/shared/**"

Bug Fixes 🐛

Ignore Patterns Ending in a Wildcard Now Exclude Files (#1963, #1876, #320)

Patterns such as **/npm-debug.log* and **/repomix-output.* only excluded directory contents, so files like npm-debug.log.1 and docs/repomix-output.xml slipped into the output. They are now excluded. Nothing that was excluded before becomes included.

.git/info/exclude Follows Git's Matching Rules (#1871, #1870)

A slash-free pattern such as secret.txt now matches at any depth, as in Git, so sub/secret.txt is no longer packed.

Special thanks to @sxh313 for this contribution! 🎉

Negated Custom Ignore Patterns No Longer Invert (#1975, #400)

!main.ts in ignore.customPatterns or --ignore excluded main.ts instead of re-including it. Negated patterns are now skipped with a warning until proper support lands (#400).

Split Output Files No Longer Packed into the Next Run (#1921, #1920)

With --split-output, files like repomix-output.1.xml from a previous run are no longer picked up as input.

Special thanks to @lorenzozanee for their first contribution! 🎉

--remove-comments Keeps URLs in CSS, SCSS, Less, Vue and Svelte (#1912, #1965, #1911)

url(http://example.com/logo.png) was cut to url(http: because // was treated as a comment. Each language now uses its own comment rules, and Vue and Svelte files are handled per <script>, <style> and markup section.

Special thanks to @plox-sumit for their first contribution! 🎉

Non-ASCII File Names in Git Logs and Diffs (#1940, #1979)

Names like 日本語.txt no longer appear as "\346\227\245..." in git logs and diffs, and output.git.sortByChanges now sorts these files correctly.

Special thanks to @feiiiiii5 for their first contribution! 🎉

--token-count-tree 0 Shows the Full Tree (#1941)

It printed nothing before; it now shows every file.

Special thanks to @feiiiiii5 for this contribution! 🎉

Nested --stdin Paths on Windows (#1922)

Piping paths such as src/(routes)/page[1].ts into repomix --stdin on Windows packed only root-level files. Nested paths now match.

Special thanks to @lux-liang for their first contribution! 🎉

Fatal Errors Visible Under --quiet and --stdout (#1875, #1874)

A failed pack under --quiet or --stdout exited with code 1 and printed nothing. The error now goes to stderr.

Special thanks to @sxh313 for this contribution! 🎉

MCP Server Fixes (#1867, #1866, #1865, #1864, #1869, #1868)

  • --mcp --verbose no longer writes diagnostics to stdout, where clients read them as protocol frames. (#1867)
  • Error logging is no longer silenced for the rest of the session after a generate_skill or pack_remote_repository call. (#1865)
  • grep_repomix_output now formats context like grep -C and handles very large outputs. (#1869)

Special thanks to @sxh313 for their first contribution! 🎉

Security Hardening 🔒

MCP pack_codebase Always Runs the Secret Scan (#1960)

A repomix.config.json in the packed directory could turn off the secret scan for MCP packs with security.enableSecurityCheck: false. The scan now always runs for MCP packs; plain CLI runs still follow the config file.

Documentation 📚

The MCP docs now state that without --sandbox, pack_codebase trusts the repomix.config.* in the directory it packs, just like running the CLI there. Use --sandbox when your assistant may pack untrusted directories, such as cloned third-party repositories. (#1961)

See MCP Server: Sandbox Mode and Why a config file is code.

How to Update

npm update -g repomix

As always, if you have any issues or suggestions, please let us know on GitHub issues or our Discord community.
