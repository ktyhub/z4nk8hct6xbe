🗂 Plusieurs espaces de travail

L'agent n'est plus lié à un seul répertoire : vous pouvez configurer plusieurs espaces de travail de projet et attribuer le sien à chaque session. Disponible à la fois dans la console Web et sur le bureau client :

  • Espaces de travail multiples : créez ou ouvrez n'importe quel répertoire en tant qu'espace de travail de projet ; les documents, les pages Web et le code produits par l'agent y sont créés et gérés.
  • Espace de travail par session : chaque session est liée à son propre espace de travail de projet, de sorte que les tâches exécutées côte à côte restent à l'écart les unes des autres.
  • Modèle par session : changez de modèle pour une seule session ; les nouvelles sessions démarrent à partir de la valeur par défaut globale.
  • Sessions groupées : la liste des sessions est regroupée par espace de travail, avec épinglage, réorganisation, renommage et suppression.
  • Ressources système partagées : la mémoire, les compétences et la base de connaissances résident toujours dans l'espace de travail système (~/cow par défaut).

🔐 Modes d'autorisation

Les sessions disposent désormais de leur propre mode d'autorisation, qui fonctionne avec les espaces de travail pour contrôler jusqu'où l'agent peut atteindre :

  • Trois niveaux : lecture seule, espace de travail-écriture et accès complet, définis indépendamment pour chaque session.
  • Mode par défaut : choisissez un mode d'autorisation par défaut et les nouvelles sessions démarrent avec celui-ci.
  • Refus actionnables : lorsqu'un appel d'outil est bloqué, l'indice est clickable afin que vous puissiez ajuster l'autorisation sur place.
<img src="https://cdn.jsdelivr.net/gh/zhayujie/cowagent-assets@main/screenshots/en/web-console-access-mode.png" width="600" />

🖥 Bureau Client

  • Saisie vocale : un bouton vocal dans la saisie du chat retranscrit ce que vous dites directement dans la case ; la reconnaissance et la synthèse vocales fonctionnent également avec des fournisseurs et des modèles personnalisés. Merci @chimyves (#3052, #3050)
  • Brouillons conservés : quitter la page de discussion et revenir ne perd plus le texte et les pièces jointes non envoyés. Merci @chimyves (#3040)
  • Lancer à la connexion : une nouvelle bascule dans les paramètres système, désactivée par défaut.
  • Diagnostics de démarrage : lorsque le backend ne démarre pas, le client signale ce qui s'est réellement passé au lieu d'une erreur générique.
  • Téléchargement du journal : la page du journal d'exécution peut télécharger le fichier journal, et les téléchargements locaux ont obtenu des tentatives et des erreurs plus claires.

Télécharger : [Bureau CowAgent] (https://cowagent.ai/download/)

🔔 Notifications de tâches

La console Web et le bureau client émettent tous deux une notification (avec un son) lorsqu'une exécution d'agent se termine ou échoue, afin que vous puissiez abandonner une longue tâche :

  • Les deux clients : notifications du système d'exploitation sur le bureau, notifications du navigateur sur le Web, uniquement lorsque la fenêtre n'est pas active. Cli Un simple clic vous ramène à la session.
  • Badge non lu : l'onglet Web affiche un nombre de non lus alors qu'il est masqué, effacé une fois que vous revenez.
  • Bascules séparées : les notifications et le son sont deux commutateurs indépendants, tous deux activés par défaut. Annuler soi-même une tâche ne déclenche plus de notification d'échec.

Merci @chimyves (#3056, #3055)

🤖 Mises à jour des modèles

  • Nouveaux modèles : glm-5.3, qwen3.8-max, gemini-3.7-flash et gemini-3.6-flash, chacun étant défini par défaut par son fournisseur.
  • Page de configuration fusionnée : la console Web replie la page Modèles dans Config, divisée en un onglet De base et un onglet Modèles, donc il y a moins de sauts.
  • Corrections d'appels : correction de la pensée forcée du GLM-5.3, ainsi que du routage et de la gestion des URL de base pour certains modèles DashScope ; les modèles personnalisés apparaissent désormais dans le sélecteur de modèles de session.

🛠 Améliorations et correctifs

  • Affichage des images : correction des images de chemin local et des images de chemin relatif dans les documents de connaissances qui ne sont pas rendues ; sur le bureau, clicking une image dans une discussion ou un document la zoome sur place. Merci @chimyves (#3046)
  • Lecteurs Windows : correction du sélecteur de dossier ne répertoriant pas les lecteurs sous Windows. Merci @CNXudiandian (#3048)
  • Conseils du shell Windows : meilleurs conseils de récupération lorsqu'une commande shell échoue sous Windows. Merci @dajiaohuang (#3065)
  • Réponses de messagerie instantanée plus propres : les réponses des agents sur les canaux de messagerie instantanée ne contiennent plus de contenu réfléchi. Merci @LHMQ878 (#3044)
  • Tâches planifiées : correction d'une tâche qui échouait avant minuit et ne revenait jamais dans les délais (Merci @chimyves #3054), et les tâches planifiées étaient reconnues au lieu d'être exécutées.
  • Premier message plus rapide : initialisation simplifiée du système de mémoire afin qu'il ne bloque plus le premier message d'une session, réduisant ainsi sensiblement l'attente avant la réponse initiale.
  • Découpage du contexte : correction de la réponse de l'IA qui n'était pas enregistrée lorsque le contexte était découpé.
  • Chaîne Feishu : la carte de streaming accumule désormais du texte au fil des tours.
  • Docker : config.json survit aux mises à niveau des conteneurs grâce au support COW_DATA_DIR.

📦 Comment mettre à niveau

  • Déploiement source : exécutez cow update pour une mise à niveau d'un click, ou extrayez le dernier code et redémarrez. Consultez le [guide de mise à niveau] (https://docs.cowagent.ai/guide/upgrade).
  • Desktop client : recherchez les mises à jour et mettez à jour avec un click dans le client, ​​ou obtenez la dernière version à partir de la [page de téléchargement] (https://cowagent.ai/download/).

chatgpt-on-wechat 2.1.7

Highlights

  • Workspace isolation — Sessions can now be bound to separate project directories in both Web and desktop, keeping generated documents, pages, and code from colliding across parallel tasks. Memory, skills, and the knowledge base remain shared in the system workspace (~/cow by default). Automations that assume artifacts always land in ~/cow should explicitly select the intended workspace.
  • Per-session permissions — Read-only, workspace-write, and full-access modes are configurable per session, with a default for new sessions and clickable denial hints for adjusting access inline. Use workspace-write when the Agent needs to modify project files without broader host access; reserve full-access for tasks that genuinely require it.
  • Model behavior and selection — Provider defaults change to glm-5.3, qwen3.8-max, gemini-3.7-flash, and gemini-3.6-flash. Since new sessions inherit the global default, pin a per-session model when reproducibility matters. Custom models now appear in the picker; GLM-5.3 forced-thinking and DashScope routing/base-URL issues are fixed.
  • Desktop and background-run UX — Desktop voice input supports custom speech providers and models (#3052, #3050), while drafts and attachments survive navigation (#3040). Web and desktop notify on completion or failure only while unfocused, with click-through and independent notification/sound switches; manual cancellation no longer triggers a failure alert (#3055, #3056).
  • Reliability and deployment — Scheduled tasks recover after midnight failures and no longer stop at acknowledgement (#3054); replies are saved after context trimming, and memory initialization no longer blocks the first response. IM replies omit thinking content (#3044), while Feishu streaming cards accumulate across turns. Upgrade source installs with cow update or pull and restart, desktop through its updater, and mount COW_DATA_DIR in Docker to preserve config.json.
  • Compatibility — No explicit breaking changes are listed.

🗂 Multiple Workspaces

The Agent is no longer tied to a single directory — you can set up several project workspaces and give each session its own. Available in both the Web console and the desktop client:

  • Multiple workspaces: create or open any directory as a project workspace; the documents, web pages, and code the Agent produces are created and managed there.
  • Per-session workspace: each session is bound to its own project workspace, so tasks running side by side stay out of each other's way.
  • Per-session model: switch the model for a single session; new sessions start from the global default.
  • Grouped sessions: the session list is grouped by workspace, with pinning, reordering, renaming, and deleting.
  • Shared system resources: memory, skills, and the knowledge base still live in the system workspace (~/cow by default).
<img src="https://cdn.jsdelivr.net/gh/zhayujie/cowagent-assets@main/screenshots/en/web-console-workspace-project-demo.png" width="800" />

Docs: Workspace

🔐 Permission Modes

Sessions now carry their own permission mode, which works together with workspaces to control how far the Agent can reach:

  • Three levels: read-only, workspace-write, and full-access, set independently for each session.
  • Default mode: pick a default permission mode, and new sessions start with it.
  • Actionable denials: when a tool call is blocked, the hint is clickable so you can adjust the permission on the spot.
<img src="https://cdn.jsdelivr.net/gh/zhayujie/cowagent-assets@main/screenshots/en/web-console-access-mode.png" width="600" />

🖥 Desktop Client

  • Voice input: a voice button in the chat input transcribes what you say straight into the box; speech recognition and synthesis also work with custom providers and models. Thanks @chimyves (#3052, #3050)
  • Drafts kept: leaving the chat page and coming back no longer loses unsent text and attachments. Thanks @chimyves (#3040)
  • Launch at login: a new toggle in system settings, off by default.
  • Startup diagnostics: when the backend fails to start, the client reports what actually went wrong instead of a generic error.
  • Log download: the run-log page can download the log file, and local uploads gained retries and clearer errors.

Download: CowAgent Desktop

Docs: Desktop Client

🔔 Task Notifications

The Web console and the desktop client both raise a notification (with a sound) when an Agent run finishes or fails, so you can walk away from a long task:

  • Both clients: OS notifications on the desktop, browser notifications on the Web — only while the window isn't focused. Clicking one takes you back to the session.
  • Unread badge: the Web tab shows an unread count while it's hidden, cleared once you switch back.
  • Separate toggles: notifications and the sound are two independent switches, both on by default. Cancelling a task yourself no longer triggers a failure notification.

Thanks @chimyves (#3056, #3055)

🤖 Model Updates

  • New models: glm-5.3, qwen3.8-max, gemini-3.7-flash, and gemini-3.6-flash, each set as its provider's default.
  • Merged config page: the Web console folds the Models page into Config, split into a Basic and a Models tab, so there's less jumping around.
  • Call fixes: fixed GLM-5.3's forced thinking, plus routing and base-URL handling for some DashScope models; custom models now show up in the session model picker.

🛠 Improvements & Fixes

  • Image display: fixed local-path images and relative-path images inside knowledge docs not rendering; on the desktop, clicking an image in a chat or a document zooms it in place. Thanks @chimyves (#3046)
  • Windows drives: fixed the folder picker not listing drives on Windows. Thanks @CNXudiandian (#3048)
  • Windows shell guidance: better recovery guidance when a shell command fails on Windows. Thanks @dajiaohuang (#3065)
  • Cleaner IM replies: Agent replies on IM channels no longer carry thinking content. Thanks @LHMQ878 (#3044)
  • Scheduled tasks: fixed a task that failed across midnight never getting back on schedule (Thanks @chimyves #3054), and scheduled tasks being acknowledged instead of run.
  • Faster first message: streamlined memory system initialization so it no longer blocks a session's first message, noticeably cutting the wait before the initial reply.
  • Context trimming: fixed the AI reply not being saved when the context was trimmed.
  • Feishu channel: the streaming card now accumulates text across turns.
  • Docker: config.json survives container upgrades through the COW_DATA_DIR mount.

📦 How to Upgrade

  • Source deployment: run cow update for a one-click upgrade, or pull the latest code and restart. See the upgrade guide.
  • Desktop client: check for updates and update with one click inside the client, or get the latest version from the download page.
