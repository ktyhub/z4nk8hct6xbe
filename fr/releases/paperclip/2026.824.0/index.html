Papierclip v2026.824.0

Sortie : 2026-08-24

Paperclip v2026.824.0 est une suite rapide de 2026.817.0 — et la première écurie à parcourir le canari complet → tous les soirs → bêta → chemin heureux stable de bout en bout, s'imprégnant comme 2026.818.0-beta.1 avant la promotion. Il comporte 172 validations : les tâches de type chat passent de l'expérience à l'expérience par défaut, les aperçus d'exécution gérés deviennent accessibles via Tailscale HTTPS, l'exécution du bac à sable obtient un contrat de capacité de fournisseur vérifié, vous pouvez vous connecter à Claude et au Codex depuis l'intérieur du produit, les importations de grandes entreprises survivent aux connexions interrompues et un grand lot de correctifs communautaires de longue date arrive.

Modifications radicales

Aucun de ces éléments ne nécessite d'action pour une installation standard, mais lisez attentivement avant la mise à niveau :

  • Les tâches de style chat sont les tâches par défaut. La bascule d'expérience « Tâches de style chat » a disparu ; la page de détail de la tâche est désormais la vue de conversation pour tout le monde. Une nouvelle préférence "Interface de tâches classique" (enableClassicTaskInterface, remplaçant enableTaskChatRedesign dans les paramètres de l'instance) restaure la page de pré-chat - en-tête au niveau de la page, fil de commentaires simple, barre latérale Propriétés fixe - mais les fonctionnalités de chat uniquement n'y sont pas disponibles. (#11101)
  • Le streaming de sortie de session Sandbox est désormais axé sur les capacités et trois indicateurs d'opérateur ont disparu. Le paramètre streamAgentSessionOutput du serveur et les clés useSessions et useLogStream du plugin Daytona n'existent plus ; l’instantané de capacité du fournisseur vérifié est la seule décision de streaming, avec un retour d’interrogation automatique. Les configurations enregistrées qui contiennent toujours les clés supprimées se chargent correctement : les clés sont simplement inertes. (#11463, #11557)
  • Les environnements d'exécution de développement gérés sont désormais par défaut les aperçus HTTPS Tailscale. Lorsque le courtier hôte est disponible, les environnements d'exécution d'arbre de travail gérés par Paperclip éligibles sont exposés en tant que tailscale_https au lieu de HTTP de bouclage. Définissez PAPERCLIP_MANAGED_RUNTIME_HTTPS=off pour conserver l'ancien comportement, ou force pour qu'il soit fermé en cas d'échec lorsque le courtier est manquant. Les routes de contrôle d'exécution gérées ont également obtenu deux nouvelles réponses 409 (workspace_runtime_control_in_progress, workspace_runtime_lease_conflict) : les appelants qui supposaient qu'un contrôle démarre toujours doivent gérer un conflit. (#11524, #11525)
  • La politique de résolution d'interaction est par défaut anyone pour les nouvelles interactions. Chaque type d'interaction passe désormais par un évaluateur de politique de résolution avec une provenance enregistrée, au lieu de règles par route qui bloquaient les agents valides. La migration 0218 n'élargit délibérément pas ce qui est déjà en attente : les lignes existantes conservent leurs anciennes restrictions sous de nouveaux noms (board_or_agents → not_creator, board_only → human_only). (#11376)
  • Les surfaces d'entraînement aux décisions sont supprimées du bureau Décisions : l'itinéraire de la bibliothèque d'entraînement, les actions de ligne et le tiroir. Le contrat d’instantané backend reste inchangé et aucune migration de données n’est exécutée. (#11225)

Faits saillants

  • Tâches de style chat, désormais l'expérience par défaut — La vue de conversation expérimentale de la dernière version correspond désormais au fonctionnement de chaque tâche, et elle a grandi au fil du temps : un espacement des messages et des bulles d'agent plus propres, une affectation consultable et l'arborescence des sous-tâches dans le volet des propriétés, des commentaires de document ancrés dans une gouttière latérale et une barre latérale de discussion qui fait apparaître chaque document de problème et artefact d'agent. Les tâches bloquées affichent leurs bloqueurs sous forme de liens avec un bloqueur ordonné et en direct directement dans le fil de discussion, et un problème avec une exécution en direct affiche un avis calme en vol au lieu d'une fausse alarme. L'intégration se fait également par chat : terminer l'assistant vous amène directement dans la conversation de votre première tâche, où l'agent vous accueille, vous pose des questions de clarification et propose un plan que vous approuvez élément par élément. (#11101, #11263, #11226, #11456, #11487, #11423)
  • Aperçus HTTPS pour les environnements d'exécution gérés, sur Tailscale : un service d'exécution géré utilisé pour écouter sur du HTTP en boucle simple, de sorte que l'aperçu de la branche d'un agent était inaccessible depuis un téléphone ou un deuxième ordinateur. Paperclip peut désormais l'exposer à une véritable URL HTTPS sur votre tailnet, construite en trois couches délibérées : un courtier d'hôte distinct de moindre privilège qui autorise chaque mappage (informations d'identification homologues, plage de ports fixe, refus de ports protégés, audit en ajout uniquement), le cycle de vie de l'exposition avec des baux d'exécution durables appartenant au problème et une récupération de contrôle limitée afin qu'un contrôle bloqué ne puisse jamais bloquer la voie pour toujours, et un médiateur de paire de ports unique afin qu'un démarrage ne puisse jamais entrer en collision avec ou adoptez le service d'un autre problème - chaque inadéquation échoue et nomme le conflit. (#11524, #11525, #11526)
  • Connectez-vous à Claude et au Codex depuis Paperclip — La page du nouvel agent propose désormais une connexion par abonnement à Claude avant de créer l'agent, sur les deux voies de test, avec des diagnostics conservés dans les journaux de serveur expurgés et des URL de connexion normalisées pour les hôtes Anthropic sur liste autorisée. Sous le capot, un flux de jetons de configuration gardé conduit claude setup-token via un pseudo-terminal sandbox avec des sessions liées au propriétaire et une livraison de jeton unique, et l'adaptateur Codex obtient une connexion de périphérique sandbox équivalente qui promeut les informations d'identification uniquement après les vérifications de préparation, puis supprime le bac à sable temporaire. Les déploiements derrière une plate-forme de terminaison TLS (Railway, Render, Fly,…) peuvent déclarer CLAUDE_LOGIN_EDGE_TLS_TERMINATED=true afin que le gardien de transport cesse d'avertir l'utilisateur d'une connexion HTTPS et qu'un identifiant de connexion à l'appareil promu survit désormais au réamorçage de la maison gérée. (#11347, #11286, #11237, #11579, #11578)
  • Un véritable contrat de capacité pour les fournisseurs de sandbox — La dernière version a introduit le streaming de sortie en direct et les sessions persistantes pour Daytona ; cette version rend ces comportements prouvables au lieu d'être configurés. Les fournisseurs déclarent les capacités dans leur manifeste, le travailleur en direct les vérifie et le serveur résout l'ensemble effectif fermé en cas d'échec comme l'intersection de déclaré, vérifié et configuré - une capacité déclarée ne peut jamais accorder une méthode que le travailleur n'a pas prouvée. Les sessions de streaming et persistantes s'activent désormais partout où l'instantané vérifié le permet, avec un retour d'interrogation automatique, et les trois indicateurs d'opérateur qui les contrôlaient ont disparu (voir Modifications récentes). (#11463, #11557)
  • Importations d'entreprise fragmentées et pouvant être reprises : la dernière version a augmenté le plafond d'importation à 1 Go ; cette version en rend le transfert digne. Une connexion interrompue à 90 % était utilisée pour recommencer l'intégralité du téléchargement : les importations se déplacent désormais comme vérifié, des parties d'environ 32 Mo mises en file d'attente sur le disque avec un registre d'exécution durable, de sorte qu'un transfert interrompu reprend à partir des parties déjà téléchargées (à travers les connexions interrompues, les actualisations de page et les redémarrages du serveur) et la mémoire de téléchargement maximale tombe à une partie. La page d'importation et CLI ont obtenu le téléchargement avec reprise et un aperçu fragmenté, les ensembles préservent désormais les horodatages et la hiérarchie des tâches via l'exportation/importation, les agents importés conservent leur propre adaptateur au lieu d'être contraints à l'adaptateur CEO de la destination, et les tâches fraîchement importées restent inactives lors de l'examen de la productivité. (#11223, #11224, #11193, #11192, #11191)

Améliorations

  • L'intégration vous rejoint là où vous êtes — Une entreprise sans agent est automatiquement envoyée en intégration, s'ouvrant à la bonne étape : l'étape de la mission est ignorée lorsque l'entreprise en a déjà une, une mission existante est transférée dans l'assistant et l'étape est décidée une seule fois au lieu de passer sous un client à mi-parcours. Les étapes de l'agent et du modèle de connexion de l'assistant ont été retravaillées pour le flux de discussion en premier, ne conservent plus un adaptateur désactivé invisible sélectionné et le panneau décoratif suit votre thème. (#11352, #11416, #11429, #11371, #11379)
  • Paperclip Cloud onboarding seed — Une instance peut désormais recevoir la mission, le premier agent et la première tâche collectés lors de l'inscription à Paperclip Cloud et les appliquer lors de l'activation, de sorte qu'une pile prédéfinie s'ouvre prête à fonctionner au lieu de demander à nouveau. (#11098)
  • Déploiements sandbox gérés — Les locataires peuvent modifier les variables d'environnement dans un environnement sandbox géré par la plateforme (et uniquement celui-ci), et un mode sandbox géré uniquement masque entièrement l'exécution locale et la sélection d'exécution échoue. Les variables d'environnement d'identification documentées des fournisseurs groupés (par exemple DAYTONA_API_KEY) atteignent désormais leurs plugins, et l'option synthétique par défaut "Local" respecte le mode. (#11200, #11244)
  • Le travail archivé rouvre sur place — Un espace de travail d'exécution isolé archivé peut être rouvert là où il se trouvait, y compris les arbres de travail git archivés pour les projets à extraction gérée. Les arrivées froides sur l'URL d'une entreprise archivée sont renvoyées vers une page claire avec une désarchive one-click. (#11322, #11395, #11302)
  • Gouvernance de révision — Les verdicts de politique de révision sont sérialisés et transactionnels, un verdict ne peut plus contourner une politique en la déclassant, le demandeur est persistant de manière atomique et l'interface utilisateur attribue un badge à la politique de révision lorsqu'elle restreint l'approbation. (#11405, #10938)
  • Les agents peuvent rechercher des secrets par nom — Un point de terminaison /secrets/catalog en lecture seule mappe les noms secrets aux identifiants pour les agents câblant les liaisons d'environnement — aucune valeur, aucune configuration de fournisseur. Les annotations des documents problématiques sont également incluses dans le contexte de révision par l'agent, de sorte que les commentaires laissés sur un document parviennent à l'agent qui agit sur celui-ci. (#9530, #11332)
  • Recherche évolutive — Le sélecteur de problèmes parent recherche sur le serveur au lieu de la page chargée, et la liste de problèmes API a obtenu un filtre updatedSince. (#11334, #9050)
  • Observabilité — Les étapes stage.sync côté hôte sont instrumentées et l'étendue du processus de l'agent est correctement hébergée, poursuivant ainsi le travail de traçage du démarrage du bac à sable de la dernière version. (#11301)
  • Voir votre chaîne avec paperclipai channels — la nouvelle commande affiche chaque voie de version (stable, bêta, nocturne, canari), la version à laquelle chacune est actuellement résolue et celle suivie par votre installation. (#11210)

Correctifs

  • Les déploiements derrière un proxy d'authentification fonctionnent de bout en bout — Le WebSocket d'événements en direct authentifie désormais les navigateurs proxy cloud (auparavant, il ne pouvait jamais se connecter via un proxy de terminaison d'authentification), la récupération de secours du service worker répond toujours avec un vrai Response au lieu d'une page vierge, le manifeste de l'application Web est récupéré avec les informations d'identification et l'interface utilisateur survit au premier chargement contre un backend froid. Le ping-pong de sélection d'entreprise archivée qui pouvait piéger une session dans une boucle de redirection a disparu. (#11290, #11292, #11245, #11246, #11300) - Tout est limité au compte connecté : les contrôles d'adhésion aux invitations, la sélection de l'entreprise et les caches de requêtes sont tous associés au compte réellement connecté, les caches sont effacés à la déconnexion et l'entreprise stockée survit à un échec de demande de l'entreprise au lieu d'être supprimée. Les brouillons d'intégration vérifient la propriété par rapport à une liste récupérée cette session et ne restaurent jamais l'état de l'assistant pour une entreprise que l'utilisateur ne possède pas. (#11417, #11430, #11380, #11477, #11382, #11370)
  • Renforcement de la sécurité — Les routes d'accès aux outils ne divulguent plus les oracles d'identification entre locataires, les webhooks de routine rejettent les rediffusions HMAC, les réponses détaillées de routine excluent la configuration du responsable, les informations d'identification du téléchargeur de publication de page sont limitées à l'assistant de publication, les résumés de l'espace de travail d'exécution sont isolés, seuls les liens de fichiers de l'espace de travail accessibles sont mis en évidence, le commentaire de secours ne peut jamais publier une transcription brute et les instructions CLI présentées aux utilisateurs passent par le coffre-fort. Formulaire npx. (#9589, #9994, #9818, #10894, #10790, #11090, #10143, #11343, #11400)
  • Les exécutions conservent leur contexte — Les sessions d'agent sont réutilisées lors des transferts d'exécution et conservées dans les commentaires de problème, les décisions de réveil des commentaires lisent l'état du problème après l'insertion, les réveils de commentaires de fermeture obsolètes sur les problèmes résolus s'arrêtent, la récupération de transfert réussie ignore les exécutions pilotées par les actions de récupération et gérées par les plugins, et les corrections du cycle de vie des exécutions ACP règlent les échecs, synchronisent les espaces de travail et nettoient correctement les baux. (#9917, #10111, #10068, #8656, #9010, #9047, #11454)
  • Résilience de plomberie sandbox — La course aux fichiers stdin sandbox est clôturée avec des écritures atomiques et un interrogateur tolérant aux pannes, les écritures stdin sont ordonnées dans le pont de processus-session, la boucle d'interrogation du pont de rappel a un délai d'attente par itération et un chien de garde, le trafic est transféré vers l'origine d'écoute locale, les itinéraires de la compétence d'embauche d'agent passent le pont de rappel, les exécutions qui frappent une fenêtre de redémarrage du travailleur du fournisseur réessayent au lieu d'échouer la configuration, les appels d'activité Daytona sont limités par appel, et syncOut accepte les listes d'archives bsdtar. (#11235, #11406, #11341, #10017, #8978, #10212, #11408, #11289)
  • Fiabilité de l'adaptateur — Claude canalise localement l'invite d'impression via stdin et n'échoue plus lors des sauts d'autorisation root uniquement ; Le Codex local ignore les avertissements stderr bénins lors de la dérivation d'une erreur de repli ; OpenCode réessaye le contrôle en amont de ses modèles en cas de conflit transitoire et traite la sonde de disponibilité comme non fatale ; Grok rapporte l'utilisation et le coût réels des jetons au lieu des zéros codés en dur ; Le nuage de curseur supprime un rappel API inaccessible ; l'embauche sur un adaptateur que l'instance ne peut pas exécuter est refusée ; et les adaptateurs se chargent sous Windows (pathToFileURL avant importation dynamique).   • Correctivité du serveur — DELETE /api/issues/:id réussit pour les problèmes avec les personnes à charge (commentaires et cascade d'état de lecture ; les enregistrements de coûts et financiers sont conservés avec leur référence de problème effacée), les références d'entreprise non UUID renvoient 404 au lieu de 500, les erreurs Zod entre packages sont reconnues, les bloqueurs de câblage dans un PATCH ne rouvrent plus implicitement un problème bloqué, les requêtes de demande d'abord non signées restent en dehors de la file d'attente de révision sans être annulées, le moissonneur de l'espace de travail du terminal cesse de mourir de faim sur ses candidats les plus anciens, le TTL par défaut JWT exécuté par l'agent est aligné sur les 48 heures documentées, de sorte que les exécutions d'ordinateurs portables suspendues cessent de se réveiller avec un identifiant expiré, un PAPERCLIP_API_URL explicite remplace l'URL d'exécution dérivée dans l'environnement d'exécution, les ports d'URL de base ne sont réécrits que pour les hôtes de bouclage et les sorties silencieuses non nulles dans la surface de flux Hermes sont des échecs. (#11331, #9959, #10168, #10269, #11338, #11238, #10176, #10339, #10258, #10107)
  • Les analyses Git de l'espace de travail sont limitées — Un planificateur limité fusionne et limite désormais chaque analyse Git coûteuse de l'espace de travail (une tempête de requêtes produisait autrefois environ 270 processus git status simultanés et des contrôles de santé affamés), et le navigateur ne démarre les analyses que lorsque le panneau de fichiers est ouvert et visible. (#11572)
  • Coupes de papier dans l'interface utilisateur — L'action d'interruption des messages en file d'attente est de retour, l'accès secret de l'agent a été déplacé vers un onglet de secrets consultable, les défilements de saisie semi-automatique à l'intérieur des boîtes de dialogue, l'archive de la boîte de réception a obtenu un toast d'annulation et les sous-tâches pliées sont mémorisées, le routage de la boîte de réception honore la politique enregistrée pour les cibles explicites, la prose d'approbation du conseil d'administration est rendue sous forme de démarque, les badges de création de dialogue utilisent le préfixe réel du problème, les liens profonds du document de problème acheminent correctement, les descriptions de problème tronquées sont signalées, les liens d'invitation générés préfèrent l'URL de base publique, le cycle de vie d'exécution sélectionné et les journaux restent à jour, et le chat de tâche mobile a obtenu des actions de blocage, un compositeur aligné sur le fil de discussion et une boîte de dialogue de nouvelle tâche qui reste au-dessus du clavier. Guide de mise à niveau

  • Migrations : cette version ajoute 11 migrations de bases de données (0212 à 0222), couvrant la première tâche d'intégration une par entreprise (0212), les exécutions de transfert d'entreprise pouvant être reprises (0213), les sessions de connexion aux appareils de l'adaptateur (0214, 0215), les graines d'intégration dans le cloud (0216), les politiques de clé étrangère de suppression de problèmes (0217), la politique de résolution d'interaction. valeurs par défaut et provenance (0218), état d'exposition à l'exécution (0219), baux d'exécution de l'espace de travail d'exécution (0220), sessions de jeton de configuration Claude (0221) et références de bail d'environnement qui survivent à la suppression de l'environnement (0222). Les migrations s'exécutent automatiquement au démarrage – aucune action manuelle n'est requise. Rien ne supprime une table ou ne supprime des données ; notez que 0218 réécrit les valeurs de stratégie de résolution sur les interactions en attente existantes (de manière conservatrice — voir Dernières modifications) et 0217/0222 modifient ce qui arrive aux lignes dépendantes lors de la suppression.
  • Nouvelles variables d'environnement facultatives (toutes ont des valeurs par défaut raisonnables ; définies uniquement si vous en avez besoin) :
    • PAPERCLIP_MANAGED_RUNTIME_HTTPS — auto (par défaut), off ou force ; contrôle la valeur par défaut Tailscale HTTPS pour les aperçus d’exécution gérés (voir Dernières modifications). PAPERCLIP_TAILSCALE_BROKER_SOCKET et PAPERCLIP_TAILSCALE_DNS_NAME remplacent le chemin du socket du courtier et le nom DNS tailnet ; PAPERCLIP_VITE_HMR_PROTOCOL (ws/wss) épingle le protocole HMR dev-preview. (#11524, #11525)
    • CLAUDE_LOGIN_TRUSTED_PROXIES — homologues proxy sur liste autorisée pour le garde de transport de connexion Claude ; CLAUDE_LOGIN_EDGE_TLS_TERMINATED=true — déclare la terminaison TLS à la périphérie de la plate-forme sur les plates-formes gérées où les adresses proxy ne sont pas connaissables. (#11286, #11579)
    • PAPERCLIP_ONBOARDING_SEED_ADAPTER_TYPE — type d'adaptateur pour l'agent créé par une graine d'intégration Cloud. (#11098)
    • SANDBOX_ORPHAN_CLEANUP_SPOOL_DIR — où les enregistrements de nettoyage durables du bac à sable sont mis en file d'attente ; PAPERCLIP_PROCESS_SESSION_STDIN_MAX_RETRIES — réessayez le plafond pour l'observateur standard du bac à sable. (#11347, #11235)
  • Clés de configuration supprimées : streamAgentSessionOutput (serveur) et useSessions / useLogStream (plugin Daytona) ne font plus rien — supprimez-les des configurations enregistrées à votre guise ; ils se chargent mais sont inertes. (#11557)
  • Agent run JWT TTL : la valeur par défaut du serveur correspond désormais aux 48 h documentées (PAPERCLIP_AGENT_JWT_TTL_SECONDS=172800). Si vous vous êtes appuyé sur l'ancienne expiration implicite d'une heure, définissez la variable explicitement. (#10176)
  • Aperçus HTTPS : pour les utiliser, installez Tailscale sur l'hôte et exécutez le nouveau courtier (voir le README @paperclipai/tailscale-https-broker) ; pour vous désinscrire, définissez PAPERCLIP_MANAGED_RUNTIME_HTTPS=off. Rien d'autre ne change pour les services non gérés ou personnalisés.

paperclip v2026.824.0

Paperclip v2026.824.0

Released: 2026-08-24

Paperclip v2026.824.0 is a fast follow to 2026.817.0 — and the first stable to walk the full canary → nightly → beta → stable happy path end to end, soaking as 2026.818.0-beta.1 before promotion. It carries 172 commits: chat-style tasks graduate from experiment to the default experience, managed runtime previews become reachable over Tailscale HTTPS, sandbox execution gains a verified provider capability contract, you can sign in to Claude and Codex from inside the product, large company imports survive dropped connections, and a large batch of long-standing community fixes lands.

Breaking Changes

None of these require action for a typical install, but read through before upgrading:

  • Chat-style tasks are the default. The "Chat-Style Tasks" experiment toggle is gone; the task detail page is now the conversation view for everyone. A new "Classic Task Interface" preference (enableClassicTaskInterface, replacing enableTaskChatRedesign in instance settings) restores the pre-chat page — page-level header, plain comment thread, fixed Properties sidebar — but chat-only features are unavailable there. (#11101)
  • Sandbox session-output streaming is now capability-driven, and three operator flags are gone. The server's streamAgentSessionOutput setting and the Daytona plugin's useSessions and useLogStream keys no longer exist; the verified provider capability snapshot is the only streaming decision, with an automatic poll fallback. Saved configurations that still carry the removed keys load fine — the keys are simply inert. (#11463, #11557)
  • Managed dev runtimes now default to Tailscale HTTPS previews. When the host broker is available, eligible Paperclip-managed worktree runtimes are exposed as tailscale_https instead of loopback HTTP. Set PAPERCLIP_MANAGED_RUNTIME_HTTPS=off to keep the old behavior, or force to fail closed when the broker is missing. Managed runtime control routes also gained two new 409 responses (workspace_runtime_control_in_progress, workspace_runtime_lease_conflict) — callers that assumed a control always starts must handle a conflict. (#11524, #11525)
  • Interaction resolver policy defaults to anyone for new interactions. Every interaction kind now goes through one resolver-policy evaluator with recorded provenance, instead of per-route rules that blocked valid agents. Migration 0218 deliberately does not widen anything already pending: existing rows keep their old restrictions under new names (board_or_agents → not_creator, board_only → human_only). (#11376)
  • The decision-training surfaces are removed from the Decisions desk — the training library route, row actions, and drawer. The backend snapshot contract is unchanged and no data migration runs. (#11225)

Highlights

  • Chat-style tasks, now the default experience — Last release's experimental conversation view is now how every task works, and it grew up on the way: cleaner message spacing and agent bubbles, searchable assignment and the sub-task tree in the properties pane, document comments docked in a side gutter, and a chat sidebar that surfaces every issue document and agent artifact. Blocked tasks show their blockers as links with live, ordered blocker work right in the thread, and an issue with a live run shows a calm in-flight notice instead of a false alarm. Onboarding is chat-first too: finishing the wizard drops you straight into your first task's conversation, where the agent greets you, asks clarifying questions, and proposes a plan you approve item by item. (#11101, #11263, #11226, #11456, #11487, #11423)
  • HTTPS previews for managed runtimes, over Tailscale — A managed runtime service used to listen on plain loopback HTTP, so an agent's branch preview was unreachable from a phone or a second computer. Paperclip can now expose it at a real HTTPS URL on your tailnet, built in three deliberate layers: a separate least-privilege host broker that authorizes every mapping (peer credentials, a fixed port range, protected-port denies, append-only audit), the exposure lifecycle with durable issue-owned runtime leases and bounded control recovery so a stranded control can never block the lane forever, and a single port-pair mediator so a start can never collide with or adopt another issue's service — every mismatch fails closed and names the conflict. (#11524, #11525, #11526)
  • Sign in to Claude and Codex from inside Paperclip — The new-agent page now offers Claude subscription login before you create the agent, on both Test lanes, with diagnostics kept in redacted server logs and login URLs normalized to allowlisted Anthropic hosts. Under the hood, a guarded setup-token flow drives claude setup-token through a sandbox pseudo-terminal with owner-bound sessions and one-time token delivery, and the Codex adapter gets an equivalent sandbox device-login that promotes the credential only after readiness checks and then deletes the temporary sandbox. Deployments behind a TLS-terminating platform edge (Railway, Render, Fly, …) can declare CLAUDE_LOGIN_EDGE_TLS_TERMINATED=true so the transport guard stops warning about a connection that is HTTPS to the user, and a promoted device-login credential now survives managed-home re-seeding. (#11347, #11286, #11237, #11579, #11578)
  • A real capability contract for sandbox providers — Last release introduced live output streaming and persistent sessions for Daytona; this release makes those behaviors provable instead of configured. Providers declare capabilities in their manifest, the live worker verifies them, and the server resolves the effective set fail-closed as the intersection of declared, verified, and configured — a declared capability can never grant a method the worker didn't prove. Streaming and persistent sessions now turn on wherever the verified snapshot allows, with an automatic poll fallback, and the three operator flags that used to gate them are gone (see Breaking Changes). (#11463, #11557)
  • Chunked, resumable company imports — Last release raised the import cap to 1 GB; this release makes the transfer worthy of it. A dropped connection at 90% used to start the whole upload over — imports now move as verified ~32 MB parts spooled to disk with a durable run ledger, so an interrupted transfer resumes from the parts already uploaded (across dropped connections, page refreshes, and server restarts) and peak upload memory drops to one part. The Import page and CLI gained the resumable upload and a chunked preview, bundles now preserve task timestamps and hierarchy through export/import, imported agents keep their own adapter instead of being coerced to the destination's CEO adapter, and freshly imported tasks stay quiescent under the productivity review sweep. (#11223, #11224, #11193, #11192, #11191)

Improvements

  • Onboarding meets you where you are — A company with no agent is sent into onboarding automatically, opening at the right step: the mission step is skipped when the company already has one, an existing mission is carried into the wizard, and the step is decided once instead of jumping under a mid-flow customer. The wizard's agent and connect-model steps were reworked for the chat-first flow, no longer keep an invisible disabled adapter selected, and the decorative panel follows your theme. (#11352, #11416, #11429, #11371, #11379)
  • Paperclip Cloud onboarding seed — An instance can now receive the mission, first agent, and first task collected during Paperclip Cloud signup and apply them at activation, so a seeded stack opens ready to work instead of asking again. (#11098)
  • Managed sandbox deployments — Tenants can edit environment variables on a platform-managed sandbox environment (and only that), and a managed-sandbox-only mode hides local execution entirely with run selection failing closed. Bundled providers' documented credential env vars (e.g. DAYTONA_API_KEY) now reach their plugin workers, and the synthetic "Local" default option respects the mode. (#11200, #11244)
  • Archived work reopens in place — An archived isolated execution workspace can be reopened where it was, including archived git worktrees for managed-checkout projects. Cold arrivals on an archived company's URL are bounced to a clear page with a one-click Unarchive. (#11322, #11395, #11302)
  • Review governance — Review-policy verdicts are serialized and transactional, a verdict can no longer bypass a policy by downgrading, the requester is persisted atomically, and the UI badges the review policy when it is what constrains approval. (#11405, #10938)
  • Agents can look up secrets by name — A read-only /secrets/catalog endpoint maps secret names to ids for agents wiring env bindings — no values, no provider config. Issue-document annotations are also included in agent review context, so feedback left on a document reaches the agent that acts on it. (#9530, #11332)
  • Search that scales — The parent-issue picker searches on the server instead of the loaded page, and the issues list API gained an updatedSince filter. (#11334, #9050)
  • Observability — Host-side stage.sync steps are instrumented and the agent process span is homed correctly, continuing last release's sandbox-startup tracing work. (#11301)
  • See your channel with paperclipai channels — the new command shows every release lane (stable, beta, nightly, canary), the version each currently resolves to, and which one your install follows. (#11210)

Fixes

  • Deployments behind an authenticating proxy work end to end — The live-events WebSocket now authenticates cloud-proxied browsers (previously it could never connect through an auth-terminating proxy), the service worker's fetch fallback always answers with a real Response instead of a blank page, the web app manifest is fetched with credentials, and the UI survives first load against a cold backend. The archived-company selection ping-pong that could trap a session in a redirect loop is gone. (#11290, #11292, #11245, #11246, #11300)
  • Everything is scoped to the signed-in account — Invite membership checks, company selection, and query caches are all keyed to the account that is actually signed in, caches clear on sign-out, and the stored company survives a failed company request instead of being dropped. Onboarding drafts verify ownership against a list fetched this session and never restore wizard state for a company the user does not own. (#11417, #11430, #11380, #11477, #11382, #11370)
  • Security hardening — Tool-access routes no longer leak cross-tenant ID oracles, routine webhooks reject HMAC replays, routine detail responses exclude assignee configuration, page-publish uploader credentials are scoped to the publish helper, execution workspace summaries are isolated, only accessible workspace file links are highlighted, the heartbeat-fallback comment can never publish a raw transcript, and CLI guidance shown to users goes through the safe npx form. (#9589, #9994, #9818, #10894, #10790, #11090, #10143, #11343, #11400)
  • Runs keep their context — Agent sessions are reused across execution handoffs and kept across issue comments, comment-wake decisions read post-insert issue state, stale closure-comment wakeups on done issues stop, successful-run handoff recovery skips recovery-action-driven and plugin-managed runs, and ACP run lifecycle corrections settle failures, sync workspaces back, and clean up leases properly. (#9917, #10111, #10068, #8656, #9010, #9047, #11454)
  • Sandbox plumbing resilience — The sandbox stdin file race is closed with atomic writes and a fault-tolerant poller, stdin writes are ordered in the process-session bridge, the callback bridge poll loop has a per-iteration timeout and watchdog, bridge traffic forwards to the local listen origin, the agent-hire skill's routes pass the callback bridge, runs that hit a provider worker restart window retry instead of failing setup, Daytona liveness calls are bounded per call, and syncOut accepts bsdtar tarball listings. (#11235, #11406, #11341, #10017, #8978, #10212, #11408, #11289)
  • Adapter reliability — Claude local pipes the print prompt via stdin and no longer fails root-only permission skips; Codex local skips benign stderr warnings when deriving a fallback error; OpenCode retries its models preflight under transient contention and treats the availability probe as non-fatal; Grok reports real token usage and cost instead of hardcoded zeros; Cursor cloud drops an unreachable API callback; hiring onto an adapter the instance cannot run is refused; and adapters load on Windows (pathToFileURL before dynamic import). (#9500, #9463, #10003, #9225, #10294, #10433, #8546, #10256, #4287)
  • Server correctness — DELETE /api/issues/:id succeeds for issues with dependents (comments and read-state cascade; cost and finance records are kept with their issue reference cleared), non-UUID company refs return 404 instead of 500, cross-package Zod errors are recognized, wiring blockers in a PATCH no longer implicitly reopens a blocked issue, unsigned ask-first requests stay out of the review queue without being cancelled, the terminal workspace reaper stops starving on its oldest candidates, the agent run JWT default TTL is aligned to the documented 48h so suspended-laptop runs stop waking with an expired credential, an explicit PAPERCLIP_API_URL overrides the derived runtime URL in run env, base-URL ports are only rewritten for loopback hosts, and silent nonzero exits in the Hermes flow surface as failures. (#11331, #9959, #10168, #10269, #11338, #11238, #10176, #10339, #10258, #10107)
  • Workspace Git scans are bounded — One bounded scheduler now coalesces and caps every expensive workspace Git scan (a request storm once produced ~270 concurrent git status processes and starved health checks), and the browser only starts scans when the file panel is open and visible. (#11572)
  • UI paper cuts — The queued-message interrupt action is back, agent secret access moved to a searchable secrets tab, slash autocomplete scrolls inside dialogs, inbox archive gained an undo toast and folded subtasks are remembered, inbox routing honors the saved policy for explicit targets, board approval prose renders as markdown, create-dialog badges use the real issue prefix, issue-document deep links route correctly, truncated issue descriptions are flagged, generated invite links prefer the public base URL, selected run lifecycle and logs stay current, and the mobile task chat gained blocker actions, a composer aligned with the thread, and a new-task dialog that stays above the keyboard. (#11374, #11283, #11222, #11220, #11069, #11221, #9817, #8550, #11551, #4771, #7619, #10169, #11282, #11296, #11281)
  • Odds and ends — Skill sync refreshes project folders in place instead of replacing them, issue writes through board keys work regardless of assignee, environment-secret bindings resolve their company context on first save, and worktree-mode dev instances warn when the embedded-Postgres data directory sits in the OS temp dir. (#11066, #9025, #11291, #8283)

Upgrade Guide

  • Migrations: this release adds 11 database migrations (0212 through 0222), covering the one-per-company onboarding first task (0212), resumable company transfer runs (0213), adapter device-login sessions (0214, 0215), Cloud onboarding seeds (0216), issue-deletion foreign-key policies (0217), interaction resolver-policy defaults and provenance (0218), runtime exposure state (0219), execution-workspace runtime leases (0220), Claude setup-token sessions (0221), and environment-lease references that survive environment deletion (0222). Migrations run automatically on startup — no manual action required. Nothing drops a table or deletes data; note that 0218 rewrites resolver-policy values on existing pending interactions (conservatively — see Breaking Changes) and 0217/0222 change what happens to dependent rows on delete.
  • New optional environment variables (all have sensible defaults; set only if you need them):
    • PAPERCLIP_MANAGED_RUNTIME_HTTPS — auto (default), off, or force; controls the Tailscale HTTPS default for managed runtime previews (see Breaking Changes). PAPERCLIP_TAILSCALE_BROKER_SOCKET and PAPERCLIP_TAILSCALE_DNS_NAME override the broker socket path and the tailnet DNS name; PAPERCLIP_VITE_HMR_PROTOCOL (ws/wss) pins the dev-preview HMR protocol. (#11524, #11525)
    • CLAUDE_LOGIN_TRUSTED_PROXIES — allowlisted proxy peers for the Claude login transport guard; CLAUDE_LOGIN_EDGE_TLS_TERMINATED=true — declare platform-edge TLS termination on managed platforms where the proxy addresses aren't knowable. (#11286, #11579)
    • PAPERCLIP_ONBOARDING_SEED_ADAPTER_TYPE — adapter type for the agent created by a Cloud onboarding seed. (#11098)
    • SANDBOX_ORPHAN_CLEANUP_SPOOL_DIR — where durable sandbox cleanup records are spooled; PAPERCLIP_PROCESS_SESSION_STDIN_MAX_RETRIES — retry ceiling for the sandbox stdin poller. (#11347, #11235)
  • Removed configuration keys: streamAgentSessionOutput (server) and useSessions / useLogStream (Daytona plugin) no longer do anything — remove them from saved configs at your leisure; they load but are inert. (#11557)
  • Agent run JWT TTL: the server default now matches the documented 48h (PAPERCLIP_AGENT_JWT_TTL_SECONDS=172800). If you relied on the old implicit 1h expiry, set the variable explicitly. (#10176)
  • HTTPS previews: to use them, install Tailscale on the host and run the new broker (see the @paperclipai/tailscale-https-broker README); to opt out, set PAPERCLIP_MANAGED_RUNTIME_HTTPS=off. Nothing else changes for unmanaged or custom services.
