Papierclip v2026.1001.0

Sortie : 2026-10-01

Paperclip v2026.1001.0 comporte 77 commits, promus à partir de 2026.921.0-beta.1. Le titre est la fiabilité : un renforcement en profondeur du coureur natif et de la récupération du chat - courses d'approbation et d'arrêt, continuité de session, reconnexion et nettoyage du bac à sable - aux côtés d'un visage plus convivial : des personnages d'agent dans toute l'application, un personnage d'intégration animé et une configuration Slack reconstruite. Autour de ceux-ci : les agents peuvent examiner les demandes d'extraction GitHub en tant que robots d'examen planifiés, Railway rejoint le catalogue de connecteurs avec des outils de déploiement gouvernés, une file d'attente d'approbations et de réponses pendant les exécutions actives au lieu de rebondir, et les faisceaux d'exécution sont désormais entièrement automatiques par défaut.

Modifications radicales

  • L'ancien courtier Composio est retiré. La méthode de catalogue de clés API, le courtier clients, la création de session, la synchronisation de compte, le cycle de vie des enfants et les itinéraires de la boîte à outils, ainsi que l'onglet Services sont tous supprimés. Les anciennes connexions Composio existantes cessent de fonctionner et il n'y a pas de migration automatisée : les connecteurs expérimentaux de l'agrégateur MCP (ci-dessous) sont le chemin du successeur ; consultez le Guide de mise à niveau pour les étapes manuelles. La provenance Vercel est intacte. (#13758)
  • Les harnais d'exécution sont désormais entièrement automatiques par défaut. Les exécutions natives par défaut Claude/ACPX sur approve-all, OpenCode sur allow et Codex pour contourner l'approbation et le bac à sable, et les adaptateurs hérités suivent la même politique : outils de fournisseur et outils connectés inclus. Les modes restrictifs explicitement configurés sont préservés et les propres décisions d'approbation de Paperclip appliquent toujours l'autorité du contrôleur ; seuls les valeurs par défaut changent. Les opérateurs qui s'appuient sur des agents non configurés héritant de portes de fournisseur restrictives doivent définir un mode explicite. (#13686, #13693)

Faits saillants

  • Les agents ont des visages — Les images de personnages statiques remplacent les icônes d'agent dans les listes, la barre latérale, les organigrammes, les tâches, les commentaires, les sélecteurs, les activités et les tableaux de bord, avec un personnage animé suivant le pointeur dans l'en-tête de l'agent (mouvement réduit et solutions de secours tactiles incluses) et une révélation de personnage intégrée à la création d'agent (#13171). L'intégration s'ouvre avec le héros somnolent ClipLab : le personnage somnole en gris pendant la configuration et se réveille dans la palette complète lors de la révision (#13629). La configuration de Slack peut télécharger l'avatar de l'agent au format PNG pour l'identité du bot, à la fois depuis la configuration et les paramètres (#13740).
  • Les agents examinent vos demandes d'extraction — Une configuration guidée transforme un agent Paperclip en un robot de révision GitHub : une invite Claude/Codex copiable parcourt l'installation de l'application, la planification de la révision et les vérifications obligatoires facultatives, avec l'origine de l'instance intégrée (#13717). La connexion MCP GitHub bénéficie également du jeu d'outils Actions (découverte et répartition du flux de travail) pour les connexions existantes et nouvelles (#13553).
  • File d'attente d'approbations et de réponses pendant les exécutions actives — Répondre à une question ou à une approbation alors que l'agent est en cours d'exécution ne rebondit plus : les cartes résolues se projettent dans la file d'attente d'exécution en tant que réponses immuables, un click explicite oriente une réponse vers un tour natif compatible (ou s'interrompt pour une nouvelle session) et le contexte saisi survit à l'interruption et au nettoyage (#13539).
  • Configuration Slack, reconstruite — L'intégration est divisée en six étapes clickables avec un lien de création généré et un manifeste en lecture seule, la validation des informations d'identification, l'état du lien de compte en direct et un test de message basé sur la mention (#13638). Les entreprises peuvent joindre des conseils de communication à une connexion Slack qui suit les conversations dans les tâches sans rappels par tour (#13760) et des rapports d'état de rappel correctement derrière les proxys Cloud (#13694).
  • Le catalogue de connecteurs s'agrandit — Railway arrive avec la configuration OAuth et des outils de déploiement gouvernés : état du service et du déploiement, journaux limités et redéploiement/redémarrage/restauration, avec accès vérifié par l'espace de travail (#13415). Les agrégateurs MCP expérimentaux (Zapier, Arcade, Composio Connect, Executor) se retrouvent derrière l'indicateur enableMcpAggregators désactivé par défaut, réutilisant le coffre-fort, les subventions et les modèles de politique existants (#13755). La recherche You.com rejoint le catalogue libre-service avec les niveaux gratuits de connexion, de clé API et sans clé (#13555), et un plug-in de fournisseur de bac à sable CreateOS implémente le cycle de vie complet de l'environnement par rapport au HTTP CreateOS API (#13434).
  • Les routines obtiennent des webhooks sécurisés — Un assistant de déclenchement de production ajoute des choix de planification et de webhook, des informations d'identification uniques, des reçus de livraison de test et une suppression réversible (#13637), et une bannière d'avertissement signale les URL de webhook qui peuvent ne pas être accessibles publiquement : hôte local, réseaux privés, HTTP et Tailscale Serve vs Funnel (#13684).
  • Compétences issues du travail et pour l'intégration — Un outil d'exécution transforme les apprentissages d'une tâche terminée en une compétence d'entreprise, validée et régie par la politique de compétences existante (#13538) ; la première tâche d'intégration passe par une compétence dédiée invoquée nativement sur Claude et Codex (#13517) ; et un guide d'évaluation ainsi que des compétences en création de compétences rejoignent la documentation (#13535).
  • Les plugins chargent des catalogues d'images — Les identités des catalogues, les chemins confinés, les versions de package et les hachages de bundle sont validés avant d'importer le code ; la sélection d'image s'applique aux installations persistantes avec suppression et restauration ; et les superpositions d'applications persistantes sont montées dans les deux shells de l'interface utilisateur (#13646).

Correctifs

  • Conversation de tâches et interface utilisateur — L'éditeur de chat ne démarre plus désactivé sur le bureau pendant que la vérification de l'état de pause est en attente (expédié plus tôt que stable 2026.916.1; #13562). La sélection d'une option à choix unique répond à la question sans faire avancer automatiquement la page (#13602), chaque bouton de copie est désormais confirmé uniquement après la réussite de l'écriture sur le clipboard (#13603), l'historique des tâches reste visible pendant que les tentatives attendent de démarrer (#13597), la dernière tentative échouée peut être réessayée même lors de tentatives automatiques ultérieures. ont été annulées (#13765) et l'écran de connexion des connexions cesse d'ajouter une étape fantôme (#13601).
  • Fiabilité du coureur et de l'exécution native — Un large passage de durcissement à travers le coureur natif : les courses d'approbation et d'arrêt se règlent correctement pendant le nettoyage (#13750), un démarrage en attente est attendu avant qu'un arrêt soit reconnu afin qu'un handle tardif ne puisse pas soumettre un tour de fournisseur (#13741), les sessions du fournisseur persistent d'un tour à l'autre avec des suites de questions et d'approbation se terminant sur la même exécution. (#13655), les réponses aux tâches et la continuité des processus chauds survivent à la déduplication et au bruit des threads d'assistance (#13738), et la récupération de Chat d'agent conserve l'identité du commentaire de réveil et rejette les tentatives obsolètes (#13678). Les opérations du bac à sable sont également devenues plus robustes : les sessions Daytona se reconnectent après un redémarrage du contrôleur avec des contrôles d'adoption résistants à la réutilisation du PID (#13691), la résiliation continue de progresser après la perte du pont avec des tentatives de nettoyage clôturées (#13287), les baux bloqués actifs par un redémarrage sont balayés (#13515), les environnements hérités sont validés et le bac à sable obsolète les binaires sont remplacés (#13677), le temps d'exécution du catalogue et les limites de notation sont réparés (#13676), les rejets de l'outil de complétion nomment les champs manquants (#13682) et les transferts de révision natifs sont complétés par des faits d'affectation validés par le serveur et des outils de révision à portée étroite (#13581). En outre : les travailleurs du plugin accèdent au CV de l'arbre des problèmes (#13757), les projets sans configuration d'espace de travail respectent l'isolation par défaut de l'opérateur (#13636), les lanceurs Git gérés fonctionnent dans les projets sandbox (#13588), un GROK_HOME vide ne masque plus la connexion de l'hôte pour les exécutions locales de Grok (#13570), et la classification des quotas Claude ACP et les temps de réinitialisation survivent jusqu'à la limite de l'adaptateur (#13651).
  • Récupération de connexion et de notification — Récupération des échecs d'authentification et de connexion du navigateur : CONNECT_TIMEOUT rejoint la stratégie de nouvelle tentative, les échecs du constructeur WebSocket sont gérés et les requêtes visibles sont interrogées toutes les 15 secondes lorsque le socket de l'entreprise est en panne (#13724). Les échecs d'exécution finalisés cessent de renotifier à chaque reconnexion (#13739) et la latence du chat diminue tandis que la réutilisation de la session gérée est préservée (#13710).
  • Correctivité du serveur — PostgreSQL récupère après la fermeture d'une connexion de transaction au lieu de coincer les requêtes en file d'attente (#13643), les requêtes JSON mal formées obtiennent un 400 de sécurité constant au lieu de faire écho aux octets soumis dans les erreurs et les rapports de plantage (#13660), les ID d'exécution de battement de coeur sont validés avant les recherches dans la base de données. (#13657), les vues de discussion d'agent ignorent les lectures de connecteur de tâches uniquement (#13654), un lecteur de journal rattrapé obtient une lecture vide au lieu d'une erreur de plage EOF passée (#13592) et les erreurs Sentry sont attribuées à la version source chargée sur le serveur et le navigateur (#13719).
  • Correction de l'URL de l'instance Cloud — Les liens de tâches transmis aux chats externes sont des URL publiques exactes (#13699), et la configuration du chat, l'enregistrement Telegram et la récupération du webhook GitHub utilisent tous l'origine Cloud revendiquée, avec la priorité de configuration auto-hébergée préservée (#13680).
  • CLI et connexions locales — L'assistant d'intégration accepte les invites par défaut au lieu de rejeter l'entrée vide qu'elles affichent (#13520), et une connexion Claude isolée par macOS est lue à partir de son élément de trousseau suffixé lorsque le fichier d'informations d'identification est manquant (#13519).

Améliorations

  • Les invites de continuation sont plus courtes pour les anciens coureurs et les natifs, avec des conseils sur l'outil de questions résidant dans le descripteur canonique (#13574) ; la copie de configuration du connecteur indique « organisation » (#13589 ); Les conventions UX du connecteur de chat sont documentées pour les auteurs de fournisseurs (#13675) ; DeepWiki est configuré comme un manuel du contributeur de 30 pages (#13745) ; et le package de base de données est livré sans instantanés historiques de bruine (#13687).

Guide de mise à niveau

  • Les migrations 0280–0283 s'exécutent lors de la mise à niveau (personnages d'agent, webhooks de routine, conseils de communication Slack, robots de révision GitHub).
  • Les connexions Composio héritées sont supprimées, sans migration automatisée (#13758). L'activation de l'indicateur expérimental enableMcpAggregators expose uniquement l'entrée de catalogue Composio Connect de remplacement : elle ne reprend pas les informations d'identification, les subventions ou les règles d'accès existantes. Pour conserver les intégrations basées sur Composio : activez l'indicateur, créez et autorisez une nouvelle connexion Composio Connect MCP, resélectionnez ses règles d'accès et supprimez chaque enregistrement de connexion héritée retirée. En attendant, les agents perdent l’accès aux outils retirés.
  • Les paramètres d'exécution par défaut ont été modifiés en mode entièrement automatique (#13686, #13693) : définir un mode restrictif explicite sur les agents qui doivent conserver les portes d'approbation côté fournisseur.
  • Aucune autre configuration ou modification du API ne nécessite d'action.

paperclip v2026.1001.0

Paperclip v2026.1001.0

Released: 2026-10-01

Paperclip v2026.1001.0 carries 77 commits, promoted from 2026.921.0-beta.1. The headline is reliability: a deep hardening pass over the native runner and chat recovery — approval and Stop races, session continuity, sandbox reconnection and cleanup — alongside a friendlier face: agent personas throughout the app, an animated onboarding character, and a rebuilt Slack setup. Around those: agents can review GitHub pull requests as scheduled review bots, Railway joins the connector catalog with governed deployment tools, approvals and answers queue during active runs instead of bouncing, and execution harnesses now default to full auto.

Breaking Changes

  • The legacy Composio broker is retired. The API-key catalog method, broker clients, session creation, account synchronization, child lifecycle and toolkit routes, and the Services tab are all removed. Existing legacy Composio connections stop working, and there is no automated migration — the experimental MCP aggregator connectors (below) are the successor path; see the Upgrade Guide for the manual steps. Vercel provenance is untouched. (#13758)
  • Execution harnesses now default to full auto. Native runs default Claude/ACPX to approve-all, OpenCode to allow, and Codex to approval-and-sandbox bypass, and the legacy adapters follow the same policy — provider tools and connected tools included. Explicitly configured restrictive modes are preserved, and Paperclip's own approval decisions still enforce controller authority; only the defaults change. Operators who relied on unconfigured agents inheriting restrictive provider gates should set an explicit mode. (#13686, #13693)

Highlights

  • Agents get faces — Static persona images replace agent icons across lists, the sidebar, org charts, tasks, comments, selectors, activity, and dashboards, with one animated pointer-following character in the agent header (reduced-motion and touch fallbacks included) and persona reveal built into agent creation (#13171). Onboarding opens with the ClipLab sleepy-to-wake hero: the character dozes in gray through setup and wakes in full palette on Review (#13629). Slack setup can download the agent's avatar as a PNG for the bot identity, from both setup and settings (#13740).
  • Agents review your pull requests — A guided setup turns a Paperclip agent into a GitHub review bot: a copyable Claude/Codex prompt walks through App installation, review scheduling, and optional required checks, with the instance origin baked in (#13717). The GitHub MCP connection also gains the Actions toolset — workflow discovery and dispatch — for existing and new connections (#13553).
  • Approvals and answers queue during active runs — Responding to a question or approval while the agent is mid-run no longer bounces: resolved cards project into the run queue as immutable responses, an explicit click steers a response into a compatible native turn (or interrupts for a fresh session), and typed context survives interruption and cleanup (#13539).
  • Slack setup, rebuilt — Onboarding splits into six clickable steps with a generated creation link and read-only manifest, credential validation, live account-link status, and a mention-based message test (#13638). Companies can attach communication guidance to a Slack connection that follows conversations into tasks without per-turn reminders (#13760), and callback health reports correctly behind Cloud proxies (#13694).
  • The connector catalog grows — Railway arrives with OAuth setup and governed deployment tools: service and deployment status, bounded logs, and redeploy/restart/rollback, with workspace-verified access (#13415). Experimental MCP aggregators (Zapier, Arcade, Composio Connect, Executor) land behind the default-off enableMcpAggregators flag, reusing the existing vault, grants, and policy models (#13755). You.com search joins the self-serve catalog with sign-in, API-key, and keyless free tiers (#13555), and a CreateOS sandbox provider plugin implements the full environment lifecycle against the CreateOS HTTP API (#13434).
  • Routines get safe webhooks — A production trigger wizard adds schedule and webhook choices, one-time credentials, test delivery receipts, and reversible removal (#13637), and a warning banner flags webhook URLs that may not be publicly reachable — localhost, private networks, HTTP, and Tailscale Serve vs Funnel (#13684).
  • Skills from work, and for onboarding — A runner tool turns a completed task's learnings into a company skill, validated and governed by the existing skill policy (#13538); the first onboarding task runs through a dedicated skill invoked natively on Claude and Codex (#13517); and an eval guide plus skill-authoring skills join the docs (#13535).
  • Plugins load image catalogs — Catalog identities, confined paths, package versions, and bundle hashes are validated before importing code; image selection applies to persisted installs with removal and rollback; and persistent application overlays mount in both UI shells (#13646).

Fixes

  • Task conversation and UI — The chat composer no longer starts out disabled on desktop while the pause-status check is pending (shipped early as stable 2026.916.1; #13562). Selecting a single-choice option answers the question without auto-advancing the page (#13602), every copy button now confirms only after the clipboard write succeeds (#13603), task history stays visible while retries wait to start (#13597), the latest failed attempt is retryable even when later automatic retries were cancelled (#13765), and the connections sign-in screen stops adding a phantom step (#13601).
  • Runner and native execution reliability — A broad hardening pass across the native runner: approval and Stop races settle correctly during cleanup (#13750), a pending startup is awaited before a Stop is acknowledged so a late handle can't submit a provider turn (#13741), provider sessions persist across turns with question and approval continuations completing on the same run (#13655), task replies and warm process continuity survive deduplication and helper-thread noise (#13738), and Agent Chat recovery keeps wake-comment identity and rejects stale retries (#13678). Sandbox operations got sturdier too: Daytona sessions reconnect after a controller restart with PID-reuse-proof adoption checks (#13691), termination keeps progressing after bridge loss with fenced cleanup attempts (#13287), leases stranded active by a restart are swept (#13515), inherited environments are validated and stale sandbox binaries replaced (#13677), catalog runtime and grading boundaries are repaired (#13676), completion-tool rejections name the missing fields (#13682), and native review handoffs complete with server-validated assignment facts and narrowly scoped reviewer tools (#13581). Also: plugin workers reach issue-tree resume (#13757), projects without workspace configuration honor the operator's isolation default (#13636), managed Git launchers work in sandbox projects (#13588), an empty GROK_HOME no longer masks the host login for local Grok runs (#13570), and Claude ACP quota classification and reset times survive to the adapter boundary (#13651).
  • Connection and notification recovery — Authentication and browser connection failures recover: CONNECT_TIMEOUT joins the retry policy, WebSocket constructor failures are handled, and visible queries poll every 15 seconds while the company socket is down (#13724). Finalized run failures stop re-notifying on every reconnect (#13739), and chat latency drops while managed session reuse is preserved (#13710).
  • Server correctness — PostgreSQL recovers after a transaction connection closes instead of wedging queued queries (#13643), malformed JSON requests get a constant safe 400 instead of echoing submitted bytes into errors and crash reports (#13660), heartbeat run IDs are validated before database lookups (#13657), agent-chat views skip task-only connector reads (#13654), a caught-up log reader gets an empty read instead of a past-EOF range error (#13592), and Sentry errors attribute to the loaded source release on both server and browser (#13719).
  • Cloud-instance URL correctness — Task links handed to external chats are exact public URLs (#13699), and chat setup, Telegram registration, and GitHub webhook recovery all use the claimed Cloud origin, with self-hosted configuration precedence preserved (#13680).
  • CLI and local logins — The onboarding wizard accepts prompt defaults instead of rejecting the empty input they display (#13520), and a macOS isolated Claude login is read from its suffixed Keychain item when the credentials file is missing (#13519).

Improvements

  • Continuation prompts are shorter for legacy and native runners, with question-tool guidance living in the canonical descriptor (#13574); connector setup copy says "organization" (#13589); chat connector UX conventions are documented for provider authors (#13675); DeepWiki is configured as a 30-page contributor handbook (#13745); and the database package ships without historical drizzle snapshots (#13687).

Upgrade Guide

  • Migrations 0280–0283 run on upgrade (agent personas, routine webhooks, Slack communication guidance, GitHub review bots).
  • Legacy Composio connections are removed, with no automated migration (#13758). Enabling the experimental enableMcpAggregators flag only exposes the replacement Composio Connect catalog entry — it does not carry over existing credentials, grants, or access rules. To keep Composio-backed integrations: enable the flag, create and authorize a new Composio Connect MCP connection, re-select its access rules, and remove each retired legacy connection record. Until that is done, agents lose access to the retired tools.
  • Execution defaults changed to full auto (#13686, #13693): set an explicit restrictive mode on agents that must keep provider-side approval gates.
  • No other configuration or API changes require action.
