OCRmonPDF v17.14.0

Nouvelles fonctionnalités

  • Nouveau moteur OCR en option, RapidOCR, qui exécute les modèles PP-OCR de PaddleOCR sur Exécution ONNX. Installez-le avec uv tool install 'ocrmypdf[rapidocr]' (ou uv pip install / pip install avec le même extra) et sélectionnez-le avec --ocr-engine rapidocr. Il lit souvent davantage les nombres et les cellules des tableaux. avec précision que Tesseract, à un coût de CPU et de mémoire plus élevé. Il soutient --rotate-pages et --deskew sans Tesseract, et la nouvelle option --rapidocr-max-side-len (API : rapidocr_max_side_len=) contrôle la distance les grandes pages sont réduites. Consultez le livre de recettes pour connaître les langues et les limitations.
  • Avec RapidOCR, --rotate-pages utilise PP-LCNet_x1_0_doc_ori de PaddlePaddle modèle d'orientation de page (6.8 MB, Apache-2.0), téléchargé lors de la première utilisation et vérifié par rapport à sa somme de contrôle, ainsi qu'à la forme du texte détecté lignes. Une page ne se tourne que lorsque les deux sont d’accord. -python -m ocrmypdf.builtin_plugins.rapidocr_ocr download [LANGUAGE...] télécharge le modèle d'orientation de page de RapidOCR et toute langue supplémentaire modèles à l’avance, pour une utilisation hors ligne ou des images de conteneurs.
  • Les images Docker n'incluent pas RapidOCR, pour les garder petites. .docker/Dockerfile.rapidocr construit une image avec RapidOCR, sa page modèle d'orientation et toutes langues supplémentaires au-dessus de l'image Ubuntu.

Corrections

  • Sélection d'un moteur OCR autre que Tesseract, y compris --ocr-engine none, ne nécessite plus l’installation de Tesseract.
  • Correction de --redo-ocr et --mode strip supprimant le texte visible d'un texte objet qui contient également du texte invisible, par exemple lors du rendu du texte le mode passe à invisible à mi-chemin. Seul le texte invisible est maintenant supprimé, et les paramètres de police et d'espacement définis là où il est supprimé sont conservé pour le texte qui suit. {issue}1769
  • Correction du moteur de rendu fpdf2 écrivant le texte d'une ligne qui monte vers la droite trop grand, jusqu'à la hauteur de son élévation, ce qui rendait également le texte de les lignes voisines se chevauchent. La boîte d'une ligne inclinée s'étend sur sa montée ainsi que son texte ; la taille du texte est désormais mesurée à la fin de la ligne où le la ligne de base est la plus élevée, comme c'était déjà le cas pour les lignes qui tombent vers la droite.

Anglais original / English original

OCRmyPDF v17.14.0

Highlights

  • RapidOCR engine — A third OCR backend joins Tesseract: PaddleOCR's PP-OCR models running on ONNX Runtime, opt-in via uv tool install 'ocrmypdf[rapidocr]' and --ocr-engine rapidocr. For developers, the real win is accuracy on numeric and tabular content where Tesseract struggles — but budget for higher CPU/memory. It can handle --rotate-pages and --deskew without Tesseract installed at all, which is a meaningful deployment simplification. Note the extra --rapidocr-max-side-len knob for controlling downscaling of large pages, and check the cookbook before committing to a language set.
  • Offline and container prep — RapidOCR's page-orientation model (PP-LCNet_x1_0_doc_ori, 6.8 MB, Apache-2.0) and any added language models download on first use and are checksum-verified, so cold-start behavior differs from Tesseract. Pre-seed them with python -m ocrmypdf.builtin_plugins.rapidocr_ocr download [LANGUAGE...] — this is the step to bake into image builds. The official Docker images deliberately omit RapidOCR to stay small; use .docker/Dockerfile.rapidocr if you need it containerized.
  • Tesseract no longer mandatory — Selecting any non-Tesseract engine, including --ocr-engine none, no longer requires Tesseract to be installed. This unblocks leaner installations and pure-redaction/strip workflows, and removes a dependency that previously had to be present even when unused.
  • --redo-ocr / --mode strip correctness (issue #1769) — Fixed invisible text being over-removed: when a single text object mixes visible and invisible runs (e.g. a mid-object switch to invisible rendering mode), only the invisible portion is now stripped, and font/spacing state is preserved for following text. If you relied on these modes to de-obfuscate scanned PDFs, reprocess affected files — prior output may have lost legitimate visible text.
  • fpdf2 sloped-line rendering fix — Lines rising to the right were rendered with text oversized by up to the line's rise, causing neighbouring lines to overlap. Text is now measured at the highest-baseline end, matching the existing handling for descending lines. Regenerate any PDFs produced with the old renderer where sloped text appeared too large or collided.
  • No breaking changes.

New features

  • New optional OCR engine, RapidOCR, which runs PaddleOCR's PP-OCR models on ONNX Runtime. Install it with uv tool install 'ocrmypdf[rapidocr]' (or uv pip install / pip install with the same extra) and select it with --ocr-engine rapidocr. It often reads numbers and table cells more accurately than Tesseract, at a higher CPU and memory cost. It supports --rotate-pages and --deskew without Tesseract, and the new option --rapidocr-max-side-len (API: rapidocr_max_side_len=) controls how far large pages are downscaled. See the cookbook for languages and limitations.
  • With RapidOCR, --rotate-pages uses PaddlePaddle's PP-LCNet_x1_0_doc_ori page orientation model (6.8 MB, Apache-2.0), downloaded on first use and checked against its checksum, together with the shape of the detected text lines. A page is turned only when both agree.
  • python -m ocrmypdf.builtin_plugins.rapidocr_ocr download [LANGUAGE...] downloads RapidOCR's page orientation model and any additional language models in advance, for offline use or container images.
  • The Docker images do not include RapidOCR, to keep them small. .docker/Dockerfile.rapidocr builds an image with RapidOCR, its page orientation model and any additional languages on top of the Ubuntu image.

Fixes

  • Selecting an OCR engine other than Tesseract, including --ocr-engine none, no longer requires Tesseract to be installed.
  • Fixed --redo-ocr and --mode strip removing visible text from a text object that also contains invisible text, such as when the text rendering mode changes to invisible partway through it. Only the invisible text is now removed, and font and spacing settings made where it is removed are kept for the text that follows. {issue}1769
  • Fixed the fpdf2 renderer writing the text of a line that rises to the right too large, by up to the height of its rise, which also made the text of neighbouring lines overlap. A sloped line's box spans its rise as well as its text; the text size is now measured at the end of the line where the baseline is highest, as it already was for lines that fall to the right.
