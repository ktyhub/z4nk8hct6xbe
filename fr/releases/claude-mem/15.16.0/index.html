#claude-mem v15.16.0

Nouveau

  • Actualisation de My Work sur votre fournisseur API (opt-in) : configurez CLAUDE_MEM_WORK_VIEW_AGENT=api pour exécuter l'actualisation de My Work sur le fournisseur que vous avez déjà sélectionné (openrouter, openai-compatible ou l'ancienne orthographe cmem). Les installations sans Claude Code, Codex ou Gemini CLI connecté (par exemple les hôtes OpenCode ou DSH) peuvent désormais utiliser My Work. Avec un fournisseur API sélectionné et le paramètre vide, l'actualisation ne revient plus à un Claude Code connecté : aucun agent ne s'exécute et rien n'est dépensé jusqu'à ce que vous en choisissiez un (#5674, merci @bulanovk).
  • Demandes d'extraction MCP GitHub dans My Work : Les demandes d'extraction créées via l'outil officiel MCP create_pull_request de GitHub apparaissent désormais en tant que produits My Work. Seuls les résultats complétés dont l'URL correspond au référentiel demandé sont acceptés (#5809, merci @Afloat16).
  • Préglage UberLLM : uberllm est désormais un préréglage du fournisseur openai-compatible (https://api.uberllm.dev/v1, modèle par défaut deepseek/deepseek-v4.1-flash) (#5706, merci @PSA-Team-source).
  • Délai d'expiration de transfert en direct réglable : CLAUDE_MEM_HOOK_HANDOFF_TIMEOUT_MS (par défaut 250) définit le budget pour le transfert en direct unique d'un hook vers le travailleur, et un transfert manqué est désormais enregistré dans WARN au lieu de DEBUG (#5831, merci @mohitdixit02).

Corrections notables

  • Nettoyage du cache du plugin : le travailleur efface désormais les dossiers des anciennes versions que les mises à jour du marché de Claude Code laissent dans ~/.claude/plugins/cache/thedotmack/claude-mem/ (un rapport : 21 versions, environ 16 Go). Il conserve la copie en cours d'exécution et la version enregistrée, et balaie après le démarrage, puis toutes les heures (#5685, merci @MaxWang007).
  • Bruit de l'antivirus Windows : l'installation, la mise à jour et la reconstruction du lanceur ne démarrent plus un PowerShell caché lorsque le dossier du lanceur est déjà sur PATH, le modèle signalé par Kaspersky (#5835, rapporté par @Ali-Sabri-0).
  • Ma langue de travail : lorsque CLAUDE_MEM_WORK_VIEW_TEXT_LANGUAGE est vide, chaque étape d'actualisation écrit désormais dans la langue des paramètres régionaux du système, donc une exécution ne mélange plus les langues (#5669, merci @0xABCD01).
  • Coût d'inactivité de My Work : l'interrogation en inactivité ne réanalyse plus chaque ligne synchronisée, et la vue d'ensemble en direct, la fusion des zones de focus et les panneaux lourds nécessitent moins de travail par mise à jour (#5834).
  • Sauvegardes : une exécution de sauvegarde declined renvoie un échec, les sauvegardes enregistrées sont signalées séparément des erreurs de rétention, les intervalles de sauvegarde au-delà de la limite du minuteur sont honorés et la restauration rejette les instantanés estampillés manquant les tables de travail (#5750, #5781, #5784, #5684, merci @Kirat0201).
  • Configuration du Shell : le bloc PATH du lanceur et l'alias de désinstallation hérité sont écrits de manière atomique, Cowork organise les événements spoolés sous $HOME lorsque l'hôte le définit, et Hermes conserve les erreurs HTTP client permanentes hors de son disjoncteur (#5680, #5679, #5677, #5678, merci @DeryFerd).
  • OpenCode : l'outil bash est signalé comme Bash, donc SKIP_BASH_PATTERNS s'applique (#5668, merci @ryrenz).
  • Sync : un échec de nettoyage Chroma après une nouvelle tentative de suppression (#5673, merci @Zhong-fan).
  • SessionStart : les étapes de lecture et de composition du cache partagent un seul budget corporel, donc un corps mis en cache n'est servi que lorsqu'il convient (#5686, merci @Varshith-Kali).

Plus de correctifs

Environ 130 correctifs plus petits de @Afloat16 concernant la capture, la synchronisation, la recherche, le contexte, l'importation, les transcriptions, les médias, le serveur et les intégrations Codex, OpenCode, OpenClaw, Hermes, Grok, Kimi, Gemini, Pi, Goose, Notion et Telegram. Points forts:

  • Recherche et contexte : les clés littérales du projet et les chemins d'accès aux fichiers sont préservés grâce au rappel, aux fusions et à la mise en cache ; Unicode et les marques de combinaison survivent aux limites des mots de requête et des extraits de code ; le contexte mis en cache expire après les restaurations et les remplacements de lignes ; le préfixe de chronologie le plus grand est conservé.
  • Synchronisation et mémoire : les titres de session s'engagent avec leur mutation de boîte d'envoi et obtiennent la rédaction du destinataire ; les sauvegardes manuelles et les nouvelles invites fonctionnent après la suppression d'une session ; les révisions de note survivent à la déduplication du titre.
  • Transcriptions et importation : les messages Codex en plusieurs parties, les résultats des correctifs appariés et les coutures du cadre zstd sont lus correctement ; le raisonnement reste en dehors des réponses finales ; OpenCode, Gemini et les résumés restaurés sont importés sans doublons ni invites perdues.
  • Serveur et fournisseurs : La dérivation de clé API reste en dehors de la boucle de requête ; les annulations se propagent via les tentatives et la compression ; l'utilisation du jeton partagé est mesurée sur les réponses compatibles ; le contenu de la mémoire est nettoyé avant le stockage.
  • Média : les ordinaux d'image, les preuves de lecture à travers les orthographes de chemin et les limites de dimension d'image annoncées sont préservées ; L'allocation en ligne n'est facturée que pour les images acceptées.

Également de @ Kirat0201 : l'historique des fichiers suit les fusions de projets entiers, la recherche interactive dans la chronologie honore les listes de projets et la recherche unifiée conserve les valeurs littérales filePath (#5789, #5787, #5785).

claude-mem v15.16.0

New

  • My Work refresh on your API provider (opt-in): set CLAUDE_MEM_WORK_VIEW_AGENT=api to run the My Work refresh on the provider you already selected (openrouter, openai-compatible, or the legacy cmem spelling). Installs with no logged-in Claude Code, Codex or Gemini CLI (for example OpenCode or DSH hosts) can now use My Work. With an API provider selected and the setting empty, the refresh no longer falls back to a logged-in Claude Code: no agent runs and nothing is spent until you choose one (#5674, thanks @bulanovk).
  • GitHub MCP pull requests in My Work: pull requests created through GitHub's official MCP create_pull_request tool now show up as My Work products. Only completed results whose URL matches the requested repository are accepted (#5809, thanks @Afloat16).
  • UberLLM preset: uberllm is now a preset of the openai-compatible provider (https://api.uberllm.dev/v1, default model deepseek/deepseek-v4.1-flash) (#5706, thanks @PSA-Team-source).
  • Tunable live handoff timeout: CLAUDE_MEM_HOOK_HANDOFF_TIMEOUT_MS (default 250) sets the budget for the single live handoff from a hook to the worker, and a missed handoff is now logged at WARN instead of DEBUG (#5831, thanks @mohitdixit02).

Notable fixes

  • Plugin cache cleanup: the worker now prunes old version folders that Claude Code's marketplace updates leave in ~/.claude/plugins/cache/thedotmack/claude-mem/ (one report: 21 versions, about 16 GB). It keeps the running copy and the registered version, and sweeps after boot settles and then hourly (#5685, thanks @MaxWang007).
  • Windows antivirus noise: install, update and launcher rebuilds no longer start a hidden PowerShell when the launcher folder is already on PATH, the pattern Kaspersky flagged (#5835, reported by @Ali-Sabri-0).
  • My Work language: when CLAUDE_MEM_WORK_VIEW_TEXT_LANGUAGE is empty, every refresh step now writes in the system locale's language, so one run no longer mixes languages (#5669, thanks @0xABCD01).
  • My Work idle cost: idle polling no longer rescans every synced row, and the live overview, focus-area merging and heavy panels do less work per update (#5834).
  • Backups: a declined backup run returns a failure, saved backups are reported separately from retention errors, backup intervals beyond the timer limit are honored, and restore rejects stamped snapshots missing worker tables (#5750, #5781, #5784, #5684, thanks @Kirat0201).
  • Shell setup: the launcher PATH block and the legacy uninstall alias are written atomically, Cowork stages spooled events under $HOME when the host sets it, and Hermes keeps permanent HTTP client errors out of its circuit breaker (#5680, #5679, #5677, #5678, thanks @DeryFerd).
  • OpenCode: the bash tool is reported as Bash, so SKIP_BASH_PATTERNS applies (#5668, thanks @ryrenz).
  • Sync: a failed Chroma cleanup after a delete is retried (#5673, thanks @Zhong-fan).
  • SessionStart: the cache read and compose steps share one body budget, so a cached body is served only when it fits (#5686, thanks @Varshith-Kali).

More fixes

About 130 smaller fixes from @Afloat16 across capture, sync, search, context, import, transcripts, media, the server, and the Codex, OpenCode, OpenClaw, Hermes, Grok, Kimi, Gemini, Pi, Goose, Notion and Telegram integrations. Highlights:

  • Search and context: literal project keys and file paths are preserved through recall, merges and caching; Unicode and combining marks survive query words and snippet limits; cached context expires after restores and row replacements; the largest fitting timeline prefix is kept.
  • Sync and memory: session titles commit with their outbox mutation and get receiver redaction; manual saves and new prompts work after a session deletion; note revisions survive title dedup.
  • Transcripts and import: multipart Codex messages, paired patch results and zstd frame seams are read correctly; reasoning stays out of final answers; OpenCode, Gemini and restored summaries import without duplicates or lost prompts.
  • Server and providers: API key derivation stays off the request loop; cancellations propagate through retries and compression; split token usage is metered on compatible replies; memory content is sanitized before storage.
  • Media: image ordinals, Read evidence across path spellings, and advertised image dimension bounds are preserved; inline allowance is charged only for accepted images.

Also from @Kirat0201: file history follows whole project merges, interactive timeline search honors project lists, and unified search keeps literal filePath values (#5789, #5787, #5785).
