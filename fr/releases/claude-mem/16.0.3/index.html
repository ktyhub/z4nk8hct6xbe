claude-mem v16.0.3

#claude-mem v16.0.3

Correctif critique

  • Le hook OMP fonctionne avec le runtime du serveur (#6367, merci @flipcyde101, ferme le #6366 rapporté par @walynde). Lorsque CLAUDE_MEM_RUNTIME était server ou server-beta, le hook OMP envoyait toujours tout au travailleur local, donc les sessions OMP étaient abandonnées. Le hook lit désormais CLAUDE_MEM_SERVER_URL, CLAUDE_MEM_SERVER_API_KEY et CLAUDE_MEM_SERVER_PROJECT_ID (ou les noms CLAUDE_MEM_SERVER_BETA_* ; les variables d'environnement l'emportent sur settings.json) et communique directement avec le /v1 API du serveur : démarrage de session, événements d'outil et de réponse, contexte et fin de session. Il applique les mêmes règles que celles appliquées par le travailleur avant de sauvegarder quoi que ce soit : les blocs <private> sont supprimés, les projets exclus et CLAUDE_MEM_SKIP_TOOLS sont honorés, chaque invite est enregistrée et le nom du projet vient de git. Si les paramètres du serveur sont incomplets, cela revient au travailleur comme auparavant.
  • Utilisateurs OMP : exécutez npx claude-mem install --ide omp une fois pour obtenir ce correctif. Le hook OMP est un fichier copié, donc une mise à jour du plugin à elle seule ne le remplace pas.

Correctifs

  • Les requêtes de connaissances et les demandes de corpus ne peuvent plus rester bloquées pour toujours (#6368, merci @flipcyde101, ferme le #6364 rapporté par @soarkit). Un flux d'agent SDK bloqué permettait de maintenir la demande et son enfant Claude CLI en vie sans fin. Une requête de connaissance ou prime s'arrête désormais au bout de 10 minutes et une requête de corpus après 15, avec une erreur 504. Le corpus reste verrouillé jusqu'à ce que le travail expiré soit réellement arrêté, il ne peut donc pas écrire après une suppression ou une reconstruction.
  • L'avis "Sauvegarde des souvenirs en pause" disparaît une fois le Codex sauvegardé (#6374, merci @ryrenz, ferme le #6372 rapporté par @raw34). Après avoir remplacé CLAUDE_MEM_PROVIDER par codex après une pause du quota de Claude, chaque nouvelle session indiquait toujours que la capture était suspendue jusqu'à ce que l'ancien temps de recharge de Claude soit épuisé. L'avis est désormais recalculé lorsque le Codex stocke une mémoire.
  • server api-key create --scope sans valeur est refusé (#6375, merci @ryrenz, ferme le #6373 rapporté par @soarkit). Il créait une clé limitée à la chaîne littérale true, que chaque requête rejetait ensuite. Un --scope, --name, --team ou --project nu imprime désormais --<flag> requires a value et quitte 1 sans rien écrire, à la fois sur create et migrate-scopes.
  • Le rapport sur les coûts de l'agent ne plante plus sur les observations sans modèle (#6376, merci @ZedingZhang, ferme le #6371 rapporté par @Realauster). acr.py rollup a soulevé un TypeError lorsqu'une fenêtre contenait à la fois un modèle manquant et un modèle nommé et sans prix.
  • L'image du serveur Docker est à nouveau construite (#6386, ferme le #6379 rapporté par @InfoALR). Il utilise désormais node:20-trixie, car le tree-sitter 0.26 a besoin d'une glibc plus récente que celle livrée par node:20.
  • L'actualisation de My Work s'exécute sur OpenCode 2.x (#6361, références #6339 rapportées par @Realauster). OpenCode 2.x rejette les indicateurs --pure et --dir, donc chaque étape d'actualisation se termine par 1. L'étape vérifie désormais opencode --version et utilise la propre isolation de chaque version. 2.0.0 à 2.2.2 et 3.x sont refusés pour une raison, car ils ne peuvent pas empêcher les plugins d'entrer. Sur chaque version, l'agent d'actualisation voit désormais tous les outils refusés.
  • OMP et Hermes lisent un port de travail enregistré sous forme de numéro (#6363, merci @chuenchen309). {"CLAUDE_MEM_WORKER_PORT": 45678} dans settings.json était autrefois ignoré, leurs requêtes étaient donc dirigées vers le port par défaut.
  • Le programme d'installation d'OpenClaw ne supprime plus un dossier qu'il n'a pas installé (#6381, merci @DeryFerd). Il a exécuté rm -rf sur le chemin d'installation nommé par ~/.openclaw/openclaw.json. Il remplace désormais un dossier uniquement lorsqu'il est manquant, vide ou contient le propre manifeste OpenClaw de Claude-mem. Tout le reste est laissé seul avec un avertissement et le dossier d'extensions par défaut est utilisé ; si cela est également pris par autre chose, le programme d'installation s'arrête.
  • Le travailleur peut arrêter chaque enfant Claude qu'il démarre (#6385, merci @DeryFerd). La compression de champ et la conclusion de Telegram ont démarré leur processus Claude en dehors de la liste des processus du travailleur, donc un travailleur qui a quitté durement les a laissés en cours d'exécution. Ils sont désormais sur cette liste et n’acceptent pas de créneau de simultanéité.
  • Une impression bloquée du CLI ne peut pas augmenter la mémoire du travailleur sans limite (#6384, merci @DeryFerd). La sortie collectée à partir de claude, codex, gemini et opencode est limitée à 128 Mi caractères, soit environ 2.5 fois le plus grand tour réel mesuré. Au-delà du plafond, le début et la fin sont conservés, un avertissement est enregistré et la réponse est refusée au lieu d'être lue comme une réponse partielle. Les sorties plus petites restent inchangées.
  • Un enregistrement de transcription sans fin ne peut pas augmenter la mémoire du travailleur sans limite (#6383, merci @DeryFerd). Un enregistrement JSONL supérieur à 64 Mio (le plus grand enregistrement réel mesuré était de 44 Mio) est ignoré, avec un avertissement indiquant le nom du fichier, le décalage de l'enregistrement et sa taille. Les lignes qui suivent sont lues normalement.
  • Le /v1/info non authentifié n'affiche plus le texte d'erreur Redis (#6380, merci @DeryFerd). Une file d'attente qui n'a pas pu être lue utilisée pour publier l'erreur du pilote, telle qu'un hôte et un port. La raison reste désormais dans le journal du serveur.

Nouveau

  • Capacité CPU opt-in pour chroma-mcp (#6369, merci @flipcyde101, répond en partie au #6365 rapporté par @FengJie2004). Définissez CLAUDE_MEM_CHROMA_MAX_THREADS sur 2 si chroma-mcp occupe plusieurs cœurs. Il bouche les threads de l'intégrateur et, sous Linux avec taskset, les processeurs que chroma-mcp peut utiliser. Il est désactivé par défaut (0), car un plafond toujours activé a ralenti le premier remplissage. #6365 reste ouvert.
  • Préréglage AIGROW pour le fournisseur compatible OpenAI (#6370, merci @guglielmo-io).

Service de synchronisation hébergé

  • Les services de synchronisation comparent les informations d'identification internes de leur projecteur en temps constant (#6382, merci @DeryFerd). Une simple comparaison de chaînes pourrait divulguer le secret partagé via le délai de réponse. Cela modifie services/sync-api et services/sync-hub, qui ne font pas partie du package npm : il n'atteint les utilisateurs qu'une fois ces services déployés, et non via cette version. ## Tests
  • Un test de transcription irrégulier compte désormais les pokes du sondage d'ajout au lieu de lancer la vérification de son fichier (#6360). changelog complet : https://github.com/thedotmack/claude-mem/compare/v16.0.2...v16.0.3

Anglais original / English original

claude-mem v16.0.3

Critical fix

  • The OMP hook works with the server runtime (#6367, thanks @flipcyde101, closes #6366 reported by @walynde). When CLAUDE_MEM_RUNTIME was server or server-beta, the OMP hook still sent everything to the local worker, so OMP sessions were dropped. The hook now reads CLAUDE_MEM_SERVER_URL, CLAUDE_MEM_SERVER_API_KEY and CLAUDE_MEM_SERVER_PROJECT_ID (or the CLAUDE_MEM_SERVER_BETA_* names; environment variables win over settings.json) and talks to the server's /v1 API directly: session start, tool and reply events, context, and session end. It applies the same rules the worker applies before it saves anything: <private> blocks are stripped, excluded projects and CLAUDE_MEM_SKIP_TOOLS are honored, every prompt is recorded, and the project name comes from git. If the server settings are incomplete, it falls back to the worker as before.
  • OMP users: run npx claude-mem install --ide omp once to get this fix. The OMP hook is a copied file, so a plugin update alone does not replace it.

Fixes

  • Knowledge queries and corpus requests can no longer hang forever (#6368, thanks @flipcyde101, closes #6364 reported by @soarkit). A stalled Agent SDK stream used to keep the request and its Claude CLI child alive with no end. A knowledge query or prime now stops after 10 minutes and a corpus request after 15, with a 504 error. The corpus stays locked until the timed-out work has really stopped, so it cannot write after a delete or rebuild.
  • The "paused saving memories" notice goes away once Codex is saving (#6374, thanks @ryrenz, closes #6372 reported by @raw34). After you switched CLAUDE_MEM_PROVIDER to codex following a Claude quota pause, every new session still said capture was paused until the old Claude cooldown ran out. The notice is now recomputed when Codex stores a memory.
  • server api-key create --scope with no value is refused (#6375, thanks @ryrenz, closes #6373 reported by @soarkit). It used to create a key scoped to the literal string true, which every request then rejected. A bare --scope, --name, --team or --project now prints --<flag> requires a value and exits 1 without writing anything, on both create and migrate-scopes.
  • The Agent Cost Report no longer crashes on observations with no model (#6376, thanks @ZedingZhang, closes #6371 reported by @Realauster). acr.py rollup raised a TypeError when one window had both a missing model and a named, unpriced one.
  • The Docker server image builds again (#6386, closes #6379 reported by @InfoALR). It now uses node:20-trixie, because tree-sitter 0.26 needs a newer glibc than node:20 ships.
  • My Work refresh runs on OpenCode 2.x (#6361, refs #6339 reported by @Realauster). OpenCode 2.x rejects the --pure and --dir flags, so every refresh step exited 1. The step now checks opencode --version and uses each version's own isolation. 2.0.0 to 2.2.2 and 3.x are refused with a reason, because they cannot keep plugins out. On every version the refresh agent now has all tools denied.
  • OMP and Hermes read a worker port saved as a number (#6363, thanks @chuenchen309). {"CLAUDE_MEM_WORKER_PORT": 45678} in settings.json used to be ignored, so their requests went to the default port.
  • The OpenClaw installer no longer deletes a folder it did not install (#6381, thanks @DeryFerd). It ran rm -rf on whatever install path ~/.openclaw/openclaw.json named. It now replaces a folder only when it is missing, empty, or holds claude-mem's own OpenClaw manifest. Anything else is left alone with a warning and the default extensions folder is used; if that is also taken by something else, the installer stops.
  • The worker can stop every Claude child it starts (#6385, thanks @DeryFerd). Field compression and the Telegram wrap-up started their Claude process outside the worker's process list, so a worker that exited hard left them running. They are now on that list, and they do not take a concurrency slot.
  • A CLI stuck printing can't grow the worker's memory without limit (#6384, thanks @DeryFerd). Output collected from claude, codex, gemini and opencode is capped at 128 Mi characters, about 2.5 times the largest real turn measured. Past the cap, the start and end are kept, a warning is logged, and the reply is refused instead of read as a partial answer. Smaller outputs are unchanged.
  • A transcript record with no end can't grow the worker's memory without limit (#6383, thanks @DeryFerd). A JSONL record over 64 MiB (the largest real record measured was 44 MiB) is skipped, with a warning that names the file, the record's offset and its size. The lines after it are read as normal.
  • The unauthenticated /v1/info no longer shows Redis error text (#6380, thanks @DeryFerd). A queue lane that could not be read used to publish the driver's error, such as a host and port. The reason now stays in the server log.

New

  • Opt-in CPU cap for chroma-mcp (#6369, thanks @flipcyde101, partly addresses #6365 reported by @FengJie2004). Set CLAUDE_MEM_CHROMA_MAX_THREADS to 2 if chroma-mcp keeps several cores busy. It caps the embedder's threads and, on Linux with taskset, the CPUs chroma-mcp can use. It is off by default (0), because an always-on cap slowed the first backfill. #6365 stays open.
  • AIGROW preset for the OpenAI-compatible provider (#6370, thanks @guglielmo-io).

Hosted sync service

  • The sync services compare their internal projector credential in constant time (#6382, thanks @DeryFerd). A plain string compare could leak the shared secret through response timing. This changes services/sync-api and services/sync-hub, which are not part of the npm package: it reaches users only once those services are deployed, not through this release.

Tests

  • A flaky transcript test now counts the append poll's pokes instead of racing its file check (#6360).

Full changelog: https://github.com/thedotmack/claude-mem/compare/v16.0.2...v16.0.3
