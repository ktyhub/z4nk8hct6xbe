#claude-mem v16.0.2

Correctif critique

  • Une mise à jour automatique ne supprime plus la version du plugin à partir de laquelle une session Claude Code en cours d'exécution a été chargée (#6352, merci @0xABCD01, ferme le #6349 rapporté par @justindrp). Le balayage du cache conserve un dossier de version pendant que le processus Claude Code enregistré dans son fichier .in_use est vivant. Sur macOS et BSD, quelques secondes de différence entre l'heure de début enregistrée par Claude Code et celle signalée par ps ont été lues comme une réutilisation PID, donc le balayage a supprimé le dossier sous une session en direct et chaque hook a échoué pour le reste de cette session. Une incompatibilité d’heure de début ne supprime plus le dossier alors que le processus à ce PID est toujours Claude Code. Un PID qui appartient désormais à un autre programme est toujours élagué comme auparavant.
  • Chaque élagage de cache enregistre désormais pourquoi et qui. Le travailleur écrit une ligne de journal par version supprimée avec sa raison (orpheline ou remplacée) et le .in_use enregistre son rejet et pourquoi (processus terminé ou incompatibilité d'heure de début), de sorte que toute suppression peut être retracée à partir du seul journal.

Correctifs

  • La carte de début de session est tirée sur les comptes Team et Enterprise (#6353, merci @KeithMoc, ferme le #6314 rapporté par @TimoWestland). Lorsqu'un plugin d'organisation s'exécute en premier et que les hooks habituels de la carte ne se déclenchent jamais, la carte se demande désormais au hook session.start et le hook contextuel y répond.
  • My Work détecte les connexions OpenCode 2.x (#6340, merci @ZedingZhang, ferme le #6339 rapporté par @Realauster). La sonde de connexion lit la sortie JSON d'OpenCode, de sorte qu'un fournisseur connecté n'est plus signalé comme déconnecté sur OpenCode 2.3.2.
  • L'actualisation de My Work préfère MXC pour les lancements isolés de Codex sous Windows (#6348, merci @QuantScorpus, références #5163). L'actualisation ne sélectionne plus le sandbox non élevé et échoue avant le démarrage de l'agent.
  • Les deux sondes hôte-observateur donnent à un observateur lent le même 1 s (#6359, merci @rtmalikian, ferme le #6358). La sonde asynchrone a utilisé 400 ms et la sonde de temps d'installation 1 s, donc l'une a appelé un observateur valide "occupé" et l'autre non.
  • Les suppressions de collection Chroma qui perdent leur réponse sont vérifiées avant une reconstruction (#6338, merci @POWDER-RANGER). Le travailleur répertorie les collections une fois au lieu de rejouer la suppression, et ne reconstruit qu'une fois la suppression confirmée.
  • chroma-mcp redémarre après une lecture annulée une fois les écritures en cours réglées (#6337, merci @MaxWang007). Le prochain appel ne va plus vers un serveur qui ne peut plus lire son entrée.
  • Les erreurs de travail et les chemins inconnus répondent dans JSON (#6341, merci @DeryFerd). Le travailleur installe désormais ses gestionnaires d'erreurs 404 et d'erreurs, de sorte qu'il ne renvoie plus la page d'erreur HTML d'Express avec les chemins de fichiers locaux dans la trace de la pile.
  • Le placement CLAUDE.md résout les chemins absolus avant la vérification du projet (#6336, merci @LeviReisJs). Les chemins à barre oblique sous Windows ne sont plus supprimés et les chemins qui climb sortent du projet avec .. sont refusés.
  • npx claude-mem doctor lit une fois le point de terminaison du médecin du travailleur (#6344, merci @DeryFerd), donc un travailleur lent coûte un délai d'attente au lieu de deux.
  • La compétence Rapport sur les coûts d'agent utilise un nom conforme aux spécifications (#6356, merci @LuckVd, références #6355), de sorte que les agents qui vérifient les noms de compétences la chargent.

Nouveau

  • Codex comme quota de repli d'observateur (#6326, merci @QuantScorpus). Lorsque Claude atteint son quota de garde, l'observateur peut utiliser le Codex local CLI connecté avec ChatGPT et revenir vers Claude via le chemin de récupération existant.
  • Préglage WorldRouter pour le fournisseur compatible OpenAI (#6357, merci @Opgeek-1).
  • La carte de démarrage affiche la marque Claude-Mem dans une colonne de droite lorsque le terminal est suffisamment large (#6333).

Tests, CI et documents

  • Un test de rereliure DNS épingle la garde hôte du travailleur devant CORS (#6345, merci @DeryFerd).
  • La version Windows exécute la protection de liste blanche post-installation (#6343, merci @DeryFerd).
  • Devin Cloud a besoin d'un secret d'organisation pour connecter CMEM Pro (#6335).
  • L'exemple d'épinglage Docker indique de construire à partir de la racine du référentiel (#6346, merci @DeryFerd). changelog complet : https://github.com/thedotmack/claude-mem/compare/v16.0.1...v16.0.2

claude-mem v16.0.2

Critical fix

  • An auto-update no longer deletes the plugin version a running Claude Code session was loaded from (#6352, thanks @0xABCD01, closes #6349 reported by @justindrp). The cache sweep keeps a version folder while the Claude Code process recorded in its .in_use file is alive. On macOS and BSD, a few seconds of difference between the start time Claude Code recorded and the one ps reports was read as PID reuse, so the sweep deleted the folder from under a live session and every hook failed for the rest of that session. A start-time mismatch no longer removes the folder while the process at that PID is still Claude Code. A PID that now belongs to another program is still pruned as before.
  • Every cache prune now logs why and who. The worker writes one log line per removed version with its reason (orphaned or superseded) and the .in_use records it rejected and why (process exited or start-time mismatch), so any removal can be traced from the log alone.

Fixes

  • The session-start card is drawn on Team and Enterprise accounts (#6353, thanks @KeithMoc, closes #6314 reported by @TimoWestland). When an organization plugin runs first and the card's usual hooks never fire, the card now asks for itself from the session.start hook and the context hook answers it.
  • My Work detects OpenCode 2.x connections (#6340, thanks @ZedingZhang, closes #6339 reported by @Realauster). The login probe reads OpenCode's JSON output, so a connected provider is no longer reported as logged out on OpenCode 2.3.2.
  • My Work refresh prefers MXC for isolated Codex launches on Windows (#6348, thanks @QuantScorpus, refs #5163). The refresh no longer picks the unelevated sandbox and fails before the agent starts.
  • Both host-observer probes give a slow observer the same 1 s (#6359, thanks @rtmalikian, closes #6358). The async probe used 400 ms and the install-time probe 1 s, so one called a valid observer "occupied" and the other did not.
  • Chroma collection deletes that lose their reply are checked before a rebuild (#6338, thanks @POWDER-RANGER). The worker lists collections once instead of replaying the delete, and only rebuilds once the delete is confirmed.
  • chroma-mcp restarts after a cancelled read once in-flight writes settle (#6337, thanks @MaxWang007). The next call no longer goes to a server that can no longer read its input.
  • Worker errors and unknown paths answer in JSON (#6341, thanks @DeryFerd). The worker now installs its 404 and error handlers, so it no longer returns Express's HTML error page with local file paths in the stack trace.
  • CLAUDE.md placement resolves absolute paths before the project check (#6336, thanks @LeviReisJs). Forward-slash paths on Windows are no longer dropped, and paths that climb out of the project with .. are refused.
  • npx claude-mem doctor reads the worker's doctor endpoint once (#6344, thanks @DeryFerd), so a slow worker costs one timeout instead of two.
  • The Agent Cost Report skill uses a spec-compliant name (#6356, thanks @LuckVd, refs #6355), so agents that check skill names load it.

New

  • Codex as an observer quota fallback (#6326, thanks @QuantScorpus). When Claude hits its quota guard, the observer can use the local Codex CLI signed in with ChatGPT and return to Claude through the existing recovery path.
  • WorldRouter preset for the OpenAI-compatible provider (#6357, thanks @Opgeek-1).
  • The startup card shows the Claude-Mem mark in a right column when the terminal is wide enough (#6333).

Tests, CI and docs

  • A DNS-rebinding test pins the worker's Host guard ahead of CORS (#6345, thanks @DeryFerd).
  • The Windows build runs the postinstall allowlist guard (#6343, thanks @DeryFerd).
  • Devin cloud needs one org secret to connect CMEM Pro (#6335).
  • The Docker pinning example says to build from the repository root (#6346, thanks @DeryFerd).

Full changelog: https://github.com/thedotmack/claude-mem/compare/v16.0.1...v16.0.2
