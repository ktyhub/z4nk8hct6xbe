claude-mem v15.21.0

Mineure Publié17 nov. 2026 Sourcethedotmack/claude-mem Anglais original

Cette page est traduite automatiquement. Le texte anglais original fait foi.

#claude-mem v15.21.0

claude-mem ne désactive plus le mode Code de Claude Code

  • Le mode Code commence avec claude-mem activé (#6278, merci @naive000 ; rapporté dans #6209 par @nasif-naseef). Le mode Code (expérimental, Claude Code 2.1.323 et versions ultérieures) refuse de démarrer lorsque le module hooks d'un plugin hooke tool.call. Le mod d'effacement automatique de claude-mem l'a fait, donc le mode Code était désactivé pour tous ceux avec claude-mem activé, même avec l'effacement automatique désactivé. Le mod lit désormais les résultats de l'outil via session.append à la place. L'effacement automatique fonctionne toujours sur chaque version de Claude Code qui exécute des mods (2.1.287 et versions ultérieures).

L'effacement automatique reprend là où il s'était arrêté

L'effacement automatique est toujours désactivé, sauf si vous définissez CLAUDE_MEM_AUTO_CLEAR_ENABLED sur true. Lorsqu'il est allumé :

  • Il reprend avec une invite de continuation au lieu du simple mot "continuer" (#6294). Avant d'effacer, Claude sauvegarde une dernière fois son état de travail, en nommant la liste sur laquelle il travaille, la tâche qu'il vient de terminer et l'objectif global. Après /clear, l'effacement automatique envoie : You are working on "<list>" and recently completed "<task>". Pick back up on our overarching goal "<goal>" from where you left off. Si cette sauvegarde a laissé l'un des trois de côté, elle envoie "continuer" comme avant et enregistre pourquoi.
  • Cela démarre à 40% de la fenêtre contextuelle au lieu de 33% (#6294). Un CLAUDE_MEM_AUTO_CLEAR_PERCENT que vous avez défini dans settings.json ou l'environnement gagne toujours.

De nouvelles façons de se connecter

  • Hermes Desktop, recherchez et enregistrez via MCP (#6284, merci @krishnadobhal ; partie de #5940). claude-mem hermes install --mcp-only --project-cwd <absolute-directory> ajoute claude-mem comme serveur MCP pour Hermes One et Hermes Desktop sans en faire le fournisseur de mémoire. Vous obtenez une recherche et une sauvegarde lorsque vous les demandez ; rien n'est capté ou injecté tout seul. claude-mem hermes uninstall supprime uniquement ce qu'il a écrit et restaure config.yaml octet par octet.
  • GitHub Copilot dans VS Code (#6286, merci @krishnadobhal ; partie de #5895). npx claude-mem install --ide copilot-vscode écrit l'entrée MCP que lit l'agent Copilot de VS Code (~/.copilot/mcp-config.json, le même fichier que Copilot CLI utilise). L'entrée inclut désormais "tools": ["*"]. Sans cela, VS Code s'est connecté à claude-mem mais n'a jamais proposé ses outils au modèle. Pas encore de capture automatique.
  • Préréglage ModelGo (#6277, merci @lichloe1116-gif de l'équipe ModelGo). Le fournisseur compatible OpenAI dispose d'un préréglage modelgo pour https://api.modelgo.ai/v1. Il ne définit aucun modèle par défaut, alors choisissez-en un que votre clé peut utiliser.

Aussi nouveau

  • Vérifications d'écriture de l'état de travail (#6217, merci @vieGPT). Vous pouvez demander à work_state_write d'exécuter une commande de vérification locale avant d'écrire dans les listes de votre choix, définies dans ~/.claude-mem/work-state-write-guard.json. Une écriture refusée renvoie HTTP 409 et rien n'est enregistré. Sans fichier, rien ne change.
  • CLAUDE_MEM_API_AGENT_EXTRA_BODY (#6225, merci @Moep90 ; #6223). Un objet JSON ajouté à chaque requête envoyée par l'agent api (l'actualisation My Work et l'agent de corpus avec api). Pour un modèle Qwen sur vLLM, {"chat_template_kwargs":{"enable_thinking":false}} désactive le raisonnement. Les champs tels que model, messages et max_tokens sont supprimés avec un avertissement et celui-ci n'est jamais envoyé à la passerelle cmem.ai.

Actualisation de mon travail

  • Les réponses lentes de votre propre modèle n'échouent plus au bout de 5 minutes environ (#6224, merci @Moep90 ; #6222). La récupération de Bun a abandonné une connexion qui était restée silencieuse pendant 5 minutes, avant que la limite de requête de 10 minutes de l'agent api ne s'applique. Maintenant, cette limite est la seule.
  • Points de terminaison qui souhaitent que max_completion_tokens fonctionne (#6242). Lorsqu'un point de terminaison refuse max_tokens, l'agent api renvoie la demande avec max_completion_tokens, au lieu d'échouer à chaque appel avec HTTP 400.
  • Un rafraîchissement ne bloque plus sur une réponse refusée deux fois (#6212, merci @Moep90). Lors d'une nouvelle tentative de regroupement, de focus ou de révision, les parties qui échouent aux vérifications sont supprimées et le reste est enregistré. Avant, le même lot échouait à chaque exécution.
  • L'histoire de construction est écrite en plusieurs parties (#6279, merci @0xABCD01 ; rapporté dans #6226 par @Moep90). L'étape de l'histoire a envoyé chaque avis modifié en une seule question. Cette question a dépassé la fenêtre contextuelle du modèle, et chaque actualisation ultérieure a échoué. Il envoie désormais des parties qui correspondent au même budget de questions que les autres étapes utilisent.
  • Les longues conversations sont regroupées selon leurs dernières demandes, pas leurs dix premières (#6243, merci @Afloat16).
  • Les commits effectués avec git commit --message ou --message= sont reconnus (#6236, merci @Afloat16).
  • Un commit obtient un lien GitHub uniquement lorsque la preuve nomme un référentiel (#6237, merci @Afloat16).
  • Pendant que My Rules attend un agent, il relie les instructions de configuration d'un rafraîchissement API (#6214, merci @liuyinchu).

Configuration, importation et exportation

  • L'installation se termine lorsque l'historique de vos invites est volumineux (#6280, merci @0xABCD01 ; #6266 ; rapporté dans #6227 par @deserteaglemj). L'installation s'est arrêtée à 99 % sur "Recherche de votre travail récent" lorsque les invites récentes dépassaient la limite de téléchargement hébergé de 2 Mio, et chaque nouvelle tentative a échoué de la même manière. Il termine maintenant l'installation sur votre ordinateur et le dit. L'étape de consentement indique également "Trop pour un seul téléchargement. Décochez un outil ou ignorez l'analyse." et désactive le bouton de téléchargement jusqu'à ce que la sélection corresponde.
  • Importations de grandes exportations (#6261, merci @Afloat16). Un fichier dépassant la limite de requête de 5 Mio du travailleur a été refusé (HTTP 413) avant que quoi que ce soit ne soit enregistré. Les fichiers volumineux sont désormais envoyés en plusieurs parties, les sessions en premier, avec leur contenu complet.
  • Les observations importées sont trouvées par déduplication de la même manière que les observations réelles, lorsque CLAUDE_MEM_DEDUP_ENABLED est activé (#6263, merci @Afloat16).
  • claude-mem import --dry-run ne s'arrête plus sur un mauvais paramètre de travailleur, puisqu'un aperçu n'appelle jamais le travailleur (#6215, merci @liuyinchu).
  • Les conversations Codex Desktop importées depuis un autre agent ne sont plus comptées comme des invites saisies dans Codex (#6219, merci @rigel905 ; #6218).
  • L'exportation vers /dev/stdout, /dev/stderr, un lien symbolique vers l'un ou l'autre, ou un FIFO y écrit un JSON propre, et les lignes de progression et les avertissements vont vers l'autre flux (#6288, à partir de #6258 par @Afloat16).

Correctifs

  • Windows : Claude Code charge à nouveau RULES-AND-TOOLS.md (#6234, merci @QuantScorpus). claude-mem a écrit ses lignes d'importation @ avec des barres obliques inverses. Claude Code saute celles-ci sans un mot, et Claude-mem a ensuite également laissé de côté son autre copie des instructions, de sorte qu'aucun des deux n'a atteint le modèle. Les lignes utilisent désormais des barres obliques. Une importation @ affichée dans un exemple de code clôturé ne compte plus comme la vraie (#6293, à partir de #6241 par @Afloat16).
  • claude-mem start exécute le travailleur installé (#6235, merci @ZedingZhang ; signalé dans #6228 par @ExactDoug), pas la copie vers laquelle pointe un ancien alias de shell, sur laquelle il peut manquer ses dépendances.
  • Les sauvegardes conservent le nouvel instantané une fois l'horloge réglée (#6273, merci @Afloat16). Auparavant, le nettoyage pouvait supprimer l'instantané qu'il venait de signaler comme étant enregistré.
  • teambrain join active la nouvelle connexion de synchronisation même lorsque l'étape de partage facultative échoue (#6275, merci @Afloat16).
  • Les résumés sans progrès ne sont pas stockés (#6202, merci @ShitK). Un résumé avec seulement un titre ou des projets futurs était autrefois enregistré et annoncé comme un succès.
  • Les messages automatiques de Claude Code ne fractionnent plus une requête (#6251, merci @Afloat16). Les analyses du conseiller et des livrables les ont traitées comme de nouvelles demandes et ont perdu les conseils et les écritures de fichiers antérieurs du même tour.
  • Corpus construit plus de 250 000 travaux d'observation (#6271, merci @Afloat16). Ils ont échoué avec too many SQL variables.
  • Codex : un plugin désactivé avec une clé TOML en pointillé reste désactivé (#6239, merci @Afloat16), par exemple plugins."claude-mem@claude-mem-local".enabled = false.
  • Le thème principal de la compétence de recherche de mémoire est YAML valide (#6276, merci @Afloat16 ; rapporté dans #6267 par @orbiutyt).
  • Aider : l'installateur édite le fichier de configuration qu'Aider utilise réellement (répertoire de travail d'abord, puis racine git, puis home) (#6289, à partir de #6230 par @Afloat16), et conserve intacts les chemins de fichiers cités dans les listes read: (#6290, à partir de #6231 par @Afloat16).
  • Les fichiers de contexte Cursor et Grok conservent le contexte le plus récent lorsque deux actualisations se chevauchent (#6291, à partir de #6232 par @Afloat16).
  • Serveur auto-hébergé : une tâche avec une clé révoquée ou une violation de portée s'exécute une fois au lieu de trois (#6252), et claude-mem server jobs retry republie avec les tentatives et les interruptions de la file d'attente (#6253), merci @HEOJUNFO. Le fournisseur OpenRouter lit au maximum 64 Ko lorsqu'il vérifie une réponse pour une erreur de champ de jeton (#6238, merci @Afloat16). Un événement d'agent illisible n'interrompt plus chaque lecture de cette table (#6199, merci @DeryFerd).

Sécurité

  • shell-quote 1.11.0 (#6205, merci @manippoudel ; rapporté dans #6200 par @lucasbritolubro). La version 1.9.0 est dans la plage CVE-2026-102422 (critique). Aucun chemin de code dans claude-mem n'a atteint le code concerné ; cela le retire de ce qui est expédié.
  • adm-zip 0.6.1 et zod 4.6.7 dans le runtime du plugin, hors de leurs avis High (#6220, merci @LeviReisJs ; rapporté dans #6211 par @noumanbhatti).
  • La clé Gemini API va dans un en-tête, pas dans l'URL de la requête (#6196, merci @DeryFerd), donc les proxys et les journaux d'accès ne l'enregistrent pas.
  • Les fichiers temporaires reçoivent un nom aléatoire et sont créés exclusivement sur les sites d'écriture atomique restants (#6198, #6193, merci @DeryFerd), donc un lien symbolique implanté ne peut pas rediriger une écriture de paramètres ou de fichiers d'état.
  • Le /v1/info non authentifié du serveur auto-hébergé affiche uniquement l'état (#6195, merci @DeryFerd) : pas de mode d'authentification, de version de schéma, d'hôte Redis ou de texte d'erreur de pilote.
  • CI : la vérification de la liste d'autorisation post-installation inspecte chaque dépendance directe du plugin (#6197), et la vérification de l'environnement de spawn lit les blocs d'environnement déclarés au-dessus d'un spawn et analyse le runtime du plugin (#6194), merci @DeryFerd.

Pour les contributeurs

  • TypeScript 7.0.2 (#6207, merci @krishnadobhal ; #6188). Les scripts et tests qui utilisent le compilateur API conservent TypeScript 6 via un alias.
  • Le smoke test d'import ferme ses lecteurs SQLite avant le scan final (#6216, merci @liuyinchu).

Anglais original / English original

claude-mem v15.21.0

claude-mem no longer turns off Claude Code's Code Mode

  • Code Mode starts with claude-mem enabled (#6278, thanks @naive000; reported in #6209 by @nasif-naseef). Code Mode (experimental, Claude Code 2.1.323 and later) refuses to start when a plugin's hooks module hooks tool.call. claude-mem's auto-clear mod did, so Code Mode was off for everyone with claude-mem enabled, even with auto-clear off. The mod now reads tool results through session.append instead. Auto-clear still works on every Claude Code version that runs mods (2.1.287 and later).

Auto-clear picks up where it left off

Auto-clear is still off unless you set CLAUDE_MEM_AUTO_CLEAR_ENABLED to true. When it is on:

  • It resumes with a continuation prompt instead of the bare word "continue" (#6294). Before clearing, Claude saves its work state one last time, naming the list it is working from, the task it just finished and the overall goal. After /clear, auto-clear sends: You are working on "<list>" and recently completed "<task>". Pick back up on our overarching goal "<goal>" from where you left off. If that save left any of the three out, it sends "continue" as before and logs why.
  • It starts at 40% of the context window instead of 33% (#6294). A CLAUDE_MEM_AUTO_CLEAR_PERCENT you set in settings.json or the environment still wins.

New ways to connect

  • Hermes Desktop, search and save over MCP (#6284, thanks @krishnadobhal; part of #5940). claude-mem hermes install --mcp-only --project-cwd <absolute-directory> adds claude-mem as an MCP server for Hermes One and Hermes Desktop without making it the memory provider. You get search and save when you ask for them; nothing is captured or injected on its own. claude-mem hermes uninstall removes only what it wrote and restores config.yaml byte for byte.
  • GitHub Copilot in VS Code (#6286, thanks @krishnadobhal; part of #5895). npx claude-mem install --ide copilot-vscode writes the MCP entry that VS Code's Copilot agent reads (~/.copilot/mcp-config.json, the same file Copilot CLI uses). The entry now includes "tools": ["*"]. Without it, VS Code connected to claude-mem but never offered its tools to the model. No automatic capture yet.
  • ModelGo preset (#6277, thanks @lichloe1116-gif of the ModelGo team). The OpenAI-compatible provider has a modelgo preset for https://api.modelgo.ai/v1. It sets no default model, so pick one your key can use.

Also new

  • Work-state write checks (#6217, thanks @vieGPT). You can make work_state_write run a local check command before it writes to lists you choose, set in ~/.claude-mem/work-state-write-guard.json. A refused write returns HTTP 409 and nothing is saved. With no file, nothing changes.
  • CLAUDE_MEM_API_AGENT_EXTRA_BODY (#6225, thanks @Moep90; #6223). A JSON object added to every request the api agent sends (the My Work refresh and the corpus agent with api). For a Qwen model on vLLM, {"chat_template_kwargs":{"enable_thinking":false}} turns reasoning off. Fields such as model, messages and max_tokens are dropped with a warning, and it is never sent to the cmem.ai gateway.

My Work refresh

  • Slow answers from your own model no longer fail at about 5 minutes (#6224, thanks @Moep90; #6222). Bun's fetch gave up on a connection that had been quiet for 5 minutes, before the api agent's 10-minute request limit applied. Now that limit is the only one.
  • Endpoints that want max_completion_tokens work (#6242). When an endpoint refuses max_tokens, the api agent sends the request once more with max_completion_tokens, instead of failing every call with HTTP 400.
  • A refresh no longer stalls on an answer that was refused twice (#6212, thanks @Moep90). On the one retry for grouping, focus or review, the parts that fail the checks are dropped and the rest is saved. Before, the same batch failed on every run.
  • The build story is written in parts (#6279, thanks @0xABCD01; reported in #6226 by @Moep90). The story step sent every changed review in one question. That question grew past the model's context window, and every refresh after that failed. It now sends parts that fit the same question budget the other steps use.
  • Long conversations are grouped by their latest requests, not their first ten (#6243, thanks @Afloat16).
  • Commits made with git commit --message or --message= are recognized (#6236, thanks @Afloat16).
  • A commit gets a GitHub link only when the evidence names one repository (#6237, thanks @Afloat16).
  • While My Rules waits for an agent, it links the instructions for setting up an API refresh (#6214, thanks @liuyinchu).

Setup, import and export

  • Setup finishes when your prompt history is large (#6280, thanks @0xABCD01; #6266; reported in #6227 by @deserteaglemj). Setup stopped at 99% on "Finding your recent work" when the recent prompts were over the 2 MiB hosted upload limit, and every retry failed the same way. It now finishes setup on your machine and says so. The consent step also shows "Too much for one upload. Untick a tool or skip the scan." and turns off the upload button until the selection fits.
  • Large exports import (#6261, thanks @Afloat16). A file over the worker's 5 MiB request limit was refused (HTTP 413) before anything was saved. Large files are now sent in parts, sessions first, with their full content.
  • Imported observations are found by deduplication the same way live ones are, when CLAUDE_MEM_DEDUP_ENABLED is on (#6263, thanks @Afloat16).
  • claude-mem import --dry-run no longer stops on a bad worker setting, since a preview never calls the worker (#6215, thanks @liuyinchu).
  • Conversations Codex Desktop imported from another agent are no longer counted as prompts typed in Codex (#6219, thanks @rigel905; #6218).
  • Exporting to /dev/stdout, /dev/stderr, a symlink to either, or a FIFO writes clean JSON there, and progress lines and warnings go to the other stream (#6288, from #6258 by @Afloat16).

Fixes

  • Windows: Claude Code loads RULES-AND-TOOLS.md again (#6234, thanks @QuantScorpus). claude-mem wrote its @ import lines with backslashes. Claude Code skips those without a word, and claude-mem then also left out its other copy of the instructions, so neither reached the model. The lines now use forward slashes. An @ import shown inside a fenced code example no longer counts as the real one (#6293, from #6241 by @Afloat16).
  • claude-mem start runs the installed worker (#6235, thanks @ZedingZhang; reported in #6228 by @ExactDoug), not the copy an old shell alias points at, which can be missing its dependencies.
  • Backups keep the new snapshot after the clock is set back (#6273, thanks @Afloat16). Before, cleanup could delete the snapshot it had just reported as saved.
  • teambrain join turns on the new sync connection even when the optional sharing step fails (#6275, thanks @Afloat16).
  • Summaries with no progress in them are not stored (#6202, thanks @ShitK). A summary with only a title or future plans used to be saved and announced as a success.
  • Claude Code's automatic messages no longer split a request (#6251, thanks @Afloat16). The advisor and deliverable scans treated them as new requests and lost earlier advice and file writes from the same turn.
  • Corpus builds over 250,000 observations work (#6271, thanks @Afloat16). They failed with too many SQL variables.
  • Codex: a plugin turned off with a dotted TOML key stays off (#6239, thanks @Afloat16), for example plugins."claude-mem@claude-mem-local".enabled = false.
  • The mem-search skill's frontmatter is valid YAML (#6276, thanks @Afloat16; reported in #6267 by @orbiutyt).
  • Aider: the installer edits the config file Aider actually uses (working directory first, then git root, then home) (#6289, from #6230 by @Afloat16), and keeps quoted file paths intact in read: lists (#6290, from #6231 by @Afloat16).
  • Cursor and Grok context files keep the newer context when two refreshes overlap (#6291, from #6232 by @Afloat16).
  • Self-hosted server: a job with a revoked key or a scope violation runs once instead of three times (#6252), and claude-mem server jobs retry republishes with the queue's retries and backoff (#6253), thanks @HEOJUNFO. The OpenRouter provider reads at most 64 KiB when it checks an answer for a token-field error (#6238, thanks @Afloat16). One unreadable agent event no longer breaks every read of that table (#6199, thanks @DeryFerd).

Security

  • shell-quote 1.11.0 (#6205, thanks @manippoudel; reported in #6200 by @lucasbritolubro). Version 1.9.0 is in the range of CVE-2026-102422 (critical). No code path in claude-mem reached the affected code; this takes it out of what ships.
  • adm-zip 0.6.1 and zod 4.6.7 in the plugin runtime, out of their High advisories (#6220, thanks @LeviReisJs; reported in #6211 by @noumanbhatti).
  • The Gemini API key goes in a header, not the request URL (#6196, thanks @DeryFerd), so proxies and access logs don't record it.
  • Temp files get a random name and are created exclusively at the remaining atomic-write sites (#6198, #6193, thanks @DeryFerd), so a planted symlink can't redirect a write of settings or state files.
  • The self-hosted server's unauthenticated /v1/info shows state only (#6195, thanks @DeryFerd): no auth mode, schema version, Redis host or driver error text.
  • CI: the postinstall allowlist check inspects every direct plugin dependency (#6197), and the spawn environment check reads env blocks declared above a spawn and scans the plugin runtime (#6194), thanks @DeryFerd.

For contributors

  • TypeScript 7.0.2 (#6207, thanks @krishnadobhal; #6188). The scripts and tests that use the compiler API keep TypeScript 6 through an alias.
  • The import smoke test closes its SQLite readers before the final scan (#6216, thanks @liuyinchu).
