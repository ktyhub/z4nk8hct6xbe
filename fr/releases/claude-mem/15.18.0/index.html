claude-mem v15.18.0

#claude-mem v15.18.0

Les agents de veille ont la même mémoire que Claude Code et Codex

claude-mem/eve donne désormais à un agent eve la boucle mémoire complète claude-mem via votre compte cmem.ai (#6042).

  • Contexte de la session : chaque tour commence par la chronologie récente de votre mémoire. Il est actualisé à chaque tour sous un seul identifiant de message, il se remplace donc au lieu de s'accumuler.
  • Rappel à chaque tour : une recherche avant le tour, comme avant.
  • L'enregistrement est désormais activé par défaut. Après chaque tour terminé, le fournisseur envoie l'invite, une observation par appel d'outil et un résumé du tour à cmem.ai en tant que plateforme eve. Les appels d'outils enregistrés et les résumés proviennent de votre allocation d'observateur cmem.ai, la même allocation que vos autres clients utilisent. Passez capture: false pour conserver l'ancien comportement en lecture seule ; le contexte de session, le rappel, la recherche et remember continuent de fonctionner.
    • Les régions <private>…</private> et le texte en forme de secret sont supprimés de votre déploiement avant que quoi que ce soit ne soit envoyé, avec les mêmes règles utilisées par le plugin Cowork.
    • Les rediffusions du même tour sont supprimées par cmem.ai (identifiants d'appel d'outil à l'échelle du tour et clé d'idempotence).
    • Chaque demande est envoyée une seule fois. Pas de nouvelle tentative, de file d'attente ou de file d'attente, donc une panne n'entraîne jamais de dépenses plus tard. Un échec est enregistré avec le nombre d'événements acceptés.
  • Outils : search, timeline, get_observations (la recherche intelligente en trois étapes) et remember.
  • versions veille : testées sur veille 0.84.0 et 1.0.0-rc.9.
  • Modèle : fonctionne sur une passerelle Vercel AI à crédit gratuit (Claude, revenant à openai/gpt-5-mini lorsque Claude se voit refuser des crédits gratuits), ou configurez ANTHROPIC_API_KEY pour appeler Claude directement et EVE_MODEL pour choisir un modèle exact. Les exécutions planifiées obtiennent la mémoire du propriétaire, l'e-mail du propriétaire doit correspondre exactement et un exemple de planification du résumé du matin est désactivé.

Documents : https://docs.claude-mem.ai/eve-integration

Les choix d'installation sont déplacés vers le navigateur

Une installation standard configure désormais le runtime dans le terminal, puis ouvre la configuration Web locale pour choisir les agents et les intégrations, les compétences groupées, le modèle, les préférences de mémoire native, les mises à jour facultatives par courrier électronique et la télémétrie (#5967). Les shells d'agent peuvent passer --setup browser lorsqu'une personne est là, ou --setup defer pour laisser les choix pour la première visite My Work. Les installations explicites de --provider / --ide et npx claude-mem update se comportent comme avant.

Aussi nouveau

  • Gemini CLI : capture native du cycle de vie avec npx claude-mem gemini install|status|uninstall (#5991, merci @Kirat0201, ferme le #5949). Documents : https://docs.claude-mem.ai/gemini-cli/setup
  • Corpus de connaissances sur votre fournisseur API (opt-in) : CLAUDE_MEM_CORPUS_AGENT=api répond à query_corpus via l'OpenRouter sélectionné ou le fournisseur compatible OpenAI au lieu de l'Agent Claude SDK. La valeur par défaut est inchangée (#5682, merci @bulanovk).
  • Agent SDK : un exemple de mémoire à l'échelle d'un projet (#5995, merci @Kirat0201).

Clarification de la confidentialité

  • Téléchargements d'historique d'invite (#5176) : la configuration du navigateur demande avant d'envoyer l'historique d'invite sélectionné à cmem.ai (corrigé dans v15.8.3, #5220). Ignorer cette étape n'envoie aucun historique d'invite. La compétence Objectifs du propriétaire peut utiliser votre agent de codage existant pour analyser l'historique local et l'enregistrer via le travailleur local sans téléchargement d'intention cmem.ai distinct. L'inférence utilise toujours le fournisseur de modèles de cet agent. La mise à jour ne supprime pas les données précédemment envoyées.

Correctifs

Merci @Afloat16 pour chaque correctif ci-dessous, sauf si un autre nom est donné.

Recherche et mémoire

  • Les mots Unicode dans les questions longues correspondent toujours aux mémoires indexées (#5997) ; correspondance des titres canoniquement équivalents (#5975) ; les barres obliques inverses littérales dans l'historique des fichiers POSIX sont conservées (#5985, merci @Kirat0201) ; le point final sémantique d'observation uniquement pagine (# 5892).
  • Recall survit aux fusions de projets répétées (#5990), et Chroma conserve les métadonnées en direct lors d'une fusion et démarre les grands projets sans diffuser les identifiants de ligne (#5881, #5862).
  • Le contenu d'observation structuré distinct n'est plus fusionné (#5979) ; les identités de session manuelles en collision sont séparées (#5868).
  • Notes de mémoire native : les métadonnées citées sont décodées (#5983), les analyses Markdown avec le préfixe BOM (#5976) et le frontmatter a besoin d'une véritable ligne de clôture de niveau supérieur (#5845).
  • Les réponses aux connaissances en plusieurs parties sont conservées entières (#6002).

Contexte et serveur

  • Les lignes de contexte du serveur obéissent aux filtres de mode (#5993, merci @0xABCD01) et conservent leurs plates-formes lorsque les réponses précédentes sont sélectionnées (#6003) ; Les étiquettes mises en cache sont actualisées une fois l'utilisation de la découverte réglée (#6006).
  • Le serveur conserve la portée de la plate-forme pour les mémoires manuelles non liées (#5875), l'identité native des reçus via la validation des événements (#5872), les plates-formes d'événements dans les flux des spectateurs (#5846) et capture les reçus de mutation dans la portée de la clé (#5883).
  • Les touches de rappel déléguées nécessitent une portée de lecture (#5856) ; les résultats de la génération en cours sont purgés avant d'être renvoyés (#5858) ; les corps récapitulatifs récupérés s'affichent dans la visionneuse (#5869).
  • L'arrêt cesse d'accepter HTTP avant de vider les connexions (#5853).
  • L'observateur conserve l'identité de livraison lorsque la capture est désactivée (#5867) ; sync conserve la boîte d'envoi lorsqu'un push arrêté est rejeté (#5850).

Importation et configuration

  • Les importations conservent l'historique Codex compressé (#6000), la provenance des parties de texte Gemini et les modifications de l'historique JSONL (#5999, #5865), Unicode dans la provenance rapide (#5989), les invites Claude héritées distinctes (#5982) et le texte d'observation hérité (#5854) ; l’activité de fork OpenCode copiée est exclue (#6004).
  • Un import d'historique est limité à ses lignes de départ (#5877) ; les analyses locales incluent l'historique du Codex archivé (n° 5888) ; la couverture symbolique laisse de côté l'historique des observateurs et les estimations du contexte du Codex (#5847, #5886).
  • Les exportations incluent l'historique complet enregistré (#5879) ; les ancêtres liés au répertoire de données travaillent pour les médias (# 5874); La règle Claude Code importe les espaces d'échappement (#5852).
  • La télémétrie révèle le partage par défaut lors de la première session (#5884).

Mon travail

  • Les passes de synchronisation du travail partagé sont limitées afin qu'un thread bloqué ne puisse pas bloquer les actions du propriétaire (#6014, merci @LuckVd), et les demandes des lecteurs ont une date limite (#5860, merci @LuckVd).
  • La provenance de la session est republiée après l'échec de la publication d'une activité (#6010, merci @bulanovk) ; La publication d’activité partagée ayant échoué est réessayée (#5870).
  • Les objectifs du propriétaire suppriment les citations invérifiables d'une nouvelle sauvegarde au lieu de refuser l'intégralité de la sauvegarde (#5992, merci @0xABCD01) ; les instantanés d'objectifs contenant uniquement des règles sont réutilisés (#5987) ; les nouvelles décisions de focus survivent à une annulation (#5849).
  • Les produits sont actualisés lorsque les fichiers locaux changent (#5887), les produits GitHub sont liés à partir de la sortie push SSH (#5998), les options git push valorisées sont analysées avant les cibles (#5885) et les sujets de validation entre guillemets simples sont conservés littéralement (#5896).
  • Les livrables conservent les déclarations des copies précédemment capturées (#5973).

Intégrations

  • OpenCode : le contrat actuel de l'outil intégré V2 est normalisé et l'état de l'outil défaillant est conservé (#5857, #5855).
  • OMP : la sémantique native de l'outil et l'identité de la réception de l'appel de l'outil sont conservées et les hooks s'installent dans le profil sélectionné (#5871, #5864, #5876).
  • OpenClaw : la configuration JSON5 est acceptée et la configuration de l'hôte et les chemins d'état sélectionnés sont utilisés (#5861, #5844).
  • Windsurf : les commandes de hook utilisateur survivent à l'installation et l'identité du serveur MCP est conservée pour le filtrage de récursion (#5882, #5880).
  • Curseur : les enveloppes argument MCP et résultat JSON sont décodées (#5848). DSH : le chemin de transcription géré s'actualise lors de la réinstallation (#5873). Code T3 : l'état du plugin TOML est lu avant la suppression (#5851).
  • La lecture intelligente des fichiers inclut les déclarations d'en-tête C et C++, les constructeurs d'enregistrements Java compacts et les TypeScript declare function (#6015, #6012, #6005) ; Les littéraux XML conservent leurs balises de fermeture (#5977).

Rédaction et performance

  • Les jetons d'accès Pulumi et les jetons personnels Doppler sont expurgés (#5984, merci @kevin9327).
  • La télémétrie regroupe les statistiques d'événements à l'arrivée (#5994), les longues lignes de transcription sont assemblées une fois lors de l'importation (#5981), l'utilisation du jeton OpenCode est diffusée en continu (#5974) et les anciennes recherches d'invites dans la visionneuse sont limitées par le temps (#6011).

Documents

  • Les guides du framework d'agent sont regroupés et un paramètre qui n'existe pas a été supprimé (#6030).
  • La réclamation du jeton est exprimée sous la forme d'un rapport de taille par résultat (#5889, merci @Zhong-fan, #4138).

claude-mem v15.18.0

eve agents get the same memory as Claude Code and Codex

claude-mem/eve now gives an eve agent the full claude-mem memory loop through your cmem.ai account (#6042).

  • Session context: each turn starts with the recent timeline from your memory. It is refreshed every turn under one message id, so it replaces itself instead of piling up.
  • Recall each turn: one search before the turn, as before.
  • Recording is now on by default. After each completed turn the provider sends the prompt, one observation per tool call, and a turn summary to cmem.ai as platform eve. Recorded tool calls and summaries come out of your cmem.ai observer allowance, the same allowance your other clients use. Pass capture: false to keep the old read-only behaviour; session context, recall, search and remember keep working.
    • <private>…</private> regions and secret-shaped text are removed on your deployment before anything is sent, with the same rules the Cowork plugin uses.
    • Replays of the same turn are dropped by cmem.ai (turn-scoped tool call ids and an idempotency key).
    • Each request is sent once. No retry, spool or queue, so an outage never creates spend later. A failure is logged with how many events were accepted.
  • Tools: search, timeline, get_observations (the three-step Smart search) and remember.
  • eve versions: tested on eve 0.84.0 and 1.0.0-rc.9.
  • Template: works on a free-credit Vercel AI Gateway (Claude, falling back to openai/gpt-5-mini when Claude is refused on free credits), or set ANTHROPIC_API_KEY to call Claude directly and EVE_MODEL to pick an exact model. Scheduled runs get the owner's memory, owner email must match exactly, and a morning-digest example schedule ships turned off.

Docs: https://docs.claude-mem.ai/eve-integration

Install choices move to the browser

A standard install now sets up the runtime in the terminal, then opens the local web setup to choose agents and integrations, bundled skills, model, native-memory preferences, optional email updates and telemetry (#5967). Agent shells can pass --setup browser when a person is there, or --setup defer to leave the choices for the first My Work visit. Explicit --provider / --ide installs and npx claude-mem update behave as before.

Also new

  • Gemini CLI: native lifecycle capture with npx claude-mem gemini install|status|uninstall (#5991, thanks @Kirat0201, closes #5949). Docs: https://docs.claude-mem.ai/gemini-cli/setup
  • Knowledge corpus on your API provider (opt-in): CLAUDE_MEM_CORPUS_AGENT=api answers query_corpus through the selected OpenRouter or OpenAI-compatible provider instead of the Claude Agent SDK. The default is unchanged (#5682, thanks @bulanovk).
  • Agent SDK: a project-scoped memory example (#5995, thanks @Kirat0201).

Privacy clarification

  • Prompt-history uploads (#5176): browser setup asks before sending selected prompt history to cmem.ai (fixed in v15.8.3, #5220). Skip this step sends no prompt history. The owner-goals skill can use your existing coding agent to analyze local history and save through the local worker without a separate cmem.ai intent upload. Inference still uses that agent's model provider. Updating does not remove data previously sent.

Fixes

Thanks @Afloat16 for every fix below unless another name is given.

Search and memory

  • Unicode words in long questions still match indexed memories (#5997); canonically equivalent titles match (#5975); literal backslashes in POSIX file history are kept (#5985, thanks @Kirat0201); the observation-only semantic endpoint paginates (#5892).
  • Recall survives repeated project merges (#5990), and Chroma keeps live metadata during a merge and bootstraps large projects without spreading row ids (#5881, #5862).
  • Distinct structured observation content is no longer merged (#5979); colliding manual session identities are kept apart (#5868).
  • Native memory notes: quoted metadata is decoded (#5983), BOM-prefixed Markdown parses (#5976), and frontmatter needs a real top-level closing line (#5845).
  • Knowledge answers in several parts are kept whole (#6002).

Context and server

  • Server context rows obey mode filters (#5993, thanks @0xABCD01) and keep their platforms when prior replies are selected (#6003); cached labels refresh after discovery usage settles (#6006).
  • The server keeps platform scope for unlinked manual memories (#5875), native receipt identity through event validation (#5872), event platforms in viewer feeds (#5846), and capture mutation receipts within the key's scope (#5883).
  • Delegated recall keys need read scope (#5856); in-flight generation results are purged before returning (#5858); salvaged summary bodies show in the viewer (#5869).
  • Shutdown stops accepting HTTP before draining connections (#5853).
  • The observer keeps delivery identity when capture is disabled (#5867); sync keeps the outbox when a stopped push is rejected (#5850).

Import and setup

  • Imports keep compressed Codex history (#6000), Gemini text-part provenance and JSONL history edits (#5999, #5865), Unicode in prompt provenance (#5989), distinct legacy Claude prompts (#5982) and legacy observation text (#5854); copied OpenCode fork activity is excluded (#6004).
  • A history import is bounded to its starting rows (#5877); local scans include archived Codex history (#5888); token coverage leaves out observer history and Codex context estimates (#5847, #5886).
  • Exports include the full saved history (#5879); linked data-directory ancestors work for media (#5874); Claude Code rule imports escape spaces (#5852).
  • Telemetry discloses default sharing in the first session (#5884).

My Work

  • Shared-work sync passes are bounded so a hung thread cannot stall owner actions (#6014, thanks @LuckVd), and reader requests have a deadline (#5860, thanks @LuckVd).
  • Session provenance is republished after a failed activity publish (#6010, thanks @bulanovk); failed shared-activity publication is retried (#5870).
  • Owner goals drop unverifiable quotes from a fresh save instead of refusing the whole save (#5992, thanks @0xABCD01); rules-only goal snapshots are reused (#5987); newer focus decisions survive an undo (#5849).
  • Products refresh when local files change (#5887), GitHub products link from SSH push output (#5998), valued git push options parse before targets (#5885), and single-quoted commit subjects are kept literally (#5896).
  • Deliverables keep declarations for previously captured copies (#5973).

Integrations

  • OpenCode: the current V2 built-in tool contract is normalized and failed tool status is kept (#5857, #5855).
  • OMP: native tool semantics and tool-call receipt identity are kept, and hooks install into the selected profile (#5871, #5864, #5876).
  • OpenClaw: JSON5 configuration is accepted, and the selected host config and state paths are used (#5861, #5844).
  • Windsurf: user hook commands survive installation and the MCP server identity is kept for recursion filtering (#5882, #5880).
  • Cursor: MCP argument and result JSON envelopes are decoded (#5848). DSH: the managed transcript path refreshes on reinstall (#5873). T3 Code: TOML plugin state is read before removal (#5851).
  • Smart file reading includes C and C++ header declarations, compact Java record constructors and TypeScript declare functions (#6015, #6012, #6005); XML literals keep their closing tags (#5977).

Redaction and performance

  • Pulumi access tokens and Doppler personal tokens are redacted (#5984, thanks @kevin9327).
  • Telemetry aggregates event statistics on arrival (#5994), long transcript lines are assembled once on import (#5981), OpenCode token usage is streamed (#5974), and legacy prompt retry lookups in the viewer are bounded by time (#6011).

Docs

  • Agent framework guides are grouped, and a setting that does not exist was removed (#6030).
  • The token claim is stated as a per-result size ratio (#5889, thanks @Zhong-fan, #4138).
