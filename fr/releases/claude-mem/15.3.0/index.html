#claude-mem v15.3.0

Ce qui a changé

Livrables sur la fiche Mon travail (#5109)

Demandez à un agent un dossier, un rapport, une page HTML ou tout autre fichier, et il se trouve à un click au recto de la carte de demande dans Mon travail, sous Livrables.

  • Le hook Stop copie ce que le tour a fait pour vous dans ~/.claude-mem/deliverables/<project>/, adressé au contenu (report-3f9a1c2b.md), de sorte que la copie survit à l'arbre de travail, au dossier de travail ou au répertoire temporaire dans lequel elle a été créée. Les fichiers qu'un agent joint via work_state_write (work_product, deliverable ou tout champ nommant un fichier qu'une personne ouvre) comptent, tout comme les decks, documents, pages, images, vidéos et feuilles de calcul écrites en dehors de l'arborescence source. Les fichiers sources ne sont jamais copiés par inférence. SubagentStop capture ce qu'un sous-agent a fait à partir de sa propre transcription.
  • Le travailleur enregistre et sert chaque copie sur GET /api/deliverables/:id/:filename, avec les mêmes règles de bouclage, de même origine et de bac à sable que les fichiers enregistrés ; démarque et texte ouverts en ligne. Lorsqu'une copie est sur le disque et que le fichier n'a pas été écrit depuis, elle constitue l'enregistrement de l'endroit où le fichier a été créé.
  • La confidentialité et les limites sont explicites. Un tour dont l'invite est entièrement <private> ne laisse aucune copie ni aucun enregistrement. Rien n'est copié pour un travailleur sur un autre hôte, qui n'a pas pu ouvrir la copie. 50 fichiers par arrêt et 512 Mio par fichier, signalés en cas d'atteinte, jamais silencieux. CLAUDE_MEM_DELIVERABLES_ENABLED=false désactive la copie.
  • La règle d'état de travail SessionStart demande désormais aux agents d'écrire ce que vous avez demandé sous forme de fichier et de le joindre sous le nom work_product avant de terminer.

Aussi nouveau

  • Instantanés automatiques de base de données locale avec restauration sécurisée : npx claude-mem backup [run|status|list] et npx claude-mem restore. Désactivé par défaut ; CLAUDE_MEM_BACKUP_ENABLED=true avec CLAUDE_MEM_BACKUP_INTERVAL_HOURS et CLAUDE_MEM_BACKUP_RETAIN_COUNT. (#3751)
  • Export Notion. Chaque nouvelle observation est insérée dans une base de données Notion dès son stockage. Inscrivez-vous via CLAUDE_MEM_NOTION_ENABLED, un jeton et un identifiant de base de données ; ne bloque jamais la capture. (#4799)
  • Les sous-agents Codex démarrent avec la chronologie de la mémoire. Un nouveau hook SubagentStart donne à un nouveau sous-agent le même contexte que SessionStart donne à une session ; les forks, qui héritent de l'historique de leurs parents, sont ignorés. Le Codex demande une fois de trust le nouveau crochet. (#4760)
  • Préglage Runcrate pour le fournisseur compatible openai. (#5067)

Correctifs

  • Antigravity CLI : claude-mem n'enregistre plus PreToolUse, qui approuvait automatiquement chaque appel d'outil agy et mettait chaque appel en file d'attente deux fois (#5085). Les invites agy sont désormais enregistrées une fois par tour, donc le travail agy apparaît dans Mon travail et les fichiers lus dans agy obtiennent leur historique d'observation (#5092).
  • Caviardage : les informations d'identification AWS temporaires sont entièrement rédigées : ID de clé d'accès ASIA, jetons de session et SecretAccessKey dans la sortie aws sts JSON (#5066, #5073, #5080).
  • Transcriptions : les points de contrôle des observateurs sont maintenus jusqu'à ce que le travail mis en mémoire tampon soit stocké (#5072) ; le chemin de configuration de la surveillance de la transcription suit CLAUDE_MEM_DATA_DIR (#5070).
  • Analyseur Observer : lit le type sur lequel le modèle s'est installé, sans jamais baliser autour de lui (#5077).
  • Windows : le lanceur compile via le chemin court 8.3 lorsque bun.exe se trouve sur un chemin non-ASCII (#5089).
  • L'aperçu du terminal SessionStart laisse de la place pour son pied de page (#5084) ; L'aide à l'installation indique quels fournisseurs ont besoin d'une connexion cmem.ai (#5086).
  • Outils de version : chaque manifeste de plugin livré contient la même version, synchronisée par la build et enregistrée dans CI (#5083, #5082, #5075). Changelog complet : https://github.com/thedotmack/claude-mem/compare/v15.2.1...v15.3.0

claude-mem v15.3.0

What changed

Deliverables on the My Work card (#5109)

Ask an agent for a deck, a report, an HTML page or any other file, and it is one click away on the front of the request's card in My Work, under Deliverables.

  • The Stop hook copies what the turn made for you into ~/.claude-mem/deliverables/<project>/, content-addressed (report-3f9a1c2b.md), so the copy outlives the worktree, scratch folder or temp directory it was made in. Files an agent attaches through work_state_write (work_product, deliverable, or any field naming a file a person opens) count, as do decks, documents, pages, images, video and spreadsheets written outside the source tree. Source files are never copied by inference. SubagentStop captures what a subagent made from its own transcript.
  • The worker records and serves each copy at GET /api/deliverables/:id/:filename, with the same loopback, same-origin and sandbox rules as recorded files; markdown and text open inline. While a copy is on disk and the file has not been written since, it stands in for the record of where the file was made.
  • Privacy and limits are explicit. A turn whose prompt is entirely <private> leaves no copy and no record. Nothing is copied for a worker on another host, which could not open the copy. 50 files per Stop and 512 MiB per file, reported when hit, never silent. CLAUDE_MEM_DELIVERABLES_ENABLED=false turns the copy off.
  • The SessionStart work-state rule now asks agents to write the thing you asked for as a file and attach it as work_product before they finish.

Also new

  • Automatic local database snapshots with crash-safe restore: npx claude-mem backup [run|status|list] and npx claude-mem restore. Off by default; CLAUDE_MEM_BACKUP_ENABLED=true with CLAUDE_MEM_BACKUP_INTERVAL_HOURS and CLAUDE_MEM_BACKUP_RETAIN_COUNT. (#3751)
  • Notion export. Each new observation is upserted into a Notion database as soon as it is stored. Opt-in through CLAUDE_MEM_NOTION_ENABLED, a token and a database id; never blocks capture. (#4799)
  • Codex subagents start with the memory timeline. A new SubagentStart hook gives a fresh subagent the same context SessionStart gives a session; forks, which inherit their parent's history, are skipped. Codex asks once to trust the new hook. (#4760)
  • Runcrate preset for the openai-compatible provider. (#5067)

Fixes

  • Antigravity CLI: claude-mem no longer registers PreToolUse, which auto-approved every agy tool call and queued each call twice (#5085). agy prompts are now recorded once per turn, so agy work shows up in My Work, and files read in agy get their observation history (#5092).
  • Redaction: temporary AWS credentials are redacted in full: ASIA access key IDs, session tokens, and the SecretAccessKey in aws sts JSON output (#5066, #5073, #5080).
  • Transcripts: watcher checkpoints are held until buffered work is stored (#5072); the transcript-watch config path follows CLAUDE_MEM_DATA_DIR (#5070).
  • Observer parser: reads the type the model settled on, never markup around it (#5077).
  • Windows: the launcher compiles through the 8.3 short path when bun.exe is on a non-ASCII path (#5089).
  • SessionStart terminal preview leaves room for its footer (#5084); install help says which providers need a cmem.ai sign-in (#5086).
  • Release tooling: every shipped plugin manifest carries the same version, synced by the build and checked in CI (#5083, #5082, #5075).

Full Changelog: https://github.com/thedotmack/claude-mem/compare/v15.2.1...v15.3.0
