Highlights

  • Local voice conversion and casting workflows — Studio’s new Convert method applies a saved voice profile to recorded or uploaded speech, with optional source-duration matching, entirely locally (#1765). Dubbing adds a project-level casting board where drag-and-drop or keyboard-accessible lists update the same per-speaker assignments as existing controls (#1767).
  • Automation and richer media exports — Batch queues can watch a folder and auto-enqueue new videos using the last add-to-queue settings, with copy-in-progress protection (#1768). Hardsub export gains opt-in karaoke captions backed by persisted word timings and a GET /dub/ass/{job_id} sidecar (#1764), while audiobook results provide local, render-timed text highlighting and click-to-seek without an ASR pass (#1766).
  • Expanded native and isolated engine support — audio.cpp adds an opt-in CPU backend for Breeze-TTS-2 with English/Chinese speech-to-speech, cloning and voice design, without a Python virtual environment (#1891). Installed CUDA, HIP, Metal and Vulkan providers are used directly, preserving device routing across remote workers (#1926); Apple Silicon also gets a single canonical OmniVoice picker entry while retaining crash isolation (#1913).
  • File-based MCP and lower-cost editing — MCP tools can return audio as files and accept file inputs constrained to a configured base path, avoiding audio in agent context (#1760). Dub editing adds opt-in live TTS preview over the existing /ws/tts socket (#1769); exports still render at full quality.
  • Installation and dependency fixes — One-click installs no longer inherit VoiceStudio’s PyTorch pin, which had blocked MOSS-TTS-v1.5 and Confucius4-TTS (#2024). Uninstalling translation engines no longer removes shared dependencies (#2019). Windows adds an independently updatable per-user MSI requiring no elevation (#1713), and downloads now resume after connection failures (#1940).
  • Operational diagnostics and clearer failure handling — Engine diagnostics now capture execution provider, device, precision, fallback stage, accelerator identity and runtime versions (#1717). Generation errors identify backend error classes (#1800), while engine catalogues expose estimated and measured disk costs (#1718), helping distinguish deployment issues from resource shortages.

No breaking changes are called out in this changelog.
