#VoiceStudio v0.5.1

Points forts

  • La génération OmniVoice sur Apple Silicon s'exécute désormais dans un enfant isolé en cas de crash, donc les sorties de mémoire MPS fatales ne suppriment plus le backend local (#1697, #1698) — merci ndntran14 !
  • L'épuisement du GPU lors du chargement du modèle renvoie désormais une erreur de doublage épurée et exploitable, et la préparation attribue correctement l'état du modèle partagé à TTS (#1695).
  • Le développement en mode source redémarre désormais un crash backend isolé sans détruire l'interface utilisateur, tandis que les boucles de crash répétées s'arrêtent toujours bruyamment avec les diagnostics (#1690)
  • La lecture du doublage conserve désormais une source compagnon audible lorsqu'un WebView peut restituer l'image d'aperçu mais ne peut pas décoder son audio (#1692)
  • Les lignes du moteur du catalogue de modèles utilisent désormais la largeur du bureau disponible et empêchent l'identité, l'état d'exécution et les actions de s'encombrer les unes les autres (#1689).
  • VoiceStudio agit désormais comme une plate-forme vocale locale : d'autres applications peuvent déclencher sa dictée native ou se connecter via des transports HTTP, WebSocket, JSON-RPC, CLI et MCP versionnés (#1646)
  • Une transcription de doublage en cours expirée ne démarre plus un deuxième appel WhisperX/CTranslate2 sur le travailleur natif abandonné, empêchant ainsi le chevauchement d'accès qui a précédé la sortie de Windows 0xC0000005 (#1669)
  • Le code de terminaison du débogueur Windows 0x40010004 n'est plus signalé à tort comme un crash du backend ou imputé à la récupération au redémarrage automatique (#1663)
  • Studio conserve désormais une réservation de génération lors des changements de page, empêchant un remontage d'empiler les tâches natives jusqu'à ce que le backend signale une capacité occupée ou soit tué sous la pression de la mémoire (#1670)
  • Les vidéos de doublage téléchargées sont normalisées au format H.264/AAC sécurisé pour le navigateur avant l'aperçu, empêchant ainsi les médias VP9, AV1 ou Opus valides d'échouer sans « aucune source prise en charge » (#1644)
  • Le doublage sépare désormais les langues parlées et cibles, préserve les traductions grâce au nettoyage des segments et permet de réessayer ou d'ignorer les traductions ayant échoué sans redémarrer le lot (#1654) — merci Number16BusShelter !
  • L'importation de sous-titres SRT de remplacement maintient désormais chaque réplique liée au haut-parleur source et au clone qui se chevauchent le mieux au lieu de réinitialiser chaque ligne sur une voix aléatoire par défaut (#1660) — merci invio-a11y !
  • Le téléchargement d'un aperçu Dub ne bloque plus toutes les requêtes du backend pendant que ffmpeg extrait son audio (#1667) — merci tfreyd !
  • Les démarrages rapides de Docker nécessitent désormais la clé d'administrateur nécessaire via le conteneur NAT au lieu de démarrer une interface utilisateur dont les actions protégées renvoient 403 (#1651) — merci wd357dui !
  • Les conteneurs WSL2 AMD utilisent désormais le pont /dev/dxg ROCDXG avec des diagnostics GPU exploitables au lieu de revenir silencieusement au CPU (#1655) — merci wd357dui !
  • Les références de clone vocal ad hoc restent désormais actives jusqu'à ce que le travail GPU annulé ou expiré cesse de les lire, afin que la mise en cache rapide puisse se terminer au lieu d'échouer sur un fichier temporaire supprimé (#1668) — merci tfreyd !
  • La dictée reste désormais liée à l'application où elle a démarré et récupère localement à partir de la sortie de la reconnaissance silencieuse (#1175)
  • Le backend répond désormais dans la seconde qui suit le lancement et raconte son démarrage étape par étape (#1550)
  • Signaler un bug à partir d'une version obsolète propose désormais en premier la dernière version (#1547)
  • Le backend n'est annoncé prêt que lorsqu'il peut réellement servir, et les redémarrages en boucle de crash s'effectuent désormais d'eux-mêmes (#1548)
  • Le filigrane invisible ne bloque plus – ou ne saute plus silencieusement – la première prise d'une session (#1615)
  • Les sous-titres dub peuvent être resynchronisés, insérés et fusionnés dans les deux sens à partir de la table de segments (#1612) — merci invio-a11y !

Modifié

  • Le catalogue de modèles utilise désormais un canevas d'espace de travail respirant avec une navigation plus simple dans les volets et les familles de moteurs au lieu de cartes imbriquées et de régions de défilement (#1685).
  • Les lanceurs de sources Linux détectent désormais les plugins audio libxdo et GStreamer manquants avant qu'ils ne provoquent une erreur de l'éditeur de liens ou un moteur de rendu WebKit vide et avorté (#1680, #1682)
  • La dictée comporte désormais une session de sortie native depuis le raccourci jusqu'à la livraison finale, restaure le texte, le HTML, l'image ou la liste de fichiers uniquement lorsqu'ils ne sont pas touchés, maintient Wayland en sécurité contre la copie à moins que l'insertion du focus actuel ne soit explicitement activée et réessaye la parole Sherpa silencieuse uniquement via un modèle ASR local déjà installé (# 1175)
  • Le backend lie son port immédiatement et rapporte la progression du démarrage en direct — /health répond 503 par étape et un nouveau point de terminaison /startup/progress répertorie chaque étape pendant que PyTorch, les routes API et les migrations de bases de données se chargent en arrière-plan, donc "commencer à l'étape X" ne peut jamais être confondu avec "mort" ; le splash du bureau raconte chaque étape (#1550)

Ajouté

  • Un side-car de bouclage Rust fourni expose le démarrage/arrêt/basculement de la dictée, les sessions de sortie ciblée, la découverte et le JSON-RPC ; le backend ajoute des événements de streaming versionnés et un pont CLI sans dépendance pour Herdr, les agents de codage, les éditeurs, les applications de bureau et les TUI (#1646)
  • Les machines NVIDIA et ROCm sans tête peuvent désormais rejoindre en tant que services Docker Compose réservés aux travailleurs, sans interface utilisateur publiée et inscription au protocole v2 durable ; mettez à jour les deux machines ensemble avant de vous reconnecter (#1638) — merci jkrogers9862 !
  • Prise en charge de Linux ARM64 (Asahi Apple Silicon) pour le moteur OmniVoice GGUF — un binaire linux-aarch64 construit avec GGML Vulkan là où la chaîne d'outils le permet, afin que les GPU Apple accélèrent la génération via le pilote open source Honeykrisp au lieu de revenir au processeur uniquement (#1641)
  • Installation en une seule commande sur chaque système d'exploitation de bureau : curl -fsSL https://voicestudio.sh/install | sh (macOS/Linux/WSL) ou irm https://voicestudio.sh/install | iex (Windows) — l'URL sert le bon script par plate-forme, et Windows obtient un programme d'installation source (scripts/install.ps1) avec une fumée CI à 3 systèmes d'exploitation (#1626)
  • Gestion des sous-titres par ligne dans la table de doublage : l'heure de fin d'une ligne est modifiable à côté de son début (saisir une heure et faire glisser le bord de la timeline prend désormais le même chemin), les lignes fusionnent avec la ligne précédente ainsi qu'avec la suivante (Ctrl/Cmd+Shift+M), et une nouvelle ligne peut être insérée dans l'espace après n'importe quelle ligne (#1612) — merci invio-a11y !
  • CI applique désormais des budgets de régression de performances sur les hot paths : les tests de nombre d'opérations épinglent le streaming TTS à une synthèse par phrase et les remixes de doublage en cache à zéro re-synthèse ; les protections fast-path couvrent zéro redécodage et les appels par lots natifs ⌈N/W⌉ lorsqu'elles sont activées (#1594)
  • Le doublage par moteur par défaut synthétise désormais plusieurs segments par passage direct au lieu d'un appel par ligne — la largeur suit la marge du périphérique de l'hôte (1 sur les cartes CPU et à faible VRAM, jusqu'à 8), OMNIVOICE_DUB_BATCH_WIDTH la remplace et les moteurs sans traitement par lots natif conservent le chemin à segment unique (#1594).
  • /ws/tts rapporte désormais le temps réel jusqu'au premier audio, et son RTF mesure seul la synthèse afin qu'un client lent ne puisse pas le gonfler (#1594)
  • Le générateur de filigrane AudioSeal mis en cache localement se réchauffe sur un thread d'arrière-plan environ 35 secondes après le démarrage (OMNIVOICE_PRELOAD_WATERMARK=0 se désactive ; la configuration explicite de =1 peut le télécharger), de sorte que la première synthèse ne sérialise plus l'importation audioseal + le chargement du modèle en ligne — mesuré à ~ 42 s sur un système de fichiers froid, 3 s de moins qu'un délai d'attente de 90 s pour client (#1576) — merci paoloantinori !
  • Les voix que vous avez clonées restent « chaudes » lors des redémarrages — les références codées persistent désormais sur le disque (~ 10 Ko chacune), de sorte que la première génération d'une session ignore le réencodage et toute passe de transcription ; OMNIVOICE_PROMPT_DISK_CACHE=0 se désinscrit (#1565)
  • Accélération FlashInfer en option pour le moteur par défaut sur CUDA (OMNIVOICE_FLASHINFER=1, ~2,2x mesuré) — nécessite le package flashinfer-python en option ; le paquet manquant ou l'échec du noyau enregistre la raison et revient au chemin standard (#1565)
  • Le rapporteur de bogues remarque lorsque vous utilisez une version obsolète et propose la dernière version avant de la déposer - avec une trappe d'évacuation "Fichier quand même" - et tamponne une ligne Build status dans chaque rapport afin que les rapports à jour puissent être distingués des rapports obsolètes (#1547).
  • Paramètres → Performances et appareil obtiennent un remplacement du périphérique de calcul (Auto / CUDA / ROCm / XPU / MPS / CPU ou OMNIVOICE_DEVICE) — épinglez l'appareil lorsque la détection automatique sélectionne des erreurs ; seuls les appareils dont dispose réellement votre machine sont proposés (#1557)
  • Points de contrôle PocketTTS 24 couches activés via OMNIVOICE_POCKETTTS_24L — meilleure prosodie pour it/de/es/pt à environ 2x temps de rendu (toujours plus rapide que le temps réel) ; le modèle rapide à 6 couches reste le modèle par défaut (#1613) — merci paoloantinori !

Documents

  • La version prise en charge et les instructions d'installation identifient désormais 0.5.1 comme version stable de bureau et de conteneur (#1687)
  • L'aperçu du Docker Hub affiche désormais la démo actuelle de commutation de moteur, le catalogue de modèles et le flux de travail vocal de la galerie (#1593)
  • La présentation et le guide d'installation du hub Docker affichent désormais les balises v0.5 et le modèle de sécurité API-key/share-PIN intégré au lieu du v0.4 obsolète et des conseils de non-authentification (#1592).
  • Les README sont désormais en tête avec des boutons de téléchargement et une procédure pas à pas en trois étapes pour le premier clone, ainsi qu'une nouvelle page de références ancrant les numéros mesurés par moteur/par appareil sur le harnais in-repo (#1555)
  • Chaque moteur a désormais son propre guide — 21 nouvelles pages sous docs/engines plus un index couvrant les 16 moteurs TTS et 11 ASR, liés depuis les deux README (#1556)
  • Le guide OmniVoice couvre désormais la combinaison d'attributs de style avec une référence clip (une instruction cohérente stabilise le clonage ; la référence gagne les conflits), le contrôle de prononciation en ligne (phonèmes pinyin/CMU) et corrige l'affirmation selon laquelle le moteur par défaut ne peut pas faire de conception vocale — il le peut, à partir des attributs (#1565).

Corrigé

  • Les espaces de travail mesurent désormais leur largeur réactive lorsque le shell post-bootstrap est réellement monté, de sorte que la mise à l'échelle native de l'interface utilisateur redistribue les projets et l'historique au lieu d'écraser la démo de doublage en colonnes illisibles (#1683).

  • Le doublage garde le sélecteur de langue source visible après le choix d'un fichier local, afin que l'ASR puisse être épinglé avant le début de la transcription (#1678) — merci Lonki-lomki-cloud !

  • Les téléchargements du moteur multimédia de première exécution sont immédiatement disponibles pour TTS sans redémarrage, et les échecs de processus multimédia manquants indiquent désormais des contrôles de réparation (#1677) — merci farhataligpt-dev !

  • Les installations sources sur les GPU AMD honorent OMNIVOICE_TORCH_VARIANT=rocm : bun run desktop échange désormais la molette de torche ROCm après uv sync et lance le backend sans resynchronisation, au lieu de revenir silencieusement à la version CUDA CPU uniquement à chaque démarrage (#1665) — merci uberclokr !

  • bun run desktop sur un nouveau clone n'échoue plus avec "le chemin de ressource ../../frontend/dist n'existe pas" — le lanceur de développement crée le répertoire de ressources Tauri réservé avant la compilation (#1664) — merci uberclokr !

  • macOS ne perd plus TTS après la première requête lorsque Python manque de os.waitid ; la propriété des sous-processus utilise désormais une solution de repli sécurisée waitpid sans risquer de réutiliser les groupes de processus (#1656) — merci paoloantinori !

  • Le démarrage du bureau, les nouvelles tentatives, la réinitialisation, la désinstallation, l'arrêt et la récupération après incident partagent désormais un seul propriétaire du cycle de vie du backend ; quitter interrompt les installateurs de première exécution et draine gracieusement puis nettoie de force l'arborescence complète des processus backend, afin que les chevauchements ne puissent pas la dupliquer ou la rendre orpheline (# 1635) — merci Xohaibxobi !

  • Les projets de grandes histoires et de livres audio persistent désormais dans IndexedDB au lieu de déborder de l'enveloppe localStorage omnivoice.app, avec une migration sans quota et un vidage ordonné de sortie/rechargement (#1636) — merci leodzai !

  • OmniVoice et son sous-processus isolé en cas de crash sont désormais acheminés vers les GPU AMD ROCm au lieu d'avertir et de revenir au CPU (#1629) — merci j4r3kb !

  • La dictée annule désormais le travail de démarrage en attente, les ressources de capture, les sockets et les minuteries lorsque le widget de capture se ferme, empêchant ainsi un travail tardif sur une vue Web détruite (#1645)

  • Les échecs de génération de streaming affichent désormais des conseils de récupération reconnus et apparaissent dans les diagnostics au lieu de renvoyer uniquement une erreur générique (#1607).

  • Le test de transport de capacité de travail ne gère plus sa propre configuration : la limite de 1 emplacement passe désormais par la négociation d'inscription au lieu de muter la configuration client après la connexion, où la ConfigUpdate ouverte au flux du serveur (portant la capacité enregistrée de 2) pourrait l'écraser et simuler une acceptation excessive ; échec de l'IC à deux reprises le 2026-08-21 (#1630)

  • Déplacer des mots à travers la limite d'un locuteur lors d'une doublage (fusionner deux lignes et les diviser à nouveau) ne double plus la seconde moitié dans la voix du premier locuteur ; chaque moitié conserve désormais le locuteur, la voix, la direction, le gain et la langue de celui qui le dit réellement (#1612) — merci invio-a11y !

  • Dictée sur un WebView qui refuse un contexte audio de 16 kHz (WKWebView) passe désormais bas avant le sous-échantillonnage, de sorte que les fréquences supérieures à 8 kHz cessent de s'incorporer dans la parole à laquelle le module de reconnaissance est alimenté (#1610)

  • Un contexte microphone qui ne peut pas être repris signale désormais une erreur micro au lieu de laisser la pilule dictée sur "Écoute" sans rien capturer (#1610)

  • La dictée ne conserve plus l'audio d'une session entière pour une récupération en mode silencieux : un micro ouvert a augmenté cette mémoire tampon d'environ 115 Mo par heure ; les deux dernières minutes sont conservées à la place (#1610)

  • Le statut de livraison du clipboard est désormais traduit dans les 21 langues, donc les utilisateurs de Wayland — où la livraison du clipboard est la valeur par défaut — ne voient plus de chaîne en anglais (#1610)

  • Un échec de chargement sherpa-onnx natif de tout type d'exception se dégrade désormais en "moteur indisponible" au lieu de supprimer la dictée WebSocket (#1610)

  • Dictation est désormais livré avec Whisper Tiny comme son unique multiplateforme par défaut, évitant le décodage vide mesuré de Parakeet sous Windows tout en gardant Parakeet sélectionnable derrière le repli d'exécution (#1175)

  • Le remixage d'un doublage ne décode, ne réécrit et ne relit plus chaque segment mis en cache — l'audio mis en cache au même débit est réutilisé directement (et rejeté s'il est tronqué), le changement de mode de synchronisation ne peut pas réutiliser l'audio tronqué par slot comme débit naturel, et RVC respecte les modes de débit naturel (#1594)

  • PocketTTS French fonctionne à nouveau — pocket-tts ne livre qu'un modèle français à 24 couches et a rejeté le nom demandé par le side-car, donc chaque demande française a échoué au chargement du modèle ; Le français charge désormais toujours french_24l (#1613) — merci paoloantinori !

  • L'installation d'IndexTTS 2.5 n'échoue plus en réclamant un téléchargement interrompu — les dépôts de pondérations config.yaml et VoiceStudio exigeaient un config_v2_5.yaml qui n'existe dans aucune version en amont ; les deux noms sont acceptés, donc une caisse renommée manuellement continue de fonctionner (#1611) — merci zuiaiyutu !

  • IndexTTS 2.5 n'a plus de génération de texte long tuée à 60 secondes — le side-car prouve désormais qu'il est vivant toutes les 5 secondes pendant que infer() s'exécute, et son délai s'élève à 900 s (OMNIVOICE_INDEXTTS_RECV_TIMEOUT_S) (#1611) — merci zuiaiyutu !

  • La route /v1/audio/speech compatible OpenAI réutilise désormais le moteur mis en cache partagé pour les identifiants model explicites au lieu de construire un nouveau moteur — et sa charge side-car/modèle, un plancher d'environ 28 s par appel pour les moteurs de sous-processus — à chaque requête, avec la même discipline résidente sur un seul moteur que /generate s'applique (#1614) — merci paoloantinori !

  • La vérification de la RAM de l'assistant d'installation ne bloque plus les machines de 8 Go dont le système d'exploitation indique ~7.8 Go utilisables — les seuils tolèrent désormais la mémoire réservée, et OMNIVOICE_RAM_PREFLIGHT=0 transforme un véritable blocage en avertissement pour ceux qui acceptent le risque MOO (#1618)

  • Le filigrane invisible s'exécute désormais avec impatience au lieu de passer par torch.compile — La compilation paresseuse d'AudioSeal a envoyé la première intégration de chaque session dans le codegen C++ d'Inductor, qui a complètement échoué sur les hôtes macOS dont la chaîne d'outils ne pouvait pas le servir et a expédié l'audio non marqué après une attente de 30 à 40 secondes ; la première intégration passe de 9,70 s à 0,26 s (# 1615) — merci paoloantinori !

  • Le bloqueur d'accessibilité macOS revérifie désormais lorsqu'il est visible et se ferme dès que l'autorisation est activée au lieu de conserver une invite d'autorisation obsolète à l'écran (#1609)

  • Les colonnes vidéo et transcription de l'éditeur de doublage peuvent désormais être redimensionnées par le pointeur ou le clavier, et la répartition choisie persiste d'un lancement à l'autre (#1571) — merci invio-a11y !

  • La synthèse CPU uniquement bénéficie désormais d'un budget d'exécution limité à dix minutes, et un rendu qui l'épuise est signalé comme un délai d'attente de calcul au lieu d'une pression de file d'attente trompeuse « la capacité de génération est occupée » (#1588) — merci ChienNguyen1111 !

  • Rapid Launchpad ↔ La navigation Dub remplace désormais proprement le propriétaire du DOM de l'espace de travail, donc un nettoyage tardif des médias/formes d'onde ne peut pas déclencher le crash du insertBefore de React (#1590) — merci nicolas-jacques !

  • Les échecs d'intégration de filigrane enregistrent désormais le traçage complet au lieu du simple message d'exception, de sorte qu'un incident audio silencieusement non marqué (l'audio passe sans être marqué par conception) peut être diagnostiqué à partir du seul journal (#1576) — merci paoloantinori !

  • Le doublage récupère désormais les échanges à deux haut-parleurs rapid lorsque la diarisation les réduit, définit par défaut la synchronisation labiale des nouveaux projets sans écraser les choix de timing enregistrés et maintient l'éditeur utilisable sur des écrans étroits (#1584) — merci victordonat0 !

  • OMNIVOICE_ASR_BACKEND=omnivoice sélectionne désormais le chemin Whisper natif de PyTorch, de sorte que la trappe d'évacuation ROCm documentée n'échoue plus en tant que moteur inconnu (#1582) — merci Patmansk !

  • Le partage réseau à partir des installations Windows MSI/portables sert désormais l'interface Web fournie aux périphériques LAN au lieu de les rediriger vers leur propre localhost (#1589) — merci TWIISTED-STUDIOS !

  • Les vidéos doublées exportées marquent désormais la langue doublée comme flux audio par défaut tout en gardant l'original disponible comme choix explicite (#1575) — merci invio-a11y !

  • Les références de clonage ne peuvent plus épuiser la mémoire du système : les clips sans transcription jusqu'à 75 secondes sont recherchés dans cinq passages délimités, les clips plus longs demandent à être coupés et les transcriptions fournies restent limitées à 20 secondes pour préserver l'alignement (#1578) — merci ACKAPOB !

  • Les sous-chemins d'artefacts stockés sont désormais résolus après le déplacement d'un répertoire de données entre Windows, macOS, Linux et Docker, tandis que les échappements de traversée et de lien symbolique restent bloqués (#1559) — merci Eman-Yousaf !

  • Un navigateur distant frappant l'administrateur 403 d'un serveur configuré avec une clé API obtient désormais le formulaire de connexion par clé API au lieu de consoles 403 sans fin, tandis que les serveurs de bureau et avec code PIN uniquement/sans clé conservent l'erreur de bouclage simple afin que les invités ne se voient jamais proposer une connexion qu'aucune clé ne peut satisfaire (#1568) — merci paoloantinori !

  • Le side-car ASR isolé en cas de crash et son contrôle en amont de téléchargement s'accordent désormais sur le modèle à charger — la définition de la variable de modèle partagée à chuchotement plus rapide s'applique aux deux variantes au lieu que le side-car en utilise silencieusement un autre (#1556)

  • "Prêt" nécessite désormais la sonde de santé approfondie (une route fonctionnelle basée sur une base de données), pas seulement la sonde d'identité - un backend dont l'installation a échoué ne peut plus être annoncé alors que chaque requête réelle échoue (#1548)

  • Le superviseur redémarre après des crashs répétés et recule désormais (immédiat, puis 5 s, puis 15 s) au lieu de réapparaître consécutivement, donc une boucle de crash serrée ne peut pas brûler tout le budget de redémarrage en quelques secondes (#1548)

  • Le test de régression du nettoyage du bureau Linux isole désormais les artefacts de build, de sorte qu'une build de développeur existante ne peut plus modifier son résultat (#1566)

  • Renommer, supprimer ou révoquer le consentement d'une voix (et activer/effacer l'historique, enregistrer les exportations) met désormais à jour à nouveau en direct chaque onglet ouvert — les événements WebSocket des routes de synchronisation ont été supprimés silencieusement, ce qui pourrait ressembler à "toutes mes voix ont disparu" (#1561) — merci paoloantinori !

VoiceStudio v0.5.1

Highlights

  • VoiceStudio becomes a local speech platform — #1646 is the architectural headline: a bundled Rust loopback sidecar (dictation start/stop/toggle, focused-output sessions, discovery, JSON-RPC) plus versioned HTTP, WebSocket, JSON-RPC, CLI, and MCP transports. This changes the integration model from "drive the desktop UI" to "call a local speech service" from coding agents, editors, TUIs, and other apps. Watch the transport versioning — pin a version in clients, since these endpoints are now a contract rather than an internal detail.

  • Startup and health-check semantics changed — the backend binds its port immediately and, while PyTorch, API routes, and DB migrations load in the background, /health answers 503-with-step and a new /startup/progress endpoint lists every step (#1550, #1548). Orchestration or readiness code that treated any non-200 as "dead" will now flap during boot; poll /startup/progress and treat 503-with-step as "starting," not "failed." Crash-loop restarts are also paced now, so repeated failures surface diagnostics instead of spinning.

  • Throughput and first-generation latency get real tuning knobs — default-engine dubbing batches several segments per forward pass, width sized to device headroom (1 on CPU/low-VRAM up to 8) with OMNIVOICE_DUB_BATCH_WIDTH to override, and same-rate cached audio is reused instead of re-decoding (#1594). CUDA users can opt into FlashInfer at ~2.2x via OMNIVOICE_FLASHINFER=1 (needs flashinfer-python, falls back gracefully); cloned-voice references persist to disk (~10 KB each) via OMNIVOICE_PROMPT_DISK_CACHE (#1565); and the AudioSeal watermark model warms on a background thread ~35s after boot, with OMNIVOICE_PRELOAD_WATERMARK=0 to opt out (#1576). Net: much faster warm starts, but account for the disk cache and background model load in resource budgets; CI now pins operation budgets so these fast paths are enforced (#1594).

  • Crash isolation hardens unattended/Windows runs — OmniVoice on Apple Silicon now runs in a crash-isolated child so fatal MPS memory exits don't take down the backend (#1697, #1698), and source-mode can restart the backend without tearing down the UI (#1690). A timed-out dub transcription no longer launches a second WhisperX/CTranslate2 call over the abandoned native worker — the overlap that preceded Windows 0xC0000005 exits (#1669) — and debugger code 0x40010004 is no longer miscounted as a backend crash (#1663). If you ship long-running or Windows generation, these remove entire classes of hard crashes and false restart accounting.

  • Heterogeneous GPU and headless deployment is now viable — with caveats — a compute-device override (Auto/CUDA/ROCm/XPU/MPS/CPU, or OMNIVOICE_DEVICE) lets you pin bad auto-detection (#1557), WSL2 AMD containers use the /dev/dxg ROCDXG bridge with actionable diagnostics instead of silently falling back to CPU (#1655), and source installs honour OMNIVOICE_TORCH_VARIANT=rocm (#1665). Headless NVIDIA/ROCm boxes can join as worker-only Compose services via protocol-v2 enrollment — but upgrade both machines together before reconnecting (#1638), and Docker quick starts now require the admin key or protected actions return 403 behind NAT (#1651). Read the enrollment and key requirements before rolling out.

  • Dubbing post-edit stops corrupting speaker identity — dubbing now separates spoken from target language, preserves translations through segment cleanup, and lets failed translations be retried or skipped without restarting the batch (#1654); SRT import binds each cue to its best-overlapping source speaker/clone instead of resetting lines to a random default voice (#1660); and per-line retiming, insertion, and two-way merge (#1612) keep each half's original voice, gain, and language when words move across a speaker boundary. For anyone doing subtitle/dub post-production, this eliminates the "second half dubbed in the wrong voice" class of bugs.

No breaking changes are called out in this release.

Highlights

  • OmniVoice generation on Apple Silicon now runs in a crash-isolated child, so fatal MPS memory exits no longer take down the local backend (#1697, #1698) — thanks ndntran14!
  • Model-load GPU exhaustion now returns a sanitized, actionable dubbing error, and readiness correctly attributes the shared model status to TTS (#1695)
  • Source-mode development now restarts an isolated backend crash without tearing down the UI, while repeated crash loops still stop loudly with diagnostics (#1690)
  • Dubbing playback now keeps an audible companion source when a WebView can render the preview picture but cannot decode its audio (#1692)
  • Model Catalogue engine rows now use the available desktop width and keep identity, runtime state, and actions from crowding one another (#1689)
  • VoiceStudio now acts as a local speech platform: other apps can trigger its native dictation or connect through versioned HTTP, WebSocket, JSON-RPC, CLI, and MCP transports (#1646)
  • A timed-out in-process dub transcription no longer starts a second WhisperX/CTranslate2 call over the abandoned native worker, preventing the overlapping access that preceded Windows 0xC0000005 exits (#1669)
  • Windows debugger termination code 0x40010004 is no longer misreported as a backend crash or charged against automatic restart recovery (#1663)
  • Studio now keeps one generation reservation across page changes, preventing a remount from stacking native jobs until the backend reports capacity busy or is killed under memory pressure (#1670)
  • Uploaded dubbing videos are normalized to browser-safe H.264/AAC before preview, preventing valid VP9, AV1, or Opus media from failing with “no supported sources” (#1644)
  • Dubbing now separates spoken and target languages, preserves translations through segment cleanup, and lets failed translations be retried or skipped without restarting the batch (#1654) — thanks Number16BusShelter!
  • Importing replacement SRT subtitles now keeps each cue bound to the best-overlapping source speaker and clone instead of resetting every line to a random default voice (#1660) — thanks invio-a11y!
  • Uploading a Dub preview no longer blocks every backend request while ffmpeg extracts its audio (#1667) — thanks tfreyd!
  • Docker quick starts now require the administrator key needed through container NAT instead of starting a UI whose protected actions return 403 (#1651) — thanks wd357dui!
  • WSL2 AMD containers now use the /dev/dxg ROCDXG bridge with actionable GPU diagnostics instead of silently falling back to CPU (#1655) — thanks wd357dui!
  • Ad-hoc voice-clone references now stay alive until cancelled or timed-out GPU work actually stops reading them, so prompt caching can finish instead of failing on a deleted temp file (#1668) — thanks tfreyd!
  • Dictation now stays bound to the app where it started and recovers locally from silent recognizer output (#1175)
  • The backend now answers within a second of launch and narrates its startup step by step (#1550)
  • Reporting a bug from an outdated build now offers the latest release first (#1547)
  • The backend is only announced ready once it can actually serve, and crash-loop restarts now pace themselves (#1548)
  • Invisible watermarking no longer stalls — or silently skips — the first take of a session (#1615)
  • Dub subtitles can be retimed, inserted, and merged in either direction from the segment table (#1612) — thanks invio-a11y!

Changed

  • Model Catalogue now uses one breathable workspace canvas with simpler pane and engine-family navigation instead of nested cards and scroll regions (#1685)
  • Linux source launchers now catch missing libxdo and GStreamer audio plugins before they can cause a linker error or an aborted, blank WebKit renderer (#1680, #1682)
  • Dictation now carries one native output session from shortcut-down through final delivery, restores text, HTML, image, or file-list clipboards only when untouched, keeps Wayland copy-safe unless current-focus insertion is explicitly enabled, and retries silent Sherpa speech only through an already-installed local ASR model (#1175)
  • The backend binds its port immediately and reports startup progress live — /health answers 503-with-step and a new /startup/progress endpoint lists every step while PyTorch, API routes, and database migrations load in the background, so "starting at step X" is never mistakable for "dead"; the desktop splash narrates each step (#1550)

Added

  • A bundled Rust loopback sidecar exposes dictation start/stop/toggle, focused-output sessions, discovery, and JSON-RPC; the backend adds versioned streaming events and a dependency-free CLI bridge for Herdr, coding agents, editors, desktop apps, and TUIs (#1646)
  • Headless NVIDIA and ROCm machines can now join as worker-only Docker Compose services with no published UI and durable protocol-v2 enrollment; update both machines together before reconnecting (#1638) — thanks jkrogers9862!
  • Linux ARM64 (Asahi Apple Silicon) support for the OmniVoice GGUF engine — a linux-aarch64 binary built with GGML Vulkan where the toolchain allows it, so Apple GPUs accelerate generation through the open-source Honeykrisp driver instead of falling back to CPU-only (#1641)
  • One-command install on every desktop OS: curl -fsSL https://voicestudio.sh/install | sh (macOS/Linux/WSL) or irm https://voicestudio.sh/install | iex (Windows) — the URL serves the right script per platform, and Windows gains a source installer (scripts/install.ps1) with a 3-OS CI smoke (#1626)
  • Per-line subtitle management in the dub table: a line's end time is editable alongside its start (typing a time and dragging its timeline edge now take the same path), lines merge with the previous row as well as the next (Ctrl/Cmd+Shift+M), and a new line can be inserted into the gap after any row (#1612) — thanks invio-a11y!
  • CI now enforces performance regression budgets on the hot paths — operation-count tests pin streaming TTS to one synthesis per sentence and cached dub re-mixes to zero re-synthesis; fast-path guards cover zero re-decoding and ⌈N/W⌉ native batch calls when enabled (#1594)
  • Default-engine dubbing now synthesizes several segments per forward pass instead of one call per line — the width follows the host's device headroom (1 on CPU and low-VRAM cards, up to 8), OMNIVOICE_DUB_BATCH_WIDTH overrides it, and engines without native batching keep the single-segment path (#1594)
  • /ws/tts now reports real time-to-first-audio, and its RTF measures synthesis alone so a slow client can't inflate it (#1594)
  • The locally cached AudioSeal watermark generator warms on a background thread ~35s after boot (OMNIVOICE_PRELOAD_WATERMARK=0 opts out; explicitly setting =1 may download it), so the first synthesis no longer serializes the audioseal import + model load inline — measured at ~42s on a cold filesystem, 3s short of a 90s client timeout (#1576) — thanks paoloantinori!
  • Voices you've cloned stay "warm" across restarts — encoded references now persist to disk (~10 KB each), so the first generation of a session skips the re-encode and any transcription pass; OMNIVOICE_PROMPT_DISK_CACHE=0 opts out (#1565)
  • Optional FlashInfer acceleration for the default engine on CUDA (OMNIVOICE_FLASHINFER=1, ~2.2x measured) — needs the optional flashinfer-python package; missing package or kernel failure logs why and falls back to the standard path (#1565)
  • The bug reporter notices when you're on an outdated build and offers the latest release before filing — with a "File anyway" escape hatch — and stamps a Build status line into every report so up-to-date reports are tellable from stale ones (#1547)
  • Settings → Performance & Device gains a compute-device override (Auto / CUDA / ROCm / XPU / MPS / CPU, or OMNIVOICE_DEVICE) — pin the device when auto-detect picks wrong; only devices your machine actually has are offered (#1557)
  • Opt-in 24-layer PocketTTS checkpoints via OMNIVOICE_POCKETTTS_24L — better prosody for it/de/es/pt at roughly 2x render time (still faster than real-time); the fast 6-layer model stays the default (#1613) — thanks paoloantinori!

Docs

  • Supported-version and install guidance now identifies 0.5.1 as the stable desktop and container release (#1687)
  • The Docker Hub overview now shows the current engine-switching demo, Model Catalogue, and gallery voice workflow (#1593)
  • The Docker Hub overview and install guide now show the v0.5 tags and the built-in API-key/share-PIN security model instead of obsolete v0.4 and no-authentication guidance (#1592)
  • The READMEs now lead with download buttons and a three-step first-clone walkthrough, and a new benchmarks page anchors measured per-engine/per-device numbers on the in-repo harness (#1555)
  • Every engine now has its own guide — 21 new pages under docs/engines plus an index covering all 16 TTS and 11 ASR engines, linked from both READMEs (#1556)
  • The OmniVoice guide now covers combining style attributes with a reference clip (consistent instruct stabilizes cloning; the reference wins conflicts), inline pronunciation control (pinyin / CMU phonemes), and corrects the claim that the default engine can't do voice design — it can, from attributes (#1565)

Fixed

  • Workspaces now measure their responsive width when the post-bootstrap shell actually mounts, so native UI scaling reflows Projects and History instead of crushing the Dubbing demo into unreadable columns (#1683)

  • Dubbing keeps the source-language selector visible after a local file is chosen, so ASR can be pinned before transcription starts (#1678) — thanks Lonki-lomki-cloud!

  • First-run media-engine downloads become available to TTS immediately without a restart, and missing media-process failures now point to repair controls (#1677) — thanks farhataligpt-dev!

  • Source installs on AMD GPUs honour OMNIVOICE_TORCH_VARIANT=rocm: bun run desktop now swaps in the ROCm torch wheel after uv sync and launches the backend without re-syncing, instead of silently reverting to the CPU-only CUDA build on every start (#1665) — thanks uberclokr!

  • bun run desktop on a fresh clone no longer fails with "resource path ../../frontend/dist doesn't exist" — the dev launcher creates the placeholder Tauri resource directory before compiling (#1664) — thanks uberclokr!

  • macOS no longer loses TTS after the first request when Python lacks os.waitid; subprocess ownership now uses a safe waitpid fallback without risking reused process groups (#1656) — thanks paoloantinori!

  • Desktop startup, Retry, reset, uninstall, shutdown, and crash recovery now share one backend lifecycle owner; quitting interrupts first-run installers and gracefully drains then force-cleans the full backend process tree, so overlaps cannot duplicate or orphan it (#1635) — thanks Xohaibxobi!

  • Large Stories and Audiobook projects now persist in IndexedDB instead of overflowing the omnivoice.app localStorage envelope, with quota-safe migration and orderly exit/reload flushing (#1636) — thanks leodzai!

  • OmniVoice and its crash-isolated subprocess now route to AMD ROCm GPUs instead of warning and falling back to CPU (#1629) — thanks j4r3kb!

  • Dictation now cancels pending startup work, capture resources, sockets, and timers when the capture widget closes, preventing late work against a destroyed webview (#1645)

  • Streaming generation failures now show recognized recovery guidance and appear in Diagnostics instead of only returning a generic error (#1607)

  • The worker-capacity transport test no longer races its own setup: the 1-slot limit now goes through the enrollment handshake instead of mutating client config after connect, where the server's stream-open ConfigUpdate (carrying the registered capacity of 2) could overwrite it and fake an over-accept; failed CI twice on 2026-08-21 (#1630)

  • Moving words across a speaker boundary in a dub — merging two lines and splitting them again — no longer dubs the second half in the first speaker's voice; each half now keeps the speaker, voice, direction, gain, and language of whoever actually says it (#1612) — thanks invio-a11y!

  • Dictation on a WebView that refuses a 16 kHz audio context (WKWebView) now low-passes before downsampling, so frequencies above 8 kHz stop folding into the speech the recognizer is fed (#1610)

  • A microphone context that cannot be resumed now reports a mic error instead of leaving the dictation pill on "Listening" while capturing nothing (#1610)

  • Dictation no longer retains a whole session's audio for silent-model recovery — an open mic grew that buffer by ~115 MB an hour; the recent two minutes are kept instead (#1610)

  • The clipboard-delivery status is now translated in all 21 languages, so Wayland users — where clipboard delivery is the default — no longer see an English string (#1610)

  • A native sherpa-onnx load failure of any exception type now degrades to "engine unavailable" instead of taking the dictation WebSocket down (#1610)

  • Dictation now ships Whisper Tiny as its one cross-platform default, avoiding Parakeet's measured empty decoding on Windows while keeping Parakeet selectable behind runtime fallback (#1175)

  • Re-mixing a dub no longer decodes, rewrites, and re-reads every cached segment — same-rate cached audio is reused directly (and rejected if truncated), switching timing modes can't reuse slot-truncated audio as natural-rate, and RVC respects natural-rate modes (#1594)

  • PocketTTS French works again — pocket-tts only ships a 24-layer French model and rejected the name the sidecar asked for, so every French request failed at model load; French now always loads french_24l (#1613) — thanks paoloantinori!

  • Installing IndexTTS 2.5 no longer fails claiming an interrupted download — the weights repo ships config.yaml and VoiceStudio demanded a config_v2_5.yaml that exists in no upstream release; both names are accepted, so a hand-renamed checkout keeps working (#1611) — thanks zuiaiyutu!

  • IndexTTS 2.5 no longer has long-text generation killed at 60 seconds — the sidecar now proves it is alive every 5 seconds while infer() runs, and its deadline rises to 900s (OMNIVOICE_INDEXTTS_RECV_TIMEOUT_S) (#1611) — thanks zuiaiyutu!

  • The OpenAI-compatible /v1/audio/speech route now reuses the shared cached engine for explicit model ids instead of constructing a fresh engine — and its sidecar/model load, a ~28s floor per call for subprocess engines — on every request, with the same single-engine-resident discipline /generate applies (#1614) — thanks paoloantinori!

  • The setup wizard's RAM check no longer blocks 8 GB machines whose OS reports ~7.8 GB usable — the thresholds now tolerate reserved memory, and OMNIVOICE_RAM_PREFLIGHT=0 turns a genuine block into a warning for those who accept the OOM risk (#1618)

  • Invisible watermarking now runs eagerly instead of through torch.compile — AudioSeal's lazy compile sent the first embed of every session into Inductor's C++ codegen, which failed outright on macOS hosts whose toolchain couldn't serve it and shipped the audio unmarked after a 30-40s wait; first embed drops from 9.70s to 0.26s (#1615) — thanks paoloantinori!

  • The macOS Accessibility blocker now rechecks while visible and closes as soon as the grant is enabled instead of keeping a stale permission prompt on screen (#1609)

  • The dubbing editor's video and transcript columns can now be resized by pointer or keyboard, and the chosen split persists across launches (#1571) — thanks invio-a11y!

  • CPU-only synthesis now gets a bounded ten-minute execution budget, and a render that exhausts it is reported as a compute timeout instead of misleading "generation capacity is busy" queue pressure (#1588) — thanks ChienNguyen1111!

  • Rapid Launchpad ↔ Dub navigation now replaces the workspace DOM owner cleanly, so late media/waveform cleanup cannot trigger React's insertBefore crash (#1590) — thanks nicolas-jacques!

  • Watermark embedding failures now log the full traceback instead of just the exception message, so a silently-unmarked-audio incident (audio passes through unmarked by design) is diagnosable from the log alone (#1576) — thanks paoloantinori!

  • Dubbing now recovers rapid two-speaker exchanges when diarization collapses them, defaults new projects to lip sync without overwriting saved timing choices, and keeps the editor usable on narrow screens (#1584) — thanks victordonat0!

  • OMNIVOICE_ASR_BACKEND=omnivoice now selects the PyTorch-native Whisper path, so the documented ROCm escape hatch no longer fails as an unknown engine (#1582) — thanks patmansk!

  • Network Sharing from Windows MSI/portable installs now serves the bundled web interface to LAN devices instead of redirecting them to their own localhost (#1589) — thanks TWIISTED-STUDIOS!

  • Exported dubbed videos now mark the dubbed language as the default audio stream while keeping Original available as an explicit choice (#1575) — thanks invio-a11y!

  • Cloning references can no longer exhaust system memory: transcript-free clips up to 75 seconds are searched in five bounded passages, longer clips ask to be trimmed, and supplied transcripts remain capped at 20 seconds to preserve alignment (#1578) — thanks ACKAPOB!

  • Stored artifact subpaths now resolve after moving a data directory between Windows, macOS, Linux, and Docker, while traversal and symlink escapes remain blocked (#1559) — thanks Eman-Yousaf!

  • A remote browser hitting an API-key-configured server's admin 403 now gets the API-key login form instead of endless console 403s, while desktop and PIN-only/no-key servers keep the plain loopback error so guests are never offered a login no key can satisfy (#1568) — thanks paoloantinori!

  • The crash-isolated ASR sidecar and its download preflight now agree on which model to load — setting the shared faster-whisper model variable applies to both variants instead of the sidecar quietly using a different one (#1556)

  • "Ready" now requires the deep health probe (a working database-backed route), not just the identity probe — a backend whose install broke underneath can no longer be announced up while every real request fails (#1548)

  • Supervisor restarts after repeat crashes now back off (immediate, then 5s, then 15s) instead of respawning back-to-back, so a tight crash loop can't burn the whole restart budget in seconds (#1548)

  • The Linux desktop cleanup regression test now isolates build artifacts, so an existing developer build can no longer change its result (#1566)

  • Renaming, deleting, or revoking consent on a voice (and starring/clearing history, recording exports) now live-updates every open tab again — the sync routes' WebSocket events were silently dropped, which could look like "all my voices are gone" (#1561) — thanks paoloantinori!

CI

  • Project agents now share pinned Vite and FastAPI skills from skills.sh (#1594)
  • Weekly full-history secret scans no longer mistake the Ed25519 private-key type name for committed key material (#1591)
