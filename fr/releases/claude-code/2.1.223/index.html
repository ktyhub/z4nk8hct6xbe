code-claude v2.1.223

Qu'est-ce qui a changé

  • Ajout d'entrées génériques de propriétaire ("owner/*") aux paramètres gérés strictKnownMarketplaces et blockedMarketplaces pour autoriser ou bloquer tous les dépôts du marché sous une organisation GitHub
  • Ajout d'un avertissement lorsque les agents de workflow, les compétences dérivées, les commandes slash ou la reprise du modèle de sous-agent demandé par les agents en arrière-plan sont restreints et que le modèle parent s'exécute à la place.
  • Ajout d'un indice /teleport dans les sessions cloud montrant comment continuer localement avec claude --teleport <session id>
  • Correction d'un contournement d'autorisation Bash où une commande spécialement conçue pouvait masquer des parties d'elle-même lors des contrôles d'autorisation
  • Correction des invites d'autorisation afin que les commandes complétées par des onglets ou un Unicode invisible ne puissent plus masquer une partie de la commande dans la boîte de dialogue d'approbation
  • Correction des scripts de workflow pouvant utiliser import() dynamique pour exécuter du code en dehors du bac à sable du workflow
  • Correction d'un écart d'autorisation où le mode bypassPermissions d'une définition d'agent ignorait la politique de désactivation des autorisations de contournement de l'organisation.
  • Correction de la reprise d'une session après un /cd en mi-session revenant vide
  • Correction de la découverte de modèles de passerelle masquant les modèles Claude enregistrés sous des identifiants préfixés par le fournisseur tels que vertex_ai/claude-* ou bedrock/anthropic.claude-*
  • Correction des clés modelOverrides qui ne sont pas des ID de modèle anthropique étant traitées comme l'ID de modèle canonique de la session ; les clés inconnues sont désormais ignorées comme documenté
  • Paramètres gérés fixes : les paramètres fournis par le serveur ne désactivent plus le bloc env d'un profil managed-settings.json ou MDM local sur la machine ; admin env fusionne désormais par clé
  • Correction des commandes en bac à sable qui ne démarrent pas sous Linux lorsque sandbox.filesystem.denyWrite couvre le répertoire de travail
  • Correction des agents d'arrière-plan du fork qui restaient bloqués "en train de reprendre" pour le reste de la session lors de l'échec de la reconstruction de l'invite parent du fork lors de la reprise.
  • Correction d'une reprise de session échouant à chaque tour ou laissant l'application interactive sur un écran d'erreur qui ne répondait pas, lorsque son historique contenait une pièce jointe de diagnostic mal formée.
  • Correction d'un blocage rare lors de l'analyse d'une sortie inhabituelle de git push
  • Modification de CLAUDE_CODE_DISABLE_1M_CONTEXT pour contenir chaque modèle Claude avec une fenêtre native de 1 M à 200 000 via le compactage automatique, et pas seulement une liste fixe ; un avertissement de démarrage apparaît désormais lorsque le compactage automatique ne maintient pas la session à 200 Ko
  • Modification du compactage automatique pour conserver les sessions sur des ID de modèle non reconnus dans la fenêtre contextuelle supposée au lieu de les laisser dépasser cette limite ; définissez CLAUDE_CODE_DISABLE_UNKNOWN_MODEL_WINDOW_ENFORCEMENT=1 pour restaurer le comportement précédent
  • Modification de /review pour qu'il soit un alias de /code-review, qui examine le diff actuel ou un PR (/code-review <level> <pr#>) ; utilisez /code-review ultra pour un examen approfondi du cloud
  • Modification de /code-review sans niveau d'effort pour réutiliser le niveau que vous avez tapé en dernier ; tapez un niveau comme /code-review high pour le changer

claude-code v2.1.223

What's changed

  • Added owner wildcard entries ("owner/*") to the strictKnownMarketplaces and blockedMarketplaces managed settings for allowing or blocking all marketplace repos under a GitHub org
  • Added a warning when workflow agents, forked skills, slash commands, or resumed background agents' requested subagent model is restricted and the parent model runs instead
  • Added a /teleport hint in cloud sessions showing how to continue locally with claude --teleport <session id>
  • Fixed a Bash permission bypass where a crafted command could hide parts of itself from permission checks
  • Fixed permission prompts so commands padded with tabs or invisible Unicode can no longer hide part of the command from the approval dialog
  • Fixed workflow scripts being able to use dynamic import() to run code outside the workflow sandbox
  • Fixed a permission gap where an agent definition's bypassPermissions mode ignored the org bypass-permissions disable policy
  • Fixed resuming a session after a mid-session /cd coming back empty
  • Fixed gateway model discovery hiding Claude models registered under provider-prefixed IDs such as vertex_ai/claude-* or bedrock/anthropic.claude-*
  • Fixed modelOverrides keys that aren't Anthropic model IDs being treated as the session's canonical model ID; unknown keys are now ignored as documented
  • Fixed managed settings: server-delivered settings no longer disable the env block of a machine-local managed-settings.json or MDM profile; admin env now merges per key
  • Fixed sandboxed commands failing to start on Linux when sandbox.filesystem.denyWrite covers the working directory
  • Fixed forked background agents getting stuck "already resuming" for the rest of the session when rebuilding the fork's parent prompt failed during resume
  • Fixed a resumed session failing every turn, or leaving the interactive app on an unresponsive error screen, when its history held a malformed diagnostics attachment
  • Fixed a rare hang when parsing unusual git push output
  • Changed CLAUDE_CODE_DISABLE_1M_CONTEXT to hold every Claude model with a native 1M window to 200K via auto-compaction, not just a fixed list; a startup warning now appears when auto-compaction isn't holding the session to 200K
  • Changed auto-compact to keep sessions on unrecognized model IDs within the assumed context window instead of letting them grow past it; set CLAUDE_CODE_DISABLE_UNKNOWN_MODEL_WINDOW_ENFORCEMENT=1 to restore the previous behavior
  • Changed /review to be an alias of /code-review, which reviews the current diff or a PR (/code-review <level> <pr#>); use /code-review ultra for a deep cloud review
  • Changed /code-review with no effort level to reuse the level you typed last; type a level like /code-review high to change it
