claude-code v2.1.265

Correctif Publié8 sept. 2026 Sourceanthropics/claude-code Anglais original

Cette page est traduite automatiquement. Le texte anglais original fait foi.

code-claude v2.1.265

Qu'est-ce qui a changé

  • Ajout de user.email et user.groups à la télémétrie que Claude Desktop et Cowork envoient via une passerelle d'applications Claude, correspondant aux sessions de terminal
  • Ajout du support pour pointer --plugin-dir vers un dossier de plugins : chaque dossier enfant avec un manifeste se charge et les enfants ajoutés ou supprimés lors de l'exécution sont récupérés
  • Ajout d'une limite de 1 Go pour les résultats des outils enregistrés sur le disque ; l'aperçu en conversation indique quand un fichier enregistré a été tronqué
  • Correction de la reprise d'un sous-agent généré au premier plan modifiant sa liste d'outils et son préfixe d'invite système, ce qui empêchait la réutilisation du cache d'invite pour cet agent.
  • Correction des coéquipiers des agents et des sous-agents repris déplaçant le contexte du hook SubagentStart et les compétences préchargées hors du préfixe d'invite lors des tours ultérieurs, ce qui empêchait la réutilisation du cache d'invite.
  • Correction de la reprise après la mort du processus précédent alors qu'un outil était en cours d'exécution : la dernière invite n'est plus réécrite et l'appel de l'outil interrompu est conservé et marqué comme interrompu
  • Correction du rejet de /model opusplan[1m] avec "Modèle introuvable"
  • Correction du code surligné par la syntaxe dans les invites d'autorisation et les messages omettant parfois un caractère après un sigil Ruby ?, Erlang $ ou Perl $
  • Correction de la transcription plein écran sautant d'une ligne à chaque fois que la commande slash ou la liste de suggestions @-file s'ouvrait ou se fermait
  • Correction d'un chemin de plugin contenant une barre oblique inverse contournant la vérification du confinement du lien symbolique sur macOS et Linux
  • Correction des répertoires de plugins dont les noms commencent par deux points étant refusés à tort car en dehors de la racine du plugin
  • Correction des sessions VS Code et SDK nécessitant occasionnellement une reconnexion lorsqu'une session était fermée lors de l'actualisation de son token
  • Correction des sessions de contrôle à distance envoyant le signal de fin de tour avant le dernier message de réponse, ce qui pouvait afficher une réponse comme terminée dans l'application Claude avant l'arrivée de sa dernière partie
  • Correction des sessions en arrière-plan (--bg) qui étaient parfois retirées à mi-tour lorsqu'un message arrivait juste avant le délai d'inactivité.
  • Correction du statut git et des sondes diff de Claude Code exécutant des filtres propres configurés par un référentiel imbriqué dans l'arborescence de travail
  • Correction de l'outil de conseiller et de ses instructions étant redécidées par demande à partir du modèle de demande ; la décision est désormais prise une fois et annoncée dans la conversation lorsqu'elle change
  • Correction de la publication d'artefacts acceptant les noms d'outils de connecteur que le connecteur n'expose pas ; la publication est désormais refusée lorsqu'aucun des outils déclarés n'existe, et avertie lorsque seuls certains n'existent pas
  • Correction de /add-dir <subdirectory> refusant de charger les agents d'un sous-répertoire lorsque les paramètres gérés verrouillent uniquement les compétences sur les plugins, et promettant des agents lorsque seuls les agents sont verrouillés
  • Correction des raccourcis clavier à deux touches s'annulant silencieusement lorsque la deuxième touche arrivait plus d'une seconde plus tard, comme cela se produit dans tmux ; ils attendent maintenant 3 secondes et affichent un avis lorsqu'ils expirent
  • Correction des compétences fourchues (context: fork) qui ne diffusaient pas leur invite de coup d'envoi et, avec --forward-subagent-text, leur texte se transformait en événements de progression dans le flux-json
  • Correction du dossier de composants par défaut d'un plugin que le système d'exploitation ne peut pas vérifier, comme une boucle de lien symbolique, étant ignoré silencieusement ; il est maintenant signalé dans /plugin avec le code d'erreur
  • Correction du relais de télémétrie OTLP de la passerelle des applications Claude, qui suspendait tous les transferts vers un collecteur pendant 30 secondes après avoir rejeté quelques charges utiles jugées mal formées ou trop volumineuses.
  • Correction de /plugin Discover/Browse et claude plugin list --json --available n'affichant aucune description ni nom d'affichage pour les plugins du marché dont les métadonnées ne résident que dans leur plugin.json
  • Correction de /login affichant « aucune URL de passerelle n'est configurée » lors d'une réexécution dans une session qui s'est connectée à une passerelle d'applications Claude définie par les paramètres gérés
  • Correction de /model affirmant qu'un modèle était "enregistré par défaut" lorsque le fichier de paramètres ne pouvait pas être écrit ; il dit maintenant que la sauvegarde a échoué et pourquoi
  • Correction de /clear de Remote Control en attente sur les hooks SessionStart et sur les boîtes de dialogue ouvertes du terminal avant de terminer
  • Correction de la boîte de dialogue /config changeant de hauteur lors du basculement entre ses onglets
  • Correction de la reprise d'un workflow exécuté après le redémarrage de son conteneur ; une reprise dont le journal d'exécution est manquant échoue désormais avec une erreur claire au lieu de réexécuter chaque agent
  • Correction de la référence du code d'erreur de la compétence claude-api : les échecs d'accès au modèle renvoient 404 et les en-têtes bêta indisponibles renvoient 400, et non 403.
  • Correction des sessions non interactives (-p avec entrée stream-json, Agent SDK, sessions cloud) réinitialisant le répertoire de travail du shell à chaque nouveau message utilisateur ; un cd persiste désormais à travers les tours
  • Correction des serveurs MCP configurés comme http qui parlent uniquement du transport HTTP+SSE existant et ne se connectent jamais ; Claude Code revient désormais à SSE comme le décrit la spécification MCP
  • Correction de certains connecteurs claude.ai dans les sessions cloud affichant comme nécessitant une authentification même s'ils sont connectés dans claude.ai (serveurs qui répondent à une requête non prise en charge avec HTTP 401)
  • Correction des sessions à distance gardant leur conteneur sandbox en vie pendant qu'une approbation de connecteur ou un lien de connexion vous attend
  • Correction des reprises de sessions affichant de longues instructions de récupération orientées vers le modèle dans les notifications « la tâche en arrière-plan n'a pas été terminée » au lieu d'une courte ligne d'état
  • Windows : correction du refus de lecture, d'écriture et d'édition de chaque fichier ("résolution du lien symbolique modifiée après vérification de l'autorisation") lors de l'exécution dans un bac à sable AppContainer ou à jeton restreint
  • Amélioration du démarrage de --worktree sur les grands dépôts : le nouveau worktree est désormais extrait en parallèle (git 2.32+)
  • Amélioration des détails de l'agent /workflows : les appels d'outils sont marqués en cours d'exécution, en échec ou terminés, la liste des tâches du sous-agent est affichée lorsqu'il en a une et Enter déplie les appels répertoriés avec leurs entrées et leurs résultats.
  • Commandes slash améliorées saisies au milieu de l'invite : les correspondances s'affichent désormais dans une liste (l'onglet l'ouvre en dehors du plein écran) au lieu d'une simple suggestion, et une compétence de plugin est désormais trouvée par son nom brut.
  • Serveurs MCP distants améliorés nécessitant une connexion : Claude Code n'enregistre plus un OAuth client auprès d'eux jusqu'à ce que vous vous authentifiiez réellement
  • Amélioration du temps de reprise de longues sessions qui lisent de nombreux fichiers
  • Amélioration de l'erreur affichée lorsqu'une image dépassant les limites de taille ne peut pas être décodée : elle nomme désormais la cause et comment la corriger au lieu de simplement citer la limite.
  • Amélioration de la lecture par l'outil Artefact d'un artefact écrit par quelqu'un d'autre : le résumé traite désormais la page comme un contenu non rust et signale les instructions intégrées plutôt que de les relayer.
  • Mise à jour de l'option d'autorisation du dossier .claude pour indiquer ce qu'elle autorise réellement : modifier les fichiers dans le dossier .claude (ou ~/.claude) du projet pour la session
  • Modification des machines avec forceLoginGatewayUrl dans les paramètres gérés pour qu'elles deviennent des sessions de passerelle d'applications Claude dès le démarrage, comme forceLoginMethod: "gateway" ; une connexion claude.ai restante ou une clé API n'est pas utilisée
  • Modification du traitement des images pour utiliser la prise en charge des images intégrée au runtime ; le CLI n'extrait plus de module image natif dans le répertoire temporaire
  • Modification des métadonnées d'affichage du plugin pour préférer l'entrée du marché à plugin.json sur l'onglet Installé et claude plugin details, comblant les lacunes de plugin.json
  • Modification des sessions de passerelle des applications Claude pour exporter OpenTelemetry directement vers un collecteur, le nom des paramètres gérés de la passerelle dans OTEL_EXPORTER_OTLP_ENDPOINT, au lieu de passer par le relais de la passerelle ; les sessions sans collecteur nommé utilisent toujours le relais
  • [VSCode] Ajout de l'archivage automatique des sessions inactives pendant une période définie (nouveau paramètre "Archiver les sessions inactives", 14 jours par défaut)
  • [VSCode] Correction du chat de la barre latérale qui revenait vide après un rechargement de la fenêtre ou un redémarrage lorsque la conversation était ouverte depuis plus de 10 minutes
  • [VSCode] Correction du point de la chronologie situé sous le texte du message "La télécommande est active".

Anglais original / English original

claude-code v2.1.265

What's changed

  • Added user.email and user.groups to the telemetry Claude Desktop and Cowork send through a Claude apps gateway, matching terminal sessions
  • Added support for pointing --plugin-dir at a folder of plugins: each child folder with a manifest loads, and children added or removed while running are picked up
  • Added a 1 GB cap on tool results saved to disk; the in-conversation preview says when a saved file was truncated
  • Fixed resuming a foreground-spawned subagent changing its tool list and system prompt prefix, which broke prompt-cache reuse for that agent
  • Fixed agent teammates and resumed subagents moving SubagentStart hook context and preloaded skills out of the prompt prefix on later turns, which broke prompt-cache reuse
  • Fixed resume after the previous process died while a tool was running: the last prompt is no longer rewritten, and the interrupted tool call is kept and marked interrupted
  • Fixed /model opusplan[1m] being rejected with "Model not found"
  • Fixed syntax-highlighted code in permission prompts and messages sometimes omitting a character after a Ruby ?, Erlang $, or Perl $ sigil
  • Fixed the fullscreen transcript jumping by one row whenever the slash-command or @-file suggestion list opened or closed
  • Fixed a plugin path containing a backslash bypassing the symlink containment check on macOS and Linux
  • Fixed plugin directories whose names begin with two dots being wrongly refused as outside the plugin root
  • Fixed VS Code and SDK sessions occasionally requiring re-login when a session was closed while refreshing its token
  • Fixed Remote Control sessions sending the end-of-turn signal before the reply's last message, which could show a reply as finished in the Claude app before its last part arrived
  • Fixed background (--bg) sessions occasionally being retired mid-turn when a message arrived just before the idle timeout
  • Fixed Claude Code's own git status and diff probes running clean filters configured by a nested repository inside the working tree
  • Fixed the advisor tool and its instructions being re-decided per request from the request's model; the decision is now made once and announced in the conversation when it changes
  • Fixed artifact publish accepting connector tool names the connector doesn't expose; the publish is now refused when none of the declared tools exist, and warned when only some don't
  • Fixed /add-dir <subdirectory> refusing to load a subdirectory's agents when managed settings lock only skills to plugins, and promising agents when only agents are locked
  • Fixed two-key keyboard shortcuts cancelling silently when the second key arrived more than a second later, as happens inside tmux; they now wait 3 seconds and show a notice when they time out
  • Fixed forked skills (context: fork) not streaming their kickoff prompt and, with --forward-subagent-text, their text turns as progress events in stream-json
  • Fixed a plugin's default component folder that the OS cannot check, such as a symlink loop, being silently skipped; it is now reported in /plugin with the error code
  • Fixed the Claude apps gateway's OTLP telemetry relay pausing all forwarding to a collector for 30 seconds after it rejected a few payloads as malformed or too large
  • Fixed /plugin Discover/Browse and claude plugin list --json --available showing no description or display name for marketplace plugins whose metadata lives only in their plugin.json
  • Fixed /login showing "no gateway URL is configured" when re-run in a session that signed in to a Claude apps gateway set by managed settings
  • Fixed /model claiming a model was "saved as your default" when the settings file couldn't be written; it now says the save failed and why
  • Fixed /clear from Remote Control waiting on SessionStart hooks and on open terminal dialogs before completing
  • Fixed the /config dialog changing height when switching between its tabs
  • Fixed resuming a workflow run after its container restarted; a resume whose run journal is missing now fails with a clear error instead of rerunning every agent
  • Fixed the claude-api skill's error-code reference: model access failures return 404 and unavailable beta headers return 400, not 403
  • Fixed non-interactive sessions (-p with stream-json input, Agent SDK, cloud sessions) resetting the shell working directory at each new user message; a cd now persists across turns
  • Fixed MCP servers configured as http that only speak the legacy HTTP+SSE transport never connecting; Claude Code now falls back to SSE as the MCP spec describes
  • Fixed some claude.ai connectors in cloud sessions showing as needing authentication even though they are connected in claude.ai (servers that answer an unsupported request with HTTP 401)
  • Fixed remote sessions keeping their sandbox container alive while a connector approval or sign-in link waits for you
  • Fixed resumed sessions showing long model-facing recovery instructions in "background task didn't finish" notices instead of a short status line
  • Windows: Fixed Read, Write and Edit refusing every file ("symlink resolution changed after permission was checked") when running inside an AppContainer or restricted-token sandbox
  • Improved --worktree startup on large repositories: the new worktree is now checked out in parallel (git 2.32+)
  • Improved /workflows agent detail: tool calls are marked running, failed or done, the subagent's task list is shown when it has one, and Enter unfolds the listed calls with their inputs and results
  • Improved slash commands typed mid-prompt: matches now show in a list (Tab opens it outside fullscreen) instead of a single suggestion, and a plugin skill is now found by its bare name
  • Improved remote MCP servers that need sign-in: Claude Code no longer registers an OAuth client with them until you actually authenticate
  • Improved the time to resume long sessions that read many files
  • Improved the error shown when an image over the size limits cannot be decoded: it now names the cause and how to fix it instead of only citing the limit
  • Improved the Artifact tool's read of an artifact someone else wrote: the summary now treats the page as untrusted content and flags embedded instructions rather than relaying them
  • Updated the .claude folder permission option to say what it actually allows: editing files in the project's .claude folder (or ~/.claude) for the session
  • Changed machines with forceLoginGatewayUrl in managed settings to be Claude apps gateway sessions from startup, like forceLoginMethod: "gateway"; a leftover claude.ai login or API key is not used
  • Changed image processing to use the runtime's built-in image support; the CLI no longer extracts a native image module to the temp directory
  • Changed plugin display metadata to prefer the marketplace entry over plugin.json on the Installed tab and claude plugin details, filling gaps from plugin.json
  • Changed Claude apps gateway sessions to export OpenTelemetry directly to a collector the gateway's managed settings name in OTEL_EXPORTER_OTLP_ENDPOINT, instead of through the gateway's relay; sessions without a named collector still use the relay
  • [VSCode] Added automatic archiving of sessions inactive for a set period (new "Archive inactive sessions" setting, default 14 days)
  • [VSCode] Fixed the sidebar chat coming back blank after Reload Window or a restart when the conversation had been open for more than 10 minutes
  • [VSCode] Fixed the timeline dot sitting below the text on the "Remote Control is active" message
