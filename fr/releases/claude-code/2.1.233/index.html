claude-code v2.1.233

code-claude v2.1.233

Qu'est-ce qui a changé

  • Ajout de la prise en charge de l'URL de demande de fusion GitLab au drapeau --worktree et à la vue claude agents (où les MR s'affichent sous la forme !N)
  • Ajout d'un paramètre de passerelle d'applications forward_user_identity opt-in sur les amonts Anthropic qui envoie l'identité de l'utilisateur connecté sous forme d'en-têtes, afin qu'un proxy derrière la passerelle puisse attribuer les dépenses par utilisateur
  • Ajout de la prise en charge opt-in du groupe de contrôle de mémoire pour les commandes de l'outil Bash sous Linux (CLAUDE_CODE_TOOL_MEMORY_LIMIT) afin qu'une version incontrôlée ne puisse pas bloquer la session
  • Ajout de la variable d'environnement CLAUDE_CODE_WEBFETCH_CACHE_TTL_MS pour configurer le TTL du cache d'URL de session WebFetch (par défaut inchangé : 15 minutes)
  • Correction des sessions cloud étant parfois marquées comme perdues lorsque l'environnement s'arrêtait alors que Claude attendait une invite d'autorisation
  • Correction des connexions MCP v2 rouvrant sans cesse les flux d'abonnements/d'écoute sur des serveurs qui mettent fin aux flux de longue durée selon un délai d'attente fixe (par exemple, des hôtes sans serveur)
  • Correction des hooks de notification ne se déclenchant pas pour les invites d'autorisation lors de l'exécution sous Claude Desktop ou VS Code
  • Correction des sessions inactives sous Linux gardant parfois un cœur de processeur à 100 % lorsque le sandboxing est activé
  • Correction des alias de compétences groupées comme /checkup et /review signalant une "commande inconnue" en mode -p ou avec des plugins/MCP chargés lorsqu'un utilisateur ou une compétence de projet masque la compétence groupée
  • Correction de la substitution d'argument de compétence/commande pour empêcher les valeurs d'argument d'être à nouveau développées en tant que marqueurs de modèle
  • Correction des chemins Windows orthographiés avec le préfixe de périphérique NT \??\ contournant la validation du chemin UNC, fermant ainsi un vecteur de fuite d'informations d'identification NTLM
  • Amélioration du temps de démarrage de la session claude self-hosted-runner : la branche de session est désormais créée sans réécrire l'arborescence de travail, et deux allers-retours serveur ne bloquent plus le lancement de l'agent
  • Amélioration du transfert des erreurs de la passerelle d'applications : les erreurs 400/413 de Vertex, Foundry et Claude Platform sur les amonts AWS véhiculent désormais le propre message de l'amont ; corrige un bug avec le compactage automatique sur la passerelle des applications
  • Amélioration de claude plugin validate pour vérifier un répertoire .claude/skills nu, signalant les fichiers SKILL.md dont le frontmatter ne parvient pas à analyser
  • Mode lecteur d'écran amélioré : le sélecteur /effort s'affiche sous la forme d'une liste numérotée avec une invite de numéro saisi, et le texte des astuces et des boîtes de dialogue n'est plus affiché par cli.
  • Diagnostics du mode d'impression améliorés : une ligne [claude-code:unrecognized_model] est écrite dans stderr lorsqu'une demande est envoyée pour un ID de modèle que Claude Code ne reconnaît pas ; mappez-le avec modelOverrides pour faire taire
  • Modification de l'astuce de configuration de l'application GitHub pour qu'elle n'apparaisse plus dans les référentiels dont l'origine distante est sur gitlab.com ou bitbucket.org ; l'astuce du marché d'entreprise couvre désormais les hôtes git internes non-GitHub
  • Les outils Todo/suivi des tâches (TaskCreate/Get/Update/List, TodoWrite) ne sont plus disponibles sur Opus 4.8, Sonnet 5, Fable 5, Mythos 5 et les modèles plus récents ; réglez CLAUDE_CODE_ENABLE_TODO_TOOLS=1 pour les ramener
  • Windows : correction du mode automatique, arrêt répété pour approbation manuelle sur les commandes Bash cd <dir> && <command> > file ordinaires (une régression 2.1.232)
  • Annulation des modifications d'autorisation 2.1.232 Bash pour les liens symboliques de style Cygwin sous Windows et pour les redirections d'entrée (< file) ; une version plus étroite reviendra dans une version ultérieure

claude-code v2.1.233

What's changed

  • Added GitLab merge request URL support to the --worktree flag and the claude agents view (where MRs display as !N)
  • Added an opt-in forward_user_identity apps gateway setting on Anthropic upstreams that sends the signed-in user's identity as headers, so a proxy behind the gateway can attribute spend per user
  • Added opt-in memory cgroup support for Bash tool commands on Linux (CLAUDE_CODE_TOOL_MEMORY_LIMIT) so a runaway build can't stall the session
  • Added CLAUDE_CODE_WEBFETCH_CACHE_TTL_MS environment variable to configure the WebFetch session URL cache TTL (default unchanged: 15 minutes)
  • Fixed cloud sessions occasionally being marked as lost when the environment shut down while Claude was waiting on a permission prompt
  • Fixed MCP v2 connections endlessly reopening the subscriptions/listen stream against servers that terminate long-held streams on a fixed timeout (e.g. serverless hosts)
  • Fixed Notification hooks not firing for permission prompts when running under Claude Desktop or VS Code
  • Fixed idle sessions on Linux sometimes keeping one CPU core at 100% when sandboxing is enabled
  • Fixed bundled skill aliases like /checkup and /review reporting "Unknown command" in -p mode or with plugins/MCP loaded when a user or project skill shadows the bundled skill
  • Fixed skill/command argument substitution to prevent argument values from being re-expanded as template markers
  • Fixed Windows paths spelled with the NT \??\ device prefix bypassing UNC path validation, closing an NTLM credential-leak vector
  • Improved claude self-hosted-runner session start time: the session branch is now created without rewriting the working tree, and two server round trips no longer block the agent's launch
  • Improved apps gateway error forwarding: 400/413 errors from Vertex, Foundry, and Claude Platform on AWS upstreams now carry the upstream's own message; fixes a bug with auto-compact on apps gateway
  • Improved claude plugin validate to check a bare .claude/skills directory, reporting SKILL.md files whose frontmatter fails to parse
  • Improved screen reader mode: the /effort selector renders as a numbered list with a typed-number prompt, and hint and dialog text is no longer clipped
  • Improved print mode diagnostics: a [claude-code:unrecognized_model] line is written to stderr when a request goes out for a model ID Claude Code doesn't recognize; map it with modelOverrides to silence
  • Changed the GitHub app setup tip to no longer appear in repositories whose origin remote is on gitlab.com or bitbucket.org; the enterprise marketplace tip now covers non-GitHub internal git hosts
  • Todo/task-tracking tools (TaskCreate/Get/Update/List, TodoWrite) are no longer available on Opus 4.8, Sonnet 5, Fable 5, Mythos 5, and newer models; set CLAUDE_CODE_ENABLE_TODO_TOOLS=1 to bring them back
  • Windows: fixed auto mode repeatedly stopping for manual approval on ordinary cd <dir> && <command> > file Bash commands (a 2.1.232 regression)
  • Reverted the 2.1.232 Bash permission changes for Cygwin-style symlinks on Windows and for input redirections (< file); a narrower version will return in a later release
