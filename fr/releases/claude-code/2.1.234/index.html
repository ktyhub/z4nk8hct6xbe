claude-code v2.1.234

Correctif Publié17 août 2026 Sourceanthropics/claude-code Anglais original

Cette page est traduite automatiquement. Le texte anglais original fait foi.

code-claude v2.1.234

Qu'est-ce qui a changé

  • Ajout de la variable d'environnement facultative CLAUDE_CODE_PROJECT_DIR_NAME : les hôtes qui attribuent à chaque session son propre répertoire de configuration peuvent choisir un nom court pour le répertoire de transcription par projet.
  • Ajout de l'action de liaison de touches selection:clear, afin qu'une touche puisse être liée pour effacer une sélection de texte dans l'application ; fonctionne également dans la vue des agents
  • Ajout d'un badge de demande de fusion GitLab au pied de page et à la ligne d'état : les dépôts avec une télécommande GitLab et un glab authentifié CLI montrent MR !N avec les états brouillon/en attente/vert
  • Claude Code poursuit désormais automatiquement votre session lorsqu'une limite d'utilisation de claude.ai est réinitialisée ; désactivez-le dans /config ("Continuer automatiquement à la limite d'utilisation")
  • Il est désormais demandé à Claude d'utiliser l'e-mail de votre compte uniquement pour vous identifier, et de ne pas l'envoyer à des services non liés, sauf si vous le demandez
  • Sécurité : les lectures de fichiers à distance, la restauration de session, les inclusions CLAUDE.md, les scripts de flux de travail et les téléchargements de fichiers rejettent désormais les chemins d'espace de noms Windows NT (\??\), renforçant ainsi les accès restants aux fichiers de pré-approbation contre le vecteur de fuite d'informations d'identification NTLM.
  • Correction du mode automatique lors de sessions très longues, revérifiant et refusant à plusieurs reprises l'accès au réseau des commandes en bac à sable après que la conversation ait été compactée
  • Correction des réponses d'autorisation au niveau de la session (y compris les refus) qui étaient supprimées lors de la réponse aux invites d'autorisation de l'outil de sous-agent en arrière-plan
  • Correction d'un crash lorsqu'une réponse API sur le chemin de secours sans streaming (généralement via des passerelles tierces) contenait un bloc de réflexion manquant son champ de réflexion ou un bloc de texte manquant son champ de texte
  • Correction du rendu des démarques devenant extrêmement lent pour certains messages contenant des séquences Unicode inhabituelles
  • Correction de SendMessage rejetant un destinataire copié depuis ListAgents lorsque le nom de la session atteint la limite de 200 caractères ou contient beaucoup d'emojis.
  • Correction de la détection du référentiel lisant mal l'hôte des télécommandes git avec des informations utilisateur inhabituelles, produisant des liens et un comportement spécifique au dépôt pour le mauvais hôte
  • Correction des diagnostics MCP imprimant les secrets résolus : les avertissements de conflit de portée affichent désormais le formulaire ${VAR} configuré et les détails d'échec de connexion affichent uniquement l'origine du serveur.
  • Correction des listes autorisées strictKnownMarketplaces acceptant les sources de marché git de style SCP dont l'hôte diffère de celui auquel git se connecterait réellement
  • Correction du texte modal tel que l'URL /login OAuth perdant des caractères lors de la copie en plein écran
  • Correction d'une règle horizontale --- dans la démarque rendue qui s'étendait dans la ligne qui la suivait
  • Correction des commandes shell consécutives se divisant en plusieurs lignes "Commandes shell Ran 1" lorsque les mises à jour de tâches/tâches étaient entrelacées entre elles
  • Correction des boîtes de dialogue comme /permissions ouvertes pendant qu'une commande shell ! était en cours d'exécution et fermées à la fin de la commande
  • Correction d'une commande shell ! en file d'attente envoyée au modèle sous forme de texte brut après avoir appuyé sur la flèche vers le haut pour modifier l'entrée en file d'attente
  • Correction des messages en file d'attente réapparaissant dans l'historique des invites alors qu'ils étaient toujours en file d'attente, Esc lors de la sélection d'un message en file d'attente n'interrompt plus le tour, et le mode ! ne reste plus bloqué après une soumission à mi-tour.
  • Correction de l'acceptation du message « Essayer le nouveau moteur de rendu plein écran ? » invite à redémarrer la session sans son mode d'autorisation (par exemple --dangerously-skip-permissions), règles d'autorisation/refus de l'outil, indicateurs de modèle ou d'effort
  • Correction de l'abandon des règles de lancement --allowed-tools/--disallowed-tools lors du redémarrage de /tui ; il est maintenant declines de basculer, avec la raison, lorsque la session a des restrictions, un redémarrage ne peut pas être reporté
  • Correction des invites trust omettant l'avertissement de portée à l'échelle du référentiel lorsque le répertoire était vu pour la première fois avant que le référentiel n'y existe.
  • Correction d'un cas où la fermeture d'un onglet de comparaison IDE lors d'une nouvelle invite d'autorisation pouvait répondre à la nouvelle invite avec l'entrée précédente
  • Corrigé : les fichiers envoyés à l'utilisateur lors des sessions de contrôle à distance hébergées par Claude Code Desktop ou VS Code sont désormais téléchargés, ils s'ouvrent donc sur le téléphone et sur le Web au lieu d'afficher une carte vide
  • Corrigé : après /login alors que CLAUDE_CODE_OAUTH_TOKEN est activé, le rappel de jeton périmé ne s'infiltre plus dans le tour automatiquement repris de Claude — il n'apparaît désormais que pour vous.
  • Corrigé : les aperçus d'autorisation sont désormais transmis uniquement aux serveurs de canal admis par la porte trust entrante, et la désactivation explicite de la capacité d'autorisation d'un serveur est honorée.
  • Corrigé : le masquage des informations d'identification sur les aperçus d'autorisations relayés ne peut plus masquer les commandes, les chemins ou les destinations à l'approbateur ; les blocs de clé privée surdimensionnés sont désormais rédigés sous une rédaction complète
  • Corrigé : les jetons du fournisseur API qui masquent les aperçus d'autorisation sont désormais masqués même lorsqu'ils sont directement suivis par des délimiteurs de shell
  • Correction des messages inter-session de Claude Desktop qui étaient supprimés silencieusement par la session du destinataire lorsque la messagerie inter-session était lue comme désactivée, ce qui laissait la requête de l'expéditeur "réfléchir" pendant plusieurs minutes.
  • Contrôle à distance : la connexion de cet ordinateur à un autre compte ou organisation claude.ai arrête désormais la session en cours en quelques secondes et indique pourquoi, au lieu d'un HTTP trompeur 404 heures plus tard.
  • Les sessions de contrôle à distance démarrées depuis Claude Code Desktop ou VS Code maintiennent désormais les téléphones et claude.ai/code à jour sur le mode d'autorisation de la session (et claude.ai/code sur le modèle) à mesure qu'ils changent.
  • Contrôle à distance : les sélections d'effort effectuées sur un téléphone ou sur claude.ai/code s'appliquent désormais aux sessions hébergées sur terminal et Desktop/VS Code, et la session publie son niveau d'effort aux clients connectés
  • SendMessage et ListAgents indiquent désormais quand la liste des sessions de votre compte était trop longue pour être vérifiée complètement, au lieu de traiter les sessions invisibles comme absentes
  • Les identifiants de profil Anthropic expirés vous dirigent désormais vers /login lorsqu'une connexion claude.ai aurait la priorité
  • Amélioration de la transcription : vos propres invites affichent désormais les démarques (blocs de code en surbrillance, code en ligne, listes) de la même manière que les réponses.
  • Amélioration de l'erreur "API a renvoyé une réponse vide ou mal formée" pour indiquer ce qui est revenu (type de contenu, type de corps, taille, ID de demande) et pourquoi la demande de streaming d'origine a échoué
  • Amélioration des titres de session générés automatiquement pour lire sous forme de noms courts et spécifiques (par exemple "Bogue du bouton de connexion") plutôt que de phrases reformulant votre demande (par exemple "Corriger le bouton de connexion sur mobile")
  • Réduction du coût contextuel du chargement de la compétence claude-api intégrée de ~ 200 000+ jetons à ~ 25 000 en chargeant des documents de référence à la demande
  • /permissions peut désormais être ouvert pendant que Claude travaille — les changements de règles s'appliquent au reste du tour en cours
  • /add-dir <path> peut désormais être utilisé pendant que Claude travaille ; Les boîtes de dialogue /add-dir, /autocompact, /theme, /help, /config et /advisor s'ouvrent à mi-tour dans l'interface utilisateur plein écran
  • /goal s'efface désormais avec un avis lorsqu'un tour s'arrête suite à une erreur irrécupérable (par exemple, authentification révoquée, solde créditeur épuisé ou débordement de contexte) au lieu de rester armé
  • /goal : lorsque les tâches en arrière-plan font attendre un objectif pendant plus de 30 minutes, Claude les enregistre désormais au lieu d'attendre indéfiniment (configurez CLAUDE_CODE_GOAL_CHECKIN_MINUTES=0 pour se désinscrire)
  • claude setup-token rejette désormais les arguments supplémentaires inattendus au lieu de les ignorer silencieusement
  • Modification de l'Esc en mode plein écran pour ne plus effacer une sélection de texte de la souris : il interrompt ou rejette comme d'habitude et la sélection reste en surbrillance
  • Suppression de la ligne redondante "Autorisé par le classificateur de mode automatique" que le mode automatique affichait sous chaque appel de l'outil Agent.
  • Suppression du paramètre « Modèle de coéquipier par défaut » de /config ; les coéquipiers de l'équipe d'agents utilisent désormais le modèle du leader à moins que l'apparition n'en nomme un
  • Réduction du compteur de temps écoulé sur l'en-tête de l'outil en cours d'exécution afin qu'il ne soit plus en concurrence avec les décomptes en gras
  • Les notifications de tâches en arrière-plan délivrées entre les tours sont désormais envoyées au modèle à l'intérieur des balises <system-reminder>, correspondant à la livraison à mi-tour.
  • Mantle : ignorez la sonde de disponibilité des broches d'administration au démarrage lorsqu'un modèle de boucle principale est déjà sélectionné
  • Windows : le démarrage ne s'arrête plus lors de tentatives répétées de changement de nom lorsque ~/.claude.json est en lecture seule

claude-code v2.1.234

What's changed

  • Added the optional CLAUDE_CODE_PROJECT_DIR_NAME environment variable: hosts that give each session its own config directory can choose a short name for the per-project transcript directory
  • Added the selection:clear keybinding action, so a key can be bound to clear an in-app text selection; also works in the agents view
  • Added a GitLab merge request badge to the footer and statusline: repos with a GitLab remote and an authenticated glab CLI show MR !N with draft/pending/green states
  • Claude Code now continues your session automatically when a claude.ai usage limit resets; turn it off in /config ("Continue automatically at usage limit")
  • Claude is now told to use your account email only to identify you, and not to send it to unrelated services unless you ask
  • Security: remote file reads, session restore, CLAUDE.md includes, workflow scripts and file uploads now reject Windows NT-namespace (\??\) paths, hardening the remaining pre-approval file accesses against the NTLM credential-leak vector
  • Fixed auto mode in very long sessions repeatedly re-checking and denying sandboxed commands' network access after the conversation had been compacted
  • Fixed session-scoped permission answers (including denies) being dropped when answering background subagent tool permission prompts
  • Fixed a crash when an API response on the non-streaming fallback path (typically via third-party gateways) contained a thinking block missing its thinking field or a text block missing its text field
  • Fixed markdown rendering becoming extremely slow for some messages containing unusual Unicode sequences
  • Fixed SendMessage rejecting a recipient copied from ListAgents when the session name is at the 200-character cap or emoji-heavy
  • Fixed repository detection mis-reading the host of git remotes with unusual userinfo, producing links and repo-specific behavior for the wrong host
  • Fixed MCP diagnostics printing resolved secrets: scope-conflict warnings now show the configured ${VAR} form, and connection-failure details show only the server origin
  • Fixed strictKnownMarketplaces allowlists accepting SCP-style git marketplace sources whose host differs from the one git would actually connect to
  • Fixed modal text such as the /login OAuth URL losing characters when copied in fullscreen
  • Fixed a --- horizontal rule in rendered markdown running into the line after it
  • Fixed consecutive shell commands splitting into multiple "Ran 1 shell command" rows when todo/task updates were interleaved between them
  • Fixed dialogs like /permissions opened while a ! shell command was running being dismissed when the command finished
  • Fixed a queued ! shell command being sent to the model as plain text after pressing up-arrow to edit the queued input
  • Fixed queued messages reappearing in the prompt history while still queued, Esc while selecting a queued message no longer interrupts the turn, and ! mode no longer sticks after a mid-turn submit
  • Fixed accepting the "Try the new fullscreen renderer?" prompt restarting the session without its permission mode (e.g. --dangerously-skip-permissions), tool allow/deny rules, model or effort flags
  • Fixed /tui dropping launch --allowed-tools/--disallowed-tools rules when it restarts; it now declines to switch, with the reason, when the session has restrictions a restart can't carry over
  • Fixed trust prompts omitting the repository-wide scope warning when the directory was first seen before the repository existed there
  • Fixed a case where an IDE diff tab closing during a permission re-prompt could answer the new prompt with the previous input
  • Fixed: files sent to the user during Remote Control sessions hosted by Claude Code Desktop or VS Code now upload, so they open on phone and web instead of showing an empty card
  • Fixed: after /login while CLAUDE_CODE_OAUTH_TOKEN is set, the stale-token reminder no longer leaks into Claude's automatically resumed turn — it now appears only to you
  • Fixed: permission previews now relay only to channel servers admitted by the inbound trust gate, and a server's explicit permission-capability opt-out is honored
  • Fixed: credential masking on relayed permission previews can no longer hide commands, paths, or destinations from the approver; oversized private-key blocks now redact under full-strength redaction
  • Fixed: provider API tokens that mask on permission previews now mask even when directly followed by shell delimiters
  • Fixed Claude Desktop inter-session messages being silently dropped by the recipient session when cross-session messaging read as disabled, which left the sender's query "thinking" for many minutes
  • Remote Control: signing this computer in to a different claude.ai account or organization now stops the running session within seconds and says why, instead of a misleading HTTP 404 hours later
  • Remote Control sessions started from Claude Code Desktop or VS Code now keep phones and claude.ai/code updated on the session's permission mode (and claude.ai/code on the model) as they change
  • Remote Control: effort picks made on a phone or on claude.ai/code now apply to terminal- and Desktop/VS Code-hosted sessions, and the session publishes its effort level to connected clients
  • SendMessage and ListAgents now say when your account's session list was too long to check completely, instead of treating unseen sessions as absent
  • Expired Anthropic profile credential now points you at /login when a claude.ai login would take precedence
  • Improved the transcript: your own prompts now render markdown (highlighted code blocks, inline code, lists) the same way replies do
  • Improved the "API returned an empty or malformed response" error to say what came back (content type, body kind, size, request ID) and why the original streaming request failed
  • Improved auto-generated session titles to read as short, specific names (e.g. "Login button bug") rather than sentences restating your request (e.g. "Fix the login button on mobile")
  • Reduced the context cost of loading the built-in claude-api skill from ~200k+ tokens to ~25k by loading reference docs on demand
  • /permissions can now be opened while Claude is working — rule changes apply to the rest of the current turn
  • /add-dir <path> can now be used while Claude is working; /add-dir, /autocompact, /theme, /help, /config and /advisor dialogs open mid-turn in the fullscreen TUI
  • /goal now clears itself with a notice when a turn dies on an unrecoverable error (e.g. revoked auth, an exhausted credit balance, or a context overflow) instead of staying armed
  • /goal: when background tasks keep a goal waiting for 30+ minutes, Claude now checks in on them instead of waiting indefinitely (set CLAUDE_CODE_GOAL_CHECKIN_MINUTES=0 to opt out)
  • claude setup-token now rejects unexpected extra arguments instead of silently ignoring them
  • Changed Esc in fullscreen mode to no longer clear a mouse text selection: it interrupts or dismisses as usual and the selection stays highlighted
  • Removed the redundant "Allowed by auto mode classifier" line that auto mode showed under every Agent tool call
  • Removed the "Default teammate model" setting from /config; agent-team teammates now use the leader's model unless the spawn names one
  • Dimmed the elapsed-time counter on the running tool header so it no longer competes with the bold counts
  • Background task notifications delivered between turns are now sent to the model inside <system-reminder> tags, matching mid-turn delivery
  • Mantle: skip the admin-pin availability probe at startup when a main-loop model is already picked
  • Windows: startup no longer stalls on repeated rename retries when ~/.claude.json is read-only
