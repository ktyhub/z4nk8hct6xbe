code-claude v2.1.295

Qu'est-ce qui a changé

  • Ajout de onFailure: "block" pour les hooks de commande et HTTP : un hook qui ne peut pas démarrer, expire ou se termine avec un code inattendu bloque l'action au lieu de la laisser passer
  • Ajout de la prise en charge du Program Status Protocol (OSC 7501) : les terminaux qui l'implémentent peuvent indiquer si Claude Code fonctionne, vous attend ou a terminé
  • Ajout du texte cité au sélecteur /copy, afin qu'un message rédigé soit copié sans ses marqueurs >
  • Ajout d'un avertissement pour claude plugin install, enable, disable et marketplace add lorsque le fichier de paramètres dans lequel ils écrivent ne se charge pas
  • Ajout d'une ligne sur stderr, lorsqu'il s'agit d'un terminal, qui indique ce qu'attend un run claude -p lorsqu'il reste ouvert après son dernier tour
  • Ajout de la prise en charge de timeouts.upstream_ttfb_ms sur Bedrock, Vertex, Foundry et autres cloud en amont de la passerelle des applications Claude : une valeur que vous définissez limite désormais le temps qu'un flux peut prendre pour démarrer à cet endroit, après quoi il bascule ou obtient un 502
  • Ajout d'un message "Backgrounding annulé" lorsque vous arrêtez le virage pendant que ← attend la fin de l'outil en cours
  • Ajout d'une liste facultative models à chaque passerelle d'applications Claude en amont : seuls les modèles répertoriés y sont envoyés, en cas de basculement également, et un * dans une entrée est un caractère générique
  • Ajout de la prise en charge de forceLoginMethod: "gateway" et forceLoginGatewayUrl dans vos propres paramètres utilisateur sur les machines sans paramètres gérés, afin que /login s'ouvre sur cette passerelle d'applications Claude
  • Ajout d'un conseil pour claude plugin validate lorsque le README d'un plugin n'a pas de ligne d'installation : il imprime la ligne à coller et ne change jamais le code de sortie, même avec --strict
  • Ajout de upstream_request_id à l'événement d'audit inference de la passerelle d'applications Claude : l'ID de requête d'Amazon Bedrock, de l'Anthropic API ou un autre en amont, pour les cas de support
  • Ajout de $.ui.notify pour les mods : génère une notification native via votre propre paramètre de notification et indique quel canal l'a envoyée
  • Ajout d'enfants au Button d'un mod : chaînes et Text, donc une ligne d'une liste peut être pressée avec une puce ou un détail sombre à l'intérieur
  • Ajout de CLAUDE_CODE_RETRY_WATCHDOG_MAX_WAIT_MS pour limiter la durée pendant laquelle le mode de nouvelle tentative sans surveillance (CLAUDE_CODE_RETRY_WATCHDOG) attend les erreurs 429 et 529.
  • Ajout d'un en-tête request-id aux réponses d'inférence réussies de la passerelle des applications Claude, afin que request_id dans la télémétrie Claude Code corresponde au journal d'audit de la passerelle
  • Correction de chaque échec de requête sur un modèle [1m] lorsqu'une passerelle, Bedrock, Vertex ou Foundry refuse la version bêta de context-1m ; Claude Code renvoie désormais sans
  • Correction de la sortie de texte claude -p supprimant les réponses précédentes lorsque le travail en arrière-plan commençait un autre tour ; la réponse de chaque tour s'imprime désormais à la fin du tour
  • Correction des serveurs MCP distants dans les sessions sans tête et SDK restant déconnectés après une panne de plus de 15 secondes, ou se reconnectant en boucle serrée à un serveur qui abandonne chaque connexion juste après sa connexion ; les chutes répétées reculent désormais, jusqu'à 30 s
  • Correction des connexions MCP distantes étant abandonnées lorsque la réponse d'erreur d'un serveur contenait un nom d'erreur réseau
  • Correction des serveurs MCP qui répètent qu'un curseur de pagination est demandé pour la même page jusqu'à 20 fois à chaque connexion
  • Correction des fichiers CSS, JavaScript et XML renvoyés par les outils MCP étant enregistrés au format .bin, ce que l'outil de lecture refuse ; les fichiers de polices et d'icônes ont désormais également leur propre extension

  • Added onFailure: "block" for command and HTTP hooks: a hook that can't start, times out, or exits with an unexpected code blocks the action instead of letting it through
  • Added Program Status Protocol (OSC 7501) support: terminals that implement it can show whether Claude Code is working, waiting on you, or done
  • Added quoted text to the /copy picker, so a drafted message copies without its > markers
  • Added a warning to claude plugin install, enable, disable and marketplace add when the settings file they write to does not load
  • Added a line on stderr, when it is a terminal, that says what a claude -p run is waiting for when it stays open after its last turn
  • Added support for timeouts.upstream_ttfb_ms on the Claude apps gateway's Bedrock, Vertex, Foundry and other cloud upstreams: a value you set now limits how long a stream may take to start there, after which it fails over or gets a 502
  • Added a "Backgrounding cancelled" message when you stop the turn while ← is waiting for the current tool to finish
  • Added an optional models list to every Claude apps gateway upstream: only the listed models are sent there, on failover too, and one * in an entry is a wildcard
  • Added support for forceLoginMethod: "gateway" and forceLoginGatewayUrl in your own user settings on machines with no managed settings, so /login opens on that Claude apps gateway
