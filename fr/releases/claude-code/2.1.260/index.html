claude-code v2.1.260

Correctif Publié3 sept. 2026 Sourceanthropics/claude-code Anglais original

Cette page est traduite automatiquement. Le texte anglais original fait foi.

code-claude v2.1.260

Qu'est-ce qui a changé

  • Ajout d'un panneau de comparaison qui s'ouvre à côté de la conversation en mode plein écran et affiche vos modifications non validées au fur et à mesure que Claude les modifie ; basculez-le avec /diff
  • Ajout d'une cause probable d'échec du cache d'invite (par exemple, définitions d'outils ou invite système modifiées, inactivité au-delà du TTL) à /cost et au champ prompt_cache de la ligne d'état.
  • Ajout de /reload-plugins aux sessions sans tête, afin qu'il apparaisse dans les listes de commandes Claude Code Desktop et SDK
  • Ajout d'une forme texte de /advisor (/advisor, /advisor <model>, /advisor off) pour l'application de bureau, la télécommande et d'autres sessions sans tête (-p/Agent SDK)
  • Ajout de oidc.scope_on_refresh à la passerelle des applications Claude pour les IdP qui renvoient un id_token lors de l'actualisation uniquement lorsqu'on leur demande à nouveau openid
  • Ajout de la prise en charge de la passerelle des applications Claude pour les nouvelles clés Claude Desktop dans les blocs de stratégie desktop, notamment userPluginMarketplacesEnabled et userPluginUploadsEnabled.
  • Correction des règles d'autorisation Edit/Write/Read dont le chemin contient des parenthèses étant supprimées comme non valides ou ignorées par le bac à sable Bash, qui laissait les dossiers « en lecture seule » accessibles en écriture
  • Correction d'une règle d'autorisation de fichier avec un modèle non compilable (par exemple un [ non fermé) faisant échouer chaque modification de fichier avec Invalid regular expression ; une telle règle de refus protège désormais le chemin littéral qu'elle indique
  • Correction des autorisations Bash qui vérifient les commandes zsh d'approbation automatique qui masquent une substitution de commande dans une affectation REPORTTIME, REPORTMEMORY ou DIRSTACKSIZE ; ceux-ci demandent désormais approbation
  • Correction de l'échec de la découverte du modèle Bedrock, du comptage de jetons et des appels d'informations d'identification AWS SSO/STS avec « impossible d'obtenir le certificat de l'émetteur local » lorsque l'autorité de certification racine de l'entreprise se trouve uniquement dans le magasin de certificats du système d'exploitation.
  • Correction de permissions.blockReadsOutsideWorkingDirectories sur macOS masquant la configuration git de l'utilisateur du git sandbox et masquant la propre caisse d'un sous-agent isolé par un arbre de travail
  • Correction des paramètres gérés qui ne se chargeaient pas pour les utilisateurs claude.ai Enterprise/Team qui disposaient également d'une clé API restante d'un /login antérieur.
  • Correction de /status répertoriant un compte claude.ai connecté et une clé API configurée comme si les deux étaient en vigueur ; l'identifiant non utilisé est maintenant marqué
  • Correction des entrées skillOverrides gérées saisies sur l'alias d'une compétence groupée (par exemple checkup pour /doctor) ne s'appliquant pas, et les règles de refus Skill(name) ne couvrant pas une compétence imbriquée répertoriée comme <dir>:name
  • Correction des agents model: fable ignorant la balise [1m] sur une broche ANTHROPIC_DEFAULT_FABLE_MODEL et s'exécutant silencieusement avec une fenêtre contextuelle de 200 Ko
  • Correction du sélecteur /model n'affichant pas Fable 5.1 pour les organisations pouvant l'utiliser, ce qui n'était accepté que lorsqu'il était saisi sous la forme /model claude-fable-5-1.
  • Correction de la mise en cache des invites sur Claude Fable 5.1 ne couvrant pas le contexte attaché après les résultats de l'outil, elle était donc renvoyée en tant qu'entrée non mise en cache à chaque tour d'appel d'outil
  • Correction du changement de modèle restant bloqué pour le reste de la session après un échec de chargement du hook de plugin ; chaque interrupteur revérifie maintenant et le refus nomme la cause
  • Correction du changement de modèle bloqué pour la session lorsque le marché d'un plugin géré par l'organisation ne pouvait pas être chargé
  • Correction des serveurs MCP fournis par SDK (par exemple les connecteurs de bureau) parfois manquants dès le premier tour et n'apparaissant qu'au suivant
  • Correction de l'échec de Claude dans les outils Chrome avec la tâche "Non connecté" à mi-tâche dans les sessions claude.ai hébergées dans le cloud lorsqu'un connecteur était ajouté ou supprimé
  • Correction des drapeaux, des emoji joints et des lettres accentuées se répartissant sur des lignes enveloppées, et du texte obsolète restant à l'écran lorsqu'un drapeau ou un emoji joint tombe dans les deux dernières colonnes du terminal (maintenant affiché sous la forme …)
  • Correction de la télécommande acceptant un choix de modèle qui n'est pas un nom de modèle valide ; il est désormais refusé avec une erreur au lieu d'échouer au message suivant
  • Correction du succès des rapports /rewind et --rewind-files lorsque les fichiers de sauvegarde du point de contrôle étaient manquants et que rien n'était réellement restauré
  • Correction de /rewind laissant un suivi de lecture de fichier obsolète à partir des tours rembobinés, ce qui provoquait des talons "Fichier inchangé depuis la dernière lecture" et une réinjection de fichier complet après des modifications externes
  • Correction de l'échec de -p --resume/--continue (tel qu'utilisé par l'application de bureau) à chaque nouvelle tentative une fois que le répertoire worktree d'une session perdait ses métadonnées git ; il échoue maintenant une fois, puis reprend sans l'arbre de travail
  • Correction d'un sous-agent qui reprenait un autre agent via SendMessage sans jamais être réveillé par la fin de cet agent (la notification était plutôt envoyée à la conversation principale)
  • Correction des équipes d'agents : la transcription d'un coéquipier en cours perdait des messages, ou devenait vide, pendant de longues attentes de nouvelle tentative API (par exemple sous CLAUDE_CODE_RETRY_WATCHDOG) car les notifications de nouvelle tentative expulsaient les vrais messages
  • Correction d'une session qui passait en arrière-plan apparaissant deux fois dans ListAgents (une fois en tant que jumeau fantôme "interactif" portant le même nom) et recevant des diffusions SendMessage dans la visionneuse
  • Correction des erreurs intermittentes « échange de sortie de tâche refusé » lorsque plusieurs sessions partagent un répertoire de projet
  • Correction de Ctrl+Z en plein écran laissant le shell sur l'écran alternatif, dessiné sur l'interface en pause
  • Correction des sous-agents de l'outil Workflow redémarrés comme bloqués alors qu'un long compactage de contexte était toujours en cours
  • Correction des plugins d'une place de marché URL qui ne parvenaient pas à s'installer avec "le chemin d'entrée de la place de marché ne reste pas dans le répertoire de la place de marché" lorsqu'une application hôte (par exemple Claude Desktop) le stocke en tant que répertoire
  • Correction d'un onglet de navigateur supplémentaire qui s'ouvre lorsqu'un artefact est publié dans une session que vous conduisez depuis claude.ai, l'application de bureau ou mobile (télécommande)
  • Correction de l'échec du premier appel de l'outil Artifact avec une erreur de validation "Paramètres d'outil invalides" dans certaines sessions Cowork
  • Correction des sélections de lignes IDE étant supprimées lors de l'exécution d'une compétence ou d'une commande slash (le contexte "N lignes sélectionnées" atteint désormais Claude)
  • Correction de la détection du référentiel pour les projets GitLab dans des sous-groupes imbriqués (par exemple gitlab.com/group/subgroup/project)
  • Correction des références au problème owner/repo#123 dans la sortie rendue reliant à github.com lorsque vous travaillez dans un référentiel GitLab ; ils renvoient désormais au numéro gitlab.com
  • Glob/Grep : Correction du chemin de recherche sondé sur le disque avant la vérification des autorisations ; un chemin manquant est désormais signalé une fois l'autorisation décidée, comme le fait Read
  • Annulation du changement 2.1.259 en appliquant les règles de refus Read() aux arguments Bash ; il a refusé npm run build selon une règle Read(./**/build/**) dans tous les modes et a émis une invite cd … && grep même en mode automatique
  • Sortie structurée améliorée : le workflow agent({schema}) rejette un schéma JSON qui ne peut jamais être satisfait à l'avance, et les erreurs de nouvelle tentative incluent désormais le dernier échec de validation
  • Amélioration de la suppression d'une session en arrière-plan dont l'arbre de travail a des validations non poussées : le message nomme désormais la branche et le nombre de validations, et une nouvelle suppression supprime l'arbre de travail
  • Amélioration du journal des échecs d'actualisation de la passerelle des applications Claude pour nommer l'étape qui a échoué
  • Amélioration de l'utilisation du processeur inactif des sessions non interactives (-p / SDK)
  • Amélioration de la passerelle des applications Claude sur Amazon Bedrock : les jetons d'entrée pour une demande abandonnée sont désormais comptés avec les CountTokens gratuits API d'AWS (octroi bedrock:CountTokens) au lieu d'une demande à un jeton.
  • Amélioration de l'erreur de paramétrage pour des règles telles que Edit(C:\dir\(name)\**), où \( est lu comme une parenthèse d'échappement plutôt que comme un séparateur de chemin, pour suggérer une orthographe sans ambiguïté
  • Amélioration du compactage automatique pour les modèles de contexte 1 M : les sessions Opus et Fable se compactent désormais peu avant la limite de 1 M de jetons, et le compactage de récupération sur de très grands contextes n'expire plus au bout de 10 minutes.
  • Amélioration des /ultrareview et claude ultrareview pour attendre jusqu'à 45 minutes (au lieu de 30) pour les analyses cloud de longue durée
  • Amélioration de /effort sur Claude Fable 5.1 afin que le changement d'effort en cours de session n'invalide plus le cache d'invite
  • Mise à jour de la compétence claude-api fournie afin que ses exemples Go, Java et C# utilisent les ID de modèle de la génération actuelle, et clarification que les modèles de travailleurs ou de sous-agents moins chers devraient également être de la génération actuelle.
  • Modification de ctrl+l / cmd+k en mode plein écran pour effacer la vue de transcription comme un terminal clear ; faites défiler vers le haut pour voir les messages précédents
  • Modification des règles d'autorisation avec du texte après la parenthèse fermante (par exemple Bash(ls) x), qui ne correspondait jamais à rien, pour être signalées comme paramètres invalides au lieu d'être silencieusement ignorées
  • Modification des paramètres gérés par le serveur afin qu'un CLAUDE.md géré (claudeMd) ne déclenche plus la boîte de dialogue d'approbation de sécurité ; les hooks, les commandes shell, le bac à sable et les paramètres env non sécurisés nécessitent toujours une approbation
  • Modification de Claude dans Chrome pour suivre les paramètres d'administration Claude dans Chrome de votre organisation ; lorsqu'un administrateur le désactive, --chrome, /chrome et les outils du navigateur ne sont pas disponibles
  • Modification de la passerelle des applications Claude pour envoyer orgPluginSettings sous forme de liste lue par Claude Desktop 1.15200.0 et versions ultérieures ; les ordinateurs de bureau plus anciens l'ignorent
  • Modification de la passerelle des applications Claude pour refuser également de démarrer, en nommant le champ, lorsqu'une politique desktop orthographie mal un champ dans un objet imbriqué d'une entrée managedMcpServers ou orgPluginSettings
  • Modification des commandes saisies à l'invite du mode bash de ! pour qu'elles s'exécutent en dehors du bac à sable même lorsque le mode bac à sable strict (sandbox.allowUnsandboxedCommands: false) est activé, comme si vous tapiez dans votre propre terminal
  • Modification du programme d'exécution auto-hébergé --kill-session-after-min pour libérer une session qui n'attend que son utilisateur (en pause, reprise au prochain message) au lieu de la tuer et de signaler un échec
  • Suppression de la limite d'une heure pour les commandes en arrière-plan lancées par les sous-agents ; ils s'exécutent maintenant jusqu'à ce qu'ils quittent ou soient arrêtés, correspondant à la session principale
  • [VSCode] Ajout du niveau d'effort sélectionné à la pilule du modèle de pied de page, correction d'un niveau d'effort obsolète après avoir changé de modèle et retour des pilules de pied de page à leur taille compacte antérieure
  • [VSCode] Ajout d'Ouvert et Fermé au menu de filtre d'état de la liste de sessions
  • [VSCode] Correction de la disparition de l'écran d'accueil dans une nouvelle session lorsque la télécommande s'allume automatiquement
  • [VSCode] Correction du sélecteur d'historique de session chargeant une session une seconde fois alors qu'elle est déjà ouverte dans un autre onglet ; il passe maintenant à cet onglet
  • [VSCode] Correction de la commande Renommer de l'onglet de session qui ne faisait rien en silence pendant le rechargement de la vue de l'onglet ; ça s'applique toujours maintenant
  • [VSCode] Correction d'un message à moitié terminé, d'une carte outil vide ou d'une ligne supplémentaire "Pensée pour" restant à l'écran après que Claude Code ait réessayé une réponse abandonnée
  • [VSCode] Correction de "Activer le contrôle à distance pour toutes les sessions" ne s'appliquant pas à un onglet de session qui démarrait encore lorsque la bascule était activée

claude-code v2.1.260

What's changed

  • Added a diff panel that opens beside the conversation in fullscreen mode and shows your uncommitted changes as Claude edits; toggle it with /diff
  • Added a likely cause for prompt-cache misses (e.g. tool definitions or system prompt changed, idle past the TTL) to /cost and the status line's prompt_cache field
  • Added /reload-plugins to headless sessions, so it appears in the Claude Code Desktop and SDK command lists
  • Added a text form of /advisor (/advisor, /advisor <model>, /advisor off) for the desktop app, Remote Control, and other headless (-p/Agent SDK) sessions
  • Added oidc.scope_on_refresh to the Claude apps gateway for IdPs that return an id_token on refresh only when asked for openid again
  • Added Claude apps gateway support for newer Claude Desktop keys in desktop policy blocks, including userPluginMarketplacesEnabled and userPluginUploadsEnabled
  • Fixed Edit/Write/Read permission rules whose path contains parentheses being dropped as invalid or ignored by the Bash sandbox, which left "read-only" folders writable
  • Fixed one file permission rule with an uncompilable pattern (e.g. an unclosed [) making every file edit fail with Invalid regular expression; such a deny rule now guards the literal path it spells
  • Fixed Bash permission checks auto-approving zsh commands that hide a command substitution in a REPORTTIME, REPORTMEMORY or DIRSTACKSIZE assignment; these now prompt for approval
  • Fixed Bedrock model discovery, token counting and AWS SSO/STS credential calls failing with "unable to get local issuer certificate" when the corporate root CA is only in the OS certificate store
  • Fixed permissions.blockReadsOutsideWorkingDirectories on macOS hiding the user's git config from sandboxed git and hiding a worktree-isolated sub-agent's own checkout
  • Fixed managed settings not loading for claude.ai Enterprise/Team users who also had a leftover API key from an earlier /login
  • Fixed /status listing a signed-in claude.ai account and a configured API key as if both were in effect; the credential not in use is now marked
  • Fixed managed skillOverrides entries keyed on a bundled skill's alias (e.g. checkup for /doctor) not applying, and Skill(name) deny rules not covering a nested skill listed as <dir>:name
  • Fixed model: fable agents ignoring the [1m] tag on an ANTHROPIC_DEFAULT_FABLE_MODEL pin and silently running with a 200K context window
  • Fixed the /model picker not showing Fable 5.1 for organizations that can use it, which was only accepted when typed as /model claude-fable-5-1
  • Fixed prompt caching on Claude Fable 5.1 not covering the context attached after tool results, so it was re-sent as uncached input on every tool-call turn
  • Fixed model switching staying blocked for the rest of the session after a plugin hook load failure; each switch now re-checks and the refusal names the cause
  • Fixed model switching being blocked for the session when an organization-managed plugin's marketplace could not be loaded
  • Fixed SDK-provided MCP servers (e.g. Desktop connectors) sometimes missing from the first turn and only appearing on the next one
  • Fixed Claude in Chrome tools failing with "Not connected" mid-task in cloud-hosted claude.ai sessions when a connector was added or removed
  • Fixed flags, joined emoji and accented letters splitting across wrapped lines, and stale text staying on screen when a flag or joined emoji falls in the terminal's last two columns (now shown as …)
  • Fixed Remote Control accepting a model pick that is not a valid model name; it is now refused with an error instead of failing on the next message
  • Fixed /rewind and --rewind-files reporting success when checkpoint backup files were missing and nothing was actually restored
  • Fixed /rewind leaving stale file-read tracking from the rewound-away turns, which caused "File unchanged since last read" stubs and full-file re-injection after external edits
  • Fixed -p --resume/--continue (as used by the desktop app) failing on every retry once a session's worktree directory lost its git metadata; it now fails once, then resumes without the worktree
  • Fixed a subagent that resumed another agent via SendMessage never being woken by that agent's completion (the notification went to the main conversation instead)
  • Fixed agent teams: an in-process teammate's transcript losing messages, or going blank, during long API retry waits (e.g. under CLAUDE_CODE_RETRY_WATCHDOG) as retry notices evicted real messages
  • Fixed a session that moved to the background appearing twice in ListAgents (once as a phantom "interactive" twin with the same name) and receiving SendMessage deliveries in the viewer
  • Fixed intermittent "task output swap refused" errors when many sessions share a project directory
  • Fixed Ctrl+Z in fullscreen leaving the shell on the alternate screen, drawn over the paused interface
  • Fixed Workflow tool subagents being restarted as stalled while a long context compaction was still in progress
  • Fixed plugins from a URL marketplace failing to install with "marketplace entry path does not stay inside the marketplace directory" when a host app (e.g. Claude Desktop) stores it as a directory
  • Fixed an extra browser tab opening when an artifact is published in a session you're driving from claude.ai, the desktop app, or mobile (Remote Control)
  • Fixed the Artifact tool's first call failing with an "Invalid tool parameters" validation error in some Cowork sessions
  • Fixed IDE line selections being dropped when running a skill or slash command (the "N lines selected" context now reaches Claude)
  • Fixed repository detection for GitLab projects in nested subgroups (e.g. gitlab.com/group/subgroup/project)
  • Fixed owner/repo#123 issue references in rendered output linking to github.com when working in a GitLab repository; they now link to the gitlab.com issue
  • Glob/Grep: Fixed the search path being probed on disk before the permission check; a missing path is now reported after permission is decided, as Read does
  • Reverted the 2.1.259 change applying Read() deny rules to Bash arguments; it denied npm run build under a Read(./**/build/**) rule in every mode and made cd … && grep prompt even in auto mode
  • Improved structured output: Workflow agent({schema}) rejects a JSON Schema that can never be satisfied up front, and retry-cap errors now include the last validation failure
  • Improved deleting a background session whose worktree has unpushed commits: the message now names the branch and commit count, and deleting again discards the worktree
  • Improved the Claude apps gateway's refresh-failure log to name the step that failed
  • Improved idle CPU usage of non-interactive (-p / SDK) sessions
  • Improved the Claude apps gateway on Amazon Bedrock: input tokens for an aborted request are now counted with AWS's free CountTokens API (grant bedrock:CountTokens) instead of a one-token request
  • Improved the settings error for rules such as Edit(C:\dir\(name)\**), where \( is read as an escaped parenthesis rather than a path separator, to suggest an unambiguous spelling
  • Improved auto-compact for 1M-context models: Opus and Fable sessions now compact shortly before the 1M-token limit, and recovery compaction on very large contexts no longer times out at 10 minutes
  • Improved /ultrareview and claude ultrareview to wait up to 45 minutes (previously 30) for long-running cloud reviews
  • Improved /effort on Claude Fable 5.1 so changing effort mid-session no longer invalidates the prompt cache
  • Updated the bundled claude-api skill so its Go, Java, and C# samples use current-generation model IDs, and clarified that cheaper worker or sub-agent models should be current-generation too
  • Changed ctrl+l / cmd+k in fullscreen mode to clear the transcript view like a terminal clear; scroll up to see earlier messages
  • Changed permission rules with text after the closing parenthesis (e.g. Bash(ls) x), which never matched anything, to be reported as invalid settings instead of being silently ignored
  • Changed server-managed settings so a managed CLAUDE.md (claudeMd) no longer triggers the security approval dialog; hooks, shell-command, sandbox, and unsafe env settings still require approval
  • Changed Claude in Chrome to follow your organization's Claude in Chrome admin setting; when an admin turns it off, --chrome, /chrome and the browser tools are unavailable
  • Changed Claude apps gateway to send orgPluginSettings in the list form read by Claude Desktop 1.15200.0 and later; older desktops ignore it
  • Changed Claude apps gateway to also refuse to start, naming the field, when a desktop policy misspells a field in a nested object of a managedMcpServers or orgPluginSettings entry
  • Changed commands typed at the ! bash-mode prompt to run outside the sandbox even when strict sandbox mode (sandbox.allowUnsandboxedCommands: false) is on, like typing into your own terminal
  • Changed self-hosted runner --kill-session-after-min to release a session that is only waiting on its user (paused, resumable on the next message) instead of killing it and reporting a failure
  • Removed the one-hour time limit on background commands started by subagents; they now run until they exit or are stopped, matching the main session
  • [VSCode] Added the selected effort level to the footer model pill, fixed a stale effort level after switching models, and returned the footer pills to their earlier compact size
  • [VSCode] Added Open and Closed to the session list's status filter menu
  • [VSCode] Fixed the welcome screen disappearing in a new session when Remote Control turns on automatically
  • [VSCode] Fixed the session history picker loading a session a second time when it is already open in another tab; it now switches to that tab
  • [VSCode] Fixed the session tab's Rename command silently doing nothing while the tab's view was reloading; it now always applies
  • [VSCode] Fixed a half-finished message, an empty tool card or an extra "Thought for" line staying on screen after Claude Code retried a dropped response
  • [VSCode] Fixed "Enable Remote Control for all sessions" not applying to a session tab that was still starting when the toggle was flipped
