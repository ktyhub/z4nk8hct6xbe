code-claude v2.1.319

Qu'est-ce qui a changé

  • Modification du mode automatique avec désactivation des indicateurs de télémétrie ou de fonctionnalité, y compris derrière les passerelles LLM : les appels que le serveur ne peut pas vérifier sont interrogés ou refusés, sans recours au classificateur intégré ; configurez CLAUDE_CODE_AUTO_MODE_SERVER=0 pour continuer à l'utiliser (Bedrock, Vertex et Foundry sont inchangés)
  • Modification du mode automatique derrière une passerelle LLM : CLAUDE_CODE_AUTO_MODE_SERVER=1 active la vérification côté serveur même avec CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS défini ; si les paramètres gérés définissent ce dernier, ils doivent également définir le 1
  • Ajout du support des tâches MCP dans le terminal : lorsqu'un serveur MCP exécute un appel d'outil en tant que tâche, Claude Code le déplace immédiatement en arrière-plan et indique à Claude le résultat une fois terminé.
  • Ajout de la variable d'environnement CLAUDE_CODE_DISABLE_MCP_TASK_BACKGROUND pour que Claude Code attende une tâche MCP dans son appel d'outil au lieu de la déplacer immédiatement en arrière-plan
  • Ajout du paramètre permissions.denyInsteadOfPrompting : un appel d'outil qui attendrait une invite d'autorisation est refusé et le tour continue, dans les sessions de terminal, les sous-agents et les coéquipiers
  • Ajout de /claude-api latency-optimize pour trouver où votre code Claude API fait attendre les gens et essayer des réglages plus rapides par rapport à votre évaluation
  • Ajout de la variable d'environnement CLAUDE_CODE_DISABLE_FEATURE_FLAGS, qui arrête la récupération des indicateurs de fonctionnalités sans désactiver la télémétrie ; chaque drapeau utilise ensuite sa valeur par défaut intégrée
  • Ajout des dépenses pour aujourd'hui, cette semaine et ce mois-ci à /usage pour les développeurs derrière une passerelle d'applications Claude qui n'ont aucune limite de dépenses, lorsque la passerelle exécute cette version ou une version ultérieure.
  • Ajout de admin.pooled_conflict_rule et admin.pooled_priority_order à la passerelle des applications Claude, pour définir quel budget de groupe mutualisé paie en premier pour un développeur dans plusieurs groupes
  • Ajout d'un paramètre facultatif login_notice à la passerelle des applications Claude qui affiche un message défini par l'opérateur sur la page de vérification du navigateur de la passerelle et sur l'écran de connexion de Claude Code
  • Ajout de CLAUDE_GATEWAY_LOG_FORMAT=json à la passerelle des applications Claude : les lignes de log opérationnelles deviennent JSON avec severity, time et message, pour les collecteurs de logs qui lisent le niveau d'un champ
  • Ajout d'un avertissement de démarrage de la passerelle d'applications Claude pour le cas où le availableModels d'une autre stratégie autorise également un identifiant de modèle personnalisé qu'une stratégie répertorie par son nom.

  • Ajout d'un avertissement lorsque votre connexion claude.ai se termine et que Claude Code continue lors de la connexion depuis ant auth login, qui facture l'utilisation à votre organisation Claude Console
  • Ajout d'une ligne au démarrage nommant l'organisation Claude Console qui est facturée dans le cas où Claude Code utilise la connexion de ant auth login
  • Ajout d'une ligne "Plus tôt dans cette session" à /tasks qui répertorie les sous-agents terminés, afin que vous puissiez en rouvrir un et lui envoyer un message même après qu'il ait quitté la liste ou après avoir redémarré
  • Ajout d'une note aux confirmations /loop dans les sessions cloud qu'un timer s'arrête avec son conteneur, avec une offre d'une boucle qui survit
  • Correction des serveurs MCP sur l'ancienne poignée de main qui ne parvenaient pas à se connecter ou renvoyaient des résultats vides, car Claude Code avait déclaré une extension qu'il n'utilisait qu'avec des serveurs plus récents.

claude-code v2.1.319

What's changed

  • Changed auto mode with telemetry or feature flags off, including behind LLM gateways: calls the server can't check are asked about or denied, with no fallback to the built-in classifier; set CLAUDE_CODE_AUTO_MODE_SERVER=0 to keep using it (Bedrock, Vertex and Foundry are unchanged)
  • Changed auto mode behind an LLM gateway: CLAUDE_CODE_AUTO_MODE_SERVER=1 turns on the server-side check even with CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS set; if managed settings set the latter, they must set the 1 too
  • Added support for MCP tasks in the terminal: when an MCP server runs a tool call as a task, Claude Code moves it to the background right away and tells Claude the result when it finishes
  • Added the CLAUDE_CODE_DISABLE_MCP_TASK_BACKGROUND environment variable to make Claude Code wait for an MCP task inside its tool call instead of moving it to the background right away
  • Added permissions.denyInsteadOfPrompting setting: a tool call that would wait on a permission prompt is denied and the turn continues, in terminal sessions, subagents and teammates
  • Added /claude-api latency-optimize to find where your Claude API code makes people wait and try faster settings against your eval
  • Added the CLAUDE_CODE_DISABLE_FEATURE_FLAGS environment variable, which stops feature-flag fetching without turning off telemetry; every flag then uses its built-in default
  • Added spend for today, this week and this month to /usage for developers behind a Claude apps gateway who have no spend limit, when the gateway runs this version or later
  • Added admin.pooled_conflict_rule and admin.pooled_priority_order to the Claude apps gateway, to set which pooled group budget pays first for a developer in several groups
  • Added an optional login_notice setting to the Claude apps gateway that shows an operator-defined message on the gateway's browser verification page and on Claude Code's sign-in screen
  • Added CLAUDE_GATEWAY_LOG_FORMAT=json to the Claude apps gateway: operational log lines become JSON with severity, time and message, for log collectors that read the level from a field
  • Added a Claude apps gateway boot warning for a case where another policy's availableModels also allows a custom model id that one policy lists by name
  • Added start-up warnings to the Claude apps gateway for policies with no desktopHome that rely on coworkTabEnabled: false or chatSessionRetentionDays, ahead of Claude Desktop's November 10 change

  • Fixed /status showing "Auto mode server: Enabled" when the server-side review isn't reaching the session, for example behind an LLM gateway that drops it
  • Fixed Claude-drafted feedback, surveys and /feedback continuing to appear after the server refused feedback for your organization
  • Fixed Claude drafting feedback on third-party gateways, where it can't be sent
  • Fixed auto mode refusing actions without saying why when permission rules or autoMode settings are very large: it now explains and, unless autoMode deny rules are set, asks you in the terminal
