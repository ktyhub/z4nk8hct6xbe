claude-code v2.1.232

code-claude v2.1.232

Qu'est-ce qui a changé

  • La création de sous-agents est désormais activée par défaut : un sous-agent subagent_type: "fork" hérite de la conversation complète et du cache d'invites, et les agents non-coéquipiers apparaissent dans les sessions interactives désormais exécutées en arrière-plan par défaut.
  • Tapez @ dans l'invite pour mentionner une autre session Claude par son nom ; Claude utilise ensuite SendMessage pour accéder directement à cette session
  • SendMessage livre désormais à un simple nom qui correspond exactement à une session en direct, au lieu de demander d'abord une confirmation auprès d'une référence.
  • Les sessions interactives sur une machine conservent désormais des noms uniques : démarrer ou renommer une session avec un nom qu'une autre session en direct utilise déjà lui donne une variante name-word-word et vous l'indique
  • Ajout de lignes /config pour « Expiration de la boîte de dialogue » et « Messages de vos autres sessions » (acceptation/maintien/refus entrant inter-sessions)
  • Ajout de la rédaction secrète pour les familles de jetons GitLab (glrt-, gloas-, glptt-, glagent-, glimt-, glsoat-, glcbt-, glft-, glffct-) et rédaction complète des jetons routables glpat-/gldt- ; le magasin de configuration glab CLI bénéficie du même bac à sable et de la même protection du chemin d'accès aux informations d'identification que gh
  • Ajout de la prise en charge de GitLab aux marchés de plugins : les URL de dépôt gitlab.com nues (y compris les sous-groupes imbriqués) sont désormais clonées comme les URL github.com et les conseils d'échec d'authentification de clonage nomment votre hôte git actuel.
  • Paramètres : additionalMarketplaces et allowedMarketplaces sont désormais acceptés comme alias plus conviviaux pour extraKnownMarketplaces et strictKnownMarketplaces
  • Politique d'entreprise : une entrée blockedMarketplaces saisie par URL pour une URL de dépôt nue continue de bloquer cette URL lorsque le CLI la classe comme clone git
  • Passerelle : la superposition desktop: accepte désormais tous les paramètres du bureau publiés (au lieu de 11 clés répertoriées manuellement), validés au démarrage par rapport au propre schéma du bureau ; Les clés inconnues ou invalides échouent au démarrage
  • Passerelle : les entrées managed.policies[].match.groups/admin.admin_groups vides et les valeurs email_domain mal formées (vides ou contenant @, des espaces ou des virgules) échouent désormais au démarrage au lieu de ne correspondre silencieusement à personne ou d'accorder un accès administrateur.
  • Fable 5 est à nouveau proposé en tant que conseiller dans /advisor pour les organisations disposant d'un accès à Fable, avec un consentement aux crédits d'utilisation configuré via /model fable.
  • Correction d'un contournement d'autorisation PowerShell où les paramètres d'écriture de variables pouvaient écraser silencieusement $PSDefaultParameterValues et rediriger l'accès aux fichiers des commandes ultérieures
  • Correction d'un contournement des autorisations Windows où Git Bash suivait des liens symboliques de style Cygwin que la validation du chemin considérait comme des fichiers normaux ; les écrits à travers eux nécessitent désormais une autorisation
  • Correction des référentiels git imbriqués héritant du trust d'un répertoire parent ; chaque référentiel nécessite désormais sa propre confirmation trust
  • Correction des connexions MCP suspendues pendant le délai d'expiration complet de 30 secondes lorsqu'un serveur ne parvient pas à répondre ou envoie une réponse mal formée à la sonde de version du protocole.
  • Correction des sessions de contrôle à distance hébergées par un pont dans une session cloud héritant de la transcription ou des informations d'identification de cette session
  • Correction des sessions de contrôle à distance démarrées depuis Claude Desktop ou un IDE apparaissant comme une nouvelle session claude.ai à chaque reprise de la session locale ; ils se rattachent maintenant à celui existant
  • Correction des sessions de contrôle à distance apparaissant inaccessibles aux clients nouvellement connectés lorsqu'ils sont inactifs
  • Correction des sessions de pont de contrôle à distance ne restaurant pas l'historique des conversations lorsque le travailleur de session redémarre
  • Contrôle à distance : reprise d'une conversation dont la session a été supprimée de claude.ai ou l'application démarre désormais un remplacement au lieu d'échouer avec un message concernant votre login (régressé dans v2.1.227)
  • Correction de la passerelle Cloud /login qui se quittait silencieusement ou quittait un terminal qui ne répondait pas après « Appuyez sur Entrée pour continuer » lorsque le chargement des paramètres gérés échouait ; la raison est maintenant indiquée
  • Correction du mode vocal sur les versions natives qui restait bloqué sur « écoute… » lorsque le service vocal rejetait la connexion ; le rejet est maintenant affiché immédiatement
  • Correction de la rotation des certificats mTLS client nécessitant un redémarrage ; Claude Code recharge désormais automatiquement le certificat et la clé pivotés en cas d'erreur de connexion
  • Correction des valeurs de région AWS ou Vertex mal formées utilisées pour créer des URL de requête ; ils reviennent maintenant à la région par défaut
  • Correction d'erreurs de délai d'inactivité du flux faisant échouer la demande au lieu de récupérer sur les déploiements Bedrock, Vertex et Gateway.
  • Correction des superpositions de taille de contenu contenant du texte tronqué rendant une colonne trop large et le texte tronqué de départ se réduisant en points de suspension
  • Correction d'un personnage égaré où un long aperçu de la commande shell ou de la description de l'agent était coupé au milieu de l'emoji.
  • Correction d'une course au démarrage qui pouvait désenregistrer silencieusement un marché de plugins en raison d'écritures simultanées sur known_marketplaces.json
  • Correction de /update et /tui refusant de redémarrer pendant que le travail qui survit à la relance était en cours
  • Correction des conseils de limite d'utilisation suggérant des commandes slash indisponibles dans SDK et les sessions à distance
  • Correction du message de consentement pour les lancements interactifs de --advisor fable, qui vous demandait d'exécuter /model fable dans une session interactive qui venait de se terminer
  • Streaming plein écran amélioré : les longues sessions restent réactives car l'ensemble de la conversation n'est plus renormalisé à chaque mise à jour
  • Amélioration de la boîte de dialogue d'approbation des paramètres gérés : affiche les URL des points de terminaison, utilise une formulation plus claire pour les modifications de télémétrie uniquement, ignore les options de routine OpenTelemetry et nécessite l'approbation pour les remplacements binaires du bac à sable gérés par le serveur (sandbox.bwrapPath, sandbox.socatPath, sandbox.ripgrep)
  • /feedback et /bug s'ouvrent désormais immédiatement lorsqu'ils sont invoqués pendant que Claude répond, au lieu d'attendre la fin du tour
  • /plugin install plugin@marketplace actualise désormais d'abord la place de marché, donc les plugins nouvellement publiés s'installent sans mise à jour manuelle de la place de marché.
  • /code-review avec effort élevé, xélevé et maximum s'exécute désormais dans un agent en arrière-plan comme les autres niveaux
  • Les images collées et clipboard sont lues sans bloquer la boucle d'événements
  • La télécommande continue désormais de se reconnecter pendant environ 30 minutes après un incident réseau et ne s'arrête plus après quelques incidents répartis sur une heure.
  • Télécommande : la reprise d'une conversation ne retire plus silencieusement la télécommande à un autre Claude Code sur la même machine qui le possède encore ; exécutez /remote-control là-bas pour le déplacer
  • Panneau d'agent mis à jour : les sous-agents terminés se cachent immédiatement avec un indice de pied de page /tasks et l'indicateur de débordement "↓ N plus" déplacé vers la gauche pour plus de visibilité.
  • Contrôle à distance : le terminal indique désormais si une session a été reprise par un autre appareil, terminée depuis une autre application ou supprimée, et cesse de suggérer une reconnexion qui l'annulerait
  • Les redirections d'entrée Bash (< file) sont désormais vérifiées comme l'orthographe de leurs arguments sur toutes les plateformes.
  • Raccourci le message affiché lors de la reprise d'un agent en arrière-plan terminé
  • Les sessions de cowork n'intègrent plus les @-importations externes à partir de fichiers de mémoire au niveau utilisateur
  • Renforcement du répertoire de socket de messagerie inter-session généré automatiquement sur le /tmp partagé : un lien symbolique pré-implanté ou le répertoire d'un autre utilisateur est désormais refusé au lieu d'être utilisé
  • Renforcement du sandbox du système de fichiers Linux contre un contournement de chemin protégé
  • Modification du sandbox.ripgrep pour qu'il soit honoré uniquement à partir des paramètres utilisateur, gérés et --settings ; les paramètres du projet ne peuvent plus remplacer le binaire ripgrep du bac à sable
  • Suppression de l'astuce de démarrage vous suggérant de créer des sous-agents personnalisés et du coup de pouce correspondant dans la visite guidée /powerup

claude-code v2.1.232

What's changed

  • Subagent forking is now on by default: a subagent_type: "fork" subagent inherits the full conversation and prompt cache, and non-teammate agent spawns in interactive sessions now run in the background by default
  • Type @ in the prompt to mention another Claude session by name; Claude then uses SendMessage to reach that session directly
  • SendMessage now delivers to a bare name that exactly matches one live session, instead of asking to confirm with a ref first
  • Interactive sessions on one machine now keep unique names: starting or renaming a session to a name another live session already uses gives it a name-word-word variant and tells you
  • Added /config rows for "Dialog expiry" and "Messages from your other sessions" (cross-session inbound accept/hold/refuse)
  • Added secret redaction for GitLab token families (glrt-, gloas-, glptt-, glagent-, glimt-, glsoat-, glcbt-, glft-, glffct-) and full redaction of routable glpat-/gldt- tokens; the glab CLI config store gets the same sandbox and credential-path protection as gh
  • Added GitLab support to plugin marketplaces: bare gitlab.com repo URLs (including nested subgroups) now clone like github.com URLs, and clone auth-failure hints name your actual git host
  • Settings: additionalMarketplaces and allowedMarketplaces are now accepted as friendlier aliases for extraKnownMarketplaces and strictKnownMarketplaces
  • Enterprise policy: a url-typed blockedMarketplaces entry for a bare repo URL keeps blocking that URL when the CLI classifies it as a git clone
  • Gateway: the desktop: overlay now accepts every released Desktop setting (was 11 hand-listed keys), validated at boot against Desktop's own schema; unknown or invalid keys fail boot
  • Gateway: empty managed.policies[].match.groups/admin.admin_groups entries and malformed email_domain values (empty, or containing @, whitespace, or commas) now fail at boot instead of silently matching no one or granting admin access
  • Fable 5 is offered as an advisor in /advisor again for organizations with Fable access, with usage-credits consent set up through /model fable
  • Fixed a PowerShell permission bypass where variable-writing parameters could silently overwrite $PSDefaultParameterValues and redirect later commands' file access
  • Fixed a Windows permission bypass where Git Bash followed Cygwin-style symlinks that path validation saw as regular files; writes through them now require permission approval
  • Fixed nested git repositories inheriting trust from a parent directory; each repository now requires its own trust confirmation
  • Fixed MCP connections hanging for the full 30-second connect timeout when a server fails to answer or sends a malformed reply to the protocol-version probe
  • Fixed Remote Control sessions hosted by a bridge inside a cloud session inheriting that session's transcript or credentials
  • Fixed Remote Control sessions started from Claude Desktop or an IDE appearing as a new claude.ai session each time the local session was resumed; they now reattach to the existing one
  • Fixed Remote Control sessions appearing unreachable to newly attached clients while idle
  • Fixed Remote Control bridge sessions not restoring conversation history when the session worker restarts
  • Remote Control: resuming a conversation whose session was deleted from claude.ai or the app now starts a replacement instead of failing with a message about your login (regressed in v2.1.227)
  • Fixed Cloud gateway /login exiting silently or leaving an unresponsive terminal after "Press Enter to continue" when managed settings failed to load; the reason is now shown
  • Fixed voice mode on native builds getting stuck on "listening…" when the voice service rejected the connection; the rejection is now shown immediately
  • Fixed mTLS client certificate rotation requiring a restart; Claude Code now reloads the rotated cert and key automatically on connection errors
  • Fixed malformed AWS or Vertex region values being used to build request URLs; they now fall back to the default region
  • Fixed stream idle timeout errors failing the request instead of recovering on Bedrock, Vertex, and gateway deployments
  • Fixed content-sized overlays containing truncated text rendering one column too wide, and start-truncated text collapsing to an ellipsis
  • Fixed a stray garbled character where a long shell-command or agent-description preview was cut off mid-emoji
  • Fixed a startup race that could silently unregister a plugin marketplace due to concurrent writes to known_marketplaces.json
  • Fixed /update and /tui refusing to restart while work that survives the relaunch was running
  • Fixed usage-limit guidance suggesting unavailable slash commands in SDK and remote sessions
  • Fixed the consent message for interactive --advisor fable launches, which told you to run /model fable in an interactive session that had just exited
  • Improved fullscreen streaming: long sessions stay responsive because the whole conversation is no longer re-normalized on every update
  • Improved the managed settings approval dialog: shows endpoint URLs, uses clearer wording for telemetry-only changes, skips routine OpenTelemetry options, and requires approval for server-managed sandbox binary overrides (sandbox.bwrapPath, sandbox.socatPath, sandbox.ripgrep)
  • /feedback and /bug now open immediately when invoked while Claude is responding, instead of waiting for the turn to finish
  • /plugin install plugin@marketplace now refreshes the marketplace first, so newly published plugins install without a manual marketplace update
  • /code-review at high, xhigh, and max effort now runs in a background agent like the other levels
  • Pasted and clipboard images are read without blocking the event loop
  • Remote Control now keeps reconnecting for about 30 minutes after a network blip and no longer drops after a few blips spread across an hour
  • Remote Control: resuming a conversation no longer silently takes Remote Control away from another Claude Code on the same machine that still has it; run /remote-control there to move it
  • Updated agent panel: completed subagents hide immediately with a /tasks footer hint, and the "↓ N more" overflow indicator moved left for visibility
  • Remote Control: the terminal now says whether a session was taken over by another device, ended from another app, or deleted, and stops suggesting a reconnect that would undo it
  • Bash input redirections (< file) are now permission-checked like their argument spellings on all platforms
  • Shortened the message shown when resuming a completed background agent
  • Cowork sessions no longer inline external @-imports from user-scope memory files
  • Hardened the auto-generated cross-session messaging socket directory on shared /tmp: a pre-planted symlink or another user's directory is now refused instead of used
  • Hardened the Linux filesystem sandbox against a protected-path bypass
  • Changed sandbox.ripgrep to be honored only from user, managed, and --settings settings; project settings can no longer override the sandbox's ripgrep binary
  • Removed the startup tip suggesting you create custom subagents, and the matching nudge in the /powerup tour
