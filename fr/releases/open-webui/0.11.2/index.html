open-webui v0.11.2

Ajouté

  • 🖼️ Aperçus plus riches pour les fichiers du terminal. Les documents Word et les diaporamas produits dans le terminal sont désormais prévisualisés comme le document fini plutôt que comme une approximation, et chaque aperçu de document gagne une bande de page sur le côté avec des vignettes numérotées que vous pouvez click pour accéder directement à une page, et l'avis avertissant qu'un aperçu peut différer du téléchargement a disparu maintenant que ce n'est plus le cas. Commit, Commit, Commit, Commit, Commit
  • ⚡ Moins de surcharge sur chaque message. Les déploiements sans pipelines configurés, ce qui est la valeur par défaut, ne paient plus de travail de configuration pour chaque message de discussion et tâche en arrière-plan. #29146
  • 🏎️ Actualisations plus légères de la liste de modèles. Sur les déploiements exécutant plusieurs Workers, une actualisation qui trouve la liste de modèles inchangée n'oblige plus chaque Worker à réécrire la liste entière dans le cache partagé, réduisant ainsi le travail et le trafic que coûtent chaque actualisation. #29264
  • 🧵 Serveurs Websocket occupés plus fluides. Les grands déploiements de websocket soutenus par Redis passent désormais beaucoup moins de temps à balayer les anciennes sessions, à lire leurs propres données de session à partir de Redis et à vérifier chaque message Websocket sortant pour les pièces jointes qu'Open WebUI n'envoie pas, donc les publications de canal, les mises à jour de collaboration, les battements de cœur et les mises à jour de chat en direct mettent moins de charge sur les serveurs occupés. #28835, #28180
  • 🧰 Une nouvelle étape de filtrage des requêtes. Les auteurs de filtres peuvent désormais utiliser request pour ajuster la charge utile juste avant chaque appel de modèle, y compris les appels de suivi après l'utilisation de l'outil, tandis que les filtres inlet, stream et outlet existants continuent de fonctionner comme avant. Commettre, Commettre
  • 🤏 Plus de place dans les aperçus de fichiers sur les écrans tactiles. Les aperçus de fichiers sur les téléphones et les tablettes n'affichent plus les boutons de zoom qui se trouvent au-dessus d'un aperçu déjà petit, laissant le pincement pour zoomer faire le travail. #29176, #29152
  • 👆 Redimensionnement des panneaux au toucher. Le séparateur à côté de la barre latérale principale ou d'un panneau latéral peut désormais être déplacé sur un écran tactile ou avec un stylet, et un déplacement effectué avec la souris continue de suivre le pointeur lorsqu'il quitte la fenêtre. Commettre, Commettre, Commettre
  • 🔤 Choix de la police d'interface. Les paramètres d'interface offrent désormais un champ de famille de polices dans lequel vous pouvez nommer une police installée sur votre ordinateur et la regarder s'appliquer sur l'interface pendant que vous tapez, avec un champ vide revenant à la police standard. Commettre
  • ♿ Couverture plus large du mode d'accessibilité. Le mode d'accessibilité augmente désormais le contraste d'une plus grande partie de l'interface, y compris le texte en sourdine, le texte des tableaux, les icônes, les éléments de couleur qui changent en survol et la surbrillance derrière la barre latérale et les éléments de menu que vous pointez, de sorte que les zones à faible contraste répondent au niveau demandé par les directives d'accessibilité dans les thèmes clairs et sombres, et le bouton de fermeture de la boîte de dialogue du dossier s'annonce désormais aux lecteurs d'écran, tout comme les aperçus de documents et de diapositives, qui peuvent désormais être atteints avec le clavier. Commit, Commit, #29160, Commit, Commit
  • 🌐 Mises à jour des traductions. Les traductions en polonais, chinois simplifié, allemand, irlandais, catalan et portugais (Brésil) ont été étendues, corrigées et mises à jour avec un texte d'interface plus récent. #29029, #29043, #29108, #29151, #29184, #29179, #29247, #29217

Corrigé

  • 🛡️ Avis de sécurité : cette version inclut des correctifs de sécurité et de contrôle d'accès. Nous vous recommandons de mettre à jour les déploiements de production dès que possible. Tous les correctifs de sécurité de cette version ne peuvent pas être énumérés dans la section corrigée. Certains peuvent être suspendus pendant une courte période pour donner aux administrateurs le temps de procéder à la mise à niveau. Avis
  • 💥 Les réponses cessent de s'interrompre en cours de discussion. Une conversation n'échoue plus dans le navigateur et cesse d'afficher la réponse de l'assistant jusqu'à ce que vous rechargez, et les discussions déjà enregistrées dans cet état s'affichent et peuvent être à nouveau modifiées. #29250, #29244
  • ⌨️ Les raccourcis d'aperçu restent dans l'aperçu. Les touches fléchées affichent désormais un aperçu d'un document ou d'une diapositive uniquement lorsque cet aperçu a le focus, au lieu de le paginer depuis n'importe où sur la page et de retirer les touches fléchées de ce que vous étiez en train de saisir. Commit, Commit
  • 🧊 Le streaming ne s'arrête plus sur les modèles de raisonnement. Une réponse d'un modèle de raisonnement est désormais diffusée jusqu'à la fin au lieu d'afficher ses premiers mots, puis de se figer jusqu'à la fin de la génération. #29053, #29035
  • 💭 La réflexion reste dans les pensées. Après qu'un modèle utilise un outil, son raisonnement pour l'étape suivante apparaît désormais dans la section Pensées réduite au lieu d'être écrit dans la réponse sous forme de texte ordinaire. #29052, #29040
  • 🧠 Les appels d'outils volumineux sont diffusés plus rapidement via clients compatibles Anthropic. Lorsqu'un appel d'outil diffusé en continu envoie un gros bloc d'arguments, Open WebUI attend désormais que ce bloc puisse réellement être terminé avant de le vérifier, au lieu de refaire la même vérification coûteuse sur chaque petit morceau. #28858
  • 🛑 L'arrêt fonctionne sur plusieurs instances. L'arrêt d'une réponse prend désormais effet sur les déploiements qui répartissent les personnes sur plusieurs instances soutenues par un cluster Redis, au lieu que la réponse continue malgré tout jusqu'à la fin. #29165, #19840
  • 🎯 Moins de rechargements inutiles du chat. Une conversation contenant une ancienne réponse inachevée ne se recharge plus à chaque fois qu'une autre réponse se termine, se rechargeant uniquement pour la réponse réellement concernée par la mise à jour. S'engager
  • 📖 Bannières avec texte souligné. Une bannière contenant du texte souligné s'affiche désormais au lieu d'échouer le rendu. #29118, #29115
  • 🧰 Les modèles épinglés commencent avec leurs propres outils. Démarrer une discussion à partir d'un modèle épinglé dans la barre latérale applique désormais les outils et les compétences de ce modèle au lieu de transférer ceux du modèle que vous avez utilisé en dernier. #29058, #29050
  • ❓ Les appels Ask_user rejetés ne tuent plus la réponse. Si un modèle pose une question à l'utilisateur d'une manière qu'Open WebUI refuse, le modèle reçoit désormais cette erreur et peut continuer ou réessayer, au lieu de laisser le chat arrêté sans réponse. #29252, #29077
  • 🚫 Les modèles désactivés ne disparaissent plus. La désactivation d'un modèle dans la liste des modèles de l'administrateur le maintient désormais en vue afin que vous puissiez le rallumer, au lieu de le faire disparaître sans aucun moyen de le récupérer. #29037, #29036
  • ✂️ Texte du message conservé intact. Le texte contenant des crochets angulaires et un signe dollar n'est plus confondu avec une mention de compétence et supprimé silencieusement avant que votre message n'atteigne le modèle. #29051, #29041
  • 📆 Les événements du calendrier déplacés restent visibles. La modification de la date d'un événement ne le fait plus disparaître du calendrier, et les événements déjà bloqués dans cet état réapparaissent. #29085, #29067
  • 🔁 Les répétitions suivent l'événement. Un événement répétitif calcule désormais ses occurrences à partir de sa propre date et heure, alors qu'une règle de répétition portant sa propre date de début pourrait les placer au mauvais jour de la semaine ou à la mauvaise heure. Commettre
  • 🔟 Les automatisations répétitives conservent leur décompte. Une automatisation configurée pour s'exécuter un nombre fixe de fois n'est plus affichée comme étant exécutée une seule fois et réécrite silencieusement en une seule exécution la prochaine fois que vous l'ouvrirez et l'enregistrerez. #29261, #29263
  • 🗓️ Les plannings survivent à une sauvegarde. Une automatisation portant une date de début affiche désormais son planning réel dans la liste et conserve son paramètre hebdomadaire ou mensuel une fois enregistrée, au lieu d'afficher le texte brut de la règle et de revenir au quotidien. #29263
  • 🧩 Les plannings d'automatisation personnalisés restent personnalisés. La réouverture d'une automatisation avec une règle de répétition personnalisée ne fait plus perdre la règle personnalisée de l'éditeur. #29260
  • 🔢 Nombre précis d'utilisateurs administrateurs. Les décomptes dans les onglets Utilisateurs administrateurs suivent désormais votre recherche et se réinitialisent lorsque vous changez d'onglet, au lieu d'afficher des numéros obsolètes ou non filtrés. #29080, #29079
  • 🧷 Les dossiers de la barre latérale cessent d'être obsolètes. Un dossier qui a été supprimé de la barre latérale est désormais également supprimé du registre interne de la barre latérale, de sorte que les actions ultérieures de la barre latérale ne ciblent pas un dossier qui n'est plus à l'écran. #29121
  • 📱 Liste des modèles lisible sur les petits écrans. L'identifiant du modèle et l'horodatage dans la liste des modèles de l'espace de travail ne chevauchent plus le nom du modèle sur les écrans étroits. #29084, #29083
  • 🧱 Les valeurs de paramètre longues arrêtent d'écraser les étiquettes. Les lignes de paramètres permettent désormais aux contrôles longs de se rétrécir dans l'espace disponible au lieu de presser l'étiquette à côté d'eux. #29229
  • 🧭 Les panneaux des valeurs par défaut du modèle restent utilisables. Les capacités du modèle et les sections de suggestions d'invite dans les paramètres d'administration défilent désormais à l'intérieur de leurs panneaux au lieu de dépasser l'espace disponible. #29235
  • 📲 Les listes déroulantes restent à l'écran. Une liste déroulante située près du bord d'un écran étroit se déplace désormais vers l'intérieur pour rester entièrement visible au lieu de s'ouvrir au-delà du bord avec ses étiquettes d'options coupées. #29226, #29225
  • 🌗 Les listes déroulantes suivent le thème. La liste qu'une liste déroulante ouvre prend désormais sa couleur claire ou foncée du reste de l'interface au lieu de la couleur par défaut du système. S'engager
  • 🎛️ La boîte de dialogue Valves reste dans les limites. Une valve dont les options sélectionnées forment une longue ligne n'étend plus son entrée au-delà du bord de la boîte de dialogue et sur la page derrière elle. #29203, #29202
  • 🧹 La recherche des discussions partagées est réinitialisée. La réouverture de la boîte de dialogue des discussions partagées commence désormais avec un champ de recherche vide et la liste complète, plutôt qu'un terme de recherche restant au-dessus des résultats non filtrés. #29082, #29081
  • 🔎 Recherche insensible à la casse au-delà de l'anglais. La recherche et le filtrage par balise ignorent désormais la casse des lettres pour le texte accentué et non latin sur les installations prises en charge par SQLite, où seules les lettres anglaises non accentuées étaient mises en correspondance, quelle que soit leur casse. Commettre
  • 🏷️ Les étiquettes avec deux-points et exemples d'URL se traduisent correctement. Le texte de l'interface tel que Warning:, http://localhost:8000 et https://mineru.net/api/v4 apparaît désormais correctement au lieu d'être mal lu par le système de traduction. #29161, #29154
  • 🔑 Correspondance précise des comptes sur SQLite. La connexion via un fournisseur d'identité fait désormais correspondre votre compte sur son identifiant exact, de sorte que les comptes dont l'identifiant est un nombre inhabituellement long ou sans zéro ne risquent plus d'être confondus avec un autre. Commettre
  • 🗃️ La liste des connaissances se charge de manière fiable. La page Connaissances de l'espace de travail remplit désormais sa liste à l'ouverture au lieu de rester occasionnellement vide. Commettre
  • 🎟️ Serveurs d'outils sans clé. Une connexion au serveur d'outils enregistrée sans clé ne reçoit plus d'en-tête d'autorisation vide, ce que certains serveurs refusaient catégoriquement. Commettre
  • 🐍 L'interpréteur de code démarre sous Windows. L'interpréteur de code intégré sert désormais ses fichiers de script et WebAssembly avec les types de fichiers sécurisés pour le navigateur que les hôtes Windows écrasent parfois, afin que Pyodide puisse se charger au lieu d'échouer avant l'exécution du code. #29139, #29133

Modifié

  • ⏱️ Limite quotidienne de répétitions. Un événement de calendrier ne peut plus être configuré pour se répéter plus d'une fois par jour, et l'enregistrement d'un événement qui se répète plus souvent est désormais refusé avec un message expliquant la limite. S'engager
  • 🏷️ Le mode contraste élevé est désormais le mode accessibilité. Le paramètre d'interface précédemment appelé « Mode contraste élevé » s'appelle désormais « Mode accessibilité », avec le même commutateur au même endroit. Commettre

open-webui v0.11.2

Added

  • 🖼️ Richer previews for terminal files. Word documents and slide decks produced in the terminal are now previewed as the finished document rather than an approximation, and every document preview gains a page strip down the side with numbered thumbnails you can click to jump straight to a page, and the notice warning that a preview might differ from the download is gone now that it does not. Commit, Commit, Commit, Commit, Commit
  • ⚡ Less overhead on every message. Deployments without pipelines configured, which is the default, no longer pay setup work for them on each chat message and background task. #29146
  • 🏎️ Lighter model list refreshes. On deployments running several workers, a refresh that finds the model list unchanged no longer has every worker rewrite the whole list to the shared cache, cutting the work and the traffic each refresh costs. #29264
  • 🧵 Smoother busy websocket servers. Large Redis-backed websocket deployments now spend far less time sweeping old sessions, reading their own session data back from Redis, and checking every outgoing websocket message for file attachments Open WebUI does not send, so channel posts, collaboration updates, heartbeats, and live chat updates put less load on busy servers. #28835, #28180
  • 🧰 A new request filter step. Filter authors can now use request to adjust the payload right before each model call, including follow-up calls after tool use, while existing inlet, stream, and outlet filters keep working as before. Commit, Commit
  • 🤏 More room in file previews on touch screens. File previews on phones and tablets no longer show zoom buttons that sit over an already small preview, leaving pinch to zoom to do the job. #29176, #29152
  • 👆 Resizing panels by touch. The divider beside the main sidebar or a side panel can now be dragged on a touchscreen or with a stylus, and a drag made with the mouse keeps following the pointer when it leaves the window. Commit, Commit, Commit
  • 🔤 Choice of interface font. Interface settings now offer a font family field where you can name a font installed on your computer and watch it apply across the interface as you type, with an empty field returning to the standard font. Commit
  • ♿ Wider accessibility mode coverage. Accessibility mode now lifts the contrast of more of the interface, including muted text, table text, icons, the colours elements change to on hover, and the highlight behind sidebar and menu items you point at, so low-contrast areas meet the level the accessibility guidelines ask for in both light and dark themes, and the close button on the folder dialog now announces itself to screen readers, as do document and slide previews, which can now be reached with the keyboard. Commit, Commit, #29160, Commit, Commit
  • 🌐 Translation updates. Polish, Simplified Chinese, German, Irish, Catalan, and Portuguese (Brazil) translations were expanded, corrected, and brought up to date with newer interface text. #29029, #29043, #29108, #29151, #29184, #29179, #29247, #29217

Fixed

  • 🛡️ Security Advisory: This release includes security and access-control fixes. We recommend updating production deployments at your earliest convenience. Not all security fixes in this version may be enumerated in the fixed section. Some may be withheld for a short time to give administrators time to upgrade. Advisories
  • 💥 Replies stop breaking mid-chat. A conversation no longer fails in the browser and stops showing the assistant reply until you reload, and chats already saved in that state display and can be edited again. #29250, #29244
  • ⌨️ Preview shortcuts stay in the preview. Arrow keys now page a document or slide preview only while that preview has focus, instead of paging it from anywhere on the page and taking the arrow keys away from whatever you were typing in. Commit, Commit
  • 🧊 Streaming no longer stalls on reasoning models. A reply from a reasoning model now streams through to the end instead of showing its first few words and then freezing until generation finishes. #29053, #29035
  • 💭 Thinking stays in Thoughts. After a model uses a tool, its reasoning for the next step now appears in the collapsed Thoughts section instead of being written into the reply as ordinary text. #29052, #29040
  • 🧠 Large tool calls stream faster through Anthropic-compatible clients. When a streamed tool call sends a large block of arguments, Open WebUI now waits until that block can actually be complete before checking it, instead of doing the same expensive check again on every tiny piece. #28858
  • 🛑 Stop works across instances. Stopping a response now takes effect on deployments that spread people across several instances backed by a Redis cluster, instead of the reply continuing to the end regardless. #29165, #19840
  • 🎯 Fewer needless chat reloads. A conversation holding an older unfinished reply no longer reloads itself each time some other response in it finishes, reloading only for the reply the update actually concerns. Commit
  • 📖 Banners with underlined text. A banner containing underlined text now displays instead of failing to render. #29118, #29115
  • 🧰 Pinned models start with their own tools. Starting a chat from a pinned model in the sidebar now applies that model's tools and skills instead of carrying over the ones from the model you used last. #29058, #29050
  • ❓ Rejected ask_user calls no longer kill the reply. If a model asks the user a question in a way Open WebUI refuses, the model now receives that error and can continue or retry, instead of leaving the chat stopped with no answer. #29252, #29077
  • 🚫 Disabled models no longer vanish. Turning a model off in the admin Models list now keeps it in view so you can turn it back on, instead of it disappearing with no way to recover it. #29037, #29036
  • ✂️ Message text kept intact. Text containing angle brackets and a dollar sign is no longer mistaken for a skill mention and silently removed before your message reaches the model. #29051, #29041
  • 📆 Moved calendar events stay visible. Changing an event's date no longer makes it disappear from the calendar, and events already stuck in that state show up again. #29085, #29067
  • 🔁 Repeats follow the event. A repeating event now works out its occurrences from its own date and time, where a repeat rule carrying a start date of its own could place them on the wrong weekday or at the wrong hour. Commit
  • 🔟 Repeating automations keep their count. An automation set to run a fixed number of times is no longer shown as running once and quietly rewritten to a single run the next time you open and save it. #29261, #29263
  • 🗓️ Schedules survive a save. An automation carrying a start date now shows its real schedule in the list and keeps its weekly or monthly setting when saved, instead of showing raw rule text and falling back to daily. #29263
  • 🧩 Custom automation schedules stay custom. Reopening an automation with a custom repeat rule no longer loses the custom rule from the editor. #29260
  • 🔢 Accurate admin user counts. The counts on the admin Users tabs now follow your search and reset when you switch tabs, instead of showing stale or unfiltered numbers. #29080, #29079
  • 🧷 Sidebar folders stop acting stale. A folder that has been removed from the sidebar is now removed from the internal sidebar registry too, so later sidebar actions do not target a folder that is no longer on screen. #29121
  • 📱 Readable model list on small screens. The model identifier and timestamp in the workspace model list no longer overlap the model name on narrow displays. #29084, #29083
  • 🧱 Long setting values stop crushing labels. Settings rows now let long controls shrink inside the available space instead of squeezing the label beside them. #29229
  • 🧭 Model defaults panels stay usable. The model capabilities and prompt suggestion sections in admin settings now scroll inside their panels instead of growing past the available space. #29235
  • 📲 Dropdowns stay on screen. A dropdown near the edge of a narrow screen now shifts inward to stay fully visible instead of opening past the edge with its option labels cut off. #29226, #29225
  • 🌗 Dropdown lists follow the theme. The list a dropdown opens now takes its light or dark colouring from the rest of the interface instead of the system default. Commit
  • 🎛️ Valves dialog stays in bounds. A valve whose selected options form a long line no longer stretches its input past the edge of the dialog and over the page behind it. #29203, #29202
  • 🧹 Shared chats search resets. Reopening the shared chats dialog now starts with an empty search box and the full list, rather than a leftover search term above unfiltered results. #29082, #29081
  • 🔎 Case-insensitive search beyond English. Searching and filtering by tag now ignore letter case for accented and non-Latin text on installations backed by SQLite, where only unaccented English letters were matched whatever their case. Commit
  • 🏷️ Labels with colons and example URLs translate correctly. Interface text such as Warning:, http://localhost:8000, and https://mineru.net/api/v4 now appears correctly instead of being misread by the translation system. #29161, #29154
  • 🔑 Precise account matching on SQLite. Signing in through an identity provider now matches your account on its exact identifier, so accounts whose identifier is an unusually long or zero-padded number are no longer at risk of being confused with another. Commit
  • 🗃️ Knowledge list loads reliably. The Knowledge page in the workspace now fills in its list on opening instead of occasionally staying empty. Commit
  • 🎟️ Tool servers without a key. A tool server connection saved without a key is no longer sent an empty authorization header, which some servers refused outright. Commit
  • 🐍 Code interpreter starts on Windows. The built-in code interpreter now serves its script and WebAssembly files with the browser-safe file types Windows hosts sometimes overwrite, so Pyodide can load instead of failing before code runs. #29139, #29133

Changed

  • ⏱️ Daily limit on repeats. A calendar event can no longer be set to repeat more often than once a day, and saving one that repeats more often is now refused with a message explaining the limit. Commit
  • 🏷️ High Contrast Mode is now Accessibility Mode. The interface setting previously called 'High Contrast Mode' is now called 'Accessibility Mode', with the same switch in the same place. Commit
