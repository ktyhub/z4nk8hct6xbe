TencentDB-Agent-Mémoire v1.0.0

[1.0.0] - 2026-06-11

Version officielle publiée : évolution du plug-in exclusif OpenClaw vers un service de mémoire universel pour tous les agents. Service complet indépendant de la passerelle + v2 HTTP API + officiel TypeScript / Python SDK, n'importe quel framework d'agent peut accéder à des capacités complètes de mémoire multicouche et de compression de contexte.

⚠️ Modifications radicales

  • Scission de l'architecture client/serveur : le moteur de mémoire est séparé du plug-in intégré OpenClaw en un processus de service Gateway indépendant, et les méthodes de déploiement et d'accès changent.
  • Changement de structure de configuration : la structure de configuration du plug-in est aplatie et reconstruite, et le champ gateway d'origine est migré vers l'imbrication server.
  • Changement de mode d'entrée du plug-in : prend en charge deux modes d'accès : local (exécuté localement au sein du processus, par défaut) et client (connexion à une passerelle de mémoire externe).

🚀 Service de passerelle indépendante (v2 API)

La capacité de mémoire n'est plus liée à l'hôte OpenClaw et fonctionne comme un service indépendant. Il fournit la lecture et l'écriture de la mémoire et la gestion du pipeline pour n'importe quel agent via HTTP v2 API :

  • Full v2 API : 14 routes standards couvrant toutes les opérations telles que la mémoire CRUD, les mises à jour atomiques, l'indexation de scènes, la requête d'état du pipeline, etc.
  • Requête d'état du pipeline (/v2/pipeline/status) : obtenez l'état d'exécution et la progression de chaque étape de L1/L2/L3 en temps réel.
  • Gestion du cycle de vie des instances (/v2/instance/destroy) : prend en charge les systèmes externes pour créer/détruire activement des instances de mémoire.
  • Authentification facultative du porteur + liste blanche CORS : Protégez la sécurité du API exposé au monde extérieur.
  • Vérification du corps de la demande : appliquez une limite supérieure de 1 Mio pour éviter les demandes anormales.

🚀 SDK officiel

  • TypeScript SDK 1.0.0 (@tencentdb-agent-memory/memory-sdk-ts) : Type sécurisé, couvrant tous les API v2, prêt à l'emploi avec l'installation npm.
  • Python SDK (tencentdb-agent-memory-sdk-python) : installation de roue à pépins, double mode synchrone/asynchrone, couvrant tous les v2 API.

🚀 Adaptation du framework Universal Agent

  • Adaptation du plug-in OpenClaw : prend en charge deux modes d'accès : local (exécuté localement dans le processus, par défaut) et client (connexion à une passerelle de mémoire externe). Le mode local conserve l'expérience originale.
  • Hermes Agent Adaptation : adaptateur memory_tencentdb_v2, prend en charge le scénario multi-tenant du framework Hermes.
  • Accès universel : tout agent pouvant envoyer des requêtes HTTP (LangChain, AutoGPT, framework auto-développé, etc.) peut accéder via SDK ou API nu.

🚀 Observabilité

  • OpenTelemetry full-link Trace : prend en charge les rapports du protocole OTLP et peut être connecté à des backends tels que Jaeger / Grafana Tempo.
  • Intégration Langfuse : transmet uniquement les étendues liées au LLM, adaptées à l'évaluation de la qualité de la récupération de la mémoire.
  • Indicateurs d'évaluation du pipeline : taux d'extraction L1, répartition des décisions de déduplication, consommation de jetons à chaque étape, délai de rappel, etc.

🚀 Décharger le serveur V2

  • Exécuteur asynchrone L1 / L1.5 / L2 : pipeline de traitement de déchargement indépendant, prenant en charge la simultanéité de sessions à grande échelle.
  • Processeur de compression L3 : tokenisation Mermaid + contrôle du budget contextuel, compression contextuelle intelligente.
  • MMD Injection : prend en charge le processus de déchargement d'injection de données multimodales.
  • Routage /v2/offload/* intégré à la passerelle : entrée de déchargement unifiée API.

📦 Méthode de déploiement

| Méthode | Descriptif | |------|------| | Conteneur Docker | docker pull agentmemory/hermes-memory:1.0.0 | | Exécutez directement le code source | node --import tsx/esm src/gateway/server.ts | | Plugin OpenClaw | Installé via install-openclaw-plugin-v2.sh | | Plug-in Hermès | Plug-in memory_tencentdb_v2 Python intégré |

⬆️ Instructions de mise à niveau à partir de 0.x

v1.0.0 et 0.x sont deux lignes de versions maintenues en parallèle :

  • 0.x (branche main) : plug-in intégré OpenClaw, adapté aux scénarios autonomes légers
  • 1.x (branche feat/server) : service Mémoire indépendant, adapté au déploiement multi-agents/multi-framework/basé sur des services

Les moteurs de mémoire de base des deux sont les mêmes (couche L0 → L3 + récupération hybride BM25/vecteur + mémoire symbolique à court terme Mermaid) et les formats de données sont compatibles.

🐛 Correction (v1.0.0-beta.2 → v1.0.0)

  • Le plug-in Hermes install_hermes_tdai_gateway.sh est amélioré : prend en charge le changement automatique d'utilisateur root, la migration automatique des anciens chemins, la détection idempotente pour ignorer les installations répétées
  • Optimisation de la configuration de la passerelle : port par défaut 8420, écriture synchrone de deux variables d'environnement /etc/profile.d/ et ~/.hermes/.env
  • Complétion du document SDK : TypeScript / Python SDK README et exemple d'accès
  • Ajustement de la configuration du plugin OpenClaw.json : supprimer le champ obsolète et adapter à la dernière version d'OpenClaw

TencentDB-Agent-Memory v1.0.0

Highlights

  • Gateway + v2 API remove the OpenClaw dependency — Memory now runs as a standalone service exposing 14 routes for CRUD, atomic updates, scenario indexing, pipeline status, and instance lifecycle. Any HTTP-capable agent can integrate; Bearer authentication, CORS allowlists, and a 1 MiB request limit support safer external deployment.
  • Breaking deployment and configuration changes require an explicit migration path — The embedded plugin becomes a client/server architecture: rename the flat gateway configuration to nested server, then choose local mode (default, in-process) or client mode (external Gateway). Existing 0.x installations can remain on main; the service-oriented 1.x line lives on feat/server, with a compatible memory engine and data format.
  • Official SDKs cover the complete API — TypeScript (@tencentdb-agent-memory/memory-sdk-ts) provides typed access, while the Python package (tencentdb-agent-memory-sdk-python) supports both synchronous and asynchronous workflows. This avoids hand-maintaining HTTP clients when integrating LangChain, AutoGPT, Hermes, or custom frameworks.
  • Offload processing is redesigned for concurrency and context control — Asynchronous L1/L1.5/L2 executors handle large session volumes, while L3 combines Mermaid symbolization with context-budget enforcement for compression. Multimodal data can enter the pipeline through /v2/offload/*, making memory infrastructure usable beyond text-only conversations.
  • Production observability is built in — OpenTelemetry traces export over OTLP to backends such as Jaeger or Grafana Tempo; Langfuse receives only LLM-related spans for extraction-quality evaluation. Pipeline metrics—including L1 extraction rate, deduplication decisions, token usage, and recall latency—help diagnose memory behavior rather than treating it as a black box.

[1.0.0] - 2026-06-11

正式版发布：从 OpenClaw 专属插件演进为面向所有 Agent 的通用记忆服务。完整的 Gateway 独立服务 + v2 HTTP API + 官方 TypeScript / Python SDK，任何 Agent 框架均可接入完整的多层记忆与上下文压缩能力。

⚠️ Breaking Changes

  • 客户端/服务端架构拆分：记忆引擎从 OpenClaw 嵌入式插件拆分为独立 Gateway 服务进程，部署方式与接入方式发生变化。
  • 配置结构变更：插件配置结构扁平化重构，原 gateway 字段迁移为 server 嵌套。
  • 插件入口模式变更：支持 local（进程内本地运行，默认）和 client（连接外部 Memory Gateway）两种接入模式。

🚀 独立 Gateway 服务（v2 API）

记忆能力不再绑定 OpenClaw 宿主，以独立服务形式运行，通过 v2 HTTP API 为任意 Agent 提供记忆读写与管线管理：

  • 完整 v2 API：14 条标准路由覆盖记忆 CRUD、原子更新、场景索引、管线状态查询等全部操作。
  • 管线状态查询（/v2/pipeline/status）：实时获取 L1/L2/L3 各阶段运行状态与进度。
  • 实例生命周期管理（/v2/instance/destroy）：支持外部系统主动创建/销毁记忆实例。
  • 可选 Bearer 鉴权 + CORS 白名单：保护对外暴露的 API 安全。
  • 请求体校验：强制 1 MiB 上限，防止异常请求。

🚀 官方 SDK

  • TypeScript SDK 1.0.0（@tencentdb-agent-memory/memory-sdk-ts）：类型安全，覆盖全部 v2 API，npm 安装即用。
  • Python SDK（tencentdb-agent-memory-sdk-python）：pip wheel 安装，同步/异步双模式，覆盖全部 v2 API。

🚀 通用 Agent 框架适配

  • OpenClaw 插件适配：支持 local（进程内本地运行，默认）和 client（连接外部 Memory Gateway）两种接入模式。local 模式保持原有体验。
  • Hermes Agent 适配：memory_tencentdb_v2 adapter，支持 Hermes 框架多租户场景。
  • 通用接入：任何能发 HTTP 请求的 Agent（LangChain、AutoGPT、自研框架等）均可通过 SDK 或裸 API 接入。

🚀 可观测性

  • OpenTelemetry 全链路 Trace：支持 OTLP 协议上报，可对接 Jaeger / Grafana Tempo 等后端。
  • Langfuse 集成：仅转发 LLM 相关 span，适合评估记忆提取质量。
  • 管线评测指标：L1 提取率、去重决策分布、各阶段 token 消耗、recall 延迟等。

🚀 Offload Server V2

  • L1 / L1.5 / L2 异步执行器：独立的 Offload 处理管线，支持大规模会话并发。
  • L3 压缩处理器：Mermaid 符号化 + 上下文预算控制，智能上下文压缩。
  • MMD 注入：支持多模态数据注入 Offload 流程。
  • Gateway 集成 /v2/offload/* 路由：统一 Offload API 入口。

📦 部署方式

| 方式 | 说明 | |------|------| | Docker 容器 | docker pull agentmemory/hermes-memory:1.0.0 | | 源码直接运行 | node --import tsx/esm src/gateway/server.ts | | OpenClaw 插件 | 通过 install-openclaw-plugin-v2.sh 安装 | | Hermes 插件 | 内置 memory_tencentdb_v2 Python 插件 |

⬆️ 从 0.x 升级说明

v1.0.0 与 0.x 是并行维护的两条版本线：

  • 0.x（main 分支）：OpenClaw 嵌入式插件，适合轻量单机场景
  • 1.x（feat/server 分支）：独立 Memory 服务，适合多 Agent / 多框架 / 服务化部署

两者核心记忆引擎相同（L0→L3 分层 + BM25/向量混合检索 + Mermaid 符号化短期记忆），数据格式兼容。

🐛 修复（v1.0.0-beta.2 → v1.0.0）

  • Hermes 插件 install_hermes_tdai_gateway.sh 完善：支持 root 自动切换用户、旧路径自动迁移、幂等检测以跳过重复安装
  • Gateway 配置优化：默认端口 8420，同步写入 /etc/profile.d/ 和 ~/.hermes/.env 两份环境变量
  • SDK 文档补全：TypeScript / Python SDK README 与接入示例
  • OpenClaw plugin.json 配置调整：移除 deprecated 字段，适配 OpenClaw 最新版本

📖 文档

  • SDK 接入指南（TypeScript / Python 示例）。
  • Gateway 独立部署文档。
  • OpenClaw / Hermes 插件安装说明。
  • Docker 部署与配置参考。
