TencentDB-Agent-Mémoire v2.0.2

[2.0.2] - 2026-10-09

Positionnement du produit : laissez l'expérience, les documents et le code de l'agent devenir des actifs réutilisables pour le prochain agent Lire les fichiers directement. Voir README_CN.md pour plus de détails.

🗄️ Backend de stockage évolutif · Prend en charge MongoDB

La mémoire de l'équipe n'est plus liée à une seule base de données et les capacités back-end de MongoDB sont encore complétées :

  • Ajout de deux nouveaux types de stockage, invite de mémoire et référence de génération, couvrant davantage de structures de données en mémoire
  • L'entrée en un clic ./start-all-mongo.sh écrira de manière persistante STORE_MODE dans .env pour les démarrages ultérieurs Gardez le même backend, plus de configuration à chaque fois
  • Correction de la capacité d'auto-guérison des scénarios de conflit d'index. Les enregistrements répétés par défaut/extraits ne provoquent plus d’erreurs de démarrage.

🔀 Plus d'accès client

  • OpenCode Ajout du package de configuration officiel de l'adaptateur mémoire (y compris opencode.json et la documentation d'accès). Vous pouvez y accéder en suivant les instructions et sans avoir besoin d'écrire du code de plug-in.
  • OpenCode prend en charge la structure de configuration du fournisseur v2 de 2.0, et la nouvelle version du client peut directement réutiliser le opencode.v2.json officiel
  • DeepSeek Harness Ajout de l'adaptation de bureau DSH, la méthode de configuration peut faire référence à la partie 1.6 de ./agents/dsh/README.md
  • Ajout d'un accès client Pi (similaire au client AI Agent de Codex, utilisant le protocole OpenAI Chat)

🧠 Import de source externe (Wiki/Code/Tâches)

  • Ajout de la possibilité d'importer des tâches à partir de systèmes de gestion de tâches externes. Les cartes de tâches affichent directement la source et prennent en charge la copie et la pagination des identifiants.
  • Ajout de l'enregistrement de la source de code externe (dépôt privé) et de l'isolation des informations d'identification. Chaque équipe détient des informations d’identification indépendantes et est invisible les unes pour les autres.
  • Ajout de l'importation de source externe Wiki pour compléter le lien d'importation d'actifs externes avec la source de code et la source de tâches

🧰Optimisation de l'expérience des compétences

  • Un nouveau mode strict est ajouté à l'extraction des compétences par lots de démarrage à froid, rendant la qualité de l'extraction plus contrôlable
  • L'extraction de compétences suit automatiquement la langue de l'utilisateur et génère un contenu plus conforme aux habitudes d'utilisation
  • La liste des compétences prend en charge le tri par activité d'utilisation, ce qui facilite la recherche des compétences à haute fréquence.

🎛️ Panneau Mémoire Hub

  • Les cartes de tâches prennent en charge l'affichage de la source, la copie d'ID et l'optimisation de la pagination, rendant les interactions d'importation par lots plus fluides.
  • Le filtrage temporel est automatiquement réinitialisé lors de l'actualisation manuelle et les mémoires nouvellement générées peuvent être consultées immédiatement

🔄 Expérience de session et d'accès

  • Le guidage de session est plus stable pour un plus grand nombre de clients : le seul agent est automatiquement sélectionné, la confirmation des actifs est plus précise et la valeur par défaut échoue Contourner automatiquement au lieu de rester bloqué
  • Correction du problème des pop-ups répétés du sous-agent parallèle WorkBuddy, et la normalisation des sessions est plus robuste
  • Correction de problèmes affectant l'expérience tels que les commandes de mémoire, la contamination des résultats des outils et la duplication des messages historiques sous divers clients.

🐛 Correction

  • Correction des anomalies de rappel BM25, de la contamination des résultats de l'outil L0 et des problèmes d'affichage du texte original dans les scénarios sans intégration
  • Correction de problèmes tels que le rappel de mémoire vide, les messages historiques en double et la troncature des listes de commutation multi-équipes.
  • Correction de problèmes tels que les instructions AGENTS.md manquantes de Claude Code
  • Correction de problèmes de compatibilité des scripts de déploiement dans certains environnements

TencentDB-Agent-Memory v2.0.2

Highlights

  • MongoDB graduates to a sticky, first-class backend — Two new stores (memory-prompt, generation-ref) fill out the Mongo schema, but the adoption-relevant change is behavioral: ./start-all-mongo.sh now persists STORE_MODE into .env, so your backend choice survives restarts instead of being re-declared every launch. Self-healing for index conflicts means duplicate default/extracted records no longer abort startup — expect fewer cold-start failures on shared collections.
  • Client integration goes config-only and broader — OpenCode ships an official Memory adapter (opencode.json + docs, no plugin code) and supports the 2.0 v2 provider schema (opencode.v2.json); DeepSeek Harness desktop (./agents/dsh/README.md §1.6) and Pi — a Codex-like agent on the OpenAI Chat protocol — are also onboarded. Watch the v1-vs-v2 provider split: load the config matching your client version or the adapter won't attach.
  • External asset import closes the loop, with credential isolation — Tasks import from external task systems with source badges, ID copy, and pagination; private repos register as code sources with per-team credentials that are mutually invisible; Wiki joins as the third source. The isolation is the security-relevant win — teams can share one deployment without cross-reading each other's private repos.
  • Skill extraction gets guardrails and ranking — Cold-start batch extraction adds a strict mode for quality control, generated content auto-follows the user's language, and the list can sort by usage activity so high-frequency skills surface. For adopters, strict mode is the knob to reach for when auto-extracted skills are noisy.
  • Recall and session reliability harden — BM25 recall without embeddings, L0 tool-result pollution, empty-recall cases, duplicate history messages, multi-team list truncation, and lost AGENTS.md instructions in Claude Code are all fixed. Note one behavior change in the hub: manual refresh now resets the time filter so newly generated memories appear immediately — relevant if you rely on filtered views.
  • Breaking changes — None reported in v2.0.2.

[2.0.2] - 2026-10-09

产品定位：让 Agent 的经验、文档、代码沉淀成可复用资产，让下一位 Agent 直接读档。详见 README_CN.md。

🗄️ 存储后端可扩展 · 支持 MongoDB

团队记忆不再绑定单一数据底座，MongoDB 后端能力进一步补全：

  • 新增 memory-prompt 与 generation-ref 两类存储，覆盖更多记忆数据结构
  • 一键入口 ./start-all-mongo.sh 会把 STORE_MODE 持久化写入 .env，后续启动 保持同一后端，不再每次重复配置
  • 修复索引冲突场景的自愈能力，重复的默认/抽取记录不再导致启动报错

🔀 更多客户端接入

  • OpenCode 新增官方 Memory adapter 配置包（含 opencode.json 与接入文档），按说明配置即可接入，无需编写插件代码
  • OpenCode 支持 2.0 的 v2 provider 配置结构，新版客户端可直接复用官方 opencode.v2.json
  • DeepSeek Harness 新增 dsh 桌面端适配，配置方式可参考 ./agents/dsh/README.md 中 1.6 的部分
  • 新增 Pi 客户端接入（类似 Codex 的 AI Agent 客户端，走 OpenAI Chat 协议）

🧠 外部源导入（Wiki / 代码 / 任务）

  • 新增从外部任务管理系统导入 Task 的能力，任务卡片直接展示来源、支持 ID 复制与分页
  • 新增外部代码源（私有仓）注册与凭据隔离，各团队持有独立凭据、互不可见
  • 新增 Wiki 外部来源导入，与代码源、任务源一起补齐外部资产导入链路

🧰 技能（Skill）体验优化

  • 冷启动批量技能抽取新增严格模式，抽取质量更可控
  • 技能抽取自动跟随用户语言，生成内容更贴合使用习惯
  • 技能列表支持按使用活跃度排序，高频技能更容易被找到

🎛️ Memory Hub 面板

  • 任务卡片支持来源展示、ID 复制与分页优化，批量导入交互更顺畅
  • 手动刷新时自动重置时间筛选，新产生的记忆能即时看到

🔄 会话与接入体验

  • 会话引导在更多客户端下更稳定：自动选中唯一 Agent、资产确认更精准、预设失败时 自动绕过而非卡住
  • 修复 WorkBuddy 并行子代理反复弹窗的问题，会话归一更稳健
  • 修复多种客户端下记忆命令、工具结果污染、历史消息重复等影响体验的问题

🐛 修复

  • 修复无 embedding 场景下 BM25 召回异常、L0 工具结果污染与原文展示问题
  • 修复记忆召回为空、历史消息重复、多团队切换列表截断等问题
  • 修复 Claude Code 的 AGENTS.md 指令丢失等问题
  • 修复部署脚本在部分环境下的兼容性问题
