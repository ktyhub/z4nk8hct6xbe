TencentDB-Agent-Mémoire v0.3.6

[0.3.6] - 2026-05-28

🚀 Nouvelles fonctionnalités

  • Contrôle du budget de contexte de rappel (#71 / #70) : ajout des configurations recall.maxCharsPerMemory et recall.maxTotalRecallChars pour élaguer les entrées trop longues dans un ordre fractionnaire et ignorer les parties de débordement pour empêcher les longues sessions d'évincer le contexte en raison de l'expansion de la mémoire.
  • Les mots d'invite L1 / L2 / L3 s'adaptent en fonction de la langue de saisie de l'utilisateur (#38) : Les champs de texte libre des quatre invites l1-extraction, l1-dedup, scene-extraction et persona-generation sont désormais écrits dans la langue des messages utilisateur, sans configurer locale.
  • Intégration de sendDimensions facultativement fermée : Ajout d'un élément de configuration embedding.sendDimensions. Lorsqu'il est défini sur false, le champ dimensions dans le corps de la demande est omis, ce qui peut être connecté à des modèles à dimensions fixes tels que BGE-M3.
  • Authentification du porteur en option par la passerelle + liste blanche CORS : Ajout de server.apiKey / TDAI_GATEWAY_API_KEY et server.corsOrigins / TDAI_CORS_ORIGINS. Après activation, les routes non /health doivent transporter un jeton Bearer, une comparaison en temps constant pour empêcher les attaques temporelles. La synchronisation client Hermes Python prend en charge MEMORY_TENCENTDB_GATEWAY_API_KEY.
  • Mode de déchargement collect : Ajout de offload.mode: "collect", qui effectue uniquement la collecte de données sans déclencher la compression L3. Il convient aux scénarios d’accumulation de données pures ou de débogage.

🐛 Correction

  • L'échec de L2 LLM entraîne l'effacement de scene_blocks/ (#88) : restaure automatiquement scene_blocks/ à partir de la dernière sauvegarde lorsque LLM génère une erreur, conception logicielle en cas d'échec.
  • Le nom du fichier de scène contient des espaces, ce qui rend la référence Persona Scene Navigation invalide : ajout de filename-normalizer.ts et normalisation automatique du nom de fichier dans SceneExtractor.extract.
  • api.runtime.state provoque un crash d'enregistrement pour undefined (#78 / #85 / #79) : ajout d'une chaîne facultative + repli, prise en charge de runtimeState.resolveStateDir() → OPENCLAW_STATE_DIR → ~/.openclaw rétrogradation à trois niveaux.
  • L'ID du slot contextEngine est incohérent avec le nom du plug-in : remplacez-le par memory-tencentdb pour éviter que openclaw doctor --fix ne réinitialise le slot.
  • Le règlement L1.5 ne revient jamais, provoquant le gel de L2 : ajoutez un délai d'attente de 60 secondes et forcez automatiquement le règlement lorsque l'emplacement du moteur de contexte n'est pas configuré.
  • La tâche texte autonome expose toujours les outils (#58 / #59) : La liste d'outils n'est pas du tout transmise dans enableTools=false.
  • Le démarrage à froid L2 ignore la fausse mise à jour l2LastRunTime : met à jour l'horodatage uniquement lorsqu'il est réellement exécuté.
  • sanitizeText supprime par erreur les caractères non BMP tels que emoji / CJK / Math Bold (#30 / #31) : ajoutez l'indicateur u au modèle standard pour correspondre uniquement au substitut isolé.
  • Troncation d'urgence bloquée en cas de rejet de MIN_KEEP : Ajout de _emergencyTruncateOversized, suppression forcée et nettoyage d'appariement.
  • Consommation de temps cumulée de plusieurs tours de compression agressive : passage de 6 tours de quantité totale de tiktoken à un seul point de coupure précis, 615 messages 84s → 14s.
  • FP-HEAD-DELETE supprime accidentellement le nouveau message : utilisez plutôt FP-BOUNDARY-DELETE + BOUNDARY-INCR-SKIP, rejouez la scène 38s→122ms.
  • Le premier assemblage est lent : ajoutez un pré-court-circuit à estimation rapide du jeton, 29 s → 1,4 s.
  • Précision du calcul du jeton : details est ajouté à INTERNAL_KEYS ; l3TiktokenEncoding est remplacé par cl100k_base par défaut.
  • Dockerfile.hermes a généré config.yaml manquant api_key (#77 / #81) : écriture synchrone de model.api_key.
  • Plusieurs problèmes avec le script d'installation (#18 / #19 / #20 / #54 / #55) : Prise en charge de l'écrasement de HERMES_AGENT_DIR, la racine ne récure plus su, l'environnement systemd utilise le nœud de chemins absolus.
  • Renforcement de sécurité plus propre : rejet de la coupure invalide, expired/total > 80% empêche la suppression, garde-corps de rétention minimum.

✨ Améliorations

  • l3TiktokenEncoding est remplacé par cl100k_base par défaut, correspondant aux segmenteurs de mots de modèle domestique/open source grand public.
  • Rétrogradation du journal de déchargement : AGGRESSIVE / EMERGENCY, etc. sont rétrogradés au débogage et WARN est émis après seulement 10 secondes.
  • Le document Docker complète les pré-étapes cd docker/opensource ; ajoute un modèle de question/problème de consultation.

TencentDB-Agent-Memory v0.3.6

Highlights

  • Recall budgets and token accounting — New recall.maxCharsPerMemory / recall.maxTotalRecallChars score-rank and truncate oversized memories so long sessions stop inflating recall and crowding the context window; both default to 0 (off), so set explicit caps to opt in and expect lower-ranked tail entries to be silently dropped (PR #71, issue #70). Separately, l3TiktokenEncoding flips from o200k_base to cl100k_base and details now include INTERNAL_KEYS, so token counts feeding budgets and compression thresholds will shift — pin the old encoding explicitly if you depended on its numbers.
  • Gateway auth and CORS (behavioral change) — With server.apiKey / TDAI_GATEWAY_API_KEY and CORS origins configured, every route except /health now demands a Bearer token compared in constant time against timing attacks; clients must send it (Hermes reads MEMORY_TENCENTDB_GATEWAY_API_KEY). Roll credentials out before enabling, and note that a non-empty allowlist keeps cross-origin callers blocked until you add their origins.
  • Language-adaptive prompts and BGE-M3 embeddings — The l1-extraction, l1-dedup, scene-extraction and persona-generation prompts now write free-text fields in the user's message language, letting you drop locale tuning (issue #38). embedding.sendDimensions: false omits the dimensions field for fixed-dimension backends like BGE-M3 — the fix if your provider rejects or ignores that parameter.
  • Fail-soft reliability and state handling — L2 LLM errors now restore scene_blocks/ from the latest backup instead of wiping it (#88), and api.runtime.state gained optional chaining plus a resolveStateDir() → OPENCLAW_STATE_DIR → ~/.openclaw fallback (#78/#85/#79). Watch two things: the contextEngine slot ID is now memory-tencentdb (old configs may be reset by openclaw doctor --fix), and sanitizeText uses the u flag so emoji/CJK/Math Bold survive instead of being stripped (#30/#31).
  • Compression, cleanup and cost wins — Aggressive compression is a single-pass cut-point (615 messages, 84s → 14s), boundary-delete replay drops 38s → 122ms, and a fast token-estimate short-circuit cuts first assemble from 29s → 1.4s. Cleaner safety guards (reject invalid cutoffs, block deletion above expired/total > 80%, min-keep floor) plus new offload.mode: "collect" (data-only, no L3 compression) make bulk runs safer for large histories.
  • No breaking changes — all configuration changes are backward compatible.

[0.3.6] - 2026-05-28

🚀 新功能

  • Recall 上下文预算控制 (#71 / #70)：新增 recall.maxCharsPerMemory 与 recall.maxTotalRecallChars 配置，按分数顺序裁剪超长条目并丢弃溢出部分，避免长会话因记忆膨胀挤占上下文。
  • L1 / L2 / L3 提示词按用户输入语言自适应 (#38)：l1-extraction、l1-dedup、scene-extraction、persona-generation 四个 prompt 的自由文本字段现在跟随用户消息语言书写，无需配置 locale。
  • Embedding sendDimensions 可选关闭：新增 embedding.sendDimensions 配置项，设为 false 时省略请求体中的 dimensions 字段，可对接 BGE-M3 等固定维度模型。
  • Gateway 可选 Bearer 鉴权 + CORS 白名单：新增 server.apiKey / TDAI_GATEWAY_API_KEY 与 server.corsOrigins / TDAI_CORS_ORIGINS，启用后非 /health 路由需携带 Bearer token，constant-time 比较防时序攻击。Hermes Python 客户端同步支持 MEMORY_TENCENTDB_GATEWAY_API_KEY。
  • Offload collect 模式：新增 offload.mode: "collect"，仅执行数据采集而不触发 L3 压缩，适用于纯数据积累或调试场景。

🐛 修复

  • L2 LLM 失败导致 scene_blocks/ 被清空 (#88)：LLM 抛错时自动从最新备份恢复 scene_blocks/，fail-soft 设计。
  • 场景文件名含空格导致 Persona Scene Navigation 引用失效：新增 filename-normalizer.ts，在 SceneExtractor.extract 中自动归一化文件名。
  • api.runtime.state 为 undefined 导致注册崩溃 (#78 / #85 / #79)：加可选链 + fallback，支持 runtimeState.resolveStateDir() → OPENCLAW_STATE_DIR → ~/.openclaw 三级降级。
  • contextEngine slot ID 与插件名不一致：改为 memory-tencentdb，避免 openclaw doctor --fix 重置 slot。
  • L1.5 settle 永不返回导致 L2 卡死：增加 60s 超时，未配置 Context Engine slot 时自动 force-settle。
  • Standalone 文本任务仍暴露工具 (#58 / #59)：enableTools=false 时彻底不传工具列表。
  • L2 cold-start skip 误更新 l2LastRunTime：仅在确实运行过时更新时间戳。
  • sanitizeText 误删 emoji / CJK / Math Bold 等非 BMP 字符 (#30 / #31)：正则加 u flag，只匹配孤立 surrogate。
  • Emergency 截断在 MIN_KEEP 拒绝下死锁：新增 _emergencyTruncateOversized，兜底强制删除并配对清理。
  • 多轮 aggressive compression 累计耗时：由 6 轮全量 tiktoken 改为单趟精确切点，615 条消息 84s→14s。
  • FP-HEAD-DELETE 误删新消息：改用 FP-BOUNDARY-DELETE + BOUNDARY-INCR-SKIP，重放场景 38s→122ms。
  • 首次 assemble 慢：增加 fast-token-estimate 前置短路，29s→1.4s。
  • Token 计算精度：details 加入 INTERNAL_KEYS；l3TiktokenEncoding 默认改为 cl100k_base。
  • Dockerfile.hermes 生成的 config.yaml 缺 api_key (#77 / #81)：同步写入 model.api_key。
  • 安装脚本多处问题 (#18 / #19 / #20 / #54 / #55)：支持 HERMES_AGENT_DIR 覆盖、root 不再递归 su、systemd 环境用绝对路径 node。
  • Cleaner 安全加固：拒绝无效 cutoff、expired/total > 80% 阻止删除、最小保留护栏。

✨ 改进

  • l3TiktokenEncoding 默认改为 cl100k_base，匹配主流国产/开源模型分词器。
  • Offload 日志降级：AGGRESSIVE / EMERGENCY 等降到 debug，仅超 10s 输出 WARN。
  • Docker 文档补充 cd docker/opensource 前置步骤；新增 question/consultation issue 模板。

⚠️ 配置项变化（向后兼容）

| Key | 默认值 | 说明 | |---|---|---| | recall.maxCharsPerMemory | 0 | 0/未设置 = 不裁剪 | | recall.maxTotalRecallChars | 0 | 0/未设置 = 不裁剪 | | embedding.sendDimensions | true | false 时不携带 dimensions，适配 BGE-M3 等 | | l3TiktokenEncoding | cl100k_base（原 o200k_base） | 仅在显式依赖 o200k_base 时需手动覆盖 |
