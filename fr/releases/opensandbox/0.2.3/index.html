OpenSandbox v0.2.3

Correctif Publié26 août 2026 Sourceopensandbox-group/OpenSandbox Anglais original

Cette page est traduite automatiquement. Le texte anglais original fait foi.

Serveur OpenSandbox/v0.2.3

Quoi de neuf

⚠️ Modifications radicales

  • OPENSANDBOX_EGRESS_SANDBOX_ID est désormais injecté par le serveur et rejeté dans l'environnement de requête : le serveur définit sans condition la variable d'attribution sandbox-id du side-car de sortie dans les environnements d'exécution Docker et Kubernetes, et l'a supprimé de la liste autorisée d'environnement. Les requêtes qui le transmettent dans env obtiennent désormais une valeur de 400 au lieu d'une valeur pouvant être usurpée par l'utilisateur. #1381

✨Caractéristiques

  • Hooks de cycle de vie Sandbox (preStart / periodic), OSEP-0020 — CreateSandboxRequest.lifecycle est accepté, validé (transports réservés, noms périodiques en double, combinaisons d'allocation de pool) et transporté vers les charges de travail Kubernetes via l'environnement OPEN_SANDBOX_LIFECYCLE réservé pour exécution. Docker rejette explicitement les demandes de cycle de vie ; PATCH et autres types de hooks sont hors de portée. Livré avec les modèles Java/Kotlin, Python et TypeScript SDK alignés. #1588 #1589
  • Limite preStart.timeoutSeconds augmentée de 300 s à 3 heures — les limites du serveur et d'OpenAPI autorisent désormais jusqu'à 10 800 s pour les hooks de pré-démarrage ; la limite périodique reste à 300s. La limite de stratégie de produit côté exécutable est supprimée, conservant les modifications de stratégie uniquement sur le serveur. #1637
  • Pause/reprise QEMU VMState pour les sandbox basés sur runc — capture opt-in de la mémoire invité/vCPU/état de l'appareil via la migration QMP ; Les rootfs et VMState compressés sont stockés sous forme d'images OCI distinctes saisies par des résumés SHA-256 immuables. Prend en charge la pause, le détachement et la restauration autonome de BatchSandbox en pool tout en préservant la mémoire invité, le disque inscriptible, l'ID de démarrage et la continuité du compteur. Les instantanés Rootfs uniquement restent rétrocompatibles. #1584
  • L'épuisement de la capacité du pool est désormais identifiable par la machine — le contrôleur publie une condition PoolAllocationPending/PoolCapacityExhausted ; le serveur attend une fenêtre d'acquisition limitée (nouveau kubernetes.pool_acquisition_timeout_seconds, 30 s par défaut), puis renvoie HTTP 429 avec KUBERNETES::POOL_CAPACITY_EXHAUSTED et Retry-After: 5 au lieu du délai d'attente de préparation générique 504. Les contrôleurs plus anciens reviennent en toute sécurité au comportement existant. #1581
  • Résumé de l'allocation du pool dans les réponses du cycle de vie — getSandbox fait désormais apparaître un bloc Sandbox.allocation facultatif (mode: pool, poolRef, state: allocated) pour les allocations de pool Kubernetes confirmées, émis uniquement pour les références concrètes de pool non génériques avec des preuves d'allocation correspondantes. Aucune donnée de pod/espace de noms/IP n'est exposée. #1481
  • Mesures de requête HTTP génériques via OTLP — un middleware ASGI léger exporte server.http.request.duration (ms) avec http_method, http_route correspondant (ou unknown pour les requêtes non acheminées/ayant échoué à l'authentification) et les attributs http_status_code, complétant l'histogramme de durée de création existant. Les chemins bruts, les identifiants, les clés et les corps ne sont jamais des attributs ; pas d'opération lorsque [otel] est désactivé. #1561
  • Diagnostics stables API avec étendues — les diagnostics respectent désormais le contrat de descripteur public en ligne : logs: container|all et events: runtime|lifecycle|all, avec 400 DIAGNOSTICS_SCOPE_UNSUPPORTED pour les étendues inconnues et des avertissements explicites pour les étendues de meilleur effort incomplètes. Les réponses en texte brut non-scope obsolètes fonctionnent toujours avec un en-tête Deprecation. #1553
  • Travail de base du backend des flottes fast-sandbox (OSEP-0007) — un FastPath v2 gRPC client encapsule tous les RPC FastPathService avec un mappage d'erreurs typées (FastPathNotFound → 404, etc.), et une couche de mappage de création/statut convertit le contrat public en sémantique fast-sandbox, rejetant les champs non pris en charge (volumes, platform, resourceRequests, credentialProxy, snapshotId, etc.) avec des erreurs claires. Pas encore câblé en tant que runtime actif. #1558 #1559
  • Les clés de signature d'accès sécurisé peuvent provenir d'un secret Kubernetes — le serveur accepte les remplacements d'environnement OPENSANDBOX_SECURE_ACCESS_KEYS / OPENSANDBOX_SECURE_ACCESS_ACTIVE_KEY (reflétant le remplacement de clé API, mode passerelle requis), et le graphique Helm ajoute server.gateway.secureAccess.existingSecret (mutuellement exclusif avec le texte en clair keys, appliqué au moment du rendu) afin que les flux GitOps ne valident jamais le matériel de clé. #1445
  • Docker runtime sandbox_env / sandbox_binds — les nouveaux champs [docker] appliquent des variables d'environnement à l'échelle de la flotte et des montages de liaison d'hôte à chaque conteneur sandbox (la requête env l'emporte sur sandbox_env ; les liaisons de configuration précèdent les liaisons dérivées de la requête), donnant au runtime Docker le hook côté opérateur du modèle de pod K8s. #1303
  • Délai d'attente de préparation du side-car de sortie configurable — le nouveau [egress] timeout_seconds (30 s par défaut, valeurs non positives rejetées) permet aux déploiements Docker d'ajuster la durée pendant laquelle le serveur attend le point de terminaison d'intégrité du side-car. #1522
  • Espaces de noms de locataire validés au démarrage (OSEP-0014) — le serveur vérifie rapidement que chaque espace de noms de locataire existe et est accessible avant de diffuser le trafic, regroupant tous les espaces de noms manquants/inaccessibles en une seule erreur fatale au lieu d'échouer uniquement au moment de la demande. OSEP-0004/0005/0014 marqué mis en œuvre. #1389

🔒 Sécurité

  • Augments de dépendances de correction CVE — google.golang.org/grpc → v1.82.1 sur kubernetes/ingress/execd/egress/internal (correctifs xDS RBAC et HTTP/2), postcss → 8.5.11 (fichier arbitraire lu via sourceMappingURL). #1385

🐛 Corrections de bugs

  • **Recherches de points de terminaison Docker ~ 108 fois plus rapides ** — la recherche de conteneur passe désormais par le nom déterministe sandbox-<id> avec la validation d'étiquette opensandbox.io/id, en revenant à l'analyse d'étiquette uniquement en cas de besoin. Test de référence local : 6,07 s → 56 ms pour la résolution du point de terminaison execd+egress. #1400
  • Le cache de l'informateur expire lorsque la montre cale — has_synced signifie désormais « le cache est actuellement actif », et non « une liste initiale terminée une fois » ; une montre bloquée ou à moitié ouverte (par exemple après une mise à niveau du plan de contrôle) se dégrade pour diriger les lectures de API au lieu de servir un statut gelé pour toujours, ce qui provoquait auparavant chaque création à 504 avec POD_READY_TIMEOUT. Liaison dérivée des boutons existants (resync_period + watch_timeout) ; pas de nouvelle configuration. #1534
  • Fuite de connexion proxy sur réponses abandonnées — lorsqu'un client en aval s'est déconnecté avant le début de la diffusion du corps de la réponse, la réponse httpx du backend n'a jamais été publiée, épuisant progressivement le pool partagé jusqu'à httpcore.PoolTimeout. Le proxy possède désormais la réponse backend pour le cycle de vie complet de l'ASGI, protège aclose() contre l'annulation et le libère en cas d'échec de l'installation. Test de résistance : 1000/1000 déconnexions nettoyées. #1488
  • ID d'opération de proxy uniques et stables — les 20 opérations HTTP proxy émettaient auparavant 4 ID d'opération en double dépendant du processus (16 avertissements OpenAPI) ; chaque méthode obtient désormais son propre ID déterministe avec un comportement de répartition, d'authentification et 405 au moment de l'exécution identique. Les clients générés doivent être régénérés. #1634
  • La création automatique de PVC ne plante plus avec un 500 mal formé — le correctif de référence du propriétaire du PVC est passé par un chemin _content_type non pris en charge qui a généré ApiTypeError (laissant les PVC sans références de propriétaire) et SandboxErrorCodes.INTERNAL_ERROR n'était pas défini, masquant la véritable erreur. Tous deux corrigés : le correctif utilise le chemin call_api de fusion stratégique pris en charge ; code d'erreur défini. #1538 #1447
  • Le conteneur de modèles securityContext atteint désormais les pods — la fusion profonde remplaçait auparavant les conteneurs du modèle, supprimant silencieusement le securityContext au niveau du conteneur. Les clés de modèle complètent désormais (ne remplacent jamais) les valeurs d'exécution, correspondant à la philosophie volumeMounts existante. #1564
  • Les redirections backend relatives à la racine restent sous la route proxy — Location: /login d'un backend sandbox est rebasé en /v1/sandboxes/{id}/proxy/{port}/login ; les références absolues, de chemin réseau et de requête uniquement restent intactes. #1516
  • Les points de terminaison du serveur proxy suppriment l'en-tête de routage d'entrée — OpenSandbox-Ingress-To (insensible à la casse) est supprimé des réponses use_server_proxy=true tandis que l'accès sécurisé et les autres en-têtes de point de terminaison sont préservés. #1503
  • Pas d'en-têtes Date/Server en double sur les réponses proxy — le proxy préserve une origine Date tout en supprimant la valeur par défaut d'Uvicorn (et l'en-tête backend Server), émettant exactement un Date. #1471
  • L'erreur de reprise invalide ne fait plus fuir les composants internes du contrôleur — le message 409 pour un bac à sable en cours d'exécution (réussite en interne) indique désormais « état en cours d'exécution » au lieu de « phase réussie » ; Statut HTTP et code d'erreur inchangés. #1586
  • Limites de CPU non finies rejetées — Les valeurs nan, infinies et dépassées sont rejetées avant la conversion du NanoCpus Docker au lieu d'être acceptées en silence. #1568
  • Montages mixtes de sous-chemins PVC en lecture seule autorisés — la source PVC est définie en lecture seule lorsque chaque montage de la revendication est en lecture seule ; le rejet au niveau du service qui bloquait la création légitime de PVC à politiques mixtes est supprimé. #1440
  • Résolution des points de terminaison du serveur proxy agent-sandbox : la résolution interne des points de terminaison délègue désormais au fournisseur de charge de travail et lit les adresses des pods agent-sandbox à partir de status.podIPs au lieu de l'annotation BatchSandbox uniquement, et met entre crochets les littéraux IPv6 avant d'ajouter le port. #1424
  • Rapport de version corrigé partout — /openapi.json, les métadonnées du package installé et le graphique appVersion ont tous signalé un 0.1.0 obsolète ; le serveur lit désormais sa version à partir des métadonnées du package au moment de l'exécution, les builds injectent SETUPTOOLS_SCM_PRETEND_VERSION et le script de version supprime Chart.yaml appVersion. #1439

📦 Divers

  • exécuté v1.0.22 est livré avec le durcissement en mode init OSEP-0018 — exécuté en tant qu'initialisation sandbox (PID 1) avec plancher de durcissement pré-exécution (bande d'environnement, ensemble de délimitation, no_new_privs, suppression d'identité, plafonds ambiants, seccomp) et durcissement Kubernetes e2e + couverture PTY/bwrap. #1474 #1555
  • Porte de cycle de vie de charge de travail fermée en cas de session isolée : le serveur distribue une porte de cycle de vie Bubblewrap native à /opt/opensandbox pour les deux environnements d'exécution ; les charges de travail restent bloquées jusqu'à ce qu'execd les marque comme prêtes. Première phase uniquement : l'admission des capacités et la mise en réseau des sessions restent désactivées. #1388
  • Le MITM transparent de sortie peut intercepter des ports TCP supplémentaires — le OPENSANDBOX_EGRESS_MITMPROXY_EXTRA_PORTS expérimental ajoute des ports au 80/443 toujours actif avec une validation de fermeture en cas d'échec (plafond multiport 15) ; La liaison des informations d'identification s'applique toujours aux ports canoniques uniquement. #1379
  • Bumps automatiques — egress v1.1.5 → v1.1.7 (#1391 #1498 #1600) ; execd v1.0.22 (#1501).

OpenSandbox server/v0.2.3

Highlights

  • Egress sandbox attribution is now server-owned — remove OPENSANDBOX_EGRESS_SANDBOX_ID from request env; Docker and Kubernetes now inject it themselves, and client-supplied values receive HTTP 400 instead of being accepted as spoofable attribution. #1381
  • Lifecycle hooks are Kubernetes-only in this release — preStart and periodic hooks reach execd through OPEN_SANDBOX_LIFECYCLE, with aligned Java/Kotlin, Python, and TypeScript SDK models. Docker explicitly rejects lifecycle requests, PATCH is unsupported, preStart.timeoutSeconds now allows 10,800 seconds, and periodic hooks remain capped at 300 seconds. #1588 #1589 #1637
  • Pause/resume preserves live QEMU state, not just disk contents — opt-in runc support captures guest memory, vCPU, and device state through QMP, storing rootfs and compressed VMState as separate digest-addressed OCI images. Pooled BatchSandbox pause, detachment, and standalone restoration preserve guest memory, writable disks, boot IDs, and counters; rootfs-only snapshots remain compatible. #1584
  • Kubernetes pool exhaustion now has an actionable backpressure contract — new allocation conditions and kubernetes.pool_acquisition_timeout_seconds (default 30s) replace generic 504s with HTTP 429, KUBERNETES::POOL_CAPACITY_EXHAUSTED, and Retry-After: 5; clients should update capacity-related retry handling. getSandbox also exposes allocation state for concrete pool references without leaking pod, namespace, or IP data. #1581 #1481
  • Regenerate proxy clients and migrate diagnostics callers — the 20 proxied operations now have unique, deterministic OpenAPI operation IDs, so generated clients should be rebuilt despite unchanged runtime dispatch. Diagnostics require explicit logs/events scopes; unsupported scopes return 400, while deprecated unscoped plain-text responses remain available with a Deprecation header. #1634 #1553
  • Secure-access keys can stay out of Git, but startup validation becomes stricter — gateway deployments can source signing keys from a Kubernetes Secret through server.gateway.secureAccess.existingSecret, mutually exclusive with plaintext keys. Ensure configured tenant namespaces exist and are accessible before startup, since missing or inaccessible namespaces now cause a fatal error rather than request-time failures. #1445 #1389

What's New

⚠️ Breaking Changes

  • OPENSANDBOX_EGRESS_SANDBOX_ID is now server-injected and rejected in request env — the server unconditionally sets the egress sidecar's sandbox-id attribution variable in both Docker and Kubernetes runtimes, and removed it from the env allowlist. Requests that pass it in env now get a 400 instead of a user-spoofable value. #1381

✨ Features

  • Sandbox lifecycle hooks (preStart / periodic), OSEP-0020 — CreateSandboxRequest.lifecycle is accepted, validated (reserved transports, duplicate periodic names, pool-allocation combinations), and transported to Kubernetes workloads via the reserved OPEN_SANDBOX_LIFECYCLE env for execd to execute. Docker explicitly rejects lifecycle requests; PATCH and other hook types are out of scope. Ships with aligned Java/Kotlin, Python, and TypeScript SDK models. #1588 #1589

  • preStart.timeoutSeconds limit raised from 300s to 3 hours — server and OpenAPI limits now allow up to 10800s for pre-start hooks; the periodic limit stays at 300s. The execd-side product policy bound is removed, keeping policy changes server-only. #1637

  • QEMU VMState pause/resume for runc-based sandboxes — opt-in capture of guest memory/vCPU/device state via QMP migration; rootfs and compressed VMState are stored as separate OCI images keyed by immutable SHA-256 digests. Supports pooled BatchSandbox pause, detachment, and standalone restoration while preserving guest memory, writable disk, boot ID, and counter continuity. Rootfs-only snapshots remain backward compatible. #1584

  • Pool capacity exhaustion is now machine-identifiable — the controller publishes a PoolAllocationPending/PoolCapacityExhausted condition; the server waits a bounded acquisition window (new kubernetes.pool_acquisition_timeout_seconds, default 30s) and then returns HTTP 429 with KUBERNETES::POOL_CAPACITY_EXHAUSTED and Retry-After: 5 instead of the generic 504 readiness timeout. Older controllers safely fall back to the existing behavior. #1581

  • Pool allocation summary in lifecycle responses — getSandbox now surfaces an optional Sandbox.allocation block (mode: pool, poolRef, state: allocated) for confirmed Kubernetes pool allocations, emitted only for concrete non-wildcard pool references with matching allocation evidence. No pod/namespace/IP data is exposed. #1481

  • Generic HTTP request metrics via OTLP — a thin ASGI middleware exports server.http.request.duration (ms) with http_method, matched http_route (or unknown for unrouted/auth-failed requests), and http_status_code attributes, complementing the existing create-duration histogram. Raw paths, IDs, keys, and bodies are never attributes; no-op when [otel] is disabled. #1561

  • Stable diagnostics API with scopes — diagnostics now honor the public inline descriptor contract: logs: container|all and events: runtime|lifecycle|all, with 400 DIAGNOSTICS_SCOPE_UNSUPPORTED for unknown scopes and explicit warnings for incomplete best-effort scopes. Deprecated no-scope plain-text responses still work with a Deprecation header. #1553

  • fast-sandbox fleets backend groundwork (OSEP-0007) — a FastPath v2 gRPC client wraps all FastPathService RPCs with typed error mapping (FastPathNotFound → 404, etc.), and a create/status mapping layer converts the public contract to fast-sandbox semantics, rejecting unsupported fields (volumes, platform, resourceRequests, credentialProxy, snapshotId, etc.) with clear errors. Not yet wired as an active runtime. #1558 #1559

  • Secure-access signing keys can come from a Kubernetes Secret — the server accepts OPENSANDBOX_SECURE_ACCESS_KEYS / OPENSANDBOX_SECURE_ACCESS_ACTIVE_KEY env overrides (mirroring the API-key override, gateway mode required), and the Helm chart adds server.gateway.secureAccess.existingSecret (mutually exclusive with plaintext keys, enforced at render time) so GitOps flows never commit key material. #1445

  • Docker runtime sandbox_env / sandbox_binds — new [docker] fields apply fleet-wide environment variables and host bind mounts to every sandbox container (request env wins over sandbox_env; config binds precede request-derived binds), giving the Docker runtime the operator-side hook the K8s pod template has. #1303

  • Egress sidecar readiness timeout configurable — new [egress] timeout_seconds (default 30s, non-positive values rejected) lets Docker deployments tune how long the server waits for the sidecar health endpoint. #1522

  • Tenant namespaces validated at startup (OSEP-0014) — the server fail-fast verifies every tenant namespace exists and is accessible before serving traffic, aggregating all missing/inaccessible namespaces into a single fatal error instead of failing only at request time. OSEP-0004/0005/0014 marked implemented. #1389

🔒 Security

  • CVE-remediating dependency bumps — google.golang.org/grpc → v1.82.1 across kubernetes/ingress/execd/egress/internal (xDS RBAC and HTTP/2 fixes), postcss → 8.5.11 (arbitrary file read via sourceMappingURL). #1385

🐛 Bug Fixes

  • Docker endpoint lookups ~108x faster — container lookup now goes through the deterministic sandbox-<id> name with opensandbox.io/id label validation, falling back to the label scan only when needed. Local benchmark: 6.07s → 56ms for execd+egress endpoint resolution. #1400

  • Informer cache expires when the watch stalls — has_synced now means "cache is currently live", not "an initial list finished once"; a stalled or half-open watch (e.g. after a control-plane upgrade) degrades to direct API reads instead of serving frozen status forever, which previously caused every create to 504 with POD_READY_TIMEOUT. Bound derived from existing knobs (resync_period + watch_timeout); no new config. #1534

  • Proxy connection leak on aborted responses — when a downstream client disconnected before response-body streaming started, the backend httpx response was never released, gradually exhausting the shared pool until httpcore.PoolTimeout. The proxy now owns the backend response for the full ASGI lifecycle, shields aclose() from cancellation, and releases on setup failure. Stress test: 1000/1000 disconnects cleaned up. #1488

  • Unique, stable proxy operation IDs — the 20 proxied HTTP operations previously emitted 4 process-dependent duplicate operation IDs (16 OpenAPI warnings); each method now gets its own deterministic ID with identical runtime dispatch, auth, and 405 behavior. Generated clients should be regenerated. #1634

  • PVC auto-create no longer crashes with a malformed 500 — the PVC owner-reference patch went through an unsupported _content_type path that raised ApiTypeError (leaving PVCs without owner refs) and SandboxErrorCodes.INTERNAL_ERROR was undefined, masking the real error. Both fixed: patch uses the supported strategic-merge call_api path; error code defined. #1538 #1447

  • Template container securityContext now reaches pods — the deep-merge previously replaced the template's containers wholesale, silently dropping container-level securityContext. Template keys now supplement (never override) runtime values, matching the existing volumeMounts philosophy. #1564

  • Root-relative backend redirects stay under the proxy route — Location: /login from a sandbox backend is rebased to /v1/sandboxes/{id}/proxy/{port}/login; absolute, network-path, and query-only references are left untouched. #1516

  • Server-proxy endpoints drop the ingress routing header — OpenSandbox-Ingress-To (case-insensitive) is removed from use_server_proxy=true responses while secure-access and other endpoint headers are preserved. #1503

  • No duplicate Date/Server headers on proxied responses — the proxy preserves an origin Date while suppressing Uvicorn's default (and the backend Server header), emitting exactly one Date. #1471

  • Invalid-resume error no longer leaks controller internals — the 409 message for a Running (internally Succeed) sandbox now says "state Running" instead of "phase Succeed"; HTTP status and error code unchanged. #1586

  • Non-finite CPU limits rejected — nan, infinite, and overflowed values are rejected before Docker NanoCpus conversion instead of being silently accepted. #1568

  • Mixed read-only PVC subPath mounts allowed — the PVC source is set read-only only when every mount of the claim is read-only; the service-level rejection that blocked legitimate mixed-policy PVC creation is removed. #1440

  • Agent-sandbox server-proxy endpoints resolve — internal endpoint resolution now delegates to the workload provider and reads agent-sandbox pod addresses from status.podIPs instead of the BatchSandbox-only annotation, and brackets IPv6 literals before appending the port. #1424

  • Version reporting fixed everywhere — /openapi.json, installed package metadata, and the chart appVersion all reported stale 0.1.0; the server now reads its version from package metadata at runtime, builds inject SETUPTOOLS_SCM_PRETEND_VERSION, and the release script bumps Chart.yaml appVersion. #1439

📦 Misc

  • execd v1.0.22 ships OSEP-0018 init-mode hardening — execd as sandbox init (PID 1) with pre-exec hardening floor (env strip, bounding set, no_new_privs, identity drop, ambient caps, seccomp) and Kubernetes hardening e2e + PTY/bwrap coverage. #1474 #1555

  • Isolated-session fail-closed workload lifecycle gate — the server distributes a native Bubblewrap lifecycle gate to /opt/opensandbox for both runtimes; workloads stay blocked until execd marks them ready. First phase only — capability admission and session networking remain disabled. #1388

  • Egress transparent MITM can intercept extra TCP ports — experimental OPENSANDBOX_EGRESS_MITMPROXY_EXTRA_PORTS appends ports to the always-on 80/443 with fail-closed validation (multiport cap 15); credential binding still applies to canonical ports only. #1379

  • Auto-bumps — egress v1.1.5 → v1.1.7 (#1391 #1498 #1600); execd v1.0.22 (#1501).
