Version OpenSandbox-1.2.0-rc.2

Deuxième version candidate sur la ligne 1.2.0, contenant tout ce qui a été fusionné depuis release-1.2.0-rc.1 — le titre est l'atterrissage de bout en bout du Credential Vault (OSEP-0022) pour les bacs à sable rapides : un coffre-fort de sortie avec une persistance durable par sujet et un transfert pause/reprise, le coffre-fort acheminé par serveur accessible par l'utilisateur API et une autorité de certification MITM épinglée en pool. La politique réseau suit le même modèle de sortie, et NetworkRule bénéficie de règles de port dans le profil classique : les bacs à sable rapides les rejettent en cas de fermeture en cas d'échec jusqu'à ce que le chemin fastlet nft les applique. Les images sont publiées maintenant ; Les packages SDK/CLI sont expédiés sur la bosse stable 1.2.0. Veuillez tester et signaler les problèmes.

Faits saillants

  • Credential Vault (OSEP-0022) est mis bout à bout pour les bacs à sable rapides : le side-car de sortie contient le coffre-fort avec des fichiers durables par sujet, un transfert d'instantané scellé pour la pause/reprise et la reprise du sujet obsolète lors de la réutilisation de l'emplacement (#2249 #2252 #2255 #2250); le serveur expose le POST|GET|PATCH|DELETE /v1/sandboxes/{id}/credential-vault API accessible à l'utilisateur sur le relais du gestionnaire FastPath avec des valeurs d'informations d'identification n'apparaissant jamais lors d'une lecture publique (#2263), et l'autorité de certification MITM est épinglée par pool, de sorte qu'un redémarrage de sortie ne fait plus tourner l'ancre trust sous les bacs à sable en direct (#2251)
  • La politique réseau reflète le coffre-fort : la politique de bac à sable rapide enregistrée devient un état de sortie avec relais CRUD, persistance durable et pause/reprise du transfert d'instantanés (#2309), et NetworkRule obtient des règles de port de bout en bout dans le profil classique - spécifications, nftables side-car, validation du serveur et les cinq SDK, tandis que les bacs à sable rapides rejettent la fermeture en cas d'échec de ports pour l'instant. - plus un port TCP côté opérateur qu'aucune stratégie utilisateur ne peut ouvrir (#2212)
  • Peaufinage du cycle de vie et des diagnostics : lifecycle.renewalPolicy remplace la clé de renouvellement opaque des extensions (OSEP-0009) (#2296) ; le contexte de diagnostic API atteint le serveur, les cinq SDK et le CLI (#2292) ; Les correctifs excd permettent de distinguer les échecs de démarrage, de préserver la sortie de session octet par octet et d'arrêter la croissance silencieuse du disque (#2303 #2318 #2295)

Serveur

  • Implémentation du côté serveur du Credential Vault (OSEP-0022, profil fast-sandbox) : le POST|GET|PATCH|DELETE /v1/sandboxes/{id}/credential-vault API, accessible par l'utilisateur, transmet les révisions complètes du coffre-fort via le relais du gestionnaire FastPath InvokeHandlerAction et traite la réponse du relais comme un accusé de réception synchrone validé en sortie ; le CRD ne transporte jamais de matériel du coffre-fort et chaque lecture publique est nettoyée côté serveur ; PATCH compose en mémoire (delete → replace → add, chaque nom étant résolu au plus une fois) avec expectedRevision comme backstop de réplique croisée, les backends non fsb proxy la surface /credential-vault du side-car et le rejet au moment de la création du fsb credentialProxy est levé (#2263)
  • Intégrez l'autorité de certification MITM épinglée dans des SandboxTemplates créés par le serveur (OSEP-0022) : la nouvelle configuration [kubernetes] template_mitm_ca_secret / template_mitm_ca_secret_key (désactivée par défaut) émet spec.egressMitmCertificate — l'entrée du certificat uniquement, jamais la clé privée — sur chaque modèle créé par le serveur ; le secret doit exister dans chaque espace de noms de modèle (distribution ops-runbook), et une copie manquée fait échouer la construction de manière observable (#2288)
  • Ajouter lifecycle.renewalPolicy (OSEP-0009) : l'option de renouvellement à l'accès passe de la clé de création opaque extensions["access.renew.extend.seconds"] à une clé renewalPolicy.extendSeconds structurée (300–86400), reflétant le modèle idlePolicy ; la clé héritée est obsolète (prise en charge dans 1.x, supprimée dans 2.0), la définition des deux n'est acceptée que lorsque les valeurs analysées correspondent, la valeur se normalise dans l'étiquette Docker existante / l'annotation Kubernetes afin que les bacs à sable de pré-mise à niveau continuent de se renouveler, et le bac à sable rapide le rejette avec 400 plutôt que d'accepter silencieusement un non-opération (#2296)
  • Implémentez le point de terminaison du contexte de diagnostic (contrat OSEP de rc.1) : GET /v1/sandboxes/{sandboxId}/diagnostics/context renvoie l'ID du bac à sable, l'état du cycle de vie, le type de back-end et les identifiants définis par le back-end pour Docker, Kubernetes et Fast Sandbox sans se connecter à execd – Le contexte Kubernetes reste disponible avant qu'un pod ne soit alloué, et les backends d'extension qui ne l'implémentent pas renvoient 501 (#2292)
  • Transférer le chemin encore codé via le proxy sandbox : Starlette a lié la route {full_path:path} à partir du chemin décodé en pourcentage et le proxy a recollé cette valeur dans l'URL en amont, donc un ? décodé a lancé une requête, # un fragment, %2F est devenu un séparateur, %25 et les échappements non UTF-8 ont été réécrits et les segments %2E%2E ont été résolus - le proxy maintenant prend la queue encore codée du client du chemin brut (en validant son décodage vers le chemin routé, avec un repli de réencodage) et lit la requête à partir de la chaîne de requête brute ; les backends reçoivent les cibles de requête octet par octet, correspondant à la passerelle d'entrée, et l'échappement du préfixe %2E%2E sur les points de terminaison mappés par l'hôte Docker est fermé (#2228)
  • Signaler l'expiration de BatchSandbox pendant que le pod est toujours en cours d'exécution : un spec.expireTime passé était toujours signalé comme Running (pod prêt avec IP), donc la facturation de l'horloge murale a continué d'augmenter après le délai d'expiration configuré ; l'expiration vérifie maintenant avant les états prêts et renvoie Terminated / SANDBOX_EXPIRED avec last_transition_at défini sur le expireTime lui-même (#2238)
  • Rejeter les instantanés de gVisor qui supprimeraient silencieusement les écritures : docker commit sous le --overlay2=root:self par défaut de gVisor peut signaler READY tout en ne restaurant aucune des écritures du bac à sable (seule l'entrée opaque /.gvisor.filestore.* est visible) ; le contrôle en amont de l'instantané résout désormais le temps d'exécution du conteneur et refuse gVisor à moins que les arguments effectifs n'incluent --overlay2=none, et la création échoue lorsque le diff du système de fichiers est réservé au magasin de fichiers (#2241)
  • Appliquer les profils de sécurité [docker] et secure_runtime au conteneur de cache exécutable : il a ignoré apparmor_profile / seccomp_profile / docker_runtime, donc sur un hôte dont le profil seccomp par défaut bloque l'image exécutable, chaque POST /sandboxes a échoué 503 sans échappement de configuration (#2254)
  • Sécuriser les correctifs de métadonnées Docker simultanés : les fonctions de lecture-modification-écriture du magasin ont été déverrouillées et chaque écriture partageait un nom temporaire, donc deux requêtes PATCH /metadata simultanées pour un bac à sable se sont précipitées dans un 500 (FileNotFoundError lors du changement de nom) ou ont laissé tomber silencieusement la clé de l'autre ; un verrou à l'échelle du magasin ainsi que des noms temporaires par écriture sérialisent les correctifs (la dernière écriture gagne par clé), une écriture échouée ne laisse plus son fichier temporaire derrière elle et le contrat de point de terminaison est désormais documenté par runtime - les correctifs Kubernetes réécrivent l'ensemble de l'étiquette qu'il a lu, les correctifs fsb envoient uniquement leurs propres clés clôturées par l'UID et la génération (#2267 #2281)
  • Résoudre les points de terminaison du proxy hors de la boucle d'événements : les gestionnaires de proxy HTTP/WebSocket appellent directement le get_endpoint synchrone – un appel de socket Docker par requête mandatée sur Docker, un serveur api lu sur les échecs de cache Kubernetes – bloquant la boucle pour toutes les autres requêtes et flux ; un démon Docker lent (par exemple lors d'une extraction d'image) suffisait à geler le serveur ; la recherche s'exécute désormais via asyncio.to_thread avec le contexte du locataire préservé (#2268)
  • Appliquer le temps de recharge de renouvellement lorsque le consommateur Redis est activé : les renouvellements de proxy ont entièrement ignoré min_interval_seconds (chaque requête proxy a exécuté un renouvellement get_sandbox + expiration) et les intentions de file d'attente n'ont été limitées que par réplica d'entrée, donc N réplicas renouvelés jusqu'à N fois par intervalle ; le temps de recharge s'applique désormais à chaque source de renouvellement et ne démarre qu'après un renouvellement réussi (#2276 #2279)

SDK

Les modifications de code ci-dessous utilisent la version stable 1.2.0 – rc ne fournit aucun package SDK.

  • Ajoutez le contrat Credential Vault client aux cinq SDK (OSEP-0022) : les bacs à sable basés sur un modèle acheminent les appels du coffre-fort via le serveur sur le même signal d'origine du modèle que la politique réseau (OPEN-SANDBOX-ORIGIN: template ou l'indicateur createFromTemplate local), tandis que les adaptateurs directs side-car restent intacts ; Le Sandbox.credential_vault de Python renvoie désormais le service de coffre-fort pour les deux profils, et Go gagne des méthodes de coffre-fort au niveau Sandbox se branchant sur le même signal (#2263)
  • Ajoutez lifecycle.renewalPolicy aux cinq SDK (OSEP-0009) : un champ de création typé avec une validation rapide côté client (extendSeconds 300–86400) câblé via les convertisseurs de création, remplaçant la clé d'extensions opaque (#2296)
  • Implémenter des diagnostics sur la surface SDK (avec #2292) : context est exposé à la fois via les façades du gestionnaire et du bac à sable dans les cinq langues, et JavaScript, Go et C# obtiennent des journaux/événements publics API correspondant à la surface Python/JVM existante (les usines personnalisées continuent de fonctionner - le nouveau service de diagnostic est facultatif)
  • Prise en charge des règles de sortie au niveau du port dans les cinq SDK (#2212) : NetworkRule.ports (TCP 1–65535, au plus 256 par règle, target désormais facultatif) avec validation côté cli reflétant le serveur (plage, doublons, plafond, domaine+ports rejetés, masque de réseau-CIDR+ports rejetés) ; JavaScript code l'invariant cible ou ports en tant que type d'union, Python normalise une cible de fil vierge lors de la relecture ###Python
  • Arrêtez de propager une récupération de point de terminaison annulée aux serveurs : le cache de point de terminaison de récupération partagée définit le CancelledError de l'appelant récupérant sur le futur partagé, donc les serveurs simultanés - par ex. Frères et sœurs TaskGroup – ont élevé CancelledError bien que rien ne les ait annulés ; les serveurs se résolvent désormais à nouveau (point de terminaison mis en cache, récupération en vol plus récente ou le leur), tandis que l'appelant annulé relance toujours comme avant (#2277)
  • Transférer credential_proxy via les pools sandbox : PoolCreationSpec.credential_proxy a été supprimé par les chemins de création de synchronisation et asynchrone, de sorte que les sandbox d'échauffement et de création directe ont perdu silencieusement la configuration demandée du proxy d'informations d'identification ; les usines personnalisées restent compatibles (le mot-clé est omis lorsqu'il n'est pas défini) (#2283)
  • Régénérez le cycle de vie client pour supprimer les valeurs par défaut obsolètes (timeout_seconds: 2, wake_on_access: true → UNSET) laissées par le changement de spécification dans #2212 ; le comportement du fil est inchangé — le serveur applique les mêmes valeurs par défaut (#2280)

Aller

  • Authentifier les requêtes de plan de données proxy avec la clé API : le mode proxy a envoyé la clé API du locataire (un identifiant qui peut créer, mettre en pause et supprimer chaque bac à sable du locataire) dans le bac à sable untrust en tant que X-EXECD-ACCESS-TOKEN (et comme authentification de sortie) tout en omettant l'en-tête OPEN-SANDBOX-API-KEY lu par le middleware du serveur, de sorte que les requêtes de proxy multi-locataires ont échoué 401 et fait surface sous forme de délais d'attente de préparation ; la clé du locataire chevauche désormais l'en-tête du serveur et n'est jamais introduite clandestinement dans le bac à sable ou le side-car de sortie, les clés proxy fournies par le point de terminaison et par l'appelant l'emportent quelle que soit la casse, et le mode direct reste sans clé (#2274)

Contrôleur

  • Correction de l'exécuteur de tâches traitant un fichier de sortie vide comme code de sortie 0 : le shim crée le fichier de sortie avant de l'écrire, et Inspect a ignoré l'erreur d'analyse — un shim tué entre les deux (ou un échec d'écriture, par exemple un disque plein) a signalé une tâche échouée ou interrompue comme Succeeded ; un fichier invalide ou vide passe désormais à la vérification pid (Running en vie, ProcessCrashed une fois parti) (#2270)

Exécuté

  • Préserver les fins de ligne de sortie de la session bash : les événements stdout run_in_session supprimaient les octets \n/\r, donc les lignes vides étaient irrécupérables et la concaténation des événements d'une exécution ne reconstruisait pas sa sortie ; le texte de l'événement porte désormais sa fin de ligne d'origine (les lignes vierges apparaissent sous forme d'événements contenant uniquement la fin), alignant le flux de session avec le contrat /command de premier plan — les consommateurs doivent concaténer le texte de l'événement par exécution au lieu de traiter chaque événement comme une ligne sans nouvelle ligne (#2318)
  • Signaler exit_code sur les erreurs de commande : une commande qui s'est exécutée et s'est terminée avec une valeur non nulle et une commande dont le processus n'a jamais démarré (par exemple fork/exec: argument list too long) a signalé le même événement d'erreur, donc clients lisant l'état de sortie de evalue pourrait signaler un échec de démarrage comme un succès ; le nouveau error.exit_code en option est présent uniquement lorsque le processus s'est exécuté et s'est terminé non nul (-1 à la fin du signal) (#2303)
  • Servir les points de montage binds via les fichiers de session isolés API : le routeur à vue fusionnée n'a enregistré que les montages de superposition, donc session.files a échoué avec ErrPathOutsideOverlays sur les mêmes destinations de liaison que session.run pouvait lire ; chaque liaison enregistre désormais une vue acheminée (dest → source, les liaisons en lecture seule rejettent les écritures, les vues de liaison masquent les superpositions sur les liens de préfixe) (#2299)
  • Tronquer les fichiers de sortie des commandes avant de les dissocier : les enfants forkés (démons) survivent légitimement aux commandes tout en conservant le fd de sortie, de sorte qu'un fichier non lié a continué à consommer le disque en tant que croissance invisible de (deleted) jusqu'à la sortie du dernier détenteur ; chaque point de suppression existant est désormais tronqué à zéro en premier, et la sortie en arrière-plan n'est touchée qu'au moment de la suppression par le concierge afin que la fenêtre de rétention reste lisible (#2295)
  • Omettre les métriques d'utilisation supérieure non valides en cas d'erreurs d'analyse : une analyse échouée du système de fichiers a émis un execd.isolation.upper.usage_bytes trompeur de 0 alors que les sessions et les données existaient encore ; les lectures invalides sont désormais omises (un supérieur vide valide indique toujours 0), et l'admission du quota échoue lorsque upper_max_bytes > 0 et une analyse échoue au lieu de contourner silencieusement la comptabilité (#2257)
  • Évitez les importations redondantes de JDK MITM CA : les bacs à sable avec plusieurs JDK installés partagent souvent un magasin trust, mais chaque JDK a réexécuté l'importation de keytool (~6.2 pour quatre JDK) ; l'initialisation est désormais dédupliquée par le chemin du magasin trust résolu avec comparaison du contenu des certificats, coupant l'étape à ~0.6 s tout en remplaçant les certificats en rotation (#2310)
  • Sessions PTY par défaut sur TERM=xterm-256color lorsque l'environnement utilisateur résolu n'a pas de TERM utilisable, donc les programmes interactifs obtiennent des couleurs ; un TERM explicite gagne toujours (#2313)

Réseautage

sortie

Les éléments du coffre-fort OSEP-0022 concernent la surface du coffre-fort d'identification du profil fast-sandbox ; les suivis d'OSEP-0023 restent limités à l'exécution de la révision expérimentale par défaut.

  • Ajout du coffre-fort de sortie pour les bacs à sable rapides (OSEP-0022), atterrissage par étapes : la surface de relais interne /vault/{sandboxUid} avec POST de création uniquement (409 en double, atomique sur les réplicas de serveur), PUT en révision complète avec expectedRevision et une condition préalable expectedIncarnation afin qu'un écrivain obsolète ne puisse jamais atterrir sur le successeur d'une réinitialisation, GET incluant la valeur et DELETE qui conserve la politique. (#2249); persistance durable par sujet — un fichier par sujet sous un volume limité au pod (tmpfs facultatif), le même protocole de validation que les fichiers de stratégie, donc acked signifie durable et appliqué, rechargement clôturé par l'incarnation et purge lors de la dissociation (#2252) ; et la route de coffre-fort fastlet-proxy remplacée supprimée avec son cache push en attente (#2247)
  • Porter le coffre-fort en pause/reprise (OSEP-0022 « Cycle de vie du coffre-fort ») : VAULT_EXPORT copie le fichier du coffre-fort dans le bundle d'instantanés strictement avant le démontage de l'exécution et scelle le sujet (toutes les opérations du coffre-fort répondent à 409 pendant la pause ; l'application continue), et VAULT_IMPORT est le seul transfert d'incarnation autorisé — le bundle est ré-estampillé avec la clôture restaurée avant data-plane-ready, validé par rapport à la politique actuelle avant tout effet durable ; un véritable échec d'exportation laisse le sujet descellé et échoue au point de contrôle de pause, donc le démontage ne s'exécute jamais sans un bundle et le coffre-fort local de sortie survit pendant la nouvelle tentative (#2255) ; un signal de capacité vaultTransfer permet à une sortie sans persistance du coffre-fort d'ignorer complètement le transfert — le point de contrôle se déroule sans le coffre-fort (sémantique de pré-transfert) au lieu d'échouer (#2290)
  • Définir la reprise de sujet obsolète lors de la réutilisation des emplacements : la clé de répartition rapide du bac à sable est l'adresse IP de l'emplacement et les emplacements sont réutilisés, de sorte qu'un SET_BINDING peut revendiquer une clé toujours détenue par un sujet mort mais enregistré - la sortie traite désormais cela comme faisant autorité, supprimant les règles nft du sujet obsolète, le refcount DNS, la redirection MITM et la tranche de coffre-fort sous le verrou de registre avant d'enregistrer le successeur refusé en premier ; le trafic n'est jamais soumis à des règles obsolètes, les déchargements tardifs restent bloqués et chaque chemin d'échec laisse chaque sujet soit entièrement enregistré, soit entièrement expulsé (#2250)
  • Épinglez l'autorité de certification MITM du bac à sable rapide (OSEP-0022 "MITM Trust Anchor") : l'autorité de certification versionnée et épinglée dans le pool est amorcée à partir d'un montage secret en lecture seule dans le répertoire de configuration mitmdump (idempotent, fermé par échec sur une paire non téléchargeable), remplaçant la génération au démarrage - un redémarrage de sortie ne fait plus tourner l'autorité de certification et invalide silencieusement le TLS trust de chaque bac à sable en direct ; une autorité de certification manquante ou incompatible refuse uniquement le module complémentaire MITM (application de la politique non affectée) avec mitmCaFingerprint / mitmCaDown apparaissant sur /healthz et le statut des actions, donc une erreur de couplage de modèle et de secret de pool est visible en un coup d'œil (#2251)
  • Alignez la politique réseau du bac à sable rapide avec le modèle de coffre-fort : la politique enregistrée devient un état de sortie – une surface de relais /policy/{sandboxUid} avec des conditions préalables de révision (sujet inconnu 404, incompatibilité d'incarnation 412, scellé 409), des fichiers durables par sujet utilisant le même protocole de validation, un transfert d'instantané POLICY_EXPORT/POLICY_IMPORT reflétant le coffre-fort et, après un redémarrage de sortie, le fichier validé remplaçant le entrée de liaison rejouée au moment de la création (#2309)
  • Prise en charge des règles de sortie au niveau du port de bout en bout (profil classique) : NetworkRule.ports (TCP 1–65535, ≤256 par règle) rend target facultatif : règles de port uniquement ou ports combinés avec un IP/CIDR ; domain+ports est rejeté car les règles de domaine sont évaluées au niveau de la couche proxy DNS ; la priorité de refus avant d'autoriser est maintenue dans toute la portée, et un bogue de clé de fusion PATCH qui permettait à une deuxième règle de port uniquement d'expulser la première est corrigé ; une liste blanche reachable.ports.cap expédiée par l'opérateur est appliquée comme une règle de refus permanent avant chaque utilisateur, de sorte que même defaultAction: allow ne peut pas ouvrir un port ne figurant pas sur la liste blanche ; la route fast-sandbox rejette ports avec 400 jusqu'à ce que le chemin fastlet nft puisse les appliquer (fermé en cas d'échec, documenté) (#2212)
  • Ajoutez des sélecteurs passthrough TLS statiques au runtime expérimental de révision en direct : OPENSANDBOX_EGRESS_MITMPROXY_PASSTHROUGH_HOSTS est un tableau d'hôtes exact/wildcard limité appliqué à ClientHello avec un rejet de 443 chevauchements ; ignore_hosts/allow_hosts natif non vide existant maintenant rejeter le démarrage en mode direct — migrer les entrées de contournement TLS statiques vers le tableau (mode hérité inchangé, aucun mode d'interception public ajouté) (#2229)
  • Émettre des compteurs d'admission TLS : un événement au mieux par flux d'admission final ClientHello egress.mitm.tls.connections_total avec des étiquettes mode/decision/reason fermées — il mesure les décisions d'admission, pas les poignées de main ou les demandes, et ne constitue explicitement pas une preuve de sécurité (#2265)
  • Ajouter la base IPC de révision de sujet d'installation uniquement (OSEP-0023 Phase 4) : un canal de socket Unix v2 authentifié achemine les transactions de révision liées à la cible vers des récepteurs d'installation indépendants à admission désactivée avec des octets de requête gelés et une réconciliation des réponses perdues ; aucun appelant de production pour l'instant (#2284)
  • Expédiez egress-trace, un visualiseur d'admission en lecture seule à l'intérieur de l'image de sortie : état de politique en direct, ensembles nft et baux DNS avec TTL, connexions sortantes réelles annotées avec leur verdict d'admission et une sous-commande probe <domain> séparant le refus de politique de l'échec du résolveur ; aucun changement de comportement du side-car et le contenu L7 déchiffré n'est délibérément jamais affiché (#2230)

Divers

  • Console : obtenez le troisième des cinq PR de console prévus – opérations d'administration et de plate-forme, avec agrégation /api/admin/sandboxes, proxy détaillé par locataire, pools API (documentés comme non isolés par locataire) et liste/pools/aperçu global du bac à sable d'administration dans l'interface utilisateur Web (#2131) ; conserver les réponses en amont vides et réussies dans le proxy BFF au lieu d'échouer le décodage JSON le 200/201/205 (#2271)
  • CLI : ajoutez osb terminal <sandbox-id>, attachant le terminal local à un véritable PTY à l'intérieur du bac à sable via le PTY WebSocket exécuté – mode brut avec redimensionnement piloté par SIGWINCH, relecture à la reconnexion, propagation du code de sortie à distance et prise en charge des modes de connexion directe et serveur-proxy (TTY interactif, POSIX) (#2313) ; signaler les entrées de durée hors plage en tant qu'erreurs de validation Click au lieu de OverflowError/ValueError non détectés (#2272)
  • OSEP : révision de l'OSEP-0022 – le coffre-fort utilise la liaison d'action en tant que révision scellée AES-256-GCM sur un canal de contrôle, avec le CA épinglé par pool comme ancre MITM trust (#2174) ; la demande prévue du pilote d'exécution OpenSandbox est retirée (le pilote de pétard est livré tel quel ; le timing de refus en premier remplace la sonde healthz de pré-création) (#2259) ; La distribution de l'espace de noms MITM CA devient une condition préalable au déploiement d'ops-runbook au lieu d'un contrôleur de synchronisation résident (#2282)

OpenSandbox release-1.2.0-rc.2

Second release candidate on the 1.2.0 line, carrying everything merged since release-1.2.0-rc.1 — the headline is the Credential Vault (OSEP-0022) landing end to end for fast sandboxes: an egress-held vault with durable per-subject persistence and pause/resume transfer, the user-reachable server-routed vault API, and a pool-pinned MITM CA. Network policy follows the same egress-held pattern, and NetworkRule gains port-scoped rules in the classic profile — fast sandboxes reject them fail-closed until the fastlet nft path enforces them. Images publish now; SDK/CLI packages ship at the 1.2.0 stable bump. Please test and report issues.

Highlights

  • Credential Vault (OSEP-0022) lands end to end for fast sandboxes: the egress sidecar holds the vault with durable per-subject files, sealed snapshot transfer for pause/resume, and stale-subject takeover on slot reuse (#2249 #2252 #2255 #2250); the server exposes the user-reachable POST|GET|PATCH|DELETE /v1/sandboxes/{id}/credential-vault API over the FastPath handler relay with credential values never appearing on any public read (#2263), and the MITM CA is pinned per pool so an egress restart no longer rotates the trust anchor under live sandboxes (#2251)
  • Network policy mirrors the vault: the recorded fast-sandbox policy becomes egress-held state with relay CRUD, durable persistence, and pause/resume snapshot transfer (#2309), and NetworkRule gains port-scoped rules end to end in the classic profile — spec, sidecar nftables, server validation, and all five SDKs, while fast sandboxes reject ports fail-closed for now — plus an operator-side TCP port floor that no user policy can open (#2212)
  • Lifecycle and diagnostics polish: lifecycle.renewalPolicy replaces the opaque renew extensions key (OSEP-0009) (#2296); the diagnostics context API reaches server, all five SDKs, and the CLI (#2292); execd fixes make start failures distinguishable, preserve session output byte-for-byte, and stop silent disk growth (#2303 #2318 #2295)

Server

  • Implement the server side of the Credential Vault (OSEP-0022, fast-sandbox profile): the user-reachable POST|GET|PATCH|DELETE /v1/sandboxes/{id}/credential-vault API pushes complete vault revisions over the FastPath InvokeHandlerAction handler relay and treats the relay response as the synchronous egress-validated ack — the CRD never carries vault material, and every public read is sanitized server-side; PATCH composes in memory (delete → replace → add, each name resolving at most once) with expectedRevision as the cross-replica backstop, non-fsb backends proxy the sidecar's /credential-vault surface, and the fsb credentialProxy create-time rejection is lifted (#2263)
  • Bake the pinned MITM CA into server-created SandboxTemplates (OSEP-0022): new [kubernetes] template_mitm_ca_secret / template_mitm_ca_secret_key config (default off) emits spec.egressMitmCertificate — the certificate entry only, never the private key — on every server-created template; the Secret must exist in each template namespace (ops-runbook distribution), and a missed copy fails the build observably (#2288)
  • Add lifecycle.renewalPolicy (OSEP-0009): the renew-on-access opt-in moves from the opaque extensions["access.renew.extend.seconds"] create key to a structured renewalPolicy.extendSeconds (300–86400), mirroring the idlePolicy pattern; the legacy key is deprecated (supported throughout 1.x, removed in 2.0), setting both is accepted only when the parsed values match, the value normalizes into the existing Docker label / Kubernetes annotation so pre-upgrade sandboxes keep renewing, and fast sandbox rejects it with 400 rather than silently accepting a no-op (#2296)
  • Implement the diagnostics context endpoint (OSEP contract from rc.1): GET /v1/sandboxes/{sandboxId}/diagnostics/context returns the sandbox ID, lifecycle state, backend type, and backend-defined identifiers for Docker, Kubernetes, and Fast Sandbox without connecting to execd — Kubernetes context stays available before a Pod is allocated, and extension backends that don't implement it return 501 (#2292)
  • Forward the still-encoded path through the sandbox proxy: Starlette bound the {full_path:path} route from the percent-decoded path and the proxy pasted that value back into the upstream URL, so a decoded ? started a query, # a fragment, %2F became a separator, %25 and non-UTF-8 escapes were rewritten, and %2E%2E segments were resolved — the proxy now takes the client's still-encoded tail from the raw path (validating it decodes to the routed path, with a re-encode fallback) and reads the query from the raw query string; backends receive request targets byte-for-byte, matching the ingress gateway, and the %2E%2E prefix-escape on Docker host-mapped endpoints is closed (#2228)
  • Report BatchSandbox expiry while the pod is still Running: a past spec.expireTime was still reported as Running (Ready pod with IP), so wall-clock billing kept growing after the configured timeout; expiry now checks before the ready states and returns Terminated / SANDBOX_EXPIRED with last_transition_at set to the expireTime itself (#2238)
  • Reject gVisor snapshots that would silently drop writes: docker commit under gVisor's default --overlay2=root:self can report READY while restoring none of the sandbox's writes (only the opaque /.gvisor.filestore.* entry is visible); snapshot preflight now resolves the container's runtime and refuses gVisor unless the effective args include --overlay2=none, and create fails closed when the filesystem diff is filestore-only (#2241)
  • Apply [docker] security profiles and secure_runtime to the execd cache container: it ignored apparmor_profile / seccomp_profile / docker_runtime, so on a host whose default seccomp profile blocks the execd image, every POST /sandboxes failed 503 with no configuration escape (#2254)
  • Make concurrent Docker metadata patches safe: the store's read-modify-write was unlocked and every write shared one temporary name, so two concurrent PATCH /metadata requests for a sandbox raced into a 500 (FileNotFoundError on rename) or silently dropped the other's key; a store-wide lock plus per-write temp names serialize patches (last write wins per key), a failed write no longer leaves its temp file behind, and the endpoint contract is now documented per runtime — Kubernetes patches write back the whole label set it read, fsb patches send only their own keys fenced by UID and generation (#2267 #2281)
  • Resolve proxy endpoints off the event loop: HTTP/WebSocket proxy handlers called the synchronous get_endpoint directly — a Docker socket call per proxied request on Docker, an apiserver read on Kubernetes cache misses — blocking the loop for every other request and stream; a slow Docker daemon (e.g. during an image pull) was enough to freeze the server; the lookup now runs via asyncio.to_thread with tenant context preserved (#2268)
  • Apply the renew cooldown when the Redis consumer is enabled: proxy renews skipped min_interval_seconds entirely (every proxied request ran a get_sandbox + expiration renew) and queue intents were only throttled per ingress replica, so N replicas renewed up to N times per interval; the cooldown now applies to every renew source and starts only after a successful renew (#2276 #2279)

SDKs

Code changes below ride the 1.2.0 stable release — rc ships no SDK packages.

  • Add the Credential Vault client contract to all five SDKs (OSEP-0022): template-backed sandboxes route vault calls through the server on the same template-origin signal as network policy (OPEN-SANDBOX-ORIGIN: template or the local createFromTemplate flag), while sidecar-direct adapters stay untouched; Python's Sandbox.credential_vault now returns the vault service for both profiles, and Go gains Sandbox-level vault methods branching on the same signal (#2263)
  • Add lifecycle.renewalPolicy to all five SDKs (OSEP-0009): a typed create field with client-side fail-fast validation (extendSeconds 300–86400) wired through the create converters, replacing the opaque extensions key (#2296)
  • Implement diagnostics across the SDK surface (with #2292): context is exposed through both the manager and sandbox facades in all five languages, and JavaScript, Go, and C# gain public logs/events APIs matching the existing Python/JVM surface (custom factories keep working — the new diagnostics service is optional)
  • Support port-scoped egress rules in all five SDKs (#2212): NetworkRule.ports (TCP 1–65535, at most 256 per rule, target now optional) with client-side validation mirroring the server (range, duplicates, cap, domain+ports rejected, netmask-CIDR+ports rejected); JavaScript encodes the target-or-ports invariant as a union type, Python normalizes a blank wire target on read-back

Python

  • Stop propagating a cancelled endpoint fetch to waiters: the shared-fetch endpoint cache set the fetching caller's CancelledError on the shared future, so concurrent waiters — e.g. TaskGroup siblings — raised CancelledError though nothing cancelled them; waiters now re-resolve (cached endpoint, newer in-flight fetch, or their own), while the cancelled caller still raises as before (#2277)
  • Forward credential_proxy through sandbox pools: PoolCreationSpec.credential_proxy was dropped by both sync and async creation paths, so warmup and direct-create sandboxes silently lost the requested credential-proxy configuration; custom factories stay compatible (the keyword is omitted when unset) (#2283)
  • Regenerate the lifecycle client to drop stale hardcoded defaults (timeout_seconds: 2, wake_on_access: true → UNSET) left behind by the spec change in #2212; wire behavior is unchanged — the server applies the same defaults (#2280)

Go

  • Authenticate proxied data-plane requests with the API key: proxy mode sent the tenant API key — a credential that can create, pause, and delete every sandbox of the tenant — into the untrusted sandbox as X-EXECD-ACCESS-TOKEN (and as egress auth) while omitting the OPEN-SANDBOX-API-KEY header the server middleware reads, so multi-tenant proxy requests failed 401 and surfaced as readiness timeouts; the tenant key now rides the server header and is never smuggled into the sandbox or egress sidecar, endpoint-supplied and caller-supplied proxy keys win regardless of casing, and direct mode stays key-free (#2274)

Controller

  • Fix task-executor treating an empty exit file as exit code 0: the shim creates the exit file before writing it, and Inspect ignored the parse error — a shim killed in between (or a failed write, e.g. full disk) reported a failed or interrupted task as Succeeded; an invalid or empty file now falls through to the pid check (Running while alive, ProcessCrashed once gone) (#2270)

Execd

  • Preserve bash session output line endings: run_in_session stdout events dropped \n/\r bytes, so blank lines were unrecoverable and concatenating a run's events did not reconstruct its output; event text now carries its original line ending (blank lines surface as events containing only the ending), aligning the session stream with the foreground /command contract — consumers should concatenate event text per run instead of treating each event as a newline-free line (#2318)
  • Report exit_code on command errors: a command that ran and exited non-zero and a command whose process never started (e.g. fork/exec: argument list too long) reported the same error event, so clients reading the exit status from evalue could report a start failure as success; the new optional error.exit_code is present only when the process ran and finished non-zero (-1 on signal termination) (#2303)
  • Serve binds mount points through the isolated session files API: the merged-view router only registered overlay mounts, so session.files failed with ErrPathOutsideOverlays on the same bind destinations that session.run could read; each bind now registers a routed view (dest → source, read-only binds reject writes, bind views shadow overlays on prefix ties) (#2299)
  • Truncate command output files before unlink: forked children (daemons) legitimately outlive commands while holding the output fd, so an unlinked file kept consuming disk as invisible (deleted) growth until the last holder exited; every existing deletion point now truncates to zero first, and background output is only touched at janitor deletion time so the retention window stays readable (#2295)
  • Omit invalid upper-usage metrics on scan errors: a failed filesystem scan emitted a misleading execd.isolation.upper.usage_bytes of 0 while sessions and data still existed; invalid readings are now omitted (a valid empty upper still reports 0), and quota admission fails closed when upper_max_bytes > 0 and a scan fails instead of silently bypassing accounting (#2257)
  • Avoid redundant JDK MITM CA imports: sandboxes with several installed JDKs often share one trust store, but each JDK re-ran the keytool import (~6.2 s for four JDKs); initialization is now deduplicated by resolved trust-store path with certificate-content comparison, cutting the stage to ~0.6 s while still replacing rotated certificates (#2310)
  • Default PTY sessions to TERM=xterm-256color when the resolved user environment has no usable TERM, so interactive programs get colors; an explicit TERM always wins (#2313)

Networking

egress

The OSEP-0022 vault items concern the fast-sandbox profile's credential-vault surface; the OSEP-0023 follow-ups remain scoped to the default-off experimental revision runtime.

  • Add the egress-held vault for fast sandboxes (OSEP-0022), landing in stages: the internal /vault/{sandboxUid} relay surface with create-only POST (409 on duplicate, atomic across server replicas), full-revision PUT with expectedRevision and an expectedIncarnation precondition so a stale writer can never land on a reset's successor, value-including GET, and DELETE that keeps the policy (#2249); durable per-subject persistence — one file per subject under a Pod-scoped volume (optional tmpfs), the same commit protocol as policy files so acked means durable and applied, incarnation-fenced reload, and purge on unbind (#2252); and the superseded fastlet-proxy vault route removed with its pending-push cache (#2247)
  • Carry the vault across pause/resume (OSEP-0022 "Vault Lifecycle"): VAULT_EXPORT copies the vault file into the snapshot bundle strictly before runtime teardown and seals the subject (all vault ops answer 409 while paused; enforcement continues), and VAULT_IMPORT is the only authorized incarnation transfer — the bundle re-stamps with the restored fence before data-plane-ready, validated against the current policy before any durable effect; a genuine export failure leaves the subject unsealed and fails the pause checkpoint, so teardown never runs without a bundle and the egress-local vault survives for the retry (#2255); a vaultTransfer capability signal lets an egress without vault persistence skip the transfer entirely — the checkpoint proceeds without the vault (pre-transfer semantics) instead of failing (#2290)
  • Define stale-subject takeover on slot reuse: the fast-sandbox dispatch key is the slot IP and slots are reused, so a SET_BINDING can claim a key still held by a dead-but-registered subject — egress now treats that as authoritative, tearing down the stale subject's nft rules, DNS refcount, MITM redirect, and vault slice under the registry lock before registering the successor deny-first; traffic is never dispatched to stale rules, late unloads stay fence-guarded no-ops, and every failure path leaves each subject either fully registered or fully evicted (#2250)
  • Pin the fast-sandbox MITM CA (OSEP-0022 "MITM Trust Anchor"): the pool-pinned, versioned CA is seeded from a read-only secret mount into the mitmdump confdir (idempotent, fail-closed on an unloadable pair), replacing generate-on-start — an egress restart no longer rotates the CA and silently invalidates every live sandbox's TLS trust; a missing or mismatched CA refuses only the MITM addon (policy enforcement unaffected) with mitmCaFingerprint / mitmCaDown surfaced on /healthz and the actions status, so a template↔pool Secret mispairing is visible at a glance (#2251)
  • Align the fast-sandbox network policy with the vault pattern: the recorded policy becomes egress-held state — a /policy/{sandboxUid} relay surface with revision preconditions (unknown subject 404, incarnation mismatch 412, sealed 409), durable per-subject files using the same commit protocol, POLICY_EXPORT/POLICY_IMPORT snapshot transfer mirroring the vault, and, after an egress restart, the committed file superseding the replayed create-time binding input (#2309)
  • Support port-scoped egress rules end to end (classic profile): NetworkRule.ports (TCP 1–65535, ≤256 per rule) makes target optional — port-only rules, or ports combined with an IP/CIDR; domain+ports is rejected since domain rules evaluate at the DNS proxy layer; deny-before-allow precedence holds across scoping, and a PATCH merge-key bug that let a second port-only rule evict the first is fixed; an operator-shipped reachable.ports.cap whitelist is enforced as an always-deny ahead of every user rule so even defaultAction: allow cannot open a non-whitelisted port; the fast-sandbox route rejects ports with 400 until the fastlet nft path can enforce them (fail-closed, documented) (#2212)
  • Add static TLS passthrough selectors to the experimental live-revision runtime: OPENSANDBOX_EGRESS_MITMPROXY_PASSTHROUGH_HOSTS is a bounded exact/wildcard host array applied at ClientHello with 443-overlap rejection; existing nonempty native ignore_hosts/allow_hosts now reject startup in live mode — migrate static TLS bypass entries to the array (legacy mode unchanged, no public interceptionMode added) (#2229)
  • Emit TLS admission counters: one best-effort event per final ClientHello admission feeds egress.mitm.tls.connections_total with closed mode/decision/reason labels — it measures admission decisions, not handshakes or requests, and is explicitly not security evidence (#2265)
  • Add the installation-only subject revision IPC foundation (OSEP-0023 Phase 4): an authenticated v2 Unix-socket channel routes target-bound revision transactions to independent, admission-disabled installation receivers with frozen request bytes and lost-reply reconciliation; no production caller yet (#2284)
  • Ship egress-trace, a read-only admission viewer inside the egress image: live policy state, nft sets and DNS leases with TTLs, real outbound connections annotated with their admission verdict, and a probe <domain> subcommand separating policy denial from resolver failure; no sidecar behavior change, and decrypted L7 contents are deliberately never shown (#2230)

Misc

  • Console: land the third of five planned console PRs — admin and platform ops, with /api/admin/sandboxes aggregation, per-tenant detail proxying, a pools API (documented as not tenant-isolated), and admin global sandbox list / pools / overview KPIs in the web UI (#2131); preserve empty successful upstream responses in the BFF proxy instead of failing JSON decode on 200/201/205 (#2271)
  • CLI: add osb terminal <sandbox-id>, attaching the local terminal to a real PTY inside the sandbox over the execd PTY WebSocket — raw mode with SIGWINCH-driven resize, replay on reconnect, remote exit code propagation, and support for both direct and server-proxy connection modes (interactive TTY, POSIX) (#2313); report out-of-range duration inputs as Click validation errors instead of uncaught OverflowError/ValueError (#2272)
  • OSEPs: OSEP-0022 revised — the vault rides the action binding as an AES-256-GCM-sealed revision on one control channel, with the per-pool pinned CA as the MITM trust anchor (#2174); the planned OpenSandbox runtime driver ask is withdrawn (the firecracker driver ships as-is; deny-first timing replaces the pre-create healthz probe) (#2259); MITM CA namespace distribution becomes an ops-runbook deployment prerequisite instead of a resident sync controller (#2282)
  • Examples: add an all-in-one Docker image for the DeerFlow example bundling the OpenSandbox server (host Docker runtime) and the DeerFlow backend, for one-command workshop starts without a local Python toolchain (#2262)
  • Docs: reflow hard-wrapped markdown prose into single-line paragraphs across 148 files (~7.4k collapsed fragments, rendering unchanged) and codify the prose style rule in AGENTS.md (#2285)
  • Tests/CI: cache Go modules for the five Kubernetes nightly e2e jobs (setup-go silently skipped its cache without a root go.sum, re-downloading the full module graph nightly) (#2306); close the credential-vault happy path in the fast-sandbox smoke — relay CRUD, injection through the real mitm for every auth type, rotation, restart durability, and purge (#2256); dump every fastlet Pod container's logs (including egress) on pause/resume verify failure (#2290)
  • release: bump platform version to 1.2.0-rc.2 across charts and image references
