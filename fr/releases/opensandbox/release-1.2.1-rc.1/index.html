Version OpenSandbox-1.2.1-rc.1

Première version candidate sur la ligne de patch 1.2.1, coupée de release-1.2.0 (2026-10-27). Titre : OSEP-0025 Credential Vault Exchange – une source d'informations d'identification exchange avec résolution d'en-tête par requête via un résolveur enfichable, câblée de bout en bout entre la sortie, le serveur, les cinq SDK, le fast-sandbox e2e et le guide Credential Vault. A noter également : exécution de téléchargements atomiques, validation de résumé pour les instantanés rootfs, diagnostics de démarrage avec délai de création Kubernetes et portée du cache d'informateur pour les grands clusters. La ligne de base pour chaque section est release-1.2.0. Les versions rc publient des images mais contiennent des packages - les artefacts SDK/CLI sont expédiés au niveau de la bosse stable 1.2.1.

Faits saillants

  • Credential Vault Exchange (OSEP-0025) : résolution d'en-tête dynamique par requête, fermée en cas d'échec et jamais persistante, sur le serveur et les cinq SDK (#2457 #2535 #2534 #2560)
  • Sécurité des données : les téléchargements exécutés sont remplacés de manière atomique afin qu'une écriture échouée conserve l'ancien fichier (#2433) ; le contrôleur refuse les instantanés rootfs dont le résultat de validation manque de résumés (#2482)
  • Opérabilité : créer des délais d'attente pour signaler la raison de l'échec du démarrage du pod (#2434) ; le contrôleur et le contrôleur fsb gagnent la portée du cache --namespaces (#2571 #2581)

Serveur

  • La liste Sandbox pousse les filtres d'égalité des métadonnées dans le sélecteur d'étiquettes Kubernetes, de sorte que les grands espaces de noms ne matérialisent plus chaque charge de travail avant le filtrage (#2559)
  • Renforcement du modèle OCI : la syntaxe du référentiel de publication est validée lors de la création et la création du bac à sable nécessite une référence de publication épinglée par résumé - un modèle réussi ne peut plus être résolu en un manifeste mutable ou sans rapport (#2491)
  • Kubernetes crée des délais d'attente et ajoute la raison de l'échec de démarrage du pod (non planifiable, ImagePullBackOff, événements d'avertissement) avant la restauration - les échecs d'extraction d'image et de planification sont à nouveau diagnostiquables via le API (#2434)
  • Docker : une suppression simultanée du conteneur n'interrompt plus la restauration après expiration du démarrage et les erreurs Docker restantes échouent au démarrage au lieu de supprimer silencieusement les minuteries (#2533) ; Les destinations en double, racine et en conflit avec le montage du serveur sont rejetées avec 400 avant le provisionnement (#2421 #2505)
  • Une racine POSIX explicite dans storage.allowed_host_paths couvre désormais ses descendants ; la vérification descendante a produit // et n'a jamais correspondu (#2474)
  • Proxy : un GET qui déclare un corps est transmis avec lui, donc les requêtes de style Elasticsearch cessent d'échouer avec 500 (#2518) ; l'épuisement du pool renvoie 503 PROXY_POOL_EXHAUSTED au lieu d'une attente de 180 secondes se terminant par 500 (#2519)
  • Corrections plus petites : metadata=env= filtre sur la valeur vide au lieu de tout faire correspondre (#2461) ; les validateurs de passerelle, de nom de compartiment et de nom d'environnement rejettent les nouvelles lignes de fin (#2499)

SDK

Les charges utiles du coffre-fort d'informations d'identification Exchange (source exchange + authentification de liaison sans type) sont acceptées sur les cinq SDK, alignées sur le contrat de serveur et de fil de sortie (#2534 #2560) ; voir la note Kotlin/C# ABI dans Mise à niveau et compatibilité. Les méthodes de téléchargement détaillées exposent les métadonnées de réponse (statut, Content-Range, isPartial) dans les cinq langues ; signatures existantes inchangées, les implémentations de systèmes de fichiers personnalisés doivent les ajouter (#1597) ###Python

  • Les flux de commandes SSE obtiennent un délai de lecture : commands.run() lève SandboxTimeoutException après max(request_timeout, 30s) de silence au lieu de bloquer définitivement sur un exécutable bloqué (#2527)
  • L'arrêt progressif du pool asynchrone draine les kills en attente au lieu de les annuler et de laisser les bacs à sable non suivis jusqu'au TTL (#2507)
  • Les flux de téléchargement libèrent la réponse HTTP en cas de suppression, de fermeture anticipée ou d'abandon en cours d'itération – plus d'épuisement du pool de connexions (#2487 #2531)
  • Les erreurs de transport lors des requêtes de flux et des lectures de corps génèrent des exceptions SDK au lieu de divulguer des erreurs brutes httpx (#2515 #2525).
  • Corrections plus petites : invalidation du cache du point de terminaison limitée à la clé en vol (#2409) ; NetworkPolicyAdapter propage les options de redirection et les hooks d'événement (#2553) ; le serveur MCP signale les erreurs SDK au lieu d'un message générique (#2524) ###JavaScript
  • Les requêtes de session isolée lancent SandboxApiException avec un statut/identifiant de demande/code d'erreur au lieu d'un Error plat (#2466)
  • Un délai de redirection infini ou négatif est traité comme aucun – requestTimeoutSeconds: Infinity n'échoue plus à chaque requête authentifiée (#2488).
  • La fermeture d'un flux de téléchargement dans sa propre boucle termine proprement l'itération au lieu de lancer un TypeError (#2514)

Kotlin

  • Les délais d'attente des commandes inférieurs à la milliseconde sont arrondis à 1 ms ; 500 µs précédemment sérialisés sous le nom 0, qui est traité comme illimité (#2537) ### C# Couvert par les modèles d'échange croisés SDK (#2560).

Aller

  • Durcissement des nouvelles tentatives/timeout : la saturation Retry-After et le plafond de 60 s s'appliquent désormais sur le chemin de nouvelle tentative générique (#2452 #2508) ; l'intervalle de temps sature au lieu d'envelopper le négatif (#2509) ; ReadyTimeout est appliqué dans des délais d'appelant plus longs (#2528) ; les vérifications de préparation des interprètes sont limitées dans un délai et nécessitent une sortie zéro confirmée (#2504 #2480) ; Les POST de télémétrie ont leur propre limite de cinq secondes (#2540)
  • Cache de point de terminaison : récupérations en cours clôturées en cas d'invalidation (#2503) ; les mutations du cycle de vie invalident les points de terminaison mis en cache (#2564) ; le dernier serveur partant annule la récupération partagée (#2579) ; les en-têtes de configuration/endpoint fusionnent sans tenir compte de la casse (#2529)
  • Pool : le FIFO inactif survit au retrait/réinsertion (#2453) ; les serveurs d'arrêt honorent l'annulation de l'appelant (#2542) ; Destroy limite la vidange du magasin d'état (#2580)
  • Execution.Text() concatène les fragments de code sans séparateurs, donc "Loading" + "...done\n" ne gagnent plus de nouvelle ligne ; formatage de la commande inchangé (#2447)
  • Corrections plus petites : l'analyseur SSE accepte les événements délimités par CR (#2439) ; les téléchargements en plusieurs parties conservent leur limite générée (#2468) ; une assertion de diagnostic irrégulière vérifie net.Error.Timeout() (#2479)

Contrôleur

  • Les validations d'instantanés Rootfs dont le résultat manque de résumés échouent désormais (CommitResultUnavailable/CommitResultIncomplete) et signalent PauseFailed avec les pods conservés - précédemment suspendu le succès signalé, supprimé les pods et chaque reprise ultérieure a échoué de façon permanente (#2482)
  • --namespaces étend le cache des informateurs, corrigeant le MOO de démarrage sur les grands clusters partagés ; la valeur par défaut vide conserve la sémantique du cluster complet ; valeur du graphique controller.namespaces (#2571)

Exécuté

  • Les téléchargements sont atomiques : fichier temporaire intermédiaire + renommage, préservation du mode/propriétaire et liens symboliques suivants – un téléchargement échoué (ENOSPC, erreur d'E/S, kill) ne détruit plus le fichier remplacé (#2433)
  • Le jeton Jupyter est découvert à partir du jpserver-*.json de l'image de l'interpréteur de code lorsque JUPYTER_TOKEN n'est pas défini ; la configuration explicite gagne (#2448)
  • L'attente de démarrage de Jupyter est restaurée à ~ 5 minutes — une interaction d'interruption Cap a été interrompue après ~ 11 s contre des images froides ([#2486] (https://github.com/opensandbox-group/OpenSandbox/pull/2486))
  • EXECD_SSE_LEGACY_COMPAT (désactivé par défaut) omet exit_code des événements SSE pour les SDK pré-1.0.18 dont le runtime kotlinx plante sur la clé inconnue (#2472)
  • filename* est codé avec les caractères attr RFC 8187, donc les noms avec =, :, ' sont analysés en clients stricts (#2516)

Réseautage

sortie

  • Credential Vault Exchange (OSEP-0025) : source exchange (point de terminaison du résolveur UDS/HTTPS), authentification de liaison sans type, liaisons d'instantanés uniquement par marqueur, un point de terminaison POST /credential-vault/_resolve et intégration de modules complémentaires injectant des en-têtes résolus avec 407/stream-kill fermé en cas d'échec — le matériel résolu n'est jamais conservé, mis en cache ou relu ; coffres-forts en ligne uniquement inchangés (#2457 #2495 #2501 #2500 #2535 #2538) ; profil side-car intégré bout à bout avec fast-sandbox e2e (#2549 #2547 #2561); chapitre du guide ajouté (#2563)
  • L'authentification de l'appelant du résolveur est différée (D5) : les points de terminaison du résolveur https:// doivent être accessibles uniquement en sortie (autorisations UDS ou règles NFT à l'échelle du réseau) comme limite actuelle du trust (#2549)
  • Le travail préparatoire d'OSEP-0023 se poursuit [EXPERIMENTAL] : lecteur sécurisé Vault v2 (#2441), gestion stricte de l'héritage avec clôture du propriétaire (#2460), écrivain Vault v2 en mode strict avec appelant du serveur (#2493) — les valeurs par défaut restent v1 ; le mode strict nécessite le producteur de bac à sable rapide couplé
  • Un hook data-plane-ready rejoué est idempotent (200) au lieu d'un faux 409 (#2510)

entrée

  • Validation du démarrage : --wake-park-budget doit être inférieur à --wake-max-flight-lifetime ; la mauvaise configuration répondait précédemment aux requêtes parquées avec 400 ou 200 vide au lieu de 503 + Retry-After (#2511)
  • Une demande de réveil en file d'attente est limitée par un budget de parc au lieu de près de deux (#2513)
  • Corrections plus petites : le statut final est enregistré après une réponse 1xx, donc 103 Early Hints ne se fait plus passer pour le statut de la demande (#2484) ; Les anciens ports de route hôte sont validés (sb-70000 n'est plus 502s, sb-08080 n'atteint plus le port 8080) (#2578) ; une course aux données de test uniquement corrigée (#2512)

Bac à sable rapide

  • Les chaînes de points de contrôle restent limitées : les chaînes de couches de points de contrôle de pause/restauration sont écrasées via overlaybd-merge pendant la validation, de sorte que les cycles répétés n'augmentent plus la chaîne de restauration sans limite (#2546 fast-sandbox#158)
  • Découverte de VM locale au nœud : le runtime Firecracker écrit un enregistrement fast-sandbox.json en écriture unique par VM (UID sandbox complet, espace de noms, nom, emplacement) à côté du journal du processus, afin que les agents locaux du nœud découvrent les VM locales par analyse de répertoire au lieu de surveiller les CR Sandbox à l'échelle du cluster ; la publication ne bloque jamais le provisionnement et le démontage supprime l'enregistrement (#2546 fast-sandbox#154)
  • Mémoire : récupération opt-in de la mémoire des invités avec admission basée sur la pression et création de rapports de pages gratuits activés par défaut dans les modèles intégrés (#2546 fast-sandbox#114)
  • Renforcement Fastlet : transport Actions v2 géré strictement (moitié producteur du récepteur à gestion stricte de sortie de cette version), correctifs de course à la retraite du propriétaire, préservation de la clôture des terminaux sur l'inventaire absent et sondes d'admission parallélisées (#2546 fast-sandbox#152)
  • Contrôleur fsb : --namespaces étend le cache de l'informateur (refuse de démarrer lorsque l'ensemble manque l'espace de noms de l'environnement d'exécution) et --kube-client-qps/--kube-client-burst ajuste le limiteur de débit client du serveur API partagé - valeurs du graphique d'adhésion controller.namespaces/controller.kubeClientQPS/controller.kubeClientBurst, les valeurs par défaut n'affichent aucun nouveau drapeau (#2581 bac à sable rapide#161)
  • Topologie d'initialisation : runtime.execd_run_as_init intègre désormais EXECD_INIT=1 dans les environnements de modèle d'image dorée fsb - auparavant ignoré sur fsb, donc execd n'a jamais pris le rôle d'initialisation OSEP-0018 ; la valeur injectée l'emporte sur une clé fournie par client (#2494) ; l'environnement d'intégration épingle la topologie complète de l'invité et toute la surface e2e la définit par défaut (#2497)
  • Environnement d'intégration : les builds du modèle overlaybd sondent le chemin d'ajout/suppression d'ublk dès le départ et auto-réparent les périphériques du noyau coincé au lieu d'échouer environ 16 minutes après le début d'une version vouée à l'échec, et le démontage libère les périphériques orphelins (#2454) ; les assertions de fumée font apparaître de véritables erreurs nft au lieu de les lire comme des règles manquantes (#2543) ; une étape de vérification du résolveur d'échange complet (relais du serveur → sortie _resolve → en-têtes injectés observés par l'invité) monte verify-native/verify-overlaybd (#2561)

Divers

  • CLI : le texte est échappé au lieu d'être analysé comme un balisage riche – les chemins comme /tmp/notes[draft].txt s'impriment correctement et n'échouent plus avec les commandes réussies (#2520) ; les fichiers de configuration cassés signalent proprement au lieu de planter chaque commande (#2521) ; config set stocke les valeurs de clé de chaîne textuellement (007123 reste 007123) (#2522) ; la session PTY est supprimée lorsque le WebSocket ne s'ouvre jamais (#2523)
  • node-agent : un flux de log dont le répertoire n'est jamais apparu est oublié après la fenêtre de rétention au lieu de persister éternellement (#2471)
  • Docs : revendications de signature d'image alignées sur la couverture réelle du flux de travail (#2467) ; Charte de l'AAIF et consolidation de la gouvernance — les contributions au code nécessitent désormais l'approbation du DCO (#2490) ; Exemples de modèles S3 définis format: native (#2506); Statut OSEP-0025 et broches de contrat (#2539)
  • Housekeeping : code mort supprimé dans les modules (#2496) ; execd CI monte des tracefs pour la fumée eBPF (#2473)

OpenSandbox release-1.2.1-rc.1

First release candidate on the 1.2.1 patch line, cut from release-1.2.0 (2026-10-27). Headline: OSEP-0025 Credential Vault Exchange — an exchange credential source with per-request header resolution through a pluggable resolver, wired end to end across egress, server, all five SDKs, fast-sandbox e2e, and the Credential Vault guide. Also notable: execd atomic uploads, digest validation for rootfs snapshots, Kubernetes create-timeout startup diagnostics, and informer-cache scoping for large clusters. Baseline for every section is release-1.2.0. rc releases publish images but hold packages — SDK/CLI artifacts ship at the 1.2.1 stable bump.

Highlights

  • Credential Vault Exchange (OSEP-0025): per-request dynamic header resolution, fail-closed and never persisted, across server and all five SDKs (#2457 #2535 #2534 #2560)
  • Data-safety: execd uploads replace atomically so a failed write keeps the old file (#2433); the controller refuses rootfs snapshots whose commit result lacks digests (#2482)
  • Operability: create timeouts report the pod startup failure reason (#2434); controller and fsb controller gain --namespaces cache scoping (#2571 #2581)

Server

  • Sandbox list pushes metadata equality filters into the Kubernetes label selector, so large namespaces no longer materialize every workload before filtering (#2559)
  • Template OCI hardening: publish repository syntax is validated at create, and sandbox creation requires a digest-pinned publish reference — a succeeded template can no longer resolve to a mutable or unrelated manifest (#2491)
  • Kubernetes create timeouts append the pod startup failure reason (unschedulable, ImagePullBackOff, warning events) before rollback — image pull and scheduling failures are diagnosable through the API again (#2434)
  • Docker: a concurrent container removal no longer aborts the startup expiration restore, and remaining Docker errors fail startup instead of silently dropping timers (#2533); duplicate, root, and server-mount-clashing destinations are rejected with 400 before provisioning (#2421 #2505)
  • An explicit POSIX root in storage.allowed_host_paths now covers its descendants; the descendant check produced // and never matched (#2474)
  • Proxy: a GET that declares a body is forwarded with it, so Elasticsearch-style requests stop failing with 500 (#2518); pool exhaustion returns 503 PROXY_POOL_EXHAUSTED instead of a 180-second wait ending in 500 (#2519)
  • Smaller fixes: metadata=env= filters on the empty value instead of matching everything (#2461); gateway, bucket-name, and env-name validators reject trailing newlines (#2499)

SDKs

Exchange credential vault payloads (exchange source + typeless binding auth) are accepted across all five SDKs, aligned with the server and egress wire contract (#2534 #2560); see the Kotlin/C# ABI note in Upgrade & Compatibility. Detailed download methods expose response metadata (status, Content-Range, isPartial) in all five languages; existing signatures unchanged, custom filesystem implementations must add them (#1597)

Python

  • SSE command streams get a read timeout: commands.run() raises SandboxTimeoutException after max(request_timeout, 30s) of silence instead of blocking forever on a stalled execd (#2527)
  • Async pool graceful shutdown drains pending kills instead of cancelling them and leaving untracked sandboxes until TTL (#2507)
  • Download streams release the HTTP response when dropped, closed early, or abandoned mid-iteration — no more connection-pool exhaustion (#2487 #2531)
  • Transport errors during stream requests and body reads raise SDK exceptions instead of leaking raw httpx errors (#2515 #2525)
  • Smaller fixes: endpoint cache invalidation scoped to the inflight key (#2409); NetworkPolicyAdapter propagates redirect options and event hooks (#2553); the MCP server reports SDK errors instead of a generic message (#2524)

JavaScript

  • Isolated-session requests throw SandboxApiException with status/request id/error code instead of a flat Error (#2466)
  • An infinite or negative redirect deadline is treated as none — requestTimeoutSeconds: Infinity no longer fails every authenticated request (#2488)
  • Closing a download stream inside its own loop ends iteration cleanly instead of throwing a TypeError (#2514)

Kotlin

  • Sub-millisecond command timeouts round up to 1 ms; 500 µs previously serialized as 0, which execd treats as unbounded (#2537)

C#

Covered by the cross-SDK exchange models (#2560).

Go

  • Retry/timeout hardening: Retry-After saturation and the 60 s cap now apply on the generic retry path (#2452 #2508); backoff saturates instead of wrapping negative (#2509); ReadyTimeout is enforced under longer caller deadlines (#2528); interpreter readiness probes are deadline-bounded and require a confirmed zero exit (#2504 #2480); telemetry POSTs get their own five-second bound (#2540)
  • Endpoint cache: in-flight fetches fenced across invalidation (#2503); lifecycle mutations invalidate cached endpoints (#2564); the last waiter leaving cancels the shared fetch (#2579); config/endpoint headers merge case-insensitively (#2529)
  • Pool: idle FIFO survives remove/reinsert (#2453); shutdown waiters honor caller cancellation (#2542); Destroy bounds state-store draining (#2580)
  • Execution.Text() concatenates code fragments without separators, so "Loading" + "...done\n" no longer gains a newline; command formatting unchanged (#2447)
  • Smaller fixes: SSE parser accepts CR-delimited events (#2439); multipart uploads keep their generated boundary (#2468); a flaky diagnostic assertion checks net.Error.Timeout() (#2479)

Controller

  • Rootfs snapshot commits whose result lacks digests now fail (CommitResultUnavailable/CommitResultIncomplete) and report PauseFailed with pods kept — previously pause reported success, deleted the pods, and every later resume failed permanently (#2482)
  • --namespaces scopes the informer cache, fixing startup OOM on large shared clusters; empty default keeps full-cluster semantics; chart value controller.namespaces (#2571)

Execd

  • Uploads are atomic: staged temp file + rename, preserving mode/owner and following symlinks — a failed upload (ENOSPC, I/O error, kill) no longer destroys the replaced file (#2433)
  • The Jupyter token is discovered from the code-interpreter image's jpserver-*.json when JUPYTER_TOKEN is unset; explicit config wins (#2448)
  • The Jupyter startup wait is restored to ~5 minutes — a backoff Cap interaction had aborted after ~11 s against cold images (#2486)
  • EXECD_SSE_LEGACY_COMPAT (default off) omits exit_code from SSE events for pre-1.0.18 SDKs whose kotlinx runtime crashes on the unknown key (#2472)
  • filename* is encoded with RFC 8187 attr-chars, so names with =, :, ' parse in strict clients (#2516)

Networking

egress

  • Credential Vault Exchange (OSEP-0025): exchange source (UDS/HTTPS resolver endpoint), typeless binding auth, marker-only snapshot bindings, a POST /credential-vault/_resolve endpoint, and addon integration injecting resolved headers with fail-closed 407/stream-kill — resolved material is never persisted, cached, or read back; inline-only vaults unchanged (#2457 #2495 #2501 #2500 #2535 #2538); sidecar profile integrated end to end with fast-sandbox e2e (#2549 #2547 #2561); guide chapter added (#2563)
  • Resolver caller auth is deferred (D5): https:// resolver endpoints must be egress-only reachable (UDS permissions or network-scoped nft rules) as the current trust boundary (#2549)
  • OSEP-0023 groundwork continues [EXPERIMENTAL]: Vault v2 safe reader (#2441), strict legacy management with owner fencing (#2460), strict-mode Vault v2 writer with server caller (#2493) — defaults remain v1; strict mode requires the paired fast-sandbox producer
  • A replayed data-plane-ready hook is idempotent (200) instead of a spurious 409 (#2510)

ingress

  • Startup validation: --wake-park-budget must be below --wake-max-flight-lifetime; the misconfiguration previously answered parked requests with 400 or empty 200 instead of 503 + Retry-After (#2511)
  • A queued wake request is bounded by one park budget instead of nearly two (#2513)
  • Smaller fixes: the final status is recorded after a 1xx response, so 103 Early Hints no longer masquerades as the request status (#2484); legacy host-route ports are validated (sb-70000 no longer 502s, sb-08080 no longer reaches port 8080) (#2578); a test-only data race fixed (#2512)

Fast Sandbox

  • Checkpoint chains stay bounded: pause/restore checkpoint layer chains are squashed through overlaybd-merge during commit, so repeated cycles no longer grow the restore chain without limit (#2546 fast-sandbox#158)
  • Node-local VM discovery: the firecracker runtime writes a write-once fast-sandbox.json record per VM — full sandbox UID, namespace, name, placement — next to the process log, so node-local agents discover local VMs by directory scan instead of watching Sandbox CRs cluster-wide; publication never blocks provisioning and teardown removes the record (#2546 fast-sandbox#154)
  • Memory: opt-in guest memory reclamation with pressure-based admission, and free-page reporting enabled by default in built templates (#2546 fast-sandbox#114)
  • Fastlet hardening: the strict managed Actions v2 transport (producer half of this release's egress strict-management receiver), owner-retirement race fixes, terminal-fence preservation across absent inventory, and parallelized admission probes (#2546 fast-sandbox#152)
  • fsb controller: --namespaces scopes the informer cache (refuses to start when the set misses the runtime-environment namespace) and --kube-client-qps/--kube-client-burst tune the shared API-server client rate limiter — opt-in chart values controller.namespaces/controller.kubeClientQPS/controller.kubeClientBurst, defaults render no new flags (#2581 fast-sandbox#161)
  • Init topology: runtime.execd_run_as_init now bakes EXECD_INIT=1 into fsb golden-image template envs — previously ignored on fsb, so execd never took the OSEP-0018 init role; the injected value wins over a client-provided key (#2494); the integration environment pins the full in-guest topology and the whole e2e surface defaults it on (#2497)
  • Integration environment: overlaybd template builds probe the ublk add/del path up front and self-heal wedged kernel devices instead of failing ~16 minutes into a doomed build, and teardown releases orphan devices (#2454); smoke assertions surface real nft errors instead of reading them as missing rules (#2543); a full-chain exchange-resolver verify stage (server relay → egress _resolve → injected headers observed by the guest) rides verify-native/verify-overlaybd (#2561)

Misc

  • CLI: text is escaped instead of parsed as Rich markup — paths like /tmp/notes[draft].txt print correctly and no longer fail successful commands (#2520); broken config files report cleanly instead of crashing every command (#2521); config set stores string-key values verbatim (007123 stays 007123) (#2522); the PTY session is deleted when the WebSocket never opens (#2523)
  • node-agent: a log stream whose directory never appeared is forgotten after the retention window instead of persisting forever (#2471)
  • Docs: image-signing claims aligned with actual workflow coverage (#2467); AAIF charter and governance consolidation — code contributions now require DCO sign-offs (#2490); S3 template examples set format: native (#2506); OSEP-0025 status and contract pins (#2539)
  • Housekeeping: dead code removed across modules (#2496); execd CI mounts tracefs for the eBPF smoke (#2473)

Upgrade & Compatibility

  • Kotlin/C# SDKs are source-compatible but not ABI-compatible with 1.2.0 — recompile; no wire changes (#2560)
  • Python: silent SSE streams now raise SandboxTimeoutException after max(request_timeout, 30s) (#2527); download-body errors raise SDK exceptions instead of raw httpx errors (#2525)
  • Go: Execution.Text() no longer inserts separators between code fragments (#2447); nonempty positional Execution{...} literals no longer compile — use keyed literals
  • Execd atomic uploads: writable file in non-writable directory is rejected, device/FIFO destinations refused, xattrs/ACLs/setgid bits not carried, bind-mounted destinations fail (EBUSY), a SIGKILL mid-upload can leave a .osb-upload-* staging file, peak disk ~3× file size (#2433)
  • Server startup: a Docker error during expiration restore (other than concurrent removal) now prevents startup — run under a restarting supervisor (#2533)
  • Ingress: --wake-park-budget below --wake-max-flight-lifetime is now enforced at startup; defaults unaffected (#2511)
  • Template list: metadata=env= now filters on the empty value (#2461)
  • OSEP-0025: exchange is additive and opt-in, but resolver caller auth is deferred — https:// resolver endpoints must be egress-only reachable (#2549 #2563)
  • Fast Sandbox: free-page reporting on by default; per-VM fast-sandbox.json record; controller.namespaces must cover pools/sandboxes and the runtime-environment namespace or the controller refuses to start (#2546 #2581)
  • Images: opensandbox/<component>:release-1.2.1-rc.1 (all three registries; fsb images for fast-sandbox)
  • Packages: unchanged — SDK/CLI artifacts publish at the 1.2.1 stable release
  • Charts: render from this tag (helm template ./manifests/charts/opensandbox)
  • Kubernetes: supported range v1.21 – v1.34
  • Skew: server ↔ CLI/SDK same line supported; ±1 minor warns
