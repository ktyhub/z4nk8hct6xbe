Version OpenSandbox-1.2.1-rc.2

Deuxième version candidate sur la ligne de patch 1.2.1, contenant tout ce qui a été fusionné depuis release-1.2.1-rc.1 (04/11/2026). Le titre est l'atterrissage de bout en bout du surabonnement sensible aux ressources OSEP-0026 : le serveur enregistre la forme effective de la machine de chaque modèle, la transmet en tant que limites par bac à sable sur les pools ResourceAware et rejoue les limites enregistrées lors des restaurations d'instantanés, validées par une voie de vérification KVM dédiée. La mise en réseau Fast Sandbox atteint la parité sur les règles de sortie au niveau du port, le runtime de révision expérimental OSEP-0023 passe des fondations de session à une porte de préparation forcée, et le fast-sandbox épinglé obtient des instantanés OCI opt-in rootfs uniquement. Un lot de sécurité corrige les bogues réels de perte de données et de disponibilité : les champs inconnus dans les objets de requête fermés sont désormais rejetés, un redémarrage du contrôleur ne peut plus expulser les pods des sandbox actifs et le chemin de données proxy du serveur passe en mode maintenance. Les images sont publiées maintenant ; Les packages SDK/CLI sont expédiés sur la bosse stable 1.2.1.

Faits saillants

  • Le surabonnement prenant en compte les ressources (OSEP-0026) arrive de bout en bout : les formes de machine modèle sont enregistrées au moment de la construction, transmises selon les limites par bac à sable lorsque le pool sélectionné signale ResourceAware, les restaurations par instantané rejouent les limites enregistrées par la source au lieu d'échouer, et une étape CI verify-resourceaware affirme la chaîne jusqu'aux valeurs du groupe de contrôle (#2602 #2623 #2628 #2633 #2637)
  • Parité et renforcement rapides de la sortie du bac à sable : les règles NetworkRule.ports au niveau du port sont désormais appliquées par sujet (le rejet 400 est levé) (#2662) ; Les baux DNS se renouvellent dans le noyau et survivent à la suppression des voisins (#2652 #2653) ; le runtime expérimental de révision du sujet OSEP-0023 atteint une porte de préparation sur les instantanés reconnus (#2666)
  • Sécurité et cycle de vie : les objets de requête fermés rejettent les champs inconnus avec 422 au lieu de les ignorer silencieusement (#2576) ; un redémarrage du contrôleur n'expulse plus les pods alloués aux sandbox actifs (#2398) ; le chemin de données du serveur-proxy est obsolète en mode maintenance : acheminez le trafic du bac à sable via la passerelle d'entrée (#2548)

Serveur

  • Surabonnement prenant en compte les ressources (OSEP-0026) : la forme de machine effective de chaque modèle (CPU/mémoire post-par défaut) est enregistrée dans spec_json.machine au moment de la construction et projetée de manière identique dans le CRD (#2623) ; le mode modèle le crée en tant que resources.limits par bac à sable lorsque - et seulement lorsque - le pool sélectionné signale ResourceAware, les pools FastPath LegacySlot/anciens ne pouvant pas être omis en toute sécurité et le mode pool lit la mise en cache TTL ([#2628] (https://github.com/opensandbox-group/OpenSandbox/pull/2628)) ; la création d'instantanés enregistre les limites par sandbox de la source et les restaure, les rejoue - auparavant, un modèle de sandbox façonné restauré sur un pool ResourceAware revenait aux valeurs par défaut du pool et FastPath rejetait carrément la restauration (#2633) ; Les stubs FastPath sont régénérés avec les champs proto prenant en compte les ressources comme base (#2619) ; le contrat est défini dans OSEP-0026 (#2602)
  • Le chemin de données proxy du serveur est obsolète en mode maintenance : /sandboxes/{id}/proxy/{port}, le paramètre use_server_proxy, les options SDK correspondantes et les indicateurs CLI/MCP portent désormais des marqueurs de dépréciation explicites (en-tête de réponse Deprecation: true, avertissements d'exécution par langue), avec sécurité et corrections de bogues uniquement – les déploiements doivent exposer le trafic sandbox via la passerelle d'entrée. (#2548)
  • Les champs inconnus dans les objets de requête fermés sont rejetés avec l'enveloppe 422 nettoyée au lieu d'être supprimés silencieusement — readonly: true sur un volume ne reste plus silencieusement accessible en écriture et createIfNotExist: false ne laisse plus la création automatique de volume activée ; dix modèles (demandes image/auth/platform/volume/OSSFS/credential-proxy/snapshot-renew) utilisent désormais extra = "forbid", et la propriété TypeScript auth token est obsolète (#2576)
  • L'informateur Kubernetes suit les écritures par objet au lieu d'invalider l'ensemble du cache : chaque création/correction/suppression marquait auparavant l'intégralité du cache de charge de travail non synchronisé jusqu'à une relist complète (jusqu'à 60 s), donc une réplique avec des écritures régulières (les renouvellements suffisent) a servi presque toutes les lectures du serveur API et s'est terminée en 429 s ; les lectures sont désormais mises en ligne uniquement pour l'objet écrit jusqu'à ce que l'événement WATCH le confirme (#2599)
  • La sonde d'activité en pause d'inactivité honore son contrat de verdict : elle ne relance jamais et chaque échec ne fait que laisser tomber le candidat actuel - une réponse 200 profondément imbriquée utilisée pour s'échapper et sauter le reste du balayage ; les réponses doivent maintenant être non compressées, contenir 4 Ko et arriver dans timeoutSeconds sous forme de limite d'échange complet (#2596)

SDK

Les modifications de code ci-dessous utilisent la version stable 1.2.1 – rc ne fournit aucun package SDK. ###Python

  • Les entiers Content-Range mal formés ou hors plage sont traités comme des métadonnées inconnues (limitées à 64 bits) et les réponses de streaming asynchrone sont fermées lorsque le mappage des métadonnées de réponse échoue dans les téléchargements standard et de session isolée - auparavant, le flux sous-jacent pouvait rester ouvert (#2570)
  • Le serveur MCP Python expose l'état des commandes en arrière-plan et les journaux incrémentiels : command_get_status (état d'exécution, code de sortie) et command_get_logs (contenu + curseur opaque), avec des conseils d'interrogation dans les descriptions de l'outil (#2648). ###JavaScript
  • Délais d'attente de commande positifs inférieurs à la milliseconde arrondis à au moins 1 ms - Math.round a sérialisé 0.0004 s en timeout: 0, ce qui désactive la limite d'exécution pour les commandes ordinaires et sélectionne la valeur par défaut du serveur dans les sessions Bash (#2440)

Aller

  • Le budget de sillage limite les tentatives en cours : après un sillage marqué 503, d'autres tentatives obtiennent une date limite pour le WakeOverallDeadline restant (en-têtes uniquement - les flux SSE établis et les corps de téléchargement ne sont jamais interrompus) (#2572), et les attentes d'attente génériques ou Retry-After qui ne peuvent pas correspondre au budget restant sont ignorées, de sorte qu'une nouvelle tentative d'échec mixte ne dort plus après la date limite ou masque l'erreur ordinaire derrière un marqueur de sillage plus ancien (#2611)
  • Renforcement du pool : une acquisition annulée ne consomme plus d'entrée inactive saine ni ne déclenche une création (#2616) ; l'arrêt progressif honore l'annulation de l'appelant en attendant que les acquisitions indépendantes soient drainées (#2617) ; la maintenance inactive (réduction, reaping proche de l'expiration) se poursuit pendant l'interruption de la création au lieu d'être ignorée pendant toute la durée du tick (#2565)
  • Une réponse SSE commençant par une nomenclature UTF-8 ne supprime plus la première trame de données ou son champ événement/id — une trame d'initialisation de commande pourrait perdre l'ID d'exécution (#2618) ; un délai d'expiration expirant dans une demande de statut renvoie désormais SandboxRunningTimeoutError quel que soit le timing, donc la classification errors.As est stable (#2668) Les README SDK rattrapent la surface livrée : cycle de vie idlePolicy + reprise de réveil, renewalPolicy et règles de port documentées dans les cinq langues (#2590) ; échangez des informations d'identification et des flux de création/interrogation de modèles fsb documentés pour JavaScript, Python, Go (#2597) et Kotlin (#2620) ; l'exemple d'isolation réseau utilise les importations réelles et la classe de règles (#2711)

Contrôleur

  • L'expulsion du pool après le redémarrage d'un contrôleur ne supprime plus les pods des sandbox actifs : le magasin d'allocation en mémoire n'a été récupéré que dans Schedule, mais l'expulsion s'est exécutée en premier à chaque réconciliation de pool - lors de la première réconciliation après un redémarrage, chaque pod étiqueté pour l'expulsion semblait inactif et a été supprimé, y compris ceux alloués ; la récupération s'exécute désormais avant toute lecture du magasin (#2398)
  • L'abaissement de poolMax met désormais à l'échelle les pods de pool inactifs : auparavant, cela ne plafonnait que la croissance, donc les pods inactifs au-dessus de la nouvelle limite fonctionnaient indéfiniment ; seuls les pods inactifs sont supprimés et les suppressions déjà planifiées sont prises en compte dans la limite (#2470)
  • L'attente de statut-RV d'un BatchSandbox supprimé est supprimée, corrigeant la croissance illimitée du tas leader - l'entrée pour le dernier correctif d'état de chaque BatchSandbox jamais réconcilié est restée pendant toute la durée de vie du processus (#2646)
  • Le timing de l'élection du leader est configurable : --leader-elect-lease-duration, --leader-elect-renew-deadline et --leader-elect-retry-period (plus les valeurs du graphique), de sorte que les opérateurs sur des plans de contrôle plus lents peuvent empêcher un blocage du serveur API de 10 s de forcer une réélection complète ; les valeurs par défaut sont inchangées (#2651)
  • Graphique : les indicateurs de fonctionnalité du contrôleur ConfigMap sont rendus dans l'espace de noms du contrôleur — il est allé dans l'espace de noms de la version Helm, où le contrôleur ne l'a jamais lu, donc controller.podRecovery.* a été ignoré en silence (#2694)

Exécuté

  • Les fichiers de session isolée API masquent les entrées supprimées par superposition : les blancs du noyau (périphériques 0/0), les répertoires user.overlay.opaque et les propres marqueurs .wh. du API masquent désormais les entrées inférieures dans stat/read/list/search — après rm f && mkdir d, les f et d/x supprimés étaient toujours lisibles avec leur ancien contenu, et RemoveAll("d") restait d/x listable jusqu'à présent (#2469)
  • La copie lors du renommage et du chmod est fidèle à la couche inférieure : le mode (y compris setuid/setgid/sticky) et la propriété de la session sont préservés, les liens symboliques restent des liens symboliques, les répertoires inférieurs uniquement peuvent être renommés et rm f.txt && mv f.txt g.txt ne ressuscite plus le fichier supprimé ; chmod refuse les liens symboliques au lieu de les suivre vers un chemin d'hôte (#2638)
  • Les courses MITM CA trust contre les redémarrages de sortie sont fermées : bootstrap uniquement trust une autorité de certification qui est apparue après une absence observée ou a survécu à une fenêtre de stabilisation, et un observateur à vie réinstalle system/merged/NSS/JDK trust chaque fois que le contenu de l'autorité de certification exportée change - auparavant, un redémarrage side-car laissait le bac à sable avec l'autorité de certification en rotation partout jusqu'à la reconstruction (#2582)
  • Les exécutions isolées au premier plan n'écrivent plus leur script dans le stdin du shell : le code qui lit stdin (read, cat) a consommé le reste du script, y compris le marqueur de fin, corrompant le code de sortie et détournant la session ; le code s'exécute désormais via eval avec </dev/null, une erreur de syntaxe termine l'exécution avec le statut 2 et la session survit (#2517)
  • Corrections plus petites : le morceau de sortie final du détenteur du PTY est vidé avant la trame exit au lieu de la faire défiler (un enfant en arrière-plan tenant le tube retarde exit d'au plus 2 s) (#2644) ; Les métriques cgroup v1 et la surveillance MOO respectent la racine de montage du conteneur, donc Docker-on-cgroup-v1 a signalé le processeur/la mémoire de l'hôte au lieu des limites du bac à sable (#2641) ; les téléchargements de répertoire renvoient 400 au lieu d'un 500/empty-200 dépendant du système de fichiers, et le 416 d'un en-tête Range mal formé transporte un message (#2451) ; un glob /files/search invalide renvoie 400 au lieu de 500 (ou 200 sur un répertoire vide) (#2687) ; created_at rapporte l'heure de naissance de l'inode via statx, donc chmod/rename ne la modifie plus (#2604) ; L'achèvement de Jupyter est dérivé du résultat réel du noyau (réponse + inactivité, erreurs IOPub conservées) au lieu de le faire courir (#2606)

Réseautage

sortie

  • Les règles de sortie au niveau du port sont appliquées par sujet dans le bac à sable rapide : le chemin NFT par sujet a gagné les chaînes d'autorisation/abandon du port TCP (MITM correspond au port d'origine de la connexion, pas à l'écouteur proxy), le serveur fsb passe par ports et fusionne par (target, ports), et le rejet 400 au moment de la création est levé - la sémantique de refus avant autorisation et TCP uniquement correspond au profil classique, et domaine + ports reste rejeté dans les deux (#2662)
  • PATCH /policy sur le side-car classique ne supprime plus les règles intactes : la clé de fusion partagée permet à un patch sans rapport de supprimer un deny existant et d'ouvrir le trafic bloqué (fail-open) ; les règles de base des scopes absents du patch sont désormais conservées, correspondant au contrat documenté (#2664)
  • Les baux DNS Fast-sandbox sont renouvelés dans le noyau : l'ajout simple d'éléments temporisés réussit mais laisse l'expiration du noyau inchangée, donc les nouvelles connexions à une adresse IP en cache ont été abandonnées une fois le premier délai d'attente écoulé ; le renouvellement utilise désormais la séquence d'ajout/suppression/réajout (#2652), et la reconstruction de la table nft partagée lorsqu'un sujet est supprimé rajoute les baux non expirés des sujets restants au lieu de laisser bloquées les adresses IP mises en cache inactives (#2653)
  • Le runtime de révision de sujet expérimental OSEP-0023 avance [EXPERIMENTAL] (derrière OPENSANDBOX_EGRESS_EXPERIMENTAL_REVISION_RUNTIME, admission toujours désactivée) : sessions de sujet d'installation uniquement avec IPC authentifié par enfant et nouvelles générations de contrôle (#2589), un agent de vidange du cycle de vie FIFO enregistrant les intentions SET/REMOVE/rebind/takeover (#2609), des instantanés de décision par sujet installés après la liaison et après chaque mutation de coffre-fort/politique (#2634 #2649), et le hook prêt pour le plan de données se lance désormais sur un instantané reconnu pour la clôture/génération/digest actuelle - renvoyant 503 alors que l'autorité ou l'ACK est manquant (#2666) ; le contrat d'intégration de propriété et de révision est épinglé dans OSEP-0022/0023 (#2586)
  • Le runtime expérimental de révision en direct du side-car rejette les ports d'interception supplémentaires au démarrage et échoue en se fermant sur les ports de destination TLS non canoniques (non 443), au lieu de les laisser atteindre la porte d'autorité HTTP ultérieure (#2587).

entrée

  • La politique de réveil lit la réutilisation d'une seule configuration Kubernetes : dessert des routes régulières et fast-sandbox avec une configuration REST analysée activée par le réveil à deux reprises, et le deuxième enregistrement d'indicateur global a paniqué au démarrage avec flag redefined: cluster (#2600)

Bac à sable rapide

  • Pool chaud ublk natif sur les déploiements OCI : OverlayBD démarre désormais avec un pool 4/8 de périphériques de 2 Gio (runtime.oci.poolLow/poolHigh/poolSizeGB réglables sur la carte, poolLow=0 désactivés), de sorte que le modèle crée des périphériques pré-alloués au lieu d'allouer à la demande ; CI affirme des hits chauds sans échecs ni redémarrages de démon (#2594 fast-sandbox#163)
  • Instantanés OCI rootfs uniquement (FSEP-0001) sur le chemin OverlayBD : la capture conserve uniquement la couche rootfs inscriptible sans vidage de mémoire et restaure les démarrages au lieu de reprendre en place - des artefacts plus petits sans fenêtre de transfert de taille mémoire et sans épinglage de modèle de processeur, avec le manifeste d'artefact conduisant la restauration ; un échec de récupération RootfsOnly suspend la route jusqu'à ce que la récupération réussisse ; capacité au niveau de l'exécution, le câblage de l'instantané OpenSandbox API arrive plus tard (#2706 fast-sandbox#173 fast-sandbox#167)
  • Renforcement du cycle de vie : les fastlets sont isolés du MOO du pool de machines virtuelles et conservent les erreurs de drainage, les diagnostics de ressources et les identités d'exécution ayant échoué au cours des phases de préparation (#2626 fast-sandbox#162) ; la pause immédiate après la création n'accélère plus la projection d'état du contrôleur - une pause interrompue conserve son intention et une reprise simultanée préserve la lignée des points de contrôle, donc aucun délai de stabilisation côté client n'est nécessaire (#2626 fast-sandbox#166)
  • Récupération d'instantanés et de rapprochement : les captures mises en quarantaine sont réconciliées et les routes dangereuses retirées, les environnements d'exécution mis en quarantaine retirés, les chemins vsock isolés, les routes suspendues restaurées et les pods Fastlet terminaux sont remplacés uniquement dans les pools actifs ; réinitialiser les horodatages de révision préserver les fractions (#2706 fast-sandbox#172 fast-sandbox#170)
  • Graphiques : le contrôleur fast-sandbox et les charges de travail d'exécution Firecracker acceptent podLabels/podAnnotations/nodeSelector/affinity, le maillage DART P2P du runtime peut être désactivé (runtime.p2p.enabled=false ne restitue aucun port service/homologue sans tête et l'agent extrait directement du magasin d'origine), et le graphique du contrôleur gagne controller.extraArgs pour les indicateurs binaires non modélisés. (#2566)
  • Intégration ResourceAware : un appareil ResourceAware SandboxPool avec sélection POOL_MODE=resource-aware (#2622), une étape verify-resourceaware affirmant le transfert de modèle de forme aux niveaux CR/cgroup/saturation (#2637), et la voie d'intégration PR exécute désormais la pile ResourceAware par défaut tout en gardant la couverture LegacySlot la nuit. (#2647)
  • Correction plus petite : le graphique du bac à sable rapide ignore le secret de la clé de route de développement lorsque routeKeys.existingSecret est défini – les installations de production ne restituent plus la clé privée Ed25519 publiée pour le développement uniquement (#2695).

Divers

  • Console : un shell sandbox de navigateur relie xterm au PTY d'exécution via un WebSocket BFF — les entrées sur les listes de locataires et d'administrateurs, les clés de locataire et les jetons d'exécution restent sur le BFF, une page ouverte équivaut à un PTY (#2233) ; une connexion excd abandonnée après la connexion est signalée comme un shell perdu au lieu d'une erreur de traçage affirmant que le shell n'a pas pu s'ouvrir (#2639) ; Les étiquettes de l'interface utilisateur sont traduites en anglais (#2657)
  • agent de nœud : une source vm-console opt-in collecte la sortie de la console invitée Fast Sandbox : découverte de VM locale de nœud à partir de fast-sandbox.json écrit par le pilote sans surveillance CR, fidélité des octets bruts par UID sandbox lors des modifications de placement et décalages reconnus en toute sécurité au redémarrage (#2234) ; l'environnement d'intégration le déploie et affirme la collecte de bout en bout (#2676) ; Les conseils opérationnels couvrent l'alignement du chemin, la couverture des nœuds et les règles de découverte (#2677)
  • CLI : les sections de configuration hors table sont rejetées avec une erreur claire au lieu de planter chaque commande (#2551) ; Les cellules du tableau None s'affichent sous la forme - au lieu du texte littéral (#2691) ; une cible de règle de sortie vide est une erreur d'utilisation avec l'indice ACTION=TARGET (#2692)
  • Suivi OSEP-0025 : l'authentification de l'appelant du résolveur est spécifiée — un JWT Ed25519 mis en cache sur chaque numéro de résolution TCP, vérifié hors ligne par rapport à un JWKS publié sur le serveur, comblant l'écart R4 différé au niveau de la couche application (#2631)
  • Gouvernance : les règles de nomination et de suppression des responsables sont renforcées : approbation majoritaire pour les responsables des composants, soutien des propriétaires de chemins, LGTM des sponsors et processus émérite/suppression (#2678) ; @jianpingpei est nommé responsable de l'agent de nœud (#2679)
  • OSEP et documents : OSEP-0024/0026 et six OSEP antérieurs sont marqués implémentés, OSEP-0006 (console développeur) est retiré (#2624 #2670 #2671 #2672 #2673); la page d'index OSEP est supprimée du site de documentation — oseps/ sur GitHub est l'index canonique (#2674)

Mise à niveau et compatibilité

  • Breaking : les champs inconnus dans les objets de requête fermés renvoient désormais 422 — les clés précédemment ignorées (par exemple readonly sur un volume) sont rejetées ; envoyer chaque champ une fois, alias ou Snake_case mais pas les deux ; dans le TypeScript SDK, ImageAuth.token combiné avec username/password échoue désormais — envoyez uniquement username et password (#2576)
  • Obsolescence : le chemin de données proxy du serveur (/sandboxes/{id}/proxy/{port}, use_server_proxy, les options SDK/CLI/MCP) est en mode maintenance – pas de nouvelles fonctionnalités, sécurité et corrections de bugs uniquement ; exposer le trafic sandbox via la passerelle d'entrée (#2548)
  • Changement de comportement : le code dans une exécution isolée au premier plan ne peut plus lire le stdin de la session (il n'a obtenu que le propre script de l'exécution de cette façon), et une erreur de syntaxe termine désormais l'exécution avec le statut 2 pendant que la session survit — auparavant, elle tuait le shell (#2517)
  • Changement de comportement : les téléchargements d'un répertoire renvoient 400 INVALID_REQUEST_BODY au lieu d'un 500 dépendant du système de fichiers ou d'un 200/206 vide/incomplet ; utilisez l'itinéraire /directories/list ; une plage 416 mal formée gagne un champ message (#2451)
  • Changement de comportement : les réponses à la sonde d'activité en pause d'inactivité doivent être non compressées, au maximum 4 Ko, et complètes dans timeoutSeconds dans le cadre d'un échange complet - tout le reste est un verdict d'erreur pour ce candidat (#2596)
  • Changement de comportement : les pools dont le nombre de pods inactifs dépasse un poolMax réduit augmentent désormais l'excédent (seuls les pods inactifs sont supprimés) (#2470).
  • Fast Sandbox : les déploiements compatibles OCI réservent par défaut un pool de périphériques ublk inactifs : définissez runtime.oci.poolLow=0 pour conserver le comportement à la demande précédent et faites correspondre poolSizeGB à la capacité du modèle construit pour les tailles de disque personnalisées (#2594)
  • Fast Sandbox : les règles de sortie au niveau du port (NetworkRule.ports) sont désormais acceptées et appliquées sur les routes fast-sandbox — elles renvoyaient auparavant 400 ; les règles existantes ne sont pas affectées (#2662)
  • Runtime de révision en direct de sortie expérimentale uniquement : les ports d'interception supplémentaires sont rejetés au démarrage – supprimez OPENSANDBOX_EGRESS_MITMPROXY_EXTRA_PORTS lors de l'activation de ce runtime (#2587)
  • Exécution de révision expérimentale fast-sandbox uniquement (OPENSANDBOX_EGRESS_EXPERIMENTAL_REVISION_RUNTIME=true) : le hook prêt pour le plan de données peut renvoyer 503 jusqu'à ce que l'instantané du sujet soit reconnu ; crée puis attend jusqu'à fastpath_wait_ready_seconds (30 s par défaut) et renvoie En attente/Indisponible (#2666)
  • Images : opensandbox/<component>:release-1.2.1-rc.2 (les trois registres ; images fsb pour fast-sandbox)
  • Packages : inchangés – Les artefacts SDK/CLI sont publiés dans la version stable 1.2.1
  • Graphiques : rendu à partir de cette balise (helm template ./manifests/charts/opensandbox)
  • Kubernetes : gamme prise en charge v1.21 – v1.34
  • Skew : serveur ↔ CLI/SDK même ligne prise en charge ; ±1 avertissement mineur

OpenSandbox release-1.2.1-rc.2

Second release candidate on the 1.2.1 patch line, carrying everything merged since release-1.2.1-rc.1 (2026-11-04). The headline is OSEP-0026 resource-aware oversubscription landing end to end: the server records each template's effective machine shape, forwards it as per-sandbox limits on ResourceAware pools, and replays recorded limits across snapshot restores, validated by a dedicated KVM verify lane. Fast Sandbox networking reaches parity on port-scoped egress rules, the experimental OSEP-0023 subject revision runtime advances from session foundations to an enforced readiness gate, and the pinned fast-sandbox gains opt-in rootfs-only OCI snapshots. A safety batch closes real data-loss and availability bugs: unknown fields in closed request objects are now rejected, a controller restart can no longer evict pods of live sandboxes, and the server-proxied data path enters maintenance mode. Images publish now; SDK/CLI packages ship at the 1.2.1 stable bump.

Highlights

  • Resource-aware oversubscription (OSEP-0026) lands end to end: template machine shapes are recorded at build time, forwarded as per-sandbox limits when the selected pool reports ResourceAware, snapshot restores replay the source's recorded limits instead of failing, and a verify-resourceaware CI stage asserts the chain down to cgroup values (#2602 #2623 #2628 #2633 #2637)
  • Fast Sandbox egress parity and hardening: port-scoped NetworkRule.ports rules are now enforced per subject (the 400 rejection is lifted) (#2662); DNS leases renew in the kernel and survive neighbour removal (#2652 #2653); the experimental OSEP-0023 subject revision runtime reaches a readiness gate on acknowledged snapshots (#2666)
  • Safety and lifecycle: closed request objects reject unknown fields with 422 instead of silently ignoring them (#2576); a controller restart no longer evicts pods allocated to live sandboxes (#2398); the server-proxy data path is deprecated into maintenance mode — route sandbox traffic through the ingress gateway (#2548)

Server

  • Resource-aware oversubscription (OSEP-0026): each template's effective machine shape (post-default CPU/memory) is recorded in spec_json.machine at build time and projected identically into the CRD (#2623); template-mode creates forward it as per-sandbox resources.limits when — and only when — the selected pool reports ResourceAware, with LegacySlot/older FastPath pools failing safe to field-omitted and the pool-mode read TTL-cached (#2628); snapshot creation records the source's per-sandbox limits and restores replay them — previously a shaped template sandbox restored on a ResourceAware pool fell back to pool defaults and FastPath rejected the restore outright (#2633); FastPath stubs are regenerated with the resource-aware proto fields as groundwork (#2619); the contract is defined in OSEP-0026 (#2602)
  • The server-proxied data path is deprecated into maintenance mode: /sandboxes/{id}/proxy/{port}, the use_server_proxy parameter, the matching SDK options, and the CLI/MCP flags now carry explicit deprecation markers (Deprecation: true response header, runtime warnings per language), with security and bug fixes only — deployments should expose sandbox traffic through the ingress gateway (#2548)
  • Unknown fields in closed request objects are rejected with the sanitized 422 envelope instead of being silently discarded — readonly: true on a volume no longer silently stays writable, and createIfNotExist: false no longer leaves automatic volume creation enabled; ten models (image/auth/platform/volume/OSSFS/credential-proxy/snapshot-renew requests) now use extra = "forbid", and the TypeScript auth token property is deprecated (#2576)
  • The Kubernetes informer tracks writes per object instead of invalidating the whole cache: every create/patch/delete previously marked the entire workload cache unsynced until a full relist (up to 60 s), so a replica with steady writes (renewals are enough) served almost every read from the API server and ended in 429s; reads now go live only for the written object until the WATCH event confirms it (#2599)
  • The idle-pause activity probe honors its verdict contract: it never raises and every failure only drops the current candidate — a deeply nested 200 answer used to escape and skip the rest of the sweep; answers must now be uncompressed, fit 4 KiB, and arrive within timeoutSeconds as a whole-exchange bound (#2596)

SDKs

Code changes below ride the 1.2.1 stable release — rc ships no SDK packages.

Python

  • Malformed or out-of-range Content-Range integers are treated as unknown metadata (64-bit bounded), and async streaming responses are closed when response-metadata mapping fails in standard and isolated-session downloads — previously the underlying stream could stay open (#2570)
  • The Python MCP server exposes background command status and incremental logs: command_get_status (running state, exit code) and command_get_logs (content + opaque cursor), with polling guidance in the tool descriptions (#2648)

JavaScript

  • Positive sub-millisecond command timeouts round up to at least 1 ms — Math.round serialized 0.0004 s as timeout: 0, which disables the runtime bound for ordinary commands and selects the server default in Bash sessions (#2440)

Go

  • The wake budget bounds in-flight retries: after a marked wake 503, further attempts get a deadline for the remaining WakeOverallDeadline (headers only — established SSE streams and download bodies are never cut off) (#2572), and generic backoff or Retry-After waits that cannot fit the remaining budget are skipped so a mixed-failure retry no longer sleeps past the deadline or hides the ordinary error behind an older wake marker (#2611)
  • Pool hardening: a cancelled acquire no longer consumes a healthy idle entry or triggers a creation (#2616); graceful shutdown honors caller cancellation while waiting for independent acquires to drain (#2617); idle maintenance (shrink, near-expiry reaping) continues during creation backoff instead of being skipped for the whole tick (#2565)
  • An SSE response starting with a UTF-8 BOM no longer drops the first data frame or its event/id field — a command init frame could lose the execution ID (#2618); a running-timeout deadline expiring inside a status request now returns SandboxRunningTimeoutError regardless of timing, so errors.As classification is stable (#2668)

SDK READMEs catch up with the shipped surface: lifecycle idlePolicy + wake-retry, renewalPolicy, and port-scoped rules documented in all five languages (#2590); exchange credentials and fsb template create/poll flows documented for JavaScript, Python, Go (#2597) and Kotlin (#2620); the network isolation example uses the real imports and rule class (#2711)

Controller

  • Pool eviction after a controller restart no longer deletes pods of live sandboxes: the in-memory allocation store was only recovered inside Schedule, but eviction ran first on every pool reconcile — on the first reconcile after a restart every pod labelled for eviction looked idle and was deleted, including allocated ones; recovery now runs before any store read (#2398)
  • Lowering poolMax now scales idle pool pods in: it previously only capped growth, so idle pods above the new bound ran indefinitely; only idle pods are deleted, and already-planned deletions count toward the bound (#2470)
  • A deleted BatchSandbox's status-RV expectation is dropped, fixing unbounded leader heap growth — the entry for the last status patch of every BatchSandbox ever reconciled stayed for the life of the process (#2646)
  • Leader election timing is configurable: --leader-elect-lease-duration, --leader-elect-renew-deadline, and --leader-elect-retry-period (plus chart values), so operators on slower control planes can stop a 10 s API-server stall from forcing a full re-election; defaults are unchanged (#2651)
  • Chart: the controller feature-flags ConfigMap is rendered into the controller's namespace — it went to the Helm release namespace, where the controller never read it, so controller.podRecovery.* was silently ignored (#2694)

Execd

  • The isolated-session files API hides overlay-deleted entries: kernel whiteouts (0/0 devices), user.overlay.opaque directories, and the API's own .wh. markers now hide lower entries in stat/read/list/search — after rm f && mkdir d the deleted f and d/x were still readable with their old contents, and RemoveAll("d") left d/x listable until now (#2469)
  • Copy-up on rename and chmod is faithful to the lower layer: mode (including setuid/setgid/sticky) and session ownership are preserved, symlinks stay symlinks, lower-only directories can be renamed, and rm f.txt && mv f.txt g.txt no longer resurrects the deleted file; chmod refuses symlinks instead of following them to a host path (#2638)
  • MITM CA trust races against egress restarts are closed: bootstrap only trusts a CA that appeared after an observed absence or survived a stabilization window, and a lifetime watcher reinstalls system/merged/NSS/JDK trust whenever the exported CA content changes — previously a sidecar restart left the sandbox with the rotated-out CA everywhere until rebuild (#2582)
  • Foreground isolated runs no longer write their script to the shell's stdin: code that reads stdin (read, cat) consumed the rest of the script including the end marker, corrupting the exit code and hijacking the session; code now runs via eval with </dev/null, a syntax error ends the run with status 2 and the session survives (#2517)
  • Smaller fixes: the PTY holder's final output chunk is flushed before the exit frame instead of racing it (a background child holding the pipe delays exit by at most 2 s) (#2644); cgroup v1 metrics and OOM watch honor the container's mount root, so Docker-on-cgroup-v1 reported host CPU/memory instead of the sandbox's limits (#2641); directory downloads return 400 instead of a filesystem-dependent 500/empty-200, and a malformed Range header's 416 carries a message (#2451); an invalid /files/search glob returns 400 instead of 500 (or 200 on an empty directory) (#2687); created_at reports the inode birth time via statx, so chmod/rename no longer change it (#2604); Jupyter completion is derived from the kernel's actual outcome (reply + idle, IOPub errors retained) instead of racing it (#2606)

Networking

egress

  • Port-scoped egress rules are enforced per subject in fast sandbox: the per-subject nft path gained TCP port allow/drop chains (MITM matches the connection's original port, not the proxy listener), the fsb server passes ports through and merges by (target, ports), and the create-time 400 rejection is lifted — deny-before-allow and TCP-only semantics match the classic profile, and domain+ports stays rejected in both (#2662)
  • PATCH /policy on the classic sidecar no longer drops untouched rules: the shared merge key let an unrelated patch remove an existing deny and open blocked traffic (fail-open); base rules of scopes absent from the patch are now kept, matching the documented contract (#2664)
  • Fast-sandbox DNS leases renew in the kernel: the plain timed-element add succeeds but leaves the kernel expiry unchanged, so new connections to a cached IP were dropped once the first timeout lapsed; renewal now uses the add/delete/re-add sequence (#2652), and rebuilding the shared nft table when one subject is removed re-adds the remaining subjects' unexpired leases instead of leaving idle cached IPs blocked (#2653)
  • The experimental OSEP-0023 subject revision runtime advances [EXPERIMENTAL] (behind OPENSANDBOX_EGRESS_EXPERIMENTAL_REVISION_RUNTIME, admission still disabled): installation-only subject sessions with authenticated per-child IPC and fresh control generations (#2589), a FIFO lifecycle drain worker recording SET/REMOVE/rebind/takeover intents (#2609), per-subject decision snapshots installed after binding and after every Vault/policy mutation (#2634 #2649), and the data-plane-ready hook now gates on an acknowledged snapshot for the current fence/generation/digest — returning 503 while authority or the ACK is missing (#2666); the ownership and revision integration contract is pinned in OSEP-0022/0023 (#2586)
  • The experimental sidecar live revision runtime rejects extra interception ports at startup and fails closed on non-canonical (non-443) TLS destination ports, instead of letting them reach the later HTTP authority gate (#2587)

ingress

  • Wake policy reads reuse a single Kubernetes config: serving regular and fast-sandbox routes with wake enabled parsed REST config twice, and the second global flag registration panicked at startup with flag redefined: cluster (#2600)

Fast Sandbox

  • Native ublk warm pool on OCI deployments: OverlayBD now starts with a 4/8 pool of 2 GiB devices (chart-tunable runtime.oci.poolLow/poolHigh/poolSizeGB, poolLow=0 disables), so template creates hit pre-allocated devices instead of allocating on demand; CI asserts warm hits with no misses or daemon restarts (#2594 fast-sandbox#163)
  • Opt-in rootfs-only OCI snapshots (FSEP-0001) on the OverlayBD path: capture persists only the writable rootfs layer without a memory dump, and restore boots instead of resuming in place — smaller artifacts with no memory-sized staging window and no CPU-model pinning, with the artifact manifest driving restore; a failed RootfsOnly recovery suspends the route until recovery succeeds; runtime-level capability, the OpenSandbox snapshot API wiring comes later (#2706 fast-sandbox#173 fast-sandbox#167)
  • Lifecycle hardening: Fastlets are isolated from VM-pool OOM and retain drain errors, resource diagnostics, and failed runtime identities across readiness phases (#2626 fast-sandbox#162); immediate pause after create no longer races the controller's status projection — an interrupted pause keeps its intent and a concurrent resume preserves checkpoint lineage, so no client-side settle delay is needed (#2626 fast-sandbox#166)
  • Snapshot and reconciler recovery: quarantined captures are reconciled and unsafe routes withdrawn, exited quarantined runtimes retired, vsock paths isolated, suspended routes restored, and terminal Fastlet Pods are replaced only in active pools; reset revision timestamps preserve fractions (#2706 fast-sandbox#172 fast-sandbox#170)
  • Charts: the fast-sandbox controller and firecracker-runtime workloads accept podLabels/podAnnotations/nodeSelector/affinity, the runtime's DART P2P mesh can be disabled (runtime.p2p.enabled=false renders no headless Service/peer port and the agent pulls directly from the origin store), and the controller chart gains controller.extraArgs for unmodeled binary flags (#2566)
  • ResourceAware integration: a ResourceAware SandboxPool fixture with POOL_MODE=resource-aware selection (#2622), a verify-resourceaware stage asserting shaped-template forwarding at CR/cgroup/saturation levels (#2637), and the PR integration lane now runs the ResourceAware stack by default while nightly keeps LegacySlot coverage (#2647)
  • Smaller fix: the fast-sandbox chart skips the dev route-key Secret when routeKeys.existingSecret is set — production installs no longer render the published development-only Ed25519 private key (#2695)

Misc

  • Console: a browser sandbox shell bridges xterm to execd's PTY over a BFF WebSocket — entries on the tenant and admin lists, tenant keys and execd tokens stay on the BFF, one page open is one PTY (#2233); a dropped execd connection after connect reports as a lost shell instead of an error traceback claiming the shell failed to open (#2639); UI labels are translated to English (#2657)
  • node-agent: an opt-in vm-console source collects Fast Sandbox guest console output — node-local VM discovery from driver-written fast-sandbox.json without CR watches, raw-byte fidelity per sandbox UID across placement changes, and restart-safe acknowledged offsets (#2234); the integration environment deploys it and asserts collection end to end (#2676); ops guidance covers path alignment, node coverage, and discovery rules (#2677)
  • CLI: non-table configuration sections are rejected with a clear error instead of crashing every command (#2551); None table cells render as - instead of the literal text (#2691); an empty egress rule target is a usage error with the ACTION=TARGET hint (#2692)
  • OSEP-0025 follow-up: resolver caller authentication is specified — a cached Ed25519 JWT on every TCP resolve dial, verified offline against a server-published JWKS, closing the deferred R4 gap at the application layer (#2631)
  • Governance: maintainer nomination and removal rules are tightened — majority approval for component maintainers, path-owner support, sponsor LGTMs, and an emeritus/removal process (#2678); @jianpingpei is nominated as node-agent maintainer (#2679)
  • OSEPs and docs: OSEP-0024/0026 and six earlier OSEPs are marked implemented, OSEP-0006 (developer console) is withdrawn (#2624 #2670 #2671 #2672 #2673); the OSEP index page is removed from the docs site — oseps/ on GitHub is the canonical index (#2674)

Upgrade & Compatibility

  • Breaking: unknown fields in closed request objects now return 422 — previously ignored keys (for example readonly on a volume) are rejected; send each field once, alias or snake_case but not both; in the TypeScript SDK, ImageAuth.token combined with username/password now fails — send only username and password (#2576)
  • Deprecation: the server-proxied data path (/sandboxes/{id}/proxy/{port}, use_server_proxy, the SDK/CLI/MCP options) is in maintenance mode — no new features, security and bug fixes only; expose sandbox traffic through the ingress gateway (#2548)
  • Behavior change: code in a foreground isolated run can no longer read the session's stdin (it only ever got the run's own script that way), and a syntax error now ends the run with status 2 while the session survives — previously it killed the shell (#2517)
  • Behavior change: downloads of a directory return 400 INVALID_REQUEST_BODY instead of a filesystem-dependent 500 or an empty/incomplete 200/206; use the /directories/list route; a malformed-range 416 gains a message field (#2451)
  • Behavior change: idle-pause activity probe answers must be uncompressed, at most 4 KiB, and complete within timeoutSeconds as a whole-exchange bound — anything else is an error verdict for that candidate (#2596)
  • Behavior change: pools whose idle pod count exceeds a lowered poolMax now scale the excess in (only idle pods are deleted) (#2470)
  • Fast Sandbox: OCI-enabled deployments reserve an idle ublk device pool by default — set runtime.oci.poolLow=0 to keep the previous on-demand behavior, and match poolSizeGB to the built template capacity for custom disk sizes (#2594)
  • Fast Sandbox: port-scoped egress rules (NetworkRule.ports) are now accepted and enforced on fast-sandbox routes — they previously returned 400; existing rules are unaffected (#2662)
  • Experimental egress live revision runtime only: extra interception ports are rejected at startup — remove OPENSANDBOX_EGRESS_MITMPROXY_EXTRA_PORTS when enabling that runtime (#2587)
  • Experimental fast-sandbox revision runtime only (OPENSANDBOX_EGRESS_EXPERIMENTAL_REVISION_RUNTIME=true): the data-plane-ready hook may return 503 until the subject snapshot is acknowledged; creates then wait up to fastpath_wait_ready_seconds (default 30 s) and return Pending/Unavailable (#2666)
  • Images: opensandbox/<component>:release-1.2.1-rc.2 (all three registries; fsb images for fast-sandbox)
  • Packages: unchanged — SDK/CLI artifacts publish at the 1.2.1 stable release
  • Charts: render from this tag (helm template ./manifests/charts/opensandbox)
  • Kubernetes: supported range v1.21 – v1.34
  • Skew: server ↔ CLI/SDK same line supported; ±1 minor warns
