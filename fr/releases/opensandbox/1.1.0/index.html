OpenSandbox docker/execd/v1.1.0

Quoi de neuf

✨Caractéristiques

  • exécuté en tant qu'initialisation du bac à sable (OSEP-0018). execd peut désormais s'exécuter en tant que PID 1 : un seul reaper avec une abstraction managedProcess sur chaque chemin de lancement, un transfert de signal (TERM/HUP/USR1/USR2/WINCH), une propagation du code de sortie appartenant au point d'entrée et un repli du sous-reaper pour le chemin du pool. Opt-in via EXECD_INIT=1 (injecté par le runtime.execd_run_as_init du serveur pour Docker/K8s Batch/Agent/Pool) ; topologie classique inchangée et désactivée par défaut. (#1474)
  • Sol de durcissement pré-exécutable. Le nouvel assistant natif opensandbox-launcher applique la bande d'environnement → KEEPCAPS → la garniture de jeu de limites → no_new_privs → la suppression d'identité → seccomp → execve ; [landlock] ajoute une liste autorisée du système de fichiers (échec d'ouverture sous ABI/noyau 5.13, signalé comme unsupported). GET /v1/isolated/capabilities gagne un objet hardening avec un état par couche ; chaque couche se dégrade en cas d'ouverture. (#1474)
  • Variante d'observation eBPF. execd-ebpf (CGO + cilium/ebpf) hooks exec/connect/privilege avec CO-RE, étendu au groupe de contrôle sandbox, émettant un audit JSONL tournant ; nécessite un noyau ≥5.10 avec BTF. L'image par défaut est inchangée. (#1474 #1562)
  • Hooks de cycle de vie preStart et periodic (OSEP-0020). CreateSandboxRequest.lifecycle est transporté vers le bac à sable via l'environnement interne OPEN_SANDBOX_LIFECYCLE (Kubernetes ; le fournisseur Docker rejette les demandes de cycle de vie). excd démarre HTTP avant preStart, exécute les hooks periodic sans chevauchement via le chemin de processus géré compatible Reaper et ne libère le processus utilisateur qu'après la réussite de preStart. La configuration persiste à $HOME/.execd/lifecycle.toml, avec EXECD_LIFECYCLE_CONFIG comme remplacement exact ; La synchronisation du bootstrap et l'arrêt preStart sont fermés en cas d'échec avec les chiens de garde TERM/KILL, et les variables de transport internes sont supprimées du code utilisateur. Modèles API alignés sur les Go/Python/JS/Kotlin/C# SDK. (#1587 #1588 #1589)

🐛 Corrections de bugs

  • Les signaux dans l'espace de noms ne fuient plus dans /command en mode init. kill -HUP 1 tuait auparavant tout ce que /command exécutait (signal: hangup) ; les signaux appartiennent désormais uniquement au redirecteur init. (#1546)
  • L'échec de la création du PTY a émis un deuxième corps de réussite. POST /pty s'arrête désormais immédiatement après la réponse d'erreur au lieu d'ajouter un corps de réussite et un identifiant de session inexistant. (#1603)
  • La validation cwd honore désormais les environnements au niveau de la requête. Les requêtes /command de premier plan/arrière-plan peuvent utiliser une variable cwd de leur propre carte envs au lieu d'être rejetées avec 400. (#1611)
  • Les charges de travail non root n'ont pas pu démarrer : /bootstrap.sh normalisé en 0755. Une image déployée transportait bootstrap.sh sous le nom de 0751 root:root, envoyant des images avec un utilisateur par défaut non root (par exemple admin) dans CrashLoopBackOff avant l'exécution des hooks. La construction de l'image force désormais les bits d'exécution sur execd/execd-ebpf/opensandbox-supervisor/bootstrap.sh quelles que soient les autorisations d'extraction. (#1619 #1606)
  • Le délai d'attente du preStart est passé de 300 s à 10 800 s (3 h). periodic.timeoutSeconds reste à 300 s ; les limites de la politique du produit sont désormais appliquées uniquement côté serveur, execd ne conservant qu'une protection technique contre les débordements. (#1637)

📦 Divers

  • Couverture OSEP-0018 fermée : chemin du serveur et renforcement e2e de Kubernetes (isolation TOML réalisée par ConfigMap, aucun changement de logique du serveur), renforcement PTY, intégration bwrap + init-reaper, politique [seccomp]/keep_capabilities personnalisée, broche de dérive EXECD_INIT↔TOML, recyclage de redémarrage K8 contre les pods en mode init, arrêt initié par l'exécution et une fumée de conteneur nu execd-ebpf (double la validation du noyau-5.10). Testez la redondance et le code mort supprimé (-359 lignes). (#1554 #1555 #1562 #1574)
  • Autorisation automatique du point de terminaison OTLP incluse dans les composants partagés (la sortie honore OTEL_EXPORTER_OTLP_METRICS_ENDPOINT/OTEL_EXPORTER_OTLP_ENDPOINT ; boucle de lecture du visualiseur PTY refactorisée en cours de route). (#1504)
  • Guide de hook de cycle de vie avec diagramme de synchronisation et exemples de création par SDK ; SDK cliValidation du délai d'attente côté ent alignée sur le serveur. (#1605)

OpenSandbox docker/execd/v1.1.0

What's New

✨ Features

  • execd as sandbox init (OSEP-0018). execd can now run as PID 1: single reaper with a managedProcess abstraction on every launch path, signal forwarding (TERM/HUP/USR1/USR2/WINCH), entrypoint-owned exit-code propagation, and a subreaper fallback for the Pool path. Opt-in via EXECD_INIT=1 (injected by the server's runtime.execd_run_as_init for Docker/K8s Batch/Agent/Pool); classic topology unchanged and default off. (#1474)

  • Pre-exec hardening floor. The new opensandbox-launcher native helper applies env strip → KEEPCAPS → bounding-set trim → no_new_privs → identity drop → seccomp → execve; [landlock] adds a filesystem allowlist (fail-open below ABI/kernel 5.13, reported as unsupported). GET /v1/isolated/capabilities gains a hardening object with per-layer state; every layer degrades fail-open. (#1474)

  • eBPF observation variant. execd-ebpf (CGO + cilium/ebpf) hooks exec/connect/privilege with CO-RE, scoped to the sandbox cgroup, emitting a rotating JSONL audit; needs kernel ≥5.10 with BTF. The default image is unchanged. (#1474 #1562)

  • preStart and periodic lifecycle hooks (OSEP-0020). CreateSandboxRequest.lifecycle is transported to the sandbox via the internal OPEN_SANDBOX_LIFECYCLE env (Kubernetes; the Docker provider rejects lifecycle requests). execd starts HTTP before preStart, runs non-overlapping periodic hooks through the reaper-aware managed-process path, and only releases the user process after preStart succeeds. Config persists at $HOME/.execd/lifecycle.toml, with EXECD_LIFECYCLE_CONFIG as exact override; bootstrap sync and preStart shutdown are fail-closed with TERM/KILL watchdogs, and internal transport vars are stripped from user code. API models aligned across Go/Python/JS/Kotlin/C# SDKs. (#1587 #1588 #1589)

🐛 Bug Fixes

  • In-namespace signals no longer leak into /command in init mode. kill -HUP 1 previously killed whatever /command was running (signal: hangup); signals are now owned by the init forwarder only. (#1546)

  • PTY creation failure emitted a second success body. POST /pty now stops immediately after the error response instead of appending a success body and a nonexistent session id. (#1603)

  • cwd validation now honors request-scoped envs. Foreground/background /command requests can use a cwd variable from their own envs map instead of being rejected with 400. (#1611)

  • Non-root workloads could not start: /bootstrap.sh normalized to 0755. A deployed image carried bootstrap.sh as 0751 root:root, sending images with a non-root default user (e.g. admin) into CrashLoopBackOff before hooks ran. The image build now forces exec bits on execd/execd-ebpf/opensandbox-supervisor/bootstrap.sh regardless of checkout permissions. (#1619 #1606)

  • preStart timeout raised from 300s to 10800s (3h). periodic.timeoutSeconds stays at 300s; product policy bounds are now enforced Server-side only, with execd keeping just a technical overflow guard. (#1637)

📦 Misc

  • OSEP-0018 coverage closed out: server-path and Kubernetes hardening e2e (ConfigMap-carried isolation TOML, no server logic change), PTY-under-hardening, bwrap + init-reaper integration, custom [seccomp]/keep_capabilities policy, EXECD_INIT↔TOML drift pin, K8s Restart recycle against init-mode pods, runtime-initiated stop, and an execd-ebpf bare-container smoke (doubles as kernel-5.10 validation). Test redundancy and dead code trimmed (-359 lines). (#1554 #1555 #1562 #1574)

  • OTLP endpoint auto-allow shipped in the shared components (egress honors OTEL_EXPORTER_OTLP_METRICS_ENDPOINT/OTEL_EXPORTER_OTLP_ENDPOINT; PTY viewer read loop refactored along the way). (#1504)

  • Lifecycle hook guide with timing diagram and per-SDK creation examples; SDK client-side timeout validation aligned with the Server. (#1605)
