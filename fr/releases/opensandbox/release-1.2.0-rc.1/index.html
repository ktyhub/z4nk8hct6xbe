OpenSandbox release-1.2.0-rc.1

Version OpenSandbox-1.2.0-rc.1

Première version candidate sur la ligne 1.2.0, contenant tout ce qui a été fusionné depuis release-1.1.1 — le titre est OSEP-0024 : pause automatique et réveil à l'accès pour les bacs à sable rapides, atterrissage de bout en bout. Les images sont publiées maintenant ; Les packages SDK/CLI sont expédiés sur la bosse stable 1.2.0. Veuillez tester et signaler les problèmes.

Faits saillants

  • La pause automatique et le réveil lors de l'accès pour les bacs à sable rapides (OSEP-0024) sont mis bout à bout : suivi des activités d'entrée et chemin de réveil, le balayeur d'inactivité côté serveur, le champ de création opt-in lifecycle.idlePolicy et le contrat de nouvelle tentative de réveil dans les cinq SDK - désactivés par défaut, additif uniquement (#2156 #2180 #2192 #2198 #2218)
  • Side-car de sortie (expérimental, opt-in) : admission Vault liée aux informations d'identification en direct, prise en charge HTTP/2 avec drain limité, persistance des fichiers de stratégie atomique et confinement des erreurs d'exécution (#2176 #2201 #2182 #2162 #2172)
  • Fiabilité du SDK : les téléchargements et téléchargements de fichiers ne sont plus interrompus après un délai d'attente de 30 secondes dans l'un des cinq SDK ; execd signale désormais les suppressions de processeur/mémoire et de MOO au niveau du bac à sable (#2165 #2186 #2196 #2206 #2191 #2200)

Serveur

  • Implémenter le côté serveur de la pause automatique OSEP-0024 pour les bacs à sable rapides : le champ de création de cycle de vie lifecycle.idlePolicy (idleTimeoutSeconds 30–86400, onIdle: pause, wakeOnAccess, activeProbe en option) est validé avec des limites pydantiques et persiste en tant qu'annotation CR réservée au bac à sable sandbox.opensandbox.io/idle-policy (l'échec d'écriture de l'annotation reste sécurisé - le bac à sable est créé sans politique) ; un balayeur inactif énumère les bacs à sable fsb activés à partir du cache des informateurs, vérifie l'activité dans Redis (écritures monotones maximales, les pierres tombales de clé manquante ne peuvent que retarder une pause), prend un verrouillage de pause par bac à sable avec une revérification sous verrouillage et émet un FastPath idempotent PauseSandbox ; un activeProbe déclaré s'exécute via la passerelle d'entrée et une réponse occupée enregistre l'activité ordinaire ; une sentinelle OpenSandbox-Skip-Activity: skip supprime l'observation pour une requête et est supprimée sur les sauts de passerelle et de serveur proxy (#2192 #2181)
  • Configurez la pause au ralenti sous le nouveau parapluie d'automatisation du cycle de vie : [idle_pause] devient [automation.idle_pause] et la porte redondante redis.enabled est supprimée — redis.dsn est requis (validé à la charge) lorsque enabled = true échoue bruyamment au lieu de ne pas démarrer silencieusement la balayeuse ; configuration.md est réécrit par souci de concision et documente désormais ingress.secure_access et les remplacements d'environnement-var manquants (#2215)
  • Pods BatchSandbox par défaut sur restartPolicy: Never : un redémarrage du conteneur kubelet sur place a recréé le conteneur principal à partir de son image - en effaçant la couche inscriptible et l'état en mémoire - tandis que le bac à sable continuait à signaler Succeed ; le redémarrage n'est jamais une récupération significative pour un bac à sable, donc la valeur par défaut est l'absence de redémarrage, ce qui rend également accessible le chemin de défaillance du terminal du contrôleur. Un restartPolicy explicite dans le modèle gagne toujours, le profil Windows continue de forcer Always (l'installation en plusieurs phases en dépend) et le mode pool est inchangé (#2128)
  • Traitez pasta/slirp4netns/none comme des modes réseau d'exécution de conteneur et transmettez-les directement, ce qui rend le réseau au niveau du noyau de podman sélectionnable — sous Windows 11 + WSL2 où netavark rompt le mode pont, pasta était le seul réseau fonctionnel et avait précédemment échoué à la création avec un 400 demandant un réseau Docker défini par l'utilisateur ; networkPolicy est désormais rejeté pour ces modes car il n'y a pas de pont auquel le side-car de sortie peut s'attacher (auparavant accepté silencieusement pour none) (#2203)
  • Analyser les horodatages Docker dont la fraction de seconde n'est pas à 3 ou 6 chiffres : Docker écrit RFC3339Nano (les zéros à droite sont supprimés), le fromisoformat de Python 3.10 rejette les fractions à 5 chiffres et l'assistant est revenu à datetime.now() - donc createdAt et status.lastTransitionAt ont signalé silencieusement l'heure actuelle ; la fraction est maintenant complétée par des zéros à 6 chiffres (#2220)

SDK

Les modifications de code ci-dessous utilisent la version stable 1.2.0 – rc ne fournit aucun package SDK.

  • Ajoutez le contrat OSEP-0024 SDK dans les cinq langues : un champ de création lifecycle.idlePolicy dactylographié (modèles IdlePolicy/ActivityProbe avec validation rapide côté client reflétant le serveur : délai d'attente de 30 à 86 400 s, couplage onIdle: "pause", limites de chemin de sonde/d'expiration ; câblé via la création standard et de modèle) et le contrat de nouvelle tentative de réveil - sur un 503 portant le marqueur OpenSandbox-Wake: expired appartenant à la passerelle (sa présence prouve que la demande a été parquée et n'a jamais été transmise, ce qui rend toute tentative de nouvelle méthode sécurisée), le SDK renvoie après Retry-After dans le cadre d'un budget limité (par défaut 5 tentatives / 60 s, par boutons client), l'épuisement déclenche une exception de délai de réveil typée transportant les tentatives et le temps d'attente, la reprise côté serveur n'est jamais annulé, la gestion du 503 nu est inchangée et les transports SSE/streaming contournent la nouvelle tentative de réveil (#2198 #2218)
  • Arrêtez de limiter les téléchargements et les téléchargements de fichiers au délai d'expiration de la demande (30 s par défaut) dans les quatre SDK restants — le délai d'expiration de l'appel complet (http.Client.Timeout, OkHttp callTimeout, AbortController, HttpClient.Timeout) couvrait l'envoi du corps de la requête et la lecture de la réponse, de sorte que tout transfert important ou lent échouait en cours de vol, même s'il était sain ; les transferts s'exécutent désormais sur un client dédié sans délai d'appel complet qui limite toujours l'attente des en-têtes de réponse, donc un transfert bloqué échoue toujours au lieu de se bloquer (#2165 #2186 #2196 #2206)
  • Supprimer les métriques sandbox.create client pour les créations d'échauffement du pool client dans Go, Python et JavaScript, en s'alignant sur Kotlin : trafic d'échauffement (skipHealthCheck codé en dur, centaines de ms) préalablement mélangé aux métriques de latence de création destinées à l'utilisateur et traîné p50/p99 vers le bas ; création directe à partir de l'acquisition du pool et créations face à l'utilisateur, maintien du reporting (#2199) ###Python
  • Nettoyage du démarrage du pool asynchrone annulé : l'annulation de SandboxPoolAsync.start() en cours d'attente a laissé l'instance bloquée dans STARTING, où un start() suivant est revenu silencieusement et les ressources appartenant au démarrage ont ignoré le nettoyage ; l'annulation réutilise désormais le chemin de nettoyage de réconciliation, se déplace vers STOPPED et relance pour que l'appelant puisse réessayer (#2209)
  • Arrêter de signaler les remplacements de fichiers ayant échoué comme réussis : les adaptateurs de système de fichiers ordinaires ont capturé et rejeté le JSONDecodeError du client généré, de sorte qu'un HTTP 400/500 vide ou non-JSON de replace_contents() a renvoyé un succès et un agent a pu continuer à s'appuyer sur une modification non appliquée ; le catch est supprimé et le contrat d'échec documenté de SandboxException est restauré (les adaptateurs de session isolée conservent leur catch de compatibilité de corps vide) (#2222)

Aller

  • Supprimez tous les en-têtes OPEN-SANDBOX-*/OPENSANDBOX-* et chaque en-tête d'authentification configuré (y compris les noms X-EXECD-ACCESS-TOKEN, X-API-Key et WithAuthHeader personnalisés) sur les redirections d'origine croisée, en comparant chaque destination au schéma, à l'hôte et au port effectif de la demande initiale afin que les informations d'identification ne puissent pas réapparaître sur les sauts d'origine étrangère ultérieurs ; appliqué aux métriques de cycle de vie, d'exécution, de sortie, de transfert de fichiers, de SSE et de création tout en préservant les stratégies CheckRedirect personnalisées (#2178)

Contrôleur

  • Conserver un BatchSandbox jusqu'à ce que le nettoyage soit terminé : un bac à sable supprimé pourrait disparaître du cycle de vie API (GET 404) alors que son pod détenu était toujours en cours d'exécution, permettant à un bac à sable de remplacement d'écrire le même répertoire persistant avant la fermeture de l'ancien rédacteur ; la suppression utilise désormais la suppression en cascade au premier plan aux côtés des finaliseurs de nettoyage de tâches et de libération de pool existants, et la réconciliation TTL s'arrête une fois la suppression acceptée - DELETE renvoie toujours 204 lorsqu'elle est acceptée, les requêtes signalent Stopping pendant le nettoyage géré et 404 n'arrive qu'après la fin de l'exécution ; les cinq documents et journaux kill des cinq SDK décrivent la sémantique de suppression acceptée (#2154)

Exécuté

  • Signaler les kills du MOO via l'interrogation cgroupfs : les preuves côté noyau étaient hors de portée depuis l'intérieur d'un bac à sable (pas de CAP_SYSLOG, pas de /dev/kmsg), donc les événements du MOO étaient inobservables ; execd interroge désormais le groupe de contrôle du bac à sable toutes les 5 s et compare le compteur de destruction du MOO du noyau (memory.events sur la v2, meilleur effort sur la v1) — les compteurs hiérarchiques couvrent les groupes de contrôle imbriqués comme les sessions isolées bwrap — en exportant execd.system.oom.kills avec un attribut de niveau local/descendant plus des journaux d'avertissement structurés avec une attribution de victime au mieux ; l'observateur s'exécute indépendamment de l'exportation OTLP et n'a besoin d'aucune fonctionnalité (#2191)
  • Rapporter les métriques CPU/mémoire à l'échelle du bac à sable : GET /metrics et les jauges execd.system.cpu.usage/execd.system.memory.usage_bytes lisent /proc via gopsutil, qui, à l'intérieur d'un conteneur, décrit l'hôte - les tableaux de bord affichent la mémoire et le CPU à l'échelle de l'hôte ; lorsque le groupe de contrôle du bac à sable comporte des limites configurées, l'utilisation provient désormais du propre groupe de contrôle du bac à sable (cpu.stat/cpu.max, memory.current/memory.max, repli v1, les hôtes hybrides préfèrent la v1), la vue d'hôte précédente étant conservée pour les invités illimités tels que les microVM à bac à sable rapide ; le format du fil est inchangé (#2200)
  • Codage en pourcentage des guillemets et des barres obliques inverses dans Content-Disposition : un nom de fichier contenant " ou \ a produit une chaîne entre guillemets qu'aucun analyseur standard n'accepte (mime.ParseMediaType l'a rejeté et clients n'a obtenu aucun nom de fichier) ; ces noms sont désormais acheminés via le même codage filename*=UTF-8'' que les noms non-ASCII (#2161)
  • Analyser l'en-tête Range avant de définir les en-têtes de téléchargement : une plage mal formée a répondu 416 avec les fichiers Content-Disposition et Content-Length toujours attachés, tronquant le corps du JSON ou le supprimant entièrement - faisant surface dans le Python SDK comme une erreur de connexion au lieu d'un 416 SandboxApiException ; la réponse d'erreur est maintenant un JSON 416 propre et les réponses 200/206 sont inchangées (#2216)

Réseautage

sortie

Tous les éléments ci-dessous concernent le moteur d'exécution de la révision expérimentale OSEP-0023, désactivé par défaut ; les déploiements existants et DNS uniquement restent inchangés.

  • Ajout d'une admission expérimentale au Vault liée aux informations d'identification en direct : les mutations du Vault transitent par la transaction de révision et installent l'instantané privé authentifié avant de publier le résultat public ; les connexions HTTPS liées sont admises et les informations d'identification d'en-tête injectées uniquement après une correspondance exacte de la demande avec l'accord d'autorité SNI/HTTP/1 (l'extension ECH ClientHellos reste opaque), avec rotation des informations d'identification par demande, clôture des liaisons supprimées sur les connexions existantes et retrait du transport à la date limite de vidange ; la portée est HTTPS de l'hôte exact sur 443 avec HTTP/1.1 et les informations d'identification d'en-tête en ligne (#2176)
  • Reconnaître les révisions de politique en direct avant la publication : la politique API et les rechargements automatiques deny.always/allow.always sont désormais validés dans l'ordre : persistance facultative du fichier, application nft, accusé de réception exact du récepteur ou relecture rapprochée, puis publication par proxy et succès du API - avec récupération fermée en cas d'échec lorsque le récepteur échoue après que nft a pris effet, et délais de vidange de 30 secondes sur les mises à jour de politique uniquement qui ne s'étendent jamais sur les révisions ultérieures. (#2182)
  • Ajout d'une admission HTTP/2 expérimentale et d'un drain limité : les instantanés se lient de manière atomique aux ID de flux client réels au niveau des en-têtes de requête, les requêtes post-clôture obtiennent REFUSED_STREAM avant d'atteindre l'origine, GOAWAY attend les obligations de sortie en suspens pendant que l'expiration utilise une fermeture anormale, et une solution de repli de sortie mitmdump unique couvre la propriété de nettoyage invérifiable ; l'adaptateur est épinglé sur CPython 3.10/3.11 et rejette les proxys en amont chaînés configurés (#2201)
  • Contenir les erreurs de récupération d'exécution dans l'espace de noms du réseau side-car : une sortie MITM inattendue déclenche désormais une clôture IPv4/IPv6 indépendante et vérifiée par relecture, épinglée à l'espace de noms d'origine pour la durée de vie du processus - bloquant tout le trafic d'entrée/sortie/transfert, y compris les connexions existantes et le bouclage - avec QuarantineConfirmed signalé uniquement après une véritable relecture des règles ; les mutations normales réussies n'introduisent jamais de clôture (#2172)
  • Conserver les fichiers de politique de révision expérimentale de manière atomique : les écritures passent par un inode temporaire du même répertoire avec fsync + rename + répertoire fsync, les restaurations remettent exactement les octets précédents (ou l'absence synchronisée) et le stockage non pris en charge - montages de liaison de fichiers, chemins en lecture seule ou liés symboliquement, liens physiques, propriété non sécurisée, métadonnées SELinux/IMA non prises en charge - est rejeté avant que l'original ne soit touché ; les opérateurs doivent fournir un montage de répertoire existant, exclusivement écrit, appartenant à la sortie (#2162)
  • Classifier les effets d'application nft avant la récupération de la politique : la construction locale, l'annulation avant le démarrage et les échecs de démarrage sont inchangés (état préservé, nouvelle tentative autorisée après la restauration), l'exécution réussie est validée et chaque erreur post-démarrage ou non classifiée est inconnue - fermeture de l'admission de l'écrivain et verrouillage de la récupération avant la restauration au mieux ; la solution de secours de table manquante conserve les deux erreurs et ne rétrograde jamais un résultat inconnu (#2167)

entrée

  • Implémentation du suivi d'activité et du réveil à l'accès OSEP-0024 : avec --activity-enabled, chaque requête acheminée enregistre un horodatage d'activité monotone sur Redis — déclencher et oublier, jamais sur le chemin actif — avec fusion d'écriture par réplique, mises à jour Lua monotoniques-max afin que les écritures dans le désordre ne régressent jamais avec l'observation la plus récente et le traitement par lots du pipeline ; avec --wake-enabled, une requête acheminée vers un bac à sable rapide en pause est garée au lieu d'une réponse 503 : un ResumeSandbox par réplique par bac à sable sous un vol unique clôturé par un point de contrôle, un parking et un budget délimités (débordement/délais d'attente, réponse 503 + Retry-After pendant que la restauration continue, jamais annulée), et la réentrée sur un itinéraire périmé est rejouée sur un nouvel itinéraire uniquement lorsqu'elle est rejouable en toute sécurité ; avec les deux indicateurs non définis, le comportement est identique en octets à celui d'aujourd'hui (#2156)
  • Renforcement complet du sillage OSEP-0024 : la relecture de routes obsolètes après la transmission est limitée aux méthodes idempotentes avec des corps reproductibles (un POST transmis n'est jamais réexécuté silencieusement) ; la réponse de délai d'attente de réveil préalable porte le marqueur défini par OSEP (503 + Retry-After: 1 + OpenSandbox-Wake: expired + un corps sandbox_wake_timeout nommant le bac à sable), supprimé de chaque réponse en amont afin qu'un bac à sable ne puisse pas forger la provenance ; un permis de restauration distinct (--wake-restore-max, détenu au terminal de vol) limite les restaurations simultanées indépendamment du parking ; et wake nécessite désormais l'opt-in lifecycle.idlePolicy par sandbox lu strictement à partir de l'annotation Sandbox CR - manquant ou mal formé signifie aucune politique et le 503 permanent d'aujourd'hui, jamais un opt-in implicite ; Les valeurs du graphique gateway.wake.* câblent les indicateurs et ajoutent un RBAC en lecture seule uniquement lorsqu'il est activé (#2180)

Bac à sable rapide

  • Rendre la suppression du sandbox fiable : la suppression envoie désormais une suppression Fastlet clôturée avant toute vérification d'absence d'exécution, de sorte qu'une entrée de registre manquante, un échec de transport ou une réponse d'inspection vide ne sont plus traités comme une preuve que le bac à sable a disparu (ce qui pourrait rendre la microVM orpheline pendant la disparition du CR) ; le Fastlet enregistre une pierre tombale par identité afin qu'une création retardée ne puisse pas relancer un bac à sable supprimé, et le finaliseur de nettoyage est conservé lors de la création du CR (#2214)
  • Rendre le placement de création plus rapide : après des rejets prouvés, FastPath actualise sa liste de candidats dans un budget limité (à l'exclusion des Fastlets déjà essayés) et attend jusqu'à 2 s que le statut de l'affectation rattrape son retard avant de changer, et un outil de suivi de création local empêche un pod Fastlet supprimé ou remplacé de bloquer la projection de la nouvelle affectation ou de récupérer la perte du pod - le chemin heureux de première création est inchangé (#2214)
  • Mises à jour NAT invité par lots : les nouveaux emplacements de VM invité préparent des chaînes DNAT/SNAT dédiées et la restauration remplace uniquement ces chaînes dans un lot iptables-restore --noflush, donc la réapplication de la même adresse invité n'accumule plus de règles, avec une nouvelle métrique fast_sandbox_network_guest_apply_stage_latency_seconds séparant les étapes d'application (#2214)

Divers

  • Console : obtenez la première tranche d'une nouvelle console Web en option : un FastAPI BFF avec des sessions httpOnly et une connexion locataire/administrateur proxy le cycle de vie /sandboxes API (avec un runtimeSummary sur liste/obtenir), plus un React SPA couvrant la vue d'ensemble des locataires, la liste/création/détail du bac à sable, le renouvellement/suppression et le point de terminaison ; premier des cinq PR de console prévus, avec l'interface utilisateur d'administration à suivre (#2129)
  • CLI : forcer les valeurs du fichier de configuration à leurs types déclarés afin qu'un api_key numérique ne se résolve plus silencieusement en null (interrompant chaque commande avec un ValidationError) et qu'un defaults.timeout numérique ne plante plus sandbox create (#2169) ; garder la sortie accessible en écriture sur les flux non UTF-8 — les utilisateurs de GBK/cp1252/C-locale ne pouvaient exécuter aucune commande osb car le rendu emoji générait UnicodeEncodeError, souvent après que le travail était déjà terminé ; les flux échappent désormais aux caractères non codables et la sortie YAML est à nouveau sauvegardée pour rester valide (#2187) ; écrire les compétences installées là où chaque outil les lit réellement — la cible claude écrit désormais .claude/skills/<name>/SKILL.md (le fichier plat précédent n'a jamais été chargé silencieusement) et les cibles globales cline/copilot écrivent ~/.cline/rules/opensandbox-<name>.md et ~/.copilot/copilot-instructions.md ; les fichiers inertes précédemment installés ne sont pas migrés (#2194 #2208)
  • Environnement d'intégration Fast-sandbox : pilotez les étapes de vérification via le osb CLI publié au lieu du curl brut (construction de modèle, création/élimination du bac à sable, récupération du point de terminaison, pause/reprise, création/obtention/liste/suppression/restauration d'instantanés, renouvellement), avec server_api conservé uniquement pour les appels que le CLI n'expose pas (la politique de réseau remplace PUT, RFC 7396 merge-patch, la barrière de code de ré-entrée d'instantané, les sondes de passerelle) (#2171) ; ajoutez un profil opt-in IDLE_PAUSE=1 qui déploie le Redis éphémère, active les valeurs de balayage et d'activité/réveil de la passerelle [automation.idle_pause], et vérifie la boucle complète de pause automatique → réveil à l'accès sur up, plus une suite SDK e2e et un travail de flux de travail KVM nocturne (#2202)
  • Docs : acceptez et documentez OSEP-0024 — la proposition elle-même (#2152) ainsi qu'une page d'architecture et un guide de l'utilisateur couvrant l'activation, la référence du champ idlePolicy, le contrat de sonde d'activité, le comportement de relance de réveil du SDK et un diagramme interactif (#2217) ; unifier les métriques de télémétrie des composants de sept emplacements dispersés en une seule référence à docs/guides/telemetry.md (#2205) ; actualisez les pages d'architecture réseau avec des diagrammes SVG relookés, une page de sortie condensée et la relocalisation du guide d'isolation du réseau (#2210) ; alignez CONTRIBUANT avec le code (Go 1.25, Gin — pas Beego) (#2175), dédupliquez les règles AGENTS.md et indiquez une fois la règle de placement architecture-vs-guides (#2211), et corrigez le terme abusif de « profil de sortie Fastlet partagé » en « processus de sortie partagé par pod Fastlet » avec une note qui gRPC se termine à FastPath (#2225)
  • Tests/CI : alignez l'assertion e2e de collecte de journaux nœud-agent avec la nouvelle ligne de fin préservée d'execd (#2164) ; rendre le flux de travail de la version parapluie uniquement en supprimant l'exécution hebdomadaire planifiée (#2223)
  • version : version de la plate-forme remplacée par 1.2.0-rc.1 dans les graphiques et les références d'images

Mise à niveau et compatibilité

  • Changement de comportement : les pods BatchSandbox sont désormais par défaut restartPolicy: Never (implicite Always → Never) — les déploiements qui reposaient sur la valeur implicite par défaut et souhaitaient des redémarrages doivent définir explicitement restartPolicy: Always dans leur batchsandbox_template_file (un avertissement de démarrage notera le compromis) (#2128)
  • Changement de comportement : les bacs à sable supprimés restent interrogeables dans Stopping jusqu'à ce que le nettoyage à l'exécution soit terminé, puis renvoient 404 – clients partageant un répertoire persistant doit attendre le 404 avant de commencer un remplacement (#2154)
  • Changement de comportement : les métriques CPU/mémoire exécutées rapportent des valeurs à l'échelle du bac à sable lorsque le groupe de contrôle du bac à sable a des limites configurées (auparavant à l'échelle de l'hôte) ; La sémantique des champs GET /metrics et les noms des métriques OTel restent inchangés, mais les tableaux de bord changeront (#2200)
  • Changement de comportement : networkPolicy est rejeté pour les modes réseau Docker none/pasta/slirp4netns — précédemment accepté silencieusement pour none (#2203)
  • Images : opensandbox/<component>:release-1.2.0-rc.1 (les trois registres)
  • Packages : inchangés – Les artefacts SDK/CLI sont publiés dans la version stable 1.2.0
  • Graphiques : rendu à partir de cette balise (helm template ./manifests/charts/opensandbox)
  • Kubernetes : plage prise en charge v1.21 – v1.34 (les cartes déclarent kubeVersion: ">=1.21.1-0")
  • Skew : serveur ↔ CLI/SDK même ligne prise en charge ; ±1 avertissement mineur

OpenSandbox release-1.2.0-rc.1

First release candidate on the 1.2.0 line, carrying everything merged since release-1.1.1 — the headline is OSEP-0024: auto-pause and wake-on-access for fast sandboxes, landing end to end. Images publish now; SDK/CLI packages ship at the 1.2.0 stable bump. Please test and report issues.

Highlights

  • Auto-pause and wake-on-access for fast sandboxes (OSEP-0024) lands end to end: ingress activity tracking and the wake path, the server-side idle sweeper, the opt-in lifecycle.idlePolicy create field, and the wake-retry contract in all five SDKs — off by default, additive only (#2156 #2180 #2192 #2198 #2218)
  • Egress sidecar (experimental, opt-in): live credential-bound Vault admission, HTTP/2 support with bounded drain, atomic policy-file persistence, and runtime fault containment (#2176 #2201 #2182 #2162 #2172)
  • SDK reliability: file uploads and downloads are no longer aborted at the 30-second request timeout in any of the five SDKs; execd now reports sandbox-scoped CPU/memory and OOM kills (#2165 #2186 #2196 #2206 #2191 #2200)

Server

  • Implement the server side of OSEP-0024 auto-pause for fast sandboxes: the lifecycle create field lifecycle.idlePolicy (idleTimeoutSeconds 30–86400, onIdle: pause, wakeOnAccess, optional activeProbe) validates with pydantic bounds and persists as the reserved sandbox.opensandbox.io/idle-policy Sandbox CR annotation (annotation-write failure stays fail-safe — the sandbox is created unpolicied); an idle sweeper enumerates opted-in fsb sandboxes from the informer cache, checks activity in Redis (monotonic-max writes, missing-key tombstones can only delay a pause), takes a per-sandbox pause lock with re-verify under lock, and issues an idempotent FastPath PauseSandbox; a declared activeProbe executes through the ingress gateway and a busy answer records ordinary activity; an OpenSandbox-Skip-Activity: skip sentinel suppresses the observation for one request and is stripped on both gateway and server-proxy hops (#2192 #2181)
  • Configure idle-pause under the new lifecycle-automation umbrella: [idle_pause] becomes [automation.idle_pause] and the redundant redis.enabled gate is removed — redis.dsn is required (validated at load) when enabled = true, failing loudly instead of silently not starting the sweeper; configuration.md is rewritten for conciseness and now documents ingress.secure_access and the missing env-var overrides (#2215)
  • Default BatchSandbox pods to restartPolicy: Never: a kubelet in-place container restart recreated the main container from its image — wiping the writable layer and in-memory state — while the sandbox kept reporting Succeed; restarting is never a meaningful recovery for a sandbox, so the honest default is no restart, which also makes the controller's terminal-failure path reachable. An explicit restartPolicy in the template still wins, the Windows profile keeps forcing Always (multi-phase installation relies on it), and pool mode is unchanged (#2128)
  • Treat pasta/slirp4netns/none as container-runtime network modes and pass them straight through, making podman's kernel-level networking selectable — on Windows 11 + WSL2 where netavark breaks bridge mode, pasta was the only working network and previously failed create with a 400 asking for a user-defined Docker network; networkPolicy is now rejected for these modes since there is no bridge for the egress sidecar to attach to (previously silently accepted for none) (#2203)
  • Parse Docker timestamps whose fractional second is not 3 or 6 digits: Docker writes RFC3339Nano (trailing zeros dropped), Python 3.10's fromisoformat rejects 5-digit fractions, and the helper fell back to datetime.now() — so createdAt and status.lastTransitionAt silently reported the current time; the fraction is now zero-padded to 6 digits (#2220)

SDKs

Code changes below ride the 1.2.0 stable release — rc ships no SDK packages.

  • Add the OSEP-0024 SDK contract to all five languages: a typed lifecycle.idlePolicy create field (IdlePolicy/ActivityProbe models with client-side fail-fast validation mirroring the server: timeout 30–86400 s, onIdle: "pause" pairing, probe path/timeout bounds; wired through both standard and template create) and the wake-retry contract — on a 503 carrying the gateway-owned OpenSandbox-Wake: expired marker (its presence proves the request was parked and never forwarded, making any-method retry safe), the SDK resends after Retry-After under a bounded budget (default 5 attempts / 60 s, per-client knobs), exhaustion raises a typed wake-timeout exception carrying attempts and waited time, the server-side resume is never canceled, bare 503 handling is unchanged, and SSE/streaming transports bypass wake retry (#2198 #2218)
  • Stop capping file uploads and downloads at the request timeout (30 s default) in all four remaining SDKs — the whole-call timeout (http.Client.Timeout, OkHttp callTimeout, AbortController, HttpClient.Timeout) covered sending the request body and reading the response, so any large or slow transfer failed mid-flight even while healthy; transfers now run on a dedicated client with no whole-call deadline that still bounds the wait for response headers, so a stalled transfer still fails instead of hanging (#2165 #2186 #2196 #2206)
  • Suppress sandbox.create client metrics for client-pool warmup creates in Go, Python, and JavaScript, aligning with Kotlin: warmup traffic (hardcoded skipHealthCheck, hundreds of ms) previously mixed into user-facing create-latency metrics and dragged p50/p99 down; direct-create from pool acquire and user-facing creates keep reporting (#2199)

Python

  • Clean up cancelled async pool startup: cancelling SandboxPoolAsync.start() mid-await left the instance stuck in STARTING, where a subsequent start() silently returned and startup-owned resources skipped cleanup; cancellation now reuses the reconciliation cleanup path, moves to STOPPED, and re-raises so the caller can retry (#2209)
  • Stop reporting failed file replacements as successful: the ordinary filesystem adapters caught and discarded the generated client's JSONDecodeError, so an empty or non-JSON HTTP 400/500 from replace_contents() returned success and an agent could keep building on an unapplied edit; the catch is removed and the documented SandboxException failure contract is restored (isolated-session adapters keep their empty-body compatibility catch) (#2222)

Go

  • Strip all OPEN-SANDBOX-*/OPENSANDBOX-* headers and every configured authentication header (including X-EXECD-ACCESS-TOKEN, X-API-Key, and custom WithAuthHeader names) on cross-origin redirects, comparing each destination against the initial request's scheme, host, and effective port so credentials cannot reappear on later foreign-origin hops; applied across lifecycle, execd, egress, file transfers, SSE, and creation metrics while preserving custom CheckRedirect policies (#2178)

Controller

  • Retain a BatchSandbox until cleanup completes: a deleted sandbox could disappear from the lifecycle API (GET 404) while its owned pod still ran, letting a replacement sandbox write the same persistent directory before the old writer exited; deletion now uses foreground cascading deletion alongside the existing task-cleanup and pool-release finalizers, and TTL reconciliation stops once deletion is accepted — DELETE still returns 204 when accepted, queries report Stopping during managed cleanup, and 404 arrives only after the runtime is gone; all five SDKs' kill docs and logs describe the accepted-deletion semantics (#2154)

Execd

  • Report OOM kills via cgroupfs polling: kernel-side evidence was out of reach from inside a sandbox (no CAP_SYSLOG, no /dev/kmsg), so OOM events were unobservable; execd now polls the sandbox cgroup every 5 s and diffs the kernel OOM kill counter (memory.events on v2, best-effort on v1) — the hierarchical counters cover nested cgroups like bwrap isolated sessions — exporting execd.system.oom.kills with a local/descendant level attribute plus structured warn logs with best-effort victim attribution; the watcher runs independently of OTLP export and needs no capabilities (#2191)
  • Report sandbox-scoped CPU/memory metrics: GET /metrics and the execd.system.cpu.usage/execd.system.memory.usage_bytes gauges read /proc through gopsutil, which inside a container describes the host — dashboards showed host-wide memory and CPU; when the sandbox cgroup carries configured limits, usage now comes from the sandbox's own cgroup (cpu.stat/cpu.max, memory.current/memory.max, v1 fallback, hybrid hosts prefer v1), with the previous host view kept for unlimitied guests such as fast-sandbox microVMs; the wire format is unchanged (#2200)
  • Percent-encode quotes and backslashes in Content-Disposition: a filename containing " or \ produced a quoted-string no standard parser accepts (mime.ParseMediaType rejected it and clients got no filename at all); such names now route through the same filename*=UTF-8'' encoding as non-ASCII names (#2161)
  • Parse the Range header before setting download headers: a malformed range answered 416 with the file's Content-Disposition and Content-Length still attached, truncating the JSON body or dropping it entirely — surfacing in the Python SDK as a connection error instead of a 416 SandboxApiException; the error response is now a clean JSON 416, and 200/206 responses are unchanged (#2216)

Networking

egress

All items below concern the default-off OSEP-0023 experimental revision runtime; legacy and DNS-only deployments are unchanged.

  • Add experimental live credential-bound Vault admission: Vault mutations flow through the revision transaction and install the private authenticated snapshot before publishing the public result; bound HTTPS connections are admitted and header credentials injected only after exact request matching with SNI/HTTP/1 authority agreement (ECH-extension ClientHellos stay opaque), with per-request credential rotation, fencing of removed bindings on existing connections, and transport retirement at the drain deadline; scope is exact-host HTTPS on 443 with HTTP/1.1 and inline header credentials (#2176)
  • Acknowledge live Policy revisions before publication: the Policy API and automatic deny.always/allow.always reloads now commit in order — optional file persistence, nft application, exact receiver acknowledgement or reconciled readback, then proxy publication and API success — with fail-closed recovery when the receiver fails after nft has taken effect, and 30-second drain deadlines on policy-only updates that never extend across later revisions (#2182)
  • Add experimental HTTP/2 admission and bounded drain: snapshots bind atomically to actual client stream IDs at requestheaders, post-fence requests get REFUSED_STREAM before reaching origin, GOAWAY waits for outstanding output obligations while expiry uses abnormal closure, and a once-only mitmdump exit fallback covers unverifiable cleanup ownership; the adapter is pinned to CPython 3.10/3.11 and rejects configured chained upstream proxies (#2201)
  • Contain runtime recovery faults in the sidecar network namespace: an unexpected MITM exit now triggers an independent, read-back-verified IPv4/IPv6 fence pinned to the original namespace for the process lifetime — blocking all input/output/forward traffic including existing connections and loopback — with QuarantineConfirmed reported only after real rule readback; normal successful mutations never introduce a fence (#2172)
  • Persist experimental revision policy files atomically: writes go through a same-directory temporary inode with fsync + rename + directory fsync, restores put back the exact previous bytes (or synchronized absence), and unsupported storage — file bind mounts, read-only or symlinked paths, hardlinks, unsafe ownership, unsupported SELinux/IMA metadata — is rejected before the original is touched; operators must provide an existing egress-owned, exclusively written directory mount (#2162)
  • Classify nft apply effects before policy recovery: local construction, pre-start cancellation, and start failures are Unchanged (state preserved, retry allowed after restore), successful execution is Committed, and every post-start or unclassified error is Unknown — closing writer admission and latching recovery before best-effort restoration; the missing-table fallback retains both errors and never downgrades an Unknown result (#2167)

ingress

  • Implement OSEP-0024 activity tracking and wake-on-access: with --activity-enabled, every routed request records a monotonic activity timestamp to Redis — fire-and-forget, never on the hot path — with per-replica write coalescing, Lua monotonic-max updates so out-of-order writes never regress the newest observation, and pipeline batching; with --wake-enabled, a request routed to a paused fast sandbox is parked instead of answered 503: one ResumeSandbox per replica per sandbox under a checkpoint-fenced singleflight, a bounded parking lot and budget (overflow/timeouts answer 503 + Retry-After while the restore continues, never canceled), and stale-route re-entry replayed on a fresh route only when safely replayable; with both flags unset, behavior is byte-identical to today (#2156)
  • Complete OSEP-0024 wake hardening: post-forward stale-route replay is restricted to idempotent methods with reproducible bodies (a forwarded POST is never silently re-executed); the pre-forward wake-timeout answer carries the OSEP-defined marker (503 + Retry-After: 1 + OpenSandbox-Wake: expired + a sandbox_wake_timeout body naming the sandbox), stripped from every upstream response so a sandbox cannot forge provenance; a separate restore permit (--wake-restore-max, held to flight terminal) bounds concurrent restores independently of the parking lot; and wake now requires the per-sandbox lifecycle.idlePolicy opt-in read strictly from the Sandbox CR annotation — missing or malformed means no policy and today's permanent 503, never an implicit opt-in; gateway.wake.* chart values wire the flags and add read-only RBAC only when enabled (#2180)

Fast Sandbox

  • Make sandbox deletion reliable: deletion now sends a fenced Fastlet delete before any runtime-absence check, so a missing registry entry, transport failure, or empty inspect response is no longer treated as proof the sandbox is gone (which could orphan the microVM while the CR disappeared); the Fastlet records a per-identity tombstone so a delayed create cannot revive a deleted sandbox, and the cleanup finalizer is persisted at CR creation (#2214)
  • Make create placement recover faster: after proven rejections FastPath refreshes its candidate list within a bounded budget (excluding Fastlets already tried) and waits up to 2 s for assignment status to catch up before switching, and a process-local create tracker stops a deleted or replaced Fastlet pod from blocking the new assignment's projection or racing pod-loss recovery — the first-create happy path is unchanged (#2214)
  • Batch guest NAT updates: new guest-VM slots prepare dedicated DNAT/SNAT chains and restore replaces only those chains in one iptables-restore --noflush batch, so reapplying the same guest address no longer accumulates rules, with a new fast_sandbox_network_guest_apply_stage_latency_seconds metric separating the apply stages (#2214)

Misc

  • Console: land the first slice of a new optional web console — a FastAPI BFF with httpOnly sessions and tenant/admin login proxying the lifecycle /sandboxes API (with a runtimeSummary on list/get), plus a React SPA covering tenant overview, sandbox list/create/detail, renew/delete, and the endpoint; first of five planned console PRs, with the admin UI to follow (#2129)
  • CLI: coerce config-file values to their declared types so a numeric api_key no longer silently resolves to null (breaking every command with a ValidationError) and a numeric defaults.timeout no longer crashes sandbox create (#2169); keep output writable on non-UTF-8 streams — GBK/cp1252/C-locale users could not run any osb command because emoji rendering raised UnicodeEncodeError, often after the work was already done; streams now escape unencodable characters and YAML output is re-dumped escaped to stay valid (#2187); write installed skills where each tool actually reads them — the claude target now writes .claude/skills/<name>/SKILL.md (the previous flat file was silently never loaded), and global cline/copilot targets write ~/.cline/rules/opensandbox-<name>.md and ~/.copilot/copilot-instructions.md; previously installed inert files are not migrated (#2194 #2208)
  • Fast-sandbox integration environment: drive the verify stages through the published osb CLI instead of raw curl (template build, sandbox create/kill, endpoint fetch, pause/resume, snapshot create/get/list/delete/restore, renew), with server_api kept only for calls the CLI does not expose (networkpolicy replace PUT, RFC 7396 merge-patch, the snapshot re-entry code fence, gateway probes) (#2171); add an opt-in IDLE_PAUSE=1 profile that deploys ephemeral Redis, enables the [automation.idle_pause] sweeper and gateway activity/wake values, and verifies the full auto-pause → wake-on-access loop on up, plus an SDK e2e suite and a nightly KVM workflow job (#2202)
  • Docs: accept and document OSEP-0024 — the proposal itself (#2152) plus an architecture page and user guide covering enablement, the idlePolicy field reference, the activity-probe contract, SDK wake-retry behavior, and an interactive diagram (#2217); unify component telemetry metrics from seven scattered locations into one reference at docs/guides/telemetry.md (#2205); refresh the network architecture pages with restyled SVG diagrams, a condensed egress page, and the network-isolation guide relocation (#2210); align CONTRIBUTING with the code (Go 1.25, Gin — not Beego) (#2175), dedupe AGENTS.md rules and state the architecture-vs-guides placement rule once (#2211), and fix the "shared Fastlet egress profile" misnomer to "shared egress process per Fastlet pod" with a note that gRPC ends at FastPath (#2225)
  • Tests/CI: align the node-agent log-collection e2e assertion with execd's preserved trailing newline (#2164); make the umbrella release workflow dispatch-only by dropping the weekly scheduled dry-run (#2223)
  • release: bump platform version to 1.2.0-rc.1 across charts and image references

Upgrade & Compatibility

  • Behavior change: BatchSandbox pods now default to restartPolicy: Never (implicit Always → Never) — deployments that relied on the implicit default and want restarts must set restartPolicy: Always explicitly in their batchsandbox_template_file (a startup warning will note the trade-off) (#2128)
  • Behavior change: deleted sandboxes stay queryable in Stopping until runtime cleanup completes, and only then return 404 — clients sharing a persistent directory should wait for the 404 before starting a replacement (#2154)
  • Behavior change: execd CPU/memory metrics report sandbox-scoped values when the sandbox cgroup has limits configured (previously host-wide); GET /metrics field semantics and OTel metric names are unchanged, but dashboards will shift (#2200)
  • Behavior change: networkPolicy is rejected for Docker network modes none/pasta/slirp4netns — previously accepted silently for none (#2203)
  • Images: opensandbox/<component>:release-1.2.0-rc.1 (all three registries)
  • Packages: unchanged — SDK/CLI artifacts publish at the 1.2.0 stable release
  • Charts: render from this tag (helm template ./manifests/charts/opensandbox)
  • Kubernetes: supported range v1.21 – v1.34 (charts declare kubeVersion: ">=1.21.1-0")
  • Skew: server ↔ CLI/SDK same line supported; ±1 minor warns
