Quoi de neuf

✨Caractéristiques

  • Réessayer les politiques d'acquisition de pool — Les pools sandbox Go prennent désormais en charge AcquirePolicyRetryNextIdle et AcquirePolicyRetryNextIdleThenCreate, permettant à Acquire d'ignorer les candidats inactifs obsolètes avant d'échouer ou de revenir à la création directe. Les politiques existantes conservent leur comportement actuel ; MaxAcquireRetries est par défaut 3. #1347
  • Sandbox créer des métriques — Sandbox.Create signale désormais les événements de latence de déclenchement et d'oubli de sandbox.create au serveur de cycle de vie. Les rapports ignorent le biais de version de l'ancien serveur et peuvent être désactivés avec OPENSANDBOX_DISABLE_METRICS=1. #1307
  • En-tête IP Client — le SDK détecte désormais au mieux l'IPv4 de l'intranet hôte et l'envoie sous le nom OPEN-SANDBOX-CLIENT-IP sur les requêtes sortantes. Les en-têtes fournis par l'utilisateur ne sont jamais écrasés. #1326
  • ** Attacher aux sessions isolées ** — le SDK peut désormais s'attacher à une session isolée existante par ID de session, permettant aux travailleurs apatrides de récupérer un handle fonctionnel pendant que la session exécutée en mémoire reste active. #1295
  • Disponibilité du mode UID — les réponses de session isolées exposent désormais la disponibilité par mode setpriv / userns, et les modes demandés indisponibles échouent avec 503 NOT_SUPPORTED. #1320
  • Filtrage exact des noms d'instantanés — la liste des instantanés prend désormais en charge un filtre name exact. #1301
  • Montages et liste de liaisons de sessions isolées — les sessions isolées peuvent désormais recevoir des montages de liaison explicites, et le SDK expose la liste des sessions isolées afin que les appelants puissent inspecter les sessions actives. #1264 #1269
  • Substitutions d'espaces réservés Credential Vault : la correspondance des demandes prend désormais en charge les espaces réservés opt-in pour les surfaces de chemin, de requête, d'en-tête et de corps, y compris les liaisons d'authentification passthrough. #1251

🐛 Corrections de bugs

  • Streaming et renforcement des connexions obsolètes — Les flux de commandes SSE de longue durée n'utilisent plus le délai d'expiration total normal des requêtes, donc la sortie des commandes n'est pas coupée par RequestTimeout. Les demandes idempotentes GET / HEAD doivent réessayer une fois sur une nouvelle connexion après un délai d'attente, une réinitialisation ou des erreurs EOF. #1316

📦 Divers

  • Suppression de la constante de la version Go SDK et de la chaîne User-Agent par défaut pour cette version. #1384

OpenSandbox sdks/sandbox/go/v1.0.5

Highlights

  • Retrying pool acquire policies (#1347) — Acquire can now skip stale idle candidates via AcquirePolicyRetryNextIdle and AcquirePolicyRetryNextIdleThenCreate, with MaxAcquireRetries defaulting to 3. Because existing policies keep their current behavior, this is opt-in: adopt it if your pool sees stale/closed idle connections, but know that the "then create" variant can mask a systematically broken idle population by silently falling back to direct creation — worth pairing with your own create-failure alerting.
  • Streaming and stale-connection hardening (#1316) — Long-lived SSE command streams are no longer bounded by the global RequestTimeout, so command output won't be truncated mid-stream on slow jobs. Idempotent GET/HEAD calls now retry exactly once on a fresh connection after timeout/reset/EOF. The practical upside is fewer spurious failures on flaky links; watch out that the retry is deliberately limited to idempotent methods, so non-idempotent calls still fail fast rather than risking duplicate side effects.
  • Isolated session lifecycle and UID modes (#1295, #1320, #1264, #1269) — You can now attach to an isolated session by ID, letting stateless workers recover a usable handle as long as the execd in-memory session is alive — a big deal for worker restarts, but note it only works while that in-memory session persists. Sessions also gain explicit bind mounts and a listing API for inspection, and mode responses expose per-mode setpriv/userns availability: unavailable requested modes now fail with 503 NOT_SUPPORTED, so callers should probe availability and handle that status instead of assuming a UID mode is always present.
  • Observability and client identity (#1307, #1326) — Sandbox.Create emits fire-and-forget sandbox.create latency events to the lifecycle server, tolerating old-server version skew; opt out with OPENSANDBOX_DISABLE_METRICS=1 if telemetry egress is a concern. Separately, the SDK best-effort detects the host intranet IPv4 and adds OPEN-SANDBOX-CLIENT-IP to outbound requests — user-supplied values are never overwritten, so proxies or gateways relying on that header should set it explicitly to avoid ambiguity.
  • Request matching and snapshot filtering (#1251, #1301) — Credential Vault request matching gains opt-in placeholders across path, query, header, and body surfaces, including passthrough auth bindings, which makes dynamic credential injection far more flexible but warrants careful scoping so placeholder patterns don't over-match. Snapshot listing also accepts an exact name filter, replacing brittle client-side filtering for precise lookups.

No breaking changes in this release.

What's New

✨ Features

  • Retrying pool acquire policies — Go sandbox pools now support AcquirePolicyRetryNextIdle and AcquirePolicyRetryNextIdleThenCreate, allowing Acquire to skip stale idle candidates before failing or falling back to direct create. Existing policies keep their current behavior; MaxAcquireRetries defaults to 3. #1347
  • Sandbox create metrics — Sandbox.Create now reports fire-and-forget sandbox.create latency events to the lifecycle server. Reporting ignores old-server version skew and can be disabled with OPENSANDBOX_DISABLE_METRICS=1. #1307
  • Client IP header — the SDK now best-effort detects the host intranet IPv4 and sends it as OPEN-SANDBOX-CLIENT-IP on outbound requests. User-provided headers are never overwritten. #1326
  • Attach to isolated sessions — the SDK can now attach to an existing isolated session by session ID, allowing stateless workers to recover a functional handle while the execd in-memory session remains alive. #1295
  • UID mode availability — isolated session responses now expose per-mode setpriv / userns availability, and unavailable requested modes fail with 503 NOT_SUPPORTED. #1320
  • Exact snapshot name filtering — snapshot listing now supports an exact name filter. #1301
  • Isolated session bind mounts and listing — isolated sessions can now receive explicit bind mounts, and the SDK exposes isolated session listing so callers can inspect active sessions. #1264 #1269
  • Credential Vault placeholder substitutions — request matching now supports opt-in placeholders for path, query, header, and body surfaces, including passthrough auth bindings. #1251

🐛 Bug Fixes

  • Streaming and stale connection hardening — long-lived SSE command streams no longer use the normal total request timeout, so command output is not cut off by RequestTimeout. Idempotent GET / HEAD requests retry once on a fresh connection after timeout, reset, or EOF errors. #1316

📦 Misc

  • Bumped the Go SDK version constant and default User-Agent string for this release. #1384
