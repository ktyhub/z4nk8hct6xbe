coffre-fort v1.21.1

##1.21.1

20 novembre 2025

SÉCURITÉ :

  • auth/aws : correction d'un problème où un utilisateur peut contourner l'authentification auprès de Vault en raison d'une mise en cache incorrecte d'AWS client
  • ui : désactiver l'analyse des écharpes pour les versions d'interface utilisateur CHANGEMENTS :
  • auth/kubernetes : mettre à jour le plugin vers v0.23.1
  • auth/saml : mettre à jour le plugin vers v0.7.0
  • auth/saml : mise à jour du plugin vers v0.7.1, qui ajoute la variable d'environnement VAULT_SAML_DENY_INTERNAL_URLS pour permettre d'empêcher les champs idp_metadata_url, idp_sso_url ou acs_urls de contenir des URL résolues en adresses IP internes.
  • noyau : version Bump Go vers 1.25.4
  • secrets/azure : Mettre à jour le plugin vers v0.25.0+ent
  • secrets/pki : les points de terminaison de signature textuelle n'ignorent plus l'extension des contraintes de base dans les CSR, en les utilisant dans les certificats générés si isCA=false ou en renvoyant une erreur si isCA=true AMÉLIORATIONS :
  • Mettez à jour github.com/dvsekhvalnov/jose2go pour corriger la vulnérabilité de sécurité CVE-2025-63811.
  • api : ajout d'un point de terminaison sys/reporting/scan avec autorisation sudo qui générera un ensemble de fichiers contenant des informations sur l'état de Vault à l'emplacement spécifié par l'élément de configuration reporting_scan_directory.
  • auth/ldap : exiger des mots de passe non vides lors de la commande de connexion pour empêcher l'accès non authentifié à Vault.
  • core/metrics : la lecture et le listing à partir d'un instantané sont désormais suivis via les métriques vault.route.read-snapshot.{mount_point} et vault.route.list-snapshot.{mount_point}.
  • Rapports d'utilisation des licences (entreprise) : ajoutez des mesures pour le nombre de certificats PKI émis.
  • politiques : ajout d'un avertissement concernant la comparaison de listes lors de l'utilisation de Allowed_parameters ou de Nied_parameters
  • secret-sync : ajoute la prise en charge de la parallélisation aux opérations de synchronisation et de désynchronisation pour les associations de granularité de clé secrète
  • secrets/pki : incluez l'AuthorityKeyID du certificat dans les champs de réponse pour les points de terminaison API qui émettent, signent ou récupèrent des certificats.
  • sys (entreprise) : ajoutez le point de terminaison sys/billing/certificates API pour récupérer le nombre de certificats PKI émis.
  • ui/activity (entreprise) : ajoutez un texte de clarification pour expliquer que la colonne "Utilisation initiale" n'aura que des horodatages pour les clients initialement utilisés après la mise à niveau vers la version 1.21
  • ui/activity (entreprise) : autorise l'interrogation manuelle de l'utilisation de client en cas de problème lors de la récupération de l'heure de début de la licence.
  • ui/activité (entreprise) : réduisez les demandes d'exportation d'activité API en récupérant de nouvelles données uniquement lors du chargement initial du tableau de bord ou lors de son actualisation manuelle.
  • ui/activité (entreprise) : prise en charge du filtrage des mois par horodatage ISO ou valeur d'affichage.
  • ui/activity : affiche le total au lieu des nouveaux clients mensuels pour les clusters gérés par HCP
  • ui/pki : ajoute la prise en charge de la configuration des paramètres server_flag, client_flag, code_signing_flag et email_protection_flag pour la création/mise à jour d'un rôle. CORRECTIONS DE BOGUES :
  • activité (entreprise) : sys/internal/counters/activity génère le type de montage correct lorsqu'il est appelé depuis un espace de noms non root
  • auth/approle (entreprise) : le paramètre de rôle alias_metadata remplit désormais le champ de métadonnées personnalisées d'alias au lieu des métadonnées d'alias.
  • auth/aws (entreprise) : le paramètre de rôle alias_metadata remplit désormais le champ de métadonnées personnalisées d'alias au lieu des métadonnées d'alias.
  • auth/cert (entreprise) : le paramètre de rôle alias_metadata remplit désormais le champ de métadonnées personnalisées d'alias au lieu des métadonnées d'alias.
  • auth/github (entreprise) : le paramètre de rôle alias_metadata remplit désormais le champ de métadonnées personnalisées d'alias au lieu des métadonnées d'alias.
  • auth/ldap (entreprise) : le paramètre de rôle alias_metadata remplit désormais le champ de métadonnées personnalisées d'alias au lieu des métadonnées d'alias.
  • auth/okta (entreprise) : le paramètre de rôle alias_metadata remplit désormais le champ de métadonnées personnalisées d'alias au lieu des métadonnées d'alias.
  • auth/radius (entreprise) : le paramètre de rôle alias_metadata remplit désormais le champ de métadonnées personnalisées d'alias au lieu des métadonnées d'alias.
  • auth/scep (entreprise) : le paramètre de rôle alias_metadata remplit désormais le champ de métadonnées personnalisées d'alias au lieu des métadonnées d'alias.
  • auth/userpass (entreprise) : le paramètre de rôle alias_metadata remplit désormais le champ de métadonnées personnalisées d'alias au lieu des métadonnées d'alias.
  • auth : correction de la panique lors de la fourniture d'un entier comme lease_id lors du renouvellement.
  • core/rotation : évitez de changer de fuseau horaire en ignorant cron.SpecSchedule
  • core : interprète tous les nouveaux rotation_schedules du gestionnaire de rotation au format UTC pour éviter une utilisation accidentelle de tz-local
  • secrets/azure : assurez-vous de l'installation correcte du plug-in Azure Enterprise Secrets.
  • secrets/pki : renvoie une erreur lors de l'émission/signature de certificats dont NotAfter est antérieur à NotBefore ou dont la période de validité n'est pas contenue par les CA.
  • ui (entreprise) : Correction de KV v2 n'affichant pas les secrets dans les espaces de noms.
  • ui (entreprise) : corrige le formulaire de connexion afin que l'entrée s'affiche correctement lorsque le jeton est une méthode de connexion préférée pour un espace de noms.
  • ui/pki : corrige l'analyse des certificats de l'extension key_usage afin que les détails reflètent avec précision les valeurs du certificat.
  • ui/pki : corrige la création et la mise à jour d'un rôle afin que basic_constraints_valid_for_non_ca soit correctement défini.
  • ui : correction de l'échec de la demande de liste de métadonnées KV v2 pour les stratégies sans barre oblique finale dans le chemin.
  • ui : résolution d'une régression qui empêchait les utilisateurs disposant d'autorisations de création et de mise à jour sur les secrets KV v1 d'ouvrir la vue d'édition. L'interface utilisateur reconnaît désormais correctement ces fonctionnalités et permet l'édition sans nécessiter un accès complet en lecture.
  • ui : mettre à jour le tableau d'archivage des comptes LDAP pour afficher les bibliothèques LDAP hiérarchiques
  • ui : mettre à jour le nombre de bibliothèques LDAP pour refléter le nombre total de nœuds au lieu du nombre de répertoires

vault v1.21.1

1.21.1

November 20, 2025

SECURITY:

  • auth/aws: fix an issue where a user may be able to bypass authentication to Vault due to incorrect caching of the AWS client
  • ui: disable scarf analytics for ui builds

CHANGES:

  • auth/kubernetes: Update plugin to v0.23.1
  • auth/saml: Update plugin to v0.7.0
  • auth/saml: Update plugin to v0.7.1, which adds the environment variable VAULT_SAML_DENY_INTERNAL_URLS to allow prevention of idp_metadata_url, idp_sso_url, or acs_urls fields from containing URLs that resolve to internal IP addresses
  • core: Bump Go version to 1.25.4
  • secrets/azure: Update plugin to v0.25.0+ent
  • secrets/pki: sign-verbatim endpoints no longer ignore basic constraints extension in CSRs, using them in generated certificates if isCA=false or returning an error if isCA=true

IMPROVEMENTS:

  • Update github.com/dvsekhvalnov/jose2go to fix security vulnerability CVE-2025-63811.
  • api: Added sudo-permissioned sys/reporting/scan endpoint which will output a set of files containing information about Vault state to the location specified by the reporting_scan_directory config item.
  • auth/ldap: Require non-empty passwords on login command to prevent unauthenticated access to Vault.
  • core/metrics: Reading and listing from a snapshot are now tracked via the vault.route.read-snapshot.{mount_point} and vault.route.list-snapshot.{mount_point} metrics.
  • license utilization reporting (enterprise): Add metrics for the number of issued PKI certificates.
  • policies: add warning about list comparison when using allowed_parameters or denied_parameters
  • secret-sync: add parallelization support to sync and unsync operations for secret-key granularity associations
  • secrets/pki: Include the certificate's AuthorityKeyID in response fields for API endpoints that issue, sign, or fetch certs.
  • sys (enterprise): Add sys/billing/certificates API endpoint to retrieve the number of issued PKI certificates.
  • ui/activity (enterprise): Add clarifying text to explain the "Initial Usage" column will only have timestamps for clients initially used after upgrading to version 1.21
  • ui/activity (enterprise): Allow manual querying of client usage if there is a problem retrieving the license start time.
  • ui/activity (enterprise): Reduce requests to the activity export API by only fetching new data when the dashboard initially loads or is manually refreshed.
  • ui/activity (enterprise): Support filtering months dropdown by ISO timestamp or display value.
  • ui/activity: Display total instead of new monthly clients for HCP managed clusters
  • ui/pki: Adds support to configure server_flag, client_flag, code_signing_flag, and email_protection_flag parameters for creating/updating a role.

BUG FIXES:

  • activity (enterprise): sys/internal/counters/activity outputs the correct mount type when called from a non root namespace
  • auth/approle (enterprise): Role parameter alias_metadata now populates alias custom metadata field instead of alias metadata.
  • auth/aws (enterprise): Role parameter alias_metadata now populates alias custom metadata field instead of alias metadata.
  • auth/cert (enterprise): Role parameter alias_metadata now populates alias custom metadata field instead of alias metadata.
  • auth/github (enterprise): Role parameter alias_metadata now populates alias custom metadata field instead of alias metadata.
  • auth/ldap (enterprise): Role parameter alias_metadata now populates alias custom metadata field instead of alias metadata.
  • auth/okta (enterprise): Role parameter alias_metadata now populates alias custom metadata field instead of alias metadata.
  • auth/radius (enterprise): Role parameter alias_metadata now populates alias custom metadata field instead of alias metadata.
  • auth/scep (enterprise): Role parameter alias_metadata now populates alias custom metadata field instead of alias metadata.
  • auth/userpass (enterprise): Role parameter alias_metadata now populates alias custom metadata field instead of alias metadata.
  • auth: fixed panic when supplying integer as a lease_id in renewal.
  • core/rotation: avoid shifting timezones by ignoring cron.SpecSchedule
  • core: interpret all new rotation manager rotation_schedules as UTC to avoid inadvertent use of tz-local
  • secrets/azure: Ensure proper installation of the Azure enterprise secrets plugin.
  • secrets/pki: Return error when issuing/signing certs whose NotAfter is before NotBefore or whose validity period isn't contained by the CA's.
  • ui (enterprise): Fix KV v2 not displaying secrets in namespaces.
  • ui (enterprise): Fixes login form so input renders correctly when token is a preferred login method for a namespace.
  • ui/pki: Fixes certificate parsing of the key_usage extension so details accurately reflect certificate values.
  • ui/pki: Fixes creating and updating a role so basic_constraints_valid_for_non_ca is correctly set.
  • ui: Fix KV v2 metadata list request failing for policies without a trailing slash in the path.
  • ui: Resolved a regression that prevented users with create and update permissions on KV v1 secrets from opening the edit view. The UI now correctly recognizes these capabilities and allows editing without requiring full read access.
  • ui: Update LDAP accounts checked-in table to display hierarchical LDAP libraries
  • ui: Update LDAP library count to reflect the total number of nodes instead of number of directories
