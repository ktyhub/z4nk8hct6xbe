coffre-fort v2.1.0

##2.1.0

01 septembre 2026

SÉCURITÉ :

  • core : mettez à jour go.etcd.io/etcd/client/pkg/v3 vers v3.7.1 pour corriger la vulnérabilité de sécurité GO-2026-6107.
  • noyau : mettez à jour software.sslmate.com/src/go-pkcs12 vers v0.7.2 pour corriger la vulnérabilité de sécurité GO-2026-5052. CHANGEMENTS :
  • Licence : ajoutez les conditions Agentic IAM au modèle de licence client et mettez à jour les conditions pour le modèle de licence Vault Platform.
  • noyau : version Bump Go vers 1.26.7.
  • oauth-resource-server (entreprise) : empêche la mutation de issuer_id après la création du profil OAuth Resource Server. Les opérateurs doivent supprimer et recréer des profils pour modifier l'issuer_id.
  • oauth-resource-server (entreprise) : empêche la mutation de unique_id_claim après la création du profil du serveur de ressources OAuth. Les opérateurs doivent supprimer et recréer des profils pour modifier le unique_id_claim.
  • oauth-resource-server (entreprise) : la fonctionnalité OAuth Resource Server ne nécessite plus d'activation via le point de terminaison sys/activation-flags/oauth-resource-server/activate.
  • oauth-resource-server (entreprise) : mettez à jour la configuration du serveur de ressources OAuth pour inclure des options de revendication personnalisées pour l'identifiant et l'acteur uniques du jeton.
  • secrets/openldap (entreprise) : mettre à jour le plugin vers v0.18.4+ent CARACTÉRISTIQUES :
  • Interface utilisateur Agent Registry (entreprise) : ajoute une nouvelle section Sécurité agent à la navigation principale avec une page Registre d'agent où les opérateurs peuvent afficher, rechercher et gérer les agents IA enregistrés, leurs entités et alias Vault associés, les politiques attribuées et leur état opérationnel.
  • Réalisation automatique des défis DNS-01 pour l'autorité de certification externe PKI : intégrez les fournisseurs DNS suivants pour la réalisation automatique des défis DNS-01 : AWS Route53, Azure DNS, Google Cloud DNS et BIND et autres serveurs conformes à la RFC2136.
  • Prise en charge PKI PKCS#12 et JKS : ajoute la prise en charge des ensembles de certificats PKCS#12 (PFX) et Java keytool (JKS) aux points de terminaison PKI pertinents. Les bundles sont renvoyés sous forme de fichiers codés en base64 et protégés par mot de passe.
  • Prise en charge SLH-DSA pour la signature/vérification hybride dans le moteur Transit (entreprise) : ajout de la prise en charge de SLH-DSA en tant que composant PQC pour les opérations de signature/vérification hybride. Ceci est compatible avec ECDSA (p-256, P-384, P-521) et Ed25519.
  • secrets/pki-external-ca (entreprise) : ajout de la prise en charge de la gestion des défis DNS-01 pour les DNS Azure, AWS, GCP et rfc2136. AMÉLIORATIONS :
  • agent-registry (entreprise) : suppression de la restriction qui interdisait l'utilisation de « refuser » dans les politiques de plafond, ce qui entraînait des erreurs de demande.
  • agent/pkiexternalca : remplacez go.uber.org/atomic par sync/atomic (stdlib) pour les opérations booléennes atomiques dans le package pkiexternalca.
  • auth/token : ajoutez une liste de refus globale pour révoquer les JWT OAuth afin d'empêcher l'autorisation de jetons spécifiques dans tous les espaces de noms.
  • core/seal (entreprise) : mettez à jour la bibliothèque Oracle Cloud pour permettre l'intégration du sceau avec les régions les plus récentes.
  • ui : faites passer dompurify de 3.4.6 à 3.4.13.
  • ui : Bump shell-quote de 1.8.4 à 1.9.0.
  • ui : exposition du champ RSA Private Key dans l'interface utilisateur lors de la génération des informations d'identification avec le moteur de secrets de base de données Snowflake. Auparavant, ce champ n'était affiché que dans le cli.
  • ui : le modal de confirmation de suppression du moteur de secrets nécessite désormais de taper delete-engine pour confirmer, affiche le nom du moteur, le nombre de secrets (moteurs KV uniquement) et une liste de ce qui sera définitivement supprimé. ConfirmModal a maintenant été mis à jour pour inclure un type facultatif de confirmation. CORRECTIONS DE BOGUES :
  • agent/pki-external-ca : correction de l'extraction de la chaîne CA à partir des réponses Vault PKI API où le champ ca_chain était toujours vide dans les modèles en raison d'une gestion incorrecte du type des réponses du tableau
  • api : tenez compte de l'en-tête HTTP Age lors du calcul de la durée de vie restante d'un bail, afin que les baux lus ou renouvelés via un proxy de mise en cache tel que Vault Agent soient renouvelés avant leur expiration.
  • core (entreprise) : correction d'une course aux données et d'une panique potentielle lors du scellement/descellement
  • core (entreprise) : correction de la panique dans collectOperatorImportMetrics lorsque router.Route renvoie une réponse nulle sans erreur lors des lectures de métadonnées KVv2 sur les nœuds secondaires de performances. Cette condition se produit pendant la phase de synchronisation partielle du flux WAL d'une jointure initiale.
  • core/login : Correction de la panique sur les demandes de connexion mal formées. Vault renvoie désormais une erreur pour les charges utiles de connexion mal formées au lieu de supprimer la connexion client (aucune perte de données).
  • core/metrics : Correction d'un bug où log_format = "json" n'avait aucun effet sur les erreurs de récepteur de télémétrie des backends statsd et statsite.
  • core/wrapping : sys/wrapping/wrap applique désormais les jetons d'encapsulation au format uuid, ignorant tout format d'encapsulation demandé par l'appelant.
  • core : correction de la commande vault operator migrate -start lors de la migration vers le stockage intégré au radeau.
  • core : Vault kv put/get fonctionne désormais avec les jetons OAuth externes.
  • cubbyhole : correction des écritures cubbyhole pour les jetons JWT dans les espaces de noms non root
  • default-auth : correction d'un problème avec les anciennes configurations d'authentification par défaut qui se briseraient lors de la mise à niveau vers une version plus récente de Vault.
  • Identité : correction de l'échec de la création d'un alias d'entité avec "l'espace de noms de l'accesseur de montage ne correspond pas à l'espace de noms de la demande" lors de l'utilisation d'un accesseur de montage synthétique dans un contexte d'espace de noms
  • oauth-resource-server (entreprise) : correction du problème où optional_authorization_details était incorrectement ignoré pour les flux de travail délégués (OBO) lorsque le sujet n'avait pas d'enregistrement d'agent, ce qui faisait que RAR n'était pas obligatoire dans ces demandes.
  • plugins : lire un plugin versionné uniquement sans spécifier -version le sélectionne désormais automatiquement lorsqu'une seule version existe, ou renvoie une erreur répertoriant les versions disponibles, au lieu d'un 404 silencieux.
  • proxy/cache (entreprise) : correction d'un bug dans le cache secret statique où les requêtes GET avec ?list=true étaient incorrectement mises en cache et servies obsolètes.
  • sdk/rotation : Les appels ultérieurs ne permettront plus de paramétrer simultanément les champs rotation_period et rotation_schedule. Le SDK vide désormais explicitement le champ adverse pour garantir l'exclusion mutuelle.
  • secret/pki : correction de la commande ACME pour finaliser la condition de concurrence dans laquelle des demandes simultanées pourraient émettre des certificats en double et en rendre un orphelin à cause du suivi par clé de commande
  • secret/pki : empêche key rename d'accepter un nom déjà détenu par une clé différente.
  • secrets/base de données : désinfectez le DisplayName contrôlé par l'appelant avant qu'il ne soit utilisé dans les noms d'utilisateur générés pour empêcher l'injection SQL via des modèles de nom d'utilisateur. Ajoute un avertissement de configuration lorsqu'un username_template fait référence à DisplayName sans fonction de troncature.
  • secrets/ldap : la rotation manuelle d'un mot de passe de rôle statique redémarrera à nouveau le TTL de rotation, correspondant au comportement antérieur à v2.0.0
  • secrets/nomad : corrigez l'épuisement des connexions en cas de concurrence élevée en introduisant un client HTTP partagé et groupé avec un plafond de connexion par hôte. Auparavant, une nouvelle connexion TCP était ouverte pour chaque demande d'informations d'identification, ce qui faisait que Nomad renvoyait des erreurs HTTP 429 « trop de connexions simultanées » lorsque plus de 100 baux étaient générés simultanément.
  • serviceregistration/consul : correction d'un problème où Vault se désenregistrait définitivement du catalogue de services Consul lorsqu'un signal SIGHUP/reload était envoyé et que la configuration utilisait Consul comme backend de stockage sans strophe service_registration explicite.
  • ui/secrets/pki : correction de l'échec du chargement de la page de liste des émetteurs lorsque le nombre d'émetteurs dépasse 10
  • ui : correction de l'erreur 403 sur la méthode d'authentification. Page de configuration pour les politiques qui autorisent la lecture sur sys/auth* mais pas sur sys/auth/*.
  • ui : Correction de la méthode d'authentification Kubernetes qui n'enregistrait pas token_reviewer_jwt — la mauvaise clé de schéma OpenAPI (KubernetesConfigureRequest) a été utilisée à la place de KubernetesConfigureAuthRequest, ce qui a entraîné l'omission du champ JWT du formulaire et de la charge utile API lors de la sauvegarde.
  • ui : correction de la bordure clipping sur les tables des widgets du tableau de bord en appliquant un style masqué par débordement.
  • ui : correction d'un bug de redirection ouverte dans la route du fournisseur OIDC.
  • ui : correction du menu volant du générateur de stratégie rejetant les sauvegardes lorsqu'aucune fonctionnalité n'est sélectionnée pour une règle.
  • ui : ajoutez la propriété totalItems pour corriger la pagination de la liste filtrée affichant un nombre total de pages incorrect
  • Interface utilisateur : correction de la fausse bannière "Pas d'accès" lors de la navigation vers l'interface utilisateur de Vault avec ?namespace=root dans l'URL

vault v2.1.0

2.1.0

September 01, 2026

SECURITY:

  • core: Update go.etcd.io/etcd/client/pkg/v3 to v3.7.1 to fix security vulnerability GO-2026-6107.
  • core: Update software.sslmate.com/src/go-pkcs12 to v0.7.2 to fix security vulnerability GO-2026-5052.

CHANGES:

  • License: Add Agentic IAM terms to client licensing model and update terms for Vault Platform licensing model.
  • core: Bump Go version to 1.26.7.
  • oauth-resource-server (enterprise): Prevent issuer_id from being mutated after OAuth Resource Server profile creation. Operators must delete and recreate profiles to change the issuer_id.
  • oauth-resource-server (enterprise): Prevent unique_id_claim from being mutated after OAuth Resource Server profile creation. Operators must delete and recreate profiles to change the unique_id_claim.
  • oauth-resource-server (enterprise): The OAuth Resource Server feature no longer requires activation via the sys/activation-flags/oauth-resource-server/activate endpoint.
  • oauth-resource-server (enterprise): Update OAuth Resource Server config to include custom claim options for the token's unique identifier and actor.
  • secrets/openldap (enterprise): Update plugin to v0.18.4+ent

FEATURES:

  • Agent Registry UI (enterprise): Adds a new Agentic Security section to the primary navigation with an Agent Registry page where operators can view, search, and manage registered AI agents, their associated Vault entities and aliases, assigned policies, and operational status.
  • Automatic DNS-01 Challenge Fulfillment for PKI External CA: Integrate with the following DNS providers for automatic DNS-01 challenge fulfillment: AWS Route53, Azure DNS, Google Cloud DNS, and BIND and other RFC2136-compliant servers.
  • PKI PKCS#12 and JKS Support: Adds support for PKCS#12 (PFX) and Java keytool (JKS) certificate bundles to relevant PKI endpoints. Bundles are returned as base64-encoded, password-protected files.
  • SLH-DSA support for Hybrid sign/verify in Transit engine (enterprise): Add support for SLH-DSA as the PQC component for Hybrid sign/verify operations. This is compatible with both ECDSA (p-256, P-384, P-521) and Ed25519.
  • secrets/pki-external-ca (enterprise): Add support for handling dns-01 challenges for Azure, AWS, GCP, and rfc2136 DNS.

IMPROVEMENTS:

  • agent-registry (enterprise): Removed the restriction that disallowed the use of 'deny' in ceiling policies, resulting in request errors.
  • agent/pkiexternalca: Replace go.uber.org/atomic with sync/atomic (stdlib) for atomic boolean operations in the pkiexternalca package.
  • auth/token: Add global denylist for revoking OAuth JWTs to prevent authorization of specific tokens across all namespaces.
  • core/seal (enterprise): Update Oracle Cloud library to enable seal integration with newer regions.
  • ui: Bump dompurify from 3.4.6 to 3.4.13.
  • ui: Bump shell-quote from 1.8.4 to 1.9.0.
  • ui: Exposing the RSA Private Key field in the UI when generating credentials with the snowflake database secrets engine. Previously, this field was only shown in the cli.
  • ui: Secrets engine delete confirmation modal now requires typing delete-engine to confirm, displays the engine name, secret count (KV engines only), and a list of what will be permanently deleted. ConfirmModal has now been updated to include a optional type-to-confirm.

BUG FIXES:

  • agent/pki-external-ca: Fix CA chain extraction from Vault PKI API responses where ca_chain field was always empty in templates due to incorrect type handling of array responses
  • api: Account for the HTTP Age header when calculating a lease's remaining lifetime, so that leases read or renewed through a caching proxy such as Vault Agent are renewed before they expire.
  • core (enterprise): Fix a data race and potential panic during seal/unseal
  • core (enterprise): Fix panic in collectOperatorImportMetrics when router.Route returns a nil response with no error during KVv2 metadata reads on performance secondary nodes. This condition occurs during the WAL-stream partial-sync phase of an initial join.
  • core/login: Fix panic on malformed login requests. Vault now returns an error for malformed login payloads instead of dropping the client connection (no data loss).
  • core/metrics: Fixed a bug where log_format = "json" had no effect on telemetry sink errors from statsd and statsite backends.
  • core/wrapping: sys/wrapping/wrap now enforces uuid-format wrapping tokens, ignoring any caller-requested wrap format.
  • core: Fix vault operator migrate -start command when migrating to raft integrated storage.
  • core: vault kv put/get now works with external OAuth tokens.
  • cubbyhole: Fix cubbyhole writes for JWT tokens in non-root namespaces
  • default-auth: Fix issue with legacy default-auth configs that would break as part of upgrading to a newer version of Vault.
  • identity: Fixed entity alias creation failing with "mount accessor namespace does not match request namespace" when using a synthetic mount accessor in a namespaced context
  • oauth-resource-server (enterprise): Fix issue where optional_authorization_details was incorrectly ignored for delegated (OBO) workflows when the subject has no agent registration, resulting in RAR not being mandatory in those requests.
  • plugins: Reading a versioned-only plugin without specifying -version now auto-selects it when only one version exists, or returns an error listing available versions, instead of a silent 404.
  • proxy/cache (enterprise): Fixed a bug in the static secret cache where GET requests with ?list=true were incorrectly cached and served stale.
  • sdk/rotation: Subsequent calls will no longer allow both the rotation_period and rotation_schedule fields to be set simultaneously. The SDK now explicitly empties the opposing field to guarantee mutual-exclusion.
  • secret/pki: Fix ACME order finalize race condition where concurrent requests could double-issue certificates and orphan one from order-keyed tracking
  • secret/pki: prevent key rename from accepting a name already held by a different key.
  • secrets/database: Sanitize the caller-controlled DisplayName before it is used in generated usernames to prevent SQL injection via username templates. Adds a configuration warning when a username_template references DisplayName without a truncate function.
  • secrets/ldap: manually rotating a static role password will restart the rotation TTL once again, matching the behavior prior to v2.0.0
  • secrets/nomad: Fix connection exhaustion under high concurrency by introducing a shared, pooled HTTP client with a per-host connection cap. Previously, a new TCP connection was opened for every credential request, causing Nomad to return HTTP 429 "too many concurrent connections" errors when more than 100 leases were generated simultaneously.
  • serviceregistration/consul: Fixed an issue where Vault would permanently deregister itself from the Consul service catalog when a SIGHUP/reload signal was sent and the configuration used Consul as the storage backend without an explicit service_registration stanza.
  • ui/secrets/pki: Fix issuers list page failing to load when issuer count exceeds 10
  • ui: Fix 403 error on auth method Configure page for policies that grant read on sys/auth* but not sys/auth/*.
  • ui: Fix Kubernetes auth method not saving token_reviewer_jwt — the wrong OpenAPI schema key (KubernetesConfigureRequest) was used instead of KubernetesConfigureAuthRequest, causing the JWT field to be omitted from the form and API payload on save.
  • ui: Fix border clipping on dashboard widget tables by applying overflow-hidden styling.
  • ui: Fix open redirect bug in OIDC provider route.
  • ui: Fix policy generator flyout rejecting saves when no capabilities are selected for a rule.
  • ui: add totalItems property to fix filtered list pagination showing incorrect total page count
  • ui: fix spurious "No access" banner when navigating to Vault UI with ?namespace=root in the URL
