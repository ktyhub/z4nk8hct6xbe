coffre-fort v2.0.4

##2.0.4

04 août 2026

CHANGEMENTS DE RUPTURE :

  • conteneurs : les packages suivants ont été supprimés du conteneur basé sur UBI images : gnupg, openssl, procps. SÉCURITÉ :
  • acl : correction d'une vulnérabilité d'élévation de privilèges où une contrainte denied_parameters sur le champ de requête policies pouvait être contournée en soumettant un nom de politique en casse mixte (par exemple "Super-Admin" au lieu de "super-admin"). Vault normalise désormais le paramètre policies en minuscules avant d'évaluer les contraintes allowed_parameters/denied_parameters.
  • identité/scim (entreprise) : le point de terminaison identity/entity/merge rejette désormais les demandes impliquant toute entité gérée par SCIM, empêchant les opérateurs privilégiés de contourner les garde-fous de propriété SCIM pour transférer des alias, des appartenances à des groupes ou des politiques au-delà des limites SCIM.
  • identité : empêche le point de terminaison de suppression par lots de l'entité (identité/entité/suppression par lots) de supprimer le stockage sous-jacent des entités qui appartiennent à un autre espace de noms.
  • Identité : les mises à jour d'entité/nom rejettent désormais les sélecteurs d'identifiant ou d'identifiant externe incompatibles pour empêcher le reciblage des mises à jour vers une autre entité. CHANGEMENTS :
  • auth/oci : mettre à jour le plugin vers v0.21.3
  • noyau : version Bump Go vers 1.26.5.
  • core : supprime la prise en charge des attributs en double dans les fichiers de configuration HCL et les définitions de stratégie. Analyser HCL avec les attributs en double échouent désormais toujours et l'environnement VAULT_ALLOW_PENDING_REMOVAL_DUPLICATE_HCL_ATTRIBUTES La variable qui restaurait précédemment le comportement hérité a été supprimée. CARACTÉRISTIQUES :
  • secrets : ajout de la possibilité d'afficher les secrets au format YAML AMÉLIORATIONS :
  • auth/cert : prise en charge de la connexion via les en-têtes de certificat x-forwarded même avec tls désactivé sur l'écouteur du coffre-fort.
  • core (entreprise) : ajoutez un point de terminaison à sys/config/oauth-resource-server/id/:config_id pour lire les profils de serveur de ressources oauth par config_id
  • core (entreprise) : rendre la validation JWT typ du serveur de ressources OAuth plus permissive pour les jetons provenant d'IdP tels qu'Okta en autorisant un en-tête typ manquant, tout en limitant les valeurs typ actuelles à at+jwt, application/at+jwt et JWT.
  • core (entreprise) : conflit de verrouillage Ameriolate sealwrap pour les chemins principaux.
  • core/acl : ajoute une option de configuration globale deny_slash_in_templated_path pour rejeter la présence de barres obliques dans les modèles d'identité rendus dans les stratégies, par défaut false.
  • core/identity : ajoute une option de configuration globale deny_slash_in_templated_path pour rejeter la présence de barres obliques dans les modèles d'identité rendus dans les stratégies, par défaut false.
  • core/managed-keys/PKCS#11 (entreprise) : fournir une valeur non vide pour un champ alors que l'autre est déjà enregistré est rejeté. Pour changer de mode d'adressage, vous devez explicitement effacer l'ancien champ en l'envoyant sous forme de chaîne vide ("") dans la même requête avec la nouvelle valeur.
  • core/managed-keys/PKCS#11 (entreprise) : slot et token_label sont désormais strictement appliqués en tant qu'identifiants mutuellement exclusifs pour un jeton HSM
  • événements : ajoutez la variable d'environnement VAULT_EVENT_NOTIFICATIONS_BOUNDED_QUEUE_SIZE pour configurer des files d'attente d'événements limitées pour les abonnés aux notifications d'événements. Définissez sur un nombre entier positif (par exemple, 16) pour activer les canaux mis en mémoire tampon de cette taille (maximum 1 000). Cela évite l'épuisement des ressources dans les déploiements avec un nombre élevé d'abonnés, mais cela se fait au détriment du risque que les abonnés manquent des événements. La valeur par défaut est 0 (sans tampon) pour une compatibilité ascendante.
  • identité/scim (entreprise) : ajout de la prise en charge du filtrage aux points de terminaison GET /scim/v2/Users et GET /scim/v2/Groups selon RFC 7644. Filtres pris en charge : userName eq, externalId eq, active eq et meta.lastModified gt/ge/lt/le pour les utilisateurs ; displayName eq et meta.lastModified gt/ge/lt/le pour les groupes. Les expressions de filtre non prises en charge renvoient HTTP 400. ServiceProviderConfig annonce désormais filter.supported: true.
  • identité/scim (entreprise) : améliorez les performances des points de terminaison de liste d'utilisateurs et de groupes SCIM en utilisant le tri par préfixe au lieu d'une passe de tri distincte.
  • Identité : Inclut le statut de l'entité et les détails de l'horodatage de l'entité/alias dans les réponses key_info de la liste d'entités.
  • oauth-resource-server : ajout de la prise en charge d'options de contrôle de politique précises (contraintes de paramètres) dans les demandes d'autorisation enrichies (RAR), notamment allowed_parameters, denied_parameters et required_parameters dans authorization_details.
  • oauth-resource-server : ajout de la prise en charge des expressions de modèle d'identité (par exemple {{identity.entity.id}}) dans les demandes d'autorisation enrichies (RAR).
  • scim : les ressources utilisateur incluent désormais un champ groups en lecture seule répertoriant les adhésions directes aux groupes gérées par le SCIM client demandeur, conformément à la RFC 7643.
  • secrets/kv (entreprise) : prise en charge de la lecture et de la récupération des secrets KVv2 à partir d'un instantané chargé, y compris la récupération sur place et la copie à partir du chemin dans le même montage et le même espace de noms.
  • ui : ajoutez une option d'affichage YAML en lecture seule à la page de détails secrets de KV v2, aux côtés des vues existantes de l'interface utilisateur et du JSON.
  • ui : Bump pnpm.overrides entrée pour tmp de 0.2.6 à 0.2.7.
  • ui : Bump pnpm.overrides entrée pour ws de 8.20.1 à 8.21.0. CORRECTIONS DE BOGUES :
  • Proxy/Agent : Correction d'un bug où les en-têtes de méthode d'authentification s'accumulaient sur le API client partagé au cours des cycles de réauthentification.
  • Proxy : correction d'un bug où l'en-tête du jeton Vault accumulait des valeurs en double lors des reconnexions WebSocket dans le programme de mise à jour du cache secret statique.
  • Récupération de secrets (entreprise) : ne redirigez pas vers le nœud actif pour les demandes de liste vers sys/storage/raft/snapshot-load ou les demandes de lecture/suppression vers sys/storage/raft/snapshot-load/{id}. Si possible, traitez ces requêtes sur le serveur de veille de performances, sinon transférez les requêtes au nœud actif.
  • audit : correction d'une régression de CVE-2025-6000 qui empêchait l'activation des périphériques d'audit sous Windows lorsqu'un répertoire de plugin était configuré.
  • audit : rendre la sérialisation du récepteur d'audit des fichiers et des sockets sensible au contexte afin que les requêtes annulées ou expirées cessent d'attendre derrière les écritures d'audit bloquées, réduisant ainsi l'accumulation de goroutines, de mémoire, de connexions et de descripteurs de fichiers pendant les conflits de récepteur d'audit
  • auth/cert : ajoute la prise en charge des en-têtes de certificat x-forwarded provenant des AWS ALB.
  • auth/spiffe (entreprise) : utilisez la chaîne complète de certificats homologues lors de la vérification des certificats.
  • aws/auth : supprimez les valeurs de métadonnées de l'instance EC2 à partir des messages d'erreur d'authentification AWS.
  • facturation de la consommation : correction d'un bug où les unités de facturation des certificats PKI, SSH et SSH OTP des nœuds de veille de performance n'étaient pas transmises aux nœuds actifs pour le stockage, entraînant la perte des événements de facturation sur les nœuds de veille.
  • facturation de la consommation : correction d'un bug où les unités de facturation de jetons SPIFFE JWT des nœuds de veille de performance n'étaient pas transmises aux nœuds actifs pour le stockage, entraînant la perte des événements de facturation sur les nœuds de veille.
  • facturation de la consommation : correction d'un bug où le nombre de certificats SSH ajustés en fonction de la durée et le nombre d'OTP dont la représentation décimale commençait par « 4 » ne pouvaient pas être relus à partir du stockage, ce qui faisait que sys/billing/overview renvoyait une erreur 500 avec « lz4 : mauvais nombre magique ». Le codage du stockage utilise désormais des chaînes décimales simples cohérentes avec d'autres mesures de facturation, évitant ainsi une identification erronée en tant que données compressées en lz4.
  • facturation de la consommation : correction d'un bug où les comptes de durée des jetons OIDC des nœuds de veille de performance n'étaient pas transmis aux nœuds actifs pour le stockage, entraînant la perte des événements de facturation sur les nœuds de veille.
  • facturation à la consommation : correction des blocages dans les chemins de facturation KMIP et d'analyse de montage en évitant l'acquisition de verrous imbriqués lors de l'énumération des montages et des plugins.
  • facturation de la consommation : corrige le comptage de rôles dynamique et statique LDAP et OpenLDAP dans la facturation des cas d'utilisation d'utiliser des points de terminaison de comptage dédiés (role-count, static-role-count) au lieu du comptage basé sur LIST, ce qui sous-estimait les rôles.
  • core (entreprise) : correction d'un bug qui entraînait un réemballage inutile des sceaux.
  • core (entreprise) : préserve les métadonnées d'encapsulation lorsque le groupe de contrôle déballe réexécute une demande approuvée qui renvoie une réponse encapsulée.
  • core (entreprise) : mise à jour de la vérification de l'état du jeton cohérent côté serveur (SSCT) lorsqu'il est utilisé sur des clusters secondaires de performances. Les codes de réponse 403 seront préférés aux codes 412 pour les demandes de jetons inter-clusters non valides adressées aux nœuds actifs secondaires.
  • Clés principales/gérées (entreprise) : autorisez les numéros d'emplacement supérieurs à 32 bits dans les clés gérées PKCS#11.
  • core/seal : correction d'une fuite de goroutine se produisant lorsque les fonctions de cryptage et de décryptage expirent.
  • core : préserve les paramètres de requête d'URL lors de la redirection des requêtes API contenant des barres obliques en double vers leur chemin canonique. Auparavant, la redirection supprimait des paramètres tels que ?list=true, modifiant potentiellement le résultat de la requête.
  • événements (entreprise) : correction d'un bug où les événements cessaient d'être transmis aux secondaires de performances après le redémarrage du nœud actif ou un événement de changement (scellement/descellement, etc.).
  • export API : normalisez le paramètre end_time dans l'export d'activité API à la fin du mois pour correspondre au comportement indiqué dans la documentation.
  • oauth-resource-server (entreprise) : l'autorisation du serveur de ressources OAuth traite désormais un tableau authorization_details vide comme une réclamation absente lorsque les détails de l'autorisation sont facultatifs. Auparavant, les jetons contenant un tableau vide étaient rejetés avec RAR_NO_MATCH au lieu de continuer via une identité et une autorisation de stratégie normales.
  • secrets-sync (entreprise) : correction d'un mappage incorrect des codes de réponse d'erreur pour les validations de chiffrement contrôlé par le client de GCP Secrets Sync, qui étaient renvoyées sous la forme d'une erreur de serveur interne de 500 au lieu de 400 requêtes incorrectes.
  • secrets-sync : correction des destinations GCP Secret Manager qui perdent leur clé KMS par région au redémarrage de Vault.
  • secrets-sync : corrige le champ Balises personnalisées dans la vue Détails pour afficher les clés avec une valeur vide
  • secrets/pki-external-ca (entreprise) : Inclut la clé privée dans les PEM du champ de réponse du certificat API lorsque certificate_format est défini sur pem_bundle
  • secrets/transit (entreprise) : ajoutez la prise en charge des clés gérées à la signature CSR et définissez les points de terminaison de la chaîne de certificats.
  • ui : gère correctement les valeurs de chaîne ("true"/"false") pour tls_disable lors de l'affichage de l'état TLS dans le widget de configuration du cluster.
  • ui : corrige la racine générée par PKI, donc non valide après avoir correctement contrôlé les entrées d'expiration du certificat.

vault v2.0.4

2.0.4

August 04, 2026

BREAKING CHANGES:

  • containers: The following packages have been removed from UBI based container images: gnupg, openssl, procps.

SECURITY:

  • acl: Fix privilege-escalation vulnerability where a denied_parameters constraint on the policies request field could be bypassed by submitting a mixed-case policy name (e.g. "Super-Admin" instead of "super-admin"). Vault now normalizes the policies parameter to lowercase before evaluating allowed_parameters/denied_parameters constraints.
  • identity/scim (enterprise): The identity/entity/merge endpoint now rejects requests that involve any SCIM-managed entity, preventing privileged operators from bypassing SCIM ownership guardrails to transfer aliases, group memberships, or policies across SCIM boundaries.
  • identity: Prevent the entity batch-delete endpoint (identity/entity/batch-delete) from deleting the underlying storage of entities that belong to another namespace.
  • identity: entity/name updates now reject mismatched id or external_id selectors to prevent retargeting updates to a different entity

CHANGES:

  • auth/oci: Update plugin to v0.21.3
  • core: Bump Go version to 1.26.5.
  • core: remove support for duplicate attributes in HCL configuration files and policy definitions. Parsing HCL with duplicate attributes now always fails, and the VAULT_ALLOW_PENDING_REMOVAL_DUPLICATE_HCL_ATTRIBUTES environment variable that previously restored the legacy behavior has been removed.

FEATURES:

  • secrets: Added ability to view secrets in YAML format

IMPROVEMENTS:

  • auth/cert: Support login via x-forwarded cert headers even with tls disabled on the vault listener.
  • core (enterprise): Add an endpoint at sys/config/oauth-resource-server/id/:config_id to read oauth resource server profiles by config_id
  • core (enterprise): Make OAuth resource server JWT typ validation more permissive for tokens from IdPs such as Okta by allowing a missing typ header, while restricting present typ values to at+jwt, application/at+jwt, and JWT.
  • core (entreprise): Ameriolate sealwrap lock contention for core paths.
  • core/acl: Adds a global deny_slash_in_templated_path configuration option to reject the presence of slashes in rendered identity templates in policies, defaulting to false.
  • core/identity: Adds a global deny_slash_in_templated_path configuration option to reject the presence of slashes in rendered identity templates in policies, defaulting to false.
  • core/managed-keys/PKCS#11 (enterprise): Providing a non-empty value for one field while the other is already saved is rejected. To switch addressing modes, you must explicitly clear the old field by sending it as an empty string ("") in the same request alongside the new value.
  • core/managed-keys/PKCS#11 (enterprise): slot and token_label are now strictly enforced as mutually exclusive identifiers for an HSM token
  • events: Add VAULT_EVENT_NOTIFICATIONS_BOUNDED_QUEUE_SIZE environment variable to configure bounded event queues for event notification subscribers. Set to a positive integer (e.g., 16) to enable buffered channels of that size (maximum 1000). This prevents resource exhaustion in deployments with high subscriber counts, but comes at the cost of the potential for subscribers to miss events. Defaults to 0 (unbuffered) for backward compatibility.
  • identity/scim (enterprise): Added filtering support to the GET /scim/v2/Users and GET /scim/v2/Groups endpoints per RFC 7644. Supported filters: userName eq, externalId eq, active eq, and meta.lastModified gt/ge/lt/le for Users; displayName eq and meta.lastModified gt/ge/lt/le for Groups. Unsupported filter expressions return HTTP 400. ServiceProviderConfig now advertises filter.supported: true.
  • identity/scim (enterprise): Improve SCIM User and Group listing endpoint performance by using prefix sort instead of a separate sort pass.
  • identity: Include entity status and entity/alias timestamp details in entity list key_info responses.
  • oauth-resource-server: Add support for fine-grained policy control options (parameter constraints) in Rich Authorization Requests (RAR), including allowed_parameters, denied_parameters, and required_parameters inside authorization_details.
  • oauth-resource-server: Add support for identity template expressions (e.g. {{identity.entity.id}}) in Rich Authorization Requests (RAR).
  • scim: User resources now include a read-only groups field listing the direct group memberships managed by the requesting SCIM client, per RFC 7643.
  • secrets/kv (enterprise): Support reading and recovering KVv2 secrets from a loaded snapshot, including in-place recover and copy-from-path within the same mount and namespace.
  • ui: Add a read-only YAML view option to the KV v2 secret details page, alongside the existing UI and JSON views.
  • ui: Bump pnpm.overrides entry for tmp from 0.2.6 to 0.2.7.
  • ui: Bump pnpm.overrides entry for ws from 8.20.1 to 8.21.0.

BUG FIXES:

  • Proxy/Agent: Fixed a bug where auth method headers accumulated on the shared API client across re-auth cycles.
  • Proxy: Fixed a bug where the Vault token header accumulated duplicate values across WebSocket reconnects in the static secret cache updater.
  • Secrets Recovery (enterprise): Do not redirect to the active node for list requests to sys/storage/raft/snapshot-load or read/delete requests to sys/storage/raft/snapshot-load/{id}. If possible, handle these requests on the performance standby, otherwise forward the requests to the active node.
  • audit: Fix a regression from CVE-2025-6000 that broke enabling audit devices on Windows when a plugin directory was configured.
  • audit: make file and socket audit sink serialization context-aware so canceled or expired requests stop waiting behind blocked audit writes, reducing buildup of goroutines, memory, connections, and file descriptors during audit sink contention
  • auth/cert: Add support for x-forwarded cert headers coming from AWS ALBs.
  • auth/spiffe (enterprise): Use the full peer certificate chain when verifying certificates.
  • aws/auth: Redact EC2 instance metadata values from AWS auth error messages.
  • consumption-billing: Fix bug where PKI, SSH and SSH OTP certificate billing units from performance standby nodes were not being forwarded to active nodes for storage, causing billing events on standby nodes to be lost.
  • consumption-billing: Fix bug where SPIFFE JWT token billing units from performance standby nodes were not being forwarded to active nodes for storage, causing billing events on standby nodes to be lost.
  • consumption-billing: Fixed a bug where SSH duration-adjusted certificate counts and OTP counts whose decimal representation began with '4' could not be read back from storage, causing sys/billing/overview to return a 500 error with "lz4: bad magic number". The storage encoding now uses plain decimal strings consistent with other billing metrics, avoiding misidentification as lz4-compressed data.
  • consumption-billing: Fixed bug where OIDC token duration counts from performance standby nodes were not forwarded to active nodes for storage, causing billing events on standby nodes to be lost.
  • consumption-billing: Fixed deadlocks in KMIP and mount-scanning billing paths by avoiding nested lock acquisition during mount and plugin enumeration.
  • consumption-billing: Fixes LDAP and OpenLDAP dynamic and static role counting in use-case billing to use dedicated count endpoints (role-count, static-role-count) instead of LIST-based counting, which was undercounting roles.
  • core (enterprise): Fix a bug that causes unnecessary seal rewrapping.
  • core (enterprise): Preserve wrapping metadata when Control Group unwrap replays an approved request that returns a wrapped response.
  • core (enterprise): Update state checking of Sever-Side Consistent Token (SSCT) when used on performance secondary clusters. 403 response codes will be preferred over 412 for invalid, cross cluster token requests to secondary active nodes.
  • core/managed-keys (enterprise): Allow slot numbers above 32 bits in PKCS#11 managed keys.
  • core/seal: Fixed goroutine leak occurring when Encryption and Decryption functions time out.
  • core: Preserve URL query parameters when redirecting API requests containing duplicate slashes to their canonical path. Previously, the redirect dropped parameters such as ?list=true, potentially changing the result of the request.
  • events (enterprise): Fix a bug where events stopped being forwarded to performance secondaries after the active node restarted or had a change event (seal/unseal, etc).
  • export API: Normalize the end_time parameter in the activity export API to the end of the month to match the behavior stated in the documentation.
  • oauth-resource-server (enterprise): OAuth Resource Server authorization now treats an empty authorization_details array like an absent claim when authorization details are optional. Previously, tokens containing an empty array were rejected with RAR_NO_MATCH instead of continuing through normal identity and policy authorization.
  • secrets-sync (enterprise):fixed incorrect error response code mapping for GCP Secrets Sync Customer Controlled Encryption validations, which were returned as 500 Internal Server Error instead of 400 Bad Request.
  • secrets-sync: Fix GCP Secret Manager destinations losing their per-region KMS key on Vault restart.
  • secrets-sync: Fixes Custom Tags field in Details view to display keys with empty value
  • secrets/pki-external-ca (enterprise): Include the private key within the certificate API response field's PEMs when certificate_format is set to pem_bundle
  • secrets/transit (enterprise): Add managed key support to CSR sign and set certificate chain endpoints.
  • ui: Correctly handle string values ("true"/"false") for tls_disable when displaying TLS status in the Cluster Configuration widget.
  • ui: Fixes PKI generate root so Not valid after correctly controls cert expiration inputs.
