go-ethereum v1.17.0

allez-Ethereum v1.17.0

<!-- Circuits Eezo-Inlaid (v1.17.0) -->

Il s'agit d'une version de fonctionnalités, avec tout le développement accumulé au cours des 3 derniers mois. Voir ci-dessous pour les faits saillants.

Notez que cette version contient plusieurs correctifs de sécurité critiques, ainsi que de nombreuses corrections de bogues, et est recommandée à tous les utilisateurs. Cependant, si vous êtes prudent concernant les mises à niveau, vous pouvez également installer v1.16.9 qui ne contient que les correctifs de sécurité critiques. Plus précisément, cette version corrige CVE-2026-26313, CVE-2026-26314, CVE-2026-26315.

Nous vous recommandons de recréer votre clé de nœud p2p après avoir installé cette mise à jour, ce que vous pouvez faire en supprimant le fichier DATADIR/geth/nodekey avant de redémarrer geth. Notez que cela entraînera une modification de l'ID du nœud p2p, ce qui peut interrompre les configurations de peering statiques.

Faits saillants

Nœud d'archive basé sur le chemin avec preuves

Le nœud d'archive basé sur le chemin peut désormais fournir des preuves (via eth_getProof) de l'état des blocs plus anciens.

Vous pouvez configurer la plage de blocs qui prend en charge la preuve indépendamment de la disponibilité des autres états d'archive. Plus précisément, vous pouvez utiliser l'indicateur de ligne de commande --history.trienode pour définir la quantité de blocs pour lesquels les nœuds d'arborescence seront suivis.

Cette fonctionnalité est désactivée par défaut. Notez que l'historique des états ne peut pas être facilement récupéré une fois supprimé, car il ne peut être généré que par le traitement de blocs. Cependant, vous pouvez activer l'historique des triénodes (et/ou l'historique des états) à tout moment pour transformer un nœud complet en un nœud d'archive partiel, conservant ainsi l'état à partir de ce moment-là.

#32727, #32621, #33551, #32981, #33399, #32913, #33303, #33584, #33329, #33681, #33103, #33098, #33515, #32247

Prise en charge de l'historique EraE

Geth prend désormais en charge le format de fichier EraE, un format d'archivage pour l'historique de la chaîne post-fusion.

#32157, #33827

OpenTelemetry Traçage

Le traçage OpenTelemetry est désormais pris en charge par le serveur RPC, y compris la prise en charge du traçage distribué. Nous avons également ajouté quelques traçages pour le traitement des blocs via le moteur API, c'est-à-dire engine_newPayload.

#33599, #33452, #33780, #33521

Tous les changements

Geth CLI

  • La sous-commande geth version-check a été supprimée. Cette commande a vérifié sur le site Web Geth les avis de vulnérabilité signés et indique si des mises à jour sont nécessaires (# 33498).
  • Il existe désormais un indicateur de ligne de commande --miner.maxblobs pour définir une limite sur les blobs inclus dans les blocs construits (#33129, #33302)
  • Geth prend désormais en charge le profilage continu avec le pyroscope Grafana (#33623)
  • Un bug rare qui pouvait interrompre la production de blocs en mode geth --dev a été corrigé (#33146)
  • Un nouvel indicateur --rpc.rangelimit configure la plage de bloc maximale pour eth_getLogs (#33163)
  • geth --exitwhensynced définira désormais les blocs finalized et safe (#33038)
  • geth --ethstats rapporte désormais le temps de traitement du nouveau Payload au serveur de statistiques (#33395)
  • De nombreux problèmes mineurs dans le traitement des indicateurs de ligne de commande de Geth ont été corrigés (#33379, #33338, #33330, #32999, #33279, #33252).
  • La commande evm blocktest peut désormais lire les noms de fichiers depuis stdin lorsqu'aucun chemin n'est fourni (#32824)

Implémentation du fork

  • EIP-8024 : SWAPN, DUPN, EXCHANGE rétrocompatibles (#33095, #33787, #33614, #33361)
  • Nous avons implémenté engine_getBlobsV3 (#33404, #33444)
  • Le moteur API rejette désormais les appels avec une mauvaise version de charge utile (#32754, #33322)
  • blsync a été mis à jour pour Fusaka (#33349, #33272, #33065, #32674)
  • Certains travaux vers la migration de l'état vers un arbre binaire ont atterri, et cela remplace l'implémentation de Verkle Tree (#33807, #33739, #33694, #32445, #33461)
  • Certaines sémantiques des listes d'accès ont été corrigées lors du travail sur les listes d'accès au niveau bloc EIP-7928 (#33281, #33637, #33450)

Noyau

  • La bibliothèque crypto/ecies a permis l'extraction de la clé privée utilisée pour la dérivation de clé via l'observation du timing de réponse. Nous vous recommandons de faire pivoter la clé du nœud après avoir appliqué cette mise à jour. (#33669)
  • Lorsqu'un bloc manquant est rencontré lors de la désindexation de l'émission, Geth l'ignore désormais et continue au lieu d'entrer dans une boucle infinie. (#33573)
  • Geth collecte et exporte désormais éventuellement des métriques sur la taille totale de l'état (#33254, #33376, #33415)
  • Il existe un nouveau hook OnStateUpdate, qui est appelé une fois que tous les états d'un bloc ont été validés. Cela donne accès au changeset du bloc. (#33490)
  • Quelques bugs mineurs de traçage ont été corrigés (#32919, #33148, #33644, #33214)
  • Divers problèmes mineurs dans la base de données du congélateur ont également été corrigés (#33747, #33025, #33203, #33344)
  • L'opération setHead désactive désormais le bloc finalisé, dans les cas où la plage de blocs annulés s'étend avant lui. (#33486)
  • La méthode SignatureValues de types.Signer signale désormais une erreur pour les tailles de signature non valides (#33647)
  • Geth imprime des messages de journal détaillés pour les « blocs lents » (#33655, #33525, #33442, #32812, #33659, #33532)
  • La configuration de Pebble a été modifiée pour des performances améliorées (#33697, #33353, #33315)
  • Un crash rare dans l'indexeur de journaux lié à la gestion de la réorganisation a été corrigé (#33810)
  • La comptabilité de la taille des différences d'état interne a été corrigée, de sorte que les différences d'état seront désormais vidées moins souvent vers le stockage sur disque (#33505).
  • Étant donné que la variante de la fonction de hachage keccak256 utilisée par Ethereum n'a plus de chemin rapide dans la bibliothèque standard, nous avons revendu l'implémentation de keccak dans notre référentiel (#33323)

Bibliothèque

  • La bibliothèque RLP dispose désormais d'un type RawList pour traiter les listes non décodées de manière plus pratique (#33755, #33834, #33840, #33841)
  • L'itérateur RLP bas niveau et ses utilisations ont été améliorés (#33245, #33188, #33820)
  • Clef peut désormais signer des transactions blob avec des preuves de cellule (#32910)
  • Correction de quelques bugs mineurs dans l'exportation de métriques (#33749, #33748)
  • La bibliothèque de portefeuille matériel prend désormais en charge le Ledger Nano Gen5 et active correctement la signature EIP-712 pour toutes les versions prises en charge. (#33297, #33113)
  • SignTextWithPassphrase fonctionne désormais correctement avec tous les portefeuilles matériels pris en charge (#33138)
  • Quelques bugs mineurs ont été corrigés dans l'implémentation du keystore (#33606, #33602, #33090)
  • La fonction bitutil.XORBytes a été dépréciée au profit du package stdlib crypto/subtle (#33331)
  • Une fuite de mémoire dans la chaîne lumineuse de la balise client a été corrigée (#33483)

###RPC

  • eth_getTransactionByHash renvoie désormais le blockTimestamp dans le cadre de l'objet de transaction (#33709)
  • Les codes d'erreur pour certaines conditions dans eth_simulateV1, eth_getLogs, eth_getStorageAt ont été améliorés pour mieux se conformer à la spécification RPC d'exécution (#33007, #33320, #33282).
  • eth_simulateV1 sélectionne désormais le jeu correct de précompilations pour l'en-tête simulé (#33363)
  • eth_sendTransaction et eth_fillTransaction sont désormais par défaut EIP-1559 (#33058)
  • L'implémentation de GraphQL a reçu quelques corrections de bugs pour les cas où un élément résolu n'est pas trouvé. (#33184, #33225)
  • Dans GraphQL, le gasPrice est désormais récupérable pour les types de transactions 0x3 et 0x4 (#33542)
  • Le serveur RPC active désormais HTTP2 en texte brut pour des performances améliorées (#33812)
  • Le RPC client n'envoie plus de trames RST_STREAM HTTP2 parasites (#33122)
  • Quelques bugs mineurs d'encodage JSON ont été corrigés dans ethclient (#33693, #33242, #33464)
  • Le gethclient a un nouveau wrapper du callTracer (#31510)
  • Dans le callTracer, les logs rapportés contiennent désormais un champ index qui est l'index du log au sein de la transaction (#33629)

Réseau P2P

  • Le mécanisme de pulsation du pool de transactions comportait quelques correctifs pour les fuites potentielles de ressources (#33704)
  • Les implémentations des protocoles eth et snap valident désormais la plupart des messages p2p avant de décoder leur contenu. Cela améliore la sécurité et les performances de synchronisation dans certains cas. (#33835)
  • Le pool de transactions blob a connu quelques corrections de bugs et accepte désormais les transactions non interrompues dans une mesure très limitée (#32717, #33775, #33474, #33352, #33301, #33260).
  • L'état de la synchronisation instantanée est désormais mieux suivi, garantissant qu'une synchronisation instantanée ne sera pas déclenchée accidentellement par le moteur API (#33157)
  • Le planificateur de synchronisation instantanée a été amélioré pour mieux protéger la base de données trie contre les mutations accidentelles pendant que le nœud traite des blocs. Cela résout certains cas extrêmes où la base de données pourrait être corrompue (#33428)
  • L'implémentation de la synchronisation d'en-tête a été corrigée pour mieux gérer les opérations setHead pendant la synchronisation (#33481)
  • Les connexions homologues délivrant des transactions périmées seront moins pénalisées, puisque la livraison de quelques transactions périmées est un phénomène courant. (#32725)
  • Les pairs annonçant des transactions d'un type et livrant un type différent sont désormais déconnectés à titre de pénalité (#33378)
  • De même, les pairs délivrant des preuves KZG invalides seront désormais déconnectés (5b99d2bba4)
  • Le pool de transactions a de nouvelles mesures pour le nombre de comptes avec des transactions (#33646, #33654)

Pour un aperçu complet des modifications, veuillez consulter le jalon de la version Geth 1.17.0.

Comme pour toutes nos versions précédentes, vous pouvez retrouver :

  • Binaires prédéfinis pour toutes les plateformes sur notre page de téléchargements.
  • Images Docker publiées sous ethereum/client-go (utiliser la balise "stable").
  • Packages Ubuntu dans notre [référentiel Launchpad PPA] (https://launchpad.net/~ethereum/+archive/ubuntu/ethereum).
  • Packages macOS dans notre [référentiel Homebrew Tap] (https://github.com/ethereum/homebrew-ethereum).

go-ethereum v1.17.0

<!-- Eezo-Inlaid Circuitry (v1.17.0) -->

This is a feature release, with all accumulated development from the last 3 months. See below for the highlights.

Note that this release contains multiple critical security fixes, as well as many bug fixes, and is recommended for all users. However, if you are cautious about upgrades, you can also install v1.16.9 which has just the critical security fixes. Specifically, this release fixes CVE-2026-26313, CVE-2026-26314, CVE-2026-26315.

We recommend recreating your p2p node key after installing this update, which you can do by removing the DATADIR/geth/nodekey file before restarting geth. Note this will cause a change in the p2p node ID, which may break static peering setups.

Highlights

Path-based Archive Node with Proofs

The path-based archive node can now serve proofs (via eth_getProof) for the state of older blocks.

You can configure the block range that supports proving independently from other archive state availability. Specifically, you can use the --history.trienode command-line flag to set the amount of blocks for which tree nodes will be tracked.

This feature is disabled by default. Note that state history cannot easily be recovered once deleted, as it can only be generated by processing blocks. However, you can enable trienode history (and/or state history) at any time to turn a full node into a partial archive node, keeping state from that point in time onwards.

#32727, #32621, #33551, #32981, #33399, #32913, #33303, #33584, #33329, #33681, #33103, #33098, #33515, #32247

EraE History Support

Geth now suports the EraE file format, an archival format for post-merge chain history.

#32157, #33827

OpenTelemetry Tracing

OpenTelemetry tracing is now supported by the RPC server, including support for distributed tracing. We have also added some tracing spans for block processing via the engine API, i.e. engine_newPayload.

#33599, #33452, #33780, #33521

All Changes

Geth CLI

  • The geth version-check subcommand has been removed. This command checked the geth website for signed vulnerability notices, and would tell if updates are necessary (#33498)
  • There is now a --miner.maxblobs command-line flag to set a limit on blobs included in built blocks (#33129, #33302)
  • Geth now supports continuous profiling with Grafana Pyroscope (#33623)
  • A rare bug that could halt block production in geth --dev mode was fixed (#33146)
  • A new --rpc.rangelimit flag configures the maximum block range for eth_getLogs (#33163)
  • geth --exitwhensynced will now set the finalized and safe block (#33038)
  • geth --ethstats now reports the newPayload processing time to the stats server (#33395)
  • A lot of minor issues in Geth's command-line flag processing have been fixed (#33379, #33338, #33330, #32999, #33279, #33252)
  • The evm blocktest command can now read filenames from stdin when no path is provided (#32824)

Fork Implementation

  • EIP-8024: Backward compatible SWAPN, DUPN, EXCHANGE (#33095, #33787, #33614, #33361)
  • We have implemented engine_getBlobsV3 (#33404, #33444)
  • The engine API now rejects calls with wrong payload version (#32754, #33322)
  • blsync has been updated for Fusaka (#33349, #33272, #33065, #32674)
  • Some work towards the migration of state to a binary tree has landed, and this replaces the Verkle Tree implementation (#33807, #33739, #33694, #32445, #33461)
  • Some access list semantics have been fixed while working on EIP-7928 Block-Level Access Lists (#33281, #33637, #33450)

Core

  • The crypto/ecies library allowed extraction of the private key used for key derivation via observation of response timing. We recommend rotating the node key after applying this update. (#33669)
  • When a missing block is encountered during tx unindexing, Geth will now skip it and move on instead of entering an infinite loop. (#33573)
  • Geth now optionally collect and export metrics about the total state size (#33254, #33376, #33415)
  • There is a new OnStateUpdate hook, which is called after all state of a block has been committed. This gives access to the changeset of the block. (#33490)
  • Some minor tracing bugs have been fixed (#32919, #33148, #33644, #33214)
  • Various minor issues in the freezer database have also been fixed (#33747, #33025, #33203, #33344)
  • The setHead operation now unsets the finalized block, in cases where the rolled-back block range extends before it. (#33486)
  • The SignatureValues method of types.Signer now reports an error for invalid signature sizes (#33647)
  • Geth prints detailed log messages for 'slow blocks' (#33655, #33525, #33442, #32812, #33659, #33532)
  • Pebble configuration has been tweaked for improved performance (#33697, #33353, #33315)
  • A rare crash in the log indexer related to reorg handling has been fixed (#33810)
  • Internal state diff size accounting has been corrected, so state diffs will now be flushed to the disk store less often (#33505)
  • Since the keccak256 hash function variant used by Ethereum no longer has a fast-path in the standard library, we have vendored the keccak implementation back into our repository (#33323)

Library

  • The RLP library now has a RawList type for dealing with un-decoded lists in a more convenient way (#33755, #33834, #33840, #33841)
  • The low-level RLP iterator and uses of it have been improved (#33245, #33188, #33820)
  • Clef can now sign blob transactions with cell proofs (#32910)
  • Fixed some corner-case bugs in metrics exporting (#33749, #33748)
  • The hardware wallet library now supports the Ledger Nano Gen5 and correctly enables EIP-712 signing for all supported versions. (#33297, #33113)
  • SignTextWithPassphrase now works correctly with all supported hardware wallets (#33138)
  • Some minor bugs were fixed in the keystore implementation (#33606, #33602, #33090)
  • The bitutil.XORBytes function has been deprecated in favor of stdlib package crypto/subtle (#33331)
  • A memory leak in the beacon chain light client was fixed (#33483)

RPC

  • eth_getTransactionByHash now returns the blockTimestamp as part of the transaction object (#33709)
  • Error codes for some conditions in eth_simulateV1, eth_getLogs, eth_getStorageAt have been improved to better comply with the execution RPC spec (#33007, #33320, #33282)
  • eth_simulateV1 now selects the correct set of precompiles for the simulated header (#33363)
  • eth_sendTransaction and eth_fillTransaction now default to EIP-1559 (#33058)
  • The GraphQL implementation has received some bug fixes for cases where a resolved item is not found. (#33184, #33225)
  • In GraphQL, the gasPrice is now retrievable for transaction types 0x3 and 0x4 (#33542)
  • The RPC server now enables plain-text HTTP2 for improved performance (#33812)
  • The RPC client no longer sends spurious RST_STREAM HTTP2 frames (#33122)
  • Some minor JSON encoding bugs have been fixed in ethclient (#33693, #33242, #33464)
  • The gethclient has a new wrapper of the callTracer (#31510)
  • In the callTracer, reported logs now contain an index field which is the index of the log within the transaction (#33629)

P2P Networking

  • The transaction pool heartbeat mechanism had some fixes for potential resource leaks (#33704)
  • The eth and snap protocol implementations nows validates most p2p messages before decoding their content. This improves security and sync performance in some cases. (#33835)
  • The blob transaction pool has seen some bug fixes and now accepts nonce-gapped transactions to a very limited extent (#32717, #33775, #33474, #33352, #33301, #33260)
  • Snap sync status is now tracked better, ensuring a snap sync will not be triggered accidentally by the engine API (#33157)
  • The snap sync scheduler was improved to better protect the trie database against accidential mutations while the node is processing blocks. This resolves some edge cases where the database could be corrupted (#33428)
  • The header sync implementation was fixed to better deal with setHead operations during sync (#33481)
  • Peer connections delivering stale transactions will be penalized less, since delivery of a few stale transactions is a common occurrence. (#32725)
  • Peers announcing transactions of one type, and delivering a different type, are now disconnected as penalty (#33378)
  • Similarly, peers delivering invalid KZG proofs will now be disconnected (5b99d2bba4)
  • The transaction pool has new metrics for the number of accounts with transactions (#33646, #33654)

For a full rundown of the changes please consult the Geth 1.17.0 release milestone.

As with all our previous releases, you can find the:

  • Pre-built binaries for all platforms on our downloads page.
  • Docker images published under ethereum/client-go (use "stable" tag).
  • Ubuntu packages in our Launchpad PPA repository.
  • macOS packages in our Homebrew Tap repository.
