orque v1.4.241

Des chats et un navigateur qui se comportent comme vous l'attendez 🧭

Cette version permet aux chats de suivre les paramètres de votre agent, apporte des outils de style Chrome au navigateur intégré et aide les connexions SSH et les serveurs gérés à récupérer. Vous trouverez également un paramètre de police de discussion, une navigation d'agent en direct et des terminaux Hermes, Kimi, Kiro et Windows plus stables.

La version courte

  • Chats qui suivent vos paramètres : Les nouveaux chats utilisent l'autorisation de chaque agent dans Paramètres → Agents, les chats renommés conservent leurs noms dans l'historique de session et un chat n'écrira pas de conversation lorsqu'un terminal est toujours en cours d'exécution.
  • Un navigateur plus proche de Chrome : Dockez DevTools dans le volet, coupez le son des onglets, voyez l'URL d'un lien au survol et utilisez les raccourcis Orca et la souris avant/arrière dans les pages.
  • Regardez les agents parcourir : Un curseur et un badge indiquent où un agent est en train de taper ou de taper, le chat vous amène à la page et les liens des terminaux et du chat s'ouvrent à côté de leur source.
  • SSH avec moins d'impasses : Les transferts de ports enregistrés reviennent après un redémarrage et expliquent les échecs, les hôtes de certificat uniquement se connectent via votre système ssh et les serveurs gérés se mettent à jour sans fermer les terminaux.
  • Agents qui démarrent et reprennent de manière fiable : Les volets Hermes et Kimi reprennent après un redémarrage, Kiro signale l'état sur son moteur V3 et les clés saisies lors du démarrage d'un agent sont conservées sous forme de brouillon.
  • Polissez là où ça compte : Choisissez une police pour le chat, zoomez avec Cmd/Ctrl + + sur les claviers non américains, ouvrez les fichiers cloud uniquement à partir des terminaux macOS et obtenez des terminaux Windows et des collages plus stables. Mises à jour sur le téléphone et sur le Web : Les téléphones ne suppriment plus les éléments de sortie du terminal, et les noms de discussion ainsi que le mode d'autorisation de chaque discussion s'affichent désormais ici. Les onglets de session conservent également les agents Working et Needs You pour Windows qui ne définissent jamais de titre.

Notes de compatibilité et de mise à niveau

  • Nouvel hôte de terminal : Les nouveaux terminaux démarrent sur un nouvel hôte de terminal, les correctifs de terminal de cette version s'appliquent donc. Les terminaux déjà ouverts avant la mise à jour continuent de fonctionner et restent attachés sur l'hôte précédent jusqu'à ce que vous les fermiez.
  • Autorisations de chat : Paramètres → Le chat n'a plus sa propre liste déroulante d'autorisations ; définissez-le par agent dans Paramètres → Agents. Les discussions existantes conservent leur autorisation enregistrée et le menu d'autorisation d'une discussion ne modifie que cette discussion.
  • Conversations ouvertes dans un terminal : Si un terminal est encore en train d'écrire une conversation, son chat ne sera pas envoyé et vous demandera de quitter l'agent ou de fermer ce terminal. La fermeture de ce terminal permet au prochain envoi de passer.
  • Serveurs SSH gérés : Mettre à jour quand même continue d'exécuter les terminaux en cours de mise à jour. L'offre de reprise des discussions après un redémarrage nécessite un serveur exécutant déjà cette version.
  • Sélections de modèles OpenCode : OpenCode 2.0.14, 2.0.15, 2.0.17 et 2.0.18 laissent le premier message non envoyé lorsqu'un modèle est sélectionné, donc Orca refuse les sélections de modèles sur ces versions.

orca v1.4.241

Chats and a browser that behave the way you expect 🧭

This release makes chats follow your agent settings, brings Chrome-style tools to the built-in browser, and helps SSH connections and managed servers recover. You’ll also find a chat font setting, live agent browsing, and steadier Hermes, Kimi, Kiro and Windows terminals.

The short version

  • Chats that follow your settings: New chats use each agent’s permission from Settings → Agents, renamed chats keep their names in Session History, and a chat won’t write a conversation a terminal is still running.
  • A browser closer to Chrome: Dock DevTools inside the pane, mute tabs playing sound, see a link’s URL on hover, and use Orca shortcuts and mouse back/forward inside pages.
  • Watch agents browse: A cursor and badge show where an agent is clicking or typing, chat jumps you to the page, and links from terminals and chat open beside their source.
  • SSH with fewer dead ends: Saved port forwards return after a restart and explain failures, certificate-only hosts connect through your system ssh, and managed servers update without closing terminals.
  • Agents that start and resume reliably: Hermes and Kimi panes resume after a restart, Kiro reports status on its V3 engine, and keys typed while an agent starts are kept as a draft.
  • Polish where it counts: Pick a font for chat, zoom with Cmd/Ctrl + + on non-US keyboards, open cloud-only files from macOS terminals, and get steadier Windows terminals and pasting.

Phone & web updates: Phones no longer drop pieces of terminal output, and chat renames and each chat’s permission mode now show there. Session tabs also keep Working and Needs You for Windows agents that never set a title.

Compatibility & upgrade notes

  • Fresh terminal host: New terminals start on a fresh terminal host so this release’s terminal fixes apply. Terminals already open before you update keep running, and stay attached, on the previous host until you close them.
  • Chat permissions: Settings → Chat no longer has its own permission dropdown; set it per agent in Settings → Agents. Existing chats keep their saved permission, and a chat’s own permission menu changes only that chat.
  • Conversations open in a terminal: If a terminal might still be writing a conversation, its chat won’t send and asks you to quit the agent there or close that terminal. Closing that terminal lets the next send go through.
  • Managed SSH servers: Update anyway keeps running terminals going through the update. The offer to resume chats after a restart needs a server already running this release.
  • OpenCode model picks: OpenCode 2.0.14, 2.0.15, 2.0.17 and 2.0.18 leave the first message unsent when a model is picked, so Orca refuses model picks on those versions.
