ansible v2.19.8

Highlights

  • GitHub Actions can access Ansible Core CI — ansible-test gains a GitHub Actions provider for requesting managed Core CI resources (#86646). Adoption is not automatic: authentication requires a pre-provisioned SSH key plus ANSIBLE_TEST_GHA_JOB_ID and ANSIBLE_TEST_GHA_SSH_KEY_ARTIFACT_ID.

  • Managed test targets now have aliases — selectors such as ubuntu, rhel/latest, and windows/latest reduce coupling to exact image or OS versions (#86651). This simplifies test-matrix maintenance, but latest aliases float as the environment catalog changes; pin names such as rhel/9.7 when reproducibility matters.

  • Network modules avoid tagged-response unpickling failures — JsonRpcServer converts AnsibleTaggedObject values to native Python types before pickling non-string responses (#86606), allowing module-side contexts to deserialize them safely. Custom RPC consumers should not expect Ansible tag metadata to cross this boundary.

  • Config lookup resolves dependent defaults — the lookup now overlays task variables on ansible.constants (#86560). Configuration defaults referencing built-ins such as ANSIBLE_HOME therefore resolve even when those names are absent from task variables, while task variables retain precedence.

  • String YAML parsing works without LibYAML — the pure-Python PyYAML loader no longer raises a traceback for string inputs, including from_yaml (#86576). This fixes controller installations built without the C extension; file parsing and LibYAML-backed installs are unaffected.

  • Breaking changes — None; no migration is required.
