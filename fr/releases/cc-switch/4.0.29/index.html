cc-switch v4.0.29

Correctif Publié10 nov. 2026 Sourcefarion1231/cc-switch Anglais original

interrupteur cc v4.0.29

#Commutateur CC v4.0.29 Cette version ajoute une nouvelle application gérée GitHub Copilot CLI : les fournisseurs disposant de leur propre clé écriront leur propre providers.json dans Copilot. Utilisez /model dans copilot pour le sélectionner avec le modèle officiel sans passer par CC Switch. Les langues coréenne et russe ont été ajoutées à l'interface. Les sept langues ont été maintenues simultanément, et l'anglais n'est plus affiché aux endroits manquants. De plus, la version de bureau du Codex sur Windows a signalé une erreur lors de l'exécution du Codex dans WSL lors de l'utilisation d'un fournisseur tiers ; Les nouvelles conversations du Codex ont signalé 400 lors de la connexion aux réponses natives tierces en amont via le routage ; lorsque le Codex se connectait au format Anthropic en amont via le routage, les réponses longues étaient tronquées par la limite supérieure de sortie de 8 192 ; Le responsable du Codex est resté bloqué en mode routage et n'a pas pu obtenir la propre liste de modèles du compte. Ajouter

GitHub Copilot CLI

GitHub Copilot CLI (copilot) devient une nouvelle application gérée (#8753, voir #5768 pour les exigences). Il existe deux types de cartes fournisseurs :

  • Connexion officielle : Connectez-vous avec Copilot CLI votre propre GitHub sans écrire de fichiers. « Open Terminal » démarre copilot avec le modèle et la force d'inférence sur la carte ; lorsque la carte est liée au compte GitHub du centre d'autorisation, utilisez ce compte pour démarrer. La limite Copilot du compte est affichée sur la carte.
  • Fournisseurs avec propre clé : cliquez sur "Ajouter" et écrivez le propre providers.json ($COPILOT_HOME/providers.json) de Copilot. Ensuite, si vous démarrez copilot n'importe où sur la machine, vous pouvez sélectionner « Logo/Modèle de carte » dans /model à côté du modèle officiel, et la demande sera envoyée directement au fournisseur sans passer par CC Switch. GitHub peut être utilisé sans se connecter.
    • CC Switch modifie uniquement ses propres entrées, laissant les autres entrées dans le fichier (Copilot lui-même écrira également ce fichier) et l'ordre inchangé. providers.json Copilot ne pourra pas démarrer s'il est mal écrit, donc l'intégralité du fichier sera vérifié selon les règles de Copilot avant l'écriture. Par exemple, la sortie maximale du modèle ne peut pas occuper toute la fenêtre contextuelle.
    • La maison où se trouve le modèle par défaut actuel de Copilot est marquée par défaut et ne peut pas être supprimée ou supprimée. Pour changer, utilisez d'abord /model dans copilot pour le remplacer par un autre modèle.
    • Le bouton terminal de la carte ne peut être utilisé qu'après l'avoir ajouté. Au démarrage, sélectionnez directement le premier modèle de cette carte.
    • Les valeurs par défaut héritent des valeurs par défaut du fournisseur de Pi. Prend également en charge :
  • MCP, Compétences, Mots d'invite : Synchronisé avec le mcp-config.json de Copilot, le répertoire de compétences et les fichiers de commandes.
  • Gestion des sessions : répertorie les sessions Copilot, qui peuvent être reprises dans le terminal.
  • Statistiques d'utilisation : importez l'utilisation à partir du journal de session de Copilot ; les fournisseurs possédant leur propre Clé seront facturés en fonction de la carte sélectionnée lors de la séance.
  • Lien d'importation en un clic : vous pouvez importer des fournisseurs Copilot, reconnaître l'écriture providers.json, prendre en charge bearerToken et conserver tous les ID de modèle dans le lien.

Interfaces coréennes et russes, sept langues sont maintenues simultanément

  • Coréen (#8794, voir #2704 pour les exigences) et Russe (#7788, voir #6010 pour les exigences) : sélection automatique par langue du système au premier démarrage, le menu de la barre d'état et le panneau de raccourcis ont également été traduits. La devise des statistiques d'utilisation a été ajoutée au won coréen (KRW), qui prend en charge l'acquisition automatique des taux de change.
  • Le turc, le coréen et le russe ne sont plus des « traductions communautaires, et l'anglais est affiché là où il manque » : chaque phrase de l'interface est disponible en sept langues : chinois simplifié, chinois traditionnel, anglais, japonais, 한국어, Türkçe et Русский. Plus tard, les rédactions nouvelles et modifiées seront également modifiées dans les sept langues.
  • Le résumé de la mise à jour qui apparaît après la mise à niveau n'est actuellement disponible qu'en chinois simplifié, chinois traditionnel, anglais et japonais, et les autres langues sont affichées en anglais.

Changement

  • Copilot explique la raison pour laquelle la liste de modèles obtenue est vide (#5500) : Les comptes Copilot Free peuvent obtenir des modèles, mais aucun d'entre eux ne peut être utilisé dans le sélecteur de modèle. Auparavant, cela indiquait seulement qu'aucun modèle n'était trouvé. Il vous indiquera maintenant que Copilot Pro n'est peut-être pas activé sur ce compte ; les formulaires Claude Code et Claude Desktop indiqueront également que gpt-4.1 ou gpt-4o peuvent être remplis manuellement. Lorsque le compte comporte des modèles, mais qu'aucun d'entre eux ne prend en charge le format en amont actuellement sélectionné, le formulaire Codex l'expliquera séparément.

Correction

  • Lorsque la version de bureau du Codex sous Windows exécute Codex dans WSL, un fournisseur tiers signale « Aucun fichier ou répertoire de ce type (erreur du système d'exploitation 2) » au démarrage (#9375). À partir de v4.0.27, CC Switch écrit le fichier de répertoire modèle en tant que chemin absolu Windows dans config.toml. Le Codex dans WSL ne peut pas lire ce chemin et les trois modes de connexion directe, de routage et d'agrégation sont affectés. Désormais sous Windows, la version de bureau du Codex a permis de revenir à l'écriture uniquement du nom de fichier lors de l'exécution du Codex dans WSL, qui sera automatiquement corrigé lors de sa prochaine écriture.
  • Nouvelle route de conversation Codex pour connecter les réponses natives tierces en amont Times 400 (#9328, associé #7074, #9379). La nouvelle version de bureau du Codex apportera les résultats de l'outil de contexte de page sans call_id dans les nouvelles conversations, tout comme les reçus pour l'automatisation et la répartition entre tâches, et les amonts avec une validation stricte rejetteront l'intégralité de la demande. Dans le passé, il n'était réécrit que pour xAI, mais désormais, toutes les réponses natives non officielles en amont sont réécrites dans un message utilisateur et le contenu est préservé. Les abonnements officiels et les résultats des outils avec call_id ne sont pas affectés.
  • Lorsque le Codex est connecté au format Anthropic en amont via le routeur, la réponse longue est tronquée et "Réponse incomplète renvoyée, motif : max_output_tokens" est signalé. Il en va de même pour la nouvelle tentative. Les requêtes Codex sans plafond de sortie étaient auparavant émises sous le numéro 8192, et il faut aussi penser que les appels d'outils qui écrivent un fichier entier à la fois seront épuisés. La valeur par défaut est désormais de 32 000. Lorsque la limite de sortie en amont est inférieure, il indiquera 400. Vous pouvez renseigner la valeur qu'il prend en charge dans les « jetons de sortie maximum » du fournisseur.
  • La carte officielle du Codex ne peut pas obtenir la propre liste de modèles du compte en mode routage : Le Codex ne peut utiliser que sa propre liste, qui ne dispose pas de modèles spécifiques au compte ; après avoir ouvert Daybreak dans la version de bureau du Codex, tous les modèles officiels deviennent gris. Désormais, lorsque le routeur utilise la carte officielle et que « Suspendre l'utilisation de la connexion officielle » n'est pas activé, le routeur transmettra la liste officielle des modèles au Codex telle quelle. Les fournisseurs tiers ne transmettent pas.
  • Lorsque Claude Code se connecte au modèle DeepSeek sur Mistral via un routage, chaque tour après l'outil est appelé rapporte 422 (#9385, #9388).
  • La carte Claude Code est utilisable uniquement en routage. Après avoir cliqué sur « Ouvrir le terminal », Claude Code affiche « Non connecté » pour chaque phrase, et la demande n'est pas envoyée du tout. Les informations d'identification des cartes telles que GitHub Copilot, Codex OAuth et xAI OAuth sont fournies par routage. Les cartes aux formats non anthropiques doivent être converties au format par routage, et le terminal se connecte directement à l'adresse de la carte et ne peut pas être utilisé. Désormais, le bouton "Ouvrir le terminal" de ce type de carte est grisé et il indique que vous devez activer le routage et exécuter le client directement dans le terminal. Ce type de carte sur la page Codex a également été modifié, passant d'un bouton caché à également grisé.
  • La limite affichée sur la carte officielle de Claude peut être celle d'un autre compte : Après avoir modifié la connexion par défaut de cette machine vers un autre compte, la carte utilisée lira la limite du compte de connexion par défaut. Il sera maintenant confirmé que la connexion par défaut appartient à ce compte.
  • Le quota d'Antigravity ne correspond pas à agy /usage ; Google AI Ultra 5x et 20x affichent uniquement « Google AI Ultra » (#9317, #9319).

cc-switch v4.0.29

Highlights

  • GitHub Copilot CLI becomes a managed app (#8753) — Two card types: official cards use Copilot CLI's own GitHub login and write no files; BYOK cards write into Copilot's own $COPILOT_HOME/providers.json (requested in #5768). The key architectural point: BYOK requests go straight from copilot to the provider via /model, bypassing CC Switch routing entirely, and work without a GitHub login. For adopters this is the first app whose config lives in the client rather than the switcher — expect to manage it from copilot itself.
  • BYOK safety rules and Copilot tooling — A malformed providers.json prevents Copilot from starting, so CC Switch validates the whole file before writing, touches only its own entry, and preserves other entries and ordering; the provider holding the current default model can't be removed until you switch away with /model. Presets are inherited from Pi. MCP servers, Skills, prompts, session resume and usage import are wired up, and one-click import links accept bearerToken while preserving model IDs — useful for migrating an existing Copilot setup.
  • Codex routing: 400s on new conversations and truncated long answers — Tool results without call_id (new-chat page context, automation receipts) are now rewritten as a user message for all non-official native Responses upstreams, not just xAI (#9328, #7074, #9379); official subscriptions and call_id-bearing results are untouched. Separately, routed requests to Anthropic-format upstreams now default to 32,000 output tokens instead of 8,192 (thinking counts toward the cap). Watch this: if an upstream's own limit is lower, set the provider's "max output tokens" or you'll trade truncation for a 400.
  • Codex WSL paths and account model lists — Since v4.0.27 CC Switch wrote Windows absolute paths for model directory files into config.toml; Codex under WSL couldn't read them and third-party providers failed with "No such file or directory" across direct, route and aggregate modes (#9375). The fix writes just the filename when WSL execution is enabled and self-corrects on the next write. Routing also now passes the official account's own model list through when the official card is active and "pause official login" is off — previously Daybreak greyed out every official model.
  • Claude Code routing and credential correctness — Fixes a 422 on every turn after a tool call when routing to DeepSeek models on Mistral (#9385, #9388), and stops the official card from showing another account's quota by verifying the default login belongs to that card. Route-only cards (Copilot, Codex OAuth, xAI OAuth, non-Anthropic formats) now grey out "Open terminal" instead of launching a session that reports "Not logged in" — if you used that button for these cards, run the client with routing enabled instead.
  • Seven languages at parity, clearer empty-model hints — Korean (#8794) and Russian (#7788) join the UI; Turkish, Korean and Russian are no longer partial translations with English fallbacks, all seven locales are maintained together, and KRW is added with automatic FX rates. Caveat: the post-upgrade summary still ships only in Simplified/Traditional Chinese, English and Japanese. An empty Copilot model list now explains a likely missing Copilot Pro subscription and suggests gpt-4.1/gpt-4o (#5500) rather than a generic "no models found".
  • No breaking changes.

CC Switch v4.0.29

本版本新增受管应用 GitHub Copilot CLI：自带 Key 的供应商会写进 Copilot 自己的 providers.json，在 copilot 里用 /model 就能和官方模型一起选，不用经过 CC Switch。界面新增韩语和俄语，七种语言从此同步维护，不再有缺的地方显示英文。

另外修复了 Windows 上 Codex 桌面版在 WSL 里运行 Codex 时，用第三方供应商启动就报错；Codex 新对话经路由连第三方原生 Responses 上游报 400；Codex 经路由连 Anthropic 格式上游时，长回答被 8192 的输出上限截断；Codex 官方卡在路由模式下拿不到账号自己的模型列表等问题。

新增

GitHub Copilot CLI

GitHub Copilot CLI（copilot）成为新的受管应用（#8753，需求见 #5768）。供应商卡片分两种：

  • 官方登录：用 Copilot CLI 自己的 GitHub 登录，不写任何文件。「打开终端」以卡片上的模型和推理强度启动 copilot；卡片绑定了授权中心的 GitHub 账号时，用这个账号启动。卡片上显示该账号的 Copilot 额度。
  • 自带 Key 的供应商：点「添加」后写进 Copilot 自己的 providers.json（$COPILOT_HOME/providers.json）。之后在本机任何地方启动 copilot，都能在 /model 里和官方模型并列选到「卡片标识/模型」，请求直接发给供应商，不经过 CC Switch 的路由。不登录 GitHub 也能用。
    • CC Switch 只改这一家自己的条目，文件里的其他条目（Copilot 自己也会写这个文件）和顺序原样保留。providers.json 写坏了 Copilot 会起不来，所以写入前会按 Copilot 的规则把整份文件校验一遍，例如模型的最大输出不能占满整个上下文窗口。
    • Copilot 当前默认模型所在的那一家标为默认，不能移除或删除。要换，先在 copilot 里用 /model 换成别家的模型。
    • 卡片上的终端按钮要添加之后才能用，启动时直接选中这张卡的第一个模型。
    • 预设沿用 Pi 的供应商预设。

此外还支持：

  • MCP、Skills、提示词：同步到 Copilot 的 mcp-config.json、Skills 目录和指令文件。
  • 会话管理：列出 Copilot 会话，可以在终端里恢复。
  • 用量统计：从 Copilot 的会话日志导入用量；自带 Key 的供应商按会话里选中的卡片记账。
  • 一键导入链接：可以导入 Copilot 供应商，认得 providers.json 写法，支持 bearerToken，链接里的模型 ID 全部保留。

韩语、俄语界面，七种语言同步维护

  • 韩语（#8794，需求见 #2704）和俄语（#7788，需求见 #6010）：首次启动按系统语言自动选择，托盘菜单和快捷面板也已翻译。用量统计的币种新增韩元（KRW），支持自动获取汇率。
  • 土耳其语、韩语、俄语不再是「社区翻译、缺的地方显示英文」：界面上的每一句话，中文简体、中文繁体、English、日本語、한국어、Türkçe、Русский 七种语言都有，之后新增和修改文案也会七种语言一起改。
  • 升级后弹出的更新摘要暂时只有中文简体、中文繁体、英文和日文，其他语言显示英文。

变更

  • Copilot 获取模型列表为空时说明原因（#5500）：Copilot Free 账号能拿到模型，但没有一个可以在模型选择器里用，以前只提示没有找到模型。现在会提示这个账号可能没有开通 Copilot Pro；Claude Code 和 Claude Desktop 的表单还会提示可以手动填写 gpt-4.1 或 gpt-4o。账号有模型、但都不支持当前选择的上游格式时，Codex 表单会单独说明。

修复

  • Windows 上 Codex 桌面版在 WSL 里运行 Codex 时，用第三方供应商一启动就报「No such file or directory (os error 2)」（#9375）。v4.0.27 起，CC Switch 在 config.toml 里把模型目录文件写成 Windows 绝对路径，WSL 里的 Codex 读不懂这个路径，直连、路由、聚合三种模式都受影响。现在在 Windows 上、Codex 桌面版开启了在 WSL 中运行 Codex 时，改回只写文件名，下次写入时自动改正。
  • Codex 新对话经路由连第三方原生 Responses 上游时报 400（#9328，相关 #7074、#9379）。新版 Codex 桌面版会在新对话里带上没有 call_id 的页面上下文工具结果，自动化和跨任务派发的回执也是这样，校验严格的上游会拒绝整个请求。以前只对 xAI 改写，现在对所有非官方的原生 Responses 上游都改写成一条用户消息，内容保留。官方订阅和带 call_id 的工具结果不受影响。
  • Codex 经路由连 Anthropic 格式上游时，长回答被截断，报「Incomplete response returned, reason: max_output_tokens」，重试也一样。Codex 请求不带输出上限，以前按 8192 发出，思考也算在内，一次写一整个文件的工具调用就会用完。现在默认改为 32000。上游的输出上限更低时会报 400，可以在供应商的「最大输出 tokens」里填它支持的值。
  • Codex 官方卡在路由模式下拿不到账号自己的模型列表：Codex 只能用它自带的列表，缺少账号专属的模型；Codex 桌面版打开 Daybreak 后，官方模型全部变灰。现在路由正在用官方卡、且没有打开「暂停使用官方登录」时，路由会把官方的模型列表原样交给 Codex。第三方供应商不转发。
  • Claude Code 经路由连 Mistral 上的 DeepSeek 模型时，工具调用之后的每一轮都报 422（#9385、#9388）。
  • 只能经路由使用的 Claude Code 卡片，点「打开终端」后 Claude Code 每句话都提示未登录（「Not logged in」），请求根本没发出去。GitHub Copilot、Codex OAuth、xAI OAuth 这类卡片的凭据由路由提供，非 Anthropic 格式的卡片要靠路由转换格式，终端直连卡片地址用不了。现在这类卡片的「打开终端」按钮变灰，并说明要开启路由后在终端里直接运行客户端。Codex 页面上这类卡片也从隐藏按钮改为同样变灰。
  • Claude 官方卡显示的额度可能是另一个账号的：本机默认登录换成别的账号后，正在用的那张卡会读到默认登录那个账号的额度。现在会先确认默认登录属于这个账号。
  • Antigravity 的额度和 agy /usage 对不上；Google AI Ultra 5x 和 20x 都只显示「Google AI Ultra」（#9317、#9319）。
