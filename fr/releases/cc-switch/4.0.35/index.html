cc-switch v4.0.35

interrupteur cc v4.0.35

#Commutateur CC v4.0.35 Cette version permet aux cartes Codex utilisant les comptes ChatGPT dans Claude Code / Claude Desktop d'utiliser GPT-6.2. La cible complète du Codex /goal peut être vue dans la gestion de session, et l'ID de demande dans les détails de la demande peut être copié en un clic. De plus, le mode automatique de Claude Code est entièrement bloqué sur les modèles qui ne peuvent pas désactiver la réflexion ; le mode d'agrégation Codex et « Open Terminal » signalent que Responses-Lite nécessite reasoning.context ; la première demande après que le Codex a compressé le contexte est rejetée ; la page d'utilisation est bloquée lorsque la date personnalisée est sélectionnée sur une année très précoce ; et la copie gérée de Skill ne peut pas être désinstallée si elle n'est plus là. Ajouter

Afficher la cible complète du Codex /goal dans la gestion de session

Lorsque la cible dépasse 700 octets, le contenu de la cible n'est pas écrit dans le contexte injecté par Codex, et la cible n'est pas visible dans la gestion de session (voir #9647). Désormais, l'objectif complet est lu à partir de l'enregistrement de la session et affiché sous la forme d'un « statut d'objectif » en une seule étape, qui est développé pour révéler le contenu complet ; Les enregistrements en double avec un objectif et un statut inchangés ne sont plus affichés.

Vous pouvez copier l'ID complet de la demande dans les détails de la demande.

Les valeurs trop longues dans les détails de la requête seront tronquées par des points de suspension. Les ID de requête longs tels que resp_... du Codex ne peuvent pas être copiés entièrement pour la correspondance des journaux (voir #9681). Il y a maintenant un bouton de copie après l'ID de la demande.

Prix ajouté du GPT-6.2 Sol / Astra

Le prix est calculé selon le fichier standard officiel (dans la limite de 272K) ; le fichier de contexte long, Batch/Fast et les autres fichiers ne sont pas distingués comme GPT-6.

Correction

  • La carte Codex utilisant un compte ChatGPT dans Claude Code / Claude Desktop ne peut pas obtenir GPT-6.2, et elle signale toujours "non pris en charge lors de l'utilisation du Codex avec un compte ChatGPT" après l'avoir renseignée manuellement (#9678, voir #9670) : OpenAI détermine quels modèles donner en fonction de la version du client Codex, CC Switch La version rapportée est trop ancienne. Maintenant, demandez selon le Codex 0.169.0, aucun ID de modèle n'est codé en dur.
  • Le mode automatique de Claude Code est entièrement rejeté pour Bash, MCP et autres appels d'outils sur les modèles qui ne peuvent pas désactiver la réflexion (voir #8887, #9671) : la demande de jugement en mode automatique nécessite de désactiver la réflexion. Des modèles comme le MiniMax-M3.1-Flash en rapportent directement 400, et Claude Code considère que le service de jugement n'est pas disponible. Désormais lors du passage par le routage (Claude Code et Claude Desktop), l'amont du format Anthropic signalera une erreur comme celle-ci et supprimera le champ qui ferme la réflexion, et réessayera dans la même société. Les requêtes initialement acceptées par l'amont sont envoyées telles quelles sans affecter le cache.
  • Le Codex a signalé "Responses-Lite nécessite que reasoning.context soit all_turns" en mode agrégation, et la connexion directe et le routage de la même société sont normaux (voir #9665) : Lorsque la carte n'écrit pas le répertoire modèle, le mode d'agrégation utilise les mêmes paramètres officiels GPT-6 que la connexion directe. La même erreur qui s'est produite lors de "l'ouverture du terminal" depuis la carte a également été corrigée.
  • Lorsque le Codex est converti au format Chat via le routage, la première requête après compression du contexte est rejetée par la passerelle avec des exigences strictes car "le contenu du message ne peut pas être vide" (voir #9660) : les messages utilisateur contenant uniquement des images deviendront des messages vides lors de la compression. Désormais, lors de la conversion au format Chat, les messages utilisateur au contenu vide sont supprimés et les autres messages restent inchangés.
  • Lorsque le point de départ de la date personnalisée sur la page d'utilisation est sélectionné sur une année très précoce telle que 1905, le client se fige (voir #9691) : Vous ne pouvez désormais sélectionner que les dates du premier enregistrement d'utilisation jusqu'à aujourd'hui. Les dates en dehors de la plage ne peuvent pas être sélectionnées et les dates saisies manuellement seront réintégrées dans la plage.
  • Impossible de désinstaller lorsque la copie gérée d'une compétence n'est plus disponible (#9669, voir #9668).

Un merci spécial aux contributeurs suivants : Votre PR a découvert et résolu un problème réel, mais le même problème a ensuite été résolu sur la ligne principale et le PR a été fermé. @xunapro (#4262, le premier PR du même type suggérait que la sélection du fournisseur de services S3 n'était pas mémorisée, et Alibaba Cloud OSS/Tencent Cloud COS a signalé 403 en raison de l'adresse du chemin), @mercutiojohn (#8547, a identifié trois raisons pour lesquelles le fournisseur Gemini CLI n'a pas réussi à obtenir la liste des modèles). Merci à @chencyan364, @DemosHume, @LAN-SHH, @mouse8867, @leafsnow, @zhuqiang1248, @ramonmi, @zx2121651, @VICCC-0x90 pour avoir soulevé des exigences, signalé des problèmes et fourni des informations de reproduction. cc-switch v4.0.35

Highlights

  • GPT-6.2 on ChatGPT-backed Codex cards — Claude Code and Claude Desktop now report Codex client version 0.169.0 instead of pinning model IDs, fixing the “not supported” rejection and letting OpenAI’s negotiation determine availability (#9678). Pricing covers only the standard ≤272K tier; long-context, Batch, and Fast tiers are not yet differentiated.
  • Auto mode tolerates mandatory reasoning — When an Anthropic-format upstream rejects the request to disable thinking—such as MiniMax-M3.1-Flash—the router removes that field and retries once with the same provider. Accepted requests remain untouched, preserving cache behavior, while Bash/MCP tool calls no longer fail across the session.
  • Codex routing handles aggregation and compaction — Cards without a model catalog now use the official GPT-6 settings employed by direct connections, satisfying Responses-Lite’s reasoning.context = all_turns requirement in aggregation and “Open Terminal” flows (#9665). Chat-format conversion also removes empty user messages produced by image-only compaction, preventing the first post-compaction request from being rejected (#9660).
  • Session and request diagnostics are no longer truncated — Full /goal text is recovered from session records even when Codex omits goals over 700 bytes from injected context; unchanged goal/status duplicates are collapsed. Long request IDs such as resp_... now have a copy button for reliable log correlation (#9647, #9681).
  • Guardrails for stale state — Missing managed Skill copies no longer block uninstall (#9669), while custom usage dates are limited to the range from the first recorded usage through today. Out-of-range manual input is clamped, eliminating the freeze caused by extremely early years (#9691).
  • Breaking changes — None.

CC Switch v4.0.35

本版本让 Claude Code / Claude Desktop 里用 ChatGPT 账号的 Codex 卡片能用上 GPT-6.2，会话管理里可以看到 Codex /goal 的完整目标，请求详情里的请求 ID 可以一键复制。

另外修复了 Claude Code 的 auto 模式在关不掉思考的模型上被整体拦下；Codex 聚合模式和「打开终端」报 Responses-Lite 需要 reasoning.context；Codex 压缩上下文后第一条请求被拒；用量页自定义日期选到很早的年份时卡死；Skill 的托管副本不在了就卸载不掉等问题。

新增

会话管理里显示 Codex /goal 的完整目标

目标超过 700 字节时，Codex 注入的上下文里不写目标内容，会话管理里也就看不到目标（见 #9647）。现在从会话记录里读出完整目标，显示成一步「目标 · 状态」，展开即是完整内容；目标和状态都没变的重复记录不再显示。

请求详情里可以复制完整的请求 ID

请求详情里过长的值会被省略号截断，像 Codex 的 resp_... 这类长请求 ID 没法完整复制去对日志（见 #9681）。现在请求 ID 后面多了一个复制按钮。

新增 GPT-6.2 Sol / Astra 的价格

按官方标准档（272K 以内）的价格计费；长上下文档、Batch / Fast 等档位和 GPT-6 一样暂不区分。

修复

  • Claude Code / Claude Desktop 里用 ChatGPT 账号的 Codex 卡片获取不到 GPT-6.2，手动填了也报「not supported when using Codex with a ChatGPT account」（#9678，见 #9670）：OpenAI 按 Codex 客户端版本决定给哪些模型，CC Switch 报的版本太旧。现在按 Codex 0.169.0 请求，没有写死任何模型 ID。
  • Claude Code 的 auto 模式在关不掉思考的模型上，Bash、MCP 等工具调用全部被拒（见 #8887、#9671）：auto 模式的判断请求要求关闭思考，MiniMax-M3.1-Flash 这类模型直接报 400，Claude Code 就认为判断服务不可用。现在经路由时（Claude Code 和 Claude Desktop），Anthropic 格式的上游这样报错会去掉关闭思考的字段，在同一家重试一次。上游本来接受的请求原样发送，不影响缓存。
  • Codex 聚合模式下报「Responses-Lite requires reasoning.context to be all_turns」，同一家直连和路由都正常（见 #9665）：卡片没写模型目录时，聚合模式改用和直连一样的 GPT-6 官方设置。从卡片「打开终端」时出现的同一个报错也一并修好。
  • Codex 经路由转成 Chat 格式时，压缩上下文后第一条请求被要求严格的网关以「message content cannot be empty」拒绝（见 #9660）：压缩时只含图片的用户消息会变成空消息，现在转成 Chat 格式时去掉内容为空的用户消息，其他消息不变。
  • 用量页自定义日期的起点选到 1905 年这类很早的年份时，客户端卡死（见 #9691）：现在只能选从第一条用量记录到今天之间的日期，范围外的日期不可选，手动输入的也会被拉回范围内。
  • Skill 的托管副本已经不在时卸载不掉（#9669，见 #9668）。

致谢

感谢 @imfuxiao（Codex 卡片支持 GPT-6.2）、@Maharramoff（卸载托管副本已不在的 Skill）、@SaladDay（拆分本地路由的转发代码、数据库访问改用应用类型）的贡献。

特别感谢以下贡献者：你们的 PR 发现并修复了真实的问题，只是同样的问题后来在主线上另行修好，PR 因此关闭。@xunapro（#4262，同类 PR 里最早提出 S3 服务商选择没被记住、阿里云 OSS / 腾讯云 COS 因路径式地址报 403）、@mercutiojohn（#8547，找准了 Gemini CLI 供应商获取模型列表失败的三个原因）。

感谢 @chencyan364、@DemosHume、@LAN-SHH、@mouse8867、@leafsnow、@zhuqiang1248、@ramonmi、@zx2121651、@VICCC-0x90 提出需求、报告问题和提供复现信息。

完整的技术细节请见 CHANGELOG。
