interrupteur cc v4.0.36

#Commutateur CC v4.0.36 Cette version ajoute une page plug-in, qui vous permet d'installer, d'activer, de mettre à jour et de désinstaller des plug-ins pour Claude Code, Codex, Grok Build, MiniMax Code, OpenClaw et Pi dans CC Switch, et de gérer le marché des plug-ins pour Claude Code, Codex et Grok Build. Les entrepôts de compétences peuvent désormais lire les entrepôts privés avec des jetons d'accès ; les fournisseurs acheminés localement peuvent fixer des multiplicateurs de frais ; et les chapitres du bureau Claude Code peuvent être consultés dans la gestion de session. De plus, nous avons résolu des problèmes tels que le blocage de l'approbation automatique après l'ouverture par le Codex de la protection officielle des quotas ; les modèles officiels nouvellement publiés en mode agrégation du Codex mettent beaucoup de temps à apparaître ; l'utilisation des sessions 1.x n'est plus comptabilisée après la mise à niveau d'OpenCode vers 2.x ; la date personnalisée sur la page d'utilisation passe à 1905 dès que l'année est saisie ; plusieurs modèles Antigravity sont affichés comme des problèmes sans prix et autres. Les niveaux d'inférence ayant le même prix dans les statistiques d'utilisation sont désormais fusionnés en une seule ligne. Anglais → | Version japonaise →

Ajouter

Page du plug-in

Ajoutez des « plug-ins » à la barre latérale et gérez les plug-ins via la propre ligne de commande de chaque application (pour les exigences, voir #791, #9220) :

  • Prend en charge Claude Code, Codex, Grok Build, MiniMax Code, OpenClaw, Pi et répertorie uniquement les applications non masquées.
  • Vous pouvez activer, désactiver, mettre à jour (le code MiniMax ne peut pas être mis à jour) et désinstaller dans « Installé » ; recherchez et installez dans « Découvrir » ; Claude Code, Codex et Grok Build peuvent également ajouter, actualiser et supprimer le plug-in market dans le « Market ». L'adresse peut être owner/repo ou GitHub, une adresse Git ou un dossier local. Les plugins pour Pi proviennent du package Pi sur npm.
  • Avant l'installation, Grok Build, OpenClaw et Pi confirmeront que les plug-ins s'exécutent avec vos autorisations et installeront uniquement ceux provenant de sources fiables. Pour les plug-ins dans Claude Code qui nécessitent un consentement sur le terminal, CC Switch ne sera pas d'accord pour vous et vous demandera d'exécuter la commande d'installation correspondante sur le terminal ; les applications qui nécessitent d’abord une connexion demanderont également des commandes de connexion.
  • Codex désactive le plug-in et modifie uniquement le enabled du plug-in en config.toml, laissant le reste du contenu et des commentaires inchangés.
  • Le téléchargement d'un grand entrepôt de marché peut prendre plusieurs minutes. Vous pouvez d'abord fermer la boîte de dialogue et vous serez invité lorsqu'elle sera terminée.

L'entrepôt de compétences prend en charge les entrepôts privés

Dans le « Management Skills Warehouse », vous pouvez définir des jetons d'accès par site. Les entrepôts privés sur GitHub, GitLab et Gitea/Forgejo peuvent parcourir, installer et rechercher des mises à jour (pour les exigences, voir #9666).

  • Les jetons sont enregistrés par site (tels que github.com, gitlab.example.com), stockés dans le stockage des informations d'identification du système (porte-clés macOS, Windows Credential Manager, les autres systèmes sont des fichiers lisibles uniquement par la machine locale) et ne sont pas synchronisés avec le cloud. Seule une autorisation en lecture seule est requise.
  • Lorsque le téléchargement échoue, il sera distingué si le token n'est pas défini ou si le token est rejeté (invalide, expiré ou non autorisé à lire cet entrepôt).

Taux de dépenses des fournisseurs

Lorsque les transferts sont facturés sur la base de remises, les coûts dans les statistiques d'utilisation peuvent être estimés sur la base de multiples (#9656). Un nouveau « multiplicateur de coût fournisseur » a été ajouté aux formulaires de fournisseur non officiels de Claude Code, Codex, Gemini CLI et Grok Build : les prix de référence de tous les modèles de cette société sont multipliés par celui-ci, 0.5 est à moitié prix et laisser vide est 1 fois.

  • Ne prend effet que pour les requêtes acheminées localement et définies après la configuration ; l'utilisation importée à partir des enregistrements de session lors d'une connexion directe est toujours comptée pour 1x.

Afficher les chapitres de la version bureau de Claude Code dans la gestion des sessions

Les chapitres attribués aux dialogues par les modèles dans la version de bureau de Claude Code étaient auparavant affichés sous forme d'appels d'outils MCP ordinaires (voir #9728, #9729 pour les exigences). Il est désormais affiché sous forme de ligne de chapitre, visible même lorsque la chronologie est fermée ; les chapitres seront répertoriés dans le répertoire de conversation et sauteront lorsque vous cliquerez dessus ; les chapitres peuvent être trouvés par recherche et les chapitres deviendront des titres lors de l'exportation vers Markdown.

Changement

  • Les statistiques d'utilisation fusionnent les engrenages d'inférence avec le même prix (#8845, voir #9065) : différentes forces d'inférence du même modèle, si les quatre prix d'entrée, de sortie, de lecture du cache et d'écriture du cache sont les mêmes que ceux du modèle de base et que le modèle de base a des prix précis, ils seront fusionnés dans la ligne du modèle de base. Le filtrage, le résumé quotidien et le temps du premier mot sont tous calculés en fonction de la fusion, et le nom du modèle d'origine est toujours affiché dans le journal des demandes.

Correction

  • Après que le Codex a activé la « Protection par quota officiel », l'approbation automatique a été bloquée lorsque le seuil a été atteint (#9733, voir #9732) : OpenAI a rendu le modèle d'approbation automatique du Codex codex-auto-review gratuit et non inclus dans le quota de package. Désormais, la protection par quota le permet directement, et les autres modèles officiels sont suspendus comme d'habitude.
  • En mode agrégation du Codex, les modèles officiels nouvellement publiés (tels que GPT-6.2) mettent beaucoup de temps à apparaître : En mode agrégation, Codex lit uniquement le répertoire des modèles écrit par CC Switch. Le cache de la liste officielle des modèles a été réduit de 6 heures à 1 heure ; la version du Codex lors de l'obtention de la liste fera également référence au CLI fourni avec la version de bureau et à la version enregistrée par le Codex lui-même. Une fois la version de bureau automatiquement mise à jour, elle ne recevra plus une liste plus courte basée sur l'ancienne version.
  • Après la mise à niveau d'OpenCode vers 2.x, les sessions créées ou poursuivies dans 1.x ne seront pas prises en compte dans l'utilisation (#8363, voir #8361) : lorsque l'ancien et le nouveau ensemble de données coexistent, les deux ensembles sont désormais lus et le même message n'est compté qu'une seule fois. Les bases de données précédemment analysées continuent à partir de la dernière analyse et ne reconstituent pas les enregistrements précédents.
  • Lorsque vous saisissez manuellement l'année dans la date personnalisée sur la page d'utilisation, elle devient 1905 (voir #9699) : Désormais, la date complète prendra effet et ne sera pas écrasée pendant le processus de saisie.
  • Plusieurs modèles Antigravity affichent « sans prix » dans les statistiques d'utilisation : la version hiérarchisée de Gemini Flash (telle que gemini-3.8-flash-tiered pour le sous-agent de navigateur intégré) est facturée au prix de base de Flash (#9600) ; La version hiérarchisée d'Hydrogen est facturée au prix de base (#9706, voir #9705) ; l'étape d'exécution lors de l'utilisation d'Orchestrator est renvoyée à Gemini 4 Hydrogen (#9686, voir #9685), l'étape de planification est renvoyée à Gemini 4 Neon et son prix est ajouté (#8845) ; La version Thinking de Claude (telle que Claude Opus 4.6 (Pensée)) est facturée selon le modèle de base correspondant. Les enregistrements existants non tarifés seront automatiquement compensés.
  • La liste des modèles en mode de routage Claude Desktop est laissée vide, et le nom du modèle Claude par défaut est utilisé à la place du modèle du fournisseur (voir #9735) : le mode de routage est à l'origine comme ceci, et l'invite du formulaire est maintenant clairement écrite : le laisser vide en connexion directe lira automatiquement /v1/models. Pour utiliser le modèle du fournisseur en mode routage, merci de remplir la liste des modèles.
  • Le MCP dans le cordis.patch.yml au niveau de la maison de DeepSeek Harness n'est pas visible dans CC Switch, et il n'y a aucune explication (voir #9714) : CC Switch lit et écrit uniquement les fichiers de chaque profil. La boîte de dialogue d'importation MCP indique désormais que les fichiers au niveau de la maison ne sont ni lus ni écrits et que le MCP qu'ils contiennent doit y être géré.

cc-switch v4.0.36

Highlights

  • Plugins move into the sidebar — A new Plugins page manages Claude Code, Codex, Grok Build, MiniMax Code, OpenClaw, and Pi by driving each app's own CLI rather than reimplementing plugin logic (#791, #9220). For adopters: install/update/uninstall plus marketplace add/refresh/remove for the first three; Pi installs come from npm; MiniMax Code cannot be updated. It is deliberately not hands-off — Grok/OpenClaw/Pi prompt before install because plugins run with your privileges, Claude Code plugins needing terminal consent are handed back to you, and login-required apps surface the login command. Two details worth knowing: disabling a Codex plugin only flips its enabled flag in config.toml and leaves all other content and comments intact (safe for config management), and large marketplace clones can take minutes, with a notification on completion.

  • Private skill repos unblocked via per-site tokens — Skill repositories now accept access tokens to browse, install, and check updates on private GitHub, GitLab, and Gitea/Forgejo repos (#9666). Tokens are scoped per host (github.com, gitlab.example.com), need only read access, and live in the OS credential store (Keychain, Windows Credential Manager, or a local user-readable file elsewhere) — critically, they do not cloud-sync, so each machine must be configured separately. Download failures now distinguish "no token set" from "token rejected" (invalid/expired/no access), turning an opaque 404 into an actionable error.

  • Cost reporting: multiplier in, tier granularity out — Non-official provider forms for Claude Code, Codex, Gemini CLI, and Grok Build gain a "provider cost multiplier" (#9656): 0.5 halves reference prices, blank means 1×, useful when a reseller bills at a discount. Scope matters — it applies only to requests routed through the local proxy after you set it; imported/direct sessions still count at 1×, so historical spend is not retroactively discounted. Separately, reasoning tiers sharing all four prices (input/output/cache read/cache write) with an exactly-priced base model now collapse into that base row (#8845, #9065); filters, daily totals, and first-token timings use the merged data while request logs keep the original model name — fewer rows, not lost detail. Antigravity pricing gaps also close (Flash/Hydrogen tiered, Orchestrator execution→Hydrogen and planning→Neon with a new price, Claude Thinking→base) with existing unpriced records recalculated (#9600, #9706, #9685, #8845) — so past spend figures may rise.

  • Usage fixes for mixed or upgraded installs — OpenCode 2.x users with leftover 1.x sessions now count usage from both databases with per-message dedup (#8363, #8361); note that previously scanned DBs resume from the last scan and older messages are not backfilled. With Codex "official quota protection" on, the now-free codex-auto-review model bypasses the pause (#9733, #9732) while other official models still pause. In Codex aggregation mode the official-model cache drops from 6h to 1h and version detection now consults the bundled/desktop CLI, so newly released models (e.g. GPT-6.2) stop lagging behind auto-updates.

  • Claude Code Desktop chapters become first-class — Model-generated chapter markers, previously rendered as generic MCP tool calls, now appear as chapter rows (#9728, #9729): visible even with the timeline collapsed, listed in the session directory with click-to-jump, searchable, and exported as Markdown headings. A small but real quality-of-life win for navigating long Desktop sessions.

  • Breaking changes — None; no migration steps required.

CC Switch v4.0.36

本版本新增插件页面，可以在 CC Switch 里安装、启用、更新、卸载 Claude Code、Codex、Grok Build、MiniMax Code、OpenClaw、Pi 的插件，并管理 Claude Code、Codex、Grok Build 的插件市场。技能仓库现在可以用访问令牌读取私有仓库；经本地路由的供应商可以设置费用倍率；会话管理里能看到 Claude Code 桌面版的章节。

另外修复了 Codex 开了官方额度保护后自动审批也被拦下；Codex 聚合模式下新发布的官方模型要很久才出现；OpenCode 升级到 2.x 后 1.x 会话的用量不再统计；用量页自定义日期一输入年份就变成 1905；Antigravity 多个模型显示未定价等问题。用量统计里价格相同的推理档位现在合并成一行。

新增

插件页面

侧栏新增「插件」，通过各应用自己的命令行管理插件（需求见 #791，#9220）：

  • 支持 Claude Code、Codex、Grok Build、MiniMax Code、OpenClaw、Pi，只列出没有隐藏的应用。
  • 「已安装」里可以启用、停用、更新（MiniMax Code 不能更新）、卸载；「发现」里搜索并安装；Claude Code、Codex、Grok Build 还可以在「市场」里添加、刷新、移除插件市场，地址可以是 GitHub 的 owner/repo、Git 地址或本地文件夹。Pi 的插件来自 npm 上的 Pi 包。
  • Grok Build、OpenClaw、Pi 安装前会先确认：插件以你的权限运行，只装来源可信的。Claude Code 里要在终端同意的插件，CC Switch 不替你同意，会提示到终端运行对应的安装命令；需要先登录的应用也会提示登录命令。
  • Codex 停用插件只改 config.toml 里这个插件的 enabled，其余内容和注释不动。
  • 大的市场仓库下载可能要几分钟，可以先关掉对话框，完成后会提示。

技能仓库支持私有仓库

「管理技能仓库」里可以按站点设置访问令牌，GitHub、GitLab、Gitea / Forgejo 上的私有仓库都能浏览、安装和检查更新（需求见 #9666）。

  • 令牌按站点保存（如 github.com、gitlab.example.com），存在系统的凭据存储里（macOS 钥匙串、Windows 凭据管理器，其他系统是本机仅自己可读的文件），不随云同步。只需要只读权限。
  • 下载失败时会区分是没设令牌，还是令牌被拒（无效、过期或无权读取这个仓库）。

供应商费用倍率

中转按折扣计费时，用量统计里的花费可以按倍率估算（#9656）。Claude Code、Codex、Gemini CLI、Grok Build 的非官方供应商表单里新增「供应商费用倍率」：这家所有模型的参考价都乘以它，0.5 即半价，留空为 1 倍。

  • 只对经本地路由、并且设置之后的请求生效；直连时从会话记录导入的用量仍按 1 倍统计。

会话管理里显示 Claude Code 桌面版的章节

Claude Code 桌面版里模型给对话打的章节，以前显示成普通的 MCP 工具调用（需求见 #9728，#9729）。现在显示成章节行，收起时间线也能看到；对话目录里会列出章节，点击即跳转；查找能搜到章节，导出 Markdown 时章节变成标题。

变更

  • 用量统计合并价格相同的推理档位（#8845，见 #9065）：同一个模型的不同推理强度，如果输入、输出、缓存读、缓存写四种价格都和基础模型相同，并且基础模型有精确价格，就合并到基础模型那一行。筛选、每日汇总和首字时间都按合并后统计，请求日志里仍显示原始模型名。

修复

  • Codex 开了「官方额度保护」后，达到阈值时自动审批也被拦下（#9733，见 #9732）：OpenAI 已经让 Codex 的自动审批模型 codex-auto-review 免费、不计入套餐额度，现在额度保护对它直接放行，其他官方模型照常暂停。
  • Codex 聚合模式下，新发布的官方模型（如 GPT-6.2）要很久才出现：聚合模式下 Codex 只读 CC Switch 写的模型目录。官方模型列表的缓存从 6 小时缩短到 1 小时；获取列表时报的 Codex 版本也会参考桌面版自带的 CLI 和 Codex 自己记录的版本，桌面版自动更新后不会再按旧版本拿到少一截的列表。
  • OpenCode 升级到 2.x 后，之后在 1.x 里新建或继续的会话不计入用量（#8363，见 #8361）：新旧两套数据并存时现在两套都读，同一条消息只算一次。以前扫描过的数据库从上次扫描处继续，不回补更早的记录。
  • 用量页自定义日期手动输入年份时，一输入就变成 1905（见 #9699）：现在输入完整的日期才生效，输入过程中不会被改写。
  • Antigravity 多个模型在用量统计里显示「未定价」：Gemini Flash 的 tiered 版本（如内置浏览器子代理用的 gemini-3.8-flash-tiered）按 Flash 基础价计费（#9600）；Hydrogen 的 tiered 版本按基础价计费（#9706，见 #9705）；用 Orchestrator 时的执行步归到 Gemini 4 Hydrogen（#9686，见 #9685），规划步归到 Gemini 4 Neon 并新增它的价格（#8845）；Claude 的 Thinking 版本（如 Claude Opus 4.6 (Thinking)）按对应的基础模型计费。已有的未定价记录会自动补算。
  • Claude Desktop 路由模式下模型列表留空，用的是默认的 Claude 模型名而不是供应商的模型（见 #9735）：路由模式本来如此，表单提示现在写清楚了：直连时留空会自动读取 /v1/models，路由模式下要用供应商的模型请填写模型列表。
  • DeepSeek Harness 的 home 级 cordis.patch.yml 里的 MCP 在 CC Switch 里看不到，也没有说明（见 #9714）：CC Switch 只读写各 profile 的文件，MCP 导入对话框现在写明 home 级文件既不读也不写，其中的 MCP 请在那里管理。
