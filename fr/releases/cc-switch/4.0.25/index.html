interrupteur cc v4.0.25

#Commutateur CC v4.0.25 Cette version ajoute une vérification de connectivité à la page MCP, qui permet de vérifier en un clic si tous les serveurs MCP activés peuvent être connectés ; lorsque le Codex utilise le compte officiel via un routage local, la demande officielle peut être automatiquement suspendue avant que le quota ne soit presque épuisé et des modèles tiers sont toujours disponibles. De plus, le taux de change sur la page d'utilisation peut être obtenu automatiquement et le formulaire du fournisseur Codex peut définir la limite de simultanéité des sous-agents. Lorsque Claude Code et Claude Desktop sont routés ou agrégés, le menu modèle indiquera de quel fournisseur provient chaque modèle et de quel modèle il s'agit réellement. Les sessions Kimi Code peuvent également être supprimées dans la gestion des sessions. Il a également résolu des problèmes tels que le "terminal ouvert" mélangeant les paramètres de routage et d'agrégation, des fournisseurs tels qu'OpenCode Go en mode routage demandant à Claude Code de se reconnecter, des erreurs signalées à chaque fois après l'envoi d'un fichier à un modèle en texte brut, le contenu du formulaire du fournisseur sous Windows clignotant d'avant en arrière, le panneau de la barre d'état ne s'ouvrant pas au démarrage et l'utilisation étant comptée deux fois lorsque Codex utilise le mappage de modèle. Pour le contenu complet de la mise à jour de 4.0, veuillez consulter les [Notes de version de v4.0] (https://github.com/farion1231/cc-switch/blob/main/docs/release-notes/v4.0.4-zh.md). Ajouter

Vérification de la connectivité MCP

Dans le passé, une fois le serveur MCP configuré, on ne savait s'il pouvait être connecté que lorsqu'il était utilisé dans l'outil de programmation (#4498). Il y a désormais un bouton « Vérifier la connectivité » en haut de la page MCP, qui vérifiera tous les serveurs activés ; il y a aussi un "Test Connexion" dans le menu de chaque ligne, et seul celui-ci sera vérifié.

  • Il ne sera pas automatiquement coché à l'ouverture de la page, et "non coché" s'affichera s'il n'a pas été coché ; après avoir modifié la configuration de connexion d'un certain serveur, ses résultats seront réinitialisés.
  • La méthode de vérification consiste à effectuer une négociation MCP avec le serveur, et les trois méthodes de connexion, commande locale (stdio), HTTP et ancienne version SSE, sont prises en charge. Attendez jusqu'à 30 secondes par serveur et l'ensemble de l'application peut en vérifier jusqu'à 3 simultanément.
  • Une fois le serveur démarré par la commande locale vérifié, il se terminera avec le processus enfant qu'il a démarré et aucun processus en arrière-plan ne sera laissé. Des commandes telles que npx et uvx peuvent également être trouvées sur macOS et Linux lorsque CC Switch n'est pas lancé depuis le terminal.

Protection par quotas officiels du Codex

Lorsque le Codex utilise le compte officiel ChatGPT, il entrera en mode Réserve lorsque le quota de cinq heures ou hebdomadaire sera épuisé. Vous pouvez désormais suspendre les demandes officielles lorsque le quota est presque épuisé, en laissant le quota, et les modèles tiers peuvent toujours être utilisés comme d'habitude. Activez « Protection des quotas officiels » dans « Paramètres → Configuration de l'application → Amélioration de l'application Codex », vous pouvez définir des seuils d'utilisation de cinq heures et hebdomadaires (95 % et 98 % par défaut) et suspendre les nouvelles demandes officielles lorsque l'un ou l'autre est atteint.

  • Ne prend effet que pour les demandes officielles du Codex acheminées localement via CC Switch et est désactivé par défaut.
  • Le taux d'utilisation lit directement les informations de quota incluses dans la réponse officielle. Plusieurs requêtes ne seront pas envoyées lors d’une utilisation normale ; il sera interrogé séparément seulement après avoir commencé à être utilisé ou après avoir été inactif pendant environ 5 minutes.
  • Si le quota est introuvable (problèmes de réseau, expiration de connexion, etc.), le système sera libéré comme d'habitude et il n'y aura pas de mauvais blocage. Les demandes suspendues renverront directement des erreurs et ne seront pas transférées aux autres fournisseurs dans la file d'attente de basculement.

Obtenez automatiquement le taux de change sur la page d'utilisation

La zone « Affichage » dans les « Paramètres d'utilisation » sur la page d'utilisation comporte une « Source de taux de change ». Vous pouvez choisir « Remplissage manuel » (par défaut) ou « Obtention automatique ». Ce n'est que lorsque la récupération automatique est sélectionnée que le réseau sera connecté. Le taux de change sera mis à jour automatiquement s'il dépasse 12 heures. Si la récupération échoue, le dernier taux de change continuera à être utilisé. Le taux de change obtenu automatiquement et celui rempli manuellement sont enregistrés séparément. Lorsque vous reviendrez au remplissage manuel, la valeur que vous avez renseignée sera toujours là. Les frais sont toujours enregistrés en dollars américains et ne sont convertis que lorsqu'ils sont indiqués.

Limite de simultanéité des sous-agents du Codex

Il existe une « Limite de concurrence des sous-agents » sous le « Modèle de sous-agent » dans le formulaire du fournisseur Codex, qui définit le nombre maximum de sous-agents pouvant être ouverts simultanément dans une session Codex (#9055). C'est le cadre global du Codex. [agents] max_threads écrit dans config.toml restera inchangé lors du changement de fournisseur, et pourra également être modifié sur la carte officielle ; si laissé vide, la valeur par défaut du Codex sera utilisée.

Le menu Modèle indique le fournisseur et le modèle réel

Claude Code En mode routage, chaque fichier du menu /model ne lisait que "Modèle Sonnet personnalisé", et il était impossible de savoir quel modèle correspondait à quel fournisseur. Elle s'écrira désormais « Fournisseur · Modèle réel · Fenêtre » (la fenêtre ne s'affiche que lorsque le curseur est à 1M vers le haut), et il en va de même pour les modèles en mode agrégation. Si le fournisseur a rédigé lui-même la description du modèle, celle que vous avez rédigée prévaudra. Claude Desktop Dans les modes de routage et d'agrégation, la description en dessous du modèle permettait d'appliquer la copie officielle selon Opus et Sonnet dans le nom, et le modèle d'agrégation affichait toujours la même phrase. Maintenant, remplacez-le également par "Fournisseur·Modèle réel·Fenêtre".

Supprimer la session Kimi Code

Les sessions Kimi Code peuvent être supprimées directement dans la gestion des sessions. Dans le passé, ils ne pouvaient être supprimés que dans Kimi Code. La méthode de suppression est la même que celle de Kimi Code, et l'historique du sous-agent sera supprimé ensemble. Prix : Ajout du GPT-6.1 Terra à la liste de prix intégrée.

Changement

  • Le routage local n'accepte plus les requêtes des pages Web. La route locale remplacera la demande par les informations d'identification de votre fournisseur enregistrées, puis la transmettra. Ainsi, si la page Web peut envoyer la demande à la route locale, elle peut utiliser votre quota. Les requêtes avec une balise d'origine du navigateur seront désormais rejetées et l'accès à cette machine via un nom de domaine commun ne sera plus accepté. Les requêtes envoyées par les outils de programmation ne sont pas affectées.
  • La barre d'outils de la page "Découvrir" de Skills est alignée avec la page "Installé" (#9125) : La position et la largeur du champ de recherche sont cohérentes, le bouton d'actualisation est remplacé par le bouton de texte "Actualiser l'entrepôt", la source, le filtre de l'entrepôt et "Voir uniquement les éléments désinstallés" sont déplacés vers l'en-tête et "Installer dans" est placé sur le côté droit de l'en-tête. Il manque une ligne, mais la fonctionnalité reste la même.
  • Lorsque le terminal préféré sous Windows est PowerShell, si PowerShell 7 est installé, utilisez-le pour ouvrir (#8992, #3271). Sinon, utilisez Windows PowerShell fourni avec le système. C'est le cas de « l'ouverture du terminal » de la carte fournisseur et de l'installation et de la mise à niveau des applications.
  • Par défaut : Le paiement à l'utilisation et le plan de jetons de Qianwen AI Platform et QwenCloud sont remplacés par le nouveau nom de domaine MaaS, et le plan de codage reste inchangé.

Désormais, seuls les paramètres propres à cette carte sont utilisés dans le terminal et vos autres paramètres globaux sont conservés comme d'habitude.

Si vous sélectionnez « Non » par défaut, vous n'êtes pas connecté (#8111, #8104). Désormais en mode routage, les informations d'identification fictives sont toujours écrites dans ANTHROPIC_AUTH_TOKEN et les requêtes envoyées en amont restent inchangées.

Désormais, lors de l'envoi vers un modèle de texte brut via le routage, les fichiers et l'audio de la conversation seront remplacés par une description textuelle ; le rapport d'erreur chinois de GLM peut également être reconnu. Le traitement des images reste inchangé.
  • Les noms et autres contenus du formulaire fournisseur sous Windows clignotent d'avant en arrière (#6420, #6349). Il s'agit du remplissage automatique de WebView2 superposant le contenu du formulaire, désormais désactivé pour la fenêtre principale.
  • Le panneau du plateau ne peut pas être ouvert et ne peut pas être quitté du plateau pendant un certain temps après le démarrage (#9154). L'utilisation de la session importée occupera la base de données au démarrage et le panneau de la barre d'état devra attendre les données. Maintenant, le panneau apparaîtra en premier, « Ouvrir la fenêtre principale » et « Quitter » seront disponibles immédiatement, et la liste sera ensuite chargée.
  • Lorsque Codex utilise le mappage de modèles via le routage, l'utilisation de la même requête est comptée deux fois (#7643, #5526). Ce qui est enregistré dans le journal de session est le nom du modèle utilisé par Codex, et ce qui est enregistré dans le routage est le nom du modèle mappé, qui ne peut pas être mis en correspondance lors de la déduplication. Désormais, les deux camps peuvent s’affronter.
  • Le quota utilisé par le sous-agent dans l'exemple officiel Pi n'est pas inclus dans les statistiques (#8386, #8340). Désormais, il sera enregistré séparément selon le fournisseur et le modèle de chaque sous-agent. Après la mise à niveau, la session Pi précédente sera relue et reconstituée.
  • Lors de l'importation de MCP depuis Pi, les serveurs non pris en charge par Pi ont également été importés et activés, et chaque synchronisation ultérieure a échoué (#7888). Les serveurs avec des méthodes de connexion SSE, des noms non conformes et des serveurs dont les noms sont uniquement différents de - et _ seront désormais ignorés et invités ; le fichier de configuration MCP de Pi ne sera plus créé lorsque Pi n'est pas installé.
  • Lorsque seul l'agent est configuré dans le terminal ou le commutateur CC et qu'aucun agent système n'est configuré, la synchronisation des prix de models.dev continue d'échouer (#8739, #6696). Il est maintenant téléchargé par CC Switch en arrière-plan et l'agent que vous avez défini sera utilisé ; il en va de même pour l'importation des prix des modèles et le remplissage automatique des paramètres du modèle dans le formulaire.
  • Lorsque Claude Code se connecte à xAI via un routeur, la demande de recherche forcée du réseau est rejetée par xAI et rapporte 422 (#8664).
  • MiniMax M3.1 Flash Thinking Gears in Pi (#8540) : Les deux préréglages officiels MiniMax suppriment "Off" et "Minimum" qui ne sont pas acceptés par ce modèle, et les engrenages restants sont envoyés comme d'habitude.

cc-switch v4.0.25

Highlights

  • MCP connectivity checks — The MCP page gains a "check connectivity" button that handshakes every enabled server (stdio, HTTP, and legacy SSE), with a 30s per-server timeout and a cap of three concurrent checks; each row also gets a "test connection" for a single server. This matters because previously you only found out a server was dead when a coding tool actually tried to use it (#4498). Watch out: results are lazy, not live — nothing is checked on page open, and editing a server's connection config resets its status, so a green result is a point-in-time signal.

  • Codex official quota protection — Opt-in under Settings → App Config → Codex App Enhancements: once 5-hour or weekly usage on an official ChatGPT account crosses a threshold (95%/98% by default), new official requests are paused while third-party models keep working. It applies only to official requests through CC Switch's local router, reads quota data already in responses (no extra calls in steady state), and fails open if quota can't be read. Important behavioral caveat: paused requests return an error outright rather than falling through to your failover queue — plan for a hard stop, not a graceful handoff.

  • Breaking: local router rejects web-origin requests — Requests carrying a browser origin marker, and access to the local router via a normal domain pointing at localhost, are now refused; coding-tool traffic is unaffected. This closes a hole where any web page could spend your stored provider credentials (reported responsibly by @yukitakasama). If you had a custom web UI or dashboard calling the local router, that integration will break and needs to move to a non-browser client.

  • Model menus show provider and actual model — Claude Code's /model menu in route mode, and Claude Desktop in route/aggregate mode, now label entries as "provider · actual model · window" (window only when 1M is in play), replacing the generic "Custom Sonnet model" and name-based Opus/Sonnet guesses. Custom descriptions you set on a provider take precedence. This is a genuine debugging win for tracing which upstream a request hit — especially paired with the auth fix below.

  • Usage accounting fixes — Two long-standing billing bugs are resolved: Codex requests using model mapping were double-counted because session logs and router logs disagreed on the model name (#7643, #5526), and Pi official-example subagent usage was omitted entirely (#8386, #8340). On upgrade, past Pi sessions are re-read to backfill missing usage. Also in route mode, placeholder credentials now go into ANTHROPIC_AUTH_TOKEN instead of ANTHROPIC_API_KEY, fixing Claude Code prompting for a custom key and ending up logged out after choosing "no" (#8111, #8104) — upstream requests are unchanged.

  • Subagent concurrency and exchange rates — Codex provider forms gain a "subagent concurrency limit" that writes [agents] max_threads into config.toml; it's a global setting that survives provider switches (also editable on the official card), and blank means the Codex default (#9055). The usage page can now auto-fetch exchange rates (12h refresh, falls back to the last known rate, stored separately from manual entries), and Kimi Code sessions can finally be deleted from session management, including subagent history.

新增

MCP 连通性检查

以前 MCP 服务器配好以后，只有在编程工具里用到时才知道能不能连上（#4498）。

现在 MCP 页面顶部多了「检查连通性」按钮，会检查所有已启用的服务器；每一行的菜单里也有「测试连接」，只检查这一个。

  • 打开页面时不会自动检查，没检查过的显示「未检查」；改了某个服务器的连接配置后，它的结果会重置。
  • 检查方式是和服务器完成一次 MCP 握手，本地命令（stdio）、HTTP 和旧版 SSE 三种连接方式都支持。每个服务器最多等 30 秒，整个应用同时最多检查 3 个。
  • 本地命令启动的服务器检查完会连同它启动的子进程一起结束，不会留下后台进程。macOS 和 Linux 上不从终端启动 CC Switch 时，也能找到 npx、uvx 这类命令。

Codex 官方额度保护

Codex 用官方 ChatGPT 账号时，五小时或每周额度用完会进入 Reserve 模式。现在可以在额度快用完时先暂停官方请求，留着额度，第三方模型照常可用。

在「设置 → 应用配置 → Codex 应用增强」里打开「官方额度保护」，可以设置五小时和每周使用率的阈值（默认 95% 和 98%），任一达到就暂停新的官方请求。

  • 只对经过 CC Switch 本地路由的 Codex 官方请求生效，默认关闭。
  • 使用率直接读官方响应里自带的额度信息，正常使用时不会多发请求；刚开始用或空闲约 5 分钟后，才会先单独查询一次。
  • 查不到额度（网络问题、登录过期等）时照常放行，不会误挡。被暂停的请求会直接返回错误，不会转到故障转移队列里的其他供应商。

用量页汇率自动获取

用量页「用量设置」里的「显示」区多了「汇率来源」，可以选「手动填写」（默认）或「自动获取」。选了自动获取才会联网，汇率超过 12 小时会自动更新，获取失败时继续用上次的汇率。自动获取的汇率和手动填的分开保存，切回手动填写时你自己填的值还在。费用仍按美元记录，只在显示时换算。

Codex 子代理并发上限

Codex 供应商表单的「子代理模型」下面多了「子代理并发上限」，设置一个 Codex 会话里最多同时开多少个子代理（#9055）。这是 Codex 的全局设置，写进 config.toml 的 [agents] max_threads，切换供应商时保持不变，官方卡片上也能改；留空就用 Codex 的默认值。

模型菜单写明供应商和实际模型

Claude Code 在路由模式下，/model 菜单里每一档以前只写「Custom Sonnet model」，看不出对应哪家供应商的哪个模型。现在会写成「供应商 · 实际模型 · 窗口」（窗口只在上游标了 1M 时显示），聚合模式下的模型也一样。供应商里自己写过模型说明的，以你写的为准。

Claude Desktop 在路由和聚合模式下，模型下面的说明以前按名字里的 Opus、Sonnet 套用官方文案，聚合模型一律显示同一句。现在也改成「供应商 · 实际模型 · 窗口」。

删除 Kimi Code 会话

会话管理里可以直接删除 Kimi Code 会话了，以前只能去 Kimi Code 里删。删除方式和 Kimi Code 自己的一样，子代理的历史会一起删掉。

变更

  • 本地路由不再接受网页发来的请求。本地路由会把请求换成你保存的供应商凭据再转发，所以网页如果能把请求发到本地路由，就能用掉你的额度。现在带浏览器来源标记的请求会被拒绝，通过普通域名指向本机的访问也不再接受。编程工具发的请求不受影响。
  • Skills「发现」页的工具栏和「已安装」页对齐（#9125）：搜索框位置和宽度一致，刷新按钮改为「刷新仓库」文字按钮，来源、仓库筛选和「只看未安装」挪进表头，「安装到」放在表头右侧。少了一行，功能不变。
  • Windows 上首选终端是 PowerShell 时，装了 PowerShell 7 就用它打开（#8992、#3271），没装才用系统自带的 Windows PowerShell。供应商卡片的「打开终端」和应用的安装、升级都是这样。
  • 预设： 千问 AI 平台和 QwenCloud 的按量付费、Token Plan 改用新的 MaaS 域名，Coding Plan 不变。

修复

  • 在路由或聚合模式下，Claude Code 卡片的「打开终端」混入了路由和聚合的设置。终端里的 Claude Code 会同时带上路由的占位凭据和这张卡片的 Key，这张卡片没配的模型档位会用上聚合里的模型名，发到这张卡片的地址上用不了；/model 菜单里也会出现其他供应商的模型。现在终端里只用这张卡片自己的设置，你的其他全局设置照常保留。
  • 路由模式下，OpenCode Go 等用 ANTHROPIC_API_KEY 存 Key 的供应商会让 Claude Code 要求确认自定义 Key，默认选「否」后就是未登录（#8111、#8104）。现在路由模式下占位凭据一律写进 ANTHROPIC_AUTH_TOKEN，发给上游的请求不变。
  • 给纯文本模型发过一个文件或音频后，之后每一轮都报 400（#6274、#6151）。现在经路由发给纯文本模型时，对话里的文件和音频会换成一段文字说明；智谱 GLM 的中文报错也能认出来。图片的处理不变。
  • Windows 上供应商表单里的名称等内容来回闪（#6420、#6349）。这是 WebView2 的自动填充在覆盖表单内容，现在已对主窗口关掉。
  • 启动后的一段时间里托盘面板打不开，也没法从托盘退出（#9154）。启动时导入会话用量会占着数据库，托盘面板要等数据。现在面板会先弹出，「打开主窗口」和「退出」马上能用，列表随后加载。
  • Codex 经路由用了模型映射时，同一个请求的用量被算两遍（#7643、#5526）。会话日志里记的是 Codex 用的模型名，路由记的是映射后的模型名，去重时对不上。现在两边能对上了。
  • Pi 官方示例的子代理用的额度没有统计进来（#8386、#8340）。现在会按每个子代理的供应商和模型分别记录，升级后会把以前的 Pi 会话重新读一遍补上。
  • 从 Pi 导入 MCP 时，Pi 不支持的服务器也被导入并启用，之后每次同步都失败（#7888）。SSE 连接方式、名字不合规、名字只差 - 和 _ 的服务器现在会跳过并提示；没装 Pi 时也不会再创建 Pi 的 MCP 配置文件。
  • 只在终端或 CC Switch 里设了代理、没设系统代理时，models.dev 价格同步一直失败（#8739、#6696）。现在改由 CC Switch 后台下载，会走你设的代理；导入模型价格和表单自动填模型参数也一样。
  • Claude Code 经路由连 xAI 时，强制联网搜索的请求被 xAI 拒绝，报 422（#8664）。
  • Pi 里的 MiniMax M3.1 Flash 思考档位（#8540）：两个 MiniMax 官方预设去掉了这个模型不接受的「关闭」和「最小」，其余档位照常发送。
