interrupteur cc v4.0.37

#Commutateur CC v4.0.37 Cette version est principalement destinée aux réparations. Les entrées de fournisseur et MCP illisibles (telles que celles écrites par les versions mises à jour et synchronisées via WebDAV/S3) ne sont plus traitées comme des configurations vides et écrasées par les valeurs par défaut lors de la prochaine sauvegarde, mais sont répertoriées séparément et peuvent être supprimées ; Pi a ajouté des préréglages Mistral AI ; La traduction de l'interface coréenne a été globalement améliorée. De plus, il a été corrigé que l'adresse d'écoute de routage local ne peut pas être démarrée lorsque IPv6 est renseigné ; "Appliquer au plug-in Claude Code" effacera l'intégralité du ~/.claude/config.json endommagé ; lorsque la vitesse du réseau est lente, le téléchargement d'un grand entrepôt de compétences est interrompu à mi-chemin ; lors de l'ouverture de CC Switch à partir du Finder, la détection du répertoire du modèle Codex ne peut pas trouver le nœud ; _ dans les paramètres d'appel de l'outil. Les champs en tête sont supprimés avant d'être envoyés en amont ; les fournisseurs qui sont supprimés et rajoutés à la file d'attente de basculement sont toujours ignorés ; le bouton "Réessayer" sur la page du plug-in semble ne pas répondre, ainsi que d'autres problèmes. Ajouter

Pi ajoute le préréglage Mistral AI

Pi a ajouté un nouveau préréglage Mistral AI, qui utilise le propre protocole Mistral de Pi (mistral-conversations), et le contenu de réflexion en streaming ne sera pas perdu (pour les exigences, voir #9343, #9344).

  • Livré avec Mistral Large 4 et Mistral Small 4, l'équipement de réflexion est cohérent avec le répertoire Mistral intégré du Pi.
  • Le nom du fournisseur est cc-switch-mistral, ce qui ne masque pas le mistral intégré au Pi.
  • mistral-conversations peut également être sélectionné dans la liste des protocoles du formulaire Pi. Oh My Pi et Kimi Code ne prennent pas en charge ce protocole et n'affichent pas cette valeur par défaut.

Changement

  • Les entrées fournisseur et MCP non lisibles sont conservées telles quelles et peuvent être supprimées individuellement (#9767) : Dans le passé, lorsque les données ne pouvaient pas être lues, elles étaient considérées comme une configuration vide. La valeur par défaut sera réécrite lors de la prochaine sauvegarde et les données d'origine seront perdues. Désormais, ces entrées sont répertoriées séparément sur la page du fournisseur et sur la page MCP, indiquant la raison pour laquelle elles ne peuvent pas être lues et ne peuvent pas être modifiées ou activées. Ils peuvent être supprimés (seuls les enregistrements dans CC Switch sont supprimés, et les fichiers de configuration de chaque application ne sont pas touchés) ; les autres entrées sont affichées et utilisées comme d'habitude, et le basculement les ignore ; l'opération pour changer celui-ci sera rejetée. Lorsqu'il existe de telles entrées, les applications cumulatives (telles que OpenCode) signaleront également une erreur lors de la synchronisation de tous les fournisseurs avec le fichier de configuration. Vous pouvez le restaurer après la mise à niveau vers une version lisible.
  • La marque 1M de Claude Code est réécrite en minuscule [1m] (voir #9757) : conforme à l'écriture du document Claude Code. Claude Code est à l'origine insensible à la casse et le [1M] existant peut toujours être utilisé.
  • Améliorations de la traduction de l'interface coréenne (#9395, #9349).
  • La ligne du compte dans le centre d'autorisation est plus lisible (#9369) : "N fournisseurs l'utilisent" dans une ligne séparée, et la colonne du nom du quota est définie en fonction du nom le plus long. Lorsque la fenêtre est étroite, le package, le nom de domaine et la date de connexion ne sont plus compressés dans des ellipses ; le pourcentage est également visible dans les traductions plus longues comme l’allemand et le russe.

Correction

  • Il ne peut pas être démarré lorsque l'adresse d'écoute de la route locale est remplie avec IPv6 (comme ::1) (voir #9743) : "une syntaxe d'adresse de socket invalide" était signalée auparavant, mais maintenant elle peut être surveillée normalement.
  • Après avoir activé "Appliquer au plug-in Claude Code", le ~/.claude/config.json endommagé sera effacé (voir #9744) : Lorsque le fichier n'est pas un JSON légal, il sera écrasé en tant que fichier vide et les autres paramètres qu'il contient seront perdus. Maintenant, une erreur sera signalée et le chemin du fichier sera indiqué, et le fichier restera inchangé ; l'écriture a également été modifiée pour écrire d'abord un fichier temporaire, puis le remplacer, de sorte que la moitié du fichier ne soit pas laissée en cas d'interruption à mi-chemin.
  • Les grands référentiels de compétences sont interrompus au milieu du téléchargement sur les connexions lentes : les compétences d'installation, de mise à jour, de vérification des mises à jour et de découverte limitaient auparavant le téléchargement complet à 60 secondes. Désormais, il ne s'arrêtera que si les données ne peuvent pas être reçues pendant 60 secondes consécutives, et il affichera le message « Aucune donnée reçue » ; l'intégralité du téléchargement peut prendre jusqu'à 10 minutes.
  • Lors de l'ouverture de CC Switch depuis le Finder, la détection du répertoire du modèle Codex ne peut pas trouver le nœud (voir #9764) : le Codex installé avec npm ne parvient donc pas à s'exécuter et CC Switch revient à CLI, qui est fourni avec la version de bureau du Codex et peut être plus ancien. Le modèle GPT en mode agrégation manque d'informations officielles (telles que les outils de recherche). Les sondes incluent désormais le PATH du shell de connexion, tout comme CC Switch lors de l'exécution d'autres outils de ligne de commande.
  • Les champs commençant par _ dans les paramètres d'appel de l'outil sont supprimés avant d'être envoyés en amont (#9753) : les champs tels que _id, _meta et __typename sont couramment utilisés dans les outils MCP, bases de données et GraphQL. Dans le passé, ils étaient supprimés en tant que champs privés. L'appel vu par le modèle est différent de l'exécution réelle. Les fournisseurs stricts peuvent directement rejeter la demande. Les paramètres d’appel d’outil restent désormais intacts.
  • Pour les fournisseurs qui sont supprimés de la file d'attente de basculement puis renvoyés, la carte s'affiche normalement mais sera toujours ignorée pendant un certain temps (#9750) : lorsqu'ils sont retirés de la file d'attente ou quittés du parcours d'une application, l'état du disjoncteur en cours d'exécution sera désormais effacé en même temps. Lors de l'ouverture d'OMO / OMO Slim, le fichier de configuration d'une autre variante n'a pas pu être supprimé et il sera désormais également demandé séparément.
  • Cliquer sur "Réessayer" après l'expiration du chargement de la page du plug-in semble ne pas répondre (Voir #9758) : les onglets installés, découverts et commercialisés afficheront tous le chargement lors d'une nouvelle tentative.
  • Plusieurs problèmes avec la page du plug-in (#9742) : Lors du passage à d'autres applications puis du retour en arrière, l'opération en cours affiche toujours un cercle ; il est réactivé lors de la mise à jour du plug-in Codex et ne sera pas désactivé une fois la mise à jour terminée ; la recherche peut également effectuer une recherche par nom d'affichage (packages Pi installés via git ou le répertoire local) ; après avoir désinstallé la version corrigée du package Pi puis l'avoir installé depuis « Discover », il ne reste plus dans « Discover » ; Windows est installé dans les plugins dans WSL et affiche désormais la version, le nom et la description.
  • Utilisation de la mémoire et des ressources (#9773) : Libérez les images mises en cache lorsque vous quittez le lecteur de session ; publier les packages d'installation téléchargés lors de la désactivation des mises à jour automatiques ; certaines requêtes réseau réutilisent les connexions HTTP et n'en créent plus de nouvelles à chaque fois ; la limite supérieure du corps de la requête (y compris la décompression) reçue par le routage local est de 200 Mio, et 413 seront renvoyés si elle dépasse.
  • Après l'installation ou la mise à niveau de l'outil de ligne de commande, l'opération suivante affiche parfois "en cours" (#9775).

Remerciements

cc-switch v4.0.37

Highlights

  • Unreadable entries are quarantined instead of overwritten — Providers and MCP entries that cannot be parsed now appear separately with an error reason and remain non-editable and disabled; failover skips them. Deleting one removes only its CC Switch record, not the application’s configuration. While such entries exist, changes to them are rejected and incremental all-provider syncs—such as OpenCode’s—fail rather than silently replacing data. Upgrade to a compatible reader to restore them (#9767).
  • Claude Code plugin configuration writes are now fail-safe — Invalid ~/.claude/config.json produces an error identifying the path and leaves the file untouched, instead of treating it as empty and erasing unrelated settings. Writes use a temporary file followed by replacement, preventing interrupted writes from leaving truncated JSON. Repair any invalid configuration before applying plugin changes (#9744).
  • Tool arguments retain underscore-prefixed fields — Fields such as _id, _meta, and __typename are no longer stripped before requests reach upstream providers. This keeps the model’s requested call aligned with actual MCP, database, or GraphQL execution and avoids rejections from strict providers (#9753).
  • Pi gains a native Mistral AI preset — cc-switch-mistral uses Pi’s mistral-conversations protocol, includes Mistral Large 4 and Small 4, and preserves streamed reasoning without colliding with Pi’s built-in mistral provider. The preset is intentionally unavailable for Oh My Pi and Kimi Code, which do not support that protocol (#9344).
  • Transfer timeouts and request limits are more explicit — Skill downloads now time out after 60 seconds without incoming data rather than after 60 seconds total, with a 10-minute overall cap, reducing failures on slow connections. Local routing rejects request bodies—including decompressed bodies—above 200 MiB with HTTP 413, so integrations proxying unusually large payloads may need streaming or chunking (#9773).
  • Compatibility — No breaking changes in this release.

CC Switch v4.0.37

本版本以修复为主。读不出来的供应商和 MCP 条目（比如由更新版本写入、经 WebDAV / S3 同步过来的）不再被当成空配置、下次保存时被默认值覆盖，而是单独列出来，可以删除；Pi 新增 Mistral AI 预设；韩语界面翻译整体改进。

另外修复了本地路由监听地址填 IPv6 时启动不了；「应用到 Claude Code 插件」会把损坏的 ~/.claude/config.json 整个清空；网速慢时大的技能仓库下载到一半被中断；从访达打开 CC Switch 时 Codex 模型目录探测找不到 Node；工具调用参数里 _ 开头的字段被删掉后才发给上游；移出又加回故障转移队列的供应商仍被跳过；插件页点「重试」看起来没反应等问题。

新增

Pi 新增 Mistral AI 预设

Pi 新增 Mistral AI 预设，走 Pi 自己的 Mistral 协议（mistral-conversations），流式的思考内容不会丢（需求见 #9343，#9344）。

  • 自带 Mistral Large 4 和 Mistral Small 4，思考档位与 Pi 内置的 Mistral 目录一致。
  • 供应商名为 cc-switch-mistral，不会遮住 Pi 内置的 mistral。
  • Pi 表单的协议列表里也可以选 mistral-conversations。Oh My Pi 和 Kimi Code 不支持这个协议，不显示这个预设。

变更

  • 读不出来的供应商和 MCP 条目原样保留，可以单独删除（#9767）：以前数据读不出来时会被当成空配置，下次保存就把默认值写回去，原来的数据丢了。现在这样的条目在供应商页和 MCP 页单独列出，显示读不出来的原因，不能编辑或启用，可以删除（只删 CC Switch 里的记录，不动各应用的配置文件）；其他条目照常显示和使用，故障转移跳过它；改这一条的操作会被拒绝，有这样的条目时，累加式应用（如 OpenCode）把全部供应商同步到配置文件也会报错。升级到能读的版本后即可恢复。
  • Claude Code 的 1M 标记改写成小写 [1m]（见 #9757）：和 Claude Code 文档写法一致。Claude Code 本来不区分大小写，已有的 [1M] 照常可用。
  • 韩语界面翻译改进（#9395，#9349）。
  • 授权中心的账号行更好读（#9369）：「N 个供应商在用」单独一行，额度名称列按最长的名称定宽，窗口窄时套餐、域名和登录日期不再被挤成省略号；德语、俄语等较长的翻译也能看到百分比。

修复

  • 本地路由的监听地址填 IPv6（如 ::1）时启动不了（见 #9743）：以前会报「invalid socket address syntax」，现在可以正常监听。
  • 开了「应用到 Claude Code 插件」后，损坏的 ~/.claude/config.json 会被清空（见 #9744）：文件不是合法 JSON 时，以前当成空文件重写，里面的其他设置都丢了。现在会报错并指出文件路径，文件原样不动；写入也改成先写临时文件再替换，中途中断不会留下半截文件。
  • 网速慢时，大的技能仓库下载到一半被中断：安装、更新、检查更新和发现技能以前都限制整个下载 60 秒。现在只有连续 60 秒收不到数据才中止，并提示「没有收到数据」；整个下载最长 10 分钟。
  • 从访达打开 CC Switch 时，Codex 模型目录探测找不到 Node（见 #9764）：用 npm 装的 Codex 因此运行失败，CC Switch 退回用 Codex 桌面版自带、可能较旧的 CLI，聚合模式下的 GPT 模型少了官方信息（比如搜索工具）。现在探测时带上登录 shell 的 PATH，和 CC Switch 运行其他命令行工具时一样。
  • 工具调用参数里 _ 开头的字段被删掉后才发给上游（#9753）：MCP、数据库、GraphQL 类工具常用 _id、_meta、__typename 这类字段，以前会被当成私有字段删掉，模型看到的调用和实际执行的不一样，严格的供应商可能直接拒绝请求。现在工具调用参数原样保留。
  • 从故障转移队列移出再加回的供应商，卡片显示正常但仍会被跳过一段时间（#9750）：移出队列或退出某个应用的路由时，现在会同时清掉运行中的熔断状态。开启 OMO / OMO Slim 时没能删掉另一个变体的配置文件，现在也会单独提示。
  • 插件页加载超时后点「重试」看起来没反应（见 #9758）：已安装、发现和市场三个页签在重试时都会显示加载中。
  • 插件页的几处问题（#9742）：切到别的应用再切回来，进行中的操作仍显示转圈；Codex 更新插件期间又把它启用，更新结束后不会再被停用；搜索也能按显示名搜到（Pi 通过 git 或本地目录安装的包）；卸掉固定版本的 Pi 包、再从「发现」安装后，它不再留在「发现」里；Windows 上装在 WSL 里的插件现在能显示版本、名称和描述。
  • 内存和资源占用（#9773）：离开会话阅读器时释放缓存的图片；关闭自动更新时释放已下载的安装包；部分网络请求复用 HTTP 连接，不再每次新建；本地路由收到的请求体（含解压后）上限为 200 MiB，超过返回 413。
  • 安装或升级命令行工具后，紧接着的操作偶尔提示「正在进行中」（#9775）。

感谢 @vastStage、@xxy9468615、@tanghululalala、@JohnZhong505 报告问题和提供复现信息。
