interrupteur cc v4.0.34

#Commutateur CC v4.0.34 Cette version du référentiel de compétences prend en charge GitLab, Gitea et Forgejo (y compris les instances auto-construites et Codeberg), et vous ne pouvez plus ajouter de référentiels uniquement sur GitHub. Vous pouvez désormais supprimer directement la session de Antigravity CLI dans la gestion de session ; après avoir activé le téléchargement automatique des mises à jour, le téléchargement de la nouvelle version commencera immédiatement. De plus, les modèles ajoutés manuellement par WorkBuddy peuvent définir l'intensité de la réflexion, et la synchronisation S3 peut également effacer les configurations enregistrées localement comme WebDAV. De plus, le fournisseur « Obtenir la liste des modèles » du Gemini CLI a signalé que la clé n'est pas valide ou obtient une liste vide ; le modèle GitHub Copilot dans le Codex est considéré comme ne prenant pas en charge les images ; Alibaba Cloud OSS, Tencent Cloud COS et Huawei Cloud OBS ne peuvent pas utiliser la synchronisation S3 ; le téléchargement complet de la synchronisation cloud échoue lorsqu'il existe des liens non valides dans le répertoire de compétences ; La fable 5.2 est affichée comme Fable 5 en mode routage ; Copilot Le taux de réussite du cache du modèle Gemini sur Copilot est faible ; Copilot a des problèmes tels qu'un échec de demande pour le modèle 1M Fable. Ajouter

L'entrepôt de compétences prend en charge GitLab, Gitea et Forgejo

"Management Skills Warehouse" n'acceptait auparavant que l'adresse de github.com, mais il peut désormais également ajouter des entrepôts publics sur GitLab, Gitea et Forgejo (pour les exigences, voir #1324, #4227), y compris les instances auto-construites et Codeberg :

  • Remplissez owner/name et traitez-le toujours comme GitHub ; lors du remplissage de l'adresse complète d'autres sites, CC Switch demandera d'abord si le site est Gitea / Forgejo ou GitLab, puis le téléchargera de la manière correspondante. Les ports personnalisés, le regroupement à plusieurs niveaux de GitLab et les adresses copiées sur la page Gitea peuvent tous être utilisés.
  • Parcourir les compétences, l'installation, vérifier les mises à jour et les liens "Ouvrir le document" mèneront tous au site où se trouve le référentiel.
  • Seuls les entrepôts publics sont pris en charge et l'adresse doit être https. Gitee ne le supporte pas encore (son interface de téléchargement nécessite un token).
  • Un même owner/name ne peut être conservé que sur un seul site. L'ajout d'un entrepôt du même nom sur un autre site remplacera celui d'origine.

Supprimer la session Antigravity CLI dans la gestion de session

Auparavant, les sessions Antigravity ne pouvaient être supprimées qu'en agy. Vous pouvez désormais supprimer directement la session d'Antigravity CLI dans la gestion de session. Lors de la suppression, il nettoiera son index de session et son résumé, tout comme agy lui-même. Il n'apparaîtra plus après le redémarrage d'agy.

  • La session ne peut pas être supprimée lorsqu'elle est ouverte dans agy. Fermez-le d'abord.
  • Les sessions Antigravity IDE, ainsi que les sessions avec uniquement des index et aucun enregistrement de session, doivent toujours être supprimées dans Antigravity.

Commencez à télécharger automatiquement la nouvelle version immédiatement après l'avoir découverte

Après avoir activé « Télécharger automatiquement les mises à jour », il fallait auparavant attendre une vérification des antécédents environ 1 minute après le démarrage pour commencer le téléchargement. La page "À propos" indiquait seulement qu'il y avait une nouvelle version, ce qui semblait que le changement n'était pas effectif. Le téléchargement commencera désormais dès qu'une nouvelle version sera trouvée au démarrage, et "Téléchargement de la nouvelle version en arrière-plan..." ou "Téléchargement terminé" sera affiché sous l'invite de nouvelle version sur la page "À propos". Les icônes, le texte et les boutons de la boîte de confirmation d'installation ont également été réalignés.

Les modèles ajoutés manuellement par WorkBuddy peuvent définir l'intensité de la réflexion

Le modèle WorkBuddy par défaut a déjà pu sélectionner l'intensité de réflexion dans le menu du modèle WorkBuddy, mais les modèles ajoutés manuellement ou sélectionnés dans la liste des modèles n'ont que le commutateur de réflexion (voir #9599). Maintenant, après avoir activé la réflexion, vous pouvez vérifier « l'intensité de la réflexion » à fournir dans les détails du modèle et définir « peut désactiver la réflexion » ; si aucun des deux n'est coché, seul le commutateur de réflexion sera toujours affiché. Les modèles obtenus à partir de la liste de modèles seront également automatiquement renseignés avec les forces disponibles selon les règles du formulaire Pi.

La synchronisation S3 peut effacer la configuration locale

Les paramètres de synchronisation S3 ont une nouvelle « Configuration claire », qui est la même que WebDAV : supprimez la zone enregistrée, le compartiment, la clé, le point de terminaison et le répertoire distant de la machine locale et arrêtez la synchronisation automatique. Les données téléchargées dans le compartiment ne seront pas supprimées.

Correction

  • Le fournisseur de Gemini CLI « Obtenir la liste des modèles » signale que la clé n'est pas valide ou qu'une liste vide est obtenue lors de l'utilisation d'une passerelle compatible (voir #8546) : dans le passé, lorsque vous appuyiez sur Authorization: Bearer pour envoyer une clé AI Studio, Google ne la reconnaissait pas ; maintenant vous l'obtenez via la méthode native de Gemini. La dernière version a été réparée par Claude Code / Claude Desktop qui a choisi le fournisseur du format Gemini Native. Cette fois, la réparation a été effectuée par le propre fournisseur du Gemini CLI.
  • Lorsque GitHub Copilot est utilisé dans le Codex, les modèles prenant en charge les images sont traités comme uniquement du texte de support (#8027, voir #7977) : lors de l'obtention de la liste des modèles, la capacité de saisie d'image déclarée par Copilot sera lue. Pour les fournisseurs Copilot qui ont été ajoutés, veuillez réobtenir la liste des modèles et l'enregistrer, puis quitter et redémarrer complètement le Codex.
  • Alibaba Cloud OSS, Tencent Cloud COS et Huawei Cloud OBS ne peuvent pas utiliser la synchronisation S3 et reçoivent une erreur de clé d'accès (voir #3996) : les nouveaux buckets de ces trois sociétés rejettent l'ancienne adresse basée sur le chemin et utiliseront désormais automatiquement l'adresse qui place le bucket dans le nom de domaine. Les autres services tels que MinIO et R2 restent inchangés.
  • Le fournisseur de services sélectionné dans les paramètres de synchronisation S3 n'est pas mémorisé après la réouverture de la page des paramètres (#8644).
  • Lorsqu'il y a des liens non valides dans le répertoire des compétences, l'intégralité du téléchargement de la synchronisation cloud échoue (voir #9615) : des liens symboliques non valides ou des connexions au répertoire qui ne peuvent pas être ouvertes sous Windows, provoquaient auparavant l'abandon de l'intégralité du téléchargement (Windows a signalé os error 5), et le téléchargement n'a pas non plus réussi à sauvegarder les compétences existantes. Ces liens sont désormais ignorés et un avertissement est enregistré.
  • Lorsque l'amont est Fable 5.2 en mode routage, le /model de Claude Code affiche toujours Fable 5 (voir #9608) : La Fable 5.2 / 5.1 est désormais écrite comme ID de modèle de la version correspondante, et Claude Desktop est également corrigé.
  • Lorsque GitHub Copilot utilise le modèle Gemini, le taux de réussite du cache pour les longues sessions n'est qu'environ 27 % (voir #9613) : Claude Code ajoute un message système à chaque tour, et Copilot semble les déplacer au début de la requête, provoquant un changement du début de chaque série de requêtes. Désormais uniquement pour le modèle Gemini sur Copilot, les messages système au milieu de la session sont envoyés en tant que messages utilisateur dans leurs positions d'origine, et le début ne change pas. Les autres fournisseurs et modèles ne sont pas concernés.
  • Lorsque GitHub Copilot utilise le modèle Fable et vérifie 1M, la requête rapporte 400 : Copilot n'a pas de version 1M du modèle Claude, et il renverra désormais le modèle normal de la même version. Après avoir obtenu la liste des modèles Copilot, les modèles qui n'ont pas de version 1M (et le contexte est inférieur à 1M) ne peuvent pas être vérifiés pour 1M ; ceux qui ont déjà été vérifiés seront répertoriés dans l’invite. Il est recommandé d'annuler car Claude Code planifiera quand même le contexte selon 1M.
  • Après avoir modifié le répertoire de configuration Hermes dans les paramètres, le fournisseur n'a pas été écrit dans le nouveau répertoire (#9567).
  • Après qu'une erreur interne se produit lors de la détection de la connectivité MCP ou de la connexion DeepSeek Harness, CC Switch doit être redémarré avant de pouvoir être réutilisé (#9572).
  • Si le nom, l'adresse ou le nom du modèle du fournisseur contient le mot mistral, il sera traité comme Mistral. Intensité de réflexion (#9573) : Désormais, seule l'adresse officielle api.mistral.ai est reconnue.
  • Ajout du prix Qwen4 Max (#9612).

Instructions de mise à niveau

Version de la base de données augmentée de 26 à 27, pour que l'entrepôt de compétences enregistre le site sur lequel il se trouve. La base de données sera automatiquement sauvegardée avant la mise à niveau ; si vous revenez à l'ancienne version après la mise à niveau, l'ancienne version vous indiquera que la version de la base de données est trop récente et ne peut pas être ouverte.

cc-switch v4.0.34

Highlights

  • One-way database migration (v26 → v27) — The only breaking change: the schema now records which host each skill repo lives on. Upgrade auto-backs-up the DB, but rollback is off the table — older builds refuse to open the newer database ("version too new"). If you need an escape hatch, keep that pre-upgrade backup yourself before deploying.
  • Skill repos escape GitHub (#4227) — "Manage skill repos" now accepts GitLab, Gitea and Forgejo, including self-hosted instances and Codeberg. owner/name still means GitHub; a full URL triggers a one-time Gitea/Forgejo-vs-GitLab prompt, and custom ports, GitLab nested groups and URLs copied from Gitea all work — browsing, install, update checks and "open docs" follow the repo's host. Watch the limits: public repos and HTTPS only (no Gitee, whose download API needs a token), and since an owner/name may exist on only one host, adding the same name elsewhere silently replaces the original entry.
  • Copilot fixes demand a manual refresh and restart — Image-capable Copilot models were misdetected as text-only (#8027); existing providers must re-fetch and save the model list, then fully quit and restart Codex. The 1M checkbox is also now honest: Copilot has no 1M Claude variants, so requests fall back to the standard model, models without 1M can no longer be flagged, and any still-checked ones are listed for you to uncheck — Claude Code otherwise keeps planning against a 1M context it won't get.
  • Copilot + Gemini cache-hit rate repaired — Long sessions through GitHub Copilot were hitting ~27% cache because Claude Code appends a system message every turn, which Copilot hoists to the front and thereby changes the prompt prefix each round (#9613). The fix re-sends mid-session system messages in place as user messages, scoped to Gemini models on Copilot only — expect better cache reuse there, no behavior change elsewhere.
  • S3 sync: virtual-hosted addressing and local config clearing — Alibaba OSS, Tencent COS and Huawei OBS buckets reject legacy path-style URLs, so sync now uses bucket-in-domain addressing (#3996); MinIO/R2 are untouched. A new "Clear config" action (like WebDAV) wipes locally stored region, bucket, keys, endpoint and remote dir and stops auto-sync — uploaded data in the bucket is safe, and the chosen provider now survives reopening settings (#8644).
  • Smaller operational fixes worth noting — Gemini CLI providers now fetch models the native way instead of sending an Authorization: Bearer AI Studio key that Google rejects or that yields empty lists via gateways (#8546). Cloud sync skips dead symlinks / broken Windows junctions with a warning instead of aborting the whole upload (#9615). Auto-download now starts the moment an update is detected at launch rather than waiting for the ~1-minute background check. And Mistral thinking-strength handling now keys off the official api.mistral.ai host, so any provider/name/model containing the string "mistral" is no longer misclassified (#9573).

CC Switch v4.0.34

本版本的技能仓库支持 GitLab、Gitea 和 Forgejo（包括自建实例和 Codeberg），不再只能添加 GitHub 上的仓库。会话管理里现在可以直接删除 Antigravity CLI 的会话；开启自动下载更新后，发现新版本会立刻开始下载。另外，WorkBuddy 手动添加的模型可以设置思考强度，S3 同步也可以像 WebDAV 一样清除本机保存的配置。

另外修复了 Gemini CLI 的供应商「获取模型列表」报 Key 无效或拿到空列表；Codex 里的 GitHub Copilot 模型被当成不支持图片；阿里云 OSS、腾讯云 COS、华为云 OBS 用不了 S3 同步；Skills 目录里有失效链接时整个云同步上传失败；路由模式下 Fable 5.2 被显示成 Fable 5；Copilot 上的 Gemini 模型缓存命中率低；Copilot 上勾了 1M 的 Fable 模型请求失败等问题。

新增

技能仓库支持 GitLab、Gitea 和 Forgejo

「管理技能仓库」以前只接受 github.com 的地址，现在也能添加 GitLab、Gitea、Forgejo 上的公开仓库（需求见 #1324、#4227），包括自建实例和 Codeberg：

  • 填 owner/name 仍按 GitHub 处理；填其他站点的完整地址时，CC Switch 会先问一次这个站点是 Gitea / Forgejo 还是 GitLab，再按对应的方式下载。自定义端口、GitLab 的多级分组、Gitea 页面上复制的地址都能用。
  • 浏览技能、安装、检查更新和「打开文档」链接都会去仓库所在的站点。
  • 只支持公开仓库，地址必须是 https。Gitee 暂不支持（它的下载接口需要令牌）。
  • 同一个 owner/name 只能保留在一个站点上，在另一个站点添加同名仓库会替换原来的。

在会话管理里删除 Antigravity CLI 会话

以前 Antigravity 的会话只能在 agy 里删。现在可以在会话管理里直接删除 Antigravity CLI 的会话，删除时会和 agy 自己一样，把它的会话索引和摘要一并清理，重启 agy 后不会再冒出来。

  • 会话正在 agy 里打开时不能删，先在 agy 里关掉它。
  • Antigravity IDE 的会话，以及只有索引、没有会话记录的会话，仍然要在 Antigravity 里删除。

发现新版本后立刻开始自动下载

开启「自动下载更新」后，以前要等启动约 1 分钟后的后台检查才开始下载，「关于」页只显示有新版本，看起来像开关没生效。现在启动时一发现新版本就开始下载，「关于」页的新版本提示下会显示「正在后台下载新版本…」或「已下载完毕」。安装确认框的图标、文字和按钮也重新对齐了。

WorkBuddy 手动添加的模型可以设置思考强度

预设里的 WorkBuddy 模型早就能在 WorkBuddy 的模型菜单里选思考强度，手动添加或从模型列表选的模型却只有思考开关（见 #9599）。现在打开思考后，模型详情里可以勾选要提供的「思考强度」，并设置「可以关闭思考」；都不勾时仍只显示思考开关。从模型列表获取的模型也会按 Pi 表单的规则自动填上可用的强度。

S3 同步可以清除本机配置

S3 同步设置新增「清除配置」，和 WebDAV 一样：从本机删除保存的区域、存储桶、密钥、端点和远程目录，并停止自动同步，存储桶里已经上传的数据不会删除。

修复

  • Gemini CLI 的供应商「获取模型列表」报 Key 无效，或者用兼容网关时拿到空列表（见 #8546）：以前按 Authorization: Bearer 发 AI Studio Key，Google 不认；现在按 Gemini 原生方式获取。上一版修好的是 Claude Code / Claude Desktop 选 Gemini Native 格式的供应商，这次修的是 Gemini CLI 自己的供应商。
  • Codex 里用 GitHub Copilot 时，支持图片的模型被当成只支持文字（#8027，见 #7977）：获取模型列表时会读取 Copilot 声明的图片输入能力。已经添加的 Copilot 供应商，请重新获取模型列表并保存，再完全退出并重启 Codex。
  • 阿里云 OSS、腾讯云 COS、华为云 OBS 用不了 S3 同步，被提示 Access Key 错误（见 #3996）：这三家的新存储桶拒绝旧的路径式地址，现在会自动改用把存储桶放在域名里的地址。MinIO、R2 等其他服务不变。
  • S3 同步设置里选的服务商，重新打开设置页后没记住（#8644）。
  • Skills 目录里有失效的链接时，云同步整个上传失败（见 #9615）：失效的符号链接，或 Windows 上打不开的目录联接，以前会让上传整体中止（Windows 上报 os error 5），下载时也会在备份现有 Skills 这一步失败。现在跳过这类链接并记录警告。
  • 路由模式下上游是 Fable 5.2 时，Claude Code 的 /model 仍显示 Fable 5（见 #9608）：Fable 5.2 / 5.1 现在写成对应版本的模型 ID，Claude Desktop 同样修正。
  • 经 GitHub Copilot 用 Gemini 模型时，长会话的缓存命中率只有约 27%（见 #9613）：Claude Code 每一轮都会追加一条系统消息，Copilot 看起来会把它们都挪到请求开头，导致每轮请求的开头都变了。现在只对 Copilot 上的 Gemini 模型，把会话中途的系统消息按原位置作为用户消息发送，开头不再变化。其他供应商和模型不受影响。
  • 经 GitHub Copilot 用 Fable 模型并勾选 1M 时，请求报 400：Copilot 没有 1M 版本的 Claude 模型，现在会退回同版本的普通模型。获取过 Copilot 模型列表后，没有 1M 版本（上下文也不到 1M）的模型不能再勾 1M；已经勾了的会列在提示里，建议取消，因为 Claude Code 仍会按 1M 规划上下文。
  • 在设置里改了 Hermes 的配置目录后，供应商没有写进新目录（#9567）。
  • MCP 连通性检测或 DeepSeek Harness 登录出过一次内部错误后，要重启 CC Switch 才能再用（#9572）。
  • 供应商名称、地址或模型名里带 mistral 字样，就会被当成 Mistral 处理思考强度（#9573）：现在只认官方地址 api.mistral.ai。
  • 新增 Qwen4 Max 的价格（#9612）。

升级说明

数据库版本从 26 升到 27，为技能仓库记录它所在的站点。升级前会自动备份数据库；升级后再退回旧版本，旧版本会提示数据库版本过新，打不开。
