Ajouter

WorkBuddy prend en charge l'importation de liens en un clic

Les liens fournisseurs ccswitch:// peuvent désormais être importés dans les fournisseurs WorkBuddy (#9768) et les cartes résultantes seront les mêmes que celles ajoutées manuellement sur la page WorkBuddy.

  • Le lien doit avoir un modèle ; apiFormat prend uniquement en charge openai_chat.
  • Lorsque l'ID modèle est déjà occupé par une autre carte, l'import sera rejeté et aucune demi-carte ne sera laissée.

Changer de compte Antigravity sous Linux

Sous Linux, vous pouvez également gérer la connexion et le changement de compte d'agy dans le centre d'autorisation. La carte officielle affiche la limite du compte lié (#9774, associé #9245).

  • Les identifiants de connexion sont stockés dans le trousseau du système (Secret Service). Lorsque le trousseau est verrouillé, les vérifications des antécédents concernant le statut et le solde créditeur seront ignorées, et le déverrouillage sera demandé lors du changement actif de numéro.
  • Pour les cartes avec compte lié sous Linux, la boîte de dialogue « Ouvrir le terminal » contient désormais « Utiliser agy pour vous connecter cette fois » : Lorsqu'il n'y a aucun compte lié à la machine ou que le trousseau n'est pas disponible, vous pouvez d'abord ouvrir le terminal avec la connexion actuelle, et la liaison de la carte reste inchangée.

Changement

  • Liste de sessions antigravité et lecteur de session (#9266, voir #9265) : recherchez simplement /usage dans le terminal pour quitter les sessions vides laissées (affichées comme Jan 1), les enregistrements résiduels qui ont été supprimés ou synchronisés à partir d'autres appareils, les sous-agents /boost et les questions de contournement /btw n'apparaissent plus dans la liste et leur utilisation est comptée comme d'habitude. Les conversations sans titre utilisent un aperçu ou la première question comme titre. Le lecteur de session peut voir les pensées, le texte, les appels d'outils (y compris MCP, le navigateur, etc.) et les résultats des outils (y compris les codes de sortie de commande, l'état d'interruption), et les modifications de fichiers affichent le nombre de lignes ajoutées et supprimées. Après la mise à niveau, l'index du corps de la session sera automatiquement reconstruit.
  • Les statistiques de recherche et d'utilisation de session sont plus rapides (#9823, #9825) : l'index de recherche n'est plus reconstruit pour chaque ID de session et chemin lors du changement d'application sur la page de session, et l'utilisation de la mémoire est beaucoup plus petite ; la requête de statistiques d'utilisation peut utiliser l'index de la base de données, le premier mot n'est lu qu'une seule fois et le prix n'est chargé qu'une seule fois pour chaque requête.
  • Supprimez le "Google" redondant du nom du package du compte Google dans le Centre d'autorisation (#9834) : "Google AI Pro" pour les comptes Antigravity et Gemini CLI s'affiche désormais comme "AI Pro".

Correction

  • Tous les fournisseurs tiers de DeepSeek Harness ont soudainement disparu (voir #9785) : Une fois cordis.patch.yml sauvegardé par certains outils YAML, le off dans l'équipement de réflexion deviendra false. CC Switch le sauvegardait tel quel et le réécrivait à chaque fois qu'il était synchronisé. DeepSeek Harness a invalidé l’intégralité de la configuration du fournisseur en raison de cette clé illégale. Il sera désormais corrigé lors de la lecture et de l'écriture (false redevient off et l'équipement inconnu est supprimé).
  • Lors de l'ouverture de CC Switch depuis le Finder, la page « Application » marque l'installation de npm fonctionnant normalement comme « impossible à exécuter » (Voir #9810) : le nœud est introuvable dans le PATH utilisé pour l'installation. Les outils de ligne de commande installés à l'aide de npm --prefix, volta, pnpm, bun, etc. seront jugés inutilisables et l'interface recommandera également de les réinstaller ou de les désinstaller. La détection inclut désormais le PATH du shell de connexion, le même que lorsque CC Switch exécute d'autres outils de ligne de commande. Windows n'est pas affecté.
  • Lors de l'ajout d'un entrepôt de compétences sur un site non pris en charge (tel que cnb.cool), seule « 0 compétence » sera demandée sans erreur (voir #9812) : ce type de site renverra une page Web à n'importe quelle adresse, et la page Web précédemment téléchargée sera traitée comme un package compressé, et il n'y aura aucune invite en cas d'échec. Maintenant, le message "Le téléchargement n'est pas un package compressé : ce site n'est peut-être pas l'entrepôt GitHub / GitLab / Gitea, et il n'est pas encore pris en charge."
  • Le niveau de réflexion sélectionné manuellement (tel que max, ultra) pour le modèle dans le Codex ne prend parfois pas effet (#9017, voir #8952) : lorsque le nom du modèle correspond au modèle officiel du Codex, le répertoire de modèles généré utilise le niveau de réflexion officiel. Appuyez maintenant sur Écrire la sélection sélectionnée dans la carte.
  • Lorsque le Codex est converti au format Chat via le routage, les outils portant des noms similaires entreront en collision (#9554, voir #9551) : lorsque le nom de l'outil ou l'espace de noms contient __, l'outil peut avoir été perdu dans le passé ou l'appel peut avoir été envoyé au mauvais outil. Chaque outil a désormais un nom unique et les appels peuvent être cartographiés avec précision.
  • Les conversations utilisant des modèles tiers via le routage Codex ne peuvent pas continuer après le passage au modèle officiel (#9756, voir #9054) : l'ID de message converti commence par resp_, et l'interface officielle exige qu'il commence par msg_. En mode connexion directe, invalid_id_prefix sera signalé. L'ID nouvellement généré change pour commencer par msg_ ; les anciennes conversations enregistrées restent inchangées.
  • Lorsque Codex est connecté à Claude sur AWS Bedrock via le routeur, chaque requête rapporte 400 (#8659, voir #6118) : la définition de l'outil contient un champ strict supplémentaire spécifique à OpenAI, que Bedrock n'accepte pas. Ce champ n'est plus transmis.
  • Double calcul du dosage :
    • Lorsque le nom du modèle comporte un préfixe de passerelle (comme antigravity/gemini-3.8-flash-high), la même demande est comptée une fois dans l'enregistrement de routage et le journal de session Codex (#9249). Supprimez maintenant le préfixe et comparez à nouveau.
    • Après la mise à jour de l'ancien fichier de session Gemini, l'utilisation archivée a été à nouveau importée ; le nombre de jetons dans la session a changé mais n'a pas été mis à jour (#9527, voir #9523).
  • Les écritures du cache pour Codex dans les statistiques d'utilisation affichent N/A (#8191) : les valeurs réelles sont désormais affichées, seuls Gemini et Grok Build affichent toujours N/A (ils ne signalent pas les écritures du cache). Le journal des requêtes ne compte plus non plus les écritures dans le cache Codex comme nouvelle entrée.
  • La vitesse de sortie d'Antigravity est affichée comme une estimation, qui est faible (#9788, voir #9787) : Antigravity enregistre elle-même le temps du premier mot et la durée de sortie du streaming, qui n'étaient pas utilisés auparavant. La vitesse est estimée en fonction du temps total passé (y compris l'attente avant le premier mot). Compte désormais la durée réelle de sortie comme pour les requêtes acheminées.
  • Lorsqu'une erreur se produit lors de la recherche de texte de conversation, "Aucune conversation ne contient ce mot" s'affiche (#9512, voir #9511) : le message "La recherche de texte a échoué et la recherche ne peut être effectuée que par titre, répertoire et premier et dernier messages." Vous pouvez cliquer sur « Réessayer » et la conversation sera réincluse dans l'index lors d'une nouvelle tentative.
  • Deux problèmes de limites avec les sessions OpenCode (#7982) : sessions qui ont été migrées vers le nouveau format puis continuées dans OpenCode 1.x utilisées pour afficher l'ancien contenu ; lorsque la migration vers le nouveau format a été interrompue à mi-chemin, les sessions inachevées n'étaient plus masquées.
  • La commande de session de restauration d'Oh My Pi signalera une erreur lorsqu'elle sera collée dans PowerShell sous Windows (#9153, voir #9152) : la méthode d'écriture PowerShell est désormais générée sous Windows, et macOS et Linux restent inchangés.
  • Rien ne se produit lorsque vous cliquez sur un lien ou ouvrez un dossier dans une AppImage Linux (#9113, voir #9112) : L'ancienne version de xdg-open fournie avec AppImage ne fait rien sous KDE Plasma 6. Utilisez maintenant le propre xdg-open du système à la place. deb/rpm, macOS et Windows ne sont pas concernés.
  • Sur macOS, fermez l'interface principale en plein écran sur la barre d'état, puis elle sera couverte par la barre de menu et le Dock lorsque vous l'ouvrirez à nouveau (#9770, voir #9769) : vous quitterez désormais le plein écran avant de fermer la barre d'état, et restaurerez le plein écran lorsque vous l'ouvrirez à nouveau depuis la barre d'état, le Dock, etc.
  • L'interface principale n'est qu'une barre blanche après ouverture (#9504, voir #9496) : La taille de la fenêtre mémorisée est anormalement petite et est restaurée à sa taille par défaut à l'ouverture.
  • Lors de la modification d'un fournisseur, fermez l'éditeur qui est encore en cours de sauvegarde et rouvrez-le, et le bouton "Enregistrer" continuera de tourner (#9593, voir #9592).
  • La migration de connexion de l'ancienne version de Copilot abandonnera en cas d'expiration du délai d'attente du réseau et réessayera après le redémarrage (#9549, voir #9544) : désormais, une fois le réseau restauré, la migration se poursuivra la prochaine fois que Copilot sera utilisé sans redémarrer ; il n'abandonnera que si le jeton expire (401/403) ou se déconnecte.
  • L'adresse de la station de transfert a été confondue avec le fabricant officiel (#9648) : lorsqu'un nom de domaine officiel apparaît dans le chemin ou les paramètres de l'adresse, ou que le nom de domaine semble similaire (comme api.x.ai.example.com), il était auparavant considéré comme ce fabricant : xAI le gérera spécifiquement, et le solde et la limite du package seront également vérifiés selon le modèle officiel de cette entreprise. Maintenant, regardez uniquement les vrais noms de domaine.
  • Lors d'opérations telles que l'importation de configuration et le téléchargement de synchronisation cloud, certains fournisseurs de l'application cumulative n'ont pas été écrits dans le fichier de configuration, mais l'invite réussit (#9747) : les fournisseurs dont l'écriture a échoué seront désormais répertoriés.
  • Après avoir déplacé l'emplacement de stockage des compétences, certaines applications n'ont pas réussi à se reconnecter, mais ont signalé un succès (#9748) : il sera désormais répertorié dans l'invite.

cc-switch v4.0.38

Highlights

  • WorkBuddy providers via shareable links — ccswitch:// links can now create WorkBuddy provider cards (#9768), extending the one-click import flow that previously excluded this provider. The constraints matter when distributing configs to a team: the link must include a model, apiFormat is limited to openai_chat, and a model ID already claimed by another card causes the whole import to be rejected rather than leaving a half-created card. Plan model IDs ahead of time if you're generating links programmatically.

  • Linux Antigravity account management — Authorization Center now handles agy login/account switching on Linux, with quota shown on the official card (#9774, #9245). Credentials live in the system Secret Service keyring, so headless or locked-keyring environments will silently skip background status/quota refresh and only prompt for unlock on an explicit switch — worth knowing before scripting this on CI boxes. The new "use current agy login for this session" option in the terminal dialog is a useful escape hatch that keeps the card's binding untouched.

  • Antigravity session cleanup and a one-time index rebuild — The session list now filters out empty /usage exits (Jan 1 entries), deleted or cross-device leftovers, /boost subagents, and /btw side questions, while their usage still counts; untitled sessions fall back to preview text or the first prompt (#9266). The reader surfaces thinking blocks, tool calls (including MCP/browser), tool results with exit codes and interruption state, and file diffs with add/delete line counts. Expect a one-time body-index rebuild after upgrading — searches may be incomplete until it finishes, and long-lived sessions will look noticeably different in the list.

  • Codex routing correctness — Four format fixes unblock previously broken routed workflows: manually selected thinking levels like max/ultra are no longer overwritten by official-model defaults (#9017); uniquely generated tool names prevent __-containing names from colliding or misrouting calls (#9554); converted message IDs now use the required msg_ prefix instead of resp_, fixing invalid_id_prefix when switching a routed conversation to an official model (#9756); and the OpenAI-only strict field is stripped from tool definitions for AWS Bedrock Claude, eliminating per-request 400s (#8659). Note that the ID fix is forward-only — already-stored conversations keep their old IDs.

  • Usage numbers you can trust — Gateway prefixes such as antigravity/ are stripped before deduplication so a single request isn't counted in both the route log and Codex session log (#9249); updated legacy Gemini session files no longer re-import archived usage and now refresh changed token counts (#9527); Codex cache-write reports real values instead of N/A and is no longer double-counted as new input (#8191). Session search and usage queries also got faster and lighter — no per-session index rebuild when switching apps, indexed queries, single-pass first-token reads, and pricing loaded once per query (#9823, #9825). Recomputed historical figures may shift once these fixes are applied.

  • Self-healing config and honest failure reporting — The DeepSeek Harness .yml fix is the subtle one: after certain YAML editors turn off into false, CC Switch used to write the invalid key back on every sync until Harness rejected the entire vendor block; it now normalizes false→off and drops unknown tiers on both read and write (#9785). npm/volta/pnpm/bun installs are no longer falsely flagged as "cannot run" when CC Switch is launched from Finder, because detection now uses the login-shell PATH (#9810); proxy URLs are matched by real hostname instead of substrings like api.x.ai.example.com (#9648); and partial failures during config import/cloud sync or skill relocation are now listed instead of reporting success (#9747, #9748). Search errors are surfaced as failures with a retry action rather than a misleading "no sessions contain this term" (#9512).

No breaking changes in this release.

新增

WorkBuddy 支持一键导入链接

ccswitch:// 供应商链接现在可以导入 WorkBuddy 供应商（#9768），生成的卡片和在 WorkBuddy 页手动添加的一样。

  • 链接必须带模型；apiFormat 只支持 openai_chat。
  • 模型 ID 已被别的卡片占用时，导入会被拒绝，不会留下半截卡片。

Linux 上切换 Antigravity 账号

Linux 上也能在授权中心管理 agy 的登录、切换账号，官方卡片上显示所绑定账号的额度（#9774，相关 #9245）。

  • 登录凭据存在系统的钥匙串（Secret Service）里。钥匙串锁着时，后台查状态和额度会跳过，主动切号时会请求解锁。
  • Linux 上绑了账号的卡片，「打开终端」对话框里多了「本次使用 agy 当前登录」：本机没有绑定的账号或钥匙串不可用时，可以先用当前登录打开终端，卡片的绑定保留不变。

变更

  • Antigravity 会话列表和会话阅读器（#9266，见 #9265）：在终端里只查一下 /usage 就退出留下的空会话（显示为 Jan 1）、已删除或从别的设备同步来的残留记录、/boost 子代理和 /btw 旁路提问不再出现在列表里，它们的用量照常统计。没有标题的会话用预览或第一句提问当标题。会话阅读器能看到思考、正文、工具调用（含 MCP、浏览器等）和工具结果（含命令退出码、中断状态），文件改动显示增删行数。升级后会话正文索引会自动重建一次。
  • 会话搜索和用量统计更快（#9823、#9825）：会话页切换应用时不再为每个会话 ID 和路径重建搜索索引，内存占用也小得多；用量统计的查询能用上数据库索引，首字时间只读一遍，价格每次查询只加载一次。
  • 授权中心里 Google 账号的套餐名去掉多余的「Google」（#9834）：Antigravity 和 Gemini CLI 账号的「Google AI Pro」现在显示为「AI Pro」。

修复

  • DeepSeek Harness 里所有第三方供应商突然消失（见 #9785）：cordis.patch.yml 经过某些 YAML 工具保存后，思考档位里的 off 会变成 false。CC Switch 以前会原样存下来、每次同步都写回去，DeepSeek Harness 因为这一个非法键把整段供应商配置都判为无效。现在读写时都会改正（false 改回 off，不认识的档位去掉）。
  • 从访达打开 CC Switch 时，「应用」页把能正常用的 npm 安装标成「无法运行」（见 #9810）：检测安装时用的 PATH 里找不到 node，用 npm --prefix、volta、pnpm、bun 等方式装的命令行工具就会被判成无法运行，界面还会建议重装或卸载。现在检测时带上登录 shell 的 PATH，和 CC Switch 运行其他命令行工具时一样。Windows 不受影响。
  • 添加不支持的站点（如 cnb.cool）上的技能仓库时，只提示「0 个技能」而不报错（见 #9812）：这类站点对任何地址都返回一个网页，以前下载到的网页被当成压缩包，失败了也没有提示。现在会提示「下载到的不是压缩包：这个站点可能不是 GitHub / GitLab / Gitea 仓库，暂不支持」。
  • Codex 给模型手动选的思考等级（如 max、ultra）有时没生效（#9017，见 #8952）：模型名和 Codex 官方模型对得上时，生成的模型目录用的是官方的思考等级。现在按卡片里选的写入。
  • Codex 经路由转成 Chat 格式时，名字相近的工具会撞名（#9554，见 #9551）：工具名或命名空间里自带 __ 时，以前可能丢掉工具，或者把调用发给错的工具。现在每个工具都有唯一的名字，调用能准确对回去。
  • Codex 经路由用过第三方模型的对话，切到官方模型后无法继续（#9756，见 #9054）：转换出来的消息 ID 以 resp_ 开头，官方接口要求以 msg_ 开头，直连模式下会报 invalid_id_prefix。新生成的 ID 改为 msg_ 开头；已经存下的旧对话不变。
  • Codex 经路由连 AWS Bedrock 上的 Claude 时，每个请求都报 400（#8659，见 #6118）：工具定义里多带了 OpenAI 专用的 strict 字段，Bedrock 不接受。现在不再转发这个字段。
  • 用量重复计算：
    • 模型名带网关前缀（如 antigravity/gemini-3.8-flash-high）时，同一个请求在路由记录和 Codex 会话日志里各算一次（#9249）。现在去掉前缀再比对。
    • Gemini 旧会话文件更新后，已经归档的用量又被导入一次；会话里的 token 数变了却没有更新（#9527，见 #9523）。
  • 用量统计里 Codex 的缓存写入显示 N/A（#8191）：现在显示实际数值，只有 Gemini 和 Grok Build 仍显示 N/A（它们不上报缓存写入）。请求日志也不再把 Codex 的缓存写入算进新输入。
  • Antigravity 的输出速度显示为估算值，偏低（#9788，见 #9787）：Antigravity 自己记录了首字时间和流式输出时长，以前没用上，速度按总耗时（含首字前的等待）估算。现在和经路由的请求一样按实际输出时长计算。
  • 会话正文搜索出错时，显示「没有会话包含这个词」（#9512，见 #9511）：现在会提示「正文搜索失败，暂时只能按标题、目录和首末消息查找」，可以点「重试」，重试时会把会话重新收录进索引。
  • OpenCode 会话的两个边界问题（#7982）：迁移到新格式后又在 OpenCode 1.x 里继续的会话，以前显示的是旧内容；新格式迁移中途中断时，没迁完的会话不再被隐藏。
  • Oh My Pi 的恢复会话命令在 Windows 上粘贴到 PowerShell 会报错（#9153，见 #9152）：Windows 上现在生成 PowerShell 写法，macOS 和 Linux 不变。
  • Linux AppImage 里点链接在浏览器中打开、或打开文件夹，没有任何反应（#9113，见 #9112）：AppImage 自带的旧版 xdg-open 在 KDE Plasma 6 下什么都不做。现在改用系统自己的 xdg-open。deb / rpm、macOS 和 Windows 不受影响。
  • macOS 上把全屏的主界面关到托盘，再打开时被菜单栏和 Dock 遮住（#9770，见 #9769）：现在关到托盘前先退出全屏，从托盘、Dock 等再打开时恢复全屏。
  • 主界面打开后只是一条白条（#9504，见 #9496）：记住的窗口尺寸异常小时，打开时恢复成默认大小。
  • 编辑供应商时，关掉还在保存的编辑器再打开，「保存」按钮一直转圈（#9593，见 #9592）。
  • Copilot 旧版登录迁移遇到网络超时就放弃，要重启才会再试（#9549，见 #9544）：现在网络恢复后，下次用到 Copilot 时会继续迁移，不用重启；只有令牌失效（401 / 403）或退出登录才放弃。
  • 中转站地址被误认成官方厂商（#9648）：地址的路径或参数里出现官方域名，或者域名长得像（如 api.x.ai.example.com）时，以前会被当成那家厂商：xAI 走专门的处理，余额和套餐额度也按那家的官方模板查。现在只看真正的域名。
  • 导入配置、云同步下载等操作中，累加式应用有供应商没写进配置文件，却提示成功（#9747）：现在会列出写入失败的供应商。
  • 移动技能存储位置后，有应用没能重新链接，却提示成功（#9748）：现在会在提示里列出来。
