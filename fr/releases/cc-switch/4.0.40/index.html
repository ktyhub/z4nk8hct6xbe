#Commutateur CC v4.0.40 Cette version permet à la carte officielle de Grok Build d'être liée au compte xAI dans le centre d'autorisation et peut être basculée entre plusieurs comptes Grok comme les cartes officielles Claude et Codex. Page du plug-in prend en charge l'antigravité CLI ; Statistiques d'utilisation a ajouté le taux de réussite du cache à la liste des fournisseurs et des modèles ; Xiaomi MiMo dispose d'une requête de solde et de limite de plan de jeton intégrée ; la fiche de compte dans le centre d'autorisation suit l'ordre et les paramètres cachés de l'application de la barre latérale. Cette version renforce également les contrôles de sécurité de l'importation de liens profonds MCP, des scripts d'utilisation, de l'importation SQL et des adresses d'écoute non natives, et améliore la vitesse de la base de données, le routage local, la synchronisation de l'utilisation, la recherche de session et la page d'application. De plus, l'utilisation de l'agent principal de Kimi Code Desktop n'est pas comptabilisée ; la vitesse de sortie antigravité est faussement élevée à partir de 4.0.38 ; la session Antigravité dans le Code T3 et l'ACP fonctionnant seul ne sont pas visibles ; la réponse officielle du Mistral API est vide une fois la réflexion lancée ; Les réponses natives de Kimi signalent toujours 400 après l'appel de l'outil de vue parallèle ; Les points du compte d'entreprise WorkBuddy sont affichés comme épuisés ; ne peut pas être vu dans la barre d'état Le quota xAI et le compte officiel sont affichés sous forme de noms de domaine de sites Web ; les compétences en double apparaissent dans la « Découverte » de la page Compétences ; la page "Application" n'affiche pas l'état de l'installation tant que la version n'est pas vérifiée. Ajouter

La carte officielle Grok est liée au compte xAI

Le formulaire officiel Grok de Grok Build a ajouté une "méthode de connexion" (#9321, fermer #8599). Vous pouvez sélectionner le compte xAI dans le centre d'autorisation, ajouter ou gérer le compte xAI, ou « vous connecter avec Grok CLI ». L'usage est le même que celui des cartes officielles Claude et Codex.

  • Chaque compte lié est une carte distincte. Avec le numéro de compte dans le nom, vous pouvez ajouter autant de cartes que vous le souhaitez ; ceux qui ne sont pas liés à un compte auront toujours la même carte fixe.
  • Lors du passage à la carte avec un compte qui y est lié, CC Switch actualisera d'abord la connexion de ce compte, puis l'écrira dans ~/.grok/auth.json de Grok CLI, et les autres contenus du fichier ne changeront pas. Grok CLI n'est pas écrit lorsque ce compte est déjà connecté ; lorsque le réseau tombe temporairement en panne, il vous invite à réessayer plus tard. Lorsque le compte est effectivement invalide, il vous invite à vous rendre au centre d'autorisation pour vous reconnecter.
  • Avant de modifier le numéro, le numéro actuellement connecté par Grok CLI sera collecté dans le centre d'autorisation ; lors du retour à la carte « Connexion avec Grok CLI », elle sera restaurée au numéro d'avant le premier changement de numéro.
  • Lors de la suppression du compte dans le centre d'autorisation, si Grok CLI utilise CC Switch pour se connecter à ce compte, la connexion d'origine sera restaurée. Si le compte d'origine a disparu, déconnectez-vous.
  • Pour les cartes liées à un numéro de compte, les limites de la carte, de l'utilisation et des palettes sont toutes vérifiées en fonction de ce numéro. Lorsque la connexion Grok CLI expire pour une carte sans compte, utilisez le compte du même utilisateur dans le centre d'autorisation pour vérifier la limite.

Plug-in antigravité CLI

La page "Plugins" prend en charge Antigravity CLI (#9882, #9885). Tout comme d'autres applications, vous pouvez appeler la propre ligne de commande de agy. Vous pouvez parcourir les plug-ins officiels et du marché partenaire dans « Découvrir » pour installer, activer, désactiver, désinstaller et mettre à jour.

  • Avant la mise à jour, comparez le numéro de version du marché. S'il s'agit de la dernière version, ne la réinstallez pas.
  • Lorsque le plug-in est occupé par une session Antigravity en cours d'exécution ou par un service en arrière-plan, vous êtes invité à le fermer d'abord et à réessayer.
  • Les plug-ins installés par l'ancienne application Antigravity sont placés dans un répertoire nommé numériquement. CC Switch ne peut pas les mettre à jour. Il vous demandera de les désinstaller et de les réinstaller dans « Découvrir ».

Statistiques d'utilisation : afficher le taux de réussite du cache par fournisseur et modèle

Les listes de statistiques d'utilisation « Fournisseur » et « Modèle » ajoutent une colonne « Taux de réussite » après les jetons, afin que vous puissiez voir quel fournisseur et quel modèle n'a pas utilisé le cache. L'algorithme est le même que le taux de réussite dans le journal des requêtes (accès au cache ÷ entrées pouvant être mises en cache). Les accès au cache et les entrées pouvant être mises en cache de chaque ligne s'additionnent au total en haut ; les lignes sans entrées pouvant être mises en cache affichent "-".

Solde Xiaomi MiMo et limite du plan de jetons

Le fournisseur de Xiaomi MiMo a intégré deux requêtes officielles (fermées #9404), vous n'avez donc plus besoin de vous fier au script d'utilisation des cookies de la console :

  • Plan de Token (Clé commençant par tp-) : Affiche le quota utilisé et total, ainsi que l'heure de fin de cette période.
  • Solde (Touche commençant par sk-) : Affiche le solde disponible (en déduisant la partie gelée). Un solde de 0 ne sera pas considéré comme une clé invalide.

La carte du centre d'autorisation suit l'application de la barre latérale

Les fiches de compte dans le centre d'autorisation sont classées dans l'ordre des applications glissées sur la page "Applications". La carte ne sera masquée que si toutes les applications qui utilisent ce compte sont masquées (les comptes Copilot, ChatGPT, xAI seront également utilisés par les fournisseurs d'applications comme Claude Code) ; la carte ignorée du formulaire fournisseur sera toujours affichée.

Changement

  • La base de données et le routage local sont plus rapides (#9820, #9821) : la base de données principale passe en mode WAL, les files d'attente de configuration, de routage, de tarification et de basculement à lire pour chaque demande de routage sont modifiées pour lire à partir du cache, les opérations de la base de données de routage sont déplacées vers un thread séparé, n'occupant plus le thread traitant la demande ; le contenu de la conversation est copié une fois de moins lors du transfert de la demande et le filtrage de confidentialité n'est plus répété pour les demandes qui n'ont pas été réécrites.
  • La synchronisation de l'utilisation est plus rapide (#9817, #9818) : les journaux de session de chaque application sont analysés en parallèle ; les scripts d'utilisation s'exécutent dans des threads séparés, ne ralentissant plus les autres requêtes.
  • La recherche du contenu de la conversation est plus rapide (#9827, #9896) : la recherche d'un ou deux mots ne parcourra plus l'intégralité du texte ; lorsque la saisie continue, la dernière recherche inachevée sera annulée. Le format de l'index de recherche a changé et l'index sera reconstruit pour la première recherche après la mise à niveau.
  • La page "Application" s'ouvre plus rapidement (#9418, #9886, fermer #9884) : Affichez d'abord le groupe "Installé/Non installé" selon le chemin d'installation de la machine, sans attendre la vérification de version de chaque outil ; les versions de chaque outil sont vérifiées en même temps, et chaque outil s'affiche une après vérification.

Sécurité

  • Deep link import MCP (#9831) : La boîte de confirmation affiche tous les champs du serveur MCP (y compris le répertoire de travail, les en-têtes de requête, etc.), et les champs à haut risque sont marqués en rouge. Lira les variables d'environnement locales, exécutera des commandes auxiliaires, pointera le répertoire de travail vers le chemin du partage réseau, ou l'adresse de configuration n'est pas http/https, refusera directement l'importation.
  • Usage Script (#9829) : les requêtes envoyées par le script ne suivent plus les redirections et ne peuvent pas être envoyées vers le propre port de routage du CC Switch. La réponse peut lire jusqu'à 2 Mio ; La clé, l'adresse et les autres variables renseignées dans le script seront correctement échappées. L'adresse de la requête d'utilisation dans le lien profond sera également vérifiée. S'il s'agit d'une adresse intranet ou locale, une boîte de confirmation s'affichera.
  • SQL Import (#9832) : lors de l'importation d'une sauvegarde SQL ou d'un instantané de synchronisation WebDAV/S3, la création de déclencheurs et de vues n'est pas autorisée, la taille maximale du fichier est de 512 Mio et l'exécution est interrompue après plus de 30 secondes.
  • Vérification de l'hôte pour les adresses d'écoute non locales (#9833) : lorsque le service de routage écoute 0.0.0.0 / ::, les requêtes de la machine locale doivent également réussir la vérification de l'hôte pour empêcher la reliaison DNS.

Correction

  • L'utilisation de l'agent principal de Kimi Code Desktop n'est pas comptée (#9505, voir #9498) : Kimi Code Desktop 1.3.5 a modifié le format du journal de session, l'utilisation de l'agent principal est ignorée et le modèle de sous-agent s'affiche sous la forme unknown. Les deux formats peuvent désormais être lus sans doubles calculs ; après la mise à niveau, les anciens journaux seront réanalysés pour compenser l'utilisation et les modèles précédemment manqués.
  • La vitesse de sortie de l'antigravité est faussement élevée (#9858) : À partir de 4.0.38, les requêtes considérées depuis longtemps peuvent afficher des dizaines de milliers de tok/s. Le jeton de sortie d'Antigravity contient une pensée cachée, et le temps du premier mot inclut également le temps de réflexion. Désormais, il est calculé sur la base du temps complet.
  • Les sessions antigravité dans T3 Code et ACP autonome ne sont pas visibles (#9857, voir #9838) : ces sessions apparaîtront désormais dans la liste des sessions et les statistiques d'utilisation. Aucune commande de récupération n'est disponible pour eux et ils ne peuvent pas être supprimés dans CC Switch ; la description ajoutée par le code T3 en dehors de la question sera supprimée et le titre affichera la question originale.
  • La réponse du API officiel de Mistral est vide une fois la réflexion activée (Voir #9902) : le API officiel de Mistral (y compris le modèle tiers qu'il fournit) divise la réponse en fragments de réflexion et de texte et les renvoie. L'itinéraire local ne peut pas être lu et la réponse est vide ou n'a aucun processus de réflexion. Les deux fragments peuvent désormais être lus séquentiellement ; les requêtes vers l’amont restent inchangées.
  • Les réponses natives de Kimi continuent de signaler 400 après avoir visualisé l'image en parallèle (#8825, voir #7504) : Codex Desktop insérera des invites entre les résultats des appels d'outils parallèles. Les réponses natives strictes comme celle de Kimi en amont élimineront les résultats qui ne suivent pas l'appel, et 400 seront signalés à chaque tour après cette session. Rassemblons maintenant tous les résultats, puis plaçons l'invite d'insertion.
  • Les points du compte d'entreprise WorkBuddy sont affichés comme épuisés (voir #9694) : le compte d'entreprise est modifié pour vérifier l'utilisation de l'entreprise, indiquant le montant total, utilisé et le délai d'expiration ; le montant illimité est affiché comme "illimité, N utilisé". Lorsque le montant n'est pas trouvé, la requête échoue et "utilisé (total 0)" n'est plus affiché.
  • Le quota xAI n'est pas visible dans le bac (voir #9899) : les fournisseurs xAI OAuth dans Codex et Claude Code (y compris les membres de l'agrégation Codex) affichent également les quotas dans le bac en fonction du compte xAI lié. Lorsqu'il n'est pas lié, le compte par défaut du centre d'autorisation est utilisé, ce qui est cohérent avec la carte d'interface principale.
  • Le compte officiel dans la barre d'état est affiché comme nom de domaine du site Web (#9863) : la carte Codex officielle avec le compte géré est liée, ainsi que les cartes Codex OAuth, GitHub Copilot et xAI OAuth. Le sous-titre de la barre d'état affiche le compte connecté (les notes manuelles sont prioritaires). La carte xAI OAuth sur l'interface principale affiche également le numéro de compte ; le bac sera mis à jour après la connexion au centre d'autorisation, le changement de compte par défaut, la suppression ou la déconnexion.
  • Les compétences en double apparaissent dans « Découvrir » sur la page Compétences : Deux compétences portant le même nom dans le dernier répertoire du même entrepôt seront chargées dans le même répertoire. "Découvrir" affichait à l'origine deux lignes, mais désormais seule celle la plus proche du répertoire racine de l'entrepôt est affichée.
  • CLI fourni avec OpenCode Desktop est invité à utiliser npm pour mettre à niveau (#9099) : la source d'installation de ce CLI est affichée comme OpenCode Desktop et explique qu'elle est mise à jour avec l'application Desktop et n'est plus comptée dans "toutes les mises à niveau" ; OpenCode installé séparément est mis à niveau comme d'habitude.
  • Les événements de streaming proches de la limite supérieure de 64 Mio sont ignorés par erreur (#9867) : la limite supérieure du tampon ajoutée par 4.0.39 est modifiée pour être jugée en fonction d'un seul événement. Les événements normaux proches de la limite supérieure ne seront plus ignorés avec le suivant dans le même bloc.

Instructions de mise à niveau

  • Si le service de routage surveille 0.0.0.0 / :: et utilise un nom d'hôte personnalisé (ne se terminant pas par .local, .internal, .localhost) pour accéder à la route sur cette machine, vous recevrez un 403 après la mise à niveau. Vous devez renseigner ce nom d'hôte dans l'« Adresse de connexion » de « Route locale » (cette adresse sera également inscrite dans la configuration de chaque client). Les autres appareils en LAN, WSL et Docker ne sont pas concernés.
  • L'index de recherche de contenu de session sera reconstruit lors de la première recherche après la mise à niveau. S'il y a plusieurs sessions, la première recherche sera plus lente.

cc-switch v4.0.40

Highlights

  • Grok Official now supports xAI account switching — #9321 adds account-bound Grok cards that refresh credentials and write only the selected identity to ~/.grok/auth.json, preserving its other contents. Quotas follow the bound account, while deleting an account or returning to “Follow Grok CLI login” restores the previous CLI identity.

  • Antigravity CLI joins the plugin manager — #9882 and #9885 support discovering and managing official and partner-market plugins through agy. Updates skip current versions and require stopping active sessions; plugins installed by older Antigravity versions into numbered directories must be uninstalled and reinstalled because CC Switch cannot update them.

  • Quota diagnostics are more actionable — Supplier and model tables now expose cache-hit rate, making cache-unfriendly workloads visible. Xiaomi MiMo also gains built-in queries for tp- Token Plan usage and sk- balance, including frozen-fund adjustments, removing the need for cookie-scraping usage scripts.

  • Import and routing surfaces are hardened — #9831, #9829, and #9832 reject risky deep-link MCP configurations, restrict usage-script redirects and response size, and block SQL triggers/views with new size and execution-time limits. Migration: if routing listens on 0.0.0.0 or :: and local requests use a custom hostname, expect HTTP 403 until that hostname is added under Local Routing → Connection Address (#9833).

  • Routing, usage collection, and search are faster — WAL, cached request-path configuration, and dedicated database threads reduce routing contention (#9820, #9821); session logs are scanned in parallel, and usage scripts run off the request path. Migration: the search-index format changed, so the first search after upgrading rebuilds the index and may take longer for large histories (#9827).

  • Provider compatibility fixes prevent empty or stuck sessions — Mistral responses now preserve reasoning/body fragment order, and Kimi native Responses groups parallel image-tool results before intervening prompts to prevent subsequent turns from repeatedly returning HTTP 400 (#8825). Antigravity throughput is recalculated against full elapsed time so hidden thinking no longer inflates tok/s, while the 64 MiB streaming fix avoids dropping valid near-limit events (#9867).

CC Switch v4.0.40

本版本让 Grok Build 的官方卡可以绑定授权中心里的 xAI 账号，像 Claude、Codex 官方卡一样在多个 Grok 账号之间切换。插件页支持 Antigravity CLI；用量统计的供应商和模型列表加了缓存命中率；小米 MiMo 内置余额和 Token Plan 额度查询；授权中心的账号卡片跟随侧栏应用的顺序和隐藏设置。

本版本还加固了深链接导入 MCP、用量脚本、SQL 导入和非本机监听地址的安全检查，并提升了数据库、本地路由、用量同步、会话搜索和「应用」页的速度。另外修复了 Kimi Code Desktop 主 agent 的用量没统计；Antigravity 输出速度从 4.0.38 起虚高；T3 Code 和单独运行的 ACP 里的 Antigravity 会话看不到；Mistral 官方 API 开思考后回复为空；Kimi 原生 Responses 在并行看图工具调用后一直报 400；WorkBuddy 企业账号积分显示为已用完；托盘里看不到 xAI 额度、官方账号显示成网站域名；Skills 页的「发现」里出现重复的技能；「应用」页要等版本检查完才显示安装状态等问题。

新增

Grok 官方卡绑定 xAI 账号

Grok Build 的 Grok Official 表单加了「登录方式」（#9321，关闭 #8599），可以选授权中心里的 xAI 账号、添加或管理 xAI 账号，或者「跟随 Grok CLI 登录」，用法和 Claude、Codex 官方卡一样。

  • 每个绑定的账号是一张单独的卡，名字带上账号，可以加任意多张；不绑账号的仍是原来那张固定的卡。
  • 切到绑了账号的卡时，CC Switch 会先刷新这个号的登录，再把它写进 Grok CLI 的 ~/.grok/auth.json，文件里的其他内容不动。Grok CLI 已经登录着这个号时不写；网络暂时失败时提示稍后重试，账号确实失效才提示去授权中心重新登录。
  • 换号前，Grok CLI 当前登录的号会先收进授权中心；切回「跟随 Grok CLI 登录」的卡时，还原成第一次换号前的号。
  • 在授权中心删掉账号时，如果 Grok CLI 正在用的是 CC Switch 替这个号写的登录，会还原原来的登录，原来的号也没了就退出登录。
  • 绑了账号的卡，卡片、用量和托盘的额度都按这个号查。没绑账号的卡在 Grok CLI 的登录过期时，改用授权中心里同一个用户的账号查额度。

Antigravity CLI 插件

「插件」页支持 Antigravity CLI（#9882、#9885），和其他应用一样调用 agy 自己的命令行，可以在「发现」里浏览官方和合作伙伴市场的插件，安装、启用、停用、卸载和更新。

  • 更新前先比对市场上的版本号，已是最新就不重装。
  • 插件被正在运行的 Antigravity 会话或后台服务占用时，提示先关掉再重试。
  • 旧版 Antigravity 应用装的插件放在数字命名的目录里，CC Switch 无法替它更新，会提示卸载后在「发现」里重新安装。

用量统计：按供应商和模型看缓存命中率

用量统计的「供应商」和「模型」列表在 Tokens 后面加了「命中率」一列，能看出是哪家供应商、哪个模型没吃到缓存。算法和请求日志里的命中率一样（缓存命中 ÷ 可缓存输入），各行的缓存命中和可缓存输入加起来与顶部的总数一致；没有可缓存输入的行显示「—」。

小米 MiMo 余额和 Token Plan 额度

小米 MiMo 的供应商内置了两种官方查询（关闭 #9404），不用再靠抓控制台 Cookie 的用量脚本：

  • Token Plan（tp- 开头的 Key）：显示已用和总额度，以及本期结束时间。
  • 余额（sk- 开头的 Key）：显示可用余额（扣除冻结部分），余额为 0 不会被当成 Key 无效。

授权中心卡片跟随侧栏应用

授权中心的账号卡片按「应用」页里拖动的应用顺序排列。只有用到这个账号的应用全都隐藏了，卡片才隐藏（Copilot、ChatGPT、xAI 账号还会被 Claude Code 等应用的供应商用到）；从供应商表单跳过来的那张卡总是显示。

新增预设

新增 StringAI。

变更

  • 数据库与本地路由更快（#9820、#9821）：主数据库改用 WAL 模式，路由每次请求要读的配置、路由、定价和故障转移队列改从缓存读，路由的数据库操作移到单独的线程，不再占住处理请求的线程；转发请求时少复制一次对话内容，没有改写过的请求不再重复跑隐私过滤。
  • 用量同步更快（#9817、#9818）：各应用的会话日志并行扫描；用量脚本在单独的线程里运行，不再拖慢其他请求。
  • 会话内容搜索更快（#9827、#9896）：一两个字的搜索不再扫描全部正文；继续输入时，上一次还没完成的搜索会被取消。搜索索引格式有变，升级后第一次搜索会重建索引。
  • 「应用」页打开更快（#9418、#9886，关闭 #9884）：先按本机的安装路径显示「已安装 / 未安装」分组，不用等每个工具的版本检查；各工具的版本同时检查，查完一个显示一个。

安全

  • 深链接导入 MCP（#9831）：确认框显示 MCP 服务器的全部字段（包括工作目录、请求头等），高危字段标红提示。会读取本机环境变量、执行辅助命令、把工作目录指向网络共享路径，或地址不是 http / https 的配置，直接拒绝导入。
  • 用量脚本（#9829）：脚本发出的请求不再跟随重定向，不能发给 CC Switch 自己的路由端口，响应最多读 2 MiB；填进脚本的 Key、地址等变量会正确转义。深链接里的用量查询地址也会检查，是内网或本机地址时确认框会提示。
  • SQL 导入（#9832）：导入 SQL 备份或 WebDAV / S3 同步快照时，不允许创建触发器和视图，文件最大 512 MiB，执行超过 30 秒即中止。
  • 非本机监听地址的 Host 检查（#9833）：路由服务监听 0.0.0.0 / :: 时，来自本机的请求也要通过防 DNS 重绑定的 Host 检查。

修复

  • Kimi Code Desktop 主 agent 的用量没统计（#9505，见 #9498）：Kimi Code Desktop 1.3.5 换了会话日志格式，主 agent 的用量被跳过，子 agent 的模型显示为 unknown。现在两种格式都能读，不会重复计算；升级后会重新扫描一次旧日志，补上以前漏掉的用量和模型。
  • Antigravity 输出速度虚高（#9858）：4.0.38 起，思考较久的请求能显示几万 tok/s。Antigravity 的输出 token 含隐藏的思考，首字时间也包含思考时长，现在改回按完整耗时计算。
  • T3 Code 和单独运行的 ACP 里的 Antigravity 会话看不到（#9857，见 #9838）：这些会话现在会出现在会话列表和用量统计里。它们没有可用的恢复命令，也不能在 CC Switch 里删除；T3 Code 加在提问外面的说明会去掉，标题显示原本的提问。
  • Mistral 官方 API 开思考后回复为空（见 #9902）：开了思考的 Mistral 官方 API（包括它提供的第三方模型）把回复拆成思考和正文两种片段返回，本地路由读不出来，回复为空或没有思考过程。现在两种片段都能按顺序读出；发给上游的请求不变。
  • Kimi 原生 Responses 在并行看图后一直报 400（#8825，见 #7504）：Codex Desktop 会在并行工具调用的结果之间插入提示，Kimi 这类严格的原生 Responses 上游会丢掉不紧跟调用的结果，这个会话之后每轮都报 400。现在先把这批结果收齐放在一起，再放插入的提示。
  • WorkBuddy 企业账号积分显示为已用完（见 #9694）：企业账号改查企业用量，显示总额度、已用和到期时间；不限量的显示「不限量，已用 N」，查不到额度时报查询失败，不再显示「已用完（共 0）」。
  • 托盘里看不到 xAI 额度（见 #9899）：Codex、Claude Code 里的 xAI OAuth 供应商（包括 Codex 聚合的成员）在托盘里也按绑定的 xAI 账号显示额度，没绑定时用授权中心的默认账号，和主界面卡片一致。
  • 托盘里官方账号显示成网站域名（#9863）：绑了托管账号的 Codex 官方卡，以及 Codex OAuth、GitHub Copilot、xAI OAuth 卡，托盘副标题显示登录的账号（手动备注优先）。主界面的 xAI OAuth 卡片也显示账号；在授权中心登录、切换默认账号、删除或退出登录后托盘会跟着更新。
  • Skills 页的「发现」里出现重复的技能：同一个仓库里末级目录同名的两个技能会装进同一个目录，「发现」里原来显示成两行，现在只显示离仓库根目录最近的那个。
  • OpenCode Desktop 自带的 CLI 被提示用 npm 升级（#9099）：这份 CLI 的安装来源显示为 OpenCode Desktop，并说明它随 Desktop 应用更新，不再计入「全部升级」；单独安装的 OpenCode 照常升级。
  • 快到 64 MiB 上限的流式事件被误跳过（#9867）：4.0.39 加的缓冲上限改成按单条事件判断，接近上限的正常事件不会再和同一块里的下一条一起被丢掉。

升级说明

  • 路由服务监听 0.0.0.0 / ::、又在本机用自定义主机名（不以 .local、.internal、.localhost 结尾）访问路由的，升级后会收到 403，需要在设置「本地路由」的「连接地址」里填上这个主机名（这个地址也会写进各客户端的配置）。局域网、WSL、Docker 里的其他设备不受影响。
  • 会话内容搜索的索引会在升级后第一次搜索时重建，会话多的话第一次会慢一些。
