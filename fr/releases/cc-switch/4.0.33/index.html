interrupteur cc v4.0.33

#Commutateur CC v4.0.33 Cette version corrige le problème selon lequel après être revenu à Claude officiel à partir d'un fournisseur tiers, la session Claude Code déjà ouverte envoie toujours la demande au fournisseur précédent et la session doit être redémarrée pour récupérer. Ollama Cloud a été ajouté à la requête de quota de package ; Le changement de compte antigravité dans le centre d'autorisation prend désormais également en charge Windows. De plus, le fournisseur de Claude Code/Claude Desktop a corrigé le rapport « La clé API n'est pas valide ou n'a aucune autorisation » lors de l'obtention de la liste des modèles lors de la sélection du format Gemini Native ; certains fournisseurs de services sont empêchés par Cloudflare d'obtenir la liste des modèles ; certaines demandes d'Antigravity Orchestrator s'affichent toujours sans prix ; La synchronisation WebDAV est totalement indisponible sur certains NAS ; L'échec du téléchargement WebDAV/S3 affiche uniquement « Échec de la construction de la demande » ; interroger xAI Problèmes tels que le fait d'être invité à se reconnecter en cas de tremblement du réseau lors de la demande de quotas ; ne pas mettre à jour une compétence à mi-chemin et supprimer la compétence d'origine, etc. Anglais → | Version japonaise →

Ajouter

Quota de packages Ollama Cloud

Le fournisseur avec l'adresse ollama.com peut désormais interroger le quota du plan de jetons (pour les exigences, voir #9382) : le package actuel affiche la proportion restante du quota et le temps de réinitialisation dans le package actuel, et l'ancienne version du package affiche la proportion restante de 5 heures et deux fenêtres par semaine. Le quota acheté séparément n'est pas affiché ; Les comptes par répartition n'ont pas de quotas de forfaits, et les raisons seront expliquées. Ollama (localhost:11434) fonctionnant nativement n'a pas de plan et ne sera pas reconnu.

  • Pour les fournisseurs Ollama Cloud nouvellement ajoutés ou pour l'importation en un clic, la requête de quota est activée par défaut ; pour les fournisseurs existants, cliquez sur « Configurer la requête d'utilisation » sur la carte et le modèle de plan de jetons sera automatiquement sélectionné. Ouvrez « Activer la requête d'utilisation » et enregistrez-le.

Changer de compte Antigravity sous Windows

Le changement de compte Antigravity dans le centre d'autorisation ne prenait en charge que macOS, mais il peut désormais également être utilisé sous Windows : après le changement, agy lit le nouveau compte. La carte officielle Antigravity peut lier le compte et vérifier la limite du compte lié. Il vous demandera également vers quel compte il basculera avant d'ouvrir le terminal. Linux n'est pas encore pris en charge.

Correction

  • Après être revenu à Claude officiel à partir d'un fournisseur tiers, la session Claude Code ouverte envoie toujours la demande au fournisseur précédent et doit être redémarrée pour reprendre (#9247, voir #7808, #3057) : Le code Claude en cours d'exécution lira uniquement les variables d'environnement settings.json qui sont ajoutées et modifiées dans la session, et celles supprimées resteront dans la session. Désormais, lors du changement, écrivez d’abord l’adresse, les informations d’identification et le mappage de modèle à supprimer sous forme de valeurs nulles. La prochaine requête de la session ouverte n'utilisera plus la précédente, puis la supprimera du fichier au bout d'environ 10 secondes. Le modèle principal (ANTHROPIC_MODEL) défini au démarrage de la session ne changera pas : s'il était défini dans le modèle précédent, sélectionnez Par défaut dans le menu modèle après être revenu, ou ouvrez une nouvelle session.
  • Lorsque le fournisseur de Claude Code / Claude Desktop sélectionne le format Gemini Native, « Obtenir la liste des modèles » signale toujours « La clé API n'est pas valide ou n'a aucune autorisation » : transmettez maintenant la clé de la manière requise par Google. La requête en cours d'acheminement est déjà normale, seule l'obtention de la liste des modèles est affectée. De plus, pour Pi, Oh My Pi et Kimi Code, si vous choisissez le fournisseur de l'interface Google, vous pouvez obtenir une liste de modèles qui ne répertoriait que jusqu'à 50 modèles auparavant, mais vous pouvez désormais tous les lister.
  • Lors de l'obtention de la liste des modèles, certains fournisseurs de services derrière Cloudflare l'ont directement rejetée et ont été signalés par erreur comme « La clé API n'est pas valide ou n'a aucune autorisation » (#7429, voir #7427) : la requête transporte désormais User-Agent par défaut ; si User-Agent est défini dans l’en-tête du fournisseur ou de la demande, le paramètre prévaudra.
  • Lorsque Antigravity sélectionne Orchestrator, certaines demandes s'affichent toujours sans prix (#9542, voir #9493) : les étapes affichées comme "Gemini 4 Hydrogen (Orchestrator)" sont tarifées en fonction du prix de Gemini 4 Hydrogen, et l'historique des 30 derniers jours compensera également les frais. Les tarifs personnalisés restent prioritaires.
  • La synchronisation WebDAV est totalement indisponible sur certains NAS, et les tests de connexion, de chargement et de téléchargement échouent tous (#5623, voir #5621) : ces NAS renvoient toujours 400 à "Créer un répertoire" lorsque le dossier partagé existe déjà. Dans le passé, il abandonnerait directement, mais maintenant il vérifiera à nouveau si le répertoire existe.
  • **Lorsque le téléchargement WebDAV / S3 est déconnecté par le serveur, seul « Échec de la construction de la demande » s'affiche ** (voir #9559) : Il est désormais clair si la demande n'est pas construite ou échoue lors de son envoi, et la raison spécifique est jointe pour faciliter la détermination s'il s'agit d'un problème de réseau, de TLS ou de serveur. Les paramètres de mot de passe et de signature dans l'adresse n'apparaîtront pas dans le rapport d'erreurs.
  • La synchronisation automatique S3 peut encore être téléchargée à nouveau après avoir été désactivée (#9528) : les téléchargements automatiques mis en file d'attente alors qu'une autre synchronisation est en cours relisent désormais les paramètres avant de démarrer et ne seront plus téléchargés si la synchronisation automatique ou la synchronisation S3 est désactivée pendant cette période. WebDAV n'est que cela.
  • Lors de l'interrogation du solde du compte xAI, si vous rencontrez une instabilité du réseau ou une erreur du service xAI, vous serez invité à vous reconnecter (#9526, voir #9522) : cette invite ne se produira que si la connexion est vraiment invalide. Les erreurs temporaires seront signalées comme d'habitude et le dernier solde trouvé sera conservé. Réessayez la prochaine fois.
  • Après l'expiration d'un compte xAI autre que celui par défaut, le compte par défaut sélectionné dans le centre d'autorisation a été remplacé par un autre compte (#9548, voir #9543).
  • Si la copie échoue à mi-chemin lors de la mise à jour d'une compétence, la compétence d'origine sera supprimée, mais elle sera toujours affichée comme installée dans la liste (voir #9521) : désormais, la nouvelle version ne sera remplacée qu'après avoir été complètement copiée, et la version originale sera conservée en cas d'échec.
  • Lorsque le Codex est converti au format Chat via le routage, required: null dans la définition de l'outil est rejeté par le strict amont (#7023, voir #7019).
  • Lorsque le chemin d'accès au fichier de configuration du shell sur macOS/Linux contient deux points, « conflit de variable d'environnement système détecté » ne parviendra pas à supprimer ou à restaurer les variables (#7170, voir #7169).
  • Les valeurs Pi par défaut de PIPELLM, AICodeWith et E-FlowCode sont affichées comme l'ancien nom du modèle dans la sélection du modèle (#9514) : Par exemple, Claude Opus 5.5 est affiché comme claude-opus-5, et la demande réelle est le nouveau modèle. Les préréglages DeepSeek Harness, Copilot CLI, Oh My Pi, MiniMax Code et Kimi Code générés à l'aide de ces préréglages sont modifiés ensemble ; Les fournisseurs déjà ajoutés conservent leurs noms enregistrés d'origine.
  • Les fournisseurs dont les adresses sont au format api.commandcode.ai/providers sont utilisés comme quota de requêtes de package de code de commande (#9518).

cc-switch v4.0.33

CC Switch v4.0.33

本版本修复了从第三方供应商切回 Claude 官方后，已经开着的 Claude Code 会话仍把请求发给上一家、要重开会话才恢复的问题。套餐额度查询新增 Ollama Cloud；授权中心的 Antigravity 账号切换现在也支持 Windows。

另外修复了 Claude Code / Claude Desktop 的供应商选 Gemini Native 格式时获取模型列表总报「API Key 无效或无权限」；部分服务商获取模型列表被 Cloudflare 拦下；Antigravity Orchestrator 仍有部分请求显示未定价；WebDAV 同步在一些 NAS 上完全用不了；WebDAV / S3 上传失败只显示「请求构造失败」；查询 xAI 额度时遇到网络抖动就被要求重新登录；更新 Skill 中途失败把原来的 Skill 删掉等问题。

新增

Ollama Cloud 套餐额度

地址是 ollama.com 的供应商现在可以查询 Token Plan 额度（需求见 #9382）：现行套餐显示本期套餐内额度的剩余比例和重置时间，旧版套餐显示 5 小时和每周两个窗口的剩余比例。单独购买的额度不显示；按量付费的账号没有套餐额度，会说明原因。本机运行的 Ollama（localhost:11434）没有套餐，不会被识别。

  • 新添加或一键导入的 Ollama Cloud 供应商默认开启额度查询；已有的供应商在卡片上点「配置用量查询」，Token Plan 模板会自动选好，打开「启用用量查询」后保存即可。

Windows 上切换 Antigravity 账号

授权中心的 Antigravity 账号切换以前只支持 macOS，现在 Windows 也能用：切换后 agy 读到的是新账号，Antigravity 官方卡可以绑定账号、查看所绑账号的额度，打开终端前也会提示将切换到哪个账号。Linux 暂不支持。

修复

  • 从第三方供应商切回 Claude 官方后，已经开着的 Claude Code 会话仍把请求发给上一家，要重开会话才恢复（#9247，见 #7808、#3057）：运行中的 Claude Code 只会读入 settings.json 里新增和改动的环境变量，被删掉的仍留在会话里。现在切换时先把要删的地址、凭据和模型映射写成空值，开着的会话下一条请求就不再用上一家，约 10 秒后再从文件里删掉。会话启动时就定下的主模型（ANTHROPIC_MODEL）不会跟着变：如果上一家设了它，切回后在模型菜单里选一次 Default，或者新开会话。
  • Claude Code / Claude Desktop 的供应商选 Gemini Native 格式时，「获取模型列表」总是报「API Key 无效或无权限」：现在按 Google 要求的方式传 Key。经路由的实际请求本来就正常，只有获取模型列表受影响。另外，Pi、Oh My Pi、Kimi Code 选 Google 接口的供应商，获取模型列表以前最多只列出 50 个，现在能列全。
  • 获取模型列表时，部分放在 Cloudflare 后面的服务商直接拒绝，被误报为「API Key 无效或无权限」（#7429，见 #7427）：请求现在默认带上 User-Agent；供应商或请求头里设了 User-Agent 的，仍以设置的为准。
  • Antigravity 选 Orchestrator 时，仍有部分请求显示未定价（#9542，见 #9493）：显示为「Gemini 4 Hydrogen (Orchestrator)」的步骤按 Gemini 4 Hydrogen 的价格计价，近 30 天内的历史也会补上费用。自定义价格仍然优先。
  • WebDAV 同步在部分 NAS 上完全用不了，测试连接、上传、下载都失败（#5623，见 #5621）：这些 NAS 在共享文件夹已存在时仍对「建目录」回 400，以前会直接中止，现在会再查一次目录是否存在。
  • WebDAV / S3 上传被服务器中途断开时，只显示「请求构造失败」（见 #9559）：现在分清是请求没构造出来还是发送时失败，并附上具体原因，方便判断是网络、TLS 还是服务器的问题。地址里的密码和签名参数不会出现在报错里。
  • S3 自动同步在关掉之后仍可能再上传一次（#9528）：另一次同步进行中时排队的自动上传，现在开始前会重新读取设置，期间关掉了自动同步或 S3 同步就不再上传。WebDAV 本来就是这样。
  • 查询 xAI 账号额度时，遇到网络抖动或 xAI 服务出错就提示需要重新登录（#9526，见 #9522）：只有登录真的失效才这样提示，临时错误照常报错并保留上次查到的额度，下次查询再试。
  • 一个非默认的 xAI 账号过期后，授权中心里选好的默认账号被换成了别的账号（#9548，见 #9543）。
  • 更新 Skill 时如果复制到一半失败，原来的 Skill 被删掉，列表里却仍显示已安装（见 #9521）：现在新版本完整复制好之后才替换，失败时保留原来的版本。
  • Codex 经路由转成 Chat 格式时，工具定义里的 required: null 被要求严格的上游拒绝（#7023，见 #7019）。
  • macOS / Linux 上 shell 配置文件的路径里带冒号时，「检测到系统环境变量冲突」删除或恢复变量会失败（#7170，见 #7169）。
  • PIPELLM、AICodeWith、E-FlowCode 的 Pi 预设在模型选择里显示成旧模型名（#9514）：比如 Claude Opus 5.5 显示成 claude-opus-5，实际请求的是新模型。用这几个预设生成的 DeepSeek Harness、Copilot CLI、Oh My Pi、MiniMax Code、Kimi Code 预设一起修正；已经添加的供应商保留原来保存的名字。
  • 地址形如 api.commandcode.ai/providers 的供应商被当成 Command Code 套餐查询额度（#9518）。

致谢

感谢 @funkpopo（切回 Claude 官方后开着的会话跟着切换，以及语言列表集中管理）、@ziyangxiami（Hydrogen Orchestrator 计价）、@SailingLoong（获取模型列表的 User-Agent）、@stofancy（WebDAV 兼容 NAS）、@HaiYangBG1（xAI 账号的两处修复、Skill 更新失败时保留原版本）、@GalaxyKW（Codex 工具定义的 required）、@cuishuang（环境变量路径里的冒号）、@SaladDay（Pi 预设模型名、Command Code 地址识别、S3 自动同步，以及 WebDAV 与 S3 同步代码合并、语言列表集中管理、前后端常量比对等内部整理）的贡献。

感谢 @Lawgk、@eDramas、@xinluke、@JImmyHui2017、@liuxixiang11、@WindowsXP-PLUS 报告问题和提供复现信息。

完整的技术细节请见 CHANGELOG。
