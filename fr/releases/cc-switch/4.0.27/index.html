interrupteur cc v4.0.27

#Commutateur CC v4.0.27 Cette version permet à la gestion de session de rechercher le corps du message, ajoute des paramètres de densité d'interface et de mise à l'échelle de l'interface, les tableaux de tarification des modèles peuvent être recherchés et les fournisseurs utilisés par Grok Build peuvent également ouvrir le terminal. La page installée de Skills a été repensée et les icônes des fournisseurs suivront le thème sombre et clair. De plus, le fichier de configuration a été remplacé par un fichier normal ou n'a pas pu être écrit lorsqu'il s'agissait d'un lien logiciel, le fournisseur était bloqué dans la récupération du disjoncteur jusqu'au redémarrage après l'annulation de la demande, le mode plan a signalé une erreur après que le Codex a défini des autorisations personnalisées, la compétence d'exécution a été faussement signalée comme ayant une mise à jour, l'entrepôt de compétences a affiché 0 compétence, pi.exe de Python a été reconnu comme Pi sous Windows, la synchronisation des prix du modèle a expiré, la fenêtre n'a pas pu être déplacée lors de l'ouverture de la boîte de dialogue. boîte de dialogue, le menu du navigateur apparaît en cliquant avec le bouton droit et des problèmes Linux tels qu'un affichage anormal du panneau de raccourcis. Pour le contenu complet de la mise à jour de 4.0, veuillez consulter les [Notes de version de v4.0] (https://github.com/farion1231/cc-switch/blob/main/docs/release-notes/v4.0.4-zh.md). Ajouter

Rechercher dans le corps du message d'une conversation

Dans le passé, la recherche sur la page de gestion de session ne permettait de trouver que le titre, le répertoire et l'ID de session. Il n'a pas pu être trouvé lorsque je me suis souvenu de ce dont j'avais parlé mais je ne me souvenais pas de quelle session il s'agissait (#7896, #7420). Vous pouvez maintenant ouvrir « Rechercher le texte du message » : ouvrez-le dans le menu « ⋯ » dans le coin supérieur droit de la page, ou cliquez directement sur le bouton dans l'invite lorsque la recherche n'a aucun résultat. Après ouverture, les résultats de la recherche répertorieront les fragments du corps touchés et le nombre de messages touchés.

  • Désactivé par défaut. Après ouverture, CC Switch indexera localement le corps du message, et la progression sera affichée lors de la création. Pour le moment, les résultats corporels peuvent ne pas être complets.
  • L'index est un fichier local distinct session-index.db, qui ne participe pas à la synchronisation ou à la sauvegarde cloud ; désactiver cet interrupteur le supprimera.

Densité de l'interface et mise à l'échelle de l'interface

Deux nouveaux éléments sont ajoutés dans « Paramètres → Général → Apparence » (#9209) :

  • Densité de l'interface : "Compact" est la taille d'origine et la valeur par défaut ; « Confortable » correspond à une taille de police plus grande et les boutons et les zones de saisie sont plus hauts.
  • Zoom de l'interface : 90 %, 100 %, 110 %, 125 % quatre niveaux, vous pouvez également appuyer sur Ctrl (⌘ sur macOS) plus +, - pour régler, appuyer sur Ctrl/⌘ plus 0 pour restaurer. Les deux paramètres ne sont enregistrés que localement, tout comme le thème. Le panneau d'accès au plateau reste de taille compacte.

Le tableau de tarification des modèles peut être recherché

Un champ de recherche a été ajouté au-dessus du tableau de tarification des modèles pour filtrer par ID ou nom de modèle (#9205). Appuyer sur Entrée modifiera le premier résultat ; lorsqu'il n'y a pas de modèle correspondant, appuyer sur Entrée ajoutera un nouveau prix pour le modèle saisi.

Grok Build Terminal ouvert

La carte fournisseur de Grok Build dispose également d'un bouton « Ouvrir le terminal » (#9234). Grok CLI ne peut pas permettre à un seul terminal de changer de fournisseur, ce bouton n'apparaît donc que sur le fournisseur utilisé. Le terminal ouvert utilise directement la configuration Grok gérée par CC Switch ; --always-approve sera ajouté lors du saut de la confirmation d'autorisation.

Changement

  • Reformatage de la page des compétences installées (#9210) :
    • La colonne du nom est fixe à gauche, et les colonnes de chaque application défilent horizontalement en dessous lorsque la fenêtre est étroite.
    • Le filtrage des statuts et des sources est déplacé vers la même barre d'outils que la page « Découvrir », et les compétences ne seront pas bloquées après avoir été sélectionnées ; les opérations par lots conservent la mise à jour, la désinstallation et « activer »/« désactiver » par application.
    • Le lien « N Updatable » sur l'en-tête a été supprimé et le « Tout mettre à jour » sur la barre d'outils a déjà écrit le numéro ; cliquez sur la marque « Mise à jour » sur chaque ligne pour mettre à jour cette compétence.
    • Le menu "..." de chaque ligne conserve le document ouvert, l'ouverture du répertoire et la désinstallation ; en cas d'échec de l'écriture, le message d'erreur s'affiche dans la position décrite.
  • L'icône du fournisseur suit le thème (#8438) : Suppression du fond blanc fixe derrière l'icône de la carte. Les icônes sombres d'une seule couleur changeront avec la couleur du texte et seront clairement visibles en mode sombre ; les icônes multicolores avec des traits sombres, les icônes d'image et les icônes que vous téléchargez auront toujours un fond clair en mode sombre.
  • Le clic droit ne fait plus apparaître le menu du navigateur (#8919, #8921) : dans le passé, un clic droit dans la fenêtre principale et le panneau de la barre d'état système faisait apparaître le menu du navigateur (sous Windows, c'était "Retour", "Recharger", "Enregistrer sous", "Imprimer", etc.). Plus maintenant; Les zones de saisie, les éditeurs de code et le texte sélectionné peuvent toujours être cliqués avec le bouton droit et copiés et collés.
  • Le journal du disjoncteur indique de quel fournisseur il s'agit (#9292) : Les journaux du disjoncteur (CB-001 à CB-006) portent tous « application : identifiant fournisseur » ; lorsque le disjoncteur rejette un fournisseur, il enregistrera également une ligne de FWD-004, indiquant le nom du fournisseur, et ne la sautera plus tranquillement. Seuls les logs ont été modifiés, mais les comportements de routage et de disjoncteur restent inchangés.
  • Préréglages : Le modèle par défaut des préréglages Mistral AI a été modifié en mistral-large-4 (Mistral Medium 3.5 a été annoncé comme obsolète par Mistral), et les préréglages Mistral AI pour Claude Code, Codex et Claude Desktop ne sont plus masqués. Le forfait Mistral Vibe et le API partagent le même quota. « Obtenir la clé API » est modifié pour ouvrir la page clé de Vibe CLI, qui est disponible gratuitement, par abonnement et par paiement à l'utilisation ; vous pouvez également le trouver en recherchant « Vibe » lors de l’ajout d’un fournisseur. Ajout de Genesis (#9269) et TokenPlus (#9296). Les fournisseurs déjà ajoutés ne sont pas concernés.

Correction

  • Lorsque le fichier de configuration est un lien logiciel, le changement de fournisseur le remplacera par un fichier normal et une erreur sera signalée directement sur Windows (#6764, #9283). Lorsque vous utilisez l'outil dotfiles ou le dossier de synchronisation pour gérer les fichiers ~/.claude/settings.json, ~/.codex/config.toml, opencode.json, etc., il s'agit généralement de liens symboliques. Dans le passé, le lien lui-même était remplacé lors de l’écriture. Sous macOS et Linux, le lien s'est transformé en un fichier normal et a été découplé du fichier d'origine. Sous Windows, une erreur « échec du remplacement atomique » (erreur du système d'exploitation 1464) a été signalée. Le fichier réel pointé par le lien est désormais écrit et le lien reste inchangé.
  • Une fois la demande annulée à mi-chemin, le fournisseur peut être en récupération du disjoncteur jusqu'au redémarrage (#7206, #9292). Pendant la période de récupération du disjoncteur, le disjoncteur ne transmet qu'une seule demande de détection ; si le client est déconnecté avant que la demande ne soit complétée, le quota ne sera pas restitué et toutes les demandes ultérieures adressées à ce fournisseur seront rejetées. Désormais, quelle que soit la fin de la demande, la place sera restituée.
  • Après avoir défini des autorisations personnalisées sur Codex, utilisez le mode plan pour signaler les erreurs (#7349, #7294). Le Codex le plus récent exige que model_catalog_json soit un chemin absolu lors de la lecture des autorisations personnalisées. Dans le passé, CC Switch écrivait le nom du fichier et le Codex signalait AbsolutePathBuf deserialized without a base path. Écrivez maintenant le chemin absolu ; écrivez toujours le nom du fichier lorsque le répertoire de configuration est en WSL.
  • Les compétences exécutées une fois sont affichées comme « pouvant être mises à jour », et cliquer sur mettre à jour couvrira l'intégralité du répertoire (#7780, #7772). Les fichiers __pycache__ et .pyc générés lors de l'exécution de Python sont inclus dans le contenu de la compétence. Ces fichiers sont désormais ignorés lors de la recherche de mises à jour ; les anciens enregistrements issus des versions précédentes seront automatiquement convertis et n'entraîneront pas de faux positifs.
  • L'entrepôt de compétences affiche "0 compétence reconnue" (#9273). La succursale d'entrepôt ajoutée lors de l'importation est enregistrée comme HEAD, ou lorsque la succursale par défaut de l'entrepôt est principale mais est affectée à principale, la quantité est toujours 0. Désormais, le décompte est basé sur les succursales réellement lues ; l'entrepôt qui ne parvient pas à lire indiquera « échec de lecture » ​​et la raison. Après avoir importé Skill et ajouté un nouvel entrepôt, il sera relu lors de sa prochaine ouverture.
  • Windows traite pi.exe dans le package Python comme Pi (#9267). Il existe un package pi sans rapport sur PyPI qui installera Scripts\pi.exe, et la page de l'application l'affichera comme « impossible à exécuter ». Pi n'est publié que via npm, et désormais pi.exe dans le répertoire Python Scripts n'est plus reconnu comme Pi.
  • La synchronisation des prix du modèle a échoué, invitant uniquement error decoding response body (#9262). Le téléchargement de la liste de prix à partir de models.dev expire à mi-chemin sur un réseau ou un proxy lent. Le délai d'attente est désormais réduit de 15 secondes à 60 secondes, et la véritable raison sera écrite dans l'état de synchronisation en cas d'échec.
  • Lors de l'ajout du fournisseur DeepSeek Harness, il n'invite que Invalid DeepSeek Harness profile YAML, je ne sais pas de quel fichier il s'agit (#9297). Désormais, le rapport d'erreur écrira le chemin du fichier de configuration d'erreur et l'erreur spécifique du YAML, ce qui facilitera la recherche du fichier à réparer.
  • Le test de connectivité détermine que la station de redirection est inaccessible (#9253, #5747). Certaines passerelles se redirigent entre /v1 et /v1/. Nous testons maintenant qu'ils peuvent se connecter même s'ils reçoivent la redirection.
  • La fenêtre ne peut pas être déplacée lors de l'ouverture d'une boîte de dialogue (#9140). Les fenêtres peuvent désormais être déplacées lorsqu'une boîte de dialogue est ouverte ; les boutons Réduire, Agrandir et Fermer sont toujours disponibles lors de l'utilisation des boutons de fenêtre de l'application sous Windows et Linux.
  • Exception d'affichage du panneau de raccourci Linux : Le panneau et la fenêtre rouverts en mode léger sont rendus incorrectement (#9233, #9216), et une partie du panneau est rognée lorsque le zoom d'affichage est défini (#9287, #8556). Les panneaux sous Linux sont passés à un arrière-plan opaque.
  • Lorsque le nom du fournisseur commence par des caractères tels qu'emoji, ou est précédé d'un espace, le premier caractère affiché sur une carte sans icône est tronqué ou vide (#8139).
  • L'avertissement de risque lié au lien d'importation en un clic manque l'adresse IPv6 avec l'adresse IPv4 intégrée (#8127). Ce type d'adresse est désormais jugé en fonction de l'adresse IPv4 vers laquelle elle pointe réellement, qu'il s'agisse de la machine locale ou de l'intranet.

cc-switch v4.0.27

Highlights

  • Full-text session search is opt-in — Search can now match message bodies, not just titles, directories, and IDs (#7896). CC Switch builds a separate local session-index.db; it is excluded from cloud sync and backups, deleted when the feature is disabled, and results may be incomplete during initial indexing—important if you rely on cross-device session history.
  • Configuration writes preserve symlinks — Provider switches now write through to the target of linked files such as ~/.claude/settings.json, ~/.codex/config.toml, and opencode.json instead of replacing the link (#9283). This keeps dotfiles and synced configurations connected and fixes Windows atomic-replacement error 1464; existing links need no migration.
  • Two reliability blockers are fixed — Codex custom-permission configurations now use an absolute model_catalog_json path, resolving plan-mode deserialization failures (#7349); WSL configuration directories intentionally still use a filename. Canceled requests now return circuit-breaker probe slots, preventing providers from remaining stuck in recovery until restart (#9292).
  • Skill updates no longer chase runtime artifacts — Update checks ignore __pycache__ and .pyc, preventing used Python Skills from being falsely marked stale and then overwritten during updates (#7780); old records are converted automatically. Repository discovery now counts the branch actually read and reports failures with reasons instead of showing “0 skills” (#9273).
  • Provider setup gains safer defaults and Grok terminal access — New Mistral AI presets default to mistral-large-4 because Medium 3.5 is deprecated; existing providers are unchanged. Grok Build’s terminal action appears only on the active provider because Grok CLI cannot switch providers per terminal; it uses CC Switch’s managed configuration and adds --always-approve when permission confirmation is skipped (#9234).
  • Breaking changes — None.

CC Switch v4.0.27

本版本让会话管理可以搜索消息正文，新增界面密度和界面缩放设置，模型定价表可以搜索，Grok Build 正在使用的供应商也能打开终端了。Skills 的已安装页重新排了版，供应商图标会跟随深浅色主题。另外修复了配置文件是软链接时被替换成普通文件或写入失败、取消请求后供应商卡在熔断恢复中直到重启、Codex 设置了自定义权限后 plan 模式报错、运行过的 Skill 被误报有更新、Skills 仓库显示 0 个 Skill、Windows 上把 Python 的 pi.exe 认成 Pi、模型价格同步超时、打开对话框时窗口拖不动、右键弹出浏览器菜单，以及 Linux 快捷面板显示异常等问题。4.0 完整的更新内容请见 v4.0 发布说明。

新增

搜索会话的消息正文

以前会话管理页的搜索只能找标题、目录和会话 ID，记得聊过什么、却想不起是哪个会话时找不到（#7896、#7420）。

现在可以打开「搜索消息正文」：在页面右上角的「⋯」菜单里打开，或者搜索没有结果时直接点提示里的按钮。打开后，搜索结果会列出命中的正文片段和命中了几条消息。

  • 默认关闭。打开后 CC Switch 会在本地为消息正文建立索引，建立期间会显示进度，这时正文结果可能还不全。
  • 索引是单独的本地文件 session-index.db，不参与云同步，也不进备份；关闭这个开关会删除它。

界面密度和界面缩放

「设置 → 通用 → 外观」里新增两项（#9209）：

  • 界面密度：「紧凑」就是原来的尺寸，也是默认值；「舒适」的字号大一档，按钮和输入框更高一些。
  • 界面缩放：90%、100%、110%、125% 四档，也可以按 Ctrl（macOS 上是 ⌘）加 +、- 调整，按 Ctrl/⌘ 加 0 复原。

两项设置只保存在本机，和主题一样。托盘快捷面板始终保持紧凑尺寸。

模型定价表可以搜索

模型定价表上方加了搜索框，按模型 ID 或名称筛选（#9205）。按回车会编辑第一个结果；没有匹配的模型时，回车会为输入的模型新增定价。

Grok Build 打开终端

Grok Build 的供应商卡片也有「打开终端」按钮了（#9234）。Grok CLI 不能只让某一个终端换供应商，所以这个按钮只出现在正在使用的供应商上，打开的终端直接用 CC Switch 管理的这份 Grok 配置；选择跳过权限确认时会加上 --always-approve。

变更

  • Skills 已安装页重新排版（#9210）：
    • 名称列固定在左侧，窗口窄时各应用的列在它下面横向滚动。
    • 状态和来源筛选移到和「发现」页一样的工具栏里，选中 Skill 后也不会被挡住；批量操作保留更新、卸载和按应用「启用到」/「停用」。
    • 去掉了页头的「N 个可更新」链接，工具栏的「全部更新」已经写了数量；点每行的「可更新」标记就能更新这个 Skill。
    • 每行的「…」菜单保留打开文档、打开目录和卸载；写入失败时，错误信息显示在描述的位置。
  • 供应商图标跟随主题（#8438）：去掉了卡片图标后面固定的白底。单色的深色图标会跟着文字颜色变化，深色模式下也看得清；带深色笔画的多色图标、图片图标和你上传的图标在深色模式下仍然带浅色底。
  • 右键不再弹出浏览器菜单（#8919、#8921）：以前在主窗口和托盘面板里点右键，会弹出浏览器自带的菜单（Windows 上是「后退」「重新加载」「另存为」「打印」等）。现在不会了；输入框、代码编辑器和选中的文字仍然可以右键复制粘贴。
  • 熔断日志写明是哪家供应商（#9292）：熔断器的日志（CB-001 到 CB-006）都带上了「应用:供应商 id」；熔断器拒绝某家供应商时也会记一行 FWD-004，写明供应商名称，不再悄悄跳过。只改了日志，路由和熔断行为不变。
  • 预设： Mistral AI 预设的默认模型改为 mistral-large-4（Mistral Medium 3.5 已被 Mistral 宣布弃用），Claude Code、Codex 和 Claude Desktop 的 Mistral AI 预设不再隐藏。Mistral Vibe 套餐和 API 共用额度，「获取 API Key」改为打开 Vibe CLI 的密钥页，免费、订阅和按量付费都能用；添加供应商时搜「Vibe」也能找到它。新增 Genesis（#9269）、TokenPlus（#9296）。已添加的供应商不受影响。

修复

  • 配置文件是软链接时，切换供应商会把它替换成普通文件，Windows 上直接报错（#6764、#9283）。用 dotfiles 工具或同步文件夹管理 ~/.claude/settings.json、~/.codex/config.toml、opencode.json 等文件时，它们通常是软链接。以前写入时会把链接本身替换掉，macOS 和 Linux 上链接变成普通文件、和原文件脱钩，Windows 上报错「原子替换失败」（os error 1464）。现在会写到链接指向的真实文件，链接保持不变。
  • 请求中途被取消后，供应商可能一直处在熔断恢复中，直到重启（#7206、#9292）。熔断恢复期间，熔断器只放一个探测请求过去；如果这个请求还没结束客户端就断开了，名额不会还回去，之后发给这家供应商的请求全被拒绝。现在无论请求怎么结束，名额都会还回去。
  • Codex 设置了自定义权限后，用 plan 模式报错（#7349、#7294）。较新的 Codex 读取自定义权限时要求 model_catalog_json 是绝对路径，以前 CC Switch 写的是文件名，Codex 报 AbsolutePathBuf deserialized without a base path。现在写成绝对路径；配置目录在 WSL 里时仍写文件名。
  • 运行过一次的 Skill 被显示为「可更新」，点更新会覆盖整个目录（#7780、#7772）。Python 运行时生成的 __pycache__ 和 .pyc 文件被算进了 Skill 的内容。现在检查更新时忽略这些文件；以前版本记下的旧记录会自动换算，不会因此误报。
  • Skills 仓库显示「识别到 0 个技能」（#9273）。导入时添加的仓库分支记为 HEAD，或者仓库默认分支是 master 却配成了 main 时，数量总是 0。现在按实际读取的分支计数；读取失败的仓库会写明「读取失败」和原因，导入 Skill 新增了仓库后，下次打开会重新读取。
  • Windows 上把 Python 包里的 pi.exe 当成 Pi（#9267）。PyPI 上有一个无关的 pi 包会装出 Scripts\pi.exe，应用页会把它显示为「无法运行」。Pi 只通过 npm 发布，现在 Python Scripts 目录里的 pi.exe 不再被识别为 Pi。
  • 模型价格同步失败，只提示 error decoding response body（#9262）。网络较慢或经代理时，从 models.dev 下载价格表会在读到一半时超时。现在超时时间从 15 秒放宽到 60 秒，失败时同步状态里会写出真正的原因。
  • 添加 DeepSeek Harness 供应商时只提示 Invalid DeepSeek Harness profile YAML，不知道是哪个文件（#9297）。现在报错会写出出错的配置文件路径和 YAML 的具体错误，方便找到文件修复。
  • 连通性测试把会重定向的中转站判为不通（#9253、#5747）。有的网关在 /v1 和 /v1/ 之间互相重定向，现在测试收到重定向就算连得上。
  • 打开对话框时窗口拖不动（#9140）。现在对话框打开时仍然可以拖动窗口；Windows 和 Linux 上使用应用内窗口按钮时，最小化、最大化和关闭按钮也照常可用。
  • Linux 快捷面板显示异常：轻量模式下重新打开的面板和窗口渲染出错（#9233、#9216），设置了显示缩放时面板被裁掉一部分（#9287、#8556）。Linux 上的面板改为不透明背景。
  • 供应商名称以 emoji 等字符开头、或前面带空格时，没有图标的卡片显示的首字是乱码或空白（#8139）。
  • 一键导入链接的风险提示漏判了内嵌 IPv4 地址的 IPv6 地址（#8127）。这类地址现在按它实际指向的 IPv4 地址判断是否为本机或内网。
