interrupteur cc v4.0.31

#Commutateur CC v4.0.31 Cette version ajoute une nouvelle application gérée Tencent WorkBuddy : le modèle personnalisé est écrit dans la propre configuration du modèle de WorkBuddy et peut être sélectionné directement dans WorkBuddy ; il peut également être basculé entre plusieurs comptes WorkBuddy. Avant de changer, vous pouvez voir le forfait, les points restants et le délai d'expiration de chaque compte. L'interface a été nouvellement ajoutée en allemand et le README est également disponible dans les huit langues de l'interface. De plus, lorsque Claude Code est connecté au relais au format OpenAI Responses via un routage, la session sera signalée comme 400 à chaque tour une fois que le même relais sera attribué à différentes ressources Azure et ne pourra pas être poursuivi ; lorsqu'il est connecté au format Gemini Native en amont via le routage, l'appel de l'outil parallèle sera signalé comme 400 et le taux de réussite du cache est très faible ; l'invite de survol de la barre d'état macOS se bloque toujours à l'écran ; l'utilisation d'anciennes conversations poursuivies par le Codex n'est jamais importée. Ajouter

### Copain de travail Tencent WorkBuddy devient une nouvelle application gérée (#8757, pour les exigences, voir #4802, #5802, #7419, #7076). Comme OpenCode, plusieurs fournisseurs sont valables en même temps :

  • Modèle personnalisé : après avoir cliqué sur "Ajouter", le modèle du fournisseur est écrit dans le propre models.json de WorkBuddy et est affiché sous la forme "Nom : ID du modèle" dans la sélection de modèle de WorkBuddy. Lorsque le nom est laissé vide, utilisez « Étiquette du fabricant ». Les modèles que vous avez ajoutés dans WorkBuddy sont conservés tels quels. Les modèles personnalisés de WorkBuddy prennent uniquement en charge le format OpenAI Chat Completions.
    • Pour les modèles du préréglage, vous pouvez sélectionner l'intensité de la réflexion dans la sélection de modèles de WorkBuddy (comme faible/élevée/max pour Kimi K3.1 Pro).
    • WorkBuddy ne prend actuellement pas en charge le même identifiant de modèle apparaissant deux fois. Lors de la sélection d'un préréglage, les modèles qui ont été utilisés par d'autres cartes seront ignorés, ainsi que la carte dont il s'agit. Les ID de modèle en double remplis manuellement seront marqués et ne pourront pas être enregistrés.
  • Compte officiel : Les comptes connectés à WorkBuddy seront automatiquement inclus dans le "Centre d'autorisation", qui affiche le pseudo, le package, les points restants et le délai d'expiration des points (expire dans les trois jours). Il existe deux entrées pour changer de compte : ajoutez la carte « WorkBuddy Official Login » liée à ce compte, ou cliquez sur « Basculer WorkBuddy vers ce compte » dans le menu de ce compte dans le centre d'autorisation.
    • Assurez-vous de quitter complètement WorkBuddy (y compris la barre de menu/la barre d'état système) avant de basculer, sinon il réécrira la connexion actuelle.
    • "Connectez-vous à un autre compte" arrête uniquement WorkBuddy sur la page de connexion localement et ne déconnectera pas le compte actuel sur le serveur. Les comptes inclus peuvent toujours être rétablis.
    • Les packages et les points ne peuvent être vérifiés que lorsque WorkBuddy est en cours d'exécution et que le compte est connecté. Une fois vérifiés, ils seront mis en cache et affichés.
  • **MCP, compétences, mots d'invite ** : synchronisé avec le mcp.json de WorkBuddy, le catalogue de compétences et le mot d'invite global CODEBUDDY.md. Les entrées MCP gérées par le connecteur WorkBuddy ne seront pas modifiées.
  • Gestion des sessions et statistiques d'utilisation : répertoriez les sessions WorkBuddy, importez l'utilisation à partir des journaux de session. La session ne peut pas être reprise dans le terminal.

Interface allemande, README en huit langues

  • Allemand : La langue du système est automatiquement sélectionnée au premier démarrage, et le menu de la barre d'état et le panneau de raccourcis ont également été traduits. Les espaces réservés pour le filtre de confidentialité sont temporairement en anglais dans l'interface allemande, tout comme le coréen et le russe.
  • README a été ajouté aux versions chinoise traditionnelle, coréenne, turque et russe, correspondant aux huit langues de l'interface.

Autres

  • Il y a « Resynchroniser maintenant » directement dans le menu « ⋯ » dans le coin supérieur droit de la page Compétences (#9417) : Pas besoin d'aller dans « Stockage et synchronisation » pour le trouver.
  • Lors du regroupement "par projet" dans la gestion des conversations, les conversations qui n'appartiennent à aucun projet dans la version de bureau Codex sont regroupées en un seul groupe "Codex Chat" (#9415) : Chaque conversation n'appartient plus à un seul groupe.
  • Ajout du filtrage des codes d'état pour les journaux de requêtes : 403, 404, 502, 503, 504, 520, 529 (#9425).

Changement

  • Le filtre de confidentialité passe à la dernière étape avant l'envoi de la demande (#9460) : Auparavant, la demande était filtrée lors de sa première entrée dans la route. Les contenus ajoutés ultérieurement à la demande, tels que les tentatives de basculement, les résumés compressés générés par CC Switch lui-même, etc., ne seront pas traités. Désormais, chaque fois qu'il sera envoyé vers l'amont, il sera filtré pour fournir une couverture plus complète ; le texte de description de l'outil ne sera pas traité. Le test est également plus rapide et les résultats sont cohérents avec ceux d’avant.
  • L'importation de l'utilisation du Codex est plus rapide (#9400) : moins d'analyses répétées et d'allocation de mémoire lors de la lecture des journaux de session Codex.

Correction

  • Claude Code / Claude Desktop signale occasionnellement 400 "L'élément demandé a été créé sous une autre ressource Azure OpenAI" lors du transfert du format OpenAI Responses via le routeur, puis signale une erreur à chaque fois dans la même session (#9424). Le transfert distribue la même session à différentes ressources Azure OpenAI, et l'historique de la session contient les enregistrements de pensées générés par une autre ressource ; un invalid_encrypted_content similaire sera signalé si le fournisseur est changé au cours de la session. Désormais, lorsque l'amont refuse de cette manière, il supprimera ces enregistrements de pensées et réessayera automatiquement, et la session pourra continuer. Les demandes normales ne sont pas affectées.
  • Lorsque Claude Code est connecté au format Gemini Native en amont via le routage, l'appel de l'outil parallèle rapportera 400 "nombre de parties de réponse de fonction" (#9453) : Les résultats de l'outil dispersés dans plusieurs messages seront désormais fusionnés avant d'être envoyés.
  • Lorsque Claude Code se connecte au format Gemini Native en amont via le routage, le taux de réussite du cache de session longue n'est qu'environ 20 % (#9450) : Claude Code ajoutera une invite de jeton restante à chaque tour. Il était auparavant déplacé au premier plan de toute l’histoire, ce qui entraînait un début différent de chaque tour. En restant désormais dans la position d'origine, l'historique précédent reste inchangé à chaque tour et le cache peut être atteint.
  • Lorsque Claude Code se connecte au format Gemini Native en amont via le routage, l'utilisation des enregistrements de requêtes de streaming est faible et les lectures du cache sont souvent enregistrées comme 0 (#9464).
  • L'invite de survol "CC Switch" de l'icône de la barre d'état sur macOS reste toujours bloquée à l'écran et ne peut quitter l'application (#9445, #9329, #9446) : cette invite ne s'affiche plus sur macOS, et les points sur l'icône et le panneau de raccourcis vous rappelleront toujours en cas de problème.
  • Lorsque d'autres applications sur macOS sont en plein écran, cliquer sur l'icône de la barre de menu n'affiche pas le panneau de raccourcis (#9331).
  • En mode de routage Claude Code, le CLAUDE_CODE_SUBAGENT_MODEL_FORCE défini dans le fournisseur ne peut pas être écrit dans settings.json (#9451, #9455) : il est désormais écrit avec le fournisseur comme les autres paramètres spécifiques au fournisseur, et vos propres paramètres globaux ne seront pas effacés par le changement.
  • Codex Après avoir poursuivi une ancienne conversation terminée, l'utilisation nouvellement générée n'a pas été importée (#9420).
  • Lorsque Codex est directement connecté à un fournisseur tiers, la désactivation de « Conserver la connexion officielle pendant le changement sans prise de contrôle » ne prendra pas effet immédiatement. Vous devez revenir à la carte officielle puis revenir en arrière (#9367) : Désormais, après avoir modifié les paramètres, la configuration actuelle du fournisseur sera écrasée.
  • Pour le modèle GPT portant le même nom que celui officiel du fournisseur tiers Codex, le nom d'affichage affiché dans la sélection du modèle n'est pas le nom d'affichage que vous avez défini (#9380).
  • Après la désinstallation de Claude Desktop sur macOS, la page "Applications" le répertorie toujours comme installé (#9383) : Désormais, seul Claude.app est reconnu et les répertoires de données restants ne sont plus comptés.
  • Le bouton Copier s'affiche avec succès sous Linux KDE Wayland, mais le presse-papiers est vide ou contient encore un ancien contenu (#9384).
  • Dans la liste déroulante des comptes de la carte officielle Copilot CLI, l'option permettant de ne pas lier un compte indique "Utiliser le compte par défaut", mais utilise en fait la propre connexion GitHub de Copilot CLI (#9408) : Maintenant, il est indiqué "Suivez la propre connexion de Copilot CLI".
  • Les modèles DeepSeek Harness ajoutés manuellement ne peuvent pas définir les options de compatibilité (#9330) : L'éditeur de compatibilité est désormais également affiché et ce caractère peut être désactivé pour les interfaces telles que le mode de compatibilité Bailian qui n'acceptent pas le caractère developer.
  • Lors de l'activation de Skill, il indique que la création du lien symbolique a échoué et que la raison spécifique ne peut pas être vue (#9439) : le rapport d'erreur contient désormais le code d'erreur fourni par le système (comme os error 5 sous Windows), ce qui permet de déterminer plus facilement s'il s'agit d'un problème d'autorisation ou d'autres raisons.
  • Dans « Applications » et « Paramètres » en bas de la barre latérale, le texte est tronqué dans les interfaces allemande, turque et russe.

cc-switch v4.0.31

Highlights

  • WorkBuddy integration — Tencent WorkBuddy is now a managed app with multiple simultaneously active providers (#8757). Custom models are written to its models.json, while MCP, Skills, prompts, sessions, and usage data can be synchronized. Only OpenAI Chat Completions is supported for custom models, and duplicate model IDs are rejected.
  • WorkBuddy account switching — The authorization center displays account plans, remaining credits, and expiration dates. Fully quit WorkBuddy—including its tray—before switching, or it may overwrite the new login; quota data is refreshed only while WorkBuddy is running and signed in.
  • Recovery for broken Azure-backed sessions — When an OpenAI Responses relay routes conversation history to a different Azure resource, CC Switch now removes incompatible reasoning records and retries once (#9424). This can recover sessions stuck on repeated 400s, including after a mid-conversation provider change.
  • Better Gemini Native routing and caching — Tool results split across messages are now combined, avoiding parallel-tool-call 400 errors (#9453). Per-turn token notices stay in place instead of being moved to the start of history, preserving cache prefixes and improving long-conversation cache hits (#9450).
  • Privacy filtering covers late-added content — Filtering now runs immediately before every upstream request, including failover retries and CC Switch-generated summaries (#9460). Tool descriptions remain unfiltered, so sensitive information embedded there is not covered.
  • Database upgrade prevents downgrade — The schema moves from version 25 to 26 for WorkBuddy MCP/Skills toggles. Backups are automatic, but older versions cannot open the upgraded database; keep the backup if rollback may be needed.

CC Switch v4.0.31

本版本新增受管应用腾讯 WorkBuddy：自定义模型写进 WorkBuddy 自己的模型配置，在 WorkBuddy 里直接就能选；还能在多个 WorkBuddy 账号之间切换，切换前先看到每个号的套餐、剩余积分和到期时间。界面新增德语，README 也有了全部八种界面语言的版本。

另外修复了 Claude Code 经路由连 OpenAI Responses 格式的中转时，会话被同一个中转分到不同 Azure 资源后每一轮都报 400、再也继续不了；经路由连 Gemini Native 格式上游时，并行工具调用报 400、缓存命中率很低；macOS 托盘悬停提示一直挂在屏幕上；Codex 续接的旧对话用量从不导入等问题。

新增

WorkBuddy

腾讯 WorkBuddy 成为新的受管应用（#8757，需求见 #4802、#5802、#7419、#7076）。和 OpenCode 一样是多个供应商同时生效：

  • 自定义模型：点「添加」后，供应商的模型写进 WorkBuddy 自己的 models.json，在 WorkBuddy 的模型选择里显示为「名称:模型 ID」，名称留空时用「厂商标签」。WorkBuddy 里自己添加的模型原样保留。WorkBuddy 的自定义模型只支持 OpenAI Chat Completions 格式。
    • 预设里的模型在 WorkBuddy 的模型选择里可以选思考强度（例如 Kimi K3.1 Pro 的 low / high / max）。
    • WorkBuddy 暂时不支持同一个模型 ID 出现两次。选预设时会跳过已被别的卡片用掉的模型并说明是哪张卡；手动填了重复的模型 ID 会标出来，不能保存。
  • 官方账号：在 WorkBuddy 里登录过的账号会自动收录到「授权中心」，显示昵称、套餐、剩余积分和积分到期时间（三天内到期标橙）。切换账号有两个入口：添加绑定了这个账号的「WorkBuddy 官方登录」卡片，或者在授权中心这个账号的菜单里点「切换 WorkBuddy 到这个账号」。
    • 切换前要先完全退出 WorkBuddy（包括菜单栏 / 托盘），否则它会把当前登录写回去。
    • 「登录另一个账号」只在本机让 WorkBuddy 停在登录页，不会在服务端登出当前账号，已收录的账号仍然可以切回去。
    • 套餐和积分要在 WorkBuddy 正在运行、并且登录着这个账号时才能查到，查到后会缓存显示。
  • MCP、Skills、提示词：同步到 WorkBuddy 的 mcp.json、Skills 目录和全局提示词 CODEBUDDY.md。WorkBuddy 连接器管理的 MCP 条目不会被改动。
  • 会话管理和用量统计：列出 WorkBuddy 会话，从会话日志导入用量。会话不能在终端里恢复。

德语界面，README 八种语言

  • 德语：首次启动按系统语言自动选择，托盘菜单和快捷面板也已翻译。隐私过滤器的占位符在德语界面下和韩语、俄语一样暂用英文。
  • README 新增繁体中文、韩语、土耳其语和俄语版本，和界面的八种语言一一对应。

其他

  • Skills 页面右上角的「⋯」菜单里直接有「立即重新同步」（#9417）：不用再进「存储与同步」里找。
  • 会话管理「按项目」分组时，Codex 桌面版不属于任何项目的对话归到一组「Codex 聊天」（#9415）：不再每个对话各占一组。
  • 请求日志的状态码筛选新增 403、404、502、503、504、520、529（#9425）。

变更

  • 隐私过滤器改在请求发出前的最后一步过滤（#9460）：以前在请求刚进入路由时过滤，故障转移重试、CC Switch 自己生成的压缩摘要等后来加进请求的内容不会被处理。现在每一次发往上游前都会过滤，覆盖更全；工具的说明文字不处理。检测也更快，结果和以前一致。
  • Codex 用量导入更快（#9400）：读取 Codex 会话日志时少做重复的解析和内存分配。

修复

  • Claude Code / Claude Desktop 经路由连 OpenAI Responses 格式的中转时，偶尔报 400「The requested item was created under a different Azure OpenAI resource」，之后同一会话每一轮都报错（#9424）。中转把同一个会话分到了不同的 Azure OpenAI 资源，会话历史里带着另一个资源生成的思考记录；会话中途换供应商也会报类似的 invalid_encrypted_content。现在上游这样拒绝时，会去掉这些思考记录后自动重试一次，会话可以继续。正常的请求不受影响。
  • Claude Code 经路由连 Gemini Native 格式上游时，并行工具调用后报 400「number of function response parts」（#9453）：分散在几条消息里的工具结果现在会合并到一起再发出。
  • Claude Code 经路由连 Gemini Native 格式上游时，长会话缓存命中率只有两成左右（#9450）：Claude Code 每一轮都会追加一条剩余 Token 提示，以前被挪到整段历史的最前面，导致每一轮的开头都不一样。现在留在原来的位置，前面的历史每一轮保持不变，可以命中缓存。
  • Claude Code 经路由连 Gemini Native 格式上游时，流式请求记录的用量偏少，缓存读取常常记成 0（#9464）。
  • macOS 上托盘图标的「CC Switch」悬停提示一直挂在屏幕上，只能退出应用（#9445、#9329、#9446）：macOS 上不再显示这个提示，出问题时图标上的圆点和快捷面板照常提醒。
  • macOS 上其他应用全屏时，点菜单栏图标弹不出快捷面板（#9331）。
  • Claude Code 路由模式下，供应商里设置的 CLAUDE_CODE_SUBAGENT_MODEL_FORCE 写不进 settings.json（#9451、#9455）：现在和供应商的其他专属设置一样随供应商写入，你自己在全局设置的值也不会被切换清掉。
  • Codex 续接已结束的旧对话后，新产生的用量一直没有导入（#9420）。
  • Codex 直连第三方供应商时，关掉「非接管切换时保留官方登录」不会立即生效，要切回官方卡再切回来（#9367）：现在改完设置就会重写当前供应商的配置。
  • Codex 第三方供应商里与官方同名的 GPT 模型，模型选择里显示的不是你设置的显示名（#9380）。
  • macOS 上卸载 Claude Desktop 后，「应用」页仍把它列为已安装（#9383）：现在只认 Claude.app，残留的数据目录不再算。
  • Linux KDE Wayland 上复制按钮提示成功，但剪贴板是空的或还是旧内容（#9384）。
  • Copilot CLI 官方卡的账号下拉里，不绑定账号的选项写着「使用默认账号」，实际用的是 Copilot CLI 自己的 GitHub 登录（#9408）：现在写成「跟随 Copilot CLI 自己的登录」。
  • DeepSeek Harness 手动添加的模型没法设置兼容选项（#9330）：现在也显示兼容性编辑器，可以为百炼兼容模式这类不接受 developer 角色的接口关掉这个角色。
  • 启用 Skill 时提示符号链接创建失败，看不出具体原因（#9439）：报错里现在带上系统给出的错误码（例如 Windows 的 os error 5），方便判断是权限问题还是别的原因。
  • 侧栏底部的「应用」和「设置」，德语、土耳其语、俄语界面下文字被截断。

升级说明

数据库版本从 25 升到 26，为 MCP 和 Skills 增加 WorkBuddy 的开关。升级前会自动备份数据库；升级后再退回旧版本，旧版本会提示数据库版本过新，打不开。
