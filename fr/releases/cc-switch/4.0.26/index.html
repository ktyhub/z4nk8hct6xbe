interrupteur cc v4.0.26

#Commutateur CC v4.0.26 Cette version permet au centre d'autorisation et aux fiches fournisseurs officielles d'afficher le plan d'abonnement de chaque compte. Le compte GitHub Copilot répertoriera tous les quotas plafonnés ; le lien d'importation en un clic peut désormais également importer des fournisseurs de Claude Desktop, MiniMax Code, Kimi Code, DeepSeek Harness et Oh My Pi. La carte Codex peut choisir de conserver le fichier Fast officiel du modèle GPT ; CC Switch vous rappellera lorsque l'agent système reprend les requêtes du Codex et de Grok Build vers le routage local. DeepSeek Harness peut configurer un répertoire de configuration et peut également le gérer une fois installé dans WSL. Cette version a également fait un tour d'optimisation des performances : la liste des fournisseurs, le chargement de la fenêtre principale, le démarrage, la lecture de session et le transfert d'itinéraire sont tous plus rapides, et l'interface n'est plus bloquée lorsque la synchronisation de session occupe la base de données. De plus, la demande de routage est bloquée pendant plus de deux minutes lorsque IPv6 n'est pas disponible, le serveur MCP qui doit être connecté indique que la connexion échoue, la carte de routage Claude Desktop change de modèle et ne prend pas effet, le taux de réussite du cache diminue lorsque le Codex est transféré vers Chat via le routage, la demande Grok du copilote GitHub rapporte 422 et la réponse est affichée à plusieurs reprises, et la fenêtre contextuelle est floue sur les écrans non Retina. Pour le contenu complet de la mise à jour de 4.0, veuillez consulter les [Notes de version de v4.0] (https://github.com/farion1231/cc-switch/blob/main/docs/release-notes/v4.0.4-zh.md). Ajouter

Plan d'abonnement au compte

Dans le passé, seul le compte Claude dans le centre d'autorisation rédigeait le plan d'abonnement, et les autres comptes n'affichaient que la date de connexion. Le compte Max et le compte Free du même service seraient exactement identiques. Désormais, les comptes GitHub Copilot, ChatGPT, Kimi, Antigravity et xAI auront également des plans d'abonnement écrits au début de la deuxième ligne. Les cartes officielles de Codex, Kimi, Antigravity et Gemini CLI, ainsi que les cartes de compte Copilot et xAI, auront également "· Nom du projet" ajouté après le sous-titre.

  • Le nom du plan sur la carte est directement basé sur le résultat de la requête de quota, et aucune requête multiple ne sera envoyée (Kimi, Antigravity et xAI auront une requête parallèle supplémentaire pour obtenir le nom du plan lors de la vérification du quota) ; le nom du plan n'apparaîtra qu'une fois le quota chargé et les cartes qui ne vérifient pas le quota ne seront pas affichées.
  • Si le nom du plan est introuvable, il ne sera tout simplement pas affiché et le montant sera affiché comme d'habitude ; si le rafraîchissement échoue, le dernier plan trouvé sera conservé.
  • La carte Grok Build connectée avec Grok CLI et la carte Antigravity sans compte n'ont pas encore de nom de plan, et cette information ne peut pas être obtenue via leur méthode de vérification du solde.

GitHub Copilot Afficher tous les soldes

Les comptes Copilot n’affichaient auparavant que le pourcentage de demandes avancées. Désormais, chaque élément avec une limite supérieure possède sa propre ligne. Vous pouvez survoler pour voir « Restant/Total », et vous pouvez également voir l'achèvement du code et le nombre de discussions pour le compte gratuit.

  • La demande avancée est renommée Crédits, ce qui est cohérent avec le nom dans le Codex, et il en est de même dans le bac.
  • Le compte gratuit n'a pas de crédits. Auparavant, il était affiché comme « 100 % restant », mais maintenant il est écrit comme « Le plan actuel n'inclut pas », et cet article n'est plus affiché sur la fiche du fournisseur.

L'importation en un clic prend en charge plus d'applications

Auparavant, les liens vers les fournisseurs pour Claude Desktop, MiniMax Code, Kimi Code, DeepSeek Harness et Oh My Pi auraient été purement et simplement rejetés. Les liens vers ces applications peuvent désormais également être importés.

  • Claude Desktop : Lorsque le lien est au format Anthropic et que le nom du modèle commence par claude- (ou qu'aucun modèle n'est écrit), il sera importé dans une carte de connexion directe ; sinon, il sera importé dans une carte de cartographie de modèle et les quatre emplacements seront remplis selon le modèle dans le lien.
  • MiniMax Code, Kimi Code, DeepSeek Harness, Oh My Pi : importé en modèle unique comme Pi, le modèle doit être inclus dans le lien.
  • Oh My Pi lira la clé écrite de certaines manières sous forme de nom de variable d'environnement ou de commande. Après l'importation, il peut envoyer votre clé locale à l'adresse indiquée dans le lien. Ainsi ce type de Clé (commençant par !, pas de lettres minuscules, etc.) sera refusé à l'import.

Les cartes Codex conservent le fichier Fast officiel

Les modèles GPT dans la liste des modèles de cartes tierces du Codex avaient le fichier officiel Fast Speed ​​supprimé, et Fast ne pouvait pas être sélectionné (#5234). Les transferts qui transfèrent des comptes ChatGPT officiels (tels que CPA) prennent en charge Fast. Désormais, dans les « Options avancées » du formulaire du fournisseur du Codex, il y a « Conserver le fichier rapide officiel » sous « Format en amont ». Il est désactivé par défaut et s'affiche uniquement lorsque le format en amont est Réponses. Après avoir ouvert le Codex et sélectionné Rapide, la requête contiendra service_tier=priority.

  • Seuls les transferts vers des comptes ChatGPT officiels seront reconnus, ce qui consommera le quota plus rapidement ; d'autres amonts peuvent signaler une erreur ou être facturés à un prix plus élevé.
  • Si vous avez déjà sélectionné Fast sous la carte officielle, cela prendra effet ici immédiatement après son ouverture. Il ne prend pas effet en mode agrégation. Le Codex doit être redémarré après modification.

Alerte lorsque l'agent système reprend la route locale

Lorsque les outils proxy tels que Clash sont activés, les requêtes envoyées par Codex et Grok Build à la route locale (http://127.0.0.1:<port>) peuvent être récupérées par le proxy système et transférées vers le nœud distant avant de renvoyer un 502 vide (#9221). Le Codex affiche uniquement « 502 Bad Gateway » et CC Switch ne peut pas recevoir de demandes. Il n'y a pas de journaux, c'est donc difficile à vérifier. Désormais, une fois que Codex ou Grok Build entre en mode routage, CC Switch enverra une requête à la route locale en arrière-plan selon les mêmes règles de proxy que le client. Lorsque la demande ne peut être retournée, un avertissement sera enregistré dans le journal ; si vous entrez manuellement en mode routage, une invite apparaîtra sur l'interface expliquant comment connecter directement l'adresse locale dans l'outil proxy (par exemple, ajoutez IP-CIDR,127.0.0.0/8,DIRECT,no-resolve au début de la règle Clash).

Répertoire de configuration du harnais DeepSeek

Dans le passé, DeepSeek Harness ne reconnaissait que DSH_HOME ou ~/.dsh, et le DSH installé dans WSL ne pouvait pas être géré dans la version Windows de CC Switch (#9239). Il existe désormais une colonne DeepSeek Harness dans "Paramètres → Configuration de l'application", où vous pouvez définir le répertoire de configuration. Les fournisseurs, les compétences, les fichiers de directives, les sessions et les importations d'utilisation suivent tous ce répertoire. Lorsque vous renseignez le chemin dans WSL, la détection de version, l'installation et la mise à niveau seront également effectuées dans cette distribution WSL.

Changement

  • Optimisation des performances :
    • La liste des fournisseurs est lue plus rapidement, et plus il y a de fournisseurs, plus elle est évidente ; les fournisseurs inchangés ne seront plus écrits à plusieurs reprises dans la base de données et la synchronisation cloud ne sera pas déclenchée (#9180).
    • La page secondaire et l'éditeur de fournisseurs sont modifiés pour être chargés lors de leur utilisation, et les scripts à charger au démarrage de la fenêtre principale sont réduits de moitié (#9181).
    • Le nettoyage des journaux au démarrage est déplacé en arrière-plan ; l'actualisation programmée est suspendue lorsque la fenêtre est masquée ou réduite, et actualisée comme d'habitude lorsque la fenêtre est visible mais pas au premier plan (#9182).
    • Lors de la lecture des enregistrements de session, copiez les données une fois de moins et le cache de session sera libéré après être entré en mode léger (#9183).
    • Routage des réponses en streaming sans beaucoup de copie de mémoire, surtout lorsque la réponse est longue ; le basculement lit la base de données moins souvent (#9161).
  • L'interface n'est plus bloquée lors de la synchronisation de session (#9178) : Les fichiers de session volumineux occuperont la base de données pendant des dizaines de secondes lors de la synchronisation. Pendant cette période, l'ouverture de la page Compétences, le passage à Pi ou Oh My Pi, l'ouverture des paramètres réseau ou de données, la sélection d'icônes, le panneau de fournisseur unifié, le test de vitesse et d'autres opérations entraîneront le blocage de toute la fenêtre et de la barre d'état jusqu'à ce que la synchronisation soit terminée. Désormais, ces opérations attendent en arrière-plan et l'interface répond comme d'habitude.
  • Refonte de la barre d'outils sur la page de lecture de session (#9109) : La première ligne contient le chemin et les outils de lecture, et la deuxième ligne contient l'heure, les statistiques de session, les modèles et l'utilisation ; le point de séparation qui tombe facilement au début et à la fin de la ligne est supprimé. Si le nom du modèle est trop long, il sera affiché sur une nouvelle ligne. Vous pouvez survoler pour voir le nom complet.
  • Par défaut : Le modèle par défaut de Grok Build est modifié en grok-4.7, le modèle par défaut du préréglage Kimi (sauf Codex) est modifié en kimi-k3.1-pro, le modèle par défaut du plan de codage Qianwen d'Hermes est modifié en qwen3.7-plus (#9193) ; TeamoRouter change en nom de domaine teamorouter.com ; le lien de téléchargement de la carte officielle Claude Desktop est remplacé par claude.com/download. Les fournisseurs déjà ajoutés ne sont pas concernés.

Correction

  • Lorsque IPv6 n'est pas disponible, les demandes de routage seront retardées de plus de deux minutes avant d'être envoyées (#9212). Les noms de domaine de services tels que Zhipu GLM et Alibaba Cloud Bailian résoudront d'abord les adresses IPv6. Dans un réseau où IPv6 est bloqué, le routage local devra attendre que le système expire chaque adresse IPv6 avant de passer à IPv4. Cela prend environ 150 secondes sous macOS et environ 43 secondes sous Windows. Désormais, si l'adresse IPv6 ne peut pas être connectée dans les 300 millisecondes, elle essaiera IPv4 en même temps et le contenu de la requête restera inchangé.
  • Le serveur MCP qui nécessite une connexion, la vérification de la connectivité affiche « Échec de la connexion » (#9190). Les serveurs tels que Notion et Sentry nécessitent une connexion OAuth. Une fois connectés au client, ils peuvent être utilisés normalement. Cependant, lorsque CC Switch vérifie sans les informations de connexion du client, il est considéré comme ayant échoué. Cette situation affiche désormais un point jaune et le survol indiquera que le serveur peut être connecté, mais nécessite uniquement une connexion. CC Switch ne lit toujours pas les informations de connexion enregistrées du client.
  • Une fois le modèle de la carte de routage Claude Desktop modifié, l'ancien modèle est toujours dans Claude Desktop, alors supprimez-le et reconstruisez-le (#9203). Lors de l'enregistrement, si le « Nom d'affichage du menu » reste vide, le nom du modèle sera automatiquement renseigné. Si vous ne modifiez le modèle que plus tard, le nom d'affichage sera toujours l'ancien. Désormais, lorsque le nom d'affichage est le même que l'ancien nom du modèle, il sera modifié avec le nouveau modèle et le nom que vous vous êtes donné restera inchangé.
  • Lorsque le Codex est transféré vers Chat via le routage, le taux de réussite du cache diminue une fois les paramètres modifiés au cours de la conversation. Par exemple, après être passé à sandbox_mode à mi-chemin, le Codex insérera une description au début de ce tour. Auparavant, il était fusionné au début de la conversation, réécrivant tout l'historique, et tous les caches en amont devenaient invalides. Cette note reste désormais en place et l'historique précédent reste inchangé.
  • Lorsque le Codex est acheminé via Chat, le contenu de réflexion d'une autre session peut être mélangé à la session en cours. L'ID d'appel d'outil fourni par l'amont est facile à répéter (comme exec_command:0). Une fois la route locale redémarrée ou le cache vidé, des appels portant le même nom dans d'autres sessions peuvent être trouvés. Désormais distingué par session Codex, recherchez uniquement au sein de la même session.
  • Lorsque la demande de routage échoue, le nom du modèle du client est enregistré dans le journal des demandes. Par exemple, la tâche en arrière-plan de Claude Desktop utilise claude-haiku-4-5-20251001. Après avoir mappé sur le modèle de cette carte, l'amont rapporte 429, mais le journal montre Haiku. Il semble qu'un modèle que vous n'avez pas configuré soit appelé. Désormais, les requêtes ayant échoué seront écrites sous la forme "claude-haiku-4-5-20251001 → modèle actuel", tout comme les requêtes réussies.
  • La carte officielle de Claude qui suit la connexion locale affichera toujours "Jeton à actualiser" après l'expiration de la connexion, et vous devrez réexécuter Claude Code pour récupérer. Désormais, lorsque la connexion expirera, CC Switch demandera à Claude Code d'actualiser la connexion elle-même et de relire le quota. Ignorer lorsque le répertoire de configuration Claude est défini.
  • Lorsque le classificateur de sécurité du mode automatique Claude Code et Claude Desktop n'est pas disponible, le client continuera de réessayer et continuera à consommer le quota (#9201, #9199). Désormais, lorsque trois séries consécutives de résultats de l'outil signalent que le classificateur n'est pas disponible, la route locale renvoie directement une erreur et ne l'envoie plus vers l'amont ; envoyez un nouveau message pour continuer.
  • Codex via GitHub Copilot avec le modèle Grok fois 422 (#7989, #7988). Désormais, les requêtes Grok de Copilot sont traitées de la même manière que le xAI direct.
  • Lorsque le Codex passe GitHub Copilot, la même réponse s'affiche deux fois (#8025, #7977).
  • Lors de l'installation ou de la mise à niveau d'une application, un fichier existant portant le même nom est rencontré et l'invite contient uniquement --force (#9196, #9173) recommandé par npm. Ce fichier provient probablement d'une autre méthode d'installation et --force l'écrasera directement. L'invite écrira désormais le chemin du fichier en conflit. Il est recommandé de renommer la sauvegarde et de réessayer.
  • La synchronisation automatique WebDAV échoue lorsqu'il existe des liens symboliques vers des fichiers dans Skills (#9197). Par exemple, lorsque CLAUDE.md et GEMINI.md sont tous deux liés à AGENTS.md, des fichiers portant le même nom apparaîtront dans le package. Chaque fichier conserve désormais son propre nom.
  • Deux problèmes avec la limite supérieure simultanée du sous-agent Codex (#9148) : lorsque config.toml a des commentaires derrière l'en-tête du tableau, la modification de la limite supérieure peut écraser [features.multi_agent_v2] ; lorsque [agents] est écrit sous forme de nom de clé avec des guillemets, un champ en double supplémentaire sera écrit et n'est pas reconnu par le Codex. La description ajoute également que les modifications ne prennent effet que pour les nouvelles sessions.
  • DeepSeek Harness ne parvient pas à trouver la clé enregistrée par CC Switch lors de l'utilisation du profil sans tête, signalant MISSING_CREDENTIAL. La lecture des informations d'identification sera désormais activée conformément au document DSH lors de l'écriture sur un profil sans tête ; les profils que vous avez modifiés cet élément resteront inchangés.
  • Sur les moniteurs 1x, les fenêtres contextuelles telles que « Sélectionner le modèle » apparaissent floues (#9238). Lorsque la fenêtre contextuelle est centrée, elle peut tomber sur un demi-pixel et le texte et les bordures apparaîtront flous sur les écrans non Retina.
  • Sous macOS, lors de la saisie dans des zones de saisie telles que des formulaires MCP, des éditeurs de mots d'invite, un entrepôt de compétences, une recherche de session, etc., la première lettre est automatiquement remplacée par une majuscule et les noms des variables d'environnement, les en-têtes de requête, les commandes et les adresses peuvent en conséquence être stockés de manière incorrecte.
  • Linux AppImage contient l'ancienne version de libwayland-client (#9229, #8723), qui ne peut pas être ouverte dans un environnement avec Intel Core Graphics et Wayland.

cc-switch v4.0.26

Highlights

  • Subscription visibility — Authorization and official-provider cards now show plan names and every metered GitHub Copilot quota, including Free-tier chat and completions. Free accounts report “not included” instead of a misleading 100% for Credits; plan names appear only after quota loading and silently disappear on lookup failure.

  • Broader one-click imports — Links now work for Claude Desktop, MiniMax Code, Kimi Code, DeepSeek Harness, and Oh My Pi. Claude Desktop links become direct connections only when using Anthropic-format claude-* models or no model; otherwise they become model-mapping cards. The other four require an explicit model, and dangerous Oh My Pi key syntax—such as !-prefixed values—is rejected to prevent accidental credential exposure.

  • Codex Fast tier and new behavior — Responses-format Codex providers can opt into Preserve official Fast tier, adding service_tier=priority when Fast is selected. This works only with gateways that forward official ChatGPT accounts, may consume quotas faster or fail elsewhere, does not apply in aggregate mode, and requires restarting Codex. Prior Fast selections activate once enabled.

  • Proxy and WSL diagnostics — Codex and Grok Build now probe local routes under the client’s proxy rules, warning when requests may escape to a proxy node and return an empty 502; add 127.0.0.0/8 to your proxy’s direct rules. DeepSeek Harness gains a configurable directory covering providers, Skills, instructions, sessions, and usage, with WSL paths also used for detection, installation, and upgrades.

  • Faster, more responsive routing — Lazy loading, reduced database writes and copies, background startup maintenance, and streamlined streaming reduce startup, session, and forwarding overhead (#9180, #9181, #9183, #9161). Session synchronization now queues UI actions instead of freezing the window and tray (#9178), while IPv6 connection failures fall back to IPv4 after 300 ms rather than waiting roughly 150 seconds on macOS (#9212).

  • Routing correctness fixes — Failed requests now log both the client-requested and actual upstream models, making mapping-related 429s diagnosable. Codex-to-Chat preserves history when settings change, preventing cache invalidation, and isolates tool-call lookup by session to stop cross-session reasoning leakage (#9203 covers a related Claude Desktop model-rename fix). Also notable: unavailable safety classifiers now stop after three rounds instead of retrying indefinitely (#9201); manually customized Claude configuration directories skip automatic login refresh.

CC Switch v4.0.26

本版本让授权中心和官方供应商卡片显示每个账号的订阅计划，GitHub Copilot 账号会列出所有有上限的额度；一键导入链接现在也能导入 Claude Desktop、MiniMax Code、Kimi Code、DeepSeek Harness 和 Oh My Pi 的供应商。Codex 卡片可以选择保留 GPT 模型的官方 Fast 档；系统代理把 Codex、Grok Build 发往本地路由的请求接走时，CC Switch 会提醒你。DeepSeek Harness 可以设置配置目录，装在 WSL 里也能管理。这一版还做了一轮性能优化：供应商列表、主窗口加载、启动、会话读取和路由转发都更快，会话同步占着数据库时界面也不再卡住。另外修复了 IPv6 不通时经路由请求先卡两分多钟、需要登录的 MCP 服务器显示连接失败、Claude Desktop 路由卡片改了模型不生效、Codex 经路由转 Chat 时缓存命中率下降、GitHub Copilot 的 Grok 请求报 422 和回复重复显示、非 Retina 显示器上弹窗模糊等问题。4.0 完整的更新内容请见 v4.0 发布说明。

新增

账号订阅计划

以前授权中心里只有 Claude 账号会写订阅计划，其他账号只显示登录日期，同一个服务的 Max 账号和 Free 账号看起来一模一样。

现在 GitHub Copilot、ChatGPT、Kimi、Antigravity、xAI 账号的第二行开头也会写订阅计划。Codex、Kimi、Antigravity、Gemini CLI 的官方卡片，以及 Copilot、xAI 账号卡片，副标题后面也会加上「· 计划名」。

  • 卡片上的计划名直接用额度查询的结果，不会多发请求（Kimi、Antigravity、xAI 查额度时会多一个并行请求取计划名）；额度加载出来后计划名才出现，不查额度的卡片不显示。
  • 计划名查不到时只是不显示，额度照常显示；刷新失败时保留上次查到的计划。
  • 跟随 Grok CLI 登录的 Grok Build 卡片、没绑账号的 Antigravity 卡片暂时还没有计划名，它们查额度的方式拿不到这项信息。

GitHub Copilot 显示全部额度

Copilot 账号以前只显示高级请求的百分比。现在每一项有上限的额度各占一行，悬停可以看到「剩余 / 共」，Free 账号的代码补全和聊天次数也能看到了。

  • 高级请求改叫 Credits，和 Codex 的叫法一致，托盘里也一样。
  • Free 账号没有 Credits，以前会显示成「还剩 100%」，现在写「当前计划不含」，供应商卡片上不再显示这一项。

一键导入支持更多应用

以前 Claude Desktop、MiniMax Code、Kimi Code、DeepSeek Harness 和 Oh My Pi 的供应商链接会直接被拒绝。现在这些应用的链接也能导入了。

  • Claude Desktop：链接是 Anthropic 格式、模型名都以 claude- 开头（或没写模型）时，导入成直连卡片；其他情况导入成模型映射卡片，四个档位按链接里的模型填好。
  • MiniMax Code、Kimi Code、DeepSeek Harness、Oh My Pi：和 Pi 一样导入成单个模型，链接里必须带模型。
  • Oh My Pi 会把某些写法的 Key 当成环境变量名或命令来读，导入后可能把你本机的密钥发到链接里的地址。所以这类 Key（以 ! 开头、没有小写字母等）会被拒绝导入。

Codex 卡片保留官方 Fast 档

Codex 第三方卡片模型列表里的 GPT 模型以前一律去掉了官方的 Fast 速度档，选不了 Fast（#5234）。转发官方 ChatGPT 账号的中转（如 CPA）其实支持 Fast。

现在 Codex 供应商表单「高级选项」里，「上游格式」下面多了「保留官方 Fast 档」，默认关闭，只在上游格式为 Responses 时显示。打开后 Codex 选了 Fast 时请求会带 service_tier=priority。

  • 只有转发官方 ChatGPT 账号的中转才认，会更快消耗额度；其他上游可能报错或按更高价格计费。
  • 以前在官方卡片下选过 Fast 的，打开后会马上在这家生效。聚合模式下不生效，改完需要重启 Codex。

系统代理接走本地路由时提醒

开着 Clash 这类代理工具时，Codex 和 Grok Build 发往本地路由（http://127.0.0.1:<port>）的请求可能被系统代理接走，转到远程节点后返回一个空的 502（#9221）。Codex 只显示「502 Bad Gateway」，CC Switch 这边也收不到请求，没有任何日志，很难查。

现在 Codex 或 Grok Build 进入路由模式后，CC Switch 会在后台按客户端同样的代理规则给本地路由发一次请求。请求回不来时，日志里会记一条警告；如果是你手动进入路由模式，界面上也会弹出提示，说明怎么在代理工具里让本机地址直连（例如在 Clash 规则最前面加 IP-CIDR,127.0.0.0/8,DIRECT,no-resolve）。

DeepSeek Harness 配置目录

以前 DeepSeek Harness 只认 DSH_HOME 或 ~/.dsh，装在 WSL 里的 DSH 在 Windows 版 CC Switch 里管不了（#9239）。

现在「设置 → 应用配置」里多了 DeepSeek Harness 一栏，可以设置配置目录。供应商、Skills、指令文件、会话和用量导入都会跟着这个目录走。填 WSL 里的路径时，版本检测、安装和升级也会在那个 WSL 发行版里进行。

变更

  • 性能优化：
    • 供应商列表读取更快，供应商越多越明显；没改动的供应商不再重复写入数据库，也就不会因此触发云同步（#9180）。
    • 次要页面和供应商编辑器改为用到时才加载，主窗口启动要加载的脚本少了一半（#9181）。
    • 启动时的日志清理挪到后台进行；窗口隐藏或最小化时暂停定时刷新，窗口可见但不在前台时照常刷新（#9182）。
    • 读取会话记录时少复制一遍数据，进入轻量模式后会释放会话缓存（#9183）。
    • 路由转发流式响应时少了大量内存复制，响应很长时尤其明显；故障转移读数据库的次数也更少（#9161）。
  • 会话同步时界面不再卡住（#9178）：大会话文件同步时会占着数据库几十秒，这期间打开 Skills 页、切到 Pi 或 Oh My Pi、打开网络或数据设置、图标选择、统一供应商面板、测速等操作会让整个窗口和托盘卡住，直到同步结束。现在这些操作都在后台等待，界面照常响应。
  • 会话阅读页的工具栏重新排版（#9109）：第一行放路径和阅读工具，第二行放时间、会话统计、模型和用量；去掉了容易落在行首行尾的分隔点，模型名太长时换行显示，悬停可看完整名称。
  • 预设： Grok Build 默认模型改为 grok-4.7，Kimi 预设（Codex 的除外）默认模型改为 kimi-k3.1-pro，Hermes 的千问 Coding Plan 默认模型改为 qwen3.7-plus（#9193）；TeamoRouter 改用 teamorouter.com 域名；Claude Desktop 官方卡片的下载链接改为 claude.com/download。已添加的供应商不受影响。

修复

  • IPv6 不通时，经路由的请求要先卡两分多钟才发出（#9212）。智谱 GLM、阿里云百炼等服务的域名会先解析出 IPv6 地址，在 IPv6 不通的网络里，本地路由要等系统把每个 IPv6 地址都超时一遍才改用 IPv4，macOS 上约 150 秒、Windows 上约 43 秒。现在 IPv6 地址 300 毫秒内连不上就同时尝试 IPv4，发出的请求内容不变。
  • 需要登录的 MCP 服务器，连通性检查显示「连接失败」（#9190）。Notion、Sentry 这类服务器需要 OAuth 登录，客户端里登录后能正常用，但 CC Switch 检查时不带客户端的登录凭据，就被判成了失败。现在这种情况显示黄色圆点，悬停会说明服务器能连上、只是要求登录。CC Switch 仍然不读取客户端保存的登录凭据。
  • Claude Desktop 路由卡片改了模型后，Claude Desktop 里还是旧模型，删掉重建才行（#9203）。保存时「菜单显示名」留空会自动填成模型名，之后只改模型时显示名还是旧的。现在显示名和旧模型名一样时会跟着新模型一起改，你自己起的名字保持不变。
  • Codex 经路由转 Chat 时，对话中途改了设置后缓存命中率下降。比如中途切换 sandbox_mode 后，Codex 会在这一轮开头插入一条说明，以前它被合并到对话最开头，改写了整段历史，上游缓存就全部失效了。现在这条说明留在原位，之前的历史保持不变。
  • Codex 经路由转 Chat 时，可能把另一个会话的思考内容混进当前会话。上游给的工具调用 ID 容易重复（如 exec_command:0），本地路由重启或缓存被挤掉后，可能找到别的会话里同名的调用。现在按 Codex 会话区分，只在同一个会话里找。
  • 路由请求失败时，请求日志里记的是客户端的模型名。比如 Claude Desktop 的后台任务用的是 claude-haiku-4-5-20251001，映射到这张卡片的模型后上游报 429，日志里却显示 Haiku，看起来像调用了一个你没配过的模型。现在失败的请求和成功的一样，会写成「claude-haiku-4-5-20251001 → 实际模型」。
  • 跟随本机登录的 Claude 官方卡片，登录过期后一直显示「令牌待刷新」，要再跑一次 Claude Code 才恢复。现在登录过期时 CC Switch 会让 Claude Code 自己刷新登录，再读取额度。设置了 Claude 配置目录时跳过。
  • Claude Code 和 Claude Desktop 自动模式的安全分类器不可用时，客户端会一直重试、持续消耗额度（#9201、#9199）。现在连续 3 轮工具结果都报告分类器不可用时，本地路由直接返回错误，不再发给上游；发一条新消息即可继续。
  • Codex 通过 GitHub Copilot 用 Grok 模型时报 422（#7989、#7988）。现在 Copilot 的 Grok 请求和直连 xAI 一样做兼容处理。
  • Codex 通过 GitHub Copilot 时，同一条回复显示两遍（#8025、#7977）。
  • 安装或升级应用时撞上已有的同名文件，提示里只有 npm 建议的 --force（#9196、#9173）。这个文件多半来自另一种安装方式，用 --force 会直接覆盖它。现在提示会写出冲突的文件路径，建议先改名备份再重试。
  • Skills 里有文件软链接时，WebDAV 自动同步失败（#9197）。比如 CLAUDE.md 和 GEMINI.md 都链接到 AGENTS.md 时，打包会出现重名文件。现在每个文件保留自己的名字。
  • Codex 子代理并发上限的两个问题（#9148）：config.toml 里表头后面带注释时，改上限可能覆盖掉 [features.multi_agent_v2]；[agents] 写成带引号的键名时，会多写一个 Codex 不认的重复字段。说明文字也补充了改动只对新会话生效。
  • DeepSeek Harness 用 headless profile 时找不到 CC Switch 保存的 Key，报 MISSING_CREDENTIAL。现在写入 headless profile 时会按 DSH 文档开启凭据读取；你自己改过这一项的 profile 保持不变。
  • 在 1x 显示器上，「选择模型」等弹窗显示模糊（#9238）。弹窗居中时可能落在半个像素上，非 Retina 显示器上文字和边框会发虚。
  • macOS 上，在 MCP 表单、提示词编辑、Skills 仓库、会话搜索等输入框里打字时首字母被自动改成大写，环境变量名、请求头、命令、地址可能因此被存错。
  • Linux AppImage 打包了旧版 libwayland-client（#9229、#8723），在 Intel 核显加 Wayland 的环境下可能打不开。
