#Commutateur CC v4.0.21 Cette version ajoute la commutation entre plusieurs comptes d'abonnement officiels pour Claude Code : ajoutez plusieurs comptes Claude dans le centre d'autorisation, choisissez-en un pour chaque carte officielle, et quelle que soit la carte vers laquelle vous basculez, Claude Code utilisera ce numéro ; si vous souhaitez utiliser plusieurs numéros en même temps, "ouvrez le terminal" depuis la carte, ce terminal utilisera toujours le numéro présent sur la carte. Connectez-vous et suivez le processus officiel de Claude Code. Le token ne restera que dans le Code Claude de la machine locale. CC Switch ne téléchargera pas, n’actualisera pas et ne se déconnectera pas. Les cartes liées aux comptes et le centre d'autorisation afficheront le forfait et le solde restant de chaque compte. De plus, "Open Terminal" a été déplacé vers la carte, et la liste des modèles du Codex peut être glissée et triée, qui sera conservée après le redémarrage en mode léger. Des problèmes tels que l’impossibilité de modifier. Ajouter

Basculer entre plusieurs comptes d'abonnement officiels Claude

Lorsque vous disposez de plusieurs abonnements Claude (tels que Max personnel et Team d'entreprise, ou plusieurs comptes Pro), vous pouvez uniquement créer /logout puis /login dans Claude Code, ou créer vous-même un répertoire de configuration pour chaque compte. Il est désormais possible de gérer plusieurs comptes dans CC Switch (#1928). Pour une comparaison de l'utilisation graphique et de la conformité élément par élément, voir Utiliser CC Switch pour basculer entre plusieurs abonnements officiels Claude et problèmes de conformité. **Sécurité et conformité. ** Le compte d'abonnement est géré par l'outil. La chose la plus importante est que le token soit sûr et ne viole pas les conditions d'Anthropic. Cette fonction est implémentée selon la documentation officielle de Claude Code. Le jeton est toujours uniquement dans votre code Claude local :

  • **Connectez-vous et suivez le processus officiel. ** Lors de l'ajout d'un compte, vous exécutez claude auth login --claudeai fourni avec Claude Code. Le mot de passe et l'autorisation sont renseignés sur la page officielle de claude.ai. CC Switch ne possède pas son propre login Claude, ni son propre client OAuth. La [Page Juridique et Conformité] d'Anthropic (https://code.claude.com/docs/en/legal-and-compliance#authentication-and-credential-use) exige que la connexion à un compte Claude soit effectuée via le propre processus d'Anthropic, et n'empêche explicitement pas les utilisateurs de se connecter au code Claude non modifié avec leurs propres abonnements.
  • **Plusieurs comptes utilisent la méthode officiellement recommandée. ** Chaque compte possède un répertoire de configuration indépendant, distingué par CLAUDE_CONFIG_DIR. La méthode est la même que celle de la section « Se connecter avec plusieurs comptes » du Code Claude [Document de certification] (https://code.claude.com/docs/en/authentication#log-in-with-multiple-accounts). CC Switch crée simplement le répertoire et ouvre le terminal pour vous.
  • **Le jeton ne quitte pas la machine. ** Le token n'existe que dans le propre emplacement de Claude Code (porte-clés pour macOS, .credentials.json pour Linux et Windows), et n'est pas téléchargé, synchronisé avec le cloud, ni écrit dans la base de données CC Switch. CC Switch lui-même se souvient uniquement des informations de compte telles que l'adresse e-mail, l'organisation, le package et le délai d'expiration de la connexion, mais ne se souvient pas des jetons.
  • **N'envoie pas de demandes pour vous. ** CC Switch n'a pas de serveur et ne nécessite pas de jeton d'abonnement pour appeler le modèle ; les demandes de dialogue sont envoyées directement à Anthropic à partir du code Claude local non modifié, et l'utilisation est facturée sur votre propre compte. Lors de la vérification de la limite, vérifiez directement l'interface de limite officielle d'Anthropic sur cette machine, qui correspond aux mêmes données que le /usage de Claude Code.
  • **Pas de rafraîchissement, pas de déconnexion, pas de changement de Code Claude. ** Les jetons sont toujours rafraîchis par Claude Code lui-même. La suppression d'un compte supprimera uniquement le répertoire créé pour lui par CC Switch (ainsi que l'entrée de ce répertoire dans le trousseau sur macOS) et ne permettra pas au compte de se déconnecter n'importe où. CC Switch ne modifie pas les fichiers programme de Claude Code.
  • **Contrôlez simplement votre propre compte. ** Il n'effectue pas automatiquement la rotation des comptes en fonction des quotas et ne fournit pas non plus la fonction de partage d'abonnements avec d'autres. La carte et le numéro seront déplacés et connectés entre les emplacements de stockage du Claude Code local (uniquement au format propre à Claude Code). La documentation officielle ne mentionne pas spécifiquement cette utilisation. Si vous souhaitez simplement utiliser la méthode précisée dans le document, conservez la carte "Connexion avec Claude Code", et les autres comptes ne peuvent être utilisés qu'à partir de la carte "Open Terminal". Comment utiliser :
  • **Ajouter un compte. ** Cliquez sur "Ajouter un compte" dans le groupe Claude du Centre d'Autorisation. Le navigateur ouvrira la page d'autorisation officielle de claude.ai, et le compte apparaîtra automatiquement dans la liste après la connexion. Si le navigateur ne peut pas revenir à la machine après autorisation, vous pouvez coller l'adresse dans la barre d'adresse ou le code sur la page arrière. Les répertoires de chaque compte n'interfèrent pas les uns avec les autres et synchroniseront vos paramètres dans ~/.claude, MCP et CLAUDE.md (à l'exception des identifiants de connexion et des paramètres liés au routage).
  • ** Choisissez un compte pour la carte officielle. ** Le menu déroulant « Méthode de connexion » de la carte officielle de Claude est le même que celui de la carte officielle du Codex : en haut se trouve le compte connecté, et en bas se trouvent « Ajouter ou gérer un compte Claude » (accéder au centre d'autorisation) et « Se connecter avec Claude Code ». Créez simplement une carte pour un compte.
  • **Coupez la carte et le numéro sera coupé. ** Lors du passage à la carte officielle du compte sélectionné, CC Switch met le login de ce compte dans la position où Claude Code le lit par défaut, et le compte d'origine est remis dans son propre répertoire. claude dans le terminal, le plug-in IDE et le script utiliseront tous ce numéro, et le code Claude déjà en cours d'exécution sera également modifié immédiatement sans redémarrage. Lors du passage à la carte officielle du compte sélectionné, la connexion actuelle sera collectée en premier si elle ne se trouve pas déjà dans le centre d'autorisation. Claude Code détient son propre verrou lors de la commutation ; si le commutateur CC se ferme accidentellement pendant la commutation, il sera automatiquement complété ou retiré la prochaine fois qu'il sera commuté ou démarré. Les cartes qui choisissent « Se connecter avec Claude Code » ne seront pas connectées, et celles qui n'ajoutent pas de compte ne seront pas concernées.
  • **Plusieurs numéros sont utilisés en même temps. ** "Open Terminal" sur la carte avec le compte sélectionné. Ce terminal est fixé au numéro présent sur la carte. Changer de carte plus tard n’affectera pas cela.
  • **Forfait et quota. ** Le sous-titre de la carte indique le numéro de compte et le forfait (tels que Max 20x), et une invite s'affiche lorsque la connexion doit être mise à jour ; la limite restante de ce compte est affichée par défaut en bas de la carte, et chaque compte du centre d'autorisation a également la même colonne de limite. Lorsque le token d'un compte inutilisé expire, CC Switch exécutera une fois le claude -p /usage de Claude Code dans son répertoire (jusqu'à une fois toutes les 10 minutes pour chaque compte). Claude Code actualisera la connexion et interrogera lui-même le quota, et CC Switch ne lira que les résultats. /usage n'appelle pas le modèle et ne consomme pas le crédit de dialogue. Les cartes officielles sans compte sélectionné afficheront également le package actuellement connecté. Quelques points à noter :
  • La télécommande que vous utilisez sera déconnectée une fois le numéro modifié ; le premier message après le changement de numéro doit reconstruire le cache d'invite, ce qui sera plus lent et utilisera plus de crédit.
  • Lorsque le répertoire de configuration de Claude est écrasé dans les paramètres (y compris en pointant vers WSL), Cheka ne changera pas de connexion et l'interface vous demandera d'utiliser "Open Terminal" à la place.

La liste des modèles du Codex peut être triée en faisant glisser

La liste des modèles dans le formulaire des fournisseurs Codex comporte une poignée de déplacement au début de chaque ligne et l'ordre peut être ajusté avec la souris ou le clavier (#8870). Cet ordre est l'ordre du menu /model dans le Codex. Lorsque la première ligne représente le modèle par défaut, le modèle glissé vers la première ligne devient le nouveau modèle par défaut. Dans le passé, je devais le supprimer et le rajouter pour le déplacer.

** "Ouvrez le terminal" et déplacez-le vers la carte. ** Auparavant dans le menu ⋯, il s'agit désormais d'un bouton icône à gauche de "Modifier". L'invite de survol est "Ouvrir le terminal avec ce fournisseur". Lorsque le terminal utilise cette carte en permanence (la carte avec votre propre adresse et Clé, la carte officielle avec le compte Claude sélectionné), il dira "(Isolement Environnemental)". **Le bouton « Ajouter un compte » pour chaque groupe du Centre d'autorisation est fixé à droite du titre. ** Dans le passé, lorsqu'il n'y avait pas de compte, le bouton était déplacé vers l'invite vide et les boutons de plusieurs groupes de cartes étaient de hauteurs différentes. La méthode de connexion de ChatGPT est remplacée par une petite liste déroulante à côté du bouton. Le menu « Supprimer tous les comptes » dans le titre a été supprimé et les comptes sont supprimés dans leurs rangées de menus respectives. Les barres de limite de chaque compte sont désormais alignées et ont la même longueur. **Le mode léger reste après le redémarrage. ** Si vous quittez CC Switch en mode léger, il sera toujours en mode léger la prochaine fois que vous le démarrerez et l'interface principale n'apparaîtra plus. La valeur actuelle n'est que la valeur par défaut, identique à OpenClaw, OpenCode et Kimi Code. Le bouton « Activer » de l’ancienne icône d’alimentation ressemblait à un interrupteur. **Lorsque la carte devient « En cours d'utilisation », la colonne d'utilisation ne se déplace plus vers la gauche et la droite. ** MCP indique quelles applications ne sont pas prises en charge lorsque SSE est sélectionné (#8882). Correction

  • Après avoir redémarré le compte ChatGPT géré, il affiche « La connexion a expiré » et ne peut pas être changé. Il récupère après un certain temps (#8901). Dans le passé, tout HTTP 403 rencontré lors de l'actualisation de la connexion était considéré comme un échec de connexion, et les erreurs réseau étaient également affichées comme expirées. Désormais, comme le Codex CLI, seules les erreurs 401 ou d'invalidation de jeton clair sont considérées comme expirées ; les problèmes de réseau temporaires seront réessayés comme d'habitude et le quota conservera le dernier résultat. Une fois le plateau changé, le solde qui n'a pas pu être interrogé dans l'interface principale sera également à nouveau interrogé.
  • Lorsque le Codex était acheminé localement, la demande était envoyée à d'autres adresses (#8849, #8848). Lorsqu'il y a plusieurs tables de fournisseurs dans config.toml, ou qu'il y a une ligne d'anciennes adresses commentées ci-dessus, le premier base_url du texte a été précédemment récupéré et la clé du fournisseur sélectionné sera envoyée ailleurs. Appuyez maintenant sur model_provider pour obtenir l'adresse de la table sélectionnée.
  • L'utilisation de la compression à distance du Codex est parfois manquée (#8879).
  • Il y a des timeout et autoApprove supplémentaires dans la configuration MCP du Codex, la version de bureau du Codex a signalé des paramètres inconnus et --strict-config a refusé de se charger (#8843). Ces deux champs appartiennent à d'autres clients. Ils ont été écrits dans config.toml comme avant. S'ils sont supprimés manuellement, ils seront réécrits lors de leur prochaine synchronisation. Désormais supprimée lors de l'écriture dans le Codex, les autres applications ne seront pas affectées.
  • Lorsque Codex est connecté à plusieurs ressources Azure via un relais, un message 400 « créé sous une autre ressource Azure OpenAI » est signalé au milieu de la session et ne peut pas être poursuivi (#8877). Réessayez maintenant après avoir reçu cette erreur, en supprimant l'ID d'entrée de l'historique. Les demandes normales ne sont pas affectées.
  • ClinePass est un amont qui renvoie les résultats des discussions terminées dans data. Les requêtes sans streaming signalent 422 « Aucun choix en réponse » (#5658).
  • Sous npm 12, l'OpenCode installé sur la page "Application" signale "Incompatible avec la version de Windows que vous exécutez" sous Windows, et Grok Build exécute toujours l'ancienne version après la mise à niveau (#8863). npm 12 n'exécute pas le script d'installation par défaut, et ces deux packages s'appuient sur lui pour placer de vrais programmes. Leurs scripts d'installation sont désormais autorisés lors de l'installation et de la mise à niveau.
  • Hermes sous Windows est affiché sous forme de deux installations sur la page "Applications" (#8839). hermes.cmd laissé dans le même répertoire n’est plus compté comme une installation.
  • Utilisation du code Kimi, le temps de demande pour tout un cycle de dialogue est le même, et lorsqu'il est calculé par heure, il est ramené à la dernière heure (#8899). Enregistrez maintenant l’heure à laquelle chaque demande est terminée. Les enregistrements importés seront corrigés lors de la prochaine modification du fichier de session.
  • Lorsque le models.yml d'Oh My Pi contient name: Search & Fetch, qui contient des valeurs telles que &, * et !, le fournisseur signale "Ce YAML utilise un format ou une syntaxe qui ne peut pas être modifié en toute sécurité par CC Switch" (#8897).
  • Lorsque ~/.gemini/.env est écrit sous la forme export GEMINI_API_KEY=..., il n'y a pas de clé après l'importation et elle sera supprimée du fichier lors du retour au fournisseur par défaut (#8862, #8861).
  • **Lors du passage d'un projet avec des mots d'invite activés à un projet sans mots d'invite, les mots d'invite d'origine ne sont pas désactivés. **
  • Lorsque la barre latérale de la page des statistiques d'utilisation est développée ou réduite, le bord droit du graphique de tendance saute (#8548).

cc-switch v4.0.21

Highlights

  • Multiple official Claude accounts, switchable per card — CC Switch can now manage several Claude.ai subscriptions (personal Max vs. company Team, multiple Pro seats) and swap which one claude uses (#1928). Accounts are added through the official claude auth login --claudeai flow, each in its own CLAUDE_CONFIG_DIR — the same pattern Claude Code's own docs recommend — with settings, MCP config and CLAUDE.md seeded from ~/.claude but credentials and routing left alone. Switching a card moves that account's login into Claude Code's default credential store (macOS Keychain / .credentials.json) under Claude Code's own lock, with automatic completion or rollback on the next launch if the app dies mid-swap; running sessions follow immediately, no restart needed. Tokens never reach CC Switch's database or any server — it stores only email, org and plan metadata, never refreshes or logs out accounts, and deletion only removes the directories it created. For genuinely parallel use, launch a terminal from the card: that shell is pinned to the card's account and unaffected by later switches. Watch-outs: Remote Control sessions disconnect on account change, the first message after a switch rebuilds the prompt cache (slower, extra usage), and if you've overridden the Claude config directory — including pointing it at WSL — card switching deliberately won't move credentials; use "Open Terminal" instead.

  • Codex routing and auth correctness — With multiple provider tables in config.toml, or a commented-out old address above the active one, CC Switch previously grabbed the first base_url in the text and paired it with the selected provider's key — sending both to the wrong host. The address is now resolved from the table named by model_provider (#8849, #8848). Related fixes: Azure relay sessions hit by 400 "created under a different Azure OpenAI resource" now retry once with the prior entry IDs stripped (#8877), remote-compaction usage is no longer lost (#8879), and managed ChatGPT accounts no longer show a false "login expired" and lock out switching on any 403 — only 401 or an explicit token-invalid error counts, matching Codex CLI, with transient failures retried and the last quota result kept (#8901). If you somehow depended on that commented-out URL being used, that behavior is gone.

  • Generated config stays valid under strict validation — CC Switch stops writing timeout and autoApprove into Codex's MCP config (#8843): those fields belong to other clients and triggered "unknown setting" errors in Codex Desktop and outright load failures under --strict-config, with manual deletion undone on the next sync; other applications' configs are unaffected. SSE selection now warns up front (#8882) — Codex accepts only stdio and HTTP and will try to talk HTTP to an SSE-only server, while Pi and Antigravity reject it on save. Editing robustness also improved: ~/.gemini/.env entries written as export GEMINI_API_KEY=... import correctly and no longer get deleted when switching back to the default provider (#8862, #8861), and Oh My Pi models.yml values containing &, *, or ! (e.g. name: Search & Fetch) no longer block saving with "unsupported YAML format" (#8897).

  • Installs and usage metering — npm 12 stopped running install scripts by default, which made the OpenCode install on Windows report "incompatible with your Windows version" and left Grok Build running the old binary after an upgrade; install and upgrade now explicitly allow those packages' scripts (#8863). A leftover hermes.cmd no longer registers as a second Windows installation (#8839), and ClinePass-style upstreams that wrap Chat Completions payloads in data no longer produce 422 "No choices in response" on non-streaming calls (#5658). Kimi Code usage is now timestamped per request completion instead of stamping a whole conversation identically and bunching it into the last hour (#8899); already-imported records correct themselves on the next session-file change.

  • Model and card workflow polish — The Codex provider form's model list is drag-reorderable with mouse or keyboard, and that order is literally the /model menu order — drag a model to the top to make it the default, replacing the delete-and-re-add workaround (#8870). "Open Terminal" moved from the ⋯ menu to an icon next to "Edit," with an "(environment isolated)" tooltip on cards pinned to an account or custom endpoint; lightweight mode now survives restarts, though a cold ccswitch:// launch still opens the main window so import dialogs can render. Presets were refreshed too: DeepSeek standardized on Flash, Kimi gained K3.1 Pro / Pro HighSpeed with low/high/max reasoning (#8867), and ClinePass (#8885) and TeamoRouter Claude (#8266) were added.

  • Breaking changes — None.

CC Switch v4.0.21

本版本为 Claude Code 增加了多个官方订阅账号的切换：在授权中心添加几个 Claude 账号，每张官方卡选一个，切到哪张卡，Claude Code 就用哪个号；想几个号同时用，从卡片上「打开终端」，那个终端固定用卡片上的号。登录走 Claude Code 官方的流程，令牌只留在本机的 Claude Code 里，CC Switch 不上传、不刷新、不登出。绑了账号的卡片和授权中心都会显示每个号的套餐和剩余额度。另外，「打开终端」挪到了卡片上，Codex 的模型列表可以拖动排序，轻量模式重启后保持。修复了托管 ChatGPT 账号重启后误报登录过期、Codex 经路由时请求发到了别的地址、Codex 的 MCP 配置里多出 timeout / autoApprove、npm 12 下 OpenCode 和 Grok Build 装不好、Kimi Code 用量的时间不对、Oh My Pi 的 models.yml 里有 &、*、! 时无法编辑等问题。4.0 完整的更新内容请见 v4.0 发布说明。

新增

在多个 Claude 官方订阅账号之间切换

手上有不止一个 Claude 订阅（比如个人 Max 和公司 Team，或者多个 Pro 账号）时，以前只能在 Claude Code 里 /logout 再 /login，或者自己给每个号建配置目录。现在可以在 CC Switch 里管理多个号（#1928）。

图文用法和逐条的合规对照见 使用 CC Switch 切换多个 Claude 官方订阅以及合规问题。

安全与合规。 订阅账号交给工具管理，最要紧的是令牌安全、不违反 Anthropic 的条款。这个功能按 Claude Code 官方文档的做法实现，令牌始终只在你本机的 Claude Code 里：

  • 登录走官方流程。 添加账号时运行的是 Claude Code 自带的 claude auth login --claudeai，密码和授权都在 claude.ai 的官方页面完成。CC Switch 没有自己的 Claude 登录，也没有自己的 OAuth 客户端。Anthropic 的法律与合规页要求 Claude 账号的登录必须通过 Anthropic 自己的流程完成，并且明确不限制用户用自己的订阅登录未经修改的 Claude Code。
  • 多账号用的是官方推荐的方法。 每个号一个独立的配置目录，用 CLAUDE_CONFIG_DIR 区分，和 Claude Code 认证文档里「Log in with multiple accounts」一节的方法一样，CC Switch 只是替你建好目录、打开终端。
  • 令牌不离开本机。 令牌只存在 Claude Code 自己的位置（macOS 的钥匙串，Linux、Windows 的 .credentials.json），不上传，不随云同步，也不写进 CC Switch 的数据库。CC Switch 自己只记邮箱、组织、套餐这类账号资料和登录过期时间，不记令牌。
  • 不替你发请求。 CC Switch 没有服务器，不用订阅令牌调用模型；对话请求都由本机未经修改的 Claude Code 直接发给 Anthropic，用量计在你自己的账号上。查额度时在本机直接查 Anthropic 官方的额度接口，和 Claude Code 自己的 /usage 查的是同一份数据。
  • 不刷新、不登出、不改 Claude Code。 令牌一律由 Claude Code 自己刷新。删除账号只删 CC Switch 为它建的目录（macOS 上连同这个目录在钥匙串里的条目），不会让这个号在任何地方退出登录。CC Switch 不修改 Claude Code 的程序文件。
  • 只管你自己的账号。 不按额度自动轮换账号，也不提供把订阅共享给别人的功能。

切卡即切号会在本机 Claude Code 的存储位置之间移动登录（只按 Claude Code 自己的格式），官方文档没有专门讲到这种用法。只想用文档写明的方式的话，卡片保持「跟随 Claude Code 登录」，其他号只从卡片「打开终端」使用。

怎么用：

  • 添加账号。 在授权中心的 Claude 组点「添加账号」。浏览器会打开 claude.ai 的官方授权页，登录后账号自动出现在列表里。浏览器授权后回不到本机时，可以把地址栏里的地址或页面上的代码粘贴回来。每个号的目录互不干扰，会同步你在 ~/.claude 里的设置、MCP 和 CLAUDE.md（登录凭据和路由相关的设置除外）。
  • 给官方卡选账号。 Claude 官方卡的「登录方式」下拉和 Codex 官方卡一样：上面是已登录的账号，下面是「添加或管理 Claude 账号」（跳到授权中心）和「跟随 Claude Code 登录」。一个号建一张卡就行。
  • 切卡即切号。 切到选了账号的官方卡时，CC Switch 把这个号的登录放进 Claude Code 默认读取的位置，原来那个号放回它自己的目录。终端、IDE 插件、脚本里的 claude 都改用这个号，已经在运行的 Claude Code 也会立即跟着换，不用重启。切到选了账号的官方卡时，现在的登录如果还不在授权中心会先收进来。切换时持有 Claude Code 自己的锁；切换中途 CC Switch 意外退出的话，下次切换或启动时会自动补完或撤回。选「跟随 Claude Code 登录」的卡不碰登录，不添加账号的人不受影响。
  • 几个号同时用。 在选了账号的卡上「打开终端」，这个终端固定用卡片上的号，之后切换卡片不影响它。
  • 套餐和额度。 卡片副标题显示账号和套餐（如 Max 20x），登录需要更新时带一个提示；卡片底部默认显示这个号的剩余额度，授权中心里每个号也有一样的额度列。不在用的号令牌过期时，CC Switch 在它的目录里运行一次 Claude Code 自带的 claude -p /usage（每个号最多 10 分钟一次），由 Claude Code 自己刷新登录、查询额度，CC Switch 只读结果。/usage 不调用模型，不消耗对话额度。没选账号的官方卡也会显示当前登录的套餐。

几点注意：

  • 切号后正在用的 Remote Control 会断开；换号后第一条消息要重建提示缓存，会慢一点、多用一点额度。
  • 在设置里覆盖了 Claude 配置目录（包括指向 WSL）时，切卡不会切换登录，界面会提示改用「打开终端」。

Codex 的模型列表可以拖动排序

Codex 供应商表单里的模型列表，每行开头有拖动手柄，可以用鼠标或键盘调整顺序（#8870）。这个顺序就是 Codex 里 /model 菜单的顺序。第一行代表默认模型时，拖到第一行的模型成为新的默认模型。以前要删掉再加回来才能挪位置。

改进

「打开终端」挪到卡片上。 以前在 ⋯ 菜单里，现在是「编辑」左边的一个图标按钮。悬停提示是「以此供应商打开终端」，终端固定用这张卡时（填了自己的地址和 Key 的卡、选了 Claude 账号的官方卡）会写「（环境隔离）」。

授权中心每组的「添加账号」按钮固定在标题右边。 以前没有账号时按钮会挪到空白提示里，几组卡片的按钮高低不一。ChatGPT 的登录方式改成按钮旁边的一个小下拉。标题里的「删除全部账号」菜单去掉了，账号在各自那一行的菜单里删除。各个账号的额度条现在对齐，长度一致。

轻量模式重启后保持。 在轻量模式下退出 CC Switch，下次启动仍是轻量模式，不再弹出主界面。从 ccswitch:// 链接冷启动时照常打开主界面，好显示导入对话框。

Hermes 卡片显示「默认」，「设为默认」移到 ⋯ 菜单里。 Hermes 把添加的供应商都写进 config.yaml，当前那家只是默认值，和 OpenClaw、OpenCode、Kimi Code 一样。以前的电源图标「启用」按钮看起来像开关。

卡片变成「使用中」时，用量一栏不再左右挪动。

MCP 选了 SSE 时提示哪些应用不支持（#8882）。Codex 只支持 stdio 和 HTTP，会把 SSE 地址当作 HTTP 连接，服务端只支持 SSE 时连不上；Pi 和 Antigravity 保存时会报错。现在「写入到」下面会提前提示。

Claude Desktop 的上游地址填 githubcopilot.com 时，上游格式显示为「由路由按模型自动选择」（#8838），和选 GitHub Copilot 供应商时一样。

OpenCode 的 OMO、OMO Slim 卡片不再显示「检测连通」（#8842）。它们只是代理和模型的对应关系，没有地址可测，以前点了会报错。

土耳其语翻译补全（#8836）。

预设： DeepSeek 一律改用 Flash 模型；Kimi 官方预设加入 K3.1 Pro 和 K3.1 Pro HighSpeed，可以选 low / high / max 思考程度（#8867）；OpenClaw 的 MiniMax M3.1 Flash 可以选 max；新增 ClinePass（#8885）、TeamoRouter Claude（#8266）；Claude Desktop 的 OpenCode Go 改用官方文档的地址，额度也能查了（#8720、#8779）。

修复

  • 托管 ChatGPT 账号重启后显示「登录已过期」、不能切换，过一会儿又自己好了（#8901）。以前刷新登录时遇到任何 HTTP 403 都当成登录失效，网络错误也显示成过期。现在和 Codex CLI 一样，只有 401 或明确的令牌失效错误才算过期；一时的网络问题照常重试，额度保留上一次的结果。托盘切换后，主界面里查询失败的额度也会重新查询。
  • Codex 经本地路由时，请求发到了别的地址（#8849、#8848）。config.toml 里有多个供应商表、或上面有一行注释掉的旧地址时，以前取的是文本里第一个 base_url，会带着选中供应商的 Key 发到别处。现在按 model_provider 选中的那张表取地址。
  • Codex 远程压缩的用量有时漏记（#8879）。
  • Codex 的 MCP 配置里多出 timeout、autoApprove，Codex 桌面版报未知设置，--strict-config 拒绝加载（#8843）。这两个字段是别的客户端的，以前原样写进了 config.toml，手动删掉下次同步又会写回来。现在写给 Codex 时去掉，其他应用不受影响。
  • Codex 经中转连到多个 Azure 资源时，会话中途报 400「created under a different Azure OpenAI resource」，无法继续（#8877）。现在收到这个错误后重试一次，去掉历史记录的条目 ID。正常的请求不受影响。
  • ClinePass 这类把 Chat Completions 结果包在 data 里返回的上游，非流式请求报 422「No choices in response」（#5658）。
  • npm 12 下，「应用」页装的 OpenCode 在 Windows 上报「与你运行的 Windows 版本不兼容」，Grok Build 升级后仍在跑旧版本（#8863）。npm 12 默认不运行安装脚本，这两个包要靠它放置真正的程序。现在安装和升级时允许它们的安装脚本。
  • Windows 上 Hermes 在「应用」页显示成两处安装（#8839）。同一目录里遗留的 hermes.cmd 不再算一处安装。
  • Kimi Code 的用量，一整轮对话的请求时间都一样，按小时统计时挤在最后一小时（#8899）。现在按每次请求完成的时间记。已导入的记录在会话文件下次变化时会更正。
  • Oh My Pi 的 models.yml 里有 name: Search & Fetch 这类含 &、*、! 的值时，保存供应商时报「此 YAML 使用了 CC Switch 无法安全编辑的格式或语法」（#8897）。
  • ~/.gemini/.env 里写成 export GEMINI_API_KEY=... 时，导入后没有 Key，切回默认供应商还会把它从文件里删掉（#8862、#8861）。
  • 从启用了提示词的项目切到没有提示词的项目，原来的提示词没有停用。
  • 用量统计页展开或收起侧栏时，趋势图右边缘跳动（#8548）。
