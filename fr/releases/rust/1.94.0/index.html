  • Stabilisez la clé d'inclusion de configuration. La clé de configuration d'inclusion de niveau supérieur permet de charger des fichiers de configuration supplémentaires, permettant une meilleure organisation, partage et gestion des configurations Cargo dans tous les projets et environnements. documents #16284
  • Stabilisez le champ pubtime dans l'index du registre. Cela enregistre le moment où une version de caisse a été publiée et permet une résolution future des dépendances basée sur le temps. Notez que crates.io remplira progressivement les packages existants lorsqu'une nouvelle version sera publiée. Toutes les caisses n'ont pas encore été publiées. #16369 #16372
  • Cargo analyse désormais TOML v1.1 pour les manifestes et les fichiers de configuration. Notez que l'utilisation de ces fonctionnalités dans Cargo.toml augmentera votre MSRV de développement, mais le manifeste publié reste compatible avec les anciens analyseurs. #16415

Notes de compatibilité

  • Interdire la diffusion libre des limites de durée de vie des types dyn -[Faire en sorte que la capture de fermeture ait un comportement cohérent et correct autour des modèles] (https://github.com/rust-lang/rust/pull/138961) Certains détails plus fins sur la façon dont les captures de fermeture précises sont affectées par la correspondance de modèles ont été modifiés. Dans certains cas, cela peut entraîner une fermeture sans déplacement qui capturait auparavant une variable entière par déplacement, pour capturer désormais seulement une partie de cette variable par déplacement et d'autres parties par emprunt. Cela peut amener le vérificateur d'emprunt à se plaindre là où il ne le faisait pas auparavant, ou à faire en sorte que Drop s'exécute à un moment différent.
  • [Les macros de bibliothèque standard sont désormais importées via le prélude, et non via #[macro_use] injecté] (https://github.com/rust-lang/rust/pull/139493) Cela générera une erreur si des macros du même nom sont importées globalement. Par exemple, si une caisse définit sa propre macro matches et que glob l'importe ensuite, il est désormais ambigu de savoir s'il s'agit de la bibliothèque personnalisée ou standard matches et une importation explicite du nom est requise pour résoudre l'ambiguïté. Une exception est core::panic et std::panic, si leur importation est ambiguë, un nouvel avertissement (ambiguous_panic_imports) est généré. Cela peut déclencher un nouvel avertissement (ambiguous_panic_imports) sur le code global #![no_std] important la caisse std. core::panic! et std::panic! sont alors tous deux concernés et celui qui est utilisé est ambigu.
  • [Ne supprimez pas le shebang dans le contexte d'expression include!(…)] (https://github.com/rust-lang/rust/pull/146377) Cela peut empêcher la compilation des inclusions précédemment utilisées si elles incluaient des fichiers qui commençaient par un shebang.
  • Les réexportations globales ambiguës sont désormais également visibles entre caisses Cela unifie le comportement entre les erreurs locales et entre caisses sur ces exportations, ce qui peut introduire de nouvelles erreurs d'ambiguïté.
  • Ne normalisez pas les clauses Where avant de vérifier leur bonne forme -Introduire un futur avertissement de compatibilité sur les attributs codegen sur les méthodes de traits sans corps Ces attributs n'ont actuellement aucun effet dans cette position.
  • Sous Windows, std::time::SystemTime::checked_sub_duration renverra None pour les périodes antérieures à l'époque Windows (1/1/1601)
  • [Les identifiants à vie tels que 'a sont désormais normalisés NFC] (https://github.com/rust-lang/rust/pull/149192).
  • [Révision de la gestion des noms de fichiers pour une cohérence entre compilateurs] (https://github.com/rust-lang/rust/pull/149709) Tous les chemins émis par le compilateur respectent désormais toujours la relative des chemins et --remap-path-prefix donnés à l'origine. L'un des effets secondaires de ce changement est que les chemins émis pour les caisses locales dans Cargo (dépendances de chemin et membres de l'espace de travail) ne sont plus absolus mais relatifs lorsqu'ils sont émis dans le cadre d'un diagnostic dans une caisse en aval. <a id="1.94.0-Internal-Changes"></a>

rust 1.94.0

<a id="1.94.0-Language"></a>

Language

  • Impls and impl items inherit dead_code lint level of the corresponding traits and trait items
  • Stabilize additional 29 RISC-V target features including large portions of the RVA22U64 / RVA23U64 profiles
  • Add warn-by-default unused_visibilities lint for visibility on const _ declarations
  • Update to Unicode 17
  • Avoid incorrect lifetime errors for closures

<a id="1.94.0-Platform-Support"></a>

Platform Support

  • Add riscv64im-unknown-none-elf as a tier 3 target

Refer to Rust's platform support page for more information on Rust's tiered platform support.

<a id="1.94.0-Libraries"></a>

Libraries

  • Relax T: Ord bound for some BinaryHeap<T> methods.

<a id="1.94.0-Stabilized-APIs"></a>

Stabilized APIs

  • <[T]>::array_windows
  • <[T]>::element_offset
  • LazyCell::get
  • LazyCell::get_mut
  • LazyCell::force_mut
  • LazyLock::get
  • LazyLock::get_mut
  • LazyLock::force_mut
  • impl TryFrom<char> for usize
  • std::iter::Peekable::next_if_map
  • std::iter::Peekable::next_if_map_mut
  • x86 avx512fp16 intrinsics (excluding those that depend directly on the unstable f16 type)
  • AArch64 NEON fp16 intrinsics (excluding those that depend directly on the unstable f16 type)
  • f32::consts::EULER_GAMMA
  • f64::consts::EULER_GAMMA
  • f32::consts::GOLDEN_RATIO
  • f64::consts::GOLDEN_RATIO

These previously stable APIs are now stable in const contexts:

  • f32::mul_add
  • f64::mul_add

<a id="1.94.0-Cargo"></a>

Cargo

  • Stabilize the config include key. The top-level include config key allows loading additional config files, enabling better organization, sharing, and management of Cargo configurations across projects and environments. docs #16284
  • Stabilize the pubtime field in registry index. This records when a crate version was published and enables time-based dependency resolution in the future. Note that crates.io will gradually backfill existing packages when a new version is published. Not all crates have pubtime yet. #16369 #16372
  • Cargo now parses TOML v1.1 for manifests and configuration files. Note that using these features in Cargo.toml will raise your development MSRV, but the published manifest remains compatible with older parsers. #16415
  • Make CARGO_BIN_EXE_<crate> available at runtime

<a id="1.94.0-Compatibility-Notes"></a>

Compatibility Notes

  • Forbid freely casting lifetime bounds of dyn-types
  • Make closure capturing have consistent and correct behaviour around patterns Some finer details of how precise closure captures get affected by pattern matching have been changed. In some cases, this can cause a non-move closure that was previously capturing an entire variable by move, to now capture only part of that variable by move, and other parts by borrow. This can cause the borrow checker to complain where it previously didn't, or cause Drop to run at a different point in time.
  • Standard library macros are now imported via prelude, not via injected #[macro_use] This will raise an error if macros of the same name are glob imported. For example if a crate defines their own matches macro and then glob imports that, it's now ambiguous whether the custom or standard library matches is meant and an explicit import of the name is required to resolve the ambiguity. One exception is core::panic and std::panic, if their import is ambiguous a new warning (ambiguous_panic_imports) is raised. This may raise a new warning (ambiguous_panic_imports) on #![no_std] code glob importing the std crate. Both core::panic! and std::panic! are then in scope and which is used is ambiguous.
  • Don't strip shebang in expression-context include!(…)s This can cause previously working includes to no longer compile if they included files which started with a shebang.
  • Ambiguous glob reexports are now also visible cross-crate This unifies behavior between local and cross-crate errors on these exports, which may introduce new ambiguity errors.
  • Don't normalize where-clauses before checking well-formedness
  • Introduce a future compatibility warning on codegen attributes on body-free trait methods These attributes currently have no effect in this position.
  • On Windows std::time::SystemTime::checked_sub_duration will return None for times before the Windows epoch (1/1/1601)
  • Lifetime identifiers such as 'a are now NFC normalized.
  • Overhaul filename handling for cross-compiler consistency Any paths emitted by compiler now always respect the relative-ness of the paths and --remap-path-prefix given originally. One side-effect of this change is that paths emitted for local crates in Cargo (path dependencies and workspace members) are no longer absolute but relative when emitted as part of a diagnostic in a downstream crate.

<a id="1.94.0-Internal-Changes"></a>

Internal Changes

These changes do not affect any public interfaces of Rust, but they represent significant improvements to the performance or internals of rustc and related tools.

  • Switch to annotate-snippets for error emission This should preserve mostly the same outputs in rustc error messages.
