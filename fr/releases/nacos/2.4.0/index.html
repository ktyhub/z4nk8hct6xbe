#nacos 2.4.0

Veuillez d'abord utiliser 2.4.0.1 Cette version est une version importante qui prend en charge de nombreuses nouvelles fonctionnalités. La fonctionnalité la plus importante est que le responsable du support Nacos initialise le mot de passe de l'utilisateur administrateur nacos au lieu d'utiliser le mot de passe par défaut pour améliorer la sécurité par défaut pour le déploiement des clusters Nacos. Une autre chose est les opérations derby désactivées par défaut API pour éviter les fausses alarmes concernant les risques correspondants pour les utilisateurs sans authentification activée lors du déploiement en mode autonome. Si les responsables souhaitent utiliser ce API pour maintenir et interroger les données dans le derby, les responsables peuvent utiliser nacos.config.derby.ops.enabled=true pour ouvrir ce API. Et d'autres fonctionnalités principales sont la prise en charge de la communication TLS Grpc entre les nœuds du cluster Nacos en tant que fonctionnalité facultative pour améliorer la sécurité de Nacos, ce qui signifie que nacos prend non seulement en charge la communication TLS entre client et le serveur ; De plus, Nacos commence à prendre en charge l'extension utilisateur Selector avant le rappel Subscriber pour le module de dénomination, et peut non seulement sélectionner des instances de services par sains et par clusters. Et Nacos client prend en charge les différences du service de rappel par nouvel événement pour réduire le cache Subscriber et comparer les logiques. Troisièmement, les fonctionnalités principales sont la prise en charge de certaines utilisations de configuration dans la console Nacos et la prise en charge d'une utilisation plus améliorée pour les plugins, telles que la prise en charge de l'ajout de toutes les métadonnées au protocole prometheus sd et la prise en charge de la signature aliyun ram v4. En plus de mises à jour substantielles de fonctionnalités, cette version corrige également certains bugs des versions précédentes et met à niveau certaines dépendances présentant des vulnérabilités de sécurité. nacos 2.4.0

Please use 2.4.0.1 first

This version is an important version which support many new features.

The most mainly feature is Nacos support maintainer to initialize the admin user nacos password instead of using default password to improve the default security for deploy nacos clusters.

One more thing is default disabled derby ops API to prevent false alarms regarding corresponding risks for users without authentication enabled when deploying in standalone mode. If maintainers want use this API to maintain and query data in derby, maintainers can use nacos.config.derby.ops.enabled=true to open this API.

And other mainly features are support TLS Grpc communication between Nacos cluster nodes as an optional feature to improve Nacos security, which means nacos not only support TLS communication between client and server; What's more, Nacos start to support user extend Selector before callback Subscriber for naming module, not only can select instance of services by healthy and clusters. And Nacos client support callback service diffs by new event to reduce Subscriber cache and compare logics.

Third mainly features are support some configs usages in Nacos console and support more enhancement usage for plugins, such as support add all metadata to prometheus sd protocol and support aliyun ram v4 signature.

In addition to substantial feature updates, this version also fixes some bugs from previous versions and upgrades certain dependencies with security vulnerabilities.
