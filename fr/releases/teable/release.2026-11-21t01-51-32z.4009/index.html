version teaable.2026-11-21T01-51-32Z.4009

Mises à jour des fonctionnalités

  • Ajout de points de terminaison MCP stricts et en lecture seule. Le point de terminaison strict sépare les actions de lecture et d'écriture afin que les IA clients compatibles puissent demander une confirmation avant d'apporter des modifications. Le point de terminaison en lecture seule prend en charge les clients qui ne peuvent pas confirmer les écritures. Les intégrations MCP existantes restent inchangées.
  • Ajout d'une bibliothèque de requêtes pour chaque base. Les membres peuvent enregistrer, rechercher, comparer et partager des révisions de requêtes privées par défaut. Les requêtes s'exécutent avec les autorisations de données actuelles de l'appelant et les applications publiées peuvent épingler une révision spécifique. La révocation de l'accès empêche les applications d'exécuter la requête épinglée jusqu'à ce que l'accès soit restauré ou que l'application soit mise à jour. Cette fonctionnalité nécessite l'activation de la bibliothèque de requêtes et de l'exécution de requêtes natives.
  • Le collage de texte brut dans les tableaux prend désormais en charge les liens plusieurs-à-plusieurs bidirectionnels. Les titres collés correspondent aux enregistrements existants dans la table liée et les liens réciproques sont mis à jour sans créer de doublons.
  • Les membres de la table peuvent désormais voir si l'accélération de la recherche est active, quels champs elle couvre et quand son statut change. Les vues partagées affichent la disponibilité uniquement pour les champs visibles dans la vue.

Corrections de bugs et améliorations

  • Mise à jour du package du plugin OpenAI vers la version 1.0.1 et raccourcis des instructions AI afin qu'elles ne soient plus coupées dans Claude Code.
  • Amélioration de la fiabilité du champ calculé v2 tout en réduisant la charge inutile de la base de données.
  • Amélioration de la fiabilité de la restauration et de la suppression des ressources, y compris un correctif pour les tables v2 restaurées qui pouvaient rester répertoriées dans la corbeille.
  • Le pré-remplissage des lignes conserve désormais les valeurs autorisées et ignore uniquement les nouvelles options de sélection que l'éditeur ne peut pas créer. Si le collage ne contient qu'une option restreinte, il renvoie toujours une erreur d'autorisation.
  • Correction d'échecs lorsque des champs étaient créés simultanément sur la même table ou lorsqu'une opération de longue durée était en cours. Les nouveaux champs apparaissent désormais de manière fiable dans la liste des champs et dans la vue par défaut.
  • Cuppy explique désormais quand une tâche s'arrête car elle manque de mémoire. Les étapes terminées restent visibles et les utilisateurs Web peuvent reprendre à partir de la dernière réponse sans recommencer.
  • Correction des recherches et des cumuls filtrés afin que la suppression des enregistrements liés recalcule uniquement les enregistrements parents concernés. La suppression est également plus rapide pour les grands ensembles de données liés.
  • Amélioration de la sécurité du partage de base afin que les visiteurs puissent accéder uniquement au contenu dans la portée de partage configurée.
  • Correction d'erreurs dans les graphiques du tableau de bord qui utilisent des données de tableau. Les totaux du graphique reflètent désormais les données que chaque utilisateur est autorisé à lire, y compris les restrictions au niveau des lignes.
  • Amélioration des performances du API V2 pour les mises à jour par lots sur plusieurs champs d'enregistrement liés tout en préservant l'ordre des liens et en gardant les liens réciproques synchronisés.

teable release.2026-11-21T01-51-32Z.4009

Feature Updates

  • Added strict and read-only MCP endpoints. The strict endpoint separates read and write actions so compatible AI clients can ask for confirmation before making changes. The read-only endpoint supports clients that cannot confirm writes. Existing MCP integrations are unchanged.
  • Added a Query Library for each Base. Members can save, find, compare, and share private-by-default query revisions. Queries run with the caller’s current data permissions, and published apps can pin a specific revision. Revoking access prevents apps from running the pinned query until access is restored or the app is updated. This feature requires both Query Library and native query execution to be enabled.
  • Plain-text paste across tables now supports two-way many-to-many links. Pasted titles match existing records in the linked table, and reciprocal links are updated without creating duplicates.
  • Table members can now see whether search acceleration is active, which fields it covers, and when its status changes. Shared views show availability only for fields visible in the view.

Bug Fixes & Improvements

  • Updated the OpenAI plugin package to version 1.0.1 and shortened AI instructions so they are no longer cut off in Claude Code.
  • Improved v2 computed-field reliability while reducing unnecessary database load.
  • Improved resource restore and deletion reliability, including a fix for restored v2 tables that could remain listed in the trash.
  • Row prefilling now keeps permitted values and skips only new select options the editor cannot create. If the paste contains only a restricted option, it still returns a permission error.
  • Fixed failures when fields were created concurrently on the same table or while a long-running operation was in progress. New fields now reliably appear in the field list and default view.
  • Cuppy now explains when a task stops because it runs out of memory. Completed steps remain visible, and web users can resume from the latest reply without starting over.
  • Fixed filtered lookups and rollups so deleting linked records recalculates only the affected parent records. Deletion is also faster for large linked datasets.
  • Improved Base share security so visitors can access only content within the configured share scope.
  • Fixed errors in Dashboard charts that use table data. Chart totals now reflect the data each viewer has permission to read, including row-level restrictions.
  • Improved V2 API performance for batch updates across multiple linked-record fields while preserving link order and keeping reciprocal links in sync.
