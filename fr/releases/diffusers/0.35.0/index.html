diffuseurs v0.35.0

Cette version contient de nouveaux pipelines de génération et d'édition d'images, un nouveau pipeline vidéo, de nouveaux scripts de formation, des améliorations de la qualité de vie et bien plus encore. Lisez entièrement le reste des release note pour ne pas manquer les choses amusantes.

Nouveaux pipelines 🧨

Nous avons accueilli de nouveaux pipelines dans cette version :

  • Wan 2.2
  • Flux-Contexte
  • Qwen-Image
  • Qwen-Image-Modifier

Wan 2.2 📹

Cette mise à jour de Wan apporte des améliorations significatives en termes de fidélité vidéo, de respect rapide et de style. Veuillez consulter le document officiel pour en savoir plus.

Flux-Contexte 🎇

Flux-Kontext est un transformateur de flux rectifié de 12 milliards de paramètres capable d'éditer des images basées sur des instructions textuelles. Veuillez consulter le document officiel pour en savoir plus.

Qwen-Image 🌅

Après une série réussie de livraison de modèles de langage et de modèles de langage de vision, l'équipe Qwen est de retour avec un modèle de génération d'images, sous licence Apache-2.0 ! Il réalise des progrès significatifs dans le rendu de texte complexe et l’édition précise d’images. Pour en savoir plus sur ce modèle puissant, reportez-vous à nos docs. Merci à @naykun pour sa contribution à Qwen-Image et Qwen-Image-Edit via ce PR et ce PR.

Nouveaux scripts de formation 🎛️

Appropriez-vous ces modèles nouvellement ajoutés avec nos scripts de formation :

  • Entraîneur de contexte
  • Entraîneur Qwen-Image

Implémentations de modélisation à fichier unique

Suivant la [philosophie] des Transformers (https://huggingface.co/blog/transformers-design-philosophy) d'implémentation de modélisation à fichier unique, nous avons commencé à implémenter du code de modélisation dans des fichiers uniques et autonomes. Le transformateur de flux [code] (https://github.com/huggingface/diffusers/blob/baa9b582f348e52aa2fc245e366611f454e1082b/src/diffusers/models/transformers/transformer_flux.py) en est un exemple.

Attention refactoriser

Nous avons massivement remanié la façon dont nous accordons l'attention dans les modèles. Cela nous permet de prendre en charge différents backends d'attention (tels que scaled_dot_product_attention natif de PyTorch, Flash Attention 3, SAGE attention, etc.) dans la bibliothèque de manière transparente. Avoir l'attention soutenue de cette manière nous permet également d'intégrer différents mécanismes de parallélisation, sur lesquels nous travaillons activement. Suivez ce PR si vous êtes intéressé. Les utilisateurs ne devraient pas du tout être affectés par ces changements. Veuillez ouvrir un problème si vous rencontrez des problèmes.

Compilation régionale

La compilation régionale réduit la latence de démarrage à froid en compilant uniquement les petits blocs fréquemment répétés d'un modèle (généralement une couche de transformateur) et permet de réutiliser les artefacts compilés pour chaque occurrence ultérieure. Pour de nombreuses architectures de diffusion, cela offre les mêmes accélérations d’exécution que la compilation de graphes complets et réduit le temps de compilation de 8 à 10 fois. Reportez-vous à ce document pour en savoir plus. Merci à @anijain2305 pour avoir contribué à cette fonctionnalité dans ce PR. Nous avons également rédigé un certain nombre d’articles centrés sur l’utilisation de torch.compile. Vous pouvez les consulter sur les liens ci-dessous :

  • Présentation de Flux Fast : Faire en sorte que Flux brrr sur les H100 -[torch.compile et diffuseurs : un guide pratique pour des performances optimales] (https://pytorch.org/blog/torch-compile-and-diffusers-a-hands-on-guide-to-peak-performance/)
  • [Inférence LoRA rapide pour flux avec diffuseurs et PEFT] (https://huggingface.co/blog/lora-fast)

Chargement plus rapide du pipeline ⚡️

Les utilisateurs peuvent désormais charger des pipelines directement sur un dispositif accélérateur, ce qui accélère considérablement les temps de chargement. Cela devient particulièrement évident lors du chargement de grands pipelines comme Wan et Qwen-Image.

from diffusers import DiffusionPipeline
import torch 

ckpt_id = "Qwen/Qwen-Image"
pipe = DiffusionPipeline.from_pretrained(
-    ckpt_id, torch_dtype=torch.bfloat16
- ).to("cuda")
+    ckpt_id, torch_dtype=torch.bfloat16, device_map="cuda"
+ )

Vous pouvez accélérer encore plus le chargement en activant le chargement parallélisé des fragments de dict d'état. Ceci est particulièrement utile lorsque vous travaillez avec des modèles volumineux tels que Wan et Qwen-Image, où les dicts d'état du modèle sont généralement répartis sur plusieurs fichiers.

import os
os.environ["HF_ENABLE_PARALLEL_LOADING"] = "yes"

# rest of the loading code
....

Meilleure intégration GGUF

@Isotr0py a contribué à la prise en charge des noyaux natifs GGUF CUDA dans ce PR. Cela devrait permettre une amélioration d’environ 10 % de la vitesse d’inférence. Nous avons également travaillé sur un outil permettant de convertir les points de contrôle réguliers en GGUF, permettant à la communauté de partager facilement ses points de contrôle GGUF. En savoir plus ici. Nous prenons désormais en charge le chargement des points de contrôle GGUF au format Diffuseurs. Vous pouvez en savoir plus sur tout cela dans nos [documents officiels GGUF] (https://huggingface.co/docs/diffusers/main/en/quantization/gguf).

Diffuseurs modulaires (expérimentaux)

Modular Diffusers est un système permettant de construire des canalisations de diffusion avec des *blocs de canalisations individuels *. Il est hautement personnalisable, avec des blocs qui peuvent être mélangés et assortis pour s'adapter ou créer un pipeline pour un flux de travail spécifique ou plusieurs flux de travail.
Le API est actuellement en développement actif et est publié en tant que fonctionnalité expérimentale. Apprenez-en davantage dans nos docs.

diffusers v0.35.0

This release comes packed with new image generation and editing pipelines, a new video pipeline, new training scripts, quality-of-life improvements, and much more. Read the rest of the release notes fully to not miss out on the fun stuff.

New pipelines 🧨

We welcomed new pipelines in this release:

  • Wan 2.2
  • Flux-Kontext
  • Qwen-Image
  • Qwen-Image-Edit

Wan 2.2 📹

This update to Wan provides significant improvements in video fidelity, prompt adherence, and style. Please check out the official doc to learn more.

Flux-Kontext 🎇

Flux-Kontext is a 12-billion-parameter rectified flow transformer capable of editing images based on text instructions. Please check out the official doc to learn more about it.

Qwen-Image 🌅

After a successful run of delivering language models and vision-language models, the Qwen team is back with an image generation model, which is Apache-2.0 licensed! It achieves significant advances in complex text rendering and precise image editing. To learn more about this powerful model, refer to our docs.

Thanks to @naykun for contributing both Qwen-Image and Qwen-Image-Edit via this PR and this PR.

New training scripts 🎛️

Make these newly added models your own with our training scripts:

  • Kontext trainer
  • Qwen-Image trainer

Single-file modeling implementations

Following the 🤗 Transformers’ philosophy of single-file modeling implementations, we have started implementing modeling code in single and self-contained files. The Flux Transformer code is one example of this.

Attention refactor

We have massively refactored how we do attention in the models. This allows us to provide support for different attention backends (such as PyTorch native scaled_dot_product_attention, Flash Attention 3, SAGE attention, etc.) in the library seamlessly.

Having attention supported this way also allows us to integrate different parallelization mechanisms, which we’re actively working on. Follow this PR if you’re interested.

Users shouldn’t be affected at all by these changes. Please open an issue if you face any problems.

Regional compilation

Regional compilation trims cold-start latency by only compiling the small and frequently-repeated block(s) of a model - typically a transformer layer - and enables reusing compiled artifacts for every subsequent occurrence. For many diffusion architectures, this delivers the same runtime speedups as full-graph compilation and reduces compile time by 8–10x. Refer to this doc to learn more.

Thanks to @anijain2305 for contributing this feature in this PR.

We have also authored a number of posts that center around the use of torch.compile. You can check them out at the links below:

  • Presenting Flux Fast: Making Flux go brrr on H100s
  • torch.compile and Diffusers: A Hands-On Guide to Peak Performance
  • Fast LoRA inference for Flux with Diffusers and PEFT

Faster pipeline loading ⚡️

Users can now load pipelines directly on an accelerator device leading to significantly faster load times. This particularly becomes evident when loading large pipelines like Wan and Qwen-Image.

from diffusers import DiffusionPipeline
import torch 

ckpt_id = "Qwen/Qwen-Image"
pipe = DiffusionPipeline.from_pretrained(
-    ckpt_id, torch_dtype=torch.bfloat16
- ).to("cuda")
+    ckpt_id, torch_dtype=torch.bfloat16, device_map="cuda"
+ )

You can speed up loading even more by enabling parallelized loading of state dict shards. This is particularly helpful when you’re working with large models like Wan and Qwen-Image, where the model state dicts are typically sharded across multiple files.

import os
os.environ["HF_ENABLE_PARALLEL_LOADING"] = "yes"

# rest of the loading code
....

Better GGUF integration

@Isotr0py contributed support for native GGUF CUDA kernels in this PR. This should provide an approximately 10% improvement in inference speed.

We have also worked on a tool for converting regular checkpoints to GGUF, letting the community easily share their GGUF checkpoints. Learn more here.

We now support loading of Diffusers format GGUF checkpoints.

You can learn more about all of this in our GGUF official docs.

Modular Diffusers (Experimental)

Modular Diffusers is a system for building diffusion pipelines pipelines with individual pipeline blocks. It is highly customisable, with blocks that can be mixed and matched to adapt to or create a pipeline for a specific workflow or multiple workflows.

The API is currently in active development and is being released as an experimental feature. Learn more in our docs.
