codegraphe v1.6.2

[1.6.2] - 2026-10-03

Faits saillants

  • Beaucoup moins de liens erronés, dans toutes les langues. Un appel, une importation ou un type résout désormais la façon dont sa langue étend les noms - via les importations, les packages, les espaces de noms et la classe dans laquelle il est écrit - de sorte qu'il cesse d'atterrir sur un symbole sans rapport qui ne partage que son nom. Cela couvre TypeScript et JavaScript, Python, Java, Kotlin, Scala, C#, VB.NET, Swift, Objective-C, Go, Rust, C et C++, PHP, Ruby, Dart, Lua, R et plus, et rend les appelants, l'impact et les réponses codegraph_explore plus dignes de trust.
  • Les surcharges, super et la récursion se résolvent correctement. Un appel atteint la surcharge à laquelle ses arguments correspondent, un appel super atteint la méthode parent et une méthode qui appelle une autre surcharge, ou la méthode d'un autre objet du même nom, ne semble plus s'appeler elle-même.
  • Routes pour plus de frameworks. Angular (y compris les bibliothèques Nx), les applications d'administration Vue Router, les routes imbriquées Rails, les add_url_rule de Flask, les FastEndpoints ASP.NET, les sous-projets Play, les routes de fermeture Vapor et les routes Expo Router API sont trouvés. Les routes NestJS et Laravel sont nommées en fonction du chemin qu'emprunte réellement une requête, et un test Spring ou Laravel qui appelle une route par URL compte comme la couvrant.
  • Plus de votre code dans le graphique. Composants Vue Options API, constantes d'énumération Java et Kotlin avec corps, JavaScript typé Flow, appels infixes Kotlin, vues et événements natifs React Native, modules Expo, fichiers CFML et Delphi .inc basés sur des balises sont tous indexés maintenant.
  • Windows : pas de fenêtres clignotantes, pas de plantages aléatoires. Le serveur d'arrière-plan n'affiche plus les fenêtres de console pendant son fonctionnement, les plantages sporadiques en cas de violation d'accès (code de sortie 3221225477) lors de l'indexation ou de l'arrêt sont corrigés et codegraph upgrade fonctionne lorsqu'une session d'agent utilise CodeGraph.
  • Un serveur d'arrière-plan plus stable. Les nouveaux MCP clients tels que Antigravity se connectent à nouveau, Claude Code voit le texte intégral de codegraph_status, une session qui a perdu le serveur partagé se reconnecte d'elle-même et un projet interrogé via projectPath est libéré après 10 minutes d'inactivité.
  • Indexation qui se termine. Les grands projets C et C++ ne manquent plus de mémoire lors de la résolution des références, un fichier COBOL ne peut plus bloquer l'indexation et codegraph sync conserve chaque appelant d'un nom défini plus d'une fois.
  • Mise à niveau : réindexez vos projets après cette version – la plupart de ces correctifs sont écrits lors de l'indexation.

Nouvelles fonctionnalités

  • Dans les projets Nuxt et Astro, une page routée par fichier est désormais liée au composant défini par son fichier. Un point de terminaison Astro est lié aux gestionnaires de verbes HTTP qu'il exporte, comme export const GET. Avant, une page route comme le pages/admin.vue de Nuxt ou le src/pages/about.astro d'Astro n'était liée à rien, donc les appelants, l'impact et les flux s'arrêtaient au niveau de la route.
  • Les liens React Router et les appels navigate(…) écrits via un objet route-config, comme le paths.app.discussion.getHref(id) de bulletproof-react, atteignent désormais la route qu'ils ouvrent. Un <Link> avec un attribut de fonction de flèche avant son to, tel que onMouseEnter={() => …}, est également lu.
  • Les routes du routeur de données React Router sont nommées par leur chemin complet : les chemins children imbriqués sont joints à ceux de leurs parents, les constantes path: paths.app.root.path sont lues et les routes lazy: () => import('./routes/x') sont liées au composant du module. Un wrapper de garde tel que <ProtectedRoute> ne remplace plus la page. Avec Bulletproof-React, chaque itinéraire a désormais son véritable chemin et sa véritable page.
  • Les routes Vapor dont le gestionnaire est une fermeture finale, comme app.get("hello") { req in … }, les routes WebSocket comme app.webSocket("chat") { req, ws in … } et les enregistrements routes.on(.POST, "x", use: handler) sont désormais trouvées, et une route de fermeture est liée à ce que la fermeture appelle, comme le fait un gestionnaire en ligne Express. Avant, seules les routes avec un gestionnaire use: étaient lues, et une route de fermeture liée à rien, donc les appelants, l'impact et les flux s'y arrêtaient.
  • Les fichiers JavaScript typés flux (ceux avec @flow dans leur commentaire d'en-tête) sont désormais analysés comme TypeScript, donc les annotations de type comme render(): React.Node ne raccourcissent plus les classes. Cela affecte principalement le code de React Native : sur les propres bibliothèques de React Native, le graphique a gagné plus de 8 000 liens et les classes de composants conservent leurs méthodes. Les fichiers sans pragma restent inchangés. Réindexez après la mise à niveau.
  • Un lien créé par un framework ou un résolveur de pont enregistre désormais celui qui l'a créé (metadata.framework, comme swift-objc-bridge ou react-native-bridge), comme le décrit le README. Auparavant, seuls les canaux d'événements et de vues synthétisés étaient nommés.
  • Les applications ASP.NET construites avec FastEndpoints ont désormais leurs routes : le Get(…) / Post(…) de chaque classe de point de terminaison dans Configure() devient une route liée à son propre HandleAsync / ExecuteAsync, y compris les chemins conservés dans la constante Route d'une classe de requête. ardalis/CleanArchitecture est passé d'aucune route à 24. Les routes minimales API écrites sans barre oblique (app.MapGet("api/todos", …)) sont désormais nommées /api/todos.
  • Les projets de lecture conservés dans des sous-répertoires sont reconnus, donc le conf/routes de chacun est lu. Un référentiel sans build Play à sa racine, comme les échantillons de playframework, est passé d'aucune route à plus de 130.
  • Les routes Rails sont désormais lues avec leur imbrication : namespace et scope ajoutent leur chemin et leur module de contrôleur, les resources imbriqués se trouvent sous le :id de leur parent, et les blocs member / collection ajoutent leurs actions. Une route avec espace de noms est désormais liée au contrôleur de son propre module. Des routes dans le config/routes.rb d'un moteur Rails sont également trouvées : Solidus est passé d'aucune route à plus de 600, et les liens route-action du mastodonte ont presque triplé.
  • Les routes de flacons enregistrées avec add_url_rule(…) sont désormais trouvées et liées à leur fonction d'affichage ou à leur vue basée sur les classes. Il en va de même pour les itinéraires enregistrés via le propre assistant d'un projet qui transmet une liste de chemins et un view_func=. flaskbb, qui enregistre chaque vue de cette façon, est passé d'aucune route à plus de 100.
  • Les composants Vue écrits avec les options API (export default { methods: {…}, computed: {…}, watch: {…}, mounted() {…} }), comme chaque application Vue 2, ont désormais leurs méthodes, propriétés calculées, observateurs et hooks de cycle de vie dans le graphique. Chacun a ses propres appelants et appels, et le @click="handleLogin" d'un modèle renvoie à la méthode qu'il exécute. Sur vue-element-admin, cela représente plus de 800 nouveaux liens, où les appels d'un composant appartenaient à l'ensemble du fichier.
  • Les événements React Native dont le nom est conservé dans une constante relient désormais le code natif au JavaScript qui les écoute, comme le addListener(PrivateTypes.DEVICE_CONNECTIVITY_EVENT, …) de NetInfo ou un .emit(PROGRESS_EVENT, …) de Java. La constante est lue de la même manière que le langage la définit, à partir du même fichier, d'une importation ou de sa classe propriétaire, de sorte qu'un paramètre qui partage le nom d'une constante ne soit jamais confondu avec celle-ci.
  • Les vues React Native déclarées avec requireNativeComponent('X'), l'ancien style Paper qui utilisait des cartes réactives natives et un contrôle segmenté, sont désormais liées à partir de JavaScript à leurs implémentations natives iOS et Android, comme le faisaient déjà les spécifications Codegen, y compris dans les fichiers .js simples. Une balise JSX écrite sous un nom différent de celui de son composant, comme <Autocomplete> pour import Autocomplete from './autocomplete.vue', est désormais liée au composant qu'elle restitue.
  • Les routes Expo Router API (app/hello+api.ts) sont désormais des points de terminaison, un par méthode exportée, comme GET /hello, liés à la fonction qui les gère. Ils apparaissaient sous la forme d'un écran nommé /hello+api. Dans un référentiel dont la racine déclare Expo Router pour un exemple d'application, une application Next.js dans son propre dossier, comme docs/ de React-native-true-sheet, ne reçoit plus d'écrans Expo créés à partir de ses fichiers.
  • Les appels dans un module Expo atteignent désormais les fonctions natives du module même lorsque le JavaScript nomme le module autrement, comme CameraManager de la caméra expo pour requireNativeModule('ExpoCamera'). Les implémentations iOS et Android sont liées. Les appels d'expo-camera étaient utilisés pour renvoyer à la méthode du même nom effectuant l'appel, donc une méthode semblait s'appeler elle-même.
  • Les applications angulaires réparties dans les bibliothèques Nx, comme angulaire-spotify, ont désormais leurs itinéraires et leur navigation. Une route chargée paresseusement et écrite async () => (await import('@app/home')).HomeModule est suivie via le index.ts de la bibliothèque jusqu'au module qu'elle réexporte, et un routerLink dans une bibliothèque atteint maintenant un écran déclaré dans une autre. Les chemins de routage construits à partir d'une constante de classe (RouterUtil.Configuration.Lyrics, `issue/:${ProjectConst.IssueId}`) or an enum are now read. A redirect in a routes file that only lazy-loads others now counts, and router.navigate(['project', 'issue', id]) without relativeTo sont lus à partir de la racine, comme le fait Angular. Réindexez les projets Angular après la mise à niveau.
  • Les applications React Router affichent désormais la navigation écrite sous le nom <Redirect to="/login" /> de React Router v5 et via un lien stylisé, comme le HeaderLink = styled(Link) de React-boilerplate utilisé comme <HeaderLink to="/features">. Les applications créées de cette manière avaient des itinéraires mais aucun lien entre leurs écrans.
  • Les routes SvelteKit sont désormais nommées par l'adresse demandée par un navigateur. Un dossier (group) comme (app) ou (marketing) ne fait plus partie du chemin d'un itinéraire, et un paramètre avec un matcher, comme [id=integer], est simplement :id. Ainsi, goto('/blocks') et <a href="/blocks"> atteignent maintenant une page qui se trouve dans src/routes/(app)/blocks/, où auparavant ils n'atteignaient rien et les écrans de l'application n'affichaient aucune navigation. Réindexez les projets SvelteKit après la mise à niveau.
  • Les applications Vue Router construites comme vue-element-admin, vue-admin-template ou vben ont désormais leurs itinéraires et leurs écrans. Les routes déclarées dans une table nommée (export const constantRoutes = [...], const routes: RouteRecordRaw[] = [...]), dans les fichiers de routes par module ou via new Router(...) sont désormais lues. Les routes enfants sont jointes au chemin de leur parent, et le composant du parent est la disposition qui les entoure. Une vue chargée paresseusement (() => import('@/views/dashboard/index')) est liée au fichier qu'elle nomme, et this.$router.push(...) compte comme une navigation. Les routes basées sur des fichiers de Nuxt proviennent désormais uniquement d'une application Nuxt, donc le dossier pages/ d'une application Vue simple ne se transforme plus en écrans inventés, et une application Nuxt à la racine de son référentiel obtient désormais ses routes. Réindexez les projets Vue après la mise à niveau.
  • Les routes NestJS sont désormais nommées en fonction du chemin emprunté par une requête : le préfixe global de app.setGlobalPrefix('api') est appliqué, ainsi que sa liste exclude, tout comme la gestion des versions URI de app.enableVersioning(...), avec @Version, VERSION_NEUTRAL et le propre version d'un contrôleur pris en compte. Une route qui apparaissait auparavant sous la forme GET /user est désormais GET /api/v1/user, donc l'appel this.http.get('/api/v1/user') ou fetch d'un frontal se connecte à la méthode de contrôleur qui la dessert. Réindexez les projets NestJS après la mise à niveau.
  • Les routes Laravel sont désormais nommées en fonction du chemin emprunté par une requête : un / de début est ajouté là où le fichier de routes le laisse de côté, les groupes Route::prefix() et Route::group(['prefix' => …]) sont appliqués, et les routes dans routes/api.php portent le préfixe /api sous lequel Laravel les sert, lu à partir de votre RouteServiceProvider, bootstrap/app.php ou de tout fichier qui monte un fichier de routes. Un front-end fetch('/api/…') se connecte désormais à la route Laravel qui le dessert. Réindexez les projets Laravel après la mise à niveau.
  • Les contrôleurs que Spring ou Laravel testent par URL comptent désormais comme testés. Cela couvre le perform(post("/owners/new")) de MockMvc, le WebTestClient, ​​le TestRestTemplate, RestAssured, le $this->postJson('api/me') de Laravel, le get('/about') de Pest et les propres assistants de requête d'un projet construits sur eux. codegraph_explore nomme désormais la suite de tests qui atteint un tel point final, alors qu'avant chacun d'entre eux ne semblait pas testé. Réindexez les projets Spring et Laravel après la mise à niveau.
  • Dans une application Angular, une méthode appelée par un modèle, comme (click)="toggleFavorite()" ou (ngSubmit)="submitForm()", est désormais liée depuis son composant. Ces méthodes ne montraient aucun appelant, donc l'impact et les questions des appelants s'arrêtaient sur eux, et les vérifications de code mort pouvaient les répertorier comme inutilisés. Réindexez les projets angulaires après la mise à niveau.
  • Les applications angulaires ont désormais des itinéraires et une navigation dans le graphique. Chaque écran d'un tableau Routes est une route nommée par son chemin complet, y compris les enfants, les fichiers loadChildren et NgModules chargés paresseusement, les chemins écrits sous forme de constantes de route ou de chaînes $localize et les redirections. Chaque itinéraire est lié à son composant. router.navigate([...]), navigateByUrl, un createUrlTree de garde et chaque routerLink dans le modèle d'un composant sont liés à l'écran qu'ils ouvrent, et les composants enfants d'un modèle (<app-article-list>) sont liés au composant qui les restitue. Des questions telles que « où va ce bouton » et « qu'est-ce qui restitue ce composant » ont désormais des réponses dans codegraph_explore. Réindexez les projets angulaires après la mise à niveau.
  • Les fichiers d'inclusion Delphi et Free Pascal (.inc) sont désormais indexés en Pascal. Avant, ils étaient lus comme PHP et étaient vides. Un fichier .inc avec une balise <?php est toujours PHP, et un mappage codegraph.json pour .inc l'emporte toujours. Merci @ijbranch pour le rapport. (#2279)
  • Dans CFML basé sur des balises, les appels écrits dans des balises sont désormais liés : dans les expressions <cfset>, <cfif>/<cfelseif>, <cfreturn>, <cfloop condition> et #…#. Auparavant, seul le code <cfscript> et <cfquery> était lu, donc les appelants et l'impact ne trouvaient presque rien dans les composants basés sur des balises. Les fonctions enveloppées dans des balises comme <cfprocessingdirective> ou <cfsilent> sont désormais également indexées, et un <cfinterface> est indexé en tant qu'interface à laquelle implements est lié. Réindexez les projets CFML après la mise à niveau. Merci @HarryMuc pour le rapport. (#2091)
  • Les constantes d'énumération Java et les entrées d'énumération Kotlin avec leur propre corps ont désormais leurs méthodes dans le graphique. Les exemples sont PLUS { int apply(…) { … } } et NewBuffer { override fun pipe() … }. Avant, ces méthodes manquaient et chaque appel qu’elles contenaient était abandonné. Le tokenizer HTML et le constructeur d'arborescence de jsoup sont écrits de cette façon, donc plus de 2 000 de leurs appels étaient invisibles. Réindexez pour récupérer cela.
  • Les appels d'infixe Kotlin, comme Users.id eq id1 ou single { … } bind MyApi::class de koin, sont désormais enregistrés comme des appels à la fonction infixe. Avant, ils n’avaient aucun appelant. Sur Exposed, eq affiche désormais plus d'un millier d'appelants. Les opérations binaires sur les nombres (x and 0xff, h shr 8) sont laissées aux propres opérateurs de Kotlin, même lorsque le projet définit une extension du même nom. Réindexez après la mise à niveau.

Correctifs

Fenêtres

  • Sous Windows, les fenêtres du terminal ne s'ouvrent et ne se ferment plus lorsque CodeGraph s'exécute en arrière-plan. Depuis 1.6.1, un serveur MCP en arrière-plan a affiché une fenêtre de console (une fenêtre de terminal Windows complète lorsqu'il s'agit du terminal par défaut) plusieurs fois au démarrage et à chaque fois qu'il resynchronisait un fichier modifié. Tous les appels git de CodeGraph sont désormais masqués. Merci @Suharaz, @23q3, @A-Van-Gestel, @HarryMuc et @MzaGuille. (#2094, #2096, #2312)
  • Sous Windows, un projet ouvert avec une casse de lettre de lecteur ou de nom de dossier différente, comme d:\work\app et D:\Work\App, rejoint désormais le serveur d'arrière-plan CodeGraph qui est déjà en cours d'exécution pour lui. Avant, chaque orthographe démarrait son propre serveur qui se fermait immédiatement, de sorte que la session servait silencieusement le graphique par elle-même, sans surveillance de fichiers partagés ni synchronisation automatique, et codegraph list montrait le projet deux fois. Merci @greatjackzhou. (#2278)
  • Sous Windows, codegraph upgrade n'interrompt plus l'installation lorsqu'une session d'agent utilise CodeGraph. Il s'arrêtait à mi-chemin et laissait CodeGraph incapable de démarrer ; il échange désormais les nouveaux fichiers avec CodeGraph en cours d'exécution et rétablit la version précédente en cas d'échec, et la réexécution du programme d'installation de PowerShell fonctionne de la même manière. Si une mise à niveau antérieure a déjà interrompu votre installation, réexécutez irm https://raw.githubusercontent.com/colbymchenry/codegraph/main/install.ps1 | iex pour la réparer. Merci @tippmar-nr pour le rapport. (#2185)
  • Sous Windows, CodeGraph ne plante plus parfois avec le code de sortie 3221225477 (une violation d'accès) sur une machine occupée : juste après l'analyse dans codegraph init, codegraph index et les synchronisations en arrière-plan, ou lorsque le serveur en arrière-plan s'arrête. L'arrêt de l'un de ses threads d'assistance (ceux qui analysent les fichiers, résolvent les références, écrivent l'index et comptent les modifications pour codegraph_status) alors qu'il était encore en cours de démarrage, ou avant qu'il ait fini de nettoyer sa mémoire, a interrompu l'ensemble du processus. Les threads finissent maintenant de démarrer et de se nettoyer avant de se terminer.

Le serveur d'arrière-plan, les sessions et le CLI

  • Le hook d'invite Claude Code ne s'exécute plus sur les messages que Claude Code utilise pour renvoyer le rapport d'un sous-agent à la session principale. Avant, un rapport aussi long pouvait occuper le hook au-delà du délai d'attente de 30 secondes de Claude Code et injecter un contexte sans rapport avec ce que vous aviez demandé. Merci @danusha2345 et @tippmar-nr pour le rapport. (#2184)
  • Les nouveaux MCP clients tels que Antigravity 2.5 se connectent à nouveau : le serveur répond désormais immédiatement à leur sonde server/discover avec "méthode non trouvée", ils passent donc directement à la poignée de main habituelle au lieu d'attendre une réponse qui pourrait prendre quelques secondes ou ne jamais arriver. Merci @danusha2345 et @samem26 pour le rapport. (#2084)
  • Une session CodeGraph qui a interrogé un autre projet via projectPath ne maintient plus ce projet verrouillé aussi longtemps qu'il est en cours d'exécution : après 10 minutes sans requête, elle laisse le projet se poursuivre, afin que la propre session du projet et codegraph index puissent reprendre le relais (réglage avec CODEGRAPH_PROJECT_IDLE_TIMEOUT_MS, 0 le maintient ouvert). Merci @danusha2345 et @bompus pour le rapport. (#2087)
  • Claude Code montre maintenant au modèle le texte intégral de codegraph_status et du refus d'index périmé d'explore. Les deux résultats portaient également structuredContent, et Claude Code affiche le structuredContent d'un résultat à la place de son texte, de sorte que le modèle n'a vu qu'un objet de fraîcheur JSON : pas de message de refus, pas de conseils de nouvelle tentative et pas de rapport d'état. Les deux résultats sont désormais uniquement du texte. Merci @bompus. (#2088)
  • Lorsqu'un agent interroge CodeGraph sur un référentiel git distinct imbriqué dans un projet indexé, celui que l'index du projet laisse de côté (par exemple parce que le .gitignore du parent l'exclut), il obtient désormais les instructions habituelles "n'est pas indexé" au lieu des réponses du code du projet parent. Les référentiels imbriqués que le parent indexe, tels que les sous-modules, fonctionnent comme avant. Merci @wstczyw pour le rapport. (#2110)
  • Une session d'agent qui a perdu sa connexion au serveur d'arrière-plan partagé de CodeGraph, ou qui n'a pas pu l'atteindre au démarrage, n'empêche plus ce serveur de s'exécuter pour le reste de la session. Il se reconnecte tout seul une fois que le serveur peut démarrer, de sorte que les autres sessions du même projet soient automatiquement synchronisées au lieu de s'exécuter en lecture seule. Merci @ijbranch pour le rapport. (#2277)
  • codegraph index n'abandonne plus avec "Impossible de vérifier que le démon CodeGraph actif s'est arrêté" alors que le serveur en arrière-plan est toujours en train de terminer son arrêt, et codegraph daemon ne signale plus un tel serveur comme étant un serveur qu'il ne pouvait pas arrêter ; les deux attendent maintenant qu'il se termine, pendant environ 20 secondes. Une session d'agent qui sert CodeGraph par elle-même, car le serveur d'arrière-plan n'était pas disponible, attend désormais également que ce travail s'arrête avant de se terminer au lieu de se terminer à mi-chemin, ce qui pourrait planter sous Windows. Merci @bompus. (#2311)
  • La télémétrie d'utilisation anonyme envoie désormais un décompte quotidien par outil ou commande, comme documenté, au lieu d'un par processus de codegraphe. Avant, à chaque lancement de serveur MCP, la commande CLI et le hook d'invite mettaient en file d'attente sa propre entrée, de sorte qu'une machine occupée téléchargeait des milliers de copies du même nombre chaque jour. Si la télémétrie est désactivée, rien ne change.

Indexation et synchronisation

  • Un fichier COBOL dont la dernière ligne se termine à l'intérieur de la zone de séquence (colonnes 1 à 6), comme un point de fermeture indenté de seulement quatre espaces, ne bloque plus l'indexation pendant plus d'une minute et se retrouve ensuite dans l'index sans symbole.
  • L'édition d'un fichier qui définit le même nom plus d'une fois, comme deux classes ayant chacune une méthode execute ou les surcharges d'une méthode, ne déplace plus tous les appelants des autres fichiers vers l'un d'eux pendant codegraph sync. Une synchronisation interrompue à mi-chemin d'un fichier ne perd plus non plus ces appelants jusqu'à une réindexation complète. Merci @ijbranch pour le rapport. (#2276)
  • L'indexation d'un grand projet C ou C++ ne manque plus de mémoire à mi-chemin de la « Résolution des références ». Les en-têtes dont la protection d'inclusion est écrite sous la forme #define X_H 1, comme dans OpenSceneGraph et osgEarth, ou qui sont inclus sous un codegraphe d'indicateur de construction ne peuvent pas être connus, étaient relus sur chaque chemin d'inclusion, qui croît de façon exponentielle avec la profondeur de l'arborescence d'inclusion. Chacun est désormais lu une fois par état d'inclusion, et une limite stricte arrête la vérification de toute arborescence d'inclusion encore trop grande. Merci @danusha2345 et @coolhitmanleon pour le rapport. (#2127)
  • Sur une machine occupée, l'indexation ou la synchronisation d'un petit projet ne démarre plus de threads d'arrière-plan supplémentaires pour résoudre les références qu'il ne peut pas utiliser. Sous une charge importante, le rythme plus lent donnait l'impression qu'un projet de dix fichiers était suffisamment volumineux pour en avoir besoin, ce qui ajoutait des secondes à l'exécution et occupait de la mémoire supplémentaire.

Dans toutes les langues

  • Un type qui étend un autre type du même nom est désormais lié à cet autre type plutôt qu'à lui-même. Lorsque la source précise le qualificatif, ce qualificatif choisit parmi les candidats du même nom. Avant, le trait BigDecimalInstances extends cats.kernel.instances.BigDecimalInstances des chats et chaque trait AllOps … with Functor.AllOps[…] pointaient vers le trait déclarant, et le JsonConverter<T> : JsonConverter de Newtonsoft.Json s'est étendu.
  • Les conventions de nom de framework pour Django, FastAPI, Flask, ASP.NET, Gin, SwiftUI et Vapor choisissent désormais uniquement une classe que la référence peut voir. Des exemples de ces conventions sont « un …View est une vue », « un …Service est un service » et « un nom capitalisé est un modèle ». La récursion réelle est inchangée.

Auparavant, les types Record<string, …> de typeorm atteignaient une entité de test appelée Record, et les exemples d'annotations @Override de okhttp atteignaient la classe Override imbriquée d'un test. Le code de support de test fourni par un projet, tel qu'un dossier testing/ ou un module *-test, reste à portée de main.

Cela couvrait les classes nommées Mocked…, Fake…, Stub… ou Dummy… : les appels resp.json() de django-allauth étaient tous allés vers son MockedResponse. Java, Kotlin et Scala

  • En Java, un nom de type nu est désormais résolu uniquement en un type accessible. Il s'agit d'un type dans le même package, importé par son nom ou avec .*, ou d'un type imbriqué utilisé depuis son propriétaire, depuis une sous-classe (classes anonymes incluses), ou écrit via son propriétaire comme dans Outer.Inner. Un constructeur ne remplace plus sa classe et une constante d'énumération est atteinte par son nom nu uniquement à l'intérieur de son énumération, dans une étiquette case ou via une importation statique. Avant, le new Retrofit.Builder() de mise à niveau était lié au RequestFactory.Builder, le micromètre de Halo Counter à sa propre classe Counter et le java.lang.Class<?> de jsoup à une classe de sélecteur imbriquée.
  • Les appels nus dans les scripts Gradle Kotlin (build.gradle.kts), comme plugins { }, dependencies { } ou api(…), ne sont plus liés à une méthode ou propriété d'une des classes propres du projet. Les fonctions d'extension de la logique de construction sur les types de Gradle sont toujours résolues. Avant, les scripts de construction de nowinandroid pointaient chaque bloc plugins { } et dependencies { } vers la classe Graph de sa logique de construction, et chaque api(…) vers la propriété api d'un registre de charpie.
  • Dans Scala, le membre d'un objet package est désormais résolu uniquement là où il se trouve dans sa portée : dans son propre package, les packages situés en dessous ou un fichier importé via ce package. Avant, les lois des chats résolvaient Eq, Order et Monoid en alias de l'objet package algebra plutôt qu'en celui de l'objet package cats, et les tests akka de sttp atteignaient le whenRequestMatches d'un objet package zio.
  • Dans les projets Spring, un nom de classe est désormais résolu par celui du propre fichier ou package de la référence avant toute convention de supposition par dossier. Une classe imbriquée dans la classe d'un autre fichier n'est jamais atteinte par son simple nom. Avant, le new Criteria() de chaque classe MyBatis Example dans le centre commercial était lié au Criteria imbriqué du premier Example, et le Lombok @Builder de Halo était lié à une classe Builder imbriquée ailleurs.
  • Dans Scala, un espace réservé de type-projecteur dans un type, comme Align[Either[A, *]], n'est plus lié à une méthode opérateur nommée *. Un nom symbolique dans un type, comme le F ~> G des chats, se résout désormais uniquement en un type.
  • Les appels Kotlin à l'intérieur d'un lambda DSL atteignent désormais le propre récepteur du lambda. Ce récepteur provient de la fonction à laquelle le lambda est transmis, même via un typealias comme le Definition<T> = Scope.(…) -> T de koin. Il l'emporte également sur d'autres types que le projet utilise ailleurs comme récepteurs lambda. Sur koin, plus de 2 000 appels get() dans single { … } atteignent désormais Scope.get au lieu de Koin.get ; en cas d'exposition, varchar(…) à l'intérieur d'un objet table atteint Table.varchar ; sur kotlinx.coroutines, launch { } atteint CoroutineScope.launch.
  • Un appel chaîné Scala comme xs.map { … } n'atteint plus un objet qui se trouve être nommé map, comme avec les chats alleycats.std.map et ses objets syntax/instances. Un type ou un objet dans une chaîne ne correspond que lorsque le récepteur nomme ce qui le contient, comme dans sttp.client4.Response(…).
  • Les importations Kotlin décident désormais de la signification d'un nom, comme le font déjà les importations Java. import java.net.Proxy ou import org.mockito.Mockito.mock ne sont plus liés à un symbole de projet du même nom, et un membre que le fichier déclare lui-même vient toujours en premier. Un import x.Foo choisit la bonne classe parmi plusieurs classes du même nom : sur okhttp, MockResponse.Builder() et Request.Builder() atteignent désormais leurs classes. Une importation de changement de nom comme import …internal.unsafeFlow as flow signifie la fonction qu'elle nomme.
  • En Java, une classe que vous importez depuis l'extérieur de votre projet possède désormais son nom. Après import java.lang.reflect.Field;, le Field du fichier n'est plus lié à une classe de projet qui partage le nom. Dans gson, il s'agissait d'une classe Field imbriquée d'un test ; dans le convertisseur W3C de jsoup, il s'agissait des Document et Element de jsoup. Une importation statique comme import static org.mockito.Mockito.verify; est traitée de la même manière.
  • Les appels Scala n'arrivent plus sur la valeur locale d'un autre test. Un val f écrit dans un bloc test("…") { } était sélectionné pour un paramètre lambda f dans une autre suite, et même pour f(…) dans la bibliothèque principale de cats. Une importation de package telle que import cats.syntax.all._ n’inclut plus les membres de chaque classe. Les membres qui sont réellement dans la portée sont désormais résolus : ceux des types parents d'un objet package importé (import sttp.client4._ donne le multipart de SttpApi) et du propre objet package du fichier.
  • Les fichiers Kotlin utilisant une syntaxe plus récente conservent désormais leurs classes intactes. Cela couvre les conditions de garde when (is X if cond ->), les gammes ..<, les chaînes multi-dollars ($$"…") et les récepteurs nullables dans les types de fonction (T?.() -> R). Auparavant, la classe autour d'un tel code pouvait se présenter sous la forme d'un ensemble de fonctions lâches. Sur Exposed, les fichiers avec une erreur d'analyse sont passés de 65 à 43, et sur kotlinx.coroutines de 50 à 46. Réindexez après la mise à niveau.
  • Le code Kotlin utilisant une fonction infixe dont le nom commence par e, comme Users.id eq id1 d'Exposed, est désormais analysé proprement. Avant, le reste d'une telle ligne était une erreur d'analyse, et dans un fichier contenant plusieurs d'entre eux, toute la classe qui l'entourait pouvait être perdue. Sur Exposed, les fichiers avec une erreur d'analyse sont passés de 229 à 71. Réindexez après la mise à niveau.
  • Dans Kotlin, un appel sans récepteur atteint désormais une méthode d'une autre classe uniquement lorsque cette classe est à portée. Cela signifie une classe, un object : Base() anonyme ou un récepteur de fonction d'extension autour de l'appel, ce dont ceux-ci héritent, ou le récepteur d'un DSL lambda (le single { get() } de Koin fonctionne sur un Scope, le withTables { … } d'Exposed sur une transaction). Un membre objet que le fichier importe est également à portée de main. Les error(…), require(x >= 0) { … } et check(…) de Kotlin n'arrivent plus sur la méthode d'une classe de projet de ce nom. Sur koin, module { … } dans un test atterrissait sur le module privé d'une autre classe de test plus de 260 fois, et à l'intérieur d'un lambda get() atterrissait sur le get de la mauvaise classe. Réindexez après la mise à niveau.
  • Les classes Kotlin dont le constructeur principal se trouve sur la ligne après le nom de la classe, avant une liste de supertypes (expect open class ByteString / internal constructor(…) : Comparable<ByteString>, courant dans le code Kotlin Multiplatform), ne perdent plus leurs membres à cause de fonctions perdues. Un appel plus tard dans une chaîne à une fonction de bibliothèque standard Kotlin (apply, let, toString, map, contains…) n'atteint plus la méthode du même nom d'un type de projet. Sur okhttp, .apply { … } atterrissait sur ConnectionSpec.apply. Réindexez après la mise à niveau.
  • Dans Scala, un appel atteint par son seul nom reste désormais à portée de main. Un nom que la fonction englobante lie en tant que paramètre ou local (f(true) pour f: A => B) est ce local. Un appel ultérieur dans une chaîne, comme fa.iterator.map(…), atteint uniquement un membre du nom de son destinataire. Un appel simple atteint uniquement la classe englobante et ses supertypes (y compris la base d'une sous-classe anonyme), un compagnon ou un objet importé. Sur les chats, les appels de paramètres comme f(a) atterrissaient sur le champ f d'une classe de cas plus de 400 fois et chaînaient .map(…) sur le map d'une classe d'opérations.
  • Dans Kotlin, un appel à une fonction de niveau supérieur ou d'extension se résout désormais uniquement en une fonction que le fichier peut voir : une dans son propre package, une qu'il importe par son nom ou une à partir d'un package qu'il importe avec *. Sur Exposed, les tests qui importaient le assertEquals de kotlin.test ou JUnit, ou l'assistant de la suite JDBC, atterrissaient sur l'assistant de la suite R2DBC plus de 3 000 fois. Sur okhttp, les tests qui importent mockwebserver3.MockResponse étaient utilisés pour construire la classe obsolète du même nom. Un type de fonction avec un récepteur qualifié, comme (DatabaseConfig.Builder.() -> Unit)?, n'interrompt plus l'analyse de la classe qui l'entoure. Réindexez après la mise à niveau.
  • Un simple appel Java comme verify(mock), assertThat(x) ou hashCode() est désormais lié uniquement à une méthode de la classe dans laquelle il se trouve, aux parents de cette classe ou à une méthode importée statiquement par le fichier. Il était autrefois lié à n'importe quelle méthode de classe de ce nom : dans Halo, les verify et eq de Mockito donnaient le verify d'un service à plus d'un millier d'appelants inventés, et dans la mise à niveau, le assertThat de Truth faisait de même à un assistant de test. Les appels aux méthodes héritées et les importations statiques du projet sont désormais liées à la bonne, comme attr(…) de jsoup à LeafNode ou and(…) / equal(…) de halo à import static …Queries.*. Réindexez les projets Java après la mise à niveau.

C# et VB.NET

  • Les noms C# suivent désormais les portées du langage. Un bloc namespace X { … } qualifie uniquement les types qu'il contient, donc un type déclaré après le bloc, ou dans le deuxième espace de noms d'un fichier, n'est plus classé sous le premier. Un espace de noms écrit dans un autre est Outer.Inner. Un using est lié à l'espace de noms du projet au lieu du using d'un autre fichier du même nom. Un global using s'applique uniquement au sein de son propre projet. Un type imbriqué n'est accessible par son nom nu que depuis l'intérieur de son propriétaire ou un type qui en dérive, y compris via une autre partie partielle. Avant, le Guard de Serilog était classé sous JetBrains.Annotations, le Some.InformationEvent() de ses tests allait au Some des tests de performances, et le même fichier new Source() d'AutoMapper pouvait atteindre le Source imbriqué d'une autre classe de test.
  • Les noms de types C# suivent désormais les espaces de noms. Un type est accessible depuis son propre espace de noms ou un espace imbriqué à l'intérieur, ou via un using de son espace de noms. Sont également comptés : un global using à l'échelle du projet, les entrées <Using> du projet, les utilisations implicites du SDK ou un alias qui le nomme. Auparavant, les tests async Task de Newtonsoft liaient Task à une classe de test de ce nom dans un autre espace de noms, et les DTO d'AutoMapper étaient liés au BaseEntity d'un autre espace de noms.
  • Les membres C# d'une interface sont désormais publics et les types déclarés sans modificateur sont désormais internes, comme le définit le langage. Un appel sur un champ typé par l'interface atteint désormais la méthode de l'interface, où il ne trouvait rien auparavant. Une supposition à partir du nom d'un destinataire ne pèse désormais que le nom du type propriétaire, et non son espace de noms. Les noms .NET standard comme ToString, Add et Write nécessitent un récepteur nommé d'après le propriétaire. Dans tous les langages, une supposition issue du code de production n'atteint plus un simulacre ou un assistant défini dans une suite de tests. Réindexez après la mise à niveau.
  • En C#, un nom simple comme TestContext, Easing ou Helper() se résout désormais uniquement en un membre de la classe dans laquelle il est écrit, ses classes externes, leurs classes de base ou un type introduit avec using static. Cela inclut un global using static et un <Using … Static="true"/> d'un fichier de projet. Sur l'eShop, le TestContext des classes de test atterrissait sur la propriété d'une autre classe de test ; sur Newtonsoft.Json, TypeNameHandling.All atteint désormais l'énumération plutôt qu'une propriété du même nom.
  • Dans VB.NET, un appel via un récepteur tel que Me.Panel.Controls.Add(…) ou New System.Drawing.Size(…) n'atteint plus un membre d'une classe non lié portant le même nom. Il est désormais résolu uniquement via Me, MyBase ou MyClass, via la propre classe ou module du membre (Logger.Log(…)) ou via un type de recherche de service (GetService(Of Notifier).Notify()). Sur SCrawler, le code du concepteur Windows Forms était utilisé pour lier plus de 700 appels Size à un cas d'énumération imbriquée et plus de 500 appels Controls.Add à une classe de collection.
  • En C# et VB.NET, un type écrit en code, comme Type sourceType, List<int>, new TypeMap() ou Dictionary<string, Type>, est désormais lié au type et non plus à une propriété, méthode ou champ qui partage son nom. List<…> était utilisé pour créer un lien vers la propriété List d'une classe de test, Type vers la propriété Type d'un attribut et un paramètre de type TypeMap vers une propriété TypeMap au lieu de la classe TypeMap. Ces membres se sont présentés avec des centaines de personnes à charge inventées. La lecture d'une propriété ou le passage d'une méthode, comme Builder.Services ou MapGet("/x", GetItems), génère toujours des liens comme avant. Réindexez les projets C# et VB.NET après la mise à niveau.

Swift et Objective-C

  • Une classe Objective-C conforme à un protocole de son propre nom est désormais liée à ce protocole plutôt qu'à elle-même. Les conventions de dénomination de Swift pour les vues, les modèles et les contrôleurs ne s'appliquent plus non plus au code Objective-C. Avant, chacune des classes de style @interface SDDiskCache : NSObject <SDDiskCache> de SDWebImage s'implémentait elle-même.
  • Dans Swift, un appel à une méthode surchargée atteint désormais la surcharge dont il épelle l'argument, avec les paramètres par défaut facultatifs. Avant, seul le nombre d’arguments était comparé. Le self.tableView(tableView, numberOfRowsInSection:) d'Alamofire à l'intérieur d'une autre surcharge tableView liée à elle-même, et cancel(optionallyProducingResumeData:) liée à cancel(producingResumeData:).
  • Un appel Swift sur une propriété déclarée avec un type, comme var cache: ImageCache! ou self.storage.write(…) de Kingfisher, atteint désormais la méthode de ce type ou celle dont il hérite. Il n'atteint plus un remplacement de sous-classe dans un test ou la méthode d'un autre type du même nom.
  • Un appel Swift sur une valeur construite sur place, comme JSONDecoder().decode(…) ou Realm().create(…), se résout désormais en la méthode de ce type, ou en celle dont il hérite. Il n'atteint plus la méthode d'un autre type du même nom : les appels JSONDecoder().decode de Vapor étaient dirigés vers le conteneur privé d'une requête.
  • En Objective-C, [super init] et les autres messages destinés à super atteignent désormais la méthode de la superclasse, jamais la propre substitution de la classe émettrice. Cela fonctionne également là où l'index a perdu la portée du @implementation. Sur SDWebImage, le [super init] des sous-classes de NSObject atterrissait sur le init de SDDiskCache et [self class] lors de tests sur le class d'une classe proxy. Sur AFNetworking, le [super encodeWithCoder:] d'un sérialiseur atteint désormais sa superclasse. Réindexez après la mise à niveau.
  • Dans Swift, un appel écrit sans récepteur, ou via self. ou super., atteint désormais uniquement un membre du type qui l'entoure ou de ce dont ce type hérite ou se conforme, et le remplacement le plus proche l'emporte. Un nom de bibliothèque standard plus tard dans une chaîne (axis.entries.removeAll(), names.contains(x)) n'atteint plus la méthode d'un type de projet, à moins que le récepteur ou l'étiquette d'argument de l'appel n'y pointe. Sur les graphiques, min(a, b) et max(a, b) atterrissaient sur le champ min d'un type de plage et une extension Sequence, et super.init(…) sur le init d'une démo Objective-C plus de 170 fois. Un global dans un terrain de jeu ou une cible de test n'est plus lié au code principal. Réindexez après la mise à niveau.
  • En Objective-C, un message n'atteint désormais une méthode que lorsqu'il pourrait réellement y être envoyé. Un message adressé à self ou super atteint uniquement la classe de l'expéditeur et ses superclasses, y compris les catégories dans les vues UIKit et AppKit. Un appel de style C comme completionBlock() n'est jamais considéré comme une méthode ou une propriété. Un message adressé à une variable locale utilise le type déclaré de la variable (FMResultSet *rs). Sur SDWebImage, [self class], respondsToSelector: et isKindOfClass: atterrissaient sur les remplacements d'une classe proxy plus de 150 fois, et sur fmdb, [rs close] atteignait désormais l'ensemble de résultats.
  • Un appel Swift via un type imbriqué, comme API.PackageController.GetRoute.query(on: db), est désormais lié à la méthode de ce type. Seul le query était conservé, donc l'appel lié au query du type quel qu'il soit arrivait en premier ; dans une application Vapor, chaque type d'itinéraire en a un, donc les appelants, l'impact et les réponses codegraph_explore pointaient vers le code d'un autre point de terminaison. La même chose s'applique aux initialiseurs de types imbriqués (API.PackageController.Model(name:)), aux cas d'énumération (Gitlab.Error.requestFailed(status:)), aux types déclarés dans un extension API.PackageController { … } et au Path.State.detail(…) de The Composable Architecture. Un appel sur un chemin de type qui ne nomme aucun type dans le projet, tel que le Plot.Node.footer(…) d'un SDK, n'est pas lié. Réindexez les projets Swift après la mise à niveau.
  • Une vue SwiftUI, une application @main, un contrôleur de vue et une sous-classe UIView sont désormais indexés une fois. Chacun obtenait auparavant une deuxième copie d'une ligne sans appelants ni appels, qui apparaissait à côté du type réel dans la recherche et les réponses codegraph_explore comme une impasse. Réindexez les projets Swift après la mise à niveau.
  • Une classe ou une structure Swift qui déclare une composition de protocole sur plusieurs lignes, comme typealias Client = AutocompleteService.Client suivi de & PostingService.Client sur la ligne suivante, est désormais indexée dans son intégralité. Cette ligne interrompait l'analyse de l'ensemble du type englobant, de sorte que ses méthodes, son initialiseur et ses propriétés ont disparu, et les appels ont atterri sur des méthodes du même nom ailleurs. Réindexez les projets Swift après la mise à niveau.
  • Une référence Swift à un type est désormais liée à la propre déclaration du type, et non à un fichier qui l'étend. Un extension View { … } ou un extension Text { … } remplaçait le type de SwiftUI, donc chaque vue, chaque Text("…") et chaque Color.red dans une application liée au fichier qui l'étendait. Ces fichiers figuraient en tête des listes les plus fiables et leur impact a atteint l'ensemble de l'application. Un nom simple comme @State, @Test ou Result<…> ne renvoie plus au State ou Result imbriqué d'un autre type, et un nom qualifié comme Build.Id renvoie au Id qu'il nomme. Les méthodes déclarées dans une extension d'un type SDK se résolvent toujours sur les types qui s'y conforment, et les méthodes d'un protocole déclarées dans l'une de ses extensions se connectent désormais à la propre implémentation de chaque type conforme. Réindexez les projets Swift après la mise à niveau.
  • Une route Vapor est désormais liée au gestionnaire qu'elle nomme. use: SearchController.show était utilisé pour établir un lien vers le show du contrôleur arrivé en premier, donc les itinéraires avec un nom de gestionnaire commun, comme show, index ou get, pointaient vers le code d'un autre point de terminaison dans les appelants, l'impact et les réponses codegraph_explore. Les types imbriqués comme API.PackageController.get et les gestionnaires déclarés dans une extension du contrôleur sont désormais également résolus, et use: self.index se résout en propre index de la collection. Réindexez les projets Vapor après la mise à niveau.

C, C++, Go et Rust

  • Un appel en code C n'est plus lié à la méthode d'une classe C++, puisque C n'a pas de méthode et ne peut pas en appeler. Avant, les appels POSIX read(fd, buf, n) de redis et le pointeur de fonction c->funcs->read(…) de hiredis pointaient vers la méthode read d'un adaptateur Qt.
  • Dans Go, un nom écrit via un package importé de l'extérieur du module, comme context.Context, http.ResponseWriter ou require.Contains de Témoin, n'est plus lié à un symbole de projet de ce nom. Auparavant, les paramètres context.Context de Fiber pointaient vers une méthode Stream.Context, ses assertions require.Contains(…) vers le Contains d'un extracteur et le http.ResponseWriter de gin vers sa propre interface ResponseWriter.
  • Dans Rust, Self::Error dans une signature se résout désormais en type associé à l'implant ou au trait englobant. Un chemin via un paramètre générique, comme V::Value, ne se résout plus en une structure sans rapport de ce nom. Avant, les signatures Self::Error de Serde indiquaient son seul struct Error, et le Self::Error d'Axum le type d'erreur de axum-core.
  • Dans les projets Rust, un nom de structure, de gestionnaire ou de service ne se résout plus en un élément déclaré dans le corps d'une fonction, et le propre élément d'un fichier précède celui de toute autre caisse. Avant, le Uri des exemples d'axum était lié à un struct Uri déclaré dans un test de routage, le runtime de tokio Handle était lié à celui de tokio-test et le Glob { … } de ripgrep dans le globset était lié au Glob des indicateurs CLI.
  • Les noms de type et de fonction Rust suivent désormais la portée de Rust. Un nom d'un autre fichier ne compte que lorsqu'un use l'apporte (ou un glob * sur son module). Un élément importé de l'extérieur du projet, comme use std::task::{Context, Poll} ou use futures::Stream, signifie cet élément extérieur. Un chemin nomme son module : io::Result n'est pas un alias Result sans rapport ailleurs, et std::io::Error est celui de std. Sur tokio, plus de 1 200 références de io::Result et 600 Context atterrissaient sur des types de projets privés.
  • Un appel C++ dans un espace de noms ouvert par une macro, comme fmt::format("{}", x), sélectionne désormais la surcharge adaptée à ses arguments. Avant, la première surcharge indexée gagnait : les 1 400 appels fmt::format de fmt atteignaient tous la surcharge text_style dans color.h. Un littéral de chaîne étroite s'adapte désormais à une chaîne de format étroit, un L"…" large s'adapte à la surcharge large et le nombre d'arguments doit également s'adapter.
  • Les classes C++ écrites autour des macros et des conditions du préprocesseur conservent désormais leurs membres. Ceux-ci incluent un spécificateur d'accès orthographié sous forme de macro (JSON_PRIVATE_UNLESS_TESTED:), une macro d'attribut après un en-tête de modèle ou un commentaire de document et un #if au milieu d'une déclaration, comme dans la liste d'initialisation d'un constructeur. La première branche d'une mi-déclaration #if est celle indexée. La classe basic_json de nlohmann/json était autrefois perdue et compte désormais environ 390 membres. Les fichiers avec une erreur d'analyse ont été supprimés sur redis, curl, pybind11 et leveldb, et aucun fichier n'a empiré. Réindexez après la mise à niveau.
  • Les appels aux propres types et modules d'une bibliothèque n'aboutissent plus sur une méthode projet qui partage le nom. Dans Rust, Vec::new(), String::from(…) et les chemins de modules comme task::spawn(…) restent la bibliothèque standard. Un maillon ultérieur d'une chaîne Rust ou Go multiligne compte désormais comme un appel chaîné, nommé d'après la première ligne de la chaîne. Dans Go, w.Header().Get(…) est net/http's. En R, un appel simple comme range(x) est une fonction, pas la méthode d'un objet. Dans JavaScript, response.text() / .json() sont récupérés. À Tokyo, task::spawn(…) atterrissait 300 fois sur TaskTracker::spawn. Sur ggplot2, range(…) atterrissait sur la méthode range d'un système de coordonnées. Réindexez après la mise à niveau.
  • En C et C++, un nom qualifié comme fmt::format atteint désormais une déclaration dans un espace de noms que la bibliothèque ouvre avec une macro, comme FMT_BEGIN_NAMESPACE de fmt, PYBIND11_NAMESPACE_BEGIN(…) de pybind11 ou apidjson et …_NAMESPACE_BEGIN de spdlog. Il fonctionne également via un alias d'espace de noms tel que namespace py = pybind11;. Sur fmt, 1 728 appels fmt::format(…) n'étaient liés à rien, tout comme environ 1 400 appels py::… sur pybind11.
  • Dans Rust et Go, un appel plus tard dans une chaîne, comme sym.filename().map(…) ou c.Flags().String(…), n'atteint plus la propre méthode du projet de ce nom lorsque le nom est celui d'une bibliothèque standard (unwrap, clone, map, iter, Go's String ou Error). Un appel simple comme get(handler) ou drop(x) n'atteint jamais une méthode. Sur Tokyo, .map(…) sur un Option atterrissait sur MutexGuard::map ; sur Axum, le get(handler) du routeur sur le get d'un pot à biscuits ; sur ripgrep, .clone() sur un type d'erreur.
  • Dans Rust, un Ok(…), Some(…), Err(…), Result<…>, Option<…>, Vec<…> ou drop(…) signifie désormais celui de la bibliothèque standard, sauf si le fichier définit ou importe un élément de projet de ce nom. Ceux-ci étaient utilisés pour établir un lien vers n'importe quelle variante ou structure d'énumération du même nom dans le projet : chaque Some(x) dans ripgrep vers la variante Some d'une énumération, et chaque Ok et Result dans serde aux structures déclarées par ses tests de macro-hygiène. Une variante d'énumération est désormais atteinte par un nom simple uniquement là où le fichier use le désigne ou son * d'énumération, et une variante ne représente jamais un type. Réindexez les projets Rust après la mise à niveau.

PHP, Ruby, Dart, Lua, R, Solidity, Erlang et CFML

  • Dans les applications Laravel, une route dont le contrôleur est nommé par chaîne est désormais liée à son gestionnaire, sans avoir besoin d'un suffixe Controller et en conservant l'espace de noms avec lequel elle est écrite : 'Common\Uploads@inline', et Route::resource('companies', 'Common\Companies', [...]) avec un tableau d'options. Deux contrôleurs du même nom dans des espaces de noms différents sont différenciés par cet espace de noms. Avant, akaunting reliait 304 de ses 313 itinéraires à rien.
  • Dans les applications Rails, les only: et except: d'une ligne resources sont désormais lus sous toutes les formes acceptées par Rails : %i[new create index], %w(index show), un nom entre guillemets et l'ancien :only => [...]. Avant, seule une liste entre parenthèses était lue, alors peut-être que le resources :family_exports, only: %i[new create index] est devenu les sept routes, dont quatre vers des actions que le contrôleur n'a pas.
  • En PHP, une classe écrite avec un espace de noms dans son nom est désormais liée à cette classe. Après use App\Fields as Field;, new Field\FirstName(), extends Field\Base et Field\FirstName::make(), tous portent le nom de App\Fields\FirstName, tout comme Fields\FirstName écrit à l'intérieur de namespace App; et un \App\Fields\FirstName pleinement qualifié. Avant, aucun d’entre eux n’avait de lien, donc les appelants et l’impact manquaient chaque cours atteint de cette manière. Merci @drakeo338. (#2256)
  • Dans Solidity, un appel à une fonction surchargée atteint désormais la surcharge dont il correspond au nombre de paramètres, comme dans les autres langages avec surcharge. Avant, le _checkRole(role, _msgSender()) d'OpenZeppelin à l'intérieur du _checkRole(bytes32 role) à un argument était lié à lui-même.
  • Dans R, un appel comme c(1, 2) n'est plus lié à une variable de données qui partage le nom d'une fonction de base, puisque R ignore les liaisons non-fonctionnelles lorsqu'il recherche un appel. Avant, les tests de facettes de ggplot2 délimitaient c <- data_frame(b = 3), et chaque appel c(…) dans ces fichiers pointait vers cette trame de données. Les fonctions construites par une usine, comme le geom_point <- make_constructor(…) de ggplot2, sont toujours résolues.
  • Un Dart extension on X { … } sans nom n'est plus confondu avec le type X, et ses membres ne sont accessibles qu'à l'intérieur du fichier qui le déclare, comme dans Dart. Avant, le linter de bloc liait le Token de l'analyseur et le Uri de Dart à de petits blocs d'extension, et chaque appel flutter_test find.text(…) était lié à un getter text sur le TaskStatus d'un autre exemple.
  • En PHP, un nom de classe non qualifié est désormais résolu en classe de l'espace de noms actuel ou en celle importée par use, comme le fait PHP. Si la classe importée provient d'une bibliothèque, elle ne se résout en rien dans le projet. Auparavant, les requêtes de formulaire de Koel liaient extends Request à la classe Request indexée en premier, et les contrôleurs de BookStack liaient Request $request (celui de Laravel, par importation) à la sous-classe Request de BookStack.
  • Un appel Dart comme ext.endsWith(".avi") ou map.putIfAbsent(…) sur une valeur dont le type n'est pas connu compte désormais comme la propre méthode String, List ou Map de Dart. Il n’aboutit plus à une méthode projet du même nom. Une extension Dart correspond également au type qu'elle étend, et non à son propre nom, donc le ext.endsWith de getx sur une chaîne a cessé d'atteindre extension RxStringExt on Rx<String>.
  • Un simple appel Lua comme ipairs(t), error("…") ou setup() de busted signifie désormais la propre fonction de Lua à moins que le fichier n'en définisse une. Il n'atteint plus une méthode de table du même nom : les appels ipairs du télescope étaient allés vers le ipairs d'une liste chaînée, et les appels error de Kong vers son module de réponse. L'alias d'une fonction d'un membre de la table hôte, comme local get_query = kong.request.get_query, est désormais également suivi.
  • Les appels Lua effectués via un alias local atteignent désormais la fonction qu'il nomme. Cela couvre local splitn = require("kong.tools.string").splitn, un membre de module tel que utils.select_listener et une fonction qu'un module exporte sous un autre nom (return { check = check_phase }). Les alias des propres fonctions de Lua, telles que local type = type ou local fmt = string.format, n'apparaissent plus comme appels dans votre projet. Sur Kong, cela représente plus de 1 000 appels qui atteignent désormais leur véritable fonction, et environ 5 000 impasses de moins.
  • Dans Solidity, un appel sans récepteur atteint désormais une fonction du contrat qui l'entoure ou de celui dont il hérite. Sur OpenZeppelin, _msgSender() dans les contrats construits sur Context atterrissait 83 fois sur le remplacement de ERC2771Context. En Erlang, un appel à la fonction d'un autre module suit désormais le -import(Mod, [f/N]) du fichier. Sur Cowboy, les appels -import(req_SUITE, [do_get/3]) atterrissaient sur le do_get/3 d'une autre suite. Un simple appel sans importation de ce type ne renvoie plus à un autre module. Réindexez après la mise à niveau.
  • Dans Lua et Luau, un appel via une table de bibliothèque standard ou hôte (string, table, io, vim, ngx, busted's assert…) ou une méthode chaîne comme line:find(…) n'atteint plus la méthode projet du même nom. Les fonctions que le projet lui-même définit sur ces tables sont toujours liées. Sur Kong, les spécifications assert.truthy(…) et assert.falsy(…) atterrissaient sur un assistant de condition plus de 1 700 fois ; sur le télescope, line:find(…) sur le find du cueilleur.
  • En PHP, un appel via une variable de type Nothing n'atteint plus la méthode d'une classe sans rapport simplement parce que c'est la seule méthode portant ce nom. La variable doit maintenant être nommée d'après la classe de la méthode, ou d'après une classe qui en hérite ($page->save() où Page étend Entity). En pleine gueule, le $response->getHeaderLine() des tests atterrissait sur un double de test ; sur symfony/console, $e->getMessage() sur une barre de progression.
  • Dans CFML, un appel n'atteint plus la méthode d'un composant sans rapport simplement parce que le nom correspond. Un appel sans récepteur à l'intérieur d'un composant atteint désormais uniquement les méthodes de ce composant et celles des composants qu'il étend, donc les éléments intégrés comme now() restent intégrés. Un appel à une variable non typée nécessite désormais que la variable soit nommée d'après le composant, donc server.keyExists(…) n'est plus pris pour le keyExists de certains composants. Sur Coldbox, now() atterrissait sur un assistant de date plus de 200 fois, et le fail(…) de TestBox dans les spécifications atteint désormais la classe de base des spécifications.
  • Dans Ruby, un appel n'atteint plus la méthode d'une classe sans rapport simplement parce que c'est la seule méthode portant ce nom. Un appel sur un récepteur non typé nécessite désormais que le récepteur soit nommé d'après la classe de la méthode, comme web_push_request.legacy_encrypt. Un appel sans récepteur à l'intérieur d'une classe atteint désormais uniquement les méthodes de cette classe, les méthodes de ses superclasses et celles des modules qu'elle inclut, étend ou ajoute. Sur rubocop, node.loc sur un nœud de syntaxe atterrissait sur l'une des méthodes loc du projet plus de 1 200 fois, et format(…) du noyau sur le format du serveur de langue. Sur mastodon, render dans les contrôleurs atterrissait sur un moteur de rendu en ligne, et authorize atteint désormais le problème d'autorisation.
  • Dans Dart, un appel écrit sans récepteur n'atteint désormais qu'une méthode de la classe dans laquelle il est écrit, d'une classe qu'il étend, mélange ou implémente, ou d'une extension sur l'un de ces types, et choisit la plus proche. Sur riverpod, package:test test(…) dans les fichiers de test utilisés pour atterrir sur la méthode test d'une classe conteneur plus de 1 100 fois, expect(…) de Shelf et getx sur expect de classes non liées et emit(…) de bloc dans une Cubit sur la mauvaise classe de base. Les classes déclarées comme class A = B with C; sont désormais indexées sous leur nom, avec ce qu'elles étendent et mélangent. Réindexer après la mise à niveau.
  • Dans R, une variable affectée en haut d'un fichier de test n'est plus liée au package ou aux autres tests, car testqui exécute chaque fichier de test dans son propre environnement. Sur ggplot2, le c <- ggplot(…) d'un test collectait 2 455 des appels c(…) du package. Les variables dans helper-*.R et setup-*.R, qui testent le chargement pour chaque test, sont toujours partagées.
  • Dans Lua et Luau, une variable ou fonction local n'est plus liée à d'autres fichiers, puisqu'elle n'est visible que dans le fichier qui la déclare. Sur Kong, le local it = it d'un assistant de spécification était utilisé pour collecter le it(…) de tous les autres fichiers de spécifications (plus de 4 000 liens), et le local ipairs = ipairs d'un module prenait le ipairs(…) de l'ensemble du projet. Les fonctions globales sont toujours liées entre les fichiers.
  • Les appels PHP sur $this, self, static et parent atteignent désormais la méthode de la classe dans laquelle ils sont écrits, une classe qu'ils étendent, ou un trait que l'un d'entre eux utilise, avec les classes et traits parents trouvés via les importations namespace et use du fichier. Sur le noyau Drupal, $this->assertEquals() (PHPUnit's) était utilisé 8 832 fois pour se lier à une classe de comparaison non liée, $this->assertSession() à une classe de base de test JavaScript et $this->t() à Views::t. Ils atteignent désormais UiHelperTrait et StringTranslationTrait, ou rien lorsque la méthode réside dans un package extérieur au référentiel. Un appel à l'intérieur d'un trait et une classe de base appelant une méthode définie par sa sous-classe conservent leurs liens. Réindexez les projets PHP après la mise à niveau.
  • Un appel de fonction PHP écrit après => dans un tableau, comme 'count' => count($items), 'by' => user()->id ou 'label' => trans('…'), est désormais lu comme un simple appel de fonction. Auparavant, il était considéré comme un appel de méthode et lié à la classe possédant une méthode de ce nom. Sur BookStack, cela signifiait 166 mauvais liens.
  • Un appel PHP écrit sans récepteur, tel que redirect($url), view('books.show'), auth() ou basename($path), est un appel de fonction et n'est plus lié à une méthode, un champ ou une classe du même nom ailleurs dans le projet. Ces liens erronés apparaissaient dans les appelants, l'impact et les réponses codegraph_explore partout où un assistant Laravel ou un PHP intégré partageait son nom avec un membre du projet. Réindexez les projets PHP après la mise à niveau.

codegraph v1.6.2

[1.6.2] - 2026-10-03

Highlights

  • Far fewer wrong links, in every language. A call, import or type now resolves the way its language scopes names — through imports, packages, namespaces and the class it is written in — so it stops landing on an unrelated symbol that only shares its name. This covers TypeScript and JavaScript, Python, Java, Kotlin, Scala, C#, VB.NET, Swift, Objective-C, Go, Rust, C and C++, PHP, Ruby, Dart, Lua, R and more, and makes callers, impact and codegraph_explore answers more trustworthy.
  • Overloads, super and recursion resolve correctly. A call reaches the overload its arguments fit, a super call reaches the parent's method, and a method that calls another overload, or another object's method of the same name, no longer looks like it calls itself.
  • Routes for more frameworks. Angular (including Nx libraries), Vue Router admin apps, Rails nested routes, Flask's add_url_rule, ASP.NET FastEndpoints, Play subprojects, Vapor closure routes and Expo Router API routes are found. NestJS and Laravel routes are named by the path a request actually takes, and a Spring or Laravel test that calls a route by URL counts as covering it.
  • More of your code in the graph. Vue Options API components, Java and Kotlin enum constants with bodies, Flow-typed JavaScript, Kotlin infix calls, React Native native views and events, Expo modules, tag-based CFML and Delphi .inc files are all indexed now.
  • Windows: no flashing windows, no random crashes. The background server no longer pops up console windows while it works, sporadic access-violation crashes (exit code 3221225477) while indexing or shutting down are fixed, and codegraph upgrade works while an agent session is using CodeGraph.
  • A steadier background server. Newer MCP clients such as Antigravity connect again, Claude Code sees the full text of codegraph_status, a session that lost the shared server reconnects by itself, and a project queried through projectPath is released after 10 idle minutes.
  • Indexing that finishes. Large C and C++ projects no longer run out of memory while resolving references, a COBOL file can no longer stall indexing, and codegraph sync keeps every caller of a name that is defined more than once.
  • Upgrading: re-index your projects after this release — most of these fixes are written while indexing.

New Features

  • In Nuxt and Astro projects, a file-routed page is now linked to the component its file defines. An Astro endpoint is linked to the HTTP-verb handlers it exports, like export const GET. Before, a page route like Nuxt's pages/admin.vue or Astro's src/pages/about.astro linked to nothing, so callers, impact and flows stopped at the route.
  • React Router links and navigate(…) calls written through a route-config object, like bulletproof-react's paths.app.discussion.getHref(id), now reach the route they open. A <Link> with an arrow-function attribute before its to, such as onMouseEnter={() => …}, is read too.
  • React Router data-router routes are named by their full path: nested children paths are joined to their parent's, path: paths.app.root.path constants are read, and lazy: () => import('./routes/x') routes link to the module's component. A guard wrapper like <ProtectedRoute> no longer stands in for the page. On bulletproof-react, every route now has its real path and page.
  • Vapor routes whose handler is a trailing closure, like app.get("hello") { req in … }, WebSocket routes like app.webSocket("chat") { req, ws in … }, and routes.on(.POST, "x", use: handler) registrations are now found, and a closure route links to what the closure calls, the way an Express inline handler does. Before, only routes with a use: handler were read, and a closure route linked to nothing, so callers, impact and flows stopped at it.
  • Flow-typed JavaScript files (those with @flow in their header comment) are now parsed like TypeScript, so type annotations like render(): React.Node no longer cut classes short. This mostly affects React Native code: on React Native's own libraries the graph gained over 8,000 links, and component classes keep their methods. Files without the pragma are unchanged. Re-index after upgrading.
  • A link made by a framework or bridge resolver now records which one made it (metadata.framework, such as swift-objc-bridge or react-native-bridge), as the README describes. Before, only synthesized event and view channels were named.
  • ASP.NET apps built with FastEndpoints now have their routes: each endpoint class's Get(…) / Post(…) in Configure() becomes a route linked to its own HandleAsync / ExecuteAsync, including paths kept in a request class's Route constant. ardalis/CleanArchitecture went from no routes to 24. Minimal API routes written without a leading slash (app.MapGet("api/todos", …)) are now named /api/todos.
  • Play projects kept in subdirectories are recognized, so each one's conf/routes is read. A repository with no Play build at its root, like playframework's samples, went from no routes to over 130.
  • Rails routes are now read with their nesting: namespace and scope add their path and controller module, nested resources sit under their parent's :id, and member / collection blocks add their actions. A namespaced route now links to its own module's controller. Routes in a Rails engine's config/routes.rb are found too: solidus went from no routes to over 600, and mastodon's route-to-action links nearly tripled.
  • Flask routes registered with add_url_rule(…) are now found and linked to their view function or class-based view. So are routes registered through a project's own helper that passes a list of paths and a view_func=. flaskbb, which registers every view that way, went from no routes to over 100.
  • Vue components written with the Options API (export default { methods: {…}, computed: {…}, watch: {…}, mounted() {…} }), as every Vue 2 app is, now have their methods, computed properties, watchers and lifecycle hooks in the graph. Each one has its own callers and calls, and a template's @click="handleLogin" links to the method it runs. On vue-element-admin that's over 800 new links, where a component's calls used to belong to the whole file.
  • React Native events whose name is held in a constant now link native code to the JavaScript that listens for them, like NetInfo's addListener(PrivateTypes.DEVICE_CONNECTIVITY_EVENT, …) or a Java .emit(PROGRESS_EVENT, …). The constant is read the way the language scopes it, from the same file, an import or its owning class, so a parameter that happens to share a constant's name is never mistaken for it.
  • React Native views declared with requireNativeComponent('X'), the older Paper style that react-native-maps and segmented-control use, now link from JavaScript to their native iOS and Android implementations, as Codegen specs already did, including in plain .js files. A JSX tag written under a different name than its component, like <Autocomplete> for import Autocomplete from './autocomplete.vue', now links to the component it renders.
  • Expo Router API routes (app/hello+api.ts) are now endpoints, one per exported method, like GET /hello, bound to the function that handles them. They used to show up as a screen named /hello+api. In a repository whose root declares Expo Router for an example app, a Next.js app in its own folder, like react-native-true-sheet's docs/, no longer gets Expo screens made from its files.
  • Calls into an Expo module now reach the module's native functions even when the JavaScript names the module something else, like expo-camera's CameraManager for requireNativeModule('ExpoCamera'). Both the iOS and the Android implementations are linked. expo-camera's calls used to link back to the same-named method making the call, so a method looked like it called itself.
  • Angular apps split across Nx libraries, like angular-spotify, now have their routes and navigation. A lazily loaded route written async () => (await import('@app/home')).HomeModule is followed through the library's index.ts to the module it re-exports, and a routerLink in one library now reaches a screen declared in another. Route paths built from a class constant (RouterUtil.Configuration.Lyrics, `issue/:${ProjectConst.IssueId}`) or an enum are now read. A redirect in a routes file that only lazy-loads others now counts, and router.navigate(['project', 'issue', id]) without relativeTo is read from the root, as Angular does. Re-index Angular projects after upgrading.
  • React Router apps now show navigation written as React Router v5's <Redirect to="/login" /> and through a styled link, like react-boilerplate's HeaderLink = styled(Link) used as <HeaderLink to="/features">. Apps built this way had routes but no links between their screens.
  • SvelteKit routes are now named by the address a browser asks for. A (group) folder like (app) or (marketing) is no longer part of a route's path, and a parameter with a matcher, like [id=integer], is just :id. So goto('/blocks') and <a href="/blocks"> now reach a page that lives in src/routes/(app)/blocks/, where before they reached nothing and the app's screens showed no navigation. Re-index SvelteKit projects after upgrading.
  • Vue Router apps built like vue-element-admin, vue-admin-template or vben now have their routes and screens. Routes declared in a named table (export const constantRoutes = [...], const routes: RouteRecordRaw[] = [...]), in per-module route files, or through new Router(...) are now read. Child routes are joined onto their parent's path, and the parent's component is the layout around them. A lazily loaded view (() => import('@/views/dashboard/index')) is bound to the file it names, and this.$router.push(...) counts as navigation. Nuxt's file-based routes now come only from a Nuxt app, so a plain Vue app's pages/ folder no longer turns into made-up screens, and a Nuxt app at the root of its repository now gets its routes. Re-index Vue projects after upgrading.
  • NestJS routes are now named by the path a request takes: the global prefix from app.setGlobalPrefix('api') is applied, along with its exclude list, and so is URI versioning from app.enableVersioning(...), with @Version, VERSION_NEUTRAL and a controller's own version taken into account. A route that used to appear as GET /user is now GET /api/v1/user, so a front end's this.http.get('/api/v1/user') or fetch call connects to the controller method that serves it. Re-index NestJS projects after upgrading.
  • Laravel routes are now named by the path a request takes: a leading / is added where the routes file leaves it out, Route::prefix() and Route::group(['prefix' => …]) groups are applied, and routes in routes/api.php carry the /api prefix Laravel serves them under, read from your RouteServiceProvider, bootstrap/app.php or any file that mounts a routes file. A front-end fetch('/api/…') now connects to the Laravel route that serves it. Re-index Laravel projects after upgrading.
  • Controllers that Spring or Laravel tests exercise by URL now count as tested. That covers MockMvc's perform(post("/owners/new")), WebTestClient, TestRestTemplate, RestAssured, Laravel's $this->postJson('api/me'), Pest's get('/about'), and a project's own request helpers built on them. codegraph_explore now names the test suite that reaches such an endpoint, where before every one of them looked untested. Re-index Spring and Laravel projects after upgrading.
  • In an Angular app, a method a template calls, like (click)="toggleFavorite()" or (ngSubmit)="submitForm()", is now linked from its component. These methods used to show no callers at all, so impact and callers questions stopped at them, and dead-code checks could list them as unused. Re-index Angular projects after upgrading.
  • Angular apps now have routes and navigation in the graph. Each screen in a Routes array is a route named by its full path, including children, lazily loaded loadChildren files and NgModules, paths written as route constants or $localize strings, and redirects. Each route is linked to its component. router.navigate([...]), navigateByUrl, a guard's createUrlTree and every routerLink in a component's template link to the screen they open, and a template's child components (<app-article-list>) are linked to the component that renders them. Questions like "where does this button go" and "what renders this component" now have answers in codegraph_explore. Re-index Angular projects after upgrading.
  • Delphi and Free Pascal include files (.inc) are now indexed as Pascal. Before, they were read as PHP and came up empty. A .inc file with a <?php tag is still PHP, and a codegraph.json mapping for .inc still wins. Thanks @ijbranch for the report. (#2279)
  • In tag-based CFML, calls written in tags are now linked: in <cfset>, <cfif>/<cfelseif>, <cfreturn>, <cfloop condition> and #…# expressions. Before, only <cfscript> and <cfquery> code was read, so callers and impact found almost nothing in tag-based components. Functions wrapped in tags like <cfprocessingdirective> or <cfsilent> are now indexed too, and a <cfinterface> is indexed as an interface that implements links to. Re-index CFML projects after upgrading. Thanks @HarryMuc for the report. (#2091)
  • Java enum constants and Kotlin enum entries with a body of their own now have their methods in the graph. Examples are PLUS { int apply(…) { … } } and NewBuffer { override fun pipe() … }. Before, those methods were missing and every call inside them was dropped. jsoup's HTML tokenizer and tree builder are written this way, so over 2,000 of their calls were invisible. Re-index to pick this up.
  • Kotlin infix calls, like Users.id eq id1 or koin's single { … } bind MyApi::class, are now recorded as calls to the infix function. Before, they had no callers at all. On Exposed, eq now shows over a thousand callers. Bit operations on numbers (x and 0xff, h shr 8) are left to Kotlin's own operators, even where the project defines a same-named extension. Re-index after upgrading.

Fixes

Windows

  • On Windows, terminal windows no longer flash open and closed while CodeGraph runs in the background. Since 1.6.1, a background MCP server popped up a console window (a full Windows Terminal window when that is the default terminal) several times when it started and again every time it re-synced a changed file. All of CodeGraph's git calls now run hidden. Thanks @Suharaz, @23q3, @A-Van-Gestel, @HarryMuc and @MzaGuille. (#2094, #2096, #2312)
  • On Windows, a project opened with a different drive-letter or folder-name case, like d:\work\app and D:\Work\App, now joins the CodeGraph background server that is already running for it. Before, each spelling started a server of its own that exited at once, so the session quietly served the graph by itself with no shared file watching or auto-sync, and codegraph list showed the project twice. Thanks @greatjackzhou. (#2278)
  • On Windows, codegraph upgrade no longer breaks the install while an agent session is using CodeGraph. It used to stop partway and leave CodeGraph unable to start; it now swaps the new files in with CodeGraph running and puts the previous version back if anything fails, and re-running the PowerShell installer works the same way. If an earlier upgrade already broke your install, re-run irm https://raw.githubusercontent.com/colbymchenry/codegraph/main/install.ps1 | iex to repair it. Thanks @tippmar-nr for the report. (#2185)
  • On Windows, CodeGraph no longer sometimes crashes with exit code 3221225477 (an access violation) on a busy machine: right after parsing in codegraph init, codegraph index and background syncs, or as the background server shuts down. Stopping one of its helper threads (the ones that parse files, resolve references, write the index and count changes for codegraph_status) while it was still starting up, or before it had finished cleaning up its memory, took the whole process down. Threads now finish starting and clean up before they exit.

The background server, sessions and the CLI

  • The Claude Code prompt hook no longer runs on the messages Claude Code uses to hand a subagent's report back to the main session. Before, such a long report could keep the hook busy past Claude Code's 30-second hook timeout and inject context unrelated to what you asked. Thanks @danusha2345, and @tippmar-nr for the report. (#2184)
  • Newer MCP clients such as Antigravity 2.5 connect again: the server now answers their server/discover probe right away with "method not found", so they go straight on to the regular handshake instead of waiting on a reply that could take seconds or never come. Thanks @danusha2345, and @samem26 for the report. (#2084)
  • A CodeGraph session that queried another project through projectPath no longer keeps that project locked for as long as it runs: after 10 minutes without a query it lets the project go, so the project's own session and codegraph index can take over again (tune with CODEGRAPH_PROJECT_IDLE_TIMEOUT_MS, 0 keeps it open). Thanks @danusha2345, and @bompus for the report. (#2087)
  • Claude Code now shows the model the full text of codegraph_status and of explore's stale-index refusal. Both results also carried structuredContent, and Claude Code shows a result's structuredContent in place of its text, so the model saw only a freshness JSON object: no refusal message, no retry guidance and no status report. Both results are now text only. Thanks @bompus. (#2088)
  • When an agent asks CodeGraph about a separate git repository nested inside an indexed project, one the project's index leaves out (for example because the parent's .gitignore excludes it), it now gets the usual "isn't indexed" guidance instead of answers from the parent project's code. Nested repositories the parent does index, such as submodules, work as before. Thanks @wstczyw for the report. (#2110)
  • An agent session that lost its connection to CodeGraph's shared background server, or couldn't reach it at startup, no longer stops that server from running for the rest of the session. It reconnects on its own once the server can start, so other sessions on the same project get auto-sync back instead of running read-only. Thanks @ijbranch for the report. (#2277)
  • codegraph index no longer gives up with "Could not verify that the active CodeGraph daemon has stopped" while the background server is still finishing its shutdown, and codegraph daemon no longer reports such a server as one it could not stop; both now wait for it to exit, for up to about 20 seconds. An agent session that is serving CodeGraph by itself, because the background server was unavailable, now also waits for that work to stop before it exits instead of exiting partway through, which could crash on Windows. Thanks @bompus. (#2311)
  • Anonymous usage telemetry now sends one daily count per tool or command, as documented, instead of one per codegraph process. Before, every MCP server launch, CLI command and prompt hook queued its own entry, so a busy machine uploaded thousands of copies of the same count each day. If you have telemetry turned off, nothing changes.

Indexing and sync

  • A COBOL file whose last line ends inside the sequence area (columns 1-6), such as a closing period indented only four spaces, no longer stalls indexing for over a minute and then ends up in the index with no symbols.
  • Editing a file that defines the same name more than once, like two classes that each have an execute method or a method's overloads, no longer moves every caller from other files onto one of them during codegraph sync. A sync interrupted partway through a file also no longer loses those callers until a full re-index. Thanks @ijbranch for the report. (#2276)
  • Indexing a large C or C++ project no longer runs out of memory partway through "Resolving refs". Headers whose include guard is written as #define X_H 1, as in OpenSceneGraph and osgEarth, or that are included under a build flag codegraph cannot know, used to be re-read on every include path, which grows exponentially with the depth of the include tree. Each is now read once per include state, and a hard limit stops the check on any include tree that is still too large. Thanks @danusha2345, and @coolhitmanleon for the report. (#2127)
  • On a busy machine, indexing or syncing a small project no longer starts extra background threads for resolving references that it can't use. Under heavy load the slower pace made a ten-file project look big enough to need them, which added seconds to the run and held extra memory.

Across languages

  • A type that extends another type of the same name now links to that other type instead of to itself. When the source spells out the qualifier, that qualifier picks between same-named candidates. Before, cats' trait BigDecimalInstances extends cats.kernel.instances.BigDecimalInstances and every trait AllOps … with Functor.AllOps[…] pointed back at the declaring trait, and Newtonsoft.Json's JsonConverter<T> : JsonConverter extended itself.
  • Framework name conventions for Django, FastAPI, Flask, ASP.NET, Gin, SwiftUI and Vapor now only pick a class the reference can see. Examples of these conventions are "a …View is a view", "a …Service is a service" and "a capitalized name is a model". The pick starts from the reference's own file and then its package, and never takes a class declared inside some function or nested in another file's class. Before, Django REST framework's tests linked each file's own MockView and Serializer to another file's, and netbox's tests linked TestForm() to a form declared inside a different test function.
  • A method that calls a same-named method on another expression's result is no longer linked to itself in any language. Examples are Scala's requestToArmeria(request).execute() inside execute(), Rust's self.0.into_route(state) inside into_route(), and Kotlin's this@Buffer.write(…) from an inner object. A value whose initializer chain calls a same-named method, like sttp's val response = basicRequest.get(…).response(…), no longer links to itself either.
  • A method that hands its call on to another object is no longer linked to itself. In TypeScript and JavaScript, a call through this.<field> or window.<x> counts as recursion only when the field is declared as the method's own class. A guess from a receiver's name alone never lands on the calling method. Before, BookStack's toggle() doing this.container.classList.toggle('open'), listen() doing window.$events.listen(…), and FileStorage::delete doing $storage->delete($path) each pointed at themselves.
  • A function or name passed as a value now resolves to what is in scope where it's written. A function nested inside another function is only reachable from inside it. In Python, a parameter or local of the same name is that local. A pytest fixture is a test's parameter only in its own module or under its conftest.py. Before, httpx's self._build_auth(auth) linked to an auth a test defines inside another function, and auth_flow(self, request) handing request on linked to the package's request() function.
  • In Java, C#, Kotlin, Swift, Scala, Dart and VB.NET, a call now reaches the overload whose parameters fit its arguments, not whichever same-named overload was indexed first. For example, HashCodeBuilder.reflectionHashCode(this) now reaches the one-argument overload with varargs, not a three-parameter one. Each overload's callers are now its own.
  • A method that calls another overload of itself now links to that overload rather than to itself. An example is toInstant(instant) returning toInstant(instant, Instant.EPOCH). The fuller overload now lists its convenience overloads among its callers, so its impact includes them. This applies to Java, C#, Kotlin, Swift, C++, Scala, Dart and VB.NET. Real recursion is unchanged.
  • Production code no longer links to a same-named symbol inside a test suite, since tests aren't built into the program. Before, typeorm's Record<string, …> types reached a test entity called Record, and okhttp's sample @Override annotations reached a test's nested Override class. Test-support code a project ships, such as a testing/ folder or a *-test module, stays in reach.
  • A method call on a variable is no longer guessed to be a test double's method just because the double has the only method of that name. That covered classes named Mocked…, Fake…, Stub… or Dummy…: django-allauth's resp.json() calls had all gone to its MockedResponse. A test that names the double still calls it.
  • A call through a class name, like THorse.Get(…), MyView.as_view() or ColorChoices.values(), now reaches the class method that class inherits. The inheritance is read from the class declarations themselves, in Pascal, Python, Ruby, PHP, TypeScript/JavaScript and the Java family. Before, such a call was resolved by guessing from the name. On Horse, THorse.Get('/ping', …) used to land on a route-group interface's Get 120 times. Re-index after upgrading.
  • A method guessed from a receiver's name no longer lands on a request handler the web framework dispatches to, such as a Django or DRF view's post / get or a controller's update / destroy. It also no longer lands on a test double the calling file never mentions. On django-allauth, tests' client.post(…) used to land on a ClientRegistrationView 425 times. On mealie, response.json() used to land on a test's _FakeHTTPResponse 424 times. In Python, site = Site.objects.create(…) now makes site a Site, so site.save() reaches the model's own save. Re-index after upgrading.
  • In C#, Java and Kotlin, a call through a field, property or parameter now lands on the method of the type it is declared with. That includes a type inherited from a base class with its type argument filled in, a generic or for-each declaration, a C# using alias, and a type parameter's bound. A call no longer falls back to a guess at some project class's same-named method, and a type from outside the project gives no link. On Newtonsoft.Json, _innerWriter.WriteValue(…) inside a writer wrapper used to land on the wrapper's own WriteValue, and a TextWriter's Write(…) on a test writer's. On commons-lang, a DateFormat field's parse(…) used to land on the project's DateParser 284 times.
  • A call on a variable declared with a type from outside the project (List<String> list, var sb = new StringBuilder(), signer = TimestampSigner()) no longer lands on a project type's method with the same name. On gson, list.add(…) used to land on a project list wrapper; on commons-lang, s.length() and buffer.append(…) on project classes. In Python, a keyword argument inside a call (prefix=IPNetwork(…)) is no longer taken for an assignment to that name.
  • A call on a type from outside the project, like Integer.valueOf(…), Arrays.asList(…), Object.assign(…) or Delphi's Exception.Create(…), no longer lands on the project's own method with that name. On commons-lang, Integer.valueOf used to land on StringUtils.valueOf over 800 times. Go's exported variables and Pascal's capitalized parameters and locals are not mistaken for type names.
  • In PHP, CFML, Pascal, COBOL and VB.NET, a call written in a different case than its definition now resolves, like formatprice() for FormatPrice or CFML's ToMatchWithCase() for toMatchWithCase. These languages ignore case in names, but such calls used to be dropped before resolution.
  • In Java, Kotlin, Swift, C#, C and C++, Go, Scala, Ruby, Dart and the other case-sensitive languages, a name no longer links to a symbol whose name differs only in case. On jsoup, JUnit's @Test had linked every test to a test method; new CookieManager() had linked to a cookieManager() getter, and a Method type to a method(). PHP, Pascal, CFML, COBOL and VB.NET, whose names really do ignore case, are unchanged.
  • A super call in an overriding method, like super.viewDidLoad(), [super init], base.Handle(), parent::setUp() or super().dispatch(…), no longer makes the method look like it calls itself. The call goes to the parent's version, so an override stops showing up as recursive and no longer lists itself among its own callers.
  • A generic type parameter, like A in def zipWith[A, B](…), T in <T> T max(…) or class Foo<T>, no longer links to a project symbol that happens to share its name. On cats, one implicit def A had thousands of made-up dependents from every A in the library. The same goes for Rust, Dart, TypeScript, Java, Kotlin, Swift, Go, C# and C++. A class or other type declared inside a function is only linked from inside that function. In Scala, a def's own parameter, like f in (f: A => B), no longer links to a same-named field elsewhere. A bare name no longer reaches a type nested inside another type unless the code is inside that type, extends it or imports its members; the type in scope is linked instead, like cats' own FlatMap in place of Eval's nested FlatMap. Re-index projects in these languages after upgrading.

JavaScript and TypeScript, with Vue, Svelte, Astro, React, Express, NestJS and Hono

  • In Vue, Svelte and Astro files, a component now owns its script, and what a <script setup>, a Svelte instance script or Astro frontmatter does at its top level is the component's doing. That covers a Nuxt page's useAsyncData(…), a Svelte page's onMount(…) and Astro's await getCollection(…). Imports and a module-level script stay with the file. Before, those calls belonged to the file, so callers and flows from a component found nothing. The component was also recorded as containing its own file, and a file with no script had no file node at all.
  • In JavaScript and TypeScript, a CommonJS require('./application') now counts as an import of that file, the way an ESM import does. A module path also resolves the way Node and bundlers find it: extensions, index files and path aliases. Before, a CommonJS file depended on nothing at file level, so Express's own lib/express.js showed no imports and impact analysis missed the files it loads. An extensionless side-effect import like import './polyfills' also stopped at its own import statement instead of reaching the file.

The handler is the route's last argument, so an inline middleware before a named handler no longer stands in for it, and a wrapper like asyncHandler(async function (req, res) {…}) and a trailing comma both work. Before, a route such as POST /login linked to nothing.
  • In NestJS projects, the provider naming convention (…Service, …Controller, …) now picks a class only from the reference's own file. Another file's provider is reached through its import, or by ordinary name matching that prefers the nearest declaration. Before, the convention's preference for *.service.ts files sent Nest's own specs' TransientService and TestService to same-named classes in unrelated sample apps.
  • In Astro projects, the component-name convention now applies only inside .astro files, where components are used. Before, a TypeScript type with a component's name was linked to that component: astrowind's image?: Image and callToAction?: CallToAction in its type declarations, and starlight's Playwright page: Page in its tests.
  • In JavaScript and TypeScript, the Express conventions for middleware (validate…, auth, logger, …), controllers and services now pick only the calling file's own declaration. Another file's is reached only through an import or require. Before, SvelteKit's remote functions linked validate(arg) to its config loader's validate in another package, and Express's examples linked logger('dev') to one example's logger.
  • In JavaScript and TypeScript, the React conventions for hooks (use…) and contexts (…Context, …Provider) now pick only from the reference's own file. Another file's hook or context is reached only through an import. An optional call like onSuccess?.(…) now gets the same scope rules as a plain call. Before, trpc's WebSocket adapter's createContext?.(…) option linked to an example app's createContext, zod's schemas.ParseContext linked to the v3 copy instead of v4's, and bulletproof-react's apps linked useUser() to one another's.
  • What a Svelte component's instance <script> or a Vue component's <script setup> declares is now private to that component. Only a Svelte <script module>, a plain Vue <script>, or a type a <script setup> exports can be reached from another file. Before, shadcn-svelte's <Item.Root> linked to a type Item that one example component declares for itself, and halo's isActive imported from its editor core linked to a tab component's local value.
  • In JavaScript and TypeScript, a name the calling function binds itself, as a parameter or a plain var/let/const above the reference, now means that local instead of a same-named function elsewhere in the file. Before, every lodash helper's object parameter linked to a function object() {} declared inside runInContext, and zod's new Class(…) linked to an unrelated Class when Class was the function's parameter. Destructured hook results like const { t } = useI18n() still link to the function they come from.

  • In a project with a Vue front end, the backend's calls no longer land on Vue components. mealie's Python QueryFilterBuilder(…) had been linking to the QueryFilterBuilder.vue component. The Vue rules (compiler macros, Nuxt auto-imports, components by name) now apply only to the app's scripts.
  • Calls in your own JavaScript no longer link to a same-named function inside a vendored minified script, like a *.min.js or a bundle made of a few enormous lines. Those names are mangled. In healthchecks, every jQuery $(…) call had gone to a one-letter helper inside bootstrap-native.min.js.
  • Calls inside an inline route handler now keep their receivers, so they resolve like any other method call. Before, Hono's app.get('/', (c) => c.text('Hello')) linked the route to the one other text method in the project, its client's ClientResponse.text; that happened in over 400 routes. A call like userService.lookup(id) reaches the service it names.
  • A barrel's export * as core from './core' now exports only core, not everything in ./core. In zod, z.string() and z.number() had been landing on same-named regex constants deep in its core module instead of the schema functions. Calls through import * as ns also find members a barrel forwards by name (export { safeParse } from '../core'). They follow a namespace path like z.coerce.number() too.

On express, over 700 express() calls now reach createApplication.

  • In JavaScript, TypeScript and Vue, a call through a name destructured from a composable or custom hook, like const { getDefaultActivityRoute } = useDefaultActivity() or const { t } = useI18n(), now reaches the function the hook returns. These calls used to resolve to nothing. mealie, elk, halo and excalidraw each gained dozens to over a hundred such links.

Every form of export still counts: the export keyword, export { … } lists, export default, and a default-exported object. On typeorm, test fixtures' local ColumnMetadata used to capture import { ColumnMetadata } from "typeorm"; on sveltekit, an unexported resolve collected other files' resolve(…) calls; on zod, a local z collected the zod package imports.

  • TypeScript's import type { X } no longer reads as an import of something named type, and import { a, type B } binds B, not type B. So a type-only import now links to the module it names, where it used to link to whatever project symbol had that name. A t('…') from useI18n() or a ref(…) from vue used to link to an interface property or a local variable of the same name elsewhere in the project, so on halo two unrelated symbols had over a thousand made-up callers each. A call imported from a package is also no longer mistaken for a project symbol when the package is declared in a nested app's package.json or a Deno import map. An import through an alias CodeGraph can't follow, like SvelteKit's $lib/… or a nested Nuxt app's ~/…, is still treated as project code. Re-index Vue, Svelte, Astro and JavaScript/TypeScript projects after upgrading.

  • JavaScript and TypeScript calls are no longer linked to a class member that merely shares their name. A call on a namespace import, like zod's z.string() (import * as z from 'zod'), or on something imported from an npm package, used to link to whichever class in the project had a string member, and a bare call like mocha's it(…) or describe(…) to an interface's it property or a class's describe field. On zod one test helper's getter had thousands of made-up callers and topped the most-depended-on list. A React hook or component imported from a package, like useQuery from @tanstack/react-query, no longer links to a same-named one in the project, and a hook nested inside another function is no longer a target at all. Re-index JavaScript and TypeScript projects after upgrading.

A call later in a chain to a Kotlin standard-library function (apply, let, toString, map, contains…) no longer lands on a project type's same-named method. On okhttp, .apply { … } used to land on ConnectionSpec.apply. Re-index after upgrading.
  • In Scala, a call reached by its name alone now stays in reach. A name that the enclosing function binds as a parameter or local (f(true) for f: A => B) is that local. A call later in a chain, like fa.iterator.map(…), reaches only a member of what its receiver is named after. A plain call reaches only the enclosing class and its supertypes (an anonymous subclass's base included), a companion, or an imported object. On cats, parameter calls like f(a) used to land on a case class's field f over 400 times, and chained .map(…) on one ops class's map.
  • In Kotlin, a call to a top-level or extension function now resolves only to one the file can see: one in its own package, one it imports by name, or one from a package it imports with *. On Exposed, tests that imported kotlin.test's or JUnit's assertEquals, or the JDBC suite's helper, used to land on the R2DBC suite's helper over 3,000 times. On okhttp, tests that import mockwebserver3.MockResponse used to construct the deprecated class of the same name. A function type with a qualified receiver, like (DatabaseConfig.Builder.() -> Unit)?, no longer breaks the parse of the class around it. Re-index after upgrading.
  • A bare Java call like verify(mock), assertThat(x) or hashCode() now links only to a method of the class it's in, of that class's parents, or one the file imports statically. It used to link to any class's method of that name: in halo, Mockito's verify and eq gave one service's verify over a thousand made-up callers, and in retrofit Truth's assertThat did the same to a test helper. Calls to inherited methods and static imports from the project now link to the right one, like jsoup's attr(…) through LeafNode or halo's and(…) / equal(…) through import static …Queries.*. Re-index Java projects after upgrading.

C# and VB.NET

  • C# names now follow the language's scopes. A block namespace X { … } qualifies only the types inside it, so a type declared after the block, or in a file's second namespace, is no longer filed under the first. A namespace written inside another is Outer.Inner. A using links to the project's namespace instead of another file's using of the same name. A global using applies only within its own project. A nested type is reachable by bare name only from inside its owner or a type deriving from it, including through another partial part. Before, serilog's Guard was filed under JetBrains.Annotations, its tests' Some.InformationEvent() went to the performance tests' Some, and AutoMapper's same-file new Source() could reach another test class's nested Source.
  • C# type names now follow namespaces. A type is in reach from its own namespace or one nested inside it, or through a using of its namespace. Also counted: a project-wide global using, the project's <Using> entries, the SDK's implicit usings, or an alias that names it. Before, Newtonsoft's async Task tests linked Task to a test class of that name in another namespace, and AutoMapper's DTOs linked to another namespace's BaseEntity.
  • C# members of an interface are now public and types declared without a modifier are now internal, as the language defines. A call on an interface-typed field now reaches the interface's method, where it used to find nothing. A guess from a receiver's name now weighs only the owner type's own name, not its namespace. Standard .NET names like ToString, Add and Write need a receiver named after the owner. In every language, a guess from production code no longer lands on a mock or helper defined in a test suite. Re-index after upgrading.
  • In C#, a bare name like TestContext, Easing or Helper() now resolves only to a member of the class it's written in, its outer classes, their base classes, or a type brought in with using static. That includes a global using static and a project file's <Using … Static="true"/>. On eShop, test classes' TestContext used to land on one other test class's property; on Newtonsoft.Json, TypeNameHandling.All now reaches the enum rather than a same-named property.
  • In VB.NET, a call through a receiver like Me.Panel.Controls.Add(…) or New System.Drawing.Size(…) no longer lands on an unrelated class's member with the same name. It now resolves only through Me, MyBase or MyClass, through the member's own class or module (Logger.Log(…)), or through a service lookup's type (GetService(Of Notifier).Notify()). On SCrawler, the Windows Forms designer code used to link over 700 Size calls to a nested enum's case and over 500 Controls.Add calls to a collection class.
  • In C# and VB.NET, a type written in code, like Type sourceType, List<int>, new TypeMap() or Dictionary<string, Type>, now links to the type and no longer to a property, method or field that shares its name. List<…> used to link to some test class's List property, Type to an attribute's Type property, and a parameter of type TypeMap to a TypeMap property instead of the TypeMap class. Those members showed up with hundreds of made-up dependents. Reading a property or passing a method, like Builder.Services or MapGet("/x", GetItems), still links as before. Re-index C# and VB.NET projects after upgrading.

Swift and Objective-C

  • An Objective-C class that conforms to a protocol of its own name now links to that protocol instead of to itself. Swift's naming conventions for views, models and controllers also no longer apply to Objective-C code. Before, every one of SDWebImage's @interface SDDiskCache : NSObject <SDDiskCache>-style classes implemented itself.
  • In Swift, a call to an overloaded method now reaches the overload whose argument labels it spells, with defaulted parameters optional. Before, only the argument count was compared. Alamofire's self.tableView(tableView, numberOfRowsInSection:) inside another tableView overload linked to itself, and cancel(optionallyProducingResumeData:) linked to cancel(producingResumeData:).
  • A Swift call on a property declared with a type, like Kingfisher's var cache: ImageCache! or self.storage.write(…), now reaches that type's method or one it inherits. It no longer lands on a subclass override in a test, or on another type's method of the same name.
  • A Swift call on a value built on the spot, like JSONDecoder().decode(…) or Realm().create(…), now resolves to that type's method, or to one it inherits. It no longer lands on some other type's method of the same name: Vapor's JSONDecoder().decode calls had gone to a request's private container.
  • In Objective-C, [super init] and other messages to super now reach the superclass's method, never the sending class's own override. This also works where the index lost the @implementation's range. On SDWebImage, NSObject subclasses' [super init] used to land on SDDiskCache's init, and [self class] in tests on a proxy class's class. On AFNetworking, a serializer's [super encodeWithCoder:] now reaches its superclass. Re-index after upgrading.
  • In Swift, a call written with no receiver, or through self. or super., now reaches only a member of the type around it or of what that type inherits or conforms to, and the nearest override wins. A standard-library name later in a chain (axis.entries.removeAll(), names.contains(x)) no longer lands on a project type's method, unless the receiver or the call's argument label points to it. On Charts, min(a, b) and max(a, b) used to land on a range type's min field and a Sequence extension, and super.init(…) on an Objective-C demo's init over 170 times. A global in a playground or a test target is no longer linked from the main code. Re-index after upgrading.
  • In Objective-C, a message now reaches a method only when it could really be sent there. A message to self or super reaches only the sender's class and its superclasses, including categories on UIKit and AppKit views. A C-style call like completionBlock() is never taken for a method or property. A message to a local variable uses the variable's declared type (FMResultSet *rs). On SDWebImage, [self class], respondsToSelector: and isKindOfClass: used to land on a proxy class's overrides over 150 times, and on fmdb [rs close] now reaches the result set.
  • A Swift call through a nested type, like API.PackageController.GetRoute.query(on: db), now links to that type's method. Only query used to be kept, so the call linked to whichever type's query came first; in a Vapor app every route type has one, so callers, impact and codegraph_explore answers pointed at another endpoint's code. The same applies to nested types' initializers (API.PackageController.Model(name:)), to enum cases (Gitlab.Error.requestFailed(status:)), to types declared in an extension API.PackageController { … }, and to The Composable Architecture's Path.State.detail(…). A call on a type path that names no type in the project, such as an SDK's Plot.Node.footer(…), is left unlinked. Re-index Swift projects after upgrading.
  • A SwiftUI view, a @main app, a view controller and a UIView subclass are now indexed once. Each used to get a second, one-line copy with no callers or calls, which showed up next to the real type in search and codegraph_explore answers as a dead end. Re-index Swift projects after upgrading.
  • A Swift class or struct that declares a protocol composition across lines, like typealias Client = AutocompleteService.Client followed by & PostingService.Client on the next line, is now indexed whole. That line used to break the parse of the entire enclosing type, so its methods, initializer and properties went missing, and calls into them landed on same-named methods elsewhere. Re-index Swift projects after upgrading.
  • A Swift reference to a type now links to the type's own declaration, not to a file that extends it. An extension View { … } or extension Text { … } used to stand in for SwiftUI's type, so every view, every Text("…") and every Color.red in an app linked to whichever file happened to extend it. Those files topped the most-depended-on lists and their impact reached the whole app. A bare name like @State, @Test or Result<…> no longer links to some other type's nested State or Result, and a qualified name like Build.Id links to the Id it names. Methods declared in an extension of an SDK type still resolve on the types that conform to it, and a protocol's methods declared in any of its extensions now connect to each conforming type's own implementation. Re-index Swift projects after upgrading.
  • A Vapor route now links to the handler it names. use: SearchController.show used to link to whichever controller's show came first, so routes with a common handler name, like show, index or get, pointed at another endpoint's code in callers, impact and codegraph_explore answers. Nested types like API.PackageController.get and handlers declared in an extension of the controller now resolve too, and use: self.index resolves to the collection's own index. Re-index Vapor projects after upgrading.

C, C++, Go and Rust

  • A call in C code is no longer linked to a C++ class's method, since C has no methods and can't call one. Before, redis's POSIX read(fd, buf, n) calls and hiredis's c->funcs->read(…) function pointer pointed at a Qt adapter's read method.
  • In Go, a name written through an imported package from outside the module, like context.Context, http.ResponseWriter or testify's require.Contains, is no longer linked to a project symbol of that name. Before, fiber's context.Context parameters pointed at a method Stream.Context, its require.Contains(…) assertions at an extractor's Contains, and gin's http.ResponseWriter at its own ResponseWriter interface.
  • In Rust, Self::Error in a signature now resolves to the enclosing impl's or trait's own associated type. A path through a generic parameter, like V::Value, no longer resolves to an unrelated struct of that name. Before, serde's Self::Error signatures pointed at its one struct Error, and axum's Self::Error at axum-core's error type.
  • In Rust projects, a struct, handler or service name no longer resolves to an item declared inside some function body, and a file's own item comes before any other crate's. Before, axum's examples' Uri linked to a struct Uri declared inside a routing test, tokio's runtime Handle linked to tokio-test's, and ripgrep's Glob { … } in globset linked to the CLI flags' Glob.
  • Rust type and function names now follow Rust's scoping. A name from another file counts only when a use brings it in (or a * glob over its module). One imported from outside the project, like use std::task::{Context, Poll} or use futures::Stream, means that outside item. A path names its module: io::Result isn't an unrelated Result alias elsewhere, and std::io::Error is std's. On tokio, over 1,200 io::Result and 600 Context references had been landing on private project types.
  • A C++ call into a macro-opened namespace, like fmt::format("{}", x), now picks the overload its arguments fit. Before, the first overload indexed won: fmt's 1,400 fmt::format calls all reached the text_style overload in color.h. A narrow string literal now fits a narrow format string, a wide L"…" fits the wide overload, and the argument count has to fit too.
  • C++ classes written around macros and preprocessor conditionals now keep their members. These include an access specifier spelled as a macro (JSON_PRIVATE_UNLESS_TESTED:), an attribute macro after a template head or a doc comment, and an #if in the middle of a declaration, such as inside a constructor's initializer list. The first branch of a mid-declaration #if is the one indexed. nlohmann/json's basic_json class used to be lost whole and now has its roughly 390 members. Files with a parse error dropped on redis, curl, pybind11 and leveldb, and no file got worse. Re-index after upgrading.
  • Calls on a library's own types and modules no longer land on a project method that happens to share the name. In Rust, Vec::new(), String::from(…) and module paths like task::spawn(…) stay the standard library's. A later link of a multi-line Rust or Go chain now counts as a chained call, named after the chain's first line. In Go, w.Header().Get(…) is net/http's. In R, a plain call like range(x) is a function, not an object's method. In JavaScript, response.text() / .json() is fetch's. On tokio, task::spawn(…) used to land on TaskTracker::spawn 300 times. On ggplot2, range(…) used to land on a coordinate system's range method. Re-index after upgrading.
  • In C and C++, a qualified name like fmt::format now reaches a declaration inside a namespace the library opens with a macro, like fmt's FMT_BEGIN_NAMESPACE, pybind11's PYBIND11_NAMESPACE_BEGIN(…) or rapidjson's and spdlog's …_NAMESPACE_BEGIN. It also works through a namespace alias like namespace py = pybind11;. On fmt, 1,728 fmt::format(…) calls used to link to nothing, and so did about 1,400 py::… calls on pybind11.
  • In Rust and Go, a call later in a chain, like sym.filename().map(…) or c.Flags().String(…), no longer lands on the project's own method of that name when the name is a standard-library one (unwrap, clone, map, iter, Go's String or Error). A plain call like get(handler) or drop(x) never lands on a method. On tokio, .map(…) on an Option used to land on MutexGuard::map; on axum, the router's get(handler) on a cookie jar's get; on ripgrep, .clone() on an error type.
  • In Rust, a bare Ok(…), Some(…), Err(…), Result<…>, Option<…>, Vec<…> or drop(…) now means the standard library's, unless the file defines or imports a project item of that name. These used to link to any same-named enum variant or struct in the project: every Some(x) in ripgrep to one enum's Some variant, and every Ok and Result in serde to structs its macro-hygiene tests declare. An enum variant is now reached by a bare name only where the file uses it or its enum's *, and a variant never stands for a type. Re-index Rust projects after upgrading.

PHP, Ruby, Dart, Lua, R, Solidity, Erlang and CFML

  • In Laravel apps, a route whose controller is named by string now links to its handler, without needing a Controller suffix and keeping the namespace it's written with: 'Common\Uploads@inline', and Route::resource('companies', 'Common\Companies', [...]) with an options array. Two same-named controllers in different namespaces are told apart by that namespace. Before, akaunting linked 304 of its 313 routes to nothing.
  • In Rails apps, a resources line's only: and except: are now read in every form Rails accepts: %i[new create index], %w(index show), a quoted name, and the older :only => [...]. Before, only a bracketed list was read, so maybe's resources :family_exports, only: %i[new create index] became all seven routes, four of them to actions the controller doesn't have.
  • In PHP, a class written with a namespace in its name now links to that class. After use App\Fields as Field;, new Field\FirstName(), extends Field\Base and Field\FirstName::make() all name App\Fields\FirstName, as do Fields\FirstName written inside namespace App; and a fully qualified \App\Fields\FirstName. Before, none of these had a link, so callers and impact missed every class reached that way. Thanks @drakeo338. (#2256)
  • In Solidity, a call to an overloaded function now reaches the overload whose parameter count it fits, as in the other languages with overloading. Before, OpenZeppelin's _checkRole(role, _msgSender()) inside the one-argument _checkRole(bytes32 role) was linked to itself.
  • In R, a call like c(1, 2) is no longer linked to a data variable that happens to share a base function's name, since R skips non-function bindings when it looks up a call. Before, ggplot2's facet tests bound c <- data_frame(b = 3), and every c(…) call in those files pointed at that data frame. Functions built by a factory, like ggplot2's geom_point <- make_constructor(…), still resolve.
  • A Dart extension on X { … } with no name is no longer mistaken for the type X, and its members are reachable only inside the file that declares it, as in Dart. Before, bloc's linter linked analyzer's Token and Dart's Uri to small extension blocks, and every flutter_test find.text(…) call linked to a text getter on another example's TaskStatus.
  • In PHP, an unqualified class name now resolves to the current namespace's class or the one a use imports, as PHP does. If the imported class comes from a library, it resolves to nothing in the project. Before, koel's form requests linked extends Request to whichever Request class was indexed first, and BookStack's controllers linked Request $request (Laravel's, by import) to BookStack's own Request subclass.
  • A Dart call like ext.endsWith(".avi") or map.putIfAbsent(…) on a value whose type isn't known now counts as Dart's own String, List or Map method. It no longer lands on a project method of the same name. A Dart extension is also matched by the type it extends, not by its own name, so getx's ext.endsWith on a String stopped reaching extension RxStringExt on Rx<String>.
  • A bare Lua call like ipairs(t), error("…") or busted's setup() now means Lua's own function unless the file defines one. It no longer lands on a table method of the same name: telescope's ipairs calls had gone to a linked list's ipairs, and kong's error calls to its response module. A function's own alias of a host table member, like local get_query = kong.request.get_query, is now followed as well.
  • Lua calls made through a local alias now reach the function it names. That covers local splitn = require("kong.tools.string").splitn, a module member such as utils.select_listener, and a function a module exports under another name (return { check = check_phase }). Aliases of Lua's own functions, such as local type = type or local fmt = string.format, no longer show up as calls into your project. On Kong that is over 1,000 calls that now reach their real function, and about 5,000 fewer dead-end edges.
  • In Solidity, a call with no receiver now reaches a function of the contract around it or of one it inherits. On OpenZeppelin, _msgSender() in contracts built on Context used to land on ERC2771Context's override 83 times. In Erlang, a call to another module's function now follows the file's -import(Mod, [f/N]). On cowboy, -import(req_SUITE, [do_get/3]) calls used to land on another suite's do_get/3. A bare call with no such import no longer links to some other module. Re-index after upgrading.
  • In Lua and Luau, a call through a standard or host library table (string, table, io, vim, ngx, busted's assert…) or a string method like line:find(…) no longer lands on the one project method with the same name. Functions the project itself defines on those tables still link. On kong, the specs' assert.truthy(…) and assert.falsy(…) used to land on a condition helper over 1,700 times; on telescope, line:find(…) on the picker's find.
  • In PHP, a call through a variable nothing types no longer lands on an unrelated class's method just because it's the only method with that name. The variable now needs to be named after the method's class, or after a class that inherits it ($page->save() where Page extends Entity). On guzzle, the tests' $response->getHeaderLine() used to land on a test double; on symfony/console, $e->getMessage() on a progress bar.
  • In CFML, a call no longer lands on an unrelated component's method just because the name matches. A call with no receiver inside a component now reaches only that component's methods and those of the components it extends, so built-ins like now() stay built-ins. A call on an untyped variable now needs the variable to be named after the component, so server.keyExists(…) is no longer taken for some component's keyExists. On coldbox, now() used to land on a date helper over 200 times, and TestBox's fail(…) in specs now reaches the spec base class.
  • In Ruby, a call no longer lands on an unrelated class's method just because it's the only method with that name. A call on an untyped receiver now needs the receiver to be named after the method's class, like web_push_request.legacy_encrypt. A call with no receiver inside a class now reaches only that class's methods, its superclasses' methods, and those of the modules it includes, extends or prepends. On rubocop, node.loc on a syntax node used to land on the project's one loc method over 1,200 times, and Kernel's format(…) on the language server's format. On mastodon, render in controllers used to land on an inline renderer, and authorize now reaches the authorization concern.
  • In Dart, a call written without a receiver now reaches only a method of the class it's written in, of a class it extends, mixes in or implements, or of an extension on one of those types, and picks the nearest one. On riverpod, package:test's test(…) in the test files used to land on a container class's test method over 1,100 times, shelf's and getx's expect(…) on unrelated classes' expect, and bloc's emit(…) in a Cubit on the wrong base class. Classes declared as class A = B with C; are now indexed under their name, with what they extend and mix in. Re-index after upgrading.
  • In R, a variable assigned at the top of a test file is no longer linked from the package or from other tests, because testthat runs each test file in its own environment. On ggplot2, a test's c <- ggplot(…) used to collect 2,455 of the package's c(…) calls. Variables in helper-*.R and setup-*.R, which testthat loads for every test, are still shared.
  • In Lua and Luau, a local variable or function is no longer linked from other files, since it's only visible in the file that declares it. On kong, a spec helper's local it = it used to collect every other spec file's it(…) (over 4,000 links), and one module's local ipairs = ipairs took the whole project's ipairs(…). Global functions are still linked across files.
  • PHP calls on $this, self, static and parent now reach the method of the class they're written in, a class it extends, or a trait any of them uses, with parent classes and traits found through the file's namespace and use imports. On Drupal core, $this->assertEquals() (PHPUnit's) used to link to an unrelated comparator class 8,832 times, $this->assertSession() to a JavaScript-test base class, and $this->t() to Views::t. They now reach UiHelperTrait and StringTranslationTrait, or nothing when the method lives in a package outside the repository. A call inside a trait, and a base class calling a method its subclass defines, keep their links. Re-index PHP projects after upgrading.
  • A PHP function call written after => in an array, like 'count' => count($items), 'by' => user()->id or 'label' => trans('…'), is now read as a plain function call. It used to be taken for a method call and linked to whichever class had a method of that name. On BookStack, that meant 166 wrong links.
  • A PHP call written without a receiver, such as redirect($url), view('books.show'), auth() or basename($path), is a function call, and no longer links to a same-named method, field or class elsewhere in the project. These wrong links showed up in callers, impact and codegraph_explore answers wherever a Laravel helper or PHP built-in shared its name with a project member. Re-index PHP projects after upgrading.
