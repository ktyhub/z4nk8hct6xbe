codegraphe v1.0.1

[1.0.1] - 2026-06-13

Nouvelles fonctionnalités

  • Nouvelle commande codegraph daemon (alias daemons) — un gestionnaire interactif pour les démons d'arrière-plan. Il montre ce qui est en cours d'exécution (le démon de votre projet actuel en premier, présélectionné), et vous appuyez sur la touche fléchée pour en sélectionner un et appuyez sur Entrée pour l'arrêter, ou choisissez "Arrêter tout". Auparavant, la seule façon d'arrêter un démon était de rechercher son pid et de le kill à la main. (#845)
  • La vérification de votre version installée est désormais facile à atteindre, quelle que soit la manière dont vous la devinez : codegraph version, codegraph -v et codegraph -version l'impriment tous, aux côtés du codegraph --version existant. (#864)
  • Le serveur CodeGraph MCP s'auto-répare désormais si son thread principal se bloque. Un chien de garde léger remarque quand le processus a cessé de répondre et l'arrête afin qu'un nouveau démarre lors de votre prochaine requête - il ne peut plus rester bloqué à 100 % du processeur sans aucun moyen de récupération. Réglez la fenêtre de détection avec CODEGRAPH_WATCHDOG_TIMEOUT_MS ou désactivez-la complètement avec CODEGRAPH_NO_WATCHDOG=1. (#850)

Correctifs

  • Les arbres de travail Git imbriqués dans votre projet — comme le .claude/worktrees/ créé par Claude Code — ne sont plus indexés en tant que copies en double de l'ensemble de votre base de code. CodeGraph indexe délibérément les véritables dépôts intégrés (un véritable deuxième projet extrait du vôtre), mais un arbre de travail n'est qu'une autre vue fonctionnelle d'un dépôt qu'il a déjà indexé, donc chacun multipliait chaque symbole - un rapport est passé d'environ 1 850 fichiers à plus de 24 000, avec la recherche et explore inondés de doublons obsolètes. CodeGraph reconnaît désormais les arbres de travail et les ignore, tout en indexant les véritables dépôts et sous-modules intégrés. Merci @tphakala. (#848)
  • L'exécution manuelle du codegraph serve --mcp ne reste plus suspendue en silence. Cette commande est le serveur MCP que votre agent IA démarre pour lui-même - pas une étape que vous exécutez directement - et dans un terminal, elle restait là à attendre une entrée qui n'arrive jamais, semblant cassée. Il reconnaît désormais quand une personne l'exécute et explique quoi faire à la place (codegraph status, codegraph daemon), et il a été supprimé de la liste des commandes afin qu'il ne ressemble plus à quelque chose que vous devez lancer.
  • Les appels de méthodes statiques inter-fichiers comme ClassName.staticMethod() sont désormais résolus correctement. CodeGraph liait l'appel à la classe au lieu de la méthode (et l'enregistrait en tant que construction), donc callers et impact pour une méthode statique sont revenus vides - un véritable angle mort dans les bases de code TypeScript et JavaScript qui s'appuient sur des classes utilitaires statiques (Python et d'autres langages avec le même avantage de forme d'appel également). L'appel est désormais lié à la méthode elle-même. Merci @contextFlow-lab. (#825)
  • codegraph affected accepte désormais les chemins de fichiers absolus et préfixés par ./, et pas seulement ceux relatifs au projet. Passer ./src/x.ts ou un chemin absolu - courant lorsque la liste de fichiers provient d'un autre outil - était utilisé pour ne rien faire correspondre silencieusement et ne signaler aucun test affecté. Merci @contextFlow-lab. (#825)
  • Le serveur CodeGraph MCP ne risque plus de rester bloqué à 100% CPU après une erreur interne inattendue. Auparavant, une telle erreur était enregistrée, mais le processus restait en cours d'exécution dans un état interrompu, où il pouvait faire tourner un cœur de processeur indéfiniment et devait être tué manuellement. Le serveur enregistre désormais l'erreur et se ferme proprement, donc un nouveau démarre à la requête suivante. Merci @songhlc. (#850)
  • CodeGraph n'indexe plus l'intégralité de votre répertoire personnel par accident. L'exécution du programme d'installation - ou codegraph init / codegraph index - à partir de votre dossier personnel ou de la racine d'un système de fichiers indexerait tout ce qui se trouve en dessous (caches, Library, tous les autres projets), produisant un index de plusieurs gigaoctets et une surveillance constante des fichiers. CodeGraph refuse désormais ces racines et vous oriente plutôt vers un projet spécifique ; passez --force si vous le souhaitez vraiment. (Combiné au correctif du descripteur de fichier macOS déjà dans 1.0.0, cela clôt le rapport d'un observateur incontrôlé épuisant la limite de fichiers système.) Merci @ligson. (#845)

codegraph v1.0.1

[1.0.1] - 2026-06-13

New Features

  • New codegraph daemon command (alias daemons) — an interactive manager for the background daemons. It shows what's running (your current project's daemon first, pre-selected), and you arrow-key to one and press enter to stop it, or pick "Stop all". Previously the only way to shut a daemon down was to hunt for its pid and kill it by hand. (#845)
  • Checking your installed version is now easy to reach however you guess at it: codegraph version, codegraph -v, and codegraph -version all print it, alongside the existing codegraph --version. (#864)
  • The CodeGraph MCP server now self-heals if its main thread ever locks up. A lightweight watchdog notices when the process has stopped responding and stops it so a fresh one starts on your next request — it can no longer sit pinned at 100% CPU with no way to recover. Tune the detection window with CODEGRAPH_WATCHDOG_TIMEOUT_MS, or turn it off entirely with CODEGRAPH_NO_WATCHDOG=1. (#850)

Fixes

  • Git worktrees nested inside your project — like the .claude/worktrees/ that Claude Code creates — are no longer indexed as duplicate copies of your whole codebase. CodeGraph deliberately indexes genuine embedded repos (a real second project checked out inside yours), but a worktree is just another working view of a repo it already indexed, so each one was multiplying every symbol — one report went from ~1,850 files to over 24,000, with search and explore flooded by stale duplicates. CodeGraph now recognizes worktrees and skips them, while still indexing real embedded repos and submodules. Thanks @tphakala. (#848)
  • Running codegraph serve --mcp by hand no longer just hangs in silence. That command is the MCP server your AI agent starts for itself — not a step you run directly — and in a terminal it used to sit there waiting for input that never comes, looking broken. It now recognizes when a person runs it and explains what to do instead (codegraph status, codegraph daemon), and it's been dropped from the command listing so it stops looking like something you need to launch.
  • Cross-file static method calls like ClassName.staticMethod() now resolve correctly. CodeGraph was linking the call to the class instead of the method (and recording it as a construction), so callers and impact for a static method came back empty — a real blind spot in TypeScript and JavaScript codebases that lean on static utility classes (Python and other languages with the same call shape benefit too). The call now links to the method itself. Thanks @contextFlow-lab. (#825)
  • codegraph affected now accepts ./-prefixed and absolute file paths, not just bare project-relative ones. Passing ./src/x.ts or an absolute path — common when the file list comes from another tool — used to silently match nothing and report no affected tests. Thanks @contextFlow-lab. (#825)
  • The CodeGraph MCP server no longer risks getting stuck at 100% CPU after an unexpected internal error. Previously such an error was logged but the process was left running in a broken state, where it could spin a CPU core indefinitely and had to be killed by hand. The server now logs the error and exits cleanly, so a fresh one starts on the next request. Thanks @songhlc. (#850)
  • CodeGraph no longer indexes your entire home directory by accident. Running the installer — or codegraph init / codegraph index — from your home folder or a filesystem root would index everything underneath it (caches, Library, every other project), producing a multi-gigabyte index and constant file-watching churn. CodeGraph now refuses these roots and points you at a specific project instead; pass --force if you genuinely mean to. (Combined with the macOS file-descriptor fix already in 1.0.0, this closes the report of a runaway watcher exhausting the system file limit.) Thanks @ligson. (#845)
