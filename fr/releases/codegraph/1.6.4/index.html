codegraphe v1.6.4

[1.6.4] - 20/11/2026

Faits saillants

  • Les petites questions coûtent moins cher. Demandez à votre agent ce qu'est une fonction ou une constante, ou qui l'appelle, et codegraph_explore répond désormais avec la définition et chaque ligne qui l'utilise, au lieu d'une longue réponse sur les fichiers associés.
  • Réponses plus rapides dans Claude Code. Le hook d'invite demande désormais au serveur CodeGraph déjà en cours d'exécution pour votre projet au lieu de charger à nouveau l'index à chaque invite, ce qui compte le plus dans les grands projets, et codegraph impact est à nouveau aussi rapide qu'il l'était dans 1.6.2.
  • Plus sûr sur un ordinateur partagé. Chaque session d'agent vérifie désormais que le serveur d'arrière-plan auquel il se connecte fonctionne comme vous avant de lui envoyer quoi que ce soit.
  • Plus de votre code dans le graphique. Les routes Elysia (Bun), les inclusions PHP construites à partir de la racine du serveur Web ou du propre dossier du fichier, les constructeurs principaux Dart 3.13 et la nouvelle syntaxe Kotlin sont maintenant lus, et les routes ASP.NET Core sont nommées de la manière dont ASP.NET les sert.
  • Liens plus précis. Des dizaines de correctifs aident les appels à atteindre le code qu'ils signifient, surtout dans JavaScript et TypeScript, Python, Rust, C#, PHP et Java, et codegraph affected ne sélectionne plus les tests de l'autre côté d'un appel HTTP, d'une file d'attente ou d'un événement à moins que vous ne réussissiez --cross-tier.
  • Moins de commandes bloquées. Un git add ou un commit n'échoue plus avec "index.lock : Le fichier existe" pendant la synchronisation de CodeGraph, un fichier dont l'analyse ne se termine jamais n'empêche plus codegraph init ou la synchronisation de se terminer, et un serveur dont le dossier de projet a été supprimé s'arrête maintenant.
  • Mise à niveau : réindexez vos projets avec codegraph index après cette version. Beaucoup de ces correctifs sont écrits lors de l'indexation, et codegraph status et votre agent vous indiquent tous deux quand un index a été créé par une ancienne version.

Sécurité

  • Sur un ordinateur partagé avec d'autres utilisateurs, chaque session d'agent vérifie désormais que le serveur d'arrière-plan CodeGraph auquel il se connecte fonctionne comme vous avant de lui envoyer quoi que ce soit, et sert la session elle-même lorsque le serveur ne peut pas le prouver, de sorte qu'un autre utilisateur ne peut plus remplacer votre serveur pour lire les requêtes de votre agent ou lui fournir des réponses inventées. Merci @aidenpan0x de l'avoir signalé.

Nouvelles fonctionnalités

  • Le hook d'invite Claude Code obtient désormais son contexte du serveur CodeGraph déjà en cours d'exécution pour votre projet au lieu de charger à nouveau l'index à chaque invite, de sorte que les invites structurelles reçoivent une réponse plus tôt, surtout dans les grands projets ; sans serveur en cours d'exécution, occupé ou ne pouvant pas prouver qu'il fonctionne comme vous, le hook le résout tout seul comme avant. Merci @aidenpan0x pour le rapport, les mesures et la pull request. (#3284)
  • Les backends Elysia (Bun) ont désormais leurs routes HTTP dans le graphique, nommées par le chemin complet emprunté par une requête, avec les préfixes new Elysia({ prefix }), .group() et un .use() dans un autre fichier inclus, et liés à leurs gestionnaires, afin que codegraph_explore puisse suivre une requête depuis son itinéraire vers votre code. Merci @ChampPABA pour le rapport. (#3255)
  • Les inclusions PHP construites à partir de la racine du serveur Web, comme require $_SERVER['DOCUMENT_ROOT'] . '/inc/header.php', sont désormais liées à leur fichier : CodeGraph détermine quel dossier le serveur sert à partir duquel vos chemins d'inclusion nomment les fichiers, ne lie rien lorsqu'ils ne le règlent pas plutôt que de deviner, et prend "webRoot": "public" dans codegraph.json (ou "." pour la racine du projet) lorsque vous préférez le nommer vous-même. Merci @artisanya pour le rapport. (#3298)
  • Kotlin est maintenant lu avec une version plus récente de sa grammaire, donc le code était mal lu, comme une classe annotée dont les méthodes apparaissaient comme des fonctions de niveau supérieur, une classe qui délègue à by un autre objet, ou une syntaxe plus récente comme les gardes when et les champs de support explicites, a maintenant ses classes, fonctions et appels dans le graphe auquel ils appartiennent. (#3410)
  • codegraph_explore répond désormais à une question sur un symbole, comme "qui appelle toValidURL ?" ou "qu'est-ce que MAX_RETRIES ?", avec la source de ce symbole et chaque ligne qui l'utilise, chacune avec la fonction dans laquelle elle se trouve et le texte de la ligne, au lieu de remplir toute sa réponse avec des fichiers qui ne partagent que des mots avec le nom, donc ces petites questions coûtent moins cher et ne laissent rien à rechercher par la suite. Merci @GeorgeTaveras1231 pour les mesures. (#3407)

Correctifs

Configuration, le serveur d'arrière-plan et le CLI

  • codegraph affected ne sélectionne plus les tests de l'autre côté d'un appel HTTP, d'une file d'attente ou d'un événement, comme les spécifications d'une application Angular pour une modification du contrôleur Spring qu'elle appelle, puisque ces tests se moquent de cette limite ; passez --cross-tier pour les inclure. Merci @jotder pour le rapport. (#3320)
  • CodeGraph ne prend plus le verrou d'index de git pendant qu'il vérifie les modifications apportées à votre référentiel, donc un git add dans un hook de pré-commit, un commit ou une extraction qui s'exécute pendant la synchronisation de CodeGraph n'échoue plus avec "index.lock : le fichier existe". Merci @iamclaudia-ai pour le rapport. (#3295)
  • codegraph impact et codegraph_impact sont à nouveau aussi rapides qu'ils l'étaient dans 1.6.2, avec les mêmes résultats : 1.6.3 lisait les dépendances de chaque symbole d'une manière qui ralentissait chaque étape de la marche. Merci @inth3shadows pour le rapport et le correctif, et @Marcos-199-GitHub pour le #3285. (#3248)
  • Lorsque la synchronisation de rattrapage du serveur CodeGraph sur un grand projet est arrêtée parce que les appels de l'outil qu'il sert empêchent son journal d'écriture anticipée de diminuer, il attend désormais avant de réessayer, un peu plus longtemps à chaque fois, au lieu de recommencer chaque seconde pendant que vous continuez à travailler. Merci @kiliman pour le rapport. (#3273)
  • Un serveur CodeGraph MCP démarré dans un dossier sans index ne démarre plus son processus de surveillance de blocage distinct jusqu'à ce que la session appelle pour la première fois un outil ou ouvre un projet. Ainsi, les sessions qui répertorient uniquement les outils, autant d'hôtes les ouvrent, utilisent moins de mémoire. Merci @AiurArtanis pour le rapport et @johnhldiver-beep pour le #3257. (#3250)
  • Un serveur CodeGraph dont le dossier de projet est supprimé, comme un arbre de travail git supprimé, se ferme désormais dans un délai d'environ une demi-minute, fermant son observateur de fichiers et supprimant les listes codegraph daemon des serveurs, au lieu de s'exécuter jusqu'à la fin de sa dernière session et son expiration. Sous Windows, il empêche également la suppression des fichiers d'index de ce dossier. Merci @deniskern pour le rapport et @johnhldiver-beep pour le #3259. (#3245)
  • codegraph upgrade exécuté à partir de votre dossier personnel ne traite plus la configuration utilisateur de vos agents comme celle d'un projet : le serveur CodeGraph du curseur continue de suivre l'espace de travail que vous ouvrez au lieu d'être épinglé à votre dossier personnel, et aucune section CodeGraph n'est écrite dans ~/AGENTS.md, ~/GEMINI.md ou ~/QWEN.md. Merci @shoma-endo pour le rapport et @b84330808 et @LuisAlbertoMK. (#3234)
  • Dans OpenCode, les instructions de CodeGraph, à la fois celles envoyées par son serveur et la section codegraph install écrite dans le AGENTS.md d'OpenCode, nomment désormais ses outils comme OpenCode les répertorie (codegraph_codegraph_explore), afin que l'agent n'appelle plus un nom d'outil qui n'existe pas. Merci @expiren pour le rapport. (#1267)
  • codegraph init dans un projet dont la dernière exécution d'index a été interrompue ou a échoué à mi-chemin indique désormais que l'index est incomplet et qu'il faut exécuter codegraph index, au lieu de "Déjà initialisé", qui se lit comme une configuration fonctionnelle. Merci @maxmilian pour le rapport et @LuisAlbertoMK. (#3228)
  • codegraph callers, callees et impact avertissent désormais lorsqu'un fichier dans la réponse a changé sur le disque après sa dernière indexation, comme le faisaient déjà codegraph node et explore, donc un numéro de ligne décalé ne se lit plus comme un numéro actuel. Avec --json, l'avertissement est envoyé à stderr et la réponse répertorie ces fichiers sous changedOnDisk. Merci @arifpambudi242 pour le rapport et @mohitdixit02. (#3260)
  • codegraph status rapporte désormais les modifications, les nouveaux fichiers et les suppressions dans la source gitignored que codegraph.json include apporte dans l'index, au lieu d'appeler l'index à jour jusqu'à ce qu'une synchronisation les récupère. Merci @mixxer pour le rapport et la pull request. (#3086)
  • Sous Linux et macOS, lorsque le système tue CodeGraph avec un signal, par exemple lorsqu'il manque de mémoire pendant codegraph init ou codegraph index, la commande indique désormais quel signal et se termine comme le ferait un shell (137 pour SIGKILL), au lieu de quitter 1 sans message. Merci @inth3shadows pour le rapport et @johnhldiver-beep. (#3277)
  • La requête d'un test Spring ou Laravel est désormais liée uniquement à une route de sa propre application, et non à une route d'un serveur JavaScript ou TypeScript qui correspond au chemin, donc codegraph affected ne sélectionne plus les tests Java ou PHP pour une modification de votre code Web. Merci @jotder pour le rapport. (#3320)

Indexation et synchronisation

  • codegraph sync et l'observateur de fichiers suivent désormais une modification qui ajoute, supprime ou redirige un membre d'un objet exporté, comme export const api = { getUser, saveUser }, donc un appel tel que api.saveUser() dans un fichier, la modification n'a pas touché aux liens vers le nouveau membre, ou vers l'objet, comme le fait un nouvel index. Merci @inth3shadows pour le rapport. (#3015)
  • Un fichier dont l'analyse ne se termine jamais, comme un fichier .tsx avec un attribut JSX à moitié typé, n'empêche plus codegraph init de se fermer ou laisse codegraph sync et l'observateur de fichiers tourner à plein régime CPU : son analyse s'arrête désormais à la limite de temps d'analyse du fichier, et le fichier est répertorié comme une analyse ayant expiré. Merci @inth3shadows pour le rapport. (#3274)
  • Après la mise à niveau, codegraph status et la première réponse CodeGraph de chaque session d'agent signalent désormais un projet indexé par 1.6.3 ou une version antérieure comme obsolète, puisque cette version lit le code dans lequel ces index sont manquants, comme les constructeurs principaux Dart, les routes Elysia, PHP inclut construit à partir de __DIR__ et les méthodes d'un objet export default ; exécutez codegraph index dans chaque projet pour le reconstruire. (#3411)

JavaScript et TypeScript

  • Les gestionnaires d'événements JavaScript et TypeScript enregistrés avec on() sont désormais liés uniquement à partir du code qui émet sur le même émetteur, et au gestionnaire défini où ils sont enregistrés, donc deux modules qui gardent chacun leur propre émetteur et utilisent le même nom d'événement ne se lient plus. Merci @inth3shadows pour le rapport. (#2973)
  • Dans JavaScript, les méthodes écrites de manière classique, Ctor.prototype.m = function () {…} et un Ctor.m = function () {…} statique, sont désormais indexées comme méthodes de leur constructeur, et les fonctions d'un objet module.exports = {…} comme exportations de ce module, donc this.m() à l'intérieur atteint le propre m du constructeur ou de l'objet au lieu d'une fonction sans rapport du même nom ailleurs. Merci @inth3shadows pour le rapport. (#2966)
  • Dans JavaScript et TypeScript, les fonctions d'un objet exporté par défaut par un module, comme un magasin Vuex divisé en actions.js, getters.js et mutations.js (export default { fetchUser() {…} }), sont désormais indexées comme default::fetchUser, donc codegraph_explore, node, query, callers et impact les trouvent, et un appel via le module importation par défaut, this.fetchUser() ou un Vuex dispatch('fetchUser') y renvoie ; un Vuex commit est désormais toujours lié à une mutation et un dispatch à une action. Merci @daniel-luan-tran pour le rapport. (#3393)
  • Dans JavaScript et TypeScript, this.findAll() dans une classe qui encapsule un assistant importé du même nom est désormais lié à la propre méthode de la classe au lieu de l'assistant importé. Merci @inth3shadows pour le rapport. (#2954)
  • Dans JavaScript et TypeScript, un appel écrit sur this, comme this.cast() ou this.validate(), ne renvoie plus à un const, à une liaison require ou à une déclaration de fonction qui ne partage que son nom, dans le même fichier ou dans un autre, car ce que l'appel atteint est une propriété de l'objet.
  • Dans TypeScript, un appel sur un paramètre ou local nommé comme un import, comme stream.write() dans stream(c, async (stream) => …), passe désormais par ce paramètre ou local, et une méthode appelée sur une fonction importée ne renvoie plus à la fonction elle-même ; la même erreur via require a déjà été corrigée dans 1.6.3. Merci @inth3shadows pour le rapport. (#2953)
  • Dans JavaScript et TypeScript, un appel à un nom qu'une fonction autour de l'appelant déclare pour elle-même, comme un assistant qu'une fonction de flèche interne appelle, est désormais lié à cette déclaration locale au lieu de l'importation du fichier du même nom. Merci @inth3shadows pour le rapport. (#2949)
  • Dans JavaScript et TypeScript, un appel à un assistant déclaré dans un bloc describe(…), ou tout autre rappel, est désormais lié à l'assistant déclaré par ce bloc au lieu d'un assistant du même nom provenant d'un autre bloc situé plus près. Merci @inth3shadows pour le rapport. (#2944)
  • Dans JavaScript et TypeScript, un appel dans une planche, comme <input {...register('email')} /> avec register extrait de useForm(), ne renvoie plus à une fonction de projet sans rapport qui partage le nom. Merci @inth3shadows pour le rapport. (#2962)
  • Dans JavaScript et TypeScript, un espace de noms de module qu'un autre module transmet par son nom, comme import { z } from 'zod' de zod de import * as z from './external'; export { z }, ou export * as ns from './schemas', conduit désormais z.string() vers ce que ce module exporte, comme le fait import * as z, au lieu d'une méthode du même nom ailleurs. Merci @inth3shadows pour le rapport. (#2951)
  • Dans JavaScript et TypeScript, une importation via un baril de plusieurs lignes export * est désormais liée au module qui exporte le nom lui-même, quelle que soit la ligne qui arrive en premier, au lieu d'une méthode du même nom d'un objet exporté par un autre module. Merci @inth3shadows pour le rapport. (#3233)
  • Dans JavaScript et TypeScript, une méthode appelée sur une variable qu'un appel de bibliothèque remplit, comme const root = createRoot(el) de React-dom, net.createServer() ou canvas.getContext('2d'), ne renvoie plus à la méthode de projet qui partage son nom. Merci @inth3shadows pour le rapport. (#2947)
  • Dans TypeScript, une méthode appelée sur une variable remplie par la fabrique statique d'une classe, comme const writer = DatabaseConnection.initialize(path), est désormais liée à la méthode de la classe que la fabrique dit renvoyer, au lieu d'une classe devinée à partir du nom de la variable. Merci @inth3shadows pour le rapport. (#2946)
  • Dans TypeScript, un appel via la propriété typée fonction d'une interface, comme matcher.snapshot(), ne renvoie plus à la méthode d'une classe non liée du même nom ; une classe qui implémente l'interface, ou la construit, est toujours liée. Merci @inth3shadows pour le rapport. (#3035)
  • Dans JavaScript et TypeScript, un appel à deux champs ou plus profonds de this, comme this.cache.list.push(1) ou this.extractor.functionTypes.includes(type), ne renvoie plus à une méthode de projet sans rapport nommée comme push, includes, has ou set de JavaScript, ou à une propriété qui partage simplement le nom. Merci @inth3shadows pour le rapport. (#2948)
  • Dans JavaScript et TypeScript, une entrée workspaces qui pointe en dehors du projet, comme "../shared" dans package.json ou pnpm-workspace.yaml, ne fait plus compter le package de ce dossier comme faisant partie du projet, donc un appel via une importation de celui-ci n'est plus lié à une de vos fonctions sans rapport avec le même nom. Merci @bompus pour le rapport et @johnhldiver-beep. (#3093)
  • Dans JavaScript et TypeScript, un appel à une variable locale déclarée après une autre dans la même instruction, comme let n = 0, ob = make(), ou à côté d'un défaut dans une déstructuration, comme const { ob = make() } = o, se lie à nouveau lorsqu'une variable du même nom en dehors de la fonction détient un type de bibliothèque, comme c'était le cas avant 1.6.3. Merci @inth3shadows pour le rapport et @mohitdixit02. (#3293)
  • Dans JavaScript, un appel à un membre d'un module obligatoire de votre projet n'a pas, comme utils.missing() après const utils = require('./utils'), de lien vers une méthode de classe non liée de ce nom. Merci @inth3shadows pour le rapport et @johnhldiver-beep. (#3272)
  • Un appel fetch ou HTTP-client vers le API d'une autre société, comme fetch('https://api.github.com/users/…'), ne renvoie plus à la route de votre propre serveur avec le même chemin ; un appel à localhost, à un hôte que votre code remplit, ou via l'URL de base d'un client toujours lié. Merci @inth3shadows pour le rapport et @johnhldiver-beep. (#2974)
  • Dans JavaScript et TypeScript, un appel ou new d'un global, comme parseInt(…), new Response(…) ou new URL(…), dans un module qui n'importe pas ce nom ne renvoie plus à un export du même nom d'un autre fichier de votre projet. Merci @inth3shadows pour le rapport. (#3238)
  • Dans JavaScript, un require() d'un dossier par un chemin relatif, comme require('..') à partir des tests d'un package, charge désormais le fichier dont le nom package.json du dossier est main, comme le fait Node, donc appelle via lui un lien vers la fonction que le fichier exporte. Avant, un dossier sans index.js n'était pas suivi, et l'appel était lié à la variable contenant le résultat require() ; sur fastify, le Fastify() de chaque test est lié à son propre fichier de test. Merci @inth3shadows pour le rapport. (#2964)
  • Dans JavaScript, une variable qui contient ce que renvoie la fonction d'un module requis, comme const app = require('./app')(), ne compte plus comme le module lui-même, donc un appel comme app.listen() ne renvoie plus à la fonction d'usine du module, et est lié à la méthode de la classe que l'usine renvoie lorsqu'elle est connue. Merci @inth3shadows pour le rapport. (#2964)
  • Dans JavaScript et TypeScript, un nom importé d'un package que votre package.json ne répertorie pas mais que votre projet a installé, comme import { useForm } from 'react-hook-form' hissé à la racine d'un monorepo node_modules, ne renvoie plus à une fonction non liée du même nom ailleurs dans votre projet (#3271). Réindexez les projets JavaScript et TypeScript après la mise à niveau. ####Python
  • Dans Python, import time ne lie plus le fichier d'importation à une fonction de projet qui se trouve être nommée time, donc une telle fonction cesse de lister tous les fichiers qui importent le module de bibliothèque standard parmi ses appelants et dans son impact. Il en va de même pour json, copy, random, logging et tout autre module, ainsi que pour une variable de secours comme brotli = None à côté d'un import brotli gardé. Merci @inth3shadows pour le rapport. (#3239)
  • Dans Python, un appel à une fonction ou une méthode déclarée avec typing.overload, comme command et prompt de click, est désormais lié au def qui s'exécute à la place du premier stub @overload, de sorte que l'implémentation affiche ses appelants et un chemin d'appel le traverse. Un stub sans implémentation en dessous, comme dans un Protocol, reste la cible, et le overload d'une autre bibliothèque dont tous les corps sont exécutés est laissé seul. Merci @inth3shadows pour le rapport et @nilotpal-n7. (#2963)
  • Dans Python, un appel comme self.create_app() sur un attribut qui contient un appelable ne renvoie plus à une fonction ou une variable du même nom dans un autre fichier, ni, lorsque la classe définit elle-même cet attribut, à la méthode d'une autre classe de ce nom, donc le chargement de l'application du flacon cesse d'afficher un exemple d'application comme appelé. Une méthode dont la classe hérite ou qu'une sous-classe remplace toujours les liens, tout comme une fonction que la classe stocke sous ce nom. Merci @inth3shadows pour le rapport et @nilotpal-n7. (#2958)
  • Dans Python, un élément intégré écrit nu, comme raise TimeoutError(…), class Bad(ValueError) ou sorted(rows), ne renvoie plus à une classe de projet ou à une fonction de ce nom dans un fichier que le code n'importe pas, donc le propre TimeoutError d'un projet cesse de collecter tous les fichiers qui lèvent l'élément intégré. Un nom que le fichier définit ou importe lui-même est toujours lié. Merci @inth3shadows pour le rapport. (#3232)
  • Dans Python, un appel d'un nom et le code qui l'entoure se lie, comme un flat = lambda … local, un paramètre, une variable de boucle ou de compréhension, un paramètre lambda, ou un paramètre local ou d'une fonction englobante, ne renvoie plus à une fonction ou variable au niveau du module de ce nom, que ce soit dans le même fichier ou dans un fichier que le code n'importe jamais. Merci @inth3shadows pour les rapports et @johnhldiver-beep. (#3037, #3230, #3231)
  • Dans Python, un local construit à partir d'une classe via son module, comme client = httpx.AsyncClient(), ou lié par with ou async with … as client, a désormais cette classe, donc client.get() est lié à AsyncClient.get au lieu de la méthode d'une classe nommée comme la variable, comme Client.get. Un with dont la classe distribue quelque chose d'autre de __enter__, et une classe d'un module extérieur à votre projet, ne donnent toujours aucun type au local. Merci @inth3shadows pour le rapport et @nilotpal-n7. (#2957)
  • Dans Python, une méthode appelée sur une limite locale à partir d'un appel, comme made = make(q) ou s = store.stage(), porte désormais le type que la fonction ou la méthode appelée déclare qu'elle renvoie : un Path, un str ou une autre classe extérieure à votre projet ne lie rien, alors que n'importe quelle méthode de projet partageant le nom pourrait le faire, et l'une de vos propres classes lie sa propre méthode même lorsque d'autres classes en ont une de ce nom. Merci @inth3shadows pour les rapports et @johnhldiver-beep. (#3038, #3240)
  • Dans Python, un from x import name écrit dans une fonction s'applique désormais à cette fonction uniquement, donc les appels de name dans le reste du fichier atteignent le propre def name du fichier au lieu de la fonction importée, en tant que wrapper qui importe l'original qu'il enveloppe attend. Merci @inth3shadows pour le rapport. (#3229)

Java, Kotlin, C# et ASP.NET

  • En Java, lorsque deux packages déclarent une classe du même nom, un appel statique, un appel sur un nouvel objet ou un appel via une variable atteint désormais celui que le fichier appelant peut voir, y compris via un import wildcard, et un appel écrit avec le package, comme com.x.b.Util.log(…), atteint la classe de ce package. Merci @inth3shadows pour les rapports et @johnhldiver-beep. (#2976, #3290, #3291)
  • Dans Kotlin, une extension déclarée sur un alias d'importation d'un type de bibliothèque, comme fun DeclAlias.pad() après import androidx.compose.ui.Modifier as DeclAlias, est désormais liée à partir d'appels sur ce type, quel que soit le nom sous lequel le fichier appelant l'importe. Merci @mixxer pour le rapport et la pull request. (#3084)
  • En C#, une méthode appelée sur ce qu'une méthode de la même classe renvoie, comme GetMailer().Send(), est désormais liée à la méthode du type que cette méthode est déclarée renvoyer. Merci @Gobakabana pour le rapport. (#2906)
  • Dans ASP.NET Core, les routes d'attributs sont désormais nommées de la manière dont ASP.NET les sert : [controller] et [action] sont renseignés, chaque contrôleur utilise son propre [Route] (ou celui de son contrôleur de base), les chemins ~/ sont autonomes et les actions marquées [HttpHead], [HttpOptions] ou [AcceptVerbs], avec leur propre [Route], ou dans une liste d'attributs sont ne manque plus. Merci @Gobakabana pour le rapport. (#2905)
  • En C#, une méthode d'extension correspond désormais au type pris par son paramètre this, donc "hi".Shout() et mailer.Shout() atteignent chacun leur propre extension, et un appel de la propre méthode d'une chaîne n'atteint plus une extension de projet du même nom. Merci @Gobakabana pour le rapport. (#2906)
  • En C#, une méthode appelée via ?. ou !., comme _mailer?.Send(), est désormais liée à la méthode du type du récepteur. Merci @Gobakabana pour le rapport. (#2906)
  • En C#, une méthode transmise ou stockée comme valeur via son objet, comme Task.Run(worker.Run) ou Action later = worker.Run;, compte désormais comme une utilisation de cette méthode, donc codegraph callers et impact l'affichent. Merci @Gobakabana pour le rapport. (#2906)

codegraph v1.6.4

[1.6.4] - 2026-11-20

Highlights

  • Small questions cost less. Ask your agent what a function or constant is, or who calls it, and codegraph_explore now answers with the definition and every line that uses it, instead of a long answer about related files.
  • Faster answers in Claude Code. The prompt hook now asks the CodeGraph server already running for your project instead of loading the index again on every prompt, which matters most in large projects, and codegraph impact is as fast as it was in 1.6.2 again.
  • Safer on a shared computer. Each agent session now checks that the background server it connects to runs as you before sending it anything.
  • More of your code in the graph. Elysia (Bun) routes, PHP includes built from the web server's root or the file's own folder, Dart 3.13 primary constructors and newer Kotlin syntax are now read, and ASP.NET Core routes are named the way ASP.NET serves them.
  • More accurate links. Dozens of fixes help calls reach the code they mean, most of all in JavaScript and TypeScript, Python, Rust, C#, PHP and Java, and codegraph affected no longer picks tests on the far side of an HTTP call, a queue or an event unless you pass --cross-tier.
  • Fewer stuck commands. A git add or commit no longer fails with "index.lock: File exists" while CodeGraph syncs, a file whose parse never ends no longer keeps codegraph init or sync from finishing, and a server whose project folder was deleted now shuts down.
  • Upgrading: re-index your projects with codegraph index after this release. Many of these fixes are written while indexing, and codegraph status and your agent both tell you when an index was built by an older version.

Security

  • On a computer shared with other users, each agent session now checks that the CodeGraph background server it connects to runs as you before sending it anything, and serves the session itself when the server can't prove it, so another user can no longer stand in for your server to read your agent's queries or feed it made-up answers. Thanks @aidenpan0x for pointing it out.

New Features

  • The Claude Code prompt hook now gets its context from the CodeGraph server already running for your project instead of loading the index again on every prompt, so structural prompts are answered sooner, most of all in large projects; with no server running, one that is busy, or one that can't prove it runs as you, the hook works it out itself as before. Thanks @aidenpan0x for the report, the measurements and the pull request. (#3284)
  • Elysia (Bun) backends now have their HTTP routes in the graph, named by the full path a request takes, with the prefixes of new Elysia({ prefix }), .group() and a .use() in another file included, and linked to their handlers, so codegraph_explore can follow a request from its route into your code. Thanks @ChampPABA for the report. (#3255)
  • PHP includes built from the web server's root, like require $_SERVER['DOCUMENT_ROOT'] . '/inc/header.php', now link to their file: CodeGraph works out which folder the server serves from where your includes' paths name files, links nothing when they don't settle it rather than guess, and takes "webRoot": "public" in codegraph.json (or "." for the project root) when you'd rather name it yourself. Thanks @artisanya for the report. (#3298)
  • Kotlin is now read with a newer version of its grammar, so code it used to misread, such as an annotated class whose methods showed up as top-level functions, a class that delegates by another object, or newer syntax like when guards and explicit backing fields, now has its classes, functions and calls in the graph where they belong. (#3410)
  • codegraph_explore now answers a question about one symbol, like "who calls toValidURL?" or "what is MAX_RETRIES?", with that symbol's source and every line that uses it, each with the function it sits in and the line's text, instead of filling its whole answer with files that only share words with the name, so these small questions cost less and leave nothing to search for afterwards. Thanks @GeorgeTaveras1231 for the measurements. (#3407)

Fixes

Setup, the background server and the CLI

  • codegraph affected no longer selects tests on the other side of an HTTP call, a queue or an event, like an Angular app's specs for a change to the Spring controller it calls, since those tests mock that boundary; pass --cross-tier to include them. Thanks @jotder for the report. (#3320)
  • CodeGraph no longer takes git's index lock while it checks your repository for changes, so a git add in a pre-commit hook, a commit or a checkout that runs while CodeGraph syncs no longer fails with "index.lock: File exists". Thanks @iamclaudia-ai for the report. (#3295)
  • codegraph impact and codegraph_impact are as fast as they were in 1.6.2 again, with the same results: 1.6.3 read each symbol's dependents in a way that slowed down every step of the walk. Thanks @inth3shadows for the report and the fix, and @Marcos-199-GitHub for #3285. (#3248)
  • When the CodeGraph server's catch-up sync on a large project is stopped because the tool calls it is serving keep its write-ahead log from shrinking, it now waits before trying again, a little longer each time, instead of starting over every second while you keep working. Thanks @kiliman for the report. (#3273)
  • A CodeGraph MCP server started in a folder with no index no longer starts its separate hang-watchdog process until the session first calls a tool or opens a project, so sessions that only list the tools, as many hosts open them, use less memory. Thanks @AiurArtanis for the report and @johnhldiver-beep for #3257. (#3250)
  • A CodeGraph server whose project folder is deleted, like a removed git worktree, now exits within about half a minute, closing its file watcher and dropping out of the servers codegraph daemon lists, instead of running until its last session ends and it times out. On Windows it also stops keeping that folder's index files from being deleted. Thanks @deniskern for the report and @johnhldiver-beep for #3259. (#3245)
  • codegraph upgrade run from your home folder no longer treats your agents' user-wide setup as a project's: Cursor's CodeGraph server keeps following the workspace you open instead of being pinned to your home folder, and no CodeGraph section is written into ~/AGENTS.md, ~/GEMINI.md or ~/QWEN.md. Thanks @shoma-endo for the report and @b84330808 and @LuisAlbertoMK. (#3234)
  • In OpenCode, CodeGraph's instructions, both the ones its server sends and the section codegraph install writes to OpenCode's AGENTS.md, now name its tools the way OpenCode lists them (codegraph_codegraph_explore), so the agent no longer calls a tool name that doesn't exist. Thanks @expiren for the report. (#1267)
  • codegraph init in a project whose last index run was killed or failed partway now says the index is incomplete and to run codegraph index, instead of "Already initialized", which read like a working setup. Thanks @maxmilian for the report and @LuisAlbertoMK. (#3228)
  • codegraph callers, callees and impact now warn when a file in the answer changed on disk after it was last indexed, as codegraph node and explore already did, so a shifted line number no longer reads as a current one. With --json the warning goes to stderr and the answer lists those files under changedOnDisk. Thanks @arifpambudi242 for the report and @mohitdixit02. (#3260)
  • codegraph status now reports edits, new files and deletions in gitignored source that codegraph.json include brings into the index, instead of calling the index up to date until a sync picked them up. Thanks @mixxer for the report and the pull request. (#3086)
  • On Linux and macOS, when the system kills CodeGraph with a signal, such as when it runs out of memory during codegraph init or codegraph index, the command now says which signal and exits as a shell would (137 for SIGKILL), instead of exiting 1 with no message. Thanks @inth3shadows for the report and @johnhldiver-beep. (#3277)
  • A Spring or Laravel test's request is now linked only to a route of its own app, not to a JavaScript or TypeScript server's route that happens to match the path, so codegraph affected no longer selects Java or PHP tests for a change to your web code. Thanks @jotder for the report. (#3320)

Indexing and sync

  • codegraph sync and the file watcher now follow an edit that adds, removes or repoints a member of an exported object, like export const api = { getUser, saveUser }, so a call such as api.saveUser() in a file the edit didn't touch links to the new member, or back to the object, as a fresh index does. Thanks @inth3shadows for the report. (#3015)
  • A file whose parse never ends, like a .tsx file with a half-typed JSX attribute, no longer keeps codegraph init from exiting or leaves codegraph sync and the file watcher spinning at full CPU: its parse now stops at the file's parse time limit, and the file is listed as a parse that timed out. Thanks @inth3shadows for the report. (#3274)
  • After you upgrade, codegraph status and the first CodeGraph answer in each agent session now flag a project indexed by 1.6.3 or earlier as out of date, since this release reads code those indexes are missing, like Dart primary constructors, Elysia routes, PHP includes built from __DIR__ and the methods of an export default object; run codegraph index in each project to rebuild it. (#3411)

Thanks @inth3shadows for the report. (#2973)
  • In JavaScript, methods written the classic way, Ctor.prototype.m = function () {…} and a static Ctor.m = function () {…}, are now indexed as methods of their constructor, and the functions of a module.exports = {…} object as that module's exports, so this.m() inside them reaches the constructor's or the object's own m instead of an unrelated function of the same name elsewhere. Thanks @inth3shadows for the report. (#2966)
  • In JavaScript and TypeScript, the functions of an object a module default-exports, like a Vuex store split into actions.js, getters.js and mutations.js (export default { fetchUser() {…} }), are now indexed as default::fetchUser, so codegraph_explore, node, query, callers and impact find them, and a call through the module's default import, this.fetchUser() or a Vuex dispatch('fetchUser') links to them; a Vuex commit now always links to a mutation and a dispatch to an action.   • In JavaScript and TypeScript, this.findAll() in a class that wraps an imported helper of the same name now links to the class's own method instead of the imported helper. Thanks @inth3shadows for the report. (#2954)
  • In JavaScript and TypeScript, a call written on this, like this.cast() or this.validate(), no longer links to a const, a require binding or a function declaration that only shares its name, in the same file or another, because what the call reaches is a property of the object.
  • In TypeScript, a call on a parameter or local named like an import, like stream.write() inside stream(c, async (stream) => …), now goes by that parameter or local, and a method called on an imported function no longer links to the function itself; the same mistake through require was already fixed in 1.6.3. Thanks @inth3shadows for the report. (#2953)
  • In JavaScript and TypeScript, a call to a name that a function around the caller declares for itself, like a helper an inner arrow function calls, now links to that local declaration instead of the file's import of the same name. Thanks @inth3shadows for the report. (#2949)
  • In JavaScript and TypeScript, a call to a helper declared inside a describe(…) block, or any other callback, now links to the helper that block declares instead of a same-named one from another block that happens to sit nearer. Thanks @inth3shadows for the report. (#2944)
  • In JavaScript and TypeScript, a call inside a spread, like <input {...register('email')} /> with register taken from useForm(), no longer links to an unrelated project function that shares the name. Thanks @inth3shadows for the report. (#2962)
  • In JavaScript and TypeScript, a module namespace that another module hands on by name, like zod's import { z } from 'zod' of import * as z from './external'; export { z }, or export * as ns from './schemas', now leads z.string() to what that module exports, as import * as z does, instead of a same-named method elsewhere. Thanks @inth3shadows for the report. (#2951)
  • In JavaScript and TypeScript, an import through a barrel of several export * lines now links to the module that exports the name itself, whichever line comes first, instead of a same-named method of an object another module exports. Thanks @inth3shadows for the report. (#3233)
  • In JavaScript and TypeScript, a method called on a variable that a library call fills in, like const root = createRoot(el) from react-dom, net.createServer() or canvas.getContext('2d'), no longer links to the one project method that happens to share its name. Thanks @inth3shadows for the report. (#2947)
  • In TypeScript, a method called on a variable a class's static factory fills in, like const writer = DatabaseConnection.initialize(path), now links to the method of the class the factory says it returns, instead of a class guessed from the variable's name. Thanks @inth3shadows for the report. (#2946)
  • In TypeScript, a call through an interface's function-typed property, like matcher.snapshot(), no longer links to an unrelated class's method of the same name; a class that implements the interface, or builds it, is still linked. Thanks @inth3shadows for the report. (#3035)
  • In JavaScript and TypeScript, a call two or more fields deep from this, like this.cache.list.push(1) or this.extractor.functionTypes.includes(type), no longer links to an unrelated project method named like JavaScript's own push, includes, has or set, or to a property that merely shares the name. Thanks @inth3shadows for the report. (#2948)
  • In JavaScript and TypeScript, a workspaces entry that points outside the project, like "../shared" in package.json or pnpm-workspace.yaml, no longer makes that folder's package count as part of the project, so a call through an import of it is no longer linked to an unrelated function of yours with the same name. Thanks @bompus for the report and @johnhldiver-beep. (#3093)
  • In JavaScript and TypeScript, a call on a local variable declared after another one in the same statement, like let n = 0, ob = make(), or beside a default in a destructuring, like const { ob = make() } = o, links again when a variable of the same name outside the function holds a library's type, as it did before 1.6.3. Thanks @inth3shadows for the report and @mohitdixit02. (#3293)
  • In JavaScript, a call to a member a required module of your project doesn't have, like utils.missing() after const utils = require('./utils'), no longer links to an unrelated class's method of that name. Thanks @inth3shadows for the report and @johnhldiver-beep. (#3272)

  • In JavaScript and TypeScript, a call or new of a global, like parseInt(…), new Response(…) or new URL(…), in a module that doesn't import that name no longer links to a same-named export of another file in your project. Thanks @inth3shadows for the report. (#3238)

Thanks @inth3shadows for the reports and @johnhldiver-beep. (#3038, #3240)
  • In Python, a from x import name written inside a function now applies to that function only, so calls of name in the rest of the file reach the file's own def name instead of the imported function, as a wrapper that imports the original it wraps expects. Thanks @inth3shadows for the report. (#3229)

  • In Java, when two packages declare a class of the same name, a static call, a call on a new object or a call through a variable now reaches the one the calling file can see, including through a wildcard import, and a call written with the package, like com.x.b.Util.log(…), reaches that package's class.   • In C#, a method passed or stored as a value through its object, like Task.Run(worker.Run) or Action later = worker.Run;, now counts as a use of that method, so codegraph callers and impact show it. Thanks @Gobakabana for the report. (#2906)
  • In Kotlin, a call named after a modifier keyword at the start of a statement, like annotation("jakarta.persistence.Entity") in a Gradle allOpen { } block or a class's own open(), is now read as the call it is, so a build script made of such calls no longer warns that it contributes nothing to the graph. Thanks @clayly for the report. (#3410)

PHP and Laravel

  • In PHP, a method called on a freshly built object, like (new SettingClient())->getSet(1), now links to the class the file's namespace and use imports name, or to a method it inherits, so these calls show up in callers and impact. Thanks @holysor for the report. (#3244)
  • In Laravel, a route written like [UserController::class, 'show'] now links to the controller the routes file imports, through a plain or aliased use, a group use, an imported namespace or a fully qualified name, instead of a same-named controller elsewhere or nothing. Thanks @inth3shadows for the reports and @johnhldiver-beep. (#2975, #3292)
  • In PHP, a method called in a different letter case than its declaration, like PriceConverter::CalcBasePrice(1) or $c->GetRate() for calcBasePrice and getRate, now links to that method, as PHP reads method names without regard to case, so those calls show up in callers and impact. Thanks @artisanya for the report and @johnhldiver-beep. (#3297)
  • In PHP code written for PHP 7 and older, a string offset in braces, like $code{0}, no longer makes the function or class around it disappear from the index with its calls credited to the file; it now reads like $code[0]. Thanks @artisanya for the report. (#3299)
  • In PHP, a require or include of a file inside a function or method now counts as that function depending on the file, so callers and impact follow code in the included file back to the function and its callers. Thanks @artisanya for the report. (#3296)
  • In PHP, an include built from the file's own directory, like require_once __DIR__ . '/inc/a.php' or dirname(__FILE__) . '/inc/b.php', now links to that file the way a plain require_once 'lib.php' does, and a path starting with ./ or ../ links only to the file named exactly, as PHP loads it, never one with .php added. Thanks @artisanya for the report and @inth3shadows. (#3298)

Rust

  • In Rust, a call through a module that a glob use brings in, like gzip::write() in a test module with use super::*, or that a use inside the function names, now links to that module's function again. Thanks @Egrn for the report and @mohitdixit02. (#3253)
  • In Rust, codegraph_explore's blast radius now recognizes unit tests in a #[cfg(test)] module or a tests.rs file, instead of reporting "no tests found" for the functions they test. Thanks @moogiemode for the report and @maxmilian. (#3265)
  • In Rust, a function or method passed as a value through its path, like g.map(Graph::counts) or .map(Self::helper), now counts in its callers and impact the way a function passed by name already did, linked only when the path names it for certain: never another type's method of the same name, and never a method of a trait implementation, since which one Rust uses there depends on the type of the argument. Thanks @Egrn for the report and @inth3shadows. (#3254)
  • In Rust, a call on a value whose type comes from outside your project, like an outside crate's builder chain or stdout.flush(), no longer links to one of your methods that only shares its name, such as your own impl Write's write and flush or an associated function like Graph::build(n), and Rules::default() on a #[derive(Default)] type no longer links to another type's default. Thanks @Egrn for the report. (#3252)
  • In Rust, a call written in the arguments of format!, println!, write!, assert_eq!, vec!, matches! or serde_json's json! now links to the function or method it calls, as the same call outside the macro does, and a variant in a matches! pattern now counts as a use of its enum. Thanks @Egrn for the report. (#3251)

Go, Swift, Dart, C and C++

  • A C++ .h header that only declares functions and extern variables, with no class, namespace or template in it, is now read as C++ when it uses a template type like CComPtr<IDiaDataSource>, a reference parameter like bstr_t& path or const qstring &name, or a default argument like int depth = 0, instead of as C, which dropped its symbols and warned "parse produced no symbols (tree has errors)". Thanks @sonyps5201314 for the report. (#3397)
  • In Swift, a type no longer picks up the inheritance of a type nested inside it, which linked a name used in the type to an unrelated type's nested type and put it in the wrong impact results. Thanks @bob-codedaptive for the report and @remote-controlled-man. (#3213)
  • In Go, a method called on new(T) or make(T) now links to that type's method, not a same-named method of another type that happened to be found first. Thanks @inth3shadows for the report. (#3237)
  • In Swift, an if or while whose condition is try await f() no longer breaks the method around it: the next member landed inside that method, and calls were recorded under names made of source text. Swift files are now read with a newer Swift grammar, which also parses more Swift 6 code without errors. Thanks @bob-codedaptive for the report. (#3212)
  • In Dart, a class declared with a Dart 3.13 primary constructor, like class Point(final int x, final int y) {…} or class const Foo({required final int a}), is now indexed under its own name with its members, where it had been named const or dropped with the rest of its file; Dart files are now read with a newer Dart grammar, which also parses dot shorthands and other recent Dart syntax without errors. Thanks @cutehackers for the report. (#3270)
