codegraphe v1.4.1

[1.4.1] - 2026-07-10

Nouvelles fonctionnalités

  • Le serveur MCP remarque désormais lorsqu'une version plus récente de CodeGraph existe et vous le signale : un serveur de longue date avait l'habitude de dériver silencieusement derrière les versions jusqu'à ce que quelque chose tombe en panne. Au démarrage, il vérifie la dernière version en arrière-plan (ne bloque jamais, au maximum une fois par jour, mise en cache sur tous les serveurs de la machine) et affiche une notification d'une seule ligne « mise à jour disponible — exécutez codegraph upgrade » dans le journal du serveur, dans les instructions que votre agent voit lors de la connexion et dans codegraph_status. Rien ne se met à jour tout seul, et être hors ligne signifie simplement aucun préavis. Désinscription avec CODEGRAPH_NO_UPDATE_CHECK=1 ; DO_NOT_TRACK=1 le désactive également. (#1243)

Correctifs

  • codegraph upgrade sur une installation Windows npm exécute à nouveau npm — le nœud moderne refuse de lancer npm.cmd directement, donc la mise à niveau a échoué avec une erreur d'apparition avant de faire quoi que ce soit. npm est désormais invoqué de la même manière qu'un terminal l'exécuterait. (#1238)
  • codegraph uninstall désinstalle désormais CodeGraph. Auparavant, il supprimait uniquement les configurations de l'agent et laissait tous les binaires installés derrière, donc codegraph s'exécutait toujours par la suite - particulièrement déroutant lorsqu'une installation globale npm et une installation autonome étaient présentes et que la suppression de l'une laissait toujours l'autre répondre sur PATH. La désinstallation trouve désormais toutes les installations sur la machine (le bundle autonome, le package global npm, le lien du lanceur) et les supprime toutes, après vous avoir montré exactement ce qu'elle a trouvé et demandé d'abord (--yes ignore l'invite). Les paramètres au niveau de la machine, tels que votre choix de télémétrie, sont conservés, une extraction de source n'est jamais touchée et le nouvel indicateur --keep-cli restaure l'ancien comportement des configurations uniquement. (#1071)
  • codegraph_explore ne permet plus aux mots anglais ordinaires dans une question en langage naturel de détourner le classement lorsqu'ils correspondent au nom d'un symbole de code. Une question telle que "comment le flux de mise à niveau vérifie-t-elle la dernière version" était utilisée pour traiter "vérifier" comme un symbole demandé par l'agent par son nom, classer le fichier de cette définition sans rapport en premier et regrouper les fichiers sur lesquels porte réellement la question hors de la réponse entièrement. Les noms de symboles écrits avec précision (camelCase, PascalCase, Snake_case, noms qualifiés) sont toujours en tête d'affiche, exactement comme auparavant, tout comme les sacs de symboles en mots simples dont les mots appartiennent ensemble dans le même fichier.
  • Les appels de méthode PHP effectués via une propriété de classe — $this->dep->method(), la forme d'appel dominante dans les bases de code d'injection de constructeur (Symfony, Laravel) — sont désormais résolus en méthode sur le type déclaré de la propriété, de sorte que les appelants et l'analyse d'impact voient les sites d'appels de production au lieu de signaler une méthode lourde en DI comme non appelée ou comme test uniquement. Les paramètres de constructeur promus, les propriétés typées, l'affectation de constructeur classique (y compris les signatures multilignes) et l'injection de setter typé comptent tous ; les propriétés typées par interface sont résolues par la méthode d'interface et les méthodes héritées sont résolues via la hiérarchie des types. Seules les déclarations en forme de propriété sont consultées — une variable locale ou un paramètre du même nom ailleurs ne peut jamais mal saisir la propriété — et une propriété dont le type ne peut pas être récupéré de manière statique reste non liée plutôt que devinée. Merci @w0lan. (#1220)
  • codegraph upgrade actualise désormais également les versions précédentes installées sur vos agents — la section CodeGraph dans CLAUDE.md / AGENTS.md / GEMINI.md et l'entrée MCP — de sorte que la mise à niveau ne laisse plus les agents suivre les instructions écrites pour les outils qui ont depuis été renommés ou supprimés. Actualisation uniquement : les agents que vous n'avez jamais configurés ne sont pas touchés et vos choix d'autorisation et de hook sont conservés. Également disponible manuellement sous le nom de codegraph install --refresh et désactivable avec CODEGRAPH_NO_INSTALL_REFRESH=1. (#1238)
  • codegraph upgrade sur une installation npm est désormais à nouveau mis à niveau via npm au lieu de créer discrètement une deuxième copie qui ne remporte jamais la course PATH - auparavant, codegraph --version continuait à signaler l'ancienne version pour toujours, quel que soit le nombre de mises à niveau. (#1238)
  • Après chaque mise à niveau, CodeGraph vérifie désormais que la commande codegraph résolue par votre terminal sert réellement la version fraîchement installée - confirmant que vous n'avez pas besoin d'un nouveau terminal ou vous indiquant exactement quelle installation obsolète masque la nouvelle. (#1071)
  • Le chien de garde de sécurité ne tue plus un index sain sur un stockage gravement dégradé. Auparavant, il jugeait l'activité uniquement par la boucle d'événements, de sorte qu'une longue écriture de base de données sur un disque en difficulté semblait identique à un processus bloqué et pouvait mettre fin à un index valide en cours. Pendant codegraph index/codegraph init, le chien de garde vérifie désormais également si les fichiers d'index sur le disque avancent avant d'agir : le travail lent mais en progression est laissé seul (délimité par un plafond rigide), tandis qu'un processus véritablement bloqué est toujours tué exactement aussi vite qu'auparavant. (#1231)
  • La synchronisation incrémentielle détecte désormais les relations entre fichiers qui ne peuvent être résolues qu'après une modification - par exemple, lorsqu'un fichier obtient une exportation qu'un autre fichier inchangé était déjà en train d'importer ou d'appeler. Auparavant, la référence dans le fichier inchangé n'était jamais revisitée, de sorte que les appelants, l'impact et les résultats de flux omettaient silencieusement le nouveau bord (tandis que l'état signalait un index propre) jusqu'à une réindexation complète. Les références qui ne peuvent pas encore être résolues sont désormais mémorisées et automatiquement réessayées chaque fois qu'un changement introduit un symbole qui pourrait les satisfaire - cela couvre également une classe obtenant une nouvelle méthode que d'autres fichiers appellent déjà. Merci @loadcosmos pour le rapport avec une reproduction minimale. (#1240)
  • Le cas inverse est également corrigé : lorsqu'une modification supprime ou déplace un symbole (ou supprime son fichier), les appelants dans les fichiers inchangés se résolvent désormais à nouveau au cours de la même synchronisation - se reconnectant au nouveau domicile du symbole lorsqu'il s'est déplacé, ou attendant de se reconnecter automatiquement à son retour - au lieu de perdre silencieusement leur relation jusqu'à une réindexation complète. (#1240)

codegraph v1.4.1

[1.4.1] - 2026-07-10

New Features

  • The MCP server now notices when a newer CodeGraph release exists and tells you — a long-running server used to drift behind releases silently until something broke. On startup it checks the latest release in the background (never blocking, at most once a day, cached across all servers on the machine) and surfaces a one-line "update available — run codegraph upgrade" notice in the server log, in the instructions your agent sees on connect, and in codegraph_status. Nothing updates by itself, and being offline just means no notice. Opt out with CODEGRAPH_NO_UPDATE_CHECK=1; DO_NOT_TRACK=1 disables it too. (#1243)

Fixes

  • codegraph upgrade on a Windows npm install actually runs npm again — modern Node refuses to launch npm.cmd directly, so the upgrade failed with a spawn error before doing anything. npm is now invoked the way a terminal would run it. (#1238)
  • codegraph uninstall now actually uninstalls CodeGraph. It used to remove only the agent configurations and leave every installed binary behind, so codegraph still ran afterward — especially confusing when both an npm global install and a standalone install were present and removing one still left the other answering on PATH. Uninstall now finds every install on the machine (the standalone bundle, the npm global package, the launcher link) and removes them all, after showing you exactly what it found and asking first (--yes skips the prompt). Machine-level settings like your telemetry choice are preserved, a source checkout is never touched, and the new --keep-cli flag restores the old configs-only behavior. (#1071)
  • codegraph_explore no longer lets ordinary English words in a natural-language question hijack the ranking when they happen to match a code symbol's name. A question like "how does the upgrade flow check the latest version" used to treat "check" as a symbol the agent asked for by name, rank that unrelated definition's file first, and crowd the files the question is actually about out of the answer entirely. Precisely written symbol names (camelCase, PascalCase, snake_case, qualified names) still get top billing exactly as before, as do plain-word symbol bags whose words belong together in the same file.
  • PHP method calls made through a class property — $this->dep->method(), the dominant call shape in constructor-injection codebases (Symfony, Laravel) — now resolve to the method on the property's declared type, so callers and impact analysis see production call sites instead of reporting a DI-heavy method as uncalled or test-only. Promoted constructor parameters, typed properties, classic constructor assignment (including multi-line signatures), and typed setter injection all count; interface-typed properties resolve to the interface method, and inherited methods resolve through the type hierarchy. Only property-shaped declarations are consulted — a same-named local variable or parameter elsewhere can never mistype the property — and a property whose type can't be recovered statically stays unlinked rather than guessed. Thanks @w0lan. (#1220)
  • codegraph upgrade now also refreshes what previous versions installed into your agents — the CodeGraph section in CLAUDE.md / AGENTS.md / GEMINI.md and the MCP entry — so upgrading no longer leaves agents following instructions written for tools that have since been renamed or removed. Refresh-only: agents you never configured are not touched, and your permission and hook choices are preserved. Also available manually as codegraph install --refresh, and skippable with CODEGRAPH_NO_INSTALL_REFRESH=1. (#1238)
  • codegraph upgrade on an npm install now upgrades through npm again instead of quietly creating a second copy that never wins the PATH race — previously codegraph --version kept reporting the old version forever, no matter how many times you upgraded. (#1238)
  • After every upgrade, CodeGraph now checks that the codegraph command your terminal resolves actually serves the freshly installed version — confirming you don't need a new terminal, or telling you exactly which stale install is shadowing the new one. (#1071)
  • The safety watchdog no longer kills a healthy index on severely degraded storage. It used to judge liveness purely by the event loop, so one long database write on a struggling disk looked identical to a hung process and could get a valid, in-progress index terminated. During codegraph index/codegraph init the watchdog now also checks whether the index files on disk are advancing before it acts: slow-but-progressing work is left alone (bounded by a hard cap), while a genuinely hung process is still killed exactly as fast as before. (#1231)
  • Incremental sync now picks up cross-file relationships that only become resolvable after an edit — for example, when a file gains an export that another, unchanged file was already importing or calling. Previously the reference in the unchanged file was never revisited, so callers, impact, and flow results silently omitted the new edge (while status reported a clean index) until a full re-index. References that can't be resolved yet are now remembered and automatically retried whenever a change introduces a symbol that could satisfy them — this also covers a class gaining a new method that other files already call. Thanks @loadcosmos for the report with a minimal reproduction. (#1240)
  • The reverse case is fixed too: when an edit removes or moves a symbol (or deletes its file), callers in unchanged files now re-resolve during the same sync — rebinding to the symbol's new home when it moved, or waiting to reconnect automatically when it comes back — instead of silently losing their relationship until a full re-index. (#1240)
