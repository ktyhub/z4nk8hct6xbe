codegraphe v1.3.0

[1.3.0] - 07/07/2026

Nouvelles fonctionnalités

  • CodeGraph indexe désormais Nix (.nix) — les flocons, les modules NixOS et home-manager, les superpositions et les ensembles de packages rejoignent le graphique : les liaisons let et attrset, les fonctions ({ pkgs, ... } simples, déstructurées et curry) et les liaisons inherit deviennent toutes des symboles consultables, avec des bords d'appel entre les liaisons. Le câblage au niveau des fichiers suit la manière dont Nix connecte réellement les fichiers : import ./relative/path.nix (avec import ./dir atteignant le default.nix du répertoire), les listes imports = [ ./hardware.nix ../common ] du module NixOS, les listes modules = [ ./configuration.nix ] de style flocon et l'idiome nixpkgs callPackage ./pkgs/foo { } - donc "qu'est-ce que cette configuration tire réellement" et "qu'est-ce qui utilise ce module" sont responsables sur les configurations réelles. Les références dynamiques (import <nixpkgs>, chemins variables, références de module d'entrée en flocon) sont délibérément laissées sans lien plutôt que devinées. Merci @TyceHerrman. (#324, #332, #648)
  • Le câblage des options du système de modules NixOS est ponté, de sorte que les questions de flux traversent les limites du module au lieu de s'y éteindre : une écriture de configuration comme launchd.user.agents.myapp = { ... } ou home.file.".gitconfig" = { ... } est liée au module qui déclare cette option (options.launchd.user.agents = mkOption { ... } - les orthographes de déclaration plates et imbriquées comptent toutes les deux, les clés entre guillemets comme system.defaults.NSGlobalDomain."com.apple.dock" correspondent à leur déclaration exacte), ce qui permet de tracer "comment l'activation de ce service produit le démon launchd / le fichier de configuration généré" de bout en bout et "ce qui définit cette option" responsable à travers les modules, tests inclus. La précision est délibérément conservatrice : les chemins ${...} interpolés, les options déclarées dans plus d'un module et les espaces de noms d'options internes aux sous-modules restent non liés plutôt que devinés, et chaque saut ponté est étiqueté comme câblage heuristique module-système plutôt que présenté comme une référence simple.
  • CodeGraph indexe désormais ArkTS (.ets) — le langage des applications HarmonyOS/OpenHarmony. Tout ce que TypeScript est extrait (classes, interfaces, énumérations, alias de type, importations/exportations, bords d'appel), plus les propres constructions d'ArkTS : les structures @Component / @ComponentV2 avec leurs décorateurs (@Entry, @State, @Prop, @Link, @Local, @Param, …) capturées et consultables, build() affiche les arborescences liées parent → enfant afin que « quelles pages restituent ce composant » soient responsables, les attributs enchaînés connectés aux fonctions @Extend/@Styles qu'ils invoquent, les méthodes et fonctions @Builder câblées dans le graphe d'appel et les liaisons d'événements de style .onClick(this.handler) liées à leurs méthodes de gestionnaire. Les projets modulaires HarmonyOS résolvent également au-delà des limites des modules : un import { CartRepository } from "data" nu suit la dépendance oh-package.json5 file: vers le bon module - honorant l'entrée main déclarée de chaque module, par les consommateurs .ets et .ts - tandis que les noms ambigus dans les monorepos multi-applications restent délibérément non liés plutôt que devinés, et les bases de code mixtes .ets/.ts se croisent librement. Validé sur de vraies applications HarmonyOS, y compris le monorepo d'échantillons officiels OpenHarmony. (#396, #512, #648, #890)
  • Les sauts dynamiques d'ArkUI sont pontés afin que les questions de flux les traversent au lieu de devenir sombres, chacune étant étiquetée comme une répartition dynamique plutôt que affichée comme un simple appel : les méthodes qui attribuent une propriété réactive (@State, @Local, …) sont liées au build() du composant (le saut de re-rendu - contrôlé par l'affectation, donc une méthode qui lit simplement l'état n'obtient aucun avantage) ; emitter.emit(eventId) est lié à l'abonné emitter.on/once correspondant lorsque les deux côtés partagent une clé d'événement récupérable de manière statique (les identifiants numériques sont associés dans un seul fichier, nommés constantes dans un module, de sorte que les échantillons non liés dans un monorepo ne se lient jamais) ; et router.pushUrl({ url: 'pages/Detail' }) renvoie à la structure @Entry de la page cible, avec des URL ambiguës non liées plutôt que devinées.
  • L'indexation interrompue ou incomplète est désormais visible au lieu d'être silencieuse : une exécution interrompue au milieu de l'index (plantage, manque de mémoire, chien de garde) laisse un marqueur que codegraph status rapporte comme un index tronqué, une exécution terminée qui a supprimé des fichiers se signale comme partielle - à la fois dans la sortie humaine et dans status --json - et codegraph index imprime un avertissement avec le nombre exact lorsque son résultat ne correspond pas à ce que l'analyse a découvert.
  • CodeGraph indexe désormais Terraform et OpenTofu (.tf, .tfvars, .tofu) — les ressources, sources de données, modules, variables, sorties, fournisseurs et chaque attribut locals deviennent des symboles (par exemple aws_s3_bucket.my_bucket, var.region, module.vpc, local.prefix) et utilise comme var.region, module.vpc.id, data.aws_caller_identity.current ou aws_s3_bucket.my.arn sont câblés entre fichiers, de sorte que les requêtes de recherche, d'appelants et d'impact renvoient des résultats réels sur les dépôts d'infrastructure au lieu de rien. Les appels de module traversent les limites du module : les entrées d'un bloc module sont liées aux variables du module enfant, module.vpc.vpc_id atteint la définition output "vpc_id" de l'enfant et le chemin local source du bloc est lié aux fichiers du module - donc "qu'est-ce qui se casse si je change la variable de ce module" atteint chaque appelant au lieu de se retrouver dans une impasse lors de la déclaration (les sources du registre et de git sont délibérément laissées comme des limites visibles plutôt que devinées). Le câblage inter-composants via le module cloudposse/atmos remote-state se connecte également : module.vpc.outputs.vpc_cidr dans un composant atteint la propre sortie du composant vpc lorsque le nom du composant est déclaré statiquement (un littéral ou une variable avec une valeur littérale par défaut) et qu'exactement un répertoire correspond - tout ce qui est dynamique ou ambigu reste sans lien. Les fournisseurs d'alias sont de première classe : provider "aws" { alias = "east" } obtient son propre symbole, et provider = aws.east sur une ressource (ou la carte providers d'un module) renvoie à cette configuration, a trouvé l'arborescence du module de la même manière que Terraform en hérite réellement. Les blocs de migration d'état moved/import/removed et les assertions check font référence aux ressources qu'ils nomment, donc la trace écrite d'un refactor fait partie du graphique. Les affectations .tfvars sont liées aux variables qu'elles définissent, y compris les fichiers var conservés dans un sous-répertoire. La résolution suit la portée réelle par répertoire de Terraform, de sorte que les variables du même nom dans les modules ne se lient jamais et "ce qui dépend de var.project_id" dans un dépôt multi-modules ne se mélange jamais à des modules non liés. Merci @Javviviii2. (#83, #310, #648)
  • CodeGraph indexe désormais CUDA (.cu, .cuh) — les noyaux, les fonctions de périphérique/hôte, les structures et les classes deviennent des symboles, et le bord de l'appel hôte → noyau survit à la syntaxe de lancement <<<grid, block>>>, donc des questions telles que « comment cet appel atteint-il le noyau GPU ? tracez à travers la limite CPU/GPU au lieu de devenir sombre sur le site de lancement. Les styles de lancement du monde réel sont tous connectés : lancements basés sur un modèle (my_kernel<Traits, 256><<<grid, block>>>(args)), lancements via un pointeur de fonction local (auto kernel = &my_kernel<...>; ... kernel<<<grid, block>>>(args) - chaque cible attribuée à une branche est liée), configurations de lancement initialisées par accolade (<<<dim3{1,1,1}, dim3{256,1,1}>>>) et noyaux définis via une macro de nom dans le premier argument (style DEFINE_FLASH_FORWARD_KERNEL(kernel_name, ...) { ... } de flash-attention), qui sont désormais indexés sous leurs vrais noms de noyau. CUDA qui se trouve dans les en-têtes simples .h/.hpp – où se trouve une grande partie du code de périphérique du monde réel, y compris les en-têtes de modèle de lancement – ​​est reconnu par le contenu et indexé de la même manière. Validé sur llm.c, flash-attention et NVIDIA CUTLASS. (#387, #648)
  • Les symboles C++ définis dans les blocs namespace portent désormais l'espace de noms dans leur nom qualifié (flash::compute_attn, C++17 namespace a::b { inclus), et les appels qualifiés par l'espace de noms (ns::fn(...)) sont résolus selon leurs définitions - auparavant, ces appels n'étaient jamais liés du tout, ce qui cachait une grande partie du graphe d'appel dans les bases de code C++ riches en espaces de noms aux appelants et à l'analyse d'impact.
  • Les appels C++ qui énoncent les arguments du modèle (fn<T, 256>(args)) sont désormais liés à la fonction qu'ils instancient, les mêmes classes de base basées sur un modèle de normalisation avaient déjà.
  • CodeGraph indexe désormais Solidity (.sol) — les contrats, bibliothèques, interfaces, structures, énumérations, modificateurs, événements, erreurs et variables d'état deviennent des symboles de première classe, avec des bords d'appel qui suivent emit, revert, des gardes de modificateurs (style onlyOwner, y compris des chaînes de constructeurs de base comme constructor() ERC20(...)) et des appels de bibliothèque/méthode (y compris les directives using). Les directives import résolvent le fichier importé, donc des questions croisées telles que « retracer transferFrom via les mises à jour des allocations et du solde » ou « Comment onlyRole atteint-il le stockage de rôle ? » travaillez immédiatement sur de vraies bases de code Solidity (validées sur les contrats solmate, solady et OpenZeppelin). Merci @naiba. (#374, #648)
  • La répartition du comportement Erlang est désormais suivie à travers le graphique : un appel de framework via un module variable - les plis Handler:init/Middleware:execute d'un cowboy, le Mod:callback(...) d'un gestionnaire de plugins - sont liés aux implémentations du référentiel du comportement qui déclare ce rappel, donc les traces de flux et l'impact traversent la limite de rappel OTP au lieu de s'y arrêter. Les liens sont déterminés avec précision : l'arité de rappel doit correspondre, exactement un comportement peut posséder cette forme de rappel (une collision reste non liée plutôt que devinée), l'implémenteur doit réellement exporter le rappel, et la diffusion est limitée - un comportement avec des centaines d'implémenteurs reste une limite visiblement dynamique. Chaque saut ponté est étiqueté comme répartition dynamique avec son site de câblage, jamais affiché comme un simple appel statique.
  • CodeGraph indexe désormais Erlang (.erl, .hrl) — fonctions, avec des clauses et des arités du même nom regroupées sous un seul symbole les couvrant toutes, ainsi que des enregistrements avec leurs champs, des alias -type/-opaque, des macros -define et des signatures -spec attachées à chaque fonction. Les appels mod:fn(...) inter-modules sont résolus en fonction du module cible, les valeurs fun name/arity sont capturées comme références (donc les enregistrements de rappel comme lists:foreach(fun submit/1, ...) sont liés), -include/-include_lib se connectent aux fichiers d'en-tête qu'ils extraient, les déclarations -behaviour lient un module de rappel à son comportement (et uniquement à un module - une macro ou une fonction du même nom ailleurs dans le référentiel ne se trompe jamais pour un), et les listes -export (plus -compile(export_all)) pilotent l'indicateur public/privé de chaque fonction. Les idiomes d'indirection d'OTP sont suivis lorsque la cible est statique : les appels spawn/apply/proc_lib/timer/rpc qui nomment leur cible en tant qu'arguments (Module, Function, Args) produisent des bords d'appel, et gen_server:call/cast se connecte au handle_call/handle_cast du module cible - le sien lors du ciblage. ?MODULE (y compris l'idiome -define(SERVER, ?MODULE)) et le module nommé lorsqu'un nom enregistré suit la convention nom du serveur après son module d'OTP (gen_server:call(other_mod, ...), directement ou via une macro -define(STORE, other_mod)) ; un nom enregistré qui ne correspond à aucun module reste dissocié. Les macros participent également au graphique : les appels d'un corps -define appartiennent à la macro, chaque ?MACRO(...) utilise des liens de site dans la chaîne d'appels (et les lectures nues de ?CONSTANT sont suivies comme références), donc un chemin d'appel caché derrière une macro - set_password → ?SQL_UPSERT_T → sql_query_t - trace de bout en bout et "où cette macro est-elle utilisée" est responsable. les scripts indexent comme n'importe quel module (la ligne shebang est comprise) et les fichiers de ressources d'application OTP (.app.src, .app) rejoignent le graphique : {mod, ...} relie une application à son module de rappel et {applications, [...]} connecte les applications sœurs parapluie - en se résolvant uniquement en modules, donc un nom d'application OTP comme ssl n'est jamais confondu avec une fonction du même nom. La répartition véritablement dynamique (Mod:handle(...), envois de messages, apparitions de modules var) est délibérément laissée sans lien plutôt que devinée. codegraph_explore comprend également l'orthographe des symboles natifs d'Erlang dans les requêtes : mod:fn/3 et init/2 trouvent les symboles qu'ils nomment. (#635, #648)
  • CodeGraph indexe désormais Visual Basic .NET (.vb) — classes, modules, interfaces, structures, énumérations, propriétés, événements, membres abstraits MustOverride et signatures Declare P/Invoke, avec les bords de hiérarchie Inherits/Implements, les bords d'appel (résolus via les parenthèses ambiguës d'appel contre index de VB), et Liens d'instanciation New/As New. Les styles VB du monde réel sont analysés proprement : fichiers de conception WinForms, chaînes interpolées et multilignes, littéraux XML (expressions <%= %> intégrées incluses), requêtes LINQ sur une seule ligne et multilignes, lambdas multilignes, câblage d'événements Handles/WithEvents, événements personnalisés, littéraux de date, identifiants de caractères de type classiques (i%, name$) et les identifiants non anglais (Unicode). (#648, #639, #170)
  • CodeGraph indexe désormais COBOL (.cbl, .cob, .cpy) — programmes, sections et paragraphes avec les bords d'appel PERFORM/GO TO, les appels inter-programmes CALL, les importations de copybooks COPY (copybooks autonomes inclus) et les enregistrements DATA DIVISION avec des noms de conditions de 88 niveaux, au format source fixe et gratuit. Les requêtes d'impact fonctionnent sur les éléments de données : chaque site d'écriture MOVE/ADD/COMPUTE/SUBTRACT renvoie au champ qu'il modifie, donc "ce qui touche ce champ de cahier" répond dans tous les programmes. Les flux CICS se connectent également : les cibles de programme EXEC CICS LINK/XCTL, les copybooks EXEC SQL INCLUDE et les sauts pseudo-conversationnels RETURN TRANSID(...) sont résolus vers le programme propriétaire de l'ID de transaction. (#590, #648)
  • CodeGraph indexe désormais CFML (.cfc, .cfm, .cfs) — à la fois le style classique basé sur des balises (<cfcomponent>/<cffunction>) et la syntaxe moderne component { ... } à script nu, y compris extends/implements, les blocs <cfscript> intégrés (à n'importe quelle profondeur d'imbrication, y compris à l'intérieur <cfif>/<cfloop>/<cftry>), les bords d'appel et les appels incorporés dans les expressions #hash# à l'intérieur des corps SQL <cfquery>. Les fichiers enregistrés avec une marque d'ordre d'octet UTF-8 et des balises avec des valeurs d'attribut non citées - toutes deux courantes dans les bases de code CFML de longue durée - sont également gérées. Merci @ghedwards. (#1118)
  • L'héritage CFML écrit sous forme de chemin de composant est désormais lié au bon composant. extends="coldbox.system.web.Controller" nomme son supertype par chemin en pointillés et extends="../base" par chemin relatif (le style FW/1) — tous deux ne produisaient auparavant aucun bord d'héritage, ce qui, sur les applications CFML de style framework, cachait la majeure partie de la hiérarchie des types de l'analyse d'impact et de rayon d'explosion (sur le propre noyau de ColdBox, plus de 90 % de l'héritage était invisible). La résolution est délibérément conservatrice : la disposition du répertoire cible doit corroborer le chemin déclaré - donc un supertype qui vit dans une bibliothèque hors dépôt (testbox, mxunit, un framework installé) reste correctement délié plutôt que d'être deviné, et un chemin ambigu ne produit aucun avantage plutôt qu'un mauvais. (#1152)
  • Les appels de méthode CFML effectués via une variable locale, un argument typé ou une propriété de composant sont désormais résolus en la bonne méthode - la même inférence de type récepteur que les autres langages orientés objet avaient déjà. var svc = new UserService(); svc.save(), createObject("component", "path.UserService"), un paramètre <cfargument> ou cfscript typé et les champs de portée variables./this. - y compris le modèle de pseudoconstructeur (variables.svc = new UserService() dans init()) et les propriétés injectées par WireBox (property name="svc" inject="UserService") - lient tous désormais l'appel à la méthode du composant déclaré, avec des méthodes héritées d'un supertype résolues via l'héritage. liens ci-dessus. Cela permet aux appelants, aux traces d'impact/rayon de souffle et de flux codegraph_explore de suivre les appels de service CFML au lieu de les supprimer ou de deviner parmi les méthodes du même nom.
  • Le hook contextuel Claude Code reconnaît désormais les invites qui décrivent le code en termes simples — dans n'importe quelle langue — en vérifiant les mots de l'invite par rapport aux noms de symboles réellement présents dans l'index de votre projet. En posant des questions sur "la machine à états des commandes", on trouve OrderStateMachine sans aucun mot-clé impliqué. La confiance décide de la quantité injectée : les questions structurelles et les invites à nommer un symbole réel bénéficient toujours d'un contexte complet dès le départ ; une correspondance de mots simples obtient un court pointeur vers les symboles correspondants afin que l'agent les interroge lui-même ; tout le reste reste silencieux, exactement comme avant.
  • La télémétrie d'utilisation anonyme compte désormais la fréquence à laquelle le hook de contexte a injecté du contexte, offert un indice ou est resté silencieux - correction des noms de compteur uniquement ; le contenu de l'invite n'est jamais stocké ni envoyé. Cela rend la précision de l'hameçon mesurable au lieu d'être devinée. Les compteurs enregistrent ce qui s'est réellement passé, pas ce qui a été tenté : une recherche qui échoue ou revient vide compte comme un résultat silencieux distinct, jamais comme un contexte livré (#1143, merci @inth3shadows).
  • Les fichiers Metal shader (.metal) sont désormais indexés. Metal Shading Language est suffisamment proche du C++ pour que les fonctions de sommet/fragment/noyau, les structures, les alias de type et les appels entre eux atterrissent tous dans le graphique — de sorte que les pipelines de shader dans les projets de la plate-forme Apple apparaissent dans l'analyse d'impact et les traces de flux au lieu d'être ignorés en silence. Les annotations d'attribut de style [[buffer(0)]] de Metal sont gérées de manière à ne pas corrompre ce qui est extrait. Merci @FluxKo pour le rapport. (#1121)
  • CodeGraph indexe désormais les anciennes cartes SQL iBatis 2 (<sqlMap>), et pas seulement les fichiers MyBatis 3 <mapper>. Les fragments <select>/<insert>/<update>/<delete>, <statement>/<procedure> d'iBatis et <sql> à l'intérieur d'un <sqlMap> deviennent des symboles d'instruction consultables - pour les cartes avec espace de noms et le style d'identification Map.statement sans espace de noms - et les références <include> se résolvent dans le fragment qu'elles extraient, donc les requêtes de recherche, d'appelants et d'impact renvoient des résultats sur les bases de code iBatis qui ne produisaient auparavant aucun symbole d'instruction. Merci @ESPINS pour le reportage et la reproduction. (#1182)
  • Vous pouvez désormais forcer la source propriétaire gitignorée dans l'index avec une liste include dans codegraph.json. Le cas que cela résout : un projet suivi par un deuxième VCS (SVN, Perforce, …) aux côtés de Git, où une source réelle est engagée dans ce VCS et délibérément répertoriée dans .gitignore afin qu'elle n'atterrisse jamais dans Git — git ne répertorie jamais ces fichiers, donc CodeGraph ne les a jamais indexés, et ni includeIgnored (qui ne fait que relancer les dépôts git intégrés dans un répertoire gitignoré) ni exclude (son ci-contre) pourrait aider. Ajoutez un codegraph.json racine avec, par exemple, { "include": ["Tools/", "Local/typescript/"] } et CodeGraph découvre ces fichiers directement à partir du disque (en remplaçant .gitignore) et les indexe sur l'index complet, le sync incrémentiel et la surveillance des fichiers, sur les projets git et non-git. Les modèles sont de style gitignore et comparés aux chemins relatifs à la racine du projet (un répertoire, un glob ** récursif ou un seul fichier). Un exclude explicite gagne toujours, et les sauts intégrés comme node_modules, dist et .git ne sont jamais réinclus. Cela complète le exclude existant (son opposé - garder les fichiers suivis out) et le includeIgnored (opter in pour les dépôts intégrés gitignorés).

Correctifs

  • L'indexation d'un grand monorepo Java ou Kotlin Spring est considérablement plus rapide. La phase de résolution de référence – la majeure partie d'un premier codegraph index – pourrait durer près d'une heure sur un grand projet multi-modules et se termine désormais en quelques minutes, produisant le même graphique. La cause : chaque appel receiver.method() dans la base de code analysait à plusieurs reprises l'ensemble des clés de configuration du projet à la recherche d'une correspondance - un travail qui ne s'applique qu'aux liaisons Spring @Value / @ConfigurationProperties, jamais aux appels de méthode ordinaires. Dans le cadre du même correctif, un appel de méthode dont le nom coïncide avec une clé de configuration (par exemple un appel service.process() à côté d'une entrée service.process dans application.yml) n'est plus lié à tort à cette clé de configuration - il est désormais résolu en méthode réelle. Merci @bayernjava pour le rapport. (#1180)
  • codegraph init sur un référentiel parent dont .gitignore exclut ses référentiels enfants, n'indexe plus rien en silence et signale le succès. La disposition "super-repo des dépôts enfants gitignored" - un dépôt Git de niveau supérieur qui .gitignore exécute chaque enfant service-*/ ou packages/* afin que git status reste silencieux - utilisée pour indexer uniquement les quelques fichiers de niveau supérieur du parent et imprimer "Terminé" avec 0 nœuds, même si l'exécution de codegraph init à l'intérieur de n'importe quel enfant a bien fonctionné (CodeGraph respecte .gitignore par défaut, donc les enfants exclus ont été ignorés). Désormais, lorsqu'un index apparaît vide, CodeGraph détecte les référentiels enfants gitignored qui ont été ignorés, les nomme et, dans un terminal interactif, propose de les indexer (en écrivant une entrée includeIgnored dans codegraph.json et en réindexant sur place) ; les exécutions non interactives impriment l'extrait codegraph.json exact à ajouter. Les projets qui conservent légitimement les clones de référence gitignored hors d'un index de travail ne sont jamais harcelés : l'offre n'apparaît que lorsque l'index serait autrement vide. Merci @small-merci pour le rapport. (#1156)
  • Le lecteur de mappage MyBatis est plus robuste sur XML du monde réel. Les valeurs d'attribut entre guillemets simples (id='getById', XML légal et commun dans les anciens mappeurs) ne sont plus ignorées, de sorte que ces instructions apparaissent dans le graphique. Les instructions et les <include> commentés avec <!-- ... --> ne produisent plus de symboles fantômes. Et deux instructions divisées par le fournisseur – le même id avec databaseId="oracle" / databaseId="mysql" – écrites sur une seule ligne ne suppriment plus silencieusement l'une des paires. Merci @ESPINS pour le rapport, les reproductions et les correctifs. (#1182)
  • codegraph init et codegraph index ne sont plus tués par le chien de garde de sécurité à l'étape "Résolution des références" sur les grandes bases de code lourdes en noms de méthodes (les gros monorepos Java/entreprise étaient les principales victimes, en particulier sur les machines plus lentes). Auparavant, la résolution n'était émise que toutes les 500 références, de sorte qu'une série dense de références coûteuses pouvait affamer le chien de garde suffisamment longtemps pour qu'il suppose que le processus était bloqué et tuait un index parfaitement sain. La résolution comporte désormais des points de contrôle après chaque référence, et deux des étapes coûteuses sont devenues beaucoup moins coûteuses : les recherches répétées de méthodes sur le même type sont désormais mises en cache et les fichiers sources ne sont plus redivisés ligne par ligne pour chaque appel résolu - l'indexation de ces dépôts est donc plusieurs fois plus rapide. Les fichiers sur une seule ligne générés ou minifiés sont également ignorés lors de l'inférence de type de récepteur au lieu d'être analysés par appel. Merci @UchihaYong et @wangmeng-95 pour les rapports. (#1122)
  • Un index laissé incomplet par une exécution interrompue se guérit désormais automatiquement lors de la prochaine synchronisation au lieu de rester silencieusement erroné pour toujours. Si l'indexation s'arrêtait à mi-chemin de la résolution des références (un crash, Ctrl-C ou l'arrêt du chien de garde corrigé ci-dessus), les fichiers concernés semblaient toujours indexés mais leurs bords d'appelant/d'impact étaient manquants - un rayon d'explosion trop petit regroupé par package ou module, par ex. une méthode injectée par Spring @Resource signalant 3 de ses 10 fichiers appelants réels - et comme les synchronisations incrémentielles ne résolvent que les fichiers qui ont changé, les dommages étaient permanents jusqu'à une réindexation complète. Toute synchronisation (un changement de fichier surveillé ou un codegraph sync nu) détecte désormais les références restantes et finit de les résoudre, codegraph status avertit lorsqu'un index est dans cet état au lieu de le faire passer pour sain, et un arrêt anticipé rare qui pourrait abandonner la résolution sur les dépôts dont les premiers fichiers ne font référence qu'à des bibliothèques externes est également corrigé. Merci @KnifeOfLife pour le rapport et l'observation de corrélation de packages qui l'ont identifié. (#1187)
  • Le serveur d'arrière-plan partagé ne s'arrête plus sous une session d'éditeur/agent en direct qui n'a tout simplement pas interrogé CodeGraph depuis un certain temps. Un minuteur de sécurité destiné à récolter un serveur abandonné – dont le client avait disparu sans jamais se fermer la connexion – reaping n'importe quel serveur qui n'avait reçu aucune demande pendant 30 minutes, y compris une session parfaitement en direct qui ne demandait tout simplement rien à CodeGraph ; qui a silencieusement abandonné la session (et toutes les autres sessions partageant le même serveur d'arrière-plan) vers un mode de processus plus lent pour le reste de sa vie. Sur une machine pendant une journée, il a tiré 20 fois lors de sessions en direct et n'a détecté aucun véritable fantôme. Le minuteur vérifie désormais si les clients connectés sont réellement toujours en vie et ne récupère que lorsqu'aucun d'entre eux ne l'est, de sorte qu'une session silencieuse mais active conserve son serveur partagé tandis qu'un serveur véritablement abandonné est toujours nettoyé. (#1200)
  • Le serveur d'arrière-plan de CodeGraph ne laisse plus de processus Node persistant lorsque votre éditeur ou agent tue son lanceur au démarrage. Si l'application qui a démarré CodeGraph (Codex, Claude Code ou un autre MCP client) a été supprimée dans la première fraction de seconde du serveur (une sonde de configuration, une requête annulée, un délai de démarrage) tout en gardant les canaux de connexion ouverts, le serveur pourrait être transmis au système avant que son chien de garde de détection d'orphelins n'ait capturé un point de référence, le laissant en cours d'exécution (inactif, ~ 30 Mo) jusqu'à ce que l'application de lancement elle-même se termine ; au cours d'une longue journée de lancements répétés, ceux-ci se sont accumulés. Le serveur enregistre désormais son parent le plus tôt possible, et les lanceurs npm et autonomes lui transmettent l'identifiant de processus de l'hôte réel afin qu'il puisse surveiller l'hôte directement au lieu du seul lanceur qui a peut-être déjà disparu. En guise de dernier filet de sécurité, un serveur qui ne reçoit jamais une seule requête après le démarrage s'arrête désormais au lieu d'attendre la sortie de l'hôte - réglable avec CODEGRAPH_STARTUP_HANDSHAKE_TIMEOUT_MS (0 désactive). Merci @ruslan33321 pour le rapport. (#1185)
  • Le hook contextuel automatique de Claude Code se déclenche désormais pour les questions structurelles posées dans près de trente langues : français, espagnol, portugais, allemand, italien, néerlandais, polonais, tchèque, roumain, hongrois, grec, suédois, danois, norvégien, finnois, russe, ukrainien, turc, indonésien, vietnamien, thaï, hindi, arabe, farsi, hébreu, japonais, coréen et chinois simplifié et traditionnel – au lieu de simplement en anglais et en chinois simplifié. Auparavant, une question naturelle du type "comment marche la state machine des commandes ?" n'a rien injecté à moins qu'il ne contienne un nom de symbole en forme de code, ce qui donne l'impression que le crochet est cassé pour les équipes non anglaises. Les questions en anglais formulées avec des formes de mots dérivées (« expliquer l'architecture… », « quelles sont les dépendances… ») se déclenchent désormais également, et les invites dans toute autre langue se déclenchent toujours lorsqu'elles nomment un symbole de l'index. Merci @anthonyle-roy-lgtm pour le rapport. (#1126)
  • Les appels de méthodes Lua et Luau avec des noms capitalisés (obj:Method() — la convention Roblox standard) sont désormais liés à la bonne méthode. Parce que la syntaxe d'appel de méthode de Lua semble identique à une annotation de type Luau, un appel capitalisé comme lg:Log() a été mal interprété comme déclarant le type de variable, donc chaque fois que deux classes ou plus partageaient un nom de méthode (Init, Update, Destroy, …) l'appel était silencieusement abandonné des appelants, du rayon d'impact/de souffle et des traces de flux. Les noms de méthodes en minuscules n’ont pas été affectés. Merci @inth3shadows pour l'analyse précise des causes profondes et la reproduction. (#1124)
  • Suppression du code mort laissé par la fonctionnalité de raisonnement géré abandonnée. Son flux codegraph login a été débranché avant d'être expédié dans une version, mais le module inutilisé était toujours livré dans les packages de plate-forme, et un examen de sécurité a signalé son étape d'ouverture du navigateur Windows (il a acheminé l'URL de connexion via cmd, ce qui aurait été dangereux si le flux avait déjà été câblé). Le module restant et ses tests sont désormais entièrement supprimés. Merci @inth3shadows pour le rapport. (#1114)
  • Le hook contextuel Claude Code ne traite plus les mots anglais ordinaires qui commencent simplement par "call", "trace", "affect" ou "connect" - callus, calligraphy, Connecticut, connective, affectate, Tracey - comme des questions structurelles, qui injectaient un contexte CodeGraph complet dans des invites qui n'avaient rien à voir avec la structure du code. Les formes véritablement structurelles (appels, appelants, rappels, site d'appel, tracés, traçage, affectés, connexions, connectivité, …) se déclenchent toujours exactement comme avant. Merci @inth3shadows pour le rapport. (#1138)
  • Une commande git bloquée ne peut plus bloquer CodeGraph indéfiniment. Le git vérifie la détection de l'arbre de travail et la configuration du git-hook, ainsi que l'étape facultative npm install -g de l'installateur, expirent désormais et échouent gracieusement au lieu de se bloquer pour toujours - cela compte le plus pour le serveur MCP en arrière-plan, où un blocage git illimité (systèmes de fichiers réseau, un fsmonitor coincé) pouvait auparavant le geler suffisamment longtemps pour que le chien de garde de sécurité le tue. Merci @inth3shadows pour le rapport. (#1139)
  • La nouvelle correspondance de mots simples du hook contextuel fonctionne immédiatement sur les projets indexés par une ancienne version de CodeGraph. La recherche de mots sur laquelle il s'appuie est construite au moment de l'index, donc un projet indexé avant la mise à niveau en avait un vide, et le hook ne trouverait rien silencieusement jusqu'à ce que quelque chose d'autre se produise pour actualiser l'index ; le hook le remplit désormais lors de la première utilisation (une étape unique - normalement, le rattrapage de démarrage du serveur MCP en arrière-plan arrive en premier). Merci @inth3shadows pour le rapport. (#1142)
  • Plusieurs correctifs de précision dans la correspondance des mots simples : un symbole renommé (par exemple une route NestJS après l'application de son préfixe de module) reste trouvable sous son nouveau nom (#1141) ; un mot qui apparaît uniquement dans votre code en tant que nom de package d'une instruction d'importation n'est plus présenté comme un symbole correspondant (#1144) ; les mots au pluriel ne génèrent plus de clés de recherche tronquées (« services » ne recherchent plus également « service ») (#1145) ; et un nom correspondant à la fois au singulier et au pluriel d'un mot ne peut plus obtenir une véritable correspondance de deux mots (#1146). Merci @inth3shadows pour les rapports.
  • Les classes Unreal Engine C++ fortement réfléchies ne sont plus supprimées de l'index. Le balisage de réflexion qui décore les membres — UPROPERTY(...), UFUNCTION(...), UCLASS(...), GENERATED_BODY(), UE_DEPRECATED_*(...), DECLARE_DELEGATE_*(...) — sont des appels de macro sans point-virgule que le tree-sitter ne reconnaît pas, donc chacun passe en récupération d'erreur ; dans une grande classe, les erreurs s'accumulent jusqu'à ce que l'ensemble du class_specifier s'effondre et que la classe, sa clause de base et ses membres disparaissent (UCharacterMovementComponent, avec environ 240 macros de ce type, a entièrement disparu, brisant chaque sous-classe/hiérarchie de types et requête de rayon de souffle qui l'a traversé). Ces macros d'annotation de début de ligne sont désormais masquées (en préservant le décalage) avant l'analyse afin que la classe survive. Merci @luoyxy pour le rapport et l'analyse des causes profondes. (suivi #1093)
  • Les membres et méthodes Unreal Engine préfixés par une macro d'exportation/visibilité ne sont plus perdus. La macro *_API ne se trouve pas seulement sur l'en-tête de classe : elle préfixe presque tous les membres exportés d'une grande classe UE (ENGINE_API virtual void Tick(...), static ENGINE_API void AddReferencedObjects(...)) ; l'analyseur lisait la macro comme un jeton de type supplémentaire et chacune de ces déclarations tombait en récupération d'erreur, donc sur les en-têtes comme Actor.h et World.h, des centaines de types de retour se sont accumulés en tant qu'erreurs orphelines et pourraient toujours faire basculer la classe dans l'effondrement. Les macros *_API / *_EXPORT / *_ABI au niveau membre/méthode (Unreal, Qt/Boost, LLVM) sont désormais effacées avant l'analyse, reflétant la récupération d'en-tête de classe existante. (suivi #1093)
  • Les macros d'annotation Unreal Engine qui apparaissent au milieu de la ligne – UMETA(DisplayName=...) d'une valeur d'énumération, UPARAM(ref) d'un paramètre ou une balise de dépréciation insérée dans un alias using (using FOnNetTick UE_DEPRECATED(5.5, "...") = ...;, qui seul a réduit UWorld dans World.h) – sont désormais également supprimées. Ceux-ci se situent dans des positions que la récupération en tête de ligne ne peut structurellement pas atteindre, et un seul pourrait faire tomber l'énumération ou la classe environnante. Ils correspondent à une liste de noms Unreal uniquement (UMETA, UPARAM, UE_DEPRECATED*), donc aucun code standard C++ ou autre bibliothèque n'est affecté. Ensemble, ces trois correctifs récupèrent la classe principale de chaque grand en-tête Unreal Engine testé (Actor, ActorComponent, SkeletalMeshComponent, World, LightComponent, CharacterMovementComponent). (suivi #1093)
  • Un en-tête C++ dont le seul signal C++ est une classe annotée par une macro d'exportation n'est plus détecté à tort comme étant du C — qui avait silencieusement abandonné la classe. Un fichier .h est par défaut C et n'est reclassé en C++ que lorsqu'il affiche une construction spécifique à C++, mais cette vérification n'a pas pu voir à travers une macro d'exportation/visibilité : class ENGINE_API UFoo : public UObject ne correspondait pas au modèle macro-aveugle class Name :, donc un en-tête léger de style Unreal-Engine contenant uniquement GENERATED_BODY() et aucun public: / virtual / explicite. namespace / template a été analysé comme C. L'extracteur C n'émet aucun nœud de classe, donc la classe - et son lien d'héritage - ont disparu du graphique, annulant discrètement la récupération de macro-classe ajoutée dans #1061. L'heuristique de détection C++ reconnaît désormais une déclaration class/struct annotée par macro d'exportation (la même forme #1061 vide avant l'analyse), correspondant à la façon dont class Foo : Bar a déjà été détecté ; le <keyword> <MACRO> <Name> à deux jetons avant un [:{] n'apparaît jamais en C valide, donc les véritables en-têtes C ne sont pas affectés. Merci @luoyxy pour le rapport et l'analyse des causes profondes. (#1133)

codegraph v1.3.0

[1.3.0] - 2026-07-07

New Features

  • CodeGraph now indexes Nix (.nix) — flakes, NixOS and home-manager modules, overlays, and package sets join the graph: let and attrset bindings, functions (simple, destructured { pkgs, ... }, and curried), and inherit bindings all become searchable symbols, with call edges between bindings. File-level wiring follows the ways Nix actually connects files: import ./relative/path.nix (with import ./dir reaching the directory's default.nix), NixOS module imports = [ ./hardware.nix ../common ] lists, flake-style modules = [ ./configuration.nix ] lists, and the nixpkgs callPackage ./pkgs/foo { } idiom — so "what does this configuration actually pull in" and "what uses this module" are answerable on real setups. Dynamic references (import <nixpkgs>, variable paths, flake-input module references) are deliberately left unlinked rather than guessed. Thanks @TyceHerrman. (#324, #332, #648)
  • The NixOS module system's option wiring is bridged, so flow questions cross the module boundary instead of going dark at it: a config write like launchd.user.agents.myapp = { ... } or home.file.".gitconfig" = { ... } links to the module that declares that option (options.launchd.user.agents = mkOption { ... } — flat and nested declaration spellings both count, quoted keys like system.defaults.NSGlobalDomain."com.apple.dock" match their exact declaration), which makes "how does enabling this service produce the launchd daemon / generated config file" traceable end-to-end and "what sets this option" answerable across modules, tests included. Precision is deliberately conservative: interpolated ${...} paths, options declared in more than one module, and submodule-internal option namespaces stay unlinked rather than guessed, and every bridged hop is labeled as heuristic module-system wiring rather than shown as a plain reference.
  • CodeGraph now indexes ArkTS (.ets) — the language of HarmonyOS / OpenHarmony apps. Everything TypeScript gets extracted (classes, interfaces, enums, type aliases, imports/exports, call edges), plus ArkTS's own constructs: @Component / @ComponentV2 structs with their decorators (@Entry, @State, @Prop, @Link, @Local, @Param, …) captured and searchable, build() view trees linked parent→child so "which pages render this component" is answerable, chained attributes connected to the @Extend/@Styles functions they invoke, @Builder methods and functions wired into the call graph, and .onClick(this.handler)-style event bindings linked to their handler methods. Modular HarmonyOS projects resolve across module boundaries too: a bare import { CartRepository } from "data" follows the oh-package.json5 file: dependency to the right module — honoring each module's declared main entry, from .ets and .ts consumers alike — while ambiguous names in multi-app monorepos deliberately stay unlinked rather than guessed, and mixed .ets/.ts codebases cross-link freely. Validated on real HarmonyOS apps including the official OpenHarmony samples monorepo. (#396, #512, #648, #890)
  • ArkUI's dynamic hops are bridged so flow questions cross them instead of going dark, each labeled as dynamic dispatch rather than shown as a plain call: methods that assign a reactive property (@State, @Local, …) link to the component's build() (the re-render hop — assignment-gated, so a method that merely reads state gets no edge); emitter.emit(eventId) links to the matching emitter.on/once subscriber when both sides share a statically-recoverable event key (numeric ids pair within one file only, named constants within one module, so unrelated samples in a monorepo never cross-link); and router.pushUrl({ url: 'pages/Detail' }) links to the target page's @Entry struct, with ambiguous urls left unlinked rather than guessed.
  • Interrupted or incomplete indexing is now visible instead of silent: a run killed mid-index (crash, out-of-memory, watchdog) leaves a marker that codegraph status reports as a truncated index, a completed run that dropped files reports itself as partial — both in the human output and in status --json — and codegraph index prints a warning with the exact counts when its result doesn't add up to what the scan discovered.
  • CodeGraph now indexes Terraform and OpenTofu (.tf, .tfvars, .tofu) — resources, data sources, modules, variables, outputs, providers, and every locals attribute become symbols (e.g. aws_s3_bucket.my_bucket, var.region, module.vpc, local.prefix), and uses like var.region, module.vpc.id, data.aws_caller_identity.current, or aws_s3_bucket.my.arn are wired up cross-file, so search, callers, and impact queries return real results on infrastructure repos instead of nothing. Module calls are bridged across the module boundary: a module block's inputs link to the child module's variables, module.vpc.vpc_id reaches the child's output "vpc_id" definition, and the block's local source path links to the module's files — so "what breaks if I change this module's variable" reaches every caller instead of dead-ending at the declaration (registry and git sources are deliberately left as visible boundaries rather than guessed). Cross-component wiring through the cloudposse/atmos remote-state module connects too: module.vpc.outputs.vpc_cidr in one component reaches the vpc component's own output when the component name is statically declared (a literal, or a variable with a literal default) and exactly one directory matches — anything dynamic or ambiguous stays unlinked. Aliased providers are first-class: provider "aws" { alias = "east" } gets its own symbol, and provider = aws.east on a resource (or a module's providers map) links to that configuration, found up the module tree the way Terraform actually inherits it. moved/import/removed state-migration blocks and check assertions reference the resources they name, so a refactor's paper trail is part of the graph. .tfvars assignments link to the variables they set, including var-files kept in a subdirectory. Resolution follows Terraform's real per-directory scoping, so same-named variables across modules never cross-link and "what depends on var.project_id" in a multi-module repo never mixes in unrelated modules. Thanks @Javviviii2. (#83, #310, #648)
  • CodeGraph now indexes CUDA (.cu, .cuh) — kernels, device/host functions, structs, and classes become symbols, and the host→kernel call edge survives the <<<grid, block>>> launch syntax, so questions like "how does this call reach the GPU kernel?" trace across the CPU/GPU boundary instead of going dark at the launch site. Real-world launch styles all connect: templated launches (my_kernel<Traits, 256><<<grid, block>>>(args)), launches through a local function pointer (auto kernel = &my_kernel<...>; ... kernel<<<grid, block>>>(args) — each branch-assigned target linked), brace-initialized launch configs (<<<dim3{1,1,1}, dim3{256,1,1}>>>), and kernels defined through a name-in-first-argument macro (flash-attention's DEFINE_FLASH_FORWARD_KERNEL(kernel_name, ...) { ... } style), which now index under their real kernel names. CUDA that lives in plain .h/.hpp headers — where much real-world device code sits, launch-template headers included — is recognized by content and indexed the same way. Validated on llm.c, flash-attention, and NVIDIA CUTLASS. (#387, #648)
  • C++ symbols defined inside namespace blocks now carry the namespace in their qualified name (flash::compute_attn, C++17 namespace a::b { included), and namespace-qualified calls (ns::fn(...)) resolve to their definitions — previously such calls never linked at all, which hid much of the call graph in namespace-heavy C++ codebases from callers and impact analysis.
  • C++ calls that spell out template arguments (fn<T, 256>(args)) now link to the function they instantiate, the same normalization templated base classes already had.
  • CodeGraph now indexes Solidity (.sol) — contracts, libraries, interfaces, structs, enums, modifiers, events, errors, and state variables become first-class symbols, with call edges that follow emit, revert, modifier guards (onlyOwner-style, including base-constructor chains like constructor() ERC20(...)), and library/method calls (including using directives). import directives resolve to the imported file, so cross-contract questions like "trace transferFrom through allowance and balance updates" or "how does onlyRole reach the role storage?" work out of the box on real Solidity codebases (validated on solmate, solady, and OpenZeppelin Contracts). Thanks @naiba. (#374, #648)
  • Erlang behaviour dispatch is now followed through the graph: a framework call through a variable module — cowboy's Handler:init/Middleware:execute folds, a plugin manager's Mod:callback(...) — links to the repo's implementations of the behaviour that declares that callback, so flow traces and impact cross the OTP callback boundary instead of stopping at it. The links are precision-gated: the callback arity must match, exactly one behaviour may own that callback shape (a collision stays unlinked rather than guessed), the implementer must actually export the callback, and the fan-out is bounded — a behaviour with hundreds of implementers stays a visibly dynamic boundary. Every bridged hop is labeled as dynamic dispatch with its wiring site, never shown as a plain static call.
  • CodeGraph now indexes Erlang (.erl, .hrl) — functions, with clauses and arities of the same name grouped as one symbol spanning all of them, plus records with their fields, -type/-opaque aliases, -define macros, and -spec signatures attached to every function. Cross-module mod:fn(...) calls resolve to the target module's function, fun name/arity values are captured as references (so callback registrations like lists:foreach(fun submit/1, ...) link up), -include/-include_lib connect to the header files they pull in, -behaviour declarations link a callback module to its behaviour (and only ever to a module — a same-named macro or function elsewhere in the repo is never mistaken for one), and -export lists (plus -compile(export_all)) drive each function's public/private flag. OTP's indirection idioms are followed where the target is static: spawn/apply/proc_lib/timer/rpc calls that name their target as (Module, Function, Args) arguments produce call edges, and gen_server:call/cast connects to the target module's handle_call/handle_cast — its own when targeting ?MODULE (including the -define(SERVER, ?MODULE) idiom), and the named module when a registered name follows OTP's name-the-server-after-its-module convention (gen_server:call(other_mod, ...), directly or through a -define(STORE, other_mod) macro); a registered name that matches no module stays unlinked. Macros participate in the graph too: a -define body's calls belong to the macro, each ?MACRO(...) use site links into the call chain (and bare ?CONSTANT reads are tracked as references), so a call path hidden behind a macro — set_password → ?SQL_UPSERT_T → sql_query_t — traces end-to-end and "where is this macro used" is answerable. escripts index like any module (the shebang line is understood), and OTP application resource files (.app.src, .app) join the graph: {mod, ...} links an app to its callback module and {applications, [...]} connects umbrella sibling apps — resolving only ever to modules, so an OTP app name like ssl is never mistaken for a same-named function. Truly dynamic dispatch (Mod:handle(...), message sends, var-module spawns) is deliberately left unlinked rather than guessed. codegraph_explore also understands Erlang-native symbol spelling in queries — mod:fn/3 and init/2 find the symbols they name. (#635, #648)
  • CodeGraph now indexes Visual Basic .NET (.vb) — classes, Modules, interfaces, structures, enums, properties, events, MustOverride abstract members, and Declare P/Invoke signatures, with Inherits/Implements hierarchy edges, call edges (resolved through VB's ambiguous call-vs-index parentheses), and New/As New instantiation links. Real-world VB styles parse cleanly: WinForms designer files, interpolated and multi-line strings, XML literals (embedded <%= %> expressions included), single-line and multi-line LINQ queries, multi-line lambdas, Handles/WithEvents event wiring, Custom Events, date literals, classic type-character identifiers (i%, name$), and non-English (Unicode) identifiers. (#648, #639, #170)
  • CodeGraph now indexes COBOL (.cbl, .cob, .cpy) — programs, sections and paragraphs with PERFORM/GO TO call edges, CALL cross-program calls, COPY copybook imports (standalone copybooks included), and DATA DIVISION records with 88-level condition names, in both fixed and free source format. Impact queries work on data items: every MOVE/ADD/COMPUTE/SUBTRACT write-site links back to the field it changes, so "what touches this copybook field" answers across programs. CICS flows connect too: EXEC CICS LINK/XCTL program targets, EXEC SQL INCLUDE copybooks, and pseudo-conversational RETURN TRANSID(...) hops resolve to the program owning the transaction id. (#590, #648)
  • CodeGraph now indexes CFML (.cfc, .cfm, .cfs) — both the classic tag-based style (<cfcomponent>/<cffunction>) and modern bare-script component { ... } syntax, including extends/implements, embedded <cfscript> blocks (at any nesting depth, including inside <cfif>/<cfloop>/<cftry>), call edges, and calls embedded in #hash# expressions inside <cfquery> SQL bodies. Files saved with a UTF-8 byte-order mark and tags with unquoted attribute values — both common in long-lived CFML codebases — are handled too. Thanks @ghedwards. (#1118)
  • CFML inheritance written as a component path now links to the right component. extends="coldbox.system.web.Controller" names its supertype by dotted path and extends="../base" by relative path (the FW/1 style) — both previously produced no inheritance edge at all, which on framework-style CFML apps hid most of the type hierarchy from impact and blast-radius analysis (on ColdBox's own core, over 90% of inheritance was invisible). Resolution is deliberately conservative: the target's directory layout must corroborate the declared path — so a supertype that lives in an out-of-repo library (testbox, mxunit, an installed framework) correctly stays unlinked rather than being guessed at, and an ambiguous path produces no edge rather than a wrong one. (#1152)
  • CFML method calls made through a local variable, typed argument, or component property now resolve to the right method — the same receiver-type inference the other object-oriented languages already had. var svc = new UserService(); svc.save(), createObject("component", "path.UserService"), a typed <cfargument> or cfscript parameter, and variables./this.-scoped fields — including the pseudoconstructor pattern (variables.svc = new UserService() in init()) and WireBox-injected properties (property name="svc" inject="UserService") — all now link the call to the declared component's method, with methods inherited from a supertype resolved through the inheritance links above. This makes callers, impact/blast-radius, and codegraph_explore flow traces follow CFML service calls instead of dropping them or guessing among same-named methods.
  • The Claude Code context hook now recognizes prompts that describe code in plain words — in any language — by checking the prompt's words against the symbol names actually in your project's index. Asking about "the state machine des commandes" finds OrderStateMachine with no keyword involved. Confidence decides how much gets injected: structural questions and prompts naming a real symbol still get full context up front; a plain-words match gets a short pointer to the matching symbols so the agent queries them itself; everything else stays silent, exactly as before.
  • Anonymous usage telemetry now counts how often the context hook injected context, offered a hint, or stayed silent — fixed counter names only; the prompt's content is never stored or sent. This makes the hook's accuracy measurable instead of guessed. The counters record what actually happened, not what was attempted: a lookup that errors or comes back empty counts as a distinct silent outcome, never as delivered context (#1143, thanks @inth3shadows).
  • Metal shader files (.metal) are now indexed. Metal Shading Language is close enough to C++ that vertex/fragment/kernel functions, structs, type aliases, and the calls between them all land in the graph — so shader pipelines in Apple-platform projects show up in impact analysis and flow traces instead of being silently skipped. Metal's [[buffer(0)]]-style attribute annotations are handled so they can't corrupt what gets extracted. Thanks @FluxKo for the report. (#1121)
  • CodeGraph now indexes legacy iBatis 2 SQL maps (<sqlMap>), not just MyBatis 3 <mapper> files. <select>/<insert>/<update>/<delete>, iBatis's <statement>/<procedure>, and <sql> fragments inside a <sqlMap> become searchable statement symbols — for both namespaced maps and the namespace-less Map.statement id style — and <include> references resolve to the fragment they pull in, so search, callers, and impact queries return results on iBatis codebases that previously produced no statement symbols at all. Thanks @ESPINS for the report and the reproduction. (#1182)
  • You can now force gitignored first-party source into the index with an include list in codegraph.json. The case this solves: a project tracked by a second VCS (SVN, Perforce, …) alongside Git, where some real source is committed to that VCS and deliberately listed in .gitignore so it never lands in Git — git never lists those files, so CodeGraph never indexed them, and neither includeIgnored (which only revives embedded git repositories inside a gitignored directory) nor exclude (its opposite) could help. Add a root codegraph.json with, e.g., { "include": ["Tools/", "Local/typescript/"] } and CodeGraph discovers those files directly off disk — overriding .gitignore — and indexes them on the full index, incremental sync, and file-watching, on both git and non-git projects. Patterns are gitignore-style and matched against project-root-relative paths (a directory, a recursive ** glob, or a single file). An explicit exclude still wins, and built-in skips like node_modules, dist, and .git are never re-included. This complements the existing exclude (its opposite — keep tracked files out) and includeIgnored (opt in to gitignored embedded repos).

Fixes

  • Indexing a large Java or Kotlin Spring monorepo is dramatically faster. The reference-resolution phase — the bulk of a first-time codegraph index — could run for the better part of an hour on a big multi-module project and now finishes in a few minutes, producing the same graph. The cause: every receiver.method() call in the codebase was repeatedly scanning the project's entire set of configuration keys looking for a match — work that only ever applies to Spring @Value / @ConfigurationProperties bindings, never to ordinary method calls. As part of the same fix, a method call whose name coincides with a configuration key (say a service.process() call alongside a service.process entry in application.yml) is no longer mislinked to that config key — it now resolves to the actual method. Thanks @bayernjava for the report. (#1180)
  • codegraph init at a parent repository whose .gitignore excludes its child repositories no longer silently indexes nothing and reports success. The "super-repo of gitignored child repos" layout — a top-level Git repo that .gitignores each service-*/ or packages/* child so git status stays quiet — used to index only the parent's few top-level files and print "Done" with 0 nodes, even though running codegraph init inside any child worked fine (CodeGraph respects .gitignore by default, so the excluded children were skipped). Now, when an index comes up empty, CodeGraph detects the gitignored child repositories that were skipped, names them, and — in an interactive terminal — offers to index them (writing an includeIgnored entry to codegraph.json and re-indexing on the spot); non-interactive runs print the exact codegraph.json snippet to add. Projects that legitimately keep gitignored reference clones out of a working index are never nagged: the offer only appears when the index would otherwise be empty. Thanks @small-thanks for the report. (#1156)
  • The MyBatis mapper reader is sturdier on real-world XML. Single-quoted attribute values (id='getById', legal XML and common in older mappers) are no longer skipped, so those statements make it into the graph. Statements and <include>s that were commented out with <!-- ... --> no longer produce phantom symbols. And two vendor-split statements — the same id with databaseId="oracle" / databaseId="mysql" — written on a single line no longer silently drop one of the pair. Thanks @ESPINS for the report, the reproductions, and the fixes. (#1182)
  • codegraph init and codegraph index no longer get killed by the safety watchdog at the "Resolving refs" step on large method-name-heavy codebases (big Java/enterprise monorepos were the main victims, especially on slower machines). Resolution used to come up for air only every 500 references, so a dense stretch of expensive ones could starve the watchdog long enough for it to assume the process was stuck and kill a perfectly healthy index. Resolution now checkpoints after every reference, and two of the expensive steps got much cheaper: repeated method lookups on the same type are now cached, and source files are no longer re-split line-by-line for every call being resolved — indexing such repos is several times faster as a result. Generated or minified single-line files are also skipped during receiver-type inference instead of being scanned per call. Thanks @UchihaYong and @wangmeng-95 for the reports. (#1122)
  • An index left incomplete by an interrupted run now heals itself on the next sync instead of silently staying wrong forever. If indexing died partway through resolving references (a crash, Ctrl-C, or the watchdog kill fixed above), the affected files still looked indexed but their caller/impact edges were missing — a too-small blast radius clustering by package or module, e.g. a Spring @Resource-injected method reporting 3 of its 10 real caller files — and because incremental syncs only re-resolve files that changed, the damage was permanent until a full re-index. Any sync (a watched file change, or a bare codegraph sync) now detects the leftover references and finishes resolving them, codegraph status warns when an index is in that state instead of passing it off as healthy, and a rare early-stop that could abandon resolution on repos whose first files reference only external libraries is fixed too. Thanks @KnifeOfLife for the report and the package-correlation observation that pinned it down. (#1187)
  • The shared background server no longer shuts down out from under a live editor/agent session that simply hasn't queried CodeGraph in a while. A safety timer meant to reap an abandoned server — one whose client vanished without the connection ever closing — was reaping any server that saw no requests for 30 minutes, including a perfectly live session that just wasn't asking CodeGraph anything; that silently dropped the session (and every other session sharing the same background server) to a slower in-process mode for the rest of its life. On one machine over a day it fired 20 times on live sessions and caught zero real phantoms. The timer now checks whether the connected clients are actually still alive and only reaps when none of them are, so a quiet-but-live session keeps its shared server while a genuinely abandoned one is still cleaned up. (#1200)
  • CodeGraph's background server no longer leaves a lingering Node process behind when your editor or agent kills its launcher during startup. If the app that started CodeGraph (Codex, Claude Code, or another MCP client) was killed within the server's first fraction of a second — a config probe, a cancelled request, a startup timeout — while keeping the connection's pipes open, the server could be handed off to the system before its orphan-detection watchdog had captured a reference point, leaving it running (idle, ~30 MB) until the launching app itself exited; over a long day of repeated launches these accumulated. The server now records its parent at the earliest possible moment, and the npm and standalone launchers pass the real host's process id down to it so it can watch the host directly instead of only the launcher that may already be gone. As a final backstop, a server that never receives a single request after starting now shuts itself down instead of waiting for the host to exit — tunable with CODEGRAPH_STARTUP_HANDSHAKE_TIMEOUT_MS (0 disables). Thanks @ruslan33321 for the report. (#1185)
  • The automatic context hook for Claude Code now fires for structural questions asked in nearly thirty languages — French, Spanish, Portuguese, German, Italian, Dutch, Polish, Czech, Romanian, Hungarian, Greek, Swedish, Danish, Norwegian, Finnish, Russian, Ukrainian, Turkish, Indonesian, Vietnamese, Thai, Hindi, Arabic, Farsi, Hebrew, Japanese, Korean, and both simplified and traditional Chinese — instead of just English and simplified Chinese. Previously a natural question like "comment marche la state machine des commandes ?" injected nothing unless it happened to contain a code-shaped symbol name, making the hook look broken for non-English teams. English questions phrased with derived word forms ("explain the architecture…", "what are the dependencies…") now fire too, and prompts in any other language still fire when they name a symbol from the index. Thanks @anthonyle-roy-lgtm for the report. (#1126)
  • Lua and Luau method calls with capitalized names (obj:Method() — the standard Roblox convention) now link to the right method. Because Lua's method-call syntax looks identical to a Luau type annotation, a capitalized call like lg:Log() was misread as declaring the variable's type, so whenever two or more classes shared a method name (Init, Update, Destroy, …) the call was silently dropped from callers, impact/blast-radius, and flow traces. Lowercase method names were unaffected. Thanks @inth3shadows for the precise root-cause analysis and repro. (#1124)
  • Removed dead code left behind by the discontinued managed-reasoning feature. Its codegraph login flow was unplugged before ever shipping in a release, but the unused module still shipped inside the platform bundles, and a security review flagged its Windows browser-open step (it routed the login URL through cmd, which would have been unsafe had the flow ever been wired back up). The leftover module and its tests are now fully deleted. Thanks @inth3shadows for the report. (#1114)
  • The Claude Code context hook no longer treats ordinary English words that merely start with "call", "trace", "affect", or "connect" — callus, calligraphy, Connecticut, connective, affectionate, Tracey — as structural questions, which used to inject full CodeGraph context into prompts that had nothing to do with code structure. Genuinely structural forms (calls, callers, callbacks, call site, traced, tracing, affected, connections, connectivity, …) still fire exactly as before. Thanks @inth3shadows for the report. (#1138)
  • A stuck git command can no longer hang CodeGraph indefinitely. The git checks behind worktree detection and git-hook setup, and the installer's optional npm install -g step, now time out and fail gracefully instead of blocking forever — this matters most for the background MCP server, where an unbounded git hang (network filesystems, a wedged fsmonitor) could previously freeze it long enough for the safety watchdog to kill it. Thanks @inth3shadows for the report. (#1139)
  • The context hook's new plain-words matching works immediately on projects indexed by an older CodeGraph version. The word lookup it relies on is built at index time, so a project indexed before the upgrade had an empty one, and the hook would silently find nothing until something else happened to refresh the index; the hook now fills it in on first use (a one-time step — normally the background MCP server's startup catch-up gets there first). Thanks @inth3shadows for the report. (#1142)
  • Several accuracy fixes to the plain-words matching: a renamed symbol (for example a NestJS route after its module prefix is applied) stays findable under its new name (#1141); a word that only appears in your code as an import statement's package name is no longer presented as a matched symbol (#1144); plural words no longer generate garbled lookup keys ("services" no longer also looks up "servic") (#1145); and a name matching both the singular and plural of one word can no longer squeeze out a genuine two-word match (#1146). Thanks @inth3shadows for the reports.
  • Heavily-reflected Unreal Engine C++ classes are no longer dropped from the index. Reflection markup that decorates members — UPROPERTY(...), UFUNCTION(...), UCLASS(...), GENERATED_BODY(), UE_DEPRECATED_*(...), DECLARE_DELEGATE_*(...) — are no-semicolon macro calls that tree-sitter doesn't recognize, so each drops into error recovery; in a big class the errors pile up until the whole class_specifier collapses and the class, its base clause, and its members vanish (UCharacterMovementComponent, with ~240 such macros, disappeared entirely, breaking every subclass/type-hierarchy and blast-radius query that went through it). These line-leading annotation macros are now blanked (offset-preserving) before parsing so the class survives. Thanks @luoyxy for the report and root-cause analysis. (#1093 follow-up)
  • Unreal Engine members and methods prefixed by an export/visibility macro are no longer lost. The *_API macro doesn't only sit on the class header — it prefixes almost every exported member of a large UE class (ENGINE_API virtual void Tick(...), static ENGINE_API void AddReferencedObjects(...)); the parser read the macro as an extra type token and each such declaration fell into error recovery, so on headers like Actor.h and World.h hundreds of return types piled up as orphan errors and could still tip the class into collapse. Member/method-level *_API / *_EXPORT / *_ABI macros (Unreal, Qt/Boost, LLVM) are now blanked before parsing, mirroring the existing class-header recovery. (#1093 follow-up)
  • Unreal Engine annotation macros that appear mid-line — an enum value's UMETA(DisplayName=...), a parameter's UPARAM(ref), or a deprecation tag wedged into a using alias (using FOnNetTick UE_DEPRECATED(5.5, "...") = ...;, which alone collapsed UWorld in World.h) — are now stripped too. These sit in positions the line-leading recovery structurally can't reach, and a single one could take down the surrounding enum or class. They are matched by an Unreal-only name list (UMETA, UPARAM, UE_DEPRECATED*) so no standard-C++ or other-library code is affected. Together these three fixes recover the main class of every large Unreal Engine header tested (Actor, ActorComponent, SkeletalMeshComponent, World, LightComponent, CharacterMovementComponent). (#1093 follow-up)
  • A C++ header whose only C++ signal is an export-macro-annotated class is no longer misdetected as C — which had silently dropped the class. A .h file defaults to C and is only reclassified as C++ when it shows a C++-specific construct, but that check couldn't see through an export/visibility macro: class ENGINE_API UFoo : public UObject didn't match the macro-blind class Name : pattern, so a lean Unreal-Engine-style header carrying just GENERATED_BODY() and no explicit public: / virtual / namespace / template was parsed as C. The C extractor emits no class nodes, so the class — and its inheritance link — vanished from the graph, quietly undoing the macro-class recovery added in #1061. The C++ detection heuristic now recognizes an export-macro-annotated class/struct declaration (the same shape #1061 blanks before parsing), matching how class Foo : Bar was already detected; the two-token <keyword> <MACRO> <Name> before a [:{] never occurs in valid C, so genuine C headers are unaffected. Thanks @luoyxy for the report and root-cause analysis. (#1133)
