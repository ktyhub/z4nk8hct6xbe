PaddleOCR v2.7.1

Highlights

  • New recognition and output capabilities — Parseq adds another recognition model (#10836), while character-level coordinates enable finer-grained text extraction (#10515). The new savefile option (#10628) and additional preprocessing controls in ppocr.py (#10217) make it easier to persist results and adapt inference pipelines without custom glue code.

  • Broader accelerator support — ONNX Runtime gains GPU support (#10668), TIPC adds XPU/NPU coverage (#10658, #10460), and MLU inference is introduced (#10249). Teams targeting these devices should validate the relevant backend in their own deployment configuration rather than assuming Paddle GPU behavior transfers unchanged.

  • Modernized dependency compatibility — Support addresses Paddle 2.5’s removal of fluid (#10391), Pillow 10.0 (#10405), and varying fitz versions (#10181). PyYAML is now explicitly listed in requirements.txt (#10653), reducing missing-dependency failures in fresh installations.

  • More reliable batch and long-running inference — Damaged images no longer abort dataset-wide inference (#10216), and sequential PDF recognition no longer inherits the first PDF’s page-count limit (#10290). Memory-leak fixes for C++ inference (#10441) and predict_rec.py (#10688), plus improved strided Tensor.numpy performance (#10773), are especially relevant to sustained production workloads.

  • Training, export, and table-evaluation fixes — Corrected seed propagation (#10614), ABINet export resizing (#10892), ABINet training (#10744), and the PP-OCRv4 distillation config’s KeyError (#10761) reduce reproducibility and pipeline failures. The structure_boxes indexing fix (#10810) corrects table distance/IoU calculations, so prior affected evaluation results should be recomputed.

  • Breaking changes — None identified in this release.
