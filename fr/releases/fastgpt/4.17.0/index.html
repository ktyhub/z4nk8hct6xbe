#FastGPT v4.17.0

Instructions de mise à niveau

**Avant de mettre à niveau vers V4.17.0, veuillez d'abord effectuer une mise à niveau vers V4.16.2 et exécuter tous les anciens scripts de mise à niveau requis par la version V4.16.x. ** Le mécanisme de mise à niveau automatique de V4.17.0 gère uniquement les nouvelles tâches enregistrées à partir de cette version, et ne réexécutera pas les scripts historiques des versions précédentes.

À partir de la version 4.17.0, les tâches enregistrées dans le mécanisme de mise à niveau du système seront automatiquement exécutées et les problèmes de concurrence multi-nœuds seront évités grâce à la préemption du bail. La détection des battements de cœur est également prise en charge pour vérifier si le script est actif. L'état du script de mise à niveau peut être consulté dans 管理员 > 版本升级.

Par défaut, la tâche de migration par lots traite les enregistrements 100 par lot. Lorsque la quantité de données est importante, elle peut être ajustée entre 50~1000 et SYSTEM_MIGRATION_BATCH_SIZE.

Proxy IA (obligatoire)

À partir de la V4.17.0, AI Proxy doit être déployé ou connecté, et défini dans l'application FastGPT et la version commerciale du service Admin qui réutilise la configuration App/Service :

  • AIPROXY_API_ENDPOINT : l'adresse racine du service proxy AI accessible, telle que http://aiproxy:3000, n'ajoute pas /v1.
  • AIPROXY_API_TOKEN : Un token administrateur non vide cohérent avec la configuration du serveur AI Proxy.

**À partir de la version V4.17.0, OPENAI_BASE_URL et CHAT_API_KEY ont été obsolètes et supprimés et ne prendront plus effet après la configuration. ** Veuillez supprimer ces deux variables de l'environnement de déploiement, utilisez plutôt la configuration du proxy AI ci-dessus et conservez l'adresse et la clé du serveur de modèle dans le canal de modèle de l'administrateur. L'ancienne configuration de remplacement systemEnv.oneapiUrl/chatApiKey ne fonctionne plus non plus.

L'absence de configuration AI Proxy entraînera l'échec de la vérification du démarrage et le modèle unique requestUrl/requestAuth ne pourra pas remplacer ces deux éléments requis. Avant la mise à niveau, veuillez confirmer que le proxy AI est accessible et que le jeton d'administrateur peut accéder à l'interface de gestion des canaux ; n'utilisez pas la clé API du fournisseur de services modèles comme jeton d'administrateur AI Proxy.

Défense CSRF

Cette version ajoute un nouvel outil CSRF qui utilise des variables d'environnement pour se défendre contre les balises HTML.

CSRF_ENABLED=true

Configuration compatible Code Sandbox seccomp (facultatif)

Code Sandbox continue d'activer seccomp par défaut. Si le noyau hôte ne prend pas en charge seccomp dans l'application, l'initialisation du pool de processus échouera ; après avoir confirmé que la capacité réduite d'isolation des appels système est acceptable, vous pouvez la définir explicitement pour Code Sandbox :

SANDBOX_DISABLE_SECCOMP=true

Cette configuration désactive uniquement seccomp, chroot, no_new_privs et la privation UID/GID reste activée. Après la fermeture, les appels système tels que le réseau, la création de processus, les threads et l'exécution binaire ne seront plus bloqués depuis la couche noyau. Il n'est pas recommandé de l'utiliser dans un environnement prenant en charge seccomp.

Autorisations de création par défaut pour les nouvelles équipes (facultatif)

Après avoir configuré DEFAULT_TEAM_BASIC_PERMISSIONS_ENABLED=true, lors de la création d'une nouvelle équipe, le groupe par défaut composé de tous les employés se verra accorder des autorisations de création d'application, de compétences et de base de connaissances. La valeur par défaut est false, qui affecte uniquement les nouvelles équipes et ne modifie pas les autorisations des équipes existantes. FastGPT Pro Veuillez conserver cette configuration cohérente dans les services FastGPT et Admin pour couvrir leurs entrées respectives de création d'équipe, y compris la constitution d'équipe autorisée par WeChat d'entreprise.

Instructions de dépréciation

Modèle d'adresse de demande personnalisée

L’adresse de demande personnalisée du modèle sera obsolète dans les versions futures. La version actuelle est toujours compatible. Veuillez le remplacer par un canal de gestion des modèles.

🚀 Nouveau contenu

  1. Le service FastGPT SSO ajoute de nouveaux membres LDAP à synchroniser avec la structure organisationnelle et complète les modèles de variables d'environnement indépendants et les documents de configuration des différents fournisseurs SSO.
  2. Le service FastGPT SSO ajoute de nouveaux utilisateurs DingTalk et synchronise les services.
  3. Le champ de téléchargement de fichiers de Workflow Tool prend en charge les paramètres à générer par l'agent ; le champ du fichier historique conserve toujours le téléchargement manuel par défaut pour éviter les changements de comportement après la mise à niveau.
  4. Ajout de la gestion automatique des tâches de mise à niveau du système, qui vous permet d'afficher l'état de la mise à niveau, la progression de l'étape, les données d'échec et les résultats d'exécution, et de réessayer les tâches non bloquantes ayant échoué.
  5. Agent V2 ajoute une nouvelle configuration de diffusion vocale (TTS), qui prend en charge la diffusion fermée, la diffusion par navigateur ou la diffusion par modèle, et peut sélectionner le timbre, ajuster la vitesse de parole et l'audition ; le style de configuration est cohérent avec Chat Agent.
  6. Le temps de réponse du premier jeton est ajouté aux détails de réponse du nœud de dialogue AI, qui mesure le temps écoulé entre le lancement de la demande de modèle et la réception du premier texte ou contenu de réflexion.
  7. Le transfert des propriétaires d'équipe est étendu au mode multi-équipes, prenant en charge la sélection des membres de l'équipe en tant que nouveaux propriétaires et réduisant le risque de mauvaise opération grâce à la confirmation des entrées.
  8. Défense CSRF pour empêcher les systèmes externes (notamment les balises HTML) de transporter des cookies pour demander directement l'interface.

⚙️ Optimisation

  1. Optimisez l'expérience de pause de conversation : la demande de pause revient immédiatement après l'écriture du point d'arrêt du flux de travail ; une fois que le client a reçu la confirmation, il interrompt activement la demande de streaming en cours et n'attend plus 5 secondes maximum.
  2. Optimiser la rétention du contenu après une pause : le modèle génère uniquement le contenu de réflexion et s'arrête lorsque le texte n'a pas été généré. Il conservera également le contenu de réflexion existant et pourra toujours être consulté après actualisation.
  3. Optimiser l'affichage des citations d'images : lorsque seuls des guillemets sont inclus après l'image, les guillemets sont affichés au centre sous l'image ; les citations en ligne dans le texte conservent la mise en page originale.
  4. Optimiser la récupération des conflits de génération : lorsque la conversation en cours est toujours générée sur le serveur, le client identifiera le conflit et restaurera le flux de génération d'origine pour éviter d'ajouter des messages vides ou des états d'erreur.
  5. Optimisez l'interaction du contenu pendant le traitement : l'aperçu plié des appels de réflexion ou d'outils prend en charge le clic pour développer et localiser directement les détails correspondants.
  6. Application d'atelier unifié, compétence, ensemble de données, marché des modèles, outils, utilisation du compte, tableau de bord du modèle, clé API, journal d'audit et interaction de filtrage de la liste des journaux d'applications ; fournit un filtrage par type, source, créateur, membre, catégorie, heure et tri par page, et prend en charge la recherche dans de longues listes d'options.
  7. Les listes d'applications, de compétences et d'ensembles de données ont ajouté des fonctionnalités de filtrage telles que le tri par créateur et heure de création ; le temps de création des applications et des ensembles de données historiques est automatiquement complété par la tâche de mise à niveau du système.
  8. Unifiez les interactions de base telles que la sélection multiple de tableaux, la plage de dates, la saisie numérique, le défilement de longues listes et les fenêtres contextuelles pour améliorer l'expérience des opérations par lots et de l'affichage de contenu long.
  9. Les listes d'applications, d'ensembles de données et de compétences et les sélecteurs de ressources associés sont remplacés par un chargement paginé, et le défilement virtuel, l'écran squelette de chargement et la navigation dans les dossiers sont optimisés pour améliorer l'expérience de chargement et de navigation lorsqu'un grand nombre de ressources sont utilisées.
  10. Le résumé du modèle, les détails et la liste des candidats sont chargés en fonction des scénarios d'utilisation. Les modèles candidats sont chargés lorsque le sélecteur est développé, et les états de chargement, d'échec de chargement et de modèle indisponible sont distingués.
  11. Logique de description d'outil unifiée : les nœuds d'outils et les sous-outils d'ensemble d'outils utilisent les introductions de nœuds comme descriptions d'appels d'outils ; Les sous-outils de l'ensemble d'outils prennent en charge l'édition directe des descriptions et conservent la personnalisation historique ou le contenu de suppression actif pour éviter d'être écrasés lors de la synchronisation des définitions d'outils.
  12. Le composant tableau prend en charge le défilement séparé de l'en-tête et du contenu, ainsi que le défilement virtuel.

  17. Compatible avec la situation où le nom du membre historique de l'équipe est manquant, l'application questionGuide est null et la référence du modèle de base de connaissances est vide, pour éviter un échec de vérification lors de la lecture d'anciennes données.
  18. Correction de l'affichage anormal des coins arrondis et des chemins des connexions de flux de travail lorsque l'espacement des nœuds est petit, ainsi que du problème selon lequel l'icône par défaut n'est pas utilisée lorsque l'icône du site est configurée comme /.

  20. Correction d'un problème où lors de la conversion d'un tableau HTML en Markdown, le nombre de colonnes d'en-tête était inférieur au nombre de lignes de données, ce qui empêchait certaines colonnes de s'afficher ; l'en-tête du tableau a été automatiquement renseigné lors de la conversion, conservant ainsi le contenu complet du tableau.

🛠️ Optimisation du code

  1. Les modèles système, les autorisations de modèle et les configurations commerciales utilisent la référence stable modelId et sont compatibles avec les anciennes références de nom de modèle via des tâches de mise à niveau automatique.
  2. La tâche de mise à niveau automatique réalise l'exclusion mutuelle multi-nœuds et la prise en charge des échecs via le bail MongoDB, en exécutant l'isolation des ID et le battement de cœur ; les tâches Big Data prennent en charge la continuation des points d'arrêt par lots.
  3. L'interface de requête des collaborateurs peut renvoyer les noms d'utilisateur de connexion des membres de l'équipe à la demande et éviter les requêtes membre par membre via des requêtes par lots.
  4. FastGPT Pro optimise le cache de création d'images de cluster et utilise le cache proxy et le Runner mis en cache pour réduire les frais d'extraction et de création répétés.
  5. Correction de la confusion entre l'adresse d'accès du script de déploiement et la configuration du port hôte. Il prend en charge la configuration indépendante des ports hôtes de FastGPT et Sandbox Proxy pour éviter une utilisation abusive du port réseau public du proxy inverse.
  6. Code Sandbox renvoie la pile d'exceptions, la chaîne d'exceptions et la sortie de console/impression capturée lorsque l'exécution du code JS ou Python échoue, et se connecte au journal de réponse au niveau d'avertissement. Les détails et la sortie des erreurs sont chacun limités à 16 000 caractères, et la troncature est explicitement marquée en cas de dépassement de la limite ; lorsque l'analyse de la réponse du travailleur échoue, l'ID du travailleur, la longueur de la réponse et le stderr capturé sont complétés. Lorsqu'un processus est terminé de force, la sortie qui n'a pas encore été envoyée peut toujours être perdue.

FastGPT v4.17.0

Highlights

  • AI Proxy is mandatory; legacy model env vars removed (breaking) — v4.17.0 requires deploying AI Proxy and setting AIPROXY_API_ENDPOINT (root address, no /v1) plus a non-empty admin AIPROXY_API_TOKEN on both FastGPT App and the commercial Admin service. OPENAI_BASE_URL, CHAT_API_KEY, and the old systemEnv.oneapiUrl/chatApiKey overrides are gone and silently ignored. Startup validation now hard-fails if either variable is missing, and per-model requestUrl/requestAuth can no longer substitute — model URLs and keys live in the admin channel UI instead. Watch out: the token is an AI Proxy admin token, not a model-provider API key; the parallel move to stable modelId references (#7599) is what makes channel-based management work.
  • Staged upgrade path and a self-managing migration engine — Don't jump straight to v4.17.0: first upgrade to v4.16.2 and run every historical 4.16.x script, because the new automatic migration manager (#7651) only registers tasks defined from this release forward — it will not backfill older ones. Registered tasks run automatically with MongoDB lease + run-ID isolation + heartbeat for multi-node mutual exclusion and stale takeover, support batched resume (default 100, tune via SYSTEM_MIGRATION_BATCH_SIZE 50–1000), and expose status/failed rows/retry under Admin → Version Upgrade. Expect startup backfills: modelId references (#7599), resource owner ACLs (#7669), legacy team-role cleanup (#7675), and owner/timestamp fills — snapshot MongoDB before booting.
  • CSRF defense and opt-out seccomp knobs — New CSRF_ENABLED=true defends against third-party HTML tags that ride on stored cookies to hit APIs; enable it if you serve embedded or user-supplied markup. Code Sandbox keeps seccomp on by default; only on kernels that reject in-process seccomp should you set SANDBOX_DISABLE_SECCOMP=true (#7631 adds a load-failure fallback), which stops kernel-level blocking of network/process/thread/binary syscalls while retaining chroot, no_new_privs, and UID/GID drop — accept the weaker isolation deliberately. Sandbox failures now surface stack traces, exception chains, captured console/print output, and 16K-truncated diagnostics; #7624 adds one-shot native isolation for JS.
  • Model references pivot to stable modelId — System models, permissions, and business config move onto immutable modelId references (#7599), with an auto-migration task translating legacy model-name references. Combined with stricter model-type checks in selectors (#7648), schema fixes (#7656), and hardened field mapping that now errors on duplicate targets (#7674), renaming or swapping models stops silently corrupting config. Watch for legacy name references being rewritten on first startup and for previously permissive field mappings that now throw explicit errors.
  • Identity and team provisioning expansion — The SSO service adds LDAP member/organization sync (#7589) and DingTalk user/department sync, each with its own env template and docs, so directory consolidation no longer needs custom glue — plan one provider env file per IdP and verify group-to-team mapping, since these are additive sync paths that can rewrite membership each cycle. Separately, DEFAULT_TEAM_BASIC_PERMISSIONS_ENABLED=true grants default app/Skill/dataset creation rights to newly created teams only (existing teams untouched); on FastGPT Pro set it on both services so every team-creation entry point, including WeCom authorization, is covered.
  • Tool, workflow, and query correctness worth upgrading for — OpenAPI tools now place parameters into Path/Query/Header/JSON Body with style/explode serialization and path-level shared params, and optional cookie params no longer block requests; #7650 persists the manual/Agent input mode and #7661 resolves MCP/HTTP tool schemas at runtime instead of stale workflow snapshots. Workflow Tool file-upload fields can be Agent-generated while historical fields stay manual to avoid behavior shifts (#7618, #7680); pausing returns immediately and aborts the stream client-side (#7635); AI chat nodes surface first-token latency (#7685). For RAG, Milvus BM25 full-text search ships with a mongo→Milvus migration (#7594).

升级说明

升级到 V4.17.0 前，请先升级到 V4.16.2，并执行完成 V4.16.x 版本要求的所有旧升级脚本。 V4.17.0 的自动升级机制只管理从本版本开始登记的新任务，不会补执行此前版本的历史脚本。

从 4.17.0 版本开始，登记到系统升级机制的任务会自动执行，并通过 lease 抢占避免多节点并发问题，同时支持心跳检测，检查脚本是否活跃。可在 管理员 > 版本升级 中查看升级脚本状态。

分批迁移任务默认每批处理 100 条记录。数据量较大时，可通过 SYSTEM_MIGRATION_BATCH_SIZE 调整为 50～1000。

AI Proxy（必需）

从 V4.17.0 起，必须部署或接入 AI Proxy，并在 FastGPT App 及复用 App/Service 配置的商业版 Admin 服务中设置：

  • AIPROXY_API_ENDPOINT：可访问的 AI Proxy 服务根地址，例如 http://aiproxy:3000，不要附加 /v1。
  • AIPROXY_API_TOKEN：与 AI Proxy 服务端配置一致的非空管理员 Token。

从 V4.17.0 起，OPENAI_BASE_URL 和 CHAT_API_KEY 已弃用并移除，配置后不再生效。 请从部署环境中删除这两个变量，改用上述 AI Proxy 配置，并在管理员的模型渠道中维护模型服务商地址和密钥。旧的 systemEnv.oneapiUrl/chatApiKey 覆盖配置也不再生效。

缺少任一 AI Proxy 配置会导致启动校验失败，单模型的 requestUrl/requestAuth 不能替代这两个必填项。升级前请确认 AI Proxy 可访问，且管理员 Token 可以访问渠道管理接口；不要把模型服务商的 API Key 当作 AI Proxy 管理员 Token。

CSRF 防御

本版本新增了环境变量用于防御 HTML 标签的 CSRF 工具。

CSRF_ENABLED=true

Code Sandbox seccomp 兼容配置（可选）

Code Sandbox 默认继续启用 seccomp。若宿主机内核不支持应用内 seccomp，进程池初始化会失败；确认可以接受系统调用隔离能力降低后，可为 Code Sandbox 显式设置：

SANDBOX_DISABLE_SECCOMP=true

该配置只关闭 seccomp，chroot、no_new_privs 和 UID/GID 降权仍保持启用。关闭后不再从内核层阻断网络、创建进程、线程和执行二进制等系统调用，不建议在支持 seccomp 的环境中使用。

新建团队默认创建权限（可选）

设置 DEFAULT_TEAM_BASIC_PERMISSIONS_ENABLED=true 后，新建团队时会为默认全员组授予应用、Skill 和知识库创建权限。默认值为 false，仅影响新建团队，不会修改已有团队权限。FastGPT Pro 请在 FastGPT 和 Admin 服务中保持该配置一致，以覆盖各自的团队创建入口，包括企业微信授权建队。

  7. FastGPT Pro 将飞书、企业微信、钉钉和微信公众号等发布渠道收到的非法消息调整为返回明确的客户端错误，避免将请求格式问题误报为服务端故障。
  8. FastGPT Pro 修复历史团队成员 role 字段可能覆盖当前权限计算的问题：除团队所有者外，废弃的角色值不再参与权限判断。
  9. 修复简易应用和对话 Agent 的隐藏多模态配置导致图片、音频或视频未进入模型请求的问题；工作流中有显式多模态开关的模型切换入口统一清除新模型不支持的选项，切回后不会自动恢复。
  10. 修复模型请求字段映射在同名、交换或链式映射时覆盖错误的问题；映射使用已归一化并按模型能力过滤的请求数据，重复目标字段会明确报错。
  11. 修复 MCP / HTTP Tool 定义随工作流快照过期或存储不兼容的问题，运行时读取工具定义，并兼容历史工具配置和鉴权信息。
  12. 修复 OpenAPI 导入工具未按接口定义发送参数的问题：根据原文将参数分配到 Path、Query、Header 和 JSON Body，支持路径级共享参数，并按 style / explode 序列化数组和浅对象，保留重复 Query 参数名及 JSON Body 中的原始数据类型。
  13. 修复 OpenAPI 定义中未传入的可选 Cookie 参数阻断请求的问题；必填参数缺失、实际传入但不支持的 Cookie 或不支持的参数编码仍会明确报错。
  14. 修复 ToolCall 统一关闭子工作流流式输出、导致子节点配置不生效的问题；子工作流继承父流程流式能力，并遵循自身禁流配置，简易应用生成的子应用和工作流工具节点仍强制禁流。
  15. 修复模型异步加载可能覆盖用户选择、将尚未加载的模型误判为不可用，以及编辑器恢复配置时意外补入默认模型的问题。
  16. 修复工作流发布时对已关闭的重排、问题优化、猜你想问和模型播报功能仍校验模型的问题；已开启的可选功能仅在模型为空时补入默认值，失效的非空模型引用仍会明确报错。
  17. 兼容历史团队成员缺失名称、应用 questionGuide 为 null 以及知识库模型引用为空的情况，避免读取旧数据时校验失败。
  18. 修复工作流连线在节点间距较小时的圆角与路径展示异常，以及站点图标配置为 / 时未使用默认图标的问题。
  19. 插件工作流模板头像保留插件返回的原始 URL，避免地址被重写后无法正确展示。
  20. 修复 HTML 表格转 Markdown 时，表头列数少于数据行导致部分列无法显示的问题；转换时自动补齐表头，保留完整表格内容。

🛠️ 代码优化

  1. 系统模型、模型权限及业务配置统一使用稳定的 modelId 引用，并通过自动升级任务兼容旧版模型名称引用。
  2. 自动升级任务通过 MongoDB lease、运行 ID 隔离和心跳实现多节点互斥与失效接管；大数据任务支持分批断点续跑。
  3. 协作者查询接口可按需返回团队成员登录用户名，并通过批量查询避免逐成员请求。
  4. FastGPT Pro 优化集群镜像构建缓存，使用代理缓存和带缓存的 Runner 降低重复拉取与构建开销。
  5. 修复部署脚本的访问地址与宿主机端口配置混淆问题，支持独立配置 FastGPT 和 Sandbox Proxy 的宿主机端口，避免误用反向代理的公网端口。
  6. Code Sandbox 在 JS 或 Python 代码执行失败时返回异常堆栈、异常链和已捕获的 console/print 输出，并记录到 warn 级别的响应日志。错误详情和输出各限制为 16K 字符，超限明确标记截断；Worker 响应解析失败时补充 worker ID、响应长度和已捕获的 stderr。进程被强制终止时，尚未发送的输出仍可能丢失。
