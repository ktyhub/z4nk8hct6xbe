#FastGPT v4.16.0

📦Guide de mise à niveau

1. Mettez à jour la variable d'environnement Agent-sandbox-proxy (facultatif)

4.16.0 doit s'appuyer sur un proxy pour l'accès au proxy de ressources statiques. Si la passerelle prend en charge ws et http sur le même port, vous ne pouvez ouvrir qu'un seul port. S'il n'est pas pris en charge, vous pouvez définir le port d'accès http en définissant PREVIEW_PORT.

# ws和http服务的端口
PORT=1006
# http服务的端口，可以覆盖 PORT
PREVIEW_PORT=1007

L'adresse d'accès commence par http:// ou https://. Lorsqu'il est déployé avec un seul port, il peut pointer vers le même nom de domaine et le même port que AGENT_SANDBOX_PROXY_URL, mais les protocoles utilisent respectivement HTTP(S) et WebSocket(S). Il est fortement recommandé que le nom de domaine configuré et le site principal FastGPT utilisent des origines différentes. Le déploiement de même origine permettra à ces scripts d'entrer dans la limite de sécurité de même origine du site principal et potentiellement d'accéder aux informations d'identification ou aux interfaces du site principal. Le système n'impose actuellement pas la vérification de l'origine pour l'isolement.

Vous pouvez vérifier s'il est accessible en visitant : https://{{host}}/health.

Les variables sont modifiées simultanément dans fastgpt-app et fastgpt-pro.

Les protocoles de prévisualisation de FastGPT, fastgpt-agent-sandbox-proxy et fastgpt-agent-sandbox ont été modifiés simultanément. Cette version de l'image de prise en charge doit être utilisée lors de l'activation de Agent Sandbox, et le déploiement mixte d'anciennes et de nouvelles versions n'est pas pris en charge.

4. Nettoyer la configuration du modèle de système historique

Cette version commence à utiliser un schéma strict lors de l'initialisation et de la sauvegarde des modèles de système. Les chaînes numériques, les dégradés de prix sous forme de chaîne ou les champs manquants enregistrés dans les versions précédentes peuvent entraîner l'échec de la vérification initiale. Après la mise à niveau, veuillez d'abord exécuter un essai à sec pour afficher la configuration du modèle qui doit être traitée ; l'exécution à sec ne modifiera pas les données ni n'actualisera le cache :

curl -X POST 'https://你的域名/api/admin/dataClean/cleanSystemModelConfigs' \
  -H 'Content-Type: application/json' \
  -H 'rootkey: 你的ROOT_KEY' \
  -d '{"dryRun":true}'

Après avoir confirmé qu'aucune donnée dans invalidSamples ne nécessite un traitement manuel, effectuez un nettoyage formel :

curl -X POST 'https://你的域名/api/admin/dataClean/cleanSystemModelConfigs' \
  -H 'Content-Type: application/json' \
  -H 'rootkey: 你的ROOT_KEY' \
  -d '{"dryRun":false}'

Le nettoyage convertit les chaînes numériques légales en nombres, convertit la forme de chaîne priceTiers en tableau et supprime les nombres facultatifs illégaux. Les numéros requis illégaux ou manquants utilisent les valeurs par défaut du système : maxContext/maxResponse/quoteMaxToken pour LLM est 16000/16000/13000, defaultToken/maxToken pour l'intégration est 500/3000 et le prix est 0. functionCall reste facultatif et le weight manquant dans Embedding est remplacé par 0.

L'exécution formelle écrit les données de manière uniforme et actualise immédiatement le cache du modèle système ; le cache d'exécution est reconstruit même s'il n'y a aucun enregistrement à mettre à jour. L'interface peut être réexécutée en toute sécurité ; lors d'un nouveau fonctionnement à sec, wouldUpdate devrait être 0. Les enregistrements qui ne peuvent pas passer le schéma de modèle complet actuel ne seront pas écrits et les détails seront tous renvoyés dans invalidSamples.

5. Migrer les données de l'outil HTTP

Cette version modifie les paramètres de tableau de l'outil HTTP en mode manuel vers le schéma JSON standard. Les environnements qui ont créé des outils HTTP manuels avant la mise à niveau doivent effectuer cette migration ; Les outils HTTP en mode OpenAPI n'ont pas besoin d'être migrés et le script sera automatiquement ignoré.

Exécutez d’abord un essai à sec pour afficher les données à traiter dans l’application actuelle et les versions historiques. le test à sec ne modifie pas les données :

curl -X POST 'https://你的域名/api/admin/4160/initHttpToolSchema' \
  -H 'Content-Type: application/json' \
  -H 'rootkey: 你的ROOT_KEY' \
  -d '{"dryRun":true}'

Après avoir confirmé le résultat, effectuez la migration officielle :

curl -X POST 'https://你的域名/api/admin/4160/initHttpToolSchema' \
  -H 'Content-Type: application/json' \
  -H 'rootkey: 你的ROOT_KEY' \
  -d '{"dryRun":false}'

Le script filtrera d'abord les applications par type d'outil HTTP, puis migrera les versions historiques correspondantes basées sur appId de ces applications. Seuls les modes manuels qui n'existent pas pour le apiSchemaStr seront traités, les autres applications et les modes OpenAPI ne seront pas modifiés. La migration est exécutée par lots et peut être réessayée en toute sécurité ; total.changedDocumentCount dans le résultat renvoyé indique le nombre de documents trouvés à traiter. Après l'exécution formelle, vous pouvez effectuer à nouveau un essai à sec pour confirmer que la valeur est 0.

6. Migrer les données de l'agent Sandbox (plus lent)

Cette version ajuste le bac à sable de l'agent d'App Chat d'« une instance par conversation » à « une instance partagée par la même application et le même utilisateur ». Les fichiers des différentes conversations sont toujours enregistrés respectivement dans le répertoire sessions/<chatId>, et les compétences publiées sont enregistrées dans le répertoire partagé projects.

Si Agent Sandbox a été précédemment activé, la migration de l'espace de travail existant doit être effectuée dans l'ordre suivant. Les environnements qui n'ont pas activé Agent Sandbox peuvent ignorer cette section.

Effectuez d’abord un essai à sec pour afficher le décompte en attente de la normalisation du champ Sandbox bêta6 et du nettoyage de l’ancienne Skill Debug Chat. l'exécution à sec ne crée pas de ressources, n'accède pas au stockage d'objets et ne modifie pas les données :

curl -X POST 'https://你的域名/api/admin/4160/initUserSandbox' \
  -H 'Content-Type: application/json' \
  -H 'rootkey: 你的ROOT_KEY' \
  -d '{"dryRun":true}'

Effectuez la migration officielle après avoir consulté les résultats de l'essai à sec. La migration officielle effectuera d'abord la normalisation bêta6 et ne poursuivra l'archivage Workspace dans la même requête que lorsque le nombre restant en attente atteindra zéro :

curl -X POST 'https://你的域名/api/admin/4160/initUserSandbox' \
  -H 'Content-Type: application/json' \
  -H 'rootkey: 你的ROOT_KEY' \
  -d '{"dryRun":false}'

Si failures contient uniquement Sandbox source is missing or deleted et qu'il a été confirmé que l'application ou la compétence correspondante n'existe plus, vous pouvez explicitement ignorer ces bacs à sable résiduels :

curl -X POST 'https://你的域名/api/admin/4160/initUserSandbox' \
  -H 'Content-Type: application/json' \
  -H 'rootkey: 你的ROOT_KEY' \
  -d '{"dryRun":false,"skipError":true}'

skipError La valeur par défaut est false, maintenant une migration stricte en cas d'omission. Ce commutateur ignore uniquement l'intégralité du groupe dont la source est manquante ou supprimée de manière logicielle, et n'archive, ne supprime ni ne migre le bac à sable qu'il contient ; Les détails du saut sont renvoyés via skippedCount et skipped. D'autres erreurs telles que l'archivage, le stockage d'objets, les fournisseurs et le contrôle de concurrence peuvent toujours bloquer les migrations.

La migration exécutera d'abord la pré-logique complète de V4.15.0-beta6 : complétez le sourceType/sourceId de l'ancien Sandbox, nettoyez les champs hérités, supprimez les ressources orphelines qui ne peuvent pas être attribuées et nettoyez les anciennes données à trois tables de Skill Debug Chat manquant sourceType et les anciens préfixes des compartiments privés et publics. Les compétences portant le même identifiant que l'application ignoreront le nettoyage du chat. Après retraitement des deux types de données, le total est normalization.pendingCount ; si la quantité n'est pas 0, elle ne sera pas saisie dans l'archive Workspace. Après la mise à zéro, archivez directement tous les anciens espaces de travail et nettoyez les anciennes ressources informatiques, puis migrez les compétences et enfin les regroupez dans des bacs à sable au niveau utilisateur par application et par utilisateur. Tant qu'il y aura un échec dans la phase d'archivage, la phase d'installation ne démarrera pas. Le nouveau Sandbox sera mis en pause une fois l'installation de Workspace terminée et sera démarré selon le processus normal lors de sa première utilisation. Les scripts peuvent être réessayés en toute sécurité et les archives et migrations terminées ne sont pas réexécutées ; les anciennes archives et les anciens enregistrements MongoDB sont conservés sous forme de sauvegardes une fois la migration terminée.

Veuillez vérifier les résultats renvoyés pour normalization.pendingCount, normalizationBlocked, failedCount, failures, skippedCount et skipped. Ce n'est que lorsque normalization.pendingCount et failedCount sont tous deux 0 et que normalizationBlocked est false que cela signifie que toutes les migrations Sandbox non ignorées sont terminées ; Les anciens enregistrements dans skipped seront conservés et ne seront pas migrés.

🚀 Nouveau contenu

  1. L'Agent Sandbox est remplacé par une instance de niveau utilisateur d'application. Plusieurs conversations de la même application et du même utilisateur réutilisent le Sandbox et isolent chaque fichier de conversation via un répertoire de session indépendant.
  2. Le HTML et les fichiers Sandbox prennent en charge l'aperçu direct via des liens en lecture seule à court terme et n'ont plus besoin d'être téléchargés à plusieurs reprises vers le stockage d'objets pour l'aperçu.
  3. App Workflow archive et restaure automatiquement l'espace de travail lorsque le fournisseur Sandbox ou l'image d'exécution change, et le processus de mise à niveau s'effectue silencieusement pendant l'exécution en cours.
  4. Le nœud de l'outil de workflow prend en charge la génération automatique des paramètres d'entrée spécifiés par l'agent et conserve les configurations existantes telles que les valeurs fixes, les références et les entrées utilisateur.
  5. Lorsque ChatAgent sélectionne un outil, il prend en charge la spécification manuelle s'il faut générer des paramètres pour l'IA.
  6. Les données de la base de connaissances prennent en charge la personnalisation du metadata et les métadonnées du JSON peuvent être importées via des modèles API, CSV ou Excel ; ce champ sera conservé dans les résultats de recherche et les exports de sauvegarde. L'importation de modèles et l'importation de sauvegarde prennent en charge les fichiers .csv et .xlsx, à l'aide des en-têtes q, a, index et metadata ; q, a et metadata ont chacun une colonne et index peut avoir plusieurs colonnes dans n'importe quel ordre. Les fichiers Excel ne prennent en charge qu'une seule feuille de calcul et ne peuvent pas contenir de cellules fusionnées. Les fichiers CSV ou Excel qui ne peuvent pas être analysés correctement entraîneront une exception de format de fichier.
  7. Téléchargez des fichiers volumineux en morceaux.
  8. Lorsque l'administrateur configure la clé de l'outil système, elle est cryptée (compatible avec la clé configurée).
  9. Conseils d'état vide dans la liste des compétences et lien lors de la sélection des compétences.
  10. La configuration système de l'application de workflow est déplacée vers le panneau de configuration indépendant dans la barre d'outils sur le côté gauche du canevas, qui sera automatiquement ouvert lors de la création d'une nouvelle application de workflow.
  11. La déclaration d'ouverture prend en charge la configuration indépendante de plusieurs questions prédéfinies et peut être triée par glisser-déposer.

⚙️ Optimisation

  1. Reconstruisez le cycle de vie et le processus de migration de l'agent Sandbox. La création, la pause, l'archivage, la restauration, la suppression et le changement de fournisseur prennent en charge la protection contre la concurrence, la reprise du point d'arrêt et les nouvelles tentatives idempotentes.
  2. Lorsque l'agent Sandbox n'est pas disponible ou n'est pas pris en charge par le package d'équipe actuel, App Chat désactive automatiquement la fonctionnalité Sandbox et les autres modèles, outils, bases de connaissances et nœuds de workflow peuvent toujours continuer à s'exécuter.
  3. Les volumes persistants peuvent être conservés après l'arrêt d'OpenSandbox et réutilisés lors des exécutions ultérieures ; les seuils de pause et d'archivage prennent en charge la configuration via des variables d'environnement.
  4. L'application et la compétence ont un statut de mise à niveau de l'image d'exécution unifié, et la page d'édition des compétences peut interroger en permanence les résultats de la mise à niveau.
  5. Créez automatiquement des répertoires parents avant d'écrire des fichiers Sandbox pour éviter l'échec de l'écriture des chemins imbriqués.
  6. Optimisez les problèmes de compatibilité tels que les anciennes données de flux de travail et les paramètres d'outils.
  7. Agent demander l'interface utilisateur.
  8. Reconstruisez la page des canaux de version, affichez-la en groupes par canaux natifs et canaux tiers, et affichez la quantité configurée pour chaque canal.
  9. La mise à jour par lots du marché des outils prend en charge l'affichage de certains éléments ayant échoué, la nouvelle tentative ou la désinstallation individuellement, et améliore l'affichage des versions installées et de l'état de la mise à jour.
  10. La limite supérieure du nombre d'applications rapides sur la page du portail est ajustée à 3 et les configurations historiques ayant dépassé la limite supérieure sont compatibles.
  11. L'analyseur PDF utilise un recadrage dynamique des bords au lieu d'un recadrage fixe pour éviter de recadrer le contenu réel.

📦 升级指南

1. 更新 Agent-sandbox-proxy 环境变量（可选）

4.16.0 需要依赖 proxy 进行静态资源代理访问，如果网关支持 ws 和 http 在同一个端口，则可以只开放一个端口。如果不支持，可以通过设置 PREVIEW_PORT 来设置 http 访问端口。

# ws和http服务的端口
PORT=1006
# http服务的端口，可以覆盖 PORT
PREVIEW_PORT=1007

访问地址以 http:// 或 https:// 开头。单端口部署时，它可以与 AGENT_SANDBOX_PROXY_URL 指向同一域名和端口，但协议分别使用 HTTP(S) 和 WebSocket(S)。强烈建议配置的域名与 FastGPT 主站使用不同的 origin。同源部署会让这些脚本进入主站的同源安全边界，可能访问主站凭证或接口。系统当前不会强制检查 origin 是否隔离。

可以通过访问: https://{{host}}/health 来确认是否可访问。

4. 清洗历史系统模型配置

本版本开始在系统模型初始化及保存时使用严格 Schema。此前版本保存的数字字符串、字符串形式的价格梯度或缺失字段可能导致初始化校验失败。升级后请先执行 dry-run，查看需要处理的模型配置；dry-run 不会修改数据或刷新缓存：

curl -X POST 'https://你的域名/api/admin/dataClean/cleanSystemModelConfigs' \
  -H 'Content-Type: application/json' \
  -H 'rootkey: 你的ROOT_KEY' \
  -d '{"dryRun":true}'

确认 invalidSamples 中没有需要人工处理的数据后，执行正式清洗：

curl -X POST 'https://你的域名/api/admin/dataClean/cleanSystemModelConfigs' \
  -H 'Content-Type: application/json' \
  -H 'rootkey: 你的ROOT_KEY' \
  -d '{"dryRun":false}'

清洗会将合法数字字符串转换为 number、将字符串形式的 priceTiers 转换为数组，并删除非法的可选数字。非法或缺失的必填数字使用系统默认值：LLM 的 maxContext/maxResponse/quoteMaxToken 分别为 16000/16000/13000，Embedding 的 defaultToken/maxToken 分别为 500/3000，价格为 0。functionCall 保持可选，Embedding 缺失的 weight 补为 0。

正式执行会统一写入数据并立即刷新系统模型缓存；即使没有记录需要更新，也会重新构建运行时缓存。接口可安全重复执行；再次 dry-run 时，wouldUpdate 应为 0。无法通过当前完整模型 Schema 的记录不会写入，详情会全部返回在 invalidSamples 中。

5. 迁移 HTTP 工具数据

本版本将手动模式 HTTP 工具的数组参数改为标准 JSON Schema。升级前创建过手动 HTTP 工具的环境需要执行此迁移；OpenAPI 模式的 HTTP 工具无需迁移，脚本会自动跳过。

先执行 dry-run，查看当前应用及历史版本中的待处理数据。dry-run 不会修改数据：

curl -X POST 'https://你的域名/api/admin/4160/initHttpToolSchema' \
  -H 'Content-Type: application/json' \
  -H 'rootkey: 你的ROOT_KEY' \
  -d '{"dryRun":true}'

确认结果后执行正式迁移：

curl -X POST 'https://你的域名/api/admin/4160/initHttpToolSchema' \
  -H 'Content-Type: application/json' \
  -H 'rootkey: 你的ROOT_KEY' \
  -d '{"dryRun":false}'

脚本会先按 HTTP 工具类型筛选应用，再根据这些应用的 appId 迁移对应的历史版本。仅 apiSchemaStr 不存在的手动模式会被处理，其他应用及 OpenAPI 模式不会修改。迁移按批次执行且可安全重试；返回结果中 total.changedDocumentCount 表示发现的待处理文档数，正式执行后可再次 dry-run，确认该值为 0。

6. 迁移 Agent Sandbox 数据(较慢)

本版本将 App Chat 的 Agent Sandbox 从“每个对话一个实例”调整为“同一 App、同一用户共享一个实例”。不同对话的文件仍分别保存在 sessions/<chatId> 目录中，已发布 Skill 则统一保存在共享的 projects 目录中。

如果此前启用过 Agent Sandbox，必须按以下顺序完成旧 Workspace 迁移。未启用过 Agent Sandbox 的环境可以跳过本节。

先执行 dry-run，查看 beta6 Sandbox 字段归一化和旧 Skill Debug Chat 清理的待处理数。dry-run 不会创建资源、访问对象存储或修改数据：

curl -X POST 'https://你的域名/api/admin/4160/initUserSandbox' \
  -H 'Content-Type: application/json' \
  -H 'rootkey: 你的ROOT_KEY' \
  -d '{"dryRun":true}'

查看 dry-run 结果后执行正式迁移。正式迁移会先执行 beta6 归一化，并且只在剩余待处理数归零时，才在同一请求中继续 Workspace 归档：

curl -X POST 'https://你的域名/api/admin/4160/initUserSandbox' \
  -H 'Content-Type: application/json' \
  -H 'rootkey: 你的ROOT_KEY' \
  -d '{"dryRun":false}'

如果 failures 中仅包含 Sandbox source is missing or deleted，并且已确认对应 App 或 Skill 确实不再存在，可以显式跳过这些残留 Sandbox：

curl -X POST 'https://你的域名/api/admin/4160/initUserSandbox' \
  -H 'Content-Type: application/json' \
  -H 'rootkey: 你的ROOT_KEY' \
  -d '{"dryRun":false,"skipError":true}'

skipError 默认为 false，省略时保持严格迁移。该开关只跳过 source 已缺失或已软删除的整个分组，不会归档、删除或迁移其中的 Sandbox；跳过明细通过 skippedCount 和 skipped 返回。归档、对象存储、Provider 和并发控制等其他错误仍会阻断迁移。

迁移会先执行 V4.15.0-beta6 的完整前置逻辑：补齐旧 Sandbox 的 sourceType/sourceId、清理遗留字段、删除无法归属的孤立资源，并清理缺失 sourceType 的旧 Skill Debug Chat 三表数据及私有、公开 Bucket 旧前缀。与 App 同 ID 的 Skill 会跳过 Chat 清理。两类数据重新统计后合计为 normalization.pendingCount；数量不为 0 时不会进入 Workspace 归档。归零后直接归档全部旧 Workspace 并清理旧计算资源，再迁移 Skill，最后按 App、用户聚合到用户级 Sandbox。只要归档阶段存在失败，安装阶段就不会开始。新的 Sandbox 会在 Workspace 安装完成后暂停，首次使用时再按正常流程启动。脚本可安全重试，已完成的归档和迁移不会重复执行；迁移完成后会保留旧归档和旧 MongoDB 记录作为备份。

请检查返回结果中的 normalization.pendingCount、normalizationBlocked、failedCount、failures、skippedCount 和 skipped。只有 normalization.pendingCount 和 failedCount 均为 0，且 normalizationBlocked 为 false 时，才表示所有未跳过的 Sandbox 迁移完成；skipped 中的 Legacy 记录会保留且不会迁移。

🚀 新增内容

  1. Agent Sandbox 改为 App 用户级实例，同一 App、同一用户的多个对话复用 Sandbox，并通过独立 session 目录隔离各对话文件。
  2. Sandbox HTML 和文件支持通过短期只读链接直接预览，不再为预览重复上传到对象存储。
  3. App Workflow 在 Sandbox Provider 或运行时镜像变化时自动归档并恢复 Workspace，升级过程在当前运行中静默完成。
  4. 工作流工具节点支持将指定输入参数交由 Agent 自动生成，并保留固定值、引用和用户输入等既有配置。
  5. ChatAgent 选择工具时，支持手动指定是否为 AI 生成参数。
  6. 知识库数据支持自定义 metadata，可通过 API、CSV 或 Excel 模板导入 JSON 元数据；检索结果和备份导出会保留该字段。模板导入和备份导入均支持 .csv 和 .xlsx 文件，使用 q、a、index、metadata 表头；q、a、metadata 各一列，index 可多列且顺序任意。Excel 文件仅支持单个工作表且不能包含合并单元格，无法正确解析的 CSV 或 Excel 文件会提示文件格式异常。
  7. 大文件分块上传。
  8. 管理员配置系统工具密钥时，加密（兼容已配置的密钥）。
  9. 技能列表空状态引导，以及选择技能时联动。
  10. 工作流应用的系统配置移至画布左侧工具栏中的独立配置面板，新建工作流应用时会自动打开。
  11. 开场白支持独立配置多个预设问题，并可拖拽排序。

⚙️ 优化

  1. 重构 Agent Sandbox 生命周期和迁移流程，创建、暂停、归档、恢复、删除及 Provider 切换支持并发保护、断点续跑和幂等重试。
  2. Agent Sandbox 不可用或当前团队套餐不支持时，App Chat 自动禁用 Sandbox 能力，其他模型、工具、知识库和 Workflow 节点仍可继续运行。
  3. OpenSandbox 停止后可保留持久卷并在后续运行时复用；暂停和归档阈值支持通过环境变量配置。
