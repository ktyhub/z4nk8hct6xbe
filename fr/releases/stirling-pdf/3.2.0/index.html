Stirling-PDF_0.33.1 Déplacement du moyeu Docker vers Stirlingtools v3.2.0

Encore une bonne sortie ! L'ancien multi-outil a été remplacé par un éditeur de page entièrement repensé. Il prend désormais à nouveau en charge les images, le renommage des fichiers et de nombreuses modifications de l'interface utilisateur QOL, ce qui facilite grandement la réorganisation et la gestion de vos documents. N'hésitez pas à nous faire savoir ce que vous en pensez et si vous rencontrez des problèmes !

Quelques changements majeurs dans la façon dont nous traitons les PDF protégés par mot de passe. Ils peuvent désormais être ouverts pour être visualisés et utilisés avec des outils courants sans avoir à supprimer le mot de passe au préalable, et vos paramètres d'autorisation PDF existants sont conservés lors du déverrouillage.

Les autres changements sont :

  • Stirling Sign envoie désormais un e-mail aux participants et aux demandeurs au fur et à mesure qu'une demande de signature progresse
  • Déposez des fichiers n'importe où sur l'établi, ainsi qu'un bouton d'ajout de fichiers repensé
  • La compression vous indique désormais quand elle n'a pas pu réduire un fichier
  • Interface utilisateur d'imposition de livrets bien rangée avec diagrammes guides
  • redirectBaseUrl facultatif pour OAuth2 et SAML lors de l'exécution derrière des proxys inverses
  • Démarrage plus rapide et utilisation réduite de la mémoire dans la visionneuse et l'éditeur de texte
  • Icônes actualisées et améliorations de l'interface utilisateur de chat

Nous avons également corrigé quelques bugs, notamment

  • Le bureau plante lors de la réorganisation des fichiers sur Mac
  • Les brouillons de formulaires sont perdus avant la fin des sauvegardes
  • Les signatures sont perdues lors de l'ajustement de la taille et de l'échelle de la page
  • L'outil de signalisation plante lors de la navigation
  • Le chat ne met pas à jour correctement la version du fichier
  • Les téléchargements S3 échouent lors d'une nouvelle tentative

Stirling-PDF_0.33.1 Docker hub move to stirlingtools v3.2.0

Highlights

  • Page Editor replaces Multi-Tool — The redesigned editor consolidates page rearrangement with image support, file renaming, and additional page actions (#7618, #8410, #8415, #8408). Update user guides and revalidate any UI automation built around the old multi-tool workflow.
  • Protected PDFs no longer require password-stripped copies — Viewing and common tools now work directly with protected files (#8393). Unlocking preserves existing permission settings (#8430), which are honored by default (#8466); administrators needing to override restrictions should review the new bypass setting before rollout.
  • Lower startup cost and memory pressure — Precompressed build output, deferred PDFium WASM loading (#8043), lazy sidebar thumbnails (#8034), and reusable text-editor buffers (#8099) reduce resource usage, especially for large document libraries and long editing sessions.
  • Document-integrity fixes reduce data loss and silent failures — Form drafts wait for saves to complete (#8455), signatures survive resizing, scaling, and navigation (#8457, #8456), AI chat tracks the current file version (#8416), and S3 retries reopen the upload stream (#8292). Redactions now fail explicitly when the engine cannot verify removal (#8451), rather than reporting uncertain success.
  • Deployment and SSO configuration changes — Docker Hub publication has moved to the stirlingtools namespace, so update image references and pins in manifests and CI; the image also includes ImageMagick 7.1.2-33 (#8444). Reverse-proxy deployments can configure the opt-in redirectBaseUrl for OAuth2/SAML callback URLs (#8473).
  • Breaking changes — None announced.

Another good release! The old multi-tool has been replaced by a completely redesigned Page Editor. It now resupports images, renaming files, and a bunch of QOL UI changes making it much easier to rearrange and manage your documents. Please let us know what you think and if you have any issues with it!

Some big changes in how we handle password-protected PDF, They can now be opened for viewing and used with common tools without having to remove the password first, and your existing PDF permission settings are kept when unlocking.

Other changes are:

  • Stirling Sign now emails participants and requesters as a signing request progresses
  • Drop files anywhere on the workbench, plus a redesigned add-files button
  • Compression now tells you when it could not shrink a file
  • Tidied booklet imposition UI with guide diagrams
  • Optional redirectBaseUrl for OAuth2 and SAML when running behind reverse proxies
  • Faster startup and lower memory use in the viewer and text editor
  • Refreshed icons and chat UI improvements

We also fixed some bugs including

  • Desktop crashing when reordering files on Mac
  • Form drafts being lost before saves completed
  • Signatures being lost when adjusting page size and scale
  • Sign tool crashing when navigating away
  • Chat not updating the file version correctly
  • S3 uploads failing on retry
