TenseurRT-LLM v0.13.0

Salut, Nous sommes très heureux d'annoncer la version 0.13.0 de TensorRT-LLM. Cette mise à jour comprend :

Principales fonctionnalités et améliorations

  • Décodage anticipé pris en charge (expérimental), voir docs/source/speculative_decoding.md.
  • Ajout de quelques améliorations au ModelWeightsLoader (un convertisseur de point de contrôle unifié, voir docs/source/architecture/model-weights-loader.md).
    • Modèles Qwen pris en charge.
    • Remplissage automatique pris en charge pour la forme TP indivisible dans INT4-wo/INT8-wo/INT4-GPTQ.
    • Performances améliorées sur *.bin et *.pth.
  • Prise en charge d'OpenAI Whisper dans le runtime C++.
  • Ajout de quelques améliorations à la classe LLM.
    • LoRA pris en charge.
    • Prise en charge de la construction de moteurs à l'aide de poids factices.
    • trust_remote_code pris en charge pour les modèles personnalisés et les tokenizers téléchargés depuis Hugging Face Hub.
  • Recherche de faisceau prise en charge pour le mode streaming.
  • Parallélisme tenseur pris en charge pour Mamba2.
  • Logits de génération de retour pris en charge pour le mode streaming.
  • Ajout du support curand et bfloat16 pour ReDrafter.
  • Ajout du mode de normalisation du mélangeur clairsemé pour les modèles MoE.
  • Ajout de la prise en charge de la mise à l'échelle QKV dans FP8 FMHA.
  • Prise en charge du FP8 pour MoE LoRA.
  • Prise en charge de la réutilisation du cache KV pour P-Tuning et LoRA.
  • Prise en charge du traitement par lots en vol pour les modèles CogVLM.
  • LoRA pris en charge pour la classe ModelRunnerCpp.
  • Cas head_size=48 pris en charge pour les noyaux FMHA.
  • Ajout d'exemples FP8 pour les modèles DiT, voir examples/dit/README.md.
  • Décodeur pris en charge avec fonctionnalités d'entrée d'encodeur pour le C++ executor API.

API Modifications

  • [CHANGEMENT RUPTURE] Réglez use_fused_mlp sur True par défaut.
  • [CHANGEMENT RUPTURE] Activé multi_block_mode par défaut.
  • [CHANGEMENT RUPTURE] Activé strongly_typed par défaut dans builder API.
  • [CHANGEMENT RUPTURE] Renommés maxNewTokens, randomSeed et minLength en maxTokens, seed et minTokens selon le style OpenAI.
  • La classe LLM
    • [CHANGEMENT RUPTURE] Mise à jour des arguments LLM.generate pour inclure PromptInputs et tqdm.
  • Le C++ executor API
    • [CHANGEMENT RUPTURE] Ajout de LogitsPostProcessorConfig.
    • Ajout de FinishReason à Result. ### Mises à jour du modèle
  • Gemma 2 pris en charge, voir la section "Exécuter Gemma 2" dans examples/gemma/README.md.

Problèmes résolus

  • Correction d'un problème de précision lors de l'activation de la suppression du problème de remplissage pour une attention croisée. (#1999)
  • Correction de l'échec de la conversion de qwen2-0.5b-instruct lors de l'utilisation de smoothquant. (#2087)
  • Correspondance du modèle exclude_modules dans convert_utils.py aux modifications apportées dans quantize.py. (#2113)
  • Correction d'une erreur du moteur de construction lorsque FORCE_NCCL_ALL_REDUCE_STRATEGY est défini.
  • Correction d'une troncature inattendue dans le mode quant de gpt_attention.
  • Correction du blocage provoqué par une condition de concurrence lors de l'annulation des demandes.
  • Correction de l'usine par défaut pour LoraConfig. (#1323)

Modifications des infrastructures

  • L'image de base Docker pour TensorRT-LLM est mise à jour vers nvcr.io/nvidia/pytorch:24.07-py3.
  • L'image de base Docker pour le backend TensorRT-LLM est mise à jour vers nvcr.io/nvidia/tritonserver:24.07-py3.
  • La version dépendante de TensorRT est mise à jour vers 10.4.0.
  • La version dépendante de CUDA est mise à jour vers 12.5.1.
  • La version dépendante de PyTorch est mise à jour vers 2.4.0.
  • La version dépendante de ModelOpt est mise à jour vers v0.15. Nous mettons régulièrement à jour la branche main avec de nouvelles fonctionnalités, des corrections de bugs et des optimisations de performances. La branche rel sera mise à jour moins fréquemment et les fréquences exactes dépendent de vos retours. Merci, L'équipe d'ingénierie TensorRT-LLM

TensorRT-LLM v0.13.0

Highlights

  • Breaking defaults and API renames — Several build/runtime defaults flip in 0.13.0: use_fused_mlp, multi_block_mode, and strongly_typed (builder API) are all now True by default, so previously-built engines can change in numerics and performance — re-benchmark and re-validate accuracy rather than assuming bit-for-bit parity. The C++ executor also renames maxNewTokens/randomSeed/minLength to OpenAI-style maxTokens/seed/minTokens and adds a required LogitsPostProcessorConfig, while LLM.generate now takes PromptInputs and tqdm; expect to touch call sites on upgrade.
  • LLM class gains LoRA, remote-code, and dummy-weight builds — The high-level LLM API now supports LoRA adapters, building engines from dummy weights (useful for CI/engine-shape validation without full checkpoints), and trust_remote_code for custom models/tokenizers pulled from Hugging Face Hub. LoRA also lands in ModelRunnerCpp and with KV-cache reuse for P-Tuning/LoRA, so adapter-serving workflows no longer need to drop to lower-level APIs.
  • New speculative-decoding and decoder side paths — Lookahead decoding ships as experimental (see docs/source/speculative_decoding.md), and ReDrafter adds curand and bfloat16 support. Treat lookahead as exploratory — it is documented but not yet a production guarantee, so validate latency/acceptance rates on your own workloads before betting on it.
  • Unified checkpoint converter gets practical — The ModelWeightsLoader path adds Qwen support, auto-padding for indivisible TP shapes in INT4-wo/INT8-wo/INT4-GPTQ, and faster *.bin/*.pth loading. Combined with fixes for smoothquant on qwen2-0.5b-instruct (#2087) and an exclude_modules pattern realigned with quantize.py (#2113), quantized Qwen users should re-run conversion — several previously failing or subtly mis-quantized cases are now corrected.
  • Broader model and streaming coverage — Whisper moves into the C++ runtime, beam search and generation-logits return now work in streaming mode, Mamba2 gains tensor parallelism, CogVLM gets in-flight batching, and MoE adds sparse mixer normalization plus FP8 LoRA. QKV scaling in FP8 FMHA and head_size=48 kernel support round out the low-precision story; the decoder-with-encoder-input-features option in the C++ executor API targets encoder-decoder serving.
  • Toolchain jump requires an environment refresh — Base images move to nvcr.io/nvidia/pytorch:24.07-py3 and tritonserver:24.07-py3, with TensorRT 10.4.0, CUDA 12.5.1, PyTorch 2.4.0, and ModelOpt v0.15. Plan a clean rebuild and compatibility check of custom plugins/kernels, and note correctness fixes for remove-padding cross-attention accuracy (#1999) and the LoraConfig default factory (#1323) that can change results for affected setups.

Hi,

We are very pleased to announce the 0.13.0 version of TensorRT-LLM. This update includes:

Key Features and Enhancements

  • Supported lookahead decoding (experimental), see docs/source/speculative_decoding.md.
  • Added some enhancements to the ModelWeightsLoader (a unified checkpoint converter, see docs/source/architecture/model-weights-loader.md).
    • Supported Qwen models.
    • Supported auto-padding for indivisible TP shape in INT4-wo/INT8-wo/INT4-GPTQ.
    • Improved performance on *.bin and *.pth.
  • Supported OpenAI Whisper in C++ runtime.
  • Added some enhancements to the LLM class.
    • Supported LoRA.
    • Supported engine building using dummy weights.
    • Supported trust_remote_code for customized models and tokenizers downloaded from Hugging Face Hub.
  • Supported beam search for streaming mode.
  • Supported tensor parallelism for Mamba2.
  • Supported returning generation logits for streaming mode.
  • Added curand and bfloat16 support for ReDrafter.
  • Added sparse mixer normalization mode for MoE models.
  • Added support for QKV scaling in FP8 FMHA.
  • Supported FP8 for MoE LoRA.
  • Supported KV cache reuse for P-Tuning and LoRA.
  • Supported in-flight batching for CogVLM models.
  • Supported LoRA for the ModelRunnerCpp class.
  • Supported head_size=48 cases for FMHA kernels.
  • Added FP8 examples for DiT models, see examples/dit/README.md.
  • Supported decoder with encoder input features for the C++ executor API.

API Changes

  • [BREAKING CHANGE] Set use_fused_mlp to True by default.
  • [BREAKING CHANGE] Enabled multi_block_mode by default.
  • [BREAKING CHANGE] Enabled strongly_typed by default in builder API.
  • [BREAKING CHANGE] Renamed maxNewTokens, randomSeed and minLength to maxTokens, seed and minTokens following OpenAI style.
  • The LLM class
    • [BREAKING CHANGE] Updated LLM.generate arguments to include PromptInputs and tqdm.
  • The C++ executor API
    • [BREAKING CHANGE] Added LogitsPostProcessorConfig.
    • Added FinishReason to Result.

Model Updates

  • Supported Gemma 2, see "Run Gemma 2" section in examples/gemma/README.md.

Fixed Issues

  • Fixed an accuracy issue when enabling remove padding issue for cross attention. (#1999)
  • Fixed the failure in converting qwen2-0.5b-instruct when using smoothquant. (#2087)
  • Matched the exclude_modules pattern in convert_utils.py to the changes in quantize.py. (#2113)
  • Fixed build engine error when FORCE_NCCL_ALL_REDUCE_STRATEGY is set.
  • Fixed unexpected truncation in the quant mode of gpt_attention.
  • Fixed the hang caused by race condition when canceling requests.
  • Fixed the default factory for LoraConfig. (#1323)

Infrastructure Changes

  • Base Docker image for TensorRT-LLM is updated to nvcr.io/nvidia/pytorch:24.07-py3.
  • Base Docker image for TensorRT-LLM Backend is updated to nvcr.io/nvidia/tritonserver:24.07-py3.
  • The dependent TensorRT version is updated to 10.4.0.
  • The dependent CUDA version is updated to 12.5.1.
  • The dependent PyTorch version is updated to 2.4.0.
  • The dependent ModelOpt version is updated to v0.15.

We are updating the main branch regularly with new features, bug fixes and performance optimizations. The rel branch will be updated less frequently, and the exact frequencies depend on your feedback.

Thanks, The TensorRT-LLM Engineering Team
