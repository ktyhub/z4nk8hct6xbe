TenseurRT-LLM v0.20.0

TensorRT-LLM version 0.20.0

Principales fonctionnalités et améliorations

  • Prise en charge du modèle
    • Ajout du support Qwen3. Reportez-vous à la section « Qwen3 » dans examples/models/core/qwen/README.md.
    • Ajout de la prise en charge de HyperCLOVAX-SEED-Vision dans le flux PyTorch. Se référer à examples/models/contrib/hyperclovax/README.md
    • Ajout de Dynasor-CoT dans les exemples d'échafaudages. Se référer à examples/scaffolding/contrib/Dynasor/README.md
    • Ajout de la prise en charge de Mistral Small 3.1 24B VLM dans le flux de travail TRT
    • Ajout de la prise en charge de Gemma3-1b-it dans le flux de travail PyTorch
    • Ajout du support du modèle Nemotron-H
    • Ajout du support Eagle-3 pour LLAMA4
  • Flux de travail PyTorch
    • Ajout du support lora
    • Ajout du support des journaux de retour
    • Adopter une nouvelle définition de logprob dans le flux PyTorch
    • Activation des statistiques par requête avec le backend PyTorch
    • Activation de LogitsProcessor dans le backend PyTorch
  • Benchmark :
    • Ajoutez la largeur du faisceau à une faible latence.
    • Correction des erreurs trtllm-bench iter_stats et cuda_graph_batch_sizes.
    • Supprimer le benchmark d'exécution Python obsolète
    • Ajouter un support de référence pour les échafaudages
  • Modèles multimodaux
    • Ajout du support dans trtllm-serve
    • Ajout du support dans trtllm-bench, le support est limité à l'image uniquement pour l'instant
  • DeepSeek-R1 W4A8 pris en charge sur Hopper
  • Ajout du support RTX Pro 6000 sur un seul GPU
  • Processeur d'entrée Llama4 intégré
  • Ajout des noyaux FHMA de réduction CGA sur Blackwell
  • Activation du contexte fragmenté pour FlashInfer
  • Réutilisation du cache KV prise en charge pour MLA
  • Ajout du support Piecewise CUDA Graph
  • Prise en charge de plusieurs adaptateurs LoRA et TP
  • Ajout d'un routeur compatible avec le cache KV pour un service désagrégé
  • Attention sans faille pour le support natif
  • Ajout du noyau group_rms_norm pour normaliser plusieurs entrées dans un seul opérateur
  • Ajout d'un routeur intelligent pour le module MoE
  • Ajout du support de la taille de tête 72 pour le noyau de prétraitement QKV
  • Ajout de la prise en charge de MNNVL MoE A2A
  • Grandes tables d'intégration optimisées dans les modèles multimodaux
  • Prise en charge des logprobs Top-K et prompt_logprobs dans LLMAPI
  • Activation du planificateur de chevauchement dans le flux de travail TRT via l'exécuteur API

Modifications des infrastructures

  • L'équipe TRT-LLM publie officiellement l'image docker sur NGC.
  • La roue TensorRT-LLM prédéfinie sur PyPI est désormais liée à PyTorch 2.7.0, qui utilise l'ABI CXX11
  • La version dépendante de TensorRT est mise à jour vers 10.10.0
  • La version dépendante de CUDA est mise à jour vers 12.9.0
  • La version publique dépendante de PyTorch est mise à jour vers 2.7.0
  • La version dépendante de NVIDIA ModelOpt est mise à jour vers 0.29.0
  • La version NCCL dépendante est conservée à 2.25.1
  • Noyaux XQA open source
  • La version des ensembles de données dépendants a été mise à niveau vers 3.1.0
  • Migrer le backend Triton vers le référentiel TensorRT LLM vers le sous-module TensorRT LLM
  • Rétrograder la version du jeu d'outils gcc de 13 à 11

API Modifications

  • [Breaking Change] : Activer le chevauchement de planification par défaut
  • Supprimer GptSession/V1 obsolète du flux de travail TRT
  • Définir _AutoDeployLlmArgs comme objet de configuration principal
  • Autoriser le remplacement des arguments CLI par le fichier YAML dans trtllm-serve
  • Introduction du champ d'intégration multimodale dans LlmRequest

Problèmes résolus

  • Correction d'un bug de blocage lorsque le serveur de contexte n'a pas suffisamment de capacité pour le cache KV (#3095)
  • Correction de la synchronisation du décodeur C++ dans PyTorch (#3106)
  • Correction du bug de création d'un flux cuda comme paramètre par défaut qui sera initialisé lors de l'importation (#3764)
  • Correction d'un bug lié à la création du flux CUDA comme paramètre par défaut, qui sera initialisé lors de l'import (#3764)
  • Correction d'un bug attention DP sur le modèle Qwen3 MoE (#4141)
  • Correction d'un accès mémoire illégal lors de l'exécution de LLaMA 4 avec CUDA Graph activé (#4101)
  • Réinitialiser les états planifiés pour éviter les fuites de mémoire dans TrtllmAttentionWrapper (#4227)

Problèmes connus

  • Prise en charge des modèles multi-GPU sur RTX Pro 6000

TensorRT-LLM v0.20.0

Highlights

  • Scheduling overlap now on by default (breaking) — The most consequential behavioral change: overlap scheduling ships enabled, which alters request scheduling and can shift latency/throughput profiles for existing deployments. The flag was also corrected to enable_overlap_scheduler (#4433), so launch scripts still using the old name will silently lose control of it — audit your configs. In the same vein, the legacy GptSession/V1 TRT path is removed (V1 batching tests dropped in #4703) and _AutoDeployLlmArgs becomes the primary config object, so code built on the old session API or config shape needs migration.
  • Toolchain and dependency jump — This release rebases on PyTorch 2.7.0 (now built with the CXX11 ABI), TensorRT 10.10.0, CUDA 12.9.0, ModelOpt 0.29.0 and datasets 3.1.0, with NCCL held at 2.25.1. The CXX11 ABI switch is the one to watch: out-of-tree C++ extensions and custom plugins must be rebuilt against the new ABI or you'll hit symbol/link mismatches. GCC is downgraded 13→11 and the Triton backend moves into a submodule — both relevant if you build from source. NVIDIA now publishes an official release image on NGC (#4400), the safest route to a consistent stack.
  • Broader model and hardware coverage — Qwen3 (including a fix for missing mrope args in summary tasks, #4432), Nemotron-H, Eagle-3 speculative decoding for Llama4, Mistral Small 3.1 24B VLM, Gemma3-1b-it and HyperCLOVAX-SEED-Vision land, plus DeepSeek-R1 W4A8 on Hopper. RTX Pro 6000 (SM120) gains single-GPU FP8/NVFP4 support for Nemotron Super 49B (#4363, #4548), but multi-GPU on that part remains a known issue — plan single-GPU deployments for now.
  • PyTorch flow approaches parity — The PyTorch backend adds LoRA, return-logits, per-request stats and LogitsProcessor support, and adopts the new logprob definition. That last item is behaviorally significant: logprob values and their contract change, so downstream scoring or cross-backend comparisons should be revalidated rather than assumed identical to the TRT path.
  • New serving and performance levers — Long-context and MoE serving get piecewise CUDA graphs, MLA KV-cache reuse, a KV-cache-aware router for disaggregated serving, chunked context for FlashInfer, a smart MoE router and the overlap scheduler via the TRT executor API. LLM API adds top-K logprobs and prompt_logprobs, and LlmRequest gains a multimodal embedding field — important if you build multimodal serving on trtllm-serve.
  • Stability fixes worth the bump — Several correctness bugs close here: a hang when the context server lacks KV-cache capacity (#3095), illegal memory access with Llama4 under CUDA graphs (#4101), C++ decoder synchronization in PyTorch (#3106) and an attention data-parallel bug on Qwen3 MoE (#4141). If you run disaggregated serving or CUDA-graph-enabled Llama4, these alone justify upgrading.
