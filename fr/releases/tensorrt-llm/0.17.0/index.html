TenseurRT-LLM v0.17.0

Salut, Nous sommes très heureux d'annoncer la version 0.17.0 de TensorRT-LLM. Cette mise à jour comprend :

Principales fonctionnalités et améliorations

  • Support Blackwell
    • REMARQUE : l'installation de pip n'est pas prise en charge pour TRT-LLM 0.17 sur les plates-formes Blackwell uniquement. Au lieu de cela, il est recommandé à l'utilisateur de créer à partir des sources à l'aide du conteneur NVIDIA NGC 25.01 PyTorch.
    • Ajout du support pour B200.
    • Ajout de la prise en charge de la série GeForce RTX 50 utilisant le sous-système Windows pour Linux (WSL) pour les modèles limités.
    • Ajout du support NVFP4 Gemm pour les modèles Llama et Mixtral.
    • Ajout du support NVFP4 pour les commandes LLM API et trtllm-bench.
    • GB200 NVL n'est pas entièrement pris en charge.
    • Ajout d'un script de référence pour mesurer les avantages en termes de performances du déchargement de l'hôte de cache KV avec les améliorations d'exécution attendues du GH200.
  • Flux de travail PyTorch
    • Le workflow PyTorch est une fonctionnalité expérimentale dans tensorrt_llm._torch. Voici une liste des infrastructures, modèles et fonctionnalités pris en charge qui peuvent être utilisés avec le flux de travail PyTorch.
    • Ajout du support pour H100/H200/B200.
    • Ajout de la prise en charge des modèles Llama, Mixtral, QWen, Vila.
    • Ajout de la prise en charge de FP16/BF16/FP8/NVFP4 Gemm et du mélange fusionné d'experts (MOE), FP16/BF16/FP8 KVCache.
    • Ajout de la prise en charge du contexte personnalisé et des noyaux d'attention au décodage via l'opération personnalisée PyTorch.
    • Ajout de la prise en charge du contexte fragmenté (désactivé par défaut).
    • Ajout du support CudaGraph pour le décodage uniquement.
    • Ajout de la prise en charge du planificateur de chevauchement pour chevaucher les entrées de préparation et le modèle en avant en décodant 1 jeton supplémentaire.
  • Ajout de la prise en charge FMHA du contexte FP8 pour le flux de travail de quantification W4A8.
  • Ajout de la prise en charge des points de contrôle quantifiés ModelOpt pour le LLM API.
  • Ajout du support FP8 pour le modèle Llama-3.2 VLM. Reportez-vous à la section « MLLaMA » dans examples/multimodal/README.md.
  • Ajout de la prise en charge PDL pour le noyau de fusion AllReduce-Norm basé sur userbuffer.
  • Ajout de la prise en charge de l'exécution pour un décodage anticipé transparent.
  • Ajout de la prise en charge des tenseurs de sortie arbitraires alignés sur les jetons pour le C++ executor API.

API Modifications

  • [BREAKING CHANGE] La réutilisation du cache KV est activée automatiquement lorsque paged_context_fmha est activé.
  • Ajout du support --concurrency pour la sous-commande throughput de trtllm-bench.

Problèmes résolus

  • Correction d'une dimension de sortie LoRA incorrecte. Merci pour la contribution de @akhoroshev dans #2484.
  • Ajout du GPU NVIDIA H200 dans le cluster_key pour la fonction de parallélisme automatique. (#2552)
  • Correction d'une faute de frappe dans la fonction __post_init__ de la classe LLmArgs. Merci pour la contribution de @topenkoff dans le #2691.
  • Correction d'un problème de taille de l'espace de travail dans le plugin d'attention GPT. Merci pour la contribution de @AIDC-AI.
  • Correction de la précision du modèle Deepseek-V2.

Modifications des infrastructures

  • L'image de base Docker pour TensorRT-LLM est mise à jour vers nvcr.io/nvidia/pytorch:25.01-py3.
  • L'image de base Docker pour le backend TensorRT-LLM est mise à jour vers nvcr.io/nvidia/tritonserver:25.01-py3.
  • La version dépendante de TensorRT est mise à jour vers 10.8.0.
  • La version dépendante de CUDA est mise à jour vers 12.8.0.
  • La version dépendante de ModelOpt est mise à jour vers 0.23 pour la plateforme Linux, tandis que 0.17 est toujours utilisée sur la plateforme Windows.

Problèmes connus

  • Besoin de --extra-index-url https://pypi.nvidia.com lors de l'exécution de pip install tensorrt-llm en raison de nouvelles dépendances tierces.
  • La roue PYPI SBSA est incompatible avec PyTorch 2.5.1 en raison d'une rupture dans le PyTorch ABI/API, comme détaillé dans le [problème GitHub] (https://github.com/pytorch/pytorch/issues/144966) associé.

TensorRT-LLM v0.17.0

Highlights

  • Blackwell support, with a source-build caveat — B200 is now supported alongside NVFP4 GEMM for Llama/Mixtral and NVFP4 exposure through the LLM API and trtllm-bench. The important catch: pip installation is not supported on Blackwell for 0.17 — you must build from source in the NVIDIA NGC 25.01 PyTorch container. GB200 NVL is only partially supported, and RTX 50-series is WSL-only with a limited model set, so plan capacity and build strategy accordingly.
  • Experimental PyTorch workflow lands — tensorrt_llm._torch adds a new path covering H100/H200/B200 and Llama, Mixtral, QWen, and Vila, with FP16/BF16/FP8/NVFP4 GEMM, fused MoE, custom attention kernels via PyTorch custom ops, and an overlap scheduler that prefetches one extra token to hide input prep. Watch the sharp edges: it's explicitly experimental, chunked context is default off, and CUDA graphs are decode-only — don't assume backend parity yet.
  • KV cache reuse becomes implicit — breaking behavior — When paged_context_fmha is enabled, KV cache reuse is now turned on automatically. This is the release's only flagged breaking change and it alters memory and request semantics for anyone who deliberately kept reuse disabled: audit your configs and re-benchmark cache footprint before upgrading.
  • Quantized-serving gaps close — ModelOpt-quantized checkpoints are now accepted directly by the LLM API, FP8 context FMHA is added for the W4A8 workflow, and Llama-3.2 VLM gains FP8 support (see the "MLLaMA" section in examples/multimodal/README.md). Together these reduce the manual engine-rebuilding work needed to serve quantized models.
  • Decoding and executor-level additions — Seamless lookahead decoding gains runtime support, the C++ executor API gets token-aligned arbitrary output tensors, PDL support arrives for the userbuffer-based AllReduce-Norm fusion kernel, and trtllm-bench throughput gains --concurrency. Relevant if you're doing speculative decoding, low-level executor integration, or concurrency-sensitive benchmarking.
  • Infrastructure shifts and install pitfalls — Base images move to pytorch:25.01-py3 / tritonserver:25.01-py3, with TensorRT 10.8.0, CUDA 12.8.0, and ModelOpt 0.23 on Linux (still 0.17 on Windows). pip install now requires --extra-index-url https://pypi.nvidia.com, and the SBSA wheel is incompatible with PyTorch 2.5.1 due to an ABI break — pin away from 2.5.1. Fix highlights include the LoRA output dimension (#2484), H200 added to cluster_key for auto-parallelism (#2552), and Deepseek-V2 accuracy.

Hi,

We are very pleased to announce the 0.17.0 version of TensorRT-LLM. This update includes:

Key Features and Enhancements

  • Blackwell support
    • NOTE: pip installation is not supported for TRT-LLM 0.17 on Blackwell platforms only. Instead, it is recommended that the user build from source using NVIDIA NGC 25.01 PyTorch container.
    • Added support for B200.
    • Added support for GeForce RTX 50 series using Windows Subsystem for Linux (WSL) for limited models.
    • Added NVFP4 Gemm support for Llama and Mixtral models.
    • Added NVFP4 support for the LLM API and trtllm-bench command.
    • GB200 NVL is not fully supported.
    • Added benchmark script to measure perf benefits of KV cache host offload with expected runtime improvements from GH200.
  • PyTorch workflow
    • The PyTorch workflow is an experimental feature in tensorrt_llm._torch. The following is a list of supported infrastructure, models, and features that can be used with the PyTorch workflow.
    • Added support for H100/H200/B200.
    • Added support for Llama models, Mixtral, QWen, Vila.
    • Added support for FP16/BF16/FP8/NVFP4 Gemm and fused Mixture-Of-Experts (MOE), FP16/BF16/FP8 KVCache.
    • Added custom context and decoding attention kernels support via PyTorch custom op.
    • Added support for chunked context (default off).
    • Added CudaGraph support for decoding only.
    • Added overlap scheduler support to overlap prepare inputs and model forward by decoding 1 extra token.
  • Added FP8 context FMHA support for the W4A8 quantization workflow.
  • Added ModelOpt quantized checkpoint support for the LLM API.
  • Added FP8 support for the Llama-3.2 VLM model. Refer to the “MLLaMA” section in examples/multimodal/README.md.
  • Added PDL support for userbuffer based AllReduce-Norm fusion kernel.
  • Added runtime support for seamless lookahead decoding.
  • Added token-aligned arbitrary output tensors support for the C++ executor API.

API Changes

  • [BREAKING CHANGE] KV cache reuse is enabled automatically when paged_context_fmha is enabled.
  • Added --concurrency support for the throughput subcommand of trtllm-bench.

Fixed Issues

  • Fixed incorrect LoRA output dimension. Thanks for the contribution from @akhoroshev in #2484.
  • Added NVIDIA H200 GPU into the cluster_key for auto parallelism feature. (#2552)
  • Fixed a typo in the __post_init__ function of LLmArgs Class. Thanks for the contribution from @topenkoff in #2691.
  • Fixed workspace size issue in the GPT attention plugin. Thanks for the contribution from @AIDC-AI.
  • Fixed Deepseek-V2 model accuracy.

Infrastructure Changes

  • The base Docker image for TensorRT-LLM is updated to nvcr.io/nvidia/pytorch:25.01-py3.
  • The base Docker image for TensorRT-LLM Backend is updated to nvcr.io/nvidia/tritonserver:25.01-py3.
  • The dependent TensorRT version is updated to 10.8.0.
  • The dependent CUDA version is updated to 12.8.0.
  • The dependent ModelOpt version is updated to 0.23 for Linux platform, while 0.17 is still used on Windows platform.

Known Issues

  • Need --extra-index-url https://pypi.nvidia.com when running pip install tensorrt-llm due to new third-party dependencies.
  • The PYPI SBSA wheel is incompatible with PyTorch 2.5.1 due to a break in the PyTorch ABI/API, as detailed in the related GitHub issue.
