TenseurRT-LLM v0.16.0

Salut, Nous sommes très heureux d'annoncer la version 0.16.0 de TensorRT-LLM. Cette mise à jour comprend :

Principales fonctionnalités et améliorations

  • Ajout de la prise en charge du décodage guidé avec le backend XGrammar.
  • Ajout du support de quantification pour RecurrentGemma. Reportez-vous à examples/recurrentgemma/README.md.
  • Ajout du support parallèle du contexte Ulysse. Reportez-vous à un exemple de construction de LLaMA 7B en utilisant le parallélisme tenseur bidirectionnel et le parallélisme contextuel bidirectionnel sur examples/llama/README.md.
  • Ajout du support de quantification W4A8 aux modèles BF16 sur Ada (SM89).
  • Ajout du support PDL pour les plugins FP8 GEMM.
  • Ajout d'une fonctionnalité de réglage dynamique d'exécution max_num_tokens, qui peut être activée en réglant --enable_max_num_tokens_tuning sur gptManagerBenchmark.
  • Ajout du support d'acceptation typique pour EAGLE.
  • Prise en charge du contexte fragmenté et de l'attention de la fenêtre coulissante à activer ensemble.
  • Ajout de la prise en charge de la taille de tête 64 pour le noyau XQA.
  • Ajout des fonctionnalités suivantes au LLM API :
    • Décodage anticipé.
    • Prise en charge de DeepSeek V1.
    • Prise en charge Méduse.
    • Arguments max_num_tokens et max_batch_size pour contrôler les paramètres d'exécution.
    • extended_runtime_perf_knob_config pour permettre diverses configurations de performances.
  • Ajout de la prise en charge de la mise à l'échelle LogN pour les modèles Qwen.
  • Ajout de la prise en charge des points de contrôle AutoAWQ pour Qwen. Reportez-vous à la section « INT4-AWQ » dans examples/qwen/README.md.
  • Ajout de la prise en charge des points de contrôle AutoAWQ et AutoGPTQ Hugging Face pour LLaMA. (#2458)
  • Ajout de allottedTimeMs à la classe C++ Request pour prendre en charge le délai d'attente par requête.
  • [CHANGEMENT RUPTURE] Suppression de la prise en charge du GPU NVIDIA V100.

API Modifications

  • [CHANGEMENT RUPTURE] Suppression de l'argument enable_xqa de trtllm-build.
  • [CHANGEMENT RUPTURE] Le contexte fragmenté est activé par défaut lorsque le cache KV et le contexte paginé FMHA sont activés sur les modèles non basés sur RNN.
  • [CHANGEMENT RUPTURE] Activation de l'intégration automatique du partage lorsque cela est possible et suppression de l'indicateur --use_embedding_sharing des scripts de conversion de points de contrôle.
  • [CHANGEMENT RUPTURE] Le point d'entrée if __name__ == "__main__" est requis pour les cas mono-GPU et multi-GPU lors de l'utilisation du LLM API.
  • [CHANGEMENT RUPTURE] Les requêtes annulées renvoient désormais des résultats vides.
  • Ajout du drapeau enable_chunked_prefill au LlmArgs du LLM API.
  • Modèles BERT et RoBERTa intégrés à la commande trtllm-build. ### Mises à jour du modèle
  • Ajout du support Qwen2-VL. Reportez-vous à la section « Qwen2-VL » du examples/multimodal/README.md.
  • Ajout d'exemples d'évaluation multimodale. Reportez-vous à examples/multimodal.
  • Ajout du support Stable Diffusion XL. Reportez-vous au examples/sdxl/README.md. Merci pour la contribution de @Zars19 dans #1514.

Problèmes résolus

  • Correction des appels de post-processeur de journaux de lots inutiles. (#2439)
  • Correction d'une faute de frappe dans le message d'erreur. (#2473)
  • Correction de l'utilisation du fonctionnement de la pince sur place en quantité fluide. Merci pour la contribution de @StarrickLiu dans #2485.
  • Correction de sampling_params pour qu'il ne soit configuré que si end_id est Aucun et tokenizer n'est pas Aucun dans le LLM API. Merci à la contribution de @mfuntowicz dans #2573.

Modifications des infrastructures

  • Mise à jour de l'image de base Docker pour TensorRT-LLM vers nvcr.io/nvidia/pytorch:24.11-py3.
  • Mise à jour de l'image de base Docker pour le backend TensorRT-LLM vers nvcr.io/nvidia/tritonserver:24.11-py3.
  • Mise à jour vers TensorRT v10.7.
  • Mise à jour vers CUDA v12.6.3.
  • Ajout de la prise en charge des roues Python 3.10 et 3.12 sur les roues TensorRT-LLM Python sur PyPI.
  • Mise à jour vers ModelOpt v0.21 pour la plateforme Linux, tandis que v0.17 est toujours utilisé sur la plateforme Windows.

Problèmes connus

  • Il existe un problème de performances AllReduce connu sur les plates-formes CPU AMD sur NCCL 2.23.4, qui peut être résolu par export NCCL_P2P_LEVEL=SYS. Nous mettons régulièrement à jour la branche main avec de nouvelles fonctionnalités, des corrections de bugs et des optimisations de performances. La branche rel sera mise à jour moins fréquemment et les fréquences exactes dépendent de vos retours. Merci, L'équipe d'ingénierie TensorRT-LLM

Anglais original / English original

TensorRT-LLM v0.16.0

Highlights

  • Broader model and quantization support — Adds Qwen2-VL and SDXL, RecurrentGemma quantization, Qwen AutoAWQ/INT4-AWQ checkpoints, and LLaMA AutoAWQ/AutoGPTQ loading (#2458). W4A8 quantization for BF16 models is also available on Ada/SM89, giving adopters more deployment options, but checkpoint format, model architecture, and GPU compatibility still need validation against the referenced examples.

  • More decoding and attention strategies — XGrammar adds a guided-decoding backend, EAGLE gains typical-acceptance support, and the LLM API adds lookahead decoding and Medusa. Chunked context and sliding-window attention can now be enabled together. These options expand structured-output and speculative-decoding workflows, but output quality and latency should be benchmarked for each combination.

  • Additional runtime performance controls — The LLM API exposes max_num_tokens, max_batch_size, and extended_runtime_perf_knob_config; gptManagerBenchmark --enable_max_num_tokens_tuning enables dynamic token-budget tuning. FP8 GEMM plugins gain PDL support, XQA supports head size 64, and Ulysses context parallelism is available. Treat tuning and advanced knobs as workload-specific optimizations rather than universally safe defaults.

  • Breaking build and entry-point changes — NVIDIA V100 support is removed, trtllm-build no longer accepts enable_xqa, and --use_embedding_sharing is removed because sharing is now enabled automatically when possible. Scripts using the LLM API must also define an if __name__ == "__main__": entry point for both single- and multi-GPU execution.

  • Request and prefill behavior changes — Chunked context is now enabled by default when KV cache and paged-context FMHA are enabled on non-RNN models; use enable_chunked_prefill in LlmArgs to control it explicitly. Cancelled requests now return empty results, so cancellation handling must not assume partial output. The sampling_params setup fix (#2573) also changes behavior for calls where end_id or the tokenizer is absent.

  • Toolchain upgrade and NCCL workaround — The release moves to TensorRT 10.7, CUDA 12.6.3, PyTorch 24.11, and Triton Server 24.11 base images; Python wheels add 3.10 and 3.12 support. Linux uses ModelOpt 0.21 while Windows remains on 0.17, so quantization environments are no longer version-aligned. AMD-CPU hosts using NCCL 2.23.4 may need export NCCL_P2P_LEVEL=SYS to mitigate a known AllReduce performance issue.

Hi,

We are very pleased to announce the 0.16.0 version of TensorRT-LLM. This update includes:

Key Features and Enhancements

  • Added guided decoding support with XGrammar backend.
  • Added quantization support for RecurrentGemma. Refer to examples/recurrentgemma/README.md.
  • Added ulysses context parallel support. Refer to an example on building LLaMA 7B using 2-way tensor parallelism and 2-way context parallelism at examples/llama/README.md.
  • Added W4A8 quantization support to BF16 models on Ada (SM89).
  • Added PDL support for the FP8 GEMM plugins.
  • Added a runtime max_num_tokens dynamic tuning feature, which can be enabled by setting --enable_max_num_tokens_tuning to gptManagerBenchmark.
  • Added typical acceptance support for EAGLE.
  • Supported chunked context and sliding window attention to be enabled together.
  • Added head size 64 support for the XQA kernel.
  • Added the following features to the LLM API:
    • Lookahead decoding.
    • DeepSeek V1 support.
    • Medusa support.
    • max_num_tokens and max_batch_size arguments to control the runtime parameters.
    • extended_runtime_perf_knob_config to enable various performance configurations.
  • Added LogN scaling support for Qwen models.
  • Added AutoAWQ checkpoints support for Qwen. Refer to the “INT4-AWQ” section in examples/qwen/README.md.
  • Added AutoAWQ and AutoGPTQ Hugging Face checkpoints support for LLaMA. (#2458)
  • Added allottedTimeMs to the C++ Request class to support per-request timeout.
  • [BREAKING CHANGE] Removed NVIDIA V100 GPU support.

API Changes

  • [BREAKING CHANGE] Removed enable_xqa argument from trtllm-build.
  • [BREAKING CHANGE] Chunked context is enabled by default when KV cache and paged context FMHA is enabled on non-RNN based models.
  • [BREAKING CHANGE] Enabled embedding sharing automatically when possible and remove the flag --use_embedding_sharing from convert checkpoints scripts.
  • [BREAKING CHANGE] The if __name__ == "__main__" entry point is required for both single-GPU and multi-GPU cases when using the LLM API.
  • [BREAKING CHANGE] Cancelled requests now return empty results.
  • Added the enable_chunked_prefill flag to the LlmArgs of the LLM API.
  • Integrated BERT and RoBERTa models to the trtllm-build command.

Model Updates

  • Added Qwen2-VL support. Refer to the “Qwen2-VL” section of examples/multimodal/README.md.
  • Added multimodal evaluation examples. Refer to examples/multimodal.
  • Added Stable Diffusion XL support. Refer to examples/sdxl/README.md. Thanks for the contribution from @Zars19 in #1514.

Fixed Issues

  • Fixed unnecessary batch logits post processor calls. (#2439)
  • Fixed a typo in the error message. (#2473)
  • Fixed the in-place clamp operation usage in smooth quant. Thanks for the contribution from @StarrickLiu in #2485.
  • Fixed sampling_params to only be setup if end_id is None and tokenizer is not None in the LLM API. Thanks to the contribution from @mfuntowicz in #2573.

Infrastructure Changes

  • Updated the base Docker image for TensorRT-LLM to nvcr.io/nvidia/pytorch:24.11-py3.
  • Updated the base Docker image for TensorRT-LLM Backend to nvcr.io/nvidia/tritonserver:24.11-py3.
  • Updated to TensorRT v10.7.
  • Updated to CUDA v12.6.3.
  • Added support for Python 3.10 and 3.12 to TensorRT-LLM Python wheels on PyPI.
  • Updated to ModelOpt v0.21 for Linux platform, while v0.17 is still used on Windows platform.

Known Issues

  • There is a known AllReduce performance issue on AMD-based CPU platforms on NCCL 2.23.4, which can be workarounded by export NCCL_P2P_LEVEL=SYS.

We are updating the main branch regularly with new features, bug fixes and performance optimizations. The rel branch will be updated less frequently, and the exact frequencies depend on your feedback.

Thanks, The TensorRT-LLM Engineering Team
