TensorRT-LLM version 0.21.0

  • Caractéristiques

    • Ajout de la prise en charge de la mémoire Fabric pour le transfert de cache KV
    • Ajout de MCP dans ScaffoldingLLM
    • Ajout du support pour la quantification w4a8_mxfp4_fp8
    • Ajout de la prise en charge de la quantification par lignes fp8
    • Ajout de la prise en charge des logits de génération dans TRTLLM Sampler
    • Ajout de la prise en charge des problèmes de journal dans TRTLLM Sampler
    • Optimisation de la performance de l'échantillonneur TRTLLM à faisceau unique en une seule étape
    • Activation du service désagrégé pour Qwen-3
    • Ajout du support EAGLE3 pour Qwen-3
    • Finalisation et allreduce fusionnés pour le modèle Qwen-MoE
    • Module MoE fusionné refactorisé
    • Ajout de la prise en charge de l'attention groupée sur Blackwell et Hopper
    • Introduction de noyaux d'attention à fenêtre coulissante pour la phase de génération sur Blackwell

    • Ajout du support GEMM à l'échelle du bloc FP8 sur SM89
    • Activation du planificateur de chevauchement entre les projets de transfert
    • Ajout de la prise en charge du graphique cuda par morceaux pour MLA
    • Ajout d'eagle3 monomoteur indépendant du modèle
    • Activé Finaliser + Allreduce + ajouter + fusion rmsnorm

    • Ajout de la prise en charge de la diffusion désagrégée Eagle3 + dans deux modèles de flux de décodage spéculatif
    • Modèles Llama 3.1 validés sur H200 NVL
  • Benchmark :
    • Ajout du script de référence all_reduce.py pour les tests
    • Ajout de la largeur du faisceau à la commande de latence trtllm-bench
    • Correction des erreurs trtllm-bench iter_stats et cuda_graph_batch_sizes
    • Activation de trtllm-bench pour exécuter LoRA et ajouter une capacité de test de performances e2e de base pour LoRA
    • Post_proc pris en charge pour le banc
    • Ajout de l'option no_kv_cache_reuse et prise en charge du streaming pour le banc de service trtllm

Modifications des infrastructures

  • L'image de base Docker pour TensorRT-LLM est mise à jour vers nvcr.io/nvidia/pytorch:25.05-py3.
  • L'image de base Docker pour le backend TensorRT-LLM est mise à jour vers nvcr.io/nvidia/tritonserver:25.05-py3.
  • La version publique dépendante de PyTorch est mise à jour vers 2.7.1.
  • La version dépendante de TensorRT est mise à jour vers 10.11.
  • La version dépendante de NVIDIA ModelOpt est mise à jour vers 0.31.
  • La version NCCL dépendante est mise à jour vers 2.27.5.

Modifications du API

  • Définir _AutoDeployLlmArgs comme objet de configuration principal
  • Suppression de la demande de décodeur de l'interface du décodeur
  • Amélioration de torch_compile_config dans les arguments llm
  • Suppression du champ use_kv_cache redondant de PytorchConfig
  • Déplacement de allreduce_strategy de api engagé vers la référence

Problèmes résolus

  • Correction du blocage du service désagrégé lorsque AllReduce à deux coups MNNVL est activé (# 4678)
  • Correction de l'équilibreur de charge EP avec couche MTP et décalage de route par rang EP (#4767)
  • Correction du remplissage du graphique cuda pour le décodage des spécifications (#4853)
  • Correction du problème de contexte long de Lama 4 (#4809)
  • Correction du calcul de max_num_sequences avec planification de chevauchement (#4532)
  • Correction du pré-remplissage fragmenté + planification de chevauchement (#5761)
  • Correction du problème de blocage de trtllm-bench dû à LLM API IPC (#4798)
  • Correction d'une erreur d'index hors limites dans le décodage des spécifications (#5954)
  • Correction de l'accès mémoire illégal MTP lors de l'échauffement du graphique cuda (# 5947)
  • Correction d'une erreur d'absence d'emplacements libres avec le décodage des spécifications + disagg (#5975)
  • Correction de la taille de la fenêtre d'attention unique pour Gemma3 1B (#5564)

Problèmes connus

  • précision/test_cli_flow::TestGpt2::test_beam_search_large est cassé.
  • L'activation simultanée du service désagrégé, du MTP et du planificateur de chevauchement peut entraîner des problèmes de précision.
  • Dans 0.21, une prise en charge complète de l'attention fragmentée a été ajoutée pour garantir que le modèle LLaMA4 peut fonctionner fonctionnellement avec une longueur de séquence > 8 000, alors qu'il existe une régression des performances connue (affecte uniquement le modèle LLaMA4) sur Hopper en raison de cette amélioration fonctionnelle. La cause première de la régression a déjà été identifiée et le correctif fera partie de la prochaine version.

TensorRT-LLM v0.21.0

Highlights

  • Breaking API reshuffle in the LLM stack — Config construction needs attention on upgrade: _AutoDeployLlmArgs becomes the primary config object, the decoder request is removed from the decoder interface, the redundant use_kv_cache field is dropped from PytorchConfig, allreduce_strategy moves from the committed API to reference, and the monolithic LLM class is split into TorchLLM/TrtLLM (#4900). TorchCompileConfig fields also lose their torch_compile prefix (#5261), so any code reading those attributes by name will break. Budget migration time for config and wrapper code, not just a version bump.

  • Disaggregated serving moves toward production transport — NIXL is now integrated into the disaggregated service's communication layer, joined by fabric-memory KV cache transfer and large-scale EP support. Stability work targets real deployment hazards: a hang when MNNVL two-shot AllReduce is enabled (#4678) and the "no free slots" failure under spec-decode + disagg (#5975) are fixed. Watch out for the documented accuracy problem when disaggregated serving, MTP, and the overlap scheduler are enabled together — that combination is not yet safe.

  • Speculative decoding gets a broader, sturdier footing — EAGLE3 lands for Qwen3 (#5206), alongside a model-agnostic one-engine EAGLE3 path and overlap scheduling between draft forwards; draft-target decoding also moves into the new framework (#4558). The long tail of correctness fixes matters more than the headline features here: CUDA-graph padding (#4853), an index-out-of-bounds in spec decoding (#5954), and an MTP illegal-memory-access during graph warmup (#5947) are all addressed, with piecewise CUDA graph support for MLA (#4467) improving graph coverage. If you were holding off on spec decode for stability reasons, this is the release to re-evaluate.

  • Model and quantization coverage expands, with a Hopper caveat — New entry points include Gemma3 VLM, Qwen3 disaggregated serving, w4a8_mxfp4_fp8 and fp8 rowwise quantization, FP8 block-scale GEMM on SM89 (Ada), and TRT-LLM Gen FP8 block-scale MoE wired into the PyTorch autotuner (#5207). LLaMA4 >8K sequences now run via full chunked attention, but that functional win carries a known performance regression on Hopper affecting LLaMA4 only, with the fix deferred to a future release — benchmark before committing to H100-class deployments. Two off-by-one/context bugs worth noting are fixed: Gemma3 1B attention window size (#5564) and Llama 4 long context (#4809).

  • Container and dependency baseline jumps to NGC 25.05 — Base images move to pytorch:25.05-py3 and tritonserver:25.05-py3, with PyTorch 2.7.1, TensorRT 10.11, ModelOpt 0.31, and NCCL 2.27.5. This is the most likely source of environment-level breakage: custom Dockerfiles and pinned host NCCL/driver combinations should be rebuilt and revalidated rather than assumed compatible.

  • Sampler and benchmark tooling get developer-facing upgrades — The TRTLLM Sampler gains generation logits, log probs, and a single-beam/single-step performance optimization, while LlmResponse is reimplemented in Python to cut pybind host overhead (#5224). Benchmarking closes several gaps that previously distorted measurements: trtllm-bench gains beam-width control, LoRA end-to-end testing, no_kv_cache_reuse, and streaming, plus fixes to iter_stats and cuda_graph_batch_sizes errors and an IPC hang (#4798). Expect cleaner perf data, but note that old benchmark scripts may need flag updates.
