argo-cd v3.5.8

Highlights

  • ApplicationSet refresh no longer rewrites the object — #31028 (cherry-pick of #31023, originally #24378/#24647) makes refresh patch only the refresh annotation instead of re-applying the whole ApplicationSet. That stops a refresh from clobbering concurrent edits to the spec from another controller or a Git write, and removes the API churn and conflict retries that came with full-object updates. Watch out: refresh is now purely a reconcile nudge — it won't normalize or reset any other field as a side effect.
  • AppProject destination deny rules actually deny now — #30894 (cherry-pick of #30884) fixes negated destination matchers (!name, !server), which previously emitted a veto even when the destination positively matched an allowed entry. This is the one to pay attention to: apps that were inexplicably "denied" despite an explicit allow will sync again, but if you were leaning on that buggy veto as an extra safety net, your effective policy is now looser. Audit spec.destinations on your AppProjects after upgrading.
  • Security: regexp2 CVE plus a major-version bump — #31027 takes dlclark/regexp2 from v1.12.0 to v2.13.0 for CVE-2026-77299, and #30917 moves go-jose/v4 to 4.1.6. regexp2 backs Argo CD's wildcard/glob matching, so this is a ReDoS-class fix worth taking even on a patch release. The v1→v2 jump is absorbed upstream, so there's nothing to change in your manifests — but if you vendor either module or depend on them directly in your own tooling, align your versions too.
  • Multi-cluster memory footprint drops — #30831 (cherry-pick of #30811, from #30810) stops gitops-engine retaining the decoded OpenAPI document per cluster. That schema doc is large and was held for every managed cluster, so control planes with dozens of clusters should see materially lower steady-state memory. No configuration needed; this alone is a good reason to roll out v3.5.8 if you've been fighting memory pressure or OOM restarts.
  • UI: tree and header readability — #30774 fixes group-node spacing in the tree view, and #30838 truncates top-bar breadcrumbs and titles instead of letting them overlap. Cosmetic, but the header fix matters if you run deeply nested projects or work in narrow windows, where the title bar previously became unreadable.
  • Toolchain refresh — #30916 moves the build to Go 1.26.11, #30920 updates OpenTelemetry to v1.46.0, and #31051 upgrades git-lfs to 3.8.1. Relevant if you build Argo CD or plugins from source (match the Go version); otherwise transparent, though the otel bump is worth a glance if your tracing pipeline pins specific semantic conventions.

No breaking changes in this release.
