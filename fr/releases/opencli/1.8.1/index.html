OpenCLI v1.8.1

Highlights

  • Broader CLI coverage — Jira/Confluence support (#1690), Upwork search/feed/detail commands (#1609), Chess.com stats/games/game/analyze (#1659), GeoGebra browser adapters (#1591), and WeRead in-book search (#1577) expand automation into team and research workflows. Bilibili also adds comment reads and --parent reply-thread access (#1588), enabling discussion-level collection beyond video metadata.
  • NotebookLM moves from retrieval to authoring — New create, add-source, write-note, generate-audio, and generate-slides commands (#1691) let scripts build notebooks and generate media. Treat these as side-effecting operations, not ordinary read commands.
  • LinkedIn and Xiaohongshu results are more complete — LinkedIn consolidates profile/jobs/posts/projects readers and adds profile experience (#1731, #1738), reducing output fragmentation. Xiaohongshu paginates creator notes beyond the 10-row /analyze/list cap (#1736), preserves carousel ordering (#1687), and captures signed note responses (#1732), reducing truncated or misordered downstream datasets.
  • Adapter data handling changes — X/Twitter no longer emits the literal "unknown" for unavailable search/notifications/following row fields (#1776), so parsers should handle missing values instead. Suno now derives plan information from subscription_type plus plans[] rather than legacy data.plan (#1706); integrations examining raw responses should follow the new shape.
  • Browser automation and local credentials are hardened — Serialized tab-group creation (#1693) and convergence of owned groups (#1794) reduce duplicate or stale groups, shipped with extension 1.0.16 (#1792). Separately, yt-dlp cookie files and browser network caches now use owner-only 0o600 permissions (#1742, #1766), protecting session data from other local users.
  • Breaking changes — None declared; Node.js >=20 remains required (#1705).

What's Changed
