KTransformateurs 0.7.0.post4

Formation LoRA par texte Kimi K2.5, reprise du point de contrôle et chargement de l'adaptateur SGLang avec des experts routés RAWINT4 natifs. ##Installation Python 3.11 / 3.12 Commencez par le [guide étape par étape] (https://github.com/yyj6666667/ktransformers/blob/14fd5a28f1d1160d521bcb7d1f1275d63f9953f7/.github/release/examples/kimi-k25/README.md) et le [kit utilisateur r2] (https://github.com/kvcache-ai/ktransformers/releases/download/v0.7.0.post4/kimi-k25-post4-user-kit-r2.tar.gz). Vérifiez SHA256SUMS-r2.txt avant de l'extraire. Le guide mis à jour est suivi dans PR #2207. Le kit contient trois YAML, des outils de préparation de données et de conversion LoRA, ainsi que des verrous de dépendance Python 3.11 / 3.12 séparés. Seuls les chemins de modèle et de sortie doivent être modifiés. Les packages de base s'installent à partir de PyPI ; la roue de branche LF approuvée et les roues PEFT/TRL réservées aux métadonnées sont fournies avec le kit. N’installez pas de packages Transformers/Accelerate en amont qui se chevauchent dans ces environnements.

  • Linux x86_64, glibc 2.35+, Python 3.11 ou 3.12, CUDA 12.8, Torch 2.9.1.
  • Matériel validé : double AMD EPYC 9355, environ 1.5 TiB RAM ; 8 GPU RTX 5090 pour la formation et 4 pour l'inférence. Il ne s’agit pas d’une réclamation de spécifications minimales.
  • ktransformers / kt-kernel / sglang-kt 0.7.0.post4 ; transformateurs-kt 5.6.0.post5 ; accélérer-kt 1.14.0.post3.
  • L'emballage est désactivé. Utilisez le modèle original épinglé et l’étape explicite de préparation des données. Les hôtes sans accès à Hugging Face doivent obtenir les instantanés de modèle/données épinglés séparément. Le supplément du 14 septembre ajoute une vraie roue CPython 3.11, y compris les fixations natives correspondantes. Les versions existantes, les fichiers originaux à cinq roues et le kit r1 sont inchangés. Python 3.11 nécessite r2 ; ne réutilisez pas les fichiers de verrouillage r1 Python 3.12 et ne renommez pas une roue cp312. Si un miroir n'a pas synchronisé le nouveau fichier, utilisez l'index officiel PyPI.

Validation et portée

Les environnements candidats propres distincts Python 3.11 et 3.12 ont réussi la formation de base Kimi, un nouveau processus de reprise très précis sur 20 comparaisons d'état, une conversion LoRA ordinaire/expert et une nouvelle génération SGLang avec les 60 couches expert-LoRA chargées. La reconstruction indépendante du Python 3.12 à conduite gelée a également réussi. Les preuves des candidats et les références de sources figées sont incluses dans r2. Le cycle de vie public-PyPI original du Python 3.12 s'est terminé le 13 septembre ; voir PUBLIC_WHEEL_VERIFICATION.json. L'installation de r2 après la publication et la vérification du cycle de vie sont désormais en cours ; la publication à elle seule n’est pas comptabilisée comme l’achèvement de ce contrôle. Le point de contrôle Neko-100 formé séparément a été rechargé dans les deux versions Python et a complété 32 réponses retenues par version avec le texte correspondant. Il affiche le style souhaité, mais échoue toujours à certaines vérifications strictes de format et de qualité du contenu. La formation à la fumée en quatre étapes ne constitue pas une expérience complète de convergence de style ni une garantie générale de qualité/sécurité. La validation des versions antérieures couvrait la formation/inférence Qwen3-30B-A3B BF16, la formation FP8 native DeepSeek-V3.1 et l'inférence de texte GLM next-0808 désignée par l'utilisateur ; ceux-ci n'ont pas été répétés pour ce supplément Python. K2.5 est validé matériellement. Le chemin de l'architecture partagée de K2.6 n'a pas été testé séparément sur le matériel. La formation visuelle, les autres architectures et les longueurs de séquence arbitraires ne sont pas certifiées ici. L'équivalence de la source originale reste enregistrée dans main-equivalence.json. Les roues reconstruites indépendamment de la même version ne remplacent pas les artefacts publiés.

ktransformers v0.7.0.post4

KTransformers 0.7.0.post4

Kimi K2.5 text LoRA training, checkpoint resume, and SGLang adapter loading with native RAWINT4 routed experts.

Python 3.11 / 3.12 installation

Start with the step-by-step guide and the r2 user kit. Check SHA256SUMS-r2.txt before extracting it. The updated guide is tracked in PR #2207.

The kit contains three YAMLs, data preparation and LoRA conversion tools, and separate Python 3.11 / 3.12 dependency locks. Only model and output paths need changing. Core packages install from PyPI; the approved LF branch wheel and metadata-only PEFT/TRL wheels are bundled with the kit. Do not install overlapping upstream Transformers/Accelerate packages into these environments.

  • Linux x86_64, glibc 2.35+, Python 3.11 or 3.12, CUDA 12.8, Torch 2.9.1.
  • Validated hardware: dual AMD EPYC 9355, approximately 1.5 TiB RAM; 8 RTX 5090 GPUs for training and 4 for inference. This is not a minimum-spec claim.
  • ktransformers / kt-kernel / sglang-kt 0.7.0.post4; transformers-kt 5.6.0.post5; accelerate-kt 1.14.0.post3.
  • Packing is disabled. Use the pinned original model and explicit data-preparation step. Hosts without Hugging Face access must obtain the pinned model/data snapshots separately.

The September 14 supplement adds one real CPython 3.11 wheel, including matching native bindings. Existing versions, the original five wheel files, and the r1 kit are unchanged. Python 3.11 requires r2; do not reuse the r1 Python 3.12 lock files or rename a cp312 wheel. If a mirror has not synchronized the new file, use the official PyPI index.

Validation and scope

Separate Python 3.11 and 3.12 clean candidate environments passed Kimi base training, bit-exact new-process resume across 20 state comparisons, ordinary/expert LoRA conversion, and fresh SGLang generation with all 60 expert-LoRA layers loaded. The independent frozen-main Python 3.12 rebuild also passed. Candidate evidence and frozen source references are included in r2.

The original Python 3.12 public-PyPI lifecycle passed on September 13; see PUBLIC_WHEEL_VERIFICATION.json. Post-publication r2 installation and lifecycle verification is now running; publication alone is not reported as completion of that check.

The separately trained Neko checkpoint-100 was reloaded in both Python versions and completed 32 held-out answers per version with matching text. It displays the intended style, but still fails some strict-format and content-quality checks. Four-step smoke training is not a full style-convergence experiment or a general-quality/safety guarantee.

Earlier release validation covered Qwen3-30B-A3B BF16 training/inference, DeepSeek-V3.1 native FP8 training, and user-designated GLM next-0808 text inference; these were not repeated for this Python supplement. K2.5 is hardware-validated. K2.6's shared architecture path was not separately hardware-tested. Vision training, other architectures, and arbitrary sequence lengths are not certified here.

Original source equivalence remains recorded in main-equivalence.json. Same-version independently rebuilt wheels do not replace published artifacts.
