activepieces 0.91.0

Highlights

  • Agents become first-class, self-modifying flow steps — A flow step can now run a saved agent (#14934), and you can configure an agent in place and let it change itself (#15400). The important part is the guardrails that shipped with it: an agent is blocked from rewriting itself based on a page it read (#15380), and every action it takes now lands in the audit log (#15362). Treat that as a real security boundary, not just telemetry. The Run Agent step also works again on community edition (#15372), so self-hosters finally get the feature.

  • Breaking: legacy product-embed removed, auth and provider rules tightened — The legacy product-embed feature is gone (#15383); anyone embedding Activepieces that way must migrate. Kimai now uses Bearer-token auth and its activity dropdown ignores the project filter (#15459). Custom AI providers that could never actually be called are now rejected (#15350), and agent steps no longer fail on reasoning-required models (#15346). Net effect: configs that previously "worked" by accident will now error loudly — audit provider and connection configs before upgrading.

  • Breaking: group-assigned runs stay on the group queue (#15498) — When no group worker is online, group-assigned runs are kept on the group queue instead of being reassigned. For self-hosted worker fleets this is a behavioral change: make sure a group worker is actually available or expect those runs to wait rather than be picked up by the general pool.

  • Flow schema v26 and the end of request bodies on GETs — Flows on http piece 0.11.11–16 are migrated to 0.11.21 (#15329): GETs with bodies are rejected and request headers are no longer lowercased. This is a coordinated sweep, not a one-off — body inputs hidden for GET/HEAD (#15398), ConvertKit api_secret moved to the query string (#15451), Talkable site_slug (#15457) and TrueLayer mandate params (#15458) out of GET bodies, and Mooninvoice dropdown filters fixed (#15464). Watch any custom step that relied on GET bodies or lowercase header names; it will fail silently.

  • Agent reliability and diagnosability get much better — Publishing now reports why it failed and blocked steps look blocked (#15524), provider errors use one consistent vocabulary (#15515), failures on our managed key are no longer blamed on the customer (#15514), repaired tool calls actually run instead of being dropped (#15501), and a vanished flow run no longer hides the real step error (#15352). If you debug production agents, these are the changes that will save the most time — error attribution is now trustworthy.

  • Connector breadth and smarter triggers — New Sage Accounting piece (#15351), Ninety EOS to-dos/issues/rocks with triggers (#15299), WhatsScale AI actions and schemas (#15010), and Gmail gmail.modify label/trash/archive actions (#15512, #15347). The Linear Updated Issue trigger can filter by changed fields (#15435), revoking a Linear key no longer "connects" successfully (#15336), Google Drive list-files is optimized (#15461), and Slack Update/Direct Message allow blocks-only messages (#15195).
