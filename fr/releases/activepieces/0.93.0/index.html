activepieces 0.93.0

Highlights

  • Agent tooling and authenticated MCP — Many pieces now expose AI actions with typed output schemas, reducing brittle downstream mapping. Postgres, MySQL and SQL Server gain schema exploration, querying and row-write tools for agents (#17072–#17075); use least-privilege database credentials and review gates for write-capable flows. MCP clients also gain OAuth2 support (#15699), so self-hosted deployments should validate OAuth callbacks, secrets and token lifecycle.

  • Low-latency messaging pipelines — Kafka adds sub-second triggers and batch publishing in one request (#16732), alongside a dedicated publish/consume piece (#16291). RabbitMQ gains queue and exchange discovery/inspection (#16927), while SQS supports receiving, deleting and batch-sending messages (#16766), lowering latency and request overhead for event-driven workflows.

  • Safer upgrades and partial updates — Polling state now survives piece upgrades and republishes (#16719, #16694, #16695), reducing replay and backfill surprises after updates. Agent-driven partial updates also stop clearing omitted fields in Zoom, Notion and Discord (#17000), while Trello and Todoist preserve archived and favorite states (#17078, #17079).

  • Runtime resilience — A failing Return Response no longer crashes the API process (#17063), and webhook response header names are sanitized (#17003), improving fault isolation for untrusted or malformed responses. The disk-pressure threshold rises to 90% (#17232); operators should account for the later intervention point in capacity planning and alerting.

  • Deprecations and model compatibility — Gistly is deprecated in favor of Supadata (#17127), so existing flows need a migration plan. Claude and Groq actions were repaired after upstream model retirements (#17107, #17123), underscoring the importance of keeping production model IDs configurable.

  • Breaking changes — None called out in the changelog.
