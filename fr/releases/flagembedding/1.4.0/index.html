FlagEmbedding v1.4.0

Highlights

  • BGE-Reasoner lands as a new SOTA retrieval family — PRs #1510–#1531 introduce a reasoning-augmented embedder/reranker that claims new state of the art on BRIGHT, plus an updated "v0923" embedder checkpoint (#1528) and a Qwen3-Embedding-8B baseline for comparison (#1517). For adopters this is a genuinely new model tier aimed at reasoning-heavy queries, not just a version bump. Watch out: it is explicitly labeled "preview," and the cluster of README link/table/value fixes (#1511, #1512, #1516, #1531) suggests docs and reported results were still being stabilized at cut time — verify published numbers against the final README before benchmarking your own choice.

  • BRIGHT becomes a first-class evaluation target — #1534/#1535 add end-to-end BRIGHT support and examples, #1553 adds an evaluate_recall_cap metric, #1527 fixes evaluate_metrics in the runner, and #1538 repairs a pytrec_eval installation failure. This matters because the headline BGE-Reasoner claims are now reproducible locally through the library's own harness — but the install fix implies prior releases could not even run this evaluator cleanly, so pin this version if you are scripting BRIGHT evals in CI.

  • Transformers V5 compatibility unblocks dependency upgrades — #1563 (first contribution from @therealmichaelberna) adds forward compatibility with Transformers V5. The practical win is that adoption no longer forces you to hold back your transformers pin; the thing to watch is real-world regression testing on V5, since compatibility patches of this kind typically land ahead of full validation across every model wrapper.

  • bf16 support tightened across inference, training, and eval — #1566 switches the embedder to bf16 and fixes the attn_implementation interface in decode_only; #1567 makes bf16 loading safe and unifies NumPy conversion; #1568 propagates use_bf16 through AbsEvalRunner.get_model and COIR model initialization (#1532 also hardens dist.get_rank() for distributed runs). For developers this means lower memory and faster inference/training without silent dtype mismatches in evaluation. Note the attn_implementation interface change in decode_only — callers overriding attention backends should recheck their arguments even though no formal break was announced.

  • Matryoshka (MRL) support goes from training to serving — #1570 adds a use_mrl finetuning interface and truncate_dim at embedder inference time, so you can train one Representation Learning model and serve it at multiple output dimensionalities (cost/accuracy trade-off) without retraining. This is the most directly useful new capability for teams right-sizing vector index size.

  • More knobs for fine-tuning and new inference paths — train_group_size becomes customizable (#1491) with its spurious "None" warning silenced (#1492), use_fast_tokenizer is exposed for finetuning (#1526), and #1572 adds decoder-only pseudo_moe inference with domain routing. These are targeted additions for advanced users tuning contrastive batches or experimenting with mixture-of-experts-style domain routing rather than broad API changes.

No breaking changes were officially documented in this release.
