FlagEmbedding v1.3.4

Highlights

  • New models in the zoo — bce-embedding-base_v1 is now loadable through the standard embedding interface (#1198), the training data behind bge-multilingual-gemma2 has been published (#1245), and model_mapping.py was extended accordingly (#1311). For adopters this is the headline capability gain: you can swap these checkpoints into existing FlagEmbedder/FlagReranker pipelines without custom model glue, and the released Gemma2 training data makes multilingual fine-tuning reproducible rather than black-box.

  • Embedder constructor signature changed — #1189 removes "useless" parameters from the embedder classes. This is the one item to treat as a potential breaking change: any code passing the now-deleted kwargs into an embedder constructor will start raising TypeError, so audit your instantiation sites before upgrading. Relatedly, #1248 adds the missing trust_remote_code flag to the fine-tuning path — without it, decoder-only/custom-architecture checkpoints fail to load during training.

  • Broader hardware and dependency support — #1216 fixes MPS device handling in AbsReranker, so Apple Silicon users can finally run reranking on GPU instead of falling back to CPU. #1350 adds a MUSA backend for Moore Threads accelerators, a real option for domestic-hardware deployments. #1343 patches compatibility with transformers 4.48.0 and #1300 fixes a Python 3.8 type-hinting error — together these unblock dependency upgrades and keep older interpreter environments viable.

  • Training correctness fixes worth re-running — #1183 fixes a bug in BGE-M3 training, #1232 corrects a category index error in DecoderOnlyEmbedderICLSameDatasetTrainDataset, and #1330 plus #1328/#1342 repair the ICL and embedder fine-tuning paths. If you were fine-tuning M3 or using the decoder-only ICL dataset, previously produced checkpoints may be subtly wrong; these fixes landed across several follow-up PRs, so retrain rather than assuming early weights are sound.

  • Evaluation numbers may shift — #1256/#1257 fix AIRBenchEvalArgs in the air-bench harness, #1341 corrects the BEIR data loader to use the validation split instead of dev, and #1227/#1230/#1235 refresh the MTEB evaluation code. The BEIR split correction in particular can change reported retrieval scores, so re-baseline before comparing against published tables. #1296 also updates the C_MTEB reference.

  • Memory and distributed-training cleanup — #1349 addresses an OOM failure and #1229 adds automatic batch-size adjustment, which should lower the entry barrier for large-batch embedding. Note that #1360 removes the data-parallel (dp) training code: if your training scripts relied on that path, you'll need to migrate to the supported alternative, even though the rest of the release is additive.
