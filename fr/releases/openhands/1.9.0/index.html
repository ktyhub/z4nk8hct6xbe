OpenHands 1.9.0

Highlights

  • Org-only deployments get simpler onboarding — The first signed-in user becomes the default-org owner, existing users are migrated into that org, and unclaimed automation events on single-org installs are routed there. Invitations now auto-accept, support copyable links without email delivery, and match pending invites by verified email. Configure hide_personal_workspaces for org-only UX and set OH_DEPLOYMENT_MODE explicitly to control cloud-account CTAs (#14740, #14745, #14752, #14758, #14759, #14786, #14794).

  • Multi-model and BYOK workflows become first-class — OHE unifies proxy-discovered and catalogued models and gates BYOK, while ACP gains model/credential fields, MCP server configuration, and a switch_acp_model proxy endpoint for cloud conversations (#14773, #14733, #14613, #14744). Teams should map credentials and MCP configuration per agent before exposing model switching broadly.

  • Enterprise identity and API-key controls expand — Admin provisioning, user.role_id super roles with permission fallback, caller-permission responses, and an organization conversation dashboard support centrally managed deployments (#14864, #14937, #15048, #14846). API keys gain not_before/expires_at validity windows and explicit “unbound” org scope, enabling time-bounded automation credentials without accidental org inheritance (#15085, #15096).

  • Sandbox defaults move closer to runtime state — Users can set default_sandbox_spec_id, and DynamicRemoteSandboxSpecService sources warm configurations from the runtime API (#14985, #14849). Concurrency now uses runtime /list rather than the removed is_paused flag; conversation-limit enforcement from #14168 was reverted, so do not build around it (#14834, #14840, #14877). Custom sandbox images should align with agent-server 1.28.0 because SDK mismatches now produce explicit errors (#14754, #14883).

  • Richer context and issue-tracker workflows — Tree-sitter AST chunking, Slack attachments, and optional full Git history improve agent context, while Jira Data Center OAuth tokens are persisted per user and shared with eligible resolver conversations (#14699, #14934, #14950, #14650, #14697). Azure DevOps adds resolver mentions and org-level one-click webhook setup (#14991); review token-sharing scope and full-history context costs before enabling widely.

  • Security and auditability upgrades merit prompt rollout — Dependency updates address XSS and multiple HTTP, JWT, and parser vulnerabilities across PostCSS, PyJWT, Tornado, aiohttp, Bleach, DOMPurify, and Starlette (#14770, #14854, #14856, #14871, #14945, #14872, #14874). Plugin-source credentials are redacted during serialization, workspaces are archived before deletion, and Laminar traces carry repo/branch metadata (#14795, #14953, #15059). Secret names must now be valid environment-variable identifiers, so audit existing definitions before upgrading (#12980).

No breaking changes are listed.
