Métriques et topologie des traces OTLP

Les applications instrumentées avec les OpenTelemetry SDK n'ont plus besoin d'un agent SkyWalking pour les tableaux de bord de service, la topologie et la recherche de traces. OAP stocke les traces OTLP au fur et à mesure de leur arrivée, et le nouveau Trace Analysis Language (TAL) transforme chaque étendue en métriques de service, d'instance et de point de terminaison, en topologie et en tableaux de bord pour les bases de données, les caches et les files d'attente de messages appelés par les services. Lisez Traces OpenTelemetry dans SkyWalking pour un démarrage rapide en une seule commande avec la boutique d'astronomie OpenTelemetry.

C'est le complément de la collision intra-règle corrigée précédemment en saisissant le nom propre du compteur : aucun nom seul n'est suffisant, car les deux collisions sont indépendantes. Les appels API sont les mêmes qu'auparavant et sont effectués uniquement pour ce que les recherches utilisent : les données sont lues à nouveau lorsqu'elles sont utilisées core.default.k8sMetadataRefreshPeriod (3 minutes) après leur écriture et supprimées core.default.k8sMetadataCacheTime après leur dernière écriture (als=21,mal=21 minutes par défaut, par cache) ; ne rien trouver n'est relu lorsqu'il est utilisé core.default.k8sMetadataNotFoundRetryPeriod (1 minute) plus tard, et les points de terminaison ou services lus sont lus à nouveau pour un pod qui n'y était pas une fois aussi ancien, car le pod peut être nouveau ; une lecture ayant échoué, comme pour un 403 ou le serveur API qui ne répond pas, est réessayée lorsqu'elle est utilisée plus tard pendant la période d'actualisation et conserve les données lues auparavant. Les lectures ayant échoué sont enregistrées sous la forme d'un résumé d'ERREUR une minute après le premier échec, puis toutes les cinq minutes au lieu d'une ligne par échec, et une ressource que le serveur API ne dessert pas, telle que ServiceEntries sans Istio, n'est pas enregistrée. Les échecs de résolution de nom d'hôte ServiceEntry sont résumés dans WARN, et une résolution défaillante tente avec un délai croissant au lieu d'être immédiatement après trois tentatives échouées. Les ServiceEntries sont lues via le Kubernetes client partagé au lieu d'un nouveau client par lecture.

Metrics and Topology from OTLP Traces

Applications instrumented with the OpenTelemetry SDKs no longer need a SkyWalking agent for service dashboards, topology and trace search. OAP stores OTLP traces as they arrive, and the new Trace Analysis Language (TAL) turns every span into service, instance and endpoint metrics, a topology, and dashboards for the databases, caches and message queues the services call.
