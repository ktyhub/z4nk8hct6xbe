Projet

  • Présentation du moteur OAL V2 :
    • Modèles AST immuables pour la sécurité des threads et un comportement prévisible
    • Énumérations de type sécurisé remplaçant les opérateurs de filtre basés sur des chaînes
    • Rapport précis sur l'emplacement des erreurs avec les numéros de fichiers, de lignes et de colonnes
    • Séparation nette entre les phases d'analyse et de génération de code
    • Testabilité améliorée avec des modèles qui peuvent être construits sans analyse
  • Introduction du moteur MAL/LAL/Hierarchy V2 — remplacez le runtime DSL basé sur Groovy par l'analyseur ANTLR4 + la génération de bytecode Javassist :
    • Supprimer la dépendance d'exécution Groovy du backend OAP
    • Compilation rapide au démarrage — les erreurs de syntaxe et de type sont détectées immédiatement au lieu de la première exécution
    • Classes générées thread-safe sans ThreadLocal ou état mutable partagé
    • Modèles AST immuables pour les trois DSL (MAL, LAL, règles de hiérarchie)
    • Le passage de contexte explicite remplace la capture de liaison/fermeture Groovy
    • Le vérificateur de versions croisées v1 (Groovy) et v2 (ANTLR4+Javassist) valide l'équivalence comportementale dans plus de 1 290 expressions
    • Les benchmarks JMH confirment les accélérations d'exécution de la v2 : MAL exécute ~ 6,8x, LAL compile ~ 39x / exécute ~ 2,8x, la hiérarchie s'exécute ~ 2,6 fois plus rapidement que Groovy v1
    • Les noms de classe générés suivent le modèle {yamlFileName}_L{lineNo}_{ruleName} pour tous les DSL (MAL/LAL/Hiérarchie) pour la traçabilité de la trace de la pile
  • Breaking Change — LAL : supprimez les sous-DSL slowSql {} et sampledTrace {} de la grammaire. Ceux-ci sont remplacés par le mécanisme configurable outputType :
    • Définissez outputType au niveau de la règle dans la configuration YAML pour spécifier la classe d'entité de sortie. Utilisez le nom court enregistré par LALOutputBuilder SPI (par exemple, outputType: SlowSQL, outputType: SampledTrace) ou un nom de classe complet comme solution de secours.
    • Les implémentations de LALOutputBuilder sont découvertes via ServiceLoader et exposent une méthode name() pour la résolution de noms courts. Types intégrés : SlowSQL (DatabaseSlowStatementBuilder), SampledTrace (SampledTraceBuilder).
    • Les champs de sortie (par exemple, id, statement, latency) sont désormais des affectations de champs régulières dans le bloc extracteur, et non plus encapsulées dans des blocs sous-DSL.
    • Les champs de sortie personnalisés sont validés par rapport aux paramètres du type de sortie au moment de la compilation.
    • Un bloc sink {} explicite est désormais obligatoire pour que les données soient conservées. Sans sink {}, aucune donnée n'est enregistrée — cela s'applique à toutes les règles LAL, y compris celles utilisant outputType. Dans la version 1, slowSql {} et sampledTrace {} diffusaient des données comme effet secondaire à l'intérieur de l'extracteur ; dans la v2, la persistance est toujours gérée par le pipeline récepteur.
    • Ordre de résolution du type de sortie : par règle YAML outputType (nom court via SPI ou FQCN) > LALSourceTypeProvider SPI par défaut > Log.class.
    • Tous les scripts LAL groupés (mysql-slowsql.yaml, pgsql-slowsql.yaml, redis-slowsql.yaml, envoy-als.yaml, k8s-service.yaml, mesh-dp.yaml) ont été mis à jour.
    • Les utilisateurs disposant de scripts LAL personnalisés utilisant slowSql {} ou sampledTrace {} doivent migrer vers la nouvelle syntaxe. Voir Documentation LAL.
    • Renommez ExtractorSpec en MetricExtractor — ne gère désormais que les blocs LAL metrics {}. Les setters de champs standard (service, couche, horodatage, etc.) sont compilés sous forme d'appels directs au setter sur le générateur de sortie.
  • Ajout du support des variables locales def dans l'extracteur LAL (et niveau de filtre). Prend en charge les fonctions intégrées toJson() et toJsonArray() pour convertir des chaînes, des cartes et du protobuf Struct en objets Gson JSON. Les variables prennent en charge la navigation null-safe (?.), le chaînage de méthodes avec inférence de type au moment de la compilation et la conversion de type explicite via as (types intégrés ou noms de classe complets, par exemple def resp = parsed?.response as io.envoyproxy.envoy.data.accesslog.v3.HTTPResponseProperties).
    • Changement radical — La signature LALOutputBuilder.init() est passée de init(LogData, NamingControl) à init(LogData, Optional<Object> extraLog, NamingControl). Le paramètre extraLog transporte l'objet d'entrée saisi (par exemple, HTTPAccessLogEntry pour les journaux d'accès des envoyés) afin que les générateurs de sortie puissent accéder aux champs spécifiques au protocole. Les implémentations personnalisées de LALOutputBuilder doivent mettre à jour leur signature de méthode init().

  • Correction de la vérification des métriques de test E2E : faites-en un échec si les valeurs métriques sont toutes nulles.

Project

  • Introduce OAL V2 engine:

    • Immutable AST models for thread safety and predictable behavior
    • Type-safe enums replacing string-based filter operators
    • Precise error location reporting with file, line, and column numbers
    • Clean separation between parsing and code generation phases
    • Enhanced testability with models that can be constructed without parsing

  • Introduce MAL/LAL/Hierarchy V2 engine — replace Groovy-based DSL runtime with ANTLR4 parser + Javassist bytecode generation:

    • Remove Groovy runtime dependency from OAP backend
    • Fail-fast compilation at startup — syntax and type errors are caught immediately instead of at first execution
    • Thread-safe generated classes with no ThreadLocal or shared mutable state
    • Immutable AST models for all three DSLs (MAL, LAL, Hierarchy rules)
    • Explicit context passing replaces Groovy binding/closure capture
    • v1 (Groovy) and v2 (ANTLR4+Javassist) cross-version checker validates behavioral equivalence across 1,290+ expressions
    • JMH benchmarks confirm v2 runtime speedups: MAL execute ~6.8x, LAL compile ~39x / execute ~2.8x, Hierarchy execute ~2.6x faster than Groovy v1
    • Generated class names follow {yamlFileName}_L{lineNo}_{ruleName} pattern for all DSLs (MAL/LAL/Hierarchy) for stack trace traceability

  • Breaking Change — LAL: remove slowSql {} and sampledTrace {} sub-DSLs from the grammar. These are replaced by the configurable outputType mechanism:

    • Set outputType at the rule level in YAML config to specify the output entity class. Use the short name registered by LALOutputBuilder SPI (e.g., outputType: SlowSQL, outputType: SampledTrace), or a fully qualified class name as fallback.
    • LALOutputBuilder implementations are discovered via ServiceLoader and expose a name() method for short name resolution. Built-in types: SlowSQL (DatabaseSlowStatementBuilder), SampledTrace (SampledTraceBuilder).
    • Output fields (e.g., id, statement, latency) are now regular field assignments in the extractor block, no longer wrapped in sub-DSL blocks.
    • Custom output fields are validated against the output type's setters at compile time.
    • An explicit sink {} block is now required for data to be persisted. Without sink {}, no data is saved — this applies to all LAL rules including those using outputType. In v1, slowSql {} and sampledTrace {} dispatched data as a side-effect inside the extractor; in v2, persistence is always handled by the sink pipeline.
    • Output type resolution order: per-rule YAML outputType (short name via SPI or FQCN) > LALSourceTypeProvider SPI default > Log.class.
    • All bundled LAL scripts (mysql-slowsql.yaml, pgsql-slowsql.yaml, redis-slowsql.yaml, envoy-als.yaml, k8s-service.yaml, mesh-dp.yaml) have been updated.
    • Users with custom LAL scripts using slowSql {} or sampledTrace {} must migrate to the new syntax. See LAL documentation.
    • Rename ExtractorSpec to MetricExtractor — now only handles LAL metrics {} blocks. Standard field setters (service, layer, timestamp, etc.) are compiled as direct setter calls on the output builder.
    • Add def local variable support in LAL extractor (and filter level). Supports toJson() and toJsonArray() built-in functions for converting strings, Maps, and protobuf Struct to Gson JSON objects. Variables support null-safe navigation (?.), method chaining with compile-time type inference, and explicit type cast via as (built-in types or fully qualified class names, e.g., def resp = parsed?.response as io.envoyproxy.envoy.data.accesslog.v3.HTTPResponseProperties).
    • Breaking Change — LALOutputBuilder.init() signature changed from init(LogData, NamingControl) to init(LogData, Optional<Object> extraLog, NamingControl). The extraLog parameter carries the typed input object (e.g., HTTPAccessLogEntry for envoy access logs) so that output builders can access protocol-specific fields. Custom LALOutputBuilder implementations must update their init() method signature.
