#caddie v2.11.3

Cette version améliore plusieurs aspects de Caddy avec des fonctionnalités mineures, des corrections de bugs et des correctifs de sécurité. Merci à tous ceux et à leurs robots qui ont contribué à faire de cette version la meilleure à ce jour !

Corrections de sécurité :

  • fastcgi : Report d'un patch de FrankenPHP pour un bug qui pourrait permettre l'exécution de fichiers non-PHP ; collaboré par @dunglas, @KC1zs4 et @chenjj.
  • vars : un correctif plus complet pour https://github.com/advisories/GHSA-m2w3-8f23-hxxf, collaboré par @everping et @vnxme.
  • admin : normalisation de l'index du tableau pour empêcher le contournement de l'authentification du socket admin distant, par @Amemoyoi et bot.
  • admin : correspondance de préfixe de chemin plus rigoureuse pour empêcher le contournement de l'authentification du socket administrateur à distance, par @Amemoyoi et le bot.

Nous avons également fusionné quelques PR qui corrigent des bogues de sécurité en amont dans d'autres projets comme quic-go et CertMagic. Merci à @marten-seemann d'avoir maintenu le quick-go avec autant de diligence !

caddy v2.11.3

Highlights

  • Security hardening — Upgrade promptly if the admin API or FastCGI is reachable: canonical array-index validation and path-segment boundary checks close remote admin authentication bypasses (#7592, #7673), FastCGI receives the non-PHP execution fix, and sensitive request headers are redacted from admin API logs (#7578). quic-go and CertMagic security fixes are also included.
  • vars expansion semantics — Placeholders in assigned values are no longer eagerly expanded; vars, vars_regexp, and matcher-placeholder behavior are now aligned (#7629, #7573, #7640). This strengthens the GHSA-m2w3-8f23-hxxf fix. Audit configurations relying on nested substitution and compute composed values explicitly before rollout.
  • More control over retries and streaming — reverse_proxy can retry based on upstream response status via lb_retry_match (#7569), clear its dynamic-upstream cache during retries (#7662), and tune the stream copy buffer (#7627). HTTP Zstandard checksums are also configurable (#7586), allowing deployments to balance integrity checking against CPU and bandwidth.
  • Smarter automated TLS — Auto-HTTPS prefers port 443 (#7666), implicit Tailscale *.ts.net policies avoid unnecessary ACME fallback (#7577), and wildcard-covered hosts no longer create duplicate automation (#7697). ACME credentials and DNS challenge override domains now accept placeholders (#7554, #7609), useful for multi-tenant configurations.
  • New trust, metrics, and logging options — System and combined CA pool modules support OS-managed or mixed trust stores (#7406); include the relevant module in custom builds. Metrics can be pushed with OTLP (#7664), and journald encoding preserves JSON timestamps (#7623, #7644), simplifying ingestion into observability pipelines.
  • Deployment and configuration usability — Imports before global options behave more intuitively (#7642), snippets support {block} (#7558), log sampling intervals accept duration strings (#7694), and notify sends READY=1 even after an error (#7597). The last change may let supervisors proceed after a readiness-path error, so verify your service-manager assumptions.

No breaking changes.

This release improves several aspects of Caddy with minor features, bug fixes, and security patches. Thank you to everyone and their bots who contributed to help make this release the best one yet!

Security patches:

  • fastcgi: Carrying over a patch from FrankenPHP for a bug that could allow non-PHP files to be executed; collaborated on by @dunglas, @KC1zs4, and @chenjj.
  • vars: A more thorough fix for https://github.com/advisories/GHSA-m2w3-8f23-hxxf, collaborated by @everping and @vnxme.
  • admin: Array index normalization to prevent remote admin socket auth bypass, by @Amemoyoi and bot.
  • admin: More rigorous path prefix matching to prevent remote admin socket auth bypass, by @Amemoyoi and bot.

We've also merged a couple PRs that fix upstream security bugs in other projects like quic-go and CertMagic. Thank you to @marten-seemann for maintaining quic-go so diligently!
