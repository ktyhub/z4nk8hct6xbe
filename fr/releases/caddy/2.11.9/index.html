chariot v2.11.9

Il s'agit d'un suivi rapide de 2.11.8, pour corriger une régression qu'il a introduite et quelques problèmes de sécurité supplémentaires, principalement dans FastCGI. Il ne contient que des correctifs rétroportés depuis master, ainsi que quelques petits ajouts. Si vous utilisez 2.11.8 et utilisez PHP, nous vous recommandons de mettre à niveau.

Un grand merci à nos sponsors pour avoir maintenu le projet en vie grâce à leurs ressources, et à nos responsables qui trient et aident sans relâche dans cette nouvelle ère implacable de l'IA.

Faits saillants

  • Corrigé : index de répertoire PHP (régression dans 2.11.8). Une requête pour un répertoire avec une barre oblique finale, comme /wp-admin/, correspondait au répertoire lui-même au lieu de son index.php, elle n'atteignait donc jamais PHP et obtenait généralement un 404. Cela cassait les pages d'administration de WordPress et d'autres applications qui servent un index via une URL à barre oblique finale. Un modèle try_files ne correspond désormais à un répertoire que lorsqu'il se termine par /. Merci @dunglas ! (#8352)
  • Les Les comparateurs de chemin avec des espaces réservés fonctionnent désormais comme prévu : les espaces réservés comme {env.FOO} ne sont plus en minuscules dans {env.foo} avant d'être recherchés, et leurs valeurs sont comparées sans tenir compte de la casse par rapport au chemin de la requête, comme les modèles statiques. Merci @BenMacha ! (#8343)
  • Nouvelle option plain_time_format pour file_server browse : définit la disposition temporelle des listes de répertoires en texte brut (Accept: text/plain). Merci @steffenbusch ! (#8084)
  • Moins d'allocations dans le nettoyage des chemins, la réécriture des en-têtes et la sélection weighted_round_robin. Merci @jvoisin ! (#7842)
  • Pour les auteurs de plugins : le nouveau httpcaddyfile.Helper.IsNamedRoute() indique à une directive si elle est analysée à l'intérieur d'une [route nommée] (https://caddyserver.com/docs/caddyfile/concepts#named-routes). (#8354)

## :avertissement : modifications cassantes

  • Le conflit client_auth est désormais une erreur Caddyfile. Lorsque deux blocs de sites partagent des politiques de connexion TLS pour le même nom d'hôte mais définissent un client_auth différent, l'adaptateur conservait le premier et supprimait silencieusement l'autre, ce qui pourrait supprimer discrètement une exigence mTLS plus stricte. (#8306)
  • Les requêtes FastCGI qui sont ambiguës quant au script qu'elles exécutent obtiennent 400 :
    • lorsque le chemin d'échappement (que voient les correspondants de chemin contenant %) et le chemin décodé sélectionneraient différents scripts, par ex. /public/tool.php%2f..%2f..%2fadmin%2ftool.php (#8357)
    • sous Windows, chemins de script avec un composant de nom court 8.3 (comme ADMINI~1) ou un : (flux de données alternatifs NTFS) (#8356)
  • Les valeurs FastCGI env ont désormais priorité sur les en-têtes de requête, donc un client ne peut plus remplacer les variables HTTP_* que vous avez définies avec env (voir ci-dessous). (#8358)

Correctifs de sécurité

Merci à tous ceux qui ont signalé de manière responsable et aidé avec les correctifs :

  • fastcgi : un client pourrait remplacer toute variable HTTP_* définie par la sous-directive env du transport FastCGI (ou php_fastcgi) en envoyant un en-tête de requête correspondant, par exemple en choisissant l'utilisateur qu'une application voit dans HTTP_X_AUTH_USER. Les valeurs configurées gagnent désormais. Rapporté par @JebeenLee et @Camel4, corrigé par @dunglas. (GHSA-q34h-28rj-5hjm, #8358)
  • fastcgi : sous Windows, les noms courts NTFS 8.3 et les flux de données alternatifs pouvaient exécuter un script qu'une règle de chemin était censée refuser, complétant ainsi le correctif FastCGI de 2.11.8. Merci @dunglas. (GHSA-9cr8-wmhh-39pm, #8356)
  • fastcgi : les barres obliques codées et les segments de points pourraient amener un outil de correspondance de chemin contenant % à approuver un script pendant qu'un autre s'exécute. Merci @dunglas. (#8357)
  • fastcgi : via HTTP/2, un champ host envoyé à côté de :authority pourrait faire en sorte que l'application voie un hôte différent (HTTP_HOST) de celui vers lequel Caddy a acheminé la requête. Merci @dunglas. (#8355)
  • httpcaddyfile : un client_auth plus strict pourrait être supprimé silencieusement lors de la fusion des politiques de connexion TLS (voir ci-dessus). Merci @sam-kota. (#8306)
  • Mise à jour de go-jose vers v4.1.6 pour GHSA-mgcc-cww5-fp2q. (#8299)

:avertissement : Ces correctifs de sécurité peuvent être défectueux si votre application s'appuie sur des comportements bogués.

:rotating_light : Avis destiné aux responsables du plugin Caddy : Dependabot vous alertera probablement des correctifs de sécurité dans Caddy et vous invitera à le mettre à niveau dans votre fichier go.mod. Veuillez mettre à niveau UNIQUEMENT la dépendance Caddy s'il y a une modification dans un API exporté que votre plugin utilise.

caddy v2.11.9

This is a quick follow-up on top of 2.11.8, to fix a regression it introduced and a few more security issues, mostly in FastCGI. It contains only fixes backported from master, plus a couple of small additions. If you're on 2.11.8 and serve PHP, we recommend upgrading.

Huge thank you to our sponsors for keeping the project alive with resources, and for our maintainers who triage and assist tirelessly in this relentless new age of AI.

Highlights

  • Fixed: PHP directory indexes (regression in 2.11.8). A request for a directory with a trailing slash, like /wp-admin/, was matched by the directory itself instead of its index.php, so it never reached PHP and usually got a 404. This broke WordPress admin pages and other apps that serve an index through a trailing-slash URL. A try_files pattern now only matches a directory when it ends in /. Thanks @dunglas! (#8352)
  • Path matchers with placeholders now work as expected: placeholders like {env.FOO} are no longer lower-cased into {env.foo} before they're looked up, and their values are compared case-insensitively against the request path, like static patterns. Thanks @BenMacha! (#8343)
  • New plain_time_format option for file_server browse: sets the time layout of plain-text directory listings (Accept: text/plain). Thanks @steffenbusch! (#8084)
  • Fewer allocations in path cleaning, header rewriting and weighted_round_robin selection. Thanks @jvoisin! (#7842)
  • For plugin authors: new httpcaddyfile.Helper.IsNamedRoute() tells a directive whether it's being parsed inside a named route. (#8354)

:warning: Breaking changes

  • Conflicting client_auth is now a Caddyfile error. When two site blocks share TLS connection policies for the same hostname but set different client_auth, the adapter used to keep the first one and silently drop the other, which could quietly remove a stricter mTLS requirement. (#8306)
  • FastCGI requests that are ambiguous about which script they run get 400:
    • when the escaped path (which %-containing path matchers see) and the decoded path would select different scripts, e.g. /public/tool.php%2f..%2f..%2fadmin%2ftool.php (#8357)
    • on Windows, script paths with an 8.3 short name component (like ADMINI~1) or a : (NTFS alternate data streams) (#8356)
  • FastCGI env values now take precedence over request headers, so a client can no longer override HTTP_* variables you set with env (see below). (#8358)

Security fixes

Thank you to everyone who reported responsibly and helped with patches:

  • fastcgi: A client could override any HTTP_* variable set with the FastCGI transport's (or php_fastcgi's) env subdirective by sending a matching request header, for example choosing the user an application sees in HTTP_X_AUTH_USER. Configured values now win. Reported by @JebeenLee and @Camel4, fixed by @dunglas. (GHSA-q34h-28rj-5hjm, #8358)
  • fastcgi: On Windows, NTFS 8.3 short names and alternate data streams could run a script that a path rule was meant to deny, completing the FastCGI fix from 2.11.8. Thanks @dunglas. (GHSA-9cr8-wmhh-39pm, #8356)
  • fastcgi: Encoded slashes and dot segments could make a %-containing path matcher approve one script while another one runs. Thanks @dunglas. (#8357)
  • fastcgi: Over HTTP/2, a host field sent next to :authority could make the application see a different host (HTTP_HOST) than the one Caddy routed the request to. Thanks @dunglas. (#8355)
  • httpcaddyfile: A stricter client_auth could be silently dropped when merging TLS connection policies (see above). Thanks @sam-kota. (#8306)
  • Updated go-jose to v4.1.6 for GHSA-mgcc-cww5-fp2q. (#8299)

:warning: These security patches may be breaking if your application relies on the buggy behaviors.

:rotating_light: Notice for Caddy plugin maintainers: Dependabot will probably alert you to the security fixes in Caddy and urge you to upgrade it in your go.mod file. Please ONLY upgrade the Caddy dependency if there's a change to an exported API your plugin uses.

  • httpcaddyfile: reject conflicting client_auth when merging TLS policies by @sam-kota in https://github.com/caddyserver/caddy/pull/8306

  • fileserver: only match a dir when the pattern ends by / by @dunglas in https://github.com/caddyserver/caddy/pull/8352
  • httpcaddyfile: add Helper.IsNamedRoute by @dunglas in https://github.com/caddyserver/caddy/pull/8354
  • fastcgi: take HTTP_HOST from the routed host only by @dunglas in https://github.com/caddyserver/caddy/pull/8355
