caddy v2.11.1

Correctif Publié23 févr. 2026 Sourcecaddyserver/caddy Anglais original

Cette page est traduite automatiquement. Le texte anglais original fait foi.

chariot v2.11.1

Notre communauté est heureuse d'annoncer le Caddy 2.11 ! Il convient de noter les nouvelles fonctionnalités, de nombreuses corrections de bugs, dont plusieurs correctifs de sécurité, et diverses améliorations de la qualité de vie (« qualité de vie »).

Il n’y a aucun changement de code par rapport à v2.11.0 autre que celui d’un travail CI. En raison d'un récent changement externe qui a interrompu notre processus de publication, la première version de 2.11 est v2.11.1.

Remerciement spécial du sponsor

Un grand merci à nos sponsors majeurs :

  • ZéroSSL
  • Rayure
  • Chemin de fer

Ils, avec des dizaines de petits sponsors, rendent ce projet et les nouvelles versions possibles, en collaboration avec notre équipe de responsables. Merci à tous !

Changements notables

  • Les clés cryptées ClientHello (ECH) tournent automatiquement.
  • Options de chronométrage pour les journaux.
  • SIGUSR1 peut désormais recharger la configuration si elle a été initialement chargée à partir d'un fichier sur la ligne de commande et n'a pas été modifiée via le API.
  • Le proxy inverse réécrit désormais automatiquement l'en-tête Host à l'adresse de l'amont lorsque l'amont est HTTPS (#7454)
  • log_append peut désormais enregistrer les corps de requêtes et de réponses, utiles pour le débogage.
  • Notre projet met désormais en œuvre et nécessite des divulgations d'assistance (pour les AI/LLM) sur les problèmes, les PR, les commentaires, les réponses, les avis, etc.
  • De très nombreuses autres améliorations mineures et corrections de bugs.

Merci à tous ceux qui ont participé à cette version !

:avertissement : correctifs de sécurité

  • fastcgi : CVE-2026-27590 par @dunglas et @AbdrrahimDahmani - L'expansion de la longueur de pliage Unicode provoque un index split_path incorrect (confusion SCRIPT_NAME/PATH_INFO) dans le transport FastCGI.
  • admin : CVE-2026-27589 par @1seal - Les requêtes d'origine croisée tentées avec le mode no-cors pourraient entraîner la réussite de certaines requêtes API ; ces demandes sont désormais bloquées. (Pour que cela soit pratiquement exploitable, un navigateur Web exécutant une page Web malveillante doit s'exécuter localement sur un processus Caddy de production.)
  • caddyhttp : CVE-2026-27588 par Asim Viladi Oglu Manizada - Le Host Matcher devient sensible à la casse pour les grandes listes d'hôtes (> 100), permettant le contournement de la route/authentification basé sur l'hôte.
  • caddyhttp : CVE-2026-27587 par Asim Viladi Oglu Manizada - Le Path Matcher ignore la normalisation de la casse pour les séquences d'échappement, permettant ainsi le contournement de l'itinéraire/auth basé sur le chemin.
  • caddytls : CVE-2026-27586 par @moscowchill - L'authentification TLS client échoue silencieusement lorsque le fichier de certificat CA est manquant ou mal formé.
  • caddyhttp : CVE-2026-27585 par @parrot409 - Une mauvaise désinfection des caractères globaux dans le matcher de fichiers peut conduire à contourner les protections de sécurité.

:rotating_light : Avis destiné aux responsables du plugin Caddy : Dependabot vous alertera probablement des correctifs de sécurité dans Caddy et vous invitera à le mettre à niveau dans votre fichier go.mod. Veuillez mettre à niveau UNIQUEMENT la dépendance Caddy s'il y a une modification dans un API exporté que votre plugin utilise. (Ensuite, [désactivez Dependabot] (https://words.filippo.io/dependabot/).)

Highlights

  • Six security patches, several with routing-visible fallout — Pin v2.11.1, not 2.11.0: v2.11.0 was never actually shipped (only a CI job differed), so this is the first real 2.11 build and carries all the fixes. CVE-2026-27586 makes TLS client auth fail closed when the CA file is missing/malformed (it previously accepted clients silently), and #7393 now panics on the tls.ca_pool.source.http -> tls.ca misconfiguration — audit any deployment leaning on a broken CA chain. CVE-2026-27588 makes the Host matcher case-sensitive for lists over 100 hosts, and CVE-2026-27587 stops case-normalizing escaped path sequences; both can re-open route/auth bypasses if you depended on case-insensitive matching at scale or with encoded paths. CVE-2026-27585 tightens file-matcher glob sanitization, CVE-2026-27590 fixes Unicode case-fold length expansion corrupting FastCGI split_path (SCRIPT_NAME/PATH_INFO confusion), and CVE-2026-27589 blocks no-cors admin API calls (realistically exploitable only when a malicious browser runs locally to the Caddy process). Plugin maintainers: ignore Dependabot's Caddy bumps unless an exported API you use actually changed.

  • HTTPS upstreams now get their Host header rewritten (#7454) — A genuine behavior change: when reverse_proxy targets an HTTPS upstream, Caddy automatically rewrites Host to the upstream's host:port. Backends that key virtual hosting, signing, or URL generation off the original client Host need review or an explicit header override. Related proxy improvements: new keepalive_idle/keepalive_count server options (#7298) with defaults filled in when partially set (#7318), keepalive preserved when PROXY protocol is in use (#7300), h2c via http.Protocols (#6990), and WebSocket/error-channel fixes (#7305, #7419, #7463).

  • Encrypted ClientHello keys rotate on their own (#7356) — ECH key rotation is now automatic, so long-lived servers no longer need manual key lifecycle management to keep ECH usable. Pair it with the new {http.request.tls.*_ech}-style placeholder and ECH status logging (#7328) to confirm ECH is actually being negotiated rather than silently falling back.

  • Logging gets time-rolling and body capture — The logger moves from lumberjack to timberjack, adding time-based rotation options (#7244); check your existing rotation config when upgrading. log_append gains an Early option and can log {http.response.body} (#7368), joined by {http.request.body_base64} (#7367) — powerful for debugging, but a data-exposure risk if enabled broadly on production logs. Logs are also buffered until config loads (#7245, #7257) and modules can register custom slog handlers (#7346).

  • Reload semantics and telemetry tighten up — SIGUSR1 can now reload configuration when it was loaded from a file on the command line and never mutated via the admin API (#7258); if you drive config through the API, this shortcut won't apply. Observability improvements include OpenTelemetry autoexport (#7317), additional span attributes (#7269), and a fix for unbounded per-host metric cardinality (#7306) — relevant if you were seeing memory growth from high-cardinality labels.

  • Auth and exposure controls expand — Basic Auth gains Argon2id support (#7186), a worthwhile hardening option over older hashes. You can now customize the Server header (#7338), trust X-Forwarded-* from Unix sockets via trusted_proxies_unix (#7265), and use multiple intermediates in a signing chain (#7057) — useful for PKI ceremonies and for stripping the default Caddy version fingerprint from responses.

No formal breaking changes were announced for this release.

Our community is pleased to announce Caddy 2.11! Of note are new features, numerous bug fixes including several security patches, and various QoL ("quality-of-life") enhancements.

There are no code changes from v2.11.0 other than to a CI job. Due to a recent external change that broke our release process, the first release of 2.11 is v2.11.1.

Notable changes

  • Encrypted ClientHello (ECH) keys are rotated automatically.
  • Time-rolling options for logs.
  • SIGUSR1 can now reload configuration if it was initially loaded from a file on the command line and did not get changed via the API.
  • Reverse proxy now automatically rewrites the Host header to the address of the upstream when the upstream is HTTPS (#7454)
  • log_append can now log request and response bodies, useful for debugging.
  • Our project now implements and requires Assistance Disclosures (for AI/LLMs) on issues, PRs, comments, replies, reviews, etc.
  • Many, many other minor improvements and bug fixes.

Thank you to everyone who was involved this release!

:warning: Security patches

  • fastcgi: CVE-2026-27590 by @dunglas and @AbdrrahimDahmani - Unicode case-folding length expansion causes incorrect split_path index (SCRIPT_NAME/PATH_INFO confusion) in FastCGI transport.
  • admin: CVE-2026-27589 by @1seal - Cross-origin requests attempted with no-cors mode could cause some API requests to succeed; such requests are now blocked. (In order for this to be practically exploitable, a web browser executing a malicious web page must be running locally to a production Caddy process.)
  • caddyhttp: CVE-2026-27588 by Asim Viladi Oglu Manizada - The Host matcher becomes case-sensitive for large host lists (>100), enabling host-based route/auth bypass.
  • caddyhttp: CVE-2026-27587 by Asim Viladi Oglu Manizada - The Path matcher skips case normalization for escape sequences, enabling path-based route/auth bypass.
  • caddytls: CVE-2026-27586 by @moscowchill - TLS client authentication silently fails open when CA certificate file is missing or malformed.
  • caddyhttp: CVE-2026-27585 by @parrot409 - Improper sanitization of glob characters in file matcher may lead to bypassing security protections.

:rotating_light: Notice for Caddy plugin maintainers: Dependabot will probably alert you to the security fixes in Caddy and urge you to upgrade it in your go.mod file. Please ONLY upgrade the Caddy dependency if there's a change to an exported API your plugin uses. (Then, turn Dependabot off.)
