daily_stock_analysis v3.19.0

Nouvelles fonctionnalités

  • Implémentation #1391 Phase 1 Lien minimum pour l'exécution du diagnostic : la tâche/SSE ajoute trace_id et enregistre les instantanés ProviderRun du marché quotidiens et en temps réel.
  • Le centre d'alarme ajoute des règles structurées de feux de signalisation à grande échelle P7, prend en charge market_light_status et market_light_score_drop et réutilise les travailleurs existants, l'historique des déclenchements, les notifications et les liens de refroidissement.
  • Mise en œuvre du résumé de diagnostic d'exécution de la phase 2 #1391 : génère un RunDiagnosticSummary lisible par l'utilisateur, fournissant un rapport historique de diagnostic API et une copie de texte désensibilisée.
  • Implémentation de la visibilité du diagnostic d'exécution de la phase 3 #1391 : les détails du rapport et les panneaux de tâches sont réduits par défaut pour afficher l'état d'exécution, la trace et les informations de dépannage réplicables ; le backend fournit un remplissage de liens historiques via api/v1/history/{record_id}/diagnostics et context_snapshot.diagnostics.
  • Ajout du contrat interne AnalysisContextPack P1 et des tests de sérialisation désensibilisés.
  • Ajout du générateur AnalysisContextPack P2 pour assembler des packages de contexte internes à partir d'artefacts existants dans des pipelines d'analyse communs.
  • Wengu a ajouté une compression visible du contexte de conversation qui est désactivée par défaut, prend en charge le commutateur Web, le préréglage avancé de l'agent, le résumé glissant et la protection du texte original récent, réduisant ainsi la consommation de jetons de longue session.
  • L'index de saisie semi-automatique des stocks prend en charge l'actualisation et le cache à distance du principal GitHub vers le local par défaut. Lorsque l'entrée d'analyse Web/CLI échoue, elle sera automatiquement rétrogradée vers l'index intégré, réduisant ainsi la probabilité que l'ancienne abréviation contamine l'analyse après décapitation et changement de nom.
  • L'analyse ordinaire et l'invite d'exécution de l'agent sont connectées au résumé à faible sensibilité d'AnalysisContextPack pour maintenir la compatibilité avec la sortie history/API/Web.

Améliorations

  • scripts/fetch_tushare_stock_list.py peut remplir et corriger les noms avec le préfixe XD/XR/DR/N/C dans les partages A pour une utilisation par défaut dans le processus d'actualisation automatique.
  • La page de routage Web est modifiée pour charger à la demande, la taille du premier paquet est réduite et une invite de récupération en cas d'échec de chargement de route est ajoutée.
  • Le tiroir Markdown de rapports Web complets a été modifié pour être chargé à la demande.
  • Ajout de lignes de base d'inférence de phase de marché et clarification de la sémantique des jours de pré-marché, intra-marché, pause déjeuner, proche de la clôture, après-marché et hors bourse.
  • Ajout de la construction du contexte de l'étape de marché et des tests de dégradation.
  • La configuration de la page des paramètres permet de compléter progressivement la rédaction bilingue chinois et anglais des champs d'affichage/configurables réels de la page des paramètres Web, couvrant l'agent, le backtesting, le reporting, le routage des notifications, l'exécution du système, l'héritage de l'IA, les sources de données et la configuration avancée des notifications.
  • P2-min : LLM Prompt injecte le contexte de l'étape de marché.

Correction

  • La génération d'index de saisie semi-automatique échouera directement lorsque pypinyin est manquant pour éviter d'écrire des index dégradés avec des champs pinyin manquants.
  • Normaliser le volume des transactions sur le marché en temps réel de Tencent en tant que calibre d'actions afin d'éviter l'amplification des multiples de changement d'énergie en volume et les rapports d'analyse trompeurs.
  • Le déploiement par défaut de Docker supprime le montage de fichier unique .env pour empêcher Device or resource busy d'être déclenché par os.replace mettant à jour le point de montage lorsque l'interface utilisateur Web enregistre la configuration.
  • Convergence #1391 Phase 0 Limite de propriété du code de partage A : Complétez la cohérence de propriété des scénarios de préfixe SH/SZ et clarifiez la portée de cette série de réparations pour data_provider/baostock_fetcher.py, data_provider/pytdx_fetcher.py et data_provider/tushare_fetcher.py.
  • Correction de la conversion de format interne des sources de données de secours telles que Baostock lorsque STOCK_LIST utilise des codes de partage A nus, conservant la configuration utilisateur pour continuer à utiliser des numéros de stock à 6 chiffres.
  • Les mises à jour automatiques du bureau Windows seront modifiées pour exécuter le programme d'installation silencieusement après que l'utilisateur a confirmé le redémarrage de l'installation et nettoyer les références de processus après l'arrêt du backend intégré, réduisant ainsi la probabilité que le programme d'installation demande « L'analyse quotidienne des stocks ne peut pas être fermée ».
  • Le bureau macOS migre la configuration d'exécution vers le répertoire de données utilisateur et migre .env, la base de données et les journaux pendant que les fichiers de l'ancien package .app sont toujours accessibles, pour éviter une reconfiguration après des remplacements et des mises à niveau ultérieurs.
  • Restauration de l'extraction des sections associées et des champs de liaison de section dans les instantanés compatibles agent/historique, et correction du problème de régression du « lien de section » manquant dans le nouveau rapport de la page d'accueil.
  • Correction du nom du champ JSON de l'alarme héritée et de la description sémantique de livraison de la période silencieuse dans l'aide des paramètres Web.
  • Correction du problème selon lequel le titre de configuration, la description et les options déroulantes des clés dans les zones de source de données, de notification, de système et d'agent de la page des paramètres Web chinois sont manquants.
  • Correction d'un problème où l'état de l'agent/de la tâche d'analyse en cours pouvait rester après avoir changé de session et reconnecté à la tâche de la page d'accueil.
  • Ajout d'une sous-piste de trace adaptée au fournisseur à l'agent unique et conservation des matériaux reasoning_content et du protocole d'outil de la réflexion DeepSeek V4 + appel d'outil sur les roues.
  • Ajout d'un délai d'expiration au niveau des appels à l'interface ascendante historique des actions Akshare Sina/Tencent A et réalisation du test de régression de routage du code boursier Tushare 605xxx Shanghai pour éviter que l'analyse planifiée ne se bloque en raison du manque de réponse de la source de données.
  • Augmenter la limite inférieure de dépendance de exchange-calendars à 4.13.0 pour éviter un échec d'analyse dû à la défaillance de l'unité Timedelta T lors de l'importation du calendrier de trading dans l'environnement pandas 3.
  • Les résultats d'analyse déclenchés par les commandes interactives (conversations DingTalk, conversations Feishu, Telegram) sont uniquement renvoyés à la conversation source et ne sont plus diffusés simultanément sur les canaux de notification statiques.
  • Adapté à l'authentification Longbridge OAuth 2.0 et à la récupération du cache de jetons pour éviter que la source de données Longbridge ne soit jugée à tort comme non configurée lorsque le nouveau backend ne dispose pas d'un jeton d'accès hérité.
  • Le chemin Longbridge OAuth enregistre explicitement les rétrogradations lorsque le SDK actuel ne prend pas en charge OAuthBuilder / Config.from_oauth pour éviter les échecs de construction lorsque Linux/Docker ne peut installer que l'ancien SDK.
  • Compatible avec le scénario où la ligne quotidienne YFinance renvoie un index de date sans nom, pour éviter l'interruption du repli quotidien des actions américaines provoquée par l'absence de la colonne date après standardisation. ###Documentations

daily_stock_analysis v3.19.0

新功能

  • 落地 #1391 Phase 1 运行诊断最小链路：任务/SSE 追加 trace_id，并记录日线与实时行情 ProviderRun 快照。
  • 告警中心新增 P7 大盘红绿灯结构化规则，支持 market_light_status 与 market_light_score_drop 并复用现有 worker、触发历史、通知和冷却链路。
  • 落地 #1391 Phase 2 运行诊断摘要：生成用户可读 RunDiagnosticSummary，提供历史报告诊断 API 与脱敏复制文本。
  • 落地 #1391 Phase 3 运行诊断可见性：报告详情和任务面板默认折叠展示运行状态、trace 与可复制排障信息；后端通过 api/v1/history/{record_id}/diagnostics 与 context_snapshot.diagnostics 提供历史链路回填。
  • 新增 AnalysisContextPack P1 内部契约与脱敏序列化测试。
  • 新增 AnalysisContextPack P2 builder，从普通分析 pipeline 已有 artifacts 组装内部上下文包。
  • 问股新增默认关闭的可见对话上下文压缩，支持 Web 开关、Agent 高级 preset、滚动摘要和最近轮次原文保护，降低长会话 token 消耗。
  • 股票自动补全索引默认支持从 GitHub main 远程刷新并缓存到本地，Web/CLI 分析入口失败时自动降级到内置索引，降低摘帽和更名后旧简称污染分析的概率。
  • 普通分析与 Agent 运行时 Prompt 接入 AnalysisContextPack 低敏摘要，保持 history/API/Web 输出兼容。

改进

  • scripts/fetch_tushare_stock_list.py 可对 A 股中带 XD/XR/DR/N/C 前缀的名称进行回填修正，供自动补全刷新流程默认使用。
  • Web 路由页面改为按需加载，降低首包体积并增加路由加载失败恢复提示。
  • Web 完整报告 Markdown 抽屉改为按需加载。
  • 新增市场阶段推断基线并明确盘前、盘中、午休、临近收盘、盘后和非交易日语义。
  • 新增运行态市场阶段上下文构造与降级测试。
  • 设置页配置帮助阶段性补齐 Web 设置页实际展示/可配置字段的中英双语文案，覆盖 Agent、回测、报告、通知路由、系统运行时、AI legacy、数据源和通知高级配置。
  • P2-min：LLM Prompt 注入市场阶段上下文。

修复

  • 股票自动补全索引生成缺少 pypinyin 时改为直接失败，避免写出缺失拼音字段的降级索引。
  • 归一腾讯实时行情成交量为股口径，避免量能变化倍数被放大并误导分析报告。
  • Docker 默认部署移除 .env 单文件挂载，避免 WebUI 保存配置时因 os.replace 更新挂载点触发 Device or resource busy。
  • 收敛 #1391 Phase 0 A 股代码归属边界：补齐 SH/SZ 前缀场景的归属一致性，明确 data_provider/baostock_fetcher.py、data_provider/pytdx_fetcher.py、data_provider/tushare_fetcher.py 的本轮修复范围。
  • 修复 STOCK_LIST 使用裸 A 股代码时 Baostock 等数据源 fallback 的内部格式转换，保持用户配置继续使用 6 位股票编号。
  • Windows 桌面端自动更新在用户确认重启安装后改为静默执行安装器，并在停止内置后端后清理进程引用，降低安装器提示“每日股票分析无法关闭”的概率。
  • macOS 桌面端将运行时配置迁移到用户数据目录，并在旧 .app 包内文件仍可访问时迁移 .env、数据库和日志，避免后续替换升级后重新配置。
  • 恢复 Agent/历史兼容快照中的关联板块与板块联动字段提取，修复新版首页报告缺少“板块联动”的回归问题。
  • 修正 Web 设置帮助中 legacy 告警 JSON 字段名与静默时段投递语义说明。
  • 修复 Web 中文设置页在数据源、通知、系统与 Agent 区域的配置标题、说明和关键下拉选项漏翻问题。
  • 修复问股会话切换和首页任务重连后可能残留 Agent/分析任务进行中状态的问题。
  • 问股 single-agent 新增 provider-aware trace 分轨，跨轮保留 DeepSeek V4 thinking + tool-call 的 reasoning_content 与工具协议材料。
  • 为 Akshare 新浪/腾讯 A 股历史兜底接口增加调用级超时，并补齐 Tushare 605xxx 沪市代码路由回归测试，避免定时分析因数据源无响应而挂起。
  • 将 exchange-calendars 依赖下限提升到 4.13.0，避免 pandas 3 环境导入交易日历时因 Timedelta 单位 T 失效导致分析失败。
  • 交互式命令（钉钉会话、飞书会话、Telegram）触发的分析结果只回到来源会话，不再同时广播到静态通知渠道。
  • 适配 Longbridge OAuth 2.0 认证与 token 缓存恢复，避免新后台无 Legacy Access Token 时长桥数据源被误判为未配置。
  • Longbridge OAuth 路径在当前 SDK 不支持 OAuthBuilder / Config.from_oauth 时明确日志降级，避免 Linux/Docker 仅可安装旧 SDK 时构建失败。
  • 兼容 YFinance 日线返回未命名日期索引的场景，避免标准化后缺少 date 列导致美股日线 fallback 中断。
