#milvus v2.6.26

##v2.6.26

Date de sortie : 26 octobre 2026

| Version Milvus | Python SDKVersion | Node.js SDKVersion | Version Java SDK | Aller à la version SDK | | ---------- | ------------------ | ------------------- | ---------------- | ---------- | | 2.6.26 | 2.6.17 | 2.6.17 | 2.6.27 | 2.6.5 |

Nous sommes ravis d'annoncer la sortie de Milvus v2.6.26 ! Cette version accélère le décodage des messages RPC, réduit l'utilisation de la mémoire proxy pour les requêtes de recherche et de requête volumineuses, et corrige les plantages de QueryNode dans le filtrage nullable et NGRAM, les blocages lors des tâches de chargement et d'importation de la collection, ainsi que les horodatages qui pourraient revenir en arrière après le démarrage du coordinateur.

Améliorations

  • Décodage accéléré des messages RPC de recherche, de requête, d'insertion et d'insertion avec un décodeur protobuf plus rapide, activé par défaut et commutable via common.enableFastPB (#53994, #54002)
  • Épinglage du stemmer de l'analyseur de texte indépendamment de Tantivy afin que les mises à niveau de Tantivy ne modifient pas les résultats de stemming ou n'entraînent pas de correspondances manquées sur les index de texte existants et les données BM25 (#54029, #54098)
  • Réduction du délai entre la fin d'une opération segcore asynchrone et la réception du résultat par son appelant sous une charge importante, de sorte que les résultats terminés n'attendent plus derrière le travail en file d'attente tout en conservant la mémoire (#54128)
  • Utilisation réduite de la mémoire proxy pour les requêtes de recherche et de requêtes volumineuses en partageant les charges utiles des requêtes entre les fragments au lieu de les copier en profondeur par fragment ; le tas actif est passé de 8.7 Go à 5.85 Go lors d'un test avec 50 nq=10 000 recherches simultanées (#54224)
  • Fusion des conditions array_contains de même colonne dans les chaînes OR/AND dans array_contains_any/array_contains_all lors de la compilation du plan, réduisant ainsi la surcharge de compilation pour les filtres avec des milliers de conditions (#54435)
  • Amélioration du filtrage de vérification des valeurs nulles sur les index de chemin JSON dans les segments scellés en mettant en cache le bitmap de validité au lieu de réanalyser l'index pour chaque requête (#54422)
  • Ajout des paramètres queryNode.segcore.interimIndex.sparseIPIndexAlgo et sparseBM25IndexAlgo pour choisir l'algorithme d'indexation provisoire (TAAT_NAIVE, DAAT_WAND ou DAAT_MAXSCORE) pour la recherche IP clairsemée et BM25 sur les segments scellés en croissance et non indexés (#54443)
  • Réduction des lectures et analyses répétées du pied de page Parquet lors du chargement de segments StorageV2 dans plusieurs lots, et récupération d'un correctif milvus-storage pour le format d'URL du point de terminaison sur les cloud souverains Azure (#54488)

Corrections de bugs

  • Correction d'un problème où la recherche de regroupement avec une taille de groupe stricte pouvait renvoyer des groupes avec moins de résultats group_size même lorsqu'il existait suffisamment d'entités correspondantes ; ajout de queryNode.groupBy.strictGroupStrategy et des paramètres associés pour régler ce comportement (#53451)
  • Correction d'un problème où le filtrage sur un champ nullable pendant l'exécution d'insertions ou d'upserts pouvait faire planter le QueryNode ou mal lire les valeurs nulles dans les segments en croissance (#53870).
  • Correction d'un problème où les filtres combinant AND/OR avec des comparaisons d'entiers hors plage sur des champs entiers nullables pouvaient faire planter le QueryNode ou renvoyer des résultats incorrects (#53897).
  • Correction d'un problème où les requêtes LIKE sur les champs avec un index NGRAM pouvaient planter le QueryNode ou renvoyer des lignes non correspondantes lorsque le modèle contenait des caractères NUL (#53710).
  • Correction d'un problème où un échec de lecture de la fenêtre TSO persistante lors du démarrage du coordinateur pouvait entraîner le recul des horodatages et des identifiants nouvellement alloués (#51795).
  • Correction d'un problème où les requêtes de recherche et de requête annulées ou expirées restaient dans la file d'attente du proxy et étaient toujours exécutées, retardant les autres requêtes sous charge (#52938).
  • Réduction de la mémoire maximale de compactage du clustering, ce qui pourrait tuer les DataNodes sur les grandes partitions (#54078)
  • Correction d'un problème où les tâches d'importation pouvaient se bloquer indéfiniment lorsqu'une seule requête nécessitait plus de mémoire que la limite de mémoire d'importation DataNode, et où les tâches d'importation abandonnées attendaient de la mémoire au lieu de quitter (#54112).
  • Correction d'un problème où les filtres sur les champs JSON qui mélangent des littéraux entiers et à virgule flottante (par exemple p == 1 OR p == 2.0) renvoyaient des résultats incomplets lorsque les statistiques JSON étaient chargées (#54157).
  • Correction d'un problème où le chargement et l'équilibrage de la collection pouvaient s'arrêter indéfiniment lorsqu'un QueryNode chargeait ou surveillait un RPC bloqué ; Les délais d'expiration des tâches QueryCoord sont désormais appliqués, avec des valeurs par défaut augmentées à 2 minutes pour les tâches de canal et à 5 minutes pour les tâches de segment et de leader (#54218).
  • Correction d'un problème où le chargement de segments sur QueryNode pouvait se bloquer indéfiniment parce que des serveurs simultanés manquaient les notifications de fin de chargement ou d'annulation (#54455).
  • Correction d'un problème où les chargements de segments de faible priorité, tels que ceux déclenchés par l'équilibrage ou les mises à jour d'index, chargeaient les données de champ brutes avec une priorité élevée et étaient en concurrence avec les chargements urgents de ressources (#54336).
  • Correction d'un problème où les requêtes paginées renvoyant une page vide échouaient avec "FieldData type not matched" dans Go SDK lorsque la sortie incluait un tableau vectoriel ou des champs vectoriels StructArray (#54360).
  • Correction d'un problème où la suppression d'une tâche d'importation n'arrêtait pas ses tâches d'importation déjà en cours d'exécution sur DataNodes (#54433)
  • Correction d'un problème où les partitions créées après LoadCollection restaient déchargées sur les clusters de secours CDC, de sorte que leurs données ne pouvaient pas être interrogées jusqu'à ce que la collection soit libérée et rechargée (#54567).
  • Correction d'un problème où la métrique milvus_proxy_report_value comptait deux fois les upserts réussis, surestimant la valeur rapportée (#54606).

milvus v2.6.26

v2.6.26

Release date: October 26, 2026

| Milvus Version | Python SDK Version | Node.js SDK Version | Java SDK Version | Go SDK Version | | -------------- | ------------------ | ------------------- | ---------------- | -------------- | | 2.6.26 | 2.6.17 | 2.6.17 | 2.6.27 | 2.6.5 |

We are excited to announce the release of Milvus v2.6.26! This release speeds up RPC message decoding, cuts Proxy memory usage for large search and query requests, and fixes QueryNode crashes in nullable and NGRAM filtering, hangs during collection loading and import jobs, and timestamps that could go backward after coordinator startup.

Improvements

  • Sped up decoding of search, query, insert, and upsert RPC messages with a faster protobuf decoder, enabled by default and switchable via common.enableFastPB (#53994, #54002)
  • Pinned the text analyzer stemmer independently of Tantivy so that Tantivy upgrades do not change stemming results or cause missed matches on existing text indexes and BM25 data (#54029, #54098)
  • Reduced the delay between an async segcore operation completing and its caller receiving the result under heavy load, so completed results no longer wait behind queued work while holding memory (#54128)
  • Reduced Proxy memory usage for large search and query requests by sharing request payloads across shards instead of deep-copying them per shard; live heap dropped from 8.7 GB to 5.85 GB in a test with 50 concurrent nq=10000 searches (#54224)
  • Merged same-column array_contains conditions in OR/AND chains into array_contains_any/array_contains_all during plan compilation, reducing compilation overhead for filters with thousands of conditions (#54435)
  • Improved null-check filtering on JSON path indexes in sealed segments by caching the validity bitmap instead of rescanning the index for every query (#54422)
  • Added the queryNode.segcore.interimIndex.sparseIPIndexAlgo and sparseBM25IndexAlgo settings to choose the interim index algorithm (TAAT_NAIVE, DAAT_WAND, or DAAT_MAXSCORE) for sparse IP and BM25 search on growing and unindexed sealed segments (#54443)
  • Reduced repeated Parquet footer reads and parsing when loading StorageV2 segments in multiple batches, and picked up a milvus-storage fix for the endpoint URL format on Azure sovereign clouds (#54488)

Bug fixes

  • Fixed an issue where grouping search with strict group size could return groups with fewer than group_size results even when enough matching entities existed; added queryNode.groupBy.strictGroupStrategy and related settings to tune this behavior (#53451)
  • Fixed an issue where filtering on a nullable field while inserts or upserts were running could crash the QueryNode or misread null values in growing segments (#53870)
  • Fixed an issue where filters that combine AND/OR with out-of-range integer comparisons on nullable integer fields could crash the QueryNode or return incorrect results (#53897)
  • Fixed an issue where LIKE queries on fields with an NGRAM index could crash the QueryNode or return non-matching rows when the pattern contained NUL characters (#53710)
  • Fixed an issue where a failed read of the persisted TSO window during coordinator startup could cause newly allocated timestamps and IDs to go backward (#51795)
  • Fixed an issue where canceled or timed-out search and query requests stayed in the Proxy queue and were still executed, delaying other requests under load (#52938)
  • Reduced peak memory of clustering compaction, which could OOM-kill DataNodes on large partitions (#54078)
  • Fixed an issue where import jobs could hang indefinitely when a single request needed more memory than the DataNode import memory limit, and where dropped import jobs kept waiting for memory instead of exiting (#54112)
  • Fixed an issue where filters on JSON fields that mix integer and floating-point literals (e.g. p == 1 OR p == 2.0) returned incomplete results when JSON stats were loaded (#54157)
  • Fixed an issue where collection loading and balancing could stall indefinitely when a QueryNode load or watch RPC hung; QueryCoord task timeouts are now enforced, with defaults raised to 2 minutes for channel tasks and 5 minutes for segment and leader tasks (#54218)
  • Fixed an issue where segment loading on QueryNode could hang indefinitely because concurrent waiters missed load-completion or cancellation notifications (#54455)
  • Fixed an issue where low-priority segment loads, such as those triggered by balancing or index updates, loaded raw field data at high priority and competed with urgent loads for resources (#54336)
  • Fixed an issue where paginated queries returning an empty page failed with "FieldData type not matched" in the Go SDK when the output included vector array or StructArray vector fields (#54360)
  • Fixed an issue where dropping an import job did not stop its import tasks already running on DataNodes (#54433)
  • Fixed an issue where partitions created after LoadCollection stayed unloaded on CDC standby clusters, so their data could not be queried until the collection was released and reloaded (#54567)
  • Fixed an issue where the milvus_proxy_report_value metric counted successful upserts twice, overstating the reported value (#54606)
