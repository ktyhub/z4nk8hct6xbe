LocalAI v4.6.0

🎉 Sortie LocalAI 4.6.0 ! 🚀

<h1 align="centre"> <br> <img hauteur="300" src="https://raw.githubusercontent.com/mudler/LocalAI/refs/heads/master/core/http/static/logo.png"> <br> <br> </h1>

LocalAI 4.6.0 est sorti !

Il s'agit d'une version axée sur la fiabilité : les backends AMD ROCm fonctionnent désormais sur GPU à pleine vitesse, les charges de modèles distribués ne se bloquent plus lorsqu'un employé décède et les sessions en temps réel se réchauffent de manière prévisible. Il apporte également une bifurcation de conversation à l'interface utilisateur de chat intégrée, un compteur Prometheus pour les événements PII/audit et un correctif SSRF pour la galerie de modèles.

Points forts :

  • 🔴 AMD ROCm fonctionne correctement - les backends audio ggml sont déchargés sur le GPU, les données de réglage du noyau hipBLASLt sont regroupées (plus de noyaux génériques lents), rocm-vllm installe la roue droite et la table d'identification ASIC est trouvée.
  • 🎙️ Temps réel prévisible - les sessions réchauffent avec impatience l'ensemble du pipeline (VAD, ASR, LLM, TTS) dès le départ, de sorte que le premier tour ne paie plus les calages de démarrage à froid par modèle, plus un nouveau POST /backend/load API et un bouton d'interface utilisateur "Charger en mémoire".
  • 🌿 Forking chat - réessayez n'importe quelle réponse de l'assistant, créez une nouvelle discussion à partir de n'importe quel point, dupliquez ou copiez l'intégralité de la conversation, directement dans l'interface utilisateur intégrée.
  • 🛡️ Durcissement distribué - un travailleur mort ne peut plus verrouiller le verrou consultatif de chargement de modèle (le coin d'environ 15 minutes a disparu), et les travailleurs backend orphelins s'auto-terminent au lieu de détenir la VRAM.
  • 📊 PII/métriques d'audit - Les détections/masques/blocs PII sont exportés sous forme de compteur Prometheus, afin que vous puissiez alerter lorsque le filtre cesse de fonctionner.
  • 🔒 Correction SSRF de la galerie - Les récupérations d'URL de configuration POST /models/apply sont validées par rapport aux adresses privées/bouclage/métadonnées.

Plus des installations backend idempotentes, des correctifs d'appel d'outils et de raisonnement sur les backends vLLM et Python/MLX, la compatibilité du proxy cloud avec les modèles de raisonnement les plus récents et l'ensemble habituel de mises à jour de dépendances.

🚀 Nouvelles fonctionnalités et améliorations majeures

🔴 Les backends AMD ROCm fonctionnent correctement sur GPU

Quatre correctifs couplés permettent aux backends ROCm/hipBLAS de fonctionner réellement sur du matériel AMD et à pleine vitesse, au lieu de revenir silencieusement au processeur ou aux noyaux génériques lents :

  • Déchargement GPU pour les backends audio ggml (#10667) : rocm-qwen3-tts-cpp, rocm-omnivoice-cpp, acestep-cpp et vibevoice-cpp construisaient uniquement le CPU car leurs Makefiles passaient le -DGGML_HIPBLAS=ON sans opération (le ggml en amont ne comprend que -DGGML_HIP=ON) et la boucle de lien CMake a omis hip. Ils utilisent désormais la même recette hipblas que lama-cpp et relient le backend HIP.
  • Données de réglage du noyau hipBLASLt (#10660, #10672) : le packager a regroupé les données rocBLAS mais pas les fichiers parallèles hipBLASLt TensileLibrary_lazy_gfx*.dat, donc chaque arch utilisait silencieusement des noyaux lents et enregistrait Cannot read "TensileLibrary_lazy_gfx*.dat". Les données sont désormais regroupées et le HIPBLASLT_TENSILE_LIBPATH est exporté par le llama-cpp et le turboquant run.sh.
  • rocm-vllm installe la roue droite (#10642, #10651) : le backend tirait le PyPI vllm uniquement CUDA (ModuleNotFoundError: No module named 'vllm' fatal sur AMD). Il épingle désormais CPython 3.12 et installe vLLM à partir de l'index de roue ROCm (https://wheels.vllm.ai/rocm/).
  • Table d'identification ASIC trouvée (#10624, #10627) : l'image hipblas de calcul uniquement n'a pas de /opt/amdgpu/share/libdrm/amdgpu.ids, donc chaque chargement de modèle est averti. La copie libdrm-common d'Ubuntu est désormais mise en place par un lien symbolique.

🔗 PR : #10667, #10672, #10651, #10627

🎙️ Temps réel : échauffement rapide du pipeline + un chargement en mémoire API

Les sessions vocales en temps réel réchauffent désormais avec impatience et de manière bloquante l'ensemble du pipeline (VAD, transcription, LLM, TTS, détection sonore, reconnaissance vocale) au début de la session au lieu de charger paresseusement chaque sous-modèle lors de la première utilisation. Le premier tour ne paie plus les blocages de démarrage à froid par modèle, et les erreurs de chargement du modèle apparaissent dès le début de la session (comme model_load_error) plutôt qu'à mi-parcours. Les sous-modèles de pipeline se chargent simultanément, de sorte qu'une session se réchauffe au moment de son étape la plus lente, pas à la somme, et une étape échouée nomme chaque modèle cassé dans une erreur jointe.

Cela ajoute également un POST /backend/load (et /v1/backend/load) natif de LocalAI, l'inverse de /backend/shutdown, exposé comme une action d'interface utilisateur « Charger en mémoire » et un outil d'administration MCP load_model, afin que les administrateurs puissent préchauffer n'importe quel modèle (y compris les pipelines complets) à la demande. L'indicateur de démarrage --load-to-memory passe désormais par le même moteur. Désinscription par pipeline avec disable_warmup: true.

🔗 PR : #10662

🌿 Chat bifurqué dans l'interface utilisateur intégrée

L'interface utilisateur du chat React bénéficie d'outils de gestion de conversation : régénérez n'importe quelle réponse de l'assistant (pas seulement la dernière), créez une nouvelle discussion à partir de n'importe quelle réponse, dupliquez une discussion dans une copie indépendante ou copiez l'intégralité de la conversation sur le clipboard en tant que Markdown. Réessayer une réponse à mi-conversation tronque correctement la conversation avant de redemander, à la fois dans le DOM et dans la charge utile de la requête (cela corrige également un bogue latent de fermeture obsolète où une nouvelle tentative à mi-conversation renvoyait les retours en aval vers le modèle). Tout le côté client, ​​aucun changement dans le backend.

🔗 PR : #10654

🛡️ Processus plus robuste et cycle de vie distribué

  • Cale de verrouillage consultatif pour les travailleurs morts (#10600) : un travailleur distribué en charge moyenne pourrait épingler un verrou consultatif PostgreSQL par modèle et faire échouer chaque demande ultérieure adressée à ce modèle avec 55P03 pendant environ 15 minutes. Le contexte de chargement détaché est désormais limité par un plafond de charge de modèle, l'attente d'installation honore l'annulation via singleflight.DoChan et lock_timeout est limité au budget de contexte de l'appelant au lieu d'un GUC de déploiement global.
  • Filet de sécurité contre la mort des parents (#10639) : si LocalAI est SIGKILL avant le démontage, les travailleurs backend générés étaient habitués à être reparentés pour s'initialiser et s'attarder, détenant la VRAM et leur port. Chaque backend interroge désormais son PID parent et se termine automatiquement lors du reparentage. Configurable via LOCALAI_BACKEND_PARENT_WATCH (activé par défaut, arrêt automatique sous Windows) et LOCALAI_BACKEND_PARENT_WATCH_INTERVAL (2s par défaut). La couverture C++ est lama-cpp pour l'instant ; Python couvre tous les backends.
  • Chien de garde plus silencieux (#10602, #10607) : le RPC Free() facultatif renvoie gRPC Unimplemented pour de nombreux backends et le proxy de la fédération, de sorte que le chien de garde n'enregistre plus un Error freeing GPU resources trompeur lors de l'expulsion. Un nouvel assistant grpcerrors.IsUnimplemented le distingue des véritables échecs.
  • Installations backend idempotentes (#10643) : POST /backends/apply et la boucle de démarrage LOCALAI_EXTERNAL_BACKENDS ne téléchargent plus et ne réextrait plus un backend déjà installé à chaque application/démarrage. Passez "force": true (le bouton d'installation de l'interface utilisateur le fait toujours, faisant également office de "Réinstaller").

🔗 PR : #10600, #10639, #10607, #10643

📊 Événements PII/audit en tant que compteur Prometheus

Le pipeline d'audit middleware PII / MITM émet désormais un seul compteur monotone, localai_pii_events_total{kind, origin, action, direction}, sur /metrics, instrumenté au point d'étranglement EventStore.Record. Les étiquettes sont limitées par la cardinalité (pas de modèle ni d'ID utilisateur). Cela complète le tampon annulaire /api/pii/events limité en capacité et, surtout, permet d'alerter en cas de panne de filtre silencieux : rate() sur le compteur détecte que le filtre PII a cessé de fonctionner après un déploiement.

🔗 PR : #10641

🔒 Galerie Durcissement SSRF

POST /models/apply avec un id vide récupère directement le url fourni ; dans une configuration Docker par défaut (pas de clé API), tout client accessible pourrait sonder les services internes ou les métadonnées du cloud (169.254.169.254) et exfiltrer une tranche via l'erreur de tâche. Les récupérations de configuration de la galerie s'exécutent désormais via la garde ValidateExternalURL existante (la même qui protège le proxy CORS et les téléchargements multimédias), bloquant les adresses privées, de bouclage, de lien local, non spécifiées et de métadonnées. Seul le simple http(s):// est validé ; huggingface://, github:, oci://, ollama:// et file:// sont intacts.

🔗 PR : #10673

🐛 Corrections de bugs (récapitulatif)

  • fix(vllm) : restauration de l'extraction d'appels d'outils sans streaming qui a régressé après #10351 (un indicateur de capacité a été confondu avec l'état d'exécution) - #10638
  • fix(python-backends) : décode l'appel à l'outil arguments pour les modèles de chat (annule les boucles d'agent MLX/Qwen3.5) et divise le raisonnement lorsqu'un modèle n'émet qu'un </think> de fermeture - #10658
  • fix(cloud-proxy) : supprimez temperature/top_p et envoyez max_completion_tokens afin que le routage vers les modèles de raisonnement les plus récents (Claude Opus 4.x, GPT-5.x) arrête le 400ing - #10640
  • fix(config) : rétablit le swa_full:true par défaut pour les modèles à fenêtre coulissante avec attention (restaure le cache KV réduit par la lumière de la mémoire ; toujours disponible en tant qu'opt-in explicite par modèle) - #10674
  • fix(kokoros) : implémentez le stub de trait AudioTranscriptionLive pour que le backend compile avec le proto mis à jour - #10612
  • fix(launcher) : conservez les données/configuration du lanceur de bureau sous ~/.localai au lieu du répertoire de travail de l'interface graphique - #10610, #10613

LocalAI v4.6.0

🎉 LocalAI 4.6.0 Release! 🚀

<h1 align="center"> <br> <img height="300" src="https://raw.githubusercontent.com/mudler/LocalAI/refs/heads/master/core/http/static/logo.png"> <br> <br> </h1>

LocalAI 4.6.0 is out!

This is a reliability-focused release: AMD ROCm backends now run on-GPU at full speed, distributed model loads no longer wedge when a worker dies, and realtime sessions warm up predictably. It also brings conversation forking to the built-in chat UI, a Prometheus counter for PII/audit events, and an SSRF fix for the model gallery.

Highlights:

  • 🔴 AMD ROCm runs correctly - ggml audio backends offload to the GPU, hipBLASLt kernel-tuning data is bundled (no more slow generic kernels), rocm-vllm installs the right wheel, and the ASIC ID table is found.
  • 🎙️ Predictable realtime - sessions eagerly warm the whole pipeline (VAD, ASR, LLM, TTS) up front, so the first turn no longer pays per-model cold-start stalls, plus a new POST /backend/load API and "Load into memory" UI button.
  • 🌿 Forking chat - retry any assistant answer, branch a new chat from any point, duplicate, or copy the whole conversation, directly in the built-in UI.
  • 🛡️ Distributed hardening - a dead worker can no longer pin the model-load advisory lock (the ~15-minute wedge is gone), and orphaned backend workers self-terminate instead of holding VRAM.
  • 📊 PII/audit metrics - PII detections/masks/blocks are exported as a Prometheus counter, so you can alert when the filter stops firing.
  • 🔒 Gallery SSRF fix - POST /models/apply config-URL fetches are validated against private/loopback/metadata addresses.

Plus idempotent backend installs, tool-calling and reasoning fixes across the vLLM and Python/MLX backends, cloud-proxy compatibility with the newest reasoning models, and the usual set of dependency updates.

🚀 New Features & Major Enhancements

🔴 AMD ROCm backends run correctly on-GPU

Four coupled fixes make ROCm/hipBLAS backends actually run on AMD hardware, and at full speed, instead of silently falling back to CPU or slow generic kernels:

  • GPU offload for ggml audio backends (#10667): rocm-qwen3-tts-cpp, rocm-omnivoice-cpp, acestep-cpp, and vibevoice-cpp were building CPU-only because their Makefiles passed the no-op -DGGML_HIPBLAS=ON (upstream ggml only understands -DGGML_HIP=ON) and the CMake link loop omitted hip. They now use the same hipblas recipe as llama-cpp and link the HIP backend.
  • hipBLASLt kernel-tuning data (#10660, #10672): the packager bundled rocBLAS data but not the parallel hipBLASLt TensileLibrary_lazy_gfx*.dat files, so every arch silently used slow kernels and logged Cannot read "TensileLibrary_lazy_gfx*.dat". The data is now bundled and HIPBLASLT_TENSILE_LIBPATH is exported by the llama-cpp and turboquant run.sh.
  • rocm-vllm installs the right wheel (#10642, #10651): the backend was pulling the CUDA-only PyPI vllm (fatal ModuleNotFoundError: No module named 'vllm' on AMD). It now pins CPython 3.12 and installs vLLM from the ROCm wheel index (https://wheels.vllm.ai/rocm/).
  • ASIC ID table found (#10624, #10627): the compute-only hipblas image lacks /opt/amdgpu/share/libdrm/amdgpu.ids, so every model load warned. Ubuntu's libdrm-common copy is now symlinked into place.

🔗 PRs: #10667, #10672, #10651, #10627

🎙️ Realtime: eager pipeline warm-up + a load-into-memory API

Realtime voice sessions now eagerly and blockingly warm the entire pipeline (VAD, transcription, LLM, TTS, sound detection, voice recognition) at session start instead of lazy-loading each sub-model on first use. The first turn no longer pays per-model cold-start stalls, and model-load errors surface up front at session start (as model_load_error) rather than mid-stream. Pipeline sub-models load concurrently, so a session warms in the time of its slowest stage, not the sum, and a failed stage names every broken model in a joined error.

This also adds a LocalAI-native POST /backend/load (and /v1/backend/load), the inverse of /backend/shutdown, exposed as a "Load into memory" UI action and a load_model MCP admin tool, so admins can pre-warm any model (including full pipelines) on demand. The --load-to-memory startup flag now routes through the same engine. Opt out per pipeline with disable_warmup: true.

🔗 PRs: #10662

🌿 Forking chat in the built-in UI

The React chat UI gains conversation-management tools: regenerate any assistant answer (not just the last), branch a new chat from any answer, duplicate a chat into an independent copy, or copy the whole conversation to the clipboard as Markdown. Retrying a mid-conversation answer correctly truncates the conversation before re-asking, both in the DOM and in the request payload (this also fixes a latent stale-closure bug where a mid-conversation retry sent the downstream turns back to the model). All client-side, no backend changes.

🔗 PRs: #10654

🛡️ Sturdier process and distributed lifecycle

  • Dead-worker advisory-lock wedge (#10600): a distributed worker going mid-load could pin a per-model PostgreSQL advisory lock and fail every subsequent request to that model with 55P03 for ~15 minutes. The detached load context is now bounded by a model-load ceiling, the install wait honors cancellation via singleflight.DoChan, and lock_timeout is scoped to the caller's context budget instead of a deployment-global GUC.
  • Parent-death safety net (#10639): if LocalAI is SIGKILLed before teardown, spawned backend workers used to get reparented to init and linger, holding VRAM and their port. Each backend now polls its parent PID and self-terminates on reparenting. Configurable via LOCALAI_BACKEND_PARENT_WATCH (default on, auto-off on Windows) and LOCALAI_BACKEND_PARENT_WATCH_INTERVAL (default 2s). C++ coverage is llama-cpp for now; Python covers all backends.
  • Quieter watchdog (#10602, #10607): the optional Free() RPC returns gRPC Unimplemented for many backends and the federation proxy, so the watchdog no longer logs a misleading Error freeing GPU resources on eviction. A new grpcerrors.IsUnimplemented helper distinguishes it from genuine failures.
  • Idempotent backend installs (#10643): POST /backends/apply and the LOCALAI_EXTERNAL_BACKENDS boot loop no longer re-download and re-extract an already-installed backend on every apply/boot. Pass "force": true (the UI's install button still does, doubling as "Reinstall").

🔗 PRs: #10600, #10639, #10607, #10643

📊 PII/audit events as a Prometheus counter

The PII middleware / MITM audit pipeline now emits a single monotonic counter, localai_pii_events_total{kind, origin, action, direction}, on /metrics, instrumented at the EventStore.Record choke point. Labels are cardinality-bounded (no pattern or user IDs). This complements the capacity-bound /api/pii/events ring buffer and, crucially, makes silent filter failure alertable: rate() on the counter detects that the PII filter stopped firing after a deploy.

🔗 PRs: #10641

🔒 Gallery SSRF hardening

POST /models/apply with an empty id fetches the supplied url directly; in a default Docker setup (no API key) any reachable client could probe internal services or cloud-metadata (169.254.169.254) and exfiltrate a slice via the job error. Gallery config fetches now run through the existing ValidateExternalURL guard (the same one protecting the CORS proxy and media downloads), blocking private, loopback, link-local, unspecified, and metadata addresses. Only plain http(s):// is validated; huggingface://, github:, oci://, ollama://, and file:// are untouched.

🔗 PRs: #10673

  • fix(launcher): keep the desktop launcher's data/config under ~/.localai instead of the GUI's working directory - #10610, #10613
