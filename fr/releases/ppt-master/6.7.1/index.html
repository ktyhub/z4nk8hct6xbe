ppt-maître v6.7.1

Version du correctif : correctifs pour le travail que l'aperçu en direct, la conversion source et l'importation source pourraient perdre sans avertissement, ainsi qu'une transmission complète des chaînes de l'interface utilisateur dans chaque langue.

Aperçu en direct

  • Les annotations non appliquées et les modifications directes survivent désormais à un arrêt du serveur (1fa3768a, #319). Avant, ils ne vivaient que dans la mémoire du serveur, et le délai d'inactivité, l'aperçu de sortie, --shutdown, un kill ou un crash avant l'application des modifications les supprimait. La fermeture du couvercle d'un ordinateur portable rendait cela probable : le minuteur d'inactivité comptait le temps de suspension, de sorte que le serveur se terminait au réveil.
    • Chaque changement d'étape est écrit dans live_preview/draft.json avant d'être reconnu. Le prochain démarrage le restaure et l'interface utilisateur répertorie les diapositives restaurées ; vous décidez toujours quand postuler.
    • Une diapositive dont le SVG a été modifié entre-temps n'y est pas relue. Son brouillon est conservé sous la forme live_preview/draft_conflict_<timestamp>.json et l'interface utilisateur l'indique.
    • L'aperçu de sortie conserve désormais le brouillon au lieu de le supprimer. Un échec d’écriture de brouillon est signalé dans l’interface utilisateur.
    • Appliquer les modifications conserve une diapositive mise en scène lorsqu'un élément annoté n'existe plus, au lieu de supprimer l'annotation. Les SVG sont écrits de manière atomique, et une soumission qui ne trouve rien en attente sur le serveur est signalée au lieu d'être affichée comme enregistrée.

Conversion et importation de sources

  • Les lots PDF/document/Excel/PowerPoint directs sans -o ne permettent plus aux entrées de même tige (budget.xlsx + budget.xlsm) d'écraser le Markdown de l'autre tout en signalant le succès (8d630fff, #317).
  • import-sources donne aux sources de même tige des tiges d'archives distinctes, donc la seconde est convertie et atteint le projet (ca04346d).
  • Les images de sortie du bloc-notes vont vers <output-stem>_files/, donc les blocs-notes convertis côte à côte n'écrasent plus les images les uns des autres (e4a4c084). ## Chaînes et invites de l'interface utilisateur
  • Correction des chaînes d'interface utilisateur en chinois simplifié, chinois traditionnel et japonais dans les pages de confirmation, de révision des spécifications et d'aperçu en direct : erreurs de signification, chaînes obsolètes, ponctuation et termes cohérents. Deux chaînes source anglaises obsolètes ont également été corrigées et les clés de traduction que rien ne lit ont été supprimées (5d613ea2, ecb6269b, bc3f51df, 5d806d29, df82a224, b6843645).
  • Les déclencheurs de workflow, les modèles et les clés candidates suivent désormais la règle du langage de dépôt (a5170959). Les documents utilisateur ne disent plus que la recommandation de communication est rédigée sans lire le contenu du modèle (667b032b). Les documents chinois sont resynchronisés avec leurs sources anglaises (e0e6576d, 0b898cd8).
  • Merci à @kevindesuyo pour l'ensemble de la chaîne d'interface utilisateur et de la documentation.

ppt-master v6.7.1

Patch release: fixes for work that the live preview, source conversion and source import could lose without a warning, plus a full pass over the UI strings in every language.

Live preview

  • Unapplied annotations and direct edits now survive a server stop (1fa3768a, #319). Before, they lived only in server memory, and the idle timeout, Exit preview, --shutdown, a kill or a crash before Apply changes discarded them. Closing a laptop lid made this likely: the idle timer counted the suspend time, so the server exited on wake.
    • Every staging change is written to live_preview/draft.json before it is acknowledged. The next start restores it and the UI lists the restored slides; you still decide when to apply.
    • A slide whose SVG changed in the meantime is not replayed onto it. Its draft is kept as live_preview/draft_conflict_<timestamp>.json and the UI says so.
    • Exit preview now keeps the draft instead of discarding it. A failed draft write is reported in the UI.
    • Apply changes keeps a slide staged when an annotated element no longer exists, instead of dropping the annotation. SVGs are written atomically, and a submit that finds nothing pending on the server is reported instead of shown as saved.

Source conversion and import

  • Direct PDF/document/Excel/PowerPoint batches without -o no longer let same-stem inputs (budget.xlsx + budget.xlsm) overwrite each other's Markdown while reporting success (8d630fff, #317).
  • import-sources gives same-stem sources distinct archive stems, so the second one is converted and reaches the project (ca04346d).
  • Notebook output images go to <output-stem>_files/, so notebooks converted side by side no longer overwrite each other's images (e4a4c084).

UI strings and prompts

  • Corrected the Simplified Chinese, Traditional Chinese and Japanese UI strings across the confirmation, spec review and live preview pages: meaning errors, stale strings, punctuation and consistent terms. Two stale English source strings were also fixed, and translation keys that nothing reads were dropped (5d613ea2, ecb6269b, bc3f51df, 5d806d29, df82a224, b6843645).
  • Workflow triggers, templates and candidate keys now follow the repo language rule (a5170959). The user docs no longer say the communication recommendation is written without reading any template content (667b032b). The Chinese docs are resynced with their English sources (e0e6576d, 0b898cd8).
  • Thanks to @kevindesuyo for the whole UI-string and docs pass.
