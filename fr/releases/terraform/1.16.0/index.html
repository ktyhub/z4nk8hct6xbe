#terraformer v1.16.0

1.16.0 (26 août 2026)

NOUVELLES FONCTIONNALITÉS :

  • Terraform stocke désormais les données privées planifiées pour les fournisseurs, permettant ainsi de préserver l'état spécifique du fournisseur lors de la planification et de l'application. (#37986)
  • terraform_data : le nouveau bloc store peut contenir des valeurs éphémères et sensibles à travers le plan et l'application. (#38298)
  • Les fournisseurs peuvent désormais utiliser des blocs imbriqués comme valeurs calculées (#38305).
  • import : les blocs import à l'intérieur des modules sont désormais pris en charge. (#38352)
  • Terraform est désormais disponible sous forme de binaire pré-construit pour Linux s390x (zLinux). (#38384)
  • Les déclencheurs d'actions de ressources peuvent désormais utiliser les modes on_failure de halt, taint ou continue. (#38722) AMÉLIORATIONS :
  • state show : La commande state show peut désormais produire une sortie lisible par machine lorsqu'elle est fournie avec l'indicateur -json (#23940)
  • espace de travail : la commande workspace list peut désormais produire une sortie lisible par machine lorsqu'elle est fournie avec l'indicateur -json (#38397)
  • test : Terraform signale désormais quelles ressources ont été laissées lorsque skip_cleanup est défini. (#38449)
  • piles : Les configurations d'actions ont désormais accès à un symbole caller contenant la valeur objet de la ressource appelante. (#38668)
  • Les actions peuvent désormais utiliser les événements before_destroy et after_destroy. (#38668)
  • cloud : Terraform affiche désormais un résumé des résultats de l'évaluation des politiques pour les exécutions plan et apply sur HCP Terraform. (#38715)
  • Politique : Terraform résout désormais les informations d'identification du plugin de stratégie à partir du cloud configuré ou du backend distant pendant init, plan et apply, plutôt que d'exiger que le plugin lise lui-même les informations d'identification. (#38716)
  • graphique : La commande terraform graph peut désormais générer des graphiques au format Mermaid à l'aide du drapeau -format=mermaid. (#38719)
  • Les sorties du module enfant avec des attributs imbriqués obsolètes non référencés ne renvoient plus d'avertissements de dépréciation. (#38778)
  • Les blocs de ressources lifecycle prennent désormais en charge destroy = false pour empêcher la destruction d'une ressource. (#38784)
  • La fonction contains() peut désormais tester les valeurs null. (#38792)
  • console : la commande terraform console accepte désormais un indicateur facultatif -scope=<module address>, qui peut être utilisé pour évaluer des expressions dans la portée d'un module ou d'une instance de module spécifique. (#31861)
  • -invoke peut désormais être combiné avec -target pour spécifier l'instance de ressource appelante lorsque plusieurs ressources déclenchent la même action. (#38845)
  • La commande terraform stacks déduit désormais automatiquement le nom d'hôte cible à partir du fichier d'informations d'identification local (credentials.tfrc.json) lorsque ni TF_STACKS_HOSTNAME ni TF_CLOUD_HOSTNAME ne sont définis (#38896). CORRECTIONS DE BOGUES :
  • Les blocs import respectent désormais correctement les noms locaux des fournisseurs. (#38338)
  • terraform apply ne panique plus lorsque le plan contient une modification sans opération pour une ressource déposée comportant des blocs lifecycle.precondition ou lifecycle.postcondition. (#38586)
  • Espace de travail : Terraform génère désormais une erreur si un nom d'espace de travail non valide est sélectionné en raison de modifications hors bande. (#38594)
  • test : Terraform génère désormais un avertissement lorsqu'un fichier référencé via l'indicateur -filter n'existe pas. (#38603)
  • init : Terraform ne supprime plus les verrous du fichier de verrouillage des dépendances pour les fournisseurs configurés comme dev_override. (#38634)
  • init : Terraform avertit désormais lorsque des fournisseurs non gérés sont utilisés et peut avoir un impact sur l'installation du fournisseur. (#38656)
  • Les actions sont désormais invoquées pour toutes les dépendances de ressources. (#38668)
  • Terraform renvoie désormais l'erreur correcte lorsqu'une cible import existe dans un état mais n'a pas de configuration correspondante. (#38782)
  • La fonction merge() ne panique plus lors du passage d'objets null. (#38792)
  • Autoriser les traits de soulignement dans les espaces de noms d'adresse source du fournisseur, afin que les adresses de fournisseur de registre privé ne soient plus rejetées comme non valides (#38894)
  • test : les valeurs éphémères facultatives n'ont pas besoin d'être définies au moment du plan (#38974) REMARQUES :
  • init : les erreurs dues à des indicateurs -upgrade et -lockfile=readonly incompatibles sont désormais générées plus tôt dans le processus d'initialisation. (#38561) REMARQUES SUR LA MISE À NIVEAU :
  • bastion_host_key est désormais correctement appliqué par les provisionneurs. Vérifiez les configurations de votre fournisseur pour vérifier que la clé configurée est correcte avant la mise à niveau. (#38318)

terraform v1.16.0

1.16.0 (August 26, 2026)

NEW FEATURES:

  • Terraform now stores planned private data for providers, allowing provider-specific state to be preserved across plan and apply. (#37986)

  • terraform_data: The new store block can hold ephemeral and sensitive values across plan and apply. (#38298)

  • Providers can now use nested blocks as computed values (#38305)

  • import: import blocks inside modules are now supported. (#38352)

  • Terraform is now available as a pre-built binary for Linux s390x (zLinux). (#38384)

  • Resource action triggers can now use on_failure modes of halt, taint, or continue. (#38722)

ENHANCEMENTS:

  • state show: The state show command can now produce machine-readable output when supplied with the -json flag (#23940)

  • workspace: The workspace list command can now produce machine-readable output when supplied with the -json flag (#38397)

  • test: Terraform now reports which resources were left behind when skip_cleanup is set. (#38449)

  • stacks: Action configurations now have access to a caller symbol containing the object value of the calling resource. (#38668)

  • Actions can now use before_destroy and after_destroy events. (#38668)

  • cloud: Terraform now displays a summary of policy evaluation outcomes for plan and apply runs against HCP Terraform. (#38715)

  • policy: Terraform now resolves policy plugin credentials from the configured cloud or remote backend during init, plan, and apply, rather than requiring the plugin to read credentials itself. (#38716)

  • graph: The terraform graph command can now output graphs in Mermaid format using the -format=mermaid flag. (#38719)

  • Child module outputs with unreferenced deprecated nested attributes no longer return deprecation warnings. (#38778)

  • Resource lifecycle blocks now support destroy = false to prevent a resource from being destroyed. (#38784)

  • The contains() function can now test for null values. (#38792)

  • console: The terraform console command now accepts an optional -scope=<module address> flag, which can be used to evaluate expressions within the scope of a module or a specific module instance. (#31861)

  • -invoke can now be combined with -target to specify the calling resource instance when multiple resources trigger the same action. (#38845)

  • The terraform stacks command now automatically infers the target hostname from the local credentials file (credentials.tfrc.json) when neither TF_STACKS_HOSTNAME nor TF_CLOUD_HOSTNAME is set (#38896)

BUG FIXES:

  • import blocks now correctly respect provider local names. (#38338)

  • terraform apply no longer panics when the plan contains a no-op change for a deposed resource that has lifecycle.precondition or lifecycle.postcondition blocks. (#38586)

  • workspace: Terraform now raises an error if an invalid workspace name becomes selected due to out-of-band changes. (#38594)

  • test: Terraform now raises a warning when a file referenced via the -filter flag does not exist. (#38603)

  • init: Terraform no longer removes locks from the dependency lock file for providers configured as dev_override. (#38634)

  • init: Terraform now warns when unmanaged providers are in use and may impact provider installation. (#38656)

  • Actions are now invoked with respect to all resource dependencies. (#38668)

  • Terraform now returns the correct error when an import target exists in state but has no corresponding configuration. (#38782)

  • The merge() function no longer panics when passed null objects. (#38792)

  • Allow underscores in provider source address namespaces, so private registry provider addresses are no longer rejected as invalid (#38894)

  • test: Optional ephemeral values do not have to be set at plan time (#38974)

NOTES:

  • init: Errors due to incompatible -upgrade and -lockfile=readonly flags are now raised earlier in the init process. (#38561)

UPGRADE NOTES:

  • bastion_host_key is now correctly applied by provisioners. Review your provisioner configurations to verify the configured key is correct before upgrading. (#38318)
