#sglang v0.5.14

Faits saillants

Nouveau modèle pris en charge : GLM-5.2, LiquidAI LFM2.5, Kimi-K2.7-Code, Poolside Laguna-M.1, DiffusionGemma, Zyphra ZAYA1, MiMo-V2-ASR DeepSeek-V4 sur GB300 depuis le jour 0 : débit 5 fois plus élevé avec la même interactivité, servant DeepSeek-V4 sur NVIDIA GB300 avec SGLang (blog). Équilibrage de charge Waterfill et LPLB MoE : deux méthodes d'équilibrage de charge au moment de la répartition pour le parallélisme expert DeepEP : Waterfill pour la répartition experte partagée et LPLB pour les réplicas experts redondants, améliorant le débit pour DeepSeek-V3/R1 et DeepSeek-V4 (blog). Noyau de pré-remplissage KDA CuteDSL sur Blackwell (SM100) : Nouveau noyau de pré-remplissage CuteDSL pour Kimi-Linear (KDA), 1.08-1.52x plus rapide que le chemin Triton via un espace de travail de travail réutilisable, plus un correctif de remplissage cuda-graph (#27488) ; voir le [Livre de recettes Kimi-Linear] (https://docs.sglang.io/cookbook/autoregressive/Moonshotai/Kimi-Linear). Économies de mémoire dans le cache de préfixes à attention linéaire : un pool de points de contrôle int8 stocke les états récurrents de manière compacte dans le cache de base Mamba, augmentant considérablement la capacité du cache de préfixes pour les modèles KDA/GDN (#28185) ; le cache intermédiaire spéculatif de fenêtre de conversion est dédupliqué avec une disposition de fenêtre coulissante, réduisant de moitié son empreinte sans changement numérique (#28302). LPLB : équilibreur de charge à programmation linéaire pour le parallélisme expert du MoE : équilibre le routage des jetons entre les répliques expertes redondantes en résolvant un LP par couche ; opt-in via --ep-dispatch-algorithm=lp, comportement par défaut inchangé (#24515). Intégration MSCCL++ et fusion MNNVL allreduce : MSCCL++ migre vers le package mscclpp Python en amont (Executor + compilateur DSL) avec des collectifs réglés automatiquement pour TP=8 à nœud unique et TP=16 à deux nœuds (#22734) ; FlashInfer a fusionné allreduce + résiduel + RMSNorm réactive un backend MNNVL derrière --flashinfer-allreduce-fusion-backend (auto / trtllm / mnnvl), corrigeant l'interaction par morceaux-CUDA-graph (#23402). Attention Nemotron DP + MTP : attention parallèle aux données pour l'hybride Nemotron-H (Mamba2 + attention complète + MoE), plus prise en charge MTP (#24955) ; voir le [Livre de recettes Nemotron 3 Ultra] (https://docs.sglang.io/cookbook/autoregressive/NVIDIA/Nemotron3-Ultra). AMD : graphique CUDA cassable sur ROCm/HIP : Le chemin d'exécution du graphique CUDA cassable s'exécute désormais sur les GPU AMD (#28173). NVFP4 MoE pour DeepSeek-V4 : ajoute un chemin de quantification NVFP4 MoE pour DeepSeek-V4 sur Blackwell pour un débit MoE plus élevé ; activer avec --moe-runner-backend flashinfer_trtllm_routed (#25820); voir le [Livre de recettes DeepSeek-V4] (https://docs.sglang.io/cookbook/autoregressive/DeepSeek/DeepSeek-V4). Optimisations du décodage et de la quantification DeepSeek-V4 : la quantification de groupe FP8 émet désormais des échelles de puissance de deux (UE8M0) directement à partir du noyau quantique de groupe par jeton, supprimant une passe d'arrondi distincte (#26766) ; Les q-heads de décodage MLA sont complétés à 64 sous attention-TP, donc FlashMLA distribue le noyau head64 ~ 2x moins cher au lieu de head128 (#27954) ; le noyau prénorme MHC est préchauffé au démarrage pour supprimer le ralentissement JIT de première exécution sur un nouveau serveur (#27986) ; et les états de compression de type mixte BF16 sont pris en charge sur les chemins C4/C128 (#27277) ; voir le [Livre de recettes DeepSeek-V4] (https://docs.sglang.io/cookbook/autoregressive/DeepSeek/DeepSeek-V4). release note complets par catégorie ci-dessous.

sglang v0.5.14

Highlights

New Model Support: GLM-5.2, LiquidAI LFM2.5, Kimi-K2.7-Code, Poolside Laguna-M.1, DiffusionGemma, Zyphra ZAYA1, MiMo-V2-ASR

DeepSeek-V4 on GB300 since Day 0: 5x higher throughput at the same interactivity, serving DeepSeek-V4 on NVIDIA GB300 with SGLang (blog).

Waterfill & LPLB MoE load balancing: Two dispatch-time load-balancing methods for DeepEP expert parallelism: Waterfill for shared-expert dispatch and LPLB for redundant expert replicas, improving throughput for DeepSeek-V3/R1 and DeepSeek-V4 (blog).

KDA CuteDSL prefill kernel on Blackwell (SM100): New CuteDSL prefill kernel for Kimi-Linear (KDA), 1.08-1.52x faster than the Triton path via a reusable scratch workspace, plus a cuda-graph padding fix (#27488); see the Kimi-Linear cookbook.

Linear-attention prefix-cache memory savings: An int8 checkpoint pool stores recurrent states compactly in the Mamba radix cache, substantially increasing prefix-cache capacity for KDA / GDN models (#28185); the speculative conv-window intermediate cache is deduplicated with a sliding-window layout, halving its footprint with no numerical change (#28302).

LPLB: linear-programming load balancer for MoE expert parallelism: Balances token routing across redundant expert replicas by solving a per-layer LP; opt-in via --ep-dispatch-algorithm=lp, default behavior unchanged (#24515).

MSCCL++ integration & MNNVL allreduce fusion: MSCCL++ migrates to the upstream mscclpp Python package (Executor + DSL compiler) with auto-tuned collectives for TP=8 single-node and TP=16 two-node (#22734); FlashInfer fused allreduce + residual + RMSNorm re-enables an MNNVL backend behind --flashinfer-allreduce-fusion-backend (auto / trtllm / mnnvl), fixing the piecewise-CUDA-graph interaction (#23402).

Nemotron DP attention + MTP: Data-parallel attention for the hybrid Nemotron-H (Mamba2 + full attention + MoE), plus MTP support (#24955); see the Nemotron 3 Ultra cookbook.

AMD: breakable CUDA graph on ROCm/HIP: The breakable CUDA graph execution path now runs on AMD GPUs (#28173).

NVFP4 MoE for DeepSeek-V4: Adds an NVFP4 MoE quantization path for DeepSeek-V4 on Blackwell for higher MoE throughput; enable with --moe-runner-backend flashinfer_trtllm_routed (#25820); see the DeepSeek-V4 cookbook.

DeepSeek-V4 decode & quantization optimizations: FP8 group quantization now emits power-of-two (UE8M0) scales directly from the per-token group-quant kernel, dropping a separate rounding pass (#26766); MLA decode q-heads are padded to 64 under attention-TP so FlashMLA dispatches the ~2x cheaper head64 kernel instead of head128 (#27954); the MHC prenorm kernel is prewarmed at startup to remove the first-run JIT slowdown on a fresh server (#27986); and BF16 mixed-dtype compression states are supported on the C4 / C128 paths (#27277); see the DeepSeek-V4 cookbook.
