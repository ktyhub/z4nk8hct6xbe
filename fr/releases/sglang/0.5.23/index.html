Quoi de neuf

  • DeepSeek-V4.1 sur GB300 obtient un débit de préremplissage jusqu'à 1,5 fois plus élevé sous charge et une latence du premier jeton environ 28 % inférieure sur les invites de 32 Ko à 64 Ko (#44403, #45059, #45107).
  • Mode SGLang à faible latence : les plugins NVIDIA megakernel et AMD monokernel exécutent le décodage DeepSeek-V4.1-Flash en tant que noyaux persistants fusionnés, pour un décodage mono-utilisateur jusqu'à 44 % plus rapide sur GB300 et 75 % sur MI350X (#44945, #45450, #44353, #44621).
  • Les modèles MoE tels que DeepSeek-V4.1-Flash, GLM-5.3-Flash et gpt-oss atteignent le premier jeton 30 % à 58 % plus tôt sur les invites 8K sur H200 (#43363).
  • Paged Experts (opt-in) exécute des modèles MoE plus grands que la mémoire GPU sur un seul GPU grand public, jusqu'à 30 fois plus rapide que le déchargement du CPU (#42557, #45787).
  • SGLang fonctionne désormais sur Google TPU7x via SGLang-TorchTPU, un plugin natif PyTorch pour TPU.
  • Vous pouvez désormais servir des adaptateurs LoRA sur des modèles MoE quantifiés (FP8 et NVFP4) avec un nouveau moteur LoRA opt-in (#45892).
  • Les modèles MLA de style DeepSeek exécutant le parallélisme de contexte de décodage peuvent désormais conserver leur cache de préfixes dans le stockage L3 basé sur des fichiers HiCache (#41187).

Dernières modifications et notes de mise à niveau

  • Le chat DeepSeek-V4 et V4.1 suit désormais la recette deepseek. Les invites, les sorties et les points de terminaison natifs /separate_reasoning et /parse_function_call passent par l'encodeur officiel de DeepSeek, et les propres encoding_dsv4.py / encoding_dsv41.py de SGLang ont disparu. Les utilisateurs de Clients peuvent le remarquer : les arguments d'appel d'outil diffusés arrivent en morceaux (le premier morceau contient arguments: ""), alors concaténez-les comme le fait OpenAI SDK ; les identifiants d'appel d'outil utilisent le format officiel call_00_... ; L'effort de raisonnement de la V4 suit le profil officiel de DeepSeek et le remplacement de dsv4_reasoning_effort_profile est supprimé ; un reasoning_effort numérique sur V4 renvoie 400 ; Les messages developer s'affichent sous forme de messages système ; /parse_function_call renvoie également les appels aux outils extérieurs à tools avec tool_index -1 ; les requêtes qui combinent tools avec continue_final_message renvoient 400. L'analyse de sortie passe par deepseek-recipe lorsque le raisonnement DeepSeek ou l'analyseur d'appel d'outil est défini ; sgl-router et sglang-server conservent pour l'instant leurs analyseurs Rust : #45315, #45907, #46219
  • La relecture limitée SWA du décodeur DeepSeek-V4.1 est activée par défaut pour les configurations CUDA prises en charge, y compris les deux rôles PD. Ce n’est pas numériquement identique au pré-remplissage complet. Transmettez --no-enable-decoder-swa-bounded-replay pour conserver le pré-remplissage complet, par exemple pour les déploiements RL dont les logprobs doivent correspondre au formateur : #44403, #45035
  • DeepSeek-V4.1 est par défaut MegaAttention sous PD. Sur SM100 / SM103, les deux rôles PD résolvent désormais flashmla_mega et la poignée de main PD vérifie la disposition KV, donc le pré-remplissage et le décodage doivent exécuter le même backend d'attention (#45075). Mettez à niveau le pré-remplissage et le décodage ensemble, car un ancien décodage ne peut pas lire le nouveau champ de prise de contact ; passez --dsv4-attn-backend flashmla sur les deux rôles pour conserver FlashMLA. Les serveurs agrégés conservent FlashMLA lorsque l'attention est parallèle à tous les rangs : #46263
  • Le backend d'attention tokenspeed_mla est supprimé. tokenspeed_mla démarre toujours comme un alias obsolète pour cutedsl_mla avec un avertissement. Pour changer, transmettez --attention-backend cutedsl_mla --kv-cache-dtype fp8_e4m3, plus --speculative-attention-mode decode avec décodage spéculatif : #44803
  • --speculative-skip-dp-mlp-sync est supprimé. Les commandes de lancement qui le transmettent échouent désormais avec une erreur d'argument non reconnu ; déposez le drapeau : #45043
  • Le nom de quantification de diffusion kitchen_int8 est supprimé. Utilisez convrot_int8, obsolète en sa faveur depuis v0.5.22 : #45706
  • SGLANG_ENABLE_UNIFIED_RADIX_TREE est désormais ignoré sans avertissement. Cela n'a déjà eu aucun effet car l'arbre de base unifié est la valeur par défaut ; supprimez-le des scripts de lancement : #45090
  • Les anciens points de contrôle .pt au format tar ne se chargent plus. La solution de repli non sécurisée weights_only=False pickle est supprimée ; convertir ces points de contrôle en safetensors ou au format zip .pt hors ligne : #42760
  • Les points de terminaison HTTP de diffusion valident plus strictement. Les valeurs d'URL pour upscaling_model_path et frame_interpolation_model_path renvoient 400, un response_format non pris en charge est rejeté avant la génération et un échec de téléchargement dans le cloud renvoie 502 au lieu de 400 : #43585
  • Le premier démarrage d'un serveur FlashInfer CUTLASS MoE prend plus de temps. Le réglage automatique au démarrage couvre désormais également les tailles de pré-remplissage, de sorte qu'un serveur sans résultats de réglage enregistrés prend plus de temps pour être prêt (sur DeepSeek-V4.1-Flash sur 8x H200, le réglage automatique passe d'environ 41 s à 177 s). Les startups ultérieures réutilisent les résultats enregistrés et --disable-flashinfer-autotune ignore le réglage : #43363
  • Les réponses PNG de diffusion sont plus grandes. La sortie PNG est désormais par défaut au niveau zlib 0 : les mêmes pixels, environ 3 fois les octets, plusieurs fois plus rapide à encoder. Définissez output_compression sur une valeur autre que 75 pour choisir un niveau : #45987
  • sgl-router déplacé vers le répertoire de niveau supérieur sgl-router/. Les builds et les scripts qui pointent vers experimental/sgl-router/ doivent mettre à jour le chemin (#45414) ; --max-in-flight est désormais --max-inflight-requests, et l'ancien nom fonctionne toujours comme alias : #44950

What's new

  • DeepSeek-V4.1 on GB300 gets up to 1.5x more prefill throughput under load and about 28% lower first-token latency on 32K to 64K prompts (#44403, #45059, #45107).
  • SGLang low-latency mode: the opt-in NVIDIA megakernel and AMD monokernel plugins run DeepSeek-V4.1-Flash decode as fused persistent kernels, for up to 44% faster single-user decode on GB300 and 75% on MI350X (#44945, #45450, #44353, #44621).
  • MoE models such as DeepSeek-V4.1-Flash, GLM-5.3-Flash and gpt-oss reach the first token 30% to 58% sooner on 8K prompts on H200 (#43363).
  • Paged Experts (opt-in) runs MoE models larger than GPU memory on a single consumer GPU, up to 30x faster than CPU offload (#42557, #45787).
  • SGLang now runs on Google TPU7x through SGLang-TorchTPU, a PyTorch-native plugin for TPU.
  • You can now serve LoRA adapters on quantized MoE models (FP8 and NVFP4) with a new opt-in LoRA engine (#45892).
  • DeepSeek-style MLA models running decode context parallelism can now keep their prefix cache in HiCache file-based L3 storage (#41187).

Breaking Changes & Upgrade Notes

  • DeepSeek-V4 and V4.1 chat now follows deepseek-recipe. Prompts, outputs and the native /separate_reasoning and /parse_function_call endpoints go through DeepSeek's official encoder, and SGLang's own encoding_dsv4.py / encoding_dsv41.py are gone. Clients may notice: streamed tool-call arguments arrive in pieces (the first chunk carries arguments: ""), so concatenate them as the OpenAI SDK does; tool-call ids use the official call_00_... format; V4 reasoning effort follows DeepSeek's official profile and the dsv4_reasoning_effort_profile override is removed; a numeric reasoning_effort on V4 returns 400; developer messages render as system messages; /parse_function_call also returns calls to tools outside tools with tool_index -1; requests that combine tools with continue_final_message return 400. Output parsing goes through deepseek-recipe when the DeepSeek reasoning or tool-call parser is set; sgl-router and sglang-server keep their Rust parsers for now: #45315, #45907, #46219
  • DeepSeek-V4.1 decoder SWA bounded replay is on by default for supported CUDA configurations, including both PD roles. It is not numerically identical to full prefill. Pass --no-enable-decoder-swa-bounded-replay to keep full prefill, for example for RL rollouts whose logprobs must match the trainer: #44403, #45035
  • DeepSeek-V4.1 defaults to MegaAttention under PD. On SM100 / SM103 both PD roles now resolve flashmla_mega and the PD handshake checks the KV layout, so prefill and decode must run the same attention backend (#45075). Upgrade prefill and decode together, since an older decode cannot read the new handshake field; pass --dsv4-attn-backend flashmla on both roles to keep FlashMLA. Aggregated servers keep FlashMLA when attention is tensor-parallel across ranks: #46263
  • The tokenspeed_mla attention backend is removed. tokenspeed_mla still starts as a deprecated alias for cutedsl_mla with a warning. To switch, pass --attention-backend cutedsl_mla --kv-cache-dtype fp8_e4m3, plus --speculative-attention-mode decode with speculative decoding: #44803
  • --speculative-skip-dp-mlp-sync is removed. Launch commands that pass it now fail with an unrecognized-argument error; drop the flag: #45043
  • The kitchen_int8 diffusion quantization name is removed. Use convrot_int8, deprecated in favor of it since v0.5.22: #45706
  • SGLANG_ENABLE_UNIFIED_RADIX_TREE is now ignored without a warning. It already had no effect because the unified radix tree is the default; drop it from launch scripts: #45090
  • Legacy tar-format .pt checkpoints no longer load. The unsafe weights_only=False pickle fallback is removed; convert such checkpoints to safetensors or zip-format .pt offline: #42760
  • Diffusion HTTP endpoints validate more strictly. URL values for upscaling_model_path and frame_interpolation_model_path return 400, an unsupported response_format is rejected before generation, and a failed cloud upload returns 502 instead of 400: #43585
  • The first startup of a FlashInfer CUTLASS MoE server takes longer. Startup autotune now also covers prefill sizes, so a server with no saved tuning results takes longer to become ready (on DeepSeek-V4.1-Flash on 8x H200, autotune goes from about 41 s to 177 s). Later startups reuse the saved results, and --disable-flashinfer-autotune skips tuning: #43363
  • Diffusion PNG responses are larger. PNG output now defaults to zlib level 0: the same pixels, about 3x the bytes, several times faster to encode. Set output_compression to a value other than 75 to pick a level: #45987
  • sgl-router moved to the top-level sgl-router/ directory. Builds and scripts that point at experimental/sgl-router/ must update the path (#45414); --max-in-flight is now --max-inflight-requests, and the old name still works as an alias: #44950
