AutoGPT autogpt-platform-beta-v0.6.35

Highlights

  • Agent execution lands in the new builder — #11186 wires real run capability into the rewritten builder, and #11277 adds cascading stop so terminating a parent graph also halts nested executions. If you've only been prototyping in the new builder, this is the release where it becomes viable for live workflows; note that nested runs now die together instead of lingering after a parent stop.

  • Block I/O contract is standardized — #11257 introduces BlockSchemaInput / BlockSchemaOutput base classes to unify error handling across blocks. Custom-block authors should plan a migration onto these bases to get consistent error propagation, and #11256 complements it by finally adding the missing error output pins to every Firecrawl block — worth rechecking any Firecrawl error-handling branches you wired around the old gap.

  • Claude 3.5 Sonnet and Haiku removed (breaking) — #11260 drops both models from the catalog. Any block or credential config pinned to claude-3.5-sonnet or haiku will fail model resolution after upgrade, so audit existing graphs and repoint them to a supported model. This is the release's one genuine breaking change.

  • SQL sanitization is tightened — #11228 and #11279 broaden sanitization of SQL terms and raw queries. A net security win, but pipelines that previously passed loosely-formed raw SQL through database blocks should expect stricter rejection and possible new validation errors — test your raw-query paths before rolling out.

  • Execution lifecycle and cluster reliability — a coordinated set of fixes: #11240 adds graceful shutdown in AppService to eliminate restart-time RPC errors, #11281 guarantees cluster-lock release on every execution-submission failure path, #11243 blocks runs of deleted agents and cleans up orphaned resources, and #11283 makes graph permission checks version-agnostic. Expect fewer stuck locks, zombie runs, and noisy restarts in production.

  • Payload and LLM-response handling tweaks — #11261 raises aiohttp's max_field_size, so oversized request fields that previously bounced now pass; #11262 and #11275 harden LLM summary handling by extracting responses from the response dict and asserting they're strings. Minor on their own, but relevant if you'd hit size ceilings or seen summary steps crash on non-string returns.
