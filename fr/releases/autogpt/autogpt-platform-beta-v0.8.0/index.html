⚠️ Mise à niveau d'une installation auto-hébergée – rupture du changement

ENCRYPTION_KEY, UNSUBSCRIBE_SECRET_KEY et BETTER_AUTH_SECRET ne sont plus livrés avec des valeurs en .env.default ; ils sont générés par installation, et le backend ne démarre pas sur la valeur que .env.default contenait. Une nouvelle installation n'a besoin de rien d'autre que make init-env (ou le programme d'installation). Une installation qui définit ses propres valeurs n’a besoin de rien. Si votre installation s'est exécutée avec les valeurs par défaut (pas de ligne ENCRYPTION_KEY dans backend/.env ou si le démarrage s'arrête avec ENCRYPTION_KEY is set to a value that was published…), faites ceci à partir de autogpt_platform/ — cela déplace vos intégrations connectées vers la nouvelle clé au lieu de les perdre :

1.docker compose down 2. Conservez la clé avec laquelle vos données sont cryptées : export OLD_ENCRYPTION_KEY=$(git show autogpt-platform-beta-v0.7.4:autogpt_platform/backend/.env.default | grep '^ENCRYPTION_KEY=' | cut -d= -f2-) (si vous avez défini votre propre clé et que vous la remplacez, exportez plutôt cette valeur et conservez une copie de backend/.env en dehors de la caisse). 3. Dans backend/.env, assurez-vous que ENCRYPTION_KEY= et UNSUBSCRIBE_SECRET_KEY= existent sans rien après =, et BETTER_AUTH_SECRET= dans frontend/.env ; puis make init-env (remplit chaque secret vide, n'écrase jamais une valeur). 4. Chiffrez à nouveau ce qui est stocké : effectuez d'abord un essai à sec, puis appliquez : docker compose build migrate rest_server && docker compose run --rm migrate docker compose run --rm --no-deps -e OLD_ENCRYPTION_KEY rest_server cli rotate-encryption-key docker compose run --rm --no-deps -e OLD_ENCRYPTION_KEY rest_server cli rotate-encryption-key --apply 5. Effacez la clé de signature de jeton stockée sous l'ancien BETTER_AUTH_SECRET, puis démarrez : docker compose up -d --wait db docker compose exec db psql -U postgres -c 'DELETE FROM platform."UserAuthJwks";' docker compose up -d --build

Instructions complètes : [Mise à niveau : les secrets sont générés par installation] (https://github.com/Significant-Gravitas/AutoGPT/blob/master/docs/platform/getting-started.md#upgrading-secrets-are-generated-per-install).

Également dans cette version : l'ancien chemin de vérification HS256 JWT est supprimé, donc un JWT_VERIFY_KEY dans backend/.env n'est plus lu (#14519) ; la table TrialNotificationDelivery inutilisée est supprimée par migration.

Highlights

  • Per-install secrets (breaking) — ENCRYPTION_KEY, UNSUBSCRIBE_SECRET_KEY, and BETTER_AUTH_SECRET no longer ship values in .env.default; the backend now refuses to boot on the old published key. Fresh installs need only make init-env, but installs that ran on defaults must recover the v0.7.4 key with git show, re-encrypt stored data via cli rotate-encryption-key --apply (dry-run first), and delete platform."UserAuthJwks" before restart — skipping this loses connected integrations. Self-hosters should treat this as a planned migration, not a drop-in bump.
  • Auth surface narrows — the legacy HS256 JWT verification path is removed and JWT_VERIFY_KEY is no longer read (#14519), and the unused TrialNotificationDelivery table is dropped by migration. Anyone relying on custom JWT verification or querying that table must adjust before upgrading.
  • Capability-first agent control — a new capability registry/index (#14568) and a switch of copilot discovery to find/describe/run_capability (#14569), plus a fix routing capability-id tools through the normal tool path so AutoPilot can create and edit agents again (#14714). MCP servers gain Basic auth (#14075) and can speak the 2026-07-28 spec alongside legacy ones (#14302) — worth regression-testing custom MCP integrations.
  • Skills become distributable packages — skills can be stored/copied/deleted and uploaded or downloaded as a whole zip (#14549, #14555), made reachable and runnable inside a turn (#14544), installed straight onto an expert or published to the marketplace with admin review (#14559, #14557). This shifts skills from local config to a shareable, versioned artifact.
  • New model providers — adds GPT-6 Astra (also promoted to the Codex advanced default, #14571), Opus 5, Claude Fable 5.1, Gemini 3.8 Flash, Qwen 3.8 Max and DeepSeek V4.1 Flash, with picker/cost-disclosure updates (#14360, #14037). Expect model-selection and billing-screen changes when adopting these.
  • Runtime hardening and behavior changes — LLM request timeout raised to 600s and made configurable (#14206), redis-py bumped to 8.1 so a dropped cluster connection no longer poisons the client (#14334), per-expert workspace isolation (#14426), and security fixes that stop replaying Authorization across cross-origin redirects (#14419) and stop deleting valid MCP credentials on a 403 (#14303).

⚠️ Upgrading a self-hosted install — breaking change

ENCRYPTION_KEY, UNSUBSCRIBE_SECRET_KEY and BETTER_AUTH_SECRET no longer ship with values in .env.default; they are generated per install, and the backend does not start on the value .env.default used to contain. A fresh install needs nothing beyond make init-env (or the installer). An install that set its own values needs nothing. If your install ran on the defaults (no ENCRYPTION_KEY line in backend/.env, or startup stops with ENCRYPTION_KEY is set to a value that was published…), do this from autogpt_platform/ — it moves your connected integrations to the new key instead of losing them:

  1. docker compose down
  2. Keep the key your data is encrypted with: export OLD_ENCRYPTION_KEY=$(git show autogpt-platform-beta-v0.7.4:autogpt_platform/backend/.env.default | grep '^ENCRYPTION_KEY=' | cut -d= -f2-) (if you had set your own key and are replacing it, export that value instead and keep a copy of backend/.env outside the checkout).
  3. In backend/.env make sure ENCRYPTION_KEY= and UNSUBSCRIBE_SECRET_KEY= exist with nothing after the =, and BETTER_AUTH_SECRET= in frontend/.env; then make init-env (fills every empty secret, never overwrites a value).
  4. Re-encrypt what is stored — dry run first, then apply: docker compose build migrate rest_server && docker compose run --rm migrate docker compose run --rm --no-deps -e OLD_ENCRYPTION_KEY rest_server cli rotate-encryption-key docker compose run --rm --no-deps -e OLD_ENCRYPTION_KEY rest_server cli rotate-encryption-key --apply
  5. Clear the token signing key stored under the old BETTER_AUTH_SECRET, then start: docker compose up -d --wait db docker compose exec db psql -U postgres -c 'DELETE FROM platform."UserAuthJwks";' docker compose up -d --build

Full instructions: Upgrading: secrets are generated per install.

Also in this release: the legacy HS256 JWT verification path is removed, so a JWT_VERIFY_KEY in backend/.env is no longer read (#14519); the unused TrialNotificationDelivery table is dropped by migration.
