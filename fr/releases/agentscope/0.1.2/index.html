agentscope v0.1.2

Highlights

  • Anthropic chat API support — Adds a native Anthropic client in both streaming and non-streaming modes (#505). Developers who previously wrote custom Claude adapters can drop that glue code and use the built-in wrapper; streaming in particular means agent loops now receive token-by-token chunks, so verify your downstream handlers tolerate incremental deltas rather than a single final message.
  • Explicit model wrapper registration — Model wrappers must now be registered explicitly rather than discovered implicitly (#504). This is the main migration item in the release: if you ship custom wrappers, add the registration call after upgrading or your models will fail to resolve.
  • RAG upgrades — Lands a multi-source RAG application (#536), a broader RAG module functionality pass (#519), and a hash field on RetrievedChunk (#528). The hash gives chunks a stable identity for deduplication and cross-source caching, but it changes the object shape—any code that constructs, serializes, or assumes a fixed RetrievedChunk schema should be rechecked.
  • Distributed-call behavior change — The reply call in distributed code now uses argument unpacking (#500), paired with a hotfix to the distributed debate example (#507). Multi-agent/distributed deployments should re-test call sites, since the new calling convention can surface as signature mismatches if you relied on the previous behavior.
  • Cross-platform and dependency hardening — Fixes a Windows local-vs-remote file detection bug (#499), workstation UTF-8 handling (#517), a list-to-dict conversion error when filtering empty values (#482), a Gradio version hotfix (#483), and a service-toolkit/logging hotfix (#487). Windows users and pipelines that filter empty config values benefit most; the Gradio pin specifically protects deployments from upstream version drift.

No breaking changes.
