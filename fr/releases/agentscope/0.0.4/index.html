agentscope v0.0.4

Highlights

  • Expanded service primitives — Agents gain arXiv search (#148), URL downloads (#140), and shell execution, reducing the custom glue code needed for research and data-ingestion workflows. Shell and download capabilities introduce new security concerns, so expose them with appropriate permissions and sandboxing.
  • Broader model coverage and configuration — DashScope adds multimodal support (#92), Llama3 gets an example-level integration (#167), and Gemini settings can be supplied through gemini.configure (#152). Corrected DashScope token accounting (#146) also improves usage tracking and downstream cost estimates.
  • Visual DAG workflows — Workstation and Copilot are now online, while Studio adds drag-and-drop DAG execution (#114), a refactored compiler/runner (#164), and activity indicators (#179). The workflow compiler now returns code strings (#178), so custom tooling consuming its output should be updated and tested against the new return value.
  • More extensible agent architecture — Agent servers can now run any agent type (#135), and ReActAgent has been decomposed into reusable modules (#153). This broadens deployment and extension options, although integrations coupled to ReActAgent internals may need adjustment.
  • Clearer failures and safer concurrency — Fixes address concurrent file-creation collisions (#147), unhandled None values (#163), and dialog agents without initialized memory (#157). OpenAI safety rejections now raise errors (#171), so applications should explicitly handle these failures in their retry and error flows.
  • Breaking changes — None explicitly announced.
