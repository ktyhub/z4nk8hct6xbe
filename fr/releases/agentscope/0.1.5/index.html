agentscope v0.1.5

Highlights

  • Structured output lands in ReActAgentV2 — PR #593 adds structured-output support to the ReAct v2 agent, so you can get typed, parseable results out of the reasoning loop instead of scraping free-form text. This is the headline capability for anyone wiring agent output into downstream services or validating responses against a schema; if you've been post-processing ReAct output by hand, this is the migration path to adopt.
  • Python and shell execution tools refactored — PR #589 reworks the built-in code/shell execution tools. Because these are among the most commonly customized components, treat this as a behavioral change worth testing: re-check your tool invocation signatures, argument passing, and any subclasses or wrappers around the old executors before upgrading.
  • AgentScope Studio overhauled — PR #586 is a full refactor of the Studio tooling (the visual/tracing surface). Expect interaction and workflow changes rather than just bug fixes; if your team relies on Studio for debugging or demos, plan a short re-orientation and validate that your existing tracing flows still surface the data you depend on.
  • DashScopeFormatter and ReActAgentV2 correctness fix — PR #591 fixes errors in the DashScope formatter together with ReActAgentV2. This matters specifically if you run Qwen/DashScope models through the v2 agent — the fix likely changes what prompts/results look like on that path, so regression-test your DashScope-backed agents after upgrading.
  • Supporting fixes and cleanup — PR #596 corrects a RAG application document path (relevant if your RAG setup copied paths from the shipped example), while PR #597 removes an outdated example. Combined with the version bumps (#592, #616) and README updates (#558, #602, #603), this is a maintenance-heavy release; pin your version deliberately rather than assuming a silent upgrade is harmless.

No breaking changes are explicitly called out in this release notes.

What's Changed

  3. Support structured output in ReActAgentV2
