agentscope v2.0.12

Highlights

  • Thinking controls are now opt-in across adapters — DeepSeek and DashScope support tri-state thinking_enable, while Gemini, Ollama, and Moonshot omit thinking parameters unless explicitly configured (#3398, #3192, #3523, #3510, #3521, #3557). Unset now inherits provider defaults instead of forcing “disabled”; set it explicitly to false where reasoning must remain off. Ollama’s structured-output fallback also supports disabling thinking (#3588).

  • New voice and speech capabilities — Voice profile management with cloud TTS cloning (#2162), browser speech input using DashScope ASR models (#3298), Volcengine audio input (#3706), and provider-specific media parameters in DataBlock (#2103) enable richer voice-driven applications. Check provider-specific credentials and quotas when adopting these paths.

  • More control over running agents — Steering is available through both the SDK and WebUI (#3638), alongside editable server-side chat queues (#2236), REST endpoints for background tasks (#1865), and a configurable tool-offload timeout in create_app (#3606). Developers can intervene in active sessions and monitor or tune long-running work without restarting the application.

  • Shell auto-approval is stricter — Bash permission rules now inspect every subcommand in a compound command (#3513), and ACCEPT_EDITS only auto-allows commands whose subcommands are all filesystem operations (#3519). Previously approved compound commands may now prompt or be rejected; update permission rules to cover each subcommand explicitly.

  • Scheduled automation now respects the selected dates and times — Fixes cover full-day filtering, chosen start/end times, standard cron day alternatives, and serialized reconciliation that prevents stale reads from restoring deleted jobs (#3504, #3547, #3610, #3602, #3608). Review existing schedules and cron expressions if their previous timing differed from the configured intent.

  • API and compatibility changes to review — The server-path skill import endpoint has been removed (#3536); callers must use the supported skill installation/import flow. OpenAI chat-message names now follow the API’s required pattern (#3548), so audit custom names before upgrading. The Claude Sonnet 4.5 model card is also deprecated (#3429), signaling that deployments should migrate to a supported model.
