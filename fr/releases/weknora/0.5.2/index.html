WeKnora v0.5.2

Highlights

  • Adaptive chunking changes retrieval inputs — The new three-tier strategy adds editor controls and live debugging, fixes overlap and parent/child handling, coalesces tiny heading chunks, and recognizes Chinese and multi-level numeric headings. TierRecursive is removed, so existing custom profiles and vector indexes should be revalidated—and re-indexed where the new segmentation is desired (#1124, #1140–#1143, #1148).
  • Storage and retrieval gain new backends — KS3 joins TOS/S3/OSS, tenant storage configurations are merged correctly, and file operations fall back to the global service when tenant configuration is unavailable. Apache Doris 4.1 and Tencent VectorDB add vector-store options, including Tencent keyword retrieval; test credentials, tenant overrides, and hybrid retrieval before switching backends (#1096, #1109, #1137, #1154, #1180, #1184, #1234).
  • Wiki generation is stricter and scales to larger graphs — Citation tracing and ontology reuse make generated content more auditable, while concept-based micro-classrooms reuse wiki graph structure. Subgraph APIs, interactive exploration, virtualized page lists, and on-demand ingest logs reduce large-graph overhead; the generic task queue and dead-letter support target roughly 40,000-document knowledge bases and provide a recovery path for failed ingestion jobs (#1119, #1120, #1167, #1169, #1176, #1241).
  • Automation gains a CLI and MCP approval controls — CLI v0.1 establishes a command-line automation surface, while agent/MCP workflows add human-in-the-loop approval. Integrations should account for approval prompts and execution state rather than assuming every MCP tool call runs unattended (#1144, #1179).
  • Streaming chat is more robust, with bounded LLM calls — Fixes separate think/answer output, normalize final-answer rendering, preserve history during model fallback, deduplicate memory writes on repeated streaming Done, and repair ChatStream cancellation leaks. LLM calls now have timeout protection, with the frontend ceiling raised to 3600 seconds; long-running agents should still supply upstream deadlines because the fallback timeout applies only when none exists (#1112, #1125, #1126, #1153, #1238, #1242, #1243).
  • Breaking build and deployment changes — The project moves to Go 1.26, raises several docreader dependency floors, and switches the frontend to npm to match the committed lockfile. Update CI images and package-manager assumptions before rebuilding. BASE_URL support and static-resource Cache-Control fixes also improve path-prefixed reverse-proxy deployments and post-upgrade frontend refreshes (#1115, #1149, #1174, #1200–#1206, #1231).
