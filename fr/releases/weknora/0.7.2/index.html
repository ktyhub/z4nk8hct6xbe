WeKnora v0.7.2

Highlights

  • MCP server rebuilt on the 2.x high-level API — #2420 migrates the server onto MCP's high-level MCPServer API (v1.1.0), while #2395 separately pins the Python SDK to 1.x — two different version lines, so check which one governs your client before upgrading. Protocol-level fixes are the real adoption blockers: #2375 corrects the SSE message route that broke initialization, #2371 moves diagnostics to stderr so stdio transport stops crashing, and #2422 accepts non-UUID Agent IDs. New tools: list_shared_knowledge_bases (#2497) and create_knowledge_from_text (#2532). Watch for startup regressions if you depended on the old low-level server wiring.
  • Wiki becomes editable and versioned — #2336 adds page revision history with diff, revert, and manual editing, with the revision drawer and reader layout polished in #2338/#2547. Archived pages are now excluded from lint cursors and stats (#2503, #2549), and folder paths survive page creation (#2429). Why it matters: wiki shifts from append-only notes to governable content — but reverts rewrite content, so treat revision history as a new audit surface.
  • Chunking and retrieval correctness sweep — A broad cluster changes what the retriever actually sees: deterministic merge order (#2319), overlap trimming that respects positions after pipeline rewrites (#2555, #2556, #2558), editable chunks with retrieval metadata (#2370), and preview/splitter alignment including normalized line endings (#2539, #2541, #2546). Storage hygiene matters too: batch delete now cleans bound vector stores (#2329), missing vector engines rebuild on demand (#2357), and SQLite filters vector candidates before top-k (#2440) — if SQLite results shifted, that's the cause. Also fixed: always-zero evaluation metrics from async passage indexing (#2359).
  • IM stability for multi-replica deployments — #2349 and #2365 harden connection lifecycle and recover channels after leader-lock loss; #2551 and #2557 fix a WeCom longconn deadlock and scope connection closes to their own generation. If you run more than one replica, these are the fixes that stop flapping channels. Integrations expand with Feishu docx sync via the blocks API and per-type downdrill (#2334), a Feishu Drive datasource (#2466), and QQBot markdown replies (#2483).
  • Auth and permission behavior changes — #2568 stops sanitizing registration passwords before hashing, so new accounts with special characters now hash exactly what was typed (existing hashes are untouched); worth flagging if your signup flow strips or transforms input. Internals were reorganized into domain-split routers with a unified auth session context (#2331), shared-agent source permissions were hardened (#2417), and #2421 lets the embed runtime read its own session — fixing 500s and lost conversations on refresh.
  • Storage, API, and upgrade notes — S3 users can rely on AWS "NoAk" default credentials such as IRSA/instance roles (#2008), and resource_urls=public returns directly loadable file URLs (#2531) — convenient for embeds, but check the exposure implications. Migration 000076 was renumbered (#2340), and deployment docs converged on docker compose pull guidance (#2574, #2576) after the earlier doc additions were reverted (#2571, #2572): on upgrade, pull fresh images instead of reusing cached tags, or you may run a stale schema.

No breaking changes.
