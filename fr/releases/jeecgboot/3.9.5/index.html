#JeecgBoot v3.9.5

Préface

JeecgBoot V3.9.3 vient de terminer une mise à niveau majeure de son architecture vers Spring Boot 4, et en moins d'une semaine, V3.9.5 a suivi. Cette fois, il ne s'agit pas d'une simple solution, mais d'une mise à niveau centralisée : les formulaires en ligne ont ajouté plusieurs sources de données et des rapports externes, les modèles de générateur de code ont été considérablement améliorés, les applications d'IA et AI Flow ont été considérablement améliorées en termes d'accès au modèle, de base de connaissances, d'orchestration des processus, de partage de jetons et de restrictions d'accès, et l'intégration de Feishu et les statistiques de journal OpenAPI ont été ajoutées. De plus, la V3.9.5 effectue un renforcement spécial des risques de sécurité tels que les autorisations d'interface sensibles, XSS, SSRF, l'injection SQL, les accès non autorisés et l'exécution de scripts, et complète le pilote Oracle, les performances de démarrage Java et l'optimisation de l'expérience des pages pour améliorer encore la sécurité, la stabilité et l'efficacité de développement du système.

Journal de mise à niveau

JeecgBoot V3.9.5 est une mise à niveau complète pour les applications low-code, l'IA, les capacités ouvertes, la sécurité et l'expérience en matière de performances : les formulaires en ligne ont ajouté la possibilité d'ajouter plusieurs sources de données, des rapports externes et l'importation d'images Excel, le modèle de générateur de code a été entièrement mis à niveau et prend en charge davantage de composants d'interface utilisateur front-end ; Les applications d'IA et AI Flow ont été considérablement améliorées en termes d'accès aux modèles, de base de connaissances, d'orchestration des processus, de partage de jetons et de limite d'accès ; dans le même temps, l'intégration Feishu, OpenAPI a été améliorée. Enregistrez les statistiques et le contrôle des autorisations, mettez à niveau le pilote Oracle et optimisez les performances de démarrage et de requête Java. De plus, cette version effectue une gestion spéciale des vulnérabilités autour des risques tels que l'accès non autorisé à l'interface, la protection des informations sensibles, XSS, SSRF, l'injection SQL et l'exécution de scripts pour améliorer encore la sécurité, la convivialité et la stabilité du système.

1. Framework de base et compatibilité des bases de données

  • Réalisation de l'adaptation compatible Jackson 3, Tomcat 11 et JDK 17, et mise à niveau du pilote Oracle.
  • Ajout de la prise en charge et de la compatibilité de Lettuce avec une commutation flexible entre Lettuce et Jedis, et optimisation du code lié à la gestion de session Redis.

JeecgBoot v3.9.5

Highlights

  • Security & auth overhaul (Shiro 3.0 + CVE batch) — Apache Shiro jumps 2.0.5 → 3.0.0 and shiro-redis 3.2.3 → 4.1.0, closing a large CVE set (SQL injection, SSRF, stored/DOM XSS, AI Flow script-node RCE, cross-tenant privilege escalation). Treat this as the riskiest upgrade: a major-version auth change plus tightened path matching, session and cookie handling means custom realms/filters and URL rules need a re-test. New default permission annotations on report export, user recycle bin and AI chat endpoints can turn previously-open calls into 401/403, and datasource configs no longer return plaintext passwords — clients that read those fields must adapt. Note: the Jimu report unauthorized-export fix (CVE-2026-58375) lands only in a later Jimu release, so that gap remains open in v3.9.5.

  • Framework baseline raised to JDK 17 / Jackson 3 / Tomcat 11 — The stack now requires JDK 17 with Jackson 3 and Tomcat 11, and defaults to lazy-initialization for faster startup. Audit custom Jackson serializers/deserializers for 2.x→3.x behavior changes, and verify the Tomcat 11 work-directory relocation if you depend on its old location. Redis now supports Lettuce with flexible switching against Jedis, so session-management code touching the Redis layer should be smoke-tested.

  • Online forms & low-code gain multi-datasource and external capture — Online forms and Online SQL can now target multiple data sources, and forms support external (public) submissions — a meaningful capability change for any workflow that collects data outside the platform, which also widens the attack surface the new permission/SSRF/XSS checks address. Excel import adds embedded (embed) and path-based (path) images plus multi-image/file import and image export; code-generator templates were expanded to emit more UI components (Popup dictionary, associated records, TinyMCE video, JVxeTable grouped selection). Added AI form generation with mock data and DB-adapted SQL, and AI generation/copy for reports and charts.

  • AI applications & AI Flow: sharing, rate limiting and orchestration — AI apps gain share Tokens plus rate limiting to stop malicious requests burning AI Token budget, and app duplication, flow-tool wrapping, plugin management and multimodal (image+text) generation. A key fix: JeecgBizToolsProvider previously failed its business-tool permission check unconditionally, so AI apps could not call business tools — that path should now work. AI Flow adds a current-user node, file-writing knowledge-base nodes, AI-assisted script authoring, stronger SQL variable binding/multi-condition queries, and refined sub-flow, variable aggregation and node grouping. Model access expands with 火山方舟, GPT Image 2, refreshed DeepSeek/Zhipu versions, and model duplication; several stability fixes target idle-session first-query stalls, stop-output errors, sub-flow result passing and MCP-then-chat breakage. Watch that newly enforced auth on anonymous AI chat and knowledge-base endpoints may affect unauthenticated integrations.

  • OpenAPI observability and third-party integrations — OpenAPI adds call-log statistics, log detail and Header display with fine-grained permission control, gains Dameng support, and fixes access for microservice Nginx deployments and Docker self-proxy addresses — useful if you run multi-tenant or containerized gateways. Feishu integration now covers messaging, org sync, third-party login and config management, and DingTalk/WeCom/Feishu/SMS support async sending; fixes cover WeCom OAuth2 callback when tenants are disabled and CAS login redirect. Also new: a level-3 (等保) password-strength switch and complexity rules, plus N+1 query reductions in user/department lookups.

前言

JeecgBoot V3.9.3 刚刚完成 Spring Boot 4 架构大升级，不到一周，V3.9.5 又接踵而至。这次并非简单修补，而是一次集中升级：Online 表单新增多数据源和外部填报，代码生成器模板大幅增强，AI 应用与 AI Flow 在模型接入、知识库、流程编排、分享 Token 和访问限流等方面全面提升，同时新增飞书集成和 OpenAPI 日志统计。

此外，V3.9.5 针对敏感接口权限、XSS、SSRF、SQL 注入、越权及脚本执行等安全风险进行专项加固，并完成 Oracle 驱动、Java 启动性能及页面体验优化，进一步提升系统的安全性、稳定性和开发效率。

升级日志

JeecgBoot V3.9.5 是一次面向低代码、AI 应用、开放能力、安全性及性能体验的综合升级：Online 表单新增多数据源、外部填报及 Excel 图片导入等能力，代码生成器模板全面升级并支持更多前端 UI 组件；AI 应用与 AI Flow 在模型接入、知识库、流程编排、分享 Token 和访问限流方面得到显著增强；同时完善飞书集成、OpenAPI 日志统计与权限控制，升级 Oracle 驱动并优化 Java 启动及查询性能。此外，本版本围绕接口越权、敏感信息保护、XSS、SSRF、SQL 注入和脚本执行等风险开展专项漏洞治理，进一步提升系统的安全性、易用性和稳定性。

  • 修复前端字典刷新及字典选择组件多选回显问题。
  • 优化审批角色分组用户展示及部门树搜索层级保留。

七、安全与漏洞专项

本次主干集中处理权限绕过、越权访问、敏感信息泄露、SQL 注入、远程代码执行、SSRF 及存储型/DOM 型 XSS 等安全风险，已确认涉及 CVE-2026-5616、CVE-2026-8195、CVE-2026-9579、CVE-2026-9580、CVE-2026-9581、CVE-2026-9604、CVE-2026-10239、CVE-2026-10240、CVE-2026-11464、CVE-2026-19000、CVE-2026-67925、CVE-2026-67926 等公开漏洞；同时将 Apache Shiro 从 2.0.5 升级至 3.0.0、shiro-redis 从 3.2.3 升级至 4.1.0，纳入上游安全修复并强化路径匹配、会话及 Cookie 安全。积木报表未授权导出问题对应 CVE-2026-58375，相关修复将在积木报表后续版本中生效。

  • 开展 AI 应用专项漏洞处理，强化模型、知识库、应用及匿名分享接口的鉴权。
  • 为更多敏感功能接口增加默认权限注解，加强积木报表导出、用户回收站和 AI 聊天等接口的权限控制。
  • 修复用户、部门、评论、校验规则、OpenAPI 及 BI 数据接口的越权和跨租户访问问题。
  • 加强 LLM API Key 等敏感凭证的权限控制和脱敏处理。
  • 加强数据源配置密码安全，接口不再返回明文密码。
  • 修复 AI Flow 脚本节点远程代码执行风险。
  • 修复 AI、OpenAPI、远程文件及图片处理相关 SSRF 风险。
  • 加强富文本、Markdown、评论、Online 表单、AI 对话、SVG 文件上传及通知公告的 XSS 防护。
  • 修复 SQL 注入检测绕过及 Online 报表 SQL 注入风险。
  • 加强 Online 报表字典查询权限校验。
  • 加强匿名 AI 聊天及远程文件访问控制。
  • 修复 Excel 导入错误提示中的 HTML 注入风险。
