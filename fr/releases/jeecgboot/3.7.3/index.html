JeecgBoot v3.7.3

Highlights

  • Three AI backends, one low-code platform — The headline change: the low-code AI assistant now switches between DeepSeek v3 and ChatGPT, plus a new path to a locally hosted DeepSeek-R1 via Ollama (help.jeecg.com/java/ai/DeepSeekR1.html). For adopters this is what lets you keep inference on-prem for data-sensitive deployments; the project recommends DeepSeek v3 for speed and quality. Watch issue #7754: each new chat turn was re-sending the full prior history, so prompt-token usage and duplicate context should normalize after upgrading.

  • Frontend toolchain jumps to Vite 6 — The build stack moves to Vite 6 with refreshed antd packages (3.4.19 and 4.2.6 lines). This is the change most likely to bite on upgrade: Vite 6 is a major bump, so custom build config, plugins, and Node version need revalidation. Relatedly, #7644 (3.7.2 dev server erroring after install) was fixed — do a clean install and dev-server smoke test before trusting an in-place upgrade.

  • Upgrade path hardened (Flyway + schema) — Coming from 3.7.2, two migration blockers were resolved: Flyway auto-upgrade failure (#7650) and sys_announcement_send missing an id primary key (#7725). These matter because a failed Flyway run or a keyless table can silently stall or corrupt an in-place upgrade — verify migrations complete cleanly before rolling out.

  • Redis stability fixes worth upgrading for alone — Two production-impact defects: a non-releasable lock causing deadlock and a QPS spike from repeated exists commands (#6876), and ERR unknown command "keys" against sys:cache:online:list* (#6918), typically hit on managed/cluster Redis where KEYS is disabled. If you run against a hosted Redis, this is the most operationally significant fix in the release.

  • JimuReport/JimuBI 1.9.3 and a JVxeTable cleanup — Both JimuReport and JimuBI move to 1.9.3, and a cluster of low-code form defects were closed: dictionary handling (#7497), single-select delete not firing (#7624), getValue diverging from docs (#7631), maxTagCount hardcoded to 1 in JvxeUserSelectCell (#7661), duplicate blur events on textarea (#7664), image-upload action honoring only the first image (#7750), and fuzzy-query JRangeNumber codegen rendering nothing on parent-child forms (#7549). Teams building Online forms should see several long-standing papercuts clear.

  • Breaking changes — None explicitly flagged; the Vite 6 major bump is the only change with real upgrade-risk, so treat the frontend build as the one area requiring a smoke test.
