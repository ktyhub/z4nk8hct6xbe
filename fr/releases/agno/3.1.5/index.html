agno v3.1.5

#Changelog

Nouvelles fonctionnalités :

  • Dépôts pour les agents en bac à sable : un ClaudeAgent ou un CodexAgent en bac à sable prend repository=Repository(url, branch="main") et démarre chaque session dans ce référentiel à /workspace/repository. Le premier tour épingle la validation exacte, les tours suivants conservent l'épingle et les modifications de l'ingénieur lors de la réutilisation à chaud et de la restauration des points de contrôle, et les référentiels privés s'authentifient avec GITHUB_READ_TOKEN à partir de l'environnement sandbox. Voir livre de recettes. (#11121)
  • S3 Checkpoint Store : S3CheckpointStore(bucket, prefix=..., endpoint_url=...) conserve les points de contrôle du bac à sable dans un compartiment compatible S3, de sorte que les agents en bac à sable s'exécutent sur plusieurs réplicas sans système de fichiers partagé. Les objets sont adressés par le contenu, les téléchargements sont vérifiés avant le retour de put et les informations d'identification proviennent de l'environnement AWS. Voir livre de recettes. (#11133)
  • Ouvrir le point de contrôle du bac à sable d'une exécution : open_run_checkpoint(run_id) / aopen_run_checkpoint sur un agent en bac à sable génère l'archive vérifiée d'une exécution terminée et validée, afin qu'un processus hôte puisse lire le tour laissé après la disparition du conteneur. checkpoint_store expose le magasin dans lequel les tours de l'agent écrivent. Voir livre de recettes. (#11131)
  • Planifications à la demande : une planification avec un cron_expr vide ou omis ne s'arme jamais et s'exécute uniquement via sa route de déclenchement, via HTTP et via ScheduleManager. ScheduleResponse.cron_expr est désormais facultatif et le signale comme null. (#11118)
  • KeenableTools : Nouvelle boîte à outils pour la recherche Web et l'extraction de pages Keenable (web_search, fetch_url_content, avec variantes asynchrones). Il fonctionne sans clé API ni nouvelle dépendance, et refuse les récupérations qui aboutissent à des adresses privées ou de bouclage. Voir livre de recettes. (#9558)

Améliorations :

  • Agents externes dans le registre : Registry(agents=[...]) accepte ClaudeAgent et CodexAgent, et les réponses de l'agent, de l'équipe et du flux de travail AgentOS portent un indicateur sandboxed. (#11127)
  • Modifications des points de terminaison de planification : la modification du endpoint d'une planification via PATCH /schedules/{schedule_id} ou via ScheduleManager met désormais à jour ses colonnes cibles au lieu de les laisser obsolètes. (#11118)

Corrections de bugs :

  • Valeurs par défaut du formulaire AgentOS sur FastAPI 0.147 : FastAPI 0.147.0 lit les champs du formulaire bool omis comme False, donc les routes d'exécution et de continuation ont renvoyé JSON au lieu de SSE lorsque stream a été omis et continuent sans regenerate=true échoué avec 400. Les routes restaurent désormais les valeurs par défaut déclarées pour stream, monitor et replace_original. (#11160)
  • Le bac à sable s'exécute sans Redis : l'agent en bac à sable exécuté sur POST /agents/{agent_id}/runs ne répond plus à 400 sur une file d'attente durable Postgres sans Redis. Le streaming et l'annulation de répliques croisées nécessitent toujours Redis. (#11161)
  • Fichiers de workflow : les sorties File produites dans les étapes Parallel, Steps, Loop, Condition et Router atteignent désormais l'étape suivante et workflow_run_response.files. (#10950)
  • YouTubeTools : les identifiants vidéo sont lus à partir des URL de courts métrages, en direct, mobiles, musicales et à confidentialité améliorée, et les identifiants vides renvoient No video ID found avant toute demande. (#10707)
  • PerplexitySearch et PubmedTools : un max_results=0 explicite est honoré au lieu d'être remplacé par la valeur par défaut. (#10595)
  • InMemoryDb : upsert_user_memory stocke une copie, donc la mutation du UserMemory après l'upsert ne modifie plus la mémoire stockée. (#11016)

agno v3.1.5

Highlights

  • Sandboxed agents get real repositories — ClaudeAgent/CodexAgent now accept repository=Repository(url, branch="main") and boot into /workspace/repository (#11121). The first turn pins the exact commit; later turns preserve both the pin and the engineer's edits across warm reuse and checkpoint restore, with private repos authenticating via GITHUB_READ_TOKEN. This turns the sandbox from a scratch container into a reproducible multi-turn coding environment — the change that matters if your agent has to build on an actual codebase rather than generate one from nothing.

  • Checkpoints become portable and inspectable — S3CheckpointStore(bucket, prefix=..., endpoint_url=...) writes content-addressed archives to any S3-compatible bucket, verifies uploads before put returns, and pulls credentials from the AWS environment, so sandboxed agents can span replicas without a shared filesystem (#11133). Paired with open_run_checkpoint(run_id) / aopen_run_checkpoint and the newly exposed checkpoint_store, a host can retrieve exactly what a completed turn left behind after the container is gone (#11131). Operationally this is the line between a demo and a deployable multi-replica service, and it gives you an artifact for auditing or post-mortems on failed runs.

  • Trigger-only schedules and a genuine endpoint fix — A schedule with no cron_expr (empty or omitted) never arms itself and fires only through its trigger route, via HTTP or ScheduleManager; ScheduleResponse.cron_expr is now optional and comes back as null (#11118). Clients that assume a string there need adjusting. The same PR fixes PATCH /schedules/{schedule_id} so changing endpoint updates the target columns instead of leaving stale routing — previously the edit looked successful while still hitting the old target, which is the kind of silent failure worth testing after upgrade.

  • KeenableTools: web search without keys — web_search, fetch_url_content and their async variants require no API key and add no dependency (#9558). The toolkit refuses fetches resolving to private or loopback addresses, a sensible SSRF default but also a hard limit: it cannot reach internal services, so keep a separate tool for those.

  • Runtime behavior changes worth checking — FastAPI 0.147 reads omitted bool form fields as False, which had made run/continue routes return JSON instead of SSE when stream was omitted and fail 400 on continues without regenerate=true; declared defaults for stream, monitor and replace_original are now restored (#11160). Sandbox runs on POST /agents/{agent_id}/runs work on a Postgres durable queue without Redis, but cross-replica streaming and cancellation still require it (#11161) — plan capacity accordingly. Smaller but real: File outputs now propagate through Parallel/Steps/Loop/Condition/Router steps (#10950), InMemoryDb.upsert_user_memory stores a copy so mutating your UserMemory afterwards no longer changes stored state (#11016), and explicit max_results=0 is honored rather than replaced by the default (#10595).

  • Breaking changes — None formally declared in this release.

Changelog

New Features:

  • Repositories for Sandboxed Agents: A sandboxed ClaudeAgent or CodexAgent takes repository=Repository(url, branch="main") and starts every session in that repository at /workspace/repository. The first turn pins the exact commit, later turns keep the pin and the engineer's edits across warm reuse and checkpoint restore, and private repositories authenticate with GITHUB_READ_TOKEN from the sandbox environment. See cookbook. (#11121)
  • S3 Checkpoint Store: S3CheckpointStore(bucket, prefix=..., endpoint_url=...) keeps sandbox checkpoints in an S3-compatible bucket, so sandboxed agents run on several replicas without a shared filesystem. Objects are content-addressed, uploads are verified before put returns, and credentials come from the AWS environment. See cookbook. (#11133)
  • Open a Run's Sandbox Checkpoint: open_run_checkpoint(run_id) / aopen_run_checkpoint on a sandboxed agent yield the verified archive a completed run committed, so a host process can read what a turn left behind after the container is gone. checkpoint_store exposes the store the agent's turns write to. See cookbook. (#11131)
  • On-Demand Schedules: A schedule with an empty or omitted cron_expr never arms itself and runs only through its trigger route, over HTTP and through ScheduleManager. ScheduleResponse.cron_expr is now optional and reports it as null. (#11118)
  • KeenableTools: New toolkit for Keenable web search and page extraction (web_search, fetch_url_content, with async variants). It works with no API key and no new dependency, and refuses fetches that resolve to private or loopback addresses. See cookbook. (#9558)

Improvements:

  • External Agents in the Registry: Registry(agents=[...]) accepts ClaudeAgent and CodexAgent, and AgentOS agent, team and workflow responses carry a sandboxed flag. (#11127)
  • Schedule Endpoint Edits: Changing a schedule's endpoint over PATCH /schedules/{schedule_id} or through ScheduleManager now updates its target columns instead of leaving them stale. (#11118)

Bug Fixes:

  • AgentOS Form Defaults on FastAPI 0.147: FastAPI 0.147.0 reads omitted bool form fields as False, so run and continue routes returned JSON instead of SSE when stream was omitted and continues without regenerate=true failed with 400. The routes now restore the declared defaults for stream, monitor and replace_original. (#11160)
  • Sandbox Runs Without Redis: Sandboxed agent runs over POST /agents/{agent_id}/runs no longer answer 400 on a Postgres durable queue without Redis. Cross-replica streaming and cancellation still need Redis. (#11161)
  • Workflow Files: File outputs produced inside Parallel, Steps, Loop, Condition and Router steps now reach the next step and workflow_run_response.files. (#10950)
  • YouTubeTools: Video ids are read from Shorts, live, mobile, music and privacy-enhanced URLs, and empty ids return No video ID found before any request. (#10707)
  • PerplexitySearch and PubmedTools: An explicit max_results=0 is honoured instead of being replaced by the default. (#10595)
  • InMemoryDb: upsert_user_memory stores a copy, so mutating the UserMemory after the upsert no longer changes the stored memory. (#11016)
