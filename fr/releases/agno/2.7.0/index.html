agno v2.7.0

#Changelog

Nouvelles fonctionnalités :

  • Comptes de service (PAT) : Exposez n'importe quel AgentOS en tant que serveur Model Context Protocol et connectez-le à votre agent de codage en une seule commande. uvx agno connect crée des jetons par client, ​​écrit la configuration MCP dans chaque client et vérifie la poignée de main – pas de modification manuelle de la configuration JSON. Les jetons sont des identités de machine agno_pat_... : stockage haché SHA-256, limité à chaque utilisateur, révocable via agno tokens revoke et appliqué dans tous les modes de déploiement.
  • agnoctl (agno CLI) : Nouveau CLI distribué sous le nom de agnoctl sur PyPI, invoqué sous le nom de agno. uvx agno connect provisionne les PAT et connecte les agents de codage MCP clients en une seule commande.
    • agno connect — découvrez un AgentOS, créez des PAT par client (--name pour un jeton partagé), écrivez la configuration MCP pour Claude Code, Claude Desktop, Cursor, Codex et ChatGPT, puis vérifiez chaque connexion.
    • agno tokens create/list/revoke – créer, inventorier et faire pivoter les PAT.
    • agno create — échafaudez un nouveau projet AgentOS à partir d'un modèle (agentos-<provider>).
    • agno up/down/restart/status — gestion du cycle de vie pour les déploiements AgentOS locaux.
  • Eval Suite Runner : Nouveau package agno.eval : Case, run_cases et CLI runner avec sujets d'équipe et notation numérique des juges.
  • Point de terminaison de découverte GET /info : signale agno_version, mcp: {enabled, path} et auth_mode afin que les outils externes (par exemple agnoctl) puissent découvrir les capacités d'un AgentOS avant de le toucher.

Améliorations :

  • Interface MCP v2 : Nouvelle surface opérateur à 8 outils sur /mcp : get_agentos_config, run_agent, run_team, run_workflow, continue_run, cancel_run, get_sessions, get_session_runs. Résultats d'exécution réduits (avec trappe d'évacuation result_mode="full"), notifications de progression MCP pour les outils de longue durée, HITL continuer/annuler le cycle de vie.
  • Couche d'authentification unique : Un AuthMiddleware sur l'application parent couvre les transports REST, /mcp et WebSocket — plus de dérive par transport. JWTMiddleware est conservé comme alias pour des raisons de compatibilité ascendante.
  • Scope Enforcement : check_route_scopes utilisé de manière identique par les chemins JWT, de compte de service et MCP, avec un get_resource_context_from_path basé sur les données (remplaçant les correspondances de sous-chaînes codées en dur). Chaque outil intégré MCP correspond à son itinéraire équivalent à REST pour les vérifications de portée.
  • Autorisation A2A : les routes A2A/AGUI appliquent désormais l'autorisation parallèlement à l'authentification ; les mappages de portée sont fusionnés par interface au niveau du préfixe de montage afin que les préfixes personnalisés soient également bloqués.

Corrections de bugs :

  • Isolement utilisateur pour les traces : GET /traces/{trace_id} applique désormais la propriété par utilisateur (renvoie 404 en cas de non-concordance, comportement de liste correspondant).
  • Authentification A2A : _add_auth_middleware n'exclut plus les routes d'interface A2A — Slack/Telegram/WhatsApp authentifient automatiquement leurs propres demandes entrantes, mais A2A ne le faisait pas et contournait auparavant la couche d'authentification unique.
  • Déduplication de la liste de base de données MCP get_agentos_config : la liste databases signalée est désormais dédupliquée dans les références de base de données d'agent/équipe/workflow.
  • get_db Guard : génère désormais un message clair 400 "Aucune base de données n'est configurée sur cet AgentOS" lorsqu'aucune base de données n'est enregistrée, au lieu d'augmenter le simple StopIteration.

Dernières modifications :

  • Surface MCP réduite de 19 → 8 outils : les outils d'écriture de session et de mémoire CRUD ne sont plus exposés via MCP. MCPServerConfig(include_tags={"memory"}) échoue désormais à la validation Pydantic. Les utilisateurs qui comptaient sur ces outils doivent plutôt appeler les points de terminaison REST.
  • Résultats d'exécution MCP découpés par défaut : les Clients qui ont consommé la forme brute RunOutput doivent soit gérer la nouvelle forme découpée, soit définir result_mode="full" dans MCPServerConfig.
  • AgentOS(authorization=True) sans clés JWT échoue rapidement : auparavant, cette configuration servait silencieusement une instance OPEN (les requêtes JWT et anonymes échouaient sans authentification). Lève désormais ValueError lors de la construction. Définissez les variables d'environnement JWT_VERIFICATION_KEY/JWT_JWKS_FILE ou transmettez verification_keys/jwks_file via authorization_config.
  • AGENTOS_URL Env Var : Renommé de AGNO_OS_URL. Migration : mettez à jour tout environnement ou configuration CI faisant référence à l'ancien nom.

  • exploit : v2.7 — comptes de service, interface MCP v2, agnoctl et suites eval par @ashpreetbedi dans https://github.com/agno-agi/agno/pull/8747

agno v2.7.0

Changelog

New Features:

  • Service Accounts (PATs): Expose any AgentOS as a Model Context Protocol server and connect it to your coding agent in one command. uvx agno connect mints per-client tokens, writes the MCP config into each client, and verifies the handshake — no manual JSON config editing. Tokens are agno_pat_... machine identities: SHA-256-hashed storage, scoped per-user, revocable via agno tokens revoke, and enforced across every deployment mode.
  • agnoctl (agno CLI): New CLI distributed as agnoctl on PyPI, invoked as agno. uvx agno connect provisions PATs and wires up coding-agent MCP clients in one command.
    • agno connect — discover an AgentOS, mint per-client PATs (--name for a shared token), write MCP config for Claude Code, Claude Desktop, Cursor, Codex, and ChatGPT, then verify each connection.
    • agno tokens create/list/revoke — mint, inventory, and rotate PATs.
    • agno create — scaffold a new AgentOS project from a template (agentos-<provider>).
    • agno up/down/restart/status — lifecycle management for local AgentOS deployments.
  • Eval Suite Runner: New agno.eval package: Case, run_cases, and CLI runner with team subjects and numeric judge scoring.
  • GET /info Discovery Endpoint: Reports agno_version, mcp: {enabled, path}, and auth_mode so external tooling (e.g. agnoctl) can discover an AgentOS's capabilities before touching it.

Improvements:

  • MCP Interface v2: New 8-tool operator surface at /mcp: get_agentos_config, run_agent, run_team, run_workflow, continue_run, cancel_run, get_sessions, get_session_runs. Trimmed run results (with result_mode="full" escape hatch), MCP progress notifications for long-running tools, HITL continue/cancel lifecycle.
  • Single Auth Layer: One AuthMiddleware on the parent app covers REST, /mcp, and WebSocket transports — no more per-transport drift. JWTMiddleware is preserved as an alias for backward compatibility.
  • Scope Enforcement: check_route_scopes used identically by JWT, service-account, and MCP paths, with a data-driven get_resource_context_from_path (replacing hardcoded substring matches). Every MCP built-in tool maps onto its REST-equivalent route for scope checks.
  • A2A Authorization: A2A/AGUI routes now enforce authorization alongside authentication; scope-mappings are merged per-interface at the mount prefix so custom prefixes are gated too.

Bug Fixes:

  • User Isolation for Traces: GET /traces/{trace_id} now enforces per-user ownership (returns 404 on mismatch, matching listing behavior).
  • A2A Authentication: _add_auth_middleware no longer excludes A2A interface routes — Slack/Telegram/WhatsApp self-authenticate their own inbound requests, but A2A did not and was previously bypassing the single auth layer.
  • MCP get_agentos_config Db-List Deduping: The reported databases list is now deduplicated across agent/team/workflow db references.
  • get_db Guard: Now raises a clear 400 "No database is configured on this AgentOS" when no db is registered, instead of raising bare StopIteration.

Highlights

  • One-command MCP onboarding and service accounts — The new agnoctl package, invoked as agno, lets uvx agno connect discover an AgentOS, mint scoped agno_pat_... tokens, configure supported coding-agent clients, and verify connections. Tokens are SHA-256-hashed and revocable; agno tokens manages their lifecycle, while agno create and local deployment commands streamline project setup. (#8747)

  • MCP v2 intentionally narrows the tool contract — /mcp drops from 19 tools to 8, retaining configuration discovery, agent/team/workflow execution, run continuation/cancellation, and session inspection, with progress notifications and HITL controls. Session-write and memory-CRUD tools are removed, and include_tags={"memory"} now fails validation—move those operations to REST and audit tool-dependent clients. (#8747)

  • MCP responses are trimmed by default — Smaller payloads change the response contract for clients parsing raw RunOutput objects. Update schema-sensitive integrations or set result_mode="full" in MCPServerConfig, then verify execution and continuation flows against the selected response shape.

  • Authorization gaps are closed across transports — A parent AuthMiddleware now covers REST, /mcp, and WebSockets, with JWTMiddleware retained as a compatibility alias. A2A/AGUI routes now enforce authorization and REST-equivalent scopes, including custom mount prefixes; review custom middleware configurations. Cross-user trace access also now returns 404 rather than exposing another user’s trace.

  • Two configuration migrations are required — AgentOS(authorization=True) without JWT verification material now raises ValueError instead of silently serving an open deployment: configure JWT_VERIFICATION_KEY/JWT_JWKS_FILE or pass verification_keys/jwks_file. Also replace AGNO_OS_URL with AGENTOS_URL in environment and CI configuration.

  • Eval suites become a first-class workflow — The new agno.eval package provides Case, run_cases, and a CLI runner with team subjects and numeric judge scoring. This gives developers a structured, reusable evaluation path for both individual agents and multi-agent teams instead of relying entirely on ad hoc scripts.

Breaking Changes:

  • MCP Surface Shrunk from 19 → 8 Tools: Session-write and memory-CRUD tools are no longer exposed via MCP. MCPServerConfig(include_tags={"memory"}) now fails Pydantic validation. Users who relied on these tools must call REST endpoints instead.
  • MCP Run Results Trimmed by Default: Clients that consumed the raw RunOutput shape must either handle the new trimmed shape or set result_mode="full" in MCPServerConfig.
  • AgentOS(authorization=True) Without JWT Keys Fails Fast: Previously this configuration silently served an OPEN instance (JWT and anonymous requests fell through unauthenticated). Now raises ValueError at construction. Set JWT_VERIFICATION_KEY/JWT_JWKS_FILE env vars or pass verification_keys/jwks_file via authorization_config.
  • AGENTOS_URL Env Var: Renamed from AGNO_OS_URL. Migration: update any environment or CI config that referenced the old name.

What's Changed
