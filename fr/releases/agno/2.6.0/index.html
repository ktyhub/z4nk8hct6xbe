agno v2.6.0

#Changelog

Nouvelles fonctionnalités :

  • Team HITL : Ajout de la couche API pour l'équipe humaine dans la boucle et prise en charge dans la page de discussion AgentOS.
  • Approbations d'équipe : Ajout de la prise en charge des approbations dans l'équipe, ainsi que dans la page de discussion AgentOS.
  • Workflow Executor HITL : Ajout de la prise en charge du niveau exécuteur humain dans la boucle dans le cas où un flux d'outils de pause est configuré sur un agent/une équipe dans une étape particulière d'un flux de travail.
  • Prise en charge multi-framework dans AgentOS (bêta) : Ajout d'une prise en charge de base pour ClaudeAgentSDK, Langgraph et DSPy en utilisant un seul AgentProtocol comme épine dorsale qui fonctionne avec le runtime AgentOS.
  • Reconnexion et reprise des exécutions : L'agent/l'équipe exécuté en arrière-plan à l'aide de SSE peut désormais être reconnecté et repris dans AgentOS en cas d'interruption (actualisation), afin que vous repartiez d'où vous êtes parti.
  • Factory : Agent/Équipe/Workflow peuvent désormais être créés dynamiquement au moment de l'exécution à l'aide de AgentFactory, TeamFactory et WorkflowFactory, permettant davantage de cas d'utilisation multi-locataires.
  • Fournisseur de contexte : Ajout de agno.context — un API propriétaire permettant de connecter une source externe (système de fichiers, Web, base de données SQL, Slack, Google Drive, serveur MCP) à un agent en tant qu'outil en langage naturel.

Corrections de bugs :

  • Usine appelable :
    • Correction de la préservation des outils d'usine et des membres lorsque l'agent/l'équipe est copié.
    • Correction de l'itération des outils d'usine appelables dans Agent.deep_copy.
  • Interface de télégramme :
    • Correction du respect de retry_after sur les erreurs de limite de débit Telegram 429
    • Ajout de l'option quoted_responses à l'interface Telegram
  • Agent OS Router : Correction de GET /workflows/{id} qui omettait les étapes de flux de travail imbriquées et Condition.else_steps (ainsi que les agents qu'elles contiennent) de la réponse
  • Workflow : Correction pour préserver parent_step_id via des couches d'enrichissement de flux de travail imbriquées en cas de flux de travail en tant qu'étape de flux de travail.
  • MCP : Correction de la gestion des en-têtes Aucun lors de la fusion des en-têtes d'initialisation dans les outils MCP.
  • Claude : Correction de rendre les importations anthropiques paresseuses dans agno.utils.models.claude.
  • Source de contenu distant : Correction du problème où deux téléchargements du même nom de fichier à partir de sources distantes différentes (dépôts GitHub, compartiments S3, compartiments GCS, etc.) produisaient des valeurs content_hash identiques.
  • FileTools : Correction de l'ajout de exclude_patterns à FileTools.
  • Agent HITL : Correction du flux pause-continuation ne gérant pas les appels d'outils ultérieurs.

Dernières modifications :

  • Filtre de type de session : le point de terminaison /sessions renvoie désormais tous les types de session (agent, équipe et workflow) par défaut, vous offrant une vue complète de vos sessions en un seul appel. Pour filtrer un type spécifique, transmettez ?type=agent ?type=team ou ?type=workflow dans votre demande.

agno v2.6.0

Changelog

New Features:

  • Team HITL: Added API layer for Team human in the loop and support in AgentOS chat page.
  • Team Approvals: Added support for Approvals in Team, along with in AgentOS chat page.
  • Workflow Executor HITL: Added support for executor level human in the loop in case when a pause tool flow is setup on an agent/team in a particular step of a workflow.
  • Multi-framework support in AgentOS (Beta): Added basic support for ClaudeAgentSDK, Langgraph and DSPy using a single AgentProtocol as the backbone which works with AgentOS runtime.
  • Reconnection and Resume Runs: Agent/Team running in background using SSE can now be reconnected and resumed in AgentOS in case of a interruption (refresh) so you start from where you left.
  • Factories: Agent/Team/Workflow can now be created dynamically at run-time using AgentFactory, TeamFactory and WorkflowFactory allowing for more multi-tenant usecases.
  • Context Provider: Added agno.context — a first-party API for plugging an external source (filesystem, web, SQL database, Slack, Google Drive, MCP server) into anagent as a natural-language tool.

Bug Fixes:

  • Callable Factory:
    • Fixed to preserve factory tools and members when Agent/Team is copied.
    • Fixed to skip iteration of callable-factory tools in Agent.deep_copy.
  • Telegram Interface:
    • Fixed to respect retry_after on Telegram 429 rate limit errors
    • Added quoted_responses option to Telegram interface
  • Agent OS Router: Fixed GET /workflows/{id} which omitted nested workflow steps and Condition.else_steps (along with the agents inside them) from the response
  • Workflow: Fixed to preserve parent_step_id through nested workflow enrichment layers in case of workflow as a workflow step.
  • MCP: Fixed to handle None headers when merging init headers in MCP tools.
  • Claude: Fixed to make anthropic imports lazy in agno.utils.models.claude.
  • Remote Content Source: Fixed where two uploads of the same filename from different remote sources (GitHub repos, S3 buckets, GCS buckets, etc.) produced identical content_hash values.
  • FileTools: Fixed to add exclude_patterns to FileTools.
  • Agent HITL: Fixed pause-continue flow not handling subsequent tool calls.

Breaking Changes:

  • Session Type Filter: The /sessions endpoint now returns all session types (agent, team, and workflow) by default, giving you a complete view of your sessions in a single call. To filter for a specific type, pass?type=agent ?type=team, or ?type=workflow in your request.
