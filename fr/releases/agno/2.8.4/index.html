agno v2.8.4

Highlights

  • Entity memory now supports capture and recall — PR #9177 replaces mandatory ALWAYS extraction with AGENTIC-only capture and reduces the tool surface to remember_about, link_entities, search_entities, and forget. recall(message) injects relevant entities plus an entity directory, while remember_about(..., note=...) connects memories to notes. This removes the automatic write-pass overhead, but capture and fact supersession require a configured model.
  • Entity-memory API migration is required — Replace create_entity/update_entity/add_fact/add_event with remember_about, map add_relationship to link_entities, and replace ID-based update_fact/delete_fact with a superseding fact or forget(...). Note that forget(entity) archives reversibly, whereas store.delete() hard-deletes; also re-check custom EntityMemoryConfig supersession prompts against the new defaults. (#9177)
  • FileSystem defaults are narrower — tools() now returns the seven notes-oriented tools instead of the full surface. Use tools(allow_delete=True) to restore delete_file, or include_tools/FULL_TOOLS to select check_lines and other tools explicitly; review agents that previously relied on deletion being available by default. (#9177)
  • First-class TrustedRouter provider — The new TrustedRouter(OpenAILike) class defaults to https://api.trustedrouter.com/v1 and trustedrouter/zdr, reads TRUSTEDROUTER_API_KEY, and is registered for model to_dict()/from_dict() round-trips. Developers can use the standard Agno model path—including tool calling and structured output—instead of a manual cookbook integration; missing credentials raise ModelAuthenticationError. (#9100)
  • Workflow HITL checkpoints serialize cleanly — StepRequirement.to_dict() now recursively converts nested executor RunRequirement/ToolExecution objects and treats missing requirement lists as empty. This fixes JSON persistence failures for executor human-in-the-loop state, eliminating the need for custom encoders when saving or transmitting checkpoints. (#9162)
  • Skill tools recover from null paths — get_skill_script and get_skill_reference now accept omitted or null path arguments and return the existing structured JSON error with available scripts/references, rather than failing Pydantic validate_call before the handler runs. Documentation-only and mixed skill sets can now let the model self-correct instead of aborting the turn; valid calls behave unchanged. (#9096)
