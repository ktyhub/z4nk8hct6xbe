agno v3.0.8

#Changelog

Nouvelles fonctionnalités

  • Lectures de pages complètes : Knowledge.read_full_page et aread_full_page renvoie une page publiée entière à partir d'un instantané SQL limité en lecture et en lecture seule. Les deux prennent en charge l’épinglage des révisions, les limites de caractères et les délais. Les pages surdimensionnées renvoient None ; les pages manquantes ou modifiées conservent les erreurs de frappe. Les appels partagent le pool de travailleurs de lecture de page existant à huit emplacements. (exploit : ajoutez des lectures de page entière limitées et un suivi de clôture partagé # 10063)
  • Usines de moteur PostgreSQL partagées : create_postgres_engine et create_async_postgres_engine exposent le pool de connexions d'Agno et les valeurs par défaut de sérialisation JSON avec des options SQLAlchemy configurables. Les URL postgres:// et postgresql:// sélectionnent Psycopg 3 dans ces nouvelles usines ; les pilotes explicites et les paramètres TLS sont préservés. La sélection du pilote du constructeur de base de données existant est inchangée. (exploit : ajouter des usines de moteurs PostgreSQL avec des valeurs par défaut partagées #10062)

Améliorations

  • Suivi de clôture Markdown partagé : agno.utils.markdown.advance_code_fence expose les règles de clôture du chunker de page pour les transformations d'application qui doivent conserver des exemples de code. Un livre de recettes d'une page complète montre les lectures et la normalisation de la prose. (exploit : ajoutez des lectures de page entière limitées et un suivi de clôture partagé # 10063)
  • Livre de recettes MCP hébergé par Magic Hour : un exemple de génération d'images et de vidéos couvre l'authentification du porteur, les longs délais d'expiration de rendu, la réutilisation de l'ID de projet et la gestion des URL de sortie. (exploit : ajouter le livre de recettes MCP hébergé par Magic Hour #10057)

Corrections de bugs

  • Intégrité des données de session (SQLite) : le upsert_sessions() en bloc dans SqliteDb / AsyncSqliteDb applique désormais la même vérification de propriétaire que le upsert_session() à une seule ligne ; auparavant, un lot contenant le session_id d'un autre utilisateur réattribuait la ligne et écrasait ses données. Les lignes refusées par le prédicat sont omises de la liste renvoyée, correspondant à Postgres et au chemin à une seule ligne. (#9937)
  • Le MCP public valide les outils réellement exposés. Les configurations de fonctions personnalisées telles que MCPConfig(tools=[custom_function], default_tools=False, stateless=True) fonctionnent désormais sans remplacement lifecycle_tools=False inutile. L'exposition publique des agents, des équipes ou des flux de travail nécessite toujours la désactivation des outils de cycle de vie ajoutés automatiquement avec lifecycle_tools=False ou exclude_tags={"lifecycle"}. (correctif : valider les outils publics efficaces de cycle de vie MCP # 10060)

agno v3.0.8

Highlights

  • Bounded full-page retrieval — Knowledge.read_full_page() and aread_full_page() fetch an entire published page in one SQL read and read-only snapshot, with revision pinning, character limits, and deadlines. Oversized pages return None, while missing or changed pages retain typed errors; reads share the existing eight-slot worker pool to bound concurrency (#10063).
  • Shared PostgreSQL engine defaults — New create_postgres_engine() and create_async_postgres_engine() factories centralize Agno’s connection-pool and JSON serialization defaults while accepting configurable SQLAlchemy options. Plain postgres:// and postgresql:// URLs select Psycopg 3; existing database constructors keep their previous driver-selection behavior, so adoption is opt-in (#10062).
  • SQLite session integrity fixes — Bulk upsert_sessions() now enforces the same owner check as single-row upserts, preventing a batch from reassigning and overwriting another user’s session. Rejected rows are omitted from returned results, aligning SQLite with PostgreSQL and the single-row path (#9937). Session JSON fields are also no longer double-encoded (#9797).
  • Effective MCP tool validation — Custom-function configurations such as MCPConfig(tools=[custom_function], default_tools=False, stateless=True) no longer require an unnecessary lifecycle_tools=False override. Publicly exposing agents, teams, or workflows still requires suppressing lifecycle tools with lifecycle_tools=False or exclude_tags={"lifecycle"} (#10060).
  • Compatibility — No breaking changes.

Changelog

New Features

  • Complete page reads: Knowledge.read_full_page and aread_full_page return an entire published page from one bounded SQL read and read-only snapshot. Both support revision pinning, character limits and deadlines. Oversized pages return None; missing or changed pages retain typed errors. Calls share the existing eight-slot page-read worker pool. (feat: add bounded full-page reads and shared fence tracking #10063)
  • Shared PostgreSQL engine factories: create_postgres_engine and create_async_postgres_engine expose Agno's connection-pool and JSON serialization defaults with configurable SQLAlchemy options. Plain postgres:// and postgresql:// URLs select Psycopg 3 in these new factories; explicit drivers and TLS settings are preserved. Existing database constructor driver selection is unchanged. (feat: add PostgreSQL engine factories with shared defaults #10062)

Improvements

  • Shared Markdown fence tracking: agno.utils.markdown.advance_code_fence exposes the page chunker's fence rules for application transforms that need to preserve code examples. A full-page cookbook demonstrates reads and prose normalization. (feat: add bounded full-page reads and shared fence tracking #10063)
  • Magic Hour hosted MCP cookbook: an example for image and video generation covers bearer authentication, long render timeouts, project ID reuse and output URL handling. (feat: add Magic Hour hosted MCP cookbook #10057)

Bug Fixes

  • Session data integrity (SQLite): bulk upsert_sessions() in SqliteDb / AsyncSqliteDb now applies the same owner check as the single-row upsert_session() — previously a batch containing another user's session_id would reassign the row and overwrite its data. Rows the predicate refuses are omitted from the returned list, matching Postgres and the single-row path. (#9937)
  • Public MCP validates the tools actually exposed. Custom-function configurations such as MCPConfig(tools=[custom_function], default_tools=False, stateless=True) now work without an unnecessary lifecycle_tools=False override. Public exposure of agents, teams or workflows still requires disabling the automatically added lifecycle tools with lifecycle_tools=False or exclude_tags={"lifecycle"}. (fix: validate effective public MCP lifecycle tools #10060)
