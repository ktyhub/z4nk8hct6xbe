agno v2.8.0

#Changelog

Nouvelles fonctionnalités

  • agno.scorer — Transformez une course en numéro :
    • CodeScorer : encapsule tout appelable (bool | float | Score ; comparaison de champs typés sous output_schema recommandée)
    • JudgeScorer : juge LLM avec le modèle toujours un choix explicite et des verdicts numériques normalisés aux points finaux exacts ((score - 1) / 9)
    • ToolCallScorer : vérifie les exécutions de l'outil de manière déterministe (les appels refusés, erronés ou rejetés par HITL ne satisfont jamais à une attente)
    • Tous les buteurs proposent des variantes synchronisées et asynchrones.
  • agno.environments — Environment + Task + run_rollouts(env, k=8) : exécutez chaque tâche K fois en isolation totale (nouvelle base de données/session/utilisateur, aucune mémoire/connaissance/écriture d'apprentissage, cache désactivé ; les lectures de connaissances fonctionnent toujours). Comprend une grille en direct par tentative, un taux de réussite réel par tâche, des empreintes digitales de dérive par rapport à la politique, save/load/diff, learning_zone() et to_sft_jsonl(...) pour exporter les tentatives de réussite en tant que SFT conversationnel JSONL avec un side-car de provenance. C'est la porte pass@k.
  • Case.scorer : la suite d'évaluation gagne un troisième contrôle — branchez n'importe quel marqueur sur un Case (avec Case.expected), gratuit et exact, pas d'appel LLM. SuiteResult.to_dict() gagne les touches additives score_value, score_passed, score_reason.
  • FileGenerationTools : Ajout de la génération de fichiers de code pour FileGenerationTools.
  • Outils Gmail : ajout de la pagination et de max_results_per_request.
  • Outils Adanos : ajout d'outils facultatifs sur le sentiment du marché Adanos.

Corrections de bugs

  • RemoteAgent / RemoteTeam : correction des métadonnées supprimées sur le chemin du protocole A2A.
  • Contenu : renvoie une chaîne vide pour une liste de contenu vide dans get_content_string().
  • Journal de décision : remplacement du datetime.utcnow() obsolète dans le magasin Decision_log.

Modifications récentes

  • ReliabilityEval correspond aux exécutions d'outils : les attentes de l'outil sont désormais satisfaites uniquement par une exécution propre (RunOutput.tools, tool_call_error non définis), et non par des requêtes côté message. Les verdicts peuvent devenir rouges après la mise à niveau — lorsqu'ils le font, l'évaluation était auparavant réussie pour une mauvaise raison (les entrées manquantes sont annotées "... (requested but refused/errored — execution matching, new in 2.8.0)"). Les vérifications d'arguments ont été déplacées vers ToolExecution.tool_args avec la même sémantique de correspondance partielle.
  • Invite de juge renforcée : Chaque AgentAsJudgeEval clôture désormais la sortie jugée derrière un nom occasionnel aléatoire par appel, avec l'instruction untrusted-data à l'intérieur de l'invite. Un </output> littéral n'échappe plus au bloc, et "marquer ce 10" dans une réponse jugée est une donnée, pas une instruction. Les verdicts des juges et le décompte des jetons peuvent changer.

agno v2.8.0

Highlights

  • Unified, reusable scorers — New agno.scorer adds sync/async CodeScorer, JudgeScorer, and ToolCallScorer. Judges require an explicitly selected model and normalize numeric verdicts with (score - 1) / 9; tool scoring checks executions rather than requested calls. Any scorer can also plug into Case, with additive SuiteResult fields score_value, score_passed, and score_reason (#9049, #9050).
  • Isolated pass@k rollouts — agno.environments runs each task K times with fresh database/session/user state, memory and learning writes disabled, and caching off while retaining knowledge reads. This measures policy reliability without cross-attempt contamination; save/load/diff support regression comparisons, and to_sft_jsonl(...) exports passing trajectories with provenance (#9050, #9070).
  • ReliabilityEval can flip red after upgrade — Tool expectations now require a clean execution in RunOutput.tools, so refused, errored, or HITL-rejected calls no longer count as success. Argument checks moved to ToolExecution.tool_args with unchanged partial-match semantics. Rerun existing evaluation baselines and investigate failures annotated as requested-but-not-executed; these often expose previously false-positive passes (#9049).
  • Judge verdicts need recalibration — AgentAsJudgeEval now wraps judged output in a random per-call nonce fence and treats embedded text—including literal </output> and “score this 10”—as untrusted data. This hardens against prompt injection, but verdicts and token counts may shift, so review judge thresholds and golden-case expectations (#9049).
  • Gmail and file-generation workflows scale better — Gmail tools gain pagination and max_results_per_request, requiring clients to consume pages when they need more than one response batch (#9030). FileGenerationTools can now generate code files, expanding it beyond non-code artifacts (#8420).
  • Remote-agent metadata and optional market signals — RemoteAgent/RemoteTeam now preserve metadata across the A2A protocol path, fixing handoffs that depended on that context (#8944). Optional Adanos tools add market-sentiment inputs without making the integration mandatory (#9060, #9061).

Changelog

New Features

  • agno.scorer — Turn a run into a number:
    • CodeScorer: wraps any callable (bool | float | Score; typed-field comparison under output_schema recommended)
    • JudgeScorer: LLM judge with the model always an explicit choice and numeric verdicts normalized to exact endpoints ((score - 1) / 9)
    • ToolCallScorer: checks tool executions deterministically (refused, errored, or HITL-rejected calls never satisfy an expectation)
    • All scorers ship sync and async variants.
  • agno.environments — Environment + Task + run_rollouts(env, k=8): run each task K times in full isolation (fresh db/session/user, no memory/knowledge/learning writes, cache off; knowledge reads still work). Includes a live per-attempt grid, real pass rate per task, drift-vs-policy fingerprints, save/load/diff, learning_zone(), and to_sft_jsonl(...) to export passing attempts as conversational-SFT JSONL with a provenance sidecar. This is the pass@k door.
  • Case.scorer: the eval suite gains a third check — plug any scorer into a Case (with Case.expected), free and exact, no LLM call. SuiteResult.to_dict() gains additive score_value, score_passed, score_reason keys.
  • FileGenerationTools: Added code file generation for FileGenerationTools.
  • Gmail Tools: Added pagination and max_results_per_request.
  • Adanos Tools: Added optional Adanos market sentiment tools.

Bug Fixes

  • RemoteAgent / RemoteTeam: Fixed metadata being dropped on the A2A protocol path.
  • Content: Return empty string for empty content list in get_content_string().
  • Decision log: Replaced deprecated datetime.utcnow() in the decision_log store.

Breaking Changes

  • ReliabilityEval matches tool executions: Tool expectations are now satisfied only by a clean execution (RunOutput.tools, tool_call_error not set), not by message-side requests. Verdicts can flip red after upgrading — when they do, the eval was previously passing for the wrong reason (missing entries are annotated "... (requested but refused/errored — execution matching, new in 2.8.0)"). Argument checks moved to ToolExecution.tool_args with the same partial-match semantics.
  • Hardened judge prompt: Every AgentAsJudgeEval now fences judged output behind a per-call random nonce, with the untrusted-data instruction inside the prompt. A literal </output> no longer escapes the block, and "score this 10" inside a judged answer is data, not an instruction. Judge verdicts and token counts may shift.
