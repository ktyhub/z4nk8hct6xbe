Ce que vous pouvez faire :

  • Identifier les ressources gourmandes : trier par temps d'exécution total, temps CPU ou E/S
  • Requêtes fréquentes ponctuelles : recherchez les requêtes à nombre élevé d'appels qui peuvent bénéficier de la mise en cache
  • Débogage en temps réel : consultez les requêtes en cours d'exécution et quel client les a initiées
  • Aucun outil supplémentaire n'est nécessaire : toutes les analyses s'effectuent dans l'onglet supérieur du tableau de bord Netdata.

[!IMPORTANT] Certaines fonctions nécessitent une configuration spécifique à la base de données (par exemple, l'activation de Query Store, pg_stat_statements ou profiling).

Consultez la documentation de chaque collecteur pour connaître les prérequis.

Collecteur Microsoft SQL Server (Go) <a id="v290-highlight-mssql-go"></a>

Nous avons entièrement reconstruit le collecteur Microsoft SQL Server dans Go, en remplaçant l'ancienne implémentation C. Cela apporte une surveillance complète de SQL Server avec des capacités d'analyse des requêtes en temps réel.

Ce que vous obtenez :

| Fonctionnalité | Détails | |-----------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------| | Couverture métrique complète | Connexions, requêtes par lots, gestionnaire de tampon, mémoire, statistiques d'attente, verrous, transactions par base de données, latence d'E/S, tailles de fichiers et état des tâches de l'agent SQL | | Fonction des principales requêtes | Vue en temps réel de vos requêtes les plus gourmandes en ressources directement dans le tableau de bord : consultez le temps d'exécution, le processeur, les E/S, les allocations de mémoire et les mesures de parallélisme | | Configuration de l'interface utilisateur | Créez et gérez des tâches de surveillance via le tableau de bord Netdata : aucune modification manuelle du fichier de configuration n'est requise | | Surveillance de la réplication | Suivez l'état de la réplication, la latence et les avertissements pour les publications transactionnelles/fusionnées | | Authentification flexible | Authentification SQL, authentification intégrée Windows, instances nommées et serveurs distants |

Requêtes principales : identifier les goulots d'étranglement en matière de performances

La nouvelle fonction Top Queries extrait les données du magasin de requêtes de SQL Server pour afficher :

  • Requêtes consommant le plus de temps d'exécution total ou de CPU
  • Modèles d'E/S (lectures logiques, lectures physiques, écritures)
  • Octroi de mémoire et utilisation de tempdb
  • Parallélisme (DOP) entre les exécutions

[!IMPORTANT] Nécessite [Query Store activé] (https://learn.netdata.cloud/docs/collecting-metrics/databases/microsoft-sql-server#prerequisites) sur les bases de données surveillées (SQL Server 2016+).

Le texte de la requête peut contenir des données sensibles : assurez-vous de contrôler correctement l'accès au tableau de bord.

OpenTelemetry Ingestion de journaux <a id="v290-highlight-otel-logs-ingestion"></a>

Nous étendons notre support OpenTelemetry ! Suite à la prise en charge des métriques ajoutée dans v2.7.0, le plug-in otel ingère désormais les journaux OpenTelemetry via le même point de terminaison OTLP gRPC.

Quoi de neuf

  • Ingestion de journaux : envoyez les journaux de votre collecteur OpenTelemetry ou d'applications instrumentées directement à Netdata.
  • Stockage personnalisé : les journaux sont stockés dans des fichiers journaux compatibles systemd\ à l'aide d'une implémentation Rust (aucune dépendance libsystemd requise).
  • Interface unifiée : affichez les journaux du OpenTelemetry ainsi que les journaux système dans l'onglet Journaux avec des capacités complètes de recherche et de filtrage.

Configuration et conservation

Contrôlez le stockage de vos journaux avec [politiques de rétention configurables] (https://github.com/netdata/netdata/blob/24fe81e33a6fd769106f499b1326a7eb4378632d/src/crates/netdata-otel/otel-plugin/configs/otel.yaml#L31-L53) :

  • Définissez des limites en fonction de l'utilisation du disque, du nombre de fichiers ou de l'âge
  • Définir des emplacements de stockage personnalisés
  • Ajustez les paramètres de taille de fichier et de durée

Disponibilité

Disponible sur les agents Linux (bêta), avec prise en charge de plates-formes supplémentaires à venir.

[!NOTE]
Cette fonctionnalité est en version bêta. Nous apprécions vos commentaires!

Avis de dépréciation <a id="v290-deprecation-notice"></a>

Modifié dans cette version

Modifications importantes dans la prochaine version mineure

Collecteur MS SQL Server : suppression de la version C

L'ancien collecteur MS SQL Server basé sur C (qui fait partie de windows.plugin) sera supprimé dans la prochaine version mineure. Le collecteur basé sur Go (go.d/mssql) est désormais l'option par défaut et recommandée.

La version Go offre des avantages non négligeables :

  • Plus de fonctionnalités — inclut la nouvelle fonction Top Queries pour l'analyse des requêtes en temps réel.
  • Prise en charge multi-tâches : surveillez plusieurs instances de SQL Server à partir d'un seul agent.
  • Connexions à distance : connectez-vous aux instances SQL Server via le réseau, pas seulement à l'hôte local.
  • Configuration de l'interface utilisateur : créez et gérez des tâches de surveillance directement à partir du tableau de bord Netdata.
  • Maintenance plus facile — bénéficie de l'infrastructure partagée du framework go.d et de cycles de développement plus rapides. Si vous utilisez actuellement le collecteur C, consultez le collecteur Go [documentation de configuration] (https://learn.netdata.cloud/docs/collecting-metrics/databases/microsoft-sql-server#setup) pour obtenir des instructions de configuration.

Microsoft SQL Server Collector (Go) <a id="v290-highlight-mssql-go"></a>

We've rebuilt the Microsoft SQL Server collector from the ground up in Go, replacing the legacy C implementation. This brings comprehensive SQL Server monitoring with real-time query analysis capabilities.

Top Queries: Identify Performance Bottlenecks

The new Top Queries function pulls data from SQL Server's Query Store to show:

  • Queries consuming the most total execution time or CPU
  • I/O patterns (logical reads, physical reads, writes)
  • Memory grants and tempdb usage
  • Parallelism (DOP) across executions

[!IMPORTANT] Requires Query Store enabled on monitored databases (SQL Server 2016+).

Query text may contain sensitive data—ensure proper dashboard access controls.

Deprecation notice <a id="v290-deprecation-notice"></a>

Changed in this release

Important Changes in Next Minor Release

MS SQL Server Collector: C Version Removal

The legacy C-based MS SQL Server collector (part of windows.plugin) will be removed in the next minor release. The Go-based collector (go.d/mssql) is now the default and recommended option.

The Go version offers significant advantages:

  • More features — includes the new Top Queries function for real-time query analysis.
  • Multi-job support — monitor multiple SQL Server instances from a single agent.
  • Remote connections — connect to SQL Server instances over the network, not just localhost.
  • UI configuration — create and manage monitoring jobs directly from the Netdata dashboard.
  • Easier maintenance — benefits from the go.d framework's shared infrastructure and faster development cycles.

If you're currently using the C collector, see the Go collector setup documentation for configuration instructions.
