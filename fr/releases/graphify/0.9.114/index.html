graphique v0.9.114

Travail de performance sur le pipeline d'extraction/construction/mise à jour, ainsi qu'un lot de correctifs d'extracteur et de build. Chaque entrée marquée Perf préserve exactement la sortie du graphique (identique à l'octet) ; l'extracteur corrige la sortie de modification et partage une modification du schéma du cache AST (voir la note à la fin).

  • Perf : ids normalize_id obtient un chemin rapide ASCII, des expressions régulières précompilées et un cache LRU, de sorte que le cas d'identifiant commun (ASCII, répété) ignore la boucle de normalisation Unicode. ~ 1,26x sur le chemin de calcul et une victoire importante sur les identifiants répétés, qui revient fortement dans un corpus.
  • Perf : cache save_cached crée la copie sur écriture de la charge utile portable sur disque au lieu de copy.deepcopy pour chaque résultat par fichier ; Environ 20 % plus rapide lors de la transformation en écriture dans le cache, évolutive en fonction de la taille du graphique par fichier. L'entrée n'est jamais mutée et les octets sur le disque sont identiques.
  • Perf : extraire chaque fichier source est lu du disque une fois (le hachage de clé et l'analyse partagent un tampon) au lieu de deux fois sur une construction à froid, et le tree-sitter Parser est réutilisé par langue au sein d'un travailleur au lieu d'être reconstruit par fichier (le fichier est lu environ de moitié sur le chemin du travailleur).
  • Perf : extraire la résolution inter-fichiers finalise ses index de nœuds/bords partagés en quelques passes fusionnées au lieu de ~6 analyses complètes indépendantes du graphique ; ~15 % plus rapide lors de l'étape de finalisation.
  • Perf : regardez la comparaison de topologie sans changement utilise un hachage de contenu indépendant de l'ordre calculé en une seule passe au lieu de trier et de re-sérialiser l'ensemble du graphique ; ~ 1,4x sur cette comparaison.
  • Perf : cluster la partition communautaire est mise en cache par un hachage de topologie et réutilisée lorsque le graphique est inchangé (~ 9x en cas d'accès au cache de cluster), et la clé de tri par bord déterministe supprime un json.dumps par bord au profit d'une clé de tuple bon marché (ordre identique).
  • Perf : analyser la centralité intermédiaire de suggest_questions exécute désormais une implémentation de Brandes à tableau plat au lieu de celle basée sur dict de networkx, avec des scores identiques bit pour bit ; ~ 2,6 fois plus rapide, augmentant avec la taille du graphique (#5303, merci @Max17190).
  • Perf : regardez chaque chemin source préservé est rebasé une fois par mise à jour incrémentielle au lieu d'être recalculé par nœud et bord ; la sortie de la mise à jour est identique en octets (#5322, merci @Max17190).
  • Correction : java un champ ou une classe annoté avec Lombok @Getter obtient le nœud getter synthétisé getX()/isX() que Javac voit, donc obj.getX() le résout ; les champs booléens utilisent isX, @Getter(AccessLevel.NONE) est respecté, un getter manuscrit n'est pas dupliqué et un @Getter non-Lombok est ignoré (#5148, merci @Deepjyoti-Sarmah).
  • Correction : kotlin, un appel de membre sur un récepteur avec un type déclaré (paramètre, propriété, val x: T ou val x = T()) se lie à la méthode de ce type dans les fichiers au lieu de la dernière méthode du même nom dans le fichier, et les appels d'interface sont envoyés à leurs implémenteurs ; un récepteur ambigu ou inconnu échoue à la fermeture (#5355, merci @xiongjianxu).
  • Correction : sql un corps de routine PostgreSQL PL/pgSQL que la grammaire analyse uniquement via la récupération d'ERREUR (RETURN QUERY SELECT ... FROM t) voit ses lectures de table récupérées sous forme de bords reads_from au lieu d'être supprimées (#5349, merci @Deepjyoti-Sarmah).
  • Correction : build lorsqu'un bord extrait par AST et une copie sémantique (LLM) du même bord sont liés, le bord déterministe EXTRAIT est conservé, donc une documentation ultérieure --update ne supprime plus un bord de code qu'une copie sémantique avait écrasé (#5334, merci @Ildar-gn).
  • Correction : sql une procédure T-SQL dont la grammaire n'analyse que partiellement l'en-tête (tree-sitter-sql 0.3.12+ lit mal le nom, absorbant les paramètres sans parenthèses ou un échappement ""/]]) donne un seul nœud de routine au lieu d'un doublon sous l'identifiant mal lu ; une vraie routine de partage de la ligne mal lue est conservée (#5236, merci @Deepjyoti-Sarmah).
  • Correction : vbnet, une méthode déclarée après un littéral de chaîne multiligne n'est plus supprimée : le fichier est analysé avec des chaînes multilignes aplaties en un espace réservé préservant la ligne, donc une chaîne non terminée sur une ligne n'avale plus le reste de la classe ; les fichiers sur une seule ligne sont analysés sans changement (#5320, merci @Deepjyoti-Sarmah).
  • Correction : cpp un type qualifié std:: (std::chrono::seconds, std::vector<T>) n'est plus recâblé sur un symbole de projet du même nom ; la référence std obtient son propre stub sans source que le recâblage du corpus ignore, tandis que les arguments de modèle du type std sont toujours résolus selon les propres types du projet (#5219, merci @deba2k5).
  • Correction : python un simple import mod où mod se trouve sur un répertoire sys.path.insert(...) (un répertoire de script non-package) lie désormais mod.func() au nœud de fonction func, correspondant au fichier unique sur ce chemin et échouant fermé en cas d'ambiguïté ou d'un nom stdlib ; un bord calls n'est plus alias sur un nœud de fichier (#5253, merci @madhusudanpatnaik).
  • Correction : servir une requête qui filtre sur la relation call conserve désormais les bords cross-repo calls (écrits comme relation=calls, context=cross_repo), qui ont été silencieusement supprimés par le filtre contextuel uniquement (#5257, merci @LHopitalOne).
  • Correction : construire le bord structurel method/contains d'un membre par rapport à son propriétaire est conservé sur un bord d'utilisation de membre dans la direction opposée (une méthode lisant la propre propriété statique ou constante de sa classe), de sorte que le membre ne disparaît plus du parcours du type ; les relations de non-utilisation (héritages/implémentements) conservent la règle existante (#2391, merci @livingforelvis). Le schéma de cache AST passe à 50 ; les caches chauds réexécutent les extractions Kotlin, Java, SQL, VB.NET, C++ et Python (importation sys.path) concernées.

graphify v0.9.114

Performance work on the extract/build/update pipeline, plus a batch of extractor and build fixes. Every entry marked Perf preserves graph output exactly (byte-identical); the extractor fixes change output and share one AST cache schema bump (see the note at the end).

  • Perf: ids normalize_id gets an ASCII fast-path, pre-compiled regexes and an LRU cache, so the common (ASCII, repeated) identifier case skips the Unicode normalization loop. ~1.26x on the compute path and a large win on repeated ids, which recurs heavily across a corpus.
  • Perf: cache save_cached builds the portable on-disk payload copy-on-write instead of copy.deepcopy-ing every per-file result; ~20% faster on the cache-write transform, scaling with per-file graph size. The input is never mutated and the on-disk bytes are identical.
  • Perf: extract each source file is read from disk once (the key hash and the parse share one buffer) instead of twice on a cold build, and the tree-sitter Parser is reused per language within a worker instead of rebuilt per file (file reads roughly halved on the worker path).
  • Perf: extract the cross-file resolution finalize builds its shared node/edge indexes in a few fused passes instead of ~6 independent full scans of the graph; ~15% faster on the finalize stage.
  • Perf: watch the no-change topology comparison uses an order-independent content hash computed in one pass instead of sorting and re-serializing the whole graph; ~1.4x on that compare.
  • Perf: cluster the community partition is cached by a topology hash and reused when the graph is unchanged (~9x on a cluster cache hit), and the deterministic edge-sort key drops a per-edge json.dumps in favour of a cheap tuple key (identical ordering).
  • Perf: analyze suggest_questions' betweenness centrality now runs a flat-array Brandes implementation instead of networkx's dict-based one, with bit-for-bit identical scores; ~2.6x faster, growing with graph size (#5303, thanks @Max17190).
  • Perf: watch each preserved source path is rebased once per incremental update instead of recomputed per node and edge; the update output is byte-identical (#5322, thanks @Max17190).
  • Fix: java a field or class annotated with Lombok @Getter gets the synthesized getX()/isX() getter node javac sees, so obj.getX() resolves to it; boolean fields use isX, @Getter(AccessLevel.NONE) is respected, a hand-written getter is not duplicated, and a non-Lombok @Getter is ignored (#5148, thanks @Deepjyoti-Sarmah).
  • Fix: kotlin a member call on a receiver with a declared type (parameter, property, val x: T, or val x = T()) binds to that type's method across files instead of the last same-named method in the file, and interface calls dispatch to their implementers; an ambiguous or unknown receiver fails closed (#5355, thanks @xiongjianxu).
  • Fix: sql a PostgreSQL PL/pgSQL routine body that the grammar only parses through ERROR recovery (RETURN QUERY SELECT ... FROM t) has its table reads recovered as reads_from edges instead of dropped (#5349, thanks @Deepjyoti-Sarmah).
  • Fix: build when an AST-extracted edge and a semantic (LLM) copy of the same edge tie, the deterministic EXTRACTED edge is kept, so a later docs --update no longer deletes a code edge that a semantic copy had overwritten (#5334, thanks @Ildar-gn).
  • Fix: sql a T-SQL procedure whose header the grammar only partly parses (tree-sitter-sql 0.3.12+ misreads the name, absorbing unparenthesised params or a ""/]] escape) yields a single routine node instead of a duplicate under the misread id; a real routine sharing the misread's line is kept (#5236, thanks @Deepjyoti-Sarmah).
  • Fix: vbnet a method declared after a multi-line string literal is no longer dropped: the file is reparsed with multi-line strings flattened to a line-preserving placeholder first, so an unterminated string on one line no longer swallows the rest of the class; single-line files are parsed unchanged (#5320, thanks @Deepjyoti-Sarmah).
  • Fix: cpp a std::-qualified type (std::chrono::seconds, std::vector<T>) is no longer rewired onto a same-named project symbol; the std reference gets its own sourceless stub the corpus rewire skips, while the std type's template arguments still resolve to the project's own types (#5219, thanks @deba2k5).
  • Fix: python a plain import mod where mod sits on a sys.path.insert(...) directory (a non-package script dir) now binds mod.func() to the func function node, matched to the unique file on that path and failing closed on ambiguity or a stdlib name; a calls edge is no longer aliased onto a file node (#5253, thanks @madhusudanpatnaik).
  • Fix: serve a query that filters on the call relation now keeps cross-repo calls edges (written as relation=calls, context=cross_repo), which were silently dropped by the context-only filter (#5257, thanks @LHopitalOne).
  • Fix: build a member's structural method/contains edge to its owner is kept over an opposite-direction member-usage edge (a method reading its class's own static property or constant), so the member no longer vanishes from the type's walk; non-usage relations (inherits/implements) keep the existing rule (#2391, thanks @livingforelvis).

The AST cache schema is bumped to 50; warm caches re-run the affected Kotlin, Java, SQL, VB.NET, C++ and Python (sys.path import) extractions.
