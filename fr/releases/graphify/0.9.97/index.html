graphique v0.9.97

0.9.97 (2026-10-27)

  • Sécurité : rédaction rationnelle la rédaction des informations d'identification pour les étiquettes de justification se déplace vers un seul point d'étranglement de pré-cache (_redact_rationale_labels à l'intérieur de _safe_extract), de sorte qu'aucun extracteur ne peut l'ignorer, et elle couvre désormais davantage de formes de fuite : informations utilisateur d'URL avec un utilisateur vide ou avec //@ dans le mot de passe, corps de clé privée PEM, jetons collés au texte environnant par _ (par exemple ghp_...), actualisation Slack xoxe- jetons, JWT courts et docstrings Common Lisp qui créaient auparavant des étiquettes sans rédaction. Les chaînes bénignes (hachages, prose sk-, URL sans informations utilisateur) sont laissées telles quelles (#4647, merci @0xkaushik-ai).
  • Sécurité : deps anyio est limité à >=4.14.2 dans l'extra mcp, au-dessus de CVE-2026-63374 (un contournement de validation de nom d'hôte IDNA 2003 vs 2008 qui permet à un MITM sur un domaine non-ASCII de présenter un certificat pour un hôte ASCII différent, CVSS 9.3). anyio n'est qu'une dépendance transitive et le fichier de verrouillage résout déjà 4.15.1, c'est donc un plancher pour empêcher une future re-résolution de régresser.
  • Correction : markdown analyse des en-têtes ATX selon CommonMark : une séquence de fin de # ne fait pas partie du texte d'en-tête (## Setup ## est "Configuration"), jusqu'à trois espaces d'indentation sont autorisés (quatre sont un bloc de code indenté) et une ligne de hachage uniquement comme ## ## ne crée aucun nœud (#4790, #4791, merci @jaimemartinez).
  • Correction : les blocs de code clôturés markdown sont suivis par les règles CommonMark (clôtures backtick et tilde, chaînes d'informations, longueur proche correspondante), donc une ligne qui ressemble à un en-tête à l'intérieur d'une clôture ne fuit plus en tant que structure, et un en-tête après un bloc ~~~ qui contient une ligne ``` n'est plus perdu (#4787, #4788, merci @jaimemartinez).
  • Correction : l'extraction structurelle yaml lit l'arborescence des nœuds composée, de sorte que les clés portent leur orthographe écrite et leur propre ligne source au lieu d'atterrir toutes sur la ligne 1, et les clés nues YAML 1.1 comme on/off/yes/no ne sont plus pliées en booléens (un bloc de workflow on: est extrait, non transformé en nœud True) (#4784, #4785, merci @jaimemartinez).
  • Correctif : razor les interfaces @implements d'un composant sont extraites en tant que bords implements au lieu d'être supprimées silencieusement (#4820, merci @ayushcodes10).
  • Correction : terraform un bloc fournisseur avec un alias obtient son propre nœud qualifié d'alias (donc deux blocs provider "aws" ne s'effondrent plus en un seul et ne perdent plus leurs attributs), et une référence provider = aws.west y est résolue au lieu de pendre ; un local littéralement nommé provider n'est plus mal lu (#4819, merci @ayushcodes10).
  • Correction : les paragraphes cobol qui suivent un END PROGRAM imbriqué se rattachent au programme englobant au lieu de coller à celui imbriqué, via une pile de programme (#4824, merci @ayushcodes10).
  • Correction : blade une directive wire:click lie le nom de la méthode nue : les modificateurs en pointillés (wire:click.prevent="submit") correspondent, les arguments d'appel sont supprimés du nom (deleteItem(5) lie deleteItem) et une action magique préfixée par $ ne crée aucun bord fabriqué (#4823, merci @ayushcodes10).
  • Correction : pascal un record est reconnu comme un type avec ses propres méthodes dans le repli de l'expression régulière (le chemin par défaut sans l'extra facultatif pascal), correspondant au chemin de l'arborescence ; Les membres operator sont également extraits (#4825, merci @ayushcodes10).
  • Correction : vbnet une déclaration Operator est extraite en tant que membre de type operator de sa classe et son corps est parcouru pour les appels, donc un appel d'assistance à l'intérieur d'un opérateur ne disparaît plus (#4821, merci @ayushcodes10).
  • Correction : fortran un call se résout en sous-programme qu'il nomme réellement au lieu d'une cible salée avec le nom du fichier appelant (qui n'a jamais été résolu), en utilisant le propre idiome de stub inter-fichiers de l'extracteur (#4795, merci @ayushcodes10).
  • Correction : cli graphify query --help/-h (et maintenant graphify explain --help/-h) sans rien d'autre imprime l'utilisation au lieu d'exécuter une requête littérale pour le texte "--help" ; une question plus longue qui contient simplement "--help" comme sous-chaîne s'exécute toujours comme une requête (#4830, merci @curl-man).
  • Correction : js, une fonction imbriquée (interne) ne s'infiltre plus dans la carte de noms à l'échelle du fichier, donc un appel ailleurs dans le fichier se lie à la fonction de niveau supérieur de ce nom plutôt qu'à une fonction interne qu'il ne peut pas voir ; Les portées de récursivité, d'observation et sœurs se résolvent correctement (portage le schéma de portée Python vers JS/TS) (#4767, merci @smngvlkz).
  • Correction : ocaml chaque liaison dans un module ... and ... ou class ... and ... chaîné par and est extraite, pas seulement la première, donc les liaisons ultérieures ne sont plus supprimées silencieusement ; chacun porte sa propre ligne source (#4822, merci @ayushcodes10).
  • Correctif : verilog, une méthode task de classe SystemVerilog est modélisée comme une méthode function (son propre nœud, ses références de bord method et de type de paramètre), et une variable locale de tâche ne fuit plus en tant que fausse référence de champ sur la classe (#4774, merci @ayushcodes10).
  • Correction : build un bord sans relation est supprimé au lieu d'être persistant, à la fois sur les chemins d'écriture de construction et bruts de --no-cluster, et le pliage d'alias (relationship à relation) s'exécute avant la vérification (#4810, merci @legendteddy ; reproducteur également déposé sous le numéro #4826 par @sunhouy).
  • Correctif : build le Shrink Guard compte un nœud de mention de document enregistré qui se replie dans son fichier jumeau AST lors du rechargement comme présent, non perdu, donc une écriture uniquement sur le cluster n'est plus refusée lorsque rien n'a été réellement perdu (#4778, #4779, merci @AndresDiagoM).
  • Correction : détecter un arbre de travail git lié dont l'extraction principale est résolue à l'intérieur de la racine d'analyse est élagué, de sorte qu'un arbre de travail frère n'est plus indexé en tant que deuxième copie complète du dépôt (#4683, #4833, merci @barlowa124 ; travail en double dans #4685 par @AndresDiagoM).
  • Correction : résolution un commentaire en ligne dans un glob pnpm-workspace est supprimé selon les règles YAML, et un glob que Path.glob rejette (un composant ** ou un modèle absolu) est ignoré avec un avertissement au lieu de planter toute l'exécution de extract (#4681, #4687, merci @Deepjyoti-Sarmah).
  • Correction : signaler un hub communautaire [[wikilink]] est envoyé via le même export._obsidian_safe_stem utilisé par l'exportation, donc le lien correspond au fichier que l'exportation écrit réellement au lieu de pendre (#4696, merci @ayushcodes10).
  • Correction : wiki une communauté réétiquetée uniquement par casse conserve son article au lieu de laisser le balayage supprimer le fichier que l'exécution vient d'écrire ; sur un système de fichiers sensible à la casse, le jumeau minuscule obsolète est dissocié plutôt que renommé sur le nouveau fichier (ce qui restaurerait silencieusement l'ancien corps) (#4508, #4798, merci @dupeisen).
  • Correction : les verbes de remplissage query get/gets/got/getting sont supprimés des termes de requête (comme les work/works existants), de sorte qu'un hub de framework étiqueté "Get" n'est pas extrait en tant que graine BFS par un bonus de correspondance exacte ; les recherches de nœuds pour un Get littéral sont toujours résolues (# 4686, merci @AndresDiagoM).

graphify v0.9.97

0.9.97 (2026-10-27)

  • Security: rationale redaction credential redaction for rationale labels moves to a single pre-cache choke point (_redact_rationale_labels inside _safe_extract), so no extractor can skip it, and it now covers more leak shapes: URL userinfo with an empty user or with //@ in the password, PEM private-key bodies, tokens glued to surrounding text by _ (for example ghp_...), Slack xoxe- refresh tokens, short JWTs, and Common Lisp docstrings that previously built labels without redacting. Benign strings (hashes, sk- prose, URLs without userinfo) are left alone (#4647, thanks @0xkaushik-ai).
  • Security: deps anyio is floored to >=4.14.2 in the mcp extra, above CVE-2026-63374 (an IDNA 2003 vs 2008 hostname-validation bypass that let a MITM on a non-ASCII domain present a cert for a different ASCII host, CVSS 9.3). anyio is only a transitive dependency and the lockfile already resolves 4.15.1, so this is a floor to stop a future re-resolution from regressing.
  • Fix: markdown ATX headings parse per CommonMark: a trailing run of # is not part of the heading text (## Setup ## is "Setup"), up to three spaces of indent are allowed (four is an indented code block), and a hash-only line like ## ## mints no node (#4790, #4791, thanks @jaimemartinez).
  • Fix: markdown fenced code blocks are tracked by CommonMark rules (backtick and tilde fences, info strings, matching close length), so a line that looks like a heading inside a fence no longer leaks as structure, and a heading after a ~~~ block that contains a ``` line is no longer lost (#4787, #4788, thanks @jaimemartinez).
  • Fix: yaml structural extraction reads the composed node tree, so keys carry their written spelling and their own source line instead of all landing on line 1, and YAML 1.1 bare keys like on/off/yes/no are no longer folded to booleans (a workflow on: block is extracted, not turned into a True node) (#4784, #4785, thanks @jaimemartinez).
  • Fix: razor a component's @implements interfaces are extracted as implements edges instead of being silently dropped (#4820, thanks @ayushcodes10).
  • Fix: terraform an aliased provider block gets its own alias-qualified node (so two provider "aws" blocks no longer collapse into one and lose attributes), and a provider = aws.west reference resolves to it instead of dangling; a local literally named provider is no longer misread (#4819, thanks @ayushcodes10).
  • Fix: cobol paragraphs that follow a nested END PROGRAM reattach to the enclosing program instead of sticking to the nested one, via a program stack (#4824, thanks @ayushcodes10).
  • Fix: blade a wire:click directive binds the bare method name: dotted modifiers (wire:click.prevent="submit") are matched, call arguments are trimmed from the name (deleteItem(5) binds deleteItem), and a $-prefixed magic action mints no fabricated edge (#4823, thanks @ayushcodes10).
  • Fix: pascal a record is recognised as a type with its own methods in the regex fallback (the default path without the optional pascal extra), matching the tree-sitter path; operator members are extracted too (#4825, thanks @ayushcodes10).
  • Fix: vbnet an Operator declaration is extracted as an operator-kind member of its class and its body is walked for calls, so a helper call inside an operator no longer vanishes (#4821, thanks @ayushcodes10).
  • Fix: fortran a call resolves to the subroutine it actually names instead of a target salted with the calling file's name (which never resolved), using the extractor's own cross-file stub idiom (#4795, thanks @ayushcodes10).
  • Fix: cli graphify query --help/-h (and now graphify explain --help/-h) with nothing else prints usage instead of running a literal query for the text "--help"; a longer question that merely contains "--help" as a substring still runs as a query (#4830, thanks @curl-man).
  • Fix: js a nested (inner) function no longer leaks into the file-wide name map, so a call elsewhere in the file binds to the top-level function of that name rather than an inner one it cannot see; recursion, shadowing and sibling scopes resolve correctly (ports the Python scope scheme to JS/TS) (#4767, thanks @smngvlkz).
  • Fix: ocaml every binding in an and-chained module ... and ... or class ... and ... is extracted, not just the first, so later bindings are no longer silently dropped; each carries its own source line (#4822, thanks @ayushcodes10).
  • Fix: verilog a SystemVerilog class task method is modeled like a function one (its own node, method edge and parameter-type references), and a task-local variable no longer leaks as a false field reference on the class (#4774, thanks @ayushcodes10).
  • Fix: build an edge with no relation is dropped instead of persisted, on both the build and the raw --no-cluster write paths, and alias folding (relationship to relation) runs before the check (#4810, thanks @legendteddy; reproducer also filed as #4826 by @sunhouy).
  • Fix: build the shrink guard counts a saved document-mention node that folds into its AST file twin on reload as present, not lost, so a cluster-only write is no longer refused when nothing was actually lost (#4778, #4779, thanks @AndresDiagoM).
  • Fix: detect a linked git worktree whose main checkout resolves inside the scan root is pruned, so a sibling worktree no longer gets indexed as a second full copy of the repo (#4683, #4833, thanks @barlowa124; duplicate work in #4685 by @AndresDiagoM).
  • Fix: resolution an inline comment in a pnpm-workspace glob is stripped per YAML rules, and a glob that Path.glob rejects (a ** component or an absolute pattern) is skipped with a warning instead of crashing the whole extract run (#4681, #4687, thanks @Deepjyoti-Sarmah).
  • Fix: report a community hub [[wikilink]] is slugged through the same export._obsidian_safe_stem the export uses, so the link matches the file the export actually writes instead of dangling (#4696, thanks @ayushcodes10).
  • Fix: wiki a community relabelled only by letter case keeps its article instead of having the sweep delete the file the run just wrote; on a case-sensitive filesystem the stale lower-case twin is unlinked rather than renamed over the fresh file (which would silently restore the old body) (#4508, #4798, thanks @dupeisen).
  • Fix: query filler verbs get/gets/got/getting are dropped from query terms (like the existing work/works), so a framework hub labelled "Get" is not pulled in as a BFS seed by an exact-match bonus; node lookups for a literal Get still resolve (#4686, thanks @AndresDiagoM).
