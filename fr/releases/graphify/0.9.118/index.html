graphique v0.9.118

Un lot de correctifs d’extraction, de résolution, de service, d’exportation, de clustering et de reporting à travers quatorze demandes d’extraction de la communauté. Les modifications Objective-C, C et C# modifient la sortie nœud/bord, de sorte que le schéma du cache AST est modifié (51 à 53) et que la première version après la mise à niveau réextrait les langues affectées ; les autres correctifs ne nécessitent aucune reconstruction.

  • Correction : csharp un paramètre ou un champ local nommé partial, required, async, nint, nuint ou with (mots-clés contextuels) que tree-sitter-c-sharp analyse mal là où une instruction commence par elle ne fait plus dérailler le fichier ; il est réécrit sous sa forme textuelle @name avant l'analyse (préservation de la longueur en octets), de sorte que le type englobant et les membres qui le suivent sont conservés au lieu d'être supprimés silencieusement (# 5043, merci @ThatAblaze).
  • Correction : c un appel via un champ de pointeur de fonction de structure (ops->run(), ops.run()) ne fabrique plus un bord calls vers une fonction libre du même nom ; le nom du champ ne constitue aucune preuve de la cible d'exécution du pointeur, donc la supposition est abandonnée. Un simple appel direct est toujours résolu (#5410, merci @sdivyanshu90).
  • Correction : objc une méthode Objective-C dont le nom se replie sur l'identifiant d'un frère dans un @interface/@implementation/@protocol (un _ de début/fin comme dans -setup/-_setup, ou une différence de casse uniquement) obtient son propre identifiant de nœud salé au lieu de l'écraser ; la déclaration et la définition d'une méthode partagent toujours un seul nœud (#5390, merci @ayushcodes10).
  • Correctif : go le type de propriétaire d'un champ struct est limité à son propre package, donc un champ d'un type dont le nom est déclaré dans deux packages se lie au bon et ses appels de membre sont résolus au lieu d'être supprimés comme ambigus (#5408, merci @azizur100389).
  • Correction : extraire une importation Svelte qui passe par un baril export * se résout désormais en véritable module de définition, correspondant au simple .ts. Le résolveur inter-fichiers masquait .vue mais pas .svelte, donc les importations Svelte <script> ont été perdues à cause d'une erreur d'analyse de modèle ; les barils enchaînés se résolvent et les réexportations ambiguës échouent. Exécutez graphify extract . --force une fois pour réparer un graphique déjà mis en cache (#5403, merci @Max17190).
  • Correctif : extraire les fichiers audio et vidéo détectés mais non extraits (l'extrait sans tête n'a pas d'étape de transcription) sont désormais signalés dans le résumé au lieu de disparaître silencieusement, correspondant aux autres notifications d'omission ; aucun nœud n'est fabriqué pour eux (#5076, merci @ayushcodes10).
  • Correction : sections La nouvelle tentative de get_section ne réutilise plus l'index de recherche de trigramme du graphique complet. La nouvelle tentative a été exécutée sur une vue de sous-graphe networkx dont le dict .graph est le même objet sur lequel l'index est mis en cache, de sorte que la nouvelle tentative a recherché des identifiants périmés, hors section et a généré KeyError ; la vue de nouvelle tentative obtient désormais ses propres métadonnées de graphique, ce qui supprime également un risque de corruption d'index de graphique partagé pour les appelants de service simultanés (# 5385, merci @Deepjyoti-Sarmah).
  • Correction : servir le serveur MCP charge graph.json hors de la boucle d'événements, donc un rechargement de graphe volumineux ne bloque plus les requêtes simultanées ; une requête lors d'un rechargement est servie sur le graphique actuel et un rechargement corrompu laisse l'ancien graphique intact (#5371, merci @Deepjyoti-Sarmah).
  • Correction : mettre à jour un GRAPH_REPORT.md clusterisé qui est supprimé alors que le graphique est par ailleurs inchangé est régénéré au lieu d'être ignoré par la porte de non-changement ; le graphique lui-même reste identique en octets (restauré à partir du cache de partition), il n'y a donc pas de reconstruction inutile (#5402, merci @Max17190).
  • Correction : les nœuds d'image requête sont rétrogradés dans la notation de départ aux côtés des documents et des articles, de sorte qu'une image riche en légendes ne dépasse plus le code réel pour une requête dont elle répète les termes (#445, merci @ayushcodes10).
  • Correction : les noms de fichiers d'exportation export honorent le NAME_MAX du système de fichiers cible (sondé via pathconf, non supposé être 255), donc graphify export obsidian/wiki/canvas n'abandonne plus avec ENAMETOOLONG sur les systèmes de fichiers qui signalent une limite inférieure telle que eCryptfs (143) ; les noms longs sont tronqués avec un suffixe de hachage et les liens internes utilisent les noms raccourcis (#2109, merci @Synvoya).
  • Correctif : les exportations de graphiques dirigés wiki incluent désormais les bords entrants, de sorte qu'un audit communautaire ne sous-estime plus la confiance (un bord AMBIGU entrant pouvait être invisible alors que la page indiquait "EXTRAIT 100 %"). Sur les pages de nœuds divins, les bords entrants sont marqués (incoming), donc une relation comme calls n'est pas lue à l'envers (#5369, merci @sdivyanshu90).
  • Correction : config .graphifyrc analyse désormais demote_docs / query_demote_docs, afin qu'un projet puisse définir la rétrogradation d'un document dans le fichier rc au lieu de uniquement via l'indicateur CLI ; un indicateur explicite le remplace toujours (#5290, merci @debojyoti10CC).
  • Perf : le comptage des chevauchements de communautés cluster lors d'une reconstruction est calculé à partir des nœuds partagés en un seul passage au lieu de croiser chaque paire de communautés, transformant une étape O (communautés au carré) en une étape linéaire avec des résultats identiques en octets (#5382, merci @Max17190).

graphify v0.9.118

A batch of extractor, resolution, serve, export, clustering and reporting fixes across fourteen community pull requests. The Objective-C, C and C# changes alter node/edge output, so the AST cache schema bumps (51 to 53) and the first build after upgrading re-extracts the affected languages; the other fixes need no rebuild.

  • Fix: csharp a local, parameter or field named partial, required, async, nint, nuint or with (contextual keywords) that tree-sitter-c-sharp mis-parses where a statement starts with it no longer derails the file; it is rewritten to its verbatim @name form before parsing (byte-length preserving), so the enclosing type and the members after it are kept instead of being silently dropped (#5043, thanks @ThatAblaze).
  • Fix: c a call through a struct function-pointer field (ops->run(), ops.run()) no longer fabricates a calls edge to a same-named free function; the field name is no evidence of the pointer's runtime target, so the guess is dropped. A plain direct call still resolves (#5410, thanks @sdivyanshu90).
  • Fix: objc an Objective-C method whose name folds onto a sibling's id within one @interface/@implementation/@protocol (a leading/trailing _ as in -setup/-_setup, or a case-only difference) gets its own salted node id instead of overwriting it; the declaration and definition of one method still share a single node (#5390, thanks @ayushcodes10).
  • Fix: go a struct field's owner type is scoped to its own package, so a field of a type whose name is declared in two packages binds to the right one and its member calls resolve instead of being dropped as ambiguous (#5408, thanks @azizur100389).
  • Fix: extract a Svelte import that comes through an export * barrel now resolves to the real defining module, matching plain .ts. The cross-file resolver was masking .vue but not .svelte, so the Svelte <script> imports were lost to a template parse error; chained barrels resolve and ambiguous re-exports fail closed. Run graphify extract . --force once to repair an already-cached graph (#5403, thanks @Max17190).
  • Fix: extract audio and video files that are detected but not extracted (headless extract has no transcription step) are now reported in the summary instead of silently vanishing, matching the other skip notices; no nodes are fabricated for them (#5076, thanks @ayushcodes10).
  • Fix: sections get_section's retry no longer reuses the full graph's trigram search index. The retry ran against a networkx subgraph view whose .graph dict is the same object serve caches the index on, so the retry searched stale, out-of-section ids and raised KeyError; the retry view now gets its own graph metadata, which also removes a shared-graph index-corruption hazard for concurrent serve callers (#5385, thanks @Deepjyoti-Sarmah).
  • Fix: serve the MCP server loads graph.json off the event loop, so a large graph reload no longer blocks concurrent requests; a request during a reload is served the current graph and a corrupt reload leaves the old graph intact (#5371, thanks @Deepjyoti-Sarmah).
  • Fix: update a clustered GRAPH_REPORT.md that is deleted while the graph is otherwise unchanged is regenerated instead of being skipped by the no-change gate; the graph itself is left byte-identical (restored from the partition cache) so there is no needless rebuild (#5402, thanks @Max17190).
  • Fix: query image nodes are demoted in seed scoring alongside documents and papers, so a caption-rich image no longer out-seeds real code for a query whose terms it happens to repeat (#445, thanks @ayushcodes10).
  • Fix: export export filenames honor the target filesystem's NAME_MAX (probed via pathconf, not assumed to be 255), so graphify export obsidian/wiki/canvas no longer aborts with ENAMETOOLONG on filesystems that report a lower limit such as eCryptfs (143); long names are truncated with a hash suffix and internal links use the shortened names (#2109, thanks @Synvoya).
  • Fix: wiki directed-graph exports now include incoming edges, so a community audit no longer under-reports confidence (an incoming AMBIGUOUS edge could be invisible while the page read "EXTRACTED 100%"). On god-node pages incoming edges are marked (incoming) so a relation like calls is not read backwards (#5369, thanks @sdivyanshu90).
  • Fix: config .graphifyrc now parses demote_docs / query_demote_docs, so a project can set doc demotion in the rcfile instead of only via the CLI flag; an explicit flag still overrides it (#5290, thanks @debojyoti10CC).
  • Perf: cluster community-overlap counting during a rebuild is computed from shared nodes in one pass instead of intersecting every pair of communities, turning an O(communities squared) step into a linear one with byte-identical results (#5382, thanks @Max17190).
