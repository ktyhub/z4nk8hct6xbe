graphique v0.9.101

graphique 0.9.101

Version de précision de résolution et d'exactitude du cache pour C++, Rust, Python, Go, la protection en écriture de build et les reconstructions incrémentielles. ###C++

  • Un appel membre x.m() est lié par le type du récepteur, désormais saisi à partir des paramètres de fonction et des champs de classe et pas seulement des paramètres locaux (void render(Base* b){ b->draw(); } se résout en Base::draw) ; un récepteur non typé ou ambigu conserve sa liaison dans le fichier (#3215, #4946).
  • Une définition hors ligne ou à en-tête divisé s'attache au propriétaire unique dont le fichier de classe se trouve dans son ensemble d'inclusion, au lieu d'une liaison croisée avec une fonction du même nom non liée ; les propriétaires ambigus échouent à la fermeture (#4916, #4920).
  • Une valeur appelable locale (un lambda ou std::function) est maintenue en dehors de la résolution d'appel globale par des durées de vie de liaison de plage d'octets, de sorte qu'elle n'émet plus d'appel INFERRED parasite vers un global du même nom ; un appel global légitime ultérieur survit (#4917, #4921).
  • Une référence d'alias de type (using Foo = Bar; puis Foo x;) se lie par orthographe exacte et un alias salé conserve son propre bord contains (#4951). ###Rust
  • Un appel qualifié par module (crate::b::helper(), super::m::f()) est résolu via une résolution inter-fichiers vérifiée par qualificatif, restant à l'intérieur de la caisse de l'appelant (#2135, #4944).
  • Un appel écrit dans les arguments d'une macro d'expression (println!("{}", f()), vec![g()]) est lié, limité à une liste verte afin que les corps macro_rules! et les DSL personnalisés soient laissés seuls (#4945).

Python / Aller

  • Un simple appel à l'intérieur d'une méthode ne se lie plus automatiquement à une méthode du même nom ; il se résout en la fonction importée ou au niveau du module qu'il nomme (#4933).
  • Les importations sont résolues sur les packages d'espace de noms PEP 420 répartis sur plusieurs racines src/ (#4929).
  • Une valeur de méthode Go atteinte via un champ récepteur est liée en tant que indirect_call (#1566, #4931).
  • Un initialiseur var au niveau du package Go fait référence aux types qu'il nomme (#2360, #4932).

Construire / mettre en cache / reconstruire / surveiller

  • Le garde en écriture ne refuse plus un graphe sain lorsque la déduplication d'entité transforme un nœud enregistré en un jumeau survivant ; une perte réelle est toujours refusée (#4940, #4952).
  • Les preuves de fichiers sémantiques provenant de sources indépendantes survivent à un pli dans un nœud propre au fichier AST ; les fantômes de mention INFERRED ordinaires se plient toujours afin que les graphiques n'accumulent pas de doublons (#4896, #4927).
  • L'index d'alias de tige de fichier ne relie un bord que lorsque le fichier du bord et la cible de l'alias partagent une famille de langues (#4949).
  • Les clés de cache conservent leur casse écrite afin que README.md et readme.md n'entrent plus en collision, et les fichiers hachés/compteurs de mots sont ouverts via os_long_path (#4925, #4937).
  • Un graphique --code-only reste uniquement en code pendant les reconstructions du crochet, du update et de la montre (#4923, #4939).
  • Une reconstruction n'attend plus indéfiniment lorsque msvcrt.locking n'est pas pris en charge (#4924, #4926).
  • Un rapprochement complet supprime les enregistrements source pour un arbre de travail Git lié exclu (#4919).
  • Les mises à jour AST uniquement préservent les preuves sémantiques inter-fichiers dont l'identifiant de nœud entre en collision avec une définition de code (#4950).
  • Un fichier découpé en tranches n'est mis en cache qu'une fois que chaque tranche a réussi et est assemblé dans l'ordre des morceaux (#4943, #4947). Le schéma du cache AST passe à 36 ; les caches chauds réexécutent les extractions concernées. Merci à @nothariharan, @Deepjyoti-Sarmah, @azizur100389, @andrebrait, @ayushcodes10, @madhusudanpatnaik, @Ethan-Ethan-Ethan et @AndresDiagoM.

graphify v0.9.101

graphify 0.9.101

Resolution-accuracy and cache-correctness release across C++, Rust, Python, Go, the build write guard, and incremental rebuilds.

C++

  • A member call x.m() binds by the receiver's type, now typed from function parameters and class fields and not only locals (void render(Base* b){ b->draw(); } resolves to Base::draw); an untyped or ambiguous receiver keeps its in-file binding (#3215, #4946).
  • An out-of-line or split-header definition attaches to the unique owner whose class file is in its include set, instead of cross-binding to an unrelated same-named function; ambiguous owners fail closed (#4916, #4920).
  • A local callable value (a lambda or std::function) is kept out of global call resolution by byte-range binding lifetimes, so it no longer mints a spurious INFERRED call to a same-named global; a later legitimate global call survives (#4917, #4921).
  • A type-alias reference (using Foo = Bar; then Foo x;) binds by exact spelling and a salted alias keeps its own contains edge (#4951).

Rust

  • A module-qualified call (crate::b::helper(), super::m::f()) resolves through qualifier-verified cross-file resolution, staying inside the caller's crate (#2135, #4944).
  • A call written inside an expression macro's arguments (println!("{}", f()), vec![g()]) is linked, gated to an allowlist so macro_rules! bodies and custom DSLs are left alone (#4945).

Python / Go

  • A bare call inside a method no longer self-binds to a same-named method; it resolves to the imported or module-level function it names (#4933).
  • Imports resolve across PEP 420 namespace packages split over multiple src/ roots (#4929).
  • A Go method value reached through a receiver field is linked as an indirect_call (#1566, #4931).
  • A Go package-level var initialiser references the types it names (#2360, #4932).

Build / cache / rebuild / watch

  • The write guard no longer refuses a healthy graph when entity dedup folds a saved node into a surviving twin; a genuine loss is still refused (#4940, #4952).
  • Independently sourced semantic file evidence survives a fold into an AST file-self node; ordinary INFERRED mention ghosts still fold so graphs do not accumulate duplicates (#4896, #4927).
  • The file-stem alias index only rebinds an edge when the edge's file and the alias target share a language family (#4949).
  • Cache keys keep their written case so README.md and readme.md no longer collide, and hashed/word-count files are opened through os_long_path (#4925, #4937).
  • A --code-only graph stays code-only across hook, update and watch rebuilds (#4923, #4939).
  • A rebuild no longer waits forever when msvcrt.locking is unsupported (#4924, #4926).
  • A full reconcile evicts source records for an excluded linked git worktree (#4919).
  • AST-only updates preserve cross-file semantic evidence whose node id collides with a code definition (#4950).
  • A sliced file is cached only once every slice has succeeded and is assembled in chunk order (#4943, #4947).

The AST cache schema is bumped to 36; warm caches re-run the affected extractions.

Thanks to @nothariharan, @Deepjyoti-Sarmah, @azizur100389, @andrebrait, @ayushcodes10, @madhusudanpatnaik, @Ethan-Ethan-Ethan and @AndresDiagoM.
