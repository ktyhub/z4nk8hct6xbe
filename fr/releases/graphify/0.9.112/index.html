graphique v0.9.112

  • Docs : python le README, ses traductions, CONTRIBUTING, RELEASING, le modèle de rapport de bug et les cibles ruff/pyright indiquent désormais Python 3.11 comme minimum, correspondant au plancher livré dans 0.9.111 (#5238, merci @Deepanshu-Mehta ; @Max17190 a envoyé le même correctif dans #5237).
  • Docs : liens le lien de configuration toujours actif dans le README et toutes les traductions pointent directement vers docs.graphify.com/open-source/vibe-coding au lieu de passer par une redirection depuis les anciens guides/chemin toujours actif (#5261, merci @SyedFahad7).
  • Correction : java chaque méthode surchargée obtient son propre nœud codé par arité et signature effacée, au lieu que toutes les surcharges s'effondrent en un seul nœud qui a supprimé des membres et des appels mal acheminés ; La correspondance de remplacement de affected est désormais sensible à l'arité, donc un fractionnement run(int) n'est pas lié à un supertype run() par étiquette, et les surcharges de dépôt croisé et de méthode générique sont également gérées (#5251, merci @deba2k5). Les surcharges de même arité, distinctes de type uniquement, se lient toujours à la première déclarée (reflétant le précédent C# #4584) ; La répartition de type argument littéral est un suivi. Les constructeurs surchargés partagent toujours un nœud.
  • Correction : go un type de récepteur nu (func (s Service) m()) se résout en type de son propre package au lieu d'être comparé à chaque type du même nom dans le corpus, donc deux packages déclarant chacun un Service conservent leurs propres bords d'appel de membre plutôt que les deux les perdent à cause d'une caution d'ambiguïté (#5242, merci @ayushcodes10).
  • Correction : rust une importation use crate::... est résolue à l'intérieur de sa propre caisse au lieu de fuir à travers les limites de la caisse vers l'élément du même nom d'une autre caisse dans un espace de travail multi-caisse ; une importation crate:: dans une seule caisse se résout toujours comme avant (#5240, merci @Max17190).
  • Correction : js un membre this.x = function (params) {...} ne fabrique plus un faux indirect_call lorsqu'un de ses paramètres masque une fonction de corpus du même nom utilisée en position d'argument ; ses propres paramètres et noms capturés à partir de la portée englobante sont traités comme des liaisons locales, tandis qu'un nom véritablement indépendant est toujours résolu (#5241, merci @Max17190).
  • Correction : c une inclusion d'angle qualifiée dans le répertoire (#include <dir/header.h>) est résolue en fichier local correspondant, et les en-têtes de bibliothèque standard (<stdio.h>, <functional>) sont conservés en dehors de l'index d'alias afin qu'un fichier de projet du même nom ne soit pas réparé sur eux ; un en-tête local qui partage un nom qualifié de répertoire est toujours résolu (#5218, merci @ Yi-111-a).
  • Correction : sql une table nommée avec des lettres non-ASCII dont la grammaire se réduit à un simple _ ne génère plus un nœud avec un identifiant vide ou un bord vers un identifiant vide ; le faux bord est supprimé à la place (#5250, merci @grbr2010).
  • Correction : dedup un mot dérivé d'un préfixe est séparé de son mot de base, donc les paires d'antonymes et de préfixes (synchronous/asynchronous, cyclic/acyclic, reload/load) ne se replient plus ensemble via l'étiquette floue fusionnent, tandis que les inflexions authentiques comme handler/handlers fusionnent toujours (#5239, merci @Deepanshu-Mehta).
  • Correction : construisez la table familiale du Edge Guard multilingue ne dérive plus de celle de l'extracteur : 37 extensions qui n'avaient pas d'entrée de famille (donc une collision de noms multilingue fortuite n'a jamais été supprimée) sont réconciliées, et un test échoue CI si les deux tables divergent à nouveau (#5247, merci @Yi-111-a).
  • Correctif : install graphify claude install écrit sa section dans le fichier que Claude Code lit réellement. Claude Code lit le AGENTS.md d'un projet uniquement lorsqu'aucun CLAUDE.md (CLAUDE.md, .claude/CLAUDE.md, CLAUDE.local.md) n'existe dans le projet ou dans tout répertoire situé au-dessus, donc la création d'un CLAUDE.md à côté d'un AGENTS.md a caché silencieusement ce AGENTS.md à Claude Code. L'installation cible désormais un CLAUDE.md/.claude/CLAUDE.md existant s'il est présent, sinon un AGENTS.md/.claude/AGENTS.md existant, sinon un nouveau CLAUDE.md comme auparavant ; la désinstallation est symétrique (#5277, merci @andrebrait).
  • Correctif : install graphify install refuse d'écraser une configuration Kilo existante qu'il ne peut pas analyser, au lieu de la remplacer silencieusement par un fichier uniquement graphique et de perdre les paramètres de l'utilisateur ; une configuration valide ou manquante fusionne toujours comme avant (#5265, merci @divya0795).
  • Correction : analyser les cycles d'importation de deux fichiers sont répertoriés avant que le plafond d'énumération ne soit rempli, donc sur un graphique avec de nombreux cycles plus longs, les cycles les plus serrés (deux fichiers mutuels) ne sont plus supprimés ; la liste est également désormais déterministe d'une exécution à l'autre (#5267, merci @divya0795).
  • Correction : extraire le net-shrink guard n'est pas armé pour une source qui n'a rien à protéger (une source qui n'a jamais produit de nœuds enregistrés, par exemple un fichier dont l'extra de grammaire facultatif n'est pas installé), donc une telle source ne bloque plus un extrait ultérieur qui réduit légitimement le graphe ; une source qui avait sauvegardé les enregistrements arme toujours le garde (#5245, merci @ayushcodes10).
  • Correction : build plier un jumeau de document Markdown préserve la structure du survivant : un véritable nœud de titre n'est plus confondu avec le jumeau sémantique de la page et le nœud de page (avec sa première page et ses bords contains) est conservé, tandis que les véritables jumeaux sémantiques se plient toujours (#5272, merci @sdivyanshu90).
  • Correctif : les alias de corpus liés par un lien symbolique build sont élagués indépendamment : l'exclusion ou la suppression d'un alias de lien symbolique ne supprime plus également sa cible ou un alias frère qui se résout dans le même fichier, car l'élagage correspond désormais aux clés sur le chemin du corpus plutôt que sur la cible physique résolue (#5273, merci @sdivyanshu90).
  • Correction : pascal une unité que la grammaire arborescente ne peut pas analyser bout à bout (par exemple une unité avec une chaîne littérale SQL échappée) est récupérée via une nouvelle tentative masquée préservant la longueur des octets, au lieu de ne produire aucun nœud ; la nouvelle tentative ne s'exécute que lorsque l'analyse normale est erronée et n'est acceptée que si elle est strictement plus saine, donc les unités déjà analysées sont inchangées (#5264, merci @patrykseksymfonia).
  • Correction : pascal une classe de base se résout en sa déclaration réelle dans l'unité dans laquelle elle est déclarée, au lieu d'un stub correspondant par convention de nom de fichier, de sorte que le bord inherits et les appels hérités via celui-ci sont résolus dans tous les fichiers (#5280, merci @patrykseksymfonia).
  • Correction : pascal un appel via une variable d'objet globale (DM.Open, l'idiome du module de données Delphi) se résout en membre de type de la variable : l'extracteur enregistre les globaux au niveau de l'unité, les champs par classe et les ombres par routine, et la résolution lie l'appel qualifié en échec via la clause d'utilisation, le laissant non résolu lorsqu'un champ, local ou global de type tableau masque le nom (# 3101, merci @patrykseksymfonia).
  • Feat : delphi un formulaire (.dfm/.lfm) est lié à l'unité qui l'implémente : la classe du formulaire et chaque stub OnClick = Handler obtiennent un avantage references INFÉRÉ par rapport à la classe et à la méthode réelles dans le frère .pas, couplés par nom de base et une recherche de classe/méthode unique (#5281, merci @patrykseksymfonia). Le schéma du cache AST passe à 48 ; les caches chauds réexécutent les extractions Go, Java, JS/TS, C/C++, SQL et Pascal concernées.

Anglais original / English original

graphify v0.9.112

  • Docs: python the README, its translations, CONTRIBUTING, RELEASING, the bug-report template and the ruff/pyright targets now state Python 3.11 as the minimum, matching the floor that shipped in 0.9.111 (#5238, thanks @Deepanshu-Mehta; @Max17190 sent the same fix in #5237).
  • Docs: links the Always-on setup link in the README and all translations points straight at docs.graphify.com/open-source/vibe-coding instead of going through a redirect from the old guides/always-on path (#5261, thanks @SyedFahad7).
  • Fix: java each overloaded method gets its own node keyed by arity and erased signature, instead of all overloads collapsing into one node that dropped members and misrouted calls; affected override-matching is now arity-aware so a split run(int) is not tied to a supertype run() by label, and cross-repo and generic-method overloads are handled too (#5251, thanks @deba2k5). Same-arity, type-only-distinct overloads still bind to the first declared one (mirroring the C# precedent #4584); literal-argument-type dispatch is a follow-up. Overloaded constructors still share one node.
  • Fix: go a bare receiver type (func (s Service) m()) resolves to its own package's type instead of being matched against every same-named type in the corpus, so two packages each declaring a Service keep their own member-call edges rather than both losing them to an ambiguity bail (#5242, thanks @ayushcodes10).
  • Fix: rust a use crate::... import resolves inside its own crate instead of leaking across crate boundaries to another crate's same-named item in a multi-crate workspace; a single-crate crate:: import still resolves as before (#5240, thanks @Max17190).
  • Fix: js a this.x = function (params) {...} member no longer fabricates a false indirect_call when one of its parameters shadows a same-named corpus function used in argument position; its own params and names captured from the enclosing scope are treated as local bindings, while a genuinely unbound name still resolves (#5241, thanks @Max17190).
  • Fix: c a directory-qualified angle include (#include <dir/header.h>) resolves to the matching local file, and standard-library headers (<stdio.h>, <functional>) are kept off the alias index so a same-named project file is not healed onto them; a local header that shares a directory-qualified name still resolves (#5218, thanks @Yi-111-a).
  • Fix: sql a table named with non-ASCII letters that the grammar collapses to a bare _ no longer mints a node with an empty id or an edge to an empty id; the bogus edge is dropped instead (#5250, thanks @grbr2010).
  • Fix: dedup a prefix-derived word is kept apart from its base word, so antonym and prefixed pairs (synchronous/asynchronous, cyclic/acyclic, reload/load) no longer fold together through the fuzzy label merge, while genuine inflections like handler/handlers still merge (#5239, thanks @Deepanshu-Mehta).
  • Fix: build the cross-language edge guard's family table no longer drifts from the extractor's: 37 extensions that had no family entry (so a coincidental cross-language name collision was never dropped) are reconciled, and a test fails CI if the two tables diverge again (#5247, thanks @Yi-111-a).
  • Fix: install graphify claude install writes its section to the file Claude Code actually reads. Claude Code reads a project's AGENTS.md only when no CLAUDE.md (CLAUDE.md, .claude/CLAUDE.md, CLAUDE.local.md) exists in the project or any directory above it, so creating a CLAUDE.md beside an AGENTS.md silently hid that AGENTS.md from Claude Code. The install now targets an existing CLAUDE.md/.claude/CLAUDE.md if present, else an existing AGENTS.md/.claude/AGENTS.md, else a new CLAUDE.md as before; uninstall is symmetric (#5277, thanks @andrebrait).
  • Fix: install graphify install refuses to overwrite an existing Kilo config it cannot parse, instead of silently replacing it with a graphify-only file and losing the user's settings; a valid or missing config still merges as before (#5265, thanks @divya0795).
  • Fix: analyze two-file import cycles are listed before the enumeration cap fills, so on a graph with many longer cycles the tightest (mutual two-file) cycles are no longer dropped; the listing is also now deterministic across runs (#5267, thanks @divya0795).
  • Fix: extract the net-shrink guard is not armed for a source that has nothing to protect (one that never produced any saved nodes, e.g. a file whose optional grammar extra is not installed), so such a source no longer blocks a later extract that legitimately shrinks the graph; a source that did have saved records still arms the guard (#5245, thanks @ayushcodes10).
  • Fix: build folding a Markdown document twin preserves the survivor's structure: a real heading node is no longer mistaken for the page's semantic twin and the page node (with its frontmatter and contains edges) is kept, while genuine semantic twins still fold (#5272, thanks @sdivyanshu90).
  • Fix: build symlinked corpus aliases are pruned independently: excluding or deleting one symlink alias no longer also drops its target or a sibling alias that resolves to the same file, because prune matching now keys on the corpus path rather than the resolved physical target (#5273, thanks @sdivyanshu90).
  • Fix: pascal a unit the tree-sitter grammar cannot parse end to end (for example one with an escaped SQL string literal) is recovered through a byte-length-preserving masked retry, instead of yielding no nodes; the retry runs only when the normal parse errored and is accepted only if strictly healthier, so units that already parse are unchanged (#5264, thanks @patrykseksymfonia).
  • Fix: pascal a base class resolves to its real declaration in the unit it is declared in, instead of a stub matched by filename convention, so the inherits edge and the inherited calls through it resolve across files (#5280, thanks @patrykseksymfonia).
  • Fix: pascal a call through a global object variable (DM.Open, the Delphi data-module idiom) resolves to the variable's type member: the extractor records unit-level globals, per-class fields and per-routine shadows, and resolution binds the qualified call fail-closed through the uses-clause, leaving it unresolved when a field, local or array-typed global shadows the name (#3101, thanks @patrykseksymfonia).
  • Feat: delphi a form (.dfm/.lfm) is linked to the unit that implements it: the form class and each OnClick = Handler stub get an INFERRED references edge to the real class and method in the sibling .pas, paired by base name and a unique class/method lookup (#5281, thanks @patrykseksymfonia).

The AST cache schema is bumped to 48; warm caches re-run the affected Go, Java, JS/TS, C/C++, SQL and Pascal extractions.
