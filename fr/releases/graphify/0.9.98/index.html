graphique v0.9.98

0.9.98 (2026-10-30)

  • Correction : construire lorsque les bords en double de même relation s'effondrent, la provenance de la copie perdante (de confiance plus faible) est conservée dans une liste also_seen sur le bord survivant au lieu d'être rejetée, de sorte que les preuves les plus faibles ne soient pas silencieusement perdues ; le champ est sérialisé en graph.json et est idempotent lors des reconstructions (#4881, #4891, merci @SyedFahad7).
  • Correction : csharp un nœud de méthode C# est étiqueté avec son type propriétaire (MyClass.Method) au lieu d'un simple Method, de sorte que les méthodes du même nom d'un type à l'autre peuvent être distinguées ; les identifiants et les bords des nœuds sont inchangés (étiquette d'affichage uniquement) (#4883, #4889, merci @SyedFahad7).
  • Feat : chemin graphify path et la sortie du chemin le plus court du MCP signalent la confiance globale du chemin comme le saut le plus faible (niveau de confiance le plus bas, puis score le plus bas), avec une ligne récapitulative nommant ce saut (#4885, #4892, merci @SyedFahad7).
  • Correction : chemin d'un point de terminaison écrit Type.Member se résout en nœud membre, pas en type conteneur, donc graphify path "Exporter.Run" "PdfReport.Build" trouve la véritable route d'appel ; les noms exacts et les noms de fichiers gagnent toujours en premier, et un Type.Member dont le membre n'existe pas échoue fermé (#4884, #4893, merci @SyedFahad7).
  • Correctif : les identifiants de fichier extrait et les identifiants par déclaration sont conservés distincts, donc une déclaration de niveau supérieur dont le nom correspond à son fichier (par exemple class Js dans a.js) n'est plus supprimée silencieusement en cas de collision d'identifiant ; les références entre fichiers se lient à l'identifiant déclaré (#4854, #4857, merci @Deepjyoti-Sarmah).
  • Correction : dedup lorsqu'une mention de document inter-fichiers et un nœud AST entrent en collision sur un identifiant de définition, le nœud AST conserve l'identifiant au lieu d'être supprimé, tandis que l'enrichissement du même fichier, les jumeaux d'extension et les cas à définition unique sont laissés tels quels (#4859, #4872, merci @TanmayShah29 ; approche en double dans #4871 par @ayushcodes10).
  • Correctif : build un cycle d'importation de deux fichiers (a importe b, b importe a) est signalé dans la construction non dirigée par défaut, et le tampon est effacé correctement lors des reconstructions incrémentielles/de surveillance afin qu'une importation abandonnée ne laisse plus un cycle obsolète (#4839, #4841, merci @Mpasha17 ; approche en double dans #4852 par @legendteddy).
  • Correction : extraire une importation JS/TS relative portant un suffixe ?query ou #fragment (./mod.js?v=1) se résout en module réel au lieu d'un nœud fantôme ; Les importations de nœuds #subpath restent intactes (#4860, #4876, merci @Jitendarmahara ; approche en double dans #4869 par @mirzasnowy).
  • Correction : go un récepteur lié à var x = T{} ou var x = &T{} (un littéral composite) est tapé comme T, correspondant à la forme x := T{}, donc ses appels membres sont résolus (#4843, merci @ayushcodes10).
  • Correctif : verilog, un constructeur de classe SystemVerilog (function new(...), qui n'a pas de type de retour) obtient son propre nœud, son bord method et ses références de type de paramètre (#4848, merci @ayushcodes10).
  • Correctif : powershell using module/using assembly supprime une véritable extension de fichier (Helpers.psm1 à helpers) mais conserve un nom de module en pointillés sans extension intact (Az.Accounts) (#4847, merci @ayushcodes10).
  • Correction : solidité un ensemble using {a, b} for T à fonction libre émet des bords uses pour chaque fonction nommée, pas seulement le formulaire using Lib for T à bibliothèque unique (#4846, merci @ayushcodes10).
  • Correction : commonlisp un defclass dont la superclasse est définie plus tard dans le même fichier se lie à ce nœud local au lieu de créer un stub sans source (#4845, merci @ayushcodes10).
  • Correction : pascal Les blocs de composants de formulaire inherited et inline (.lfm/.dfm) sont reconnus, donc un bloc object ultérieur conserve son parent correct au lieu d'être re-parenté par une pile d'imbrication corrompue (#4844, merci @ayushcodes10).
  • Correction : sert lorsque deux nœuds sont liés dans une recherche et ne diffèrent que par cas, celui épelé exactement comme demandé gagne (les autres restent accessibles un niveau plus bas) au lieu que chaque orthographe soit refusée comme ambiguë (#4870, merci @nothariharan).
  • Correction : export les clés d'exportation de texte Cypher MERGE sur l'identifiant de nœud stable et définit l'étiquette séparément, donc la réimportation après un changement d'étiquette met à jour le nœud au lieu de créer un doublon (#4878, merci @oleksii-tumanov).
  • Correction : pdf le cache de texte converti est saisi sur le chemin source résolu, donc deux PDF avec le même nom relatif dans des racines différentes ne s'empoisonnent pas au sein d'un même processus (#4851, merci @xunguangzlj-cloud).

graphify v0.9.98

0.9.98 (2026-10-30)

  • Fix: build when duplicate same-relation edges collapse, the losing (weaker-confidence) copy's provenance is kept in an also_seen list on the surviving edge instead of being discarded, so the weaker evidence is not silently lost; the field is serialized to graph.json and is idempotent across rebuilds (#4881, #4891, thanks @SyedFahad7).
  • Fix: csharp a C# method node is labelled with its owning type (MyClass.Method) instead of a bare Method, so same-named methods across types are distinguishable; node ids and edges are unchanged (display label only) (#4883, #4889, thanks @SyedFahad7).
  • Feat: path graphify path and the MCP shortest-path output report the overall path confidence as the weakest hop (lowest confidence tier, then lowest score), with a summary line naming that hop (#4885, #4892, thanks @SyedFahad7).
  • Fix: path an endpoint written Type.Member resolves to the member node, not the containing type, so graphify path "Exporter.Run" "PdfReport.Build" finds the real call route; exact names and file names still win first, and a Type.Member whose member does not exist fails closed (#4884, #4893, thanks @SyedFahad7).
  • Fix: extract file ids and per-declaration ids are kept distinct, so a top-level declaration whose name matches its file (for example class Js in a.js) is no longer silently dropped on an id collision; cross-file references bind to the declared id (#4854, #4857, thanks @Deepjyoti-Sarmah).
  • Fix: dedup when a cross-file document mention and an AST node collide on a defining id, the AST node keeps the id instead of being dropped, while same-file enrichment, extension twins and single-definer cases are left as-is (#4859, #4872, thanks @TanmayShah29; duplicate approach in #4871 by @ayushcodes10).
  • Fix: build a two-file import cycle (a imports b, b imports a) is reported in the default undirected build, and the stamp is cleared correctly on incremental/watch rebuilds so a dropped import no longer leaves a stale cycle (#4839, #4841, thanks @Mpasha17; duplicate approach in #4852 by @legendteddy).
  • Fix: extract a relative JS/TS import carrying a ?query or #fragment suffix (./mod.js?v=1) resolves to the real module instead of a phantom node; Node #subpath imports are left untouched (#4860, #4876, thanks @Jitendarmahara; duplicate approach in #4869 by @mirzasnowy).
  • Fix: go a receiver bound with var x = T{} or var x = &T{} (a composite literal) is typed as T, matching the x := T{} form, so its member calls resolve (#4843, thanks @ayushcodes10).
  • Fix: verilog a SystemVerilog class constructor (function new(...), which has no return type) gets its own node, method edge and parameter-type references (#4848, thanks @ayushcodes10).
  • Fix: powershell using module/using assembly drops a real file extension (Helpers.psm1 to helpers) but keeps a dotted module name with no extension intact (Az.Accounts) (#4847, thanks @ayushcodes10).
  • Fix: solidity a free-function using {a, b} for T set emits uses edges for each named function, not just the single-library using Lib for T form (#4846, thanks @ayushcodes10).
  • Fix: commonlisp a defclass whose superclass is defined later in the same file binds to that local node instead of minting a sourceless stub (#4845, thanks @ayushcodes10).
  • Fix: pascal inherited and inline form component blocks (.lfm/.dfm) are recognised, so a later object block keeps its correct parent instead of being re-parented by a corrupted nesting stack (#4844, thanks @ayushcodes10).
  • Fix: serve when two nodes tie in a lookup and differ only by case, the one spelled exactly as queried wins (the others stay reachable one tier down) instead of every spelling being refused as ambiguous (#4870, thanks @nothariharan).
  • Fix: export the Cypher text export keys MERGE on the stable node id and sets the label separately, so re-importing after a label change updates the node instead of creating a duplicate (#4878, thanks @oleksii-tumanov).
  • Fix: pdf the converted-text cache is keyed on the resolved source path, so two PDFs with the same relative name in different roots do not poison each other within one process (#4851, thanks @xunguangzlj-cloud).
