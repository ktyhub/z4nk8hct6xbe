graphique v0.9.113

  • Changement : packaging le Python minimum est désormais 3.11.5 (au lieu de 3.11), et le soupsieve est épinglé sur 4.1.1 pour chaque interprète. Les versions corrigées de soupsieve nécessitent 3.11.5, donc augmenter le plancher efface les avis ouverts de soupsieve (ReDoS et récursivité/polynomial-DoS dans l'analyseur de sélecteur CSS, atteints de manière transitive via beautifulsoup4 dans les extras facultatifs svg/all/pdf). Les installations sur Python 3.11.0-3.11.4 continuent de se résoudre en 0.9.112 ; tout le monde sur 3.11.5 et plus n'est pas affecté (#5301, merci @TPAteeq).
  • Correction : les méthodes ruby d'une classe ou d'un module dont les noms diffèrent uniquement par un _ de début/fin ou par casse (_read_attribute/read_attribute, _where!/where!), y compris celles d'un class << self, obtiennent des identifiants de nœuds distincts au lieu que l'un avale l'autre (#5292, merci @rohit-jsfreaky).
  • Correction : les fonctions de champ de table lua dont les noms diffèrent uniquement par un _ de début/fin (M._load/M.load, Runner:_start/Runner:start) obtiennent des identifiants de nœud distincts ; M.f/M:f nomme toujours un champ (#5294, merci @rohit-jsfreaky).
  • Correction : les membres scala dont les noms diffèrent uniquement par un _ initial, un suffixe de définition _= ou une casse (_enter/enter, size/size_=, forEach/foreach), y compris dans une classe et son objet compagnon, obtiennent des identifiants de nœud distincts (#5296, merci @rohit-jsfreaky).
  • Correction : les définitions elixir dont les noms diffèrent uniquement par un _ de début/fin, un suffixe !/? ou une casse (_name/name, get/get!, __schema__/schema) obtiennent des identifiants de nœud distincts, donc un appel get! n'atteint plus get. (#5298, merci @rohit-jsfreaky).
  • Correction : rust l'argument de type d'un trait de prélude (Celsius dans impl From<Celsius> ou une limite T: Into<Celsius>) est lu comme une référence d'argument générique au lieu d'être confondu avec le trait lui-même, donc il n'émet plus un mauvais bord implements/inherits (#5332, merci @azeemshaik025).
  • Correction : go un appel de membre est conservé lorsqu'un autre package dans le corpus nomme un type de fichier frère : le stub sans source en collision est déplacé vers son propre identifiant au lieu de saler la déclaration réelle et de rendre orphelins ses bords de méthode, qui avaient abandonné l'appel (#5304, merci @Yi-111-a).
  • Correctif : ruby, une méthode écrite en ligne après un modificateur d'accès (private def validate, private_class_method def self.audit) conserve son appartenance à la classe englobante au lieu d'être émise en tant que fonction au niveau du fichier, donc les appels se résolvent en méthode (#5310, merci @Synvoya).
  • Correction : swift un appel qui est le dernier opérande d'une expression d'opérateur (base + bonus(), !isEmpty()), que la grammaire analyse en tant qu'appelé, est extrait au lieu d'être supprimé (#5311, merci @Synvoya).
  • Correction : kotlin un appel sous un opérateur de préfixe (!isReady(), -compute()) est extrait au lieu d'être supprimé, y compris les préfixes empilés et !obj.ready() (#5312, merci @Synvoya).
  • Correction : vbnet un paramètre avec une valeur par défaut est compté comme facultatif quel que soit l'ordre du modificateur (ByVal Optional x As Integer = 0, ByRef Optional ...), donc l'arité de la méthode et la résolution de surcharge sont correctes (#5320, merci @Deepjyoti-Sarmah).
  • Correction : les identités cpp include sont conservées lorsque le cache AST se trouve sur un autre lecteur que la source (un cas Windows multi-lecteurs où os.path.relpath était déclenché et chaque fichier avait une clé vide), donc le pliage de déclaration/définition fonctionne toujours ; le chemin normal sur le même lecteur est inchangé (#5145, merci @ Ayushraj06-bit).
  • Correction : les tentatives de génération d'étiquettes llm conservent un plancher de sortie de 512 jetons, de sorte que la passe de récupération d'une seule communauté n'est plus affamée en dessous du lot à partir duquel elle est en cours de récupération ; un GRAPHIFY_MAX_OUTPUT_TOKENS explicite remplace toujours (#2086, merci @Synvoya).
  • Correction : ruby un include/prepend/extend d'un module écrit dans un bloc class << self émet son bord mixes_in, au lieu d'être manqué car seules les instructions directes du corps de classe ont été analysées (#5317, merci @Synvoya).
  • Correction : python une classe avec une base paramétrée (class C(Base[T]), class D(Mapping[str, int])) émet le bord inherits vers le type de base et est parcourue pour les appels de méthode héritée, au lieu d'être supprimée et marquée comme opaque ; un argument générique imbriqué, une base d'appel et mod.Base[T] ne sont toujours pas traités comme des parents (#5318, merci @Synvoya).
  • Correction : tsconfig un mappage tsconfig.json extends et un mappage exact compilerOptions.paths sont résolus par rapport à la configuration/fichier analysé réel qu'ils nomment plutôt qu'à un stub pendant ; un package non-corpus s'étend, un chemin générique et une extension circulaire échoue fermée (# 5223, merci @Deepjyoti-Sarmah).
  • Correction : cpp une déclaration avant de classe inaccessible (un chemin d'inclusion n'atteint pas) ne bloque plus le repli de la déclaration d'un membre dans sa définition hors ligne ; les cas véritablement ambigus (un modèle ou une deuxième définition) restent toujours séparés (#5337, merci @winesoft-namjin-yun).
  • Correction : extraire une importation qui cible un en-tête impliqué dans une collision d'identifiant n'est plus inconditionnellement redirigée vers la variante d'en-tête : le repointage est contrôlé par la famille de langue du fichier d'importation, donc un Python import foo à côté d'un foo.h/foo.py en collision garde son avantage sur foo.py au lieu d'être supprimé comme multilingue (#5328, merci @sdivyanshu90).
  • Correction : servir une requête qui est un identifiant de nœud exact se résout directement sur ce nœud au lieu d'être surclassée par un autre nœud qui partage son chemin source tokenisé (#5343, merci @Ayushraj06-bit). Le schéma du cache AST passe à 49 ; les caches chauds réexécutent les extractions Ruby, Lua, Scala, Elixir, Rust, Swift, Kotlin, VB.NET, Python et TypeScript-config concernées.

Anglais original / English original

graphify v0.9.113

  • Change: packaging the minimum Python is now 3.11.5 (was 3.11), and soupsieve is pinned to 4.1.1 for every interpreter. soupsieve's patched releases require 3.11.5, so raising the floor clears the open soupsieve advisories (ReDoS and recursion/polynomial-DoS in the CSS selector parser, reached transitively through beautifulsoup4 in the optional svg/all/pdf extras). Installs on Python 3.11.0-3.11.4 keep resolving to 0.9.112; everyone on 3.11.5 and up is unaffected (#5301, thanks @TPAteeq).
  • Fix: ruby methods of one class or module whose names differ only by a leading/trailing _ or by case (_read_attribute/read_attribute, _where!/where!), including those in a class << self, get distinct node ids instead of one swallowing the other (#5292, thanks @rohit-jsfreaky).
  • Fix: lua table-field functions whose names differ only by a leading/trailing _ (M._load/M.load, Runner:_start/Runner:start) get distinct node ids; M.f/M:f still name one field (#5294, thanks @rohit-jsfreaky).
  • Fix: scala members whose names differ only by a leading _, a _= setter suffix, or case (_enter/enter, size/size_=, forEach/foreach), including across a class and its companion object, get distinct node ids (#5296, thanks @rohit-jsfreaky).
  • Fix: elixir defs whose names differ only by a leading/trailing _, a !/? suffix, or case (_name/name, get/get!, __schema__/schema) get distinct node ids, so a get! call no longer lands on get (#5298, thanks @rohit-jsfreaky).
  • Fix: rust a prelude trait's type argument (Celsius in impl From<Celsius> or a T: Into<Celsius> bound) is read as a generic-argument reference instead of being mistaken for the trait itself, so it no longer emits a wrong implements/inherits edge (#5332, thanks @azeemshaik025).
  • Fix: go a member call is kept when another package in the corpus names a sibling-file type: the colliding sourceless stub is moved to its own id instead of salting the real declaration and orphaning its method edges, which had dropped the call (#5304, thanks @Yi-111-a).
  • Fix: ruby a method written inline after an access modifier (private def validate, private_class_method def self.audit) keeps its membership of the enclosing class instead of being emitted as a file-level function, so calls to it resolve to the method (#5310, thanks @Synvoya).
  • Fix: swift a call that is the last operand of an operator expression (base + bonus(), !isEmpty()), which the grammar parses as the callee, is extracted instead of dropped (#5311, thanks @Synvoya).
  • Fix: kotlin a call under a prefix operator (!isReady(), -compute()) is extracted instead of dropped, including stacked prefixes and !obj.ready() (#5312, thanks @Synvoya).
  • Fix: vbnet a parameter with a default value is counted as Optional regardless of modifier order (ByVal Optional x As Integer = 0, ByRef Optional ...), so method arity and overload resolution are correct (#5320, thanks @Deepjyoti-Sarmah).
  • Fix: cpp include identities are kept when the AST cache is on another drive than the source (a Windows cross-drive case where os.path.relpath raised and every file got an empty key), so declaration/definition folding still works; the normal same-drive path is unchanged (#5145, thanks @Ayushraj06-bit).
  • Fix: llm label-generation retries keep a 512-token output floor, so the single-community recovery pass is no longer starved below the batch it is recovering from; an explicit GRAPHIFY_MAX_OUTPUT_TOKENS still overrides (#2086, thanks @Synvoya).
  • Fix: ruby an include/prepend/extend of a module written inside a class << self block emits its mixes_in edge, instead of being missed because only direct class-body statements were scanned (#5317, thanks @Synvoya).
  • Fix: python a class with a parameterized base (class C(Base[T]), class D(Mapping[str, int])) emits the inherits edge to the base type and is walked for inherited-method calls, instead of being dropped and marked opaque; a nested generic argument, a call base, and mod.Base[T] are still not treated as parents (#5318, thanks @Synvoya).
  • Fix: tsconfig a tsconfig.json extends and exact compilerOptions.paths mapping resolve to the real scanned config/file they name rather than a dangling stub; a non-corpus package extends, a wildcard path, and a circular extends fail closed (#5223, thanks @Deepjyoti-Sarmah).
  • Fix: cpp an unreachable class forward declaration (one no include path reaches) no longer blocks the fold of a member's declaration into its out-of-line definition; genuinely ambiguous cases (a template or a second definition) still stay separate (#5337, thanks @winesoft-namjin-yun).
  • Fix: extract an import that targets a header involved in an id collision is no longer unconditionally repointed to the header variant: the repoint is gated by the importing file's language family, so a Python import foo beside a colliding foo.h/foo.py keeps its edge to foo.py instead of being dropped as cross-language (#5328, thanks @sdivyanshu90).
  • Fix: serve a query that is an exact node id resolves straight to that node instead of being out-ranked by a different node that shares its tokenized source path (#5343, thanks @Ayushraj06-bit).

The AST cache schema is bumped to 49; warm caches re-run the affected Ruby, Lua, Scala, Elixir, Rust, Swift, Kotlin, VB.NET, Python and TypeScript-config extractions.
