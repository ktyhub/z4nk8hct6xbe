kops v1.37.0

Consultez le kOps 1.37 release notes complet pour plus de détails, y compris les modifications importantes et les dépréciations.

Faits saillants

  • Prise en charge de Kubernetes 1.37, avec etcd 3.7.3 par défaut pour les clusters Kubernetes 1.37
  • Référentiels d'actifs privés dans le stockage d'objets cloud : URL s3://, gs:// et azureblob:// pour KOPS_BASE_URL et spec.assets.fileRepository, avec des nœuds s'authentifiant via leur identité d'instance
  • Amorçage de nœud plus petit et plus résilient : le téléchargement du nœud passe d'environ 120 Mo à moins de 10 Mo, grâce à une compression binaire et xz plus petite, et le démarrage réessaye les tâches ayant échoué
  • Container Runtime : containersd 2.3.6 et runc 1.5.1 par défaut, avec la configuration containersd version 4 ; les versions de containersd antérieures à 2.1.0 ne sont plus prises en charge
  • Extension Karpenter : Karpenter v1.15.1, gestion des interruptions gérées par kOps (file d'attente SQS et règles EventBridge), paramètres de volume racine dans EC2NodeClass, prise en charge de instanceRequirements et groupes d'instances mixtes GPU et non GPU
  • Autorisations AWS IAM plus étroites pour les rôles d'instance (Route 53, KMS, EC2, SQS) et aucune stratégie en ligne pour les rôles qui ne nécessitent aucune autorisation
  • Modifications du gestionnaire etcd : images etcd regroupées montées en tant que volumes d'images et prise en charge des versions etcd personnalisées à partir d'une image fournie par l'utilisateur sur les nouveaux clusters
  • Mise en réseau : Calico v3.32.3 avec le passage à ClusterNetworkPolicy, prise en charge de la politique réseau pour AWS VPC CNI, kube-router v2.12.0 avec un backend expérimental de politique réseau nftables et kindnet v1.0.3
  • Azure : requêtes d'amorçage authentifiées avec des métadonnées d'instance signées, détection kops rolling-update cluster des machines virtuelles obsolètes et deux réplicas de gestionnaire de contrôleur cloud sur des plans de contrôle hautement disponibles
  • Akamai (Linode) : le fournisseur expérimental gère désormais les clés SSH, les réseaux, les sous-réseaux, les instances et les volumes de stockage en bloc
  • Mises à jour des composants : etcd-manager v3.0.20261022 avec etcd 3.5.35/3.6.16/3.7.3, Cilium v1.18.16, AWS VPC CNI v1.23.2, CoreDNS v1.15.0, AWS Load Balancer Controller v3.6.2, cert-manager v1.21.3, cluster-autoscaler v1.37.0
  • Supprimé : prise en charge de Kubernetes 1.31, gossip DNS (et protokube), AWS Classic Load Balancers pour le API et la mise en réseau Kopeio. Migrez avec kOps 1.36 avant la mise à niveau

kops v1.37.0

See the full kOps 1.37 release notes for details, including breaking changes and deprecations.

Highlights

  • Kubernetes 1.37 support, with etcd 3.7.3 as the default for Kubernetes 1.37 clusters
  • Private asset repositories in cloud object storage: s3://, gs://, and azureblob:// URLs for KOPS_BASE_URL and spec.assets.fileRepository, with nodes authenticating through their instance identity
  • Smaller and more resilient node bootstrap: the nodeup download drops from about 120 MB to under 10 MB, through a smaller binary and xz compression, and bootstrap retries failed tasks
  • Container runtime: containerd 2.3.6 and runc 1.5.1 by default, with containerd configuration version 4; containerd versions older than 2.1.0 are no longer supported
  • Karpenter expansion: Karpenter v1.15.1, kOps-managed interruption handling (SQS queue and EventBridge rules), root volume settings in EC2NodeClass, instanceRequirements support, and mixed GPU and non-GPU instance groups
  • Narrower AWS IAM permissions for the instance roles (Route 53, KMS, EC2, SQS), and no inline policies for roles that need no permissions
  • etcd-manager changes: bundled etcd images mounted as image volumes, and support for custom etcd versions from a user-supplied image on new clusters
  • Networking: Calico v3.32.3 with the move to ClusterNetworkPolicy, network policy support for AWS VPC CNI, kube-router v2.12.0 with an experimental nftables network policy backend, and kindnet v1.0.3
  • Azure: bootstrap requests authenticated with signed instance metadata, kops rolling-update cluster detection of outdated VMs, and two cloud-controller-manager replicas on highly available control planes
  • Akamai (Linode): the experimental provider now manages SSH keys, networks, subnets, instances, and block-storage volumes
  • Component updates: etcd-manager v3.0.20261022 with etcd 3.5.35/3.6.16/3.7.3, Cilium v1.18.16, AWS VPC CNI v1.23.2, CoreDNS v1.15.0, AWS Load Balancer Controller v3.6.2, cert-manager v1.21.3, cluster-autoscaler v1.37.0
  • Removed: support for Kubernetes 1.31, gossip DNS (and protokube), AWS Classic Load Balancers for the API, and Kopeio networking. Migrate with kOps 1.36 before the upgrade
