LightRAG v1.5.7rc2

Highlights

  • Apache AGE migration path — PR #3620 adds an offline tool to move an existing graph out of Apache AGE into plain PostgreSQL tables, giving AGE users a concrete exit route from the extension. Read it together with #3621, which now hard-refuses PGGraphStorage on Apache AGE ≥ 1.8.0 because that combination crashes the backend. If you're on 1.8+, run the migration before upgrading — otherwise startup fails rather than degrading.
  • Graph-first ingestion with deferred vector indexing — PR #3473 decouples entity/relation extraction from embedding: ingest the graph first, build vectors later. This is a real win for bulk loads and for pipelines that want to schedule index builds independently, but until indexing catches up, query results will be incomplete/stale — plan your refresh window accordingly.
  • Custom chunking is now explicit (and enforced) — PR #3665 introduces a dedicated selector for custom chunking; #3662 warns when another selector silently bypasses your chunker, closing a footgun where teams assumed their chunking strategy was active when it wasn't. Separately, #3663 and #3667 now reject negative token overlap and negative chunk overlap, so configs that以前 "worked" with a negative value will fail fast at startup or query time.
  • Security hardening and API exposure — Untrusted-document and write-path risks get a major pass: bounded per-document Markdown image downloads (GHSA-25c3-j78v-83qx, #3605) plus removal of quadratic Markdown image parsing (#3656), DOCX decompression limits and sidecar path containment (#3614), OOXML member/image budgets (#3619), bounded MinerU/Docling external result downloads (#3638), and attribute validation on manual entity/relation APIs (GHSA-c922-pw4m-4wcv, #3623) enforced across backends (#3624). If you ingest third-party files or expose the write APIs, treat this as a priority upgrade. PR #3672 also adds ENABLE_API_DOCS to control whether API docs are exposed — useful for internet-facing deployments; verify the default if you relied on docs being served.
  • Embedding and Ollama behavior changes — The EMBEDDING_DIM startup guard now covers all embedding bindings (#3646), and custom Ollama dimensions fail fast (#3636) while embedding_dim is actually forwarded to Ollama's embed API (#3604) — custom-dimension setups that previously misconfigured silently will now either work correctly or stop at startup. On the generation side, #3599 disables "thinking" for Ollama extract/keyword roles by default, so extraction output and cost/latency may shift until you re-enable it. #3670 widens the openai requirement to <4.0.0.
  • Data-integrity and backend reliability fixes — NetworkXStorage.get_node/get_edge now return copies (#3588), so code that mutated returned objects to "update" the graph will silently stop working — switch to the proper write APIs. Also: rebuild recomputes the most common entity type and normalizes keywords (#3589), the agtype quote-stripping that corrupted quote-bearing entity_ids is removed (#3587), self-loops survive entity rename (#3622) but are rejected at manual write paths (#3625), graph truncation is deterministic across backends (#3593), Milvus vector/id lookups are paged to respect the gRPC ceiling (#3629), and OpenAI streams/clients are closed on interrupted mid-COT generation (#3635). Expect small result diffs after upgrade.

No explicitly flagged breaking changes in this release.
