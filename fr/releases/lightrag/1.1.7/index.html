LightRAG v1.1.7

Highlights

  • Broader vector-storage options — Chroma now supports on-disk PersistentClient through local_path, eliminating the need for a separate Chroma server in local deployments (#772). MongoDB gains MongoVectorDBStorage backed by Atlas Vector Search, alongside async Motor-based KV, graph, and document-status implementations (#781); Atlas users should confirm vector-search availability and configure cosine_better_than_threshold.

  • Asynchronous ingestion changes API semantics — Text and file uploads are accepted into a background pipeline, with batch files processed concurrently (#791). A success response means accepted, not indexed, so poll document status before querying. Migration: replace /documents/batch with /documents/file_batch, stop expecting document_count in InsertResponse, and use the new /documents/texts endpoint for text arrays (#798).

  • Custom system prompts and token budgets — query()/aquery() now use system_prompt= instead of prompt= across all retrieval modes; existing custom-prompt calls must be updated (#806). Local retrieval now truncates entity context to a token budget, while MAX_TOKEN_TEXT_CHUNK, MAX_TOKEN_ENTITY_DESC, and MAX_TOKEN_RELATION_DESC configure chunk/entity/relation limits (#797), reducing oversized prompts but potentially changing retrieved context.

  • WebUI overhaul — The new interface adds an API tab, fixes component paths and invalid num_turns handling, renders Markdown, and surfaces streaming errors (#792, #800, #816). CORS and streaming headers were also improved for browser and proxy clients (#785); integrations or automation built around the previous UI should be revalidated.

  • Neo4j reliability fixes — Label validation and broader error handling are paired with a corrected get_edge() property shape, configurable timeouts, float timeout parsing, and a max_pool_size fix (#780, #812, #805, #820). Neo4j deployments should review pool/timeout configuration and test consumers that depend on edge-property formatting.

  • Tighter storage extension contracts — Storage base classes now enforce abstract methods and standardize document-status lookup through get_docs_by_status(); PostgreSQL, Oracle, and TiDB database connection modules are loaded dynamically when needed (#795, #833). Custom backends must implement the required interface, and mixed-storage deployments should run startup smoke tests.
