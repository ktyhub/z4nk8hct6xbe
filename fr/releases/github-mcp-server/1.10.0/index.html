github-mcp-serveur v1.10.0

Faits saillants

v1.10.0 est une version substantielle de sécurité, de fiabilité et de compatibilité pour le serveur MCP GitHub.

Plus sûr par défaut

  • Ajout de la suppression confirmée du référentiel avec élicitation de formulaire et état multi-aller-retour protégé (#3076).
  • Informations d'identification du porteur restreintes aux autorités GitHub configurées (#3056).
  • HTTPS appliqué pour les hôtes GitHub Enterprise (#3069).
  • La configuration statique --tools non valide a été fermée en cas d'échec (#3050).
  • Verrouillage renforcé, limites de requêtes, isolation du cache, traversée d'URL et nettoyage des réponses (#3109, #3112, #3113, #3111, #3108, #3114, #3110).

Meilleure compatibilité du serveur d'entreprise GitHub

  • list_issues et search_issues se dégradent désormais en toute sécurité lorsque les types GraphQL de champs personnalisés ne sont pas disponibles (#3086, #2897).
  • list_issues renvoie désormais les identifiants des personnes affectées et les tableaux vides stables pour les problèmes non attribués (#3064).
  • Les échecs de validation exposent les détails de l'ensemble de règles sécurisé lorsqu'ils sont fournis par le GitHub API (#3081).

Opérations plus sûres sur les fichiers du référentiel

  • get_file_contents identifie désormais les liens symboliques et étiquette clairement le contenu déréférencé.
  • Les écritures de liens symboliques nécessitent un opt-in explicite pour allow_symlink_write: true (#3071).
  • Correction des ressources MCP binaires étant codées deux fois en base64 (#3098).

Des contrats d'outils plus fiables

  • Modes d'entrée add_issue_comment corrigés (#3085).
  • issue_write.issue_fields[].delete: false est désormais un non-op valide pour les clients à schéma strict (#3077).
  • Les outils sans paramètre acceptent une propriété arguments omise tout en rejetant null explicite et JSON malformé (#3099).
  • Les outils d'abonnement aux notifications annoncent explicitement un comportement destructeur (#2936).
  • Les refus de demande d'examen du copilote renvoient désormais des conseils exploitables au lieu d'un simple 404 (#3119).

Projets, actions et efficacité

  • Ajout des opérations de cycle de vie de la vue Projet et de la configuration du champ visible (#2961, #2988).
  • Actions réduites et autres charges utiles de réponse réussie (#3047, #3055).
  • Performances de nettoyage améliorées et dépendances d'interface utilisateur/build actualisées (#3120, #3100).

Changements de comportement à noter

  • Les noms statiques inconnus de --tools empêchent désormais le démarrage.
  • Les mises à jour de liens symboliques nécessitent un consentement explicite.
  • Les requêtes ne peuvent pas assouplir le verrouillage imposé par le serveur.
  • Les corps de requêtes HTTP surdimensionnés sont rejetés prématurément.
  • add_issue_comment effectue une validation de mode mutuellement exclusive plus stricte.
  • La suppression du référentiel nécessite un MCP moderne éligible client, ​​une prise en charge de l'élicitation de formulaire et les étendues appropriées.

github-mcp-server v1.10.0

Highlights

v1.10.0 is a substantial security, reliability, and compatibility release for the GitHub MCP Server.

Safer by default

  • Added confirmed repository deletion with form elicitation and protected multi-round-trip state (#3076).
  • Restricted bearer credentials to configured GitHub authorities (#3056).
  • Enforced HTTPS for GitHub Enterprise hosts (#3069).
  • Made invalid static --tools configuration fail closed (#3050).
  • Hardened lockdown, request limits, cache isolation, URL traversal, and response sanitization (#3109, #3112, #3113, #3111, #3108, #3114, #3110).

Better GitHub Enterprise Server compatibility

  • list_issues and search_issues now degrade safely when issue custom-field GraphQL types are unavailable (#3086, #2897).
  • list_issues now returns assignee logins and stable empty arrays for unassigned issues (#3064).
  • Validation failures expose safe ruleset details when supplied by the GitHub API (#3081).

Safer repository file operations

  • get_file_contents now identifies symbolic links and clearly labels dereferenced content.
  • Symbolic-link writes require explicit allow_symlink_write: true opt-in (#3071).
  • Fixed binary MCP resources being base64-encoded twice (#3098).

More reliable tool contracts

  • Corrected add_issue_comment input modes (#3085).
  • issue_write.issue_fields[].delete: false is now a valid no-op for strict-schema clients (#3077).
  • Zero-parameter tools accept an omitted arguments property while rejecting explicit null and malformed JSON (#3099).
  • Notification subscription tools explicitly advertise destructive behavior (#2936).
  • Copilot review-request denials now return actionable guidance instead of a bare 404 (#3119).

Projects, Actions, and efficiency

  • Added Project view lifecycle operations and visible-field configuration (#2961, #2988).
  • Reduced Actions and other successful response payloads (#3047, #3055).
  • Improved sanitization performance and refreshed UI/build dependencies (#3120, #3100).

Behavior changes to note

  • Unknown static --tools names now prevent startup.
  • Symbolic-link updates require explicit opt-in.
  • Requests cannot relax server-enforced lockdown.
  • Oversized HTTP request bodies are rejected early.
  • add_issue_comment performs stricter mutually exclusive mode validation.
  • Repository deletion requires an eligible modern MCP client, form elicitation support, and the appropriate scopes.
