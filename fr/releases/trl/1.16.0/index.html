Trainium2, Qwen3-0.6B SFT, 20 étapes : **130 s avec la valeur par défaut contre 260 s sans**. * Ajouter un guide de formation sur AWS Trainium par @qgallouedec dans https://github.com/huggingface/trl/pull/7729 * `pad_to_multiple_of` par défaut à `"auto"` par @qgallouedec dans https://github.com/huggingface/trl/pull/7724 * Exécutez la tête LM fusionnée et les noyaux de distillation sur des appareils sans Triton par @qgallouedec dans https://github.com/huggingface/trl/pull/7669 * Signaler l'appareil Neuron en `trl env` et la télémétrie par @qgallouedec en https://github.com/huggingface/trl/pull/7672 * Prise en charge de n'importe quel accélérateur dans le déchargement d'activation par @qgallouedec dans https://github.com/huggingface/trl/pull/7670 ### 🌳 Attention aux arbres pour AsyncGRPO AsyncGRPO regroupe désormais chaque ligne de micro-lots sous la forme d'un **arbre de préfixes** au lieu d'une séquence plate. Les déploiements multi-tours et multi-générations répètent de nombreux préfixes : sur une invite partagée, ces jetons étaient transmis une fois par ligne. L'emballage des arbres les transmet une fois. ```text rollout 0: [ prompt ] [ completion A ] prompt ──┬── completion A ── later turn rollout 1: [ prompt ] [ completion B ] => └── completion B rollout 2: [ prompt ] [ completion A ] [ … ] ``` Les chaînes sans fourche s'effondrent en segments, et les requêtes de chaque segment s'occupent du K/V rassemblé le long de son chemin racine-segment dans un seul appel varlen FA3. Pas de tenseur de masque : chaque couche, à l'exception de l'attention, s'exécute une fois par jeton unique, et seul K/V est dupliqué selon des préfixes partagés. 🛠️ TRL now trains on AWS Trainium

<img width="1672" height="941" alt="Neon Warehouse_ AWS and Trainium Support" src="https://github.com/user-attachments/assets/dcb6e2a1-0f7c-4635-819b-a1ec6f5e143b" />

The fused LM head from v1.15 is what made Neuron tractable; the remaining gaps are closed here. There is a guide to go with it.

Neuron recompiles once per input shape, so an unpadded run stalls about a minute on every new sequence length. pad_to_multiple_of now defaults to "auto": 128 on Neuron, None elsewhere, so nothing changes on GPU. Trainium2, Qwen3-0.6B SFT, 20 steps: 130 s with the default against 260 s without.

🌳 Tree attention for AsyncGRPO

AsyncGRPO now packs every micro-batch row as a prefix tree instead of a flat sequence. Multi-turn and multi-generation rollouts repeat a lot of prefix: on a shared prompt, those tokens used to be forwarded once per row. Tree packing forwards them once.

rollout 0:  [ prompt ] [ completion A ]              prompt ──┬── completion A ── later turn
rollout 1:  [ prompt ] [ completion B ]        =>             └── completion B
rollout 2:  [ prompt ] [ completion A ] [ … ]

Chains without a fork collapse into segments, and each segment's queries attend to the K/V gathered along its root-to-segment path in a single FA3 varlen call. No mask tensor: every layer except attention runs once per unique token, and only K/V is duplicated along shared prefixes.

Qwen3-1.7B, 32K tokens per rollout, forward + backward:

| layout | packing ratio | sequence packing | tree packing | peak GiB | | --- | --- | --- | --- | --- | | shared prompt | 1.00 | 8677 ms | 8737 ms (0.99×) | 35.2 → 35.2 | | shared prompt | 2.29 | 8266 ms | 4341 ms (1.90×) | 35.2 → 18.0 | | shared prompt | 3.37 | 8179 ms | 2755 ms (2.97×) | 35.2 → 13.6 | | nested fork | 1.60 | 8557 ms | 6217 ms (1.38×) | 35.2 → 23.8 | | nested fork | 3.56 | 8172 ms | 2635 ms (3.10×) | 35.2 → 13.5 |

There is no packing option to choose: with nothing shared a tree row is exactly the old sequence packing, at a ~1% cost.

by @AmineDiro in https://github.com/huggingface/trl/pull/7328

Muse Spark Open

Support for meta-models/Muse-Spark-Open-816B-A42B: the tiny-model script, coverage in the VLM tests (SFT, DPO, KTO, chat-template utils, fused LM head), and a LoRA SFT example on 8 nodes of 8×H100 with DistributedConfig(fsdp_size=64, ep_size=8), token dispatch and packing. Measured at 14.2 s/step, 131k tokens/step, 40.2 GB per GPU.

Needs transformers>=5.20.0; the adapter save additionally needs transformers#49500 with peft 0.21.2.

by @qgallouedec in https://github.com/huggingface/trl/pull/7536
