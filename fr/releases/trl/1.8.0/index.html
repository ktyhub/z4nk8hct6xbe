Fonctionnalités

🎓 KTO est désormais un entraîneur stable

Après de nombreux cycles de travail d'alignement KTOTrainer ↔ DPOTrainer, KTO passe de trl.experimental.kto au package de niveau supérieur trl. Même API que DPO/GRPO/SFT — les importations passent du stade expérimental, les tests se déplacent vers l'arborescence de tests principale, les documents ne le signalent plus comme expérimental. La voie expérimentale fonctionne toujours et émet un FutureWarning (suppression dans v2.0.0).

# Before
from trl.experimental.kto import KTOConfig, KTOTrainer

# Now
from trl import KTOConfig, KTOTrainer

Selon notre télémétrie, KTO est le 4ème entraîneur le plus utilisé en TRL – cette remise des diplômes était attendue en retard. par @albertvillanova dans https://github.com/huggingface/trl/pull/6175, https://github.com/huggingface/trl/pull/6287 et https://github.com/huggingface/trl/pull/6345

Récompenses appartenant à l'environnement et prise en charge multi-environnements

Trois changements interdépendants rendent la formation RL agent avec des environnements considérablement plus ergonomiques. Récompense appartenant à l'environnement. Si votre environnement environment_factory définit une méthode get_reward() réservée (pas d'arguments → float), elle est appelée une fois par déploiement terminé et traitée comme une source de récompense. reward_funcs devient facultatif : plus de fuite d'état d'environnement vers les fonctions de récompense appartenant à l'entraîneur.

class WordleEnv:
    def reset(self, **kwargs):
        self._target = sample(words); self._solved = False

    def get_reward(self) -> float:       # optional, reserved (not a tool)
        return 1.0 if self._solved else 0.0

    def guess(self, word: str) -> str:   # exposed as a tool
        self._solved = word == self._target; ...

trainer = GRPOTrainer(
    model=model,
    train_dataset=dataset,
    environment_factory=WordleEnv,       # no reward_funcs needed
)

Prise en charge multi-environnements. environment_factory accepte désormais dict[str, factory] en plus d'un seul appelable. Chaque ligne de l'ensemble de données sélectionne son environnement via une colonne environment, et seuls les outils de cet environnement sont exposés dans l'invite de cette ligne — afin qu'une tâche de codage et un jeu puissent s'entraîner ensemble en une seule fois sans divulguer les schémas d'outils de chacun. L’utilisation d’un appel unique est inchangée. Le même câblage arrive dans GRPO, AsyncGRPO, DPPO et GRPO-with-replay-buffer. Récompense appartenant à l'environnement par @qgallouedec dans https://github.com/huggingface/trl/pull/6238; multi-env dans https://github.com/huggingface/trl/pull/6001 et https://github.com/huggingface/trl/pull/6002

Régularisation d'entropie pour GRPO

GRPOConfig prend désormais en charge la régularisation de l'entropie statique et adaptative (Skywork-OR1). Le bonus encourage l’exploration et aide à prévenir un effondrement prématuré des politiques.

GRPOConfig(
    entropy_coef=0.01,          # static
    # or:
    use_adaptive_entropy=True,  # adjust to target entropy
    entropy_target=1.5,
    entropy_coef_delta=0.01,
    entropy_coef_min=0.0,
    entropy_coef_max=0.1,
)

Le mode adaptatif ajuste le coefficient une fois par étape d'optimisation à partir de l'entropie agrégée par fenêtre (en fonction de l'accumulation de gradient) et persiste entropy_coef dans le point de contrôle pour la reprise. Non compatible avec le noyau Liger. par @albertvillanova dans https://github.com/huggingface/trl/pull/6140

Argument du formateur quantization_config (QLoRA simplifié)

QLoRA ne nécessite plus d'accéder à model_init_kwargs ou de précharger le modèle manuellement.

SFTTrainer(
    model="meta-llama/Llama-2-7b-hf",
    quantization_config=BitsAndBytesConfig(load_in_4bit=True),
    peft_config=LoraConfig(),
    train_dataset=dataset,
)

Ajouté aux SFTTrainer, DPOTrainer, GRPOTrainer, RLOOTrainer, RewardTrainer et KTOTrainer. Se trouve à côté de peft_config (l'autre ingrédient QLoRA non sérialisable), s'écoule dans from_pretrained et augmente s'il est également défini dans args.model_init_kwargs. Supprime également la ligne redondante get_kbit_device_map() – QLoRA s’entraîne de manière identique sans elle dans toutes les configurations testées. par @qgallouedec dans https://github.com/huggingface/trl/pull/6157 et https://github.com/huggingface/trl/pull/6276

La perte aux du MoE s'étend au DPO et au KTO

v1.7 a ajouté la perte auxiliaire d'équilibrage de charge du routeur à GRPOTrainer / RLOOTrainer / AsyncGRPOTrainer. Il figure désormais également sur DPOTrainer et KTOTrainer, de sorte que les modèles MoE post-formation avec données de préférence maintiennent l'équilibre des experts. par @qgallouedec dans https://github.com/huggingface/trl/pull/6208 et https://github.com/huggingface/trl/pull/6275

chunked_nll respectueux des neurones via un emballage de jetons de forme statique

Le chemin NLL fragmenté avait une indexation dépendante des données qui interrompait la compilation XLA/Neuron. Ce PR le retravaille pour regrouper les jetons valides au premier plan via un argsort stable sur le masque de validité, parcourir des morceaux entiers de ceil(n_valid / chunk_size) * chunk_size (un tenseur, pas de synchronisation Python-int) et utiliser ignore_index=-100 à l'intérieur de chaque morceau. Le comportement du GPU est inchangé ; Neuron fonctionne désormais également - même petite empreinte mémoire (~1.33 GiB par rapport à l'alternative naïve 5.94 GiB) sans recompilation par masque. par @michaelbenayoun dans https://github.com/huggingface/trl/pull/6314

Traitement par lots dynamique prenant en charge l'emballage dans AsyncGRPO

Le micro-batching AsyncGRPO devient sensible au packaging et limité aux jetons au-dessus du chemin sans remplissage de v1.7 :

  • Σ Lᵢ² équilibrage des lignes — une affectation gourmande la plus longue en premier donne à chaque ligne DP le même Σ Lᵢ² au lieu du même nombre de jetons (l'attention est O(L²), FFN est O(L), donc un nombre de jetons égal n'égalise pas l'horloge murale). Les retardataires de tous les rangs disparaissent ; +19% MFU à 4B dans l'indice de référence.
  • Token-budget packaging (opt-in) – limitez chaque ligne à des jetons token_budget avec un nombre d'échantillons variable, dissociant ainsi la mémoire maximale de per_device_train_batch_size. Utile dans les régimes limités en mémoire (pas de points de contrôle de gradient, contexte long, très grands modèles). Les deux utilisent l’accumulation de gradient existante de HF Trainer – pas de chirurgie en boucle d’entraînement, les collectifs FSDP/EP restent en phase. par @AmineDiro dans https://github.com/huggingface/trl/pull/6092

trl v1.8.0

Features

🎓 KTO is now a stable trainer

After many cycles of KTOTrainer ↔ DPOTrainer alignment work, KTO graduates from trl.experimental.kto to the top-level trl package. Same API as DPO/GRPO/SFT — imports move from experimental, tests move to the main test tree, docs no longer flag it as experimental. The experimental path still works and emits a FutureWarning (removal in v2.0.0).

# Before
from trl.experimental.kto import KTOConfig, KTOTrainer

# Now
from trl import KTOConfig, KTOTrainer

Per our telemetry, KTO is the 4th most used trainer in TRL — this graduation was overdue.

by @albertvillanova in https://github.com/huggingface/trl/pull/6175, https://github.com/huggingface/trl/pull/6287 and https://github.com/huggingface/trl/pull/6345

Environment-owned rewards & multi-environment support

Three interrelated changes make agentic RL training with environments substantially more ergonomic.

Environment-owned reward. If your environment_factory env defines a reserved get_reward() method (no args → float), it's called once per completed rollout and treated as a reward source. reward_funcs becomes optional — no more leaking env state back out to trainer-owned reward funcs.

class WordleEnv:
    def reset(self, **kwargs):
        self._target = sample(words); self._solved = False

    def get_reward(self) -> float:       # optional, reserved (not a tool)
        return 1.0 if self._solved else 0.0

    def guess(self, word: str) -> str:   # exposed as a tool
        self._solved = word == self._target; ...

trainer = GRPOTrainer(
    model=model,
    train_dataset=dataset,
    environment_factory=WordleEnv,       # no reward_funcs needed
)

Multi-environment support. environment_factory now accepts dict[str, factory] in addition to a single callable. Each dataset row selects its environment via an environment column, and only that env's tools are exposed in that row's prompt — so a coding task and a game can train together in one run without leaking each other's tool schemas. Single-callable usage is unchanged.

Same wiring lands in GRPO, AsyncGRPO, DPPO, and GRPO-with-replay-buffer.

Env-owned reward by @qgallouedec in https://github.com/huggingface/trl/pull/6238; multi-env in https://github.com/huggingface/trl/pull/6001 and https://github.com/huggingface/trl/pull/6002

Entropy regularization for GRPO

GRPOConfig now supports both static and adaptive entropy regularization (Skywork-OR1). The bonus encourages exploration and helps prevent premature policy collapse.

GRPOConfig(
    entropy_coef=0.01,          # static
    # or:
    use_adaptive_entropy=True,  # adjust to target entropy
    entropy_target=1.5,
    entropy_coef_delta=0.01,
    entropy_coef_min=0.0,
    entropy_coef_max=0.1,
)

Adaptive mode adjusts the coefficient once per optimizer step from window-aggregated entropy (gradient accumulation-aware) and persists entropy_coef in the checkpoint for resume. Not compatible with the Liger kernel.

by @albertvillanova in https://github.com/huggingface/trl/pull/6140

quantization_config trainer argument (streamlined QLoRA)

QLoRA no longer requires reaching into model_init_kwargs or pre-loading the model manually.

SFTTrainer(
    model="meta-llama/Llama-2-7b-hf",
    quantization_config=BitsAndBytesConfig(load_in_4bit=True),
    peft_config=LoraConfig(),
    train_dataset=dataset,
)

Added to SFTTrainer, DPOTrainer, GRPOTrainer, RLOOTrainer, RewardTrainer, and KTOTrainer. Sits next to peft_config (the other non-serializable QLoRA ingredient), flows into from_pretrained, and raises if also set in args.model_init_kwargs. Also drops the redundant get_kbit_device_map() line — QLoRA trains identically without it across all tested configurations.

by @qgallouedec in https://github.com/huggingface/trl/pull/6157 and https://github.com/huggingface/trl/pull/6276

MoE aux loss extends to DPO and KTO

v1.7 added the router load-balancing auxiliary loss to GRPOTrainer / RLOOTrainer / AsyncGRPOTrainer. It's now on DPOTrainer and KTOTrainer too, so post-training MoE models with preference data keeps experts balanced.

by @qgallouedec in https://github.com/huggingface/trl/pull/6208 and https://github.com/huggingface/trl/pull/6275

Neuron-friendly chunked_nll via static-shape token packing

The chunked NLL path had data-dependent indexing that broke XLA/Neuron compilation. This PR reworks it to pack valid tokens to the front via a stable argsort on the validity mask, iterate over ceil(n_valid / chunk_size) * chunk_size whole chunks (a tensor, no Python-int sync), and use ignore_index=-100 inside each chunk. GPU behavior is unchanged; Neuron now works too — same tiny memory footprint (~1.33 GiB vs the naive 5.94 GiB alternative) with no per-mask recompilation.

by @michaelbenayoun in https://github.com/huggingface/trl/pull/6314

Packing-aware dynamic batching in AsyncGRPO

AsyncGRPO micro-batching becomes packing-aware and token-bounded on top of the padding-free path from v1.7:

  • Σ Lᵢ² row balancing — a greedy longest-first assignment gives every DP row the same Σ Lᵢ² instead of the same token count (attention is O(L²), FFN is O(L), so equal token counts don't equalize wall-clock). Cross-rank stragglers vanish; +19% MFU at 4B in the benchmark.
  • Token-budget packing (opt-in) — cap each row at token_budget tokens with a variable sample count, decoupling peak memory from per_device_train_batch_size. Useful in memory-bound regimes (no gradient checkpointing, long context, very large models).

Both ride HF Trainer's existing gradient accumulation — no training-loop surgery, FSDP/EP collectives stay in lockstep.
