trl v1.7.0

Fonctionnalités

SFT par défaut, loss_type est désormais "chunked_nll"

Le flip annoncé dans v1.6 a atterri. Le réglage de loss_type est facultatif, et la valeur par défaut est désormais "chunked_nll", ce qui donne à chaque exécution de SFTTrainer ~ 30 % de VRAM de pointe en moins en moyenne (jusqu'à ~ 50 % sur les modèles à grand vocabulaire) avec un temps d'horloge mural neutre ou légèrement plus rapide. Aucune action nécessaire. La résolution automatique revient à "nll" lorsque use_liger_kernel=True (les deux chemins sont incompatibles). Si vous voulez l'ancien comportement - par ex. pour les têtes personnalisées, épinglez-le explicitement :

SFTConfig(loss_type="nll")

par @qgallouedec dans https://github.com/huggingface/trl/pull/5846

Perte auxiliaire MoE dans GRPO / RLOO / AsyncGRPO

Les modèles MoE post-formation incluent désormais correctement la perte auxiliaire d'équilibrage de charge du routeur, correspondant à la propre référence du modèle et à SFTTrainer. Activer via model_init_kwargs :

GRPOConfig(
    ...,
    model_init_kwargs={"output_router_logits": True, "router_aux_loss_coef": 0.001},
)

Sondé via _get_per_token_logps_and_entropies (renvoie désormais un 3-tuple incluant aux_loss), intégré à la perte de politique avec une mise à l'échelle de cumul de diplômes adaptée à chaque entraîneur et enregistré sous aux_loss. AsyncGRPO le recalcule via load_balancing_loss_func dans le chemin fragmenté de la tête LM (identique au chemin fragmenté de SFT). par @AmineDiro dans https://github.com/huggingface/trl/pull/6083, plus câblage de configuration router_aux_loss_coef par @qgallouedec dans https://github.com/huggingface/trl/pull/6085

Nouvel entraîneur expérimental GMPO

[Optimisation de la politique géométrique-moyenne] (https://huggingface.co/papers/2507.20673) débarque en tant que formateur expérimental. Remplace la moyenne arithmétique des rapports d'importance par jeton de GRPO par une moyenne géométrique au niveau de la séquence (moyenne des rapports logarithmiques clipped, puis exp) ; clipping est unilatéral par signe d'avantage et appliqué dans l'espace du journal. epsilon=0.4 par défaut selon le document.

from trl.experimental.gmpo import GMPOConfig, GMPOTrainer

trainer = GMPOTrainer(
    model="Qwen/Qwen3-4B",
    args=GMPOConfig(epsilon=0.4),
    reward_funcs=accuracy_reward,
    train_dataset=dataset,
)

par @raghulchandramouli dans https://github.com/huggingface/trl/pull/6078

Transformateurs batching continu en GRPO / RLOO

use_transformers_paged était obsolète dans v1.4 ; il est maintenant remplacé par un [traitement continu des transformateurs] approprié (https://huggingface.co/docs/transformers/main/en/main_classes/text_generation#transformers.GenerationMixin.generate_batch). L'ancienne branche contournait silencieusement la correction de l'échantillonnage par importance (logprobs = None) ; le nouveau chemin capture les logprobs de output.logprobs et expose un ContinuousBatchingConfig pour le réglage du cache KV.

GRPOConfig(
    ...,
    use_transformers_continuous_batching=True,
    transformers_continuous_batching_config={
        "use_cuda_graph": False,
        "max_memory_percent": 0.4,  # leave headroom for training
    },
)

Benchmark (Llama-3.2-1B-Instruct, A100 80 Go, GSM8K) : 1.25× plus rapide à N=64 générations avec -16 Go de VRAM maximale par rapport au generate() par défaut. À utiliser lorsque N ≥ 32 avec des longueurs de complétion variables. use_transformers_paged=True fonctionne toujours et transmet le nouveau drapeau avec un FutureWarning. Nécessite transformers>=5.8.0. par @sergiopaniego dans https://github.com/huggingface/trl/pull/5765

AsyncGRPO : synchronisation native du poids avec vLLM ≥ 0.22.0

WeightTransferClient pilote désormais le transfert de poids RL 4 phases API natif de vLLM au lieu de l'ancien flux à 2 appels : pause(mode="keep") → start_weight_update → threadé update_weights + diffusion NCCL → finish_weight_update → resume. Validé de bout en bout sur H100 sur un seul nœud, FSDP2×4 + TP=4 et FSDP2×4 + DP=2×TP=4 à 2 nœuds (temps de synchronisation du poids ≈ 0.18-0.8 s). par @AmineDiro dans https://github.com/huggingface/trl/pull/5892

Formation sans remplissage dans AsyncGRPO

AsyncGRPO prend désormais en charge le même chemin sans remplissage que SFT avait déjà. Aplatit le lot et utilise les limites de document basées sur position_ids au lieu d'un remplissage à droite jusqu'à la séquence la plus longue – une accélération significative et des économies de mémoire sur les charges de travail de longueur hétérogène. par @qgallouedec dans https://github.com/huggingface/trl/pull/5854

Intégration du port expérimental

Un nouvel adaptateur trl.experimental.harbor connecte les suites de tâches agents Harbor au GRPOTrainer via environment_factory. Même modèle que l'intégration OpenReward : une seule spécification connecte les trois emplacements d'entraîneur :

from trl import GRPOConfig, GRPOTrainer
from trl.experimental.harbor import HarborSpec

spec = HarborSpec("AdithyaSK/data_agent_rl_environment_train", agent="bash", num_tasks=64)

trainer = GRPOTrainer(
    model="Qwen/Qwen3-4B",
    args=GRPOConfig(num_generations=8, max_steps=50, max_tool_calling_iterations=25),
    train_dataset=spec.train_dataset,
    environment_factory=spec.environment_factory,
    reward_funcs=spec.reward_funcs,
)

Faisceau bash intégré, plus exemples de faisceaux jupyter et terminal_notes. Gated par le nouveau supplément trl[harbor]. par @adithya-s-k dans https://github.com/huggingface/trl/pull/6018

trust_remote_code dans les configurations d'entraînement

Un seul champ trust_remote_code: bool = False sur les configurations du formateur couvre désormais toute la surface de chargement (modèle, processeur/tokenizer, modèle de référence, modèle de récompense, tokenizer de récompense, enseignant) au lieu d'obliger les utilisateurs à le faire passer par plusieurs dicts kwarg indépendants.

SFTConfig(trust_remote_code=True)

ModelConfig.trust_remote_code est supprimé pour éviter la duplication de --trust_remote_code lors de la combinaison de classes de données ; Le comportement du CLI est inchangé. par @qgallouedec dans https://github.com/huggingface/trl/pull/5802

Refactor SFT : créer des étiquettes pendant la préparation de l'ensemble de données

La construction d'étiquettes sort de l'assembleur et passe à la préparation des ensembles de données, de sorte que « ce qui peut être entraîné » est défini exactement à un seul endroit. Un seul lot map produit une colonne labels dans laquelle chaque jeton conserve son ID lorsque chaque masque applicable est 1, sinon -100. Plain LM reste neutre en termes de stockage ; Les ensembles de données pré-tokenisés avec des colonnes de masque suivent désormais le même chemin. Étape 1 vers la correction du numéro 3927. par @0xadvait dans https://github.com/huggingface/trl/pull/6037

trl v1.7.0

Features

SFT default loss_type is now "chunked_nll"

The flip announced in v1.6 has landed. Setting loss_type is optional, and the default now resolves to "chunked_nll" — giving every SFTTrainer run ~30% less peak VRAM on average (up to ~50% on large-vocab models) with wall-clock time neutral or slightly faster. No action needed.

The auto-resolve falls back to "nll" when use_liger_kernel=True (the two paths are incompatible). If you want the old behavior — e.g. for custom heads — pin it explicitly:

SFTConfig(loss_type="nll")

by @qgallouedec in https://github.com/huggingface/trl/pull/5846

MoE auxiliary loss in GRPO / RLOO / AsyncGRPO

Post-training MoE models now correctly include the router load-balancing auxiliary loss, matching the model's own reference forward and SFTTrainer. Enable via model_init_kwargs:

GRPOConfig(
    ...,
    model_init_kwargs={"output_router_logits": True, "router_aux_loss_coef": 0.001},
)

Plumbed through _get_per_token_logps_and_entropies (now returns a 3-tuple including aux_loss), folded into the policy loss with grad-accum scaling matched per trainer, and logged as aux_loss. AsyncGRPO recomputes it via load_balancing_loss_func in the chunked LM-head path (same as SFT's chunked path).

by @AmineDiro in https://github.com/huggingface/trl/pull/6083, plus router_aux_loss_coef config wiring by @qgallouedec in https://github.com/huggingface/trl/pull/6085

New experimental GMPO trainer

Geometric-Mean Policy Optimization lands as an experimental trainer. Replaces GRPO's per-token arithmetic mean of importance ratios with a sequence-level geometric mean (mean of clipped log-ratios, then exp); clipping is one-sided by advantage sign and applied in log space. Default epsilon=0.4 per the paper.

from trl.experimental.gmpo import GMPOConfig, GMPOTrainer

trainer = GMPOTrainer(
    model="Qwen/Qwen3-4B",
    args=GMPOConfig(epsilon=0.4),
    reward_funcs=accuracy_reward,
    train_dataset=dataset,
)

by @raghulchandramouli in https://github.com/huggingface/trl/pull/6078

Transformers continuous batching in GRPO / RLOO

use_transformers_paged was deprecated in v1.4; it's now replaced with proper transformers continuous batching. The old branch silently bypassed importance-sampling correction (logprobs = None); the new path captures logprobs from output.logprobs and exposes a ContinuousBatchingConfig for KV-cache tuning.

GRPOConfig(
    ...,
    use_transformers_continuous_batching=True,
    transformers_continuous_batching_config={
        "use_cuda_graph": False,
        "max_memory_percent": 0.4,  # leave headroom for training
    },
)

Benchmark (Llama-3.2-1B-Instruct, A100 80GB, GSM8K): 1.25× faster at N=64 generations with -16 GB peak VRAM vs default generate(). Use when N ≥ 32 with variable completion lengths.

use_transformers_paged=True still works and forwards to the new flag with a FutureWarning. Requires transformers>=5.8.0.

by @sergiopaniego in https://github.com/huggingface/trl/pull/5765

AsyncGRPO: native weight sync with vLLM ≥ 0.22.0

WeightTransferClient now drives vLLM's native 4-phase RL weight-transfer API instead of the older 2-call flow: pause(mode="keep") → start_weight_update → threaded update_weights + NCCL broadcast → finish_weight_update → resume. Validated end-to-end on H100 across single-node, FSDP2×4 + TP=4, and 2-node FSDP2×4 + DP=2×TP=4 (weight-sync time ≈ 0.18-0.8 s).

by @AmineDiro in https://github.com/huggingface/trl/pull/5892

Padding-free training in AsyncGRPO

AsyncGRPO now supports the same padding-free path SFT already had. Flattens the batch and uses position_ids-based document boundaries instead of right-padding to the longest sequence — meaningful speedup and memory savings on heterogeneous-length workloads.

by @qgallouedec in https://github.com/huggingface/trl/pull/5854

Experimental Harbor integration

A new trl.experimental.harbor adapter plugs Harbor agentic task suites into GRPOTrainer via environment_factory. Same pattern as the OpenReward integration — one spec wires all three trainer slots:

from trl import GRPOConfig, GRPOTrainer
from trl.experimental.harbor import HarborSpec

spec = HarborSpec("AdithyaSK/data_agent_rl_environment_train", agent="bash", num_tasks=64)

trainer = GRPOTrainer(
    model="Qwen/Qwen3-4B",
    args=GRPOConfig(num_generations=8, max_steps=50, max_tool_calling_iterations=25),
    train_dataset=spec.train_dataset,
    environment_factory=spec.environment_factory,
    reward_funcs=spec.reward_funcs,
)

Built-in bash harness, plus jupyter and terminal_notes example harnesses. Gated by the new trl[harbor] extra.

by @adithya-s-k in https://github.com/huggingface/trl/pull/6018

trust_remote_code in trainer configs

A single trust_remote_code: bool = False field on the trainer configs now covers the whole load surface — model, processor / tokenizer, reference model, reward model, reward tokenizer, teacher — instead of forcing users to thread it through several independent kwarg dicts.

SFTConfig(trust_remote_code=True)

ModelConfig.trust_remote_code is removed to avoid duplicate --trust_remote_code when combining dataclasses; CLI behavior is unchanged.

by @qgallouedec in https://github.com/huggingface/trl/pull/5802

KTO ↔ DPO alignment: tests, evaluate, sync_ref_model

The last alignment cycle before graduation: KTO now has parity with DPO on pad_to_multiple_of, sync_ref_model, evaluate(), method order/signature, metric placement (all moved into _compute_loss), and a real text + VLM (including multi-image) test suite.
