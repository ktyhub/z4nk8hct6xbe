🎓 DistillationTrainer est désormais un entraîneur stable

Après un refactor d'environ 30 PR qui a remodelé son contrat de données, son chemin de perte, sa pile de génération, sa surface de configuration et ses tests, DistillationTrainer et DistillationConfig passent de trl.experimental.distillation au package de niveau supérieur trl. Même surface d’import que SFT / DPO / GRPO / KTO. L'ancienne voie expérimentale fonctionne toujours et émet un FutureWarning (suppression dans v2.0.0).

# Before
from trl.experimental.distillation import DistillationConfig, DistillationTrainer

# Now
from trl import DistillationConfig, DistillationTrainer

Débarque également un trl distillation CLI et déplace les tests vers tests/. L'arc de refactorisation complet : passage des colonnes de signature à prompt (format messages obsolète), épinglage de la pile de génération aux GRPO, câblage de la perte JSD fragmentée et suppression du chemin logit complet, nettoyage du chemin Liger pour partager l'extraction avec le chemin fragmenté, adoption du timing log() / training_step / _save_checkpoint de GRPO, reconstruction de la suite de tests à la forme GRPO, et bien plus encore. par @qgallouedec sur ~30 PR (#6479, #6480, #6481, #6482, #6484, #6487, #6497, #6508, #6509, #6510, #6511, #6512, #6513, #6521, #6522, #6523, #6524, #6525, #6526, #6530, #6537, #6604, #6605, #6606, #6607, #6609, #6610, #6611, #6612, #6613, #6614, #6629, #6630, #6632, #6633, #6634, #6639, #6640, #6641, #6642, #6643, #6644, #6645, #6647, #6653).

AsyncGRPO : formation des agents propriétaires de boucles (faisceau OpenEnv)

Nouveau chemin expérimental propriétaire de boucle (boîte noire) pour AsyncGRPOTrainer — pour former des agents externes comme opencode qui exécutent leur propre boucle d'outils, plutôt que TRL conduisant à chaque tour comme dans le chemin de boîte blanche environment_factory. L'agent s'exécute dans une session OpenEnv en mode transparent_proxy ; un proxy dans le bac à sable capture les identifiants de jeton et les logprobs de chaque tour. Une fois terminé, TRL lit la trace, reconstruit les lignes d'entraînement par tour et note l'espace de travail avec le verify() de la session. Livré avec trois hooks de stratégie fournis par l'appelant (rollout_reward_fn, train_turn_fn, agent_turn_fn) afin que vous puissiez supprimer les appels aux framework (générateur de titres, résumé de contexte) et renforcer uniquement les tours que vous souhaitez. Comprend un examples/scripts/openenv/opencode.py autonome (bac à sable de sous-processus local + vérificateur stdin/stdout DeepCoder), validé de bout en bout sur Qwen3-4B. par @AmineDiro dans https://github.com/huggingface/trl/pull/6420, plus variante HF-sandbox par @sergiopaniego dans https://github.com/huggingface/trl/pull/6565

Exemple SFT de diffusion par bloc DiffusionGemma

Un nouvel exemple SFT pour google/diffusiongemma-26B-A4B-it implémentant la recette de référence : un bloc de réponse par étape, corruption aléatoire uniforme des jetons avec t ~ U(eps, 1), autoconditionnement en deux passes, entropie croisée plate sur tout le canevas plus une co-perte autorégressive sur l'encodeur. LoRA cible l'attention + les linéaires MLP denses. Nécessite transformers >= 5.12.0. Livré avec les modèles de discussion diffusion_gemma.jinja / diffusion_gemma_training.jinja (avec marqueurs {% generation %}) afin que assistant_only_loss=True fonctionne immédiatement. par @kashif dans https://github.com/huggingface/trl/pull/6003

trl v1.10.0

Features

🎓 DistillationTrainer is now a stable trainer

After a ~30-PR refactor that reshaped its data contract, loss path, generation stack, config surface, and tests, DistillationTrainer and DistillationConfig graduate from trl.experimental.distillation to the top-level trl package. Same import surface as SFT / DPO / GRPO / KTO. The old experimental path still works and emits a FutureWarning (removal in v2.0.0).

# Before
from trl.experimental.distillation import DistillationConfig, DistillationTrainer

# Now
from trl import DistillationConfig, DistillationTrainer

Also lands a trl distillation CLI and moves the tests to tests/. The full refactor arc: switched signature columns to prompt (deprecated messages-format), pinned the generation stack to GRPO's, wired the chunked JSD loss and deleted the full-logit path, cleaned the Liger path to share extraction with the chunked path, adopted GRPO's log() / training_step timing / _save_checkpoint, rebuilt the test suite to GRPO shape, and much more.

by @qgallouedec across ~30 PRs (#6479, #6480, #6481, #6482, #6484, #6487, #6497, #6508, #6509, #6510, #6511, #6512, #6513, #6521, #6522, #6523, #6524, #6525, #6526, #6530, #6537, #6604, #6605, #6606, #6607, #6609, #6610, #6611, #6612, #6613, #6614, #6629, #6630, #6632, #6633, #6634, #6639, #6640, #6641, #6642, #6643, #6644, #6645, #6647, #6653).

AsyncGRPO: loop-owning agent training (OpenEnv harness)

New experimental loop-owning (black-box) path for AsyncGRPOTrainer — for training external agents like opencode that run their own tool loop, rather than TRL driving each turn as in the environment_factory white-box path.

The agent runs in an OpenEnv session in transparent_proxy mode; an in-sandbox proxy captures each turn's token ids and logprobs. On completion, TRL reads the trace, rebuilds per-turn training rows, and scores the workspace with the session's verify(). Ships with three caller-supplied policy hooks (rollout_reward_fn, train_turn_fn, agent_turn_fn) so you can drop framework aux calls (title generator, context summarizer) and reinforce only the turns you want.

Includes a self-contained examples/scripts/openenv/opencode.py (local subprocess sandbox + DeepCoder held-out stdin/stdout verifier), validated end-to-end on Qwen3-4B.

by @AmineDiro in https://github.com/huggingface/trl/pull/6420, plus HF-sandbox variant by @sergiopaniego in https://github.com/huggingface/trl/pull/6565

DiffusionGemma block-diffusion SFT example

A new SFT example for google/diffusiongemma-26B-A4B-it implementing the reference recipe: one response block per step, uniform random token corruption with t ~ U(eps, 1), two-pass self-conditioning, flat cross-entropy over the whole canvas plus an autoregressive co-loss on the encoder. LoRA targets attention + dense MLP linears. Requires transformers >= 5.12.0.

Ships with diffusion_gemma.jinja / diffusion_gemma_training.jinja chat templates (with {% generation %} markers) so assistant_only_loss=True works out of the box.
