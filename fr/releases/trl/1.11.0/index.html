trl v1.11.0

Fonctionnalités

Utilisez le propre serveur de vLLM au lieu de celui de TRL

trl vllm-serve exécutait une application FastAPI personnalisée autour du LLM de vLLM, avec sa propre diffusion parallèle aux données et une extension de travail pour la synchronisation du poids. Le propre serveur de vLLM couvre tout cela. Le serveur personnalisé a disparu : trl/scripts/vllm_serve.py passe de 1 218 à ~130 lignes et traduit désormais ses indicateurs en vllm serve, imprime la commande équivalente, transmet tout argument supplémentaire et définit les trois paramètres dont TRL a besoin (--weight-transfer-config, --logprobs-mode processed_logprobs, --max-logprobs -1). fastapi, uvicorn et pydantic laissent le vllm supplémentaire. La synchronisation du poids utilise désormais le moteur de transfert de poids NCCL de vLLM : les tenseurs sont annoncés une fois et diffusés en une seule diffusion groupée, au lieu d'une requête HTTP + diffusion par tenseur. Les logprobs du professeur de distillation proviennent de prompt_logprobs. Benchmark (mode serveur GRPO sur H100, Qwen2.5-1.5B / Qwen2.5-VL-3B, même graine, mêmes données) : | Configuration | avant | après | accélération | | --- | --- | --- | --- | | Texte, TP=1 | 1.08, 0.91 s/étape | 0.63, 0.62 s/étape | 1.59× | | Texte, TP=2 | 0.96, 0.96 s/étape | 0.62, 0.60 s/étape | 1.57× | | VLM, TP=1 | 2.14, 2.13 s/étape | 1.48, 1.48 s/étape | 1.44× | Complétions identiques en bits par rapport à l'ancien serveur (16/16 sur 4 invites × n = 4, logprobs identiques à 0.0 sur 499 jetons). trl vllm-serve accepte toujours les mêmes indicateurs – il se contente maintenant de transmettre à vllm serve. par @qgallouedec dans https://github.com/huggingface/trl/pull/6765

Nouveau AsyncDistillationTrainer expérimental (+ MOPD multi-enseignant)

Distillation asynchrone selon la politique, architecturée comme AsyncGRPOTrainer : un agent de déploiement en arrière-plan génère les propres achèvements de l'étudiant et les note par rapport à un enseignant servi via HTTP, de sorte que la génération et la formation se chevauchent au lieu d'alterner. L'enseignant n'est jamais chargé localement, juste une URL de serveur vLLM. Prend également en charge MOPD (distillation multi-enseignants sur politique) : transmettez plus d'une entrée dans teacher_server_urls et acheminez chaque échantillon vers un enseignant via une colonne teacher_id (par exemple, un professeur de mathématiques et un professeur de code, chacun servi indépendamment).

from trl.experimental.async_distillation import AsyncDistillationConfig, AsyncDistillationTrainer

trainer = AsyncDistillationTrainer(
    model="Qwen/Qwen3-4B",
    args=AsyncDistillationConfig(
        teacher_server_urls=["http://teacher-math:8000", "http://teacher-code:8000"],
        teacher_top_k=16,
    ),
    train_dataset=dataset,  # rows carry a `teacher_id` column for MOPD
)
trainer.train()

par @kashif dans https://github.com/huggingface/trl/pull/6705

Exemples réorganisés en dossiers par exemple

examples/ était divisé par format (scripts/ vs notebooks/), qui dispersait les fichiers associés (par exemple, sft_nemotron_3 existait à la fois en tant que script et bloc-notes, dans des dossiers différents ; les blocs-notes OpenEnv vivaient séparément des scripts OpenEnv). Tout est maintenant un dossier par histoire — le nom indique la méthode et la tâche (grpo_wordle, sft_gpt_oss, ppo_tldr), et le dossier contient tous les fichiers dont l'exemple a besoin (scripts, blocs-notes, invites, modèles de discussion, code d'évaluation). Les scripts de démonstration légers pour un seul entraîneur sont supprimés (ils se trouvent dans trl/scripts/ et chaque page de documentation de l'entraîneur contient un extrait exécutable). Les anciens liens examples/scripts/… et examples/notebooks/… GitHub / Colab seront 404 – méritent d'être signalés dans les publications en aval. par @qgallouedec dans https://github.com/huggingface/trl/pull/6820

trl v1.11.0

Features

Use vLLM's own server instead of TRL's

trl vllm-serve used to run a custom FastAPI app around vLLM's LLM, with its own data-parallel fan-out and a worker extension for weight sync. vLLM's own server covers all of that. The custom server is gone: trl/scripts/vllm_serve.py drops from 1218 to ~130 lines and now translates its flags into vllm serve, prints the equivalent command, forwards any extra argument, and sets the three settings TRL needs (--weight-transfer-config, --logprobs-mode processed_logprobs, --max-logprobs -1). fastapi, uvicorn and pydantic leave the vllm extra.

Weight sync now uses vLLM's NCCL weight-transfer engine — tensors are announced once and streamed in a single packed broadcast, instead of one HTTP request + broadcast per tensor. Distillation teacher logprobs come from prompt_logprobs.

Benchmark (GRPO server-mode on H100, Qwen2.5-1.5B / Qwen2.5-VL-3B, same seed, same data):

| Setup | before | after | speedup | | --- | --- | --- | --- | | Text, TP=1 | 1.08, 0.91 s/step | 0.63, 0.62 s/step | 1.59× | | Text, TP=2 | 0.96, 0.96 s/step | 0.62, 0.60 s/step | 1.57× | | VLM, TP=1 | 2.14, 2.13 s/step | 1.48, 1.48 s/step | 1.44× |

Bit-identical completions vs the old server (16/16 over 4 prompts × n=4, logprobs identical to 0.0 over 499 tokens). trl vllm-serve still accepts the same flags — it just forwards to vllm serve now.

by @qgallouedec in https://github.com/huggingface/trl/pull/6765

New experimental AsyncDistillationTrainer (+ multi-teacher MOPD)

Async on-policy distillation, architected like AsyncGRPOTrainer: a background rollout worker generates the student's own completions and scores them against a teacher served over HTTP, so generation and training overlap instead of alternating. The teacher is never loaded locally — just a vLLM server URL.

Also supports MOPD (multi-teacher on-policy distillation): pass more than one entry in teacher_server_urls and route each sample to a teacher via a teacher_id column (e.g. a math teacher and a code teacher, each served independently).

from trl.experimental.async_distillation import AsyncDistillationConfig, AsyncDistillationTrainer

trainer = AsyncDistillationTrainer(
    model="Qwen/Qwen3-4B",
    args=AsyncDistillationConfig(
        teacher_server_urls=["http://teacher-math:8000", "http://teacher-code:8000"],
        teacher_top_k=16,
    ),
    train_dataset=dataset,  # rows carry a `teacher_id` column for MOPD
)
trainer.train()

by @kashif in https://github.com/huggingface/trl/pull/6705

Examples reorganized into per-example folders

examples/ was split by format (scripts/ vs notebooks/), which scattered related files (e.g. sft_nemotron_3 existed as both a script and a notebook, in different folders; OpenEnv notebooks lived apart from OpenEnv scripts). Everything is now one folder per story — the name says the method and the task (grpo_wordle, sft_gpt_oss, ppo_tldr), and the folder holds every file the example needs (scripts, notebooks, prompts, chat templates, eval code). Thin single-trainer demo scripts are removed (they live in trl/scripts/ and each trainer doc page has a runnable snippet). Old examples/scripts/… and examples/notebooks/… GitHub / Colab links will 404 — worth flagging in downstream posts.

by @qgallouedec in https://github.com/huggingface/trl/pull/6820
