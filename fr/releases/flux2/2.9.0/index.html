flux2 v2.9.0

Faits saillants

Flux v2.9.0 est une version fonctionnelle. Les utilisateurs sont encouragés à effectuer une mise à niveau pour la meilleure expérience. Pour un aperçu détaillé des nouvelles fonctionnalités et des modifications du API incluses dans cette version, veuillez vous référer au [article de blog Announcing Flux 2.9 GA] (https://fluxcd.io/blog/2026/06/flux-v2.9.0/). Aperçu des nouvelles fonctionnalités :

  • Système de plugins Flux CLI avec les plugins Mirror et Schema (flux plugin)
  • Le champ Appliquer côté serveur ignore les règles pour un contrôle de dérive précis (Kustomization)
  • Décryptage SOPS avec le chiffrement post-quantique Age (Kustomization)
  • Authentification Workload Identity Kubernetes pour OpenBao et Vault (Kustomization)
  • Stratégies post-rendu Helm, y compris la prise en charge des crochets de graphique (HelmRelease)
  • Mode littéral pour les références de valeurs Helm reflétant helm --set-literal (HelmRelease)
  • Autoriser les types vides dans les expressions de contrôle de santé CEL (Kustomization, HelmRelease)
  • Signature et vérification du commit Git avec les clés SSH (GitRepository, ImageUpdateAutomation)
  • Authentification AWS CodeCommit à l'aide de Workload Identity (GitRepository)
  • Racine Sigstore trusted personnalisée pour une vérification sans clé dans des environnements isolés (OCIRepository)
  • Découverte du répertoire de modèles de chemin pour monorepos (ArtifactGenerator)
  • Récepteurs webhook sans secret et sécurisés par OIDC (Receiver) ❤️ Un grand merci à tous les contributeurs Flux qui nous ont aidé avec cette version !

Compatibilité Kubernetes

Cette version est compatible avec les versions suivantes du Kubernetes : | Version Kubernetes | Minimum requis | |---------------------|------------------| | v1.34 | >= 1.34.1 | | v1.35 | >= 1.35.0 | | v1.36 | >= 1.36.0 |

[!NOTE] Notez que le projet Flux n'offre le support que pour les trois dernières versions mineures de Kubernetes. La rétrocompatibilité avec les anciennes versions de Kubernetes et OpenShift est proposée par des fournisseurs tels que ControlPlane qui fournit un support d'entreprise pour Flux.

Compatibilité OpenShift

Flux peut être installé sur le cluster Red Hat OpenShift directement depuis OperatorHub à l'aide de Flux Operator. L'opérateur permet la configuration du verrouillage multi-tenant de Flux, des politiques réseau, du stockage persistant, du partitionnement, de la mise à l'échelle verticale et de la synchronisation de l'état du cluster à partir des référentiels Git, des artefacts OCI et du stockage compatible S3.

Procédure de mise à niveau

:attention : Les Flux API image.toolkit.fluxcd.io/v1beta2 et notification.toolkit.fluxcd.io/v1beta2 ont atteint la fin de leur vie utile et ont été retirés des CRD. Veuillez suivre la Procédure de mise à niveau pour Flux v2.7+ pour une mise à niveau en douceur des anciennes versions de Flux vers v2.9.

flux2 v2.9.0

Highlights

Flux v2.9.0 is a feature release. Users are encouraged to upgrade for the best experience.

For a compressive overview of new features and API changes included in this release, please refer to the Announcing Flux 2.9 GA blog post.

Overview of the new features:

  • Flux CLI Plugin System with the Mirror and Schema plugins (flux plugin)
  • Server-Side Apply field ignore rules for fine-grained drift control (Kustomization)
  • SOPS decryption with the Age post-quantum cipher (Kustomization)
  • Kubernetes Workload Identity authentication for OpenBao and Vault (Kustomization)
  • Helm post-render strategies, including chart hooks support (HelmRelease)
  • Literal mode for Helm values references mirroring helm --set-literal (HelmRelease)
  • Allow empty kind in CEL health check expressions (Kustomization, HelmRelease)
  • Git commit signing and verification with SSH keys (GitRepository, ImageUpdateAutomation)
  • AWS CodeCommit authentication using Workload Identity (GitRepository)
  • Custom Sigstore trusted root for keyless verification in air-gapped environments (OCIRepository)
  • Path pattern directory discovery for monorepos (ArtifactGenerator)
  • Secret-less, OIDC-secured webhook Receivers (Receiver)

❤️ Big thanks to all the Flux contributors that helped us with this release!

Kubernetes compatibility

This release is compatible with the following Kubernetes versions:

| Kubernetes version | Minimum required | |--------------------|------------------| | v1.34 | >= 1.34.1 | | v1.35 | >= 1.35.0 | | v1.36 | >= 1.36.0 |

[!NOTE] Note that the Flux project offers support only for the latest three minor versions of Kubernetes. Backwards compatibility with older versions of Kubernetes and OpenShift is offered by vendors such as ControlPlane that provide enterprise support for Flux.

OpenShift compatibility

Flux can be installed on Red Hat OpenShift cluster directly from OperatorHub using Flux Operator. The operator allows the configuration of Flux multi-tenancy lockdown, network policies, persistent storage, sharding, vertical scaling and the synchronization of the cluster state from Git repositories, OCI artifacts, and S3-compatible storage.

Upgrade procedure

:warning: The Flux APIs image.toolkit.fluxcd.io/v1beta2 and notification.toolkit.fluxcd.io/v1beta2 have reached end-of-life and have been removed from the CRDs.

Please follow the Upgrade Procedure for Flux v2.7+ for a smooth upgrade from older versions of Flux to v2.9.
