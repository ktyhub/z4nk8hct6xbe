flux2 v2.10.0

Faits saillants

Flux v2.10.0 est une version fonctionnelle. Les utilisateurs sont encouragés à effectuer une mise à niveau pour la meilleure expérience. Aperçu des nouvelles fonctionnalités :

  • L'identité de l'objet est généralement disponible ; la porte de fonctionnalité ObjectLevelWorkloadIdentity est retirée
  • SPIFFE mTLS pour la communication inter-contrôleurs
  • Notification Event, Alert et Provider API promus v1
  • OCIRepository comme source graphique pour HelmRelease
  • Décryptage SOPS pour les fichiers chiffrés avec des expressions régulières de commentaires et --override-manager-before-dry-run (Kustomization)
  • Mise à jour d'images par lots avec .spec.policyChangeDelay, nouvelle tentative sur les push rejetés et .Changed.Summary (ImageUpdateAutomation)
  • Backend de stockage d'artefacts Flux activé par défaut pour les balises ImageRepository
  • Artefacts inter-espaces de noms, provisionnement des espaces de noms des locataires et découverte de modèles de chemin (ArtifactGenerator)
  • Nouveaux fournisseurs de notifications Zoom, incident.io et Mastodon
  • Construit avec Kubernetes 1.37 et Go 1.27 ❤️ Un grand merci à tous les contributeurs Flux qui nous ont aidé avec cette version !

Compatibilité Kubernetes

Cette version est compatible avec les versions suivantes du Kubernetes : | Version Kubernetes | Minimum requis | |---------------------|------------------| | v1.35 | >= 1.35.2 | | v1.36 | >= 1.36.1 | | v1.37 | >= 1.37.0 |

[!NOTE] Notez que le projet Flux n'offre le support que pour les trois dernières versions mineures de Kubernetes. La rétrocompatibilité avec les anciennes versions de Kubernetes et OpenShift est proposée par des fournisseurs tels que ControlPlane qui fournit un support d'entreprise pour Flux.

Compatibilité OpenShift

Flux peut être installé sur le cluster Red Hat OpenShift directement depuis OperatorHub à l'aide de Flux Operator. L'opérateur permet la configuration du verrouillage multi-tenant de Flux, des politiques réseau, du stockage persistant, du partitionnement, de la mise à l'échelle verticale et de la synchronisation de l'état du cluster à partir des référentiels Git, des artefacts OCI et du stockage compatible S3.

Procédure de mise à niveau

⚠️ Modifications majeures dans cette version :

  • L'identité de l'objet est toujours activée et le Flux RBAC par défaut n'accorde plus le verbe create sur la ressource serviceaccounts/token. Si votre installation repose sur le RBAC par défaut, liez un ClusterRole avec cette autorisation au contrôleur ServiceAccount avant la mise à niveau. Voir fluxcd/flux2#6139 pour le ClusterRole et le ClusterRoleBinding requis.
  • Les notifications Alert et Provider API sont promues en v1. La conversion d'un v1beta3 Alert ou Provider en v1 supprime les champs obsolètes Alert.spec.summary et Provider.spec.interval, le jeton JWT statique pour Azure Event Hub et la configuration TLS ou proxy dans Provider.spec.secretRef. Utilisez plutôt eventMetadata.summary, proxySecretRef et certSecretRef.
  • Le backend de stockage des artefacts Flux est désormais celui par défaut pour la base de données de balises ImageRepository. Le changement de porte efface la base de données de balises locale, de sorte que la première réconciliation après la mise à niveau effectue une nouvelle analyse à chaque ImageRepository. Configurez --feature-gates=FluxStorage=false pour continuer à utiliser BadgerDB.
  • L'authentification du cluster distant avec .spec.kubeConfig.configMapRef utilise l'identité de l'objet ; remplacez l'ancienne clé audiences par credential.auth.fluxcd.io/audiences. Veuillez suivre la Procédure de mise à niveau pour Flux v2.7+ pour une mise à niveau en douceur des anciennes versions de Flux vers v2.10.

flux2 v2.10.0

Highlights

Flux v2.10.0 is a feature release. Users are encouraged to upgrade for the best experience.

Overview of the new features:

  • Object identity is generally available; the ObjectLevelWorkloadIdentity feature gate is retired
  • SPIFFE mTLS for inter-controller communication
  • Notification Event, Alert and Provider APIs promoted to v1
  • OCIRepository as a chart source for HelmRelease
  • SOPS decryption for files encrypted with comment regexes, and --override-manager-before-dry-run (Kustomization)
  • Image update batching with .spec.policyChangeDelay, retry on rejected pushes, and .Changed.Summary (ImageUpdateAutomation)
  • Flux artifact storage backend enabled by default for ImageRepository tags
  • Cross-namespace artifacts, tenant namespace provisioning, and path-pattern discovery (ArtifactGenerator)
  • New Zoom, incident.io and Mastodon notification providers
  • Built with Kubernetes 1.37 and Go 1.27

❤️ Big thanks to all the Flux contributors that helped us with this release!

Kubernetes compatibility

This release is compatible with the following Kubernetes versions:

| Kubernetes version | Minimum required | |--------------------|------------------| | v1.35 | >= 1.35.2 | | v1.36 | >= 1.36.1 | | v1.37 | >= 1.37.0 |

[!NOTE] Note that the Flux project offers support only for the latest three minor versions of Kubernetes. Backwards compatibility with older versions of Kubernetes and OpenShift is offered by vendors such as ControlPlane that provide enterprise support for Flux.

OpenShift compatibility

Flux can be installed on Red Hat OpenShift cluster directly from OperatorHub using Flux Operator. The operator allows the configuration of Flux multi-tenancy lockdown, network policies, persistent storage, sharding, vertical scaling and the synchronization of the cluster state from Git repositories, OCI artifacts, and S3-compatible storage.

Upgrade procedure

⚠️ Breaking changes in this release:

  • Object identity is always enabled and the default Flux RBAC no longer grants the create verb on the serviceaccounts/token resource. If your installation relies on the default RBAC, bind a ClusterRole with this permission to the controller ServiceAccount before upgrading. See fluxcd/flux2#6139 for the required ClusterRole and ClusterRoleBinding.
  • The notification Alert and Provider APIs are promoted to v1. Converting a v1beta3 Alert or Provider to v1 drops the deprecated Alert.spec.summary and Provider.spec.interval fields, the static JWT token for Azure Event Hub, and TLS or proxy configuration in Provider.spec.secretRef. Use eventMetadata.summary, proxySecretRef and certSecretRef instead.
  • The Flux artifact storage backend is now the default for the ImageRepository tag database. Switching the gate wipes the local tag database, so the first reconciliation after the upgrade rescans every ImageRepository. Set --feature-gates=FluxStorage=false to keep using BadgerDB.
  • Remote cluster authentication with .spec.kubeConfig.configMapRef uses object identity; replace the legacy audiences key with credential.auth.fluxcd.io/audiences.

Please follow the Upgrade Procedure for Flux v2.7+ for a smooth upgrade from older versions of Flux to v2.10.
