MaxKB v1.4.1

Highlights

  • Application orchestration output control — PR #921 adds return-content settings to both the fixed-reply and AI-chat nodes, letting workflow authors define exactly what each node emits instead of accepting a hardcoded response. This is the release's most meaningful capability change: it makes chained orchestrations genuinely composable and lets you normalize node output before it reaches the next step or the end user.
  • Concurrent Xunfei Spark sessions no longer cross-talk — PR #920 fixes a race where simultaneous questions from multiple users produced interleaved, mixed-up answers. If you run the iFlytek Spark model in a multi-user deployment, treat this as a correctness-and-privacy fix and upgrade before exposing the app to concurrent traffic.
  • Knowledge-base ingestion reliability — Several ingestion paths were quietly lossy or broken: PDF Q&A uploads dropped content (#946), QA-pair spreadsheets containing only numeric cells failed to parse (#933), and adding segments with ultra-high-resolution images errored out (#943). PR #934 also stops vectorization jobs from continuing on documents that have already been deleted — important for both index integrity and avoiding wasted embedding compute.
  • Web-site knowledge bases finally honor the chosen embedding model — PR #948 fixes the vector-model picker silently not taking effect when creating a Web-site knowledge base. Worth auditing any existing web-site KBs where you assumed a non-default model was active; they may have been embedded with the default all along.
  • Orchestration and conversation UX fixes — Multi-turn conversation settings now apply when chatting from the settings page (#945), the opening-phrase and prompt editors can be expanded for long prompts (#945), user questions preserve line breaks on the Q&A page, and a permissions false positive that showed "no permission" to view-only users in advanced orchestration is gone. PR #940 also lifts the 20-character cap that made longer model names error out — check custom model labels after upgrading.
  • Breaking changes — None in this release.
