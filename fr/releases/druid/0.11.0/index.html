druide druide-0.11.0

Druid 0.11.0 contient plus d'une centaine d'améliorations de performances, de stabilité et de corrections de bugs provenant de près de 40 contributeurs. Cette version ajoute deux fonctionnalités de sécurité majeures, la prise en charge TLS et des points d'extension pour l'authentification et l'autorisation. Les principales nouvelles fonctionnalités incluent :

  • Prise en charge de TLS (alias SSL)
  • Points d'extension pour l'authentification et l'autorisation
  • Prise en charge des doubles colonnes
  • Stratégie d'équilibrage des coûts de mise en cache
  • Prise en charge de l'expression jq dans l'analyseur JSON -Extension de cache Redis
  • Améliorations des performances de GroupBy
  • Diverses améliorations de Druid SQL La liste complète des changements est ici : https://github.com/druid-io/druid/pulls?utf8=%E2%9C%93&q=is%3Apr%20is%3Aclosed%20milestone%3A0.11.0 La documentation pour cette version se trouve à l'adresse suivante : http://druid.io/docs/0.11.0/

Faits saillants

Prise en charge de TLS

Druid prend désormais en charge TLS, permettant les communications client et inter-nœuds cryptées. Veuillez consulter http://druid.io/docs/0.11.0/operations/tls-support.html pour plus de détails sur la configuration et les extensions associées. Ajouté par @pjain1 dans https://github.com/druid-io/druid/pull/4270.

Points d'extension d'authentification/autorisation

Des points d'extension pour authentifier et autoriser les demandes ont été ajoutés à Druid. Veuillez consulter http://druid.io/docs/0.11.0/configuration/auth.html pour plus d'informations sur la configuration et la mise en œuvre de l'extension. L'extension d'authentification Kerberos existante a été mise à jour pour implémenter la nouvelle interface Authenticator. Veuillez consulter la section « Modifications de la configuration Kerberos » sous « Mise à jour à partir de 0.10.1 et versions antérieures » pour plus d'informations si vous utilisez l'extension Kerberos. Ajouté par @jon-wei dans https://github.com/druid-io/druid/pull/4271

Prise en charge des colonnes doubles

Druid prend désormais en charge les colonnes d'agrégation de type double. Veuillez consulter http://druid.io/docs/0.11.0/querying/aggregations.html pour la documentation sur les nouveaux agrégateurs doubles. Ajouté par @b-slim dans https://github.com/druid-io/druid/pull/4491. ###cachingStratégie d'équilibrage des coûts Les utilisateurs effectuant une mise à niveau vers 0.11.0 sont encouragés à essayer la nouvelle stratégie d'équilibrage de segment cachingCost sur leurs coordinateurs. Cette stratégie offre d'importantes améliorations de performances par rapport à la stratégie d'équilibrage des coûts existante et il est prévu qu'elle devienne la stratégie par défaut dans la version suivant 0.11.0. Cette stratégie peut être sélectionnée en définissant la propriété suivante sur les coordinateurs :

druid.coordinator.balancer.strategy=cachingCost

Ajouté par @dgolitsyn dans https://github.com/druid-io/druid/pull/4731

Prise en charge des expressions jq dans l'analyseur JSON

L'analyseur d'entrée JSON de Druid prend désormais en charge les expressions jq utilisant jackson-jq, permettant davantage de transformations d'entrée avant l'ingestion. Veuillez consulter http://druid.io/docs/0.11.0/ingestion/flatten-json.html pour plus de détails. Ajouté par @knoguchi dans https://github.com/druid-io/druid/pull/4171.

Extension de cache Redis

Une nouvelle implémentation de cache utilisant Redis a été ajoutée dans une extension, ajoutée par @QiuMM dans https://github.com/druid-io/druid/pull/4615.. Veuillez vous référer à la demande d'extraction précédente pour plus de détails.

Améliorations des performances de GroupBy

Plusieurs nouvelles optimisations de performances ont été ajoutées à la requête GroupBy par @jihoonson dans les PR suivants : https://github.com/druid-io/druid/pull/4660 Tri parallèle pour ConcurrentGrouper https://github.com/druid-io/druid/pull/4576 Agrégation basée sur un tableau pour la requête groupBy https://github.com/druid-io/druid/pull/4668 Ajoutez IntGrouper pour éviter le boxing/unboxing inutile dans l'agrégation basée sur un tableau PR #4660 offre une amélioration générale en parallélisant le tri partiel des résultats, tandis que PR #4576 et #4668 offrent des améliorations significatives lors du regroupement sur une seule colonne String.

Améliorations SQL

Diverses améliorations et fonctionnalités ont été ajoutées à Druid SQL, par @gianm dans les PR suivants : https://github.com/druid-io/druid/pull/4750 - Prise en charge du TRIM https://github.com/druid-io/druid/pull/4720 - Arrondi pour compte distinct https://github.com/druid-io/druid/pull/4561 - Métriques pour les requêtes SQL https://github.com/druid-io/druid/pull/4360 - Prise en charge des expressions SQL

Et bien plus encore !

La liste complète des changements est ici : https://github.com/druid-io/druid/pulls?utf8=%E2%9C%93&q=is%3Apr%20is%3Aclosed%20milestone%3A0.11.0

Mise à jour depuis 0.10.1 et versions antérieures

Veuillez consulter ci-dessous les modifications entre 0.10.1 et 0.11.0 dont vous devez être conscient avant la mise à niveau. Si vous effectuez une mise à jour à partir d'une version antérieure à 0.10.1, veuillez consulter les release note des versions intermédiaires concernées pour des notes supplémentaires.

Amélioration des coordinateurs et des suzerains

Le correctif suivant modifie la façon dont les redirections coordinateur->overlord sont gérées : https://github.com/druid-io/druid/pull/5037 L'algorithme d'élection du chef du suzerain a changé dans 0.11.0 : https://github.com/druid-io/druid/pull/4699. En raison des deux correctifs ci-dessus, une attention particulière est nécessaire lors de la mise à niveau de Coordinateur ou Overlord vers 0.11.0. Tous les coordinateurs et suzerains doivent être fermés et mis à niveau ensemble. Par exemple, pour mettre à niveau les coordinateurs, vous devez arrêter tous les coordinateurs, les mettre à niveau vers 0.11.0, puis les démarrer. Les suzerains devraient être améliorés de la même manière. Pendant le processus de mise à niveau, il ne doit y avoir aucune période pendant laquelle un coordinateur ou un suzerain non 0.11.0 s'exécute simultanément avec un coordinateur ou un suzerain 0.11.0. Notez qu'au moins un suzerain doit être évoqué le plus rapidement possible après les avoir tous arrêtés afin que les péons, la tranquillité, etc. continuent de fonctionner après quelques tentatives. Notez également que la propriété druid.zk.paths.indexer.leaderLatchPath n'est plus utilisée désormais.

Modifications du nom du service

Dans les versions antérieures de Druid, les caractères / dans les noms de service définis par druid.service étaient remplacés par des caractères : car ces noms de service étaient utilisés dans les chemins Zookeeper. Le Druide 0.11.0 n'effectue plus ces remplacements de personnages. Exemple : 1 - si l'ancienne configuration avait un courtier avec le nom de service test/broker : druid.service=test/broker et un routeur a été configuré en supposant que / sera remplacé par : dans le nom du service de courtier, druid.router.tierToBrokerMap={"hot":"test:broker","_default_tier":"test:broker"} la configuration du routeur doit être mise à jour pour supprimer cette hypothèse : druid.router.tierToBrokerMap={"hot":"test/broker","_default_tier":"test/broker"} Exemple : 2 - Si l'ancienne configuration avait un seigneur avec le nom de service test/overlord, alors la valeur de druid.coordinator.asOverlord.overlordService ou druid.selectors.indexing.serviceName doit être test/overlord et non test:overlord. Exemple : 3 - Si l'ancienne configuration avait un seigneur avec le nom de service test:overlord, alors la valeur de druid.coordinator.asOverlord.overlordService ou druid.selectors.indexing.serviceName devrait être test:overlord et non test/overlord. Les configurations suivantes liées au nom de service sont également affectées et doivent être mises à jour pour correspondre exactement à la valeur de la propriété druid.service sur un autre nœud découvert. druid.coordinator.asOverlord.overlordService druid.selectors.coordinator.serviceName druid.selectors.indexing.serviceName druid.router.defaultBrokerServiceName druid.router.coordinatorServiceName druid.router.tierToBrokerMap Veuillez consulter https://github.com/druid-io/druid/issues/4992 pour plus de détails.

Modifications de la configuration de Kerberos

Le format de configuration de l'authentification Kerberos a changé suite aux nouvelles interfaces introduites par #4271. Veuillez vous référer à http://druid.io/docs/0.11.0/development/extensions-core/druid-kerberos.html pour les nouvelles propriétés de configuration. Les utilisateurs peuvent pointer le nom d'autorisation de l'authentificateur Kerberos vers une instance d'un mécanisme d'autorisation « allowAll » pour reproduire le comportement pré-0.11.0 d'un cluster utilisant l'authentification Kerberos sans autorisation.

Recherches Modifications du chemin API

Les chemins pour la configuration de recherche API ont changé en raison du #5058. Les chemins de configuration qui avaient la forme /druid/coordinator/v1/lookups ont désormais la forme /druid/coordinator/v1/lookups/config. Veuillez consulter http://druid.io/docs/0.11.0/querying/lookups.html pour le API actuel.

Migration vers les colonnes doubles

Avant 0.11.0, les agrégateurs Double* stockaient les valeurs de colonne sur le disque sous forme de Float tout en effectuant des agrégations à l'aide de représentations Double. Le PR #4491 permet aux agrégateurs Double de stocker les valeurs des colonnes sur le disque en tant que Doubles. En raison de problèmes liés aux mises à jour progressives et aux rétrogradations de version, ce comportement est désactivé par défaut et Druid continuera à stocker les agrégateurs doubles sur le disque sous forme de flotteurs. Pour activer le stockage sur deux colonnes, définissez la propriété suivante dans les propriétés d'exécution communes :

druid.indexing.doubleStorage=double

Les utilisateurs ne doivent pas définir cette propriété lors d'une mise à niveau continue initiale vers 0.11.0, car les nœuds exécutant Druid avant 0.11.0 ne seront pas en mesure de gérer les colonnes doubles créées pendant la période de mise à niveau. Les utilisateurs devront également réindexer tous les segments avec des colonnes doubles s'ils passent de 0.11.0 à une ancienne version. Veuillez consulter les numéros 4944 et 4605 pour plus d'informations.

Analyser les modifications de la requête

La requête Scan a été déplacée de extensions-contrib vers Core Druid. Dans le cadre de cette migration : https://github.com/druid-io/druid/pull/4751,, la gestion de la colonne de temps par la requête d'analyse a été modifiée. La colonne d'heure est maintenant renvoyée sous la forme "__time" plutôt que "horodatage", elle n'est plus incluse si vous ne la demandez pas spécifiquement dans vos "colonnes", et elle est renvoyée sous forme de chaîne longue plutôt que de chaîne. Les utilisateurs peuvent rétablir le traitement du temps de la requête Scan au comportement d'extension hérité en définissant "legacy" : true dans leurs requêtes ou en définissant la propriété druid.query.scan.legacy = true. Ceci est destiné à fournir un chemin de migration pour les utilisateurs qui utilisaient auparavant l'extension contrib.

Modifications de l'interface des extensions

Prise en charge de l'agrégateur à double colonne

L'interface Aggregator a acquis une méthode getDouble(), qui convertit par défaut le résultat de getFloat(). La méthode getDouble() doit être réimplémentée pour tous les agrégateurs personnalisés pouvant prendre en charge les doubles. Voir https://github.com/druid-io/druid/pull/4595 pour plus de détails.

Modification de l'interface de QueryRunner

L'interface QueryRunner a changé et l'ancienne méthode run() a été supprimée, remplacée par une nouvelle méthode qui accepte un objet QueryPlus. Les extensions de requête personnalisées devront implémenter la nouvelle interface. Veuillez consulter https://github.com/druid-io/druid/pull/4184 et https://github.com/druid-io/druid/pull/4482 pour plus de détails.

Modification de l'interface du filtre

La méthode Filter.getBitmapResult() n'a plus d'implémentation par défaut : https://github.com/druid-io/druid/pull/4481 Les extensions de filtres personnalisés devront maintenant fournir une implémentation pour getBitmapResult().

Autres remarques

jvm/gc/time métrique

La métrique jvm/gc/time n'est plus émise, remplacée par une nouvelle métrique nommée jvm/gc/cpu pour les raisons décrites ici : https://github.com/druid-io/druid/pull/4480

Stratégie de sélection des travailleurs par défaut

Veuillez noter que la stratégie de sélection des travailleurs par défaut est passée de fillCapacity à equalDistribution. Ce changement a été introduit dans 0.10.1, la version précédente, mais n'a pas été mentionné dans les 0.10.1 release note, il est donc à nouveau rappelé ici.

Création de segments V8 supprimée

Druid construira désormais toujours des segments V9, la création de segments V8 n'est plus prise en charge et la propriété buildV9Directly pour les tâches d'ingestion a été supprimée. Veuillez consulter https://github.com/druid-io/druid/pull/4420 pour plus de détails.

LogLevelAdjuster supprimé

Veuillez noter que le LogLevelAdjuster a été supprimé : https://github.com/druid-io/druid/pull/4236 Tout utilisateur utilisant des mbeans pour configurer les niveaux de journalisation doit plutôt configurer log4j2 à l'aide de jmx.

druid druid-0.11.0

Druid 0.11.0 contains over a hundred performance improvements, stability improvements, and bug fixes from almost 40 contributors. This release adds two major security features, TLS support and extension points for authentication and authorization.

Major new features include:

  • TLS (a.k.a. SSL) support
  • Extension points for authentication and authorization
  • Double columns support
  • cachingCost Balancer Strategy
  • jq expression support in JSON parser
  • Redis cache extension
  • GroupBy performance improvements
  • Various improvements to Druid SQL

The full list of changes is here: https://github.com/druid-io/druid/pulls?utf8=%E2%9C%93&q=is%3Apr%20is%3Aclosed%20milestone%3A0.11.0

Documentation for this release is at: http://druid.io/docs/0.11.0/

Highlights

TLS support

Druid now supports TLS, enabling encrypted client and inter-node communications. Please see http://druid.io/docs/0.11.0/operations/tls-support.html for details on configuration and related extensions.

Added by @pjain1 in https://github.com/druid-io/druid/pull/4270.

Authentication/authorization extension points

Extension points for authenticating and authorizing requests have been added to Druid. Please see http://druid.io/docs/0.11.0/configuration/auth.html for information on configuration and extension implementation.

The existing Kerberos authentication extension has been updated to implement the new Authenticator interface, please see the "Kerberos configuration changes" section under "Updating from 0.10.1 and earlier" for more information if you are using the Kerberos extension.

Added by @jon-wei in https://github.com/druid-io/druid/pull/4271

Double columns support

Druid now supports Double type aggregator columns. Please see http://druid.io/docs/0.11.0/querying/aggregations.html for documentation on the new Double aggregators.

Added by @b-slim in https://github.com/druid-io/druid/pull/4491.

cachingCost Balancer Strategy

Users upgrading to 0.11.0 are encouraged to try the new cachingCost segment balancing strategy on their coordinators. This strategy offers large performance improvements over the existing cost balancer strategy, and it is planned to become the default strategy in the release following 0.11.0.

This strategy can be selected by setting the following property on coordinators:

druid.coordinator.balancer.strategy=cachingCost

Added by @dgolitsyn in https://github.com/druid-io/druid/pull/4731

jq expression support in JSON parser

Druid's JSON input parser now supports jq expressions using jackson-jq, enabling more input transforms before ingestion. Please see http://druid.io/docs/0.11.0/ingestion/flatten-json.html for more details.

Added by @knoguchi in https://github.com/druid-io/druid/pull/4171.

Redis cache extension

A new cache implementation using Redis has been added in an extension, added by @QiuMM in https://github.com/druid-io/druid/pull/4615. Please refer to the preceding pull request for more details.

GroupBy performance improvements

Several new performance optimizations have been added to the GroupBy query by @jihoonson in the following PRs:

https://github.com/druid-io/druid/pull/4660 Parallel sort for ConcurrentGrouper https://github.com/druid-io/druid/pull/4576 Array-based aggregation for groupBy query https://github.com/druid-io/druid/pull/4668 Add IntGrouper to avoid unnecessary boxing/unboxing in array-based aggregation

PR #4660 offers a general improvement by parallelizing partial result sorting, while PR #4576 and #4668 offer significant improvements when grouping on a single String column.

SQL improvements

Various improvements and features have been added to Druid SQL, by @gianm in the following PRs:

https://github.com/druid-io/druid/pull/4750 - TRIM support https://github.com/druid-io/druid/pull/4720 - Rounding for count distinct https://github.com/druid-io/druid/pull/4561 - Metrics for SQL queries https://github.com/druid-io/druid/pull/4360 - SQL expressions support

And much more!

The full list of changes is here: https://github.com/druid-io/druid/pulls?utf8=%E2%9C%93&q=is%3Apr%20is%3Aclosed%20milestone%3A0.11.0

Updating from 0.10.1 and earlier

Please see below for changes between 0.10.1 and 0.11.0 that you should be aware of before upgrading. If you're updating from an earlier version than 0.10.1, please see release notes of the relevant intermediate versions for additional notes.

Upgrading coordinators and overlords

The following patch changes the way coordinator->overlord redirects are handled: https://github.com/druid-io/druid/pull/5037

The overlord leader election algorithm has changed in 0.11.0: https://github.com/druid-io/druid/pull/4699.

As a result of the two patches above, special care is needed when upgrading Coordinator or Overlord to 0.11.0. All coordinators and overlords must be shut down and upgraded together.

For example, to upgrade Coordinators, you would shutdown all coordinators, upgrade them to 0.11.0 and then start them. Overlords should be upgraded in a similar way.

During the upgrade process, there must not be any time period where a non-0.11.0 coordinator or overlord is running simultaneously with an 0.11.0 coordinator or overlord.

Note that at least one overlord should be brought up as quickly as possible after shutting them all down so that peons, tranquility etc continue to work after some retries.

Also note that the druid.zk.paths.indexer.leaderLatchPath property is no longer used now.

Service name changes

In earlier versions of Druid, / characters in service names defined by druid.service would be replaced by : characters because these service names were used in Zookeeper paths. Druid 0.11.0 no longer performs these character replacements.

Example:1 - if the old configuration had a broker with service name test/broker: druid.service=test/broker

and a Router was configured assuming that / will be replaced with : in the broker service name, druid.router.tierToBrokerMap={"hot":"test:broker","_default_tier":"test:broker"}

the Router configuration should be updated to remove that assumption: druid.router.tierToBrokerMap={"hot":"test/broker","_default_tier":"test/broker"}

Example:2 - If the old configuration had overlord with service Name test/overlord then value of druid.coordinator.asOverlord.overlordService or druid.selectors.indexing.serviceName should be test/overlord and not test:overlord

Example:3 - If the old configuration had overlord with service Name test:overlord then value of druid.coordinator.asOverlord.overlordService or druid.selectors.indexing.serviceName should be test:overlord and not test/overlord

Following service name-related configurations are also affected and should be updated to exactly match the value of druid.service property on other node being discovered.

druid.coordinator.asOverlord.overlordService druid.selectors.coordinator.serviceName druid.selectors.indexing.serviceName druid.router.defaultBrokerServiceName druid.router.coordinatorServiceName druid.router.tierToBrokerMap

Please see https://github.com/druid-io/druid/issues/4992 for more details.

Kerberos configuration changes

The Kerberos authentication configuration format has changed as a result of the new interfaces introduced by #4271. Please refer to http://druid.io/docs/0.11.0/development/extensions-core/druid-kerberos.html for the new configuration properties.

Users can point the Kerberos authenticator's authorizerName to an instance of an "allowAll" authorizer to replicate the pre-0.11.0 behavior of a cluster using Kerberos authentication with no authorization.

Lookups API path changes

The paths for the lookups configuration API have changed due to #5058.

Configuration paths that had the form /druid/coordinator/v1/lookups now have the form /druid/coordinator/v1/lookups/config.

Please see http://druid.io/docs/0.11.0/querying/lookups.html for the current API.

Migrating to Double columns

Prior to 0.11.0, the Double* aggregators would store column values on disk as Float while performing aggregations using Double representations.

PR #4491 allows the Double aggregators to store column values on disk as Doubles. Due to concerns related to rolling updates and version downgrades, this behavior is disabled by default and Druid will continue to store Double aggregators on disk as floats.

To enable Double column storage, set the following property in the common runtime properties:

druid.indexing.doubleStorage=double

Users should not set this property during an initial rolling upgrade to 0.11.0, as any nodes running pre-0.11.0 Druid will not be able to handle Double columns created during the upgrade period. Users will also need to reindex any segments with Double columns if downgrading from 0.11.0 to an older version. Please see #4944 and #4605 for more information.

Scan query changes

The Scan query has been moved from extensions-contrib to core Druid. As part of this migration: https://github.com/druid-io/druid/pull/4751, the scan query's handling of the time column has changed.

The time column is now is returned as "__time" rather than "timestamp", it is no longer included if you do not specifically ask for it in your "columns", and it is returned as a long rather than a string.

Users can revert the Scan query's time handling to the legacy extension behavior by setting "legacy" : true in their queries, or setting the property druid.query.scan.legacy = true. This is meant to provide a migration path for users that were formerly using the contrib extension.

Extension Interface Changes

Aggregator double column support

The Aggregator interface has gained a getDouble() method, which defaults to casting the result of getFloat(). The getDouble() method should be re-implemented for any custom aggregators that can support doubles.

See https://github.com/druid-io/druid/pull/4595 for more details.

QueryRunner interface change

The QueryRunner interface has changed and the old run() method has been removed, replaced by a new method that accepts a QueryPlus object.

Custom query extensions will need to implement the new interface.

Please see https://github.com/druid-io/druid/pull/4184 and https://github.com/druid-io/druid/pull/4482 for more details.

Filter interface change

The Filter.getBitmapResult() method no longer has a default implementation: https://github.com/druid-io/druid/pull/4481

Custom filter extensions will need to provide an implementation for getBitmapResult() now.

Other Notes

jvm/gc/time metric

The jvm/gc/time metric is no longer emitted, replaced by a new metric named jvm/gc/cpu for the reasons described here: https://github.com/druid-io/druid/pull/4480

Default worker select strategy

Please note that the default worker select strategy has changed from fillCapacity to equalDistribution. This change was introduced in 0.10.1, the previous release, but was not mentioned in the 0.10.1 release notes, so it is called out again here.

V8 segment creation removed

Druid will now always build V9 segments, creating V8 segments is no longer supported and the buildV9Directly property for ingestion tasks has been removed.

Please see https://github.com/druid-io/druid/pull/4420 for more details.

LogLevelAdjuster removed

Please note that the LogLevelAdjuster has been removed: https://github.com/druid-io/druid/pull/4236

Any user using mbeans to configure log levels should configure log4j2 using jmx instead.
