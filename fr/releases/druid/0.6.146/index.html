druid 0.6.146

Correctif Publié21 août 2014 Sourceapache/druid Anglais original

Cette page est traduite automatiquement. Le texte anglais original fait foi.

druide druide-0.6.146

Nouvelles fonctionnalités

  • Capacités de reschème ajoutées. Vous pouvez désormais ingérer un segment Druid existant et modifier le nom, les dimensions, les métriques, le cumul, etc. du segment. (Plus d'infos : http://druid.io/docs/0.6.146/Ingestion-FAQ.html)
  • Histogrammes et quantiles approximatifs. Nous avons ouvert un nouveau module, druid-histogram, qui comprend un nouvel agrégateur pour créer des distributions approximatives et peut être utilisé pour les quantiles. En fonction de la précision des résultats souhaités, cet agrégateur peut être plus lent que les autres agrégateurs Druid. Cette fonctionnalité est encore quelque peu expérimentale, mais nous aimerions vraiment travailler avec la communauté pour la rendre plus stable en production. (Plus d'infos : http://druid.io/docs/0.6.146/ApproxHisto.html)
  • Délai d'expiration et annulation de la requête. Vous pouvez désormais spécifier une clé facultative « timeout » et une valeur longue dans le contexte de requête Druid pour annuler les requêtes exécutées depuis trop longtemps. Vous pouvez également émettre une annulation explicite de requête. (Plus d'infos : http://druid.io/docs/0.6.146/Querying.html)
  • groupBy et sélectionnez la mise en cache des requêtes (désactivée par défaut). Les requêtes Select et groupBy ne sont pas mises en cache par défaut. Cela permet d'éviter que les grands ensembles de résultats de ces requêtes ne débordent du cache. Toutefois, si votre charge de travail génère des résultats groupBy de taille raisonnable et que vous souhaitez activer le cache pour ces requêtes, vous pouvez remplacer les valeurs par défaut de druid.*.cache.unCacheable (http://druid.io/docs/0.6.146/Broker-Config.html).
  • Les cadres intermédiaires peuvent désormais être mis sur liste noire. Cela permet des mises à jour progressives des middleManagers. Consultez les nouveaux documents sur les mises à jour progressives de Druid. (http://druid.io/docs/0.6.146/Rolling-Updates.html)
  • Les informations d'identification S3 peuvent désormais être lues à partir du fichier. Merci @metacret !
  • Les journaux de tâches HDFS pour le service d'indexation sont désormais pris en charge. Merci @realfun !
  • Les tâches d'index prennent désormais en charge la spécification manuelle des shardSpecs et la possibilité d'ignorer l'étape de détermination des partitions.
  • Les requêtes TimeBoundary peuvent désormais renvoyer uniquement le temps maximum ou minimum. http://druid.io/docs/0.6.146/TimeBoundaryQuery.html

Améliorations

  • Les requêtes groupBy imbriquées prennent désormais en charge les agrégateurs de publications et toutes les fonctionnalités des requêtes groupBy normales.
  • Les requêtes groupBy prennent désormais en charge les agrégateurs de cardinalité.
  • Les stratégies de recherche de ports pour les péons sont plus intelligentes et peuvent désormais réutiliser les ports.
  • Les récepteurs complets existants tenteront désormais d'être remis beaucoup plus tôt après les mises à jour ou les redémarrages en temps réel.
  • UserData plus flexible pour la mise à l'échelle automatique du service d'indexation sur EC2 qui n'est plus lié à notre environnement de déploiement.
  • La logique asynchrone du routeur Druid a été considérablement améliorée.
  • Les routeurs prennent désormais en charge les remplacements facultatifs de stratégie de routage.
  • Les déploiements Druid 0.6.x fonctionnent désormais avec Apache Whirr. Nous allons également bientôt créer un moyen de déployer Druid avec docker.
  • Nettoyage de certaines configurations redondantes dans le service d'indexation.
  • De nombreux tests unitaires de requêtes et de mise en cache ont été ajoutés.
  • Des propriétés de travail explicites peuvent désormais être ajoutées pour les tâches d'ingestion Hadoop.

Documents

  • Il existe désormais des documents expliquant comment effectuer des mises à jour et des redémarrages continus de Druid. http://druid.io/docs/0.6.146/Rolling-Updates.html
  • Nouveaux documents pour configurer la journalisation dans Druid. http://druid.io/docs/0.6.146/Logging.html
  • Documents Kafka 8 maintenant ajoutés. Merci @r4j4h http://druid.io/docs/0.6.146/Kafka-Eight.html
  • Ajout de documents pour les topN inversés http://druid.io/docs/0.6.146/TopNMetricSpec.html#inverted-topnmetricspec
  • Documentation Cassandra mise à jour. Merci @lexicalunit https://github.com/metamx/druid/pull/680

Divers

  • La version du conservateur est passée à 2.6.0
  • Version Jetty remplacée par 9.2.2
  • Version Goyave remplacée par 16.0.1
  • La journalisation du coordinateur et des nœuds historiques est désormais moins détaillée

druid druid-0.6.146

New features

  • Reschema capabilities added. You can now ingest an existing Druid segment and change the name, dimensions, metrics, rollup, etc. of the segment. (More info: http://druid.io/docs/0.6.146/Ingestion-FAQ.html)
  • Approximate histograms and quantiles. We’ve open sourced a new module, druid-histogram that includes a new aggregator to build approximate distributions and can be used for quantiles. Depending on the accuracy of the desired results, this aggregator can be slower than the other Druid aggregators. This features is still somewhat experimental, but we would really love to work with the community to make it more production stable. (More info: http://druid.io/docs/0.6.146/ApproxHisto.html)
  • Query timeout and cancellation. You can now specify an optional “timeout” key and a long value in the Druid query context to cancel queries that have been running for too long. You can also issue explicit query cancellation. (More info: http://druid.io/docs/0.6.146/Querying.html)
  • groupBy and select query caching (disabled by default). Select and groupBy queries do not cache by default. This is to prevent large result sets from these queries overflowing the cache. However, if your workload generates groupBy results of reasonable size and you’d like to enable the cache for these queries, you can override the default values for druid.*.cache.unCacheable (http://druid.io/docs/0.6.146/Broker-Config.html).
  • Middle-managers can now be blacklisted. This allows for rolling updates of middleManagers. See new docs on rolling Druid updates. (http://druid.io/docs/0.6.146/Rolling-Updates.html)
  • S3 credentials can now be read from file. Thanks @metacret!
  • HDFS task logs for the indexing service now supported. Thanks @realfun!
  • Index tasks now support manual specification of shardSpecs and the ability to skip the determine partitions step.
  • TimeBoundary queries can now return just the max or min time. http://druid.io/docs/0.6.146/TimeBoundaryQuery.html

Improvements

  • Nested groupBy queries now support post aggregators and all functionality of normal groupBy queries.
  • groupBy queries now support cardinality aggregators.
  • Port finding strategies for peons are smarter and can now reuse ports.
  • Existing complete sinks will now try to be handed off much sooner after real-time updates or restarts.
  • More flexible userData for indexing service autoscaling on EC2 that is no longer tied to our deployment environment.
  • The async logic in the Druid router was improved significantly.
  • Routers now support optional routing strategy overrides.
  • Druid 0.6.x deployments now work with Apache Whirr. We are going to create a way of deploying Druid with docker soon as well.
  • Cleaned up some redundant configs in the indexing service.
  • A whole bunch of query and caching unit tests were added.
  • Explicit job properties can now be added for Hadoop ingestion tasks.

Docs

  • There are now docs about how to do rolling Druid updates and restarts. http://druid.io/docs/0.6.146/Rolling-Updates.html
  • New docs for configuring logging in Druid. http://druid.io/docs/0.6.146/Logging.html
  • Kafka 8 docs now added. Thanks @r4j4h http://druid.io/docs/0.6.146/Kafka-Eight.html
  • Added docs for inverted topNs http://druid.io/docs/0.6.146/TopNMetricSpec.html#inverted-topnmetricspec
  • Updated Cassandra documentation. Thanks @lexicalunit https://github.com/metamx/druid/pull/680

Misc

  • Curator version bumped to 2.6.0
  • Jetty version bumped to 9.2.2
  • Guava version bumped to 16.0.1
  • Logging for coordinator and historical nodes is now less verbose
