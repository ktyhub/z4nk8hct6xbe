druide druide-0.21.0

Apache Druid 0.21.0 contient environ 120 nouvelles fonctionnalités, corrections de bugs, améliorations des performances, améliorations de la documentation et couverture de tests supplémentaire de 36 contributeurs. Reportez-vous à la liste complète des modifications et à tout ce qui est associé au jalon pour plus de détails.

<a name="21-new-features" href="#21-new-features">#</a> Nouvelles fonctionnalités

<a name="21-operation" href="#21-operation">#</a> Opération

<a name="21-k8s-extension" href="#21-k8s-extension">#</a> Découverte du service et élection du leader basée sur Kubernetes

La nouvelle extension Kubernetes prend en charge la découverte de services et l'élection de leader basée sur Kubernetes. Cette extension fonctionne en conjonction avec la vue du serveur basée sur HTTP (druid.serverview.type=http) et la gestion des tâches (druid.indexer.runner.type=httpRemote) pour vous permettre d'exécuter un cluster Druid sans aucune dépendance ZooKeeper. Cette extension est encore expérimentale. Voir Extension Kubernetes pour plus de détails. https://github.com/apache/druid/pull/10544 https://github.com/apache/druid/pull/9507 https://github.com/apache/druid/pull/10537

<a name="21-segment-count-limit-for-balancing" href="#21-segment-count-limit-for-balancing">#</a> Nouvelle configuration du coordinateur dynamique pour limiter le nombre de segments lors de la recherche d'un segment candidat pour l'équilibrage des segments

Vous pouvez configurer le percentOfSegmentsToConsiderPerMove pour limiter le nombre de segments pris en compte lors de la sélection d'un segment candidat à déplacer. Les candidats sont recherchés jusqu'à maxSegmentsToMove * 2 fois. Cette nouvelle configuration empêche Druid de parcourir tous les segments disponibles pour accélérer le processus d'équilibrage des segments, surtout si vous avez de nombreux segments disponibles dans votre cluster. Voir Configuration dynamique du coordinateur pour plus de détails. https://github.com/apache/druid/pull/10284

<a name="21-indexer-endpoints" href="#21-indexer-endpoints">#</a> Points de terminaison status et selfDiscovered pour les indexeurs

L'indexeur prend désormais en charge les points de terminaison status et selfDiscovered. Voir Informations sur le processeur APIs pour plus de détails. https://github.com/apache/druid/pull/10679

<a name="21-querying" href="#21-querying">#</a> Requête

<a name="21-grouping-function" href="#21-grouping-function">#</a> Nouvelle fonction d'agrégation grouping

Vous pouvez utiliser la nouvelle fonction SQL de l'agrégateur grouping avec GROUPING SETS ou CUBE pour indiquer quelles dimensions de regroupement sont incluses dans l'ensemble de regroupement actuel. Voir Fonctions d'agrégation pour plus de détails. https://github.com/apache/druid/pull/10518

<a name="21-expr-type-handling" href="#21-expr-type-handling">#</a> Amélioration de la gestion des arguments manquants dans les expressions et les fonctions

Le traitement des expressions peut désormais être vectorisé lorsque des entrées sont manquantes. Par exemple une colonne inexistante. Lorsqu'un argument manque dans une expression, Druid peut désormais déduire le type de résultat approprié en fonction d'arguments non nuls. Par exemple, pour longColumn + nonExistentColumn, nonExistentColumn est traité comme (long) 0 au lieu de (double) 0.0. Enfin, en mode de gestion des valeurs nulles par défaut, les fonctions mathématiques peuvent produire une sortie correctement en traitant les arguments manquants comme des zéros. https://github.com/apache/druid/pull/10499

<a name="21-timestampadd" href="#21-timestampadd">#</a> Autoriser un point zéro pour TIMESTAMPADD

La fonction TIMESTAMPADD autorise désormais une période nulle. Cette fonctionnalité est requise pour certains outils BI tels que Tableau. https://github.com/apache/druid/pull/10550

<a name="21-ingestion" href="#21-ingestion">#</a> Ingestion

<a name="21-parallel-ingestion-without-intervals" href="#21-parallel-ingestion-without-intervals">#</a> L'ingestion parallèle native ne nécessite plus d'intervalles explicites

La tâche parallèle ne nécessite plus de définir des intervalles explicites dans granularitySpec. Si des intervalles sont manquants, la tâche parallèle exécute une étape supplémentaire pour l'échantillonnage d'entrée qui collecte les intervalles à indexer. https://github.com/apache/druid/pull/10592 https://github.com/apache/druid/pull/10647

<a name="21-old-kafka-support" href="#21-old-kafka-support">#</a> Prise en charge de l'ancienne version de Kafka

Druid prend désormais en charge Apache Kafka plus ancien que 0.11. Pour lire une ancienne version de Kafka, définissez isolation.level sur read_uncommitted dans consumerProperties. Seuls les 0.10.2.1 ont été testés jusqu'à cette version. Voir Configurations du superviseur Kafka pour plus de détails. https://github.com/apache/druid/pull/10551

Fusion de segments en plusieurs phases pour l'ingestion de lots natifs

Un nouveau tuningConfig, maxColumnsToMerge, contrôle le nombre de segments pouvant être fusionnés en même temps dans la tâche. Cette configuration peut être utile pour éviter une pression mémoire élevée lors de la fusion. Voir tuningConfig pour l'ingestion par lots natif pour plus de détails. https://github.com/apache/druid/pull/10689

<a name="21-compaction" href="#21-compaction">#</a> La réingestion native consomme moins de mémoire

Les tâches parallèles trient désormais les segments par ID avant de les attribuer à des sous-tâches. Ce tri minimise le nombre de tranches de temps à gérer pour chaque sous-tâche. En conséquence, chaque sous-tâche devrait utiliser moins de mémoire, en particulier lorsqu'une seule tâche parallèle est émise pour réingérer des segments couvrant une longue période. https://github.com/apache/druid/pull/10646

<a name="21-metrics" href="#21-metrics">#</a> Métriques

<a name="21-coordinator-duty-metrics" href="#21-coordinator-duty-metrics">#</a> Métriques d'exécution des tâches du coordinateur

Le coordinateur effectue plusieurs tâches de « service ». Par exemple, l'équilibrage des segments, le chargement de nouveaux segments, etc. Il existe désormais deux nouvelles mesures pour vous aider à analyser la rapidité avec laquelle le coordinateur exécute ces tâches.

  • coordinator/time : le temps d'exécution d'une tâche individuelle
  • coordinator/global/time : le temps d'exécution de toutes les tâches exécutables https://github.com/apache/druid/pull/10603

<a name="21-query-timeout-metric" href="#21-query-timeout-metric">#</a> Mesure du délai d'expiration des requêtes

Une nouvelle métrique fournit le nombre de requêtes expirées. Les requêtes précédemment expirées étaient traitées comme interrompues et incluses dans le query/interrupted/count (voir [Codes d'état HTTP modifiés pour les erreurs de requête] (#21-http-error-codes) pour plus de détails). query/timeout/count : le nombre de requêtes expirées pendant la période d'émission https://github.com/apache/druid/pull/10567

<a name="21-shuffle-metrics" href="#21-shuffle-metrics">#</a> Mélanger les métriques pour l'ingestion par lots

Deux nouvelles métriques fournissent des statistiques de mélange pour les MiddleManagers et les indexeurs. Ces métriques ont le supervisorTaskId comme dimension.

  • ingest/shuffle/bytes : nombre d'octets mélangés par période d'émission
  • ingest/shuffle/requests : nombre de requêtes de lecture aléatoire par période d'émission Pour activer les métriques de lecture aléatoire, ajoutez org.apache.druid.indexing.worker.shuffle.ShuffleMonitor dans druid.monitoring.monitors. Voir Métriques aléatoires pour plus de détails. https://github.com/apache/druid/pull/10359

<a name="21-cron-scheduler" href="#21-cron-scheduler">#</a> Nouveau planificateur de surveillance des métriques sécurisé contre la dérive d'horloge

Le planificateur de surveillance des métriques par défaut est implémenté sur la base de ScheduledThreadPoolExecutor qui est sujet à une [dérive d'horloge] illimitée (https://en.wikipedia.org/wiki/Clock_drift). Un nouveau planificateur de moniteur, ClockDriftSafeMonitorScheduler, surmonte cette limitation. Pour utiliser le nouveau planificateur, définissez druid.monitoring.schedulerClassName sur org.apache.druid.java.util.metrics.ClockDriftSafeMonitorScheduler dans le fichier runtime.properties. https://github.com/apache/druid/pull/10448 https://github.com/apache/druid/pull/10732

<a name="21-http-error-codes" href="#21-http-error-codes">#</a> Codes d'état HTTP améliorés pour les erreurs de requête

Avant cette version, Druid renvoyait « l'erreur interne (500) » pour la plupart des erreurs de requête. Druid renvoie désormais différents codes d'erreur en fonction de leur cause. Le tableau suivant répertorie les erreurs et leurs codes correspondants qui ont changé : Exception | Descriptif| Ancien code | Nouveau code ------------ | ------------- | ------------- | ------------- SqlParseException et ValidationException de Calcite | Échec de la planification des requêtes | 500 | 400 QueryTimeoutException | L'exécution de la requête ne s'est pas terminée dans le délai d'attente | 500 | 504 ResourceLimitExceededException | La requête a demandé plus de ressources que le seuil configuré | 500 | 400 InsuffisantResourceException | La requête n'a pas pu être planifiée en raison du manque de tampons de fusion disponibles au moment où elle a été soumise | 500 | 429, fusionné avec QueryCapacityExceededException QueryUnsupportedException | Fonctionnalité non prise en charge | 400 | 501 Il existe également une nouvelle métrique de requête pour les erreurs de délai d'expiration des requêtes. Voir Nouvelle métrique de délai d'expiration de requête pour plus de détails. https://github.com/apache/druid/pull/10464 https://github.com/apache/druid/pull/10746

<a name="21-query-interrupted-metric" href="#21-query-interrupted-metric">#</a> Requête interrompue métrique

query/interrupted/count ne compte plus les requêtes qui ont expiré. Ces requêtes sont comptées par query/timeout/count.

<a name="21-context-dimension" href="#21-context-dimension">#</a> Dimension context dans les métriques de requête

context est désormais une dimension par défaut émise pour toutes les métriques de requête. context est une chaîne au format JSON contenant le contexte de requête pour la requête à laquelle la métrique émise fait référence. L'ajout d'une dimension qui n'existait pas auparavant modifie certaines métriques émises par Druid. Vous devez prévoir de gérer cette nouvelle dimension context dans votre pipeline de métriques. Étant donné que la dimension est une chaîne au format JSON, une solution courante consiste à analyser la dimension et à l'aplatir ou à extraire les bits souhaités et à supprimer l'intégralité de la chaîne au format JSON. https://github.com/apache/druid/pull/10578

<a name="21-deprecate-zk-3.4" href="#21-deprecate-zk-3.4">#</a> Prise en charge obsolète d'Apache ZooKeeper 3.4

[Comme ZooKeeper 3.4 est en fin de vie depuis un certain temps] (https://mail-archives.apache.org/mod_mbox/zookeeper-user/202004.mbox/%3C41A7EC67-D8F4-4C3A-B2DB-C2741C2EECA3%40apache.org%3E), la prise en charge de ZooKeeper 3.4 est obsolète dans 0.21.0 et sera supprimée dans un avenir proche. https://github.com/apache/druid/issues/10780

<a name="21-consistent-segments-table" href="#21-consistent-segments-table">#</a> Format de sérialisation cohérent et convention de dénomination des colonnes pour la table sys.segments

Toutes les colonnes de la table sys.segments sont désormais sérialisées au format JSON pour les rendre cohérentes avec les autres tables système. Les noms de colonnes utilisent désormais la même convention « casse serpent ». https://github.com/apache/druid/pull/10481

<a name="21-known-issues" href="#21-known-issues">#</a> Problèmes connus

<a name="21-cve-2020-13949" href="#21-cve-2020-13949">#</a> Vulnérabilité de sécurité connue dans la bibliothèque Thrift

L'[extension Thrift] (https://druid.apache.org/docs/latest/development/extensions-contrib/thrift.html) peut être utile pour ingérer des fichiers au format Thrift dans Druid. Cependant, il existe une [vulnérabilité de sécurité connue] (https://nvd.nist.gov/vuln/detail/CVE-2020-13949) dans la version de la bibliothèque Thrift utilisée par Druid. La vulnérabilité peut être exploitable en ingérant des fichiers Thrift conçus de manière malveillante lorsque vous utilisez des indexeurs. Nous recommandons d'accorder l'autorisation DATASOURCE WRITE uniquement aux utilisateurs trusted.

<a name="21-docker-volume-ownership" href="#21-docker-volume-ownership">#</a> Problèmes d'autorisation lors de l'exécution du cluster Druid basé sur docker

Si vous exécutez le cluster Druid docker pour la première fois sur votre machine, l'utilisation de l'image 0.21.0 peut créer des répertoires internes avec le compte root. En conséquence, les services Druid peuvent échouer en raison d’un manque d’autorisations. Ce problème est classé dans https://github.com/apache/druid/issues/11166. Si vous utilisez docker compose, vous pouvez utiliser les commandes ci-dessous pour contourner ce problème. Ces commandes créeront d'abord des répertoires internes à l'aide d'une ancienne image, puis démarreront les services à l'aide de l'image 0.21.0.

$ cd ${PREV_SRC_DIR}
$ docker-compose -f distribution/docker/docker-compose.yml create
$ cd ${0.21.0_SRC_DIR}
$ docker-compose -f distribution/docker/docker-compose.yml up

Si vous n'utilisez pas docker compose, vous pouvez transmettre directement le paramètre de volume pour /opt/druid/var lorsque vous démarrez des services à l'aide de l'image 0.21.0. Par exemple, vous pouvez exécuter la commande ci-dessous pour démarrer le service coordinateur.

$ docker run -v /path/to/host/dir:/opt/druid/var apache/druid:0.21.0 coordinator

Pour une liste complète des problèmes ouverts, veuillez consulter https://github.com/apache/druid/labels/Bug.

druid druid-0.21.0

Apache Druid 0.21.0 contains around 120 new features, bug fixes, performance enhancements, documentation improvements, and additional test coverage from 36 contributors. Refer to the complete list of changes and everything tagged to the milestone for further details.

<a name="21-new-features" href="#21-new-features">#</a> New features

<a name="21-operation" href="#21-operation">#</a> Operation

<a name="21-k8s-extension" href="#21-k8s-extension">#</a> Service discovery and leader election based on Kubernetes

The new Kubernetes extension supports service discovery and leader election based on Kubernetes. This extension works in conjunction with the HTTP-based server view (druid.serverview.type=http) and task management (druid.indexer.runner.type=httpRemote) to allow you to run a Druid cluster with zero ZooKeeper dependencies. This extension is still experimental. See Kubernetes extension for more details.

https://github.com/apache/druid/pull/10544 https://github.com/apache/druid/pull/9507 https://github.com/apache/druid/pull/10537

<a name="21-segment-count-limit-for-balancing" href="#21-segment-count-limit-for-balancing">#</a> New dynamic coordinator configuration to limit the number of segments when finding a candidate segment for segment balancing

You can set the percentOfSegmentsToConsiderPerMove to limit the number of segments considered when picking a candidate segment to move. The candidates are searched up to maxSegmentsToMove * 2 times. This new configuration prevents Druid from iterating through all available segments to speed up the segment balancing process, especially if you have lots of available segments in your cluster. See Coordinator dynamic configuration for more details.

https://github.com/apache/druid/pull/10284

<a name="21-indexer-endpoints" href="#21-indexer-endpoints">#</a> status and selfDiscovered endpoints for Indexers

The Indexer now supports status and selfDiscovered endpoints. See Processor information APIs for details.

https://github.com/apache/druid/pull/10679

<a name="21-querying" href="#21-querying">#</a> Querying

<a name="21-grouping-function" href="#21-grouping-function">#</a> New grouping aggregator function

You can use the new grouping aggregator SQL function with GROUPING SETS or CUBE to indicate which grouping dimensions are included in the current grouping set. See Aggregation functions for more details.

https://github.com/apache/druid/pull/10518

<a name="21-expr-type-handling" href="#21-expr-type-handling">#</a> Improved missing argument handling in expressions and functions

Expression processing now can be vectorized when inputs are missing. For example a non-existent column. When an argument is missing in an expression, Druid can now infer the proper type of result based on non-null arguments. For instance, for longColumn + nonExistentColumn, nonExistentColumn is treated as (long) 0 instead of (double) 0.0. Finally, in default null handling mode, math functions can produce output properly by treating missing arguments as zeros.

https://github.com/apache/druid/pull/10499

<a name="21-timestampadd" href="#21-timestampadd">#</a> Allow zero period for TIMESTAMPADD

TIMESTAMPADD function now allows zero period. This functionality is required for some BI tools such as Tableau.

https://github.com/apache/druid/pull/10550

<a name="21-ingestion" href="#21-ingestion">#</a> Ingestion

<a name="21-parallel-ingestion-without-intervals" href="#21-parallel-ingestion-without-intervals">#</a> Native parallel ingestion no longer requires explicit intervals

Parallel task no longer requires you to set explicit intervals in granularitySpec. If intervals are missing, the parallel task executes an extra step for input sampling which collects the intervals to index.

https://github.com/apache/druid/pull/10592 https://github.com/apache/druid/pull/10647

<a name="21-old-kafka-support" href="#21-old-kafka-support">#</a> Old Kafka version support

Druid now supports Apache Kafka older than 0.11. To read from an old version of Kafka, set the isolation.level to read_uncommitted in consumerProperties. Only 0.10.2.1 have been tested up until this release. See Kafka supervisor configurations for details.

https://github.com/apache/druid/pull/10551

Multi-phase segment merge for native batch ingestion

A new tuningConfig, maxColumnsToMerge, controls how many segments can be merged at the same time in the task. This configuration can be useful to avoid high memory pressure during the merge. See tuningConfig for native batch ingestion for more details.

https://github.com/apache/druid/pull/10689

<a name="21-compaction" href="#21-compaction">#</a> Native re-ingestion is less memory intensive

Parallel tasks now sort segments by ID before assigning them to subtasks. This sorting minimizes the number of time chunks for each subtask to handle. As a result, each subtask is expected to use less memory, especially when a single Parallel task is issued to re-ingest segments covering a long time period.

https://github.com/apache/druid/pull/10646

<a name="21-web-console" href="#21-web-console">#</a> Web console

<a name="21-refresh-console-style" href="#21-refresh-console-style">#</a> Updated and improved web console styles

The new web console styles make better use of the Druid brand colors and standardize paddings and margins throughout. The icon and background colors are now derived from the Druid logo.

https://github.com/apache/druid/pull/10515

<a name="21-web-console-partitioning" href="#21-web-console-partitioning">#</a> Partitioning information is available in the web console

The web console now shows datasource partitioning information on the new Segment granularity and Partitioning columns.

Segment granularity column in the Datasources tab

Partitioning column in the Segments tab

https://github.com/apache/druid/pull/10533

<a name="21-web-console-dim-ordering" href="#21-web-console-dim-ordering">#</a> The column order in the Schema table matches the dimensionsSpec

The Schema table now reflects the dimension ordering in the dimensionsSpec.

https://github.com/apache/druid/pull/10588

<a name="21-metrics" href="#21-metrics">#</a> Metrics

<a name="21-coordinator-duty-metrics" href="#21-coordinator-duty-metrics">#</a> Coordinator duty runtime metrics

The coordinator performs several 'duty' tasks. For example segment balancing, loading new segments, etc. Now there are two new metrics to help you analyze how fast the Coordinator is executing these duties.

  • coordinator/time: the time for an individual duty to execute
  • coordinator/global/time: the time for the whole duties runnable to execute

https://github.com/apache/druid/pull/10603

<a name="21-query-timeout-metric" href="#21-query-timeout-metric">#</a> Query timeout metric

A new metric provides the number of timed out queries. Previously timed out queries were treated as interrupted and included in the query/interrupted/count (see Changed HTTP status codes for query errors for more details).

query/timeout/count: the number of timed out queries during the emission period

https://github.com/apache/druid/pull/10567

<a name="21-shuffle-metrics" href="#21-shuffle-metrics">#</a> Shuffle metrics for batch ingestion

Two new metrics provide shuffle statistics for MiddleManagers and Indexers. These metrics have the supervisorTaskId as their dimension.

  • ingest/shuffle/bytes: number of bytes shuffled per emission period
  • ingest/shuffle/requests: number of shuffle requests per emission period

To enable the shuffle metrics, add org.apache.druid.indexing.worker.shuffle.ShuffleMonitor in druid.monitoring.monitors. See Shuffle metrics for more details.

https://github.com/apache/druid/pull/10359

<a name="21-cron-scheduler" href="#21-cron-scheduler">#</a> New clock-drift safe metrics monitor scheduler

The default metrics monitor scheduler is implemented based on ScheduledThreadPoolExecutor which is prone to unbounded clock drift. A new monitor scheduler, ClockDriftSafeMonitorScheduler, overcomes this limitation. To use the new scheduler, set druid.monitoring.schedulerClassName to org.apache.druid.java.util.metrics.ClockDriftSafeMonitorScheduler in the runtime.properties file.

https://github.com/apache/druid/pull/10448 https://github.com/apache/druid/pull/10732

<a name="21-rds-password-provider" href="#21-rds-password-provider">#</a> New extension for a password provider based on AWS RDS token

A new PasswordProvider type allows access to AWS RDS DB instances using temporary AWS tokens. This extension can be useful when an RDS is used as Druid's metadata store. See AWS RDS extension for more details.

<a name="21-system-table-leader" href="#21-system-table-leader">#</a> The sys.servers table shows leaders

A new long-typed column is_leader in the sys.servers table indicates whether or not the server is the leader.

https://github.com/apache/druid/pull/10680

<a name="21-https-influxdb" href="#21-https-influxdb">#</a> druid-influxdb-emitter extension supports the HTTPS protocol

<a name="21-dynamic-config-provider" href="#21-dynamic-config-provider">#</a> Extensible Kafka consumer properties via a new DynamicConfigProvider

A new class DynamicConfigProvider enables fetching consumer properties at runtime. For instance, you can use DynamicConfigProvider fetch bootstrap.servers from location such as a local environment variable if it is not static. Currently, only a map-based config provider is supported by default. See DynamicConfigProvider for how to implement a custom config provider.

<a name="21-post-agg-subtotal" href="#21-post-agg-subtotal">#</a> Post-aggregator computation with subtotals

Before 0.21.0, the query fails with an error when you use post aggregators with sub-totals. Now this bug is fixed and you can use post aggregators with subtotals.

https://github.com/apache/druid/pull/10653

<a name="21-indexer-announce" href="#21-indexer-announce">#</a> Indexers announce themselves as segment servers

In 0.19.0 and 0.20.0, Indexers could not process queries against streaming data as they did not announce themselves as segment servers. They are fixed to announce themselves properly in 0.21.0.

https://github.com/apache/druid/pull/10631

<a name="21-historical-segment-loading" href="#21-historical-segment-loading">#</a> Validity check for segment files in historicals

Historicals now perform validity check after they download segment files and re-download automatically if those files are crashed.

<a name="21-upgrading-to-0.21.0" href="#21-upgrading-to-0.21.0">#</a> Upgrading to 0.21.0

Consider the following changes and updates when upgrading from Druid 0.20.0 to 0.21.0. If you're updating from an earlier version than 0.20.0, see the release notes of the relevant intermediate versions.

<a name="21-http-error-codes" href="#21-http-error-codes">#</a> Improved HTTP status codes for query errors

Before this release, Druid returned the "internal error (500)" for most of the query errors. Now Druid returns different error codes based on their cause. The following table lists the errors and their corresponding codes that has changed:

Exception | Description| Old code | New code ------------ | ------------- | ------------- | ------------- SqlParseException and ValidationException from Calcite | Query planning failed | 500 | 400 QueryTimeoutException | Query execution didn't finish in timeout | 500 | 504 ResourceLimitExceededException | Query asked more resources than configured threshold | 500 | 400 InsufficientResourceException | Query failed to schedule because of lack of merge buffers available at the time when it was submitted | 500 | 429, merged to QueryCapacityExceededException QueryUnsupportedException | Unsupported functionality | 400 | 501

There is also a new query metric for query timeout errors. See New query timeout metric for more details.

https://github.com/apache/druid/pull/10464 https://github.com/apache/druid/pull/10746

<a name="21-query-interrupted-metric" href="#21-query-interrupted-metric">#</a> Query interrupted metric

query/interrupted/count no longer counts the queries that timed out. These queries are counted by query/timeout/count.

<a name="21-context-dimension" href="#21-context-dimension">#</a> context dimension in query metrics

context is now a default dimension emitted for all query metrics. context is a JSON-formatted string containing the query context for the query that the emitted metric refers to. The addition of a dimension that was not previously alters some metrics emitted by Druid. You should plan to handle this new context dimension in your metrics pipeline. Since the dimension is a JSON-formatted string, a common solution is to parse the dimension and either flatten it or extract the bits you want and discard the full JSON-formatted string blob.

https://github.com/apache/druid/pull/10578

<a name="21-deprecate-zk-3.4" href="#21-deprecate-zk-3.4">#</a> Deprecated support for Apache ZooKeeper 3.4

As ZooKeeper 3.4 has been end-of-life for a while, support for ZooKeeper 3.4 is deprecated in 0.21.0 and will be removed in the near future.

https://github.com/apache/druid/issues/10780

<a name="21-consistent-segments-table" href="#21-consistent-segments-table">#</a> Consistent serialization format and column naming convention for the sys.segments table

All columns in the sys.segments table are now serialized in the JSON format to make them consistent with other system tables. Column names now use the same "snake case" convention.

https://github.com/apache/druid/pull/10481

<a name="21-known-issues" href="#21-known-issues">#</a> Known issues

<a name="21-cve-2020-13949" href="#21-cve-2020-13949">#</a> Known security vulnerability in the Thrift library

The Thrift extension can be useful for ingesting files of the Thrift format into Druid. However, there is a known security vulnerability in the version of the Thrift library that Druid uses. The vulerability can be exploitable by ingesting maliciously crafted Thrift files when you use Indexers. We recommend granting the DATASOURCE WRITE permission to only trusted users.

<a name="21-docker-volume-ownership" href="#21-docker-volume-ownership">#</a> Permission issues in running the docker-based Druid cluster

If you run the Druid docker cluster for the first time in your machine, using the 0.21.0 image can create internal directories with the root account. As a result, Druid services can fail due lack of permissions. This issue is filed in https://github.com/apache/druid/issues/11166.

If you are using docker compose, you can use the below commands to work around this issue. These commands will create internal directories first using an old image and then start services using the 0.21.0 image.

$ cd ${PREV_SRC_DIR}
$ docker-compose -f distribution/docker/docker-compose.yml create
$ cd ${0.21.0_SRC_DIR}
$ docker-compose -f distribution/docker/docker-compose.yml up

If you are not using docker compose, you can directly pass the volume parameter for /opt/druid/var when you start services using the 0.21.0 image. For example, you can run the command below to start the coordinator service.

$ docker run -v /path/to/host/dir:/opt/druid/var apache/druid:0.21.0 coordinator

For a full list of open issues, please see https://github.com/apache/druid/labels/Bug.
