Apache Druid 25.0.0 contient plus de 300 nouvelles fonctionnalités, corrections de bugs, améliorations des performances, améliorations de la documentation et couverture de tests supplémentaire de 51 contributeurs. <a name="25-highlights" href="#25-highlights">#</a> Faits saillants

<a name="25-highlights-msq" href="#25-highlights-msq-">#</a> Le moteur de tâches MSQ est désormais prêt pour la production

Le moteur de tâches de requêtes multi-étapes (MSQ) utilisé pour l'ingestion basée sur SQL est désormais prêt pour la production. Utilisez-le pour toutes les charges de travail prises en charge. Pour plus d’informations, consultez les pages suivantes :

  • Ingestion
  • Ingestion basée sur SQL

<a name="25-highlights-deploying-druid" href="#25-highlights-deploying-druid">#</a> Déploiements Druid simplifiés

Le nouveau script start-druid simplifie grandement le déploiement de toute combinaison de services Druid sur un seul serveur. Il est livré pré-emballé avec les configurations requises et peut être utilisé pour lancer un cluster Druid entièrement fonctionnel en appelant simplement ./start-druid. Pour les druides expérimentés, il donne également un contrôle complet sur les propriétés d'exécution et les arguments JVM pour disposer d'un cluster qui correspond exactement à vos besoins. Le script start-druid rend obsolètes les profils existants tels que start-micro-quickstart et start-nano-quickstart. Ces profils pourront être supprimés dans les versions futures. Pour plus d'informations, voir Déploiement sur un seul serveur.

<a name="25-highlights-string-dictionary-compression" href="#25-highlights-string-dictionary-compression">#</a> Compression de dictionnaire de chaînes (expérimental)

Ajout de la prise en charge des dictionnaires de chaînes codées au premier plan pour les colonnes de chaînes plus petites, entraînant une réduction de la taille des segments avec seulement des pénalités de performances mineures pour la plupart des requêtes Druid. Cela peut être activé en définissant IndexSpec.stringDictionaryEncoding sur {"type":"frontCoded", "bucketSize": 4} , où bucketSize est n'importe quelle puissance de 2 inférieure ou égale à 128. La définition de cette propriété demande aux tâches d'indexation d'écrire des segments à l'aide de dictionnaires compressés de la taille de compartiment spécifiée.

Tout segment écrit à l'aide de la compression par dictionnaire de chaînes n'est pas lisible par les anciennes versions de Druid. Pour plus d'informations, voir [Codage avant] (https://druid.apache.org/docs/latest/ingestion/ingestion-spec.html#front-coding). https://github.com/apache/druid/pull/12277

<a name="25-highlights-kubernetes-native-tasks" href="#25-highlights-kubernetes-native-tasks">#</a> Tâches natives Kubernetes

Druid peut désormais utiliser le Kubernetes pour lancer et gérer des tâches, éliminant ainsi le besoin de cadres intermédiaires. Pour utiliser cette fonctionnalité, activez le druid-kubernetes-overlord-extensions dans la liste de chargement des extensions pour votre processus Overlord. https://github.com/apache/druid/pull/13156

<a name="25-highlights-hadoop-3-compatible-binary" href="#25-highlights-hadoop-3-compatible-binary">#</a> Binaire compatible Hadoop-3

Druid est désormais fourni sous forme de binaire dédié aux utilisateurs de Hadoop-3, qui contient des fichiers jar compatibles Hadoop-3. Si vous n'utilisez pas Hadoop-3 avec votre cluster Druid, vous pouvez continuer à utiliser le binaire classique.

Le moteur de requête de tâches MSQ est désormais activé par défaut pour Docker. https://github.com/apache/druid/pull/13069

Les requêtes à plusieurs étapes n'apparaissent plus dans la boîte de dialogue Historique des requêtes. Elles sont toujours disponibles dans le panneau Tâches de requête récentes.

<a name="25-msq-clustered-by-limit" href="#25-msq-clustered-by-limit">#</a> Limite sur les colonnes CLUSTERED BY

Lors de l'utilisation du moteur de tâches MSQ pour ingérer des données, le nombre de colonnes pouvant être transmises dans la clause CLUSTERED BY est désormais limité à 1 500. https://github.com/apache/druid/pull/13352

<a name="25-msq-string-dict" href="#25-msq-string-dict">#</a> Prise en charge de la compression du dictionnaire de chaînes

Le moteur de tâches MSQ prend en charge le codage frontal des dictionnaires String pour une meilleure compression. Cela peut être activé pour les instructions INSERT ou REPLACE en définissant indexSpec sur une chaîne json valide dans le contexte de requête. https://github.com/apache/druid/pull/13275

<a name="25-msq-sketch-merging-mode" href="#25-msq-sketch-merging-mode">#</a> Mode de fusion d'esquisses

Les utilisateurs peuvent désormais collecter des statistiques clés, utilisées pour générer des limites de partition, séquentiellement ou en parallèle. Définissez clusterStatisticsMergeMode sur PARALLEL, SEQUENTIAL ou AUTO dans le contexte de requête pour utiliser le mode de fusion d'esquisses correspondant. Pour plus d'informations, voir [Mode de fusion d'esquisses] (https://druid.apache.org/docs/latest/multi-stage-query/reference.html#sketch-merging-mode). https://github.com/apache/druid/pull/13205

<a name="25-msq-op-improvements" href="#25-msq-op-improvements">#</a> Améliorations des performances et des opérations

  • Messages d'erreur : pour les avertissements MSQ non autorisés de certains types, l'avertissement apparaît désormais comme l'erreur. https://github.com/apache/druid/pull/13198
  • Secrets : Pour les tâches contenant du SQL avec des clés sensibles, Druid masque désormais les clés lors de la journalisation à l'aide des expressions régulières. https://github.com/apache/druid/pull/13231
  • Précision du sous-échantillonnage : le moteur de tâches MSQ utilise désormais le nombre d'octets au lieu du nombre de clés lors du sous-échantillonnage des données. https://github.com/apache/druid/pull/12998
  • Utilisation de la mémoire : lors de la détermination des limites de partition, l'empreinte du tas des croquis internes utilisés par MSQ est désormais plafonnée à 10 % de la mémoire disponible ou à 300 Mo, selon la valeur la plus faible. Auparavant, le plafond était strictement de 300 Mo. https://github.com/apache/druid/pull/13274
  • Rapports de tâches : Ajout des champs pendingTasks et runningTasks au rapport du travailleur. Voir Requête des informations sur l'état de la tâche pour connaître les modifications associées à la console Web. https://github.com/apache/druid/pull/13263

<a name="25-Operations-compaction" href="#25-Operations-compaction">#</a> Compactage

Le comportement du compactage a changé pour améliorer le temps et l'espace disque nécessaires :

  • Lorsque des segments doivent être récupérés, téléchargez-les un par un et supprimez-les lorsque Druid en a terminé avec eux. Cela prend encore du temps mais minimise l'espace disque requis.
  • Ne récupérez pas les segments de la tâche compacte principale lorsqu'ils ne sont pas nécessaires. Si l'utilisateur fournit un granularitySpec, un dimensionsSpec et un metricsSpec complets, Druid ignore la récupération des segments. Pour plus d'informations, consultez la documentation sur Compaction et Compactage automatique. https://github.com/apache/druid/pull/13280

Apache Druid 25.0.0 contains over 300 new features, bug fixes, performance enhancements, documentation improvements, and additional test coverage from 51 contributors.

<a name="25-highlights" href="#25-highlights">#</a> Highlights

<a name="25-highlights-msq" href="#25-highlights-msq-">#</a> MSQ task engine now production ready

The multi-stage query (MSQ) task engine used for SQL-based ingestion is now production ready. Use it for any supported workloads. For more information, see the following pages:

  • Ingestion
  • SQL-based ingestion

<a name="25-highlights-deploying-druid" href="#25-highlights-deploying-druid">#</a> Simplified Druid deployments

The new start-druid script greatly simplifies deploying any combination of Druid services on a single-server. It comes pre-packaged with the required configs and can be used to launch a fully functional Druid cluster simply by invoking ./start-druid. For experienced Druids, it also gives complete control over the runtime properties and JVM arguments to have a cluster that exactly fits your needs.

The start-druid script deprecates the existing profiles such as start-micro-quickstart and start-nano-quickstart. These profiles may be removed in future releases. For more information, see Single server deployment.

<a name="25-highlights-string-dictionary-compression" href="#25-highlights-string-dictionary-compression">#</a> String dictionary compression (experimental)

Added support for front coded string dictionaries for smaller string columns, leading to reduced segment sizes with only minor performance penalties for most Druid queries.

This can be enabled by setting IndexSpec.stringDictionaryEncoding to {"type":"frontCoded", "bucketSize": 4} , where bucketSize is any power of 2 less than or equal to 128. Setting this property instructs indexing tasks to write segments using compressed dictionaries of the specified bucket size.

Any segment written using string dictionary compression is not readable by older versions of Druid.

For more information, see Front coding.

https://github.com/apache/druid/pull/12277

<a name="25-highlights-kubernetes-native-tasks" href="#25-highlights-kubernetes-native-tasks">#</a> Kubernetes-native tasks

Druid can now use Kubernetes to launch and manage tasks, eliminating the need for middle managers.

<a name="25-highlights-hadoop-3-compatible-binary" href="#25-highlights-hadoop-3-compatible-binary">#</a> Hadoop-3 compatible binary

  • Secrets: For tasks containing SQL with sensitive keys, Druid now masks the keys while logging with the help regular expressions. https://github.com/apache/druid/pull/13231

<a name="25-operations-compaction" href="#25-operations-compaction">#</a> Compaction

Compaction behavior has changed to improve the amount of time it takes and disk space it takes:

  • When segments need to be fetched, download them one at a time and delete them when Druid is done with them. This still takes time but minimizes the required disk space.
  • Don't fetch segments on the main compact task when they aren't needed. If the user provides a full granularitySpec, dimensionsSpec, and metricsSpec, Druid skips fetching segments.

For more information, see the documentation on Compaction and Automatic compaction.

https://github.com/apache/druid/pull/13280

<a name="25-operations-batch-allocation" href="#25-operations-batch-allocation">#</a> Batched segment allocation

Segment allocation on the Overlord can take some time to finish, which can cause ingestion lag while a task waits for segments to be allocated. Performing segment allocation in batches can help improve performance.

There are two new properties that affect how Druid performs segment allocation:

| Property | Description | Default | | - | - | - | |druid.indexer.tasklock.batchSegmentAllocation| If set to true, Druid performs segment allocate actions in batches to improve throughput and reduce the average task/action/run/time. See batching segmentAllocate actions for details.|false| |druid.indexer.tasklock.batchAllocationWaitTime|Number of milliseconds after Druid adds the first segment allocate action to a batch, until it executes the batch. Allows the batch to add more requests and improve the average segment allocation run time. This configuration takes effect only if batchSegmentAllocation is enabled.|500|

In addition to these properties, there are new metrics to track batch segment allocation. For more information, see New metrics for segment allocation.

For more information, see the following:

  • Overlord operations
  • Task actions and Batching segmentAllocate actions

https://github.com/apache/druid/pull/13369 https://github.com/apache/druid/pull/13503

The cachingCost balancer strategy now behaves more similarly to cost strategy. When computing the cost of moving a segment to a server, the following calculations are performed:

<a name="25-upgrade" href="#25-upgrade">#</a> Upgrading to 25.0.0

Consider the following changes and updates when upgrading from Druid 24.0.x to 25.0.0. If you're updating from an earlier version, see the release notes of the relevant intermediate versions.

<a name="25-upgrade-segment-discovery" href="#25-upgrade-segment-discovery">#</a> Default HTTP-based segment discovery and task management

The default segment discovery method now uses HTTP instead of ZooKeeper.

This update changes the defaults for the following properties:

| Property | New default | Previous default | | - | - | - | | druid.serverview.type for segment management | http | batch | | druid.coordinator.loadqueuepeon.type for segment management | http | curator | | druid.indexer.runner.type for the Overlord | httpRemote | local |

To use ZooKeeper instead of HTTP, change the values for the properties back to the previous defaults. ZooKeeper-based implementations for these properties are deprecated and will be removed in a subsequent release.

https://github.com/apache/druid/pull/13092

<a name="25-upgrade-hll-and-quantiles-sketches" href="#25-upgrade-hll-and-quantiles-sketches">#</a> Finalizing HLL and quantiles sketch aggregates

The aggregation functions for HLL and quantiles sketches returned sketches or numbers when they are finalized depending on where they were in the native query plan.

Druid no longer finalizes aggregators in the following two cases:

  • aggregators appear in the outer level of a query
  • aggregators are used as input to an expression or finalizing-field-access post-aggregator

This change aligns the behavior of HLL and quantiles sketches with theta sketches.

To restore old behaviour, you can set sqlFinalizeOuterSketches=true in the query context.

https://github.com/apache/druid/pull/13247

<a name="25-upgrade-kill-tasks-mark-unused" href="#25-upgrade-kill-tasks-mark-unused">#</a> Kill tasks mark segments as unused only if specified

When you issue a kill task, Druid marks the underlying segments as unused only if explicitly specified. For more information, see the API reference

https://github.com/apache/druid/pull/13104
