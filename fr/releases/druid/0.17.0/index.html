druide druide-0.17.0

Apache Druid 0.17.0 contient plus de 250 nouvelles fonctionnalités, améliorations de performances, corrections de bogues et améliorations majeures de la documentation provenant de 52 contributeurs. Consultez la [liste complète des modifications] (https://github.com/apache/incubator-druid/compare/0.16.1-incubating...0.17.0-incubating) et [tout ce qui est associé au jalon] (https://github.com/apache/incubator-druid/milestone/35).

Faits saillants

Améliorations de l'ingestion par lots

Druid 0.17.0 inclut une mise à jour importante du système natif d’ingestion par lots. Cette mise à jour ajoute le cadre interne pour prendre en charge les formats binaires non textuels, avec une prise en charge initiale d'ORC et Parquet. De plus, les tâches par lots natives peuvent désormais lire les données de HDFS. Cette refonte modifie la manière dont la source d'ingestion et le format des données sont spécifiés dans la tâche d'ingestion. Pour utiliser les nouvelles fonctionnalités, veuillez vous référer à la documentation sur InputSources et InputFormats. Veuillez consulter la documentation suivante pour plus de détails : https://druid.apache.org/docs/0.17.0/ingestion/data-formats.html#input-format https://druid.apache.org/docs/0.17.0/ingestion/native-batch.html#input-sources https://druid.apache.org/docs/0.17.0/ingestion/native-batch.html#partitionsspec https://github.com/apache/druid/issues/8812

Partitionnement de plage à dimension unique pour l'ingestion de lots natifs parallèles

La tâche d'index parallèle prend désormais en charge la spécification de partitions de type single_dim, qui permet un partitionnement basé sur une plage sur une seule dimension. Veuillez consulter https://druid.apache.org/docs/0.17.0/ingestion/native-batch.html pour plus de détails.

Modifications du compactage

Conseils de répartition des tâches d'index parallèle

La tâche d'indexation parallèle a désormais une nouvelle configuration, splitHintSpec, dans le tuningConfig pour permettre aux opérateurs de fournir des conseils pour contrôler la quantité de données lues par chaque sous-tâche de première phase. Il existe actuellement un type de spécification d'indice partagé, SegmentsSplitHintSpec, utilisé pour réingérer les segments Druid.

Compactage automatique parallèle

Le compactage automatique peut désormais utiliser la tâche d'indexation parallèle, permettant un plus grand débit de compactage. Pour contrôler le niveau de parallélisme, l'auto-compactiontuningConfig dispose de nouveaux paramètres, maxNumConcurrentSubTasks et splitHintSpec. Veuillez consulter https://druid.apache.org/docs/0.17.0/configuration/index.html#compaction-dynamic-configuration pour plus de détails. https://github.com/apache/incubator-druid/pull/8570 ### Compaction automatique avec état Le compactage automatique utilise désormais partitionSpec pour suivre les modifications apportées par les tâches de compactage précédentes, permettant au coordinateur de réduire les opérations de compactage redondantes. Veuillez consulter https://github.com/apache/druid/issues/8489 pour plus de détails. Si le compactage automatique est activé, veuillez consulter les informations sous « Modifications du compactage automatique avec état » dans la section « Mise à niveau vers Druid 0.17.0 » avant la mise à niveau.

Fusion de requêtes parallèles sur les courtiers

Le courtier Druid peut désormais fusionner de manière opportuniste les résultats des requêtes en parallèle à l’aide de plusieurs threads. Veuillez consulter druid.processing.merge.useParallelMergePool dans la section Broker de la [référence de configuration] (https://druid.apache.org/docs/0.17.0/configuration/index.html) pour plus de détails sur la façon de configurer cette nouvelle fonctionnalité. La fusion parallèle est activée par défaut (contrôlée par la propriété druid.processing.merge.useParallelMergePool) et la plupart des utilisateurs ne devraient pas avoir à modifier les propriétés de configuration avancées décrites dans la référence de configuration. De plus, le parallélisme de fusion peut être contrôlé requête par requête à l’aide du contexte de requête. Des informations sur les nouveaux paramètres de contexte de requête sont disponibles sur https://druid.apache.org/docs/0.17.0/querying/query-context.html. https://github.com/apache/incubator-druid/pull/8578

Gestion des valeurs nulles compatible SQL

Dans 0.17.0, nous avons ajouté une documentation officielle pour le mode de gestion des valeurs nulles compatible SQL de Druid. Veuillez consulter https://druid.apache.org/docs/0.17.0/configuration/index.html#sql-compatible-null-handling et https://druid.apache.org/docs/0.17.0/design/segments.html#sql-compatible-null-handling pour plus de détails. Plusieurs bugs qui existaient dans ce mode jusqu'alors non documenté ont été corrigés, notamment autour de la gestion des valeurs nulles dans les colonnes numériques. Nous recommandons aux utilisateurs de commencer à envisager de faire passer leurs clusters vers ce nouveau mode après la mise à niveau vers 0.17.0. La liste complète des bogues de gestion des valeurs nulles corrigés dans 0.17.0 peut être trouvée sur https://github.com/apache/druid/issues?utf8=%E2%9C%93&q=label%3A%22Area+-+Null+Handling%22+milestone%3A0.17.0+.

Extension LDAP

Druid prend désormais en charge l'authentification LDAP. L'autorisation à l'aide de groupes LDAP est également prise en charge en mappant les groupes LDAP aux rôles Druid.

  • L'authentification LDAP est gérée en spécifiant un validateur d'informations d'identification de type LDAP.
  • L'autorisation à l'aide de LDAP est gérée en spécifiant un fournisseur de rôles de type LDAP et en définissant les mappages de rôles groupe LDAP -> Druid dans Druid. L'intégration LDAP nécessite l'extension principale druid-basic-security. Veuillez consulter https://druid.apache.org/docs/0.17.0/development/extensions-core/druid-basic-security.html pour plus de détails. Comme il s'agit de la première version prenant en charge LDAP et qu'il existe une grande variété d'écosystèmes LDAP, certains cas d'utilisation et fonctionnalités LDAP peuvent ne pas être encore pris en charge. Veuillez signaler un problème si vous avez besoin d'améliorations de cette nouvelle fonctionnalité. https://github.com/apache/incubator-druid/pull/6972

Émetteur Dropwizard

Un nouvel émetteur de métriques Dropwizard a été ajouté en tant qu'extension de contribution. Les types de métriques Dropwizard actuellement pris en charge sont le compteur, la jauge, le compteur, la minuterie et l'histogramme. Ces métriques peuvent être émises à l'aide d'une console ou d'un rapporteur JMX. Veuillez consulter https://druid.apache.org/docs/0.17.0/design/extensions-contrib/dropwizard.html pour plus de détails. https://github.com/apache/incubator-druid/pull/7363

Ressource de découverte de soi

Une nouvelle paire de points de terminaison a été ajoutée à tous les services Druid qui renvoient des informations indiquant si le service Druid a reçu une confirmation que le service a été ajouté au cluster, du mécanisme central de découverte de service (actuellement ZooKeeper). Ces points de terminaison peuvent être utiles en tant que contrôles de santé/prêts. Les nouveaux points de terminaison sont : -/status/selfDiscovered/status -/status/selfDiscovered Veuillez consulter le Druide [référence API] (https://druid.apache.org/docs/0.17.0/operations/api-reference.html) pour plus de détails. https://github.com/apache/incubator-druid/pull/6702 https://github.com/apache/incubator-druid/pull/9005

Table système des superviseurs

Les superviseurs de tâches (par exemple les superviseurs Kafka ou Kinesis) sont désormais enregistrés dans les tables système dans une nouvelle table sys.supervisors. Veuillez consulter https://druid.apache.org/docs/0.17.0/querying/sql.html#supervisors-table pour plus de détails. https://github.com/apache/incubator-druid/pull/8547

Démarrage historique rapide avec chargement paresseux

Une nouvelle propriété de configuration booléenne pour les historiques, druid.segmentCache.lazyLoadOnStart, a été ajoutée. Cette nouvelle propriété permet aux historiques de différer le chargement d'un segment jusqu'à la première interrogation de ce segment, ce qui peut réduire considérablement les temps de démarrage de l'historique pour les clusters comportant un grand nombre de segments. Veuillez consulter la référence de configuration pour plus de détails. https://github.com/apache/incubator-druid/pull/6988

Modification de la distribution du cache des segments historiques

Une nouvelle propriété historique, druid.segmentCache.locationSelectorStrategy, a été ajoutée. Si plusieurs emplacements de stockage de segments sont spécifiés dans druid.segmentCache.locations, la nouvelle propriété locationSelectorStrategy permet à l'utilisateur de spécifier la stratégie utilisée pour remplir les emplacements. Les options actuellement prises en charge sont roundRobin et leastBytesUsed. Veuillez consulter la référence de configuration pour plus de détails. https://github.com/apache/incubator-druid/pull/8038

Nouveaux points de terminaison de préparation

Un nouveau point de terminaison Broker a été ajouté : /druid/broker/v1/readiness. Un nouveau point de terminaison historique a été ajouté : /druid/historical/v1/readiness. Ces points de terminaison sont similaires aux points de terminaison /druid/broker/v1/loadstatus et /druid/historical/v1/loadstatus existants. Ils diffèrent en ce sens qu'ils ne nécessitent pas de contrôles d'authentification/autorisation et qu'au lieu d'un corps JSON, ils renvoient uniquement un code de réponse HTTP 200 succès ou 503. https://github.com/apache/incubator-druid/pull/8841

Affectation des tâches de support en fonction des catégories MiddleManager

Il est désormais possible de définir une propriété de nom « catégorie » pour chaque MiddleManager. De nouvelles stratégies de sélection des travailleurs prenant en compte les catégories ont été ajoutées, permettant à l'utilisateur de contrôler la manière dont les tâches sont attribuées aux MiddleManagers en fonction des catégories configurées. Veuillez consulter la documentation du druid.worker.category dans la [référence de configuration] (https://druid.apache.org/docs/0.17.0/configuration/index.html) et les liens suivants pour plus de détails : https://druid.apache.org/docs/0.17.0/configuration/index.htmlEqual-Distribution-With-Category-Spec https://druid.apache.org/docs/0.17.0/configuration/index.html#Fill-Capacity-With-Category-Spec https://druid.apache.org/docs/0.17.0/configuration/index.html#WorkerCategorySpec https://github.com/apache/druid/pull/7066

Mises à jour des vulnérabilités de sécurité

Un grand nombre de dépendances ont été mises à jour vers des versions plus récentes pour corriger les vulnérabilités de sécurité. Veuillez consulter les PR ci-dessous pour plus de détails : -https://github.com/apache/incubator-druid/pull/8878 -https://github.com/apache/incubator-druid/pull/8980

Mise à niveau vers Druid 0.17.0

La requête native sélectionnée a été remplacée

Le type de requête natif Select, obsolète, a été supprimé dans 0.17.0. Si vous disposez de requêtes natives qui utilisent Select, vous devez les modifier pour utiliser Scan à la place. Consultez la documentation sur les requêtes d'analyse (https://druid.apache.org/docs/0.17.0/querying/scan-query.html) pour plus de détails sur la syntaxe et le format de sortie. Pour les requêtes Druid SQL qui utilisent Select, aucune modification n’est nécessaire ; le planificateur SQL utilise déjà le type de requête Scan sous les couvertures pour les requêtes Select. https://github.com/apache/incubator-druid/pull/8739

Les anciennes consoles ont été supprimées

Les anciennes consoles de coordinateur et de suzerain ont été supprimées et remplacées par la nouvelle console Web sur le coordinateur et le suzerain. https://github.com/apache/incubator-druid/pull/8838

Mise à niveau de Calcite 1.21, gestion des valeurs nulles Druid SQL

Druid 0.17.0 met à jour Calcite vers la version 1.21. Cette version plus récente de Calcite peut effectuer des optimisations supplémentaires qui supposent un comportement de gestion des valeurs nulles conforme à SQL lors de la planification des requêtes. Si vous utilisez Druid SQL et comptez sur un comportement de gestion des valeurs nulles, veuillez lire les informations sur https://druid.apache.org/docs/0.17.0/configuration/index.html#sql-compatible-null-handling et assurez-vous que votre cluster Druid s'exécute en mode de gestion des valeurs nulles conforme à SQL avant la mise à niveau. https://github.com/apache/incubator-druid/pull/8566

Ajustements de journalisation

Druid 0.17.0 a rangé son cycle de vie, ses requêtes et sa journalisation d'ingestion. Veuillez consulter https://github.com/apache/incubator-druid/pull/8889 pour une liste détaillée des modifications. Si vous vous êtes appuyé sur des messages de journal spécifiques pour les intégrations externes, veuillez consulter les nouvelles modifications de journalisation avant la mise à niveau. L’ensemble complet des messages du journal est toujours visible lorsque la journalisation est définie au niveau DEBUG. Les fichiers de configuration du modèle log4j2 qui montrent comment activer la journalisation DEBUG par package sont fournis dans le dossier de configuration _common dans les exemples de clusters sous conf/druid.

Modifications du compactage automatique avec état

La logique de planification du compactage automatique du 0.17.0 suit les informations de partitionnement de segments supplémentaires dans le magasin de métadonnées de Druid qui ne sont pas présentes dans les anciennes versions. Ces informations sont utilisées pour déterminer si un ensemble de segments a déjà été compacté selon les configurations de compactage automatique actuelles du cluster. Lorsque ces nouvelles métadonnées ne sont pas présentes, un ensemble de segments sera toujours planifié pour un compactage initial et ces nouvelles métadonnées seront créées après leur compactage, permettant au planificateur de les ignorer ultérieurement si la configuration du compactage automatique reste inchangée. Étant donné que ces métadonnées supplémentaires de partitionnement de segments ne sont pas présentes avant 0.17.0, la logique de planification de compactage automatique recompactera tous les segments d'une source de données une fois après la mise à niveau vers 0.17.0. Ce recompactage sur l'ensemble des segments pour chaque source de données pour laquelle le compactage automatique est activé signifie que :

  • Il y aura une période de transition après la mise à niveau au cours de laquelle davantage de tâches de compactage totales seront mises en file d'attente que dans des conditions normales.
  • L'utilisation du stockage profond augmentera à mesure que l'ensemble de segments sera recompacté (l'ancien ensemble de segments est toujours conservé dans le stockage profond à moins qu'il ne soit explicitement supprimé). Il est conseillé aux utilisateurs d'être conscients de l'augmentation temporaire des tâches de compactage planifiées et de l'impact sur l'utilisation du stockage en profondeur. La documentation sur la suppression des anciens segments se trouve sur https://druid.apache.org/docs/0.17.0/ingestion/data-management.html#deleting-data

Propriété targetCompactionSizeBytes supprimée

La propriété targetCompactionSizeBytes a été supprimée de la tâche de compactage et de la configuration du compactage automatique. Pour l'auto-compaction, maxRowsPerSegment est désormais une configuration obligatoire. Pour les tâches de compactage non automatique, n'importe quel partitionsSpec peut être utilisé. https://github.com/apache/incubator-druid/pull/8573

Réglage de la tâche de compactageConfig

En raison des modifications de compactage automatique parallèle introduites par #8570, toutes les spécifications de tâche de compactage soumises manuellement doivent être mises à jour pour utiliser un type index_parallel pour la section tuningConfig au lieu d'index. Ces modifications de spécifications doivent être appliquées après la mise à niveau du cluster vers 0.17.0. Les configurations de compactage automatique existantes peuvent rester inchangées après la mise à jour ; le compactage automatique créera des tâches de compactage non parallèles jusqu'à ce que les configurations de compactage automatique soient mises à jour pour utiliser le parallélisme après la mise à niveau. Pour contrôler le niveau de parallélisme, l'auto-compactiontuningConfig dispose de nouveaux paramètres, maxNumConcurrentSubTasks et splitHintSpec. Veuillez consulter https://druid.apache.org/docs/0.17.0/configuration/index.html#compaction-dynamic-configuration pour plus de détails.

Tâche de compactage ioConfig

La tâche de compactage nécessite désormais un ioConfig dans la spécification de la tâche. Veuillez consulter le https://druid.apache.org/docs/0.17.0/ingestion/data-management.html#compaction-ioconfig pour plus de détails. ioConfig n'a pas besoin d'être ajouté aux configurations d'auto-compactage existantes, le coordinateur après la mise à niveau créera automatiquement des spécifications de tâches avec des sections ioConfig. https://github.com/apache/incubator-druid/pull/8571

Champs de spécification de partition renommés

Les champs targetPartitionSize et maxSegmentSize dans les spécifications de partition sont obsolètes. Ils ont été renommés respectivement targetNumRowsPerSegment et maxRowsPerSegment. https://github.com/apache/incubator-druid/pull/8507

Les métriques du cache sont désactivées par défaut

Les métriques du cache sont désormais désactivées par défaut. Pour activer les métriques de cache, ajoutez "org.apache.druid.client.cache.CacheMonitor" à la propriété druid.monitoring.monitors. https://github.com/apache/incubator-druid/pull/8561

Le superviseur API a été modifié pour être cohérent avec la tâche API

Les spécifications des tâches du superviseur doivent désormais placer les sections dataSchema, tuningConfig et ioConfig comme sous-champs d'un champ spec. Veuillez consulter https://github.com/apache/incubator-druid/pull/8810 pour des exemples. L'ancien format est toujours accepté dans 0.17.0.

Segments API changement de sémantique

Le point de terminaison /datasources/{dataSourceName}/segments sur le coordinateur renvoie désormais tous les segments utilisés (y compris ceux masqués) sur les intervalles spécifiés, plutôt que uniquement ceux visibles. https://github.com/apache/incubator-druid/pull/8564

Fournisseur de mot de passe pour l'authentification de base de HttpEmitterConfig

La propriété druid.emitter.http.basicAuthentication accepte désormais un fournisseur de mot de passe. Nous vous recommandons de mettre à jour vos configurations pour utiliser un fournisseur de mots de passe si vous utilisez l'émetteur HTTP. https://github.com/apache/incubator-druid/pull/8618

Changement de transformation d'expression à valeurs multiples

La réutilisation de colonnes à valeurs multiples dans les expressions n'entraînera plus d'explosions cartésiennes inutiles. Veuillez consulter les liens suivants pour plus de détails. https://github.com/apache/druid/issues/8947 https://github.com/apache/incubator-druid/pull/8957

Ingestion Kafka/Kinesis lors des mises à niveau progressives

Lors d'une mise à niveau continue, s'il y a des tâches exécutant 0.17.0 et des overlords exécutant des versions plus anciennes, et qu'une tâche a progressé dans la lecture des données de son flux mais a rejeté tous les enregistrements qu'elle a vus (par exemple, tous n'étaient pas analysables), vous verrez des NullPointerExceptions sur les overlords exécutant des versions plus anciennes lorsque la tâche met à jour le overlord avec ses décalages de flux actuels. Auparavant, il y avait un bug dans cette zone (https://github.com/apache/incubator-druid/issues/8765) où de telles tâches ne parvenaient pas à communiquer leurs décalages actuels au suzerain. Le protocole de publication des tâches/overlord a été mis à jour pour résoudre ce problème, mais les anciens overlords ne reconnaissent pas ce changement de protocole. Cette condition devrait être assez rare.

Changement de version Hadoop par défaut

Druid 0.17.0 regroupe désormais les bibliothèques Hadoop 2.8.5 au lieu de 2.8.3. Si vous faisiez référence aux bibliothèques 2.8.3 groupées dans votre configuration via la propriété druid.indexer.task.defaultHadoopCoordinates ou la propriété hadoopDependencyCoordinates dans vos spécifications d'ingestion Hadoop, vous devrez mettre à jour ces références pour qu'elles pointent plutôt vers les bibliothèques 2.8.5 groupées.

Méthode ParseSpec.verify supprimée

Si vous conserviez une extension personnalisée qui fournit une implémentation pour l'interface ParseSpec, la méthode verify a été supprimée et l'annotation @Override sur la méthode devra être supprimée dans toutes les implémentations personnalisées. https://github.com/apache/druid/pull/8744

Problèmes connus

Filtrage sur les colonnes longues en mode de gestion des valeurs nulles compatible SQL

Nous sommes actuellement conscients d'un bug lié à l'application de certains types de filtres sur les valeurs nulles des colonnes longues lorsque la gestion des valeurs nulles compatible SQL est activée (https://github.com/apache/druid/issues/9255). Veuillez signaler un problème si vous rencontrez d'autres problèmes de gestion des valeurs nulles.

Aperçu des spécifications d'ingestion dans la console Web

Les spécifications d'aperçu affichées pour les tâches d'ingestion par lots natives créées dans le chargeur de données de la console Web ne sont pas correctement formatées et échoueront si vous les copiez et les soumettez manuellement. Cependant, la soumission de ces spécifications via Data Loader soumet une spécification correctement formatée. https://github.com/apache/druid/issues/9144

Autres problèmes connus

Pour une liste complète des problèmes ouverts, veuillez consulter https://github.com/apache/druid/labels/Bug

druid druid-0.17.0

Apache Druid 0.17.0 contains over 250 new features, performance enhancements, bug fixes, and major documentation improvements from 52 contributors. Check out the complete list of changes and everything tagged to the milestone.

Highlights

Batch ingestion improvements

Druid 0.17.0 includes a significant update to the native batch ingestion system. This update adds the internal framework to support non-text binary formats, with initial support for ORC and Parquet. Additionally, native batch tasks can now read data from HDFS.

This rework changes how the ingestion source and data format are specified in the ingestion task. To use the new features, please refer to the documentation on InputSources and InputFormats.

Please see the following documentation for details: https://druid.apache.org/docs/0.17.0/ingestion/data-formats.html#input-format https://druid.apache.org/docs/0.17.0/ingestion/native-batch.html#input-sources https://druid.apache.org/docs/0.17.0/ingestion/native-batch.html#partitionsspec

https://github.com/apache/druid/issues/8812

Single dimension range partitioning for parallel native batch ingestion

The parallel index task now supports the single_dim type partitions spec, which allows for range-based partitioning on a single dimension.

Please see https://druid.apache.org/docs/0.17.0/ingestion/native-batch.html for details.

Compaction changes

Parallel index task split hints

The parallel indexing task now has a new configuration, splitHintSpec, in the tuningConfig to allow for operators to provide hints to control the amount of data that each first phase subtask reads. There is currently one split hint spec type, SegmentsSplitHintSpec, used for re-ingesting Druid segments.

Parallel auto-compaction

Auto-compaction can now use the parallel indexing task, allowing for greater compaction throughput.

To control the level of parallelism, the auto-compactiontuningConfig has new parameters, maxNumConcurrentSubTasks and splitHintSpec.

Please see https://druid.apache.org/docs/0.17.0/configuration/index.html#compaction-dynamic-configuration for details.

https://github.com/apache/incubator-druid/pull/8570

Stateful auto-compaction

Auto-compaction now uses the partitionSpec to track changes made by previous compaction tasks, allowing the coordinator to reduce redundant compaction operations.

Please see https://github.com/apache/druid/issues/8489 for details.

If you have auto-compaction enabled, please see the information under "Stateful auto-compaction changes" in the "Upgrading to Druid 0.17.0" section before upgrading.

Parallel query merging on brokers

The Druid broker can now opportunistically merge query results in parallel using multiple threads.

Please see druid.processing.merge.useParallelMergePool in the Broker section of the configuration reference for details on how to configure this new feature.

Parallel merging is enabled by default (controlled by the druid.processing.merge.useParallelMergePool property), and most users should not have to change any of the advanced configuration properties described in the configuration reference.

Additionally, merge parallelism can be controlled on a per-query basis using the query context. Information about the new query context parameters can be found at https://druid.apache.org/docs/0.17.0/querying/query-context.html.

https://github.com/apache/incubator-druid/pull/8578

SQL-compatible null handling

In 0.17.0, we have added official documentation for Druid's SQL-compatible null handling mode.

Please see https://druid.apache.org/docs/0.17.0/configuration/index.html#sql-compatible-null-handling and https://druid.apache.org/docs/0.17.0/design/segments.html#sql-compatible-null-handling for details.

Several bugs that existed in this previously undocumented mode have been fixed, particularly around null handling in numeric columns. We recommend that users begin to consider transitioning their clusters to this new mode after upgrading to 0.17.0.

The full list of null handling bugs fixed in 0.17.0 can be found at https://github.com/apache/druid/issues?utf8=%E2%9C%93&q=label%3A%22Area+-+Null+Handling%22+milestone%3A0.17.0+

LDAP extension

Druid now supports LDAP authentication. Authorization using LDAP groups is also supported by mapping LDAP groups to Druid roles.

  • LDAP authentication is handled by specifying an LDAP-type credentials validator.
  • Authorization using LDAP is handled by specifying an LDAP-type role provider, and defining LDAP group->Druid role mappings within Druid.

LDAP integration requires the druid-basic-security core extension. Please see https://druid.apache.org/docs/0.17.0/development/extensions-core/druid-basic-security.html for details.

As this is the first release with LDAP support, and there are a large variety of LDAP ecosystems, some LDAP use cases and features may not be supported yet. Please file an issue if you need enhancements to this new functionality.

https://github.com/apache/incubator-druid/pull/6972

Dropwizard emitter

A new Dropwizard metrics emitter has been added as a contrib extension.

The currently supported Dropwizard metrics types are counter, gauge, meter, timer and histogram. These metrics can be emitted using either a Console or JMX reporter.

Please see https://druid.apache.org/docs/0.17.0/design/extensions-contrib/dropwizard.html for details.

https://github.com/apache/incubator-druid/pull/7363

Self-discovery resource

A new pair of endpoints have been added to all Druid services that return information about whether the Druid service has received a confirmation that the service has been added to the cluster, from the central service discovery mechanism (currently ZooKeeper). These endpoints can be useful as health/ready checks.

The new endpoints are:

  • /status/selfDiscovered/status
  • /status/selfDiscovered

Please see the Druid API reference for details.

https://github.com/apache/incubator-druid/pull/6702 https://github.com/apache/incubator-druid/pull/9005

Supervisors system table

Task supervisors (e.g. Kafka or Kinesis supervisors) are now recorded in the system tables in a new sys.supervisors table.

Please see https://druid.apache.org/docs/0.17.0/querying/sql.html#supervisors-table for details.

https://github.com/apache/incubator-druid/pull/8547

Fast historical start with lazy loading

A new boolean configuration property for historicals, druid.segmentCache.lazyLoadOnStart, has been added.

This new property allows historicals to defer loading of a segment until the first time that segment is queried, which can significantly decrease historical startup times for clusters with a large number of segments.

Please see the configuration reference for details.

https://github.com/apache/incubator-druid/pull/6988

Historical segment cache distribution change

A new historical property, druid.segmentCache.locationSelectorStrategy, has been added.

If there are multiple segment storage locations specified in druid.segmentCache.locations, the new locationSelectorStrategy property allows the user to specify what strategy is used to fill the locations. Currently supported options are roundRobin and leastBytesUsed.

Please see the configuration reference for details.

https://github.com/apache/incubator-druid/pull/8038

New readiness endpoints

A new Broker endpoint has been added: /druid/broker/v1/readiness.

A new Historical endpoint has been added: /druid/historical/v1/readiness.

These endpoints are similar to the existing /druid/broker/v1/loadstatus and /druid/historical/v1/loadstatus endpoints.

They differ in that they do not require authentication/authorization checks, and instead of a JSON body they only return a 200 success or 503 HTTP response code.

https://github.com/apache/incubator-druid/pull/8841

Support task assignment based on MiddleManager categories

It is now possible to define a "category" name property for each MiddleManager. New worker select strategies that are category-aware have been added, allowing the user to control how tasks are assigned to MiddleManagers based on the configured categories.

Please see the documentation for druid.worker.category in the configuration reference, and the following links, for more details: https://druid.apache.org/docs/0.17.0/configuration/index.htmlEqual-Distribution-With-Category-Spec https://druid.apache.org/docs/0.17.0/configuration/index.html#Fill-Capacity-With-Category-Spec https://druid.apache.org/docs/0.17.0/configuration/index.html#WorkerCategorySpec

https://github.com/apache/druid/pull/7066

Security vulnerability updates

A large number of dependencies have been updated to newer versions to address security vulnerabilities.

Please see the PRs below for details:

  • https://github.com/apache/incubator-druid/pull/8878
  • https://github.com/apache/incubator-druid/pull/8980

Upgrading to Druid 0.17.0

Select native query has been replaced

The deprecated Select native query type has been removed in 0.17.0.

If you have native queries that use Select, you need to modify them to use Scan instead. See the Scan query documentation (https://druid.apache.org/docs/0.17.0/querying/scan-query.html) for syntax and output format details.

For Druid SQL queries that use Select, no changes are needed; the SQL planner already uses the Scan query type under the covers for Select queries.

https://github.com/apache/incubator-druid/pull/8739

Old consoles have been removed

The legacy coordinator and overlord consoles have been removed, and they have been replaced with the new web console on the coordinator and overlord.

https://github.com/apache/incubator-druid/pull/8838

Calcite 1.21 upgrade, Druid SQL null handling

Druid 0.17.0 updates Calcite to version 1.21. This newer version of Calcite can make additional optimizations that assume SQL-compliant null handling behavior when planning queries.

If you use Druid SQL and rely on null handling behavior, please read the information at https://druid.apache.org/docs/0.17.0/configuration/index.html#sql-compatible-null-handling and ensure that your Druid cluster is running in the SQL-compliant null handling mode before upgrading.

https://github.com/apache/incubator-druid/pull/8566

Logging adjustments

Druid 0.17.0 has tidied up its lifecycle, querying, and ingestion logging.

Please see https://github.com/apache/incubator-druid/pull/8889 for a detailed list of changes. If you relied on specific log messages for external integrations, please review the new logging changes before upgrading.

The full set of log messages can still be seen when logging is set to DEBUG level. Template log4j2 configuration files that show how to enable per-package DEBUG logging are provided in the _common configuration folder in the example clusters under conf/druid.

Stateful auto-compaction changes

The auto-compaction scheduling logic in 0.17.0 tracks additional segment partitioning information in Druid's metadata store that is not present in older versions. This information is used to determine whether a set of segments has already been compacted under the cluster's current auto-compaction configurations.

When this new metadata is not present, a set of segments will always be scheduled for an initial compaction and this new metadata will be created after they are compacted, allowing the scheduler to skip them later if auto-compaction config is unchanged.

Since this additional segment partitioning metadata is not present before 0.17.0, the auto-compaction scheduling logic will re-compact all segments within a datasource once after the upgrade to 0.17.0.

This re-compaction on the entire set of segments for each datasource that has auto-compaction enabled means that:

  • There will be a transition period after the upgrade where more total compaction tasks will be queued than under normal conditions
  • The deep storage usage will increase as the entire segment set is re-compacted (the old set of segments is still kept in deep storage unless explicitly removed).

Users are advised to be aware of the temporary increase in scheduled compaction tasks and the impact on deep storage usage. Documentation on removing old segments is located at https://druid.apache.org/docs/0.17.0/ingestion/data-management.html#deleting-data

targetCompactionSizeBytes property removed

The targetCompactionSizeBytes property has been removed from the compaction task and auto-compaction configuration. For auto-compaction, maxRowsPerSegment is now a mandatory configuration. For non-auto compaction tasks, any partitionsSpec can be used.

https://github.com/apache/incubator-druid/pull/8573

Compaction task tuningConfig

Due to the parallel auto-compaction changes introduced by #8570, any manually submitted compaction task specs need to be updated to use an index_parallel type for the tuningConfig section instead of index. These spec changes should be applied after the cluster is upgraded to 0.17.0.

Existing auto-compaction configs can remain unchanged after the update; the auto-compaction will create non-parallel compaction tasks until the auto-compaction configs are updated to use parallelism post-upgrade.

To control the level of parallelism, the auto-compactiontuningConfig has new parameters, maxNumConcurrentSubTasks and splitHintSpec.

Please see https://druid.apache.org/docs/0.17.0/configuration/index.html#compaction-dynamic-configuration for details.

Compaction task ioConfig

The compaction task now requires an ioConfig in the task spec.

Please see https://druid.apache.org/docs/0.17.0/ingestion/data-management.html#compaction-ioconfig for details.

ioConfig does not have to be added to existing auto-compaction configurations, the coordinator after the upgrade will automatically create task specs with ioConfig sections.

https://github.com/apache/incubator-druid/pull/8571

Renamed partition spec fields

The targetPartitionSize and maxSegmentSize fields in the partition specs have been deprecated. They have been renamed to targetNumRowsPerSegment and maxRowsPerSegment respectively.

https://github.com/apache/incubator-druid/pull/8507

Cache metrics are off by default

Cache metrics are now disabled by default. To enable cache metrics, add "org.apache.druid.client.cache.CacheMonitor" to the druid.monitoring.monitors property.

https://github.com/apache/incubator-druid/pull/8561

Supervisor API has changed to be consistent with task API

Supervisor task specs should now put the dataSchema, tuningConfig, and ioConfig sections as subfields of a spec field. Please see https://github.com/apache/incubator-druid/pull/8810 for examples.

The old format is still accepted in 0.17.0.

Segments API semantics change

The /datasources/{dataSourceName}/segments endpoint on the Coordinator now returns all used segments (including overshadowed) on the specified intervals, rather than only visible ones.

https://github.com/apache/incubator-druid/pull/8564

Password provider for basic authentication of HttpEmitterConfig

The druid.emitter.http.basicAuthentication property now accepts a password provider. We recommend updating your configurations to use a password provider if using the HTTP emitter.

https://github.com/apache/incubator-druid/pull/8618

Multivalue expression transformation change

Reusing multi-valued columns in expressions will no longer result in unnecessary cartesian explosions. Please see the following links for details.

https://github.com/apache/druid/issues/8947 https://github.com/apache/incubator-druid/pull/8957

Kafka/Kinesis ingestion during rolling upgrades

During a rolling upgrade, if there are tasks running 0.17.0 and overlords running older versions, and a task made progress reading data from its stream but rejected all the records it saw (e.g., all were unparseable), you will see NullPointerExceptions on overlords running older versions when the task updates the overlord with its current stream offsets.

Previously, there was a bug in this area (https://github.com/apache/incubator-druid/issues/8765) where such tasks would fail to communicate their current offsets to the overlord. The task/overlord publishing protocol has been updated to fix this, but older overlords do not recognize this protocol change.

This condition should be fairly rare.

Default Hadoop version change

Druid 0.17.0 now bundles Hadoop 2.8.5 libraries instead of 2.8.3.

If you were referencing the bundled 2.8.3 libraries in your configuration via the druid.indexer.task.defaultHadoopCoordinates property, or the hadoopDependencyCoordinates property in your Hadoop ingestion specs, you will need to update these references to point to the bundled 2.8.5 libraries instead.

ParseSpec.verify method removed

If you were maintaining a custom extension that provides an implementation for the ParseSpec interface, the verify method has been removed, and the @Override annotation on the method will need to be removed in any custom implementations.

https://github.com/apache/druid/pull/8744

Known issues

Filtering on long columns in SQL-compatible null handling mode

We are currently aware of a bug with applying certain filter types on null values from long columns when SQL-compatible null handling is enabled (https://github.com/apache/druid/issues/9255).

Please file an issue if you encounter any other null handling problems.

Ingestion spec preview in web console

The preview specs shown for native batch ingestion tasks created in the Data Loader of the web console are not correctly formatted and will fail if you copy them and submit them manually. Submitting these specs through the Data Loader submits a correctly formatted spec, however.

https://github.com/apache/druid/issues/9144

Other known issues

For a full list of open issues, please see https://github.com/apache/druid/labels/Bug
