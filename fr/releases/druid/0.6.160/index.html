druid 0.6.160

Correctif Publié4 nov. 2014 Sourceapache/druid Anglais original

Cette page est traduite automatiquement. Le texte anglais original fait foi.

druide druide-0.6.160

Améliorations

  • Les nœuds de courtier ne démarrent désormais qu'après avoir lu toutes les informations sur les segments dans Zookeeper
  • Les requêtes groupBy imbriquées devraient désormais fonctionner avec les agrégations de publications.
  • Les requêtes groupBy imbriquées devraient désormais fonctionner avec des métriques complexes.
  • Le seigneur du service d'indexation peut désormais attribuer des tâches aux travailleurs en fonction de stratégies.
  • Le Firehose local peut désormais trouver tous les fichiers d'un répertoire.
  • L'horodatage et les métriques sont désormais automatiquement ajoutés aux exclusions de dimensions.
  • Amélioration de la gestion des pannes lors des transferts en temps réel.
  • Téléchargement parallèle de segments. Plusieurs threads peuvent désormais être utilisés pour télécharger des segments à partir du stockage profond.
  • Les segments peuvent être annoncés et interrogés lors du chargement initial d'un nœud.
  • Agrégateurs filtrés natifs pour les filtres de type sélecteur
  • La stratégie de sélection de courtier personnalisée pour le routeur peut désormais être écrite en JavaScript ##Documents
  • Exemple de configuration Hadoop maintenant disponible
  • Meilleures pratiques et recommandations désormais mises à jour
  • Le nœud Experimental Router est désormais documenté (druid.io/docs/latest/Router.html).
  • La lance à incendie locale est désormais documentée (http://druid.io/docs/latest/Firehose.html).
  • De nombreuses améliorations de la FAQ, des documents de métadonnées de segment améliorés, des documents d'ingestion Firehose améliorés, une vue complète du cluster expliquée. Merci @pdeva !
  • Mises à jour de la documentation Cassandra. Merci @lexicalunit !

Corrections de bugs

  • Ajout d'une solution de contournement pour un problème de connexion de jetée à moitié ouverte qui apparaît lorsque les connexions client mettent fin à une requête de longue durée. Les symptômes lorsque ce bug apparaît sont que le cluster semble bloqué et ne répond pas. Une autre solution de contournement à ce problème consiste simplement à utiliser les délais d’expiration du contexte de requête.
  • Correction des résultats de fusion des partitions avec des intervalles de temps, ce qui pouvait provoquer des résultats non fusionnés dans le désordre (#796).
  • HDFS devrait désormais fonctionner pour les systèmes de fichiers autres que ceux par défaut. Merci @flowbehappy !
  • Plusieurs dimensions spatiales peuvent désormais être ingérées.
  • Correction d'un bug avec les histogrammes approximatifs ne fonctionnant pas avec les requêtes groupBy.
  • Correction des derniers 8 Ko ne fonctionnant pas pour les journaux de tâches non-s3.
  • Correction de la configuration dynamique ne fonctionnant pas pour la limitation de la réplication.
  • Correction des requêtes de recherche générant des exceptions en cas de requête sur des dimensions inexistantes
  • Correction de la rupture de la lance à incendie pour les dimensions non présentes.
  • Les requêtes de sélection fonctionnent désormais si vous spécifiez des dimensions inexistantes (#778)
  • Le cache groupBy fonctionne désormais avec des métriques complexes
  • Correction de quelques problèmes de connexion qui existaient avec RabbitMQ (#794)

Anglais original / English original

druid druid-0.6.160

Improvements

  • Broker nodes now only start up after reading all information about segments in Zookeeper
  • Nested groupBy queries should now work with post aggregations.
  • Nested groupBy queries should now work with complex metrics.
  • The overlord in the indexing service can now assign tasks to workers based on strategies.
  • Local firehose can now find all files under a directory.
  • Timestamp and metrics are now automatically added to dimension exclusions.
  • Improved failure handling during real-time hand-offs.
  • Parallel downloading of segments. Multiple threads can now be used to download segments from deep storage.
  • Segments can be announced and queried as a node is initially loading up.
  • Native filtered aggregators for selector type filters
  • Custom Broker selection strategy for Router can now be written in JavaScript

Documentation

  • Example Hadoop Configuration now available
  • Best Practices and Recommendations now updated
  • Experimental Router node is now documented (druid.io/docs/latest/Router.html).
  • Local firehose is now documented (http://druid.io/docs/latest/Firehose.html).
  • Numerous improvements to FAQS, segment metadata docs improved, ingest firehose docs improved, full - cluster view explained. Thanks @pdeva!
  • Updates to Cassandra documentation. Thanks @lexicalunit!

Bug Fixes

  • Added a workaround for a jetty half open connection issue that appears when client connections terminate a long running query. The symptoms when this bug appears are that the cluster appears stuck and unresponsive. Another workaround for this issue is to simply use query context timeouts.
  • Fixed merging results from partitions with time gaps, which could cause out of order unmerged results (#796).
  • HDFS should now work for non-default filesystems. Thanks @flowbehappy!
  • Multiple spatial dimensions can now be ingested.
  • Fixed a bug with approximate histograms not working with groupBy queries.
  • Fixed last 8kb not working for non-s3 task logs.
  • Fixed dynamic configuration not working for replication throttling.
  • Fix search queries throwing exceptions if querying for non-existing dimensions
  • Fix ingest firehose breaking for non-present dimensions.
  • Select queries now work if you specify non-existing dimensions (#778)
  • groupBy cache now works with complex metrics
  • Fixed some serde problems that existed with RabbitMQ (#794)
