druide druide-0.14.0-incubating

Apache Druid (en incubation) 0.14.0-incubating contient plus de 200 nouvelles fonctionnalités, des améliorations de performances/stabilité/documentation et des corrections de bugs de 54 contributeurs. Les principales nouvelles fonctionnalités et améliorations incluent :

  • Nouvelle console Web
  • Service d'indexation Amazon Kinesis
  • Mode déclassement pour les historiques
  • Cache de segments publiés dans Broker
  • Agrégateur et expression de filtres Bloom
  • Extension Apache Parquet mise à jour
  • Option de poussée forcée pour les requêtes GroupBy imbriquées
  • Meilleure gestion des transferts de segments et des règles de suppression
  • Tuez automatiquement les tâches MapReduce lorsque les tâches d'ingestion Apache Hadoop sont supprimées
  • Prise en charge de la balise DogStatsD pour l'émetteur statsd
  • Nouveau API pour récupérer toutes les spécifications de recherche
  • Nouvelles options de compactage
  • Stratégie d'équilibrage des segments de mise en cache plus efficace La liste complète des changements est ici : https://github.com/apache/incubator-druid/pulls?q=is%3Apr+is%3Amerged+milestone%3A0.14.0 La documentation de cette version se trouve à l'adresse suivante : http://druid.io/docs/0.14.0-incubating/

Faits saillants

Nouvelle console Web

Druid dispose d'une nouvelle console Web qui offre des fonctionnalités qui étaient auparavant réparties entre les consoles coordinatrice et suzerain. La nouvelle console permet à l'utilisateur de gérer les sources de données, les segments, les tâches, les processus de données (historiques et MiddleManagers) et la configuration dynamique du coordinateur. L'utilisateur peut également exécuter des requêtes SQL et Druid natives dans la console. Pour plus de détails, veuillez consulter http://druid.io/docs/0.14.0-incubating/operations/management-uis.html Ajouté par @vogievetsky dans #6923.

Service d'indexation Kinesis

Druid prend désormais en charge l'ingestion à partir des flux Kinesis, fournie par la nouvelle extension principale druid-kinesis-indexing-service. Veuillez consulter http://druid.io/docs/0.14.0-incubating/development/extensions-core/kinesis-ingestion.html pour plus de détails. Ajouté par @jsun98 dans #6431.

Mode de mise hors service pour les historiques

Les processus historiques peuvent désormais être mis en mode « déclassement », dans lequel le coordinateur ne considérera plus le processus historique comme une cible pour la réplication de segment. Le coordinateur déplacera également des segments hors du déclassement historique. Ceci est contrôlé via la configuration dynamique du coordinateur. Pour plus de détails, veuillez consulter http://druid.io/docs/0.14.0-incubating/configuration/index.html#dynamic-configuration. Ajouté par @egor-ryashin dans #6349.

Cache de segments publiés sur Broker

Druid Broker a désormais la possibilité de maintenir un cache de segments publiés en interrogeant le coordinateur, ce qui peut améliorer considérablement le temps de réponse pour les requêtes de métadonnées sur la table système sys.segments. Veuillez consulter http://druid.io/docs/0.14.0-incubating/querying/sql.html#retrieving-metadata pour plus de détails. Ajouté par @surekhasaharan dans #6901

Agrégateur et expression de filtres Bloom

Un nouvel agrégateur pour la construction de filtres Bloom au moment de la requête et la prise en charge des vérifications de filtres Bloom dans les expressions Druid ont été ajoutés à l'extension druid-bloom-filter. Veuillez consulter http://druid.io/docs/0.14.0-incubating/development/extensions-core/bloom-filter.html Ajouté par @clintropolis dans #6904 et #6397

Extension de parquet mise à jour

druid-extensions-parquet a été déplacé dans l'ensemble d'extensions de base à partir des extensions de contribution et prend désormais en charge l'aplatissement et les valeurs int96. Veuillez consulter http://druid.io/docs/0.14.0-incubating/development/extensions-core/parquet.html pour plus de détails. Ajouté par @clintropolis dans #6360

Option de poussée vers le bas pour les requêtes GroupBy imbriquées

L'exécution de requêtes externes pour les requêtes GroupBy imbriquées peut désormais être transférée aux processus historiques ; auparavant, les requêtes externes étaient toujours exécutées sur le Broker. Veuillez consulter https://github.com/apache/incubator-druid/pull/5471 pour plus de détails. Ajouté par @samarthjain dans #5471.

Meilleure gestion du transfert de segments et des règles de rétention

Le transfert de segment ignorera désormais les segments qui seraient supprimés par les règles de conservation d'une source de données, évitant ainsi les échecs d'ingestion causés par le problème n° 5868. Les règles de chargement des périodes incluront désormais le futur par défaut. Une nouvelle règle « Period Drop Before » a été ajoutée. Veuillez consulter http://druid.io/docs/0.14.0-incubating/operations/rule-configuration.html#period-drop-before-rule pour plus de détails. Ajouté par @QiuMM dans #6676, #6414 et #6415. ## Tuez automatiquement les tâches MapReduce lorsque les tâches d'ingestion Hadoop sont supprimées Druid mettra désormais automatiquement fin aux tâches MapReduce créées par les tâches d'ingestion par lots Hadoop lorsque la tâche d'ingestion est supprimée. Ajouté par @ankit0811 dans #6828.

Prise en charge des balises DogStatsD pour l'émetteur statsd

L'extension statsd-emitter prend désormais en charge les balises de style DogStatsD. Veuillez consulter http://druid.io/docs/0.14.0-incubating/development/extensions-contrib/statsd.html Ajouté par @deiwin dans #6605, avec prise en charge des balises constantes ajoutées par @glasser dans #6791.

Nouveau API pour récupérer toutes les spécifications de recherche

Un nouveau API permettant de récupérer toutes les spécifications de recherche pour tous les niveaux a été ajouté. Veuillez consulter http://druid.io/docs/0.14.0-incubating/querying/lookups.html#get-all-lookups pour plus de détails. Ajouté par @jihoonson dans #7025.

Nouvelles options de compactage

Le compactage automatique prend désormais en charge l'option maxRowsPerSegment. Veuillez consulter http://druid.io/docs/0.14.0-incubating/design/coordinator.html#compacting-segments pour plus de détails. La tâche de compactage prend désormais en charge une nouvelle option segmentGranularity, rendant obsolète l'ancienne option keepSegmentGranularity permettant de contrôler la granularité des segments compactés. Veuillez consulter le tableau segmentGranularity dans http://druid.io/docs/0.14.0-incubating/ingestion/compaction.html pour plus d'informations sur ces propriétés. Ajouté par @jihoonson dans #6758 et #6780.

Stratégie d'équilibrage des segments de mise en cache plus efficace

La stratégie d'équilibrage des segments du coordinateur cachingCost ne prendra désormais en compte que les processus historiques pour les décisions d'équilibrage. Auparavant, la stratégie prenait également en compte inutilement les tâches des travailleurs actifs, qui ne sont pas des cibles pour la réplication de segments. Ajouté par @QiuMM dans #6879.

Mise à jour depuis 0.13.0-incubating et versions antérieures

Temps d'arrêt de l'ingestion de Kafka lors de la mise à niveau

En raison du problème décrit dans le numéro 6958, les tâches d'indexation Kafka existantes peuvent être interrompues inutilement lors d'une mise à niveau continue d'Overlord. Les tâches terminées seront redémarrées par l'Overlord et fonctionneront correctement après le redémarrage initial.

Modifications des extensions de parquet

L'extension druid-parquet-extensions a été déplacée de contrib vers core. Lors du déploiement de 0.14.0-incubating, veuillez vous assurer que votre répertoire extensions-contrib ne contient pas d'anciennes versions de l'extension Parquet. De plus, il existe désormais deux styles d'analyseurs Parquet dans l'extension :

  • parquet-avro : convertit Parquet en Avro, puis analyse la représentation Avro. Il s'agissait de l'analyseur existant avant 0.14.0-incubating.
  • parquet : Un nouvel analyseur qui analyse directement le format Parquet. Seul ce nouvel analyseur prend en charge les valeurs int96. Avant 0.14.0-incubating, un analyseur de type parquet aurait pour tâche d'utiliser l'analyseur de conversion Avro. Dans 0.14.0-incubating, pour continuer à utiliser l'analyseur de conversion Avro, vous devrez mettre à jour vos spécifications d'ingestion pour utiliser parquet-avro à la place. Le champ inputFormat dans le inputSpec pour les tâches utilisant l'entrée Parquet doit également correspondre au choix de l'analyseur : -parquet : org.apache.druid.data.input.parquet.DruidParquetInputFormat -parquet-avro : org.apache.druid.data.input.parquet.DruidParquetInputFormat Veuillez consulter http://druid.io/docs/0.14.0-incubating/development/extensions-core/parquet.html pour plus de détails.

Exécution de Druid avec Hadoop non-2.8.3

Si vous envisagez d'utiliser Druid 0.14.0-incubating avec des versions Hadoop autres que 2.8.3, vous devrez peut-être procéder comme suit :

  • Définissez les coordonnées de dépendance Hadoop sur votre version cible comme décrit dans http://druid.io/docs/0.14.0-incubating/operations/other-hadoop.html sous Tip #3: Use specific versions of Hadoop libraries.
  • Reconstruisez Druid avec votre version cible de Hadoop en modifiant hadoop.compile.version dans le Druid principal pom.xml, puis en suivant les instructions de construction standard.

Autres changements de comportement

Nettoyage des anciennes tâches

Les anciennes entrées de tâches dans le stockage des métadonnées seront désormais automatiquement nettoyées avec leurs journaux de tâches. Veuillez consulter http:/druid.io/docs/0.14.0-incubating/development/extensions-core/configuration/index.html#task-logging et #6592 pour plus de détails.

Dimensionnement automatique du tampon de traitement

La propriété druid.processing.buffer.sizeBytes a un nouveau comportement par défaut si elle n'est pas définie. Druid choisira désormais automatiquement une valeur pour la taille du tampon de traitement en utilisant la formule suivante :

processingBufferSize = totalDirectMemory / (numMergeBuffers + numProcessingThreads + 1)
processingBufferSize = min(processingBufferSize, 1GB)

Où :

  • totalDirectMemory : la limite de mémoire directe pour le JVM spécifiée par -XX:MaxDirectMemorySize
  • numMergeBuffers : la valeur de druid.processing.numMergeBuffers.
  • numProcessingThreads : la valeur de druid.processing.numThreads. Au maximum, Druid utilisera 1 Go pour la taille du tampon de traitement automatiquement choisie. La taille du tampon de traitement peut toujours être spécifiée manuellement. Veuillez consulter le numéro 6588 pour plus de détails.

Les règles de conservation incluent désormais le futur par défaut

Veuillez noter que les nouvelles règles de conservation incluront désormais le futur par défaut. Veuillez consulter le numéro 6414 pour plus de détails.

Modifications de la propriété

Annonce du segment

La propriété druid.announcer.type utilisée pour choisir entre Zookeeper ou la gestion/découverte de segments basée sur HTTP a été déplacée vers druid.serverview.type. Si vous utilisiez http avant 0.14.0-incubating, vous devrez mettre à jour vos configurations pour utiliser le nouveau druid.serverview.type. Veuillez consulter ce qui suit pour plus de détails : -http://druid.io/docs/0.14.0-incubating/configuration/index.html#segment-management -http://druid.io/docs/0.14.0-incubating/configuration/index.html#segment-discovery

corrige la propriété manquante dans JsonTypeInfo de SegmentWriteOutMediumFactory

La propriété druid.peon.defaultSegmentWriteOutMediumFactory.@type a été corrigée. La propriété est désormais druid.peon.defaultSegmentWriteOutMediumFactory.type sans le "@". Veuillez consulter le numéro 6656 pour plus de détails.

Dépréciations

Agrégateur d'histogramme approximatif

L'agrégateur ApproximateHistogram est obsolète ; il s'agit d'un algorithme dépendant de la distribution sans limites d'erreur formelles et qui présente des problèmes de précision importants. L'agrégateur DataSketches quantiles doit être utilisé à la place pour les cas d'utilisation de quantiles et d'histogrammes. Veuillez consulter [Agrégateurs d'histogrammes et de quantiles] (http://druid.io/docs/0.14.0-incubating/querying/aggregations.html#histograms-and-quantiles)

Agrégateur Cardinalité/HyperUnique

Les agrégateurs Cardinality et HyperUnique ont été abandonnés au profit de l'agrégateur DataSketches HLL et de l'agrégateur Theta Sketch. Ces agrégateurs ont de meilleures caractéristiques de précision et de performances. Veuillez consulter Compter les agrégateurs distincts pour plus de détails.

Période du bloc de requête

La configuration du contexte de requête chunkPeriod est désormais obsolète, ainsi que la métrique query/intervalChunk/time associée. Veuillez consulter le numéro 6591 pour plus de détails.

keepSegmentGranularity pour le compactage

L'option keepSegmentGranularity pour les tâches de compactage est obsolète. Veuillez consulter le numéro 6758 et le tableau segmentGranularity dans http://druid.io/docs/0.14.0-incubating/ingestion/compaction.html pour plus d'informations sur ces propriétés.

Modifications de l'interface pour les développeurs d'extensions

Classe SegmentId

Druid utilise désormais une classe SegmentId au lieu de chaînes simples pour représenter les ID de segment. Veuillez consulter le numéro 6370 pour plus de détails. Ajouté par @leventov.

druid-api, druid-common, java-util déplacés vers druid-core

Les modules druid-api, druid-common, java-util ont été déplacés dans druid-core. Veuillez mettre à jour vos dépendances en conséquence si votre projet dépendait de ces bibliothèques. Veuillez consulter le numéro 6443 pour plus de détails.

druid druid-0.14.0-incubating

Apache Druid (incubating) 0.14.0-incubating contains over 200 new features, performance/stability/documentation improvements, and bug fixes from 54 contributors. Major new features and improvements include:

  • New web console
  • Amazon Kinesis indexing service
  • Decommissioning mode for Historicals
  • Published segment cache in Broker
  • Bloom filter aggregator and expression
  • Updated Apache Parquet extension
  • Force push down option for nested GroupBy queries
  • Better segment handoff and drop rule handling
  • Automatically kill MapReduce jobs when Apache Hadoop ingestion tasks are killed
  • DogStatsD tag support for statsd emitter
  • New API for retrieving all lookup specs
  • New compaction options
  • More efficient cachingCost segment balancing strategy

The full list of changes is here: https://github.com/apache/incubator-druid/pulls?q=is%3Apr+is%3Amerged+milestone%3A0.14.0

Documentation for this release is at: http://druid.io/docs/0.14.0-incubating/

Highlights

New web console

Druid has a new web console that provides functionality that was previously split between the coordinator and overlord consoles.

The new console allows the user to manage datasources, segments, tasks, data processes (Historicals and MiddleManagers), and coordinator dynamic configuration. The user can also run SQL and native Druid queries within the console.

For more details, please see http://druid.io/docs/0.14.0-incubating/operations/management-uis.html

Added by @vogievetsky in #6923.

Kinesis indexing service

Druid now supports ingestion from Kinesis streams, provided by the new druid-kinesis-indexing-service core extension.

Please see http://druid.io/docs/0.14.0-incubating/development/extensions-core/kinesis-ingestion.html for details.

Added by @jsun98 in #6431.

Decommissioning mode for Historicals

Historical processes can now be put into a "decommissioning" mode, where the coordinator will no longer consider the Historical process as a target for segment replication. The coordinator will also move segments off the decommissioning Historical.

This is controlled via Coordinator dynamic configuration. For more details, please see http://druid.io/docs/0.14.0-incubating/configuration/index.html#dynamic-configuration.

Added by @egor-ryashin in #6349.

Published segment cache on Broker

The Druid Broker now has the ability to maintain a cache of published segments via polling the Coordinator, which can significantly improve response time for metadata queries on the sys.segments system table.

Please see http://druid.io/docs/0.14.0-incubating/querying/sql.html#retrieving-metadata for details.

Added by @surekhasaharan in #6901

Bloom filter aggregator and expression

A new aggregator for constructing Bloom filters at query time and support for performing Bloom filter checks within Druid expressions have been added to the druid-bloom-filter extension.

Please see http://druid.io/docs/0.14.0-incubating/development/extensions-core/bloom-filter.html

Added by @clintropolis in #6904 and #6397

Updated Parquet extension

druid-extensions-parquet has been moved into the core extension set from the contrib extensions and now supports flattening and int96 values.

Please see http://druid.io/docs/0.14.0-incubating/development/extensions-core/parquet.html for details.

Added by @clintropolis in #6360

Force push down option for nested GroupBy queries

Outer query execution for nested GroupBy queries can now be pushed down to Historical processes; previously, the outer queries would always be executed on the Broker.

Please see https://github.com/apache/incubator-druid/pull/5471 for details.

Added by @samarthjain in #5471.

Better segment handoff and retention rule handling

Segment handoff will now ignore segments that would be dropped by a datasource's retention rules, avoiding ingestion failures caused by issue #5868.

Period load rules will now include the future by default.

A new "Period Drop Before" rule has been added. Please see http://druid.io/docs/0.14.0-incubating/operations/rule-configuration.html#period-drop-before-rule for details.

Added by @QiuMM in #6676, #6414, and #6415.

Automatically kill MapReduce jobs when Hadoop ingestion tasks are killed

Druid will now automatically terminate MapReduce jobs created by Hadoop batch ingestion tasks when the ingestion task is killed.

Added by @ankit0811 in #6828.

DogStatsD tag support for statsd-emitter

The statsd-emitter extension now supports DogStatsD-style tags. Please see http://druid.io/docs/0.14.0-incubating/development/extensions-contrib/statsd.html

Added by @deiwin in #6605, with support for constant tags added by @glasser in #6791.

New API for retrieving all lookup specs

A new API for retrieving all lookup specs for all tiers has been added. Please see http://druid.io/docs/0.14.0-incubating/querying/lookups.html#get-all-lookups for details.

Added by @jihoonson in #7025.

New compaction options

Auto-compaction now supports the maxRowsPerSegment option. Please see http://druid.io/docs/0.14.0-incubating/design/coordinator.html#compacting-segments for details.

The compaction task now supports a new segmentGranularity option, deprecating the older keepSegmentGranularity option for controlling the segment granularity of compacted segments. Please see the segmentGranularity table in http://druid.io/docs/0.14.0-incubating/ingestion/compaction.html for more information on these properties.

Added by @jihoonson in #6758 and #6780.

More efficient cachingCost segment balancing strategy

The cachingCost Coordinator segment balancing strategy will now only consider Historical processes for balancing decisions. Previously the strategy would unnecessarily consider active worker tasks as well, which are not targets for segment replication.

Added by @QiuMM in #6879.

New metrics:

  • New allocation rate metric jvm/heapAlloc/bytes, added by @egor-ryashin in #6710.
  • New query count metric query/count, added by @QiuMM in #6473.
  • SQL query metrics sqlQuery/bytes and sqlQuery/time, added by @gaodayue in #6302.
  • Apache Kafka ingestion lag metrics ingest/kafka/maxLag and ingest/kafka/avgLag, added by @QiuMM in #6587
  • Task count metrics task/success/count, task/failed/count, task/running/count, task/pending/count, task/waiting/count, added by @QiuMM in #6657

New interfaces for extension developers

RequestLogEvent

It is now possible to control the fields in RequestLogEvent, emitted by EmittingRequestLogger. Please see #6477 for details. Added by @leventov.

Custom TLS certificate checks

An extension point for custom TLS certificate checks has been added. Please see http://druid.io/docs/0.14.0-incubating/operations/tls-support.html#custom-tls-certificate-checks for details. Added by @jon-wei in #6432.

Kafka Indexing Service no longer experimental

The Kafka Indexing Service extension has been moved out of experimental status.

SQL Enhancements

Enhancements to dsql

The dsql command line client now supports CLI history, basic autocomplete, and specifying query timeouts in the query context.

Added in #6929 by @gianm.

Add SQL id, request logs, and metrics

SQL queries now have an ID, and native queries executed as part of a SQL query will have the associated SQL query ID in the native query's request logs. SQL queries will now be logged in the request logs.

Two new metrics, sqlQuery/time and sqlQuery/bytes, are now emitted for SQL queries.

Please see http://druid.io/docs/0.14.0-incubating/configuration/index.html#request-logging and http://druid.io/docs/0.14.0-incubating/querying/sql.html#sql-metrics for details.

Added by @gaodayue in #6302

More SQL aggregator support

The follow aggregators are now supported in SQL:

  • DataSketches HLL sketch
  • DataSketches Theta sketch
  • DataSketches quantiles sketch
  • Fixed bins histogram
  • Bloom filter aggregator

Added by @jon-wei in #6951 and @clintropolis in #6502

Other SQL enhancements

  • SQL: Add support for queries with project-after-semijoin. #6756
  • SQL: Support for selecting multi-value dimensions. #6462
  • SQL: Support AVG on system tables. #601
  • SQL: Add "POSITION" function. #6596
  • SQL: Set INFORMATION_SCHEMA catalog name to "druid". #6595
  • SQL: Fix ordering of sort, sortProject in DruidSemiJoin. #6769

Added by @gianm.

Updating from 0.13.0-incubating and earlier

Kafka ingestion downtime when upgrading

Due to the issue described in #6958, existing Kafka indexing tasks can be terminated unnecessarily during a rolling upgrade of the Overlord. The terminated tasks will be restarted by the Overlord and will function correctly after the initial restart.

Parquet extension changes

The druid-parquet-extensions extension has been moved from contrib to core. When deploying 0.14.0-incubating, please ensure that your extensions-contrib directory does not have any older versions of the Parquet extension.

Additionally, there are now two styles of Parquet parsers in the extension:

  • parquet-avro: Converts Parquet to Avro, and then parses the Avro representation. This was the existing parser prior to 0.14.0-incubating.
  • parquet: A new parser that parses the Parquet format directly. Only this new parser supports int96 values.

Prior to 0.14.0-incubating, a specifying a parquet type parser would have a task use the Avro-converting parser. In 0.14.0-incubating, to continue using the Avro-converting parser, you will need to update your ingestion specs to use parquet-avro instead.

The inputFormat field in the inputSpec for tasks using Parquet input must also match the choice of parser:

  • parquet: org.apache.druid.data.input.parquet.DruidParquetInputFormat
  • parquet-avro: org.apache.druid.data.input.parquet.DruidParquetInputFormat

Please see http://druid.io/docs/0.14.0-incubating/development/extensions-core/parquet.html for details.

Running Druid with non-2.8.3 Hadoop

If you plan to use Druid 0.14.0-incubating with Hadoop versions other than 2.8.3, you may need to do the following:

  • Set the Hadoop dependency coordinates to your target version as described in http://druid.io/docs/0.14.0-incubating/operations/other-hadoop.html under Tip #3: Use specific versions of Hadoop libraries.
  • Rebuild Druid with your target version of Hadoop by changing hadoop.compile.version in the main Druid pom.xml and then following the standard build instructions.

Other Behavior changes

Old task cleanup

Old task entries in the metadata storage will now be cleaned up automatically together with their task logs. Please see http:/druid.io/docs/0.14.0-incubating/development/extensions-core/configuration/index.html#task-logging and #6592 for details.

Automatic processing buffer sizing

The druid.processing.buffer.sizeBytes property has new default behavior if it is not set. Druid will now automatically choose a value for the processing buffer size using the following formula:

processingBufferSize = totalDirectMemory / (numMergeBuffers + numProcessingThreads + 1)
processingBufferSize = min(processingBufferSize, 1GB)

Where:

  • totalDirectMemory: The direct memory limit for the JVM specified by -XX:MaxDirectMemorySize
  • numMergeBuffers: The value of druid.processing.numMergeBuffers.
  • numProcessingThreads: The value of druid.processing.numThreads.

At most, Druid will use 1GB for the automatically chosen processing buffer size. The processing buffer size can still be specified manually.

Please see #6588 for details.

Retention rules now include the future by default

Please be aware that new retention rules will now include the future by default. Please see #6414 for details.

Property changes

Segment announcing

The druid.announcer.type property used for choosing between Zookeeper or HTTP-based segment management/discovery has been moved to druid.serverview.type. If you were using http prior to 0.14.0-incubating, you will need to update your configs to use the new druid.serverview.type.

Please see the following for details:

  • http://druid.io/docs/0.14.0-incubating/configuration/index.html#segment-management
  • http://druid.io/docs/0.14.0-incubating/configuration/index.html#segment-discovery

fix missing property in JsonTypeInfo of SegmentWriteOutMediumFactory

The druid.peon.defaultSegmentWriteOutMediumFactory.@type property has been fixed. The property is now druid.peon.defaultSegmentWriteOutMediumFactory.type without the "@".

Please see #6656 for details.

Deprecations

Approximate Histogram aggregator

The ApproximateHistogram aggregator has been deprecated; it is a distribution-dependent algorithm without formal error bounds and has significant accuracy issues.

The DataSketches quantiles aggregator should be used instead for quantile and histogram use cases.

Please see Histogram and Quantiles Aggregators

Cardinality/HyperUnique aggregator

The Cardinality and HyperUnique aggregators have been deprecated in favor of the DataSketches HLL aggregator and Theta Sketch aggregator. These aggregators have better accuracy and performance characteristics.

Please see Count Distinct Aggregators for details.

Query Chunk Period

The chunkPeriod query context configuration is now deprecated, along with the associated query/intervalChunk/time metric. Please see #6591 for details.

keepSegmentGranularity for Compaction

The keepSegmentGranularity option for compaction tasks has been deprecated. Please see #6758 and the segmentGranularity table in http://druid.io/docs/0.14.0-incubating/ingestion/compaction.html for more information on these properties.

Interface changes for extension developers

SegmentId class

Druid now uses a SegmentId class instead of plain Strings to represent segment IDs. Please see #6370 for details.

Added by @leventov.

druid-api, druid-common, java-util moved to druid-core

The druid-api, druid-common, java-util modules have been moved into druid-core. Please update your dependencies accordingly if your project depended on these libraries.

Please see #6443 for details.
