AstrBot v4.20.1

Highlights

  • New provider backends & config surface — OpenRouter chat-completions adapter with custom-header support (#6436), MiniMax provider (#6318), and a YAML-bindable local temporary directory (#6191). Custom headers matter if you route through proxies or need per-tenant auth, and the temp-dir binding gives operators control over where uploads/scratch files land. Watch out: a bug meant newly created providers weren't synced into providers_config until #6388 — after upgrading, re-check that runtime-created provider configs actually persisted. Provider icons now load from jsDelivr instead of the npm registry (#6340), so locked-down environments must allow that CDN.
  • Agent/tool-calling reliability — This is the most adoption-relevant cluster: TypeError on null choices from API responses (#6313), AttributeError on null delta during streaming tool calls (#6365), media send failures when tool-calling mode is skills-like (#6317), and subagent handoff tools being dropped during plugin filtering (#6155). Together these close real crash paths in tool-use and multi-agent flows — if you rely on streaming tool calls or handoffs, this patch is worth picking up specifically for these fixes.
  • Migration note: startup command & session identity — Docs/README now standardize on astrbot run (#6189), so any scripts, service units, or runbooks copied from older docs need updating. Internally, _extract_session_id was refactored for chat-type branching (#5775) and UMO handling compatibility was broadened (#5996); session-key derivation can shift as a result, so validate session continuity/history lookup on non-standard chat types after upgrading.
  • Platform adapter message fidelity — A batch of fixes that change what users actually see: Telegram GIFs no longer downgrade to static images (#6329) and plain replies are no longer misread as thread replies (#6174); QQ webhook retries no longer fire duplicate callbacks (#6320) and official face messages parse to readable text (#6355); OneBot @ spacing (#6238) and Plain.toDict() whitespace for mentions (#6244) are preserved. If your bots depend on exact message text or reaction timing, expect observable behavior changes here rather than silent improvements.
  • WebUI/WebChat & maintenance — Batch conversation deletion (#6160), configurable send shortcuts plus input localization (#6272), shiki-based code-block rendering (#6286), refined theme colors (#6263), stabilized sidebar hash navigation (#6159), and a fix for stream-result page crashes on queue errors (#6123). Housekeeping worth noting: cron prompts lost the deprecated utcnow() warning (#6192), an already-removed API key no longer throws in the retry loop (#6193), and duplicate dependency entries were removed (#6247) — check your deploy if you pinned against those deps.
  • Breaking changes — None reported in this release.

  • 优化 WebUI 主题配色与视觉体验。（#6263）
  • 优化 OneBot @ 组件后处理，避免消息文本解析空格问题。（#6238）

修复

  • 修复创建新 Provider 后未同步 providers_config 的问题。（#6388）
  • 修复 API 返回 null choices 时的 TypeError。（#6313）
  • 修复 QQ Webhook 重试回调重复触发的问题。（#6320）
  • 修复流式模式下 delta 为 None 导致工具调用时报错的问题。（#6365）
  • 修复模型服务链接说明文字错误。（#6296）
  • 修复 AI 在 tool-calling 模式设为 skills-like 时发送媒体失败的问题。（#6317）
  • 修复 Telegram 适配器中 GIF 被错误转成静态图的问题。（#6329）
  • 将 Provider 图标来源替换为 jsDelivr CDN 地址，修复部分环境下图标加载问题。（#6340）
  • 修复 QQ 官方表情消息未解析为可读文本的问题。（#6355）
  • 修复 WebChat 队列异常时流式结果页面崩溃的问题。（#6123）
  • 修复子代理 handoff 工具在插件过滤时丢失的问题。（#6155）
  • 修复 Cron 提示文案缺少空格及 utcnow() 的弃用警告问题。（#6192）
  • 修复 WebUI 启动时 Sidebar hash 导航抖动/定位问题。（#6159）
  • 修复启动重试过程中移除已移除 API Key 的 ValueError 报错。（#6193）
  • 修复 README 启动命令引用更新为 astrbot run。（#6189）
  • 修复 Plain.toDict() 在 @ 提及场景下空白字符丢失的问题。（#6244）
  • 修复 provider 依赖重复定义问题。（#6247）
  • 修复 Telegram 中普通回复被误判为线程的处理问题。（#6174）

其他

  • 调整 astrbot.service 及 CI 配置，升级 GitHub Actions 版本。
