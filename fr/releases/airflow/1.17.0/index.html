airflow helm-chart/1.17.0

Highlights

  • Airflow 3.0.2 becomes the default image — The chart jumps from Airflow 2.10.5 to 3.0.2 (#51594), so an otherwise routine Helm upgrade changes the application’s major version. Validate DAG and plugin compatibility and follow the Airflow 3 migration path first; if you cannot move yet, explicitly pin the previous image tag while planning the upgrade.
  • Kubernetes 1.30 is now the minimum — Clusters older than 1.30 must be upgraded before installing chart 1.17.0 (#51515), or you need to remain on an older chart release. This compatibility gate applies independently of the Airflow image change.
  • EdgeExecutor deployments are supported — New chart support (#50897) allows Airflow 3 installations to opt into remote edge workers instead of relying only on traditional worker deployments. Plan executor configuration, worker bootstrap, networking, and API-server reachability together; existing Celery or Kubernetes worker values should not be assumed to cover edge workers.
  • API server configuration and routing are repaired — The chart adds the missing API server ingress (#49727), webserver_config.py (#50108), undeclared properties (#51012), and replica setting (#50814). The execution API URL is also corrected when base_url includes a subpath (#51454), which matters for reverse-proxied installations; recheck ingress routes, TLS, and path-prefix configuration during the upgrade.
  • JWT secrets are handled automatically — Helm now generates the JWT secret during installation (#49923) and always deploys it (#51799), avoiding missing-secret failures in the Airflow 3 API authentication path. If you manage secrets externally, review resource ownership and overrides before upgrading to prevent conflicts with your secret workflow.
  • Security defaults, RBAC, and labels need review — The FAB enable_proxy_fix default is corrected for Airflow 3 (#50056), the pod-launcher role binding is fixed (#49219), and the DAG processor service account is added to the SCC role binding (#51080), improving proxy handling and Kubernetes/OpenShift authorization. Unified labels (#49522) and truncated executor labels (#51817) may affect custom selectors and dashboards, so audit label-based tooling during rollout.

Significant Changes

Default Airflow image is updated to 3.0.2 (#51594)

The default Airflow image that is used with the Chart is now 3.0.2, previously it was 2.10.5.

New Features

  • Add extra secret annotations to most secrets (#48890)
  • Add support for EdgeExecutor (#50897)

Improvements

  • Unify k8s labels & add some missing k8s labels (#49522)

Bug Fixes

  • Fix missing api server ingress (#49727)
  • Replace break function in pod-launcher-rolebinding template (#49219)
  • Add webserver_config.py file to api-server (#50108)
  • Declare missing API server properties (#51012)
  • Add missing api server replicas parameter (#50814)
  • Fix FAB enable_proxy_fix default for Airflow 3 (#50056)
  • Add the dag processor ServiceAccount to SecurityContextConstraints role binding (#51080)
  • Generate JWT secret during HELM install (#49923)
  • Always deploy JWT secret (#51799)
  • Add missing workers.kerberosInitContainer configuration in values (#51405)
  • Truncate the executor label length (#51817)
  • Fix execution_api_server_url when base_url has a subpath (#51454)

Doc only changes

  • Bump minimum helm version in docs (#48700)
  • Clarify which worker fields apply to Celery and Kubernetes worker pods (#50458)
  • Capitalize the term airflow (#49450)
  • Add EdgeExecutor to readme (#51017)
  • Add 3.X/2.X clarification for CeleryKubernetesExecutor (#49916)

Misc

  • Default Airflow image is updated to 3.0.2 (#51594)
  • Bump minimal Kubernetes version to 1.30 (#51515)
  • Delete unneeded and operator (#51114)
