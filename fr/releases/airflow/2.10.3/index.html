airflow 2.10.3

Highlights

  • Security hardening for secrets and the web UI — Variable values and sensitive configuration are masked more aggressively during DAG-author-facing operations (#43123, #43278, #43335, #43337, #43040), and dompurify is bumped 2.2.9 → 2.5.6 in airflow/www (#42270), closing a known sanitizer/XSS weakness. If you expose the webserver to less-trusted users this is the main reason to upgrade — expect some previously readable config values to appear masked after the patch.

  • Migration signals: session auth deprecated, unicodecsv dropped — The session auth backend is now deprecated (#42911), so teams using it should plan a move to a supported backend before a future major. Providers targeting Airflow 2.8.0+ no longer carry the unicodecsv dependency (#42765, #42970), and Flask-AppBuilder is backported to 4.5.2 (#43318) — custom auth backends, provider plugins, and pinned web dependencies should be regression-tested against this stack.

  • OpenTelemetry observability gets more configurable — Metrics now honor host.name and OTEL_RESOURCE_ATTRIBUTES (#42428, #42604), the previously hardcoded OTEL_SERVICE_NAME can be overridden via environment variable (#42242, #42441), and executor events can emit conditional OTEL events (#43558, #43567). Dashboard owners relying on stable service/resource labels should verify their attribute mapping after upgrade, since key names and sources can now differ.

  • Scheduler and executor reliability sweep — Zombie tasks are cleaned up correctly when task instances are terminated (#43065), the scheduler retries updating trigger timeouts on deadlock (#41429, #42651), and internal API calls now retry transient HTTP 502/504 during webserver startup (#42994, #43044). Separating sessions for RTIF writes/deletes fixes StaleDataError (#42928, #43012), and the broken scheduler_loop_duration stat is restored (#42886, #43544). Much of this patch is aimed at eliminating intermittent scheduler flakiness rather than adding features.

  • Stable API contract tweaks — /api/v1/dags now returns a reliable total_entries (#43377, #43429), and the batch "list task instances" endpoint formally accepts limit/offset in its request-body schema (#43479). These are additive, but they change generated OpenAPI clients and typed schemas, so pagination logic and client stubs should be regenerated and rechecked.

  • DAG authoring and mapped-task behavior — Mapped operators now work with task_instance_mutation_hook at index 0 (#42661, #43089) and TrySelector in the Logs/Grid panels is fixed (#43566); PythonOperator no longer errors on DAG names containing hyphens (#42993); BashOperator executes templated scripts as a file (#43191); and schedule_downstream_tasks now includes upstream tasks under the one_success trigger rule (#42582, #43299). Note the behavioral change that manually failing a dag_run now marks all tasks skipped (#43572) — worth reviewing if you have alerting or retry logic keyed on task state.

No breaking changes.

  • Adds support for task_instance_mutation_hook to handle mapped operators with index 0. (#42661) (#43089)

  • Restores the use of separate sessions for writing and deleting RTIF data to prevent StaleDataError. (#42928) (#43012)
  • Fixes PythonOperator error by replacing hyphens with underscores in DAG names. (#42993)
  • Improving validation of task retries to handle None values (#42532) (#42915)
  • Fixes error handling in dataset managers when resolving dataset aliases into new datasets (#42733)
  • Enables clicking on task names in the DAG Graph View to correctly select the corresponding task. (#38782) (#42697)
  • Prevent redirect loop on /home with tags/last run filters (#42607) (#42609) (#42628)
  • Support of host.name in OTEL metrics and usage of OTEL_RESOURCE_ATTRIBUTES in metrics (#42428) (#42604)
  • Reduce eyestrain in dark mode with reduced contrast and saturation (#42567) (#42583)
  • Handle ENTER key correctly in trigger form and allow manual JSON (#42525) (#42535)
  • Ensure DAG trigger form submits with updated parameters upon keyboard submit (#42487) (#42499)
  • Do not attempt to provide not stringified objects to UI via xcom if pickling is active (#42388) (#42486)
  • Fix the span link of task instance to point to the correct span in the scheduler_job_loop (#42430) (#42480)
  • Bugfix task execution from runner in Windows (#42426) (#42478)
  • Allows overriding the hardcoded OTEL_SERVICE_NAME with an environment variable (#42242) (#42441)
  • Improves trigger performance by using selectinload instead of joinedload (#40487) (#42351)
  • Suppress warnings when masking sensitive configs (#43335) (#43337)
  • Masking configuration values irrelevant to DAG author (#43040) (#43336)
  • Execute templated bash script as file in BashOperator (#43191)
  • Fixes schedule_downstream_tasks to include upstream tasks for one_success trigger rule (#42582) (#43299)
  • Add retry logic in the scheduler for updating trigger timeouts in case of deadlocks. (#41429) (#42651)
  • Mark all tasks as skipped when failing a dag_run manually (#43572)
  • Fix TrySelector for Mapped Tasks in Logs and Details Grid Panel (#43566)
  • Conditionally add OTEL events when processing executor events (#43558) (#43567)
  • Fix broken stat scheduler_loop_duration (#42886) (#43544)
  • Ensure total_entries in /api/v1/dags (#43377) (#43429)
  • Include limit and offset in request body schema for List task instances (batch) endpoint (#43479)
  • Don't raise a warning in ExecutorSafeguard when execute is called from an extended operator (#42849) (#43577)
