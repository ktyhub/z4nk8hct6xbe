airflow 3.1.0

Highlights

  • Human-in-the-loop approvals become first-class — AIP introduces HITLOperator, ApprovalOperator, and HITLEntryOperator (#52868) with a dedicated UI and RBAC-gated forms (#53035), filterable API endpoints (#53376, #53923), and a new No Response Received action state (#55149). This replaces ad-hoc external approval hacks with native pause-and-resume gates; expect new required-action tables/permissions to appear on upgrade and think about where your DAGs now block on human input.

  • Deadline alerts (AIP-86) enable proactive SLA monitoring — Deadlines are modeled as first-class objects tied to DAG runs (#50925, #50093) with configurable reference points and notification callbacks (#50677, #50093), async Notifier support (#53831), and UI/API surfaces (#53951, #53903, #53201, #55086). You can now alert before a deadline instead of polling for missed runs — note the new async notifier path may require updating custom notifiers.

  • The React UI is now extensible via plugins (AIP-68) — A new React plugin system (#52255), iframe external views (#51003, #51889), and custom React app dashboard integration (#54131, #54144) let you embed your own pages and actions in the modern UI. If you maintain plugins, watch for new validation warnings surfaced in /plugins (#55673), and don't assume legacy FAB-style views port automatically.

  • Runtime and dependency modernization — Python 3.13 is now supported (#46891) alongside SQLAlchemy 2.0 compatibility work (#52233, #52518, #54940) and a new psycopg3 Postgres driver option (#52976). If you're pinned to older Python or ORM/driver versions, test DAG serialization and DB connectivity carefully — the SQLAlchemy 2.0 changes touch query behavior under the hood.

  • All Airflow logging switches to structlog — A wholesale move to structured logging (#52651, #55434, #55431, #55638) changes log shape, alongside JWT token redaction (#55499), guaranteed filename/lineno fields (#55581), and corrected timestamps when default_timezone isn't UTC (#54431). Downstream log parsers, dashboards, and alerting rules built on the old text format need review; task stdout/stderr is now filterable in the log viewer (#55508).

  • Upgrade path from 2.x is substantially hardened — A batch of migration fixes covers DB downgrade with existing FAB tables (#55738), serialized-DAG v3→v2 downgrade conversion (#55975), orphaned tasks left over from 2.x (#55848), custom triggers using synchronous connection calls (#55799), log-format preservation during upgrade (#55824), and slash characters in Variable keys (#55324). These clear common 2.x upgrade blockers — still verify migrations and custom triggers in staging before cutover.

No breaking changes are called out in this release.
