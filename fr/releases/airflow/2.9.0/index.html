airflow 2.9.0

Mineure Publié8 avr. 2024 Sourceapache/airflow Anglais original

Cette page est traduite automatiquement. Le texte anglais original fait foi.

débit d'air 2.9.0

Changements importants

Les méthodes suivantes de l'écouteur API sont considérées comme stables et peuvent être utilisées pour le système de production (il s'agissait d'une fonctionnalité expérimentale dans les anciennes versions d'Airflow) (#36376) :

Événements du cycle de vie :

  • on_starting
  • before_stopping Événements de changement d'état DagRun :
  • on_dag_run_running
  • on_dag_run_success
  • on_dag_run_failed Événements de changement d’état de l’instance de tâche :
  • on_task_instance_running
  • on_task_instance_success
  • on_task_instance_failed

La prise en charge de Microsoft SQL-Server pour la méta-base de données Airflow a été supprimée (#36514)

Après discussion <https://lists.apache.org/thread/r06j306hldg03g2my1pd4nyjxg78b3h4>__ et un voting process <https://lists.apache.org/thread/pgcgmhf6560k8jbsmz8nlyoxosvltph2>__, Le PMC et les committers d'Airflow ont atteint une résolution pour ne plus maintenir MsSQL en tant que backend de base de données pris en charge. Depuis Airflow, la prise en charge de MsSQL par 2.9.0 a été supprimée pour le backend de la base de données Airflow. Un script de migration qui peut aider à migrer la base de données avant la mise à niveau vers Airflow 2.9.0 est disponible dans airflow-mssql-migration repo on Github <https://github.com/apache/airflow-mssql-migration>_. Notez que le script de migration est fourni sans support ni garantie. Cela n'affecte pas les packages de fournisseurs existants (opérateurs et hooks), les DAG peuvent toujours accéder et traiter les données de MsSQL.

Les URI des ensembles de données sont désormais validés en entrée (#37005)

Les ensembles de données doivent utiliser un URI conforme aux règles établies dans l'AIP-60 et la valeur sera automatiquement normalisé lorsque le fichier DAG sera analysé. Voir documentation on Datasets <https://airflow.apache.org/docs/apache-airflow/stable/authoring-and-scheduling/datasets.html>_ pour une description plus détaillée des règles. Vous devrez peut-être modifier vos identifiants d'ensemble de données s'ils ressemblent à un URI, mais sont utilisé d'une manière moins courante, comme en s'appuyant sur la section d'authentification de l'URI, ou avoir un nom de protocole sensible à la casse.

La méthode get_permitted_menu_items in BaseAuthManager has been renamed filter_permitted_menu_items (#37627)

Ajouter des actions REST API aux événements du journal d'audit (#37734)

Le journal d'audit event name for REST API events will be prepended with api. or ui., selon qu'il provient de l'interface utilisateur d'Airflow ou de l'extérieur.

Support officiel pour Python 3.12 (#38025)

Il y a cependant quelques mises en garde :

  • Pendulum2 ne prend pas en charge Python 3.12. Pour Python 3.12, vous devez utiliser Pendulum 3 <https://pendulum.eustace.io/blog/announcing-pendulum-3-0-0.html>_
  • La version minimale de SQLAlchemy prise en charge lorsque Pandas est installé pour Python 3.12 est 1.4.36 publié dans Avril 2022. Airflow 2.9.0 augmente la version minimale prise en charge de SQLAlchemy à « 1.4.36 » pour tous Versions Python. Tous les fournisseurs ne prennent pas en charge Python 3.12. Lors de la version initiale d'Airflow 2.9.0, les fournisseurs suivants sont publiés sans prise en charge de Python 3.12 :
    • apache.beam - pending on Prise en charge d'Apache Beam pour 3.12 <https://github.com/apache/beam/issues/29149>_
    • papermill - en attente de sortie de la version Python 3.12 compatible avec la papeterie client including this merged issue <https://github.com/nteract/papermill/pull/771>_

Empêcher le stockage d'objets chaîne volumineux dans les champs du modèle rendu (#38094)

Il existe désormais une limite à la longueur des données pouvant être stockées dans les champs du modèle rendu. La limite est fixée à 4 096 caractères. Si les données dépassent cette limite, elles seront tronquées. Vous pouvez modifier cette limite en définissant l'option de configuration « [core]max_template_field_length » dans votre configuration de flux d'air.

Changez le type de valeur de la colonne de la table xcom en longblob pour le backend MySQL (#38401)

Colonne du tableau Xcom value type has changed from blob to longblob. Cela vous permettra de stocker des données relativement volumineuses dans Xcom, mais le processus peut prendre beaucoup de temps si vous avez beaucoup de données volumineuses stockées dans Xcom. Pour rétrograder à partir de la révision : b4078ac230a1, ensure that you don't have Xcom values larger than 65,535 bytes. Otherwise, you'll need to clean those rows or run airflow db clean xcom pour nettoyer la table Xcom.

airflow 2.9.0

Significant Changes

Following Listener API methods are considered stable and can be used for production system (were experimental feature in older Airflow versions) (#36376):

Lifecycle events:

  • on_starting
  • before_stopping

DagRun State Change Events:

  • on_dag_run_running
  • on_dag_run_success
  • on_dag_run_failed

TaskInstance State Change Events:

  • on_task_instance_running
  • on_task_instance_success
  • on_task_instance_failed

Support for Microsoft SQL-Server for Airflow Meta Database has been removed (#36514)

After discussion <https://lists.apache.org/thread/r06j306hldg03g2my1pd4nyjxg78b3h4>__ and a voting process <https://lists.apache.org/thread/pgcgmhf6560k8jbsmz8nlyoxosvltph2>__, the Airflow's PMC and Committers have reached a resolution to no longer maintain MsSQL as a supported Database Backend.

As of Airflow 2.9.0 support of MsSQL has been removed for Airflow Database Backend.

A migration script which can help migrating the database before upgrading to Airflow 2.9.0 is available in airflow-mssql-migration repo on Github <https://github.com/apache/airflow-mssql-migration>_. Note that the migration script is provided without support and warranty.

This does not affect the existing provider packages (operators and hooks), DAGs can still access and process data from MsSQL.

Dataset URIs are now validated on input (#37005)

Datasets must use a URI that conform to rules laid down in AIP-60, and the value will be automatically normalized when the DAG file is parsed. See documentation on Datasets <https://airflow.apache.org/docs/apache-airflow/stable/authoring-and-scheduling/datasets.html>_ for a more detailed description on the rules.

You may need to change your Dataset identifiers if they look like a URI, but are used in a less mainstream way, such as relying on the URI's auth section, or have a case-sensitive protocol name.

The method get_permitted_menu_items in BaseAuthManager has been renamed filter_permitted_menu_items (#37627)

Add REST API actions to Audit Log events (#37734)

The Audit Log event name for REST API events will be prepended with api. or ui., depending on if it came from the Airflow UI or externally.

Official support for Python 3.12 (#38025)

There are a few caveats though:

  • Pendulum2 does not support Python 3.12. For Python 3.12 you need to use Pendulum 3 <https://pendulum.eustace.io/blog/announcing-pendulum-3-0-0.html>_

  • Minimum SQLAlchemy version supported when Pandas is installed for Python 3.12 is 1.4.36 released in April 2022. Airflow 2.9.0 increases the minimum supported version of SQLAlchemy to 1.4.36 for all Python versions.

Not all Providers support Python 3.12. At the initial release of Airflow 2.9.0 the following providers are released without support for Python 3.12:

  • apache.beam - pending on Apache Beam support for 3.12 <https://github.com/apache/beam/issues/29149>_
  • papermill - pending on Releasing Python 3.12 compatible papermill client version including this merged issue <https://github.com/nteract/papermill/pull/771>_

Prevent large string objects from being stored in the Rendered Template Fields (#38094)

There's now a limit to the length of data that can be stored in the Rendered Template Fields. The limit is set to 4096 characters. If the data exceeds this limit, it will be truncated. You can change this limit by setting the [core]max_template_field_length configuration option in your airflow config.

Change xcom table column value type to longblob for MySQL backend (#38401)

Xcom table column value type has changed from blob to longblob. This will allow you to store relatively big data in Xcom but process can take a significant amount of time if you have a lot of large data stored in Xcom.

To downgrade from revision: b4078ac230a1, ensure that you don't have Xcom values larger than 65,535 bytes. Otherwise, you'll need to clean those rows or run airflow db clean xcom to clean the Xcom table.
