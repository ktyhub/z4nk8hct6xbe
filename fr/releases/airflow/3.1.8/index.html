Changements importants

Backfill permissions are now handled via DagAccessEntity.Run (#61456)

is_authorized_backfill of the BaseAuthManager interface has been removed. Core n'appellera plus cette méthode et leur provider counterpart implementation will be marked as deprecated. Permissions for backfill operations are now checked against the DagAccessEntity.Run permission using the existing Décorateur requires_access_dag. In other words, if a user has permission to run a DAG, they can perform backfill operations on it. Please update your security policies to ensure that users who need to perform backfill operations have the appropriate DagAccessEntity.Run permissions. (Les utilisateurs having the Backfill permissions without having the DagRun ones will no longer be able to perform backfill operations without any update)

Elasticsearch is now fully compatible with remote logging along (#62940)

Elasticsearch is now fully compatible with remote logging along side with apache-airflow-providers-elasticsearch>=6.5.0. Please review elasticsearch provider release notes for more information https://airflow.apache.org/docs/apache-airflow-providers-elasticsearch/6.5.0/changelog.html (#62121) (#62940)

airflow 3.1.8

Highlights

  • Backfill authorization moves to DAG-run permissions (breaking) — BaseAuthManager.is_authorized_backfill is removed (#61456); Core no longer calls it and the provider-side implementation is deprecated. Backfill is now gated by DagAccessEntity.Run via the existing requires_access_dag decorator, so anyone who can run a DAG can backfill it. Audit your security policies before upgrading: principals granted only Backfill rights will silently lose that ability, and custom auth managers should drop the obsolete hook. A related fix corrects backfill permission handling itself (#62856, #62873).

  • Session cookie and JWT hardening — Session cookies are now scoped to base_url (#62771, #62851, UI follow-up #62859), and symmetric-key JWTs always carry a kid in the header (#62883, #62943). These are behavior changes that matter for reverse-proxy/subpath deployments and multi-issuer token setups: verify cookie domain/path and token validation after upgrade if your API server sits under a non-root base_url. The release also closes a missing DAG read-permission check on the dependencies endpoint (#62046, #62586).

  • Elasticsearch remote logging reaches parity — Remote task logging to Elasticsearch is now fully supported with apache-airflow-providers-elasticsearch>=6.5.0 (#62940, #62121). If you use remote logging, pin that provider floor and read its 6.5.0 notes — this is what makes the ES backend a first-class option alongside the older S3/WASB paths (WASB base-path handling was also fixed, #61013).

  • Database and migration changes to watch during upgrade — dag_bundle.signed_url_template widens from varchar(200) to text (#61041, #62568); SQLite migration handling of disable_sqlite_fkeys is corrected in revision 509b94a1042d (#63256, #63272); task_instance_history sequence is restored on downgrade (#62759); and XCom migration no longer chokes on NaN/Infinity floats (#62686) or pendulum.date.Date serialization (#61176). Back up and test both upgrade and rollback paths, especially on SQLite.

  • Task SDK and plugin API additions — literal and ParamsDict are now exposed at the SDK top level (#59782, #62756), a new on_task_instance_skipped listener hookspec lands (#59467, #61863), and XComResponse gains a run_after alias for backward compatibility (#61443, #61672). Low-risk but useful for plugin and custom DAG authors: they remove private-import workarounds and let you react to skips without polling task state.

  • Reliability and observability fixes worth noting — Crash fixes for the triggerer when a trigger calls builtin print (#60258, #61703), the API server under PYTHONASYNCIODEBUG=1 (#61281, #61933), and the scheduler on a task instance with a null dag_version_id (#61813, #61846). OTEL metrics are flushed at process shutdown (#61808, #61869) and missing ti.start/ti.finish metrics are restored (#62019, #62110) — relevant if you build SLOs on Airflow 3 metrics. UI changes also cut grid-view memory and API pressure (#61273, #61656, #62085).
