opentelemetry-collecteur v0.165.0

Images et binaires ici : https://github.com/open-telemetry/opentelemetry-collector-releases/releases/tag/v0.165.0

Utilisateur final Changelog

🛑 Changements récents 🛑

  • pkg/confighttp : Supprimez les champs obsolètes IdleConnTimeout, MaxIdleConns, MaxIdleConnsPerHost, DisableKeepAlives. (#15973)

🚀 Nouveaux composants 🚀

  • pkg/xreceiverhelper : ajoutez xreceiverhelper avec un ObsReport qui rapporte les métriques d'échantillon de profil par type d'échantillon. (#16251) ObsReport.EndProfilesOpBySampleType enregistre le Métriques otelcol_receiver_{accepted,refused,failed}_profile_samples avec un supplément Attribut sample_type, formaté comme "type:unit", car une seule charge utile peut contenir plusieurs profils avec différents types d’échantillons. Utilisez ProfileSampleCountsByType pour calculer le nombre d'échantillons avant les profils sont transmis au consommateur suivant, car les données peuvent être mutées en aval. Le récepteur OTLP utilise désormais EndProfilesOpBySampleType.

💡 Améliorations 💡

  • pkg/configmiddleware : permet de remplacer le numéroteur utilisé par confighttp.ToClient et configgrpc.ToClient (#16019)
  • pkg/featuregate : Autoriser les traits de soulignement dans les ID de porte de fonctionnalité. (#16243)
  • pkg/pdata : améliore les performances des fonctions pcommon.Map Get, Range et All. (#16282, #16321)
  • pkg/pdata : Réduire le nombre d'allocations lors de la mise à jour d'une primitive (#16226)
  • pkg/service : le service prend désormais en charge la configuration de détecteurs de ressources supplémentaires pour la télémétrie interne conformément à la mise à jour d'otelconf v0.26.0. (#15869)
  • pkg/service : Avertir au démarrage lorsqu'un pipeline combine le processeur par lots avec le traitement par lots exporterhelper. (#15965) La détection ne croise pas les connecteurs et n'inspecte pas les wrappers d'exportateur qui cachent la capacité de traitement par lots d'exportorhelper.
  • pkg/xprocessorhelper : Instrument xprocessorhelper.NewProfiles avec otelcol_processor_incoming_items, otelcol_processor_outgoing_items et otelcol_processor_internal_duration, cohérent avec les autres constructeurs de signaux. (#15523)
  • processor/memory_limiter : ajout d'une section de configuration garbage_collector pour permettre la désactivation du garbage collection forcé via le champ enabled. (#15081)
  • processor/queue_batch : faites passer le processeur queue_batch en version bêta pour les traces, les métriques et les journaux, et en alpha pour les profils. (#12022)
  • processor/queue_batch : rapporter les métriques de file d'attente et de lot en tant que métriques de processeur (#14038)

🧰 Corrections de bugs 🧰

  • cmd/mdatagen : Correction de la panique dans Attribute.TestValue() et Attribute.TestValueTwo() lors de la gestion d'attributs à élément unique ou d'énumération vides. (#15644)
  • cmd/mdatagen : Correction de l'échec des tests de métriques générés lorsque les portes de fonctionnalités through_gates d'une migration de métriques sont promues après l'alpha. (#16249) Les tests générés définissent désormais explicitement les portes des fonctionnalités de migration pour chaque scénario de test et restauration leur état précédent lors du nettoyage, au lieu de supposer que les portes sont désactivées par défaut. Lorsque l'étape d'une porte interdit l'état dont un cas a besoin, comme la désactivation d'une porte stable, le constructeur de métriques le test ignore uniquement son décompte dépendant de la porte et ses assertions d'avertissement, ainsi que la métrique versionnée par combinaison les sous-tests pour cette combinaison sont ignorés.
  • cmd/mdatagen : Générez des documents de configuration README pour les définitions exported_configs. (#16164) Les définitions d'objet et les alias de type scalaire sous exported_configs sont désormais affichés dans le README après la table config:. Les packages qui déclarent uniquement exported_configs peuvent désormais obtenir des documents générés une fois que leur README contient les marqueurs de configuration. Les composants qui déclarent uniquement exported_configs n'obtiennent plus de table de configuration vide.
  • cmd/schemagen : Gérer les erreurs de fichier introuvable lors du chargement des schémas (#15925)
  • pkg/configgrpc : limite la fenêtre du décodeur zstd à la taille maximale configurée du message de réception au lieu de la valeur par défaut de la bibliothèque. (#16280) Une trame zstd déclare sa fenêtre dans l'en-tête et le décodeur lui a attribué avant de produire un résultat, donc un petit message spécialement conçu pourrait générer un grand allocation indépendamment de max_recv_msg_size_mib. Le décodeur est également est retourné dans son pool dès que gRPC en a terminé avec un message.
  • pkg/confighttp : Lié la fenêtre du décodeur zstd par max_request_body_size au lieu de la valeur par défaut de la bibliothèque. (#16280) Une trame zstd déclare sa fenêtre dans l'en-tête et le décodeur lui a attribué avant de produire quoi que ce soit, de sorte qu'un petit corps fabriqué puisse conduire un grand allocation quelle que soit la taille du corps de la demande configurée.
  • pkg/confighttp : Accepter Content-Encoding : identité comme équivalent à aucun encodage. (#15122)
  • pkg/exporterhelper : Correction d'une panique Cannot unref freed data lorsqu'une file d'attente d'envoi persistante transfère les requêtes vers un autre pipeline (#15256)
  • pkg/exporterhelper : Avec wait_for_result, annulation d'une requête dont la file d'envoi déjà acceptée ne revient plus tôt (#16255) Auparavant, un contexte annulé faisait renvoyer context.Canceled alors que la requête était toujours livrés, afin que les appelants puissent signaler un échec pour les données qui avaient été envoyées. L'annulation prend encore effet alors que rien n’a été fait avec la demande.
  • pkg/pdata : ajout d'une limite de profondeur de récursion (100) à la désorganisation des prototypes d'AnyValue, ArrayValue, KeyValueList et KeyValue pour empêcher le débordement de pile de charges utiles profondément imbriquées conçues de manière malveillante. (#15301)
  • pkg/service : ignorer les nœuds de graphique qui n'ont pas été construits lors de l'arrêt pour éviter une panique lorsqu'un rechargement partiel du récepteur ne parvient pas à construire un récepteur. (#16261)

opentelemetry-collector v0.165.0

Images and binaries here: https://github.com/open-telemetry/opentelemetry-collector-releases/releases/tag/v0.165.0

End User Changelog

🛑 Breaking changes 🛑

  • pkg/confighttp: Remove deprecated fields IdleConnTimeout, MaxIdleConns, MaxIdleConnsPerHost, DisableKeepAlives. (#15973)

🚀 New components 🚀

  • pkg/xreceiverhelper: Add xreceiverhelper with an ObsReport that reports profile sample metrics per sample type. (#16251) ObsReport.EndProfilesOpBySampleType records the otelcol_receiver_{accepted,refused,failed}_profile_samples metrics with an additional sample_type attribute, formatted as "type:unit", as a single payload can hold multiple profiles with different sample types. Use ProfileSampleCountsByType to compute the sample counts before the profiles are passed to the next consumer, as the data may be mutated downstream. The OTLP receiver now uses EndProfilesOpBySampleType.

💡 Enhancements 💡

  • pkg/configmiddleware: allow to override the dialer used by confighttp.ToClient and configgrpc.ToClient (#16019)
  • pkg/featuregate: Allow underscores in feature gate IDs. (#16243)
  • pkg/pdata: Improve performance of pcommon.Map Get, Range, and All functions. (#16282, #16321)
  • pkg/pdata: Reduce number of allocations when updating an oneof primitive (#16226)
  • pkg/service: Service now supports configuring additional resource detectors for internal telemetry as per the update to otelconf v0.26.0. (#15869)
  • pkg/service: Warn at startup when a pipeline combines the batch processor with exporterhelper batching. (#15965) Detection does not cross connectors or inspect exporter wrappers that hide exporterhelper's batching capability.
  • pkg/xprocessorhelper: Instrument xprocessorhelper.NewProfiles with otelcol_processor_incoming_items, otelcol_processor_outgoing_items, and otelcol_processor_internal_duration, consistent with the other signal constructors. (#15523)
  • processor/memory_limiter: Add garbage_collector config section to allow disabling forced garbage collection via enabled field. (#15081)
  • processor/queue_batch: Promote the queue_batch processor to beta for traces, metrics, and logs, and to alpha for profiles. (#12022)
  • processor/queue_batch: Report queue and batch metrics as processor metrics (#14038)

🧰 Bug fixes 🧰

  • cmd/mdatagen: Fix panic in Attribute.TestValue() and Attribute.TestValueTwo() when handling single-element or empty enum attributes. (#15644)

  • cmd/mdatagen: Fix generated metrics tests failing when a metric migration's through_gates feature gates are promoted past alpha. (#16249) The generated tests now explicitly set the migration feature gates for each test case and restore their previous state on cleanup, instead of assuming the gates are disabled by default. When a gate's stage forbids the state a case needs, such as disabling a stable gate, the metrics-builder test skips only its gate-dependent count and warning assertions, and the per-combination versioned-metric sub-tests for that combination are skipped.

  • cmd/mdatagen: Generate README configuration docs for exported_configs definitions. (#16164) Object definitions and scalar type aliases under exported_configs are now rendered in the README after the config: table. Packages that only declare exported_configs can now get generated docs once their README contains the config markers. Components that only declare exported_configs no longer get an empty configuration table.

  • cmd/schemagen: Handle file-not-found errors when loading schemas (#15925)

  • pkg/configgrpc: Bound the zstd decoder window by the configured maximum receive message size instead of the library default. (#16280) A zstd frame declares its window in the header and the decoder allocated it before producing any output, so a small crafted message could drive a large allocation regardless of max_recv_msg_size_mib. The decoder is also returned to its pool as soon as gRPC is done with a message.

  • pkg/confighttp: Bound the zstd decoder window by max_request_body_size instead of the library default. (#16280) A zstd frame declares its window in the header and the decoder allocated it before producing any output, so a small crafted body could drive a large allocation regardless of the configured request body size.

  • pkg/confighttp: Accept Content-Encoding: identity as equivalent to no encoding. (#15122)

  • pkg/exporterhelper: Fix a Cannot unref freed data panic when a persistent sending queue forwards requests into another pipeline (#15256)

  • pkg/exporterhelper: With wait_for_result, canceling a request that the sending queue already accepted no longer returns early (#16255) Previously a canceled context made it return context.Canceled while the request was still delivered, so callers could report a failure for data that had been sent. Canceling still takes effect while nothing has been done with the request.

  • pkg/pdata: Add recursion depth limit (100) to proto unmarshalling of AnyValue, ArrayValue, KeyValueList, and KeyValue to prevent stack overflow from maliciously crafted deeply nested payloads. (#15301)

  • pkg/service: Skip graph nodes that have not been built during shutdown to prevent a panic when a partial receiver reload fails to build a receiver. (#16261)

  • pkg/componentstatus: Deprecate componentstatus.Watcher in favour of extensioncapabilities.ComponentStatusWatcher (#16304)

🚀 New components 🚀

  • pkg/xreceiverhelper: Add xreceiverhelper with an ObsReport that reports profile sample metrics per sample type. (#16251) ObsReport.EndProfilesOpBySampleType records the otelcol_receiver_{accepted,refused,failed}_profile_samples metrics with an additional sample_type attribute, formatted as "type:unit", as a single payload can hold multiple profiles with different sample types.
