Utilisateur final Changelog

🛑 Changements récents 🛑

  • pkg/configoptional : Retirer le portail stabilisé configoptional.AddEnabledField. (#15421)
  • pkg/confmap : Supprimer le featuregate stabilisé confmap.newExpandedValueSanitizer (#15418)
  • pkg/exporterhelper : Retirer la porte d'écurie exporter.PersistRequestContext. (#15424)
  • pkg/otelcol : Supprimer la porte d'écurie otelcol.printInitialConfig (#15425)
  • pkg/service : Supprimer le featuregate stable telemetry.UseLocalHostAsDefaultMetricsAddress (#15419)
  • pkg/xpdata : Retirer la porte d'écurie pdata.enableRefCounting. (#15426)
  • processor/memory_limiter : renommez les métriques de limiteur de mémoire obsolètes pour inclure le préfixe memory_limiter (par exemple otelcol_processor_memory_limiter_*) afin de clarifier qu'elles sont spécifiques à ce processeur. (#11203)

🚀 Nouveaux composants 🚀

  • cmd/schemagen : déplacez le schemagen CLI de opentelemetry-collector-contrib vers ce référentiel en tant que cmd/schemagen. (#14543) La source de l'outil est identique à la version de contrib en amont (github.com/open-telemetry/opentelemetry-collector-contrib/cmd/schemagen) à l'exception du chemin du module et l'espace de noms des appareils de test, qui reflète désormais le module collecteur (go.opentelemetry.io/collector/cmd/schemagen). Un test d'intégration de contribution uniquement qui pointait vers trois les composants de contribution sont supprimés ; Le CI make generate-schemas + git-diff existant de contrib continue de exercez la fonctionnalité FactoryMaps sur des composants du monde réel.

💡 Améliorations 💡

  • cmd/mdatagen : ajout de la prise en charge des métriques versionnées (#15309) Permet aux métadonnées de spécifier des métriques versionnées pour la migration vers de nouvelles conventions sémantiques. Deux scénarios sont possibles lorsque le nom de la métrique reste le même pendant la migration. Lorsqu'un nom de métrique reste le même mais que son type diffère, seule la dernière métrique est émis avec le nouveau type. Lorsqu'un nom de métrique reste le même mais que ses attributs diffèrent, la dernière version est émis avec des attributs combinés pendant la période de migration.
  • cmd/schemagen : ajoutez la prise en charge de overlayFile pour fusionner en profondeur des fragments de schéma sélectionnés à la main dans des schémas générés. (#14543) Les composants peuvent déclarer un overlayFile dans .schemagen.yaml pointant vers un fichier YAML dont les clés sont fusionnées de manière récursive dans le schéma généré automatiquement après génération. Cela permet d'injecter des descriptions, des contraintes ou des propriétés supplémentaires qui ne peuvent pas être utilisées. être dérivé des types Go. Initialement ajouté à la copie de contribution de cmd/schemagen dans open-telemetry/opentelemetry-collector-contrib#48917 et importé avec l'outil dans ce mouvement.
  • cmd/schemagen : ajoutez l'indicateur -p pour spécifier un modèle de package Go personnalisé pour la structure de configuration. (#14543) Le nouvel indicateur -p permet aux appelants de remplacer le modèle de package . par défaut par un paramètre arbitraire. Accédez au sélecteur de package (par exemple, un sous-paquet dont le schéma de type Config doit fonctionner). Initialement ajouté à la copie de contribution de cmd/schemagen dans open-telemetry/opentelemetry-collector-contrib#48966 et importé avec l'outil dans ce mouvement.

🧰 Corrections de bugs 🧰

  • cmd/mdatagen : Correction d'un problème lorsque la dernière porte de fonctionnalité est supprimée, des fichiers obsolètes restent. (#15423)
  • cmd/mdatagen : Correction des acronymes connus à la fin des identifiants Go générés pour qu'ils soient en majuscules, comme dans toute autre position (#15438)
  • cmd/schemagen : Correction de la détection du mode lors de l'utilisation de -p pour cibler un package en dehors du répertoire courant. (#15453) Un nouveau drapeau -m component|package est disponible en remplacement manuel lorsque la détection automatique n'est pas possible.

opentelemetry-collector v0.155.0

Images and binaries here: https://github.com/open-telemetry/opentelemetry-collector-releases/releases/tag/v0.155.0

End User Changelog

🛑 Breaking changes 🛑

  • pkg/confighttp: Remove stabilized gate confighttp.framedSnappy (#15420)
  • pkg/configoptional: Remove stabilized gate configoptional.AddEnabledField. (#15421)
  • pkg/confmap: Remove stabilized featuregate confmap.newExpandedValueSanitizer (#15418)
  • pkg/exporterhelper: Remove stable gate exporter.PersistRequestContext. (#15424)
  • pkg/otelcol: Remove stable gate otelcol.printInitialConfig (#15425)
  • pkg/service: Remove stable featuregate telemetry.UseLocalHostAsDefaultMetricsAddress (#15419)
  • pkg/xpdata: Remove stable gate pdata.enableRefCounting. (#15426)
  • processor/memory_limiter: Rename deprecated memory limiter metrics to include the memory_limiter prefix (e.g. otelcol_processor_memory_limiter_*) to clarify they are specific to this processor. (#11203)

🚀 New components 🚀

  • cmd/schemagen: Move the schemagen CLI from opentelemetry-collector-contrib to this repository as cmd/schemagen. (#14543) The tool's source is identical to the upstream contrib version (github.com/open-telemetry/opentelemetry-collector-contrib/cmd/schemagen) except for the module path and the test fixtures' namespace, which now reflect the collector module (go.opentelemetry.io/collector/cmd/schemagen). A contrib-only integration test that pointed at three contrib components is removed; contrib's existing make generate-schemas + git-diff CI continues to exercise the FactoryMaps feature against real-world components.

💡 Enhancements 💡

  • cmd/mdatagen: Add support for versioned metrics (#15309) Allows metadata to specify versioned metrics for migrating to new semantic conventions. There are two scenarios catered for when the metric name stays the same during migration. When a metric name stays the same but its type differs, just the latest metric is emitted with the new type. When a metric name stays the same but its attributes differ, the latest version is emitted with combined attributes during the migration period.

  • cmd/schemagen: Add overlayFile support to deep-merge hand-curated schema fragments into generated schemas. (#14543) Components can declare an overlayFile in .schemagen.yaml pointing to a YAML file whose keys are recursively merged into the auto-generated schema after generation. This allows injecting descriptions, constraints, or additional properties that cannot be derived from Go types. Originally added to the contrib copy of cmd/schemagen in open-telemetry/opentelemetry-collector-contrib#48917 and brought over with the tool in this move.

  • cmd/schemagen: Add -p flag to specify a custom Go package pattern for the config struct. (#14543) The new -p flag lets callers override the default . package pattern with an arbitrary Go package selector (e.g. a sub-package whose Config type schemagen should walk). Originally added to the contrib copy of cmd/schemagen in open-telemetry/opentelemetry-collector-contrib#48966 and brought over with the tool in this move.

🧰 Bug fixes 🧰

  • cmd/mdatagen: Fix an issue when the last feature gate is removed, stale files are left. (#15423)
  • cmd/mdatagen: Fix known acronyms at the end of generated Go identifiers to be all-caps, same as in any other position (#15438)
  • cmd/schemagen: Fix mode detection when using -p to target a package outside the current directory. (#15453) A new -m component|package flag is available as a manual override when auto-detection is not possible.

API Changelog

🛑 Breaking changes 🛑

  • cmd/mdatagen: Remove the reaggregation_enabled metadata setting and always generate per-metric reaggregation config. (#15305) Legacy metadata files that still contain reaggregation_enabled are accepted, but the value is ignored.

🚩 Deprecations 🚩

  • pkg/service: Deprecate service.Settings.CollectorConf and extensioncapabilities.ConfigWatcher in favor of service.Settings.ConfigSnapshot and extensioncapabilities.ConfigSnapshotWatcher, which provide effective and unexpanded configuration representations. (#15432)

💡 Enhancements 💡

  • pkg/config/configmiddleware: Migrated middleware config to schema based (#15440)
  • pkg/pdata: Add DisallowUnknownFields option to JSONUnmarshaler in plog, ptrace, pmetric, pprofile, and xpdata to error on JSON fields not defined by the OTLP schema. (#15279) When DisallowUnknownFields is false (the default), unknown fields are silently ignored, matching the previous behavior. Warning: enabling this option breaks forwards compatibility with future evolutions of the OTLP format, as fields added to the format in newer versions will be rejected as unknown.

🧰 Bug fixes 🧰

  • cmd/mdatagen: Fix known acronyms at the end of generated Go identifiers to be all-caps, same as in any other position (#15438)
