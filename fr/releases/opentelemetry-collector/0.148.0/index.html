Utilisateur final Changelog

❗ Problèmes connus ❗

  • service : le point de terminaison de métriques interne Prometheus du collecteur (:8888) émet désormais des étiquettes de service OTel avec un trait de soulignement. noms (service_name, service_instance_id, service_version) au lieu de noms en notation par points (service.name, service.instance.id, service.version). Les utilisateurs scraping ce point de terminaison avec le récepteur Prometheus verront ceux-ci renommés étiquettes dans les attributs de ressources et de points de données. Pour contourner le problème, ajoutez le metric_relabel_configs suivant à votre scrape config dans le récepteur prometheus : 
    metric_relabel_configs:  - source_labels: [service_name]    target_label: service.name  - source_labels: [service_instance_id]    target_label: service.instance.id  - source_labels: [service_version]    target_label: service.version  - regex: service_name|service_instance_id|service_version    action: labeldrop
    Voir https://github.com/open-telemetry/opentelemetry-collector/issues/14814 pour plus de détails et de mises à jour.

🛑 Changements récents 🛑

  • all : modifiez les unités métriques pour qu'elles soient singulières afin de correspondre aux spécifications OTel, par ex. {requests} -> {request} (#14753)

💡 Améliorations 💡

  • cmd/mdatagen : ajout du champ deprecated_type pour permettre de spécifier un alias pour les types de composants. (#14718)
  • cmd/mdatagen : Générer un MetricsBuilder API à l'échelle de l'entité qui applique les associations entité-métrique au moment de la compilation (#14659)
  • cmd/mdatagen : ignorer la génération des options de configuration de réagrégation pour les métriques qui n'ont pas d'attributs agrégeables. (#14689)
  • pkg/service : le rapporteur d'état interne ne supprime plus les statuts répétés Ok et RecoverableError (#14282) Les événements de statut peuvent désormais transporter des métadonnées et il est utile de permettre leur émission malgré la valeur de statut elle-même. ne change pas.

🧰 Corrections de bugs 🧰

  • cmd/builder : ajoutez .exe pour afficher les noms binaires lors de la création pour les cibles Windows. (#12591)
  • exporter/debug : Ajout de l'impression des métadonnées métriques avec une verbosité détaillée. (#14667)
  • exporter/otlp_grpc : évite la panique du pointeur nul lorsque les méthodes push sont appelées avant que l'exportateur OTLP n'initialise ses gRPC clients. (#14663) Lorsque la file d'attente d'envoi et les nouvelles tentatives sont désactivées, l'appel de ConsumeTraces, ConsumeMetrics, ConsumeLogs ou ConsumeProfiles avant l'exportateur OTLP initialise ses gRPC clients pourrait provoquer une panique de déréférencement de pointeur nul. Les méthodes push renvoient désormais une erreur au lieu de paniquer.
  • exporter/otlp_http : affiche l'URL de destination réelle dans les messages d'erreur lorsque l'URL de la demande est modifiée par le middleware. (#14673) Déballe le *url.Error renvoyé par http.Client.Do() pour éviter les journaux d'erreurs trompeurs lorsqu'une extension middleware met à jour dynamiquement le point de terminaison.
  • pdata/pprofile : Changer le dictionnaire des entrées des tables du dictionnaire une seule fois lors de la fusion des profils (#14709) Pour les données des tables de dictionnaire, nous avions l'habitude de changer de dictionnaire lorsque nous faisions le commutateur pour les données qui les utilisent. Cependant, lorsqu'une entrée est associée à plusieurs autres données (plusieurs les échantillons peuvent utiliser la même pile), nous aurions changé le dictionnaires de l’entrée plusieurs fois. Nous changeons désormais de dictionnaire pour les données de table de dictionnaire une seule fois, avant changer les profils de ressources.

API Changelog

🛑 Changements récents 🛑

  • cmd/mdatagen : générer un type de configuration par métrique <MetricName>Config pour chaque métrique lorsque reaggregation_enabled: true (#14689) Les métriques avec des attributs agrégeables obtiennent AggregationStrategy et EnabledAttributes []<MetricName>AttributeKey champs; d'autres obtiennent uniquement Enabled. Constantes de clé d'attribut saisies (par exemple DefaultMetricAttributeKeyStringAttr) remplacez []string, éliminant ainsi les allocations de tranches d'attributs d'exécution. Les erreurs de validation répertorient désormais les attributs valides et les stratégies par leur nom. Les composants utilisant reaggregation_enabled: true devront mettre à jour les références à MetricConfig.
  • pdata/pprofile : Mettre à jour le protoID pour les champs d'exemple de message (#14652)

💡 Améliorations 💡

  • cmd/mdatagen : extension de l'outil mdatagen pour générer des structures de configuration go pour les composants du collecteur OpenTelemetry. (#14561) Le code go de configuration du composant est généré à partir de la section config du fichier metadata.yaml.
  • cmd/mdatagen : étendre l'outil mdatagen pour générer le schéma de configuration JSON pour les composants OpenTelemetry. (#14543) Le schéma de configuration du composant JSON est généré à partir de la section config du fichier metadata.yaml.
  • cmd/mdatagen : Génération de schéma pour les parties de configuration contrôlées par mdatagen (#14562) Le schéma est généré dans un fichier yaml séparé et utilisé pour créer un schéma de composant complet.
  • pdata/pprofile : Implémentation d'attributs basés sur la référence dans les profils (#14546)
  • pkg/pdata : Mise à niveau des définitions de protobuf OTLP vers la version 1.10.0 (#14766)
  • pkg/service : le rapporteur d'état interne ne supprime plus les statuts répétés Ok et RecoverableError (#14282) Les événements de statut peuvent désormais transporter des métadonnées et il est utile de permettre leur émission malgré la valeur de statut elle-même. ne change pas.
  • pkg/xexporterhelper : Ajout d'une logique pour nettoyer les partitions de la mémoire qui ne sont pas utilisées pendant une période de temps spécifique. (#14526)
  • pkg/xpdata : Ajouter le constructeur NewEntity, Entity.CopyToResource et EntityAttributeMap.All à pdata/xpdata/entity (#14659)

🧰 Corrections de bugs 🧰

  • cmd/mdatagen : préserve les extensions personnalisées (par exemple, x-customType, x-pointer) pendant la résolution de référence de schéma. (#14713, #14565) Résout un problème où les propriétés personnalisées définies localement sur un nœud étaient écrasé et perdu lors de la résolution d'un $ref en un schéma externe/interne.
  • pkg/xexporterhelper : Correction d'un problème de course lorsque la partition est supprimée de LRU et que de nouveaux éléments sont ajoutés en même temps. (#14526)

opentelemetry-collector v0.148.0

Images and binaries here: https://github.com/open-telemetry/opentelemetry-collector-releases/releases/tag/v0.148.0

End User Changelog

❗ Known Issues ❗

  • service: The collector's internal Prometheus metrics endpoint (:8888) now emits OTel service labels with underscore names (service_name, service_instance_id, service_version) instead of dot-notation names (service.name, service.instance.id, service.version). Users scraping this endpoint with the Prometheus receiver will see these renamed labels in resource and datapoint attributes. As a workaround, add the following metric_relabel_configs to your scrape config in prometheus receiver: 
    metric_relabel_configs:  - source_labels: [service_name]    target_label: service.name  - source_labels: [service_instance_id]    target_label: service.instance.id  - source_labels: [service_version]    target_label: service.version  - regex: service_name|service_instance_id|service_version    action: labeldrop
    See https://github.com/open-telemetry/opentelemetry-collector/issues/14814 for details and updates.

🛑 Breaking changes 🛑

  • all: Change metric units to be singular to match OTel specification, e.g. {requests} -> {request} (#14753)

💡 Enhancements 💡

  • cmd/mdatagen: Add deprecated_type field to allow specifying an alias for component types. (#14718)
  • cmd/mdatagen: Generate entity-scoped MetricsBuilder API that enforces entity-metric associations at compile time (#14659)
  • cmd/mdatagen: Skip generating reaggregation config options for metrics that have no aggregatable attributes. (#14689)
  • pkg/service: The internal status reporter no longer drops repeated Ok and RecoverableError statuses (#14282) Status events can now carry metadata and there's value in allowing them to be emitted despite the status value itself not changing.

🧰 Bug fixes 🧰

  • cmd/builder: Add .exe to output binary names when building for Windows targets. (#12591)

  • exporter/debug: Add printing of metric metadata in detailed verbosity. (#14667)

  • exporter/otlp_grpc: Prevent nil pointer panic when push methods are called before the OTLP exporter initializes its gRPC clients. (#14663) When the sending queue and retry are disabled, calling ConsumeTraces, ConsumeMetrics, ConsumeLogs, or ConsumeProfiles before the OTLP exporter initializes its gRPC clients could cause a nil pointer dereference panic. The push methods now return an error instead of panicking.

  • exporter/otlp_http: Show the actual destination URL in error messages when request URL is modified by middleware. (#14673) Unwraps the *url.Error returned by http.Client.Do() to prevent misleading error logs when a middleware extension dynamically updates the endpoint.

  • pdata/pprofile: Switch the dictionary of dictionary tables entries only once when merging profiles (#14709) For dictionary table data, we used to switch their dictionaries when doing the switch for the data that uses them. However, when an entry is associated with multiple other data (several samples can use the same stack), we would have been switching the dictionaries of the entry multiple times.

    We now switch dictionaries for dictionary table data only once, before switching the resource profiles.

API Changelog

🛑 Breaking changes 🛑

  • cmd/mdatagen: Generate a per-metric config type <MetricName>Config for each metric when reaggregation_enabled: true (#14689) Metrics with aggregatable attributes get AggregationStrategy and EnabledAttributes []<MetricName>AttributeKey fields; others get Enabled only. Typed attribute key constants (e.g. DefaultMetricAttributeKeyStringAttr) replace []string, eliminating runtime attribute slice allocations. Validation errors now list valid attributes and strategies by name. Components using reaggregation_enabled: true will need to update references to MetricConfig.

  • pdata/pprofile: Update protoID for message Sample fields (#14652)

💡 Enhancements 💡

  • cmd/mdatagen: Extend mdatagen tool to generate go config structs for OpenTelemetry collector components. (#14561) The component config go code is generated from config section of the metadata.yaml file.

  • cmd/mdatagen: Extend mdatagen tool to generate config JSON schema for OpenTelemetry components. (#14543) The component config JSON schema is generated from config section of the metadata.yaml file.

  • cmd/mdatagen: Schema generation for mdatagen-controlled config parts (#14562) The schema is generated in separate yaml file and used to create full component schema.

  • pdata/pprofile: Implement reference based attributes in Profiles (#14546)

  • pkg/pdata: Upgrade the OTLP protobuf definitions to version 1.10.0 (#14766)

  • pkg/service: The internal status reporter no longer drops repeated Ok and RecoverableError statuses (#14282) Status events can now carry metadata and there's value in allowing them to be emitted despite the status value itself not changing.

  • pkg/xexporterhelper: Add logic to cleanup partitions from memory which are not being used for specific time period. (#14526)

  • pkg/xpdata: Add NewEntity constructor, Entity.CopyToResource, and EntityAttributeMap.All to pdata/xpdata/entity (#14659)

🧰 Bug fixes 🧰

  • cmd/mdatagen: Preserve custom extensions (e.g., x-customType, x-pointer) during schema reference resolution. (#14713, #14565) Fixes an issue where custom properties defined locally on a node were overwritten and lost when resolving a $ref to an external/internal schema.

  • pkg/xexporterhelper: Fix race when partition is being removed from LRU and new items are being added at the same time. (#14526)
