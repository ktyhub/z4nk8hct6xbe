rea rea-agents-4.0.0

4.0.0 (2026-10-05)

⚠ CHANGEMENTS DE RUPTURE

  • Les métadonnées de comparaison gérées ajoutent la correspondance de signature exacte et son nombre, et name_matching rapporte désormais le repli de signature exacte.
  • configuration : la configuration sans portée actualise uniquement les enregistrements existants appartenant à REA. Utilisez --all-detected pour configurer chaque client détecté. Le programme d'installation JSON contient un résumé compact du médecin ; utilisez un vrai médecin pour un diagnostic complet. L’annulation et les essais réussis se terminent désormais avec succès.
  • Supprimez la relecture contrôlée, la caractérisation des nœuds, la machine de relecture finie, la planification d'exécution gérée et les outils de traçage de chaînes redondants. Supprimez la relecture des processus, les cales, les scénarios réactifs, les points de contrôle personnalisés, ainsi que la relecture active du navigateur et les entrées de portée d'origine.
  • outils : Suppression des commandes de configuration et de politique des autorisations, des champs d'approbation, des entrées de portée du système de fichiers et des options de confirmation corrigées. La capture de processus hérite de l'environnement hôte et accepte les noms de commandes ; les appelants doivent actualiser les schémas des outils et migrer les champs supprimés.

rea rea-agents-4.0.0

4.0.0 (2026-10-05)

⚠ BREAKING CHANGES

  • Managed comparison metadata adds exact-signature matching and its count, and name_matching now reports exact-signature-fallback.
  • setup: unscoped setup refreshes only existing REA-owned registrations. Use --all-detected to configure every detected client. Setup JSON contains a compact doctor summary; use rea doctor for full diagnostics. Cancellation and successful dry runs now exit successfully.
  • Remove controlled replay, Node characterization, finite replay-machine, managed runtime planning, and redundant string-tracing tools. Retire process replay, shims, reactive scenarios, custom checkpoints, and active browser replay and origin-scope inputs.
  • tools: Removed permission configuration and policy commands, approval fields, filesystem scope inputs, and fixed confirmation options. Process capture inherits the host environment and accepts command names; callers must refresh tool schemas and migrate removed fields.
