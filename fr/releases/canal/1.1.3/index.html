canal canal-1.1.3

Nouvelles fonctions

  1. Prend en charge le nouveau protocole d'authentification caching_sha2_password de mysql8.0
  2. Prise en charge du protocole d'authentification Azure MySQL
  3. Le canal délivre le message MQ [Livraison MQ]
    • Prise en charge de la possibilité de définir un routage dynamique de sujets et de partitions selon les règles de la table
    • Ajout d'une transaction de livraison de messages Kafka
  4. client intégré du canal [ClientAdapter]
    • L'adaptateur rds ajoute la configuration de synchronisation mysql à tout le niveau de la base de données
    • es-adapter ajoute une adaptation d'index de documents parent-enfant

Petites exigences et correction de bugs

  1. Résolvez le problème selon lequel le serveur monocœur ne peut pas recevoir de données #1605
  2. Corrigez TableMeta TSDB pour prendre en charge utf8mb4 #1550
  3. Correction de la duplication de données en mode non-flatMessage lors de l'envoi de messages MQ #1551
  4. Correction des données apparaissant lorsque Kafka est configuré en mode partition #1636
  5. Correction de plusieurs problèmes d'analyse DDL de fastsql #1306 #1546 #1626
  6. Corrigez la conversion de type, le pointeur nul, la casse, la synchronisation DDL et d'autres problèmes de synchronisation de l'adaptateur rdb #1313 #1338 #1341 #1408 #1433
  7. Correction du mode de livraison MQ, le serveur de canal HA ne prend pas effet après le changement #1229
  8. Corrigez l'erreur de type de clé primaire dans la base de données es-adapter #1559
  9. Correction de l'encodage du jeu de caractères n'existe pas #1662

canal canal-1.1.3

Highlights

  • Authentication coverage — Adds support for MySQL 8’s caching_sha2_password and Azure MySQL authentication, removing protocol-level connection blockers for those sources. Validate credentials and connection security against the target server when switching sources.
  • MQ routing and Kafka transactions — Per-table rules can now select dynamic topics and partitions, enabling table-specific streams and deliberate partition placement. New Kafka delivery transactions add atomic publication, but routing changes can invalidate consumer offset and ordering assumptions, and Kafka transactions alone do not provide end-to-end exactly-once processing.
  • Adapter scope and data modeling — rds-adapter can synchronize an entire MySQL database, reducing table-by-table setup while broadening captured changes; es-adapter adds parent/child document indexing for relational structures. Review database scope and Elasticsearch mappings before enabling them.
  • HA and delivery reliability — Fixes address single-core server ingestion (#1605), duplicate MQ sends outside flatMessage mode (#1551), and MQ delivery failing to switch over after Canal Server HA changes (#1229). HA and non-flat-message deployments should verify failover and deduplication behavior after upgrading.
  • Schema and encoding correctness — fastsql DDL fixes (#1306, #1546, #1626), rdb-adapter type/nullability/case/DDL fixes (#1313, #1338, #1341, #1408, #1435), and ES primary-key typing (#1559) reduce replication and indexing drift during schema changes. TSDB utf8mb4 and missing-charset fixes (#1550, #1662) also matter for metadata-heavy deployments; revalidate affected tables if earlier runs produced mismatches.
  • Compatibility — No breaking changes are explicitly listed.

功能新增

  1. 支持mysql8.0新的caching_sha2_password认证协议
  2. 支持Azure MySQL的认证协议
  3. canal投递MQ消息 【MQ投递】
    • 支持按表规则定义dynamic topic、partition路由的能力
    • 新增kafka消息投递事务
  4. canal内置的客户端【ClientAdapter】
    • rds-adapter 增加mysql整个DB层面的同步配置
    • es-adapter 新增父子文档索引适配

小需求&bugfix

  1. 解决server单核服务器无法接收数据的问题 #1605
  2. 修复TableMeta TSDB支持utf8mb4 #1550
  3. 修复MQ消息发送时非flatMessage模式出现数据重复 #1551
  4. 修复Kafka配置为分区模式时出现数据 #1636
  5. 修复fastsql的几个DDL解析问题 #1306 #1546 #1626
  6. 修复rdb-adapter同步的类型转化、空指针、大小写、DDL同步等问题 #1313 #1338 #1341 #1408 #1433
  7. 修复投递MQ模式，canal server HA在切换后不生效 #1229
  8. 修复es-adapter数据库主键类型错误 #1559
  9. 修复charset编码不存在 #1662
