canal 1.1.6

Correctif Publié24 mai 2022 Sourcealibaba/canal Anglais original

Cette page est traduite automatiquement. Le texte anglais original fait foi.

canal canal-1.1.6

Nouvelles fonctions

  1. Prise en charge de l'abonnement et de la consommation du binlog PolarDB-X 2.0
    • PolarDB-X est une base de données distribuée cloud native développée indépendamment par Alibaba. Le Binlog global récemment lancé est entièrement compatible avec le protocole binlog mysql [Document de référence] (https://help.aliyun.com/document_detail/207719.html)
    • Canal peut prendre en charge nativement l'amarrage des journaux binaires PolarDB-X et prend entièrement en charge plusieurs modes tels que TCP/MQ/adaptateur #3494.
  2. Ajout du support Puslar MQ #3791 #4060
  3. Ajout d'un adaptateur pour prendre en charge TableStore #3754
  4. Compatible avec la nouvelle version de MySQL8.0 (8.0.29), telle que les colonnes cachées, les types de caractères, etc., #3976

Optimisation importante

  1. Basculez fastjson vers la version 2.0.2 et mettez à niveau Druid vers la version 1.2.10.
  2. Correction des problèmes d'analyse des instructions DDL liés dans la méta de la table #3839 #3840 #3954 #3900
  3. Correction du problème selon lequel les métadonnées de la table ne pouvaient pas correspondre correctement aux conditions de filtre lors de l'enregistrement des versions historiques #3693
  4. Correction du connecteur Kafka lisant les variables d'environnement #3829
  5. Résolvez le problème d'échec de démarrage de l'adaptateur ES dans certains scénarios #3466 #3144 #3684
  6. Mettez à niveau jvm gc vers l'algorithme G1 #4014
  7. Corrigez l'erreur de synchronisation causée par les mots-clés sous synchronisation RDB #2783 #3984
  8. Résoudre le problème des threads simultanés sous la multi-instance sur une seule machine de l'adaptateur #3923

Petites exigences et correction de bugs

  1. Corrigez le problème du pointeur nul dans CanalServer.get() #4027
  2. Résoudre le problème de simultanéité du démarrage de l'instance en mode administrateur #4018
  3. Corrigez la vérification du mot de passe fort à 6 chiffres en mode administrateur #3877
  4. Correction de l'exception du pointeur nul lors de l'obtention des métadonnées de la table dans mysql 8.0 #3538
  5. Résoudre le problème de temps négatif du type de temps mysql #4178
  6. Correction de la configuration de surveillance de l'exportateur d'images docker du serveur canal #3576
  7. Correction du démarrage en mode local compatible avec canal-server sous Windows #3484
  8. Restaurer la version 18.0 de Guava pour être compatible avec le mode adaptateur #3880
  9. Correction de l'exception d'obtention du nom d'index sous synchronisation es #4122
  10. Résoudre le problème de deux tables de jointure sous synchronisation ES #4161
  11. Optimiser la configuration d'impression des journaux de Rocketmq #3329

canal canal-1.1.6

Highlights

  • PolarDB-X 2.0 CDC — Canal can now consume PolarDB-X 2.0 global binlog through its MySQL-compatible protocol using TCP, MQ, or adapter paths (#3494). This brings a distributed SQL source into existing Canal pipelines; validate DDL and schema-history behavior before cutting over production workloads.
  • Pulsar and TableStore integrations — Adds Apache Pulsar MQ support (#3791, #4060) and a TableStore adapter (#3754), expanding options for event distribution and downstream writes. Verify connector configuration and TableStore schema mappings during rollout.
  • MySQL 8.0.29 and schema-metadata fixes — Supports hidden columns and newer type metadata (#3976), while fixing DDL parsing (#3839, #3840, #3954, #3900), historical-version filter matching (#3693), and negative TIME values (#4178). These changes reduce schema-history mismatches and ingestion failures when replaying or filtering changes.
  • RDB synchronization and operational hardening — Fixes keyword-related RDB failures (#2783, #3984), admin-instance startup races (#4018), CanalServer.get() null pointers (#4027), and adapter multi-instance threading (#3923). Review the admin-mode six-character password validation change (#3877) against existing credentials before upgrading.
  • Dependency and JVM migration — FastJSON moves to 2.0.2, Druid to 1.2.10, and Guava is rolled back to 18.0 for adapter compatibility (#3880); JVM GC switches to G1 (#4014). Custom adapters directly using FastJSON may require package/API updates, and existing JVM heap and GC settings should be revalidated in staging.
  • Breaking changes — None explicitly declared; custom integrations still require compatibility checks against the dependency and JVM changes.

功能新增

  1. 支持PolarDB-X 2.0 binlog的订阅和消费
    • PolarDB-X是阿里巴巴自主研发的云原生分布式数据库，近期推出全局Binlog可完全兼容mysql binlog协议 参考文档
    • canal可原生支持PolarDB-X binlog对接,全面支持tcp/MQ/adapter等多种模式 #3494
  2. 新增Puslar MQ支持 #3791 #4060
  3. 新增Adapter，支持TableStore #3754
  4. 兼容MySQL8.0新版本(8.0.29), 比如隐藏列、type类型等，#3976

重要优化

  1. 切换fastjson为2.0.2版本，以及升级druid为1.2.10版本
  2. 修复table meta中相关DDL语句解析问题 #3839 #3840 #3954 #3900
  3. 修复table meta在保存历史版本时无法正确匹配过滤条件 #3693
  4. 修复kafka connector读取env变量 #3829
  5. 修复ES Adapter部分场景启动失败问题 #3466 #3144 #3684
  6. 升级jvm gc为G1算法 #4014
  7. 修复RDB同步下的关键字引起的同步报错 #2783 #3984
  8. 修复adapter单机多实例下的并发线程问题 #3923

小需求&bugfix

  1. 修复CanalServer.get()出现空指针问题 #4027
  2. 修复admin模式下instance启动的并发问题 #4018
  3. 修复admin模式下的密码6位强校验 #3877
  4. 修复mysql 8.0获取table meta的空指针异常 #3538
  5. 修复mysql time类型的负值时间问题 #4178
  6. 修复canal-server的docker镜像exporter监控配置 #3576
  7. 修复windows下兼容canal-server的local模式启动 #3484
  8. 回滚guava版本18.0兼容adapter模式 #3880
  9. 修复es同步下通过索引名获取异常 #4122
  10. 修复es同步下两个join表的问题 #4161
  11. 优化rocketmq的日志打印配置 #3329
