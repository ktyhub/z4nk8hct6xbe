brpc 1.18.0

Highlights

  • Parser hardening is the headline — treat 1.18.0 as a security upgrade — Much of this release bounds wire-declared sizes and decompressed output (#3382, #3476) and closes remotely reachable memory-safety bugs: HTTP/2 receive-path resource growth (#3474), request smuggling via HTTP/1 desync framing and dropped chunked trailers (#3521), char-signedness out-of-bounds reads in header/URL lookup tables (#3376), exp-golomb OOB reads in AVC SPS parsing (#3371, #3483, #3334), and a use-after-free in SingleIOBuf::assign (#3397). Depth/allocation caps also land for Redis, AMF, mcpack2pb and Thrift (#3344, #3353, #3499, #3500). If you expose brpc's HTTP or Redis-facing endpoints to untrusted traffic, upgrading closes real remotely triggerable bugs — but expect previously tolerated oversized or deeply nested payloads to start being rejected.

  • Builtin services move to internal_port — plan the migration before rollout — #3308, #3511, #3512 and #3525 gate builtin services (/vars, /status, pprof, etc.) behind ServerOptions.internal_port and apply auth checks to builtin requests arriving on the public port. This is the most disruptive operator-facing change: health checks, metrics scrapers and debugging endpoints will stop responding on the public port until you set internal_port and repoint them, so update your probes and monitoring config before putting 1.18.0 behind a load balancer.

  • New protocols and modern TLS materially widen adoption — A clean-room MySQL client covering auth, text protocol, transactions and prepared statements (#3310, #3330) lets simple integrations drop a separate MySQL client; TLSv1.3 (#3319) plus client-side peer name verification (#3408) modernize transport security (peer verification is new behavior — enable it for external calls); Protobuf v35 support (#3429) unblocks projects on newer protobuf, and body+attachment checksumming (#3407) protects large payloads end to end.

  • RDMA gets a correctness pass — plus a shared-memory alternative — Handshake V3 with ECE negotiation (#3350, #3326, #3352) and the LD/ST-based UBShmTransport (#3290) arrive alongside fixes for a fallback path that previously failed the socket instead of dropping to TCP (#3424, #3406), missed recv CQEs after re-arming (#3425), a server-side data race (#3505) and stale CQ callbacks (#3412). RDMA users should re-test failover: Socket::_state is now atomic (#3347), so fallback timing and state transitions have changed.

  • Streaming RPC refactored, with new limits and two new balancers — #3422 reworks streaming RPC and adds stream-ID validation, per-request stream caps and reassembled-message size limits (#3485, #3489, #3493, #3494); verify your stream counts and message sizes against these new ceilings. On routing, Peak-EWMA p2c (#3367) and bounded-load consistent hashing c_murmurhash_bl (#3502) become selectable, and WeightedRandomizedLoadBalancer no longer skips the last server (#3426) — a subtle but real shift in traffic distribution worth watching after upgrade.

  • Toolchain baseline and API surface change — check before building — All builds now target C++14 (#3419), and bthread drops its previously unimplemented barrier and rwlockattr APIs (#3504); the ADD/SUB_TLS_PTHREAD_LOCK_COUNT macros become inline functions (#3394) and TLS pointer access is macro-guarded on ARM (#3380). Bazel users get fixed external-dependency proto rules (#3427) and a bzlmod guide (#3468), while RISC-V gains Zvbc CRC32C (#3332) and a suite of RVV memcpy/base64/string optimizations. Confirm your compiler meets C++14 and remove any links to the dropped bthread symbols before upgrading.

Apache bRPC 1.18.0 broadens protocol coverage and platform support, and significantly hardens parsers and transport internals.
