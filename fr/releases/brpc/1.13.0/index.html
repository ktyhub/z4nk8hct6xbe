brpc 1.13.0

Highlights

  • HTTP and Baidu-std payload flexibility — HTTP bodies now support ProtoJson (#2921), while Baidu-std accepts JSON, Proto JSON, and Proto text (#2946). This improves protobuf interoperability, but clients must explicitly align serialization choices and test content-type handling.
  • Runtime-tunable method concurrency — Per-method concurrency can be updated dynamically (#2923), enabling operators to adjust throttling without redeploying. Recheck queueing and tail latency whenever limits change.
  • Automatic large-stream segmentation — Large bRPC stream messages are segmented automatically (#2889), reducing manual chunking and oversized-payload failures. Validate behavior with older or non-bRPC peers and monitor backpressure.
  • Concurrency correctness hardening — Fixes cover AgentCombiner (#2949), Wrapper (#2952), batch stream creation and SetHostSocket (#2938), plus compiler-sensitive thread-local access (#2918, #2934). High-concurrency services should rerun Release-build stress tests after upgrading.
  • Diagnostics and dependency compatibility — AddressSanitizer support (#2890), corrected Prometheus formatting (#2899), and EventDispatcher latency metrics (#2897) improve troubleshooting. Include protobuf v27+ (#2941) and glog linking (#2914) in dependency-upgrade build checks.
  • Breaking changes — None are listed in this release.
