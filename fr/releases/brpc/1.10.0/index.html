brpc 1.10.0

Highlights

  • Circuit breaker half-open state — (#2634) adds a half-open probe phase, so a tripped channel tests recovery with a limited request trickle before fully closing. Practically, this means fewer stuck-open circuits after transient downstream blips; what to watch is whether your existing failure thresholds and retry budgets still line up now that recovery is probed rather than purely timed.
  • Connect on socket creation — (#2574) establishes connections during Socket construction instead of deferring to the first RPC. This moves the error surface earlier: code that relied on lazy connect and never checked early failures must now handle them at creation time. Paired with the double-close (#2663) and uninitialized-local-side (#2672) fixes, Socket lifecycle handling is materially safer in this release.
  • Stricter HTTP handling — (#2600) rejects requests with no Host header, and (#2577) corrects malformed headers when multiple Cookie/Set-Cookie values are present. Standards-compliant callers are fine, but proxies, health checkers, or raw-socket clients that previously sent hostless requests will now be refused — audit those before upgrading. The h2 rpc_dump memory leak fix (#2661) is also worth noting for long-running servers.
  • Fine-grained threading control — bthread concurrency can now be set per tag (#2628), EventDispatcher accepts multiple IO types (#2560), and FastPthreadMutex is exposed to users with a contention profiler (#2589). For mixed-workload servers this enables targeted tuning; the new profiler is the right way to locate lock contention rather than guessing at it.
  • Compile-time and API hygiene — BRPC_VALIDATE_GFLAG is now restricted to global and namespace scope (#2625); macro uses inside classes or functions will fail to compile, so this is the most likely migration snag for downstream code. MongoServiceAdaptor and SpanFilter gain virtual destructors (#2651), making polymorphic deletion across shared-library boundaries safe, and the new SCOPE_EXIT macro (#2643) simplifies cleanup paths.
  • Correctness fixes worth prioritizing — FlatMap's assign operator (#2622) and multi-FlatMap scale/size bugs (#2669), stream_rpc↔baidu_std switching (#2678), and max-concurrency enforcement for thrift and nshead (#2613). If your services use FlatMap-backed structures or mix stream and standard RPC on the same endpoints, this release resolves real behavioral bugs rather than just polish.

No breaking changes are formally declared in this release.
