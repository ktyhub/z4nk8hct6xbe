brpc 1.15.0

Highlights

  • bthread scheduler correctness on ARM64 and under load — Several low-level concurrency bugs are fixed that could otherwise show up as hangs or crashes in production: bthread_id_unlock failing on aarch64 (#3084), a SIMD misalignment issue (#3092), and Signal Trace mode delivering SIGURG to the wrong thread (#3039). If you run brpc on ARM64 or enable signal tracing, these are the highest-priority fixes in the release — the signal bug in particular can manifest as mysterious interruptions in unrelated threads.

  • New opt-in bthread tuning knobs — Adds a configurable ParkingLot count (#3033), a bthread priority-queue flag (#3078), a "don't signal when no waiter" flag for parking lots (#3079), and a timer-bucket count flag (#3112). All new flags default to false/existing behavior, so adoption is zero-risk by default; the value is for high-contention services that previously had no way to tune scheduler wakeups or lock sharding. Watch these when profiling tail latency under heavy concurrency.

  • RDMA becomes easier to build against and more scalable — brpc::rdma::GlobalRdmaInitializeOrDie is now declared even without defining BRPC_WITH_RDMA (#3047), so callers can compile against the API without forcing the full RDMA build. The RDMA runtime also relaxes block restrictions and moves polling-mode message processing into a new bthread (#3076), which should improve throughput/isolation for RDMA users — test this carefully if you rely on the old in-poller processing assumptions.

  • Better latency visibility and safer diagnostics — RPCs now expose received_us to users (#3073), enabling accurate server-side queueing/latency attribution that was previously internal-only. MultiDimension::set_max_stats_count is made public (#3074) for stats control, while pb2json gains a depth limit (#3099) and the jemalloc profiler restricts extra options (#3101) — the former guards against stack exhaustion from deeply nested protobuf-to-JSON conversions, a real concern if you accept untrusted protobufs.

  • Build and dependency portability — Fixes a symbol conflict with glog by marking InstallSymbolizeOpenObjectFileCallback as BAIDU_WEAK (#3064), so brpc coexists more cleanly with glog-based stacks. Also adds Bazel config settings for with_bthread_tracer (#3111) and NO_PTHREAD_MUTEX_HOOK (#3090), repairs macOS CI including CMake < 3.5 compatibility (#3080, #3093), and replaces google::protobuf::int64 with plain int64_t (#3081) — collectively lowering friction for embedding, older toolchains, and non-default build configurations.

  • Stability fixes in core data paths — Addresses socket _versioned_ref recovery and removes the _hc_started flag (#3060), initializes _combiner in the IntRecorder constructor (#3066), fixes an infinite loop during flatmap resizing when the bucket count is a power of two (#3071), prevents WeightedRandomizedLoadBalancer from returning 0 with no servers (#3108), and removes BIO usage for SSL (#3105). These are quiet but important: the flatmap loop and load-balancer edge case can cause CPU spins or bad routing under specific conditions, so upgrade even if you don't need the new features.

No breaking changes are noted in this release.
