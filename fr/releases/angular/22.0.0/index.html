Modifications radicales

compilateur

  • Ce changement déclenchera les diagnostics nullishCoalescingNotNullable et optionalChainNotNullable sur les projets existants. Vous souhaiterez peut-être désactiver temporairement ces 2 diagnostics sur votre tsconfig.
  • L'attribut préfixé des données ne lie plus les entrées ni les sorties.
  • Le compilateur lancera le cas échéant lorsque les entrées, les sorties ou le modèle sont liés aux mêmes entrées/sorties.
  • Les variables in ajouteront des expressions de modèle.

compilateur-cli

  • Les éléments avec plusieurs sélecteurs correspondants seront désormais lancés au moment de la compilation.

noyau

  • Le deuxième argument de appRef.bootstrap n'accepte plus any. Assurez-vous que l'élément que vous transmettez n'est pas nullable.
    • Les versions TypeScript antérieures à 6.0 ne sont plus prises en charge.
  • Les animations de congé ne sont plus limitées à l'élément en cours de suppression.
  • Les composants avec la propriété changeDetection non définie sont désormais OnPush par défaut. Spécifiez changeDetection: ChangeDetectionStrategy.Eager pour conserver le comportement précédent.
  • modifier la signature AnimationCallbackEvent.animationComplete
  • ChangeDetectorRef.checkNoChanges a été supprimé. Dans les tests, utilisez plutôt fixture.detectChanges().
  • createNgModuleRef a été supprimé, utilisez plutôt createNgModule
  • ComponentFactoryResolver et ComponentFactory ne sont plus disponibles. Transmettez la classe de composants directement aux API qui nécessitaient auparavant une usine, comme le ViewContainerRef.createComponent, ou utilisez le createComponentFunction autonome.
  • ComponentFactoryResolver et ComponentFactory ne sont plus disponibles. Transmettez la classe de composant directement aux API qui nécessitaient auparavant une usine, tels que ViewContainerRef.createComponent, ou utilisez la fonction autonome createComponent.
  • stream Resource (qui inclut rxResource) résolvent désormais la valeur de manière synchrone si le flux/observable renvoie une valeur de manière synchrone. Cela peut interrompre certains tests qui supposaient une résolution asynchrone de la valeur.

formulaires

  • Les règles de validation min et max ne sont plus prises en charge valeurs de chaîne. Les valeurs liées doivent être des nombres ou null. ###http
  • Utilisez le HttpXhrBackend avec le provideHttpClient(withXhr) si vous souhaitez continuer à prendre en charge les rapports de progression du téléchargement.

navigateur de plateforme

  • Cela supprime les styles lorsqu'ils semblent ne plus être utilisés par un host associé. Cependant, d'autres DOM sur la page peuvent toujours être affectés par ces styles s'ils n'utilisent pas ViewEncapsulation.Emulated ou si ces styles sont utilisés par des éléments en dehors d'Angular, ce qui peut faire apparaître d'autres DOM sans style.
  • L'intégration Hammer.js a été supprimée. Utilisez votre propre implémentation.

routeur

  • Le type de retour pour TitleStrategy.getResolvedTitleForRoute était auparavant « any », alors que le type de retour réel ne pouvait être que string ou undefined. Le type de retour reflète désormais correctement les valeurs possibles. Le code qui lit la valeur devra peut-être être ajusté. (cerise choisie dans le commit ad37f52c1212164c51ffcc533067af05c2c33c89)
  • Le paramètre currentSnapshot dans CanMatchFn et la méthode canMatch de l'interface CanMatch sont désormais obligatoires. Alors que c'était déjà le comportement du routeur au moment de l'exécution, les implémentations de classe existantes de CanMatch doivent désormais inclure le troisième argument pour satisfaire l'interface.
  • paramsInheritanceStrategy est désormais défini par défaut sur "toujours" La valeur par défaut de paramsInheritanceStrategy a été modifiée de « emptyOnly » à « always ». Cela signifie que les paramètres de route sont hérités par défaut de toutes les routes parents. Pour restaurer le comportement précédent, définissez paramsInheritanceStrategy sur « emptyOnly » dans la configuration de votre routeur.
  • provideRoutes() a été supprimé. Utilisez provideRouter() ou ROUTES comme jeton multiple si nécessaire.

mise à niveau

  • Les getAngularLib/setAngularLib obsolètes ont été supprimés, utilisez plutôt getAngularJSGlobal/setAngularJSGlobal.

Dépréciations

###http

  • withFetch est désormais obsolète, il peut être supprimé en toute sécurité.
  • L'option reportProgress est obsolète, veuillez utiliser reportUploadProgress & reportDownloadProgress à la place.

Highlights

  • OnPush becomes the default change-detection strategy — @Component now defaults to ChangeDetectionStrategy.OnPush (eae8f7e30b), so views are no longer re-checked on every async event unless explicitly marked dirty. Big perf win, but a genuine behavior change for anything that relied on default CD updating "for free." A companion migration (cb4cb77053) injects ChangeDetectionStrategy.Eager where legacy semantics are needed — run it and audit components that depended on implicit checks before upgrading.
  • Toolchain floor moves, and a quiet HTTP backend switch — TypeScript 5.9 support is dropped (8fe025f514) while Node.js 26 is added (b8d3f36ed9). More subtly, the new provideHttpClient → HttpXhrBackend migration (3bc095d508) exists because the default backend changed (to fetch); if you rely on XHR-specific behavior, run that schematic to pin the old implementation or expect different request semantics.
  • Full AI / WebMcp tooling surface lands — provideWebMcpTools and the experimental declareWebMcpTool (3b0ae5fef0, ef1810197b), plus registered runtime debugging tools and an in-page DI graph explorer (8ce9cc4f6b, 75f2cb8f56). This is Angular positioning app internals to be machine-readable by AI agents — powerful, but largely experimental: pin versions and expect API churn.
  • Signals and @defer mature, with new build-time guards — debounced signals (b918beda32), synchronous values for stream resources (4e331062e8), SSR resource caching (5a7c1e62dc), and an rxResource subscription-leak fix (b20f0fe078) round out reactive state; @defer gains configurable idle behavior and optional timeouts (a5981b83a6, 98eb24cea0). Watch for new diagnostics that may surface in CI: NG8023 for duplicate selectors (ca67828ee2) and a warning for prefetch without a main trigger (7f9450219f).
  • Shadow DOM breaks alongside a security-hardening cluster — dedicated legacy shadow DOM selectors (194f723f66) and deprecated shadow-CSS encapsulation polyfills (4c25a42e98) are removed (breaking if you rely on them), offset by new bootstrapping under shadow roots (cdda51a3b2). Treat the #68868 fixes as security-relevant: dynamic href/xlink:href on SVG <a> is now sanitized and tag names are normalized across compiler, runtime, and i18n, so audit custom-namespace templates.
  • Testing and DI APIs reshuffle — @Service is now stable (8f3d0b9d97, 7aad302c3e), injectAsync debuts (444b024d49), and ApplicationRef can bootstrap with config (a0aa8304cd). Plan for two testing changes: TestBed.getFixture is renamed to getLastFixture (dc3131c639), and Testability stability now keys off PendingTasks (9f479ae964), which can shift async test timing and flakiness.

Breaking Changes

compiler

  • This change will trigger the nullishCoalescingNotNullable and optionalChainNotNullable diagnostics on exisiting projects. You might want to disable those 2 diagnotiscs in your tsconfig temporarily.
  • data prefixed attribute no-longer bind inputs nor outputs.
  • The compiler will throw when there a when inputs, outputs or model are binding to the same input/outputs.
  • in variables will throw in template expressions.

compiler-cli

  • Elements with multiple matching selectors will now throw at compile time.

core

  • The second arguement of appRef.bootstrap does not accept any anymore. Make sure the element you pass is not nullable.
    • TypeScript versions older than 6.0 are no longer supported.
  • Leave animations are no longer limited to the element being removed.
  • Component with undefined changeDetection property are now OnPush by default. Specify changeDetection: ChangeDetectionStrategy.Eager to keep the previous behavior.
  • change AnimationCallbackEvent.animationComplete signature
  • ChangeDetectorRef.checkNoChanges was removed. In tests use fixture.detectChanges() instead.
  • createNgModuleRef was removed, use createNgModule instead
  • ComponentFactoryResolver and ComponentFactory are no longer available. Pass the component class directly to APIs that previously required a factory, such as ViewContainerRef.createComponent or use the standalone createComponentFunction.
  • ComponentFactoryResolver and ComponentFactory are no longer available. Pass the component class directly to APIs that previously required a factory, such as ViewContainerRef.createComponent or use the standalone createComponent function.
  • stream Resource (which includes rxResource) are now resolving the value synchronously if the stream/observable returns a value sychronously. This can break some tests that assumed an asynchronous resolution of the value.

forms

  • min and max validation rules no longer support string values. Bound values must be numbers or null.

http

  • Use the HttpXhrBackend with provideHttpClient(withXhr) if you want to keep supporting upload progress reports.

platform-browser

  • This removes styles when they appear to no longer be used by an associated host. However other DOM on the page may still be affected by those styles if not leveraging ViewEncapsulation.Emulated or if those styles are used by elements outside of Angular, potentially causing other DOM to appear unstyled.
  • Hammer.js integration has been removed. Use your own implementation.

router

  • The return type for TitleStrategy.getResolvedTitleForRoute was previously 'any' while the actual return type could only be either string or undefined. The return type now reflects the possible values correctly. Code that reads the value may need to be adjusted.

    (cherry picked from commit ad37f52c1212164c51ffcc533067af05c2c33c89)

  • The currentSnapshot parameter in CanMatchFn and the canMatch method of the CanMatch interface is now required. While this was already the behavior of the Router at runtime, existing class implementations of CanMatch must now include the third argument to satisfy the interface.

  • paramsInheritanceStrategy now defaults to 'always'

    The default value of paramsInheritanceStrategy has been changed from 'emptyOnly' to 'always'. This means that route parameters are inherited from all parent routes by default. To restore the previous behavior, set paramsInheritanceStrategy to 'emptyOnly' in your router configuration.

  • provideRoutes() has been removed. Use provideRouter() or ROUTES as multi token if necessary.

upgrade

  • Deprecated getAngularLib/setAngularLib have been removed use getAngularJSGlobal/setAngularJSGlobal instead.

Deprecations

http

  • withFetch is now deprecated, it can be safely removed.
  • The reportProgress option is deprecated please use reportUploadProgress & reportDownloadProgress instead.
