angular v22.1.0

Highlights

  • App-scoped CSS variables — The compiler now namespaces CSS variables to the application, including variables used in component properties. This reduces collisions between independently built libraries and global styles, but review integrations that depend on exact CSS variable names (#68846).

  • Foreign-component interoperability — foreignImports now supports import aliases, and Angular components accept uninvoked signals directly as foreign-component props. Additional fixes cover foreign scopes and control-flow blocks, plus disposal of Angular views inside foreign @content, making mixed-framework rendering more reliable (#68674, #69558, #69674).

  • Writable linkedSignal behavior — A custom set option lets developers define explicit write behavior while retaining linkedSignal’s source-driven reset semantics, enabling richer editable-state patterns without replacing the signal abstraction.

  • Explicit HTTP caching controls — New options allow caching credentialed and normally non-cacheable requests. Meanwhile, transfer caching now skips credentialed and uncacheable traffic by default (#69017). Treat credentialed caching as an explicit security and invalidation decision; this release also enables XSRF protection for root-provided HttpClient instances.

  • Stronger editor diagnostics — The language service now typechecks non-exported standalone classes and templates requiring inline typecheck blocks, and accounts for strictTemplates being enabled by default (#68454). Expect editor findings to align more closely with compilation.

  • Deprecations and migration support — HttpClient.jsonp, HttpClientJsonpModule, and related JSONP APIs are deprecated; migrate consumers to standard HTTP requests. Angular also adds an injectable-to-service migration and fixes control-flow migration handling around then/else, so review migration output before committing.

No breaking changes.
