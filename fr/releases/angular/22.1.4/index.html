angular v22.1.4

Highlights

  • Prototype-pollution hardening — A coordinated set of fixes in common and core (60a874c3fb, 3da35cbab9, 7c752d4815) closes off lookup tables and TransferState merges that could collide with Object.prototype members (constructor, __proto__, toString). This is the most consequential change for SSR apps: serialized state can no longer shadow prototype members during hydration, improving both correctness and security posture. No API change, but worth auditing any custom keys you write into TransferState that happen to use those names — they previously "worked" by accident.

  • Actionable hydration errors — 7546b7a805 replaces hard crashes with coded RuntimeErrors when hydration/rendering can't locate an expected DOM node. Mismatch debugging improves substantially: instead of an opaque stack trace you get a stable error code you can look up. Watch for these appearing in logs after upgrade — DOM drift that was previously silent may now be reported, so treat new hydration errors as a signal to check server/client markup parity.

  • Template type-checking and diagnostics — Three compiler-cli fixes: correct type-check-block expressions for optional chaining (079a846263), diagnostic "related message" source files now point at the .html template instead of generated .ts (afe8499a14), and metadata is retained for strict standalone errors (55eeb46418). Thenet effect is fewer false positives and error locations you can actually navigate to, which matters most to projects running strictTemplates or strict standalone mode.

  • Safer upgrade paths for i18n apps — The standalone bootstrap migration no longer drops registerLocaleData calls (85c8829ac1), so non-English apps can migrate without silently losing locale registration — a failure that only surfaced later at runtime in date/number pipes. Paired with platform-server no longer stripping unicode whitespace during URL resolution (71e52d1396), this patch makes the upgrade path materially safer for localized and SSR applications.

  • Locale-aware NaN formatting — e8378dfeab makes number formatting emit the locale's NaN symbol rather than a hardcoded one. Small but observable behavioral change: snapshot tests or assertions that expect the literal string NaN in non-en locales may need updating.

  • JIT, dynamic components, and tooling polish — b199bdfa2a explicitly rejects foreign components in JIT mode and 9a8e4826b9 preserves namespaces for dynamic component hosts, tightening correctness around component identity; 05c7c725a5 scopes animations declared in minified nested rules so animation scoping survives minification. Rounding out the release, the language service now honors quote-style preferences for generated imports (93d7f718d2) and forms uses dot-access for readonly rule configuration (c8eb7f0056) — ergonomics fixes rather than behavior changes.

No breaking changes.
