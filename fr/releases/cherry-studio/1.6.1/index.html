cherry-studio v1.6.1

Highlights

  • AI SDK runtime and native provider tools — AI SDK is now packaged behind a plugin-based request and MCP layer (#7404), with provider options, built-in tools, Google URL context, and revised citation handling (#10068). Custom integrations should move off the old middleware hooks; built-in web search is also suppressed when an external search provider is configured, avoiding duplicate searches and charges (#9995).
  • Local API server — An optional Express server exposes OpenAI-compatible /v1/chat/completions and /v1/models endpoints, MCP routes, and OpenAPI documentation. It defaults to localhost:23333 with API-key/Bearer authentication (#9855), letting scripts and other clients reuse configured providers; keep it disabled or tightly authenticated because it fronts local model credentials.
  • Anthropic OAuth and reasoning budgets — Anthropic settings now support PKCE OAuth, authorization-code entry, and login/logout as an alternative to API keys (#8905). Thinking requests subtract the reasoning budget from maxTokens before invoking the AI SDK, preventing the combined values from exceeding model limits (#9991).
  • Unified knowledge base and native document uploads — Large-file handling adopts the OpenAI Files API, with native uploads for Qwen qwen-long and qwen-doc models (#9997). The FAISS/LangChain backend is removed in favor of EmbedJS/libSQL (#10178); persisted-state migrations drop the old framework selector (#10148, #10178), so custom state readers need updating and affected FAISS/LangChain indexes should be rebuilt.
  • More reliable MCP tool execution — Logging, error propagation, and header handling are hardened (#9878, #10100), while progress events now include callId and tool-call state management is refactored (#9946, #10028). This improves correlation for long-running or concurrent tools; integrations parsing progress payloads should key on callId.
  • Zod 4 and contributor tooling migration — Validation schemas move to Zod 4 (#10002), styling shifts toward HeroUI/Tailwind (#9973), and formatting, linting, and type-checking adopt Biome, Oxlint, and tsgo (#10170, #10168, #10188). Fork and plugin authors should expect schema API and UI-component changes and update their local scripts accordingly.
