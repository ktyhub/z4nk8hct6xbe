#xerj v1.0.0-rc.101

[1.0.0-rc.101] - 2026-11-05

rc.101 : XERJ-Query — le moteur répond aux faits et aux questions de comptage d'un modèle qui fonctionne sur CPU, désactivé par défaut. Cette version est livrée avec XERJ-Query compilé dans le binaire et le sert via /_facts sur un nœud démarré avec --facts-model-dir <DIR> : écrivez des faits dans un espace de noms, demandez un langage naturel question, et lisez une réponse vérifiée avec ses preuves citées et la réponse exacte programme qui l’a produit. Les questions de comptage (« combien de… sur… ? ») reçoivent une réponse par un exécuteur testamentaire exact, servi uniquement lorsque deux modèles indépendants s'accordent sur le programme. Le modèle est livré en tant qu'élément de version distinct, un élément échangeable Répertoire xerj-model-bundle-v1 (poids FP16, servi sur CPU avec un int8-guard encodage des mêmes poids — pas de GPU, rien ne sort de la machine). Sur l'honnête XERJ Score v2 (crédit mesuré par rapport à l'Opus 5.5 = 100 sur les faits + comptage évaluation), le bundle expédié, candidate_a_s47, obtient 90.29 sur le évaluation standard – pas l'ensemble frais/scellé ; robustesse aux nouvelles formulations et Le comptage des nouvelles prises n'est pas mesuré séparément pour cet ensemble. Le moteur sert le bundle évalué exactement : une reproduction octet par octet de ses réponses à travers les 2 387 éléments d’évaluation. Sans le drapeau un nœud est le nœud rc.100 était : non Itinéraire /_facts, pas de chargement de modèle, la même liste d'outils MCP.

Installations packagées ont leur propre provenance et les noms d'orientation MCP XERJ_AUTH. Découverte les remplacements de priorité et d’informations d’identification explicites restent inchangés.

  • xerj autoindex échoue lors d'une exécution lorsqu'un index d'ensemble de données ne contient aucun document bien que le journal indique que des documents y ont été écrits, même lorsque les autres les ensembles de données sont en direct (#2407, défaut 2). Le chèque résumait les documents en direct sur chaque ensemble de données, donc un index -json rempli permet une réexécution d'impression ok : indexé et index consultable over an empty `-docs. L'erreur nomme chacun vide index et ses fichiers contributifs ; les totaux d'enregistrement ne sont déclarés que lorsque ces fichiers ciblent uniquement cet ensemble de données. Le nombre inconnu de frères et sœurs ne se cache pas données manquantes confirmées de manière indépendante.

  • L'extraction de source SQL ne découpe plus les têtes d'instructions dans un UTF-8 caractère, donc les têtes de déclarations/commentaires CJK non reconnues ne paniquent pas (# 2547).

  • Les fichiers Markdown courts avec le frontmatter YAML conservent leur corps de prose même lorsque les puces ou les lignes Key: value sont également analysées comme YAML (#2447). Existant le comportement du titre frontal et la détection structurée du corps CSV/JSON demeurent.

  • Les fichiers vides conservent des identités d'inventaire distinctes au lieu d'être signalés en tant que doublons de contenu de chemins non liés (#2449). Octet non vide identique les fichiers sont toujours dédupliqués.

  • Une recherche avec à la fois query et un knn de niveau supérieur renvoie les hits size, pas k (#2561). La page a été élargie à k, donc size: 5, k: 20 est revenu 20 coups sûrs. k définit toujours le nombre de voisins les plus proches qui rejoignent le candidat défini et la page from/size via l'union, comme dans Elasticsearch.

  • La suppression d'index n'attend plus les statistiques d'index sans rapport pendant résoudre ses sélecteurs. Les listes d'index et les contrôles de santé sont également publiés leur carte d'index se verrouille avant d'attendre les statistiques, donc un schéma bloqué la mise à jour ne maintient pas ces verrous contre DELETE (partie de #2405 ; extrait à partir du #2489). L'annulation de fusion/vidage et le plafond de mémoire de processus restent suivis séparés.

  • xerj autoindex compresse les étapes de phase B par fichier avec zstd niveau 1 et utilise des fichiers temporaires nettoyés par le système d'exploitation lorsque le client sorties (#2493, partie du #2427). Il termine la compression tamponnée avant supprimer les enregistrements précédents, donc une erreur de finalisation d'étape préserve l'ancien des dossiers et un curriculum vitae ordinaire peuvent compléter le remplacement. Compression les économies dépendent des données ; cela n’impose pas de limite de mémoire disque ou serveur.

  • La patience de la contre-pression en vrac du autoindex est désormais mesurée depuis le dernier progrès, pas depuis le premier tour. Une fenêtre que le serveur draine quelques-uns enregistrements à la fois (par article 429 resource_exhausted sur une intégration date limite ou refus d'admission) utilisé pour avorter avec bulk backend failed une fois les tours passés ensemble, le 600 s THROTTLE_PATIENCE, même si chaque tour a établi des records. Chaque tour qui règle au moins un élément maintenant redémarre l'horloge de patience et l'interruption ; des rounds qui ne règlent rien ça compte toujours, donc un serveur qui répond à 429 échoue toujours aux mêmes limites comme avant.

  • xerj autoindex titre un fichier prose qui s'ouvre avec le frontmatter YAML de sa touche title:, ou à partir de la première ligne après la fermeture --- lorsqu'il y a n'est aucun (#2556). Chacun de ces fichiers (Jekyll, Hugo, Obsidian) était autrefois intitulé ---, sa clôture d'ouverture. Un bloc --- principal qui n'est pas analysable frontmatter (non fermé, pas un mappage YAML, plus de 64 Ko) prend la première ligne ce n'est pas un simple --- ; le corps, le texte initial et start_line sont inchangés. Un fichier inchangé n'est pas réextrait, donc réindexez avec xerj autoindex --fresh pour retitrer des documents déjà dans un index.

  • Une réindexation --no-graph dont les options diffèrent de la génération engagée (par exemple --sample ou --follow-symlinks) est refusé avant tout est copié et l'erreur nomme l'option. Il permettait de copier et de préparer le dossier entier, puis signalez "Impossible de dériver la génération N ; le durable l'état de la génération n'est pas cohérent en interne", bien que l'état ait été intact et les options d'origine mettaient toujours à jour le corpus (#2577).

  • xerj autoindex --no-graph --dry-run refuse désormais une option modifiée c'est ce que fait l'exécution réelle, en nommant l'option, au lieu d'imprimer un plan et de quitter 0 pour une exécution qui serait alors refusée. La note du --max-minutes à ce sujet itinéraire recommande --dry-run comme moyen de vérifier d'abord un plan (#2684).

  • xerj search et xerj def sans hits sur un préfixe dont l'autoindexation les indices existent mais dont la première exécution n'est pas terminée maintenant, dites-le : recherchez à nouveau une fois l'exécution terminée, ou réexécutez la même commande si elle s'est arrêtée. Ils avaient l'habitude de affiche les autres index du nœud et "le catalogue ne répertorie aucun préfixe ; --prefix est le nom de l'index avant le slug de l'ensemble de données", qui se lit comme un mauvais --prefix (#2670).

  • xerj autoindex lit une feuille de calcul sans ligne d'en-tête et sans texte, comme une exportation de tous les nombres, sous forme de tableau : un enregistrement par ligne, des colonnes nommées col_A, col_B et ainsi de suite, les valeurs conservent leurs types de cellules. Il utilisé pour indexer une telle feuille comme un seul document texte, dont la casquette de 4 096 sections coupé : dans la reproduction #2720, une feuille de 200 000 lignes gardait des lignes jusqu'à 72 724. Une feuille dont les 20 premières lignes contiennent une cellule de texte, des lignes inégales, une colonne ou une seule ligne est encore indexée en tant que document (#2720).

  • Une réexécution de --no-graph n'est plus abandonnée lorsqu'un fichier gagne une partie du commit la génération n'a pas d'ensemble de données pour, par exemple, une feuille de calcul nouvelle ou renommée feuille, ou une feuille qui gagne une ligne d'en-tête et se déplace du document lecture à la table lecture. Le fichier est mis de côté avec un message de reconstruction (sortie 3) et tous les autres fichiers sont toujours indexés. Avant, ça arrêtait tout exécuté avec "l'affectation gelée a 0 correspondance pour le groupe" (#2720).

  • xerj autoindex indexe les partiels HTML et les fichiers modèles au lieu de les classant comme du XML mal formé. Un fichier qui s'ouvre avec un balisage et qui contient les balises de fermeture étaient lues au format XML, donc un dossier de 16 fichiers ou plus de ce type devenait un Ensemble de données XML et chaque fichier a été supprimé lors de son premier <%, && ou non fermé balise, avec le texte après ce point perdu. .html et .htm sont désormais lus comme HTML et .hbs, .handlebars, .mustache, .ejs, .erb, .jsp, .aspx, .cshtml, .razor, .twig, .jinja, .jinja2, .j2, .njk, .liquid, .astro, .marko et .riot sous forme de texte, également lorsqu'ils sont compressés. Réel XML, y compris .xml, .xaml et .svg, est inchangé. Un index construit avant ce correctif, il conserve ses fichiers indésirables jusqu'à ce que chacun change ou que le dossier est à nouveau indexé avec --fresh (#2740).

  • Lorsque le serveur refuse un enregistrement ou un bord de graphique, xerj autoindex désormais nomme le fichier d'où il provient et ne marque pas ce fichier comme terminé. Il avait l'habitude de marquez chaque fichier dans le même volume, de sorte que la réexécution du message d'abandon demande pour avoir repris le dossier, signalé le succès et n'a jamais envoyé le refus enregistrement (#2807).

  • Un fichier dont le serveur refuse l'enregistrement au-delà de ses 8 Mo par document la limite est désormais mise de côté comme indésirable, avec son nom de fichier et la raison du serveur, et l'exécution se termine avec la sortie 3. Ses autres enregistrements sont supprimés et il est réessayé lors de la prochaine exécution. Il avait l'habitude d'abandonner toute l'exécution, chaque réexécution, jusqu'à ce que --fresh. Sur un champ semantic_text, les vecteurs ajoutés par le serveur comptent vers cette limite : un fichier .d.ts généré de 2 Mo est ainsi devenu 16.6 Mo. --no-semantic peut indexer un tel fichier (#2807).

  • xerj corpus index et xerj autoindex --no-graph nomment désormais le fichier a l'enregistrement refusé vient, et pour un refus de taille, ils disent comment indexer le reste : sous un nouveau --prefix et --state-dir, avec le fichier laissé de côté (--exclude) ou avec --no-semantic. Cette route corrige sa liste de fichiers avant il envoie n'importe quoi, il ne peut donc pas mettre de côté un fichier refusé. On disait seul "le vrac préparé contenait 1 articles rejetés" (#2807).

  • xerj corpus index et xerj autoindex --no-graph dimensionnent désormais chaque enregistrement avec les vecteurs que le serveur ajoutera, avant de corriger la liste de fichiers, et mettre de côté un dossier qui ne pourrait pas être considéré comme un dossier indésirable. La course se termine avec la sortie 3, les autres enregistrements du fichier sont indexés et les réexécutions sont également terminées. Le fichier .d.ts généré de 2 Mo à partir du numéro 2807 ne perd que l'intégralité de son enregistrement ; ses enregistrements de type sont toujours indexés. Cette route s'arrêtait sur le serveur refus, et chaque rediffusion s'arrêtait sur le même disque. Une course qui s'est déroulée plus tôt la version déjà arrêtée de cette façon relit la liste qu'elle a corrigée et s'arrête à nouveau ; indexez ce dossier sous un nouveau --prefix et --state-dir (#2807).

xerj v1.0.0-rc.101

[1.0.0-rc.101] - 2026-11-05

rc.101: XERJ-Query — the engine answers facts and counting questions from a model that runs on CPU, off by default. This release ships XERJ-Query compiled into the binary and serves it over /_facts on a node started with --facts-model-dir <DIR>: write facts to a namespace, ask a natural-language question, and read a verified answer with its cited evidence and the exact program that produced it. Counting questions ("how many … over …?") are answered by an exact executor, served only when two independently-seeded models agree on the program. The model ships as a separate release asset, a swappable xerj-model-bundle-v1 directory (FP16 weights, served on CPU with an int8-guard encoding of the same weights — no GPU, nothing leaves the machine). On the honest XERJ Score v2 (credit measured against Opus 5.5 = 100 on the facts + counting evaluation) the shipped bundle, candidate_a_s47, scores 90.29 on the standard eval — not the fresh/sealed set; robustness to new wordings and fresh-set counting are not separately measured for this bundle. The engine serves the evaluated bundle exactly: a byte-for-byte reproduction of its answers across all 2,387 evaluation items. Without the flag a node is the node rc.100 was: no /_facts route, no model load, the same MCP tool list.

Upgrade notes — read before starting rc.101 on an existing data directory

  • ONE-WAY DATA-DIRECTORY UPGRADE. rc.101 writes new segments as ZPS4 postings and stores text columns as row-dictionary blocks by default. The first flush moves the data directory to on-disk format 4; rc.100 and every earlier build read only format 3 and refuse such a directory at open ("written by a newer xerj"). A data directory that rc.101 has written to cannot be opened by rc.100 again — take a backup or snapshot before the first start if you may need to roll back. To keep writing format 3 postings, set XERJ_FTS_POST_CODEC=packed before the first rc.101 start (and XERJ_STORED_ROW_BLOCKS=0 to keep the old stored-text layout); the opt-in positions-off text fields (index_options: docs|freqs) move the directory to format 5. These defaults will be on public main before rc.102, so a later public release opens rc.101 directories.
  • Provenance. The rc.101 binaries are built from a private tree: public main at 3f6aefa8 plus the XERJ-Query engine lanes (storage, ingest, facts wiring) plus the model crates xerj-infer, xerj-serve and xerj-exec, which are licensed Proprietary and ship as binary + model bundle only. Those three crates are not Apache-2.0 and are not in the public repository; the Apache-2.0 LICENSE covers the engine source on main. The engine lanes (non-proprietary) land on public main by pull request before rc.102.
  • XERJ-Query is opt-in. Nothing changes for a node started as before. The flag is --facts-model-dir <DIR>; see the first entry under Added.

Added

  • XERJ-Query is opt-in. It ships compiled in and stays off until the server is started with --facts-model-dir <DIR> (or XERJ_FACTS_MODEL_DIR; the flag wins). Off, a node behaves as rc.100 did: every /_facts path answers 404 xerj_query_not_enabled naming the flag, no model loads and no facts thread starts, the MCP tool list has no xerj_facts_ask (the published schema is that default list), and memory namespaces and brains ending in -facts are ordinary names again. On, everything below applies; xerj mcp lists xerj_facts_ask when the node it proxies answers GET /_facts (XERJ_MCP_FACTS=on|off decides instead).

  • Facts in the default build: /_facts, the xerj_facts_ask MCP tool, and _ask with decline_v2 as the default rule (verify: served remains). Read final_status and final_answer: under decline_v2 the plain status and answer are the unchecked program's. Every _ask response now carries a path field, facts or counting, and a counting answer reports its program_sha256 and whether the partner model agreed. The /_facts status no longer carries a "spike": true flag and reports the node's counting state. Without a model directory XERJ-Query is off (see the entry above).

  • Exact counting answers in the default build. When the node is started with a model bundle that carries a counting role (see "Model bundles" below), a counting question is answered by an exact executor — the RC4 counting path (stack v6) in xerj-infer and xerj_serve::counting — and served only when the question routed to counting, its hard checks passed, and a partner model produced the same program; otherwise the fact path answers under decline_v2. The xerj ask CLI gains the matching count operation. COUNTING_OFF now applies only when the bundle has no counting role, or its counting model is absent or fails its load checks; in that case facts keeps serving and only counting questions decline. Known limitations of counting on rc.101 (measured on user-written facts): counting engages only when every fact of the counted subjects carries a stable subject_id (one per subject, on every fact about it); without it the count is INCOMPLETE and the answer is UNKNOWN with path: "facts". The op-set is set counts ("how many X have Y", optionally "distinct <field>"); sums, totals and numeric thresholds decline. A served count tallies the members of the matched set and does not check the noun of the question: "How many devices do the Berlin offices have in total?" over office = Berlin facts with no devices relation is served as a verified count of people (path: "counting", partner_agreement: true, the same program_sha256 as "how many people have office Berlin"). Counting answers carry no evidence ids by design, and the response names the program only by program_sha256. Ask for the member type you mean and read a count as a member count.

  • Model bundles. --facts-model-dir (or XERJ_FACTS_MODEL_DIR) may point at a bundle directory (bundle.json, schema xerj-model-bundle-v1) that holds a facts role and optional counting/served and counting/partner roles, each a directory with its own manifest.json and weights. A directory with no bundle.json stays a plain facts export, as before. Replacing a single role is a directory rename while the node is stopped, with no change to bundle.json or code; load checks refuse a role whose weights or tokenizer hash does not match its manifest, a served/partner pair that disagree, or an unknown rule name. Serving precision is per role in bundle.json (XERJ_FACTS_PRECISION still overrides facts); weights may be stored F32 or F16 and both widen to f32 at load, so no serving path depends on how a model was trained. See docs/MODEL_BUNDLE.md.

  • A file whose record the server refuses as over its 8 MiB per-document limit is now set aside as junk, with its file name and the server's reason, and the run completes with exit 3. Its other records are removed and it is retried on the next run. It used to abort the whole run, every rerun, until --fresh. On a semantic_text field the vectors the server adds count toward that limit: a 2 MB generated .d.ts file grew to 16.6 MB this way. --no-semantic may index such a file (#2807).

  • xerj corpus index and xerj autoindex --no-graph now name the file a refused record came from, and for a size refusal they say how to index the rest: under a new --prefix and --state-dir, with the file left out (--exclude) or with --no-semantic. That route fixes its file list before it sends anything, so it cannot set a refused file aside. It used to say only "prepared bulk contained 1 rejected items" (#2807).

  • xerj corpus index and xerj autoindex --no-graph now size each record with the vectors the server will add, before they fix the file list, and set aside a record that would not fit as a junk record. The run completes with exit 3, the file's other records are indexed, and reruns complete too. The 2 MB generated .d.ts file from #2807 loses only its whole-file record; its type records are still indexed. That route used to stop on the server's refusal, and every rerun stopped on the same record. A run that an earlier version already stopped this way replays the list it fixed and stops again; index that folder under a new --prefix and --state-dir (#2807).

Assets and provenance

Binaries for 8 targets plus the XERJ Query-1 model bundle:

  • xerj-1.0.0-rc.101-<target>.tar.gz / .zip (+ .sha256), .deb for the two linux-gnu targets.
  • xerj-model-bundle-v1-v1.0.0-rc.101.tar.gz (+ .sha256): the XERJ Query-1 bundle (candidate_a_s47, FP16, served as int8 on CPU). Enable with xerj --facts-model-dir <DIR>; without the flag the node is rc.100. Install both in one step: curl -fsSL https://xerj.org/get | sh -s -- --with-model.

Provenance: this release's binaries were built from a private tree (public main at 3f6aefa8 + the XERJ-R storage/ingest/facts lanes + the proprietary model crates xerj-infer/xerj-serve/xerj-exec, which ship as binary + bundle only and are not in this repository). The six x86_64/macOS/Windows assets were cross-built by the release workflow; the two aarch64 Linux assets were built natively on an aarch64 host from the same tag after GitHub's ARM cross-build runners were shut down mid-job twice. Every asset carries its SHA-256.

Known limitations (measured): counting engages only on facts that carry subject_id and covers set counts, not sums; a count tallies the matched set and does not check the noun of the question (a quantity question about a relation the store lacks can be served as a member count); the model over-declines (383 of 1,600 standard-eval items). Details: docs/FACTS_API.md, docs/XERJ_QUERY_1.md.

Known issue (opt-in storage option): with source_ref enabled, a search that reads text from an edited source file can return the old text instead of the "file changed" error when the edit keeps the file size the same (intermittent, 2 of 3 isolated runs). The default layout stores text in the index and is not affected. Tracked for rc.102.
