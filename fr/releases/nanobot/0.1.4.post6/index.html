nanobot v0.1.4.post6

🐈 Le nanobot v0.1.4.post6 est là : 57 PR fusionnés, 27 nouveaux contributeurs et une version qui consiste moins à ajouter de la surface qu'à repenser ce qu'il y a en dessous. Certaines versions concernent ce que vous pouvez faire. Celui-ci concerne la propreté avec laquelle vous pouvez le faire. Le runtime de l'agent a été formellement décomposé, une dépendance majeure a été supprimée, le streaming s'est déroulé de bout en bout et une vulnérabilité de sécurité a été corrigée. Au-delà du travail sur les fonctionnalités, v0.1.4.post6 est un tournant structurel – le genre de version qui rend la prochaine version possible.

Faits saillants

  • Le runtime de l'agent a été décomposé en morceaux composables — Un AgentRunner partagé a été extrait, les hooks de cycle de vie ont été unifiés en un HookContext formel et la progression du sous-agent est désormais préservée même en cas d'échec. Le routage des commandes a été refactorisé dans une structure conviviale pour les plugins, et process_direct a été unifié pour renvoyer OutboundMessage de manière cohérente. Il ne s’agit pas seulement d’un nettoyage : c’est la base des comportements d’agents enfichables, des stratégies d’exécution personnalisées et des intégrations de cycle de vie tierces à venir. (#2524, #2541, #2388, #2338)
  • litellm a été remplacé par des SDK natifs OpenAI + Anthropic — L'ensemble de la couche fournisseur a été réécrit pour communiquer directement avec les SDK en amont au lieu de passer par litellm. L'optimisation rapide du cache pour Anthropic, la gestion appropriée de max_completion_tokens pour OpenAI o1 et la préservation de la signature Gemini ont tous été de la partie. Si vous avez déjà débogué un traçage Litelm à 2 heures du matin, vous comprenez pourquoi c'est important. (#2448, #1109, #2468, #2550, #2453)
  • Le streaming est passé de bout en bout — Du fournisseur au canal jusqu'au CLI, la sortie du streaming s'effectue désormais comme un chemin de première classe. Feishu a obtenu la prise en charge du streaming CardKit, les deltas de flux en file d'attente sont fusionnés pour réduire les appels API et le gestionnaire de canaux gère correctement les limites de flux. C'est la différence entre "le robot tape..." et le regarder réfléchir. (#2365, #2545, #2497)
  • Une vulnérabilité de sécurité a été corrigée — L'injection d'e-mails et l'usurpation d'identité via une vérification d'authentification manquante ont été corrigées. Les e-mails entrants vérifient désormais SPF/DKIM via les en-têtes Authentication-Results, avec verify_dkim et verify_spf activés par défaut. Le contenu des e-mails est balisé avec [EMAIL-CONTEXT] pour empêcher l’injection d’invites LLM à partir du corps des e-mails. Voir l'avis pour plus de détails. (GHSA-4gmr-2vc8-7qh3)
  • La prise en charge de WeChat est désormais une chaîne complète — WeChat (Weixin) a rejoint la famille de chaînes avec une interrogation longue HTTP, une connexion par code QR et une compatibilité avec le plugin 1.0.3. Parallèlement, Telegram, QQ, WhatsApp et Feishu ont tous reçu des améliorations multicanaux, notamment des mécanismes de nouvelle tentative avec une interruption exponentielle. (#2412, #2428, #2386, #2478)
  • La couverture des fournisseurs n'a cessé de s'étendre — Les fournisseurs Mistral et OVMS sont arrivés, Step Fun (阶跃星辰) a rejoint l'écosystème et les rapports d'erreurs personnalisés des fournisseurs sont devenus beaucoup plus honnêtes — des erreurs brutes API au lieu de JSONDecodeError opaques. nanobot continue de rencontrer les utilisateurs partout où se trouvent leurs modèles. (#2199, #2472, #2289, #2139)
  • L'agent est devenu plus intelligent en matière de ressources — La répartition simultanée par session a été effectuée, des capacités sensorielles multimodales natives ont été ajoutées, l'estimation des jetons compte désormais tous les champs de message et la consolidation de la mémoire réserve correctement la marge d'achèvement. La boucle d'agent gère également CancelledError avec élégance et enregistre les résultats des sous-agents avec les rôles corrects. (#2393, #2304, #2344, #2378, #2239, #2104)
  • Feishu et Telegram ont tous deux progressé — Feishu a obtenu des cartes de streaming, l'analyse des blocs de code dans les messages postés et des correctifs pour le rendu des démarques et les types de médias. Telegram bénéficie d'une prise en charge des médias URL HTTP(S), de pools de connexions séparés pour éviter l'épuisement des pools et d'une journalisation des erreurs réseau plus silencieuse. Petit individuellement, substantiel ensemble. (#2545, #2246, #1814, #1755, #1793, #2247, #2272)
  • CLI et l'intégration sont devenus plus performants — Un assistant intégré complet est arrivé, --dir permet plusieurs instances, /status affiche les informations d'exécution, -h fonctionne partout et le fuseau horaire est désormais configurable. Le genre de peaufinage qui donne l’impression que l’expérience de première diffusion est intentionnelle. (#2101, #1763, #1985, #2123, #2477, #1136, #2266)
  • Infrastructure renforcée à tous les niveaux — Les processus zombies sont récoltés lors de l'expiration du délai d'attente du shell, les magasins de tâches cron sont étendus aux espaces de travail, les schémas d'outils MCP gèrent correctement les paramètres nullables, les versions Docker incluent openssh-client et la suite de tests a été réorganisée dans une structure plus propre. Le genre de travail qui empêche le rapport de bug que vous auriez autrement déposé le mois prochain. (#2362, #2204, #2230, #2287, #1911, #2427, #2367)

Communauté

Bienvenue chaleureusement à nos 27 nouveaux contributeurs dans cette version. v0.1.4.post6 est façonné par la conviction que le travail le plus important en open source n'est pas toujours le plus visible. Remplacer une dépendance principale, décomposer un runtime, combler une faille de sécurité : aucun de ces éléments ne donne lieu à des démos flashy, mais tous font de nanobot un projet sur lequel vous pouvez construire avec plus de confiance demain qu'hier. Merci à tous ceux qui ont contribué au code, aux correctifs, à la documentation et aux idées. Les fondations deviennent plus solides. nanobot v0.1.4.post6

🐈 nanobot v0.1.4.post6 is here — 57 PRs merged, 27 new contributors, and a release that's less about adding surface area than about rethinking what's underneath.

Some releases are about what you can do. This one is about how cleanly you can do it. The agent runtime got formally decomposed, a major dependency was removed, streaming went end-to-end, and a security vulnerability was closed. Beneath the feature work, v0.1.4.post6 is a structural turning point — the kind of release that makes the next release possible.

Highlights

  • The agent runtime was decomposed into composable pieces — A shared AgentRunner was extracted, lifecycle hooks were unified into a formal HookContext, and subagent progress is now preserved even on failure. Command routing was refactored into a plugin-friendly structure, and process_direct was unified to return OutboundMessage consistently. This isn't just cleanup — it's the foundation for pluggable agent behaviors, custom execution strategies, and third-party lifecycle integrations that are coming next. (#2524, #2541, #2388, #2338)

  • litellm was replaced with native OpenAI + Anthropic SDKs — The entire provider layer was rewritten to talk directly to upstream SDKs instead of routing through litellm. Prompt cache optimization for Anthropic, proper max_completion_tokens handling for OpenAI o1, and Gemini thought signature preservation all came along for the ride. If you've ever debugged a litellm traceback at 2am, you understand why this matters. (#2448, #1109, #2468, #2550, #2453)

  • Streaming went end-to-end — From provider to channel to CLI, streaming output now flows as a first-class path. Feishu gained CardKit streaming support, queued stream deltas are coalesced to reduce API calls, and the channel manager handles stream boundaries correctly. This is the difference between "the bot is typing..." and actually watching it think. (#2365, #2545, #2497)

  • A security vulnerability was patched — Email injection and spoofing via missing authentication verification has been fixed. Inbound emails now verify SPF/DKIM through Authentication-Results headers, with verify_dkim and verify_spf enabled by default. Email content is tagged with [EMAIL-CONTEXT] to prevent LLM prompt injection from email bodies. See the advisory for details. (GHSA-4gmr-2vc8-7qh3)

  • WeChat support landed as a full channel — WeChat (Weixin) joined the channel family with HTTP long-poll, QR code login, and plugin 1.0.3 compatibility. Alongside it, Telegram, QQ, WhatsApp, and Feishu all received cross-channel enhancements including retry mechanisms with exponential backoff. (#2412, #2428, #2386, #2478)

  • Provider coverage kept expanding — Mistral and OVMS providers arrived, Step Fun (阶跃星辰) joined the ecosystem, and custom provider error reporting got much more honest — raw API errors instead of opaque JSONDecodeError. nanobot continues to meet users wherever their models live. (#2199, #2472, #2289, #2139)

  • The agent got smarter about resources — Per-session concurrent dispatch landed, native multimodal sensory capabilities were added, token estimation now counts all message fields, and memory consolidation properly reserves completion headroom. The agent loop also handles CancelledError gracefully and records subagent results with correct roles. (#2393, #2304, #2344, #2378, #2239, #2104)

  • Feishu and Telegram both leveled up — Feishu gained streaming cards, code block parsing in post messages, and fixes for markdown rendering and media types. Telegram got HTTP(S) URL media support, separated connection pools to prevent pool exhaustion, and quieter network error logging. Small individually, substantial together. (#2545, #2246, #1814, #1755, #1793, #2247, #2272)

  • CLI and onboarding became more capable — A full-featured onboard wizard arrived, --dir enables multiple instances, /status shows runtime info, -h works everywhere, and timezone is now configurable. The kind of polish that makes first-run experience feel intentional. (#2101, #1763, #1985, #2123, #2477, #1136, #2266)

  • Infrastructure hardened across the board — Zombie processes are reaped on shell timeout, cron job stores are scoped to workspaces, MCP tool schemas handle nullable params correctly, Docker builds include openssh-client, and the test suite was reorganized into a cleaner structure. The kind of work that prevents the bug report you'd otherwise file next month. (#2362, #2204, #2230, #2287, #1911, #2427, #2367)

Community

A warm welcome to our 27 new contributors in this release.

v0.1.4.post6 is shaped by a belief that the most important work in open source isn't always the most visible. Replacing a core dependency, decomposing a runtime, closing a security hole — none of these make for flashy demos, but all of them make nanobot a project you can build on with more confidence tomorrow than yesterday. Thank you to everyone who contributed code, fixes, docs, and ideas. The foundation is getting stronger.
