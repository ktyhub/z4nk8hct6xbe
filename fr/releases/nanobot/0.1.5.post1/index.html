nanobot v0.1.5.post1

🐈 nanobot v0.1.5.post1 est là 🎉 — 80 PR fusionnés, 25 nouveaux contributeurs. L'agent a appris à se gérer lui-même. Si v0.1.5 visait à rendre le bâtiment habitable, v0.1.5.post1 vise à ce que le bâtiment apprenne à prendre soin de lui-même. L'agent compresse désormais son propre contexte avant qu'il ne devienne trop long, injecte des messages de suivi à mi-parcours au lieu de vous faire attendre, découvre des compétences réutilisables à partir de ses propres flux de travail et ouvre un WebSocket pour que tout puisse lui parler. Pendant ce temps, plus de 40 corrections de bugs dans le cron, la mémoire, les nouvelles tentatives et les canaux ont transformé « ça marche la plupart du temps » en « ça marche ».

Faits saillants

  • Injection à mi-tour — les suivis ne font pas la queue — Si vous envoyez un autre message alors que l'agent travaille encore, il ne se met plus en file d'attente derrière un verrou. Le suivi est injecté dans le tour actif, et sur les chaînes de streaming, la réponse continue dans la même réponse en direct. Cela donne l’impression que les longues chaînes d’appels d’outils sont interactives plutôt qu’à sens unique. Le drainage des cas extrêmes sur les chemins d’erreur a été renforcé lors d’une passe de suivi. (#3042, #3110)
  • Dream apprend des compétences, pas seulement des faits — Le flux de consolidation de Dream peut désormais reconnaître les flux de travail répétés et les promouvoir en compétences d'espace de travail autonomes sous skills/. Combiné avec la configuration disabledSkills pour exclure les compétences dont vous ne voulez pas, la surface de compétences de l'agent est désormais quelque chose qui se développe de manière organique et reste gérable. (#3048, #2959)
  • Compact automatique — l'agent gère son propre contexte — Les sessions ne se développent plus jusqu'à ce qu'elles atteignent le mur. Le compactage automatique surveille les périodes d'inactivité, puis résume de manière proactive le contexte plus ancien tout en préservant les messages en direct récents. Ainsi, lorsque vous revenez, l'agent se souvient de ce qui compte sans traîner tout ce qui ne l'est pas. Il ne s’agit pas de la vieille approche « neutraliser la session » ; c'est une compression chirurgicale qui maintient la conversation continue. Associez-le à idleCompactAfterMinutes dans la configuration pour un contrôle précis. (#3007, #3081, #3093)
  • Canal WebSocket — connectez n'importe quoi — Un nouveau canal websocket exécute un serveur WebSocket avec streaming (événements delta + stream_end), authentification basée sur des jetons (statiques ou émises), sessions par connexion et prise en charge TLS. Applications Web, CLI, extensions Chrome, scripts : tout ce qui peut ouvrir un socket peut désormais communiquer avec l'agent en temps réel. (#2964)
  • Les chaînes sont devenues plus profondes — Telegram a obtenu le partage de position. Discord a obtenu des réponses en streaming et une prise en charge proxy. Feishu a ajouté le cycle de vie des emoji terminés, des astuces sur les outils en ligne et la configuration du domaine global Lark. QQ et WeCom ont reçu un soutien médiatique total. L'outil message de Slack résout désormais #channel_name et @user en identifiants réels. Le point de terminaison API accepte les téléchargements de fichiers via JSON base64 et multipart, avec extraction automatique de documents (PDF, DOCX, XLSX, PPTX) sur tous les canaux. Et l’amplification des nouvelles tentatives – où un envoi échoué déclencherait des tentatives en cascade – a été corrigée sur chaque canal. (#2910, #2939, #2960, #2993, #3046, #3044, #3138, #2938, #3053)
  • Prestataires — pensée adaptative et Kimi — Le mode de raisonnement adaptive d'Anthropic est arrivé, permettant à Claude de décider quand et combien réfléchir. Les modèles Kimi capables de réfléchir (kimi-k2.5, k2.6-code-preview) bénéficient désormais de l'injection automatique extra_body.thinking via reasoningEffort. Les champs de raisonnement du Plan StepFun API s'affichent correctement. Les prestataires non-Claude bénéficient d’une application appropriée de l’alternance des rôles. Et les arguments d’appel d’outil sont normalisés pour les fournisseurs stricts qui rejettent le JSON mal formé. (#2882, #3124, #2903, #2637, #3154)
  • MCP, outils et recherche — Les ressources et les invites MCP sont désormais exposées en tant qu'outils en lecture seule — l'agent peut les interroger directement. Plusieurs serveurs MCP se connectent dans le cadre de tâches isolées au lieu de s'affronter. L'outil d'édition de notebook est arrivé. Kagi a rejoint la gamme des fournisseurs de recherche Web. Et l'outil d'exécution est devenu plus strict : la prise en charge de Windows est arrivée, allowed_env_keys vous permet de transférer sélectivement les variables d'environnement, les fichiers d'état internes sont protégés en écriture et working_dir en dehors de l'espace de travail est rejeté. (#2907, #3019, #3017, #2945, #2893, #2962, #3061)
  • Cron a arrêté de supprimer les tâches — Quatre correctifs cron distincts concernaient les rechargements du magasin réentrant pendant l'exécution des tâches, la duplication des tâches à intervalle fixe en raison du remplacement simultané du magasin, le non-rechargement de la configuration des tâches et l'état d'exécution manuelle non préservé. Si vous comptez sur des tâches planifiées, cette version est celle où elles deviennent ennuyeuses. (#3038, #3034, #2895, #2930)

nanobot v0.1.5.post1

🐈 nanobot v0.1.5.post1 is here 🎉 — 80 PRs merged, 25 new contributors. The agent learned to manage itself.

If v0.1.5 was about making the building livable, v0.1.5.post1 is about the building learning to take care of itself. The agent now compresses its own context before it gets too long, injects follow-up messages mid-turn instead of making you wait, discovers reusable skills from its own workflows, and opens a WebSocket so anything can talk to it. Meanwhile, 40+ bug fixes across cron, memory, retry, and channels turned "it works most of the time" into "it works."

Highlights

  • Mid-turn injection — follow-ups don't wait in line — If you send another message while the agent is still working, it no longer queues behind a lock. The follow-up gets injected into the active turn, and on streaming channels the reply continues in the same live response. This makes long tool-call chains feel interactive instead of one-way. Edge-case draining on error paths was hardened in a follow-up pass. (#3042, #3110)

  • Dream learns skills, not just facts — Dream's consolidation flow can now recognize repeated workflows and promote them into standalone workspace skills under skills/. Combined with disabledSkills config for excluding skills you don't want, the agent's skill surface is now something that grows organically and stays manageable. (#3048, #2959)

  • Auto compact — the agent manages its own context — Sessions no longer grow until they hit the wall. Auto compact watches for idle periods, then proactively summarizes older context while preserving recent live messages — so when you come back, the agent remembers what matters without dragging along everything that doesn't. This isn't the old "nuke the session" approach; it's surgical compression that keeps the conversation feeling continuous. Pair it with idleCompactAfterMinutes in config for fine-grained control. (#3007, #3081, #3093)

  • WebSocket channel — connect anything — A new websocket channel runs a WebSocket server with streaming (delta + stream_end events), token-based auth (static or issued), per-connection sessions, and TLS support. Web apps, CLIs, Chrome extensions, scripts — anything that can open a socket can now talk to the agent in real time. (#2964)

  • Channels got deeper — Telegram gained location sharing. Discord got streaming replies and proxy support. Feishu added done-emoji lifecycle, inline tool hints, and Lark global domain config. QQ and WeCom received full media support. Slack's message tool now resolves #channel_name and @user to real IDs. The API endpoint accepts file uploads via JSON base64 and multipart, with automatic document extraction (PDF, DOCX, XLSX, PPTX) across all channels. And retry amplification — where a failed send would trigger cascading retries — was fixed across every channel. (#2910, #2939, #2960, #2993, #3046, #3044, #3138, #2938, #3053)

  • Providers — adaptive thinking and Kimi — Anthropic's adaptive reasoning mode landed, letting Claude decide when and how much to think. Kimi thinking-capable models (kimi-k2.5, k2.6-code-preview) now get automatic extra_body.thinking injection via reasoningEffort. StepFun Plan API reasoning fields fall back correctly. Non-Claude providers get proper role alternation enforcement. And tool-call arguments are normalized for strict providers that reject malformed JSON. (#2882, #3124, #2903, #2637, #3154)

  • MCP, tools, and search — MCP resources and prompts are now exposed as read-only tools — the agent can query them directly. Multiple MCP servers connect in isolated tasks instead of racing each other. The notebook editing tool arrived. Kagi joined the web search provider lineup. And the exec tool got tighter: Windows support landed, allowed_env_keys lets you selectively forward env vars, internal state files are write-protected, and working_dir outside the workspace is rejected. (#2907, #3019, #3017, #2945, #2893, #2962, #3061)

  • Cron stopped dropping jobs — Four separate cron fixes addressed reentrant store reloads during job execution, fixed-interval tasks duplicating due to concurrent store replacement, job config not reloading, and manual run state not being preserved. If you rely on scheduled tasks, this release is the one where they become boring. (#3038, #3034, #2895, #2930)

A retry amplification loop spotted by @Bahtya. A channel error path that silently swallowed messages, fixed by @yanghan-cyber.
