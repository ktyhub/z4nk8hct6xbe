career-ops career-ops-v1.33.0

Highlights

  • JD extraction moves to public APIs — browser-extract now reads Greenhouse, Lever and Ashby job descriptions directly from their public APIs and ships a fetch-jd.mjs helper (#3654, closing the long-standing #2582). This is structural, not cosmetic: structured API payloads replace brittle DOM scraping, so JD capture survives markup changes and gives downstream archiving/dedup a stable content source.

  • Multi-CLI batch evaluation lands — the new --cli flag runs batch evaluation across opencode, gemini and qwen, while ollama-eval streams responses and exposes OLLAMA_NUM_CTX (#3922). Paired with fixes that parse (rather than concatenate) Gemini scores (#3799) and persist OpenAI/Ollama evaluations as tracker rows (#3797), cross-model comparison finally becomes usable — note the side effect that evals now mutate the tracker.

  • External data roots and localized reports finally work — a broad fix cluster makes CAREER_OPS_DATA_DIR authoritative: serve:dashboard (#3929), funnel-velocity/calibrate/weekly-digest (#3715), jd-skill-gap (#4209), and scripts/post-merge hooks now resolving from the code root rather than the data root (#3761). Parsing also handles French report headers (#3808), archetype headers in every localized mode (#3866) and Chinese section titles (#3803). If you ran a non-default data dir or non-English reports, the commit "four defects invisible in the maintainer's own checkout" is precisely your case — expect previously failing commands to start working.

  • JD archival becomes a hard requirement — oferta/pdf now enforces JD archival in every report, and check-jd-archive rejects login-wall/404/paywall/JS-shell text as non-content (#3837) while crediting jds/ captures named by a tracker row. Behavioral change to watch: a scraped stub no longer satisfies the archive check, so reports that previously passed may now flag missing JDs.

  • Provider failures degrade gracefully — network/parser hardening pins accept-encoding to avoid truncated zstd bodies, stops Radancy from trusting totalResults while cache-busting JSON and retrying fetches (#3839), routes id encoding through _safe-url (garena, feishu-jobs, mokahr), and ensures a lone surrogate in one id/slug no longer aborts an entire page. For scan operators this means fewer all-or-nothing page failures — individual bad postings drop instead of killing the whole run.

  • Wider coverage, with a web opt-in — new sources: Gem's REST API as a verified-URL mode (#3783), zero-auth Telegram channels via t.me/s/ (#3668), Collage HR (#3787), and server-side Algolia filters that make WTTJ scans exhaustive (#3757). Separately, the local dashboard API gains an opt-in origin allowlist (#3597) — default behavior is unchanged, but cross-origin consumers must now configure it explicitly.

No breaking changes in this release.
