career-ops web-v0.10.0

Highlights

  • Evidence-tiered requirement importance in Block B — #3596 adds importance levels to Block B requirements derived from how each one is evidenced. This is a schema-level addition: scoring, filters, and UI now get a first-class signal for "hard requirement vs. nice-to-have" instead of relying on string heuristics. Consumers of Block B should read the new field and decide whether their matching logic should weight it — otherwise the metadata is inert.
  • Two new scanner providers: Feishu Jobs and MokaHR — #3491 extends source coverage into Chinese-market job boards and ATS platforms. Adopters gain new provider config and credentials to wire up; anyone maintaining provider allowlists, docs, or scan schedules should update them. Watch raw posting volume and dedupe assumptions — more sources feed the same pipeline.
  • Tailored-CV resolution tightened — filename audit needed — A cluster of fixes changes which CV gets attached. Resolvers now require the cv- prefix (#2156), selection is scoped to the current application rather than "newest for the company" (ca11627), and a company with no usable slug no longer matches every tailored CV (#3214). Together these kill a class of "wrong document sent" bugs, but check that your tailored-CV files follow the cv- convention before upgrading, or they will stop resolving.
  • Today queue ordering and localized status ranking — The action queue is now ordered before it is truncated (3a067ee), and "Awaiting your decision" is ranked using all EVALUATED aliases rather than an English prefix (d7573e1). Behavioral change: the items at the top of Today can differ, and non-English status labels now rank correctly. Re-baseline any automation or snapshots that depended on the old order.
  • Config and offline resilience — A malformed portals.yml is preserved instead of being silently replaced with the example file (07ed4f3), so hand-edited config survives — but syntax errors now surface as errors rather than being auto-repaired. Production fonts are self-hosted (a2e46c3), so the app boots without calling Google, which matters for air-gapped/offline installs. Grok is discovered in its default install directories, not just on PATH (77657dc), easing setup.
  • Apply flow and reporter feedback — Applying directly from the generated PDF index is now supported (ac761fa), closing the gap between "generate" and "apply." Beta reporters are told when a duplicate search could not run (77bf490) instead of it failing silently — a small but useful observability win for triage.

No breaking changes.

Features

  • web: enable apply from the generated pdf index (ac761fa)
  • web: find Grok in its default install dirs, not only on PATH (77657dc)

  • web: rank "Awaiting your decision" by every EVALUATED alias, not an English prefix (d7573e1)
  • web: require the cv- prefix so the tailored-CV resolvers stop returning the cover letter (#2156) (414d340)
  • web: resolve the tailored CV for THIS application, not the newest for the company (ca11627)
  • web: self-host the production fonts so the app starts without Google (a2e46c3)
  • web: tell the beta reporter's user when the dupe search could not run (77bf490)
