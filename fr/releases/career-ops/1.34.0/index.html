opérations de carrière carrière-opérations-v1.34.0

<!-- co:release-notes:career-ops-v1.34.0 -->

Il s'agit de la première version depuis que j'ai commencé à travailler à plein temps sur des opérations de carrière. L'invite de mise à jour s'affiche désormais uniquement lorsqu'une nouvelle version est réellement disponible. Jusqu'à présent, presque tout changement arrivant sur main pouvait le déclencher, souvent tous les jours. Cette version contient également le travail de 63 personnes, dont 43 contribuent pour la première fois.

Faits saillants

  • La mise à jour demande uniquement les nouvelles versions. update-system.mjs installe la dernière version publiée au lieu de main, check demande uniquement lorsqu'une version plus récente existe et dit non dure jusqu'à la prochaine version au lieu de toujours. Le suivi de main reste disponible avec --channel main. Construit sur la résolution de sortie de @obielin dans #3845.
  • Moins d'offres en direct marquées comme fermées. Liveness vérifie désormais les pages d'entreprise avec un Greenhouse gh_jid, SmartRecruiters, Arbeitsagentur et We Work Remotely via leurs API publics (#4444), et une page de carrière qui charge son ATS dans une iframe n'est plus lue comme une publication morte (#4439), toutes deux par @luochen211.
  • Analyses plus précises. Détection au niveau du domaine des republications de l'agrégateur par @vaishaldsouza (#4263), un filtre d'emplacement strict opt-in qui échoue fermé sur des emplacements vides par @Zoubeir23 (#4033), des lignes de liste noire pouvant couvrir un domaine entier (#4169) et un avertissement lorsqu'un portail ne renvoie aucune tâche sans une seule réponse réussie (#4441), tous deux par @luochen211.
  • Nouvelles sources. Un fournisseur d'emplois Python.org par @lasithadilshan (#4173), un fournisseur de forums mondiaux généralistes par @ConnorCloze (#4100) et une épingle explicite de locataire Personio par @duathron (#4001), les trois premières contributions.

Mise à jour

Votre agent propose cette mise à jour au début de votre prochaine session. Si vous avez déjà lancé une invite de mise à jour, exécutez-la une fois pour la récupérer :

node update-system.mjs apply --confirm

Nouvelles installations : npx @santifer/career-ops init.

<!-- co:release-notes:career-ops-v1.34.0 -->

This is the first release since I started working on career-ops full time. The update prompt now shows up only when a new version is actually out. Until now, almost any change landing on main could trigger it, often every day. This release also carries work from 63 people, 43 of them contributing for the first time.

Highlights

  • Update prompts only for new versions. update-system.mjs installs the latest published release instead of main, check asks only when a newer release exists, and saying no lasts until the next version instead of forever. Tracking main stays available with --channel main. Built on @obielin's release resolution in #3845.
  • Fewer live offers marked as closed. Liveness now checks company pages with a Greenhouse gh_jid, SmartRecruiters, Arbeitsagentur and We Work Remotely through their public APIs (#4444), and a careers page that loads its ATS in an iframe is no longer read as a dead posting (#4439), both by @luochen211.
  • Sharper scans. Domain-level detection of aggregator reposts by @vaishaldsouza (#4263), an opt-in strict location filter that fails closed on empty locations by @Zoubeir23 (#4033), blacklist rows that can cover a whole domain (#4169), and a warning when a portal returns zero jobs without a single successful response (#4441), both by @luochen211.
  • New sources. A Python.org Jobs provider by @lasithadilshan (#4173), a generalist-world board provider by @ConnorCloze (#4100) and an explicit Personio tenant pin by @duathron (#4001), all three first contributions.

Updating

Your agent offers this update at the start of your next session. If you declined an update prompt before, run this once to pick it up:

node update-system.mjs apply --confirm

New installs: npx @santifer/career-ops init.
