cognée v1.6.7

#v1.6.7

Date de sortie : 2026-11-06 Modifications : v1.6.6rc1 → v1.6.7

Demandes d'extraction : #6266, #6337, #6338, #6339, #6340, #6342, #6392, #6404, #6493, #6512, #6540, #6546, #6550, #6564

Résumé

Cette version renforce la sécurité de l'ingestion et améliore le comportement et les performances de la recherche et de la récupération. Vous bénéficierez de garanties plus strictes lors de la transmission des informations de connexion au fichier système ou à la base de données, de recherches ciblées plus correctes (requêtes ciblant un type de document ou un espace de noms spécifique) et d'une notation plus rapide et plus efficace pour les recherches vectorielles.

Faits saillants

  • Ingestion plus sûre : les chaînes de connexion brutes à la base de données et les chemins de serveur/fichier non sécurisés sont refusés par défaut, réduisant ainsi le risque d'identification accidentelle ou d'exposition du serveur.
  • Exactitude de la recherche et du rappel : les requêtes typées/portées (requêtes ciblées sur un type ou une portée de document spécifique) renvoient désormais des résultats corrects et sécurisés LLM et les sélections « se sentant chanceuses » ignorent les types de données désactivés.
  • Performances de récupération : la notation des requêtes est beaucoup plus rapide pour les backends PGVector, Turso et LanceDB en regroupant et en parallélisant le travail de notation.
  • Divers correctifs de robustesse : correctifs pour le compactage/migration de LanceDB, les insertions de graphiques, les opérations de session/oubli et les en-têtes d'exportation pour les utilisateurs de SDK.

Modifications radicales

  • Paramètres d'ingestion plus stricts pour les bases de données et les chemins distants : les chaînes de connexion brutes à la base de données et les chemins de fichiers du serveur via HTTP sont refusés par défaut. Impact : les flux de travail ou les connecteurs qui ont précédemment ingéré de telles chaînes de connexion commenceront à échouer à l'ingestion. Action : vérifiez votre configuration d'ingestion et vos contrôles d'inscription explicites dans la documentation pour autoriser ces sources si vous les utilisez intentionnellement.
  • ACCEPT_LOCAL_FILE_PATH gère désormais également les entrées s3:// : si vous vous appuyiez sur un comportement auparavant permissif pour les URI s3://, vous devrez peut-être définir ACCEPT_LOCAL_FILE_PATH ou suivre l'opt-in documenté pour réactiver ces entrées. Consultez la documentation d'ingestion API pour plus de détails.

Nouvelles fonctionnalités

  • Ancres de graphique à colonnes (DLT) : ajoute une nouvelle colonne au stockage du grand livre/graphique qui stocke les « ancres de graphique » (petits pointeurs qui aident à relier les lignes du tableau dans le graphique). Ce qu'il fait : enregistre les informations d'ancrage sur les écritures de colonnes afin que les requêtes graphiques et les processus en aval puissent référencer ces lignes de manière plus fiable. Pourquoi c'est important : améliore l'exactitude et la traçabilité des flux de travail qui s'appuient sur des colonnes basées sur des graphiques et sur le rapprochement du grand livre.

Améliorations

  • Gestion de l'ingestion plus stricte et plus claire : la messagerie d'ingestion a été simplifiée et le système dispose désormais d'une règle de refus unique pour les entrées de connexion réseau ou de base de données non sécurisées, ce qui permet de comprendre plus facilement pourquoi un fichier ou une connexion a été rejeté. Pourquoi c'est important : moins d'ingestions accidentelles de chaînes de connexion sensibles ou de chemins distants.
  • Contraintes de routage séparées pour les portées et les LLM : le code qui décide quels documents acheminer vers un modèle de langage (LLM) et lesquels acheminer par portée (type de document ou espace de noms) a été refactorisé en règles distinctes. Ce qu'il fait : rend les recherches ciblées et le comportement de routage LLM plus clairs et plus prévisibles. Pourquoi c'est important : améliore l'exactitude lorsque vous ciblez uniquement des types de documents spécifiques ou que vous souhaitez conserver certaines recherches sans LLM.
  • Gestion de la portée de recherche et de rappel : les portées typées (requêtes qui disent "uniquement rechercher des documents de type X") sont désormais honorées de manière cohérente dans les recherches de blocs et les requêtes citées/portées, et ces mêmes phrases citées évitent le routage LLM inutile. Pourquoi c'est important : les requêtes ciblées renvoient des résultats plus précis et attendus et évitent les appels LLM supplémentaires.
  • Corriger les codes d'erreur pour l'ingestion de fichiers : les requêtes interdites renvoient désormais 403 avec un message utile au lieu de 415. Pourquoi c'est important : une gestion plus claire des erreurs aide les opérateurs à diagnostiquer plus rapidement les problèmes d'autorisation et de contrôle.
  • Conserver les en-têtes OMP sur les exports SDK : lors de l'export des artefacts SDK (utilisés par les flux Cognee X / SDK) les en-têtes de style OpenMP sont conservés. Pourquoi c'est important : évite de perdre la configuration/les métadonnées lors des flux de travail d'exportation SDK.

Performances

  • Notation par lots sur tous les backends : PGVector et Turso évaluent désormais tout un lot de requêtes dans une seule instruction de base de données, réduisant ainsi les allers-retours et la latence pour les requêtes multi-requêtes (impact pratique : latence plus faible pour les récupérations multi-requêtes).
  • Optimisations du scoring LanceDB : un lot de requêtes peut être évalué avec une seule analyse d'identifiant sur LanceDB, et le scoring de plusieurs requêtes est parallélisé par identifiant. Impact pratique : récupérations de lots plus rapides lors de l'utilisation de LanceDB comme magasin de vecteurs.
  • Ignorez les collections vectorielles manquantes en une seule recherche pour PGVector : réduit le travail inutile lorsqu'une collection n'est pas présente. Impact pratique : des chemins de récupération plus rapides et moins de recherches dans certains cas d'échec.
  • Suppressions par lots pour le cache d'oubli/de session : les suppressions liées à la session sont regroupées pour réduire les frais généraux. Impact pratique : des opérations d’oubli à grande échelle plus rapides et plus efficaces.

Sécurité

  • Refus par défaut des chaînes de connexion à la base de données : les chaînes de connexion brutes à la base de données sont refusées par défaut pour éviter toute ingestion accidentelle d'identifiants. Si vous ingérez intentionnellement des sources de base de données, vous devez explicitement vous y inscrire (voir la documentation). Pourquoi c'est important : réduit le risque de fuite d'identifiants par ingestion.
  • Refuser les chaînes de connexion contenant les identifiants Cognee : le serveur refusera désormais les tentatives d'ingestion incluant les propres identifiants du produit. Pourquoi c'est important : empêche les connexions autoréférentielles accidentelles et la réutilisation des informations d'identification.
  • Refuser les chemins de fichiers du serveur sur HTTP par défaut : les entrées qui ressemblent à des chemins de fichiers de serveur sur HTTP brut sont refusées sauf si elles sont explicitement autorisées. Pourquoi c'est important : protège contre l'ingestion accidentelle de fichiers distants provenant de serveurs non rust.
  • ACCEPT_LOCAL_FILE_PATH contrôle également les entrées s3:// : la bascule d'environnement existante qui contrôle si les chemins du système de fichiers local sont acceptés contrôle désormais également les entrées de style s3:// dans l'ingestion des API. Pourquoi c'est important : rend le contrôle du chemin de fichier cohérent entre les sources locales et de style S3.
  • Corriger les erreurs d'autorisation : le API renvoie désormais 403 (Interdit) pour les tentatives d'ingestion de fichiers bloquées avec des informations utiles. Pourquoi c'est important : une signalisation d'erreur plus claire et plus appropriée pour les problèmes d'autorisation.

Corrections de bugs

  • Exclure les types désactivés de « se sentir chanceux » : la sélection unique de bloc « se sentir chanceux » ignore désormais les types de documents désactivés, évitant ainsi les accès non pertinents.
  • Refuser les étendues de fragments non notables : les recherches de fragments dont les étendues ne peuvent pas être notées sont désormais refusées plus tôt, évitant ainsi les résultats confus ou trompeurs.
  • Conserver la portée typée lorsqu'aucun vecteur ne correspond : lorsque votre portée typée ne renvoie aucune similitude vectorielle, la portée typée est toujours préservée afin que la logique en aval sache ce qui a été demandé.
  • Recherche de fragments de portée par nom de document : les recherches au niveau des fragments qui spécifient un nom de document limitent désormais la recherche de manière appropriée à ce document.
  • Correctifs LanceDB : plusieurs correctifs pour conserver les lignes de fenêtre pendant le compactage et pour réparer les lignes écrites lors des migrations, améliorant ainsi l'intégrité des données après des modifications de schéma ou des opérations de maintenance.
  • Corrections de graphiques et d'upsert : upsert_edges acceptera les ID de nœud de chaîne et d'autres correctifs de graphiques améliorent la robustesse des écritures de graphiques.
  • Corrections de session/oubli : la portée du propriétaire de session et la correspondance de suppression de session ont été renforcées afin que les flux de travail d'oubli survivent aux propriétaires de session supprimés ou manquants.
  • Copie d'index et lignes stockées : les lignes d'index sont désormais copiées telles qu'elles sont stockées, évitant ainsi les incohérences entre les métadonnées d'index et les données stockées.

Modifications techniques

  • Refactoriser : diviser le routage de portée et les contraintes de routage LLM en composants distincts pour simplifier la logique de routage et faciliter le test des modifications futures.
  • Refactorisation et nettoyage des messages en cas de refus d'ingestion : unification du format du message de refus afin qu'il y ait un seul endroit pour décider pourquoi une ingestion est rejetée.
  • Refonte de la notation de récupération : chemins de notation repensés afin que les backends puissent évaluer les lots de requêtes en moins d'instructions, et ajout de simulations/tests pour les moteurs prenant en charge les collections. Effet pratique : code de récupération plus clair et mieux testé avec des gains de performances mesurables.
  • CI et tests : ajout et mise à jour de nombreux tests (unitaires, intégration, e2e) et workflows CI pour augmenter la couverture et la fiabilité ; Nous avons également ajouté davantage de dispositifs de test de connecteurs et de simulations d'adaptateurs.

cognee v1.6.7

v1.6.7

Release Date: 2026-11-06 Changes: v1.6.6rc1 → v1.6.7

Pull Requests: #6266, #6337, #6338, #6339, #6340, #6342, #6392, #6404, #6493, #6512, #6540, #6546, #6550, #6564

Summary

This release tightens ingestion safety and improves how search and retrieval behave and perform. You’ll see stricter safeguards when giving the system file or database connection info, more correct scoped searches (queries that target a specific document type or namespace), and faster, more efficient scoring for vector searches.

Highlights

  • Safer ingestion: raw database connection strings and unsafe server/file paths are refused by default, reducing risk of accidental credential or server exposure.
  • Search and recall correctness: typed/scoped queries (queries targeted at a specific document type or scope) now return correct, LLM-safe results and "feeling lucky" picks ignore disabled data types.
  • Retrieval performance: query scoring is much faster for PGVector, Turso and LanceDB backends by batching and parallelizing scoring work.
  • Various robustness fixes: fixes for LanceDB compaction/migration, graph upserts, session/forget operations, and export headers for SDK users.

Breaking Changes

  • Stricter ingestion defaults for databases and remote paths: raw database connection strings and server file paths over HTTP are refused by default. Impact: workflows or connectors that previously ingested such connection strings will start failing ingestion. Action: review your ingestion configuration and explicit opt-in controls in the docs to allow these sources if you intentionally use them.
  • ACCEPT_LOCAL_FILE_PATH now also gates s3:// inputs: if you relied on previously permissive behavior for s3:// URIs, you may need to set ACCEPT_LOCAL_FILE_PATH or follow the documented opt-in to re-enable those inputs. Check the ingestion API docs for details.

New Features

  • Column graph anchors (DLT): Adds a new column to the ledger/graph storage that stores "graph anchors" (small pointers that help link table rows back into the graph). What it does: records anchor information on column writes so graph queries and downstream processes can reference those rows more reliably. Why it matters: improves correctness and traceability for workflows that rely on graph-backed columns and ledger reconciliation.

Improvements

  • Stricter and clearer ingestion handling: the ingestion messaging was simplified, and the system now has a single refusal rule for unsafe network or database connection inputs so it’s easier to understand why a file or connection was rejected. Why it matters: fewer accidental ingestions of sensitive connection strings or remote paths.
  • Separated routing constraints for scopes and LLMs: the code that decides which documents to route to a language model (LLM) and which to route by scope (document type or namespace) was refactored into distinct rules. What it does: makes scoped searches and LLM routing behavior clearer and more predictable. Why it matters: improves correctness when you target only specific document types or want to keep some searches LLM-free.
  • Search and recall scope handling: typed scopes (queries that say "only search documents of type X") are now honored consistently in chunk searches and quoted/scoped queries, and those same quoted phrases avoid unnecessary LLM routing. Why it matters: scoped queries return more accurate, expected results and avoid extra LLM calls.
  • Correct error codes for file ingestion: requests that are forbidden now return 403 with a helpful message instead of 415. Why it matters: clearer error handling helps operators diagnose permission and gating problems faster.
  • Keep OMP headers on SDK exports: when exporting SDK artifacts (used by Cognee X / SDK flows) OpenMP-style headers are preserved. Why it matters: avoids losing configuration/metadata during SDK export workflows.

Performance

  • Batch scoring across backends: PGVector and Turso now score a whole batch of queries in a single database statement, reducing round trips and latency for multi-query requests (practical impact: lower latency for multi-query retrievals).
  • LanceDB scoring optimizations: a batch of queries can be scored with a single id scan on LanceDB, and scoring of multiple queries is parallelized by id. Practical impact: faster batch retrievals when using LanceDB as the vector store.
  • Skip missing vector collections in one lookup for PGVector: reduces wasted work when a collection is not present. Practical impact: faster retrieval paths and fewer lookups in some failure cases.
  • Batch deletes for forget/session cache: session-related deletes are batched to reduce overhead. Practical impact: faster and more efficient large-scale forget operations.

Security

  • Default refusal of database connection strings: raw database connection strings are refused by default to prevent accidental ingestion of credentials. If you intentionally ingest database sources, you must explicitly opt in (see docs). Why it matters: reduces the risk of credential leakage via ingestion.
  • Refuse connection strings containing Cognee credentials: the server will now refuse ingestion attempts that include the product’s own credentials. Why it matters: prevents accidental self-referential connections and credential reuse.
  • Refuse server file paths over HTTP by default: inputs that look like server file paths over plain HTTP are refused unless explicitly allowed. Why it matters: protects against accidental remote-file ingestion from untrusted servers.
  • ACCEPT_LOCAL_FILE_PATH also gates s3:// inputs: the existing environment toggle that controls whether local filesystem paths are accepted now also controls s3:// style inputs in ingestion APIs. Why it matters: makes file-path gating consistent across local and S3-style sources.
  • Correct permission errors: the API now returns 403 (Forbidden) for blocked file ingestion attempts with helpful info. Why it matters: clearer, more appropriate error signaling for permission problems.

Bug Fixes

  • Exclude disabled types from "feeling lucky": the one-shot "feeling lucky" chunk selection now ignores document types that are disabled, preventing irrelevant hits.
  • Refuse unscorable chunk scopes: chunk searches with scopes that cannot be scored are now refused early, avoiding confusing or misleading results.
  • Keep typed scope when no vector matches: when your typed scope returns no vector similarities, the typed scope is still preserved so downstream logic knows what was requested.
  • Scope chunk search by document name: chunk-level searches that specify a document name now limit the search appropriately to that document.
  • LanceDB fixes: several fixes to keep window rows during compaction and to repair rows written during migrations, improving data integrity after schema changes or maintenance operations.
  • Graph and upsert fixes: upsert_edges will accept string node IDs and other graph fixes improve robustness of graph writes.
  • Session/forget fixes: session-owner scoping and session-delete matching were hardened so forgetting workflows survive deleted or missing session owners.
  • Index copy and stored rows: index rows are now copied as stored, avoiding mismatches between index metadata and stored data.

Technical Changes

  • Refactor: split scope routing and LLM routing constraints into separate components to simplify routing logic and make future changes easier to test.
  • Refactor and message cleanup for ingestion refusal: unified the refusal message format so there’s a single place deciding why an ingestion is rejected.
  • Retrieval scoring rework: redesigned scoring paths so backends can score query batches in fewer statements, and added mocks/tests for collection-aware engines. Practical effect: clearer, better-tested retrieval code with measurable perf gains.
  • CI and tests: added and updated many tests (unit, integration, e2e) and CI workflows to increase coverage and reliability; also added more connector test fixtures and adapter mocks.

Dependency Updates

Updated:

  • fastembed: <=0.8.0 → >=0.9.1,<0.10
  • filelock: >=3.12.0,<4.0.0 → >=3.12.0
  • onnxruntime: >=1.24.1 → >=1.17
  • pydantic: >=2.10.5 → >=2.13

Removed:

  • diskcache >=5.6.3
  • instructor >=1.9.1,<1.15.3
