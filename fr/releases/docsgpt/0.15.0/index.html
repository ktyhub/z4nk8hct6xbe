DocsGPT 0.15.0

Highlights

  • Remote MCP servers, now with OAuth — #1947 adds remote MCP support, and #1964 rebuilt it around OAuth plus a fastmcp client that speaks SSE and other transports. This is the headline capability for agent builders: tools are no longer confined to in-process functions, so agents can reach external MCP ecosystems. If you experimented with the early MCP implementation, re-test it — the auth and transport layers were replaced underneath it.

  • Model registry and multi-provider capability metadata — #2158 introduces a central model registry with declared capabilities, paired with #2174 fixing model selection in agents via the API. Why it matters: provider/model choice shifts toward declarative, capability-based routing. Before upgrading, verify your custom models are registered with the right capabilities or they may not be selectable.

  • PostgreSQL as a first-class vector backend — #1906 adds PGVectorStore, letting you keep embeddings in PostgreSQL instead of operating a separate Qdrant instance (which also received fixes in #1905). Concrete migration win for teams already running Postgres. Combine with #2173's context compression to reduce token spend on long conversations.

  • Schema-validated structured outputs — #1924 adds structured output with JSON schema validation, so agent responses can be constrained to a contract instead of free-form text. Together with the prompt-variable and template-rendering work (#2128, #2091), this is what makes agent output safe to consume programmatically — worth adopting if you build on the API.

  • API and config surface moved — check your integrations — Answer routes were restructured (#1896) and user routes reorganized into a domain-driven layout (#2005), with webhook fixes in #2175. More importantly, #2050 renames the LLM_PROVIDER setting (and runtime naming) alongside the new Windows PowerShell deployment path: update your env/config keys before rolling out. These are the most likely breakage points for self-hosters and API consumers.

  • Agent tooling matures; frontend toolchain leaps — Premade agent templates and seeding (#1910), token/request limiting (#2041), Google Drive ingestion with OAuth fixes (#1937, #1976), multi-select sources (#1930), and MongoDB-backed NotesTool/MemoryTool with tool_id management (#1982, #2026) make agents considerably more production-ready. On the frontend, dependency jumps to Tailwind 4, Vite 7, ESLint 9, and i18next 25 mean custom forks need config/styling migration — budget for it rather than treating these as routine bumps.
