DocsGPT 0.16.0

Highlights

  • Visual agent workflows with CEL branching — The headline capability is a visual agent workflow builder (#2264) with condition nodes that evaluate CEL expressions (#2280), letting you branch on context/variables instead of hard-coding linear sequences. Agents can be grouped into folders (#2245), and agent "Self" tools (Notes/Todo) now persist via artifacts with streaming artifact_id support (#2267). Why it matters: this pushes DocsGPT from single prompt-and-retrieve toward an orchestration platform; if you built flat agents, expect to rethink their structure.
  • Ingestion overhaul: Docling, OCR, S3 and SharePoint — Parsing moves to Docling (#2202) with OCR for attachments (#2246) and a synthetic-PDF path for models that can't ingest files natively (#2263). New connectors include Amazon S3 with synchronization (#2244) and SharePoint (#2283), alongside improved crawlers and changed chunk filtering (#2250). Why it matters: scanned docs and non-file-native models now work without preprocessing — but altered chunk filtering can shift retrieval quality, so re-index and re-evaluate before rollout.
  • Streaming and token accounting reshape responses — Thinking tokens and artifact_ids now stream (#2275, #2276, #2267); history tokens are counted from chunks and the old UI token-limit setting is removed (#2196), with further token fixes (#2285) and agent-side context validation/message truncation (#2249). Message format was reworked (#2349) and stream fallbacks hardened (#2332). Why it matters: direct consumers of the streaming API should expect changed event/field shapes and no client-side token cap — update parsers and rely on server-side truncation.
  • React widget: styled-components v6 migration — Widget users must handle that shouldForwardProp is no longer provided by default under styled-components v6 (#2312); the dependency moves to 6.3.12 (#2323), npm packages to v0.6.3 (#2333), and publishing is now automated via Actions (#2328). Watch for custom props leaking onto DOM elements after upgrading — this is the likeliest "worked before" regression.
  • Node.js 22 required for builds — CI and local builds must move to Node.js 22 for Vite compatibility (#2169). Treat this as a minimum-version bump in your toolchain before pulling 0.16.0; older Node images will fail the frontend build.
  • Security fix and broader tool/provider surface — A stored-XSS vector in PromptsModal (dangerouslySetInnerHTML) is fixed (#2279), a concrete reason to upgrade if prompt content is shared. Extensibility gains include API-tool body serialization with content-type handling (#2192), dynamic config rendering for MCP tools (#2286), improved tool logging/error handling incl. DuckDuckGo (#2282), and new integrations: Novita AI (#2320), speech-to-text (#2306) and a Research agent (#2327).
