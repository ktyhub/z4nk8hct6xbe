DocsGPT 0.17.0

Highlights

  • Mandatory Postgres migration — User data now lives in Postgres. Existing 0.16.x deployments must complete the documented migration before upgrading; do not run docker compose pull first. Plan for a maintenance window and verify the migrated data before cutting over.
  • Storage layer overhaul ("Pg 4") — PR #2390 accompanies the Postgres transition, making database provisioning, backups, and persistence part of deployment planning rather than application-only concerns. Operators should validate credentials, volume/database availability, and restore procedures with the new stack.
  • Stronger supply-chain checks — The new zizmor GitHub Actions workflow (#2383) adds automated security analysis for CI workflows, helping catch unsafe Actions usage before changes reach maintainers or downstream users. This strengthens the project’s release process, but does not replace securing your own deployment.
  • Security documentation is now actionable — A public threat model (#2391) and incident-response guidance linked from SECURITY.md (#2379) give adopters concrete context for trust boundaries, abuse scenarios, and response responsibilities. Review these documents when designing production controls and internal incident runbooks.
  • Broad dependency refresh, including major-version tooling — Alongside security patches such as cryptography 46.0.7, the release updates core AI SDKs (openai 2.31.0, google-genai 1.73.1), fastmcp 3.2.4, and langchain-core 1.2.26. Custom integrations should run their provider/MCP compatibility tests; frontend extension maintainers should also rebuild after jumps including lucide-react 1.8.0 and svgo 4.0.1.

User data now lives in Postgres. Existing 0.16.x deployments must complete the Postgres Migration before upgrading - do not docker compose pull first.
