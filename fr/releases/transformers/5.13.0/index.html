Némotron 3.5 ASR

<img width="1632" height="735" alt="image" src="https://github.com/user-attachments/assets/597bbb9c-b046-4e47-b9fd-f242e0a5b04d" />

Nemotron 3.5 ASR est un modèle de reconnaissance vocale multilingue à 600 millions de paramètres de NVIDIA, conçu pour une transcription de haute qualité dans les paramètres de streaming à faible latence et de lots à haut débit, avec ponctuation native et capitalisation. Pour le streaming, il propose des tailles de fragments configurables : 80 ms, 160 ms, 560 ms et 1 120 ms, permettant aux utilisateurs de choisir entre la latence et la précision en fonction de leur application. Son architecture FastConformer-RNNT sensible au cache est au cœur de cette fonctionnalité : contrairement au streaming tampon traditionnel, qui retraite à plusieurs reprises les fenêtres audio qui se chevauchent, le modèle traite uniquement chaque nouveau fragment entrant tout en réutilisant le contexte d'encodeur mis en cache des fragments précédents. Cela élimine les calculs redondants, améliore considérablement l'efficacité et minimise les délais de bout en bout sans sacrifier la précision, ce qui le rend bien adapté aux charges de travail de transcription en temps réel.

VidéoPrisme

Le modèle VideoPrism a été proposé dans l'article VideoPrism: A Foundational Visual Encoder for Video Understanding de Google DeepMind (article de blog).

VideoPrism est un encodeur vidéo à usage général qui aborde diverses tâches de compréhension vidéo avec un seul modèle figé. Le modèle est pré-entraîné sur un corpus hétérogène à grande échelle contenant 36 millions de paires de sous-titres vidéo de haute qualité et 582 millions de clips vidéo avec du texte parallèle bruité (par exemple, transcriptions ASR). L'approche de pré-entraînement améliore l'auto-encodage masqué grâce à une distillation globale-locale d'intégrations vidéo sémantiques et à un schéma de brassage de jetons, permettant au modèle de se concentrer principalement sur la modalité vidéo tout en exploitant le texte associé aux vidéos. VideoPrism atteint des performances de pointe sur 31 des 33 tests de compréhension vidéo dans quatre grands groupes de tâches, de la réponse aux questions vidéo Web à la vision par ordinateur pour la science.

MiniCPM3

MiniCPM3 est le modèle de langage dense MiniCPM de troisième génération d'OpenBMB. La variante 4B (openbmb/MiniCPM3-4B) surpasse de nombreux 7B–9B ouverts modèles sur des références standard tout en restant suffisamment légers pour une utilisation sur l'appareil.

MiniCPM3 combine plusieurs idées architecturales :

  • Multi-head Latent Attention (MLA) de DeepSeek-V2, qui compresse le cache clé/valeur en une représentation latente de bas rang tout en utilisant des plongements rotatifs sur une partie du têtes de requête/clé.
  • Un SwiGLU MLP standard (pas de MoE).
  • Trois facteurs d'échelle scalaires qui régissent le flux du signal :
    • scale_emb — met à l'échelle les intégrations d'entrée.
    • scale_depth / sqrt(num_hidden_layers) — met à l'échelle les connexions résiduelles.
    • hidden_size / dim_model_base — met à l'échelle les états cachés avant la tête du modèle de langage.

HfExporters : Exportation native et unifiée pour PyTorch / ONNX / ExecuTorch

<img alt="thumbnail" src="https://github.com/user-attachments/assets/3ba5751b-c99e-4945-b5a8-b2b29231f5df" />

Un pipeline d'exportation natif intégré à Transformers : une classe de base (HfExporter), trois sous-classes pour les environnements d'exécution qui nous intéressent, un API unifié :

| Exportateur | Sortie | Durée d'exécution | |---|---|---| | DynamoExporter | ExportedProgram | N’importe quel runtime PyTorch, compilation AOT | | OnnxExporter | ONNXProgram | Tout runtime ONNX (ORT, TensorRT, OpenVINO, …) | | ExecutorchExporter | ExecutorchProgramManager | Mobile et périphérie (ExecuTorch) | Même forme d’appel pour les trois. Formes dynamiques par défaut. Les modèles de style génération se divisent automatiquement en pré-remplissage + décodage (+ sous-encodeurs vision/audio pour les VLM).

from transformers import AutoModelForMaskedLM, AutoTokenizer
from transformers.exporters import OnnxExporter, OnnxConfig

model_id = "hf-internal-testing/tiny-random-BertForMaskedLM"
tokenizer = AutoTokenizer.from_pretrained(model_id)
model = AutoModelForMaskedLM.from_pretrained(model_id).eval()
inputs = tokenizer(["Hello, my dog is cute"] * 2, return_tensors="pt")
onnx_program = OnnxExporter().export(model, inputs, config=OnnxConfig(dynamic=True))

new_input = tokenizer("Hello, my cat is so adorable!", return_tensors="pt")
torch.testing.assert_close(
    onnx_program.call_reference(**new_input)[0],   # numpy reference
    onnx_program(**new_input)[0],                  # onnxruntime
    rtol=1e-4, atol=1e-4,
)

Échangez une ligne contre un autre runtime : DynamoExporter() / DynamoConfig ou ExecutorchExporter() / ExecutorchConfig(backend=...).

Pour les modèles génératifs, la répartition pré-remplissage/décodage est capturée automatiquement :

from transformers import AutoModelForCausalLM, AutoTokenizer
from transformers.exporters import OnnxExporter, OnnxConfig

model_id = "hf-internal-testing/tiny-random-LlamaForCausalLM"
tokenizer = AutoTokenizer.from_pretrained(model_id)
model = AutoModelForCausalLM.from_pretrained(model_id).eval()
inputs = tokenizer(["Hello, my dog is cute"] * 2, return_tensors="pt")

artifacts = OnnxExporter().export_for_generation(model, inputs, config=OnnxConfig(dynamic=True))
# {"prefill": ONNXProgram, "decode": ONNXProgram}

<img width="1632" height="735" alt="image" src="https://github.com/user-attachments/assets/597bbb9c-b046-4e47-b9fd-f242e0a5b04d" />

Nemotron 3.5 ASR is a 600M-parameter multilingual speech recognition model from NVIDIA, built for high-quality transcription in both low-latency streaming and high-throughput batch settings, with native punctuation and capitalization. For streaming, it offers configurable chunk sizes—80ms, 160ms, 560ms, and 1120ms, letting users trade off latency against accuracy to suit their application. Its cache-aware FastConformer-RNNT architecture is central to this capability: unlike traditional buffered streaming, which repeatedly reprocesses overlapping audio windows, the model processes only each new incoming chunk while reusing cached encoder context from prior chunks. VideoPrism

The VideoPrism model was proposed in the paper VideoPrism: A Foundational Visual Encoder for Video Understanding by Google DeepMind (blog post).

VideoPrism is a general-purpose video encoder that tackles diverse video understanding tasks with a single frozen model. MiniCPM3

MiniCPM3 is the third-generation MiniCPM dense language model from OpenBMB. The 4B variant (openbmb/MiniCPM3-4B) outperforms many 7B–9B open models on standard benchmarks while remaining lightweight enough for on-device usage.

MiniCPM3 combines several architectural ideas:

  • Multi-head Latent Attention (MLA) from DeepSeek-V2, which compresses the key/value cache into a low-rank latent representation while still using rotary embeddings on a portion of the query/key heads.
  • A standard SwiGLU MLP (no MoE).
  • Three scalar scaling factors that govern signal flow:
    • scale_emb — scales input embeddings.
    • scale_depth / sqrt(num_hidden_layers) — scales residual connections.
    • hidden_size / dim_model_base — scales hidden states before the language model head.

HfExporters: Native, Unified export for PyTorch / ONNX / ExecuTorch

<img alt="thumbnail" src="https://github.com/user-attachments/assets/3ba5751b-c99e-4945-b5a8-b2b29231f5df" />

A native, in-Transformers export pipeline — one base class (HfExporter), three subclasses for the runtimes we care about, one unified API:

| Exporter | Output | Runtime | |---|---|---| | DynamoExporter | ExportedProgram | Any PyTorch runtime, AOT compilation | | OnnxExporter | ONNXProgram | Any ONNX runtime (ORT, TensorRT, OpenVINO, …) | | ExecutorchExporter | ExecutorchProgramManager | Mobile and edge (ExecuTorch) |

Same call shape across all three. Dynamic shapes by default. Generation-style models split automatically into prefill + decode (+ vision/audio sub-encoders for VLMs).

from transformers import AutoModelForMaskedLM, AutoTokenizer
from transformers.exporters import OnnxExporter, OnnxConfig

model_id = "hf-internal-testing/tiny-random-BertForMaskedLM"
tokenizer = AutoTokenizer.from_pretrained(model_id)
model = AutoModelForMaskedLM.from_pretrained(model_id).eval()
inputs = tokenizer(["Hello, my dog is cute"] * 2, return_tensors="pt")
onnx_program = OnnxExporter().export(model, inputs, config=OnnxConfig(dynamic=True))

new_input = tokenizer("Hello, my cat is so adorable!", return_tensors="pt")
torch.testing.assert_close(
    onnx_program.call_reference(**new_input)[0],   # numpy reference
    onnx_program(**new_input)[0],                  # onnxruntime
    rtol=1e-4, atol=1e-4,
)

Swap one line for another runtime — DynamoExporter() / DynamoConfig or ExecutorchExporter() / ExecutorchConfig(backend=...).
