Baleine Code v0.8.62

CodeWhale est le projet canonique, la commande, le package npm et nom de l'actif de version. L'ancien package npm deepseek-tui est obsolète et ne reçoit aucune autre version. Utilisateurs venant de Les anciens noms v0.8.x deepseek / deepseek-tui devraient migrer avec docs/REBRAND.md.

Installer

Recommandé — npm (une commande, les deux binaires)

npm install -g codewhale

Le wrapper télécharge les deux binaires de cette version et les place dans le même répertoire.

docker run --rm -it \
  -e DEEPSEEK_API_KEY="$DEEPSEEK_API_KEY" \
  -v ~/.deepseek:/home/codewhale/.deepseek \
  ghcr.io/hmbown/codewhale:v0.8.62

L'image contient le répartiteur codewhale et le runtime codewhale-tui. La balise latest est également mise à jour lors de la sortie.

cargo install codewhale-cli codewhale-tui --locked

Les deux caisses sont requises : codewhale-cli produit le répartiteur codewhale et codewhale-tui produit le runtime interactif auquel le répartiteur délègue. L'installation d'un seul binaire échouera au moment de l'exécution avec une erreur MISSING_COMPANION_BINARY.

Qu'y a-t-il dans v0.8.62

Modifié

  • GLM-5.2 est désormais le modèle Z.AI direct par défaut. DEFAULT_ZAI_MODEL résout à GLM-5.2 dans codewhale-tui et codewhale-config ; le glm-5.1 l'alias est toujours résolu en GLM-5.1 (la valeur par défaut a été découplée de l'alias arm pour qu'il ne suive plus la valeur par défaut). Docs et config.example.toml non ne décrit plus le GLM-5.2 comme un aperçu opt-in.
  • GLM-5-Turbo enregistré comme modèle réel et câblé comme le plus rapide/explore frère sous-agent pour la famille GLM : un parent GLM-5.2 plus rapide/explorer les enfants vers GLM-5-Turbo (direct Z.ai) et z-ai/glm-5-turbo (OpenRouter), au lieu de GLM-5.1. GLM-5.1 et GLM-5-Turbo eux-mêmes n'avoir pas de niveau moins cher et garder les enfants chez le parent.
  • Les sous-agents type: "explore" sont par défaut model_strength: "faster". Délimité le travail de recherche/recherche/statut en lecture seule utilise désormais le frère ou la sœur de la même famille, moins cher automatiquement, sauf si un model ou model_strength: "same" explicite est fourni. Les rôles non explorés conservent la valeur par défaut conservatrice same.
  • L'itinéraire plus rapide GPT-5.5 / OpenAI Codex reste sur GPT-5.5 avec raisonnement résolu en low (les réponses du Codex API n'ont pas de vrai off, donc le résolu l'effort est maintenant honnête low plutôt que off réécrit silencieusement). Non La solution de secours DeepSeek/GLM est fabriquée lorsqu'il n'y a pas de frère du même fournisseur moins cher existe. Le routage DeepSeek Pro → Flash et sa voie plus rapide sans réflexion sont inchangé.
  • Invite de base/conseils sur les compétences des délégués mis à jour pour encourager le parallèle exploration en lecture seule (2-4 sous-agents type: "explore") pour un dépôt large, investigations de version, de branche, de référence et de surface API, tout en conservant architecture, intégration et vérification finale dans le parent. Le les exemples de compétences de délégation utilisent désormais model_strength, indépendant du fournisseur, au lieu de ID de modèle DeepSeek codés en dur.
  • Garde-corps de synthèse d'agent. La constitution de base encadre désormais les outils autour preuves suffisantes plutôt qu’une persistance illimitée : lectures supplémentaires, recherches, et la délégation doit cibler un fait manquant, et les agents doivent répondre avec limites au lieu d’élargir indéfiniment les recherches. Le garde-boucle d'exécution bloque désormais les appels en lecture seule/délégués en double plus tôt et plafonne les répétitions de larges boucles de recherche/délégation en un seul tour avec un outil de forçage de synthèse erreur. Les métadonnées Guard distinguent les doublons exacts (identical_tool_call) à partir de boucles sans progression (no_progress_tool_loop).
  • Transfert et visibilité des sous-agents. Les achèvements directs des sous-agents sont drainés avant la prochaine demande de modèle parent, afin que les enfants ayant terminé puissent réveiller le modèle principal modélisez rapidement au lieu d'attendre une branche d'utilisation d'outil vide ou un moteur inactif chemin. Les sous-agents imbriqués signalent désormais les achèvements à leur parent immédiat boîte de réception ; le modèle principal ne reçoit toujours que des complétions directes des enfants, évitant ainsi les inondations des petits-enfants tout en préservant le flux de preuves imbriqué. Sortie du sous-agent les directives exigent désormais la provenance de l'agent enfant lorsqu'un sous-agent s'appuie sur un rapport de l'enfant : citez l'enfant agent_id et la ou les lignes de PREUVE de l'enfant, et ne présentez pas les découvertes des enfants comme des faits directement vérifiés. Les commandes de la barre latérale sous-agents sous forme d'arborescence parent/enfant et annote les lignes imbriquées avec le parent et informations de profondeur dans le texte de survol.
  • Provenance récapitulative du sous-agent (#2652). Le résultat en texte libre d'un sous-agent est maintenant explicitement traité comme une auto-évaluation non vérifiée plutôt que confirmée des preuves. La sentinelle d'achèvement porte summary_kind: complete | truncated afin que le modèle parent puisse déterminer s'il a vu le rapport complet ou un clippé extrait. Les résumés courts (≤ 12 000 caractères) bénéficient d'une "revérification du matériel" douce suffixe « revendications » ; les plus longs sont tête+queue tronqués avec un marqueur honnête indiquant que le milieu élidé n'est pas récupérable via retrieve_tool_result. Chaque résumé porte donc exactement une borne frontière, jamais les deux.
  • Centralisation des métadonnées du fournisseur. Vars d'environnement du fournisseur, clés de configuration, alias, et les indices d'authentification sont désormais résolus via le registre partagé ProviderMetadata sur codewhale-config, codewhale-tui et codewhale-cli, réduisant ainsi la dérive entre le sélecteur de fournisseur, codewhale auth, doctor --json et la configuration des indices.

Ajouté

  • Questions de clarification pour les agents (#3102). Les agents disposent désormais d'un Outil request_user_input pour poser à l'utilisateur des questions de clarification structurées via une surface d'interface utilisateur modale au lieu d'émettre uniquement un message de discussion et d'espérer l’utilisateur le remarque. Refléte le flux d'approbation/de demande secrète du harnais déjà utilisé pour les autorisations. L'outil accepte 1 à 3 questions, chacune avec un en-tête, un identifiant, 2 à 4 options sélectionnables (étiquette + description) et Indicateurs allow_free_text / multi_select (tous deux par défaut sur false pour rétrocompatibilité). L’entrée est validée à l’avance avec des erreurs exploitables. Filaire sur toutes les couches : l'outil request_user_input, la gestion moteur (turn_loop → approval), un modal TUI interactif (UserInputView) avec navigation complète au clavier et protocole d'exécution (EventFrame::UserInputRequest + AppRequest::SubmitUserInput) donc sans tête / app-server clients peut répondre par programme. Les tests de parité couvrent le fil aller-retour et la valeur par défaut des indicateurs omis.
  • Hyperliens de transcription — OSC 8 hors bande (#3029). Fichier Clickable / Les liens file:line / URL atteignent désormais le terminal via un coffre-fort à la dérive des colonnes chemin. Les charges utiles des liens sont intégrées en bande par le moteur de rendu markdown, puis extrait des cellules tampons ratatui et réémis hors bande par ColorCompatBackend — afin que les octets ESC n'occupent jamais les colonnes d'affichage ou sélection corrompue. Les terminaux pris en charge reçoivent des hyperliens en direct ; d'autres voient le texte de l'étiquette inchangé. Clipboard/extraction de sélection bandes codes résiduels comme défense en profondeur.
  • Porte de découverte de compétences réservée à CodeWhale (#3296). Nouveau [skills].scan_codewhale_only = true limite la découverte de compétences pendant la session à Racines appartenant à CodeWhale (<workspace>/.codewhale/skills, ~/.codewhale/skills, et tout skills_dir explicite) tout en ignorant les répertoires multi-outils tels que .claude/skills, .opencode/skills, .cursor/skills et ~/.agents/skills. La valeur par défaut reste l'analyse de compatibilité étendue.
  • Règles d'exécution d'autorisation/demande (#3295). Frère permissions.toml avec demande uniquement les règles sont désormais chargées par le moteur TUI et appliquées à exec_shell avant Raccourcis d’approbation automatique/de session. Les règles de demande correspondantes forcent une invite d'approbation dans des flux autrement approuvés automatiquement et sont rejetés sous approval_mode = "never".
  • Documentation sans authentification du Runtime API. docs/RUNTIME_API.md documente désormais codewhale app-server --insecure-no-auth pour les tests de bouclage uniquement et les avertissements contre le combiner avec --mobile sur 0.0.0.0.

Corrigé

  • TUI polish. Le bloc de bienvenue de démarrage vide est centré par le réel largeur du texte rendu, corrigeant la disposition décentrée laissée par l'ancienne composition de bienvenue orientée barre latérale. Erreurs de lecture du corps HTTP en streaming maintenant expliquer si CodeWhale peut réessayer avant la sortie ou s'il affiche un avertissement après une sortie partielle pour éviter de relire et de dupliquer le texte diffusé.
  • Préservation des commentaires de configuration. Réécriture de config.toml, settings.toml ou tui.toml fusionne désormais les commentaires des utilisateurs et le formatage dans le fichier sérialisé. documenter; si la fusion des commentaires échoue, l'écriture revient à la version sérialisée sortie plutôt que d’échouer.
  • Porte d'instantanés respectée pour les instantanés par outil (#3292). Instantanés par outil vérifiez maintenant [snapshots].enabled avant d'écrire, en faisant correspondre l'existant porte au niveau de la session.
  • Détection Poppler pdftotext (#1667). Le résolveur de dépendances sonde maintenant pdftotext -v au lieu de --version, car Poppler traite --version comme un nom de fichier d’entrée. Corrige la détection sur les systèmes sur lesquels seul Poppler est installé.
  • Visibilité de la liste de contrôle de confirmation du plan. Le modal de confirmation en mode Plan affiche désormais la liste de contrôle active sous les détails du plan, afin que les utilisateurs puissent consulter le béton checklist_write répartition des travaux avant d'accepter ou de réviser un plan.

Codewhale v0.8.62

Highlights

  • Model defaults and cheaper "explore" routing — DEFAULT_ZAI_MODEL now resolves to GLM-5.2 in both the TUI and config, and docs/config.example.toml stop labeling it an opt-in preview; the glm-5.1 alias still resolves to GLM-5.1, so alias and default are deliberately decoupled — audit anything that assumed they track each other. GLM-5-Turbo is now a registered model and the faster sibling for the GLM family, and type: "explore" sub-agents default to model_strength: "faster", so read-only lookups route to GLM-5-Turbo / z-ai/glm-5-turbo instead of GLM-5.1. Expect cheaper, faster broad repo and API-surface investigations; opt out with an explicit model or model_strength: "same" (non-explore roles keep same). The Codex/GPT-5.5 faster lane also now honestly reports reasoning: "low" rather than silently rewriting off, and no DeepSeek/GLM fallback is invented when no cheaper sibling exists.
  • Structured clarification questions (#3102) — Agents gain a first-class request_user_input tool: 1–3 questions with headers, ids, 2–4 labelled options, and allow_free_text / multi_select flags defaulting to false for back-compat, surfaced as a keyboard-navigable modal. It is wired end-to-end through the engine (turn_loop → approval) and runtime protocol (EventFrame::UserInputRequest / AppRequest::SubmitUserInput), so headless and app-server clients must handle the new event to answer programmatically — a real upgrade over an easily missed chat message.
  • Sub-agent reports are treated as unverified (#2652) — Free-text summaries are now self-reports, not evidence: summary_kind: complete | truncated lets the parent branch on clipping, short (≤12,000 char) reports get a soft "re-verify material claims" suffix, and longer ones are head+tail truncated with an explicit note that the elided middle is unrecoverable via retrieve_tool_result. Combined with earlier duplicate/no-progress loop guards (identical_tool_call vs no_progress_tool_loop), mandatory child agent_id/EVIDENCE provenance, and completions drained before the next parent request, expect agents to synthesize sooner and cite nested sources — and to hedge more on a child's claims instead of presenting them as directly verified.
  • New scoping and approval controls — [skills].scan_codewhale_only = true (#3296) restricts session skill discovery to .codewhale roots and explicit skills_dir, ignoring .claude, .opencode, .cursor, and ~/.agents directories (the broad scan remains the default). Sibling permissions.toml ask-only rules (#3295) are now loaded by the TUI engine and applied to exec_shell ahead of Auto/session shortcuts, forcing a prompt even in auto-approved flows and erroring under approval_mode = "never". Config rewrites also preserve user comments and formatting in config.toml, settings.toml, and tui.toml instead of dropping them.
  • Terminal hyperlinks that don't break layout (#3029) — Markdown file, file:line, and URL links are embedded in-band by the renderer, extracted from ratatui cells, and re-emitted out-of-band by ColorCompatBackend, so OSC 8 escape bytes never consume display columns or corrupt selection; unsupported terminals simply show the label text. Worth verifying if your terminal, multiplexer, or log pipeline is sensitive to extra escape sequences. (pdftotext detection also switches to pdftotext -v so Poppler-only systems resolve correctly — #1667.)
  • Migration and install gotchas — deepseek-tui is deprecated with no further releases; users on legacy v0.8.x package or binary names must follow docs/REBRAND.md. Cargo installs need both codewhale-cli and codewhale-tui (--locked) or runtime fails with MISSING_COMPANION_BINARY, and the Windows NSIS installer is unsigned, so expect SmartScreen warnings until signing is wired up. Both binaries ship in every platform archive and via the npm wrapper, so those paths avoid the companion-binary pitfall.

No breaking changes.

CodeWhale is the canonical project, command, npm package, and release-asset name. The legacy npm package deepseek-tui is deprecated and receives no further releases. Users coming from v0.8.x legacy deepseek / deepseek-tui names should migrate with docs/REBRAND.md.

What's in v0.8.62

Changed

  • GLM-5.2 is now the default direct Z.AI model. DEFAULT_ZAI_MODEL resolves to GLM-5.2 in both codewhale-tui and codewhale-config; the glm-5.1 alias still resolves to GLM-5.1 (the defaulting was decoupled from the alias arm so it no longer tracks the default). Docs and config.example.toml no longer describe GLM-5.2 as an opt-in preview.
  • GLM-5-Turbo registered as a real model and wired as the faster/explore sub-agent sibling for the GLM family: a GLM-5.2 parent routes faster/explore children to GLM-5-Turbo (direct Z.ai) and z-ai/glm-5-turbo (OpenRouter), instead of down to GLM-5.1. GLM-5.1 and GLM-5-Turbo themselves have no cheaper tier and keep children on the parent.
  • type: "explore" sub-agents default to model_strength: "faster". Bounded read-only lookup/search/status work now uses the cheaper same-family sibling automatically, unless an explicit model or model_strength: "same" is supplied. Non-explore roles keep the conservative same default.
  • GPT-5.5 / OpenAI Codex faster route stays on GPT-5.5 with reasoning resolved to low (the Codex Responses API has no true off, so the resolved effort is now honest low rather than off silently rewritten). No DeepSeek/GLM fallback is fabricated when no cheaper same-provider sibling exists. DeepSeek Pro→Flash routing and its no-thinking faster lane are unchanged.
  • Base prompt / delegate skill guidance updated to encourage parallel read-only exploration (2-4 type: "explore" sub-agents) for broad repo, version, branch, benchmark, and API-surface investigations, while keeping architecture, integration, and final verification in the parent. The delegate skill examples now use provider-neutral model_strength instead of hardcoded DeepSeek model ids.
  • Agent synthesis guardrails. The base constitution now frames tools around sufficient evidence rather than open-ended persistence: extra reads, searches, and delegation must target a missing fact, and agents should answer with limits instead of broadening searches indefinitely. The runtime loop guard now blocks duplicate read-only/delegated calls earlier and caps repeated broad lookup/delegation loops in a single turn with a synthesis-forcing tool error. Guard metadata distinguishes exact duplicates (identical_tool_call) from no-progress loops (no_progress_tool_loop).
  • Sub-agent handoff and visibility. Direct sub-agent completions are drained before the next parent model request, so finished children can wake the main model promptly instead of waiting for an empty-tool-use branch or idle engine path. Nested sub-agents now report completions to their immediate parent inbox; the main model still receives only direct-child completions, avoiding grandchild floods while preserving nested evidence flow. Sub-agent output guidance now requires child-agent provenance when a sub-agent relies on a child report: cite the child agent_id and the child's EVIDENCE line(s), and do not present child findings as directly verified facts. The sidebar orders sub-agents as a parent/child tree and annotates nested rows with parent and depth information in hover text.
  • Sub-agent summary provenance (#2652). A sub-agent's free-text result is now explicitly treated as an unverified self-report rather than confirmed evidence. The completion sentinel carries summary_kind: complete | truncated so the parent model can branch on whether it saw the full report or a clipped excerpt. Short summaries (≤ 12,000 chars) get a soft "re-verify material claims" suffix; longer ones are head+tail truncated with an honest marker stating the elided middle is not retrievable via retrieve_tool_result. Every summary therefore carries exactly one boundary marker, never both.
  • Provider metadata centralization. Provider env vars, config keys, aliases, and auth hints are now resolved through the shared ProviderMetadata registry across codewhale-config, codewhale-tui, and codewhale-cli, reducing drift between the provider picker, codewhale auth, doctor --json, and setup hints.

Added

  • Agent clarification questions (#3102). Agents now have a first-class request_user_input tool to ask the user structured clarifying questions through a modal UI surface instead of only emitting a chat message and hoping the user notices. Mirrors the approval/secret-request flow the harness already used for permissions. The tool accepts 1-3 questions, each with a header, an id, 2-4 selectable options (label + description), and allow_free_text / multi_select flags (both default to false for back-compat). Input is validated up front with actionable errors. Wired across all layers: the request_user_input tool, engine handling (turn_loop → approval), an interactive TUI modal (UserInputView) with full keyboard navigation, and the runtime protocol (EventFrame::UserInputRequest + AppRequest::SubmitUserInput) so headless / app-server clients can answer programmatically. Parity tests cover the wire round-trip and the omitted-flags default.
  • Transcript hyperlinks — out-of-band OSC 8 (#3029). Clickable file / file:line / URL links now reach the terminal through a column-drift-safe path. Link payloads are embedded in-band by the markdown renderer, then extracted out of the ratatui buffer cells and re-emitted out-of-band by ColorCompatBackend — so the ESC bytes never occupy display columns or corrupt selection. Supporting terminals get live hyperlinks; others see the label text unchanged. Clipboard/selection extraction strips residual codes as defense-in-depth.
  • CodeWhale-only skill discovery gate (#3296). New [skills].scan_codewhale_only = true limits session-time skill discovery to CodeWhale-owned roots (<workspace>/.codewhale/skills, ~/.codewhale/skills, and any explicit skills_dir) while ignoring cross-tool directories such as .claude/skills, .opencode/skills, .cursor/skills, and ~/.agents/skills. The default remains the broad compatibility scan.
  • Permission/ask runtime rules (#3295). Sibling permissions.toml ask-only rules are now loaded by the TUI engine and applied to exec_shell before Auto/session approval shortcuts. Matching ask rules force an approval prompt in otherwise auto-approved flows and are rejected under approval_mode = "never".
  • Runtime API no-auth documentation. docs/RUNTIME_API.md now documents codewhale app-server --insecure-no-auth for loopback-only testing and warns against combining it with --mobile on 0.0.0.0.

Fixed

  • TUI polish. The empty-startup welcome block is centered by the actual rendered text width, fixing the off-center layout left over from the old sidebar-oriented welcome composition. Streaming HTTP body read errors now explain whether CodeWhale can retry before output, or is surfacing a warning after partial output to avoid replaying and duplicating streamed text.
  • Config comment preservation. Rewriting config.toml, settings.toml, or tui.toml now merges user comments and formatting back into the serialized document; if comment merge fails, the write falls back to plain serialized output rather than failing.
  • Snapshot gate respected for per-tool snapshots (#3292). Per-tool snapshots now check [snapshots].enabled before writing, matching the existing session-level gate.
  • Poppler pdftotext detection (#1667). The dependency resolver now probes pdftotext -v instead of --version, because Poppler treats --version as an input filename. Fixes detection on systems where only Poppler is installed.
  • Plan confirmation checklist visibility. The Plan-mode confirmation modal now shows the active checklist under the plan details, so users can review the concrete checklist_write work breakdown before accepting or revising a plan.
