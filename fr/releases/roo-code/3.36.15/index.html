[3.36.15] - 2025-12-19

Version 3.36.15 - Prise en charge de la fenêtre contextuelle 1M

  • Ajout de la prise en charge bêta de 1 million de fenêtres contextuelles pour Claude Sonnet 4 sur Vertex AI, permettant ainsi un contexte beaucoup plus large pour les tâches complexes (PR #10209 par @hannesrudolph)
  • Ajout de la prise en charge native des appels d'outils pour les fournisseurs LM Studio et Qwen-Code, améliorant ainsi la compatibilité avec les modèles locaux (PR #10208 par @hannesrudolph)
  • Ajoutez des valeurs par défaut d'appel d'outil natif pour les fournisseurs compatibles OpenAI, étendant ainsi les appels de fonctions natives à davantage de configurations (PR #10213 par @hannesrudolph)
  • Activer les appels d'outils natifs pour le fournisseur Requesty (PR #10211 par @daniel-lxs)
  • Améliorez la gestion et la visibilité des erreurs API avec des messages d'erreur plus clairs et de meilleurs commentaires des utilisateurs (PR #10204 par @brunobergher)
  • Ajoutez des diagnostics d'erreur téléchargeables à partir des erreurs de chat, ce qui facilite le dépannage et le signalement des problèmes (PR #10188 par @brunobergher)
  • Correction du bouton d'actualisation des modèles qui ne vidait pas correctement le cache, garantissant ainsi la mise à jour correcte des listes de modèles (#9682 par @tl-hbk, PR #9870 par @pdecat)
  • Correction de la gestion des propriétés supplémentaires pour une compatibilité en mode strict, résolvant les problèmes de validation de schéma avec certains fournisseurs (PR #10210 par @daniel-lxs)

Anglais original / English original

Roo-Code v3.36.15

Highlights

  • 1M-token context beta — Claude Sonnet 4 on Vertex AI gains beta support for a 1M-token context window, enabling substantially larger repositories and longer tool-output histories in a single request. Treat this as opt-in beta functionality and watch for provider-side context and pricing limits (PR #10209).

  • Broader native tool-calling support — LM Studio and Qwen-Code now support native tool calls, improving function execution with local models instead of relying on text-based tool-call parsing. OpenAI-compatible providers gain native tool-call defaults, while Requesty enables them explicitly, reducing provider-specific setup across self-hosted and gateway deployments (PRs #10208, #10213, #10211).

  • More actionable failures — API errors now provide clearer messages and feedback, and chat errors can be downloaded as diagnostic attachments. This shortens troubleshooting by making failed model or tool requests easier to inspect and share in bug reports (PRs #10204, #10188).

  • Model refresh actually invalidates cached results — The refresh-models action now flushes the cache properly, so newly added or removed provider models should appear without stale list entries. This resolves the behavior reported in #9682 (PR #9870).

  • Strict-schema compatibility fix — Corrected additionalProperties handling for strict mode, addressing validation failures with providers that enforce JSON Schema constraints. If strict function schemas previously broke tool execution, retest those integrations after updating (PR #10210).

No breaking changes.

[3.36.15] - 2025-12-19

3.36.15 Release - 1M Context Window Support

  • Add 1M context window beta support for Claude Sonnet 4 on Vertex AI, enabling significantly larger context for complex tasks (PR #10209 by @hannesrudolph)
  • Add native tool calling support for LM Studio and Qwen-Code providers, improving compatibility with local models (PR #10208 by @hannesrudolph)
  • Add native tool call defaults for OpenAI-compatible providers, expanding native function calling across more configurations (PR #10213 by @hannesrudolph)
  • Enable native tool calls for Requesty provider (PR #10211 by @daniel-lxs)
  • Improve API error handling and visibility with clearer error messages and better user feedback (PR #10204 by @brunobergher)
  • Add downloadable error diagnostics from chat errors, making it easier to troubleshoot and report issues (PR #10188 by @brunobergher)
  • Fix refresh models button not properly flushing the cache, ensuring model lists update correctly (#9682 by @tl-hbk, PR #9870 by @pdecat)
  • Fix additionalProperties handling for strict mode compatibility, resolving schema validation issues with certain providers (PR #10210 by @daniel-lxs)
