Version 3.36.6 - Prise en charge des alias d'outils

  • Ajout de la prise en charge des alias d'outils pour la personnalisation des outils spécifiques au modèle, permettant aux utilisateurs de configurer la façon dont les outils sont présentés aux différents modèles d'IA (PR #9989 par @daniel-lxs)
  • Désinfectez les noms du serveur et des outils MCP pour la compatibilité API, en garantissant que les caractères spéciaux ne causent pas de problèmes avec les appels API (PR #10054 par @daniel-lxs)
  • Améliorer la visibilité du minuteur d'approbation automatique dans les suggestions de suivi pour une meilleure sensibilisation des utilisateurs aux actions en attente (PR #10048 par @brunobergher)
  • Correctif : Annuler le délai d'expiration de l'approbation automatique lorsque l'utilisateur commence à taper, empêchant ainsi les approbations automatiques accidentelles pendant l'interaction de l'utilisateur (PR #9937 par @roomote)
  • Ajoutez le type WorkspaceTaskVisibility pour les paramètres cloud de l'organisation afin de prendre en charge les contrôles de visibilité de l'équipe (PR #10020 par @roomote)
  • Correctif : Extrayez le message d'erreur brut des métadonnées OpenRouter pour un rapport d'erreurs plus clair (PR #10039 par @daniel-lxs)
  • Correctif : Afficher la liste déroulante des protocoles d'outils pour le fournisseur LiteLLM, restaurant l'option de configuration manquante (PR #10053 par @daniel-lxs)

Roo-Code v3.36.6

Highlights

  • Model-specific tool aliases — PR #9989 introduces tool alias support, letting you define per-model names/schemas for the same underlying tool. This matters because tool-call contracts (names, parameter shapes) vary across model providers; aliases let one tool definition serve multiple models without duplicating tool implementations or forking config. Watch for: aliases are presentation-layer only — verify your agent prompts and any tool-name assertions still match what the model actually emits.

  • MCP name sanitization — PR #10054 sanitizes MCP server and tool names before they go out on API calls. If your custom MCP servers or tools use special characters (spaces, punctuation, non-ASCII), previously these could produce malformed requests or silent failures; adopting 3.36.6 makes those names API-safe, but be aware that sanitization may transform names, so any code that keys off the original exact tool name should be checked.

  • Auto-approval safety changes — Two changes tighten the human-in-the-loop path: PR #9937 cancels the auto-approval timeout as soon as the user starts typing (preventing an action from auto-approving mid-interaction), and PR #10048 surfaces the countdown more clearly in follow-up suggestions. For developers, this means fewer accidental approvals during active sessions and better visibility into pending actions — but automation that relied on the timer firing unattended may now wait longer.

  • Cleaner diagnostics — PR #10039 extracts the raw error message from OpenRouter metadata instead of showing the wrapped/generic form. If you build on OpenRouter-backed models, expect more actionable error text in logs and UI, which should cut down on guesswork when debugging failed tool calls or provider errors.

  • LiteLLM and org visibility — PR #10053 restores the tool-protocol dropdown for LiteLLM, recovering a configuration option that had gone missing — important if you route through LiteLLM and need to pick the right tool-calling protocol. Separately, PR #10020 adds a WorkspaceTaskVisibility type for organization cloud settings, enabling team-level task visibility controls; adopters building on the cloud/team features will need to account for the new type in their settings models.

No breaking changes in this release.

  • Improve auto-approve timer visibility in follow-up suggestions for better user awareness of pending actions (PR #10048 by @brunobergher)
  • Fix: Cancel auto-approval timeout when user starts typing, preventing accidental auto-approvals during user interaction (PR #9937 by @roomote)
  • Add WorkspaceTaskVisibility type for organization cloud settings to support team visibility controls (PR #10020 by @roomote)
  • Fix: Extract raw error message from OpenRouter metadata for clearer error reporting (PR #10039 by @daniel-lxs)
  • Fix: Show tool protocol dropdown for LiteLLM provider, restoring missing configuration option (PR #10053 by @daniel-lxs)
