archify v2.12.0

Highlights

  • Verified, atomic diagram delivery — The most consequential change for anyone consuming Archify's output: PRs #25, #31, #37 and #39 add "stability gates" and atomic verified delivery, so the first diagram you receive is guaranteed complete rather than a half-rendered or untrustworthy frame. If you built workarounds for flaky first renders or partial exports, you can drop them — but expect failures to surface loudly now instead of silently shipping a broken diagram.

  • Bounded, safe auto-routing — PR #33, reinforced by #34, #41 and #43, reworks architecture auto-routing to be explicitly bounded, spreads shared automatic ports, and lets resolved routes be exported as share cards. The behavioral shift is from free-form to constrained, deterministic routing: diagrams that leaned on implicit shared-port behavior may lay out differently after the upgrade, so re-check any layout-critical saved diagrams.

  • Stricter relationship validation — PRs #35 and #42 reject ambiguous "relationship corridors" and enforce label clearance. This is a deliberate tightening: inputs that previously rendered but read ambiguously will now be refused or re-laid-out. If you generate diagrams from templates with dense or overlapping edges, audit them for new validation errors before rolling out.

  • Share cards and live style previews — PRs #38, #40 and #43 introduce copyable, share-ready diagram cards (including exported resolved routes), while #36 and #27 bring interactive demos and live visual-style switching to the docs. For adopters this is the lowest-friction way to evaluate styles without committing to config — no migration needed, just new surface area to try.

  • More resilient preview and Skill discovery — PR #45 adds a last-good live preview, #26 removes a WebM cleanup race, and #32 fixes portable Skill discovery metadata. If you run Archify as an agent Skill or depend on WebM output, these remove known flakiness: the preview now falls back to the last valid render instead of blanking, and the Skill should be discoverable across environments without manual path fixes.

No breaking changes.
