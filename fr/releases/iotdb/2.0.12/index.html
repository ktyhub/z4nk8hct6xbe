#iotdb v2.0.12

Fonctionnalités et améliorations

Prévention des injections SQL : Refactorisation du PreparedStatement du modèle de table pour empêcher l'injection SQL Gestion du cluster : Prise en charge du déploiement de cluster IPv6 REST : REST API prend en charge la définition du fuseau horaire client Synchronisation des données : Performances de filtrage optimisées pour les colonnes autres que les premières TAG dans le modèle de table Outils d'importation/exportation de données : Stratégie de dégradation pour les fichiers de chargement Gestion de base de données : SHOW CREATE DATABASE/TOPIC/PIPE Calcul - Exécution de requêtes - Clauses SQL : Optimisez le message d'erreur lorsqu'une requête select * comporte trop de colonnes Fonctions : Ajout de la fonction d'analyse temps-fréquence (FFT) Fonctions : Fonctions de filtrage ajoutées (HighPass, LowPass) Dernier cache de points : Le dernier cache de points prend en charge l'activation/la désactivation selon la granularité de la table/base de données. Fonctions : Fonctions d'agrégation taux/augmentation/irate/delta intégrées pour le modèle de table Fonctions : Ajout de la fonction de corrélation de séquence (XCorr) Fonctions : Fonction table M4 intégrée Fonctions : Fonction table de correspondance de tendance de série chronologique Fonctions : Ajout de la fonction table intégrée read_tsfile, prenant en charge les requêtes directes à partir d'un fichier ts spécifié à l'aide de SQL. Métadonnées du modèle d'arborescence : Lors de la création d'une nouvelle série temporelle sous un appareil existant, ignorez les attributs alignés/non alignés spécifiés dans l'instruction de création et utilisez les attributs alignés/non alignés de l'appareil actuel au lieu de signaler une erreur. Mesure : Optimisation du résultat de validation de la mesure lors des écritures du cache Suppression de granularité de l'appareil : Correction d'un problème où, après avoir supprimé une table contenant une grande quantité de données, puis recréé la table et écrit les données, l'interrogation de cette table avait une latence élevée. Optimisation de la mémoire : Optimisation de la mémoire lors de la copie de la TVList mémorisable lors des requêtes Pipe Data Sync : Optimisation de l'algorithme de correspondance pour ** Métadonnées du modèle d'arborescence : Ajout d'un indicateur booléen aux nœuds de périphérique indiquant s'il existe d'autres périphériques ci-dessous et réglage de la requête select measurement from xxx.** Clauses SQL : Optimisation des performances pour order by time + limit de table complète dans le modèle de table Clauses SQL : Optimisation de la mémoire pour les requêtes de table complète dans le modèle de table Pipe Data Sync : Optimisation de l'algorithme d'expansion/contraction du bloc de mémoire Pipe

Bogues

Fusion de fichiers en ligne : Correction d'un problème où show disk_usage provoquait le blocage de la fusion. Métadonnées du modèle d'arbre : Correction du problème « aucune base de données correspondante » Synchronisation des données : Prise en charge du stockage de la progression du point de contrôle de l'analyse TsFile, de sorte que lors d'une nouvelle tentative après un échec, il n'est pas nécessaire de réanalyser l'intégralité du fichier. Ecriture de base : Correction d'un problème où, pour le même périphérique aligné, l'écriture d'abord d'une requête avec moins de colonnes et plus de lignes, puis l'écriture d'une requête avec plus de colonnes et une ligne généraient un WAL qui, au redémarrage du DataNode, provoquait une grave expansion des valeurs nulles mémorisables et provoquait finalement le blocage du redémarrage du DataNode. TsFile Sync : Lors du chargement d'un fichier ts, modifiez la logique de comparaison des jeux de réplicas : lors de la comparaison des jeux de réplicas, ne vous souciez plus de l'ordre de la liste, comparez uniquement si les éléments des ensembles sont exactement identiques ; changer la comparaison de liste en une comparaison définie Pipe Data Sync : Correction d'un problème où Pipe lançait un NPE pour des points de mesure nuls lors de la conversion d'une écriture d'insertion partielle dans une tablette. Pipe Data Sync : Correction d'un problème où Pipe s'arrêtait après un délai d'attente d'analyse du fichier tsfile Fusion de fichiers en ligne : Correction d'un problème où la fusion ne revenait pas à la copie lors de l'échec de la création de liens physiques. Pipe Data Sync : Ajout de limites de quota de mémoire indépendantes par Pipe ou d'une planification équitable Pipe Data Sync : Implémentation d'un recul exponentiel et d'une protection par disjoncteur pour les scénarios dans lesquels le disque est plein ou le récepteur n'est pas disponible Pipe Data Sync : Ajout de limites globales et par Pipe sur les TsFiles en vol Pipe Data Sync : Correction d'un problème où drop pipe n'attendait pas le retour de l'évier Outils d'importation/exportation de données : Correction d'une erreur lors de l'exécution de tsfile load alors qu'une base de données nommée avec un préfixe root. existe déjà Métadonnées du modèle de tableau : Optimisation de la gestion des caractères spéciaux échappés avec des backticks dans les vues de tableau Pipe Data Sync : Lors de la suppression d'un Pipe, il existe des processus asynchrones (par exemple, récupération) ; le résultat de l'exécution asynchrone doit être communiqué à l'utilisateur Synchronisation des données du tuyau : Drop pipe n'attend plus le retour de l'évier, garantissant ainsi le retrait complet du tuyau Pipe Data Sync : Correction du décalage dans la partie assignateur lors de l'exécution des commandes Pipe create/start/stop/delete Pipe Data Sync : Correction du problème de journalisation excessive en réduisant la quantité de journaux du côté du récepteur Pipe. Pipe Data Sync : Correction d'un problème où le fractionnement d'un fichier ts dans 1.3.x pour synchroniser des données partielles avec 2.x échouait

iotdb v2.0.12

Features & Improvements

SQL Injection Prevention: Refactored the table model's PreparedStatement to prevent SQL injection Cluster Management: Support IPv6 cluster deployment REST: REST API supports setting the client timezone Data Sync: Optimized filtering performance for non-first TAG columns in the table model Data Import/Export Tools: Degradation strategy for Load files Database Management: SHOW CREATE DATABASE/TOPIC/PIPE Computation - Query Execution - SQL Clauses: Optimize the error message when a select * query has too many columns Functions: Added time-frequency analysis function (FFT) Functions: Added filtering functions (HighPass, LowPass) Latest Point Cache: The latest point cache supports being enabled/disabled at table/database granularity Functions: Built-in rate/increase/irate/delta aggregate functions for the table model Functions: Added sequence correlation function (XCorr) Functions: Built-in M4 table-valued function Functions: Time-series trend matching table-valued function Functions: Added the built-in table-valued function read_tsfile, supporting direct querying from a specified tsfile using SQL Tree Model Metadata: When creating a new time series under an existing device, ignore the aligned/unaligned attributes specified in the create statement and use the current device's aligned/unaligned attributes instead of reporting an error Measurement: Optimized the validation result of Measurement during cache writes Device-Granularity Deletion: Fixed an issue where, after deleting a table with a large amount of data and then re-creating the table and writing data, querying that table had high latency Memory Optimization: Memory optimization when copying the memtable TVList during queries Pipe Data Sync: Optimized the matching algorithm for ** Tree Model Metadata: Added a boolean flag to device nodes indicating whether there are other devices below, and tuned the query select measurement from xxx.** SQL Clauses: Performance optimization for full-table order by time + limit in the table model SQL Clauses: Memory optimization for full-table queries in the table model Pipe Data Sync: Optimized the Pipe memory block expansion/contraction algorithm

Bugs

Online File Merge: Fixed an issue where show disk_usage caused the merge to hang Tree Model Metadata: Fixed the "no matched database" issue Data Sync: Support storing TsFile parsing checkpoint progress, so that on retry after failure there is no need to re-parse the entire file Basic Write: Fixed an issue where, for the same aligned device, first writing a request with fewer columns and more rows and then writing a request with more columns and one row generated a WAL that, upon restarting the DataNode, caused severe memtable null-value expansion and ultimately caused the DataNode restart to hang TsFile Sync: When loading a tsfile, modify the replica set comparison logic: when comparing replica sets, no longer care about list order, only compare whether the elements within the sets are exactly identical; change the list comparison to a set comparison Pipe Data Sync: Fixed an issue where Pipe threw an NPE for null measurement points when converting a partial insert write into a tablet Pipe Data Sync: Fixed an issue where Pipe stopped after a tsfile parsing timeout Online File Merge: Fixed an issue where the merge did not fall back to copying when creating hard links failed Pipe Data Sync: Added per-Pipe independent memory quota limits or fair scheduling Pipe Data Sync: Implemented exponential backoff and circuit breaker protection for scenarios where the disk is full or the receiver is unavailable Pipe Data Sync: Added global and per-Pipe limits on in-flight TsFiles Pipe Data Sync: Fixed an issue where drop pipe did not wait for the sink's return Data Import/Export Tools: Fixed an error when executing tsfile load while a database named with a root. prefix already exists Table Model Metadata: Optimized the handling of special characters escaped with backticks in table views Pipe Data Sync: When deleting a Pipe there are asynchronous processes (e.g., recover); the asynchronous execution result needs to be communicated to the user Pipe Data Sync: Drop pipe no longer waits for the sink's return, ensuring complete removal of the Pipe Pipe Data Sync: Fixed the lag in the assigner portion when executing Pipe create/start/stop/delete commands Pipe Data Sync: Fixed the excessive logging issue by reducing the amount of logs on the Pipe receiver side Pipe Data Sync: Fixed an issue where splitting a tsfile in 1.3.x to sync partial data to 2.x failed
