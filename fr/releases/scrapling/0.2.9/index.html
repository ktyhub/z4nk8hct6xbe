Scrapling v0.2.9

Qu'est-ce qui a changé

Nouvelles fonctionnalités

  1. Présentation du support asynchrone très attendu pour Scrapling ! Vous disposez désormais de la version de classe AsyncFetcher de Fetcher, et StealthyFetcher et PlayWrightFetcher ont une nouvelle méthode appelée async_fetch avec les mêmes options.
>> from scrapling import StealthyFetcher
>> page = await StealthyFetcher().async_fetch('https://www.browserscan.net/bot-detection')  # the async version of fetch
>> page.status == 200
True
  1. Désormais, la classe StealthyFetcher a l'argument geoip dans ses méthodes de récupération qui, lorsqu'il est activé, fait que la classe utilise automatiquement la longitude, la latitude, le fuseau horaire, le pays et les paramètres régionaux de l'IP, puis usurpe l'adresse IP WebRTC. Il calculera et usurpera également la langue du navigateur en fonction de la répartition des locuteurs de la langue dans la région cible.
  2. Ajout de l'argument retries aux classes Fetcher/AsyncFetcher afin que vous puissiez désormais définir le nombre de tentatives de chaque requête effectuée par httpx.
  3. Ajout de la méthode url_join à Adaptor et Fetchers qui prend une URL relative et la joint à l'URL actuelle pour générer une URL complète absolue !
  4. Ajout de la méthode keep_cdata à Adaptor et Fetchers pour empêcher l'analyseur de supprimer les cdata en cas de besoin.
  5. Désormais, la méthode Adaptor/Response body renvoie la réponse HTML brute lorsque cela est possible (sans la traiter dans la bibliothèque).
  6. Ajout de la journalisation pour la classe Response. Ainsi, lorsque vous utilisez les récupérateurs, vous obtiendrez un journal donnant des informations sur la réponse que vous avez obtenue. Exemple : 
    >> from scrapling.defaults import Fetcher>> Fetcher.get('https://books.toscrape.com/index.html')[2024-12-16 13:33:36] INFO: Fetched (200) <GET https://books.toscrape.com/index.html> (referer: https://www.google.com/search?q=toscrape)>>
  7. Désormais, l'utilisation de toutes les méthodes de chaîne standard sur un TextHandler comme .replace() entraînera un autre TextHandler. Avant, il renvoyait la chaîne standard.
  8. De grandes améliorations de la vitesse dans la bibliothèque et des améliorations de la furtivité dans les classes Fetchers en général.
  9. Ajout de fonctions factices comme extract_first`extract` qui renvoie le même résultat que le parent. Ces fonctions sont ajoutées uniquement pour faciliter la copie du code de Scrapy/Parsel vers Scrapling en cas de besoin, car ces fonctions y sont utilisées !
  10. En raison de la refactorisation d'une grande partie du code et de l'utilisation de la mise en cache aux bonnes positions, l'exécution de requêtes en masse entraînera désormais une forte augmentation de la vitesse.

Modifications cassantes

  • Désormais, la prise en charge de Python 3.8 a été supprimée. (Principalement parce que Playwright a arrêté de le prendre en charge mais c'était de toute façon une version problématique)
  • L'argument debug a été supprimé de toute la bibliothèque, maintenant si vous souhaitez définir la bibliothèque en débogage, faites ceci après avoir importé la bibliothèque : 
    >>> import logging>>> logging.getLogger("scrapling").setLevel(logging.DEBUG)

Bugs éliminés

  1. Désormais, WebGL est activé par défaut car de nombreuses protections vérifient s'il est activé maintenant.
  2. Quelques erreurs et fautes de frappe dans la documentation/README.

Changements dans la qualité de vie

  1. Tous les enregistrements sont désormais unifiés sous le nom d'enregistreur scrapling pour un contrôle plus facile et plus propre. Nous utilisions auparavant l'enregistreur racine.
  2. Restructuration du dossier tests dans une structure plus propre et ajout de tests pour les nouvelles fonctionnalités. Tous les tests ont été réécrits dans une version plus propre et davantage de tests ont été ajoutés pour une couverture plus élevée.
  3. Refactorisation d'une grande partie du code pour qu'il soit plus propre et plus facile à maintenir.

Tous ces changements faisaient partie des changements que j'avais décidé auparavant d'ajouter avec 0.3 mais j'ai décidé de les ajouter ici car il faudra un certain temps avant la prochaine version. La prochaine étape consiste maintenant à terminer le site de documentation détaillée puis à travailler sur la version 0.3.

[!NOTE] Un rappel amical que maintenir et améliorer Scrapling demande beaucoup de temps et d'efforts, ce que je fais avec plaisir depuis des mois même si cela devient de plus en plus difficile. Donc, si vous aimez Scrapling et souhaitez qu'il continue de s'améliorer, vous pouvez m'aider en me soutenant via le [Bouton Parrainer] (https://github.com/sponsors/D4Vinci).

Scrapling v0.2.9

Highlights

  • First-class async API — v0.2.9 introduces AsyncFetcher as the async counterpart to Fetcher, plus async_fetch on both StealthyFetcher and PlayWrightFetcher with option parity to their sync fetch methods. This is the headline capability: you can now run Scrapling inside asyncio crawlers without blocking on Playwright/stealth sessions, and for most code the migration is simply fetch → await fetch.

  • Two breaking changes to plan for — Python 3.8 support is dropped (largely because Playwright upstream ended it), and the debug argument is removed library-wide; to enable debugging you must now call logging.getLogger("scrapling").setLevel(logging.DEBUG) after import. Audit your runtime environments and strip any debug=True fetch calls before upgrading.

  • geoip stealth mode — StealthyFetcher gains a geoip flag that derives longitude, latitude, timezone, country and locale from the request IP, spoofs the WebRTC IP address, and selects a browser language from the target region's speaker distribution. Paired with WebGL now being enabled by default (many bot-detection scripts probe for it), this raises the anti-bot bar — but since locality is inferred from the exit IP, your proxy choice directly determines the spoofed identity.

  • Unified logging and per-response logs — all logging now flows through a single scrapling logger instead of the root logger, and Response/Fetchers emit an INFO line per fetch (status, method, URL, referer). You get out-of-the-box request visibility and can silence, route, or set levels with one logger config rather than fiddling with root handlers.

  • Parser and Adaptor API additions — new url_join resolves a relative URL against the current page into a full absolute URL, keep_cdata stops the parser from stripping CDATA, and body now returns raw unprocessed HTML when available. TextHandler string operations such as .replace() now return another TextHandler rather than a plain str, preserving the fluent chain; Scrapy/Parsel-style extract/extract_first shims were also added to make porting external code less painful.

  • Throughput-focused refactor — Fetcher/AsyncFetcher gain a retries argument for per-request httpx retries, while internal refactoring with caching at key points (plus general speed and stealth work) makes bulk requests substantially faster. Large-batch scrapers should see measurable gains with no code changes required.

What's changed

New features

  1. Introducing the long-awaited async support for Scrapling! Now you have the AsyncFetcher class version of Fetcher, and both StealthyFetcher and PlayWrightFetcher have a new method called async_fetch with the same options.
>> from scrapling import StealthyFetcher
>> page = await StealthyFetcher().async_fetch('https://www.browserscan.net/bot-detection')  # the async version of fetch
>> page.status == 200
True

  1. Now the StealthyFetcher class has the geoip argument in its fetch methods which when enabled makes the class automatically use IP's longitude, latitude, timezone, country, and locale, then spoof the WebRTC IP address. It will also calculate and spoof the browser's language based on the distribution of language speakers in the target region.

  2. Added the retries argument to Fetcher/AsyncFetcher classes so now you can set the number of retries of each request done by httpx.

  3. Added the url_join method to Adaptor and Fetchers which takes a relative URL and joins it with the current URL to generate an absolute full URL!

  4. Added the keep_cdata method to Adaptor and Fetchers to stop the parser from removing cdata when needed.

  5. Now Adaptor/Response body method returns the raw HTML response when possible (without processing it in the library).

  6. Adding logging for the Response class so now when you use the Fetchers you will get a log that gives info about the response you got. Example:

    >> from scrapling.defaults import Fetcher
>> Fetcher.get('https://books.toscrape.com/index.html')
[2024-12-16 13:33:36] INFO: Fetched (200) <GET https://books.toscrape.com/index.html> (referer: https://www.google.com/search?q=toscrape)
>>

  7. Now using all standard string methods on a TextHandler like .replace() will result in another TextHandler. It was returning the standard string before.

  8. Big improvements to speed across the library and improvements to stealth in Fetchers classes overall.

  9. Added dummy functions like extract_first`extract` which returns the same result as the parent. These functions are added only to make it easy to copy code from Scrapy/Parsel to Scrapling when needed as these functions are used there!

  10. Due to refactoring a lot of the code and using caching at the right positions, now doing requests in bulk will have a big speed increase.

Breaking changes

  • Now the support for Python 3.8 has been dropped. (Mainly because Playwright stopped supporting it but it was a problematic version anyway)

  • The debug argument has been removed from all the library, now if you want to set the library to debugging, do this after importing the library:

    >>> import logging
>>> logging.getLogger("scrapling").setLevel(logging.DEBUG)

Bugs Squashed

  1. Now WebGL is enabled by default as a lot of protections are checking if it's enabled now.
  2. Some mistakes and typos in the docs/README.

Quality of life changes

  1. All logging is now unified under the logger name scrapling for easier and cleaner control. We were using the root logger before.
  2. Restructured the tests folder into a cleaner structure and added tests for the new features. All the tests were rewritten to a cleaner version and more tests were added for higher coverage.
  3. Refactored a big part of the code to be cleaner and easier to maintain.

All these changes were part of the changes I decided before to add with 0.3 but decided to add them here because it will be some time till the next version. Now the next step is to finish the detailed documentation website and then work on version 0.3

[!NOTE] A friendly reminder that maintaining and improving Scrapling takes a lot of time and effort which I have been happily doing for months even though it's becoming harder. So, if you like Scrapling and want it to keep improving, you can help by supporting me through the Sponsor button.
