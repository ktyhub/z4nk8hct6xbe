Scrapling v0.5

Scrapling v0.5 met à niveau presque tout : récupération, analyse, araignées, automatisation du navigateur, outils d'IA et documents en dix langues 🚀

[!NOTE] Suivez-nous sur X pour des trucs et astuces quotidiens

[!AVERTISSEMENT] Cette version introduit de nombreuses modifications majeures qui ne conviennent pas ici. Consultez le Guide de migration vers v0.5 avant de mettre à jour.

🚀 Nouveautés et changements dans la qualité de vie

  • Un serveur MCP beaucoup plus performant pour les agents IA qui peuvent résoudre presque tous les CAPTCHA (Consultez la docs) :

    • Flux de travail complets du navigateur : remplissez des formulaires, click, survolez, faites défiler, utilisez le clavier, gérez les boîtes de dialogue et attendez les résultats dans une séquence ordonnée. Prend en charge différents types de champs et des interactions plus lentes, les actions s'arrêtant à la première erreur.
    • Lisez et recherchez la page actuelle sans la recharger : extrayez le HTML, le Markdown ou le texte d'une page entière ou d'un élément. Les instantanés de page consultables affichent les rôles, les noms et les positions des éléments, avec des vues ciblées qui conservent le contexte environnant.
    • Exécutez un JavaScript personnalisé et prenez des captures d'écran ciblées : exécutez des scripts, y compris un travail asynchrone, avec accès au propre JavaScript de la page. Capturez des éléments individuels, la fenêtre d'affichage ou la page entière au format PNG ou JPEG.
    • Inspecter l'activité réseau et réutiliser les connexions : examinez les demandes et les réponses enregistrées, enregistrez et restaurez l'état de connexion du navigateur et interagissez avec les éléments du Shadow DOM ouvert ou fermé. Lisez le trafic enregistré avant de fermer la session.
    • Utilisez moins de jetons et obtenez des erreurs plus claires : des descriptions d'outils plus simples et des conseils partagés réduisent le texte répété, tandis que les échecs du navigateur et des requêtes parviennent aux agents avec des messages d'erreur utiles.

  • Voir les demandes derrière la page. Activez record_requests=True pour enregistrer le trafic terminé à travers les charges, les actions et les onglets, puis inspectez les réponses enregistrées sans envoyer à nouveau de requêtes. (Consultez les docs)

    from scrapling.fetchers import StealthySession

with StealthySession(record_requests=True) as session:
    session.fetch("https://example.com", network_idle=True)
    for response in session.network.search(url_pattern=r"/api/", limit=None):
        print(response.url, response.status, response.body)
    • Filtrer par URL, méthode, type de ressource ou statut ; récupérer une réponse par ID. Inspectez les en-têtes, les données envoyées, les réponses API, les erreurs HTTP et les redirections via le Response API habituel.
    • Conserve les corps de texte pris en charge avec des limites de taille, ainsi que les métadonnées et une raison pour laquelle un corps ne peut pas être enregistré. La limite par défaut est de 1 000 requêtes. Fonctionne avec les sessions synchronisées et asynchrones ; L'historique Python enregistré reste lisible après la fermeture.

  • Enregistrez une connexion une fois et réutilisez-la au fil des exécutions. save_state(path) et load_state(path) enregistrent les cookies, le stockage local et IndexedDB dans JSON compatible Playwright. Les sessions de navigateur synchronisées et asynchrones les prennent en charge. (Consultez les docs)

    • Charger l'état avant de récupérer ou de recharger une page. Nécessite un contexte de navigateur partagé et démarré sans proxy_rotator ; les onglets, les paramètres du navigateur et sessionStorage ne sont pas enregistrés.

  • Extrayez le Shadow DOM ouvert avec pierce_shadow=True, puis utilisez CSS ou XPath comme d'habitude. Disponible dans les récupérateurs de navigateur, les sessions et l'option --pierce-shadow du CLI. Préserve le contenu des machines à sous sans modifier la page en direct. La capture HTML exclut les racines fermées et les documents iframe. (Consultez les docs)

  • Choisissez la façon dont votre araignée explore un site. CrawlSpider et ses sous-classes, y compris ContentSpider, prennent en charge crawl_strategy="bfs" pour la planification la plus ancienne en premier ou "dfs" pour la planification la plus récente en premier. La priorité l'emporte toujours et les pages simultanées peuvent se terminer dans un ordre différent. (Consultez les docs)

Scrapling v0.5

Highlights

  • Breaking changes — budget a migration pass before bumping — v0.5 deliberately ships a large set of breaking changes across fetching, parsing, spiders, and browser automation that the changelog explicitly says "don't fit here." Treat this as a major-version upgrade, not a drop-in patch: read the Migrating to v0.5 guide first and plan to re-run your integration suite rather than trusting old call signatures.

  • MCP server becomes an agent-first browser stack — The MCP server is no longer a thin scraping wrapper: it adds ordered browser workflows (fill/click/hover/scroll/keyboard/dialogs with fail-fast on the first error), accessibility-style page snapshots with roles/names/positions, custom async JavaScript execution against the page's own context, element/viewport/full-page screenshots, recorded request/response inspection, and save/restore of login state. The net effect for adopters is that Scrapling can now serve as the automation backend for an AI agent that solves CAPTCHAs and drives multi-step flows, with leaner tool descriptions and clearer error messages to cut token spend.

  • Network history and reusable login state — StealthySession(record_requests=True) records traffic across loads/actions/tabs and exposes it via session.network.search(url_pattern=..., limit=None), so you can inspect API responses, headers, redirects, and HTTP errors without re-sending requests (default cap 1,000 requests, sync + async, history still readable after close). Pair that with save_state(path)/load_state(path) for Playwright-compatible JSON covering cookies, localStorage, and IndexedDB. Watch the constraints: state loading needs a started, shared browser context without proxy_rotator, and tabs, browser settings, and sessionStorage are not persisted — so proxy-rotating setups can't use this shortcut.

  • Open Shadow DOM piercing — pierce_shadow=True (plus CLI --pierce-shadow) lets the same CSS/XPath selectors traverse open shadow roots in browser fetchers and sessions, preserving slot content without mutating the live page. This removes a long-standing blind spot for modern component-based sites, but note the boundary: closed roots and iframe documents are excluded from HTML capture, so traversal is not truly universal.

  • Explicit crawl-order control for spiders — CrawlSpider and subclasses like ContentSpider now accept crawl_strategy="bfs" (oldest-first) or "dfs" (newest-first), giving you a knob over discovery order that previously had to be approximated with priorities. Priority still wins and concurrent pages can finish out of order, so don't treat this as a strict sequencing guarantee — but it does let you tune breadth vs. depth for politeness, deduplication, and how quickly you reach deep content.

  • Correctness fixes that change request identity and cache behavior — A cluster of fingerprint fixes (query params #448, empty/falsy JSON bodies #480, header insertion order #466) plus prevention of request-body/header leakage into followed links (#462) alters what counts as the "same" request, which can shift deduplication and cache keys after upgrade. Caching is also hardened: blocked responses are no longer stored as successful dev-cache entries (#446) and failed robots.txt lookups aren't cached as crawl permission (#443); checkpoint files survive crawl exceptions (#486). Revalidate any caches, allowlists, or cached crawl permissions produced by v0.4 rather than carrying them forward blindly.

Scrapling v0.5 upgrades almost everything: fetching, parsing, spiders, browser automation, AI tools, and docs in ten languages 🚀

🚀 New Stuff and quality of life changes

  • A much more capable MCP server for AI agents that can solve almost any CAPTCHA (Check the docs):

    • Complete browser workflows: fill forms, click, hover, scroll, use the keyboard, handle dialogs, and wait for results in one ordered sequence. Supports different field types and slower interactions, with actions stopping at the first error.
    • Read and search the current page without reloading it: extract HTML, Markdown, or text from a whole page or one element. Searchable page snapshots show element roles, names, and positions, with focused views that retain the surrounding context.
    • Run custom JavaScript and take focused screenshots: execute scripts, including async work, with access to the page's own JavaScript. Capture individual elements, the viewport, or the full page as PNG or JPEG.
    • Inspect network activity and reuse logins: examine recorded requests and responses, save and restore browser login state, and interact with elements inside open or closed Shadow DOM. Read recorded traffic before closing the session.
    • Use fewer tokens and get clearer errors: leaner tool descriptions and shared guidance reduce repeated text, while browser and request failures reach agents with useful error messages.

  • See the requests behind the page. Enable record_requests=True to record completed traffic across loads, actions, and tabs, then inspect saved responses without sending requests again. (Check the docs)

    from scrapling.fetchers import StealthySession

with StealthySession(record_requests=True) as session:
    session.fetch("https://example.com", network_idle=True)
    for response in session.network.search(url_pattern=r"/api/", limit=None):
        print(response.url, response.status, response.body)
    • Filter by URL, method, resource type, or status; retrieve one response by ID. Inspect headers, sent data, API responses, HTTP errors, and redirects through the usual Response API.
    • Retains supported text bodies with size limits, plus metadata and a reason when a body cannot be saved. The default limit is 1,000 requests. Works with sync and async sessions; saved Python history stays readable after close.

  • Save a login once and reuse it across runs. save_state(path) and load_state(path) save cookies, local storage, and IndexedDB in Playwright-compatible JSON. Both sync and async browser sessions support them. (Check the docs)

    • Load state before fetching or reloading a page. Requires a started, shared browser context without proxy_rotator; tabs, browser settings, and sessionStorage are not saved.

  • Extract open Shadow DOM with pierce_shadow=True, then use CSS or XPath as usual. Available in browser fetchers, sessions, and the CLI's --pierce-shadow option. Preserves slot content without changing the live page. HTML capture excludes closed roots and iframe documents. (Check the docs)

  • Choose how your spider explores a site. CrawlSpider and its subclasses, including ContentSpider, support crawl_strategy="bfs" for oldest-first or "dfs" for newest-first scheduling. Priority still wins, and concurrent pages can finish in a different order. (Check the docs)
