Scrapling v0.4.3

Une nouvelle mise à jour avec de nombreux changements importants 🎉

🚀 Nouveautés et changements dans la qualité de vie

  • Ajout d'un nouvel outil MCP pour ouvrir un navigateur persistant normal/furtif afin de continuer à l'utiliser avec le reste des outils, et un autre nouvel outil pour le fermer. (Exemples)
  • Ajout d'un nouvel outil MCP pour répertorier toutes les sessions de navigateur existantes. Destiné à être utilisé avec les nouveaux outils.
  • Ajout d'une nouvelle option aux sessions du navigateur pour collecter automatiquement toutes les requêtes en arrière-plan qui se produisent lors d'une requête (Résout #159) [Exemples].
  • Ajout d'un nouveau désinfectant pour protéger le serveur MCP des attaques courantes par injection d'invite en supprimant le contenu caché/invisible.
  • Ajout d'une nouvelle option de ligne de commande appelée --ai-targeted aux commandes Web Scraping pour rendre le contenu ciblé sur l'IA et sécurisé contre les attaques par injection d'invite courantes comme le serveur MCP.
  • Ajout d'une nouvelle option aux sessions de navigateur appelée executable_path pour permettre de définir un chemin de navigateur personnalisé (Résout #202)
  • Refactorisé le code du serveur MCP pour qu'il soit facilement maintenu et unifié tous les outils pour qu'ils soient asynchrones.
  • Refactorisé le code des commandes CLI pour qu'il soit facilement maintenu et plus court de 210 lignes.

Scrapling v0.4.3

Highlights

  • Persistent MCP browser sessions — Open, list, and close long-lived normal or stealthy browsers, allowing multi-step scraping workflows to reuse browser state across tool calls. The new executable_path option also supports custom browser installations in CI or containers (#202).

  • Background request capture — Browser sessions can automatically collect XHR/fetch and other background traffic generated during a request (#159). This makes it easier to inspect API calls behind dynamic pages, rather than relying only on rendered DOM content.

  • AI-targeted content hardening — MCP sanitization removes hidden or invisible content to reduce prompt-injection exposure, while the CLI’s new --ai-targeted flag applies comparable protection to scraped output. Expect targeted output to omit concealed text; the bundled agent skill now requires this flag for command-line scraping.

  • Async-only MCP tools — All MCP tools have been unified as async. Custom wrappers and integrations should await tool results rather than assuming synchronous execution, though the refactor does not introduce new MCP capabilities by itself.

  • More reliable spider retries and recovery — HTTP methods now survive retries (#201), page-content retrieval has a maximum retry limit to prevent infinite loops (#197), and checkpoint restoration returns False instead of triggering a bare-raise error (#196). Together, these changes reduce hung jobs and incorrect retry behavior.

  • Texthandler compatibility change — get_all was replaced with getall to match the Selector API. Update any code calling the old method; this rename is the main compatibility item to check before upgrading.

A new update with many important changes 🎉

🚀 New Stuff and quality of life changes

  • Added a new MCP tool to open a persistent normal/stealthy browser to keep using it with the rest of the tools, and another new tool to close it. (Examples)
  • Added a new MCP tool to list all existing browser sessions. Aimed to be used with the new tools.
  • Added a new option to browser sessions to automatically collect all background requests that happen during a request (Solves #159) [Examples].
  • Added a new sanitizer to protect the MCP server from common Prompt Injection attacks by removing hidden/invisible content.
  • Added a new commandline option called --ai-targeted to the Web Scraping commands to make content targeted to AI and safe against common Prompt Injection attacks like the MCP server.
  • Added a new option to browser sessions called executable_path to allow setting a custom browser path (Solves #202)
  • Refactored the MCP server code to be easily maintained and unified all tools to be async.
  • Refactored the CLI commands code to be easily maintained and shorter by 210 lines.

🐛 Bug Fixes

  • A fix to preserve HTTP method across retries in spider session by @karesansui-u in #201
  • Added a max retry limit to getting page content to prevent infinite loop by @haosenwang1018 & @D4Vinci in #197
  • Replace bare raise with return False in _restore_from_checkpoint by @haosenwang1018 in #196
  • Replaced get_all with getall in Texthandler to match the Selector class.

Coverage/tests improvement

  • Added _normalize_credentials edge case coverage tests by @Bortlesboat in #192
  • Added save/retrieve round-trip and core storage coverage tests by @haosenwang1018 in #193
  • Added coverage for TextHandler regex paths and TextHandlers.re() by @haosenwang1018 in #194
  • Added edge case tests for filter, iterancestors, and find_similar by @awanawana in #200

Agent Skill improvement

  • Fixed broken markdown links in skill references by @yetval in #204
  • Improved the skill structure to be more acceptable by Clawhub validation.
  • Forced the skill to use the --ai-targeted commandline option when scraping through commandline commands.

Docs improvement

  • Added Korean README translation by @greatsk55 in #187
  • CJK Latin spacing fixes for the Chinese and Japanese READMEs.
  • Fixed broken links from the old website design.
