DeepSpeed v0.19.7

Highlights

  • Breaking removals — Sparse attention, Nebula checkpointing, deepspeed.compression, 1-bit Adam/Lamb, 0/1 Adam, and MiCS ZeRO-3 are removed. sparse_attention, Nebula, compression, and MiCS config keys now raise errors, so migrate these workloads before upgrading (#8490, #8493). Also update LR-range-test scripts: --lr_range_test_staircase is now presence-only; pass the bare flag to enable it, not True or False (#8337).
  • Muon finally honors optimizer settings — Caller parameter groups retain their LR and weight decay when split into Muon and Adam branches (#8440); Newton–Schulz now runs at default ZeRO stage 0 instead of silently reducing Muon to SGD (#8442); and zero.Init with ZeRO-3 correctly identifies matrix parameters rather than leaving all weights on AdamW (#8438). Expect different update trajectories and additional stage-0 compute in existing Muon jobs.
  • AutoEP gains opt-in fast paths — DEEPSPEED_AUTOEP_COMM_BACKEND=deepep selects DeepEP v2 while NCCL remains the default; the upstream benchmark reports a 1.22× end-to-end speedup on 16 H100s (#8213). DeepEP v2 and NCCL ≥2.30.4 are required, and folded tensor parallelism falls back to NCCL. The separate combine_impl="fused_weighted_sum" path reduces intermediate memory but remains experimental, without a statistically conclusive end-to-end win (#8326).
  • ZeRO checkpoint portability improves — zero_to_torch.py --dtype and convert_zero_checkpoint_to_state_dict(...) support FP32/FP16/BF16 export while preserving shared aliases; existing FP32 conversion remains compatible (#8318). Lower precision reduces artifact size and shard-planning requirements but introduces rounding. Universal-checkpoint resume across different AutoTP sizes is also repaired (#8474).
  • Compiled and distributed execution gets correctness fixes — AutoTP collectives no longer silently disappear when activation checkpointing is enabled under DeepCompile (#8355), and _DimZeroAllToAll now propagates backward gradients under torch.compile (#8491). Ulysses also fixes seq-first all-to-all output layout (#8317) and tracks KV-head count per DistributedAttention instance (#8316). Re-check loss and gradient parity when enabling these paths after upgrading.
  • Continuous batching arrives experimentally — Setting SamplingConfig.continuous_batch_size=N lets rollout retire requests independently and refill KV-cache rows while preserving output order (#8368); prefill/decode and continuous-batching profiling were also added (#8350, #8494). Default generation is unchanged, but the new path currently requires Transformers cache-class support, equal-width prompts, greedy single-sample decoding, and single-device validation.
