🚀 Quoi de neuf dans v1.14.1 ?

v1.14.1 est une version de correctif axée sur le renforcement de la sécurité, la stabilité du flux de travail et de la base de connaissances, le nettoyage du déploiement et la migration continue de la plate-forme d'interface utilisateur après v1.14.0.

🔐 Sécurité

  • Durcissement SECRET_KEY auto-hébergé — Les déploiements Docker ne reposent plus sur une clé publique par défaut. Lorsque SECRET_KEY est laissé vide, le API génère et conserve une clé d'exécution via le backend de stockage configuré, tandis que les clés explicitement configurées continuent de fonctionner comme avant. Merci @laipz8200 dans #36049.
  • Protection interne des points de terminaison des métriques — /threads et /db-pool-stat sont renforcés pour éviter toute exposition non authentifiée des détails du runtime interne et du pool de bases de données. Merci @orbisai0security dans #35665.
  • Isolement des comptes et des outils — correction d'un problème d'IDOR dans GET /account/avatar et étendue du nettoyage des informations d'identification par défaut de l'outil intégré au locataire actuel. Merci @NeatGuyCoding et @GareArc dans #35771 et #35887.
  • Sécurité des dépendances — LiteLLM mis à niveau pour CVE-2026-42208 et actualisé plusieurs dépendances backend, notamment urllib3, gunicorn, gitpython, mako, les packages Google SDK, les bibliothèques de stockage et les packages d'exportateur OpenTelemetry. Merci @crazywoola dans #35953, #35779, #35791, #35863, #35864, #35958, #36011, #36012, #36013, #36017 et #36050.

Guide de mise à niveau

Remarques importantes

  • Cette version inclut une nouvelle migration de base de données pour les catégories d'applications Explore configurables. Exécutez les migrations de bases de données dans le cadre de la mise à niveau.
  • Les variables d'environnement Docker Compose sont désormais divisées en fichiers catégorisés sous docker/envs/**. Si vous conservez un docker-compose.yaml ou un .env personnalisé, examinez la nouvelle disposition et réappliquez soigneusement les personnalisations locales.
  • Pour les déploiements auto-hébergés, les valeurs SECRET_KEY explicitement configurées continuent d'être respectées. Si SECRET_KEY est vide, Dify génère et conserve désormais automatiquement une clé d'exécution.

Déploiements de composition Docker

  1. Sauvegardez vos fichiers docker-compose YAML et env personnalisés.

    cd docker
cp docker-compose.yaml docker-compose.yaml.$(date +%s).bak
cp .env .env.$(date +%s).bak 2>/dev/null || true

  2. Obtenez le dernier code de la branche ou de la balise de publication.

    git fetch --tags
git checkout 1.14.1

  3. Arrêtez le service. Veuillez exécuter dans le répertoire docker.

    docker compose down

  4. Sauvegardez les données.

    tar -cvf volumes-$(date +%s).tgz volumes

  5. Vérifiez la nouvelle présentation du fichier d'environnement docker/envs/** et réappliquez toutes les personnalisations locales.

  6. Services de mise à niveau.

    docker compose up -d

Déploiements de code source

  1. Arrêtez le serveur API, le Worker et le serveur Web frontal.

  2. Obtenez le dernier code de la balise de version.

    git fetch --tags
git checkout 1.14.1

  3. Mettez à jour les dépendances de Python.

    cd api
uv sync

  4. Exécutez le script de migration.

    uv run flask db upgrade

  5. Redémarrez le serveur API, le Worker et le serveur Web frontal.

🚀 What's New in v1.14.1?

v1.14.1 is a patch release focused on security hardening, workflow and knowledge-base stability, deployment cleanup, and continued UI platform migration after v1.14.0.

🔐 Security

  • Self-hosted SECRET_KEY hardening — Docker deployments no longer rely on a public default key. When SECRET_KEY is left empty, the API generates and persists a runtime key through the configured storage backend, while explicitly configured keys continue to work as before. Thanks @laipz8200 in #36049.
  • Internal metrics endpoint protection — /threads and /db-pool-stat are hardened to avoid unauthenticated exposure of internal runtime and database-pool details. Thanks @orbisai0security in #35665.
  • Account and tool isolation — fixed an IDOR issue in GET /account/avatar and scoped builtin-tool default-credential cleanup to the current tenant. Thanks @NeatGuyCoding and @GareArc in #35771 and #35887.
  • Dependency security — upgraded LiteLLM for CVE-2026-42208 and refreshed several backend dependencies, including urllib3, gunicorn, gitpython, mako, Google SDK packages, storage libraries, and OpenTelemetry exporter packages. Thanks @crazywoola in #35953, #35779, #35791, #35863, #35864, #35958, #36011, #36012, #36013, #36017, and #36050.

🧩 Workflow, HITL, and app runtime

  • Workflow stability — restored workflow-version loading through the backend API, fixed online-user polling for large app lists, prevented preview resize observer loops, and avoided schema model collisions in trial workflows. Thanks @hjlarry and @lyzno1 in #35817, #35786, #35936, and #36061.
  • Workflow authoring polish — fixed variable reference picker behavior for sub-variables, workflow node title overflow, condition operator popovers, workflow checklist semantics, and KB metadata filter field selection. Thanks @iamjoel, @hjlarry, @lyzno1, and @shawny011717 in #35732, #35740, #35828, #36006, and #34149.

Upgrade Guide

Important notes

  • This release includes a new database migration for configurable Explore app categories. Run database migrations as part of the upgrade.
  • Docker Compose environment variables are now split into categorized files under docker/envs/**. If you maintain a customized docker-compose.yaml or .env, review the new layout and re-apply local customizations carefully.
  • For self-hosted deployments, explicitly configured SECRET_KEY values continue to be respected. If SECRET_KEY is empty, Dify now generates and persists a runtime key automatically.

Docker Compose Deployments

  1. Back up your customized docker-compose YAML and env files.

    cd docker
cp docker-compose.yaml docker-compose.yaml.$(date +%s).bak
cp .env .env.$(date +%s).bak 2>/dev/null || true

  2. Get the latest code from the release branch or tag.

    git fetch --tags
git checkout 1.14.1

  3. Stop the service. Please execute in the docker directory.

    docker compose down

  4. Back up data.

    tar -cvf volumes-$(date +%s).tgz volumes

  5. Review the new docker/envs/** env file layout and re-apply any local customizations.

  6. Upgrade services.

    docker compose up -d

Source Code Deployments

  1. Stop the API server, Worker, and Web frontend Server.

  2. Get the latest code from the release tag.

    git fetch --tags
git checkout 1.14.1

  3. Update Python dependencies.

    cd api
uv sync

  4. Run the migration script.

    uv run flask db upgrade

  5. Restart the API server, Worker, and Web frontend Server.
