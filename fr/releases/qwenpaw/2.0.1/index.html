QwenPaw v2.0.1

Highlights

  • PawApp mini-app platform — Plugins can now build rich interactive UIs instead of relying solely on text-based tool output. The bundled Kanban app provides a concrete reference for project-management workflows and SDK adoption (#6150).
  • Configurable agent loops — The ReAct loop is now a first-class DefaultMode with explicit lifecycle and approval gates. Console-editable modes and the Oh-My-Paw presets make custom iteration limits, stop conditions, and multi-agent workflows accessible without code changes; integrations hooking the built-in loop should align with the new mode lifecycle (#6210, #6270, #5882).
  • Unified governance, wider default file access — ToolGuard rules now feed the governance policy engine, while global reads are allowed by default for paths classified as non-sensitive. This centralizes enforcement but widens effective filesystem access: review sensitive-file classifications and existing allowlists, and note that persistent “Always Allow” decisions now use toolSource rather than executionLevel (#6390, #6067, #6095).
  • MCP credential migration and policy timing — ${VAR} header credentials are migrated to environment references through a schema-watermarked, one-shot process. Validate required environment variables after upgrading; policy changes now apply immediately, and MCP connection timeouts no longer block workspace startup, so successful startup does not guarantee every server is connected (#6091, #6133, #5949, #6174).
  • More controllable automatic memory — Automatic memory capture is restricted to external user queries, excluding internal or tool-generated context. Teams relying on the previous behavior should review stored memory and rebuild indexes; automatic memory can be disabled entirely with auto_memory_interval=0, while console/API-triggered rebuilds and startup self-repair improve recovery (#6120, #6135, #6235).
  • Production health checks and trace attribution — The new /api/healthz endpoint supports container orchestration, and trusted-proxy handling resolves real client IPs behind load balancers—configure proxy trust carefully to prevent IP spoofing. Langfuse traces now include user, session, and package-version dimensions with valid hexadecimal IDs, improving filtering and deployment-level analysis (#6028, #6030, #5922, #6277).

No breaking changes are listed in this release.

What's Changed

✨ Added

PawApp Platform

Custom Agent Modes

  • User-editable Agent Mode: Create and edit custom agent loop modes directly from the console — define iteration limits, stop conditions, and approval gates without touching code (#6270)
  • Oh-My-Paw Plugin: Five ready-to-use Agent Loops (UltraQA, Ralph, Ultrawork, Autopilot, Team) for multi-agent collaboration and long-running tasks (#5882)

Memory & Observability

  • ReMe Light index maintenance: Explicit index rebuild via console button or API, improved startup self-repair, and optimized Markdown chunking for large documents (#6235)
  • ReMe reliability improvements: Runtime memory stats inspection, CJK embedding safety, and background summarizer graceful shutdown (#6098)
  • ReMe indexing safeguards: Enhanced configuration validation and indexing stability (#6153)
  • Langfuse trace enrichment: Traces now carry user ID, session ID, and package version for better filtering and analysis (#5922)

  • Drag-and-drop file upload: Drop files directly into the chat input area in the desktop app (#6327)

  • One-click agent config copy: Duplicate an agent configuration with a single click (#6262)
  • Configurable log rotation: Set log file rotation limits from the configuration (#6183)

Security & Governance

  • Windows restricted-token sandbox: Code execution isolated via Windows restricted tokens for an additional sandbox option (#5931)
  • Governance rules: New governance rule definitions for finer-grained access control (#6215)
  • Sensitive file detection: More file types detected as sensitive; global file reads now allowed by default for non-sensitive paths (#6067)

Runtime & Multi-Agent
