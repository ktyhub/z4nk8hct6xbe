Architecture de base

  • Runtime 2.0 : Refactorisez le noyau basé sur AgentScope 2.0 (#5078, #4846, #5018, #5552)

QwenPaw v2.0.0

Highlights

  • Runtime 2.0 architecture — The AgentScope 2.0 kernel refactor unifies MCP/A2A/ACP connections, encrypted credential storage, and per-call approvals (#5078, #5067). Plugin authors should validate against AgentScope 2.0 middleware semantics; semver-gated compatibility now prevents incompatible plugins from appearing in the catalog (#5221, #5661).
  • Breaking changes and migration — Plan Mode and its plan_mode configuration are removed (#5605, #5618). Rename preserve_thinking to relay_reasoning; it now defaults off for DashScope to prevent duplicated reasoning output (#5876). Review /compact automation because its lifecycle behavior changed, and adopt the new /system_prompt command (#5450, #5815).
  • Policy and sandbox hardening — ToolGuard and plugin governance now share one allow/deny/ask evaluation path (#5088, #5546), supplemented by session-level policy overrides and configurable approval behavior for cron jobs (#5685, #5847). Linux execution uses bubblewrap namespaces and Windows uses AppContainer, so deployments must satisfy the corresponding OS-level sandbox prerequisites (#5310, #5525).
  • Long-context recall and compression — SQLite-backed history.db adds FTS5 search, turn persistence, eviction indexing, and a sandboxed Python recall REPL, with existing sessions auto-imported and 30-day default retention (#5321). Context handling now protects the active turn from eviction, truncates oversized tool results, and marks the eviction seam—reducing OOM and token-overflow risks in tool-heavy sessions (#5765, #5510, #5871). Compression now uses AgentScope 2.0’s native strategy (#5309).
  • Memory backend migration — ReMe v0.4.0 replaces the in-house runtime, writes memory per turn rather than on session close, and weighs recency/frequency during retrieval (#5349, #5540, #5820). ADBPG is now REST-only with auto-search, while the new none backend lets lightweight deployments disable memory entirely (#5296, #5732).
  • Desktop, terminal, and integration expansion — Desktop packaging moves from Electron to Tauri, adds an NSIS installer on Windows, and bundles Node.js plus ACP modules; existing build and distribution workflows need updating (#5734, #5814). qwenpaw tui adds project-scoped coding sessions, streaming tool rendering, context usage, and inline approvals (#5032, #5448, #5673, #5443). OpenAI Responses API and full Slack support broaden integration options, while GitHub Models users should verify credentials after the endpoint migration (#5519, #5193, #5735).

What's Changed

✨ Added

Core Architecture

  • Runtime 2.0: Refactor the kernel based on AgentScope 2.0 (#5078, #4846, #5018, #5552)
  • Agent OS Driver: Unified management of MCP/A2A/ACP connections, encrypted credential storage, and per-call approval policy (#5067)
  • Loop Engineering: New Loop gate design with three Loop templates: Normal Mode / Mission Mode / Goal Mode (#5665, #5727)
  • Governance & Sandbox: Policy engine with allow/deny/ask rules, ToolGuard detectors merged into a single policy evaluation path, and a generalized governance pattern for plugins (#5088, #5546, #5301)

  • Scroll Context: SQLite-backed working history (history.db) with FTS5 full-text search, eviction index, turn-level persistence, and a sandboxed recall_history_python REPL for on-demand recall of older turns. 30-day default retention, auto-imports existing sessions on startup (#5321)
  • Native Compression: Refactor using AgentScope 2.0's built-in context compression strategy (#5309)

Long-term Memory

  • ReMe v0.4.0 backend: Replace the in-house memory runtime with ReMe v0.4.0 — vector store, auto-tracking, and retrieval are now handled by the ReMe v0.4.0 library (#5349)
  • Turn-based tracking: Memory writes now happen per-turn via middleware, no longer tied to session close (#5540)

  • ADBPG REST mode: ADBPG memory backend switched to REST-only, with auto search (#5296)

  • 'none' backend: Config option to fully disable the memory system for lightweight deployments (#5732)
