#hermès-agent v2026.4.30

Agent Hermès v0.12.0 (v2026.4.30)

Date de sortie : 30 avril 2026 Depuis v0.11.0 : 1 096 commits · 550 PR fusionnés · 1 270 fichiers modifiés · 217 776 insertions · 213 contributeurs de la communauté (y compris les co-auteurs)

La version Curator — Hermes Agent se maintient désormais tout seul. Un conservateur d'arrière-plan autonome note, élague et consolide votre bibliothèque de compétences selon son propre calendrier. La boucle d’auto-amélioration qui examine ce qu’il faut économiser a fait l’objet d’une mise à niveau substantielle. Quatre nouveaux fournisseurs d'inférence, une 18e plate-forme de messagerie, une 19e via le plugin Teams, des intégrations natives Spotify + Google Meet, ComfyUI et TouchDesigner-MCP sont passés d'optionnels à fournis par défaut, et une réduction d'environ 57 % du démarrage à froid visible de TUI.

✨ Points forts

  • Conservateur autonome — hermes curator s'exécute en tant qu'agent d'arrière-plan sur le ticker cron de la passerelle (cycle par défaut de 7 jours). Il évalue votre bibliothèque de compétences, consolide les compétences associées, supprime celles qui sont mortes et rédige des rapports par exécution dans logs/curator/run.json + REPORT.md. Les compétences archivées sont classées consolidées ou élaguées via modèle + heuristique. Les portes de défense en profondeur protègent les compétences groupées/hub de la mutation. Unifié sous auxiliary.curator — choisissez le modèle du conservateur dans hermes model, gérez-le depuis le tableau de bord. hermes curator status classe les compétences par utilisation (les plus utilisées/les moins utilisées). (#17277, #17307, #17941, #17868, #18033)
  • Boucle d'auto-amélioration — considérablement améliorée — Le fork de révision en arrière-plan (le cœur de l'auto-amélioration d'Hermès : après chaque tour, il décide quels souvenirs/compétences enregistrer ou mettre à jour) est désormais prioritaire en classe (basé sur une rubrique plutôt que sur une forme libre), biaisé par la mise à jour active (préfère la compétence que l'agent vient de charger), gère les sous-fichiers references//templates/ et hérite correctement du moteur d'exécution en direct du parent (fournisseur, modèle, les informations d’identification se propagent réellement). Limité aux ensembles d'outils de mémoire et de compétences afin qu'il ne puisse pas s'étendre. Les fournisseurs de mémoire se sont arrêtés proprement. Messages de l'outil de tour préalable exclus du résumé afin que le fork voie un contexte propre. (#16026, #17213, #16099, #16569, #16204, #15057)
  • Intégrations de compétences — extension majeure — ComfyUI v5 avec installation locale officielle CLI + REST + matérielle, déplacée de facultative à intégrée par défaut (#17610, #17631, #17734). TouchDesigner-MCP fourni par défaut, étendu avec GLSL, post-FX, audio, géométrie et 9 nouveaux documents de référence (#16753, #16624, #16768 — @kshitijk4poor + @SHL0MS). Release Date: April 30, 2026 Since v0.11.0: 1,096 commits · 550 merged PRs · 1,270 files changed · 217,776 insertions · 213 community contributors (including co-authors)

The Curator release — Hermes Agent now maintains itself. An autonomous background Curator grades, prunes, and consolidates your skill library on its own schedule. The self-improvement loop that reviews what to save got a substantial upgrade. Four new inference providers, a 18th messaging platform, a 19th via Teams plugin, native Spotify + Google Meet integrations, ComfyUI and TouchDesigner-MCP moved from optional to bundled-by-default, and a ~57% cut to visible TUI cold start.

✨ Highlights

  • Autonomous Curator — hermes curator runs as a background agent on the gateway's cron ticker (7-day cycle default). It grades your skill library, consolidates related skills, prunes dead ones, and writes per-run reports to logs/curator/run.json + REPORT.md. Archived skills are classified consolidated-vs-pruned via model + heuristic. Defense-in-depth gates protect bundled/hub skills from mutation. Unified under auxiliary.curator — pick the curator's model in hermes model, manage it from the dashboard. hermes curator status ranks skills by usage (most-used / least-used). (#17277, #17307, #17941, #17868, #18033)

  • Self-improvement loop — substantially upgraded — The background review fork (the core of Hermes' self-improvement: after each turn it decides what memories/skills to save or update) is now class-first (rubric-based rather than free-form), active-update biased (prefers the skill the agent just loaded), handles references//templates/ sub-files, and properly inherits the parent's live runtime (provider, model, credentials actually propagate). Restricted to memory + skills toolsets so it can't sprawl. Memory providers shut down cleanly. Prior-turn tool messages excluded from the summary so the fork sees a clean context. (#16026, #17213, #16099, #16569, #16204, #15057)
