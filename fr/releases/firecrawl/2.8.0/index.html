Firecrawl v2.8.0

#v2.8.0

Firecrawl v2.8.0 est là !

Firecrawl v2.8.0 apporte des améliorations majeures aux flux de travail des agents, aux outils de développement et aux déploiements auto-hébergés sur les API et SDK, y compris notre nouvelle Skill.

  • Agents parallèles pour exécuter simultanément des milliers de requêtes /agent, optimisés par notre nouveau modèle Spark 1 Fast.
  • Firecrawl CLI avec prise en charge complète des commandes scrape, search, crawl et map.
  • Compétence Firecrawl pour permettre aux agents IA (Claude Code, Codex, OpenCode) d'utiliser Firecrawl de manière autonome.
  • Trois nouveaux modèles alimentant /agent : Spark 1 Fast pour une récupération instantanée (actuellement disponible uniquement dans Playground), Spark 1 Mini pour les requêtes de recherche complexes et Spark 1 Pro pour les tâches d'extraction avancées.
  • Améliorations de l'agent, notamment des webhooks, la sélection de modèles et de nouveaux outils de serveur MCP.
  • Améliorations des performances à l'échelle de la plate-forme, notamment une exécution de recherche plus rapide et des appels Redis optimisés.
  • Améliorations du SDK, y compris la compatibilité Zod v4.

Et bien plus encore, découvrez-le ci-dessous !

Nouvelles fonctionnalités

  • Agents parallèles
    Exécutez des milliers de requêtes /agent en parallèle avec la gestion automatique des pannes et l'exécution intelligente en cascade. Propulsé par Spark 1-Fast pour une récupération instantanée, mise à niveau automatique vers Spark 1 Mini pour les requêtes complexes nécessitant une recherche complète.

  • Firecrawl CLI
    Nouvelle interface de ligne de commande pour Firecrawl avec prise en charge complète des commandes scrape, search, crawl et map. Installez avec npm install -g firecrawl-cli.

  • Compétence Firecrawl
    Permet aux agents comme Claude Cursor, Codex et OpenCode d'utiliser Firecrawl pour la navigation Web et l'extraction de données, installable via npx skills add firecrawl/cli.

  • Famille de modèles Spark
    Trois nouveaux modèles alimentent /agent : Spark 1 Fast pour une récupération instantanée (actuellement disponible dans Playground), Spark 1 Mini (par défaut) pour les tâches d'extraction quotidiennes à un coût 60 % inférieur, et Spark 1 Pro pour des recherches multi-domaines complexes nécessitant une précision maximale. Spark 1 Pro atteint un rappel d'environ 50 % tandis que Mini offre un rappel d'environ 40 %, tous deux surpassant considérablement les outils coûtant 4 à 7 fois plus cher par tâche.

  • Outils de l'agent du serveur Firecrawl MCP
    Nouveaux outils firecrawl_agent et firecrawl_agent_status pour la collecte autonome de données Web via des agents compatibles MCP.

  • Webhooks pour agents
    Le point de terminaison de l'agent prend désormais en charge les webhooks pour les notifications en temps réel sur l'achèvement et la progression des tâches.

  • Sélection du modèle d'agent
    Le point de terminaison de l'agent accepte désormais un paramètre model et inclut les informations de modèle dans les réponses d'état.

  • Images Docker multi-arches
    Les déploiements auto-hébergés prennent désormais en charge l'architecture linux/arm64 en plus de amd64.

  • Mode d'exploration du plan du site uniquement
    Nouvelle option d'exploration pour utiliser exclusivement les URL du plan du site sans suivre les liens.

  • Paramètre de carte ignoreCache
    Nouvelle option pour contourner les résultats mis en cache lors du mappage des URL.

  • En-têtes personnalisés pour /map
    Le point de terminaison de la carte prend désormais en charge les en-têtes de requête personnalisés.

  • Extraction d'image d'arrière-plan
    Scraper extrait désormais les images d'arrière-plan des styles CSS.

  • Messages d'erreur améliorés
    Tous les messages d'erreur destinés aux utilisateurs incluent désormais des explications détaillées pour aider à diagnostiquer les problèmes.

API Améliorations

  • Recherche sans limites de concurrence : les scrapes dans la recherche s'exécutent désormais directement sans surcharge de file d'attente.
  • Renvoyez 400 pour les actions non prises en charge avec des erreurs claires lorsque les actions demandées ne sont pas prises en charge par les moteurs disponibles.
  • L'ID de travail est désormais inclus dans les métadonnées de recherche pour un suivi plus facile.
  • Metadata responses now include detected timezone.
  • Remplissez le titre des métadonnées de og:title ou twitter:title lorsqu'il est manquant.
  • Préserver le paramètre gid lors de la réécriture des URL Google Sheets.
  • Correction du chemin v2 dans la pagination du statut de scrape par lots.
  • Validez la propriété de l'équipe lors de l'ajout à des analyses existantes.
  • Les captures d'écran avec fenêtre d'affichage personnalisée ou paramètres de qualité contournent désormais le cache.
  • Appels Redis optimisés sur les points finaux.
  • Reduced excessive robots.txt fetching and parsing.
  • Paramètre de délai d'expiration minimum de la demande désormais configurable.

SDK Améliorations

JavaScript SDK

  • Compatibilité Zod v4 — la conversion de schéma fonctionne désormais avec Zod v4 avec une détection d'erreur améliorée.
  • Exportations Watcher — Watcher et WatcherOptions sont désormais exportés à partir du point d'entrée SDK.
  • Agent Webhook Support — nouvelles options de webhook pour les appels d'agent.
  • Error Retry Polling — SDK réessaye l'interrogation après des erreurs passagères.
  • ID de travail dans les exceptions — les exceptions d'erreur incluent désormais jobId pour le débogage.

Python SDK

  • Aides à la pagination manuelle pour parcourir les résultats.
  • Prise en charge des webhooks d'agent ajoutée à l'agent client.
  • Le point de terminaison de l'agent accepte désormais le paramètre de sélection de modèle.
  • Les métadonnées incluent désormais des informations sur les limites de concurrence.
  • Correction de la gestion de max_pages dans les requêtes d'exploration.

Améliorations du tableau de bord

  • Le mode sombre est désormais pris en charge.
  • Sur la page d'utilisation, vous pouvez désormais visualiser l'utilisation du crédit répartie par jour.
  • Sur la page des journaux d'activité, vous pouvez désormais filtrer par la clé API qui a été utilisée.
  • Le format de sortie "images" est désormais pris en charge dans le Playground.
  • Tous les administrateurs peuvent désormais gérer les abonnements de leur équipe.

Qualité et performances

  • Ignorez les contrôles de conversion de démarque pour les documents HTML volumineux.
  • Exportez Google Docs au format HTML au lieu de PDF pour des performances améliorées.
  • Format de marque amélioré avec une meilleure détection du logo et des messages d'erreur pour les PDF et les documents.
  • Amélioration des performances de chargement des métadonnées lopdf.
  • Module html-to-markdown mis à jour avec plusieurs corrections de bugs.
  • Augmentation de la limite du corps du service de démarque et ajout de la journalisation des ID de demande.
  • Meilleur filtrage Sentry pour les travaux annulés et les erreurs de moteur.
  • Correction des conditions de course aux extraits et de la gestion des pilules empoisonnées RabbitMQ.
  • Configuration centralisée de Firecrawl dans la base de code.
  • Plusieurs correctifs de vulnérabilités de sécurité, notamment CVE-2025-59466 et la pollution du prototype lodash.

Améliorations auto-hébergées

  • Prise en charge de l'URL personnalisée API via firecrawl --api-url http://localhost:3002 pour les instances locales.
  • Prise en charge d'ARM64 Docker via des images multi-arch pour les serveurs Apple Silicon et ARM.
  • Correction des informations d'identification de la base de données docker-compose prêtes à l'emploi.
  • Correction du démarrage du service Playwright causé par des problèmes de chemin Chromium.
  • Mise à jour de Node.js vers la version majeure 22 au lieu d'une version mineure épinglée.
  • Ajout du point de terminaison de vérification de l'état de RabbitMQ.
  • Correction de l'exposition du port PostgreSQL dans docker-compose.

firecrawl v2.8.0

v2.8.0

Firecrawl v2.8.0 is here!

Firecrawl v2.8.0 brings major improvements to agent workflows, developer tooling, and self-hosted deployments across the API and SDKs, including our new Skill.

  • Parallel Agents for running thousands of /agent queries simultaneously, powered by our new Spark 1 Fast model.
  • Firecrawl CLI with full support for scrape, search, crawl, and map commands.
  • Firecrawl Skill for enabling AI agents (Claude Code, Codex, OpenCode) to use Firecrawl autonomously.
  • Three new models powering /agent: Spark 1 Fast for instant retrieval (currently only available in Playground), Spark 1 Mini for complex research queries, and Spark 1 Pro for advanced extraction tasks.
  • Agent enhancements including webhooks, model selection, and new MCP Server tools.
  • Platform-wide performance improvements including faster search execution and optimized Redis calls.
  • SDK improvements including Zod v4 compatibility.

And much more, check it out below!

New Features

  • Parallel Agents
    Execute thousands of /agent queries in parallel with automatic failure handling and intelligent waterfall execution. Powered by Spark 1-Fast for instant retrieval, automatically upgrading to Spark 1 Mini for complex queries requiring full research.

  • Firecrawl CLI
    New command-line interface for Firecrawl with full support for scrape, search, crawl, and map commands. Install with npm install -g firecrawl-cli.

  • Firecrawl Skill
    Enables agents like Claude Cursor, Codex, and OpenCode to use Firecrawl for web scraping and data extraction, installable via npx skills add firecrawl/cli.

  • Spark Model Family
    Three new models powering /agent: Spark 1 Fast for instant retrieval (currently available in Playground), Spark 1 Mini (default) for everyday extraction tasks at 60% lower cost, and Spark 1 Pro for complex multi-domain research requiring maximum accuracy. Spark 1 Pro achieves ~50% recall while Mini delivers ~40% recall, both significantly outperforming tools costing 4-7x more per task.

  • Firecrawl MCP Server Agent Tools
    New firecrawl_agent and firecrawl_agent_status tools for autonomous web data gathering via MCP-enabled agents.

  • Agent Webhooks
    Agent endpoint now supports webhooks for real-time notifications on job completion and progress.

  • Agent Model Selection
    Agent endpoint now accepts a model parameter and includes model info in status responses.

  • Multi-Arch Docker Images
    Self-hosted deployments now support linux/arm64 architecture in addition to amd64.

  • Sitemap-Only Crawl Mode
    New crawl option to exclusively use sitemap URLs without following links.

  • ignoreCache Map Parameter
    New option to bypass cached results when mapping URLs.

  • Custom Headers for /map
    Map endpoint now supports custom request headers.

  • Background Image Extraction
    Scraper now extracts background images from CSS styles.

  • Improved Error Messages
    All user-facing error messages now include detailed explanations to help diagnose issues.

API Improvements

  • Search without concurrency limits — scrapes in search now execute directly without queue overhead.
  • Return 400 for unsupported actions with clear errors when requested actions aren't supported by available engines.
  • Job ID now included in search metadata for easier tracking.
  • Metadata responses now include detected timezone.
  • Backfill metadata title from og:title or twitter:title when missing.
  • Preserve gid parameter when rewriting Google Sheets URLs.
  • Fixed v2 path in batch scrape status pagination.
  • Validate team ownership when appending to existing crawls.
  • Screenshots with custom viewport or quality settings now bypass cache.
  • Optimized Redis calls across endpoints.
  • Reduced excessive robots.txt fetching and parsing.
  • Minimum request timeout parameter now configurable.

SDK Improvements

JavaScript SDK

  • Zod v4 Compatibility — schema conversion now works with Zod v4 with improved error detection.
  • Watcher Exports — Watcher and WatcherOptions now exported from the SDK entrypoint.
  • Agent Webhook Support — new webhook options for agent calls.
  • Error Retry Polling — SDK retries polling after transient errors.
  • Job ID in Exceptions — error exceptions now include jobId for debugging.

Python SDK

  • Manual pagination helpers for iterating through results.
  • Agent webhook support added to agent client.
  • Agent endpoint now accepts model selection parameter.
  • Metadata now includes concurrency limit information.
  • Fixed max_pages handling in crawl requests.

Dashboard Improvements

  • Dark mode is now supported.
  • On the usage page, you can now view credit usage broken down by day.
  • On the activity logs page, you can now filter by the API key that was used.
  • The "images" output format is now supported in the Playground.
  • All admins can now manage their team's subscriptions.

Quality & Performance

  • Skip markdown conversion checks for large HTML documents.
  • Export Google Docs as HTML instead of PDF for improved performance.
  • Improved branding format with better logo detection and error messages for PDFs and documents.
  • Improved lopdf metadata loading performance.
  • Updated html-to-markdown module with multiple bug fixes.
  • Increased markdown service body limit and added request ID logging.
  • Better Sentry filtering for cancelled jobs and engine errors.
  • Fixed extract race conditions and RabbitMQ poison pill handling.
  • Centralized Firecrawl configuration across the codebase.
  • Multiple security vulnerability fixes, including CVE-2025-59466 and lodash prototype pollution.

Self-Hosted Improvements

  • CLI custom API URL support via firecrawl --api-url http://localhost:3002 for local instances.
  • ARM64 Docker support via multi-arch images for Apple Silicon and ARM servers.
  • Fixed docker-compose database credentials out of the box.
  • Fixed Playwright service startup caused by Chromium path issues.
  • Updated Node.js to major version 22 instead of a pinned minor.
  • Added RabbitMQ health check endpoint.
  • Fixed PostgreSQL port exposure in docker-compose.
