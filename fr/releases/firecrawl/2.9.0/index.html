Feu d'artifice v2.9.0

Améliorations

  • Interaction avec le navigateur via le point de terminaison /interact — Grattez une page, puis appelez /interact pour prendre des mesures dessus — click boutons, remplissez des formulaires, naviguez plus profondément ou extrayez du contenu dynamique. Décrivez ce que vous voulez en langage naturel via prompt, ou écrivez le code Playwright (Node.js, Python) et Bash (agent-browser) pour un contrôle total. Les sessions persistent d'un appel à l'autre, avec des URL d'affichage en direct et d'affichage en direct interactif pour le streaming en temps réel du navigateur. Les profils persistants vous permettent d'enregistrer et de réutiliser l'état du navigateur (cookies, localStorage) à travers les scrapes. Disponible en JS, Python, Java et Rust SDK.
  • Format query — Ajout du format query au point de terminaison /scrape — transmettez une invite en langage naturel et obtenez une réponse directe dans data.answer.
  • Format audio — Ajout de l'option de format audio pour récupérer les réponses, renvoyant la sortie audio sous forme de champ sur le document.
  • Paramètre onlyCleanContent — Ajout du paramètre onlyCleanContent au point de terminaison /scrape, qui supprime la navigation, les publicités, les bannières de cookies et tout autre contenu non sémantique de la sortie markdown.
  • Modes d'analyse PDF — Ajout de modes d'analyse PDF (fast, auto, ocr) et d'une option maxPages pour contrôler la profondeur d'extraction et le comportement OCR.
  • Java et Elixir SDK — Ajout des SDK Java et Elixir officiels avec prise en charge complète de la v2 API.
  • Prise en charge des fichiers .doc hérités — Ajout de la prise en charge de l'analyse des fichiers .doc hérités.
  • Moteur Wikimédia — Ajout d'un moteur dédié pour les pages scraping Wikipédia et Wikimédia avec une qualité de sortie améliorée.
  • contentType dans les réponses de scrape — Ajout de contentType pour gratter les réponses des PDF et des documents.
  • Améliorations du pipeline PDF — Pipeline PDF amélioré avec une meilleure détection des tableaux, une suppression des en-têtes/pieds de page, une gestion mixte des PDF, une analyse d'images en ligne et une détection d'octets magiques.
  • Extraction de marque — Extraction de marque améliorée pour ignorer les éléments DOM cachés pour un résultat plus propre.
  • Performances HTML vers markdown — Amélioration des performances de conversion HTML vers markdown et correction des blocs de code perdant du contenu lors de la conversion.
  • File d'attente simultanée — Nouveau système de file d'attente simultanée avec rapprocheur et remplissage pour une planification des tâches plus fiable.
  • Rust SDK v2 — Ajout de l'espace de noms v2 API avec prise en charge d'agent au Rust SDK.
  • Correction des paramètres Python SDK timeout, max_retries et backoff_factor — ceux-ci étaient auparavant acceptés mais silencieusement ignorés.
  • Délais d'expiration des tâches plafonnés à 48 heures pour empêcher les tâches incontrôlées de consommer des ressources.
  • Ajout de limites de tentatives pour éviter les boucles de scrape.
  • Les types de contenu binaire sont désormais rejetés au début du pipeline de scrape pour éviter un traitement inutile.

Correctifs

  • Correction des réponses vides lors de l'utilisation du modèle o3-mini sur les tâches d'extraction.
  • Correction des clés API révoquées restant valides jusqu'à 10 minutes après la suppression.
  • Correction d'une condition de concurrence critique dans les tâches d'extraction qui provoquait des plantages « Tâche introuvable ».
  • Correction de time_taken dans /v1/map renvoyant toujours ~0.
  • Correction des réponses au statut d'analyse faisant désormais apparaître un statut failed avec un message d'erreur et des données partielles lorsqu'un échec au niveau de l'analyse se produit.
  • Correction de maxPages qui n'était pas transmis à l'extracteur PDF — auparavant, le contenu PDF complet était renvoyé en facturant uniquement le nombre limité de pages.
  • Correction des crédits de demande gratuite étant consommés et facturés de manière incorrecte sur les tâches d'agent dépassant le seuil maxCredits.
  • Correction du tableau de bord affichant des limites de concurrence incorrectes en raison de lectures obsolètes.
  • Correction du marquage colors.secondary qui n'était pas renseigné.
  • Correction de removeBase64Images fonctionnant après deriveDiff dans le pipeline du transformateur, provoquant des problèmes de différence.
  • Correction de la récupération GCS utilisant un index de ligne incorrect pour les recherches d'informations sur le cache.
  • Correction du ZodError non géré dans le contrôleur /v1/search.
  • Résolution de plusieurs CVE dans les dépendances, notamment handlebars, path-to-regexp, fast-xml-parser, rollup (CVE-2026-27606), undici et autres.
  • Renforcement du service Playwright contre les attaques SSRF.

##API

  • Ajout du point de terminaison GET /v2/team/activity pour répertorier les tâches récentes de scraping, d'exploration et d'extraction avec une pagination basée sur le curseur (dernières 24 heures, jusqu'à 100 résultats par page, filtrables par type de point de terminaison).
  • Ajout du paramètre regexOnFullURL sur les demandes d'exploration pour appliquer le filtrage includePaths/excludePaths sur l'URL complète, y compris les paramètres de requête. Disponible en JS, Python, Java et Elixir SDK.
  • Ajout du paramètre deduplicateSimilarURLs sur les requêtes d'exploration. Disponible en JS, Python, Java et Elixir SDK.
  • Le point de terminaison extract est obsolète : utilisez plutôt le point de terminaison /agent. Les méthodes extract existantes dans JS et Python SDK sont marquées comme obsolètes.
  • Renommé persistentSession en profile sur les requêtes de navigateur/interaction (writeMode est désormais saveChanges). L'ancien nom du paramètre reste fonctionnel mais n'est plus documenté.

firecrawl v2.9.0

Firecrawl v2.9.0

Improvements

  • Browser Interaction via /interact endpoint — Scrape a page, then call /interact to take actions on it — click buttons, fill forms, navigate deeper, or extract dynamic content. Describe what you want in natural language via prompt, or write Playwright code (Node.js, Python) and Bash (agent-browser) for full control. Sessions persist across calls, with live view and interactive live view URLs for real-time browser streaming. Persistent profiles let you save and reuse browser state (cookies, localStorage) across scrapes. Available in JS, Python, Java, and Rust SDKs.
  • query format — Added query format to the /scrape endpoint — pass a natural-language prompt and get a direct answer back in data.answer.
  • audio format — Added audio format option to scrape responses, returning audio output as a field on the document.
  • onlyCleanContent parameter — Added onlyCleanContent parameter to the /scrape endpoint, which strips navigation, ads, cookie banners, and other non-semantic content from markdown output.
  • PDF parsing modes — Added PDF parsing modes (fast, auto, ocr) and a maxPages option to control extraction depth and OCR behavior.
  • Java and Elixir SDKs — Added official Java and Elixir SDKs with full v2 API support.
  • Legacy .doc file support — Added support for parsing legacy .doc files.
  • Wikimedia engine — Added a dedicated engine for scraping Wikipedia and Wikimedia pages with improved output quality.
  • contentType in scrape responses — Added contentType to scrape responses for PDFs and documents.
  • PDF pipeline improvements — Improved PDF pipeline with better table detection, header/footer stripping, mixed PDF handling, inline image parsing, and magic byte detection.
  • Branding extraction — Improved branding extraction to skip hidden DOM elements for cleaner output.
  • HTML-to-markdown performance — Improved HTML-to-markdown conversion performance and fixed code blocks losing content during conversion.
  • Concurrency queue — New concurrency queue system with reconciler and backfill for more reliable job scheduling.
  • Rust SDK v2 — Added v2 API namespace with agent support to the Rust SDK.
  • Fixed Python SDK parameters timeout, max_retries, and backoff_factor — these were previously accepted but silently ignored.
  • Capped job timeouts at 48 hours to prevent runaway jobs from consuming resources.
  • Added retry limits to prevent scrape loops.
  • Binary content types are now rejected early in the scrape pipeline to avoid wasted processing.

Fixes

  • Fixed empty responses when using the o3-mini model on extract jobs.
  • Fixed revoked API keys remaining valid for up to 10 minutes after deletion.
  • Fixed a race condition in extract jobs that caused "Job not found" crashes.
  • Fixed time_taken in /v1/map always returning ~0.
  • Fixed crawl status responses now surfacing a failed status with an error message and partial data when a crawl-level failure occurs.
  • Fixed maxPages not being passed to the PDF extractor — previously, full PDF content was returned while only charging for the limited page count.
  • Fixed free request credits being incorrectly consumed and billed on agent jobs exceeding the maxCredits threshold.
  • Fixed dashboard displaying incorrect concurrency limits due to stale reads.
  • Fixed branding colors.secondary not being populated.
  • Fixed removeBase64Images running after deriveDiff in the transformer pipeline, causing diff issues.
  • Fixed GCS fetch using wrong row index for cache info lookups.
  • Fixed unhandled ZodError in /v1/search controller.
  • Resolved multiple CVEs across dependencies including handlebars, path-to-regexp, fast-xml-parser, rollup (CVE-2026-27606), undici, and others.
  • Hardened the Playwright service against SSRF attacks.

API

  • Added GET /v2/team/activity endpoint for listing recent scrape, crawl, and extract jobs with cursor-based pagination (last 24 hours, up to 100 results per page, filterable by endpoint type).
  • Added regexOnFullURL parameter on crawl requests to apply includePaths/excludePaths filtering against the full URL including query parameters. Available in JS, Python, Java, and Elixir SDKs.
  • Added deduplicateSimilarURLs parameter on crawl requests. Available in JS, Python, Java, and Elixir SDKs.
  • Deprecated the extract endpoint — use the /agent endpoint instead. Existing extract methods in JS and Python SDKs are marked deprecated.
  • Renamed persistentSession to profile on browser/interact requests (writeMode is now saveChanges). The old parameter name remains functional but is no longer documented.
