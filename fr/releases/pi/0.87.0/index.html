pi v0.87.0

Nouvelles fonctionnalités

  • Contexte de session canonique et limites d'extension — Modifiez le contexte du modèle sans réécrire l'historique et ajoutez des hooks de cycle de vie exploitables. Voir ContextEditEntry et événements d'extension.
  • Extensions de contexte de transcription complète — Utilisez context_with_system pour les transformations de messages système par requête. Voir context_with_system.
  • Limites d'entrée d'image par modèle — Configurez le redimensionnement d'image sécurisé par modèle pour les pièces jointes, read et les images de résultats d'outils. Voir [Limites d'entrée d'image] (https://github.com/earendil-works/pi/blob/v0.87.0/packages/coding-agent/docs/models.md#image-input-limits).

Modifications radicales

  • Suppression de l'option d'agent shouldStopAfterTurn héritée. Utilisez finishTurn et renvoyez plutôt { action: "end" }. finishTurn s'exécute avant turn_end mais applique la décision par la suite et reçoit également des réponses d'erreur et d'abandon ; migrez les prédicats de réponse normale en renvoyant undefined pour ces sorties matérielles. Voir le @earendil-works/pi-agent-core changelog pour un exemple complet avant et après.
  • Ajout de ContextEditEntry au syndicat SessionEntry exporté. Les consommateurs TypeScript dotés de commutateurs d'entrée exhaustifs doivent gérer context_edit ; utilisez replacement: null pour l'omission et le remplacement du contenu dans le cas contraire.
  • Rendu SessionManager canonique pour le contexte du fournisseur AgentSession. L'attribution de session.agent.state.messages ne remplace plus l'historique des demandes futures ; restaurez avec SessionManager.inMemory(cwd, { id }, entries), naviguez avec session.navigateTree() ou ajoutez via session.sessionManager et appelez session.refreshContext().
  • Extension de TurnEndEvent avec les champs de limite obligatoires et ajout de AgentBeforeSettleEvent à l'union ExtensionEvent exportée. Les consommateurs qui construisent des événements ou allument de manière exhaustive ExtensionEvent doivent gérer les nouvelles formes. ExtensionRunner.emit() n'accepte plus turn_end ; les intégrations hôtes répartissent des limites exploitables avec emitBoundary(baseEvent, buildContext).
  • Exécutions différées demandées aux gestionnaires agent_settled jusqu'à ce que tous les gestionnaires réglés aient terminé. Les gestionnaires observent toujours ctx.isIdle() === true, mais ne voient plus de agent_start réentrant lors de la même expédition de notification.

Ajouté

  • Ajout de modifications de contexte de modèle en ajout uniquement. Par exemple, sessionManager.appendContextEdit(entryId, null) omet un message du contexte du futur fournisseur sans modifier l'historique brut, l'utilisation ou l'historique de l'interface utilisateur.
  • Ajout de limites d'extension exploitables turn_end et agent_before_settle. Renvoyez { entries: [...event.entries, draft], continue: true } pour conserver les entrées structurelles dans l'ordre et garantir une prochaine demande du fournisseur sans modifier le pilotage ou la planification de suivi.
  • Ajout d'une entrée de compactage sans retenue : sessionManager.appendCompaction(summary, null, tokensBefore) stocke le propre ID du compactage comme limite conservée.
  • Ajout de l'événement d'extension context_with_system, qui s'exécute après les gestionnaires context sur la transcription complète, y compris les messages système, et envoie son résultat textuellement. Voir context_with_system.
  • Ajout de profils de redimensionnement d'image par modèle via inputLimits.images.resize dans models.json, appliqués aux pièces jointes, aux lectures d'images et aux images de résultats d'outils (#9631).

Corrigé

  • Correction des remplacements d'édition contextuelle de chaînes produisant un contenu de message d'assistant et de résultat d'outil non valide au lieu de blocs de texte.
  • Correction des métadonnées de limite invisibles au contexte et des modifications de remplacement provoquant le résumé des entrées nouvellement ajoutées ou remplacées avant leur première demande du fournisseur.
  • Correction de la comptabilité du contexte modifié, rejetant l'utilisation valide de l'assistant capturée après la dernière modification du contexte et réutilisant cette utilisation après un compactage ultérieur, la rendant obsolète.
  • Correction des tentatives d'erreur sélectionnées et de la récupération finale de la longueur/débordement en conservant les tentatives de modèle abandonnées dans le contexte du futur fournisseur ; les omissions de récupération après l'exécution sont désormais conservées sans masquer l'historique brut des transcriptions ni modifier la planification des files d'attente.
  • Correction des gestionnaires context qui filtrent ou découpent les messages en supprimant les déclarations d'invite et d'outil, qui, après un compactage piloté par l'extension, laissaient les requêtes sans outils intégrés ou obligeaient le Codex à émettre du texte brut d'appel d'outil. Les gestionnaires ne voient plus les messages système ; Pi restaure l'état de l'invite et de l'outil après leur exécution. Voir context (#9789, #9822).
  • Correction de /bug permettant les téléchargements en mode hors ligne tout en préservant les exportations zip locales (#9841 par @christianklotz).
  • Correction du réchauffement du cache d'invite d'inactivité, reconstruisant les caches expirés lorsque son minuteur ou une décision d'extension est retardé.
  • Diagnostics de crash améliorés avec des astuces identifiant les extensions chargées qui apparaissent dans la trace de la pile.
  • Correction des fichiers texte commençant par GIF étant mal classés en tant qu'images et omis de l'entrée read et CLI @file (#9755).
  • Correction du modèle d'invite mal formé qui était silencieusement ignoré au lieu d'être signalé comme un avertissement de ressource (#9830 par @christianklotz).
  • Correction des points de terminaison de chat complétions compatibles OpenAI inconnus hérités recevant des schémas d'outils stricts à moins qu'ils n'annoncent explicitement la prise en charge (#9816).

Anglais original / English original

pi v0.87.0

New Features

  • Canonical session context and extension boundaries — Edit model context without rewriting history and add actionable lifecycle hooks. See ContextEditEntry and extension events.
  • Full-transcript context extensions — Use context_with_system for per-request system-message transformations. See context_with_system.
  • Per-model image input limits — Configure cache-safe image resizing per model for attachments, read, and tool-result images. See Image Input Limits.

Breaking Changes

  • Removed the inherited shouldStopAfterTurn agent option. Use finishTurn and return { action: "end" } instead. finishTurn runs before turn_end but applies the decision afterward, and it also receives error and aborted responses; migrate normal-response predicates by returning undefined for those hard exits. See the @earendil-works/pi-agent-core changelog for a complete before-and-after example.
  • Added ContextEditEntry to the exported SessionEntry union. TypeScript consumers with exhaustive entry switches must handle context_edit; use replacement: null for omission and a content replacement otherwise.
  • Made SessionManager canonical for AgentSession provider context. Assigning session.agent.state.messages no longer replaces future request history; restore with SessionManager.inMemory(cwd, { id }, entries), navigate with session.navigateTree(), or append through session.sessionManager and call session.refreshContext().
  • Expanded TurnEndEvent with required boundary fields and added AgentBeforeSettleEvent to the exported ExtensionEvent union. Consumers constructing events or exhaustively switching on ExtensionEvent must handle the new shapes. ExtensionRunner.emit() no longer accepts turn_end; host integrations dispatch actionable boundaries with emitBoundary(baseEvent, buildContext).
  • Deferred runs requested from agent_settled handlers until all settled handlers finish. Handlers still observe ctx.isIdle() === true, but no longer see a reentrant agent_start during the same notification dispatch.

Added

  • Added append-only model-context edits. For example, sessionManager.appendContextEdit(entryId, null) omits one message from future provider context without changing raw history, usage, or UI history.
  • Added actionable turn_end and agent_before_settle extension boundaries. Return { entries: [...event.entries, draft], continue: true } to persist structural entries in order and ensure one next provider request without changing steering or follow-up scheduling.
  • Added retain-none compaction input: sessionManager.appendCompaction(summary, null, tokensBefore) stores the compaction's own ID as its kept boundary.
  • Added the context_with_system extension event, which runs after context handlers on the full transcript including system messages and sends its result verbatim. See context_with_system.
  • Added per-model image resize profiles through inputLimits.images.resize in models.json, applied to file attachments, image reads, and tool-result images (#9631).

Fixed

  • Fixed string context-edit replacements producing invalid assistant and tool-result message content instead of text blocks.
  • Fixed context-invisible boundary metadata and replacement edits causing newly appended or replaced input to be summarized before its first provider request.
  • Fixed edited-context accounting both discarding valid assistant usage captured after the latest context edit and reusing that usage after a later compaction made it stale.
  • Fixed selected error retries and final length/overflow recovery retaining abandoned model attempts in future provider context; post-run recovery omissions are now persisted without hiding raw transcript history or changing queue scheduling.
  • Fixed context handlers that filter or slice messages dropping the prompt and tool declarations, which after extension-driven compaction left requests without built-in tools or made Codex emit raw tool-call text. Handlers no longer see system messages; Pi restores the prompt and tool state after they run. See context (#9789, #9822).
  • Fixed /bug allowing uploads in offline mode while preserving local zip exports (#9841 by @christianklotz).
  • Fixed idle prompt-cache warming rebuilding expired caches when its timer or an extension decision is delayed.
  • Improved crash diagnostics with hints identifying loaded extensions that appear in the stack trace.
  • Fixed text files beginning with GIF being misclassified as images and omitted from read and CLI @file input (#9755).
  • Fixed malformed prompt template frontmatter being silently ignored instead of reported as a resource warning (#9830 by @christianklotz).
  • Fixed inherited unknown OpenAI-compatible Chat Completions endpoints receiving strict tool schemas unless they explicitly advertise support (#9816).
