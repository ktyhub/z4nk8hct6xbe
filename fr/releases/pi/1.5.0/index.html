pi v1.5.0

Nouvelles fonctionnalités

  • Mise à jour de l'extension changelogs : découvrez ce qui a changé dans les packages d'extension installés lors du prochain lancement après une mise à jour. Les auteurs de packages peuvent choisir le chemin changelog et collapseChangelog condense les notifications. Voir Afficher un changelog.
  • Diffusion plus rapide : les appels d'outils volumineux sont analysés de manière incrémentale, et les réponses et lignes d'outils lourdes en code réutilisent la mise en évidence et le rendu Markdown au lieu de répéter le travail à chaque mise à jour. Voir [Garder le rendu réactif] (https://github.com/earendil-works/pi/blob/v1.5.0/packages/coding-agent/docs/tui.md#keep-rendering-responsive).
  • Commandes de mise à jour automatique personnalisées : utilisez PI_SELF_UPDATE_COMMAND ou selfUpdateCommand pour mettre à jour pi via un wrapper ou un autre gestionnaire de packages. Voir Commande de mise à jour personnalisée.
  • GPT-6.1 Terra : disponible via OpenAI, Azure OpenAI Responses et OpenAI Codex, avec recherche d'outils, changements de niveau de réflexion à mi-conversation et réflexion off. Le Codex propose une fenêtre contextuelle de 500K. Voir Modèles.

Modifications radicales

  • La validation des arguments de l'outil s'exécute sur @earendil-works/pi-schema. Les fonctionnalités de TypeBox en dehors du schéma JSON (Type.Refine(), Type.BigInt(), Type.Undefined(), codecs, formats Format.Set()) ne s'appliquent plus aux arguments de l'outil ; voir [Schémas de paramètres d'outil et TypeBox] (https://github.com/earendil-works/pi/blob/v1.5.0/packages/coding-agent/docs/extensions.md#tool-parameter-schemas-and-typebox). Les outils de schéma JSON simples, y compris les outils MCP, bénéficient désormais de la même coercition que les outils TypeBox, tels que la conversion de chaînes numériques et l'encapsulation d'une valeur unique dans un tableau. Échecs de validation, le modèle voit la liste des messages du schéma pi (- path: missing, - limit: expected number, got string) au lieu de ceux de TypeBox (must have required properties path, must be number).

Ajouté

  • Les packages d'extension peuvent désormais afficher leur changelog après une mise à jour. Pi lit pi.changelogPath à partir du package.json du package, ou CHANGELOG.md dans la racine du package, et lors du prochain lancement, affiche les entrées plus récentes que la dernière version vue sous « Mises à jour des extensions ». Le paramètre collapseChangelog condense cela à une ligne par package (#5958, #8790)
  • pi.exec() accepte une option maxBuffer qui limite stdout et stderr combinés, et son résultat a un champ truncated qui est vrai lorsque la sortie dépasse la limite (#11360)
  • La connexion par code d'appareil (par exemple GitHub Copilot) ouvre désormais la page de vérification et copie le code lorsque vous appuyez sur Entrée. Les fournisseurs peuvent désactiver l'une ou l'autre action avec openBrowserOnConfirm: false ou copyCodeOnConfirm: false (#9282, #9301).
  • pi update peut mettre à jour Pi via un wrapper ou un autre gestionnaire de packages. Définissez PI_SELF_UPDATE_COMMAND (par exemple mise use -g npm:{packageName}@{version}) ou le paramètre global selfUpdateCommand ; pi update l'exécute lorsque pi.dev signale une version plus récente et remplit {packageName}, {version} et {installSpec} à partir de cette version. Voir Commande de mise à jour personnalisée (#7756, #5607)
  • Les extensions peuvent formater les raccourcis clavier configurés par l'utilisateur avec keyText() et keyHint() à partir du contexte de rendu de l'outil et des options de rendu de messages et d'entrées. L'importation de ces fonctions depuis @earendil-works/pi-coding-agent peut résoudre la propre copie du package de l'extension, qui ne voit pas les raccourcis clavier de pi, donc des astuces telles que keyHint("app.tools.expand", "to expand") sont rendues sans la clé. La doc recommande désormais les fonctions injectées (#4748)
  • Ajout des entrées de session persistantes messageId et ISO timestamp à MarkdownTransformContext. Ils sont disponibles lors du rendu des entrées enregistrées et non définis pour le rendu en direct (#7952 par @vipentti)
  • Ajout d'une option blocked pour intégrer les composants ctx.ui.custom() afin que les invites d'approbation et autres boîtes de dialogue personnalisées puissent signaler que pi attend la saisie de l'utilisateur. Les superpositions ignorent l'option. Voir Écrans et superpositions personnalisés (#11428)
  • Ajout de Usage.cost.totalFromProvider pour distinguer les totaux facturés des estimations du catalogue dans SDK et des données d'utilisation de l'extension ; l'utilisation combinée est marquée comme signalée par le fournisseur uniquement lorsque chaque partie est (#11178)
  • Ajout de métadonnées concrètes responseModel aux messages des fournisseurs de messages pi tels que Radius, y compris lorsqu'un modèle virtuel est demandé. Voir AssistantMessage (#11265)
  • Ajout de GPT-6.1 Terra pour OpenAI, Azure OpenAI Responses et OpenAI Codex, avec recherche d'outils et changements au niveau de la réflexion à mi-conversation. Il prend en charge la réflexion off ; Le Codex propose une fenêtre contextuelle de 500K

Modifié

  • Les extensions continuent d'importer Type, Static et TSchema à partir de @earendil-works/pi-ai : les cartes Pi qui importent dans l'entrée de compatibilité de pi-ai ainsi que la TypeBox qu'elle regroupe, maintenant que pi-ai lui-même ne réexporte plus TypeBox, et son StringEnum y reste une TypeBox TUnsafe<T>. Les fabriques d'outils intégrées (createReadTool() et les autres) renvoient TypeBoxAgentTool<typeof schema>, qui conserve params tapé pour TypeBox.
  • Invite système renforcée
  • pi update pour les installations à partir du programme d'installation pi.dev ne transmet plus --min-release-age=0 à npm ci. Le fichier de verrouillage de la version épingle chaque paquet, donc l'indicateur n'a eu aucun effet et les scanners de sécurité qui le bloquent ont arrêté la mise à jour (#11262)
  • /model et /scoped-models affichent désormais le nom d'un modèle à côté de son ID lorsque le nom ajoute des mots qui manquent à l'ID, comme un remplacement de models.json renommé (#5916, #11347)
  • La connexion MCP OAuth utilise désormais par défaut le document de métadonnées d'identification Client de pi lorsque le serveur d'autorisation le prend en charge pour les clients publics, et enregistre un client dynamiquement dans le cas contraire, comme le Codex, Claude Code et l'opencode. Les Clients enregistrés avant restent utilisés pendant que leur URI de redirection correspond. Le nouveau oauth.clientRegistration: "auto" par défaut s'enregistre lorsque clientName ou un callbackUrl autre que celui par défaut est défini ; "dcr" s'enregistre toujours. pi mcp add --oauth-client-registration définit le mode (#11426)
  • Modification du modèle OpenAI par défaut de gpt-5.5 à gpt-6.1-sol, y compris après la connexion à ChatGPT lorsqu'aucun modèle n'est sélectionné (#11442)
  • Mise à jour du catalogue de modèles intégré vers models.dev v2. Les modèles en temps réel et contenant uniquement des images ne sont plus proposés comme modèles de discussion ; les nouveaux modèles de chat OpenAI et Google sont inclus

Corrigé

  • Mise à jour de la correspondance globale pour empêcher le déni de service dû à des modèles globaux amplifiés.
  • Correction d'une décision enregistrée "Ne pas trust" ignorée pour les projets ne nécessitant pas de ressources trust, par exemple un dossier avec uniquement AGENTS.md. pi a auto-trusted ces projets, donc ctx.isProjectTrusted() a renvoyé true et les commandes du package les ont traités comme trusted. Une décision enregistrée dans trust.json est désormais prioritaire ; auto-trust s'applique uniquement lorsqu'aucune décision n'est enregistrée (#10947)
  • Correction de Shift+Enter mettant en file d'attente un suivi au lieu d'insérer une nouvelle ligne dans les configurations du terminal Apple qui envoient ESC + Return. pi vérifie maintenant l'état de la touche Shift locale pour cette séquence, comme il l'a déjà fait pour Return ; Alt+Enter sans Shift met toujours un suivi en file d'attente (#11559)
  • Correction de l'état de fonctionnement (OSC 7501) disparaissant dans Rex et iTerm2 lors des exécutions en mode TUI normal. Les messages rendus ont écrit des marqueurs d'invite OSC 133 sur le terminal, que le terminal traite comme une nouvelle invite shell ; le mode normal ne les écrit plus (#11519)
  • Correction du compactage, des résumés de branche et des résumés de rapports de bogues dans les sessions SDK, renvoyant le jeton OAuth stocké au runtime du modèle en tant que clé API explicite. L'authentification du fournisseur qui traite les clés explicites différemment de l'OAuth stocké voit désormais la connexion OAuth, comme le font les invites normales (#11520)
  • Correction d'une mise à jour redondante des invites système (outils, règles) lorsqu'une extension définissait les mêmes outils actifs dans un ordre différent, par exemple une liste pi.setActiveTools() inversée. Les outils qui restent actifs conservent désormais leur ordre et les outils nouvellement activés sont ajoutés (#11495).
  • Correction du crash de pi.exec() pi avec RangeError: Invalid string length lorsqu'une commande imprimait plus de résultats que ne pouvait contenir une chaîne. La limite de sortie par défaut est la plus petite entre 256 Mio et la limite de chaîne d'exécution ; au-delà du plafond, la commande est terminée et le résultat a truncated: true et un code de sortie différent de zéro (#11360)
  • Correction de pi.exec() ne revenant jamais lorsqu'une commande ignorait SIGTERM après un délai d'attente ou un abandon. pi envoie désormais SIGKILL 5 secondes plus tard, comme prévu
  • Correction de pi install et pi remove ajoutant des entrées imbriquées de plus en plus profondes au npm package-lock.json lorsque le répertoire de l'agent est atteint via un lien symbolique, tel que ~/.pi lié à un référentiel dotfiles. pi transmet désormais le chemin réel résolu à npm (#11358)
  • La connexion MCP rejette désormais les points de terminaison d'autorisation et les autres URL de métadonnées OAuth qui ne sont pas http: ou https:. Auparavant, un serveur MCP malveillant pouvait fournir une URL file: ou un protocole personnalisé, que pi transmettait au gestionnaire d'URL de la plateforme.
  • Les téléchargements automatiques fd et rg ne récupèrent plus les binaires x86-64 sur ARM32 et d'autres architectures sans version prédéfinie. pi avertit désormais et recommande d'installer l'outil avec le gestionnaire de packages système (#11209)
  • Correction des lettres de classement de recherche /model dispersées sur une partie antérieure d'une entrée au-dessus d'une correspondance réelle, par exemple opus répertoriant gpt-oss-120b et claude-sonnet-4.5 avant claude-opus-4.1 (#11220, #11296)
  • Correction de la recherche /resume correspondant aux lettres dispersées n'importe où dans les messages et identifiants de session, par exemple 1024 correspondant à l'intérieur d'un UUID de session. Les noms de session et les répertoires de travail correspondent toujours de manière floue ; Les identifiants et le texte du message correspondent désormais uniquement en tant que sous-chaînes exactes (#11220, #11024, #11296).
  • Correction de l'export HTML affichant une page vierge pour les sessions avec des milliers d'entrées (#11225, #11293)
  • Correction de l'exportation HTML n'affichant pas les messages système : l'invite et les outils du système, ainsi que les mises à jour ultérieures des sections, comme après /reload. pi --export inclut désormais également l'invite système et les outils (#11261, #3464, #11290)
  • Correction de l'abandon d'une commande bash sur macOS exécutant parfois la commande suivante d'une liste telle que long_step; next_step. pi arrête désormais le groupe de processus avant de le tuer (#11252, #11289)
  • Correction des appels d'outils en streaming volumineux prenant trop de temps CPU et de mémoire car chaque delta ré-analysait les arguments accumulés. Les flux de proxy des fournisseurs et des agents analysent désormais chaque delta une fois, les outils de grammaire ne copient plus l'intégralité de leur entrée par delta et les moteurs de rendu d'outils interactifs s'exécutent au maximum une fois par image (#9265).
  • Correction de la boîte de dialogue de connexion ouvrant des URL de connexion qui ne sont pas des URL Web et imprimant des caractères de contrôle à partir des URL de connexion, de code de périphérique et d'informations, ce qui pouvait mettre fin à un lien hypertexte de terminal et envoyer des séquences d'échappement au terminal.
  • Correction de tui.select.pageUp et tui.select.pageDown étant ignorés dans la commande slash et la saisie semi-automatique de fichier, /settings, ainsi que dans les sélecteurs de modèle, de modèles étendus, de connexion, de fork, de /mcp et de lama.cpp. En mode plein écran, PageUp/PageDown déplacent désormais une liste ouverte ou un menu de saisie semi-automatique au lieu de faire défiler la transcription, et une touche de page liée à la saisie semi-automatique des pages Ctrl+V au lieu de coller une image (#7629, basé sur #7680 par @muyiyr).
  • Correction de la sortie de l'outil et de la commande ! affichant les paramètres des séquences de contrôle avec un préfixe <, = ou > sous forme de texte, par exemple 35;59;1M à partir d'un rapport de souris ESC[<35;59;1M ou 0;276;0c à partir d'une réponse de terminal ESC[>0;276;0c. Le texte après les séquences en mode clavier ESC= et ESC> est toujours conservé (#11377)
  • Correction de pi -e npm:<pkg> restant sur la version du premier téléchargement. À chaque démarrage et /reload, pi réinstalle désormais un package npm -e sans version exacte lorsque le registre a une version correspondante plus récente. pi -e git:<repo>@<branch> est également resté lors de sa première extraction et est maintenant récupéré et réinitialisé dans la branche ; une référence de hachage de validation déjà extraite n'est pas récupérée. Le mode hors ligne et les vérifications échouées conservent la copie en cache (#11375, #11590)
  • Correction des chemins Windows comparés en tenant compte de la casse. Lorsque le répertoire de travail et le répertoire personnel ne différaient que par la casse des lettres de lecteur (c:\Users\me vs C:\Users\me), les compétences dans ~/.agents/skills étaient chargées deux fois, en tant que compétences de projet et d'utilisateur, et étaient signalées comme collisions de noms. La même incompatibilité a également demandé à nouveau le projet enregistré trust, masqué les sessions dans un répertoire de session personnalisé de --continue et /resume et empêché pi remove de correspondre aux packages locaux configurés (#10488).
  • Correction des chemins à côté du répertoire personnel affichés avec un préfixe ~ cassé, par exemple /home/me2/project affiché comme ~2/project lorsque le répertoire personnel est /home/me
  • Correction de l'échec de pi mcp login -l et pi mcp logout -l avec Unknown option --local. bien que pi mcp add et pi mcp remove acceptent -l. Avec -l, ils exigent désormais que le serveur soit un serveur de projet. Les options inconnues sont désormais signalées comme saisies et un nom de serveur mal saisi obtient une suggestion, par exemple Did you mean "gurker"?.
  • Correction du nom pnpm de pi update pour les installations qui ne vivent que sous PNPM_HOME, par exemple un wrapper sous $PNPM_HOME/global-nub/. pi a dit "non géré par une installation globale de pnpm" ; il nomme désormais le gestionnaire de packages uniquement lorsque ce gestionnaire est propriétaire de l'installation (#7756)
  • Correction du collage, de la copie et de l'ouverture du navigateur pour la connexion échouant silencieusement sur WSL lorsque le répertoire de travail est profond. Les programmes Windows tels que powershell.exe et explorer.exe ne peuvent pas démarrer à partir d'un répertoire dont le chemin \\wsl.localhost\... dépasse 260 caractères ; pi démarre maintenant ces assistants à partir de / (#11592)
  • Correction de l'échec silencieux de l'éditeur externe, par exemple lorsque la commande de l'éditeur est erronée ou qu'un éditeur Windows ne peut pas démarrer à partir d'un répertoire WSL profond. pi affiche désormais un message d'état tel que External editor exited with code 1; prompt unchanged (#11592)
  • Correction de tool_search et du codemode searchTools() classant un outil en dessous des outils qui ne mentionnent que son nom dans leurs descriptions, par exemple peekaboo app classant mcp__peekaboo__app 14ème. Un outil correspondant à plus de mots de la requête se classe désormais au-dessus d'un mot correspondant à moins, un mot de requête dans le nom d'un outil obtient plus de scores que n'importe quel nombre de mentions dans sa description, un outil dont le nom complet est dans la requête obtient un gros bonus et les instructions longues du serveur ne diminuent plus les scores des outils de ce serveur (#11331).
  • Correction de tool_search et du mode code searchTools() ne trouvant rien pour les requêtes chinoises, japonaises, thaïlandaises et autres requêtes non-ASCII, car le tokenizer ne conservait que les lettres et chiffres ASCII. Les mots de n'importe quel script correspondent désormais, le texte sans espaces entre les mots tels que 搜索记录 est divisé en mots et le texte canoniquement équivalent tel que café et cafe\u0301 correspond (#10816, #11037 par @haoqixu).
  • Correction de l'arrêt de pi update avec git clean -fdx failed with code 1 sous Windows lorsqu'une autre session pi avait le module natif ou l'exécutable d'une extension git ouvert. Windows ne peut pas supprimer de tels fichiers, la mise à jour a donc laissé le nouveau code avec les anciennes dépendances. pi avertit maintenant, installe quand même les dépendances et réessaye le nettoyage lors de la prochaine mise à jour (#11597)
  • Correction des lignes d'outils et des réponses diffusées en continu mettant à nouveau en évidence le même code à chaque redessin. Une ligne de mode code en cours d'exécution a mis en évidence l'intégralité de son script à chaque mise à jour de progression et tick de minuterie, une ligne write complète de son fichier entier à chaque mise à jour et bascule d'expansion, un write en streaming ses 50 premières lignes sur chaque delta et une réponse en streaming à chaque bloc de code précédent sur chaque delta. Les lignes réutilisent désormais leur dernière surbrillance jusqu'à ce que le code, le thème ou les grammaires chargées changent, et les messages de l'assistant conservent leurs blocs Markdown rendus pendant la diffusion (#10971).
  • Correction des photos redimensionnées envoyées au format PNG de plusieurs mégaoctets même lorsque le format JPEG était beaucoup plus petit, provoquant l'échec ou l'expiration des requêtes volumineuses. Le redimensionnement de l'image essaie désormais d'abord le codage le plus petit (#11551).
  • Correction du succès du rapport pi update --extensions sans avertissement lorsque les métadonnées de registre obsolètes de npm laissaient un package dans son ancienne version. pi signale désormais les versions installées et attendues (#11536)
  • Correction des avertissements de validation de compétence étiquetés [Skill conflicts] même en l'absence de collision de noms. Ils sont désormais affichés sous [Skill warnings] (#11521)
  • Correction des descriptions des outils de mode code, y compris les types de sortie union entière et multiligne dans chaque requête. Les syndicats objecteurs résument désormais leurs domaines et leurs discriminateurs ; d'autres types multilignes pointent vers describeTool() pour la déclaration complète (#11501)
  • Correction de l'avis de démarrage de la portée du modèle restant dans le shell après avoir quitté le mode plein écran. Il apparaît maintenant dans l'en-tête plein écran de pi (#11508)

  • Correction d'échecs d'écriture de session laissant en mémoire des entrées absentes du disque, de sorte que les entrées ultérieures indiquaient des parents manquants et que les sessions reprises perdaient l'historique et les outils antérieurs (#11460).
  • Correction des résumés de branche /tree ignorant le niveau de réflexion de la session, ce qui pouvait amener les modèles de raisonnement à rejeter les demandes de résumé avec un effort none non pris en charge (#11444)
  • Correction de la pensée cachée avec une étiquette de pensée cachée vide ajoutant toujours des lignes vides avant les réponses et les appels d'outil (#11402)
  • Correction de l'installation et de la suppression des packages, impression de l'audit npm et des conseils de financement, y compris les instructions npm audit fix qui pourraient installer une deuxième copie de pi dans le répertoire du package (#11409)
  • Correction du remplacement d'un éditeur d'extension alors qu'une boîte de dialogue était ouverte, masquant la boîte de dialogue et la laissant sans réponse. Le nouvel éditeur apparaît désormais après la fermeture de la boîte de dialogue (#11431)
  • Correction des lignes de contexte grep décalées par rapport aux numéros de ligne de correspondance de ripgrep lorsqu'un fichier contient un seul retour chariot (#11398)

  • Correction du fork de session lent sur les systèmes de fichiers où l'ouverture de fichiers coûte cher en écrivant le fork via un seul handle de fichier (#11253)
  • Correction de pi.exec() corrompant les caractères UTF-8 répartis sur des morceaux stdout ou stderr (#11312)
  • Correction de pi.exec() renvoyant un stderr vide lorsqu'une commande ne pouvait pas être générée, comme un exécutable manquant. Il préserve désormais le message d'erreur d'apparition (#11257 par @muyiyr).
  • Correction d'un package configuré qui ne parvenait pas à installer un démarrage en panne. pi ignore désormais le package, signale un avertissement d'extension et réessaye au prochain démarrage ou /reload ; les commandes d'installation et de mise à jour explicites échouent toujours avec une sortie différente de zéro (#11304 par @Lincoln504)
  • Correction de l'exemple d'extension todo faisant planter le TUI lorsqu'un appel d'outil échouait la validation d'un argument (#8057 par @cyzlmh)
  • Mise à jour de undici vers 8.12.3 et de l'exemple d'extension Gondolin vers 0.14.0 pour les avis de sécurité
  • Correction des coûts totaux d'OpenRouter en utilisant les estimations du catalogue au lieu de la facturation rapportée pour les achèvements de chat et les messages anthropiques. Les totaux BYOK incluent à la fois les frais d'OpenRouter et les coûts en amont déclarés ; les coûts des composants restent des estimations du catalogue (#9980)
  • Correction des requêtes OpenCode Zen et OpenCode Go utilisant des points de terminaison partagés au lieu de leurs points de terminaison OpenAI, Anthropic, Google et System One spécifiques au protocole (#11434 par @vimtor)

  • Correction des modèles Kimi K3.1 Pro utilisant les paramètres de requête Kimi K2 sur Kimi Coding, Moonshot et OpenCode Go. Ils envoient désormais le bon effort de raisonnement, préservent les réflexions antérieures, acceptent les outils ajoutés au milieu de la conversation et utilisent les tarifs de la famille K3.
  • Correction de l'échec des requêtes Flash OpenCode DeepSeek V4.1 lorsqu'une longue conservation du cache envoyait le paramètre prompt_cache_retention non pris en charge.
  • Correction de l'échec de GPT-5.4 et GPT-5.5 avec Missing namespace for function_call après le passage d'un modèle qui avait appelé des outils (#11415).
  • Correction de l'échec des requêtes Bedrock Claude lorsque les outils stricts préférés dépassent les limites des outils stricts du fournisseur. Les requêtes réessayent désormais une fois avec les outils préférés non stricts tout en gardant les outils stricts requis stricts (#11416)
  • Correction des alias ~anthropic/claude-*-latest d'OpenRouter perdant la réflexion antérieure après les appels d'outils en utilisant les messages anthropiques API (#9534)
  • Correction des titres de terminaux contenant des caractères de contrôle pouvant injecter des séquences d'échappement de terminal et des flux de messages pi acceptant des index de blocs de contenu invalides
  • Correction des chemins et des jetons de séparation de sélection double click en plein écran sur ~, ., \ et + ; les caractères des mots correspondent désormais aux valeurs par défaut d'iTerm2 (#10980)
  • Correction de l'affichage mathématique plus large que la zone de contenu, divisé par retour à la ligne ; il revient désormais au LaTeX brut (#11483)
  • Correction des mots stylisés se terminant exactement à la largeur du retour à la ligne, en ajoutant un espace de début sur la ligne suivante et en barrant le remplissage de la ligne enveloppée (#10925)
  • Correction des résumés de branche /tree incluant les réponses échouées de l'assistant et le contenu original que les modifications contextuelles avaient masqué ou remplacé. Les résumés prennent désormais en compte les mêmes modifications de contexte que les requêtes en direct et le compactage (#11602).

Supprimé

  • Suppression de l'exemple d'extension natif du système d'exploitation sandbox/ et de sa dépendance. Utilisez l'exemple Gondolin ou le guide de conteneurisation.

pi v1.5.0

New Features

  • Extension update changelogs: see what changed in installed extension packages on the next fresh launch after an update. Package authors can choose the changelog path, and collapseChangelog condenses the notices. See Show a changelog.
  • Faster streaming: large tool calls are parsed incrementally, and code-heavy answers and tool rows reuse highlighting and rendered Markdown instead of repeating the work on every update. See Keep rendering responsive.
  • Custom self-update commands: use PI_SELF_UPDATE_COMMAND or selfUpdateCommand to update pi through a wrapper or another package manager. See Custom update command.
  • GPT-6.1 Terra: available through OpenAI, Azure OpenAI Responses, and OpenAI Codex, with tool search, mid-conversation thinking-level changes, and thinking off. Codex offers a 500K context window. See Models.

Breaking Changes

  • Tool argument validation runs on @earendil-works/pi-schema. TypeBox features outside JSON Schema (Type.Refine(), Type.BigInt(), Type.Undefined(), codecs, Format.Set() formats) no longer apply to tool arguments; see Tool parameter schemas and TypeBox. Plain JSON Schema tools, including MCP tools, now get the same coercion as TypeBox tools, such as converting numeric strings and wrapping a single value into an array. Validation failures the model sees list pi-schema's messages (- path: missing, - limit: expected number, got string) instead of TypeBox's (must have required properties path, must be number).

Added

  • Extension packages can now show their changelog after an update. Pi reads pi.changelogPath from the package's package.json, or CHANGELOG.md in the package root, and on the next fresh launch shows entries newer than the last seen version under "Extension Updates". The collapseChangelog setting condenses this to one line per package (#5958, #8790)
  • pi.exec() accepts a maxBuffer option that limits stdout and stderr combined, and its result has a truncated field that is true when output exceeded the limit (#11360)
  • Device-code login (for example GitHub Copilot) now opens the verification page and copies the code when you press Enter. Providers can turn either action off with openBrowserOnConfirm: false or copyCodeOnConfirm: false (#9282, #9301)
  • pi update can update Pi through a wrapper or another package manager. Set PI_SELF_UPDATE_COMMAND (for example mise use -g npm:{packageName}@{version}) or the global selfUpdateCommand setting; pi update runs it when pi.dev reports a newer release and fills {packageName}, {version}, and {installSpec} from that release. See Custom update command (#7756, #5607)
  • Extensions can format the user's configured keybindings with keyText() and keyHint() from the tool render context and the message and entry renderer options. Importing these functions from @earendil-works/pi-coding-agent can resolve the extension's own copy of the package, which does not see pi's keybindings, so hints such as keyHint("app.tools.expand", "to expand") rendered without the key. The docs now recommend the injected functions (#4748)
  • Added persisted session-entry messageId and ISO timestamp to MarkdownTransformContext. They are available when rendering saved entries and undefined for live rendering (#7952 by @vipentti)
  • Added a blocked option to inline ctx.ui.custom() components so approval prompts and other custom dialogs can report that pi is waiting for user input. Overlays ignore the option. See Custom screens and overlays (#11428)
  • Added Usage.cost.totalFromProvider to distinguish billed totals from catalog estimates in SDK and extension usage data; combined usage is marked provider-reported only when every part is (#11178)
  • Added concrete responseModel metadata to messages from pi-messages providers such as Radius, including when a virtual model is requested. See AssistantMessage (#11265)
  • Added GPT-6.1 Terra for OpenAI, Azure OpenAI Responses, and OpenAI Codex, with tool search and mid-conversation thinking-level changes. It supports thinking off; Codex offers a 500K context window

Changed

  • Extensions keep importing Type, Static and TSchema from @earendil-works/pi-ai: Pi maps that import to pi-ai's compat entry plus the TypeBox it bundles, now that pi-ai itself no longer re-exports TypeBox, and its StringEnum there stays a TypeBox TUnsafe<T>. The built-in tool factories (createReadTool() and the others) return TypeBoxAgentTool<typeof schema>, which keeps params typed for TypeBox.
  • Tightened system prompt
  • pi update for installs from the pi.dev installer no longer passes --min-release-age=0 to npm ci. The release lockfile pins every package, so the flag had no effect, and security scanners that block it stopped the update (#11262)
  • /model and /scoped-models now show a model's name next to its ID when the name adds words the ID lacks, such as a renamed models.json override (#5916, #11347)
  • MCP OAuth sign-in now uses pi's Client ID Metadata Document by default when the authorization server supports it for public clients, and registers a client dynamically otherwise, like Codex, Claude Code, and opencode. Clients registered before stay in use while their redirect URI matches. The new default oauth.clientRegistration: "auto" registers when clientName or a non-default callbackUrl is set; "dcr" always registers. pi mcp add --oauth-client-registration sets the mode (#11426)
  • Changed the default OpenAI model from gpt-5.5 to gpt-6.1-sol, including after ChatGPT sign-in when no model is selected (#11442)
  • Updated the built-in model catalog to models.dev v2. Realtime and image-only models are no longer offered as chat models; newer OpenAI and Google chat models are included

Fixed

  • Updated glob matching to prevent denial of service from amplified glob patterns.
  • Fixed a saved "Do not trust" decision being ignored for projects without trust-requiring resources, for example a folder with only AGENTS.md. pi auto-trusted such projects, so ctx.isProjectTrusted() returned true and package commands treated them as trusted. A saved decision in trust.json now takes precedence; auto-trust applies only when no decision is saved (#10947)
  • Fixed Shift+Enter queueing a follow-up instead of inserting a newline in Apple Terminal setups that send ESC + Return. pi now checks the local Shift key state for that sequence, as it already did for plain Return; Alt+Enter without Shift still queues a follow-up (#11559)
  • Fixed the working status (OSC 7501) disappearing in Rex and iTerm2 during runs in regular TUI mode. Rendered messages wrote OSC 133 prompt markers to the terminal, which the terminal treats as a new shell prompt; regular mode no longer writes them (#11519)
  • Fixed compaction, branch summaries, and bug-report summaries in SDK sessions passing the stored OAuth token back to the model runtime as an explicit API key. Provider auth that treats explicit keys differently from stored OAuth now sees the OAuth login, as normal prompts do (#11520)
  • Fixed a redundant system prompt update (tools, rules) when an extension set the same active tools in a different order, for example a reversed pi.setActiveTools() list. Tools that stay active now keep their order and newly activated tools are appended (#11495)
  • Fixed pi.exec() crashing pi with RangeError: Invalid string length when a command printed more output than fits in a string. The default output cap is the smaller of 256 MiB and the runtime string limit; past the cap, the command is terminated and the result has truncated: true and a nonzero exit code (#11360)
  • Fixed pi.exec() never returning when a command ignored SIGTERM after a timeout or abort. pi now sends SIGKILL 5 seconds later, as intended
  • Fixed pi install and pi remove adding ever deeper nested entries to the npm package-lock.json when the agent directory is reached through a symlink, such as ~/.pi linked into a dotfiles repo. pi now passes the resolved real path to npm (#11358)
  • MCP sign-in now rejects authorization endpoints and other OAuth metadata URLs that are not http: or https:. Before, a malicious MCP server could supply a file: or custom protocol URL, which pi passed to the platform URL handler.
  • Automatic fd and rg downloads no longer fetch x86-64 binaries on ARM32 and other architectures without a prebuilt release. pi now warns and recommends installing the tool with the system package manager (#11209)
  • Fixed /model search ranking letters scattered over an earlier part of an entry above a real match, for example opus listing gpt-oss-120b and claude-sonnet-4.5 before claude-opus-4.1 (#11220, #11296)
  • Fixed /resume search matching scattered letters anywhere in session messages and IDs, for example 1024 matching inside a session UUID. Session names and working directories still match fuzzily; IDs and message text now match only as exact substrings (#11220, #11024, #11296)
  • Fixed HTML export showing a blank page for sessions with thousands of entries (#11225, #11293)
  • Fixed HTML export not showing system messages: the system prompt and tools, and later section updates such as after /reload. pi --export now includes the system prompt and tools too (#11261, #3464, #11290)
  • Fixed aborting a bash command on macOS sometimes running the next command of a list such as long_step; next_step. pi now stops the process group before killing it (#11252, #11289)
  • Fixed large streamed tool calls taking excessive CPU time and memory because every delta re-parsed the accumulated arguments. Providers and agent proxy streams now parse each delta once, grammar tools no longer copy their entire input per delta, and interactive tool renderers run at most once per frame (#9265)
  • Fixed the login dialog opening sign-in URLs that are not web URLs, and printing control characters from sign-in, device-code, and info URLs, which could end a terminal hyperlink and send escape sequences to the terminal
  • Fixed tui.select.pageUp and tui.select.pageDown being ignored in slash command and file autocomplete, /settings, and the model, scoped models, login, fork, /mcp, and llama.cpp selectors. In fullscreen mode, PageUp/PageDown now move an open list or autocomplete menu instead of scrolling the transcript, and a page key bound to Ctrl+V pages autocomplete instead of pasting an image (#7629, based on #7680 by @muyiyr)
  • Fixed tool output and ! command output showing the parameters of control sequences with a <, = or > prefix as text, for example 35;59;1M from a mouse report ESC[<35;59;1M or 0;276;0c from a terminal reply ESC[>0;276;0c. Text after the keypad-mode sequences ESC= and ESC> is still kept (#11377)
  • Fixed pi -e npm:<pkg> staying on the version from the first download. On each start and /reload, pi now reinstalls an -e npm package without an exact version when the registry has a newer matching version. pi -e git:<repo>@<branch> likewise stayed on its first checkout and is now fetched and reset to the branch; a commit-hash ref that is already checked out is not fetched. Offline mode and failed checks keep the cached copy (#11375, #11590)
  • Fixed Windows paths being compared case-sensitively. When the working directory and home directory differed only in drive-letter casing (c:\Users\me vs C:\Users\me), skills in ~/.agents/skills loaded twice, as project and user skills, and were reported as name collisions. The same mismatch also re-asked for saved project trust, hid sessions in a custom session directory from --continue and /resume, and stopped pi remove from matching configured local packages (#10488)
  • Fixed paths next to the home directory being shown with a broken ~ prefix, for example /home/me2/project shown as ~2/project when home is /home/me
  • Fixed pi mcp login -l and pi mcp logout -l failing with Unknown option --local. although pi mcp add and pi mcp remove accept -l. With -l, they now require the server to be a project server. Unknown options are now reported as typed, and a mistyped server name gets a suggestion, for example Did you mean "gurker"?
  • Fixed pi update naming pnpm for installs that only live under PNPM_HOME, for example a wrapper under $PNPM_HOME/global-nub/. pi said "not managed by a global pnpm install"; it now names the package manager only when that manager owns the install (#7756)
  • Fixed image paste, copy, and opening the browser for sign-in failing silently on WSL when the working directory is deep. Windows programs such as powershell.exe and explorer.exe cannot start from a directory whose \\wsl.localhost\... path exceeds 260 characters; pi now starts these helpers from / (#11592)
  • Fixed the external editor failing silently, for example when the editor command is wrong or a Windows editor cannot start from a deep WSL directory. pi now shows a status message such as External editor exited with code 1; prompt unchanged (#11592)
  • Fixed tool_search and codemode searchTools() ranking a tool below tools that only mention its name in their descriptions, for example peekaboo app ranking mcp__peekaboo__app 14th. A tool matching more of the query's words now ranks above one matching fewer, a query word in a tool's name scores more than any number of mentions in its description, a tool whose whole name is in the query gets a large bonus, and long server instructions no longer lower the scores of that server's tools (#11331)
  • Fixed tool_search and codemode searchTools() finding nothing for Chinese, Japanese, Thai, and other non-ASCII queries, because the tokenizer kept only ASCII letters and digits. Words in any script now match, text without spaces between words such as 搜索记录 is split into words, and canonically equivalent text such as café and cafe\u0301 matches (#10816, #11037 by @haoqixu)
  • Fixed pi update stopping with git clean -fdx failed with code 1 on Windows when another pi session had a git extension's native module or executable open. Windows cannot delete such files, so the update left the new code with the old dependencies. pi now warns, installs the dependencies anyway, and retries the clean on the next update (#11597)
  • Fixed tool rows and streamed answers highlighting the same code again on every redraw. A running codemode row highlighted its whole script on every progress update and timer tick, a complete write row its whole file on every update and expand toggle, a streamed write its first 50 lines on every delta, and a streamed answer every earlier code block on every delta. Rows now reuse their last highlighting until the code, theme, or loaded grammars change, and assistant messages keep their rendered Markdown blocks while streaming (#10971)
  • Fixed resized photos being sent as multi-megabyte PNGs even when JPEG was much smaller, causing large requests to fail or time out. Image resizing now tries the smaller encoding first (#11551)
  • Fixed pi update --extensions reporting success without warning when npm's stale registry metadata left a package at its old version. pi now reports the installed and expected versions (#11536)
  • Fixed skill validation warnings being labeled [Skill conflicts] even when there was no name collision. They are now shown under [Skill warnings] (#11521)
  • Fixed codemode tool descriptions including entire union and multi-line output types in every request. Object unions now summarize their fields and discriminators; other multi-line types point to describeTool() for the full declaration (#11501)
  • Fixed the model-scope startup notice being left in the shell after exiting fullscreen mode. It now appears inside pi's fullscreen header (#11508)
  • Fixed startup from a deleted working directory crashing with an uncaught uv_cwd stack trace. pi now asks the user to change to an existing directory (#11509)
  • Fixed failed session writes leaving entries in memory that were absent from disk, so later entries pointed to missing parents and resumed sessions lost earlier history and tools (#11460)
  • Fixed /tree branch summaries ignoring the session's thinking level, which could make reasoning models reject summary requests with an unsupported none effort (#11444)
  • Fixed hidden thinking with an empty hidden-thinking label still adding blank rows before answers and tool calls (#11402)
  • Fixed package installation and removal printing npm audit and funding advice, including npm audit fix instructions that could install a second copy of pi into the package directory (#11409)
  • Fixed replacing an extension editor while a dialog was open hiding the dialog and leaving it unanswerable. The new editor now appears after the dialog closes (#11431)
  • Fixed grep context lines being offset from ripgrep's match line numbers when a file contains a lone carriage return (#11398)
  • Fixed --model <provider>/<id> failing for provider IDs containing slashes, such as URL-derived llama.cpp provider IDs (#11394)
  • Fixed slow session forking on filesystems where opening files is expensive by writing the fork through one file handle (#11253)
  • Fixed pi.exec() corrupting UTF-8 characters split across stdout or stderr chunks (#11312)
  • Fixed pi.exec() returning empty stderr when a command could not be spawned, such as a missing executable. It now preserves the spawn error message (#11257 by @muyiyr)
  • Fixed a configured package failing to install crashing startup. pi now skips the package, reports an extension warning, and retries on the next start or /reload; explicit install and update commands still fail with a nonzero exit (#11304 by @Lincoln504)
  • Fixed the todo extension example crashing the TUI when a tool call failed argument validation (#8057 by @cyzlmh)
  • Updated undici to 8.12.3 and the Gondolin extension example to 0.14.0 for security advisories
  • Fixed OpenRouter cost totals using catalog estimates instead of reported billing for Chat Completions and Anthropic Messages. BYOK totals include both OpenRouter charges and reported upstream costs; component costs remain catalog estimates (#9980)
  • Fixed OpenCode Zen and OpenCode Go requests using shared endpoints instead of their protocol-specific OpenAI, Anthropic, Google, and System One endpoints (#11434 by @vimtor)
  • Fixed Zhipu/Z.ai usage-limit errors (code 1308) being treated as transient HTTP 429 errors, causing automatic retries that cannot succeed until the usage cap resets (#11537)
  • Fixed LiteLLM's ContextWindowExceededError not being recognized as context overflow (#11492)
  • Fixed Gemini tool schemas sending unsupported const keywords. They are now converted to single-value enum schemas without rewriting literal data in defaults, examples, or enum values, or losing properties named __proto__ (#11308)
  • Fixed the faux provider counting simulated cache-write tokens as both input and cache writes
  • Fixed Orca terminals falling back to text for inline images. Orca is now recognized as supporting true color and hyperlinks, and Kitty images when it advertises ORCA_IMAGE_PROTOCOL=kitty (#9329 by @XRX193)
  • Fixed bare Markdown URLs swallowing following CJK punctuation and text; explicit Markdown links and angle autolinks are unchanged (#10934 by @haoqixu)
  • Fixed Kitty-protocol F1–F12 shortcuts, including modified function keys, not being recognized, and F13+ and other functional keys inserting invisible private-use characters into the editor (#11419, #11345)
  • Fixed Kitty images inside padded or colored boxes disappearing when their first row scrolled above the fullscreen viewport. Partially visible images are now cropped correctly, including beside other text
  • Fixed deeply nested Markdown blockquotes producing exponentially many lines, hanging or crashing rendering once their borders exhausted the available width (#11272)
  • Fixed Claude sessions failing with role 'system' must precede an 'assistant' message when a system update was followed by an empty or reasoning-only assistant reply (#11091)
  • Fixed Claude mid-conversation thinking-level changes failing with Invalid effort level on accounts whose organization caps effort below high (#10063)
  • Fixed Kimi K3.1 Pro models using Kimi K2 request settings on Kimi Coding, Moonshot, and OpenCode Go. They now send the correct reasoning effort, preserve earlier thinking, accept tools added mid-conversation, and use K3-family pricing
  • Fixed OpenCode DeepSeek V4.1 Flash requests failing when long cache retention sent the unsupported prompt_cache_retention parameter
  • Fixed GPT-5.4 and GPT-5.5 failing with Missing namespace for function_call after switching from a model that had called tools (#11415)
  • Fixed Bedrock Claude requests failing when preferred strict tools exceed the provider's strict-tool limits. Requests now retry once with preferred tools non-strict while keeping required strict tools strict (#11416)
  • Fixed OpenRouter's ~anthropic/claude-*-latest aliases losing earlier thinking after tool calls by using the Anthropic Messages API (#9534)
  • Fixed terminal titles containing control characters being able to inject terminal escape sequences, and pi-messages streams accepting invalid content-block indices
  • Fixed fullscreen double-click selection splitting paths and tokens at ~, ., \, and +; word characters now match iTerm2's defaults (#10980)
  • Fixed display math wider than the content area being split apart by line wrapping; it now falls back to raw LaTeX (#11483)
  • Fixed styled words ending exactly at the wrap width adding a leading space on the next line, and strikethrough leaking into wrapped-line padding (#10925)
  • Fixed /tree branch summaries including failed assistant replies and original content that context edits had hidden or replaced. Summaries now honor the same context edits as live requests and compaction (#11602)

Removed

  • Removed the native OS sandbox/ extension example and its dependency. Use the Gondolin example or the containerization guide.
