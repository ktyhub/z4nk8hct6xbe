pi v1.5.1

Nouvelles fonctionnalités

  • Connexion et déconnexion Shell : utilisez pi auth login <provider> et pi auth logout <provider> sans démarrer de session, avec la clé API et les options de connexion sans navigateur. Voir [Commandes d'informations d'identification] (https://github.com/earendil-works/pi/blob/v1.5.1/packages/coding-agent/docs/cli.md#credential-commands).
  • Réchauffement du cache d'invite d'inactivité : les caches éligibles restent désormais chauds jusqu'à 30 minutes entre les exécutions, lorsqu'une actualisation est censée s'autofinancer. Voir cacheWarming.
  • Fils de messages anthropiques : les requêtes envoient uniquement de nouveaux messages pendant que le serveur poursuit la conversation, avec un repli des requêtes complètes lorsque le contexte précédent change. Voir Compatibilité anthropique.
  • Diagrammes Mermaid plus riches : diagrammes circulaires, styles définis par l'auteur, étiquettes clickable sur les terminaux pris en charge et diagrammes dans des résumés de branchement et de compactage étendus. Voir [Paramètres d'affichage] (https://github.com/earendil-works/pi/blob/v1.5.1/packages/coding-agent/docs/settings.md#terminal-and-display) et [Transformateurs Markdown] (https://github.com/earendil-works/pi/blob/v1.5.1/packages/coding-agent/docs/extensions.md#piregistermarkdowntransformertransformer-options).
  • Classificateurs Copilot GitHub : appelez Microsoft-Decision-1 via le mode code models.classify() pour les décisions et probabilités typées. Voir [Utiliser des modèles de classificateur] (https://github.com/earendil-works/pi/blob/v1.5.1/packages/coding-agent/docs/models.md#use-classifier-models).
  • Résumés des mises à jour des packages : pi update --extensions rapporte la version npm de chaque package ou la modification du commit git et distingue les mises à jour inchangées, ignorées et averties. Voir [Mettre à jour Pi ou les packages] (https://github.com/earendil-works/pi/blob/v1.5.1/packages/coding-agent/docs/cli.md#update-pi-or-packages).

Modifications radicales

  • Les rappels personnalisés GrepOperations.readFile ne sont plus appelés pour les lignes de contexte. Le champ reste accepté comme facultatif et obsolète, de sorte que les intégrations existantes sont toujours compilées. L'outil grep prend désormais les lignes de contexte de ripgrep et ne lit plus lui-même les fichiers correspondants. Pour rechercher un système distant, remplacez le execute() de grep ; voir Exécution à distance (#9276)
  • Les modèles compatibles OpenAI n'envoient plus "tools": [] lorsque tous les outils sont désactivés dans une session qui a utilisé des outils ; le champ est omis. Cela corrige 400 erreurs (tools must not be an empty array) de vLLM 0.20+, également derrière LiteLLM. Si votre proxy nécessite tools une fois que l'historique contient des appels d'outils, comme les anciennes versions de LiteLLM devant Anthropic, définissez compat.requiresToolsWithToolHistory: true pour ce modèle dans models.json (#11843).

Ajouté

  • pi update répertorie désormais chaque package mis à jour avec sa version npm ou son changement de commit git, par exemple npm:foo 1.2.0 -> 1.3.0, et imprime Packages are already up to date lorsque rien n'a changé. Lorsque rien n'a changé mais qu'une mise à jour a imprimé un avertissement, par exemple parce que npm a laissé l'ancienne version installée après avoir résolu les métadonnées de registre obsolètes, il imprime No packages were updated, see the warnings above à la place ; en mode hors ligne, il imprime Skipped package updates (offline mode). PackageManager.update() signale chaque package modifié comme un nouvel événement de progression result dont message contient cette ligne (#11707, #11711)
  • Les sessions Anthropic utilisent désormais des fils de discussion : chaque requête envoie uniquement les nouveaux messages et le serveur continue à partir de la réponse précédente, revenant à la requête complète lorsque la conversation change (par exemple après un compactage ou un changement de liste d'outils). Activé par défaut pour le fournisseur anthropic sur api.anthropic.com ; définissez compat.supportsMessageThreads dans models.json pour l'activer pour les passerelles qui transmettent le champ thread, ou pour le désactiver. Le réchauffement du cache ne touche pas le thread de la session (#11545)
  • pi.registerMarkdownTransformer() prend un { messageTypes } en option qui sélectionne les surfaces Markdown sur lesquelles un transformateur fonctionne. Outre l'utilisateur, l'assistant et la réflexion Markdown, les transformateurs peuvent désormais opter pour custom (messages personnalisés et blocs de compétences), summary (résumés de branchement et de compactage) et changelog (Quoi de neuf, /changelog, l'avis de mises à jour d'extension et la note de mise à jour disponible). Sans options, un transformateur s'exécute sur l'utilisateur, l'assistant et pense Markdown comme avant. Le moteur de rendu Mermaid intégré dessine désormais également des diagrammes dans des résumés de branchement et de compactage étendus.
  • pi auth login <provider> se connecte à un fournisseur depuis le shell sans démarrer de session, par exemple pi auth login radius. Il se connecte avec un compte dans le navigateur et se ferme ; --api-key enregistre une clé API à la place et --no-browser utilise à la place le code de l'appareil ou la connexion par copie du code. La connexion à Radius configure également le serveur Radius MCP. pi auth logout <provider> supprime les informations d'identification stockées, comme /logout
  • Les superpositions ctx.ui.custom() honorent désormais l'option blocked : pi signale l'état du programme bloqué (OSC 7501) à partir du moment où la superposition est affichée jusqu'à ce qu'elle appelle done(), également lorsqu'elle est masquée avec setHidden(). La fermeture d'une superposition bloque les autres questions ouvertes (#11816)
  • Ajout du fournisseur qwen-token-plan-individual-cn pour Qwen Token Plan Individual sur le point de terminaison chinois, en utilisant QWEN_TOKEN_PLAN_CN_API_KEY (#7989 par @bigoldcat123)
  • Ajout de la prise en charge du classificateur Microsoft-Decision-1 via GitHub Copilot, y compris le mode code models.classify() (#11679 par @Marvae)
  • Ajout de compat.promptCacheKeyMode ("auto", "enabled" ou "disabled") pour activer les clés de cache d'invite pour les proxys compatibles ou les omettre pour les points de terminaison qui les rejettent. Définissez-le dans models.json lors de l'utilisation de pi (#9442 par @dannote)
  • Ajout de compat.requiresNonNullAssistantContent pour les points de terminaison compatibles OpenAI qui nécessitent une chaîne vide au lieu de null dans les messages de l'assistant contenant uniquement des appels d'outils. Définissez-le dans models.json lors de l'utilisation de pi (#8118 par @gaoyk19)
  • Ajout de la coloration syntaxique pour les fichiers Dart, Nix, Groovy et Gradle dans les vues en lecture et en écriture (#11643)
  • Ajout du GLM 5.3 à la liste autorisée des modèles individuels du plan de jeton Qwen (#11658)
  • Ajout de Claude Fable 5.2 (claude-fable-5-2) au fournisseur anthropic (8 $/40 $ par million de jetons d'entrée/sortie, contexte 1M, sortie 128K). Comme le Fable 5.1, il utilise l'effort par message et les messages système à mi-conversation ; Les demandes de refus de ses classificateurs de sécurité avant toute sortie sont répondues par Claude Opus 5 via un repli côté serveur et facturées au prix de l'Opus 5. Claude Fable 5.2 et Mythos 5.2 sur d'autres fournisseurs, tels que anthropic/claude-fable-5.2 d'OpenRouter, bénéficient du même support d'effort par message

Modifié

  • Le modèle par défaut du fournisseur anthropic est désormais Claude Opus 5.5 (claude-opus-5-5) au lieu de Claude Opus 4.8
  • Modèles par défaut déplacés vers des modèles plus récents au même prix ou à un prix inférieur : amazon-bedrock Claude Opus 5.5, azure GPT-6.1 Sol, google et google-vertex Gemini 4 Argon, vercel-ai-gateway GLM 5.3, baseten GLM 5.3, minimax et minimax-cn MiniMax-M3, qwen-token-plan et qwen-token-plan-cn Qwen3.8 Max, opencode-go Kimi K3.1 Pro et Kimi K2.7 Code au lieu de Kimi K2.6 pour moonshotai, moonshotai-cn, huggingface, opencode, openrouter, cloudflare-workers-ai et cloudflare-ai-gateway
  • cacheWarming est désormais par défaut "idle" au lieu de "streaming" : pi maintient également les caches d'invites éligibles au chaud pendant 30 minutes maximum entre les exécutions de l'agent, mais uniquement lorsqu'une actualisation est censée être rentable. Définissez "cacheWarming": "streaming" dans les paramètres globaux pour le comportement précédent
  • Les réchauffements de cache consécutifs s'affichent désormais sous la forme d'une seule ligne Cache warmed: $<total> avec le coût cumulé au lieu d'une ligne par réchauffement.
  • Le fournisseur OpenAI Codex est à nouveau affiché comme "OpenAI Codex" au lieu de "OpenAI Codex (legacy)" dans /login et le sélecteur de modèle
  • Les listes de fournisseurs /login et /logout et les complétions /login <provider> affichent désormais en premier les partenaires préférés Radius et OpenRouter, puis tous les autres fournisseurs par ordre alphabétique. Dans les listes de fournisseurs, les partenaires sont marqués ✦, la ligne Radius sélectionnée scintille dans les couleurs du logo Radius et la ligne OpenRouter sélectionnée brille dans la couleur de la marque OpenRouter (citron vert sur les thèmes sombres, violet sur les thèmes clairs).
  • Rendu Mermaid du terminal mis à niveau pour prendre en charge davantage de types de diagrammes, notamment les diagrammes circulaires, les styles définis par l'auteur et les étiquettes clickable sur les terminaux prenant en charge les hyperliens (#8158 par @xl0).

Corrigé

  • Correction de la correspondance glob de l'outil grep à partir du dossier dans lequel pi a été démarré au lieu de path : avec path: "repo", glob: "migrations/main/*.js" renvoyait No matches found même si repo/migrations/main/a.js existe. Les Globs sont désormais relatifs à path, la même forme dans laquelle grep imprime ses résultats, également lorsque path est un lien symbolique. Un ./ (./src/*.ts) en tête est ignoré au lieu de ne correspondre à rien (#11807, #10998).
  • Correction des arguments du modèle d'invite supprimant les apostrophes et fusionnant les mots : une apostrophe à l'intérieur d'un mot, comme dans doesn't, n'ouvre plus une citation ; une citation sans correspondance finale est conservée sous forme de texte ; et \" dans "..." (ou \' dans '...') donne une citation littérale (#11861)
  • Correction de l'outil bash signalant uniquement Command timed out lorsque la commande était déjà terminée, mais un processus en arrière-plan qu'il avait démarré continuait à écrire sur sa sortie jusqu'à l'expiration du délai. L'erreur signale désormais également le code de sortie du shell et le moment où il s'est terminé (#11613)
  • Les images des messages de pilotage et de suivi, y compris prompt() pendant la diffusion, sont désormais redimensionnées comme les images dans les invites inactives au lieu d'être envoyées et enregistrées en taille réelle (#11738).
  • L'échec de l'actualisation du jeton d'une connexion MCP n'enregistre plus un OAuth client ou ne remplace le vérificateur PKCE d'une connexion en cours, ce qui a entraîné l'échec de cette connexion. La connexion MCP actualise désormais les jetons stockés avec le client stocké même lorsque le port de rappel de bouclage a changé, au lieu d'enregistrer un nouveau client et d'ouvrir le navigateur. Ctrl+C dans /mcp et le --timeout de pi mcp login arrêtent désormais également une connexion pendant qu'il attend jusqu'à 25 secondes pour l'actualisation du jeton d'un autre processus pi, et un verrouillage d'actualisation qui échoue pour une autre raison que cette attente fait désormais échouer la connexion au lieu d'ouvrir le navigateur.
  • Correction de pi mcp list signalant que les serveurs MCP avec "auth": { "provider": "<provider>" }, tels que Radius, nécessitaient une connexion bien que le fournisseur soit connecté : la commande shell n'envoyait aucun jeton. Il envoie désormais le jeton /login du fournisseur et l'actualise lorsqu'il expire. Pour ces serveurs, l'indice de connexion nomme /login <provider> au lieu de pi mcp login, et pi mcp login et pi mcp logout pointent vers /login et /logout au lieu d'échouer avec "n'utilise pas OAuth".
  • Correction du mode RPC ignorant le ctx.shutdown() d'une extension lorsqu'il est inactif, par exemple à partir d'un timer : le processus continuait à s'exécuter jusqu'à ce que le client envoie une autre commande. pi s'arrête désormais immédiatement lorsqu'il est inactif, et un arrêt demandé par une commande d'extension attend que la réponse prompt de la commande soit écrite (#11599)
  • Correction des notes changelog se répétant à chaque nouveau lancement lorsque la version du package installée a un suffixe préliminaire, tel que 0.1.5-20261020.7 : la version enregistrée était lue comme 0.1.0, donc les notes 0.1.1 à 0.1.5 étaient comptées comme nouvelles à chaque fois. Une version enregistrée sans major.minor.patch n'affiche désormais aucune note et est remplacée par la version installée, au lieu d'afficher l'intégralité du changelog (#11703)
  • Correction du mode RPC coupant le nettoyage à l'arrêt, comme l'actualisation d'un jeton MCP en attente, lorsque stdin se fermait et que SIGTERM arrivait ensemble, ce que font les gestionnaires de processus comme Paseo et systemd. Pi a perdu le jeton actualisé et le serveur MCP a révoqué la connexion. Une fois qu'un arrêt a commencé, un stdin EOF ou un seul signal ne l'interrompt plus ; un deuxième signal sort toujours immédiatement. De même, le mode d'impression ne meurt plus à cause d'un signal arrivant lors de son nettoyage final (#11599).
  • Correction de l'outil grep lisant chaque fichier correspondant en mémoire lorsque context était défini, ce qui manquait de mémoire sur les fichiers volumineux ; le contexte vient désormais de ripgrep, qui corrige également les fichiers UTF-16 et les CR isolés dans les lignes correspondantes, et l'avis de limite de correspondance n'apparaît plus lorsqu'il existe exactement des correspondances limit (#9276, #11423)
  • Correction de l'outil de recherche signalant la limite de résultat lorsque exactement les fichiers limit correspondent, et limit: 0 dans find et ls renvoyant chaque résultat ou une liste vide ; les limites inférieures à 1 signifient désormais 1 (#7121)
  • Correction des lignes de correspondance grep, de la sortie en mode code, des résumés de compactage des résultats de l'outil, des erreurs MCP et des résumés du serveur coupant un emoji ou un autre caractère non-BMP en deux lors de la troncature, ce qui laissait un substitut solitaire non valide dans le texte (#7121)
  • Correction de l'outil de recherche sous Windows ne renvoyant aucun résultat pour les modèles avec des séparateurs Windows tels que src\**\*.ts, et pour chaque modèle de chemin tel que src/**/*.ts avec fd 10.5.1, que pi télécharge maintenant. Les modèles de chemin Windows correspondent désormais de la même manière avec chaque version de fd : src/**/*.ts trouve également les fichiers directement dans src/, et src/*.ts ne trouve plus de fichiers dans les sous-répertoires (#9262)
  • Correction de l'outil de lecture chargeant des fichiers entiers en mémoire, qui manquait de mémoire sur les gros fichiers même avec offset/limit ; il diffuse désormais le fichier et ne conserve que les lignes affichées. Le ReadOperations personnalisé peut également diffuser en fournissant le nouveau createReadStream en option (#9654).
  • Correction des connexions OAuth telles que openai et anthropic échouant avec invalid_grant après l'arrêt de pi alors qu'il actualisait un jeton expiré, par exemple un RPC client qui arrête pi juste après le démarrage pendant l'actualisation du catalogue en arrière-plan. Le point de terminaison du jeton avait déjà remplacé le jeton d'actualisation, mais pi s'est arrêté avant d'enregistrer le nouveau. En quittant, pi attend désormais qu'une actualisation de jeton en cours soit enregistrée (#11692)
  • Correction de Ctrl+P ne passant pas au seul modèle concerné (ou au seul modèle disponible) lorsque le modèle actif est un autre ; il indiquait à la place "Un seul modèle dans la portée". Cycling en avant à partir d'un modèle en dehors de la portée sélectionne désormais également le premier modèle étendu au lieu de l'ignorer (#11806)
  • Correction du /reload et des commutateurs de session laissant les superpositions d'extensions à l'écran lorsqu'une extension avait plus d'un ctx.ui.custom({ overlay: true }) ouvert : seule la superposition la plus haute était supprimée, et les autres gardaient le focus et la saisie même si l'extension qui les ouvrait avait disparu. Toutes les superpositions d'extensions, y compris celles masquées, sont désormais supprimées et supprimées ; les propres superpositions de pi restent ouvertes
  • Correction de la connexion /mcp restant sur « Connexion en cours… » pendant quelques minutes après une connexion réussie au navigateur, avec Ctrl+C ne faisant rien : pi attendait que le navigateur abandonne une connexion inutilisée au port de rappel OAuth. Le serveur de rappel ferme désormais les connexions restantes lorsqu'il s'arrête (#11311)
  • Correction de l'abandon de pi (zsh: abort) après des lectures d'images répétées, signalées sur macOS arm64 avec le nœud 24.16. Chaque redimensionnement d'image démarre un thread de travail, et pi n'a pas attendu qu'il s'arrête, donc le redimensionnement suivant a démarré un nouveau thread de travail alors que le précédent était encore en train de s'arrêter. Le crash est très probablement un bug de Node déclenché par ce chevauchement et qui n'a pas pu être reproduit sous Linux ; l'image se redimensionne maintenant et attend que le travailleur précédent s'arrête, ce qui ajoute environ 15 ms par image (#10695)
  • Correction de tool_search et searchTools() ne trouvant pas d'outil par noms de propriétés et descriptions derrière un $ref local, comme dans les schémas d'entrée MCP qui mettent leurs modèles dans $defs. Les définitions référencées sont lues une fois, donc les schémas récursifs ne bouclent pas et les définitions sans références restent en dehors du texte de recherche (#11803)
  • Correction du résumé du mode code resolves to d'un outil laissant de côté les noms de champs derrière un $ref local, par exemple structuredContent? au lieu de structuredContent?: { results } pour les schémas de sortie MCP qui mettent leurs modèles dans $defs (#11803)
  • Correction de chaque échec de script en mode code avec URI malformed lorsqu'un outil appelable, tel qu'un outil MCP, avait un $ref avec un pourcentage d'échappement mal formé (#/$defs/%E0) dans son schéma, même les scripts qui n'appellent pas cet outil. Le paramètre s'affiche désormais sous la forme unknown dans la déclaration de l'outil (#11803).
  • Correction de ctrl+o qui n'étendait pas ou ne réduisait pas la sortie des commandes ! et !! exécutées pendant que l'agent fonctionne. La nouvelle sortie !/!! démarre désormais dans l'état de développement actuel, la sortie ne disparaît plus lorsqu'un message de pilotage ou de suivi est mis en file d'attente, et elle passe dans le chat lorsque l'agent termine au lieu du prochain message soumis (#11875).
  • Correction de la reprise d'une session restaurant un ancien niveau de réflexion après avoir accédé à /tree avant un changement de /thinking. Comme le modèle, le niveau de réflexion en direct est désormais enregistré sur la nouvelle branche avec l'invite suivante (#11451)
  • Correction des images en ligne en mode plein écran affichant uniquement leur première ligne dans Orca, tandis que le mode normal les affichait en entier. Le plein écran dessine désormais les images Kitty après les lignes qu'elles couvrent sur chaque terminal, comme c'était déjà le cas pour WezTerm (#11835)
  • Correction de l'outil d'édition réécrivant les fins de ligne des lignes intactes dans les fichiers avec des fins de ligne mixtes CRLF/LF ou CR solitaires, et manquant de mémoire sur les fichiers volumineux après que le fichier ait déjà été écrit ; le diff ne couvre désormais que les lignes modifiées et leur environnement et est calculé avant l'écriture (#8544)
  • Correction du programme d'installation de Windows (irm https://pi.dev/install.ps1 | iex) qui abandonnait avec NativeCommandError dans Windows PowerShell 5.1 lorsque npm ou Node.js imprimait un avertissement, par exemple npm warn Unknown user config à partir d'une clé .npmrc inconnue. Il a échoué avant le menu d'action lors de la migration d'une installation npm et lors des installations gérées. Un managed-install.json non valide a également interrompu le programme d'installation au lieu d'être signalé (#11944)
  • Correction de l'échec de pi update --models avec Could not refresh model catalogs: openai: OAuth refresh failed for openai: ... invalid_grant lorsque la connexion d'un fournisseur était devenue obsolète. Les fournisseurs intégrés dont le catalogue provient de pi.dev, tels que openai, n'actualisent plus du tout leur jeton OAuth pour une actualisation de catalogue. Pour les fournisseurs qui répertorient les modèles avec connexion, tels que Radius et OpenRouter, un échec d'actualisation du jeton imprime désormais un avertissement nommant le fournisseur et pi auth login <provider>, et les autres catalogues sont toujours actualisés ; la commande échoue uniquement pour d'autres erreurs, telles qu'une panne de réseau
  • Correction de l'outil PowerShell signalant Command exited with code 1 sous Windows PowerShell 5.1 lorsqu'une commande native réussissait mais que son stderr était redirigé, comme dans git push 2>&1 | Select-Object -Last 3. Windows PowerShell 5.1 transforme ce stderr en enregistrements d'erreurs ; ces commandes signalent désormais le code de sortie PowerShell 7 (#8842)
  • Correction de la suppression d'un marqueur de collage avec Retour arrière corrompant les marqueurs courts ultérieurs tels que [paste #2], provoquant la soumission du texte du marqueur au lieu de son contenu collé (#11923)

La découverte d'agent et les vérifications trust utilisent désormais le répertoire de travail de chaque tâche, et les résultats simples et en chaîne sont tronqués sans perdre les détails complets de l'outil (#8250 par @terrorobe)

pi v1.5.1

New Features

  • Shell login and logout: use pi auth login <provider> and pi auth logout <provider> without starting a session, with API-key and no-browser sign-in options. See Credential commands.
  • Idle prompt cache warming: eligible caches now stay warm for up to 30 minutes between runs when a refresh is expected to pay for itself. See cacheWarming.
  • Anthropic message threads: requests send only new messages while the server continues the conversation, with full-request fallback when earlier context changes. See Anthropic compatibility.
  • Richer Mermaid diagrams: pie charts, author-defined styles, clickable labels on supported terminals, and diagrams in expanded branch and compaction summaries. See Display settings and Markdown transformers.
  • GitHub Copilot classifiers: call Microsoft-Decision-1 through codemode models.classify() for typed decisions and probabilities. See Use classifier models.
  • Package update summaries: pi update --extensions reports each package's npm version or git commit change and distinguishes unchanged, skipped, and warned updates. See Update Pi or packages.

Breaking Changes

  • Custom GrepOperations.readFile callbacks are no longer called for context lines. The field remains accepted as optional and deprecated so existing integrations still compile. The grep tool now takes context lines from ripgrep and no longer reads matched files itself. To search a remote system, override grep's execute(); see Remote Execution (#9276)
  • OpenAI-compatible models no longer send "tools": [] when all tools are disabled in a session that has used tools; the field is omitted. This fixes 400 errors (tools must not be an empty array) from vLLM 0.20+, also behind LiteLLM. If your proxy requires tools once the history has tool calls, such as older LiteLLM versions in front of Anthropic, set compat.requiresToolsWithToolHistory: true for that model in models.json (#11843)

Added

  • pi update now lists each updated package with its npm version or git commit change, for example npm:foo 1.2.0 -> 1.3.0, and prints Packages are already up to date when nothing changed. When nothing changed but an update printed a warning, for example because npm left the old version installed after resolving stale registry metadata, it prints No packages were updated, see the warnings above instead; in offline mode it prints Skipped package updates (offline mode). PackageManager.update() reports each changed package as a new result progress event whose message holds that line (#11707, #11711)
  • Anthropic sessions now use message threads: each request sends only the new messages and the server continues from the previous reply, falling back to the full request when the conversation changed (for example after compaction or a tool list change). On by default for the anthropic provider on api.anthropic.com; set compat.supportsMessageThreads in models.json to enable it for gateways that forward the thread field, or to turn it off. Cache warming does not touch the session's thread (#11545)
  • pi.registerMarkdownTransformer() takes an optional { messageTypes } that selects the Markdown surfaces a transformer runs on. Besides user, assistant, and thinking Markdown, transformers can now opt into custom (custom messages and skill blocks), summary (branch and compaction summaries), and changelog (What's New, /changelog, the Extension Updates notice, and the Update Available note). Without options a transformer runs on user, assistant, and thinking Markdown as before. The built-in Mermaid renderer now also draws diagrams in expanded branch and compaction summaries
  • pi auth login <provider> logs in to a provider from the shell without starting a session, for example pi auth login radius. It signs in with an account in the browser and exits; --api-key saves an API key instead, and --no-browser uses device code or copy-code sign-in instead. Logging in to Radius also configures the Radius MCP server. pi auth logout <provider> removes the stored credentials, like /logout
  • ctx.ui.custom() overlays now honor the blocked option: pi reports blocked program status (OSC 7501) from when the overlay is shown until it calls done(), also while it is hidden with setHidden(). Closing one overlay keeps other open questions blocked (#11816)
  • Added the qwen-token-plan-individual-cn provider for Qwen Token Plan Individual on the China endpoint, using QWEN_TOKEN_PLAN_CN_API_KEY (#7989 by @bigoldcat123)
  • Added Microsoft-Decision-1 classifier support through GitHub Copilot, including codemode models.classify() (#11679 by @Marvae)
  • Added compat.promptCacheKeyMode ("auto", "enabled", or "disabled") to enable prompt cache keys for compatible proxies or omit them for endpoints that reject them. Set it in models.json when using pi (#9442 by @dannote)
  • Added compat.requiresNonNullAssistantContent for OpenAI-compatible endpoints that require an empty string instead of null in assistant messages containing only tool calls. Set it in models.json when using pi (#8118 by @gaoyk19)
  • Added syntax highlighting for Dart, Nix, Groovy, and Gradle files in read and write views (#11643)
  • Added GLM 5.3 to the Qwen Token Plan Individual model allowlist (#11658)
  • Added Claude Fable 5.2 (claude-fable-5-2) to the anthropic provider ($8/$40 per million input/output tokens, 1M context, 128K output). Like Fable 5.1 it uses per-message effort and mid-conversation system messages; requests its safety classifiers refuse before any output are answered by Claude Opus 5 through server-side fallback and billed at Opus 5's price. Claude Fable 5.2 and Mythos 5.2 on other providers, such as OpenRouter's anthropic/claude-fable-5.2, get the same per-message effort support

Changed

  • The default model for the anthropic provider is now Claude Opus 5.5 (claude-opus-5-5) instead of Claude Opus 4.8
  • Default models moved to newer models at the same or a lower price: amazon-bedrock Claude Opus 5.5, azure GPT-6.1 Sol, google and google-vertex Gemini 4 Argon, vercel-ai-gateway GLM 5.3, baseten GLM 5.3, minimax and minimax-cn MiniMax-M3, qwen-token-plan and qwen-token-plan-cn Qwen3.8 Max, opencode-go Kimi K3.1 Pro, and Kimi K2.7 Code instead of Kimi K2.6 for moonshotai, moonshotai-cn, huggingface, opencode, openrouter, cloudflare-workers-ai and cloudflare-ai-gateway
  • cacheWarming now defaults to "idle" instead of "streaming": pi also keeps eligible prompt caches warm for up to 30 minutes between agent runs, but only when a refresh is expected to pay for itself. Set "cacheWarming": "streaming" in global settings for the previous behavior
  • Consecutive cache warms now show as one Cache warmed: $<total> line with the cumulative cost instead of one line per warm
  • The OpenAI Codex provider is shown as "OpenAI Codex" again instead of "OpenAI Codex (legacy)" in /login and the model selector
  • The /login and /logout provider lists and /login <provider> completions now show the preferred partners Radius and OpenRouter first, then all other providers alphabetically. In the provider lists, partners are marked with ✦, the selected Radius row shimmers in the Radius logo colors and the selected OpenRouter row glows in OpenRouter's brand color (lime on dark themes, violet on light themes)
  • Upgraded terminal Mermaid rendering to support more diagram types, including pie charts, author-defined styles, and clickable labels on terminals with hyperlink support (#8158 by @xl0)

Fixed

  • Fixed the grep tool's glob matching from the folder pi was started in instead of from path: with path: "repo", glob: "migrations/main/*.js" returned No matches found even though repo/migrations/main/a.js exists. Globs are now relative to path, the same form grep prints its results in, also when path is a symlink. A leading ./ (./src/*.ts) is ignored instead of matching nothing (#11807, #10998)
  • Fixed prompt template arguments dropping apostrophes and merging words: an apostrophe inside a word, as in doesn't, no longer opens a quote; a quote with no closing match is kept as text; and \" inside "..." (or \' inside '...') gives a literal quote (#11861)
  • Fixed the bash tool reporting only Command timed out when the command had already exited but a background process it started kept writing to its output until the timeout. The error now also reports the shell's exit code and when it exited (#11613)
  • Images in steering and follow-up messages, including prompt() while streaming, are now resized like images in idle prompts instead of being sent and saved at full size (#11738)
  • A failed token refresh of an MCP connection no longer registers an OAuth client or replaces the PKCE verifier of a sign-in in progress, which made that sign-in fail. MCP sign-in now refreshes the stored tokens with the stored client even when the loopback callback port changed, instead of registering a new client and opening the browser. Ctrl+C in /mcp and the --timeout of pi mcp login now also stop a sign-in while it waits up to 25 seconds for another pi process's token refresh, and a refresh lock that fails for another reason than that wait now fails the sign-in instead of opening the browser.
  • Fixed pi mcp list reporting MCP servers with "auth": { "provider": "<provider>" }, such as Radius, as needing sign-in although the provider was signed in: the shell command sent no token. It now sends the provider's /login token and refreshes it when it expired. For these servers the sign-in hint names /login <provider> instead of pi mcp login, and pi mcp login and pi mcp logout point to /login and /logout instead of failing with "does not use OAuth"
  • Fixed RPC mode ignoring an extension's ctx.shutdown() while idle, for example from a timer: the process kept running until the client sent another command. pi now shuts down right away when idle, and a shutdown requested by an extension command waits until the command's prompt response is written (#11599)
  • Fixed changelog notes repeating on every fresh launch when the installed package version has a prerelease suffix, such as 0.1.5-20261020.7: the saved version was read as 0.1.0, so the 0.1.1 to 0.1.5 notes counted as new each time. A saved version without major.minor.patch now shows no notes and is replaced by the installed version, instead of showing the whole changelog (#11703)
  • Fixed RPC mode cutting off shutdown cleanup, such as a pending MCP token refresh, when stdin closed and SIGTERM arrived together, which process managers like Paseo and systemd do. Pi lost the refreshed token and the MCP server revoked the sign-in. Once a shutdown has started, a stdin EOF or a single signal no longer interrupts it; a second signal still exits at once. Print mode likewise no longer dies from a signal that arrives during its final cleanup (#11599)
  • Fixed the grep tool reading every matched file into memory when context was set, which ran out of memory on large files; context now comes from ripgrep, which also fixes UTF-16 files and lone CRs in matched lines, and the match limit notice no longer appears when exactly limit matches exist (#9276, #11423)
  • Fixed the find tool reporting the result limit when exactly limit files match, and limit: 0 in find and ls returning every result or an empty listing; limits below 1 now mean 1 (#7121)
  • Fixed grep match lines, codemode output, compaction summaries of tool results, and MCP error and server summaries cutting an emoji or other non-BMP character in half when truncating, which left an invalid lone surrogate in the text (#7121)
  • Fixed the find tool on Windows returning no results for patterns with Windows separators such as src\**\*.ts, and for every path pattern such as src/**/*.ts with fd 10.5.1, which pi now downloads. Windows path patterns now match the same way with every fd version: src/**/*.ts also finds files directly in src/, and src/*.ts no longer finds files in subdirectories (#9262)
  • Fixed the read tool loading whole files into memory, which ran out of memory on large files even with offset/limit; it now streams the file and keeps only the shown lines. Custom ReadOperations can stream too by providing the new optional createReadStream (#9654)
  • Fixed OAuth logins such as openai and anthropic failing with invalid_grant after pi was stopped while it refreshed an expired token, for example an RPC client that stops pi right after startup while the background catalog refresh runs. The token endpoint had already replaced the refresh token, but pi exited before saving the new one. On exit, pi now waits for a token refresh in progress to be saved (#11692)
  • Fixed Ctrl+P not switching to the only model in scope (or the only available model) when the active model is a different one; it showed "Only one model in scope" instead. Cycling forward from a model outside the scope now also selects the first scoped model instead of skipping it (#11806)
  • Fixed /reload and session switches leaving extension overlays on screen when an extension had more than one ctx.ui.custom({ overlay: true }) open: only the topmost overlay was removed, and the others kept focus and input although the extension that opened them was gone. All extension overlays, including hidden ones, are now removed and disposed; pi's own overlays stay open
  • Fixed /mcp sign-in staying on "Connecting…" for minutes after a successful browser sign-in, with Ctrl+C doing nothing: pi waited for the browser to drop an unused connection to the OAuth callback port. The callback server now closes remaining connections when it shuts down (#11311)
  • Fixed pi aborting (zsh: abort) after repeated image reads, reported on macOS arm64 with Node 24.16. Each image resize starts a worker thread, and pi did not wait for it to stop, so the next resize started a new worker while the previous one was still shutting down. The crash is most likely a Node bug that this overlap triggers and could not be reproduced on Linux; image resizes now wait for the previous worker to stop, which adds about 15 ms per image (#10695)
  • Fixed tool_search and searchTools() not finding a tool by property names and descriptions behind a local $ref, as in MCP input schemas that put their models in $defs. Referenced definitions are read once, so recursive schemas do not loop, and definitions nothing references stay out of the search text (#11803)
  • Fixed the codemode resolves to summary of a tool leaving out field names behind a local $ref, for example structuredContent? instead of structuredContent?: { results } for MCP output schemas that put their models in $defs (#11803)
  • Fixed every codemode script failing with URI malformed when any callable tool, such as an MCP tool, had a $ref with a malformed percent escape (#/$defs/%E0) in its schema, even scripts that do not call that tool. The parameter now renders as unknown in the tool's declaration (#11803)
  • Fixed ctrl+o not expanding or collapsing the output of ! and !! commands run while the agent is working. New !/!! output now starts in the current expand state, the output no longer disappears when a steering or follow-up message is queued, and it moves into the chat when the agent finishes instead of on the next submitted message (#11875)
  • Fixed resuming a session restoring an old thinking level after /tree navigated to before a /thinking change. Like the model, the live thinking level is now recorded on the new branch with the next prompt (#11451)
  • Fixed inline images in fullscreen mode showing only their first row in Orca, while regular mode showed them in full. Fullscreen now draws Kitty images after the rows they cover on every terminal, as it already did for WezTerm (#11835)
  • Fixed the edit tool rewriting the line endings of untouched lines in files with mixed CRLF/LF or lone CR line endings, and running out of memory on large files after the file was already written; the diff now covers only the changed lines and their surroundings and is computed before writing (#8544)
  • Fixed the Windows installer (irm https://pi.dev/install.ps1 | iex) aborting with NativeCommandError in Windows PowerShell 5.1 when npm or Node.js printed any warning, for example npm warn Unknown user config from an unknown .npmrc key. It failed before the action menu when migrating an npm installation, and during managed installs. An invalid managed-install.json also aborted the installer instead of being reported (#11944)
  • Fixed pi update --models failing with Could not refresh model catalogs: openai: OAuth refresh failed for openai: ... invalid_grant when a provider's login had gone stale. Built-in providers whose catalog comes from pi.dev, such as openai, no longer refresh their OAuth token for a catalog refresh at all. For providers that list models with the login, such as Radius and OpenRouter, a failed token refresh now prints a warning naming the provider and pi auth login <provider>, and the other catalogs still refresh; the command fails only for other errors, such as a network failure
  • Fixed the powershell tool reporting Command exited with code 1 under Windows PowerShell 5.1 when a native command succeeded but its stderr was redirected, as in git push 2>&1 | Select-Object -Last 3. Windows PowerShell 5.1 turns that stderr into error records; such commands now report the exit code PowerShell 7 reports (#8842)
  • Fixed deleting a paste marker with Backspace corrupting later short markers such as [paste #2], causing the marker text to be submitted instead of its pasted content (#11923)
  • Fixed dropped provider streams reported as "cut short after the reply had begun" not triggering automatic retries (#11879)
  • Fixed the subagent extension example passing Bun's Windows virtual entry path as part of the prompt when spawning a compiled pi binary (#11865)

  • Fixed internal cursor markers leaking into terminal output, including with multiple markers or horizontally clipped content (#9441 by @muyiyr)
  • Fixed the subagent extension example showing running tasks as completed, losing subprocess failure diagnostics, and failing to stop child processes on abort. Agent discovery and trust checks now use each task's working directory, and single and chain results are truncated without losing the full tool details (#8250 by @terrorobe)
  • Fixed large pasted text being replaced by literal paste markers when switching editors, opening custom UI, or restoring queued messages (#10146 by @w-winter)
  • Fixed prompts and session-tree navigation overlapping during asynchronous input hooks, authentication, or branch summaries, which could install the wrong conversation context (#9155 by @acmerfight)
  • Fixed Claude Sonnet 5 requests sending an unsupported temperature parameter (#7961 by @jingtao-wisdomgraph)
  • Fixed extensions loaded through symlinked paths failing to resolve their dependencies by resolving the entry file's real path before importing it (#8112 by @cad0p)
  • Fixed the plan-mode extension example missing completion markers in thinking blocks and common completion phrases, dropping formatted or long plan steps, and sending an extra model turn to acknowledge completion (#7950 by @giannisCKS)
  • Fixed OpenAI Responses requests sending session_id instead of the documented session-id affinity header (#11639)
  • Fixed delivered image-only steering and follow-up messages remaining in the pending queue (#8612 by @wutongyuonce)
  • Fixed cancellation during lazy provider loading or authentication being reported as an error instead of an abort (#8635 by @Mallikarjun-0)
