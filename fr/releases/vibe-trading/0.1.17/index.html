Highlights

  • Daily paper trading that cannot reach a broker (#1939) — The headline is a real sandbox: paper_trade_step (agent + MCP), vibe-trading paper step, POST /api/paper-trade/step, and saved accounts via the vibe-trading paper CLI, REST /api/paper-accounts, and a Web page — matching orders or a strategy file against completed daily bars for cn_a, hk and us. Design clients around two constraints: accounts move forward only, and an advance carries the revision it read, so a stale or concurrent advance is refused (HTTP 409) and a failed step leaves the ledger unchanged. Strategy code runs in a child process that sees only bars strictly before the execution day — that is your lookahead guarantee — but fills are daily-close and all-or-none with simplified fees, board lots and A-share T+1, corporate actions and cash dividends are unmodelled, and NAV is not total return. Price caliber is enforced hard: adjusted, unknown or non-finite prices are rejected and split-like jumps return PAPER_DATA_NOT_READY instead of rescaling holdings, so expect data-pipeline work before a backtest-to-paper handoff.

  • Undefined values now say null, not 0 — The widest behavioral change in this cycle is also the quietest: a profit factor with no losing trade, an undefined correlation, a factor benchmark with too few IC observations, upside at a zero price and an unbounded ratio now return null or a refusal rather than a plausible-looking number, and a missing price no longer bridges a return pair, a VaR transition or a lag pair. That is the right correctness default, but it is a downstream contract change — dashboards, alert thresholds and NOT NULL columns that assumed a float must handle nulls or rows will silently disappear. Upgrade for two related fixes too: an after-close SEC filing can no longer reach the IC a bar early, and misspelled backtest settings are surfaced in the run card instead of being silently ignored, so runs that previously "passed" may now report errors.

  • Runtime control changes: budgeted model decisions and hardened custom endpoints (closes #1854, #1264) — Safety checks still run every minute, but model decisions now default to every 15 minutes in a fresh conversation, capped at 26 decisions and 1,000,000 reported tokens per broker per UTC day; configure once-daily timing, timezone and an operator-set USD ceiling via Runtime → Model schedule, the chat runner panel, vibe-trading connector runner-settings or GET/PUT /live/runner/settings, with spending history surviving restarts. Limits are checked only after a provider responds, so a single response can overshoot, and exhaustion or missing usage trips the existing kill switch with its cancel/flatten behavior; treat estimates as guardrails, not billing truth. The grounding gate

  • Indexed and container field refs resolve, and a miss lists the refs that would work (#1633, thanks @zeus229). a.0.b and a[0].b now name the same evidence element; an unindexed field still selects none. When a call::field ref matches nothing, the correction lists exact call_id::path[i] refs, value matches first. A ref naming a container lists its numeric descendants that hold the figure's value, and a tool name shared by several calls ranks those calls by value match, most recent first. These are hints only: no hint authorizes a value, and a maintainer follow-up keeps them to the figure's own instrument and to the element an indexed ref names.

  • A ref naming no call of the session gets real refs to copy (#1638, thanks @zeus229). A scope::field ref whose scope names no call, tool or run stays rejected, now with the unknown_call_id reason and up to five exact call_id::field candidates. The system prompt tells the model to copy tool_call_id verbatim instead of inventing a short alias. A maintainer follow-up applies the same instrument and figure-kind limits a real ref has, so a candidate is never one that would be refused.

  • A correction keeps the figures that already passed (#1702, thanks @he-yufeng). The correction prompt listed only what failed, and a model facing 65 issues rewrote whole numeric sections as prose, deleting valid Risk X-Ray values and a benchmark table that had no issue. It now also lists up to 24 measured figures that checked clean and tells the model to keep them as written. A value that fails anywhere in the draft is not listed, and bare integers never are. When more than 24 issues exist, the prompt says how many are not shown and that unlisted figures are not assumed to pass.

  • Only the engine's own output grounds a backtest report (#1685, thanks @cgycorey). The active run's metrics.csv could credit an earlier run's Sharpe to the current call; that archived copy now counts only when its manifest names the full directory the call declared and the exact call id, and a model-written manifest is ignored. A metrics.csv or metrics.json the model wrote is no longer engine evidence, a date cell with an explicit year must match that year, and a resolver step that failed, was refused or came back empty no longer erases a locked or conflicting identity.

  • A derived figure's ref must name evidence that exists (#1835, #1837, thanks @zeus229). A comma- or semicolon-separated ref is resolved member by member, and an empty or unknown member fails with no_evidence instead of falling back to every value in the session. A single ref that names no call, tool, field, artifact or observed symbol is refused the same way rather than borrowing a coincidentally equal value. Unattributed multi-symbol arithmetic keeps its no_symbol diagnostic.

  • Derived notes after a label parse, and process metadata is not evidence (#1728, #1767, thanks @zeus229). A note such as scenario result: 125 / 10000 * 100 was not evaluable because only the full-width ： was a separator; the ASCII : now is too. Top-level exit_code, returncode, elapsed_seconds and duration_seconds of a code-running tool's result are no longer recorded as observed values, so a backtest's runtime cannot ground a figure.

  • Percent-named fields are read as percentage points (#1823, closes #1820, thanks @he-yufeng). A-share rows carry changepercent values that are already points, so 0.52 - 1.41 refused the correct "-0.89%" and passed "-89%". When every data operand anchors only to fields named percent, pct or ending in %, the result is read in points; an operand whose value also appears under a plain field keeps the fraction reading. A maintainer follow-up converts the operands before evaluating, so ratios and compound factors of two point values come out right.

  • Every data operand of a derived figure must be observed. Only added or subtracted terms were checked, so a numerator or denominator the session never fetched could pass. A chosen multiplier or divisor (a discount factor, a weight) now needs a count declaration and its value and label on the same visible line of the answer. Literal 1 and square or cube exponents are structural, and an explicit trailing *100 on a percent claim is read as a unit conversion without exempting any other operand.

  • Instrument identity survives matrices and ticker-keyed results (#1850, #1851, thanks @zeus229). In a square Markdown matrix with an empty top-left header (a correlation table), each row's symbol is taken from its first cell, bold removed, when the row and column symbol sets are complete, unique and equal; anything else stays unscoped. A result keyed by instrument (risk_contribution_pct.ABC.US) keeps each value's instrument and exact ref, so the same number cannot ground a claim about another instrument. List-indexed scalars such as positions[0].contribution_pct keep their indexed-ref meaning.

  • A figure that names its currency must match evidence in that currency (#1905, thanks @ThreeTima). An ISO code or an unambiguous mark (€, £, ₩, ₹, 人民币, 美元, 円) fixes the figure's currency for observed, derived and proposed checks, and SEC XBRL amounts carry their declared unit (CHF, NZD, BRL, ARS and VND included).   • More secret formats are redacted (#1874, #1866, #1867, #1868, #1869, #1870, thanks @rudycelekli). #1874 combined the five smaller PRs. These are now redacted:

    • unlabelled GitHub fine-grained (github_pat_), GitLab (glpat-), npm, Hugging Face, Stripe (sk_/rk_ live and test), Google API (AIza) and AWS ASIA keys;
    • PEM and PGP private-key blocks, including a block cut off before its END line, which is redacted to the end of the text;
    • Cookie: and Set-Cookie: header values;
    • fields named like cookie or private_key in structured payloads.

    Public keys and certificates are left as they are, and running redaction twice changes nothing. Since 47de62de, a quoted header such as curl -H "Cookie: a=\"x\"; b=y" is redacted up to its closing quote.

  • Telegram bot tokens, Slack and Discord webhook URLs, Groq and NVIDIA keys are redacted (#1880, thanks @rudycelekli). The Telegram token is caught inside https://api.telegram.org/bot<token>/…, which HTTP error messages repeat in full. For a webhook URL, only the secret last path segment is replaced. The PR accepted only 8–10 digit Telegram bot ids and lowercase hooks.slack.com. 2c00cd20 widened that to any length of numeric id, to GovSlack (hooks.slack-gov.com) and to webhook hostnames in any letter case.

CLI, API and scheduling

  • vibe-trading update leaves a Git install alone (#1655, thanks @rudycelekli). An install made from a Git URL was treated as a PyPI wheel, so the update replaced the user's chosen revision with a released wheel. The command now detects vcs_info in the install metadata, reports the newer PyPI version and tells the user to update from the original source.

  • The terminal dashboard matches parallel tool results to the right call (#1859, closes #1856, thanks @Shizoqua). When several calls to the same tool ran at once, progress and results were matched by tool name and recency, so results could be swapped between calls. They are now matched by call id. Since 47de62de, a result whose id matches no step gets its own step and no longer completes a different call that is still running.

  • CLI limits and number formatting (#1886, #1926, thanks @rudycelekli). vibe-trading list --limit and memory search --limit reject zero and negative values instead of passing them on. Token counts, abbreviated numbers and durations switch unit when rounding reaches the next one: 999,950 tokens shows as 1.0M tokens instead of 1000.0k tokens, 999.6 ms as 1.0s, and 59.96 s as 1m 00s instead of 60.0s.

  • A cancelled upload leaves no partial file (#1945, thanks @rudycelekli). If the upload request was cancelled while a chunk was being read, the half-written file stayed in the uploads directory with no reference to it. The file is now deleted and the cancellation is re-raised.

  • More runtime files follow VIBE_TRADING_HOME (#1896, #1904, #1887, thanks @rudycelekli). These paths were fixed to ~/.vibe-trading and now use the runtime root:

    • persistent memory and its search index (memory/, memory_index.db);
    • autopilot run directories;
    • the alpha-bench panel cache and reports;
    • the Gildata code cache.

    The Shadow Account report route also reads from the runtime root, which is where the report writer saves. Report links therefore work again when VIBE_TRADING_HOME is set. Existing files under ~/.vibe-trading are not moved, and the memory paths are read when the process starts.

Channels and scheduled delivery

  • IM channels show agent progress again, without repeated lines (#1878, thanks @alexwan02). Channel replies now forward the attempt's status lines (working, waiting for the model, using a tool, checking the figures), tool hints and opt-in reasoning while the agent runs, so Feishu's streaming card and other streaming channels update again (reported in #1792). Only those labels go out: answer drafts and tool results stay private, and the final answer still passes grounding first. #1878 applies the channel's own visibility settings before deduplicating, so hidden tool hints no longer break the dedupe and a chat no longer stacks one "Waiting for the model" per tool round.

  • Streamed replies are no longer lost or split (#1860, #1903, #1929, closes #1857, thanks @Shizoqua). Telegram (#1860) and Matrix (#1903) dropped the whole answer when the live preview message could never be created; they now send the accumulated reply as a new message. CI installs the matrix extra so the Matrix test runs instead of skipping. WeCom (#1929) generated a new stream id for every chunk, so progress and the final answer arrived as unrelated messages; one id now covers each reply.

  • Email sender authentication cannot be satisfied by forged headers (#1508, thanks @Shizoqua). SPF and DKIM checks read only the single Authentication-Results header bearing the configured trusted_authserv_id; with none configured, or with two matching headers, verification fails closed. A pass counts only when its domain equals the From domain or an aligned dmarc=pass is in the same header, and comments or quoted text cannot pose as results. The receiving provider must strip forged copies bearing its id; the id is not a signature. The guided Email setup exposes the setting, and a blank one rejects inbound mail while SPF or DKIM checks are on. The PR described trusting the topmost header; what shipped selects by configured id instead.

  • URL credentials in channel settings are neither leaked nor erased (#1742, #1744, thanks @cgycorey). Status and config redaction strips user:password@ even when the port is malformed or out of range or the URL is followed by punctuation, where it used to return the URL untouched (#1741). Saving or testing a form that echoes the redacted URL keeps the stored credential instead of overwriting it (#1743); a different URL or a clear flag still applies. Connection-test and reset messages, including raised SDK exceptions, are scrubbed too.

  • Unchanged empty fields no longer block channel saves (#1681, thanks @zeus229). A nullable setting such as Email's post_action was submitted by the form as an empty string and rejected with a 422 on unrelated edits. An empty value now maps back to null where the adapter's default is null, for both Save and Test.

Web UI and locales

  • Run trades list every trade, newest first (#1865, #1877, #1831, thanks @alexwan02 and @he-yufeng). The Trades tab and its CSV download used the first 500 rows of trade_log, which dropped the newest trades of a long run; they now use the full trades.csv rows (#1865). Rows sort newest first with a header toggle, keeping same-time fills in engine order, and the symbol filter lists codes in order (#1877). #1831 removes a race in the Settings effort-level test that intermittently failed frontend CI; the component is unchanged.
