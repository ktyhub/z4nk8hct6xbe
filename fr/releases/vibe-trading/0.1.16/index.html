Vibe-Trading v0.1.16

Highlights

  • Grounding now declares numbers instead of guessing them — src/agent/grounding.py becomes the src/agent/grounding/ package: figures are classified only by SHAPE, then declared in a trailing fenced figures block (value | role | note | ref) as observed / derived / proposed / cited / count and checked against that session's tool evidence by role. The behavior change users feel most: a failing figure no longer refuses the whole answer — after one correction round (down from four) the bad numbers are cut in place ((omitted※) / （略※）) with a footnote, and the redacted document itself must pass the gate; the correction turn gets no tools so revisions can't restart research (#1600). A backtest's own outputs — Sortino, turnover, weights and Monte Carlo p-values, not just Sharpe — now ground its report, and run cards cite a metric only when it matches the saved artifacts/metrics.csv and its manifest checksum (#1612). Watch for the new grounding_status events and "Checking the figures…" chat state if you depend on the old refusal path.

  • Long runs keep their context, but the compaction knobs changed — compaction used a fixed 40K-token estimate and began clearing tool results from step three, so multi-company comparisons re-fetched the same filings until a no_progress stop; it now derives the window from VIBE_TRADING_CONTEXT_WINDOW, a limit learned from provider errors, src/providers/context_windows.json (272K Codex, 1M DeepSeek), or 128K, with VIBE_TRADING_CONTEXT_MAX_TOKENS (200K) capping prompts. TOKEN_THRESHOLD is deprecated and ignored with a warning — remove it from .env. Read-only results lost to compaction are replayed from the run cache (#1488), and Codex (ChatGPT sign-in) now sends mid-run hints as developer messages and preserves reasoning-item ids instead of replacing the ~49K-character system prompt.

  • Weekly/monthly bars and new markets change how you ask for data — get_market_data and backtests accept 1W/1M (and 1w/1wk/1mo), resampled from daily bars at each fetch boundary via loaders.base.resample_bars (#1479); 1M is matched before case folding, fixing the silent bug where a monthly request returned one-minute bars (#1487), and annualisation is 52/12. Argentina (BYMA) becomes market ar_equity in ARS (#1543), but execution is deliberately unmodelled — an Argentine backtest raises rather than borrowing US or crypto commissions and lot rules. get_stock_profile gains a listing block so a secondary listing like GOOGL.BA no longer reads as the primary (#1577), and USD BYMA/TSX lines plus RMB/USD HK counters are excluded from single-currency backtests (#1576).

  • Four new brokers, one new A-share source, and a generated capability matrix — KIS (#1407), Upbit (#1408), Toss Securities (#1409) and Scalable Capital (#1417) land, all read-only or paper-only: KIS paper trades on KIS's own server (live is read-only), Upbit paper simulates against live quotes, and Toss/Scalable refuse every order. The README broker matrix is now generated from the profile registry with one row per built-in profile and explicitly says the rows are declarations, not runtime verification — regenerate with PYTHONPATH=agent python -m src.trading.capability_matrix (#1629). Gildata joins the A-share fallback chain as token-gated (#1474): set GILDATA_TOKEN, and note that a previously saved MARKET_DATA_ORDER_A_SHARE stops validating once gildata joins and must be re-saved once in Settings.

  • Migration notes you can't skip — Portfolio valuation moves to version 3: v2 snapshots are no longer read, so portfolio history restarts after upgrading (#1510). Email now verifies TLS certificates by default and adds STARTTLS on plain IMAP (#1544); a self-signed/internal-CA server or an imap_use_ssl: false server without STARTTLS will stop connecting until you set verify_tls: false / imap_use_tls: false. Existing Robinhood mandates must be recommitted with an explicit account from get_accounts (#1442). MT5 no longer auto-picks a broker alias — quotes, history and backtests require the exact native symbol (47a036d6, #1597/#1598) — and the Requesty built-in provider is removed in favor of LANGCHAIN_PROVIDER=openrouter with OPENROUTER_BASE_URL=https://router.requesty.ai/v1.

  • Alpha values have shifted — stored research is not comparable — factor values change for 23 alphas: the 15 qlib158 CNTP/CNTN/CNTD families now treat a missing close as NaN instead of a flat day (#1459), WVMA5…WVMA60 take the absolute numerator as upstream does (#1594), and GTJA 103/133/177 score days since the most recent extreme high instead of an inverted low (#1604). Any IC, benchmark or comparison computed before this release is not comparable with one computed after it — re-run stored studies before drawing conclusions.

Rolls up 492 commits / 116 merged pull requests since 0.1.15, from 16 contributors.

The theme of this cycle is a number that can show where it came from. The final-answer grounding gate stopped guessing what a number is from the words around it: the model declares each figure's role — observed, derived, proposed, cited or count — the gate checks that declaration against the session's tool evidence, and a figure that fails is cut from the answer instead of the whole answer being refused. A backtest's own output (its Sortino, turnover, weights and Monte Carlo p-values, not only its Sharpe) now grounds the report written about it, run cards cite a metric only where the saved CSV agrees, and the generated broker matrix states each profile's permissions as declarations rather than as runtime verification. Research runs stopped losing what they fetched: compaction follows the model's real context window instead of a fixed 40K estimate that began clearing tool results from the third step. The missing-data sweep reached 59 more alphas: 15 qlib158 count factors, 20 that filled a missing input with a constant and 24 comparison gates. Argentina (BYMA), weekly and monthly bars, Bahasa Indonesia, Gildata, OpenCode, Email and WebSocket channels and four broker connectors (KIS, Upbit, Toss Securities, Scalable Capital) land alongside.

Added

  • Stock profiles carry the listing's own identity (#1577, thanks @Shizoqua). get_stock_profile returns a listing block beside the issuer's fundamentals: Yahoo's symbol, exchange, quote type and quote currency, plus the financial currency and underlying symbol when Yahoo declares them. A secondary listing no longer reads as the primary one. GOOGL.BA is an ARS line in Buenos Aires carrying Alphabet's USD financials, and GGALD.BA is a USD line whose issuer reports in ARS. Nothing is inferred from the ticker.

  • Volume statistics in technical_indicators (#1571, thanks @zeus229). The tool returns the latest volume, its 20-bar mean and their ratio, computed from the bars it already fetched. The mean needs a complete 20-bar window. volume.unit is the unit the serving source declares (board lots on the A-share sources, shares on the Yahoo family, null when undeclared), because the two are 100x apart and nothing in the numbers tells them apart.

  • Argentina (BYMA) market data (#1543, thanks @zeus229). A .BA symbol — a BYMA listing or a locally traded CEDEAR — is its own market ar_equity, quoted in ARS, served by yahoo → yfinance → local, and reported as market ar by get_stock_profile. Execution is deliberately not modelled: an Argentine backtest raises instead of borrowing US or crypto commissions, lot sizes, settlement and short-selling rules. The Web UI carries the market too — Settings source priority, the positions asset-class grouping and the sector union — and with it uk_equity, vietnam_equity and index, which had been missing from one or more of those three since they landed. EnvConfig.data's per-market MARKET_DATA_ORDER_* fields are now guarded against FALLBACK_CHAINS instead of a hand-written list, which is why uk_equity never had one.

  • Weekly and monthly bars (#1479). get_market_data and backtests take 1W and 1M (and 1w / 1wk / 1mo). Loaders are still asked for daily bars; loaders.base.resample_bars builds the period bar at the three fetch boundaries (runner, market data, benchmark), so a weekly bar is the same whichever source served the days, at that source's daily caliber. A week runs Monday to Sunday, a month is a calendar month, and each bar is dated on the last trading day inside it: first open, highest high, lowest low, last close, summed volume and amount, volume-weighted vwap, mean funding rate. Annualisation is 52 / 12; a weekly perpetual bar settles 21 funding periods. 1M is matched before any case fold, which read it as one minute in strict-100x validation and in attribution (98,280 bars a year). The technical-indicator tool canonicalises its documented 1wk / 1mo and fetches whole periods instead of two days per bar.

  • IM channels are configured from the Web UI (#1520, #1529; #1519, #1530, thanks @shadowinlife). The Settings panel renders each built-in channel's fields from backend metadata, masks secrets (**** plus the last four characters, never sent back), tests the unsaved form against the provider (ok / invalid_credentials / network / unsupported), and hot-swaps only the saved channel with no restart. DingTalk and QQ have guided setups; a shared token probe backs both. Saves write channels.<name> in ~/.vibe-trading/agent.json atomically at mode 0600; a YAML config is shown read-only. Reloads of one channel are serialized in ChannelManager, and stop_all cancels a reload's start that is still connecting.

  • Email and WebSocket join the guided Web UI channel setup (#1544, after #1519, thanks @shadowinlife). Both channels get hand-written field metadata — localized labels, masked secrets — plus connection tests and per-channel hot apply. Email's test probes the real IMAP login, mailbox select and SMTP login without ever sending a message; WebSocket is a server channel with no remote credentials, so its test validates the TLS cert/key material and binds every resolved address locally — an address held by the already-running server reads as the expected state, not a failure. Saving a WebSocket config hot-swaps the server: connected clients (including the Web UI chat) briefly disconnect and reconnect. A hand-written field hint's secret flag is now authoritative for the keys it covers — the regex fail-safe still masks every unhinted key — so token-shaped non-secrets such as websocket_requires_token stay visible and editable instead of being masked, and a form save can no longer silently flip the stored token requirement. The web config routes now build the WebSocket adapter with the gateway services it requires; previously every WebSocket save or test failed validation. Email's polling loop also skips stale-config delete/move post-actions once a stop or hot swap begins, while the already-fetched batch is still delivered. Both the probe and the polling loop now send an RFC 2971 IMAP ID after login: NetEase mailboxes (163/126/yeah.net) accept the login but reject the first SELECT with Unsafe Login until the client identifies itself, so without this the Email channel could not read the most common Chinese mailboxes. The identification is static and carries no user data or secrets, and servers that ignore ID are unaffected; verified end-to-end against a live 163.com account.

  • Portfolio valuation accepts any ISO-4217 currency (#1510, thanks @zeus229). A source whose currency has no FX rate fails with the currency named and is excluded from the totals; the healthy sources stay in.

  • Gildata (恒生聚源) joins the A-share fallback chain as a token-gated source (#1474, thanks @sambazhu). The new gildata loader talks to the vendor's raw-api MCP endpoint (one JSON-RPC POST per call, token in the Authorization header) and serves A-share daily OHLCV through the StockDailyQuote tool with restorationStatus=1 — forward, split-AND-dividend adjusted bars, stamped split_dividend in the price-caliber table after being measured against a live payload. An unresolvable symbol answers rows: [] (never an error), so the chain keeps walking. Without a token the loader reports unavailable and the chain skips it — no behavior change for existing users beyond one reorderable entry at the chain's tail. One migration note: a MARKET_DATA_ORDER_A_SHARE value saved before this change is a permutation of the old 7-source chain, so it stops validating once gildata joins — the Settings card flags it and the default order applies until the saved order is re-saved (one click) with the new source included.

Its connection reads exactly one account, picked from Robinhood's own get_accounts list in the connection center or with vibe-trading connector select-account <id>. A second page of positions, a null list or item, or an unknown field is an error, not a shorter account. Positions show quantity and cost but no price until the quote reply is mapped. An account that also holds options, crypto, futures, event contracts, mutual funds or fixed income fails the source instead of showing an equity-only view.

Changed

  • source="qveris" refuses markets with splits and dividends (#1494). It picks a capability by search rank, which ignores adjustment: for 600519.SH the top pick was FMP's non-split-adjusted EOD, and a tool named adjusted returned raw closes. Stocks and ETFs are refused before anything is searched or billed; crypto, forex, futures, macro and index bars are served as before. Both QVeris budget gates reserve only a flat per-call quote now: 1 credits/result had reserved 1 credit for a call that billed 9.66, and qveris_execute returns quote_not_bounded for any other shape.

  • A price index is stamped raw (#1541). Eastmoney's fqt=1 equals fqt=0 on every bar of the A-share indices measured, Tencent serves only day for the SSE/SZSE ones, and Yahoo's adjclose equals close on ^GSPC / ^NDX / ^HSI, but the per-source table stamped an A-share index additive and a Yahoo index dividend-adjusted. price_caliber takes the symbol; A-share index codes are matched per exchange, since 000001.SZ is Ping An Bank.

  • Portfolio valuation version 3 (#1510, thanks @zeus229): snapshots stored under version 2 are no longer read, so portfolio history starts again after upgrading.

  • Tencent, Eastmoney and AKShare A-share prices are labelled split_dividend_additive (#1497, #1493, thanks @cgycorey). Their forward adjustment subtracts cash dividends from the level instead of scaling by a ratio (on 600519.SH, qfq minus raw takes five values over 500 bars against 367 distinct ratios), so a basket mixing them with multiplicative sources warns, and a run served only by them warns that its returns are not total returns. Tencent's HK series is labelled raw: it serves no adjusted HK bars. The prices themselves are unchanged.

  • connector account renders Binance spot balances as Asset / Free / Locked / Total, Futu's per-currency assets, and Trading 212's cash and metadata (#1539); before, Binance printed blank rows and the other two printed "No account summary returned."

  • The final-answer grounding gate no longer guesses what a number is from the words around it. Only a number's SHAPE is inferred — a decimal point, a percent sign, a currency mark or a table cell makes it a measurement; dates (including year-less "09-14"), years, security codes, line-leading ordinals and code in a language-tagged fence are structure; a plain integer is checked only as a price of an instrument quoted in the thousands — so a sentence gets the same verdict in every language. A measurement that equals a price or volume this session's tools returned needs nothing more. Any other one is declared in a fenced figures block at the end of the answer, one line per figure — value | role | note | ref — and checked by role: observed must appear in the referenced call or tool (ref may name either), filtered to the figure's own symbol, with a currency-marked figure compared only against money-denominated values and a percent only against non-price ones; derived needs an evaluable formula whose added or subtracted operands are all observed, matching the figure at the precision and sign it was written with; proposed is a price inside its own symbol's observed range or a derivation; cited must name its source on the figure's own line, because the block is stripped before anyone reads the answer; count covers counts, weights, thresholds and probabilities, while a currency-marked figure, or one inside its instrument's price range that no derivation uses as a factor, is checked as observed when declared count. No role other than observed may sit in a price column. The block is stripped from the released answer and never streamed; the artifact keeps it. The price-word, level-word, derivation-phrase and metric-subject catalogues are deleted with it (65 compiled regexes → 12, all shape), and src/agent/grounding.py is now the src/agent/grounding/ package.

  • A rejected answer costs one correction round, not four, and is then released with its failing figures cut rather than refused. The correction prompt lists every failing figure as written, with its declared role and what the evidence says (the observed range, the nearest observed values, or what its own formula evaluates to, in the figure's units), and names the three ways out: declare, rewrite to an observed value, or remove. If the second draft still fails, each failing figure is replaced by （略※） / (omitted※) at its own span, bare-integer restatements of a cut figure are swept too, a footnote says how many were omitted and why, and the whole document — footnote included — must pass the same gate before release. The canned fallback is left for an identity finding, a run that never observed a price, or a cut that still fails. Drafts that triggered bounded search_symbol / get_market_data recovery do not spend the correction budget. The run stays degraded with a reason naming the redaction, the release path's rechecks are not counted as rejected drafts, and the shipped document is recorded under released in artifacts/grounding_evidence.json.

  • A draft missing only a source or currency word gets a data note appended, not another model round. The canonical symbol is deliberately not repaired this way: it is the figure's subject, and a note naming it under an answer about another instrument would footnote a misattribution.

  • The chat shows that the answer is being checked. The agent loop emits grounding_status ({stage: "revising", round, issues} after a rejection, {stage: "released_redacted", removed} before a cut release), and the chat page shows "Checking the figures in this answer (round N)…" until answer text arrives, in all eight locales.

  • MetaTrader 5 no longer picks a broker alias when several match (47a036d6, with #1597 and #1598). Quotes, history, orders, symbol search and the backtest loader took the shortest suffixed name (EURUSDm over EURUSDz); they now refuse and ask for the exact native symbol. The connector still tries a configured symbol_suffix first; the backtest loader does not read it.

  • run_card.json schema_version is 1.0 (was 0.1), with the optional tool_traces and citations keys from #1612.

  • Broker connectors: 18, up from 14 (KIS, Upbit, Toss Securities, Scalable Capital). test_readme_counts.EXPECTED_BROKERS is checked against the profile registry, not incremented by hand.

  • The opt-in loader cache is at version 7 (#1411, thanks @shadowinlife). Entries written under version 6, which include Tencent series the forward walk truncated, are never matched again and are fetched afresh.

  • VIBE_TRADING_BAOSTOCK_TIMEOUT (default 30 seconds) bounds each BaoStock lock wait, connection and complete message (#1615, thanks @he-yufeng). It is not a deadline for a whole multi-symbol fetch.

  • The a_share fallback chain is tencent, mootdx, eastmoney, baostock, akshare, tushare, gildata, local (#1474, thanks @sambazhu).

  • Factor values change for 23 alphas, so an IC, bench or comparison stored before this release is not comparable with one computed after it: qlib158_cntp* / cntn* / cntd* (15 factors; the first value lands one bar later and windows touching a gap are NaN, #1459), qlib158_wvma5 … wvma60 (5; every value, #1594), and gtja191_103 / 133 / 177 (3; direction and scale, #1604). Patell z for market_adjusted and mean_adjusted event studies moves slightly as well (#1449, thanks @Shizoqua).

  • A grounding correction turn is offered no tools (#1600, thanks @zeus229) — after a rejected draft the model was handed every tool again, so revising a figure could restart research. Unless the gate asks for recovery (an unresolved symbol or a missing price), the correction turn gets none. A call made anyway is not run and, since 47a036d6, spends one of the two correction rounds; at the cap the last real draft goes through the existing cut-and-recheck release.

Fixed

Long research runs stop losing what they fetched

A user's two runs on the Codex provider (GPT-6 Sol) failed as "0 steps · no_progress": a risk-parity backtest after 1m03s and a comparison of A-share and Hong Kong game companies after 4m50s. They were two different failures.

  • Context compaction follows the model's real context window — compaction fired at a fixed estimate of 40,000 tokens (characters / 4 of the messages, not counting tool definitions), while the system prompt alone is about 12,500 of them. From the third step it cleared every tool result but the last three, so a comparison across a dozen companies re-fetched the same filings until the no-progress stop: reproduced on v0.1.15 with DeepSeek V4 Pro, seven A-share issuers' filings fetched four to five times each, stop at iteration 16; with a larger budget the re-fetches went from 54 to 0. The window now comes from VIBE_TRADING_CONTEXT_WINDOW, else a limit learned from the provider's own context-length error during the run, else src/providers/context_windows.json (272K for the Codex GPT-6 / GPT-5.6 models, 1M for DeepSeek V4, each entry naming its source), else 128K, and VIBE_TRADING_CONTEXT_MAX_TOKENS (200K) caps what a prompt may cost. Usage is read from the input tokens the provider reports. The three layers fire at 80 / 90 / 100% of what the system prompt and tool schemas leave, and clear the oldest results first, only down to the line. A context-length error is compacted and retried instead of failing the run. TOKEN_THRESHOLD is deprecated and ignored with a warning; remove it from .env.

  • read_file says where the agent may read, and lists a directory — the 1m03s failure: on the same prompt, a live DeepSeek V4 run went looking for the backtest engine's source (../../agent/src/backtest, the checkout's absolute path, skills/../backtest/engine.py) and every attempt got the same "File not found or path escapes workspace". Each spelling was a new call and none an observation, so eight rounds exhausted the no-progress budget in 93 seconds, before any backtest ran. The refusal now names the case (outside_readable_roots or not_found), the readable roots (the run directory and skills/) and where the engine's contracts are documented (load_skill); a directory inside those roots returns its entries. The boundary itself is unchanged.

  • A failed or cancelled run keeps its steps — only a completed run saved its tool trail, so the Web history showed "0 steps" for exactly the runs someone would want to inspect.

  • A no-progress stop says which calls produced nothing, and why — each failing or repeated call is listed with its reason and count ("read_file failed (… not found) ×3"), instead of a message about previous summaries and artifact paths written for a different failure.

  • get_market_data fails when no requested symbol returned data — an envelope holding only _unresolved was a success, so a run whose sources were all down counted it as progress. It is now error_code: no_market_data; a partial result is still a success, and grounding still records every symbol as unavailable.

  • Codex (ChatGPT sign-in) keeps the system prompt, its reasoning and its call ids — a system message the loop adds mid-run (a retry hint, a write-the-file reminder) replaced the whole 49,000-character system prompt for every later request; it is now sent as a developer message, as the Codex CLI does. Reasoning items are carried from turn to turn the way the Codex CLI replays them, and resent without them if the backend refuses; tool calls keep the item ids the backend issued instead of a fabricated fc_0; the prompt-cache key is stable for the session instead of changing on every request. The default Codex model is gpt-6-sol: gpt-5.4 is refused for ChatGPT accounts.

A backtest report is checked against the backtest

A risk-parity versus equal-weight report ended in the canned refusal in 12 of 15 replayed runs. Replaying all 26 stored drafts through the gate (880 of 882 recorded rejections reproduced) showed that four in five refused figures were values the backtest itself had written.

  • A backtest's own output grounds the report about it — only metrics whose names the gate knew (Sharpe, return, drawdown, volatility, win rate) were evidence. Every scalar of the run card, the metrics row, the risk X-ray, the Monte Carlo validation and the rebalance summary now is (lists such as the 1,000 simulated Sharpes are not descended, and a file other than the metrics must match the run card's SHA-256 manifest). A figure may name the run it came from — rp, rp/artifacts/metrics.csv, risk_parity target_positions.csv, rp::sortino — and a value from one backtest does not ground a figure declared from another. Replayed: value_mismatch 196 → 1, not_in_referenced_call 167 → 7. On the same runs a real value declared with its run passes 97% of the time and the same value moved 2–10% passes 0.7%; the undeclared path was deliberately not widened (the whole metrics row there would have passed 16% of invented values).

  • A comparison's arithmetic is read as it is written — a formula glued to its labels ("等权 Sortino 1.2115 − 风险平价 1.1329") or followed by a bracketed aside was "not arithmetic"; an operand written as a percent was read as a whole number, so "13.28% − 12.98%" anchored on nothing and "0.666 × (1 − 3%)" computed the wrong value; a sum of squared weights (HHI) could not be written at all; a formula's negative operand (a drawdown) could never anchor; and a field two runs both hold anchored neither. All now evaluate (only a literal square or cube is accepted as a power), and the ones that still fail are the model's own arithmetic. A declared value may be a fraction (1/3) or a multiple (5.5x).

  • A report that still fails after a completed analysis is released with the failing figures cut — naming a symbol made any request a market answer, and a market answer with no fetched price was never released cut.   • A correction says what went wrong with a figure the model did declare — 0.3897 and 38.97% stay two assertions, and so do −1.51pp and a formula that computes +1.51, but the model is now told which value it declared (also when it has the opposite sign) and that its formula runs the other way round, instead of "not declared" or "its own note evaluates to 1.51%". The grounding gate

  • A tail-risk figure names its own field once a session holds more than one (#1425, after #1444, thanks @he-yufeng). A call- or tool-scoped ref (ref x1) pooled every tail-risk field that call returned, and an undeclared tail-risk percent pooled every tail-risk value in the session, so an ES 95% could quote the VaR 95% value and pass. Accepted cost, stated in the issue: an undeclared VaR 95% beside a VaR 99% is correct today and now costs one correction round. The system prompt states the rule so a risk report declares the ref on its first attempt.

  • Tail-risk figures keep their identity under a field ref (#1444, thanks @he-yufeng).   • The grounding gate reads decimal commas (#1517, thanks @zeus229): 17,93 % and 1.410,00 CNY ground against tool results, two unspaced numbers such as 1400,1777 stay two numbers, and a written figure must match its evidence within half a unit of its last written digit (a truncated 30.20% for 30.2052% is now sent back for correction).   • A redacted answer keeps its row numbers and its labels (#1471).   • Price-denominated indicator values are evidence, by registration. Two real runs that followed the contract were still released redacted: "2026-09-11 / 09-14" in a table cell shipped as "2026-09-11 /（略※）-（略※）", and "24.6M → 22.6M lots" as "(omitted※)M → (omitted※)M". Backtest runner and engines

  • Backtests align calendars at any timestamp resolution (#1560, thanks @Shizoqua). The engine merged symbol calendars and placed prices through raw nanosecond integers, but a local duckdb source serves microseconds.   • Mean-variance style optimizers size a short by its own expected return (#1548, thanks @Shizoqua). The signal itself took the worst of the available metrics and was not fooled; the published number was.

  • qlib158 CNTP / CNTN / CNTD stop counting a missing close as a flat day (#1459, thanks @cgycorey) — the 15 factors (three families × 5 / 10 / 20 / 30 / 60 windows) turn close > prev close into 0/1 and average it, and a NaN comparison reads False. The registry mask from #1377 blanks the gap bar itself, but every later window that still held the gap counted the halt as a day that neither rose nor fell, so cntd read closer to zero than the observed days say. The comparison is NaN now wherever either close is missing: a gap blanks window + 1 rows and the value returns, equal to the gap-free run, once it scrolls out. The same rule moves the first value from row window - 1 to row window, matching each factor's min_warmup_bars, because the first bar has no prior close. On sparse panels this can trip the registry's >95% NaN guard; each factor's notes states from what missing-bar fraction.

  • qlib158 WVMA takes the absolute return in its numerator, as upstream does (#1594, thanks @Shizoqua) — wvma5 … wvma60 computed ts_std(ret·v) / ts_mean(|ret|·v), a signed numerator over an absolute denominator, where qlib's formula takes Abs on both. Every value of the five factors changes. The finishing commit (a5d47c20) points the attribution header at the upstream file that actually defines WVMA (qlib/contrib/data/loader.py, MIT) instead of handler.py, and pins the formula against an independent scalar oracle, a gap and all-zero volume.

  • GTJA alphas 103, 133 and 177 score a fresh extreme high, not low (#1604, thanks @Shizoqua) — HIGHDAY / LOWDAY count bars since the extreme, but the port put the 0-based window index, counted from the oldest bar, in their place. Alpha 103 read a low set today as 5 and a low 19 bars old as 100: the recency signal was inverted. The PR restored the direction one bar off (95 and 0). The finishing commit (0244ecea) counts days since the extreme with today as 0, so alphas 103 and 177 run from 5 to 100 over a 20-bar window, and takes the most recent bar on a tie. It also corrects gtja191/LICENSE.md to cite the Guotai Junan report of 2017-06-15 by Li Chen and Liu Fubing, where the zoo had named a 2014 report.

  • A custom zoo root no longer replaces the bundled alpha of the same name (#1468, fixes #1465, thanks @cgycorey) — Registry(zoo_root=...) loaded custom alpha files into sys.modules under the bundled module's own name. Once a custom root had computed its own qlib158/cntp5.py, a default Registry() in the same process computed the custom code too. The import cache is keyed by module path and zoo root now; module names and relative imports inside a custom root are unchanged. No shipped caller passes zoo_root; it is the path tests and plugins use.

Quant Library and analysis tools

  • A strict-bench OOS split needs two IC observations on each side (#1559, thanks @Shizoqua). A split outside the loaded prices is refused. An alpha whose IC series leaves fewer than two observations on either side is skipped, with the counts in the reason. The IC series ends one forward-return horizon before the prices, so a split one bar from the end used to publish verdicts measured on nothing.

  • Quant inputs are checked before they are used (#1555-#1558, thanks @Shizoqua). HRP aligns a supplied correlation matrix, and the covariance's own rows, to the covariance's column labels; swapping two rows used to move the weights with no error. Purged cross-validation refuses an unordered or duplicated timestamp index, and a label that ends before it starts. Impact models and every fixed-income entry point refuse NaN and infinities instead of returning NaN prices, durations and curves.

  • Shadow-account overtrading uses the whole trading window (#1563, thanks @Shizoqua). A long hold that closed before later short trades no longer shrinks the span.

  • Event-study z-statistics no longer over-reject (#1466). A CAR's standard error summed each day's variance, ignoring that every day is forecast with the same estimated parameters, so the days' abnormal returns are correlated. On null data, the standardised CAR's variance was 1.11 with a 120-day estimation window and 1.41–1.46 with a 30-day one. It is now 1.02 and 1.07, which is only the t correction for an estimated residual variance. Patell and BMP inherit the fix; market_adjusted was already right.

  • Shadow account: an other-market rule no longer matches every symbol (#1538, thanks @Shizoqua), and overtrading PnL no longer double-counts trades already explained (#1475).

  • Quantlib: comps refuses negative bridge magnitudes like the DCF bridge (#1535, thanks @Shizoqua); accrued interest is exact on coupon dates under 30/360 and rejects an unknown day count there too (#1509); Kyle's lambda fits an intercept (#1477).

  • ML strategy: a single-class training window is skipped and the previous model keeps predicting (#1522, thanks @Shizoqua). Memory: two entries with one title and different types keep separate index rows, and forget names the type when ambiguous (#1525). Swarm run and task files use unique temp names (#1536).

  • Patell z uses each normal-return model's own degrees of freedom (#1449, thanks @Shizoqua) — the df / (df - 2) correction in event_study assumed the market model's two estimated parameters for every event, so market_adjusted (none estimated) and mean_adjusted (one) over-stated the variance and reported a slightly smaller |z|, and a larger p-value, than their own fits support. The market model is unchanged. The finishing commit (844b13b9) has estimate_market_model read its residual degrees of freedom from the same table, so the two cannot drift apart.

  • Microstructure estimators refuse NaN and infinite inputs (#1451, thanks @Shizoqua) — a non-finite price came back from roll_effective_spread as a 0.0 spread, kyles_lambda returned nan, and vpin produced a series from NaN or negative volumes. All three raise now, and vpin also refuses a non-finite bucket_size. amihud_illiquidity drops an infinite row the way it already dropped a NaN one; before, an infinite return made the ratio infinite and an infinite volume counted as a zero-illiquidity day. The accept side is pinned too (c6010208): constant prices are a zero spread, all-zero order flow a zero lambda, and zero-volume bars leave VPIN unchanged.

  • Copula pseudo-observations give ties one rank and leave NaN missing (#1453, thanks @Shizoqua) — the double argsort ranked tied values by position ([1, 1, 3] became 0.25 / 0.5 / 0.75) and sorted a NaN last, handing it the column's top rank and counting it in the normaliser. pseudo_observations uses average ranks now, keeps a NaN as NaN with each column normalised by its own count of observations, and refuses infinite values.

  • spread_term_structure keeps tenor 5 and 5.0 in one column (#1507, thanks @Shizoqua) — the column name was built from the raw key, so issuers quoting the same tenor as an int and as a float were split across 5Y_spread_bp and 5.0Y_spread_bp, each NaN for the other group. The reference-curve lookup already treated the two as one tenor.

  • Purged cross-validation refuses a timestamp label index it cannot map (#1556, thanks @Shizoqua) — label end times passed as a Series are turned into positions with searchsorted, which assumes a sorted index. An unordered or duplicated index mapped label ends to the wrong rows with no error, so the purge protected the wrong rows; it raises now. The finishing commit (250ef746) closes the neighbouring gap: a timestamp label ending before its own start was clipped up to it (ends at positions [1, 0, 3, 3] came back as [1, 1, 3, 3]) and now raises, as the positional form already did. A NaT end stays allowed and purges through the last observation.

  • Market-impact models refuse infinite inputs (#1557, thanks @Shizoqua) — NaN was already refused, but positive infinity passed every positivity check: an infinite ADV priced a linear_impact or sqrt_impact order at zero impact, and an infinite price, traded volume or bps returned an infinite buy fill. Price, volume, ADV, bps, impact coefficient, volatility and eta must all be finite now.

  • The correlation-analysis cointegration examples call the Quant Library (#1404, thanks @Shizoqua) — the skill's Engle-Granger example carried its own statsmodels fit and raised KeyError on an unnamed Series, because it looked the hedge ratio up by the series' name. The PR named the regressor; the finishing commit (bd29a187) replaced the local fit with find_hedge_ratio, cointegration_test and adf_test from src.quantlib.timeseries, and the half-life example with compute_half_life. The example now inherits their refusal to pair two legs on different indices positionally, keeps its result keys and adds half_life.

  • portfolio_risk_xray works on windows longer than 250 bars (#1462, closes #1461, thanks @he-yufeng) — the tool fetched prices under the shared 250-row cap. Above it fetch_market_data returns a sampled envelope rather than the bar list the tool parses, so a window of 251 bars or more failed with "no close prices returned for any requested symbol", which is about anything over a year of daily bars. It requests every row now (max_rows=0, as technical_indicators does); volatility, VaR/ES and drawdown need consecutive bars regardless.

  • benford_check reads the leading digit from the number as written (#1591, thanks @Shizoqua) — financial_rigor's Benford check took the digit from 10 ** frac(log10(v)), which lands just under an integer for some exact round values, so 5000 counted as a leading 4. Among the integers 1 to 100,000, twelve were misread (8, 30, 40, 50, 80, 500, 600, 900, 5000, 6000, 9000, 50000). The PR rounded before truncating, which would have read 4999.9999999 as a 5; the finishing commit (d0ef98a6) takes the first significant digit of a Decimal built from the supplied value instead, with no float round-trip. Zero, NaN and infinite values are still skipped.

  • The sentiment scorer reads "low" as bearish only (#1448, thanks @Shizoqua, thanks @Shizoqua) — "low" was in both the bullish and the bearish word lists, so it cancelled itself and shares tumbled to a new low today scored neutral. It was the only word in both; a test now keeps the lists disjoint.

  • Head-and-shoulders detection checks shoulder symmetry on negative series (#1456, thanks @Shizoqua) — the pattern tool divided the shoulder gap by the signed shoulder average. On a series below zero the ratio went negative and always passed the 5% test, so clearly asymmetric shoulders were flagged as a pattern. It divides by the absolute average now, as double_top_bottom already did.

Live trading, brokers and the strategy store

  • Robinhood live trading reads and trades the account the mandate names (#1442). The runner, the pre-trade gate and the commit-time ceiling fetch called Robinhood with no account_number, and read replies one level too shallow (data.positions where Robinhood nests data.data.positions). So every reconciliation aborted, and the gate refused every order because it could not read positions. The tests stayed green only because their fake replies had a shape Robinhood never sends. A Robinhood mandate is now bound at commit to one account from get_accounts: listed, not deactivated, and open to agentic trading. The Web confirm dialog and the CLI both ask for it, and never take it from the agent-written proposal. Every runner and gate call sends that account, and an order naming another account is refused. Held positions, which Robinhood reports without a price, are priced the way a quantity order already was, and one that cannot be priced fails the exposure check closed. Existing Robinhood mandates must be committed again with an account.

  • SDM decay metrics treat NaN and infinite bench results as missing (#1447, thanks @0xouzm) — three stored sharpe=inf rows read as healthy, so a non-dry sdm_decay_scan moved a strategy in monitoring back to active, and -inf read as critical. SQLite keeps infinities as written, so the persistent store was affected too. compute_decay_metrics now drops non-finite values, independently for IC and Sharpe, before the three-observation minimum.

  • A mandate narrowed to zero exposure is stored as zero (#1593, thanks @Shizoqua, thanks @Shizoqua) — narrowing max_total_exposure_usd or account_funding_usd to 0 at commit is legal, but the cap mapping used x or default, so the saved mandate got the order cap back as its exposure limit: the commit widened what the user had just narrowed. An explicit zero now persists, and an order checked against that mandate breaches max_total_exposure_usd.

  • A malformed Robinhood buying_power is a shape error, not an unknown (#1526, thanks @lorenzozanee) — a non-null buying_power that was not an object (a bare number, string or list) was read as unknown and passed; it now raises, so the portfolio source errors instead of carrying the reply. An omitted or null value stays unknown and zero stays valid. As merged the PR also refused an omitted buying_power; 46892136 restored that case to unknown, which is what the PR description specified.

  • Interval and event triggers carry market=None again (#1599, thanks @woshi77777stars, thanks @woshi77777stars) — Trigger.market was both a dataclass field and a classmethod factory, so every non-market trigger carried the bound method as its market, and dataclasses.asdict() + json.dumps() raised on it. due_now() was unaffected. The factory is bound after the class body (d0ef98a6 keeps subclass binding intact), and a repo-wide static test fails on any dataclass or NamedTuple field shadowed this way.

  • With an MT5 profile selected, search_symbol resolves the broker's own symbols (#1597, closes #1589, thanks @lorenzozanee) — it returned no MT5 candidate for an explicit symbol such as XAUUSD, so the identity gate blocked trading_quote, trading_history and get_market_data. Search now reads the configured terminal's catalog by terminal_path with no login credentials. After 47a036d6 every query is answered from that terminal while MT5 is selected, a web-search hit is never substituted, and an ambiguous alias is refused.

  • Backtests attach to the running MT5 terminal without seeing its credentials (#1598, thanks @he-yufeng) — the sandbox's ephemeral HOME had no mt5.json, so the loader attached bare and a forex backtest could fall through to akshare while get_market_data used MT5 in-process. The sandbox now gets only terminal_path and timeout (validated by 47a036d6), never login, password or server, and a bare attach warns that the SDK may pick another installation logged into another account.

  • Dhan paper orders reject fractional share quantities (#1595, thanks @Shizoqua, thanks @Shizoqua) — 0.5 passed the positive check and truncated to 0, returning a successful simulated fill for zero shares, and 1.5 silently became 1. Only whole numbers of at least one share are accepted; a5d47c20 parses with Decimal, so 1.00000000000000001 is refused too, and NaN, infinity or text return an error instead of raising.

Swarm workers

  • A swarm worker can load only the skills its spec lists (#1414, thanks @shadowinlife, thanks @shadowinlife) — SwarmAgentSpec.skills was read only to filter the prompt, so load_skill loaded any skill a worker named. The worker's load_skill now refuses a skill outside the list and names the ones allowed. An empty list stays unrestricted, as the prompt filter treats it; the main agent is unchanged.

  • A swarm tool that declares run_dir gets the directory the model named, confined to the agent's workspace (#1430, thanks @cgycorey) — the worker overwrote every call's run_dir with the workspace, so backtest, exposed to 19 preset agents, never saw the directory it was given. A relative path now resolves under the workspace, an absolute one inside it is kept, and one outside is refused with an error naming the workspace. Tools that do not declare run_dir still get the workspace.

  • Every swarm worker that writes its summary also writes its message log (#1439, thanks @cgycorey) — messages.json is the only record of the arguments the model asked a tool for, and the completed, token-limit, content-filter and incomplete exits wrote summary.md without it, so the most common outcome left no log. Both files now go through one writer. A failed LLM call still writes neither.

Agent loop, providers and goals

  • An explicit provider header survives an ambient twin (#1573, #1568, thanks @zeus229). When OPENAI_CUSTOM_HEADERS names a header the provider also sets (a user-agent beside the Kimi / NVIDIA / OpenCode User-Agent), openai 3.19.2's case-insensitive merge dropped the provider's value. That turned CI red for every PR on 2026-09-24. The first fix proposed would have sent both headers under openai 2.53, the version the lock file and the Docker image install. Every ambient spelling is now omitted and the explicit value re-set after the omits, which holds under both.

  • Read-only results lost to context compaction are restored, not refetched (#1488, thanks @zeus229). A successful read-only call whose payload compaction removed is replayed from the run's own cache, at most six times a run; past the cap it runs again, as it did before, instead of being refused with "use the previous result" for a payload the model cannot see. The cap is checked per restore, and any successful write empties the cache, so a regenerated file is read afresh. read_url opts in; no_cache=true always fetches.

  • OpenAI's gpt-5.6 models run with their reasoning on the agent's default configuration (#1473). /v1/chat/completions refuses function tools for gpt-5.6-terra and gpt-5.6-luna unless reasoning_effort is none, including when no effort is configured and the model applies its own default, so a plain LANGCHAIN_PROVIDER=openai setup failed on its first tool call with Function tools with reasoning_effort are not supported. The adapter now treats that refusal the way it treats a rejected temperature or stream_options: the request is retried on /v1/responses, where the effort travels as reasoning.effort, and the model is remembered for the rest of the process so later calls go there first. Nothing changes for a model whose chat endpoint accepts tools, and LANGCHAIN_USE_RESPONSES_API=true still selects the route up front and skips the one failed request.

  • A research goal that is an order is still refused (#1562, thanks @Shizoqua). The execution filter no longer rejects research that mentions shares or coins ("should the fund sell its GOOGL shares"). It refuses an objective that opens with buy or sell, puts a quantity right after the verb, or writes 买入 / 卖出 with a quantity and a unit. The first version of the change had made "Buy 100 shares of NVDA" an accepted goal.

  • Research goals refuse an order that puts "now" or "immediately" before the verb (#1605, thanks @Shizoqua) — the execution filter matched only the verb-then-cue order, so Immediately buy TSLA, Now sell GOOGL and Please immediately short TSLA were accepted as research objectives. The mirrored rule requires the cue to sit directly before the verb, with only separators and an optional please between them. The first version allowed up to 40 characters there and also refused Now research whether to buy AAPL; the finishing commit (0244ecea) keeps that and similar research phrasings accepted. The check runs on a goal's objective, on each of its criteria and on an objective update.

  • The tail a full compaction keeps counts a thinking model's reasoning (#1582, thanks @Shizoqua) — the layer-3 tail is sized to a 20K-token budget, but the sizing read content and tool-call arguments and skipped reasoning_content, so on reasoning-heavy turns the kept tail could run far past its budget and compaction freed less than intended. The reasoning text is counted now, as the loop's token estimate already counted it.

  • technical_indicators results are restored after compaction instead of fetched again (#1601, thanks @zeus229) — the tool is read-only but repeatable, and a repeatable tool is replayed from the run's memory only if it opts in; it did not, so an identical request after compaction re-ran the market-data fetch. It opts in now, like web_reader, within the loop's existing replay budget.

  • Token counts and Polymarket CLOB token ids are no longer redacted as credentials (#1606, thanks @Shizoqua) — the token credential marker is a substring match, so token_budget, token_usage, total_input_tokens, total_output_tokens and clob_token_id read [redacted] in traces, event previews and the live audit ledger. Since 0244ecea each is released only in its expected shape (a non-negative integer, a map of counts, a decimal uint256 id); any other value under those names stays redacted.

  • A remote MCP tool with a malformed properties schema still gets a valid one (#1607, thanks @Shizoqua) — normalize_mcp_tool_schema dropped a non-object properties such as a string or a list and then skipped the {} fallback, so the tool reached the model as an object schema with no properties key at all. It gets {} now, unless the top level composes anyOf / oneOf / allOf.

  • The Copilot credential fallback re-reads the token after 60 seconds (#1619, closes #1617, thanks @lorenzozanee) — when neither COPILOT_GITHUB_TOKEN nor OPENAI_API_KEY is set, get_llm_credentials falls back to GH_TOKEN / GITHUB_TOKEN or gh auth token, and it cached that answer for the life of the process. The cache now expires after 60 seconds. Its consumer is provider diagnostics: Copilot requests go through the SDK client, which resolves credentials each time it is created.

Channels, memory and configuration

  • The Email channel verifies TLS certificates by default (#1544, thanks @shadowinlife). The implicit-SSL paths (IMAP4_SSL / SMTP_SSL) in both the connection probe and the polling/send adapter used Python's default unverified context (CERT_NONE, no hostname check), so the mailbox password travelled to a server whose certificate was never checked — an active network attacker between the operator and their mail provider could harvest it. All four call sites now build their context through a shared email_tls_context() that verifies the certificate and hostname against the system CA bundle, matching the STARTTLS path, which already did. A new verify_tls field (default true, surfaced in the guided Email setup in all nine locales) is the documented opt-out for self-signed or internal-CA servers. Upgrade note: a mail server with such a certificate connected before this change and now fails the TLS handshake until verify_tls is set to false for it.

  • Plain IMAP no longer sends the mailbox password in clear text (after #1544). With imap_use_ssl off, the Email channel and its connection test logged in over an unencrypted connection, and the guided setup put that switch one click away. A new imap_use_tls (on by default, the IMAP twin of smtp_use_tls) upgrades the connection with STARTTLS before LOGIN; a server that offers no STARTTLS is reported as a network failure before the password is sent. verify_tls now governs STARTTLS on IMAP and SMTP as well as implicit SSL, so a self-signed server can opt out on any path. Upgrade note: an imap_use_ssl: false setup against a server without STARTTLS stops connecting until imap_use_tls is set to false for it, which sends the password in plain text again.

  • Settings-write routes reject cross-site browser requests (#1544, thanks @shadowinlife). require_settings_write_auth did not apply the cross-site guard that its siblings require_auth and require_event_stream_auth enforce on unsafe methods, so a malicious web page could attempt a CSRF write against any settings route — including the new POST /channels/email/test, which merges stored credentials with a caller-supplied patch and could be steered to send the stored mailbox password to an attacker-chosen host. The guard now runs first on every settings-write route; same-origin Web UI calls and non-browser clients (CLI/curl, no Origin) are unaffected.

  • Channel adapters log through stdlib again: {} placeholders, napcat's 17 sites and loguru-only .opt() calls lost their messages (signal's _safe_handle raised instead of swallowing) (#1533, #1531, thanks @shadowinlife). Slack DMs from unapproved senders get a pairing code (#1524, thanks @Shizoqua); Discord no longer pings @everyone or roles (#1537); duplicate-reply suppression covers integer message ids and is bounded (#1476); the WebSocket channel starts again (from #1521).

  • Two memories sharing a title keep separate index rows and links (#1545, thanks @Shizoqua). Under VT_MEMORY_HIERARCHY an entry lives at {memory_type}/{slug}.md, so two entries with one title had the same path.name: the second add() overwrote the first's MEMORY.md row, and the semantic-link block beside it excluded the other entry as "self" and wrote an ambiguous target. Both key on the path relative to the memory dir now; a sidecar written earlier, with a bare filename or an absolute path, is still read.

  • /agent.json, /agent.yaml and /agent.yml are gitignored at the runtime root; the Feishu QR login already wrote channel credentials there.

  • Signal channel: stripping the bot's mention no longer removes the wrong character after an emoji (#1478, thanks @Shizoqua) — Signal reports a mention's start and length in UTF-16 code units, and the channel sliced the Python string with them directly. Each character outside the Basic Multilingual Plane (most emoji) before the mention shifted the slice by one, so the mention placeholder stayed in the text handed to the agent and the neighbouring character was cut instead. Offsets are converted to string indices before a mention is stripped or tested as a leading mention.

  • A file received over DingTalk is saved inside its download directory whatever it is named (#1506, thanks @Shizoqua) — the adapter joined the inbound fileName to the per-sender download path unsanitized, so a name with ../ segments, or an absolute path (which replaces the whole path when joined), could write outside it. The name goes through safe_filename now, as the other adapters already sanitize a remote file name.

  • A channel that fails to load logs which one and why (#1580, thanks @Shizoqua, thanks @Shizoqua) — two channel-registry log calls had two %s placeholders and one argument, so an external plugin that failed to import, or a built-in channel skipped for a missing SDK (at debug level), printed --- Logging error --- instead of its name and the exception.

  • The README says which process owns Telegram polling (#1583, closes #1553, thanks @lorenzozanee) — Telegram allows one getUpdates poller per bot token. vibe-trading serve owns the channel runtime, and channels start asks the running server (VIBE_TRADING_API_URL, default http://127.0.0.1:8000) to start it rather than polling itself, so the conflict to avoid is a second server process with the same token enabled.

  • Memory garbage collection no longer compresses an entry it just archived (#1450, thanks @Shizoqua) — the compression pass reused the entry list read before archiving, so an entry just moved to archive/ was compressed from a path that no longer existed and logged a failure. 451c554a skips by whether the file still exists, not by id: ids are six hex characters two files can share, and an archive step that failed leaves its file to be compressed.

  • An unparseable optional numeric setting falls back to its default instead of failing config load (#1592, thanks @Shizoqua) — the coercion that drops a bad int / float env value skipped int | None fields, so ANTHROPIC_MAX_TOKENS=not_a_number raised while building EnvConfig. Optional fields get the same fallback now; a parseable value outside the field's bounds (ANTHROPIC_MAX_TOKENS=0) is still rejected.

Web UI and locales

  • Leaving a chat cancels its pending history scrolls — a scroll scheduled while a conversation's history loaded could still fire after leaving it, and a history load still in flight could schedule another.

  • A welcome-screen quick action stays highlighted after you click it (#1500, thanks @shadowinlife) — the first chip was styled as selected by its position, whatever had been clicked, so the chip you chose never lit up. The highlight now follows the click and moves with the next one, and each chip reports aria-pressed.

  • Broker SDK diagnostics no longer name Longbridge for every broker (#1436, thanks @tingkk) — the shared sdk_missing and network_unreachable messages on the Runtime page and in the chat connector status said Longbridge whichever broker raised them, so an unreachable Futu OpenD gateway sent the user to check Longbridge. They now name the affected broker's SDK, service or local gateway, in every locale.
