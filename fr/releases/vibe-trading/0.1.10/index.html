Vibe-Trading v0.1.10

🌍 v0.1.10 — Couche de données globale + roll-up depuis 0.1.9

v0.1.10 est une version roll-up. Le titre est la Couche de données mondiale : le registre de données de marché passe de 10 à 18 sources et gagne 18 outils de données en lecture seule qui vont au-delà de l'OHLCV dans les fondamentaux et les flux, tous exposés sur MCP. Autour de lui, tout ce qui a été accumulé depuis 0.1.9 est livré : 10 connecteurs de courtier SDK, la pile complète Alpha Zoo alpha compare, une révision de la fiabilité du fournisseur, Research Autopilot Phase 1, un cache de données local opt-in et une vague de renforcement de la sécurité pilotée par la communauté. Cette version est disponible sur les versions PyPI, ClawHub et GitHub.

pip install -U vibe-trading-ai
# or
uv tool install --reinstall vibe-trading-ai

Faits saillants

🌍 Couche de données globale — 18 sources + 18 outils de données en lecture seule

Le registre des chargeurs passe de 10 à 18 sources de données de marché :

  • Gratuit, sans clé — tushare, okx, yfinance, akshare, baostock, tencent, mootdx, ccxt, futu, local, plus quatre nouveaux ajouts directs API : Eastmoney, Sina, Stooq et un HTTP direct Yahoo client.
  • Fournisseurs américains à clé facultatifs — Finnhub, Alpha Vantage, Tiingo, FMP ; les clés absentes sont ignorées dans la chaîne de secours, ne la faites jamais planter. Les chaînes de secours sont réorganisées en fonction du risque d'interdiction IP (points de terminaison publics légers et tolérants à la limitation ; pistes REST sécurisées par clé) derrière une porte HTTP limitée partagée (backtest/loaders/_http.py) avec des tranches de débit par hôte, une gigue et une réutilisation de session. Au sommet 18 outils de données en lecture seule : flux de fonds, tableau dragon-tigre, flux vers le nord (Stock-Connect), négociation sur marge, transactions en bloc, nombre d'actionnaires, expiration du blocage, appartenance au secteur, rapports de recherche, actualités, dépôts auprès de la SEC (EDGAR + XBRL), états financiers, chaînes d'options, participations institutionnelles, sélection complète du marché, recherche de symboles, macro FRED et recherche d'actions A en langage naturel iwencai - sur Actions A / États-Unis / HK, tous exposés sur MCP. Trois clients partagés (eastmoney / yahoo / sec_edgar) soutiennent les chargeurs et les outils, et un index data-routing consolidé ainsi que des compétences eastmoney / sec-edgar par source documentent la couche.

💱 10 connecteurs de courtier SDK — lecture + papier, mandat en direct

Le trading s'effectue en priorité sur le connecteur : choisissez un profil, et le papier/en direct est un attribut du connecteur. Cette version porte la liste à 10 courtiers — IBKR (TWS/Gateway local en lecture seule) · Robinhood (Agentic MCP, OAuth) · Tiger · Longbridge · Alpaga · OKX · Binance · Futu · Dhan · Shoonya (Inde NSE/BSE + F&O). Les connecteurs Direct-SDK partagent un transport broker_sdk et chacun lit + passation de commande sur compte papier ; le placement en direct passe une seule porte d'autonomie limitée fermée par échec (sdk_order_gate.py : mandat + kill switch + audit). Les courtiers sans aucun discriminateur papier d'exécution/live (Longbridge, Dhan, Shoonya) sont structurellement limités à papier + lecture seule — leurs place_order / cancel_order refusent catégoriquement toute configuration non papier à la première ligne. Les outils de passation de commandes restent hors MCP (agent + CLI uniquement).

📊 Comparaison alpha entre CLI / REST / Web / outil d'agent

vibe-trading alpha compare classe n'importe quel ensemble de facteurs Alpha Zoo par IC/IR sur votre univers, partageant un noyau compare_runner.compare_alphas derrière le CLI, une route REST POST /alpha/compare avec progression diffusée en continu SSE, la vue de comparaison de l'interface utilisateur Web Alpha Zoo et un outil d'agent alpha_compare en lecture seule. Un filtre de sous-ensemble run_bench(only=…) analyse uniquement les facteurs comparés au lieu de l'ensemble du zoo.

🔌 Refonte de la fiabilité des fournisseurs

Une couche de capacités de fournisseur contrôle la capture/la relecture du raisonnement, les signatures de pensée Gemini, l'agent utilisateur Kimi et les corps de raisonnement OpenRouter par fournisseur. vibe-trading provider doctor imprime un instantané de diagnostic expurgé. Les échecs de streaming génèrent désormais un ProviderStreamError explicite et expurgé (portant status_code + .retryable) avec une nouvelle tentative pour les transitoires et un échec rapide sur 4xx ; un reasoning_delta SSE limité pilote un indicateur d'activité « Raisonnement… » dans l'interface utilisateur Web. Également : un adaptateur DeepSeek natif en option (VIBE_TRADING_DEEPSEEK_ADAPTER), des délais d'attente pour les outils en lecture seule (VIBE_TRADING_TOOL_TIMEOUT_SECONDS) et une gestion de la température par fournisseur (Kimi-k2 forcé à 1.0, MiniMax bloqué > 0).

🔬 Recherche sur le pilote automatique phase 1

run_research_autopilot transforme un hypothesis_id en objectif de recherche (thèse comme objectif, critères d'acceptation pertinents pour le backtest, conseils pour l'étape suivante), et generate_backtest_config écrit automatiquement un backtest config.json à partir de l'univers de l'hypothèse et des sources de données — de sorte que l'agent passe directement de l'idée → signal_engine.py → exécuter.

🗃️ Activer le cache de données local + chargeur local

VIBE_TRADING_DATA_CACHE=1 met en cache les barres installées dans ~/.vibe-trading/cache (domicile de l'utilisateur, jamais le dépôt) ; un garde d'obsolescence ne met jamais en cache une plage se terminant aujourd'hui, et les images mises en cache sont identiques en octets aux récupérations en direct. Un nouveau chargeur local lit OHLCV directement à partir de vos propres fichiers CSV / Parquet / DuckDB via ~/.vibe-trading/data-bridge/config.yaml, avec prise en charge normale de la chaîne de secours.

🛡️ Vague de sécurité & de durcissement

Une passe de renforcement pilotée par la communauté : authentification d'écriture des paramètres API (#245), adhésion à l'outil shell de l'agent (#243), rejet de la liaison de l'hôte en boucle (#242), authentification d'arrêt local explicite (#241) et confinement des identifiants pour les identifiants de proposition de mandat (#256), les types de mémoire persistante (#257) et les identifiants d'exécution d'essaim MCP (#258). Plus un arrêt réactif à mi-parcours + une reconnexion SSE au retour à une session en cours (#229), un repli multimoteur web_search (#231) et un aller-retour Gemini thoughtSignature via des appels d'outils compatibles OpenAI (#176, #184).

🪪 Les rapports de versions sont désormais cohérents

--version, le REST API (/docs + /api), la poignée de main du serveur MCP et le pied de page de l'interface utilisateur Web proviennent tous d'une seule source : le REST API avait dérivé vers un mauvais 5.0.0 codé en dur. L'emballage fournit également désormais des exemples de scripts de compétences dans la roue, et l'image Docker installe les bibliothèques natives de weasyprint pour le rendu des rapports PDF.

Vibe-Trading v0.1.10

🌍 v0.1.10 — Global data layer + roll-up since 0.1.9

v0.1.10 is a roll-up release. The headline is the Global data layer: the market-data registry grows from 10 to 18 sources and gains 18 read-only data tools that reach past OHLCV into fundamentals and flow, all exposed over MCP. Around it ships everything accumulated since 0.1.9 — 10 broker SDK connectors, the Alpha Zoo alpha compare full stack, a provider-reliability overhaul, Research Autopilot Phase 1, an opt-in local data cache, and a community-driven security-hardening wave.

This release is available on PyPI, ClawHub, and GitHub Releases.

pip install -U vibe-trading-ai
# or
uv tool install --reinstall vibe-trading-ai

Highlights

🌍 Global data layer — 18 sources + 18 read-only data tools

The loader registry grows from 10 to 18 market-data sources:

  • Free, no key — tushare, okx, yfinance, akshare, baostock, tencent, mootdx, ccxt, futu, local, plus four new direct-API additions: Eastmoney, Sina, Stooq, and a direct-HTTP Yahoo client.
  • Optional key-gated US providers — Finnhub, Alpha Vantage, Tiingo, FMP; absent keys are skipped in the fallback chain, never crash it.

Fallback chains are re-ordered by IP-ban risk (lightweight, throttle-tolerant public endpoints lead; key-gated REST trails) behind a shared throttled HTTP gate (backtest/loaders/_http.py) with per-host rate buckets, jitter, and session reuse. On top sit 18 read-only data tools — fund flow, dragon-tiger board, northbound (Stock-Connect) flow, margin trading, block trades, shareholder count, lockup expiry, sector membership, research reports, news, SEC filings (EDGAR + XBRL), financial statements, options chains, institutional holdings, full-market screening, symbol search, FRED macro, and iwencai natural-language A-share search — across A-share / US / HK, all exposed over MCP. Three shared clients (eastmoney / yahoo / sec_edgar) back the loaders and tools, and a consolidated data-routing index plus per-source eastmoney / sec-edgar skills document the layer.

💱 10 broker SDK connectors — read + paper, mandate-gated live

Trading is connector-first: pick a profile, and paper/live is an attribute of the connector. This release brings the roster to 10 brokers — IBKR (local read-only TWS/Gateway) · Robinhood (Agentic MCP, OAuth) · Tiger · Longbridge · Alpaca · OKX · Binance · Futu · Dhan · Shoonya (India NSE/BSE + F&O). Direct-SDK connectors share a broker_sdk transport and each does read + paper-account order placement; live placement passes a single fail-closed bounded-autonomy gate (sdk_order_gate.py: mandate + kill switch + audit). Brokers with no runtime paper/live discriminator (Longbridge, Dhan, Shoonya) are structurally capped at paper + read-only — their place_order / cancel_order hard-refuse any non-paper config at the first line. Order-placing tools stay off MCP (agent + CLI only).

📊 Alpha compare across CLI / REST / Web / agent tool

vibe-trading alpha compare ranks any set of Alpha Zoo factors by IC / IR on your universe, sharing one compare_runner.compare_alphas core behind the CLI, a POST /alpha/compare REST route with SSE-streamed progress, the Alpha Zoo Web UI Compare view, and a read-only alpha_compare agent tool. A run_bench(only=…) subset filter benches only the compared factors instead of the whole zoo.

🔌 Provider-reliability overhaul

A provider capability layer gates reasoning capture/replay, Gemini thought signatures, Kimi user-agent, and OpenRouter reasoning bodies per provider. vibe-trading provider doctor prints a redacted diagnostic snapshot. Streaming failures now raise an explicit, redacted ProviderStreamError (carrying status_code + .retryable) with one retry for transients and fail-fast on 4xx; a throttled reasoning_delta SSE drives a "Reasoning…" liveness indicator in the Web UI. Also: an optional native DeepSeek adapter (VIBE_TRADING_DEEPSEEK_ADAPTER), read-only tool hard-timeouts (VIBE_TRADING_TOOL_TIMEOUT_SECONDS), and per-provider temperature handling (Kimi-k2 forced to 1.0, MiniMax clamped > 0).

🔬 Research Autopilot Phase 1

run_research_autopilot turns a hypothesis_id into a research goal (thesis as objective, backtest-relevant acceptance criteria, next-step hints), and generate_backtest_config auto-writes a backtest config.json from the hypothesis's universe and data sources — so the agent goes straight from idea → signal_engine.py → run.

🗃️ Opt-in local data cache + local loader

VIBE_TRADING_DATA_CACHE=1 caches settled bars to ~/.vibe-trading/cache (user home, never the repo); a staleness guard never caches a range ending today, and cached frames are byte-identical to live fetches. A new local loader reads OHLCV straight from your own CSV / Parquet / DuckDB files via ~/.vibe-trading/data-bridge/config.yaml, with normal fallback-chain support.

🛡️ Security & hardening wave

A community-driven hardening pass: API settings-write auth (#245), agent shell-tool opt-in (#243), loopback-host rebinding rejection (#242), explicit local-shutdown auth (#241), and identifier containment for mandate proposal-ids (#256), persistent-memory types (#257), and MCP swarm run-ids (#258). Plus responsive Stop mid-stream + SSE reconnect on returning to a running session (#229), multi-engine web_search fallback (#231), and Gemini thoughtSignature round-trip through OpenAI-compat tool calls (#176, #184).

🪪 Version reporting is now consistent

--version, the REST API (/docs + /api), the MCP server handshake, and the Web UI footer all derive from one source — the REST API had drifted to a wrong hardcoded 5.0.0. Packaging also now ships skill example scripts in the wheel, and the Docker image installs weasyprint's native libs so PDF reports render.
