gstack v1.100.0.0

#gstack v1.100.0.0 #gstack v1.100.0.0 Cette version corrige cinq avis de sécurité dans une dépendance, sécurise les verrous du shell de gstack sur Ubuntu 26.04 et modifie la façon dont /ship écrit et examine les demandes d'extraction. Une vérification de crochet facultative est supprimée.

Correctifs

  • Sécurité : hono est épinglé sur 4.13.16, qui corrige cinq avis (GHSA-3gg2-335m-rxc6, GHSA-46wx-v44x-9hh2, GHSA-4h7h-rv7c-7m2v, GHSA-4m76-xfj5-7975, GHSA-h7mg-cq63-vhpq) trouvés dans 4.13.13. hono n'atteint gstack que via ses outils de développement et de test, et le propre code de gstack ne l'utilise jamais, donc aucun des cinq n'était accessible ; les contributeurs obtiennent le correctif sur leur prochain bun install. (#4408)
  • Les verrous shell de gstack admettent à nouveau exactement un titulaire sur Ubuntu 26.04 et l'actuel ubuntu-latest de GitHub, dont Rust mkdir signale le succès même lorsqu'un autre processus a d'abord créé le répertoire. Avant cela, deux mises à jour pouvaient déplacer une caisse à la fois, ou deux appels gstack-config set pouvaient se perdre mutuellement. (#4262)
  • La vérification de la documentation de /ship ne gaspille plus une de ses deux tentatives lorsque le modèle de vérification écrit du texte après sa ligne de résultat ; il est demandé une fois, gratuitement, de renvoyer seul le résultat. (#4285)
  • Une fois qu'une ligne de résultat dans cette vérification de documentation indique "bloqué", aucune ligne ultérieure ni aucune réponse renvoyée ne peuvent la transformer en réussite. Une lacune subsiste : un bloqueur écrit uniquement en texte brut après une ligne de résultat réussie dépend toujours de la réponse suivante qui le signale. (#4434)
  • Une compétence que vous avez écrite et dont le contrat répertorie toujours check_after_last_edit conserve ses autres chèques. Le crochet d'arrêt facultatif ignore uniquement cet élément et imprime une ligne SKILL_CONTRACT_SKIPPED nommant le fichier jusqu'à ce que vous le supprimiez ; un contrat qui ne mentionne rien d’autre n’est vérifié pour rien. (#4439)
  • gstack-pr-wait, gstack-ci-gate et la version stable n'appellent plus de commit vert lorsqu'une tentative précédente de vérification a échoué et qu'une réexécution n'a créé aucune tâche, ou lorsqu'un flux de travail a échoué avant de démarrer une tâche. Un statut de validation échoué compte également comme rouge. (#4257)
  • /ship donne la version d'une pull request qui fusionne une revue complète. Une révision antérieure ne compte plus une fois que les lignes supprimées par une branche ont changé avec sa base, et l'historique des révisions d'un organisme de relations publiques conserve chaque exécution de /ship au lieu de seulement la dernière. (#4365)
  • L'étape de test de /ship n'échoue plus avec E2BIG: argument list too long avant l'exécution de tout test sous Linux dans des projets comportant des milliers de fichiers de tests unitaires ; les fichiers sont répartis sur plusieurs processus d'exécution et comptés comme une seule exécution. (#4426)
  • La commande de test à distance de /ship ne place plus chaque fichier de test sélectionné sur une seule ligne de commande, ce que Linux refuse au-delà de 128 Ko. (#4429)
  • La page d'approbation de /autoplan renvoie un plan pour examen lorsque les deux réviseurs le contestent et ne sont pas d'accord sur le point de savoir s'il s'agit d'un changement de portée ou d'une commande, demande à un plan sans section ### Owner's words de confirmer sa direction dans ce cas également, et vérifie le devis du propriétaire uniquement par rapport au dossier d'approbation de ce référentiel. (#4441)
  • /ship accepte un correctif de documentation lorsque la vérification nomme le fichier avec un numéro de ligne, tel que notes.md:8 ou notes.md:8:12. (#4437)
  • Les exécutions Ubicloud démarrées ensemble ne peuvent plus dépasser la limite de vCPU du projet, une nouvelle commande ubi-runner.sh room indique combien de VM supplémentaires peuvent être utilisées, et deux propriétaires dont les identifiants partagent un préfixe ne suppriment plus mutuellement leurs VM expirées. (#4430)
  • La version stable quotidienne ne se bloque plus lorsque le test Windows nocturne de Gstack échoue ou ne se termine pas. (#4400)
  • L'exécution du test Windows nocturne se termine à nouveau dans le délai imparti, réparti sur huit fragments avec des horaires à jour. (#4409)
  • Le test d'installation de Windows s'exécute désormais lorsqu'une pull request modifie uniquement bin/gstack-lock.sh. (#4433)
  • L'évaluation de couverture de test /review n'échoue plus lors d'une exécution qui lit le fichier source lorsque zsh s'arrête à un echo ==== non cité. (#4364)
  • Seize liens de documentation dans docs/skills.md et docs/review-policy.md rejoignent leur section. Contribué par @Davmunrey. (#4394)
  • Le README relie les deux nouveaux guides, et les documents d'installation et de désinstallation comptent et nomment correctement les hooks d'installation. (#4403)
  • docs/releases.md indique que la version stable traite un statut de validation échoué comme rouge et un statut en attente comme toujours en cours d'exécution. (#4436)

Modifications

  • Les demandes d'extraction ouvertes par /ship affichent au plus trois lignes simples avant les sections réduites, et chaque fusion avec gstack-ship-queue land aboutit à un commit intitulé avec le titre PR. Le .gstack/plain-titles.json d'un référentiel peut désormais définir body_since (les anciens PR ne reçoivent que des avertissements) et étendre ou remplacer la liste par défaut de mots internes de gstack. Voir docs/writing-prs.md. (#4438)
  • /ship compte les cycles de révision par pull request au lieu de par exécution, donc un PR expédié plusieurs fois obtient toujours au maximum deux cycles de révision, et la version qui fusionne obtient toujours une révision complète. (#4360)
  • La page d'approbation de /autoplan montre la contestation d'un évaluateur concernant la portée, l'ordre, la direction, le coût ou l'emballage d'un plan comme choix pour le propriétaire, recommandant le changement de l'évaluateur, au lieu de "garder votre direction" par défaut. Les forfaits peuvent citer leur propriétaire sous ### Owner's words, et les forfaits d'application peuvent s'ouvrir avec une table ### Day one. (#4431)
  • La liste de compétences de Claude Code indique désormais quand utiliser chaque compétence gstack, donc des requêtes telles que "réviser mes modifications" sont chargées/révisées. La liste s'allonge d'environ 840 jetons par session. (#4387)
  • L'étape de test de /ship imprime PREGATE: time limit hit lorsqu'il manque de temps, et --step-timeout <seconds> définit son budget (une heure par défaut). (#4429)
  • Chaque compétence indique désormais à l'agent de poser une question une fois et d'ouvrir et de nettoyer chaque fichier avant de le remettre. (#4383)
  • Chaque compétence indique désormais à l'agent de ne jamais imprimer un environnement complet, une configuration Git ou une liste de processus, et d'attendre sur CI avec un appel gstack-pr-wait au lieu d'une boucle d'interrogation. (#4382)
  • Les agents gstack ouvrent chaque rapport d'état avec trois lignes, Failed or skipped:, Unverified: et Also changed:, et conservent le rapport sous 250 mots. (#4273)
  • Les documents de /captain nomment les lignes Failed or skipped: et Also changed: et indiquent qu'une ligne manquante est demandée dans un suivi, ce qui n'est jamais une raison pour rejeter le rapport. (#4432)
  • /eval-plan vérifie quatre choses qu'il laissait au jugement : les décisions et les sections de notation d'un pré-enregistrement, l'accord du juge avec les étiquettes manuelles, et trois façons courantes dont un résultat peut induire en erreur. (#4384)
  • gstack-runaway indique le coût des sillages froids et vides d'un thread, pas seulement combien il y en avait, et scan --wakes répertorie chaque sillage. (#4385)
  • Le guide de politique du navire explique comment fusionner toute demande de tirage avec gstack-ship-queue land, y compris dans un référentiel avec un seul responsable, avec une solution de repli gh pr merge épinglée. (#4377)
  • Deux nouveaux guides : résoudre un correctif dans le référentiel de quelqu'un d'autre et exécuter un test de jeu avec de vraies personnes. (#4380)
  • ETHOS.md termine sa section « Expliquer le nombre » avec une liste de contrôle de trois éléments pour les rédactions. (#4381)
  • docs/ship-policy.md documente le schéma .gstack/approval-classes.json, les commandes gstack-approval-classes et comment citer l'approbation d'un propriétaire. (#4355)

Suppressions

  • Le hook Stop optionnel ne vérifie plus qu'un test a été exécuté après la dernière édition ; /verify le demande plutôt en termes simples. Avec /verify chargé, Claude Opus 5.5 et GPT-6.1 Sol l'ont déjà fait dans 96 % et 89 % des exécutions, et la vérification a déplacé les résultats de -0.5 à +2 points, à l'intérieur du bruit. (#4428)

gstack v1.100.0.0

gstack v1.100.0.0

This release fixes five security advisories in a dependency, makes gstack's shell locks safe on Ubuntu 26.04, and changes how /ship writes and reviews pull requests. One optional hook check is removed.

Fixes

  • Security: hono is pinned to 4.13.16, which fixes five advisories (GHSA-3gg2-335m-rxc6, GHSA-46wx-v44x-9hh2, GHSA-4h7h-rv7c-7m2v, GHSA-4m76-xfj5-7975, GHSA-h7mg-cq63-vhpq) found in 4.13.13. hono reaches gstack only through its development and test tools, and gstack's own code never uses it, so none of the five was reachable; contributors get the fix on their next bun install. (#4408)
  • gstack's shell locks admit exactly one holder again on Ubuntu 26.04 and GitHub's current ubuntu-latest, whose Rust mkdir reports success even when another process created the directory first. Before this, two updates could move one checkout at once, or two gstack-config set calls could drop each other's keys. (#4262)
  • /ship's documentation check no longer wastes one of its two attempts when the checking model writes text after its result line; it is asked once, for free, to resend the result alone. (#4285)
  • Once any result line in that documentation check says "blocked", no later line and no resent answer can turn it into a pass. One gap remains: a blocker written only in plain text after a passing result line still depends on the resent answer reporting it. (#4434)
  • A skill you wrote whose contract still lists check_after_last_edit keeps its other checks. The optional Stop hook skips only that item and prints a SKILL_CONTRACT_SKIPPED line naming the file until you delete it; a contract that lists nothing else is checked for nothing. (#4439)
  • gstack-pr-wait, gstack-ci-gate and the stable release no longer call a commit green when an earlier attempt of a check failed and a rerun created no jobs, or when a workflow failed before starting any job. A failed commit status also counts as red. (#4257)
  • /ship gives the version of a pull request that merges a full review. An earlier review no longer counts once the lines a branch removes have changed with its base, and a PR body's review history keeps every /ship run instead of only the last. (#4365)
  • /ship's test step no longer fails with E2BIG: argument list too long before any test runs on Linux in projects with thousands of unit test files; the files are split across several runner processes and counted as one run. (#4426)
  • /ship's remote test command no longer puts every selected test file on one command line, which Linux refuses past 128 KiB. (#4429)
  • /autoplan's approval page sends a plan back for review when both reviewers challenge it and disagree on whether it is a scope or an order change, asks a plan with no ### Owner's words section to confirm its direction in that case too, and checks an owner quote only against this repository's approvals record. (#4441)
  • /ship accepts a documentation fix when the check named the file with a line number, such as notes.md:8 or notes.md:8:12. (#4437)
  • Ubicloud runs started together can no longer go past the project's vCPU limit, a new ubi-runner.sh room command says how many more VMs fit, and two owners whose ids share a prefix no longer delete each other's expired VMs. (#4430)
  • The daily stable release no longer stalls when gstack's nightly Windows test run fails or doesn't finish. (#4400)
  • The nightly Windows test run finishes within its time limit again, split across eight shards with up-to-date timings. (#4409)
  • The Windows setup test now runs when a pull request changes only bin/gstack-lock.sh. (#4433)
  • The /review test-coverage evaluation no longer fails a run that read the source file when zsh stops at an unquoted echo ====. (#4364)
  • Sixteen documentation links in docs/skills.md and docs/review-policy.md reach their section again. Contributed by @Davmunrey. (#4394)
  • The README links the two new guides, and the install and uninstall docs count and name setup's hooks correctly. (#4403)
  • docs/releases.md says the stable release treats a failed commit status as red and a pending one as still running. (#4436)

Changes

  • Pull requests opened by /ship show at most three plain lines before collapsed sections, and every merge with gstack-ship-queue land lands as one commit titled with the PR title. A repository's .gstack/plain-titles.json can now set body_since (older PRs only get warnings) and extend or replace gstack's default list of in-house words. See docs/writing-prs.md. (#4438)
  • /ship counts review rounds per pull request instead of per run, so a PR shipped several times still gets at most two review rounds, and the version that merges always gets a full review. (#4360)
  • /autoplan's approval page shows a reviewer's challenge to a plan's scope, order, direction, cost or packaging as a choice for the owner, recommending the reviewer's change, instead of defaulting to "keep your direction". Plans can quote their owner under ### Owner's words, and app plans can open with a ### Day one table. (#4431)
  • Claude Code's skill list now says when to use each gstack skill, so requests like "review my changes" load /review. The list grows by about 840 tokens per session. (#4387)
  • /ship's test step prints PREGATE: time limit hit when it runs out of time, and --step-timeout <seconds> sets its budget (default one hour). (#4429)
  • Every skill now tells the agent to ask a question once and to open and clean up every file before handing it over. (#4383)
  • Every skill now tells the agent never to print a whole environment, git config or process listing, and to wait on CI with one gstack-pr-wait call instead of a polling loop. (#4382)
  • gstack agents open each status report with three lines, Failed or skipped:, Unverified: and Also changed:, and keep the report under 250 words. (#4273)
  • /captain's docs name the Failed or skipped: and Also changed: lines and say a missing one is asked for in a follow-up, never a reason to reject the report. (#4432)
  • /eval-plan checks four things it used to leave to judgment: a preregistration's decisions and scoring sections, the judge's agreement with hand labels, and three common ways a result can mislead. (#4384)
  • gstack-runaway reports what a thread's cold and empty wakes cost, not only how many there were, and scan --wakes lists each wake. (#4385)
  • The ship policy guide explains how to merge any pull request with gstack-ship-queue land, including in a repository with one maintainer, with a pinned gh pr merge fallback. (#4377)
  • Two new guides: landing a fix in someone else's repository, and running a playtest with real people. (#4380)
  • ETHOS.md ends its "Explain the Number" section with a three-item checklist for write-ups. (#4381)
  • docs/ship-policy.md documents the .gstack/approval-classes.json schema, the gstack-approval-classes commands and how to cite an owner's approval. (#4355)

Removals

  • The optional Stop hook no longer checks that a test ran after the last edit; /verify asks for that in plain words instead. With /verify loaded, Claude Opus 5.5 and GPT-6.1 Sol already did it in 96% and 89% of runs, and the check moved results by -0.5 to +2 points, inside the noise. (#4428)
