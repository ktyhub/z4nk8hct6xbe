gstack v1.101.0.0

#gstack v1.101.0.0

gstack v1.101.0.0

Quoi de neuf

  • Avant qu'il ne vous soit demandé d'essayer une version d'application, la nouvelle commande gstack-first-use fait appel à un agent d'une autre famille de modèles qui s'appuie sur le même type d'appareil et vérifie les cinq premières choses que vous ferez avec. (#4465)
  • Avant qu'un agent pose une question à son propriétaire, gstack-owner-answers peut vérifier le brouillon par rapport aux réponses précédentes du propriétaire et suggérer de supprimer uniquement les lignes qu'un oui permanent existant couvre déjà. (#4467)
  • GitHub Les release note répertorient désormais chaque changement en termes simples, avec un lien vers sa pull request. (#4390)
  • Lorsqu'un autre agent conduit/expédie pas à pas, chaque phase s'exécute désormais comme une seule commande, les appels sont comptés et la course s'arrête après 100 minutes. (#4451)
  • L'étape de poussée de /ship se termine désormais toujours par une ligne PUSH: indiquant s'il a poussé ; si un script correspond aux anciennes lignes PUSH:, mettez-le à jour. (#4474)
  • Le plan de révision de /ship envoie désormais le code Swift qui demande des autorisations de confidentialité ou touche la santé, le calendrier, les contacts ou les fichiers sur l'appareil au panneau de révision complet. (#4472)
  • gstack-autoplan revise --plan avec un fichier différent indique désormais que l'exécution suit ce fichier. (#4470)
  • /office-hours explique pourquoi il recommande un mode, en citant vos propres mots. (#4450)
  • /office-hours conserve ses 34 vidéos et essais de fondateurs hors du fichier de compétences, la compétence est donc plus petite d'environ 8.6 Ko. (#4463) - Unattended /autoplan exécute désormais la révision du deuxième modèle que vous avez activée et l'attend au lieu de mettre fin à la session. (#4459)

Sécurité

  • Le fichier, la ligne et la raison d'un résultat de sécurité n'apparaissent plus dans la description d'une pull request ; il affiche un identifiant opaque et les détails restent dans le dossier d'approbation privé. (#4486)
  • La vérification des secrets détecte désormais un secret construit à partir de morceaux courts avec + ou écrit dans un commentaire, et arrête de signaler trois types de code ordinaire. (#4457)

Correctifs

  • /ship avec un token cap sur Claude Code ne s'arrête plus à son premier transfert : la nouvelle session reçoit désormais son invite. Merci @exGeni. (#4452)
  • Sur Claude Code, l'invite de cette session de transfert commence désormais par la commande saisie /ship, donc la compétence se charge réellement. (#4487)
  • /ship ne s'arrête plus pour la signature d'un propriétaire lors de la fusion de la base, seul le texte côté base est modifié. (#4458)
  • La prose de confirmation d'un critique ne devient plus une conclusion critique que seul un propriétaire peut effacer. (#4458)
  • Lorsque /ship s'arrête à sa limite de révision et que le propriétaire autorise un tour supplémentaire, ce tour paie désormais pour la correction des résultats au lieu d'une autre révision en lecture seule. (#4479)
  • /ship sur Codex ne s'arrête plus à l'audit de couverture des tests : les compétences Codex démarrent désormais leurs sous-agents d'audit et de révision avec les propres outils du Codex (activez multi_agent = true sous [features] dans ~/.codex/config.toml). (#4489)
  • /ship ne signale plus aucun bloqueur lorsque l'examen du deuxième modèle en a trouvé un, et ne se terminera pas tant que ce bloqueur est ouvert. (#4485)
  • Lorsque /ship publie une description de pull request, le décompte des cycles de révision précédents provient désormais toujours de l'historique réel du PR ; une description contenant des blocs d'historique supplémentaires pourrait faire compter un tour à Gstack là où il y en avait trois. (#4440)
  • gstack-post ne signale plus les identifiants d'exécution et les identifiants de validation de /ship en tant que numéros de téléphone, donc la publication d'une description de demande d'extraction /ship ne nécessite plus de confirmation. (#4488)
  • Le plan de révision de /ship trie désormais les fichiers Swift et Xcode par risque au lieu d'envoyer chaque demande d'extraction iOS au panneau de révision complet. (#4469)
  • La sélection de tests pré-push de /ship trouve désormais les tests d'une application monorepo qui importe via son propre alias @/. Merci @dtoelke. (#4464)
  • Un test, ou un référentiel scratch dans le répertoire temporaire, ne peut plus écrire de lignes d'approbation dans votre véritable Capy Drive. (#4466)
  • le routeur de gstack ne donne plus de règle spéciale aux rapports de bugs, donc le modèle corrige un bug comme il le ferait sans gstack ; sur Claude Code, un rapport de bug ne charge également plus le routeur. (#4442)
  • Une exécution /autoplan sans surveillance sur Claude Code ne signale plus sa garde de phase comme étant désactivée alors qu'elle est activée, et un rapport de phase écrit uniquement en raisonnement obtient désormais un refus qui nomme le correctif. (#4481)
  • gstack-autoplan revise ne refuse plus un plan que le premier next avait accepté. (#4470)
  • Une révision de plan du deuxième modèle dans /autoplan n'est plus signalée comme indisponible lors de son exécution réelle. (#4471)
  • Unattended /autoplan enregistre désormais la réponse relayée du propriétaire à sa dernière question au lieu de la refuser. (#4484)
  • Deux exécutions /autoplan démarrées dans la même seconde ne partagent plus un identifiant d'exécution. (#4459)
  • Deux exécutions gstack-owner-answers add pour la même réponse n'entrent plus en collision. (#4490)
  • skill_prefix=true survit désormais aux mises à jour lorsque gbrain est installé. Merci @fliaron. (#4454)
  • Les documents OpenClaw ne vous envoient plus vers ClawHub, qui n'a actuellement aucune compétence Gstack ; ils pointent vers ./setup --host openclaw. Merci @exGeni. (#4454)
  • gstack-issue-links ne lit plus les problèmes des autres référentiels comme ceux de Gstack. (#4454)
  • /sync-gbrain ne dit plus OK lorsque l'importation de pages ou l'envoi d'artefacts échoue, et qu'un chemin d'attente mal formé n'arrête plus la synchronisation des artefacts pour chaque projet. (#4455)
  • La préparation d'une extraction pour une exécution Ubicloud n'échoue plus lorsque git réécrit une référence à côté. (#4447)
  • Avec un fournisseur Codex personnalisé, le contrôle de préparation au Codex et la révision du deuxième modèle sélectionnent désormais le même modèle : le model du fournisseur dans ~/.codex/config.toml ne compte que lorsqu'il s'agit du modèle du niveau de révision (gpt-6-astra pour le niveau frontière), et tous deux refusent tout autre nom pour la même raison. Sur le fournisseur OpenAI d'origine, la révision du deuxième modèle dans /autoplan et /spec utilise désormais le modèle du niveau de révision au lieu de celui de config.toml. (#4491)
  • gstack-artifact validate et ack refusent désormais un /autoplan run.json que gstack-autoplan n'a pas écrit, ou dont le journal, les résultats de révision ou le point de contrôle ne sont pas d'accord avec lui. (#4494)

Modifications pour les responsables

  • Une exécution de CI qui a réussi seulement après la réexécution de ses tâches ayant échoué est désormais marquée comme telle partout où gstack la réutilise. (#4473)
  • /ship réutilise le test réussi de CI lors de la fusion de la base qui n'a modifié aucun fichier et s'arrête au lieu de démarrer tranquillement des tests locaux d'une heure ou de réviser un diff vide. (#4461)
  • Un plan préenregistré pour tester/expédier sans son sous-agent de coordination distinct. (#4456)
  • Ce plan permet désormais de résoudre manuellement les cas de retour en conflit avec le code ultérieur. (#4460)
  • CI télécharge les résultats des tests de la suite gratuite sur Trunk avec le téléchargeur d'analyse v2.1.8 et l'analyseur cli 0.17.0. (#4453)
  • Un test de politique n'échoue plus une fois que la propre version de gstack atteint la version mineure après la clé de politique la plus récente. (#4495)
  • L'évaluation /plan-ceo-review HOLD SCOPE n'échoue plus à une révision car sa question de suivi ne répétait pas le nom du mode. (#4447) Comparez v1.100.0.0...v1.101.0.0 · changelog complet

gstack v1.101.0.0

gstack v1.101.0.0

What's new

  • Before you're asked to try an app build, the new gstack-first-use command has an agent from another model family play that build on the same kind of device and check the first five things you'll do with it. (#4465)
  • Before an agent asks its owner a question, gstack-owner-answers can check the draft against the owner's earlier answers and suggest dropping only the lines an existing standing yes already covers. (#4467)
  • GitHub release notes now list every change in plain words, with a link to its pull request. (#4390)
  • When another agent drives /ship step by step, each phase now runs as one command, the calls are counted, and the run stops itself after 100 minutes. (#4451)
  • /ship's push step now always ends with one PUSH: line that says whether it pushed; if a script matched the old PUSH: lines, update it. (#4474)
  • /ship's review plan now sends Swift code that asks for privacy permissions or touches health, calendar, contacts or on-device files to the full review panel. (#4472)
  • gstack-autoplan revise --plan with a different file now says the run follows that file. (#4470)
  • /office-hours explains why it recommends a mode, quoting your own words. (#4450)
  • /office-hours keeps its 34 founder videos and essays out of the skill file, so the skill is about 8.6 KB smaller. (#4463)
  • Unattended /autoplan now runs the second-model review you turned on, and waits for it instead of ending the session. (#4459)

Security

  • A security finding's file, line and reason no longer appear in a pull request description; it shows an opaque id and the details stay in the private approval record. (#4486)
  • The secrets check now catches a secret built from short pieces with + or written in a comment, and stops flagging three kinds of ordinary code. (#4457)

Fixes

  • /ship with a token cap on Claude Code no longer stops at its first handoff: the new session now receives its prompt. Thanks @exGeni. (#4452)
  • On Claude Code, that handoff session's prompt now starts with the typed /ship command, so the skill actually loads. (#4487)
  • /ship no longer stops for an owner's sign-off when merging the base only changed base-side text. (#4458)
  • A reviewer's confirming prose no longer becomes a Critical finding that only an owner can clear. (#4458)
  • When /ship stops at its review-round limit and the owner allows one more round, that round now pays for fixing the findings instead of another read-only review. (#4479)
  • /ship on Codex no longer stops at the test coverage audit: Codex skills now start their audit and reviewer subagents with Codex's own tools (turn on multi_agent = true under [features] in ~/.codex/config.toml). (#4489)
  • /ship no longer reports zero blockers when the second-model review found one, and won't finish while that blocker is open. (#4485)
  • When /ship posts a pull request description, the count of earlier review rounds now always comes from the PR's real history; a description carrying extra history blocks could make gstack count one round where there were three. (#4440)
  • gstack-post no longer flags /ship's own run ids and commit ids as phone numbers, so posting a /ship pull request description no longer needs a confirm. (#4488)
  • /ship's review plan now sorts Swift and Xcode files by risk instead of sending every iOS pull request to the full review panel. (#4469)
  • /ship's pre-push test selection now finds the tests of a monorepo app that imports through its own @/ alias. Thanks @dtoelke. (#4464)
  • A test, or a scratch repository in the temp directory, can no longer write approval rows into your real Capy Drive. (#4466)
  • gstack's router no longer gives bug reports a special rule, so the model fixes a bug the way it would without gstack; on Claude Code, a bug report also no longer loads the router. (#4442)
  • An unattended /autoplan run on Claude Code no longer reports its phase guard as off while it is on, and a phase report written only in reasoning now gets a denial that names the fix. (#4481)
  • gstack-autoplan revise no longer refuses a plan that the first next accepted. (#4470)
  • A second-model plan review in /autoplan is no longer reported as unavailable when it actually ran. (#4471)
  • Unattended /autoplan now records the owner's relayed answer to its final question instead of refusing it. (#4484)
  • Two /autoplan runs started in the same second no longer share a run id. (#4459)
  • Two gstack-owner-answers add runs for the same answer no longer collide. (#4490)
  • skill_prefix=true now survives updates when gbrain is installed. Thanks @fliaron. (#4454)
  • The OpenClaw docs no longer send you to ClawHub, which has no current gstack skills; they point to ./setup --host openclaw. Thanks @exGeni. (#4454)
  • gstack-issue-links no longer reads other repositories' issues as gstack's. (#4454)
  • /sync-gbrain no longer says OK when pages failed to import or an artifacts push failed, and one malformed queued path no longer stops artifacts sync for every project. (#4455)
  • Packing a checkout for a Ubicloud run no longer fails when git is rewriting a ref beside it. (#4447)
  • With a custom Codex provider, the Codex readiness check and the second-model review now pick the same model: the provider's model in ~/.codex/config.toml counts only when it is the review tier's model (gpt-6-astra for the frontier tier), and both refuse any other name with the same reason. On the stock OpenAI provider, the second-model review in /autoplan and /spec now uses the review tier's model instead of config.toml's. (#4491)
  • gstack-artifact validate and ack now refuse an /autoplan run.json that gstack-autoplan didn't write, or whose journal, review outputs or checkpoint disagree with it. (#4494)

Changes for maintainers

  • A CI run that passed only after its failed jobs were re-run is now marked as such wherever gstack reuses it. (#4473)
  • /ship reuses CI's passing test run when merging the base changed no file, and stops instead of quietly starting hour-long local test runs or reviewing an empty diff. (#4461)
  • A preregistered plan for testing /ship without its separate coordinating subagent. (#4456)
  • That plan now lets case reverts that conflict with later code be resolved by hand. (#4460)
  • CI uploads free-suite test results to Trunk with analytics-uploader v2.1.8 and analytics-cli 0.17.0. (#4453)
  • A policy-floor test no longer fails once gstack's own version reaches the minor release after the newest policy key. (#4495)
  • The /plan-ceo-review HOLD SCOPE eval no longer fails a review because its follow-up question didn't repeat the mode name. (#4447)
