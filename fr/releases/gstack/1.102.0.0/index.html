gstack v1.102.0.0

#gstack v1.102.0.0 gstack 1.102.0.0 fait du Codex un hôte de première classe : il obtient désormais les suggestions de compétences de gstack, la vérification des commandes destructives et la liste de contrôle de /review. Le test de commandement destructeur a été repensé pour demander beaucoup moins souvent tout en captant beaucoup plus de dégâts réels. Vérification des commandes destructives (/attention)

  • Il ne demande plus de supprimer les fichiers de travail (dossiers /tmp, mktemp, caches, sortie de build), et il demande désormais avant les suppressions en dehors de votre projet, en jetant le travail non validé, les réécritures de l'historique, les suppressions de branches distantes, les réinitialisations de bases de données et les suppressions de cloud. Une suppression récursive de / ou de votre dossier personnel, une poussée forcée vers la branche par défaut et l'effacement d'un disque entier sont bloqués quelle que soit leur écriture. Sur une rediffusion de 254 322 commandes d'agents réels, les demandes inoffensives sont passées de 1.40% des commandes à 0.33%, et les commandes destructrices interceptées sont passées de 443 à 930 sur 948. (#4513)
  • Il lit les commandes plus attentivement : git push --repo=origin +main, les poussées forcées après un cd ou avec --all/--mirror, les git clean -q silencieux, find -L … -delete et wipefs -a dans chaque orthographe sont capturés ; Les essais à sec git push -nf et les greps pour le texte SQL ne demandent plus. Sur la même rediffusion, cela n'attrape pas moins de commandes destructrices, et ajoute 141 demandes inoffensives (0.39 % des commandes au total) ; un suivi est en cours sur ceux-ci. (#4525)
  • Les programmes de l'agent SDK reçoivent un avertissement au lieu d'une demande, car le SDK refuse une demande et personne ne répond. Réglez GSTACK_SESSION_KIND=interactive pour conserver la demande. (#4513) Codex
  • ./setup --host codex (Codex 0.170+) ajoute des crochets qui suggèrent la bonne compétence gstack pour une invite et exécutent la vérification des commandes destructives avant chaque commande shell. Le Codex ne peut pas poser de questions sur une seule commande, donc une commande à risque est bloquée dans les sessions interactives et avertie sous codex exec. Trust les hooks lorsque le Codex le demande au démarrage. (#4512)
  • /review sur Codex a lieu une seule fois s'il tente de terminer sans sa passe ni son rapport contradictoire, comme sur Claude Code. (#4522) Il compte un sous-agent Sol démarré avec task_name lors de ce passage. (#4526)
  • Les hooks Codex fonctionnent lorsque le chemin de votre dossier Codex contient des caractères shell, la désinstallation conserve vos propres hooks trusted, la configuration correspond plus étroitement au schéma de hook du Codex et la liste de contrôle de /review lit ; et échoue correctement. (#4528)
  • Les suggestions de compétences, les invites de sélection et les documents nomment les compétences de la manière dont le Codex les répertorie ($review, pas $gstack-review). (#4523, #4524)
  • les heures de bureau, la révision de la conception des plans et la mise à niveau de gstack se chargent à nouveau sur le Codex, une compétence sous codex exec sait qu'elle est sans surveillance, et les réviseurs du Codex commencent avec un contexte propre. (#4510) Crochets et routage
  • Les hooks d'assistance sont activés par défaut, la vérification des commandes destructives s'exécute comme un hook et le routage des invites se déclenche sur les longs rapports de bogues. Grâce aux compétences de Gstack, le hook de routage achemine 14 des 60 rapports de bogues réels (au lieu de 17) ; les documents correspondent maintenant. (#4503, #4505)
  • Le hook de routage suggère désormais également les compétences que vous avez installées vous-même et arrête d'envoyer des rapports de bogues à /qa. Avec les compétences installées, il achemine 40 des 60 rapports de bogues réels. (#4506) /expédition, révision et CI
  • Sur Capy, /ship ne modifie ni ne commente plus les pull request sous votre compte GitHub ; il transmet le texte au propre outil de relations publiques de Capy. (#4518)
  • Une commande dont la sortie a été coupée échoue désormais au lieu d'être jugée sur une partie de sa sortie. Cela comble une lacune où un push dont la différence dépassait 64 Mio pourrait transporter un identifiant au-delà du crochet de pré-push. (#4492, #4502)
  • Un échec de révision du deuxième modèle nomme la cause qui l'a arrêté, enregistre un 402 comme un arrêt budgétaire et ne supprime jamais sa propre invite. (#4515, #4519)
  • Lorsqu'un correctif touche une vérification de fusion, le deuxième cycle de révision l'examine désormais au lieu d'effectuer un rapport. (#4520)
  • La politique d'expédition peut marquer les données publiées comme contenu afin que /ship puisse examiner les PR de données volumineuses, et un tel dossier ne peut pas masquer le code source ou les fichiers d'agent lors de l'examen. (#4511, #4516)
  • La révision de /ship fonctionne lorsque la caisse à expédier n'est pas la caisse par défaut du projet. (#4507)
  • La vérification de la machine d'état de /ship accepte les lignes d'en-tête écrites par son lecteur. (#4504)
  • La vérification des numéros modifiés arrête de signaler les tests qui partagent uniquement un mot comme limit. Merci @dtoelke. (#4496)
  • Les PR qui ont fusionné une version réutilisent leur test antérieur lorsque la version n'a régénéré qu'un fichier déclaré. (#4483)
  • Lorsque Claude Code exécute /verify avant une validation, il obtient une vérification rapide au lieu de la boucle de correctif complète (#4508), et cette vérification échoue proprement après un délai d'attente. (#4527)
  • Le collecteur d'avis ne supprime plus un véritable P0 écrit sous forme de puce récapitulative et arrête de lire les listes de portée des réviseurs en tant que résultats. (#4527)
  • gstack-ship-queue ready remplit désormais ses fusions d'essai avec d'autres PR ouverts et quel deuxième modèle a vérifié l'enregistrement de décision, ainsi que six petites corrections d'outils /ship, y compris l'enregistrement d'une décision relayée par un autre agent. (#4529)
  • Les exécutions de tests dont les travailleurs démarrent dans leur propre session ne sont plus interrompues car bloquées. Merci @dtoelke. (#4533)
  • Free-suite CI survit à un miroir Ubuntu lent, et quatre tests et vérifications d'évaluation instables ont été corrigés. (#4530) Grain
  • La vérification de lecture de /sync-gbrain fonctionne lorsque la première page dépasse 64 Ko. (#4497)
  • La synchronisation d'un deuxième dépôt ne demande plus au premier dépôt de se synchroniser à nouveau. Merci @SatriaSuriaAriffin. (#4532)

gstack v1.102.0.0

gstack 1.102.0.0 makes Codex a first-class host: it now gets gstack's skill suggestions, the destructive-command check and /review's checklist hold. The destructive-command check was rebuilt to ask far less often while catching far more real damage.

Destructive-command check (/careful)

  • It no longer asks about deleting scratch files (/tmp, mktemp folders, caches, build output), and it now asks before deletes outside your project, throwing away uncommitted work, history rewrites, remote branch deletes, database resets and cloud deletes. A recursive delete of / or your home folder, a force-push to the default branch, and wiping a whole disk are blocked however they're written. On a replay of 254,322 real agent commands, harmless asks fell from 1.40% of commands to 0.33%, and destructive commands caught rose from 443 to 930 of 948. (#4513)
  • It reads commands more carefully: git push --repo=origin +main, force-pushes after a cd or with --all/--mirror, quiet git clean -q, find -L … -delete, and wipefs -a in every spelling are caught; git push -nf dry runs and greps for SQL text no longer ask. On the same replay this catches no fewer destructive commands, and it adds 141 harmless asks (0.39% of commands in total); a follow-up is working on those. (#4525)
  • Agent SDK programs get a warning instead of an ask, because the SDK refuses an ask nobody answers. Set GSTACK_SESSION_KIND=interactive to keep the ask. (#4513)

Codex

  • ./setup --host codex (Codex 0.170+) adds hooks that suggest the right gstack skill for a prompt and run the destructive-command check before every shell command. Codex can't ask about a single command, so a risky one is blocked in interactive sessions and warned about under codex exec. Trust the hooks when Codex asks at startup. (#4512)
  • /review on Codex is held once if it tries to finish without its adversarial pass or report, as on Claude Code. (#4522) It counts a Sol subagent started with task_name as that pass. (#4526)
  • Codex hooks work when your Codex folder's path has shell characters, uninstall keeps your own hooks trusted, setup matches Codex's hook schema more closely, and /review's checklist reads quoted ; and failed reads correctly. (#4528)
  • Skill suggestions, picker prompts and docs name skills the way Codex lists them ($review, not $gstack-review). (#4523, #4524)
  • office-hours, plan-design-review and gstack-upgrade load again on Codex, a skill under codex exec knows it's unattended, and Codex reviewers start with a clean context. (#4510)

Hooks and routing

  • The helper hooks are on by default, the destructive-command check runs as a hook, and prompt routing fires on long bug reports. With gstack's own skills the routing hook routes 14 of 60 real bug reports (was 17); the docs now match. (#4503, #4505)
  • The routing hook now also suggests skills you've installed yourself, and stops sending bug reports to /qa. With installed skills it routes 40 of 60 real bug reports. (#4506)

/ship, review and CI

  • On Capy, /ship no longer edits or comments on pull requests under your GitHub account; it hands the text to Capy's own PR tool. (#4518)
  • A command whose output was cut off now fails instead of being judged on part of its output. This closes a gap where a push whose diff passed 64 MiB could carry a credential past the pre-push hook. (#4492, #4502)
  • A failed second-model review names the cause that stopped it, records a 402 as a budget stop, and never deletes its own prompt. (#4515, #4519)
  • When a fix touches a merge check, the second review round now reviews it instead of reporting done. (#4520)
  • Ship policy can mark published data as content so /ship can review large data PRs, and such a folder can't hide source code or agent files from review. (#4511, #4516)
  • /ship's review works when the checkout being shipped isn't the project's default checkout. (#4507)
  • /ship's state-machine check accepts the header lines its reader writes. (#4504)
  • The changed-number check stops flagging tests that only share a word like limit. Thanks @dtoelke. (#4496)
  • PRs that merged a release reuse their earlier test run when the release only regenerated a declared file. (#4483)
  • When Claude Code runs /verify before a commit, it gets a quick check instead of the full fix loop (#4508), and that check fails cleanly on a timeout. (#4527)
  • The review collector no longer drops a real P0 written as a summary bullet, and stops reading reviewers' scope lists as findings. (#4527)
  • gstack-ship-queue ready now fills in its trial merges against other open PRs and which second model checked the decision record, plus six small /ship tool fixes, including recording a ruling relayed from another agent. (#4529)
  • Test runs whose workers start in their own session are no longer killed as stalled. Thanks @dtoelke. (#4533)
  • Free-suite CI survives a slow Ubuntu mirror, and four flaky tests and eval checks were fixed. (#4530)

GBrain

  • /sync-gbrain's read check works when the first page is over 64 KB. (#4497)
  • Syncing a second repo no longer makes the first repo ask you to sync again. Thanks @SatriaSuriaAriffin. (#4532)
