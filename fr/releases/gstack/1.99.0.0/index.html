#gstack v1.99.0.0

gstack v1.99.0.0

Une version importante : une boucle de conception au moment de la construction pour le travail de l'interface utilisateur, de nombreux correctifs /ship et /autoplan et des vérifications secrètes plus strictes avant que quoi que ce soit ne soit poussé.

Quoi de neuf

  • /design-review --build <preview url> est une nouvelle boucle d'adhésion pour l'interface utilisateur que vous êtes encore en train de créer : elle répertorie les états que votre modification peut afficher, vérifie chacun d'entre eux sur la largeur du bureau et du téléphone avec des captures d'écran, et corrige les problèmes d'espacement et de cible tactile pendant trois tours maximum sans rien commettre #4142.
  • Le design lint de gstack peut désormais vérifier une section de l'écran d'une application en cours d'exécution pour détecter les lignes encombrées, le texte d'aide exigu, les notes aussi fortes que les noms et les petites cibles tactiles [#4138] (https://github.com/garrytan/gstack/pull/4138).
  • /ship écrit désormais les titres des demandes d'extraction, les messages de validation, les noms de branches et les entrées changelog avec des mots de tous les jours qui indiquent ce qui a changé pour quelqu'un utilisant le projet #4146.
  • Un référentiel peut répertorier ses propres dossiers réservés aux documents dans .gstack/ship-policy.json (docs_only), donc les modifications de prose y ignorent également le test complet dans /ship #4185.
  • /eval-plan demande maintenant une ligne lesson:, et les conseils de gstack indiquent que les rapports de résultats s'ouvrent avec deux ou trois points à retenir, ce qui fonctionne en premier #4173.
  • Les documents /autoplan et le texte d'aide indiquent désormais ce qu'une exécution rapide et une exécution entièrement interactive donnent réellement à leurs réviseurs #4186.

Correctifs

  • L'étape d'approbation finale de /autoplan s'affiche à nouveau et les réponses à son élément d'approbation du plan sont acceptées (merci @exGeni pour le rapport, et @ElNeMeR70 et @szsunyuan pour les correctifs proposés) #4219.
  • Les réponses rec et all de /autoplan appliquent désormais tous les changements de plan recommandés, et rec est le mot par défaut [#4225] (https://github.com/garrytan/gstack/pull/4225).
  • /autoplan ne reste plus bloqué entre les phases après que Claude Code 2.1.317 compacte une longue session (rapporté et corrigé par @vilano93) #4226.
  • /autoplan ne s'arrête plus après une phase lorsque Claude Code sauvegarde son rapport de phase sous la forme d'un résumé commençant par une autre phrase (merci @mstormo d'avoir trouvé la cause) #4171.
  • La porte opt-in /autoplan fait désormais que chaque phase publie son résultat juste après son propre rapport, dans l'ordre #4135.
  • Le navigateur de gstack affiche désormais un correctif clair lorsqu'un hôte Linux bloque le bac à sable de Chromium (stock Ubuntu 23.10+ ou Docker non root), au lieu d'un mur de journal Playwright #4162.
  • Les erreurs de navigateur manquant n'indiquent plus aux utilisateurs Linux et Windows d'ouvrir l'application Aside réservée à macOS #4131.
  • browse scroll <selector> fait défiler à nouveau jusqu'à l'élément au lieu de descendre vers le bas de la page #4192.
  • Le moteur de rendu de gstack ne confond plus le /usr/bin/browse de Debian et Ubuntu (un lien vers xdg-open) pour son propre navigateur #4192.
  • Sur les installations Codex, repo-local et autres sans ~/.claude, les compétences de site enregistrées du navigateur restent désormais avec le projet dans lequel elles ont été enregistrées au lieu d'apparaître dans chaque projet #4192.
  • Une préférence de question « Ne jamais poser » s'applique désormais lorsque le marqueur de la question est écrit en capitals ou comporte un indice mal formé #4192.
  • Deux démarrages rapides de tunnel dans le démon de navigation, ou un lors du propre démarrage du démon, ne laissent plus ouvert un deuxième tunnel ngrok public que vous ne pouvez pas fermer #4210 #4212.
  • ./setup ne refuse plus les hooks sains lorsque Bun plante en les vérifiant #4167.
  • gstack-uninstall ne supprime plus les fichiers .gstack/ validés de votre dépôt ou le travail non enregistré dans .gstack-worktrees/ #4241.
  • Les captures QA sur macOS n'enregistrent plus une commande terminée comme incomplète (merci @vilano93 pour le rapport et les mesures) #4170.
  • Lorsque deux machines enregistrent chacune une décision entre les poussées de synchronisation cérébrale, la synchronisation reconstruit désormais la liste de décisions fusionnée au lieu d'échouer à chaque poussée ultérieure [#4220] (https://github.com/garrytan/gstack/pull/4220).
  • La vérification secrète et le hook de pré-push lisent désormais les fichiers que git traite comme binaires (un octet NUL, un texte UTF-16 ou un attribut -diff), donc un jeton caché dans l'un d'eux n'est plus poussé #4243.
  • Les apprentissages, les événements de la chronologie et la synchronisation cérébrale ne stockent ni n'envoient plus de clés live Stripe, de jetons Slack, de jetons npm ou d'URL de base de données avec un mot de passe [#4247] (https://github.com/garrytan/gstack/pull/4247).
  • La vérification des secrets avant fusion n'échoue plus le code qui lit une variable d'environnement, telle que opts.env.API_TOKEN ou import.meta.env.X #4157.
  • La vérification des secrets avant fusion n'arrête plus /ship sur le session = self.client.session de Django (rapporté par @dgrant) #4228.
  • La vérification pré-push ne marque plus les vrais fichiers dont les noms commencent simplement par tmp ou scratch #4177.
  • Moins de fausses données de confidentialité lorsque /ship publie une description PR : les numéros d'exécution CI et les numéros similaires écrits automatiquement ne se lisent plus comme des numéros de téléphone [#4198] (https://github.com/garrytan/gstack/pull/4198).
  • /ship ne s'arrête plus lorsque ses documents vérifient les réponses avec une petite erreur de formatage, et une réponse qui n'a qu'une mauvaise forme est réparée une fois au lieu d'utiliser la nouvelle tentative #4147 #4205.
  • L'évaluation du deuxième modèle de /ship n'est plus aussi claire lorsqu'elle mentionne un problème, et une évaluation propre qui se termine par une phrase sur ses vérifications n'est plus signalée comme manquante #4130 #4136 #4140.
  • /ship ne s'arrête plus sur une réponse propre du critique qui ne mentionne qu'un mot de gravité en passant, ou sur un résultat faible écrit sous forme d'élément numéroté avec une liste imbriquée #4218 #4237.
  • /ship n'ouvre plus les problèmes GitHub pour examiner les résultats dans le code, le PR n'a pas changé ; ils restent répertoriés dans la description du PR #4208.
  • /ship ne cale plus sur une branche qui a fusionné dans des milliers de fichiers de données, et les PR de gros résultats rentrent désormais dans sa limite de taille de révision #4149 #4184.
  • /ship ne demande plus de révision financière des fichiers exclus par votre politique de révision, et ne conserve plus un fichier de résultats en révision car une réponse de modèle contient "fit (" #4159 #4195.
  • /ship n'exécute plus deux fois les mêmes tests locaux restants lorsque les résultats du CI sont réutilisés lors du même commit #4127.

Modifications pour les responsables

  • Les propres demandes d'extraction de gstack qui modifient uniquement les documents destinés aux humains ignorent désormais les suites de tests et exécutent une vérification des documents à la place #4178.
  • Corrections des outils de fusion : la file d'attente de fusion n'appelle plus une tête verte lorsqu'une vérification a échoué, n'obtient plus les validations parents non révisées d'un PR empilé, lit ses notes dans un processus git et accepte les réexécutions de CI #4235 #4229 #4242 #4246.
  • Corrections des outils de révision : une révision de suivi propre ultérieure compte après qu'une précédente a trouvé un bloqueur, une fusion de base qui déplace uniquement les lignes autour d'une modification révisée ne force plus une autre révision complète, et les fichiers de données avec des noms entre guillemets conservent leur révision de ligne secrète #4188 #4259 #4203.
  • Correctifs d'enregistrement de planification : la vérification du plan fonctionne sur les dépôts publics, chaque hachage d'approbation /autoplan nomme sa propre exécution, un agent ne peut plus régler une question /autoplan réservée au propriétaire et la table d'approbations maintient les chemins locaux en dehors des descriptions PR #4133 #4137 #4201 #4199.
  • Documents et outils de workflow agent-thread : les threads conservent leur PR jusqu'à la fin, restent silencieux entre les mises à jour, ne peuvent pas être archivés tout en détenant un PR ouvert, et les PR externes sont traités comme des rapports de bogues ; Outils réservés à Capy déplacés dans leur propre dossier et installés uniquement sur les machines Capy #4224 #4145 #4143.
  • Une note de conception mesure ce qu'une vérification plus légère des demandes d'extraction de threads d'agent uniquement permettrait d'économiser #4144.
  • La vérification "Titre brut" est désormais requise avant la fusion d'une pull request, et gère les descriptions très longues #4152.
  • CI : Trunk surveille désormais davantage de tâches de demande d'extraction et reçoit les résultats de la suite gratuite uniquement pour la détection des tests irréguliers, la suite gratuite reste sous sa limite de temps de tâche lorsque ses données de synchronisation deviennent obsolètes, et les dépendances et les actions CI ont reçu des correctifs #4148 #4187 #4245 #4202.
  • Les réussites quotidiennes irrégulières ont corrigé les tests et les contrôles d'évaluation qui ont mal interprété le travail correct ou ont couru leurs propres appareils #4128 #4132 #4167 #4223. Mise à niveau : si vous utilisez les compétences de site enregistrées dans le navigateur sur une installation sans ~/.claude, les compétences enregistrées avant cette version restent dans ~/.gstack/projects/unknown/learnings.jsonl ; copiez les lignes souhaitées dans le learnings.jsonl de ce projet. gstack v1.99.0.0

gstack v1.99.0.0

A large release: a build-time design loop for UI work, many /ship and /autoplan fixes, and stronger secret checks before anything is pushed.

What's new

  • /design-review --build <preview url> is a new opt-in loop for UI you are still building: it lists the states your change can show, checks each one at desktop and phone widths with screenshots, and fixes spacing and tap-target problems for up to three rounds without committing anything #4142.
  • gstack's design lint can now check one section of a running app screen for crowded rows, cramped help text, notes as loud as names, and small tap targets #4138.
  • /ship now writes pull request titles, commit messages, branch names and changelog entries in everyday words that say what changed for someone using the project #4146.
  • A repository can list its own docs-only folders in .gstack/ship-policy.json (docs_only), so prose changes there skip the full test run in /ship too #4185.
  • /eval-plan now asks for a lesson: line, and gstack's guidance says results write-ups open with two or three plain takeaways, what works first #4173.
  • The /autoplan docs and help text now say what a quick run and a full interactive run actually give their reviewers #4186.

Fixes

  • /autoplan's final approval step renders again, and replies to its plan-approval item are accepted (thanks @exGeni for the report, and @ElNeMeR70 and @szsunyuan for proposed fixes) #4219.
  • /autoplan's rec and all replies now apply every recommended plan change, and rec is the one-word default #4225.
  • /autoplan no longer gets stuck between phases after Claude Code 2.1.317 compacts a long session (reported and fixed by @vilano93) #4226.
  • /autoplan no longer stops after a phase when Claude Code saves its phase report as a summary that starts with another sentence (thanks @mstormo for finding the cause) #4171.
  • The opt-in /autoplan gate now makes each phase publish its result right after its own report, in order #4135.
  • gstack's browser now prints a clear fix when a Linux host blocks Chromium's sandbox (stock Ubuntu 23.10+ or non-root Docker), instead of a wall of Playwright log #4162.
  • Missing-browser errors no longer tell Linux and Windows users to open the macOS-only Aside app #4131.
  • browse scroll <selector> scrolls to the element again instead of to the page bottom #4192.
  • gstack's renderer no longer mistakes Debian and Ubuntu's /usr/bin/browse (a link to xdg-open) for its own browser #4192.
  • On Codex, repo-local and other installs without ~/.claude, the browser's saved site skills now stay with the project they were saved in instead of showing up in every project #4192.
  • A "never ask" question preference now still applies when the question's marker is written in capitals or carries a malformed hint #4192.
  • Two quick tunnel starts in the browse daemon, or one during the daemon's own startup, no longer leave a second public ngrok tunnel open that you can't close #4210 #4212.
  • ./setup no longer refuses healthy hooks when Bun crashes while checking them #4167.
  • gstack-uninstall no longer deletes your repo's committed .gstack/ files or unsaved work in .gstack-worktrees/ #4241.
  • QA captures on macOS no longer record a finished command as incomplete (thanks @vilano93 for the report and measurements) #4170.
  • When two machines each log a decision between brain-sync pushes, sync now rebuilds the merged decision list instead of failing on every later push #4220.
  • The secret check and pre-push hook now read files git treats as binary (a NUL byte, UTF-16 text, or a -diff attribute), so a token hidden in one no longer gets pushed #4243.
  • Learnings, timeline events and brain sync no longer store or push Stripe live keys, Slack tokens, npm tokens or database URLs with a password #4247.
  • The pre-merge secrets check no longer fails code that reads an environment variable, such as opts.env.API_TOKEN or import.meta.env.X #4157.
  • The pre-merge secrets check no longer stops /ship on Django's session = self.client.session (reported by @dgrant) #4228.
  • The pre-push check no longer flags real files whose names merely start with tmp or scratch #4177.
  • Fewer false privacy holds when /ship posts a PR description: CI run numbers and similar machine-written numbers no longer read as phone numbers #4198.
  • /ship no longer stops when its docs check replies with a small formatting mistake, and a reply that only has the wrong shape is repaired once instead of using up the retry #4147 #4205.
  • /ship's second-model review no longer passes as clean when it mentions a problem, and a clean review that signs off with a sentence about its checks is no longer reported as missing #4130 #4136 #4140.
  • /ship no longer stops on a clean reviewer reply that only mentions a severity word in passing, or on a Low finding written as a numbered item with a nested list #4218 #4237.
  • /ship no longer opens GitHub issues for review findings in code the PR didn't change; they stay listed in the PR description #4208.
  • /ship no longer stalls on a branch that merged in thousands of data files, and big results PRs now fit under its review size limit #4149 #4184.
  • /ship no longer asks for a money review of files your review policy leaves out, and no longer keeps a results file in review because a model reply contains "fit (" #4159 #4195.
  • /ship no longer runs the same leftover local tests twice when CI results are reused at the same commit #4127.

Changes for maintainers

  • gstack's own pull requests that change only human-facing docs now skip the test suites and run a docs check instead #4178.
  • Merge-tooling fixes: the merge queue no longer calls a head green while a check on it failed, no longer lands a stacked PR's unreviewed parent commits, reads its notes in one git process, and accepts rerun CI runs again #4235 #4229 #4242 #4246.
  • Review-tooling fixes: a later clean follow-up review counts after an earlier one found a blocker, a base merge that only shifts lines around a reviewed change no longer forces another full review, and data files with quoted names keep their secret-line review #4188 #4259 #4203.
  • Planning-record fixes: the plan check works on public repos, each /autoplan approval hash names its own run, an agent can no longer settle an owner-only /autoplan question, and the approvals table keeps local paths out of PR descriptions #4133 #4137 #4201 #4199.
  • Agent-thread workflow docs and tools: threads keep their PR to the end, stay quiet between updates, can't be archived while holding an open PR, and outside PRs are treated as bug reports; Capy-only tools moved into their own folder and install only on Capy machines #4240 #4176 #4244 #4251 #4250 #4204 #4213 #4224 #4145 #4143.
  • A design note measures what a lighter check for agent-thread-only pull requests would save #4144.
  • The "Plain title" check is now required before a pull request merges, and handles very long descriptions #4152.
  • CI: Trunk now watches more pull request jobs and receives free-suite results for flaky-test detection only, the free suite stays under its job time cap when its timing data goes stale, and dependencies and CI actions got patch bumps #4148 #4187 #4245 #4202.
  • Daily flaky passes fixed test and eval checks that misread correct work or raced their own fixtures #4128 #4132 #4167 #4223.

Upgrade: if you use the browser's saved site skills on an install without ~/.claude, skills saved before this release stay in ~/.gstack/projects/unknown/learnings.jsonl; copy the lines you want into that project's learnings.jsonl.
