#gstack v1.97.0.0

gstack v1.97.0.0

Principalement /ship, la commande de gstack qui examine, teste et ouvre une pull request pour vous : moins de cycles de révision supplémentaires inutiles, des audits qui suivent vos préférences de modèle, deux portes d'adhésion qui maintiennent /investigate et /plan-ceo-review à leur étape clé et un correctif de sécurité du navigateur.

Quoi de neuf

  • Une porte d'adhésion pour /plan-ceo-review empêche la session de se terminer jusqu'à ce que l'évaluation ait rédigé ses conclusions classées ; allumez-le avec ./setup --ceo-review-gate #4047.
  • Une porte d'adhésion pour /investigate bloque un correctif jusqu'à ce qu'une cause première soit écrite, y compris les correctifs effectués via les commandes shell ; allumez-le avec ./setup --investigate-gate #4045.
  • Si vous suivez le canal de mise à jour stable, les correctifs importants (sécurité, régressions, perte de données, bloqueurs) deviennent désormais stables en une journée, et stable n'a jamais plus d'une semaine de retard sur les modifications testées sur le [#4083] principal (https://github.com/garrytan/gstack/pull/4083).

Correctifs

  • Sécurité : le navigateur fourni par gstack utilise désormais Playwright 1.65.0 avec Chromium 158, qui ne trust ne correspond plus aux autorités de certification eMudhra compromises [#4087] (https://github.com/garrytan/gstack/pull/4087).
  • Le journal d'audit de navigation n'enregistre plus ce que vous tapez dans les pages, comme les mots de passe envoyés avec fill ou type, les réponses de dialogue et les valeurs de cookie ou d'en-tête. Rapporté par @derHaken #4073, #4081.
  • Le journal d'audit de navigation et le journal réseau ne conservent plus les valeurs de requête URL ni les informations d'identification, de sorte que les champs d'un formulaire de connexion soumis restent hors du disque #4082.
  • gstack-brain-sync n'appelle plus un push rejeté comme une erreur d'authentification simplement parce que l'URL de votre télécommande contient un mot comme auth ou 403, il réessaye donc le push comme il se doit #4035.
  • Le démon de navigation n'échoue plus avec le message « Le port… est-il utilisé ? » sur une machine occupée ; il choisit désormais son port juste avant de commencer à écouter #4035.
  • L'analyse secrète de gstack ne signale plus le code ordinaire tel que config.prod ou server.local(...) comme nom d'hôte interne divulgué, merci @nazarli-shabnam #4043.
  • Les documents de /ship, la couverture des tests et les audits de plans s'exécutent désormais sur le modèle que vous avez défini dans vos préférences au lieu de toujours sur Sonnet 5.5 #4038, #4042.
  • /ship ne demande plus un autre cycle de révision lorsque son propre audit de documents modifie des fichiers après la révision, même lorsque l'audit est exécuté deux fois #4034, #4071.
  • L'ajout de modèles review_exclude_paths sur votre branche principale ne force plus la révision des demandes d'extraction ouvertes lorsqu'aucun de leurs fichiers ne correspond à #4030, #4036, #4041.
  • Chaque réviseur /ship voit désormais la même différence réduite, y compris un réviseur dont les instructions ont été reconstruites de manière autonome après un démarrage raté #4048.
  • La planification de l'examen de /ship se termine en 35 secondes environ sur de très grands référentiels de résultats au lieu d'expirer #4040.
  • Les demandes d'extraction de résultats remplies d'invites de modèle capturées n'atteignent plus la limite de taille d'examen de /ship simplement parce que ces invites mentionnent les variables clés API [#4044] (https://github.com/garrytan/gstack/pull/4044).
  • /ship et /review ne comptent plus la phrase finale d'un évaluateur telle que "Aucun de ces éléments n'atteint le niveau CRITIQUE". comme constatation critique #4075.
  • Une demande d'extraction empilée dont le parent a été fusionné par squash n'a plus les propres modifications de /ship flag main en tant que modifications non révisées [#4021] (https://github.com/garrytan/gstack/pull/4021).
  • /ship ne reste plus bloqué lorsqu'une ligne de documentation contenant une réclamation d'argent, de sécurité ou numérique est ajoutée une fois la révision terminée #4062.
  • /ship ne reste plus bloqué après une fusion de base qui modifie une ligne révisée et déplace le code à côté d'elle ; il demande maintenant une petite revérification #4054.
  • /ship ne demande plus une nouvelle révision lorsqu'une fusion de base ne fait que modifier un numéro de version ou de règles que la politique de votre vaisseau déclare comme mécanique #4053.
  • /ship ne s'arrête plus sur un fichier Godot .uid ajouté après examen, et votre politique d'expédition peut désormais nommer vos propres fichiers de test #4063.
  • Une politique de livraison dont la version minimale de gstack est plus récente que la dernière version stable est désormais refusée nommément, au lieu d'envoyer des sessions vers une mise à niveau qui ne peut pas la satisfaire #4080.
  • La vérification "tester à nouveau après votre dernière modification" de /investigate remarque désormais les correctifs écrits via des commandes shell telles que sed -i ou un heredoc #4078.
  • Les portes /investigate et /plan-ceo-review ne laissent plus une session se terminer sans contrôle lorsque leur analyse s'exécute lentement #4072.
  • /runaway-stopper ne signale plus les agents qui s'enregistrent toutes les quatre minutes en attendant sur CI comme fugueurs #4069.
  • Le coureur Ubicloud derrière /ubicloud ne traite jamais une erreur API comme un succès et ne détruit jamais une VM créée par un autre appelant sous le même nom #4039, #4046.

Modifications pour les responsables

  • Les étapes de finition et d'acceptation de /ship gèrent mieux les cycles de réparation accordés par le propriétaire : les contrôles de réparation enchaînés comptent tous, un cycle accordé actualise l'argent et la sécurité relus tout seul, les notes dirigées par le propriétaire clôturent leurs résultats et le résultat nomme la subvention utilisée #4050, #4064, #4070, #4077.
  • L'enregistrement relu d'argent et de sécurité survit à une fusion principale ultérieure et accepte prend sa limite d'attente CI de la politique du navire de base (ci_record_timeout_s) #4058, #4065.
  • accepter vérifie une branche selon sa propre politique de test lorsque cette branche ajoute uniquement des exécutions de tests, et un propriétaire peut accorder une exception pour une exécution de test #4061.
  • Les nouvelles clés de politique de navire mechanical_retake et test_code nécessitent gstack 1.97.0.0 #4079.
  • Sur Capy, les commandes d'assistance /ship enregistrent désormais leurs propres appels afin que le nombre d'appels d'une course soit connu #4059.
  • Le propre référentiel de gstack exécute désormais une vérification de version payante sur main toutes les 8 heures, teste à nouveau une demande d'extraction fusionnée sur la pointe de main avant de la fusionner lorsque main a déménagé, et fait réexécuter les fichiers de test ignorés par CI avant la fusion #4031, #4029, #4028.
  • L'étape de fusion masque son propre environnement, y compris le jeton GitHub, des vérifications qu'elle exécute sous Linux #4032.
  • La vérification du fichier de version accepte une sortie de version que l'outil de version du référentiel régénère #4033.
  • Une pull request qui modifie setup n'exécute plus chaque cas d'évaluation payant sur un écran étroit [#4056] (https://github.com/garrytan/gstack/pull/4056).
  • L'avertissement de partition lente de CI libre prend désormais en compte les partitions réparties sur des tâches parallèles, merci @indraoverflow #4085.
  • Réparations de tests : deux fichiers de test réussissent désormais en un seul processus, et quatre tests irréguliers indiquent pourquoi ils ont échoué #4068, #4074.
  • L'inventaire des preuves enregistre les derniers verdicts d'acheminement et d'évaluation #4076.
  • gstack génère désormais une édition chargée à la demande de trois compétences (enquêter, examiner et examiner le plan) pour un autre hôte d'agent [#4049] (https://github.com/garrytan/gstack/pull/4049).
  • Documents d'agent : les agents sur Capy commentent et demandent des avis uniquement via les outils de relations publiques de Capy, les agents exécutent /ship sleep jusqu'à la fin et gardent leur contexte petit, et AGENTS.md répertorie les compétences par nom uniquement #4027, #4055, #4060. gstack v1.97.0.0

gstack v1.97.0.0

Mostly /ship, gstack's command that reviews, tests and opens a pull request for you: fewer needless extra review rounds, audits that follow your model preference, two opt-in gates that hold /investigate and /plan-ceo-review to their key step, and a browser security fix.

What's new

  • An opt-in gate for /plan-ceo-review keeps the session from finishing until the review has written its ranked findings; turn it on with ./setup --ceo-review-gate #4047.
  • An opt-in gate for /investigate blocks a fix until a root cause is written down, including fixes made through shell commands; turn it on with ./setup --investigate-gate #4045.
  • If you follow the stable update channel, important fixes (security, regressions, data loss, blockers) now reach stable within a day, and stable is never more than a week behind tested changes on main #4083.

Fixes

  • Security: gstack's bundled browser now uses Playwright 1.65.0 with Chromium 158, which no longer trusts the compromised eMudhra certificate authorities #4087.
  • The browse audit log no longer saves what you type into pages, such as passwords sent with fill or type, dialog answers, and cookie or header values. Reported by @derHaken #4073, #4081.
  • The browse audit log and network log no longer keep URL query values or credentials, so a submitted login form's fields stay off disk #4082.
  • gstack-brain-sync no longer calls a rejected push an auth error just because your remote's URL contains a word like auth or 403, so it retries the push as it should #4035.
  • The browse daemon no longer fails with "Is port … in use?" on a busy machine; it now picks its port right before it starts listening #4035.
  • gstack's secret scan no longer flags ordinary code such as config.prod or server.local(...) as a leaked internal hostname, thanks @nazarli-shabnam #4043.
  • /ship's docs, test-coverage and plan audits now run on the model you set in your preferences instead of always on Sonnet 5.5 #4038, #4042.
  • /ship no longer asks for another review round when its own docs audit edits files after the review, even when the audit runs twice #4034, #4071.
  • Adding review_exclude_paths patterns on your main branch no longer forces open pull requests through review again when none of their files match #4030, #4036, #4041.
  • Every /ship reviewer now sees the same trimmed diff, including a reviewer whose instructions were rebuilt on their own after a failed start #4048.
  • /ship's review planning finishes in about 35 seconds on very large results repositories instead of timing out #4040.
  • Results pull requests full of captured model prompts no longer hit /ship's review size limit just because those prompts mention API key variables #4044.
  • /ship and /review no longer count a reviewer's closing sentence such as "None of these rises to CRITICAL." as a critical finding #4075.
  • A stacked pull request whose parent was squash-merged no longer has /ship flag main's own changes as unreviewed edits #4021.
  • /ship no longer gets stuck when a docs line with a money, security or numeric claim is added after the review finished #4062.
  • /ship no longer gets stuck after a base merge that both changes a reviewed line and moves code next to it; it now asks for one small re-check #4054.
  • /ship no longer asks for a new review when a base merge only bumps a version or rules number your ship policy declares as mechanical #4053.
  • /ship no longer stops on a Godot .uid file added after review, and your ship policy can now name your own test files #4063.
  • A ship policy whose minimum gstack version is newer than the latest stable release is now refused by name, instead of sending sessions to an upgrade that cannot satisfy it #4080.
  • /investigate's "test again after your last edit" check now notices fixes written through shell commands such as sed -i or a heredoc #4078.
  • The /investigate and /plan-ceo-review gates no longer let a session end unchecked when their scan runs slowly #4072.
  • /runaway-stopper no longer flags agents that check in every four minutes while waiting on CI as runaways #4069.
  • The Ubicloud runner behind /ubicloud never treats an API error as success and never destroys a VM that another caller created under the same name #4039, #4046.

Changes for maintainers

  • /ship's finish and accept steps handle owner-granted fix rounds better: chained fix-checks all count, a granted round refreshes the money and security re-read on its own, owner-ruled notes close their findings, and the result names the grant it used #4050, #4064, #4070, #4077.
  • The money and security re-read record survives a later main merge, and accept takes its CI wait limit from the base ship policy (ci_record_timeout_s) #4058, #4065.
  • accept checks a branch under its own test policy when that branch only adds test runs, and an owner can grant an exception for one test run #4061.
  • The new ship-policy keys mechanical_retake and test_code require gstack 1.97.0.0 #4079.
  • On Capy, /ship helper commands now log their own calls so a run's call count is known #4059.
  • gstack's own repository now runs one paid release check on main every 8 hours, re-tests a pull request merged onto main's tip before merging it when main has moved, and has CI-skipped test files rerun before merge #4031, #4029, #4028.
  • The merge step hides its own environment, including the GitHub token, from the checks it runs on Linux #4032.
  • The release-file check accepts a release output that the repository's release tool regenerates #4033.
  • A pull request that edits setup no longer runs every paid eval case on a narrow screen #4056.
  • The free-CI slow-shard warning now accounts for shards split across parallel jobs, thanks @indraoverflow #4085.
  • Test repairs: two test files now pass in one process, and four flaky tests report why they failed #4068, #4074.
  • The evidence inventory records the latest routing and /investigate eval verdicts #4076.
  • gstack now generates a load-on-demand edition of three skills (investigate, review and plan review) for another agent host #4049.
  • Agent docs: agents on Capy comment and request reviews only through Capy's PR tools, agents running /ship sleep until it finishes and keep their context small, and AGENTS.md lists skills by name only #4027, #4055, #4060.
