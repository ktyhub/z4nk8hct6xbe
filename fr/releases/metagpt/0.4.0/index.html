MetaGPT v0.4.0

Highlights

  • Structured code generation via aask_code — #490 replaces fragile parsing of freeform LLM output with OpenAI function calling (tool use), so generated code arrives as structured arguments instead of being scraped from prose. This materially raises the reliability of code-emitting pipelines, but it depends on function-calling-capable models — non-OpenAI or older backends will need a fallback path.
  • New LLM backend: Zhipu ChatGLM — #492/#498 add a first-class ChatGLM API adapter, broadening provider choice beyond OpenAI and giving teams a China-accessible, cost-differentiated option. Expect new credential/endpoint config, and verify feature parity: not every backend will support the tool-use path that aask_code relies on.
  • Role message subscription API — #518 adds a simple entry point for subscribing to a role's messages. This is a building block for observers, logging, and event-driven workflows — important if you're embedding MetaGPT as a framework rather than just driving the CLI.
  • Production hardening — #485 handles openai.error.RateLimitError instead of crashing, and #472 fixes the missing-workspace failure on clean setups. Together these make unattended and CI runs far less brittle: throttling no longer aborts a run, and fresh clones won't die on a nonexistent workspace directory.
  • Knowledge base and onboarding fixes — #501 repairs search_kb.py for more dependable KB retrieval, while #494/#499 add an online docs site and corrected Windows install notes — a signal of improving cross-platform setup.

No breaking changes are noted in this release.

What's Changed

  • Add aask_code function, which enables more stable code generation using openai function call (tool use) by @orange-crow #490
  • Support Zhipu ChatGLM API by @better629 #492 #498

Bugfixes and improvements

  • Fix workspace not existing issue by @border #472

  • Fix problems in search_kb.py by @seehi #501

Documents
