argo-rollouts v1.10.0

Highlights

  • Stabilization backport, not a feature release — v1.10.0 is cut directly from the rc1 line and virtually every change is a cherry-pick, so treat this as production-hardening rather than a capability drop. If you were waiting on a new API or feature from main, it isn't here; the value is in crash and correctness fixes that make 1.10 safe to standardize on.

  • Controller resilience under informer races and cache staleness — This is the core of the release: #4916 deepcopies ALB status updates to eliminate shared-cache mutation bugs (#3673, #4184); #4870 gives experiments an API fallback when the ReplicaSet lister is stale on AlreadyExists; and #4846 stops notifications from panicking when writing Unstructured objects. These hit hardest in high-churn clusters where stale listers and concurrent status writes are routine — prioritize this upgrade if you've seen unexplained controller restarts.

  • Notifications subsystem: behavior and log-noise changes — #4866 makes the namespace-supporting notification controller selectable via a self-service flag, and #4849 downgrades unconfigured notification triggers to a lower log level (fixing #3459). Watch the flag wiring if you run on the namespace-scoped path, and expect markedly quieter controller logs if you had leftover triggers configured.

  • Pod placement and rollout-state correctness — #4917 guards against empty Values in the injected anti-affinity check, closing an edge case that could skew scheduling when values are unset; #4919 syncs the desired-replicas annotation during abort scale-downs so a rollout's recorded intent stays consistent with actual replica counts. Both are small but matter if you rely on annotations for autoscaling or audit tooling.

  • Lower API-server load and better diagnostics — #4952 skips an unnecessary ephemeral-metadata Pod listing, reducing API pressure at scale, while #4906 now logs the underlying error when newRolloutContext returns nil, turning a previously silent failure into something you can debug. Together these improve both the operating cost and the observability of a busy controller.

  • Supply chain and release hygiene — #4830 upgrades the pnpm used for SBOM generation, improving the fidelity of the generated bill of materials; two flaky tests (#4909, #4907) were stabilized, reinforcing that this is a quality-focused point release rather than a functional one.

No breaking changes are introduced in this release.
