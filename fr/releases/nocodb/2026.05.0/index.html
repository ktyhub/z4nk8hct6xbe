🚀 NocoDB : Version de fonctionnalité

<img width="1865" height="1147" alt="Version de fonctionnalité - 2026 05 0 (1)" src="https://github.com/user-attachments/assets/cb644e9e-f3e6-4afd-8209-86e0951337b1" /> ## Disponibilité | Fonctionnalité | CE / Gratuit | Payant/Entreprise | |---|:---:|:---:| | Disposition des champs multicolonnes dans les formulaires | ❌ | ✅ | | Valeur d'affichage personnalisée sur les enregistrements liés | ❌ | ✅ | | Recherche de sélecteur de liens multi-champs | ✅ | ✅ | ## Disposition des champs multicolonnes dans les formulaires > La disposition des champs multi-colonnes est disponible sur le forfait **Plus** et supérieur sur le Cloud, et avec la licence **Enterprise** sur les versions auto-hébergées. <img width="750" alt="form_field_custom_layout" src="https://github.com/user-attachments/assets/1e4e108d-9585-4068-bfa7-074035abec9c" /> <br></br> Les champs de formulaire ont toujours été empilés un par ligne. Cela fonctionne pour les enquêtes courtes, mais sur les formulaires plus longs, cela étire la page, divise les entrées associées et pousse les répondants à abandonner à mi-chemin de ce qui aurait dû être une soumission rapide. **La disposition des champs multicolonnes** vous permet de regrouper les champs associés côte à côte dans des colonnes de même largeur. Mettez le prénom et le nom sur la même ligne, ajustez la ville, l'état et le code postal dans un seul bloc d'adresse, ou regroupez toutes les entrées qui vont ensemble, jusqu'à **5 champs par ligne**. Pour regrouper des champs, faites glisser une fiche de champ sur la ligne d'un autre champ dans le générateur de formulaire. Les deux s'alignent sur une largeur égale et partagent la rangée. Les champs **Texte long**, **Pièce jointe** et **JSON** occupent toujours une ligne complète, car leurs entrées sont trop hautes ou trop larges pour être partagées. Votre mise en page est transmise à l'URL du formulaire partagé. Sur le bureau, les champs s'affichent exactement comme configurés ; sur mobile (moins de 768 px), les lignes se réduisent en une seule colonne pour plus de lisibilité. [En savoir plus sur la disposition des champs multicolonnes →](https://nocodb.com/docs/product-docs/views/view-types/form#arrange-fields-in-multi-column-rows-) ## Valeur d'affichage personnalisée sur les enregistrements liés > La valeur d'affichage personnalisée est disponible sur le forfait **Plus** et supérieur sur le Cloud, et avec la licence **Enterprise** sur les versions auto-hébergées. <img width="750" alt="custom-display" src="https://github.com/user-attachments/assets/4540941a-85f2-4fc0-ba5e-6aa1d47ceead" /> <br></br> Les enregistrements liés ont toujours montré la valeur d'affichage principale de la table liée, généralement un nom ou un titre. Cela fonctionne jusqu'à ce que deux contacts partagent un nom, que l'équipe financière ait besoin de l'identifiant externe d'un compte pour le rapprochement ou qu'un représentant du support souhaite voir le niveau d'un client en un coup d'œil. Une mauvaise colonne rend les pilules liées plus difficiles à analyser et force des clicks supplémentaires à confirmer le contexte. **Valeur d'affichage personnalisée** vous permet de remplacer la valeur par défaut de n'importe quel champ `Link to Another Record` (LTAR), lien par lien. Choisissez la colonne qui a le plus de sens pour ce lien : un e-mail sur Tâches → Propriétaire, un identifiant externe sur Offres → Compte, un niveau sur Billets → Client. Votre choix s'applique partout où un enregistrement lié apparaît : pilules cellulaires dans la grille, la galerie et le kanban ; la liste déroulante du sélecteur de liens ; formulaires étendus; cartes en ligne de calendrier et de chronologie ; info-bulles d'affichage de la carte ; entrées du journal d'audit pour les événements de liaison et de dissociation ; et des références dans la recherche, le filtrage, le tri, le regroupement et la formule. Le paramètre est conservé lors de l’exportation, de l’importation et de la duplication de base. [En savoir plus sur la valeur d'affichage personnalisée →](https://nocodb.com/docs/product-docs/fields/field-types/links-based/link-to-another-record#custom-display-value-field-) ### Recherche de sélecteur de liens multi-champs, restaurée La recherche déroulante du sélecteur de liens correspond désormais à nouveau à plusieurs champs. Dans 2026.04.0, la recherche était [portée uniquement sur la colonne de valeur d'affichage] (https://nocodb.com/docs/changelog/2026.04.0#ltar-linked-record-search-display-value-only) pour des raisons de fiabilité. Avec cette version, une recherche de champ plus large revient et la liste déroulante utilise un défilement virtuel avec un cache fragmenté afin qu'elle reste fluide sur les tables contenant des milliers d'enregistrements liés. Disponible sur tous les forfaits. ## Améliorations et correctifs - **La vue Timeline est désormais mise à jour en temps réel** - Les barres ajoutées, déplacées ou redimensionnées par un autre collaborateur apparaissent immédiatement sur votre timeline, sans actualisation de page. - **Recherche et remplacement NocoDocs sur des documents volumineux** - Correction d'un blocage et d'un manque de mémoire pouvant survenir lors de la recherche ou de l'exécution de tout remplacement dans des documents longs. - **Cellules utilisateur dans les vues partagées et publiques** - Les champs utilisateur exposent désormais uniquement le nom et l'avatar dans les vues partagées et publiques. Les adresses e-mail ne sont plus incluses dans la charge utile de la cellule. - **Affichage conditionnel du formulaire pour les champs LTAR V2** - Les règles d'affichage/masquage conditionnel sur les champs de formulaire sont désormais évaluées par rapport à la valeur d'affichage de l'enregistrement lié pour les champs `Link to Another Record` V2, correspondant à la façon dont la règle est lue dans le générateur de formulaire. - **La vue Formulaire masque les champs AutoNumber et UUID** - Les champs d'identifiant générés automatiquement sont désormais masqués dans le panneau Champs du formulaire, car ils ne peuvent pas être définis par l'auteur du formulaire. - **Création et restauration d'instantanés** - Correction d'une importation de date manquante qui interrompait la création d'instantanés à partir des paramètres de base, resserrait la validation du nom d'instantané afin que les instantanés soient restaurés proprement, et le flux de restauration d'instantané nettoie désormais automatiquement les titres de base dérivés. --- ## Ce qui a changé * corvée : peluches par @DarkPhoenix2704 dans https://github.com/nocodb/nocodb/pull/13756 * Nc fix (nocodb) : faire correspondre les liens V2 oo via l'échange fk_mm dans getRelatedLinksColumn par @rameshmane7218 dans https://github.com/nocodb/nocodb/pull/13752 * Correction : conserver les informations de fuseau horaire dans DateTime, sélectionner les en-têtes de recherche groupés par @rameshmane7218 dans https://github.com/nocodb/nocodb/pull/13757 * Nc feat : champ de valeur d'affichage personnalisé pour les colonnes LTAR par @rameshmane7218 dans https://github.com/nocodb/nocodb/pull/13590 * correctif : gestion des badges par @mertmit dans https://github.com/nocodb/nocodb/pull/13773 * Nc fix (nc-gui) : évaluez l'affichage sur condition du formulaire par rapport à la valeur d'affichage pour V2 LTAR par @rameshmane7218 dans https://github.com/nocodb/nocodb/pull/13754 * Correction/recherche Nc par @dstala dans https://github.com/nocodb/nocodb/pull/13784 ## Problèmes résolus - 🚀 NocoDB : Feature Release

<img width="1865" height="1147" alt="Feature release - 2026 05 0 (1)" src="https://github.com/user-attachments/assets/cb644e9e-f3e6-4afd-8209-86e0951337b1" />

| Feature | CE / Free | Paid / Enterprise | |---|:---:|:---:| | Multi-Column Field Layout in Forms | ❌ | ✅ | | Custom Display Value on Linked Records | ❌ | ✅ | | Multi-Field Link Picker Search | ✅ | ✅ |

Multi-Column Field Layout in Forms

Multi-Column Field Layout is available on the Plus plan and above on Cloud, and with Enterprise license on self-hosted.

<img width="750" alt="form_field_custom_layout" src="https://github.com/user-attachments/assets/1e4e108d-9585-4068-bfa7-074035abec9c" /> <br></br> Form fields have always stacked one per row. That works for short surveys, but on longer forms it stretches the page, splits up related inputs, and pushes respondents to drop off partway through what should have been a quick submission.

Multi-Column Field Layout lets you group related fields side-by-side in equal-width columns. Put first and last name on the same line, fit city, state, and zip into a single address block, or group any inputs that belong together, up to 5 fields per row.

To group fields, drag a field card onto another field's row in the form builder. Both snap to equal width and share the row. Long Text, Attachment, and JSON fields always occupy a full row, since their inputs are too tall or wide to share.

Your layout carries through to the shared form URL. On desktop, fields render exactly as configured; on mobile (under 768 px), rows collapse to a single column for readability.

Learn more about Multi-Column Field Layout →

Custom Display Value on Linked Records

Custom Display Value is available on the Plus plan and above on Cloud, and with Enterprise license on self-hosted.

<img width="750" alt="custom-display" src="https://github.com/user-attachments/assets/4540941a-85f2-4fc0-ba5e-6aa1d47ceead" /> <br></br> Linked records have always shown the primary display value of the linked table, usually a name or title. That works until two contacts share a name, the finance team needs an account's external ID for reconciliation, or a support rep wants to see a customer's tier at a glance. The wrong column makes linked pills harder to scan and forces extra clicks to confirm context.

Custom Display Value lets you override the default on any Link to Another Record (LTAR) field, on a per-link basis. Pick the column that makes the most sense for that link: an email on Tasks → Owner, an external ID on Deals → Account, a tier on Tickets → Customer.

Your choice applies everywhere a linked record appears: cell pills in grid, gallery, and kanban; the link picker dropdown; expanded forms; calendar and timeline inline cards; map view tooltips; audit log entries for link and unlink events; and references in search, filter, sort, group-by, and formula. The setting is preserved across export, import, and base duplication.

Learn more about Custom Display Value →

Multi-Field Link Picker Search, Restored

The link picker dropdown search now matches across multiple fields again. In 2026.04.0, search was scoped to the display value column only for reliability. With this release, broader field search returns, and the dropdown uses virtual scrolling with a chunked cache so it stays smooth on tables with thousands of linked records. Available across all plans.

Improvements and Fixes

  • Timeline View now updates in realtime - Bars added, moved, or resized by another collaborator appear on your Timeline immediately, without a page refresh.
  • NocoDocs search and replace on large documents - Fixed a freeze and out-of-memory crash that could occur when searching or running replace-all in long documents.
  • User cells in shared and public views - User fields now expose only the name and avatar on shared and public views. Email addresses are no longer included in the cell payload.
  • Form show-on-condition for V2 LTAR fields - Conditional show/hide rules on form fields now evaluate against the linked record's display value for V2 Link to Another Record fields, matching how the rule reads in the form builder.
  • Form view hides AutoNumber and UUID fields - Auto-generated identifier fields are now hidden in the Form fields panel, since they cannot be set by the form submitter.
  • Snapshot creation and restore - Fixed a missing date import that broke snapshot creation from base settings, tightened snapshot-name validation so snapshots restore cleanly, and the snapshot restore flow now sanitises derived base titles automatically.
