NocoDB dans les connecteurs Claude

NocoDB est désormais disponible dans Claude Connectors, donc une base peut être connectée à Claude depuis le répertoire des connecteurs plutôt que d'ajouter manuellement l'URL MCP. Une fois connecté, Claude peut utiliser tous les outils MCP autorisés par le rôle d'utilisateur connecté, qui, à partir de cette version, est un ensemble de 149 couvrant l'ensemble de l'espace de travail. <img width="1280" height="1102" alt="claude-connectors" src="https://github.com/user-attachments/assets/9a241a7f-c90d-4bde-b3c4-665914eeb13d" />

1200 % d'outils MCP en plus

Le serveur MCP est passé de 11 outils à 149, couvrant l'ensemble de l'espace de travail, pas seulement les enregistrements. Claude, ChatGPT, Cursor ou n'importe quel MCP client peuvent désormais créer dans NocoDB : dresser une table, connecter un workflow à un webhook, assembler une page d'interface ou verrouiller des autorisations, le tout en une seule conversation. Les outils couvrent les tables, les champs, les vues, les filtres, les tris, les flux de travail, les interfaces, les tableaux de bord, les widgets, les scripts, les documents, les webhooks, les commentaires, les autorisations, la sécurité au niveau de l'enregistrement, la coloration des lignes, les dossiers, les membres et l'importation et l'exportation CSV. Chacun enveloppe le même service que son REST API, donc la validation, les autorisations et l'audit sont identiques, et chaque appel respecte le rôle de l'appelant : les téléspectateurs lisent, les éditeurs écrivent, les créateurs modifient le schéma. <img width="1008" height="868" alt="mcp-tools" src="https://github.com/user-attachments/assets/d61251cb-7e12-491e-9ca2-fb353087bc21" /> En savoir plus sur MCP → 149 n’est que le début. Nous construisons déjà le prochain ensemble, et c’est celui qui change pour de bon les logiciels d’entreprise.

E-mails en texte enrichi dans les workflows

Les e-mails de workflow peuvent désormais être formatés. Les nœuds Envoyer un e-mail, SMTP, Gmail et Outlook partagent un éditeur de texte enrichi qui prend en charge les titres, le style de texte, les listes, les couleurs et les liens avec un texte d'ancrage personnalisé. Les variables de workflow peuvent être insérées n'importe où dans le corps. <img width="1137" height="781" alt="rich-text-email" src="https://github.com/user-attachments/assets/eb80d79a-974c-44c6-bb28-bffdfb1fcd71" /> En savoir plus sur le nœud Envoyer un e-mail →

Améliorations

  • Boutons sur les pages d'interface - Les boutons peuvent désormais être placés sur les en-têtes de page de tableau, les barres d'outils de révision d'enregistrement, les en-têtes de groupe de tableau de bord et les groupes de champs à l'intérieur d'une feuille d'enregistrement. Les boutons au niveau de la page exécutent une automatisation sans enregistrement, et Aller à la page de l'interface peut ouvrir une page dans n'importe quelle interface de la base. En savoir plus
  • Glisser-déposer dans la vue Liste - Les enregistrements dans la vue Liste peuvent être glissés à travers la hiérarchie : déposez-les les uns sur les autres pour les imbriquer, ou sur un autre parent pour les y déplacer. Les sous-enregistrements voyagent avec leur parent et les liens sous-jacents sont mis à jour pour vous. En savoir plus
  • Créer un champ d'enregistrement lié en ligne - Lorsque des niveaux de vue de liste ou des enregistrements imbriqués nécessitent un lien qui n'existe pas encore, click Créez un champ d'enregistrement lié pour le créer sur place, à la fois dans la vue de base et dans le générateur d'interface. En savoir plus
  • Assistants de date dans les expressions de workflow - $now() renvoie l'heure actuelle et $dateAdd(date, amount, unit) la décale, par exemple $dateAdd($now(), 3, 'days').
  • Kanban plus rapide - Le tableau Kanban optimisé, auparavant un aperçu des fonctionnalités, est désormais la valeur par défaut partout, y compris dans l'édition Community. Les piles se chargent progressivement à mesure que vous faites défiler.
  • Téléchargements Excel de grands tableaux - Les exportations Excel sont diffusées en continu, de sorte que les très grands tableaux se téléchargent de manière fiable et produisent des fichiers plus petits.
  • Progression des tâches dans les documents longs - Le nombre de tâches d'un document de liste de contrôle vous suit dans l'en-tête une fois que le titre défile hors de la vue.

Ce qui est corrigé

  • Recherches imbriquées - La recherche d'une recherche affiche chaque valeur de la grille et se résout correctement sur des liens plusieurs-à-un, sur MySQL, SQL Server et Oracle.
  • Consolidations conditionnelles avec l'utilisateur actuel - Les champs de cumul, de recherche et de lien dont les conditions utilisent l'utilisateur actuel sont calculés pour chaque utilisateur plutôt que servis à partir d'un cache partagé.
  • Fiabilité de la synchronisation - Une synchronisation de table se termine désormais toujours plutôt que de rester dans l'état de synchronisation, et la modification d'une synchronisation d'application est enregistrée sans erreur.
  • Nœuds d'enregistrement de workflow - Le test d'un nœud Créer un enregistrement ou Mettre à jour un enregistrement signale toute clé de champ qui ne correspond pas à la table cible, au lieu d'écrire un enregistrement vide.
  • Feuilles d'enregistrement d'interface - Les modifications apportées en parcourant les enregistrements apparaissent immédiatement dans la grille, les actions de liaison et de dissociation proposent Annuler et un enregistrement créé dans un groupe reste dans ce groupe.
  • Navigation au clavier de l'interface - Lorsqu'une feuille d'enregistrement est ouverte, les touches fléchées se déplacent dans la grille et la feuille suit, et Alt+Gauche et Alt+Droite passent d'un enregistrement à l'autre.
  • Générateur d'interface - L'ajout d'un tri maintient la liste déroulante ouverte, le regroupement d'une vue liée intégrée laisse la page derrière elle en place et une interface lancée reflète les modifications publiées à partir d'un autre onglet.
  • Listes de contrôle des documents - Le fait de cocher une tâche est reflété pour chaque collaborateur en temps réel, et un nouveau sous-élément non coché sous une tâche terminée s'affiche sans barré.
  • Autorisations d'intégration - Si vous tentez de modifier une intégration créée par quelqu'un d'autre, un message clair s'affiche au lieu de vous déconnecter.
  • MCP - Le tri des enregistrements fonctionne dans l'édition communautaire, les jetons sans rôle de base reçoivent une réponse claire d'accès refusé et l'autorisation OAuth est terminée à partir de clients tels que la plate-forme OpenAI.
  • Sources externes - Une page de résultats surdimensionnée explique comment réduire les champs ou la taille de la page au lieu de signaler la source comme inaccessible.
  • Dossiers - Le bouton + d'une source de données externe propose désormais Dossier à côté de Table, et un dossier créé à partir du menu Déplacer vers d'un élément prend la position de l'élément dans la barre latérale au lieu de la fin de la liste.

Notes d'auto-hébergement

  • Le mode Communauté maintient les fonctionnalités gratuites visibles - Avec Afficher uniquement les fonctionnalités de l'édition communautaire activé, les flux de travail, les interfaces et les dossiers restent disponibles et les sous-fonctionnalités verrouillées par le plan sont masquées plutôt que affichées comme des contrôles morts.
  • Renforcement de la sécurité - Les jetons API désactivés ou expirés sont rejetés dans l'édition communautaire, les champs masqués restent masqués derrière les règles de couleur des lignes sur les vues partagées, les commentaires sont étendus à leur base et la visibilité des tables est appliquée sur chaque itinéraire.
  • Erreurs d'autorisation PostgreSQL plus claires - Une tentative de modification de schéma sans propriété de la table nomme la table affectée dans son intégralité, y compris les noms entre guillemets avec des espaces ou une casse mixte.
  • Types de champs payants sur les déploiements sans licence - Les types de champs non inclus dans l'édition communautaire (UUID, AutoNumber, couleur, contraintes uniques et limites de recherche) sont désormais rejetés par le API ainsi que par l'interface utilisateur.

Modification radicale prévue du format datetime API

<Callout type="info">Ce changement a été annoncé pour la première fois dans 2026.08.2 et est toujours prévu pour une prochaine version. Il ne fait pas partie de 2026.09.0. Nous conservons la notification ici afin que les intégrations puissent être préparées.</Callout> Sur les déploiements PostgreSQL et SQLite, les valeurs datetime renvoyées par NocoDB passeront d'une précision de la seconde à la milliseconde : | Aujourd'hui | Sortie à venir | | --- | --- | | 2026-07-25 12:34:56+00:00 | 2026-07-25 12:34:56.000+00:00 |

  • Portée : Réponses REST API, charges utiles de webhook et exportations CSV/fichier. Les valeurs sont formatées lors de la lecture, de sorte que les enregistrements existants sont également renvoyés dans le nouveau format. Aucune migration de données ni remplissage n'est requis.
  • Ce qu'il faut vérifier : Les consommateurs qui analysent les dates et heures avec un format strict ou fixe devront peut-être accepter le composant milliseconde. Les analyseurs tolérants tels que Day.js et la plupart des analyseurs ISO 8601 ne sont pas affectés.
  • Filtres : Les filtres de plage et le tri ne sont pas affectés. Les filtres d'égalité date-heure exacte se comparent à la seconde précision, ils peuvent donc ne pas correspondre aux valeurs contenant des millisecondes différentes de zéro. Un filtrage prenant en compte la milliseconde est prévu à titre de suivi.
  • Non affecté : Les connexions MySQL, SQL Server et Oracle conservent la seconde précision, les dates et heures rendues par formule restent à la seconde précision et l'affichage de la date et de l'heure dans l'application reste inchangé.

Pour plus de détails sur les fonctionnalités introduites dans 2026.08.2, consultez le 2026.08.2 changelog.

NocoDB in Claude Connectors

NocoDB is now available in Claude Connectors, so a base can be connected to Claude from the connectors directory rather than adding the MCP URL manually. Once connected, Claude can use every MCP tool the connecting user's role allows, which as of this release is a set of 149 covering the whole workspace.

1200% More MCP Tools

The MCP server has gone from 11 tools to 149, covering the whole workspace, not just records. Claude, ChatGPT, Cursor, or any MCP client can now build in NocoDB: stand up a table, wire a workflow to a webhook, assemble an interface page, or lock down permissions, all in one conversation.

Tools span tables, fields, views, filters, sorts, workflows, interfaces, dashboards, widgets, scripts, documents, webhooks, comments, permissions, Record-Level Security, row coloring, folders, members, and CSV import and export. Each wraps the same service as its REST API, so validation, permissions, and audit are identical, and every call respects the caller's role: viewers read, editors write, creators change schema.

Improvements

  • Buttons across interface pages - Buttons can now be placed on table page headers, record review toolbars, dashboard group headers, and field groups inside a record sheet. Page-level buttons run an automation without a record, and Go to interface page can open a page in any interface in the base. Learn more
  • Drag and drop in List View - Records in List View can be dragged across the hierarchy: drop one onto another to nest it, or onto a different parent to move it there. Sub-records travel with their parent, and the underlying links are updated for you. Learn more
  • Create a linked record field inline - When List View levels or nested records need a link that does not exist yet, click Create a linked record field to create it on the spot, in both the base view and the interface builder. Learn more
  • Date helpers in workflow expressions - $now() returns the current time and $dateAdd(date, amount, unit) offsets it, for example $dateAdd($now(), 3, 'days').
  • Faster Kanban - The optimized Kanban board, previously a feature preview, is now the default everywhere, including the Community Edition. Stacks load progressively as you scroll.
  • Excel downloads of large tables - Excel exports are streamed, so very large tables download reliably and produce smaller files.
  • Task progress in long documents - The task count of a checklist document follows you into the header once the title scrolls out of view.

What's Fixed

  • Nested lookups - A lookup of a lookup shows every value in the grid and resolves correctly over many-to-one links, on MySQL, SQL Server, and Oracle.
  • Conditional rollups with Current User - Rollup, lookup, and link fields whose conditions use Current User are computed for each user rather than served from a shared cache.
  • Sync reliability - A table sync now always completes rather than staying in the syncing state, and editing an app sync saves without error.
  • Workflow record nodes - Testing a Create record or Update record node reports any field key that does not match the target table, instead of writing a blank record.
  • Interface record sheets - Edits made while stepping through records appear in the grid immediately, link and unlink actions offer Undo, and a record created inside a group stays in that group.
  • Interface keyboard navigation - With a record sheet open, arrow keys move through the grid and the sheet follows, and Alt+Left and Alt+Right step between records.
  • Interface builder - Adding a sort keeps the dropdown open, grouping an embedded linked view leaves the page behind it in place, and a launched interface reflects changes published from another tab.
  • Document checklists - Ticking a task is reflected for every collaborator in realtime, and a new unchecked sub-item under a completed task renders without strikethrough.
  • Integration permissions - Attempting to edit an integration created by someone else shows a clear message instead of signing you out.
  • MCP - Sorting records works in the Community Edition, tokens without a base role receive a clear access denied response, and OAuth authorization completes from clients such as OpenAI's platform.
  • External sources - An oversized page of results explains how to reduce fields or page size instead of reporting the source as unreachable.
  • Folders - The + button on an external data source now offers Folder alongside Table, and a folder created from an item's Move to menu takes the item's position in the sidebar instead of the end of the list.

Self-Hosting Notes

  • Community mode keeps Free features visible - With Show only community edition features on, Workflows, Interfaces, and folders stay available, and plan-locked sub-features are hidden rather than shown as dead controls.
  • Security hardening - Disabled or expired API tokens are rejected in the Community Edition, hidden fields stay hidden behind row color rules on shared views, comments are scoped to their base, and table visibility is enforced on every route.
  • Clearer PostgreSQL permission errors - A schema change attempted without table ownership names the affected table in full, including quoted names with spaces or mixed case.
  • Paid field types on unlicensed deployments - Field types not included in the Community Edition (UUID, AutoNumber, Color, unique constraints, and lookup limits) are now rejected by the API as well as the UI.

Planned Breaking Change to API Datetime Format

<Callout type="info">This change was first announced in 2026.08.2 and is still planned for an upcoming release. It is not part of 2026.09.0. We are keeping the notice here so integrations can be prepared.</Callout>

On PostgreSQL and SQLite deployments, datetime values returned by NocoDB will move from second to millisecond precision:

| Today | Upcoming release | | --- | --- | | 2026-07-25 12:34:56+00:00 | 2026-07-25 12:34:56.000+00:00 |

  • Scope: REST API responses, webhook payloads, and CSV/file exports. Values are formatted on read, so existing records are returned in the new format too. No data migration or backfill is required.
  • What to check: Consumers that parse datetimes with a strict or fixed format may need to accept the millisecond component. Tolerant parsers such as Day.js and most ISO 8601 parsers are unaffected.
  • Filters: Range filters and sorting are unaffected. Exact datetime equality filters compare at second precision, so they may not match values carrying non-zero milliseconds. Millisecond-aware filtering is planned as a follow-up.
  • Not affected: MySQL, SQL Server, and Oracle connections keep second precision, formula-rendered datetimes stay at second precision, and the datetime display in the app is unchanged.

For more details on the features introduced in 2026.08.2, see the 2026.08.2 changelog.
