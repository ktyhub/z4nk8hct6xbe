Comprendre-N'importe quoi v2.9.8

Faits saillants

Cours de code à côté de votre source (#753) — par @06FallingLight90

La visionneuse de code comprend désormais des explications par fichier alignées sur la visite guidée. Les fichiers couverts par la visite reçoivent des sections détaillées ; cliCliquer sur une section met en évidence ses lignes sources. Les autres fichiers reçoivent un aperçu. Les leçons sont générées lorsque la visite est construite ou reconstruite, publiées après l'enregistrement du graphique et supprimées lorsque les fichiers quittent le graphique. Les mises à jour partielles préservent les leçons existantes ; une reconstruction de la tournée rafraîchit leurs gammes de lignes.

Prise en charge de Devin et un serveur MCP stdio (#726) — par @isaiahfrantz

Devin peut charger le pipeline d'analyse du plugin et les hooks post-commit. Le nouveau serveur MCP expose six outils pour les graphiques existants : état, recherche, explication, analyse de l'impact des changements, intégration et démarrage du tableau de bord. Chaque outil inclut des informations sur la fraîcheur des graphiques et les processus du tableau de bord sont arrêtés à la fermeture du serveur. Les instructions de configuration se trouvent dans le [MCP README] (https://github.com/Egonex-AI/Understand-Anything/blob/v2.9.8/understand-anything-plugin/packages/mcp/README.md).

Analyse incrémentale et préservation des symboles

  • La préparation incrémentielle déterministe réconcilie les modifications de fichiers, ignore les règles, les empreintes structurelles et les importations. Les mises à jour préservent l'architecture survivante et le contenu de la visite lorsque ces étapes n'ont pas besoin d'être exécutées (#682).
  • Les vérifications des preuves à la source protègent les symboles existants lors des mises à jour incrémentielles, et l'échec de la finalisation restaure le graphique et les empreintes digitales enregistrés (#683, #753).
  • Les empreintes digitales font correspondre les méthodes en fonction de leur propriétaire et de leur nom, en gardant distinctes les méthodes du même nom dans différentes classes (#766) — par @thejesh23.
  • La fusion par lots de base, les importations relatives Python, la détection de cible Makefile et les relations tested_by pour Swift, Rust, Ruby et PHP reçoivent des correctifs d'exactitude (#564, #728, #725, #689).

Fraîcheur du graphique et mises à jour automatiques

  • Le tableau de bord et le rapport sur les compétences consommatrices de graphiques lorsque l'analyse enregistrée est obsolète (#558) — par @jiang4wqy.
  • Les hooks PostToolUse lisent les entrées de l'outil depuis stdin et fournissent un contexte supplémentaire dans le format de réponse pris en charge (#598, #609) — par @amitvijapur et @KumamuKuma.
  • Les commits contenant uniquement des artefacts graphiques générés ne déclenchent plus une boucle de mise à jour automatique (#634) — par @SulimanAbdulrazzaq.
  • Les fichiers illisibles sont signalés séparément des fichiers sans prise en charge de l'analyseur (#686) — par @dajiaohuang.

Prise en charge du tableau de bord et de grands référentiels

  • Le calcul de mise en page forcée s'exécute dans un Web Worker (#576) — par @KumamuKuma.
  • Les améliorations du traitement graphique couvrent la génération de visites, l'analyse, la détection de communauté, le filtrage et la recherche intégrée (#490) — par @DashBot-0001.
  • Un benchmark reproductible enregistre les délais d'analyse déterministes, la mémoire, la couverture et les résultats d'intégrité pour les grands référentiels (#587) — par @KumamuKuma.
  • Les fichiers Markdown s'affichent dans la visionneuse de code et les échecs de chargement de graphiques font apparaître leurs erreurs HTTP (#577).
  • /understand --exclude accepte les modèles d'ignorance fournis par l'utilisateur (#373) — par @yiziff. Les règles d'ignorance de démarrage couvrent désormais les tests et appareils supplémentaires Python, Rust, Ruby et Swift (#579, #582, #597, #600) — par @thejesh23.

Langues, installation et documentation

  • Tableau de bord vietnamien, compétences et prise en charge README (#709) — par @rgb-vgx.
  • L'installation de Kimi utilise .kimi-code/skills sur Unix et Windows (#685, #687) — par @FumasterLin et @dajiaohuang.
  • L'installation de Windows prend en charge PowerShell 5.1 (#185) — par @Bortlesboat.
  • Mise à jour des conseils d'installation du Codex et de VS Code Copilot, des commandes de test des contributeurs, des README traduits et des résultats d'intégration enregistrés sous UA_ONBOARDING.md (#566, #756, #718, #567, #606, #637).

Understand-Anything v2.9.8

Highlights

Code lessons alongside your source (#753) — by @06FallingLight90

The code viewer now includes per-file explanations aligned with the guided tour. Tour-covered files get detailed sections; clicking a section highlights its source lines. Other files receive an overview. Lessons are generated when the tour is built or rebuilt, published after the graph is saved, and pruned when files leave the graph. Partial updates preserve existing lessons; a tour rebuild refreshes their line ranges.

Devin support and a stdio MCP server (#726) — by @isaiahfrantz

Devin can load the plugin's analysis pipeline and post-commit hooks. The new MCP server exposes six tools for existing graphs: status, search, explanation, change-impact analysis, onboarding, and dashboard startup. Each tool includes graph freshness information, and dashboard processes are stopped when the server exits. Setup instructions are in the MCP README.

Incremental analysis and symbol preservation

  • Deterministic incremental preparation reconciles file changes, ignore rules, structural fingerprints, and imports. Updates preserve surviving architecture and tour content when those stages do not need to run (#682).
  • Source-evidence checks protect existing symbols during incremental updates, and failed finalization restores the saved graph and fingerprints (#683, #753).
  • Fingerprints match methods by their enclosing owner and name, keeping same-named methods in different classes distinct (#766) — by @thejesh23.
  • Baseline batch merging, Python relative imports, Makefile target detection, and tested_by relationships for Swift, Rust, Ruby, and PHP receive correctness fixes (#564, #728, #725, #689).

Graph freshness and automatic updates

  • The dashboard and graph-consuming skills report when saved analysis is stale (#558) — by @jiang4wqy.
  • PostToolUse hooks read tool input from stdin and deliver additional context in the supported response format (#598, #609) — by @amitvijapur and @KumamuKuma.
  • Commits containing only generated graph artifacts no longer trigger an auto-update loop (#634) — by @SulimanAbdulrazzaq.
  • Unreadable files are reported separately from files without parser support (#686) — by @dajiaohuang.

Dashboard and large-repository support

  • Force-layout computation runs in a Web Worker (#576) — by @KumamuKuma.
  • Graph-processing improvements cover tour generation, parsing, community detection, filtering, and embedding search (#490) — by @DashBot-0001.
  • A reproducible benchmark records deterministic analysis timings, memory, coverage, and integrity results for large repositories (#587) — by @KumamuKuma.
  • Markdown files render in the code viewer, and graph-loading failures surface their HTTP errors (#577).
  • /understand --exclude accepts user-supplied ignore patterns (#373) — by @yiziff. Starter ignore rules now cover additional Python, Rust, Ruby, and Swift tests and fixtures (#579, #582, #597, #600) — by @thejesh23.

Languages, installation, and documentation

  • Vietnamese dashboard, skill, and README support (#709) — by @rgb-vgx.
  • Kimi installation uses .kimi-code/skills on Unix and Windows (#685, #687) — by @FumasterLin and @dajiaohuang.
  • Windows installation supports PowerShell 5.1 (#185) — by @Bortlesboat.
  • Updated Codex and VS Code Copilot installation guidance, contributor test commands, translated READMEs, and onboarding output saved as UA_ONBOARDING.md (#566, #756, #718, #567, #606, #637).

Standalone viewer

The attached understand-anything-viewer.tgz includes the dashboard from this release. Open an already analyzed project with:

npx https://github.com/Egonex-AI/Understand-Anything/releases/download/v2.9.8/understand-anything-viewer.tgz /path/to/analyzed/project

The viewer requires Node.js 18 or newer. Workspace builds and the MCP server require Node.js 22 or newer and pnpm 10 or newer. Existing .ua/ and legacy .understand-anything/ data directories remain supported.
