accélérer v1.6.0

Prise en charge FSDPv2

Cette version introduit le support de FSDPv2 grâce à @S1ro1. Si vous utilisez le code python, vous devez définir fsdp_version=2 dans FullyShardedDataParallelPlugin :

from accelerate import FullyShardedDataParallelPlugin, Accelerator

fsdp_plugin = FullyShardedDataParallelPlugin(
    fsdp_version=2
    # other options...
)
accelerator = Accelerator(fsdp_plugin=fsdp_plugin)

Si vous souhaitez convertir une configuration YAML contenant la configuration FSDPv1 en configuration FSDPv2, utilisez notre outil de conversion :

accelerate to-fsdp2 --config_file config.yaml --output_file new_config.yaml`

Pour en savoir plus sur la différence entre FSDPv1 et FSDPv2, lisez la [documentation] suivante (https://huggingface.co/docs/accelerate/main/en/concept_guides/fsdp1_vs_fsdp2).

Prise en charge de DeepSpeed TP

Nous avons ajouté la prise en charge initiale de DeepSpeed + TP. Peu de changements ont été nécessaires car le DeepSpeed ​​API était déjà compatible. Nous devions seulement nous assurer que le chargeur de données était compatible avec TP et que nous pouvions sauvegarder les poids TP. Merci @inkcherry pour le travail ! https://github.com/huggingface/accelerate/pull/3390. Pour utiliser TP avec deepspeed, vous devez mettre à jour le paramètre dans le fichier de configuration deepspeed en incluant la clé tensor_parallel :

    ....
    "tensor_parallel":{
      "autotp_size": ${autotp_size}
    },
   ...

Plus de détails dans ce deepspeed PR.

Prise en charge du backend distribué XCCL

Nous avons ajouté la prise en charge de XCCL, un backend distribué Intel qui peut être utilisé avec les appareils XPU. Plus de détails dans cette torche PR. Merci @dvrogozh pour l'intégration !

accelerate v1.6.0

Highlights

  • FSDPv2 goes first-class (opt-in) — PR #3394 adds PyTorch's native fully_shard path behind a new fsdp_version=2 flag on FullyShardedDataParallelPlugin; existing FSDPv1 code keeps working unchanged, so this is an additive migration, not a forced one. For YAML users, the new accelerate to-fsdp2 --config_file ... --output_file ... CLI converts v1 configs — prefer it over hand-porting, since v1/v2 semantics differ (see the concept guide). Note that gradient clipping was broken at launch and fixed in #3465, so pin to v1.6.0 if you rely on clip_grad_norm with FSDP2.
  • DeepSpeed + tensor parallelism lands — PR #3390 makes TP work with DeepSpeed by fixing TP-aware dataloaders and TP weight saving; enable it by adding tensor_parallel: { "autotp_size": ... } to your DeepSpeed config, with #3443 patching a follow-up attribute bug. Also worth knowing: new no_ssh and Slurm multinode launcher options for DeepSpeed (#3329) — useful on clusters that forbid inter-node SSH.
  • XPU users get a real distributed backend — PR #3401 wires up Intel's XCCL for XPU training; combined with #3448, which drops the old device-index workaround now that XPU accepts integer indices like CUDA. If you had custom index-handling code for XPU, this is the release to remove it.
  • Experiment-tracking improvements — MLflowTracker gains log_artifact, log_artifacts, and log_figure (#3419), and CometMLTracker can now reuse an existing experiment (#3328) — handy if you want resumed runs to land in one experiment instead of creating duplicates.
  • Correctness fixes worth upgrading for — #3459 fixes seeding of a new generator in multi-GPU runs, #3464 fixes get_balanced_memory on MPS, #3405 fixes AMD GPU handling in should_reduce_batch_size(), and #3403 fixes a device KeyError in tied_params_map (particularly relevant now that XPU/XCCL is supported).

No breaking changes in this release.

FSDPv2 support

This release introduces the support for FSDPv2 thanks to @S1ro1.

If you are using python code, you need to set fsdp_version=2 in FullyShardedDataParallelPlugin:

from accelerate import FullyShardedDataParallelPlugin, Accelerator

fsdp_plugin = FullyShardedDataParallelPlugin(
    fsdp_version=2
    # other options...
)
accelerator = Accelerator(fsdp_plugin=fsdp_plugin)

If want to convert a YAML config that contains the FSDPv1 config to FSDPv2 one , use our conversion tool:

accelerate to-fsdp2 --config_file config.yaml --output_file new_config.yaml`

To learn more about the difference between FSDPv1 and FSDPv2, read the following documentation.

DeepSpeed TP support

We have added initial support for DeepSpeed + TP. Not many changes were required as the DeepSpeed APIs was already compatible. We only needed to make sure that the dataloader was compatible with TP and that we were able to save the TP weights. Thanks @inkcherry for the work ! https://github.com/huggingface/accelerate/pull/3390.

To use TP with deepspeed, you need to update the setting in the deepspeed config file by including tensor_parallel key:

    ....
    "tensor_parallel":{
      "autotp_size": ${autotp_size}
    },
   ...

More details in this deepspeed PR.

Support for XCCL distributed backend

We've added support for XCCL which is an Intel distributed backend which can be used with XPU devices. More details in this torch PR. Thanks @dvrogozh for the integration !
