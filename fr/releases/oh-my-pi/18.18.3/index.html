oh-mon-pi v18.18.3

@oh-my-pi/pi-catalogue

Modifié

  • Ajout d'un biais de délégation balanced entre eager et restrained ; les modèles sans règle delegation-bias se résolvent désormais avec celle-ci au lieu de eager

@oh-my-pi/pi-coding-agent

Modifications radicales

  • L'outil ask prend un formulaire HTML ({ html }) au lieu de questions[] : le modèle écrit un <form> de radios, cases à cocher, sélections, entrées de texte et zones de texte avec sa recommandation présélectionnée, et reçoit les données du formulaire soumises sous la forme JSON. AskToolDetails est maintenant { answers: { name, question, answer }[]; timedOut? } ; QuestionResult, les chemins « Autre », « Discuter à ce sujet », réponse-note et réponse-image de l'outil sont supprimés, et la nouvelle réponse /tree rouvre le formulaire d'origine (NavigateTreeResult.reopenAsk porte html).

Ajouté

  • Dans Tern, cliquer à droite sur cli une réponse ask propose Note, qui annote cette réponse sans la sélectionner (#18551 par @H4vC)
  • task.eager (preferred/always) façonne désormais uniquement l'invite système de l'agent principal ; les sous-agents reviennent à la propre politique de délégation de leur modèle au lieu d'être poussés à générer d'autres sous-agents
  • Les formulaires ask peuvent afficher des images : <img src> à partir d'une URL http(s), d'un URI data: ou d'un fichier local (par rapport au répertoire de travail de la session), et des diagrammes <svg> en ligne, dessinés dans le formulaire du terminal et nativement dans Tern.
  • Les formulaires ask donnent à chaque radio et groupe de cases à cocher une réponse "Autre" en texte libre : son texte est la valeur de la radio ou est ajouté au tableau du groupe de cases à cocher (repli champ par champ, invités de collaboration et élicitation ACP inclus)
  • L'interface utilisateur de l'extension gagne ui.formDialog(html, options) en option, qui restitue un HTML <form> et se résout en { data, timedOut? } (non défini en cas d'annulation). Le TUI interactif le restitue sous la forme d'une boîte de dialogue de formulaire, les ACP clients avec élicitation de formulaire obtiennent une élicitation avec une propriété par champ, et les hôtes sans celle-ci (RPC) répondent à l'outil ask champ par champ via select/input/editor.
  • Les cellules d'évaluation peuvent exécuter des commandes shell avec sh : sh("git status") dans Python, await sh`ls ${dir}` or await sh("make", { cwd }) in JavaScript. Commands run on the embedded bash engine to completion (never auto-backgrounded), return their output, and raise ShellError avec le code de sortie en cas d'échec.
  • omp zsh sous Windows exécute les utilitaires intégrés d'omp (ls, cat, head, jq, …) pour les commandes que PATH n'a pas, à moins qu'un command_not_found_handler ne les gère (#18532 par @H4vC).

Modifié

  • Clarification des descriptions des outils et des URL internes pour les transcriptions concises history://, la conservation des emplois proc:// et les recherches d'agents parqués, ainsi que la sortie de texte de requête read JSON (#18553 par @xiangnan0811)
  • Les modèles sans règle de délégation (Claude, Gemini, …) ne sont plus poussés à déléguer : la règle « mapper le code inconnu via la tâche » et les nudges « Tâche + scout » dans les descriptions des outils de recherche sont remplacés par une légère suggestion d'explorer des sous-systèmes inconnus avec un scout
  • Dans Tern, click une réponse ask puis Note annote désormais la réponse mise en évidence sur la question affichée au lieu de celle qui vient d'être clicked (#18551 par @H4vC)

Corrigé

  • Correction des notes ask ajoutées avec n juste après avoir choisi une réponse atterrissant sur la question précédente au lieu de celle affichée ; un Tern click puis Note note toujours la réponse juste clicked, et le bouton Note la nomme (#18317 par @DonMikone)
  • Correction de l'échec de /export sous Windows lors de l'enregistrement dans le répertoire actuel, y compris les chemins relatifs tels que sub/../session.html ; le message d'exportation affiche désormais le chemin complet du fichier écrit (#18369, #18525 par @minhngoc25a).
  • L'initialisation de Todo nomme désormais les phases vides Tasks, afin que les mises à jour ultérieures puissent y répondre (#18552 par @xiangnan0811).
  • omp zsh et l'outil bash sous Windows : les commandes en arrière-plan sans contrôle des tâches ignorent Ctrl-C (INT, et QUIT en zsh) comme le font zsh et bash, donc le Ctrl-C de la console les laisse fonctionner (#18532 par @H4vC).
  • omp zsh trouve la bibliothèque de fonctions du système zsh (chargements compinit) sur Debian, Ubuntu et Arch, et sous Windows à partir d'un MSYS2, Cygwin ou Git pour Windows zsh (#18532 par @H4vC).
  • omp zsh sous Windows : les commandes saisies ne se terminent plus par ^M, les programmes sont trouvés via Path, les scripts redirigés exécutent chaque ligne, cd prend C:\…/C:/…, .. et ~ (en gardant $PWD comme C:/…), >/dev/null fonctionne, l'invite est % plutôt que celle de root #, $OSTYPE est msys et aucun avertissement USERNAME n'est imprimé (#18532 par @H4vC).
  • omp zsh sous Windows édite les lignes avec ZLE (historique, complétion des onglets, raccourcis clavier, $COLUMNS) ; Ctrl-C abandonne la ligne, exécute un trap INT ou interrompt un read qui continue ensuite, au lieu de terminer le shell (#18532 par @H4vC).
  • omp zsh sous Windows : Ctrl-C interrompt le programme de premier plan, jobs, fg et bg fonctionnent (un travail ramené avec fg obtient également Ctrl-C), et la substitution de processus atteint les programmes Windows (diff <(…) <(…), prog >(…)) (#18532 par @H4vC).
  • Sous Windows, /dev/null fonctionne dans l'outil bash (>/dev/null, cat /dev/null, [ -c /dev/null ]) (#18532 par @H4vC).
  • Sous Windows, /dev/tty ouvre la console dans omp zsh et l'outil bash (prog >/dev/tty), et un programme MSYS ou Cygwin tué par Ctrl-C rapporte le statut 130 au lieu de 512 (#18532 par @H4vC).
  • omp zsh imprime la ligne [n] pid pour un pipeline en arrière-plan sous contrôle de travail, comme pour une commande unique (#18532 par @H4vC).
  • omp zsh démarre compinit beaucoup plus rapidement : les éléments de tableau et d'association uniques sont attribués et lus sans copier l'intégralité du paramètre, et autoload -r ne relit plus les résumés .zwc dans $fpath pour chaque fonction qu'il résout (#18533 par @H4vC).
  • Les read -k et read -q de omp zsh lisent une clé du terminal sans attendre Entrée, comme le fait zsh, au lieu de lire l'entrée standard (#18533 par @H4vC).
  • Les listes de complétion omp zsh marquent à nouveau les types de fichiers (dir/, exe*), print -c présente les mots en colonnes sans terminal et ${x?msg} termine un shell non interactif avec le statut 1 comme le fait zsh (#18533 par @H4vC).
  • Les flotteurs omp zsh conservent une précision arithmétique totale (le s=$EPOCHREALTIME; print $(( EPOCHREALTIME - s )) ne dérive plus jusqu'à une seconde) et s'impriment toujours dans leur style -F/-E (#18533 par @H4vC).
  • Les typeset -U path / typeset -U fpath (et local -U path) de omp zsh suppriment les entrées répétées comme le fait zsh (#18533 par @H4vC).
  • omp zsh et l'outil bash : $! d'un pipeline en arrière-plan est le pid de son dernier programme, comme dans bash et zsh, donc kill $! signale ce programme ; La ligne [n] de omp zsh pour un pipeline en arrière-plan répertorie le pid de chacun de ses processus, comme le fait zsh (#18547 par @H4vC).
  • omp zsh est plus rapide : les appels de fonctions, les boucles et l'arithmétique s'exécutent 2 à 3 fois plus rapidement, compinit presque 4 fois plus rapidement, et la construction d'un grand tableau ou d'une association un élément à la fois (a+=(x), h[k]=v) ou la lecture de $a[i] à partir d'un grand tableau ne ralentit plus avec sa taille (#18565 par @H4vC).

@oh-my-pi/collab-web

Modifié

  • Les fiches outils ask affichent les légendes des champs du formulaire HTML et le nombre de champs en attente, ainsi que chaque question avec sa réponse soumise (ou "(pas de réponse)") une fois répondue, signalant les soumissions effectuées avant l'expiration du délai d'attente.

@oh-my-pi/pi-tui

Modifications radicales

  • Le moteur de rendu de l'outil ask dessine désormais les appels de formulaire { html } et les résultats AskToolDetails { answers, timedOut } ; QuestionResult et les champs de détails de la liste de questions ont été supprimés.

Ajouté

  • Ajout d'une entrée de note au menu de droite click de chaque ligne de réponse de la boîte de dialogue de demande dans Tern, annotant cette réponse sans la sélectionner (#18551 par @H4vC)
  • Ajout de HtmlFormDialog, qui restitue un formulaire HTML sous forme de formulaire de terminal interactif, divise les formulaires longs en pages et renvoie les réponses sous la forme JSON. Les <select> simples sont des listes déroulantes d'une seule ligne, les groupes de radios et de cases à cocher obtiennent une réponse "Autre" en texte libre, <img> (URL, URI data: ou fichier local) et les images <svg> en ligne se chargent en arrière-plan, un délai d'inactivité facultatif soumet les valeurs actuelles et les terminaux Tern obtiennent le formulaire de manière native.
  • Ajout d'une option cursor: "start" à Editor.setText afin que le texte multiligne pré-rempli s'ouvre sur sa première ligne.

Modifié

  • La note de la boîte de dialogue de demande juste après un pointeur click annote désormais la réponse en surbrillance de la question affichée au lieu de la réponse simplement clicked, et le bouton Note ne nomme plus de cible de redirection (#18551 par @H4vC).

Corrigé

oh-my-pi v18.18.3

@oh-my-pi/pi-catalog

Changed

  • Added a balanced delegation bias between eager and restrained; models without a delegation-bias rule now resolve to it instead of eager

@oh-my-pi/pi-coding-agent

Breaking Changes

  • The ask tool takes one HTML form ({ html }) instead of questions[]: the model writes a <form> of radios, checkboxes, selects, text inputs and textareas with its recommendation preselected, and receives the submitted form data as JSON. AskToolDetails is now { answers: { name, question, answer }[]; timedOut? }; QuestionResult, the "Other", "Chat about this", answer-note and answer-image paths of the tool are removed, and /tree re-answer reopens the original form (NavigateTreeResult.reopenAsk carries html).

Added

  • In Tern, right-clicking an ask answer offers Note, which annotates that answer without picking it (#18551 by @H4vC)
  • task.eager (preferred/always) now shapes only the main agent's system prompt; subagents fall back to their model's own delegation policy instead of being pushed to spawn further subagents
  • ask forms can show pictures: <img src> from an http(s) URL, a data: URI or a local file (relative to the session's working directory), and inline <svg> diagrams, drawn in the terminal form and natively in Tern
  • ask forms give every radio and checkbox group a free-text "Other" answer: its text is the radio's value or is appended to the checkbox group's array (field-by-field fallback, collab guests and ACP elicitation included)
  • Extension UI gains optional ui.formDialog(html, options), which renders an HTML <form> and resolves to { data, timedOut? } (undefined when cancelled). The interactive TUI renders it as a form dialog, ACP clients with form elicitation get one elicitation with a property per field, and hosts without it (RPC) answer the ask tool field by field through select/input/editor.
  • Eval cells can run shell commands with sh: sh("git status") in Python, await sh`ls ${dir}` or await sh("make", { cwd }) in JavaScript. Commands run on the embedded bash engine to completion (never auto-backgrounded), return their output, and raise ShellError with the exit code on failure.
  • omp zsh on Windows runs omp's builtin utilities (ls, cat, head, jq, …) for commands PATH does not have, unless a command_not_found_handler handles them (#18532 by @H4vC).

Changed

  • Clarified tool and internal-URL descriptions for history:// concise transcripts, proc:// job retention and parked-agent lookups, and read JSON query text output (#18553 by @xiangnan0811)
  • Models without a delegation rule (Claude, Gemini, …) no longer get pushed to delegate: the "map unknown code via task" rule and the "Task + scout" nudges in search tool descriptions are replaced by a light suggestion to explore unfamiliar subsystems with a scout
  • In Tern, clicking an ask answer and then Note now annotates the answer highlighted on the question shown instead of the one just clicked (#18551 by @H4vC)

Fixed

  • Fixed ask notes added with n right after picking an answer landing on the previous question instead of the one shown; a Tern click then Note still notes the answer just clicked, and the Note button names it (#18317 by @DonMikone)
  • Fixed /export failing on Windows when saving in the current directory, including relative paths such as sub/../session.html; the export message now shows the full path of the written file (#18369, #18525 by @minhngoc25a).
  • Todo initialization now names empty phases Tasks, so subsequent updates can address them (#18552 by @xiangnan0811)
  • omp zsh and the bash tool on Windows: background commands without job control ignore Ctrl-C (INT, and QUIT in zsh) as zsh and bash do, so the console's Ctrl-C leaves them running (#18532 by @H4vC).
  • omp zsh finds the system zsh's function library (compinit loads) on Debian, Ubuntu and Arch, and on Windows from an MSYS2, Cygwin or Git for Windows zsh (#18532 by @H4vC).
  • omp zsh on Windows: typed commands no longer end in ^M, programs are found through Path, piped scripts run every line, cd takes C:\…/C:/…, .. and ~ (keeping $PWD as C:/…), >/dev/null works, the prompt is % rather than root's #, $OSTYPE is msys, and no USERNAME warning is printed (#18532 by @H4vC).
  • omp zsh on Windows edits lines with ZLE (history, Tab completion, key bindings, $COLUMNS); Ctrl-C abandons the line, runs an INT trap, or interrupts a read that then goes on, instead of ending the shell (#18532 by @H4vC).
  • omp zsh on Windows: Ctrl-C interrupts the foreground program, jobs, fg and bg work (a job brought back with fg gets Ctrl-C too), and process substitution reaches Windows programs (diff <(…) <(…), prog >(…)) (#18532 by @H4vC).
  • On Windows, /dev/null works in the bash tool (>/dev/null, cat /dev/null, [ -c /dev/null ]) (#18532 by @H4vC).
  • On Windows, /dev/tty opens the console in omp zsh and the bash tool (prog >/dev/tty), and an MSYS or Cygwin program killed by Ctrl-C reports status 130 instead of 512 (#18532 by @H4vC).
  • omp zsh prints the [n] pid line for a background pipeline under job control, as it does for a single command (#18532 by @H4vC).
  • omp zsh starts compinit many times faster: single array and association elements are assigned and read without copying the whole parameter, and autoload -r no longer re-reads the .zwc digests in $fpath for every function it resolves (#18533 by @H4vC).
  • omp zsh's read -k and read -q read a key from the terminal without waiting for Enter, as zsh does, instead of reading standard input (#18533 by @H4vC).
  • omp zsh completion listings mark file types again (dir/, exe*), print -c lays words out in columns without a terminal, and ${x?msg} ends a non-interactive shell with status 1 as zsh does (#18533 by @H4vC).
  • omp zsh floats keep full precision in arithmetic (s=$EPOCHREALTIME; print $(( EPOCHREALTIME - s )) no longer drifts by up to a second) and still print in their -F/-E style (#18533 by @H4vC).
  • omp zsh's typeset -U path / typeset -U fpath (and local -U path) drop repeated entries as zsh does (#18533 by @H4vC).
  • omp zsh and the bash tool: $! of a background pipeline is its last program's pid, as in bash and zsh, so kill $! signals that program; omp zsh's [n] line for a background pipeline lists the pid of each of its processes, as zsh does (#18547 by @H4vC).
  • omp zsh is faster: function calls, loops and arithmetic run 2–3× faster, compinit almost 4× faster, and building a large array or association one element at a time (a+=(x), h[k]=v) or reading $a[i] from a large array no longer slows down with its size (#18565 by @H4vC).

@oh-my-pi/collab-web

Changed

  • ask tool cards show the HTML form's fieldset legends and field count while pending, and each question with its submitted answer (or "(no answer)") once answered, flagging submissions made by the timeout

@oh-my-pi/pi-tui

Breaking Changes

  • The ask tool renderer now draws { html } form calls and AskToolDetails { answers, timedOut } results; QuestionResult and the question-list detail fields were removed.

Added

  • Added a Note entry to the right-click menu of each ask dialog answer row in Tern, annotating that answer without picking it (#18551 by @H4vC)
  • Added HtmlFormDialog, which renders an HTML form as an interactive terminal form, splits long forms into pages, and returns the answers as JSON. Single <select>s are one-row dropdowns, radio and checkbox groups get a free-text "Other" answer, <img> (URL, data: URI or local file) and inline <svg> pictures load in the background, an optional inactivity timeout submits the current values, and Tern terminals get the form natively.
  • Added a cursor: "start" option to Editor.setText so prefilled multi-line text opens at its first line.

Changed

  • The ask dialog's Note right after a pointer click now annotates the highlighted answer of the question shown instead of the answer just clicked, and the Note button no longer names a redirect target (#18551 by @H4vC)

Fixed

  • Fixed the ask dialog's n right after a keyboard pick annotating the previous question's answer instead of the highlighted row shown; only a pointer click still redirects Note to the answer just picked, and the Note button then names it (#18317 by @DonMikone)
