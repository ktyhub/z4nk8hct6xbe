ant-design 6.6.2

Highlights

  • Accessibility improvements without new APIs — Progress avoids duplicate SVG announcements, Steps triggers onClick on keyboard activation and hides decorative arrows, Tooltip preserves existing aria-describedby relationships, and Skeleton.Image placeholders are hidden from assistive technology (#59139, #59105, #59107). Recheck custom Steps handlers and screen-reader output after upgrading.

  • Numeric 0 now behaves as valid content and identity — Rendering fixes cover Alert, Empty, Card, Tag, Breadcrumb, Segmented, FloatButton, Form.Item, and Statistic (#59117, #59094, #59079, #59101). Zero-valued rowKey no longer remounts List items (#59113), DirectoryTree supports Shift selection from a key: 0 node (#59029), and Descriptions preserves item state when reordering key: 0 entries (#59064).

  • Type definitions now reject unsupported APIs — Alert’s global closable and Select/AutoComplete’s onPopupVisibleChange typings no longer expose unsupported callbacks or props (#59100, #59142). Code that previously type-checked through those inaccurate declarations may require adjustment, although no runtime migration is implied.

  • Navigation and data-selection edge cases are fixed — Menu popup IDs are unique across instances and horizontal submenus remain open as the pointer crosses into their popup (#59048, #59088). Transfer correctly handles disabled-only search results and recovery from an empty filter (#59121, #59074). Sortable Table headers forward non-Enter keys to custom onKeyDown handlers and no longer emit duplicate filter-close callbacks (#59078, #59023).

  • Controlled state, form safety, and style precedence are corrected — DirectoryTree accepts explicitly undefined controlled key arrays again (#59076); Notification close buttons no longer submit enclosing forms (#59126); Checkbox.Group disabled={false} overrides global disabled state for JSX children (#59109); local CheckableTag.style now wins over ConfigProvider’s tag.style (#59087); and Grid Row clears stale align/justify classes when props or breakpoint matches are removed (#59066).

  • List deprecation now provides a migration target — The runtime warning recommends migrating to Listy (#59060). Existing List usage continues to work, but teams should schedule a migration rather than start new work on the deprecated component.
