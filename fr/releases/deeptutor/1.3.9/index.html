DeepTutor v1.3.9

DeepTutor v1.3.9 Release Note

Date de sortie : 2026.05.09 v1.3.9 s'appuie sur la base multi-utilisateurs v1.3.8 avec un TutorBot plus large options de déploiement, un routage plus sûr des fournisseurs pour les modèles de réflexion et une chemin d’intégration Web. Il ajoute le support Zulip et NVIDIA NIM, améliore le démarrage l'ergonomie et intègre les principaux correctifs de problèmes signalés après la dernière version.

Faits saillants

Expansion du canal et du fournisseur TutorBot

  • Zulip est désormais une chaîne TutorBot - les robots peuvent écouter les messages privés et diffuser des sujets, appliquer allow_from, choisir la mention uniquement ou ouvrir le flux répond et relie la file d'attente des événements de Zulip au bus asynchrone TutorBot.
  • Les mathématiques et les fichiers fonctionnent mieux dans Zulip - LaTeX est converti en Zulip-friendly Le balisage KaTeX, les appels de téléchargement/téléchargement utilisent un comportement de nouvelle tentative configurable, et les noms de fichiers de pièces jointes incluent des résumés du chemin de téléchargement pour éviter les collisions.
  • Les sujets Zulip maintiennent les conversations séparées - les sujets de diffusion en font désormais partie de la clé de discussion/session, avec un repli stable (no topic) pour les sujets vides.
  • TutorBot prend en charge NVIDIA NIM - nvidia_nim est disponible dans TutorBot configuration du fournisseur et détection du registre, y compris le comportement de streaming de NIM qui omet stream_options non pris en charge.

Fiabilité du modèle et de l'exécution

  • Les fenêtres contextuelles configurées sont respectées - le plafond de sécurité est relevé à 1 000 000 de jetons alors que la solution de repli grand modèle reste 65 536, donc explicite Les paramètres du modèle de style 128K ne sont plus bloqués silencieusement.
  • La détection de vision Qwen est corrigée - Les modèles Qwen VL sont traités comme compatible avec la vision sur DashScope, compatible avec OpenAI et liaisons personnalisées.
  • Le mode de réflexion minimal est sécurisé pour le fournisseur - DeepSeek, DashScope, VolcEngine, BytePlus et MiniMax ne reçoivent plus un niveau supérieur rejeté reasoning_effort=minimal; DeepTutor envoie la désactivation spécifique au fournisseur signalez à la place.
  • Les coûts de DeepSeek v4 sont suivis - la comptabilité des jetons de recherche comprend Entrées de prix deepseek-v4-flash et deepseek-v4-pro.

Web et polonais CLI

  • deeptutor start lance la pile Web complète - le CLI délègue désormais à scripts/start_web.py pour que le backend et le frontend puissent être démarrés à partir d'un seul et les échecs du lanceur se propagent via le code de sortie CLI.
  • L'intégration dans la barre latérale est plus claire - les icônes de navigation principales sont désormais exposées Info-bulles localisées et étendues avec descriptions et prise en charge du focus clavier.
  • Les messages utilisateur multilignes restent lisibles - Le rendu des messages de discussion est préservé Maj+Entrée les sauts de ligne, corrigeant les blocs de code et les invites structurées qui étaient auparavant réduit en une seule ligne.
  • Les ressources attribuées sont plus faciles à comprendre - résumés de sélection de modèles et les actions de la base de connaissances en lecture seule présentent désormais des étiquettes plus claires pour sessions non-admin, limitées par une subvention.

Parité multi-utilisateurs et magasin de sessions

  • Les options de modèle attribuées correspondent au contrat du sélecteur - Choix LLM non-administrateur renvoie désormais les noms de profils, les noms de modèles, les étiquettes et les métadonnées actives/par défaut dans la même forme attendue par le sélecteur de modèle Web.
  • Les sessions PocketBase prennent en charge davantage de flux de discussion - les métadonnées des messages peuvent être persistant, la recherche du dernier message est disponible et la suppression des messages fonctionne avec ID de chaîne PocketBase ainsi que ID d'entier SQLite.
  • La régénération reste neutre en termes de stockage - la logique de nouvelle tentative peut supprimer la dernière message de l'assistant sans supposer que le magasin de session de sauvegarde utilise un nombre entier clés primaires. ## Tests
  • Ajout de la couverture du canal Zulip pour l'analyse de la configuration, les vérifications des autorisations et la duplication filtrage, mentions, portée du sujet du flux, extraction des pièces jointes, nouvelle tentative comportement, conversion LaTeX, état de saisie, envoi, téléchargements et démarrage échecs.
  • Ajout des tests du fournisseur TutorBot NVIDIA NIM pour la détection du registre et du schéma acceptation et compatibilité des demandes de streaming.
  • Ajout de tests de régression LLM pour la capacité de vision Qwen, fenêtre contextuelle explicite les budgets et les kwargs des fournisseurs à la réflexion minimale.
  • Ajout de la couverture CLI afin que deeptutor start propage le code de sortie du lanceur.
  • Ajout d'une couverture de tarification des jetons de recherche pour les entrées du modèle DeepSeek v4.

Notes de mise à niveau

  • Installez ou actualisez le .[tutorbot] extra, ou requirements/tutorbot.txt, pour incluez la nouvelle dépendance zulip>=0.8.0,<1.0.0 avant d'activer les robots Zulip.
  • Configurez les robots Zulip avec site, email, apiKey, allowFrom et groupPolicy ; utilisez mention pour des déploiements de flux plus sûrs et open uniquement quand chaque message de flux doit atteindre le bot.
  • Si vous utilisez LLM_REASONING_EFFORT=minimal avec DeepSeek, DashScope, VolcEngine, BytePlus ou MiniMax, conservez le paramètre tel quel ; v1.3.9 le traduit à la charge utile de désactivation spécifique au fournisseur.
  • Les grandes fenêtres contextuelles configurées peuvent désormais être honorées au lieu d'être plafonnées à 65 536 jetons, vérifiez donc les limites du fournisseur et le comportement attendu en matière de coûts rapides.
  • Les déploiements PocketBase facultatifs doivent garantir que la collection messages dispose d'un Champ metadata_json JSON avant de s'appuyer sur les métadonnées de régénération/session parité.

DeepTutor v1.3.9

DeepTutor v1.3.9 Release Notes

Release Date: 2026.05.09

v1.3.9 builds on the v1.3.8 multi-user foundation with broader TutorBot deployment options, safer provider routing for thinking models, and a smoother web onboarding path. It adds Zulip and NVIDIA NIM support, improves startup ergonomics, and folds in the main issue fixes reported after the last release.

Highlights

TutorBot Channel and Provider Expansion

  • Zulip is now a TutorBot channel - bots can listen to private messages and stream topics, enforce allow_from, choose mention-only or open stream replies, and bridge Zulip's event queue into the async TutorBot bus.
  • Math and files work better in Zulip - LaTeX is converted to Zulip-friendly KaTeX markup, upload/download calls use configurable retry behavior, and attachment filenames include upload-path digests to avoid collisions.
  • Zulip topics keep conversations separated - stream topics now become part of the chat/session key, with a stable (no topic) fallback for empty topics.
  • TutorBot supports NVIDIA NIM - nvidia_nim is available in TutorBot provider config and registry detection, including NIM's streaming behavior that omits unsupported stream_options.

Model and Runtime Reliability

  • Configured context windows are respected - the safety ceiling is raised to 1,000,000 tokens while the large-model fallback remains 65,536, so explicit 128K-style model settings are no longer silently clamped.
  • Qwen vision detection is fixed - Qwen VL models are treated as vision-capable across DashScope, OpenAI-compatible, and custom bindings.
  • Minimal thinking mode is provider-safe - DeepSeek, DashScope, VolcEngine, BytePlus, and MiniMax no longer receive a rejected top-level reasoning_effort=minimal; DeepTutor sends the provider-specific disable signal instead.
  • DeepSeek v4 costs are tracked - research token accounting includes deepseek-v4-flash and deepseek-v4-pro pricing entries.

Web and CLI Polish

  • deeptutor start launches the full web stack - the CLI now delegates to scripts/start_web.py so backend and frontend can be started from one command, and launcher failures propagate through the CLI exit code.
  • Sidebar onboarding is clearer - primary navigation icons now expose scoped, localized tooltips with descriptions and keyboard focus support.
  • Multi-line user messages stay readable - chat message rendering preserves Shift+Enter line breaks, fixing code blocks and structured prompts that were previously collapsed into one line.
  • Assigned resources are easier to understand - model-selection summaries and read-only knowledge-base actions now present clearer labels for non-admin, grant-scoped sessions.

Multi-User and Session Store Parity

  • Assigned model options match the selector contract - non-admin LLM choices now return profile names, model names, labels, and active/default metadata in the same shape expected by the web model selector.
  • PocketBase sessions support more chat flows - message metadata can be persisted, last-message lookup is available, and message deletion works with PocketBase string IDs as well as SQLite integer IDs.
  • Regenerate remains storage-neutral - turn retry logic can remove the last assistant message without assuming the backing session store uses integer primary keys.

Tests

  • Added Zulip channel coverage for config parsing, permission checks, duplicate filtering, mentions, stream topic scoping, attachment extraction, retry behavior, LaTeX conversion, typing status, sending, uploads, and startup failures.
  • Added TutorBot NVIDIA NIM provider tests for registry detection, schema acceptance, and streaming request compatibility.
  • Added LLM regression tests for Qwen vision capability, explicit context-window budgets, and minimal-thinking provider kwargs.
  • Added CLI coverage so deeptutor start propagates the launcher exit code.
  • Added research token-pricing coverage for the DeepSeek v4 model entries.

Upgrade Notes

  • Install or refresh the .[tutorbot] extra, or requirements/tutorbot.txt, to include the new zulip>=0.8.0,<1.0.0 dependency before enabling Zulip bots.
  • Configure Zulip bots with site, email, apiKey, allowFrom, and groupPolicy; use mention for safer stream deployments and open only when every stream message should reach the bot.
  • If you use LLM_REASONING_EFFORT=minimal with DeepSeek, DashScope, VolcEngine, BytePlus, or MiniMax, keep the setting as-is; v1.3.9 translates it to the correct provider-specific disable payload.
  • Large configured context windows may now be honored instead of capped at 65,536 tokens, so verify provider limits and expected prompt-cost behavior.
  • Optional PocketBase deployments should ensure the messages collection has a metadata_json JSON field before relying on regenerate/session metadata parity.
