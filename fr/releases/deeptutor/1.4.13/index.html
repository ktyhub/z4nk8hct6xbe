DeepTutor v1.4.13 Release Note

Date de sortie : 2026.06.27 Un suivi corrigé et peaufiné de v1.4.12 : les partenaires avec des noms non latins sont créés correctement et peuvent être transmis à des utilisateurs spécifiques, les logos s'affichent après la connexion en mode multi-utilisateur et les petites bases de connaissances sont récupérées de manière fiable. Drop-in - pas de migrations.

Quoi de neuf

Partenaires : noms dans n'importe quelle langue et attribution d'administrateur

La création d'un partenaire avec un nom chinois (ou tout autre nom non latin) fonctionne désormais : l'identifiant conserve les lettres Unicode au lieu de se réduire à un slug vide. Les partenaires deviennent également une ressource pouvant être accordée : un administrateur peut attribuer des partenaires spécifiques à des utilisateurs non-administrateurs spécifiques, qui les voient, se connectent et les consultent ensuite dans le chat. Le partenaire s'exécute toujours dans son propre espace de travail isolé et le partenaire CRUD API reste réservé aux administrateurs : une subvention n'ouvre que la porte à utiliser un partenaire attribué.

Multi-utilisateur : les logos et les éléments statiques s'affichent après la connexion

Dans un déploiement multi-utilisateurs, le logo de la barre latérale et la bannière de connexion apparaissaient brisés après la connexion (problème n° 599) : la porte d'authentification a renvoyé la récupération de bouclage sans cookie de l'optimiseur d'image Next.js vers /login. Les ressources statiques publiques contournent désormais la porte, de sorte que les logos, les favicons, les polices et les icônes se chargent normalement. La politique de routage du middleware a été transférée dans un module pur et testé unitairement.

Les petites bases de connaissances récupèrent de manière fiable

La récupération hybride (BM25) plantait sur une base de connaissances contenant seulement un ou deux documents, car le nombre de résultats demandés dépassait le nombre de fragments indexés. Le décompte est désormais limité à la taille du corpus, de sorte que les petites bases de connaissances renvoient ce qu'elles ont au lieu de commettre des erreurs au moment de la requête.

Une limite de téléchargement pour chaque format

Les téléchargements de documents partagent désormais une limite unique de 200 Mo dans tous les formats ; le plafond séparé et inférieur qui rejetait les fichiers PDF plus volumineux a disparu. La limite du corps du proxy dans le conteneur a été augmentée pour correspondre, de sorte que les téléchargements volumineux soient transmis sans troncature silencieuse.

Démarrage du conteneur portable

La configuration supervisord du conteneur démarre désormais proprement sous Docker/Podman avec racine et Podman sans racine avec userns_mode: keep-id. Il n'épingle plus son propre privilège ni n'écrit sur un chemin appartenant à la racine, supprimant ainsi un échec de démarrage (et un avertissement de fichier pid cosmétique) sous un identifiant de maintien sans racine.

Notes de mise à niveau

Visite sans rendez-vous de v1.4.12 : pip install -U deeptutor ; Les utilisateurs de Docker tirent ghcr.io/hkuds/deeptutor:latest. Aucune migration et aucun changement de comportement pour les configurations mono-utilisateur existantes. Dans les déploiements multi-utilisateurs, l'attribution d'un partenaire à un utilisateur est une nouvelle option dans l'éditeur de subventions : rien ne change jusqu'à ce que vous l'utilisiez. Changelog complet : https://github.com/HKUDS/DeepTutor/compare/v1.4.12...v1.4.13

DeepTutor v1.4.13

Highlights

  • Partners go global and grantable — Partner IDs now preserve Unicode letters, so a Chinese (or any non-Latin) name yields a valid slug instead of an empty one that collides or overwrites. Partners also become a grantable resource: admins can assign specific partners to specific non-admin users, who can then see, connect, and consult them in chat. Mind the boundary — partner CRUD stays admin-only; a grant only unlocks use of an already-created partner, and its isolated workspace is unchanged. For single-user setups this is a no-op until you touch the grant editor.

  • Multi-user logos finally render (issue #599) — After login, sidebar logos, favicons, fonts, and icons broke because the auth gate bounced the Next.js image optimizer's cookie-less loopback fetch to /login. Public static assets now bypass the gate, and the middleware routing policy was extracted into a pure, unit-tested module — a maintainability win since this class of regression is now cheap to catch. If you customized that middleware, re-check your assumptions against the new module.

  • Tiny knowledge bases stop crashing on hybrid search — BM25/hybrid retrieval threw when the requested result count exceeded the number of indexed chunks; a 1–2 document KB was enough to trigger it. The count is now clamped to corpus size, so small or per-user knowledge bases and dev/test environments return what they have instead of erroring at query time. Expect fewer hits than requested on small corpora — that's intentional, not truncation.

  • One 200 MB upload cap for every format — Documents now share a single 200 MB limit; the separate, lower PDF cap that silently rejected larger files is gone, and the in-container proxy body limit was raised to match. Watch your own ingress/nginx client_max_body_size: the container will now accept the bytes, but an outer proxy can still truncate before they arrive.

  • Rootless container startup — supervisord now starts cleanly under rootful Docker/Podman and rootless Podman with userns_mode: keep-id. It no longer pins its own privilege or writes to a root-owned path, removing a common startup failure plus a cosmetic pidfile warning — rootless deployments work out of the box.

  • Upgrade path — Drop-in from v1.4.12: pip install -U deeptutor, or docker pull ghcr.io/hkuds/deeptutor:latest. No data migrations; partner assignment is opt-in in the grant editor.

No breaking changes.

DeepTutor v1.4.13 Release Notes

Release Date: 2026.06.27

A fixes-and-polish follow-up to v1.4.12: partners with non-Latin names create correctly and can be handed to specific users, logos render after login in multi-user mode, and small knowledge bases retrieve reliably. Drop-in — no migrations.

What's New

Partners: any-language names, and admin assignment

Creating a partner with a Chinese (or any non-Latin) name now works — the id keeps Unicode letters instead of collapsing to an empty slug. Partners also become a grantable resource: an admin can assign specific partners to specific non-admin users, who then see, connect, and consult them in chat. The partner still runs in its own isolated workspace, and the partner CRUD API stays admin-only — a grant only opens the door to use an assigned partner.

Multi-user: logos and static assets render after login

In a multi-user deployment, the sidebar logo and login banner showed up broken after signing in (issue #599): the auth gate bounced the Next.js image optimizer's cookie-less loopback fetch to /login. Public static assets now bypass the gate, so logos, favicons, fonts, and icons load normally. The middleware's routing policy moved into a pure, unit-tested module.

Small knowledge bases retrieve reliably

Hybrid (BM25) retrieval crashed on a knowledge base with only a document or two, because the requested result count exceeded the number of indexed chunks. The count is now clamped to the corpus size, so tiny knowledge bases return what they have instead of erroring at query time.

One upload limit for every format

Document uploads now share a single 200 MB limit across all formats; the separate, lower cap that rejected larger PDFs is gone. The in-container proxy body limit was raised to match, so large uploads pass through without silent truncation.

Portable container startup

The container's supervisord configuration now starts cleanly under both rootful Docker/Podman and rootless Podman with userns_mode: keep-id. It no longer pins its own privilege or writes to a root-owned path, removing a startup failure (and a cosmetic pidfile warning) under rootless keep-id.

Upgrade Notes

Drop-in from v1.4.12: pip install -U deeptutor; Docker users pull ghcr.io/hkuds/deeptutor:latest. No migrations and no behavior changes for existing single-user setups. In multi-user deployments, assigning a partner to a user is a new option in the grant editor — nothing changes until you use it.
