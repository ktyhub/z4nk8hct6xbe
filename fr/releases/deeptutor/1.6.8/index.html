DeepTutor v1.6.8

DeepTutor v1.6.8 Release Note

Date de sortie : 2026.09.14 v1.6.8 reçoit vingt-deux demandes d'extraction de la communauté et une analyse des rapports qui les sous-tendent. Là où v1.6.7 recherchait un budget symbolique consacré à la pensée cachée, celui-ci répond principalement à une plainte différente : J'ai fait quelque chose et l'application n'a rien fait en silence. Une discussion supprimée sans retour en arrière, un lien de livre qui a ouvert la bibliothèque au lieu du livre, une pièce jointe que le modèle n'a jamais mentionnée, un backend tué alors qu'il était encore en cours de démarrage. Trois nouvelles surfaces arrivent à côté : une corbeille, une recherche d'historique et un outil qui va au-delà de votre propre base de connaissances. Drop-in - pas de migrations.

Quoi de neuf

Les discussions supprimées sont récupérables

Auparavant, la suppression d’une conversation était définitive. Il déplace désormais le chat vers une corbeille – une section pliable dans la barre latérale – où vous pouvez le restaurer ou le supprimer définitivement. Les pièces jointes, l'état de maîtrise et le reste des artefacts d'une discussion survivent au voyage et reviennent avec, et seule une purge explicite supprime tout du disque.

Recherchez tout l'historique de vos conversations

Le sélecteur d'historique recherche désormais le texte des messages, et non seulement les titres. Les matchs reviennent avec un court extrait autour du coup afin que vous puissiez distinguer deux conversations similaires avant de les ouvrir. Littéral, insensible à la casse et limité à la fois sur la requête et sur l'extrait.

Un outil qui va au-delà de votre base de connaissances

knowledge_frontier lit une base de connaissances et part à la recherche de ce qui n'y est pas - des travaux récents sur le même sujet, apparus comme un point de départ plutôt que comme une réponse. Il se monte automatiquement lorsqu'un tour possède un KB, à côté de rag et kb_files :

deeptutor run chat "Find recent work beyond this material" --kb textbook --tool knowledge_frontier

Les modèles de raisonnement qui s'arrêtent en pleine réflexion le disent désormais

Un tour qui dépensait tout son budget en raisonnement caché et ne rapportait rien terminait le tour par un échec opaque. Deux lectures de cette scène se déroulent désormais en série : un tour qui a visiblement atteint son plafond échoue avec les compteurs qui le prouvent – tours, personnages de raisonnement, jetons d'achèvement – parce que c'est une configuration sur laquelle vous pouvez agir. Tout ce qui raisonne sans répondre termine le tour en disant de quel type de vide il s'agit. Les tours rejoués conservent leur raisonnement pour les fournisseurs qui les envoient, et un bloc <think> principal n'avale plus le JSON après lui.

Les lectures et les livres s'ouvrent là où vous les avez indiqués

Une URL de livre approfondie a ouvert la bibliothèque et vous a laissé trouver le livre vous-même ; le plan a cessé de suivre la page sur laquelle vous vous trouviez réellement une fois que le matériel était un document plutôt qu'un média ; un matériel de lecture rendu "ne peut pas s'ouvrir" pendant le rythme avant le début du chargement. Tous les trois sont fixes. Il en va de même pour un EPUB recompressé par macOS : l'archive du Finder encapsule le livre dans un répertoire, ce qui laissait DeepTutor traiter les entrées __MACOSX/._* comme des chapitres.

Pièces jointes que le modèle peut réellement voir

Les images des tours précédents sont renvoyées, donc une question de suivi sur une image contient toujours l'image, le capuchon étant désormais un paramètre plutôt qu'une constante. Et un fichier dont l'extraction de texte n'a rien produit (un PDF numérisé, généralement) est répertorié avec la raison au lieu d'être ignoré en silence, afin que le modèle puisse nommer le fichier et expliquer pourquoi il ne peut pas le citer plutôt que de vous demander de le télécharger à nouveau.

Paramètres, démarrage et choses qui échouaient discrètement

L'application de paramètres qui ne changeaient rien permettait de toute façon de réinitialiser chaque runtime client ; Un seul endroit décide désormais de cela, au lieu de cinq sites d'appel, chacun décidant à sa manière. Le lanceur ne tue plus un backend qui est simplement en train de démarrer. La progression de la récupération déconnectée de la boucle d'événements vous atteint au lieu de disparaître. Une fonctionnalité est annulée lorsque le tour qui la consomme s'arrête, les travailleurs de GraphRAG réparent les enregistrements Arrow obsolètes avant de démarrer, et derrière un proxy inverse, le journal d'accès enregistre le véritable client plutôt que le proxy.

Corrections mineures qui valent la peine d'être mentionnées

Une carte ask_user supprime une option dont le texte visible en duplique un autre. Un plan de quiz qui revient sans modèle échoue au lieu de ne rien produire en silence. Un retryable: false explicite est honoré plutôt que remplacé par le code d'état. read_skill récupère correctement un fichier manquant. Une session tenue par un tour mort s'efface d'elle-même. Le budget de la sonde de raisonnement n'est plus aussi aberrant qu'il l'était, et chaque budget LLM réside désormais dans agents.yaml, une entrée par étape.

Notes de mise à niveau

Exécutez pip install -U deeptutor ; Les utilisateurs de Docker tirent ghcr.io/hkuds/deeptutor:latest. Rien n'a besoin d'être migré.

  • La suppression d'un chat est désormais réversible, et cela change la signification de "supprimer". Une suppression logicielle supprime ; la ligne reste jusqu'à ce que vous la vidiez de la corbeille. La suppression d'un matériel de lecture supprime toujours ses sessions de la même manière qu'auparavant.
  • agents.yaml est propriétaire de chaque budget LLM. Les entrées max_tokens au niveau de la scène y ont été déplacées, une par étape. Les valeurs que vous avez déjà définies sont toujours lues ; les étapes qui n'avaient pas d'entrée en ont désormais une.
  • Le capuchon de réinjection de l'image précédente est configurable. Il s'agissait d'un 4 codé en dur. Il réside désormais dans les paramètres système et 0 désactive la fonctionnalité. Changelog complet : https://github.com/HKUDS/DeepTutor/compare/v1.6.7...v1.6.8

DeepTutor v1.6.8

Highlights

  • Recoverable chat deletion — Chats now move to a sidebar recycle bin rather than being immediately removed, preserving attachments, mastery state, and other artifacts. Restoration is automatic in effect, but permanent deletion requires an explicit purge.
  • Full-text history search — The history picker now searches message bodies with case-insensitive matching and contextual excerpts, making it easier to locate a conversation by remembered details rather than its title.
  • Knowledge-frontier exploration — The new knowledge_frontier tool automatically mounts alongside rag and kb_files when a turn has a knowledge base, surfacing recent related work beyond the supplied material as a starting point for further investigation.
  • Actionable reasoning failures — Empty turns caused by reasoning-budget exhaustion now report the relevant counters, while other empty outcomes explain their failure mode. Provider reasoning is retained during replay, and leading <think> blocks no longer hide subsequent JSON responses.
  • More reliable multimodal context — Earlier-turn images are re-sent for follow-up questions, and the previous hard-coded limit of four is now configurable in system settings; setting it to 0 disables re-injection. Files with no extractable text are also explicitly surfaced to the model with the reason instead of being silently skipped.
  • Configuration and lifecycle fixes — Every LLM budget now lives in agents.yaml under stage-level max_tokens entries; existing values are still read, and stages previously without an entry receive one. Startup, cancellation, GraphRAG worker recovery, retrieval logging, and reverse-proxy client-IP handling also see targeted fixes that reduce silent failures and unnecessary resets.

No breaking changes or migrations.

DeepTutor v1.6.8 Release Notes

Release Date: 2026.09.14

v1.6.8 lands twenty-two community pull requests and a sweep of the reports behind them. Where v1.6.7 chased a token budget spent on hidden thinking, this one mostly answers a different complaint: I did a thing and the app quietly did nothing. A deleted chat with no way back, a book link that opened the library instead of the book, an attachment the model never mentioned, a backend killed while it was still starting. Three new surfaces arrive alongside — a recycle bin, history search, and a tool that looks past your own knowledge base. Drop-in — no migrations.

What's New

Deleted chats are recoverable

Deleting a conversation used to be final. It now moves the chat to a recycle bin — a collapsible section in the sidebar — where you can restore it or delete it for good. Attachments, mastery state and the rest of a chat's artifacts survive the trip and come back with it, and only an explicit purge removes anything from disk.

Search your whole conversation history

The history picker now searches message text, not just titles. Matches come back with a short excerpt around the hit so you can tell two similar conversations apart before opening either. Literal, case-insensitive, and bounded on both the query and the excerpt.

A tool that looks past your knowledge base

knowledge_frontier reads a knowledge base and goes looking for what is not in it — recent work on the same subject, surfaced as a starting point rather than an answer. It mounts automatically when a turn has a KB, next to rag and kb_files:

deeptutor run chat "Find recent work beyond this material" --kb textbook --tool knowledge_frontier

Reasoning models that stop mid-thought now say so

A round that spent its whole budget on hidden reasoning and returned nothing used to end the turn with an opaque failure. Two readings of that scene now run in series: a round that demonstrably hit its cap fails with the counters that prove it — rounds, reasoning characters, completion tokens — because that is a configuration you can act on. Anything else that reasoned without answering ends the turn saying which kind of empty it was. Replayed rounds keep their reasoning for providers that send it, and a leading <think> block no longer swallows the JSON after it.

Reading and Books open where you pointed them

A deep book URL opened the library and left you to find the book yourself; the outline stopped tracking the page you were actually on once the material was a document rather than media; a reading material rendered "cannot open" during the beat before loading had begun. All three are fixed. So is an EPUB that macOS re-zipped — Finder's archive wraps the book in a directory, which used to leave DeepTutor treating __MACOSX/._* entries as chapters.

Attachments the model can actually see

Images from earlier turns are re-sent so a follow-up question about a picture still has the picture, with the cap now a setting rather than a constant. And a file whose text extraction produced nothing — a scanned PDF, typically — is listed with the reason instead of being skipped in silence, so the model can name the file and say why it cannot quote it rather than asking you to upload it again.

Settings, startup and the things that were failing quietly

Applying settings that changed nothing used to reset every runtime client anyway; one place now decides that, instead of five call sites each deciding it their own way. The launcher no longer kills a backend that is merely still starting. Retrieval progress logged off the event loop reaches you instead of vanishing. A capability is cancelled when the turn consuming it stops, GraphRAG workers repair stale Arrow registrations before they start, and behind a reverse proxy the access log records the real client rather than the proxy.

Smaller fixes worth naming

An ask_user card drops an option whose visible text duplicates another. A quiz plan that comes back with no templates fails instead of silently producing nothing. An explicit retryable: false is honored rather than overridden by the status code. read_skill recovers a missing file properly. A session held by a dead turn clears itself. The reasoning probe budget is no longer the outlier it was, and every LLM budget now lives in agents.yaml, one entry per stage.

Upgrade Notes

Run pip install -U deeptutor; Docker users pull ghcr.io/hkuds/deeptutor:latest. Nothing needs migrating.

  • Deleting a chat is now reversible, and that changes what "delete" means. A delete soft-deletes; the row stays until you purge it from the recycle bin. Deleting a reading material still removes its sessions the same way it did before.
  • agents.yaml owns every LLM budget. Stage-level max_tokens entries moved there, one per stage. Values you already set are still read; stages that had no entry now have one.
  • The prior-image re-injection cap is configurable. It was a hard-coded 4. It lives in system settings now, and 0 turns the feature off.
