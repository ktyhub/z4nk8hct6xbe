DeepTutor v1.2.2

DeepTutor v1.2.2 Release Note

Date de sortie : 2026.04.22

Faits saillants

Système de compétences créées par l'utilisateur

Introduction d'un sous-système Skills complet qui permet aux utilisateurs de créer, de modifier et d'activer des fichiers SKILL.md personnalisés à partir de l'interface utilisateur Web. Chaque compétence se trouve sous data/user/workspace/skills/<name>/SKILL.md avec le frontmatter YAML (name, description, triggers en option) et un corps Markdown qui est injecté textuellement dans l'invite du système de discussion lorsqu'il est actif.

  • Backend — SkillService (deeptutor/services/skill/service.py) fournit CRUD + listing + sélection avec validation stricte du nom (^[a-z0-9][a-z0-9-]{0,63}$), analyse du frontmatter et isolation au niveau du répertoire. REST API monté à /api/v1/skills avec GET /list, GET /{name}, POST /create, PUT /{name}, DELETE /{name}.
  • Frontend — un nouvel onglet Compétences dans la page de gestion des connaissances (web/app/(utility)/knowledge/page.tsx) avec l'éditeur SKILL.md en ligne et un menu de sélection de compétences dans le compositeur de chat. Les compétences peuvent être basculées individuellement ou réglées en mode auto (envoie ["auto"] au backend). web/lib/skills-api.ts fournit une couche API côté client mise en cache. UnifiedChatContext transporte skills via la charge utile WebSocket.

Révision des performances d'entrée du chat (#351, #360, #362)

Suppression du décalage d'entrée dans les longues conversations grâce à la colocation d'état profond :

  • ComposerInput — extrait de ChatComposer dans son propre composant memo afin que les rendus fréquents de frappe soient isolés du reste du compositeur (panneaux de fonctionnalités, puces de référence, menus d'outils). Expose un impératif ComposerInputHandle (clear(), getValue()) pour éviter de lever l'état d'entrée.
  • SimpleComposerInput — une variante légère pour la page de discussion TutorBot qui supprime entièrement les mentions @ et les fonctionnalités, corrigeant le décalage résiduel signalé après le refactor initial.
  • React.memo sur les panneaux de configuration — QuizConfigPanel, MathAnimatorConfigPanel, ResearchConfigPanel et VisualizeConfigPanel sont désormais enveloppés dans React.memo ; les rappels parents dans ChatPage se sont stabilisés avec useCallback.
  • Assistants @-mention exportés — shouldOpenAtPopup et stripTrailingAtMention ont été déplacés vers ComposerInput.tsx en tant qu'exportations nommées pour la réutilisation entre composants.

Repli automatique pour le rejet de response_format

Extension de la garde statique supports_response_format v1.2.1 avec un chemin de récupération automatique d'exécution. Lorsqu'un fournisseur renvoie de manière inattendue HTTP 400 pour response_format={"type":"json_object"} (commun avec les modèles de style LM Studio + Gemma/Qwen), les deux chemins d'exécution LLM détectent désormais l'erreur, suppriment le champ et réessayent une fois :

  • chemin aiohttp (cloud_provider.py) — L'heuristique _looks_like_unsupported_response_format détecte le rejet dans _openai_complete et _openai_stream ; en cas de correspondance, la demande est réessayée sans response_format et la paire (liaison, modèle) est mise en cache.
  • Chemin OpenAI SDK (executors.py) — _create_with_format_fallback encapsule client.chat.completions.create, attrapant BadRequestError et appliquant la même logique de nouvelle tentative + cache.
  • Cache d'exécution (capabilities.py) — L'enregistrement disable_response_format_at_runtime / is_response_format_disabled_at_runtime a découvert des incompatibilités dans un set au niveau du module afin que les appels suivants ignorent response_format d'emblée sans payer le coût de nouvelle tentative.
  • _answer_now.py — stream_synthesis vérifie désormais supports_response_format avant d'attacher response_format, empêchant ainsi le 400 en premier lieu pour les flux de réponse rapides.

Correctif LAN/accès à distance (#340)

Lorsqu'une autre machine sur le réseau local ouvre l'interface utilisateur Web, le NEXT_PUBLIC_API_BASE au moment de la construction (généralement http://localhost:8001) est résolu par le propre bouclage du navigateur distant au lieu du serveur. Un nouvel assistant resolveBase() dans web/lib/api.ts détecte cette incompatibilité et échange le nom d'hôte contre window.location.hostname au moment de l'exécution, de sorte que apiUrl() et wsUrl() atteignent le bon backend, quelle que soit la machine qui a ouvert la page.

Badge de version de la barre latérale et lien GitHub

La barre latérale affiche désormais la version actuelle de la build à côté d'un indicateur d'état :

  • Route /api/version : un point de terminaison ISR Next.js qui interroge api.github.com/repos/HKUDS/DeepTutor/releases/latest (revalidation horaire, GITHUB_TOKEN facultatif pour la marge de limite de débit) et renvoie la dernière balise, le nom, l'URL et la date de publication.
  • VersionBadge — compare NEXT_PUBLIC_APP_VERSION (injecté au moment de la construction via next.config.js / git describe --tags) avec la dernière version récupérée. Affiche un point vert lorsqu'il est à jour, orange lorsqu'il est obsolète et neutre lorsqu'il est inconnu. Clicking accède à la page de version.
  • Dockerfile — le nouvel argument de build APP_VERSION est intégré à l'environnement Next.js afin que les déploiements basés sur Docker obtiennent également un affichage précis de la version.
  • Icône GitHub — un lien direct vers le référentiel ajouté aux états de la barre latérale réduite et développée.

Prise en charge des pièces jointes d'images Deep Solve

DeepSolveCapability extrait désormais la première pièce jointe d'image (URI de données ou URL) de context.attachments via un nouvel assistant _first_image_url et la transmet aux agents du planificateur et du solveur. En interne, PlannerAgent et SolverAgent ont été refactorisés pour utiliser la classe de données Attachment via le pipeline multimodal unifié de BaseAgent au lieu de construire manuellement des tableaux de messages multimodaux, supprimant ainsi deux fonctions d'assistance identiques de _build_multimodal_messages. BaseAgent.stream_llm a également acquis une logique pour construire des messages à partir de system_prompt + user_prompt lorsque attachments sont fournis sans messages explicite, et des journaux lorsque les images sont supprimées pour des modèles sans vision.

Passthrough des pièces jointes du pipeline de chat agent

Les méthodes _stage_responding et _stage_acting dans AgenticChatPipeline appellent désormais _prepare_messages_with_attachments après la création des messages, garantissant ainsi que les images téléchargées par l'utilisateur sont transmises au LLM à chaque étape de discussion, et pas seulement à l'étape de réflexion initiale.

Résilience TutorBot WebSocket (#354)

Renforcement du point de terminaison /api/v1/tutorbot/{bot_id}/ws :

  • Démarrage automatique — si le bot est configuré mais n'est pas en cours d'exécution lorsqu'un WebSocket se connecte, le point de terminaison appelle désormais automatiquement mgr.start_bot() au lieu de se fermer immédiatement avec 4004. Les ID de bot inconnus reçoivent toujours une charge utile d'erreur JSON avant la fermeture.
  • _safe_send wrapper — tous les appels ws.send_json passent par un assistant qui intercepte WebSocketDisconnect / RuntimeError, empêchant ainsi les exceptions non gérées lorsque le client tombe en cours de flux.
  • Déconnexion gracieuse — _handle_user_messages attrape WebSocketDisconnect sur receive_text et se brise proprement.

Page de paramètres : Masquage des touches API (#355)

Le champ Clé API de la page Paramètres est désormais rendu par défaut par type="password" avec un bouton bascule Eye / EyeOff. L'état de visibilité est réinitialisé lors du basculement entre les services ou les profils.

Refonte de l'interface utilisateur de la bibliothèque de livres

Remplacement de l'espace réservé minimal « Sélectionner un livre » par un composant BookLibrary complet (web/app/(workspace)/book/components/BookLibrary.tsx) comprenant la recherche, des cartes filtrées par statut avec le nombre de chapitres/pages, les actions de création et de suppression et les badges de statut (Brouillon/Plan/Compilation/Prêt). BookSidebar a été simplifié en une vue de lecteur d'un seul livre avec un bouton de retour « ← Tous les livres », et la page du livre affiche désormais de manière conditionnelle soit la bibliothèque, soit la barre latérale en fonction de la vue actuelle.

Mode plein écran de visualisation

Les visualisations SVG, Mermaid et ChartJS disposent désormais d'un bouton Agrandir (en haut à droite) qui ouvre le graphique dans une superposition plein écran avec Échap pour fermer. Les visualisations HTML iframe sont exclues car elles offrent déjà leur propre possibilité « Ouvrir dans un nouvel onglet ».

Corrections de bugs

  • L'adaptateur d'intégration ConnectError n'a pas été réessayé (#353) — a ajouté httpx.ConnectError au tuple d'exception de nouvelle tentative dans OpenAICompatibleEmbeddingAdapter, de sorte que les échecs de connexion transitoires pendant l'intégration sont réessayés avec un intervalle exponentiel au lieu d'être déclenchés immédiatement.
  • Renforcement par intégration RAG None — CustomEmbedding._aget_query_embedding et _aget_text_embedding génèrent désormais un ValueError clair lorsque le fournisseur renvoie None au lieu de planter plus tard dans le calcul de similarité. La méthode par lots _aget_text_embeddings détermine désormais la dimension de vecteur zéro de secours à partir des vecteurs frères ou du dim configuré, et la déclenche si aucun des deux n'est disponible (empêchant la persistance silencieuse des vecteurs de longueur nulle).
  • Crash de suppression de Ko sur un répertoire manquant — KnowledgeBaseManager.delete_knowledge_base résout désormais le chemin directement via self.base_dir / name et gère le cas où le dossier sur le disque a déjà été supprimé, nettoyant l'entrée kb_config.json orpheline au lieu de lever FileNotFoundError.
  • CLI parse_json_object espaces blancs — la fonction supprime désormais les espaces blancs de début et de fin avant l'analyse, donc les nouvelles lignes de fin de canal du shell ne provoquent plus json.JSONDecodeError.

Extension de la suite de tests

  • TutorBot WebSocket — 2 nouveaux tests couvrant le démarrage automatique des robots arrêtés mais configurés et la charge utile d'erreur JSON pour les ID de robot inconnus (tests/api/test_tutorbot_router.py).
  • Assistants CLI — 2 tests pour la gestion des espaces parse_json_object et JSON invalide (tests/cli/test_common.py).
  • Paramètres d'itinéraire — 3 tests pour le nouvel utilitaire firstParam (web/tests/route-params.test.ts).
  • Base de résolution API — teste la logique d'échange de nom d'hôte LAN (web/tests/api-resolve-base.test.ts).

DeepTutor v1.2.2

DeepTutor v1.2.2 Release Notes

Release Date: 2026.04.22

Highlights

User-Authored Skills System

Introduced a full Skills subsystem that lets users create, edit, and activate custom SKILL.md files from the web UI. Each skill lives under data/user/workspace/skills/<name>/SKILL.md with YAML frontmatter (name, description, optional triggers) and a Markdown body that is injected verbatim into the chat system prompt when active.

  • Backend — SkillService (deeptutor/services/skill/service.py) provides CRUD + listing + selection with strict name validation (^[a-z0-9][a-z0-9-]{0,63}$), frontmatter parsing, and directory-level isolation. REST API mounted at /api/v1/skills with GET /list, GET /{name}, POST /create, PUT /{name}, DELETE /{name}.
  • Frontend — a new Skills tab in the Knowledge management page (web/app/(utility)/knowledge/page.tsx) with inline SKILL.md editor, and a skill picker menu in the chat composer. Skills can be toggled individually or set to auto mode (sends ["auto"] to the backend). web/lib/skills-api.ts provides a cached client-side API layer. UnifiedChatContext carries skills through the WebSocket payload.

Chat Input Performance Overhaul (#351, #360, #362)

Eliminated input lag in long conversations through deep state colocation:

  • ComposerInput — extracted from ChatComposer into its own memo'd component so frequent keystroke re-renders are isolated from the rest of the composer (capability panels, reference chips, tool menus). Exposes an imperative ComposerInputHandle (clear(), getValue()) to avoid lifting input state.
  • SimpleComposerInput — a lightweight variant for the TutorBot chat page that strips @-mention and capability overhead entirely, fixing residual lag reported after the initial refactor.
  • React.memo on config panels — QuizConfigPanel, MathAnimatorConfigPanel, ResearchConfigPanel, and VisualizeConfigPanel are now wrapped in React.memo; parent callbacks in ChatPage stabilized with useCallback.
  • @-mention helpers exported — shouldOpenAtPopup and stripTrailingAtMention moved to ComposerInput.tsx as named exports for cross-component reuse.

Auto-Fallback for response_format Rejection

Extended the v1.2.1 static supports_response_format guard with a runtime auto-recovery path. When a provider unexpectedly returns HTTP 400 for response_format={"type":"json_object"} (common with LM Studio + Gemma/Qwen-style models), both LLM execution paths now detect the error, drop the field, and retry once:

  • aiohttp path (cloud_provider.py) — _looks_like_unsupported_response_format heuristic detects the rejection in _openai_complete and _openai_stream; on match, the request is retried without response_format and the (binding, model) pair is cached.
  • OpenAI SDK path (executors.py) — _create_with_format_fallback wraps client.chat.completions.create, catching BadRequestError and applying the same retry + cache logic.
  • Runtime cache (capabilities.py) — disable_response_format_at_runtime / is_response_format_disabled_at_runtime record discovered incompatibilities in a module-level set so subsequent calls skip response_format upfront without paying the retry cost.
  • _answer_now.py — stream_synthesis now checks supports_response_format before attaching response_format, preventing the 400 in the first place for fast-path answer flows.

LAN / Remote Access Fix (#340)

When another machine on the local network opens the web UI, the build-time NEXT_PUBLIC_API_BASE (typically http://localhost:8001) would resolve to the remote browser's own loopback instead of the server. A new resolveBase() helper in web/lib/api.ts detects this mismatch and swaps the hostname for window.location.hostname at runtime, so apiUrl() and wsUrl() reach the correct backend regardless of which machine opened the page.

Sidebar Version Badge & GitHub Link

The sidebar now displays the current build version alongside a status indicator:

  • /api/version route — a Next.js ISR endpoint that queries api.github.com/repos/HKUDS/DeepTutor/releases/latest (hourly revalidation, optional GITHUB_TOKEN for rate-limit headroom) and returns the latest tag, name, URL, and publish date.
  • VersionBadge — compares NEXT_PUBLIC_APP_VERSION (injected at build time via next.config.js / git describe --tags) against the fetched latest release. Shows a green dot when up-to-date, amber when outdated, and neutral when unknown. Clicking navigates to the release page.
  • Dockerfile — new APP_VERSION build arg piped into the Next.js env so Docker-based deployments also get accurate version display.
  • GitHub icon — a direct link to the repository added to both collapsed and expanded sidebar states.

Deep Solve Image Attachment Support

DeepSolveCapability now extracts the first image attachment (data-URI or URL) from context.attachments via a new _first_image_url helper and passes it to the planner and solver agents. Internally, PlannerAgent and SolverAgent were refactored to use the Attachment dataclass through BaseAgent's unified multimodal pipeline instead of manually constructing multimodal message arrays — removing two identical _build_multimodal_messages helper functions. BaseAgent.stream_llm also gained logic to construct messages from system_prompt + user_prompt when attachments are provided without explicit messages, and logs when images are stripped for non-vision models.

Agentic Chat Pipeline Attachment Passthrough

The _stage_responding and _stage_acting methods in AgenticChatPipeline now call _prepare_messages_with_attachments after building messages, ensuring that user-uploaded images are forwarded to the LLM in every chat stage — not just the initial thinking stage.

TutorBot WebSocket Resilience (#354)

Hardened the /api/v1/tutorbot/{bot_id}/ws endpoint:

  • Auto-start — if the bot is configured but not running when a WebSocket connects, the endpoint now calls mgr.start_bot() automatically instead of immediately closing with 4004. Unknown bot IDs still receive a JSON error payload before close.
  • _safe_send wrapper — all ws.send_json calls go through a helper that catches WebSocketDisconnect / RuntimeError, preventing unhandled exceptions when the client drops mid-stream.
  • Graceful disconnect — _handle_user_messages catches WebSocketDisconnect on receive_text and breaks cleanly.

Settings Page: API Key Masking (#355)

The API Key field on the Settings page is now rendered as type="password" by default with an Eye / EyeOff toggle button. The visibility state resets when switching between services or profiles.

Book Library UI Overhaul

Replaced the minimal "Select a book" placeholder with a full BookLibrary component (web/app/(workspace)/book/components/BookLibrary.tsx) featuring search, status-filtered cards with chapter/page counts, creation and deletion actions, and status badges (Draft / Outline / Compiling / Ready). BookSidebar was simplified to a single-book reader view with a "← All books" back button, and the book page now conditionally shows either the library or the sidebar based on the current view.

Visualization Fullscreen Mode

SVG, Mermaid, and ChartJS visualizations now have a Maximize button (top-right) that opens the graphic in a fullscreen overlay with Escape-to-close. HTML iframe visualizations are excluded since they already provide their own "Open in new tab" affordance.

Bug Fixes

  • Embedding adapter ConnectError not retried (#353) — added httpx.ConnectError to the retry exception tuple in OpenAICompatibleEmbeddingAdapter, so transient connection failures during embedding are retried with exponential backoff instead of raising immediately.
  • RAG None-embedding hardening — CustomEmbedding._aget_query_embedding and _aget_text_embedding now raise a clear ValueError when the provider returns None instead of crashing later in similarity computation. The batch method _aget_text_embeddings now determines the fallback zero-vector dimension from sibling vectors or the configured dim, and raises if neither is available (preventing silent persistence of zero-length vectors).
  • KB delete crash on missing directory — KnowledgeBaseManager.delete_knowledge_base now resolves the path directly via self.base_dir / name and handles the case where the on-disk folder was already removed, cleaning up the orphaned kb_config.json entry instead of raising FileNotFoundError.
  • CLI parse_json_object whitespace — the function now strips leading/trailing whitespace before parsing, so trailing newlines from shell piping no longer cause json.JSONDecodeError.

Test Suite Expansion

  • TutorBot WebSocket — 2 new tests covering auto-start of stopped-but-configured bots and JSON error payload for unknown bot IDs (tests/api/test_tutorbot_router.py).
  • CLI helpers — 2 tests for parse_json_object whitespace handling and invalid JSON (tests/cli/test_common.py).
  • Route params — 3 tests for the new firstParam utility (web/tests/route-params.test.ts).
  • API resolve base — tests for the LAN hostname swap logic (web/tests/api-resolve-base.test.ts).
