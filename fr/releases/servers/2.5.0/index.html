# serveurs v2.5.0

Correctifs de sécurité

v2.5.0 corrige huit vulnérabilités sur trois serveurs. Mettez à niveau mcp-server-git vers 2026.11.18, @modelcontextprotocol/server-filesystem à 2.4.0 et @modelcontextprotocol/server-everything à 2.3.1. | Forfait | Affecté | Corrigé dans | | --- | --- | --- | | mcp-server-git | via 2026.11.11 | 2026.11.18 | | @modelcontextprotocol/server-filesystem | toutes les versions antérieures à 2.4.0 et les versions datées de 2025.1.14 à 2026.8.31 | 2.4.0 | | @modelcontextprotocol/server-everything | via 2.3.0 | 2.3.1 | ###mcp-server-git2026.11.18

  • Une fusion ne démarre plus la maintenance automatique de Git. Un git_merge réussi, une avance rapide incluse, s'est terminé par git maintenance run --auto, dont le garbage collection exécute les commandes des propres noms gc.recentObjectsHook d'un référentiel, avec les privilèges du serveur. maintenance.auto est désormais false et gc.auto est 0 pour chaque commande Git exécutée par le serveur (GHSA-h2g3-rwxm-xfm3)
  • Git ne récupère jamais un objet manquant par lui-même. La configuration d'un référentiel pourrait déclarer un prometteur distant et nommer le programme que Git exécute pour le récupérer (remote.<name>.uploadpack, core.sshCommand), qu'un outil en lecture seule démarrait ensuite lorsqu'il avait besoin d'un objet qui n'était pas sur le disque. La récupération paresseuse est désactivée (GIT_NO_LAZY_FETCH=1), et un Git trop ancien pour être honoré qui refuse un référentiel qui déclare un prometteur distant (GHSA-87qg-cmw8-jc5m)
  • Les pilotes sont lus à nouveau après qu'un outil ait écrit l'arborescence de travail. La configuration d'un référentiel peut inclure un fichier créé par une fusion ou une extraction, de sorte qu'un filtre ou un pilote de fusion pourrait apparaître après que le serveur ait vidé ceux qu'il a trouvés et s'exécuter pendant le git merge --abort qui suit un conflit. git_checkout, git_merge et cet abandon relisent désormais les pilotes avant l'exécution de toute autre commande Git. Le contrôle de confinement --repository n'est pas encore répété après une telle écriture (#5599) (GHSA-9vjp-x34c-xg6v)
  • Un pilote de filtre ou de fusion avec un nom vide est également vidé. Git accepte [filter ""], sélectionné par filter= dans .gitattributes, et la liste du serveur des pilotes d'un référentiel l'a manqué, donc sa commande a été exécutée (GHSA-pm7p-vphh-2cg7)
  • Les entrées d'index qui pointent en dehors de l'arborescence de travail sont refusées. Avec --repository, un .git/index contrefait nommant un chemin tel que ../outside/secret faisait en sorte que git_diff_unstaged et git_diff renvoient le contenu de ce fichier, et git_status signalait s'il existe. L'index est désormais vérifié depuis son sommet avant qu'un outil ne le lise, et le cache non suivi, qui peut nommer un répertoire en dehors de l'arborescence de travail, est désactivé (GHSA-r2q8-f657-4r56)
  • La propre configuration d'un sous-module n'exécute plus de programmes. Avec diff.submodule=diff dans la configuration du référentiel, git_diff a exécuté un diff imbriqué à l'intérieur de chaque sous-module modifié sous les propres pilotes diff.external et textconv du sous-module, et git_checkout et git_add ont également exécuté Git dans un sous-module sous sa propre configuration. diff.submodule est maintenant short, les pilotes définis par un sous-module extrait sont remplacés et un Git plus ancien que 2.33, qui ne transmettrait pas les remplacements dans un sous-module, est refusé pour un référentiel qui en a un extrait (GHSA-8wv7-r664-7594) ###@modelcontextprotocol/server-filesystem2.4.0
  • Les listes de répertoires restent avec le répertoire qui a été vérifié (Linux et macOS). list_directory, list_directory_with_sizes, directory_tree et search_files répertorient désormais un répertoire en place après l'avoir vérifié, donc un répertoire échangé contre un lien symbolique entre la vérification et le listing ne peut plus renvoyer les noms des entrées en dehors des répertoires autorisés. Sous Windows, une liste n'est pas encore ancrée (#5600) (GHSA-rq2p-q7c4-6g27) ###@modelcontextprotocol/server-everything2.3.1
  • gzip-file-as-resource traite une adresse NAT64 comme l'adresse IPv4 qu'elle transporte. La protection d'adresse privée de l'outil lit les adresses dans 64:ff9b::/96 comme publiques, donc sur un réseau avec une passerelle NAT64, une URL peut atteindre une adresse IPv4 privée via celle-ci. L'adresse IPv4 intégrée est désormais vérifiée (GHSA-38j4-j742-j7r3)

Mise à niveau à partir d'une version npm avec version datée

Les serveurs TypeScript sont passés des versions de date (2025.x, 2026.x) aux versions sémantiques dans 1.0.0. Les gestionnaires de packages classent 2.4.0 en dessous de chaque version 2025.x et 2026.x, ils ne le proposeront donc pas comme mise à niveau. Si vous utilisez une version date de @modelcontextprotocol/server-filesystem, installez explicitement 2.4.0 : npm install @modelcontextprotocol/server-filesystem@2.4.0.

servers v2.5.0

Security fixes

v2.5.0 fixes eight vulnerabilities in three servers. Upgrade mcp-server-git to 2026.11.18, @modelcontextprotocol/server-filesystem to 2.4.0 and @modelcontextprotocol/server-everything to 2.3.1.

| Package | Affected | Fixed in | | --- | --- | --- | | mcp-server-git | through 2026.11.11 | 2026.11.18 | | @modelcontextprotocol/server-filesystem | all versions before 2.4.0, and date versions 2025.1.14 through 2026.8.31 | 2.4.0 | | @modelcontextprotocol/server-everything | through 2.3.0 | 2.3.1 |

mcp-server-git 2026.11.18

  • A merge no longer starts Git's automatic maintenance. A successful git_merge, a fast-forward included, ended in git maintenance run --auto, whose garbage collection runs the commands a repository's own gc.recentObjectsHook names, with the server's privileges. maintenance.auto is now false and gc.auto is 0 for every Git command the server runs (GHSA-h2g3-rwxm-xfm3)
  • Git never fetches a missing object by itself. A repository's configuration could declare a promisor remote and name the program Git runs to fetch from it (remote.<name>.uploadpack, core.sshCommand), which a read-only tool then started when it needed an object that was not on disk. Lazy fetching is turned off (GIT_NO_LAZY_FETCH=1), and a Git too old to honor that refuses a repository that declares a promisor remote (GHSA-87qg-cmw8-jc5m)
  • Drivers are read again after a tool writes the working tree. A repository's configuration can include a file that a merge or checkout creates, so a filter or merge driver could appear after the server had emptied the ones it found, and run during the git merge --abort that follows a conflict. git_checkout, git_merge and that abort now read the drivers again before any other Git command runs. The --repository confinement check is not yet repeated after such a write (#5599) (GHSA-9vjp-x34c-xg6v)
  • A filter or merge driver with an empty name is emptied too. Git accepts [filter ""], selected by filter= in .gitattributes, and the server's list of a repository's drivers missed it, so its command ran (GHSA-pm7p-vphh-2cg7)
  • Index entries that point outside the working tree are refused. With --repository, a crafted .git/index naming a path such as ../outside/secret made git_diff_unstaged and git_diff return that file's content, and git_status report whether it exists. The index is now checked from its top before any tool reads it, and the untracked cache, which can name a directory outside the working tree, is turned off (GHSA-r2q8-f657-4r56)
  • A submodule's own configuration no longer runs programs. With diff.submodule=diff in the repository's configuration, git_diff ran a nested diff inside each changed submodule under the submodule's own diff.external and textconv drivers, and git_checkout and git_add ran Git inside a submodule under its own configuration too. diff.submodule is now short, the drivers a checked-out submodule defines are overridden, and a Git older than 2.33, which would not pass the overrides into a submodule, is refused for a repository that has one checked out (GHSA-8wv7-r664-7594)

@modelcontextprotocol/server-filesystem 2.4.0

  • Directory listings stay with the directory that was checked (Linux and macOS). list_directory, list_directory_with_sizes, directory_tree and search_files now list a directory in place after checking it, so a directory swapped for a symlink between the check and the listing can no longer return the names of entries outside the allowed directories. On Windows a listing is not yet anchored (#5600) (GHSA-rq2p-q7c4-6g27)

@modelcontextprotocol/server-everything 2.3.1

  • gzip-file-as-resource treats a NAT64 address as the IPv4 address it carries. The tool's private-address guard read addresses in 64:ff9b::/96 as public, so on a network with a NAT64 gateway a URL could reach a private IPv4 address through one. The embedded IPv4 address is now checked (GHSA-38j4-j742-j7r3)

Upgrading from a date-versioned npm release

The TypeScript servers moved from date versions (2025.x, 2026.x) to semantic versions in 1.0.0. Package managers rank 2.4.0 below every 2025.x and 2026.x version, so they won't offer it as an upgrade. If you are on a date version of @modelcontextprotocol/server-filesystem, install 2.4.0 explicitly: npm install @modelcontextprotocol/server-filesystem@2.4.0.
