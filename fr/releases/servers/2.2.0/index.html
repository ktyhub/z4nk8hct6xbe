# serveurs v2.2.0

Sécurité : mises à jour du runtime Node.js et du certificat CA (octobre 2026)

Le 20 octobre 2026, eMudhra a révélé que les clés privées de huit de ses certificats CA intermédiaires pouvaient être récupérées à partir des certificats publics. Le 21 octobre, Node.js a publié des [versions de sécurité] (https://nodejs.org/en/blog/vulnerability/october-2026-security-releases) qui mettent à jour ses certificats d'autorité de certification fournis pour la compromission et corrigent plusieurs CVE d'exécution de haute gravité non liées. Le 23 octobre, certifi 2026.10.23 de Python a supprimé les racines eMudhra emSign Root CA - C1 et emSign ECC Root CA - C3. Comment se présentent ces serveurs

  • Les serveurs TypeScript s'appuient sur le moteur d'exécution Node.js pour les vérifications de certificats. Ils ne fournissent aucun certificat CA qui leur est propre. Seul server-everything effectue des requêtes HTTPS sortantes (gzip-file-as-resource) et le Node.js sur lequel il s'exécute les vérifie. server-filesystem, server-memory et server-sequential-thinking n'établissent aucune connexion réseau.
  • mcp-server-fetch vérifie HTTPS par rapport au bundle certifi, via httpx. L'installation à partir de PyPI (uvx mcp-server-fetch, pip install mcp-server-fetch) résout le certifi, 2026.10.23 ou version ultérieure actuel. Le fichier fetch Docker du référentiel s'installe à partir de son fichier de verrouillage, que cette version déplace vers certifi 2026.10.23 (#5341).
  • mcp-server-git et mcp-server-time n'établissent aucune connexion réseau. Si vous exécutez un serveur TypeScript à partir de npm (npx ou une installation globale) Il fonctionne sur votre Node.js, que nous ne pouvons pas mettre à jour pour vous. Veuillez exécuter Node.js 24.22.1 ou 26.12.1, ou version ultérieure, et vérifiez auprès de node --version. Le champ engines des packages accepte n'importe quel Node.js 24, donc npm ne vous avertira pas d'un runtime plus ancien et non corrigé. Si vous exécutez mcp-server-fetch à partir d'un environnement existant Un environnement créé avant le 23 octobre conserve son ancien certifi. Actualisez-le avec uvx --refresh mcp-server-fetch ou pip install -U certifi.

servers v2.2.0

Security: Node.js runtime and CA certificate updates (October 2026)

On October 20, 2026, eMudhra disclosed that the private keys for eight of its intermediate CA certificates could be recovered from the public certificates. On October 21, Node.js shipped security releases that update its bundled CA certificates for the compromise and fix several unrelated high-severity runtime CVEs. On October 23, Python's certifi 2026.10.23 removed the eMudhra roots emSign Root CA - C1 and emSign ECC Root CA - C3.

How these servers stand

  • The TypeScript servers rely on the Node.js runtime for certificate checks. They ship no CA certificates of their own. Only server-everything makes outbound HTTPS requests (gzip-file-as-resource), and the Node.js it runs on verifies them. server-filesystem, server-memory and server-sequential-thinking make no network connections.
  • mcp-server-fetch verifies HTTPS against the certifi bundle, through httpx. Installing from PyPI (uvx mcp-server-fetch, pip install mcp-server-fetch) resolves the current certifi, 2026.10.23 or later. The repository's fetch Dockerfile installs from its lockfile, which this release moves to certifi 2026.10.23 (#5341).
  • mcp-server-git and mcp-server-time make no network connections.

If you run a TypeScript server from npm (npx or a global install)

It runs on your Node.js, which we can't update for you. Please run Node.js 24.22.1 or 26.12.1, or later, and check with node --version. The packages' engines field accepts any Node.js 24, so npm won't warn you about an older, unpatched runtime.

If you run mcp-server-fetch from an existing environment

An environment created before October 23 keeps its older certifi. Refresh it with uvx --refresh mcp-server-fetch, or pip install -U certifi.
