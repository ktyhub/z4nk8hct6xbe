# serveurs v2.4.0

Correctifs de sécurité

v2.4.0 corrige six vulnérabilités sur trois serveurs. Mettez à niveau @modelcontextprotocol/server-filesystem vers 2.3.0, et mcp-server-git et mcp-server-fetch à 2026.11.11. | Forfait | Affecté | Corrigé dans | | --- | --- | --- | | @modelcontextprotocol/server-filesystem | toutes les versions antérieures à 2.3.0 et les versions datées de 2025.1.14 à 2026.8.31 | 2.3.0 | | mcp-server-git | via 2026.11.4 | 2026.11.11 | | mcp-server-fetch | via 2026.11.4 | 2026.11.11 | ###@modelcontextprotocol/server-filesystem2.3.0

  • Les lectures restent avec le fichier qui a été vérifié (Linux et macOS). Les outils de lecture et les ressources de fichiers ouvrent désormais un fichier relatif au répertoire qui a été vérifié, comme l'ont déjà fait les écritures, de sorte qu'un répertoire échangé contre un lien symbolique entre la vérification d'accès et la lecture ne peut plus renvoyer un fichier en dehors des répertoires autorisés. Un FIFO, un socket ou un périphérique est refusé plutôt que lu. Sous Windows cela réduit la course sans la fermer, comme pour les écritures (#5260) (GHSA-p9cv-8g75-4xcg)
  • move_file déplace uniquement la source qu'il a vérifiée. Un déplacement au sein d'un périphérique retire d'abord la source de son propre répertoire vérifié sous un nouveau nom, donc un répertoire source échangé contre un lien symbolique ne peut plus amener un fichier extérieur dans les répertoires autorisés, où il deviendrait lisible (GHSA-7m4x-rv66-mxhh)

mcp-server-git 2026.11.11

  • La propre configuration Git d'un référentiel ne peut plus obliger le serveur à exécuter un programme. Un appel en lecture seule tel que git_status sur un référentiel untrusted utilisé pour exécuter une commande nommée dans son .git/config (core.fsmonitor, diff.external, hooks, filtrer et fusionner les pilotes, signature) avec les privilèges du serveur. Chaque commande Git remplace désormais ces paramètres, et un Git plus ancien que 2.31, qui ignorerait les remplacements, est refusé (GHSA-6hqx-gqrx-c5r2)
  • Le confinement --repository couvre les magasins d'objets alternatifs, les arbres de travail liés et les liens dans le répertoire Git. Un référentiel à l'intérieur de celui autorisé pourrait lire les objets d'un autre référentiel via objects/info/alternates, ou transmettre le répertoire Git d'un arbre de travail lié comme référentiel autorisé. Les deux sont refusés, tout comme un lien symbolique dans un répertoire Git qui mène en dehors du référentiel autorisé. Sous Windows, une jonction de répertoire n'est pas encore couverte (#5520) (GHSA-q74p-4wrc-q7w6) ###mcp-server-fetch2026.11.11
  • Les adresses IPv6 locales du site sont privées. Le garde d'adresse privée lit fec0::/10 comme public. Elle est désormais refusée, tout comme toute adresse IPv6 hors monodiffusion globale (2000::/3) qui ne porte pas d'adresse IPv4 (GHSA-3rxj-6jhw-qfv7)
  • robots.txt est comparé au chemin que le site va résoudre, ainsi qu'au chemin tel qu'écrit, donc //private ou /x/../private ne peut plus dépasser Disallow: /private (GHSA-f9hh-cmx9-2f23)

Mise à niveau à partir d'une version npm avec version datée

Les serveurs TypeScript sont passés des versions de date (2025.x, 2026.x) aux versions sémantiques dans 1.0.0. Les gestionnaires de packages classent 2.3.0 en dessous de chaque version 2025.x et 2026.x, ils ne le proposeront donc pas comme mise à niveau. Si vous utilisez une version date de @modelcontextprotocol/server-filesystem, installez explicitement 2.3.0 : npm install @modelcontextprotocol/server-filesystem@2.3.0.

servers v2.4.0

Security fixes

v2.4.0 fixes six vulnerabilities in three servers. Upgrade @modelcontextprotocol/server-filesystem to 2.3.0, and mcp-server-git and mcp-server-fetch to 2026.11.11.

| Package | Affected | Fixed in | | --- | --- | --- | | @modelcontextprotocol/server-filesystem | all versions before 2.3.0, and date versions 2025.1.14 through 2026.8.31 | 2.3.0 | | mcp-server-git | through 2026.11.4 | 2026.11.11 | | mcp-server-fetch | through 2026.11.4 | 2026.11.11 |

@modelcontextprotocol/server-filesystem 2.3.0

  • Reads stay with the file that was checked (Linux and macOS). The read tools and file resources now open a file relative to the directory that was checked, as writes already did, so a directory swapped for a symlink between the access check and the read can no longer return a file from outside the allowed directories. A FIFO, socket or device is refused rather than read. On Windows this narrows the race without closing it, as for writes (#5260) (GHSA-p9cv-8g75-4xcg)
  • move_file moves only the source it checked. A move within one device first takes the source out of its own checked directory under a fresh name, so a source directory swapped for a symlink can no longer bring an outside file into the allowed directories, where it would become readable (GHSA-7m4x-rv66-mxhh)

mcp-server-git 2026.11.11

  • A repository's own Git configuration can no longer make the server run a program. A read-only call such as git_status on an untrusted repository used to run a command named in its .git/config (core.fsmonitor, diff.external, hooks, filter and merge drivers, signing) with the server's privileges. Every Git command now overrides those settings, and a Git older than 2.31, which would ignore the overrides, is refused (GHSA-6hqx-gqrx-c5r2)
  • --repository confinement covers alternate object stores, linked worktrees and links in the Git directory. A repository inside the allowed one could read another repository's objects through objects/info/alternates, or pass a linked worktree's Git directory off as the allowed repository's. Both are refused, as is a symlink in a Git directory that leads outside the allowed repository. On Windows a directory junction is not yet covered (#5520) (GHSA-q74p-4wrc-q7w6)

mcp-server-fetch 2026.11.11

  • IPv6 site-local addresses are private. The private-address guard read fec0::/10 as public. It is now refused, and so is any IPv6 address outside global unicast (2000::/3) that does not carry an IPv4 address (GHSA-3rxj-6jhw-qfv7)
  • robots.txt is matched against the path the site will resolve, as well as the path as written, so //private or /x/../private can no longer get past Disallow: /private (GHSA-f9hh-cmx9-2f23)

Upgrading from a date-versioned npm release

The TypeScript servers moved from date versions (2025.x, 2026.x) to semantic versions in 1.0.0. Package managers rank 2.3.0 below every 2025.x and 2026.x version, so they won't offer it as an upgrade. If you are on a date version of @modelcontextprotocol/server-filesystem, install 2.3.0 explicitly: npm install @modelcontextprotocol/server-filesystem@2.3.0.
