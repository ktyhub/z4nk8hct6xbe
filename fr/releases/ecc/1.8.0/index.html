ECC v1.8.0 : version des performances du harnais

v1.8.0 fait passer ECC d'un « bundle de configuration » à un système de performance de harnais d'agent pratique : des hooks plus fiables, des contrôles d'évaluation/qualité plus forts et une parité plus stricte entre Claude Code, Cursor, OpenCode et Codex (application macOS + CLI). https://github.com/user-attachments/assets/18f05e41-a49b-4126-9771-3df1e07cd7b7

Quoi de neuf

  • Nouvelles commandes de harnais -/harness-audit -/loop-start -/loop-status -/quality-gate -/model-route
  • Mises à niveau de NanoClaw v2
    • Modèle de routage
    • Chargement à chaud de compétences
    • Branche de session/recherche/export/compact/métriques
  • Nouvelles compétences et opérateurs de harnais -agent-harness-construction -agentic-engineering -ralphinho-rfc-pipeline -ai-first-engineering -enterprise-agent-ops -nanoclaw-repl -continuous-agent-loop
  • Nouveaux agents -harness-optimizer -loop-operator

Fiabilité et correctifs de crochets

  • Correction de la résolution racine de SessionStart (remplacement robuste lorsque l'environnement racine du plugin est manquant).
  • Correction du comportement du résumé de session vide/partielle en déplaçant la persistance du résumé vers le chemin du cycle de vie Stop où la charge utile de transcription existe.
  • Ajout de contrôles de hook explicites : -ECC_HOOK_PROFILE=minimal|standard|strict -ECC_DISABLED_HOOKS=comma,separated,ids
  • Remplacement des commandes hook one-liner en ligne fragiles par des scripts dédiés pour un comportement multiplateforme plus sûr.
  • Amélioration de la gestion des chemins Windows pour la logique d'avertissement de document/liste blanche.
  • Comportement d'observateur renforcé pour les environnements non interactifs afin de réduire le risque de blocage.

Parité entre les faisceaux

  • Claude Code, Cursor, OpenCode et Codex partagent désormais un comportement plus strict autour des hooks, des commandes et de la sémantique d'exécution des compétences.
  • Miroirs de commandes OpenCode ajoutés pour le nouveau jeu de commandes de harnais.
  • Alignement de la configuration/documents du Codex amélioré pour les flux de travail de l'application et du CLI.

Notes de compatibilité

  • autonomous-loops est conservé pour des raisons de compatibilité dans cette version.
  • continuous-agent-loop est désormais le nom canonique de la compétence.

Chemin de mise à niveau

  1. Extrayez la dernière version et réinstallez/mettez à jour ECC.
  2. Exécutez /harness-audit pour déterminer la fiabilité et les risques de base.
  3. Utilisez /quality-gate . --strict sur les dépôts actifs.
  4. Si nécessaire, réglez les crochets avec ECC_HOOK_PROFILE et ECC_DISABLED_HOOKS.

ECC v1.8.0

Highlights

  • Harness operations become first-class — v1.8.0 repositions ECC from a static config bundle into a runtime harness system, adding five commands (/harness-audit, /loop-start, /loop-status, /quality-gate, /model-route) plus harness-optimizer and loop-operator agents. The practical shift: you can now baseline and observe live agent loops instead of hand-editing config, so run /harness-audit right after upgrading to see what your setup actually looks like under the new semantics.

  • Hook reliability work changes when summaries land — SessionStart now falls back gracefully when the plugin-root env var is absent, and summary persistence moves to the Stop lifecycle path where the transcript payload exists, so previously empty/partial summaries should populate correctly. Inline one-liner hooks are replaced with dedicated scripts (safer cross-platform, better Windows path handling), and observer behavior is hardened for non-interactive runs to cut hang risk. Watch for any downstream automation that assumed summaries were written early in a session.

  • New environment knobs are the main escape hatch — ECC_HOOK_PROFILE=minimal|standard|strict and ECC_DISABLED_HOOKS=comma,separated,ids let you dial hook strictness or disable specific hooks without patching config files. If a stricter default profile breaks a legacy workflow, these variables are the fastest rollback lever short of reinstalling the previous version.

  • Cross-harness parity is tighter, so treat it as behavioral change — Claude Code, Cursor, OpenCode, and Codex now align on hook, command, and skill-execution semantics, with OpenCode command mirrors for the new harness set and Codex config/docs alignment across both app and CLI. If you run ECC in more than one harness, don't assume last release's behavior carried over; re-audit each one, especially where skill execution rules were normed.

  • NanoClaw v2 enables continuous loops and session introspection — model routing, skill hot-load, and session branch/search/export/compact/metrics ship with new skills such as continuous-agent-loop, enterprise-agent-ops, and nanoclaw-repl. Migration detail worth pinning: continuous-agent-loop is now the canonical skill name while autonomous-loops stays as a compatibility alias, so update references gradually. Recommended adoption path is pull/reinstall → /harness-audit → /quality-gate . --strict → tune the env knobs on active repos.

  • Breaking changes — None; compatibility is preserved through the autonomous-loops alias.

ECC v1.8.0: Harness Performance Release

v1.8.0 shifts ECC from "config bundle" to a practical agent harness performance system: more reliable hooks, stronger eval/quality controls, and tighter parity across Claude Code, Cursor, OpenCode, and Codex (macOS app + CLI).

What’s New

  • New harness commands
    • /harness-audit
    • /loop-start
    • /loop-status
    • /quality-gate
    • /model-route
  • NanoClaw v2 upgrades
    • Model routing
    • Skill hot-load

Reliability and Hook Fixes

  • Fixed SessionStart root resolution (robust fallback when plugin root env is missing).
  • Fixed empty/partial session summary behavior by moving summary persistence to the Stop lifecycle path where transcript payload exists.
  • Added explicit hook controls:
    • ECC_HOOK_PROFILE=minimal|standard|strict
    • ECC_DISABLED_HOOKS=comma,separated,ids
  • Replaced fragile inline one-liner hook commands with dedicated scripts for safer cross-platform behavior.
  • Improved Windows path handling for doc-warning/whitelist logic.
  • Hardened observer behavior for non-interactive environments to reduce hang risk.

Cross-Harness Parity

  • Claude Code, Cursor, OpenCode, and Codex now share tighter behavior around hooks, commands, and skill execution semantics.
  • OpenCode command mirrors added for the new harness command set.
  • Codex config/docs alignment improved for both app and CLI workflows.

Compatibility Notes

  • autonomous-loops is retained for compatibility in this release.
  • continuous-agent-loop is now the canonical skill name.

Upgrade Path

  1. Pull latest and reinstall/update ECC.
  2. Run /harness-audit to baseline reliability and risk.
  3. Use /quality-gate . --strict on active repos.
  4. If needed, tune hooks with ECC_HOOK_PROFILE and ECC_DISABLED_HOOKS.
