Méthode

Comment STAGS collecte, normalise et publie les release note.

Voir →
01 Collecter Une tâche planifiée interroge les versions GitHub API pour chaque référentiel suivi, en ignorant les brouillons, les corps vides et les versions préliminaires, sauf configuration contraire.
02 Normaliser Chaque version est réduite à un enregistrement stable : projet, version sémantique, date de publication, canal de sortie et un résumé d'une ligne extrait du corps.
03 Publier Les notes sont stockées sous forme de Markdown dans le référentiel et rendues sous forme de pages statiques à chaque poussée, de sorte que le site reste rapide et que chaque entrée a une URL stable.
